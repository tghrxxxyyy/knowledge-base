# 零信任架构（Zero Trust Architecture）

> 零信任 =「**永不信任，始终验证**」（Never Trust, Always Verify）。传统安全模型假设内网可信（边界防御），零信任假设内网和外网一样危险——每次访问都必须验证身份、设备、上下文。本篇按「解决的问题 → 原理 → 实践」拆解。

---

## 一、要解决的问题

| 痛点 | 说明 |
|------|------|
| 边界失效 | VPN 被破 = 内网裸奔（传统边界防御失效） |
| 横向移动 | 攻击者进入内网后自由扩散（缺乏微隔离） |
| 内部威胁 | 恶意员工/被控账号在内网无限制访问 |
| 云原生模糊 | 多云/混合云/远程办公，传统边界消失 |
| 合规要求 | SOC2/ISO27001 越来越多要求零信任 |

> 核心认知：**零信任不是产品，是架构原则**——每层都验证（网络/应用/数据），最小权限，持续评估风险。

---

## 二、核心原理

### 2.1 零信任三原则

| 原则 | 说明 |
|------|------|
| 显式验证 | 每次访问都验证身份（不靠 IP/网段信任） |
| 最小权限 | 只给完成任务所需的最小权限（Just-In-Time/Just-Enough） |
| 假设入侵 | 假设已被攻破，实施微隔离 + 持续监控 |

### 2.2 核心架构

```
用户/设备 → 身份验证（MFA/SSO）→ 设备评估（合规/补丁/EDR）
  → 策略引擎（ABAC/PBAC）→ 决策（允许/拒绝/要求 MFA）
  → 代理（反向代理/Service Mesh）→ 后端应用/数据

关键组件：
  IDP（Identity Provider）：身份认证（Okta/Azure AD/Keycloak）
  PEP（Policy Enforcement Point）：策略执行点（反向代理/Sidecar）
  PDP（Policy Decision Point）：策略决策点（评估上下文）
  PAM（Privileged Access Management）：特权访问管理
  SIEM/XDR：安全事件检测与响应
```

### 2.3 实施层次

| 层次 | 措施 | 说明 |
|------|------|------|
| 身份层 | MFA + SSO + 持续验证 | 每次访问都验证（不只是登录时） |
| 设备层 | EDR + 设备合规检查 | 设备必须打补丁/杀毒/合规 |
| 网络层 | 微隔离 + 加密 | 每个服务独立信任域（mTLS） |
| 应用层 | API 网关 + 鉴权 | 最小权限 API 访问 |
| 数据层 | 加密 + 访问控制 | 数据分级 + 字段级权限 |
| 可观测层 | SIEM + XDR + UEBA | 异常行为检测 |

---

## 三、零信任与 Service Mesh

```
Service Mesh（Istio/Envoy）是零信任在网络层的天然实现：

  mTLS（双向 TLS）：每个 Service 间通信都加密+认证
  RBAC：按 Service/ Namespace/ 标签控制访问
  JWT 验证：每个请求携带身份令牌
  可观测性：全链路请求日志（审计）

= 零信任的「网络层 + 身份层 + 可观测层」一体实现
```

## 四、生产实践

### 4.1 实施路线图

```
阶段一（基础）：统一身份（SSO + MFA）→ 特权账号管理（PAM）
阶段二（网络）：微隔离（NetworkPolicy）→ mTLS（Service Mesh）
阶段三（应用）：API 鉴权 → ABAC 策略引擎
阶段四（数据）：数据加密 + 字段级权限
阶段五（监控）：SIEM + UEBA 异常检测
```

### 4.2 关键实践

| 实践 | 说明 |
|------|------|
| SSO + MFA | 所有系统统一身份入口 + 多因素认证 |
| 设备合规 | 设备必须打补丁/装 EDR/加密磁盘才能访问 |
| mTLS | 服务间通信全部加密（Service Mesh 实现） |
| 最小权限 | RBAC/ABAC + JIT 临时提权（超时自动回收） |
| 持续验证 | 每次请求评估风险（异常行为触发 MFA） |
| 日志审计 | 全量访问日志 + 异常告警 |

### 4.3 常见坑

- **一刀切部署**：全面零信任改造太重 → 分阶段（先身份、再网络、再应用）
- **用户体验下降**：频繁 MFA 烦人 → 风险自适应（低风险免 MFA）
- **遗留系统兼容**：老系统不支持 mTLS → 代理层适配
- **成本**：零信任工具链（IDP/PAM/SIEM）成本高 → 先用开源（Keycloak）
