# 代码质量度量与静态分析实战

> 本文深入测试之外的"质量内建"手段：代码质量度量维度、静态分析（SAST）工具与实践、复杂度控制、技术债务管理与质量门禁。内容基于工程实践，工具名以主流为准。

## 1. 为什么要度量质量

- 代码质量是"可维护、可读、少缺陷"的综合。
- 不度量就无法改进，但错误度量会误导（如唯覆盖率论）。
- 度量是手段，不是目的：目标是可持续交付。

## 2. 质量度量维度

- 可读性：命名、注释、结构、重复度。
- 复杂性：圈复杂度、嵌套深度。
- 可测试性：依赖是否可替、是否易 Mock。
- 缺陷密度：千行代码缺陷数。
- 覆盖率：行/分支/变更覆盖。
- 技术债务：重构成本估算。

## 3. 圈复杂度

- 衡量独立路径数量，越高越难测试维护。
- 计算方法：判定节点（if/for/while/case/&&/||）数 + 1。
- 经验阈值：>10 需关注，>20 高风险，应拆分。
- 降低：提取方法、用多态替分支、提前 return。

## 4. 重复代码（Duplication）

- 复制粘贴导致修改遗漏、不一致。
- 工具可检测相似块。
- 消除：抽公共方法/工具类/模板方法。
- 但过度抽象也危险，需权衡。

## 5. 静态分析（SAST）

### 5.1 作用

- 不运行代码，分析源码找缺陷、坏味道、安全漏洞。
- 优点：早、快、全量、可集成 CI。
- 局限：有假阳性，需人工确认。

### 5.2 典型检查项

- 空指针风险。
- 资源未关闭（流/连接）。
- 并发隐患（共享可变状态）。
- SQL/命令注入。
- 不安全的反序列化。
- 未使用变量/死代码。

### 5.3 工具生态

- Java：SpotBugs/PMD/Checkstyle/SonarQube。
- 多语言：SonarQube、CodeQL 思路。
- 安全：依赖漏洞扫描（SCA）。
- 各语言均有对应 linter。

## 6. Checkstyle 与风格

- 统一代码风格（命名、缩进、换行）。
- 在 CI 卡风格违规，避免评审扯皮。
- 配合格式化工具（如 Spotless）自动修复。

## 7. 复杂度控制实战

- 长方法拆分：单一职责。
- 深嵌套改卫语句（early return）。
- 大 switch 改策略模式/查表。
- 用 Optional 减少 null 判断分支。

## 8. 技术债务

### 8.1 定义

- 为短期速度牺牲长期质量，累积的"将来自付利息"。
- 不等同于缺陷，是"该做未做的好实践"。

### 8.2 管理

- 显式记录：技术债务清单 + 影响 + 估算。
- 定期偿还：每个迭代留比例时间重构。
- 避免无意识累积：新代码守质量门禁。

## 9. 质量门禁（Gate）

- 在 CI 设卡：覆盖率、复杂度、重复率、静态分析严重项。
- 不达标拒绝合入。
- 分级：阻断级（必须修）与警告级（记录）。

## 10. Code Review 仍为关键

- 工具查不出"设计是否合理、是否过度工程"。
- Review 关注：可读性、边界、并发、安全、测试覆盖。
- 小 PR 易 review，大 PR 难见效。

## 11. 度量陷阱

- 唯覆盖率：为数字写无效测试。
- 唯行数：鼓励写长代码。
- 复杂度一刀切：小方法高复杂但短，未必坏。
- 假阳性疲劳：规则太多误报，团队忽视所有告警。

## 12.  SonarQube 思路

- 持续检查平台，聚合多维度质量。
- 质量门（Quality Gate）卡合入。
- 技术债务比（技术债务/开发成本）做趋势。
- 新代码重点守门，老代码渐进改善。

## 13. 覆盖率的正确用法

- 关注"变更覆盖率"：本次改动是否覆盖。
- 关注"风险路径覆盖"：核心逻辑而非全量。
- 结合分支覆盖而非仅行覆盖。
- 不追求 100%，追求关键路径。

## 14. 安全静态分析（SAST/SCA）

- SAST：源码层找注入、XSS、不安全反序列化。
- SCA：依赖库漏洞与许可证风险。
- 二者都应进 CI，定期扫描。
- 依赖漏洞需及时升级（有兼容风险，需测试）。

## 15. 质量内建文化

- 质量是每个人的责任，而非 QA 收尾。
- "童子军规则"：离开时代码比来时干净。
- 重构是日常，不是大扫除。
- 度量透明，团队共视趋势。

## 16. 落地步骤

1. 选工具链（linter + 静态分析 + 覆盖率）。
2. 配基线（老代码不卡死，新代码卡严）。
3. 接 CI 门禁。
4. 定期看板回顾，偿还债务。
5. 结合 Code Review 与测试。

## 17. 常见踩坑

1. **门禁过严致绕过**：开发者关检查或跳过；应合理阈值 + 可申诉。
2. **只度量无行动**：看板漂亮但不改，无意义。
3. **覆盖率形式主义**：一堆 assertTrue(true)。
4. **静态分析噪声大**：不调规则，误报淹没真问题。
5. **老代码一次性治理**：代价高、易冲突；应增量。
6. **忽视可读性与设计**：工具查不出"难懂但合规"的代码。

## 18. 度量指标参考

| 指标 | 健康线（经验） |
|---|---|
| 行覆盖率 | 增量 > 80% |
| 圈复杂度 | 单方法 < 10 |
| 重复率 | < 5% |
| 阻断级漏洞 | 0 |
| 严重代码异味 | 0 新增 |

## 19. 与测试的关系

- 静态分析 + 单测 + 集成测试 + 评审 = 质量四重保障。
- 静态分析查"现在就错的"，测试查"行为是否对"。
- 二者互补，不可互相替代。

## 20. 小结

代码质量度量与静态分析是"质量内建"的发动机：用圈复杂度、重复率、覆盖率、SAST/SCA 多维度量，用 CI 门禁卡住新增问题，用技术债务清单持续偿还。铁律：**新代码严、老代码渐进、覆盖率看变更与风险路径、静态分析必须降噪、Code Review 不可替代**。度量服务于可维护，而非数字达标。
