# 测试数据管理与工厂实战

> 测试数据的质量直接决定测试有效性。手工造数据脆弱且难维护，测试数据工厂（Test Data Factory）与夹具（Fixture）能系统化产出可控、可复用的数据。本文讲设计模式与落地。

## 1. 测试数据的痛点

| 痛点 | 影响 |
| --- | --- |
| 硬编码数据 | 易过期、难维护 |
| 依赖真实库 | 慢、不稳定、污染 |
| 数据耦合 | 一个用例改数据，其他失败 |
| 难覆盖边界 | 边界数据手工难造 |

## 2. 测试工厂模式

用工厂方法批量构造对象，带合理默认值，按需覆写：

```java
class UserFactory {
    static User valid() {
        return User.builder()
            .name("张三").age(30).email("a@b.com").build();
    }
    static User builder() { return valid().toBuilder(); } // 链式覆写
}
// 使用
User u = UserFactory.valid().toBuilder().age(17).build(); // 边界
```

- 默认产出"合法"数据，覆写个别字段测边界。
- 比直接 `new User(...)` 可读且易维护。

## 3. 夹具（Fixture）

- **Setup/Teardown**：用例前后准备/清理。
- **共享夹具**：一组用例共用（如数据库 schema）。
- 注意隔离：用例间互不影响（独立数据、独立事务回滚）。

```python
@pytest.fixture
def db():
    conn = create_test_db()
    yield conn
    conn.rollback(); conn.close()
```

## 4. 数据来源策略

| 策略 | 说明 | 适用 |
| --- | --- | --- |
| 工厂构造 | 内存对象 | 单元测试 |
| 数据库种子 | 预置 SQL | 集成测试 |
| 快照/副本 | 生产脱敏副本 | E2E |
| Mock/Stub | 假数据 | 隔离外部 |

## 5. 隔离与清理

- 每用例独立数据，避免依赖顺序。
- 事务回滚：测试后 rollback，不污染库。
- 唯一标识：用随机/序列避免冲突。

## 6. 边界数据构造

- 用工厂快速造边界：空、超长、负数、特殊字符。
- 参数化测试覆盖多组：

```python
@pytest.mark.parametrize("age,valid",[(0,False),(17,False),(18,True),(150,False)])
def test_age(age, valid):
    assert UserFactory.valid().toBuilder().age(age).build().is_valid()==valid
```

## 7. 与生产数据脱敏

- 生产副本必须脱敏（PII 替换/加密）。
- 合规：遵守《个人信息保护法》，最小化使用真实数据。

## 8. 常见坑

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 用例互相依赖 | 顺序敏感 | 独立+回滚 |
| 数据过期 | 频繁失败 | 工厂动态生成 |
| 真实库慢 | 测试久 | 内存/ Mock |
| 脱敏缺失 | 合规风险 | 强制脱敏 |

## 10. 小结

测试数据要用工厂/夹具系统化生成，默认合法、按需覆写边界。核心是隔离（独立+回滚）、可维护（工厂而非硬编码）、合规（脱敏）。好的数据管理让测试稳定且易扩展。
