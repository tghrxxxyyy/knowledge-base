# 测试环境管理实战

> 测试环境是质量保障的"试验场"，但环境不一致、抢占冲突、数据污染是团队最常见的痛点。好的环境管理要做到：环境可重建、数据可造、隔离可控、成本可控。

## 1. 环境分层

```mermaid
flowchart LR
    D[开发自测] --> T[测试集成]
    T --> S[预发Staging]
    S --> P[生产]
```

| 环境 | 用途 | 数据 |
| --- | --- | --- |
| 开发 | 单元/本地 | Mock |
| 测试 | 集成/自动化 | 造数 |
| 预发 | 准生产验证 | 脱敏生产 |

## 2. 可重建（IaC）

- 环境用代码定义（Terraform/K8s YAML），一键重建。
- 镜像/依赖版本锁定，避免"我机器上是好的"。
- 配置外部化，环境差异只在配置。

## 3. 测试数据管理

- **造数工厂**：按模板批量生成符合约束的数据。
- **脱敏**：从生产抽取后脱敏再导入。
- **隔离**：每用例用独立数据集合，避免互相污染。
- **清理**：用例结束回收/重置。

## 4. 隔离与成本

- **环境池/命名空间**：多人并行不冲突。
- **按需拉起**：用后即毁，省资源。
- **流量隔离**：测试流量不进生产。

## 5. 常见坑

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 环境漂移 | 不一致 | IaC 重建 |
| 数据污染 | 用例互相影响 | 隔离 + 清理 |
| 抢占 | 冲突 | 命名空间池 |
| 成本爆 | 长期占用 | 按需销毁 |
| 配置混乱 | 错环境 | 配置中心 |

## 6. 面试题

1. 为什么环境要用 IaC？
2. 测试数据如何隔离？
3. 多团队如何不抢环境？
4. 生产数据如何安全用于测试？
5. 环境成本如何控制？

## 7. 小结

测试环境管理 = IaC 可重建 + 数据工厂 + 隔离 + 按需成本。核心是"环境即代码、数据可造可控、用完即走"。
