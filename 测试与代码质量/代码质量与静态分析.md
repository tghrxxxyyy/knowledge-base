# 代码质量与静态分析

> 板块：测试与代码质量 　|　 返回：[README](README.md)

## 一、质量维度

- 可读性、可维护性、可测试性、安全性、性能。
- 不要只盯「能跑」。

## 二、静态分析工具

| 语言 | 工具 |
|------|------|
| Java | SpotBugs/PMD/Checkstyle/SonarQube |
| JS/TS | ESLint/Prettier |
| Python | flake8/pylint/black |
| Go | go vet/golangci-lint |

## 三、SonarQube 指标

- 代码重复率、圈复杂度、认知复杂度、技术债、安全漏洞。
- 设质量门禁（Quality Gate）：不达标不准合并。

## 四、圈复杂度

- 分支越多越难测。方法圈复杂度 > 10 警惕，> 20 必须拆。

## 五、pre-commit 钩子

- 提交前自动跑 lint/format/单测，挡住低级问题。

## 六、CR 文化

- 小 PR、明确清单、聚焦设计而非风格。
- 自动化管风格，人审管逻辑。

## 七、常见坑

1. 工具装了不接门禁 → 形同虚设。
2. 只看覆盖率 → 忽略坏味道。
3. CR 变成找茬 → 团队对立。
