# 单元测试与测试金字塔

> 板块：测试与代码质量 　|　 返回：[README](README.md)

## 一、测试金字塔

```
        /\        UI/E2E（少、慢、贵）
       /  \      集成测试（中）
      /----\     单元测试（多、快、廉）
     /------```

- 单元测试应占 70%+：快、稳定、好定位。
- 集成/E2E 少而精：覆盖关键链路。
- 反模式「冰淇淋筒」：大量 E2E、极少单测 → 慢且脆。

## 二、单元测试原则（FIRST）

- **Fast**：毫秒级，可随时跑。
- **Isolated**：不依赖外部（DB/网络），用 mock/double。
- **Repeatable**：重复跑结果一致。
- **Self-validating**：自动断言，不需要人看。
- **Timely**：随代码写，不事后补。

## 三、AAA 结构

```java
@Test
void should_deduct_stock_when_order_paid() {
    // Arrange
    Order order = new Order(SKU_A, 2);
    // Act
    order.pay();
    // Assert
    assertEquals(0, stock.of(SKU_A));
}
```

## 四、Mock 与边界

- 用 Mockito 等隔离依赖，只测目标逻辑。
- 不要 mock 一切 → 测的是 mock 不是逻辑。
- 边界：空、null、超长、负数、并发。

## 五、度量

- 覆盖率只看行/分支不够，看「关键路径覆盖」。
- 变异测试（Mutation）验证测试有效性。

## 六、常见坑

1. 单测调真实 DB/接口 → 慢且不稳定。
2. 一个测试多断言多分支 → 难定位。
3. 只为覆盖率写无断言测试 → 假绿。
4. 依赖执行顺序 → 并行跑就挂。

## 七、TDD

- 红（写失败测试）→ 绿（最小实现）→ 重构。
- 适合复杂逻辑/算法；UI 层不强制。
