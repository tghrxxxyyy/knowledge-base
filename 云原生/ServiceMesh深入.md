# Service Mesh 深入（Istio / Linkerd）

> 板块：云原生 　|　 返回：[README](README.md)

## 一、Service Mesh 解决什么

把服务治理（熔断、限流、mTLS、重试、流量镜像）从业务代码剥离，下沉到 Sidecar 代理。

- 数据面：Envoy（Sidecar，处理实际流量）。
- 控制面：Istio 下发配置、证书。

## 二、核心能力

- 流量管理：灰度（按权重/header 路由）、镜像、超时重试。
- 安全：服务间 mTLS 自动。
- 可观测：自动埋点指标/链路。

## 三、价值与代价

- 价值：业务零侵入、统一治理、多语言通用。
- 代价：多一跳延迟、运维复杂度、资源开销。

## 四、适用场景

- 多语言微服务、强治理需求、渐进式交付（金丝雀）。

## 五、与 SDK 治理对比

| 方式 | 优点 | 缺点 |
|------|------|------|
| SDK（Dubbo/Sentinel） | 低延迟、简单 | 绑定语言、升级难 |
| Mesh | 语言无关、统一 | 延迟/复杂度高 |

## 六、常见坑

1. 盲目上 Mesh → 复杂度爆炸。
2. 忽视 Sidecar 资源 → OOM。
3. mTLS 配置错 → 全链路断。
