# 容器与镜像构建优化实战

> 本文讲清容器镜像的构建原理与优化：镜像分层、Dockerfile 最佳实践、多阶段构建、镜像瘦身、层缓存、Base 镜像选型、CI 集成与镜像安全。内容基于公开容器实践，命令以 Docker/OCI 为准。

## 1. 镜像的分层结构

- 镜像由多层（layer）只读叠加组成，每层是文件系统的差量。
- 容器运行时在镜像层上加一个可写层（容器层）。
- 相同层可共享缓存，节省存储与拉取。
- 层越多、越大，拉取与启动越慢。

## 2. 层缓存机制

- 构建时按 Dockerfile 指令逐层，命中缓存则复用。
- 顺序敏感：前面的层变了，后面全部失效。
- 优化：变动少的指令放前面（依赖安装先于代码拷贝）。
- 这是镜像构建快慢的关键。

## 3. Dockerfile 最佳实践

- 选小 Base：alpine/slim 而非完整发行版。
- 合并 RUN：减少层数，但需平衡可读性。
- 清理缓存：同一条 RUN 内 apt 装完即清，避免留在层里。
- 用 .dockerignore：排除无关文件（node_modules、.git）。
- 非 root 运行：安全最佳实践。

```dockerfile
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY . .
RUN npm run build
FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
USER nginx
```

## 4. 多阶段构建

- 一个 Dockerfile 多 FROM，前一阶段构建，后一阶段只取产物。
- 最终镜像不含编译工具链，体积骤降。
- 适合：编译型语言（Go/Java/Rust）、前端构建。
- 是镜像瘦身的标准手段。

## 5. 镜像瘦身

- 用 distroless / alpine / slim 基础镜像。
- 多阶段构建剥离构建依赖。
- 移除不必要的 shell、文档、缓存。
- 用工具（如 dive）分析层体积，定位大文件。
- 权衡：过小镜像难调试（无 shell/curl）。

## 6. Base 镜像选型

- 完整版（ubuntu）：调试方便，体积大。
- slim：适中，去文档与多余包。
- alpine：最小，但 musl libc 可能兼容问题。
- distroless：仅运行时，最小，无 shell。
- 选哪个看可调试性与体积权衡。

## 7. 构建缓存与 CI

- CI 中复用层缓存加速构建（buildkit cache）。
- 依赖层单独缓存：先 COPY 依赖清单再 COPY 代码。
- 注意缓存安全：不可信缓存可能投毒，需受控。
- 并发构建用 BuildKit 提升效率。

## 8. 镜像安全

- 最小权限：非 root、只读根文件系统（read-only rootfs）。
- 漏洞扫描：扫描基础镜像与依赖 CVE。
- 签名与校验：镜像签名（如 cosign 思路）验证来源。
- 不用 latest 标签：固定版本，可复现。
- 密钥不进镜像：用 Secret/挂载。

## 9. 镜像仓库与分发

- 私有仓库（Registry）托管镜像。
- 镜像标签策略：语义版本 + commit SHA，避免 latest 歧义。
- 镜像预热：大规模部署前先拉到节点，避免启动风暴。
- 多架构：同镜像支持 amd64/arm64（manifest list）。

## 10. 容器运行时细节

- 资源限制：CPU/内存 limit，防止单容器吃满节点。
- 健康检查：容器健康探针。
- 优雅终止：SIGTERM + 优雅关闭。
- 日志： stdout/stderr 由运行时收集。
- 只读根文件系统 + 挂载可写卷。

## 11. 启动优化

- 镜像小 → 拉取快。
- 预热/预拉：节点已有镜像则秒起。
- 避免启动脚本重活（初始化放在构建期）。
- 冷启动敏感场景（Serverless）更需精简。

## 12. 与 K8s 的衔接

- 镜像由 Deployment 引用，K8s 调度拉取。
- 镜像拉取策略（IfNotPresent / Always）。
- 私有仓库需配置 imagePullSecret。
- 准入控制可强制签名校验与安全策略。

## 13. 常见踩坑

1. **依赖层放代码后**：代码一动，依赖重装，缓存失效慢。
2. **用 latest**：不可复现、回滚困难。
3. **密钥 COPY 进镜像**：泄露风险；用 Secret。
4. **root 运行**：被攻破危害大；用非 root。
5. **未扫描漏洞**：带 CVE 上线；CI 扫描。
6. **单阶段含构建工具**：镜像巨大；多阶段剥离。
7. **忽略 .dockerignore**：把 node_modules 打进上下文，慢且大。

## 14. 构建工具演进

- BuildKit：更高效、可并发、可缓存的构建引擎。
- 云原生构建：远程构建缓存共享。
- 无需 Dockerfile 的构建（如 buildpacks）自动探测。
- 趋势：更快、更安全、可复现。

## 15. 镜像大小参考（思路）

- 基础运行（distroless/alpine）：MB 级。
- 完整发行版：百 MB 到 GB。
- 多阶段后前端产物镜像：常 < 50MB。
- 具体数字随技术栈变化，以实测为准。

## 16. 优化清单

- 小 Base（alpine/slim/distroless）。
- 多阶段构建。
- 依赖层前置缓存。
- .dockerignore 配置。
- 非 root + 只读根 fs。
- 固定版本标签。
- CI 漏洞扫描 + 缓存复用。
- 镜像签名。

## 17. 与 GitOps 关系

- 镜像是 GitOps 交付的制品（见 GitOps 章节）。
- 镜像 tag/SHA 写入 Git 清单，触发部署。
- 镜像不可变（不覆盖同 tag）保证可追溯。

## 18. 小结

容器镜像优化核心是"分层缓存 + 多阶段构建 + 小 Base + 安全加固"。设计铁律：**变动少的前置以利用缓存、多阶段剥离构建依赖、非 root 运行、固定版本标签、CI 扫描漏洞、密钥不入镜像**。镜像小则拉取快、启动快、攻击面小，是云原生交付效率与安全的共同根基。
