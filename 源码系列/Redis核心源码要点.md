# Redis 核心源码要点

> 本文从原理与工程视角梳理 Redis 的核心机制：单线程模型、数据结构实现（SDS/跳表/字典）、持久化（RDB/AOF）、过期删除、内存淘汰、主从复制与哨兵/集群。内容基于公开实现原理，具体命令与参数以版本为准。

## 1. Redis 为什么快

- 基于内存，数据在 RAM，速度快于磁盘。
- 单线程处理命令（网络 IO + 命令执行），避免锁竞争与上下文切换。
- 高效数据结构（跳表、字典、压缩列表）。
- IO 多路复用（epoll）处理海量连接。
- 注意：6.0 后引入多线程 IO（网络读写），但命令执行仍单线程（核心逻辑）。

## 2. 单线程的取舍

- 优点：无锁、实现简单、原子性天然（命令级）。
- 缺点：一个慢命令（KEYS、大lua）阻塞全部。
- 因此要避免大 key、慢查询。
- 多核利用靠多实例（分片）而非单进程多线程。

## 3. 核心数据结构

- String：SDS（简单动态字符串），预分配减少拷贝。
- List：早期双向链表，后优化为 quicklist（ ziplist + 链表）。
- Hash：ziplist（小数据紧凑）/ hashtable（大数据）。
- Set：intset / hashtable。
- ZSet（有序集合）：跳表（skiplist）+ 字典（查分）。
- 底层按需切换（小数据紧凑编码，省内存）。

## 4. 跳表（Skiplist）

- ZSet 用跳表支持按 score 范围查询与排名。
- 多层有序链表，插入随机层数，平均 O(log n)。
- 比平衡树实现简单，范围查询友好。
- 字典用于按 member 查 score（O(1)）。

## 5. 字典（Dict）与 rehash

- 渐进式 rehash：扩容时不一次性迁移，分多次在命令执行间隙迁移。
- 避免大字典 rehash 卡顿。
- 两个哈希表（ht[0]/ht[1]）过渡。

## 6. 持久化：RDB

- 某一时刻的内存快照，存磁盘。
- 优点：恢复快、文件紧凑。
- 缺点：可能丢最后一次快照后的数据。
- 触发：save（同步阻塞）/ bgsave（fork 子进程）。
- fork 时若内存大，Copy-On-Write 可能短暂占用。

## 7. 持久化：AOF

- 追加记录每条写命令（文本协议）。
- 优点：数据更完整（可每秒/每次刷盘）。
- 缺点：文件大、恢复慢（重放命令）。
- AOF rewrite：定期压缩（重写精简命令集）。
- 通常 RDB + AOF 混合，兼顾速度与安全。

## 8. 过期删除策略

- 惰性删除：访问时检查是否过期，过期则删。
- 定期删除：后台定时抽样扫描过期键删除。
- 两者结合，避免大量 key 同时过期卡顿。
- 主从下过期由主节点驱动（从节点不主动删，保持一致）。

## 9. 内存淘汰（Eviction）

- 内存达 maxmemory 时的策略：
- noeviction：拒绝写（默认，防丢数据）。
- allkeys-lru / volatile-lru：最近最少用淘汰。
- allkeys-lfu / volatile-lfu：最不常使用。
- allkeys-random / volatile-random：随机。
- volatile-ttl：先淘汰快过期的。
- 缓存场景常用 allkeys-lru 或 lfu。

## 10. 主从复制

- 主节点写，从节点异步复制。
- 全量同步：从请求，主 bgsave 发 RDB，从加载，再补增量。
- 增量同步：断线重连后补部分命令（backlog 缓冲）。
- 异步复制：主写完即返回，从可能滞后。

## 11. 哨兵（Sentinel）

- 监控主从，自动故障转移。
- 多个哨兵互相感知，判定主下线（多数派）。
- 选新主（优先从、复制偏移新）。
- 客户端通过哨兵发现当前主节点。
- 解决单点：主挂自动切换。

## 12. 集群（Cluster）

- 数据按 slot（16384 个哈希槽）分片到多节点。
- 每个节点负责部分槽，槽可迁移。
- 客户端计算 key 的 slot 路由到对应节点（或重定向 MOVED）。
- 每个分片可主从，故障转移。
- 适合大数据量水平扩展。

## 13. 事务与 Lua

- MULTI/EXEC：命令排队，原子执行（非回滚，出错继续执行后续）。
- 不支持回滚（与关系库不同）。
- Lua 脚本：整段原子执行，适合复杂原子操作（如限流、分布式锁续期）。
- 注意 Lua 不能太长，否则阻塞。

## 14. 分布式锁（Redisson 思路）

- SET key value NX EX：原子加锁 + 过期。
- 防误删：value 用唯一标识，删时校验。
- 锁续期：看门狗定时延长（防业务未完锁过期）。
- 红锁（Redlock）争议大，简单场景单实例+哨兵足够。
- 见分布式锁场景设计章节。

## 15. 大 key 与热 key

- 大 key：单个 value 过大（如大 list/big hash），删除/序列化慢，阻塞。
- 热 key：某 key 高频访问，单节点瓶颈。
- 解决：拆分大 key、本地缓存、热 key 分散（加随机后缀）。
- 监控：定期扫描 bigkeys。

## 16. 管道与批量

- Pipeline：一次发多条命令，减少网络往返 RTT。
- 注意：pipeline 非事务，只是批量。
- mget/mset、Lua 也是批量手段。
- 适合初始化、批量读写。

## 17. 常见踩坑

1. **大 key 操作**：阻塞单线程；拆分。
2. **KEYS 命令**：全量遍历，生产禁用；用 SCAN。
3. **缓存与库双写不一致**：见高并发缓存章节（先库后删缓存）。
4. **过期键堆积**：大量同时过期致卡顿；过期时间加随机。
5. **内存淘汰误配**：noeviction 拒写；按场景配 lru/lfu。
6. **AOF 每次刷盘**：性能差；折中 everysec。
7. **单实例扛所有**：应分片/集群水平扩展。

## 18. 与业务结合

- 缓存：热点数据前置（见高并发章节）。
- 计数器/限流：INCR、令牌桶。
- 排行榜：ZSet（见场景设计排行榜章节）。
- 消息队列：list/stream（轻量）。
- 会话/共享状态。

## 19. 性能调优方向

- 避免慢命令与大 key。
- 用 Pipeline 批量。
- 合理 maxmemory 与淘汰策略。
- 持久化策略按数据重要度选。
- 集群分片均衡。

## 20. 小结

Redis 快在"内存 + 单线程无锁 + 高效结构 + IO 多路复用"，稳在"RDB/AOF 持久化 + 主从/哨兵/集群高可用"。掌握数据结构切换、过期与淘汰、复制与故障转移，即掌握其原理。铁律：**禁大 key 与 KEYS、缓存先库后删、淘汰策略按场景、持久化兼顾安全与性能、水平扩展用集群分片**。它是高并发系统的标配缓存与高速存储。
