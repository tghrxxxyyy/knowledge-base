# 读写分离与分库分表实战

当单库性能成为瓶颈，常用两条路径扩展：读写分离（ scale out 读）与分库分表（scale out 写与容量）。
本文讲解原理、路由、一致性、分片策略、分布式 ID 与典型坑。

## 一、读写分离

### 1.1 原理

- 主库（Master）负责写，从库（Slave）负责读。
- 主库数据通过 binlog 复制（异步/半同步）到从库。
- 读请求分散到多个从库，提升读吞吐。

### 1.2 延迟问题

- 主从复制存在延迟，刚写入的数据在从库可能读不到。
- 场景：下单后立即查订单，读到旧数据。

缓解：

- 写后读强制走主库（关键路径）。
- 半同步复制降低延迟。
- 业务上接受最终一致（如"稍后可在我的订单查看"）。

### 1.3 路由方式

- 中间件（如 ShardingSphere、Proxy）按读写类型路由。
- 框架层（如 MyBatis 注解）标记方法走主/从。
- 手动指定数据源。

### 1.4 负载均衡从库

- 多个从库间做负载均衡（轮询/权重）。
- 某从库延迟过大可摘除。

## 二、分库分表

### 2.1 什么时候需要

- 单表数据量过大（如千万/亿级），查询慢、索引膨胀。
- 单库连接数、CPU、IO 达到上限。
- 写入成为瓶颈，单实例无法横向扩展。

### 2.2 垂直拆分

- 垂直分库：按业务域拆库（用户库、订单库、商品库）。
- 垂直分表：把大表按字段拆（常用字段 + 扩展字段）。
- 降低单库/单表宽度与耦合。

### 2.3 水平拆分（分片）

- 水平分表：同一结构的数据按规则分散到多张表。
- 水平分库：分散到多个库实例。
- 每张表/库只存部分数据，整体容量线性扩展。

### 2.4 分片键（Sharding Key）

- 决定数据落在哪个分片的字段（如 user_id、order_id）。
- 选择原则：
  - 高频查询条件包含该字段，避免跨分片。
  - 数据分布均匀，防止热点分片。
  - 尽量稳定不变。

### 2.5 分片算法

- 取模（hash % N）：简单均匀，但扩容需迁移大量数据。
- 范围分片：按时间/ID 区间，易扩容但易热点。
- 一致性哈希：节点变化仅影响少量数据，更适合动态扩缩。
- 基因法：分片键中嵌入用于路由的"基因"，保证关联数据同片。

## 三、分布式 ID

### 3.1 为什么不能用自增主键

- 分片后各库自增会冲突，无法全局唯一。
- 需全局唯一且趋势递增（利于索引）的 ID。

### 3.2 常见方案

- Snowflake：时间戳 + 机器ID + 序列，趋势递增、本地生成。
  - 依赖时钟，时钟回拨会出问题。
- UUID：全局唯一但无序、过长、索引不友好。
- 号段（Segment）：从中心批量取一段 ID 本地发放，性能高。
- 数据库号段/Redis 自增：简单但中心化。

## 四、跨分片查询

### 4.1 问题

- 不带分片键的查询需扫描所有分片（全路由）。
- 跨分片 JOIN、聚合、分页困难。

### 4.2 应对

- 冗余/异构索引：建一张按查询维度分片的映射表。
- 异构同步：把数据同步到 ES/OLAP 做复杂查询。
- 应用层归并：各分片查后由中间件合并排序分页。
- 避免跨分片事务：尽量单分片内完成。

## 五、分布式事务

### 5.1 尽量避免

- 让一个事务只在一个分片内完成。
- 通过分片键设计把关联数据放同一分片。

### 5.2 必要时的方案

- 最终一致：本地消息表 / 事务消息 / Saga。
- 不追求强一致，接受可补偿。

## 六、扩容迁移

### 6.1 平滑扩容

- 提前规划分片数（如 2 的次幂便于翻倍）。
- 翻倍扩容时，每个旧分片的数据一半迁到新分片。
- 用一致性哈希可最小化迁移量。

### 6.2 双写迁移

- 新旧分片双写，校验一致后切换读。
- 灰度切流，回滚可控。

## 七、中间件选型

- ShardingSphere（JDBC/Proxy）：生态成熟、与 Java 契合。
- MyCat / ProxySQL：代理层透明。
- 自研路由层：高度定制但成本高。

## 八、常见坑

- 分片键选错导致大量跨分片查询。
- 用自增主键做分片键，数据倾斜且 ID 冲突。
- 跨分片 JOIN 性能灾难。
- 扩容迁移数据不一致。
- 分布式事务误用强一致拖累性能。

## 九、速记

- 读写分离：主写从读，缓解读瓶颈；代价是复制延迟，关键读走主库。
- 垂直拆库/表，水平分片扩容量；分片键是灵魂，选高频且均匀的字段。
- 分片算法：取模简单、范围易热点、一致性哈希易扩缩。
- 分布式 ID：Snowflake 趋势递增、UUID 无序、号段高性能。
- 跨分片：用冗余索引/ES/归并，避免跨分片事务，扩容用翻倍或双写。
