# 容量规划与压测实战

> "系统能扛多少？" 是架构师的必答题。容量规划用压测数据推导资源需求，压测用真实流量模型验证。二者结合，才能在大促/突发前做到心里有数、资源不浪费。

## 1. 容量推导

```mermaid
flowchart LR
    QPS[目标QPS] --> P[单实例容量]
    P --> N[所需实例数]
    N --> R[资源预算]
```

- 单实例容量 = 压测得到的稳定 QPS（如 2000 QPS/实例）。
- 所需实例 = 目标 QPS / 单实例容量 × 安全冗余（如 1.5×）。
- 考虑依赖（DB/缓存）容量是否匹配。

## 2. 压测类型

| 类型 | 目的 |
| --- | --- |
| 基准 | 单接口极限 |
| 容量 | 系统拐点 |
| 稳定性 | 长时间是否劣化 |
| 全链路 | 真实流量模型 |

## 3. 压测要点

- **流量模型真实**：按业务比例混合接口，非单一接口。
- **梯度加压**：逐步上量找拐点，记录 P99/错误率。
- **监控全链路**：CPU、连接、慢查询、GC 一起看。
- **影子库/流量**：生产压测用影子表，不污染真实数据。

## 4. 容量治理

- 定位瓶颈：CPU 型 / IO 型 / 锁 / 外部依赖。
- 扩容 or 优化（缓存、异步、批处理）。
- 设定水位告警，预留弹性。

## 5. 常见坑

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 模型失真 | 结论错 | 真实流量 |
| 只看均值 | 漏长尾 | 看 P99 |
| 污染数据 | 影响线上 | 影子库 |
| 忽略依赖 | 局部好全局崩 | 全链路 |
| 无冗余 | 突发挂 | 安全系数 |

## 7. 小结

容量规划 = 压测出单实例能力 + 目标/冗余推导资源。核心是"用数据说话、看长尾、控依赖、留冗余"。
