# 边缘计算与 CDN 边缘架构

> 板块：架构 　|　 返回：[README](README.md)
> 适用：超低延迟、就近接入、带宽优化、IoT/车联网、实时互动。

边缘计算把算力从中心云下沉到**离用户/设备更近的边缘节点**，解决中心云"延迟高、带宽贵、弱网不可用"的痛点。CDN 是最成熟的边缘形态，而边缘函数/边缘节点则进一步把计算下沉。

## 一、为什么需要边缘

- **延迟**：中心云跨地域 RTT 30–100ms，边缘可降到 5–20ms。
- **带宽**：视频/大文件回源中心带宽成本高，边缘缓存就近服务。
- **可用性**：弱网/断网时边缘可本地自治（IoT 网关）。
- **合规**：数据不出域（如工厂数据本地处理）。

## 二、边缘形态谱系

```
终端(设备) → 边缘节点(工厂网关/基站/边缘DC) → 区域中心 → 中心云
```

| 形态 | 位置 | 算力 | 场景 |
|------|------|------|------|
| CDN 边缘 | 运营商 PoP | 缓存/简单改写 | 静态加速、边缘缓存 |
| 边缘函数（Edge Functions） | CDN PoP | 轻量计算 | A/B、改写、鉴权 |
| 边缘节点/MEC | 基站/园区 | 容器/VM | 车联网、工业 |
| 边缘网关 | 现场 | 嵌入式 | IoT 采集预处理 |

## 三、CDN 架构

```
用户 → 本地 DNS/GSLB → 最近边缘节点
                        ↓ (命中) 直接返回
                        ↓ (未命中) 回源(源站/上层)
```

- **GSLB**：基于地理位置/运营商调度到最近节点。
- **缓存策略**：TTL、缓存键（去参）、 purge 刷新、分层回源（边缘→区域→源）。
- **边缘计算**：在边缘执行 JS/WASM（如 Cloudflare Workers、AWS Lambda@Edge），做请求改写、鉴权、A/B。

## 四、边缘函数（Edge Functions）

- 在 CDN 节点运行轻量代码，处理每个请求。
- 冷启动极低（节点常驻、V8 隔离），适合请求级逻辑。
- 限制：无长连接、无本地持久态（状态走外部分布式存储）。

```javascript
// Cloudflare Workers 示例：边缘鉴权 + 改写
export default {
  async fetch(req) {
    const token = req.headers.get('Authorization');
    if (!valid(token)) return new Response('deny', { status: 401 });
    const url = new URL(req.url);
    url.pathname = '/edge' + url.pathname;   // 路径改写
    return fetch(url, req);
  }
}
```

## 五、数据一致性与同步

- 边缘多副本，配置/数据同步采用最终一致（乐观复制）。
- 边缘状态外置：用户态存中心或全局 KV（如 Cloudflare KV、DynamoDB 全局表）。
- 冲突处理：版本/时间戳/CRDT（协同编辑场景）。

## 六、适用场景

- **静态/视频加速**：CDN 缓存。
- **实时互动**：游戏/音视频低延迟。
- **IoT/车联网**：边缘预处理，降带宽、降延迟。
- **个性化**：边缘按地域/用户改写内容（A/B、本地化）。
- **安全**：边缘 WAF、限流、Bot 防护。

## 七、不适用

- 强一致事务（跨边缘难保证）。
- 重计算/大模型推理（需大算力，边缘受限）。
- 数据强合规需集中管控（边缘分散增风险）。

## 八、与中心云的协同

- **中心**：全局控制面、重计算、数据存储、训练。
- **边缘**：就近接入、缓存、轻计算、过滤。
- 典型：边缘采集 → 中心分析/训练 → 下发策略到边缘。

## 九、常见坑

1. **边缘状态本地化** → 多节点不一致；状态外置全局存储。
2. **缓存键设计错** → 命中率低/串用户；合理去参 + 隔离。
3. **回源风暴** → 大量未命中同时回源；请求合并 + 锁。
4. **边缘函数过重** → 超时/成本高；只放轻逻辑。
5. **配置推送延迟** → 边缘生效慢；接受最终一致 + 监控。
6. **安全边界模糊** → 边缘成攻击面；边缘 WAF + 最小权限。
