# DDD 值对象与实体设计实战

> 实体（Entity）与值对象（Value Object）是 DDD 建模的两块基石。搞清"何时用标识、何时用值"是写出好领域模型的前提。本文讲清区别、实现与误用。

## 1. 实体 vs 值对象

| 维度 | 实体 | 值对象 |
| --- | --- | --- |
| 标识 | 有唯一 ID | 无 ID，靠属性定义 |
| 相等 | 按 ID | 按属性值 |
| 可变性 | 可变的属性 | 不可变 |
| 例子 | 用户、订单 | 金额、地址、颜色 |

口诀：**能替换且不影响业务含义 → 值对象；需要被唯一追踪 → 实体**。

## 2. 实体设计

```java
class User {
    UserId id;          // 标识
    String name;
    Email email;
    void changeEmail(Email e){ this.email = e; } // 行为内聚
}
```

- ID 不变，其余可改。
- 行为（方法）与数据在一起，避免贫血。
- 相等性由 ID 决定。

## 3. 值对象设计

```java
class Money {              // 不可变
    private final long cents;
    private final Currency currency;
    Money add(Money o){
        if (o.currency != this.currency) throw ...;
        return new Money(cents + o.cents, currency); // 返回新对象
    }
}
```

- final 字段，无 setter。
- 操作为"不变异"，返回新实例。
- equals 比较所有属性。

## 4. 何时用值对象

- 描述性属性（金额、地址、时间段、坐标）。
- 可替换、无生命周期（换地址不影响"人"的身份）。
- 组合值对象（如 Money = 数值 + 币种）。

## 5. 误用与纠正

| 误用 | 后果 | 纠正 |
| --- | --- | --- |
| 实体当值对象 | 相等性混乱 | 加 ID |
| 值对象可变 | 隐蔽 bug | final + 新实例 |
| 基本类型散用 | 缺语义 | 包装成值对象（如 Money） |

## 6. 值对象的好处

- **表达力**：`Money` 比 `long cents` 语义强。
- **安全**：不可变天然线程安全。
- **复用**：可组合（如 `Address` 含 `Country`/`City` 值对象）。
- **校验内聚**：构造即校验（如邮箱格式）。

## 7. 持久化

- 实体：表 + 主键。
- 值对象：可内嵌实体表（同表多列）或序列化存储。
- ORM（如 JPA/@Embeddable、MyBatis 映射）支持值对象持久化。

## 8. 实战示例

```java
class Order {                 // 实体
    OrderId id;
    List<OrderLine> lines;   // OrderLine 可设计为值对象
    Address shipTo;           // 值对象
    Money total(){ ... }      // 行为
}
```

## 10. 小结

实体看标识、值对象看属性。用好值对象能让模型更富表达、更安全；把行为放进实体避免贫血。建模时先问"它是否需被唯一追踪"，答案决定用实体还是值对象。
