# DDD 聚合设计原则与不变式实战

> 聚合（Aggregate）是 DDD 中一致性边界的核心概念。聚合设计的好坏直接决定系统的复杂度与性能。本文讲聚合根的选取、不变式（Invariant）保护与常见反模式。

## 1. 聚合的定义

- **聚合**：一组相关对象的集群，作为一个整体被外界访问。
- **聚合根（Aggregate Root）**：聚合的入口，外部只引用聚合根，通过它操作内部对象。
- **边界**：一个事务内只修改一个聚合（强一致），跨聚合用最终一致。

## 2. 聚合根选取原则

- **业务一致性**：哪些对象必须一起保证规则？它们应在一个聚合。
- **事务边界**：一次事务修改一个聚合，避免大聚合锁。
- **生命周期**：对象是否随聚合根生灭？

反例：把"用户 + 订单 + 商品"放一个聚合 → 巨大聚合，并发差。

## 3. 不变式保护

不变式是业务规则，必须在聚合内始终成立：

```java
class Order {
    List<OrderItem> items;
    Money total;
    void addItem(Product p, int qty){
        if (qty<=0) throw new IllegalArgumentException();
        items.add(new OrderItem(p, qty));
        total = total.add(p.price.multiply(qty)); // 保持总额一致
    }
}
```

- 规则（总额=各项和）由聚合方法保证，不外露中间态。
- 外部无法绕过，保证不变量不被破坏。

## 4. 引用 vs 标识

- 聚合内引用对象（值对象/实体）。
- 聚合间只通过 **ID** 引用，不持对象引用（避免跨聚合一致性）。

```java
class Order {
    UserId userId;   // 引用用户聚合的 ID，非 User 对象
}
```

## 5. 值对象

- 无标识、不可变（如 Money、Address、Color）。
- 用值相等判断（equals 比较属性）。
- 适合描述性属性，减少实体复杂度。

```java
class Money {
    final long cents;
    Money add(Money o){ return new Money(cents+o.cents); }
}
```

## 6. 仓储边界

- 仓储按 **聚合根** 定义，不按子实体。
- 一个聚合一个 Repository，加载/保存整个聚合。
- 不提供"更新某个子实体"的接口，防止绕过聚合。

## 7. 大聚合拆分

- 若一个聚合过大（如订单含上百项 + 历史），拆：
  - 把不常一起变的拆成独立聚合（如订单项独立为 OrderItem 聚合，用 orderId 关联）。
  - 用领域事件同步（订单项变更发事件通知订单）。

## 8. 常见反模式

| 反模式 | 问题 | 对策 |
| --- | --- | --- |
| 上帝聚合 | 锁竞争 | 拆小 |
| 跨聚合引用对象 | 一致性难 | 用 ID 引用 |
| 聚合暴露内部 | 不变式破坏 | 封装方法 |
| 仓储按子实体 | 绕过根 | 仅按根 |

## 9. 设计检查清单

- 一个事务只改一个聚合？
- 跨聚合用事件/最终一致？
- 聚合间只引用 ID？
- 不变式在聚合内闭合？
- 仓储只按根？

## 11. 小结

聚合是"一致性边界 + 事务边界"。好的聚合小、内聚、保护不变式；跨聚合用 ID 引用与最终一致。聚合根封装变化，仓储按根管理，是 DDD 落地的关键纪律。
