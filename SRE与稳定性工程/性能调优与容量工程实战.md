# 性能调优与容量工程实战

> 性能问题从"慢"开始，到"崩"结束。调优是"定位瓶颈 → 验证假设 → 量化收益"的科学，而非玄学；容量工程则是把性能结论转化为可预测的资源规划。二者是稳定性的左膀右臂。

## 1. 调优方法论

```mermaid
flowchart LR
    S[现象:慢/错] --> M[度量:定位瓶颈]
    M --> H[假设:CPU/IO/锁/依赖]
    H --> E[验证:压测/对比]
    E --> F[落地:优化]
    F --> S2[复测量化]
```

- **先度量再动手**：没有基线就没有优化。
- **二八原则**：先解决占大头的热点。
- **单变量验证**：一次只改一个，确认收益。

## 2. 常见瓶颈

| 层 | 瓶颈 | 手段 |
| --- | --- | --- |
| CPU | 热点方法、序列化 | 算法、缓存、批处理 |
| IO | 慢查询、磁盘 | 索引、异步、批写 |
| 锁 | 竞争、长事务 | 无锁、缩短临界区 |
| 依赖 | 下游慢 | 超时、熔断、本地缓存 |
| GC | 频繁 Full GC | 调参、减少对象 |

## 3. 容量工程

- 由压测得单实例容量，推导容量需求。
- 设水位线（如 70%）触发扩容。
- 弹性 + 预留，应对突发。
- 容量评审纳入变更流程。

## 4. 工具链

- **CPU/内存**：profiler（火焰图）。
- **数据库**：慢查询日志、执行计划。
- **链路**：trace 找慢 span。
- **系统**：top/iostat/网络。

## 5. 常见坑

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 凭感觉调 | 无效 | 先度量 |
| 多变量 | 不知效 | 单变量 |
| 只压单接口 | 失真 | 全链路 |
| 忽略依赖 | 局部好 | 端到端 |
| 无水位 | 突发挂 | 弹性 |

## 7. 小结

性能调优 = 度量定位 + 单变量验证 + 量化收益；容量工程 = 压测出能力 + 水位弹性。核心是"用数据说话、用科学方法收敛问题"。
