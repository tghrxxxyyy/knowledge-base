# SLO 与错误预算实践

> 板块：SRE 　|　 返回：[README](README.md)

## 一、SLO 是什么

- **SLI**：实际指标（如请求成功率）。
- **SLO**：目标（如 99.9% 请求成功）。
- **错误预算**：允许失败的量（0.1%）。

## 二、为什么用错误预算

把「稳定性」量化为可消耗的资源：

- 预算充足 → 可大胆发布。
- 预算烧完 → 冻结非必要变更，先恢复稳定性。

## 三、设定 SLO 的步骤

1. 选对用户关心的 SLI（不可用定义）。
2. 设可达且有挑战的目标（99.9% 而非 100%）。
3. 按窗口（如 28 天滚动）计算预算。

## 四、错误预算策略

- 预算 > 剩余 → 冻结发布、聚焦稳定性。
- 预算充裕 → 正常迭代。
- 多次烧完 → 架构层面改造。

## 五、常见坑

1. SLO 设 100% → 永远超支，失去意义。
2. SLI 定义不清 → 扯皮。
3. 预算无动作 → 形同虚设。
