# 容量治理与资源优化实战

> 容量不足会导致性能劣化甚至雪崩，资源浪费则推高成本。容量治理在"够用"与"省钱"间找平衡：预测需求、合理预留、持续调优。本文讲解容量规划、压测、弹性与优化实战。

## 1. 容量治理的目标

| 目标 | 说明 |
| --- | --- |
| 可用性 | 峰值流量下不宕机 |
| 性能 | 延迟在 SLO 内 |
| 成本 | 不浪费资源 |
| 弹性 | 流量波动自适应 |

矛盾：预留多→稳但贵；预留少→省但险。治理用"数据驱动"平衡。

## 2. 容量规划方法

### 2.1 基于历史
- 看历史峰值（日/周/大促），留余量（如 1.5~2x）。
- 考虑增长趋势（月环比）。

### 2.2 基于压测
- 全链路压测得出单实例容量（QPS/连接）。
- 目标容量 / 单实例容量 = 所需实例数 + buffer。

```mermaid
flowchart LR
    A[目标QPS] --> B[单实例容量]
    B --> C[实例数=目标/单实例*冗余]
    C --> D[资源规划]
```

## 3. 全链路压测

- 影子流量/影子库，避免污染生产。
- 从入口逐步加压，找到瓶颈（DB/缓存/线程池）。
- 记录各层容量水位，定位短板。

## 4. 弹性伸缩

| 类型 | 机制 | 适用 |
| --- | --- | --- |
| HPA | 基于 CPU/QPS 自动扩 | 常规 |
| VPA | 自动调 request/limit | 资源错配 |
| 定时伸缩 | 已知波峰提前扩 | 可预测 |
| KEDA | 基于事件（队列长度） | 事件驱动 |

## 5. 资源优化

- **右配（Right-sizing）**：根据实际使用调 request/limit，避免过度分配。
- **混部**：不同峰谷的服务共享节点，提升利用率。
- **Spot/抢占**：非关键负载用低价实例。
- **闲置清理**：下线不用资源、释放孤立磁盘。

## 6. 容量水位监控

- 核心指标：CPU/内存/连接/队列深度/线程池活跃。
- 设水位线：正常/警戒/危险，分级告警。
- 预测性扩容：基于趋势提前扩，而非等打满。

## 7. 限流与过载保护

- 容量不足时，限流保核心，丢弃非核心。
- 多级限流：网关→服务→资源。
- 负载兜底：队列满则快速失败，避免雪崩。

## 8. 成本可视化

- 资源打标签（团队/环境/服务）。
- 成本按团队分摊（showback）。
- 浪费告警（低利用率资源）。

## 9. 容量演练

- 混沌工程注入资源压力，验证弹性与降级。
- 大促前全链路压测 + 预案演练。
- 红蓝对抗：蓝军打流量，红军保稳定。

## 10. 常见坑

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 预留不足 | 峰值宕机 | 压测+冗余 |
| 过度分配 | 成本高 | 右配 |
| 无弹性 | 浪费/风险 | HPA |
| 单点瓶颈 | 整体受限 | 找短板 |
| 无水位 | 突发打满 | 水位监控 |

## 12. 小结

容量治理 = 规划（历史+压测）+ 弹性（HPA/VPA）+ 优化（右配/混部）+ 监控（水位）。目标是在稳定与成本间找数据驱动的平衡点，配合限流与演练抵御峰值冲击。
