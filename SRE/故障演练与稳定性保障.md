# 故障演练与稳定性保障

> 板块：SRE 　|　 返回：[README](README.md)

## 一、稳定性优先

功能重要，但「不出事」更重要。SRE 用工程化手段保障可用性。

## 二、混沌工程

- 主动注入故障（杀节点、断网络、增延迟），验证系统韧性。
- 工具：Chaos Mesh / Litmus。
- 原则：从小范围、可回滚、有止损开始。

## 三、降级与熔断

- 熔断：依赖错误率超阈值，暂时切断，快速失败（Sentinel/Resilience4j）。
- 降级：非核心功能关掉（如推荐关掉，保下单）。
- 限流：保护自身不被打垮（令牌桶）。

## 四、容量与压测

- 全链路压测（影子库/流量染色）找瓶颈。
- 容量规划：按峰值 × 冗余系数扩容。

## 五、应急预案

- 每个核心链路有 runbook：现象 → 止损动作 → 恢复。
- 定期演练，避免「纸上预案」。

## 六、复盘（Postmortem）

- 不追责（blameless），聚焦根因与改进。
- 故障 → 时间线 → 根因 → 行动项（带负责人/期限）。

## 七、常见坑

1. 只压测单接口不压全链路。
2. 降级开关没测过 → 真用时失效。
3. 复盘无行动项 → 同样故障复发。
4. 监控盲区 → 故障发现晚。
