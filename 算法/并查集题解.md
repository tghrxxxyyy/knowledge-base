# 并查集（题解 / Union-Find）

## 〇、本体介绍

**并查集（Disjoint Set / Union-Find）**：维护「不相交集合」的数据结构，支持两种操作——`find(x)` 找 x 所属集合代表、`union(x,y)` 合并两集合。用于**动态连通性**问题：网络连通、朋友圈、连通分量、最小生成树、岛屿扩展。

**优化**：路径压缩（`find` 时把节点直接挂到根）+ 按秩/大小合并（小树挂大树），使近乎 O(1)（反阿克曼函数 α(n)）。

**面试高频**：岛屿数量（DFS/BFS 也行）、省份数量、冗余连接（判环）、最小生成树（Kruskal）、账户合并、方程满足性（带权并查集）。

---

## 一、标准实现

```java
int[] parent, rank;
void init(int n){ parent = new int[n]; rank = new int[n];
    for(int i=0;i<n;i++) parent[i]=i; }
int find(int x){ while(parent[x]!=x) { parent[x]=parent[parent[x]]; x=parent[x]; } return x; } // 路径压缩
void union(int x,int y){
    int rx=find(x), ry=find(y);
    if(rx==ry) return;
    if(rank[rx]<rank[ry]) parent[rx]=ry;
    else { parent[ry]=rx; if(rank[rx]==rank[ry]) rank[rx]++; } // 按秩合并
}
```

### 1.1 深挖：路径压缩到底怎么工作

```mermaid
graph LR
    subgraph 压缩前（链状）
        A[1] --> B[2] --> C[3] --> D[4]
    end
    subgraph find(1) 之后（扁平化）
        A2[1] --> D2[4]
        B2[2] --> D2
        C2[3] --> D2
    end
```

- **路径压缩**：`find(x)` 递归/迭代过程中，把沿途所有节点直接挂到根上。下次 find 任意节点 O(1) 级别。
- **按秩合并**：用「树高估计」rank，矮树挂高树，防退化链。
- **两者合用时摊还复杂度 O(α(n))**（α 反阿克曼函数，<5 对任何实际输入），可视为常数。

> 面试常问「为什么接近 O(1)」：路径压缩让树极矮 + 按秩合并让树不高，每次 find 基本一步到根。

## 二、经典例题

- **省份数量（547）**：每个人初始独立，好友关系合并，最后不同根的数量即省份。
- **岛屿数量（200）**：也可并查集——遍历陆地边把相邻陆地合并，最后根计数（与 DFS 等价）。
- **冗余连接（684）**：给一棵树+一条边形成环，按输入顺序加边，遇到 `find(u)==find(v)` 即环边，返回。
- **账户合并（721）**：邮箱作为元素，同一人的账户邮件互相 union，收集各连通块。
- **等式方程可满足性（990）**：`==` 先合并，`!=` 后检查是否同集，同集则矛盾（带权可做不等式）。
- **Kruskal MST**：边按权排序，能合并（不形成环）就选入，直到选 V-1 条。

### 2.1 深挖：冗余连接（判环）与岛屿（二维映射）模板

```java
// 684 冗余连接：树 + 一条边 ⇒ 唯一环；顺序加边，遇到两端已连通即环边
int[] findRedundantConnection(int[][] edges) {
    DSU dsu = new DSU(edges.length + 1);
    for (int[] e : edges)
        if (!dsu.union(e[0], e[1])) return e;  // 合并失败 ⇒ 已在同一集合 ⇒ 成环
    return new int[0];
}

// 200 岛屿数量（并查集版）：二维坐标映射一维，相邻陆地 union
int numIslands(char[][] grid) {
    int m = grid.length, n = grid[0].length;
    DSU dsu = new DSU(m * n);
    int[][] dir = {{1,0},{-1,0},{0,1},{0,-1}};
    int ones = 0;
    for (int i = 0; i < m; i++)
        for (int j = 0; j < n; j++) if (grid[i][j] == '1') {
            ones++;
            for (int[] d : dir) {
                int ni = i + d[0], nj = j + d[1];
                if (ni < 0 || ni >= m || nj < 0 || nj >= n || grid[ni][nj] != '1') continue;
                dsu.union(i * n + j, ni * n + nj);   // idx = r*cols + c
            }
        }
    return dsu.count();   // 连通块数 = 陆地数 - 成功合并次数
}
```

## 三、带权并查集（进阶）

维护「节点到根的相对权值」，支持**带权关系**推理（如「A 比 B 多 3」）。`find` 时累加路径上的权；`union` 时按关系推导新权。题目：种类并查集（食物链 240）、区间关系。

### 3.1 深挖：带权并查集实现要点

```java
// weight[x] = x 到 parent[x] 的相对权值（find 压缩时同步累加）
int find(int x) {
    if (parent[x] != x) {
        int root = find(parent[x]);        // 先找根（递归到顶）
        weight[x] += weight[parent[x]];    // 累加「父到根」的权
        parent[x] = root;                  // 再压缩
    }
    return parent[x];
}
void union(int x, int y, int w) {          // 已知 y = x + w（相对关系）
    int rx = find(x), ry = find(y);
    if (rx == ry) { /* 校验 weight[y] - weight[x] 是否等于 w */ return; }
    parent[rx] = ry;
    weight[rx] = weight[y] - weight[x] - w;  // 向量三角形推导
}
```

> 应用：**食物链（240）**（3 种关系循环）、**带权区间和**（前缀和思想的并查集化）、等式/不等式系统。`union` 时权值的正负方向极易错，建议画向量图推导。

## 四、易错点

- `find` 必须路径压缩且返回根，别返回中间节点。
- 合并先判是否同根，避免自环计数。
- 二维坐标要映射到一维下标（`r*cols+c`）。
- 递归 find 注意栈深（超大数据量用迭代版）。
- union 返回值语义：返回 boolean（是否真的合并）可简化判环逻辑。

## 面试高频问题（30+ 条）

1. **并查集解决哪类问题？** 动态连通性：连通分量、合并集合、判环、最小生成树。
2. **两个核心优化？** 路径压缩（find 扁平化）、按秩/大小合并（小挂大），接近 O(1)。
3. **路径压缩原理？** find 时把沿途节点直接挂到根，降低树高。
4. **按秩合并原理？** 矮树挂到高树，避免退化成链。
5. **时间复杂度？** 带两优化约 O(α(n))，α 是反阿克曼，实际常数级。
6. **岛屿数量用并查集怎么做？** 相邻陆地 union，最后不同根计数（等价 DFS）。
7. **冗余连接怎么找环边？** 顺序加边，find(u)==find(v) 即形成环，返回该边。
8. **省份/朋友圈数量？** 关系合并后统计根节点个数。
9. **Kruskal 为什么用并查集？** 边排序后依次合并，避免成环即选入，至 V-1 条。
10. **账户合并思路？** 邮箱为元素，同人账户互相 union，收集连通块。
11. **等式方程可满足性？** `==` 先并，`!=` 再查同集矛盾。
12. **带权并查集是什么？** 维护节点到根的权值，支持带权关系推理（如食物链）。
13. **二维坐标怎么映射一维？** `idx = r*cols + c`，便于数组下标。
14. **并查集和 DFS 求连通怎么选？** 动态加边选并查集；静态图 DFS 更直观。
15. **初始化 parent[i]=i 含义？** 每个元素自成一个集合（自己是根）。
16. **为什么合并前要 find？** 比较根是否相同，相同则不操作（已连通），不同才挂。
17. **并查集能删元素吗？** 原生难删；可「延时删除」或重建，不常用。
18. **最小生成树并查集 vs Prim？** 并查集配 Kruskal（边视角）；Prim 用堆（点视角）。
19. **连通块计数除了并查集还有什么？** DFS/BFS 遍历计数、Flood Fill。
20. **并查集在实战？** 社交好友、网络分区、Kruskal、图像分割、分布式一致性快照。
21. **路径压缩后 rank 还准确吗？** rank 只是上界估计，不精确也无妨，仅用于合并决策。
22. **如何判断两个元素是否已连通？** `find(x)==find(y)`。
23. **路径压缩后树高是多少？** 摊还极矮，但单次最坏仍可能 O(log n)（无按秩时 O(n)）。
24. **为什么叫反阿克曼？** α(n) 增长极慢（n 是 10^80 时 α≈5），所以「接近常数」。
25. **union 需要返回什么？** 建议 boolean：合并成功与否，判环/计数都靠它。
26. **带权并查集 find 的权值累加顺序？** 先递归到根，回溯时从父累加，保证每条边只加一次。
27. **「敌人/伙伴」关系的两种写法？** 种类并查集（开 2n/3n 空间）或带权取模。
28. **食物链为什么开 3n？** 把「同类/吃/被吃」编码为三类集合，查询矛盾。
29. **并查集能排序吗？** 不能；它是连通结构，不是排序结构。
30. **「最小生成树 Kruskal 判环」为什么并查集最合适？** 动态加边 + 判连通，正是并查集主场。
31. **在线（动态）判连通，并查集是最优吗？** 无删边时最优（α(n)）；有删边需离线/Link-Cut 树。
32. **并查集与「等值约束求解」？** 等式方程可满足性即「约束传播」的并查集解法。

## 七、并查集逐题精讲（含 Go 实现 + 复杂度）

### 7.1 标准模板（Go，路径压缩 + 按秩）

```go
type DSU struct {
    parent, rank []int
}
func NewDSU(n int) *DSU {
    p, r := make([]int, n), make([]int, n)
    for i := range p { p[i] = i }
    return &DSU{p, r}
}
func (d *DSU) Find(x int) int {
    for d.parent[x] != x { d.parent[x] = d.parent[d.parent[x]]; x = d.parent[x] } // 路径压缩（迭代）
    return x
}
func (d *DSU) Union(x, y int) bool { // 返回是否真的合并
    rx, ry := d.Find(x), d.Find(y)
    if rx == ry { return false }
    if d.rank[rx] < d.rank[ry] { d.parent[rx] = ry } else {
        d.parent[ry] = rx
        if d.rank[rx] == d.rank[ry] { d.rank[rx]++ }
    }
    return true
}
// 操作 O(α(n)) 摊还，空间 O(n)。
```

### 7.2 岛屿数量（200）：二维映射

```go
func numIslands(grid [][]byte) int {
    if len(grid) == 0 { return 0 }
    m, n := len(grid), len(grid[0])
    dsu := NewDSU(m * n)
    dirs := [][]int{{1, 0}, {-1, 0}, {0, 1}, {0, -1}}
    ones := 0
    for i := 0; i < m; i++ {
        for j := 0; j < n; j++ {
            if grid[i][j] == '1' {
                ones++
                for _, d := range dirs {
                    ni, nj := i+d[0], j+d[1]
                    if ni >= 0 && ni < m && nj >= 0 && nj < n && grid[ni][nj] == '1' {
                        if dsu.Union(i*n+j, ni*n+nj) { /* 合并成功 */ }
                    }
                }
            }
        }
    }
    // 连通块数 = 陆地总数 - 成功合并次数；也可扫所有陆地取不同根计数
    roots := map[int]bool{}
    for i := 0; i < m; i++ {
        for j := 0; j < n; j++ {
            if grid[i][j] == '1' { roots[dsu.Find(i*n+j)] = true }
        }
    }
    return len(roots)
}
// 时间 O(m*n*α)，空间 O(m*n)。与 DFS 等价，但适合"动态加陆"的场景。
```

### 7.3 账户合并（721）

```go
// 思路：每个邮箱是一个元素，同一账户的邮箱两两 union；再按连通块收集
func accountsMerge(accounts [][]string) [][]string {
    emailToId := map[string]int{}
    dsu := NewDSU(len(accounts) * 10) // 邮箱上限
    id := 0
    for _, acc := range accounts {
        for _, e := range acc[1:] {
            if _, ok := emailToId[e]; !ok { emailToId[e] = id; id++ }
        }
        first := emailToId[acc[1]]
        for _, e := range acc[2:] { dsu.Union(first, emailToId[e]) } // 同账户邮箱互并
    }
    groups := map[int][]string{}
    for e, idx := range emailToId {
        root := dsu.Find(idx)
        groups[root] = append(groups[root], e)
    }
    var res [][]string
    for _, list := range groups {
        sort.Strings(list)
        res = append(res, list)
    }
    return res
}
// 时间 O(N log N)（并查集 + 排序），空间 O(N)。
```

### 7.4 Kruskal 最小生成树（核心应用）

```go
func kruskal(n int, edges [][3]int) int { // edges: [u, v, w]
    sort.Slice(edges, func(i, j int) bool { return edges[i][2] < edges[j][2] }) // 边按权升序
    dsu := NewDSU(n)
    mst, cnt := 0, 0
    for _, e := range edges {
        if dsu.Union(e[0], e[1]) { // 不形成环才选入
            mst += e[2]
            cnt++
            if cnt == n-1 { break } // 生成树只需 V-1 条边
        }
    }
    if cnt != n-1 { return -1 } // 不连通
    return mst
}
// 时间 O(E log E)（排序），空间 O(V)。边视角的最小生成树，天然配并查集。
```

## 八、带权并查集进阶（向量推导）

### 8.1 食物链（240）思路

用 `3n` 空间把「同类 / 吃 / 被吃」编码为三类集合。关键规则：
- `x` 与 `y` 同类：`find(x)==find(y)`、`find(x+n)==find(y+n)`、`find(x+2n)==find(y+2n)` 须一致。
- `x` 吃 `y`：`find(x)==find(y+n)`、`find(x+n)==find(y+2n)`、`find(x+2n)==find(y)` 须一致。
- 出现矛盾即假话（题中第 2 类关系）。

```go
// 带权版更通用：维护 d[x] = x 到 root 的"关系值"（0 同类/1 吃/2 被吃），find 时 d[x] += d[parent[x]]
// 合并时按"向量三角形"推导权值，详见前文 3.1。
```

> 带权并查集三句口诀：**找根先压缩、回溯累加权、合并画向量**。

### 8.2 复杂度与边界（进阶）

| 操作 | 带两优化 | 仅路径压缩 | 仅按秩 | 无优化 |
|------|----------|------------|--------|--------|
| Find/Union | O(α(n)) | O(log n) | O(log n) | O(n) |

- 递归 find 在极深链上可能栈溢出，超大输入用**迭代版**（见 7.1）。
- 带权并查集 `find` 的权值累加顺序：必须先递归到根，**回溯时从父往子累加**，保证每条边只加一次。

## 九、并查集 vs 其他连通手段

| 手段 | 能否动态加边 | 能否判环 | 复杂度 | 适用 |
|------|------|------|------|------|

## 十、更多易错点（补充）

1. 初始化 `parent[i]=i`，每个元素自成一个集合。
2. `Union` 返回 boolean：判环 / 计数都靠它（合并失败说明已连通）。
3. 二维坐标务必 `idx = r*cols + c`，且 `rows*cols` 不溢出（大网格用 `int64`）。
4. 种类并查集开 `2n`/`3n` 空间，查询前先 `find` 再比。
5. 大数据量用迭代 find，避免递归爆栈。
6. rank 仅是高度上界估计，不必精确，仅用于合并决策。

## 十三、真题演练：冗余连接 + 等式方程

### 13.1 冗余连接（684）：唯一环边

```java
// 给一棵树 + 一条边形成环，按输入顺序加边，第一个"两端已连通"的边即环边
int[] findRedundantConnection(int[][] edges) {
    DSU d = new DSU(edges.length + 1);
    for (int[] e : edges)
        if (!d.Union(e[0], e[1])) return e; // 合并失败 → 已形成环
    return new int[0];
}
// 时间 O(n α(n))，空间 O(n)。若要求"删哪条边使树仍合法且保留最大输入序"，取最后一条冗余边即可。
```

### 13.2 等式方程可满足性（990）

```go
func equationsPossible(equations []string) bool {
    d := NewDSU(26)
    // 第一遍：合并所有 ==
    for _, e := range equations {
        if e[1] == '=' {
            d.Union(int(e[0]-'a'), int(e[3]-'a'))
        }
    }
    // 第二遍：检查所有 != 是否同集（同集则矛盾）
    for _, e := range equations {
        if e[1] == '!' {
            if d.Find(int(e[0]-'a')) == d.Find(int(e[3]-'a')) { return false }
        }
    }
    return true
}
// 时间 O(n α(26))≈O(n)，空间 O(1)。先并后查，是"约束传播"的并查集解法。
```

### 13.3 复杂度与边界（补充表）

| 场景 | 做法 | 复杂度 |
|------|------|--------|
| 连通块计数 | 扫所有元素取不同根 | O(n α) |
| 动态加边判环 | 合并失败即环 | O(n α) |
| Kruskal | 边排序 + 合并选 V-1 | O(E log E) |
| 等式/不等式 | 先并 == 再查 != | O(n α) |
| 食物链 | 3n 种类并查集 | O(n α) |

## 十四、速记补充与实战清单

- **手写并查集三要素**：`parent` 数组初始化、`Find` 路径压缩、`Union` 按秩 + 返回 boolean。
- **面试自测**：能否在 1 分钟内写出带两优化的 DSU？能否讲清 α(n) 为什么接近常数？
- **反例防御**：并查集不能直接删除元素；需要"删边连通性"时改用离线（时间倒流）或 Link-Cut 树。

> 一句话：**并查集 = 动态连通的瑞士军刀；写对优化、用对返回值是及格线，带权与种类是加分项**。
