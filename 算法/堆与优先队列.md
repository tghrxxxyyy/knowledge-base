# 堆与优先队列（Heap & Priority Queue）

## 〇、本体介绍

**堆**：一种**完全二叉树**，用数组实现，满足「父节点 ≤/≥ 子节点」（小顶堆/大顶堆）。核心操作 `push`/`pop` 都是 O(log n)，`top` O(1)。

**优先队列（PQ）**：抽象数据结构，底层常由堆实现。JDK 的 `PriorityQueue` 是小顶堆；想大顶堆传 `Comparator.reverseOrder()`。

**面试高频**：TopK、第 K 大、堆排序、数据流中位数、合并 k 个有序序列、定时器（最小堆存到期时间）。

---

## 一、堆的核心操作

- **上浮（sift up）**：插入末尾后与其父比较交换，直到满足堆序。
- **下沉（sift down）**：弹出堆顶后把末位移到顶，与较小/较大子比较下沉。
- **建堆**：从最后一个非叶节点向前 `siftDown`，O(n)（非 n log n）。

### 1.1 深挖：手写堆的完整实现（面试默写级）

```java
class MinHeap {
    int[] a;          // 从下标 1 开始，父 = i/2，子 = 2i、2i+1
    int size;

    MinHeap(int cap) { a = new int[cap + 1]; }

    void push(int x) {
        a[++size] = x;
        int i = size;
        while (i > 1 && a[i] < a[i / 2]) {   // 上浮：比父小就换
            swap(i, i / 2);
            i /= 2;
        }
    }

    int pop() {                              // 弹出堆顶
        int top = a[1];
        a[1] = a[size--];
        int i = 1;
        while (2 * i <= size) {              // 下沉：与较小的子节点换
            int c = 2 * i;
            if (c + 1 <= size && a[c + 1] < a[c]) c++;
            if (a[i] <= a[c]) break;
            swap(i, c);
            i = c;
        }
        return top;
    }

    // 建堆（heapify）：从最后一个非叶节点 size/2 开始向前下沉，O(n)
    void heapify(int[] arr, int n) {
        for (int i = n / 2; i >= 1; i--) sink(arr, i, n);
    }
    void sink(int[] arr, int i, int n) { /* 同 pop 的下沉逻辑 */ }
}
```

> **建堆为什么是 O(n)**：叶子不用动；第 k 层节点下沉代价与其高度成正比，级数求和收敛于 O(n)。若逐个插入则是 O(n log n)。

## 二、经典例题

- **TopK / 第 K 大（215）**：维护大小为 k 的**小顶堆**，遍历时大于堆顶则替换，最后堆顶即第 K 大；O(n log k)。
- **前 K 个高频元素（347）**：哈希计数 + 小顶堆（按频率），或桶排序 O(n)。
- **合并 k 个有序链表（23）**：小顶堆存各链表头，每次取最小并补入该链表的下一个。
- **数据流的中位数（295）**：**双堆**——大顶堆存较小半、小顶堆存较大半，两堆 size 差 ≤1，中位数即堆顶组合。
- **丑数（264）**：多指针 + 最小堆或直接三指针。

### 2.1 深挖：TopK 与双堆中位数模板

```java
// TopK：维护大小为 k 的小顶堆（留最大的 k 个），堆顶即第 K 大
public int findKthLargest(int[] nums, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>(); // 小顶堆
    for (int x : nums) {
        heap.offer(x);
        if (heap.size() > k) heap.poll();   // 超过 k 就丢掉当前最小
    }
    return heap.peek();
}
// 变体：前 K 个最小 → 大顶堆（Comparator.reverseOrder()），堆顶即第 K 小

// 双堆求中位数（数据流，O(log n) 插入）
class MedianFinder {
    PriorityQueue<Integer> lo = new PriorityQueue<>(Comparator.reverseOrder()); // 大顶堆（较小半）
    PriorityQueue<Integer> hi = new PriorityQueue<>();                          // 小顶堆（较大半）

    public void addNum(int x) {
        lo.offer(x);          // 先入 lo
        hi.offer(lo.poll());  // 把 lo 最大送入 hi → hi 始终 ≥ lo
        if (lo.size() < hi.size()) lo.offer(hi.poll());  // 平衡：lo 不短于 hi
    }
    public double findMedian() {
        return lo.size() > hi.size() ? lo.peek() : (lo.peek() + hi.peek()) / 2.0;
    }
}
```

> 工程提示：JDK `PriorityQueue` 是非线程安全的；多线程用 `PriorityBlockingQueue`。延时/定时任务常用「按到期时间排序的小顶堆」（见 场景设计/延迟任务与订单超时关闭.md）。

## 三、堆排序

- 建大顶堆 → 反复把堆顶（最大）与末位交换并下沉 → 得到升序。O(n log n)，原地、不稳定。
- 相比快排：最坏也 O(n log n)；但常数大、缓存不友好，实际常慢于快排。

### 3.1 深挖：堆排序实现

```java
public void heapSort(int[] a) {
    int n = a.length;
    // 1) 建大顶堆（数组下标从 0 开始：左=2i+1，右=2i+2）
    for (int i = n / 2 - 1; i >= 0; i--) sink(a, i, n);
    // 2) 反复取堆顶与末位交换、缩小范围下沉
    for (int i = n - 1; i > 0; i--) {
        swap(a, 0, i);
        sink(a, 0, i);
    }
}
void sink(int[] a, int i, int n) {
    while (2 * i + 1 < n) {
        int c = 2 * i + 1;
        if (c + 1 < n && a[c + 1] > a[c]) c++;
        if (a[i] >= a[c]) break;
        swap(a, i, c);
        i = c;
    }
}
```

## 四、易错点

- 大小顶堆别搞反：TopK 用**小顶堆**（容量 k）才能留最大的 k 个。
- 双堆求中位数要平衡 size，插入时先入一堆放另一堆再平衡。
- `PriorityQueue` 默认小顶， comparator 写反会变「越大越优先出」。
- 堆排序循环边界：`sink` 的 n 是「当前堆大小」，交换后递减。

## 五、工程应用：堆/优先队列在源码与系统中的位置

| 场景 | 说明 |
|------|------|
| JDK `PriorityQueue`/`PriorityBlockingQueue` | 默认小顶堆；无界阻塞队列的调度基础 |
| Java 定时器 `ScheduledThreadPoolExecutor` | **DelayedWorkQueue 是优先队列**，按到期时间排序（见 源码系列/ThreadLocal与并发集合源码.md） |
| Netty | `HashedWheelTimer`（时间轮）；默认也支持 DelayQueue |
| Redis | ZSet 用跳表（非堆），但 `maxmemory` 近似 LRU 采样思想类似堆的淘汰 |
| Kafka | 时间轮延迟队列；`Streams` 分组聚合用优先队列 |
| MySQL | 排序缓冲的 TopN 优化（堆排序做 limit k） |
| 操作系统 | 调度器就绪队列（按优先级）、中断处理 |
| 图算法 | Dijkstra 的优先队列优化（O((V+E) log V)）、Prim 最小生成树 |

> 面试加分：**时间轮 vs 最小堆做延迟任务**——时间轮 O(1) 插删但精度受槽粒度限制，最小堆精度高但 O(log n)。延迟消息/订单超时（见 场景设计/延迟任务与订单超时关闭.md）常两者结合。

## 面试高频问题（30+ 条）

1. **堆的时间复杂度？** push/pop O(log n)，建堆 O(n)，top O(1)。
2. **堆为什么用数组？** 完全二叉树可下标映射（i 的父=(i-1)/2，左=2i+1，右=2i+2），省指针。
3. **TopK 为什么用小顶堆？** 堆只留最大的 k 个，堆顶是这 k 个里最小（即第 K 大），新元素更大才入。
4. **TopK 能不用堆吗？** 能：快排 partition 平均 O(n)、桶/计数（值域小）、BFPRT 最坏 O(n)。堆适合数据流。
5. **PriorityQueue 默认大顶还是小顶？** 小顶堆（自然序升序出队）。
6. **如何用两个堆求中位数？** 大顶堆存较小半、小顶堆存较大半，平衡 size，中位数取堆顶组合。O(log n) 插入。
7. **堆排序稳定吗？** 不稳定（交换破坏相等元素顺序）。
8. **建堆为什么 O(n)？** 从末非叶向上下沉，级数求和得 O(n) 而非 n log n。
9. **堆和 BST 区别？** 堆只保证父子序、不保证全局有序、查找任意值 O(n)；BST 中序有序、查找 O(log n)。
10. **最小堆实现定时器？** 按到期时间入小顶堆，轮询取堆顶若到期则执行，否则等待到堆顶时间。
11. **合并 k 个有序链表用堆？** 小顶堆放各链表当前头，取最小后补该链表下一节点，O(n log k)。
12. **堆在源码哪用？** Java 定时器、Redis 有序集合（跳表为主）、调度器优先级、Dijkstra 优先队列。
13. **为什么堆求 TopK 比排序快？** 只维护 k 个，O(n log k) < O(n log n)（k≪n）。
14. **大顶堆怎么写（Java）？** `new PriorityQueue<>(Comparator.reverseOrder())` 或 `(a,b)->b-a`。
15. **堆化（heapify）是啥？** 把任意数组调整成堆，从末非叶节点下沉，O(n)。
16. **TopK 数据流场景？** 数据无限、不能全存，堆维护 k 个即可。
17. **第 K 小怎么求？** 维护大小为 k 的**大顶堆**，逻辑对称。
18. **堆能求第 K 大和第 K 小一起吗？** 可维护双堆分别管大小半，类似中位数。
19. **为什么堆排序缓存不友好？** 下沉跳跃访问，局部性差；快排顺序访问更优。
20. **优先队列能用平衡树吗？** 能（如 TreeSet），支持 O(log n) 删除任意值、范围查询，但常数更大。
21. **斐波那契堆？** 理论更优（decrease-key O(1)），但实际常数大，Dijkstra 工程多用二叉堆。
22. **如何用堆做「多路归并」？** 同合并 k 链表思想，适用于外部排序多段归并。
23. **堆的插入过程？** 末尾插入 + 上浮比较交换到满足堆序。
24. **堆的删除过程？** 堆顶与末尾交换，移除末尾，新顶下沉。
25. **删除堆中任意元素（非顶）？** 需要索引支持（如带位置数组）；标堆做不到，工程用标记删除或懒删除。
26. **懒删除是什么？** 把待删元素标记，出堆时若标记则丢弃继续出——处理「堆顶已失效」场景。
27. **时间轮 vs 最小堆？** 时间轮 O(1) 插删、粒度受限；最小堆 O(log n)、精度高，常用「时间轮+桶」组合。
28. **MySQL limit k 为什么用堆？** 排序缓冲只保留前 k 最小，避免全排 O(n log n)。
29. **二叉堆 vs d 叉堆？** d 叉堆下沉比较次数多但高度低；缓存友好性不同，k=4 左右常用。
30. **为什么 Dijkstra 用堆不用数组？** 数组取最小 O(n)，堆 O(log n)，稀疏图大幅提速。
31. **TopK 的海量数据场景（10 亿取前 100）？** 单机堆 O(n log k)；分布式可每机 TopK 再归并，或用 Trie/位图。
32. **PriorityQueue 可以存 null 吗？** 不能（构造器即抛 NPE），比较器为空时按自然序。
