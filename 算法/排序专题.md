# 排序专题（Sorting）

## 〇、本体介绍

**排序**是算法面试的"开场白"：背模板、比复杂度、讲稳定性，三件事一次考察完。本章覆盖**手写模板**（快排/归并/堆排/插入/冒泡/选择）、**经典复杂度对比表**、**稳定性分析**与**工程选型**，配套高频问答题。

**面试高频**：手写快排、归并排序（含链表版）、快排与归并的差异、稳定性、TopK 三种解法（见「[堆与优先队列](堆与优先队列.md)」）。

## 一、复杂度总览（背这张表）

| 算法 | 平均 | 最坏 | 最好 | 空间 | 稳定 | 备注 |
|------|------|------|------|------|------|------|
| 冒泡排序 | O(n²) | O(n²) | O(n)（已有序+标志位） | O(1) | ✅ | 简单，教学用 |
| 选择排序 | O(n²) | O(n²) | O(n²) | O(1) | ❌ | 交换次数最少 |
| 插入排序 | O(n²) | O(n²) | O(n)（近乎有序） | O(1) | ✅ | **小数组/近乎有序最优** |
| 希尔排序 | O(n^1.3) | O(n²) | O(n) | O(1) | ❌ | 插入的改进，分步长 |
| 归并排序 | O(n log n) | O(n log n) | O(n log n) | O(n) | ✅ | 稳定、外部排序基础 |
| 快速排序 | O(n log n) | **O(n²)**（有序+固定 pivot） | O(n log n) | O(log n) | ❌ | **平均最快**，工程默认 |
| 堆排序 | O(n log n) | O(n log n) | O(n log n) | O(1) | ❌ | 原地但缓存不友好 |
| 计数排序 | O(n+k) | O(n+k) | O(n+k) | O(k) | ✅ | 值域小、非比较 |
| 桶排序 | O(n+k) | O(n²) | O(n+k) | O(n+k) | ✅ | 数据均匀分布 |
| 基数排序 | O(d(n+k)) | O(d(n+k)) | O(d(n+k)) | O(n+k) | ✅ | 按位排序，d 为位数 |

> 记忆口诀：**"快"均快于堆；稳定看"冒插归基数桶计"；归并最坏也 O(n log n)，快排最坏退化 O(n²)。**

## 二、手写模板（面试必背）

### 2.1 快速排序（最常考）

```java
// 三数取中 + 双指针分区，规避有序数组退化
void quickSort(int[] a, int l, int r) {
    if (l >= r) return;
    int p = partition(a, l, r);
    quickSort(a, l, p - 1);
    quickSort(a, p + 1, r);
}

int partition(int[] a, int l, int r) {
    int mid = l + (r - l) / 2;
    // 三数取中：把 a[l],a[mid],a[r] 的中位数换到 l，做 pivot
    if ((a[l] > a[mid]) != (a[l] > a[r])) { /* a[l] 即中位数 */ }
    else if ((a[mid] > a[l]) != (a[mid] > a[r])) swap(a, l, mid);
    else swap(a, l, r);
    int pivot = a[l];
    while (l < r) {
        while (l < r && a[r] >= pivot) r--;   // 注意 >= 防死循环
        a[l] = a[r];
        while (l < r && a[l] <= pivot) l++;
        a[r] = a[l];
    }
    a[l] = pivot;
    return l;
}
```

- **复杂度**：平均 O(n log n)；**每次 partition 只切掉 1 个**时退化 O(n²)（有序数组 + 固定首元素 pivot）。
- **稳定性**：交换会打乱相等元素顺序 → 不稳定。
- **工程优化**：三数取中、随机 pivot、小区间（< 16）改用插入排序、重复元素三路切分。

### 2.2 归并排序（链表排序靠它）

```java
void mergeSort(int[] a, int l, int r) {
    if (l >= r) return;
    int mid = l + (r - l) / 2;
    mergeSort(a, l, mid);
    mergeSort(a, mid + 1, r);
    merge(a, l, mid, r);
}

void merge(int[] a, int l, int mid, int r) {
    int[] tmp = new int[r - l + 1];      // O(n) 辅助空间
    int i = l, j = mid + 1, k = 0;
    while (i <= mid && j <= r) tmp[k++] = a[i] <= a[j] ? a[i++] : a[j++];  // <= 保稳定
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= r) tmp[k++] = a[j++];
    System.arraycopy(tmp, 0, a, l, tmp.length);
}
```

- **稳定**：合并时左半优先（`<=`），相等元素保持原序。
- **任何情况都是 O(n log n)**：适合对最坏复杂度敏感的场景。
- **链表排序**：`Merge Sort` 无需辅助数组（链表天然支持 O(1) 合并），LeetCode 148。

### 2.3 堆排序（见「[堆与优先队列](堆与优先队列.md)」）

建大顶堆 → 堆顶与末位交换 → 下沉，O(n log n)，原地不稳定。面试考原理多过手写。

### 2.4 插入排序（小数组/近乎有序最优）

```java
void insertionSort(int[] a) {
    for (int i = 1; i < a.length; i++) {
        int cur = a[i], j = i - 1;
        while (j >= 0 && a[j] > cur) {   // 大于才右移，相等不动 → 稳定
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = cur;
    }
}
```

- 几乎有序时接近 O(n)；常数小，是快排小区间递归的收尾选择。
- JDK `Arrays.sort` 对**对象数组**用的就是"归并/插入变体（TimSort）"。

### 2.5 冒泡 / 选择（手写热身）

```java
// 冒泡：相邻交换，稳定；加 swapped 标志，有序即停
void bubbleSort(int[] a) {
    for (int i = 0; i < a.length - 1; i++) {
        boolean swapped = false;
        for (int j = 0; j < a.length - 1 - i; j++) {
            if (a[j] > a[j + 1]) { swap(a, j, j + 1); swapped = true; }
        }
        if (!swapped) break;
    }
}

// 选择：每轮找最小值放到前部，不稳定（跨距离交换）
void selectionSort(int[] a) {
    for (int i = 0; i < a.length - 1; i++) {
        int minIdx = i;
        for (int j = i + 1; j < a.length; j++) if (a[j] < a[minIdx]) minIdx = j;
        swap(a, i, minIdx);
    }
}
```

## 三、稳定性分析（为什么重要）

- **稳定的排序**：冒泡、插入、归并、计数、桶、基数。
- **不稳定的排序**：选择、希尔、快排、堆排。
- **排序稳定性有什么用？** 多字段排序时需要：先按时间排，再按分数排 → 若第二步稳定，则分数相同者仍保持时间序。数据库 `ORDER BY a, b`、表格多列排序都依赖这一点。

> 记忆口诀：**"选希快堆不稳定，冒插归计桶基稳"**。

## 四、工程选型（生产怎么排）

| 场景 | 选择 | 原因 |
|------|------|------|
| 通用排序（JDK `Arrays.sort`） | 快排（基本类型）/ TimSort（对象） | 平均最快；对象要稳定所以用归并变体 |
| 近乎有序（日志按时间几乎有序） | 插入排序 | O(n)，常数小 |
| 内存受限 + 最坏情况敏感 | 堆排序 | 原地 O(1) 空间，无 O(n²) |
| 稳定性要求（多字段排序） | 归并排序 | 稳定 + 最坏 O(n log n) |
| 超大文件（无法全部进内存） | 外部排序 = 归并 | 分块排序 + 多路归并 |
| 值域小（成绩 0~100、年龄） | 计数排序 | O(n+k) 线性 |
| 浮点/均匀分布大数据 | 桶排序 | 哈希到桶内各自排 |

> ⚠️ 实战提醒：**快排在有序数据上退化**是经典事故（误把固定 pivot 用在大数据量有序流上）；语言库默认排序都是调过的，自写排序要补随机 pivot 或三数取中。

## 五、TopK 与排序的关系（高频交叉题）

- **排序后取前 k**：O(n log n)，不划算。
- **堆（小顶堆容量 k）**：O(n log k)，数据流友好，见「[堆与优先队列](堆与优先队列.md)」。
- **快排 partition**：平均 O(n)——partition 返回位置 > k 只排左半，只排右半，平均砍半。BFPRT 可把最坏也做到 O(n)（工程少用）。

```java
// 快排思想求第 K 大：partition 后根据下标只递归一侧
int findKthLargest(int[] a, int k) {
    int l = 0, r = a.length - 1, target = a.length - k;
    while (true) {
        int p = partition(a, l, r);       // 复用 2.1 的 partition（升序）
        if (p == target) return a[p];
        else if (p < target) l = p + 1;
        else r = p - 1;
    }
}
```

## 面试高频问题（20+ 条）

1. **手写快排，说说复杂度？** 平均 O(n log n)，有序+固定 pivot 退化 O(n²)；空间 O(log n)（递归栈）。
2. **快排为什么不稳定？** partition 交换跨距离移动相等元素，可能越过与其相等的元素。
3. **归并为什么稳定？** 合并时左半 `<=` 右半先取，相等元素保持原顺序。
4. **为什么工程上对象排序用归并不用快排？** 稳定性要求：快排不稳定，TimSort（归并变体）稳定且对近乎有序数据 O(n)。
5. **堆排序为什么慢于快排？** 下沉跳跃访问内存（缓存不友好），快排顺序扫描。
6. **排序稳定性有什么用？** 多字段排序时保留前序排序的次序。
7. **近乎有序数组用什么排序？** 插入排序 O(n)（如 TimSort 的实际应用场景）。
8. **O(n log n) 是比较排序的下界？** 是，决策树模型：n! 种排列 ≥ 2^h，h ≥ log(n!) ≈ n log n。
9. **计数排序的限制？** 值域 k 大则内存爆炸；只能排整数（或可映射整数）。
10. **基数排序 vs 计数排序？** 基数按位多次排序（LSD/MSD），位数 d 决定趟数；计数一次到位。
11. **链表排序用什么？** 归并：链表切半无需随机访问，合并 O(1) 指针操作，空间 O(log n)（递归）或 O(1)。
12. **第 K 大除了排序还有啥？** 堆 O(n log k)、快排 partition 平均 O(n)、BFPRT 最坏 O(n)。
13. **快排优化手段？** 随机/三数取中 pivot、小区间插入排序、重复元素三路切分（三分快排）。
14. **外部排序是什么？** 数据超内存：分段读入内存排好写回（归并段），最后多路归并。
15. **希尔排序的增量怎么选？** 希尔序列/1,3,7…；最坏仍 O(n²)，但实际快于简单插入。
16. **稳定排序的稳定指什么？** 相等元素的相对顺序不变。
17. **Arrays.sort 基本类型为什么用快排？** 基本类型无需稳定，快排平均更快且常数小。
18. **Collections.sort 用什么？** TimSort：稳定、自适应（检测已有有序段合并）。
19. **什么场景排序会退化？** 快排：有序/逆序 + 固定 pivot；桶排序：数据全进一个桶。
20. **能否 O(n) 排序？** 非比较排序（计数/桶/基数）可，但依赖数据特性（值域/分布）。
21. **归并排序的空间能优化吗？** 手写可减少临时数组复用（仍 O(n)）；链表归并 O(1) 空间。
22. **三路快排解决什么？** 大量重复元素：=pivot 单独归堆，两边递归，避免退化成 O(n²)。
23. **排序在框架里的应用？** MySQL `filesort`（内存排序/归并外部排序）、Kafka 页缓存排序索引、ES 倒排合并。
