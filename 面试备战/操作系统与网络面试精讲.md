# 操作系统与网络面试精讲

> 本文面向后端/基础架构面试，梳理操作系统与计算机网络的高频考点：进程线程、内存管理、IO 模型、TCP/UDP、HTTP、HTTPS、DNS、以及常见追问。重原理与对比，而非死记数字。

## 1. 进程与线程

- 进程：资源分配基本单位，独立地址空间。
- 线程：调度基本单位，共享进程内存。
- 切换成本：进程 > 线程（地址空间切换）。
- 通信：进程靠 IPC（管道/消息队列/共享内存/套接字）；线程靠共享内存（需同步）。

## 2. 协程（Coroutine）

- 用户态轻量线程，调度在用户层，切换成本极低。
- 适合高并发 IO（如 Go goroutine、Java 虚拟线程思路）。
- 与线程关系：M:N 映射，少量 OS 线程跑大量协程。

## 3. 内存管理

- 虚拟内存：每个进程独享虚拟地址空间，MMU 映射到物理。
- 分页：虚拟/物理都按页（如 4KB）管理，解决碎片。
- 缺页中断：访问未加载页，触发从磁盘换入。
- 分段 vs 分页：分段按逻辑（代码/数据段），分页按固定大小。

## 4. 缓存与局部性

- CPU 缓存层级：L1/L2/L3，越近越快越小。
- 时间局部性：刚访问的很可能再访问。
- 空间局部性：邻近地址很可能访问。
- 程序应尽量连续访问，提升命中。

## 5. IO 模型

- 阻塞 IO：调用后一直等，直到完成。
- 非阻塞 IO：立即返回，需轮询。
- IO 多路复用：select/poll/epoll，一个线程管多连接（见 Netty Reactor）。
- 异步 IO（AIO）：完成后回调，真正不阻塞。
- epoll 优势：事件驱动，无连接数线性扫描，高并发基础。

## 6. 零拷贝

- 传统 IO：内核缓冲区 ↔ 用户缓冲区 ↔ 套接字，多次拷贝。
- sendfile：内核内直接转发，减少拷贝（如文件服务器）。
- mmap：文件映射到内存，省一次拷贝。
- 与 Netty/消息队列零拷贝思想呼应。

## 7. TCP 核心

- 可靠：序号、确认、重传、滑动窗口。
- 三次握手：确认双方收发能力，同步初始序号。
- 四次挥手：全双工关闭，各自关闭方向。
- 流量控制：滑动窗口防发送过快。
- 拥塞控制：慢启动、拥塞避免、快重传、快恢复。

## 8. 为什么三次握手

- 两次不够：无法确认服务端收能力，且旧连接请求可能建错连接。
- 不是两次能确认双方的收发都正常。
- 四次可合并（SYN+ACK 一起），故三次。

## 9. TIME_WAIT

- 主动关闭方最后进入 TIME_WAIT，等待 2MSL。
- 目的：确保最后 ACK 到达、让旧报文消散。
- 高并发短连接下 TIME_WAIT 多，占端口；可调 reuse/timestamps（依系统）。

## 10. UDP 特点

- 无连接、不可靠、快、支持广播。
- 无握手/重传，适合实时（音视频、DNS、游戏）。
- 应用层需自己保证可靠（如 QUIC/自研）。

## 11. HTTP 要点

- 无状态，靠 Cookie/Session/Token 维持状态。
- 方法：GET/POST/PUT/DELETE 等。
- 状态码：2xx 成功、3xx 重定向、4xx 客户端、5xx 服务端。
- 持久连接（keep-alive）复用 TCP，减少握手。
- HTTP/2：多路复用、头部压缩、服务端推送。

## 12. HTTPS

- HTTP + TLS，加密 + 认证 + 完整性。
- 过程：TCP → TLS 握手（证书验证、密钥协商）→ 加密传输。
- 对称加密传数据，非对称协商密钥。
- 证书由 CA 签发，防中间人。

## 13. DNS

- 域名 → IP 的分布式系统。
- 递归查询 + 迭代查询。
- 解析链：根 → 顶级域 → 权威。
- 缓存减少查询；DNS 劫持/污染是安全风险。

## 14. 长连接与短连接

- 短连接：每次请求新建（HTTP/1.0 风格），开销大。
- 长连接：复用一个连接（keep-alive、WebSocket、RPC）。
- 选哪个看请求频率与场景。

## 15. 负载均衡层次

- DNS 轮询（粗）、L4（IP/端口）、L7（HTTP 内容）。
- 算法：轮询、最少连接、一致性哈希。
- 与高并发架构章节呼应。

## 16. 常见追问

- epoll 和 select 区别？→ epoll 事件驱动无轮询、支持海量连接。
- TIME_WAIT 太多怎么办？→ 端口复用/调参/连接池。
- 为什么 TCP 可靠？→ 序号确认重传+窗口。
- HTTPS 握手几次？→ TCP 三次 + TLS 若干。
- 进程线程区别？→ 资源单位 vs 调度单位。
- 零拷贝是什么？→ 减少内核用户间多余拷贝。

## 17. 实战关联

- 网络编程：Netty/IO 多路复用（见源码章节）。
- 高并发：连接池、长连接、epoll（见架构章节）。
- 安全：HTTPS/mTLS（见网格/安全章节）。
- 数据库：连接池、TCP 握手成本（见存储章节）。

## 18. 常见易错

1. **混淆进程线程**：线程不独立地址空间。
2. **认为 UDP 不可靠就无用**：实时场景正需要它。
3. **TIME_WAIT 误判为 bug**：正常机制。
4. **HTTP 无状态理解偏**：靠上层维持会话。
5. **epoll 当万能**：仍是同步非阻塞，配合多线程。
6. **HTTPS 只在握手加密**：全程加密，握手只是协商。

## 19. 复习建议

- 抓主线：进程/内存/IO 一条线，TCP/HTTP 一条线。
- 多问"为什么"（为什么三次握手、为什么 TIME_WAIT）。
- 结合网络编程与高并发理解，而非孤立背。

## 20. 小结

操作系统与网络是后端基础：进程线程协程定位资源与调度，虚拟内存与缓存决定性能，IO 模型（尤其 epoll）支撑高并发；TCP 可靠靠序号/确认/窗口，HTTPS 靠 TLS 加密认证，DNS 解析靠分层缓存。面试重"为什么"与对比（阻塞/非阻塞、TCP/UDP、进程/线程），并能与网络编程、高并发架构串联理解。
