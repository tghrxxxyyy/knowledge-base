## 一、索引（最高频）

### 1.1 为什么用 B+ 树而不是 B 树/红黑树/哈希
- **B+ 树**：非叶子节点只存 key，扇出大、树矮（3 层存千万级）；叶子成双向链表，**范围查询/排序极快**；
- **红黑树**：树高 log n 但仍是 O(log n) 且非叶子存数据，扇出小、范围查询要中序遍历，不适合磁盘；
- **哈希**：等值 O(1) 但**不支持范围/排序**；
- **B 树**：非叶子也存数据，扇出小、范围查询差。

> 结论：磁盘 IO 友好（矮胖）+ 范围友好 → B+ 树是关系库索引事实标准。

### 1.2 聚簇 vs 非聚簇
- **聚簇索引（InnoDB）**：叶子存整行数据，主键即聚簇；一张表只有一个；
- **二级索引**：叶子存主键值，回表需再查聚簇；
- **覆盖索引**：查询字段都在索引里，免回表 → 重点优化手段。

### 1.3 最左前缀与索引失效
- 联合索引 `(a,b,c)` 生效：用 `a`、`a,b`、`a,b,c`、`a,c`（c 失效但 a 用上）；
- **失效场景**：对索引列运算/函数、隐式类型转换、`LIKE '%x'` 前模糊、OR 含非索引列、使用 `!=`/`NOT IN` 视情况、违背最左前缀。

## 二、事务与隔离级别

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 实现 |
|----------|------|-----------|------|------|
| 读未提交 | ❌ | ❌ | ❌ | 无锁 |
| 读已提交 RC | ✅ | ❌ | ❌ | 语句级快照 |
| 可重复读 RR | ✅ | ✅ | ❌(MVCC 防大部分) | MVCC + 间隙锁 |
| 串行化 | ✅ | ✅ | ✅ | 锁全表 |

- **MVCC**： undo log 多版本 + ReadView，读不加锁、读写不阻塞；
- **幻读**：RR 下靠 **Next-Key Lock（间隙锁+记录锁）** 防插入。

### 2.1 事务问题速记
| 问题 | 含义 |
|------|------|
| 脏读 | 读到别的事务未提交的数据 |
| 不可重复读 | 同事务内两次读同行结果不同（被改） |
| 幻读 | 同事务内两次范围查询结果集行数变（被增删） |

## 三、SQL 优化套路（面试开口即答）

1. **EXPLAIN 看执行计划**：type（ALL 全表最差→const 最优）、key（用到索引）、rows（扫描行）、Extra（Using filesort/index）；
2. **慢查询日志** 定位慢 SQL；
3. **加/调索引**：覆盖索引、联合索引最左、避免失效；
4. **重写 SQL**：避免 `SELECT *`、减少子查询改 JOIN、分页深翻用游标/id>last；
5. **架构层**：读写分离、分库分表、缓存扛读。

```sql
-- 深分页优化：用上一页最大 id 游标
SELECT * FROM orders WHERE id > ? ORDER BY id LIMIT 20;
```

## 四、锁

| 锁 | 范围 | 用途 |
|----|------|------|
| 行锁 | 单行 | 高并发更新 |
| 间隙锁 | 范围空隙 | 防幻读 |
| 表锁 | 整表 | DDL、全表更新 |
| 意向锁 | 表级标记 | 快速判断能否加表锁 |
| 死锁 | — | 两事务互等 → 检测+回滚一方 |

> 避免死锁：固定加锁顺序、缩短事务、降低锁粒度。

## 五、分库分表（高频场景题）

- **垂直拆分**：按列/按业务（订单库、用户库）；治"表宽/业务耦合"；
- **水平拆分**：按 id 哈希/范围路由；治"数据量大"；
- **分片键**：选高频查询维度（user_id），避免跨分片 JOIN；
- **跨分片查询**：ES 宽表 / 冗余 / 基因法（分片键包含关联键信息）；
- 详见[分库分表与数据迁移](../分库分表与数据迁移/)。

## 六、经典场景题

### 6.1 如何设计短链系统存储？
- 短码作主键（Base62），KV/关系表皆可；读多写少，缓存扛读；
- 容量：`62^6 ≈ 568 亿` 足够。

### 6.2 怎么统计日活/留存？
- 位图（Bitmap）/ HyperLogLog 近似；明细落表按天 partition。

### 6.3 大表加字段卡死？
- MySQL 8 在线 DDL（INSTANT）；或 pt-osc/gh-ost 无锁变更。

### 6.4 缓存与 DB 一致性？
- 写：先更新 DB 再删缓存（或延迟双删）；读未命中回源回填；最终一致 + 对账（见[高并发架构实战](../架构/高并发架构实战.md)）。

## 七、面试高频追问

1. Q：为什么 B+ 树？ A：矮胖（扇出大、磁盘友好）+ 叶子链表（范围/排序快）。
2. Q：聚簇和非聚簇区别？ A：聚簇叶子存整行（主键即聚簇），二级索引叶子存主键需回表。
3. Q：覆盖索引？ A：查询列全在索引 → 不回表，性能关键。
4. Q：最左前缀？ A：联合索引按左列优先匹配，违背则失效。
5. Q：RR 怎么防幻读？ A：MVCC + Next-Key Lock（间隙锁）。
6. Q：MVCC 原理？ A：undo log 版本链 + ReadView，读不加锁。
7. Q：深分页怎么优化？ A：游标（id>last ORDER BY id LIMIT）。
8. Q：死锁怎么避免？ A：固定加锁顺序、缩短事务、降粒度。
9. Q：分库分表分片键？ A：选高频查询维度，避免跨分片 JOIN。
10. Q：大表加字段？ A：在线 DDL / gh-ost 无锁变更。

## 八、Cheat Sheet

| 主题 | 要点 |
|------|------|
| 索引 | B+树矮胖+范围友好；覆盖索引免回表；最左前缀 |
| 事务 | RR 靠 MVCC+间隙锁；RC 语句级快照 |
| 优化 | EXPLAIN→索引→重写→读写分离/分表 |
| 锁 | 行/间隙/表；死锁防：顺序+短事务 |
| 分表 | 垂直治宽、水平治大；分片键选高频维 |
