# 系统设计题精解（面试高频）

> 板块：面试备战 　|　 返回：[README](README.md)

## 一、系统设计面试的套路

面试官不考你背答案，考「拆解问题 + 权衡取舍 + 演进思维」。标准解题框架：

1. **澄清需求**：功能范围、QPS、数据量、延迟要求、读多还是写多。
2. **估算容量**：用二八定律算存储/带宽/QPS，作为技术选型依据。
3. **画骨架**：核心组件（网关、服务、存储、缓存、MQ）先搭出来。
4. **逐层深入**：每组件选方案，说清为什么，以及瓶颈在哪。
5. **权衡与降级**：CAP 怎么取舍、峰值怎么扛、故障怎么降级。
6. **演进**：从单机到集群，从小规模到大规模，分阶段讲。

> 关键：宁可慢但要问清需求，不要上来就堆技术名词。

## 二、容量估算速算

| 量 | 估算 |
|----|------|
| 1 亿用户、10% 日活 | 1000 万 DAU |
| 人均 20 次请求/天 | 2 亿次/天 ≈ 2300 QPS 均值 |
| 峰值系数 3 | ~7000 QPS 峰值 |
| 单条记录 1KB | 2 亿条 ≈ 200 GB/天 |

- 存储：算年增量（200GB×365 ≈ 70TB），决定分库分表或冷热分离。
- 带宽：响应 10KB × 7000 QPS ≈ 70 MB/s，决定 CDN/压缩策略。

## 五、经典题：设计一个 Feed 流

- 见 [场景设计/Feed信息流设计](../../场景设计/Feed信息流设计.md)。
- 考察点：推模式（写扩散）vs 拉模式（读扩散）、冷热分离、游标分页。

## 六、经典题：设计一个限流器

- 算法：计数器、滑动窗口、令牌桶、漏桶。
- 分布式限流用 Redis + Lua 或网关层（Sentinel/Kong）。
- 考察点：精度 vs 性能、集群一致性。

## 七、经典题：设计一个缓存层

- 见 [场景设计/缓存经典三问与一致性](../../场景设计/缓存经典三问与一致性.md)。
- 考察点：缓存穿透/击穿/雪崩、一致性、多级缓存。

## 八、经典题：设计一个排行榜

- Redis Sorted Set（ZADD/ZRANGE）天然支持。
- 海量用户用分片 + 合并，或离线计算 + 缓存。

## 九、经典题：设计一个搜索引擎

- 倒排索引 + 分词 + TF-IDF/BM25 + 排序。
- 见 Elasticsearch 思路；实时性用近实时 refresh。

## 十、高并发通用武器库

- 缓存（Redis）、异步（MQ）、分片（分库分表）、限流（令牌桶）、降级（熔断）、冗余（多副本）。
- 读写分离、CDN、静态化、预热。

## 十一、数据一致性怎么答

- 强一致：2PC/事务，性能差，少用。
- 最终一致：本地消息表、事务消息、Saga、TCC。
- 见 [场景设计/分布式事务与最终一致] 与 [分库分表]。

## 十二、常见失分点

1. 不问需求直接开写 → 方向错。
2. 只讲技术不问规模 → 选型无依据。
3. 忽视瓶颈与降级 → 不落地。
4. 背诵流行架构但不懂权衡 → 一问就露馅。
5. 不画演进 → 显得只考虑当前。

## 十三、答题话术模板

「这个系统峰值约 X QPS、存储 Y，我先用缓存+分库分表扛量；一致性上选最终一致用事务消息；峰值用 MQ 削峰+限流；故障降级到只读/排队。后续如果量再涨，做 X 演进。」
