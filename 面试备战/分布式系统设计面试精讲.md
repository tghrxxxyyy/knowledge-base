# 分布式系统设计面试精讲

> 本文面向后端/架构面试，讲解分布式系统设计题的通用解法：需求澄清、容量估算、数据建模、核心组件选型、一致性、可用性与扩展性设计，并附典型题目拆解套路。重方法论而非背答案。

## 1. 面试解题四步法

1. **澄清需求**：功能范围、QPS、数据量、延迟、一致性要求、读写比。
2. **容量估算**：用二八定律粗算存储、带宽、机器数。
3. **高层设计**：画出核心组件（客户端/CDN/网关/服务/缓存/DB/MQ）。
4. **深挖瓶颈**：一致性、热点、故障、扩展性，逐项优化。

## 2. 需求澄清清单

- 功能性：支持哪些操作？
- 规模：DAU、峰值 QPS、总量、增长。
- 延迟：P99 要求？
- 一致性：能否最终一致？
- 可用性：SLA 几个 9？
- 约束：成本、合规、地域。

## 3. 容量估算套路

- 读 QPS = DAU × 人均日读 ÷ 86400 × 峰值系数。
- 存储 = 单条大小 × 总量 × 副本 × 保留期。
- 带宽 = QPS × 平均响应大小。
- 机器数 = 峰值 QPS ÷ 单实例容量 × 安全系数。
- 估算不求精确，求"数量级合理"。

## 4. 通用架构骨架

```
Client → CDN(静态) → LB → API网关
   → 无状态服务(多实例) → 缓存(Redis)
   → 数据库(主从/分片) → MQ(异步解耦)
```

- 无状态服务便于水平扩展。
- 缓存抗读。
- 数据库主从/分片抗写。
- MQ 削峰异步。

## 5. 设计短链系统

- 功能：长链 → 短码，访问短链 302 跳转。
- 短码生成：自增 ID + Base62；或哈希+冲突重试；或分布式发号。
- 存储：短码 → 长链映射（KV/关系库）。
- 缓存：热门短码进 Redis。
- 跳转：301（缓存）vs 302（统计）；按统计需求选。
- 防滥用：限流、黑名单。

## 6. 设计限流器

- 算法：计数器、滑动窗口、漏桶、令牌桶（见限流章节）。
- 分布式：用 Redis + Lua 原子扣令牌。
- 维度：用户/IP/接口。
- 响应：拒绝 / 排队 / 降级。

## 7. 设计排行榜

- 实时 TopN：Redis ZSet（score 排序）。
- 海量：分片 ZSet + 合并；或离线计算+缓存。
- 防刷：同用户多设备去重。

## 8. 设计秒杀

- 静态化：商品页 CDN。
- 拦截：答题/验证码过滤机器人。
- 库存：Redis 预扣 + 异步落库；库存售罄快速失败。
- 削峰：MQ 异步下单。
- 防超卖：Redis 原子扣减 / 数据库乐观锁 / 分布式锁。
- 限流降级：超出容量直接兜底。

## 9. 设计消息队列

- 组件：Producer、Broker（Topic/Partition）、Consumer Group。
- 持久化：顺序写日志 + 索引。
- 消费模型：拉 vs 推；消费位点管理。
- 高可用：副本 + 选主。
- 顺序：单 partition 内有序。
- 重复：至少一次 → 消费幂等。

## 10. 设计缓存层

- 模式：Cache-Aside（读穿透写失效）、Read-Through、Write-Through、Write-Behind。
- 穿透：空值缓存 / 布隆过滤器。
- 击穿：热点 key 互斥重建 / 逻辑过期。
- 雪崩：过期时间加随机抖动 / 多级缓存。
- 一致性：先更库再删缓存，配合延时双删/订阅 binlog。

## 11. 一致性设计选择

- 强一致：2PC/分布式事务（谨慎，慢）。
- 最终一致：消息表/事务消息 + 幂等（主流）。
- 选主：Raft/ZAB（etcd/ZK）。
- 读写：主写从读，容忍复制延迟。

## 12. 可用性设计

- 冗余：多副本、多可用区。
- 降级：非核心功能可关。
- 熔断：下游异常快速失败。
- 限流：保护自身。
- 超时重试：带退避与幂等。
- 故障演练：主动注入验证。

## 13. 扩展性设计

- 无状态服务水平扩展。
- 数据分片：按 user_id 哈希 / 范围。
- 读写分离。
- 异步化：MQ 解耦。
- 热点处理：本地缓存、分桶、限流。

## 14. 数据建模要点

- 选存储：OLTP（MySQL）、缓存（Redis）、分析（ClickHouse）、搜索（ES）。
- 分库分表：评估是否真需要（先单机/读写分离）。
- 索引：高频查询建索引，避免全表。
- 幂等键：所有写操作带业务唯一键。

## 15. 常见追问与陷阱

- "你的设计单点在哪里？" → 指出并加冗余。
- "数据一致性怎么保证？" → 选模型 + 幂等 + 对账。
- "热点 key 怎么办？" → 拆分/本地缓存/限流。
- "故障怎么办？" → 降级熔断限流 + 多副本。
- "容量不够？" → 水平扩展 + 分片 + 缓存。

## 16. 高频题目清单

- 短链、限流、排行榜、秒杀、MQ、缓存、Feed 流、IM、支付、URL 采集、打车派单、票务选座。
- 这类题万变不离：需求澄清 → 容量 → 骨架 → 深挖一致性/可用/扩展。

## 17. 答题禁忌

1. 一上来就写细节，不做需求澄清。
2. 容量估算跳过，显得没规模意识。
3. 忽视单点与故障，设计"纸面完美实际脆弱"。
4. 一致性承诺过强（说强一致却无方案）。
5. 不分读写、不分冷热，全压主库。

## 18. 小结

分布式设计面试题考的是**结构化思维**而非某个标准答案。固定套路：澄清需求 → 估算容量 → 画骨架 → 深挖一致性/可用性/扩展性，并在每步指出单点与降级。储备好短链、限流、缓存、MQ、秒杀等通用组件的设计要点，遇到新题也能套用。记住：先跑通主链路，再谈优化与异常。
