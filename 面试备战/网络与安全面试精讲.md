# 网络与安全面试精讲

> 网络与安全的扎实基础是后端/全栈面试的硬通货。本文整理 TCP、HTTP、HTTPS、常见攻击与防护高频题。

## 1. TCP

**Q：三次握手？**
1. 客户端 SYN（seq=x）。
2. 服务端 SYN+ACK（seq=y, ack=x+1）。
3. 客户端 ACK（ack=y+1）。
目的：双方确认收发能力，同步初始序号。

**Q：为什么不是两次？**
防止已失效连接请求突然到达服务端，导致服务端误建连接浪费资源。

**Q：四次挥手？**
1. 主动方 FIN。2. 被动方 ACK。3. 被动方 FIN。4. 主动方 ACK。
被动方需先处理完数据再 FIN，故 ACK 与 FIN 分开（多一次）。

**Q：TIME_WAIT 意义？**
确保最后一个 ACK 到达；让旧报文在网络中消亡，避免影响新连接。

**Q：流量控制与拥塞控制？**
- 流量控制：滑动窗口，按接收方能力发。
- 拥塞控制：慢启动、拥塞避免、快重传、快恢复，防止压垮网络。

## 2. HTTP

**Q：HTTP 1.0/1.1/2/3 区别？**
- 1.0：单请求单连接。
- 1.1：持久连接、管线化、Host 头。
- 2：多路复用、头部压缩、服务端推送。
- 3（QUIC）：基于 UDP，0-RTT，抗丢包。

**Q：GET 与 POST 区别？**
语义（获取 vs 提交）、幂等、参数位置（URL vs body）、缓存。本质都是 TCP 请求。

**Q：常见状态码？**
2xx 成功、3xx 重定向、4xx 客户端错（401/403/404）、5xx 服务端错（502/503）。

## 3. HTTPS

**Q：HTTPS 握手流程？**
1. 客户端 Hello + 支持的加密套件。
2. 服务端证书（含公钥）+ 选定套件。
3. 客户端验证证书（CA 链）。
4. 生成对称密钥，用公钥加密传给服务端。
5. 之后用对称密钥通信。

**Q：为什么混合加密？**
非对称加密慢，用于安全交换对称密钥；对称加密快，用于传输数据。

**Q：对称 vs 非对称？**
- 对称：同密钥，快，密钥分发难。
- 非对称：公私钥对，慢，解决分发。

## 4. 安全攻击与防护

**Q：SQL 注入？**
拼接 SQL 导致恶意注入。防护：预编译（PreparedStatement）、参数化、输入校验、最小权限。

**Q：XSS？**
注入恶意脚本到页面。防护：输出转义、CSP、HttpOnly Cookie。

**Q：CSRF？**
借用户身份发请求。防护：CSRF Token、SameSite Cookie、校验 Referer。

**Q：DDOS？**
海量请求打垮服务。防护：限流、CDN、清洗、冗余。

**Q：中间人攻击？**
拦截通信。防护：HTTPS、证书校验、HSTS。

## 5. 实战题

**Q：浏览器访问 https 站点全过程？**
DNS → TCP → TLS 握手 → HTTP 请求 → 渲染。

**Q：502 与 504 区别？**
- 502：网关收到无效响应（上游挂/协议错）。
- 504：网关等待上游超时。

**Q：如何防止接口被刷？**
限流（令牌桶）、验证码、风控、IP 黑名单、行为分析。

## 7. 小结

网络面试重在"握手/挥手为什么这样设计"与"各版本演进动机"；安全重在"攻击原理 + 防护手段 + 纵深防御"。理解机制而非死记结论。
