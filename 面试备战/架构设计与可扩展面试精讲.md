# 架构设计与可扩展性面试精讲

> 架构师面试侧重"权衡、演进、质量属性"。本文整理架构设计高频题与答题框架。

## 1. 质量属性

**Q：架构设计要关注哪些质量属性？**
性能、可扩展性、可用性、可维护性、安全性、可观测性、成本。没有银弹，需权衡（如一致性 vs 可用性）。

**Q：如何评估可扩展性？**
- 水平扩展能力（无状态、数据分片）。
- 模块解耦（边界清晰、依赖单向）。
- 弹性（自动伸缩）。

## 2. 演进路径

**Q：单体到微服务的演进？**
单体 → 模块拆分（分层/模块化）→ 提取公共服务 → 微服务（按业务域）。不是一上来就微服务，需组织与运维能力匹配。

**Q：何时该拆分？**
团队规模变大、部署耦合、某模块独立扩展需求强。过早拆分增加复杂度。

## 3. 高并发设计

**Q：如何设计一个高并发系统？**
分层优化：客户端（CDN/缓存）→ 接入（负载均衡/限流）→ 应用（无状态/异步/池化）→ 数据（分库分表/读写分离/缓存）→ 异步削峰（MQ）。

**Q：限流算法？**
计数器、滑动窗口、令牌桶、漏桶。令牌桶允许突发，漏桶平滑。

**Q：缓存策略？**
Cache Aside + 多级缓存 + 防穿透/击穿/雪崩（见缓存架构专题）。

## 4. 一致性

**Q：CAP 定理？**
分区容错下，一致性与可用性不可兼得。实际多取 AP + 最终一致，或 CP。

**Q：最终一致如何实现？**
异步复制 + 对账 + 重试 + 幂等。读时修复（read-repair）。

## 5. 设计题框架

**Q：如何回答"设计一个短链/秒杀/Feed"？**
1. 澄清需求（量级、读写比、约束）。
2. 估算（QPS、数据量）。
3. 画架构图（分层）。
4. 点出瓶颈与优化（缓存、分片、异步）。
5. 讨论权衡（一致性、成本）。
6. 容错与监控。

## 6. 常见陷阱

**Q：过度设计 vs 欠设计？**
- 过度：为未知需求堆抽象，复杂难维护。
- 欠设计：无边界、强耦合，难以演进。
- 适度：满足当前 + 留好演进点。

**Q：技术选型依据？**
业务匹配、团队熟悉度、生态成熟度、运维成本、可扩展性。避免"追新"。

## 7. 实战题

**Q：设计一个支持千万用户的 Feed 流？**
- 写扩散（推模式）vs 读扩散（拉模式）取舍。
- 时间线分片、缓存热数据、异步聚合。
- 降级：热门用户走推，长尾走拉。

**Q：如何保证系统可用性 99.99%？**
冗余（多副本）、无单点、优雅降级、限流熔断、混沌演练、监控告警。

## 8. 面试题清单

1. 质量属性的权衡？
2. 单体到微服务演进时机？
3. 高并发系统分层优化？
4. CAP 与最终一致？
5. 设计题的标准答题框架？
6. 如何避免过度设计？

## 9. 小结

架构面试考的是"权衡思维与演进视角"，而非背具体技术。掌握质量属性、演进路径、设计题框架，能应对绝大多数场景题。
