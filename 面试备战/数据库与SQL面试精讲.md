# 数据库与 SQL 面试精讲

数据库是后端面试的必考核心。本文按"概念 → 原理 → 面试追问"组织，帮助在面试中既有深度又能答到考点上。结合 [源码系列/缓存与存储源码要点](../源码系列/缓存与存储源码要点.md) 食用更佳。

## 一、索引（面试必问）

- **作用**：把全表扫描变有序查找，B+ 树索引 O(log n)。
- **B+ 树特点**：多路平衡、叶子串成链表便于范围查询；非叶子只存键，叶子存数据/指针；树矮（千万数据 3–4 层），IO 少。
- **聚簇索引（InnoDB）**：数据和主键索引放一起，主键即数据位置；二级索引叶子存主键，回表查数据。
- **最左前缀**：联合索引 (a,b,c) 能用到 a、a,b、a,b,c，跳 a 或用 b 后的范围则中断。
- **覆盖索引**：查询字段都在索引里，不用回表，快。
- **索引失效**：对列函数/计算、隐式类型转换、前导模糊 `LIKE '%x'`、用 `!=`/OR 不当、优化器选错。

> 追问："为什么用 B+ 树不用哈希/B 树？" → 范围查询友好、矮树少 IO、叶子链表支持全范围扫描；哈希只支持等值、B 树非叶子也存数据导致树更高。

## 二、事务与 ACID

- **原子性（A）**：undo log 保证回滚。
- **一致性（C）**：业务约束由应用+DB 共同保证（AID 是手段，C 是目标）。
- **隔离性（I）**：锁 + MVCC。
- **持久性（D）**：redo log 保证宕机不丢。
- **隔离级别**：读未提交 → 读已提交 → 可重复读（MySQL 默认）→ 串行化。级别越高越安全越慢。
- 读未提交有脏读；读已提交解决脏读，有不可重复读；可重复读解决不可重复读；串行化解决幻读但性能最差。

## 三、MVCC 与幻读

- **MVCC**：每行有隐藏事务 ID 与回滚指针，读不加锁，读历史快照；读写不阻塞。
- **快照读**：普通 SELECT 读快照；**当前读**：`SELECT ... FOR UPDATE`/`UPDATE` 读最新并加锁。
- **幻读**：同一事务两次范围查询返回行数不同。MySQL 在 RR 下用 **间隙锁（Next-Key Lock）** 防幻读。
- 注意：RR 下快照读无幻读，但当前读仍可能（需锁保护），Next-Key Lock 同时锁记录与间隙。

## 四、锁

- **行锁/表锁**：InnoDB 默认行锁（基于索引），**无索引则升级表锁**。
- **共享锁（S）/ 排他锁（X）**：读共享，写排他。
- **意向锁**：表级，标识「即将在行上加锁」，避免逐行检查。
- **Next-Key Lock**：记录锁 + 间隙锁，防幻读，也易引发死锁/锁等待。

> 死锁排查：`SHOW ENGINE INNODB STATUS` 看最近死锁；业务上按固定顺序加锁、缩短事务、降低锁粒度可避免。

## 五、慢 SQL 与优化

- `EXPLAIN` 看执行计划：type（访问类型，越靠前越好 const/ref/range）、key（用到的索引）、rows（扫描行数）、Extra（Using filesort/index）。
- 常见慢因：缺索引、索引失效、回表多、大表 JOIN、深分页（`LIMIT 100000,10`）、`SELECT *`、锁等待。
- 优化：加/调索引、改写 SQL、分页用游标（`WHERE id > ? LIMIT`）、冗余/汇总表、归档冷数据。

## 六、分库分表

- **垂直分**：按业务拆库（用户库/订单库），或单表拆字段（大字段独立）。
- **水平分**：按分片键（用户 ID/订单 ID 哈希或按时间）把大表拆到多库多表。
- **中间件**：ShardingSphere、Vitess。
- 见 [分库分表/README](../分库分表/README.md) 与 [场景设计/分布式ID生成](../场景设计/分布式ID生成.md)。
- 坑：跨分片 JOIN/事务难、分片键选错无法路由、扩容需重新分片（翻倍扩容或一致性哈希）。

## 七、缓存与数据库一致

- 见 [场景设计/缓存经典三问与一致性](../场景设计/缓存经典三问与一致性.md)。
- 读穿透/写策略：先更 DB 再删缓存（Cache-Aside），配合延迟双删/订阅 binlog 兜底。

## 八、主从与复制

- **binlog**：主库写 binlog，从库拉取重放（异步为主，有延迟）。
- **延迟问题**：从库读可能读到旧数据；强一致读走主。
- **CDC**：Canal/Debezium 订阅 binlog 做异构同步/缓存更新，见 [源码系列/缓存与存储源码要点](../源码系列/缓存与存储源码要点.md)。

## 九、高频面试题（12 连问）

1. 为什么用 B+ 树不用哈希/B 树？→ 范围友好、矮树少 IO、叶子链表。
2. 聚簇 vs 非聚簇？→ 数据是否和主键放一起（InnoDB 聚簇）。
3. 最左前缀是什么？→ 联合索引按序匹配，跳列失效。
4. 什么是回表？→ 二级索引查到主键再查数据，覆盖索引可免。
5. MVCC 怎么实现？→ 隐藏事务 ID + undo 版本链 + ReadView。
6. RR 怎么防幻读？→ Next-Key Lock（记录+间隙）。
7. 死锁怎么排查？→ `SHOW ENGINE INNODB STATUS`、固定加锁顺序。
8. 大表怎么优化？→ 索引、SQL 改写、归档冷数据、分库分表。
9. 深分页慢怎么办？→ 游标分页 / 延迟关联。
10. 缓存和 DB 怎么一致？→ Cache-Aside + 删缓存 + binlog 兜底。
11. 主从延迟怎么处理？→ 监控、关键读走主、并行复制。
12. 为什么不要 `SELECT *`？→ 回表/网络/覆盖索引失效。

## 十、常见误区

- 建一堆索引 → 拖慢写入、占空间，按查询建。
- 以为 RR 完全无幻读 → 当前读/特殊场景仍需注意。
- 用字符串主键或 UUID → 索引碎片、插入随机化，宜自增或有序 ID。
- 大事务 → 锁久、主从延迟、连接占用，拆小。
- 不分场景上分库分表 → 过度设计。
