# 证券 / 基金 / 交易业务模型（深扒）

> 金融交易系统的核心铁律是「**正确性 > 性能 > 体验**」：一笔错单、一次重复扣款、一毫秒的行情延迟，都是真金白银的事故。它把一致性、幂等、审计推到极致。
>

## 二、核心系统架构

### 2.1 撮合引擎（交易心脏）
- **价格优先 + 时间优先**：买卖盘口按价格档排序，同价按时间序。
- **内存订单簿**：全内存撮合，微秒级；成交后异步落库。
- **无锁/环形队列**：高吞吐下避免锁竞争（见「[并发编程](../基础知识/并发编程.md)」）。

### 2.2 行情（低延迟）
- 行情分发走**二进制协议 + 组播/推**，端到端延迟追求毫秒级。
- 快照 + 增量，客户端本地重建订单簿。

### 2.3 资金与持仓（强一致）
- 委托冻结资金/持仓，成交后**原子划转**，任何一步失败整体回滚。
- **T+1 / 交收**：交易与资金交收分离，日终清算对账。

### 2.4 风控与合规
- 事前：限额、持仓上限、黑名单；事中：异常交易监测；事后：反洗钱、对账审计。

## 六、深挖：核心业务机制

### 6.1 撮合引擎内部（价格优先 + 时间优先）

```
订单簿: 买单按价格从高到低（买一最高），卖单按价格从低到高（卖一最低）
撮合: 新订单到达 → 与对侧最优档比对 → 价格可成交则撮合 → 未成交进本方队列
同价: 先到先成交（时间优先）→ 撮合引擎必须全局有序（单线程/队列串行）
```

| 关键点 | 做法 |
|--------|------|
| 全局有序 | 撮合请求进**单线程/无锁环形队列**，杜绝并发错序 |
| 内存化 | 订单簿全内存，成交后异步落库 |
| 微秒级 | 对象池、避免 GC 停顿（低延迟 JVM/本地内存） |
| 可重放 | 撮合日志（append-only）用于故障恢复与审计 |

### 6.2 行情低延迟链路

```
交易所 → 行情网关(解析) → 组播/推流(二进制增量) → 客户端重建订单簿
快照(snapshot) + 增量(delta) 交替，增量丢失用快照兜底
```

- 带宽与延迟权衡：增量传输减带宽；客户端本地维护订单簿；
- **行情时间必须用交易所/行情服务器授时**（本地时钟不可信）；
- 降级：行情中断 → 停止开新单 + 提示（保护投资者）。

### 6.3 资金/持仓强一致（T+1 与交收）

```
委托 → 冻结资金/持仓(原子) → 撮合成交 → 成交后划转(原子) → 日终清算/交收
```

- 冻结与划转必须在**同一事务/补偿协议**内完成（TCC）；
- 日终清算：成交明细 vs 资金流水自动对账，差异挂账告警；
- 隔日交收（T+1）：当天成交次日资金到位，清算与交收分离。

## 八、面试与系统设计视角

1. 设计一个撮合引擎：内存订单簿 + 单线程有序 + 价格时间优先。
2. 行情低延迟怎么做：二进制协议 + 快照增量 + 组播/推流。
3. 资金划转强一致：冻结 + TCC + 日终对账。
4. 委托幂等：委托号唯一 + 状态机防重复成交。
5. 断网恢复：撮合日志重放 + 状态重建 + 对账。

## 九、交易特有坑

- **重复委托/重复成交**：网络重发 → 委托号幂等 + 唯一约束。
- **资金非原子**：冻结与扣减不原子 → 必用事务/补偿，禁部分成功。
- **行情延迟致误判**：用本地时间比行情 → 须用交易所授时/序号。
- **清算对账缺失**：日终不核对 → 长尾资损，必须自动对账 + 差异告警。
- **风控滞后**：只事后查 → 事前事中拦截前置。

> 口诀：**"交易三优先：正确>性能>体验；撮合内存快，资金原子转，风控前置拦，日终必对账。"**
