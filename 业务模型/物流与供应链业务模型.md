# 物流与供应链业务模型

> 本文从业务建模角度梳理物流与供应链系统的核心域：仓储（WMS）、运输（TMS）、订单履约、库存、调度与轨迹，以及关键的状态机与一致性挑战。内容基于公开行业实践，具体规则以业务为准。

## 1. 供应链的范围

- 从采购、仓储、库存、拣货、打包、运输到签收的全链路。
- 核心目标：在成本约束下，把对的东西、在对的时间、送到对的地点。

## 2. 核心实体

- 商品（SKU）：最小销售单位。
- 库存：可用、锁定、在途、残损。
- 仓库（Warehouse）：物理存储节点。
- 订单（Order）：销售/采购/调拨。
- 运单（Waybill）：运输单元。
- 包裹（Package）：实际发货单元。

## 3. 仓储管理（WMS）

### 3.1 入库

- 预约到货 → 质检 → 上架（库位分配）。
- 库位策略：就近、品类聚合、冷热分区。
- 入库单与采购单/调拨单对账。

### 3.2 库存

- 可用库存 = 总库存 - 锁定 - 在途 - 残损。
- 锁定：订单创建即锁库存，防超卖。
- 多仓库存：总库存 = 各仓之和，需路由到最近有货仓。

### 3.3 拣货

- 摘果式：按单拣，适合小单。
- 播种式：批量拣后再分，适合多单。
- 路径优化：减少拣货员行走距离。

### 3.4 打包与出库

- 复核：扫商品确认与订单一致。
- 称重、打单、交接承运商。
- 出库减库存、生成运单。

## 4. 运输管理（TMS）

- 运力：自有车/第三方/快递。
- 路由：从发货仓到目的地的路径规划。
- 调度：车辆装载、线路排程。
- 时效：预估到达、承诺时效。

## 5. 订单履约流程

```
用户下单 → 库存锁定 → 仓内作业(拣/包) → 交运 → 干线运输
   → 末端配送 → 签收 → 对账结算
```

- 每个环节是状态机的一个状态。
- 异常分支：缺货、破损、拒收、退货。

## 6. 库存一致性

- 超卖问题：并发下单超库存。
- 防超卖：下单锁库存（数据库乐观锁/Redis 原子扣减）。
- 多仓库存路由：选有货且最近仓，避免跨区。
- 库存与订单最终一致：用消息确认扣减成功。

## 7. 状态机设计

- 订单状态：待支付→已支付→待发货→已发货→已签收→完成。
- 运单状态：已揽收→运输中→派送中→已签收/异常。
- 每个状态转换有守卫（合法前置态、权限、幂等）。
- 状态变更需留痕（审计）。

## 8. 轨迹与时效

- 轨迹：节点扫描（揽收/中转/派送）时间线。
- 时效预估：基于历史线路时效 + 实时拥堵。
- 超时预警：预计超时触发干预。

## 9. 调度与优化

- 车辆装载率：拼车提高满载。
- 路径优化：TSP 思路减少里程（规模小可用启发式）。
- 末端配送：站点—配送员—客户的分派。
- 动态调度：实时订单插入最优路线。

## 10. 逆向物流（退货）

- 退货申请 → 审核 → 寄回 → 入库质检 → 退款/换货。
- 库存回流：良品回可用，残品隔离。
- 退款需与支付对账（见支付章节）。

## 11. 对账与结算

- 与承运商按运单、重量、时效结算。
- 与商家按销售、退货对账。
- 差异处理：丢件赔付、重量争议。

## 12. 预警与异常

- 库存预警：低库存补货。
- 时效预警：超时订单介入。
- 异常件：破损、丢件、拒收处理流。
- 滞销：库存周转慢，促销清仓。

## 13. 与电商的关系

- 电商下单后触发履约（本文链路）。
- 库存是电商与物流的交界。
- 物流时效直接影响用户体验与复购。

## 14. 技术要点

- 高并发锁库存：Redis/DB 原子。
- 状态机：明确转换与幂等。
- 轨迹：时序数据，可用时序库/宽表。
- 调度：规则引擎 + 优化算法。
- 可观测：每个节点状态可查。

## 15. 常见踩坑

1. **锁库存不及时**：下单未锁，超卖。
2. **状态机无守卫**：乱跳状态，数据错乱。
3. **多仓路由错**：跨区发货，运费高时效差。
4. **库存与订单不一致**：扣减失败未回滚，账实不符。
5. **轨迹丢失节点**：无法定责与时效分析。
6. **对账滞后**：与承运商账期长，差异难追。
7. **退货不回库存**：良品未回流，损失。

## 16. 建模清单

- 明确核心实体与状态机。
- 库存模型（可用/锁定/在途）。
- 锁库存防超卖。
- 履约流程节点与异常分支。
- 轨迹时序采集。
- 对账结算机制。
- 预警与调度优化。

## 17. 演进方向

- 智能补货：基于预测的补货。
- 路径优化：实时动态调度。
- 自动化仓：AGV/分拣线。
- 全链路可视化：用户可查每一节点。

## 18. 小结

物流与供应链建模的核心是"实体 + 状态机 + 库存一致性"。锁库存防超卖、状态机守卫防乱跳、多仓路由降成本、轨迹留痕可追责、对账结算兜底。复杂度在履约链路长、异常多、跨系统一致。铁律：**下单必锁库存、状态转换必有守卫与幂等、账实必须定期对、异常分支必须建模**，并用预警与调度优化时效与成本。
