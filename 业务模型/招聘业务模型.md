# 招聘业务模型

> 板块：业务模型 　|　 返回：[README](README.md)
> 关联：[内容社区与UGC业务模型](内容社区与UGC业务模型.md)、[电商交易业务模型](电商交易业务模型.md)、[支付清结算与账务模型](支付清结算与账务模型.md)

招聘（Job/Recruitment）是典型的"双边市场"业务模型：连接**求职者（C 端）**与**企业/HR（B 端）**，核心价值是"高效、精准地匹配人与岗位"。与电商（买卖商品）、社区（内容消费）不同，招聘的匹配更重"信任、精准、长周期决策"。本文梳理核心域、双边模型、匹配推荐、面试流程、B 端付费与风控。

## 一、核心域

| 域 | 职责 | 关键实体 |
|----|------|---------|
| 用户域 | 求职者、HR/招聘者账号 | 候选人、HR、企业 |
| 职位域 | 职位发布、JD 管理 | 职位、JD、职位状态 |
| 简历域 | 简历创建/解析/存储 | 简历、工作经历、技能标签 |
| 匹配域 | 人岗匹配、推荐 | 匹配分、推荐列表 |
| 沟通域 | 打招呼、聊天、面试邀约 | 会话、消息、邀约 |
| 流程域 | 投递→筛选→面试→offer→入职 | 投递记录、面试安排、offer |
| 交易域 | B 端付费（会员/置顶/猎头） | 订单、套餐、分账 |
| 风控域 | 虚假职位、简历造假、黑产 | 风控事件、信用分 |

## 二、双边市场模型

```
求职者(C端) ──投递/沟通──▶ 职位(B端)
   ▲                          │
   │       匹配推荐(双向)      │
   └──────────────────────────┘
企业(B端) 付费获取曝光/联系方式
```

| 侧 | 核心诉求 | 平台价值 |
|----|---------|---------|
| 求职者 | 找到合适、真实、高薪的岗位 | 精准匹配、真实信息、流程顺畅 |
| 企业 | 快速招到合适的人、低成本 | 海量候选人、筛选工具、品牌曝光 |
| 平台 | 撮合成功、双边活跃 | 匹配效率、信任、商业化 |

> 双边市场的关键：**供给（职位）与需求（候选人）双边冷启动**——职位少则求职者不来，求职者少则企业不来。先一边突破（如先聚职位或先聚简历）。

## 三、核心实体与关系

```
候选人 1─* 简历 1─* 投递 *─1 职位 1─1 企业
职位 *─* 技能标签（匹配用）
投递 1─* 面试记录 1─1 offer
```

- **简历（Resume）**：结构化简历（基本信息、教育、工作、项目、技能）。需解析（PDF/Word → 结构化）提取字段。
- **职位（Job）**：JD（职责、要求、薪资、地点、标签）。
- **匹配分**：候选人简历 vs 职位要求的相似度（技能/经验/地点/薪资期望）。

## 四、匹配与推荐

### 4.1 双向推荐

- **给求职者推职位**：基于简历标签（技能/行业/地点/薪资期望）匹配职位标签。
- **给企业推候选人**：基于职位要求匹配候选人（逆向推荐）。
- 都是**召回 → 排序** 两阶段（见 [推荐系统设计](../场景设计/推荐系统设计.md)）。

### 4.2 匹配特征

| 维度 | 特征 |
|------|------|
| 硬性 | 地点、薪资期望、学历、经验年限、技能 |
| 软性 | 行业匹配、公司规模偏好、跳槽频率 |
| 行为 | 浏览/收藏/投递/沟通（隐式反馈） |
| 文本 | JD 与简历语义相似度（NLP/向量） |

### 4.3 向量化匹配

- 简历与 JD 用文本向量（Embedding）表示，向量检索（如 [向量数据库](../技术选型/存储引擎与数据库内核选型实战.md)）找最相似。
- 结合规则（硬性条件过滤） + 模型（软性排序）。

## 五、招聘流程（长周期状态机）

```
投递 → 企业查看 → 筛选(初筛) → 面试邀约 → 面试(多轮) → offer → 入职/拒
         │                                                  │
         └────────── 拒绝/不合适 ──────────────────────────┘
```

- 每步都有状态与时效（如"企业 48h 未处理自动提醒"）。
- **面试安排**：时间协调、视频/现场、面试官分配。
- **offer 管理**：薪资、职级、入职日期，电子签。
- **数据回流**：入职/拒因用于优化匹配（负反馈）。

## 六、B 端商业化

| 模式 | 说明 |
|------|------|
| 职位套餐 | 企业包月发布 N 个职位 |
| 简历下载/查看 | 按份/包计费获取候选人联系方式 |
| 置顶/曝光 | 职位加权推荐 |
| 猎头/RPO | 高客单价撮合服务 |
| 会员 | 招聘者会员权益 |

- 交易与分账见 [支付清结算与账务模型](支付清结算与账务模型.md)。
- 关键：B 端付费的 ROI 取决于"招到人"的转化率，需效果可追踪。

## 七、风控与信任（招聘重灾区）

| 风险 | 手段 |
|------|------|
| 虚假职位 | 企业认证、职位审核、黑名单 |
| 简历造假 | 学历/工作经历核验、背调 |
| 黑产/诈骗 | 刷量、引流到外部、杀猪盘识别 |
| 简历倒卖 | 数据加密、访问审计、最小授权 |
| 隐私合规 | 简历属敏感个人信息，采集/使用需授权（GDPR/个人信息保护法） |

> 招聘平台信任崩塌极快（一个诈骗职位上热搜），风控与审核是第一优先级。

## 八、数据指标

| 维度 | 指标 |
|------|------|
| 双边 | 活跃求职者、活跃企业、职位数、简历数 |
| 匹配 | 投递率、面试邀约率、沟通率 |
| 转化 | 面试率、offer 率、入职率（最终漏斗） |
| 商业 | B 端付费率、ARPU、续费率 |
| 质量 | 虚假职位率、投诉率、举报率 |

## 九、与电商/社区对比

| 模型 | 核心资产 | 决策周期 | 信任要求 |
|------|---------|---------|---------|
| 电商 | 商品/交易 | 短 | 中 |
| 社区 | 内容/关系 | 中 | 中 |
| 招聘 | 人岗匹配 | 长（数周） | 极高（诈骗敏感） |

## 十、常见建模坑

1. **只做单向推荐** → 企业找不到人、人看不到岗，双边失衡（需双向）。
2. **不匹配硬性条件** → 推的岗位薪资/地点不符，体验差（规则过滤前置）。
3. **流程状态机不清** → 投递/面试/offer 状态混乱（明确状态机）。
4. **风控后置** → 诈骗职位扩散（发布即审 + 企业认证）。
5. **隐私不合规** → 简历数据违规，法律风险（授权 + 加密 + 审计）。
6. **B 端效果不可追踪** → 付费企业流失（效果归因）。
7. **简历解析失败** → 结构化差，匹配不准（多级解析 + 人工兜底）。
