# 法律专业服务业务模型

> 法律服务是"高专业度 + 强信任 + 结果不确定"的知识密集型业务：咨询、合同、诉讼、合规。其核心是**供给（律师）匹配**与**服务过程管理**，平台需解决信息不对称与信任问题。

## 1. 业务结构

```mermaid
flowchart LR
    U[用户] --> M[需求匹配]
    M --> L[律师]
    L --> C[咨询/委托]
    C --> S[交付:文书/代理]
    S --> F[反馈/评价]
```

## 2. 核心模块

| 模块 | 关键 |
| --- | --- |
| 需求分类 | 婚姻/劳动/公司法务等 |
| 律师匹配 | 领域、地域、评级 |
| 咨询 | 文字/语音/视频 |
| 委托 | 合同、费用、进度 |
| 知识库 | 模板、案例、法规 |

## 3. 匹配与信任

- 按专业领域 + 地域 + 成功率匹配律师。
- 律师实名 + 执业证 + 评价背书。
- 明码标价（咨询/文书/代理）。
- 资金托管，按节点结算。

## 4. 交付管理

- 案件进度可视，节点提醒。
- 文书模板化提效，专业复核。
- 隐私与保密合规（律师保密义务）。

## 5. 常见坑

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 匹配错 | 不专业 | 领域精准 |
| 信任低 | 不敢委托 | 资质 + 评价 |
| 价格黑 | 投诉 | 明码标价 |
| 进度盲 | 焦虑 | 进度可视 |
| 隐私 | 泄露 | 保密机制 |

## 6. 面试题

1. 法律服务如何做供需匹配？
2. 如何建立用户信任？
3. 案件交付如何管理？
4. 隐私合规怎么做？

## 7. 小结

法律服务 = 精准匹配 + 信任背书 + 过程可视 + 合规保密。核心是"把高门槛的专业服务变得可信、可预期、可追溯"。
