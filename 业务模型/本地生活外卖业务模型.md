# 本地生活 / 外卖业务模型（深扒）

> 外卖 = 「**线上交易 + 实时调度 + 履约时效**」三者的强耦合：既要像电商一样下单支付，又要像出行一样实时派单，还要卡死「30 分钟送达」的时效。
>
> 配套总览见「[业务模型总览](业务模型总览.md)」；调度/峰值见「[出行打车](出行打车业务模型.md)」「[架构](../架构)」。

---

## 一、业务全景与领域划分

外卖本质是「**用户 — 商家 — 骑手**」三角实时协同。按限界上下文拆为七大域：

```mermaid
flowchart TD
    U[用户域] --> O[订单域]
    M[商家域] --> O
    O --> Dispatch[调度域]
    R[骑手域] --> Dispatch
    O --> Pay[支付域]
    O --> M
    Dispatch --> R
    O --> A[履约/时效域]
```

| 域 | 核心职责 | 关键实体 |
|----|----------|----------|
| 用户域 | 地址、偏好、会员 | 用户、地址 |
| 商家域 | 商品、库存、出餐时长 | 门店、菜品、营业状态 |
| 订单域 | 购物车、下单、状态机 | 订单、订单项 |
| 调度域 | 派单、路径、合单 | 调度任务、骑手候选 |
| 骑手域 | 位置、状态、容量 | 骑手、载具、容量 |
| 支付域 | 收银、对账 | 支付单 |
| 履约域 | 出餐、取餐、送达、时效 | 履约单、时效指标 |

## 二、核心系统架构

### 2.1 商家与出餐
- **出餐时长预估**：商家历史出餐速度 + 当前排队单量，决定「何时派骑手去取」。
- **高峰限流**：爆单时商家接单能力有限，需**排队/延迟发单**防雪崩。

### 2.2 智能调度（派单 + 路径 + 合单）
- **派单**：综合骑手位置、载量、方向、商家出餐进度，选最优骑手。
- **合单（顺路单）**：把同一方向、时间窗相近的 2~3 单合并给一个骑手，提人效。
- **路径规划**：多取多送的**带时间窗的车辆路径问题（VRPTW）**，近似算法求解。

### 2.3 履约时效
- 全链路时效拆解：**下单 → 接单 → 出餐 → 取餐 → 配送 → 送达**，每段有 SLA。
- 超时预警：某段超阈值自动触发改派/补偿，保障体验。

## 六、深挖：核心业务机制

### 6.1 出餐时间预估（调度前置条件）

```
出餐时长 = f(商家历史出餐分位数, 当前排队单量, 菜品结构, 时段)
```

- 关键洞察：**出餐进度不可见是超时的头号原因** → 商家 App 上报「接单/制作中/出餐完成」事件；
- 预估过乐观 → 骑手空等；过保守 → 用户等久。用**分位数（如 P75）+ 动态修正**，并根据履约表现对商家分级；
- 联动：出餐慢的商家 → 延长派单缓冲/降权展示。

### 6.2 合单调度（VRPTW 的工程化）

```
问题：多个取餐点 + 多个送餐点 + 时间窗（出餐完成/超时死线）→ 最小化总成本
```

| 要素 | 含义 |
|------|------|
| 取货点 | 商家位置 + 出餐完成时间（最早可取） |
| 送货点 | 用户位置 + 期望送达窗 |
| 路径约束 | 骑手容量（≤3单）、方向一致性 |
| 目标 | 单均成本最低 / 总超时最少 / 骑手收入均衡 |

- 精确解不可行（NP 难）→ 用**插入启发式 + 局部搜索**（模拟退火/LNS）+ 实时改派兜底；
- 时间窗冲突就**拆单**：宁可少合，不拖垮一单。

### 6.3 时效 SLA 拆解与补偿

```
下单 → 商家接单 → 出餐完成 → 骑手取餐 → 送达
 30s     2~8min        5~15min    3~20min   合计 ≤30min
每段有阈值，超阈值自动触发: 改派 / 补贴 / 补偿券
```

- 超时责任归属（商家慢 / 骑手慢 / 平台派单晚）→ 计费与考核依据；
- 补偿自动化：超时自动发券，减少客服压力（见 [通知中心与站内信](../场景设计/通知中心与站内信设计.md)）。

## 八、面试与系统设计视角

1. 设计一个外卖调度系统：接单 → 出餐预估 → 派单（合单）→ 路径 → 超时兜底。
2. 骑手位置百万级怎么收：长连接 + 批量上报 + 轨迹抽稀（同出行）。
3. 合单 vs 时效怎么权衡：时间窗约束 + 拆单 + 改派兜底。
4. 午高峰商家爆单怎么保护：排队发单 + 延迟接单 + 出餐预估动态拉长。
5. 恶劣天气预案：动态溢价 + 时效放宽 + 提前运力激励。

## 九、外卖特有坑

- **出餐慢拖垮时效**：商家出餐进度不可见 → 必须采集出餐事件驱动调度。
- **合单翻车**：为提效强合单导致某单严重超时 → 时间窗约束 + 超时改派。
- **运力预测失准**：高峰期骑手不够 → 需历史 + 天气 + 活动多维预测并提前激励。
- **商家超卖/沽清**：菜品售罄未及时同步 → 库存与商品联动。
- **隐私与交通安全**：实时位置合规 + 骑手超速风险 → 脱敏 + 安全提醒。

> 口诀：**"外卖三角：用户等、商家出、骑手送；调度算合单，时效卡 SLA，出餐要先知，运力靠预测。"**
