# 数据导出与批量下载系统设计

> 板块：场景设计 　|　 返回：[README](README.md)
> 适用：后台报表导出、用户数据下载、大文件批量导出。

数据导出看似简单，实则坑在**大文件、长耗时、高内存、防刷防盗**。正确做法是异步化 + 流式 + 对象存储。

## 一、同步 vs 异步

| 方式 | 适用 | 风险 |
|------|------|------|
| 同步导出 | 小数据（<1万行） | 超时、阻塞请求线程 |
| 异步导出 | 大数据 | 需任务管理与通知 |

> 经验：超过几万行必须异步。同步导出一旦慢查询或内存溢出，直接拖垮 Web 线程池。

## 二、异步导出流程

```
用户请求 → 创建导出任务(状态: 处理中) → 返回任务ID
                                      ↓ (MQ/定时)
                          Worker 流式查询+写文件(分片)
                                      ↓
                          上传 OSS → 更新任务(完成+下载URL)
                                      ↓
                          通知用户(站内信/邮件)
```

## 三、流式与内存控制

- **流式查询**：JDBC `ResultSet` 游标/`fetchSize`、ES `scroll`/search_after，避免一次性加载全量到内存。
- **分片写入**：每 N 万行切一个文件，或单文件流式追加。
- **格式**：CSV（简单）、Excel（POI 用 SXSSF 流式避免 OOM）。

```java
// 流式导出 CSV，避免全量进内存
try (PreparedStatement ps = conn.prepareStatement(sql, ResultSet.TYPE_FORWARD_ONLY, ResultSet.CONCUR_READ_ONLY)) {
    ps.setFetchSize(1000);
    ResultSet rs = ps.executeQuery();
    while (rs.next()) {
        writer.write(toCsvLine(rs));  // 逐行写
    }
}
```

## 四、大文件与下载

- **对象存储**：文件生成后传 OSS/S3，下载走**预签名 URL**（带过期与权限）。
- **断点/分片**：超大会用分片上传与 Range 下载。
- **有效期**：下载链接设 TTL（如 10 分钟/24h），防长期暴露。

## 五、防刷与限流

- 单用户导出频控（如 1 分钟 1 次）。
- 导出任务数上限，防止堆积压垮 Worker。
- 敏感数据脱敏/权限校验，防止越权导出他人数据。

## 六、进度与体验

- 任务列表展示：处理中/完成/失败 + 进度百分比。
- 完成后通知，点击下载。
- 失败可重试，保留错误原因。

## 七、常见坑

1. **同步导出大表** → 超时/OOM；改异步流式。
2. **全量加载内存** → 堆溢出；用游标流式。
3. **下载 URL 长期有效** → 数据泄露；用预签名 + TTL。
4. **无权限校验** → 越权下载；导出前鉴权。
5. **POI 默认模式** → HSSF/XSSF 吃内存，用 SXSSF 流式。
6. **任务无限堆积** → Worker 雪崩；限流 + 队列容量。
