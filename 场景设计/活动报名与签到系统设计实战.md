# 活动报名与签到系统设计实战

> 活动报名用于线下/线上活动：报名、审核、签到、核验。核心是名额控制、防止黄牛与现场高效核验。

## 1. 背景与挑战

- 规模增长后单体难以为继，需要合理拆分与治理
- 边界不清导致耦合与回归
- 缺乏可观测性使问题定位困难

## 2. 设计原则

- 单一职责，边界清晰
- 先测后写，质量内建
- 可观测兜底，故障可定位

## 4. 核心要点

| 要点 | 说明 |
| --- | --- |
| 报名 | 表单+名额 |
| 审核 | 资质过滤 |
| 签到 | 二维码/人脸 |
| 核验 | 现场核验 |
| 统计 | 到场率 |

## 5. 关键实现

```python
def checkin(ticket):
    if ticket.used: raise Invalid('已签到')
    if not valid_qr(ticket.qr): raise Invalid
    ticket.used = True
```

## 6. 落地步骤

1. 明确目标与约束：SLA、成本上限、合规要求，避免范围蔓延。
2. 拆分核心模块，定义清晰的接口与边界（契约先行）。
3. 关键技术选型做最小化原型，验证风险点再全面铺开。
4. 接入可观测（日志/指标/链路）与告警，确保出问题可定位。
5. 灰度发布，监控核心指标，按阶段放量并保留回滚能力。

## 7. 度量与指标

| 指标 | 目标 | 手段 |
| --- | --- | --- |
| 可用性 | 99.9%+ | 多副本 + 健康探测 + 自动摘除 |
| 延迟 | P99 达标 | 缓存 + 异步 + 索引/批处理 |
| 成本 | 可控 | 弹性伸缩 + 资源画像 + 预算告警 |

## 8. 常见坑

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 设计失衡 | 复杂度错配 | 按规模选型，避免过度设计 |
| 边界遗漏 | 异常未覆盖 | 明确失败与降级路径 |
| 可观测缺 | 出问题无据 | 埋点 + 日志 + 链路追踪 |
| 扩展差 | 需求变更崩 | 预留扩展点与配置化 |

## 9. 面试题

- 名额如何控制？
- 签到如何高效？
- 如何防黄牛？
- 审核怎么做？
- 到场率怎么算？

## 10. 演进路径

- 从单体 / 最小可用，演进到分层与服务化治理。
- 从人工运维，演进到自动化、声明式与可观测。
- 从被动救火，演进到主动演练、容量规划与 SLO 驱动。

## 11. 小结

活动报名与签到系统设计实战 的核心是"结构化拆解、明确边界、可观测兜底"：在正确性与扩展性之间取平衡，用工程化手段把不确定性降到最低，并随规模持续演进。
