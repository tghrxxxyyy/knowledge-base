# 权限系统设计（RBAC/ABAC 深入 / 数据权限 / 缓存刷新 / 审计）

> 权限是几乎所有系统的地基。本篇深入拆解：RBAC 详细设计（角色继承/互斥）、ABAC 规则引擎、数据权限（行级）、权限缓存刷新策略、审计日志、OAuth2 开放平台权限。

---

## 一、核心模型

### 1.1 RBAC（基于角色的访问控制）

```
用户 ──多对多──> 角色(如: 运营) ──多对多──> 权限(如: 商品上架)
权限 = 操作(create/read/update/delete) × 资源(商品/订单/用户)

RBAC 变体：
  RBAC0：基础模型（用户↔角色↔权限）
  RBAC1：角色继承（子角色继承父角色权限）
  RBAC2：约束（互斥角色：出纳和会计不能同一人）
  RBAC3：RBAC1 + RBAC2
```

### 1.2 ABAC（基于属性的访问控制）

```
规则：允许 员工 查看 订单，当 (订单.owner == 用户.id) 或 (用户.role == "管理员")

条件 = 主体属性 + 资源属性 + 环境属性(时间/IP/设备) + 操作

适用：复杂业务系统（ERP/金融/医疗）、数据权限场景
优点：行级/数据级权限表达力强
缺点：策略引擎复杂、性能开销大
```

### 1.3 选型决策

| 场景 | 选择 | 理由 |
|------|------|------|
| 后台管理系统 | RBAC | 角色数量有限，管理简单 |
| 数据权限（只看本部门） | RBAC + 数据范围字段 | 简单够用 |
| 复杂条件权限 | ABAC | 属性组合灵活 |
| 混合场景 | RBAC（基础）+ ABAC（扩展） | 互补 |

## 二、数据模型设计

### 2.1 RBAC 标准五表

```
user（用户表）
  id, username, password, status, created_at

role（角色表）
  id, name, code, description, data_scope(数据范围)

permission（权限表）
  id, name, code, type(menu/button/api), parent_id, path, icon

user_role（用户-角色关联）
  user_id, role_id

role_perm（角色-权限关联）
  role_id, perm_id
```

### 2.2 数据权限（行级）

```
数据范围（data_scope）：
  1：全部数据
  2：本部门数据
  3：本部门及子部门数据
  4：仅本人数据
  5：自定义（指定部门/人员）

实现：查询时拼 SQL 条件
  if (dataScope == 2) {
      sql += " AND dept_id = " + currentDeptId;
  } else if (dataScope == 4) {
      sql += " AND created_by = " + currentUserId;
  }
```

### 2.3 菜单+按钮权限

```
菜单树（权限表 parent_id 表达层级）：
  系统管理
    ├── 用户管理（菜单）
    │   ├── 用户新增（按钮）
    │   ├── 用户编辑（按钮）
    │   └── 用户删除（按钮）
    └── 角色管理（菜单）
        └── 角色分配（按钮）

前端：根据权限列表动态渲染菜单和按钮
后端：每个 API 接口关联权限码（如 user:create）
```

## 三、鉴权实现

### 3.1 鉴权链路

```
请求 → 网关/拦截器: 解析 Token(JWT) → 取用户 → 取权限列表(缓存)
  → 注解/中间件(@PreAuthorize / AOP) 校验 → 通过放行 / 403
```

### 3.2 Spring Security 示例

```java
// 权限注解
@PreAuthorize("hasAuthority('user:create')")
public User createUser(CreateUserDTO dto) { ... }

@PreAuthorize("hasRole('ADMIN') or #userId == authentication.principal.id")
public User getUser(Long userId) { ... }

// 数据权限（AOP 拦截）
@Aspect
@Component
public class DataScopeAspect {
    @Before("@annotation(dataScope)")
    public void doBefore(JoinPoint joinPoint) {
        DataScope scope = dataScopeService.getDataScope(currentUserId);
        if (scope.getDataScope() == 2) {
            // 追加 WHERE dept_id = ?
            appendDeptFilter(joinPoint, scope.getDeptId());
        } else if (scope.getDataScope() == 4) {
            // 追加 WHERE created_by = ?
            appendUserFilter(joinPoint, scope.getUserId());
        }
    }
}
```

## 四、高性能实现

### 4.1 权限缓存

```
缓存策略：
  Redis 缓存用户权限列表（TTL + 变更主动失效）
  Key: user:permissions:{userId}
  Value: Set<String> 权限码列表

刷新机制：
  1. 角色变更 → 广播失效（Redis Pub/Sub）
  2. 权限变更 → 广播失效
  3. 用户角色变更 → 失效该用户缓存
  4. TTL 兜底（如 10 分钟过期）
```

### 4.2 位图加速

```
权限编码为位（如 64 位整数）：
  user:create = 1 << 0
  user:read   = 1 << 1
  user:update = 1 << 2
  user:delete = 1 << 3
  order:create = 1 << 4

角色 = 权限位 OR 集合：
  运营角色 = user:create | user:read | user:update
  = 0b00000111

校验 = (userPerm & requiredPerm) != 0：
  O(1) 判断，性能极高

适用：权限数量有限（< 64）且需要极致性能
```

### 4.3 网关前置

```
粗粒度（路径级）：网关拦截（如 /admin/* 只允许 admin 角色）
细粒度（数据级）：业务内执行（数据权限 SQL 拦截）
按钮级：前端根据权限列表动态渲染（后端不强制）
```

## 五、审计日志

### 5.1 审计要素

```
Who（谁）：用户ID、用户名、角色
What（做了什么）：操作类型（增删改查）、资源、数据
When（什么时候）：时间戳
Where（在哪里）：IP地址、设备信息
Result（结果）：成功/失败、变更前后值
```

### 5.2 实现

```java
@Aspect
@Component
public class AuditAspect {
    @Around("@annotation(auditLog)")
    public Object doAudit(JoinPoint joinPoint, AuditLog auditLog) {
        AuditRecord record = new AuditRecord();
        record.setUserId(currentUserId);
        record.setAction(auditLog.action());
        record.setResource(auditLog.resource());
        record.setTimestamp(Instant.now());
        record.setIpAddress(getClientIp());
        
        Object result = joinPoint.proceed();
        
        record.setSuccess(true);
        auditLogService.saveAsync(record);  // 异步写入
        return result;
    }
}
```

## 六、安全细节

| 安全点 | 措施 |
|--------|------|
| 权限校验 | **必须后端校验**（前端隐藏按钮只是体验） |
| 越权测试 | 改 ID 访问他人资源（IDOR）→ 数据权限兜底 |
| 敏感操作 | 二次确认 + 审计日志 |
| 权限最小化 | 默认无权限，按需分配 |
| 临时授权 | JIT（Just-In-Time）提权 + 超时自动回收 |

## 七、面试答题框架

1. 需求澄清：管理端/开放平台？要数据权限吗？用户量/角色量规模？
2. 选型：默认 RBAC（+角色继承）；行级数据权限 → 引入数据范围字段
3. 数据模型：五表关系 + 按钮级权限 + 数据权限实现
4. 实现：JWT → 拦截器 → 缓存权限 → AOP 注解校验
5. 性能：Redis 缓存 + 位图加速（可选）+ 网关前置
6. 安全：后端强校验 + 防 IDOR + 审计日志
7. 扩展：权限变更即时生效 + 开放平台用 OAuth2 + Scope
