# 用户标签与画像系统

> 板块：场景设计 　|　 返回：[README](README.md)
> 适用：精准营销、个性化推荐、风控、用户分群。

用户画像 = 给用户打标签 + 把标签组合成可查询的画像。难点在**标签体系的统一、实时与离线的融合、查询性能、隐私合规**。

## 一、标签体系

| 类型 | 来源 | 例子 |
|------|------|------|
| 事实标签 | 直接取（注册信息、行为日志） | 性别、城市、设备 |
| 规则标签 | 规则计算 | 近30天活跃、高价值用户 |
| 模型标签 | 算法预测 | 流失概率、兴趣类目 |
| 偏好标签 | 行为统计 | 喜欢夜间下单、客单价高 |

## 二、架构

```
行为日志 → 实时流(Flink) → 实时标签(热数据)
         → 离线数仓(Spark) → 离线标签(T+1 宽表)
                          ↓ 合并
                   标签宽表(画像底座)
                          ↓
              画像服务(OLAP/图/API) → 业务(推荐/营销/风控)
```

- **实时**：Flink 消费行为事件，更新近期标签（如"正在浏览某类目"）。
- **离线**：Spark 每日批量算稳定标签，写入标签宽表。
- **合并**：实时 + 离线合并成统一画像，供查询。

## 三、标签宽表与存储

- **宽表**：一行一个用户，列是各标签（HBase/ClickHouse/数仓表）。
- **查询**：按用户 ID 取全量标签；按标签反向圈人（如"标签=高价值 AND 城市=北京"）。
- **OLAP**：圈人用 ClickHouse/Doris，标签位图（Bitmap）加速交并差。

```sql
-- 圈人：高价值且近期活跃且在一线城市
SELECT user_id FROM user_profile
WHERE is_high_value=1 AND active_30d=1 AND city IN ('北京','上海','深圳');
```

## 四、画像服务

- **API**：`GET /profile/{uid}` 返回标签 JSON。
- **特征服务**：给推荐/风控提供实时特征。
- **分群**：运营按标签组合圈定人群，推送活动。

## 五、隐私与合规

- **最小化**：只采集必要数据，避免过度画像。
- **授权**：用户知情同意，提供关闭/删除（GDPR/个保法）。
- **脱敏**：敏感标签（健康、位置）加密存储。
- **用途限制**：标签不得超范围使用。

## 六、常见坑

1. **标签口径不一** → 各团队各算各的，数据打架；建统一标签中台。
2. **实时离线割裂** → 实时和离线标签冲突；统一合并层。
3. **圈人慢** → 全表扫；用 Bitmap/OLAP 索引。
4. **标签膨胀** → 几千个无用标签，维护难；定期治理。
5. **隐私违规** → 未授权用敏感数据；合规审查 + 脱敏。
6. **画像更新滞后** → 推荐不新鲜；关键标签实时化。
