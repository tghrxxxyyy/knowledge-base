# 计费与计量系统设计

> 板块：场景设计 　|　 返回：[README](README.md)
> 适用：SaaS/云服务/API 按量付费、资源用量计费、订阅与包月混合计费。

计费系统的第一性原理是**"用量可计量、账单可追溯、金额不错算"**。它连接业务用量与财务营收，错误会直接导致客诉或资损。

## 一、核心概念

| 概念 | 含义 |
|------|------|
| 计量（Metering） | 采集"用了多少"（调用次数、流量、时长、存储） |
| 计费（Rating） | 把用量按价格模型换算成金额 |
| 账单（Billing） | 按周期（日/月）汇总成可收款单据 |
| 出账（Invoicing） | 生成发票/扣款指令 |
| 对账（Reconciliation） | 计费金额与支付/渠道勾对 |

## 二、整体架构

```
用量事件 → 采集SDK/埋点 → 消息队列 → 计量聚合(实时/离线) → 计费引擎 → 账单存储 → 出账/扣款 → 对账
```

- **采集层**：业务系统上报用量事件（如 API 调用、资源时长），通过 MQ 解耦，避免阻塞主链路。
- **计量层**：实时（Flink/流计算）做近实时用量，离线（Spark/批）做 T+1 校正，二者互补。
- **计费层**：计费引擎按价格套餐（按需/阶梯/包月）算费。
- **账单层**：按月/日汇总，生成账单与明细。
- **对账层**：计费与支付渠道核对，发现差异告警。

## 三、计量采集

```json
{
  "tenantId": "t_001",
  "resourceId": "api_chat_gpt4",
  "eventTime": "2026-08-31T10:00:00Z",
  "quantity": 1,
  "meta": { "userId": "u_99", "region": "cn" }
}
```

- **防丢失**：MQ 至少一次 + 幂等去重（eventId 唯一），避免重复计量。
- **防篡改**：用量事件带签名，计费侧校验，防止伪造用量。
- **削峰**：高并发上报走 MQ 缓冲，计量异步处理。

## 四、计费模型

| 模型 | 说明 | 适用 |
|------|------|------|
| 按需（Pay-as-you-go） | 单价 × 用量 | 弹性资源、API 调用 |
| 包月/包年 | 固定费换不限量或额度 | 稳定客户 |
| 阶梯计费 | 用量越大单价越低 | 鼓励多用 |
| 预留/承诺 | 承诺最低消费换折扣 | 大客户 |
| 混合 | 包月保底 + 超额按需 | 主流 SaaS |

```java
// 阶梯计费示例
double calc(long qty, double[] steps, double[] prices) {
    double cost = 0; long remain = qty;
    for (int i = 0; i < steps.length; i++) {
        long seg = Math.min(remain, steps[i] - (i==0?0:steps[i-1]));
        cost += seg * prices[i]; remain -= seg;
        if (remain <= 0) break;
    }
    return cost;
}
```

## 五、账单与出账

- **账单周期**：自然月为主，支持按日/按需出账。
- **明细可追溯**：每条费用对应用量明细，客户可下钻。
- **欠费停服**：余额/额度不足触发停服，充值后恢复；需通知与宽限期。
- **退费与调账**：优惠、错账通过调账单处理，留痕审计。

## 六、实时计费 vs 离线计费

| 维度 | 实时 | 离线 |
|------|------|------|
| 时效 | 秒级 | T+1 |
| 用途 | 额度控制、防超额 | 正式账单、财务 |
| 风险 | 计算错难回滚 | 可重算校正 |
| 成本 | 流计算资源贵 | 批处理便宜 |

> 实践：实时用于控制（超额即限流/停服），离线用于精准出账（最终金额以离线为准）。

## 七、多租户计量

- 隔离：每个租户独立用量与账单，避免串账。
- 配额：租户级/资源级额度，超额触发告警或限流。
- 币种与税率：跨境需支持多币种、含税价。

## 八、常见坑

1. **计量事件丢失** → 漏算收入；用 MQ + 幂等 + 对账兜底。
2. **重复计量** → 多算客诉；eventId 去重。
3. **单价变更无版本** → 历史账单对不上；价格带生效时间版本。
4. **实时与离线金额不一致** → 以离线为准，实时仅控制。
5. **时区错误** → 跨时区账单周期错；统一 UTC 存储、本地展示。
6. **欠费停服误伤** → 需宽限期与多通道通知。
