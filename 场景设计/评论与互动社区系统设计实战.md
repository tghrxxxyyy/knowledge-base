# 评论与互动社区系统设计实战

> 评论、点赞、回复、@、热评是内容社区的基础互动能力。系统设计要兼顾：树形结构、高并发写、热度排序、敏感管控与实时通知。

## 1. 数据模型

```mermaid
erDiagram
    COMMENT ||--o{ COMMENT : 回复
    COMMENT {
        id
        target_id 被评对象
        user_id
        parent_id 父评论
        root_id 根评论
        content
        like_count
        status 正常/审核/删除
        created_at
    }
    LIKE {
        user_id
        comment_id
        created_at
    }
```

## 2. 评论结构

- **扁平 vs 树形**：
  - 扁平：所有评论平铺，靠 `parent_id` 关联，查询简单但深层回复难展。
  - 树形：嵌套存储，展示直观，分页复杂。
- 常用折中：**两级结构**——一级评论 + 其下回复列表，避免无限嵌套。

## 3. 存储与查询

- 评论主表按 `target_id` 分库分表（如按内容 ID 取模）。
- 热点内容评论用缓存（如 Redis 存 Top 热评）。
- 分页：游标分页（`created_at, id`）优于 offset，避免深翻性能差。

```sql
SELECT * FROM comment
WHERE target_id=? AND root_id=?
ORDER BY like_count DESC, created_at DESC
LIMIT 20 OFFSET ?;
```

## 4. 点赞设计

- **计数**：评论表 `like_count` 字段，写时 +1；也可异步由点赞流水聚合。
- **是否已赞**：`user_id+comment_id` 唯一，缓存用户点赞集合。
- **防刷**：单用户点赞频率限制，防止刷量。

```redis
SADD like:set:{commentId} {userId}   # 已赞成员
SCARD like:set:{commentId}           # 点赞数
```

## 5. 热度排序

热评排序综合多因子：

```
hot = like*W1 + reply*W2 + recent_time_boost - penalty
```

- 时间衰减：新评论有初始曝光权重。
- 高赞优先：点赞高置顶。
- 争议/举报降权：被举报评论下沉。

## 6. 内容安全

- **先发后审 / 先审后发**：高风险场景先审。
- **敏感词 + 模型审核**：文本过滤 + 语义模型识别违规。
- **用户举报**：举报触发人工复核，命中则下线。

## 7. 实时互动

- 评论/回复通过长连接或推送通知被评论者。
- @某人实时提醒。
- 点赞数变更可走消息广播前端实时刷新。

## 8. 高并发

- 写高峰（热点内容）用 MQ 异步落库，削峰。
- 读多写少，热评缓存，DB 读走从库。
- 评论数等聚合指标异步更新，允许短暂不一致。

## 9. 常见坑

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 深分页慢 | 翻页卡 | 游标分页 |
| 计数不准 | 点赞漂移 | 流水聚合+对账 |
| 热评抖动 | 顺序乱跳 | 稳定 tie-break |
| 违规内容 | 风险 | 审核+举报 |
| 写峰雪崩 | DB 压力 | MQ 削峰 |

## 11. 小结

评论互动系统 = 树形/两级结构 + 分表存储 + 聚合计数 + 热度排序 + 内容安全 + 异步削峰。读多写少，缓存与 MQ 是关键。
