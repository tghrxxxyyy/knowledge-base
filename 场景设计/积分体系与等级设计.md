# 积分体系与等级设计

> 板块：场景设计 　|　 返回：[README](README.md)
> 关联：[电商交易业务模型](../业务模型/电商交易业务模型.md)、[内容社区与UGC业务模型](../业务模型/内容社区与UGC业务模型.md)、[分布式锁与幂等设计](分布式锁与幂等设计.md)

积分与等级是互联网产品最常用的"用户激励 + 留存"手段：签到、消费、互动得积分，积分可兑换、抵现；等级反映用户价值，解锁权益。看似简单，实则涉及**获取规则、账户记账、防刷、过期、兑换、对账**一整套体系。本文系统拆解。

## 一、积分体系的核心目标

| 目标 | 说明 |
|------|------|
| 激励行为 | 促活、促消费、促传播（做任务得积分） |
| 提升留存 | 等级权益 + 积分沉淀（"沉没成本"）提高流失门槛 |
| 促进转化 | 积分抵现、兑换，拉动交易 |
| 用户分层 | 等级区分高价值用户，差异化运营 |

> 设计原则：规则透明、到账及时、防刷严谨、可兑换、可对账。

## 二、核心实体

```
用户 ──1:N──▶ 积分账户（按类型/币种）
积分账户 ──1:N──▶ 积分流水（获取/消耗/过期/冻结）
用户 ──1:1──▶ 等级（成长值驱动）
```

| 实体 | 关键字段 |
|------|---------|
| 积分账户 | user_id, balance, frozen, expire_bucket（按过期批次） |
| 积分流水 | id, user_id, type(获取/消耗/过期), amount, biz_no(业务单号), expire_at, create_at |
| 等级 | user_id, level, growth(成长值), upgrade_at |
| 获取规则 | rule_id, action(签到/消费/互动), points, limit(每日上限), start/end |

## 三、积分的"可加性"与"账户模型"

积分本质是**多币种、带过期、可冻结**的虚拟货币：

- **多币种**：通用积分、成长值（不可兑换）、活动积分（限时使用）分开账户。
- **带过期**：多数积分有有效期（如当年有效、滚动 12 个月过期），需按批次管理。
- **可冻结**：风控/申诉时冻结部分积分，解冻或扣减。

```sql
CREATE TABLE point_account (
    user_id   BIGINT PRIMARY KEY,
    balance   BIGINT NOT NULL DEFAULT 0,   -- 可用余额
    frozen    BIGINT NOT NULL DEFAULT 0,   -- 冻结
    updated_at DATETIME
);
CREATE TABLE point_ledger (              -- 只追加流水
    id        BIGINT PRIMARY KEY,
    user_id   BIGINT,
    biz_no    VARCHAR(64),               -- 业务幂等键(订单/任务ID)
    type      TINYINT,                   -- 1获取 2消耗 3过期 4冻结 5解冻
    amount    BIGINT,
    expire_at DATETIME,
    created_at DATETIME,
    UNIQUE KEY uk_biz (biz_no, type)     -- 防重复记账
);
```

## 四、积分获取（发放）

| 来源 | 说明 | 风控 |
|------|------|------|
| 消费得积分 | 按金额比例（如 1 元=1 分） | 退款回退积分 |
| 签到 | 连续签到递增奖励 | 模拟器/脚本识别 |
| 完成任务 | 看视频、分享、评论 | 行为真实性校验 |
| 活动奖励 | 抽奖、裂变 | 预算封顶、频控 |
| 成长值 | 累计行为得成长值 → 升级 | 同积分但不可兑换 |

- **发放幂等**：每次发放带 `biz_no`（订单号/任务记录），唯一索引防重复发放（见 [分布式锁与幂等设计](分布式锁与幂等设计.md)）。
- **预算控制**：活动积分总额封顶，发完即止；按用户维度设每日/每月获取上限。
- **异步发放**：消费后通过 MQ 异步发积分，主链路不阻塞；失败重试（幂等）。

## 五、积分消耗（兑换/抵现）

| 方式 | 说明 |
|------|------|
| 积分商城兑换 | 实物/虚拟商品，扣积分 |
| 积分抵现 | 下单时按比例抵现（如有 100 积分抵 1 元） |
| 抽奖/玩法 | 消耗积分参与 |
| 权益解锁 | 高等级专属（不消耗） |

- 消耗也需幂等（biz_no），防重复扣。
- **余额不足拦截**：`UPDATE point_account SET balance=balance-? WHERE user_id=? AND balance>=?` 影响行数=0 则失败。
- **对账**：积分流水与兑换订单核对，防资损（多发/多扣）。

## 六、积分过期（滚动过期）

- 主流做法：**按获取批次滚动过期**（如 2026-01 获取的积分 2027-01 到期）。
- 实现：流水带 `expire_at`，定时任务扫描到期批次，批量扣减（或实时计算可用余额 = 总额 − 未到期冻结）。
- 展示"即将过期 X 分"促使用户消耗，提升活跃。

```sql
-- 定时过期：扫描 expire_at <= now 且未处理的流水，批量扣减
UPDATE point_account a
JOIN (SELECT user_id, SUM(amount) s FROM point_ledger
      WHERE type=1 AND expire_at<=? AND expired=0 GROUP BY user_id) b
ON a.user_id=b.user_id
SET a.balance = a.balance - b.s;
```

## 七、等级与成长值

| 维度 | 说明 |
|------|------|
| 成长值 | 累计行为（消费、活跃）得成长值，单调递增 |
| 等级阈值 | 如 0/100/500/2000/5000 → L1~L5 |
| 权益 | 高等级：专属客服、折扣、免费券、生日礼 |
| 保级/降级 | 按周期（年）考核，未达标降级（或只升不降，看策略） |

- 成长值**只增不减**（除非违规清退），与可消耗的积分分离。
- 升级实时计算（成长值过阈值即升），权益立即生效或下周期生效。

## 八、防刷与风控

| 风险 | 手段 |
|------|------|
| 脚本刷积分 | 设备指纹、行为序列、人机校验 |
| 虚假交易套积分 | 交易风控联动，退款回退 |
| 积分变现黑产 | 兑换限制、实名、限额 |
| 并发重复发放 | 幂等键 + 唯一索引 + 分布式锁 |
| 预算超发 | 活动总额 + 用户上限双控 |

## 九、高并发与一致性

- **记账**：余额 + 流水双写，流水只追加（审计）。
- **并发扣减**：条件更新 + 行锁，防超扣。
- **最终一致**：MQ 异步发放，消费端幂等；与订单/交易通过 biz_no 关联对账。
- **热点用户**：大 V/高活跃用户积分账户高频写 → 行锁竞争，可分段账户或异步聚合。

## 十、监控与对账

| 指标 | 说明 |
|------|------|
| 发放/消耗速率 | 异常突增=刷分 |
| 积分余额分布 | 健康度（大量临期=促消耗机会） |
| 对账差异 | 流水与业务单不符 → 告警 |
| 兑换履约 | 实物发货、虚拟到账 |

## 十一、常见坑

1. **发放不幂等** → 重复发积分（资损），必须 biz_no 唯一。
2. **过期不分批** → 全量过期或算错可用余额（滚动批次管理）。
3. **积分与成长值混用** → 逻辑混乱（分离：可消耗 vs 只增不减）。
4. **无预算上限** → 活动被刷爆（总额 + 用户上限）。
5. **退款不回退积分** → 资损/套利。
6. **余额更新无并发控制** → 超扣/少扣。
7. **规则不透明** → 用户投诉（展示获取/消耗/过期明细）。
8. **兑换不核对** → 黑产变现（实名+限额+风控）。

## 十二、落地清单

- [ ] 账户模型：余额 + 流水（只追加）+ 冻结 + 过期批次。
- [ ] 发放/消耗均幂等（biz_no 唯一索引 + 分布式锁）。
- [ ] 规则引擎化：获取规则可配置、带预算与上限。
- [ ] 滚动过期 + 临期提醒。
- [ ] 等级与成长值分离，阈值驱动升级。
- [ ] 防刷：设备指纹 + 行为风控 + 退款回退。
- [ ] 对账：积分流水与业务单每日核对。
