# 订单系统设计（状态机、超时、防超卖、对账）

> 订单系统是电商的**心脏**：下单、支付、库存、履约、退款围绕它转。面试高频题「设计一个订单系统」。本篇讲「解决的问题 → 核心流程 → 状态机 → 关键难题（幂等/防超卖/超时/对账）→ 高并发下单」。

---

## 一、解决的问题与定位

**解决的问题**：
1. 下单后**全生命周期管理**（待支付→已支付→已发货→已完成/已取消/退款中）；
2. 高并发秒杀时不超卖、不重复下单、不漏单；
3. 与支付/库存/物流/营销多方系统**对得上账**。

**定位一句话**：**「订单 = 电商核心流转状态机：前端扣库存锁单，后端异步履约，支付回调驱动状态，对账保证钱货一致。」**

---

## 二、核心流程与状态机

### 2.1 下单主流程（高并发骨架）

```
用户下单 ──> 防重(幂等: userId+商品+session 去重)
          ──> 校验(库存/价格/优惠) ──> 扣库存(Redis 预扣 / DB 乐观锁)
          ──> 创建订单(状态: 待支付) ──> 生成支付单 ──> 调支付渠道
          ──> 支付回调 ──> 校验签名+幂等 ──> 更新库存(正式扣) + 订单(已支付)
          ──> MQ 异步: 出库履约/积分/通知
```

### 2.2 订单状态机（必画）

```
待支付 ──支付回调──> 已支付 ──发货──> 已发货 ──确认收货──> 已完成
   │                    │
   ├─超时取消──> 已取消    ├─退款──> 退款中 ──> 已退款
   │                    │
   └─用户取消──> 已取消    └─售后──> 售后中(纠纷处理)
```

**状态机关键原则**：
- 状态**单向流转**，禁止跳变（防脏数据）；
- 状态变更 = 乐观锁更新（`UPDATE ... SET status=? WHERE id=? AND status=?`）或版本号；
- **不允许回退的链路**（已支付→待支付 必须走"退款"而非"修改状态"）。

## 三、四大关键难题与解法

### 3.1 幂等（防重复下单/重复支付回调）

- 下单幂等：`userId + 商品 + 会话` 唯一索引/Redis SETNX，重复点击只返回同一订单；
- 支付回调幂等：以 **支付单号** 为唯一键，回调处理前先查状态，已处理直接返回成功；
- 业务幂等键统一：`bizId + 幂等表（唯一约束）`，先插后做。

### 3.2 防超卖（库存扣减）

| 方案 | 做法 | 适用 |
|------|------|------|
| 数据库乐观锁 | `UPDATE stock SET num=num-1 WHERE sku=? AND num>0` | 常规商品（低频） |
| **Redis 预扣** | `DECR` + 校验 ≥0，异步同步 DB | 秒杀/高并发 |
| 队列串行化 | 同 SKU 请求进队列串行扣减 | 极端争用 |

> 关键：**扣库存与订单创建必须同事务/同锁域**；预扣后 15~30 分钟未支付要自动释放回滚。

### 3.3 订单超时（未支付自动取消）

- 方案 A：**延迟消息**（RocketMQ 延迟消息 / Redis ZSET 扫描）——到点触发检查取消，回滚库存；
- 方案 B：定时任务批量扫描「待支付超过 X 分钟」订单（分页 + 限量，量大时用延迟消息兜底）；
- 组合：**延迟消息精准触发 + 定时任务兜底扫描**是标准答案。

### 3.4 对账（钱货一致）

```
支付渠道账单(日终) ⇄ 我方支付流水 ⇄ 订单状态
差异项: 渠道已扣款但我方未更新(回调丢失) → 主动查询补偿/人工
```

- 日终对账 + **回调丢失补偿**（定时主动查支付渠道状态）；
- 对账脚本只读比对，差异进工单系统。

## 四、高并发下单架构要点

1. **读多写少拆分**：商品详情走缓存（多级缓存），订单写走 DB 分库分表；
2. **订单表分库分表**：按 `user_id`（查我的订单）或 `order_id` 双分片，跨分片查询用订单表冗余；
3. **异步化**：下单只做「锁库存+建单」，履约/通知/积分全部 MQ 异步；
4. **削峰**：秒杀场景 请求先进队列/令牌桶限流，后端固定速率处理；
5. **数据一致性**：本地消息表 / 事务消息保证「库存扣了但订单没建」这类跨系统一致。

## 五、面试答题框架

1. **需求澄清**：B2C 电商？下单量级？是否需要秒杀？
2. **核心流程**：下单→锁库存→建单→支付回调→履约，画出时序；
3. **状态机**：画状态图，讲单向流转 + 乐观锁更新；
4. **四难题逐个答**：幂等、防超卖、超时、对账（见上表）；
5. **高并发**：分库分表、异步 MQ、缓存读、队列削峰。

## 六、速查表

| 主题 | 一句话 |
|------|--------|
| 状态机 | 单向流转 + 乐观锁，支付回调驱动 |
| 幂等 | 幂等表唯一约束 + 回调状态判断 |
| 防超卖 | Redis 预扣 + DB 乐观锁，同锁域 |
| 超时 | 延迟消息精准 + 定时任务兜底 |
| 对账 | 渠道账单⇄流水⇄订单，差异工单 |
| 高并发 | 分库分表 + MQ 异步 + 限流削峰 |
