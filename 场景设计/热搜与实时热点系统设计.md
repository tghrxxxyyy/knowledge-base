# 热搜与实时热点系统设计深入（话题聚类 / 风控引擎 / 算法公式 / 运营干预）

> 热搜 = 超高并发的经典场景题。本篇深入拆解：话题聚类算法、风控引擎设计、热度公式调优、运营干预机制、数据回放。

---

## 一、核心矛盾

1. 计算全网**热点话题**的热度（不只看点击量，要抗刷、要反映"爆发性"）
2. **秒~分钟级**更新榜单（事件爆发后迅速上榜）
3. 高并发读（首页流量集中打榜单接口）+ 高并发写（行为流巨大）

> 核心主线：行为采集 → 实时计算热度 → 话题聚类 → 风控过滤 → 榜单生成 → 展示推送

## 二、热度公式（深入）

### 2.1 多维加权公式

```
热度 = Σ (行为权重 wᵢ × 行为量 vᵢ) × 时间衰减因子 f(t) × 爆发系数

示例（近似微博）：
  阅读量 × 1 + 转发 × 5 + 评论 × 8 + 赞 × 2 + 搜索量 × 20
  
时间衰减：
  f(t) = e^(-λt)  或  窗口内滚动计算
  近 1h 权重 × 1.0，近 4h × 0.5，近 24h × 0.2

爆发系数：
  爆发系数 = 当前小时行为量 / 过去 24h 平均行为量
  爆发越猛（如突然爆发），系数越高
```

### 2.2 热度衰减实现

```
方案1：指数衰减（实时）
  score = score × e^(-λ × Δt)
  每分钟衰减一次
  优点：精确
  缺点：需要定时任务

方案2：滑动窗口（Flink）
  近 1h/4h/24h 三个窗口分别统计
  加权合成：热度 = 1h × 0.6 + 4h × 0.3 + 24h × 0.1
  优点：精确、可做去重
  缺点：状态管理复杂

方案3：Redis ZSET 滚动
  ZADD score = timestamp（分数=时间戳）
  ZREVRANGEBYSCORE 获取最近 N 分钟的 score 总和
  优点：简单
  缺点：去重弱、量级受限
```

## 三、话题聚类算法

### 3.1 为什么需要聚类

```
热搜对象不是"文本"而是"话题"
  → 多条关于同一事件的帖子需要聚合
  → 聚类后才能计算话题级别的热度

难点：
  实时流式聚类（不是离线批处理）
  话题演化（新帖子加入后话题特征变化）
  多语言/多模态（文本+图片+视频）
```

### 3.2 聚类方案

| 方案 | 原理 | 适用 |
|------|------|------|
| TF-IDF + 余弦 | 提取关键词，计算相似度 | 简单场景 |
| TextRank | 图排序提取关键词 | 关键词提取 |
| BERT Embedding | 语义向量聚类 | 语义聚类 |
| LDA 主题模型 | 概率主题模型 | 主题发现 |
| 运营+算法混合 | 算法辅助聚合，运营确认 | 小规模团队 |

### 3.3 实时聚类流程

```
新帖子 → 关键词提取（TF-IDF / BERT）
  → 与已有话题计算相似度
  → 相似度 > 阈值 → 归入已有话题
  → 相似度 < 阈值 → 创建新话题
  → 话题热度重新计算
```

## 四、风控引擎设计

### 4.1 风控层次

```
第一层：数据过滤（实时）
  去重：同用户重复行为只计一次
  异常账号过滤：注册时间短/无头像/僵尸号
  机器流量过滤：爬虫/机器人

第二层：统计检测（准实时）
  增速异常：单话题增速远超历史曲线
  集中度异常：大量行为来自同一 IP/设备
  时间异常：凌晨爆发（非正常时段）

第三层：人工审核（离线）
  复审队列：可疑话题人工确认
  举报机制：用户举报 → 加速下榜
```

### 4.2 风控规则

| 规则 | 说明 |
|------|------|
| 去重 | 同用户同话题同类型行为 1 小时内只计 1 次 |
| 增速阈值 | 话题热度增速 > 历史 99 分位 → 标记 |
| 账号质量 | 新注册账号（< 7天）行为权重 × 0.1 |
| 设备指纹 | 同设备多账号 → 标记为疑似刷子 |
| 内容质量 | 纯链接/无意义内容 → 降权 |
| 人工审核 | 可疑话题进入复审队列 |

### 4.3 风控与热度联动

```
风控标记 → 热度降权/过滤

降权：嫌疑话题热度 × 0.5（不完全排除，但降低排名）
过滤：确认刷榜话题从榜单移除
复审：降权话题进入人工审核队列
```

## 五、高并发读优化

### 5.1 榜单缓存

```
Redis ZSET：topic_id → score
  ZREVRANGE hot:rank 0 49 → Top50

本地缓存：Caffeine（10s 过期）
  → 毫秒级响应

CDN 缓存：1~5s 过期
  → 扛首页流量
```

### 5.2 增量推送

```
榜单变化不大时 → 增量 diff 推送

流程：
  1. 榜单服务对比新旧 Top50
  2. 只推变化条目（新增/排名变化/移除）
  3. 客户端本地更新

好处：
  省流量（大部分时候只有几条变化）
  降低服务端压力
```

### 5.3 降级策略

| 级别 | 策略 |
|------|------|
| 正常 | 实时热度 + 本地缓存 + CDN |
| 轻微故障 | 本地缓存 + CDN（关闭实时更新） |
| 严重故障 | 静态榜（24h 历史榜） |
| 兜底 | 运营手动置顶 |

## 六、运营干预

### 6.1 机制

| 类型 | 说明 |
|------|------|
| 置顶 | 运营手动置顶重要事件 |
| 热搜 | 运营手动添加热搜词 |
| 下架 | 违规/敏感话题人工下架 |
| 降权 | 可疑话题手动降权 |
| 审核 | 新话题上线前人工审核 |

### 6.2 审核流程

```
新话题 → 算法打分 → 风控过滤 → 审核队列
  → 审核通过 → 上榜
  → 审核拒绝 → 不上榜
  → 敏感话题 → 标记 + 不上榜
```

## 七、数据回放与审计

```
所有行为流 → Kafka → 数据湖（永久存储）

用途：
  1. 热度复盘：回放历史数据，验证热度公式
  2. 风控审计：回溯刷榜行为，优化风控规则
  3. 算法迭代：离线测试新聚类/热度算法
```

## 八、面试答题框架

1. **需求澄清**：更新频率、规模（日行为量）、榜单长度（Top10/50）
2. **热度公式**：多维加权 × 时间衰减 × 爆发系数
3. **实时计算**：Flink 多窗口聚合 → Redis ZSET
4. **话题聚类**：TF-IDF/BERT 相似度聚类
5. **风控**：数据过滤 → 统计检测 → 人工审核三层
6. **高并发读**：榜单快照缓存 + diff 增量推送 + CDN + 降级
7. **进阶**：运营干预 + 数据回放 + 算法迭代
