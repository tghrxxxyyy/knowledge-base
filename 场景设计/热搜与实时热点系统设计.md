# 热搜与实时热点系统设计

> 微博热搜、抖音热榜、知乎热榜——「实时热点榜」是超高并发的经典场景题：全网事件秒级上榜、百万级点击量级、榜单实时变化。本篇讲「解决的问题 → 核心指标 → 数据模型 → 实时计算 → 展示优化 → 面试答题框架」。

---

## 一、解决的问题与定位

**解决的问题**：
1. 计算全网**热点话题**的热度（不只看点击量，要抗刷、要反映"爆发性"）；
2. **秒~分钟级**更新榜单（事件爆发后迅速上榜）；
3. 高并发读（首页流量集中打榜单接口）+ 高并发写（行为流巨大）。

**定位一句话**：**「热度 = 多维加权 + 时间衰减的『爆发性』指标；实时链路（Flink/Redis 滑动窗口）算热度，榜单缓存 + 增量推送扛高并发读——核心难点在『热度公式』与『实时窗口』。」**

---

## 二、热度计算：什么算"热"？

### 2.1 热度特征

- **时间敏感**：三小时前的 10 万点击 vs 现在的 1 万点击，后者更热——热度必须**随时间衰减**；
- **爆发性**：持续高热（稳定话题）与突然爆发（事件）都算热，但爆发更值钱；
- **多维**：阅读量、讨论量（评论/转发/发帖）、搜索量、视频播放，加权重合成。

### 2.2 经典热度公式（面试必讲）

```
热度 = Σ (行为权重 wᵢ × 行为量 vᵢ) × 时间衰减因子 f(t)

例(近似微博):
热度 = 阅读量×1 + 转发×5 + 评论×8 + 赞×2 + 搜索量×20
时间衰减: f(t) = e^(-λt) 或 窗口内滚动计算(近1h/4h/24h 不同权重)
```

- **为什么加权**：阅读量大但无人讨论 ≠ 热——讨论/转发/搜索权重高，体现"参与度"；
- **为什么衰减**：防"老话题霸榜"；事件新闻就是"当下"的产物。

### 2.3 抗刷（防作弊，面试亮点）

- **去重与防重**：同用户重复行为只计一次（用户维度去重：浏览按设备、讨论按用户）；
- **权重校验**：异常账号（注册时间短/无头像/僵尸号）行为降权或不计；
- **统计口径**：只算"真实用户"行为（打标过滤机器/爬虫流量）；
- **异常检测**：单话题增速异常（远超曲线）触发风控复审。

## 三、实时计算架构

```
行为流(浏览/评论/搜索/转发) ──> Kafka
                                  │
                       Flink 滑动窗口聚合(近N小时, 按话题维度)
                                  │  抗刷过滤 + 去重 + 衰减
                                  ▼
                        热度结果写入 Redis(ZSET: topic→score)
                                  │
             榜单服务: 定时拉取 TopN + 变更事件(websocket/push)
                                  │
                              CDN/缓存: 秒级快照 + 增量 diff
```

### 3.1 实时窗口选型

| 方案 | 实现 | 优劣 |
|------|------|------|
| **Flink 滑动窗口** | 近 1h/4h/24h 多窗口分别聚合，加权合成 | 精确、可做去重；运维重 |
| Redis ZSET 滚动 | 行为直接 ZINCRBY，定时衰减扫描 | 简单；去重弱、量级受限 |
| 离线+实时融合 | 大基数/长周期离线算，短周期实时补 | 混合复杂度高 |

> 标准答案：**Flink 算实时热度（多窗口加权）→ Redis ZSET 存话题分 → 榜单服务缓存 TopN；高并发读靠『榜单快照缓存 + 变化 diff 推送』。**

### 3.2 高并发读优化

- **榜单接口不打实时计算**：服务端维护 TopN 快照（ZREVRANGE 取前 50），毫秒级响应；
- **推送 vs 轮询**：榜单变化不大时**增量 diff**（榜单服务对比新旧，只推变化条目），客户端本地更新——省流量；
- **CDN 兜底**：热榜页可缓存 1~5 秒（容忍微弱延迟）；
- **降级**：实时链路故障时回退「离线榜」（24h 窗口）或静态榜。

## 四、话题识别（进阶，面试加分）

- 热搜对象不是"文本"而是**话题**：实时流式**关键词聚类/事件抽取**（NLP 层：提取实体 + 相似度聚类），聚类后的话题进入热度计算；
- 备选方案：运营人工建话题 + 算法辅助聚合（小规模团队常用）；
- 热搜词提取：TF-IDF / TextRank 对增量文本提取候选词。

---

## 五、面试答题框架

1. **需求澄清**：热搜榜单更新频率、规模（日行为量）、榜单长度（Top10/50）；
2. **热度公式**：多维加权 + 时间衰减（先讲"为什么"）；
3. **实时计算**：Flink 滑动窗口 → Redis ZSET，抗刷与去重；
4. **高并发读**：榜单快照缓存 + diff 增量推送 + CDN + 降级；
5. **进阶**：话题聚类识别、风控。
