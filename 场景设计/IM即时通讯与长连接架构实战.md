# IM 即时通讯与长连接架构实战

> 本文梳理即时通讯（IM）系统的核心架构：长连接接入、消息可靠投递、离线推送、已读回执、群聊扩散、消息时序与存储。内容基于公开工业实践，具体参数以业务为准。

## 1. IM 的核心挑战

- 海量长连接：百万/千万级 TCP 连接维持。
- 低延迟投递：消息尽快到达对端。
- 可靠性：不丢、不重、不漏。
- 一致性：多端消息顺序一致。
- 扩展性：连接数、消息量持续增长。

## 2. 长连接接入层

- 客户端与网关（接入层）维持长连接（TCP/WebSocket）。
- 接入层无状态，可水平扩展。
- 连接与用户映射：connId ↔ userId 存于接入层内存或 Redis。
- 多协议：移动端 TCP（私有协议/长连），Web 用 WebSocket。

## 3. 连接管理

- 心跳：客户端定时发心跳，服务端检测超时断连。
- 重连：断线指数退避重连，恢复会话。
- 多端：同一用户多设备，消息需多端同步。
- 网关选型：Netty 类高性能网络框架。

## 4. 消息投递模型

- 客户端 → 接入层 → 消息服务（逻辑）→ 落库 → 推送给接收方接入层 → 客户端。
- 推拉结合：在线推送（Push），离线后拉取（Pull）。
- 下发失败进离线队列，重连后拉取。

## 5. 可靠性：不丢不重

- 不丢：消息先落库再推送，确认（ACK）机制。
- 不重：消息带唯一 ID，接收端去重。
- 至少一次 + 去重 = 有效一次体验（见幂等章节）。
- 发送方收 ACK 才认为成功，否则重试。

## 6. 消息时序

- 服务端统一序号（如全局递增 ID / 逻辑时钟）。
- 乱序到达：客户端按序号排序展示。
- 跨设备：同一会话多端按服务端序号对齐。
- 避免用客户端本地时间（时钟漂移）。

## 7. 已读回执

- 接收方读后发回执，更新发送方状态。
- 群聊已读：记录已读成员集合（大群用位图/计数优化）。
- 存储：会话最后已读序号。

## 8. 离线消息

- 用户不在线，消息入离线库。
- 上线后拉取离线（按会话、按序号增量）。
- 离线推送：移动端走厂商推送通道（APNs/FCM/厂商 Push）。
- 避免离线消息无限堆积：清理已读老消息。

## 9. 群聊扩散

- 写扩散（Feed）：消息写一份，群成员各自拉（适合小群）。
- 读扩散：消息写群，成员读取时拉（适合大群）。
- 折中：小群写扩散，大群按订阅关系分发。
- 大群优化：群成员分片，批量推。

## 10. 消息存储

- 短消息存 DB（按会话分表）。
- 历史消息冷热分离：热存在线，冷归档。
- 多媒体（图片/语音）存对象存储，消息体存 URL。
- 分页拉取历史，游标用消息序号。

## 11. 会话与未读

- 会话列表：最近联系人、最后一条、未读数。
- 未读计数：每会话未读，总未读聚合。
- 置顶、免打扰、拉黑等会话属性。

## 12. 扩展性设计

- 接入层无状态水平扩展（接更多连接）。
- 逻辑层按 userId 哈希分片。
- 消息存储分库分表（按会话/时间）。
- 网关与逻辑解耦，独立扩缩。

## 13. 安全

- 传输加密（TLS/私有加密）。
- 鉴权：长连接建立后校验 token。
- 防刷：发消息频率限制。
- 内容安全：敏感词/违规检测。

## 14. 与推送系统关系

- IM 实时消息走长连接 Push。
- 离线/系统通知走推送通道。
- 二者可共用接入层与消息服务（见推送系统设计章节）。

## 15. 典型指标

- 在线连接数、消息吞吐（条/秒）。
- 端到端延迟（P99）。
- 投递成功率、离线触达率。
- 多端同步一致性。

## 16. 常见踩坑

1. **心跳设错**：过短耗电/带宽，过长检测慢；按需调。
2. **消息无 ACK**：以为送达实则丢失；必须确认+重试。
3. **无去重**：重试导致重复消息；唯一 ID 去重。
4. **用本地时间排序**：时钟漂移乱序；用服务端序号。
5. **大群写扩散**：消息量爆炸；用读扩散/分片。
6. **离线库无限增长**：存储成本与拉取慢；归档清理。
7. **连接状态不一致**：网关重启丢映射；用共享存储。
8. **未做限流**：被刷消息拖垮；接入层限流。

## 17. 演进路径

- 单机能跑：单机长连接 + 内存消息。
- 分片：接入/逻辑/存储分离。
- 海量：接入层集群 + 逻辑分片 + 存储分表 + 离线推送。
- 多端：会话同步 + 多端已读。

## 18. 与 WebSocket 关系

- Web 端常用 WebSocket 维持长连。
- 移动端倾向 TCP 私有协议（省流量、可控）。
- 服务端接入层统一处理不同协议，对上层透明。

## 19. 小结

IM 架构的核心是"长连接接入 + 可靠投递 + 时序一致 + 离线兜底"。设计铁律：**消息先落库后推送、ACK+去重保不丢不重、服务端序号定序而非本地时间、群聊按规模选写/读扩散、离线走推送通道、接入层无状态可扩展**。多端同步与已读回执是体验关键，需用统一序号与状态存储保证。
