# 图片与文件存储架构实战

> 板块：场景设计 　|　 返回：[README](README.md)
> 适用：UGC 图片/视频、头像、文档、静态资源托管。

文件存储的核心是**可靠性、成本、访问速度**。直接存本地磁盘很快遇到容量与可用性问题，生产普遍用"对象存储 + CDN + 处理服务"。

## 一、整体架构

```
客户端 → 上传网关(鉴权/限流) → 对象存储(OSS/S3)
                                ↓ 触发
                          异步处理(缩略图/转码/审核)
客户端 → CDN → 对象存储(读，回源)
```

- **对象存储**：OSS/S3 存原文件，高可靠、无限扩容。
- **CDN**：边缘缓存热点文件，加速读取、降低回源。
- **处理服务**：异步生成缩略图、视频转码、内容审核。

## 二、上传方案

| 方案 | 流程 | 优点 |
|------|------|------|
| 服务端中转 | 客户端 → 应用 → 存储 | 易鉴权，慢、占带宽 |
| 客户端直传（预签名） | 客户端拿预签名 URL 直传 | 省带宽、快 |
| 分片上传 | 大文件切片并发传 | 断点续传、稳定 |

```java
// 服务端签发预签名 URL（客户端直传，省应用带宽）
String url = ossClient.generatePresignedUrl(bucket, key,
    Date.from(Instant.now().plusSeconds(300)), HttpMethod.PUT);
// 客户端用该 URL 直接 PUT 上传
```

## 三、图片处理

- **缩略图**：上传后异步生成多尺寸（原图/中图/小图），读时按规格返回。
- **实时处理**：部分 CDN 支持 URL 参数实时裁剪（`?x-oss-process=image/resize,w_200`）。
- **格式优化**：WebP/AVIF 降体积，提升加载速度。

## 四、视频处理

- 上传原片 → 转码为多码率（1080p/720p/480p）→ 切片 HLS/DASH → CDN 分发。
- 用转码集群（FFmpeg/MediaConvert）异步处理，避免阻塞。

## 五、内容安全

- 上传即送审核（图片鉴黄、暴恐、文本违规），违规文件隔离/删除。
- 先审后发 or 先发后审（依业务风险）。

## 六、成本与生命周期

- **存储分级**：热数据标准存储，冷数据归档存储（便宜）。
- **生命周期规则**：临时文件 N 天后自动删除，节省成本。
- **CDN 回源优化**：合理缓存策略，降低回源率。

## 七、常见坑

1. **存本地磁盘** → 容量与可用性瓶颈；用对象存储。
2. **服务端中转大文件** → 带宽打满；用预签名直传。
3. **原图无限大** → 存储/流量贵；限尺寸 + 缩略图。
4. **无审核** → 违规内容风险；接入审核。
5. **URL 长期有效** → 盗链/泄露；预签名 + TTL + 防盗链 Referer。
6. **回源率高** → CDN 缓存短；调长缓存 + 版本化文件名。
