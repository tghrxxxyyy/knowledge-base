# 通信带宽分析

> 对应 Alistarh 2017 (QSGD) 与 Narayanan 2021 通信建模。

## 一、背景与挑战
压缩能否提速取决于带宽节省是否超过本地压缩计算。需量化每步通信字节与压缩开销。

## 二、核心原理
比较全精度 all-reduce($32\\Psi$)与压缩后传输(符号/稀疏+索引)。当跨节点 IB 带宽 $B$ 小于压缩节省比时净收益为正。

## 三、形式化与数学基础
净时间：
$ T = \\max\\big(32\\Psi/B,\\; c\\Psi + \\Psi_{\\mathrm{comp}}/B_{\\mathrm{comp}}\\big) $，
其中 $c$ 为压缩后每元素比特(1-bit 为 $1/32$)。收益阈值 $B < 32/c\\cdot B_{\\mathrm{comp}}$。

## 四、代码实现
```python
def net_gain(psi, B_ib, B_comp, c_bits=1):
    t_full = 32 * psi / B_ib
    t_comp = c_bits * psi / B_ib + psi / B_comp   # 压缩计算 + 传输
    return t_full - t_comp
```

## 五、与其他技术对比
节点内 NVLink 带宽高，压缩通常得不偿失；跨节点 IB 下压缩收益显著。TP 的 all-reduce 一般不宜压缩(延迟敏感)。

## 六、常见误区
误区一：压缩总提速——节点内或压缩慢时反降。误区二：只看带宽忽略延迟——小消息延迟主导。误区三：压缩无计算成本。

## 七、与开源书/权威来源对应
Alistarh 2017 QSGD 带宽分析；Narayanan 2021 通信模型；microsoft/DeepSpeed。

## 八、面试题
问：压缩何时有益？答：跨节点低带宽且压缩计算便宜时。问：节点内为何不压？答：NVLink 快，压缩反增延迟。

## 九、演进与趋势
按层敏感度自适应压缩；fp8 原生通信省去软件压缩。

## 十、小结
通信带宽分析决定压缩的性价比，须结合硬件与压缩算子开销评估。
