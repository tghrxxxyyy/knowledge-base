# 多智能体协作 Multi-Agent

> 对应 AutoGen（Wu et al., 2023）、MetaGPT（Hong et al., 2023）、CAMEL（Li et al., 2023）以及「生成式智能体」协作范式。属智能体工程深入板块。

## 一、背景与挑战

单个 Agent 在复杂任务上会遇到「角色冲突」：它既要当规划者，又要当执行者，还要当评审，能力被稀释、上下文被杂糅。多智能体协作的思想：用多个**角色化、专精化**的 Agent 分工协作，如同人类团队。挑战在于：如何设计角色与通信协议、如何避免「群体幻觉」与成本爆炸、如何调度与收敛。

## 二、核心原理

多智能体系统的典型协作模式：
1. **分工流水线**：角色按工序衔接，如「产品经理 → 架构师 → 工程师 → 测试」，每角色只管一段（MetaGPT 的 SOP）。
2. **辩论/评审**：多个 Agent 各自给出方案并互评，通过分歧提升质量（如双人评审、陪审团）。
3. **中心编排（Orchestrator）**：一个调度 Agent 把任务拆给专家 Agent，汇总结果（AutoGen 的 GroupChat）。
4. **开放式协作（CAMEL）**：角色间自发对话推进任务，靠「任务提示器」防跑偏。

协作的关键是**通信协议**：消息格式、共享黑板（blackboard）、以及对「何时停止/汇总」的约定，否则信息在传递中丢失或失真。

## 三、形式化与数学基础

设智能体集合 $\mathcal{A}=\{a_1,\dots,a_n\}$，共享消息历史 $H$。第 $i$ 个 Agent 在轮次 $t$ 基于历史与自身角色 $r_i$ 产生消息：

$$
m_i^{(t)} \sim \pi_{\theta,i}\big(\cdot \mid H^{(t)}, r_i\big)
$$

历史更新 $H^{(t+1)}=H^{(t)}\cup\{m_i^{(t)}\}$。编排器聚合得最终输出：

$$
y = \text{aggregate}\big(\{m_i^{(T_i)}\}_{i=1}^{n}\big)
$$

协作可视为对单 Agent 策略的「分治」：把难任务 $P$ 拆为子任务 $\{P_i\}$，令 $\sum_i \text{cost}(P_i) < \text{cost}(P)$ 且质量提升，等价于用「多样性集成」降低单点偏差方差：

$$
\text{Var}(\bar{y}) = \frac{1}{n^2}\sum_i \text{Var}(y_i) + \frac{n-1}{n}\overline{\text{Cov}}
$$

适度独立（低协方差）时，集成提升稳定性。

## 四、代码实现（AutoGen 风格）

```python
import autogen
assistant = autogen.AssistantAgent("engineer", llm_config=cfg)
critic    = autogen.AssistantAgent("critic",    llm_config=cfg)
group = autogen.GroupChat(
    agents=[assistant, critic],
    messages=[], max_round=8)
mgr = autogen.GroupChatManager(group, llm_config=cfg)
mgr.run("用 Python 写一个快速排序，并评审其边界情况。")
# engineer 产出 -> critic 评审 -> 多轮收敛
```

## 五、与其他技术对比

| 模式 | 通信 | 优势 | 风险 |
|------|------|------|------|
| 单 Agent | 自环 | 简单省成本 | 角色冲突 |
| 分工流水线 | 顺序 | 专精高效 | 单点阻塞 |
| 辩论评审 | 双向 | 质量高 | 成本高、易扯皮 |
| 中心编排 | 星型 | 可控 | 调度瓶颈 |

## 六、常见误区

- 无脑堆 Agent 数量，延迟与 token 成本翻倍，质量却未提升（小任务单 Agent 更优）。
- 通信协议混乱（格式不统一、无终止条件），信息在传递中丢失。
- 所有角色用同模型同提示，只是换名字，未真分工。
- 缺汇总/裁决机制，多个方案无法收敛到最终输出。

## 九、演进与趋势

多智能体从「脚本化 SOP」走向「动态编队」：系统按任务自动组建临时团队；并出现标准化 Agent 间协议（如 A2A、MCP 支撑的发现与调用）。与推理模型结合后，单 Agent 能力增强，使「少而强」逐渐替代「多而杂」。趋势是「人—多 Agent」混合团队、以及把协作过程本身作为可学习对象（元控制器优化谁该在何时发言），在质量、成本、可控间取得平衡。

## 十、小结

多智能体协作通过角色分工、辩论评审与中心编排，把复杂任务拆给专精 Agent，以「多样性集成」降低单点偏差、提升质量。其价值在复杂、需多视角任务上显著，但须防成本爆炸与通信失真。落地关键是清晰的角色定义、统一通信协议与收敛机制；简单任务仍宜用单 Agent 以省成本。
