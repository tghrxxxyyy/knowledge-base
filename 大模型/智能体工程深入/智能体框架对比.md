# 智能体框架对比

> 工程选型参考，综合 LangChain、LlamaIndex、AutoGen、MetaGPT、CrewAI 等主流框架的官方定位与社区实践。属智能体工程深入板块。

## 一、背景与挑战

Agent 生态工具众多，初学者常陷入「选哪个框架」的抉择困难。不同框架的**设计哲学**与**强项**差异明显：有的偏「组件拼装」，有的偏「数据/RAG」，有的偏「多智能体对话」，有的偏「角色化 SOP」。选型错误会导致后期重构成本高。本篇给出横向对比与决策建议。

## 二、核心原理

框架本质是「Agent 能力的封装层」，提供：模型抽象、工具/记忆接口、编排（链/图/对话）、可观测与部署。按定位可粗分为：
- **通用编排型**：把 LLM、工具、记忆、向量库等抽象成可组合组件，适合自建复杂管线。
- **数据/RAG 型**：围绕索引、检索、文档问答优化，适合知识密集型应用。
- **多智能体型**：内置 Agent 间对话与编排，适合协作/辩论场景。
- **角色 SOP 型**：用「岗位 + 标准流程」驱动，适合软件工程等结构化产出。

选型应锚定「任务形态」而非「流行度」。

## 三、形式化与数学基础

设需求向量为 $R=(\text{复杂度},\text{多Agent},\text{RAG比},\text{可控性},\text{上手快})$，各框架映射为能力向量 $C_f$。选型即求匹配度：

$$
f^\* = \underset{f}{\arg\max}\; \text{sim}(R, C_f)
$$

其中 $\text{sim}$ 可为加权余弦。经验权重：通用业务偏「可控性+上手快」，研究原型偏「多Agent+复杂度」。框架也可组合（如用 LlamaIndex 做检索、LangGraph 做编排），并非互斥。

## 六、常见误区

- 认为「一个框架包打天下」，忽视组合使用（如 LlamaIndex+LangGraph）。
- 为简单任务引入重框架，过度工程化。
- 只看文档热度，忽略团队熟悉度与维护成本。
- 把框架当「Agent 智能来源」——智能在模型与编排，框架只是脚手架。

## 八、面试题

- LangChain 与 LlamaIndex 的定位差异？能否组合？
- 何时该用 AutoGen 而非 LangGraph 做多 Agent？
- 框架的「可控性」从哪些机制体现（图、状态、断点）？
- 为什么说「框架不是智能来源」？真正的智能在哪？

## 九、演进与趋势

框架正收敛为「编排 + 协议」两层：上层用图/工作流表达控制流（LangGraph、LlamaIndex Workflows），下层用开放协议接入工具与数据（MCP）。多智能体协议（A2A）使不同框架的 Agent 可互操作。趋势是「轻内核 + 标准协议 + 可观测」，框架差异从「功能多寡」转向「协议开放度与生态」，降低锁定风险。

值得补充的选型检查清单：
- **可观测性**：是否内置轨迹追踪、回放、评测钩子（LangSmith、Phoenix）？
- **中断恢复**：长任务能否暂停/恢复/人工接管（human-in-the-loop）？
- **部署形态**：是否支持编译为独立服务、批处理与流式？
- **社区与版本稳定性**：API 是否频繁破坏性变更，文档是否跟得上？

实践中常见组合是「LlamaIndex 管检索 + LangGraph 管编排 + 自研记忆」，而非绑定单一全家桶。

## 十、小结

智能体框架按定位分为通用编排、数据/RAG、多智能体、角色 SOP 四类，选型应锚定任务形态（复杂度、是否需要多 Agent、RAG 比重、可控性）而非流行度。框架可组合使用，且只是脚手架——真正的智能来自模型、工具与编排设计。趋势是开放协议化与轻内核，降低厂商锁定。
