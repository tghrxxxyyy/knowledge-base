# 规划与任务分解

> 对应 Plan-and-Solve（Wang et al. 2023）、Tree-of-Thoughts（Yao et al. 2023）与 AutoGPT/ BabyAGI 的计划—执行范式。属智能体工程深入板块，讨论 Agent 的核心能力之一。

## 一、背景与挑战

当任务从「单轮问答」变为「多步达成目标」时，盲目行动极易陷入循环或偏离目标。规划（planning）的任务是：在动手前或执行中，把抽象目标拆成可执行、可验证的**子目标序列**。挑战在于：环境可能不确定（结果不可预知）、任务可能很长（需数十步）、且计划在遇到意外时需重新调整（重规划）。

## 二、核心原理

规划范式主要有三类：
1. **一次性计划（Plan-and-Execute）**：先由模型生成完整步骤清单，再逐一执行；适合确定性强、可预测的任务。代表：Plan-and-Solve Prompting。
2. **动态重规划（Re-plan）**：每执行几步后根据观测重新生成剩余计划，适应不确定环境。
3. **探索式规划（Tree-of-Thoughts）**：把推理建模为树，广度/深度搜索多路径并自评剪枝，适合需要「试错探索」的问题（如 24 点游戏、迷宫）。

与 ReAct 的区别：纯 ReAct 边想边做、缺乏显式全局蓝图；规划—执行分离则先有「地图」再走，更适合长任务与可解释性。

## 三、形式化与数学基础

把任务看作在状态空间 $\mathcal{S}$ 中从初始态 $s_0$ 到目标态 $s^*$ 的搜索。计划是一串子目标/动作 $P=(a_1,\dots,a_n)$，智能体最大化到达概率：

$$
\max_{P}\; P\big(s_n=s^* \mid s_0, P, \text{env}\big)
$$

Tree-of-Thoughts 把该过程显式化为树搜索，节点 $v$ 的「前景值」由模型自评 $V(v)$ 给出，并配合广度优先（BFS）或深度优先（DFS）与剪枝：

$$
\text{扩展}(v) \;\text{s.t.}\; V(v) \ge \tau_{\text{keep}}
$$

其中 $\tau_{\text{keep}}$ 为保留阈值，自评估信号替代外部奖励，构成语言模型的「内部搜索」。

## 四、代码实现

```python
def plan_and_execute(goal, llm, env, max_steps=20):
    plan = llm(f"把目标拆为有序步骤：{goal}")   # 一次性计划
    steps = parse_steps(plan)
    trace = []
    for step in steps[:max_steps]:
        obs = env.run(step["action"])
        trace.append((step, obs))
        if not step["check"](obs):               # 子目标未达成
            plan = llm(f"原计划失败，观测：{obs}\n重规划：{goal}")
            steps = parse_steps(plan)             # 动态重规划
    return trace
```

## 五、与其他技术对比

| 策略 | 全局蓝图 | 适应变化 | 成本 | 适用 |
|------|---------|---------|------|------|
| 一次性计划 | 有 | 弱 | 低 | 确定任务 |
| 动态重规划 | 实时更新 | 强 | 中 | 不确定环境 |
| ToT 探索 | 树搜索 | 强 | 高 | 需搜索任务 |
| 纯 ReAct | 无 | 中 | 中 | 中等任务 |

## 六、常见误区

- 计划过细过僵，环境一变即整体失效，缺乏重规划机制。
- 把「列步骤」当作「已验证」，未对每步子目标设可检查断言。
- 过度探索（ToT 全展开）导致成本爆炸，却无剪枝。
- 计划与执行用不同格式/术语，衔接处信息丢失。

## 九、演进与趋势

规划正与「世界模型」「模拟器」结合：Agent 先在内部推演计划后果再执行（如「心智模拟」）。LLM 编译器（LLM Compiler）把计划编译成可并行 DAG，提升效率；多智能体中「规划者角色」专门产出并维护共享计划。趋势是从「文本计划」走向「结构化、可校验、可回滚的执行图」，使长程任务更可靠、可观测、可中断恢复。

工程落地补充：
- **计划粒度**：以「一个可验证子目标」为单位，而非「一句话动作」。
- **预算感知**：为规划本身设 token/步数上限，防止「过度思考」挤占执行。
- **回滚点**：在关键子目标后打检查点，失败可从最近检查点重规划而非从头开始。

## 十、小结

规划与分解是 Agent 处理长程、不确定任务的核心能力。一次性计划适合确定性任务，动态重规划适应变化，Tree-of-Thoughts 用搜索应对需探索问题。关键是为子目标设可检查断言并支持重规划，避免把「列出步骤」误当「已达成」。它与 ReAct 互补，常组合成「先规划、再执行、遇变重规划」的稳健闭环。
