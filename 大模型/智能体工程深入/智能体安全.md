# 智能体安全

> 对应 OWASP Top 10 for LLM Applications 与 NIST AI Risk Management Framework 中关于 Agent 风险的部分；并参考「安全与对齐深入」板块。属智能体工程深入板块，此处从 Agent 工程视角摘要。

## 一、背景与挑战

纯生成式 LLM 的风险主要是「说错话」；而 Agent 因具备**工具调用能力**，风险从「文本」跃迁到「动作」——它能读文件、发请求、执行代码、转账、发邮件。一个被诱导的 Agent 可能造成真实世界损害。最具代表性的新威胁是**提示注入（prompt injection）**：攻击者把恶意指令藏进 Agent 检索到的网页、邮件或工具返回中，劫持其原本目标。Agent 安全的核心挑战是：在模型本身不可完全信任的前提下，如何构建「纵使被注入也不致灾」的系统护栏。

## 二、核心原理

Agent 安全遵循「纵深防御（defense in depth）」原则，在多个层面设防：
1. **权限最小化**：每个工具仅授予必要权限，敏感操作（删除、外发、支付）默认关闭或需审批。
2. **调用确认**：高风险动作（high-impact action）强制人工确认或二次校验。
3. **沙箱隔离**：代码执行、命令运行放在受限容器，限制网络与文件系统访问。
4. **输入净化**：对检索内容、工具返回做标记（如区分「不可信外部数据」与「系统指令」），降低注入成功率。
5. **行为审计与熔断**：记录完整轨迹，对异常模式（高频外发、越权访问）触发熔断。

其设计哲学是：不应假设模型「永远听话」，而要让危险动作在系统层就难以发生。

## 三、形式化与数学基础

把 Agent 策略视为在状态 $s$ 下选择动作 $a\in\mathcal{A}$ 的分布 $\pi(a\mid s)$。安全约束引入**不可行动作集** $\mathcal{A}_{\text{block}}(s)$ 与**需确认集** $\mathcal{A}_{\text{confirm}}(s)$：

$$
\pi_{\text{safe}}(a\mid s)=
\begin{cases}
0, & a\in\mathcal{A}_{\text{block}}(s)\\[4pt]
\text{human}(s), & a\in\mathcal{A}_{\text{confirm}}(s)\\[4pt]
\pi(a\mid s), & \text{otherwise}
\end{cases}
$$

对提示注入可建模为环境对观测的污染：$o' = o \oplus \text{inject}(\text{malicious})$，防御目标是让策略对 $o'$ 的敏感度为 0，即 $\pi(a\mid s,o)\approx\pi(a\mid s,o')$ 于关键动作。这等价于提升指令—数据与权限的隔离度。

## 四、代码实现

```python
RISKY = {"delete_file", "send_email", "transfer", "exec_code"}

def safe_dispatch(action, args, need_human_confirm):
    if action in RISKY:
        if not need_human_confirm(action, args):   # 人工/策略网关
            return {"ok": False, "reason": "需人工确认"}
        if not permission_check(action, args):     # 权限最小化校验
            return {"ok": False, "reason": "权限不足"}
    return sandbox_run(action, args)               # 沙箱内执行
```

## 五、与其他技术对比

| 防线 | 位置 | 挡得住注入吗 | 代价 |
|------|------|------------|------|
| 提示词加固 | 模型输入 | 部分 | 低 |
| 权限最小化 | 系统层 | 强 | 中 |
| 沙箱 | 执行层 | 强 | 中 |
| 人工确认 | 决策层 | 最强 | 高（断自动化） |

单一防线都不够，需组合；「零信任」是 Agent 安全的默认姿态。

## 六、常见误区

- 以为「模型足够强就不会被注入」：注入利用的是指令与数据混淆，与能力无关。
- 把工具返回当可信内部数据，未做隔离标记。
- 只在提示里写「不要做危险事」，却未在执行层拦截。
- 记录轨迹但不审计，事后无法归因与复盘。
- 把「确认」做成「一键全同意」，形同虚设，未对动作分级。
- 信任边界画错：把不可信的外部内容直接拼进系统提示，反而放大注入面。

## 九、演进与趋势

Agent 安全正从「事后加固」走向「架构内建」：工具调用默认走权限网关、不可信内容强制隔离标签、沙箱成为标配。行业出现「Agent 防火墙」「策略即代码」等概念，并有基准（如 AgentDojo）评测抗注入能力。随多智能体与自主 Agent 普及，安全重点将转向「Agent 间的信任与授权传播」以及「长期自主运行的可控收敛」。

## 十、小结

Agent 因能调用工具，风险从文本升级为动作，提示注入是头号威胁。安全不能依赖模型自觉，而要靠权限最小化、沙箱、调用确认与审计等系统层纵深防御。核心原则是「零信任」：即使被注入，危险动作也应难以发生。这与「安全与对齐深入」板块互补，本篇聚焦工程落地。
