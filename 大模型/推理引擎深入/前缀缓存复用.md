# 前缀缓存复用

> 对应 llm-course（mlabonne）推理优化章节；SGLang RadixAttention（Zheng et al., 2024）；vLLM 自动前缀缓存（Automatic Prefix Caching）（以官方最新文档为准）。

## 一、背景与挑战

大模型推理中，多个请求常共享同一段前缀：系统提示（system prompt）、Few-shot 示例、长文档上下文、固定指令模板。若每个请求都重新计算这段前缀的 KV 缓存（prefill），会：

- 重复消耗算力：相同 token 被多次前向。
- 抬高首 token 延迟（TTFT）：长系统提示尤其明显。
- 浪费显存：相同 KV 被多份冗余存储。

挑战在于：前缀可能任意长、共享模式动态变化，需高效识别可复用块并管理其生命周期。

## 二、核心原理

前缀缓存复用（Prefix Caching）核心是「计算一次、多处复用」：

1. 哈希标识：用前缀 token 序列的哈希（或 Radix 树路径）作为缓存键。
2. 命中复用：新请求若前缀命中，直接取已算 KV，跳过对应 prefill。
3. 树状组织：SGLang 用 RadixAttention 以基数树（radix tree）管理前缀，能表达「共享前缀 + 分叉」的共享结构。
4. 淘汰策略：显存紧张时按 LRU 等策略驱逐低频前缀。

收益与「共享长度 × 命中请求数」成正比；在大量请求共用同一系统提示的场景（如多轮对话、批量文档 QA）收益最大。

## 三、形式化与数学基础

设请求 $r$ 的前缀 token 为 $p_r$，已有缓存集合 $K$。命中则节省 prefill 计算量正比于

$$ \text{save}(r) = |p_r \cap k^*|\cdot C_{\text{step}},\quad k^*=\arg\max_{k\in K} |p_r \cap k| $$

其中 $|\cdot|$ 为可复用 token 数，$C_{\text{step}}$ 为单 token 单层注意力算力。缓存命中率：

$$ h = \frac{1}{N}\sum_{r=1}^{N} \mathbb{I}[p_r \in K] $$

Radix 树把 $h$ 在共享结构上的复用率进一步放大。

## 四、代码实现

```python
# 前缀缓存命中示意（伪代码）
class PrefixCache:
    def __init__(self):
        self.store = {}   # key: 前缀哈希 -> KV 块

    def lookup(self, prefix_tokens):
        key = hash(tuple(prefix_tokens))
        return self.store.get(key)   # 命中返回 KV，否则 None

    def put(self, prefix_tokens, kv):
        key = hash(tuple(prefix_tokens))
        self.store[key] = kv

# 推理时优先复用
kv = cache.lookup(req.prefix)
if kv is not None:
    reused = True                 # 跳过 prefill 对应段
else:
    kv = model.prefill(req.prefix)
    cache.put(req.prefix, kv)
```

## 五、与其他技术对比

| 技术 | 复用对象 | 触发 | 收益 |
|------|----------|------|------|
| 静态缓存 | 固定系统提示 | 手动 | 有限 |
| 自动前缀缓存(vLLM) | 任意命中前缀 | 自动 | 高 |
| RadixAttention(SGLang) | 树状共享前缀 | 自动 | 最高 |

Radix 树适合「前缀分叉多」的结构化程序。

## 六、常见误区

- 短提示无所谓：系统提示一旦变长，复用收益指数上升。
- 缓存越多越好：显存有限，需合理淘汰避免挤占生成 KV。
- 忽略前缀哈希冲突：需保证哈希唯一或带长度校验。

## 九、演进与趋势

无缓存 → 手动固定系统提示缓存 → 自动前缀缓存（哈希命中）→ Radix 树共享前缀 → 与 PagedAttention、连续批处理协同。趋势是把「前缀复用」作为推理引擎默认能力，并与 KV 量化结合进一步省显存。

## 十、小结

前缀缓存复用是高并发服务的性价比之王：在「多请求共享长前缀」场景下，以极小工程代价显著降低 TTFT 与算力浪费，是吞吐优化第一道关口。
