# 前缀缓存复用

> 见「推理引擎深入/PagedAttention深入」与「上下文工程深入」。

## 一、背景与挑战

多请求共享系统提示/长上下文，重复计算浪费。

## 二、核心原理

缓存已计算的 KV 前缀（RadixAttention/自动前缀），新请求命中即复用，省 prefill。

## 三、关键要点

- 共享越长收益越大。
- 需管理缓存淘汰。

## 四、代码实现

```python
kv = radix.get(prefix_hash); if kv: reuse(kv)
```

## 五、与其他对比

- 每次重算贵；复用省时。

## 六、常见误区

- 仅短提示无所谓——长系统提示收益大。

## 七、与开源书对应
