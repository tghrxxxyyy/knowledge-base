# 激活修补（Activation Patching）

> 对应 Meng et al., *Locating and Editing Factual Associations*, 2022；Goldowsky-Dill et al., 2020。

## 一、背景与挑战

如何确定"是哪个位置的激活导致了某输出差异"？激活修补提供受控对照。

## 二、核心原理

取两个输入（基线/目标）跑前向，记录各层激活；把目标在某处的激活替换进基线运行，若输出变向目标，则该处对该行为因果重要。常用 corrupted/clean 对。

## 三、数学形式

修补响应 $R(h_i) = \text{acc}(M_{patch(i)}(x_{clean},x_{corr})) - \text{acc}(M(x_{corr}))$；高 $R$ 即关键节点。

## 四、代码实现

```python
clean, corr = run_pair(model, prompt_a, prompt_b)
for (l, name) in nodes:
    with patch_act(model, l, name, clean[l, name]):
        out = model(corr)
    log_patch[(l, name)] = score(out)
```

## 五、与其他对比

- 与 事实关联回路 衔接（ROME 用其定位）。
- 与 因果干预总览 共享基础。

## 六、常见误区

- 只做单层单点修补，遗漏分布式贡献。
- 修补顺序/残差叠加导致非线性交互被忽略。

## 八、面试题

- 激活修补怎么做？答：记录 clean/corr 激活，把 clean 处激活补进 corr 运行，看输出是否变 clean。

## 九、演进

单点修补 → 组件级 → 因果图自动定位。

## 十、小结

激活修补是定位因果节点的最常用工具，clean/corr 对照是关键。
