# 上下文窗口扩展

> 对应 RoPE 外推（Su et al., 2021）、ALiBi（Press et al., 2021）、位置插值 PI（Chen et al., 2023）与 YaRN（Peng et al., 2023）；亦见本系列「旋转位置编码 RoPE」「位置外推方法对比」。

## 一、背景与挑战

模型训练时的最大序列长度（如 4096）即其上下文窗口。当推理或继续训练需要超越该长度时，朴素做法会让位置编码落入未训练区域，导致性能崩塌。上下文窗口扩展要回答两个问题：

1. **能否外推**：已训练权重能否处理更长位置（位置编码层面的问题）。
2. **能否装下**：长序列的 KV Cache 与注意力计算在显存/算力上是否可行（系统层面的问题）。

本篇聚焦前者（位置编码改造），后者见「注意力复杂度与优化」「FlashAttention」。

## 二、核心原理

- **位置插值 PI**：把新位置索引线性压缩回训练区间 $[0,L)$，使注意力落在已训练分布内。
- **NTK-aware 缩放**：不均匀地把缩放分配到各频率维度，保护低频全局结构、压缩高频局部细节。
- **YaRN / Dynamic NTK**：在 NTK 基础上结合注意力温度与高频保护，长文本更稳；Dynamic 在推理期随长度动态调因子。
- **ALiBi**：注意力分数加随距离线性衰减的偏置，天然支持外推，无需位置编码改造。

## 三、形式化与数学基础

线性位置插值：若原训练长度 $L$，目标 $L'>L$，对位置 $m$：

$$
m' = m\cdot\frac{L}{L'}
$$

NTK 把整体缩放拆成逐频率维度系数，对第 $d$ 维频率 $\theta_d$ 施加缩放：

$$
\theta_d' = \theta_d \cdot \alpha_d,\quad \alpha_d \text{ 随维度非均匀}
$$

YaRN 同时引入缩放因子 $s$ 与注意力温度 $t=0.1\ln s+1$，对注意力 logits 做再缩放以恢复被插值压低的高频幅度。

## 四、代码实现

以 HuggingFace 启用长窗口（YaRN）为例：

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-7b-hf",
    rope_scaling={
        "type": "yarn",
        "factor": 8.0,                              # 窗口扩到约 8 倍（32K）
        "original_max_position_embeddings": 4096,
    },
    torch_dtype="auto",
)
tok = AutoTokenizer.from_pretrained("meta-llama/Llama-2-7b-hf")
ids = tok("长文档..." * 5000, return_tensors="pt").to("cuda")
out = model.generate(**ids, max_new_tokens=128)
```

免训练外推适合快速验证；要稳定长上下文通常需配合继续训练。

## 五、与其他技术对比

| 方法 | 是否需重训 | 外推能力 | 备注 |
|------|-----------|----------|------|
| PI/NTK | 轻量继续训练 | 中 | 简单有效 |
| YaRN | 轻量 | 强 | 当前主流 |
| ALiBi | 否 | 强 | 需架构支持 |
| RoPE 直接外推 | 否但易崩 | 弱 | 不推荐 |

## 六、常见误区

- **直接外推 RoPE 即可**：超出训练位置后旋转角度落在未训练区间，长程检索准确率骤降。
- **外推倍数越大越好**：超过数十倍后即使 YaRN 也需继续训练巩固。
- **只改位置编码不优化显存**：长序列 KV Cache 爆显存，仍需分页/量化。
- **混淆窗口扩展与长程能力**：能装下不等于能用好，注意力稀释问题仍在。

## 九、演进与趋势

- **免训练 → 轻量继续训练**：先缩放验证，再长序列巩固。
- **动态缩放**：推理期按实际长度动态选择因子（Dynamic NTK）。
- **与 KV 压缩协同**：外推解决「能否看」，KV 压缩解决「能否装」。
- **架构内建外推**：ALiBi 类偏置让训练期即具备外推性。

## 十、小结

上下文窗口扩展本质是「位置编码改造 + 系统优化」的组合。RoPE 系靠 PI/NTK/YaRN 缩放实现免训练扩容，ALiBi 靠距离偏置天然外推；但倍数过大终需继续训练兜底，并与 KV 压缩协同解决显存。具体倍率与参数以官方最新文档为准。
