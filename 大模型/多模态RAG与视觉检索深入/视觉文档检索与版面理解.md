# 视觉文档检索与版面理解

> 对应 huggingface/transformers 文档理解模型与 microsoft/graphrag 结构化思路及 run-llama/llama_index。

## 一、背景与挑战
PDF、扫描件、带表格/图表的文档难以用纯文本分块。视觉文档检索需理解版面（标题、表格、图注）才能精准定位证据。

## 二、核心原理
先用版面分析（OCR + 区域检测）把页面拆为带类型的区域（段落/表/图），对各区域做多模态编码并建立索引。检索时按区域粒度召回，保留版面上下文。

## 三、形式化与数学基础
页面 P 分解为区域集合 $R(P)=\{r_k\}$，每区域带类型 $t_k$ 与嵌入 $e_k$。检索得分含类型偏置：
$s(q, r_k) = \text{sim}(E_q(q), e_k) + \lambda \cdot \mathbb{1}[t_k \in T_{\text{rel}}]$
$T_{\text{rel}}$ 为与查询相关的类型集合（如表格类查询更看重表区域）。

## 四、代码实现
```python
def layout_retrieve(q, regions, enc, T_rel, lam=0.3):
    scored = []
    for r in regions:
        s = cos(enc(q), r.emb) + lam * (r.type in T_rel)
        scored.append((r, s))
    return sorted(scored, key=lambda x: -x[1])
```

## 五、与其他技术对比
相比纯文本 OCR 后分块，版面感知检索避免表格/图注被切断，定位更准；代价是需要版面模型与更复杂索引。

## 六、常见误区
误区一：OCR 文本足够，忽视图表中的视觉信息。误区二：把整页当一块，丢失细粒度定位。

## 七、与开源书/权威来源对应
- huggingface/transformers 提供文档/版面模型（如 LayoutLM 思路）。
- microsoft/graphrag 体现结构化抽取价值。
- run-llama/llama_index 支持多模态索引。

## 九、演进与趋势
端到端视觉语言模型直接读取页面图像并定位证据，减少 OCR 错误传播，并与图谱结合抽取表格关系。

## 十、小结
版面理解让 RAG 扩展到扫描件与复杂文档，是多模态落地的关键能力。
