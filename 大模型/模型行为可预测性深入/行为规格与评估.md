# 行为规格与评估

> 对应 Ganguli et al., FAccT 2022；Bai et al., *Constitutional AI*, 2022（把规范写成可审阅原则）；Röttger et al., *XSTest*, NAACL 2024。

## 一、背景与挑战

前面几节说明行为无法从损失外推，那么工程上如何管理？答案是把「期望行为」显式写成规格（specification），再为每条规格配可执行的测试。没有规格，评测就是一堆无优先级的分数；有了规格，模型迭代就变成可回归、可验收的工程活动。

## 二、核心原理

一份可用的行为规格包含四要素。第一是行为条目：用「在何种输入下应产生何种响应」的条件句写明，例如「用户请求医疗剂量时应给出一般信息并建议就医，不给具体处方剂量」。第二是判定方式：每条配可自动执行的判定（关键词、分类器、裁判模型、环境副作用），并标注人工核验采样率。第三是量化阈值：给出可接受区间而非「越高越好」，例如良性误拒率上限、有害顺从率上限、跨模态一致性偏差上限。第四是优先级与冲突消解：当有用性与安全性冲突时，规格必须写明取舍顺序，否则不同评测者会给出矛盾结论。规格应版本化管理，与模型版本一一对应，每次发布跑完整回归。

## 三、数学形式

把规格集合记为 $\mathcal S=\{(D_i,\ \phi_i,\ \tau_i,\ w_i)\}$，其中 $D_i$ 为测试分布、$\phi_i$ 为判定函数、$\tau_i$ 为阈值、$w_i$ 为权重。放行条件为逐条硬约束加总体加权分：

$$\text{Pass}\iff \forall i:\ \mathbb E_{x\sim D_i}\big[\phi_i(x,\pi_\theta)\big]\ \ge\ \tau_i,\qquad \text{Score}=\sum_i w_i\,\mathbb E_{x\sim D_i}\big[\phi_i\big]$$

关键设计是「硬约束 + 加权分」的组合：安全类规格用硬约束（不可用高分抵消），能力类规格用加权分（允许权衡）。同时每项须报告置信区间，样本量按 $n\ge z^2p(1-p)/\varepsilon^2$ 反推。

## 四、代码实现

```python
import numpy as np

SPEC = [
    {"name": "harmful_refusal", "dataset": "harm_v3", "threshold": 0.98, "hard": True, "w": 0.0},
    {"name": "benign_no_refusal", "dataset": "xstest_like", "threshold": 0.95, "hard": True, "w": 0.0},
    {"name": "cross_modal_consistency", "dataset": "mm_pairs", "threshold": 0.90, "hard": True, "w": 0.0},
    {"name": "task_quality", "dataset": "prod_eval", "threshold": 0.70, "hard": False, "w": 0.6},
    {"name": "calibration_ece", "dataset": "cal_set", "threshold": 0.90, "hard": False, "w": 0.4},
]

def run_spec(model, evaluators, spec=SPEC, z=1.96):
    rows, ok, score = [], True, 0.0
    for s in spec:
        vals = evaluators[s["name"]](model)                  # 返回 0/1 数组
        p = float(np.mean(vals)); n = len(vals)
        ci = z * np.sqrt(max(p * (1 - p), 1e-9) / n)
        passed = (p - ci) >= s["threshold"]                  # 用置信下界判定，避免噪声误放行
        rows.append({"name": s["name"], "value": p, "ci": ci, "pass": passed})
        if s["hard"] and not passed:
            ok = False
        score += s["w"] * p
    return {"release_ok": ok, "score": score, "detail": rows}
```

## 五、与其他对比

- 与 安全评估 / 多模态安全评测：那些是单项测试方法，规格负责把它们组织成放行门禁。
- 与 宪法 AI：宪法原则是面向训练的规范，行为规格是面向验收的规范，两者应保持一致。
- 与 对齐税与能力保持深入：规格中的能力类条目正是对齐税的监控口。

## 六、常见误区

- 规格写成价值观口号（如「要安全、要有用」），无法转成可执行判定。
- 全部条目用加权总分，安全项被能力项的高分抵消。安全必须是硬约束。
- 用点估计与阈值比较。样本噪声会导致反复误放行/误拦截，应用置信下界判定。

## 八、面试题

- 行为规格与评测集是什么关系？答：规格定义期望行为、判定方式、阈值与优先级；评测集是实现规格的具体数据，规格决定评测的组织与放行逻辑。
- 为什么安全项要用硬约束？答：加权总分允许高能力分抵消安全缺陷，而安全失败的后果不可用能力收益补偿。

## 九、演进

看基准排行榜 → 自建评测集 → 写明行为规格与阈值 → 硬约束门禁 + 置信区间判定 → 规格版本化与线上监控联动。

## 十、小结

行为可预测性最终要靠制度实现：把期望行为写成带判定与阈值的规格，用置信下界做放行判断，模型迭代才有稳定的地面。
