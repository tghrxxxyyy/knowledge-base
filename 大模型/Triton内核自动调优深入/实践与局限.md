# Triton实践与局限

> 对应 Triton 在生产部署的注意事项。

## 一、背景与挑战

Triton 并非万能，需知适用范围与坑。

## 二、核心原理

适合 elementwise/reduction/融合 GEMM；对复杂控制流、跨 block 依赖、极致峰值仍弱；需固定 shape 或用 autotune 覆盖变种。

## 三、数学形式

适用域 $D=\{kernel:\text{tilable}\land \text{no cross-block dep}\}$；超出则退回 CUDA。

## 四、代码实现

```python
if needs_custom_sync:
    use_cuda()   # Triton 不擅长
```

## 五、与其他对比

- 与 推理CUDA图优化深入：Triton kernel 可入图。
- 与 张量核心与混合精度推理深入：自动走 TC。

## 六、常见误区

- 用 Triton 实现强依赖图（如某些稀疏）低效。
- 忽视编译器版本差异致性能漂移。

## 八、面试题

- Triton 何时不合适？答：复杂跨块依赖/极致峰值/特殊同步场景，宜用 CUDA。

## 九、演进

通用内核 → 专用 Triton lib → 与编译栈融合。

## 十、小结

Triton 覆盖主流融合内核且高效，边界场景仍需 CUDA。
