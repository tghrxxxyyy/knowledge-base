# 查询理解在检索链路

> 对应 end-to-end query understanding + retrieval；与 RAG 检索链路衔接。

## 一、背景与挑战

查询理解处于链路起点，错误向下游放大。

## 二、核心原理

顺序：纠错→意图→实体/槽位→扩展/改写→检索（稠密/混合/迟交互）→重排；每步可并行多路。

## 三、数学形式

$RAG(q)=\text{Gen}(\text{Rerank}(\text{Retrieve}(\text{QU}(q))))$；QU 含前述子模块。

## 四、代码实现

```python
u = understand(q)              # 意图+实体+扩展
cands = hybrid(u.rewritten, 200); top = rerank(q, cands, 8)
```

## 五、与其他对比

- 与 查询改写与扩展深入（改写在 QU 内）共享。
- 与 检索器训练深入（理解影响训练目标）衔接。

## 六、常见误区

- 模块顺序错（如重排后再纠错无效）。
- 各环节无统一表示致割裂。

## 十、小结

查询理解串联检索前处理，是 RAG 召回到生成的质量起点。
