# 模型量化与压缩进阶实战

> 大模型落地的第一道坎是"太大跑不动"。量化（降低数值精度）、剪枝、蒸馏、稀疏化把模型压小、提速、降显存，让模型能上边缘、降成本。核心是"压多少、掉多少精度"的权衡工程。

## 1. 压缩手段对比

| 手段 | 原理 | 收益 |
| --- | --- | --- |
| 量化 | FP16/BF16/INT8/INT4 | 显存/带宽省 |
| 剪枝 | 去冗余权重/通道 | 计算减 |
| 蒸馏 | 小模型学大模型 | 能力保 |
| 稀疏 | 结构化稀疏计算 | 加速 |

## 2. 量化等级

```text
FP32 (1.0x) → FP16/BF16 (0.5x) → INT8 (0.25x) → INT4 (0.125x)
精度损失: 低 → 中 → 明显需校准 → 明显
```

- **PTQ（训练后量化）**：直接量化，快、免训练，需校准集。
- **QAT（量化感知训练）**：训练中模拟量化，精度更好。

## 3. 实践要点

- **校准集**：代表真实分布，避免离群值破坏量化。
- **混合精度**：敏感层（如 attention）保留高精度。
- **KV Cache 量化**：推理时显存大头，量化收益大。
- **硬件对齐**：不同芯片对 INT4 支持不同，需验证。

## 4. 评估

- 量化后跑基准，确认掉点可接受。
- 端到端延迟/吞吐/显存实测。
- 边缘端重点看内存占用与功耗。

## 5. 常见坑

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 掉点严重 | 答错 | 混合精度 |
| 校准不当 | 离群破坏 | 好校准集 |
| 硬件不支持 | 不加速 | 验证后端 |
| 仅看大小 | 忽略延迟 | 端到端测 |
| KV 未量化 | 显存仍高 | 连同量化 |

## 7. 小结

模型压缩 = 量化为主 + 剪枝/蒸馏/稀疏辅助。核心是"用校准和混合精度保精度，用端到端实测验证收益"。
