# 检索增强推荐

> 对应 github facebookresearch/faiss 项目与 Lewis 2020 的 RAG 论文。

## 一、背景与挑战
纯生成或排序模型受限于参数容量，难覆盖全量物品。检索增强先召回候选再精排，兼顾规模与精度。

## 二、核心原理
用用户与物品向量在 FAISS 等索引中近邻检索得到候选集，再交给精排模型或大模型重排，形成召回-排序两段式。

## 三、形式化与数学基础
近邻召回：
$ \mathcal{N}(u)=\{i : s(u,i)\ge \tau\} $
其中 $ s $ 为向量相似度阈值。

## 四、代码实现
```python
import numpy as np

def recall(index, u_vec, k=200):
    d, i = index.search(u_vec.reshape(1, -1), k)
    return i[0]

def rerank(model, user, items):
    return sorted(items, key=lambda it: model(user, it), reverse=True)[:10]

def two_stage(index, model, u_vec):
    cands = recall(index, u_vec)
    return rerank(model, u_vec, cands)
```

## 五、与其他技术对比
相比端到端生成，检索增强可服务亿级物品；相比纯向量召回，精排提升相关性与多样性。

## 六、常见误区
索引未及时更新导致陈旧召回。召回与精排目标不一致引发断层。
