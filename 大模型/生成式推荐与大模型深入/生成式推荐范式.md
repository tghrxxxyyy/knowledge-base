# 生成式推荐范式

> 对应 github huggingface/transformers 项目与 Vaswani 2017 的 Transformer 论文。

## 一、背景与挑战
传统推荐是打分排序，难以建模多样兴趣与组合偏好。生成式推荐把候选生成视为序列生成，可直接产出物品序列或下一步交互。

## 二、核心原理
将用户历史交互编码为 token 序列，自回归生成下一个或一组物品 ID。相比 pointwise 打分，生成式天然支持集合级偏好。

## 三、形式化与数学基础
生成式推荐似然：
$ p(I_{t+1}|H)=\prod_i p(i_i | H, i_{<i}) $
其中 $ H $ 为历史，$ I $ 为待生成物品序列。

## 四、代码实现
```python
import torch

def gen_rec(model, hist_ids, k=10):
    ids = list(hist_ids)
    for _ in range(k):
        logits = model(ids)[-1]
        nxt = int(logits.argmax())
        if nxt == 0:
            break
        ids.append(nxt)
    return ids[len(hist_ids):]

def encode_hist(items, vocab):
    return [vocab[i] for i in items]
```

## 五、与其他技术对比
相比 DIN/DeepFM 等排序模型，生成式更利于探索与多样性；但推理成本与候选去重是挑战。

## 六、常见误区
把生成物品当排序结果直接展示。未去重导致重复推荐。

## 八、面试题
问：生成式相比排序式推荐优势？答：集合级建模、兴趣多样性与端到端可学习。

## 九、演进与趋势
物品语义 ID、多模态生成式召回与实时自适应。

## 十、小结
生成式把推荐重构为序列生成问题，打开新范式。
