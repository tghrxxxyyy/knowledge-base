# 混合精度FP16与BF16原理

> 对应 pytorch/pytorch `torch.amp` 混合精度实践与 NVIDIA/TensorRT-LLM 精度配置。

## 一、背景与挑战

纯 FP32 训练的瓶颈有两个：张量核在 FP32 下吞吐远低于 FP16/BF16；激活、梯度、优化器状态的访存量与显存占用约为低精度的两倍。混合精度用低精度承载计算与存储、用 FP32 保存主权重与优化器状态，在几乎不损失收敛性的前提下提升速度并降低显存。

挑战在于：FP16 与 BF16 的失效模式不同。FP16 的敌人是**下溢**（梯度归零）与**溢出**（激活变 inf）；BF16 的敌人是**分辨率不足**（小更新被舍入吃掉）。因此两种格式需要不同的护栏。

## 二、核心原理

混合精度维护两份参数：

- 低精度副本 $\theta_{lp}$：用于前向/反向的矩阵运算，享受张量核加速；
- FP32 主副本 $\theta_{fp32}$：接收还原后的梯度做更新，避免长期累积误差。

每步流程为：把 $\theta_{fp32}$ cast 为 $\theta_{lp}$ → 低精度前向 → 低精度反向得梯度 → 梯度转 FP32 → 优化器在 FP32 主副本上更新。FP16 还需在反向中做 loss 缩放以对抗下溢；BF16 因范围充足通常省略该步。

autocast 负责按算子决定精度：矩阵乘/卷积降精度，归约与超越函数维持 FP32。

## 三、形式化与数学基础

FP16：$1+5+10$，最大规格化数约 $6.5\times10^{4}$，最小正规数约 $6.1\times10^{-5}$。
BF16：$1+8+7$，最大规格化数约 $3.4\times10^{38}$，最小正规数约 $1.2\times10^{-38}$。

参数更新在 FP32 上执行：

$$ \theta^{(t+1)}_{fp32} = \theta^{(t)}_{fp32} - \eta\,\mathrm{cast}_{fp32}\!\left(g^{(t)}_{lp}\right) $$

FP16 路径加缩放：

$$ g_{lp} = \frac{1}{S}\,\mathrm{cast}_{lp}\!\left(S \cdot g_{fp32}\right) $$

其中 $S$ 由动态缩放器自适应。若不做缩放，当 $|g| < 6.1\times10^{-5}$ 时梯度在 FP16 中变为 0，参数停止更新——这就是 FP16 必须配 GradScaler 的原因。

## 四、代码实现

```python
import torch

# 推荐模板：BF16 计算 + FP32 主权重（无需 scaler）
def train_bf16(model, opt, loader):
    for x, y in loader:
        opt.zero_grad(set_to_none=True)
        with torch.autocast(device_type="cuda", dtype=torch.bfloat16):
            loss = model(x, y).loss
        loss.backward()
        opt.step()

# FP16 模板：必须使用 GradScaler 防止梯度下溢
def train_fp16(model, opt, loader):
    scaler = torch.amp.GradScaler("cuda")
    for x, y in loader:
        opt.zero_grad(set_to_none=True)
        with torch.autocast(device_type="cuda", dtype=torch.float16):
            loss = model(x, y).loss
        scaler.scale(loss).backward()
        scaler.unscale_(opt)
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        scaler.step(opt)
        scaler.update()
```

模型侧只需保证参数为 FP32，`autocast` 会在算子级完成 cast，无需手改层定义。

## 五、与其他技术对比

| 维度 | FP32 | FP16 + AMP | BF16 + AMP |
| --- | --- | --- | --- |
| 张量核吞吐 | 基线 | 高 | 高 |
| 动态范围 | 大 | 窄，易溢出 | 与 FP32 同 |
| 分辨率 | 高 | 较高 | 较低 |
| 梯度下溢风险 | 无 | 高，需缩放 | 低 |
| 是否需 GradScaler | 否 | 是 | 通常否 |
| 硬件要求 | 通用 | 较广 | 较新架构更友好 |

## 六、常见误区

- 认为 BF16 全面优于 FP16：BF16 分辨率低，对需要精细累积的算子不利。
- BF16 下仍加 GradScaler：浪费范围且无收益。
- 忘记主权重 FP32：直接 update 低精度参数会因舍入而停滞。
- 对 layer norm、loss 强制低精度：归约误差被放大。
- 以为 autocast 全局生效：它只覆盖注册算子，自定义 kernel 不受管。

## 七、与开源书·权威来源对应

pytorch/pytorch 的 `torch.amp` 文档描述 autocast 算子分派与 GradScaler 状态机；NVIDIA/TensorRT-LLM 精度章节给出 BF16/FP16/FP8 的选型与实现建议。具体默认值与支持范围以官方最新文档为准。

## 八、面试题

- 问：混合精度为何要保留 FP32 主权重？答：避免低精度舍入导致的小更新丢失与累积误差。
- 问：BF16 与 FP16 如何选？答：大模型与支持 BF16 的加速器优先 BF16，范围安全、免缩放。
- 问：autocast 决定精度的粒度？答：算子级，而非张量级或全局级。
- 问：FP16 训练必配什么？答：GradScaler（动态 loss scaling）。

## 九、演进与趋势

FP8（E4M3/E5M2）配合细粒度缩放逐步进入训练与推理；编译器层面的自动精度调度（按张量/按区域）持续演进；与张量并行、序列并行结合时需统一各卡的精度策略。支持情况以官方最新文档为准。

## 十、小结

混合精度的本质是「低精度计算、高精度累加、FP32 主权重」。BF16 胜在范围、省去缩放；FP16 胜在分辨率、但必须有 GradScaler 护航。
