# 混合精度与梯度累积协同

> 对应 microsoft/DeepSpeed 的梯度累积与混合精度文档，以及 pytorch/pytorch 的 autocast 教程。

## 一、背景与挑战

显存不足以支撑目标全局批大小时，梯度累积（gradient accumulation）用 $K$ 个 micro-batch 逼近一次大 batch 更新；混合精度则进一步压缩显存与加速。二者叠加后出现三个必须协调的问题：累积期的 dtype（低精度累加会不会丢小梯度）、缩放器的调用时机（一个累积周期只 step 一次）、以及 loss 的归一化（是否除以 $K$）。

处理不当的典型症状是：等效学习率被隐式放大 $K$ 倍导致训练不稳，或梯度在低精度累加中逐渐归零。

## 二、核心原理

梯度累积利用梯度的线性性：先对 micro-batch 求平均再更新，等价于拼接成大 batch 后求梯度。

$$ \nabla_\theta L_{\text{batch}} = \frac{1}{K}\sum_{k=1}^{K} \nabla_\theta L_k $$

协同要点：

1. 每个 micro-batch 的 loss 除以 $K$，使累积梯度量级与真实大 batch 一致；
2. 反向累积写在参数 `.grad` 中，PyTorch 按参数 dtype 累加，因此主权重为 FP32 时累加也是 FP32；
3. `GradScaler` 每个累积周期只 `step`/`update` 一次，中间步只 `backward`；
4. 梯度裁剪放在缩放还原之后、`step` 之前。

## 三、形式化与数学基础

设 micro-batch 梯度 $g_k$，累积 $K$ 步后：

$$ G = \sum_{k=1}^{K} g_k, \qquad \theta \leftarrow \theta - \eta\,G \quad (\text{未归一化}) $$

归一化后：

$$ \theta \leftarrow \theta - \eta \cdot \frac{1}{K}\sum_{k=1}^{K} g_k = \theta - \eta\, \bar g $$

若不除以 $K$，等效学习率为 $\eta K$。低精度累加误差：设 $\hat G = \mathrm{fl}(\sum \mathrm{cast}(g_k))$，其相对误差随 $K$ 与单位舍入 $u$ 增长，界约为 $O(Ku)$。BF16 的 $u = 2^{-8}$ 明显大于 FP16 的 $2^{-11}$，故 BF16 下更应让累加发生在 FP32 缓冲中（主权重 FP32 天然满足）。

## 四、代码实现

```python
import torch

ACCUM = 8
scaler = torch.amp.GradScaler("cuda", enabled=True)   # FP16 路径

model.train()
opt.zero_grad(set_to_none=True)
for i, (x, y) in enumerate(loader):
    with torch.autocast(device_type="cuda", dtype=torch.float16):
        loss = model(x, y).loss / ACCUM        # 关键：除以累积步数
    scaler.scale(loss).backward()              # 每个 micro-batch 都反向

    if (i + 1) % ACCUM == 0:
        scaler.unscale_(opt)                   # 先还原缩放
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        scaler.step(opt)                       # 每周期的唯一一次更新
        scaler.update()
        opt.zero_grad(set_to_none=True)

# 处理尾部不足一个累积周期的残差（可选）
# if len(loader) % ACCUM != 0: scaler.step(opt); scaler.update()
```

若使用 BF16，可移除 `scaler`，直接 `loss.backward()` 与 `opt.step()`，其余结构不变。

## 五、与其他技术对比

| 方案 | 累加 dtype | 是否需缩放 | 显存特征 | 适用场景 |
| --- | --- | --- | --- | --- |
| FP32 累积 | FP32 | 否 | 最高 | 小模型、调试 |
| FP16 + 缩放 | FP32 主权重 | 是 | 低 | 旧卡大 batch |
| BF16 累积 | FP32 主权重 | 通常否 | 低 | 大模型主流 |
| 低精度梯度缓冲 | 低精度 | 视情况 | 最低 | 极端省显存，精度有损 |

## 六、常见误区

- 忘记 `loss / ACCUM`：等效学习率放大 $K$ 倍，训练震荡。
- 每个 micro-batch 都 `scaler.step`：梯度被反复部分更新，数值与语义都错。
- 只在最后一个 micro-batch 才 `backward`：前面的梯度丢失。
- 用 BF16 累积还担心下溢：范围充足，真正问题是分辨率而非下溢。
- 忽略残差批次：最后不足 $K$ 步的梯度被丢弃，等效 batch 偏小。

## 八、面试题

- 问：累积时为何可以除以 $K$？答：梯度线性，先平均与后平均等价，归一化保证等效学习率不变。
- 问：累积期梯度存在哪、什么精度？答：存在参数的 `.grad` 中，精度随参数 dtype（主权重 FP32 即 FP32）。
- 问：GradScaler 在每个 micro-batch 都 update 吗？答：不，每累积周期一次。
- 问：BF16 累积还需缩放吗？答：通常不需要。

## 九、演进与趋势

ZeRO 系列对优化器状态、梯度、参数分片进一步降低显存；FP8 训练引入细粒度缩放与更复杂的累积策略；这些技术常与梯度累积叠加使用。具体实现以官方最新文档为准。

## 十、小结

混合精度与梯度累积协同的要点是三条：**loss 除以 $K$、每周期只 step 一次、还原后再裁剪**。BF16 下可省缩放，但 FP32 主权重与 FP32 累加仍不可省。
