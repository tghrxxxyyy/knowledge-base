# 混合精度实践与陷阱

> 对应 Micikevicius et al., 2018 实践；Hugging Face AMP 文档经验。

## 一、背景与挑战

混合精度落地有诸多隐性陷阱：某些算子（softmax、layernorm、loss）对低精度敏感，应留在 FP32。

配置不当会“省了显存却训崩”。

## 二、核心原理

白名单（矩阵乘、卷积）走低精度；黑名单（softmax/layernorm/loss/归约）强制 FP32。autocast 按算子类型自动分发。

同时注意 BN 的 running_var 应为 FP32，避免统计漂移。

## 三、数学形式

有效精度由最敏感算子决定：$\mathrm{err}\approx\max\{\mathrm{err}_{fp16}(\text{敏感算子}),\mathrm{err}_{fp32}(\text{其余})\}$。

## 四、代码实现

```python
with torch.amp.autocast(device_type="cuda", dtype=torch.float16):
    h = model.fp16_layers(x)            # 低精度
loss = crit_fp32(h.float(), y)          # 损失回 FP32
```

## 五、与其他对比

- 与 归一化层数值稳定性深入 衔接，归一化对低精度敏感应留 FP32。
- 与 注意力数值稳定与溢界深入 衔接，softmax 留 FP32 更稳。
- 与 混合精度溢出检测深入 各篇互补。

## 六、常见误区

- 全图统一 FP16，softmax/layernorm 数值劣化。
- 忽略 BN 统计量精度，训练漂移。
- 在 CPU 上开 autocast 无效却未察觉。

## 八、面试题

- 哪些算子应留 FP32？答：softmax、layernorm、loss、归约等对低精度敏感者。
- 为何 autocast 不是全 FP16？答：敏感算子精度劣化，需按类型回 FP32。

## 九、演进

手工转换 → autocast 自动分发 → BF16 放宽限制。

## 十、小结

混合精度需区分算子敏感度，敏感算子留 FP32 才能既快又稳。
