# FP16 与 BF16 的表示与溢界

> 对应 IEEE 754（FP16）；BF16 由 Google 提出（Wang et al., *BFLOAT16*, 2019）；Micikevicius18 讨论。

## 一、背景与挑战

理解两种低精度格式的位宽分配，才能解释为何 FP16 易溢而 BF16 不易。

指数位决定动态范围，尾数位决定精度；二者权衡不同。

## 二、核心原理

FP16：1 符号 + 5 指数 + 10 尾数，最大约 65504，易上溢。BF16：1+8+7，指数同 FP32，最大约 3.4e38，几乎不上溢但尾数更粗。

因此 FP16 需损失缩放把梯度抬进可表示区，BF16 通常不必。

## 三、数学形式

FP16 可表示范围约 $[6e-5, 65504]$；BF16 约 $[1e-38, 3.4e38]$；超出即 Inf/0。

## 四、代码实现

```python
import torch
print(torch.finfo(torch.float16).max, torch.finfo(torch.bfloat16).max)
# 65504.0  vs  3.4028e+38
```

## 五、与其他对比

- 与 混合精度溢出检测深入 总览衔接，本篇解释“为何 FP16 需缩放”。
- 与 注意力数值稳定与溢界深入 同源（exp 上溢）。
- 与 优化器状态数值误差深入 相关，尾数精度影响状态累积。

## 六、常见误区

- 认为 BF16 不会下溢（仍会，但范围大得多）。
- 把 FP16 最大值当“安全区”，接近即失精度。
- 忽视硬件对 BF16 的支持差异（旧 GPU 无原生 BF16）。

## 八、面试题

- 为何 BF16 不需损失缩放？答：指数位与 FP32 同宽，动态范围足够，基本不上溢。
- FP16 最大表示多少？答：约 65504，超过即 Inf，故需缩放。

## 九、演进

FP32 → FP16 → BF16 → FP8（H100）。

## 十、小结

位宽分配决定溢界：FP16 范围窄需缩放，BF16 范围宽更省心。
