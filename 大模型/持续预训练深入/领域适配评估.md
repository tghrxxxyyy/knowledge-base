# 领域适配评估

> 对应 Gururangan et al., *Don't Stop Pretraining*, 2020 与持续预训练评估实践。

## 一、背景与挑战

领域继续预训练（domain-adaptive pretraining）在通用模型上注入领域语料后，必须回答一个关键问题：模型是否真正「学到了领域知识」，同时没有「忘记通用能力」？只涨领域分数却掉通用分数，意味着发生了灾难性遗忘或分布偏斜，这种适配是失败的。因此领域适配评估必须是**双轨制**：同时测量领域任务增益与通用能力保持，否则单看领域指标会被虚假繁荣误导。

## 二、核心原理

领域适配评估围绕三类信号展开：

- **领域下游任务**：在领域微调后的模型上跑领域基准（如医疗 QA、法律分类、代码补全），看持续预训练是否带来增益。
- **通用基准**：用 MMLU、常识推理、通用 QA 等衡量通用能力是否退化，防遗忘。
- **困惑度（PPL）**：在领域验证集与通用验证集分别计算 PPL，前者下降说明领域语言建模变好，后者不应显著上升。

核心判据是「领域涨、通用不跌」才视为成功；若领域涨但通用跌，需在数据配比（replay 比例）或训练步数上回调。

## 三、形式化与数学基础

设通用能力得分为 $C$，领域能力得分为 $D$，适配后分别为 $C', D'$。理想状态满足：

$$
\Delta D = D' - D > 0,\qquad \Delta C = C' - C \ge -\tau
$$

其中 $\tau$ 为可容忍的通用退化阈值（常取 0 或很小正值）。可用「相对保持率」量化遗忘：

$$
R = \frac{C'}{C}\times 100\%
$$

PPL 层面，领域集 $\mathcal{D}_{\text{dom}}$ 上的困惑度：

$$
\text{PPL}_{\text{dom}} = \exp\!\Big(-\frac{1}{N}\sum_{i}\log p_\theta(x_i)\Big)
$$

持续预训练后 $\text{PPL}_{\text{dom}}$ 应明显下降，而 $\text{PPL}_{\text{gen}}$ 基本不变。

## 四、代码实现

```python
def evaluate_adaptation(model, dom_eval, gen_eval):
    dom_before = gen_eval.run(model_init)        # 适配前通用分
    dom_after  = dom_eval.run(model_adapted)      # 适配后领域分
    gen_after  = gen_eval.run(model_adapted)
    return {
        "domain_gain": dom_after["score"] - dom_before["score"],
        "general_drop": gen_after["score"] - dom_before["score"],
        "keep_rate": gen_after["score"] / dom_before["score"],
    }
```

## 六、常见误区

- 只报领域指标：领域涨、通用崩的伪成功最危险，因为上线后综合能力下降用户可感知。
- 用训练集 PPL 当效果：训练 PPL 必然下降，必须以独立验证/测试集为准。
- 忽略长度与分布差异：领域与通用基准难度不同，直接比绝对值需谨慎，应看相对变化。
- 一次评估定论：持续预训练不同阶段能力曲线不同，建议在多个 checkpoint 上评估挑最优。

## 九、演进与趋势

评估从单一任务分数，走向「领域-通用帕累托前沿」可视化、动态加权评测、以及对长上下文与工具调用等新能力的专项评估。行业也强调持续预训练中的「评估门控 checkpoint」自动回滚。以官方最新文档为准。

**实践要点：**

- 评估频率建议每若干百步一次，开销可控且足以捕捉能力曲线变化，便于早停与择优。
- 通用基准应覆盖多维度（知识、推理、代码、安全），单点指标易误判。
- 领域 PPL 关注相对下降幅度而非绝对值，不同领域绝对量级不可比。
- 最佳 checkpoint 选择应以「领域增益 − 通用退化惩罚」综合打分，而非单纯领域最高分。

## 十、小结

领域适配评估的本质是平衡「学新」与「不忘旧」，双轨指标（领域增益 + 通用保持）+ 独立验证集 PPL 是落地标配，任何只看单侧的评估都可能掩盖失败。
