# 嵌入模型持续训练

> 对应 Reimers & Gurevych, *Sentence-BERT*, 2019、Gao et al., *SimCSE*, 2021 与对比学习嵌入训练实践。

## 一、背景与挑战

检索增强生成（RAG）的效果高度依赖嵌入模型（embedding model）的召回质量。通用嵌入模型在公开语料上训练，面对垂直领域（医疗、法律、金融、代码）时，领域术语与语义关系未被充分表示，召回率显著下降。领域继续训练嵌入模型即用领域语料/查询-文档对做对比学习微调，把领域语义注入向量空间。挑战在于：领域词表扩展、难负例构造、以及避免微调后通用检索能力退化（同前述双轨评估）。

## 二、核心原理

嵌入模型通常输出句向量 $e=\text{Enc}(x)\in\mathbb{R}^d$，经归一化后用内积/余弦相似度度量相关性。对比学习目标让「正例对」相似度高于「负例对」：

$$
\mathcal{L} = -\log\frac{\exp(\text{sim}(q,d^+)/\tau)}{\exp(\text{sim}(q,d^+)/\tau) + \sum_{d^-\in\mathcal{N}}\exp(\text{sim}(q,d^-)/\tau)}
$$

其中 $q$ 为查询（或锚点），$d^+$ 为正文档，$d^-$ 为负文档（含随机负例与难负例），$\tau$ 为温度。持续训练的关键是**难负例挖掘**：用当前模型召回的「高相似但错误」文档作为负例，迫使模型学到更细粒度区分。

## 三、形式化与数学基础

设编码器输出归一化向量 $u=\text{Enc}(q)/\| \text{Enc}(q)\|$，$v=\text{Enc}(d)/\| \text{Enc}(d)\|$，相似度 $\text{sim}(q,d)=u^\top v$。InfoNCE 损失在 batch 内构造负例：

$$
\mathcal{L}_{\text{InfoNCE}} = -\frac{1}{B}\sum_{i=1}^{B}\log\frac{e^{u_i^\top v_i^+ / \tau}}{\sum_{j=1}^{B} e^{u_i^\top v_j / \tau}}
$$

领域适配常采用「继续预训练 + 微调」两段：先在领域语料上做 MLM 或自监督对比（如 SimCSE 的 dropout 正例对），再用领域查询-文档对微调。若领域引入新 token，需扩展词表与嵌入矩阵并随机初始化新行，再小幅训练使其收敛。

## 四、代码实现

```python
import torch.nn.functional as F

def contrastive_loss(q, d_pos, d_negs, tau=0.05):
    # q, d_pos, d_negs: 归一化后的句向量 [B,d]
    pos = (q * d_pos).sum(-1) / tau           # [B]
    neg = q @ d_negs.t() / tau                # [B, K]
    logits = torch.cat([pos.unsqueeze(1), neg], dim=1)
    labels = torch.zeros(q.size(0), dtype=torch.long)
    return F.cross_entropy(logits, labels)
```

## 六、常见误区

- 只用随机负例：模型易学到「主题级」粗粒度相似，难负例才能逼出细粒度区分。
- 忽略词表扩展：领域新术语未被切分，语义被切碎，召回必然差。
- 只训领域丢通用：通用检索退化，应保留部分通用数据混合。
- 把嵌入模型当生成模型继续预训练：嵌入模型无因果 LM 头，需对比/双塔目标而非续写。

## 九、演进与趋势

从双塔 DPR 到自监督 SimCSE、再到多语言/长文档嵌入与「嵌入+重排」联合训练。当前趋势是更大负例库（in-batch + 跨设备负例）、难负例在线挖掘，以及用 LLM 生成合成查询-文档对扩充训练信号。以官方最新文档为准。

**实践要点：**

- 难负例可来自 BM25（词汇重叠高但无关）与模型召回（语义相近但错误）两类，混合使用覆盖更全。
- 训练时采用「梯度缓存 / 大模型召回、小模型训练」分工，可降低难负例挖掘成本。
- 评估用「召回率@k + NDCG」而非单点准确率，更能反映检索质量。
- 上线后建议定期用最新查询日志刷新难负例，防止分布漂移导致召回退化。

## 十、小结

嵌入模型持续训练是提升 RAG 领域召回的核心手段，要点在于领域词表扩展、难负例挖掘与通用-领域混合防退化；对比学习目标与两阶段训练是工程落地的标准配方。
