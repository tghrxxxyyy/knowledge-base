# 批处理吞吐与延迟权衡

> 对应 Kwon 2023 vLLM; Hoffmann 2022 Chinchilla; Kaplan 2020 scaling laws。

## 一、背景与挑战
增大批大小提升吞吐但抬高单请求首 token 延迟（TTFT）与区间延迟（TPOT），需在 SLA 内平衡。

## 二、核心原理
在线服务常设批上限与排队阈值；超过则拒绝或排队，保证 p99 延迟符合 SLA。批大小与延迟近似线性增长。

## 三、形式化与数学基础
TPOT 近似：
$ \text{TPOT} \approx \frac{2P/B + \text{overhead}}{b} $
b 为批大小，P 参数，B 带宽。吞吐 ∝ b 但 TPOT ∝ 1/b 反向。

## 四、代码实现
```python
def pick_batch(pending, max_b, sla_tpot):
    b = min(max_b, len(pending))
    while est_tpot(b) > sla_tpot and b > 1:
        b -= 1
    return pending[:b]
```

## 五、与其他技术对比
离线批处理可拉满吞吐不顾延迟；在线需租户级 SLA，权衡更紧。

## 六、常见误区
误区：吞吐最大即最优。忽略尾延迟会让交互体验极差。

## 七、与开源书/权威来源对应
Kwon et al. 2023 vLLM 讨论吞吐-延迟权衡。见 vllm-project/vllm。

## 八、面试题
问：如何同时优化 TTFT 与 TPOT？
答：阶段解耦 + 分离式架构分别压低二者，再配合批控。

## 九、演进与趋势
SLA 感知调度、优先级队列成为生产必备。

## 十、小结
批处理不是越大越好，应在 SLA 约束下求吞吐–延迟帕累托前沿。
