# 迭代级调度与静态批处理

> 对应 Kwon 2023 vLLM; Shoeybi 2019 Megatron; Rasley 2020 DeepSpeed ZeRO。

## 一、背景与挑战
早期服务按“整请求”排队调度，GPU 在等待长请求时闲置，且无法插空处理新请求。

## 二、核心原理
迭代级调度（iteration-level scheduling）把一次生成拆成多步，每步重新决策：哪些序列进批、哪些被抢占、哪些新接入，调度粒度等于一次前向。

## 三、形式化与数学基础
调度策略 π 在每步选择子集 B_t ⊆ S，目标最大化效用：
$ \max_\pi \mathbb{E}\left[\sum_t R(B_t) - C(\text{preempt})\right] $

## 四、代码实现
```python
def schedule(step, queues, gpu_slots):
    running = select_running(gpu_slots)
    waiting = admit_arrivals(queues, gpu_slots - len(running))
    return running + waiting           # 迭代级重组
```

## 五、与其他技术对比
静态调度在请求开始固定批次；迭代级每次前向重算，灵活但需高效 KV 管理配合。

## 六、常见误区
误区：迭代级调度本身省显存。它不省显存，需 PagedAttention 等机制配合才稳。

## 七、与开源书/权威来源对应
Kwon et al. 2023 vLLM 提出 iteration-level scheduling。见 vllm-project/vllm。

## 八、面试题
问：迭代级调度为何需要 KV 分页？
答：动态增删序列使 KV 长度不定，分页可避免碎片与整块预留。

## 九、演进与趋势
抢占+重计算/交换策略让长请求不饿死短请求。

## 十、小结
迭代级调度把调度粒度降到单步，是连续批处理得以成立的控制层。
