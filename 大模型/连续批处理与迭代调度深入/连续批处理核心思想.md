# 连续批处理核心思想

> 对应 Kwon 2023 vLLM; Rasley 2020 DeepSpeed ZeRO; Shoeybi 2019 Megatron。

## 一、背景与挑战
静态批处理必须等批次最慢请求结束才能释放，长尾请求拖垮整体 GPU 利用率，短请求也被迫等待。

## 二、核心原理
连续批处理（continuous batching）在每次迭代（每生成一个 token）后，动态把完成/新到的请求加入或移出批次，使 GPU 始终满载不同进度的序列。

## 三、形式化与数学基础
设序列集合 S_t 在步 t 活跃，各序列进度 p_i。批次吞吐：
$ \text{throughput} = \frac{\sum_i \text{tokens}_i}{\max_i T_i} $
连续批处理让 max_i T_i 接近最短完成时间之和的摊薄值。

## 四、代码实现
```python
while waiting or running:
    batch = scheduler.pick()          # 每步动态组批
    out = model.step(batch)
    for seq in batch:
        if seq.finished:
            scheduler.release(seq)
        else:
            scheduler.append(seq, out)
    scheduler.admit(new_requests)
```

## 五、与其他技术对比
静态批处理按请求粒度组批；连续批处理按 token 步进粒度，利用率显著提升。

## 六、常见误区
误区：批越大越好。受显存 KV 上限约束，过大引发 OOM 或抢占。

## 七、与开源书/权威来源对应
Kwon et al. 2023 Efficient Memory Management for Large Language Model Serving via PagedAttention (vLLM)。见 vllm-project/vllm。

## 八、面试题
问：连续批处理相对静态批处理的本质改进？
答：把批的边界从“请求级”细化到“token 步级”，实现细粒度复用。

## 九、演进与趋势
与 PagedAttention、优先级抢占结合，成为推理服务器事实标准。

## 十、小结
连续批处理通过逐 token 动态组批大幅拉升 GPU 利用率，是现代推理引擎基石。
