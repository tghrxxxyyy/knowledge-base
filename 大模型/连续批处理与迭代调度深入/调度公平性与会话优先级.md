# 调度公平性与会话优先级

> 对应 Kwon 2023 vLLM; Zhao 2023 FSDP; Rasley 2020 DeepSpeed ZeRO。

## 一、背景与挑战
多租户共享 GPU 时，长请求可能饿死短请求，或某租户抢占全部资源，需公平与优先级策略。

## 二、核心原理
引入优先级队列与配额：高优先级请求插队，配额限制每租户并发；配合抢占把低优先 KV 换出以支持高优先。

## 三、形式化与数学基础
加权公平共享：租户 i 长期获得份额：
$ s_i = \frac{w_i}{\sum_j w_j} \cdot C $
调度尽量在窗口内逼近 s_i。

## 四、代码实现
```python
def admit(req, quotas):
    if quotas[req.tenant] + 1 <= quotas.limit(req.tenant):
        quotas[req.tenant] += 1
        return True
    return False
```

## 五、与其他技术对比
FIFO 简单但不公平；优先级+配额兼顾 SLA 与隔离，代价是调度复杂度。

## 六、常见误区
误区：优先级高就永不排队。仍受显存与批上限约束，需配额防独占。

## 七、与开源书/权威来源对应
vLLM、Ray Serve 均有多租户调度。见 vllm-project/vllm、pytorch/pytorch FSDP。

## 八、面试题
问：抢占后如何恢复低优先请求？
答：KV 换出到 CPU，待资源释放再换入续算，或重计算。

## 九、演进与趋势
层级化调度（租户→会话→请求）成为云推理标准。

## 十、小结
公平与优先级保证多租户下稳定 SLA，是推理服务可用性的核心。
