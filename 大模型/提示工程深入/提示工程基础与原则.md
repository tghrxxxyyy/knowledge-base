# 提示工程基础与原则

> 对应 dair-ai/Prompt-Engineering-Guide（promptingguide.ai）。提示工程是「用自然语言编程大模型」的学科。

## 一、背景与挑战

大模型能力很强，但输出高度依赖**输入提示（prompt）的写法**。同样一个任务，措辞、结构、示例差异可让结果从错误百出到精准稳定。提示工程研究如何**设计输入**以可靠地引导模型行为，是低成本、无需微调即可适配任务的核心手段。它面对的挑战包括：歧义、格式不符、幻觉、对长指令遵从度下降、以及不同模型对同一提示敏感度不同。

## 二、核心原理

好提示遵循几条原则：

1. **清晰具体**：明确角色、任务、约束与输出格式，避免模糊词。
2. **结构化**：用分隔符（`###`、`<tag>`、`---`）隔离指令与输入，防混淆，也利于防注入。
3. **给示例（少样本）**：用 1–N 个输入/输出对锚定风格与格式，稳定性显著提升。
4. **分步推理**：复杂任务显式要求「一步步思考」（Chain-of-Thought）。
5. **迭代调优**：像写代码一样反复试错、对照评估改进。

本质是给模型足够的「脚手架」，把模糊意图转成模型易遵从的明确信号。

## 三、形式化与数学基础

把提示记为 $p$，任务输入 $x$，模型 $M$ 输出 $y \sim M(\cdot\mid p,x)$。提示工程寻找使期望任务指标最优的 $p^*$：

$$p^* = \arg\max_{p} \mathbb{E}_{(x,y^*)}[ \text{score}(M(y\mid p,x), y^*) ].$$

少样本通过在上下文拼入示范 $(x_k,y_k)$ 改变条件分布：

$$P(y\mid p, x) = M\big(y \mid p \oplus (x_1,y_1)\oplus\cdots\oplus(x_k,y_k)\oplus x\big).$$

分隔符降低指令与数据被模型「混读」的概率，提升指令遵从。

## 四、代码实现

基础模板（结构化、带角色与格式约束）：

```text
你是一名资深数据分析师。
任务：把用户评论分类为 正面/负面/中性，并给出一句话理由。

输入：
"""
这部手机续航很差，但屏幕很惊艳。
"""

要求：
1. 严格输出 JSON：{"label": "...", "reason": "..."}
2. 不要输出多余内容。
```

LangChain 中可用模板变量管理：

```python
from langchain.prompts import PromptTemplate
tpl = PromptTemplate.from_template(
    "你是一名{role}。任务：{task}\n输入：{input}\n输出JSON：{schema}")
print(tpl.format(role="分析师", task="分类", input="...", schema="{label,reason}"))
```

## 六、常见误区

- **把 prompt 当「咒语」堆无用词**（「请你务必、深呼吸」）：多数无效，应写具体约束。
- **忽略输出格式约束**：导致下游解析失败，应明确要求 JSON/分隔符。
- **一次塞太多指令**：过长反而降低遵从，应分层或拆子任务。
- **不做评估**：凭感觉调，应建小验证集对照。

## 九、演进与趋势

提示工程走向系统化：**自动提示工程（APE）**用模型搜最优提示；**DSPy/OPRO** 把提示当可优化参数；**结构化输出**与**函数调用**成为生产标配；以及结合**检索/记忆**的复合提示。提示逐步从「手写文本」演变为「可编程管线」。

## 十、小结

提示工程是用自然语言编程大模型的艺术与科学：遵循清晰、结构化、给示例、分步、迭代五原则，即可在不微调的前提下可靠引导模型行为；它是低成本适配任务的首选手段，也是 CoT、RAG、Agent 等高级技术的入口。
