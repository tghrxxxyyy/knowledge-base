# 提示链与任务分解

> 对应 Prompt-Engineering-Guide「Prompt Chaining」与 LangChain / LlamaIndex 的链（Chain）抽象。属提示工程深入板块，讨论把复杂任务拆为多次模型调用的可控编排。

## 一、背景与挑战

把极复杂任务塞进「一次超长 prompt」会面临三重困境：上下文窗口有限、单步出错难定位、中间结果无法校验、输出难以解析。提示链（prompt chaining）的思想是：将任务拆成多条 prompt 串成的**流水线**，上一步的规范化输出作为下一步输入，逐步逼近目标。它把「一次性押注」变为「分步收敛」，显著提升可控性、可观测性与可维护性。

## 二、核心原理

提示链的核心是一种**模块化分解**：每个子 prompt 只负责单一职责（抽取、校验、翻译、总结、格式化），并可在步骤间插入规则校验、人工审核或重试。与思维链（CoT）的关键区别：CoT 是**单次调用内**模型「边想边写」；提示链是**多次独立调用**，每次有清晰的输入输出契约，因此是工程对象而非纯推理技巧。

典型模式：
- **线性链**：A→B→C 顺序执行。
- **分支链**：依上一步结果路由到不同下游。
- **带校验的链**：每步后断言，失败则回退/重试。

## 三、形式化与数学基础

设任务分解为函数序列 $f_1,\dots,f_n$，其中第 $i$ 步由提示 $p_i$ 与模型 $\pi_\theta$ 实现：

$$
o_i = \pi_\theta\big(p_i \oplus \text{format}(o_{<i})\big), \quad o_0 = x
$$

最终输出 $y=o_n$。若引入校验谓词 $c_i(o_i)\in\{\top,\bot\}$，链在 $c_i=\bot$ 时触发重试或更换分支：

$$
\text{chain}(x) = o_n \quad \text{s.t.}\quad \forall i,\; c_i(o_i)=\top \;\text{(或重试上限内)}
$$

相比单步联合分布 $P(y\mid x)$，链式把复杂映射分解为多个条件分布的乘积近似，降低每步所需建模容量。

## 四、代码实现

```python
def run_chain(steps, x, max_retry=2):
    state = {"input": x}
    for step in steps:           # step: (prompt_fn, validator)
        prompt_fn, validator = step
        for _ in range(max_retry):
            out = llm(prompt_fn(state))
            if validator(out):
                state[step.name] = out
                break
        else:
            raise RuntimeError(f"步骤 {step.name} 校验失败")
    return state["output"]

# 例：抽取 -> 校验 -> 翻译 -> 总结
steps = [
    Step("extract",  p_extract,  is_json),
    Step("translate",p_translate, not_empty),
    Step("summarize",p_summarize, len_le(200)),
]
```

## 五、与其他技术对比

| 方法 | 调用次数 | 可控性 | 成本 | 可观测 |
|------|---------|--------|------|--------|
| 单次长 prompt | 1 | 低 | 低 | 差 |
| 思维链 CoT | 1 | 中 | 低 | 中 |
| 提示链 | 多 | 高 | 中高 | 高 |
| 智能体(ReAct) | 动态 | 高 | 高 | 高 |

提示链是「确定性编排」，智能体是「动态决策」，二者可在复杂系统中组合使用。

## 六、常见误区

- 把本可一步完成的简单任务硬拆多步，徒增时延与成本。
- 步骤间契约不清晰，上下游格式错位导致级联失败。
- 缺少校验与重试，单点错误沿链放大。
- 在链中混用非确定性输出当作确定输入，引入不可复现问题。

## 九、演进与趋势

提示链已从手写脚本演化为声明式编排：LangChain LCEL、LlamaIndex Workflows、以及面向 LLM 的 DSL（如 SGLang、DSPy）都用「图/管线」表达步骤与分支。配合可观测平台（LangSmith、Phoenix）实现逐步追踪与回放。趋势是把「拆分策略」本身自动化——由模型或优化器决定何时链式化、何时并行化，进一步降低人工编排成本。

## 十、小结

提示链用多次模型调用把复杂任务拆成可校验、可观测的流水线，换取可控性与可维护性，代价是更多调用与成本。它与 CoT（单步内推理）、智能体（动态决策）形成由静到动的谱系。工程落地应明确步骤契约、加入校验重试，并避免对简单任务过度拆分。
