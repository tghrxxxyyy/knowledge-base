# 结构化输出与约束解码

> 对应 Prompt-Engineering-Guide「Formatting」与 LLM 工程实践（guidance、outlines、lm-format-enforcer）。属提示工程深入板块，聚焦「让模型输出可机器解析」。

## 一、背景与挑战

在生产系统中，模型输出往往不是给人读的，而是要被下游程序消费：分类标签、抽取字段、工具参数、图谱三元组等。若输出是自然语言，解析脆弱、易因格式漂移而失败。核心挑战是：如何让 LLM 的输出**结构性可保证**，既保留语言模型的表达力，又满足严格的语法约束（JSON Schema、正则、上下文无关文法）。

## 二、核心原理

获取结构化输出有两条路线：
1. **软约束（提示约束）**：在 prompt 中描述 schema、给出示例、列明字段规则。模型「尽力」遵守，但属概率行为，可能漏字段、错类型、补多余文字。
2. **硬约束（约束解码 / constrained decoding）**：在自回归采样时，用语法（CFG / JSON Schema / 正则）实时计算每个时间步的合法 token 集合，仅从合法集合中采样。这样**从机制上保证**输出一定符合语法，解析零失败。

约束解码的关键在于「前缀接纳（prefix acceptance）」：维护一个解析器状态，任何使当前前缀变为非法字符串的 token 都被屏蔽。现代实现（如 outlines 的有限状态机、guidance 的 token 级约束）可在不显著影响质量的前提下完成。

## 三、形式化与数学基础

设词汇表为 $\mathcal{V}$，语法 $G$ 定义合法字符串集合 $L(G)$。在已生成前缀 $x_{<t}$ 后，合法后缀首 token 集合为：

$$
\mathcal{A}(x_{<t}) = \{\, v\in\mathcal{V} \mid x_{<t}\!v \text{ 是 } L(G) \text{ 中某串的前缀} \,\}
$$

约束解码将下一步概率重标定：

$$
P_{\text{cons}}(v\mid x_{<t}) = \frac{P_\theta(v\mid x_{<t})\,\mathbb{I}[v\in\mathcal{A}(x_{<t})]}{\sum_{u\in\mathcal{A}(x_{<t})} P_\theta(u\mid x_{<t})}
$$

若用「强制（force）」而非「加权」，则直接在唯一合法 token 上置概率 1，彻底消除歧义。

## 四、代码实现

```python
# 方案 A：纯提示约束（软，需后处理校验）
schema_hint = '''
请严格输出 JSON，字段：
{"sentiment": "正面"|"负面"|"中性", "confidence": 0.0~1.0}
仅输出 JSON，不要任何解释。
'''

# 方案 B：约束解码（硬保证，以 outlines 为例）
from outlines import models, generate
import json

model = models.transformers("Qwen/Qwen2.5-0.5B")
generator = generate.json(model, {
    "sentiment": str,
    "confidence": float,
})
result = generator("评论：这家店服务态度真好，下次还来。")
print(json.loads(result))  # 保证合法 JSON
```

## 五、与其他技术对比

| 方法 | 保证级别 | 实现复杂度 | 质量影响 | 适用 |
|------|---------|-----------|---------|------|
| 自然语言描述 | 无 | 低 | 小 | 原型 |
| 少样本格式示例 | 弱 | 低 | 小 | 简单 |
| 后处理修复 | 中（可能失败） | 中 | 中 | 容错系统 |
| 约束解码 | 强（语法级） | 高 | 极小 | 生产关键 |

约束解码在金融、医疗、工具调用等对格式零容忍场景几乎成为标配。

## 六、常见误区

- 以为「提示写清楚就一定守法」：软约束对长 schema、嵌套结构仍会失手。
- 把约束解码当万能：它保证语法，不保证语义正确（字段值仍可能错）。
- 在需要自由文本的字段上过度约束，反而降低表达力。
- 忽略 JSON 中的转义与编码（引号、换行），解析端需统一规范。

## 九、演进与趋势

约束解码从「正则/CFG」走向「结构化生成即服务」：主流推理框架（vLLM、TGI、SGLang）已内置 JSON / 正则约束；OpenAI、Anthropic 等提供 `response_format` 与工具 schema 自动约束。SGLang 的「受控解码」与「DSL 编排」进一步把结构约束与程序流程融合。未来趋势是把语法约束前移到训练（用结构化语料 SFT）以缩小软硬约束差距。

## 十、小结

结构化输出是 LLM 落地工程的刚需。软约束成本低但不保证；约束解码用语法实时屏蔽非法 token，从机制上确保输出可解析、近乎零质量损失，已成为生产关键场景的标配。落地时仍须配合语义校验与转义规范，约束解决「形状」，语义需另设护栏。
