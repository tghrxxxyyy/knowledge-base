# 角色与风格提示

> 对应 Prompt-Engineering-Guide「Role Prompting」与 OpenAI 提示工程指南。通过设定角色、语气与受众约束输出风格，属提示工程深入板块。

## 一、背景与挑战

大模型是「多面手」，同一模型在不同语境下可呈现截然不同的语言风格与专业深度。若提示不约束，输出往往在口吻、详尽度、专业度上漂移，难以满足产品对一致性（如品牌语气、客服话术）的要求。角色与风格提示（Role/Persona Prompting）的目标，正是通过显式声明「你是谁、对谁说、怎么说」，把模型的「行为分布」锚定到期望区间，从而稳定输出基调。

## 二、核心原理

大模型在预训练阶段吸收了海量不同身份、风格的文本。当提示声明「你是一位资深律师」时，相当于在输入空间中激活了与该角色强相关的子分布：词汇偏好、论证方式、谨慎程度都会随之偏移。这是一种**上下文条件化**而非权重修改——模型参数不变，仅由前缀上下文引导解码走向特定区域。风格维度通常可正交拆解：

- **角色**：专家/新手、特定职业、虚构人物。
- **语气**：正式/口语、幽默/严谨、亲切/权威。
- **受众**：儿童/高管/同行，决定术语密度。
- **长度与格式**：字数上限、列表或段落。

## 三、形式化与数学基础

设模型条件分布为 $P_\theta(y\mid x)$，角色提示为前缀 $r$（如「你是严谨的医学顾问」）。角色提示相当于把解码分布改写为：

$$
P_\theta(y\mid x) \;\longrightarrow\; P_\theta(y\mid r \oplus x)
$$

其中 $\oplus$ 表示拼接。若定义风格空间为潜在变量 $s$，则可视为对后验的约束：

$$
P_\theta(y\mid x, s) \propto P_\theta(y\mid x)\, \mathbb{I}[\text{style}(y)\approx s]
$$

理想情况下，提示使模型在风格子空间内最大化任务相关似然，而非全局似然，从而抑制无关风格。

## 四、代码实现

```python
def build_role_prompt(role: str, audience: str, tone: str, task: str, max_words: int = 120):
    system = (
        f"你现在的角色是：{role}。\n"
        f"你的受众是：{audience}。\n"
        f"表达语气：{tone}。\n"
        f"回答不超过 {max_words} 字，使用中文，避免专业术语堆砌。"
    )
    return [{"role": "system", "content": system},
            {"role": "user", "content": task}]

# 示例：向儿童解释黑洞
msgs = build_role_prompt(
    role="天体物理科普作家",
    audience="8岁小学生",
    tone="生动、比喻化、鼓励式",
    task="用一句话解释黑洞是什么。"
)
```

## 五、与其他技术对比

| 技术 | 作用层 | 是否改权重 | 主要增益 |
|------|--------|-----------|---------|
| 角色/风格提示 | 输入前缀 | 否 | 风格一致、基调可控 |
| 少样本示例 | 输入示例 | 否 | 任务模式学习 |
| 系统提示固化 | 输入前缀 | 否 | 长期行为约束 |
| 微调/SFT | 权重 | 是 | 深层风格内化 |

角色提示成本低、即改即生效，但风格约束强度弱于微调；二者常结合——用 SFT 固化「品牌人格」，用角色提示做细粒度场景切换。

## 六、常见误区

- 认为角色提示「改变了模型权重」：实际只是上下文引导，关闭该前缀即失效。
- 角色声明与任务矛盾（如「你是不懂编程的新手」却要求写复杂代码），导致输出质量崩塌。
- 风格约束过死，挤占任务信息预算，反而答非所问。
- 仅设角色不设受众/长度，风格仍可能漂移。

## 七、与开源书·权威来源对应

- Prompt-Engineering-Guide：「Role Prompting」章节（promptingguide.ai）。

## 八、面试题

- 角色设定为何能改变输出？它是否修改了模型权重？
- 系统提示（system message）与用户提示里的角色声明，优先级与效果有何差异？
- 如何量化评估一个角色提示是否真的「生效」而非幻觉式一致？

## 九、演进与趋势

角色提示已演化为「人格/人设（persona）」工程：多智能体系统中不同 agent 通过稳定人设分工协作；产品侧则将品牌人格写入系统提示并配合护栏防止「人设崩塌」。与 RLHF/DPO 对齐后的模型，对角色指令的遵从度显著提升。前沿方向还包括用可学习的软提示（soft prompt）隐式编码人格，以及评估角色一致性的自动化基准。

## 十、小结

角色与风格提示是用输入前缀「激活」模型内部特定行为分布的轻量技术，成本低、可逆、即生效，是控制输出基调与专业度的首选手段。它不改动权重，约束强度弱于微调，工程中常与 SFT 固化的人格配合使用以达到稳定且可控的风格表现。
