# 零样本提示 Zero-Shot

> 对应 dair-ai/Prompt-Engineering-Guide「Zero-Shot Prompting」与 Brown et al., *Language Models are Few-Shot Learners*, 2020（上下文学习）。

## 一、背景与挑战

最早与模型交互的方式是**零样本（zero-shot）**：不给任何示例，仅用自然语言描述任务，期望模型凭预训练学到的能力直接完成。随着模型规模与指令微调（如 InstructGPT/RLHF）普及，零样本在分类、翻译、摘要、抽取、格式化等大量任务上已可用，成为最快、最省的落地方式。它的挑战是：表述不清或输出约束缺失时，模型容易答非所问或格式不符。

## 二、核心原理

零样本可行的基础是**上下文学习（in-context learning）**与**指令遵从**：大模型在海量文本上预训练，已内隐学到大量任务模式；指令微调进一步让它「听懂指令」。因此只要把任务用清晰自然语言说清，并把期望输出格式写明白，模型即可在「零示例」下映射到正确行为。关键在于**指令具体 + 输出格式约束 + 必要时给角色/边界**。

## 三、形式化与数学基础

设任务分布，模型 $M$ 在零样本下输出：

$$y \sim M(\cdot \mid p, x),$$

其中 $p$ 为任务指令、$x$ 为输入。上下文学习表明，即使无梯度更新，条件分布已被 $p$ 显著偏移到目标任务（Brown et al., 2020）。指令微调把该偏移进一步强化，使小模型也能遵从显式指令。质量随模型规模与对齐程度提升，但对分布外或需专业知识的任务仍弱于少样本/RAG。

## 四、代码实现

零样本分类（明确指令 + 输出格式）：

```text
将下面句子分类为 正面 / 负面 / 中性，只输出标签：
"这部手机续航很差，但屏幕很惊艳。"
输出：
```

代码侧（OpenAI 兼容）：

```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")
r = client.chat.completions.create(
    model="meta-llama/Llama-2-7b-chat-hf",
    messages=[{"role":"user",
      "content":'把句子分类为 正面/负面/中性，只输出标签：\n"这家餐厅服务周到，菜品一般。"'}],
    temperature=0, max_tokens=8)
print(r.choices[0].message.content.strip())
```

## 五、与其他提示形式对比

| 形式 | 示例数 | 成本 | 稳定性 | 适用 |
|------|-------|------|--------|------|
| 零样本 | 0 | 最低 | 中 | 通用简单任务 |
| 少样本 | k>0 | 中（长 prompt） | 高 | 需锚定格式/风格 |
| CoT | 0/少 | 中 | 中高 | 多步推理 |
| RAG | 0+检索 | 中高 | 高 | 需外部知识 |

## 六、常见误区

- **指令含糊**：如「分析一下这段文本」缺输出规格，易得到泛泛而谈。
- **忽略输出格式约束**：不写「只输出 JSON/标签」常导致多余解释、解析失败。
- **复杂任务硬上零样本**：分布外或需推理的任务应转少样本/CoT/RAG。
- **温度未设 0**：分类等确定性任务建议低温度以稳定。

## 九、演进与趋势

零样本是**指令微调 / 对齐模型**的核心使用方式；与**结构化输出**、**函数调用**结合成为生产默认。自动提示工程（APE）可为零样本任务搜出更优指令；零样本也被用作**评测基线**对比少样本增益。随模型能力增强，越来越多任务「零样本即可」。

## 十、小结

零样本提示不提供任何示例，仅用清晰自然语言指令 + 输出格式约束引导模型完成任务，依赖大模型预训练的上下文学习与指令微调的指令遵从能力；它成本最低、最易用，但复杂或分布外任务应升级为少样本、CoT 或 RAG。
