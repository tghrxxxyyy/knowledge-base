# 自主编码智能体总览

> 对应 Jimenez et al., *SWE-bench*, ICLR 2024；Yang et al., *SWE-agent*, NeurIPS 2024；Chen et al., *Evaluating LLMs Trained on Code (HumanEval)*, 2021。

## 一、背景与挑战

从函数级补全到仓库级问题修复，任务性质发生质变：需要在几十万行代码中定位、理解跨文件依赖、修改后不破坏既有行为。
真实软件工程任务的评测显示，仓库级修复的难度远高于独立函数生成，瓶颈在定位与验证而非语法生成。

## 二、核心原理

- 闭环三件套：定位（找到相关文件与函数）、修改（最小化补丁）、验证（运行测试与静态检查），失败则回到定位或修改。
- 智能体计算机接口（ACI）：为模型设计专用的文件浏览、片段编辑、搜索与测试命令，比裸终端更少出错。
- 最小改动原则：补丁越小越易审阅、越不易引入回归，也更接近人类工程习惯。

## 三、数学形式

端到端解决率可分解为 $P(\text{solve})=P(\text{locate})\cdot P(\text{patch}\mid \text{locate})\cdot P(\text{pass}\mid \text{patch})$。

由于三项相乘，定位环节的召回不足是最常见的天花板；提高定位召回通常比增强生成能力收益更大。

## 四、代码实现

```python
def fix_issue(agent, repo, issue, max_iter=6):
    files = agent.locate(repo, issue)                 # 定位候选文件
    for _ in range(max_iter):
        patch = agent.edit(repo, files, issue)        # 最小补丁
        ok, log = run_tests(repo, patch)
        if ok:
            return patch
        if "No such file" in log or "ImportError" in log:
            files = agent.locate(repo, issue, hint=log)   # 定位不准则重定位
        else:
            agent.observe(log)                        # 测试失败作为反馈
    return None
```

## 五、与其他对比

- 与代码补全工具：补全在光标处提供局部建议，人保持主导；编码智能体自主完成定位到验证的闭环，需要更强的护栏与审阅。
- 与一般智能体：拥有近乎理想的外部验证器（编译器与测试），因此自我纠正在此领域是真正有效的。

## 六、常见误区

- 把整个仓库塞进上下文：成本高且注意力被稀释，应用检索与符号索引定位。
- 只看测试通过率忽略补丁质量：通过测试的补丁可能靠改测试或加特例作弊。
- 无回滚机制直接改工作区，失败后仓库状态污染，应在分支或副本上操作。

## 八、面试题

- 仓库级修复为何比函数生成难得多？答：需要跨文件定位与依赖理解，且必须通过既有测试不引入回归，成功率是多环节乘积。
- 为什么编码领域的自我纠正更有效？答：编译器与测试提供与模型误差无关的客观反馈，避免了自评式纠错的相关性问题。

## 九、演进

函数级补全（HumanEval）→ 交互式调试（Self-Debug）→ 仓库级基准（SWE-bench）→ 专用智能体接口（SWE-agent）→ 多智能体协作与人机协同评审。

## 十、小结

编码智能体的成败集中在定位与验证两端，最小补丁加客观测试构成它可靠工作的基础闭环。
