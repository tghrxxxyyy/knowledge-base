# 补丁生成与基准

> 对应 Jimenez et al., *SWE-bench*, ICLR 2024；Yang et al., *SWE-agent*, NeurIPS 2024。

## 一、背景与挑战

评测编码智能体不能只看生成像不像，必须看补丁能否让真实项目的测试从失败转为通过。
基于真实开源仓库与真实提交构建的基准把任务变成可自动判定，但也带来环境依赖、数据污染与评分细节等复杂性。

## 二、核心原理

- 任务构造：取真实缺陷或特性提交，保留问题描述与测试，移除官方补丁，要求智能体产出等效修复。
- 判定标准：应用补丁后，原本失败的测试（fail-to-pass）必须通过，且原本通过的测试（pass-to-pass）不得回归。
- 补丁形式：统一 diff 便于审阅与应用；应要求最小改动并禁止修改测试。

## 三、数学形式

解决率为 $\text{Resolve}=\frac{\#\{\text{fail2pass 全通过且 pass2pass 无回归}\}}{N}$。

引入多次尝试时用 pass@k：$\text{pass@}k=\mathbb E_{\text{task}}\big[1-\binom{n-c}{k}/\binom{n}{k}\big]$，其中 $n$ 为采样数、$c$ 为其中正确数。

## 四、代码实现

```python
def judge(repo, patch, f2p, p2p):
    with worktree(repo) as w:                 # 隔离副本，失败可丢弃
        if not apply_patch(w, patch):
            return False, "补丁无法应用"
        if touched_tests(patch):
            return False, "禁止修改测试"
        return (all(run_test(w, t).ok for t in f2p) and
                all(run_test(w, t).ok for t in p2p)), "judged"
```

## 五、与其他对比

- 与 HumanEval 类函数级基准：函数级只验证独立函数行为，无需定位与回归控制，难度与真实工程差距大。
- 与人工评审：人工能评价可维护性与设计质量，自动基准只能测行为等价，二者互补。

## 六、常见误区

- 只报 fail-to-pass 不报 pass-to-pass，掩盖回归。
- 忽略环境固定（依赖版本、随机种子、时区），导致结果不可复现。
- 数据污染：模型训练语料可能包含官方补丁，需用较新提交或做去污分析后再解读分数。

## 八、面试题

- 为什么必须同时检查 pass-to-pass？答：只保证目标测试通过无法排除回归，等于允许用破坏其他功能的方式换取通过。
- 如何缓解基准污染？答：使用训练截止后的新提交、检查是否复现官方补丁、报告去重与污染分析结果。

## 九、演进

函数级通过率 → 真实仓库缺陷修复 → 加回归约束的严格判定 → 环境容器化保证复现 → 持续更新以对抗污染。

## 十、小结

补丁基准的价值在于客观可判定：目标测试转通过、既有测试不回归、环境可复现、污染要披露。
