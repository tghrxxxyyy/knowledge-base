# 测试驱动与执行反馈

> 对应 Chen et al., *Teaching Large Language Models to Self-Debug*, ICLR 2024；Zhong et al., *LDB* 等基于执行反馈的调试工作。

## 一、背景与挑战

生成的代码在语法上几乎总能通过，但语义正确性只能由执行来判定。
如何把执行结果转成对模型有用的反馈，以及在没有测试时如何自造测试，是编码智能体的核心工程。

## 二、核心原理

- 反馈层级：编译或导入错误（最强定位）、测试断言失败（含期望与实际值）、运行时异常堆栈、覆盖率与性能指标。
- 先复现后修复：优先写出能复现缺陷的最小测试，修复后该测试转为回归防护。
- 反馈压缩：只保留失败断言、关键堆栈帧与相关变量值，避免整份日志淹没上下文。

## 三、数学形式

若单次修复成功率为 $p$ 且每轮反馈近似独立，$n$ 轮内成功概率为 $1-(1-p)^n$。

实际反馈不独立（同类错误反复），有效增益随轮次衰减，可用 $1-\prod_{i=1}^{n}(1-p_i)$ 且 $p_i$ 递减来刻画，故轮数应设上限。

## 四、代码实现

```python
def debug_loop(agent, repo, patch, rounds=5):
    for _ in range(rounds):
        res = run_tests(repo, patch)
        if res.ok:
            return patch
        fb = {"failed": res.failed_tests[:3],
              "assert": res.first_assert,           # 期望值与实际值
              "trace": res.trace_frames[:5]}
        patch = agent.revise(patch, fb)
    return None
```

## 五、与其他对比

- 与纯自评修复：执行反馈是客观信号，纠错收益稳定；自评修复在代码任务上同样容易改坏。
- 与形式化验证：验证能给出正确性保证但成本高、适用面窄；测试是工程上的最优性价比折中。

## 六、常见误区

- 让智能体修改测试以让其通过：必须锁定测试文件为只读或在评测中检测测试被篡改。
- 把完整 CI 日志回灌，关键断言被埋没在噪声里。
- 只跑相关单测不跑全量回归，修复引入的副作用被漏过。

## 八、面试题

- 执行反馈为何比自评有效？答：编译器与测试的判断独立于模型的生成偏差，提供真正的新信息。
- 为什么先写复现测试？答：它把模糊的缺陷描述变成可判定条件，既指导修复也成为长期回归防护。

## 九、演进

一次性生成 → 编译错误回灌 → 测试断言驱动修复 → 复现测试先行加全量回归 → 覆盖率与性能纳入反馈。

## 十、小结

执行反馈是编码智能体唯一可靠的裁判，工程重点是压缩反馈信息并防止测试被绕过。
