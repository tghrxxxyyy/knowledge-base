# 工具链与终端交互

> 对应 Yang et al., *SWE-agent*, NeurIPS 2024（智能体计算机接口设计）；开源 OpenHands 等工程实践。

## 一、背景与挑战

把裸 shell 交给模型看似最灵活，实际错误率高：路径出错、编辑越界、交互式命令卡住、输出过长淹没上下文。
接口设计是可测量的性能因素，好的专用命令能显著提升成功率而不改变底层模型。

## 二、核心原理

- 面向模型的命令集：带行号的文件查看窗口、按行范围替换的编辑命令、结构化搜索、受限的测试运行入口。
- 输出治理：分页显示、长输出截断加尾部保留、错误优先展示，确保关键信息在上下文预算内。
- 防呆约束：编辑前强制校验语法、越界行号直接报错、禁止交互式与长驻命令、超时自动终止。

## 三、数学形式

若每步动作失败率为 $q$，$T$ 步任务成功率约 $(1-q)^T$；把 $q$ 从 0.2 降到 0.05 在 $T=20$ 时成功率从约 $0.01$ 升到约 $0.36$。

这说明接口带来的单步可靠性提升在长轨迹上被指数放大，是性价比最高的优化点之一。

## 四、代码实现

```python
def edit_lines(path, start, end, new_text):
    lines = read(path).splitlines()
    if not (1 <= start <= end <= len(lines) + 1):
        return "错误: 行号越界"
    cand = lines[:start - 1] + new_text.splitlines() + lines[end:]
    src = "\n".join(cand)
    if not syntax_ok(path, src):                 # 保存前语法校验
        return "错误: 语法检查未通过, 未写入"
    write(path, src); return view(path, start - 5, end + 5)
```

## 五、与其他对比

- 与裸终端：裸终端表达力最强但错误率高；专用接口以牺牲少量灵活性换取显著可靠性。
- 与 IDE 插件式协作：插件由人主导、智能体建议；自主智能体需要自带等价的浏览与编辑能力。

## 六、常见误区

- 允许无限制输出，一条命令的日志就吃掉整个上下文。
- 用整文件重写代替行范围编辑，token 浪费且易丢失未展示部分。
- 未禁止交互式命令，智能体在等待输入处死锁直到超时。

## 八、面试题

- 为什么接口设计能显著提升成功率？答：长轨迹成功率是单步可靠性的幂函数，降低单步失败率带来指数级收益。
- 为什么优先行范围编辑而非整文件重写？答：省 token、改动可审、避免模型重写未见部分造成隐性破坏。

## 九、演进

裸 shell → 受限命令白名单 → 面向模型的浏览与编辑接口 → 保存前静态校验 → 结合语言服务的符号级编辑。

## 十、小结

工具链设计是编码智能体的隐形杠杆：受限命令、结构化输出、保存前校验，把单步错误压到最低。
