# 仓库级理解与定位

> 对应 Jimenez et al., *SWE-bench*, ICLR 2024；Zhang et al., *RepoCoder*, EMNLP 2023（仓库级检索增强代码生成）。

## 一、背景与挑战

问题描述常是自然语言缺陷报告，与代码符号之间没有直接词面对应。
仓库上下文远超窗口，必须靠检索与结构分析选出少量真正相关的代码片段。

## 二、核心原理

- 多路定位：词法搜索（报错信息、函数名、异常类型）、语义检索（问题描述对代码文档）、结构分析（调用图、导入图、测试到实现的映射）。
- 测试反向定位：失败测试的堆栈是最强信号，沿调用栈上溯往往直达缺陷位置。
- 迭代扩展：从种子文件出发按依赖边扩展一到两跳，控制上下文规模同时覆盖相关实现。

## 三、数学形式

融合多路排名可用 RRF：$\text{score}(f)=\sum_{r}\frac{1}{k+\text{rank}_r(f)}$，避免不同信号分数不可比。

定位是不可恢复环节，端到端上限受召回约束 $P(\text{solve})\le \text{Recall@}k(\text{files})$，因此宁可略放宽 $k$ 也要保召回。

## 四、代码实现

```python
def locate(repo, issue, k=8):
    lex = grep_symbols(repo, extract_identifiers(issue))
    sem = vec_index(repo).search(embed(issue), k=30)
    stk = files_from_traceback(issue)
    fused = rrf([stk, lex, sem], k=60)[:k]
    return expand_by_imports(repo, fused, hops=1)     # 依赖一跳扩展
```

## 五、与其他对比

- 与全量上下文（超长窗口）：长窗口省去定位工程，但成本高且长程注意力衰减，检索仍普遍更划算。
- 与静态分析工具：静态分析给出精确依赖与类型，是语义检索的强补充，二者结合优于任一单独使用。

## 六、常见误区

- 只做向量检索：代码中的标识符属于专名，词法匹配不可或缺。
- 忽略测试文件与配置文件，很多缺陷线索在测试期望或参数默认值中。
- 扩展跳数过多导致上下文爆炸，反而降低模型定位精度。

## 八、面试题

- 代码检索与文本检索有何不同？答：标识符是专名需词法匹配、结构依赖可用调用图显式利用、堆栈提供强定位信号。
- 定位失败为何是硬上限？答：相关文件未进入上下文时模型无法修复，后续生成与验证再强也无从补救。

## 九、演进

关键词搜索 → 语义检索 → 多路融合加依赖扩展 → 结合静态分析与堆栈的定位 → 面向定位的专用微调与索引。

## 十、小结

仓库级定位是编码智能体的第一性瓶颈，词法、语义、结构三路融合是当前最实用的答案。
