# 同态加密与密态

> 对应 Microsoft SEAL（BFV/CKKS 方案）、Paillier 加法同态与 CKKS 近似计算；参考 llm-course (mlabonne) 与联邦学习实践。

## 一、背景与挑战

在跨机构场景（如多家医院联合建模、银行联合风控）中，即便是「只传梯度」的联邦学习，参数本身仍可能泄露信息。若要求「数据连计算过程都不暴露」，就需要密态计算：在密文上直接完成模型推理或训练。核心挑战：

- 计算开销大：密态运算比明文慢几个数量级。
- 精度损失：部分方案（CKKS）为近似计算，需控误差。
- 方案选择：加法/乘法同态能力不同，需匹配任务。
- 工程复杂：密文膨胀、密钥管理、参数调优门槛高。
- 适用边界：仅适合特定高价值、低延迟容忍任务。

## 二、核心原理

同态加密允许在密文上做特定运算，解密结果等于对明文做同样运算。按能力分：

- 部分同态（PHE）：仅支持一种运算（如 Paillier 仅加法）。
-  somewhat 同态（SHE）：有限次加法与乘法。
- 全同态（FHE）：任意次加法与乘法（如 BFV、CKKS）。

在 LLM 场景，典型用法是：客户端加密输入 $x\to \text{Enc}(x)$，服务端在密文上跑模型得到 $\text{Enc}(y)$，回传后客户端解密得 $y$，全程服务端不见明文。CKKS 擅长浮点近似，适合神经网络推理。

（落地补充：）
- 工程上多采用混合架构，对必须保密的输入走密态推理。
- 可明文部分走普通路径，用 TEE 补齐侧信道防护。
- 把性能代价限制在真正敏感的高价值任务上。
- 与联邦学习组合可在「传参数」之外再叠加密态计算。

## 三、形式化与数学基础

同态性要求存在运算 $\oplus,\otimes$ 使：

$$ \text{Dec}\big(\text{Enc}(a) \oplus \text{Enc}(b)\big) = a + b $$
$$ \text{Dec}\big(\text{Enc}(a) \otimes \text{Enc}(b)\big) = a \times b $$

对线性层 $y = Wx + b$，可在密态逐元素完成：

$$ \text{Enc}(y) = W \otimes \text{Enc}(x) \oplus \text{Enc}(b) $$

CKKS 引入近似误差 $\epsilon$，满足 $\|\text{Dec}(\cdot) - (Wx+b)\| \le \epsilon$，需把 $\epsilon$ 控制在任务容忍内。

## 四、代码实现

```python
# 密态推理示意（基于 SEAL/CKKS 思路，伪 API）
from seal import CKKSEncoder, Encryptor, Evaluator

enc = Encryptor(context, public_key)
evalr = Evaluator(context)

ct_x = enc.encrypt(encode(x))            # 客户端加密输入
ct_y = evalr.multiply_plain(ct_x, W)     # 密态线性变换
ct_y = evalr.add_plain(ct_y, b)
y = decode(decryptor.decrypt(ct_y))      # 客户端解密结果
# 服务端全程只见密文 ct_x / ct_y
```

## 五、与其他技术对比

| 维度 | 联邦学习 | 同态加密（密态） |
| --- | --- | --- |

| 性能 | 较高 | 很低（慢） |

| 复杂度 | 中 | 高 |

## 六、常见误区

- 「密态通用且快」：实际很慢，仅适合特定任务。
- 「加密即绝对安全」：仍受侧信道与参数选择影响。
- 「FHE 万能」：深度网络多层乘法会迅速放大噪声，需重线性化与模切换。
- 「忽略精度」：CKKS 近似误差在关键场景不可忽略。

## 九、演进与趋势

从「明文计算」到「联邦」再到「密态计算」；趋势是 GPU 加速 FHE、与 TEE（可信执行环境）混合、以及把密态推理做成隐私保护推理服务（PIR）。

## 十、小结

同态加密代表隐私保护的「最强形态」——数据连计算过程都不暴露。代价是高昂性能与工程复杂度，适合高敏、低吞吐要求的推理与特定计算，是联邦与差分隐私之外的重要补充。
