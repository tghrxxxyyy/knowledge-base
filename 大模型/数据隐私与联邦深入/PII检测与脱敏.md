# PII 检测与脱敏

> 对应 Microsoft Presidio（PII 识别与脱敏）、NER 隐私工程实践；参考 llm-course (mlabonne) 与 OWASP LLM Top 10。

## 一、背景与挑战

大模型在训练与推理两端都会接触到个人可识别信息（PII）：姓名、电话、身份证、银行卡、病历、住址等。若在训练语料中残留 PII，模型可能记忆并泄露；若推理输出回显 PII，则直接违反隐私与合规。核心挑战：

- 格式多样：同一类 PII 有多种写法（如电话带/不带区号）。
- 多语种：中文、英文、日文的姓名与证件模式不同。
- 上下文敏感：同一串数字可能是订单号也可能是身份证。
- 高召回要求：漏掉一条敏感信息即可能造成泄露。
- 过脱敏：脱敏过度会破坏文本可用性。

## 二、核心原理

PII 处理分「检测」与「脱敏」两步：

1. 检测：混合使用正则（固定格式）、NER（实体识别）、分类器（上下文判断）与字典，输出文本中 PII 的跨度与类型。
2. 脱敏：对训练数据做脱敏（替换/删除/泛化），防止模型记忆；对推理输出做实时脱敏，防止回显。

实践中推荐「多层互补」：正则兜底格式、NER 补上下文、人工规则补边界，以牺牲少量精度换取高召回。

（落地补充：）
- 脱敏应做成「管线关卡」而非一次性脚本，在数据入库、训练、推理返回三处部署检测。
- 任一环节命中敏感实体即掩码或拒绝，形成纵深防线而非单点防护。

## 三、形式化与数学基础

把检测视为序列标注，对 token $x_i$ 预测是否为 PII 及类型：

$$ \hat{y}_i = \arg\max_{c} P(c \mid x_{i-k:i+k}) $$

以召回优先评估，关注漏报代价：

$$ \text{Recall} = \frac{TP}{TP+FN},\quad \text{代价} \propto FN $$

脱敏映射可写为函数 $m(\cdot)$，要求敏感 span 被替换为占位且不可逆：

$$ m(x) = x \circ \prod_{s\in \text{PII}(x)} [\text{span}_s \to \text{[MASK]}_s] $$

## 四、代码实现

```python
# 用正则 + 占位做训练前脱敏（高召回优先）
import re

phone_re = re.compile(r"(?<!\d)1[3-9]\d{9}(?!\d)")
id_re = re.compile(r"(?<!\d)\d{17}[\dXx](?!\d)")

def redact(text):
    text = phone_re.sub("[PHONE]", text)   # 手机号占位
    text = id_re.sub("[ID_CARD]", text)    # 身份证占位
    return text

clean = redact("用户 13800001234 身份证 110101199001011234 已注册")
print(clean)  # 用户 [PHONE] 身份证 [ID_CARD] 已注册
```

## 五、与其他技术对比

| 维度 | 训练前脱敏 | 输出脱敏 |
| --- | --- | --- |
| 目标 | 防模型记忆 PII | 防输出回显 PII |
| 时机 | 数据入库前 | 推理返回前 |
| 方法 | 替换/删除/泛化 | 实时检测+掩码 |
| 失效后果 | 训练数据泄露 | 直接违规暴露 |

## 六、常见误区

- 「正则覆盖全」：新格式、变体写法会漏检，需 NER 互补。
- 「脱敏一次就够」：推理链路任意新入口都可能带回 PII。
- 「只脱显式」：隐式标识（组合特征）仍可重识别。
- 「忽略多语种」：非中文 PII 模式差异大，单语规则失效。
