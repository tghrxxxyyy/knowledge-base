# 合规与监管

> 对应 GDPR（被遗忘权/数据最小化）、中国《个人信息保护法》与《数据安全法》；参考 llm-course (mlabonne) 与 OWASP LLM Top 10。

## 一、背景与挑战

大模型在「收集—训练—推理—留存」全周期都受隐私法规约束。GDPR、中国个保法等要求数据处理合法、目的限定、最小必要、可删除、可审计。违规代价是高额罚款与声誉损失。核心挑战：

- 合法性基础：训练数据需有合法来源与授权。
- 最小必要：只收集与处理任务相关的数据。
- 被遗忘权：用户要求删除其数据，模型需支持（删数据甚至重训）。
- 跨境限制：数据出境受审批与本地化约束。
- 可审计：数据 lineage 与处理记录须可查。

## 二、核心原理

合规是「技术隐私 + 法律约束」的双线工程。落地要点：

1. 数据治理：建立数据清单、来源证明、授权记录（datasheet/lineage）。
2. 目的限定与最小必要：仅采集必要字段，训练前脱敏与匿名化。
3. 权利响应：提供被遗忘、访问、更正的技术接口。
4. 留存与销毁：设定留存期，到期安全删除或重训去个人化。
5. 跨境与审计：跨境传输走合规通道，处理全程留痕供监管核查。

技术侧与「PII 检测与脱敏」「差分隐私」「机器遗忘」协同，把法律要求变成可执行机制。

（落地补充：）
- 落地上把合规要求编码为管线关卡，数据授权、用途边界、留存告知任一不通过即阻断。

## 三、形式化与数学基础

被遗忘权可建模为：对用户 $u$ 的数据集 $D$，删除其样本得到 $D_{-u}$，需训练出「近似」原模型的 $M_{-u}$：

$$ \|M(D) - M(D_{-u})\| \le \eta $$

理想情况用机器遗忘（unlearning）使重训误差 $\eta\to 0$。最小必要可写为信息量约束：

$$ I(X_{\text{used}}; Y) \approx I(X_{\text{all}}; Y),\quad |X_{\text{used}}| \ll |X_{\text{all}}| $$

即在更少字段上保留几乎同等效用。

## 四、代码实现

```python
# 被遗忘权：标记删除并触发重训/遗忘
def request_forget(user_id, store, model):
    rows = store.query(user=user_id)
    if not rows:
        return "no_record"
    store.delete(rows)                 # 删除原始数据
    # 触发机器遗忘或增量重训
    model = machine_unlearn(model, rows) or retrain(model, store)
    log_forget_event(user_id, ts=now())  # 留存处置记录供审计
    return "done"

status = request_forget(user_id="u_123", store=user_store, model=lm)
```

## 六、常见误区

- 「匿名化即免责」：重识别风险仍在，匿名化非万能。
- 「不输出 PII 就合规」：训练数据来源非法同样违规。
- 「被遗忘=删记录」：模型记忆需遗忘或重训才彻底。
- 「跨境无碍」：数据出境受审批，随意传输违法。

## 九、演进与趋势

从「无规」到「告知同意」再到「全周期合规」；趋势是合规自动化（数据 lineage 平台）、机器遗忘工程化、以及把法规要求内建为训练管线的强制关卡。

## 十、小结

合规是隐私的「法律边界」。把合法性、最小必要、被遗忘权、审计要求转化为数据治理与模型机制（脱敏、DP、遗忘），才能让大模型在监管框架内安全运行。
