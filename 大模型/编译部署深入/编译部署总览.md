# 编译部署总览

> 对应 Chen et al., *TVM: An Automated End-to-End Optimizing Compiler for Deep Learning*, OSDI 2018；与 算子融合深入 / 内核调优深入 衔接。

## 一、背景与挑战

训练框架（PyTorch/TF）图与部署目标（GPU/CPU/边缘）差异大，需编译优化并落地。

## 二、核心原理

编译部署链路：前端解析 → 计算图优化 → 调度/调优 → 代码生成 → 运行时服务；TVM/MLIR/XLA 各擅其场。

## 三、数学形式

端到端延迟 $L = L_{pre} + L_{kernel} + L_{post}$；图优化主要压缩 $L_{kernel}$ 中的访存与冗余。

## 四、代码实现

```python
mod, params = relay.frontend.from_pytorch(scripted, shape)
with tvm.transform.PassContext(opt_level=3):
    lib = relay.build(mod, target="cuda")
```

## 五、与其他对比

- 与 算子融合深入（融合在此发生）接力。
- 与 模型导出ONNX深入（ONNX 常作中间表示）衔接。

## 六、常见误区

- 以为 build 一次处处快，需按目标硬件重编译调优。
- 忽略预处理/后处理也占端到端延迟。

## 八、面试题

- 编译部署和推理服务区别？答：编译解决“怎么生成高效 kernel”，服务解决“怎么调度请求跑起来”。

## 九、演进

解释执行 → 图编译（XLA） → 自动调优编译（TVM）。

## 十、小结

编译部署把训练图转成目标硬件高效代码，是性能落地中枢。
