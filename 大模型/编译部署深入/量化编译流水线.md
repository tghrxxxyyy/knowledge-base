# 量化编译流水线

> 对应 Jacob et al., *Quantization and Training of NNs for Efficient Integer-Arithmetic-Only Inference*, CVPR 2018（整数量化）；与 编译部署深入 衔接。

## 一、背景与挑战

FP16/INT8 部署能大幅降带宽与算力，但需把量化融进编译并对齐数值。

## 二、核心原理

训练后量化（PTQ）或量化感知训练（QAT）；编译期把 scale/zero-point 折叠进算子，用 fake quant 校准入界。

## 三、数学形式

量化 $r = S(q-Z)$、$q=\text{round}(r/S+Z)$；卷积整型近似 $\text{int}\approx \frac{S_w S_x}{S_y}(q_w-Z_w)(q_x-Z_x)+Z_y$。

## 四、代码实现

```python
qconfig = torch.ao.quantization.get_default_qconfig("fbgemm")
model.qconfig = qconfig
torch.ao.quantization.prepare(model, inplace=True)
```

## 五、与其他对比

- 与 模型导出ONNX深入（ONNX 量化格式）衔接。
- 与 算子融合深入（量化算子也需融合）相关。

## 六、常见误区

- 仅权重量化忽略激活分布漂移致精度崩。
- 校准集不具代表性使 scale 偏差大。

## 八、面试题

- PTQ 与 QAT 区别？答：PTQ 训练后直接量化，QAT 训练时插 fake quant 让网络适配量化误差。

## 九、演进

FP32 → FP16 → INT8(PTQ) → INT8(QAT)/INT4。

## 十、小结

量化编译把低精度收益做实，须校准保证数值对齐。
