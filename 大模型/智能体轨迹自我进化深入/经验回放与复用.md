# 经验回放与复用

> 对应 经验回放（experience replay）与 few-shot 复用。

## 一、背景与挑战

相似子任务反复出现，每次重规划浪费且质量不稳。需要把好经验“回放”到新情境。

## 二、核心原理

保存成功轨迹为高价值样本，新任务来时检索最相关若干作为 in-context 示范（few-shot）或作为计划模板微调。回放需配合质量过滤，避免劣质样本污染。

## 三、数学形式

检索权重：

$$w_i = \text{sim}(task,\, traj_i)\cdot q(traj_i)$$

$q$ 为轨迹质量分，低质不参与回放。

## 四、代码实现

```python
demos = topk(memory.search(task, k=3), by="quality")
plan = llm(plan_prompt + demos)
```

## 五、与其他对比

- 与 向量检索记忆 共享检索机制。
- 与 智能体推理成本建模深入 省去重复规划降本。

## 六、常见误区

- 回放未判质量，失败样本也被模仿。
- 演示过多挤占主任务上下文。

## 八、面试题

- 为何回放要按质量过滤？答：劣质样本会污染策略，使进化方向错误。

## 九、演进

无回放 → 全量回放 → 质量加权检索回放。

## 十、小结

经验回放让“做过的事”加速“新做的事”，复用即进化。
