# 向量索引选型实践

> 对应生产选型；向量数据库选型与调优实战（文件）衔接。

## 一、背景与挑战

内存/速度/召回三角权衡，需按规模选型。

## 二、核心原理

小规模高质量：HNSW；大规模省内存：IVF+PQ；流式更新：需支持增删的引擎。

## 三、数学形式

权衡：召回@k vs 查询延迟 vs 内存字节/向量。

## 四、代码实现

```python
if mem_budget_low: idx="IVF4096,PQ64"
else: idx="HNSW,M=32"
```

## 五、与其他对比

- 与 混合检索深入（向量召回组件）配合。
- 与 长文档切分深入（决定向量数）衔接。

## 六、常见误区

- 只看召回忽略内存成本。
- 索引参数未随数据分布调。

## 七、与开源书对应

- llm-course：https://github.com/mlabonne/llm-course

## 八、面试题

- 何时选 IVF+PQ 而非 HNSW？答：亿级且内存受限、可容忍略低召回时。

## 九、演进

单引擎 → 混合索引 → 自适应/分层。

## 十、小结

索引选型是内存/速度/召回的权衡，按规模与预算定。
