# 检索证据核查与归因

> 对应 Rashkin et al., *Measuring Attribution in Natural Language Generation*, Computational Linguistics 2023；Gao et al., *RARR*, ACL 2023；Es et al., *RAGAS*, EACL 2024。

## 一、背景与挑战

事实性判断需要外部证据。工程上不仅要判断对错，还要给出可核查的引用，使答案具备可追溯的归因链。

## 二、核心原理

标准框架是 AIS（可归因于识别来源）：一条陈述若通读引用证据的普通读者会同意其被支持，则该陈述可归因。

- 核查流程：断言抽取 → 证据检索 → 蕴含判定 → 未支持则改写或标注存疑（RARR 的编辑-归因思路）。
- RAG 系统评估还需分开度量检索质量与生成忠实度，避免把召回问题记为生成幻觉。

## 三、数学形式

归因率 $\mathrm{AIS}=\frac{1}{n}\sum_i\mathbb{1}\big[E_i\models c_i\big]$；RAG 侧忠实度 $\mathrm{Faith}=\frac{\#\{\text{被检索上下文支持的断言}\}}{\#\{\text{全部断言}\}}$。

另需上下文相关性与答案相关性两项，三者共同刻画「检索对不对、答案有没有超出证据」。

## 四、代码实现

```python
def attribution_report(claims, retrieve_fn, entail_fn):
    rows = []
    for c in claims:
        ev = retrieve_fn(c)
        rows.append((c, ev[:1], bool(entail_fn(ev, c))))
    ok = sum(1 for r in rows if r[2])
    return round(ok / max(len(rows), 1), 3), rows
```

## 五、与其他对比

- 与自一致性对照：证据核查能发现「稳定但错误」的信念，是唯一可纠正世界事实的路径。
- 与 事实一致性评估指标 衔接：蕴含判定是两者共享的核心算子。

## 六、常见误区

- 只要求答案带引用不校验引用是否真支持，产生「装饰性引用」。
- 把检索失败造成的空证据判为模型幻觉，掩盖了召回侧问题。

## 八、面试题

- AIS 定义要点？答：普通读者读过引用证据后会同意该陈述被支持，即可归因。
- 为何要拆分检索与生成指标？答：定位责任方，避免把召回不足误判为生成幻觉。

## 九、演进

带引用生成 → AIS 形式化（2023）→ 检索-编辑-归因流水线 → RAG 分项指标体系（2024）。

## 十、小结

证据核查是事实性治理的终点，其前提是引用可验证与检索/生成责任可分离。
