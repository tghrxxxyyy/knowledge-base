# 通信拓扑与开销

> 对应 Qian et al., *ChatDev*, ACL 2024（链式协作）；Wu et al., *AutoGen*, 2023（可编程会话拓扑）。

## 一、背景与挑战

多智能体的显性成本是 token：每条消息都可能进入其他智能体的上下文，形成组合爆炸。
拓扑（谁能看到谁、什么时候看到）既决定成本，也决定信息传播与误差扩散路径。

## 二、核心原理

- 常见拓扑：全连接（信息全、成本高）、星形（中心协调者，避免两两广播）、链式流水线（低成本、误差易累积）、树形分治（可并行、需合并）。
- 上下文预算应按拓扑分配：中心节点承担聚合与摘要职责，边缘节点只看必要片段。
- 摘要与引用机制：传递指针（工件 ID）而非全文，读取时按需拉取，显著降低重复注入。

## 三、数学形式

单轮 token 成本近似 $C=\sum_{(i,j)\in E}\big(|m_i|+|c_j|\big)$；全连接下 $|E|=m(m-1)$ 使 $C$ 随 $m$ 二次增长。

星形拓扑 $|E|=2(m-1)$ 线性增长，但中心节点上下文长度成为瓶颈，需引入分层摘要把长度压到 $O(\log m)$ 级别。

## 四、代码实现

```python
def star_round(hub, workers, task, llm):
    subtasks = hub.split(task)                      # 中心分派
    results = [w(s) for w, s in zip(workers, subtasks)]
    digest = [summarize(r, max_tokens=200) for r in results]  # 摘要回传
    return hub.merge(task, digest)

def cost_estimate(edges, msg_len, ctx_len):
    return sum(msg_len[i] + ctx_len[j] for i, j in edges)
```

## 五、与其他对比

- 与分布式系统通信模型：同样面临广播风暴与一致性问题，但这里「带宽」是上下文窗口，成本按 token 计价。
- 与单体长上下文方案：把所有信息交给一个长上下文模型可省通信，但失去并行与角色专精，且长上下文有效性会衰减。

## 六、常见误区

- 全量历史广播：每个智能体都携带完整会话，成本随轮数与人数双重膨胀。
- 只统计模型调用次数不统计 token，忽略上下文重复注入这一真正的成本大头。
- 中心协调者不做摘要，最终自身超长而截断关键早期信息。

## 八、面试题

- 为什么全连接多智能体难以扩展？答：消息与上下文成本随智能体数二次增长，且信息冗余不带来相应收益。
- 星形拓扑的瓶颈在哪？答：中心节点上下文长度与摘要质量，需分层摘要与引用式传递缓解。

## 九、演进

全量广播 → 星形协调 → 链式与树形分治 → 引用式工件传递 → 按预算自适应选择拓扑。

## 十、小结

拓扑设计等于成本设计：用星形或树形收敛通信、用摘要与引用切断重复注入。
