# 防御机制与指令层级

> 对应 Wallace et al., *The Instruction Hierarchy*, 2024；Chen et al., *StruQ*, 2024 与 *SecAlign*（用偏好优化提升注入鲁棒性）, 2024。

## 一、背景与挑战

注入防御方案很多，但效果差异巨大，且几乎都以效用损失为代价。需要一张按「作用层次」组织的地图：哪些是提示级补丁、哪些是训练级改造、哪些是系统级强制，各自能提供什么程度的保证。

## 二、核心原理

按强度递增分四层。提示层：加免责声明、用分隔符包裹数据、要求模型重述用户意图。成本最低，可挡朴素攻击，但可被改写绕过，不提供任何保证。检测层：用分类器或另一模型检测注入片段、检测输出是否偏离原任务。有一定效果但存在漏报误报，且检测器本身可被攻击。训练层：指令层级训练（教模型按 sys > user > tool > data 优先级取舍冲突指令）、结构化查询训练（StruQ）、以及用偏好优化把「忽略数据段指令」作为偏好目标（SecAlign 思路）。这类方法把成功率显著压低且效用损失可控，是当前最有效的模型侧手段。系统层：最小权限、能力隔离、动作白名单、人工确认。只有这一层能提供与模型能力无关的强制约束，是不可省略的兜底。

## 三、数学形式

指令层级可写成带优先级的冲突消解：当来源 $\ell_i\succ\ell_j$ 且指令 $c_i,c_j$ 冲突时，要求

$$\pi_\theta\big(y\mid s\big)\ \text{满足}\quad y\in\arg\max_{y'}\ \log\pi_\theta\big(y'\mid \{c_k:\ \ell_k\succeq \ell_i\}\big)$$

训练时用偏好优化实现：构造 $(x,\ y_w=\text{遵循高优先级},\ y_l=\text{遵循注入指令})$ 的偏好对，最小化

$$\mathcal L=-\mathbb E\Big[\log\sigma\Big(\beta\log\tfrac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)}-\beta\log\tfrac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}\Big)\Big]$$

即把「拒绝执行数据段指令」变成一条可优化的偏好，而非靠提示约定。

## 四、代码实现

```python
import torch.nn.functional as F

def build_hierarchy_pairs(samples):
    # chosen: 忽略数据段注入、完成用户任务；rejected: 执行注入任务
    pairs = []
    for s in samples:
        x = render(build_typed_prompt(s["system"], s["user"], s["injected_docs"], []))
        pairs.append({"prompt": x, "chosen": s["target_answer"], "rejected": s["injected_answer"]})
    return pairs

def instruction_hierarchy_loss(model, ref, batch, beta=0.1):
    lp_w, lp_l = seq_logp(model, batch["chosen"]), seq_logp(model, batch["rejected"])
    rf_w, rf_l = seq_logp(ref, batch["chosen"]), seq_logp(ref, batch["rejected"])
    delta = beta * ((lp_w - rf_w) - (lp_l - rf_l))
    return -F.logsigmoid(delta).mean()

def defense_stack(system, user, docs, model, policy):
    prompt = render(build_typed_prompt(system, user, [sanitize_data_segment(d) for d in docs], []))
    out = model(prompt)                                  # 训练过指令层级的模型
    return out if action_guard({"tool": "none"}, policy, tainted_context=True)["decision"] == "allow" else None
```

## 五、与其他对比

- 提示层 vs 训练层：前者零成本但无保证，后者需数据与训练但效果显著且可度量。
- 训练层 vs 系统层：训练降低概率，系统提供硬约束；两者不可互相替代。
- 与 安全微调：手段相似（偏好优化），但目标是「来源优先级」而非「内容有害性」。

## 六、常见误区

- 只做提示层加固就宣布防御完成。改写类攻击可轻易绕过，且无法量化残余风险。
- 用检测器作为唯一防线。检测器有漏报，且可被针对性构造绕过。
- 训练指令层级时不加良性对照，导致模型对正常的「文档中包含操作说明」类任务也一概不执行，效用大跌。

## 八、面试题

- 指令层级训练如何落地为可优化目标？答：构造「遵循高优先级来源」优于「执行数据段注入」的偏好对，用 DPO 类目标训练，使优先级成为学到的行为而非提示约定。
- 为什么系统层防御不可省？答：模型侧手段只能降低成功概率，唯有最小权限与动作校验能在模型被操纵时仍阻止实际危害。

## 九、演进

免责声明与分隔符 → 注入检测器 → 结构化查询训练（StruQ） → 指令层级与偏好优化（SecAlign 思路） → 与系统层能力隔离协同的纵深防御。

## 十、小结

注入防御应按层组织：提示层提门槛、检测层做筛查、训练层压概率、系统层保底线；只有四层齐备才能给出可度量的残余风险。
