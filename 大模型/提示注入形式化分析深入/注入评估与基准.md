# 注入评估与基准

> 对应 Liu et al., USENIX Security 2024（注入基准框架）；Debenedetti et al., *AgentDojo*, NeurIPS 2024。

## 一、背景与挑战

注入评估的核心困难是「双目标」：既要测攻击是否成功，又要测防御是否损害正常功能；而且攻击面随应用形态（纯问答、RAG、智能体）大幅变化。很多报告只给一个成功率数字，既不可复现也不可比。

## 二、核心原理

一份可用的注入评测需要固定六件事：应用形态与工具集合、攻击者可控内容的比例与位置、注入任务清单（贴近真实后果，如外泄密钥、改收件人、越权写文件）、注入构造模板集合、判定方式（注入任务是否完成 + 原任务是否完成）、以及是否允许多轮迭代攻击。动态环境基准（如 AgentDojo 形态）相比静态数据集的优势在于：注入效果由环境状态变化判定，而不是靠字符串匹配，避免了「模型只是复述了注入指令」被误判为成功。报告形式建议给出随攻击者可控比例变化的 ASV 曲线，并在每个点标注原任务完成率。

## 三、数学形式

以攻击者可控文档比例 $\rho$ 为自变量，报告二维曲线

$$\big(\rho,\ \mathrm{ASV}(\rho),\ U(\rho)\big),\qquad \mathrm{ASV}(\rho)=\mathbb E\big[\mathbb 1\{\text{注入任务完成}\}\big],\ \ U(\rho)=\mathbb E\big[\mathbb 1\{\text{原任务完成}\}\big]$$

防御比较应在同一 $\rho$ 与同一注入模板集合下进行，并额外报告无攻击时的效用 $U_0$ 以计算效用损失 $\Delta U=U_0-U_0^{\text{defended}}$。综合评分可用 $\mathrm{Score}=U_0^{\text{defended}}-\lambda\,\mathrm{ASV}(\rho)$，$\lambda$ 由业务风险偏好决定。

## 四、代码实现

```python
def injection_benchmark(model, defense, cases, injection_tasks, templates,
                        ratios=(0.0, 0.1, 0.25, 0.5), env=None):
    report = {}
    for rho in ratios:
        asv = utl = 0
        for c in cases:
            docs = list(c["docs"])
            k = int(len(docs) * rho)
            for i in range(k):
                tpl = templates[i % len(templates)]
                docs[i] = tpl(docs[i], injection_tasks[i % len(injection_tasks)])
            out = model(defense(c["system"], c["user"], docs))
            # 关键：用环境状态变化判定注入是否真正生效，而非字符串匹配
            asv += int(env.injected_effect_observed() if env else judge_injected(out))
            utl += int(judge_target(out, c["target_task"]))
        report[rho] = {"ASV": asv / len(cases), "target_success": utl / len(cases)}
    report["utility_no_attack"] = report[0.0]["target_success"]
    return report
```

## 五、与其他对比

- 与 安全评估（越狱）：都要求写明预算，但注入必须额外报告原任务效用与攻击者可控比例。
- 与 威胁模型形式化：那里定义指标，这里落到基准设计与判定实现。
- 与 智能体评测：动态环境判定是两者共享的方法论进步。

## 六、常见误区

- 用字符串匹配判定注入成功。模型复述注入指令、或部分执行都会造成误判，应以环境副作用为准。
- 只在 $\rho=1$（全部文档被控）下测试。既不现实又无法反映防御在低比例下的价值。
- 比较防御时更换注入模板集合。模板差异对结果影响极大，必须固定后再比较。

## 八、面试题

- 注入评测为什么倾向动态环境而非静态数据集？答：动态环境用真实副作用判定注入是否生效，避免字符串匹配带来的误判，且能覆盖多步链式污染。
- 报告注入防御效果的最少信息量？答：固定注入模板与工具集合下，随攻击者可控比例变化的 ASV 曲线，以及对应的原任务完成率与无攻击效用。

## 九、演进

零散攻击案例 → 静态注入数据集 → 三要素形式化基准 → 动态环境与真实副作用判定 → 面向智能体的持续红队。

## 十、小结

注入评估的可信度来自「固定攻击面 + 真实副作用判定 + 双目标报告」；缺少任一项，防御对比都只是数字上的错觉。
