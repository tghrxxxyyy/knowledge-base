# 激活重计算调度

> 对应 激活显存调度（与检查点协同）；与 梯度检查点深入 衔接。

## 一、背景与挑战

激活常是峰值显存主体；需在显存预算内安排哪些激活保留、哪些重算，并尽量重叠计算与传输。

## 二、核心原理

构建执行图，按张量生命周期与体积排程：可用 K-peak 调度将显存峰值控制在 $K$ 倍最优；结合检查点决定保存集合。

## 三、数学形式

调度峰值 $\le K\cdot OPT$（$K$ 近似常数）；目标在满足 $M\le M_{budget}$ 下最小化重算次数。

## 四、代码实现

```python
plan = schedule_activations(graph, mem_budget=M)   # 返回保存/重算表
```

## 五、与其他对比

- 与 梯度检查点深入（重计算机制）是调度对象。
- 与 显存与计算重叠（传输重叠）配合提吞吐。

## 六、常见误区

- 调度与框架实际分配不一致致预算失效。
- 忽视某些激活被多处复用（应保留一份）。
