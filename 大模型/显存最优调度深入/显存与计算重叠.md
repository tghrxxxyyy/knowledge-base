# 显存与计算重叠（Offload/Overlap）

> 对应 激活/状态 offload（ZeRO-Offload, Ren et al., 2021）；与 显存最优调度深入 总览衔接。

## 一、背景与挑战

把优化器状态/激活 offload 到 CPU/NVMe 省显存，但 PCIe 传输会拖慢；需与计算重叠掩盖延迟。

## 二、核心原理

在 GPU 计算本步时，异步把下一步要用的状态从 CPU 搬回；用双缓冲与 CUDA stream 重叠传输与计算，带宽瓶颈被掩盖。

## 三、数学形式

有效延迟 $L\approx\max(L_{compute}, L_{transfer})$（重叠后）而非二者之和；吞吐取决于较慢者。

## 四、代码实现

```python
with torch.cuda.stream(copy_stream):
    state = state.cpu()              # 异步 offload
compute_on_gpu()                     # 与传输重叠
```

## 五、与其他对比

- 与 梯度检查点深入（省激活）协同，offload 是另一种省法。
- 与 分布式优化器深入（ZeRO-Offload）同一技术。

## 六、常见误区

- 未重叠致传输串行化、训练极慢。
- NVMe 带宽不足时 offload 反成瓶颈。

## 八、面试题

- offload 为何要重叠？答：掩盖 PCIe 传输延迟，使带宽瓶颈不串行叠加到计算时间。

## 九、演进

同步 offload → 异步双缓冲 → 智能分层（GPU/CPU/NVMe）。

## 十、小结

offload 以带宽换显存，重叠执行是保持其可用的关键。
