# 工具错误处理与重试

> 对应 Chen et al., *Teaching Large Language Models to Self-Debug*, ICLR 2024；Gou et al., *CRITIC*, ICLR 2024（外部反馈纠错）。

## 一、背景与挑战

真实工具会超时、限流、返回空结果或结构变化，智能体若把异常当成普通文本继续推理，会产生「基于错误观测的自信答案」。
挑战在于区分可重试的瞬时故障与需要改变策略的语义失败，并避免无界重试造成成本爆炸与副作用重复。

## 二、核心原理

- 错误分层：传输层（超时、5xx）可退避重试；参数层（校验失败、4xx）应把报错回灌让模型改参数；语义层（结果为空）应换工具或换查询。
- 幂等设计：写操作携带幂等键，使重试不产生重复副作用；不可幂等操作重试前需人工确认或补偿事务。
- 失败也是观测：把结构化错误摘要写进上下文，比隐藏错误更有利于模型自纠，但要避免堆叠冗长堆栈污染上下文。

## 三、数学形式

指数退避第 $n$ 次等待 $t_n=\min(t_{\max},\, t_0\cdot 2^{n})\cdot(1+\epsilon)$，$\epsilon$ 为抖动，用于打散并发重试尖峰。

若单次成功率为 $p$ 且故障独立，$n$ 次内成功概率 $1-(1-p)^n$；但相关性故障（限流）会使独立性假设失效，需熔断而非加重试。

## 四、代码实现

```python
def call_with_policy(tool, args, msgs, llm, max_retry=3):
    for n in range(max_retry):
        try:
            return tool.run(**args)
        except Transient as e:                  # 瞬时故障：退避重试
            sleep(min(8, 0.5 * 2 ** n) * (1 + random()))
        except BadRequest as e:                 # 参数问题：回灌让模型改
            msgs.append({"role": "tool", "content": f"调用失败: {e}"})
            args = llm.fix_args(msgs, tool.schema)
    raise ToolGaveUp(tool.name)
```

## 五、与其他对比

- 与纯提示式自纠（无外部反馈）：有真实报错的纠错成功率显著更高，因为反馈是客观信号而非模型自我猜测。
- 与传统微服务重试：机制类似，但多了「让模型改写请求」这一层语义修复，需要控制它不去掩盖真实约束。

## 六、常见误区

- 对所有异常统一重试三次，把参数错误重复三遍，纯浪费。
- 把原始堆栈全量回灌，模型抓不住要点且上下文被挤占；应提取错误码与关键字段。
- 只统计最终成功率，不统计每类错误的分布，导致无法定位是描述问题、Schema 问题还是外部服务问题。

## 八、面试题

- 为什么参数错误不该退避重试？答：故障不是瞬时的，重复相同请求必然再失败，正确做法是把报错作为反馈让模型修正参数。
- 如何防止重试导致重复副作用？答：写操作用幂等键或事务补偿，并在编排层对不可幂等工具禁用自动重试。

## 九、演进

裸调用崩溃 → 统一 try 加固定重试 → 错误分层加退避熔断 → 报错回灌的模型自纠 → 带成本预算的策略化恢复。

## 十、小结

错误处理是智能体从演示走向生产的分水岭：分层归因、幂等保护、把结构化报错当成可学习的观测。
