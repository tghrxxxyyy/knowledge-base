# 多步与并行工具编排

> 对应 Shen et al., *HuggingGPT*, NeurIPS 2023；Kim et al., *LLMCompiler*, ICML 2024（并行调用编排）。

## 一、背景与挑战

复杂任务往往需要多次调用，串行 ReAct 每步都要一次模型往返，延迟与 token 成本随步数线性增长。
但并非所有调用都有依赖：相互独立的检索、查询可以并发执行，关键在于让模型先表达依赖关系而非逐步试探。

## 二、核心原理

- 把调用序列建模为有向无环图（DAG）：节点是调用，边表示某个参数依赖前一步输出。
- 先规划出 DAG（一次生成多调用及占位引用），再由调度器做拓扑排序，同层节点并发执行、结果回填占位符。
- 存在真正的动态依赖（下一步取决于上一步内容）时退回交错模式，实践中常混合：粗粒度并行 + 局部串行。

## 三、数学形式

设调用图 $G=(V,E)$，节点延迟 $\ell_v$，则串行时间为 $\sum_{v}\ell_v$，并行下界为关键路径 $\max_{p\in\text{paths}}\sum_{v\in p}\ell_v$。

加速比 $S=\frac{\sum_v \ell_v}{\text{critpath}(G)}$ 说明收益完全由依赖结构决定，链式任务并行无益。

## 四、代码实现

```python
import asyncio

async def run_dag(plan, tools):
    done, pending = {}, {n.id: set(n.deps) for n in plan}
    while pending:
        ready = [n for n in plan if n.id in pending and not pending[n.id]]
        outs = await asyncio.gather(*[tools[n.name].arun(**bind(n.args, done))
                                      for n in ready])
        for n, o in zip(ready, outs):
            done[n.id] = o; pending.pop(n.id)
            for s in pending.values():
                s.discard(n.id)
    return done
```

## 五、与其他对比

- 与单步 ReAct：ReAct 适应性强但往返多；DAG 编排延迟低但需要前瞻规划能力，规划错时纠错代价更大。
- 与工作流引擎（固定 DAG）：固定流程可控可测但不通用；LLM 生成 DAG 灵活但需要图合法性校验与循环检测。

## 六、常见误区

- 并发时忽略工具副作用与限流，导致重复下单或触发风控；写操作应串行或加幂等键。
- 认为并行必然更快；若关键路径由单个慢工具主导，加速比接近 1。
- 结果回填时把大段观测全部塞回上下文，导致后续步骤被无关文本挤爆，应做摘要或引用式传递。

## 八、面试题

- 什么情况下并行编排收益最大？答：多个彼此独立、单次延迟较高的只读调用，关键路径远短于总耗时。
- 如何兼顾并行与动态依赖？答：分段执行，每段内并行、段间由模型看到结果后再规划下一段，即 分段前瞻规划。

## 九、演进

单工具单步 → 交错串行（ReAct）→ 一次多调用批处理 → DAG 规划加并发调度 → 带成本模型的调度优化。

## 十、小结

多步编排的本质是依赖分析：先让模型交出依赖结构，再用调度器把独立分支压进同一时间片。
