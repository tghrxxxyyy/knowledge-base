# 输出过滤与回滚

> 对应 OWASP LLM Top 10（LLM02 敏感信息泄露）与 llm-course（mlabonne）安全章；亦见 HuggingFace 安全分类器实践。

## 一、背景与挑战

即便输入过滤、提示加固与模型对齐层层把关，输出仍可能越界：模型可能在长生成中「中途越权」、在工具调用结果里夹带隐私、或输出可被社会工程利用的内容。输出过滤是纵深防御的最后一道闸门——它不依赖输入是否「看起来安全」，而是直接审视模型产出的内容本身。其挑战在于生成是流式、长文本的，需在低延迟下做实时或近实时判定，且要兼顾误伤（把合法内容误判为有害）与漏报（放过真实有害输出）。

此外，当检测到危险输出时，简单截断可能留下半成品误导信息，需要设计「回滚/降级」策略，使最终呈现给用户的是安全、连贯的替代内容。

## 二、核心原理

输出过滤通常由并行检测器组成：

1. 安全分类：对生成文本做有害性（暴力、违法、偏见）分类，命中即拦截。
2. PII 检测：识别并脱敏个人身份信息（姓名、电话、密钥），防止训练数据或上下文泄露。
3. 注入/越权标记：检测输出中是否包含「系统提示泄露」或「工具越权指令」。
4. 拒答诱导校验：对模型自称「我无法…」但实际已泄露的假拒答做二次审查。
5. 回滚与降级：危险时回退到已生成的安全前缀，或直接返回标准安全拒绝，并记录事件供改进。

输出检测可与输入层的标签体系打通，形成统一的策略面。

## 三、形式化与数学基础（含 LaTeX）

对生成序列 $y=(y_1,\dots,y_T)$，逐段（或流式窗口）计算风险：

$$
r_t=\mathrm{clf}_{\text{safe}}(y_{1:t}),\qquad \mathrm{PII}_t=\mathrm{detect}_{\text{pii}}(y_{1:t})
$$

触发拦截的条件为任一段超过阈值：

$$
\text{block}(y)=\bigvee_{t=1}^{T}\big[\,r_t>\theta_{\text{safe}}\;\vee\;\mathrm{PII}_t>\theta_{\text{pii}}\,\big]
$$

当触发时回滚到最后一个安全点 $t^*=\max\{t: r_t\le\theta_{\text{safe}}\}$，并以安全回复替代：

$$
y_{\text{final}}=y_{1:t^*}\;\oplus\;\texttt{<SAFE\_REFUSAL>}
$$

## 四、代码实现

```python
# 流式输出过滤与回滚（结构示意）
def stream_filter(tokens, clf, pii_det, safe_reply):
    safe_prefix = []
    for t, tok in enumerate(tokens):
        safe_prefix.append(tok)
        window = "".join(safe_prefix)
        if clf.unsafe(window) or pii_det.has_pii(window):
            log_event(window)                 # 记录用于改进
            return safe_reply()               # 回滚为安全拒绝
    return "".join(safe_prefix)
```

## 五、与其他技术对比

- 仅输入过滤：假设输入安全则输出安全，忽略模型内在缺陷与工具副作用，存在盲区。
- 仅模型对齐：对已知分布有效，对零日攻击与上下文泄露脆弱。
- 输出过滤：直接审视产物，与前述层异构互补，是兜底闸门，但需在延迟与准确率间权衡。

## 六、常见误区

- 「输出一定安全」：对齐不充分或新攻击下，输出仍可能越界，必须检测。
- 「截断即安全」：生硬截断可能留下误导片段，应回滚到安全点或给完整拒绝。
- 「只查关键词」：有害内容常以改写、暗示呈现，需语义级分类器。
- 「误伤无所谓」：把正常医疗/法律建议误判会损害核心体验，需调阈值与人工抽检。

## 七、与开源书·权威来源对应

- OWASP LLM Top 10（LLM02 敏感信息泄露、LLM01 注入）定义输出层风险。
- llm-course（mlabonne）安全章与 HuggingFace 提供文本安全分类器实践。
- 各安全分类器（如毒性检测、PII 识别）作为可复用组件。

## 九、演进与趋势

从批后检测走向流式、近实时安全护栏（guardrail）：在生成每个 token 段即时判定，结合结构化输出约束（如 JSON schema）减少危险面。与可观测体系联动，使每次拦截都沉淀为训练/过滤改进样本，形成「检测—记录—再训练」闭环。

落地要点：
- 流式检测需权衡粒度与开销，过长窗口增加延迟，过短漏检片段；通常按语义句边界切分。
- 回滚策略应优先返回已生成的安全前缀，避免让用户看到被截断的半成品。
- 拦截事件统一上报，作为对抗训练与输入过滤的新样本来源。
输出护栏正从「事后过滤」演进为「生成期实时守护」。

## 十、小结

输出过滤与回滚直接审视模型产物，以安全分类、PII 检测与回滚降级构成纵深防御的兜底闸门。它弥补输入层与对齐层的盲区，需以 OWASP、HuggingFace 安全实践为基准，并以低延迟、低误伤、可记录为工程目标，是生产部署不可或缺的一环。
