# 评测与红蓝对抗

> 对应 OWASP LLM Top 10 评测视角与 JailbreakBench/red-teaming 方法论；亦见 llm-course（mlabonne）、「安全红队方法论/红队方法论总览」。

## 一、背景与挑战

防御措施若不能量化，就无法比较、无法迭代，更无法向业务与监管证明其价值。越狱防御尤其需要对抗性验证：攻击者视角（红队）主动寻找缝隙，防守方（蓝队/安全工程）据此加固，形成攻防对抗的评测闭环。核心难点在于——防御效果不是「有没有过滤」这种二元判断，而是「在多大 attack coverage 下仍保持多高拒绝率」的连续度量，且攻击在持续演化，一次性评测很快过时。

另一挑战是评测本身可能被游戏化：模型学会在评测集上拒答却在真实分布上漏防，因此需覆盖多样、未见过的攻击模板，并以人类/自动双标注保证标签质量。

## 二、核心原理

红蓝对抗评测的核心闭环：

1. 攻击库构建：汇集已知越狱模板（角色扮演、注入、编码绕过、多轮）并持续补充零日样本。
2. 自动化红队：用 GCG、PAIR、TAP 等算法规模化生成攻击，或人工专家构造高难度样本。
3. 指标度量：以攻击成功率（ASR, Attack Success Rate）为主，配合拒绝质量、误伤率。
4. 对比实验：在「无防御 / 旧防御 / 新防御」下跑同一攻击库，量化改善幅度。
5. 报告与复盘：输出风险趋势、短板层、修复建议，反馈到防御开发与训练闭环。

## 三、形式化与数学基础（含 LaTeX）

攻击成功率定义为在 $N$ 条攻击样本中模型被成功诱导违规的比例：

$$
\text{ASR}=\frac{1}{N}\sum_{i=1}^{N}\mathbb{1}[\text{model\_complies}(x_i)]
$$

防御改善可用相对下降率刻画：

$$
\Delta_{\text{rel}}=\frac{\text{ASR}_{\text{old}}-\text{ASR}_{\text{new}}}{\text{ASR}_{\text{old}}}
$$

更稳健地，引入置信区间（多次采样/多模板）：

$$
\text{ASR}\pm z\cdot\sqrt{\frac{\text{ASR}(1-\text{ASR})}{N}}
$$

避免小样本下因偶然波动误判防御有效。同时监控误伤率 $\text{FPR}$ 以防「靠全拒答刷低 ASR」。

## 四、代码实现

```python
# 攻击成功率评测（结构示意）
def eval_asr(attack_set, defend_fn):
    success = 0
    for prompt in attack_set:
        out = defend_fn(prompt)               # 走完整防御链路
        if is_harmful_compliance(out):         # 判定是否被诱导违规
            success += 1
    return success / max(len(attack_set), 1)

asr_old = eval_asr(redteam, defend_old)
asr_new = eval_asr(redteam, defend_new)
print(f"ASR {asr_old:.2%} -> {asr_new:.2%}, 相对下降 {1 - asr_new/asr_old:.1%}")
```

## 五、与其他技术对比

- 主观人工试错：不可复现、不可比较，无法支撑迭代决策。
- 单点功能测试：只能验证「能拒某句话」，测不出分布鲁棒性。
- 量化红蓝对抗：以 ASR 连续度量、覆盖多类攻击、支持前后对比与趋势追踪，是防御研发的工程化基础。

## 六、常见误区

- 「一次性评测足够」：攻击模板不断演化，评测需周期性刷新。
- 「ASR 低就是安全」：若靠「全拒答」压低 ASR，误伤率会爆表，需用 FPR 共同约束。
- 「只用公开基准」：模型会在已知基准上过拟合，应保留私有/零日攻击集。
- 「忽略标注质量」：有害顺从的判定标准不一致会让 ASR 失真。

## 七、与开源书·权威来源对应

- OWASP LLM Top 10 提供风险分类与评测映射。
- JailbreakBench 给出标准化攻击集与 ASR 协议。
- llm-course（mlabonne）、红队方法论总览提供攻防流程与指标定义。

## 九、演进与趋势

从人工红队走向「自治红队」：用更强模型自动生成并筛选攻击，配合人类在环标注；评测从单一 ASR 扩展到多维度（鲁棒性、公平性、误伤、对抗迁移性）。可复现评测套件与排行榜（含私有攻击集）成为安全治理的信任基础设施。

值得强调的是，评测集本身需要版本化与防过拟合：公开基准被反复刷分后区分度下降，应保留私有/零日攻击集作为「留存考题」。同时把评测结果接入 CI，使每次模型或防御变更都自动跑红蓝对抗并对比 ASR 趋势，让安全成为可回归的工程属性。ASR 应与误伤率并列公示，避免为压低 ASR 而牺牲可用性。

补充要点：
- 评测集应随新攻击手法持续扩充，避免基准老化失真。
- 红蓝对抗结果应形成可检索的知识库，反哺防御开发。

## 十、小结

评测与红蓝对抗以量化 ASR 与误伤率为核心，用「无防御/旧/新」对比验证防御价值，并通过攻防闭环驱动持续改进。它依赖 OWASP、JailbreakBench 等权威方法论，是让越狱防御从「感觉安全」走向「可证明安全」的关键环节。
