# 指令层级与越权防御总览

> 对应 Wallace et al., *The Instruction Hierarchy*, 2024；Perez & Ribeiro, *Ignore Previous Prompt*, 2022。

## 一、背景与挑战

系统提示、开发者指令、用户消息、工具返回混在一起，模型难分优先级，易被低优先级内容越权操控。

## 二、核心原理

建立明确层级：系统>开发者>用户>工具结果；越权即低层伪装成高层指令，需训练与结构双重防御。

## 三、数学形式

层级序 $L_{sys}>L_{dev}>L_{user}>L_{tool}$；越权发生当模型执行 $L_i$ 内容却误认来自 $L_j,j>i$。

## 四、代码实现

```python
assert role(user_msg) < role(system_msg)
```

## 五、与其他对比

- 与价值观冲突消解深入共享优先级。
- 与安全与能力权衡深入共享拒绝控制。

## 六、常见误区

- 以为提示写清层级模型就遵守。
- 忽视工具返回的低信任级。

## 八、面试题

- 指令层级为何必要？答：混合来源需优先级，否则低信任内容可伪装高层越权。

## 九、演进

无层级 → 软提示 → 显式层级训练。

## 十、小结

指令层级是提示注入防御的结构基础。
