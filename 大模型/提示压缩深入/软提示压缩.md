# 软提示与语义压缩

> 对应 soft prompt / 蒸馏式压缩；与 提示工程深入 衔接。

## 一、背景与挑战

硬文本压缩有损且不可逆；软提示用连续向量表示把长提示压成少量 embedding。

## 二、核心原理

用编码器把长 prompt 映射为少量可训练 soft token，冻结 LLM 微调这些 token 以重建任务行为，推理只传软提示。

## 三、数学形式

压缩：$\mathbf{S}=E_\phi(P)\in\mathbb R^{k\times d}$（$k\ll|P|$）；训练 $\min_\phi \mathcal L(\text{LLM}(\mathbf{S}), Y)$。

## 四、代码实现

```python
soft = prompt_encoder(hard_prompt)     # k 个向量
logits = model(inputs_embeds=soft)
```

## 五、与其他对比

- 比硬压缩更保信息但不可读、需训练。
- 与 参数高效微调深入（prefix tuning）同用 soft token。

## 六、常见误区

- 软提示不可解释、难调试。
- 任务切换需重训软提示。

## 八、面试题

- 问：软提示压缩优劣？答：保信息且省 token，但需训练、不可读、泛化窄。

## 九、演进

硬压缩 → soft token → 检索式软提示库。

## 十、小结

软提示压缩以连续向量换极致压缩，适合固定任务的常驻提示。
