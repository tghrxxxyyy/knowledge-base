# 引用溯源与证据对齐

> 对应 Asai et al. 2023《Self-RAG》、引用增强生成（Citation Generation）研究，及 Lewis et al. 2020 RAG。

## 一、背景与挑战

可信生成要求「言之有据」：模型的每一条事实性陈述都应能追溯到具体来源片段，而非凭空生成。引用溯源（citation / grounding）要解决两个难题：

- **生成侧**：模型需在学习生成时同时决定「在哪句话后插入哪个引用标记」。
- **校验侧**：反过来，如何自动判断一条引用是否真正支持其对应的 claim（而非为了「看起来可信」而凑引用）。

在长文档、多源检索场景下，错误的引用比没有引用更具迷惑性，因为它伪装成可验证。

## 二、核心原理

证据对齐把「生成—引用—校验」串成闭环：

1. **引用生成**：要求模型输出带标记的文本，如「北京人口约 2189 万¹」，其中上标映射到检索结果编号。
2. **标记映射**：把引用标记解析为对应的检索片段（chunk / sentence）。
3. **支撑校验**：用自然语言推断（NLI）或 LLM 评判，判断 claim 是否被该片段蕴含（entailment）。
4. **聚合**：以 claim 级支撑度汇编成文档级可信分。

关键在于「对齐是细粒度的」——句子级甚至短语级对齐优于整段级，能暴露「半句有源、半句编造」的情形。

## 三、形式化与数学基础

设回答含 claim 集合 C，检索证据集合 E。对每个 claim c，其最佳证据支撑度：

$$
A(c) = \max_{e \in E} \text{sim}(c, e)
$$

其中 sim 可为蕴含概率（NLI）或向量 / LLM 打分，取值 [0,1]。文档整体对齐得分：

$$
A = \frac{1}{|C|}\sum_{c \in C} A(c)
$$

若要求「强支撑」，可改为仅计 sim 超过阈值 τ 的比例：

$$
A_\tau = \frac{1}{|C|}\sum_{c} \mathbb{1}[A(c) \ge \tau]
$$

反事实校验（把证据替换为无关文本，看 claim 是否仍被支持）可进一步检测「伪引用」。

## 四、代码实现

```python
# 证据对齐：为每个 claim 找最佳支撑证据（示意）
def align_claims_to_evidence(claims, evidences, scorer):
    results = []
    for c in claims:
        best = max(evidences, key=lambda e: scorer(c, e))
        results.append((c.text, best.id, scorer(c, best)))
    return results

# scorer 可用 NLI 蕴含概率或 LLM 评判
def nli_score(claim, evidence):
    return nli_model(f"{evidence} </s> {claim}")["entailment"]
```

## 五、与其他技术对比

- **无引用生成**：最自由但不可审计，事实错误难以定位。
- **仅计数引用**：统计「引用数量」毫无意义，关键是支撑质量。
- **Self-RAG 批判标记**：在生成时自评 grounded，是引用溯源的生成侧实现。
- **RAGAS faithfulness**：从答案反推是否由上下文支撑，是校验侧思路。

## 六、常见误区

- **误区一：有引用 = 可信**——引用可能与 claim 无关或仅部分支持。
- **误区二：整段对齐足够**——长证据里常只有一句支撑，需句子级对齐。
- **误区三：检索命中即支撑**——检索到文档不等于该句被蕴含。
- **误区四：伪引用无害**——错误引用比无引用更危险（伪装可信）。

## 九、演进与趋势

从「生成后补引用」走向「生成时联合决策引用位置与内容」；细粒度句子级对齐、反事实校验与可点击溯源界面成为可信系统的标配。多模态证据（图表、表格）对齐也在发展中，具体以官方最新文档为准。

## 十、小结

引用溯源把可信性从「声明」变为「可验证」。真正的价值不在引用数量，而在每个 claim 与证据之间经过细粒度、可反事实检验的对齐。
