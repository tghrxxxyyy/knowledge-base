# 事实性自动评测流水线

> 对应 Es et al. 2023 RAGAS、Lewis et al. 2020 RAG，及 LLM 评测工程化实践（lm-evaluation-harness）。

## 一、背景与挑战

事实性不能只在发布前「抽测一次」。在模型持续迭代、提示词频繁调整、检索库不断更新的生产环境中，幻觉可能随任何一次改动悄悄恶化。人工抽检无法高频回归，因此需要一个**端到端、可复现、可告警的自动事实性评测流水线**。

核心挑战：

- **稳定性**：评测结果需可复现，避免评判 LLM 随机性掩盖真实变化。
- **阈值治理**：告警阈值不能一成不变，长尾类别需单独监控。
- **可定位**：出问题时能区分是「检索退化」还是「生成编造」。

## 二、核心原理

流水线把事实性度量串成自动化阶段，典型架构为：

1. **生成（Generate）**：以固定 prompt 套件驱动被测模型产出回答。
2. **原子事实抽取（Extract）**：拆成可验证 claim。
3. **检索 / 比对（Retrieve & Verify）**：每个 claim 与知识源比对，得支撑标签。
4. **指标聚合（Score）**：算忠实度、幻觉率、引用对齐等。
5. **告警与归档（Alert & Store）**：超阈值触发告警，结果入库形成趋势曲线。

为可复现，prompt、评判模型版本、知识源快照都应版本化；长尾类别（如特定领域、特定语言）单独分组监控，避免被均值掩盖。

## 三、形式化与数学基础

端到端事实分可拆为忠实度 F 与对齐度 A 的加权：

$$
Q = \alpha F + (1-\alpha) A
$$

其中 F 为原子事实支撑率（见事实性幻觉度量章节），A 为引用对齐度（见引用溯源章节）。对类别 k 设独立阈值 τ_k：

$$
\text{alert}_k = \mathbb{1}[Q_k < \tau_k]
$$

阈值 τ_k 可由历史基线动态估计，例如：

$$
\tau_k = \mu_k - \beta \sigma_k
$$

β 控制严格度。趋势监控可统计滑动窗口均值变化 Δ，超过 δ 即提示回归。

## 四、代码实现

```python
# 事实性自动评测流水线骨架（示意）
def fact_pipeline(gen_fn, questions, extract_fn, verify_fn, score_fn):
    report = []
    for q in questions:
        answer = gen_fn(q)
        claims = extract_fn(answer)
        evidences = verify_fn(claims)        # 检索 + 支撑判定
        score = score_fn(claims, evidences)
        report.append({"q": q, "score": score})
    return report

# 按类别分组告警
def check_alert(by_category, thresholds):
    flags = {}
    for cat, scores in by_category.items():
        flags[cat] = mean(scores) < thresholds.get(cat, 0.8)
    return flags
```

## 五、与其他技术对比

- **手工评测**：准但慢，无法高频回归。
- **一次性脚本**：可跑但缺版本治理与告警，易「跑完即忘」。
- **完整流水线**：快、可复现、可告警，但需持续校准阈值与评判模型。
- **lm-evaluation-harness**：提供标准化任务与指标，可嵌入流水线作为评测后端。

## 六、常见误区

- **误区一：阈值固定不变**——数据分布漂移后误报 / 漏报激增。
- **误区二：只看总平均分**——长尾类别崩溃被均值掩盖。
- **误区三：评判模型不版本化**——升级评判 LLM 后历史曲线不可比。
- **误区四：告警即回滚**——应先区分噪声波动与真实回归。

## 九、演进与趋势

从「离线条样评测」走向「实时采样 + 在线回归 + 自动回滚候选」；结合持续评测（continual evaluation）与评测即代码（evaluation-as-code），把事实性变成可运营指标。具体实现以各团队工程与官方工具为准。

## 十、小结

自动事实性流水线让「可信性」从一次性的发布检查变为可运营的日常指标。其关键不在算出一个分，而在可复现、可分组告警、可趋势追溯。
