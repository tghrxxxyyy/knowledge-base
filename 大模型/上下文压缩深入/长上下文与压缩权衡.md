# 长上下文与压缩的权衡

> 对应长上下文性价比研究；与 KV缓存优化深入 / 推理经济成本深入 衔接。

## 一、背景与挑战

原生长上下文贵且易“中间丢失”；压缩省成本但可能丢信息，需按任务选策略。

## 二、核心原理

高信息密度任务（含关键长尾事实）宜长上下文或轻压缩；噪声多的检索场景宜先压缩；可组合“长上下文+压缩”分层。

## 三、数学形式

期望效用 $U = \text{acc}(L, r) - c\cdot L\cdot(1-r)$；在预算 $c$ 下选上下文长度 $L$ 与压缩率 $r$。

## 四、代码实现

```python
if density(ctx) < tau:
    ctx = compress(ctx, rate=0.5)
answer = llm(question, ctx)
```

## 五、与其他对比

- 与 检索增强失效分析深入 共判“该不该压”。
- 与 流式生成与增量解码深入 共享成本视角。

## 六、常见误区

- 盲目追长上下文忽略噪声放大。
- 用固定压缩率不随任务调。

## 八、面试题

- 何时用压缩而非更长上下文？答：检索噪声多、成本敏感且信息可压缩时。

## 九、演进

全量长上下文 → 检索+不压 → 检索+压缩。

## 十、小结

长上下文与压缩非对立，按信息密度与成本动态组合最佳。
