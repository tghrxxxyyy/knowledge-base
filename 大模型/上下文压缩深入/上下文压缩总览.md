# 上下文压缩总览

> 对应 Jiang et al., *LLMLingua / LongLLMLingua*, 2023；Li et al., *Selective Context*, 2023。

## 一、背景与挑战

长上下文（32k–1M token）带来高昂 KV 缓存与注意力成本；而检索喂入的上下文常含大量冗余与噪声，压缩可在几乎不损质量下显著降本。

## 二、核心原理

在文本送入 LLM 前做压缩：删除冗余/低信息句、抽象为短摘要，或映射为可学习的软提示向量；目标是保留任务相关信息、压掉噪声。

## 三、数学形式

压缩率 $r = |C_{comp}| / |C_{orig}|$；优化目标 $\min_{r}\ \mathcal L(C_{comp}) + \lambda\,r$，其中 $\mathcal L$ 为下游任务损失。

## 四、代码实现

```python
from llmlingua import PromptCompressor
comp = PromptCompressor()
out = comp.compress_prompt(long_context, target_token=500, rate=0.5)
compressed = out["compressed_prompt"]
```

## 五、与其他对比

- 与 检索增强失效分析深入 互补：压缩先去噪，减少噪声上下文干扰生成。
- 与 长文档切分深入 不同侧：切分决定索引粒度，压缩决定送入模型的信息量。

## 六、常见误区

- 压缩过度丢失关键实体/数字，导致答案事实错误。
- 把压缩率等同质量：高率不一定低损，取决于信息密度。

## 八、面试题

- 为何长上下文仍要压缩？答：降 KV 与注意力开销、去检索噪声，提升性价比与稳定性。

## 九、演进

无压缩 → 摘要式压缩 → 选择性删除（Selective Context）→ 软提示压缩（LLMLingua/AutoCompressor）。

## 十、小结

上下文压缩以更低 token 成本逼近长上下文效果，是 RAG 与长文场景的性价比关键。
