# 上下文压缩质量评估

> 对应压缩评测基准（如 LongLLMLingua 实验）；与 模型评测指标深入 衔接。

## 一、背景与挑战

压缩不能只看长度，须量化对下游任务的影响，避免“省了 token 丢了答案”。

## 二、核心原理

在 QA/摘要/推理基准上对比压缩前后准确率；报告压缩率与保真度；用人工抽检关键信息保留率。

## 三、数学形式

保真度 $F = \text{acc}(C_{comp}) / \text{acc}(C_{orig})$；信息保留 $\rho = |K\cap K_{comp}|/|K|$（$K$ 为关键事实集）。

## 四、代码实现

```python
base = eval_qa(llm, ctx)
comp = eval_qa(llm, compress(ctx))
print("保真度", comp/base, "压缩率", len(comp)/len(base))
```

## 五、与其他对比

- 与 检索增强失效分析深入 共用评测框架。
- 与 指令微调数据质量深入 的“少而精”理念呼应。

## 六、常见误区

- 只在单基准评测致结论偏。
- 忽视延迟/成本双指标。

## 八、面试题

- 如何证明压缩无损？答：在多个下游任务对比准确率与关键信息保留率，并测成本收益。

## 九、演进

长度比对 → 任务准确率 → 多维度（保真/成本/延迟）。

## 十、小结

压缩质量须以任务保真与成本双指标评估，方知进退。
