# 推理时安全解密

> 对应安全加载（enclave 内解密）；机密计算（Intel SGX、AWS Nitro）。Nitro 提供机密计算。

## 一、背景与挑战

权重解密后的明文在内存中若被 dump，仍会泄露，需受保护内存加载。

## 二、核心原理

在可信执行环境（TEE）内解密权重，明文仅存于 enclave 受保护内存，外部不可读。

## 三、数学形式

信任边界：明文 $w$ 仅存在于 $TEE$ 内；外部视图只有 $E_k(w)$。

## 四、代码实现

```python
with enclave.context() as ec:
    w = ec.decrypt(blob, key)
    out = model(w, x)
```

## 五、与其他对比

- 与 静态加密存储（解密前）衔接。
- 与 机密计算保护（环境）共享。

## 六、常见误区

- 解密在普通进程内存致可被 dump。
- TEE 度量未校验致加载被篡改镜像。

## 七、与开源书对应

## 八、面试题

- 为何要 TEE 内解密？答：明文仅存于受保护内存，防外部 dump 与篡改。

## 九、演进

明文内存 → 进程加密 → TEE 内解密。

## 十、小结

推理时安全解密把明文暴露面压到最小，配合静态加密形成闭环。
