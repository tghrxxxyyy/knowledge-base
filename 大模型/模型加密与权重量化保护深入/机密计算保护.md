# 机密计算保护

> 对应机密计算（Confidential Computing Consortium）；TEE 保护使用中数据。CCC 推动 TEE 标准。

## 一、背景与挑战

数据使用中（推理时）的保护最难，传统加密只覆盖静态与传输，使用中仍裸奔。

## 二、核心原理

机密计算用硬件 TEE 隔离代码与数据，提供远程证明（attestation）验证运行环境可信。

## 三、数学形式

远程证明：验证方校验 $proof = Sign_{HW}(measurement)$，确认 $TEE$ 未篡改。

## 四、代码实现

```python
report = tee.attest()
verify_remote(report, expected_hash)
```

## 五、与其他对比

- 与 推理时安全解密（解密位置）衔接。
- 与 权保护总览（运行时）共享。

## 六、常见误区

- 忽略远程证明，误信未度量环境。
- TEE 性能开销未评估致吞吐降。

## 八、面试题

- 机密计算解决什么？答：保护使用中数据，远程证明确保运行环境未被篡改。

## 九、演进

静态加密 → 传输加密 → 使用中机密计算。

## 十、小结

机密计算补全数据全生命周期保护，是权重运行时安全的关键。
