# 蒸馏的局限与经验

> 对应 Hinton 2015 蒸馏讨论与 huggingface/trl 实践文档。

## 一、背景与挑战

蒸馏并非总是有效：当学生容量远小于教师，或任务高度依赖教师的隐含偏见时，蒸馏可能失效甚至退化。

## 二、核心原理

蒸馏受限于"学生能否表达教师函数"。容量差距过大时，软标签的细粒度信息学生无法拟合。此外教师若存在分布偏差，学生会继承。

## 三、形式化与数学基础

设学生假设空间 $ \\mathcal H_s $，教师函数 $ f_t $：

$ \\min_{h\\in\\mathcal H_s}\\mathcal L(h,f_t)\\to\\infty \\ \\text{若}\\ f_t\\notin\\text{span}(\\mathcal H_s) $

容量不足导致不可逼近。

## 四、代码实现

```python
def capacity_gap_check(teacher_ppl, student_ppl, threshold=2.0):
    if student_ppl > threshold * teacher_ppl:
        print("学生容量不足, 蒸馏收益有限")
# 监控学生相对教师的退化程度
```

## 五、与其他技术对比

- 量化/剪枝不改变容量上限，蒸馏受学生容量约束。
- 与 LoRA 适配不同，蒸馏是跨模型能力迁移。

## 六、常见误区

- 指望极小学生逼近超大教师；不现实。
- 只用软标签，丢失真实分布锚定。

## 九、演进与趋势

渐进式蒸馏（学生再作教师）、多教师与课程式蒸馏缓解容量问题。

## 十、小结

蒸馏受学生容量与教师质量双重约束，合理设定规模差与混合真实标签是关键。
