# 模型压缩总览

> 对应 Han et al., *Deep Compression* (ICLR 2016, arXiv:1510.00149)、Frantar et al., GPTQ (arXiv:2210.17323)、Dettmers et al., LLM.int8() (arXiv:2208.07339)、Lin et al., AWQ (arXiv:2306.00978)，以及官方仓库 github.com/TimDettmers/llm.int8、github.com/AutoGPTQ/AutoGPTQ、github.com/vllm-project/vllm、github.com/ggml-org/llama.cpp 与开源课程 github.com/mlabonne/llm-course；关联篇章「量化基础」「INT8 量化」「GPTQ 与 AWQ」「模型剪枝」「知识蒸馏」「LoRA」。

## 一、背景与挑战

千亿参数的 LLM 把「显存 = 参数量 × 精度字节数」这条账算得非常残酷：一个 70B 模型即便用 FP16 存放，仅权重就需要 140GB，还没算 KV cache、激活值和优化器状态。单卡 80GB 的 A100/H100 根本放不下，推理必须多卡切分，带宽成为吞吐瓶颈——自回归解码是访存受限（memory-bound）的，每生成一个 token 都要把全部权重读一遍，此时算力利用率往往不到 1%。训练侧同样昂贵：全参微调 7B 模型需要的 Adam 状态是权重本身的 8 倍以上显存。

模型压缩要同时解决四件事：**降显存**（能不能装下）、**降带宽**（解码吞吐）、**降算力**（prefill 速度与训练成本）、**保精度**（下游任务不塌）。这四者并不总是一致——例如纯权重量化几乎不省算力，只省访存；结构化剪枝能省 FLOPs 但要重训。大模型时代的新挑战是：(1) 巨大模型不可能从头重训验证压缩效果，必须走 **post-training** 路线；(2) outlier channel 现象让朴素的 per-tensor 量化在 4bit/8bit 下直接崩掉；(3) 量化、剪枝、蒸馏常被叠加使用，相互放大误差，需要统一的选型框架而不是单点技巧。

## 二、核心原理

### 2.1 剪枝（Pruning）

砍掉冗余权重或结构单元。按粒度分两类：

- **非结构化剪枝**：按 |w| 阈值砍掉单个权重，得到稀疏矩阵。压缩率高但硬件需要稀疏 kernel（2:4 半结构化稀疏是 Ampere+ 的原生支持），否则无法加速。
- **结构化剪枝**：整通道/整头/整层删除，直接得到更瘦的稠密模型，无需特殊 kernel，是部署友好路线。大模型时代流行 **layer pruning / slice-wise** 剪枝（如 SliceGPT 的行/列删除），因为它可以复用稠密推理路径。

剪枝通常遵循「训练 → 打分 → 剪枝 → 微调恢复」的迭代流程，LLM 时代还发展出 Wanda（用激活幅值给权重打分，无需重训）、SparseGPT（用二阶信息逐列更新补偿误差）等 one-shot 方法。

### 2.2 量化（Quantization）

把 FP16/BF16 权重映射到 INT8/INT4/FP8 等低比特表示，是当前收益最大、工程生态最成熟的压缩手段：

- **PTQ（训练后量化）**：不碰训练，直接校准数据上求 scale。大模型基本只用 PTQ，代表有 GPTQ（逐层二阶误差最小化 + 量化后用校准集做权重补偿）、AWQ（按激活幅度识别 salient channel，对其保护性缩放）、NF4（bitsandbytes 的 4bit normalfloat，信息论上对正态分布权重最优）。
- **W8A8 / LLM.int8()**：权重 INT8 + 激活 INT8，面对 outlier feature（少数通道激活值达数千）用 vector-wise 量化与部分 channel 保留在 FP16 处理。
- **KV cache 量化 / 激活量化**：解码瓶颈在于访存，KV cache 常占长上下文显存的大头，FP8/KIVI 类方法把它也压下去。

### 2.3 蒸馏（Distillation）

小模型拟合大模型的软标签（logits）或中间表征。核心公式是 Hinton 版蒸馏损失：用温度 $T$ 软化教师分布，让学生同时学习软标签与真标签。大模型时代它有两个杀手级应用：一是「**小模型先蒸后训**」（如 Mistral 7B 级别的模型吸收 70B 教师的推理数据），二是把长尾能力从大模型迁到小模型以降低服务成本。蒸馏必须重新训练，成本高于纯 PTQ，但精度上限通常更高。

### 2.4 低秩分解与共享

权重矩阵若近似低秩，可用 $W \approx BA$（$B \in \mathbb{R}^{m\times r}, A \in \mathbb{R}^{r\times n}, r \ll \min(m,n)$）替换，参数量从 $mn$ 降到 $r(m+n)$。这正是 LoRA 的参数高效微调视角——微调只更新低秩增量。权重共享（如 Albert 复用 embedding、跨层 tied weights）用结构先验换参数，但共享过头会限制容量，大模型时代较少单独使用，多与量化叠加。

### 2.5 选型决策树

按场景走：只要装不下、且要立刻上线 → **权重量化（GPTQ/AWQ 4bit，KV 量化配套）**；要真实 FLOPs 加速（prefill 为主）→ **结构化剪枝 / 小模型蒸馏**；要压到端侧 1-3B 级别 → **蒸馏从头训 + 4bit**；显存吃紧但拒绝精度风险 → **NF4 + LoRA（冻结量化基座）**；训练场景省 Adam 状态 → **8bit optimizer + LoRA**。经验法则：**先量化、再蒸馏、最后才动结构**，因为量化可逆且验证成本最低。

## 三、形式化与数学基础

线性量化（对称量化）映射：

$$q = \mathrm{clamp}\left(\mathrm{round}\left(\frac{w}{s}\right), -2^{b-1}, 2^{b-1}-1\right), \quad s = \frac{\max(|w|)}{2^{b-1}-1}, \quad \hat{w} = s \cdot q$$

GPTQ 的目标是对每层权重求解带约束的二阶误差最小化：

$$\arg\min_{\hat{W}} \| WX - \hat{W}X \|_2^2$$

利用 Hessian 近似 $H = 2XX^\top$，逐列量化并对未量化权重做误差补偿更新 $\hat{W}_{:,>i} \mathrel{-}= \delta_i \, \text{row}(H^{-1}_{i,>i})$——这就是 GPTQ 「量化一列、补偿其余」的数学本质。蒸馏损失：

$$\mathcal{L} = (1-\lambda)\,\mathrm{CE}(y, p_s) + \lambda T^2 \,\mathrm{KL}\!\left(\mathrm{softmax}(z_t/T) \,\|\, \mathrm{softmax}(z_s/T)\right)$$

$T^2$ 因子用于补偿温度带来的梯度尺度。低秩近似由 Eckart–Young 定理保证：取 SVD 前 $r$ 个奇异值是 Frobenius 范数意义下的最优 rank-$r$ 近似，误差 $\|W - W_r\|_F = \sqrt{\sum_{i>r}\sigma_i^2}$。非结构化剪枝常以 $\|W \odot M\|_0 \le k$ 约束下的损失增长 $\Delta \mathcal{L} \approx \frac{1}{2}\,\delta w^\top H\, \delta w$（OBD/OBS 框架）来选择该剪谁。

## 四、代码实现

```python
import torch

# ---------- 1) 对称 INT8 权重量化（PTQ 最小实现，带 per-channel scale） ----------
def quantize_int8_per_channel(w: torch.Tensor):
    # w: [out, in]，逐输出通道求 scale，避免 outlier 通道拖垮整体精度
    scale = w.abs().amax(dim=1, keepdim=True) / 127.0          # 对称量化，2^7 - 1 = 127
    q = torch.round(w / scale).clamp(-128, 127).to(torch.int8)  # 存储只需 1 byte
    w_hat = q.float() * scale                                    # 推理前反量化（或用 kernel 融合）
    return q, scale, w_hat

def sq_error(w, w_hat):
    return (w - w_hat).pow(2).sum().item()  # 校准：选 scale 使该误差最小

# ---------- 2) 蒸馏损失（软标签 + 硬标签，含温度缩放） ----------
def distill_loss(student_logits, teacher_logits, labels, T=4.0, alpha=0.7):
    p_t = torch.softmax(teacher_logits / T, dim=-1)
    log_p_s = torch.log_softmax(student_logits / T, dim=-1)
    kd = torch.nn.functional.kl_div(log_p_s, p_t, reduction="batchmean") * (T * T)
    ce = torch.nn.functional.cross_entropy(student_logits, labels)
    return alpha * kd + (1 - alpha) * ce   # T^2 补偿温度造成的梯度缩小

# ---------- 3) 非结构化 magnitude pruning 掩码 ----------
def magnitude_prune(weight, sparsity=0.9):
    k = int(weight.numel() * (1 - sparsity))
    thresh = weight.abs().flatten().kthvalue(k).values      # 只保留 |w| 最大的 k 个
    mask = (weight.abs() >= thresh).float()
    return weight * mask, mask                                # 剪枝后需继续微调恢复精度

# 生产建议：PTQ 走 AutoGPTQ/AWQ 的校准流水线（256~512 条领域样本即可），
# 不要自己手写 scale 搜索；上面的实现只用于理解与单元验证。
```

## 五、与其他技术对比

| 维度 | 量化 (PTQ) | 剪枝（结构化） | 知识蒸馏 | 低秩/LoRA | 权重共享 |
|------|-----------|---------------|----------|-----------|----------|
| 主要节省 | 显存、访存带宽 | 算力 FLOPs | 模型规模、端到端成本 | 参数、优化器状态 | 参数 |
| 是否需训练 | 否（校准即可） | 是（需恢复微调） | 是（需重训或继续预训练） | 微调时是 | 预训练时确定 |
| 加速效果 | 解码吞吐提升明显，prefill 有限 | 直接省 FLOPs | 换成小模型后全面加速 | 微调收益，推理需合并 | 有限 |
| 精度风险 | 低（4bit 时中等） | 中（层剪激进则掉点） | 中（取决于数据配比） | 低 | 中 |
| 生态成熟度 | 最高（vLLM/llama.cpp/GPTQ 全支持） | 中（依赖 kernel） | 高 | 高（PEFT 标配） | 低 |
| 可叠加性 | 可与剪枝/蒸馏叠加 | 可与量化叠加 | 可先蒸后量化 | 与量化共存（QLoRA） | 弱 |

## 六、常见误区

1. **「量化 4bit 一定掉点严重」**：领域校准集 + GPTQ/AWQ 下，多数任务相对 FP16 掉点在 1% 以内；真正崩的往往是用随机校准数据、或压到 2bit/3bit 的场景。
2. **「量化能大幅提速」**：权重量化省的是显存与加载带宽，对访存受限的解码是实打实的吞吐收益；但对 compute-bound 的大 batch prefill，INT4 kernel 反而可能更慢，需实测。
3. **「剪枝掉点就该砍更少」**：非结构化高稀疏度若没有 2:4 这类硬件支持，纸上压缩率再高也不省时间；部署导向应优先结构化剪枝。
4. **「蒸馏不需要数据」**：蒸馏对数据分布极敏感，用通用语料蒸一个领域模型会丢掉教师的领域优势，必须用目标域样本。
5. **「压缩方法可以随意叠加、线性收益」**：先激进量化再剪枝会叠加误差，且校准分布相互干扰；叠加时要逐项做消融，确认每一项的独立贡献。
6. **「LoRA 不是压缩」**：训练时它是参数高效手段，但与冻结基座 + 4bit（QLoRA）组合后，整套微调管线的显存需求下降数倍，属于事实上的压缩工程。

## 八、面试题

1. **四种压缩方法分别主要节省什么资源？**
   要点：量化省显存/访存（解码吞吐↑）；结构化剪枝省 FLOPs；蒸馏换小模型、全面降本；低秩省参数与优化器状态。答题时把「省什么」与「哪种瓶颈被缓解」绑定——访存瓶颈 vs 算力瓶颈。
2. **GPTQ 和 AWQ 的核心区别是什么？**
   要点：GPTQ 用二阶（Hessian）信息逐列量化并做误差补偿，依赖校准集求逆；AWQ 不训练、按激活幅度找 salient channel 做 per-channel 缩放，免重排、硬件友好、通用性更好。
3. **LLM.int8() 为什么要对 outlier 单独处理？**
   要点：大模型少数通道激活值是普通通道的数百倍，per-tensor INT8 会把它们压成 0；LLM.int8() 用 vector-wise 量化 + 少数 outlier 通道走 FP16，混合精度解决动态范围问题。
4. **为什么说 LLM 推理解码是 memory-bound 的？量化因此有多大收益？**
   要点：每 token 生成要读全部权重，算术强度极低；INT4 权重让 HBM 读取量减半以上，吞吐近似随权重字节数线性提升（受 kernel 效率影响）。而 prefill 是 compute-bound，需分开讨论。
5. **生产上部署一个 70B 模型，你怎么选压缩组合？**
   要点：先 4bit AWQ/GPTQ 权重量化 + KV cache 量化，装进单机多卡；若对延迟敏感，用蒸馏得到 8B 级专用模型 + 量化；给出「先量化、再蒸馏、最后改结构」的顺序与精度/吞吐实测方案。

## 九、演进与趋势

早期（2016 前后）是 Han et al. 的「剪枝 + 量化 + 熵编码」经典三件套，针对 CNN 打包压缩率。Transformer 时代先落地的是蒸馏（DistilBERT、TinyBERT），随后 INT8 推理成为数据中心标配。2022 年 LLM.int8() 发现 outlier 现象，2022-2023 GPTQ/AWQ 把 PTQ 推到 4bit 可用，bitsandbytes 的 NF4/QLoRA 让 4bit 训练进入消费级显卡。2023-2024 起，FP8 在 H100 上原生加速、W4A8/AWQ 成为 vLLM 默认选项之一；结构化方向出现 SliceGPT、layer-drop 等「剪层」工作；混合精度量化（不同层不同 bit，如 QuIP#、AQLM 向 2bit 进军）和投机解码、MTP 这类系统级手段开始互补。趋势是：**压缩从单点算法变成整条推理栈的协同设计**——量化格式（GGUF/FP8）、调度器、KV cache 策略、甚至训练时就为量化友好而做的量化感知训练（QAT for LLM）一起被优化；同时蒸馏被前置到数据管线（用大模型合成数据训小模型），与压缩融为一体。

## 十、小结

模型压缩的五条主线——剪枝、量化、蒸馏、低秩、共享——本质上都在回答同一个问题：模型容量中哪些是任务真正需要的。量化处理数值精度冗余，剪枝处理结构冗余，蒸馏处理能力的可转移性，低秩与共享处理参数化冗余。大模型时代的实践结论是：**post-training 量化（GPTQ/AWQ 4bit + KV 量化）是收益/风险比最高的第一步**，蒸馏负责把专用能力压进小模型，结构化剪枝与低秩在训练侧省成本。选型要从「当前瓶颈是显存、带宽还是算力」出发走决策树，并且每一层压缩都必须用目标域评测集验证——压缩不是一次性技巧，而是与推理引擎、内核、数据管线共同演进的系统工程。
