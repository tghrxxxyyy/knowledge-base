# 梯度累积与学习率缩放

> 对应 huggingface/transformers `gradient_accumulation_steps` 与 pytorch/pytorch。

## 一、背景与挑战

linear scaling rule 指出：batch 翻倍、学习率应翻倍（在 warmup 期内）以近似保持优化动力学。当用梯度累积把逻辑 batch 从 B 增至 K·B 时，是否也要相应放大学习率？若处理不当，要么欠优化，要么训练不稳。更深一层：累积带来的「等效大 batch」与「真实多卡大 batch」在优化轨迹上等价，但 wall-clock 更慢，因此 lr 缩放只影响收敛质量，不改变是否需要更长训练步数——这一点常被忽略，导致误以为放大 lr 就能省时间。

## 二、核心原理

梯度累积把逻辑 batch 增大到 $B_{\mathrm{eff}}=K\cdot B$。按 linear scaling rule，前期（warmup 阶段）应把学习率乘以 $\frac{B_{\mathrm{eff}}}{B_{\mathrm{ref}}}$ 以复现大 batch 动力学；后期仍按原调度衰减。注意累积改变的只是每步的逻辑 batch，每步 wall-clock 更慢，但优化轨迹与大 batch 等价。实践中若累积步数很大（如 32+），warmup 比例也应相应拉长，避免初期大 lr 配小有效步数导致震荡，否则会出现 loss 尖刺。

## 三、形式化与数学基础

有效 batch 与学习率：

$$
B_{\mathrm{eff}}=K\cdot B,\qquad \mathrm{lr}_{\mathrm{eff}}=\mathrm{lr}_{\mathrm{base}}\cdot\frac{B_{\mathrm{eff}}}{B_{\mathrm{ref}}}
$$

更新量近似：

$$
\theta\leftarrow\theta-\eta_{\mathrm{eff}}\,\frac{1}{K}\sum_{k=1}^{K}g_k
$$

当 $\eta_{\mathrm{eff}}=K\eta_{\mathrm{base}}$ 时，等价于大 batch 一次更新（忽略二阶项）。也可写成「lr 不变、但总步数按 K 缩放」的等价视角：累积 K 步 ≈ 大 batch 训练到达同一点需 K 倍步数，二者总计算量相同。

## 四、代码实现

```python
base_lr, base_bs, micro_bs, K = 3e-4, 256, 8, 32
bs_eff = micro_bs * K                 # 256
lr = base_lr * (bs_eff / base_bs)     # 3e-4 * 1 = 3e-4 (本例相等)
optimizer = torch.optim.AdamW(params, lr=lr)
# 仍需 warmup 与余弦衰减调度
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=total_steps)

def auto_lr(base_lr, micro_bs, K, ref_bs):
    # 按有效 batch 自动缩放, 避免手算出错
    return base_lr * (micro_bs * K / ref_bs)
```

## 五、与其他技术对比

| 方式 | 优化动力学 | 每步耗时 | 总步数 |
| --- | --- | --- | --- |
| 真实大 batch | 等价 | 低(并行) | 少 |
| 累积大 batch | 等价 | 高(串行) | 同(eff batch 视角) |

累积复现大 batch 效果，仅更慢。

## 六、常见误区

- 只加累积却不调 lr：可能欠优化（等效小 batch 动力学）。
- 过度放大 lr：引发不稳定甚至发散。
- 后期仍乘 K：调度应衰减，warmup 后才适用 scaling。
- 忽略 warmup 长度：大 K 需更长 warmup 以稳住初期。
- 以为放大 lr 能省时间：只改收敛质量，不改总计算量。

## 九、演进与趋势

自动 batch-lr 校准工具减少手工换算；把 scaling 写入调度器（如按有效 batch 自动定 lr）。一些框架支持「lr 随累积步数自动缩放」开关，避免用户手动计算，并在大 K 时自动拉长 warmup。

（补充）工程上还有一个常被忽略的点：累积步数 K 与学习率调度器的总步数必须协调。若调度器按「物理 step 数」而非「逻辑更新数」计数，累积会把实际更新次数压缩 K 倍，导致 cosine 曲线在训练中途就走完，等效学习率过早归零。实践要点：

- 把调度器的 step 计数绑定到 `opt.step()` 调用次数，而非遍历 dataloader 的次数。
- 当 K 改变（如显存变化导致 micro-batch 调整）时，重新计算 lr 与 warmup 比例，不要沿用旧值。
- 在日志中同时记录「物理步」与「逻辑步」，便于排查收敛异常。
- 若使用梯度裁剪，裁剪阈值同样应按累积后的平均梯度设定，否则 K 越大越易触发误裁剪。

对极长训练（如预训练），建议把有效 batch 与 lr 作为同一组超参联合记录，形成可复现的训练配方，避免后续实验难以对齐基线。

（补充续）还有一类「隐性耦合」：启用累积后，若优化器用了带动量的方法（SGD-momentum / Adam），动量项的更新频率从每物理步变为每逻辑步，等效于把动量历史按 K 倍稀释。因此大 K 下有时需调小动量系数或调大 lr 补偿，否则初期收敛偏慢。

落地清单：
- 调度器 step 绑定 `opt.step()`，杜绝按 dataloader 计数。
- lr 与 warmup 比例按有效 batch 重算，K 变动即重算。
- 梯度裁剪阈值按累积后平均梯度设定。
- 日志同时打印物理步与逻辑步，便于复现与排查。

## 十、小结

累积改变逻辑 batch，lr 须按 scaling rule 协同调整：warmup 期乘倍数、后期衰减，方能复现大 batch 动力学。同时要注意 warmup 长度与累积步数的配合，并理解放大 lr 不省总计算量。
