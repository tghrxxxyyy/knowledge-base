# 梯度累积与分布式训练

> 对应 microsoft/DeepSpeed 与 pytorch/pytorch DDP/FSDP。

## 一、背景与挑战

大模型训练常受单卡显存限制，micro-batch 很小。数据并行（DDP/FSDP）已通过多卡增大全局 batch，但若仍达不到目标 batch 或显存吃紧，可在每张卡内部叠加梯度累积进一步突破上限。关键在于理解累积（时间维）与跨卡同步（空间维）如何协同。常见误区是把二者当成二选一：实际上它们正交——数据并行解决「多卡同时算」，累积解决「单卡分多步算」，可同时开启，且分别作用于 batch 大小的不同轴。

## 二、核心原理

每张卡内部做 K 步 micro-batch 前向反向并累加梯度（不更新），累积末尾再做一次优化器 step；卡间通过 all-reduce 在 step 时同步梯度。全局有效 batch 为：

$$
B_{\mathrm{global}}=N_{\mathrm{gpu}}\times B_{\mathrm{micro}}\times K
$$

累积把梯度同步频率降为每 K 步一次，减少通信开销；FSDP 再切分参数/优化器状态进一步省显存。在 FSDP+累积组合下，单卡可训练参数量进一步放大，因为参数分片与梯度累积分别从空间与时间两个轴释放显存，二者相乘得到总有效容量。

## 三、形式化与数学基础

设第 $k$ 步第 $r$ 卡的微批梯度为 $g_{r,k}$，DDP 在 step 时对跨卡梯度取平均：

$$
\bar g = \frac{1}{N_{\mathrm{gpu}}K}\sum_{r=1}^{N_{\mathrm{gpu}}}\sum_{k=1}^{K} g_{r,k}
$$

累积等价于把逻辑大 batch 的梯度分 K 步计算，与一次性大 batch 的统计量一致（忽略 batch norm 差异，见「梯度累积与虚拟批次深入/梯度累积与BatchNorm」）。若引入 FSDP 的分片，则每卡只存 $1/N_{\mathrm{gpu}}$ 的参数与梯度，通信为分片级 all-gather/reduce-scatter，进一步降低峰值显存。

## 四、代码实现

```python
for i, (x, y) in enumerate(loader):          # 每卡独立 micro-batch
    loss = model(x, y).loss / ACCUM
    loss.backward()                          # DDP 在 step 时 all-reduce
    if (i + 1) % ACCUM == 0:
        opt.step(); opt.zero_grad()          # 累积末尾更新

def effective_batch(n_gpu, micro_bs, K):
    # 全局有效 batch 的解析: 三因子相乘
    return n_gpu * micro_bs * K

def comm_savings(K):
    # 累积把跨卡同步频率降为每 K 步一次
    return f"sync every {K} steps"
```

## 五、与其他技术对比

| 手段 | 维度 | 作用 |
| --- | --- | --- |
| 数据并行 | 空间(卡) | 增大 batch+提速 |
| 梯度累积 | 时间(步) | 增大 batch+省显存 |
| FSDP | 空间(卡) | 切分参数省显存 |
| 序列并行 | 空间(卡) | 切长序列省显存 |

四者可叠加：DP/FSDP 解决空间，累积解决时间。

## 六、常见误区

- 认为累积可替代跨卡同步：二者解决不同维度（时间 vs 空间），须并用。
- 忘记 loss 除 ACCUM：导致有效学习率随 K 放大。
- 在累积中误用 BN：每微批统计错位（见 BatchNorm 文档）。
- 累积步数过大：通信/更新频率过低，优化动力学偏离大 batch 行为。
- 以为累积免费：它省显存但增加 wall-clock（串行多步）。

## 九、演进与趋势

梯度累积与序列并行、张量并行、FSDP 组合支撑万亿参数训练；异步累积与通信 overlap 进一步隐藏同步开销。ZeRO 各阶段与累积配合，使单卡也能参与超大模型训练，形成多层并行堆叠。

（补充）当三者（数据并行、FSDP、累积）组合时，还需注意 all-reduce 与累积步的耦合：DDP 默认在 `backward()` 内对每个 micro-batch 做梯度同步，因此每累积 K 步实际发生了 K 次跨卡通信，只不过只在末尾 `step`。这与「累积减少通信」的直觉有出入——累积减少的是优化器更新频率，而非梯度同步频率。实践要点：

- 若想真正减少通信，应结合 FSDP 的分片通信或梯度压缩，而非仅靠累积。
- 多卡下确认各卡 micro-batch 与 K 一致，否则全局 batch 计算会偏差。
- 在流水线并行（PP）下，累积需跨 stage 对齐，避免某一 stage 提前更新。
- 用 profiler 实测每步通信占比，确认累积带来的收益是否达到预期。

掌握这些正交维度的组合关系，才能在大模型训练中精准控制显存、吞吐与收敛质量的三角权衡。

（补充续）另一个工程陷阱是「累积步数与梯度裁剪的交互」：若裁剪在每次 `backward` 后按单 micro-batch 梯度做，累积 K 步的等效裁剪阈值会被放大 K 倍，改变收敛动力学。应在累积完成后、统一 `step` 前对平均梯度做裁剪，使裁剪语义与真实逻辑 batch 一致。

多机训练时建议用框架（DeepSpeed/FSDP）内置的累积开关而非手写循环，并开启梯度通信的 overlap，把本就省不下的同步开销藏进前向/反向计算之后。

## 十、小结

累积在分布式下叠加显存与通信收益：时间维累积配合空间维并行，是扩展大模型训练的关键组合。理解「时间 vs 空间」的正交性，才能正确堆叠各类并行策略而不互相抵消。
