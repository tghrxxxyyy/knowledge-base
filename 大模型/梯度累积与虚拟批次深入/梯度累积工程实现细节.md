# 梯度累积工程实现细节

> 对应 pytorch/pytorch 训练循环与 karpathy/nanoGPT 实现。

## 一、背景与挑战

正确实现梯度累积涉及梯度清零时机、混合精度 scaler 交互、梯度裁剪位置等细节，极易出错。常见 bug：每微批都清零梯度使累积失效；或在 scaler.step 前未 unscale 就裁剪，导致裁剪用的范数尺度错误。还有更隐蔽的：在累积中途调用了 `opt.step()`（如某个回调），或在分布式下误把 all-reduce 频率与累积步数混淆，造成部分卡提前更新而其余卡梯度错位。

## 二、核心原理

关键约定：
- 仅在累积末尾 `opt.step()` 并 `zero_grad()`；中间步骤只 `backward()`。
- 梯度裁剪应在 step 之前、对全部累积梯度统一进行。
- 混合精度下先 `scaler.unscale_` 再裁剪，再 `scaler.step`/`scaler.update`。
- 若 loss 已除 ACCUM，则梯度已是平均尺度，裁剪阈值按平均梯度设定。
- 分布式下 DDP 的 all-reduce 发生在 `backward()` 内（默认），累积多步即多同步，需确认与 FSDP 的 reduce 时机一致，避免重复或遗漏归约。

## 三、形式化与数学基础

累积梯度（已除 K）：

$$
G=\frac{1}{K}\sum_{k=1}^{K}g_k
$$

裁剪：

$$
G\leftarrow G\cdot\min\!\left(1,\frac{C}{\|G\|}\right)
$$

再更新 $\theta\leftarrow\theta-\eta G$。裁剪作用于全累积梯度而非单微批，否则阈值语义错位。注意若先 `unscale`，梯度从「缩放域」回到「真实域」，裁剪阈值 $C$ 才对应真实梯度范数；否则裁剪的是放大/缩小后的假范数。

## 四、代码实现

```python
scaler = torch.cuda.amp.GradScaler()
for i, (x, y) in enumerate(loader):
    with torch.autocast(dtype=torch.bfloat16):
        loss = model(x, y).loss / ACCUM
    scaler.scale(loss).backward()
    if (i + 1) % ACCUM == 0:
        scaler.unscale_(opt)                       # 还原尺度再裁剪
        torch.nn.utils.clip_grad_norm_(params, 1.0)
        scaler.step(opt); scaler.update(); opt.zero_grad()

def safe_accumulate(loss, scaler, opt, acc, i, clip=1.0):
    # 封装累积关键约定, 防止误清零/误裁剪
    scaler.scale(loss / acc).backward()
    if (i + 1) % acc == 0:
        scaler.unscale_(opt)
        torch.nn.utils.clip_grad_norm_(opt.param_groups[0]["params"], clip)
        scaler.step(opt); scaler.update(); opt.zero_grad()
```

## 五、与其他技术对比

| 场景 | 无累积 | 有累积 |
| --- | --- | --- |
| 清零时机 | 每步 | 仅末尾 |
| 裁剪对象 | 单步梯度 | 累积梯度 |
| 混合精度 | 直接 step | 先 unscale |

## 六、常见误区

- 每微批后都 `zero_grad()`：累积失效，等效未累积。
- scaler.step 前未 unscale 就裁剪：范数量级错误。
- 裁剪阈值未按平均梯度设定：与 loss/K 不一致。
- 在回调里触发额外 step：破坏累积节奏。
- 累积与 DDP 混用时重复归约：需确认 backend 的 all-reduce 触发点。

## 九、演进与趋势

高阶 API（Trainer、DeepSpeed engine）已封装这些细节；编译器（torch.compile）可融合累积循环。框架层把「清零/裁剪/缩放」约定固化为标准训练循环，减少手写错误，也让 AMP 与累积的组合开箱即用。

（补充）当使用 HuggingFace Accelerate 或 DeepSpeed 时，多数细节已被封装：只需设置 `gradient_accumulation_steps`，框架会自动在末尾 `step` 并清零，并在混合精度下正确处理 `unscale`。但理解底层仍有价值：当自定义训练循环或调试诡异的梯度异常时，往往就是上述某个约定被破坏。实践要点：

- 优先用成熟 Trainer/Engine 管理累积，避免手写循环埋坑。
- 自定义循环时，把「清零/反传/裁剪/更新」四步画成状态机，逐状态核对。
- 在分布式下确认梯度同步与累积步的关系（见「梯度累积与分布式训练」），避免重复或遗漏归约。
- 加单元测试：用 K=1 与 K=3 跑同一 batch，断言参数更新结果近似一致。

工程稳健性来自对这些「不起眼约定」的敬畏：它们单独看微不足道，组合起来却决定训练能否收敛。

## 十、小结

精确控制清零/裁剪/缩放时机是累积正确性的核心：只在末尾更新、裁剪作用于全累积梯度、混合精度先 unscale。把这些约定封装成辅助函数或交予高阶框架，是工程稳健的关键。
