# 上下文检索与压缩

> 对应 RAG/长上下文混合；LM-Infinite、StreamingLLM（Xiao et al., 2023）。

## 一、背景与挑战

即便支持长上下文，全量塞入贵且注意力被稀释；需检索或压缩关键信息。

## 二、核心原理

把长文档检索出相关片段入上下文；或压缩历史为摘要/键值；StreamingLLM 用注意力 sink 保稳态流式。

## 三、数学形式

压缩比 $r=|ctx_{comp}|/|ctx_{full}|$；检索保留 top-k 相关块保利用率。

## 四、代码实现

```python
chunks = retrieve(long_doc, query, k=4)
ctx = "; ".join(chunks)
```

## 五、与其他对比

- 与 检索重排序 / 长文档切分 共享检索。
- 与 智能体记忆 共享压缩。

## 六、常见误区

- 全量塞入致"中间丢失"（lost in middle）。
- 压缩丢关键约束。

## 七、与开源书对应

- harvardnlp/annotated-transformer：https://github.com/harvardnlp/annotated-transformer
- rasbt/LLMs-from-scratch：https://github.com/rasbt/LLMs-from-scratch

## 八、面试题

- 长上下文为何还需检索？答：全量注意力贵且中段易忽略，检索保相关与省成本。

## 九、演进

全量→检索注入→压缩流式。

## 十、小结

长上下文并非越多越好，检索与压缩提升性价比。
