# 向量记忆与检索

> 对应 Park et al., *Generative Agents*, UIST 2023（记忆流检索）；Lewis et al., *RAG*, NeurIPS 2020（检索范式基础）。

## 一、背景与挑战

记忆条目数量增长后必须靠索引召回，但记忆检索与文档检索的分布差异明显：条目短、时间敏感、常有指代与省略。
直接套用文档 RAG 会出现召回相似但过时、或语义相近但主体错位（把别人的偏好当成用户的）的问题。

## 二、核心原理

- 条目规范化：写入时补全主体与时间（谁、何时、什么事），避免依赖上下文才能理解的碎片。
- 混合检索：稠密向量捕语义、稀疏索引捕专名与 ID、元数据过滤限定主体与时间窗，三者结合再融合排序。
- 结果整合：召回后做去重与冲突检测，冲突条目按时间与来源置信度取舍，再压缩注入。

## 三、数学形式

综合排序可写作 $s(m)=\lambda_1\cos(E(q),E(m))+\lambda_2\,\text{bm25}(q,m)+\lambda_3\gamma^{\Delta t}+\lambda_4\,\text{conf}(m)$。

排名融合可用 RRF：$\text{RRF}(m)=\sum_r \frac{1}{k+\text{rank}_r(m)}$，避免稀疏与稠密分数尺度不一致。

## 四、代码实现

```python
def mem_search(q, subject, dense, sparse, now, k=6):
    d = dense.search(embed(q), k=30, filter={"subject": subject})
    s = sparse.search(q, k=30, filter={"subject": subject})
    fused = rrf([d, s], k=60)
    fused.sort(key=lambda m: 0.8 * m.fuse + 0.2 * decay(now - m.ts), reverse=True)
    return dedup_conflicts(fused)[:k]
```

## 五、与其他对比

- 与文档 RAG：切分策略不同（记忆天然是小条目）、需要主体过滤与时效衰减，写入侧还要做归并。
- 与关系型状态存储：结构化状态适合精确字段（订单号、余额），向量记忆适合模糊语义回忆，二者应并存。

## 六、常见误区

- 不带主体元数据，导致多用户或多角色场景下记忆串味。
- 只用向量不叠加专名匹配，导致 ID、型号、人名类查询召回失败。
- 召回后不做冲突检测，让相反的两条记忆同时进上下文让模型摇摆。

## 八、面试题

- 记忆检索与文档检索的关键差异？答：条目短且时效敏感、需主体隔离、写入侧要归并去重，排序需引入时新性与置信度。
- 为什么用 RRF 融合？答：稀疏与稠密分数不可直接比较，按排名融合免归一化且对尺度差异鲁棒。

## 九、演进

全量历史注入 → 向量召回 → 混合检索加元数据过滤 → 多因子排序 → 带冲突消解的记忆装配。

## 十、小结

向量记忆不是「文档 RAG 换个库」，主体隔离、时效衰减与冲突消解才是它的专属难题。
