# 记忆写入与遗忘

> 对应 Park et al., *Generative Agents*, UIST 2023（反思与重要性打分）；Zhong et al., *MemoryBank*, AAAI 2024（基于遗忘曲线的记忆更新）。

## 一、背景与挑战

无限写入会让记忆库充满琐碎与重复，检索精度随规模下降；写得太少则丢关键信息。
同时用户偏好会变、事实会过期，缺少更新与遗忘机制的记忆会主动制造错误。

## 二、核心原理

- 写入门控：只有满足条件的内容才落库（用户明确陈述的偏好、任务结论、稳定事实），临时闲聊不写。
- 归并与升级：同类条目合并计数并提升置信度；多条相关条目可周期性总结为更抽象的结论条目。
- 遗忘：按时间衰减降权、按命中频次保鲜、对显式变更做失效标记（软删除并保留历史以便审计）。

## 三、数学形式

记忆强度可用衰减模型 $S(t)=S_0\exp(-t/\tau)$，每次被成功召回并有用时 $\tau$ 增大（间隔重复效应）。

淘汰规则可取 $S(t)<\theta$ 且近期未命中；置信度更新可用 Beta 后验 $\text{Beta}(\alpha+s,\ \beta+f)$ 融合成功与失败次数。

## 四、代码实现

```python
def commit(store, cand, llm):
    if not llm_yes(llm, f"以下内容是否值得长期记住(偏好/结论/稳定事实): {cand}"):
        return
    dup = store.nearest(embed(cand), thresh=0.92)
    if dup:
        dup.count += 1; dup.tau *= 1.2; dup.ts = now(); return   # 归并保鲜
    store.add(Memory(cand, vec=embed(cand), ts=now(), tau=72.0))

def forget(store, theta=0.2):
    store.items = [m for m in store.items if m.strength() >= theta or m.pinned]
```

## 五、与其他对比

- 与缓存淘汰（LRU/LFU）：思路相似，但记忆还要处理语义冲突与显式变更，不能只按访问频率。
- 与数据库软删除：审计需求一致，但记忆的失效常是语义层判定（偏好改变），需要模型参与。

## 六、常见误区

- 把每轮对话都写入，库膨胀后召回噪声压倒有用信息。
- 硬删除历史导致无法解释「智能体为何曾这样做」，审计与回溯困难。
- 偏好变更时新增条目却不失效旧条目，两条并存造成行为不稳定。

## 八、面试题

- 为什么需要遗忘机制？答：库规模增长直接损害召回精度，且过期事实会主动引入错误，衰减与失效是质量保障。
- 偏好冲突如何处理？答：新条目写入时对语义相反的旧条目打失效标记，检索层优先最新且高置信条目，保留历史仅供审计。

## 九、演进

全量写入 → 规则门控 → 归并与重要性打分 → 衰减遗忘与显式失效 → 置信度后验驱动的记忆治理。

## 十、小结

记忆质量由写入门控与遗忘策略共同决定，能忘的记忆系统才可长期使用。
