# 结构化日志

> 对应结构化日志（JSON）实践；与 推理安全与审计 衔接。

## 一、背景与挑战

非结构化日志难检索；请求级需含 trace_id/用户/长度以便审计排障。

## 二、核心原理

统一 JSON 字段（ts、trace_id、model、prompt_len、gen_len、latency、status）；集中采集（Loki/ES）；按字段检索。

## 三、数学形式

日志量 $V = R\cdot f_{fields}$；需采样与留存策略控成本。

## 四、代码实现

```python
log.info(json.dumps({"trace_id": tid, "latency": L, "status": 200}))
```

## 五、与其他对比

- 与 指标/链路 构成完整栈；
- 与 推理安全深入（审计）共享字段。

## 六、常见误区

- 记全 prompt 致隐私与成本风险；
- 日志无 trace_id 难关联。

## 七、与开源书对应

- datawhalechina/llm-universe：https://github.com/datawhalechina/llm-universe
- llm-course：https://github.com/mlabonne/llm-course

## 八、面试题

- 为何日志要结构化？答：便于检索、聚合与跨系统关联（trace_id）。

## 九、演进

文本日志 → JSON → 采样+留存。

## 十、小结

结构化日志以统一字段支撑检索与审计。
