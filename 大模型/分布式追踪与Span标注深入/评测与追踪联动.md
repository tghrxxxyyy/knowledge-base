# 评测与追踪联动

> 对应 OpenTelemetry 可观测性范式与 EleutherAI/lm-evaluation-harness（Gao 2021）、vllm-project/vllm 追踪实践。

## 一、背景与挑战

大模型评测（如用 lm-evaluation-harness 跑 MMLU、GSM8K）产出的是聚合分数，但当分数异常下降时，工程师往往无法回答「是数据变了、模型退化了，还是推理链路（批处理、缓存、调度）引入的偏差？」。评测与线上链路彼此割裂，导致定位靠猜、复现靠运气。挑战在于：评测请求与线上请求走的是不同代码路径，分数与耗时/token/错误缺乏关联，无法做因果归因与失败回放。

联动的目标，是把每次评测请求也纳入统一可观测体系，使「分数波动」可被「链路事实」解释。

## 二、核心原理

评测与追踪联动的核心做法：

1. 评测即请求：把评测样本当作普通推理请求发出，自动打 trace（trace_id），与线上同源埋点。
2. 分数—链路关联：在评测结果落库时，把 trace_id、span 上下文、耗时、token 数一并写入，建立样本级索引。
3. 失败回放：对低分或异常样本，按 trace_id 拉取完整调用链（检索、重写、生成、解码各阶段），定位是哪一环节导致错误。
4. 偏差归因：对比不同版本/后端下同一样本的 span 差异（如 decode 时延突增、缓存命中率变化），隔离评测噪声与真实退化。

其本质是「用可观测性的因果链为评测结果背书」。

## 三、形式化与数学基础（含 LaTeX）

对失败样本做原因归因，用贝叶斯视角：

$$
P(\text{cause}=c\mid \text{fail})\propto P(\text{fail}\mid c)\,P(c)
$$

其中 $c\in\{\text{data, model, infra, prompt}\}$ 为候选原因，$P(c)$ 为先验（如某后端近期变更则 infra 先验升高）。若样本 $i$ 在版本 $v$ 下 span 特征为 $\mathbf{s}_i^v$，则分数差异可分解：

$$
\Delta \text{score}=\mathbb{E}_{\text{fail}}[f(\mathbf{s}^{v_1})]-\mathbb{E}_{\text{fail}}[f(\mathbf{s}^{v_2})]
$$

通过对比 $\mathbf{s}$ 各维度（时延、token、重试）定位主因。

## 四、代码实现

```python
# 评测样本与 trace 关联（结构示意）
def link_eval(trace_id, sample_id, score, store):
    store.tag(trace_id, "eval_sample", sample_id)
    store.tag(trace_id, "eval_score", score)
    if score < 0.5:
        store.flag(trace_id, "low_score")        # 低分样本标记，便于回放
        spans = store.get_spans(trace_id)
        log_failure(sample_id, spans)            # 记录失败链路用于归因

# 回放：按样本拉取完整调用链
def replay(sample_id):
    tid = store.lookup_trace(sample_id)
    return store.get_trace(tid)
```

## 五、与其他技术对比

- 孤立评测：只存分数，无法解释「为什么错」，定位靠人工翻日志。
- 孤立追踪：有链路但无业务语义（哪次请求是评测、期望答案？）。
- 联动：分数与链路双向索引，缩短 MTTR，并使评测结果具备可解释性与可审计性。

## 六、常见误区

- 「评测不传 trace 上下文」：分数与链路断开，事后无法回放。
- 「只存总分不存样本级链路」：聚合均值掩盖了个别样本的链路异常。
- 「评测走特殊捷径」：与线上不同路径，分数无法反映真实服务行为。
- 「忽略缓存/批处理偏差」：评测开了缓存而线上未开，结论失真。

## 九、演进与趋势

评测正演化为「生产流量的影子副本」：用线上真实分布采样做持续评测，每条都带 trace，使评测成为可观测体系的一部分；结合实验（experiment）框架，模型/后端/提示的每次变更都自动跑带链路的评测并对比归因。

落地要点：
- 评测请求与线上请求走同一套埋点与后端，避免「评测环境」与「生产环境」脱节。
- 把低分样本自动建 issue 并附 trace 链接，研发可直接回放定位。
- 用 trace 差异解释分数漂移，区分「模型退化」与「链路波动」。
评测与追踪联动，让模型质量从「一次性打分」变成「持续可观测的指标」。低分样本的 trace 链接应作为评测报告的标准字段，而非附言。

补充要点：
- 评测报告应支持按 trace 下钻到失败样本做根因分析。
- 低分样本自动建 issue 并附链路，缩短定位时间。

## 十、小结

评测与追踪联动把每次评测请求纳入统一可观测体系，用 trace_id 关联分数与链路，实现样本级失败回放与因果归因。其权威基础是 OpenTelemetry 与 lm-evaluation-harness，落地价值在于让评测从「黑盒分数」升级为「可解释、可审计、可定位」的工程闭环。
