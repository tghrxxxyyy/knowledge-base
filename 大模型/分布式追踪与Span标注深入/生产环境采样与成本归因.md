# 生产环境采样与成本归因

> 对应 OpenTelemetry 采样规范与 Kwon 2023 vLLM（PagedAttention 高效服务）、LLM 推理成本度量实践。

## 一、背景与挑战

全量 tracing 在高流量 LLM 服务上成本极高：每条请求可能涉及数十个 span、KB 级属性（提示与输出文本）、以及 token 计费数据。全量采集会压垮 collector、膨胀存储、并因序列化开销反噬 Inference 延迟。另一方面，若盲目均匀采样，会丢失最关键的信号——长尾错误、低概率越狱、超高成本请求往往正是需要被 100% 捕获的。挑战在于：在「成本可控」与「关键路径/异常必采」之间取得平衡，并把 token 与时延成本精确分摊到业务方、用户、功能模块，支撑配额与计费。

## 二、核心原理

1. 动态采样：按路径、用户等级、错误率、成本阈值决定采样率；错误与长尾（高时延/高 token）强制全采。
2. 尾部采样（Tail Sampling）：在请求结束后据最终结果（成功/错误/超阈值）决定是否保留，避免提前丢弃关键样本。
3. 成本归因：把每次请求的 token 成本（输入+输出）与时延开销，按调用方/租户/功能维度分摊。
4. 缓存修正：命中 KV cache / 语义缓存的请求实际成本低于全量计算，归因时需扣除，避免重复计费。
5. 配额联动：实时成本看板驱动限流与预算告警。

实践上建议把采样决策与归因放在同一处理链路，避免二者口径不一致：保留下来的 trace 必须带齐成本标签，被丢弃的请求至少在聚合指标里留痕。缓存折减系数 $\eta$ 应取自实际命中率统计而非经验常数，否则归因会系统性偏高。对多租户系统，还应支持按租户维度分别设定采样率与预算上限。

补充要点：
- 尾部采样应在请求结束后据结果决策，避免提前丢弃关键样本。
- 长尾错误与超高成本请求建议强制全采，常态流量低采样控成本。
- 采样率本身应可观测，记录每条请求的取舍原因以便审计。

## 三、形式化与数学基础（含 LaTeX）

单用户 $u$ 的成本由归属其的 span 的 token 成本求和：

$$
\text{cost}(u)=\sum_{s\in\mathrm{spans}(u)} c_{\text{token}}\cdot (n^{\text{in}}_s+n^{\text{out}}_s)\cdot (1-\eta_s)
$$

其中 $c_{\text{token}}$ 为单价，$\eta_s$ 为缓存命中折减（命中则 $\eta_s\to1$）。整体追踪开销受采样率约束：

$$
\text{storage}\approx n\cdot \bar{S}\cdot r_{\text{sample}}
$$

尾部采样下有效覆盖率偏向异常：设异常占比 $\pi$，则异常样本保留率 $r_{\text{tail}}\approx1$，正常样本 $r_0\ll1$，在固定成本下最大化异常可见性。

    result = {}
    for u, uspans in spans.items():
        total = 0.0

            tokens = s["in_tokens"] + s["out_tokens"]

## 五、与其他技术对比

- 全量采集：信息完整但昂贵，仅适合低流量或关键环境。
- 均匀采样：成本低但丢失长尾错误，归因为均值掩盖异常用户。
- 尾部/重要性采样：固定成本下最大化关键信号，配合成本分摊支撑计费与配额。

## 六、常见误区

- 「均匀采样丢失长尾错误」：应错误/超阈值必采，而非按比例。
- 「归因忽略缓存命中」：命中缓存实际成本远低于全算，不扣减会高估。
- 「只看存储不看序列化开销」：span 属性过大（完整输出）会反噬推理延迟。
- 「归因到请求级忽略租户」：多租户下需细分到用户/功能才可用于配额。

## 九、演进与趋势

实时成本看板与配额联动：按归因结果动态限流/降配；采样策略由静态阈值走向基于异常检测的 adaptive sampling；缓存命中率、批处理效率被纳入归因模型，使单位成本更贴近真实算力消耗。

落地模式：
- 为每租户/功能设置成本预算与告警线，超阈值自动降级或要求预付费。
- 对高价值长尾请求保留全量 trace，对海量低价值请求仅采样，保证关键信号不丢。
- 把单位成本（元/token）作为核心 SLO 之一，与延迟、质量并列审视。
成本归因的终极目标，是让每一次 LLM 调用都「算得清账、付得起钱、查得到因」。

## 十、小结

生产环境采样与成本归因在可控开销下保障关键信号不丢失，并把 token/时延成本按租户与功能精确分摊。其权威基础是 OpenTelemetry 采样规范与 vLLM 高效服务实践，落地关键是尾部采样、缓存修正与配额联动，使 LLM 运维可量化、可计费、可控。
