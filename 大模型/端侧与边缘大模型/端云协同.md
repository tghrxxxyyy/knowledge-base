# 端云协同

> 对应 Shi et al. (2016)「Edge Computing: Vision and Challenges」；Satyanarayanan「The Emergence of Edge Computing」；mlabonne《LLM Course》端侧部署章节。

> 端云协同把推理在「端侧（隐私/低延迟/离线）」与「云端（强能力/新知识）」之间动态分工，是兼顾体验与能力的现实路径。它不是「二选一」，而是「按请求画像分流」。行业实践从早期的「端侧预处理 + 云端主推理」逐步演进为「端侧为主、云端增强」。

## 一、背景与挑战

纯端侧受算力/显存约束，复杂推理、长上下文、知识密集型任务力不从心；纯云端则有网络延迟、隐私顾虑、离线不可用、规模化成本高等问题。端云协同要在三者之间权衡：(1) 路由决策——哪些请求端侧处理、哪些上云；(2) 隐私分级——敏感数据尽量不出端；(3) 体验一致性——切换不感知、不中断；(4) 成本——云端调用按量计费，需控量；(5) 降级——断网或云故障时如何兜底。

## 二、核心原理

协同范式有三层：(1) **能力分层**——简单/高频/隐私任务（唤醒、摘要、改写）端侧完成，复杂/少频任务（深度研究、代码生成）上云；(2) **预处理/路由**——端侧用极小模型做意图识别与分流；(3) **混合生成**——端侧起草、云端精修，或云端检索后端侧合成。核心是「用端侧兜住下限、用云端拉高上限」，并通过本地缓存与结果复用降低云端命中率。工程上还需处理「上下文搬运」：端侧已生成的草稿与用户历史如何高效传给云端而不重复计算。

## 三、形式化与数学基础

设端侧成本 $c_e$、延迟 $l_e$，云端成本 $c_c$、延迟 $l_c$（含网络），请求 $x$ 的难度为 $d(x)$。路由策略可写为阈值函数：

$$r(x) = \begin{cases} \text{edge}, & d(x) \le \tau \\ \text{cloud}, & d(x) > \tau \end{cases}$$

目标是在延迟与成本约束下最大化效用：

$$\max_{r} \; \mathbb{E}\!\left[ u(\text{quality}(r(x),x)) \right] \quad \text{s.t.}\; l_r \le L,\; c_r \le C$$

隐私维度引入出端数据量 $s(x)$：当 $s(x)$ 超过阈值则强制端侧或本地脱敏。阈值 $\tau$ 可由在线学习随网络状况与用户习惯自适应，例如弱网时主动压低 $\tau$ 让更多请求留端。设云端命中率为 $h$，则平均成本 $\bar{c} = (1-h)c_e + h c_c$。

## 四、代码实现

简化的路由决策（以意图难度打分分流，示意）：

```python
def route(prompt: str, local_model) -> str:
    score = local_model.score_difficulty(prompt)  # 0~1，越小越简单
    if score < 0.3:
        return "edge"          # 简单改写/摘要，本地完成
    if contains_pii(prompt):
        return "edge"          # 含隐私，强制本地
    if network.flaky:
        return "edge"          # 弱网降级，兜住下限
    return "cloud"             # 复杂推理上云

dest = route(user_prompt, tiny_router)
reply = run_locally(user_prompt) if dest == "edge" else call_cloud(user_prompt)
```

生产环境还应加请求级缓存（相似问题命中本地历史）与超时回退（云端超时就用端侧弱结果），并统计云端命中率以做成本告警。

## 六、常见误区

- **过度上云**：把本可本地的简单任务也上云，徒增延迟与成本、泄露隐私。
- **路由抖动**：同一类请求反复横跳，体验割裂；应加缓存与确定性规则。
- **隐私泄漏**：路由判断失误使敏感数据出端；需默认保守策略。
- **忽视降级**：断网时云端路径无兜底，应自动回退端侧。
- **成本失控**：无云端命中率监控，月底账单超预期；应设配额与熔断。
- **上下文丢失**：上云时不带端侧草稿，导致重复生成、体验割裂。

## 九、演进与趋势

趋势是语义级路由（小模型精准判断意图与所需能力）、端侧草稿+云端验证的混合生成、设备集群联邦推理、以及随端侧模型变强而「默认端侧、云端兜底」的翻转。隐私计算（本地脱敏、差分）将让更多敏感任务留在端侧，云端逐渐退化为「能力增强层」而非必需品。边缘节点（如家庭网关、车载算力）也会成为「准云端」，形成端-边-云三级协同。

工程落地要点：

- 路由策略以「难度分 + 隐私标签 + 网络质量」三维决策，并设云端命中率与成本配额告警。
- 断网/超时须自动回退端侧弱结果，保证基本可用。
- 上下文在端云切换时应连贯传递，避免重复生成导致体验割裂。
- 弱网时主动压低难度阈值，让更多请求留端，提升鲁棒性。
- 隐私默认保守：含 PII 的请求一律本地，宁可能力降级也不出端。
- 成本熔断：云端账单超阈值即限流，保护单位经济。
- 可观测性：路由决策日志应可回放，便于定位体验割裂根因。

## 十、小结

端云协同用「端侧兜下限、云端拉上限」平衡体验、隐私与成本。落地要害是稳健的路由策略、隐私默认保守、断网降级与成本熔断，避免简单任务上云与敏感数据出端两类典型错误，并以上下文连贯保障切换无感。
