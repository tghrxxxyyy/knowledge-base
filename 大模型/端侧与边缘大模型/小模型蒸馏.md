# 小模型蒸馏

> 对应 Hinton, Vinyals & Dean (2015)「Distilling the Knowledge in a Neural Network」；mlabonne《LLM Course》；HuggingFace Transformers 文档；Gou et al. (2021)「Knowledge Distillation: A Survey」。

> 知识蒸馏把大模型（教师）的能力迁移到小模型（学生），是端侧小模型最重要的来源之一：在算力与内存受限的设备上，靠「软标签」而非仅靠硬标签逼近教师行为。典型案例是拿 7B/13B 教师蒸馏出 0.5B~1.5B 学生，用于手机输入法纠错、本地摘要等场景。

## 一、背景与挑战

端侧设备（手机、PC、车机）内存常只有数 GB，无法容纳百亿参数以上的模型。直接训练小模型，效果远低于同规模「从教师蒸馏而来」的学生。核心矛盾在于：学生参数量小、容量（capacity）有限，而我们希望它尽量复刻教师在海量数据上学到的「暗知识」（类间相似性、置信度分布）。

主要挑战包括：(1) 容量鸿沟——学生无法表达教师全部能力，需取舍；(2) 数据可用性——蒸馏常需无标签数据或教师生成的合成数据；(3) 任务适配——对话、推理、工具调用等能力如何用软标签有效传递；(4) 训练稳定性——温度、损失权重需精细调节；(5) 评估缺失——小模型在长尾任务上的退化难以被单一指标捕捉。

## 二、核心原理

蒸馏的本质是让学生同时拟合「硬标签」（真实标注）与「软标签」（教师 softmax 输出的概率分布）。软标签携带了教师对各类别相对关系的判断（例如「猫」与「狗」比「猫」与「汽车」更相似），信息密度远高于 one-hot。

关键技巧是**温度 softmax**：在 softmax 前除以温度 $T>1$，使分布更平滑，凸显暗知识；训练学生时用同样温度，计算两者的 KL 散度，最后乘以 $T^2$ 以补偿梯度尺度。推理时学生恢复标准温度 $T=1$。

对于大语言模型，还衍生出**序列级蒸馏 / 思维链蒸馏**（学生模仿教师的思考步骤）、**特征蒸馏**（对齐隐层表示），以及用教师生成高质量「指令-回复」对来监督微调学生（属于数据蒸馏范畴，常用于构造端侧 SFT 语料）。

## 三、形式化与数学基础

带温度的 softmax 定义为：

$$q_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$

其中 $z_i$ 为 logit，$T$ 为温度。学生与教师在温度 $T$ 下的软目标分布分别记为 $p_i$、$q_i$。蒸馏损失取两者 KL 散度（等价于交叉熵）：

$$\mathcal{L}_{\text{KD}} = T^2 \cdot \mathrm{KL}\!\left(p \,\|\, q\right) = T^2 \sum_i p_i \log \frac{p_i}{q_i}$$

总损失为软损失与硬损失加权和：

$$\mathcal{L} = \alpha \, \mathcal{L}_{\text{KD}} + (1-\alpha)\, \mathcal{L}_{\text{CE}}(y, q)$$

其中 $\alpha$ 通常为 $0.5\sim0.9$，$y$ 为真实 one-hot 标签。思维链蒸馏则可对生成的 token 序列最大化教师似然 $\sum_t \log q_\theta(x_t\mid x_{<t})$。学生容量上限可定性理解为：若教师有效秩远高于学生参数量所能表达的自由度，则必然存在不可恢复的能力损失，故应优先蒸馏目标任务分布而非「全能力」。

## 四、代码实现

以下为典型的 PyTorch 蒸馏训练片段（节选，仅示意核心逻辑）：

```python
import torch, torch.nn.functional as F

def distill_loss(student_logits, teacher_logits, labels, T=4.0, alpha=0.7):
    # 软损失：温度软化后的 KL 散度
    soft_s = F.log_softmax(student_logits / T, dim=-1)
    soft_t = F.softmax(teacher_logits / T, dim=-1).detach()
    kd = F.kl_div(soft_s, soft_t, reduction="batchmean") * (T * T)
    # 硬损失：真实标签交叉熵
    ce = F.cross_entropy(student_logits, labels)
    return alpha * kd + (1 - alpha) * ce

# 训练循环（示意）
for x, y in loader:
    s = student(x); t = teacher(x).detach()
    loss = distill_loss(s, t, y, T=4.0, alpha=0.7)
    loss.backward(); opt.step(); opt.zero_grad()
```

实践要点：教师输出需 `detach()` 停止梯度；`reduction="batchmean"` 与乘以 $T^2$ 是 Hinton 原论文推荐做法，避免软目标梯度被温度缩放「稀释」；温度建议在小集合上做网格搜索（如 $T\in\{2,4,6\}$），并以验证集困惑度/准确率定档。

## 五、与其他技术对比

| 压缩手段 | 原理 | 端侧友好度 | 能力保持 | 训练成本 |
| --- | --- | --- | --- | --- |
| 知识蒸馏 | 教师→学生软标签 | 高 | 中高 | 中 |
| 量化 | 低比特存储/计算 | 高 | 中 | 低 |
| 剪枝 | 去冗余权重/通道 | 中 | 中 | 中 |
| 结构化稀疏 | 稀疏模式 | 中 | 中 | 高 |
| NAS | 自动搜结构 | 中 | 高 | 高 |
| LoRA 适配 | 低秩增量 | 中（部署额外权重） | 中 | 低 |

实践中常组合使用：先蒸馏得到好学生，再量化部署，三者正交可叠加；蒸馏与 LoRA 也可串行（先蒸馏底座、再 LoRA 适配端侧任务）。

## 六、常见误区

- **温度乱设**：T 过小软标签退化为 one-hot、丢失暗知识；T 过大噪声放大、训练缓慢。需在小集合上网格搜索。
- **忽视容量鸿沟**：期望 0.5B 学生复刻 70B 教师全部能力不现实，应聚焦目标任务分布。
- **数据质量差**：用噪声/分布偏离的数据蒸馏，学生学到错误归纳偏好。
- **只蒸馏答案不蒸馏过程**：纯结果蒸馏对推理任务收益有限，CoT/过程蒸馏更优。
- **损失权重失衡**：α 过大导致硬标签欠拟合、基础任务崩坏。
- **教师选择随意**：用与自己目标域不匹配的教师，迁移收益有限；应选领域相近、能力足够的教师。
- **只看平均分**：忽视长尾/安全相关退化的评估，上线后在小众场景翻车。

## 九、演进与趋势

方向包括：数据高效/无数据蒸馏（用教师自生成数据）、多教师集成蒸馏、结合 RLHF 偏好的「偏好蒸馏」、以及面向特定端侧芯片的联合蒸馏+量化（QAT 式端到端优化）。随着 1B~3B 学生模型架构改进（更优的注意力、更长上下文），小模型天花板持续提升，蒸馏在端侧落地中的权重只增不减。工具链上，自动化蒸馏流水线（自动选教师、调温、评测）正在成熟。

## 十、小结

小模型蒸馏是端侧模型的核心来源：以温度软标签传递暗知识，用加权和平衡软/硬目标。落地关键是选对温度与权重、尊重容量鸿沟、以目标任务为中心，并以「蒸馏+量化」组合收尾。其价值在于用可控的训练成本，把大模型能力「下放」到内存与算力受限的设备。
