# 推理服务架构

> 对应 llm-course 部署章与 vLLM 文档。

## 一、背景与挑战

生产推理需高吞吐、低延迟、可扩展与可观测，非单机脚本可比。

## 二、核心原理

典型分层：网关（鉴权/限流）→ 调度器（批处理）→ 推理引擎（模型执行）→ KV 缓存/显存管理。常配 metrics/trace。

## 三、关键要点

- 解耦「请求」与「执行」。
- 批处理提升 GPU 利用率。

## 四、代码实现

# 伪：网关->调度

## 五、与其他对比

- 直接调模型简单；服务化解耦、可扩展。

## 六、常见误区

- 单进程能扛——并发一上来就崩。
