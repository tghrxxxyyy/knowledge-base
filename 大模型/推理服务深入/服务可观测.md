# 服务可观测

> 见「推理服务深入/推理服务架构」与「大模型工程落地/LLMOps」。

## 一、背景与挑战

推理服务出问题需快速定位：延迟、错误、显存、队列。

## 二、核心原理

采集 metrics（QPS/延迟/显存）、logs（请求级）、traces（跨组件），用 Prometheus/Grafana/LangSmith 可视化。

## 三、代码实现

```python
from prometheus_client import Histogram
LAT = Histogram("ttft","first token latency")
```

## 四、关键要点

- TTFT/TPOT 是 LLM 关键 SLO。
- trace 串联网关→引擎。

## 五、与其他对比

- 普通服务看 QPS；LLM 还要看 token 指标。

## 六、常见误区

- 只看平均延迟——长尾更要命。

## 七、与开源书对应

- vLLM metrics; llm-universe: https://github.com/datawhalechina/llm-universe
- LangSmith: https://github.com/langchain-ai/langchain

## 八、面试题

- LLM 服务该监控哪些特有指标？

## 九、演进

日志 → metrics → trace → 全链路。

## 十、小结

可观测让推理服务「看得见」。
