# 限流与配额

> 见「推理服务深入/推理服务架构」与「大模型部署成本模型」。

## 一、背景与挑战

GPU 资源有限，需防滥用与超支。

## 二、核心原理

按用户/Key/模型设 QPS 与 token 配额，令牌桶限流，超额降级或排队；配合成本告警。

## 三、代码实现

```python
if not bucket.allow(user, cost=tokens): return 429
```

## 四、关键要点

- 限流保护后端也防账单爆。
- 配额可按层级。

## 五、与其他对比

- 无限制易雪崩；硬限制伤体验——需软限流。

## 六、常见误区

- 限流只为防攻击——也为控成本。
