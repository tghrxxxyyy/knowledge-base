# 流式与分块处理

> 对应 Dai et al., *Transformer-XL*, 2019；以及滚动窗口/分块注意力推理实践。

## 一、背景与挑战

推理时输入持续增长，若每步重算全部历史既慢又占显存。

## 二、核心原理

把序列切成固定块/窗口，维护跨块的隐藏状态（memory）或 KV 缓存，新块只与近期块交互；配合滑动窗口或全局 token，控制注意力规模在常数级。

## 三、数学形式

每步仅算 $O(w)$ 窗口注意力：$score_{ij}$ 仅当 $i-j<w$ 或 $j\in G$（全局）；成本随总长 $O(n\cdot w)$ 而非 $O(n^2)$。

## 四、代码实现

```python
cache = []
for blk in blocks:
    k, v = proj(blk)
    cache.append((k, v)); cache = cache[-W:]      # 只留近 W 块
    out = attend(q, cat(cache), cat(cache_v))
```

## 五、与其他对比

- 与 FlashAttention深入 互补：流式管推理编排，FA 管单块效率。
- 与 稀疏注意力深入 都限制注意力范围。

## 六、常见误区

- 窗口过小丢长程依赖；需全局 token 或记忆补偿。
- 缓存管理不当致跨块位置错乱（需相对/ALiBi）。

## 八、面试题

- 流式推理如何控制成本？答：分块+缓存近窗 KV/隐藏，注意力规模恒定，成本随总长线性。

## 九、演进

全量重算 → 块缓存 → 滑动窗口+记忆+全局 token。

## 十、小结

流式分块把推理成本压到线性，是服务长对话/长文档的实用方案。
