# 动态轴与动态维度

> 对应 ONNX, *Dynamic Axes Specification*（opset 动态形状）；与 模型导出ONNX深入 衔接。

## 一、背景与挑战

序列长度/批大小可变，导出若固定 shape 则无法服务变长输入。

## 二、核心原理

用 `dynamic_axes` 把特定维度标记为动态（batch/seq），ONNX 以符号维度表示，运行时按实际张量定型。

## 三、数学形式

输入形状 $[B,S,D]$ 中 $B,S$ 为符号维：$B=\text{sym\_batch},\ S=\text{sym\_seq}$，运行时实例化为具体整数。

## 四、代码实现

```python
dynamic_axes={"x": {0: "batch", 1: "seq"}, "y": {0: "batch"}}
torch.onnx.export(..., dynamic_axes=dynamic_axes)
```

## 五、与其他对比

- 与 服务框架深入（变长请求）需求呼应。
- 与 算子融合深入（动态 shape 影响融合特化）相关。

## 六、常见误区

- 仅标 batch 漏标 seq，仍无法变长。
- 动态维度触发运行时重编译，首包延迟尖刺。

## 八、面试题

- 为什么用动态轴？答：让导出的图接受变长/变批输入，避免为每种 shape 重新导出。

## 九、演进

固定 shape → 单动态轴 → 多符号维度 + 形状推断。

## 十、小结

动态轴赋予 ONNX 灵活性，代价是运行时定型与可能的重编译。
