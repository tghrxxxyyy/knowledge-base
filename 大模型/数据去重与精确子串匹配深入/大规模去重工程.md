# 大规模去重工程

> 对应 Soldaini et al., *Dolma*, 2024（去重工具）；Penedo et al., *FineWeb*, 2024（高效去重流水线）。

## 一、背景与挑战

万亿 token 语料去重需分布式、低内存、可复现。

## 二、核心原理

用分片 + MinHash 桶 + 布隆过滤器近似；或后缀数组（如 Google 的 deduplication）做精确子串。以 Spark/Ray 并行，指纹入库后增量更新。

## 三、数学形式

内存上界约 $O(k\cdot N_{doc})$ 签名；比较只在同桶：$E[\text{比较}]\ll N^2$。

## 四、代码实现

```python
buckets = defaultdict(list)
for doc, sig in shard:
    buckets[band(sig)].append(doc)
```

## 五、与其他对比

- 与 数据版权与合规清洗深入（同属预处理工程）共享基础设施。
- 与 多语种分词与挑战深入（需先分词建指纹）依赖。

## 六、常见误区

- 单机能跑的脚本直接套万亿规模致 OOM。
- 增量语料未与历史去重致重复回流。

## 八、面试题

- 如何扩展到万亿 token？答：MinHash 分桶并行 + 增量指纹库，避免两两比较。

## 九、演进

单机脚本 → 分布式 MinHash → 后缀数组精确 + 增量。

## 十、小结

大规模去重靠分桶并行与增量指纹，是数据工程硬骨头。
