# 过程奖励与结果奖励 PRM/ORM

> 对应 Lightman et al.(2023, *Let's Verify Step by Step*) 与 OpenAI 验证器研究。

## 一、背景与挑战

训练或评估推理模型时，需要「判断对错」的奖励信号。最朴素的是**结果奖励（ORM, Outcome Reward Model）**：只看最终答案对不对。但复杂数学/多步推理中，最终答案可能因「蒙对」或中间步骤错误却答案巧合正确而误判，且无法告诉模型「哪一步错了」。**过程奖励（PRM, Process Reward Model）** 改为对每一步推理给正确性信号，能精准定位错误、引导探索。挑战在于 PRM 标注成本极高——需人工或强模型逐步判分，且步骤切分与标注一致性难保证，噪声标注反而有害。

## 二、核心原理

- **ORM**：输入 $(x, y_{\text{full}})$，输出标量 $r\in[0,1]$ 表示最终正确性。训练简单（答案对错即标签），但信号粗糙，无法指导中间探索。
- **PRM**：把推理切分为步骤 $s_1,\dots,s_n$，对每步输出正确性概率 $p_i=P(\text{step } i \text{ 正确}\mid x, s_{<i})$。可用于逐步剪枝搜索树、给 RL 提供细粒度优势，显著提升难分布表现。

Lightman 等人（2023）在 MATH 上系统比较：用 PRM 做 beam search 显著优于 ORM，且 PRM 训练的模型在难分布上泛化更好。代价是 PRM 需逐步标注（其 PRM800K 数据集耗资巨大）。

### 工程落地要点

- **步骤切分规范**：先定「一步」的粒度（如一行推导/一个子目标），标注与训练须一致，否则 PRM 失真。
- **自动标注**：用强模型（如 R1）自举对步骤打分、再用人类抽检校准，降低标注成本。
- **混合使用**：终局用 ORM/可执行验证保底，中间用 PRM 做搜索剪枝与 RL 优势，互补最稳。
- **防噪声**：对 PRM 低分步骤做二次校验，避免单点误判砍掉正确路径。
- **奖励塑形**：PRM 可加权「关键转折步」，比均匀逐步权重更利难任务。
- **在线更新**：部署后收集人类/执行反馈回灌 PRM，持续纠偏。

## 三、形式化与数学基础

ORM 给定全解 $y$ 的奖励：

$$
r_{\text{ORM}} = \mathbb{I}[\text{final}(y) = \text{gold}]
$$

PRM 对第 $i$ 步的局部正确性：

$$
p_i = P_\phi(\text{correct}\mid x, s_1,\dots,s_i)
$$

用 PRM 给完整轨迹打分可累乘或取最小值（任一步错则整解存疑）：

$$
r_{\text{PRM}} = \prod_{i=1}^{n} p_i \quad\text{或}\quad r_{\text{PRM}}=\min_i p_i
$$

在 best-of-n 或 beam search 中，用 $r_{\text{PRM}}$ 替代 $r_{\text{ORM}}$ 选优，可避开「答案对但过程错」的陷阱。

## 四、代码实现

用 PRM 给每步打分并筛掉坏步骤（示意）：

```python
def score_trajectory(prm, x, steps):
    probs = []
    for i in range(1, len(steps) + 1):
        probs.append(prm(x, steps[:i]))      # 第 i 步正确概率
    return min(probs)                         # 保守：任一步低分则整解低分

# 搜索时优先扩展 PRM 高分分支
best = max(candidates, key=lambda c: score_trajectory(prm, x, c.steps))
```

## 五、与其他技术对比

| 奖励 | 信号粒度 | 标注成本 | 训练价值 | 局限 |
|------|----------|----------|----------|------|
| ORM | 终局 | 低 | 中 | 无法定位错误 |
| PRM | 逐步 | 高 | 高 | 标注难、步骤切分敏感 |
| 可执行验证 | 终局/部分 | 中 | 高 | 仅代码/可验证域 |

## 六、常见误区

- **以为 ORM 够用**：在长推理中 ORM 易被「蒙对答案」误导，且无法指导中间探索。
- **PRM 一定优于 ORM**：PRM 若标注噪声大，反而引入错误信号；且推理成本高。
- **步骤切分随意**：切分粒度严重影响 PRM 精度，需与训练时一致。
- **PRM 分高即正确**：PRM 也会误判，应结合可执行验证兜底。
- **只靠人工标注**：成本高且不可扩展，需自动/半自动标注辅助。

## 九、演进与趋势

从人工标注 PRM 走向**自动过程监督**（如 Math-Shepherd 用模型自举逐步标注），降低门槛。PRM 也与 RL（GRPO/PPO）结合提供逐步优势。趋势是「ORM + PRM + 可执行验证」混合：能用代码判定的用执行，不能的用 PRM，终局再用 ORM 兜底，形成多层级奖励体系。

## 十、小结

ORM 与 PRM 是推理模型的两种奖励粒度：ORM 简单廉价但信号粗糙，PRM 逐步精细、能定位错误并提升搜索质量，却依赖昂贵标注。实践中以 PRM（或自动过程监督）做中间引导、ORM/可执行验证做终局校验的组合最为有效，是强推理训练与评测的基石。
