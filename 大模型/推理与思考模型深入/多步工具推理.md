# 多步工具推理

> 对应工具调用（function calling）与 ReAct(2022)、Toolformer(2023) 等推理+工具深度结合研究。

## 一、背景与挑战

纯语言推理在涉及精确计算、实时数据、私有数据库、代码执行的任务上力不从心——模型「心算」会错、知识会过时、无法触达系统。多步工具推理让模型在长思考中**规划「调用工具 → 观察结果 → 再推理」的循环**，把不可靠的内心计算外包给确定性工具。代表范式 ReAct（推理+行动交错）、Toolformer（自监督学工具使用）。工程挑战在于：工具返回结果需结构化可解析，长链路中工具调用状态需维护，危险操作（删库、发消息、付费）需权限与确认，且失败重试不能陷入死循环。

## 二、核心原理

基本循环是「思考（Thought）→ 行动（Action/工具调用）→ 观察（Observation）」反复迭代：

1. **思考**：模型分析当前状态，决定下一步需要什么信息或计算。
2. **行动**：生成结构化工具调用（函数名 + 参数 JSON）。
3. **观察**：执行工具，把结果插入上下文作为新观察。
4. 回到思考，直至能给出最终答案。

推理模型因具备长链规划能力，比普通模型更擅长「先想清楚要查什么、按什么顺序查」，减少无效调用。工具返回作为「观察」显式进入思维链，使推理可验证、可纠错，也天然与「检索增强推理」「树式搜索」结合。

### 工程落地要点

- **工具 schema 设计**：参数用 JSON Schema 强约束，模型输出经校验后再执行，避免非法参数导致崩溃。
- **结果结构化**：工具返回应是可解析的字典/对象，而非自由文本，便于模型引用与后续步骤拼接。
- **权限分级**：只读工具（搜索、计算）可自动执行；写操作（发信、删库、付费）须人工确认或沙箱。
- **失败自愈**：调用异常时把错误回灌上下文，让模型换参数重试或换工具，而非直接终止。
- **上下文裁剪**：多轮观察会膨胀上下文，需定期摘要或只保留关键观察，防超长截断。
- **并行调用**：相互独立的工具可并行执行（如同时查多个 API），缩短多步时延。

## 三、形式化与数学基础

把多步推理视为部分可观测的 agent 轨迹，第 $t$ 步：

$$
o_t = \text{Tool}(a_t),\qquad a_t \sim \pi_\theta(\cdot \mid x, h_t),\quad h_t = (h_{t-1}, a_{t-1}, o_{t-1})
$$

其中 $h_t$ 为累积历史（思考+行动+观察）。最优策略最大化带工具的环境回报：

$$
\max_\theta \mathbb{E}\Big[ R\big(x, (a_1,o_1,\dots,a_T,o_T)\big) \Big]
$$

工具调用的可靠性要求动作可解析：$a_t = \text{parse}(\text{LLM}(h_t))$，解析失败时需重试或回退，否则轨迹断裂。

## 四、代码实现

用函数调用做多步工具推理（伪代码）：

```python
tools = {"calc": calc, "search": web_search, "sql": run_sql}

def agent_loop(question, max_steps=6):
    hist = question
    for _ in range(max_steps):
        out = llm.generate(hist, tools=tools)      # 模型可返回 tool_call
        if out.finished:
            return out.answer
        name, args = out.tool_call["name"], out.tool_call["args"]
        obs = tools[name](**args)                  # 执行并观察
        hist += f"\n行动:{name}({args})\n观察:{obs}"
    return llm.generate(hist)
```

| ReAct | 思考/行动交错 | 中 | 多步任务 |
| 推理模型+工具 | 长链内规划 | 强 | 复杂推理 |

## 六、常见误区

- **工具一调就灵**：返回结果若非结构化、含噪声，模型易误读。
- **忽视权限控制**：写操作/付费操作需人工确认，否则危险。
- **过度依赖工具**：能心算的也去调，徒增延迟与成本。
- **无重试/兜底**：一次解析失败就崩，应设重试与默认分支。
- **忽略上下文膨胀**：多轮观察累积会撑爆上下文，需摘要裁剪。

## 九、演进与趋势

从手写工具 schema 走向「模型自举学工具」（Toolformer 风格）与「推理模型原生工具调用」：长思考内自主编排多工具、并行调用、出错自愈。结合检索、代码执行、浏览器形成 agent 工作流。安全方向是沙箱化执行与权限分级，让危险工具可控调用；同时用「工具调用轨迹」做 RL 进一步提升规划能力。

## 十、小结

多步工具推理把模型从「靠记忆与心算」升级为「会借工具」的 agent：在长思考中规划调用、观察结果、再推理，显著提升计算与实时任务的可靠性。落地关键是工具结果结构化、调用状态可维护、危险操作有权限护栏、长链路有上下文裁剪。它与检索增强推理、树式搜索共同构成「强推理 agent」的能力底座。
