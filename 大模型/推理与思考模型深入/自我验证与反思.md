# 自我验证与反思 Self-Verification

> 对应 Shinn et al.(2023, Reflexion) 与推理模型的「生成-验证-修正」闭环研究。

## 一、背景与挑战

早期 LLM 采用「一次性生成答案」范式，缺乏纠错能力：一旦前几步推理出错，后续会沿错误路径越走越远，且模型自身往往「不知道自己错了」。在代码、数学、多跳问答等任务上，单遍生成错误率高。自我验证（self-verification）与反思（reflection）试图赋予模型闭环能力：生成候选后回过头检查、找矛盾、再修正，把线性生成升级为「试错—反思」的迭代过程。挑战在于「验证者」本身也是模型，可能和生成者犯同样的错；且额外反思会消耗更多 token 与延迟，需平衡收益与成本。

## 二、核心原理

基本闭环是「生成 → 验证 → 修正」：

1. **生成**：模型产出初步答案或推理链。
2. **验证**：显式要求模型检查——重算关键步骤、对照题目条件、列举可能矛盾、或用外部工具（代码执行、检索）核实。
3. **修正**：若发现不一致，生成修订版并说明改动理由。

Reflexion 进一步把反思写入「记忆」，把失败经验以自然语言总结，供下一轮推理参考，形成跨步累积的元认知。验证手段分两类：内部验证（模型自问自答）与外部验证（执行代码、查表、调用 verifier 模型）。后者因有客观判据而更可靠。

### 工程落地要点

- **触发条件**：对高价值或高不确定输出才启用反思，简单题直接答，控成本。
- **外部判官优先**：凡可代码执行/检索核实的，交给工具验证，比纯文本自验可靠。
- **结构化输出**：要求模型分「结论/检查项/矛盾/修订」四段，便于程序解析与自动重试。
- **迭代上限**：设最大反思轮数（如 3），防止「修正-再错」死循环。
- **记忆复用**：把已证伪的假设写入会话记忆，后续避免重复踩坑（Reflexion 思路）。
- **置信度校准**：让模型给自身答案置信度，低置信才触发验证，减少无谓开销。

## 三、形式化与数学基础

把推理看作在状态空间搜索，自我验证等价于给每条轨迹打分：

$$
s = \arg\max_{y\in\mathcal{Y}} \; \mathbb{P}_\theta(y\mid x) \cdot \mathbb{I}[\text{verify}(y, x) = \text{OK}]
$$

其中 $\text{verify}(\cdot)$ 是验证函数。多次迭代时，第 $t+1$ 轮在上一轮反思 $m_t$ 条件下生成：

$$
y_{t+1} \sim p_\theta(\cdot \mid x, y_t, \text{reflect}(y_t, x))
$$

反思质量影响修正方向；若验证器准确率为 $a$，独立验证 $n$ 次至少一次发现错误的概率为 $1-(1-a)^n$，说明多次独立验证能提升检出率。

## 四、代码实现

用提示让模型自我验证（零代码即可，但配合执行更可靠）：

```python
prompt = f"""问题：{question}
请先给出答案，再做三步自我验证：
1. 重算关键数值；
2. 检查是否满足题设所有约束；
3. 若发现矛盾，给出修正后的最终答案。"""
resp = llm.generate(prompt)

# 更可靠：把模型产出的代码交给解释器执行验证
code = extract_code(resp)
result = sandbox.run(code)   # 外部工具验证
if not check_consistent(result, question):
    resp = llm.generate(f"你的结果 {result} 与题设矛盾，请修正。")
```

## 五、与其他技术对比

| 方式 | 可靠性 | 成本 | 适用 |
|------|--------|------|------|
| 单遍生成 | 低 | 低 | 简单题 |
| 自我验证（文本） | 中 | 中 | 通用 |
| 外部工具验证 | 高 | 中高 | 代码/数学 |
| verifier 模型 | 高 | 高 | 评优选优 |

## 六、常见误区

- **认为自我验证一定有效**：模型验证时可能用同样的错误假设，形成「自我确认偏误」。
- **把反思当万能**：反思若不落到可执行检查（如真跑代码），容易变成空话套话。
- **忽视成本**：每轮反思都翻倍 token，应在难度高时才启用。
- **反思无限循环**：模型可能在「修正-再错」间打转，需设最大迭代次数与早停。
- **外部验证即真理**：代码执行/检索也可能被错误输入误导，仍需结果校验。

## 九、演进与趋势

从纯文本自我辩论（self-debate）走向「工具增强验证」：用代码解释器、检索、符号求解器作为客观判官。更前沿的是训练专门的 verifier / critic，与生成器分离，避免「自己骗自己」。多智能体互审（一个生成、一个 critique）也是热门方向；Reflexion 式记忆则让 agent 跨任务积累经验，形成持续改进的元认知。

## 十、小结

自我验证与反思把 LLM 从「一次成型」升级为「生成—检查—修正」的闭环，显著提升复杂任务准确率。其上限由验证器的可靠性决定：纯文本自验易陷入自我确认，配合外部工具（代码执行、检索）或独立 verifier 才能稳定生效。工程上应按任务难度动态开关反思、设迭代上限，在成本与质量间取得平衡。
