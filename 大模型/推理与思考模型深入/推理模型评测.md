# 推理模型评测

> 对应模型评测深入，聚焦推理维度；常用 AIME、MATH、LiveCodeBench、GPQA 等基准。

## 一、背景与挑战

推理模型（o1/R1/QwQ 等）的评测比普通模型更复杂：它们输出长思维链，单次采样结果波动大——同一题可能因一次「走神」而错，也可能因多想一步而对。因此**单次 pass@1 会低估真实能力**，需要多次采样聚合。同时，推理模型常在数学/代码竞赛题上训练，存在基准污染与过拟合风险，评测集必须足够「新」且「难」。此外，成本与延迟也是推理模型不可忽视的维度：一个 pass@8 很高但每次耗费十万 token 的模型，未必比 pass@1 略低但便宜十倍的模型更值得部署。

## 二、核心原理

推理评测的关键设计：

- **多采样聚合**：对每个问题采样 $k$ 次，常用 pass@k（至少一次正确比例）与 mean@k（平均正确率）共同刻画能力。
- **难度分层**：按题目难度分组报告，避免被简单题抬高均值，关注难分布上的差距。
- **防污染**：优先用竞赛新题（如当年 AIME）、闭源测试集，或做 n-gram 去重排查训练泄漏。
- **过程质量**：除答案对错，还评估思维链是否合理、是否自我验证、是否出现幻觉。
- **可复现**：固定温度/随机种子，报告方差，避免单次好运误导。

典型基准：AIME/MATH（数学）、LiveCodeBench（代码）、GPQA（研究生级科学）、Codeforces（竞赛编程）、ZOOBENCH 等。

### 工程落地要点

- **固定协议**：锁定温度、随机种子、采样数与最大长度，结果才可复现、可横向比较。
- **分层报告**：按难度分桶报 pass@1/pass@k，关注「难桶」差距而非整体平均。
- **过程审计**：随机抽样思维链，人工或 LLM-judge 评估是否出现幻觉、逻辑跳跃。
- **成本入账**：每次评测记录平均 token 与时延，给出「准确率-成本」散点。
- **防泄漏检查**：对训练集做 n-gram/embedding 去重，剔除可能见过的题。
- **持续基准**：用按月更新的活基准对抗数据漂移与污染。

## 三、形式化与数学基础

pass@k 的经典无偏估计（从 $n$ 次采样中 $c$ 次正确）：

$$
\text{pass@}k = 1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}
$$

当 $n$ 足够大、采样独立时，pass@1 近似为 $c/n$，而 pass@k 随 $k$ 提升：若单题正确率 $p$，则

$$
\mathbb{P}(\text{pass@}k\ge 1) = 1 - (1-p)^k
$$

这说明聚合采样能显著抬升难样本的通过率，但也掩盖了单次可靠性——这正是工程落地要警惕的。

## 四、代码实现

用均值与 pass@k 聚合多次采样：

```python
import numpy as np
def pass_at_k(n, c, k):
    if n - c < k:  return 1.0
    return 1.0 - np.prod(1.0 - k / np.arange(n - c + 1, n + 1))

scores = [run(model, q) for _ in range(8)]   # 8 次采样
c = sum(scores)
print("pass@1", c/8, "pass@8", pass_at_k(8, c, 8))
```

## 五、与其他技术对比

| 指标 | 含义 | 用途 |
|------|------|------|
| pass@1 | 单次正确率 | 用户体验估计 |
| pass@k | 多次至少一次对 | 能力上限估计 |
| mean@k | 平均正确率 | 稳定性 |
| 成本/延迟 | token 与时延 | 落地可行性 |

## 六、常见误区

- **只看 pass@1**：低估模型在难样本上的潜力，也不利于比较模型。
- **用训练见过的题测**：竞赛题易泄漏，数字虚高，应优先当年新题。
- **忽略成本**：某模型 pass@8 高但每次 10 万 token，落地不现实。
- **不报方差**：单次采样噪声大，应多次重复取均值与置信区间。
- **重答案轻过程**：思维链充满幻觉但答案碰对，pass@k 会误导，需过程评估。

## 九、演进与趋势

评测从「答案对错」走向「过程 + 结果」双评：用 PRM 给思维链打分，用 LLM-as-judge 评估推理质量。动态、持续更新的「活基准」（live benchmark）对抗污染。推理模型还会被放进 agent 工作流整体评测，而非孤立看单题；同时强调「可复现报告」（种子、方差、预算消耗）。

## 十、小结

推理模型评测的核心是「多次采样 + 难度分层 + 防污染 + 算成本」。pass@k 揭示能力上限但高估单次可靠性，pass@1 才是用户体验近似。选模型时应在准确率与每题成本间找 Pareto 前沿，并优先用新题/竞赛题防污染，同时报告过程质量与方差。
