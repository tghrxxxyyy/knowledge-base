# 链式与树式搜索在推理中的应用

> 对应 Wei et al.(2022, CoT)、Yao et al.(2023, ToT)、以及蒙特卡洛树搜索(MCTS) 在 LLM 推理中的运用。

## 一、背景与挑战

LLM 单遍「直接生成答案」在复杂任务上错误率高，因为缺乏系统化探索。搜索结构决定了推理能否「试多条路、比较、回溯」。线性链（CoT）只能走一条路；而许多问题（数学证明、规划、博弈、多跳问答）存在分支与死路，需要树式搜索与回溯。挑战是：搜索越宽越深，token 成本越高，且必须有人「评判哪条路更好」——这个评判者（verifier / value）的质量直接决定搜索是否划算，差评判者会让搜索在错误分支上越陷越深。

## 二、核心原理

- **CoT（链）**：单条线性推理，逐步推出结论，最简单但无法纠错，一步错步步错。
- **CoT-SC（自洽性）**：采样多条链，用多数投票/verifier 选最优，等价于并行搜索。
- **ToT（树）**：把推理拆成「思考步骤」节点，每步生成多个候选，用价值函数评估并保留有希望的分支，遇死路回溯。
- **MCTS**：在树上做「选择-扩展-模拟-回溯」，用奖励逐步更新节点价值，平衡探索与利用，AlphaGo 同思路用于数学/棋类/规划。
- **Best-of-N**：并行采样 N 条，verifier 选最优，是搜索的最简形式。

搜索本质是「以算力换准确率」，收益受评判者质量与问题分支结构共同约束。

### 工程落地要点

- **评判者先行**：先有可靠 verifier/PRM 再做搜索，否则树越大越易在错支上加深。
- **宽度深度权衡**：难且分支多的题用 ToT/MCTS，简单题用 CoT-SC，避免无谓开销。
- **剪枝策略**：用 PRM 对分支打分，保留 top-k 并剪掉低于阈值的死路，控成本。
- **并行采样**：best-of-n 与 ToT 各分支可并行，配合批处理提吞吐。
- **早停**：verifier 已高置信可提前结束搜索，省算力。
- **与 RL 协同**：训练阶段让模型内化「何时分支、何时回溯」，推理时搜索退化为兜底。

## 三、形式化与数学基础

把推理建模为树，$s$ 为状态（已生成前缀），$a$ 为下一步扩展。MCTS 用 UCB 选子节点：

$$
a^* = \arg\max_a \left( Q(s,a) + c\cdot \frac{\sqrt{\ln N(s)}}{N(s,a)} \right)
$$

其中 $Q(s,a)$ 为动作价值估计，$N$ 为访问次数，第二项鼓励探索。每轮模拟得到奖励 $r$ 后回溯更新：

$$
N(s,a)\!\leftarrow\! N(s,a)+1,\qquad Q(s,a)\!\leftarrow\! Q(s,a)+\frac{r-Q(s,a)}{N(s,a)}
$$

Best-of-N 则可视为深度为 1、宽度为 N 的并行搜索，用 verifier 分数 $v$ 选： $\hat y=\arg\max_i v(y_i)$。

## 四、代码实现

Best-of-N + verifier（最简搜索）：

```python
def best_of_n(problem, n, verifier):
    cands = [llm.generate(problem) for _ in range(n)]
    scored = sorted(((verifier(c), c) for c in cands), reverse=True)
    return scored[0][1]

# ToT 风格：每步保留 top-k 分支
def tot(problem, steps=4, branch=3, value_fn=None):
    states = [problem]
    for _ in range(steps):
        expanded = []
        for s in states:
            for b in range(branch):
                expanded.append(s + "\n" + llm.generate(s, stop="\n"))
        states = sorted(expanded, key=value_fn, reverse=True)[:branch]
    return states[0]
```

## 五、与其他技术对比

| 方法 | 搜索结构 | 是否回溯 | 成本 | 依赖 |
|------|----------|----------|------|------|
| CoT | 链 | 否 | 低 | 无 |
| CoT-SC | 多链并行 | 否 | 中 | 投票 |
| ToT | 树 | 是 | 中高 | 价值函数 |
| MCTS | 树+模拟 | 是 | 高 | 模拟奖励 |
| Best-of-N | 并行 N | 否 | 中 | verifier |

## 六、常见误区

- **搜索越深越好**：深度增加成本指数上升，且价值函数噪声会被放大。
- **没有 verifier 也搜得动**：无评判者时，树的扩展与剪枝都失去依据。
- **CoT-SC 等同 ToT**：前者只并行不回溯，后者能纠正中间错误路径。
- **树搜索必然更准**：若价值函数差，树搜索可能比单链更差且更贵。
- **MCTS 开箱即用**：需设计合理的模拟与奖励，否则退化为随机游走。

## 九、演进与趋势

从显式树搜索走向「隐式搜索」：用 RL 训练模型把探索内化进长思维链（如 o1/R1），外部搜索退化为兜底。同时 MCTS 与 verifier/PRM 结合做「指导式搜索」，在代码与数学上收益明显。方向是「训练时学会搜索、推理时按需调用搜索」的混合架构，并用过程奖励做更细的树上剪枝。

## 十、小结

链、树、并行搜索是推理模型探索解空间的三种结构：CoT 线性无回溯，CoT-SC/Best-of-N 并行无回溯，ToT/MCTS 树式可回溯。它们共同依赖 test-time compute 与可靠的评判者（verifier/PRM）。选型应权衡成本与任务分支复杂度——简单题用链，难且分支多的用树式搜索，且搜索深度必须与评判者质量匹配。
