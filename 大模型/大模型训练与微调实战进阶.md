# 大模型训练与微调实战进阶

> 本文在训练与部署总览（见大模型目录相关章节）基础上，深入训练与微调的工程实战：预训练数据管线、SFT 数据构建、PEFT（LoRA/QLoRA）、全参微调取舍、训练稳定性与显存优化、评估与迭代。内容基于公开实践，具体超参以实验为准。

## 1. 训练的两大阶段

- 预训练（Pre-training）：海量无标注语料，学通用语言/知识表征。
- 后训练（Post-training）：SFT、对齐（RLHF/DPO）、领域适配。
- 多数团队不自建预训练，而是基于开源基座做后训练/微调。
- 成本：预训练算力巨大，微调可控。

## 2. 预训练数据管线

- 数据来源：网页、书籍、代码、学术、对话。
- 清洗：去重（近似去重）、去毒、质量过滤（困惑度/规则）。
- 分词：Tokenizer 训练或复用，词表影响效率。
- 数据配比：不同域比例影响能力偏向。
- 质量决定上限，清洗常被低估。

## 3. SFT 数据构建

- 指令-回答对：覆盖任务类型（问答、摘要、代码、工具调用）。
- 质量 > 数量：几千条精标常胜过几十万噪声。
- 多样性：不同领域、格式、难度。
- 格式统一：system/user/assistant 多轮对话结构。
- 防污染：训练集与评测集不重叠。

## 4. 全参微调（Full Fine-tuning）

- 更新模型全部参数。
- 优点：拟合最强。
- 缺点：显存高、易过拟合、灾难性遗忘、成本高。
- 适用：数据量大、任务差异大、资源充足。

## 5. PEFT：LoRA

- 低秩适配：冻结原权重，只训练低秩矩阵（A、B）。
- 参数量极小（原模型 <1% 量级），显存友好。
- 可多任务多 LoRA 适配切换，底座共享。
- 推理可合并权重或动态加载适配器。

```text
原始线性层: y = Wx
LoRA: y = Wx + B A x   (A: d×r, B: r×d, r << d)
训练只更新 A、B，W 冻结
```

## 6. QLoRA

- 在 LoRA 基础上量化基座（如 4bit NF4），进一步降显存。
- 配合分页优化器防显存峰。
- 使消费级/单卡也能微调大模型。
- 精度略有损，但多数任务可接受。

## 7. 显存优化技术

- 混合精度（FP16/BF16）：提速降显存。
- 梯度检查点（Gradient Checkpointing）：用算力换显存。
- ZeRO/分片：优化器状态、梯度、参数分片（多卡）。
- 卸载（Offload）：放 CPU/显存间搬运（慢但能跑）。
- 量化（QLoRA）：基座低比特。

## 8. 灾难性遗忘

- 微调新任务后旧能力退化。
- 缓解：保留部分通用数据混合训练、LoRA（少改）、回放。
- 评估需覆盖旧任务，不只看新任务指标。

## 9. 训练稳定性

- 学习率预热（warmup）与衰减。
- 梯度裁剪防爆炸。
- 监控 loss 曲线、梯度范数、NaN。
- 批量大小与学习率需配合（线性缩放规则）。

## 10. 对齐：RLHF / DPO

- RLHF：训练奖励模型（RM）→ 用 PPO 优化策略贴合奖励。
- 流程复杂（奖励模型 + 强化学习 + 参考模型）。
- DPO：把对齐转为分类损失，简化流程，无需独立 RM 与 RL 循环。
- 二者目标一致：让输出更符合人类偏好与安全。

## 11. 评测闭环

- 自动：基准集（知识/推理/指令遵循）、模型裁判（LLM-as-Judge）。
- 人工：抽样打分、红队测试。
- 回归：新版本对比旧版本，防能力回退。
- 领域评测：针对业务场景自建测试集。

## 12. 领域适配实战

- 医疗/法律/金融等需领域知识。
- 策略：领域语料继续预训练（增量）+ SFT 少量精标。
- 注意合规与隐私（训练数据脱敏）。
- 评估需领域专家参与。

## 13. 多卡与分布式训练

- 数据并行：同模型多副本，数据分片。
- 模型并行/流水线：超大模型切层或切张量。
- ZeRO：优化器状态分片，省显存。
- 通信是瓶颈，需高速互联（NVLink/IB）。

## 14. 推理侧协同

- 训练产出的模型需量化/蒸馏降本（见推理优化章节）。
- 部署：vLLM/推理框架 + 网关（见 LLMOps 章节）。
- 训练与部署用同一 tokenizer，避免不一致。

## 15. 常见踩坑

1. **数据不清洗**：噪声拉低上限；去重去毒是基本功。
2. **训练集污染评测**：指标虚高；严格隔离。
3. **全参微调小数据**：过拟合遗忘；用 LoRA。
4. **显存估算错**：OOM 反复；用梯度检查点/QLoRA。
5. **只看新任务指标**：旧能力塌了未知；全覆盖评测。
6. **学习率乱设**：loss 不稳/不收敛；warmup+衰减。
7. **忽略灾难性遗忘**：业务通用能力退化；混合通用数据。
8. **评测无闭环**：改了不知好坏；建回归集。

## 16. 数据配比经验（方向）

- 通用能力数据保留一定比例，防遗忘。
- 指令数据覆盖任务广度。
- 领域数据占比随目标调，过度偏科伤通用。
- 具体比例因模型与数据而异，需实验。

## 17. 与 RAG 的关系

- 微调注入"能力/风格/知识倾向"，RAG 注入"最新/私有事实"。
- 二者互补：RAG 解决知识时效，微调解决行为对齐。
- 优先 RAG 解决事实，再微调解决风格/格式。

## 18. 成本与决策

- 自训基座：极贵，仅大厂/特定需求。
- 基于开源基座 SFT/LoRA：主流性价比路线。
- 纯 RAG + prompt：零训练成本，先验证再微调。
- 决策按数据量、领域差异、预算。

## 19. 落地清单

- 明确目标（能力/领域/风格）。
- 构建高质量 SFT 数据（去污、隔离评测）。
- 选微调方式（LoRA/QLoRA 起步）。
- 显存优化（混合精度+检查点+分片）。
- 评测闭环（自动+人工+回归）。
- 推理协同（量化部署）。

## 20. 小结

大模型训练实战的核心是"数据质量优先 + 微调方式按资源选 + 显存工程化 + 评测闭环"。多数团队走"开源基座 + LoRA/QLoRA SFT + 对齐"的高性价比路线，而非从零预训练。铁律：**数据清洗与隔离评测不可省、LoRA 起步防遗忘与省显存、显存靠混合精度/检查点/分片、评测必须覆盖旧能力防回退、RAG 与微调互补而非替代**。
