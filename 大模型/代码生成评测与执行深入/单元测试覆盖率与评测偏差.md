# 单元测试覆盖率与评测偏差

> 对应代码评测中测试充分性与 Zheng et al. 2023 "Measuring Coding Challenge Competence with APPS" 的测试设计。

## 一、背景与挑战

评测集的测试质量直接决定分数可信度。测试少则漏判错误，测试偏则模型可钻空子（如硬编码）。覆盖率与边界设计是关键。

## 二、核心原理

用分支/路径覆盖率衡量测试充分性；用对抗测试（边界、异常、大输入）检验鲁棒性。偏差来源包括：测试可见导致的过拟合、用例分布偏移。

## 三、数学形式

分支覆盖率：

$$
C=\frac{|\mathrm{branches\ executed}|}{|\mathrm{branches\ total}|}
$$

漏判率（假通过）：

$$
\mathrm{FP}=\frac{|\{\text{错码通过测试}\}|}{|\text{全部错码}|}
$$

## 四、代码实现

```python
def coverage(branches_exec, branches_total):
    return branches_exec / branches_total if branches_total else 0.0

print(round(coverage(7, 10), 3))
```

## 五、与其他对比

相比只看 pass@k，覆盖率揭示测试是否充分；相比手工题，自动生成测试可扩大覆盖但需校验。

## 六、常见误区

误区一：pass@k 高即测试充分（可能测试弱）。误区二：测试可见不算泄漏。误区三：忽略边界用例。

## 八、面试题

- Q：测试不充分如何误导评测？答：弱测试让错误代码通过，虚高 pass@k。
- Q：如何降低测试泄漏？答：隐藏测试、动态生成、对抗边界。

## 九、演进

从固定单测到覆盖率引导与变异测试（mutation testing），评测严谨性持续提升。

## 十、小结

单元测试覆盖率是代码评测可信度的隐藏变量，弱测试会系统性高估模型能力。
