# 代码评测的数据污染检测

> 对应代码基准污染审计与 "Do Developers Copy from Stack Overflow?" 类来源追溯实践。

## 一、背景与挑战

代码模型大量训练于 GitHub/Stack Overflow，HumanEval 等题面与题解可能已被记忆。污染检测需区分"学会编程"与"背下题解"。

## 二、核心原理

方法：题面 n-gram 与训练语料重叠、变量重命名后重测（记忆者应掉点）、难例变体（扰动输入输出格式）、以及发布后新题对照。

## 三、数学形式

重命名一致性：

$$
\Delta=\mathrm{Acc}(q)-\mathrm{Acc}(q_{\mathrm{renamed}})
$$

泄漏指标加权：

$$
L=\alpha\cdot o_{\mathrm{ngram}}+\beta\cdot\Delta
$$

## 四、代码实现

```python
def rename_drop(acc_orig, acc_renamed):
    return acc_orig - acc_renamed

print(round(rename_drop(0.8, 0.55), 3))
```

## 五、与其他对比

相比数学污染检测，代码更易因变量名记忆；相比文本基准，代码可执行验证更客观。

## 六、常见误区

误区一：混淆"见过类似模式"与"记忆题解"。误区二：重命名不掉点即无污染（可能真会）。误区三：忽略许可证污染。

## 八、面试题

- Q：如何判断代码模型是记忆还是学会？答：变量重命名/格式扰动后重测，记忆者显著掉点。
- Q：代码污染特殊风险？答：许可证与版权泄露。

## 九、演进

从静态基准到滚动竞赛题 + 变体探测，代码污染审计走向常态化。

## 十、小结

代码评测污染检测以变体重测为核心，区分记忆与泛化能力。
