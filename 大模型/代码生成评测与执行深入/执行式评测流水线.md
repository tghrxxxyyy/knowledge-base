# 执行式评测流水线

> 对应 Chen et al. 2021 执行式代码评测流程与容器化沙箱实践。

## 一、背景与挑战

执行式评测需安全运行不可信生成代码，面临沙箱逃逸、依赖缺失、超时与资源滥用。流水线要在隔离、可复现、可并行间平衡。

## 二、核心原理

流程：生成代码 -> 注入测试 -> 容器/沙箱执行 -> 捕获 stdout/异常/超时 -> 聚合 pass@k。关键是用 seccomp/资源限制与确定性随机种子保证可复现。

## 三、数学形式

超时惩罚函数：

$$
s=\begin{cases}1 & \text{全部断言通过}\\ 0 & \text{异常/超时/失败}\end{cases}
$$

聚合：

$$
\mathrm{pass@k}=1-\frac{\binom{n-c}{k}}{\binom{n}{k}}
$$

## 四、代码实现

```python
import subprocess, tempfile, os

def safe_run(code, tests, timeout=5):
    src = code + "\n" + tests
    with tempfile.NamedTemporaryFile("w", suffix=".py", delete=False) as f:
        f.write(src); path = f.name
    try:
        r = subprocess.run(["python3", path], capture_output=True, timeout=timeout)
        return r.returncode == 0
    except Exception:
        return False
    finally:
        os.unlink(path)
```

## 五、与其他对比

相比静态分析（快但不判行为），执行式更可靠但有开销与安全成本；相比本地跑，容器化保证隔离。

## 六、常见误区

误区一：直接本地执行生成代码（安全风险）。误区二：不设超时导致挂死。误区三：非确定性导致分数漂移。

## 八、面试题

- Q：为何执行式评测需沙箱？答：生成代码不可信，需隔离防逃逸与资源滥用。
- Q：如何保证可复现？答：固定随机种子、依赖版本与超时。

## 九、演进

从本地脚本到 Kubernetes/容器池 + 缓存，执行式评测走向规模化与可审计。

## 十、小结

执行式评测流水线以隔离执行为代码功能评测提供可信基础设施。
