# RAG 检索优化实战

> RAG（检索增强生成）的效果瓶颈往往不在生成，而在检索。"问得准、答得对"的前提是"召得回、排得准"。检索优化是一场"切分—向量—重排—召回"的系统工程。

## 1. RAG 链路

```mermaid
flowchart LR
    Q[查询] --> R[召回:向量/关键词]
    R --> F[融合]
    F --> Re[重排:Rerank]
    Re --> C[压缩:TopK]
    C --> LLM[生成]
    LLM --> A[答案+引用]
```

## 2. 切分策略

- **固定窗口**：简单但易切断语义。
- **语义切分**：按句/段边界、标题层级。
- **重叠窗口**：相邻块重叠，减少边界信息丢失。
- **父子块**：检索用小块、生成用大块，兼顾精度与上下文。

## 3. 召回增强

| 方法 | 说明 |
| --- | --- |
| 向量召回 | 语义相似，擅长概念匹配 |
| 关键词/BM25 | 精确词面匹配，互补 |
| 混合召回 | 向量 + BM25 融合 |
| 查询改写 | 多查询/假设文档扩充 |
| 元过滤 | 按时间/来源/权限过滤 |

## 4. 重排与压缩

- **Rerank 模型**：对召回结果精细打分重排（如交叉编码器）。
- **重排数量**：先召 50–100，重排取 Top 5–10。
- **上下文压缩**：去除冗余，控制 token 成本。

## 5. 常见坑

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 切分不当 | 召回错位 | 语义+重叠 |
| 只向量 | 漏精确词 | 混合召回 |
| 召回太少 | 答不出 | 扩大候选 |
| 重排缺失 | 排序差 | 加 Rerank |
| 无引用 | 不可信 | 返回出处 |

## 7. 小结

RAG 检索优化 = 合理切分 + 混合召回 + 重排精排 + 引用可溯。核心是先解决"找得对"，生成才有好基础。
