# 分离式架构动机与瓶颈

> 对应 Kwon 2023 vLLM; Ainslie 2023 GQA; Dao 2022 FlashAttention。

## 一、背景与挑战
同实例混跑 prefill 与 decode 时，prefill 的大矩阵乘挤占带宽，使 decode 的 TPOT 抖动剧烈，尾延迟难控。

## 二、核心原理
把 prefill 与 decode 部署到不同 GPU 池：prefill 实例专注算力密集的首 token 生成，decode 实例专注带宽密集的逐 token 生成，二者通过 KV 传输衔接。

## 三、形式化与数学基础
耦合时 decode 步时延被 prefill 干扰：
$ T_{decode}^{coupled} = T_{comp} + T_{interfere}(prefill) $
分离后：
$ T_{decode}^{disagg} \approx T_{comp} + T_{kv\_transfer} $

## 四、代码实现
```python
prefill_out = prefill_engine(prompt)        # 算力实例
kvcache = move(prefill_out.kv, decode_gpu)  # 跨实例传输
first_token = decode_engine.start(kvcache)
```

## 五、与其他技术对比
耦合部署简单但干扰大；分离部署延迟稳定但需高速互联与调度协同。

## 六、常见误区
误区：分离总更快。短 prompt 下传输开销可能抵消收益。

## 七、与开源书/权威来源对应
DistServe、Splitwise 等论文提出 disaggregated prefill/decode。见 vllm-project/vllm。

## 八、面试题
问：分离式主要解决什么指标？
答：主要压低并稳定 decode 的 TPOT，减少 prefill 干扰。

## 九、演进与趋势
弹性实例池按需扩缩 prefill/decode 比例，成为云推理主流形态。

## 十、小结
分离式通过物理隔离两阶段，把异构瓶颈分别优化，换来稳定低延迟。
