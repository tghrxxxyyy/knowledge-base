# 预填充与解码实例划分

> 对应 Ainslie 2023 GQA; Kwon 2023 vLLM; Shoeybi 2019 Megatron。

## 一、背景与挑战
如何按负载划分两类实例数量？请求到达率与平均长度决定二者算力需求比例。

## 二、核心原理
按 SLA 反推：prefill 需满足 TTFT，decode 需满足 TPOT。用排队论估计各阶段所需并发实例数，独立伸缩。

## 三、形式化与数学基础
设到达率 λ、平均 prefill 算力 μ_p，所需 prefill 实例：
$ N_p \ge \frac{\lambda \cdot T_{prefill}}{SLA_{ttft}} $
decode 类似用 SLA_tpot 与序列数估计。

## 四、代码实现
```python
def plan_instances(lam, Tp, Td, sla_ttft, sla_tpot, n_active):
    Np = ceil(lam * Tp / sla_ttft)
    Nd = ceil(n_active * Td / sla_tpot)
    return Np, Nd
```

## 五、与其他技术对比
固定比例易浪费；动态规划按实时指标调比更省成本。

## 六、常见误区
误区：实例越多越好。跨实例传输与调度开销随实例数上升。

## 七、与开源书/权威来源对应
Splitwise (2023) 提出按阶段划分实例。见 NVIDIA/TensorRT-LLM、vllm-project/vllm。

## 八、面试题
问：如何确定 prefill/decode 实例比例？
答：依到达率、prompt 长度分布与 SLA 用排队模型估算后动态调。

## 九、演进与趋势
自动弹性 + 预测式扩缩成为托管服务标配。

## 十、小结
实例划分本质是按 SLA 做容量规划，比例应随负载动态调整。
