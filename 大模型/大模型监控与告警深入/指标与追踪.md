# 指标与追踪

> 对应 OpenTelemetry 标准；LLM trace 实践。

## 一、背景与挑战

一次请求跨多组件，需 trace 串联与指标聚合定位慢点。

## 二、核心原理

用 span 记录每段（网关/限流/调度/生成），父子关联；指标用 RED + 自定义 token 指标；采样控开销。

## 三、数学形式

链路耗时 $T = \sum span_i$；关键路径为最长依赖链。

## 四、代码实现

```python
with tracer.start_as_current_span("llm.gen") as s:
    s.set_attribute("completion_tokens", ct)
```

## 五、与其他对比

- 与 API网关可观测性深入（入口 trace）互补。
- 与 推理缓存与命中优化深入（命中指标）相关。

## 六、常见误区

- 100% 采样致开销大，需尾采样。
- span 过细噪声、过粗无定位力。

## 八、面试题

- trace 与 metric 区别？答：trace 看单次链路延迟分布，metric 看聚合趋势。

## 九、演进

日志 → 指标 → 分布式追踪 → 采样。

## 十、小结

指标看趋势、trace 查单次，二者结合排障。
