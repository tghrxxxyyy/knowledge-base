# 延迟与吞吐监控

> 对应 LLM 服务 SLO（TTFT/ITL/吞吐）；vLLM 指标。

## 一、背景与挑战

用户感知延迟（首字/逐字）与系统吞吐需分别监控，否则体验与成本脱节。

## 二、核心原理

监控 TTFT（排队+prefill）、ITL（解码间隔）、吞吐（tok/s/卡）、队列深度；分位而非均值。

## 三、数学形式

ITL 方差 $\sigma_{ITL}^2$ 反映卡顿；排队延迟 $Q = \lambda\cdot E[t^2]/(2(1-\rho))$。

## 四、代码实现

```python
histogram("ttft", ttft, buckets=[0.1,0.5,1,3])
gauge("queue_depth", len(sched))
```

## 五、与其他对比

- 与 模型服务负载均衡深入（吞吐来源）衔接。
- 与 推理缓存与命中优化深入（降 TTFT）相关。

## 六、常见误区

- 只看均值忽略 P99 卡顿。
- 吞吐高但 ITL 大（批过大）未察觉。

## 八、面试题

- 为何看 P99 而非均值？答：少数长尾请求最影响体验，均值掩盖卡顿。

## 九、演进

均值 → P95 → P99/ITL 分布。

## 十、小结

延迟监控看分位与 ITL，吞吐看每卡效率。
