# 可观测性实践

> 对应生产 LLM 观测落地；Prometheus+Grafana+OTel。

## 一、背景与挑战

工具零散、数据孤岛，需统一管线把指标/trace/日志汇到一起。

## 二、核心原理

OTel 采集→Prometheus 存指标→Grafana 看板；LLM 专用加 token/质量面板；告警接 OnCall。

## 三、数学形式

可观测性覆盖度 $c = \frac{|\text{instrumented}|}{|\text{components}|}\to 1$。

## 四、代码实现

```python
from opentelemetry import metrics
meter.create_histogram("llm.latency").record(t)
```

## 五、与其他对比

- 与 指标与追踪深入 衔接（本节落地）。
- 与 成本优化与资源调度深入（成本面板）相关。

## 六、常见误区

- 面板过多无人看；应聚焦 SLO。
- 高基数标签炸 Prometheus。

## 七、与开源书对应

## 八、面试题

- 落地可观测性要点？答：统一采集、聚焦 SLO 面板、控标签基数、接告警。

## 九、演进

散工具 → OTel 统一 → SLO 驱动看板。

## 十、小结

可观测性落地靠统一管线+SLO 看板+告警闭环。
