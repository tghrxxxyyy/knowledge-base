# 大模型监控总览

> 对应 LLM 可观测性（traces/metrics）；OpenLLMetry 实践。

## 一、背景与挑战

LLM 输出非确定性、链路长（网关→服务→模型），需专门监控保障质量与成本。

## 二、核心原理

三层：基础设施（GPU/显存/延迟）、请求（token/错误/满意度）、质量（幻觉/偏置）指标，统一看板+告警。

## 三、数学形式

可用性 $A = \frac{uptime}{uptime+downtime}$；SLO 常以错误预算约束。

## 四、代码实现

```python
record(metric="tokens", value=n, tags={"model":m})
alert_if(error_rate > 0.05)
```

## 五、与其他对比

- 与 API网关可观测性深入（网关层）衔接。
- 与 大模型监控与告警深入 各节展开。

## 六、常见误区

- 只监控基础设施忽略输出质量。
- 指标无标签致难定位租户。

## 七、与开源书对应

- datawhalechina/llm-universe：https://github.com/datawhalechina/llm-universe
- mlabonne/llm-course：https://github.com/mlabonne/llm-course

## 八、面试题

- LLM 监控特别在哪？答：非确定输出+长链路，需质量与成本指标并重。

## 九、演进

资源监控 → 请求指标 → 质量可观测。

## 十、小结

LLM 监控覆盖设施/请求/质量三层，质量不可省。
