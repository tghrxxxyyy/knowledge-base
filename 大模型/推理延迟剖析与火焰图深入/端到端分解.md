# 端到端延迟分解

> 对应把请求延迟拆为排队/调度/prefill/decode 各段。

## 一、背景与挑战

优化需先定位是哪段主导，避免盲目改内核。

## 二、核心原理

在引擎各阶段埋点：入队时刻、schedule 时刻、prefill 起止、每 decode 步起止、采样耗时；输出分位（P50/P99）诊断长尾。

## 三、数学形式

$L = L_q + L_{sch} + L_{pre} + n L_{dec} + L_{sample}$；长尾常由 $L_q$ 或抢占引起。

## 四、代码实现

```python
trace = {"q":t_q, "pre":t_pre, "dec":t_dec}
```

## 五、与其他对比

- 与 迭代级批处理调度深入：调度/抢占段在此可见。
- 与 推理延迟剖析与火焰图深入 总览：分解是火焰图前提。

## 六、常见误区

- 平均延迟掩盖 P99 长尾（由排队/抢占）。
- 埋点自身开销污染测量。

## 七、与开源书对应

## 八、面试题

- 长尾延迟常因？答：排队堆积或抢占换出，非纯计算，需调度层治理。

## 九、演进

端到端 → 阶段埋点 → 分布式 trace。

## 十、小结

端到端分解先定性再定量，是性能治理的第一把刀。
