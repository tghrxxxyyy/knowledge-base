# 推理延迟剖析总览

> 对应 LLM 服务性能剖析（与 vLLM/TensorRT-LLM 性能文档相关）。

## 一、背景与挑战

推理慢在何处？需分解 TTFT（首 token）与 TPOT（每 token）到算子/内核层级，方能针对性优化。

## 二、核心原理

端到端延迟 = 排队 + 调度 + 预填充（prefill）+ 解码（decode，含 KV 读写、GEMM、采样）；用 profiler 逐层下钻定位热点。

## 三、数学形式

TTFT $=t_{queue}+t_{prefill}$；TPOT $\approx t_{decode}/1$（自回归）；总 $=TTFT+n\cdot TPOT$。

## 四、代码实现

```python
t0=time(); out=generate(req); print(time()-t0, len(out))
```

## 五、与其他对比

- 与 迭代级批处理调度深入：调度开销在剖析中可见。
- 与 张量核心与混合精度推理深入：GEMM 占比在火焰图显现。

## 六、常见误区

- 只看端到端忽略构成（队列 vs 计算）。
- 在 CPU 端计时忽略 GPU 异步未同步。

## 八、面试题

- TTFT 与 TPOT 区别？答：前者含排队+prefill，后者为逐 token 解码延迟。

## 十、小结

延迟剖析先把端到端拆为阶段，再下钻内核，是优化起点。
