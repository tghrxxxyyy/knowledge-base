# 优化器状态分片总览

> 对应 Rajbhandari et al., *ZeRO: Memory Optimizations*, 2020；与 数据并行深入 / FSDP深入 衔接。

## 一、背景与挑战

数据并行各卡复制完整优化器状态（Adam 的 m/v、fp32 副本），显存随模型增大成为瓶颈。

## 二、核心原理

ZeRO 将优化器状态、梯度、参数分片到各卡，每卡只持有一部分，通信换显存。

## 三、数学形式

Adam 状态显存约 $12\Phi$（fp16 参数+梯度+fp32 副本+m/v）；分片后约 $12\Phi/N$。

## 四、代码实现

```python
from deepspeed import ZeroStageOption
cfg = {"zero_optimization": {"stage": 2}}
```

## 五、与其他对比

- 与 梯度累积深入 在显存上互补（分片省状态、累积省激活）。
- 与 FSDP深入 是同源不同实现的产物。

## 六、常见误区

- 以为分片零通信，实际有 all-gather/reduce-scatter。
- 小模型用高 stage 反增通信负担。

## 八、面试题

- 优化器状态为何占显存大？答：Adam 维护 fp32 副本与 m/v，约 12 字节每参数。

## 九、演进

DDP → ZeRO-1/2/3 → Offload/FP16 优化器。

## 十、小结

优化器状态分片以通信换显存，是训练超大模型的基石技术。
