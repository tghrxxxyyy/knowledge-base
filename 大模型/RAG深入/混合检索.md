# 混合检索 Hybrid Search

> 对应 mlabonne/llm-course「RAG / Hybrid Search」；关键词 + 向量互补。

## 一、背景与挑战

纯向量检索擅长「语义泛化」，但对**专有名词、ID、精确短语、稀有词**不敏感——因为语义模糊化会把「精确匹配」信号抹平。例如查询里的人名、产品型号、错误码，向量检索常常查不到字面命中的文档。

同时，向量检索对词序、拼写高度敏感，而用户对精确短语的诉求在很多时候是刚性的。单一向量检索召回率因此存在结构性天花板，尤其在专业术语密集的场景。

## 二、核心原理

混合检索 = 稀疏检索(关键词，如 BM25) + 稠密向量检索，融合两路得分：

- **BM25**：基于词频与逆文档频率，擅长精确匹配与稀有词加权。
- **稠密向量**：基于语义，擅长同义/改写泛化。

两路互补：BM25 补「字面命中」，向量补「语义命中」，共同提升召回与精度。融合常用两种方式：

```
加权求和：score = α · dense_score + (1-α) · bm25_score
Reciprocal Rank Fusion(RRF)：按排名倒数加权，无需归一化
```

生产上 RRF 因免归一化、鲁棒，常被优先采用。

## 三、形式化与数学基础

BM25 对查询词 $q$ 与文档 $d$ 的得分：

$$\mathrm{BM25}(q,d)=\sum_{t\in q} \mathrm{IDF}(t)\,\frac{f_{t,d}\,(k_1+1)}{f_{t,d}+k_1(1-b+b\cdot |d|/L_{\text{avg}})}$$

其中 $f_{t,d}$ 为词频，$k_1,b$ 为调节参数。RRF 则只依赖各路返回的排序位置：

$$\mathrm{RRF}(d)=\sum_{r\in \text{runs}}\frac{1}{k+\mathrm{rank}_r(d)}$$

$k$ 为常数(常取 60)，对分数尺度不敏感，故鲁棒且免归一化；加权求和则要求两路分数先归一化到可比尺度。

## 四、代码实现

```python
def rrf(rank_lists, k=60):
    scores = {}
    for ranks in rank_lists:           # 每路返回有序 doc_id 列表
        for i, doc in enumerate(ranks):
            scores[doc] = scores.get(doc, 0.0) + 1.0 / (k + i + 1)
    return sorted(scores, key=scores.get, reverse=True)

# 融合：向量路 + BM25 路
final = rrf([dense_ranked, bm25_ranked])
```

## 五、与其他技术对比

| 检索方式 | 精确匹配 | 语义泛化 | 备注 |
|----------|----------|----------|------|
| 纯 BM25 | 强 | 弱 | 无嵌入依赖 |
| 纯向量 | 弱 | 强 | 需嵌入 |
| 混合(RRF) | 强 | 强 | 推荐默认 |
| 混合(加权) | 强 | 强 | 需归一化 |

## 六、常见误区

- 直接对两路原始分数加权求和，却忽略量纲差异导致某路主导。
- 认为混合一定优于纯向量，在小语料/强语义场景未必。
- 忘记为 BM25 维护可更新的倒排索引。
- RRF 的 $k$ 取值过小会过度偏向排名靠前者，过大则各路区分度下降。
- 两路候选集不一致(如向量取 Top100、BM25 取 Top20)导致融合偏斜。

## 九、演进与趋势

混合检索成为生产 RAG 默认配置。SPLADE、BM25 与稠密向量进一步统一为「稀疏-稠密联合表征」(如 BGE-M3 同时输出稀疏与稠密向量)，一次编码即获得两路信号，部署更简洁；学习型融合(用模型学融合权重)也在提升精度。

## 十、小结

混合检索以 BM25 补向量之「精确匹配」短板，以向量补 BM25 之「语义」短板。RRF 因免归一化、鲁棒而被广泛采用，是提升召回的性价比之选；稀疏-稠密联合表征让两路信号一次编码即得。
