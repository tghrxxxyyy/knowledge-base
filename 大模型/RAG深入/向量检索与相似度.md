# 向量检索与相似度度量

> 对应 mlabonne/llm-course「RAG / Vector Stores」；相似度度量是检索排序的基础。

## 一、背景与挑战

检索本质是把查询向量与海量文档向量「比远近」，而「远近」如何定义直接决定召回结果。文本嵌入向量应当用哪种相似度，是检索工程的基本决策：

- 文本语义对「方向」敏感，而非绝对大小。
- 不同嵌入模型的向量分布(均值、方差、模长)不同。
- 跨模型、跨任务的向量空间彼此不可比。
- 低精度(如 float16/float8)累积点积会带来数值偏差。

理解三种基础度量及其关系，是正确配置向量库与避免分数异常的前提。

## 二、核心原理

三种常用度量：

| 度量 | 公式 | 适用 |
|------|------|------|
| 余弦 | $\cos=\frac{a\cdot b}{\|a\|\|b\|}$ | 方向敏感(文本) |
| 点积 | $a\cdot b$ | 已归一化等价余弦 |
| 欧氏 | $\|a-b\|$ | 绝对距离 |

文本检索几乎都用余弦(或归一化后的点积)。关键事实：**当两向量均已 L2 归一化(模长为 1)时，余弦相似度等于点积**。因此工程上常先归一化再点积，复用高效的点积索引，同时避免模长差异干扰排序。

## 三、形式化与数学基础

余弦相似度：

$$\cos(a,b)=\frac{a\cdot b}{\|a\|\|b\|}$$

归一化向量 $\hat a=a/\|a\|$，$\hat b=b/\|b\|$，则：

$$\hat a\cdot\hat b=\frac{a\cdot b}{\|a\|\|b\|}=\cos(a,b)$$

欧氏距离 $\|a-b\|^2=\|a\|^2+\|b\|^2-2a\cdot b$；在归一化条件下 $\|a\|=\|b\|=1$，故欧氏距离与余弦单调相关，排序一致。这就是「归一化后三者等价排序」的数学基础，也是为什么归一化是 RAG 检索的默认前置步骤。

## 四、代码实现

```python
import numpy as np

def cosine(a, b):
    a, b = np.asarray(a), np.asarray(b)
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

# 先归一化再用点积，等价于余弦且更快，便于复用点积索引
def dot_after_norm(a, b):
    a_n, b_n = a / np.linalg.norm(a), b / np.linalg.norm(b)
    return float(np.dot(a_n, b_n))
```

## 五、与其他技术对比

| 度量 | 对模长 | 对方向 | RAG 推荐 |
|------|--------|--------|----------|
| 余弦 | 不敏感 | 敏感 | 推荐 |
| 点积 | 敏感 | 敏感 | 归一化后可用 |
| 欧氏 | 敏感 | 间接 | 一般不用 |

## 六、常见误区

- 未归一化就混用「余弦」与「点积」，得到不同排序。
- 把不同嵌入模型的向量直接比相似度，空间不可比。
- 误以为欧氏距离与余弦在任意情况等价(仅归一化时等价)。
- 用 float32 低精度累积大量向量点积时出现数值偏差。
- 忽略重排模型输出与检索分数的尺度差异，直接拼接比较。

## 九、演进与趋势

检索相似度正从「单一余弦」走向「多表征联合打分」(稠密向量 + 稀疏词权 + 元数据加权)。部分向量库支持在索引层直接指定度量并自动归一化，降低配置出错概率；量化检索(float8/int8)在控制数值偏差的同时大幅压缩内存。

## 十、小结

文本检索默认用余弦相似度；归一化后余弦与点积等价，可复用高效点积索引。务必保证检索与重排使用同一嵌入空间与同一度量，跨模型向量不可直接比较，并注意数值精度。
