# 图谱 RAG GraphRAG

> 对应微软 Microsoft GraphRAG 与 mlabonne/llm-course 进阶；用知识图谱增强全局问答。

## 一、背景与挑战

传统 RAG 擅长「点查」：给定一个具体问题，检索出最相关的若干片段作答。但面对**全局性、聚合性、概括性**问题(如「这份报告里所有风险主题的演变趋势是什么？」「社区讨论的主要争议有哪些？」)，点查只能零散命中片段，无法给出宏观结构化答案。

根因在于：向量检索基于局部语义相似，天然缺乏对「实体间关系、主题间聚合」的全局视图；多跳关系也被打散在不同片段中，难以串联。

## 二、核心原理

GraphRAG 在离线阶段用 LLM 从文档中抽取**实体-关系-主张**，构建知识图谱，并做**社区检测(community detection)**与社区级摘要；在线阶段既能做传统向量检索，也能沿图遍历或在社区摘要上做全局归纳：

```
离线：文档 → LLM 抽取(实体/关系/声明) → 建图 → 社区检测 → 社区摘要
在线：问题 → 向量检索 ∪ 图遍历 / 社区摘要聚合 → LLM 综合作答
```

社区摘要弥补了局部检索的全局盲点，使「鸟瞰式」问题可被回答；图遍历则把分散的实体关系串联成推理链路。

## 三、形式化与数学基础

将文档集建模为图 $G=(V,E)$，节点 $v\in V$ 为实体，边 $e\in E$ 为关系。社区划分把节点聚为互不重叠(或重叠)的子集 $\{C_1,\dots,C_K\}$。对每个社区生成摘要文本 $S_i$。全局查询 $q$ 的作答可视为对社区摘要集合的聚合：

$$\text{answer}(q)=\mathrm{LLM}\Big(q,\ \bigcup_{i=1}^{K} S_i\Big)$$

图遍历则沿边扩展邻域 $N(v)$，捕捉多跳关系；模块度优化决定社区划分质量。

## 四、代码实现

```python
# Microsoft GraphRAG 管线(示意)
from graphrag.index import index as graphrag_index
from graphrag.query import search

# 离线建图与社区摘要
graphrag_index.run(config="settings.yaml", root="./input")

# 在线：全局查询走社区摘要聚合
result = search.global_search(
    query="本批文档讨论的主要风险主题有哪些？",
    root="./output",
)
print(result.response)
```

## 五、与其他技术对比

| 维度 | 传统 RAG | GraphRAG |
|------|----------|----------|
| 擅长 | 点查、事实 | 全局、聚合 |
| 离线成本 | 低 | 高(抽取+摘要) |
| 可解释 | 片段引用 | 图+社区溯源 |
| 适用 | 通用 | 知识密集 |

## 六、常见误区

- 把 GraphRAG 当所有场景默认方案，忽视其高昂离线成本。
- 认为图一定优于文本，其实实体抽取噪声会污染图谱。
- 社区粒度设错导致摘要过粗(丢细节)或过碎(失聚合价值)。
- 忽略图谱与向量索引的协同而非替代关系。
- 同名实体未做消歧，被错误合并。

## 九、演进与趋势

图谱 RAG 与「Agentic 检索」「多跳推理」结合，向「自动构建动态子图并推理」演进。更轻量的方案(如 HippoRAG)尝试用生物启发记忆机制与个性化 PageRank 降低建图成本，使图谱增强在更多场景可行。

## 十、小结

GraphRAG 用「实体-关系图谱 + 社区摘要」补传统 RAG 的全局盲点，适合知识密集型、需鸟瞰式回答的场景，但需权衡离线抽取与摘要成本；实体抽取质量与社区粒度是工程成败关键。
