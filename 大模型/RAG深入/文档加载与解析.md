# 文档加载与解析

> 对应 Datawhale llm-universe「文档加载与切割」与 LangChain/LlamaIndex Loaders；多格式解析是 RAG 数据管线第一步。

## 一、背景与挑战

知识源极其多样：PDF、Word、Markdown、网页、数据库、表格、PPT、扫描件……它们格式异构、版式复杂。RAG 数据管线第一步就是把这些「非结构化/半结构化」源统一解析为带元数据的纯文本，供后续切分与嵌入。

核心挑战：

- **PDF 版式**：多栏、表格、公式、页眉页脚错乱。
- **扫描件**：需 OCR，且版面恢复困难。
- **网页噪声**：导航、广告、脚本混入正文。
- **表格/图表**：结构化信息易在转文本时丢失语义。
- **大文件**：分块加载避免内存溢出。

解析质量直接决定下游切分与检索上限。

## 二、核心原理

解析目标是「保结构地抽取文本」：保留标题层级、段落、表格，并附上来源/页码等元数据，使后续切分不割裂语义、生成可溯源。常用工具栈：

- **LangChain Document Loaders**：Unstructured / PyPDF / WebBase 等。
- **LlamaIndex**：面向 RAG 的加载与索引一体化。
- **unstructured / 专业库**：复杂版式 PDF、扫描件解析。
- **OCR**：PaddleOCR、Tesseract 等处理扫描件。

解析产出统一的 `Document(page_content, metadata)` 结构，再交给切分器。现代方案也用多模态大模型直接「看图取文」，提升复杂版式还原度。

## 三、形式化与数学基础

把加载视为映射 $\phi: \text{Source} \to \{(t_i, m_i)\}_{i=1}^{n}$，其中 $t_i$ 为文本块、$m_i$ 为其元数据(来源、页码、标题路径)。质量目标可写为还原度：

$$\mathrm{fidelity}=\frac{|\text{保留的结构单元}|}{|\text{原文结构单元}|}$$

结构单元含表格单元格、标题层级、列表等；fidelity 越高，下游切分越不易割裂语义，生成也越能正确溯源。

## 四、代码实现

```python
from langchain_community.document_loaders import PyPDFLoader, WebBaseLoader

docs = PyPDFLoader("manual.pdf").load()          # 每页一个 Document
web = WebBaseLoader("https://example.com").load() # 网页正文

for d in docs:
    print(d.metadata.get("page"), d.page_content[:80])
```

对扫描件需先 OCR：`d = pyocr / paddleocr(image)` 再转文本；表格建议用专门 table parser 保留单元格结构。

## 五、与其他技术对比

| 源 | 挑战 | 工具 |
|----|------|------|
| PDF | 版式/表格/扫描 | PyPDF / unstructured / OCR |
| 网页 | 噪声清洗 | WebBaseLoader / BeautifulSoup |
| 表格 | 结构保持 | csv / pandas / table parser |
| Word | 样式 | Docx2txt |
| 扫描件 | OCR | PaddleOCR / Tesseract |

## 六、常见误区

- 忽略表格，导致结构化知识在转文本时丢失。
- 网页抓取未去导航/广告噪声，污染索引。
- 解析时丢弃标题层级元数据，使切分失去结构依据。
- 把扫描件当文本 PDF 直接读，得到空白内容。
- 大文件一次性加载导致内存溢出，未做流式/分块加载。

## 九、演进与趋势

从「规则/OCR 解析」走向「多模态大模型直接理解版式」，把 PDF 页面作为图像由视觉语言模型抽取结构化文本与表格，大幅降低复杂版式丢失。解析正与切分、嵌入形成端到端一体化管线，并支持增量更新与版本管理。

## 十、小结

文档加载与解析是 RAG 数据管线地基。保结构、保元数据、去噪声的解析质量，直接决定下游切分与检索上限；应按源类型选对工具，并对扫描件与表格给予特别处理，复杂版式可借助多模态模型。
