# 文本切分策略 Chunking

> 对应 llm-universe 与 llm-course。切分粒度直接影响检索召回与上下文质量。

## 一、核心概念

把长文档切成「块(chunk)」，每块嵌入建索引。关键权衡：

- **块太小**：语义不完整，检索到的片段缺乏上下文。
- **块太大**：嵌入模糊、检索不准、占用上下文窗口。

常用策略：

| 策略 | 说明 |
|------|------|
| 固定长度 | 按字符/token 数切，重叠 overlap |
| 递归字符 | 按段落→句子→词递归，保结构 |
| 语义切分 | 按语义边界(句向量突变)切 |
| 按结构 | Markdown 标题/代码块切 |
| 父子文档 | 小块检索、父块喂给 LLM |

## 二、代码实现（LangChain 递归切分）

```python
from langchain.text_splitter import RecursiveCharacterTextSplitter
splitter = RecursiveCharacterTextSplitter(
    chunk_size=500, chunk_overlap=50,
    separators=["\n## ", "\n### ", "\n\n", "\n", "。", ""])
chunks = splitter.split_documents(docs)
```

## 三、关键要点

- `chunk_overlap` 防边界信息割裂。
- 检索用小块、生成用大块（父子文档）是常见最佳实践。

## 四、常见误区

- 重叠过大导致重复上下文浪费。
- 切分忽略语言特性（中文按字切优于按空格）。
