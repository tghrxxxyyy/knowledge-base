# 嵌入模型选型

> 对应 mlabonne/llm-course「Embeddings」与 Hugging Face MTEB 榜单；嵌入质量决定语义检索上限。

## 一、背景与挑战

检索增强生成(RAG)的检索质量根本上取决于「文本 → 向量」的映射质量。一个糟糕的嵌入模型会让语义相近的句子在向量空间里相距甚远，使后续所有检索、重排、生成努力都建立在不稳固的地基上。

选型时面临的典型挑战：

- **领域漂移**：通用嵌入在医疗、法律、代码等垂直领域的语义边界与通用语料差异大。
- **维度与成本权衡**：高维向量更精准但存储与检索开销线性上升，长上下文嵌入(如 8k token)成本更高。
- **多语言/跨语言**：中文查询检索英文文档需要跨语言对齐能力，否则跨语言相似度偏低。
- **归一化与可比性**：不同模型输出的向量分布(均值、方差、模长)不同，跨模型分数不可直接比较。
- **长文档建模**：段落级嵌入与文档级嵌入的粒度选择影响召回。
- **评测基准失真**：榜单第一未必适配你的具体查询分布，需做子集验证。

## 二、核心原理

嵌入模型本质是「句子/段落编码器」，通常通过对比学习训练：正样本(语义相同的不同表述)在向量空间靠近，负样本拉远。训练目标常用 InfoNCE：

$$\mathcal{L} = -\log \frac{\exp(s(q, d^+)/\tau)}{\sum_{i=1}^{N}\exp(s(q, d_i)/\tau)}$$

其中 $s(q, d)$ 为相似度，$\tau$ 为温度系数。推理阶段把文本编码为定长稠密向量，供 ANN 检索使用。

两类重要变体：

- **Instruct Embeddings**：在编码时拼接任务指令(如「为检索编码」)，同一模型适配不同任务。
- **Matryoshka 表征**：训练时让向量的「前缀维度」也保持语义，可截断到更小维度用，兼顾精度与成本。

主流模型谱系：OpenAI text-embedding-3 系列、BGE(智源)、M3E、E5(微软)、GTE(阿里)、BGE-M3(支持稠密/稀疏/多向量多检索范式)等。

## 三、形式化与数学基础

设查询嵌入 $q\in\mathbb{R}^d$、文档嵌入集合 $D=\{d_1,\dots,d_n\}\subset\mathbb{R}^d$，检索即求解：

$$\hat{d} = \arg\max_{d\in D}\ \mathrm{sim}(q, d)$$

常用相似度(归一化后互为等价)：

$$\cos(q,d)=\frac{q\cdot d}{\|q\|\|d\|},\qquad \|q\|=\|d\|=1 \Rightarrow \cos = q\cdot d$$

MTEB(Massive Text Embedding Benchmark)从检索、聚类、分类、比对、重排等多个任务综合打分，是横向选型的权威参考，但需结合自身业务子集做针对性验证，避免「榜单好、业务差」。

## 四、代码实现

```python
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("BAAI/bge-large-zh")
texts = ["大模型检索增强生成", "RAG 的检索架构"]
vecs = model.encode(texts, normalize_embeddings=True)  # L2 归一化
# 归一化后可直接用点积近似余弦
sim = float(np.dot(vecs[0], vecs[1]))
print(f"cosine sim = {sim:.4f}")
```

若使用 Matryoshka 模型，可截断维度复用：`vecs[:, :256]` 即更低维近似向量。

## 六、常见误区

- 检索与重排使用不同嵌入空间却未做对齐，导致分数不可比。
- 未做 L2 归一化，使余弦相似度与点积结果异常。
- 盲目追榜单第一，忽略自身语料分布差异。
- 误以为维度越高越好，忽视存储与检索的边际收益递减。
- 用短文本嵌入模型直接编码超长文档，语义被截断稀释。

## 九、演进与趋势

嵌入模型正从「单一稠密向量」走向「稠密 + 稀疏 + 多向量」统一表征(如 BGE-M3)，并强化长文档、多语言与指令跟随(如 instruct 版嵌入)。Matryoshka 表征学习让单模型可截取不同维度，兼顾精度与成本；更小更快的蒸馏模型持续压缩部署开销，长上下文嵌入(支持 8k token)让整篇文档直接编码成为可能。

## 十、小结

嵌入模型是 RAG 检索质量的上限决定者。选型应基于业务语料分布、维度成本、多语言需求与 MTEB 综合表现综合权衡，并坚持评测驱动、检索-重排空间对齐的工程纪律。
