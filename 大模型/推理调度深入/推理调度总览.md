# 推理调度总览

> 对应 LLM 服务调度（路由/排队/扩缩容）；与 推理服务深入 / 连续批处理深入 衔接。

## 一、背景与挑战

多模型/多副本/多租户下，请求如何路由、排队、扩缩决定成本与延迟。

## 二、核心原理

调度层在网关做负载均衡、亲和路由（同会话同副本）、优先级、自动扩缩。

## 三、数学形式

队列延迟 = 等待 + 服务；目标最小化 p99 同时控成本（GPU 时租）。

## 四、代码实现

```python
router.route(req, policy="affinity")   # 会话亲和
```

## 五、与其他对比

- 与 连续批处理深入（引擎内调度）分层：网关调度 vs 引擎步调度。
- 与 大模型网关与流量管控实战 衔接。

## 六、常见误区

- 忽略会话亲和致 KV 重建（重复计算）。
- 扩缩滞后致冷启动延迟。

## 七、与开源书对应

- llm-course：https://github.com/mlabonne/llm-course

## 八、面试题

- 为什么会话亲和重要？答：同会话落同副本可复用 KV，省重算。

## 九、演进

随机路由 → 亲和/优先级 → 自适应调度。

## 十、小结

推理调度在网关层统筹路由与资源，是成本与延迟的总开关。
