# 推理调度与网关关系

> 对应 LLM 网关架构；大模型网关与流量管控实战 衔接。

## 一、背景与挑战

调度逻辑应放网关还是引擎？职责划分影响灵活与性能。

## 二、核心原理

网关负责路由/认证/限流/计费；引擎负责步级连续批；二者通过 API/队列协作。

## 三、数学形式

端到端延迟 = 网关处理 + 网络 + 引擎排队 + 生成。

## 四、代码实现

```python
gw.auth(req); gw.limit(req); replica = sched.route(req); engine.step(replica, req)
```

## 五、与其他对比

- 与 大模型网关与流量管控实战 共享网关职责。
- 与 推理服务深入 共享。

## 六、常见误区

- 把引擎调度逻辑塞进网关致耦合。
- 网关无状态丢失亲和。

## 七、与开源书对应

- llm-course：https://github.com/mlabonne/llm-course

## 八、面试题

- 网关与引擎调度如何分工？答：网关管路由/限流/计费，引擎管步级批处理。

## 九、演进

单体 → 网关+引擎分离 → 服务网格。

## 十、小结

网关与引擎分层调度，职责清晰才能灵活可扩展。
