# 路由与会话亲和

> 对应请求路由策略。

## 一、背景与挑战

无状态路由使同会话请求落到不同副本，KV 无法复用。

## 二、核心原理

按会话 ID 哈希/一致性哈希路由到固定副本，复用 KV 缓存，降低首 token 延迟（TTFT）。

## 三、数学形式

命中本地 KV 省去重算，TTFT 从 $O(L)$ 降到 $O(1)$（相对）。

## 四、代码实现

```python
replica = hash(session_id) % n
forward(req, replica)
```

## 五、与其他对比

- 与 KV缓存优化深入（跨请求复用）互补。
- 与 多租户与资源隔离深入 共享路由。

## 六、常见误区

- 副本扩缩破坏一致性哈希映射致缓存失效。
- 亲和致热点副本过载。

## 七、与开源书对应

## 八、面试题

- 亲和路由的代价？答：副本不均/扩缩时缓存失效，需再平衡。

## 九、演进

无状态 → 会话亲和 → 分层缓存(全局 KV)。

## 十、小结

会话亲和是降低 TTFT 的有效手段，需配合再平衡。
