# 推理自动扩缩容

> 对应副本弹性伸缩。

## 一、背景与挑战

流量波动大，固定副本浪费或过载；需按负载扩缩。

## 二、核心原理

按队列长度/GPU 利用率/延迟指标扩缩副本，考虑冷启动与碎片。

## 三、数学形式

目标副本数 $n = \lceil \lambda / \mu_{cap} \rceil$（$\lambda$ 到达率，$\mu_{cap}$ 单副本容量）。

## 四、代码实现

```python
if qlen > H_high: scale_up()
if gpu_util < L_low: scale_down()
```

## 五、与其他对比

- 与 推理经济成本深入 直接相关（副本数=成本）。
- 与 边缘端侧推理深入 对照（端侧难弹性）。

## 六、常见误区

- 缩容过激致冷启动抖动。
- 忽视模型加载时间（分钟级）。

## 七、与开源书对应

- llm-course：https://github.com/mlabonne/llm-course

## 八、面试题

- 扩缩容难点？答：冷启动慢、指标滞后、碎片与亲和冲突。

## 九、演进

手动 → 阈值 → 预测式弹性。

## 十、小结

自动扩缩平衡成本与延迟，难点在冷启动与指标滞后。
