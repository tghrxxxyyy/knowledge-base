# 代理式代码智能体与工具调用

> 对应 Yao 2022 的 ReAct 论文与 github huggingface/transformers 项目。

## 一、背景与挑战
一次性生成整段程序容易在长逻辑中出错。代理式智能体通过「思考-行动-观察」循环，调用编译器、测试框架、文件读写等工具，把大任务分解为可验证的小步骤，从而提升可靠性。

## 二、核心原理
ReAct 把推理轨迹与外部动作交错：模型先输出 Thought 规划，再输出 Action 调用工具，环境返回 Observation，模型据此继续。代码场景下，Action 可以是运行单元测试、查询符号定义或编辑文件。

## 三、形式化与数学基础
轨迹概率分解为：
$ p(y|x)=\prod_{t} p(z_t | x, z_{<t}) $
其中 $ z_t\in\{\text{Thought},\text{Action},\text{Observation}\} $，Observation 来自环境而非模型。

## 四、代码实现
```python
def react_step(prompt, model, tools):
    # tools: dict name->callable
    out = model.generate(prompt)
    if 'Action:' in out:
        name = out.split('Action:')[1].split('\n')[0].strip()
        obs = tools[name]() if name in tools else 'unknown'
        return prompt + out + '\nObservation: ' + str(obs) + '\n'
    return prompt + out

def run_agent(task, model, tools, steps=10):
    buf = 'Task: ' + task + '\n'
    for _ in range(steps):
        buf = react_step(buf, model, tools)
        if 'Answer:' in buf:
            break
    return buf
```

## 五、与其他技术对比
相比纯 CoT 推理，ReAct 引入真实环境反馈，减少事实性错误；相比固定流水线，它更灵活但更难保证可复现。

## 六、常见误区
让模型编造工具返回结果而非真正执行，会退化为幻觉。未限制循环步数可能陷入重复动作。

## 七、与开源书/权威来源对应
- Yao 2022 ReAct（推理 + 行动）
- github huggingface/transformers 的 Tool 与 Agent 接口

## 八、面试题
问：ReAct 中 Observation 的作用？答：把不可微的环境信号回灌给模型，使后续决策基于真实状态而非记忆。

## 九、演进与趋势
向多工具编排、自动工具生成与带验证的树搜索方向发展。

## 十、小结
代理式代码智能体用工具闭环把生成错误暴露在可执行环境中，是可落地的工程范式。
