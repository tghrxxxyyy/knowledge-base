# 程序合成与约束解码

> 对应 Willard & Louf 2023 的 constrained decoding 论文。

## 一、背景与挑战
自由生成代码常产生不合语法的 token 序列或违反领域文法的输出。约束解码在生成阶段强制输出满足正则、文法或类型规则，既保证可用性又不必重训模型。

## 二、核心原理
把约束表示为有限状态机或上下文无关文法，每步只允许与当前状态相容的 token 进入候选。beam search 在受限 vocab 上归一化概率，从而输出始终合法。

## 三、形式化与数学基础
令合法前缀集合为 $ L $，第 $ t $ 步允许 token：
$ V_t = \{ v : \text{prefix}_{t-1} \cdot v \in \text{Prefix}(L) \} $
得分仅对 $ V_t $ 上的分布归一化。

## 四、代码实现
```python
def constrained_step(logits, allowed_mask):
    # logits: (V,) ; allowed_mask: bool (V,)
    big = -1e9 * (1 - allowed_mask)
    scores = logits + big
    return int(scores.argmax())

def synth(program, logits_seq, masks):
    toks = []
    for lg, mk in zip(logits_seq, masks):
        i = constrained_step(lg, mk)
        toks.append(i)
        if i == program.eos_id:
            break
    return toks
```

## 五、与其他技术对比
相比事后校验再重试，约束解码一次生成即合法，省去重采样开销；相比专用 DSL 编译器，它保留大模型泛化能力。

## 六、常见误区
约束过严会迫使模型在无法满足条件的位置强行截断。把文法写错会让整个生成失败。

## 八、面试题
问：约束解码如何不影响训练？答：仅在推理时对 logits 施加掩码，模型权重不变。

## 九、演进与趋势
从正则约束走向类型导向与语义约束，并与代理执行反馈结合。

## 十、小结
约束解码以最小的推理期成本把领域知识注入生成，是程序合成的关键技术。
