# 仓库级代码生成与上下文检索

> 对应 Lewis 2020 的 RAG 论文与 github run-llama/llama_index 项目。

## 一、背景与挑战
真实软件仓库包含数十万行跨文件代码，单文件上下文窗口远不足以覆盖调用关系、类型定义与配置依赖。仓库级代码生成需要从全局图谱中检索相关符号，再把局部片段拼回提示，否则生成的函数常引用不存在的接口或遗漏隐式约束。

## 二、核心原理
将仓库构建为代码图谱：文件、类、函数为节点，import 与调用为边。给定自然语言需求，先用向量检索召回 top-k 相似片段，再用图谱沿调用边做一跳或两跳扩展，得到结构化上下文。最终把上下文按相关性压缩进提示。

## 三、形式化与数学基础
检索得分可用最大内积搜索表示：
$ s(q,c)=\max_{c\in C}\; q^\top c / (\\|q\\|\\|c\\|) $
其中 $ q $ 为查询向量，$ c $ 为候选代码块向量，$ C $ 为仓库语料。

## 四、代码实现
```python
import numpy as np

def retrieve(query_vec, corpus_vecs, k=8):
    # query_vec: (d,) ; corpus_vecs: (n,d)
    norms = np.linalg.norm(corpus_vecs, axis=1)
    sims = corpus_vecs @ query_vec
    sims = sims / (norms * np.linalg.norm(query_vec) + 1e-9)
    idx = np.argsort(-sims)[:k]
    return idx, sims[idx]

def expand_by_graph(idx, adj, hops=1):
    seen = set(idx.tolist())
    for _ in range(hops):
        nxt = set()
        for i in seen:
            nxt.update(adj.get(i, []))
        seen.update(nxt)
    return sorted(seen)
```

## 五、与其他技术对比
与仅用当前文件补全相比，仓库级检索显著提升跨文件一致性；但代价是检索延迟与上下文噪声。相较纯向量库，图谱扩展能显式建模调用依赖，减少幻觉接口。

## 六、常见误区
误以为检索越多越好，导致提示被无关片段淹没。忽略符号重名与多版本 API 会造成错误上下文。把测试文件当作实现上下文也会误导生成。

## 八、面试题
问：仓库级检索相比文件级补全的核心难点是什么？答：跨文件依赖建模、上下文预算分配与检索噪声过滤三者权衡。

## 九、演进与趋势
从简单向量召回走向调用图 + 提交历史的时序检索，并结合静态分析的精确符号定位。

## 十、小结
仓库级代码生成依赖检索与图谱的协同，关键是把全局结构压缩为高质量局部上下文。
