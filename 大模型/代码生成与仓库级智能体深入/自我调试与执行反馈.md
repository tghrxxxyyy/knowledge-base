# 自我调试与执行反馈

> 对应 Wei 2022 的 chain-of-thought 论文与 github facebookresearch/llama 项目。

## 一、背景与挑战
模型首次生成的代码常有运行时错误或逻辑偏差。自我调试让模型读取执行器或测试返回的报错，定位问题并修订，形成生成-执行-修正闭环。

## 二、核心原理
把报错信息作为追加上下文，提示模型以 CoT 分析根因，再输出补丁。多轮迭代直到测试通过或步数耗尽，可将通过率显著提升。

## 三、形式化与数学基础
设验证器 $ V $ 返回布尔通过与轨迹 $ \tau $，目标是最小化：
$ \mathcal{L}=\sum_{t} \mathbb{I}[V(\text{fix}_t)=\text{False}] $
其中 $ \text{fix}_t $ 为第 $ t $ 轮修订。

## 四、代码实现
```python
def self_debug(gen, run, refine, task, rounds=5):
    code = gen(task)
    for _ in range(rounds):
        err = run(code)
        if err is None:
            return code
        code = refine(task, code, err)
    return code

def execute(code):
    try:
        exec(compile(code, 'prog', 'exec'))
        return None
    except Exception as e:
        return str(e)
```

## 五、与其他技术对比
相比一次性生成，自我调试用真实执行信号纠错；相比人工调试，自动化闭环可规模化但受测试覆盖限制。

## 六、常见误区
把报错文本直接当答案会导致泄露测试。无限重试浪费算力且无收敛保证。

## 八、面试题
问：执行反馈为何比人工标注便宜？答：运行器可无限次提供信号，且错误信号即监督。

## 九、演进与趋势
结合静态分析、类型检查与形式化验证构建多层反馈。

## 十、小结
自我调试把可执行环境变为训练与推理的隐形教师，是代码智能体核心。
