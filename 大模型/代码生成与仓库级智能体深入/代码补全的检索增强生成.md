# 代码补全的检索增强生成

> 对应 github stanford-futuredata/ColBERT 项目与 Lewis 2020 RAG 论文。

## 一、背景与挑战
编辑器内的代码补全需要低延迟且上下文相关。仅靠模型参数记忆难以覆盖私有仓库风格与最新 API，因此需要在输入侧注入从代码库检索的相似片段。

## 二、核心原理
采用 late-interaction 检索：把查询与候选都切分为 token 级向量，用最大相似度求和衡量相关性。返回片段与光标前后上下文拼接后送补全长模型。

## 三、形式化与数学基础
ColBERT 打分：
$ S(q,D)=\sum_{i}\max_{j} q_i^\top d_j $
其中 $ q_i $ 为查询 token 向量，$ d_j $ 为文档 token 向量。

## 四、代码实现
```python
import numpy as np

def colbert_score(q_vecs, d_vecs):
    # q_vecs: (mq,d) ; d_vecs: (md,d)
    sim = q_vecs @ d_vecs.T
    return float(sim.max(axis=1).sum())

def rank(cands, q_vecs):
    scores = [colbert_score(q_vecs, cv) for cv in cands]
    order = np.argsort(-np.array(scores))
    return order
```

## 五、与其他技术对比
相较单向量检索（如 FAISS 扁平内积），late-interaction 保留 token 级匹配，更适合代码标识符对齐；代价是存储与计算更大。

## 六、常见误区
把整文件塞入索引忽略函数边界，会降低匹配精度。未做去重会让相似片段重复占预算。

## 八、面试题
问：late interaction 为什么适合代码？答：代码相关性常在少数关键标识符上，token 级最大匹配更鲁棒。

## 九、演进与趋势
向结构化切片（AST 节点）检索与增量索引演进。

## 十、小结
检索增强让补全具备仓库感知能力，是私有代码场景的标配。
