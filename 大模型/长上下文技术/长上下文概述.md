# 长上下文技术概述

> 对应 llm-course「长上下文与推理优化」、FlashAttention（Dao et al., 2022）、Ring Attention（Liu et al., 2023）与 StreamingLLM（Xiao et al., 2023）等原始工作。

## 一、背景与挑战

现代大语言模型在训练时受限于算力与显存，上下文窗口（context window）通常固定为某个长度 $L$（如 4K、8K、32K）。但随着应用深入，许多真实场景需要模型「一眼看尽」远超训练长度的内容：

- **整本文档/书籍问答**：合同、论文、代码仓库的全文理解。
- **长程代码库推理**：跨文件、跨函数的依赖追踪。
- **超长对话与 Agent 多轮**：保留数十轮乃至上百轮交互状态。
- **长视频/长音频转写后的语义对齐**。

把序列长度从 $L$ 提升到 $L'$ 时，最朴素的稠密自注意力会带来两个核心困难：

1. **计算复杂度**：$O(L^2 d)$ 的时间与 $O(L^2)$ 的显存，使 128K 甚至 1M 长度在朴素实现下无法运行。
2. **位置外推（extrapolation）**：训练时只见过位置 $[0, L)$，如何让其泛化到 $[0, L')$ 是位置编码的根本难题。

## 二、核心原理

长上下文技术大致分两条主线。

**主线 A：位置外推**。模型参数不变，仅改造位置编码或推理时的位置映射，使已训练好的权重能「看懂」更长位置。代表方法：ALiBi 的距离偏置、RoPE 配合 NTK-aware 缩放、位置插值（PI）、YaRN 等（见本系列「位置外推方法对比」「上下文窗口扩展」）。

**主线 B：注意力/显存优化**。在不改变语义的前提下降低 $O(L^2)$ 的代价，代表作：

- FlashAttention：以分块（tiling）与重计算（recomputation）把注意力在 SRAM 内完成，将显存从 $O(L^2)$ 降到 $O(L)$。
- 稀疏/线性注意力：限制每个 token 只关注局部窗口或固定模式。
- 分页/分块 KV Cache（如 PagedAttention）：推理时按页管理 KV，缓解长上下文显存碎片。

此外还有**继续训练（long-context continual pretraining）**：在长序列语料上以较长 $L'$ 继续训练，让模型真正学会长程依赖，而非仅外推。

## 三、形式化与数学基础

自注意力的核心运算对长度为 $n$ 的序列：

$$
\text{Attention}(Q,K,V)=\text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

其中 $Q,K,V\in\mathbb{R}^{n\times d_k}$。朴素实现需要显式 materialize $n\times n$ 的注意力矩阵，时间与显存均为 $O(n^2)$。

引入位置编码后，相似度实际变为带位置信息的度量。以 RoPE 为例，旋转后的查询与键：

$$
q_m=R_{\Theta,m}^d q,\quad k_j=R_{\Theta,j}^d k
$$

其内积仅依赖相对位置 $m-j$，这也是 RoPE 可被「外推」改造的基础。若采用位置插值，把位置索引压缩：

$$
m' = \frac{L}{L'}\,m
$$

使新位置 $m\in[0,L')$ 被映射到训练区间 $[0,L)$ 内，从而避免超出训练分布。

## 四、代码实现

以下用 HuggingFace Transformers 在加载 RoPE 系模型时启用长上下文缩放（以 YaRN 为例）：

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-7b-hf",
    rope_scaling={"type": "yarn", "factor": 4.0},  # 将窗口扩到约 4 倍
    attn_implementation="flash_attention_2",        # 使用 FlashAttention-2 降显存
    torch_dtype="auto",
)
tok = AutoTokenizer.from_pretrained("meta-llama/Llama-2-7b-hf")
text = "请阅读以下长文档并总结：" + "长文本" * 8000
out = model.generate(**tok(text, return_tensors="pt").to("cuda"), max_new_tokens=128)
print(tok.decode(out[0]))
```

注意：仅改 `rope_scaling` 属「免训练外推」，质量有限；要达到稳定长上下文通常还需配合继续训练。

## 五、与其他技术对比

| 维度 | 位置外推（PI/NTK/YaRN） | 注意力优化（FlashAttn） | 继续训练 | 检索增强（RAG） |
|------|------------------------|------------------------|----------|----------------|
| 是否改参数 | 否（或轻量） | 否 | 是 | 否 |
| 显存代价 | 不变 | 显著降低 | 训练成本高 | 低 |
| 外推上限 | 数倍~数十倍 | 依赖实现 | 由数据决定 | 理论无上限 |
| 适合场景 | 推理期快速扩容 | 长序列训练/推理 | 真长程能力 | 超长/外部知识 |

## 六、常见误区

- **「窗口数字越大越强」**：外推倍数过大而无继续训练，长程位置会落入未训练区域，事实一致性骤降。
- **混淆长度与容量**：能放得下不等于能「用好」，注意力对极远端 token 的权重易被近端淹没。
- **忽视 KV Cache 显存**：长上下文推理的瓶颈常在显存而非算力，分页/量化 KV 往往比换模型更关键。
- **以为 RAG 可完全替代长上下文**：RAG 依赖检索质量，缺失上下文时仍需要模型自身长程理解。

## 九、演进与趋势

- **从外推到真训练**：社区逐渐从「免训练外推」走向长上下文继续训练 + 数据配比（如长文档、书籍、repo 权重）。
- **稀疏与分层注意力**：局部窗口 + 全局 token 的混合模式在长视频/长音频中更常见。
- **KV Cache 压缩**：量化、驱逐（eviction，如 StreamingLLM 的 sink 机制）、共享前缀成为推理侧主战场。
- **无限上下文设想**：Ring Attention 把序列切到多设备，理论上可将上下文扩到「近无限」，受通信带宽约束。

## 十、小结

长上下文并非单一技术，而是「位置外推 + 注意力/显存优化 + 继续训练 + 检索增强」的组合拳。工程上常先用 RoPE 缩放/FlashAttention 做快速扩容，再用长上下文继续训练巩固质量，最后以 KV 压缩与 RAG 兜底超长场景。具体组合与倍率以官方最新文档与实践为准。
