# 长上下文评测

> 对应 *Needle In A Haystack*（Kamradt, 2023）、LongBench（Bai et al., 2023）、RULER（Hsieh et al., 2024）；参考 llm-course 长上下文章节。

## 一、背景与挑战

模型标称支持「128K token」不等于真能用好 128K。朴素长文问答可由模型先验知识蒙混，无法验证是否真正读完上下文。评测要回答：在任意长度、任意位置放入关键信息，模型能否稳定检索并据此回答？更要暴露「lost in the middle」——信息放在中部时召回率骤降的现象。挑战是构造可控、可复现、抗记忆的评测。

## 二、核心原理

方法论沿三个层次：(1) **NIAH（捞针）**——长 filler 中插入事实「针」，扫描长度×位置矩阵得准确率热力图；(2) **多任务长文**（LongBench）——摘要、单文档/多文档 QA、Few-shot 等真实长文任务；(3) **合成能力**（RULER）——聚合检索、多针、数值追踪等，抗数据污染。重点指标是「不同位置召回率」与「有效长度」（在指定准确率阈值下可达的最大长度）。评测须用虚构/随机针防记忆。

## 三、形式化与数学基础

对长度 $L$、位置比 $p$ 投放针，准确率：

$$\text{Acc}(L,p)=\mathbb{E}_q\big[\mathbf{1}(\hat y=y^\star)\big]$$

「lost in the middle」表现为中间区间偏低：

$$\text{Acc}(L,0.5) \ll \min\big(\text{Acc}(L,0.05),\ \text{Acc}(L,0.95)\big)$$

有效长度（阈值 $\alpha$）：

$$L_{\text{eff}}=\max\!\left\{L:\ \min_p \text{Acc}(L,p)\ge \alpha\right\}$$

RULER 综合多子能力得总分 $S=\sum_w w_i s_i$，更稳健反映真实长程能力。

## 四、代码实现

```python
def niah_eval(model, lengths, positions, needle):
    grid = {}
    for L in lengths:                 # 如 [4k, 16k, 32k, 64k, 128k]
        for p in positions:           # [0.0,0.25,0.5,0.75,1.0]
            hay = filler(L)[:int(L*p)] + needle["fact"] + filler(L)[int(L*p):]
            ok = needle["ans"] in model.chat(hay + "\n" + needle["q"])
            grid[(L, p)] = ok
    return grid                       # 绘热力图：行=长度，列=位置
```

## 五、与短上下文评测对比

| 维度 | 短上下文 | 长上下文 |
|---|---|---|
| 信息位置 | 单一 | 头/中/尾扫描 |
| 抗记忆 | 弱需去污染 | 需虚构针 |
| 主指标 | 准确率 | 有效长度+热力图 |
| 任务 | 多选/QA | 检索/摘要/多针 |

## 六、常见误区

- 只看头尾不测中部：中部最弱区常被漏，高估能力。
- 把标称长度当有效长度：实际常明显更短。
- 用已知事实当针：测的是记忆而非检索，应随机/虚构。
- 单点采样：需矩阵扫描才可靠。

## 八、面试题

1. 为何长上下文模型常「lost in the middle」？答：注意力对中部位置累积干扰最大、相对信号最弱，两端有边界增益。
2. 有效长度如何定义？答：在指定准确率阈值下模型可达的最大上下文长度。
3. NIAH 的针为何要虚构？答：防模型靠预训练记忆而非检索回答。

## 九、演进与趋势

从单点 NIAH 到 RULER 多能力合成、到 ∞-Bench 超长多语言；并开始评「多针聚合」「噪声干扰」「真实长文档」而非单事实检索，更贴近落地。

## 十、小结

长上下文评测用可控捞针矩阵与多任务长文集，揭示长度×位置两个维度的真实能力。它提醒我们：标称窗口 ≠ 有效长度，中部召回是核心短板，必须用虚构针与矩阵扫描才能客观衡量。
