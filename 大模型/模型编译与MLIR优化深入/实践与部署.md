# 编译实践与部署

> 对应生产编译部署；与 弹性推理自动伸缩深入 / 推理服务可观测性深入 衔接。

## 一、背景与挑战

编译收益依赖稳定形状与工作负载；动态 LLM 服务需谨慎。

## 二、核心原理

对固定 shape 预编译缓存；动态 batch 用符号形状+特化；导出为独立 artifact 供服务加载，配合版本管理。

## 三、数学形式

缓存命中率决定收益：命中走编译 kernel，未命中回退 eager（慢）。收益随特化度 $h$ 提升：$R(h)=\frac{|\text{compiled}(h)|}{|\text{total}|}$。

## 四、代码实现

```python
torch.compile(model, dynamic=True)   # 符号形状减少重编译
```

## 五、与其他对比

- 与 量化推理引擎深入 可级联（先量化后编译）；
- 与 模型编译总览 闭环。

## 六、常见误区

- 把编译 artifact 当跨硬件可移植（不可）；
- 忽略首次编译冷启动时延。

## 八、面试题

- 动态 shape 如何编译？答：用符号形状+特化，平衡重编译与覆盖。

## 九、演进

固定形状 → 符号形状 → AOT 全静态。

## 十、小结

编译部署需稳定形状与缓存策略，方能稳获收益。
