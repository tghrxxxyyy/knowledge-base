# 长上下文与 KV-Cache 优化

> 板块：大模型 / 上下文工程 　|　 返回：[README](README.md)

## 一、上下文窗口的真相

模型标称「支持 128K / 200K token」，但：

- **有效上下文 ≠ 标称窗口**：长文中间信息常被「丢失在中间」（lost in the middle）。
- **成本随长度线性增长**：输入 token 直接计费，且 KV-Cache 占显存。
- **延迟增加**：注意力是 O(n²) 复杂度（虽 FlashAttention 优化常数，仍随 n 增长）。

> 上下文工程的核心：用最少的 token 装下最相关的信息，而非无脑堆长。

## 二、KV-Cache 是什么

自回归生成时，每个新 token 都要和之前所有 token 做注意力。为避免重复计算，把历史 token 的 K、V 矩阵缓存下来：

- **显存占用** ≈ 2（K,V）× layers × seq_len × hidden × bytes。
- 长对话 / 长文档 = KV-Cache 爆炸的主因。
- 优化方向：减少 seq_len（压缩/裁剪）、降低精度、共享/复用。

## 三、KV-Cache 优化技术

| 技术 | 思路 | 收益 |
|------|------|------|
| KV 量化 | FP16 → INT8/INT4 | 显存降 2~4 倍 |
| PagedAttention | 分页管理，减少碎片 | 吞吐提升 |
| MQA / GQA | 多查询/分组共享 KV | KV 量降数倍 |
| 滑动窗口 | 只保留最近 N token | 无限长但丢远处 |
| 稀疏注意力 | 只算重要位置 | 长序列可行 |
| Prefix Cache | 系统提示/公共前缀复用 | 多轮省算力 |

## 四、Context 压缩策略

- **检索式上下文**：只把相关片段塞进 prompt（RAG），而非整本文档。
- **摘要压缩**：把早期对话摘要成几行，保留最近原文。
- **层级裁剪**：重要信息前置，次要信息后置或丢弃。
- **LongLLMLingua**：用小型模型压缩冗余 token，保信息量。

```python
# 简单上下文裁剪（保留最近 + 关键）
def build_context(history, max_tokens):
    recent = history[-k:]                 # 最近 k 轮原文
    summary = summarize(history[:-k])     # 更早的压缩成摘要
    return fit(summary + recent, max_tokens)
```

## 五、Lost-in-the-Middle 与应对

研究发现：把答案信息放中间，模型容易忽略；放开头/结尾召回更好。

- **重排证据**：把最相关片段放首尾。
- **分块问答**：先分段检索作答，再汇总，避免一次性塞长文。
- **显式指引**：prompt 里标注「关键信息在下方引用块」。

## 六、多轮对话的缓存复用

- 系统提示（system prompt）每轮相同 → Prefix Cache 复用，省重复计算。
- 工具定义、few-shot 示例固定在前缀，享受缓存命中。
- 用户历史若不变，整段前缀可复用 KV。

## 七、长文档处理架构

```
用户问 → 检索相关段落(top-k) → 计算各段重要性 → 重排 → 压缩 → 拼进 ≤窗口
      → 若仍超长：分块并行问答 → 聚合答案
```

- 不要直接把 100 页 PDF 丢进 prompt。
- 用 RAG + 分块问答 + 聚合，比单次长上下文更稳更省。

## 八、窗口外推（RoPE 缩放）

- 训练时窗口 4K，想用 32K → 需位置编码外推（NTK-aware RoPE、YaRN）。
- 外推会牺牲一定短文本精度，需实测。
- 优先选原生长窗口模型（如支持 128K 的模型），而非强行外推。

## 九、成本治理

- 估算成本：input_tokens × 单价。长上下文任务先压缩再发。
- 高频相同前缀用缓存（多数厂商对 cache 命中打折）。
- 监控每轮 token 数，设上限防失控。

## 十、评测长上下文能力

- 基准：LongBench、Needle-In-A-Haystack（针在草堆里）。
- 自测：在长文档里埋关键信息，看模型能否定位。
- 按任务定窗口：多数业务 8K~32K 足够，不必盲目上 200K。

## 十一、常见坑

1. 把整本文档塞 prompt → 贵且 lost-in-middle。
2. 不压缩多轮历史 → KV 爆显存、成本飙升。
3. 忽略 Prefix Cache → 重复算系统提示。
4. 强行外推窗口 → 短文本质量下降。
5. 只看标称窗口不看有效窗口 → 长文答非所问。

## 十二、落地清单

1. 量化「有效窗口」而非标称窗口。
2. RAG + 分块问答替代整文档。
3. 多轮历史摘要压缩 + Prefix Cache。
4. 关键证据重排到首尾。
5. 长任务先压缩再发，监控成本。
