## 一、三系统对比表

| 维度 | Codex CLI | Claude Memory | Gemini CLI |
| --- | --- | --- | --- |
| 文件名 | `AGENTS.md` / `~/.codex/memories/*` | `CLAUDE.md` / `~/.claude/projects/<p>/memory/MEMORY.md` | `GEMINI.md` |

| fallback 文件名 | ✅ 可配 `project_doc_fallback_filenames` | ❌ 无 | ❌ 无 |
| session save | ❌ 无 | ✅ `/memory refresh` | ✅ `/chat save` |

## 二、记忆机制原理（实现层）

### 2.1 记忆的三种形态

```
静态层（Static Files）：
  AGENTS.md / CLAUDE.md
  启动时注入 prompt
  适合：确定性、团队共享、长期不变的约定

生成层（Auto Memory）：
  会话中自动总结 → 写入记忆文件
  适合：踩坑记录、隐含业务规则、调试结论
  特点：机器本地、不云同步

索引层（RAG Memory）：
  历史会话 → 向量化 → 检索注入
  适合：跨会话查询历史事实
  特点：需要向量库 + 检索链路
```

### 2.2 记忆写入流程（Auto Memory）

```
1. 会话结束/空闲 → 触发总结
2. 提取关键事实（去重/去噪）
3. 分类（项目知识/用户偏好/踩坑）
4. 写入记忆文件（Markdown 结构）
5. 下次会话启动 → 注入 prompt

关键设计：
  触发时机：会话空闲（Codex 约 6h 才 eligible）
  去重：与已有记忆比对（向量相似度）
  容量：超出上限 → 截断/淘汰最旧
  可靠性：不是数据库，是 prompt 的一部分
```

## 三、分层记忆架构（企业级）

### 3.1 三层模型

```
L1 工作记忆（Working Memory）：
  当前会话上下文（messages）
  存储：上下文窗口
  容量：受模型限制

L2 情景记忆（Episodic Memory）：
  历史会话摘要（谁做了什么、结论）
  存储：向量库（RAG 检索）
  检索：按相似度注入

L3 语义记忆（Semantic Memory）：
  长期事实（项目规范、用户偏好、知识）
  存储：向量库 + 关系库
  检索：主动查询 + 自动注入
```

### 3.2 RAG 式长期记忆

```
写入：
  会话 → 分段 → Embedding → 存入向量库
  附带元数据（时间/会话ID/用户/项目）

检索：
  用户提问 → 向量检索 Top-K
  → 相关记忆注入 prompt
  → 模型生成

优点：
  容量无上限（不占上下文）
  只注入相关记忆（降低噪音）
  支持跨会话/跨项目查询
```

### 3.3 记忆总结策略

```
定时总结：会话结束/空闲时触发
增量总结：新消息 → 增量更新已有摘要
分层总结：
  L1：消息级（保留最近 N 条）
  L2：会话级（摘要 + 关键事实）
  L3：知识级（去重合并进长期记忆）
```

## 四、记忆写入策略

### 4.1 什么值得记

```
值得记：
  踩过的坑与 workaround
  项目特有 API 约定
  隐含业务规则
  调试结论（bug 根因与修复）
  用户偏好（格式/语言/习惯）

不值得记：
  会话中显而易见的内容
  临时状态（很快过期）
  可推导的信息
```

### 4.2 什么不该记（写入前过滤）

```
敏感信息：密钥/Token/PII
临时信息：一次性的调试输出
低价值：闲聊、无结论的讨论
过期信息：已修复/已废弃
```

### 4.3 记忆冲突处理

```
冲突场景：
  新记忆与旧记忆矛盾
  规则文件与自动记忆冲突

处理：
  规则文件优先（静态层 > 生成层）
  冲突检测（写入时比对相似记忆）
  人工确认（高价值冲突标记）
  版本化（记忆文件纳入 VCS 可回溯）
```

## 五、给工程师的落地清单

### 1. 项目级 `CLAUDE.md` / `AGENTS.md` 写什么

放**确定性、团队共享、长期不变**的约定：

```text
# 项目级 CLAUDE.md / AGENTS.md 推荐内容
- 技术栈与版本
- 构建 / 测试 / 提交 命令
- 目录约定
- 编码规范
- 明确禁止项
```

### 2. 哪些放自动记忆（Auto Memory）

- 踩过的坑与对应 workaround；
- 项目特有的 API 约定、隐含业务规则；
- 调试结论（某 bug 根因与修复点）。

### 3. 敏感信息务必 `.gitignore`

```bash
# .gitignore 建议追加
CLAUDE.local.md
.env
.env.*
```

> ⚠️ 记忆是「上下文」而非「强制配置」：冲突规则模型可能随机选；要强制用 Hook（PreToolUse）。

## 六、避坑

| 坑 | 说明 | 对策 |
|----|------|------|
| 别把记忆当数据库 | 它是注入 prompt 的 Markdown | 关键真相放静态层 + VCS |
| 别在静态文件塞机密 | 可能提交仓库 | 明文密钥一律禁入 |
| 上下文膨胀 | 超长内容被静默截断 | 单文件 <200 行，<32 KiB |
| override 语义别混 | 各工具机制不同 | 按工具文档确认 |
| 跨工具复用要显式 | Claude 不自动读 `AGENTS.md` | 需 `@AGENTS.md` 导入 |
| 别指望即时记忆 | 需会话空闲约 6h 才 eligible | 关键信息显式写入静态层 |

> 一句话落地：**静态层写确定性规则并版本化，生成层补涌现事实但别依赖其持久性，敏感信息全部 `.gitignore`，强制行为交给 Hook。**

## 七、企业级记忆系统实现

### 7.1 架构

```
应用 → 记忆服务（Memory Service）
  ├── 写入：会话 → 摘要 → 向量化 → 存储
  ├── 检索：查询 → 向量 Top-K → 注入
  ├── 管理：浏览/删除/导出/版本
  └── 权限：按 user_id/tenant_id 隔离

存储：
  向量库（Milvus/Qdrant）+ 关系库（元数据）
  静态层：Git 仓库（版本化）

治理：
  PII 检测与脱敏（写入前）
  TTL 与清理（过期记忆）
  审计日志（谁写入/谁查询）
```

### 7.2 多租户与最小权限

```
隔离维度：
  tenant_id → user_id → project_id

访问控制：
  检索前校验调用方权限
  记忆可见面审查（跨工具被读）

合规：
  GDPR 访问权（提供浏览/导出）
  GDPR 被遗忘权（按 user_id 彻底删除）
  数据脱敏（写入前 mask）
```

## 八、隐私合规深化（GDPR / 脱敏 / 被遗忘权）

| GDPR 条款 | 要求 | 记忆系统落地 |
| --- | --- | --- |
| 第 15 条 访问权 | 用户可查被存了什么 | 提供浏览与导出 |
| 第 17 条 被遗忘权 | 用户可要求删除 | 按 `user_id` 彻底清除 |
| 第 25 条 by design | 默认最小化收集 | 只存必要事实，禁明文 PII |
| 第 32 条 安全 | 传输存储加密 | 本地存储 + 访问控制 |

**数据脱敏（写入前）**：

```python
import re
def mask(text):
    text = re.sub(r"\b[\w.]+@[\w.]+\.\w+\b", "[EMAIL]", text)
    text = re.sub(r"\b\d{6,}\b", "[ID]", text)
    text = re.sub(r"(?i)(api[_-]?key|token)\s*[:=]\s*\S+",
                  r"\1: [REDACTED]", text)
    return text
```

> ⚠️ 自动记忆机器本地、不云同步，本身就降低外泄面；但 GDPR 的「被遗忘权」要求你能**按用户彻底删除**。
