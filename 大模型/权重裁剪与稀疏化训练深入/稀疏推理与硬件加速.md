# 稀疏推理与硬件加速

> 对应 稀疏计算与专用内核；与 推理加速深入 / KV缓存优化深入 衔接。

## 一、背景与挑战

软件稀疏若不配合算子/硬件，实则更慢；结构化稀疏才能稳定加速。

## 二、核心原理

N:M 稀疏（每 M 个保留 N 个）、通道裁剪配合 dense 算子；依赖 cuSPARSE/专用内核或编译器。

## 三、数学形式

$2:4$ 稀疏下理论算力减半但需内核支持；实际加速取决于内存带宽与计算比。

## 四、代码实现

```python
W_2to4 = to_sparse24(W)   # 每4保留2
y = sparse_mm(x, W_2to4)
```

## 五、与其他对比

- 与 量化深入 同样需硬件支持才见效。
- 与 优化器状态分片深入（训练侧）分属推理/训练两端。

## 六、常见误区

- 未验证内核支持就宣称加速，结果更慢。
- 稀疏率与硬件块大小不匹配致浪费。

## 八、面试题

- 为何非结构化稀疏难加速？答：不规则访问模式无法被标准稠密内核利用，缺硬件/库支撑。

## 九、演进

CPU 稀疏 → GPU 2:4 → 编译器自动稀疏。

## 十、小结

稀疏加速依赖结构化形态与内核支持，是软硬协同工程。
