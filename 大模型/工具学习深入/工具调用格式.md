# 工具调用格式与协议

> 对应 OpenAI function calling；ReAct 文本格式。

## 一、背景与挑战

模型须用稳定可解析格式表达调用，否则无法可靠 dispatch。

## 二、核心原理

两种主流：JSON Schema 描述函数，模型输出结构化 `arguments`；或 ReAct 文本 `Action: ...` 经正则解析。结构化更鲁棒。

## 三、数学形式

函数签名 $f_i:\text{args}_i\to\text{out}_i$；约束 $\text{args}_i$ 满足 schema $\mathcal S_i$。

## 四、代码实现

```python
tools = [{"name": "search", "parameters": {...}}]
resp = llm(messages, tools=tools)
call = resp.tool_calls[0]
```

## 五、与其他对比

- 与 指令遵循（约束输出）共享格式控制。
- 与 智能体规划 共享动作表达。

## 六、常见误区

- schema 过严致合法调用被拒。
- 文本解析对格式抖动脆弱。

## 七、与开源书对应

## 八、面试题

- JSON 调用 vs ReAct 文本？答：JSON 可强校验、解析稳；文本更灵活但易错。

## 九、演进

自由文本→ReAct→JSON function calling。

## 十、小结

调用格式决定可靠性，结构化 schema 是当前最佳实践。
