# 代码评测基准

> 对应 Chen et al., *Evaluating Large Language Models Trained on Code* (HumanEval), 2021；Austin et al., *MBPP*, 2021；Jain et al., *LiveCodeBench*, 2024；SWE-bench（Jimenez et al., 2024）；参考 HuggingFace BigCode 评测。

## 一、背景与挑战

代码能力是 LLM 落地最直观的价值之一。评测需覆盖从「写单函数」到「修真实仓库 issue」的跨度。核心挑战：(1) **污染**——HumanEval 等公开题已进入训练集，分数虚高；(2) **执行环境**——必须真实运行测试用例而非靠文本匹配；(3) **复杂度**——单函数无法反映真实软件工程（多文件、依赖、上下文）。基准因此从函数级走向仓库级、竞赛级。

## 二、核心原理

代码基准分层：(1) **函数级**：HumanEval（164 题，给定签名+docstring 生成实现，run 测试用例判 pass@k）、MBPP（约 500 道小学编程）；(2) **竞赛级**：LiveCodeBench 持续收录新竞赛题防泄漏，评 pass@k 与码长；(3) **仓库级**：SWE-bench 给真实 GitHub issue + 仓库快照，模型需生成 patch，用真实 CI 测试套件验证 `fail→pass`。评测均在 sandbox 中执行，pass@k 为通用指标。仓库级额外要求模型先定位相关文件再改，难度陡增。

## 三、形式化与数学基础

函数级 pass@k（同推理章节）：

$$pass@k = \mathbb{E}\!\left[1-\frac{\binom{n-c}{k}}{\binom{n}{k}}\right]$$

SWE-bench 以「解决率」衡量：对 issue $i$，模型 patch 使原失败测试变通过：

$$\text{Resolve} = \frac{1}{|\mathcal{I}|}\sum_{i\in\mathcal{I}} \mathbf{1}\!\left(\text{FAIL}_{\text{before}}(i)\land \text{PASS}_{\text{after}}(i)\right)$$

其中 $\text{PASS}_{\text{after}}$ 仅统计该 issue 关联的（gold）测试，防止无关改动蒙混。还需过滤「恰好通过但逻辑错」的假阳性（用 FAIL_TO_PASS / PASS_TO_PASS 双约束）。

## 四、代码实现

```python
import subprocess, tempfile

def run_tests(code: str, tests: str) -> bool:
    with tempfile.TemporaryDirectory() as d:
        open(f"{d}/sol.py", "w").write(code + "\n" + tests)
        r = subprocess.run(["python", f"{d}/sol.py"], capture_output=True)
        return r.returncode == 0

# HumanEval 风格
for prob in humaneval:
    cands = [model.generate(prob["prompt"]) for _ in range(20)]
    ok = sum(run_tests(c, prob["test"]) for c in cands)
    scores.append(pass_at_k(20, ok, 1))
```

SWE-bench 需拉仓库、apply patch、跑 `pytest` 对应测试，工程量大，通常用官方 harness。

## 五、与其他基准对比

| 基准 | 层级 | 执行 | 防泄漏 |
|---|---|---|---|
| HumanEval | 函数 | 是 | 弱 |
| MBPP | 函数 | 是 | 弱 |
| LiveCodeBench | 竞赛 | 是 | 强 |
| SWE-bench | 仓库 | 是 | 中 |

## 六、常见误区

- 只看 HumanEval 高分：已饱和且可能污染，须补 LiveCodeBench/SWE-bench。
- 文本匹配代替执行：必须真跑测试，否则格式诡计可骗分。
- 忽略 sandbox 安全：执行不可信代码须隔离（容器/限速）。
- 把 SWE-bench 当函数题：它要定位+改多文件，难在上下文检索。

## 八、面试题

1. SWE-bench 相比 HumanEval 难在哪？答：需定位多文件、理解真实仓库、生成可过 CI 的 patch，而非单函数。
2. 为何代码评测必须执行？答：文本匹配易被格式骗，真跑测试才验正确性。
3. 为何要 LiveCodeBench？答：竞赛新题防训练污染，分数更可信。

## 九、演进与趋势

代码评测从函数级走向 SWE-bench Verified、多语言、多 Agent 协作（生成+审查+测试）评测，并把「长上下文代码理解」「工具调用执行」纳入，更贴近工程真实。

## 十、小结

代码基准用真实执行为唯一判据，从函数级 HumanEval 演进到竞赛级 LiveCodeBench 与仓库级 SWE-bench。防污染、sandbox 执行与仓库级难度，是评估模型真实编码力的三要素。
