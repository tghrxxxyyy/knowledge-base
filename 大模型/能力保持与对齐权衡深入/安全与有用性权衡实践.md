# 安全与有用性权衡实践

> 对应 Ouyang et al. 2022 InstructGPT 与 Bai et al. 2022 宪法AI（Constitutional AI）。

## 一、背景与挑战

对齐训练要让模型既「有用」（乐于回答合理请求、完成复杂任务）又「安全」（拒绝有害请求、不产出违规内容）。但二者在实践中常冲突：安全策略若过严，模型会把本可回答的合法问题也拒掉，称为「过度拒绝（over-refusal）」；若过松，则可能被诱导产出有害内容。InstructGPT 已观察到这种折衷，宪法 AI（Bai 2022）进一步用一套原则减少人工红队依赖。挑战在于：安全边界模糊（同一问题换个措辞可能合法也可能违规），自动评测易漏边界案例，且不同用户群体对「安全」的容忍度不同。需要在可接受的拒答率下最大化有用性。

## 二、核心原理

平衡安全与有用的常见工程手段：
1. **安全分类器 + 阈值校准**：在生成前/后用分类器判断请求与回复安全性，阈值决定拒答严格度；阈值过低误拒、过高漏放。
2. **可供性提示（affordances）**：在系统提示中写入安全原则与例外情形，引导模型区分真实有害与表面敏感。
3. **原则式对齐（Constitutional AI）**：用一组自然语言原则（宪法）让模型自我批判与修正，减少昂贵人工红队，并缓解过度拒绝。
4. **红队测试**：用对抗样本持续探测边界，把失败案例回收进训练/评测。
5. **分级安全**：按风险分档（低风险直答、中风险加警告、高风险拒答），替代一刀切。

核心是「校准」——在安全与有用之间找令业务可接受的工作点。

## 三、形式化与数学基础

以拒绝率 $R$ 与合规率 $C$ 为监控量。对验证集 $\mathcal{V}$，拒绝率：

$$ R = \frac{1}{|\mathcal{V}|}\sum_{x\in\mathcal{V}} \mathbf{1}[\text{model 拒答}(x)] $$

合规率（未拒答中合规比例）：

$$ C = \frac{\sum_{x\notin\mathcal{R}} \mathbf{1}[\text{合规}(x)]}{|\mathcal{V}|-|\mathcal{R}|} $$

目标是在约束 $C\ge c^*$ 下最小化 $R$（少误拒）。阈值扫描即找使二者同时达标的 $t^*$：

$$ t^* = \arg\min_t R(t)\quad \text{s.t.}\quad C(t)\ge c^* $$

## 四、代码实现

```python
def scan(safety_scores, labels, thresholds):
    """扫描安全阈值，输出各阈值下的拒答率与合规率"""
    out = []
    for t in thresholds:
        pred_refuse = safety_scores >= t
        refused = pred_refuse.sum()
        R = refused / len(labels)
        allow = ~pred_refuse
        C = (labels[allow] == 1).mean() if allow.any() else 0.0
        out.append((t, R, C))
    return out

# 选满足 C>=0.95 的最小 R 对应阈值
best = min((r for t, R, C in out if C >= 0.95), key=lambda x: x[1])
```

## 五、与其他技术对比

| 方法 | 过度拒绝 | 人工成本 | 可控性 | 适用 |
|------|----------|----------|--------|------|
| 纯 RLHF | 易偏高 | 高 | 中 | 通用 |
| 宪法 AI | 较低 | 低 | 中 | 大规模 |
| 安全分类器 | 依阈值 | 中 | 高 | 生产克制 |
| 分级安全 | 低 | 中 | 高 | 精细业务 |

宪法 AI 以原则减少过度拒绝；纯 RLHF 易偏向安全端而误拒。

## 六、常见误区

- **安全阈值一刀切**：固定阈值在边界案例上大量误拒，应分级或动态。
- **只用自动评测**：自动指标漏掉语义边界，需人工红队抽样。
- **把拒答当安全**：拒答多不代表真安全，可能只是「更保守」。
- **忽视文化/语言差异**：中文安全边界与英文不同，分类器需本地化。
- **安全与能力解耦评估**：只测拒答率会漏掉「变笨」，需同时看有用性分。

## 九、演进与趋势

- **细粒度安全分级**：按风险动态决定拒答/警告/直答。
- **用户意图理解**：先判用户真实意图再定安全策略，降误拒。
- **可解释安全**：输出拒答理由，提升透明度与可接受度。
- **自适应阈值**：依请求上下文动态调安全严格度。

## 十、小结

安全与有用需动态平衡：用安全分类器阈值校准、原则式对齐减少过度拒绝、红队持续探测边界。核心是以 R/C 双指标系统扫描工作点，避免一刀切与仅看自动评测，在合规前提下最大化有用性。
