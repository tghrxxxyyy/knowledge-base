# 多向量检索质量评估

> 对应 Thakur et al., *BEIR*, 2021；MS MARCO leaderboard（ColBERT 系列）。

## 一、背景与挑战

多向量是否值得额外存储/算力，需量化对比单向量与重排。

## 二、核心原理

在 MS MARCO 看 NDCG@10、BEIR 看零样本泛化；对比 DPR（单向量）、ColBERT、cross-encoder 的精度-延迟。

## 三、数学形式

精度-成本权衡 $Q = NDCG - \lambda\cdot \log(\text{latency}\cdot\text{storage})$；取帕累托优。

## 四、代码实现

```python
for model in [dpr, colbert, ce]:
    report(model.name, eval_marco(model), latency(model))
```

## 五、与其他对比

- 与 稠密检索评估 共享指标。
- 与 检索重排序深入（cross-encoder 精度上限）对照。

## 六、常见误区

- 只看精度忽略存储成本；多向量常 10x 于双塔。
- BEIR 上多向量优势在长文档域更明显。

## 八、面试题

- 何时选多向量？答：长文档/细粒度匹配且存储预算足时，精度优于双塔。

## 九、演进

单向量 → 多向量 → 压缩多向量（性价比优化）。

## 十、小结

多向量质量评估须连同存储延迟看，压缩后性价比显著提升。
