# 多向量索引结构

> 对应 Santhanam et al., *PLAID*, 2022（分桶质心索引）；Khattab et al., *XTR*, 2021。

## 一、背景与挑战

迟交互需对每 query token 与文档 token 比对，朴素实现慢；需专用索引。

## 二、核心原理

按 token 向量质心分桶，查询仅与命中质心桶的文档 token 计算；PLAID 用倒排式质心桶，XTR 用可解释 token 路由减少计算。

## 三、数学形式

索引 $\mathcal I=\{(c_k, \{d_j: k(d_j)=k\})\}$；查询只取 $q_i$ 近质心对应桶计算 MaxSim。

## 四、代码实现

```python
buckets = invert_by_centroid(doc_tokens)   # 质心->文档token倒排
hits = [buckets[c] for c in nearest_centroids(Q)]
```

## 五、与其他对比

- 与 向量检索算法深入（IVF 倒排）同源。
- 与 多向量压缩 共构高效多向量检索。

## 六、常见误区

- 桶数/质心数不当致检索变慢或漏召回。
- 查询 token 未路由致全量比对。

## 八、面试题

- 多向量索引为何用质心桶？答：只在查询 token 近质心的文档 token 间算 MaxSim，降复杂度。

## 九、演进

暴力 MaxSim → 质心分桶 → PLAID 倒排加速。

## 十、小结

多向量索引靠质心分桶把迟交互降为局部计算，兼顾精度与速度。
