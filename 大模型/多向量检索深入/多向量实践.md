# 多向量检索实践

> 对应 ColBERT/PLAID 工程实践；与 RAG 检索链路衔接。

## 一、背景与挑战

落地需折中精度、存储、延迟与更新成本。

## 二、核心原理

用 ColBERTv2/PLAID 建索引；查询端裁剪停用词 token；与重排组合；增量更新靠重索引分片。

## 三、数学形式

端到端 $RAG(q)=\text{Gen}(\text{Rerank}(\text{ColBERT}(q)))$；候选数受索引大小约束。

## 四、代码实现

```python
index = ColBERT(index_name).search(q, k=100)
top = reranker(q, index, k=5)
```

## 五、与其他对比

- 与 双塔模型深入（更省）对照成本。
- 与 检索重排序深入 组合精排。

## 六、常见误区

- 文档频繁更新致重索引贵；需分片增量。
- 查询长未裁剪致 MaxSim 计算膨胀。

## 九、演进

离线全量 → 分片增量 → 服务化 PLAID。

## 十、小结

多向量实践以压缩与裁剪控成本，配合重排进 RAG 链路。
