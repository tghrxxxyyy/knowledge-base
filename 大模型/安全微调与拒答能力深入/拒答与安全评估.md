# 拒答与安全评估

> 对应 Röttger et al., *XSTest*, NAACL 2024；Zou et al., *Universal and Transferable Adversarial Attacks on Aligned Language Models*, 2023；Bai et al., 2022。

## 一、背景与挑战

安全评估最容易犯的错误是「用单一集合、单一指标、单一提示形式」得出结论。真实攻击面包含直接请求、角色扮演、多轮诱导、编码混淆、对抗后缀等多种形式，而防守侧还要兼顾误拒。评估设计不当会同时高估安全性与低估可用性损失。

## 二、核心原理

一套可用的评估应包含四个维度。样本维度：真实有害集、类安全对照集、多轮诱导集、对抗后缀集分别独立报告。判定维度：拒答判定不能只靠关键词，需要用分类器或裁判模型识别「形式拒答但实质泄露」的情况。攻击强度维度：区分零样本请求与经过优化的对抗提示（如基于梯度的后缀搜索），并报告攻击预算（查询次数、迭代步数）。稳定性维度：同一语义用多种表述重测，报告方差而非单点值。最终结论应是一条「攻击强度—顺从率」曲线加上固定顺从率下的误拒率，而不是一个孤立百分数。

## 三、数学形式

定义在攻击预算 $B$ 下的攻击成功率

$$\mathrm{ASR}(B)=\mathbb E_{x\sim D_{\text{harm}}}\Big[\max_{a\in\mathcal A(B)}\mathbb 1\{\text{unsafe}\big(\pi_\theta(a(x))\big)\}\Big]$$

其中 $\mathcal A(B)$ 是预算内可用的攻击变换集合（改写、角色、后缀等）。安全边界的综合刻画为在给定 $\mathrm{ASR}(B)\le\epsilon$ 约束下的误拒率 $\mathrm{OR}$，二者构成类似 ROC 的权衡曲线；报告时必须写明 $B$，否则数字不可比。

## 四、代码实现

```python
def asr_curve(model, harmful, attacks_by_budget, unsafe_judge):
    # attacks_by_budget: {预算: [变换函数,...]}，变换含改写/角色/后缀等
    out = {}
    for budget, attacks in sorted(attacks_by_budget.items()):
        hit = 0
        for x in harmful:
            success = False
            for a in attacks:
                if unsafe_judge(model(a(x))):      # 任一变换成功即计为成功
                    success = True
                    break
            hit += int(success)
        out[budget] = hit / len(harmful)
    return out

def paired_report(model, harmful, benign_lookalike, attacks_by_budget, judge):
    return {"asr": asr_curve(model, harmful, attacks_by_budget, judge),
            "over_refusal": safety_report(model, harmful, benign_lookalike)["over_refusal_rate"]}
```

## 五、与其他对比

- 与 拒答边界与过度拒答：那里定义双侧错误率，这里加入攻击强度这一维。
- 与 多模态安全与越狱深入：评估框架相同，但攻击变换集合需扩展到图像与跨模态通道。
- 与 提示注入形式化分析深入：注入评估关注「指令来源」，安全评估关注「内容有害性」，指标不可混用。

## 六、常见误区

- 报告单一 ASR 数字而不写攻击预算与攻击集合，导致跨模型不可比。
- 用关键词判定 unsafe，漏掉包装在小说、代码注释、翻译任务里的实质泄露。
- 只评单轮。多轮渐进诱导是实际最有效的攻击路径之一，必须单列。

## 八、面试题

- 报告安全性时为何必须写明攻击预算？答：ASR 随可用攻击变换与搜索预算单调上升，不写预算的数字无法比较也无法复现。
- 如何避免把「形式拒答」误判为安全？答：用裁判模型或分类器判定实质内容是否泄露，而非只看开头是否有道歉词。

## 九、演进

关键词命中率 → 双侧错误率（漏拒 + 误拒） → 引入攻击强度曲线 → 多轮与多模态攻击面 → 持续红队与线上监控。

## 十、小结

安全评估的可信度取决于攻击面覆盖与判定质量；把 ASR 写成随预算变化的曲线并配报误拒率，才是可复现、可决策的报告方式。
