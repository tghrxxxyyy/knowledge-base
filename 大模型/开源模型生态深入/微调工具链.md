# 微调工具链

> 对应 Hu et al. 2021《LoRA》、Dettmers et al. 2023《QLoRA》，以及 HuggingFace PEFT / TRL、Axolotl、LLaMA-Factory、DeepSpeed（版本以官方最新文档为准）。

## 一、背景与挑战

开放权重普及之后，"能不能改"成了第一需求：通用基座不懂企业术语、不遵循内部格式、不会调用私有工具。但全参数微调数十亿参数模型在工程上几乎不可行——优化器状态、梯度与激活会把显存需求推到权重的数倍。

工具链要解决的是整条流水线，而不只是训练：数据如何组织成对话/指令格式、如何做长度分桶与 packing、如何在单卡放下模型、如何稳定收敛、如何合并权重并部署、如何评测回归。任何一环缺失，微调就会变成难以复现的手艺。此外工具链与模型版本耦合紧密，容易出现"升级后结果变了"。

## 二、核心原理

**PEFT** 是基石。LoRA 假设微调引起的权重变化是低秩的，冻结 $W_0$，只训练低秩增量：

$$
W = W_0 + \Delta W = W_0 + BA, \quad B \in \mathbb{R}^{d \times r},\ A \in \mathbb{R}^{r \times k},\ r \ll \min(d,k)
$$

前向为 $h = W_0 x + \frac{\alpha}{r}BAx$，$A$ 用高斯、$B$ 用零初始化，保证起点 $\Delta W = 0$。可训练参数从 $dk$ 降到 $r(d+k)$，且**推理时可把 $BA$ 合并回 $W_0$，零额外延迟**。

**QLoRA** 引入 NF4 量化基座、双重量化与分页优化器，把基座显存压到 4-bit。**训练框架**（DeepSpeed ZeRO、FSDP、梯度检查点、flash-attention）负责分布式与显存，一体化封装（Axolotl、LLaMA-Factory、TRL）则把数据格式、LoRA 配置与导出变成配置驱动。

## 三、形式化与数学基础

LoRA 的参数压缩比为

$$
\frac{|\Delta W|_{\mathrm{LoRA}}}{|W_0|} = \frac{r(d+k)}{dk} \approx \frac{2r}{\min(d,k)} \quad (d \approx k)
$$

以 $d=k=4096$、$r=16$ 为例，可训练参数约为全量的 $0.78\%$。$\alpha/r$ 缩放使学习率对秩 $r$ 不敏感。

混合精度 + Adam 的训练显存约为

$$
M_{\text{train}} \approx 2P_{\text{bf16}} + 4P_{\text{fp32}} + 8P_{\text{Adam}} + 4P_{\text{grad}} + M_{\text{act}} \approx 16P
$$

这正是全参微调昂贵的原因；LoRA 只保留基座权重与少量可训练参数，优化器状态几乎消失；QLoRA 把第一项压到 $0.5P$。ZeRO 按阶段把优化器状态、梯度、参数分片到 $N_d$ 张卡，每卡对应项约为 $1/N_d$，代价是额外通信；梯度检查点把激活显存从 $O(LSd)$ 降为按段重算的量级，代价约 $1/3$ 额外前向计算。

## 四、代码实现

```python
# 用 PEFT 挂 LoRA，只训练低秩增量，最后合并回基座
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments, Trainer
from peft import LoraConfig, get_peft_model
from datasets import load_dataset

MODEL_ID = "Qwen/Qwen2.5-7B-Instruct"
tok = AutoTokenizer.from_pretrained(MODEL_ID)
base = AutoModelForCausalLM.from_pretrained(MODEL_ID, torch_dtype=torch.bfloat16, device_map="auto")

model = get_peft_model(base, LoraConfig(
    r=16, lora_alpha=32, lora_dropout=0.05, bias="none", task_type="CAUSAL_LM",
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj"]))
model.print_trainable_parameters()

# 数据侧统一走官方 chat template，避免格式错配
to_text = lambda ex: tok.apply_chat_template(
    [{"role": "user", "content": ex["question"]},
     {"role": "assistant", "content": ex["answer"]}], tokenize=False)

raw = load_dataset("json", data_files="train.jsonl", split="train")
ds = raw.map(lambda e: tok(to_text(e), truncation=True, max_length=2048),
             remove_columns=raw.column_names)

def collate(features):
    # padding 位置的 label 用 -100，让 loss 忽略，避免模型学习生成填充符
    max_len = max(len(f["input_ids"]) for f in features)
    pad = lambda xs, v: xs + [v] * (max_len - len(xs))
    return {"input_ids": torch.tensor([pad(f["input_ids"], tok.pad_token_id) for f in features]),
            "labels": torch.tensor([pad(f["input_ids"], -100) for f in features]),
            "attention_mask": torch.tensor([pad([1]*len(f["input_ids"]), 0) for f in features])}

args = TrainingArguments(output_dir="out-lora", per_device_train_batch_size=4,
    gradient_accumulation_steps=8, learning_rate=1e-4,   # LoRA 学习率高于全参
    num_train_epochs=2, bf16=True, logging_steps=10, save_strategy="epoch",
    gradient_checkpointing=True, optim="adamw_torch")

Trainer(model=model, args=args, train_dataset=ds, data_collator=collate).train()

merged = model.merge_and_unload()          # 合并后推理无额外开销
merged.save_pretrained("out-merged", safe_serialization=True)
```

## 五、与其他技术对比

| 维度 | 全参数微调 | LoRA | QLoRA | 提示工程 |
|------|-----------|------|-------|----------|
| 可训练参数 | 100% | ~0.1%~1% | 同 LoRA + 4bit 基座 | 0 |
| 显存 | 极高（~16P） | 中 | 低 | 无训练 |
| 遗忘风险 | 高 | 低 | 低 | 无 |
| 能力上限 | 最高 | 高，接近全参 | 略低 | 受上下文限制 |
| 部署 | 直接 | 可合并，零开销 | 需反量化合并 | — |

| 工具 | 定位 | 适合场景 |
|------|------|----------|
| PEFT | LoRA/适配器原语 | 需要精细控制训练代码 |
| TRL | SFT/DPO/GRPO 训练器 | 对齐阶段 |
| Axolotl | 配置驱动一体化训练 | 快速复现实验 |
| LLaMA-Factory | 训练 + 界面 + 导出 | 团队协作与低代码 |

## 六、常见误区

- **认为必须全参数微调**：多数业务适配用 LoRA 已足够，且遗忘风险更低。
- **秩越大越好**：过大的 $r$ 逼近全参，带来过拟合与遗忘，收益迅速饱和。
- **学习率照搬全参**：LoRA 通常需要 $10^{-4}$ 量级，过低会"训不动"。
- **padding 参与 loss**：未用 `-100` 掩码会让模型学习生成填充符。

## 九、演进与趋势

工具链从"手写训练循环"→"PEFT 提供原语"→"配置驱动一体化框架"→"算子级加速与端到端平台"。趋势上：全参与 PEFT 的界限模糊，出现选择性解冻与部分层训练；对齐训练内置化，SFT/DPO/GRPO 成为标配；长上下文与多模态微调成为新难点；显存优化下沉到算子与编译层；可复现性受重视，配置、种子与数据版本被纳入管理。

## 十、小结

微调工具链把"改模型"从研究工程变成可复现流程。两条主线：数学上 LoRA 用低秩增量 $W_0 + BA$ 把可训练参数压缩两个数量级且可无损合并；工程上量化、分片、重计算与算子融合解决显存与吞吐。实践建议是用配置驱动框架跑通基线，再用 PEFT 精细调参，并始终用留存集与人工评测而非训练 loss 判断效果。
