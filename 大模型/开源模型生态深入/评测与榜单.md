# 评测与榜单

> 对应 Gao et al.《lm-evaluation-harness》、Liang et al.《HELM》、Zheng et al. 2023《MT-Bench and Chatbot Arena》、OpenCompass（榜单内容以官方最新文档为准）。

## 一、背景与挑战

开放权重模型快速增长后，"选哪个"需要客观依据。但现实更复杂：**基准会被污染**，公开题目很可能已进入训练集，分数虚高；**格式敏感**，少样本数、模板、抽取正则的微小差异可造成数个百分点波动；**分布错配**，多选题形式的 MMLU 类基准与真实对话、Agent 调用差异很大；**口径不统一**，不同榜单的生成参数与评分模型不同，跨榜比较无意义；**成本约束**，全面评测耗大量 GPU 时间。

## 二、核心原理

方法按"答案是否自由生成"分为两类。**对数似然评分**把候选拼到上下文后算条件概率取最大，对生成参数不敏感、可复现性高，适合多选题类基准：

$$
\hat{y} = \arg\max_{y \in \mathcal{Y}} \sum_t \log P_\theta(y_t \mid x, y_{<t})
$$

**生成式评分**让模型自由生成，再用规则抽取或裁判模型打分，更接近真实使用但方差更大。LLM-as-a-judge 会引入裁判自身偏差（偏爱更长、更靠前的回答）。

**人类偏好评测**（如 Chatbot Arena）用成对匿名对战，借 **Bradley–Terry 模型**把胜负转成能力评分：设模型 $i$ 的潜在能力 $\gamma_i$，则

$$
P(i \succ j) = \frac{e^{\gamma_i}}{e^{\gamma_i} + e^{\gamma_j}} = \sigma(\gamma_i - \gamma_j)
$$

用最大似然估计 $\gamma$ 并给出置信区间。这类评测反映"体感"，但受提示风格与用户群体构成影响。

## 三、形式化与数学基础

评测目标是期望风险 $R(\theta) = \mathbb{E}[s(f_\theta(x), y^\ast)]$，实践中用 $n$ 个样本的经验均值估计。评分为 0/1 时标准误为

$$
\mathrm{SE} = \sqrt{\frac{\hat{R}(1 - \hat{R})}{n}}
$$

$n = 1000$ 且准确率在 50% 附近时，标准误约 1.5 个百分点，因此**一两分的榜单差异通常不具统计显著性**。比较两模型时应看

$$
\Delta = \hat{R}_A - \hat{R}_B, \qquad \mathrm{SE}(\Delta) = \sqrt{\mathrm{SE}_A^2 + \mathrm{SE}_B^2}
$$

只有 $|\Delta|$ 明显超过 $2\cdot\mathrm{SE}(\Delta)$ 才值得采信。

Bradley–Terry 的对数似然为 $\mathcal{L}(\gamma) = \sum_{i \succ j} \log \sigma(\gamma_i - \gamma_j)$，梯度上升求解并需加正则以保证可辨识性。污染检测可用困惑度异常刻画：

$$
\mathrm{PPL}(y^\ast \mid x) \ll \mathrm{PPL}(y^{\text{paraphrase}} \mid x) \Rightarrow \text{疑似污染}
$$


```python
# 自建多选基准：用累积对数似然给候选打分，避免采样方差
import torch

def score_choices(model, tok, context, choices):
    scores = []
    ctx_len = tok(context, return_tensors="pt")["input_ids"].shape[-1]
    for ch in choices:
        ids = tok(context + " " + ch, return_tensors="pt").to(model.device)
        with torch.inference_mode():
            logp = torch.log_softmax(model(**ids).logits[:, :-1], dim=-1)
            picked = logp.gather(-1, ids["input_ids"][:, 1:].unsqueeze(-1)).squeeze(-1)
        scores.append(picked[0, ctx_len - 1:].sum().item())   # 只统计候选部分
    return scores

# 显著性判断：se = sqrt(se_a^2 + se_b^2)，|Δ| > 1.96*se 才值得采信
def diff_significant(acc_a, n_a, acc_b, n_b, z=1.96):
    se = (acc_a * (1 - acc_a) / n_a + acc_b * (1 - acc_b) / n_b) ** 0.5
    return abs(acc_a - acc_b) > z * se
```

## 五、与其他技术对比

| 评测类型 | 代表 | 优点 | 局限 |
|----------|------|------|------|
| 对数似然多选 | MMLU、HellaSwag | 可复现、对采样不敏感 | 与真实对话分布错配 |
| 生成 + 规则抽取 | GSM8K、HumanEval | 接近真实使用 | 抽取正则影响大，方差高 |
| 裁判模型评分 | MT-Bench | 覆盖开放式任务 | 长度/位置/自偏好偏差 |
| 人类成对对战 | Chatbot Arena | 反映体感 | 成本高，受用户群体影响 |
| 多维度综合 | HELM、OpenCompass | 覆盖准确性、鲁棒性等 | 运行成本大 |

| 关注点 | 公开榜单 | 自建评测 |
|--------|----------|----------|
| 可比性 / 目标相关性 | 强 / 弱 | 弱 / 强 |
| 抗污染 / 维护成本 | 弱 / 低 | 强 / 高 |

## 六、常见误区

- **把榜单排名当选型结论**：榜单是初筛，最终必须回到业务集验证。
- **忽略置信区间**：一两分差距通常落在噪声范围内。
- **跨榜比较分数**：prompt、少样本数与评分方式不同，分数不可直接对比。
- **评测集与训练集重叠**：自建评测集若参与过训练，指标完全失去意义。

## 九、演进与趋势

评测从"单一准确率"→"多任务基准套件"→"对话式与裁判式"→"过程式与 Agent 式"。趋势上：从静态数据集转向动态/对抗式生成以降低污染；从结果正确转向过程正确；成本成为评测维度（达到目标质量所需 token 与延迟）；安全与鲁棒性与能力并列；统计严谨性提升，置信区间与跨模板方差被更多采用。

## 十、小结

评测与榜单是选型的罗盘而非终点。正确使用需要三点自觉：用统一框架与统一口径复现分数；理解有限样本下的统计误差，不把噪声当信号；在自有业务集上做最终裁决并警惕污染。把公开榜单当作候选集过滤器、把自建评测当作决策依据，才是可持续的做法。
