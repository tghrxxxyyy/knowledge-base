# 规划与任务分解总览

> 对应 Yao et al., *ReAct*, ICLR 2023；Wang et al., *Plan-and-Solve Prompting*, ACL 2023；Huang et al., *Inner Monologue*, CoRL 2022。

## 一、背景与挑战

长任务无法一步到位：需要把目标拆成有序子目标、分配工具、在失败时调整。
语言模型天然是局部下一步预测器，缺少全局一致的计划表征，容易出现遗漏步骤、重复劳动与目标漂移。

## 二、核心原理

- 两大范式：先规划后执行（一次生成计划再逐步落实，可控可审计）与边想边做（每步依据观测决定下一步，适应性强）。
- 分解质量取决于子目标是否可验证：每个子目标应有明确完成判据，否则无法判断是否推进。
- 计划需要显式表征（列表、DAG、树），以便程序侧跟踪进度、检测循环与做重规划。

## 三、数学形式

规划可视为在状态空间中寻找动作序列使目标谓词成立：$\pi^*=\arg\max_{\pi}\ \mathbb E\big[\sum_t \gamma^t r(s_t,a_t)\big]$，$r$ 常为稀疏的目标达成奖励。

分解则是引入子目标集合 $\{g_i\}$ 使 $P(\text{success})\approx\prod_i P(g_i\mid g_{<i})$；子目标越可验证，单项概率越接近可控。

## 四、代码实现

```python
def plan_and_execute(llm, tools, goal):
    steps = llm.json(f"把目标拆成可验证子任务列表: {goal}", schema=PLAN_SCHEMA)
    done = []
    for s in steps["steps"]:
        out = execute_step(llm, tools, s, context=done)
        if not check(s["done_when"], out):          # 子目标判据
            out = replan_and_retry(llm, tools, s, out)
        done.append({"step": s["name"], "result": out})
    return summarize(llm, goal, done)
```

## 五、与其他对比

- 与经典 AI 规划（STRIPS/PDDL）：经典方法需完整形式化域，保证正确性；LLM 规划无需建模但缺乏可靠性保证，混合方案是让 LLM 写 PDDL 再交给求解器。
- 与函数调用编排：编排解决「怎么执行」，规划解决「执行什么与顺序」。

## 六、常见误区

- 子任务写成不可验证的抽象描述（如「深入分析」），无法判定完成，流程失控。
- 一次性生成过细计划：前期信息不足，细粒度计划很快失效，应分层与滚动细化。
- 不检测重复与循环，智能体在两个步骤间反复摆动直到耗尽预算。

## 八、面试题

- 先规划后执行与边想边做如何取舍？答：环境可预测、步骤依赖清晰时前者更省更可审计；环境不确定、观测决定路径时后者更稳。
- 好的子任务分解标准是什么？答：可独立执行、可用程序或工具验证完成、粒度与可用信息匹配，且顺序依赖显式。

## 九、演进

单步问答 → 链式思维 → 交错推理与行动（ReAct）→ 显式计划与重规划 → 树搜索与外部求解器混合。

## 十、小结

规划的工程要点是让计划可表征、子目标可验证、失败可重规划，而非追求一次生成完美方案。
