# 分层任务分解

> 对应 Zhou et al., *Least-to-Most Prompting*, ICLR 2023；Khot et al., *Decomposed Prompting*, ICLR 2023；经典 HTN 规划。

## 一、背景与挑战

一步给出细粒度全量计划在信息不足时必然失效，而完全走一步看一步又缺少全局结构。
分层分解提供中间路径：先粗后细，把复杂目标逐层展开为可执行叶子任务。

## 二、核心原理

- 由易到难（least-to-most）：先分解出子问题序列，再顺序求解，后续子问题可复用前面答案。
- 分解式提示（decomposed prompting）：每类子任务交给专用子提示或专用工具处理，主控只负责调度与拼装。
- 滚动细化：只把当前层展开到可执行粒度，下层在需要时再展开，避免过早承诺。

## 三、数学形式

层次分解把成功率写成条件乘积：$P(\text{solve})=\prod_{i=1}^{n}P(g_i\mid g_{<i})$，故降低单步难度可显著提升整体成功率。

若不分解，直接求解概率近似 $P_{\text{direct}}$；当各 $P(g_i\mid g_{<i})$ 因难度下降而接近 1 时，分解收益最大。

## 四、代码实现

```python
def decompose(llm, goal, depth=0, max_depth=2):
    if depth == max_depth or llm_yes(llm, f"该任务可由单个工具直接完成吗: {goal}"):
        return {"leaf": goal}
    subs = llm.json(f"把任务分解为2-4个有序子任务: {goal}", schema=SUBS_SCHEMA)
    return {"goal": goal,
            "children": [decompose(llm, s, depth + 1, max_depth) for s in subs["subs"]]}
```

## 五、与其他对比

- 与 HTN 经典规划：HTN 用人工方法库保证可行性；LLM 分解覆盖开放任务但需验证叶子可执行性。
- 与思维树：ToT 在同一抽象层做搜索；分层分解是跨抽象层展开，二者可嵌套（每层内用搜索选分解方案）。

## 六、常见误区

- 分解层数过深，管理与上下文成本超过收益，且中间层信息失真。
- 子任务间存在隐藏耦合却按独立处理，导致结果无法拼装。
- 叶子任务仍不可执行（没有对应工具或数据），说明分解未以能力边界为终止条件。

## 八、面试题

- 分解为什么能提升成功率？答：把低概率的一次性求解拆成多个高概率子步骤，条件乘积在单步难度下降时整体上升。
- 分解的终止条件应是什么？答：叶子任务能被单个工具或单次调用可靠完成，且有明确完成判据。

## 九、演进

单步直答 → 由易到难分解 → 分解式提示专用子模块 → 分层滚动细化 → 与求解器/搜索结合的混合规划。

## 十、小结

分层分解以能力边界为终止条件，用滚动细化对抗信息不足，是长任务的骨架方法。
