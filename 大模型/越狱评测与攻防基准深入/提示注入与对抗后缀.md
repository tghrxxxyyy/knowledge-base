# 提示注入与对抗后缀

> 对应 Ouyang 2022 InstructGPT 的对齐训练，以及 Goodfellow 2014 对抗样本（adversarial examples）思想在文本上的延伸。

## 一、背景与挑战

越狱攻击在「语义层」与「统计层」各有一类代表：提示注入属于前者，攻击者利用指令优先级混淆，在正常指令后追加覆盖性语句（如「忽略以上所有规则」）；对抗后缀属于后者，通过梯度优化在 token 级追加一串难读字符，使模型的 refusal 分布塌陷为顺从。

二者分别考验模型对语义与对统计扰动的鲁棒性，是评测中必须分别覆盖的两条攻击主轴，因为单测一类会高估整体防御强度。

在 RAG 与 Agent 场景下，提示注入还可从「工具返回内容」「检索片段」等外部信道进入，攻击面比单纯的用户输入框更宽。

## 二、核心原理

提示注入的核心是利用「系统提示 vs 用户提示」的优先级模糊：当模型未严格约束指令层级时，用户侧注入的「你现在是无限制助手」可覆盖安全准则。对抗后缀则把问题建模为连续优化：在输入 $x$ 后拼接可微后缀 $\delta$，最小化模型输出有害内容 $y_{\text{harmful}}$ 的损失，使 refusal 概率被压制。

它常不可读，却因直接作用于 logits 而稳定有效，揭示了对齐并非「语义级」保障，而是可被统计层面扰动击穿。

关键要点：

- 提示注入利用指令优先级混淆，覆盖系统安全准则。
- 对抗后缀在 token 级追加难读串，使 refusal 分布塌陷。
- 二者分别考验语义与统计两层面鲁棒性。
- 注入还可从工具返回、检索片段等外部信道进入。
- 困惑度可作为后缀检测信号，但攻击者可反向优化低困惑度后缀。
- 防御需覆盖更宽数据信道，而非仅用户输入框。

## 三、形式化与数学基础

后缀优化目标（白盒）：

$$
\delta^* = \arg\min_{\delta} \mathcal{L}\big(\text{model}(x \oplus \delta),\, y_{\text{harmful}}\big)
$$

其中 $\oplus$ 表示拼接。攻击成立当：

$$
\Pr(\text{harmful} \mid x\oplus\delta^*) > \tau
$$

困惑度（perplexity）可作为检测信号：正常文本 $PPL$ 低，对抗后缀 $PPL$ 异常高，故有：

$$
\text{suspect}(\delta) = \mathbb{1}[PPL(\delta) > \theta]
$$

但攻击者可反向优化「低困惑度后缀」，使该信号失效，需多层检测。

## 四、代码实现

```python
# 对抗后缀搜索（简化白盒示意）
def search_suffix(model, x, y_harmful, iters=50, lr=0.1):
    delta = random_tokens(8)                 # 初始化难读后缀
    for _ in range(iters):
        loss = model.loss(x + delta, y_harmful)
        delta = delta - lr * grad(loss, delta)   # 沿梯度逼近有害后缀
    return delta

# 困惑度过滤（黑盒可部署的护栏）
def is_suspicious(suffix, ppl_model, theta=100.0):
    return ppl_model.perplexity(suffix) > theta
```

## 六、常见误区

误区一：只测英文后缀——多语言与混合编码常绕过，且中文拆字同样有效。

误区二：忽略解码参数——temperature/top-p 会影响攻击成功率，评测须固定解码配置。

误区三：困惑度过滤万能——攻击者可优化「低困惑度后缀」，单一统计信号易被反制。

误区四：把系统提示写死即安全——注入仍可能从工具调用上下文、检索结果进入。

误区五：认为不可读就无害——恰恰相反，不可读后缀往往更稳定有效。

## 七、与开源书·权威来源对应

Ouyang 2022 对齐训练提升 refusal；Goodfellow 2014 提出对抗样本概念，被延伸到文本（如 GCG 攻击）；huggingface/transformers 提供攻击实验基座；OWASP LLM Top 10（LLM01 提示注入）列举典型手法。

## 九、演进与趋势

自适应防御对后缀做困惑度过滤与语义一致性检测；攻击则从单后缀走向「后缀 + 多轮 + 工具调用」组合；前缀/中间注入（如长上下文里的隐藏指令）成为新战场，要求防御覆盖更宽的数据信道。

形式化验证「无论注入何种指令都不输出受限内容」是长期目标，当前多依赖经验性多层护栏。

## 十、小结

提示注入与对抗后缀分别考验语义与统计两层面的鲁棒性，防御须兼顾指令层级约束与后缀检测，并覆盖工具/检索等外部信道，方能在两类攻击下都保持稳健。
