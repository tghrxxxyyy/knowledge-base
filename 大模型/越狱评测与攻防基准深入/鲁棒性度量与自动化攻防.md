# 鲁棒性度量与自动化攻防

> 对应 Rafailov 2023 DPO 的鲁棒性讨论，以及 Ouyang 2022 InstructGPT 的对齐框架。

## 一、背景与挑战

攻防是持续博弈：模型与防御每迭代一次，攻击者就会寻找新弱点。若只在发布前做一次越狱评测，结果会迅速失效。因此鲁棒性度量应进入日常 CI，作为可自动运行的回归与告警，而非一次性报告。

这需要把「攻击生成—目标推理—裁判评分」串成闭环，让防御的每次变更都有量化反馈，否则团队无法判断「这次改动是更安全还是更脆弱」。

安全工程的核心是「可度量才可治理」：没有持续度量，越狱防御会随模型更新悄悄退化，等到线上事故才被发现，代价极高。

## 二、核心原理

自动化攻防循环包含：①攻击生成器（模板库 / 优化器 / 模型自生成）产出候选对抗输入；②目标模型推理得到输出；③裁判（规则或模型裁判）判定是否越界；④汇总 ASR 并与其历史值比较，报告漂移。当某风险类别的 ASR 超过阈值或较上一周期明显上升，触发告警并阻断发布。

关键是攻击库的版本化与防污染：攻击样本必须与训练集物理隔离，否则防御会在已知攻击上过拟合，评测数字虚高。

关键要点：

- 自动化攻防循环：攻击生成→推理→裁判→漂移告警。
- ASR 漂移 = 当前周期减上一周期，超阈值即阻断发布。
- 最坏类别漂移比均值更能暴露真实风险。
- 攻击库须版本化且与训练集物理隔离，防污染与过拟合。
- 裁判一致性需人工复核，避免误报制造噪音。
- 告警应分级（info/warn/block）而非全量推送。

## 三、形式化与数学基础

ASR 漂移定义为相邻周期之差：

$$
\Delta = \mathrm{ASR}_{t} - \mathrm{ASR}_{t-1}
$$

对第 $c$ 类风险，最坏类别漂移：

$$
\Delta_{\max} = \max_c \big(\mathrm{ASR}_{t}(c) - \mathrm{ASR}_{t-1}(c)\big)
$$

告警规则：若 $\Delta_{\max} > \gamma$ 或 $\mathrm{ASR}_{t} > \eta$，则阻断。漂移的统计显著性可用两比例 z 检验判定，避免小样本误报。

## 四、代码实现

```python
# ASR 漂移计算与告警（示意）
def drift(asr_now, asr_prev):
    return asr_now - asr_prev

def should_block(asr_now, asr_prev, gamma=0.05, eta=0.20):
    d = drift(asr_now, asr_prev)
    return d > gamma or asr_now > eta        # 超阈值或漂移过大即阻断

# 每日回归：跑攻击库，更新基线
def nightly(asr_lib, model, guard):
    cur = asr(asr_lib, model, guard)
    if should_block(cur, baseline):
        alert("ASR regression detected")
    baseline = cur
```

## 五、与其他技术对比

| 方式 | 频率 | 人力 | 风险 |
|------|------|------|------|
| 一次性评测 | 低 | 高 | 易过时 |
| 半自动 | 中 | 中 | 中 |
| 全自动 CI | 高 | 低 | 攻击库污染 |

全自动最高频，但必须解决攻击库污染与裁判一致性两大风险，否则度量本身不可信。

## 六、常见误区

误区一：只看均值忽略最坏类别——某类 ASR 飙升被平均掩盖，而该类可能正是最危险的越狱路径。

误区二：未对误报做人工复核——裁判误判会制造噪音，长期导致团队对告警麻木。

误区三：攻击库与训练集混用——造成数据污染与过拟合，评测形同虚设。

误区四：告警无阈值——全量告警导致疲劳忽略，应分级（info/warn/block）。

误区五：把回归通过当「绝对安全」——ASR 低只说明已知攻击被挡，未知攻击仍是开放问题。

## 九、演进与趋势

攻防即服务（Red-Teaming as a Service）与持续红队平台兴起；攻击生成器与防御训练在统一闭环里互促，度量从单指标走向「安全-效用-成本」多维面板。

合成攻击生成与漏洞优先级排序（按危害分级告警）将成为标准，使有限人力聚焦最高风险。

## 十、小结

鲁棒性度量应进入日常 CI 而非一次性报告，以 ASR 漂移与最坏类别监控驱动持续防御迭代，并警惕攻击库污染与裁判偏差两大陷阱。
