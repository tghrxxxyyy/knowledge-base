# 越狱评测基准与攻防度量

> 对应 Ouyang 2022 InstructGPT 的对齐评测，以及 Rafailov 2023 DPO 中偏好优化可被攻破的讨论。

## 一、背景与挑战

没有统一基准，各家「我们的防御很安全」的声明便无法验证，测评结果不可比较。越狱评测基准要解决三件事：固定的攻击语料（可复现）、明确的目标模型接口、独立的裁判判定是否越界。同时基准必须「保鲜」——一旦攻击集泄漏到训练，防御便在已知集上过拟合，声明失真。

基准还是研究共同体的「通用语言」：只有共享基准，不同防御方案才能横向对比，社区才能就「什么是一次成功的越狱」达成共识。

否则每个团队自说自话，安全声明沦为营销话术，无法支撑真实的风险决策。

## 二、核心原理

基准运行方式：固定一组攻击样本 $X$，对目标模型 $M$ 逐一推理，得到输出集合；由独立裁判 $J$（人类或模型裁判，尽量与训练解耦）判定每条是否越界；汇总为攻击成功率 ASR，并以鲁棒准确率 $R=1-\mathrm{ASR}$ 报告。高质量基准应覆盖多风险类别、多语言、单轮与多轮，并定期滚动补充新攻击。

裁判的独立性至关重要：若裁判与训练同源（例如用同一模型给训练打分又做评测），会出现「自证清白」的偏倚，基准失去公信力。

## 三、形式化与数学基础

鲁棒准确率：

$$
R = 1 - \mathrm{ASR} = \frac{1}{N}\sum_i \mathbb{1}[\text{guard}(\text{model}(x_i)) = \text{pass}]
$$

对第 $c$ 类风险的子基准：

$$
R_c = 1 - \frac{1}{N_c}\sum_{i\in c} \mathbb{1}[\text{fail}_i]
$$

加权总鲁棒性（按风险严重度 $w_c$）：

$$
R_{\text{weighted}} = \sum_c w_c R_c, \quad \sum_c w_c = 1
$$

加权口径避免「在简单类别刷分、难类别失守」的失真。

## 四、代码实现

```python
# 鲁棒准确率评测（示意）
def robustness(prompts, model, judge):
    blocked = 0
    for p in prompts:
        out = model(p)
        if judge(out) == "pass":           # 未被越狱
            blocked += 1
    return blocked / len(prompts)

# 分风险类别汇总
def report(prompts, model, judge):
    by_cat = {}
    for c in set(p.cat for p in prompts):
        sub = [p for p in prompts if p.cat == c]
        by_cat[c] = robustness(sub, model, judge)
    return by_cat
```

## 五、与其他技术对比

| 基准类型 | 可回归 | 保鲜难度 | 成本 |
|----------|--------|----------|------|
| 静态固定集 | 高 | 高（易泄漏） | 低 |
| 滚动更新集 | 高 | 中 | 中 |
| 纯人工 | 低 | 低 | 高 |
| 自适应生成 | 中 | 低 | 中 |

静态集便宜但易过时，滚动与自适应在保鲜上更优，代价是运维更复杂。

## 六、常见误区

误区一：评测集一成不变——防御在已知攻击上过拟合，数字虚高。

误区二：裁判标准不一致——不同版本裁判致结果不可比，应在基准中冻结裁判版本。

误区三：只看总 ASR——掩盖某类风险失控，应分风险类别报告。

误区四：用训练同来源裁判——自证清白有偏，必须解耦。

误区五：把基准通过当上线许可——基准只度量已知攻击，未知攻击需红队补充。

## 九、演进与趋势

从静态基准走向「滚动基准 + 自适应攻击生成 + 多裁判交叉验证」；评测扩展到多模态、代理式（agentic）与工具调用场景，度量从 ASR 走向更细的后果分级（如危害等级、可逆性）。

开放基准与排行榜（leaderboard）正推动防御研究可复现，但也带来「针对榜单过拟合」的新风险，需配合私有held-out集。

## 十、小结

基准的保鲜度决定防御声明的可信度：以固定可复现攻击集 + 独立裁判 + 分风险报告 + 滚动补充，方能持续验证鲁棒性，并警惕过拟合与裁判偏倚两大致命伤。
