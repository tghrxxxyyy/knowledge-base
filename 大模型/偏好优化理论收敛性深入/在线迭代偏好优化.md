# 在线迭代偏好优化

> 对应 Ouyang et al., *InstructGPT*, NeurIPS 2022（多轮迭代 RLHF）；理论动机见 Azar et al., AISTATS 2024 与离线—在线混合的偏好优化研究。

## 一、背景与挑战

单轮离线 DPO 的收益会饱和：数据里的败者回答很快被压得足够低，剩下的梯度都来自已经分开的对，而模型的新失败模式并不在数据里。要继续提升，必须让数据跟着策略走——这就是在线（或迭代）偏好优化。

## 二、核心原理

循环三步：用当前策略对 prompt 采样多个候选；用裁判（人类、奖励模型或更强模型）给出偏好；把新偏好对喂回偏好优化，并把参考模型更新为上一轮策略。这样每轮的数据都是 on-policy 的，覆盖问题被持续修补，同时参考模型的滚动更新等价于做了一系列小步 KL 约束的近似策略镜像下降。风险是误差累积：裁判的偏差会被逐轮放大，形成自我强化的偏好漂移。

## 三、数学形式

第 $t$ 轮：以 $\pi_{t-1}$ 为参考与采样策略，在数据 $D_t\sim\pi_{t-1}$ 上求

$$\pi_t=\arg\max_\pi\ \mathbb E_{D_t}\big[\text{pref-objective}\big]-\beta\,\mathrm{KL}(\pi\,\|\,\pi_{t-1})$$

这是一族 KL 邻域内的迭代更新（镜像下降型），总偏离满足 $\mathrm{KL}(\pi_T\|\pi_0)$ 随轮数近似累加，因此需要按轮预算控制总偏离，而不是只控制单轮 $\beta$。

## 四、代码实现

```python
def iterative_preference_loop(model, prompts, judge, rounds=3, k=4):
    ref = snapshot(model)                       # 冻结当前权重作为参考
    for t in range(rounds):
        pairs = []
        for x in prompts:
            cands = [generate(model, x, temperature=0.9) for _ in range(k)]
            w, l = judge.best_worst(x, cands)   # 裁判给出最优/最差
            if judge.margin(x, w, l) > 0.2:     # 过滤差异过小的对
                pairs.append((x, w, l))
        train_dpo(model, ref, pairs, beta=0.1)  # 一轮偏好优化
        if kl_estimate(model, ref) > KL_BUDGET: # 总偏离超预算则停止
            break
        ref = snapshot(model)                   # 参考模型滚动更新
    return model
```

## 五、与其他对比

- 相对单轮 DPO：持续修补覆盖，收益更高；代价是每轮采样与标注成本，以及漂移风险。
- 相对 PPO：迭代 DPO 是「批式在线」，采样与更新解耦，工程更简单；PPO 是逐 batch 在线，样本效率更高但更难稳。
- 与 奖励模型过优化与奖励黑客深入：若裁判是奖励模型，迭代循环会加速过优化，必须监控真实指标。

## 六、常见误区

- 每轮不更新参考模型。那样 KL 约束始终针对最初模型，后期变成强行拉回，收益被抵消。
- 用同一个奖励模型无限迭代。裁判偏差被逐轮放大，最终对齐到 RM 的癖好而非人类偏好。
- 不过滤低差异对。差异过小的对贡献噪声梯度，是迭代后期质量下滑的常见原因。

## 八、面试题

- 迭代偏好优化为何优于单轮？答：数据随策略更新保持 on-policy，持续覆盖新的失败模式，避免梯度饱和。
- 迭代中如何防止漂移？答：滚动更新参考模型、控制总 KL 预算、定期换用独立裁判或引入人工抽检。

## 九、演进

单轮离线 DPO → 多轮迭代 DPO（参考滚动） → 混合在线（部分 on-policy 采样 + PPO 式更新） → 带主动学习的偏好采集。

## 十、小结

在线迭代把偏好优化从「一次性拟合」变成「持续镜像下降」，是突破单轮饱和的主路径，但必须以总 KL 预算与裁判独立性作为安全带。
