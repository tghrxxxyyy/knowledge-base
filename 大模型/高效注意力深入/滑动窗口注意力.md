# 滑动窗口注意力

> 对应 Beltagy et al., *Longformer: The Long-Document Transformer*, 2020（arXiv:2004.05150）；Jiang et al., *Mistral 7B*, 2023（Sliding Window Attention）；Child et al., *Generating Long Sequences with Sparse Transformers*, 2019（dilated pattern）；FlashAttention 系列（Dao et al.）中对局部 mask 的高效实现；参见本库「高效注意力深入」其余篇与「长上下文技术」。

## 一、背景与挑战

标准自注意力对长度 $n$ 的序列需要 $O(n^2)$ 的注意力分数计算与（朴素实现下）$O(n^2)$ 的中间显存。当 $n$ 从 2k 扩到 32k、128k 时，二次项迅速吃掉训练预算与 HBM。然而大量任务（代码局部作用域、自然语言局部依存、滑动窗口检索）并不需要**每个 query 都看全序列**：真正被 softmax 高权重选中的位置往往聚集在附近或少数全局锚点。

滑动窗口注意力（Sliding Window Attention, SWA）的出发点是：若每个 query 只关注最近 $w$ 个 key（$w \ll n$），则单层复杂度降为 $O(nw)$，显存与计算近似线性；再通过**全局 token、膨胀空洞、多头异构窗口或层间堆叠**，在有限层数内把有效感受野扩到全序列。

真正的工程挑战在于：

1. **感受野 vs 窗口大小**：仅因果局部窗时，第 $L$ 层理论感受野约 $L \cdot w$；要覆盖 $n$ 需要 $O(n/w)$ 层，不现实。
2. **全局信息稀疏注入**：文档分类、检索问答需要跨段落信息；全用局部窗会“近视”。
3. **与 KV cache / Flash 的兼容**：推理时窗口可转化为有界 KV cache；训练时需自定义 mask 且不破坏 FlashAttention 的 fused kernel。
4. **因果与双向的取舍**：LM 只能因果（左窗）；编码器可双向（对称窗）。

## 二、核心原理

### 2.1 因果滑动窗口

对因果 LM，位置 $i$ 的 query 只允许看到 $[i-w+1, i]$。相对全连接因果 mask，每个 query 的有效 key 数从 $i+1$ 压到 $\min(i+1, w)$。

单层复杂度：

$$
\text{FLOPs} \approx O(n \cdot w \cdot d), \quad \text{Score 显存} \approx O(n \cdot w)
$$

当 $w$ 固定（如 Mistral 7B 取 $w=4096$），序列从 4k 到 32k 时计算近似线性增长，而非平方。

### 2.2 感受野与堆叠

因果 SWA 堆叠 $L$ 层后的**理论感受野**（不计全局头）：

$$
R(L, w) = L \cdot (w - 1) + 1
$$

例：$L=32, w=4096 \Rightarrow R \approx 13$ 万 token。这是“层间复利”：每层在上一层已扩大的隐状态上再滑一窗，远端信息以**间接**方式传递（类似卷积感受野），但路径变长，远距离 token 的梯度/信号可能衰减。

### 2.3 Dilated / 稀疏模式（Sparse Transformers、Longformer）

为在**单层**内覆盖更远距离，Child et al. 提出空洞（dilated）滑窗：stride 为 $2^k$ 的稀疏采样；Longformer 则组合：

- **局部滑窗**（window size $w$）：捕捉邻域；
- **全局注意力 token**：对 `[CLS]`、问题 token 等特殊位置，允许其 attend 全序列、全序列也可 attend 它（任务相关的全局锚）；
- 部分实现再加 **dilated** 分支扩大无全局 token 时的覆盖。

全局 token 数量 $g \ll n$ 时，额外复杂度 $O(g \cdot n \cdot d)$，仍近线性。

### 2.4 多头异构窗口（Mistral 风格）

Mistral 7B 采用纯局部滑窗（$w=4096$）而非 Longformer 式全局头，依赖深度与 $L\cdot w$ 感受野覆盖长文档；部分开源变体则让部分 head 用大窗/全局、部分 head 用小窗，平衡局部细节与全局摘要。异构时要小心：不同 head 的 mask 不同，Flash 需按 head 组配置 window size。

### 2.5 与 FlashAttention、线性注意力的关系

| 技术 | 注意力语义 | 与 SWA 关系 |
|------|------------|-------------|
| FlashAttention | **精确** softmax，IO 优化 | SWA 的 mask 可与 Flash 融合：跳过窗外 block，进一步省算力 |
| 线性注意力 / Performer | **近似**核化，$O(n)$ | 不同路线：SWA 仍用 softmax 但稀疏连接；线性注意力改算子 |
| Mamba/SSM | 状态递推 | 也线性，但可选择性记忆；SWA 保留 softmax 表达力 |
| MQA/GQA | 减 KV 头 | 正交：可与 SWA 叠加，同时减头与减窗 |

FlashAttention-2/3 支持 `window_size=(left, right)`，在 kernel 内对块做窗口跳过，使 SWA 训练既有算法稀疏又有实现加速。

## 三、形式化与数学基础

全连接因果注意力允许集合：

$$
\mathcal{A}_{\text{full}}(i) = \{ j : 0 \le j \le i \}
$$

因果滑动窗口允许集合：

$$
\mathcal{A}_{\text{swa}}(i; w) = \{ j : \max(0, i-w+1) \le j \le i \}
$$

注意力输出：

$$
\text{Attn}(i) = \sum_{j \in \mathcal{A}(i)} \alpha_{ij} V_j, \quad
\alpha_{ij} = \frac{\exp(q_i^\top k_j / \sqrt{d})}{\sum_{j' \in \mathcal{A}(i)} \exp(q_i^\top k_{j'} / \sqrt{d})}
$$

带全局 token 集 $\mathcal{G}$ 的 Longformer 型允许集合：

$$
\mathcal{A}(i) = \mathcal{A}_{\text{swa}}(i; w) \cup \mathcal{G} \cup \{ j : i \in \mathcal{G} \}
$$

膨胀滑窗（第 $k$ 个 head 或层用 stride $s$）：

$$
\mathcal{A}_{\text{dil}}(i; w, s) = \{ j = i - t \cdot s : t = 0,1,\ldots,\lfloor (w-1)/s \rfloor, \; j \ge 0 \}
$$

复杂度对比（单层、head 数 $h$、维度 $d$ 固定）：

| 模式 | 时间 | Score 存储 |
|------|------|------------|
| 全连接 | $O(n^2 d)$ | $O(n^2)$ |
| SWA | $O(n w d)$ | $O(n w)$ |
| SWA + $g$ 全局 | $O(n w d + g n d)$ | $O(n w + g n)$ |

## 四、代码实现

```python
import torch
import torch.nn.functional as F

def sliding_window_causal_mask(n: int, w: int, device="cpu"):
    """返回 (n, n) 的布尔 mask：True 表示允许 attend。
    因果 + 左侧窗口 w。推理/教学用；生产请用 Flash 的 window_size 参数。
    """
    i = torch.arange(n, device=device).unsqueeze(1)
    j = torch.arange(n, device=device).unsqueeze(0)
    causal = j <= i
    window = (i - j) < w
    return causal & window  # (n, n)

def naive_swa_attention(q, k, v, w: int):
    """教学版 SWA：q,k,v 形状 (B, H, N, D)。仅用于正确性对照，未做 IO 优化。"""
    B, H, N, D = q.shape
    scores = q @ k.transpose(-2, -1) / (D ** 0.5)          # (B,H,N,N)
    mask = sliding_window_causal_mask(N, w, q.device)      # (N,N)
    scores = scores.masked_fill(~mask, float("-inf"))
    p = F.softmax(scores, dim=-1)
    return p @ v

# 生产路径：FlashAttention 直接吃 window_size（左右各 w_left / w_right）
# from flash_attn import flash_attn_func
# out = flash_attn_func(q, k, v, causal=True, window_size=(w - 1, 0))
# q,k,v: (B, N, H, D) 注意 FA 的维序与上式不同

# 多头异构示意：部分头大窗、部分头小窗（需自定义 kernel 或分组调用）
def multi_head_windows(H: int, base_w: int):
    # 例：一半头 w=4096，一半头 w=1024；或留 1 个全局头
    return [base_w if h % 2 == 0 else base_w // 4 for h in range(H)]
```

训练配置侧（概念示意，具体字段随框架变化）：

```yaml
# 非官方字段，仅示意“窗口 + 可选全局头”的配置形状
model:
  attn_implementation: flash_attention_2
  sliding_window: 4096
  global_attn_head_indices: [0]   # Longformer 式：head 0 做全局
```

生产踩坑：

- 直接用 `masked_fill` 造 $n\times n$ mask 会在长序列上 OOM，等于没省显存；必须走 Flash/vLLM 的窗口实现。
- 混用 SWA 与 KV cache：推理时 cache 只需保留最近 $w$ 个 KV，但若框架按全注意力缓存，显存仍随 $n$ 涨。
- SFT 时窗口 $w$ 与 max_seq_len 不匹配：文档长于 $w$ 但模型只有局部头，远距离监督信号弱，指标异常却难归因。

## 五、与其他技术对比

| 维度 | 全连接注意力 | 滑动窗口 | Longformer 混合 | 线性注意力 | Mamba/SSM |
|------|--------------|----------|-----------------|------------|-----------|
| 复杂度 | $O(n^2)$ | $O(nw)$ | $O(nw + gn)$ | $O(n)$ | $O(n)$ |
| 远距离依赖 | 一层直达 | 需层间堆叠 | 全局头直达 | 核近似传递 | 状态压缩 |
| 精确 softmax | 是 | 是（窗内） | 是 | 否 | 否（递推） |
| 实现成熟度 | 极高 | Flash/window 成熟 | 需定制 mask | 生态参差 | 自定义 kernel |
| 典型代表 | GPT-2/3 原始 | Mistral 7B | Longformer、BigBird | Performer | Mamba、Jamba |
| 与 Flash 兼容 | 直接 | window_size | 部分 | 不适用 | 不适用 |

选型直觉：

- 序列 ≤ 8k、算力充足：全连接 + Flash 最稳。
- 4k–128k、强局部性（代码、语音、日志）：SWA + 足够深度。
- 需要跨文档全局聚合（QA、分类）：Longformer 式全局 token，或 SWA + 外挂检索。
- 超长且可近似：线性/SSM，或混合层（局部 SWA 与全局/线性层交替）。

## 六、常见误区

1. **认为窗口能一层覆盖任意长依赖**。单层只能看 $w$；跨窗必须靠层堆叠、全局 token 或外挂记忆。
2. **把 SWA 当成近似注意力**。窗内仍是精确 softmax；它改变的是**连接模式**，不是算子形式（对比线性注意力才是改算子）。
3. **只关注训练 FLOPs，忽略推理 KV cache 策略**。SWA 的显存收益依赖 cache 驱逐；若 cache 仍存全序列，收益消失。
4. **所有 head 同一窗，却期望某些 head 像全局摘要头**。异构窗或全局头是显式设计，不是自动涌现的保证。
5. **在长文档任务上沿用短窗微调**。$w$ 小于任务有效跨度时，加数据也救不回远距离召回。
6. **自定义稀疏 mask 后仍走朴素 attention**。算法上稀疏、实现上 $O(n^2)$ 物化，等于白做。

## 八、面试题

**问题 1：滑动窗口注意力如何把复杂度降到线性？窗口 $w$ 与序列长 $n$ 的关系？**  
要点：每个 query 只计算 $w$ 个 key，总分数计算 $O(nw)$；$w$ 固定则对 $n$ 线性。代价是单层无法直达远距离，需 $L$ 层把感受野扩到约 $Lw$。

**问题 2：Longformer 如何兼顾局部与全局？全局 token 的额外开销？**  
要点：局部滑窗 + 对少数 token 的全序列注意力；全局 token 数为 $g$ 时额外 $O(gn)$，$g \ll n$ 时仍近线性。适合分类 CLS、问题 token 锚点。

**问题 3：Mistral 的 SWA 与 Longformer 有何不同？**  
要点：Mistral 7B 主要用纯局部窗 + 深度扩感受野，不依赖大量全局头；Longformer 面向编码器任务显式引入全局 token。推理上 SWA 可用有界 KV cache。

**问题 4：SWA 与 FlashAttention 是互斥的吗？**  
要点：不互斥。Flash 是 IO 优化的精确注意力；SWA 是稀疏连接模式。FA 提供 window 参数，在分块时跳过窗外块，二者叠加。

**问题 5：为什么训练用了 SWA，长文检索类指标仍崩？**  
要点：模型等效感受野可能仍不足；或全局信息无注入通道；需检查层数、窗口、是否具备全局头/外挂记忆，并做跨窗口 needle 类探针。

**问题 6：推理时如何利用 SWA 压缩 KV cache？**  
要点：每个新 token 只依赖最近 $w$ 个 KV；超出窗口的历史可驱逐（PagedAttention 的 sliding window 模式）；多轮对话中若需更早上下文，应另做记忆/摘要而非无限 cache。

## 九、演进与趋势

1. **稀疏模式时代（2019）**：Sparse Transformers 的 strided/dilated → 手工设计连通图。
2. **文档级混合（2020）**：Longformer、BigBird：局部 + 全局 + 随机，服务长文档理解。
3. **生产 LM 标配（2023–）**：Mistral 等把 SWA 推广到 decoder-only 主流，窗口与层数、GQA、Flash 一起选型。
4. **异构与混合架构（2024–）**：SWA 层与全注意力层交替（如部分 MoE/长上下文模型），或 SWA 与线性/SSM 层混排，在成本与全局性间折中。
5. **与 KV 管理融合**：vLLM 等引擎把 sliding window 做成 cache 策略，训练推理一体的“窗口契约”写进模型 config。

## 十、小结

滑动窗口注意力用“只看附近”换取对 $n$ 的线性复杂度，再通过深度感受野、全局 token 与膨胀采样补回全局信息。它与 FlashAttention 正交（稀疏连接 + IO 优化可叠加），与线性/SSM 互补（精确局部 softmax vs 算子级近似）。生产上选窗口不是拍脑袋：要同时核算层数给出的 $Lw$、任务的真实跨度、KV cache 驱逐策略，以及 kernel 是否真支持 window——算法写了稀疏、实现仍是稠密，是这条技术线最常见的翻车点。
