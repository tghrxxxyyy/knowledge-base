# 分块与重计算

> 对应 Chen et al., *Training Deep Nets with Sublinear Memory Cost*, 2016（activation checkpointing）；Dao et al., *FlashAttention / FlashAttention-2*, 2022–2023（tiling + 在线 softmax + 反向重计算）；Narayanan et al., *Efficient Large-Scale Language Model Training on GPU Clusters*（Megatron 与 selective recompute）；PyTorch `torch.utils.checkpoint` 与 HuggingFace `gradient_checkpointing` 文档；参见本库「高效注意力深入」其余篇与「训练技巧与稳定性」。

## 一、背景与挑战

反向传播需要前向的中间激活（或能从边界重算它们）。训练 Transformer 时，**激活显存**常超过参数与优化器状态，成为 batch size / 序列长度的第一瓶颈。朴素公式：

$$
M_{\text{act}} \approx \mathcal{O}(B \cdot L \cdot n \cdot d)
$$

（$B$ batch、$L$ 层、$n$ 序列、$d$ 隐维；再乘上每层多份张量：QKV、MLP 中间维 $\sim 4d$、attention 相关等。）175B 级模型即使权重用混合精度+ZeRO，激活仍可能把单卡打爆。

两条互补的工程路线：

1. **分块（Tiling / Chunking）**：把大张量切成适合 SRAM/寄存器的块，流式计算，避免在 HBM 物化 $n\times n$ 等大中间结果（FlashAttention 的核心）。
2. **重计算（Recomputation / Checkpointing）**：前向只保存少量“检查点”，反向时用算力换显存，重新计算丢掉的激活。

挑战在于：重计算一般使前向+反向总 FLOPs 上升（全重算理论约 $+1/3$ 前向量级的时间），且**不是所有算子重算都划算**——有的激活便宜、有的重算极贵（如 attention 的 $n^2$ 路径）。因此“无脑全开 checkpoint”常常显存降了、吞吐崩了。

## 二、核心原理

### 2.1 激活检查点（Activation Checkpointing）

经典策略（Chen et al. 2016）：

- 将网络切成 $k$ 段，段边界存输出（checkpoint）。
- 前向：段内不存中间激活。
- 反向：对每段从 checkpoint 重算该段前向，再算该段反向。

显存从 $O(N)$（$N$ 为可微算子数）降到 $O(\log N)$（均匀切分时）或 $O(\sqrt{N})$（实用折中），代价约 $4/3$ 倍前向计算（每个段重算一次前向）。

PyTorch 语义：

```python
y = checkpoint(block, x, use_reentrant=False)
```

- `use_reentrant=False`：推荐的新实现，支持非张量输入、更稳的 RNG 管理。
- RNG：dropout 等需在重算时复现同一随机数；PyTorch 用保存/恢复 RNG state 或 per-seed 标记。

### 2.2 选择性重计算（Selective Recomputation）

并非所有中间张量都值得存或值得重算。启发式：

| 张量 | 存？ | 重算？ | 理由 |
|------|------|--------|------|
| LayerNorm 输入 | 便宜且小 | 可重算 | 体积小，有时直接存 |
| 注意力 softmax 概率 $P$ | 不存 | 反向重算 | $O(n^2)$，Flash 已不物化 |
| QKV 线性输出 | 按显存 | 可分块重算 | 大而规则 |
| MLP 中间 $4d$ 激活 | 按显存 | 可重算 | GELU 重算便宜 |
| 残差流边界 | 存 | — | checkpoint 点 |

Megatron 的 selective recompute：只对 attention 等“重算收益高、代价可控”的部分重算，其余保留；比整层全 checkpoint 更省时间。

### 2.3 与 FlashAttention 反向重计算的关系

FlashAttention **前向就不存** $n\times n$ 的 $S$ 与 $P$，只存（或可省）logsumexp 等 $O(n)$ 摘要；反向时用 Q/K/V 与 L 重新分块算 $dS$、$dV$。这本质上是：

- **算法级**：tiling + 在线 softmax → 无需物化。
- **实现级**：反向 IO-aware 的重计算，而非从 HBM 读回巨大 $P$。

因此：开了 FlashAttention 后，再对整个 attention 模块套 PyTorch checkpoint 往往**重复付费**（两次分块重算）。实践上更优：attention 用 FA 自身的反向重算，只对非 attention 大块（或 FA 不覆盖的自定义算子）打 checkpoint。

### 2.4 显存–时间 Tradeoff

设全模型 $L$ 个块，checkpoint 选 $c$ 个边界：

- 显存：约 $O(c \cdot \text{激活/块}) + O(\text{边界})$
- 额外时间：约 $\Delta t \propto (L/c)$ 相关的重算量（分段重算）；全模型一体 checkpoint 时接近“多算一遍前向”的某个比例

经验法则：

1. 先用 FlashAttention 消掉 attention 的 $n^2$ 激活。
2. 再对 **Transformer block 级** checkpoint 做粗粒度开关，用 `torch.profiler` / `gpusmem` 看峰值。
3. 若仍不够，对 block 内 MLP 或 norm 细粒度选择性重算。
4. 终极档：CPU offload 激活（ZeRO-Offload / FSDP CPU offload），把重算换成 PCIe 传输，时间代价更大。

## 三、形式化与数学基础

### 3.1 反向需要什么

对一层 $y = f(x)$，反向需 $\partial f / \partial x$ 依赖的中间量（如 sigmoid 输出、attention 的 $P$）。若前向不保存，可：

$$
\tilde{y} = f(x) \quad\text{（重算）}, \qquad
\frac{\partial \mathcal{L}}{\partial x} = \frac{\partial \mathcal{L}}{\partial y}\cdot \frac{\partial f}{\partial x}\Big|_{\tilde{\cdot}}
$$

只要 $f$ 确定（含 RNG 一致），重算激活在数值上等价（浮点非结合会引入极小差异）。

### 3.2 分段 checkpoint 的显存–计算

将 $N$ 个算子均分为 $g$ 段：

$$
M_{\text{act}} = O(g) \ \text{(边界)} + O(N/g)\ \text{(段内重算缓冲)},
\quad \min_g \Rightarrow M = O(\sqrt{N})
$$

计算量：

$$
T \approx T_{\text{fwd}} + T_{\text{bwd}} + T_{\text{recompute}}
\approx \left(1 + \frac{1}{2} + \frac{1}{3}\right) T_{\text{fwd}}\ \text{量级（经典结论）}
$$

具体比例随分段与实现变化；工程上以实测吞吐为准。

### 3.3 FlashAttention 的 L 与反向

前向对每个 query 行维护：

$$
L_i = \log \sum_j \exp(s_{ij} - m_i) \quad (O(n)\ \text{存储})
$$

反向利用 $Q,K,V,L$ 重算块内 softmax 相关量：

$$
dS_{ij} = P_{ij}\,(dP_{ij} - \sum_l P_{il}\, dP_{il}), \quad
P_{ij} = \exp(s_{ij} - m_i - L_i)
$$

无需从 HBM 读 $P\in\mathbb{R}^{n\times n}$。

## 四、代码实现

```python
import torch
from torch.utils.checkpoint import checkpoint

class BlockCheckpoint(torch.nn.Module):
    """Transformer block 外包一层 checkpoint。推荐 non-reentrant。"""
    def __init__(self, block):
        super().__init__()
        self.block = block

    def forward(self, x):
        # 训练时走 checkpoint，推理时直接前向
        if self.training:
            return checkpoint(self.block, x, use_reentrant=False)
        return self.block(x)

def build_model_with_ckpt(n_layers: int, policy: str = "all"):
    """
    policy:
      - "all": 每层都 checkpoint（省显存、较慢）
      - "none": 全存激活
      - "periodic": 每 4 层 checkpoint 一次（折中）
      - "attention_only": 仅对 attn 子模块 checkpoint（需自定义拆分）
    """
    layers = [TransformerBlock() for _ in range(n_layers)]
    wrapped = []
    for i, blk in enumerate(layers):
        use = (
            policy == "all"
            or (policy == "periodic" and i % 4 == 0)
            or (policy == "attention_only" and False)  # 实际应包 blk.attn
        )
        wrapped.append(BlockCheckpoint(blk) if use else blk)
    return torch.nn.Sequential(*wrapped)

# HuggingFace 训练常用开关（示意字段名，随版本可能变化）
# model.gradient_checkpointing_enable()
# model.config.use_cache = False  # 训练开 ckpt 时通常关 KV cache

# 显存粗估（教学）：单位简化为“激活元素个数”
def act_elems(B, L, n, d, mlp_ratio=4, store_attn_prob=False):
    per_layer = (
        3 * B * L * n * d          # QKV 激活粗算，忽略头维细节
        + 2 * B * L * n * int(mlp_ratio * d)  # MLP 两层
        + (B * L * n * n if store_attn_prob else B * L * n)  # P vs FA 的 L
    )
    return per_layer
```

生产踩坑：

- 开启 checkpoint 后仍设 `use_cache=True`，训练显存异常或与实现冲突。
- 对很小的层也 checkpoint：重算开销 > 显存收益。
- RNG：自定义 dropout 在 non-reentrant 下未正确 seed，重算数值不一致导致 loss 尖刺。
- 混用自定义 attention + 全层 ckpt，却没有 profiler，吞吐掉 20%+ 却找不到原因。

## 五、与其他技术对比

| 维度 | 全存激活 | Block Checkpoint | 选择性重算 | Flash（不物化 P） | CPU Offload 激活 |
|------|----------|------------------|------------|-------------------|-----------------|
| 显存 | 最高 | 很低 | 低–中 | attention 项极低 | 最低（驻留少） |
| 额外计算 | 0 | 高（约多一遍前向量级） | 中 | 前向已付 tiling 成本 | 传输+可能重算 |
| 实现复杂度 | 低 | 低（API 开关） | 中（需策略） | 高（kernel） | 中（框架支持） |
| 与 TP/PP | 正交 | 正交，PP 边界常全存 | 正交 | 常默认开 | 与 ZeRO-Offload 联动 |
| 适用 | 小模型/调试 | 默认省显存手段 | 大模型提吞吐 | 训练推理标配 | 显存极端受限 |

与量化/低精度：重计算改变的是**存不存激活**；bf16/fp8 改变的是**每个元素多大**。二者可叠加，但都要用数值稳定性检查（loss scale、grad norm）兜底。

## 六、常见误区

1. **以为重计算是免费午餐**。它用时间换显存；若算力已饱和（GPU util 高、带宽不是瓶颈），加 checkpoint 可能净亏吞吐。
2. **FA + 整模块 checkpoint 重复重算**。attention 内部已反向重算，外层再包一层等于重算套重算。
3. **checkpoint 粒度越细越好**。过细导致边界存储多、调度开销大；过粗则单段重算缓冲又变大。需实测峰值与吞吐。
4. **忽视 dropout/RNG 一致性**。重算路径随机数不一致 → 前向与反向梯度不匹配 → 难查的 NaN 或低效训练。
5. **把激活 checkpoint 与 ZeRO 混为一谈**。ZeRO 分片的是优化器状态/梯度/参数；checkpoint 管的是**中间激活**，解决的问题不同。
6. **推理也开训练用 checkpoint**。推理无梯度，checkpoint 无收益还可能增加延迟。

## 八、面试题

**问题 1：activation checkpoint 如何把激活显存从 $O(N)$ 降到 $O(\sqrt N)$？代价是什么？**  
要点：只存段边界；反向对每段重算。显存看边界+单段缓冲；代价是额外前向计算与 RNG 管理复杂度。

**问题 2：FlashAttention 为什么说“已经用了重计算”？**  
要点：前向不存 $n\times n$ 的 $P,S$，反向用 $Q,K,V$ 与 logsumexp 分块重算；与外部 checkpoint 功能重叠，叠开可能浪费算力。

**问题 3：什么情况下不该对某层开 checkpoint？**  
要点：该层激活占比很小、重算代价高（如超大 $n$ 的非 FA 路径）、或 GPU 算力已是瓶颈而显存有余。应 profile 峰值与 step 时间后再定。

**问题 4：选择性重计算的“选择”依据是什么？**  
要点：按张量体积 vs 重算 FLOPs 比：体积大、重算便宜的优先丢弃；$O(n^2)$ 概率矩阵优先不物化；边界小张量保留。

**问题 5：开 checkpoint 后 loss 出现尖刺/NaN，如何排查？**  
要点：检查 `use_reentrant`、dropout RNG、自定义 autograd 是否在重算路径副作用（如原地修改）、混合精度 GradScaler 与重算的交互。

**问题 6：如何用一句话向 TL 解释“显存不够是加卡还是开重算”？**  
要点：先开 FA + 合理 checkpoint（近零硬件成本），仍不够再 ZeRO/FSDP 分片状态，再不够才 PP/TP 或 offload；加卡要结合通信拓扑算总拥有成本。

## 九、演进与趋势

1. **Sublinear checkpointing（2016）**：通用分段重算，为深网训练奠基。
2. **框架内建（2018–2021）**：PyTorch/TensorFlow 原生 checkpoint API，HF `gradient_checkpointing` 普及。
3. **与 IO 感知融合（2022–）**：FlashAttention 把重算做进 kernel，反向不再读回大矩阵。
4. **选择性/可学习重算（Megatron 等）**：按算子配置重算集合，在吞吐与显存间帕累托优化。
5. **更大粒度系统化**：与 ZeRO-Offload/Infinite、CPU/NVMe 层级存储、FP8 激活压缩组合，形成“存不下就重算或下沉”的多级策略。

## 十、小结

分块与重计算是训练侧最经典的“显存换时间”手段：tiling 避免在 HBM 物化大中间结果，checkpoint 与 Flash 反向则用可控的重算换回激活空间。生产顺序建议是——先 Flash 消掉 attention 二次项，再 block 级 checkpoint，再选择性重算与分片状态，最后才是 offload。每一次开关都应以峰值显存与 tokens/s 实测为准；把重计算当默认免费开关，是这条技术线上最常见的性能回旋镖。
