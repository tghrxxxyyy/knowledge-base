# 重排延迟与部署

> 对应线上重排工程；与 推理调度深入 / 连续批处理深入 衔接。

## 一、背景与挑战

重排增加每请求计算，需控制延迟与成本。

## 二、核心原理

仅对召回 top-N（如 50-100）重排；用蒸馏小模型；与生成共批（连续批处理）。

## 三、数学形式

延迟 $L = L_{recall} + L_{rerank}(N) + L_{gen}$；选 N 在质量/延迟拐点。

## 四、代码实现

```python
cands = retriever.search(q, 100)        # 快
top = reranker.rank(q, cands, 10)       # 精
```

## 五、与其他对比

- 与 KV缓存优化深入（重排本身不需长 KV）不同，重排在检索侧。
- 与 推理经济成本深入 衔接（成本）。

## 六、常见误区

- N 过大致重排成瓶颈。
- 重排模型未与生成同硬件调度致排队。

## 七、与开源书对应

- llm-course：https://github.com/mlabonne/llm-course

## 八、面试题

- 如何控重排延迟？答：限制候选数 N、用蒸馏小重排模型、与生成共批。

## 九、演进

串行 → 并行流水 → 重排蒸馏到召回。

## 十、小结

重排部署须限制候选与用轻量模型，平衡质量与延迟。
