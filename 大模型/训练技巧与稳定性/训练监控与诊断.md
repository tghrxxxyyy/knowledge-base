# 训练监控与诊断

> 对应 Megatron-LM / DeepSpeed 训练可观测性实践；参考 llm-course 训练稳定性章节、LangChain 实验追踪（W&B）文档。

## 一、背景与挑战

大模型训练常以千卡、数周计，任何一次静默失败（silent failure）都可能让数百万算力打水漂：loss 悄悄发散、注意力退化成均匀分布、激活值溢出为 NaN、数据管线喂入损坏样本。这类问题不会立即崩溃，而是在数百步后才被发现，因此必须建立**持续可观测**体系。挑战在于：指标维度多（标量/分布/张量），日志量大，需在极低开销下实时报警并支持回滚干预。

## 二、核心原理

可观测体系围绕三类信号：(1) **标量趋势**——train/val loss、learning rate、grad norm、token 吞吐；(2) **分布形态**——注意力权重熵、激活值直方图、嵌入范数，用于捕捉退化；(3) **异常事件**——loss spike、NaN/Inf、硬件 ECC 错误。诊断闭环为：采集 → 可视化 → 触发阈值告警 → 自动干预（跳过该 step / 临时降 LR / 重启该 rank）。关键是区分「可恢复波动」与「真发散」，避免误杀。

## 三、形式化与数学基础

梯度范数监控：记第 $t$ 步梯度拼成向量 $g_t$，其全局范数

$$\|g_t\|_2 = \sqrt{\sum_i g_{t,i}^2}$$

注意力退化检测常用熵：对第 $h$ 头、第 $i$ 个查询的注意力分布 $a_{i}^{(h)}$，

$$H(a_i^{(h)}) = -\sum_j a_{ij}^{(h)} \log a_{ij}^{(h)}$$

熵过低说明注意力塌缩到少数 key，过高（接近均匀）说明未学到结构；二者皆为异常信号。loss spike 可定义为相对滑动均值偏离：

$$\frac{\mathcal{L}_t - \mu_t}{\sigma_t} > \tau \quad (\tau\approx 3)$$

## 四、代码实现

```python
from torch.utils.tensorboard import SummaryWriter
writer = SummaryWriter("runs/exp1")

for step, (x, y) in enumerate(loader):
    loss = model(x, y).loss
    loss.backward()
    gnorm = torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    # 检测 spike
    if torch.isfinite(loss) and gnorm > 10 * running_mean:
        optimizer.zero_grad(); continue      # 跳过坏 step
    optimizer.step()

    if step % 50 == 0:
        writer.add_scalar("train/loss", loss, step)
        writer.add_scalar("train/grad_norm", gnorm, step)
        attn = model.attn_weights.detach().cpu()
        writer.add_histogram("attn/entropy", - (attn * attn.log()).sum(-1), step)
```

生产环境常用 W&B / MLflow 替代裸 TensorBoard，并接告警 webhook。

## 六、常见误区

- 只盯 train loss：loss 平稳也可能注意力已塌缩，需看熵/范数分布。
- spike 一律重启：多为单步坏数据，跳过该 step 即可，误重启浪费算力。
- 监控频率太低（每千步）：错过早期发散，回滚成本高。
- 忽视硬件指标：GPU ECC、HBM 温度常与训练不稳定强相关。

## 八、面试题

1. loss spike 第一步该查什么？答：优先查该 batch 数据是否损坏/含异常 token，再看 grad norm 与 LR 是否异常。
2. 为何只看 loss 不够？答：注意力/激活退化不立即反映到 loss。
3. 如何区分可恢复波动与发散？答：用滑动均值 ±3σ 阈值，并结合多指标交叉验证。

## 九、演进与趋势

监控正从「事后看板」走向「主动自治」：自动跳过坏 step、动态降 LR、故障 rank 自动重启，并与分布式训练框架（DeepSpeed、Megatron）深度集成；可观测性标准（如 OpenTelemetry 接入）让训练、数据、硬件指标统一关联。

## 十、小结

长周期大模型训练把「可观测性」从锦上添花变成生命线。建立标量 + 分布 + 异常事件三层监控，配合明确阈值与自动干预，才能在算力昂贵的前提下稳稳跑完数周训练，而非事后才发现问题。
