# 混合精度训练

> 对应 Micikevicius et al., *Mixed Precision Training*, 2018；参考 NVIDIA AMP、HuggingFace Transformers 训练文档、PyTorch `torch.amp`。

## 一、背景与挑战

FP32 训练稳定但占用 4 字节/参数，且受限于显存带宽与算力。现代加速卡（如 NVIDIA Tensor Core）在 FP16/BF16 下算力可达 FP32 的 2–16 倍。挑战在于：低精度动态范围窄，梯度易下溢（FP16 最小正规数约 $6\times10^{-8}$）或激活溢出，直接全量低精度会令训练发散。混合精度（Mixed Precision）的核心思想是**在数值敏感处保留高精度、在计算密集处用低精度**，兼顾速度与稳定。

## 二、核心原理

标准混合精度把参数、梯度、优化器状态分成两类：(1) **主权重（master weights）保持 FP32**，用于累积更新避免舍入误差；(2) **前向/反向用 FP16/BF16** 计算，加速矩阵乘与降低带宽。FP16 方案需 **loss scaling**：把损失乘以大系数 $S$ 提升梯度幅值，反向后再除回，防止下溢；而 **BF16**（8 位指数，与 FP32 同指数范围）几乎不需要 scaling，成为现代首选。此外，归约（softmax、loss）常在 FP32 进行以保数值稳定。

## 三、形式化与数学基础

FP16 为 1 符号 + 5 指数 + 10 尾数，动态范围约 $[6\times10^{-8}, 65504]$；BF16 为 1 + 8 指数 + 7 尾数，范围与 FP32 一致，精度更低。loss scaling 形式：

$$\tilde{\mathcal{L}} = S \cdot \mathcal{L},\quad \tilde g = S \cdot g,\quad g = \text{div}(\tilde g, S)$$

若 $\tilde g$ 仍下溢（低于 FP16 最小正规数），该梯度置零。动态 scaling 会监控溢出步数：连续 $N$ 步无 Inf/NaN 则 $S \leftarrow S\cdot 2$，出现溢出则 $S \leftarrow S/2$ 并跳过该步。BF16 因指数范围宽，可省去此机制：

$$\text{BF16}(x) = \text{round\_to\_7\_mantissa}(\text{FP32}(x))$$

## 四、代码实现

```python
import torch
scaler = torch.amp.GradScaler()          # FP16 需；BF16 可省略
model, opt = model.cuda(), optimizer

for x, y in loader:
    x, y = x.cuda(), y.cuda()
    opt.zero_grad()
    with torch.amp.autocast(device_type="cuda", dtype=torch.bfloat16):
        loss = model(x, y).loss
    scaler.scale(loss).backward()        # FP16 防下溢
    scaler.step(opt)
    scaler.update()
```

HuggingFace 中只需 `fp16=True` 或 `bf16=True`（Trainer 自动处理），并推荐 Ampere 及以后架构用 BF16。

## 五、与其他精度方案对比

| 方案 | 范围 | 需 scaling | 算力 | 适用 |
|---|---|---|---|---|
| FP32 | 大 | 否 | 低 | 调试基线 |
| FP16 + AMP | 窄 | 是 | 高 | 旧架构 |
| BF16 | 大 | 否 | 高 | 现代默认 |
| FP8 | 窄 | 是 | 最高 | H100+ 推理/训练 |

## 六、常见误区

- 认为 BF16 也需 loss scaling：BF16 范围同 FP32，通常不需要。
- 全程 FP16 不用 scaling：梯度下溢，loss 不降。
- 把 LayerNorm/Embedding 也压成 FP16：归约操作留 FP32 更稳。
- 旧 GPU 强制 BF16：缺乏 Tensor Core BF16 支持时收益有限。

## 八、面试题

1. 为何 BF16 比 FP16 更适合训练？答：BF16 指数位与 FP32 相同，动态范围大，几乎不溢出/下溢，免 loss scaling。
2. FP16 为何要 loss scaling？答：提升梯度幅值防下溢为 0。
3. 哪些操作应留在 FP32？答：归约、softmax、loss 计算、优化器状态。

## 九、演进与趋势

FP8（E4M3/E5M2）已在 H100/H200 上进入训练与推理，进一步省带宽；FP8 需更精细的 scaling 与逐张量（per-tensor）量化。未来还有 MXFP6/MXFP4 微缩放格式，配合硬件降低大模型训练与推理成本，但 BF16 仍是当前最稳的默认选择。

## 十、小结

混合精度是降本提速的基石：用 BF16 作主精度、FP32 保关键归约与优化器状态，是现代训练默认配置。理解 FP16/BF16 的数值范围差异与 loss scaling 原理，才能在速度与稳定之间拿到最优解。
