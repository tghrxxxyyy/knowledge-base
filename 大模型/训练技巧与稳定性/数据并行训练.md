# 数据并行训练

> 对应 PyTorch DistributedDataParallel (DDP) 文档、Microsoft DeepSpeed / ZeRO 论文（Rajbhandari et al., 2020）；参考 Megatron-LM。

## 一、背景与挑战

单个加速卡即使有 80GB 显存，也放不下数十亿乃至数千亿参数的模型与优化器状态，更无法在合理时间内处理海量训练数据。数据并行（Data Parallelism, DP）是最直观的横向扩展手段：把训练数据切分到多张卡，每张卡持有完整模型副本，各自算梯度后同步。核心挑战在于：梯度同步的通信开销、多卡状态一致性，以及当模型本身大到单卡放不下时，单纯数据并行已无能为力，需与张量/流水并行、ZeRO 显存优化组合。

## 二、核心原理

经典数据并行流程：每个 rank（进程）载入同一份模型权重与优化器状态；每个 step 各自取一个 mini-batch 前向/反向得到梯度；通过集合通信 `AllReduce` 把所有卡梯度求平均；各卡用平均梯度独立更新，因初始一致且更新一致，参数始终保持同步。PyTorch 的 DDP 在反向时即触发梯度分桶（bucketing）异步 AllReduce，隐藏通信延迟；DeepSpeed ZeRO 进一步把优化器状态、梯度、参数分片到各卡，以通信换显存。

## 三、形式化与数学基础

设 $K$ 个副本，第 $k$ 卡数据为 $\mathcal{B}_k$，单卡损失 $L_k(\theta)=\frac{1}{|\mathcal{B}_k|}\sum_{x\in\mathcal{B}_k}\ell(x;\theta)$，总目标为各卡平均：

$$L(\theta)=\frac{1}{K}\sum_{k=1}^{K} L_k(\theta)$$

梯度满足：

$$g = \nabla_\theta L = \frac{1}{K}\sum_{k=1}^{K} \nabla_\theta L_k = \text{AllReduce}_{\text{mean}}(g_1,\dots,g_K)$$

AllReduce 朴素实现为「先 Reduce 再 Broadcast」，$K$ 卡每卡收发 $2(K-1)\cdot |\theta|$ 字节；Ring AllReduce 将其降为 $\frac{2(K-1)}{K}\cdot |\theta|$，与卡数无关，仅取决于参数总量。

## 四、代码实现

```python
import torch
import torch.distributed as dist
from torch.nn.parallel import DistributedDataParallel as DDP

dist.init_process_group(backend="nccl")
rank, world = dist.get_rank(), dist.get_world_size()
torch.cuda.set_device(rank)

model = MyTransformer().cuda(rank)
model = DDP(model, device_ids=[rank])          # 反向时自动 AllReduce
sampler = torch.utils.data.distributed.DistributedSampler(
    dataset, num_replicas=world, rank=rank)
loader = DataLoader(dataset, sampler=sampler, batch_size=8)

for x, y in loader:
    x, y = x.cuda(rank), y.cuda(rank)
    optimizer.zero_grad()
    loss = model(x, y).loss
    loss.backward()        # DDP 在此触发梯度同步
    optimizer.step()
```

## 五、与其他并行策略对比

| 策略 | 切分对象 | 通信量 | 适用瓶颈 |
|---|---|---|---|
| 数据并行 | 数据 | 梯度 $O(P)$ | 算力不足、显存够 |
| 张量并行 | 层内权重 | 层间激活 $O(P)$ | 单层过大 |
| 流水并行 | 跨层 | 层间激活 | 模型过深 |
| ZeRO(DP 增强) | 状态分片 | 略增 | 显存不足 |

数据并行最易上手，常与 ZeRO 结合；超大模型再叠加 TP/PP 构成 3D 并行。

## 六、常见误区

- 认为数据并行能解决显存不足：单卡仍需放下整模型，显存不够要用 ZeRO/TP/PP。
- 忘记 `DistributedSampler`：各卡读到相同数据，等效减小 batch 多样性。
- 以为 DDP 自动加速 $K$ 倍：通信与负载不均使其略低于线性加速比。
- 在 `loss.backward()` 后手动 AllReduce：DDP 已内置，重复同步会出错。

## 八、面试题

1. 数据并行的通信瓶颈在哪？答：梯度 AllReduce，量正比于参数量，用 Ring AllReduce 消去卡数因子。
2. DDP 与旧 DataParallel 区别？答：DDP 多进程、每卡一副本、梯度异步同步，效率高且无 GIL。
3. 模型太大单卡放不下怎么办？答：引入 ZeRO 分片 + 张量/流水并行。

## 九、演进与趋势

从 Parameter Server 到 Horovod 的 AllReduce，再到 DDP 的梯度 bucketing 与 DeepSpeed ZeRO 三级分片（ZeRO-1/2/3），数据并行已从「简单复制」演进为「状态分片 + 通信重叠」。未来趋势是零冗余与通信压缩（如梯度量化、异步通信）进一步逼近线性扩展效率。

## 十、小结

数据并行是分布式训练的第一块基石，原理清晰、落地简单；真正的工程难点在显存与通信的权衡——当单卡装不下模型时，必须让数据并行与 ZeRO、张量/流水并行协同，才能把规模推向上千亿参数。
