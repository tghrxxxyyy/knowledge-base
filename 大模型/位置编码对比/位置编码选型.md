# 位置编码选型指南

> 工程决策参考；综合 Vaswani et al. 2017、Su et al. 2021 (RoPE)、Press et al. 2022 (ALiBi)、Raffel et al. 2020 (T5) 等位置编码方案。

## 一、背景与挑战

位置编码是 Transformer 的「顺序开关」：自注意力本身置换不变，必须注入顺序信息才能理解序列。不同下游任务、不同模型形态（编码器/解码器/统一模型）、不同长度需求，对位置编码的敏感性截然不同。选错会导致外推失败、长上下文崩塌或训练不稳。

选型的核心权衡维度：**外推能力**（训练短能否推理长）、**实现复杂度**、**参数开销**、**与任务匹配**（理解型 vs 生成型）。

## 二、核心原理

位置编码可归为四类路线：

1. **可学习绝对编码**：训练时学 $P\in\mathbb{R}^{L\times d}$，简单但长度固定、难外推。
2. **正弦绝对编码**：固定公式注入，可外推但有限，无需参数。
3. **相对偏置编码**：T5 把相对距离作为注意力偏置，利于理解；ALiBi 用线性偏置，天然外推。
4. **旋转编码（RoPE）**：相对距离编码进 Q/K 内积，生成模型主流，外推靠 base/NTK。

选型即按「任务类型 + 长度需求 + 实现成本」映射到上述路线。

实战决策清单可归纳为四问：是否生成长文本（决定 RoPE/ALiBi）、是否编码器且仅短序列（可用绝对）、团队是否熟悉某编码的内核修改（决定 ALiBi 落地成本）、下游是否需微调以换更强外推（决定 YaRN）。有明确长上下文目标的通用 LLM，优先 RoPE+NTK/YaRN；追求开箱即用的强外推且不愿调参，选 ALiBi；纯 NLU 编码器用可学习绝对或 T5 偏置最省心。

## 三、形式化与数学基础

设序列长度 $L_{train}$ 与期望 $L_{test}$。外推余量 $\eta = L_{test}/L_{train}$。各方案对 $\eta$ 的容忍：

$$
\eta_{\text{abs}} \approx 1,\quad \eta_{\text{sine}} \lesssim 1.5,\quad \eta_{\text{ALiBi}} \gg 1,\quad \eta_{\text{RoPE+NTK}} \gg 1
$$

即绝对类几乎不可外推，RoPE/ALiBi 经处理可大幅外推。理论容量上，RoPE 以 $d/2$ 个频率覆盖相对距离，分辨率由 base 决定。

## 四、代码实现

按场景选择编码的精简判断：

```python
def choose_pos_enc(task, need_extrapolate, is_encoder):
    if is_encoder and not need_extrapolate:
        return "learned_absolute"          # NLU 简单够用
    if need_extrapolate and task == "gen":
        return "rope"                      # 生成+长上下文
    if need_extrapolate and task == "cheap":
        return "alibi"                     # 强外推省调参
    return "relative_bias"                 # T5 类理解
```

## 五、与其他技术对比

| 场景 | 推荐 | 理由 | 不推荐 |
|------|------|------|--------|
| 通用生成 LLM | RoPE | 可外推+主流生态 | 绝对编码 |
| 强外推不调参 | ALiBi | 天然外推 | 正弦 |
| 编码器 NLU | 可学习绝对/T5 | 长度固定、理解强 | RoPE(重) |
| 长上下文检索 | RoPE+NTK/YaRN | 显式外推 | 绝对 |

## 六、常见误区

- **「一种编码通吃」**：生成与理解、长与短需求不同，应分场景。
- **「外推总能白嫖」**：绝对编码外推极弱，RoPE 也需调基频。
- **「编码器也要 RoPE」**：NLU 长度固定，简单绝对或 T5 偏置更划算。
- **忽视实现成本**：ALiBi 省调参但需改注意力内核，RoPE 生态最成熟。

## 九、演进与趋势

位置编码正从「训练期固定」走向「外推可配置」：RoPE+NTK/YaRN 与 ALiBi 成为长上下文两大路线，且常与训练期长度课程协同。未来趋势是把外推作为架构默认能力，并在统一多模态模型中复用同一套相对编码。

## 十、小结

位置编码是架构关键开关，选型应据任务类型、长度需求与实现成本：通用生成选 RoPE，强外推省调参选 ALiBi，编码器 NLU 用绝对/T5。配齐外推处理才能稳住长上下文。

补充经验：同一底座在预训练阶段选定编码后切换成本极高，故选型应在架构设计早期完成；若事后发现外推不足，RoPE 系可通过 NTK/YaRN 事后补救，而绝对编码几乎只能重训，这也是当代新模型普遍默认 RoPE 的隐性原因。
