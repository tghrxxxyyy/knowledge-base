# 金融应用场景

> 对应 llm-universe（datawhale）金融 NLP 实践、FinGPT 金融大模型；参考 llm-course (mlabonne)。

## 一、背景与挑战

金融是对时效、准确、合规极度敏感的高价值垂直领域。机构每天要处理海量文本：公告、新闻、财报、研报、客服对话、合规文档。通用大模型虽能处理自然语言，但缺乏金融语义、实时数据与合规模板，直接套用常出现「一本正经地出错」。核心挑战：

- 时效性强：行情、政策瞬息万变，模型需接实时数据而非训练快照。
- 准确性要求高：数字、条款、法律结论不容幻觉。
- 合规必带：任何对外内容需风险提示与免责，并保留来源。
- 领域语义深：金融术语、监管口径、产品规则需要专门知识。

## 二、核心原理

金融 LLM 应用多为「检索增强生成（RAG）+ 工具调用 + 护栏」的落地形态：

1. 信息抽取：从公告/新闻/财报抽取实体、事件、数值与关系。
2. 情感与风险判别：结合金融情感模型给出信号与风险分。
3. 研报/合规生成：基于实时数据按模板产出初稿，强制引用来源与风险提示。
4. 智能客服/投顾：接知识库与合规策略，回答受约束、可留痕。
5. 代码辅助：把量化策略想法转为回测脚本。

关键共性是用 RAG 把模型「接上」权威实时数据，用护栏把输出「框在」合规边界内。

（落地补充：）
- 实践中常「领域小模型 + 通用大模型」分工：小模型做高精度抽取分类。
- 通用大模型负责生成与对话，二者经 RAG 共享实时证据，兼顾成本与可控。

## 三、形式化与数学基础

RAG 场景下，给定查询 $q$，先检索相关文档集合 $D_q = \{d_1,\dots,d_k\}$，再条件生成：

$$ P(y \mid q) = \sum_{d\in D_q} P(d\mid q)\, P(y\mid q,d) $$

为降低幻觉，常约束生成仅基于检索证据，用忠实度度量：

$$ \text{Faithfulness} = \frac{|\text{claims}(y) \cap \text{supported}(D_q)|}{|\text{claims}(y)|} $$

贴近 1 表示回答基本可由证据支撑。

## 四、代码实现

# 金融场景典型链路：检索证据 -> 抽取事件 -> 风险打分
def financial_pipeline(news, retriever, extractor, scorer):
    docs = retriever.search(news, top_k=5)        # 接实时/权威库
    events = extractor.extract(docs)              # 实体与事件抽取
    risk = scorer.score(events)                   # 风险/情感打分
    return events, risk

## 五、与其他技术对比

## 六、常见误区

- 「模型给投资建议即决策」：必须有人审与风控闸，建议不等于决策。
- 「通用模型直接上金融」：缺领域知识与合规框架，易错且违规。
- 「忽略数据时效」：用训练快照回答实时问题会严重失真。
- 「不留存来源」：对外内容无引用与留痕，难追责。

## 十、小结

金融是 LLM 的高价值垂直领域。以 RAG 接实时权威数据、以护栏保合规，可在研报、投顾、风控、合规、量化等场景释放价值，同时把幻觉与违规风险控制在可接受范围。
