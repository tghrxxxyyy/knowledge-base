# 监管与披露

> 对应 国家网信办《生成式人工智能服务管理暂行办法》、算法备案与登记要求、OWASP LLM Top 10（LLM10 训练数据合规 / LLM05 供应链风险）；参考 llm-course (mlabonne)。

## 一、背景与挑战

金融是强监管行业，银行、证券、保险、基金等机构的模型决策直接关系到投资者权益与系统性风险。当大模型被用于投顾建议、信贷审批、研报生成、智能客服等场景时，监管者要求「可审计、可解释、可追责」，这与大模型天然的概率生成、黑盒特性存在张力。典型挑战包括：

- 算法需备案/登记：提供方须说明训练数据来源、模型用途、安全防护措施与适用范围。
- 决策需可解释：信贷拒贷、风控拦截等须向用户与监管给出可理解依据。
- 输出需防误导：投资建议、预测类内容须带风险提示与免责声明。
- 数据合规：训练与微调数据须来源合法，涉及个人信息须最小必要并脱敏。
- 全程留痕：日志、模型版本、数据 lineage 需可追溯、可报送、防篡改。

## 二、核心原理

监管披露的本质是把「模型的不透明行为」转化为「可验证的客观记录」。核心做法分三层：

1. 模型与数据登记：维护模型卡片（model card）与数据卡片（datasheet），记录版本、参数量、训练语料范围、微调数据、评测结果与已知局限。
2. 决策溯源：对每一次影响用户的输出，记录输入、模型版本、关键特征/检索证据、生成理由、复核人，形成不可篡改的审计链。
3. 输出治理：对建议、预测、合规结论类输出强制附加来源引用与风险提示；对敏感场景引入人在回路（human-in-the-loop）复核。

三者共同构成「事前备案、事中留痕、事后可查」的监管闭环。

## 三、形式化与数学基础

把一次模型决策记为五元组 $(x, m, e, y, r)$，其中 $x$ 为输入，$m$ 为模型版本，$e$ 为支撑证据（检索片段或特征），$y$ 为输出，$r$ 为理由。披露的完整度定义为被完整记录的决策占比：

$$ C = \frac{1}{N}\sum_{i=1}^{N} \mathbb{I}\big(\text{trace}(x_i,m_i,e_i,y_i,r_i)\ \text{齐全且可回溯}\big) $$

监管目标常要求 $C \to 1$。对可解释性，可用局部代理 $y \approx g(x)$ 的保真度衡量：

$$ F = 1 - \frac{1}{N}\sum_{i=1}^{N}\frac{|y_i - g(x_i)|}{\max_j |y_j|} $$

$F$ 越接近 1，给出的解释越可信。

# 记录一次模型决策的完整溯源链
from dataclasses import dataclass, asdict
import hashlib, time

@dataclass
class AuditRecord:
    req_id: str
    model_ver: str
    input_hash: str
    evidence: list
    output: str
    rationale: str
    reviewer: str
    ts: float

def audit_record(model_ver, req, out, rationale, evidence, reviewer):
    rec = AuditRecord(
        req_id=req.id,
        model_ver=model_ver,
        input_hash=hashlib.sha256(req.text.encode()).hexdigest(),
        evidence=[e.id for e in evidence],
        output=out,
        rationale=rationale,
        reviewer=reviewer,
        ts=time.time(),
    )
    store.append(asdict(rec))  # 落库并打水印，供监管报送与回溯
    return rec

def render_with_disclaimer(out, risk_note):
    # 敏感输出强制附加风险提示
    return f"{out}\n\n风险提示：{risk_note}（本内容不构成投资建议）"

## 五、与其他技术对比

| 维度 | 通用消费级应用 | 金融大模型应用 |
| --- | --- | --- |
| 可审计要求 | 低，事后追溯即可 | 高，事前备案 + 全程留痕 |
| 可解释要求 | 可选 | 强制，尤其信贷/风控 |
| 输出治理 | 一般内容过滤 | 强制风险提示与免责 |
| 数据合规 | 通用隐私法 | 叠加金融与个保双重要求 |
| 人在回路 | 少见 | 高风险场景必需 |

## 六、常见误区

- 「黑盒也能上线」：金融强监管下，无解释、无留痕的决策不可接受。
- 「备案一次就够」：模型迭代、数据变更需持续更新登记与评测。
- 「生成带免责即免责」：免责声明不能替代可解释与可复核。
- 「只看准确率」：忽略公平性、稳定性与对抗鲁棒性同样会被监管质疑。

## 九、演进与趋势

从「无规可用」到「日志留痕」再到「全链路审计」；趋势是自动生成合规报告、模型卡片标准化（OECD、行业自律准则）、监管沙盒试点，以及把披露能力内建到推理管线（可观测性 + 水印 + 证据绑定）。

## 十、小结

监管与披露是金融大模型的「生命线」。把不透明的概率生成，转化为可登记、可留痕、可解释、可追责的客观记录，是金融 AI 落地的硬性前提，也是技术团队必须内建的一等能力。
