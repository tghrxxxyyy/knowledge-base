# 风控与反欺诈

> 对应 金融风控实践（规则 + 图模型 + 模型融合）、OWASP LLM Top 10（LLM01 提示注入 / LLM06 过度依赖）；参考 llm-course (mlabonne)。

## 一、背景与挑战

金融欺诈手段持续演化：电信诈骗、洗钱链路、虚假交易、骗贷、舆情操纵等往往以文本（投诉、交易备注、聊天记录）和行为混合形态出现。传统规则系统面对新型话术与长尾模式反应滞后，而纯模型又面临可解释与误杀/漏杀的两难。核心挑战：

- 欺诈多变：话术与链路快速翻新，规则易过时。
- 文本信号弱：备注、客诉中风险信息稀疏且隐晦。
- 误杀与漏杀需平衡：过严伤害体验，过松放大损失。
- 监管可解释：拦截决策须能向用户与监管说明原因。

## 二、核心原理

LLM 在风控中承担「语义理解 + 风险推理」角色，而非替代既有系统。典型架构是三层融合：

1. 文本理解层：用 LLM 解析投诉、交易备注、舆情，抽取风险实体（账户、金额、对手、话术类型）与可疑意图。
2. 图与规则层：把实体接入关系图与既有规则，计算关联风险分（如共谋账户、资金闭环）。
3. 决策层：融合多源分数，输出风险等级，并对高风险样本触发人工复核（人在回路）。

模型输出不应直接拦截，而是作为「风险证据」进入可解释的合规模板。

（落地补充：）
- 风控 LLM 应置于「只读分析」位，只产出风险证据与可疑度，不直接拦截。
- 真实拦截/放行由规则引擎与人工在回路决定，便于审计每条结论来源。
- 对可疑样本保留申诉通道，避免误杀带来的客诉与体验损失。

## 三、形式化与数学基础

设文本经 LLM 编码得到风险表征 $h = \text{Enc}(t)$，其与已知欺诈原型 $p_k$ 的相似度给出话术风险：

$$ s_{\text{text}} = \max_k \frac{h^\top p_k}{\|h\|\|p_k\|} $$

最终风险为加权融合：

$$ R = \alpha\, s_{\text{text}} + \beta\, s_{\text{graph}} + \gamma\, s_{\text{rule}} $$

当 $R > \tau_{\text{block}}$ 直接拦截，$\tau_{\text{review}} < R \le \tau_{\text{block}}$ 转人工复核，以平衡误杀与漏杀。

## 四、代码实现

```python
# LLM 解析交易备注，融合图分数给出风险等级
def score_transaction(note, graph, rules, tau_review=0.4, tau_block=0.8):
    h = llm.encode(note)                       # 文本风险表征
    s_text = max(cosine(h, p) for p in fraud_prototypes)
    s_graph = graph.risk(note.account)         # 关系图分数
    s_rule = rules.match(note)                 # 规则命中分数
    R = 0.4 * s_text + 0.4 * s_graph + 0.2 * s_rule
    if R > tau_block:
        return "block", R, explain(note, h)
    if R > tau_review:
        return "review", R, explain(note, h)   # 转人工复核
    return "pass", R, None

label, score, reason = score_transaction(note, graph, rules)
```

## 五、与其他技术对比

| 维度 | 纯规则 | 纯模型 | LLM + 图融合 |

## 六、常见误区

- 「模型判风险即拦截」：应保留复核与申诉通道，避免误杀客诉。
- 「只信文本」：忽略行为与关系图会漏掉团伙欺诈。
- 「提示注入」：欺诈者可能诱导风控 LLM 误判，需输入净化与权限隔离。
- 「过度依赖模型」：违反 OWASP LLM06，关键拦截须有人兜底。

从「规则」到「模型」再到「人机协同」；趋势是多模态风控（文本 + 图像 + 行为）、实时图计算、以及对风控 LLM 自身的对抗鲁棒评测。

## 十、小结

风控与反欺诈是金融 LLM 的刚需场景。把 LLM 作为语义理解的证据来源，与图模型、规则、人工复核融合，可兼顾灵活性与可解释，避免误杀与过度依赖。
