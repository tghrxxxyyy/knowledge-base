# 金融评测基准

> 对应 FinanceBench、FinGPT Bench、CFBenchmark 等金融评测集；参考 llm-course (mlabonne) 与 lm-evaluation-harness。

## 一、背景与挑战

通用基准（MMLU、HellaSwag 等）无法反映模型在金融任务上的真实能力：金融文本含大量数值推理、监管判断、长文档理解与领域术语，通用高分模型在金融场景可能「不及格」。核心挑战：

- 领域覆盖：需覆盖金融知识、数值推理、合规判断、多语言。
- 数值推理短板：大模型常在计算、单位换算、表格理解上出错。
- 数据污染：训练数据可能已包含公开基准，需防泄漏导致虚高。
- 任务真实：评测应贴近真实业务（研报问答、公告抽取），而非玩具题。

## 二、核心原理

金融基准通常由「题项 + 标准答案 + 评分器」组成，按能力维度切分：

1. 知识类：金融概念、法规、产品规则的选择/问答。
2. 推理类：基于财报/公告的数值计算与逻辑推断。
3. 合规类：判断某行为是否合规、给出依据。
4. 抽取类：从长文档抽取实体/事件/数值的准确率。

评测结果用领域加权总分与分项拆解呈现，避免被某单项掩盖短板。结合 lm-evaluation-harness 可标准化跑分与复现。

（落地补充：）
- 建议把基准拆为「能力卡」，每项独立跑分并附置信区间。
- 迭代时只看变化的分项，避免被总分掩盖回归。
- 数值推理题项需区分「最终答案正确」与「过程合理」。
- 对公开基准做留题验证，防训练数据污染导致的虚高。

## 三、形式化与数学基础

设基准含 $K$ 个能力维度，维度 $k$ 权重 $w_k$（$\sum w_k = 1$），模型在该维度准确率为 $a_k$，则领域总分：

$$ S = \sum_{k=1}^{K} w_k\, a_k $$

为缓解污染，用 $n$ 次重采样下的方差与「留题验证集」估计稳定性：

$$ \hat{S} = \frac{1}{n}\sum_{i=1}^{n} S_i,\quad \text{CI} = \hat{S} \pm 1.96\,\frac{\sigma_S}{\sqrt{n}} $$

置信区间宽说明分数不可靠，需警惕。

## 四、代码实现

```python
# 用 lm-evaluation-harness 跑金融基准（示意）
from lm_eval import simple_evaluate

res = simple_evaluate(
    model="fin-gpt-v2",
    tasks=["financebench_qa", "cfbench_reasoning"],
    num_fewshot=0,
    device="cuda:0",
)
# 输出各维度准确率与总分
for task, metrics in res["results"].items():
    print(task, metrics["acc"], metrics.get("acc_stderr"))
```

## 五、与其他技术对比

| 维度 | 通用基准 | 金融领域基准 |
| --- | --- | --- |
| 覆盖 | 广而浅 | 窄而深 |
| 数值推理 | 弱项暴露少 | 重点测 |
| 合规 | 不涉及 | 核心维度 |
| 污染风险 | 高（公开） | 需私有/动态集 |

## 六、常见误区

- 「通用高分 = 金融可用」：领域数值与合规能力常被通用分掩盖。
- 「只看总分」：分项短板（如推理）在实盘会放大。
- 「忽视污染」：公开基准可能已被训练数据包含，分数虚高。
- 「静态基准」：市场与法规变化使旧基准失效，需动态更新。

## 九、演进与趋势

从「通用基准」到「领域基准」再到「实时任务评测」；趋势是动态/私有基准、agent 化任务（多步检索+推理）、以及把合规与安全纳入评测。

## 十、小结

领域基准是金融 LLM 可用性的保障。用加权多维评测、控制污染、贴近真实任务，才能甄别模型在金融场景的真实能力，避免通用高分带来的误判。
