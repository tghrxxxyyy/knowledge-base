# 研报与合规生成

> 对应 llm-universe（datawhale）文档生成实践、RAG 生成范式；参考 llm-course (mlabonne) 与 dair-ai Prompt Engineering Guide。

## 一、背景与挑战

研究报告要求数据准确、引用规范、措辞合规、结论可复核。人工撰写耗时且易在海量数据中遗漏要点；用 LLM 自动生成虽快，但一旦「幻觉」出不存在的数据或遗漏风险提示，对外发布将带来合规与声誉风险。核心挑战：

- 数据准确：引用的行情、财务数字必须可核、可溯源。
- 引用规范：观点与数据须标注来源，禁止编造出处。
- 措辞合规：投资建议、预测须带免责与风险提示。
- 防幻觉：模型可能生成看似合理但错误的事实。
- 人工责任：发布前仍需分析师复核与署名。

## 二、核心原理

研报生成采用「数据绑定 + 模板约束 + 引用强制 + 人工复核」的管线：

1. 数据接入：从行情、财报、公告等权威源拉取实时数据，作为生成的唯一事实底座。
2. 结构化大纲：按「宏观/行业/公司/估值/风险」模板组织，保证覆盖完整。
3. 证据约束生成：每段结论必须绑定检索到的证据块，超界表述被禁止（grounded generation）。
4. 合规注入：自动追加免责声明、风险提示、数据时点。
5. 人工复核：分析师核对事实、口径与合规后署名发布。

本质是「模型写初稿，证据做背书，人做终审」。

（落地补充：）
- 机构常把研报生成接进内容中台，模型只产带引用的草稿。
- 合规系统自动校验免责/风险/时点是否齐全，未过则退回补充。
- 整条链路全程留痕，既提速又让合规可审计、可追责。

## 三、形式化与数学基础

把生成视为在证据约束下的条件概率，要求每个声明 $c_j$ 都能在证据集 $E$ 中找到支撑：

$$ P(y\mid q, E) = \prod_{j} P(c_j \mid q, E),\quad \text{其中 } \forall j,\ \text{support}(c_j)\subseteq E $$

忠实度（不编造）度量：

$$ F = \frac{|\{c_j: \text{support}(c_j)\neq\varnothing\}|}{|\{c_j\}|} $$

$F=1$ 表示无一句无据。合规完整度 $G$ 衡量免责/风险/时点是否齐全，目标 $G\to 1$。

## 四、代码实现

```python
# 基于实时数据生成研报初稿，强制证据与合规
def draft_report(data, retriever, llm, analyst):
    docs = retriever.search(data.facts, top_k=8)   # 权威证据
    prompt = build_section_prompt(data.ticker, docs)  # 含模板与禁编造指令
    draft = llm.generate(prompt, grounded=True)
    draft = attach_disclaimer(draft, risk_note=data.risk)  # 注入合规
    # 人工复核后才发布，analyst 署名
    return human_review(draft, by=analyst)

def attach_disclaimer(text, risk_note):
    return text + f"\n\n风险提示：{risk_note}（本研报仅供参考，不构成投资建议）"
```

## 五、与其他技术对比

| 维度 | 通用写作 | 研报合规生成 |
| --- | --- | --- |
| 事实底座 | 记忆（易错） | 实时数据绑定 |
| 引用 | 无强制 | 每段须有证据 |
| 合规 | 无 | 免责/风险必带 |
| 责任 | 无 | 人工复核署名 |

## 六、常见误区

- 「自动生成即发布」：必须人工复核与署名，模型不担责。
- 「模型补数据」：缺失数据应标「暂无」而非编造。
- 「忽略时点」：不标数据日期会让结论失真。
- 「模板僵化」：纯模板失去洞察，需人机协作保质量。

## 九、演进与趋势

从「模板填空」到「摘要抽取」再到「数据驱动生成」；趋势是多模态研报（图+表+文）、自动证据链可视化、以及把合规检查内建为生成约束。

## 十、小结

研报与合规生成的关键在于「证据绑定 + 合规护栏 + 人工终审」。让模型在数据底座上写初稿、用引用与风险提示框住边界、由分析师把关，才能在提效的同时守住合规底线。
