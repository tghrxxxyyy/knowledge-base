# 量化策略辅助

> 对应 QuantConnect / Lean 回测引擎、Backtrader 量化框架；参考 llm-course (mlabonne) 与 dair-ai Prompt Engineering Guide。

## 一、背景与挑战

量化投研的典型路径是「想法 → 因子/信号 → 回测脚本 → 调参 → 实盘」。其中从自然语言策略到可运行回测代码往往占去大量时间，且需要跨域知识（金融 + 工程）。大模型的代码生成与推理能力可以显著降低这条路径的门槛，但金融场景对正确性、可复现、防过拟合要求极高，用错一行代码或误解一个指标都可能造成实盘亏损。核心挑战：

- 自然语言歧义：策略描述到代码存在多义映射。
- 回测过拟合：LLM 生成的策略可能在历史数据上「看起来很好」。
- 不可复现：随机种子、数据切片、手续费假设常被遗漏。
- 合规边界：自动生成的策略仍需研究者负责与人工验证。

## 二、核心原理

把 LLM 定位为「策略实现加速器」而非「决策主体」。工作流为：

1. 意图澄清：用结构化提示让模型输出因子定义、信号逻辑、调仓规则的伪代码或配置。
2. 代码生成：结合领域代码模型（如 FinGPT-Code 思路）生成回测脚本，自动注入数据加载、手续费、滑点、基准等标准模块。
3. 受控执行：在隔离环境跑回测，强制固定随机种子与数据区间，输出绩效与诊断。
4. 人工验证：研究者核对信号口径、排查幸存者偏差与前视泄漏（look-ahead bias），再决定是否入场。

关键是把「生成」与「验证」解耦，模型负责提速，人负责把关。

## 三、形式化与数学基础

策略信号可写为关于特征向量 $x_t$ 的函数 $s_t = f_\theta(x_t)$。回测用历史收益 $r_t$ 估计策略净值：

$$ P_T = \prod_{t=1}^{T}\big(1 + s_t \cdot r_t - c(s_t)\big) $$

其中 $c(s_t)$ 为交易成本。过拟合风险可用「回填倍数」（backtest overfitting probability）刻画，简化用夏普比率的过拟合惩罚：

$$ \hat{\theta}^* = \arg\max_\theta \frac{\bar{r}_s}{\sigma_s} - \lambda \cdot \text{deg}(f_\theta) $$

$\lambda$ 越大，越抑制复杂度的过拟合。

## 四、代码实现

```python
# 用 LLM 把自然语言策略翻译为回测骨架，再受控执行
from quantconnect import QCAlgorithm

def build_strategy(prompt):
    # 让模型输出因子与调仓规则（伪代码/配置），而非直接跑实盘
    spec = llm.generate(f"把策略转为回测配置:{prompt}", json_mode=True)
    return spec

def run_backtest(spec, seed=42):
    qc = QCAlgorithm()
    qc.set_seed(seed)              # 强制可复现
    qc.add_costs(slippage=0.001)   # 注入真实成本假设
    qc.load(spec.factors)
    report = qc.backtest()
    # 输出夏普、最大回撤、过拟合诊断
    return report.sharpe, report.max_drawdown, report.leakage_check()

spec = build_strategy("均线金叉 + 成交量过滤，日频调仓")
sharpe, mdd, leak = run_backtest(spec)
print(sharpe, mdd, leak)  # 人工核对后再决定是否上实盘
```

## 五、与其他技术对比

| 维度 | 研究者手写 | LLM 辅助生成 |
| --- | --- | --- |
| 速度 | 慢，需跨域知识 | 快，分钟级出骨架 |
| 正确率 | 依赖个人经验 | 需人工核对口径 |
| 可复现 | 易遗漏假设 | 可强制注入标准模块 |
| 过拟合风险 | 人为可控 | 更易堆砌复杂策略 |

## 六、常见误区

- 「回测好 = 实盘好」：历史拟合不保证未来，需样本外与 Walk-forward 验证。
- 「让模型直接下单」：策略决策必须有人把关与风控闸。
- 「忽略成本假设」：无手续费/滑点的回测严重失真。
- 「前视泄漏」：用了未来信息（如当天收盘价做当天信号）是常见坑。

## 九、演进与趋势

从「手写指标」到「库调用」再到「自然语言生成策略」；趋势是多智能体分工（想法代理、代码代理、审计代理）、自动 Walk-forward 验证、以及把 LLM 嵌入研究平台形成闭环。

## 十、小结

LLM 在量化中的定位是「提效的副驾」而非「自动驾驶」。通过生成与验证解耦、强制可复现与成本假设、人工核对口径，可在不放大风险的前提下显著加速策略研发。
