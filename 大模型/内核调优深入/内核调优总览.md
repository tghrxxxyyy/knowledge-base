# 内核调优总览

> 对应 Volkov, *Better Performance through the Roofline Model*, 2010（GPU 性能方法论）；与 算子融合深入 衔接。

## 一、背景与挑战

同样的算法在不同 kernel 实现下可差数倍，需系统性调优而非盲目试错。

## 二、核心原理

从 roofline 出发，先判定算力/带宽瓶颈，再针对瓶颈调：访存受限优化访存（合并/共享内存），算力受限优化指令（FP16/Tensor Core）。

## 三、数学形式

占用率 $\text{Occupancy}=\frac{\text{active warps}}{\text{max warps per SM}}$；有效带宽 $B_e=\frac{\text{bytes}}{\text{time}}$ 应逼近峰值 $\beta$。

## 四、代码实现

```python
cfg = triton.autotune([...], key=["M","N","K"])(kernel)
```

## 五、与其他对比

- 与 算子融合深入（融合减少访存）目标一致。
- 与 编译部署深入（自动调度）呼应。

## 六、常见误区

- 只看占用率忽略实际内存合并，高占用未必高吞吐。
- 过早用 Tensor Core 而数据未对齐。

## 九、演进

## 十、小结

内核调优以 roofline 为纲，先定位瓶颈再优化，避免凭直觉。
