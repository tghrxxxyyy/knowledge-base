# 多跳 RAG

> 对应 IRRAM、Self-Ask 与 Agentic RAG 多步检索范式；复杂问题的分步检索。

## 一、背景与挑战

单跳检索答不了需要**多步推理**的问题，例如「A 的作者的另一本书讲了什么？」「导致事故 X 的根本原因链是什么？」。这类问题无法用一次向量查询解决，因为其答案分散在多个文档、需先后检索并逐步推理。

核心难点：

- 首跳检索结果决定后续查询方向，首跳错了全盘错。
- 每跳都引入检索噪声与模型误差，错误会沿链路累积。
- 需「规划 + 改写 + 整合」的闭环，而非单次取 Top-k。

## 二、核心原理

多跳 RAG 以**迭代检索**为核心：

```
初始查询 q0 → 检索 → 子答案/证据 → 构造下一跳查询 q1 → 再检索 → … → 综合作答
```

关键能力：

- **查询规划**：把原问题分解为子问题(如 Self-Ask 的显式中间问)。
- **查询改写**：基于已得证据重写下一跳查询。
- **证据整合**：把各跳片段汇成连贯上下文再生成。
- **终止判定**：何时信息已充足可作答。

Agentic RAG 让 LLM 自主决定「查几次、查什么、何时停」。

## 三、形式化与数学基础

把多跳过程建模为状态转移。设第 $t$ 跳状态 $s_t=(q_t, E_t)$，其中 $E_t$ 为截至当前的证据集：

$$q_{t+1} = \mathrm{Plan}(q_0, E_t),\qquad E_{t+1}=E_t \cup \mathrm{Retrieve}(q_{t+1})$$

最终答案 $y=\mathrm{Generate}(q_0, E_T)$。误差随跳数累积：

$$P(\text{正确}) \approx \prod_{t=1}^{T} P(\text{第 }t\text{ 跳正确})$$

故跳数越多、单跳准确率越低，端到端正确率指数下降——这是多跳易错的量化根源。

## 四、代码实现

```python
def multi_hop(query, max_hops=3):
    evidence, q = [], query
    for _ in range(max_hops):
        ctx = vectordb.similarity_search(q, k=3)
        evidence += ctx
        # 让 LLM 判断是否足够，否则生成下一跳问题
        nxt = llm(f"已有证据：{evidence}\n还能直接作答吗？不能则只输出下一跳问题：{query}")
        if nxt.startswith("足够"):
            break
        q = nxt
    return llm(f"基于证据回答：{evidence}\n问题：{query}")
```

## 五、与其他技术对比

| 方式 | 跳数 | 错误累积 | 适用 |
|------|------|----------|------|
| 单跳 RAG | 1 | 无 | 事实点查 |
| 多跳 RAG | 多 | 有 | 推理/聚合 |
| GraphRAG | 图遍历 | 中 | 全局/关系 |

## 六、常见误区

- 首跳检索质量差却继续，错误一路放大。
- 不控制跳数上限，无限循环抬高成本。
- 各跳片段不整合，生成时上下文零散。
- 把多跳当默认，简单问题也应加重排即可。

## 九、演进与趋势

多跳正与 Agent 框架深度融合：模型自主规划检索步骤、调用工具、反思证据充分性。图谱 RAG 为其中「关系型多跳」提供结构化捷径，二者互补构成复杂问答的主流方案。

## 十、小结

多跳 RAG 以迭代检索应对需逐步推理的问题，但错误随跳数指数累积。工程关键在于提升单跳准确率、控制跳数、做好证据整合与终止判定；复杂关系类问题可结合 GraphRAG。
