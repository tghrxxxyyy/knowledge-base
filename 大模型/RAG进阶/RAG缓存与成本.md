# RAG 缓存与成本

> 对应 LLM 工程落地中的缓存策略与 vLLM/推理优化实践；降本增效的关键杠杆。

## 一、背景与挑战

RAG 每次请求都要走「嵌入查询 + 检索 + (重排) + LLM 生成」全流程，高频相似 query 会造成大量重复计算与 token 开销。在面向用户的场景里，成本与延迟直接决定能否规模化。

核心挑战：

- 相同/近义问题反复触发完整链路。
- 长上下文 + 大模型生成 token 成本高。
- 缓存命中若误判会返回错误答案(新鲜度/语义漂移)。
- 缓存无失效策略导致陈旧知识被长期复用。
- 个人/敏感 query 明文缓存引发合规风险。

成本结构通常是「检索便宜、生成贵」，因此生成侧缓存(语义缓存)与 prefill 缓存收益最大。

## 二、核心原理

三类缓存协同：

- **精确缓存(Exact Cache)**：对完全一致的 query(通常哈希)直接返回历史答案，零推理成本。
- **语义缓存(Semantic Cache)**：对语义相近 query(向量近邻)命中历史结果，需相似度阈值防误命中。
- **前缀缓存(Prefix Cache)**：缓存系统 prompt / 长上下文前缀的 KV，避免重复 prefill。

语义缓存是 RAG 降本主力：把新 query 嵌入后与缓存向量比相似度，超过阈值即复用。前缀缓存则省去重复计算相同上下文的 prefill，对固定知识库前缀尤为有效。

## 三、形式化与数学基础

语义缓存命中判定：设缓存项 $\{(q_j, a_j, \mathbf{e}_j)\}$，新查询 $\mathbf{e}_q$，若

$$\max_j\ \cos(\mathbf{e}_q, \mathbf{e}_j) \ge \tau$$

则复用 $a_{\hat j}$，否则走完整链路并把 $(q, a, \mathbf{e}_q)$ 写入缓存。阈值 $\tau$ 权衡命中率与错误率：过低误命中(答非所问)，过高退化为精确缓存。可配合 TTL 控制新鲜度：

$$\text{valid}(j) \iff \text{now} - t_j \le \text{TTL}$$

## 四、代码实现

```python
import numpy as np

def semantic_cache_get(query_vec, cache, tau=0.92):
    if not cache:
        return None
    sims = [float(np.dot(query_vec, e) / (np.linalg.norm(query_vec)*np.linalg.norm(e)))
            for e in cache["vecs"]]
    best = int(np.argmax(sims))
    return cache["ans"][best] if sims[best] >= tau else None
```

## 五、与其他技术对比

| 缓存 | 命中条件 | 收益 | 风险 |
|------|----------|------|------|
| 精确 | 完全一致 | 最高 | 命中率低 |
| 语义 | 近义 | 高 | 误命中 |
| 前缀 | 相同前缀 | 省 prefill | 内存 |

## 六、常见误区

- 语义缓存阈值过低，把不同意图的问题误判为命中，返回错误答案。
- 无失效/TTL 策略，知识更新后旧答案仍被复用。
- 把含个人隐私的 query 明文缓存，引发合规风险(应脱敏/哈希)。
- 只缓存答案不缓存检索上下文，导致无法溯源。
- 缓存命中率过高却不监控质量，错误答案被长期放大。

## 九、演进与趋势

缓存从「单点语义缓存」走向「多级缓存」：精确 → 语义 → 前缀 → 检索结果缓存(相同 query 不重复检索)。结合上下文压缩与量化推理，RAG 单位成本持续下降；也有工作按知识新鲜度自动设定 TTL，并在命中时附「置信度」提示，降低误命中危害。

## 十、小结

缓存是 RAG 降本关键杠杆：精确缓存兜底、语义缓存扩命中、前缀缓存省 prefill。务必设好相似度阈值与失效策略，并做隐私脱敏，在成本与正确性间取得平衡；生成侧缓存通常收益最大。
