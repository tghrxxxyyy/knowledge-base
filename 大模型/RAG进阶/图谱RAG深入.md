# 图谱 RAG 深入

> 对应微软 Microsoft GraphRAG 与 HippoRAG；在「RAG深入/图谱RAG」基础上的工程与算法深入。

## 一、背景与挑战

传统向量 RAG 的局部相似检索，在「鸟瞰式、聚合式、多跳推理」问题上有结构性盲点。GraphRAG 用知识图谱补足全局视图，但落地时要回答更深层的问题：

- 实体/关系抽取噪声如何控制？
- 社区划分粒度如何影响摘要质量？
- 在线阶段如何在「向量检索 / 图遍历 / 社区摘要」间选择？
- 离线成本如何压到可接受？
- 同名实体消歧、关系方向性如何处理？

## 二、核心原理

GraphRAG 管线分两阶段深化：

**离线**：文档 → LLM 抽取(实体、关系、主张) → 建图 $G=(V,E)$ → 社区检测(如 Leiden) → 每层社区生成自然语言摘要。摘要层级向上聚合，使任意粒度全局问题都能找到对应摘要集合。

**在线**：根据问题类型选择路径——
- 具体事实：走向量检索命中节点及其邻域。
- 全局主题：走社区摘要聚合。
- 多跳关系：沿边遍历子图再推理。

```
离线：抽取 → 建图 → 社区检测 → 社区摘要(分层)
在线：问题分类 → {向量/图遍历/社区摘要} → LLM 综合
```

## 三、形式化与数学基础

图 $G=(V,E)$，社区划分 $\mathcal{C}=\{C_1,\dots,C_K\}$ 由模块度优化得到：

$$Q = \frac{1}{2|E|}\sum_{ij}\Big(A_{ij}-\frac{k_i k_j}{2|E|}\Big)\delta(c_i,c_j)$$

每个社区 $C_i$ 生成摘要 $S_i$。全局查询作答为对社区摘要的聚合：

$$\text{answer}(q)=\mathrm{LLM}\Big(q,\ \bigcup_{i=1}^{K} S_i\Big)$$

多跳推理则沿邻域扩展 $N^{(h)}(v)=\{u : \mathrm{dist}_G(v,u)\le h\}$ 捕捉 $h$ 跳关系；模块度 $Q$ 越高，社区划分越内聚，摘要越有代表性。

## 四、代码实现

```python
# GraphRAG 本地查询(在已有索引上)
from graphrag.query import search

resp = search.local_search(
    query="某实体的核心关系是什么？",
    root="./output",
)
# 全局查询走社区摘要
resp = search.global_search(
    query="主要争议主题有哪些？",
    root="./output",
)
```

HippoRAG 则用「嵌入 + 个性化 PageRank」在已有图谱上做多跳检索，省去重新抽取摘要的开销。

## 五、与其他技术对比

| 维度 | 向量 RAG | GraphRAG(局部) | GraphRAG(全局) |
|------|----------|----------------|----------------|
| 事实点查 | 优 | 优 | 中 |
| 多跳 | 弱 | 强 | 中 |
| 全局聚合 | 弱 | 弱 | 优 |
| 成本 | 低 | 中 | 高 |

## 六、常见误区

- 社区粒度设错导致摘要过粗(丢失细节)或过碎(失去聚合价值)。
- 实体抽取无去歧义，同名实体被错误合并。
- 把图当银弹，忽视其离线抽取与摘要的高成本。
- 在线阶段路径选择不当，简单事实也走昂贵的全局聚合。
- 关系方向颠倒(谁指向谁)使多跳推理出错。

## 九、演进与趋势

轻量化图谱 RAG(HippoRAG)用「个性化 PageRank + 已有嵌入」模拟长期记忆，降低建图成本；图谱与 Agent 推理结合，使「检索-推断-再检索」在图上自适应展开，是多跳问答的重要方向。动态图谱(随新文档增量更新)也在研究中。

## 十、小结

图谱 RAG 深入价值在「分层社区摘要 + 多路径在线检索」。它以更高的离线成本换取全局/多跳能力，工程关键是控制好抽取质量、社区粒度、实体消歧与路径选择；轻量化方案正逐步降低落地门槛。
