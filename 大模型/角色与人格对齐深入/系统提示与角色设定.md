# 系统提示与角色设定

> 对应 system prompt 工程；与 dair-ai 提示工程指南 衔接。

## 一、背景与挑战

系统提示是注入角色的最直接方式，但易被长对话稀释或被攻击改写。

## 二、核心原理

系统提示置于上下文最前，定义身份、边界、语气；配合输出格式约束，越界时拒绝。

## 三、数学形式

有效约束近似先验 $p(r)\propto p_{base}(r)\cdot\mathbb 1(r\in P)$ 经提示近似实现。

## 四、代码实现

```python
messages = [{"role":"system","content":persona_prompt}] + turns
```

## 五、与其他对比

- 与 指令格式与模板深入（系统提示即模板）共享。
- 与 角色注入攻击深入（防御面）对照。

## 六、常见误区

- 系统提示过长被注意力稀释。
- 把安全规则只放系统提示，被越狱绕开。

## 八、面试题

- 系统提示为何放最前？答：作为最强先验框定身份与边界，且通常权重最高不易被覆盖。

## 九、演进

单句设定 → 结构化系统提示 → 角色+安全双层。

## 十、小结

系统提示是角色设定的首要手段，需配合防御防绕过。
