# 检查点与显存权衡

> 对应 显存-计算交换分析；与 显存最优调度深入 衔接。

## 一、背景与挑战

给定显存上限，须决定哪些层检查点化以最大化吞吐同时不 OOM。

## 二、核心原理

以每层激活大小与时长构建代价模型，求解在显存约束下总重算时间最小的检查点集合；常近似为按激活体积贪心。

## 三、数学形式

约束 $\sum a_i \le M$（激活预算）；目标 $\min \sum_{i\in C} t_i$（重算耗时），$C$ 为检查点选择集合。

## 四、代码实现

```python
plan = select_checkpoints(activations, times, mem_limit=M)
```

## 五、与其他对比

- 与 分布式优化器深入（减状态）是不同的显存来源。
- 与 显存最优调度深入（offload）并列替代方案。

## 六、常见误区

- 只看激活体积忽视重算时间（瓶颈转移）。
- 与激活重计算调度重复设计致冲突。

## 八、面试题

- 如何定检查点集合？答：在显存预算下选使重算耗时最小（或体积最大）的层作锚点。

## 九、演进

经验间隔 → 代价模型 → 联合调度。

## 十、小结

检查点须以显存-计算代价模型决策，而非盲目均匀化。
