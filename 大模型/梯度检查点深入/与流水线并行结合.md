# 检查点与流水线并行结合

> 对应 Huang et al., *GPipe*, 2019；Harlap et al., *PipeDream*；与 分布式优化器深入 衔接。

## 一、背景与挑战

流水线并行把模型切到多卡，每卡存一段激活；检查点在该段内进一步降显存，提升微批数量。

## 二、核心原理

GPipe 在每段内用检查点（forward 全存、backward 重算）以支持大微批；PipeDream 用 1F1B 与激活重计算平衡各卡显存与气泡。

## 三、数学形式

段内激活由检查点控制；流水线气泡比随微批数 $m$ 下降约 $1/(m+1)$，检查点使 $m$ 能更大。

## 四、代码实现

```python
for mb in microbatches:
    pipe.send(checkpoint(layer, mb))   # 段内检查点
```

## 五、与其他对比

- 与 分布式优化器深入（跨卡状态分片）解决不同瓶颈。
- 与 显存最优调度深入 共同规划段内显存。

## 六、常见误区

- 段间通信与检查点重算叠加致吞吐下降。
- 微批过多致气泡反而增大（需平衡）。

## 八、面试题

- 检查点如何助流水线？答：段内降激活显存，使单卡可容纳更多微批，减少流水线气泡。

## 九、演进

无检查点 → GPipe 段内 → PipeDream 1F1B+重算。

## 十、小结

检查点与流水线结合，在显存与吞吐间放大可并行微批数。
