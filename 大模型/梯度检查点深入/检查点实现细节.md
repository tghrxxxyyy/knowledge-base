# 检查点实现细节与陷阱

> 对应 PyTorch `torch.utils.checkpoint` 实现；与 数值稳定性深入 衔接。

## 一、背景与挑战

检查点重算会重跑前向，若前向含随机性（dropout、随机采样）或原地操作，重算结果不一致致错误梯度。

## 二、核心原理

框架用 `torch.no_grad` 包裹重算前向并重建计算图；要求被检查点函数纯（无副作用）、非原地写、随机数可控（种子重放）。

## 三、数学形式

反向需 $\frac{\partial L}{\partial x}= \frac{\partial L}{\partial y}\frac{\partial y}{\partial x}$，重算须产出与原前向一致的 $y$ 方能得到正确梯度。

## 四、代码实现

```python
with torch.random.fork_rng():        # 固定随机性
    out = checkpoint(dropout_layer, x)
```

## 五、与其他对比

- 与 训练不稳定诊断深入（重算数值差）共享数值问题。
- 与 梯度检查点深入 各节为理论与实践。

## 六、常见误区

- 检查点内用 inplace 操作致反向图错误。
- 未固定随机种子致重算 dropout 不一致。

## 八、面试题

- 检查点为何要固定随机性？答：重算前向须与原前向一致，否则梯度基于不同激活而错误。

## 九、演进

naive 重算 → 确定性重放 → 自动纯函数检测。

## 十、小结

检查点实现须保证重算一致性，规避原地写与随机性陷阱。
