# 张量并行部署

> 对应 Megatron-LM (Shoeybi et al. 2019) 与 vLLM / TensorRT-LLM 推理部署实践。

## 一、背景与挑战

当模型权重、激活与 KV Cache 的总和超过单张加速卡的显存时，必须跨多卡切分模型。张量并行（Tensor Parallelism, TP）是推理侧最常用的切分方式：它将每一层的权重矩阵沿特定维度切到多张卡上，每层前向通过卡间集合通信（all-reduce）拼回完整结果。其优势是「层内并行」、无明显流水线气泡；劣势是对卡间带宽极度敏感。生产上 vLLM、TensorRT-LLM、DeepSpeed-Inference 均支持通过 `--tensor-parallel-size`（或等价参数）指定 TP 度。挑战在于：TP 度并非越大越好——通信开销随卡数线性增长，跨节点（NVLink 之外走 PCIe/网络）时延会迅速侵蚀收益；同时并非所有算子都适合切分，需按 Megatron 的「列并行/行并行」规则重塑计算图。

## 二、核心原理

以 Transformer 的线性层 $Y=XA$ 为例，Megatron 给出两种切分：
- **列并行（Column Parallel）**：把权重 $A$ 按列切成 $A=[A_1;A_2]$，各卡持有 $A_i$，独立算 $Y_i=XA_i$，输出沿特征维拼接，无需通信。
- **行并行（Row Parallel）**：把 $A$ 按行切 $A=[A_1,A_2]$，各卡持有 $A_i$，算 $X_iA_i$ 后做一次 **all-reduce** 求和得到 $Y$。

通过交替使用列并行与行并行，可在不引入额外通信的前提下把 MLP 与 Attention 的两层矩阵乘串起来。Attention 的多头则天然可按头切分（每个头在一张卡上独立计算 softmax）。

实践中 TP 部署还需精确算显存账：TP 节省的是「权重」显存，而 KV Cache 随序列长度与批大小线性增长，这部分在 TP 下按头分片但总量不变，规划副本显存时须另算。并非所有算子都线性可分——LayerNorm、残差加、softmax 等沿特征维的归约若错误切分会引入额外 all-reduce 或数值偏差，因此推理引擎通常只对线性层做 TP，归约类算子保持副本或置于 TP 边界。另外，TP 通信发生在每一层内部，对延迟敏感的解码步尤甚，故生产上常限制 TP 度不超过单机 NVLink 域内卡数（如 8），跨节点改用流水线并行。

## 三、形式化与数学基础

设 TP 度为 $P$，单层矩阵乘 FLOPs 为 $F$。理想情况下每卡计算量降为 $F/P$，但需一次 all-reduce，通信量约为 $2b\times h$（激活大小，$b$ 为 batch、$h$ 为隐藏维）。通信受限下的有效加速：

$$ \text{speedup} \approx \frac{F}{F/P + 2\cdot \alpha + 2\beta\cdot b h / P} $$

其中 $\alpha$ 为通信启动延迟、$\beta$ 为带宽倒数。当 $P$ 增大使 $F/P$ 小于通信项时，加速曲线走平甚至回落。故 TP 通常限制在单机 NVLink 域（如 8 卡）内。

## 四、代码实现

```python
from vllm import LLM

# 单机 4 卡张量并行，vLLM 自动按 Megatron 方案切分权重
llm = LLM(
    model="meta-llama/Llama-3-70b",
    tensor_parallel_size=4,     # 仅当模型放不下单卡时使用
    gpu_memory_utilization=0.9,
)

# TensorRT-LLM 等价：trtllm-build --world_size=4 --tp_size=4 ...
# DeepSpeed-Inference：replace_with_tensor_parallel(mp_size=4)
```

## 五、与其他并行方式对比

| 维度 | 张量并行 TP | 流水线并行 PP | 数据并行 DP | 序列并行 SP |
|------|-------------|---------------|-------------|-------------|
| 切分对象 | 层内权重 | 跨层 | 数据批次 | 层内激活 |
| 通信类型 | all-reduce | p2p + 气泡 | all-reduce 梯度 | all-gather/reduce-scatter |
| 主要瓶颈 | 卡间带宽 | 流水线气泡 | 显存副本 | 激活显存 |
| 跨节点友好 | 否 | 是 | 是 | 部分 |

推理场景通常 TP（单机多卡）+ 少量 PP（跨节点超大模型）组合；纯 DP 用于多副本吞吐而非单请求加速。

## 六、常见误区

- **TP 越大越快**：受限于卡间带宽，跨节点 TP 会因网络时延严重掉速，应在 NVLink 域内使用。
- **所有层都切分**：LayerNorm、残差、softmax 等沿特征维的归约需谨慎，错误切分会引入额外通信或数值偏差。
- **忽略 KV Cache 的并行**：TP 下每卡只持部分头，KV Cache 也按头分片，显存估算需据此调整。
- **与量化混用不考虑支持**：并非所有推理引擎对每个 TP 度都支持某量化格式，需先验证。
- **忽视通信计算重叠**：不重叠 all-reduce 会因气泡浪费算力，应启用 kernel 融合。
- **显存估算漏算 KV**：TP 主要省权重，KV Cache 仍随序列增长需单独预算。
- **跨节点强用 TP**：NVLink 之外走网络，时延使加速转负，应改用流水线并行。
- **忽略 TP 与 PP 的协同**：超大模型应 TP（单机）+ PP（跨节点）组合，而非一味拉大 TP。
- **不设通信超时**：卡间 all-reduce 卡死会整批挂起，需带超时与降级。
- **权重加载不做预热**：新副本冷启动拖慢首响，应预取权重到本地。

部署前建议做一次「渐进式 TP 扫描」：从 TP=1 起逐步增大，记录单请求 TTFT 与吞吐，找到边际收益为零的拐点即最优度，避免凭经验直接拉满。

## 九、演进与趋势

- **序列并行（SP）**：进一步切分 LayerNorm/Dropout 的激活，缓解激活显存压力。
- **TP+PP+DP 三维组合**：Megatron 的 PTM 把三者统一调度，适配万卡推理集群。
- **通信计算重叠**：将 all-reduce 与后续计算流水线化，隐藏通信延迟。
- **专家并行（EP）**：MoE 下按专家分片，与 TP 协同。
- **TP 度自动搜索**：依据模型参数量、单卡显存与卡间拓扑自动求解最优 TP，避免凭经验试错。
- **量化与 TP 融合**：FP8 等低比特权重在 TP 分片下仍需高效 all-reduce kernel，二者需协同设计。
- **通信计算重叠**：将 all-reduce 与后续矩阵乘流水线化，隐藏通信气泡，是推理引擎的关键优化。
- **KV 分片调度协同**：TP 下 KV 按头分片，调度器据此预分配块可避免显存碎片。

## 十、小结

张量并行是「放不下就切权重」的基础手段，核心是 Megatron 的列/行并行与 all-reduce 拼接。它以卡间带宽为代价换取单请求跨卡加速，生产上应限定在 NVLink 域内，并与 PP、量化协同以平衡显存、延迟与吞吐。
