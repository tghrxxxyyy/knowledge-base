# 多模型路由

> 对应 Chen et al. 2023 FrugalGPT、llm-course (mlabonne) 成本控制实践与 dair-ai Prompt Engineering Guide。

## 一、背景与挑战

大语言模型服务在真实业务中存在显著的成本与质量差异：旗舰模型（千亿参数级闭源模型）在复杂任务上表现优异，但单 token 成本高、延迟大；小模型（几亿到几十亿参数开源模型）成本低、速度快，但在多步推理、长上下文理解上容易出错。若能按请求难度「分层调度」——简单请求交给小模型、困难请求才升级到大模型——即可在几乎不损失用户体验的前提下把单位成本压低一个数量级。这一思想在 FrugalGPT 中被称为 LLM cascade（级联），也是业界「模型路由器」的核心动机。挑战在于：路由决策本身需要开销，且路由错误（把难样本误判给小模型）会直接损害答案质量；此外不同任务的最优难度划分并不固定，需要持续校准。

## 二、核心原理

多模型路由本质是一个「分类/决策」问题，目标是最小化代价函数：

$$ \min_{\text{router}} \mathbb{E}_{x}\big[\,c(x) + \lambda\cdot \mathbf{1}[\text{answer}(x)\text{ 未达质量}]\,\big] $$

常见实现路径有三类：
1. **规则路由**：按可观测信号（输入长度、是否含代码、用户套餐等级）直接分流，零额外推理开销，但难以刻画真实难度。
2. **学习式路由器**：用小分类器（基于 embedding 的线性模型或轻量 BERT）预测「小模型是否足够」，作为门控信号。
3. **LLM 自判断 / 置信度路由**：先让小模型生成并自评置信度（如 token 概率熵、self-consistency 方差），低于阈值才升级大模型。FrugalGPT 还在第三层用大模型对前层输出做「提示增强」以提升最终质量。

为避免路由抖动，生产系统通常引入缓存：对高频相似请求直接复用历史最优路径。

## 三、形式化与数学基础

设模型集合 $\mathcal{M}=\{M_1,\dots,M_k\}$，按能力升序排列（$M_1$ 最小、$M_k$ 最强）。级联在某请求 $x$ 上的成本为各层累计，直到某一层 $M_j$ 判定「足够好」：

$$ \text{Cost}(x)=\sum_{i=1}^{j(x)} \text{cost}(M_i\mid x) $$

质量门控可用小模型输出置信度 $\phi(M_i(x))$ 表达，当 $\phi(M_i(x))\ge \tau$ 时停止并采纳。整体期望成本：

$$ \mathbb{E}_x[\text{Cost}(x)] = \sum_{i=1}^k \Pr\big(j(x)=i\big)\cdot \sum_{t=1}^{i}\text{cost}(M_t\mid x) $$

路由器的优化目标即在给定质量约束 $\Pr[\text{质量达标}]\ge q^*$ 下最小化上式。

## 四、代码实现

```python
import math
from typing import Callable

def entropy(probs):
    return -sum(p * math.log(p + 1e-9) for p in probs)

def cascade_route(prompt, models, tau=0.6):
    for m in models:                 # 由小到大遍历
        out, probs = m.generate(prompt, return_probs=True)
        conf = 1.0 - entropy(probs) / math.log(len(probs))
        if conf >= tau:              # 置信度足够，停止升级
            return out, m.name
    return out, m.name               # 已到最强模型

# 也可训练独立路由器：router.fit(X_embed, y_is_hard)
```

## 五、与其他技术对比

| 方案 | 额外延迟 | 成本节省 | 实现复杂度 | 适用场景 |
|------|----------|----------|------------|----------|
| 固定小模型 | 低 | 高 | 极低 | 简单标准化任务 |
| 规则路由 | 低 | 中 | 低 | 信号明确的业务 |
| 学习式路由器 | 中 | 高 | 中 | 难度分布复杂 |
| LLM 级联 | 中-高 | 高 | 中 | 质量要求高 |
| 单大模型直出 | 高 | 无 | 低 | 不计成本 |

相较「单大模型直出」，路由以可忽略的路由开销换取大幅降本；相较「纯缓存」，路由能覆盖未命中长尾；相较「单纯重试」，级联是主动的难度感知调度。

## 六、常见误区

- **误以为路由一定降本**：当难样本占比高时，大量请求仍会升级到大模型，收益有限，需先评估流量难度分布。
- **阈值一次性设死**：数据分布漂移后阈值失效，应在线监控各层采纳率并自动校准。
- **忽略路由器自身成本**：大模型做自评/路由会抵消收益，理想路由应轻量（小模型或规则）。
- **把质量门控等同于正确性**：置信度高不等于答案对，需定期用金标准校验。

## 九、演进与趋势

- **语义路由**：基于请求 embedding 的近邻/聚类路由，配合向量库实现细粒度分流。
- **强化学习路由**：把「质量-成本」作为奖励，端到端学习路由策略（如 RouteLLM）。
- **与投机解码结合**：小模型草稿 + 大模型校验，在生成层面而非请求层面降本。
- **统一网关标准化**：LiteLLM/OpenRouter 让路由成为调用层基础设施。

## 十、小结

多模型路由通过「分层调度 + 质量门控」在大模型成本与体验间取平衡，核心是设计低开销、可在线校准的路由器，并用代价函数量化权衡。落地时先评估流量难度分布，再选择规则/学习式/级联方案，并持续监控各级采纳率与质量。
