# KV缓存驱逐策略

> 对应长上下文 KV 管理（如 H2O、StreamingLLM）。

## 一、背景与挑战

超长对话/文档 KV 超出显存；需驱逐不重要历史。

## 二、核心原理

按注意力得分/累积重要性保留关键 token（如近期窗口+重要历史），驱逐低贡献 K/V。

## 三、数学形式

保留集合 $S=\{t: \text{score}_t>\tau\}$ 或 top-k；滚动窗口保最近 $w$ 个。

## 四、代码实现

```python
imp = attn_scores.mean(-1)      # 每位置重要性
keep = imp.topk(k).indices
K, V = gather(K, keep), gather(V, keep)
```

## 五、与其他对比

- 与 长上下文技术 / 长上下文推理深入 衔接。
- 与 注意力数学基础 共享重要性度量。

## 六、常见误区

- 纯近期窗口丢关键早期事实（StreamingLLM 用 sink）。
- 驱逐后位置编码需保持一致。

## 七、与开源书对应

- llm-course：https://github.com/mlabonne/llm-course

## 八、面试题

- 驱逐 KV 的风险？答：丢掉重要历史致事实遗忘/上下文断裂。

## 九、演进

全缓存 → 滑动窗口 → 重要性驱逐(sink+topk)。

## 十、小结

KV 驱逐在超长场景必要，须平衡容量与信息保留。
