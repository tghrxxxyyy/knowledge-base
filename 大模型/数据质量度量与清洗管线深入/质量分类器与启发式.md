# 质量分类器与启发式

> 对应 Brown et al. 2020《Language Models are Few-Shot Learners》（GPT-3）中的质量过滤实践、Raffel et al. 2019《Exploring the Limits of Transfer Learning》（C4 / Common Crawl 清洗），以及 HuggingFace transformers 与 karpathy/nanoGPT 的数据实践。

## 一、背景与挑战

网页抓取语料（Common Crawl 一类）中真正"像人写的、有信息量的文本"只占一部分，其余是导航菜单、模板页、SEO 垃圾、机器翻译腔、被反复转载的短文。纯靠规则很难覆盖：规则的召回高但精度低，写多了又互相打架，维护成本随语料来源增加而爆炸。

于是工程上形成两层结构：**启发式规则**做廉价的高召回初筛（去掉明显垃圾），**可学习的质量分类器**做精细打分排序。挑战在于：分类器的"高质量"定义来自参考语料的选择，如果参考语料是维基百科，模型会学到百科腔，把所有论坛、口语、代码、对话都判为低质——而这些恰恰是下游能力需要的分布。此外，分类器本身需要推理算力，在 TB 级语料上跑一遍并不便宜，需要在精度与吞吐之间权衡。

## 二、核心原理

**启发式层**依赖可解释的统计特征，成本低、可并行：

- 长度与结构：字符数、行数、平均行长的分布异常（如大量短行，常见于列表/菜单）。
- 符号比例：标点、数字、非 ASCII、大写字母占比；大量 HTML 标签残留。
- 语言识别：用 fastText 一类语言 ID 模型过滤非目标语言与置信度过低的文本。
- 重复信号：文档内 n-gram 重复率、行级重复率。
- "脏词/停用词"清单：过滤成人站点、赌博与 SEO 词表命中密集的页面。

**分类器层**的典型做法是"正例来自高质量参考源（书籍、百科、教科书、精选网页），负例来自未过滤的原始网页"，训练一个二分类器（早期常用逻辑回归/浅层模型加特征，后期用 Transformer 微调），对每篇文档输出质量分 $f_\theta(d) \in [0, 1]$，再按阈值或分位数筛选：

$$
\hat{y} = \mathbb{1}\left[ f_\theta(d) > \tau \right]
$$

更稳妥的用法不是硬阈值，而是**按分位数取 top-k%**，这样保留率可控，也便于做"高质量语料可重复训练多轮"的配比设计。

## 三、形式化与数学基础

设文档集合 $\mathcal{D}$，真实质量标签 $y \in \{0,1\}$，分类器输出 $s = f_\theta(d)$。阈值决策的风险为

$$
\mathcal{R}(\tau) = \mathbb{E}_{d}\left[ \mathbb{1}[s \le \tau] \cdot \mathbb{1}[y = 1] \cdot c_{\mathrm{fn}} + \mathbb{1}[s > \tau] \cdot \mathbb{1}[y = 0] \cdot c_{\mathrm{fp}} \right]
$$

其中 $c_{\mathrm{fn}}$ 是误杀高质量文档的代价（信息损失、多样性下降），$c_{\mathrm{fp}}$ 是放过低质文档的代价（训练噪声）。由于两类代价不对称，最优阈值一般不等于 0.5：

$$
\tau^\ast = \arg\min_{\tau} \mathcal{R}(\tau)
$$

实践中常令保留率固定为 $\rho$，取 $\tau$ 为经验分位数：

$$
\tau_\rho = \inf \left\{ t : \frac{1}{|\mathcal{D}|} \sum_{d} \mathbb{1}[f_\theta(d) \le t] \ge 1 - \rho \right\}
$$

**分布偏移**是分类器最大的理论隐患。设参考源分布为 $p_{\mathrm{ref}}$，待筛语料分布为 $p_{\mathrm{corpus}}$，分类器实际学的是 $p_{\mathrm{ref}}$ 与 $p_{\mathrm{raw}}$ 的判别边界。当两者不重叠区域较大时，模型会依赖"风格"而非"质量"做判断。可用重要性权重校正：

$$
\mathbb{E}_{p_{\mathrm{corpus}}}[g(d)] = \mathbb{E}_{p_{\mathrm{ref}}}\left[ \frac{p_{\mathrm{corpus}}(d)}{p_{\mathrm{ref}}(d)} g(d) \right], \qquad w(d) = \frac{p_{\mathrm{corpus}}(d)}{p_{\mathrm{ref}}(d)}
$$

工程上更常见的替代方案是**减轻负例偏差**：负例不完全取原始网页，而是混入启发式已过滤但仍存疑的样本，并对分数做分源校准（每个来源单独取分位数）。

融合规则与分类器时，可用加权和或级联：

$$
Q(d) = \sum_k w_k \, q_k(d), \qquad \sum_k w_k = 1,\ w_k \ge 0
$$

## 四、代码实现

```python
# 启发式层：廉价、可并行、高召回的初筛规则
import re
import unicodedata

BAD_PATTERNS = [
    re.compile(r"javascript is required", re.I),
    re.compile(r"all rights reserved", re.I),
    re.compile(r"\b(buy cheap|casino|viagra)\b", re.I),
]

def heuristic_features(text):
    n = max(len(text), 1)
    lines = text.split("\n") or [""]
    return {
        "n_chars": len(text),
        "mean_line_len": sum(len(x) for x in lines) / max(len(lines), 1),
        "digit_ratio": sum(c.isdigit() for c in text) / n,
        "nonascii_ratio": sum(ord(c) > 127 for c in text) / n,
        "upper_ratio": sum(c.isupper() for c in text) / n,
        "punct_ratio": sum(c in ".,;:!?" for c in text) / n,
    }

def heuristic_keep(text, min_chars=200, max_upper=0.3, max_digit=0.2):
    # 先做归一化，避免全角/控制字符影响统计
    t = unicodedata.normalize("NFKC", text)
    if len(t) < min_chars:
        return False
    if any(p.search(t) for p in BAD_PATTERNS):
        return False
    f = heuristic_features(t)
    if f["upper_ratio"] > max_upper:      # 大量全大写多为抓取噪声
        return False
    if f["digit_ratio"] > max_digit:      # 数字密集多为表格/报价页
        return False
    return True
```

```python
# 分类器层：用参考源训练二分类打分器，再按分位数筛选
import torch
from transformers import AutoTokenizer, AutoModelForSequenceClassification

MODEL_ID = "bert-base-multilingual-cased"   # 仅为示意，实际选型以任务为准
tok = AutoTokenizer.from_pretrained(MODEL_ID)
clf = AutoModelForSequenceClassification.from_pretrained(MODEL_ID, num_labels=2)
clf.eval()

@torch.inference_mode()
def score_docs(texts, batch_size=32, max_len=512):
    probs = []
    for i in range(0, len(texts), batch_size):
        batch = texts[i:i + batch_size]
        enc = tok(batch, truncation=True, max_length=max_len,
                  padding=True, return_tensors="pt")
        logits = clf(**enc).logits
        probs.extend(torch.softmax(logits, dim=-1)[:, 1].tolist())
    return probs
```

```python
# 按保留率取分位数阈值，比固定阈值更可控
def select_top_frac(texts, scores, keep_frac=0.3):
    pairs = sorted(zip(texts, scores), key=lambda x: x[1], reverse=True)
    k = max(int(len(pairs) * keep_frac), 1)
    return [t for t, _ in pairs[:k]], pairs[k - 1][1]

docs = [d for d in raw_docs if heuristic_keep(d)]
scores = score_docs(docs)
kept, threshold = select_top_frac(docs, scores, keep_frac=0.3)
print("启发式保留:", len(docs), "分类器保留:", len(kept), "阈值:", round(threshold, 4))
```

## 五、与其他技术对比

| 维度 | 纯启发式规则 | 学习式质量分类器 | 人工标注/规则+人审 |
|------|--------------|------------------|---------------------|
| 成本 | 极低 | 中（训练+推理算力） | 极高 |
| 覆盖模式 | 仅显式可枚举的模式 | 可捕捉隐式风格与语义 | 最全面 |
| 可解释性 | 强 | 弱（需额外解释手段） | 强 |
| 分布偏移敏感度 | 低 | 高（易过拟合参考源） | 低 |
| 吞吐 | 高 | 中低（取决于模型大小） | 极低 |
| 维护成本 | 规则膨胀后高 | 重训即可 | 持续投入 |
| 典型用法 | 初筛、兜底黑名单 | 打分排序、按分位取用 | 制作评测集与分类器正负例 |

## 六、常见误区

- **只用单一参考源训练**：正例全是百科会让分类器歧视口语、对话、论坛与代码，损失多样性。
- **把分类器分数当绝对质量**：分数是相对的排序信号，跨来源不可直接比较，应按源分别取分位数。
- **硬阈值一刀切**：不同来源的分数分布不同，固定阈值会导致各源保留率失衡。
- **忽略误杀的长尾**：被判低质的往往包含方言、小众领域与口语，正是差异化能力的来源。
- **不评估分类器本身**：应抽样人工复核高分与低分样本，检查精度与召回。
- **规则与分类器顺序颠倒**：先跑昂贵的分类器再跑廉价规则，会浪费大量算力。
- **忘记去重**：质量高但高度重复的文档仍会浪费算力并放大偏见，应与去重步骤配合。

## 七、与开源书·权威来源对应

- Brown et al. 2020《Language Models are Few-Shot Learners》（GPT-3）：提出用高质量参考源训练分类器对网页语料打分的经典做法。

## 九、演进与趋势

路线从"人工写规则"演进到"参考源训练分类器"，再到"用强模型自动生成质量标注"。趋势上，一是**自监督与模型反馈信号**（困惑度、自洽性、模型间互评）部分替代人工标注；二是**多目标打分**，同时给出教育价值、信息密度、事实性等维度而非单一分数；三是**按源自适应阈值**，用分位数与重要性权重缓解分布偏移；四是**过滤与配比联动**，高质量数据可重复训练多轮；五是**可审计性**成为硬要求，每一步的淘汰率与样本留存都要可追溯（对应数据血缘与卡片实践）。

## 十、小结

质量分类器把筛选从"枚举规则"升级为"学习排序"，但它并不取代启发式：规则负责廉价高召回的初筛，分类器负责精细打分。核心风险是参考源分布偏移，因此应按来源校准、抽样人工复核、保留一定比例的"非典型"文本以维持多样性。工程上，先廉价规则后昂贵模型、先去重后打分，是控制成本的基本顺序。
