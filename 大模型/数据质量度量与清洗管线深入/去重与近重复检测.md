# 去重与近重复检测

> 对应 Broder 1997《On the Resemblance and Containment of Documents》（MinHash）、Indyk & Motwani 1998《Approximate Nearest Neighbors》（LSH）、Lee et al. 2022《Deduplicating Training Data Makes Language Models Better》，以及 HuggingFace datasets 与 EleutherAI/lm-evaluation-harness 生态中的去重实践。

## 一、背景与挑战

网页语料的重复程度远超直觉：同一篇新闻被上百家站点转载，文档模板与免责声明逐字相同，代码片段在不同仓库间复制，书籍扫描件存在多个版本。重复带来的问题至少有三层：**算力浪费**——相同的 token 被反复喂给模型；**分布偏斜**——高频转载内容（热点新闻、SEO 页面）在语料中的实际权重被放大，低频但高价值的内容被稀释；**隐私与记忆风险**——重复次数越多，模型记忆并复述该片段的概率越高（Carlini 等人的抽取攻击已证明重复是记忆的关键变量）。

工程挑战在于规模与粒度的矛盾：TB 级语料无法做 $O(N^2)$ 的两两比较；同时重复并不只发生在文档级——段级、句级、模板块级的重复（如每页相同的导航栏）同样有害，而文档级哈希对它们完全无效。此外，阈值设定存在两难：过严会删掉合理复用的内容（引用、法条、标准表述），过松则达不到去重效果。

## 二、核心原理

**精确去重**用哈希：对全文做 SHA-256，相同内容必然相同哈希。它零误判、成本极低，但只能抓逐字节相同的文档，无法处理改了一个标点的转载。

**MinHash** 解决近重复。把文档表示为 n-gram（通常是 5~13-gram 的词或字符）集合 $S$，用 $m$ 个独立随机哈希函数取每个集合的最小哈希值，构成签名向量：

$$
h_{\min}^{(i)}(S) = \min_{x \in S} \pi_i(x), \qquad \mathrm{sig}(S) = \left( h_{\min}^{(1)}(S), \dots, h_{\min}^{(m)}(S) \right)
$$

关键性质是：两个集合的 MinHash 签名在任意位置相等的概率，恰好等于它们的 Jaccard 相似度：

$$
\Pr\left[ h_{\min}(A) = h_{\min}(B) \right] = \frac{|A \cap B|}{|A \cup B|} = J(A, B)
$$

因此签名向量的重合比例就是 Jaccard 的无偏估计，把集合相似度问题转化为签名比较问题。

**LSH（局部敏感哈希）**解决"找谁和谁比"。把 $m$ 维签名分成 $b$ 个 band，每个 band 含 $r$ 行（$m = b \cdot r$），对每 band 的内容再次哈希入桶；只有至少在一个 band 中全部 $r$ 行都相同的文档才会进入同一个桶：

$$
\Pr[\text{候选对}] = 1 - \left( 1 - J^r \right)^b
$$

这是一条 S 形曲线，在阈值 $J \approx (1/b)^{1/r}$ 附近急剧上升，因此**通过选择 $b$ 与 $r$ 就能设定相似度阈值**。这一步把比较复杂度从 $O(N^2)$ 降到近似 $O(N)$。

**粒度选择**：文档级用整篇 n-gram 集合；段级对段落或滑动窗口做签名；后缀数组（Suffix Array）方法能精确找出所有超过长度阈值的重复子串，适合去除模板块与长片段重复，代价是内存与实现复杂度更高。

## 三、形式化与数学基础

**Jaccard 相似度**：

$$
J(A, B) = \frac{|A \cap B|}{|A \cup B|}
$$

实践中常用加权的 5-gram 集合（词级或字符级），并用 $n$ 的选择平衡：太小则几乎所有文本都相似，太大则抓不到改写。

**MinHash 无偏性证明要点**：设 $h$ 为随机哈希，$H(A \cup B)$ 中最小元素落在 $A \cap B$ 的概率为

$$
\Pr\left[ \arg\min_{x \in A \cup B} h(x) \in A \cap B \right] = \frac{|A \cap B|}{|A \cup B|} = J(A, B)
$$

用 $m$ 个独立哈希，估计值 $\hat{J} = \frac{1}{m} \sum_{i=1}^{m} \mathbb{1}[h^{(i)}_{\min}(A) = h^{(i)}_{\min}(B)]$，由 Hoeffding 不等式：

$$
\Pr\left[ |\hat{J} - J| \ge \varepsilon \right] \le 2 \exp(-2 m \varepsilon^2)
$$

因此要把误差控制在 $\varepsilon = 0.05$ 且置信度 95%，所需签名字长 $m$ 满足 $2\exp(-2m\varepsilon^2) \le 0.05$，即

$$
m \ge \frac{\ln(40)}{2\varepsilon^2} \approx \frac{3.69}{2 \times 0.0025} \approx 738
$$

这解释了为什么实践中常取 $m$ 在数百到一两百之间的量级（具体需按误差容忍度计算）。

**LSH 阈值性质**：band 数 $b$、每 band 行数 $r$ 下，成为候选的概率为

$$
f(J) = 1 - (1 - J^r)^b
$$

其拐点约在 $J^\ast \approx (1/b)^{1/r}$。设计时应先确定业务阈值（如 $J \ge 0.8$ 判为重复），再反解 $b, r$。

**去重对分布的影响**：设语料中某内容出现 $k$ 次，权重为 $w$，去重后变为 1 次。混合分布的变化可写为

$$
p_{\mathrm{before}} = \sum_i \frac{k_i w_i}{\sum_j k_j w_j} \, \delta_{x_i}, \qquad
p_{\mathrm{after}} = \sum_i \frac{w_i}{\sum_j w_j} \, \delta_{x_i}
$$

去重把"出现频次主导"拉回"内容多样性主导"，这正是 Lee et al. 2022 所观察到的收益来源之一（去重后模型在同等算力下损失更低、记忆更少）。

**后缀数组去重**：定义重复子串为长度 $\ge L$ 且在语料中出现 $\ge K$ 次的子串，用后缀数组可在 $O(N \log N)$ 或线性时间内找出全部此类子串并删除。相比 MinHash，它无概率误判，但内存开销大。

## 四、代码实现

```python
# 精确去重：零误判、极廉价，应作为第一步
import hashlib

def exact_dedup(docs):
    seen, out, dropped = set(), [], 0
    for d in docs:
        h = hashlib.sha256(d["text"].encode("utf-8")).hexdigest()
        if h in seen:
            dropped += 1
            continue
        seen.add(h)
        out.append(d)
    return out, dropped
```

```python
# MinHash 签名：用 m 个随机置换（这里用盐值哈希近似）取最小哈希
import re
import random

WORD_RE = re.compile(r"\w+", re.UNICODE)

def shingles(text, n=5):
    toks = WORD_RE.findall(text.lower())
    if len(toks) < n:
        return {" ".join(toks)} if toks else set()
    return {" ".join(toks[i:i + n]) for i in range(len(toks) - n + 1)}

def minhash_signature(shingle_set, m=128, seed=42):
    rng = random.Random(seed)
    # 用固定种子的随机系数模拟独立哈希：h(x) = (a*x + b) mod p
    a = [rng.getrandbits(31) for _ in range(m)]
    b = [rng.getrandbits(31) for _ in range(m)]
    p = (1 << 61) - 1                      # 梅森素数，便于取模
    sig = [p] * m
    for s in shingle_set:
        x = int(hashlib.sha1(s.encode("utf-8")).hexdigest()[:15], 16)
        for i in range(m):
            h = (a[i] * x + b[i]) % p
            if h < sig[i]:
                sig[i] = h
    return tuple(sig)
```

```python
# LSH 分带：只有同一 band 内全部行相同的文档才成为候选对
def lsh_candidates(signatures, bands=32):
    m = len(signatures[0])
    rows_per_band = m // bands
    buckets = [dict() for _ in range(bands)]
    for idx, sig in enumerate(signatures):
        for bi in range(bands):
            chunk = sig[bi * rows_per_band:(bi + 1) * rows_per_band]
            key = hashlib.sha1(str(chunk).encode()).hexdigest()
            buckets[bi].setdefault(key, []).append(idx)
    candidates = set()
    for bucket in buckets:
        for group in bucket.values():
            if len(group) > 1:
                for i in range(len(group)):
                    for j in range(i + 1, len(group)):
                        candidates.add((group[i], group[j]))
    return candidates

def jaccard_from_sig(sig_a, sig_b):
    return sum(1 for x, y in zip(sig_a, sig_b) if x == y) / len(sig_a)

def near_dedup(docs, threshold=0.8, m=128, bands=32):
    sigs = [minhash_signature(shingles(d["text"]), m=m) for d in docs]
    to_remove = set()
    for i, j in lsh_candidates(sigs, bands=bands):
        if i in to_remove or j in to_remove:
            continue
        if jaccard_from_sig(sigs[i], sigs[j]) >= threshold:
            # 保留先出现的（或更长的）那一份，保证结果确定
            to_remove.add(j if len(docs[i]["text"]) >= len(docs[j]["text"]) else i)
    return [d for k, d in enumerate(docs) if k not in to_remove], len(to_remove)
```

```python
# 段级去重：先按段落切分再签名，可抓模板块与转载段落
def paragraph_dedup(text, seen_hashes, min_chars=80):
    kept = []
    for para in text.split("\n"):
        p = para.strip()
        if len(p) < min_chars:
            kept.append(para)
            continue
        h = hashlib.sha1(p.encode("utf-8")).hexdigest()
        if h in seen_hashes:
            continue
        seen_hashes.add(h)
        kept.append(para)
    return "\n".join(kept)
```

## 五、与其他技术对比

| 维度 | 精确哈希 | MinHash + LSH | 后缀数组 | 嵌入聚类 |
|------|----------|---------------|----------|----------|
| 检出类型 | 逐字节相同 | 近重复（Jaccard） | 任意长度重复子串 | 语义相似 |
| 复杂度 | $O(N)$ | 约 $O(N)$ | $O(N \log N)$ | 高（需推理） |
| 误判 | 无 | 有概率误差（可控） | 无 | 有（阈值敏感） |
| 内存 | 低 | 中（签名 + 桶） | 高 | 高 |
| 实现难度 | 极低 | 中 | 高 | 中 |
| 适合规模 | 任意 | TB 级 | 百 GB 级 | 小规模精选 |

| 粒度 | 抓什么 | 代价 |
|------|--------|------|
| 文档级 | 整篇转载 | 低，但漏掉段落级 |
| 段/块级 | 模板块、免责声明 | 中 |
| 子串级（后缀数组） | 任意长度复制 | 高（内存） |
| 语义级 | 改写、翻译腔转载 | 最高（需嵌入） |

## 六、常见误区

- **只做文档级去重**：段落级与模板块重复（导航、版权声明）占比可能很高，必须用段落或子串级方法。
- **阈值过严**：Jaccard 阈值设到 0.95 会漏掉大量改写转载；设到 0.5 又会误删合理复用内容（法条、引用、标准表述）。
- **忽略 shingle 大小 $n$ 的影响**：$n$ 太小导致所有文档都"相似"，太大则抓不到局部改写。
- **签名长度凭感觉**：$m$ 决定估计误差，应按 Hoeffding 界计算而非随意取值。
- **band/row 配置与阈值不匹配**：LSH 的 $b, r$ 决定相似度拐点，必须与业务阈值对应反推。
- **去重顺序错误**：应先精确去重（廉价）再近重复去重（昂贵），且去重应在质量打分之前，避免重复文档互相抬高分数。
- **认为去重只是省算力**：它同时改写了数据分布、降低记忆与泄露风险，对最终能力有直接影响。

## 七、与开源书·权威来源对应

- Broder 1997《On the Resemblance and Containment of Documents》：MinHash 估计 Jaccard 相似度的原始论文，是整个近重复检测领域的基石。
- Indyk & Motwani 1998《Approximate Nearest Neighbors: Towards Removing the Curse of Dimensionality》：LSH 的奠基工作，给出分带策略的概率性质。
- Lee et al. 2022《Deduplicating Training Data Makes Language Models Better》：系统证明去重能降低损失、减少记忆并改善生成质量，是"去重不只是省算力"的实证依据。
- Carlini et al. 2021《Extracting Training Data from Large Language Models》：说明重复次数与记忆/抽取风险的正相关，是去重必要性的安全侧依据。
- Raffel et al. 2019（C4）与 Penedo et al. 2023（RefinedWeb）：公开语料中精确去重与模糊去重的工程实践（具体参数以各自论文与文档为准）。
- Abadi et al. 2016（DP-SGD）与 Kulkarni et al. 相关工作：从隐私角度补充去重的局限与替代方案。
- HuggingFace datasets 与 EleutherAI/lm-evaluation-harness 生态：提供大规模 map/filter 与去重脚本，以及验证去重效果所需的统一评测能力。

## 九、演进与趋势

去重技术从"精确哈希"演进到"MinHash + LSH"，再到"子串级（后缀数组）与语义级"。趋势上，一是**粒度下沉**，从文档级下沉到段落与子串级，以应对模板与片段复用；二是**语义去重**兴起，用嵌入聚类抓取改写、翻译与同义复述，代价是需要 GPU 与更谨慎的阈值；三是**去重与隐私联动**，优先删除高重复的敏感片段以降低记忆风险；四是**流式与增量去重**，支持新语料持续入库而不必全量重算；五是**去重效果可度量**，用记忆率、分布熵与下游损失共同评估，而非只看删除比例。

## 十、小结

去重是降低冗余、纠偏分布与降低记忆风险的基础步骤。核心方法是三层：精确哈希做零成本初筛，MinHash + LSH 做近重复检测（其无偏性来自 $\Pr[h_{\min}(A) = h_{\min}(B)] = J(A,B)$，阈值由 $b, r$ 控制），后缀数组或段落级方法处理模板块与子串复制。工程上要注意顺序——精确在前、昂贵在后、去重在打分之前——并按 Hoeffding 界选择签名长度、按业务阈值反推 band 配置，最后用去重后的分布变化与下游指标验证效果。
