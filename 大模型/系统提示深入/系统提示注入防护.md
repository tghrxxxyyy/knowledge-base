# 系统提示注入防护

> 对应 Liu et al., *Prompt Injection Attacks*, 2023；Perez & Ribeiro, 2022。

## 一、背景与挑战

用户或外部内容可借“忽略以上指令”覆盖系统提示，致越权或泄露。

## 二、核心原理

防护：将系统提示与不可信内容严格分隔（角色/分隔符）；对指令性用户输入做检测与拒答；用结构化信道区分“指令”与“数据”。

## 三、数学形式

危险度 $d(u)=P_{cls}(\text{injection}\mid u)$；当 $d(u)>\tau$ 拒绝，否则拼接上下文。

## 四、代码实现

```python
if injection_clf(user_msg) > 0.8:
    return "请求含注入风险，已拒绝。"
```

## 五、与其他对比

- 与 防御性提示深入 同主题（宏观防御）。
- 与 安全红队深入（发现漏洞）互补。

## 六、常见误区

- 仅靠自然语言“请勿忽略指令”无法防注入。
- 把未清洗的外部文档直接拼进系统提示层级。

## 八、面试题

- 如何防系统提示被覆盖？答：分隔指令与数据信道、检测注入、对不可信内容降权。

## 九、演进

无防护 → 分隔符 → 分类器+隔离信道。

## 十、小结

系统提示注入防护靠信道隔离与注入检测，自然语言声明不够。
