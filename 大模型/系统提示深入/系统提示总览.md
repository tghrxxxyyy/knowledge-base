# 系统提示总览

> 对应 OpenAI, *Model Spec*, 2024；Anthropic, *Claude System Prompt* 实践；提示工程基础。

## 一、背景与挑战

裸指令下模型行为不稳定、缺角色与边界；系统提示统一注入角色、约束、输出格式与安全基线。

## 二、核心原理

系统提示作为对话首条 message 提供全局指令（角色、语气、禁止项、输出 schema），对后续用户轮持续生效，等价于条件先验。

## 三、数学形式

条件生成 $P_\theta(y\mid x, s)$，其中 $s$ 为系统提示；多轮下 $y_t\sim P_\theta(\cdot\mid s, x_{<t}, y_{<t})$。

## 四、代码实现

```python
from openai import OpenAI
c = OpenAI()
r = c.chat.completions.create(
    model="gpt-4o",
    messages=[{"role":"system","content":"你是严谨中文助手，只输出JSON。"},
              {"role":"user","content":"北京人口?"}])
```

## 五、与其他对比

- 与 提示工程深入（单轮技巧）相比，系统提示跨轮持久、更稳定。
- 与 安全对齐深入 共享约束目标。

## 六、常见误区

- 系统提示过长挤占上下文且易被越狱试探。
- 把应放用户侧的内容硬编码进系统提示，降低灵活性。

## 八、面试题

- 系统提示为何跨轮生效？答：作为首条 message 进入上下文，对每轮生成提供恒定条件先验。

## 九、演进

无指令 → 单次指令 → 持久系统提示 → 分层系统提示（基线+任务）。

## 十、小结

系统提示是模型行为的全局先验，统一角色、约束与格式，是生产应用底座。
