# 审核与过滤

> 对应 OpenAI Moderation 类工业实践、EleutherAI/lm-evaluation-harness 中的安全评测任务与 OWASP Top 10 for LLM Applications。

## 一、背景与挑战

无论模型是否经过安全对齐，面向公众的服务都必须对输入与输出做审核，以识别并拦截违法不良信息（暴力、色情、仇恨、自残、侵权、虚假信息等）。审核系统面临三重压力：一是漏放（false negative）带来合规与声誉风险；二是误伤（false positive）损害正常用户体验，尤其在医疗、法律、文学创作等正当场景；三是攻击者会用变体、拆字、谐音、编码、跨语种与多模态拼接绕过规则。此外，多语种与多模态场景要求审核能力有相应覆盖，而低资源语言往往缺乏标注数据，成为审核盲区。

## 二、核心原理

现代内容审核是「多信号融合 + 分级处置」的系统：

1. 规则层：关键词、正则、敏感词库与黑名单。零延迟、可解释、易热更，但泛化差，易被变体绕过，误伤也高。
2. 模型层：用多标签分类器对文本/图像/音频打风险分（暴力、色情、仇恨、自残、诈骗等），泛化能力强，但需训练数据、算力与定期更新。
3. 语义层：用强模型做上下文感知裁判，处理讽刺、隐晦、组合风险与跨句依赖，代价是延迟与成本。
4. 决策层：按阈值与业务优先级做放行、附加提示、转人工复核、安全改写或直接拦截。

工程上有三个要点：一是分级而非二值，对边界样本降级或转人工；二是信号融合，规则快筛 + 模型精排 + 大模型兜底，在延迟与准确率之间分层取舍；三是闭环，拦截与漏放样本回流到训练与词库，形成攻防迭代。同时要防止审核系统自身被绕过：对输入做规范化（Unicode 归一、同音/形近字还原）后再匹配，避免简单变形逃逸。

## 三、形式化与数学基础

对每个样本 $x$，分类器输出风险向量 $\mathbf{p} = (p_1,\dots,p_K)$，三级决策规则为：

$$ \text{action}(x) = \begin{cases} \text{block}, & \max_k p_k > \tau_{\text{high}} \\ \text{review}, & \tau_{\text{low}} < \max_k p_k \le \tau_{\text{high}} \\ \text{pass}, & \text{otherwise} \end{cases} $$

阈值决定误伤—漏放权衡。以风险类别 $k$ 为例：

$$ \text{FPR}_k = \frac{|\{x: \hat{y}_k=1, y_k=0\}|}{|\{x: y_k=0\}|}, \qquad \text{FNR}_k = \frac{|\{x: \hat{y}_k=0, y_k=1\}|}{|\{x: y_k=1\}|} $$

ROC/PR 曲线上的工作点即合规要求的平衡点。由于有害样本通常稀疏，PR 曲线比 ROC 更能反映真实表现。多信号融合可用加权对数几率：

$$ s(x) = \sum_{m} w_m \log \frac{p_m(x)}{1 - p_m(x)} + b $$

其中 $m$ 遍历规则、模型、裁判等信号，$w_m$ 由验证集拟合。融合的价值在于各信号错误相关性低时显著降低总体漏放。

## 四、代码实现

```python
# 多信号融合审核与分级处置（示意）
import unicodedata


def normalize(text):
    # 输入规范化：先归一再匹配，抵抗全角/变体/零宽字符绕过
    text = unicodedata.normalize("NFKC", text)
    return "".join(ch for ch in text if unicodedata.category(ch) != "Cf")


def rule_hits(text, lexicon):
    # 规则层：快筛，命中即进入高优先级
    return [w for w in lexicon if w in text]


def moderate(text, clf, lexicon, tau_high=0.9, tau_low=0.5, w=(1.0, 1.0)):
    text_n = normalize(text)
    hits = rule_hits(text_n, lexicon)
    probs = clf.predict_proba(text_n)          # dict: 类别 -> 概率
    peak = max(probs.values())

    # 融合：规则命中提升风险分，模型分提供泛化能力
    score = w[0] * peak + w[1] * (1.0 if hits else 0.0)
    if score > tau_high or len(hits) >= 3:
        return "block", {"probs": probs, "hits": hits, "score": score}
    if score > tau_low:
        return "review", {"probs": probs, "hits": hits, "score": score}
    return "pass", {"probs": probs, "hits": hits, "score": score}


# 业务侧：block 拦截或安全改写，review 转人工，同时留痕回流样本池
action, detail = moderate(user_text, moderation_model, sensitive_lexicon)
if action == "block":
    resp = safe_refuse()
elif action == "review":
    resp = enqueue_human_review(user_text, detail)
else:
    resp = generate(user_text)
log_audit(user_text, resp, action, detail)
```

## 五、与其他技术对比

- 纯规则 vs 纯模型：规则快、可解释、易热更，但泛化差；模型泛化好但需训练与算力，且可解释性弱。
- 输入审核 vs 输出审核：输入审核防有害意图与提示注入，输出审核防有害结果，二者互补缺一不可。
- 单分类器 vs 多信号融合：融合显著提升鲁棒性，代价是延迟、成本与调参复杂度。
- 硬拦截 vs 安全改写：拦截最安全但伤体验；改写保留可用性，但需保证不残留风险信息。

## 六、常见误区

- 「一次配置永久有效」：对抗手法不断升级，词库与模型必须持续更新并做回归测试。
- 「阈值越高越安全」：阈值过高会漏放更多隐性有害内容，安全不等于高阈值。
- 「只靠关键词」：变体、谐音、拆字、编码即可绕过，必须结合语义模型与输入规范化。
- 「分类器没有偏差」：审核模型对特定方言、族群语言或少数群体话题可能过判，需做公平性审计。

## 九、演进与趋势

审核过滤正从「关键词 + 单分类器」走向「多模态统一审核 + 大模型裁判 + 实时对抗」：用强模型做上下文级判定以理解讽刺与隐晦表达；把审核嵌入推理管线实现低延迟流式拦截；用红队自动化持续挖掘绕过手法反哺训练，形成攻防闭环；同时加强审核系统的可解释性（输出命中理由与证据片段）与公平性审计，使拦截决策可被复核与申诉。

## 十、小结

审核与过滤是内容安全体系的关键闸门。依靠规则、模型与语义多层融合，在误伤与漏放之间持续求平衡，并通过反馈闭环不断进化，才能真正守住上线底线。
