# 内容安全体系

> 对应 OWASP Top 10 for LLM Applications 与国内《生成式人工智能服务安全基本要求》（具体条款以官方最新文档为准）。

## 一、背景与挑战

生成式大模型在开放问答、Agent 工具调用、多模态生成等场景中，可能产出违法不良信息、歧视性内容、虚假信息或泄露隐私。单点防护（例如只做输出过滤）容易被绕过，且事后处置成本高。核心挑战在于：风险分布在「输入—检索—生成—输出—传播」全链路，任何一环缺失都会成为短板；攻击者会针对最弱环节（如检索投毒、间接提示注入）而非正面突破；模型能力越强、开放度越高，越需要体系化约束兜底；同时体系必须覆盖文本、图像、音频、视频与多语种场景。

## 二、核心原理

内容安全体系遵循「事前—事中—事后—反馈」的全链路闭环：

1. 事前（输入侧）：对用户提示做风险意图识别、越狱与提示注入检测、敏感主体识别；对 RAG 检索结果做来源可信度过滤与投毒检测；对工具调用做参数白名单与权限校验。
2. 事中（生成侧）：通过系统提示、安全微调、RLHF/RLAIF 对齐降低有害输出概率；对高风险场景（代码执行、医疗、法律、金融）启用更严格护栏与人工确认。
3. 事后（输出侧）：对生成结果做分类器与规则扫描，命中则拦截、降级、安全改写或附加风险提示；多模态输出需做跨模态一致性检测。
4. 反馈闭环：记录拦截与漏放事件，人工复核边界样本，把新绕过手法沉淀为规则与训练数据，反哺前三层。

体系设计的核心思想是纵深防御（defense in depth）：单层必然存在漏检，多层叠加且层间机制异构（规则、模型、检索、人工）才能显著提升鲁棒性。另一个要点是「降级优先于硬拒」：对边界样本给出受限但有用的回答，比一律拒答更能兼顾安全与体验。

## 三、形式化与数学基础

设各层拦截率为 $p_i\ (i=1..n)$，在层间近似独立的假设下，整体漏过率：

$$ P_{\text{leak}} = \prod_{i=1}^{n} (1 - p_i) $$

可见增加层数或提升单层准确率，都能指数级降低漏过；但各层往往相关（同源模型共享盲区），真实收益低于独立假设，需实测校准而非照搬公式。

输出审核的阈值选择可写成代价最小化问题：

$$ \text{Cost} = \alpha \cdot N_{\text{miss}} + \beta \cdot N_{\text{false}} + \gamma \cdot L $$

其中 $\alpha$ 为漏放代价（高）、$\beta$ 为误伤代价、$\gamma \cdot L$ 为审核引入的延迟代价。求 $\min \text{Cost}$ 即得工作阈值。

端到端安全水位可用「暴露量」刻画，设请求量为 $Q$、有害意图占比 $\pi$、漏过率 $P_{\text{leak}}$：

$$ E = Q \cdot \pi \cdot P_{\text{leak}} $$

体系建设的目标就是把 $E$ 压到监管与业务可接受的水平，而不是把 $P_{\text{leak}}$ 归零——后者在开放生成场景下无法达成。

## 四、代码实现

```python
# 全链路内容安全网关（示意）：输入→生成→输出→留痕→反馈
HIGH_RISK_DOMAINS = {"code_exec", "medical", "legal", "finance"}


def safe_generate(prompt, model, retriever=None, domain="general"):
    # 1) 事前：输入审核与提示注入检测
    if not input_safe(prompt):
        return refuse("请求违反内容安全策略"), {"stage": "input", "action": "block"}

    # 2) 事前：检索来源过滤，防止检索投毒
    context = []
    if retriever is not None:
        for doc in retriever(prompt):
            if source_trusted(doc) and not looks_injected(doc.text):
                context.append(doc)

    # 3) 事中：带安全系统提示生成，高风险场景收紧解码参数
    sys_prompt = SAFETY_SYSTEM_PROMPT
    if domain in HIGH_RISK_DOMAINS:
        sys_prompt += "\n该场景高风险：不确定时必须声明不确定性并建议人工核实。"
        out = model(prompt, system=sys_prompt, context=context, temperature=0.0)
    else:
        out = model(prompt, system=sys_prompt, context=context)

    # 4) 事后：输出审核与分级处置
    labels = moderation(out)
    peak = max(labels.values())
    if peak > TAU_HIGH:
        action = "rewrite"
        out = safe_rewrite(out)          # 安全改写或拒答
    elif peak > TAU_LOW:
        action = "review"                # 转人工复核
        out = with_disclaimer(out)
    else:
        action = "pass"

    # 5) 留痕与反馈：事件进入审计日志与样本池
    log_audit(prompt, out, model.version, labels, action)
    return out, {"stage": "output", "action": action, "labels": labels}
```

## 五、与其他技术对比

- 单点审核 vs 体系化：单点易被针对性绕过；体系化通过多层互补提升鲁棒性，代价是延迟与工程复杂度。
- 关键词规则 vs 分类模型：规则可解释、零延迟、零样本，但易被变体绕过；模型泛化好但需维护、校准与算力。
- 外部审核 vs 模型内对齐：外审是硬性兜底，模型内对齐降低有害输出的发生概率，二者不可互相替代。
- 硬拒答 vs 安全改写：硬拒最安全但伤体验；降级改写兼顾可用性，但需保证改写后不残留风险。

## 六、常见误区

- 「模型自己会拒答」：对齐存在分布外失效与越狱风险，必须保留外部审核兜底。
- 「只做输出过滤」：忽略输入侧提示注入、检索投毒与工具滥用，防护不完整。
- 「一套规则全球通用」：不同语种、文化与法域对违规的界定不同，需要本地化词库与判定口径。
- 「层层加码就更好」：层数增加带来延迟与误伤累积，应按实测漏过率与成本选择层数。

## 九、演进与趋势

内容安全体系从「关键词 + 输出过滤」走向「检测—生成—验证」一体化：用强模型做上下文感知审核，理解讽刺、隐晦与组合风险；用红队自动化持续挖掘新绕过手法并反哺规则与训练；把安全能力下沉到推理引擎（如在服务框架的调度与输出阶段挂载护栏）以降低延迟；并以合规可审计为目标建设统一安全中台，实现策略集中管理、热更新与跨产品线复用。

## 十、小结

体系化是内容安全的底座：用事前、事中、事后的纵深防御把风险关进可控范围，并用反馈闭环持续加固，是模型合规上线的工程前提。
