# 生成标识与披露

> 对应国内《人工智能生成合成内容标识办法》、C2PA（Coalition for Content Provenance and Authenticity）与 Kirchenbauer et al. 2023 文本水印工作（具体要求以官方最新文档为准）。

## 一、背景与挑战

当大模型广泛参与文本、图像、音频、视频的合成与编辑，用户往往难以辨别内容是否由 AI 生成，由此带来误导、虚假信息扩散、版权争议与信任危机。监管要求服务提供者对 AI 生成内容进行标识，并在文件元数据层面保留机器可校验的来源凭证。核心挑战有四：一是显式标识（如「AI 生成」字样或角标）容易被裁剪、截图或伪造；二是隐式标识（水印）需在不可感知性、鲁棒性与对内容质量的损伤之间权衡；三是内容跨平台传播、二次编辑后标识容易丢失；四是不同平台标识口径与元数据格式不统一，缺乏互认机制。因此需要显式与隐式双轨并行，并推动跨平台互认。

## 二、核心原理

生成标识与披露由三层构成：

1. 显式标识（面向用户的披露）：在内容的可见位置附加提示。文本可直接拼接前缀或后缀说明；图像在角标叠加半透明标识；音视频在片头片尾或画面角落声明；交互式服务还需在界面上明示。
2. 隐式标识（面向机器核验）：在生成阶段嵌入人眼不可感知但算法可检测的信号。文本水印通过偏置采样分布（如绿色列表词表）留下统计痕迹；图像水印多在频域或潜变量空间嵌入；音频可用扩频或相位编码。
3. 元数据凭证（面向跨平台追溯）：遵循 C2PA 等标准，把生成工具、时间、模型信息、编辑历史写入签名的元数据清单（manifest），并配合哈希绑定内容本身，防止凭证被剥离后冒用。

三者分工明确：显式标识保障用户知情权，隐式水印提供内容绑定的抗裁剪证据，元数据凭证提供可验证的来源链。工程上应在生成引擎内原生集成，而不是事后追加，否则容易被绕过或遗漏。

## 三、形式化与数学基础

以文本绿色列表水印为例：把词表按伪随机方式划分为绿色集合 $G$ 与红色集合 $R$，采样时给绿色词的 logits 加偏置 $\delta$，检测时用基于比例的统计量：

$$ z = \frac{|\hat{G}| - \gamma |S|}{\sqrt{\gamma(1-\gamma)|S|}} $$

其中 $|S|$ 为生成 token 数，$\gamma = |G|/|V|$ 为绿色词比例，$|\hat{G}|$ 为实际落在绿色集合的 token 数。在零假设（无水印）下该统计量近似服从标准正态分布，$|z|$ 越大越可能带水印。

对连续型水印分数 $s_w$，可按似然比判决：

$$ \Lambda = \frac{P(\text{content} \mid H_1)}{P(\text{content} \mid H_0)} \mathop{\gtrless}_{\text{no-wm}}^{\text{wm}} \tau $$

阈值 $\tau$ 决定误报与漏检。水印方案的质量可用三个指标联合刻画：不可感知性（对困惑度或感知质量的影响）、鲁棒性（经改写/压缩/翻译后 $|z|$ 的衰减）与误报率（人类文本被误判的比例）。这三者相互制约，需在给定场景下选取工作点。

## 四、代码实现

```python
# 显式披露 + 隐式文本水印检测（示意）
import hashlib


def disclose(output, tag="【AI生成】"):
    # 显式标识：面向用户的可见披露
    return f"{tag}{output}"


def green_set(vocab, key, gamma=0.5):
    # 用密钥派生伪随机绿色词表，保证检测方可复现
    greens = set()
    for w in vocab:
        h = hashlib.sha256((key + w).encode()).hexdigest()
        if int(h[:8], 16) / 0xFFFFFFFF < gamma:
            greens.add(w)
    return greens


def detect_watermark(tokens, greens, gamma=0.5, tau=4.0):
    # 绿色列表水印的 z 检验
    n = len(tokens)
    if n == 0:
        return False, 0.0
    g = sum(1 for t in tokens if t in greens)
    z = (g - gamma * n) / (gamma * (1 - gamma) * n) ** 0.5
    return abs(z) > tau, z


# 元数据凭证：把内容哈希与生成信息写入签名清单
def build_manifest(content_bytes, model_id, tool="demo-llm"):
    import json
    manifest = {
        "claim_generator": tool,
        "model": model_id,
        "content_hash": hashlib.sha256(content_bytes).hexdigest(),
    }
    body = json.dumps(manifest, sort_keys=True).encode()
    return manifest, sign(body)   # sign 由平台私钥完成，验证方用公钥校验
```

## 五、与其他技术对比

- 显式标识 vs 隐式水印：显式对人友好、实现简单，但易被裁剪；隐式抗裁剪，但需专用检测器且存在误报。
- 元数据凭证（C2PA）vs 内容水印：凭证信息丰富、可验证签名，但随文件流转可能被剥离；水印绑定内容本身，鲁棒但承载信息少。
- 生成时嵌入 vs 事后添加：生成时嵌入可作用于潜变量与采样过程，鲁棒性更好；事后添加易被去除且可能损伤质量。
- 被动平台标注 vs 主动生成方披露：主动披露责任更明确，也更符合监管对服务提供者的要求。

## 六、常见误区

- 「只做隐式水印即满足合规」：监管通常要求「显著标识」，仅靠不可见水印不足以保障用户知情权。
- 「标识一次写入永久有效」：内容经多次编辑、转码、转发后标识可能丢失，需多副本冗余与跨平台校验。
- 「水印不可破解」：强压缩、改写、翻译、重绘都会削弱水印，需多层鲁棒设计并明确保密假设。
- 「水印等于事实核查」：水印只证明内容的生成来源，不证明内容陈述的真实性，二者不可混淆。

## 七、与开源书·权威来源对应

- 国内《人工智能生成合成内容标识办法》：明确显式与隐式标识的义务、主体与实现方式（以最新发布版本为准）。
- C2PA（Coalition for Content Provenance and Authenticity）：跨行业的内容来源与真实性元数据标准，定义 manifest 与签名机制。
- Kirchenbauer et al. 2023：提出绿色列表文本水印及统计检测方法，是后续水印工作的重要基线。
- HuggingFace Transformers：提供带水印生成与检测的实验性实现，可作为工程参考（接口以官方最新文档为准）。

## 九、演进与趋势

标识机制正从「可见文字 + 简单水印」走向「语义鲁棒水印 + 可验证来源链 + 跨平台互认」：研究对改写、翻译、重绘仍可检测的图像与视频水印；用去中心化或第三方公证增强元数据不可篡改；在生成引擎内原生集成标识，确保从源头落地；并推动不同平台之间的标识互认与校验接口标准化，使标识在传播链条中不至于断链。

## 十、小结

生成标识与披露保障用户的知情权与内容的可追溯性，是 AI 内容治理的基础设施。显式与隐式结合、内容与元数据双轨、跨平台贯通，才能真正发挥作用。
