# 多语言表示对齐

> 对应 Conneau 2020 XLM-R 与 Artetxe 2019 跨语言对齐。

## 一、背景与挑战

多语言模型希望用一套参数处理多种语言，并实现「零样本跨语迁移」：在英语上微调的任务，能直接用于法语、中文等未微调语言。难点在于不同语言词表、形态、语序各异，若表示空间各语言各自为政，跨语相似语义（如英文「cat」与中文「猫」）的向量会相距很远，迁移无从谈起。

核心挑战有三：(1) 如何在没有平行语料时让不同语言相近义项向量接近；(2) 低资源语言数据稀少，表示质量天然偏低；(3) 共享子词切分会导致高资源语言「抢占」表示空间，低资源语言被边缘化。对齐（alignment）就是把各语言的语义锚定到同一几何空间。

## 二、核心原理

主流做法是「共享子词词表 + 对齐式预训练目标」。以 XLM-R 为例：它在上百种语言上用共享的 SentencePiece 词表做掩码语言建模（MLM），由于同一子词（如拉丁字母词根）跨语言共享，模型被迫在不同语言间复用表示，从而隐式对齐。更显式的路线用平行句（翻译对）做翻译语言建模（TLM）或对比对齐：把互为翻译的句子编码到相近向量。

对齐可分两类：(1) 词级对齐——用 bilingual dictionary 把一种语言的词向量线性映射到另一种（如通过正交 Procrustes 求旋转矩阵 $W$ 使 $\|W X - Y\|_F$ 最小）；(2) 句级对齐——用平行句对比，使翻译对句向量接近。二者都依赖「分布假设在跨语言中成立」：相似上下文产生相似表示，因此共享上下文结构的语言会自然趋同。

实践中还常用「翻译对对比」显式拉近跨语言同义句：把互为翻译的句子编码到相近向量，比纯共享词表更直接的利用平行语料。低资源语言常通过高资源语言「桥接」获得能力，但也会被高资源语言在共享表示空间中抢占主导，需用按语言采样加权或温度调节缓解。评测多用 Tatoeba 句向量检索、XTREME 跨语言任务，验证零样本迁移效果。

## 三、形式化与数学基础

词级对齐常归结为求解正交映射 $W \in \mathbb{R}^{d\times d}$（保持向量长度与夹角）：

$$ \min_{W^\top W = I} \| W X - Y \|_F^2 $$

闭式解为 $W = U V^\top$，其中 $U \Sigma V^\top = \mathrm{svd}(Y X^\top)$（Procrustes 分析）。句级对比对齐的损失：

$$ \mathcal{L} = -\log \frac{\exp(\mathrm{sim}(\mathbf{u}_s, \mathbf{u}_t)/\tau)}{\sum_{k} \exp(\mathrm{sim}(\mathbf{u}_s, \mathbf{u}_{t_k})/\tau)} $$

其中 $(s,t)$ 为平行句对，其余 $t_k$ 为负例。

## 四、代码实现

```python
import torch
import torch.nn.functional as F

def procrustes_align(src_vecs, tgt_vecs):
    # src_vecs, tgt_vecs: [K, d] 互为翻译的种子词典向量
    M = tgt_vecs.t() @ src_vecs          # [d, d]
    U, S, Vh = torch.linalg.svd(M)
    W = U @ Vh                           # 正交旋转矩阵
    return W

def xlmr_sentence_sim(model, tokenizer, sent_a, sent_b):
    # 共享编码器对不同语言句做句向量对比（以官方最新文档为准）
    def encode(s):
        ids = tokenizer(s, return_tensors="pt")
        h = model(**ids).last_hidden_state
        return F.normalize(h.mean(dim=1), dim=-1)
    return float(encode(sent_a) @ encode(sent_b).t())
```

## 五、与其他技术对比

| 方法 | 是否需要平行语料 | 对齐粒度 | 低资源友好度 |
|------|------------------|----------|--------------|
| 共享词表 MLM（XLM-R） | 否 | 隐式、词/句 | 中（被高资源主导） |
| TLM 翻译语言建模 | 是（平行句） | 句级 | 较好 |
| 词级 Procrustes | 是（种子词典） | 词级 | 依赖词典质量 |
| 无监督映射（MUSE） | 否（对抗） | 词级 | 较好 |

## 六、常见误区

误区一：共享词表即自动对齐——仅提供对齐可能，高资源语言仍会主导空间。误区二：低资源语言「免费」获得能力——其表示质量受数据量硬约束。误区三：对齐后可丢弃源语言——跨语迁移仍受领域偏移影响。误区四：所有语言对称贡献——实际训练损失被高资源语言主导，需采样加权。

## 八、面试题

1. 多语言模型如何实现跨语言零样本迁移？共享子词 + 对齐预训练目标使跨语同义向量接近，英语微调可迁移到未微调语言。
2. 为什么低资源语言表示质量低？数据稀少 + 高资源语言在共享空间中占主导。
3. Procrustes 对齐做什么？用正交旋转矩阵把一种语言词向量空间映射到另一种，保持几何关系。
4. TLM 与 MLM 区别？TLM 在平行句拼接上做掩码，显式利用翻译对对齐句表示。

近期工作把跨语言对齐从「表示接近」推进到「任务对齐」：同一指令在多语言下触发一致行为。低资源语言通过高资源桥接 + 主动学习补充平行语料。多模态对齐（如文本-语音联合）沿用了 XLM-R 的共享子词思路。评测覆盖 XTREME、FLORES 等，强调零样本与少样本跨语迁移。

## 九、演进与趋势

从 XLM 的 TLM，到 XLM-R 的大规模纯 MLM 对齐，再到用平行语料 + 对比学习的显式句对齐。趋势包括：按语言采样加权缓解高资源主导；把多语言对齐扩展为多模态对齐（文本-图像-语音）；以及用指令微调统一跨语言任务格式，让「零样本跨语」更稳。

落地多语言检索/分类时，优先用 XLM-R 类共享子词预训练，再轻量微调。
低资源语言靠高资源桥接 + 主动学习补平行语料，并用采样加权防高资源主导。
对齐质量用 Tatoeba 句向量检索、XTREME 跨语言任务验证零样本迁移效果。
若只需双语，用平行句做翻译对对比比纯共享词表更直接。
评测要覆盖真正低资源语言，而非只在高资源语言上报告均值。
共享词表是基础，但高资源语言会抢占表示空间，需温度/采样调节。
词级 Procrustes 对齐用正交旋转矩阵把一种语言映射到另一种，保持几何。
句级对齐用平行句对比损失，使翻译对句向量接近。
多模态对齐（文本-语音）沿用 XLM-R 共享子词思路，统一表示空间。
零样本跨语迁移依赖对齐质量，未对齐语义仍会掉点。
指令微调把「跨语言任务对齐」从表示接近推进到行为一致。
领域术语在多语言下易失配，需领域平行语料补强。
评测指标除准确率外，应看跨语言一致性（如各语言方差）。
部署时按语言路由或统一模型，权衡成本与效果。

## 十、小结

多语言表示对齐让不同语言的同义概念落在同一向量邻域，是跨语零样本迁移的前提。其实现依赖共享子词、对齐预训练目标与（可选）平行语料，权衡点在是否需要平行数据、低资源语言是否被边缘化。对齐质量直接决定跨语言能力上限。
