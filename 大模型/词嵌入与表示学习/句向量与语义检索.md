# 句向量与语义检索

> 对应 Reimers & Gurevych 2019 SBERT（Sentence-BERT）。

## 一、背景与挑战

句向量（sentence embedding）是把整句话映射为定长向量，使语义相似的句子在向量空间接近，从而支撑语义检索、去重、聚类、相似度排序等任务。它是 RAG（检索增强生成）检索模块的底座——检索召回质量直接取决于句向量质量。

核心挑战：原生 BERT 用 `[CLS]` 池化得到的句向量在语义相似度任务上表现很差——同一句话不同表述的向量距离，可能大于不同语义句子的距离；且 BERT 逐对编码（把两句话拼一起做分类）无法离线建库，检索时要对每对 query-doc 推理，成本不可接受。需要一种能产生「可直接用余弦度量的句向量」的编码方式，且能离线批量编码文档。

## 二、核心原理

SBERT（Sentence-BERT）用「孪生网络 / 三胞胎网络」结构：两个共享权重的 BERT 编码器分别编码句子 A、B，再用池化（mean-pooling 或 max-pooling）把 token 序列压成句向量，最后用余弦相似度或 MSE / 三元组损失做对比微调，使语义相近的句子向量靠近。

训练目标常用三元组损失：锚点 $a$、正例 $p$、负例 $n$，要求

$$ \|\mathbf{u}_a - \mathbf{u}_p\| < \|\mathbf{u}_a - \mathbf{u}_n\| - \varepsilon $$

这样句向量空间具备「余弦/欧氏距离即可度量语义相似」的性质，离线把全部文档编码入库，检索时只编码 query 一次并做近邻搜索，复杂度从 $O(N)$ 对推理降到 $O(1)$ 查表。

检索落地还需配套近邻索引：文档向量入库后，线上用 FAISS / Annoy 等 ANN 结构做近似最近邻，避免暴力 $O(N)$ 扫描。相似度通常用余弦（向量先 L2 归一化，点积即余弦）。领域迁移时，通用句向量模型在垂直语料上可能退化，需用领域平行/检索对做继续对比训练（领域适配）。此外，长文档需先做切分再编码，检索命中片段后回灌原文，这与 RAG 的「召回-重排」两段式一致。

## 三、形式化与数学基础

设编码器为 $E(\cdot)$，池化函数 $\mathrm{pool}(\cdot)$。句向量 $\mathbf{u} = \mathrm{pool}(E(s))$。三元组损失：

$$ \mathcal{L}_{\mathrm{triplet}} = \max\left(0,\; \|\mathbf{u}_a-\mathbf{u}_p\|^2 - \|\mathbf{u}_a-\mathbf{u}_n\|^2 + \varepsilon \right) $$

若用余弦相似度，则相似度 $\mathrm{sim}(a,b) = \frac{\mathbf{u}_a^\top \mathbf{u}_b}{\|\mathbf{u}_a\|\|\mathbf{u}_b\|} \in [-1,1]$。mean-pooling 取最后一层所有 token 隐状态的平均；实验表明其通常优于单取 `[CLS]`，因为 `[CLS]` 在预训练中未被显式训练为句级语义聚合点。

## 四、代码实现

```python
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")

docs = ["如何重置路由器密码", "路由器登录入口打不开怎么办", "今天天气真好"]
doc_vecs = model.encode(docs, normalize_embeddings=True)   # 离线建库

q = "怎么改 WiFi 密码"
q_vec = model.encode([q], normalize_embeddings=True)[0]

# 余弦相似度 = 点积（已归一化）
scores = doc_vecs @ q_vec
top = int(np.argmax(scores))
print(docs[top], float(scores[top]))
```

## 五、与其他技术对比

| 方法 | 是否可离线建库 | 相似度质量 | 备注 |
|------|----------------|------------|------|
| BERT `[CLS]` 直接取 | 否（需成对） | 差 | 未经句向量对比训练 |
| SBERT 孪生 + pooling | 是 | 好 | 检索标配 |
| SimCSE | 是 | 好 | dropout 正例，无标注也可 |
| 词向量平均（Word2Vec） | 是 | 一般 | 忽略词序与句法 |

## 六、常见误区

误区一：BERT 原生 `[CLS]` 向量即可做检索——未经过句级对比训练，语义判别弱。误区二：句向量空间天然各向同性——实际常各向异性，需归一化或白化（见「表示空间几何」）。误区三：池化方式无影响——mean-pooling 通常优于 CLS，但具体任务需实验。误区四：编码一次永久有效——分布随模型与领域漂移，检索库需定期刷新。

## 八、面试题

1. 为什么 BERT 原生 `[CLS]` 不适合检索？它未经句级对比训练，同义句距离可能大于异义句；且需成对编码无法离线建库。
2. SBERT 如何做到可离线检索？孪生共享编码器分别编码，句向量可批量入库，检索只编码 query 一次。
3. mean-pooling 为何通常优于 CLS？CLS 未被显式训练为句语义聚合点，mean 聚合全部 token 信息更稳。
4. 三元组损失的 margin 作用？拉开正负例距离下限，防止模型把所有向量压到一点。

指令微调（instruction tuning）让句向量模型理解「以什么视角比较相似」（如语义 vs 字面），催生「按指令检索」。生成式检索则用模型直接生成文档 id 或摘要，与稠密检索互补。长文档需分层表示（句→段→文档）与迟交互（ColBERT 式多向量）提升细粒度。评测从 STS 扩展到 BEIR 等跨领域基准。

## 九、演进与趋势

从 SBERT 到大规模对比训练的通用句向量模型（如基于 SimCSE、难负例挖掘的变体），再到多语言句向量与「检索 + 重排」两段式架构。向量数据库（ANN 索引）与量化压缩使亿级文档近邻检索毫秒级。趋势是把句向量与生成式检索、指令微调结合，支撑更细粒度语义匹配。

检索落地分三步：离线把文档编码入库、线上编码 query、ANN 近邻返回候选。
相似度统一用余弦（向量先归一化，点积即余弦），避免用欧氏距离混用。
领域迁移用领域检索对继续对比训练，或做表示白化适配通用模型。
长文档先切分再编码，命中片段回灌原文，与 RAG 的「召回-重排」两段式一致。
评测用 BEIR 等跨领域基准，而非单一 STS，更能反映真实检索鲁棒性。
mean-pooling 通常优于取 CLS，因为 CLS 未被显式训练为句级语义聚合点。
迟交互（ColBERT 式多向量）保留词级对齐，细粒度优于单向量但存储更高。
生成式检索用模型直接生成文档 id，与稠密检索互补，适合候选有限的场景。
指令微调让模型理解「以什么视角比较相似」，催生按指令检索。
量化（PQ/SQ）是亿级库落地的必选项，需权衡召回率与内存。
向量索引选型（IVF/HNSW）取决于数据规模与查询 QPS。
去重、聚类等任务同样消费句向量，余弦阈值需按数据分布标定。
检索召回不足时优先查表示质量，而非直接加重排模型。
监控线上召回与延迟，定期用新语料刷新向量库防分布漂移。

## 十、小结

句向量让「自然语言句子」可被余弦/欧氏距离直接比较，是语义检索与 RAG 的底座。SBERT 用孪生网络 + pooling + 对比损失，解决了 BERT 不可离线建库与 `[CLS]` 判别弱的问题。池化方式、分布各向异性与检索库刷新，是落地时最易被忽视的要点。
