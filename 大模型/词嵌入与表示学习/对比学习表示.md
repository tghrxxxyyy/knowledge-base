# 对比学习表示

> 对应 Gao 2021 SimCSE 与 Radford 2021 CLIP。

## 一、背景与挑战

无标注语料规模远大于人工标注，如何在没有显式监督信号的情况下学到「语义相近向量相近、语义相远向量相远」的可迁移表示，是对比学习要解决的核心问题。传统静态词嵌入（Word2Vec、GloVe）只能给出词级、上下文无关向量，且整句或整文档需要再做池化，效果有限。

对比学习的动机是：与其预测具体的标签，不如构造「什么该靠近、什么该远离」的相对关系。只要正例（语义一致）与负例（语义不同）定义得当，模型就能在海量无标注数据上自我监督地学到判别性表示。难点在于：(1) 正例从哪来——需要一种低成本、可扩展地产生「同一语义不同视角」样本的方法；(2) 负例是否足够——负例太少会让模型走捷径（collapse 到常数向量）；(3) 温度等超参如何平衡难负例的权重。

## 二、核心原理

对比学习把表示学习写成一个度量学习问题：给定锚点 $z$，一个正例 $z^+$ 与若干负例 $\{z_k\}$，目标是让 $\mathrm{sim}(z, z^+)$ 尽量大、$\mathrm{sim}(z, z_k)$ 尽量小。这里的相似度通常是余弦相似度，编码器一般是一个共享权重的双塔（bi-encoder），正例来自数据增强或天然配对。

两条代表性路线：SimCSE 用「dropout 噪声即增广」——同一句话过两次同一编码器，因 dropout 的随机性得到两个略有差异的向量，互为正例，无需任何外部标注；CLIP 则用图文对（一张图与其描述文本）作为天然正例，图像塔与文本塔分别编码后对比。两条路线共享同一损失骨架 InfoNCE，只是正例构造方式不同。关键设计是温度系数 $\tau$：它缩放 logit，控制分布锐度，过小会让难负例被过度强调、易过拟合，过大会让所有样本梯度趋平。

从工程实现看，batch 构造直接决定负例质量：SimCSE 用同一 batch 内其他句子作为 in-batch 负例，batch 越大负例越充分，但受显存约束；CLIP 则用配对中其余图文作为跨模态负例。难负例（语义相近但非正例）对表示判别力贡献最大，实践中常通过离线检索召回难负例，或用动量记忆队列（MoCo 思路）在批次间复用负例，弥补 batch 受限时的负例不足。dropout 正例的随机性要足够，否则两次编码差异过小，正例信号被淹没。

## 三、形式化与数学基础

InfoNCE 损失可写成对「当前 batch 内正例」的分类交叉熵：

$$ \mathcal{L} = -\mathbb{E}\left[ \log \frac{\exp(\mathrm{sim}(z, z^+)/\tau)}{\sum_{k=1}^{N} \exp(\mathrm{sim}(z, z_k)/\tau)} \right] $$

其中 $z_k$ 包含唯一的正例 $z^+$ 与其余 $N-1$ 个负例（in-batch negatives）。当相似度取余弦 $\mathrm{sim}(z, z') = \frac{z^\top z'}{\|z\|\|z'\|}$ 时，分母的归一化项 $Z = \sum_k \exp(\mathrm{sim}(z,z_k)/\tau)$。可证明，最小化该损失等价于最大化 $z$ 与 $z^+$ 互信息的下界，这正是「InfoNCE = Info Noise-Contrastive Estimation」的由来。温度 $\tau$ 越大，分布越平滑，模型越关注「把正例从负例中挑出」而非区分难负例；$\tau$ 越小，梯度越集中于难负例。

## 四、代码实现

```python
import torch
import torch.nn.functional as F

def simcse_loss(z, tau=0.05):
    # z: [2B, d]，同句两次编码相邻排列 -> 正例为 i 与 i+B
    z = F.normalize(z, dim=-1)
    sim = z @ z.t() / tau          # 余弦相似度 / 温度
    B = z.size(0) // 2
    mask = torch.eye(2 * B, dtype=torch.bool, device=z.device)
    sim = sim.masked_fill(mask, -1e9)   # 排除自身
    # 正例：第 i 行对应第 i+B 列
    labels = torch.arange(B, device=z.device)
    labels = torch.cat([labels + B, labels])
    return F.cross_entropy(sim, labels)

def clip_loss(image_feat, text_feat, tau=0.07):
    # 图文互为正例，batch 内其余为图文负例
    image_feat = F.normalize(image_feat, dim=-1)
    text_feat = F.normalize(text_feat, dim=-1)
    logits = image_feat @ text_feat.t() / tau
    labels = torch.arange(logits.size(0), device=logits.device)
    loss_i = F.cross_entropy(logits, labels)
    loss_t = F.cross_entropy(logits.t(), labels)
    return (loss_i + loss_t) / 2
```

## 五、与其他技术对比

| 方法 | 正例来源 | 负例来源 | 典型用途 |
|------|----------|----------|----------|
| SimCSE | dropout 两次编码 | in-batch | 句向量、语义检索 |
| CLIP | 图文对 | in-batch 跨模态 | 多模态检索、零样本分类 |
| SimCLR | 图像强增广 | in-batch | 视觉表示 |
| MoCo | 队列维护 | 动量编码器队列 | 视觉表示 |
| BYOL | 预测自身 | 无显式负例 | 视觉表示（靠不对称结构防塌缩） |

对比学习相比纯语言模型式「预测下一个 token」更关注整体语义相似度；与有监督分类相比，它对标注零依赖，且学到的表示迁移性更好。

## 六、常见误区

误区一：负例越多越好，于是无脑堆 batch。负例确实能提升下界质量，但过大的 batch 带来显存与重复负例问题，且当负例本身就语义相近时会引入噪声标签。误区二：SimCSE 不需要负例——它实际用 in-batch 中其他句子作为负例，若 batch 太小则正例信号被淹没。误区三：温度随便设——$\tau$ 直接决定难负例权重，常需网格搜索。误区四：对比学习学到的空间天然各向同性——实际上常出现各向异性，需用白化或归一化缓解（见「表示空间几何」）。

## 八、面试题

1. 为什么对比学习需要大量负例？因为 InfoNCE 是在「正例 vs 所有负例」上做分类，负例越多互信息下界越紧，表示越判别。
2. 温度 $\tau$ 的作用与取值陷阱？它缩放 logit 锐度，过小过拟合难负例、过大梯度消失，需调参。
3. SimCSE 没有显式负例如何工作？用同一 batch 内其他句子作为 in-batch 负例，dropout 提供正例。
4. 如何防止表示塌缩到常数向量？靠足够多负例 + 温度调节，BYOL 则用非对称预测头与停止梯度。

产业侧，对比句向量已成为检索与去重基础设施，配合向量数据库（ANN 索引 + 量化压缩）支撑亿级文档毫秒检索。多模态上，CLIP 范式催生了大量「文本-图像-视频」对齐模型，并衍生出用自然语言描述图像区域（region-text）的细粒度对比。可解释方向则关注「表示空间里语义轴是否可分解、可干预」，把对比学习与探针分析结合。

## 九、演进与趋势

从 SimCLR 的强增广 + 大 batch，到 MoCo 的队列解耦负例数量与 batch，再到 SimCSE 把 dropout 作为免费增广，对比学习逐步降低对昂贵增广与超大 batch 的依赖。CLIP 把范式推向「任意模态配对」。近年趋势包括：难负例挖掘、对比损失与 MSE 的融合（SimCSE 的PromptBERT 变体）、以及把对比目标与生成式预训练结合的「对比 + 生成」双塔架构。

实践上先确定正例来源：有平行句对用监督式 SBERT 三元组损失，无标注用 SimCSE 的 dropout 正例。
负例规模靠更大 batch 或动量队列（MoCo 思路）补充，难负例比随机负例贡献更大。
温度 τ 需网格搜索，常见区间 0.05–0.2，过小过拟合难负例、过大令梯度趋平。
句向量上线前必须 L2 归一化或白化，并用 STS/BEIR 召回率验证，而非只看训练 loss。
生产侧用 ANN 索引 + 乘积量化（PQ）控制内存与延迟，亿级文档可毫秒级检索。
跨语言/多模态场景直接采用 XLM-R、CLIP 式预训练，而非从零自训。
表示空间若各向异性严重，先做白化再检索，召回质量明显提升（见「表示空间几何」）。
dropout 正例的随机性要足够，两次编码差异过小会让正例信号被淹没。
对比损失与 MSE 的融合（如 PromptBERT）可进一步提升句向量判别力。
对比学习与生成式预训练结合（对比 + 生成双塔）是近期提升泛化的方向。
评测不要只用单数据集均值，要分领域看，避免高资源语言掩盖低资源退化。
蒸馏可把大模型句向量压到小模型，兼顾效果与延迟，是落地常用手段。
在线服务中把约束生成与句向量检索配合，能同时保证召回质量与输出结构。
监控检索召回与延迟的 trade-off，按业务 SLA 调索引参数与量化位数。

## 十、小结

对比学习用「拉近正例、推远负例」的相对监督，在无标注数据上学到高质量语义表示。SimCSE 与 CLIP 分别代表了文本内与跨模态两条成熟路线，其核心都是 InfoNCE 损失与温度调节。理解正例构造、负例规模与温度三者关系，是落地对比表示的关键。
