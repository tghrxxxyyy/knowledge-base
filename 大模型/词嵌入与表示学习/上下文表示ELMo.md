# 上下文表示 ELMo

> 对应 Peters 2018 ELMo（Deep contextualized word representations）。

## 一、背景与挑战

静态词嵌入（Word2Vec、GloVe）给每个词一个固定向量，无法区分一词多义：「苹果」在「吃苹果」与「苹果公司」中应不同。早期做法只能靠后期任务自己学上下文，但词级向量本身不含句法、语义角色信息。ELMo 的动机是：词的含义由它所处的上下文决定，表示应「依上下文动态生成」。

挑战来自两点：一是如何让同一词在不同语境得到不同向量；二是如何把这种上下文表示用到下游任务（如序列标注、问答），且不与已有静态嵌入冲突；三是 LSTM 类模型在长句上并行差、速度慢，相比后来的 Transformer 算力劣势明显。

## 二、核心原理

ELMo 预训练一个双向语言模型（biLM）：前向 LSTM 从左向右预测下一词，后向 LSTM 从右向左预测上一词，二者共享词表与嵌入层。对于输入句子，每个词在每一层 LSTM 都有一个隐状态；ELMo 将该词在各层隐状态做加权组合，得到上下文相关表示：

$$ \mathbf{h}_k^{\mathrm{ELMo}} = \gamma \sum_{j=0}^{L} s_j \mathbf{h}_{k,j} $$

其中 $j=0$ 是词嵌入层，$j\ge 1$ 是第 $j$ 层 LSTM 隐状态，$\gamma$ 是整体缩放，$s_j$ 是 softmax 归一化的层权重，由下游任务学习——这样任务可自行决定「更看重哪一层语义」（底层偏词法、顶层偏语义）。

值得补充的是，ELMo 的双向 LM 与前向/后向各自独立，并非真正深层双向交互——这点和后来 BERT 的 masked LM 不同。其词表示是字符级 CNN 编码后再送 LSTM，因此天然缓解未登录词问题。下游用法上，通常把 ELMo 向量与任务原有词特征拼接，而非替换，任务只学习层权重 s_j 与整体缩放 γ，预训练参数保持冻结，这种「特征型」用法区别于 BERT 的「微调型」。

## 三、形式化与数学基础

双向语言模型联合最大似然：

$$ \sum_{k=1}^{N} \left( \log p(t_k \mid t_1,\dots,t_{k-1}; \overrightarrow{\Theta}) + \log p(t_k \mid t_{k+1},\dots,t_N; \overleftarrow{\Theta}) \right) $$

ELMo 表示由各层隐状态的线性组合构成，组合权重 $s_j = \frac{\exp(w_j)}{\sum_{j'} \exp(w_{j'})}$。这种「特征型」用法（把 ELMo 向量拼到下游模型词特征上）与后来 BERT 的「微调型」用法不同：ELMo 通常冻结预训练参数，仅学习任务相关权重 $s_j$ 与 $\gamma$。

## 四、代码实现

```python
import torch
from allennlp.commands.elmo import Elmo, batch_to_ids

# 加载预训练 ELMo（选项文件 + 权重文件，以官方最新文档为准）
options = "https://allennlp.org/elmo-2x4096-512-2048cnn-2xhighway/options.json"
weights = "https://allennlp.org/elmo-2x4096-512-2048cnn-2xhighway/weights.hdf5"
elmo = Elmo(options, weights, num_output_representations=2, dropout=0)

sents = [["今天", "吃", "苹果"], ["苹果", "发布", "新品"]]
char_ids = batch_to_ids(sents)            # ELMo 基于字符 CNN，天然处理未登录词
emb = elmo(char_ids)["elmo_representations"]
# emb[0]: [2, 3, 1024] 第一层；emb[1]: 第二层。按层加权由下游任务学习
```

## 五、与其他技术对比

| 表示 | 上下文相关 | 训练方式 | 速度 | 多义处理 |
|------|------------|----------|------|----------|
| Word2Vec/GloVe | 否 | 无监督 | 快 | 不支持 |
| ELMo | 是（LSTM） | 双向 LM | 较慢（串行） | 支持 |
| BERT | 是（Transformer） | 掩码 LM | 较快（可并行） | 支持 |
| GPT | 是（单向） | 自回归 | 快 | 支持 |

ELMo 比 BERT 早，算力低、表达弱，但作为「静态到动态表示」的关键过渡，其「多层隐状态加权组合」思想影响深远。

## 六、常见误区

误区一：ELMo 与 BERT 等价，只是模型不同——二者范式不同，ELMo 是特征抽取、BERT 常微调整模型。误区二：ELMo 权重 $s_j$ 是固定的——它由下游任务学习，不同任务会偏向不同层。误区三：字符 CNN 输入意味着无需词表——字符级确实缓解未登录词，但推理开销更高。误区四：ELMo 已被完全淘汰——在轻量、可解释、冻结表示场景仍有用。

## 八、面试题

1. ELMo 如何实现上下文相关表示？通过双向 LSTM 预训练语言模型，取各层隐状态加权组合，权重由下游任务学习。
2. 为什么用两层 LSTM 而非一层？不同层捕获不同粒度信息，加权组合让任务自适应选择。
3. ELMo 与 BERT 的本质区别？ELMo 是特征型、冻结预训练；BERT 多微调整模型、基于 Transformer 自注意力。
4. 字符级输入的好处？天然处理未登录词与形态学变化，但推理更慢。

在如今大模型时代，ELMo 的「多层隐状态加权」思想仍以变体存在：指令微调中常对不同层表示做任务自适应加权，检索增强中把表示与来源句绑定。轻量场景（端侧、隐私）下，冻结的 ELMo 类表示因可解释、低成本仍有一席之地。总体看，上下文表示的范式已从「特征抽取」演进到「端到端微调 + 检索溯源」。

## 九、演进与趋势

ELMo 之后，BERT 用 Transformer 自注意力取代 LSTM，实现更深、可并行的上下文表示；GPT 系列走单向自回归路线。但「多层表示加权组合」的思路在 ULMFiT、技能适配与可解释表示中仍有回响。近年趋势是把上下文表示与检索增强结合，让表示既动态又可溯源。

ELMo 落地多采用「冻结预训练 + 下游拼接」用法：把各层加权向量拼到任务词特征上。
仅学习层权重 s_j 与整体缩放 γ，预训练参数保持冻结，区别于 BERT 的微调型。
字符级 CNN 输入使其天然抗未登录词，适合术语多变的垂直领域。
推理成本高于静态嵌入、低于 BERT 类 Transformer，适合端侧或可解释权重场景。
多层隐状态加权让任务自适应选择偏词法还是偏语义的层，灵活性强。
若追求更深上下文，应升级到 BERT/RoBERTa 并微调，而非加宽 ELMo。
评估上对比「加 ELMo」前后任务指标（如 NER F1）确认收益，避免无谓开销。
ELMo 的双向 LM 是前向/后向独立，并非真正深层双向，这一点弱于 masked LM。
冻结表示便于复现与调试，是科研与教学中的经典 baseline。
在需要句级而非词级表示时，ELMo 不如 SBERT，应按任务选模型。
长文档表示可对各词 ELMo 向量再做池化，但效果通常不如句级模型。
领域适配可用领域语料继续训练双向 LM，再冻结用于下游。
序列标注任务中 ELMo 常与 CRF 结合，提升标签转移的全局一致性。
部署时把 ELMo 向量离线算好缓存，线上只做拼接，控制延迟。

## 十、小结

ELMo 首次把「词的含义由上下文决定」做成可用产品：双向语言模型 + 多层隐状态加权组合，让同一词在不同句子得到不同向量。虽被 Transformer 系取代，但其「特征型上下文表示」范式与层权重自适应思想，仍是表示学习的重要一环。
