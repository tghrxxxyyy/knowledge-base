# 前缀缓存与提示复用

> 对应 Gim et al., *Prompt Cache*, 2024；Zheng et al., *SGLang RadixAttention*, 2023。

## 一、背景与挑战

多请求共享系统提示/长上下文前缀时，重复计算浪费；缓存可复用前缀 KV，省算力降延迟。

## 二、核心原理

把提示按语义边界（如段落/函数）切块并哈希，相同前缀直接复用已算 KV；RadixAttention 用基数树管理多请求共享前缀。

## 三、数学形式

复用节省 $S = \sum_i (|P_i| - |P_i\cap \text{cache}|)\cdot c_{step}$；命中率随共享度升。

## 四、代码实现

```python
# SGLang：相同前缀自动命中 RadixAttention 缓存
out = sg.lang.ainvoke("你是一个助手\n" + user_q)   # 前缀 KV 复用
```

## 五、与其他对比

- 与 增量解码 同依赖 KV 复用。
- 与 多智能体协同深入（共享系统提示）强相关。

## 六、常见误区

- 前缀微小差异致缓存失效（需对齐边界）。
- 缓存无淘汰策略致显存涨。

## 八、面试题

- 前缀缓存为何快？答：相同提示前缀的 KV 只算一次，多请求/多轮直接复用。

## 九、演进

无缓存 → 固定前缀缓存 → 基数树动态复用。

## 十、小结

前缀缓存通过共享 KV 复用，削减重复前缀的重复计算。
