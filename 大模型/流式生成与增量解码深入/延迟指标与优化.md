# 流式生成延迟指标（TTFT / TPOT）

> 对应 LLM 服务延迟指标（TTFT、TPOT、E2E）；与 推理经济成本深入 衔接。

## 一、背景与挑战

仅看端到端延迟掩盖体验问题；需拆首字延迟与逐字间隔分别优化。

## 二、核心原理

TTFT（Time To First Token）受 prefill 与排队影响；TPOT（Time Per Output Token）受解码步进与批处理影响；两者分别优化。

## 三、数学形式

$\text{TTFT}=T_{queue}+T_{prefill}$；$\text{TPOT}=T_{step}/1$（单 token 步时）；E2E $= \text{TTFT} + n\cdot \text{TPOT}$。

## 四、代码实现

```python
t0 = time(); first = next(stream)
ttft = time()-t0
toks = [first] + list(stream); tpot = (time()-t0-ttft)/len(toks)
```

## 五、与其他对比

- 与 投机解码（降 TPOT）、前缀缓存（降 TTFT）对应。
- 与 上下文压缩深入（降 prefill）联动。

## 六、常见误区

- 以平均延迟掩盖长尾首字延迟。
- 批过大降 TPOT 但涨 TTFT 需平衡。

## 八、面试题

- TTFT 与 TPOT 分别怎么降？答：TTFT 靠前缀缓存/并发调度，TPOT 靠投机解码/更优批处理。

## 九、演进

单延迟 → TTFT/TPOT 分治 → SLO 驱动调度。

## 十、小结

拆分 TTFT/TPOT 才能精准优化流式体验与成本。
