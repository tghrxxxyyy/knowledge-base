# 流式生成总览

> 对应 vLLM *PagedAttention*（Kwon et al., 2023）；DeepSpeed-FastGen（Holmes et al., 2024）。

## 一、背景与挑战

用户体验要求首字快、后续稳定吐字；服务端需高吞吐（连续批处理）与低延迟并存，涉及调度、缓存与解码协同。

## 二、核心原理

流式生成逐步输出 token：每次前向只算新 token 并复用 KV 缓存；服务端用连续批处理把多请求拼批，用 PagedAttention 管理变长 KV。

## 三、数学形式

第 $t$ 步输出 $x_t \sim p_\theta(\cdot \mid x_{<t}, KV_{<t})$；增量计算使每步复杂度 $O(1)$ 而非 $O(t)$（相对朴素重算）。

## 四、代码实现

```python
for token in model.generate(prompt, streamer=True, max_new=256):
    print(token, end="", flush=True)   # 逐 token 流式输出
```

## 五、与其他对比

- 与 上下文压缩深入 共享成本视角（更少 token=更短流式）。
- 与 KV缓存优化深入 直接耦合（增量依赖 KV）。

## 六、常见误区

- 未复用 KV 致每步重算爆炸。
- 批处理不当使长请求拖垮短请求延迟。

## 八、面试题

- 流式生成如何高效？答：增量解码复用 KV 缓存，每步只算新 token，配合连续批处理提吞吐。

## 九、演进

逐句生成 → token 流式 → 连续批处理+PagedAttention。

## 十、小结

流式生成靠增量解码与高效调度，平衡延迟与吞吐。
