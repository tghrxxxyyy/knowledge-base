# 端到端评估与人工对齐

> 对应 Es et al. 2023《RAGAS》与 Zheng et al. 2023《LLM-as-judge》及 run-llama/llama_index。

## 一、背景与挑战
分维度指标易优化却未必对应用户真实满意。端到端评估把「最终答案是否解决问题」作为目标，并与人工偏好对齐，防止指标博弈。

## 二、核心原理
用代表性测试集跑完整 RAG 流水线，收集最终答案，由人工或 judge 按整体满意度打分；再用这些分数校准自动指标权重，使自动评分逼近人工判断。

## 三、形式化与数学基础
令自动分 $s$ 与人工分 $h$ 做最小二乘对齐：
$\hat{h} = \beta_0 + \beta_1 s_{\text{f}} + \beta_2 s_{\text{cr}} + \beta_3 s_{\text{ar}}$
通过回归求 $\beta$ 使 $\hat{h} \approx h$，实现指标到体验的映射。

## 四、代码实现
```python
import numpy as np
def calibrate(auto_feats, human_scores):
    X = np.c_[np.ones(len(auto_feats)), auto_feats]
    beta, *_ = np.linalg.lstsq(X, human_scores, rcond=None)
    return beta   # 用于加权自动分
```

## 五、与其他技术对比
相比纯分维度自动评测，端到端对齐更贴近业务；相比纯人工，自动代理可日常监控。关键是保持人工校准样本的新鲜度。

## 六、常见误区
误区一：一次校准永久有效，数据分布漂移需定期重校。误区二：用自动分直接优化导致过拟合指标而非体验。

## 九、演进与趋势
在线实验（A/B）与离线指标联合，用真实用户信号持续校正评估体系，形成评估-优化闭环。

## 十、小结
端到端人工对齐确保自动评估不偏离真实价值，是评估体系的最后一公里。
