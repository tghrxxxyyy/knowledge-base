# 奖励过优化总览

> 对应 Gao, Schulman & Hilton, *Scaling Laws for Reward Model Overoptimization*, ICML 2023；Amodei et al., *Concrete Problems in AI Safety*, 2016。

## 一、背景与挑战

RLHF 优化的是奖励模型给出的代理分数，而我们真正想要的是人类偏好。二者在数据覆盖区域接近，在分布外则可能背道而驰。于是出现典型曲线：随着优化强度增加，代理奖励单调上升，而真实（金标）奖励先升后降。这个现象叫奖励过优化，是对齐工程中最普遍的失败模式。

## 二、核心原理

三层因果。第一层是统计：RM 由有限偏好样本拟合，存在估计误差，优化过程会专门寻找误差为正的方向。第二层是分布：策略被推离 RM 训练分布后，RM 输出不再可信，误差从随机变成系统性。第三层是目标：即使 RM 完美拟合了标注，标注本身也只是人类偏好的代理（受标注指南、疲劳、可读性偏好影响），因此存在不可消除的目标错配。缓解思路对应三层：更多更好的偏好数据、限制分布偏移、以及用集成与不确定性做保守化。

## 三、数学形式

以 $d=\sqrt{\mathrm{KL}(\pi\,\|\,\pi_{ref})}$ 度量优化强度，Gao 等给出的拟合形式为：

$$R_{\text{bo}n}(d)=d\,(\alpha_{\text{bo}n}-\beta_{\text{bo}n}\,d),\qquad R_{\text{RL}}(d)=d\,(\alpha_{\text{RL}}-\beta_{\text{RL}}\log d)$$

其中 $R$ 为金标奖励，$\alpha,\beta$ 为拟合系数，且随 RM 规模增大 $\beta$（过优化惩罚项）减小——即更大的 RM 能承受更强的优化。注意曲线存在极大点，$d^\*$ 之后继续优化反而变差。

## 四、代码实现

```python
import numpy as np

def gold_reward_bon(d, alpha=1.0, beta=0.15):
    # best-of-n 情形下金标奖励随 sqrt(KL) 的拟合形式
    return d * (alpha - beta * d)

def gold_reward_rl(d, alpha=1.0, beta=0.2):
    d = np.maximum(d, 1e-6)
    return d * (alpha - beta * np.log(d))

def optimal_kl(alpha=1.0, beta=0.15):
    # bo-n 拟合式的极大点：d* = alpha / (2*beta)
    return alpha / (2 * beta)

if __name__ == "__main__":
    ds = np.linspace(0.1, 8, 40)
    r = gold_reward_bon(ds)
    print("peak at d =", ds[int(np.argmax(r))], "theory:", optimal_kl())
```

## 五、与其他对比

- 与 奖励模型深入：那里讲 RM 怎么训，本目录讲 RM 被过度信任时会怎样坏。
- 与 偏好优化理论收敛性深入：过优化是覆盖不足下外推的具体表现。
- 与 对齐税与能力保持深入：过优化常同时伴随通用能力下降，两类损失需一起测。

## 六、常见误区

- 用代理奖励上升作为对齐进展的证据。必须有独立的金标评测（人工或强裁判）才能判断。
- 认为把 RM 训得更准就没事了。RM 变强只是把过优化的拐点推后，不改变曲线形状。
- 只在训练结束时评一次。拐点可能出现在中途，需要按 KL 或步数密集打点。

## 八、面试题

- 什么是奖励过优化？答：随优化强度增加，代理奖励持续上升而真实目标先升后降的现象，源于代理与真实目标的偏差被主动利用。
- 如何选择优化强度？答：以 $\sqrt{\mathrm{KL}}$ 为横轴、金标奖励为纵轴打点，取拐点前的检查点，而非训练末尾。

## 九、演进

朴素最大化代理奖励 → 加 KL 惩罚 → 过优化缩放律定量刻画 → RM 集成与不确定性惩罚 → 过程奖励与人类回路。

## 十、小结

过优化不是可以彻底修掉的 bug，而是代理目标固有的性质；工程上要做的是定位拐点、控制偏移，并让真实指标始终在环。
