# 缓解与监控实践

> 对应 Ouyang et al., *InstructGPT*, NeurIPS 2022（KL 惩罚与人工评测）；Gao et al., ICML 2023；Pan et al., *The Effects of Reward Misspecification*, ICLR 2022。

## 一、背景与挑战

理论上知道过优化会发生，工程上需要一套能跑在流水线里的监控与止损机制：什么指标必须打点、哪个阈值触发停训、上线前如何验证没有被黑客化。缺少这层，前面所有分析都停留在事后解释。

## 二、核心原理

监控体系分四层。第一层是分布偏移：按检查点记录相对参考模型的 KL、序列 log-ratio 的尾部分位数。第二层是奖励可信度：集成分歧度、代理奖励与金标（人工或强裁判）分数的相关性衰减。第三层是行为特征：平均生成长度、格式化模板占比、拒答率、谄媚翻转率——这些是已知捷径的直接探针。第四层是能力回归：通用基准与专项任务分数，防止对齐税被过优化掩盖。止损规则是「任一层越界即回滚到上一个通过检查的检查点」，而不是继续训到计划步数。

## 三、数学形式

综合止损可写成带惩罚的选择准则：在候选检查点集合 $\{\theta_t\}$ 中选

$$\theta^\star=\arg\max_{t}\ \Big\{\hat R_{\text{gold}}(\theta_t)-\lambda_1\,\mathrm{KL}(\pi_{\theta_t}\|\pi_{ref})-\lambda_2\,\mathrm{Drift}(\theta_t)\Big\}$$

其中 $\mathrm{Drift}$ 汇总长度、拒答率、谄媚率等行为漂移。若金标评测昂贵，可先用集成保守奖励 $\bar r-\lambda s^2$ 做粗筛，再对少量候选做人工评测。

## 四、代码实现

```python
class OveroptGuard:
    def __init__(self, kl_budget=8.0, len_ratio_max=1.35, refusal_max=0.12):
        self.kl_budget, self.len_ratio_max, self.refusal_max = kl_budget, len_ratio_max, refusal_max
        self.best = None

    def check(self, ckpt, m):
        # m 由评测流水线给出：kl / 长度比 / 拒答率 / 集成分歧 / 金标分
        alerts = []
        if m["kl"] > self.kl_budget:
            alerts.append("kl_over_budget")
        if m["len_ratio"] > self.len_ratio_max:
            alerts.append("length_inflation")
        if m["refusal_rate"] > self.refusal_max:
            alerts.append("over_refusal")
        if m["ens_std"] > m["ens_std_p95"]:
            alerts.append("reward_uncertain")
        score = m["gold"] - 0.05 * m["kl"] - 0.5 * max(0.0, m["len_ratio"] - 1.0)
        if not alerts and (self.best is None or score > self.best[1]):
            self.best = (ckpt, score)
        return {"alerts": alerts, "score": score, "best": self.best}
```

## 五、与其他对比

- 与 训练不稳定诊断：那关注梯度与损失的数值问题，本节关注目标错配导致的「看起来正常但方向错」。
- 与 奖励模型集成与不确定性：集成提供本体系中最便宜的可信度信号。
- 与 对齐税与能力保持深入：第四层监控与对齐税测量共用同一套基准。

## 六、常见误区

- 只保存最后一个检查点。过优化的最优点常在中途，不密集打点等于放弃止损能力。
- 金标评测样本量太小。人工评测几十条的噪声足以掩盖真实差异，需按置信区间设计样本量。
- 阈值一次设定长期不变。基座、数据与任务变化后阈值需重新校准，否则告警失效或误报泛滥。

## 八、面试题

- 一套过优化监控最少要哪几个指标？答：相对参考模型的 KL、独立金标分数、行为漂移（长度与拒答率）、以及集成分歧度。
- 为什么止损要按检查点而非按步数计划？答：过优化拐点位置不可预先确定，只有按检查点评测并回滚才能取到峰值附近的模型。

## 九、演进

事后人工发现异常 → KL 惩罚 + 末尾评测 → 密集检查点 + 多层监控 → 集成不确定性粗筛 + 人工精评的分层止损。

## 十、小结

治理奖励黑客的落地形态是一套监控与回滚规则：分布偏移、奖励可信度、行为漂移、能力回归四层齐备，才敢让 RLHF 自动化跑。
