# 算子融合总览

> 对应 Chetlur et al., *cuDNN: Efficient Primitives for Deep Learning*, 2014（卷积融合原语）；与 内核调优深入 / 编译部署深入 衔接。

## 一、背景与挑战

深度学习推理由大量细碎算子（Conv、BN、ReLU、BiasAdd）串联而成，逐个算子都会读写全局显存（HBM），显存带宽成为主要瓶颈。

## 二、核心原理

算子融合（kernel fusion）把相邻算子合并为单个 CUDA kernel，中间结果留在寄存器或共享内存，避免多次 HBM 往返，同时提升算术强度（Arithmetic Intensity）。

## 三、数学形式

算术强度 $AI = \frac{\text{FLOPs}}{\text{bytes}}$；融合后写回量由 $\sum_i M_i$ 降为 $M_{out}$，使 $AI$ 显著增大，更靠近 roofline 算力峰区。

## 四、代码实现

```python
# 用 Triton 表达 Conv+BN+ReLU 融合的核心逻辑
@triton.jit
def fused_conv_bn_relu(x, w, gamma, beta, y, eps):
    acc = tl.dot(x, w)            # 寄存器内完成卷积
    acc = (acc - mean) / tl.sqrt(var + eps)
    acc = acc * gamma + beta      # BN 融合
    tl.store(y, tl.maximum(acc, 0.0))   # ReLU 融合
```

## 五、与其他对比

- 与 内核调优深入（单 kernel 微优化）互补，融合是图/调度层优化。
- 与 编译部署深入（计算图优化）衔接，融合常由编译器自动完成。

## 六、常见误区

- 并非融合越多越好：过大 kernel 会耗尽寄存器导致 spill 到显存。
- 跨 stride 的算子（如 MaxPool）融合收益低，反而增加复杂度。

## 八、面试题

- 为何算子融合能加速？答：减少 HBM 读写往返、提升算术强度，贴合 roofline 模型从带宽区移向算力区。

## 九、演进

手写融合 → 框架内置融合（cuDNN） → 编译器自动融合（TVM/MLIR）。

## 十、小结

算子融合通过合并 kernel 降低显存带宽压力，是推理加速的基础且高效手段。
