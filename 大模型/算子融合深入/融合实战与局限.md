# 算子融合实战与局限

> 对应 NVIDIA, *TensorRT Layer Fusion*, 2017；与 编译部署深入 / 模型导出ONNX深入 衔接。

## 一、背景与挑战

生产部署需在可维护性与极致性能间权衡，融合并非银弹。

## 二、核心原理

TensorRT 通过 builder 做 layer fusion 与 constant folding，生成串行 kernel；但融合 kernel 难以调试且对 shape 敏感（需重编）。

## 三、数学形式

收益评估：$\Delta T = T_{\text{unfused}} - (T_{\text{fused}} + T_{\text{compile}})$；仅当 $\Delta T>0$ 且调用频次高才值得。

## 四、代码实现

```python
builder = trt.Builder(logger)
config = builder.create_builder_config()
config.set_flag(trt.BuilderFlag.FP16)
engine = builder.build_engine(network, config)
```

## 五、与其他对比

- 与 内核调优深入（手调 kernel）对比可移植性。
- 与 模型导出ONNX深入（ONNX 图作融合输入）衔接。

## 六、常见误区

- 动态 shape 下融合 kernel 重编译造成首包延迟尖刺。
- 过度融合致单 kernel 难以 profiling。

## 八、面试题

- 融合有哪些代价？答：kernel 特化难调试、动态 shape 重编译、寄存器压力增大。

## 九、演进

离线融合 → 运行时自适应融合 → 自动代价模型决策。

## 十、小结

融合收益显著但带来可维护性与重编译成本，需按场景权衡。
