# 融合模式分类

> 对应 Lattner et al., *MLIR: A Compiler Infrastructure for the End of Moore's Law*, 2021（多级方言融合）；与 编译部署深入 衔接。

## 一、背景与挑战

不同算子结构的融合收益与可行性差异巨大，需分类处理。

## 二、核心原理

常见 fusion：垂直融合（element-wise/Broadcast 串联）、水平融合（同构算子并列，如多个 MatMul 合成 batch）、特殊融合（Conv+BN+ReLU、MHA 融合）。MLIR 用方言分层表达。

## 三、数学形式

垂直融合：$y=f_2(f_1(x))$ 合并为单 kernel，访存 $M=M_{out}$ 而非 $M_1+M_2$。水平融合：$Y_i=A_i X$ 合并为 $\text{stack}(A_i)X$。

with fusion.Op():

## 五、与其他对比

- 与 内核调优深入（手写融合 kernel）是编译器方案的对立面。
- 与 模型导出ONNX深入（图算子粒度）相关。

## 六、常见误区

- 把含动态控制流的算子强行融合导致特化 kernel 爆炸。
- 水平融合增大临时张量，超出共享内存反降速。

## 八、面试题

- 垂直与水平融合区别？答：垂直是串行小算子合并省访存，水平是并列同构算子合并提升并行度。

## 九、演进

手工分类融合 → 编译器规则 → 代价模型自动分类。

## 十、小结

融合模式决定可行性，编译器按垂直/水平/特殊分别生成最优 kernel。
