# 融合的内存带宽本质

> 对应 Williams et al., *Roofline: An Insightful Visual Performance Model*, 2009；与 内核调优深入 衔接。

## 一、背景与挑战

很多算子受限于显存带宽而非算力，单独执行时 HBM 往返字节数远大于其计算量。

## 二、核心原理

用 Roofline 模型刻画性能上限：由算力峰值与带宽峰值共同围成；算术强度低的算子落在带宽斜坡区，融合提升 $AI$ 可使其移向算力峰值区。

## 三、数学形式

可达性能 $\text{Perf}=\min(\pi,\, \beta\cdot AI)$，其中 $\pi$ 为峰值 FLOP/s，$\beta$ 为内存带宽；融合使 $AI\uparrow$，Perf 逼近 $\pi$。

## 四、代码实现

```python
ai = flops / max(bytes_accessed, 1)
perf = min(peak_flops, mem_bw * ai)
print("bounded by", "compute" if perf >= peak_flops*0.9 else "memory")
```

## 五、与其他对比

- 与 编译部署深入（图优化减少中间张量）共享同一目标。
- 与 内核调优深入（tiling）配合提升单 kernel 效率。

## 六、常见误区

- 高算术强度算子（大矩阵乘）融合收益很小甚至可能更慢。
- 忽视寄存器溢出对融合 kernel 的反向拖累。
