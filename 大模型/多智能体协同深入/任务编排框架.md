# 任务编排框架（AutoGen / MetaGPT）

> 对应 AutoGen（Wu et al., 2023）与 MetaGPT（Hong et al., 2023）工程实践。

## 一、背景与挑战

手写多 Agent 交互难维护；需框架提供会话、工具、人类介入与终止管理。

## 二、核心原理

AutoGen 以可对话 Agent + 用户代理（可执行代码/人类）构建对话流；MetaGPT 以角色 SOP 把需求转产品文档到代码。

## 三、数学形式

对话轮 $t$：$m_t = a_{i_t}(H_{<t})$；$H_t = H_{<t}\cup\{m_t\}$；终止由 max_round/条件触发。

## 四、代码实现

```python
group = GroupChat(agents=[pm, dev, qa], messages=[], max_round=10)
mgr = GroupChatManager(group, llm=llm)
pm.initiate_chat(mgr, message="实现登录接口")
```

## 五、与其他对比

- 与 角色分工与通信 是“框架实现”层。
- 与 流式生成与增量解码深入 共享底层推理。

## 六、常见误区

- 框架滥用致链路不可调试。
- 忽略人类介入点致错误自动放大。

## 七、与开源书对应

- dair-ai/Prompt-Engineering-Guide：https://github.com/dair-ai/Prompt-Engineering-Guide

## 八、面试题

- AutoGen 与 MetaGPT 区别？答：前者通用对话编排、强调人类/工具回路；后者以 SOP 角色链做软件生成。

## 九、演进

脚本拼装 → 对话框架 → SOP 产品化框架。

## 十、小结

编排框架把多 Agent 工程化，关键在终止与可观测。
