# 校验与回滚

> 对应 Ruan et al., *ToolEmu*, 2023。

## 一、背景与挑战

工具调用常产生副作用（发邮件、写数据库）。若调用“成功返回”但结果语义错误，盲目继续会造成不可逆损害。需先校验再确认。

## 二、核心原理

在执行副作用前插入校验层：用规则或模型判断返回是否满足前置契约（schema、值域、业务约束）。对可逆操作采用“暂存-校验-提交/回滚”两阶段；不可逆操作强制人工确认。

## 三、数学形式

定义校验得分 $v\in[0,1]$，仅当 $v>\tau$ 才提交：

$$commit = \mathbb{1}[v(\text{result}) > \tau]$$

回滚概率随 $\tau$ 提高而下降。

## 四、代码实现

```python
res = tool(**args)
score = validator.check(res)
if score < THRESHOLD:
    rollback(args); raise InvalidResult(res)
commit(args)
```

## 五、与其他对比

- 与 智能体安全与权限沙箱深入 的“最小权限+确认”正交互补。
- 与 降级与兜底 衔接：校验失败即触发兜底。

## 六、常见误区

- 只校验 HTTP 状态码，忽略业务层面语义错误。
- 回滚本身有成本，却未评估是否值得。

## 八、面试题

- 为什么 HTTP 200 不等于调用成功？答：网络成功但业务语义可能错误，需独立校验层。

## 九、演进

无校验 → 状态校验 → 语义校验+可逆回滚。

## 十、小结

校验与回滚把“副作用风险”关进笼子，是高可信智能体的必备闸口。
