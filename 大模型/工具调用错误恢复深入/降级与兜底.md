# 降级与兜底

> 对应 工程韧性设计（resilience）与 human-in-the-loop 实践。

## 一、背景与挑战

当主工具多次失败或不可用，智能体不应卡死。需要预设降级路径，在保质量与保可用间取得平衡。

## 二、核心原理

构建工具能力的有向图，每节点标注成本/可靠性。失败时按可靠性降序切换候选（如：实时 API → 缓存快照 → 规则近似 → 人工）。降级需保证“至少返回一个可用结果”而非崩溃。

## 三、数学形式

选择使期望效用最大化的兜底工具：

$$a^* = \arg\max_{a\in A_{fallback}} \big(u(a) - c(a)\big)\cdot r(a)$$

$r(a)$ 为可用性，不可用时贡献为 0。

## 四、代码实现

```python
for alt in fallback_chain(primary):
    if alt.available():
        return alt.run(args)
escalate_to_human(args)   # 最终兜底
```

## 五、与其他对比

- 与 反思与自我纠正 衔接：降级后可反思根因。
- 与 人机协作与人在环深入 共享人工兜底节点。

## 六、常见误区

- 降级路径本身未测试，关键时刻失效。
- 兜底返回低质量结果却未标注“降级态”，误导用户。

## 八、面试题

- 兜底为何要标“降级态”？答：让用户知悉结果置信度下降，避免误当权威结论。

## 九、演进

单工具 → 多候选 → 带成本效用的自动降级。

## 十、小结

降级与兜底保证“永不崩溃”，把局部故障隔离在单工具而非整条轨迹。
