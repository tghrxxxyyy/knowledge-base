# 错误恢复评估基准

> 对应 Liu et al., *AgentBench*, 2023；Ruan et al., *ToolEmu*, 2023。

## 一、背景与挑战

恢复机制是否真的提升鲁棒性，需用可控故障注入来量化，而非仅靠 anecdote。

## 二、核心原理

在基准中故意注入故障（延迟、错误码、畸形返回），比较开启/关闭恢复模块的任务完成率、重试次数、人工介入率。ToolEmu 用仿真环境规模化评估风险与恢复。

## 三、数学形式

恢复增益：

$$\Delta = \frac{N_{ok}^{recover} - N_{ok}^{baseline}}{N_{total}}$$

并监控平均重试开销 $C_{retry}$ 避免“恢复比任务还贵”。

## 四、代码实现

```python
for case in bench:
    with inject_fault(case, rate=0.3):
        score = run_agent(case, recover=True)
```

## 五、与其他对比

- 与 智能体可靠性与失败模式深入 共用故障分类与度量。
- 与 智能体推理成本建模深入 共担开销核算。

## 六、常见误区

- 只在无故障环境测，恢复模块价值被掩盖。
- 忽视恢复带来的额外延迟成本。
