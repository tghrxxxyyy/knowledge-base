# 工具调用错误恢复总览

> 对应 Yao et al., *ReAct*, 2022；Shinn et al., *Reflexion*, 2023；Ruan et al., *ToolEmu*, 2023。

## 一、背景与挑战

智能体通过工具调用扩展能力，但接口超时、参数非法、返回异常、副作用不可逆等故障频发。一次未处理的异常即可中断整个任务轨迹。错误恢复是把“单次脆弱调用”变成“可重试、可纠正、可降级”的鲁棒流程的核心能力。

## 二、核心原理

恢复机制分三层：重试（retry）应对瞬时故障；反思（reflection）利用自然语言反馈修正计划；兜底（fallback）在多次失败后切换到近似路径或向人类求助。三者常组合成“重试→反思→降级”的漏斗式策略。

## 三、数学形式

设单次调用成功率 $p$，经 $k$ 次独立重试后的累计成功率：

$$P_{ok}=1-(1-p)^k$$

可见重试对瞬时故障收益显著，但对系统性错误（固定 $p$ 低）无效，需配合反思。

## 四、代码实现

```python
def call_with_recovery(tool, args, max_retry=3):
    for i in range(max_retry):
        try:
            return tool(**args)
        except TransientError as e:
            log(f"retry {i}: {e}")
    raise RecoveryFailed(args)
```

## 六、常见误区

- 对确定性错误盲目重试，浪费 token 且放大副作用。
- 重试不设退避（backoff），对限流类故障雪上加霜。

## 八、面试题

- 重试为何不能解决所有错误？答：仅对瞬时/随机故障有效，系统性错误需反思或降级。

## 九、演进

无处理 → 简单重试 → 反思式纠正 → 分级兜底与人类回退。

## 十、小结

错误恢复是智能体落地的“安全带”，重试、反思、降级三件套决定其工程可用性。
