# 自我批判式对齐原理

> 对应 Bai et al. 2022（Constitutional AI）、Yao et al. 2022（ReAct）与 Madaan et al. 2023（Self-Refine）。

## 一、背景与挑战

让大模型在生成后自我审查并修正，是降低有害与低质输出的轻量对齐手段。相比需要采集人类偏好、训练奖励模型再做强化学习的 RLHF，自我批判无需额外标注与训练，部署成本极低，且推理过程可解释、可审计。但其效果依赖模型自身是否具备足够的「判别力」——批判能力未必与生成能力同步增长；若不加以约束，批判可能无实质改进甚至越改越差；此外每轮批判都要额外推理，延迟与成本随轮数线性上升。因此它适合作为对齐体系的补充层，而非替代品。

## 二、核心原理

自我批判式对齐把一次生成拆成「生成—批判—修订」的循环：

1. 草稿生成：模型先产出初始回答 $y_0$，此阶段追求覆盖与多样性。
2. 批判生成（critique）：模型切换为「审查者」角色，基于原则、外部工具或自洽性指出 $y_0$ 的具体问题。角色切换通过提示实现，把生成与审查解耦到不同的上下文。
3. 修订（revise）：模型依据 critique 产出 $y_1$，可多轮迭代。
4. 终止：达到轮数上限、验证器确认改进，或批判认为无问题则停止。

批判的依据可以是三类：自然语言原则（宪法 AI 思路，把规范写成可引用的条款）、可调用工具（计算器、检索、代码执行的客观反馈）、多样本自洽性（多次采样后取多数结论并指出不一致）。显式分离生成与审查，等价于引入一个推理时的「元认知」步骤，让模型把一次性的直觉输出转化为经过检查的结果。

## 三、形式化与数学基础

把修订建模为映射。给定输入 $x$、草稿 $y_t$、批判者 $C$，第 $t+1$ 步：

$$ \text{critique}_t = C(x, y_t), \qquad y_{t+1} = M\big(\text{revise}(x,\, y_t,\, \text{critique}_t)\big) $$

critique 可由模型自身产生，也可由独立验证器 $V$ 或工具产生。若引入验证器，则迭代在改进时继续，否则停止：

$$ \text{continue} \iff V(x, y_{t+1}) > V(x, y_t) + \epsilon $$

其中 $\epsilon > 0$ 防止把采样噪声当作改进。整体收益与成本可写为：

$$ \Delta = \mathbb{E}\big[V(x, y_T)\big] - V(x, y_0), \qquad \text{Cost} = \sum_{t=0}^{T-1} \big(c_{\text{crit}} + c_{\text{rev}}\big) $$

在工程上常把问题转化为「在给定成本预算内最大化 $\Delta$」，由此决定轮数上限。另一种理论视角是把它看作对后验的近似：批判—修订相当于对初始分布做一次重加权，使输出更靠近高评分区域，但不改变分布支撑集——这解释了为何它无法产生模型根本不会的内容。

## 四、代码实现

```python
# 自我批判循环（推理时，无参数更新）
def self_refine(model, x, verifier=None, rounds=2, eps=0.02):
    y = model.generate(x)
    history = [{"round": 0, "output": y}]

    for t in range(1, rounds + 1):
        critique = model.generate(
            "作为严格审查者，逐条指出下面回答的事实错误、逻辑漏洞与安全隐患：\n" + y
        )
        if is_no_issue(critique):
            break               # 批判认为无问题，提前终止

        y_new = model.generate(
            f"根据批评修订回答，只改有问题的部分。\n原回答：{y}\n批评：{critique}\n修订："
        )
        if verifier is not None:
            old, new = verifier(x, y), verifier(x, y_new)
            if new <= old + eps:
                break           # 未改善则保留上一版，防止越改越差
        y = y_new
        history.append({"round": t, "output": y, "critique": critique})

    return y, history


def is_no_issue(critique):
    # 简单判空：批判过短或含无问题标记时视为无需修订
    return len(critique.strip()) < 20 or "无问题" in critique[:20]
```

## 五、与其他技术对比

- 自我批判 vs RLHF：前者易部署、可解释、零训练；后者真正改变参数、上限更高，但需数据与算力。
- 自我批判 vs 思维链：CoT 是顺向推理的自我展开，自我批判是逆向校验，二者可叠加（先 CoT 再批判）。
- 自我批判 vs 自洽性投票：投票只做选择不做修改，批判能定位并修正具体问题，但依赖批判质量。
- 有验证器 vs 无验证器：验证器防止越改越差，代价是额外推理与需要一个可信的验证信号。

## 六、常见误区

- 「多轮一定更好」：模型可能反复自我肯定而无实质改进，边际收益迅速衰减，需验证器兜底。
- 「批判无依据也行」：缺乏原则或工具支撑的批判易乱改、引入新错误。
- 「可替代训练对齐」：它只是推理时改进，无法提升模型固有知识与能力上限。
- 「批判提示随便写」：提示决定批判的粒度与可执行性，无结构的批判只会产出空泛评价。

## 七、与开源书·权威来源对应

- Bai et al. 2022（Constitutional AI）：用原则引导自我批判与修订，并把修订结果用于 RLAIF 训练。
- Yao et al. 2022（ReAct）：推理与行动交织、以反思驱动动作选择，是推理时反思的思想来源之一。
- Madaan et al. 2023（Self-Refine）：系统研究迭代式自我反馈对生成质量的提升与边界。
- HuggingFace Transformers：可加载对话模型，通过角色切换实现生成—批判流程（接口以官方最新文档为准）。

## 九、演进与趋势

自我批判正从「同源自循环」走向「批判模型与生成模型解耦 + 工具辅助验证 + 人类在环」：专门训练的批判模型具备更强判别力；工具（检索、执行、单元测试）提供客观信号，降低自偏好风险；把批判轮数与触发条件做成风险自适应策略以控制成本；并把批判—修订产生的（草稿，修订）对作为偏好数据回流训练，形成推理期与训练期的闭环。

## 十、小结

自我批判以推理时迭代换取对齐质量，零训练成本、过程可解释，是 RLHF 之外高性价比的护栏。但它受限于模型自身判别力，必须配合原则、验证器与轮数控制才能稳定生效。
