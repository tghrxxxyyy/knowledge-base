# 自我对弈与迭代改进

> 对应 Bai et al. 2022（Constitutional AI 中的红队自玩）、Silver et al. 2017（AlphaGo Zero 自我对弈）与 HuggingFace TRL 偏好训练实践。

## 一、背景与挑战

对齐数据的获取成本高：人工标注偏好昂贵、周期长，且难以覆盖模型当前的真实弱点——标注者往往不知道模型在哪里会失败。自我对弈（self-play）的思路是让模型自身扮演「对手/红队」去攻击当前策略，暴露弱点并据以改进，从而以低成本持续扩展对齐数据。挑战有四：一是对手与策略同源时容易「协同」而非对抗，生成的样本越来越同质，形成退化；二是过强的对手会生成不可解或与真实分布无关的样本，训练信号变成噪声；三是对弈产出的偏好对需要经过滤才能进入训练，否则会固化错误；四是缺乏外部校验时，整个循环可能收敛到一个自洽但偏离人类偏好的状态。

## 二、核心原理

自我对弈构建「策略模型 ↔ 对手模型」的对抗循环：

1. 对手模型针对当前策略 $\pi_t$ 生成它容易出错的难例（红队提示、边界问题、越狱尝试、刁钻推理题）。
2. 策略模型在这些难例上作答，并通过批判/修订或多样本采样得到更优响应。
3. 将（难例, 较优响应, 原响应）组织为偏好对，进入 DPO/PPO 等对齐训练。
4. 更新后的策略成为下一轮对手的攻击目标，难度呈课程式上升。

这一设计与博弈论中的自我对弈一致：双方能力共同提升，且对手始终针对当前最薄弱处，比静态数据集更聚焦、更高效。工程上有三个关键控制点：一是保持对抗性，通过提高采样温度、使用不同提示词或引入异源模型，防止对手与策略落入「共谋」；二是难度控制，用「策略是否能解」作为过滤器，剔除不可解与过于简单的样本，保留处于能力边界的样本；三是数据质量闸门，对偏好对做去重、长度校验与原则一致性检查后再入训练集。

## 三、形式化与数学基础

设第 $t$ 步策略为 $\pi_t$，对手生成针对其弱点的样本分布 $\mathcal{A}(\pi_t)$，对齐更新为：

$$ \pi_{t+1} = \text{Align}\big(\pi_t,\ \mathcal{D}_t\big),\quad \mathcal{D}_t \sim \mathcal{A}(\pi_t) $$

理想情况下对手使样本难度最大化当前策略的「应会却错」程度：

$$ \mathcal{A}(\pi_t) = \arg\max_{q}\ \mathcal{L}_{\text{gap}}(q, \pi_t) $$

其中 $\mathcal{L}_{\text{gap}}$ 衡量模型在该样本上的表现与期望表现的差距。实际不可直接求解该 argmax，常用近似：采样多个候选问题，按策略失败率或不确定性排序，取 Top-K。

难例选择可写成带约束的筛选：

$$ \mathcal{D}_t = \{\,q : \underline{s} \le \text{solve\_rate}(q, \pi_t) \le \bar{s}\,\} $$

即只保留策略「时而会、时而不会」的样本——全对的无信息量，全错的可能不可解。难度随 $t$ 自适应上升，形成课程学习。

## 四、代码实现

```python
# 自我对弈：对手生成难例 -> 策略作答 -> 过滤 -> 产出偏好对
def self_play(adversary, policy, base_topics, n=8, temperature=1.0):
    candidates = []
    for topic in base_topics:
        # 对手在较高温度下采样，跳出与策略的协同区
        q = adversary.generate(
            f"构造一个能难倒模型、但人类专家可以正确回答的{topic}问题：",
            temperature=temperature,
        )
        answers = [policy.generate(q) for _ in range(4)]   # 多次采样估计可解性
        ok = [judge(q, a) for a in answers]                # judge 返回是否通过
        solve_rate = sum(ok) / len(ok)

        if not (0.0 < solve_rate < 1.0):
            continue        # 全对（太简单）或全错（可能不可解）都丢弃

        best = answers[ok.index(True)] if any(ok) else self_critique(policy, q, answers[0])
        worst = answers[ok.index(False)] if not all(ok) else answers[0]
        candidates.append({"x": q, "chosen": best, "rejected": worst,
                           "solve_rate": solve_rate})
    return dedup(candidates)


def dedup(samples):
    # 去重：防止对手反复生成同一类问题导致训练集同质化
    seen, out = set(), []
    for s in samples:
        key = s["x"][:64]
        if key in seen:
            continue
        seen.add(key)
        out.append(s)
    return out
```

## 五、与其他技术对比

- 自我对弈 vs 静态数据集：前者针对当前弱点、难度自适应；后者固定、易过拟合旧弱点且被刷分。
- 自我对弈 vs 纯人类红队：前者可规模化、低成本；后者质量高、更贴近真实攻击但稀缺且贵。
- 同源对手 vs 异源对手：异构对手更能打破协同，但需维护额外模型，成本更高。
- 自对弈数据 vs 自标注偏好：前者强调对抗性难例挖掘，后者强调原则式修订，二者可串联使用。

## 六、常见误区

- 「对手越强越好」：过强对手生成不可解样本，训练信号噪声大，甚至教模型产生幻觉式自信。
- 「对弈数据可直接使用」：未过滤的低质与退化样本会污染训练，必须设置可解性闸门与去重。
- 「同源必然对抗」：温度与提示不加扰动，对手可能与策略同分布「共谋」，样本越来越简单。
- 「可以完全不要人类」：缺乏外部校验时循环会自洽收敛，应保留人类抽检作为校准锚点。

## 七、与开源书·权威来源对应

- Bai et al. 2022（Constitutional AI）：用红队自玩（red-team self-play）生成对抗数据并用于偏好训练。
- Silver et al. 2017（AlphaGo Zero）：自我对弈从零学习的思想启发，展示课程式难度上升的价值。
- HuggingFace TRL：提供 DPOTrainer / GRPOTrainer 等，可直接消费对弈产出的偏好数据（接口以官方最新文档为准）。
- Perez et al. 2022（Red Teaming LMs）：研究自动化红队生成，与自对弈思路互补。

## 九、演进与趋势

自我对弈正从「单模型自言自语」走向「多模型生态对弈 + 难度自适应 + 人类在环筛选关键样本」：用不同架构、不同训练源的模型互为对手以打破协同；用可验证奖励（单元测试、执行结果、形式化校验）替代主观裁判，让「谁更好」有客观答案；与课程学习、自动验证结合，形成可扩展的对齐数据工厂；并把难例库沉淀为长期资产，用于回归测试与模型卡披露。

## 十、小结

自我对弈以对抗持续暴露模型弱点，是可扩展的对齐数据生产路径。其成败取决于能否保持对抗性、控制难度与过滤噪声，并保留人类校验作为方向锚点。
