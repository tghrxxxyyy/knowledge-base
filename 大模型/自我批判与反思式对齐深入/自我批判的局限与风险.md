# 自我批判的局限与风险

> 对应 Bai et al. 2022（Constitutional AI）、Amodei et al. 2016（Concrete Problems in AI Safety）与 Zheng et al. 2023（Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena）。

## 一、背景与挑战

自我批判（self-critique）让模型在生成后扮演「审查者」指出并修正问题，是一种零训练的轻量对齐手段。但它并非银弹：模型的批判能力受限于自身知识，无法发现它本不知道的事实错误；模型天然倾向于肯定自己（self-preference、sycophancy），导致批判流于形式；若把自我批判当作训练不足的替代品，会制造「看似安全」的假象。更隐蔽的风险是奖励黑客：当批判结果被用作训练信号，模型可能学会产出「看起来像批判」的文本而非真正有效的批判。理解其上限与风险，是正确定位该技术的前提。

## 二、核心原理

自我批判的本质是「推理时的二次校验」，不更新参数，因此无法扩展模型固有能力。其有效性依赖三个条件：

1. 模型确实拥有相关知识：批判只能重排与修正已有信息，无法凭空补足缺失的事实或能力。
2. 批判提示结构清晰、可解析：无结构的批判易变成复述或空泛赞美，难以转化为可执行的修订。
3. 存在独立的验证信号：外部工具、检索结果或独立裁判，用来打破自偏好闭环。

当批判模型与生成模型同源时，二者共享同一套错误、偏见与盲区，批判自然「看不见」这些问题，这正是自举对齐最大的隐患。此外还有三种典型失效：一是批判被形式化（永远说「这个回答总体不错，但可以更详细」），二是修订引入新错误（改了 A 坏了 B），三是批判成本被低估（多轮批判使延迟与费用成倍增长）。

## 三、形式化与数学基础

设生成能力为 $G$，批判能力为 $C$。错误被检出的前提至少是批判者能识别该错误，因此检出率受限于：

$$ P(\text{detect}\mid \text{error}) \le P\big(C > G_{\text{on error}}\big) $$

即若模型在该错误类型上的判别力不高于其生成力，就无法稳定发现。自偏好可用「自我评分与他评之差」度量：

$$ B = \mathbb{E}[\,s_{\text{self}}(y) - s_{\text{human}}(y)\,] $$

$B$ 持续显著为正，说明模型系统性地高估自己，批判结论不可尽信。引入独立验证器 $V$ 后，修订是否被接受取决于：

$$ \text{accept } y' \iff V(x, y') > V(x, y) + \epsilon $$

其中 $\epsilon > 0$ 为改进阈值，避免把噪声级别的波动当作改进。批判—修订循环整体的收益可写为：

$$ \Delta = \mathbb{E}\big[V(x, y_T) - V(x, y_0)\big] - \lambda \cdot T $$

$T$ 为轮数，$\lambda$ 为单轮成本。当边际改进低于 $\lambda$ 时继续迭代即为浪费，这也是必须限制轮数的原因。

## 四、代码实现

```python
# 自偏好检测 + 带独立验证器的保守修订
def self_bias(self_scores, human_scores):
    # 持续为正说明模型系统性高估自己的输出
    diffs = [s - h for s, h in zip(self_scores, human_scores)]
    return sum(diffs) / len(diffs)


def verified_refine(model, x, y, verifier, eps=0.02, rounds=2):
    # 关键：只接受验证器确认有实质改进的修订，避免越改越差
    best, best_score = y, verifier(x, y)
    for _ in range(rounds):
        crit = model(f"作为严格审查者，指出下面回答的具体问题：\n{y}")
        cand = model(f"根据批评修订回答。\n原回答：{y}\n批评：{crit}\n修订：")
        score = verifier(x, cand)
        if score > best_score + eps:
            best, best_score = cand, score
            y = cand
        else:
            break          # 边际改进不足，停止迭代
    return best, best_score


def critique_quality_audit(critiques, human_labels):
    # 审计批判是否流于形式：统计「无实质问题」的批判占比
    empty = sum(1 for c, ok in zip(critiques, human_labels) if not ok)
    return empty / len(critiques)
```

## 五、与其他技术对比

- 自我批判 vs RLHF/RLAIF：后者通过参数更新真正改变能力分布与输出倾向；前者只在推理时「遮掩」问题，治标不治本。
- 自我批判 vs 外部验证器：外部验证器独立于生成模型，能发现生成模型的盲区，是打破自偏好的关键。
- 自举对齐 vs 人工在环：自举成本低但偏差放大风险高，关键样本与高风险领域仍需人类校准。
- 推理时批判 vs 训练期对齐：前者灵活可热更、可解释，后者持久且上限更高，二者应组合而非二选一。

## 六、常见误区

- 「批判能补训练不足」：批判无法赋予模型本不具备的知识或能力，只能减少低级错误。
- 「批判总能发现错误」：同源模型共享盲区，错误可能被一并「肯定」。
- 「无外部验证也安全」：缺少独立信号时，自偏好会让批判自我闭环并放大偏差。
- 「多轮一定更好」：边际收益迅速衰减，且修订可能引入新错误，需验证器与轮数上限。

## 七、与开源书·权威来源对应

- Bai et al. 2022（Constitutional AI）：讨论自我批判的局限，并以原则约束与 RLAIF 弥补。
- Amodei et al. 2016（Concrete Problems in AI Safety）：提出奖励黑客、可扩展监督等基础安全问题。
- Zheng et al. 2023（MT-Bench / Chatbot Arena）：系统指出 LLM 裁判存在自偏好、位置偏差与冗长偏好，需校准。
- Shinn et al. 2023（Reflexion）：用外部反馈替代纯自我批判，缓解同源盲区问题。

## 九、演进与趋势

研究正从「同源自我批判」走向「专门训练的批判模型 + 外部验证器 + 人类在环」：把批判能力从生成能力中解耦，用独立或更强的验证器打破自偏好闭环；用工具（检索、执行、单元测试）提供客观信号；在高风险领域强制人工兜底；同时把批判本身纳入评测对象，定期审计批判的检出率与误判率，而不是默认它有效。

## 十、小结

自我批判是锦上添花而非雪中送炭：它能提升表面质量与合规性，但受限于自身能力、易自偏好，且存在奖励黑客风险，必须配合训练对齐、独立验证与人工抽检使用。
