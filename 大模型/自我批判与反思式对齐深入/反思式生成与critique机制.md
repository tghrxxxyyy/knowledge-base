# 反思式生成与critique机制

> 对应 Shinn et al. 2023（Reflexion）、Yao et al. 2022（ReAct）与 Wei et al. 2022（Chain-of-Thought）。

## 一、背景与挑战

面对需要试错、规划与长程推理的复杂任务（代码生成、Agent 决策、数学推理、多步检索），模型容易「一条路走到黑」：一旦中间步骤出错，后续全部建立在错误前提上。反思式生成（reflective generation）通过把环境反馈或自我批评写入可复用的记忆，让模型在下一轮推理中参考过往失败，实现「尝试—反思—再尝试」。挑战有四：记忆会随轮次无限增长，最终撑爆上下文；反馈噪声需要过滤，错误反思会误导后续尝试；反思只改上下文不改权重，能力上限仍受基础模型约束；此外还存在「反思形式化」问题——模型反复输出空洞的总结而没有真正改变策略。

## 二、核心原理

Reflexion 类方法的核心是「口头反思 + 记忆」，而非参数更新：

1. Actor：基于当前上下文（含历史记忆）产生动作或回答 $y_t$。
2. Evaluator：环境或批判器给出反馈 $\text{fb}_t$（执行结果、测试失败信息、评分、检索证据）。
3. Self-Reflection：模型把 $(x, y_t, \text{fb}_t)$ 用自然语言总结为可复用的经验，追加进记忆 $M$。
4. 下一轮 Actor 在 $M$ 的指引下避开已犯错误，重新尝试。

反思是上下文学习式的元策略改进：模型并未改变权重，而是用自然语言在上下文里「记住了」该怎么做、不该怎么做。这使得改进即时生效且可解释，但代价是消耗上下文预算。工程上三个要点：一是记忆分层，短期记忆放当前轨迹，长期记忆用向量库存取，按需检索而非全量拼接；二是写入门槛，只在反馈包含新信息（如失败且原因明确）时写入反思；三是反思结构化，固定为「错误—原因—下次策略」三段式，便于检索与去重。

## 三、形式化与数学基础

策略在上下文而非参数上更新。设第 $t$ 步记忆为 $M_t$，则：

$$ M_{t+1} = M_t \cup \{(x, y_t, \text{fb}_t)\} $$

策略据此更新，基础参数 $\theta$ 冻结：

$$ \pi_{t+1} = \text{policy}\big(\cdot \mid M_{t+1}, \theta_{\text{frozen}}\big) $$

若用标量奖励 $r_t$，可仅在 $r_t < r_{\text{th}}$ 时写入反思，控制记忆规模：

$$ M_{t+1} = \begin{cases} M_t \cup \{(x, y_t, \text{fb}_t)\}, & r_t < r_{\text{th}} \\ M_t, & \text{otherwise} \end{cases} $$

反思质量可用「下一轮成功率提升」衡量：

$$ \Delta_{\text{succ}} = P(\text{success}\mid M_{t+1}) - P(\text{success}\mid M_t) $$

$\Delta_{\text{succ}} \le 0$ 说明反思无效甚至有害，应停止写入并转人工。记忆预算约束可写为：

$$ |M_t| + |\text{context}(x)| \le L_{\max} $$

超限时需做摘要压缩或按相关性剪枝，这也是长程任务中记忆管理的核心问题。

## 四、代码实现

```python
# 反思式生成：记忆驱动迭代（参数冻结），含写入门槛与容量控制
class ReflexionAgent:
    def __init__(self, model, max_mem=5, r_th=0.8):
        self.model = model
        self.memory = []        # 存 (x, y, reflection)
        self.max_mem = max_mem
        self.r_th = r_th

    def _render(self, x):
        # 只拼接近期且相关的反思，避免上下文膨胀
        mem = "\n".join(f"- 教训：{r}" for (_, _, r) in self.memory[-self.max_mem:])
        return f"{x}\n\n过去的经验：\n{mem}" if mem else x

    def act(self, x, max_retry=3):
        y = self.model.generate(self._render(x))
        fb = self.critique(x, y)              # {score: float, ok: bool, summary: str}

        if fb["score"] < self.r_th and fb["summary"]:
            # 仅在失败且反馈含新信息时写入，防止噪声累积
            self.memory.append((x, y, fb["summary"]))
        if fb["ok"] or max_retry <= 1:
            return y, len(self.memory)
        return self.act(x, max_retry - 1)     # 带记忆重试

    def critique(self, x, y):
        # 实际系统中这里应接真实环境反馈：单元测试、执行结果、检索校验
        return self.model.judge(x, y)
```

## 五、与其他技术对比

- 反思 vs RLHF：反思不改权重、靠上下文记忆即时改进；RLHF 改参数、上限更高但成本与周期长。
- 反思 vs 自我批判：二者都是推理时迭代；反思强调跨轮记忆与长程任务中的策略修正，自我批判更偏单轮输出修订。
- 参数更新 vs 上下文更新：前者持久、不占上下文；后者零训练、即时生效，但受上下文长度与检索质量限制。
- 环境反馈 vs 自我评判：环境反馈（测试通过与否）客观可靠；自我评判便宜但受自偏好影响，宜优先使用前者。

## 六、常见误区

- 「记忆越多越好」：无限增长导致上下文溢出与噪声累积，需摘要、剪枝与相关性检索。
- 「反馈无需过滤」：噪声反馈会误导后续尝试，应只保留高信息量、可执行的反思。
- 「反思能突破能力上限」：基础模型不会做的，反思也做不出，它主要减少低级错误与重复犯错。
- 「反思等同于思考更久」：没有环境信号的反复思考只是在同一分布内重采样，收益有限。

## 七、与开源书·权威来源对应

- Shinn et al. 2023（Reflexion）：提出语言化反思 + 记忆的 Agent 框架，验证在决策与编程任务上的收益。
- Yao et al. 2022（ReAct）：推理与行动交织，用反思驱动动作选择，是推理时反思的重要来源。
- Wei et al. 2022（Chain-of-Thought）：展示中间推理步骤对复杂任务的必要性，为反思提供表达载体。
- LlamaIndex / LangChain：提供带记忆与回调的 Agent 框架，可作为反思式生成的工程参考实现。

## 九、演进与趋势

反思机制正从「全量记忆」走向「记忆压缩 + 自动反馈生成 + 长程检索」：用向量库或结构化经验库存储反思，按需检索以支持超长任务；用可验证信号（单元测试、执行器、形式化校验）替代主观评判，提高反馈可靠性；把反思与工具调用深度耦合，让「想—做—验证」形成闭环；并探索把高频有效的反思蒸馏进模型参数，使上下文层的临时改进沉淀为持久能力。

## 十、小结

反思机制以记忆驱动迭代，适合需要试错的复杂任务，是零训练成本的元策略改进。其工程关键在于控制记忆规模、保证反馈质量，并清醒认识到它无法突破基础模型的能力上限。
