# 无限上下文与检索增强

> 对应 RAG (Lewis 2020); Atlas (Izacard 2022); RETRO (Borgeaud 2021)。

## 一、背景与挑战
要让 LLM 拥有"无限"记忆，需把外部检索整合到生成过程。检索增强生成（RAG）是这一方向的主流。

## 二、核心原理
三类集成方式：
1. 一次性 RAG：检索文档入 prompt，模型生成。
2. 迭代 RAG：多次检索 + 重写查询。
3. 端到端 RAG：检索与生成联合训练（如 RETRO、Atlas）。

## 三、形式化与数学基础
RETRO 形式：$ y = f(x, \text{retrieve}(x, D); \theta) $，其中检索模块可微。Atlas 用 FiD（Fusion-in-Decoder）解码多个文档。

## 四、代码实现
```python
# RETRO 风格
chunks = retrieve(query, k=10)
chunk_emb = embed(chunks)
y = decoder(query_emb, chunk_emb)  # 交叉注意力
```

## 五、与其他技术对比
- vs 端到端微调：RAG 数据高效（无需更新权重）。
- vs 工具调用：RAG 是被动检索，工具调用更灵活。

## 六、常见误区
- 检索质量是上限，需高质量索引。
- 文档切分与去重对结果影响大。

## 七、与开源书/权威来源对应
- facebookresearch/retrieval-augmented-lm。
- huggingface/transformers RAG 实现。
- run-llama/llama_index。

## 八、面试题
- RAG 与微调如何选？答：知识更新频繁选 RAG，任务模式变化选微调。

## 九、演进与趋势
基础 RAG → 多跳 RAG → 端到端 RAG（RETRO/Atlas）→ GraphRAG。

## 十、小结
RAG 是"无限上下文"的工程实用方案，核心是高质量检索。
