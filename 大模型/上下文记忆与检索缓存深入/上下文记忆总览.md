# 上下文记忆总览

> 对应 transformer-XL (Dai 2019); Memorizing Transformer (Wu 2022); RAG (Lewis 2020)。

## 一、背景与挑战
LLM 上下文窗口有限（4k-128k），但应用常需"无限"记忆。上下文记忆（in-context memory）通过外部存储 + 检索扩展可用信息。

## 二、核心原理
方案1：长上下文（直接扩到 128k+）。
方案2：检索增强（RAG）：查询时检索外部文档并入 prompt。
方案3：记忆 token：让模型学会"写入"长期记忆位置。
方案4：Memorizing Transformer：在注意力中检索 kNN 文档。

## 三、形式化与数学基础
RAG 形式：$ y = f(x, \text{retrieve}(x, D)) $，$D$ 是外部文档库。检索分数常用向量相似度 $\text{sim}(q, d) = q^\top d / \|q\|\|d\|$。

## 四、代码实现
```python
# 简易 RAG
query_emb = embed(query)
topk = faiss_index.search(query_emb, k=10)
context = "\n".join([docs[i] for i in topk[1][0]])
prompt = context + "\nQ: " + query
answer = llm(prompt)
```

## 五、与其他技术对比
- vs 长上下文：长上下文直接但贵，RAG 便宜但检索质量受限。
- vs 微调：微调改变权重，RAG 改输入。

## 六、常见误区
- RAG 不是万能，检索错则全错。
- 上下文记忆与模型参数化记忆是不同机制。

## 七、与开源书/权威来源对应

## 八、面试题
- RAG 的局限？答：检索质量上限即答案质量上限。

## 九、演进与趋势
长上下文 → RAG → 记忆 token → MemGPT 风格分层记忆。

## 十、小结
上下文记忆是 LLM 应用的核心能力，RAG 是主流实现。
