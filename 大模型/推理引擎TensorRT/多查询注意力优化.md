# 多查询与分组查询注意力

> 对应 Shazeer, *Multi-Query Attention*, 2019 与 Ainslie et al., *GQA: Training Generalized Multi-Query Transformer Models*, 2023。

## 一、背景与挑战

标准多头注意力（MHA）中，每个注意力头都有各自独立的 K、V 投影。解码时每个头的 K/V 都要单独缓存进 KV Cache，导致 KV 显存与访存量随**头数**线性膨胀。在长上下文、高并发场景下，KV Cache 成为显存与时延的主要瓶颈。能否**让多个头共享同一份 K/V**，从而压缩 KV 体积？这正是 MQA / GQA 的出发点。

## 二、核心原理

- **MHA（多头）**：有 $h$ 个头，各自 $K,V \in \mathbb{R}^{d}$，KV 总量正比于 $h$。
- **MQA（多查询）**：所有 $h$ 个 Q 头**共享同一组** $K,V$（即 $n_{\text{kv}}=1$），KV 体积降至 $1/h$，大幅减显存带宽，解码更快；代价是表达力略降、质量可能略损。
- **GQA（分组查询）**：把 $h$ 个头分成 $g$ 组（$1<g<h$），每组共享一组 K/V（$n_{\text{kv}}=g$），是 MHA 与 MQA 的折中——既显著压缩 KV，又比 MQA 更保质量。

主流模型（LLaMA-2/3、Mistral、Qwen 等）普遍采用 GQA，默认在质量与效率间取得平衡。

## 三、形式化与数学基础

设头数 $h$、每组头数 $d$，KV 头数 $n_{\text{kv}}$（$n_{\text{kv}}=h$ 为 MHA，$=1$ 为 MQA，$g$ 为 GQA）。单 token 单层 KV 字节数：

$$M_{\text{kv,1tok}} = 2 \cdot n_{\text{kv}} \cdot d \cdot s_{\text{bytes}}.$$

对比 MHA 压缩比为 $h / n_{\text{kv}}$。解码单步注意力对 KV 的访存量随之降为原来的 $n_{\text{kv}}/h$，使 memory-bound 的解码更快。GQA 计算时第 $i$ 个 Q 头使用其所属组 $g(i)$ 的 K/V：

$$\text{Attn}_i = \text{softmax}\!\left(\frac{q_i K_{g(i)}^\top}{\sqrt d}\right) V_{g(i)}.$$

## 四、代码实现

HuggingFace 中以 `num_key_value_heads` 表达 GQA/MQA（等于 $h$ 即 MHA）：

```python
from transformers import AutoConfig
cfg = AutoConfig.from_pretrained("meta-llama/Llama-2-7b-chat-hf")
print(cfg.num_attention_heads, cfg.num_key_value_heads)
# LLaMA-2-7b: (32, 32) MHA; 70b: (64, 8) -> GQA, g=8
```

概念：把 Q 头按组重复映射到共享 K/V：

```python
# repeat_kv: 把 n_kv 个 K/V 复制到每组内 h/g 个 Q 头
K_rep = repeat_kv(K, n_rep=g)   # shape [B, h, S, d]
V_rep = repeat_kv(V, n_rep=g)
```

## 五、与其他注意力变体对比

| 类型 | KV 头数 | KV 大小 | 质量 | 解码速度 |
|------|--------|---------|------|---------|
| MHA | $h$ | 大 | 高 | 慢 |
| MQA | 1 | 最小 | 略降 | 最快 |
| GQA | $g$ | 中 | 接近 MHA | 快 |

## 六、常见误区

- **以为 MQA 一定掉点严重**：多数任务 GQA/MQA 影响很小，长文本/高并发收益远大于微小质量差。
- **把 GQA 当独立架构**：它只是注意力投影的共享策略，可叠加于任何 Transformer。
- **忽略训练时就要定**：MQA/GQA 需在训练阶段就采用；对已有 MHA 模型做后处理转换不保证等价。
- **混淆 num_key_value_heads 与 num_attention_heads**：前者是 KV 头数，决定压缩比，后者是 Q 头数，决定容量，二者可不同。
- **认为 KV 越小越好**：极端 MQA 在超长上下文/强推理任务上偶有质量回落，需按任务验证。

## 九、演进与趋势

GQA 已成大模型默认配置；进一步有 **MLA（Multi-head Latent Attention，DeepSeek）** 用低秩压缩 KV 取得更高压缩比且保质量；以及 KV 量化（FP8/INT4）与 GQA 叠加。长上下文方向持续探索更省的 KV 表达。

## 十、小结

MQA 让所有 Q 头共享 K/V、GQA 按组共享，本质是用「减少 KV 头数」压缩 KV Cache 的显存与带宽，从而加速 memory-bound 的解码；GQA 作为折中兼顾质量与效率，已成为现代开源模型的标准注意力配置。
