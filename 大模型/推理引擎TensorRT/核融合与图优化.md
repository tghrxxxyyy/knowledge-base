# 核融合与图优化

> 对应 NVIDIA TensorRT-LLM 编译优化文档与通用深度学习编译（kernel fusion / graph optimization）原理。

## 一、背景与挑战

大模型推理由大量小算子（LayerNorm、RMSNorm、矩阵乘 GEMM、激活、残差加、softmax 等）串联而成。若每个算子都作为独立 CUDA kernel 启动并读写全局显存（HBM），会累积两笔巨大开销：**kernel 启动开销**与**反复的 HBM 读写**。GPU 算力远高于显存带宽，频繁访存使计算单元「饿着等数据」。核融合与图优化正是为削减这两类开销而生。

## 二、核心原理

- **算子融合（kernel fusion）**：把多个相邻算子合并进单个 CUDA kernel，中间结果留在寄存器/共享内存（SRAM），不落 HBM。例如把 `RMSNorm → QKV 投影 → 残差` 融成一个 kernel。融合层数越多，省下的读写与启动次数越多。
- **图优化（graph optimization）**：在整图层面做常量折叠、布局变换（NCHW↔NHWC）、死代码消除、精度转换（插入 quant/dequant）、层调度重排，并在编译期选定最优 kernel 实现与分块策略。
- TRT-LLM 以 **plugin**（如 `gemm_plugin`、`attention_plugin`）形式提供高度融合的定制 kernel，是性能关键。

## 三、形式化与数学基础

设某子图有 $m$ 个算子，第 $j$ 个读写张量大小 $T_j$，HBM 带宽 $B_w$。未融合时访存约 $\sum_j c_j T_j$（$c_j$ 为读写系数），融合后中间张量不再落 HBM，仅首尾与 HBM 交互，访存降为 $O(T_{\text{io}})$。启动开销由 $m \cdot t_{\text{launch}}$ 降为 $t_{\text{launch}}$（单 kernel）。计算强度（arithmetic intensity）：

$$\text{AI} = \frac{\text{FLOPs}}{\text{Bytes}},\qquad \text{融合后 AI 提升} \Rightarrow \text{更接近 compute-bound}.$$

SRAM 带宽约为 HBM 的数十倍，故留在片上即大幅提速。

## 四、代码实现

TRT-LLM 构建时启用 plugin 即触发融合（示意）：

```bash
trtllm-build --checkpoint_dir ./ckpt \
  --output_dir ./engine \
  --gemm_plugin float16 \
  --attention_plugin float16
```

概念：融合 RMSNorm + 线性投影到一个 kernel：

```cpp
// 伪代码：单 kernel 内完成 norm 与投影，x 不写回 HBM
__global__ void fused_rmsnorm_qkv(float* x, float* w, float* out) {
    float ss = rms(x);                 // 寄存器内求和
    for (int i : threads) out[i] = (x[i]/ss) * w[i];  // 直接送 GEMM
}
```

## 五、与其他优化对比

| 优化 | 削减的开销 | 发生阶段 |
|------|-----------|---------|
| 核融合 | HBM 读写 + 启动 | 编译/构建 |
| 图优化 | 冗余计算/布局 | 编译 |
| 量化 | 带宽/算力 | 构建+运行 |
| 连续批处理 | 空闲等待 | 运行 |

## 六、常见误区

- **认为融合越多越好无代价**：融合会增大单 kernel 寄存器/共享内存占用，过度融合可能反而溢出或降低占用率，需编译期搜索。
- **混淆构建慢与推理慢**：融合增加的是一次性编译时间，换来的是长期推理加速。
- **以为所有框架都默认融合**：需引擎支持 plugin，否则退化为逐算子执行。
- **把融合等同于「算子越少越好」**：融合还要受寄存器/共享内存容量约束，过度融合可能降低占用率。
- **忽视精度对齐**：融合后数值累积顺序变化，FP16 下可能与逐算子结果有微小差异，需回归校验。

## 九、演进与趋势

融合走向自动化：编译期用代价模型搜索最优融合子图；与 **FP8/FP4 Tensor Core** 融合（quant 内嵌）；**FlashAttention** 本身即注意力算子的极致融合；以及面向新架构（Blackwell）的持久化 kernel（persistent kernel）减少启动。融合+量化仍是性能主线。

## 十、小结

核融合把相邻算子合并为单 kernel、图优化在整图层面消除冗余与重排，二者共同削减 HBM 读写与 kernel 启动开销，是 TRT-LLM 等编译型引擎相对即时执行框架的性能源泉；代价是更长的一次性编译时间，适合固定模型的高频服务。
