# 吞吐与延迟优化

> 对应 NVIDIA TensorRT-LLM 性能调优指南与 vLLM / TRT-LLM 生产实践文档。

## 一、背景与挑战

大模型推理服务有两个常被同时追求却互相牵制的指标：**吞吐（throughput，req/s 或 token/s）** 与 **延迟（latency）**。延迟又拆成首 token 延迟 **TTFT（Time To First Token）** 与每输出 token 间隔 **TPOT（Time Per Output Token）**。线上调优的目标是：在既定 TTFT/TPOT SLO 约束下，把单卡/集群能扛的并发与吞吐推到最高。难点在于瓶颈可能是算力、显存带宽或显存容量三者之一，须先定位再下药。

## 二、核心原理

调优遵循「先定量、再改参」：用压测工具（如 benchmarks 或 LM Bench）测量各分位延迟与 GPU 利用率。若算力吃满（SM 占用高、kernel 密），是 compute-bound，靠更优 kernel/量化；若显存带宽吃满（kernel 少但 HBM 带宽满），是 memory-bound，靠减小 KV/权重位宽；若 OOM 或并发上不去，是容量瓶颈，靠分页/共享前缀。各杠杆：

- 提高并发上限（连续批处理）；
- 降低 KV/权重精度（FP8/INT4）；
- 投机解码提解码速度；
- 前缀缓存省重复计算；
- 调 `--gpu-memory-utilization` 与并行策略。

## 三、形式化与数学基础

理想吞吐受最短木板约束。设单步算力上限 $F_{\text{flops}}$，权重访存 $M_w$，HBM 带宽 $B_w$，则权重受限步时间：

$$t_{\text{mem}} = \frac{M_w}{B_w}, \qquad t_{\text{calc}} = \frac{\text{FLOPs}_{\text{step}}}{F_{\text{flops}}}.$$

若 $t_{\text{mem}} > t_{\text{calc}}$ 为 memory-bound（大模型解码典型）；量化把 $M_w$ 减半即可近倍提速。端到端吞吐近似：

$$\text{Throughput} \approx \frac{\text{并发数} \times \text{平均输出长度}}{T_{\text{TTFT}} + \text{TPOT} \times L_{\text{out}}}.$$

## 四、代码实现

TRT-LLM 构建时选量化与并行（影响吞吐/延迟）：

```bash
trtllm-build --checkpoint_dir ./ckpt \
  --output_dir ./engine \
  --gemm_plugin fp8 \
  --quant_fp8 \
  --tp_size 4
```

用内置基准测延迟分布：

```bash
python benchmarks/cpp/perf_benchmarks.py \
  --model ./engine --num_requests 256 --dataset ./prompts.json
```

## 五、与其他技术对比

| 杠杆 | 影响 | 代价 |
|------|------|------|
| FP8 权重 | 降带宽/算力 | 需 Hopper+，近似无损 |
| INT4 权重量化 | 更省显存/带宽 | 质量略降 |
| 投机解码 | 降 TPOT | 需草稿模型 |
| 前缀缓存 | 降 TTFT | 占用额外显存 |

## 六、常见误区

- **盲目堆 batch**：容量瓶颈下只会增加 TPOT 与 OOM 风险，不提吞吐。
- **只盯平均延迟**：尾部 p99 才是 SLO 失效点，需看分位。
- **忽略 TTFT 与 TPOT 的不同瓶颈**：TTFT 受 prefill 算力主导，TPOT 受解码带宽主导。
- **量化一刀切**：并非所有层都适合同一精度，敏感层（如注意力输出投影）留 FP16 常更稳。
- **不区分在线/离线**：离线批量可放任大 batch 求吞吐，在线交互须守延迟 SLO，策略不同。

## 九、演进与趋势

调优走向自动化：自动搜索最优 `--tp_size`、量化方案与批上限；分离 prefill 与 decode 两阶段部署（disaggregated serving）以分别优化 TTFT/TPOT；以及基于实时负载的弹性并发。多实例 + 网关调度成为大规模服务常态。

## 十、小结

吞吐与延迟优化要先定位瓶颈（算力/带宽/容量），再用「并发+量化+投机解码+前缀缓存+并行」组合杠杆在 SLO 内最大化吞吐；核心认知是 TTFT 由 prefill 算力主导、TPOT 由解码显存带宽主导，二者优化手段不同。
