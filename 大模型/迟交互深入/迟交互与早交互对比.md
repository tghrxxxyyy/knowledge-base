# 迟交互与早交互对比

> 对应 检索架构分类；与 双塔模型深入 / 多向量检索深入 对照。

## 一、背景与挑战

交互发生的早晚直接决定精度与效率。

## 二、核心原理

早交互（双塔）：编码即聚合，仅一次内积，最快但最弱。迟交互：保留 token 向量，检索时聚合，慢些但细。早融合（交叉编码器）：输入即拼接，最强但不可索引。

## 三、数学形式

早：$s=q^\top d$；迟：$s=\sum_i\max_j q_i^\top d_j$；早融合：$s=C([q;d])$。

## 四、代码实现

```python
early = q @ d.T
late = sum(max(q[i]@d.T) for i in range(len(q)))
```

## 五、与其他对比

- 与 检索重排序深入（早融合即重排）互补。
- 与 双塔推理加速（早交互索引）对照。

## 六、常见误区

- 以为迟交互可完全替代重排；难 query 仍须重排。
- 早交互精度不足时长文档检索差。

## 八、面试题

- 三类交互取舍？答：早交互召回快、迟交互折中、早融合精排准但不可索引。

## 九、演进

早交互 → 迟交互 → 早融合（两阶段）。

## 十、小结

交互早晚是检索精度-效率主轴，常三段式组合使用。
