# 迟交互检索实践

> 对应 ColBERT/PLAID 部署经验；与 RAG 检索链路衔接。

## 一、背景与挑战

上线需平衡精度、成本与更新频率。

## 二、核心原理

离线建压缩多向量索引；在线查询裁剪+迟交互打分；与重排组合；监控延迟与召回。

## 三、数学形式

端到端延迟 $L=L_{enc}+L_{late}(|Q|\cdot|B|)+L_{rerank}$；$B$ 为命中桶均大小。

## 四、代码实现

```python
Q = colbert.encode(q); hits = plaidx.search(Q, k=50)
ctx = rerank(q, [h.text for h in hits], k=5)
```

## 五、与其他对比

- 与 多向量检索深入（同索引）共享。
- 与 检索重排序深入 组合。

## 六、常见误区

- 索引未随数据更新致陈旧。
- 查询不裁剪致延迟高。

## 八、面试题

- 迟交互上线要点？答：压缩索引、查询裁剪、与重排组合、监控延迟召回。

## 九、演进

研究原型 → PLAID 服务 → 自适应桶。

## 十、小结

迟交互实践以压缩与裁剪控成本，配合重排提升 RAG 召回。
