# 批处理与调度协同

> 对应 Yu et al., *Orca: Iteration-Level Scheduling*, OSDI 2022；与 优先级调度深入 / 连续批处理 衔接。

## 一、背景与挑战

调度决策需与连续批处理协同，否则优先级在批内被摊平。

## 二、核心原理

在每解码步组批时纳入优先级与长度感知，使高优先请求优先进批，并在批满时按优先级淘汰。

## 三、数学形式

步级组批 $B_t=\text{top}_k(\text{eligible}, k)$ 按 $(p_i,\, -w_i)$ 排序，$w_i$ 为已等待。

## 四、代码实现

```python
eligible = [r for r in queue if kv_ok(r)]
batch = sorted(eligible, key=lambda r: (r.prio, -r.waited))[:max_b]
```

## 五、与其他对比

- 与 连续批处理（机制）配合实现优先级。
- 与 请求调度与排队（组批入口）衔接。

## 六、常见误区

- 优先级只用于排队不用于组批，效果打折。
- 批满时一律 FIFO 丢高优先。

## 八、面试题

- 调度如何与批处理协同？答：在步级组批时按优先级排序入选，使高优先请求进批更靠前。

## 九、演进

批后调度 → 批内 FIFO → 步级优先组批。

## 十、小结

调度价值需落到连续批的步级组批，才能真正生效。
