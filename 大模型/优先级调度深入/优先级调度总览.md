# 优先级调度总览

> 对应 Agrawal et al., *Sarathi-Serve: Turbocharging LLM Serving with Quasi-Preemptive Scheduling*, 2023（arXiv:2308.16369）；与 优先级调度深入 / 服务框架深入 衔接。

## 一、背景与挑战

多用户/多任务共享 GPU，需决定谁先执行、谁可抢占，以保 SLA 与公平。

## 二、核心原理

在请求/批层面按优先级（用户 tier、SLA 紧急度、长度）调度，必要时抢占低优先级以保高优先。

## 三、数学形式

调度准则：选序使加权完成时间 $\sum w_i C_i$ 最小；优先级 $p_i$ 高者优先 $C_i$ 小。

## 四、代码实现

```python
reqs.sort(key=lambda r: (r.priority, r.arrival), reverse=True)
```

## 五、与其他对比

- 与 请求调度与排队（调度在前级）互补。
- 与 网关限流深入（优先级在入口先标）呼应。

## 六、常见误区

- 静态优先级致低层长期饿死。
- 优先级只看用户忽略长度导致队头阻塞。
