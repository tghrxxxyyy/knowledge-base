# 量化评估与部署

> 对应量化基准（如 perplexity / MMLU 退化评估）；mlabonne/llm-course 评测章节。

## 一、背景与挑战

量化后需验证精度损失与加速收益，避免“压了但坏了”。

## 二、核心原理

用困惑度（PPL）、下游任务（MMLU/QA）评估；测量显存下降与吞吐提升；按层敏感度做混合比特（敏感层留高精度）。

## 三、数学形式

PPL $= \exp(-\frac1N\sum_i\log p(w_i|w_{<i}))$；加速比 $= T_{fp16}/T_{quant}$。

## 四、代码实现

```python
ppl = torch.exp(-mean(logprobs))
print("mem", get_mem(model), "speedup", base/ppl_time)
```

## 五、与其他对比

- 与 边缘设备部署优化深入（部署目标）衔接。
- 与 成本优化与资源调度深入（显存即成本）相关。

## 六、常见误区

- 只看 PPL 忽略任务级退化。
- 均匀比特忽略了层敏感度差异。

## 八、面试题

- 如何评估量化好坏？答：PPL + 下游任务 + 显存/吞吐，敏感层用混合精度兜底。

## 九、演进

人工试 → 自动混合精度搜索 → 按敏感度逐层配置。

## 十、小结

量化须多维评估，混合精度是平衡精度与压缩的务实手段。
