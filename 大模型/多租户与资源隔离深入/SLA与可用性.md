# SLA 与可用性

> 见「多租户与资源隔离深入/多租户架构」与「推理服务深入/服务可观测」。

## 一、背景与挑战

企业客户需明确 SLA（可用性/延迟），否则不可用。

## 二、核心原理

定义 SLO（如 99.9% 可用、P95 延迟），多副本+健康检查+故障转移+降级（小模型兜底）保障。

## 三、关键要点

- 降级保核心不崩。
- 多区域防单点。

## 四、代码实现

```python
if primary_unhealthy: switch_to(standby)
```

## 五、与其他对比

- 单实例无 SLA；多副本才稳。
