# 配额与计费

> 对应 LiteLLM 用量计量与计费实践、以及云厂商 LLM 用量计量文档。

## 一、背景与挑战

多租户平台必须解决「谁用了多少、该收多少钱、预算如何约束」三件事。没有计量，成本无法分摊；没有配额，单个租户可能耗尽共享额度影响他人；没有预算封顶，可能出现天价账单。计费还须与推理引擎的实际资源消耗对齐，否则账实不符、客户投诉，甚至引发合规与信任危机。

计费口径本身也充满坑：token 计数方式（BPE/wordpiece）、是否计入思考 token、缓存命中如何折算、长上下文的 KV cache 占用是否单独计价——这些都需要与推理引擎严格对齐，否则「账单上的 token」与「模型实际消耗的 token」出现偏差。

从治理视角，配额与计费还是「行为引导」工具：通过差异化单价（高峰更贵、缓存命中更便宜）引导租户错峰与复用，既平抑集群负载又降低全局成本。因此配额不只要「限」，更要「导」——用价格信号把租户行为塑造成对平台整体有利的形态，而非单纯设置上限阻止滥用。

## 二、核心原理

计量维度通常包括：输入/输出 token 数、请求次数、推理时长、缓存命中与否、模型等级（如 GPT-4 vs 小模型）。系统按「分层套餐 + 超额付费」组合计费；实时把每次用量写入账单，超预算即限流或阻断。配额则约束并发、速率（RPM/TPM）与月度额度。缓存命中可不计费或减半，鼓励复用。配额与隔离需在路由层统一生效，避免「计费在 A 层、限流在 B 层」的割裂。

关键要点：

- 计量维度含输入/输出 token、请求数、时长、缓存命中、模型等级。
- 分层套餐 + 超额付费组合计费，实时写入账单并超预算限流。
- 配额约束并发、速率（RPM/TPM）与月度额度。
- 缓存命中应折减以激励复用，而非全价计费。
- 预算封顶需实时生效，避免天价账单。
- 配额与隔离需在路由层统一闭环，避免账实偏差。

## 三、形式化与数学基础

单次请求费用：

$$
\text{cost} = \frac{n_{\text{in}}}{1000}\cdot p_{\text{in}} + \frac{n_{\text{out}}}{1000}\cdot p_{\text{out}} - \delta\cdot \mathbb{1}[\text{cache hit}]
$$

其中 $p$ 为每千 token 单价，$\delta$ 为缓存折减。租户 $t$ 累计账单：

$$
B_t = \sum_k \text{cost}_k
$$

预算约束：$\text{if } B_t > B_t^{\max}$ then $\text{throttle}(t)$。速率约束：

$$
\sum_{k\in\text{window}} \text{tokens}_k \le \text{TPM}_t
$$

并发约束：在途请求数 $\le \text{CONC}_t$。

## 四、代码实现

```python
# 按 token 实时计费并校验预算
def charge(tenant, n_in, n_out, p_in, p_out, cache_hit=False):
    cost = (n_in * p_in + n_out * p_out) / 1000.0
    if cache_hit:
        cost *= 0.5                        # 缓存命中折减
    if bill[tenant] + cost > budget[tenant]:
        raise QuotaExceeded(tenant)
    bill[tenant] += cost
    return cost

# 速率限制（令牌桶）
def allow(tenant, tokens, bucket):
    if bucket[tenant].consume(tokens):
        return True
    return False                           # 触发 429 限流

# 并发限制：路由层统一准入
def admit(tenant, inflight):
    if inflight[tenant] >= CONC[tenant]:
        raise ConcurrencyExceeded(tenant)
```

## 五、与其他技术对比

| 计费方式 | 公平性 | 复杂度 | 适用 | 账实对齐难度 |

| 分层套餐 + 超额 | 高 | 高 | 企业 | 中 |
| 算力时长 | 中 | 高 | 自建集群 | 高 |

## 六、常见误区

误区一：只计输出 token——输入同样消耗上下文与算力。误区二：缓存命中仍全价——应折减以激励复用。误区三：预算只在月底核算——需实时封顶防爆单。误区四：配额与隔离脱节——限流需在路由层统一生效。误区五：忽略 KV cache 占用——长上下文的显存占用应按时长或块数另计。

## 九、演进与趋势

从「包月」到「按 token 实时计量」，再到「分层套餐 + 缓存折减 + 预算告警」一体化；平台引入信用额度、预付费与跨模型统一计价，并按租户等级联动配额与 SLA。计量逐步下沉到推理引擎内核，使账单与真实资源消耗逐字节对齐。

## 十、小结

配额与计费让多租户平台可持续运营，核心是把计量、预算封顶与限流在路由层统一闭环，并与实际推理消耗（含 KV cache）严格对齐，避免账实偏差。
