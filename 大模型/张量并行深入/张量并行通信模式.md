# 张量并行通信模式

> 对应 Megatron-LM 通信分析；Narayanan et al., 《Efficient Large-Scale Language Model Training on GPU Clusters Using Megatron-LM》, 2022。

## 一、背景与挑战

每两层一次 all_reduce，通信次数多，需与计算重叠以隐藏延迟。

## 二、核心原理

前向/反向各在行并行处产生一次 all_reduce；用计算-通信重叠（算子间流水线）把 all_reduce 与相邻 GEMM 重叠；张量并行适合高带宽机内 NVLink。

## 三、数学形式

每层通信量约 $2b s h$（一次 all_reduce，b 批大小、s 序列、h 隐藏）；总通信随层数线性。

## 四、代码实现

```python
# 用 NCCL 异步 all_reduce 与 GEMM 重叠
work = dist.all_reduce(y, group=tp_group, async_op=True)
z = torch.matmul(y, next_w)        # 计算同时通信
work.wait()
```

## 五、与其他对比

- 与 通信压缩深入 不同：TP 通信是激活而非梯度，难压缩。
- 与 流水线并行深入 相比通信更碎但延迟更低。

## 六、常见误区

- 跨节点跑高并行度 TP 致带宽瓶颈。
- 未重叠通信致 GPU 空等。

## 八、面试题

- 张量并行适合什么硬件？答：高带宽低延迟互连（如 NVLink），跨节点效率低。

## 九、演进

同步通信 → 计算重叠 → 重排通信。

## 十、小结

张量并行通信密集，依赖机内高带宽与计算重叠才能高效。
