# 行/列并行矩阵乘法

> 对应 Megatron-LM 张量切分；Shoeybi et al., 2019。

## 一、背景与挑战

矩阵乘法是 Transformer 主要算力，需在多卡高效切分而不引入多余通信。

## 二、核心原理

列并行（按输出通道切 $A$）：各卡算独立输出列，无需通信即可拼接。行并行（按输入通道切 $A$）：各卡持不同输入通道权重，结果需 $all\_reduce$ 求和。两者链式拼接时，行并行的输入可由前一列并行输出直接提供（已分片），省一次通信。

## 三、数学形式

列并行 $Y_i=XA_i$；行并行 $Y=\sum_i X_i A_i$；连续 GEMM $Y=X A B$ 用列-行配对，仅末尾一次 $all\_reduce$。

## 四、代码实现

```python
# 列并行后直接接行并行，免中间 all_gather
a_shard = col_shard(A, rank)         # 本卡列
b_shard = row_shard(B, rank)         # 本卡行
z = torch.matmul(torch.matmul(x, a_shard), b_shard)
dist.all_reduce(z, group=tp_group)   # 仅一次
```

## 五、与其他对比

- 区别于 数据并行深入 的逐卡复制完整矩阵。
- 是 张量并行深入 总览的具体算子实现。

## 六、常见误区

- 误把列并行输出再 all_gather 后送行并行，多一次通信。
- 切分维度与 batch/序列维混淆。

## 八、面试题

- 为何列并行后接行并行只需一次通信？答：列并行输出本就是分片，行并行求和即 all_reduce。

## 九、演进

单 GEMM 切分 → GEMM 链式免通信拼接 → 融合算子。

## 十、小结

行列并行配对让连续矩阵乘仅在链尾通信，是张量并行高效关键。
