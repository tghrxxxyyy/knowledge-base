# 双塔模型（Bi-Encoder）总览

> 对应 Karpukhin et al., *DPR*, 2020；Reimers & Gurevych, *Sentence-BERT*, 2019（共享孪生编码）。

## 一、背景与挑战

检索需对十亿级文档实时打分，交叉编码器逐对编码太慢；双塔把文档离线编码、query 在线编码后内积检索。

## 二、核心原理

query 与 document 各过独立 encoder 得稠密向量，相似度仅由二者向量内积/余弦决定；文档向量预计算可建 ANN 索引。

## 三、数学形式

$q=E_q(x), d=E_d(y)$；$s(x,y)=q^\top d/(\|q\|\|d\|)$（余弦），推理复杂度 $O(N)$ 编码降为 $O(1)$ 查表。

## 四、代码实现

```python
q_emb = model.encode(query, normalize=True)
hits = index.search(q_emb, k=10)
```

## 五、与其他对比

- 速度与 迟交互/交叉编码器 对比：双塔最快但交互最弱。
- 与 稠密检索训练深入（训练目标）衔接。

## 六、常见误区

- 双塔无法建模 query-doc 细粒度词交互，长文档弱。
- 文档侧未归一化致内积≠余弦。

## 八、面试题

- 双塔为何快？答：文档向量离线预计算，在线仅编码 query 一次后内积检索。

## 九、演进

单塔 → 双塔(DPR/SBERT) → 多向量(ColBERT)。

## 十、小结

双塔以离线文档编码换检索速度，是大规模语义召回的基础结构。
