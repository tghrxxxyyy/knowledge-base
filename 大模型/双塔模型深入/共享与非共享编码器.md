# 双塔编码器共享策略

> 对应 Reimers & Gurevych, 2019（Siamese SBERT）；Karpukhin et al., 2020（DPR 独立编码器）。

## 一、背景与挑战

query 与 document 分布/长度不同，是否共享参数影响表达与效率。

## 二、核心原理

共享编码器（Siamese）参数少、易对齐，适合句对相似；独立编码器（DPR）各用 BERT，表达更强但需更多数据对齐两塔。

## 三、数学形式

共享：$E_q=E_d$；独立：$E_q\ne E_d$；投影后须映射到同维 $d$ 空间以可比。

## 四、代码实现

```python
q_emb = q_encoder(query); d_emb = d_encoder(doc)   # 可同构或异构
```

## 五、与其他对比

- 共享适合对称检索（句-句），独立适合非对称（query-段落）。
- 与 嵌入模型训练深入（池化）衔接。

## 六、常见误区

- 非对称任务强行共享致表达错配。
- 两塔未同维度归一，相似度无可比性。

## 八、面试题

- 何时共享编码器？答：对称检索（两塔分布同）可共享省参并保对齐。

## 九、演进

独立双塔 → 共享孪生 → 适配器区分。

## 十、小结

编码器共享与否取决于任务对称性，非对称检索常用独立塔更灵活。
