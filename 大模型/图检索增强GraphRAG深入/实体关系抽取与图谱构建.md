# 实体关系抽取与图谱构建

> 对应 microsoft/graphrag 开源仓库与 huggingface/transformers 信息抽取能力。

## 一、背景与挑战
GraphRAG 的第一步是把非结构化文本转为图。抽取质量直接决定后续检索与摘要的上限，噪声实体会污染图谱。

## 二、核心原理
用 LLM 对每个文本块做零样本/少样本抽取，输出实体（带类型）与关系三元组（头-关系-尾），并做去重与共指消解，合并同名实体，形成统一图。

## 三、形式化与数学基础
对每个块 $c_i$，抽取函数：
$\mathcal{T}_i = \text{LLM}_{\text{ext}}(c_i) = \{(e_h, r, e_t)\}$
合并图：$G = \bigcup_i \text{merge}(\mathcal{T}_i, \text{resolve}(e))$
其中 resolve 为实体对齐（如归一化命名与类型）。

## 四、代码实现
```python
def extract_triples(llm, chunk):
    out = llm.complete(f"抽取实体与关系三元组，JSON列表：\n{chunk}")
    return parse_triples(out)
def build_graph(chunks, llm):
    g = Graph()
    for c in chunks:
        for (h, r, t) in extract_triples(llm, c):
            g.add_edge(h, t, label=r)
    return g
```

## 五、与其他技术对比
相比传统 NLP 流水线（NER+RE 分别训练），LLM 抽取零样本、泛化好但成本高；可混合小模型提效。图构建也可从已有知识库导入。

## 六、常见误区
误区一：抽取越多三元组越好，冗余关系拖慢检索。误区二：忽略共指，导致同一实体分裂成多个节点。

## 七、与开源书/权威来源对应
- microsoft/graphrag 提供抽取提示与图存储。
- huggingface/transformers 可承载 NER/RE 模型。
- run-llama/llama_index 支持图谱索引。
