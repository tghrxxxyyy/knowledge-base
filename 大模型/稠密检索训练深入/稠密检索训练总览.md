# 稠密检索训练总览

> 对应 Karpukhin et al., *Dense Passage Retrieval (DPR)*, 2020（开放域问答的双塔稠密检索训练）。

## 一、背景与挑战

词法检索（BM25）只能做字面匹配，无法捕捉语义近义；稠密检索把 query 与 passage 编码到同一向量空间，用内积召回，但随机初始化编码无语义结构，必须训练。

## 二、核心原理

用双塔 encoder 分别编码 query 与 passage，训练目标让正例对相似度高于负例；推理时对全库 passage 离线建向量索引，query 在线编码后做 ANN 检索。

## 三、数学形式

对比损失 $\mathcal L = -\log\frac{\exp(s(q,p^+))}{\exp(s(q,p^+))+\sum_{i=1}^n\exp(s(q,p_i^-))}$，其中 $s(q,p)=E_q(q)^\top E_p(p)$。

## 四、代码实现

```python
from sentence_transformers import InputExample
train = [InputExample([q, pos], label=1), InputExample([q, neg], label=0)]
```

## 五、与其他对比

- 与 双塔模型深入（编码结构）共享；与 向量检索算法深入（索引）衔接。
- 与 混合检索深入（稠密一路）互补。

## 六、常见误区

- 仅用随机负例训练信号弱，须引入难负例。
- 训练语料与下游检索分布不一致致迁移差。

## 八、面试题

- 稠密检索为何需训练？答：随机编码无语义结构，训练把相关对拉近、负例推远。

## 九、演进

词法检索 → DPR 双塔 → 难负例/蒸馏 → 生成式检索。

## 十、小结

稠密检索以双塔对比训练拉近语义空间，是 RAG 召回核心，但依赖高质量正负对。
