# 难负例挖掘（Hard Negative Mining）

> 对应 Xiong et al., 2020（ANN 难负例）；Zhan et al., *ANCE*, 2021（近似最近邻难负例）。

## 一、背景与挑战

随机/批内负例太易，模型学不到细粒度区分；需用与正例相近的难负例提升判别力。

## 二、核心原理

先用当前检索器从全库召回 top-k（排除正例），取排名靠前但非相关的 passage 作难负例；ANCE 用自身最近检出的近邻动态更新难负例，避免 stale。

## 三、数学形式

难负例集 $H_i = \text{TopM}_{p\ne p_i^+} E_q(q_i)^\top E_p(p)$；损失在正负+难负上计算。

## 四、代码实现

```python
hard = index.search(enc(q), k=50)[1][0][1:10]   # 跳过正例取近邻
```

## 五、与其他对比

- 比 批内负例 更具判别性但需离线召回步骤。
- 与 检索器训练深入（RocketQA 迭代）共享。

## 六、常见误区

- 太难负例（接近正例却真相关）成噪声，须人工校验或阈值。
- 一次性难负例 stale，需周期刷新。

## 八、面试题

- 为何要难负例？答：易负例无区分度，难负例逼模型学细粒度语义差异。

## 九、演进

随机负例 → 离线难负例 → ANCE 动态难负例。

## 十、小结

难负例是稠密检索精度关键，难度须适中并用近期模型刷新。
