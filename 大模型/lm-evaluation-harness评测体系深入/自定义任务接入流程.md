# 自定义任务接入流程

> 对应 Gao et al. 2021 lm-evaluation-harness（EleutherAI）任务扩展文档与官方示例；参考官方仓库 tasks 目录。

## 一、背景与挑战

业务自有评测集（内部知识问答、领域合规、私有基准）往往无法用现成任务覆盖，若每次都从零写脚本，会重复造轮子：数据加载、few-shot、缓存、并行、报告全要重写，且结果与社区基准不可比。harness 提供低成本接入机制：既支持声明式 YAML（简单任务），也支持 Python Task 子类（复杂逻辑），注册后即可被统一 evaluator 调度，自动获得缓存、并行与标准报告。挑战在于：接入需遵循任务接口契约，否则会出现指标命名冲突、结果结构错误或与其他任务不兼容。

## 二、核心原理

接入两种路径：

1. 声明式（YAML）：仅配置 dataset、doc_to_text、metric 等，适合标准格式任务，无需写代码。
2. 编程式（Task 子类）：继承 `lm_eval.api.task.Task`，实现关键方法，适合自定义逻辑（如特殊打分、动态 few-shot、工具调用评测）。

最小接口契约包括：数据加载（`training_docs`/`test_docs`）、文档到文本（`doc_to_text` 或 `construct_requests`）、结果处理（`process_results`）、聚合与方向（`aggregation`/`higher_is_better`）。实现后在 `lm_eval/tasks` 注册，或经 `TASK_REGISTRY`/`DEFAULT_TASK_REGISTRY` 加载。

## 三、形式化与数学基础（含 LaTeX）

任务接口约束为一组必须可调用的方法集合：

$$
\mathcal{I}=\{\text{doc\_to\_text},\ \text{fewshot\_context},\ \text{construct\_requests},\ \text{process\_results},\ \text{aggregation}\}
$$

evaluator 对样本 $i$ 调用：

$$
r_i=\text{process\_results}\big(\text{doc}_i,\ \text{construct\_requests}(\text{doc}_i)\big)
$$

再按 aggregation 规约：

$$
M=\text{aggregation}(\{r_i\})
$$

只要 $\mathcal{I}$ 被满足，evaluator 无需关心任务内部，从而实现「一次接入、统一调度」。

## 四、代码实现

```python
# 最小 process_results 实现（结构示意）
def process_results(self, doc, results):
    # results: 模型输出列表，取首个
    pred = results[0].strip()
    gold = doc["answer"].strip()
    return {"acc": float(pred == gold)}
```

## 五、与其他技术对比

- 从零写脚本：灵活但重复、不可比、无缓存/并行/报告。
- harness 接入：自动获得缓存、并行、标准报告与社区可比性。
- YAML vs 子类：前者零代码但受限，后者灵活但有维护成本，按复杂度选择。

## 六、常见误区

- 「在 process_results 里做重计算」：会拖慢评测，重活应前置到请求构造。
- 「忽略指标命名冲突」：自定义指标名与内置重名会被覆盖，应加前缀。
- 「few-shot 取自测试集」：造成泄露，须用训练/校验拆分。
- 「未声明 aggregation/higher_is_better」：报告缺失或排序错误。

## 九、演进与趋势

声明式任务 + 模板库让非工程师也能贡献评测；任务依赖与组合（如先检索再问答）被支持；自动校验接口契约降低接入错误率。

## 十、小结

自定义任务接入以「声明式 YAML 或 Task 子类」两种路径，复用 harness 的缓存、并行与报告，使私有基准低成本纳入统一评测。其权威基础是 Gao 2021 与官方扩展文档，落地关键是满足接口契约、规范 few-shot 来源并避免指标冲突。
