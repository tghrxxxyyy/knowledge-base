# 指标计算与聚合逻辑

> 对应 Gao et al. 2021 lm-evaluation-harness（EleutherAI）指标与聚合设计；参考官方仓库 metric 实现。

## 一、背景与挑战

不同任务使用的指标语义迥异：MMLU 用多选准确率，WikiText 用困惑度（perplexity），翻译用 BLEU，生成式问答可能用 exact match 或基于模型判分。若每个任务各自硬编码聚合，既重复又易错，且跨任务构建「综合榜单」时面临量纲不可比（acc 是 0–1，perplexity 是正值、越低越好）。harness 的设计是把「指标计算、聚合函数、方向（higher_is_better）」声明为任务的可插拔部分，由 evaluator 在样本级结果上统一规约，保证透明与可组合。

挑战在于：聚合必须可解释（知道综合分由哪些子指标加权）、须报告方差（stderr）以判断显著性，且不同量纲不可直接平均。

## 二、核心原理

- 样本级处理：`process_results(doc, results)` 把模型原始输出转为若干指标值（如 `acc`、`f1`）。
- 聚合函数：每个指标声明 aggregation（mean、median、perplexity 取 exp(mean(log)）等。
- 方向声明：`higher_is_better` 标记，避免排序反转（如 perplexity 应越低越好）。
- 报告方差：同时给出 stderr，支撑显著性判断。
- 跨任务综合：仅在同量纲、同方向下加权，否则分别报告。

报告时应同时给出样本量与置信区间；样本过少时均值本身不可信。LLM-as-judge 类指标还需额外报告裁判一致性（如多次评判的同意率），避免把裁判噪声当模型能力。对多选题，是否向模型展示选项字母、是否要求固定输出格式，都会改变 loglikelihood 比较的公平性，需在配置中固化。

补充要点：
- 对生成式评分，需固定解码策略与停止条件，否则指标不可比。
- 综合分发布时应附各子项明细与样本量，便于复核。
- 对 LLM-as-judge，应报告裁判自身一致性与潜在偏差方向。

## 三、形式化与数学基础（含 LaTeX）

对单指标的样本集合，均值聚合：

$$
\bar m=\frac{1}{N}\sum_{i=1}^{N} m_i,\qquad \text{stderr}=\sqrt{\frac{1}{N(N-1)}\sum_{i}(m_i-\bar m)^2}
$$

困惑度类指标先对对数似然取均值再指数化（避免被长序列长度扭曲）：

$$
\text{PPL}=\exp\!\left(-\frac{1}{L}\sum_{t=1}^{L}\log P(w_t\mid w_{<t})\right)
$$

跨任务综合分仅在归一化后加权：

$$
M=\sum_{t} w_t\, \tilde M_t,\quad \sum_t w_t=1,\quad \tilde M_t=\frac{M_t-\mu_t}{\sigma_t}\ (\text{必要时})
$$

且必须保证 $\text{higher\_is\_better}$ 一致，否则排序反转会给出错误结论。

## 四、代码实现

```python
# 加权聚合示例（结构示意，仅同量纲同方向）
def weighted(per_task):
    # per_task: [(metric_value, weight)]
    total_w = sum(w for _, w in per_task)
    return sum(m * w for m, w in per_task) / total_w

# harness 中指标声明示意
def aggregation(self):
    return {"acc": mean, "acc_stderr": stderr}

def higher_is_better(self):
    return {"acc": True}          # perplexity 等应声明 False
```

## 五、与其他技术对比

- 硬编码指标：重复、易错、不可组合。
- harness 解耦：指标与聚合分离，便于跨任务构建综合榜单。
- 与 `evaluate` 库对比：harness 把 higher_is_better 与聚合内建进 Task，更贴合 LLM 评测报告需求。

## 六、常见误区

- 「把不同量纲指标直接平均」：acc 与 perplexity 不可比，需归一或分别报。
- 「未声明 higher_is_better」：排序反转，综合榜单误导。
- 「只报均值不报 stderr」：无法判断模型间差异是否显著。
- 「perplexity 直接取均值」：应先均值对数似然再 exp，否则被长度偏置。

## 九、演进与趋势

指标血缘与不确定性估计被纳入报告；基于 bootstrap 的置信区间替代简单 stderr；模型判分（LLM-as-judge）指标需标注其自身偏差。综合分从「简单平均」走向「带权、带置信、带说明」。

实践中应警惕「指标博弈」：当综合分成为优化目标，模型可能过拟合到评测指标而偏离真实能力。对策是保持指标多样性、引入人类校准样本，并对 LLM-as-judge 类指标单独报告其一致性，避免把裁判的偏差伪装成模型的能力。

## 十、小结

指标计算与聚合逻辑必须把计算、聚合与方向声明解耦，报告均值与方差，并避免跨量纲误平均。其权威基础是 Gao 2021 与 harness 指标实现，透明、可声明的聚合是综合分具备可信度的前提。
