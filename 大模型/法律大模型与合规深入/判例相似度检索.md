# 判例相似度检索

> 对应 github facebookresearch/faiss 项目与 github stanford-futuredata/ColBERT 项目。

## 一、背景与挑战
找相似判例需理解事实要件而非关键词。用稠密向量捕捉语义，用 late-interaction 保留关键事实 token，可提升检索召回。

## 二、核心原理
把判例摘要编码为向量存入 FAISS 索引做粗排，再用 ColBERT 式 token 级最大匹配做精排，兼顾速度与精度。

## 三、形式化与数学基础
FAISS 内积检索：
$ \text{NN}(q)=\arg\max_{d} q^\top d $
精排分数 $ S=\sum_i\max_j q_i^\top d_j $。

## 四、代码实现
```python
import numpy as np

def coarse(index, q, k=50):
    d, i = index.search(q.reshape(1, -1), k)
    return i[0], d[0]

def rerank(q_tok, docs_tok):
    out = []
    for di, dt in enumerate(docs_tok):
        s = sum(max(qi @ dj for dj in dt) for qi in q_tok)
        out.append((s, di))
    return sorted(out, reverse=True)
```

## 五、与其他技术对比
相比 BM25，稠密检索覆盖同义表述；相比单向量，late-interaction 对事实要素更敏感。

## 六、常见误区
未做管辖区区分会把不同法域判例混为一谈。向量陈旧遗漏新判决。

## 八、面试题
问：为何判例检索要两阶段？答：粗排控成本，精排保相关，平衡效率与质量。

## 九、演进与趋势
要件抽取式检索、判例权重与时效性融合。

## 十、小结
语义加 token 级检索是判例推荐的核心技术。
