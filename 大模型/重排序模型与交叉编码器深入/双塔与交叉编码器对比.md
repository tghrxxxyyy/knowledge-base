# 双塔与交叉编码器对比

> 对应 Devlin et al. 2018《BERT》与 stanford-futuredata/ColBERT 及 huggingface/transformers。

## 一、背景与挑战
检索系统既要高吞吐召回又要高准重排，理解两类编码器的能力边界才能合理分工。

## 二、核心原理
双塔（bi-encoder）分别编码查询与文档，交互只在最后点积发生，可离线索引文档向量；交叉编码器在编码期全交互，精度高但须在线成对计算，无法预索引。

## 三、形式化与数学基础
双塔相似度：
$\text{sim}(q,d) = E_q(q)^\top E_d(d)$
交叉编码器分数：
$s(q,d) = f_\theta(q \oplus d)$
时间复杂度分别为 $O(Nd)$（可预计算 $E_d(d)$）与 $O(N\cdot C(q,d))$，后者随 N 线性且常系数大。

## 四、代码实现
```python
def bi_encoder_index(docs, enc):
    return [enc.encode_text(d) for d in docs]  # 离线
def ce_rerank(q, cands, ce):
    return sorted(cands, key=lambda d: -ce.score(q, d))  # 在线
```

## 五、与其他技术对比
ColBERT 是折中：延迟交互（late interaction）保留 token 级向量，可在近似预索引下获得接近交叉编码器的精度，比纯双塔更强、比交叉编码器更快。

## 六、常见误区
误区一：认为双塔一定精度低，实际上大模型双塔 + 难负例已接近交叉编码器。误区二：忽视延迟约束盲目上交叉编码器。

## 七、与开源书/权威来源对应
- Devlin et al. 2018 提供编码器基础。
- stanford-futuredata/ColBERT 实现延迟交互检索。
- huggingface/transformers 支持两类模型。

## 八、面试题
1. 双塔为何可以离线建索引而交叉编码器不行？
2. ColBERT 的 late interaction 如何兼顾两者优势？
3. 难负例对双塔训练为何重要？

## 九、演进与趋势
统一架构（如将双塔与交叉编码器共享 backbone 蒸馏）、以及用 LLM 表征替代 BERT 编码器成为新方向。

## 十、小结
双塔负责「快而广」召回，交叉编码器负责「慢而精」重排，二者互补构成现代检索主干。
