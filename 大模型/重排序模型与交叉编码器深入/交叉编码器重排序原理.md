# 交叉编码器重排序原理

> 对应 Devlin et al. 2018《BERT: Pre-training of Deep Bidirectional Transformers》与 huggingface/transformers。

## 一、背景与挑战
双塔检索器在召回阶段高效但交互不足，对语义细微差异不敏感。重排序阶段可用更强但更慢的交叉编码器对候选做精细打分。

## 二、核心原理
交叉编码器把查询与文档拼接为单一序列 [CLS] q [SEP] d [SEP]，经 Transformer 双向注意力后取 [CLS] 表征接分类头输出相关性分数。由于查询与文档 token 全程交互，能捕捉细粒度对齐。

## 三、形式化与数学基础
打分函数：
$s(q,d) = W^\top \text{BERT}([ \text{CLS}, q, \text{SEP}, d, \text{SEP} ])_{[\text{CLS}]}$
训练用成对或列表损失，例如 pairwise hinge：
$\mathcal{L} = \max(0, m - s(q,d^+) + s(q,d^-))$

## 四、代码实现
```python
from transformers import AutoModelForSequenceClassification, AutoTokenizer
tok = AutoTokenizer.from_pretrained("cross-encoder/ms-marco")
model = AutoModelForSequenceClassification.from_pretrained("cross-encoder/ms-marco")
def score(q, d):
    x = tok(q, d, truncation=True, return_tensors="pt")
    return model(**x).logits.squeeze(-1)
```

## 五、与其他技术对比
相比双塔，交叉编码器精度更高但无法离线建索引，只能对少量候选（如 Top-100）重排；因此是「召回 + 重排」两段式标准做法。

## 六、常见误区
误区一：用交叉编码器做全库检索，复杂度 O(N) 不可行。误区二：直接拿预训练 BERT 输出 [CLS] 当分数，未微调则不可靠。

## 七、与开源书/权威来源对应
- Devlin et al. 2018 提出 BERT 双向编码基础。
- huggingface/transformers 是交叉编码器主流实现库。
- Lewis et al. 2020 在 RAG 中强调检索质量决定上限。

## 九、演进与趋势
出现更轻量的蒸馏交叉编码器、以及用 LLM 做 listwise 重排（如 RankGPT），并把重排与生成联合优化。

## 十、小结
交叉编码器以计算换精度，是检索流水线中提升相关性的关键一环。
