# Softmax 与温度

> 对应 d2l-zh 第 3 章交叉熵与第 10 章注意力中的 softmax；Hinton et al., *Distilling the Knowledge in a Neural Network*, 2015。

## 一、背景与挑战

神经网络最后一层输出的通常是一串任意实数（logits，比如 [2.1, -0.5, 1.3]），它们既不是概率，也没有统一的尺度，直接拿来比较或采样都不方便。我们想要的是：一组非负、和为 1、能解释为“可能性”的数——这就是 softmax 的工作。但把 logits 变成概率时有一个自由参数：**温度 τ**。同一串 logits，温度不同，得到的分布可以是“几乎确定选最大”，也可以是“接近掷骰子”。生成式 API 里的 `temperature` 参数、知识蒸馏里的软标签、注意力的数值稳定，背后都是这同一个旋钮。理解它，就能明白为什么只调一个数字，模型的回答风格就会大变。

## 二、核心原理

带温度的 softmax 定义为：

```
p_i = exp(z_i / τ) / Σ_j exp(z_j / τ)
```

直觉可以这样建立。把每个 logit 想象成**几位候选人的支持率**：

- **τ = 1（常规）**：按原始支持率换算成百分比，正常计票。
- **τ < 1（低温）**：放大大差距、压缩小差距，强者愈强。当 τ→0 时，分布趋近 one-hot——全部票都投给最高分者，输出非常“确定”。
- **τ > 1（高温）**：压缩差距，2.1 和 1.3 的差别被抹平。当 τ→∞ 时，分布趋近均匀分布，人人平等，输出变得“发散、有随机性”。

生活里也有类似现象：看演唱会投票，若规则是“票数直接翻倍计”，第一名会碾压所有人；若规则是“每人发十张票随便撒”，差距就被抹平了。温度 τ 干的就是“调整计票倍率”这件事。

生成时的采样行为随之改变：低温下模型几乎总选最可能的词，文风保守稳定；高温下低概率词也有机会被抽中，文风跳跃甚至容易胡说。**温度不改变各候选的排名**（谁高谁低不变），只改变差距被放大还是被压缩。很多聊天模型 API 默认把 temperature 设在 0.7 左右，就是在“一本正经”和“天马行空”之间取平衡；若你要求模型输出严格的 JSON 或做数据抽取，通常应把它调到 0 附近，尽量减少随机性带来的格式错误。

## 三、数学形式

softmax 的核心性质是 $p_i>0$ 且 $\sum_i p_i=1$。从公式看，$p_i \propto e^{z_i/\tau}$，指数上除以 τ 等价于“先把分数的尺度缩小再做指数”，所以 τ 就是在控制分布的锐度。数值实现上要先减去最大值再取指数（`z - z.max()`），避免 `exp` 溢出，这利用了 softmax 的平移不变性：给所有 logits 同时加减一个常数，结果不变。温度还能和已有知识串起来：交叉熵训练时 τ=1，模型输出的就是它对各类别的自信程度；而注意力里除以 $\sqrt{d_k}$ 本质上相当于一次**缩小尺度的低温控制**，防止点积数值过大把 softmax 饱和成 one-hot（见「注意力机制总览」）。同一个数学动作，在训练、生成、蒸馏三个场景反复出现。

## 四、代码实现

```python
import torch
import torch.nn.functional as F

logits = torch.tensor([2.1, -0.5, 1.3])

for tau in [0.2, 1.0, 2.0]:
    # 先除温度再归一化；tau 越小分布越尖、越大越平
    probs = F.softmax(logits / tau, dim=-1)
    print(f"tau={tau}: {probs.round(decimals=3)}")
# tau=0.2 时接近 [0.97, 0.01, 0.02]；tau=2.0 时明显更平缓

# 生成采样：高温让低概率词更容易被抽中
next_token = torch.multinomial(probs, num_samples=1)
```

## 五、与其他技术对比

| 维度 | argmax 贪心 | 低温采样 | 高温采样 | 均匀随机 |
|------|------------|---------|---------|----------|
| 确定性 | 完全确定 | 较确定 | 较随机 | 完全随机 |
| 多样性 | 最低（易复读） | 低到中 | 高（易跑题） | 无意义随机 |
| 概率信息 | 直接丢弃 | 保留 | 保留 | 无 |
| 典型用途 | 分类评测、信息抽取 | 事实问答、代码 | 创意写作、头脑风暴 | 基线对照 |
| 对应 API | temperature≈0 | temperature 较小 | temperature 较大 | — |

还要注意：temperature 采样只改变“怎么从候选里选”，不改变“候选有哪些”。若想进一步限制候选集合，就要配合 top-k（只保留概率最高的 k 个词）或 top-p（按累计概率截断核子集）等策略。实践中常见组合是：先用 top-p 砍掉长尾，再用 temperature 在剩下的候选里调节随机程度。

## 六、常见误区

1. **温度就是学习率**：完全无关。学习率改的是梯度更新步长，温度只在 softmax 归一化这一步改变分布形状。
2. **温度会改变候选词的排名**：不会。它只压缩或放大量级差距，最大值仍对应最大概率。
3. **训练时也该把温度调高**：常规训练用 τ=1；高温主要出现在知识蒸馏（让学生看见软标签里的暗知识）和生成采样。
4. **温度越低一定越好**：过低接近贪心，容易陷入重复句式；创造性任务反而需要较高温度，要按任务调参。
5. **softmax 输出天然是校准好的置信度**：深度模型常常过度自信，需要在验证集上做温度校准，0.9 的概率才可能真的代表九成把握。
6. **调温度能修复幻觉**：温度只能改变随机程度，不能给模型补充事实知识；事实错误要靠更好的数据、检索增强或约束解码来解决。

## 八、面试题

1. **温度在知识蒸馏中起什么作用？**
   要点：高 τ 让软标签分布更平滑，暴露各类别之间的相对关系（“暗知识”），比硬 one-hot 传递更多信息；学生先用同样的 τ 对齐，再降回 1。
2. **τ→0 和 τ→∞ 时分布如何变化？**
   要点：τ→0 趋近 one-hot（更确定），τ→∞ 趋近均匀（更随机）；前者梯度容易消失，后者失去区分度。
3. **为什么说除以 $\sqrt{d_k}$ 本质是温度缩放？**
   要点：点积除以常数与 logits 除以温度形式相同，都是把分数尺度压小，避免 softmax 饱和、保持梯度流动。
4. **temperature 和 top-p 分别控制什么？**
   要点：temperature 改变整个分布的形状，top-p 直接截断长尾候选集合；两者常叠加使用。
5. **如何判断模型的置信度是否可信？**
   要点：看可靠性曲线与 ECE；若预测 0.9 的样本实际只对 0.7，就在验证集上学习一个温度做校准。

## 九、演进与趋势

softmax 从分类网络的标准件，逐步演化出多个分支：蒸馏让它成为师生之间传递知识的媒介；校准研究关注“模型说的 90% 是否真是 90%”；生成时代它与 top-k、top-p、min-p 等截断策略组合成解码工具箱。近年还有 Z-loss、logit 归一化等训练技巧用来约束 logits 尺度，以及针对超长词表的 softmax 计算优化。方向很一致：让“概率”这层皮既稳定又可控——训练端更稳，生成端更好调。

## 十、小结

softmax 把任意分数变成合法概率，温度 τ 是控制分布**尖锐程度**的旋钮：低温放大差距、趋向确定，高温抹平差距、趋向随机，而且不改变排名。它同时是 API 里 `temperature`、蒸馏软标签、注意力数值稳定这三件事背后的同一个数学对象。掌握“概率解释 + 温度两极 + 与学习率无关”这三点，相关面试题基本都能答到点上。
