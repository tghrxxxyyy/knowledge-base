# 多头注意力

> 对应 d2l-zh 第 10 章「多头注意力」、harvardnlp/annotated-transformer；以及本库「注意力数学基础/缩放点积注意力推导」；Vaswani et al., 2017。

## 一、背景与挑战

单个注意力头就像只用一只眼睛看世界：一次只能学出一种“相似度打分”方式，输出是各种关系混在一起的平均。但语言里的关系本来就是多样的：有的词在找主谓搭配，有的在找指代对象，有的在关注邻近的修饰词，还有的只看位置远近。只有一套 Q/K/V 投影时，模型被迫用同一个视角同时表达这些不同类型的依赖，容量明显不够。打个比方：一篇课文让一个人同时从语法、语义、指代三个角度做批注，结果往往是三个角度都做得半生不熟。多头注意力的解法很朴素——既然视角不同，就多配几组人马，每人负责一个角度，最后把各人的批注汇总成完整理解。

## 二、核心原理

多头注意力的做法是：把输入分别投影到 h 组（常见 8、12、16、32 组）低维子空间，每组独立做一次缩放点积注意力，得到一个“头”；再把 h 个头的输出按维度拼接起来，经过一次输出投影融合回原来的维度。

可以这样直觉地理解**每个头在看什么**：

- 有的头倾向于关注**相邻词**，像一个局部 n-gram 检测器；
- 有的头跨越长距离，专门匹配**指代关系**或**主谓一致**；
- 有的头权重分布很平，几乎在做**平均池化**，负责平滑上下文；
- 还有的头呈现明显的**对角线模式**，在做位置到位置的对应。

这些分工不是人为规定的，而是训练中自发涌现的。不同头的投影矩阵让它们各自学会不同的打分标准，就像一支乐队里鼓、贝斯、吉他各司其职，最后合奏出完整的一段音乐。值得注意的是，多头并不是把同一个任务重复做 h 遍：因为每个头有独立的 $W_i^Q, W_i^K, W_i^V$，它们从输入里提取的本来就是不同的关系模式，输出拼在一起后携带的信息比任何单头都丰富。

## 三、数学形式

$$\text{MultiHead}(Q,K,V)=\text{Concat}(\text{head}_1,\dots,\text{head}_h)\,W^O$$
$$\text{head}_i=\text{Attention}(QW_i^Q,\ KW_i^K,\ VW_i^V)$$

其中每个 $W_i^Q\in\mathbb{R}^{d_{model}\times d_k}$ 把输入投影到更小的维度，常取 $d_k=d_{model}/h$。也就是说：**总维度不变，但被切成 h 份，每份单独做注意力**。因为每头维度缩小为原来的 1/h，总计算量与单头全维度的注意力大致相当——多头带来的几乎是“免费”的表达力提升。最后的 $W^O$ 负责把拼接结果重新混合，让不同头的信息相互配合，而不是简单堆在一起。实际代码里还常看到每头内部再用 `view + transpose` 把 batch 和头维交换，目的是让同一头的向量在张量里连续排布，方便一次点积算完。

## 四、代码实现

```python
import torch.nn as nn

# PyTorch 内置多头注意力：embed_dim 必须能被 num_heads 整除
mha = nn.MultiheadAttention(embed_dim=512, num_heads=8, batch_first=True)
# 输出为注意力加权结果；attn_weights 形状是 (batch, 头数, 目标长, 源长)
out, attn_weights = mha(query=x, key=x, value=x)  # 自注意力：三者同源
```

## 五、与其他技术对比

| 维度 | 单头注意力 | 多头注意力 | 单头 + 多层堆叠 |
|------|-----------|-----------|-----------------|
| 视角数量 | 一种打分标准 | h 种并行标准 | 逐层递进但同层单一 |
| 关系建模 | 不同关系易混杂 | 各头分工更清晰 | 依赖深度间接实现 |
| 计算开销 | 基准 | 约等于基准（降维分摊） | 随层数线性增长 |
| 可解释性 | 一张权重图 | 每头一张，模式各异 | 中间层较难解读 |
| 常见配置 | 现已少见 | 8 / 12 / 16 / 32 头 | 与多头正交，通常同时使用 |

## 六、常见误区

1. **头数越多越好**：过多的头会造成冗余，收益递减，甚至因为每头维度太低而变差；近年常见做法是减少头数、增大单头维度。
2. **每个头都有明确的语义标签**：可视化确实能发现部分头专精局部或指代，但也有大量头功能重叠，不必强行一一对应解读。
3. **多头等于把维度放大 h 倍**：每头维度是被**切小**的，总参数量与单头全维版接近，好处来自视角并行，而不是参数堆叠。
4. **各头输出直接相加就行**：标准实现是先拼接再乘输出投影 $W^O$，这一步的跨头信息混合不可省略。
5. **多头能解决一切长程问题**：它仍受序列长度平方复杂度的约束，超长文本还需要稀疏或窗口化策略配合。

## 八、面试题

1. **多头注意力为什么有效？**
   要点：不同投影子空间让各头学到不同的相似度度量，可同时覆盖局部、长距、位置等多种依赖；拼接 + 输出投影再把信息融合。
2. **为什么每头维度常取 $d_{model}/h$？**
   要点：保持总计算量与单头相当，参数量不随头数膨胀，表达力却提升了。
3. **头数不能整除模型维度怎么办？**
   要点：主流框架会直接报错，需要调整头数或维度；工程上必须保证 embed_dim 能被 num_heads 整除。
4. **如何观察某个头学到的东西？**
   要点：可视化该头的注意力权重矩阵，看它是否局部化、对角化或趋于均匀；也可以做头剪枝实验，看删掉后性能是否下降。
5. **单头多层堆叠能否替代多头？**
   要点：部分功能可以由深度弥补，但同层内并行的多视角更省深度，实践中两者搭配效果最好。

## 九、演进与趋势

从最初的均匀多头出发，后来出现了多种变体：**分组查询注意力（GQA）** 让多个查询头共享 K/V，大幅节省推理时的 KV 缓存；**多查询注意力（MQA）** 更激进，所有头共用一套 K/V；**滑动窗口注意力** 只让部分头看全局，其余只看局部；还有一些工作做**头剪枝与合并**，发现训练完成后大量头可以删除而不掉点。总体趋势是：承认“不是每个头都需要看全局”，在保住多视角收益的同时，压低显存与计算成本。

## 十、小结

多头注意力 = **多个小注意力并行 + 拼接融合**。它让模型在每一层同时用多种视角观察序列，每头像一位各管一摊的专家，最后由输出投影汇总意见。记住“切小维度换多视角、参数量基本不变”这个关键直觉，再理解 GQA 等省显存变体就水到渠成了。
