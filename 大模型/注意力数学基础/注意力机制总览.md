# 注意力机制总览

> 对应 d2l-zh 第 10 章「注意力机制」与 harvardnlp/annotated-transformer；Vaswani et al., *Attention Is All You Need*, 2017。

## 一、背景与挑战

早期的序列建模主要靠 RNN：信息要一个词一个词地往后传，像接力赛跑，前面的人必须把内容背下来再交给后面的人。这带来两个大问题。第一是**长程依赖难**，句子开头的主语隔了几十个词之后，信息在一次次传递中不断被稀释、遗忘，模型很难知道“它”到底指谁。第二是**难以并行**，第 t 步必须等第 t-1 步算完，训练时无法像卷积那样把整段同时算完，GPU 利用率很低。注意力机制的思路很直接：既然要建模词与词的关系，何必绕道接力？让每个位置直接“看”一遍全句，挑出相关的部分重点处理。这就像读书时遇到不认识的概念，不必从第一页重读，而是直接翻到目录里最相关的那一节。这个想法其实早有雏形：早期的翻译模型会在生成每个词时回头“瞄一眼”原文，这就是 Bahdanau 注意力。Transformer 把这种“按需聚焦”推到极致，用注意力完全替代了循环结构，从而开启了大模型时代。对入门者来说，只需要记住一句话：注意力解决的是**信息怎么在长序列里高效流动**的问题。

## 二、核心原理

注意力的核心可以用一个生活例子讲清：**去图书馆找资料**。

- **查询（Query，Q）**：你带着的问题，比如“我想找关于 Transformer 的书”。
- **键（Key，K）**：每本书书脊上的标签，专门用来被检索、比对。
- **值（Value，V）**：书的正文内容，真正被你取走使用的东西。

流程是：拿你的问题 Q 和每一本书的标签 K 逐一对比（算相似度），相似度高的书获得更高的权重；然后按这些权重把各本书的内容 V 加权汇总，得到最终答案。关键点在于：**检索时看的是标签，取用时拿的是内容**，键和值分工不同。由于所有权重都非负且和为 1，这相当于对全句做一次“软性查表”——不像查字典那样只取唯一一条，而是按相关程度把所有位置的内容都掺一点进来，重点位置占比大，边缘位置占比小。这就是“内容寻址”：模型不再单纯依赖位置顺序，而是按当前需要的内容去记忆里取东西。

## 三、数学形式

最常用的**缩放点积注意力**只有一行核心公式：

$$\text{Attention}(Q,K,V)=\text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

逐块解释它的含义：

1. $QK^\top$：每个查询和所有键做点积，得到“两两相似度”矩阵，形状是 序列长度 × 序列长度。
2. $\sqrt{d_k}$：向量维度越大，点积数值天然越大，除以它把数值拉回稳定范围，防止 softmax 过于极端（详见「Softmax与温度」）。
3. softmax：把一堆任意实数的相似度变成一组和为 1 的权重。
4. 乘 $V$：按权重对值向量加权求和，得到每个位置的输出。

可以把整个过程概括为一句话：**先打分，再按分加权平均**。再补一个从 seq2seq 到 Transformer 的过渡直觉：传统 seq2seq 会把整句话压缩成一个固定长度的向量，信息塞不下就丢；注意力出现后，解码器每生成一个词都可以重新查阅原文的全部位置，解码不再依赖那一根“瓶颈向量”。等研究者发现连循环本身也可以省掉、全用注意力堆起来，Transformer 就诞生了。

## 四、代码实现

```python
import torch
import torch.nn.functional as F

def attention(Q, K, V):
    d_k = Q.size(-1)
    # 1. 相似度打分，并用维度缩放保持数值稳定
    scores = Q @ K.transpose(-2, -1) / d_k ** 0.5
    # 2. 归一化成权重，每行和为 1
    weights = F.softmax(scores, dim=-1)
    # 3. 对值加权求和，得到输出
    return weights @ V
```

## 五、与其他技术对比

| 维度 | RNN / LSTM | 卷积 (CNN) | 注意力 / Transformer |
|------|-----------|-----------|----------------------|
| 信息路径 | 逐步传递，长程衰减 | 只看局部窗口 | 任意两位置一步直达 |
| 并行性 | 必须串行 | 可整段并行 | 可整段并行 |
| 长距离依赖 | 需精心设计门控 | 需堆叠层扩大感受野 | 天然直达 |
| 计算复杂度 | O(n) 但难并行 | O(n·k) | O(n²)，序列长时偏高 |
| 位置信息 | 天然有序 | 天然有序 | 需额外注入位置编码 |

## 六、常见误区

1. **注意力权重就是模型的“解释”**：权重只反映加权比例，高权重不等于因果解释，可视化结果仅供参考。
2. **注意力能自动记住全部历史**：它只是对当前输入的加权聚合，并不自带长期存储，真正的记忆要靠外部结构或缓存。
3. **注意力天然懂语序**：纯注意力对输入是置换不变的，必须配合位置编码才能区分词的先后。
4. **序列越长越该用注意力**：复杂度是序列长度的平方，超长文本往往要借助稀疏注意力或分块策略。
5. **Q、K、V 一定来自不同内容**：自注意力里三者都是同一序列投影而来，只有编码器-解码器的交叉注意力才分别来自不同序列。
6. **注意力可以取代一切结构**：它擅长建模两两关系，但对严格顺序、局部卷积式特征等并非最优，实践中常与前馈层、卷积或状态空间模块搭配使用。

## 八、面试题

1. **注意力相比 RNN 的核心优势是什么？**
   要点：任意位置直接交互、没有长程衰减、整段可并行训练；代价是随序列长度平方增长的显存开销。
2. **为什么要除以 $\sqrt{d_k}$？**
   要点：高维点积的数值方差随维度增大，过大数值会把 softmax 推向 one-hot 导致梯度消失；缩放后训练更稳定。
3. **自注意力和交叉注意力有什么区别？**
   要点：自注意力的 Q/K/V 同源（同一序列），交叉注意力的 Q 来自解码器、K/V 来自编码器输出。
4. **如何理解“注意力是软查表”？**
   要点：像字典查询，但不取唯一值，而是按相似度对所有值加权平均，权重非负且和为 1。

## 九、演进与趋势

大致路线：2014 年 Bahdanau 注意力在 seq2seq 中首次引入“翻译时回看原文”；2017 年缩放点积注意力 + 多头 + 位置编码构成 Transformer；随后出现更省算力的稀疏注意力、线性注意力，以及 FlashAttention 这类从显存读写层面做优化的工程方案。近几年还兴起了状态空间模型（如 Mamba）等与注意力互补的结构，以及混合专家（MoE）路线。总体趋势是保留“内容寻址”的核心思想，同时压低平方级开销，让超长上下文变得可行。

## 十、小结

注意力的本质是**按需聚焦的加权聚合**：用查询去和键比相似度，再按权重汇总值。它让序列建模从“接力传递”变成“直接查阅”，是 Transformer 的基石。理解了 Q/K/V 的检索直觉、缩放的作用和平方复杂度的代价，后面学习多头注意力、温度与采样都会顺理成章。
