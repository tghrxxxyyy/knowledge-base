# 负载均衡

> 对应 Shazeer et al., *Sparsely-Gated MoE*, 2017 与 Fedus et al., *Switch Transformers*, 2022，无辅助损失路由见 Rajbhandari et al., *DeepSpeed-MoE*, 2022。

## 一、背景与挑战

MoE 的门控网络在训练初期很容易「塌缩」：所有 token 都涌向少数几个专家，其余专家几乎不被激活。这带来两大问题：一是大量专家参数闲置、容量浪费；二是被偏爱的专家成为计算与显存瓶颈，拖慢整体吞吐。

如何让专家被均匀利用，是 MoE 训练稳定性的核心难题，也是 MoE 能否真正「用满参数」的关键。除均衡外，还需警惕「伪均衡」——表面均匀但专家无语义分工。

## 二、核心原理

主流解法是加入**辅助负载均衡损失（auxiliary load-balancing loss）**，它鼓励每个专家获得相近的路由概率均值。设 $f_i$ 为分配到专家 $i$ 的 token 占比（实际负载），$P_i$ 为门控对专家 $i$ 的概率均值（路由倾向），辅助损失定义为：

$$ L_{aux} = \alpha \cdot N \cdot \sum_{i=1}^{E} f_i \cdot P_i $$

当负载与概率同时偏高时损失增大，从而把「概率 mass」推向冷门专家。$\alpha$ 是平衡系数，过大伤害主任务、过小则失衡。

除辅助损失外，还有 **expert-choice**（让专家选 token，天然均衡）、**Sinkhorn 路由**（用最优传输强制均匀）、以及 **无辅助损失** 的 DeepSpeed-MoE 方案。实践中还常用「专家重要性指数」监控，发现塌缩早止损。

## 三、形式化与数学基础

令 $E$ 为专家数，$T$ 为批次 token 数。对每个专家 $i$：

$$ f_i = \frac{1}{T}\sum_{x} \mathbb{1}[i \in topk(G(x))] $$

$$ P_i = \frac{1}{T}\sum_{x} G_i(x) $$

辅助损失：

$$ L_{aux} = \alpha \cdot E \cdot \sum_{i=1}^{E} f_i \cdot P_i $$

该损失在 $f_i = P_i = 1/E$（完全均匀）时最小。注意 $f_i$ 与 $P_i$ 通过门控参数耦合，需用无偏估计与梯度乘子避免主任务被压垮。

expert-choice 下直接令 $f_i = B/T$ 为常数，无需此损失，从结构上消除失衡。

## 四、代码实现

```python
import torch

# 计算辅助负载均衡损失
def load_balancing_loss(gate_probs, indices, num_experts, alpha=0.01):
    T = gate_probs.shape[0]
    mask = torch.zeros_like(gate_probs)
    mask.scatter_(1, indices, 1.0)
    f = mask.sum(0) / T                 # [E] 实际负载
    P = gate_probs.mean(0)              # [E] 路由概率均值
    aux = alpha * num_experts * (f * P).sum()
    return aux

# 总损失（用 (1-alpha) 缩放主任务，避免被压垮）
loss = (1.0 - alpha) * task_loss + load_balancing_loss(probs, idx, E, alpha)
```

## 五、与其他技术对比

| 方法 | 是否需要辅助损失 | 均衡质量 | 实现难度 |
| --- | --- | --- | --- |
| 辅助损失（Switch） | 是 | 中（需调 alpha） | 低 |
| expert-choice | 否（天然均衡） | 高 | 中 |
| Sinkhorn 路由 | 否（最优传输） | 高 | 高 |
| 无辅助损失（DeepSpeed） | 否 | 中高 | 中 |

辅助损失最易落地但需调参；无辅助方案更优雅，适合大规模稳定训练。

## 六、常见误区

- 认为均衡损失越大越好：过大会压制主任务损失，使模型学不到东西；$\alpha$ 需精调（常 0.01 量级）。
- 认为无失衡就无需关注：训练后期仍可能因数据分布漂移出现局部失衡。
- 把路由概率均值当真实负载：未考虑容量裁剪与 top-k 截断的影响。
- 认为均衡等于高质量：专家均匀使用不代表分工合理，仍需主任务信号引导专精度。

## 八、面试题

- MoE 负载不均衡的后果？答：专家闲置浪费参数、热门专家成瓶颈、训练不稳定甚至崩溃。
- 辅助损失怎么工作？答：惩罚「高概率且高负载」的专家，把路由 mass 推向冷门专家。
- 无辅助损失方案如何均衡？答：用 expert-choice 或 Sinkhorn 在结构上强制均匀，省去 alpha 调参。
- 为何用 (1-alpha) 缩放主损失？答：补偿辅助损失对主任务梯度的压制，保持学习效果。

## 九、演进与趋势

辅助损失 → 无辅助损失（expert-choice / Sinkhorn / DeepSpeed-MoE）→ 可微、端到端联合优化的均衡机制，目标是在零调参下保持均衡且不影响主任务。

结合负载感知的动态调整成为新方向：根据实时专家热度重分配容量，使均衡与吞吐协同优化。

## 十、小结

负载均衡让每个专家各司其职，是 MoE 训练能否真正用满参数的关键；辅助损失是最常用手段，但无辅助方案正成为更优雅的替代，且需配合主任务缩放避免质量损失。
