# 门控与路由

> 对应 Shazeer et al., *Sparsely-Gated MoE*, 2017 与 Fedus et al., *Switch Transformers*, 2022，细粒度路由见 DeepSeek-AI, *DeepSeekMoE*, 2024。

## 一、背景与挑战

路由（routing）决定每个 token 被送往哪个专家，是 MoE 的灵魂。一个糟糕的路由会让少数专家过载、其余闲置（负载失衡），或让 token 在专家间抖动导致训练不稳定。

好的路由需要在「专家专精度」「负载均衡」「计算效率」之间折中，并能在分布式环境下低成本通信。

路由策略一旦确定，还直接决定专家容量、并行方式与丢弃率，因此是整个 MoE 系统的中枢。实践中路由 bug（如全部 token 涌向专家 0）是训练初期最常见的失败模式。

## 二、核心原理

门控（gating）网络通常是一个轻量线性投影，把 token 隐状态映射到各专家的得分，再经 softmax 归一化得到路由概率，取 top-k 作为选中专家：

$$ G(x) = \text{Softmax}(W_g \cdot x) $$

$$ \text{selected} = topk(G(x), k) $$

为提升训练稳定性，Switch 引入 **Noisy Top-k**：在门控 logits 上加可学习的均匀噪声，鼓励探索；同时用**专家容量**限制单专家接收的 token 上限，防止过载。

近年 **细粒度路由**（DeepSeekMoE）把专家拆得更小、路由到更多更细的单元，提升专家利用率与专精度。还有 **expert-choice**（专家选 token）反转角色，让专家从批次中挑选自己要处理的 token，天然均衡且零丢弃。

## 三、形式化与数学基础

对 token $x$，门控输出概率分布 $p_i = G_i(x)$，满足 $\sum_i p_i = 1$。top-k 路由只保留最大 $k$ 个，归一化后作为加权系数：

$$ w_i = \frac{p_i}{\sum_{j \in topk} p_j}, \quad i \in topk $$

Noisy Top-k 在训练时对 logit 加噪：

$$ \tilde h_i = h_i + \text{Softplus}(N_i) \cdot \epsilon_i, \quad \epsilon_i \sim \mathcal{U}(0,1) $$

其中 $N_i$ 为可学习噪声幅度。细粒度路由中专家数 $E$ 增大、激活数 $k$ 相应增多，但 $k/E$ 比例保持较小。

expert-choice 下，每个专家从批次选固定 $B$ 个 token，自动满足容量均衡，无需容量裁剪。

## 四、代码实现

```python
import torch

# 门控网络：线性投影 + softmax + top-k
class TopKGate(torch.nn.Module):
    def __init__(self, dim, num_experts, k=2):
        super().__init__()
        self.w = torch.nn.Linear(dim, num_experts, bias=False)
        self.k = k

    def forward(self, x):
        logits = self.w(x)                       # [tokens, E]
        if self.training:
            noise = torch.rand_like(logits)      # Noisy Top-k
            logits = logits + torch.nn.functional.softplus(self.w.weight.sum(0)) * noise
        probs = torch.softmax(logits, dim=-1)
        topk = probs.topk(self.k, dim=-1)        # 取 top-k 专家
        return topk.indices, topk.values

# expert-choice 示意：每个专家挑 batch 中分数最高的 B 个 token
def expert_choice(gate_probs, tokens_per_expert):
    selected = [torch.topk(gate_probs[:, e], tokens_per_expert).indices
                for e in range(gate_probs.shape[1])]
    return selected
```

## 五、与其他技术对比

| 路由方式 | 均衡性 | 专精度 | 复杂度 |
| --- | --- | --- | --- |
| 粗粒度 top-1 | 需辅助损失 | 中 | 低 |
| 粗粒度 top-2 | 较好 | 中 | 低 |
| 细粒度多专家 | 好（配合共享专家） | 高 | 中 |
| expert-choice | 天然均衡 | 高 | 中高 |

可见：均衡性随路由机制升级而提升，但实现复杂度同步上升，需按团队工程能力取舍。

## 六、常见误区

- 认为路由越复杂越好：过度复杂的路由增加通信与实现成本，且可能引入不稳定性；工程上常先用简单 top-k + 辅助损失。
- 认为 softmax 概率可直接当专家重要性：概率分布受容量裁剪与噪声影响，不能等同真实负载。
- 忽略容量限制：无容量时单专家可能瞬时过载，破坏训练稳定性。
- 认为 top-k 权重可微到专家参数：门控离散选择本身不可微，靠软加权近似，需专家函数可微支撑梯度回流。

## 八、面试题

- 为何需要专家容量限制？答：防止单专家被过多 token 打满导致显存溢出与训练不稳定。
- Noisy Top-k 作用？答：训练期加噪鼓励探索，缓解路由过早固化。
- 细粒度路由优势？答：更细的路由单元提升专家专精度与利用率。
- expert-choice 为何零丢弃？答：专家从批次主动挑选固定量 token，天然满足容量均衡。

## 九、演进与趋势

top-1 → top-2 → 细粒度多专家 + 共享专家 → expert-choice（专家选 token，天然均衡且零丢弃）。可微分路由与端到端联合优化也是前沿，目标是在不牺牲主任务前提下最大化专家分工。

未来路由可能结合可学习容量、跨层路由一致性（同一 token 跨层走相近专家以降低通信），进一步压低训练与推理成本。

## 十、小结

门控与路由决定 MoE 的「分工效率」，从简单 top-k 到细粒度与专家选择，核心目标始终是：专精度高、负载均衡、通信可控，三者缺一不可。
