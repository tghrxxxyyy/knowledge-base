# 动态计算与 MoE 路由

> 对应 Mixture-of-Experts 动态路由；与 动态层数路由深入 衔接。

## 一、背景与挑战

大模型需在不增推理算力下扩参，动态选专家即动态计算。

## 二、核心原理

每 token 经门控选 top-k 专家，仅激活部分参数；计算量随专家数固定但参数量大而省激活。

## 三、数学形式

$y=\sum_{e\in \text{topk}(g(x))} g_e(x) E_e(x)$；激活参 $\ll$ 总参。

## 四、代码实现

```python
weights, idx = gate(x).topk(k)
y = sum(w * experts[i](x) for w,i in zip(weights, idx))
```

## 五、与其他对比

- 与 早退推理深入 都减激活算力，机制不同。
- 与 推理成本深入 直接关联。

## 六、常见误区

- 负载不均致部分专家过忙（需辅助损失）。
- 路由塌缩。

## 八、面试题

- MoE 为何是动态计算？答：门控每 token 选专家，仅激活部分参数，算力随路由变。

## 九、演进

稠密 → top-k MoE → 细粒度路由。

## 十、小结

MoE 路由是参数级动态计算，扩参不增激活成本。
