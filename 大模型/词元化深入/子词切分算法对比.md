# 子词切分算法对比

> 对应 llm-course「Tokenizers」与 d2l-zh 自然语言处理章节。

## 一、背景与挑战

词表过大(纯词)或 OOV(字符级)都不理想。子词在二者间平衡：高频词保留、低频词拆子词，使词表可控且能表达任何词。

## 二、核心原理

- **BPE**：自底向上合并高频相邻对(见「预训练/词元化BPE」)。
- **WordPiece**：按 `score = count(a)count(b)/count(ab)` 增益合并。
- **Unigram**：从全词出发，用语言模型概率删除低损子词。
- **SentencePiece**：空白视为 `_`，免预分词，多语友好。

## 三、数学形式

WordPiece 合并增益：

```
gain = count(a) * count(b) / count(ab)
```

Unigram 删除损失(基于 unigram LM 概率)：

```
L(x) = -log P(x) = - Σ_i log P(sub_i)
```

## 四、代码实现

```python
from transformers import AutoTokenizer
tok = AutoTokenizer.from_pretrained("bert-base-chinese")
print(tok.tokenize("深度学习让NLP更简单"))
```

## 五、关键要点

| 算法 | 合并/删除依据 | 代表 |
|------|---------------|------|
| BPE | 频率 | GPT/LLaMA |
| WordPiece | 似然增益 | BERT |
| Unigram | 概率损失 | mT5 |
| SentencePiece | 任意 | 多语 |

## 六、与其他对比

- BPE 实现简单、速度快；Unigram 理论更优雅但慢。
- SentencePiece 统一处理空格，适合多语。

## 七、常见误区

- 用 A 模型 tokenizer 解码 B 模型输出，必然乱码。
- 中文 token 数常被低估(一个汉字常占 1-2 token)。

## 十、演进

从 BPE → Unigram → SentencePiece → 字节级 BPE(GPT-2 用 bytes 避免 OOV)。

## 十一、小结

子词算法是 LLM 输入管线的基石，选型和训练一致性决定下游质量。
