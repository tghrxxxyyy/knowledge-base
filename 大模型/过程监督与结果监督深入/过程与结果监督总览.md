# 过程监督与结果监督总览

> 对应 Lightman et al., *Let's Verify Step by Step*, 2023（ORM/PRM）；与 奖励模型深入 衔接。

## 一、背景与挑战

数学/推理任务仅看最终答案（ORM）难纠过程错误；过程监督（PRM）标每步 Correctness。

## 二、核心原理

ORM：对完整解答打分。PRM：对推理每步打分，训练时反馈更密集，引导正确中间步骤。

## 三、数学形式

PRM 目标：最大化正确步骤概率乘积或逐步二分类；推理用 beam 选高 PRM 路径。

## 四、代码实现

```python
step_scores = [prm(x, steps[:i]) for i in range(1, len(steps)+1)]
path_score = sum(step_scores)
```

## 五、与其他对比

- 与 奖励模型深入（ORM/PRM 是其形态）共享。
- 与 直接偏好优化深入（多在结果级）对照。

## 六、常见误区

- PRM 标注贵且步定义难。
- 误以为 PRM 总优于 ORM（数据足时 ORM 也强）。

## 八、面试题

- 过程监督为何利于推理？答：每步反馈更早纠偏，避免错误累积。

## 九、演进

ORM → PRM → 自举 PRM（模型自标步骤）。

## 十、小结

过程监督以细粒度反馈提升推理可靠性，代价是标注成本。
