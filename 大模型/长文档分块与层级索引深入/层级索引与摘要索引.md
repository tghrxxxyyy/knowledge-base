# 层级索引与摘要索引

> 对应 run-llama/llama_index 的 SummaryIndex 与层级检索思路及 Lewis et al. 2020。

## 一、背景与挑战
平铺块检索在长文档中难以把握全局，且大量小块增加噪声。层级索引引入「块-摘要-文档」多层结构，先检索摘要定位，再下钻细节。

## 二、核心原理
底层为细粒度文本块；上层为每个块/组生成摘要，对摘要建索引。查询先匹配摘要层召回候选组，再在组内精检细块，形成「先粗后细」的两段检索。

## 三、形式化与数学基础
设摘要层 $S=\{s_j\}$，每块映射所属摘要 $g(c_i)=j$。检索：
$j^* = \arg\max_j \text{sim}(q, s_j),\quad c^* = \arg\max_{c: g(c)=j^*} \text{sim}(q, c)$
该分层把候选空间从 $|C|$ 降到 $|S|$ 再局部细化。

## 四、代码实现
```python
def hierarchical_search(q, summaries, blocks, llm, k=3):
    top_groups = rank(summaries, q, k)
    hits = []
    for g in top_groups:
        hits += rank(blocks[g], q, k)
    return hits
```

## 五、与其他技术对比
相比纯块检索，层级索引兼顾全局定位与细节，减少无关块干扰；成本在需预生成摘要，但检索更准更省 token。

## 六、常见误区
误区一：摘要层可完全替代细块，实则最终仍需细块作答。误区二：摘要与块失配，导致下钻落空。

## 七、与开源书/权威来源对应
- run-llama/llama_index 的 SummaryIndex 提供摘要层。
- Lewis et al. 2020 检索增强基础。
- microsoft/graphrag 社区摘要是层级思想的延伸。

## 十、小结
层级索引用「摘要-细节」双层把全局与局部统一，是长文档 RAG 的进阶结构。
