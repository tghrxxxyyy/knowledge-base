# 递归字符分块

> 对应 run-llama/llama_index 的 RecursiveCharacterTextSplitter 与 datawhalechina/llm-universe 实践。

## 一、背景与挑战
无结构长文本需要稳健、可复现的切分。递归字符分块按一组分隔符优先级（换行、句点、空格）逐级切，尽量在语义自然处断开。

## 二、核心原理
先按最长分隔符（如段落 `\n\n`）切到接近块大小，若仍超长则按次级分隔符（如 `\n`、句号）再切，直至满足长度。保持块间可选重叠以维持连贯。

## 三、形式化与数学基础
给定分隔符序列 $\Sigma = [\sigma_1,\dots,\sigma_m]$（长度递减），递归函数：
$\text{split}(T, i) = \begin{cases} [T] & |T| \le L \\ \text{merge}(\text{split}(T_{\sigma_i}, i+1)) & \text{否则} \end{cases}$
其中 $T_{\sigma_i}$ 为按 $\sigma_i$ 切分的结果，merge 在长度允许时合并相邻段。

## 四、代码实现
```python
def recursive_split(text, seps=["\n\n","\n",". "," "], size=512, overlap=50):
    if len(text) <= size:
        return [text]
    sep = seps[0]
    parts = text.split(sep)
    return [p for part in parts for p in recursive_split(part, seps[1:], size, overlap)]
```

## 五、与其他技术对比
相比固定分块更尊重文本层级，实现简单、零模型依赖；相比语义分块精度略低但更稳更快，是默认首选。

## 六、常见误区
误区一：分隔符顺序随意，应从粗到细。误区二：重叠过大造成重复召回与成本上升。
