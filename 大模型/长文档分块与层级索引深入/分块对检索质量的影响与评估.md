# 分块对检索质量的影响与评估

> 对应 run-llama/llama_index 评估与 Es et al. 2023《RAGAS》及 Gao et al. 2021 lm-eval-harness。

## 一、背景与挑战
分块策略是 RAG 质量的隐藏杠杆，但常被忽视。需量化不同块大小/边界对检索与端到端的影响，避免凭直觉调参。

## 二、核心原理
在固定检索器与生成器下，扫块大小、重叠、策略，观察 NDCG@k（检索）与 RAGAS 维度（生成）。最优块常在「含完整事实单元」与「不过长稀释」的交点。

## 三、形式化与数学基础
定义块质量对下游的弹性：
$\epsilon(L) = \frac{\partial \text{RAGAS}(L)}{\partial \log L}$
通过网格搜索找使 RAGAS 与 NDCG 联合最大的 $(L^*, \text{overlap}^*)$。

## 四、代码实现
```python
def tune_chunk(sizes, docs, eval_fn):
    best, cfg = -1, None
    for L in sizes:
        score = eval_fn(chunk_docs(docs, L))
        if score > best:
            best, cfg = score, L
    return cfg
```

## 五、与其他技术对比
相比只调检索器/重排，调块往往收益更高且零额外推理成本；但需稳定评测集，否则结论不可复现。

## 六、常见误区
误区一：块大小对所有文档通用，实则不同类型差异大。误区二：只在检索指标上调，忽略对生成的连锁影响。
