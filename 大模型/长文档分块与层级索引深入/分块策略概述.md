# 分块策略概述

> 对应 run-llama/llama_index 检索索引与 Lewis et al. 2020《RAG》检索基础。

## 一、背景与挑战
长文档直接喂入检索会因长度超过上下文且语义稀释而效果差。分块（chunking）把文档切成可检索单元，块大小与边界直接决定召回质量。

## 二、核心原理
主流策略：固定长度（按 token/字符）、递归字符（按段落-句子逐级切）、语义分块（按语义边界）、文档结构感知（按标题/章节）。目标是在「上下文完整」与「检索精准」间平衡。

## 三、形式化与数学基础
设文档 D 切为块集合 $\{c_i\}$，期望最大化检索信噪比：
$\max_{\{c_i\}} \frac{1}{|Q|}\sum_{q} \text{Rel}(q, \text{top}_k(\{c_i\}))$
约束为 $|c_i| \le L_{\max}$，L_max 由嵌入模型与上下文窗口决定。

## 四、代码实现
```python
def fixed_chunk(text, size=512, overlap=64):
    toks = text.split()
    return [" ".join(toks[i:i+size]) for i in range(0, len(toks), size-overlap)]
```

## 五、与其他技术对比
固定分块简单但易切断语义；递归/语义分块更自然但成本高；结构感知最准但依赖文档格式。实际常组合使用。

## 六、常见误区
误区一：块越大越好，过大稀释注意力且超出嵌入最优长度。误区二：忽略重叠，导致边界信息割裂。

## 九、演进与趋势
从静态分块走向上下文感知（用 LLM 判断边界）与按查询动态分块，并与层级索引结合。

## 十、小结
分块是 RAG 工程的第一道工序，合理的块边界是高质量检索的前提。
