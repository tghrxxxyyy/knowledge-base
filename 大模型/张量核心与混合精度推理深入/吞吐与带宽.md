# 吞吐、带宽与精度权衡

> 对应 Roofline 视角分析推理瓶颈（算力 vs 带宽）。

## 一、背景与挑战

选精度不仅要看算力，还要看是否受显存带宽限制（decode 常属带宽界）。

## 二、核心原理

decode 每步算量少、需读全部权重，属 memory-bound；低精度减半字节直接近似翻倍带宽有效吞吐；prefill 算力界，TC 低精度提算力。

## 三、数学形式

带宽界可达吞吐 $\approx \frac{\text{bw}}{\text{param\_bytes}}$ token/s；param_bytes 随精度减半而减半。

## 四、代码实现

```python
eff_tok = bw / (n_params * bytes_per_param)
```

## 五、与其他对比

- 与 权重内存分页与卸载深入：带宽界时卸载增延迟。
- 与 张量核心与混合精度推理深入 总览：精度影响字节数。

## 六、常见误区

- 以为更低精度总更快（算力界才显著，带宽界受限于读）。
- 忽视激活重算/KV 带宽占比。

## 八、面试题

- 为何 decode 常带宽界？答：每步仅算一个新 token 却要读全权重，读 outweigh 算。

## 九、演进

FP32 → BF16 → INT8/FP8 降字节。

## 十、小结

精度选择要按 Roofline 瓶颈：decode 重带宽、prefill 重算力。
