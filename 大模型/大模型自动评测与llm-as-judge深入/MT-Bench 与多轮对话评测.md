# MT-Bench 与多轮对话评测

> 对应 Zheng et al. 2023《Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena》。

## 一、背景与挑战
单轮问答基准（如 MMLU）能测知识问答，却测不出真实助手最关键的能力：在多轮上下文中保持指代、状态与任务目标的一致性。用户很少只问一句，更多是「先让它写，再让它改，再追问细节」，模型要能在上下文累积中不跑偏、不遗忘、不自相矛盾。

MT-Bench 正是为填补这一空白而提出的多轮对话基准。它把「对话质量」这一原本依赖人主观判断的对象，变成可由强模型裁判按统一提示批量打分的结构化任务，从而使多轮能力也进入可复现的自动评测视野。

难点在于：多轮评测引入上下文依赖，第一轮的回答质量会影响后续轮次的上下文，评分不再是同分布独立样本；同时裁判本身的质量直接决定结论可信度。

## 二、核心原理
MT-Bench 的做法是构造一组高质量的多轮问题（每个样本包含若干连续轮次），覆盖写作、角色扮演、推理、数学、编程、知识抽取等类别。评测时，模型依次完成每一轮，裁判模型在每一轮结束后，依据该轮的问题与该轮的回答（必要时结合历史上下文）给出 1-10 分的评分。

关键设计包括：问题集固定且公开，保证跨模型可比；裁判提示固定，保证评分口径一致；按类别汇总，便于定位模型在不同能力上的强弱。为了抑制位置与长度偏差，MT-Bench 还配套设计了成对比较（pairwise）通道，作为打分制的交叉验证。

## 三、形式化与数学基础
设一个多轮样本包含 $T$ 轮，第 $t$ 轮裁判给出的分数为 $s_t$，则该样本的得分为各轮分数的均值：

$$ S = \frac{1}{T}\sum_{t=1}^{T} s_t $$

数据集层面的总分是各样本得分的平均：

$$ \bar{S} = \frac{1}{M}\sum_{j=1}^{M} S_j = \frac{1}{M}\sum_{j=1}^{M}\frac{1}{T_j}\sum_{t=1}^{T_j} s_{j,t} $$

若按类别汇总，可对同一类别内样本取均值。需要强调的是，简单取均值隐含「各轮等权」假设；若首轮与续轮难度不同，是否加权、如何加权应以官方评测脚本与说明为准，不宜自行发明权重。

## 四、代码实现
```python
# 计算单个 MT-Bench 样本的多轮均值分
def mt_bench_score(turn_scores):
    # turn_scores: 每轮裁判打分组成的列表
    if not turn_scores:
        raise ValueError("empty turn scores")
    return sum(turn_scores) / len(turn_scores)

# 汇总整个数据集，并按类别分组统计
def aggregate(records):
    by_cat = {}
    for r in records:
        by_cat.setdefault(r["category"], []).append(mt_bench_score(r["turn_scores"]))
    return {c: sum(v) / len(v) for c, v in by_cat.items()}
```

## 五、与其他技术对比
| 维度 | MT-Bench | MMLU 等静态基准 | Chatbot Arena（人类投票） |
| --- | --- | --- | --- |
| 交互形态 | 多轮对话 | 单轮选择题 | 多轮对话 |
| 评分来源 | 模型裁判 | 标准答案 | 真实人类偏好 |
| 可复现性 | 高 | 高 | 中（样本持续变化） |
| 贴近真实使用 | 较贴近 | 一般 | 最贴近 |
| 主要风险 | 裁判偏差 | 与使用场景脱节 | 成本高、难自动化 |

MT-Bench 在「贴近真实对话」与「自动可复现」之间取折中：比静态题更接近助手使用场景，比人类竞技场更廉价可重复，代价是引入裁判质量这一新变量。

## 六、常见误区
误区一：把多轮分数简单相加而不取均值，导致轮数多的样本权重被放大。误区二：忽略首轮与续轮难度差异，直接跨模型比较而不看类别细分。误区三：评测时把历史上下文在不同模型间串用，造成上下文泄漏、答案可比性丧失。误区四：只看总分不看方差，掩盖了模型在特定类别上的严重短板。误区五：把裁判结论当作绝对真理而不做人工抽检。

## 九、演进与趋势
多轮评测正从纯文本对话扩展到工具调用轮次（agent 轨迹）、长上下文一致性以及多模态交互，评测对象由「回答质量」延伸到「任务完成度」。与此同时，评测集面临污染（数据泄漏）风险，推动动态生成与留出集设计。行业也在探索把 rubric 维度化，让分数不仅反映好坏，还能解释「差在哪一维度」。

使用 MT-Bench 时，几个工程细节决定结论是否可信：

- 上下文隔离：每个模型、每个样本必须从干净上下文开始，避免跨次污染。
- 提示固定：裁判提示与系统提示需版本化，改动后应重跑基线。
- 采样一致：被评模型的温度、top-p 与最大长度需统一，否则比较不公。
- 裁判版本：裁判模型升级会系统性改变分数，必须重建可比基线。
- 人工抽检：按类别抽样复核裁判结论，尤其关注低自洽率样本。

报告结果时，建议同时给出：

- 总体均分与按类别均分，避免总分掩盖短板。
- 多次运行的均值与置信区间，暴露随机性。
- 与基线的差值与显著性判断，而非孤立分数。

一个常见陷阱是把 MT-Bench 分数当作绝对质量指标对外宣传。它更适合用作「同批次内模型间的相对比较」；跨批次、跨版本比较必须先确认数据集、提示与裁判完全一致。

## 十、小结
MT-Bench 把对话质量这一主观对象结构化为可批量、可复现的多轮评测，是多轮能力评测的奠基性基准。它的价值不在某个具体分数，而在于确立了「固定问题集 + 固定裁判提示 + 分类汇总」的评测协议。使用时应始终配合人工抽检与偏差分析，把自动分数定位为「高效的相对比较工具」，而非绝对结论。
