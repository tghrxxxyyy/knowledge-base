# LLM-as-judge 基础范式与自洽性

> 对应 Zheng et al. 2023《Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena》与 Brown et al. 2020《Language Models are Few-Shot Learners》。

## 一、背景与挑战
用人工评测大模型输出，成本高、速度慢、难以复现，也无法嵌入持续集成流水线。LLM-as-judge 用强模型替代人类打分，把评测变成可批量、可复现的函数调用，从而支撑快速迭代。但随之而来的是一组新问题：裁判模型自身存在偏差、对提示敏感、结论不稳定，且它与人类判断的对齐程度在部署前往往是未知的。

因此，LLM-as-judge 的核心不是「用了裁判」，而是「如何证明裁判可信」。一个未经一致性验证的裁判，可能把系统性错误当成结论放大，比人工评测更危险——它给人一种客观的错觉。

## 二、核心原理
基础范式是：给定问题 $x$ 与两个候选回答 $a$、$b$，让裁判模型在提示中先输出推理理由、再输出偏好结论（A 胜、B 胜或平局）。这种「先理由后结论」的链式结构，既提升可解释性，也被观察到能改善判断质量。

从抽象层面看，该范式把「不可微、昂贵的人类偏好估计」近似为一个可调用的确定性（在温度 0 或固定采样下）函数 $J(x, a, b) \to \{\text{A}, \text{B}, \text{tie}\}$。评测系统围绕这个函数构建：批量调用、聚合统计、与少量人类标注对齐。

自洽性（self-consistency）是提升可靠性的重要手段：对同一判断多次采样（提高温度），观察结论是否稳定；若多次采样结论不一致，说明该样本处于裁判的「判断模糊区」，应降权或转人工。

## 三、形式化与数学基础
裁判与人类的一致性常用 Cohen's kappa 度量，它剔除了「随机猜中」的部分：

$$ \kappa = \frac{p_o - p_e}{1 - p_e} $$

其中 $p_o$ 为观测一致率，$p_e$ 为在类别边缘分布下由随机造成的期望一致率。$\kappa = 0$ 表示与随机无异，$\kappa = 1$ 表示完全一致，负值表示比随机更差。相比裸准确率 $p_o$，$\kappa$ 更能反映真实对齐水平。

自洽性可形式化为同一输入下多次判断的众数稳定性。设对样本 $i$ 采样 $K$ 次得到结论集合 $\{o_i^{(1)}, \dots, o_i^{(K)}\}$，定义自洽率：

$$ C = \frac{1}{N}\sum_{i=1}^{N}\mathbb{1}\bigl[\text{mode}(o_i^{(1..K)}) = o_i^{(k)}\ \forall k\bigr] $$

$C$ 越高说明裁判在该样本上越确定。低自洽率的样本正是人工重点复核的对象。

## 四、代码实现
```python
# 基础成对裁判：先理由、后结论
def judge(question, answer_a, answer_b, model, temperature=0.0):
    system = "你是公正的裁判。先给出简明理由，再输出最终结论（A、B 或 tie）。"
    user = (
        f"问题：{question}\n"
        f"回答 A：{answer_a}\n"
        f"回答 B：{answer_b}\n"
        f"请判断哪个回答更好。"
    )
    return model.generate(system, user, temperature=temperature)

# 自洽性：多次采样取众数
def self_consistent_judge(question, a, b, model, k=5):
    votes = [judge(question, a, b, model, temperature=0.7) for _ in range(k)]
    return max(set(votes), key=votes.count), votes
```

LLM-as-judge 在成本与灵活性之间取得很好平衡，但它继承了训练数据中的价值观与风格偏好，对长度、格式、位置等表面特征敏感，必须配合一致性度量与人工校准才能用于决策。

## 六、常见误区
误区一：「裁判是强模型，所以永远正确」。错，强模型同样有系统性偏差，需量化对齐。误区二：「裁判给自己或同族模型的回答打分更高，只是巧合」。错，这是可复现的自我偏好偏差。误区三：「没做人工校准就直接上线做发布决策」。错，未验证的裁判不可作为门禁。误区四：「只用准确率报告一致性」。错，应当同时报告 kappa 等剔除随机基线的指标。误区五：「改了裁判提示仍沿用旧的验证结论」。错，提示变更需重做一致性实验。

## 九、演进与趋势
范式从「单一裁判」演进到「多裁判投票与集成」，从纯成对比较扩展到带 rubric 的维度打分，并引入自洽性采样、校准集微调与对抗式裁判来抑制偏差。另一条路线是用人类偏好数据专门微调裁判模型，使其在特定领域更贴合人类判断。整体方向是「让自动裁判的判断过程可度量、可校准、可审计」。

部署裁判式评测时，建议把下面这些实践固化为流程：

- 提示版本化：裁判提示与系统消息入库，变更走评审并重做验证。
- 采样固化：温度、种子与最大长度统一记录，保证可复现。
- 原始证据留存：保存裁判的完整输出与理由，便于复盘与问责。
- 校准集维护：保留一小批带人类标签的样本，用于版本升级后的快速验证。
- 分歧队列：把与人类不一致、或自洽率低的样本集中人工复核。
- 多裁判集成：对高风险结论用多个裁判投票，降低单一模型偏差。

评估裁判本身时，除了总体一致性，还应分维度报告：事实性、有用性、安全性等维度上的一致性可能差异很大，总体数字会掩盖维度级的失效。只有把「在哪一维度不可信」也讲清楚，裁判结论才真正可用。

## 十、小结
LLM-as-judge 是自动评测的核心范式：它用可批量、可复现的模型判断替代昂贵的人工评测，把评测工程化。但其结论的可信度取决于一致性度量、偏差分析与人工抽检——没有经过对齐验证的裁判，只是把人类的偏见换成了模型的偏见。把它当作「需要被验证的测量仪器」，而非「真理本身」，才是正确的使用姿势。
