# 评测协议：成对比较与打分制

> 对应 Zheng et al. 2023《Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena》与 Gao et al. 2021 lm-evaluation-harness。

## 一、背景与挑战
评测协议决定分数是否可比、是否可复现。同一批模型输出，用不同协议得到的排序可能不同：成对比较稳健但只给相对结论，打分制能给出绝对分却受量表锚定影响。若在协议未固定、口径不统一的情况下比较模型，得到的结论毫无意义。

更深层的挑战在于「裁判的随机性」与「量表的漂移」：同样的回答在不同时间、不同提示下可能得到不同分数；不同评测者心中「7 分」的含义也不一致。协议设计的目标，是用实验设计与统计聚合把这些噪声压到可控范围。

## 二、核心原理
两种基本协议：

- 成对比较（pairwise）：给裁判同一问题的两个回答，让其选 A 胜、B 胜或平局。只要求相对判断，绕开了「绝对分怎么定」的难题，对量表漂移鲁棒。缺点是无法单独给出「绝对质量」，且需要大量比较才能稳定排序。
- 打分制（pointwise / direct scoring）：让裁判在固定量表（如 1-10）上给出绝对分。便于跨模型横向排序与设定阈值告警，但量表锚定主观、易受长度与格式影响，不同批次分数可能不可比。

两者可统一到同一个偏好概率模型下：把 pairwise 的胜者看作伯努利观测，用 Bradley-Terry 或 Elo 从成对结果反推每个模型的隐含实力分；打分制则可视为对同一潜在质量的有噪观测。工程上常用「打分制做快速筛查、成对比较做精细排序」的组合。

## 三、形式化与数学基础
Bradley-Terry 模型假设模型 $A$、$B$ 各有隐含实力 $s_A$、$s_B$，则 A 胜出的概率为：

$$ P(A \succ B) = \frac{e^{s_A}}{e^{s_A} + e^{s_B}} = \sigma(s_A - s_B) $$

其中 $\sigma$ 为 logistic 函数。给定一批成对结果，可用最大似然估计实力参数；Elo 则是其在线增量版本，每场比赛后按胜负调整双方分数。

打分制下，若对同一输出采样多次得到分数 $\{s^{(1)}, \dots, s^{(K)}\}$，应报告均值与不确定性，而非单次分数：

$$ \bar{s} \pm z_{1-\alpha/2}\,\frac{\sigma}{\sqrt{K}} $$

平局（tie）在 BT 模型中需特殊处理，可视为双方各得半胜，或引入独立的平局概率参数；平局率过高往往意味着量表或候选区分度不足。

## 四、代码实现
```python
import math

# Bradley-Terry：由实力分计算 A 胜出概率
def bt_prob(s_a, s_b):
    return math.exp(s_a) / (math.exp(s_a) + math.exp(s_b))

# 从成对结果估计实力（简化的一步梯度更新）
def bt_update(s_a, s_b, a_wins, lr=0.1):
    p = bt_prob(s_a, s_b)          # A 胜的预测概率
    y = 1.0 if a_wins else 0.0     # 实际结果
    s_a += lr * (y - p)            # 梯度上升
    s_b -= lr * (y - p)
    return s_a, s_b
```

```text
# 协议选择建议
- 需要绝对分或跨批次阈值告警 -> 打分制（配锚定参考回答）
- 需要稳健排序、且质量差异细微 -> 成对比较 + BT/Elo 聚合
- 生产门禁 -> 打分制快速筛查，关键结论用成对比较复验
- 无论哪种 -> 固定提示与采样参数，报告均值±不确定性
```

## 五、与其他技术对比
| 维度 | 成对比较（Pairwise） | 打分制（Pointwise） |
| --- | --- | --- |
| 判断难度 | 较低（相对） | 较高（需锚定量表） |
| 抗量表漂移 | 强 | 弱 |
| 能否给绝对分 | 否 | 是 |
| 数据效率 | 需较多比较 | 单次即得分数 |
| 聚合方式 | BT / Elo | 均值与置信区间 |
| 主要风险 | 平局多、比较爆炸 | 锚定偏差、长度偏差 |

成对比较对量表漂移鲁棒，打分制便于横向排序与阈值告警，但需锚定参考回答；两者不是对立，而是可组合的两级尺度。

## 六、常见误区
误区一：「把打分简单平均而不检查方差」。错，方差大说明结论不稳，均值会误导。误区二：「忽略平局率」。错，平局率过高意味着候选区分度不足或裁判无判断力。误区三：「跨批次直接比较绝对分」。错，量表可能漂移，需用锚定样本校准。误区四：「成对比较不需要统计聚合」。错，少量比较的胜负排序极不稳定，需 BT/Elo 聚合与置信区间。误区五：「协议固定了就够了」。错，还需固定提示、温度与裁判版本。

## 九、演进与趋势
协议正从单一维度总分走向 rubric 维度化打分，让分数可解释「差在哪一维度」；同时引入多次采样与温度扰动来提升稳定性，并把裁决的不确定性显式暴露。聚合侧，BT/Elo 与主动采样（优先比较实力接近的模型）结合，以更少的比较得到更稳定的排序。整体方向是「协议即实验设计」，把统计严谨性内建到评测流程中。

实现层面，几个细节最容易出错：

- 平局处理：需在模型中显式建模，或折算为半胜，不能简单丢弃。
- 顺序随机化：成对比较必须随机化候选顺序，否则位置偏差会污染实力估计。
- 采样次数：单次判断随机性大，应多次采样并报告分布。
- 锚定样本：打分制应固定若干参考回答作为量表锚点，跨批次才可比。
- 显著性：实力分差异需给出置信区间，重叠则不可宣称更优。

选择协议的决策清单：

- 只需相对排序、差异细微 → 成对比较 + BT/Elo。
- 需要绝对分或阈值告警 → 打分制 + 锚定参考。
- 既要稳健又要速度 → 打分制筛查，关键结论成对复验。

## 十、小结
评测协议的核心是匹配下游用途：需要绝对分与阈值就用打分制并锚定参考；需要稳健细微排序就用成对比较加 BT/Elo 聚合。无论选哪种，都必须固定提示与采样参数、报告不确定性与平局率，并用统计聚合压制裁判随机性。协议不是形式，而是让「模型 A 比 B 好」这句话在统计上站得住脚的前提。
