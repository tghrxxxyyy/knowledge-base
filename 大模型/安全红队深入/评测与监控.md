# 安全评测与监控

> 对应 HELM / OpenLLM Leaderboard 安全评测思想与 OWASP LLM 监控实践。

## 一、背景与挑战

模型的安全不能止步于「发布时合格」。上线前需要一套系统化的安全评测集来验证抗攻击能力（越狱、注入、有害内容），上线后更需要实时监控来捕捉未知攻击与分布漂移：用户的对抗手法在不断进化，训练时未见过的提示词组合、突发的滥用模式，都可能绕过静态评测。挑战在于：静态评测易「过拟合」固定样例，而线上流量长尾且对抗性强，监控既要低延迟又要避免误报淹没运营；此外还需建立用户举报到修复的闭环，使一线反馈回流成新的评测样本。安全评测与监控构成「双轨」：前者回答「模型现在安全吗」（离线、受控、可重复），后者回答「线上现在安全吗」（实时、对抗、长尾）。

## 二、核心原理

需要区分「安全评测」与「安全监控」的职责边界：前者回答「模型现在安全吗」（离线、受控、可重复），后者回答「线上现在安全吗」（实时、对抗、长尾）。二者指标应统一口径，避免出现「评测 0 越狱但线上频发」的分裂。安全评测与监控构成「双轨」：

- 评测轨（离线）：在受控环境用标准化对抗集测量攻击成功率（ASR）、违规率、偏见得分等，作为发布门禁。
- 监控轨（在线）：对实时流量做异常检测——异常提示词模式、可疑工具调用频次、敏感实体外泄、用户短时间内高频试探等，触发告警或限流；同时收集用户举报，人工复核后沉淀为评测样本。

核心指标：ASR（攻击成功率）、违规率（violation rate）、平均风险分。二者互补：评测防「已知退化」，监控捕「未知攻击」。

## 三、形式化与数学基础

设线上流量按时间窗划分，窗口 $t$ 内风险事件数 $X_t$，正常基线均值 $\mu$、方差 $\sigma^2$。用控制图（如 $3\sigma$ 准则）判定异常：

$$\frac{|X_t - \mu|}{\sigma} > 3 \Rightarrow \text{告警}$$

对单条请求，风险评分器 $r(x)\in[0,1]$，当 $\sum_{i\in\text{window}} r(x_i) > \lambda$ 触发熔断。ASR 在评测集定义同前：

$$\text{ASR} = \frac{\text{成功攻击数}}{\text{总攻击数}}$$

发布门槛常设为 $\text{ASR} \le \epsilon$。监控的核心是把「单点异常」聚合为「窗口级态势」以降低误报。

## 四、代码实现

```python
# 基于滑动窗口的异常监控（示意）
from collections import deque

class RiskMonitor:
    def __init__(self, window=100, lam=5.0):
        self.buf = deque(maxlen=window)
        self.lam = lam

    def ingest(self, risk_score: float):
        self.buf.append(risk_score)
        if len(self.buf) == self.buf.maxlen:
            if sum(self.buf) > self.lam:
                return "ALERT"   # 触发告警/限流
        return "OK"
```

## 五、与其他技术对比

| 手段 | 时机 | 覆盖面 | 短板 |
|------|------|--------|------|
| 离线评测 | 发布前 | 已知攻击 | 易过拟合 |
| 在线监控 | 运行中 | 未知/长尾 | 误报成本 |
| 用户举报 | 事后 | 真实危害 | 滞后 |

三者组合形成「事前—事中—事后」完整闭环。

## 六、常见误区

- 把评测高分等同「安全」：静态集易被针对性修复而掩盖真实风险。
- 监控只看总量不看分布：某类攻击局部爆发会被均值掩盖。
- 举报不回流：一线发现的真实危害未转化为评测样本。
- 告警阈值固定：流量自然波动会制造误报疲劳，应自适应基线。

## 七、与开源书·权威来源对应

- HELM、OpenLLM Leaderboard 等将安全维度纳入基准评测。
- OWASP LLM Top 10 强调上线后监控与事件响应。
- 内容安全实践普遍采用「评测门禁 + 实时风控 + 举报闭环」，以官方最新文档为准。

## 九、演进与趋势

- 评测从「固定集」走向「自适应生成」，用模型自动构造对抗样例。
- 监控引入大模型本身做语义级异常检测，替代纯关键词规则。
- 评测、监控、红队三系统打通，形成统一的风险中台。
- 可解释风控：对告警给出「为何触发」的自然语言说明，降低运营负担。

## 十、小结

安全评测与监控是大模型上线的「前后两道防线」：离线评测守住已知风险底线，在线监控捕捉未知攻击与漂移，二者配合用户举报闭环，构成可持续的安全运营体系。核心指标 ASR 与违规率须贯穿始终，并以自适应基线抑制误报。
