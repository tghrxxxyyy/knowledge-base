# 合规与治理

> 对应《生成式人工智能服务管理暂行办法》、NIST AI RMF 与 GDPR/PIPL 数据合规要求。

## 一、背景与挑战

大模型进入生产后，面临的不再是学术评测，而是监管、行业与客户三方叠加的合规压力。一方面，训练与推理过程涉及个人信息（PII）、版权语料、商业秘密等敏感数据；另一方面，生成内容可能含违法不良信息、歧视性表述或虚假陈述，带来法律与声誉风险。治理的目标，是在「模型能力」与「可控可问责」之间建立可持续的平衡：既要让模型可用，又要做到数据可追溯、决策可解释、风险可处置。国内外监管框架的差异（如备案制 vs 风险评估制）也要求企业具备跨辖区的合规适配能力。更棘手的是，模型迭代频繁，治理不能「一次搞定」，而要随版本持续运行。

## 二、核心原理

国际层面，欧盟 AI Act 按风险分级施加义务，与国内的备案制形成互补视角，出海产品需同时对齐。治理不是一次性合规动作，而是贯穿「数据采集—训练—评估—上线—运营」全生命周期的闭环。许多风险（如训练语料版权、生成内容违法）往往事后审计才暴露，因此可观测性与留痕能力本身即是合规资产。合规治理可拆为两条主线。其一是「数据合规」：数据收集需有合法基础（同意、合同、公共利益），训练需去除可直接识别个人的信息，跨境传输受限制。其二是「内容与服务治理」：上线前做安全评估与算法备案（国内生成式服务多需备案），运行中建立内容审核与应急下线机制。在治理机制上，业界普遍采用「模型卡（Model Card）+ 数据卡（Datasheet）+ 风险评估报告 + 红队报告 + 上线审批」的文档链，把抽象责任落到具体工件上，使合规可审计、可复现。

## 三、形式化与数学基础

可从「风险敞口」角度量化治理强度。设风险事件集合 $\mathcal{E}$，每类风险 $e$ 的发生概率为 $p_e$，单起损失为 $L_e$，控制手段 $c$ 的覆盖率（降低概率的比例）为 $\rho_c\in[0,1]$，则残余风险：

$$R_{resid} = \sum_{e\in\mathcal{E}} p_e(1-\max_c \rho_c)\cdot L_e$$

治理目标即选择成本可控的控制集 $\mathcal{C}$，使 $R_{resid}\le R_{budget}$。这本质是一个带预算约束的风险最小化问题，且需随新风险 $e$ 出现而动态更新 $\mathcal{C}$，体现治理的持续性。

## 四、代码实现

```python
# 简易合规检查清单（伪代码示意）
CHECKS = {
    "pii_redacted": False,      # 训练数据已脱敏
    "license_ok": False,        # 语料授权合规
    "model_card": False,        # 已写模型卡
    "filing_done": False,       # 已完成备案/评估
}

def gate_release(checks: dict) -> bool:
    missing = [k for k, v in checks.items() if not v]
    if missing:
        raise RuntimeError(f"未通过合规门禁: {missing}")
    return True
```

## 五、与其他技术对比

| 维度 | 仅技术安全 | 合规治理 |
|------|-----------|----------|
| 关注点 | 攻击/防御 | 法律/责任 |
| 产出 | 评测分数 | 文档/备案 |
| 责任主体 | 工程师 | 企业/法务 |
| 可审计性 | 弱 | 强 |

技术安全解决「能不能被打」，治理解决「该不该上线、出问题谁负责」，二者互补而非替代。

## 六、常见误区

- 误以为合规等于「不生成坏内容」：数据合规（隐私、版权）往往比内容安全更隐蔽且代价更高。
- 治理文档与工程实践脱节：模型卡写了「无偏见」却无对应评测，等同无效。
- 认为「开源模型无需合规」：若用于面向公众的服务，仍受内容与数据监管约束。
- 把备案当作一次性动作：模型迭代后需重新评估与更新材料。
- 重内容审核、轻数据合规：训练语料的版权与隐私风险往往更隐蔽、代价更高。

## 七、与开源书·权威来源对应

- 国内《生成式人工智能服务管理暂行办法》明确训练数据合规、安全评估与备案要求。
- NIST AI Risk Management Framework（AI RMF）提供「治理—映射—测量—管理」四职能框架。
- GDPR（欧盟）、PIPL（个人信息保护法）规定数据处理合法基础与跨境规则，以官方最新文本为准。

## 九、演进与趋势

- 从「事后问责」走向「事前评估 + 持续监测」的主动治理。
- 监管科技（RegTech）将合规检查嵌入 CI/CD，实现「合规即代码」。
- 跨国企业日益需要统一 AI 治理中台，以适配不同司法辖区的差异化要求。
- 自动化证据采集（训练血缘、评测记录）让合规从「人工填报」变「系统生成」。

## 十、小结

合规与治理是企业级大模型落地的底座工程。它把数据安全、内容责任与可追溯性转化为可执行、可审计的工作流，核心抓手是数据合规、算法备案、模型/数据卡与上线门禁，并以持续监控闭合风险闭环。治理不是一次动作，而是随版本迭代长期运行的机制。
