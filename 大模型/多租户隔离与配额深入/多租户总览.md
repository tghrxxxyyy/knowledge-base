# 多租户隔离与配额总览

> 对应多租户模型服务（KServe 复用推理服务）；litellm 路由与配额。litellm 提供多模型路由。

## 一、背景与挑战

多团队或客户共享 GPU 集群，需隔离防互相干扰，并按配额计费与限流。

## 二、核心原理

逻辑隔离（命名空间、队列）为主，物理隔离（独占卡）为辅；配额限定每租户最大并发与算力。

## 三、数学形式

租户 $i$ 配额 $q_i$，约束 $\sum_i q_i \le C_{total}$；超额请求排队或拒绝。

## 四、代码实现

```python
if used[t] + 1 > quota[t]:
    raise HTTPError(429)
admit(t, req)
```

## 五、与其他对比

- 与 公平调度DRF / 限流与熔断 共享机制。
- 与 租户成本隔离（计费）衔接。

## 六、常见误区

- 逻辑隔离下嘈邻效应（noisy neighbor）拖垮邻居。
- 配额静态致碎片或饥饿。

## 八、面试题

- 多租户为何隔离？答：防互相干扰并保证配额公平，支撑共享集群按量计费。

## 九、演进

独享 → 逻辑隔离 → 弹性配额与物理兜底。

## 十、小结

多租户以隔离与配额在共享成本与性能保障间平衡。
