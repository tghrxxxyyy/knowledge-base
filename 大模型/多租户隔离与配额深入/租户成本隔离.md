# 租户成本隔离

> 对应按租户计量计费；litellm 成本追踪 / Prometheus label。litellm 记录每请求花费。

## 一、背景与挑战

共享集群需把成本精确归因到租户，否则无法结算与优化。

## 二、核心原理

每请求打租户标签，记录 token、GPU 秒、时长，按单价分摊；超预算报警。

## 三、数学形式

成本 $cost_i = p_{tok}\cdot tok_i + p_{gpu}\cdot gpu\_sec_i$；月度汇总对账。

## 四、代码实现

```python
labels = {"tenant": t}
prom.counter("gpu_sec", labels).inc(elapsed)
```

## 五、与其他对比

- 与 成本归因与计费深入（全局归因）衔接。
- 与 配额管理策略（预算）共享。

## 六、常见误区

- 标签缺失致成本无法归因。
- 仅按 token 忽略固定开销。

## 八、面试题

- 成本隔离如何做？答：请求打租户标签，记录资源用量，按单价分摊并预警。

## 九、演进

无计量 → 标签计数 → 实时分摊与预算。

## 十、小结

租户成本隔离是共享集群可运营的前提。
