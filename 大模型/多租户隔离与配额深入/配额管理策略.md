# 配额管理策略

> 对应 K8s ResourceQuota / LimitRange；litellm 预算。K8s 提供命名空间级配额。

## 一、背景与挑战

需限制每租户长期与瞬时用量，防滥用并保证公平与成本可控。

## 二、核心原理

配额分并发数、RPM、TPM、GPU 小时；可设硬上限与弹性借用（borrow）邻近空闲配额。

## 三、数学形式

令牌桶：$tokens_{t+1}=\min(C, tokens_t + r\Delta t) - cost$；耗尽即拒。

## 四、代码实现

```python
if bucket.consume(t, cost=1):
    admit(req)
else:
    raise HTTPError(429)
```

## 五、与其他对比

- 与 限流与熔断（限流算法）共享令牌桶。
- 与 租户成本隔离（配额=预算）衔接。

## 六、常见误区

- 配额过紧业务受阻，过松成本失控。
- 跨区配额未汇总致全局超用。

## 八、面试题

- 配额与限流区别？答：配额是总量或时段上限，限流是速率控制，常配合用。

## 九、演进

静态 → 弹性借用 → 按预算动态。

## 十、小结

配额量化租户权利，是计费与公平的基础。
