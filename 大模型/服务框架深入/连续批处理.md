# 连续批处理

> 对应 Yu et al., *Orca: A Distributed Serving System for Transformer-Based Generative Models*, OSDI 2022（iteration-level batching）；与 服务框架深入 衔接。

## 一、背景与挑战

静态批处理须等最慢请求生成完才能返回，长尾拖垮整体延迟与利用率。

## 二、核心原理

连续批处理（iteration-level）在每个解码步动态纳入新请求、剔除已完成步，使批在 token 粒度流动而非请求粒度。

## 三、数学形式

每步可服务集合 $B_t=\{r: r\ \text{alive at step }t\}$；吞吐 $\Theta\approx\frac{1}{T}\sum_t |B_t|$。

## 四、代码实现

```python
while not all_done:
    batch = scheduler.poll_ready()      # 每步动态组批
    logits = model.step(batch)
    scheduler.update(batch, logits)
```

## 五、与其他对比

- 与 分页注意力PagedAttention（KV 配合动态批）协同。
- 与 优先级调度深入（批内排序）相关。

## 六、常见误区

- 动态批带来调度开销，需与 kernel 融合抵消。
- 忽视不同长度请求的内存峰值叠加。

## 八、面试题

- 连续批为何优于静态批？答：以 token 步为单位动态组批，避免等长补齐与长尾空等，提升利用率。

## 九、演进

请求级批 → 步级连续批 → 抢占式连续批。

## 十、小结

连续批处理是 LLM 服务吞吐的命门，使 GPU 始终满载。
