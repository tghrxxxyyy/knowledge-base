# 可观测性与运维

> 对应 CNCF, *OpenTelemetry / Prometheus*（指标与追踪）；与 服务框架深入 衔接。

## 一、背景与挑战

线上服务出问题难定位，需要指标、日志、追踪三位一体。

## 二、核心原理

采集吞吐、TTFT、TPOT、队列长度、GPU 利用率、错误率，结合 trace 定位慢请求环节（调度/计算/回传）。

## 三、数学形式

首 token 延迟 $TTFT$；每输出 token 时间 $TPOT=\frac{T_{gen}}{N_{gen}}$；P99 监控尾延迟。

## 四、代码实现

```python
# 暴露 Prometheus 指标
REQUEST_LAT.observe(time.perf_counter()-start)
GPU_UTIL.set(get_gpu_util())
```

## 五、与其他对比

- 与 网关限流深入（限流指标）共享监控。
- 与 优先级调度深入（按指标调权）闭环。

## 六、常见误区

- 只看均值忽略 P99 尾延迟。
- 指标过细影响性能本身。
