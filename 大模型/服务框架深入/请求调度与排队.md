# 请求调度与排队

> 对应 NVIDIA, *Triton Model Scheduling*, 2020；与 服务框架深入 / 优先级调度深入 衔接。

## 一、背景与挑战

多请求到达需排队与调度，否则相互阻塞、尾延迟失控。

## 二、核心原理

用队列 + 调度器按策略（FIFO/优先级/公平）派发到实例；结合连续批在步级调度，控制最大批与队列延迟。

## 三、数学形式

队列延迟 $W=\frac{\rho}{\mu-\lambda}$（M/M/1）；需 $\lambda<\mu$ 防雪崩，$\rho$ 为利用率。

## 四、代码实现

```python
sched = FairScheduler(max_batch=32, max_wait_ms=10)
req = await sched.enqueue(prompt, priority=user_tier)
```

## 五、与其他对比

- 与 优先级调度深入（具体策略）互补。
- 与 网关限流深入（限流在前、调度在后）串联。

## 六、常见误区

- 队列无限长致 OOM 与超时雪崩。
- 调度不考虑 KV 峰值致显存溢出。

## 八、面试题

- 为何要限队列长度？答：避免请求无限堆积引发 OOM/超时雪崩，保护尾延迟。

## 九、演进

无调度 → FIFO → 优先级/公平调度。

## 十、小结

请求调度与排队把并发请求有序喂给连续批，是稳定服务的前提。
