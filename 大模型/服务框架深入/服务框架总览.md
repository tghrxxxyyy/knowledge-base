# 服务框架总览

> 对应 Kwon et al., *vLLM: Efficient Memory Management for LLM Serving with PagedAttention*, SOSP 2023；与 服务框架深入 / 编译部署深入 衔接。

## 一、背景与挑战

LLM 自回归生成 token 慢且显存（KV Cache）占用大，朴素服务利用率低。

## 二、核心原理

现代 LLM 服务框架以连续批处理 + 分页 KV Cache 为核心，结合高效调度与并行，最大化吞吐与 GPU 利用率。

## 三、数学形式

吞吐 $\Theta=\frac{\text{generated tokens}}{T}$；受限于 $\min(\text{compute}, \text{memory bandwidth}, \text{KV capacity})$。

## 四、代码实现

```python
from vllm import LLM, SamplingParams
llm = LLM(model="meta-llama/Llama-2-7b", gpu_memory_utilization=0.9)
out = llm.generate(prompts, SamplingParams(temperature=0.8, top_p=0.95))
```

## 五、与其他对比

- 与 连续批处理 / 分页注意力PagedAttention 是总览分解。
- 与 编译部署深入（提供执行内核）上下游。

## 六、常见误区

- 以为堆 GPU 就快，调度不当利用率仍低。
- 忽略 KV Cache 碎片导致并发受限。
