# 多模型并发隔离

> 对应 NVIDIA, *Triton Concurrent Model Execution*, 2020；与 服务框架深入 / 优先级调度深入 衔接。

## 一、背景与挑战

同一服务器需同时服务多个模型/版本，相互抢占资源致抖动。

## 二、核心原理

按模型划分实例与显存配额，使用独立的 CUDA stream/上下文或 MPS 隔离，配合优先级保证关键模型延迟。

## 三、数学形式

给定显存 $M$，约束 $\sum_i m_i \le M$；SLA 违约率 $P(\text{lat}>SLA_i)\le \epsilon_i$。

## 四、代码实现


## 五、与其他对比

- 与 多模型路由深入（路由到不同模型）前后衔接。
- 与 优先级调度深入（优先保障）相关。

## 六、常见误区

- 多模型共享同上下文致互相污染/争抢。
- 配额固定无法弹性应对峰值。
