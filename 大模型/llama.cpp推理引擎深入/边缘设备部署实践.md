# 边缘设备部署实践

> 对应 ggerganov/llama.cpp 官方示例；Dettmers 2023 QLoRA；Karpathy/nanoGPT。

## 一、背景与挑战

在手机、树莓派、旧笔记本等资源受限设备上跑 LLM，要在精度、速度、内存三者间做硬性权衡。这些设备通常没有独立高性能 GPU，内存带宽有限，散热与功耗受限，还存在系统可用内存碎片问题。

失败模式很具体：模型加载即 OOM、首 token 延迟数秒、长对话中途被系统杀掉、电池迅速耗尽。部署的核心不是「能不能跑」，而是「在给定内存与延迟预算内稳定跑」。

## 二、核心原理

边缘部署是一个多变量的约束优化问题，主要手段有五：

1. **量化**：用 Q4_K/Q5_K 把权重大小压到 FP16 的约 1/3~1/4；
2. **限制上下文**：按可用内存设置 `--ctx-size`，避免 KV cache 失控；
3. **启用合适后端**：Apple 用 Metal、跨厂商 GPU 用 Vulkan、无 GPU 用多线程 CPU；
4. **层卸载**：用 `-ngl` 把部分层放到 GPU/NPU，其余留在 CPU；
5. **小批处理**：端侧通常 batch=1，追求低延迟而非吞吐。

三者预算关系可写成一条不等式，指导参数选择。

## 三、形式化与数学基础

内存预算：

$$ M_{total} \approx |W|_{quant} + |KV| + M_{runtime} + M_{os} \le M_{avail} $$

其中权重项（以每权重 $b$ 位、参数量 $P$ 计）为

$$ |W|_{quant} \approx \frac{P \cdot b}{8} \;\text{字节}, \qquad |KV| = 2 L n_{layers} n_{kv} d_{head} \cdot \text{prec} $$

延迟模型：首 token 延迟约正比于预填充计算量 $2 P S_{prompt}$ 除以设备算力 $F$；解码每 token 延迟约正比于读取权重字节数除以带宽 $B$：

$$ t_{decode} \approx \frac{|W|_{quant}}{B} $$

因此**量化对解码延迟的收益来自减少字节数**，而非提升算力。吞吐与延迟的对偶关系决定了端侧应优先优化 $t_{decode}$。

## 四、代码实现

```text
# Apple Silicon：Metal 加速，尽量卸载层
./llama-cli -m model-q4_k_m.gguf -p "你好" -n 256 \
  -ngl 99 --ctx-size 2048 -t 6

# 树莓派/无 GPU：纯 CPU 多线程，降低线程数减少调度开销
./llama-cli -m model-q4_k_m.gguf -p "总结这段话" -n 128 \
  -ngl 0 --ctx-size 1024 -t 4

# 只做单轮问答，控制显存/内存峰值
./llama-cli -m model-q5_k_m.gguf -p "翻译" -n 64 --no-warmup
```

配套建议：优先选 3B 以下的小模型；用 F16 转量化一次后固化 GGUF 分发；用 mmap 加载避免一次性占用内存；长任务用流式输出改善体感延迟。参数名与默认值以仓库最新文档为准。

## 六、常见误区

- 认为模型越大越好：端侧应匹配内存与延迟预期，3B 常在体验上优于 7B。
- 只算权重内存：长上下文下 KV cache 可能数倍于权重，必须一并预算。
- 盲目把 `-ngl` 设到最大：显存不足会 OOM，需按可用显存试探。
- 忽略线程数并非越多越好：超出物理核数后上下文切换反而降速。
- 认为量化只降内存不降质量：低比特会损失精度，敏感任务应上调位宽。
- 忽略 mmap 与页缓存的关系：首次运行仍有冷启动读盘开销，重复运行才受益。
- 认为一次调参可通吃所有设备：内存与后端差异要求按机型分别标定参数。

## 八、面试题

- 问：端侧部署的首要约束？答：内存与内存带宽，需量化 + 限上下文 + 合适后端共同满足。
- 问：为何量化能降低解码延迟？答：解码访存受限，权重字节数减少直接缩短每 token 的读取时间。
- 问：如何决定上下文长度？答：按剩余内存减去权重与运行时开销后反推 KV 预算。
- 问：Metal 与 CPU 后端如何选？答：有 Apple GPU 优先 Metal，无 GPU 则用多线程 CPU。
- 问：如何验证内存预算是否成立？答：用 `time -v` 观察峰值 RSS 与缺页，再回调上下文与卸载层数。
- 问：端侧首 token 延迟由什么决定？答：预填充计算量除以设备算力，减小系统提示长度收益显著。

## 九、演进与趋势

更小更专的端侧模型（3B 以下）配合 llama.cpp 成为主流；NPU 与移动 GPU 原生内核逐步接入；量化 KV cache、投机解码与分组量化进一步压低内存与延迟。端云协同（本地处理常规请求、云端兜底疑难请求）也在成为常见形态。具体支持以仓库最新文档为准。

## 十、小结

边缘部署的本质是在内存、延迟、质量之间求解带约束的优化问题。掌握权重、KV、运行时三部分的内存预算模型，再据此选择量化等级、上下文长度与卸载层数，就能让 LLM 稳定跑在口袋设备上，兼顾隐私与离线可用。
