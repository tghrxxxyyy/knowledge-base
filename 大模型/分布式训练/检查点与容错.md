# 检查点与容错

> 对应 Megatron-LM / DeepSpeed 检查点机制、PyTorch `torch.save` 分布式 checkpoint 实践。

## 一、背景与挑战

大模型训练动辄数天到数周、消耗大量算力，任何中断（硬件故障、spot 实例回收、OOM、网络抖动）都意味着巨大损失。检查点（checkpoint）机制让训练可「断点续训」：周期性把足够的状态持久化，故障后从最近点恢复。挑战在于：① 状态庞大（参数 + 优化器状态 + 调度器 + RNG），单次保存慢且占存储；② 同步保存阻塞训练；③ 多卡分片下需保证一致性与可重放；④ 存储成本与保存频率需权衡。

## 二、核心原理

一个完整 checkpoint 应含：

- **模型参数**（含 TP/PP/DP 分片布局下的本卡分片）。
- **优化器状态**（动量、方差、step）——这是「为何能续训」的关键，缺它只能从参数重训、丢失动量信息。
- **学习率调度器状态**、**全局 step / epoch**。
- **RNG 状态**（数据采样、Dropout、CUDA 随机源）——保证可复现、续训数据顺序一致。

工程要点：

- **异步写**：在后台线程/进程写盘，不阻塞训练步进。
- **多副本 + 校验**：写双份、校验 checksum 防静默损坏。
- **分片保存**：ZeRO/FSDP 下每卡存自己分片，加载时按当前并行度重组（支持弹性扩缩容）。
- **容错**：spot 被回收后，新实例从最新 checkpoint 续训，几乎零损失。

## 三、形式化与数学基础

设训练状态 $S_t = \{W_t,\ \theta_t^{\text{opt}},\ \lambda_t,\ \text{step}_t,\ \text{RNG}_t\}$，其中 $\theta_t^{\text{opt}}$ 为优化器状态。续训要求从 $S_{t-k}$（最近 checkpoint）恢复后，后续轨迹与「未中断」一致：

$$\text{traj}(S_{t-k}) = \text{traj}^{\text{ideal}}(t-k\to T)\quad \text{当 RNG 与数据序一致}$$

保存频率 $f$ 决定最坏丢失量：丢失至多 $f$ 步的算力。异步写使保存开销与主训练重叠：

$$\text{blocking\_time} \approx 0 \quad (\text{若 IO 带宽充足})$$

## 四、代码实现

PyTorch 分布式保存（每卡存分片 + 元数据）：

```python
state = {
    "model": model.state_dict(),           # FSDP 下为分片
    "optimizer": optimizer.state_dict(),
    "step": step,
    "rng": torch.get_rng_state(),
}
# 异步保存（如用 torch.distributed.checkpoint 或后台线程）
torch.save(state, f"ckpt/step_{step}/rank{rank}.pt")
# 加载：先恢复 RNG 与 step，再 load_state_dict 续训
```

## 五、与其他技术对比

| 策略 | 阻塞 | 恢复粒度 | 存储 |
|------|------|---------|------|
| 同步全量保存 | 高 | 整模型 | 大 |
| 异步分片保存 | 低 | 每卡分片 | 中 |
| 仅存参数 | 低 | 丢优化器状态 | 小 |

## 六、常见误区

- 只存参数不存优化器状态，续训丢失动量、收敛劣化。
- 忽略 RNG 状态，续训数据顺序错位、不可复现。
- 同步保存阻塞训练，拖慢整体吞吐。
- 不校验 checkpoint 完整性，恢复时发现损坏。

## 九、演进与趋势

从「同步全量」走向「异步分片 + 校验 + 弹性恢复」：支持并行度变化的弹性训练（扩缩容后重分片），并与对象存储/分布式文件系统深度集成，实现秒级容错。

## 十、小结

检查点与容错是长训练的工程生命线：保存参数、优化器状态、调度器、step 与 RNG，异步分片写盘并校验，才能在故障时近乎零损失续训。核心口诀——「优化器状态与 RNG 一个都不能少」。
