# 流水线并行 Pipeline Parallelism

> 对应 Huang et al. 2019（GPipe）、Harlap et al. 2018（PipeDream）。

## 一、背景与挑战

当模型层数很多、单卡放不下整模型时，可把模型**按层切到不同设备**，形成流水线：第 1 台算前几层、第 2 台算中间层……这就是流水线并行（Pipeline Parallelism, PP）。朴素做法是「先让设备 1 跑完所有 micro-batch 再传给设备 2」，但这会造成严重的**设备空闲气泡（bubble）**——除首尾设备外，中间设备大部分时间在等前序/后序。如何把设备填满、压缩气泡，是 PP 的核心课题。GPipe 用同步微批次、PipeDream 用异步更新，是两条主线。

## 二、核心原理

- **微批次（micro-batch）**：把大 batch 切成多个 micro-batch，在各阶段间流水，使设备尽量不空。
- **GPipe（同步）**：前向把整批 micro-batch 依次流过各阶段，再统一反向，气泡大但数值等价于大 batch；用「1F1B」可减小气泡。
- **1F1B 调度**（one-forward-one-backward）：先前沿填充满水（若干纯前向），之后每个设备交替做「一次前向 + 一次反向」，使反向尽早开始，显著压缩气泡。
- **PipeDream（异步）**：用不同版本的权重做前向/反向（staggered），进一步降气泡，但引入 staleness（梯度用旧权重算），需平衡收敛。

通信：阶段间只传**激活**（前向）与**激活梯度**（反向），带宽要求低于张量并行（TP 需层内 all-reduce）。

1F1B 调度是压缩气泡的关键，理解它要分清「填充阶段」与「稳态阶段」。填充阶段：先让第 1 台设备连续做若干 micro-batch 的前向，把激活逐层传下去，直到最后一台也开始工作——此时各设备像水管注水一样依次填满。稳态阶段：此后每台设备交替执行「一次前向 + 一次反向」，由于反向依赖的前向激活已在本地（或由后一阶段回传的激活梯度触发），设备几乎不停顿。仅最前与最后若干 micro-batch 存在不可避免的填充/排空开销，其余时间设备满负荷。

GPipe 与 PipeDream 的根本分歧在「权重版本」。GPipe 等所有 micro-batch 前向完再统一反向，等价于一个大 batch、数值干净，但气泡大；PipeDream 用「交错版本」——设备 $i$ 反向时用的是稍早版本的权重（staleness = $D-1$ 个 micro-batch），从而几乎无气泡，但梯度带陈旧性，需靠保守 LR 或补偿算法保证收敛。现代框架多用 1F1B 的同步变体，并在其基础上发展出 **Interleaved 1F1B**：把每层再切成多个虚拟 stage、轮流分配给设备，使每台持有不连续的若干层，进一步把气泡压到接近理论下界。PP 与 TP 搭配时，通常把 PP 跨节点（通信少、只需传激活），TP 放节点内（通信频、需 NVLink），以最小化跨节点带宽压力。

## 三、形式化与数学基础

设 $D$ 个设备（阶段），$m$ 个 micro-batch，单 stage 计算时间 $t_f$（前向）、$t_b$（反向）。朴素串行气泡占比近似：

$$\text{bubble} \approx \frac{(D-1)(t_f+t_b)}{m(t_f+t_b)} = \frac{D-1}{m}$$

即 micro-batch 数 $m$ 越大、设备数 $D$ 越小，气泡占比越低。1F1B 把稳态阶段设备利用率提升到接近满负荷，仅首尾仍有 $O(D)$ 个 micro-batch 的填充/排空开销。PipeDream 的 staleness 为 $D-1$ 个版本：

$$\nabla_t \approx \nabla \mathcal{L}\big(W_{t-(D-1)}\big)$$

## 四、代码实现

PyTorch 流水线（概念示意）：

```python
from torch.distributed.pipeline.sync import Pipe
# 把模型按层分成 stages，Pipe 自动做微批次流水
model = Pipe(nn.Sequential(layer1, layer2, layer3, layer4),
             chunks=8)          # chunks = micro-batch 数
out = model(input)              # 内部按 1F1B 调度流式执行
```

DeepSpeed/PipeDream 也提供各自 PP 实现，常配合 3D 并行。

## 五、与其他技术对比

| 并行 | 切分 | 通信量 | 气泡 |
|------|------|--------|------|
| 数据并行 DP | 样本 | 中 | 无 |
| 张量并行 TP | 层内 | 高 | 无 |
| 流水线并行 PP | 层 | 低（激活） | 有（需 1F1B） |

## 六、常见误区

- micro-batch 数设太小，气泡占比飙升、设备空闲。
- 把 PP 与 TP 混用却未放同节点，跨节点激活传输成瓶颈。
- 误以为 PP 无通信，实际阶段间激活传输也吃带宽。
- 忽略 1F1B 调度，朴素流水气泡巨大、吞吐惨。

## 九、演进与趋势

现代框架普遍采用 **1F1B + 调度优化**（如 Interleaved 1F1B，把每层再切虚拟 stage 进一步降气泡），并与 DP/TP 组成 3D 并行。激活重计算常与 PP 配合，用算力换显存。

## 十、小结

流水线并行把模型按层切分、用微批次流水执行，以低通信代价扩展超大模型；代价是设备空闲气泡。1F1B 调度是压缩气泡的关键，配合 3D 并行成为大模型训练的标准拼图之一。
