# 数据集与并行加载

> 对应 PyTorch `DistributedSampler` / `DataLoader` 文档、大规模训练数据管道工程实践。

## 一、背景与挑战

多卡训练时，数据管道常成为隐性瓶颈：GPU 算力越强，越容易被「喂不饱」——数据预处理慢、磁盘 IO 慢、各卡数据重叠或错位，都会让昂贵算力空转。问题本质是：如何在多进程/多卡下**高效、无重叠、可复现**地分发数据，并用并行预处理与预取掩盖 IO 延迟。本文聚焦分布式数据加载的关键设计。

## 二、核心原理

核心组件与要点：

- **DistributedSampler**：按 `rank`（进程编号）把数据集分片，保证 $N$ 张卡拿到**互不重叠**的样本，且全局不重不漏（epoch 末尾 shuffle 用固定 seed 保证可复现）。
- **多进程预处理**：`DataLoader(num_workers>0)` 让 CPU 多进程并行做解码/分词/增强，避免阻塞 GPU。
- **预取（prefetch）**：用独立线程/进程提前把下一批载入显存/页缓存，掩盖磁盘与解码延迟。
- **内存映射 / 缓存**：大文件用 mmap 或预 tokenize 落盘，避免每 epoch 重复解析。
- **pin_memory**：锁页内存加速主机→设备拷贝。

错误的数据管道会让 GPU 利用率长期低于 50%，而算力成本照常计费。

## 三、形式化与数学基础

设数据集 $\mathcal{D}$ 大小 $|\mathcal{D}|=M$，卡数 $N$，rank $r$ 的数据分片：

$$\mathcal{D}_r = \{\,x_i \in \mathcal{D} : i \equiv r \pmod N\,\},\quad |\mathcal{D}_r| \approx M/N$$

全局每 epoch 处理样本数（无重叠、无遗漏）：

$$\bigcup_{r=0}^{N-1} \mathcal{D}_r = \mathcal{D},\quad \mathcal{D}_r \cap \mathcal{D}_{r'} = \varnothing\ (r\ne r')$$

GPU 空闲率近似由数据供给延迟决定：

$$\text{idle} \approx \max\Big(0,\ \frac{t_{\text{load}} - t_{\text{compute}}}{t_{\text{compute}}}\Big)$$

当 `num_workers × 预取` 足以掩盖 $t_{\text{load}}$ 时 idle→0。

## 四、代码实现

分布式数据加载标准写法：

```python
import torch
from torch.utils.data import DataLoader, DistributedSampler

sampler = DistributedSampler(dataset, num_replicas=world_size, rank=rank,
                             shuffle=True, seed=42)
loader = DataLoader(
    dataset,
    batch_size=micro_bs,
    sampler=sampler,
    num_workers=8,          # 多进程预处理
    prefetch_factor=4,      # 预取
    pin_memory=True,        # 锁页加速拷贝
)

    sampler.set_epoch(epoch)   # 关键：每 epoch 换种子，保证 shuffle 不重复
    for batch in loader:
        train_step(batch)
```

## 五、与其他技术对比

| 配置 | 重叠风险 | 吞吐 | 说明 |
|------|---------|------|------|
| 单进程无预取 | 高 | 低 | GPU 空转 |
| num_workers>0 | 低 | 中 | 并行预处理 |
| +预取+pin | 极低 | 高 | 掩盖 IO |
| 无 DistributedSampler | 有 | — | 数据重复/漏 |

## 六、常见误区

- 多卡不用 DistributedSampler，各卡重复同数据，训练无效且浪费。
- 忘记 `sampler.set_epoch(epoch)`，多 epoch 下 shuffle 失效、顺序重复。
- `num_workers` 设 0 或过小，CPU 解码跟不上 GPU。
- 预处理在 GPU 侧做，反而抢训练算力。

## 九、演进与趋势

从「离线预处理落盘」走向「流式（streaming）数据管道」：超大规模语料边读边训、动态 shuffle，配合 WebDataset / Mosaic 等格式减少小文件 IO 开销，进一步消除数据瓶颈。

## 十、小结

数据管道是分布式训练的「隐形瓶颈」。用 DistributedSampler 保证多卡无重叠分发、用多进程预处理+预取+pin_memory 掩盖 IO、用 set_epoch 保证可复现，才能把昂贵算力喂饱。数据工程与模型并行同等重要。
