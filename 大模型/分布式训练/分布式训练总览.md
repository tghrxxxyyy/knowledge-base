# 分布式训练总览

> 对应 Narayanan et al., *Efficient Large-Scale Language Model Training on GPU Clusters*（Megatron-LM, 2021, SC'21）；Rajbhandari et al., *ZeRO: Memory Optimizations Toward Training Trillion Parameter Models*（SC'20）；Huang et al., *PyTorch Distributed*（DDP）；Rasley et al., *DeepSpeed*（2020）；官方文档：NVIDIA/Megatron-LM、deepspeedai/DeepSpeed、pytorch/torch.distributed、huggingface/transformers（FSDP）；mlabonne/llm-course「Training」；参见本库「分布式训练」其余篇与「推理优化/张量并行与流水线并行」。

## 一、背景与挑战

单卡无法容纳大模型的**参数 + 优化器状态 + 梯度 + 激活**，也无法在有限时间内扫完万亿 token。分布式训练把这些压力拆到多卡/多机，但拆分维度彼此耦合：

- **放得下**（显存）：ZeRO/FSDP 分片状态，TP/PP 切计算图，checkpoint 降激活。
- **跑得快**（吞吐）：DP 用满数据并行度，PP 减 bubble，TP 只在高带宽互联内切。
- **同步得对**（正确性）：梯度同步语义、混合精度 loss scaling、确定性与可复现。

核心矛盾是 **计算/显存 vs 通信**：每多切一刀并行，就多一类通信原语；带宽不足时，通信吃掉全部收益。因此分布式选型不是“都开”，而是按 **模型大小、单卡显存、互联拓扑（NVLink/NDR IB/以太网）、目标序列长** 做组合优化。

## 二、核心原理

### 2.1 四大并行维度与 DDP

| 策略 | 切分对象 | 典型通信 | 适用 |
|------|----------|----------|------|
| **数据并行 DP / DDP** | 每卡全模型副本，分 data | 梯度 AllReduce | 默认；模型能放进单卡 |
| **张量并行 TP** | 层内权重矩阵按列/行切 | 激活 AllGather / ReduceScatter（每层多次） | 层太宽，单卡放不下一层 |
| **流水线并行 PP** | 按层切到不同 stage | stage 间点对点传激活 | 层多，适合纵向深模型 |
| **序列并行 SP** | 长序列沿 seq 维切（配合 TP 对 LayerNorm/Dropout） | 视实现（如 Ring Attention） | 极长上下文训练 |
| **ZeRO / FSDP** | 优化器状态 / 梯度 / 参数分片 | AllGather 参数、ReduceScatter 梯度 | 显存被状态打爆，仍想 DP 语义 |

**DDP 要点**：梯度桶（bucket）异步 AllReduce、overlap 通信与反向；`find_unused_parameters`、静态图假设；与 `no_sync()` 做梯度累积时跳过同步。

**ZeRO 三阶段**：

1. Stage 1：分片优化器状态（Adam 的 m/v 等）。
2. Stage 2：再分片梯度。
3. Stage 3：再分片参数（≈FSDP）；前向/反向需 AllGather 参数，算完可释放。

### 2.2 张量并行（TP）直觉

对 MLP $Y = XA$（$A\in\mathbb{R}^{d\times 4d}$）：按列切 $A$ 得部分 $Y_i$，需 AllReduce 求和；下行再按行切，ReduceScatter。Attention 中 head 维天然可切：每卡持 $h/p$ 个头。TP 通信频繁 → **只在 NVLink 节点内**（如 8 卡）使用，跨节点用 PP/DP。

### 2.3 流水线并行（PP）与 bubble

将 $L$ 层分到 $p$ 个 stage，微批（microbatch）$m$ 形成流水。bubble 比例近似：

$$
\text{bubble} \approx \frac{p-1}{m}
$$

增大 microbatch、用 1F1B 调度、交错 schedule 可压 bubble；但 microbatch 增大会增加激活峰值（可配 recompute）。

### 2.4 序列并行与 Ring Attention

- **Megatron 式 SP**：TP 组内，把 LayerNorm/Dropout 的 activation 沿 seq 切开，与 TP 的列/行切互补，降低激活显存。
- **Ring Attention / Striped Attention**：长序列切块，块沿环传 KV，与 flash tiling 结合，支持近线性扩展上下文训练（见「长上下文」相关篇）。

### 2.5 3D 并行组合

典型 3D：**TP × PP × DP**（ZeRO 可再叠在 DP 维）。例：节点内 TP=8，跨节点 PP=4，外层 DP 扩到总卡数。选型顺序经验：

1. 模型能塞进单机 → 优先 FSDP/ZeRO-3 或 TP（视层数）。
2. 塞不进单机、层较深 → TP（节点内）+ PP（跨节点）+ DP。
3. 超长序列 → SP/Ring，或序列维与 DP 组合。

## 三、形式化与数学基础

设总参数数 $P$，每参数混合精度存 $2$ 字节，Adam 状态约 $12$ 字节量级（fp32 master + m + v，实现有差异）：

$$
M_{\text{naive}} \approx P \cdot (2 + 2 + 12) = 16P\ \text{bytes 量级（未计激活）}
$$

DDP 每卡都付上述成本；ZeRO-$s$（$s=1,2,3$）分片因子 $s$ 相关维数后，每卡状态近似：

$$
M_{\text{ZeRO}-s} \approx \frac{a_s P + b_s P}{W} + \text{comm buffers} + M_{\text{act}}
$$

（$W$ 为 DP 世界大小；Stage1 主要减优化器，Stage3 参数也分片。）

AllReduce 通信量（Ring 实现，消息 $m$ 字节，$W$ 卡）：

$$
V_{\text{AllReduce}} = 2 \cdot \frac{W-1}{W} \cdot m \approx 2m
$$

DP 每 step 梯度同步代价 $O(m)$ 与参数量同阶；TP 每层多次小消息，对延迟/带宽更敏感。PP 点对点 $O(\text{microbatch} \cdot \text{hidden})$。

吞吐目标可粗写为：

$$
\text{Efficiency} \approx \min\Big( \eta_{\text{compute}},\ \eta_{\text{comm}} \Big),\quad
\eta_{\text{comm}} = \frac{T_{\text{compute}}}{T_{\text{compute}} + T_{\text{comm}}}
$$

工程上用 MFU（Model FLOPs Utilization）统一衡量：接近硬件峰值 FLOPs 的百分比。

生产踩坑：

- `torchrun` 端口/网卡选错，多机 AllReduce 走以太网导致 MFU 崩。
- DDP + 梯度累积忘了 `no_sync()` 或 `scale/accum` 步数写错，等效 batch 与 LR 调度错位。
- FSDP 保存/加载未处理分片权重，恢复训练 shape 对不上。
- TP 与 PP 的 rank 映射写反，表现为 loss 偶发 NaN 或“看似在训实则部分卡空转”。
- 监控只看 GPU util，不看 tokens/s 与 MFU，通信瓶颈被掩盖。

## 五、与其他技术对比

| 维度 | DDP | ZeRO-1/2 | ZeRO-3/FSDP | TP | PP | SP/Ring |
|------|-----|----------|-------------|----|----|---------|
| 切什么 | 数据（模型复制） | 优化器/梯度 | +参数 | 层内权重 | 层 | 序列 |
| 通信模式 | 梯度 AllReduce | RS + AG | 频繁 AG | 层内高频 | 边界 P2P | 块传递 |
| 显存收益 | 无分片 | 状态减 | 参数也减 | 激活/权重 | 每卡层子集 | 激活↓ |
| 互联要求 | 中 | 中 | 中高 | 高（节点内） | 中（可跨节点） | 高带宽 |
| 典型组合 | 小模型 | 7B–70B DP | 大 70B+ | 节点内 | 深模型 | 超长 n |
| 实现代表 | DDP | DeepSpeed S1/2 | FSDP、S3 | Megatron | Megatron | Ring Attention |

与「推理并行」区别：训练需梯度与优化器同步；推理并行（TP 推理、连续批）更关注延迟与 KV cache，不维护 ZeRO 状态。

## 六、常见误区

1. **所有并行维度都开到最大**。TP 跨节点、PP 深度过大、DP 过碎，通信占比飙升，MFU 反而低于单机 DP。
2. **用 GPU util 判断效率**。util 100% 可能在空转等 NCCL；应看 MFU、tokens/s、通信 profile。
3. **ZeRO 与 TP/PP 叠加时世界大小语义混乱**。DP 组大小、TP×PP 是否占满节点要画 rank grid 再配，不能抄别人的 world_size。
4. **忽略激活显存只调 ZeRO stage**。长序列时激活是主因，需 FA + checkpoint + SP，而不是盲目 Stage3。
5. **多机训练不固定 NCCL 环境与拓扑**。IB/GDR 未启用、`NCCL_DEBUG` 从不看，一次静默降级到 TCP 就全盘变慢。
6. **checkpoint 只存分片权重的一部分就当全量备份**。恢复需要 FSDP/DCP/DeepSpeed 专用加载器与优化器状态。

## 八、面试题

**问题 1：3D 并行是哪三维？各自解决什么瓶颈？**  
要点：TP 切层内宽矩阵（单层放不下）；PP 切层（深度）；DP/ZeRO 切数据与状态（吞吐与优化器显存）。通信上 TP 要高带宽，PP 为流水 P2P，DP 为周期 AllReduce/RS。

**问题 2：ZeRO 三个 stage 分别分片什么？与 FSDP 的关系？**  
要点：S1 优化器状态，S2 加梯度，S3 加参数；FSDP 对应 S3 思路并集成参数 AllGather 生命周期。选 stage 看显存缺口与通信容忍度。

**问题 3：为什么 TP 一般限制在 8 卡节点内？**  
要点：TP 每层多次激活同步，延迟敏感；NVLink 带宽远高于跨节点以太网/普通 IB 互联，跨节点 TP 通信占比失控。

**问题 4：PP 的 bubble 如何压？代价是什么？**  
要点：增 microbatch、1F1B 等调度、异步 pipeline；代价是激活显存随 microbatch 增加，可能需 recompute；microbatch 太少则气泡比例高。

**问题 5：DDP 梯度累积为何常用 no_sync？**  
要点：累积步内梯度在本地累加，仅在最后一步 AllReduce，减少通信次数；需注意 loss 按累积数缩放与 LR schedule。

**问题 6：大模型训练 MFU 低，排查顺序？**  
要点：profile 算子与通信占比 → 查数据加载（dataloader 饿死）→ 查 NCCL 是否降级路径 → 查 TP/PP 配置与序列长度 packing → 再考虑算法级（Flash、checkpoint 策略）与精度（bf16/fp8）。

## 九、演进与趋势

1. **纯 DDP 时代**：模型 ≤ 单卡显存；瓶颈在数据加载与网络 AllReduce。
2. **模型并行兴起（Megatron）**：TP+PP 支撑 100B 级 GPT 训练，工程范式定型。
3. **ZeRO/FSDP（2020–）**：把“状态显存”从每卡剥离，DP 语义下训更大模型。
4. **通信-计算重叠与 3D 组合成熟**：1F1B、异步 pipeline、overlap 调度成为标配。
5. **超长序列与 SP/Ring**：上下文 128k–1M+，序列并行与 Flash 深度绑定。
6. **低精度与新硬件**：BF16 → FP8 训练、更紧的 kernel 与互联（NVLink domain 驱动 TP 布局）；弹性多租与云上拓扑感知调度。
7. **系统收敛**：Megatron-DeepSpeed、torchrun+FSDP、各家 end-to-end 配方把并行配置沉淀为“推荐拓扑表”。

## 十、小结

分布式训练总览的主线是：**用 DP/ZeRO 解决“装得下与扩吞吐”，用 TP/PP 解决“单层/单模型放不下”，用 SP/Ring 解决“序列过长”**，再用 3D 拓扑把通信限制在正确层级。选型先画 rank grid 与显存账（参数/状态/激活），再按互联带宽决定 TP 半径与 PP stage 数，用 MFU 而非 GPU util 验收。通信原语（AllReduce、AllGather、ReduceScatter、P2P）是贯穿一切的物理约束——并行策略的优劣，最终都体现在 profile 里通信与计算的重叠质量上。
