# 训练框架选型

> 对应 NVIDIA Megatron-LM、Microsoft DeepSpeed、PyTorch FSDP 官方文档；综述参考 llm-course (mlabonne) 分布式训练章节。

## 一、背景与挑战

单个 GPU 的显存（常见 24GB/40GB/80GB）远小于训练大模型所需的「参数 + 梯度 + 优化器状态 + 激活值」总和。以混合精度训练为例，参数量为 $P$ 的模型，仅 Adam 优化器状态（fp32 主参数副本、一阶动量、二阶动量）就约占 $12P$ 字节，再加上梯度与激活值，7B 模型全量驻留即需数十 GB，70B 以上模型单卡完全无法容纳。因此必须借助并行与显存优化技术把内存与计算分摊到多卡/多机。

核心矛盾有三：(1) 显存墙——模型状态超出单卡；(2) 通信墙——并行度越高，卡间同步开销越大；(3) 计算墙——吞吐受限于 MFU（Model FLOPs Utilization）。选型本质是在「可训最大模型规模、显存占用、通信带宽需求、工程复杂度」之间权衡。

## 二、核心原理

- 数据并行（Data Parallelism, DP）：模型全量复制到每张卡，按 batch 切分数据，反向传播后 All-Reduce 汇总梯度。优点实现简单，缺点不降低单卡显存。
- ZeRO（Zero Redundancy Optimizer）：将优化器状态（ZeRO-1）、梯度（ZeRO-2）、参数（ZeRO-3）分片到各卡，显存由 $O(N)$ 降到接近 $O(1/N)$，是 DeepSpeed 与 FSDP 的底层机制。
- 张量并行（Tensor Parallelism, TP）：把单层权重矩阵按行/列切分到多卡，层内做 All-Reduce，要求高带宽（NVLink），适合单机多卡。
- 流水并行（Pipeline Parallelism, PP）：把网络按层切成若干 stage，用 micro-batch 与 1F1B 调度隐藏空泡（bubble）。
- 序列并行（Sequence Parallelism）：进一步把激活值沿序列维度切分，缓解长序列显存压力。

## 三、形式化与数学基础

混合精度下模型状态显存近似：

$$M_{state} \approx 2P\text{(参数 fp16)} + 2P\text{(梯度 fp16)} + 12P\text{(Adam fp32 状态)} = 16P$$

其中 $P$ 为参数量（fp16 参数占 $2P$ 字节）。ZeRO-3 将参数与优化器状态分片，单卡驻留约：

$$M_{per\_gpu} \approx \frac{16P}{N} + M_{act}$$

$N$ 为 GPU 数，$M_{act}$ 为激活值显存（与序列长度、batch、层数成正比）。TP 中矩阵乘按列切分权重 $A=[A_1,A_2]$，各卡计算 $Y_i = X A_i$ 后 All-Reduce 得到完整 $Y$；其通信主要发生在层内前向/反向各一次 All-Reduce，对带宽极其敏感。激活重计算（checkpointing）以算力换显存，使 $M_{act}$ 由 $O(L)$ 降为常数。

## 四、代码实现

FSDP 最简封装（PyTorch 原生）：

```python
from torch.distributed import init_process_group
from torch.distributed.fsdp import FSDP, MixedPrecision
import torch

init_process_group("nccl")
model = MyModel().cuda()
model = FSDP(model, mixed_precision=MixedPrecision(...))
# 训练循环与单卡一致，FSDP 在反向时自动 all-gather 参数、reduce-scatter 梯度
for batch in loader:
    loss = model(batch).loss
    loss.backward(); optimizer.step()
```

DeepSpeed 只需在 `ds_config.json` 中声明 `zero_optimization.stage=3` 即可启用分片，并以 `deepspeed train.py --deepspeed ds_config.json` 启动。Megatron-LM 则通过 `torchrun --nproc_per_node=8 pretrain_gpt.py --tensor-model-parallel-size 4 --pipeline-model-parallel-size 2` 启动 3D 并行。

## 五、与其他技术对比

| 框架 | 并行能力 | 显存优化 | 通信依赖 | 适合规模 |
|------|----------|----------|----------|----------|
| Megatron-LM | TP+PP+DP | 极致 | NVLink | 超大规模(百亿+) |
| DeepSpeed | ZeRO(1/2/3) | 强 | 以太网可 | 中大~超大 |
| PyTorch FSDP | 类 ZeRO-3 | 强 | 以太网可 | 中大规模 |
| Accelerate | 封装 DP/FSDP | 中 | 低 | 快速实验 |
| Colossal-AI | 多种并行 | 强 | 依赖 | 研究灵活 |

经验法则：中小规模（<13B，单机 8 卡）FSDP/DeepSpeed 足够；超大规模常采用 Megatron 的 TP/PP 配合 DeepSpeed ZeRO 做 3D 并行。通信量上，DP 每步 All-Reduce 梯度（2P），TP 每层两次 All-Reduce（与序列长度相关），PP 仅 stage 边界传输激活。

## 六、常见误区

- 把 TP 跨节点跑在以太网而非 NVLink 上，层内 All-Reduce 成为瓶颈。
- 忽视 PP 的空泡开销，micro-batch 过少导致设备利用率低。
- 认为 ZeRO-3 等同于 TP：二者通信模式与适用拓扑不同，ZeRO-3 偏重显存、TP 偏重计算切分。
- 用 naive DP 训大模型导致 OOM，未启用任何分片。
- 忽略激活重计算，长序列下激活显存爆掉。

- 何时选 Megatron 而非 FSDP？两者在通信拓扑上的根本差异是什么？

- TP 与 PP 各自适合什么硬件拓扑？能否组合？
- 为什么激活值重计算（activation checkpointing）能换显存？

## 九、演进与趋势

从 1D DP 到 3D 并行（DP+TP+PP），再到序列并行、上下文并行（Context Parallelism）切分长序列；FlashAttention 类算子大幅降低激活显存与计算量；ZeRO-Offload / CPU Offload 把优化器状态卸载到主机内存；MoE 带来专家并行的新型拓扑；新一代互联（NVLink Switch、InfiniBand）持续提升通信上限。框架层趋向统一（FSDP 与 DeepSpeed 能力收敛）。

## 十、小结

框架选型没有银弹：先看模型规模与硬件拓扑（单机 NVLink 还是多机以太网），中小规模优先 FSDP/DeepSpeed 降低工程成本，超大规模再用 Megatron 做 TP/PP 精细切分。显存、通信、计算三者权衡贯穿始终。
