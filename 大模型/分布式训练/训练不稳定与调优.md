# 训练不稳定与调优

> 对应 Kaplan et al. 2020（Scaling Laws）、大模型训练工程实践与 DeepSpeed/Megatron 调优经验。

## 一、背景与挑战

大规模预训练并非「开箱即收敛」。实践中常遇到：loss spike（突刺，单步 loss 暴涨）、NaN/Inf、收敛慢、下游任务差。这些问题在小数模型上罕见，在百亿/千亿模型上频繁出现，且与数据、初始化、学习率、数值精度强相关。调优的本质是「在稳定与效率间找平衡」：太保守收敛慢，太激进易崩。本文汇总高频不稳定现象及其对策。

## 二、核心原理

常见现象与对策：

- **Loss spike**：常由单条坏数据（格式错、标签错、极长样本）触发。对策：LR warmup + cosine decay 平滑前期、监测并跳过异常 step、清洗数据。
- **NaN/Inf**：多由数值溢出（FP16 未 scaling）、除零（layernorm 方差）、注意力 logits 过大。对策：用 BF16、梯度裁剪、稳定初始化、检查数据。
- **收敛慢**：学习率不当、batch 过小、数据噪声大。对策：warmup 后余弦退火、调到 Chinchilla 量级的 token 数。
- **注意力熵异常**：监控 attention 分布熵，过早坍缩或发散都是信号。

通用稳定手段：梯度裁剪（clip grad norm）、稳定初始化（如 scaled init）、BF16 优先、充分的 LR warmup、数据质量过滤（去重、去毒、去脏）。

## 三、形式化与数学基础

学习率 schedule（warmup + cosine decay）：

$$\eta_t = \begin{cases} \eta_{\max}\cdot \dfrac{t}{T_{\text{warm}}}, & t < T_{\text{warm}} \\[6pt] \eta_{\min} + \dfrac{1}{2}(\eta_{\max}-\eta_{\min})\Big(1+\cos\big(\pi\tfrac{t-T_{\text{warm}}}{T-T_{\text{warm}}}\big)\Big), & t\ge T_{\text{warm}} \end{cases}$$

梯度裁剪限制更新幅度，防爆炸：

$$g \leftarrow g \cdot \min\Big(1,\ \dfrac{c}{\|g\|_2}\Big)$$

其中 $c$ 为裁剪阈值（如 1.0）。loss spike 可建模为单步异常注入：若 $\mathcal{L}_t > \kappa\cdot\mathcal{L}_{t-1}$，则回退/跳过该 step。

## 四、代码实现

warmup + cosine 与梯度裁剪：

```python
import torch
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4)
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(
    optimizer, T_max=total_steps, eta_min=3e-5)
# 训练循环
loss.backward()

```

## 五、与其他技术对比

| 现象 | 常见根因 | 首要对策 |
|------|---------|---------|
| loss spike | 坏数据 | 跳过 step + 清洗 |
| NaN | 溢出/除零 | BF16 + 裁剪 |
| 收敛慢 | LR/batch | warmup + 调 batch |
| 熵异常 | 初始化/数据 | 监控 + 重初始化 |

## 六、常见误区

- 一遇 spike 就降全局 LR，实则多为单条坏数据，应定位而非整体降速。
- 忽视数据质量，把脏数据当「多样性」喂入。
- FP16 不 scaling 直接上大模型，NaN 频发。
- 不监控梯度范数/注意力熵，等问题已崩才发现。

## 九、演进与趋势

从「事后救火」走向「全程可观测 + 自动回滚」：实时监控 loss/梯度/RNG、异常自动跳过或回退 checkpoint；并探索更稳的优化器与初始化（如 Muon、改进 layernorm）以降低大规模训练门槛。

## 十、小结

训练不稳定多由坏数据、数值溢出、LR 不当引发。对策是「warmup + 余弦 + 梯度裁剪 + BF16 + 数据清洗 + 全程监控」，并把 spike 当作信号去定位而非整体降速。稳定是大规模训练的前提。
