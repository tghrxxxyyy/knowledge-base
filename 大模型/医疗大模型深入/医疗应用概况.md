# 医疗应用概况

> 对应 Singhal et al.「Large Language Models Encode Clinical Knowledge (Med-PaLM)」(2022/2023)、llm-course mlabonne 与医疗 LLM 综述。

## 一、背景与挑战

医疗是对准确性、安全性、合规性要求最高的 LLM 垂直领域之一：一次幻觉式用药建议或错误诊断可能危及生命安全，且涉及严格隐私法规。与此同时，医疗场景价值巨大——问诊辅助、文献问答、报告生成、临床决策支持可显著缓解医生负担。核心矛盾是：模型「看似专业」的输出与「必须可溯源、可追责」的临床要求之间的落差。

## 二、核心原理

医疗 LLM 通常经历：在医学语料（教科书、指南、论文、脱敏电子病历）上继续预训练或指令微调，使其掌握医学术语与推理；再叠加对齐（RLHF/DPO）降低有害与幻觉；最后通过循证 RAG 接入权威知识库，强制引用指南与文献。应用定位始终为「辅助」而非「替代」医生：提供候选、解释与证据，最终决策由具备资质的医师作出。

## 三、形式化与数学基础

医疗回答的质量可分解为事实准确率与证据可追溯性。设回答 $y$ 对应证据集合 $E$，定义证据对齐得分：

$$
\text{Cite}(y) = \frac{1}{|y|}\sum_{c \in y} \mathbb{1}[\exists e \in E,\, \text{supports}(e, c)]
$$

即回答中每个论断都有证据支撑的比例。结合事实准确率 $\text{Acc}(y)$ 与安全性 $S(y)$（无违规建议），整体效用：

$$
U(y) = \alpha\,\text{Acc}(y) + \beta\,\text{Cite}(y) + \gamma\,S(y)
$$

循证 RAG 通过检索 $E \leftarrow \text{Retriever}(q)$ 提升 $\text{Cite}$ 与 $\text{Acc}$。

## 四、代码实现

```python
def medical_assistant(query: str, med_rag, guidelines):
    # 循证检索，强制引用
    ctx = med_rag.retrieve(query, top_k=5, sources=guidelines)
    prompt = build_prompt(query, ctx, with_citation=True)
    answer = llm.generate(prompt)
    # 校验：每个论断须命中证据
    if citation_coverage(answer, ctx) < 0.8:
        answer += "\n⚠️ 部分结论缺乏证据，仅供参考，请咨询医师。"
    return answer
```

## 五、与其他技术对比

| 模型 | 医学深度 | 循证 | 适用 |
|------|----------|------|------|
| 通用 LLM | 浅 | 无 | 科普 |
| 医学微调 LLM | 深 | 弱 | 辅助 |
| 循证 RAG 医疗 | 深 | 强 | 临床辅助 |

通用模型缺乏医学深度与证据约束，医疗专用模型更专，但须以循证兜底。

## 六、常见误区

- 误区一：医疗模型可直接诊断。须医生把关，模型仅辅助。
- 误区二：流畅即正确。医学文本流畅不等于临床正确，须核对证据。
- 误区三：一次微调永久有效。医学知识更新快，需持续更新与 RAG。
- 误区四：忽略合规。隐私与算法备案是上线前提。

## 九、演进与趋势

从通用模型直接试用，到医学语料微调、再到循证 RAG + 多模态（影像/病理）+ Agent 工作流。趋势是「可解释、可追溯、可追责」的临床级系统，以及与电子病历深度集成的人机协同。

落地形态常见四类：导诊分诊、文献/指南问答、病历书写辅助、临床决策支持，决策支持最严苛需完整证据链。选型上中小机构多调用合规云 API 叠加私有 RAG，大型医院倾向本地化部署保数据不出域。无论哪种，可解释、可追溯、可撤回应作为产品默认能力而非事后补丁。

- 四类形态：分诊 / 问答 / 书写 / 决策支持。
- 部署选择：云 API+RAG 或院内本地化。
- 默认能力：可解释与可追溯内建。
- 证据链：决策支持须完整引用指南。
- 边界清晰：模型辅助、医师终判。

## 十、小结

医疗是 LLM 高价值且高风险的垂直领域，核心约束是准确性、循证与合规。有效路径是以医学微调打底、循证 RAG 兜底、明确「辅助不替代」定位，并守住隐私与责任边界。
