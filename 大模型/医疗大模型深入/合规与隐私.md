# 合规与隐私

> 对应《中华人民共和国个人信息保护法》《数据安全法》、HIPAA 与《人工智能医疗器械软件》等监管规范；技术见「医疗大模型深入/临床文本处理」。

## 一、背景与挑战

医疗数据属于最敏感的个人数据类别，受严格法规保护（国内《个人信息保护法》《数据安全法》、美国 HIPAA、欧洲 GDPR）。医疗 LLM 在训练、微调、推理、部署各环节都面临合规约束：数据须去标识化、访问须授权、处理须可审计、模型须备案。挑战在于：合规要求随地区与场景变化、隐私与效用需平衡、且「算法可解释、可追责」是监管硬性期待。

## 二、核心原理

合规工程围绕四条主线：（1）数据合规——采集前知情同意、去标识化（脱敏 PII 与准标识符）、最小化收集；（2）访问控制——基于角色的权限（RBAC）、零信任、数据不出可信域；（3）审计与追溯——全链路日志、模型决策可回放、算法备案；（4）部署合规——私有化/本地化部署满足「数据不出域」，并通过医疗器械或算法备案审查。医疗 AI 还常要求「训练数据可溯源、模型可解释」。

## 三、形式化与数学基础

去标识化可视为对记录 $r=(a_1,\dots,a_m)$ 的映射 $f$，使重识别风险低于阈值。设准标识符集合 $Q$，重识别概率：

$$
R(Q) = \max_{q \in Q} \Pr[\text{individual} \mid q]
$$

合规要求 $R(Q) \le \epsilon$（如 $\epsilon$ 对应「公开披露风险可接受」）。$k$-匿名则要求每个等价类至少含 $k$ 条记录：

$$
\forall\, \text{equiv-class } E,\quad |E| \ge k
$$

差分隐私进一步给出数学边界（见「数据泄露与隐私」章节）。

def access_control(user, action, trusted_zone):
    # 零信任：默认拒绝，显式授权
    if not user.authenticated:
        return deny("未认证")
    if action.risk == "high" and not user.has_role("physician"):
        return deny("无权限")
    if not in_trusted_zone(trusted_zone):
        return deny("数据不出域")
    audit_log(user, action)              # 全链路审计
    return allow(action)

def deploy_model_locally(model, zone):
    if zone.type != "trusted":
        raise ComplianceError("禁止在非可信域部署医疗模型")
    return serve(model, zone)

## 六、常见误区

- 误区一：去标识化即安全。准标识符重识别风险仍在，须 $k$-匿名等增强。
- 误区二：私有化部署即合规。还需访问控制、审计、备案配套。
- 误区三：合规是法务的事。技术层（脱敏、隔离、日志）是合规落地基础。
- 误区四：一次性合规。法规与模型持续变化，须常态化治理。

## 九、演进与趋势

从「无规可用」到「去标识化基线」，再到「全链路合规与算法治理」。趋势是隐私计算（联邦学习、安全多方计算）、可验证合规（自动审计）、以及跨境数据流动的标准化框架。

落地层面数据不出域常以专属云或院内私有化实现，模型微调也在可信域内完成；算法备案需提交数据来源、场景与风险说明。跨院协作可用联邦学习在不共享原始数据下联合建模，兼顾效用与合规。合规应嵌入 CI/CD 与上线评审作为常态治理，而非一次性认证。

- 私有化：院内可信域完成训练与推理。
- 联邦学习：跨院协作不共享原始数据。
- 常态化：合规进研发流水线评审。
- 算法备案：提交来源/场景/风险说明。
- 审计留痕：全链路决策可回放。

## 十、小结

合规与隐私是医疗 AI 上线的前提而非可选项。须以数据去标识化、访问控制、审计追溯与私有化部署构建全链路合规，并随法规持续治理，技术层是合规落地的真实支撑。
