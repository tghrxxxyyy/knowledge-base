# 工具调用与检索融合智能体

> 对应 Yao et al. 2022《ReAct》与 huggingface/transformers 的工具调用范式及 run-llama/llama_index。

## 一、背景与挑战
真实问答常需组合检索与计算：先查资料，再做数值推理或调用 API。单一检索器无法覆盖表格、代码、数据库等异质工具，需要统一的函数调用接口。

## 二、核心原理
把检索也视为一种工具 Tool[retrieve(query)]，与计算器、SQL、Python 执行器等并列。智能体在 Thought 中选择工具并填参，系统调度执行，Observation 回流。关键在统一工具描述（schema）与参数解析。

## 三、形式化与数学基础
工具集合 $\mathcal{T}=\{T_1,\dots,T_m\}$，智能体输出结构化动作：
$a_t = (T_i, \text{args}_t) \sim P_\theta(\cdot \mid x, \tau_{<t})$
执行得到 $o_t = T_i(\text{args}_t)$，轨迹似然为条件乘积，训练可用模仿或强化学习最大化成功奖励。

## 四、代码实现
```python
TOOLS = {"retrieve": retriever.search, "calc": eval, "sql": db.run}
def agent_step(llm, x, traj):
    act = llm.parse_action(llm(x, traj))  # 返回 {name, args}
    obs = TOOLS[act["name"]](act["args"])
    return act, obs
```

## 五、与其他技术对比
相比仅检索的 RAG，工具融合支持多源异构证据；相比固定 pipeline，它按需调用更省算力。难点在工具选择错误与参数幻觉。

## 六、常见误区
误区一：认为所有工具都应并行调用，其实有依赖必须串行。误区二：忽略工具副作用，写操作工具需权限与确认。

## 七、与开源书/权威来源对应
- Yao et al. 2022 定义 Thought/Action/Observation 循环。
- huggingface/transformers 提供 tool 调用与 agent 抽象。
- run-llama/llama_index 集成检索与多种工具。

## 九、演进与趋势
函数调用走向标准化（JSON schema、严格解析），并结合模型微调（如 InstructGPT 风格）提升调用准确率，形成可组合的工具生态。

## 十、小结
将检索抽象为一种工具，使智能体能在统一框架下组合异质能力，是 Agentic RAG 的工程核心。
