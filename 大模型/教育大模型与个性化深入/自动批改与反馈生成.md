# 自动批改与反馈生成

> 对应 Zheng 2023 的 LLM-as-judge 论文与 github EleutherAI/lm-evaluation-harness 项目。

## 一、背景与挑战
主观题与代码作业批改成本高。用大模型作评判，给出分数与针对性反馈，可大幅减负，但需控制一致性偏差。

## 二、核心原理
以 rubric 为基准，让裁判模型对被评答案逐项打分并输出理由。多裁判投票或参考答案为锚可降低随机性。

## 三、形式化与数学基础
裁判一致性可用加权 Cohen kappa：
$ \kappa = \frac{p_o - p_e}{1 - p_e} $
其中 $ p_o $ 为观测一致率，$ p_e $ 为期望一致率。

## 四、代码实现
```python
def judge(model, rubric, answer):
    prompt = '评分标准:\n' + rubric + '\n作答:\n' + answer + '\n逐项给分并说明:'
    return model.generate(prompt)

def aggregate(votes):
    # votes: list of int scores
    n = len(votes)
    mean = sum(votes) / max(n, 1)
    return mean, max(votes) - min(votes)
```

## 五、与其他技术对比
相比规则自动判分，LLM 批改覆盖开放题；相比人工，成本低但需防位置偏差与宽松倾向。

## 六、常见误区
把裁判分数当绝对真值。未提供 rubric 导致不稳定。
