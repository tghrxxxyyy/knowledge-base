# 多环境基准设计

> 对应 Liu et al., *AgentBench*, ICLR 2024（多环境评测）；Shridhar et al., *ALFWorld*, ICLR 2021。

## 一、背景与挑战

不同环境考察的能力维度差异极大：SQL 环境考精确性与语法，网页环境考长程导航与容错，家务模拟考常识与状态推演。
在单一环境上调优容易产生过拟合式结论，需要有意设计覆盖面与难度梯度。

## 二、核心原理

- 维度设计：动作空间大小、观测噪声、轨迹长度、是否可逆、反馈稀疏程度，构成能力坐标系。
- 难度分层：从单步工具调用到多步跨系统任务，保证不同水平模型都有区分度，避免全 0 或全满分。
- 可判定性：每个任务需要程序可判定的成功条件，尽量避免依赖模型评审的主观判定。

## 三、数学形式

若各环境成功率为 $p_e$，综合分常取加权平均 $\bar p=\sum_e w_e p_e$；权重需公开，否则排名不可解释。

环境区分度可用相邻能力档模型的分数差与噪声比 $\frac{p_A-p_B}{\text{SE}}$ 衡量，比值过小说明该环境无法区分。

## 四、代码实现

```python
ENVS = [("db", 0.2), ("web", 0.3), ("os", 0.2), ("game", 0.15), ("dialog", 0.15)]

def suite_score(agent):
    detail = {name: evaluate(agent, load_tasks(name))["success"] for name, _ in ENVS}
    overall = sum(detail[name] * w for name, w in ENVS)
    return {"overall": round(overall, 4), "detail": detail}
```

## 五、与其他对比

- 与单环境深评：单环境能细致刻画特定能力，但结论外推性差；多环境牺牲深度换覆盖。
- 与真实业务评测：真实业务最有说服力但不可公开复现，公开基准提供可比较的相对信号。

## 六、常见误区

- 环境全部同质（都是网页），综合分只是重复测量同一能力。
- 任务难度过于集中，导致强弱模型分数趋同，基准失去区分度。
- 权重不公开或随意调整，使综合排名可被操纵。

## 八、面试题

- 如何判断一个评测环境是否有价值？答：看它对不同能力档模型的区分度是否显著超过采样噪声，且能力维度不与既有环境重复。
- 综合分的隐患是什么？答：权重决定排名却常被忽视，应同时公开分环境明细并说明权重依据。

## 九、演进

单任务演示 → 单环境基准 → 多环境综合套件 → 分层难度与区分度分析 → 面向业务规则的领域基准。

## 十、小结

多环境基准的设计核心是覆盖不同能力维度并保持区分度，综合分必须配合分项明细解读。
