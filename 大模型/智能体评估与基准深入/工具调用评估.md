# 工具调用评估

> 对应 Qin et al., *ToolLLM/ToolBench*, ICLR 2024；Patil et al., *Gorilla*, 2023（API 调用正确性评估）。

## 一、背景与挑战

工具调用的正确性有多个层次：选对工具、填对参数、顺序正确、最终答案正确，任一层出错都会失败但原因不同。
只报最终成功率无法指导优化，需要分层指标定位瓶颈。

## 二、核心原理

- 分层指标：工具选择准确率、参数结构合法率、参数语义正确率、调用序列匹配度、端到端任务成功率。
- 参数评估方式：结构用 Schema 校验，语义用规范化后与参考值比较（大小写、单位、日期格式先归一）。
- 序列评估：允许等价重排（独立调用顺序不影响结果），用集合或图匹配而非严格字符串相等。

## 三、数学形式

调用选择可用宏平均 F1：$F1=\frac{2PR}{P+R}$，避免高频工具主导指标。

序列相似可用归一化编辑距离 $1-\frac{\text{lev}(\hat a, a^*)}{\max(|\hat a|,|a^*|)}$，或在 DAG 上比较可达关系以容许并行重排。

## 四、代码实现

```python
def score_calls(pred, gold):
    sel = f1([c.name for c in pred], [c.name for c in gold])
    struct = mean(validate_ok(c) for c in pred)
    sem = mean(norm_args(p.args) == norm_args(g.args)
               for p, g in zip(pred, gold) if p.name == g.name)
    seq = 1 - lev([c.name for c in pred], [c.name for c in gold]) / max(len(pred), len(gold))
    return {"select_f1": sel, "schema_ok": struct, "args_exact": sem, "seq_sim": seq}
```

## 五、与其他对比

- 与端到端成功率：端到端是最终目标但归因能力弱；分层指标能定位是选择、填参还是顺序问题。
- 与人工评审：人工可判断「另一种合理解法」，自动匹配容易惩罚等价但不同的正确路径。

## 六、常见误区

- 用严格字符串比较参数，把等价表达（2024-01-01 与 2024/1/1）判为错误。
- 强制单一参考调用序列，惩罚合理的并行或替代路径。
- 只在单轮上评估，忽略多步依赖场景中前序失败导致的连锁错误。

## 八、面试题

- 为什么工具调用要分层评估？答：不同层次的错误对应不同优化手段（描述、Schema、示例、规划），合并指标无法归因。
- 如何避免误判等价调用？答：参数先做规范化，序列用集合或 DAG 可达性比较，允许等价重排与替代路径。

## 九、演进

端到端成功率 → 调用名匹配 → 分层结构与语义指标 → 允许等价路径的序列评估 → 结合真实执行结果的评测。

## 十、小结

工具调用评估要分层且宽容于等价解：既能归因具体环节，又不惩罚合理的替代路径。
