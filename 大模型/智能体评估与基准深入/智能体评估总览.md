# 智能体评估与基准总览

> 对应 Liu et al., *AgentBench*, ICLR 2024；Zhou et al., *WebArena*, ICLR 2024；Yao et al., *tau-bench*, 2024。

## 一、背景与挑战

静态问答指标无法反映智能体能力：同一模型在多步交互中可能因为一次动作失误而全盘失败。
智能体评估需要可交互环境、可判定的任务成功条件、以及对成本与稳定性的度量，复杂度远高于单轮基准。

## 二、核心原理

- 三层指标：结果层（任务成功率）、过程层（轨迹合规、冗余步数、非法动作率）、成本层（token、调用次数、时延）。
- 多环境覆盖：不同环境考察不同能力（数据库操作、网页浏览、系统命令、多轮对话遵从），单一环境结论不可外推。
- 方差控制：智能体输出随机性大，需多次重复取均值并报告置信区间与失败模式分布。

## 三、数学形式

成功率的二项不确定性为 $\text{SE}=\sqrt{\hat p(1-\hat p)/N}$，$N$ 为任务数；小样本基准上数点差异常在噪声内。

多次采样能力用 pass@k：$\text{pass@}k=\mathbb E\big[1-\binom{n-c}{k}/\binom{n}{k}\big]$，区分「能做到」与「稳定做到」。

## 四、代码实现

```python
def evaluate(agent, tasks, repeats=3):
    rec = []
    for t in tasks:
        for _ in range(repeats):
            tr = run_episode(agent, t.env, t.goal, max_steps=t.budget)
            rec.append({"ok": t.judge(tr), "steps": len(tr.actions),
                        "illegal": tr.illegal, "tokens": tr.tokens})
    p = sum(r["ok"] for r in rec) / len(rec)
    se = (p * (1 - p) / len(rec)) ** 0.5
    return {"success": p, "se": se,
            "avg_steps": mean(r["steps"] for r in rec),
            "avg_tokens": mean(r["tokens"] for r in rec)}
```

## 五、与其他对比

- 与静态基准（知识问答）：静态基准可批量自动评分但无法反映交互与工具使用能力。
- 与人工体验评测：人工能覆盖开放任务与主观质量，但成本高、可复现性差，宜与自动评测互补。

## 六、常见误区

- 单次运行就下结论：智能体方差大，单次结果不可靠。
- 只报成功率不报成本，忽略「用十倍 token 换两个点」的不经济方案。
- 不设步数与预算上限，导致失败任务无限耗时且指标不可比。

## 八、面试题

- 智能体评估为什么必须多次重复？答：交互过程随机性叠加导致方差大，单次结果的差异常被采样噪声主导。
- 除成功率还应报告什么？答：过程指标（步数、非法动作、循环率）与成本指标（token、调用、时延），以及失败模式分布。

## 九、演进

静态问答 → 单环境交互任务 → 多环境综合基准（AgentBench）→ 真实网页与业务规则环境（WebArena、tau-bench）→ 含成本与稳定性的综合评价。

## 十、小结

智能体评估要同时回答「能不能做到、稳不稳定、贵不贵」，缺一项的结论都不足以指导选型。
