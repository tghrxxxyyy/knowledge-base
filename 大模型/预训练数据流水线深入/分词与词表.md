# 分词与词表构建

> 对应 Sennrich et al., *BPE*, 2015；GPT-2/LLaMA 分词实践。

## 一、背景与挑战

分词决定 token 效率与跨语言公平；不良词表增算耗、损多语表现。

## 二、核心原理

BPE/Unigram 在语料上合并高频子词构建词表；词表大小权衡：大词表降序列长但增嵌入参；需覆盖多语与代码。

## 三、数学形式

序列长度 $L\approx |S|/(\text{avg token chars})$；词表 $V$ 增则嵌入参 $O(V\cdot d)$ 线性增。

## 四、代码实现

```python
from tokenizers import ByteLevelBPETokenizer
tok = ByteLevelBPETokenizer()
tok.train(files, vocab_size=32000)
ids = tok.encode("Hello 世界").ids
```

## 五、与其他对比

- 与 流式生成与增量解码深入（token 流）直接耦合。
- 与 多模态预训练深入（文本编码器）共享。

## 六、常见误区

- 词表过小致序列过长、推理贵。
- 训练/推理分词器不一致致错位。

## 八、面试题

- 为何用 BPE？答：以子词兼顾词表规模与未登录词，平衡压缩率与灵活性。

## 九、演进

Word → BPE → Unigram/SentencePiece → 字节级。

## 十、小结

分词是预训练与推理的接口，词表设计影响成本与多语公平。
