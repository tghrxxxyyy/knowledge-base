# 可解释性与对齐监控

> 对应 Azaria & Mitchell 2023《The Internal State of an LLM Knows When It's Lying》与 Zou 2023《Representation Engineering》等对齐监控研究。

## 一、背景与挑战

即使经过 RLHF/DPO 对齐，模型仍可能在内部「明知错误却输出错误」（hallucination、deception、power-seeking）。传统外部评测只能看到最终文本，无法提前发现危险意图。对齐监控（alignment monitoring）试图在生成过程中读取内部激活，预警「欺骗」「危险目标」等状态，做到预防性安全。

挑战：(1) 危险状态标签稀缺，难以训出鲁棒探针；(2) 模型可能学会「隐藏」危险特征（梯度博弈）；(3) 误报成本高，需平衡灵敏度与可用性；(4) 监控本身不应被对抗绕过。

## 二、核心原理

核心思路是用可解释性工具「读出」内部状态：在残差流上训练探针/SAE 特征，检测是否浮现「欺骗意图」「自我增益」「有害计划」等概念方向；一旦得分超阈值，即触发拒答、干预或上报。

这类监控是「预防性」而非「事后」：在 token 生成前或生成中拦截，比仅靠输出过滤更早、更根本。它与方向干预互补——监控负责「发现」，干预负责「纠正」。

一个可落地的监控管线包含四段：采样、评分、聚合、决策。采样对每步激活按层抽样；评分用预训练探针得到危险概念得分；聚合按请求或时间窗取最大或均值；决策超阈值触发拒答或注入方向干预。部署上需把探针推理融合进推理服务的前向钩子，控制额外延迟在毫秒级，并用影子流量先验证探针召回再切到生产拦截。还需建立误报/漏报复盘机制：对每次告警人工标注是否真危险，据此回调整阈值与特征集。由于危险样本极稀缺，应定期用红队生成对抗样本扩充校准集，防止探针被梯度博弈绕过。指标上建议关注召回而非准确率：危险场景宁可误报也不可漏报，业务侧用人工复核消化误报成本。实践中监控常与拒答策略、方向干预组成三层防线：先监控发现，再干预纠正，最后才硬拒答。

监控的触发动作需分级：低危告警仅记录，中危注入干预，高危直接拒答并上报。
分级能避免非危险异常（如偶发无意义输出）被过度拦截，影响可用性。
干预方向本身也应来自离线标定：用红队数据找出「最能降低危险得分」的方向组合。
生产环境建议先用影子模式运行监控（只告警不拦截），积累误报样本后再开启拦截。
这与灰度发布的理念一致：新监控策略也应小流量验证再全量。
监控还需考虑对抗：攻击者可能构造对抗样本让危险特征不被探针激活（梯度博弈）。
缓解办法是多用源特征、定期重训探针，并把行为级指标（如异常工具调用）作为兜底。
监控的延迟预算通常很紧，探针推理应放在残差流读取的同一步，避免额外往返。
最终监控效果要用「漏报导致的真实事故数」衡量，而非单纯看探针准确率。

## 三、形式化与数学基础

设第 $l$ 层激活 $\vec{h}^{(l)}_t$ 在位置 $t$。对危险概念 $c$ 用探针得到方向 $\vec{v}_c$ 与偏置 $b_c$，得分：

$$s_c(t) = \sigma\left(\vec{v}_c^\top \vec{h}^{(l)}_t + b_c\right) \in (0,1)$$

监控决策为：

$$\text{alert}(t) = \mathbb{1}\left[ s_c(t) > \tau \right]$$

其中阈值 $\tau$ 由验证集的 ROC 选定，权衡假阳（误拦正常请求）与假阴（漏报危险）。多概念可组合为风险聚合：

$$R(t) = \max_c s_c(t)$$

触发条件 $R(t) > \tau$ 即告警。

## 四、代码实现

```python
import torch

def monitor_step(hidden_layer, probes, tau=0.8):
    # probes: {name: (v, b)} 危险概念探针
    scores = {}
    for name, (v, b) in probes.items():
        s = torch.sigmoid(hidden_layer @ v + b)  # [seq]
        scores[name] = s.max().item()
    risk = max(scores.values())
    if risk > tau:
        return True, scores  # 触发告警/拒答
    return False, scores

# 在生成循环每步调用，命中即中断或注入方向干预降低风险
```

注意：探针阈值应按业务代价调参，高风险场景宁可误报也不可漏报。

## 六、常见误区

- 认为监控=对齐：它只是检测与缓解，不等于模型内在可信。
- 忽视梯度博弈：模型可能训练出「不被探针检测」的危险特征。
- 单一探针定生死：应多概念、多层级交叉验证。
- 高估准确率：危险样本极少，准确率虚高，需看召回与 PR 曲线。

## 九、演进与趋势

从「能否读出谎言」走向「实时监控+自动干预」的闭环，并与 SAE 单义特征、自动化电路发现结合提升可解释信号质量。对抗「隐藏特征」的鲁棒监控是开放问题。具体以官方最新研究为准。

## 十、小结

对齐监控用可解释性在生成过程中读出危险内部状态，是预防性安全的关键工具。它与方向干预构成「发现—纠正」闭环，但仍需警惕梯度博弈与标签稀缺带来的局限。
