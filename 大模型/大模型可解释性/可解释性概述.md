# 大模型可解释性概述

> 对应 Elhage et al. 2021《A Mathematical Framework for Transformer Circuits》与 Anthropic《Transformer Circuits》系列研究。

## 一、背景与挑战

LLM 参数动辄百亿千亿，前向过程是不可直接解读的高维非线性变换。模型「为什么」输出某答案、内部是否藏有欺骗或危险意图，传统评测无法回答。机制可解释性（mechanistic interpretability）试图逆向工程模型，把「权重」翻译成「可理解的算法/电路」，目标是像读懂程序一样读懂网络。

挑战：(1) 规模与维度灾难；(2) 非线性与叠加（superposition）使单义特征难以直接观测；(3) 因果验证困难——相关性不等于因果；(4) 工程与理论的鸿沟。

## 二、核心原理

机制可解释性沿三条主线：(1) 线性表示假设——概念近似对应向量方向；(2) 电路（circuit）分析——定位实现具体计算的小子图，如 induction heads 实现复制、copy-suppression 抑制重复；(3) 特征解构——用稀疏自编码器（SAE）把叠加的多义神经元拆成大量单义特征。

分析范式通常是：先确定「行为」（如某任务失败），再用激活修补（activation patching）找出关键层/头，最后用探针或 SAE 解释其表示的语义。残差流被视为信息主通道，各组件通过它读写。

在实践中，机制可解释性的工作流通常分四步，构成标准闭环。第一，用数据集构造「行为探针」任务，如判断模型是否在复制 token、是否输出真值。第二，用激活修补或因果中介定位对该行为贡献最大的层与头。第三，在定位到的位置训练线性探针或拟合 SAE 特征，把高激活维度映射回人类可读语义。第四，用干预（激活加法或特征置零）验证因果性，确认改这个方向真的改变行为。这四条是后续对齐监控的工具基础，缺一不可。值得注意的是，可解释性对象既含局部电路（induction heads、copy-suppression），也含全局现象（如 grokking、phase change）。前者回答某一能力如何实现，后者回答能力何时、为何涌现。两者都需要上述因果闭环，而不能停留在相关性层面。

从工程视角看，可解释性不是一次性分析，而是持续的能力建设。
团队应维护一份「电路目录」，记录已定位的 head/特征及其触发条件，供后续审计复用。
当模型升级时，旧目录可能失效，需用激活修补重新验证，而非直接沿用。
可解释性还服务于模型编辑：定位到负责某偏见的 direction 后，可用方向干预在推理期抑制它。
这与对齐监控共享底层探针，区别在于前者用于理解、后者用于防护。
教学上常用「toy model」先验证方法，再迁移到大模型，降低试错成本。
公开的特征可视化（如特征字典浏览器）能帮助人工标注 SAE 特征语义。
可解释性结论应写入模型卡（model card），作为发布前的透明度材料。
最后，任何可解释性发现都应标注置信度，因为因果验证本身有统计前提。

## 三、形式化与数学基础

把 transformer 看作在残差流 $\vec{h}$ 上依次叠加注意力与 MLP 分支：

$$\vec{h}^{(l+1)} = \vec{h}^{(l)} + \mathrm{Attn}^{(l)}(\vec{h}^{(l)}) + \mathrm{MLP}^{(l)}(\vec{h}^{(l)})$$

注意力头 $h$ 对位置 $i$ 的贡献可写为对 value 的加权：

$$\mathrm{head}_h(\vec{h})_i = \sum_{j} A_{ij}^{(h)} W_V^{(h)} \vec{h}_j, \quad A_{ij}^{(h)} = \mathrm{softmax}_j\left(\frac{(W_Q^{(h)}\vec{h}_i)^\top (W_K^{(h)}\vec{h}_j)}{\sqrt{d_k}}\right)$$

叠加假设下，模型用 $n \ll d$ 个特征方向以近似正交方式「压缩」进 $d$ 维空间，导致单个神经元多义。SAE 试图学习字典 $\hat{\vec{h}} = \sum_k f_k \vec{b}_k$，其中 $f_k$ 稀疏。

## 四、代码实现

用激活修补定位某行为的关键层：在干净（正确）与损坏（破坏）输入间交换中间激活，观察输出恢复程度。

```python
import torch

def activation_patching(model, clean, corrupted, layer_idx):
    # 取 corrupted 前向，但在 layer_idx 处替换成 clean 的激活
    cache = {}
    def hook(mod, inp, out):
        cache['h'] = out
    handle = model.layers[layer_idx].register_forward_hook(hook)
    with torch.no_grad():
        model(corrupted)
        h_clean_layer = run_clean_collect(clean, layer_idx)
    handle.remove()
    # 将 corrupted 在该层激活替换为 h_clean_layer 后继续前向
    patched_logits = run_with_injected(model, layer_idx, h_clean_layer, corrupted)
    return patched_logits

# 恢复率 = (patched_score - corrupted_score) / (clean_score - corrupted_score)
```

## 五、与其他技术对比

| 路线 | 目标 | 方法 | 是否需训练 |
|------|------|------|-----------|
| 机制可解释性 | 理解内部算法 | 电路/探针/SAE | 部分 |
| 特征归因(注意力/LIME) | 输入重要性 | 梯度/注意力 | 否 |
| 探针 | 读概念方向 | 线性分类 | 是 |
| 红队/行为测试 | 外部行为 | 提示攻击 | 否 |

## 六、常见误区

- 把注意力权重当「解释」：注意力≠归因，权重高不代表信息真正流通。
- 混淆相关与因果：高探针准确率不等于该方向驱动行为。
- 忽视叠加：直接看神经元会误判，需用 SAE 解耦。
- 认为可解释性=可视化：单张图无法刻画全局电路。

## 九、演进与趋势

从单头功能到全局电路，从神经元到 SAE 单义特征，从「解释已训练模型」到「可解释性指导训练（如稀疏化、监控）」。自动化可解释性（用模型解释模型）与对齐监控是热点。具体进展以官方最新论文为准。

## 十、小结

机制可解释性把黑箱权重翻译为可读电路，是安全、可控、调试的基础科学。其核心是线性表示、电路分析与特征解构三件套，并始终需用因果验证把关。
