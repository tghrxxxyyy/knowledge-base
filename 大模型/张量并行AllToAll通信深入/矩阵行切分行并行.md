# 矩阵行切分行并行

> 对应 Shoeybi 2019 Megatron-LM 与 Vaswani 2017 Attention Is All You Need 的矩阵形式。

## 一、背景与挑战

行并行（Row Parallelism）是张量并行的另一半：它把权重矩阵按**行**分块，输入相应按列分块，每张卡计算一个**部分和**。它通常作为 MLP 的第二层或注意力输出投影层，因为此时输入恰好是上一层列并行产出的按列切分结果，可以直接消费而不需要额外的重排。

难点在于理解它的输出语义：行并行得到的是部分和，必须通过 all-reduce 求和才等价于完整结果。这一点与列并行「输出按列切分、无需通信」形成对照，也是初学者最容易搞错的地方。

## 二、核心原理

设线性变换 $Y = XA$，其中 $X \in \mathbb{R}^{b \times h}$、$A \in \mathbb{R}^{h \times d}$。把 $A$ 按行分块、$X$ 按列分块：

$$ A = \begin{bmatrix} A_1 \\ A_2 \\ \vdots \\ A_p \end{bmatrix}, \qquad X = \begin{bmatrix} X_1 & X_2 & \cdots & X_p \end{bmatrix} $$

每张卡 $i$ 持有 $A_i \in \mathbb{R}^{h/p \times d}$ 与 $X_i \in \mathbb{R}^{b \times h/p}$，计算：

$$ Y_i = X_i A_i \in \mathbb{R}^{b \times d} $$

由于矩阵乘对行/列的分解性质：

$$ XA = \sum_{i=1}^{p} X_i A_i = \sum_{i=1}^{p} Y_i $$

因此必须对 $\{Y_i\}$ 做 all-reduce 求和，才能得到完整输出 $Y$。

**与列并行的配对**：列并行层的输出天然是按列切分的（即 $X_1,\dots,X_p$ 的分布），正好是行并行所需的输入布局。二者配对后，两个 GEMM 之间**零通信**，只在行并行输出处做一次 all-reduce。

## 三、形式化与数学基础

行并行的等价性：

$$ Y = X A = \begin{bmatrix} X_1 & \cdots & X_p \end{bmatrix} \begin{bmatrix} A_1 \\ \vdots \\ A_p \end{bmatrix} = \sum_{i=1}^{p} X_i A_i $$

维度核对：$X_i A_i$ 的形状为 $(b \times h/p)(h/p \times d) = (b \times d)$，是完整输出形状，因此是**求和**而非拼接。这一点务必与列并行区分。

通信量：all-reduce 每个元素发送约 2 倍元素大小，故单次行并行输出的通信量为

$$ C_{row} = 2 \, b \, d \, w $$

其中 $w$ 为每元素字节。若下游继续行并行，则重复该通信；若下游是列并行，则无需通信。

整除约束：输入维 $h$ 必须被并行度 $p$ 整除。

## 四、代码实现

```python
import torch
import torch.distributed as dist

class RowParallelLinear(torch.nn.Module):
    # 权重按行切分：本卡持有 in_features/world 列
    def __init__(self, in_features, out_features, world, bias=True):
        super().__init__()
        self.world = world
        self.weight = torch.nn.Parameter(
            torch.empty(out_features, in_features // world)
        )
        self.bias = torch.nn.Parameter(torch.zeros(out_features)) if bias else None

    def forward(self, x):
        # x 已按列切分到本卡（来自上一个列并行层）
        y_local = torch.nn.functional.linear(x, self.weight, None)

        # 部分和 -> all-reduce 求和得到完整输出
        if self.world > 1:
            dist.all_reduce(y_local, op=dist.ReduceOp.SUM)

        if self.bias is not None:
            y_local = y_local + self.bias     # 偏置只需加一次
        return y_local

# 配对用法：ColumnParallelLinear -> GeLU -> RowParallelLinear
# 两个 GEMM 之间无通信，仅行并行输出处一次 all-reduce
```

偏置必须放在 all-reduce **之后**加一次，否则会被重复累加 $p$ 次。

## 五、与其他技术对比

| 维度 | 行并行 | 列并行 |
| --- | --- | --- |
| 切分对象 | 权重按行（输入维） | 权重按列（输出维） |
| 输入要求 | 已按列切分 | 完整复制 |
| 输出形态 | 完整（经 all-reduce） | 按列切分 |
| 中间通信 | 输出处 all-reduce | 无 |
| 偏置处理 | 求和后加一次 | 本地直接加 |
| 典型位置 | MLP/注意力第二层 | MLP/注意力第一层 |

## 六、常见误区

- 认为行并行总无通信：只有在输入已按列切分时 GEMM 才局部；得到完整输出仍需 all-reduce。
- 把部分和当成拼接：$Y = \sum Y_i$ 而非 $\mathrm{Concat}$，这是最常见的数学错误。
- 切分维度不对齐：必须与上游列并行配对，否则需先 all-gather。
- 偏置加在 all-reduce 之前：会被加 $p$ 次，结果偏大。
- 认为行并行改变数值：在无限精度下严格等价，有限精度只有舍入差异。

## 七、与开源书·权威来源对应

Shoeybi 2019 Megatron-LM 定义了行/列并行的配对与通信分析；Vaswani 2017 提供了注意力与 MLP 的矩阵形式，是理解切分等价性的基础。具体实现以官方最新文档为准。

## 八、面试题

- 问：行并行何时零通信？答：输入已按列切分且权重按行切分时，GEMM 完全局部；但输出仍需 all-reduce。
- 问：行并行输出如何合并？答：各卡的 $Y_i$ 求和（all-reduce SUM）。
- 问：与列并行如何配对？答：列并行产出按列切分的输入，供行并行直接消费。
- 问：偏置为何在 all-reduce 后加？答：避免被重复累加。

## 九、演进与趋势

行并行与序列并行、专家并行组合以支撑更大模型；FP8 GEMM 与通信压缩降低切分后单卡算力与带宽压力；计算-通信重叠进一步隐藏 all-reduce 开销。具体方案以官方最新文档为准。

## 十、小结

行并行是张量并行基本单元，与列并行配对可实现 MLP 的无通信切分。核心要点：**输入按列切、权重按行切、输出求和、偏置后加**。理解 $Y = \sum_i Y_i$ 而非拼接，就抓住了行并行的本质。
