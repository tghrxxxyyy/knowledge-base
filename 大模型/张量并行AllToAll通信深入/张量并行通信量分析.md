# 张量并行通信量分析

> 对应 Shoeybi 2019 (Megatron-LM) 与 Narayanan 2021 通信建模。

## 一、背景与挑战
评估 TP 是否划算需量化通信量。TP 每层有 all-reduce(行并行输出)与潜在 all-to-all(序列并行)，随层数累积。

## 二、核心原理
每个 transformer 层 TP 通信主要来自输出投影后的 all-reduce，量约 $2\\Psi_{\\mathrm{layer}}$(一次 reduce 双向)。节点内 NVLink 带宽高可隐藏，节点间 IB 则成瓶颈。

## 三、形式化与数学基础
每层 all-reduce 数据量：
$ C_{\\mathrm{layer}} = 2 b s h $ (b 批, s 序列, h 隐藏)，
总 $C_{\\mathrm{TP}} = L \\cdot 2 b s h$。对比 PP 仅传激活 $b s h$，TP 通信量显著更大但延迟低。

## 四、代码实现
```python
# 估算单步 TP 通信字节
def tp_comm_bytes(L, b, s, h, dtype_bytes=2):
    return L * 2 * b * s * h * dtype_bytes   # all-reduce 每元素两次
# 节点内 NVLink ~300GB/s 可掩盖，节点间 IB ~50GB/s 需谨慎
```

## 五、与其他技术对比
TP 通信最频繁但带宽需求高、延迟敏感；PP 通信少但有时延气泡；ZeRO 通信量介于二者且跨节点友好。故 TP 宜节点内。

## 六、常见误区
误区一：TP 通信量小——逐层 all-reduce 累积很大。误区二：TP 跨节点可行——IB 带宽不足。误区三：通信与序列长度无关，实际 $C\\propto s$。

## 七、与开源书/权威来源对应
Shoeybi 2019 通信对比；Narayanan 2021 给出 3D 并行带宽模型。

## 八、面试题
问：TP 每层通信量？答：约 $2bsh$ 的 all-reduce。问：为何 TP 限节点内？答：逐层通信对延迟极敏感。

## 九、演进与趋势
通信-计算重叠内核、fp8 通信压缩降低 TP 带宽压力。

## 十、小结
TP 通信密集且延迟敏感，应置于节点内高带宽域，与 PP/ZeRO 分层部署。
