# 冷启动与预热

> 对应大模型加载与预热；与 量化推理引擎深入（降加载）衔接。

## 一、背景与挑战

加载权重（尤其 FP16/量化）与编译图耗时秒级，冷启动拖垮首请求。

## 二、核心原理

最小副本常驻；新副本启动先预热（跑一次 dummy 前向）；用低秩/量化减加载；就绪探针防未热流量。

## 三、数学形式

冷启动时延 $C = T_{load} + T_{compile} + T_{warmup}$；需 $C\ll$ 伸缩间隔。

## 四、代码实现

```python
model.warmup(dummy_input)   # 启动后置就绪
readiness_probe(ok=warm_done)
```

## 五、与其他对比

- 与 量化推理引擎深入（量化降 $T_{load}$）互补；
- 与 模型编译深入（编译冷启动）相关。

## 六、常见误区

- 未预热即接流致首请求超时；
- 最小副本为 0 致长冷启动。

## 七、与开源书对应

- llm-course：https://github.com/mlabonne/llm-course
- datawhalechina/llm-universe：https://github.com/datawhalechina/llm-universe

## 八、面试题

- 如何降冷启动？答：量化减加载、常驻最小副本、启动预热与就绪探针。

## 九、演进

每次加载 → 预热池 → 快照恢复。

## 十、小结

冷启动靠常驻+预热+轻量加载缓解，是弹性前提。
