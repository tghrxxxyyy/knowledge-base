# 多模型路由与弹性

> 对应多模型网关与路由；与 推理服务可观测性深入 衔接。

## 一、背景与挑战

多模型共享 GPU 池，需路由与按模型分别伸缩，避免碎片。

## 二、核心原理

网关按模型/版本路由；按模型独立指标伸缩；用多租户调度或 MPS/MIG 切分 GPU 提利用率。

## 三、数学形式

池占用 $U=\sum_m \frac{R_m\cdot c_m}{G}$；路由使各模型负载均衡且保 SLO。

## 四、代码实现

```python
route(req, model) -> pick(healthy_replicas[model])
```

## 五、与其他对比

- 与 预填充解码分离深入（同池异构）思路相通；
- 与 弹性推理自动伸缩总览 是上层。

## 六、常见误区

- 固定分池致碎片；
- 路由未考虑副本热度。

## 八、面试题

- 多模型如何弹性？答：按模型独立指标伸缩，并用切分/路由提池利用率。

## 九、演进

单模型 → 分池 → 共享池+路由。

## 十、小结

多模型弹性靠路由与切片，平衡碎片与 SLO。
