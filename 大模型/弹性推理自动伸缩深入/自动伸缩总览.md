# 弹性推理自动伸缩总览

> 对应 K8s HPA/KEDA 与 LLM 服务弹性；与 推理服务可观测性深入 衔接。

## 一、背景与挑战

LLM 推理显存贵、负载波动大；固定副本浪费、不足则 SLO 违约，需弹性。

## 二、核心原理

按指标（并发/队列/KV 占用/吞吐）扩缩副本数；LLM 特有显存常驻与冷启动，需预热与最小副本。

## 三、数学形式

目标副本 $R=\lceil \frac{\text{load}}{\text{capacity\_per\_replica}} \rceil$；受 max/min 约束。

## 四、代码实现

```python
desired = ceil(qps / cap_per_replica)
scale_to(clamp(desired, min_r, max_r))
```

## 五、与其他对比

- 与 预填充解码分离深入（两池分别伸缩）协同；
- 与 推理服务可观测性深入（指标源）闭环。

## 六、常见误区

- 仅按 QPS 忽略 KV/显存占用；
- 缩容过激杀长请求。

## 八、面试题

- LLM 弹性为何难？答：显存常驻、冷启动慢、负载指标需含 KV 占用。

## 九、演进

固定副本 → HPA → 自定义指标弹性。

## 十、小结

弹性伸缩以指标驱动副本数，平衡成本与 SLO。
