# 查询改写与扩展总览

> 对应 Query Rewriting/Rewriting for RAG；与 RAG深入 / 混合检索深入 衔接。

## 一、背景与挑战

用户问题口语化、缺上下文、歧义，直接检索召回差；需改写/扩展以匹配文档。

## 二、核心原理

用 LLM 把原查询改写为更适合检索的形式（补全上下文、拆解、去歧），或扩展为多条子查询并行检索。

## 三、数学形式

改写 $q'\sim P_\theta(q'|q, C)$；扩展 $\{q_1..q_m\}$ 覆盖多意图；最后融合结果。

## 四、代码实现

```python
q_prime = llm(f"改写query便于检索: {q}")
docs = retrieve(q_prime)
```

## 五、与其他对比

- 与 混合检索深入（改写后双路）配合。
- 与 检索增强生成前沿 衔接（多查询检索）。

## 六、常见误区

- 改写过度改变原意致检索偏题。
- 多查询无去重致上下文冗余。

## 八、面试题

- 为何要查询改写？答：原查询口语/缺上下文，改写对齐文档语言提召回。

## 九、演进

无改写 → 规则改写 → LLM 改写/扩展。

## 十、小结

查询改写/扩展是 RAG 检索前处理，显著提升召回相关性。
