# 查询改写与检索链路

> 对应 RAG 端到端；检索增强生成前沿 衔接。

## 一、背景与挑战

改写是检索链首环，错误会向下游放大。

## 二、核心原理

改写应在召回与重排前，配合混合/扩展与重排构成完整链。

## 三、数学形式

$RAG(q) = \text{Gen}(\text{Rerank}(\text{HybridRetrieve}(\text{Rewrite}(q))))$。

## 四、代码实现

```python
q2 = rewrite(q); cands = hybrid(q2, 200); top = rerank(q, cands, 8)
```

## 五、与其他对比

- 与 检索重排序深入 / 混合检索深入 / 长文档切分深入 共构成 RAG 链路。
- 与 大模型与数据库深入 衔接（检索系统）。

## 六、常见误区

- 改写在链路中位置错（如重排后改写无效）。
- 各环节度量割裂无端到端视图。

## 八、面试题

- 改写在 RAG 链位置？答：最前端，影响后续所有检索质量。

## 九、演进

独立模块 → 链路集成 → 端到端联合优化。

## 十、小结

查询改写处于 RAG 链路起点，其质量决定下游上限。
