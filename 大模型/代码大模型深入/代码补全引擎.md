# 代码补全引擎

> 见「代码大模型深入/代码模型总览」与「推理优化/KV缓存」。

## 一、背景与挑战

IDE 内补全需低延迟、高接受率。

## 二、核心原理

本地/服务端模型做 FIM 补全，结合语法校验、上下文（光标前后）与用户习惯；延迟敏感需小模型+缓存。

## 三、关键要点

- 低延迟优先（<200ms 体感好）。
- 需过滤低质补全避免干扰。

## 四、代码实现

```python
sugg = coder.complete(prefix, suffix, max_tokens=8)
if confidence(sugg) > 0.7: show(sugg)
```

## 五、与其他对比

- Chat 改码重；补全轻量实时。

## 六、常见误区

- 补全越长越好——短而准更易接受。

## 七、与开源书对应

- StarCoder FIM; llm-course: https://github.com/mlabonne/llm-course
- Continue/FauxPilot 开源补全。
