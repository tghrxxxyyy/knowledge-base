# 人机协作评估

> 对应 HITL 系统评估（人效、采纳率、认知负荷）。

## 一、背景与挑战

协作好坏不能只看 agent 指标，还要看人是否更高效、更省心。

## 二、核心原理

评估三维：任务成效（完成率/质量）、人效（节约时间/认知负荷）、信任健康（采纳率与误用率）。良好协作应同时提升前两者且不致盲从。

## 三、数学形式

协作增益：

$$G = \frac{Q_{collab}\cdot T_{saved}}{1 + Load_{human}}$$

$Load$ 为人的额外负担。

## 四、代码实现

```python
metrics = {"quality": q, "time_saved": t, "load": l}
```

## 五、与其他对比

- 与 多智能体通信评估 类比（都把“交互方”当指标）。
- 与 成本评估基准 共担效率视角。

## 六、常见误区

- 只测 agent 质量，忽略人更累了。
- 采纳率当信任，盲从也高采纳。

## 八、面试题

- 协作评估为何含认知负荷？答：协作价值看人是否真省力，否则只是转移负担。

## 九、演进

agent 单维 → 人效二维 → 信任健康三维。

## 十、小结

人机协作评估须把“人”放进指标，否则协作可能只是转移了负担。
