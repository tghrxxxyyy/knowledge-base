# 人机协作与人在环总览

> 对应 Human-in-the-loop（HITL）系统与协同智能（centaur intelligence）。

## 一、背景与挑战

智能体并非要取代人，而是在“机器擅长的规模化/检索/执行”与“人擅长的判断/责任/创意”间互补。设计不当会变成人或 agent 互相甩锅。

## 二、核心原理

把人视为系统中的特殊 agent，定义协作契约：何时 agent 自主、何时请求人、人提供什么（确认/纠正/偏好/知识）。关键是“恰当处的人”，而非“处处的人”。

## 三、数学形式

人机分工按能力-成本-风险分配：

$$a^* = \arg\min_{a\in\{human,agent\}} c(a)\quad s.t.\ r(a)\ge r_{req}$$

高风险高判断任务归人。

## 五、与其他对比

- 与 智能体安全与权限沙箱深入 共享高风险确认。
- 与 智能体轨迹自我进化深入 共享反馈通道。

## 六、常见误区

- 要么全自动化要么全人工，缺中间档。
- 把人当“确认按钮”，未发挥其判断价值。

## 八、面试题

- 人在环的核心价值？答：在判断、责任、创意处补机器短板，而非仅做确认。

## 九、演进

全人工 → 全自动 → 风险分级的人机协同。

## 十、小结

人机协作的本质是按能力-风险分配任务，让两者各司其职。
