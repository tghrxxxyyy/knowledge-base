# 干预与确认点设计

> 对应 HITL 中的检查点（checkpoint）与可中断执行。

## 一、背景与挑战

何时让人介入直接决定体验与成本。介入太频繁人疲于点击，太少则错误已酿成。

## 二、核心原理

在“不可逆/高风险/不确定性高”三类节点插入确认；可逆/低风险允许 agent 自主并事后可撤销。提供随时中断（pause/resume）能力，使人能接管。

## 三、数学形式

确认触发：

$$confirm = \mathbb{1}[irreversible \lor risk\ge\tau \lor entropy(action) > h]$$

## 四、代码实现

```python
if irreversible(action) or risk(action) >= THRESH:
    human.review(action)  # 可改可拒
```

## 五、与其他对比

- 与 关键操作人类确认 同机制、不同侧重（这里强调节奏设计）。
- 与 降级与兜底 衔接人拒后的收场。

## 六、常见误区

- 确认点均匀撒，重要节点反而没拦。
- 不可中断的长任务，人无法及时接管。

## 八、面试题

- 确认点如何定？答：落在不可逆/高风险/高不确定节点，可逆低险放手。

## 九、演进

无干预 → 全量确认 → 风险分级+可中断。

## 十、小结

干预点设计是协作节奏的“旋钮”，贵在精准而非密集。
