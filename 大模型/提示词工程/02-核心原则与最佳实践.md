# 核心原则与最佳实践

> 本节汇总三家主流来源的可操作经验：OpenAI 的「八条经验法则」、Anthropic 的「最佳实践」、Microsoft 的「4S 原则」。共性极高：**清晰、具体、给上下文、用示例、迭代**。

## 一、OpenAI 八条经验法则

来源：https://help.openai.com/en/articles/6654000-best-practices-for-prompt-engineering-with-openai-api

1. **用最新、能力最强的模型**
   新模型通常更容易「听懂人话」，提示工程成本更低。注意：推理模型（reasoning）与 GPT 类模型的提示方式存在差异。

2. **指令放开头，用 `###` 或 `"""` 分隔指令与上下文**

   ```text
   较差 ❌：Summarize the text below as a bullet point list.
   {text input here}

   较好 ✅：Summarize the text below as a bullet point list of the most important points.
   Text: """
   {text input here}
   """
   ```

3. **尽量具体、描述详尽**（上下文、结果、长度、格式、风格都要说清）

   ```text
   较差 ❌：Write a poem about OpenAI.
   较好 ✅：以 {著名诗人} 的风格，写一首简短而鼓舞人心、关于 OpenAI 的诗，
            重点着墨于近期推出的 DALL·E（文本生成图像模型）。
   ```

4. **用示例显式表达期望的输出格式**
   模型「看样学样」比单纯文字描述更可靠，也便于程序化解析。

   ```text
   Extract the important entities mentioned in the text below.
   First extract all company names, then people names, then specific topics, finally general themes.
   Desired format:
   Company names:
   People names: -||-
   Specific topics: -||-
   General themes: -||-
   Text: {text}
   ```

5. **先零样本，再少样本，都不行再微调**（见概述「学习范式」）

6. **减少模糊、空洞的描述**

   ```text
   较差 ❌：The description should be fairly short, a few sentences only.
   较好 ✅：Use a 3 to 5 sentence paragraph to describe this product.
   ```

7. **与其说「不要做什么」，不如说「要做什么」**

   ```text
   较差 ❌：DO NOT ASK USERNAME OR PASSWORD. DO NOT REPEAT.
   较好 ✅：The agent will diagnose the problem and suggest a solution,
            while refraining from asking any PII such as username or password;
            instead refer the user to the help article www.example.com/help/faq
   ```

8. **代码生成专属：用「引导词」把模型引向某种模式**

   ```python
   # 在提示末尾补一个 import 暗示模型用 Python 起笔；
   # SELECT 暗示用 SQL 起笔。
   import
   ```

## 二、Anthropic 最佳实践

来源：https://docs.anthropic.com/en/prompt-library/library

### 1. 用 XML 标签给复杂提示「分块」
当提示里混着指令、上下文、示例、可变输入时，用一致、有语义的标签（如 `<instructions>`、`<context>`、`<examples>`、`<input>`）包裹，能显著降低模型误读：

```xml
<instructions>把用户问题基于下方税务条款回答，且必须引用原文。</instructions>
<tax_code>{{TAX_CODE}}</tax_code>
<examples>
  <example>
    <question>...</question>
    <answer>...</answer>
  </example>
</examples>
<input>{{QUESTION}}</input>
```

> 多文档时把每个文档包在 `<document><source>...</source><doc>...</doc></document>` 里；层级关系用嵌套标签。

### 2. 在 system 里给模型一个「角色」
一句话聚焦语气与行为：

```python
client.messages.create(
    model="claude-opus-4-8",
    system="You are a helpful coding assistant specializing in Python.",
    messages=[{"role": "user", "content": "How do I sort a list of dictionaries by key?"}],
)
```

### 3. 长上下文（20k+ token）的摆位技巧
- **长文档/数据放最上面**，指令、示例放下面；查询放最后。测试显示查询放末尾在复杂多文档场景可提升约 30% 质量。
- 让模型先**引用原文再作答**（grounding），帮它「穿过噪声」。

```xml
First, pull relevant quotes from the tax code in <quotes> tags.
Then write a concise, factual response in <answer> tags, grounded in those quotes.
```

### 4. 说清「要做什么」，而不是「不要做什么」
与 OpenAI 第 7 条一致：用正向指令。例如不要说「不要用 markdown」，而说「用流畅的散文段落写作」。

### 5. 用示例（few-shot / multishot）校准
好示例三要素：**相关**（贴近真实场景）、**多样**（覆盖边界）、**结构化**（用标签包起来）；给 3–5 个效果最好。

> ⚠️ Anthropic 最新模型默认更简洁、更自然、更少自我表扬；若你希望它在工具调用后给总结，要显式要求。

## 三、Microsoft 4S 原则（尤其适合代码助手 / Copilot）

来源：https://learn.microsoft.com/.../introduction-prompt-engineering-with-github-copilot

| 原则 | 含义 | 要点 |
| --- | --- | --- |
| **S**ingle（单一） | 聚焦单个明确任务 | 一次只问一件事，避免歧义 |
| **S**pecific（具体） | 指令明确详尽 | 具体 → 更精准的建议 |
| **S**hort（简短） | 在具体的同时保持简洁 | 平衡细节与长度，别堆砌 |
| **S**urround（有上下文） | 用描述性文件名、保持相关文件打开 | 给模型更丰富的项目上下文 |

延伸做法：
- **角色提示（Role prompting）**：让 Copilot 扮演安全专家 / 性能专家 / 测试专家，首轮即拿到更对口的实现。
- **链式提示（Chain prompting）**：把复杂功能拆成多轮对话逐步叠加（先实现 → 加错误处理 → 加测试 → 加文档 → 优化），长对话可**总结上下文或重置**，避免每轮成本膨胀。
- **断言并迭代**：首轮不对就补充细节与示例再问，而不是推倒重来。

## 四、跨厂商共识（速记）

> 清晰（clear） + 具体（specific） + 给上下文（context） + 给示例（examples） + 迭代（iterate）
>
> 黄金校验法（Anthropic）：把你的提示词给一个对任务**几乎零背景**的同事看，如果他看懵了，模型也会懵。
