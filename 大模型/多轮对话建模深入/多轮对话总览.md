# 多轮对话建模总览

> 对应 Budzianowski et al., *MultiWOZ*, 2018；任务型多轮对话 benchmark 与建模范式。

## 一、背景与挑战

单轮问答忽略上下文与状态，无法处理依赖历史、澄清、改写的连续交互。

## 二、核心原理

把对话建模为状态转移：每轮结合历史 $H_t$ 与当前输入 $u_t$ 产生动作/回复；可显式维护对话状态。

## 三、数学形式

回复 $r_t\sim p_\theta(r_t|H_t,u_t)$，$H_t=(u_1,r_1,\dots,u_t)$；状态 $S_t=f(S_{t-1},u_t,r_{t-1})$。

## 四、代码实现

hist = []
for u in user_turns:
    resp = model(apply_template(hist, u)); hist.append((u, resp))

## 五、与其他对比

- 与 指令微调范式深入（单轮指令扩展为对话）衔接。
- 与 角色与人格对齐深入（对话中保持人格）共享。

## 六、常见误区

- 直接把所有历史拼入，超长致截断与噪声。
- 忽略状态跟踪，答非所问。

## 八、面试题

- 多轮对话为何需状态？答：后续轮依赖历史意图与槽位，状态压缩历史避免重复与矛盾。

## 九、演进

流水线 DST → 端到端 LLM → 长上下文记忆。

## 十、小结

多轮对话以历史与状态保持连贯，是助手型产品的核心。
