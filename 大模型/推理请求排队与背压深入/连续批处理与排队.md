# 连续批处理与排队

> 对应 continuous batching（vLLM, Kwon et al., 2023, arXiv:2309.06180）；Triton dynamic batching。

## 一、背景与挑战

逐请求推理 GPU 利用率低；批处理提吞吐但增延迟，需与排队协同。

## 二、核心原理

vLLM 连续批处理在 token 级动态凑批，完成的请求立即离场、新请求补入，最大化 GPU 占用。

## 三、数学形式

吞吐 $T = \frac{B \cdot L_{out}}{t_{step}\cdot B + t_{overhead}}$，批大小 $B$ 越大吞吐越高但尾延迟升。

## 四、代码实现

```python
scheduler.blocked.append(req)
running = scheduler.prompt_admit(budget)
out = model.step(running)   # 连续批
```

## 五、与其他对比

- 与 排队系统总览 共享队列概念。
- 与 模型加密与权重量化保护深入 无直接关系，本篇聚焦吞吐。

## 六、常见误区

- 静态大批发尾延迟不可接受。
- 批内变长致短请求被长请求拖。

## 八、面试题

- 连续批处理优势？答：token 级动态凑批，完成即离场，兼顾高吞吐与低尾延迟。

## 九、演进

无批 → 静态批 → 连续批（paged attention）。

## 十、小结

连续批处理是排队与 GPU 效率的关键结合点。
