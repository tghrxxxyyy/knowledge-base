# 背压机制设计（Backpressure）

> 对应流式系统背压（Reactive / Triton 队列满拒绝）；防止级联雪崩。Reactive Streams 定义背压。

## 一、背景与挑战

当下游处理慢于上游生产，缓冲无限增长最终 OOM；需向上游反向施压。

## 二、核心原理

队列达阈值时拒绝新请求或返回 429，迫使客户端减速或重试，保护系统稳定。

## 三、数学形式

背压触发：当 $len(q) \ge Q_{max}$ 或 $util>\rho_{hi}$ 时，接纳率 $a=0$。

## 四、代码实现

```python
if q.qsize() >= QMAX:
    raise HTTPError(429, "rate limited")
q.put(req)
```

## 五、与其他对比

- 与 限流与熔断（多租户）共享拒绝语义。
- 与 排队系统总览（队列阈值）衔接。

## 六、常见误区

- 阈值过高仍 OOM；过低浪费容量。
- 客户端无退避致重试风暴。

## 八、面试题

- 背压为何必要？答：反向限流防缓冲无限增长 OOM，牺牲部分请求保整体可用。

## 九、演进

丢弃 → 拒绝（429） → 自适应背压与指数退避。

## 十、小结

背压以可控拒绝换系统稳定，是抗过载核心机制。
