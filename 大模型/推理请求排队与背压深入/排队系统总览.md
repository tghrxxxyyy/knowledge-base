# 推理请求排队总览

> 对应队列论与服务系统；vLLM 与 Triton 采用内部批队列。vLLM 文档描述其调度队列。

## 一、背景与挑战

突发流量下并发请求超过推理实例处理能力，需排队平滑；否则 OOM 或超时雪崩。

## 二、核心原理

请求入队，调度器按批（batching）从队列取若干请求送入 GPU；队列长度反映系统负载。

## 三、数学形式

M/M/1 近似：平均等待 $W_q=\frac{\rho}{\mu(1-\rho)}$，$\rho=\lambda/\mu$ 为利用率。

## 四、代码实现

```python
q = asyncio.Queue(maxsize=1024)
async def worker():
    batch = await take(q, n=32)
    out = model.generate(batch)
```

## 五、与其他对比

- 与 连续批处理与排队 共享批概念。
- 与 多租户隔离与配额深入（每租户队列）衔接。

## 六、常见误区

- 队列无限长致内存爆与请求长期饥饿。
- 忽略排队延迟已使 SLA 失效。

## 八、面试题

- 为何要队列？答：削峰填谷，把突发转成可控批处理，防过载雪崩。

## 九、演进

无队列 → 固定批 → 连续批（continuous batching）。

## 十、小结

排队是推理系统抗突发与提吞吐的第一道缓冲。
