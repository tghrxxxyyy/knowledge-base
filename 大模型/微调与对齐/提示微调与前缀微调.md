# 提示微调与前缀微调

> 对应 llm-course「Prompt/Prefix Tuning」与 Lester et al., *Prompt Tuning* (2021)、Li & Liang, *Prefix-Tuning* (2021)。

## 一、背景与挑战

全参数微调与 LoRA 仍会改动或新增主干权重。提示微调（Prompt Tuning）与前缀微调（Prefix Tuning）走得更远：它们**完全冻结主干**，只学习一段连续的「软提示 / 前缀」向量，把任务信息编码进这段可训练嵌入中。其动机是：大模型具备丰富的隐式能力，合适的连续前缀即可「唤醒」对应行为，而无需触碰任何原始参数，因而极致省参数、天然抗灾难性遗忘。

## 二、核心原理

- **Prompt Tuning**（Lester et al., 2021）：在输入嵌入前拼接可学习软提示 $P\in\mathbb{R}^{k\times d}$，仅训练 $P$，冻结主干。无编码器，最简洁。
- **Prefix Tuning**（Li & Liang, 2021）：在 Transformer **每一层**注意力的键（K）与值（V）前加可学习前缀 $P_K^{(l)}, P_V^{(l)}$，从更深层控制生成。为稳定常以 MLP 重参数化前缀。
- **P-Tuning v2**：将提示施加到每一层，接近 Prefix 的效果，使小模型也受益。

二者区别在于「软提示作用的位置」：Prompt 在嵌入输入层，Prefix 贯穿各层注意力。

## 三、形式化与数学基础

Prompt Tuning 把输入序列嵌入变为拼接：

$$
\tilde X = [P;\, X] \in \mathbb{R}^{(k+n)\times d}
$$

训练目标为仅优化 $P$ 的似然：

$$
\mathcal{L} = -\sum_{t} \log p_\theta\!\big(x_t \mid [\tilde X]_{<t};\ \theta_{\text{frozen}},\ P_{\text{trainable}}\big)
$$

Prefix Tuning 在第 $l$ 层把前缀并入注意力键值：设原 $K=[\text{key}_1,\dots,\text{key}_n]$，则 $\tilde K^{(l)} = [P_K^{(l)}; K^{(l)}]$，$\tilde V^{(l)} = [P_V^{(l)}; V^{(l)}]$，注意力在扩展后的序列上计算，前缀由此影响每一层的表征流向。

## 四、代码实现

```python
from peft import PrefixTuningConfig, get_peft_model, TaskType

cfg = PrefixTuningConfig(
    task_type=TaskType.CAUSAL_LM,
    num_virtual_tokens=30,
    encoder_hidden_size=512,
    prefix_projection=True,     # 用 MLP 重参数化前缀，更稳定
)
model = get_peft_model(base, cfg)
model.print_trainable_parameters()   # 仅前缀可训练
```

```python
# Prompt Tuning 则改用 PromptTuningConfig（无 prefix_projection）

```

## 五、与其他技术对比

| 方法 | 训练参数位置 | 作用层级 | 小模型表现 | 推理开销 |
|------|--------------|----------|------------|----------|
| Prompt Tuning | 软提示 | 输入嵌入 | 需大模型 | 序列略变长 |
| Prefix Tuning | 前缀 K/V | 每层注意力 | 较好 | K/V 略增 |
| P-Tuning v2 | 多层提示 | 所有层 | 好 | 序列略变长 |
| LoRA | 低秩矩阵 | 指定权重 | 好 | 可合并消除 |

## 六、常见误区

- 认为软提示可读可解释：软提示是连续嵌入，不可当自然语言拼接使用。
- 小模型直接用 Prompt Tuning 想媲美全参数：需足够大模型（常 10B+）才接近全参数效果。
- 把 Prefix 与 Prompt 混用：Prefix 改的是每层 K/V，Prompt 只改输入嵌入，行为差异显著。
- 前缀长度随意：过长易过拟合、挤占有效上下文，过短表达力不足。

## 九、演进与趋势

从 Prompt/Prefix 的单序列软提示，到 P-Tuning v2 的多层统一、再到与 LoRA 混合（如 (IA)³ + LoRA）。研究也探索提示初始化（用任务描述文本初始化软提示）、多任务提示库与提示蒸馏。以官方最新文档为准。

**实践要点：**

- Prefix 的前缀长度与层数共同决定容量，深层前缀对小模型帮助更大但增加 K/V 计算。
- 前缀重参数化（prefix projection）用 MLP 生成前缀，比直接优化更稳定，尤其小模型。
- Prompt Tuning 在 10B 以下模型常弱于 LoRA，选型时应按模型规模权衡。
- 推理时前缀/软提示作为固定前缀常驻，注意其与动态输入的拼接顺序与位置编码一致。

## 十、小结

提示与前缀微调以「零主干改动」实现极省参数的适配，适合大模型少样本与多任务隔离场景；Prefix 因跨层控制更稳，Prompt 因最简最受青睐，应按模型规模与稳定性需求选型。
