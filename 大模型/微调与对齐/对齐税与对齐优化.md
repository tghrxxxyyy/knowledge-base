# 对齐税与对齐优化

> 对应 llm-course 对齐章节与 OpenAI「Alignment Tax」相关讨论，及 *Training Language Models to Follow Instructions* (Ouyang et al., 2022)。

## 一、背景与挑战

对齐（RLHF/DPO）让模型更服从指令、更安全，但研究与实践发现：经过对齐的模型在**某些预训练已具备的能力**上（如知识问答广度、数学推理、代码生成、创作流畅度）可能出现下降。这种「为对齐付出的能力代价」被称为**对齐税（Alignment Tax）**。它的危害是隐性的——模型看起来更「乖」，却在硬核任务上退步，且难被主观体验直接察觉。

## 二、核心原理

对齐税源于优化目标的改变：预训练目标是语料续写似然，对齐目标是人类偏好。当偏好数据偏向「礼貌、简短、安全」时，模型会抑制那些「更长、更技术化、更冒险」但往往更有信息量的输出。KL 约束虽能保护参考模型，但 $\beta$ 选择不当仍会压缩能力分布。缓解思路围绕三点展开：**强 SFT 基座**（对齐前能力基底更高）、**保留参考模型**（DPO 的 $\pi_{ref}$ 提供锚点）、**高质量偏好数据**（减少噪声带来的能力漂移）。

## 三、形式化与数学基础

以 DPO 为例，目标含隐式奖励 $r(x,y)=\beta\log\frac{\pi_\theta(y\mid x)}{\pi_{ref}(y\mid x)}$。当 $\beta$ 较大，策略被强约束于 $\pi_{ref}$ 附近，能力保留好但对齐不足；当 $\beta$ 较小，模型自由追逐偏好，对齐强但可能偏离预训练能力。权衡可写为对「能力损失」与「对齐增益」的折中：

$$
\text{效用} \approx \underbrace{\mathbb{E}[\text{capability}(\pi_\theta)]}_{\text{受 KL 压缩}} - \underbrace{\lambda\,\text{alignment\_gap}}_{\text{偏好满足}}
$$

实践中通过调节 $\beta$ 与数据配比寻找帕累托前沿。

## 四、代码实现

```python
# 用参考模型 KL 监控对齐税：评估时同时测「通用基准」与「对齐基准」
def eval_tax(model, ref_model, cap_bench, align_bench):
    cap = model.evaluate(cap_bench)      # MMLU / 代码 / 数学
    ali = model.evaluate(align_bench)     # 指令遵循 / 安全
    ref_cap = ref_model.evaluate(cap_bench)
    return {"capability_drop": ref_cap - cap, "alignment_gain": ali}
```

## 五、与其他技术对比

| 策略 | 对对齐税的影响 | 代价 |
|------|----------------|------|
| 强 SFT 基座 | 降低税（基底高） | 需更多 SFT 数据 |
| 控制 $\beta$ | 平衡能力/对齐 | 需搜索 |
| 迭代式 DPO / 拒绝采样 | 提质、减税 | 流程更长 |
| 多任务混合偏好 | 防单能力塌陷 | 数据工程复杂 |

## 六、常见误区

- 认为「对齐一定提升所有能力」：对齐主要提升指令遵循与安全性，硬核能力可能下降。
- 用单一对齐指标验收：只看指令遵循分数会掩盖通用能力塌缩，必须双轨评测。
- 盲目增大 $\beta$：虽保留能力，却可能让对齐「走过场」。
- 忽略 SFT 质量：弱 SFT 基座的对齐税更高，因为对齐要在更低的起点上补偿。

## 九、演进与趋势

从早期「对齐 vs 能力」的零和观，到认识到可通过更好的数据（如拒绝采样优选、宪法式偏好）与训练配方降低税收。前沿探索包括「对齐不影响推理」的分离式训练、以及把能力评估纳入对齐目标做联合优化。以官方最新文档为准。

**实践清单（降低对齐税的可执行项）：**

- 在 SFT 阶段就混入一定比例的能力型样本（数学、代码、知识 QA），而非纯指令样本，可抬高对齐基底、降低后续税收。
- 偏好数据构建引入拒绝采样：用强模型生成多候选，再用 RM 或规则筛最优，避免把噪声偏好喂给 DPO。
- 采用分阶段对齐：先轻量 SFT 建立格式，再 DPO 提升偏好，最后用少量 PPO 精修高风险能力，逐步逼近帕累托前沿。
- 监控指标除指令遵循外，定期跑 MMLU/代码/数学基准，设定通用能力下限告警，跌破即回退。
- 评估时区分「安全拒答」与「能力缺失」：二者表面都表现为不回答，但后者需补能力而非加对齐。
- 当通用分跌破阈值，回退到上一 checkpoint 并降低 $\beta$ 或增大 replay 比例重训。

**示例**：某 7B 模型经强 DPO（$\beta=0.05$）后，指令遵循从 60 升到 82，但 MMLU 从 55 掉到 48，对齐税为 7 分。把 $\beta$ 调到 0.1、SFT 加入 20% 知识样本后重训，MMLU 回到 53、指令遵循保持 80，税收降至 2 分，整体更优。经验上对齐税并非恒定：数据越干净、基座越强，税收越低；弱基座上强行强对齐税收显著，因此「先强身（能力/持续预训练）后对齐（轻量偏好）」的顺序优于逆向顺序。

**典型表现与诊断：**

- 知识广度下降：继续预训练/对齐后，模型在事实性问答（如 MMLU、TriviaQA）上的准确率回落，常因对齐数据偏向「安全简短」而抑制了长知识性输出。
- 推理链退化：数学与代码任务得分下滑，因偏好数据缺乏严谨推理示范，策略学会「看似合理但跳过步骤」。
- 创作流畅度降低：开放式写作变得模板化、保守，多样性指标（如 self-BLEU 反向）下降。
- 诊断方法：固定一套「能力探针」基准，在对齐前后各跑一次并差分，定位具体退化维度，而非笼统判断。

**缓解路径对比：**

| 路径 | 机制 | 适用 |
|------|------|------|
| 强 SFT 基底 | 对齐前能力更高，税更低 | 通用对齐 |
| 控制 $\beta$ | 约束偏离参考 | DPO 为主 |
| 拒绝采样 SFT | 用优选回答补能力 | 数据充足 |
| 持续预训练补能 | 先注入领域/推理知识再对齐 | 弱基座 |

## 十、小结

对齐税是对齐流程中不可避免的权衡，关键是用强基座、合理 KL 约束与双轨评测把它压到最低；对齐优化的本质是在能力保留与偏好满足间寻找帕累托最优。
