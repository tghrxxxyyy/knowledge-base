# 量化评估与部署

> 对应量化基准（perpl\&任务）；lm-eval-harness 评估体系衔接。

## 一、背景与挑战

量化后须验证精度损失可接受，否则“省显存丢智能”。

## 二、核心原理

评困惑度（PPL）看语言建模退化；评下游任务（MMLU/常识）看能力保持；测延迟/显存看收益。

## 三、数学形式

相对退化 $\Delta = \frac{\text{PPL}_{q}-\text{PPL}_{fp}}{\text{PPL}_{fp}}$；精度-效率帕累托前沿选点。

## 四、代码实现

```python
from lm_eval import simple_evaluate
res = simple_evaluate(model, tasks=["mmlu"], device="cuda")
```

## 五、与其他对比

- 与 模型评测指标深入 共享评估法。
- 与 推理经济成本深入 衔接（成本收益）。

## 六、常见误区

- 只看 PPL 忽略任务掉点（尤其推理/长尾）。
- 部署精度与评测精度不符（kernel 差异）。

## 八、面试题

- 问：如何判定量化可接受？答：PPL 小幅升+下游任务不掉点，且显存/延迟收益明显。

## 九、演进

手工评 → 基准套件 → 自动化帕累托选配。

## 十、小结

量化部署须以 PPL+任务双校验，平衡效率与能力。
