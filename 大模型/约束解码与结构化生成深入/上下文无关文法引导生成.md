# 上下文无关文法引导生成

> 对应 Willard & Louf 2023 constrained decoding; Lewis 2020 RAG; Vaswani 2017。

## 一、背景与挑战

复杂结构（程序代码、SQL、领域查询语言、嵌套 JSON）难以用正则或有限状态机描述——它们有递归与嵌套，正则表达式表达能力不足（正则无法匹配任意深度括号配对）。上下文无关文法（CFG）能精确刻画这类嵌套语法，引导 LLM 在每一步只生成符合文法的 token，从而稳定产出可编译/可解析字符串。

挑战在于：CFG 引导需要维护推导栈与「当前可发射 token 集合」，歧义文法会导致状态爆炸；且要把文法编译成可在自回归每一步高效查询的结构（下推自动机 PDA 或 Earley 解析表），否则解码延迟不可接受。

## 二、核心原理

把 CFG 编译成下推自动机（PDA），维护当前非终结符栈 $\sigma$。每步根据栈顶非终结符可展开的产生式，推导其 FIRST 集合，得到当前合法 token 集合；发射某 token 后按产生式更新栈（压入/弹出）。当栈归约到只剩起始符 $S$ 且输入结束，即生成合法字符串。

要点：合法续写由「栈顶产生式能推导出的首个 token」决定。例如栈顶为 `Expr`，其产生式 `Expr -> "(" Expr ")"` 的 FIRST 含 `"("`，则当前允许发射 `"("`。通过增量解析，每步只更新受影响的少量状态，使开销可控。

与正则/trie 相比，CFG 能表达任意深度嵌套（如括号配对、递归表达式），这是正则做不到的。代价是解析状态可能随文法规模膨胀，尤其歧义文法。工程上需在编译期做左因子化、消除左递归、剪枝不可达产生式，使每步合法集合查询保持轻量。把文法自动编译成分为词感知的 PDA，还能避免子词切分导致的越界。

## 三、形式化与数学基础

文法 $G = (N, T, P, S)$，$N$ 非终结符、$T$ 终结符、$P$ 产生式、$S$ 起始符。合法前缀集合为 $L(G)$ 的前缀闭包。解码时维护推导栈 $\sigma$，转移：

$$ \sigma \xrightarrow{x} \sigma' \iff x \in \mathrm{first}(\sigma') $$

约束分布同前：`p'(x_t) = p(x_t)/Z` 当 $x_t$ 属当前合法集合。FIRST 集合递归定义：

$$ \mathrm{first}(X) = \begin{cases} \{X\} & X \in T \\ \bigcup_{X \to \alpha} \mathrm{first}(\alpha) & X \in N \end{cases} $$

其中 $\mathrm{first}(\alpha\beta)$ 在 $\alpha$ 可推导出空串时还需并入 $\mathrm{first}(\beta)$。

## 四、代码实现

```python
import torch

class CFGGuided:
    def __init__(self, grammar):
        self.grammar = grammar          # 产生式表，以官方最新文档为准
        self.stack = ["S"]              # 起始符

    def next_tokens(self):
        # 由栈顶非终结符推导当前可发射 token 集合
        top = self.stack[-1]
        return self.grammar.first_tokens(top)

    def advance(self, token):
        # 按产生式更新栈：弹出栈顶、压入右部（逆序）
        prod = self.grammar.match(self.stack[-1], token)
        self.stack.pop()
        for sym in reversed(prod.rhs):
            if sym not in self.grammar.terminals:
                self.stack.append(sym)

def cfg_step(grammar_state, logits, vocab_size):
    allowed = grammar_state.next_tokens()
    mask = torch.full((vocab_size,), float("-inf"))
    for tid in allowed:
        mask[tid] = 0.0
    return (logits + mask).softmax(-1)
```

## 五、与其他技术对比

| 约束 | 表达力 | 适合 | 成本 |
|------|--------|------|------|
| 正则 / trie | 扁平、无递归 | 标签、模板 | 低 |
| CFG | 嵌套、递归 | 代码、SQL | 中-高 |
| JSON Schema | CFG 特例 | API 契约 | 低-中 |

CFG 比正则表达力强，能处理任意深度嵌套；JSON Schema 约束可视为 CFG 的一个受限子集（见「JSON Schema 约束生成」）。

## 六、常见误区

误区一：任何文法都能高效引导——歧义文法会使状态数爆炸，需左因子化、消除左递归。误区二：CFG 一定比正则慢很多——增量解析 + 缓存可接近无约束速度。误区三：文法只管结构不管取值——字段内容语义仍需提示。误区四：栈为空即完成——需栈归约到 $S$ 且输入终止，否则可能截断。

## 八、面试题

1. CFG 引导如何避免死状态？只在能完整归约到 $S$ 的活前缀上扩展，剪枝不可达分支。
2. 为什么正则不足以描述代码？正则无法匹配任意深度括号配对，CFG 才有递归表达力。
3. FIRST 集合作用？决定栈顶非终结符当前可发射的 token，是每步约束的来源。
4. 左递归如何处置？左递归会使解析陷入无限循环，需改写为右递归或迭代形式。

代码生成场景把 CFG 与语言服务器（LSP）结合，实时校验生成片段的语法与类型，约束随校验反馈动态调整。SQL 生成则用 CFG 保证方言语法（如窗口函数、CTE）正确。推理加速上，把 PDA 状态预编译为查表 + 位图，使每步合法集合查询 O(1)。与测试驱动生成（TDD）结合可进一步提升可用性。

## 十、小结

CFG 把语法知识注入采样过程：用下推自动机维护推导栈，每步只发射符合文法的 token，使 LLM 稳定产出合法程序与查询。理解 FIRST 集合、栈更新与歧义消除，是驾驭 CFG 引导生成的关键。
