# 约束解码的形式化定义

> 对应 Willard & Louf 2023 constrained decoding; Ouyang 2022 InstructGPT; Zheng 2023 LLM-as-judge。

## 一、背景与挑战
自由生成难以保证输出符合格式（JSON、SQL、代码），解析失败率高。约束解码在采样时强制 token 落在合法集合，使输出结构可机读。

## 二、核心原理
把生成过程视为在约束语言 L 上的游走：每一步允许的下一个 token 集合由当前前缀与文法/模式决定，非法 token 概率置零。

## 三、形式化与数学基础
令 A(w) 为前缀 w 后合法续写集合，约束分布：
$ p'(x_t) = \begin{cases} p(x_t)/Z & x_t \in A(w_{<t}) \\ 0 & \text{otherwise} \end{cases} $
其中 Z = sum_{x in A} p(x) 为归一化项。

## 四、代码实现
```python
def constrained_logits(logits, allowed_ids):
    mask = torch.full_like(logits, -1e9)
    mask[allowed_ids] = 0
    return (logits + mask).softmax(-1)
```

## 五、与其他技术对比
后处理校验需重试且浪费；约束解码一次到位。提示工程软约束无保证，硬约束解码有保证。

## 六、常见误区
误区：约束解码会严重降质。仅在合法空间内重归一化，对质量影响可控。

## 七、与开源书/权威来源对应
Willard & Louf 2023 Efficient Guided Generation for Large Language Models。见 huggingface/transformers、vllm-project/vllm。

## 八、面试题
问：约束解码如何不影响分布语义？
答：在合法子集上重归一化，等价于条件分布 p(x | x in L)。

## 九、演进与趋势
从正则到文法到 JSON Schema 自动编译，约束解码成为 Agent/工具调用基石。

## 十、小结
约束解码用“合法集合遮罩”把随机性约束进可解析空间，是结构化输出的可靠手段。
