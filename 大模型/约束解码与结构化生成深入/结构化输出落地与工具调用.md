# 结构化输出落地与工具调用

> 对应 Ouyang 2022 InstructGPT; Zheng 2023 LLM-as-judge; Willard & Louf 2023 constrained decoding。

## 一、背景与挑战

Agent 与函数调用（tool calling）要求模型输出能被程序直接消费的参数对象（如 JSON），而非自由自然语言。若让模型「自己写 JSON 再解析」，常因多余说明文字、格式瑕疵、字段缺失导致 `json.loads` 失败，需要重试往返，落地成本高。结构化生成把「自然语言 → 结构化参数」的解析失败率降到近零，是 LLM 从「聊天」走向「可执行系统」的关键接口。

挑战在于：如何把工具的函数签名 / JSON Schema 注入生成过程？如何保证嵌套数组、可选字段、枚举都合法？以及约束只管结构、不管取值合理，如何与提示配合。

## 二、核心原理

将工具的函数 Schema 注入约束解码器，生成严格符合 Schema 的参数对象；同时用系统提示说明字段语义，让模型在合法结构内填值。外层调度程序拿到输出后直接调用函数，无需 try/except 重试。典型闭环：用户请求 → 模型选工具 → 约束解码生成参数 JSON → 调度器执行 → 结果回灌模型 → 生成最终回答。

约束解码在此扮演「格式保险」：即使模型想多写解释，遮罩也会把输出限制在 Schema 定义的字段、类型与括号结构内。嵌套（object 内嵌 array、array 内嵌 object）由 FSM 递归展开处理。

落地时还涉及「工具选择」与「参数生成」两段：先由模型在多个候选工具中选定 name，再对所选工具的 Schema 做约束生成。多工具编排下，FSM 需支持跨工具状态；流式输出时还要保证「边生成边可解析」。约束只保结构，取值合理性（如日期格式、取值范围）仍需下游校验层兜底，必要时结合重试而非整段重来。

## 三、形式化与数学基础

函数 $f$ 的 Schema $S_f$ 决定参数空间 $P_f$（所有合法参数对象的集合）。约束解码把生成限制在其实例语言 $I(S_f)$ 上，输出 $o \in P_f$ 直接满足调用契约：

$$ \forall o \sim \text{constrained}(S_f):\; o \in P_f \implies f(o) \text{ 可调用} $$

整段生成概率即前节约束分布的乘积。由于 $I(S_f)$ 由 Schema 编译出的 FSM 描述，每步合法 token 集合由 FSM 当前状态决定（见「JSON Schema 约束生成」）。

## 四、代码实现

```python
import json

def tool_call(model, schema, prompt):
    fsm = build_schema_fsm(schema)         # Schema -> 有限状态机
    raw = model.generate(prompt, fsm=fsm)  # 约束生成 JSON
    return json.loads(raw)                 # 近零失败，无需 try/except

def dispatch(tools, call):
    # call: {"name": str, "arguments": dict}
    fn = tools[call["name"]]
    return fn(**call["arguments"])         # 直接调用，契约由 Schema 保证

# 流程：选工具 -> 约束生成参数 -> 执行 -> 回灌
```

## 五、与其他技术对比

| 方案 | 首轮成功率 | 重试往返 | 备注 |
|------|------------|----------|------|
| 模型自由写 JSON + try/except | 低-中 | 需要 | 浪费、延迟高 |
| 提示 + few-shot | 中 | 需要 | 无硬保证 |
| 约束解码（Schema FSM） | 高 | 不需要 | 工程标配 |
| 模型原生 JSON mode | 高 | 不需要 | 仍建议 + 约束双保险 |

约束生成相对「自由写再解析」省去重试往返，相对 few-shot 有硬保证。

## 六、常见误区

误区一：有了 Schema 就无需提示——约束只管结构，不管取值是否合理（如把「日期」填成乱码），语义说明仍必要。误区二：约束能管取值语义——不能，需校验层（如范围检查）兜底。误区三：嵌套数组简单——array 下标与字段完成态需 FSM 精确跟踪，否则易缺元素。误区四：一次约束解决全部——复杂工具链需多轮选工具 + 约束生成配合。

## 八、面试题

1. 约束解码如何支持嵌套工具与数组？FSM 对 array/object 递归展开，跟踪下标与字段完成态，逐状态限定下一步。
2. 为何仍需提示？约束只保证结构合法，取值合理性靠提示与下游校验。
3. 结构化生成相对自由生成的收益？首轮即可解析、省重试、延迟与成本双降。
4. 模型原生 JSON mode 与约束解码关系？互补双保险，前者靠模型、后者靠解码时强制。

Agent 框架正把「工具注册表」标准化为带 Schema 的服务目录，约束解码直接消费该目录生成调用。多步规划下，约束从单工具参数扩展到「计划树」结构（如 JSON 描述步骤与依赖）。可观测与可调试上，记录每步约束状态便于定位「模型选错工具」还是「参数填错」。安全上，约束限制可调用集合本身也是一层防护。

## 十、小结

结构化生成是 LLM 落地为可执行系统的关键接口：把工具 Schema 编译为 FSM 注入解码，使输出零解析失败、可直接调用函数。约束管结构、提示管语义，二者配合是 Agent 工程的事实标准。
