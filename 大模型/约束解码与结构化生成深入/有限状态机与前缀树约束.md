# 有限状态机与前缀树约束

> 对应 Willard & Louf 2023 constrained decoding; Sennrich 2016 BPE; Kudo & Richardson 2018 SentencePiece。

## 一、背景与挑战

当合法输出是有限集合（如分类标签、固定模板、受控词表、枚举值）时，用正则或文法显得笨重；用前缀树（trie）或确定性有限状态机（DFA）可精确约束每一步允许的字符/token，避免越界与拼写错误。典型场景：让模型只能输出预定义意图标签、只能填某个字段的枚举值、只能续写固定模板的占位符。

挑战在于：现代 LLM 基于子词分词（BPE / SentencePiece），「词」并不等于 token。若直接在字符级建 trie，子词边界会与约束错位，导致约束失效或碎片化。因此必须在 token 空间而非字符空间构建约束。

## 二、核心原理

把候选词集构造成 trie：每个节点代表一个前缀，边代表续写的字符/token，到达叶节点即完成一个合法词。解码时按已生成前缀沿边下行，仅允许存在子节点的续写。更一般地，有限状态机用状态表描述「当前状态下可发射的 token 与跳转到的下一状态」，覆盖循环、分支等结构。

关键适配：用目标 tokenizer 把每个候选序列编码成 token 序列，在 token 空间建 trie/FSM，使每条边对应一个 token。这样约束与模型的真实生成单位对齐，不会出现「字符合法但子词非法」的错位。

一个易混淆点：trie 是 FSM 的树形特例（无状态合并），DFA 可共享状态、表达循环与分支。对「先选 A 后只能选 B」这类带状态约束，纯 trie 不够，需要 FSM。生产中常把二者组合：外层 DFA 选模板/分支，内层 trie 填枚举值，覆盖「有限候选 + 确定结构」复合场景。约束的状态缓存与复用能把每步查询降到接近常数。

## 三、形式化与数学基础

trie $T$ 上，给定已生成前缀 $w$，合法续写集合：

$$ A(w) = \{ c \mid w \cdot c \text{ 是 } T \text{ 中某条路径的前缀} \} $$

若建在 token 空间，则 $c$ 为单个 token，$w$ 为已生成 token 序列。约束分布同前：`p'(c) = p(c)/Z` 当 $c \in A(w)$ 否则 0。有限状态机则显式记录状态 $q$，转移函数 $\delta(q, c) = q'$，合法续写即 $\{c \mid \delta(q,c) \text{ 有定义}\}$。终止条件为到达接受态（叶节点 / 接受状态）。

## 四、代码实现

```python
import torch

class Trie:
    def __init__(self):
        self.children = {}          # token_id -> Trie
        self.is_leaf = False

    def insert(self, token_ids):
        node = self
        for tid in token_ids:
            node = node.children.setdefault(tid, Trie())
        node.is_leaf = True

    def allowed_tokens(self):
        return list(self.children.keys())

def trie_step(node, logits, vocab_size):
    allowed = node.allowed_tokens()
    mask = torch.full((vocab_size,), float("-inf"))
    for tid in allowed:
        mask[tid] = 0.0
    return (logits + mask).softmax(-1)

# 用法：把候选词用 tokenizer 编码后插入 trie，每步按当前 node 查询合法 token
```

## 五、与其他技术对比

| 约束 | 适用范围 | 复杂度 | 备注 |
|------|----------|--------|------|
| 前缀树 trie | 有限候选集 | $O(|候选|)$ | 确定集合最简可靠 |
| DFA / FSM | 有限状态结构 | $O(状态数)$ | 支持循环分支 |
| 正则 | 扁平模式 | 中 | 可编译为 DFA |
| CFG | 嵌套/递归 | 高 | 见「上下文无关文法引导生成」 |

三者可组合成混合约束：外层 DFA 选模板，内层 trie 填枚举。

## 六、常见误区

误区一：trie 与 BPE 冲突——不冲突，只要在子词（token）层面建 trie，使每条边对应一个 token 而非字符。误区二：字符级 trie 直接用——子词边界错位会使约束碎片化或越界。误区三：trie 只能做词——配合 FSM 可表达带状态的序列（如「先选 A 再只能选 B」）。误区四：枚举值随便生成——若枚举未被 tokenizer 切成单一 token，需覆盖其 BPE 切分路径。

## 八、面试题

1. 如何在子词分词下做精确 trie 约束？把候选序列用目标 tokenizer 编码，在 token 空间建 trie，沿 token 边约束。
2. trie 与 DFA 关系？trie 是 DFA 的特例（树形、无合并状态）；DFA 可共享状态、表达循环。
3. 枚举字段为何要覆盖 BPE 切分？枚举可能被切成多 token，约束需覆盖整条 token 路径。
4. 死状态如何避免？仅在能完整到达接受态的活前缀上扩展，剪枝不可达分支。

工程实践把 trie/FSM 的状态表缓存并按 batch 共享，使约束开销接近线性。对超大类目（如百万级 SKU 枚举），采用「两层 trie」或倒排 + FSM 混合，避免状态爆炸。与向量检索结合时，先用 ANN 召回候选再在 FSM 内约束，兼顾语义与格式。可解释上，约束命中路径可回溯为「为何生成该 token」。

## 十、小结

前缀树 / DFA 是有限确定集合约束的最简可靠形式：在 token 空间构建、沿边精确限制续写，避免拼写与越界。理解「字符级 vs token 级」的边界，是让 trie 约束在真实 LLM 上生效的关键，常与高级约束组合使用。
