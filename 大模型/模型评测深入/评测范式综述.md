# 大模型评测范式综述

> 对应 llm-course「Evaluation」章节，以及 HELM (Liang et al., 2022) 与 OpenCompass 评测框架方法论。

## 一、背景与挑战

大模型能力多维、场景多样，没有「一个分数定高低」。不同利益方（研究者、产品、监管）关心不同侧面：研究者要能力上限，产品要真实场景可用，监管要安全合规。挑战在于：① 评测维度割裂，容易「刷榜不刷能力」；② 静态基准易过拟合与污染；③ 自动评测有偏差，人工评测贵且慢。需要一套结构化范式把能力、对齐、场景三类评测打通。

## 二、核心原理

大模型评测可分层组织：

1. **能力评测**：知识（MMLU）、推理（GSM8K/BBH）、数学（MATH）、代码（HumanEval）、长上下文等，衡量「能不能做」。
2. **对齐评测**：有用性（helpfulness）、安全性（harmlessness）、诚实性（honesty/truthfulness），衡量「该不该做、是否可信」。
3. **场景评测**：具体业务指标（准确率、时延、成本、留存），衡量「落地好不好」。

评测方法对应四种范式：基准数据集（可复现）、人工评测（质量高）、模型裁判（LLM-as-judge，快而廉）、在线 A/B（真实但需流量）。

## 三、形式化与数学基础

多维评测常用加权聚合，设维度 $j$ 分数 $s_j$、权重 $w_j$：

$$
S_{\text{overall}} = \sum_{j} w_j\, s_j, \qquad \sum_j w_j = 1
$$

LLM-as-judge 把成对比较转为 Bradley-Terry 胜率模型，模型 $A$ 对 $B$ 的胜率：

$$
P(A \succ B) = \frac{\exp(\theta_A)}{\exp(\theta_A)+\exp(\theta_B)}
$$

在线 A/B 用两比例显著性检验（如双比例 z 检验）判断指标差异是否真实，而非噪声。

## 四、代码实现

用 OpenCompass 配置一次多维度评测：

```python
# 伪配置：opencompass 风格
from opencompass import OpenCompass

oc = OpenCompass(
    models=["meta-llama/Llama-3-8B", "Qwen/Qwen2-7B"],
    datasets=["mmlu", "gsm8k", "truthfulqa", "ceval"],
    eval_mode="llm_judge",          # 或 exact / ppl
)
report = oc.run()
report.aggregate(by="capability")   # 按能力维度聚合
```

## 五、与其他技术对比

| 范式 | 优点 | 局限 | 适用 |
|------|------|------|------|
| 基准 | 可复现、低成本 | 易过拟合/污染 | 能力初筛 |
| 人工 | 质量高、可信 | 贵、慢、难扩展 | 上线校验 |
| LLM 裁判 | 快、便宜、规模化 | 偏见/不一致 | 大规模预筛 |
| A/B | 真实用户信号 | 需流量、周期长 | 线上决策 |

## 六、常见误区

- 「只看单一基准」：忽视真实场景与对齐，易误判。
- 「LLM 裁判绝对可靠」：裁判自身有偏好偏差、位置偏差、长度偏差，需校准与人工抽检。
- 「分数高等于产品好」：能力≠用户价值，需场景指标。
- 「一次评测定论」：需多次采样 + 置信区间。

## 九、演进与趋势

从「刷单榜」走向「整体评估（holistic）」：HELM 主张多维度联合报告；OpenCompass 推动中文全景评测；LLM-as-judge 与 MT-Bench 等建立裁判校准方法；动态防污染基准（LiveBench 等）缓解泄露。未来趋势是「自动化 + 人类校准 + 在线信号」三层融合，以及多模态、Agent、安全红队（red-teaming）纳入统一范式。

## 十、小结

大模型评测应分能力、对齐、场景三层，结合基准、人工、LLM 裁判、A/B 四种范式。单一指标或单一基准都不足以定论，需多维聚合 + 统计严谨 + 人类校准。具体框架与最新维度以 HELM、OpenCompass 及 llm-course 为准。
