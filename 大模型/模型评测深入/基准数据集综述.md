# 基准数据集综述

> 对应 llm-course「Evaluation」章节、HELM (Liang et al., 2022)、OpenCompass 以及各基准原始论文（MMLU、GSM8K、HumanEval、TruthfulQA 等）。

## 一、背景与挑战

大模型能力评估依赖标准化基准。但基准数量爆炸、口径不一，研究者常「挑榜」证明自家模型强。核心挑战是：① 不同基准衡量不同能力，单点分数无法代表整体；② 开源基准易泄露进训练集（数据污染 contamination），高分可能来自记忆而非能力；③ 中文等语种缺乏高质量本地化基准。一份可靠的基准综述，是选型与横向对比的前提。

## 二、核心原理

基准按能力维度大致归为：知识（MMLU、C-Eval）、推理（GSM8K、MATH、BBH）、代码（HumanEval、MBPP）、真实性与安全（TruthfulQA）、常识（HellaSwag）、长上下文与 Agent（后续章节）。每个基准定义「任务格式 + 标准答案 + 评分脚本」，通过零样本/少样本 prompting 测模型，输出标准化指标（准确率、pass@k 等）。

## 三、形式化与数学基础

多数知识/推理基准用**准确率**或**精确匹配（EM）**：

$$
\text{Acc} = \frac{1}{N}\sum_{i=1}^{N} \mathbb{1}[\hat{y}_i = y_i]
$$

对于多选 MMLU，常以 5-shot 下 57 学科整体正确率为报告值；对于链式推理任务，需先抽取最终答案再比对（见「自动化评测框架」）。存在数据污染时，真实泛化误差应写作：

$$
\mathcal{E}_{\text{true}} \approx \mathcal{E}_{\text{clean}} \gg \mathcal{E}_{\text{leaked}}
$$

即用未泄露的保留集（held-out）估计才可靠。

## 四、代码实现

用 lm-evaluation-harness 跑多个基准并汇总：

```bash
# 一次性评测多个英文基准
python -m lm_eval \
  --model hf \
  --model_args pretrained=meta-llama/Llama-3-8B \
  --tasks mmlu,gsm8k,hellaswag,truthfulqa \
  --num_fewshot 5 \
  --device cuda:0 \
  --output_path results.json
```

中文基准（如 C-Eval、CMMLU）通常作为独立 task 插件加载，需指定 `fewshot` 与 `src` 分区。

## 五、与其他技术对比

| 基准 | 衡量能力 | 规模(约) | 主要风险 |
|------|----------|----------|----------|
| MMLU | 多任务知识(57学科) | 14k+ | 部分题泄露 |
| GSM8K | 小学数学推理 | 8.5k | 模板化 |
| MATH | 竞赛数学 | 12k | 难度高、方差大 |
| HumanEval | 代码生成 | 164 | 规模小、易过拟合 |
| TruthfulQA | 真实性/抗幻觉 | 817 | 主观 |
| HellaSwag | 常识推理 | 10k | 偏简单 |
| BBH | 困难 BIG-Bench | 6.5k | 综合难 |
| C-Eval/CMMLU | 中文知识 | 13k/11k | 需本地化 |

## 六、常见误区

- 「MMLU 高就等于能力强」：MMLU 偏知识记忆，不能反映推理/对齐。
- 「基准分数可直接跨榜比较」：不同 fewshot、prompt、评分脚本下不可比。
- 「公开基准分数一定可信」：需确认是否为未污染保留集，否则可能是记忆。
- 「中文只用英文基准翻译」：语言与文化差异要求本地化基准（C-Eval）。

## 九、演进与趋势

基准正从「静态题库」走向「动态/防污染」：LiveCodeBench 用竞赛后题、LiveBench 定期更新题源；从单能力到「整体评估」（HELM、OpenCompass 多维度聚合）；从自动分数到「LLM-as-judge + 人类校准」；长上下文、Agent、多模态基准快速补位。未来重点在可复现、防泄露与时间鲁棒性。

## 十、小结

基准数据集是能力评估的标尺，但「选哪把尺、怎么读」决定结论是否成立。知识、推理、代码、真实性、中文本地化各有权威基准，使用时应关注污染、可比性与维度互补。具体规模与最新版本以各基准官方仓库为准。
