# 预填充解码分离架构总览

> 对应 SplitFuse/Orca 与 DistServe（Zhong et al., 2024）；与 连续批处理深入 衔接。

## 一、背景与挑战

预填充（prefill，算密集）与解码（decode，带宽密集）异构，混部互相干扰、难分别扩缩。

## 二、核心原理

把两阶段放不同 GPU 池：prefill 实例算首 token 并产出 KV；decode 实例接管自回归生成；KV 跨实例传输。

## 三、数学形式

时延 $L=L_{prefill}+L_{KV\_transfer}+L_{decode}$；分离后各池可独立按负载扩缩。

## 四、代码实现

```python
kv = prefill_engine.encode(prompt)      # 产出 KV
tokens = decode_engine.generate(kv, max_new=256)
```

## 五、与其他对比

- 与 单体（混合）架构对照（见下节）；
- 与 树形投机解码深入 可叠加于 decode 侧。

## 六、常见误区

- 忽视 KV 传输开销致总时延反升；
- 两池比例错配致一侧重载。

## 八、面试题

- 为何分离 prefill/decode？答：二者计算特性异，分离可独立优化与扩缩、减干扰。

## 九、演进

混合 → 实例内分时 → 跨实例分离。

## 十、小结

分离架构把异构阶段解耦，是大规模服务的重要拓扑。
