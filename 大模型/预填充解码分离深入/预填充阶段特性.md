# 预填充阶段特性

> 对应 LLM 推理剖析（Orion/DistServe）。

## 一、背景与挑战

prefill 一次处理整 prompt，矩阵乘大、算力饱和，但延迟敏感（TTFT）。

## 二、核心原理

prefill 是批矩阵乘 $Q=W X$（$X$ 为整序列），可充分并行；受 compute-bound，适合大 batch 与高 MFU。

## 三、数学形式

FLOPs $\approx 2\cdot n_{layers}\cdot d_{model}\cdot L_{in}$ 前向；TTFT 主要由其决定。

## 四、代码实现

```python
logits, kv = model.prefill(prompt_ids)   # 算首 token + KV
```

## 五、与其他对比

- 与 decode（带宽密集）对照鲜明；
- 与 内存高效注意力深入 共决 TTFT。

## 六、常见误区

- 用 decode 小 batch 配置跑 prefill 致算力浪费；
- 忽略长 prompt 的 TTFT 抖动。

## 七、与开源书对应

- d2l-zh：https://github.com/d2l-ai/d2l-zh
- harvardnlp/annotated-transformer：https://github.com/harvardnlp/annotated-transformer

## 八、面试题

- prefill 是算密集还是带宽密集？答：算密集（大矩阵乘），受算力限制。

## 九、演进

串行 → 连续批 prefill → 分离 prefill 池。

## 十、小结

prefill 以算力利用为主，决定首 token 时延。
