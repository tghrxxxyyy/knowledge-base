# 指令微调实现

> 对应 rasbt/LLMs-from-scratch 第7章、Ouyang et al. 2022（InstructGPT / RLHF）、Hu et al. 2021（LoRA）。

## 一、背景与挑战

预训练模型只是"续写机器"，不懂按指令办事。SFT（Supervised Fine-Tuning）用「指令-回答」对教模型遵循任务格式。实现上的关键差异不在前向，而在 **loss mask**：只让回答部分计算交叉熵，提示部分不贡献梯度；否则模型会学着"复读"问题。此外学习率通常比预训练小一个量级，避免灾难性遗忘已学知识。数据配比（多任务混合）与模板一致性也直接决定微调后能否泛化到未见指令；其六，**数据来源**，可用人工标注、Self-Instruct 自生成或蒸馏更强模型，质量参差需清洗。

## 二、核心原理

SFT 与预训练共用因果 LM 损失，唯一区别是标签构造：把 prompt 对应位置的 label 设为 `-100`（PyTorch 的 `ignore_index`），仅 output 段保留真实 token id。训练循环与预训练完全一致：取 batch → 前向 → 带 mask 的交叉熵 → 反向 → 更新。可选进一步用 LoRA 只训低秩适配器，大幅降显存。多轮对话则每轮 assistant 内容都参与 loss、user 内容屏蔽。为提升泛化，常把多种任务（摘要、分类、翻译、QA）混合成统一指令流一起训。

## 三、形式化与数学基础

带掩码的交叉熵：设序列长度 $T$，标签 $\ell_t\in\{-100\}\cup\mathbb{V}$，损失只累加非 `-100` 位置：

$$\mathcal{L}_{\text{SFT}} = -\frac{1}{|\{t:\ell_t\ne -100\}|}
\sum_{t:\ell_t\ne -100}\log P_\theta(x_t\mid x_{<t})$$

对比预训练损失对所有 $t$ 求和。LoRA 把权重更新约束为低秩：

$$W = W_0 + \Delta W = W_0 + BA,\quad B\in\mathbb{R}^{d\times r},A\in\mathbb{R}^{r\times k},\,r\ll d$$

仅训练 $A,B$，参数量从 $O(dk)$ 降到 $O(r(d+k))$，推理时可与 $W_0$ 合并或并行挂载。

## 四、代码实现

```python
import torch.nn.functional as F

optimizer = torch.optim.AdamW(model.parameters(), lr=3e-5)  # 比预训练小
for batch in sft_loader:
    logits = model(batch["input_ids"])                 # (B,T,V)
    loss = F.cross_entropy(
        logits.view(-1, V), batch["labels"].view(-1),  # labels 中 prompt 段=-100
        ignore_index=-100)
    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    optimizer.step(); optimizer.zero_grad()
```

## 六、常见误区

- **prompt 段也参与 loss**：模型学"复述问题"，指令遵循变差。
- **学习率过大**：灾难性遗忘底座能力。
- **训练/推理模板不一致**：格式错位，回答乱套。
- **忽视 EOS**：生成不停，直到 max_len。
- **数据单一任务**：只训一类指令，泛化差，应多任务混合。
- **只训单轮**：缺多轮对话样本，长对话易崩。

## 九、演进与趋势

从单轮 SFT 走向"多轮对话 SFT"；从全量微调走向 QLoRA（4-bit 量化+LoRA）让消费级显卡可训；SFT 之后常接 RLHF/DPO 对齐人类偏好；指令数据质量（如 decontamination、LIMA 的"少而精"）比数量更关键已成为共识；课程式 SFT（先易后难）进一步提升稳定性，Self-Instruct 让小模型也能自扩指令量。

## 十、小结

指令微调的本质是"用 loss mask 把监督信号精准打在回答上"。模板一致、lr 收敛、可选 LoRA 降本、多任务混合提泛化，是把它跑通的四个要点，也是 Chat 模型诞生前的最后一步监督训练。
