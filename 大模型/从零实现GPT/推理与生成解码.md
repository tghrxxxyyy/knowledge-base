# 推理与生成解码

> 对应 rasbt/LLMs-from-scratch 第4-5章、Holtzman et al. 2019（The Curious Case of Neural Text Degeneration / 核采样）、Fan et al. 2018（分层采样）。

## 一、背景与挑战

训练完的模型要做"生成"：给定前缀自回归地吐出后续 token，直到 EOS 或达最大长度。难点在于**解码策略**——纯贪心确定性但易陷入重复循环，纯高温采样多样却可能胡言。如何平衡"连贯"与"多样"，以及如何处理 KV-cache 与上下文截断，是推理实现的核心。另外**重复惩罚（repetition penalty）**与**长度控制**也是实际产品必须处理的问题，否则易产生车轱辘话或戛然而止。

## 二、核心原理

生成即循环：取当前前缀 → 前向得最后一位 logits → 按策略得下一 token 分布 → 采样/取最大 → 拼回前缀 → 重复。常用策略：

- **贪心**：每步 $\arg\max$，确定但易重复。
- **温度采样**：$p=\text{softmax}(\logits/T)$，$T>1$ 更随机、$T<1$ 更集中。
- **Top-k**：只在概率最高的 $k$ 个 token 中重归一化再采样。
- **Top-p（核采样）**：取累计概率达 $p$ 的最小 token 集合，动态截断低概率尾部。
- **重复惩罚**：对历史出现过的 token 降低其概率，抑制车轱辘话。

## 三、形式化与数学基础

温度缩放把 logits $z$ 变为：

$$p_i = \frac{\exp(z_i/T)}{\sum_j \exp(z_j/T)}$$

核采样定义候选集 $V^{(p)}=\min\mathcal{V}$ 使 $\sum_{v\in\mathcal{V}} p_v\ge p$，再在 $V^{(p)}$ 上重归一化采样。Top-k 则是 $V^{(k)}=\{v:\text{rank}(p_v)\le k\}$。重复惩罚用因子 $\theta$ 调整：若 $x_i$ 已生成，则 $\tilde{z}_i = z_i/\theta$（$\theta>1$ 降权）。三者都抑制"长尾噪声"，Top-p 的优势是候选数随分布自适应。

## 四、代码实现

```python
import torch, torch.nn.functional as F

def generate(model, idx, ctx_len, max_new=50, T=1.0, top_k=None, top_p=None):
    for _ in range(max_new):
        logits = model(idx[:, -ctx_len:])[:, -1, :] / T      # 截断到上下文
        if top_k:
            kth = torch.topk(logits, top_k).values[:, -1:]
            logits = torch.where(logits < kth, torch.tensor(-torch.inf), logits)
        probs = F.softmax(logits, -1)
        if top_p:
            sp, order = probs.sort(descending=True)
            cum = sp.cumsum(-1)
            keep = cum - sp > top_p
            remove = order[keep]
            probs[0, remove] = 0
            probs = probs / probs.sum(-1, keepdim=True)
        next_id = torch.multinomial(probs, 1)
        idx = torch.cat([idx, next_id], dim=1)
        if next_id.item() == model.eos_id:
            break
    return idx
```

## 五、与其他技术对比

| 策略 | 多样性 | 连贯性 | 适用 |
|------|--------|--------|------|
| 贪心 | 低 | 稳定易重复 | 确定性任务 |
| 高温 | 高 | 易混乱 | 创意 |
| Top-k | 中 | 较稳 | 通用 |
| Top-p | 中高 | 平衡 | 对话/创作 |

## 六、常见误区

- **未截断上下文到 `ctx_len`**：位置越界，推理报错。
- **温度=0 仍用 multinomial**：应改 `argmax`，否则非确定性。
- **Top-k 与 Top-p 同时用却冲突**：需明确优先级或只取其一。
- **忽略 EOS 提前 break**：生成无限拉长。
- **不做重复惩罚**：长文本出现反复啰嗦的循环句。

## 九、演进与趋势

解码从"采样"走向"约束生成"（JSON/正则受限解码，如 guidance、outlines）；推理引擎用 KV-cache 与 PagedAttention（vLLM）大幅提吞吐；投机解码与 Medusa 加速自回归；长上下文与流式输出成为产品标配；基于搜索的"最佳 N 候选（best-of-n）+ 奖励模型"常用于质量敏感场景。

## 十、小结

生成解码是"采样策略 + 上下文管理 + 终止控制"的组合拳。Top-p 兼顾多样与合理、温度调可控性、EOS 收尾、重复惩罚抑啰嗦，理解这些才能调出既通顺又不复读的文本。
