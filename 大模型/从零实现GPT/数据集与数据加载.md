# 数据集与数据加载

> 对应 rasbt/LLMs-from-scratch 第2章、HuggingFace `datasets` 与 `torch.utils.data` 文档。

## 一、背景与挑战

语言建模是"下一个 token 预测"。把一长串文本变成可批量训练的样本，核心是构造 `(x, y)` 滑动窗口对，并保证**不跨文档泄漏**。难点：超长语料的样本高度重叠需高效处理；训练/验证集应按文档切分以防验证集"偷看"训练内容；`batch_size × ctx_len` 直接决定显存占用；token 化应在离线阶段完成以避免每步重复编码；多 worker 加载时需固定随机种子保证可复现；文档边界处理不当会让一条样本混入两篇不相关文本；其六**样本打包（packing）**，padding 浪费显存，需把多文档拼满定长以提升吞吐。

## 二、核心原理

把整份语料编码为 id 序列后，用长度为 `ctx_len` 的滑窗生成样本：`x` 取位置 $[i, i+\text{ctx\_len})$，`y` 取 $[i+1, i+\text{ctx\_len}+1)$，即 `y` 是 `x` 右移一位。用 `Dataset.__getitem__` 按需切片，`DataLoader` 负责批处理与打乱。**文档边界**需在组 batch 前处理（如丢弃跨文档窗口或加 BOS），防止一条样本拼接两篇不相关文本。大规模场景改用内存映射或流式加载；用 packing 把若干短文档拼接成定长块，减少 pad。

## 三、形式化与数学基础

给定 token 序列 $s=(s_1,\dots,s_N)$，滑窗产生样本对：

$$x^{(i)} = (s_i, s_{i+1}, \dots, s_{i+L-1}),\quad y^{(i)} = (s_{i+1},\dots,s_{i+L})$$

目标为最大化：

$$\mathcal{L} = -\sum_{t=1}^{L}\log P_\theta(s_{i+t}\mid s_{i:i+t-1})$$

共 $N-L$ 个样本。批大小 $B$、上下文 $L$、词表 $V$ 时，单步显存约 $O(B\cdot L\cdot d_{\text{model}})$（前向）+ 优化器状态。为防泄漏，训练集索引集 $\mathcal{I}_{\text{train}}$ 与验证集 $\mathcal{I}_{\text{val}}$ 须满足文档不相交；packing 后文档间以特殊分隔符断开。

## 四、代码实现

```python
import torch
from torch.utils.data import Dataset, DataLoader

class TextDataset(Dataset):
    def __init__(self, ids: list[int], ctx_len: int):
        self.ids = ids
        self.ctx_len = ctx_len
    def __len__(self):
        return len(self.ids) - self.ctx_len
    def __getitem__(self, i):
        x = torch.tensor(self.ids[i:i + self.ctx_len])
        y = torch.tensor(self.ids[i + 1:i + 1 + self.ctx_len])
        return x, y

# 训练/验证按文档切分，避免跨文档泄漏
train_ids, val_ids = split_by_document(corpus_ids)
train_loader = DataLoader(TextDataset(train_ids, 256), batch_size=16,
                          shuffle=True, num_workers=4)
val_loader = DataLoader(TextDataset(val_ids, 256), batch_size=16, shuffle=False)

# packing：把多文档拼满定长，减少 padding 浪费
def pack(docs, L):
    buf, out = [], []
    for d in docs:
        buf += [BOS] + d
        while len(buf) >= L:
            out.append(buf[:L]); buf = buf[L:]
    return out
```

## 五、与其他技术对比

| 方式 | 重叠 | 效率 | 文档隔离 |
|------|------|------|----------|
| 滑窗 | 高 | 高 | 需手动 |
| 不重叠块 | 低 | 中 | 天然 |
| 流式+packing | 中 | 高 | 配置 |

## 六、常见误区

- **y 不是 x 右移一位**：自回归目标错位，学不到续写。
- **跨文档滑窗**：样本混入两篇文本，污染训练。
- **每步重复 tokenize**：CPU 瓶颈，应离线编码。
- **batch 跨越文档未处理**：BOS/分隔缺失致语义混乱。
- **多 worker 种子不同**：数据顺序不可复现，实验难比对。
- **shuffle 不按文档**：把同文档切进训练与验证，泄漏。

## 九、演进与趋势

从内存滑窗走向**内存映射 + 流式加载**（如 `IndexedDataset`、HuggingFace 流式），支撑 TB 级语料；packing 把多文档拼满固定长度减少 padding 浪费；分布式 `IterableDataset` 成为大规模预训练标配；样本加权（按领域/质量）让数据配比可控，并用高效索引支持按权重采样。

## 十、小结

数据加载的本质是"把连续文本切成对的滑窗样本，并守住文档边界"。`(x, y)` 错位一位即自回归目标，离线 tokenize + 按文档切分 + packing 提吞吐，是规模化的两个基本功与一个优化常识。
