# 文本表征与词元化实现

> 对应 rasbt/LLMs-from-scratch 第2章（Working with Text Data）、Sennrich et al. 2016（BPE）。

## 一、背景与挑战

模型只吃整数。把文本变成可训练 id 序列是第一步，称为词元化（tokenization）。粒度选择决定序列长度与词汇表大小：字符级简单但序列长、难建模词意；子词级（BPE/WordPiece）在"词表小"与"序列短"间取得平衡，是 GPT 系列的标准。难点：训练/推理必须用同一 tokenizer，否则词表错位；特殊 token（BOS/EOS/PAD/UNK）需统一处理；中文等无空格语言需子词切分；同一字符串在不同 tokenizer 下 id 不同，"token 计数"直接影响上下文长度预算；其六**下游影响**，分词粒度会改变有效上下文长度与位置编码范围，进而影响长文本任务表现。

## 二、核心原理

子词 BPE 从字符出发，反复合并"最高频相邻对"构建词表，使常见词保留为整 token、罕见词拆成子词。编码 = 文本 → 子词序列 → id；解码 = id → 子词 → 拼接还原文本。生产用 `tiktoken`（GPT-2/3/4 系列）或 `tokenizers`（HuggingFace，BPE/WordPiece 快速实现）。教学常用字符级降低门槛，但生产 GPT 一律 BPE。现代多用语字节级 BPE（BBPE），先按 UTF-8 字节再合并，彻底消除 UNK。分词器在预训练前需与词表、上下文长度一并规划。

## 三、形式化与数学基础

BPE 合并规则按相邻对频率最大化：

$$(a^\star,b^\star)=\arg\max_{(a,b)} \text{count}(ab)$$

逐轮把 $ab$ 替换为新符号，直到词表达目标大小 $|\mathcal{V}|$。编码可视为把字符串 $S$ 映射到 token 序列 $\tau=(t_1,\dots,t_m)$ 使 $\text{decode}(\tau)=S$ 且 $|\tau|$ 最小（贪心最长短语匹配）。字符级则 $\mathcal{V}=\Sigma$（字符集），序列长度 $|S|$ 远大于子词级。BBPE 先令 $\Sigma$ 为 256 字节，再在字节上合并，故任意 UTF-8 字符串皆可无损编码。

## 四、代码实现

```python
import tiktoken

enc = tiktoken.get_encoding("gpt2")              # 生产用 BPE
ids = enc.encode("Hello, GPT from scratch!")
print(ids, enc.decode(ids))                       # 编码/解码可逆

# 教学：字符级 tokenizer
class CharTokenizer:
    def __init__(self, text):
        chars = sorted(set(text))
        self.stoi = {c: i for i, c in enumerate(chars)}
        self.itos = {i: c for i, c in enumerate(chars)}
    def encode(self, s): return [self.stoi[c] for c in s]
    def decode(self, ids): return "".join(self.itos[i] for i in ids)
```

## 六、常见误区

- **训练/推理用不同 tokenizer**：词表错位，输出全错。
- **解码未处理特殊 token**：BOS/EOS/PAD 残留成乱码。
- **中文按字符当 BPE**：应确认 tokenizer 含中文子词表。
- **忽略 pad 长度对齐**：batch 内长度不一未 padding。
- **用字符数估上下文**：实际按 token 数算，中文常 1 字≈1–2 token。
- **emoji/特殊字符漏测**：非常规 Unicode 可能拆成多字节 token，长度超预期。

## 九、演进与趋势

从 BPE 到 **BBPE（字节级 BPE）** 彻底消除 UNK，任何语言/表情皆可编码；Unigram（SentencePiece）以概率删词替代合并；分词与模型联合优化（如 ByT5 直接字节输入）成为去分词化探索方向；分词器在预训练前需与词表、上下文长度一并规划，并随多语料扩展词表。

## 十、小结

词元化是"文本→整数"的桥梁。BPE 以子词平衡词表与序列长度，是 GPT 的事实标准；训练推理同 tokenizer、特殊 token 规范处理、按 token 而非字符规划上下文、留意非常规字符的长度膨胀，是这条链路不出错的四道闸门。
