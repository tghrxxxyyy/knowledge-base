# 企业知识库 RAG 落地实战

> 板块：大模型 　|　 返回：[README](README.md)
> 覆盖：知识库 RAG 的文档接入、切分、索引、检索、生成、权限与运营。详见 [RAG/02-RAG进阶与召回优化实战](../RAG/02-RAG进阶与召回优化实战.md)。

与个人问答不同，企业知识库面对：多格式文档（PDF/Word/Confluence/工单）、强权限（部门隔离）、高频更新、准确性要求高、需可溯源。RAG 是把企业私有知识「接进来、找得准、答得对、可追溯」的工程。本文从链路到运营系统拆解。

## 一、企业知识库的特殊性

- **多格式**：PDF/Word/PPT/网页/工单/代码，解析难度不一。
- **强权限**：部门/角色隔离，A 不能搜到 B 的机密文档。
- **高频更新**：制度/价格/手册频繁变更，索引要跟上。
- **准确性**：答错可能误导业务决策，比闲聊要求高。
- **可溯源**：回答要能指向原文，便于核验与追责。

## 二、整体链路

```
文档源(对接) → 解析清洗 → 切分 → 向量化 + 关键词索引 → 入库
                                ↓
用户问 → 召回(混合) → 重排 → 上下文组装 → LLM 生成 → 带引用返回
```

每个环节都有"企业级"特殊要求（权限、脱敏、溯源）。

## 三、文档接入与解析

- **数据源**：文件系统、对象存储、Confluence/Wiki、数据库、工单系统（Jira/钉钉）。
- **解析**：PDF/Word/PPT 提取文本与表格；扫描件需 OCR；保留标题层级与页码便于溯源。
- **清洗**：去噪（页眉页脚/重复）、去密（脱敏）、格式归一（Markdown）。
- **元数据采集**：来源、部门、更新时间、权限标签、文档类型、密级。

## 四、切分策略

- 按语义/标题结构切，避免切断上下文（见 [RAG/02](../RAG/02-RAG进阶与召回优化实战.md) 的父子块/句子窗口）。
- 企业文档常有长表格、代码块，需特殊处理（表格整体保留、代码按块）。
- 块大小：一般 300–800 token，配合检索精度调。
- 保留块级元数据：所属文档、章节、页码，供引用与过滤。

## 五、索引与混合检索

- **向量索引**：ANN（HNSW/IVF），语义召回。
- **关键词索引**：BM25，对专有名词/编号/术语更准。
- **混合**：RRF 或加权融合，召回更稳。
- **元数据过滤**：先按部门/时间/权限过滤再向量检索，保证「只能搜到能看的」。

## 六、重排与查询改写

- **重排**：cross-encoder（如 BGE-Reranker）对 top-50 精排取 top-5。
- **查询改写**：口语化问题改写成检索友好 query；多跳问题拆多路检索。
- 详见 [RAG/02-RAG进阶与召回优化实战](../RAG/02-RAG进阶与召回优化实战.md)。

## 七、权限与合规（企业级核心）

- **检索即鉴权**：召回阶段用用户身份过滤可访问文档，**绝不先召回后裁剪**（会泄露片段到上下文，模型可能复述）。
- **脱敏**：入库前对 PII 脱敏；生成时对敏感内容打码。
- **审计**：记录谁问了什么、引用了哪篇，便于追溯与纠错。
- 合规要求见 [开源项目/12-安全合规与秘钥管理](../../开源项目/12-安全合规与秘钥管理.md)。

## 八、生成与溯源

- **Prompt 约束**：只基于给定上下文回答，上下文不足时明确说「知识库未覆盖」，**禁止编造**。
- **引用**：返回段落到原文（文档+页码/段落 ID），让用户可核验。
- **置信度**：低相关时提示用户补充信息或转人工。

## 九、评测与运营

- **标注集**：建 ≥200 条业务问答，测召回率与答案忠实度（Ragas / DeepEval）。
- **反馈闭环**：用户点赞/点踩、纠错，反哺切分与检索调优。
- **更新机制**：文档变更触发增量重建（避免全量重算），删除文档同步清理索引。
- **监控**：检索命中率、答案置信度、高频无结果问题（发现知识盲区）。

## 十、与 NL-to-SQL / Agent 的关系

- 结构化数据查询走 NL-to-SQL（见用户 Dify 工作流），非结构化文档走 RAG。
- 复杂任务可 Agent 编排：先 RAG 取文档，再调工具/SQL，最后综合生成。

## 十一、常见坑

1. **不鉴权先召回** → 越权看到别人文档（合规事故）。
2. **切块丢标题层级** → 上下文断裂答非所问。
3. **只用向量忽略 BM25** → 专有名词/编号召回差。
4. **让模型自由发挥** → 编造知识库没有的内容。
5. **不做评测** → 改了不知好坏，无法量化改进。
6. **文档更新不重建索引** → 回答过期，失去信任。
7. **忽略增量** → 全量重建成本高、时效差。

## 十二、落地清单

1. 梳理数据源与权限模型。
2. 建解析 + 清洗 + 脱敏管线。
3. 语义切分 + 父子块 + 元数据。
4. 混合检索 + 元数据过滤。
5. 加重排 + 查询改写。
6. 生成约束 + 引用 + 置信度。
7. 标注集评测 + 反馈闭环 + 增量更新。
