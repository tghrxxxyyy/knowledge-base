# 专家并行与容量因子

> 对应 Fedus et al., 《Switch Transformers》, 2021。

## 一、背景与挑战

每专家处理 token 数需上限，否则显存/算力不可控。

## 二、核心原理

容量因子 $cap$ 决定每专家最多 token 数 $C$；超过则丢弃（或多专家共享）；调 $cap$ 在质量与资源间权衡，典型 1.0-1.25。

## 三、数学形式

$C = \lceil \frac{k T}{E}\cdot cap\rceil$；溢出率随分布不均与 $cap$ 降。

## 四、代码实现

```python
capacity = int(k * tokens / experts * cap_factor)
mask = dispatched_tokens < capacity
```

## 五、与其他对比

- 与 负载均衡 互补（容量防溢出）。
- 与 混合并行深入 资源规划相关。

## 六、常见误区

- cap 过小丢太多 token 降质量。
- cap 过大显存浪费且不均。

## 八、面试题

- 容量因子怎么选？答：在溢出率与显存间权衡，常 1.0-1.25 并配负载损失。

## 九、演进

固定 → 动态容量 → 无丢弃路由。

## 十、小结

容量因子约束每专家负载，是 MoE 稳定训练必需。
