# 专家并行与路由

> 对应 Lepikhin et al., 《GShard: Scaling Giant Models with Conditional Computation》, 2020；Switch Transformer, 2021。

## 一、背景与挑战

路由决定 token 去哪专家，影响质量、负载与通信。

## 二、核心原理

门控 $G=softmax(W_g x)$，top-k 选专家；GShard 用专家容量与辅助负载损失；Switch 用 top-1 简化；路由可在专家维 all-to-all 分发 token。

## 三、数学形式

门控 $g(x)=softmax(W_g x)$；负载损失 $L_{aux}=\alpha\cdot E\cdot \sum_i f_i\cdot P_i$（$f_i$ 分配率、$P_i$ 路由概率）。

## 四、代码实现

```python
logits = gate(x); w = softmax(logits, -1)
topk_val, topk_idx = w.topk(k)
dispatch = all_to_all(x, topk_idx)         # 按专家分发
```

## 五、与其他对比

- 与 数据并行深入 路由不同（DP 不分发 token）。
- 与 序列并行深入 在注意力处可并存。

## 六、常见误区

- top-k 过大失稀疏优势。
- 无负载损失致专家不均。

## 八、面试题

- 为何要负载均衡损失？答：防路由集中使部分专家饿死、算力浪费。

## 九、演进

top-k → top-1(Switch) → 分组路由。

## 十、小结

路由是 MoE 核心，需平衡质量、负载与通信。
