# 专家并行通信（All-to-All）

> 对应 GShard / Switch 并行实现；Lepikhin et al., 2020。

## 一、背景与挑战

token 按路由去不同卡上的专家，需跨卡分发与收集。

## 二、核心原理

分发阶段 all-to-all 把 token 按目标专家送到对应卡；各卡算本地专家；组合阶段再 all-to-all 送回原卡；通信量正比 token 数。

## 三、数学形式

通信量 $C_{moe}\approx 2\cdot T\cdot h\cdot 2$ 字节（两次 all-to-all）；与专家数/卡数相关。

## 四、代码实现

```python
sent = dist.all_to_all(tokens_by_expert, group=ep_group)  # 分发
out = experts_local(sent)
got = dist.all_to_all(out, group=ep_group)                # 收回
```

## 五、与其他对比

- 与 张量并行深入 all-reduce 不同（此处 all-to-all 按专家）。
- 跨节点 all-to-all 带宽敏感。

## 六、常见误区

- 未合并两次 all-to-all 增开销。
- 专家分布不均致通信长尾。

## 八、面试题

- 专家并行为何用 all-to-all？答：token 按路由去各卡专家，需分发与回收两次交换。

## 九、演进

全收集 → all-to-all → 分组路由降通信。

## 十、小结

专家并行通信是 all-to-all，规模受跨节点带宽限制。
