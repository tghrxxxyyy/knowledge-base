# 推理服务化与模型部署实战

> 板块：大模型 　|　 返回：[README](README.md)
> 适用：把训练好的模型（LLM/多模态/小模型）变成高吞吐、低延迟、可扩展的在线服务。

训练出模型只是第一步，能否**高效、稳定、低成本地服务线上流量**才是落地关键。本文聚焦推理服务化架构、吞吐优化与部署形态。

## 一、推理服务瓶颈

| 瓶颈 | 原因 | 优化 |
|------|------|------|
| 显存 | 权重 + KV Cache + 激活 | 量化、分页注意力 |
| 计算 | 矩阵乘、decode 自回归 | 批处理、算子优化 |
| 延迟 | 自回归逐 token | 投机解码、并行 |
| 吞吐 | 并发低 | 连续批处理（continuous batching） |

## 二、推理服务架构

```
网关/路由 → 推理服务(多副本) → GPU 推理引擎(vLLM/TensorRT-LLM)
                ↓                        ↓
           负载均衡                 模型权重 + KV Cache 管理
                ↓
           监控(延迟/吞吐/GPU利用率)
```

- **推理引擎**：vLLM（PagedAttention、连续批处理）、TensorRT-LLM（极致优化）、Triton（多框架）、SGLang。
- **服务框架**：FastAPI/TGI（Text Generation Inference）、Ray Serve。
- **路由**：按模型/版本/负载路由，支持灰度。

## 三、关键优化技术

### 3.1 量化（Quantization）

| 方法 | 精度 | 显存节省 | 质量损失 |
|------|------|----------|----------|
| FP16/BF16 | 半精度 | ~2x | 极小 |
| INT8 | 8位 | ~4x | 小 |
| GPTQ/INT4 | 4位 | ~8x | 中等 |
| AWQ | 4位 | ~8x | 较小（激活感知） |

> 量化是显存与成本的杠杆：INT4 可让 70B 模型在单卡跑起来，但需评估质量。

### 3.2 KV Cache 与 PagedAttention

- 自回归生成需缓存历史 Key/Value，KV Cache 随序列增长。
- **PagedAttention（vLLM）**：像操作系统分页一样管理 KV Cache，减少碎片，提升显存利用率与并发。
- 长上下文场景 KV Cache 是显存主消耗，需重点优化。

### 3.3 连续批处理（Continuous Batching）

- 传统静态批处理：等齐一批再算，短请求等长的。
- 连续批处理：token 级动态组批，完成即出，显著提升 GPU 利用率。

### 3.4 投机解码（Speculative Decoding）

- 用小模型/草稿快速预测多个 token，大模型一次验证，加速 decode 阶段。

## 四、部署形态

| 形态 | 说明 | 适用 |
|------|------|------|
| 单机单卡 | 简单 | 小模型/测试 |
| 多卡多副本 | 横向扩展 | 生产常用 |
| 张量并行 | 单模型切多卡 | 超大模型 |
| 流水线并行 | 层切分 | 超大模型 |
| 量化+小卡 | 降本 | 成本敏感 |

## 五、弹性与成本

- **GPU 利用率**：监控 SM 利用率、显存，低利用率=浪费。
- **自动扩缩容**：按队列长度/延迟扩副本；闲时缩容省钱。
- **混部**：推理与训练错峰混部，提升集群利用率。
- **按需实例**：突发用按量 GPU，常态用包年。

## 六、可观测

- **指标**：首 token 延迟（TTFT）、每 token 延迟（TPOT）、吞吐（tokens/s）、队列长度、GPU 利用率。
- **质量**：输出打分、幻觉率、用户反馈。
- **成本**：token 成本、GPU 小时成本。

## 七、常见问题

1. **显存爆** → OOM；量化 + PagedAttention + 限长。
2. **延迟高** → 无批处理；连续批处理 + 投机解码。
3. **吞吐低** → GPU 空转；动态批处理 + 并发调优。
4. **成本失控** → 常驻大卡；量化 + 弹性 + 混部。
5. **长上下文慢** → KV Cache 大；限制长度 + 优化注意力。
6. **版本混乱** → 多模型并存出错；模型注册 + 路由灰度。
