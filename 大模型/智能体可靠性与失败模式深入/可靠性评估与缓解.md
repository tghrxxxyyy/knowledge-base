# 可靠性评估与缓解

> 对应 AgentBench 多维可靠性与 ToolEmu 风险评测。

## 一、背景与挑战

可靠性提升需可量化：哪些模式已压住、哪些仍频发、加固是否真有效。

## 二、核心原理

建立失败模式监控面板：每类失败的发生率、平均修复成本、用户影响。用故障注入（见错误恢复章）规模化复现，迭代加固直至长尾可控。报告 p95 表现而非仅均值。

## 三、数学形式

可靠性得分：

$$S_{rel} = 1 - \frac{1}{K}\sum_k w_k \cdot P(fail_k)$$

$w_k$ 为第 $k$ 类失败权重（按影响）。

## 四、代码实现

```python
panel = {m: rate(m) for m in FAIL_MODES}
report(p95(panel))
```

## 五、与其他对比

- 与 错误恢复评估基准 / 安全评估基准 同属量化闭环。
- 与 可靠性与失败模式总览 首尾呼应。

## 六、常见误区

- 只看均值，长尾致命失败被掩盖。
- 加固后不复测，不知是否真有效。

## 八、面试题

- 为何看 p95 可靠性？答：均值掩盖偶发但高影响的失败，p95 反映最坏常态。

## 九、演进

 anecdotal → 分类计数 → 加权面板+故障注入复测。

## 十、小结

可靠性评估把“加固”变成可验证的闭环，长尾可控才算真可靠。
