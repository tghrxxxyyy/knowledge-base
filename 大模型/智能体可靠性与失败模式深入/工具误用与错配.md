# 工具误用与错配

> 对应 ToolEmu 风险评测中的工具误用场景。

## 一、背景与挑战

agent 可能选错工具、传错参数、误读返回，或对工具能力过度/错误假设（如以为能写文件实则只读）。

## 二、核心原理

根因：工具描述不清、参数 schema 未约束、返回未校验。加固：工具元数据含精确能力/参数约束、调用前 schema 校验、返回后按契约校验（见错误恢复章）。

## 三、数学形式

误用概率随描述模糊上升：

$$P(misuse) \propto \frac{1}{clarity(spec)} + \frac{1}{constraint(schema)}$$

## 四、代码实现

```python
if not schema.validate(args):
    raise BadArgs(tool, args)
out = tool(**args)
```

## 五、与其他对比

- 与 校验与回滚 / 异常分类与重试 共担参数与返回治理。
- 与 智能体安全与权限沙箱深入 共担越权误用。

## 六、常见误区

- 工具描述写“能做一切”致错误假设。
- 仅校验类型不校验语义范围。

## 八、面试题

- 如何降工具误用？答：精确工具描述+参数 schema 校验+返回契约校验。

## 九、演进

无约束 → 类型校验 → 语义+能力精确描述。

## 十、小结

工具误用靠“清晰契约+双重校验”治理，把模糊期望变成硬约束。
