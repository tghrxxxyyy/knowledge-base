# 循环与卡死

> 对应 agent 无限循环（infinite loop）与停滞（stall）分析。

## 一、背景与挑战

agent 可能在“反思→同样错误→再反思”中打转，或等待永远不来的工具结果，消耗预算且无产出。

## 二、核心原理

根因：无进展检测、反思不更新策略、缺少终止条件。加固：监测状态/动作重复度，连续 $k$ 步无进展则强制换策略或升级人工；对所有等待设超时。

## 三、数学形式

重复度检测：

$$rep_t = \mathbb{1}[a_t = a_{t-1} = \dots = a_{t-k+1}]$$

$rep_t$ 持续为真即触发干预。

## 四、代码实现

```python
if len(set(recent_actions[-K:])) == 1:
    switch_strategy()  # 或 escalate
```

## 五、与其他对比

- 与 成本预算与早停 共用停止逻辑。
- 与 规划与反思成本权衡 防止反思死循环。

## 六、常见误区

- 仅靠最大步数硬截断，未区分“有进展长任务”。
- 超时设 0 或未设，永久挂起。

## 八、面试题

- 如何检测卡死？答：监测近期动作/状态重复度，连续无变化即判定停滞。

## 九、演进

硬截断 → 进展检测 → 自动换策略+人工升级。

## 十、小结

循环靠“进展监测+多样化解”破解，把死循环变成可控异常。
