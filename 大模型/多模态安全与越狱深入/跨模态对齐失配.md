# 跨模态对齐失配

> 对应 Qi et al., AAAI 2024；Liu et al., MM-SafetyBench, ECCV 2024；与 Bai et al., 2022 的纯文本安全对齐对照。

## 一、背景与挑战

「已对齐的语言模型接上视觉编码器后安全性下降」这一现象，需要一个比「数据没覆盖」更精确的解释。核心在于：安全行为是在语言模型的文本嵌入分布上学到的判别边界，而视觉连接层把图像映射进来的向量并不落在这个分布内，边界在那里没有定义。

## 二、核心原理

三个失配层次。表示失配：视觉 token 经投影后进入语言模型的嵌入空间，但其分布与文本 token 嵌入的分布存在系统性差异，安全相关的方向在视觉子空间上未被约束。训练目标失配：视觉指令微调优化的是描述与问答准确性，损失里没有任何拒答信号，梯度会把语言模型的部分安全倾向一并覆盖（与下游微调破坏安全对齐同源）。层级失配：安全判断往往依赖较深层的语义特征，而视觉信息注入发生在输入层，经过多层混合后可能绕过原有的判别路径。工程含义是：只在语言侧补安全数据不够，必须让安全样本包含视觉 token，才能在视觉子空间上重新定义边界。

## 三、数学形式

设文本嵌入分布 $P_t$、投影后的视觉嵌入分布 $P_v$，安全策略等价于在嵌入空间上学到的判别函数 $g$。安全泛化误差可用分布差异上界刻画：

$$\big|\mathbb E_{P_v}[\ell(g)]-\mathbb E_{P_t}[\ell(g)]\big|\ \le\ C\cdot d\big(P_v,\,P_t\big)$$

其中 $d$ 为某种分布距离（如 MMD 或 $\mathcal H$-divergence）。$d(P_v,P_t)$ 越大，纯文本安全训练向视觉输入的迁移越不可靠——这给出了「安全不跨模态迁移」的形式化表述。

## 四、代码实现

```python
import torch

def mmd_gap(text_emb, vis_emb, sigma=1.0):
    # 用 RBF-MMD 粗测两种模态嵌入的分布差异，作为安全迁移风险的代理指标
    def k(a, b):
        d2 = ((a[:, None, :] - b[None, :, :]) ** 2).sum(-1)
        return torch.exp(-d2 / (2 * sigma ** 2))
    m, n = len(text_emb), len(vis_emb)
    return (k(text_emb, text_emb).sum() / (m * m)
            + k(vis_emb, vis_emb).sum() / (n * n)
            - 2 * k(text_emb, vis_emb).sum() / (m * n)).item()

@torch.no_grad()
def refusal_direction_projection(model, safe_dir, vis_tokens):
    # 检查视觉 token 在“拒答方向”上的投影是否被压制
    return (vis_tokens @ safe_dir / safe_dir.norm()).mean().item()
```

## 五、与其他对比

- 与 微调破坏安全对齐：视觉指令微调是「无害数据破坏安全」的一个具体实例。
- 与 多模态安全总览：这里给出失配的形式化视角，那里给出攻击面全景。
- 与 表示对齐相关主题：安全是表示对齐质量的下游体现之一。

## 六、常见误区

- 认为冻结语言模型只训连接层就能保住安全。连接层同样能把有害语义送入模型，边界仍未被定义。
- 用文本安全集验证多模态模型的安全性。测的是 $P_t$ 上的边界，与 $P_v$ 上的行为无关。
- 把失配简单归因为「视觉编码器太弱」。即使视觉表示很强，只要安全信号未在视觉输入上训练过，边界依然缺失。

## 八、面试题

- 用一句话解释安全为何不跨模态迁移？答：安全是嵌入空间上的判别边界，视觉嵌入分布与文本嵌入分布存在差异，边界在视觉子空间上未被训练定义。
- 冻结语言模型能避免安全退化吗？答：不能。有害语义仍可经连接层注入，且安全边界在视觉输入分布上依然缺失。

## 九、演进

文本安全对齐 → 接入视觉后观察退化 → 用表示分布差异解释失配 → 在视觉输入上补安全训练 → 跨模态统一的安全目标。

## 十、小结

跨模态对齐失配把「安全不迁移」讲成了分布差异问题：新增模态即新增未定义边界的输入子空间，必须在该子空间上重新训练安全行为。
