# 提示缓存工作原理

> 对应 Anthropic Prompt Caching 技术文档；KV Cache 基础。

## 一、背景与挑战

理解缓存如何命中与失效，才能正确设计前缀。

## 二、核心原理

请求到达时引擎对前缀做哈希/分块定位缓存；若前缀与已缓存完全一致则复用 KV，否则重算并写入；缓存按 TTL 或容量淘汰。

## 三、数学形式

命中函数 $H(x)=\mathbf 1[\text{prefix}(x)\in \text{Cache}]$；命中时算力 $O(L_{new})$ 而非 $O(L_{total})$。

## 五、与其他对比

- 与 推理经济成本深入 衔接（计费）。

## 六、常见误区

- 在缓存前缀中插入可变内容（用户 id）破坏命中。
- 忽视最小缓存长度门槛。

## 八、面试题

- 缓存为何要求前缀一致？答：KV 按前缀定位，任何字节变化都使哈希失配、无法复用。

## 九、演进

按请求缓存 → 断点标记 → 分层 TTL。

## 十、小结

提示缓存靠前缀一致命中，设计须把可变内容移到末尾。
