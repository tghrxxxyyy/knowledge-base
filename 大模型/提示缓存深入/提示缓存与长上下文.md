# 提示缓存与长上下文

> 对应长上下文技术（128K+）；上下文压缩深入 衔接。

## 一、背景与挑战

长系统提示/长文档反复发送，上下文越长缓存价值越高。

## 二、核心原理

将固定长文档置于缓存前缀，多轮问答仅变用户部分，复用长 KV，避免每轮重算长 prefill。

## 三、数学形式

省算 $E = L_{doc}\cdot (C_{pf}-C_{hit})$；文档越长省得越多。

## 四、代码实现

```python
sys=[{"type":"text","text":DOC,"cache_control":{"type":"ephemeral"}}]
for q in questions: ask(messages=[{"role":"user","content":q}])
```

## 五、与其他对比

- 与 长文档切分深入（RAG 免塞全文）替代方案对照。
- 与 前缀缓存深入 同目标不同层。

## 六、常见误区

- 文档频繁更新致缓存频繁失效。
- 长上下文替代 RAG 而忽略成本。

## 八、面试题

- 长文档为何适合缓存？答：长前缀固定且多轮复用，省去重复长 prefill 计算。

## 九、演进

每轮重发 → 缓存长前缀 → 动态文档分块缓存。

## 十、小结

提示缓存是长上下文多轮场景的降本利器，配合稳定文档前缀。
