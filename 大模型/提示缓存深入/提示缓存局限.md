# 提示缓存局限

> 对应缓存一致性（CAP 权衡）；推理经济成本深入 衔接。

## 一、背景与挑战

缓存非银弹，有范围、TTL、一致性限制。

## 二、核心原理

缓存按租户/模型隔离；前缀变化即失效；TTL 短致高重复仍可能 miss；并发写入有竞争。

## 三、数学形式

有效命中 $\alpha_{eff}=\alpha\cdot \mathbf 1[t_{now}-t_{write}<TTL]$；过期即 0。

## 四、代码实现

```python
if (now - cache_ts) > TTL:
    refresh_cache()   # 重新写入，全价
```

## 五、与其他对比

- 与 语义缓存深入（按语义而非字节）互补解决失效。
- 与 前缀缓存深入（进程内）范围不同。

## 六、常见误区

- 期待跨模型/跨账号共享缓存。
- 忽略 TTL 致以为命中实为重写。

## 八、面试题

- 提示缓存为何会 miss？答：前缀变化、TTL 过期或租户/模型不匹配均致失配。

## 九、演进

单租户 → 隔离租户 → 跨请求共享优化。

## 十、小结

提示缓存受 TTL 与一致性约束，需配合语义缓存覆盖变前缀场景。
