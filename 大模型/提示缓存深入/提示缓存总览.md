# 提示缓存总览

> 对应 Anthropic, *Prompt Caching*（2024）；OpenAI, *Prompt Caching* 文档。

## 一、背景与挑战

重复前缀（系统提示、长文档、few-shot）每轮重算贵；缓存可复用已处理的前缀，降本提速。

## 二、核心原理

将命中的前缀 KV 缓存在服务端，后续请求复用；命中部分按更低缓存价计费，未命中走全价。

## 三、数学形式

成本 $C = C_{hit}\cdot L_{cached} + C_{full}\cdot L_{new}$，其中 $C_{hit}\ll C_{full}$；延迟省去前缀 prefill。

## 四、代码实现

```python
r = client.messages.create(
    model="claude-3-5-sonnet",
    system=[{"type":"text","text":LONG,"cache_control":{"type":"ephemeral"}}],
    messages=[{"role":"user","content":q}])
```

## 五、与其他对比

- 与 前缀缓存深入（引擎层 KV 复用）互补，提示缓存是 API 层语义化缓存。
- 与 语义缓存深入（按语义命中）不同。

## 六、常见误区

- 前缀不固定致无法命中（如时间戳在系统提示）。
- 误以为缓存无限期，TTL 过期后重新计费。

## 八、面试题

- 提示缓存为何降本？答：复用前缀 KV，命中段按低价计费且省 prefill 计算。

## 九、演进

无缓存 → 服务端 KV 缓存 → API 显式缓存断点。

## 十、小结

提示缓存复用稳定前缀的 KV，是降本提速的关键 API 能力。
