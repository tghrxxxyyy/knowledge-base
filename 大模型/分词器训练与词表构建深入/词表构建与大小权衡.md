# 词表构建与大小权衡

> 对应 Touvron et al., *LLaMA*, 2023（32K 词表省算力）；Brown et al., *GPT-3*, 2020（50K+）；参数量分析。

## 一、背景与挑战

词表大则序列短但 embedding 参数量大；词表小则序列长、算力高。

## 二、核心原理

embedding 参数约 $|V|\times d$；词表大降低序列长度与 attention 成本。LLaMA 选 32K 在算力与长度间折中；多语常更大。

## 三、数学形式

总参数 $\approx |V|d + L\cdot(\text{layers})$；序列长度 $T\propto 1/\text{avg\_tok\_per\_word}$；需联合优化。

## 四、代码实现

```python
emb_params = vocab_size * d_model
print(emb_params / 1e6, "M params")
```

## 五、与其他对比

- 与 多语种分词与挑战深入（多语需更大词表）衔接。
- 与 数据混合比例课程深入 无关，但词表影响有效 token。

## 六、常见误区

- 词表过小致中文等被切成大量单字，序列暴涨。
- 词表过大稀释低频子词、embedding 浪费。

## 八、面试题

- 词表大小怎么选？答：按语料与算力折中，多语更大、单语可更小。

## 九、演进

小词表 → 大词表 → 按语料自适应。

## 十、小结

词表大小是参数与序列长度的权衡核心超参。
