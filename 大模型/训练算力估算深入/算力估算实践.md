# 算力估算实践

> 对应 LLaMA（Touvron et al., 2023）训练报告；Patterson et al., *Carbon Emissions*, 2021.

## 一、背景与挑战

从理论 FLOPs 到真实 GPU 小时，需考虑利用率、并行策略与硬件峰值，否则预算偏差大。

## 二、核心原理

真实时长 $T=\frac{C}{P_{peak}\cdot u\cdot n_{gpu}}$，$u$ 为 MFU（模型浮点利用率，常 30-50%）；并行引入通信与重算开销。

## 三、数学形式

$T_{gpu-hours}=\frac{6ND}{FLOPs\_per\_GPU\_sec \times u}$；成本 $=T_{gpu-hours}\times price$。

## 四、代码实现

```python
C = 6 * 7e9 * 1.4e12
gpu_flops = 312e12            # A100 BF16
mfU = 0.4
hours = C / (gpu_flops * mfU * 3600)
```

## 五、与其他对比

- 与 Transformer FLOPs计算（理论 C）衔接得真实时长。
- 与 推理算力估算（无训练开销）对照。

## 六、常见误区

- 用峰值 FLOPs 忽略 MFU 致严重低估。
- 忽略通信/重算使大并行效率下降。

## 八、面试题

- 为何要乘 MFU？答：实际利用率远低于硬件峰值（30-50%），不计会严重低估 GPU 时长。

## 九、演进

理论 FLOPs → 乘 MFU → 含并行/重算模型。

## 十、小结

算力估算实践要把理论 FLOPs 经 MFU 与并行折算为真实 GPU 小时与成本。
