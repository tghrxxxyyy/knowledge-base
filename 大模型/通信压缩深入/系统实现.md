# 通信压缩系统实现

> 对应分布式训练系统；Tang et al., 2021（1-bit Adam 系统）。

## 一、背景与挑战

压缩需与 all-reduce/桶机制融合才有效。

## 二、核心原理

在梯度桶就绪即压缩再通信；用 NCCL 自定义或先在卡内压缩再 all-reduce；需处理压缩/解压开销与通信的重叠。

## 三、数学形式

开销比 $\frac{t_{compress}+t_{comm}}{t_{comm}^{full}}$ 应 <1 才收益。

## 四、代码实现

```python
for bucket in grad_buckets:
    comp = compress(bucket)                # 卡内压
    dist.all_reduce(comp, group=dp_group)
```

## 五、与其他对比

- 与 混合并行深入 通信重叠配合。
- 与 数据并行深入 桶机制结合。

## 六、常见误区

- 压缩开销抵消通信收益。
- 解压端类型不匹配。

## 八、面试题

- 压缩如何融入桶？答：桶就绪即卡内压缩再 all-reduce，与计算重叠。

## 九、演进

独立压缩 → 桶融合 → 硬件加速。

## 十、小结

通信压缩须与桶/重叠融合，开销低于通信收益才有效。
