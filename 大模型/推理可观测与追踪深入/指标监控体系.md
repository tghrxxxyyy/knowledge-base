# 指标监控体系

> 对应 Prometheus 拉模型；RED 与 USE 方法（Tom Wilkie）。RED 方法定义请求指标。

## 一、背景与挑战

需量化延迟、错误、饱和，才能设 SLO 与告警。

## 二、核心原理

RED（请求率、错误、时延）加 USE（资源利用率、饱和、错误）；用计数器与直方图暴露。

## 三、数学形式

p99 时延：$P_{99}=\inf\{x: P(L\le x)\ge 0.99\}$；错误率 $E=\frac{fail}{total}$。

## 四、代码实现

```python
prom.histogram("infer_latency_s", buckets=[0.1, 0.5, 1, 2])
prom.counter("infer_errors").inc()
```

## 五、与其他对比

- 与 队列监控与容量（队列指标）共享。
- 与 告警与SLO治理（阈值）衔接。

## 六、常见误区

- 用平均值掩盖长尾（应看 p99）。
- 指标无维度难下钻。

## 七、与开源书对应

## 八、面试题

- 为何看 p99 非均值？答：均值掩盖长尾，p99 反映最差用户体验与 SLO 风险。

## 九、演进

计数 → 直方图 → RED 与 USE 标准化。

## 十、小结

指标监控用 RED 与 USE 把系统状态量化，是告警基础。
