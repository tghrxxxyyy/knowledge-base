# 日志与诊断

> 对应结构化日志（JSON）加关联 trace_id；ELK 与 Loki。Loki 支持按标签查询日志。

## 一、背景与挑战

出错时需从海量日志中定位该请求上下文，非结构化日志难检索。

## 二、核心原理

输出 JSON 结构化日志，带 trace_id、tenant、版本；集中采集可按字段检索与关联 trace。

## 三、数学形式

检索命中 $H = \{log: log.trace\_id = t^*\}$；诊断即过滤关联集。

## 四、代码实现

```python
log.info("gen_done", extra={"trace_id": tid, "tok": n})
```

## 五、与其他对比

- 与 分布式追踪实现（关联）共享 trace_id。
- 与 可观测总览（三支柱）衔接。

## 六、常见误区

- 日志含敏感 prompt 致合规风险。
- 日志量过大吞资源。

## 七、与开源书对应

- mlabonne/llm-course：https://github.com/mlabonne/llm-course
- d2l-zh：https://github.com/d2l-ai/d2l-zh

## 八、面试题

- 日志为何结构化？答：带字段与 trace_id，可检索关联，定位单请求上下文。

## 九、演进

文本 → JSON 结构 → 关联 trace 集中检索。

## 十、小结

结构化日志配 trace_id，让诊断从大海捞针变精准过滤。
