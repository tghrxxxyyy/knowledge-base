# 推理可观测总览

> 对应可观测三支柱（metrics、logs、traces，Google SRE）；OpenTelemetry。OTel 提供统一标准。

## 一、背景与挑战

推理链路长（路由、排队、批处理、GPU、后处理），故障难定位，需统一可观测。

## 二、核心原理

指标（metrics）看趋势、日志（logs）看事件、追踪（traces）看单次请求链路；三者关联排障。

## 三、数学形式

可观测度 $O = f(M,L,T)$；定位时间 $MTTR$ 随关联度上升而下降。

## 四、代码实现

```python
from opentelemetry import trace
tracer = trace.get_tracer("infer")
with tracer.start_as_current_span("generate"):
    out = model(req)
```

## 五、与其他对比

- 与 指标监控体系 / 分布式追踪实现 / 日志与诊断 分述。
- 与 队列监控与容量（指标来源）衔接。

## 六、常见误区

- 只打点不关联 trace 致难定位。
- 高基数标签爆炸（如每 prompt 哈希）。

## 八、面试题

- 三支柱？答：metrics 趋势、logs 事件、traces 单次链路，关联排障。

## 九、演进

日志 → 指标 → 追踪 → 统一 OTel。

## 十、小结

可观测是线上推理可运维的基础，三支柱缺一不可。
