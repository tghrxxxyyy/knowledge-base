# 分布式追踪实现

> 对应 OpenTelemetry / Jaeger；W3C traceparent 传播。OTel 定义 trace 上下文标准。

## 一、背景与挑战

一次请求跨网关、队列、多实例，需串联各环节耗时定位瓶颈。

## 二、核心原理

每请求带 trace_id，各 span 记录起止与父子关系；上下文经 header 传播跨服务。

## 三、数学形式

链路耗时 $L = \sum_{span} dur(span) + \sum overlap$；瓶颈 $span^*=\arg\max dur$。

## 四、代码实现

```python
with tracer.start_as_current_span("queue") as s:
    s.set_attribute("wait_ms", w)
    handle(req)
```

## 五、与其他对比

- 与 延迟剖析定位（细到算子）对照层级。
- 与 可观测总览（三支柱）衔接。

## 六、常见误区

- 未传播 context 致链路断裂。
- trace 过多采样丢失偶发慢请求。

## 八、面试题

- trace 如何串联？答：trace_id 全局唯一，span 父子加 context 传播跨服务拼成链路。

## 九、演进

无 → 单服务日志 → OTel 跨服务 trace。

## 十、小结

分布式追踪把跨服务耗时可视化，是定位长尾瓶颈关键。
