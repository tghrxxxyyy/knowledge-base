# 延迟剖析定位（Profiling）

> 对应 PyTorch profiler / Triton 吞吐分析；GPU 算子级耗时。PyTorch 自带 profiler。

## 一、背景与挑战

p99 高但不知卡在哪：是排队、预填充还是解码、还是后处理。

## 二、核心原理

在算子或阶段级打点，区分 prefill 与 decode 耗时、kernel 占用，定位 GPU 空闲与瓶颈。

## 三、数学形式

端到端 $L = L_{queue}+L_{prefill}+L_{decode}+L_{post}$；分解求最大项。

## 四、代码实现

```python
with torch.profiler.profile() as p:
    model.generate(inp)
print(p.key_averages().table())
```

## 五、与其他对比

- 与 分布式追踪实现（请求级）对照到算子级。
- 与 连续批处理与排队（decode 瓶颈）衔接。

## 六、常见误区

- 只在离线剖析忽略线上变长。
- 忽视 GPU 空闲（kernel launch 瓶颈）。

## 八、面试题

- 延迟剖析看什么？答：分解 prefill、decode、后处理，定 GPU 占用与空闲瓶颈。

## 九、演进

整体计时 → 阶段计时 → 算子级 profiler。

## 十、小结

延迟剖析把高延迟归因到具体阶段与算子，指导优化。
