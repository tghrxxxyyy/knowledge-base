# 函数调用编排

> 对应工具调用（Function Calling / Tool Use）的工程编排；协议参考 OpenAI function calling 与 MCP（Model Context Protocol）。

## 一、背景与挑战

当模型决定调用多个工具时，这些调用之间往往存在依赖与并发关系：查天气和查汇率互不依赖可并行；「先查用户再查其订单」则必须串行；某步失败要重试或降级；最终结果要聚合成一段自然语言。编排不当会造成延迟高、结果错乱或流程崩溃。

挑战：(1) 依赖分析——哪些可并行、哪些必须等前置；(2) 并发控制——并行调用的限流与超时；(3) 错误重试与降级；(4) 结果标准化与聚合；(5) 把工具返回正确回填为消息。

## 二、核心原理

编排要点：

- 依赖图：把工具调用建模为有向无环图（DAG），边表示数据依赖。
- 并行：无依赖的调用并发发起，降低端到端时延。
- 串行：依赖前置输出的调用排队等待。
- 重试/超时：对瞬时失败有限重试，超时不阻塞整体。
- 降级：失败返回兜底提示而非抛异常崩溃。
- 聚合：把多个工具结果标准化为消息，交给模型综合生成。

实践中常用状态机或工作流引擎管理多步工具流。

## 三、形式化与数学基础

设工具调用集合 $\{c_1,\dots,c_n\}$，依赖关系为偏序 $\prec$（$c_i\prec c_j$ 表示 $c_j$ 依赖 $c_i$）。可并行层（topological layers）：

$$L_0=\{c_i\mid \text{无前置}\},\quad L_{k+1}=\{c_j\mid \forall c_i\prec c_j, c_i\in \cup_{t\le k}L_t\}$$

层内并行执行，层间串行。端到端时延近似：

$$T \approx \sum_{k} \max_{c_j\in L_k} t(c_j)$$

即由每层最慢调用决定，并行能显著压缩总时长。

## 四、代码实现

按依赖分批执行的简化思路（示意）：

```python
async def run_calls(calls, deps):
    done, results = set(), {}
    while len(done) < len(calls):
        ready = [c for c in calls
                 if c not in done and deps[c] <= done]
        batch = [call_tool(c, results) for c in ready]
        for c, r in zip(ready, await asyncio.gather(*batch, return_exceptions=True)):
            results[c] = r if not isinstance(r, Exception) else fallback(c)
            done.add(c)
    return aggregate(results)
```

## 五、与其他技术对比

| 方式 | 特点 | 适用 |
|------|------|------|
| 顺序串行 | 简单 | 强依赖 |
| 全并行 | 最快 | 全独立 |
| DAG 编排 | 最优 | 混合依赖 |
| 状态机 | 可控 | 复杂流程 |

## 六、常见误区

- 把本可并行的调用串行执行，无谓拉长延迟。
- 忽略超时，某工具挂起拖垮整条链路。
- 单点失败直接抛异常崩溃，不做降级。
- 工具返回值格式不一，模型无法正确聚合。
- 重试无退避（backoff），对瞬时故障疯狂重试放大负载。

## 九、演进与趋势

从手写编排到「声明式工作流」与「Agent 自动规划」结合；MCP 让工具即插即用；模型原生支持并行 tool call；编排层内置重试、限流、可观测，并向「自愈流程」（失败自动改路径）演进；并把编排成功率纳入评测驱动开发的回归指标。

## 十、小结

函数调用编排本质是对工具依赖的 DAG 调度：无依赖并行、有依赖串行，配合超时、重试（带退避）、降级与结果聚合，才能把多工具调用串成可靠、低延迟的业务流程。
