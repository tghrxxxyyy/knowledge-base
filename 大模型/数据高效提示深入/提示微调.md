# 提示微调（Prompt Tuning / P-Tuning）

> 对应 Lester, Al-Rfou & Constant, *The Power of Scale*, 2021；Liu et al., 2021（P-tuning v2）。

## 一、背景与挑战

全参数微调每个任务存整套权重；连续提示微调仅训练极少量前缀/软提示参数，共享底座。

## 二、核心原理

在输入 embedding 前拼接可学习软提示向量 $P\in\mathbb R^{m\times d}$，反向传播只更新 $P$，冻结主体。P-tuning v2 进一步在每层加提示，提升小模型效果。

## 三、数学形式

令前缀 $P_\theta$，隐状态 $H=\text{Transformer}([P_\theta; E(x)])$；优化 $\min_\theta \mathcal L_{task}(H, y)$，主体参数固定。

## 四、代码实现

```python
soft_prompt = nn.Parameter(torch.randn(m, d))
emb = torch.cat([soft_prompt, tok_emb], 0)
logits = model(inputs_embeds=emb).logits
```

## 五、与其他对比

- 与 少样本提示 比，提示微调更新少量参数、效果更稳。
- 与 参数高效微调深入（LoRA 等）并列，参数更少但表达受限。

## 六、常见误区

- 仅输入层加提示对小模型效果差（需深层提示）。
- 提示初始化影响收敛（可用词嵌入初始化）。

## 八、面试题

- Prompt Tuning 与全微调区别？答：只训少量软提示向量，冻结主体，单底座多任务共享。

## 九、演进

手工模板 → Prefix Tuning → Prompt Tuning → P-tuning v2（深层）。

## 十、小结

提示微调以极小可训练参数实现多任务适配，是数据/存储高效的典型方案。
