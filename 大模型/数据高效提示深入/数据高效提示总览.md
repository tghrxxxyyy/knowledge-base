# 数据高效提示总览

> 对应 Liu et al., *GPT understands, too*, 2021（P-tuning）；与 提示工程 / 参数高效微调 衔接。

## 一、背景与挑战

全参数微调大模型成本高，且每任务需存一份权重；数据高效提示用少量可学习提示或少量示例，以极少监督达成好效果。

## 二、核心原理

两类路线：离散/连续提示（在输入前加可学习或搜索的 token）激活模型既有能力；少样本提示（in-context）用极少标注示例引导。二者都避免改动主体权重。

## 三、数学形式

连续提示把前缀 $P$ 拼入输入：$h = \text{LM}([P; x])$，仅优化 $P$ 的参数；少样本以 $k$ 个示例构成上下文 $c$，预测 $y=\arg\max P(y|c,x)$。

## 四、代码实现

```python
from peft import PromptTuningConfig, get_peft_model
cfg = PromptTuningConfig(task_type="CAUSAL_LM", prompt_tuning_init_text="分类任务")
model = get_peft_model(base, cfg)
```

## 五、与其他对比

- 与 在线蒸馏深入 都追求"少数据/少算力"；提示不训主体权重。
- 与 权重平均与模型融合深入（多任务融合提示）可结合。

## 六、常见误区

- 提示长度过短表达能力不足、过长占上下文。
- 少样本示例顺序/质量显著影响结果。

## 八、面试题

- 数据高效提示为何省数据？答：只学少量提示参数或靠上下文示例激活既有能力，无需全量标注微调。

## 九、演进

手工提示 → 连续提示(Prompt Tuning) → 自动提示搜索。

## 十、小结

数据高效提示以极少参数或示例激活大模型能力，是低成本适配核心手段。
