# 请求路由与一致性哈希

> 对应 Kwon 2023 vLLM; Lewis 2020 RAG; Zhao 2023 FSDP。

## 一、背景与挑战
多租户/多模型场景需把同类请求稳定路由到特定副本（如亲和某适配器），同时避免节点增减引发大规模重映射。

## 二、核心原理
用一致性哈希把 (tenant, adapter) 映射到副本环，节点变动仅影响邻近区间，保证会话/缓存亲和且重映射最小。

## 三、形式化与数学基础
哈希环 H 上副本位置 {h_i}，请求 key k 路由到首个顺时针 ≥ hash(k) 的副本：
$ \text{target}(k) = \min_{i} \{ h_i \ge \text{hash}(k) \} $

## 四、代码实现
```python
def choose(key, ring):
    h = hash(key)
    for node in sorted(ring):
        if node >= h:
            return ring[node]
    return ring[min(ring)]
```

## 五、与其他技术对比
普通取模扩容全量重映射；一致性哈希仅局部迁移，适合有状态副本。

## 六、常见误区
误区：哈希即随机。需带虚拟节点使分布均匀。

## 七、与开源书/权威来源对应
一致性哈希经典实践；多LoRA 亲和路由。见 vllm-project/vllm。

## 八、面试题
问：一致性哈希解决什么问题？
答：节点扩缩时最小化键值重分布，保持会话亲和。

## 九、演进与趋势
带权虚拟节点按副本容量分配区间。

## 十、小结
一致性哈希让有状态推理副本的路由既亲和又弹性。
