# 负载均衡动机与拓扑

> 对应 Kwon 2023 vLLM; Zhao 2023 FSDP; Rasley 2020 DeepSpeed ZeRO。

## 一、背景与挑战
多推理副本下，若请求倾斜到少数节点，会造成热点与 SLA 违规，需把流量合理分散。

## 二、核心原理
在网关层做负载均衡：依据副本负载（队列长度、GPU 利用率、显存）路由请求，而非简单轮询，避免忙节点堆积。

## 三、形式化与数学基础
设副本 i 负载 l_i，目标最小化最大负载：
$ \min \max_i l_i $
路由选 argmin_i l_i 或按权重反比分配。

## 四、代码实现
```python
def route(replicas, req):
    best = min(replicas, key=lambda r: r.queue_len + r.kv_used/r.kv_cap)
    return best
```

## 五、与其他技术对比
轮询简单但不感知负载；负载感知均衡提升整体 SLA 与利用率。

## 六、常见误区
误区：均衡即均分请求数。应均衡有效负载（token 数、显存占用）。

## 七、与开源书/权威来源对应
vLLM 多副本部署；K8s Service 负载均衡。见 vllm-project/vllm。

## 八、面试题
问：为何不能仅轮询？
答：请求代价异构，轮询致忙闲不均，尾延迟恶化。

## 九、演进与趋势
基于预测的主动均衡，提前迁移负载。

## 十、小结
负载均衡把请求按真实代价分散，是多副本服务稳定的前提。
