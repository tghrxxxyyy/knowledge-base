# 限流算法令牌桶与漏桶

> 对应 Kwon 2023 vLLM; Zhao 2023 FSDP; Rasley 2020 DeepSpeed ZeRO。

## 一、背景与挑战
突发流量会压垮推理副本，需限流保护 SLA，同时尽量允许合理突发。

## 二、核心原理
令牌桶按速率 r 放令牌、容量 b，请求消耗令牌，空则拒绝/排队；漏桶以固定速率出水，平滑输出。前者允许突发，后者限制速率。

## 三、形式化与数学基础
令牌桶令牌数：
$ T(t) = \min(b,\ T(t_0) + r(t-t_0)) $
请求需 token_cost（如按输出长度）个令牌。

## 四、代码实现
```python
class TokenBucket:
    def __init__(self, r, b):
        self.r, self.b, self.tok = r, b, b
        self.ts = time.time()
    def allow(self, n):
        now = time.time()
        self.tok = min(self.b, self.tok + self.r*(now-self.ts))
        self.ts = now
        if self.tok >= n:
            self.tok -= n; return True
        return False
```

## 五、与其他技术对比
漏桶强制恒定速率，抗突发但可能丢弃；令牌桶更宽容突发，适合 LLM 不均请求。

## 六、常见误区
误区：限流只限请求数。应按 token 数限流，因代价随长度变化大。

## 七、与开源书/权威来源对应
经典限流算法；vLLM 中按并发与 KV 限流。见 vllm-project/vllm。

## 八、面试题
问：LLM 限流为何按 token？
答：请求算力与 KV 随 token 数线性增长，按数限流才公平。

## 九、演进与趋势
分层限流（租户→会话→请求）与动态配额。

## 十、小结
令牌桶/漏桶是保护推理服务的第一道防线，按 token 计费更合理。
