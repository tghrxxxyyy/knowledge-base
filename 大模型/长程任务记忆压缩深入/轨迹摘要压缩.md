# 轨迹摘要压缩

> 对应 对话/轨迹摘要（conversation summarization）技术。

## 一、背景与挑战

逐步累积的文本记忆会线性增长。需在“存取成本”与“信息保真”间取得平衡，定期生成滚动摘要。

## 二、核心原理

采用“滚动摘要”策略：每 $k$ 步把旧片段与增量合并为更短摘要，旧片段可丢弃或归档。摘要提示需明确保留实体、决策、未完成子目标。

## 三、数学形式

摘要递归更新：

$$S_{t} = \text{Compress}(S_{t-k},\, x_{t-k:t})$$

随 $t$ 增长，长度被约束在 $O(1)$ 附近。

## 四、代码实现

```python
if step % K == 0:
    summary = llm(compress_prompt(summary, recent))
```

## 五、与其他对比

- 与 长程任务记忆压缩总览 的“中期记忆”对应。
- 与 人机协作与人在环深入 共享“摘要供人审阅”。

## 六、常见误区

- 摘要无结构，关键数字被泛化丢失。
- 合并频率不当，过于频繁增成本或过于稀疏丢信息。

## 八、面试题

- 滚动摘要为何优于截断？答：保留语义要点而非简单丢弃，信息损失更小。

## 九、演进

截断 → 单次摘要 → 滚动递归摘要。

## 十、小结

摘要压缩以低密度表示承载长程信息，是上下文受限下的主流解法。
