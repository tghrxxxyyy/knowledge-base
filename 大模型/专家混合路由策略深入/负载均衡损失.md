# 负载均衡损失

> 对应 Shazeer 2017 的辅助负载均衡损失；Switch Transformers 进一步加 router z-loss。

## 一、背景与挑战

路由易塌缩到少数专家（多数 token 去同几个），其余饿死，浪费参数且训练不稳。

## 二、核心原理

加辅助损失鼓励各专家被选频率均衡：用每专家路由概率均值与token占比的散度作惩罚，逼路由器分散。

## 三、数学形式

$\mathcal L_{aux}=\alpha\sum_e f_e\cdot P_e$，$f_e$ 为 token 选专家 $e$ 比例，$P_e$ 为路由给 $e$ 的平均概率，均衡时最小。

## 四、代码实现

```python
f = (assign == e).mean(0)        # token 占比
P = router_probs.mean(0)         # 路由概率
aux = alpha * (f * P).sum()
```

## 五、与其他对比

- 与 专家容量与丢弃 协同：均衡损失减不均，容量限制兜底溢出。
- 与 训练不稳定诊断深入 共享稳定性主题。

## 六、常见误区

- 辅助损失权重过大压垮主任务，过小无效。
- 仅看均值均衡忽略专家间专业分化不足。

## 八、面试题

- 为何需要负载均衡损失？答：防止路由塌缩到少数专家，使参数被充分利用。

## 九、演进

无均衡 → 辅助均衡损失 → z-loss/更强约束。

## 十、小结

负载均衡损失是 MoE 训练必需正则，平衡专家利用与专业化。
