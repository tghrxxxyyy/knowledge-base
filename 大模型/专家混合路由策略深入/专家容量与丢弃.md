# 专家容量与丢弃

> 对应 Shazeer 2017 的容量因子（capacity factor）与 token 丢弃机制。

## 一、背景与挑战

并行 MoE 需固定每专家批大小；若某专家过载，多出的 token 须处理（丢弃或溢出），否则无法实现并行。

## 二、核心原理

设每专家容量 $C=\text{factor}\times\frac{T}{E}$；超容量 token 被丢弃（或送共享专家/溢出缓冲），以换硬件规整。

## 三、数学形式

$C=\gamma\cdot T/E$，$\gamma$ 为容量因子；丢弃率随 $\gamma$ 减小而升，需权衡质量与算力。

## 四、代码实现

```python
cap = int(capacity_factor * T // E)
kept = tokens[:cap]                 # 超容丢弃
```

## 五、与其他对比

- 与 负载均衡损失 互补：容量是硬性上限，均衡损失是软性引导。
- 与 推理调度深入 相关：专家并行需规整批。

## 六、常见误区

- 容量因子过小丢太多 token 损质量；过大浪费算力。
- 忽略丢弃 token 在评估时的影响，导致离线指标虚高。

## 八、面试题

- 专家容量作用？答：给每专家固定批大小以利并行，溢出 token 丢弃或溢出。

## 九、演进

无容量 → 容量因子+丢弃 → 溢出缓冲/共享专家缓解。

## 十、小结

专家容量以规则批实现 MoE 并行，是工程落地与质量的权衡点。
