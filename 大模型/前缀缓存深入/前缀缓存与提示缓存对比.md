# 前缀缓存与提示缓存对比

> 对应引擎层 vs API 层缓存；提示缓存深入 衔接。

## 一、背景与挑战

两者都复用前缀 KV，但层级、控制方式不同，易混淆。

## 二、核心原理

前缀缓存：推理引擎内自动，按 token 前缀 Radix 共享，对调用方透明。提示缓存：API 显式断点，跨请求按语义标识缓存并影响计费。

## 三、数学形式

前缀缓存命中 $H_{eng}=f(hash(prefix))$；提示缓存命中 $H_{api}=f(cache\_id, TTL)$。

## 四、代码实现

```python
# 两者可叠加：引擎自动 + API 显式断点
resp = api(messages, cache_control={"type":"ephemeral"})
```

## 五、与其他对比

- 与 KV缓存优化深入 同属引擎优化。
- 与 语义缓存深入（非 KV）对照。

## 六、常见误区

- 以为开了提示缓存就无需引擎前缀缓存（可叠加）。
- 混淆两者命中指标。

## 八、面试题

- 两层缓存区别？答：引擎层自动按 token 共享透明；API 层显式断点、影响计费、跨租户可控。

## 九、演进

引擎层 → API 层 → 双层协同。

## 十、小结

前缀缓存与提示缓存层级互补，生产中常叠加使用。
