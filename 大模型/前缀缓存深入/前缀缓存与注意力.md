# 前缀缓存与注意力机制

> 对应 Multi-Query/Cross-Attention 对缓存的影响；FlashAttention 基础。

## 一、背景与挑战

不同注意力结构（MHA/GQA/MQA）缓存大小与共享效率不同。

## 二、核心原理

GQA/MQA 多查询共享 K/V 头，KV 显存更小、缓存更省；前缀缓存块与注意力头布局相关。

## 三、数学形式

KV 显存 $M = 2\cdot L\cdot h_{kv}\cdot d_{head}\cdot B_{bytes}$；GQA 下 $h_{kv}\ll h_q$ 显著减小。

## 四、代码实现

```python
# GQA 配置影响缓存体积
config = {"num_attention_heads":32, "num_kv_heads":8}
```

## 五、与其他对比

- 与 KV缓存优化深入（量化/驱逐）共享降显存。
- 与 前缀缓存总览 机制互补。

## 六、常见误区

- 以为前缀缓存不受注意力架构影响（GQA 更省）。
- 忽略块表管理开销。

## 八、面试题

- GQA 为何利于缓存？答：KV 头少，缓存体积按头数缩小，共享前缀成本更低。

## 九、演进

MHA → MQA → GQA（平衡缓存与质量）。

## 十、小结

前缀缓存效率受注意力架构影响，GQA 显著降缓存体积。
