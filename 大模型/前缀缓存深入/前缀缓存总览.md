# 前缀缓存总览

> 对应 Zheng et al., *SGLang: RadixAttention*, 2024；vLLM Automatic Prefix Caching, 2023。

## 一、背景与挑战

多请求共享相同前缀（系统提示、few-shot、对话历史）时，每请求重算 KV 浪费；引擎层可自动复用。

## 二、核心原理

用基数树（Radix Tree）按 token 前缀组织 KV 块，相同前缀的请求共享已算 KV，避免重复 prefill。

## 三、数学形式

共享节省 $S = \sum_{i} |P_i \cap P_{shared}|\cdot c_{kv}$，其中 $P_i$ 为各请求前缀。

## 四、代码实现

```python
# vLLM 开启自动前缀缓存
llm = LLM(model="meta-llama/Llama-3-8B", enable_prefix_caching=True)
```

## 五、与其他对比

- 与 提示缓存深入（API 层）机制同源但更自动。
- 与 KV缓存优化深入 共享 KV 管理。

## 六、常见误区

- 认为需手动标缓存点（自动前缀缓存不需要）。
- 忽视块粒度对齐影响共享率。

## 八、面试题

- 前缀缓存为何省算？答：相同 token 前缀的 KV 只算一次，后续请求直接复用。

## 九、演进

无共享 → 会话级 KV → RadixAttention 全局共享。

## 十、小结

前缀缓存以 RadixAttention 自动复用 KV，是推理引擎降本核心。
