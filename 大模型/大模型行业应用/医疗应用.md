# 医疗应用

> 对应 Lewis et al. 2020（Retrieval-Augmented Generation / RAG）、HIPAA 合规框架、FDA AI/ML 软件指南。

## 一、背景与挑战

医疗是高风险、强监管场景：临床文档摘要、医学问答、文献检索、辅助决策都直接关乎生命安全。核心约束有四：其一，**绝不替代诊断**，模型只能辅助，最终责任在执业医师；其二，**循证**，结论必须有可核查的指南/文献出处，禁止凭空编造医学事实；其三，**隐私合规**，患者数据受 HIPAA（美）与《个人信息保护法》（中）严格约束，脱敏与最小化采集是底线；其四，**可解释与可追溯**，每一次输出应能回链到源证据，供医生复核。此外还有**术语严谨**（ICD/MeSH 编码）、**证据时效性**（指南会更新）、**评测基准**（MedQA、PubMedQA 等）等工程与学术难点，决定系统能否真正达临床可用门槛。

## 二、核心原理

医疗大模型最稳妥的范式是 **RAG + 人工复核**：

1. **知识库构建**：将临床指南、药品说明书、权威文献做切块、向量化，建立可检索证据库。
2. **检索增强生成**：先检索与问题最相关的 $k$ 条证据，再把证据拼入 prompt 让模型据此作答并标注出处。
3. **不确定即拒答**：当检索证据不足或置信度低，模型应明确"建议咨询专科医生"而非硬编。
4. **人工闭环**：医生对输出做最终确认，反馈回流持续改进。
5. **术语对齐**：用医学本体（UMLS、SNOMED CT）做实体链接，提升检索与表述准确性。

## 三、形式化与数学基础

RAG 的生成概率分解为检索与生成两部分：

$$P(y \mid x) = \sum_{z \in \mathcal{Z}} P_\eta(z \mid x)\,P_\theta(y \mid x, z)$$

其中 $x$ 为问诊/文档，$z$ 为检索到的证据块，$\mathcal{Z}$ 为证据库。目标是最大化证据条件下的似然，使答案"有源可溯"。隐私侧以差分隐私刻画风险：

$$\Pr[\mathcal{M}(D)\in S] \le e^\varepsilon \Pr[\mathcal{M}(D')\in S] + \delta$$

$\varepsilon$ 越小，单条记录被反推的概率越低。可附加"证据覆盖度"指标约束生成的可靠性，并对输出做事实一致性校验。

## 四、代码实现

一个带出处标注的医学 RAG 骨架：

```python
def answer_medical(question: str, retriever, llm) -> str:
    evidences = retriever.search(question, top_k=4)   # 指南/文献块
    ctx = "\n".join(f"[{i}] {e.text}" for i, e in enumerate(evidences))
    prompt = f"仅依据下列证据回答，并标注引用编号：\n{ctx}\n\n问：{question}"
    ans = llm(prompt)
    if confidence(ans) < 0.6:
        return "证据不足，请咨询执业医师。"
    return ans  # 输出含 [0]..[3] 溯源

def confidence(ans: str) -> float:                    # 证据覆盖度代理
    return min(1.0, ans.count("[") / 4.0)
```

## 六、常见误区

- **把模型当诊断者**：越权给出确诊结论，违背"辅助"定位。
- **无溯源的医学断言**：编造文献编号，医生无法复核。
- **未脱敏就入库**：直接用含姓名病历训练/检索，触犯隐私法。
- **忽视证据时效性**：用过期指南作答，临床建议失真。
- **混淆证据等级**：把论坛经验当指南一级证据引用。
- **跨语种术语错配**：中英医学词表不统一致检索召回错位。

## 九、演进与趋势

多模态病历理解（影像+文本联合）、院内本地化部署满足数据不出域、与电子病历系统（EMR）深度集成做实时辅助、循证等级自动标注。监管上"可解释 AI"正从建议变为强制，模型决策需可审计、可撤回；MedRAG 等工作把检索与推理进一步耦合以提升复杂临床题的正确率。

## 十、小结

医疗场景的第一原则是"安全可溯"。RAG 提供证据锚点、人工复核提供责任闭环、隐私合规提供法律底线——三者缺一不可，模型能力反而是次要考量；术语对齐、证据等级管理与可量化评测（MedQA 等）进一步支撑可信落地与持续改进。
