# 智能客服应用

> 对应 Lewis et al. 2020（Retrieval-Augmented Generation / RAG）、Rasa 对话管理文档、HuggingFace Transformers 文档。

## 一、背景与挑战

客服是大模型落地最成熟、ROI 最清晰场景之一：产品咨询、工单处理、售后答疑高频且标准化。挑战：其一，**幻觉控制**，答错参数/政策会直接引发客诉与赔偿；其二，**知识时效**，产品文档、价格、活动频繁变动，静态模型立刻过时；其三，**多轮上下文**，用户常追问、改口、补条件，需维持会话状态；其四，**意图路由**，超出知识范围须准确转人工而非硬答；其五**情感与合规**，安抚话术与禁语要可控；其六**成本与并发**，大促期间咨询量陡增，需限流与缓存热门问答；其七**评测口径**，应以"解决率/CSAT"而非仅"答案准确率"衡量，避免答非所问却被判对。

## 二、核心原理

成熟客服系统采用 **RAG + 对话管理 + 转人工策略** 架构：

1. **知识检索**：实时从产品文档、FAQ、工单库召回相关片段作为回答依据。
2. **对话状态跟踪（DST）**：维护槽位（订单号、问题类型）与历史，支撑多轮。
3. **生成与溯源**：模型据检索内容作答，并附来源链接供用户/质检核查。
4. **意图分类与路由**：识别投诉、退款、技术支持等意图，高风险/低置信直接转人工。
5. **热点缓存**：对高频问题缓存标准回答，降调用量、提响应速度。

## 三、形式化与数学基础

对话状态可建模为信念分布 $b(s)$ 在状态空间 $\mathcal{S}$ 上的更新：

$$b'(s') = \eta\,P(s'\mid s, a, o)\,\sum_{s} b(s)$$

其中 $a$ 为系统动作、$o$ 为用户观测、$\eta$ 为归一化常数。RAG 回答概率：

$$P(y\mid x) = \sum_{z} P_\eta(z\mid x)\,P_\theta(y\mid x, z)$$

检索证据 $z$ 使回答"有源可溯"，从源头抑制幻觉。转人工阈值可用置信度 $c(y)$ 触发：$c<\tau \Rightarrow \text{handoff}$，避免低质硬答。

## 四、代码实现

一个 RAG 客服回复与转人工骨架：

```python
def support_reply(query, history, retriever, llm, threshold=0.5):
    ctx = retriever.search(query, top_k=3)
    prompt = f"依据证据回答，附[编号]：\n{ctx}\n历史：{history}\n问：{query}"
    ans, conf = llm.answer_with_confidence(prompt)
    if conf < threshold:
        return "已为您转接人工客服，请稍候。"
    return ans  # 含 [0]..[2] 溯源
```

## 六、常见误区

- **纯生成不检索**：模型凭旧知识答新品，必错。
- **不转人工硬撑**：低置信仍编，酿成投诉。
- **忽略会话历史**：每轮独立，用户重复说背景。
- **无溯源**：质检无法核查、用户不信任。
- **无并发限流**：大促打爆推理服务。
- **只追首响速度**：忽视"一次解决率"，体验未真正改善。

## 九、演进与趋势

从"单轮问答"走向"任务型 Agent"（能查订单、发起退款、调 API）；主动式客服（异常主动提醒）；多语言与语音全链路；知识库自动巡检与过期预警，让 RAG 知识始终保持新鲜；用强化学习优化转人工阈值以平衡成本与满意度，并引入"解决率"而非"命中率"做目标函数。

## 十、小结

智能客服的护城河是"有据、可控、能兜底"。RAG 保证回答与时俱进且有源，对话管理撑起多轮，转人工策略守住风险底线，热点缓存与限流解决规模化成本——以"解决率"为北极星，协同才能既降本又保体验。
