# 金融应用

> 对应 实时 RAG（金融资讯检索）、HuggingFace Transformers 文档、监管合规框架（如 SEC 披露要求、投顾适当性规则）。

## 一、背景与挑战

金融场景对"时效、合规、可追溯"三位一体要求极严：财报摘要、舆情分析、研报生成、风控与投顾辅助都直接关联资金与监管。挑战：其一，**数据时效**，股价、利率、公告瞬息万变，静态模型答出的"当前价"即刻失真；其二，**合规红线**，荐股、收益承诺、保本表述受严格限制，越线即违规；其三**可追溯**，任何分析结论须能回链数据来源供合规审查；其四**噪声与操纵**，舆情含谣言与水军，需去噪与置信评估；其五**隐私**，客户持仓与身份属敏感数据；其六**风险口径**，压力测试与风控指标须口径统一，避免前后矛盾；其七**可解释**，风控结论需展示因子贡献度，而不能只给"高风险"标签。

## 二、核心原理

金融大模型落地以"实时 RAG + 合规护栏 + 可审计"为核心：

1. **实时检索**：接入行情、公告、新闻、研报的实时/近实时数据源，回答前先取最新事实。
2. **分析生成**：在证据上做摘要、对比、归因，输出带引用的结论，不做无据预测。
3. **合规过滤**：后置规则/分类器拦截荐股、保本承诺、绝对收益表述。
4. **审计留痕**：记录每次调用的输入、检索来源、模型版本，满足可回溯审查。
5. **去噪与置信**：对舆情做来源可信度加权，低置信标注"仅供参考"。

## 三、形式化与数学基础

实时 RAG 在时刻 $t$ 的证据集 $\mathcal{Z}_t$ 上生成：

$$P(y\mid x, t) = \sum_{z\in\mathcal{Z}_t} P_\eta(z\mid x, t)\,P_\theta(y\mid x, z)$$

强调证据随时间滚动更新。合规可建模为约束满足：输出 $y$ 须满足监管谓词 $\psi(y)=\text{true}$，例如"不含具体买卖建议""不含保本收益承诺"。置信度用证据覆盖度刻画：

$$c(y) = \frac{|\{z\in\mathcal{Z}_t: \text{support}(y,z)\}|}{|\text{claims}(y)|}$$

即被证据支撑的断言占比，低于阈值则标注"仅供参考"。

## 四、代码实现

一个带实时检索与合规护栏的金融问答骨架：

```python
FORBIDDEN = ["买入", "卖出", "保本", "稳赚"]
def compliance_check(text: str) -> bool:
    return not any(w in text for w in FORBIDDEN)

def finance_qa(question, live_retriever, llm):
    fresh = live_retriever.search(question, top_k=5)   # 行情/公告/新闻
    ctx = "\n".join(f"[{i}] {h.src}@{h.time}: {h.text}" for i, h in enumerate(fresh))
    ans = llm(f"仅依据带时间戳证据作答并标注来源：\n{ctx}\n问：{question}")
    if not compliance_check(ans):                        # 拦截荐股/保本
        ans = "根据合规要求，本回答不提供具体投资建议。"
    return ans
```

## 六、常见误区

- **用旧权重答实时行情**：模型知识截止，价格全错。
- **输出买卖建议**：触碰投顾牌照与适当性红线。
- **无来源断言**：研报/风控结论不可审计。
- **轻信舆情**：未去噪即据此生成，易被操纵信息带偏。
- **忽略审计留痕**：监管检查无据可查。
- **把相关当因果**：仅凭两指标同涨就下因果结论，误导投研。

## 九、演进与趋势

从"问答摘要"走向"Agent 化投研"（自动取数、跑因子、出报告）；实时多源融合与事件驱动更新；可解释风控（归因到具体指标）；监管沙盒下的合规自动化审查逐步标准化；私有化部署满足客户数据不出域，领域预训练（如 BloombergGPT）提升金融语义理解。

## 十、小结

金融 AI 的铁律是"时效、合规、可追溯"三不误。实时 RAG 提供新鲜事实、合规护栏守住监管底线、审计留痕支撑可回溯，去噪与置信评估抑制操纵信息、可解释归因满足风控诉求——在强监管行业，可信远比聪明重要。
