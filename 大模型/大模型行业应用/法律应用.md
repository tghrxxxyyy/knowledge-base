# 法律应用

> 对应 Lewis et al. 2020（Retrieval-Augmented Generation / RAG）、HuggingFace Transformers 文档、法律检索（Legal IR）研究。

## 一、背景与挑战

法律场景对"精确与可溯"的要求近乎苛刻：合同审查、判例检索、法规问答、文书起草都直接关系权利与义务。挑战：其一，**长文档理解**，合同/判决常数千字且条款相互引用，模型易丢上下文；其二，**精确引用**，每条结论必须指向具体法条/案号，编造判例在法庭上无效且危险；其三，**幻觉代价极高**，错误法律意见可能导致败诉或违规；其四，**时效与管辖**，法条因地（省/国）、因时而异；其五**保密**，卷宗属高度敏感数据，不得外泄；其六**术语与体系**，不同法域（大陆/英美）推理逻辑不同，需领域校准；其七**责任归属**，AI 给出的建议若出错，最终责任仍在律师/律所，系统必须可审计、可追责。

## 二、核心原理

法律 AI 的稳健范式是 **强约束 RAG + 严格溯源 + 切分策略**：

1. **长文档切分**：按条款/段落做结构感知分块，保留标题与层级，避免切断引用关系。
2. **精确检索**：用混合检索（向量 + 关键词/BM25）召回法条与判例，关键词保证"条文编号"等硬匹配。
3. **受限生成**：仅依据检索证据作答，强制输出引用（法条编号、案号、段落），无据则声明"未找到"。
4. **私有化部署**：卷宗与在办案件本地闭环，满足保密与律师执业纪律。
5. **差异比对**：合同审阅时自动比对模板与在办文本，高亮偏离条款。

## 三、形式化与数学基础

强约束 RAG 把"可核验"作为硬条件：答案 $y$ 须能从证据集 $\mathcal{Z}$ 中back 出支撑片段：

$$y \in \mathcal{Y}_{\text{valid}} \iff \exists z\in\mathcal{Z}:\, \text{support}(y, z) = \text{true}$$

生成概率仍按 RAG 分解：

$$P(y\mid x)=\sum_{z} P_\eta(z\mid x)\,P_\theta(y\mid x, z)$$

切分策略可用重叠滑窗控制信息丢失，窗口长度 $L$ 与重叠 $o$ 满足 $o < L$，使跨段引用不被截断。检索质量用召回率 $\text{Recall}@k$ 监控关键条文是否进 top-k。

## 四、代码实现

一个带法条引用的法律问答骨架：

```python
def legal_qa(question: str, retriever, llm) -> str:
    hits = retriever.hybrid_search(question, top_k=5)  # 向量+BM25
    ctx = "\n".join(f"[{i}] {h.meta['cite']}: {h.text}" for i, h in enumerate(hits))
    prompt = f"仅依据证据，给出法律意见并标注引用：\n{ctx}\n问：{question}"
    ans = llm(prompt)
    if not has_citation(ans):
        ans += "\n（注：未检索到明确依据，建议咨询执业律师。）"
    return ans

def review_contract(draft: str, template: str) -> list:
```

## 六、常见误区

- **编造法条/案号**：模型"自信地错"，在法律场景后果严重。
- **长文档一刀切分块**：切断"见第 3.2 条"类引用。
- **纯向量检索漏硬匹配**：条文编号 BM25 更稳，应混合。
- **公有云跑涉密卷宗**：违反保密与执业纪律。
- **跨法域混用**：把英美判例当大陆法依据，推理错位。
- **过度信任检索排名**：top-1 未必最相关，应多召回交叉验证。

## 九、演进与趋势

从"检索问答"走向"文书自动起草与审阅差异比对"；长上下文模型（百万 token）缓解切分痛点；判例类案推送与胜率预测；律所私有知识库 + 本地大模型成为合规标配；用知识图谱串联法条-判例-要件，提升推理严谨度，并保留完整决策链路以满足可追责要求。

## 十、小结

法律 AI 的红线是"每句话都有出处、每份卷宗都不出域"。结构感知切分 + 混合检索 + 强约束生成构成可信法律助手的基石，跨法域校准、差异比对与可追责链路进一步贴近真实执业，模型大小反在其次。
