# 量化推理引擎总览

> 对应 Jacob et al., *Quantization*, 2018；GPTQ Frantar22；与 KV缓存优化深入 衔接。

## 一、背景与挑战

LLM 权重/激活 FP16 占显存大、带宽高；量化用低比特降显存与带宽、提吞吐。

## 二、核心原理

把权重/激活从 FP16 映射到 INT8/INT4/FP8；线性层用缩放因子 $s$ 与零点 $z$；推理用低比特计算或反量化。

## 三、数学形式

量化 $\hat w = \text{round}(w/s)+z$，反量化 $\tilde w = s(\hat w - z)$；误差 $\|\tilde w-w\|$。

## 四、代码实现

```python
q = torch.quantize_per_channel(w, s, z, dtype=torch.qint8)
```

## 五、与其他对比

- 与 内存高效注意力深入（省注意力显存）互补；
- 与 模型编译深入 可级联（量化后编译）。

## 六、常见误区

- 以为量化总提速（反量化开销/低比特 kernel 少）；
- 激活离群值（outlier）致 INT8 崩。

## 八、面试题

- 量化为何降显存？答：低比特表示权重/激活，字节数等比下降。

## 九、演进

PTQ → GPTQ/AWQ → 训练后低比特内核。

## 十、小结

量化以低比特换显存带宽，是推理降本主力。
