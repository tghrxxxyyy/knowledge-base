# 量化实践与内核

> 对应生产量化内核；与 模型编译深入 / 推理服务可观测性深入 衔接。

## 一、背景与挑战

低比特 kernel（INT4 matmul、mixed GEMM）稀缺且需调；精度回退需评估。

## 二、核心原理

用专用内核（如 Marlin、ExLlama）做 INT4×FP16 GEMM；混合精度路由； perplexity/下游评测把关回退。

## 三、数学形式

吞吐提升 $T_{q}/T_{fp16}\approx \text{bits}_{fp16}/\text{bits}_q$（受 kernel 效率限）。

## 四、代码实现

```python
out = marlin_gemm(x, Wq, scales, bits=4)
```

## 五、与其他对比

- 与 模型编译深入 可协同（量化后编译）；
- 与 弹性推理自动伸缩深入 量化降单卡成本。

## 六、常见误区

- 仅看显存省忽略 kernel 成熟度；
- 未做下游评测直接上线。

## 七、与开源书对应

- llm-course：https://github.com/mlabonne/llm-course
- d2l-zh：https://github.com/d2l-ai/d2l-zh

## 八、面试题

- 量化后为何需评测？答：低比特有损，需 perplexity/下游确认可接受。

## 九、演进

通用内核 → 专用 mixed GEMM → 硬件原生 FP8。

## 十、小结

量化落地靠成熟内核与评测闭环，否则省显存不省心。
