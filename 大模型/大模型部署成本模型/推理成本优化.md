# 推理成本优化

> 对应 vLLM（Kwon et al. 2023）、PagedAttention 与 FrugalGPT（Chen et al. 2023）。同样效果，成本可以差一个量级。

## 一、背景与挑战

大模型上线后，推理成本随调用量线性增长，往往在数月内超过训练成本。挑战是：吞吐与延迟互相制约；长上下文使 KV Cache 成为显存瓶颈；小批量时 GPU 利用率极低；而且降本手段常与质量冲突（量化损失精度、小模型掉点）。目标是在**可接受质量损失**内最大化「每美元请求数」。

## 二、核心原理

主要杠杆按收益排序：

1. **批处理与调度**：Continuous Batching 让新请求随时加入正在执行的批次，GPU 不空转。
2. **KV Cache 管理**：PagedAttention 把 KV 分块存储、按需分配，显存碎片从 ~60% 降到 ~4%，同样显存撑更大并发。
3. **量化**：权重/激活降到 INT8/INT4（GPTQ、AWQ、SmoothQuant），显存与带宽减半到四分之一。
4. **模型路由**：简单问题走小模型、难的走大模型（FrugalGPT 思想）。
5. **缓存**：完全相同或语义相近的查询直接复用结果。
6. **提示压缩**：去掉冗余上下文，直接省输入 token。

## 三、形式化与数学基础

吞吐与成本：

$$\text{cost per 1k req}=\frac{C_{\text{gpu-hour}}}{\text{throughput}_{\text{req/hour}}}\times 1000$$

KV Cache 显存（层数 $L$、头数 $h$、维度 $d$、序列 $s$、batch $b$、精度字节 $p$）：

$$M_{\text{kv}} = 2 \cdot L \cdot h \cdot d \cdot s \cdot b \cdot p$$

量化收益（$p$ 从 2 字节降到 0.5 字节）约为 4 倍。批处理的加速比受限于：

$$\text{speedup} \approx \min(b,\, \text{饱和点})$$

## 四、代码实现

启用连续批处理的服务（以 vLLM 为例，参数以版本为准）：

```python
from vllm import LLM, SamplingParams
llm = LLM(model="meta-llama/Llama-2-7b-hf",
          quantization="awq",        # 可选：权重量化
          max_model_len=4096,
          gpu_memory_utilization=0.9)  # 提高显存占用换并发
outs = llm.generate(prompts, SamplingParams(max_tokens=256))
```

语义缓存（近似复用）：

```python
hit = cache.lookup(embed(prompt), threshold=0.95)
if hit: return hit
ans = llm.generate(prompt); cache.store(embed(prompt), ans)
```

## 五、与其他技术对比

| 手段 | 收益 | 质量损失 | 复杂度 |
|------|------|---------|--------|
| 连续批处理 | 2–10x | 无 | 低 |
| KV Paged 管理 | 2–4x 并发 | 无 | 中 |
| 量化 INT8/4 | 2–4x | 小–中 | 中 |
| 模型路由 | 2–5x | 可控 | 中 |
| 语义缓存 | 不定 | 小 | 低 |

## 六、常见误区

- 盲目量化：低比特在小模型上掉点明显，需评测。
- 只优化单请求延迟：吞吐才是成本关键。
- 缓存命中率不看语义，导致错误复用。
- 忽略输入 token：RAG 场景里提示往往是大头。

## 九、演进与趋势

推理引擎（vLLM、TensorRT-LLM、SGLang）持续压榨调度与显存；投机解码用大模型验证小模型草稿；Prefix caching 让系统提示近乎免费；按质量自适应路由成为标配。

## 十、小结

推理降本的优先级：先上连续批处理与 KV 优化（无损、收益大），再考虑量化与路由（有损、需评测），最后用缓存与提示压缩收尾。
