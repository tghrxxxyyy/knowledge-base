# 上下文工程总览 Context Engineering

> 对应 llm-course 与工业界「Context Engineering」实践（如 Anthropic/Shopify 工程博客）。2024 年后，提示工程演进为「上下文工程」：系统性地决定喂给模型的全部上下文。

## 一、核心概念

上下文工程是把「正确的信息，以正确的格式，在正确的时机」放入模型上下文窗口的学科，涵盖：

- **指令(instruction)**：系统提示、角色、规则。
- **上下文(state)**：对话历史、用户画像、检索片段。
- **示例(few-shot)**：演示、样板。
- **工具(tools)**：可用函数 schema。
- **结构化输出**：格式约束。

与提示工程区别：提示工程偏「怎么写一句 prompt」，上下文工程偏「怎么编排整个上下文」（含检索、记忆、压缩、路由）。

## 二、关键原则

| 原则 | 说明 |
|------|------|
| 最小必要 | 只放相关上下文，防稀释 |
| 结构化 | 用标签/分隔隔离段落 |
| 动态 | 按需检索/摘要/淘汰 |
| 可观测 | 记录上下文便于调试 |
