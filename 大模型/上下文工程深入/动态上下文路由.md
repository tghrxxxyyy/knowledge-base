# 动态上下文路由

> 对应 LlamaIndex 文档（RouterQueryEngine / Query Routing）、LangChain 文档（RouterChain）。

## 一、背景与挑战

当系统只服务单一任务时，一个固定系统提示即可。但真实生产系统往往要同时处理多类意图：问答、写代码、调用工具、进入 Agent、查不同知识库。若用「一个万能上下文」硬扛，会导致：① 提示过长、成本升高；② 指令互相干扰、模型无所适从；③ 无关知识被注入、噪声稀释注意力。动态上下文路由的思路是——先理解「当前这条输入属于哪类、需要哪些资源」，再据此组装最贴合的上下文，做到「按需供给」。

## 二、核心原理

路由分两步：① **意图识别**（分类）：判断输入意图/领域/复杂度；② **资源选择**：据意图决定加载哪个系统提示模板、检索哪个知识库、挂载哪些工具、是否进入 Agent 模式。关键设计点：

- 路由模型可用小模型（如意图分类器、轻量 LLM）完成，不必用大模型，省成本低时延。
- 必须有**兜底路由**：分类不确定时回退到通用模板，避免「路由失败即崩」。
- 路由决策应可解释、可记录，便于评测与审计。
- 路由粒度可分层：先粗分领域，再细分子任务。

典型实现：LangChain 的 `RouterChain` 用一个 LLM 生成路由目的地；LlamaIndex 的 `RouterQueryEngine` 用 `Selector` 在多个 `QueryEngine`/工具间选择。

路由的设计要避免「路由本身成为瓶颈」。高频线上请求里，若每次都用大模型做意图分类，会额外增加一次 LLM 调用与可观时延。因此生产实践多用轻量方案：小模型分类器、规则/关键词路由、甚至用 embedding 近邻做语义路由。只有在分类边界模糊、影响重大时，才升級到大模型路由并保留人工兜底。

路由还应与缓存协同：一旦路由结果确定，对应的系统提示模板即固定，这正是前缀缓存能命中前提。若路由导致模板频繁变动，缓存收益随之下降，二者需在架构层统一规划。另一个易忽视的点是「路由的可观测性」——记录每条请求走了哪条路由、命中哪个知识库，才能在做 ablation 时量化每条路由对最终质量的贡献，避免路由层级无限膨胀却无人评估。

分层路由是规模化的常见形态：先按大域粗分（客服/技术/计费），域内再细分任务类型；粗层可用极廉价规则，细层才上模型。这样兼顾成本与精度。

## 三、形式化与数学基础

设意图空间为 $\mathcal{Y} = \{y_1,\dots,y_m\}$，上下文模板集合为 $\mathcal{T} = \{T_1,\dots,T_m\}$（与知识源、工具集一一或组合对应）。路由函数 $r$ 将输入 $x$ 映射到配置：

$$r(x) = \arg\max_{y \in \mathcal{Y}}\ P(y \mid x;\ \phi)$$

随后组装上下文 $C_x = \text{assemble}(T_y, \text{retrieve}(x, K_y), \text{tools}(y))$。目标是在路由正确时最小化无关上下文注入比例：

$$\min_{r}\ \mathbb{E}_x\big[\,\text{irrelevant}(C_x)\,\big],\quad \text{s.t.}\ \text{acc}(C_x)\ge \tau$$

$\phi$ 可用少量标注样本微调或纯提示式 zero-shot 分类。

## 四、代码实现

以 LlamaIndex 的路由为例：

```python
from llama_index.query_engine.router_query_engine import RouterQueryEngine
from llama_index.selectors.llm_selectors import LLMSingleSelector
from llama_index.tools.query_engine import QueryEngineTool

tools = [
    QueryEngineTool.from_defaults(qe_faq, name="faq"),
    QueryEngineTool.from_defaults(qe_code, name="code"),
]
engine = RouterQueryEngine(
    selector=LLMSingleSelector.from_defaults(),
    query_engine_tools=tools,
)
resp = engine.query("如何在 Python 里读 CSV？")  # 自动路由到 code
```

## 五、与其他技术对比

| 方案 | 上下文精度 | 成本 | 复杂度 |
|------|-----------|------|--------|
| 单一万能模板 | 低 | 高 | 低 |
| 规则路由（关键词） | 中 | 低 | 低 |
| 模型路由（LLM 分类） | 高 | 中 | 中 |
| 分层路由 | 高 | 中 | 高 |

## 六、常见误区

- 路由分类器与生成模型用同一上下文，反而耦合、互相干扰。
- 无兜底，分类置信度低时直接失败。
- 路由维度过多（意图爆炸），维护成本高且易错分。
- 忽略路由本身的成本，高频请求下小模型路由更划算。

## 九、演进与趋势

路由正从「静态意图分类」演进为「语义+成本感知的自适应路由」：结合检索置信度、缓存命中、用户画像动态组装上下文；并与上下文缓存优化联动（命中缓存前缀可跳过部分路由）。多 Agent 系统本质上是路由的递归化。

## 十、小结

动态上下文路由是规模化的关键：用轻量分类把「正确上下文」精准送到模型面前，既省成本又减噪声。核心是「分类 + 兜底 + 可评测」，让上下文从静态模板升级为按需供给的系统。
