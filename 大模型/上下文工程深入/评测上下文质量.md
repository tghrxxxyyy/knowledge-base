# 评测上下文质量

> 对应 mlabonne 的 LLM Course（Evaluation 章节）、HuggingFace Evaluate / llm-course 评测实践。

## 一、背景与挑战

上下文工程最大的陷阱是「凭感觉调上下文」：加一段提示、换几个示例、塞点检索结果，然后主观觉得「好像更好了」。但上下文的每一部分都影响质量、成本与时延，且彼此存在非线性交互——一段看似有用的指令可能在某类输入下反而干扰模型。没有量化评测，任何改动都是盲调。挑战在于：① 上下文贡献难以归因；② 质量指标随任务而异（准确率、格式合规、引用正确性）；③ 成本与质量必须联合权衡，不能只看一端。

## 二、核心原理

上下文质量评测的核心方法论是 **ablation（消融/删减实验）**：系统性地移除上下文中的某一段（系统规则、单个 few-shot 示例、一条检索片段、一段摘要），在固定评测集上对比指标变化，从而定位每段的边际贡献。配合 **回归测试**：维护一小批有代表性的评测样例，任何上下文改动都跑一遍回归，防止「修一处坏三处」。理想闭环是：改动 → 在评测集上回归 → 看质量/成本/时延三维指标 → 保留正向改动、回滚负向改动。

再进一步，可做 **成分扫描**：枚举上下文组合（不同示例集 × 不同检索 Top-k × 有无某条规则），找出帕累托最优配置。这比人工试错更稳健。

评测驱动上下文迭代的落地有几个关键习惯。其一是**固定评测集要小而精**：不在于数量多，而在于覆盖典型分布与边界 case，且每次改动都跑同一批样本，保证前后可比。其二是**分层指标**：除了端到端准确率，还应追踪「格式合规率、引用正确率、拒答恰当率、成本、尾延迟」，因为上下文改动常在这些维度上此消彼长。其三是**回归守护**：把评测接入 CI，任何 prompt/上下文 PR 必须通过回归门禁才能合入，避免「改 A 坏 B」悄悄发生。

成分扫描适合一次性找最优组合，但不必每次都做；更经济的做法是「单变量 ablation」——每次只动一个组件，观察指标变化，从而建立「这份上下文里每块内容的贡献地图」。当某块 ablation 后指标不降反升，它就是该删的噪声。对于线上系统，还可做**在线评测**：以 A/B 或影子流量对比新旧上下文，用真实分布验证离线结论。需提醒的是，离线评测集若与线上分布漂移，结论会失效，因此评测集本身也要随业务持续更新。

## 三、形式化与数学基础

设上下文由若干组件构成 $C = \{c_1, c_2, \dots, c_k\}$，在评测集 $\mathcal{D}$ 上的指标为 $M(C)$。组件 $c_i$ 的边际贡献用消融度量：

$$\Delta_i = M(C) - M(C \setminus \{c_i\})$$

若 $\Delta_i \le 0$，则该组件「有害或无用」，应删除；若显著为正则保留。联合优化目标为帕累托前沿：

$$\max_{C'\subseteq C}\ \big(M(C'),\ - \text{cost}(C')\big)$$

即在不显著牺牲质量的前提下最小化 token 成本与时延。

## 四、代码实现

一个最小消融脚本骨架：

```python
def eval_context(ctx_components, dataset, run_fn):
    base = run_fn(ctx_components, dataset)
    ablations = {}
    for c in ctx_components:
        subset = [x for x in ctx_components if x != c]
        ablations[c] = run_fn(subset, dataset)
    return base, {c: base - ablations[c] for c in ablations}

# 示例：run_fn 返回准确率，ablation 正值说明该组件有正向贡献
```

生产上可接 HuggingFace `evaluate` 或自建回归脚本，固定随机种子保证可比。

## 五、与其他技术对比

| 评测方式 | 归因能力 | 成本 | 说明 |
|----------|---------|------|------|
| 主观抽查 | 无 | 低 | 易误判 |
| 端到端回归 | 弱 | 中 | 防退化 |
| 消融 ablation | 强 | 高 | 定位贡献 |
| 成分扫描 | 强 | 很高 | 找最优组合 |

## 六、常见误区

- 只看「质量」不看「成本与时延」，导致上线后昂贵超时。
- 用少量同质样例做评测，结论不可外推。
- 把消融当一次性动作，缺回归看护，后续改动悄悄劣化。
- 指标定义模糊（如「更通顺」），无法复现与对比。

## 九、演进与趋势

从手工 ablation 走向 **自动化上下文搜索**：用小规模代理模型预筛组合、用在线 A/B 持续评测、把评测指标接入 CI 做上下文回归门禁。评测本身正成为上下文工程的「编译器测试」。

## 十、小结

没有评测的上下文改动是盲调。用 ablation 做贡献归因、用回归测试兜底、用帕累托视角联合权衡质量与成本，才能把上下文工程从「玄学」变成可度量、可迭代的工程学科。
