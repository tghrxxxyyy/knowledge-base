# 系统提示设计

> 对应 OpenAI Prompt Engineering 指南、Anthropic 系统提示最佳实践、mlabonne LLM Course。

## 一、背景与挑战

系统提示（system prompt）是注入在上下文最前、用于设定模型「角色、目标、约束、输出格式、禁忌」的一段指令。它决定了模型的行为基调，是上下文工程的核心组件。设计难点在于：① 既要全面又要简洁，过长会被模型「中间遗忘」；② 规则之间可能自相矛盾，模型会随机选一个；③ 输出格式需与下游解析器严格对齐，否则解析失败；④ 不同任务对角色与边界要求差异大，缺乏统一范式。

## 二、核心原理

优秀系统提示通常包含：明确角色与职责、列出**硬规则**（用「必须/禁止」清晰表达，避免模糊）、定义输出 schema（JSON/XML/固定字段）、给出降级策略（信息不足时如何回答）、声明禁忌（不做什么）。要点：

- 硬规则要可执行、可校验，避免「尽量」「最好」这类无法判定的措辞。
- 输出 schema 与解析代码对齐，必要时要求模型先输出结构化再解释。
- 避免过长导致忽略：把稳定通用部分前置、可变动部分后置，配合上下文缓存。
- 避免矛盾：若两条规则冲突，模型会任取其一，须显式排优先级。

系统提示的「位置与结构」也影响效果。系统提示通常置于上下文最前，对后续所有 token 具有因果可见性，但过长时模型对中段信息的注意力会被两端稀释（lost-in-the-middle）。因此建议把「最高优先级、最不可违反的硬规则」放在开头与结尾（首因+近因更强），中间放解释性内容。输出 schema 应紧邻任务说明，减少模型「自由发挥」的空间。

写系统提示时还应区分「给模型的指令」与「给开发者的注释」：后者不应进入线上 prompt，否则既占 token 又可能被模型误读为指令。版本管理也很重要——把系统提示当作代码资产，纳入评审与回归测试，任何改动都跑一遍评测集（见评测上下文质量），防止「手滑一句」让线上行为悄然劣化。多语言场景要显式声明回复语言与术语表，避免模型在语言中切换或翻译专有名词。

最后，系统提示不是「越细越好」。当规则过细到覆盖每一种边缘情况，反而增加矛盾概率与维护成本。好的实践是用「少量强规则 + 清晰的角色与输出约定 + 降级策略」覆盖 80% 场景，把剩余长尾交给示例与检索，而非无休止地堆规则。

## 三、形式化与数学基础

设系统提示为 $S$，用户输入 $x$，模型在 $S$ 约束下生成 $y$。理想情况下 $y$ 满足约束集 $\mathcal{R}(S)$：

$$y = \arg\max_{y'}\ P_\theta(y' \mid S, x)\quad \text{s.t.}\quad y' \in \bigcap_{r\in\mathcal{R}(S)} \text{valid}(r)$$

当约束存在冲突 $r_i \perp r_j$（同时满足不可能），需引入优先级序 $\prec$：

$$\text{valid}(r_i) \succ \text{valid}(r_j) \Rightarrow \text{优先满足 } r_i$$

此外，上下文位置影响注意力：系统提示置于最前，对后续所有 token 都有因果可见性，但过长时中段信息易被稀释（lost-in-the-middle 现象）。

## 四、代码实现

一个带输出 schema 与降级策略的系统提示示例：

```text
你是订单客服助手。
角色：只回答订单相关问题。
硬规则：
- 禁止透露用户隐私字段（手机号、地址）。
- 信息不足时必须回复「请提供订单号」，不得编造。
输出格式（严格 JSON）：
{"intent": "query|refund", "answer": str, "need_more": bool}
```

对应解析：

```python
import json
out = json.loads(model_response)  # schema 对齐保证可解析
```

## 五、与其他技术对比

| 要素 | 写好 | 写差 |
|------|------|------|
| 角色 | 清晰单一 | 多重冲突 |
| 规则 | 必须/禁止 | 尽量/建议 |
| 输出 | 结构化 schema | 自由文本 |
| 长度 | 精简聚焦 | 冗长失焦 |

## 六、常见误区

- 系统提示过长被模型忽略（中间遗忘），却继续堆内容。
- 规则用模糊词「尽量」，无法判定与约束。
- 输出格式与解析器不对齐，导致生产解析失败。
- 多条硬规则互相矛盾，未声明优先级。

## 九、演进与趋势

从「手写好一段提示」走向「结构化、可组合、可版本化」的系统提示：用模板 + 配置生成、用评测回归守护、用提示编译器自动优化。多 Agent 中每个 Agent 拥有独立系统提示，整体由编排层管理。

## 十、小结

系统提示设计是上下文工程的基石：用清晰角色、可执行硬规则、对齐的输出 schema 与明确降级策略，把模型行为「钉」在预期范围内。关键是精简、无矛盾、可评测——长不等于强。
