# 检索增强上下文 RAG in Context

> 对应 Lewis et al. 2020（RAG: Retrieval-Augmented Generation）、LlamaIndex / LangChain RAG 文档。

## 一、背景与挑战

LLM 的知识固化在训练权重里，存在时效性与私有数据盲区，且易「幻觉」编造。检索增强生成（RAG）在生成前先检索相关知识，拼入上下文再生成，使回答**有据可依、可溯源**。作为上下文工程最常用的「动态信息源」，RAG 的质量高度依赖：检索是否相关、片段是否去重、排序是否合理、是否带来源标记。挑战在于：检索噪声会直接污染生成，Top-k 选择存在非线性权衡。

## 二、核心原理

RAG 流水线：① **索引**：把文档切块、Embedding 入库；② **检索**：对 query 做向量近邻检索取 Top-k；③ **组装**：把片段带来源标记拼入上下文；④ **生成**：模型基于片段回答并尽量引用。关键工程点：

- 检索质量决定上限：切块粒度、Embedding 模型、query 改写（multi-query/hyde）都影响召回。
- 片段排序与去重：相似片段冗余会浪费上下文，需重排（rerank）与去重。
- 相关性过滤：低分片段应丢弃，避免噪声。
- 来源标记：每段带来源，便于溯源与防御注入（见上下文隔离与安全）。
- Top-k 权衡：过多稀释注意力、引入噪声；过少召回不足。

RAG 的工程细节远比「检索+拼接」丰富。其一是**切块策略**：固定长度切块易切断语义边界，按章节/段落/句子边界切块、或重叠滑窗切块，能提升召回质量；对表格/代码等结构化内容应有专用解析，而非当作纯文本。其二是**查询改写**：原始 query 常简短且含指代（「它」「这个」），先用模型改写成自包含查询再检索，召回更准；multi-query 可生成多个角度的查询以覆盖不同表述。其三是**重排（rerank）**：向量召回的 Top-k 用交叉编码器重排，能显著改善相关性排序，把真正有用的片段排到前面。

来源标记与可追溯是生产底线：每个片段带来源（文档名+段落位置），生成时要求模型引用编号，既便于用户核查，也让错误可归因到具体检索。相关性过滤不能省——相似度低于阈值的片段应丢弃，宁缺毋滥，否则噪声会稀释对关键片段的注意力。对于「检索不到」的情况要有降级策略：明确告知用户「无可靠资料」，而非让模型凭空编造，这正是 RAG 相比纯生成最大的可信优势。

## 三、形式化与数学基础

给定查询 $q$ 与文档块集合 $\mathcal{D}=\{d_1,\dots,d_M\}$，检索取相关度最高的 $k$ 块：

$$\mathcal{R}_q = \text{TopK}_{d\in\mathcal{D}}\ \text{sim}\big(\text{emb}(q),\ \text{emb}(d)\big),\quad |\mathcal{R}_q|=k$$

生成条件概率在检索上下文上计算：

$$P(y\mid q) = \prod_{t} P_\theta\big(y_t \mid q,\ \mathcal{R}_q,\ y_{<t}\big)$$

注意力被 $k$ 个片段分摊，噪声片段占比：

$$\rho_{\text{noise}} = \frac{|\{d\in\mathcal{R}_q: \text{rel}(d,q)<\tau\}|}{k}$$

过大 $k$ 抬高 $\rho_{\text{noise}}$ 且稀释对关键片段的注意力，过小则召回不足——故存在非线性最优 $k^*$。

## 四、代码实现

LlamaIndex 最小 RAG 组装：

```python
from llama_index import VectorStoreIndex, Document
index = VectorStoreIndex.from_documents(docs)
query_engine = index.as_query_engine(similarity_top_k=3)
resp = query_engine.query("RAG 的核心思想是什么？")
# resp.response 为答案，resp.source_nodes 带来源可追溯
```

生产常加 rerank + 来源标记：`[1] 文档A第3段 ...`。

## 六、常见误区

- 认为「检索越多越准」，实则 Top-k 过多稀释注意力、引入噪声。
- 切块过大或过小，导致召回粒度不匹配。
- 检索片段不带来源标记，无法溯源且易注入。
- 不做相关性过滤，把低分噪声直接喂给模型。

## 九、演进与趋势

从「向量检索 + 拼文本」走向「多路检索（向量+关键词+图）+ 重排 + 自反思校验 + 迭代检索（self-RAG）」。Agentic RAG 还能根据生成需要主动决定再检索什么。

## 十、小结

检索增强上下文把「静态权重知识」升级为「动态可溯源知识」。成败在检索质量与片段组织：合理 Top-k、去重重排、来源标记，才能让模型「知其所据」。它是上下文工程最常用也最易踩坑的动态信息源。
