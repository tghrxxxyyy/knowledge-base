# 上下文压缩与摘要

> 对应 LangChain 文档（ConversationSummaryMemory / 摘要链）、Lewis et al. 2020（RAG 中压缩上下文思路）。

## 一、背景与挑战

上下文窗口虽在变大（8K → 32K → 128K 乃至更长），但「窗口大」不等于「该全塞」。长对话、长文档、长轨迹会快速抬高成本、增加时延，并因 lost-in-the-middle 现象降低模型对关键信息的利用率。当上下文逼近上限，必须压缩：否则直接截断会丢失早期关键信息（如用户偏好、已确认的事实），导致模型「翻脸不认账」。挑战在于：压缩会丢细节，如何「保主干、丢噪声」是关键。

## 二、核心原理

常用压缩策略三类，常组合使用：

- **对话摘要**：用 LLM 把历史轮次压成结构化摘要（谁、要什么、已确认什么、待办什么），保留语义骨架。
- **检索式记忆**：把历史写入向量库，按当前 query 召回相关片段，而非全量保留。
- **丢弃低价值轮次**：按重要性打分（如含决策/实体/约束的轮次保留，寒暄丢弃）。

组合范式是 **滑动窗口 + 关键摘要 + 检索**：最近若干轮原样保留（保新鲜），更早期用摘要/检索替代（保关键）。关键事实（ID、订单号、约束）应结构化保留，避免被摘要模糊化。

在长上下文模型的工程实践中，压缩并非「越短越好」，而是「保主干、丢噪声」。一个常见做法是分层处理：最近 2-4 轮原样保留（保新鲜交互），更早的轮次先尝试检索式取回相关片段，取不回再退化为摘要，最后才考虑丢弃。这样在窗口紧张时优先牺牲的是「大概率无关的早期寒暄」，而非「已确认的硬约束」。

另一个关键点是关键事实的结构化保留。用户 ID、订单号、已声明的偏好与禁忌，不应被压进一段自然语言摘要而模糊化，而应以字段形式（JSON / 表）单独维护，并在每轮注入前拼回上下文。否则模型会在后续轮次「遗忘」自己刚才答应过的事。对于工具型 Agent，还应保留「已完成动作清单」与「当前子目标」，避免重复调用或陷入循环。

压缩的触发也应智能化：不必每轮都跑摘要，可在上下文 token 数超过阈值（如窗口的 70%）时才触发一次压缩，平时用滑动窗口即可，从而控制成本。检索式记忆与摘要并非二选一，最优实践是「近期窗口 + 摘要骨架 + 检索补细节」三层叠加。

## 三、形式化与数学基础

设历史为序列 $h = (h_1,\dots,h_t)$，压缩函数 $\phi$ 输出保留集 $R_t = \phi(h_{\le t})$。目标是最小化信息损失：

$$\min_{\phi}\ \mathcal{L}_{\text{info}} = \sum_{k=1}^{t} w_k \cdot \mathbb{I}\big(\text{key}_k \notin \text{reconstruct}(R_t)\big)$$

其中 $\text{key}_k$ 为第 $k$ 轮关键事实，$w_k$ 为其重要性权重。约束为注入长度 $\text{len}(R_t) \le L_{\max}$（窗口上限）。摘要与检索分别提供 $\phi$ 的两种实现：摘要偏「全局压缩」，检索偏「按需取回」。

## 四、代码实现

用 LLM 做历史摘要压缩：

```python
from langchain.chains.summarize import load_summarize_chain
from langchain.llms import OpenAI

summarizer = load_summarize_chain(OpenAI(), chain_type="map_reduce")
summary = summarizer.run(old_turns)   # 把早期轮次压成一段摘要
new_context = f"[历史摘要]\n{summary}\n[近期对话]\n{recent_turns}"
```

更省成本的做法：只在 token 数超阈值时触发一次摘要，平时滑动窗口即可。

## 五、与其他技术对比

| 策略 | 保真度 | 成本 | 适用 |
|------|--------|------|------|
| 直接截断开头 | 低 | 低 | 不推荐 |
| 滑动窗口 | 中 | 低 | 局部相关 |
| LLM 摘要 | 中 | 中 | 长对话 |
| 检索式记忆 | 高（按需） | 中 | 长期/知识 |

## 六、常见误区

- 简单截断开头，丢最早确认的关键约束（如「不要做某事」）。
- 摘要过狠，把实体/数字模糊化（「用户要查订单」丢了订单号）。
- 只压缩不检索，长程事实彻底失忆。
- 每次都摘要，成本不必要；应设阈值触发。

## 九、演进与趋势

从「事后压缩」走向「原生长上下文 + 智能压缩」混合：模型原生支持长窗口，但工程上仍用压缩控制成本；并出现「自动决定摘要粒度」「分层记忆（情节/语义）」等更精细策略。

## 十、小结

上下文压缩的本质是「在窗口约束下保主干、丢噪声」。组合滑动窗口、LLM 摘要与检索式记忆，并把关键事实结构化保留，才能既控成本又不断联。盲目截断是最差解。
