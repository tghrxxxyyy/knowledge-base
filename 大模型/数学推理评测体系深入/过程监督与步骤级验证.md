# 过程监督与步骤级验证

> 对应 Lightman et al. 2023 "Let's Verify Step by Step" 与步骤级数学验证。

## 一、背景与挑战

数学解答错误常发生在某一步，结果监督无法定位。步骤级验证需对每步判正误，但人工标注昂贵、自动标注易传播错误。

## 二、核心原理

PRM 对每步输出正确/错误概率，推理时按步骤得分排序（best-of-n by process）。评测在 MATH 上比较 PRM 与 ORM 的分布外泛化，并测错误步骤召回率。

## 三、数学形式

步骤错误召回：

$$
R=\frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FN}}
$$

过程排序选择正确解概率：

$$
P_{\mathrm{sel}}=\sum_{\tau\in\mathcal{C}_{\mathrm{correct}}}s(\tau)
$$

## 四、代码实现

```python
def step_recall(tp, fn):
    return tp / (tp + fn) if (tp + fn) else 0.0

print(step_recall(18, 2))
```

## 五、与其他对比

相比 ORM，PRM 更细粒度且可解释；相比人工判卷，自动 PRM 可扩展但需防错误传播。

## 六、常见误区

误区一：PRM 标注可由强模型零成本获取（其实会带偏）。误区二：步骤全对即答案对（可能最后一步算错）。误区三：忽略累计误差。

## 八、面试题

- Q：步骤级验证为何难？答：需逐步标注且自动标注易传播模型错误。
- Q：PRM 如何排序候选？答：按各步正确概率累乘选最高分轨迹。

## 九、演进

从人工 PRM 到 math-shepherd 自举标注，步骤验证走向自动化与可扩展。

## 十、小结

过程监督以步骤级信用分配提升数学推理可靠性，是前沿推理训练的核心评测对象。
