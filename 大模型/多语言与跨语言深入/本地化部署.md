# 本地化部署

> 对应 llama.cpp、GGUF 量化与端侧推理实践，llm-course（mlabonne），及端侧大模型部署资料。

## 一、背景与挑战

数据与主权合规、网络受限、隐私保护与低延迟需求，推动大模型从「云端集中」走向「本地 / 边缘部署」。本地化部署的核心挑战：

- **算力受限**：本地设备（笔记本、手机、工控机）显存与算力远不及数据中心 GPU。
- **模型体积**：原始 FP16 模型动辄数十 GB，无法直接装入端侧。
- **语言适配**：本地模型需覆盖目标语言（尤其小语种），否则失去本地意义。
- **合规与离线**：部分场景要求数据不出本地、完全离线运行。

## 二、核心原理

本地化部署通过「压缩 + 高效推理」在受限硬件上跑起可用模型：

1. **量化（Quantization）**：将权重从 FP16 降为 INT8 / INT4 / 更低位，显存占用近似线性下降（如 4-bit 约为原 1/4），代价是少量精度损失。
2. **高效推理引擎**：llama.cpp（GGUF）、MLC-LLM、Ollama 等用 CPU / GPU / NPU 混合执行，支持 metal / CUDA / Vulkan 后端。
3. **模型选型**：优先选用已针对端侧优化的小模型（如 1B–14B 量级），配合本地语言 LoRA 适配器。
4. **数据闭环**：推理与微调均在本地完成，数据不出境，满足合规。

部署形态包括「纯本地离线」与「本地推理 + 远程安全护栏」两种，按合规强度选择。

## 三、形式化与数学基础

量化把浮点权重 w ∈ ℝ 映射到低位整数。以对称 INT4 为例，缩放因子：

$$
s = \frac{\max(|W|)}{2^{b-1} - 1}, \quad \hat w = \text{clip}\left(\text{round}\left(\frac{w}{s}\right), -2^{b-1}, 2^{b-1}-1\right)
$$

反量化近似为 w ≈ s · \hat w。显存节省比约为位宽比：

$$
R_{mem} \approx \frac{16}{b}
$$

INT4（b=4）约节省 4 倍显存。精度损失可用困惑度（perplexity）衡量，部署后需在目标语言上回测：

$$
PPL = \exp\left(-\frac{1}{N}\sum_{i}\log p(w_i|w_{<i})\right)
$$

PPL 上升过多则说明量化过度。

## 五、与其他技术对比

- **云端通用 API**：算力强、免运维，但依赖网络、存在数据出境与合规风险。
- **本地部署**：合规、离线、低延迟，但受硬件限制、需量化取舍。
- **边缘集群（含 GPU 服务器）**：介于两者之间，适合企业内网。
- **端侧 NPU 推理**：极致低功耗，但模型规模与精度受限更严。

## 六、常见误区

- **误区一：本地 = 落后**——合理量化下，中小模型可满足多数任务。
- **误区二：量化无损**——低位量化会抬升困惑度，需回测验证。
- **误区三：选型只看参数**——端侧更看推理引擎与硬件后端适配。
- **误区四：离线即可高枕无忧**——本地模型仍需安全护栏与输出过滤。

## 九、演进与趋势

模型压缩从单纯量化走向「量化 + 稀疏 + 结构化剪枝」协同；端侧 NPU 与统一内存架构（如 Apple Silicon）使更大模型可本地运行；本地 + 小模型的「个人助手」范式兴起。具体性能以官方最新基准为准。

## 十、小结

本地化部署以量化与高效推理引擎为支柱，在算力受限下实现合规、离线、低延迟的本地语言模型服务，是数据主权与小语种落地的关键路径。
