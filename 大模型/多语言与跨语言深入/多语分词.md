# 多语分词

> 对应 SentencePiece（Kudo & Richardson 2018）、字节级 BPE（Radford et al. 2019 GPT-2）、llm-course（mlabonne）与 HuggingFace Tokenizers 文档。

## 一、背景与挑战

多语言大模型面对数十到上百种语言，分词（Tokenization）是模型理解文本的第一道关卡。英语等空格分隔语言天然「词少、token 多信息」，而中文、日文、泰文、阿拉伯文等要么缺乏清晰词边界、要么字符集庞大，往往一个词被切成更多子词（subword），导致：

- 同等语义下，非英语文本的 token 数显著膨胀，直接抬高推理成本与上下文占用。
- 低资源语言在共享词表中占比极小，子词被切得过碎（退化为 byte-level fallback），语义表征退化。
- 跨语言迁移时，同一概念在不同语言被编码为不一致的子词序列，削弱共享表征效果。

因此，多语分词不只是「切词」，而是影响容量、成本、公平性与跨语一致性的核心设计问题。

## 二、核心原理

主流多语分词器普遍基于子词算法，核心思想是「高频词保留为整词、低频词递归拆分为更小的可复用片段」，在词表大小与覆盖度之间取平衡。

1. **SentencePiece（SPM）**：把输入视为纯字符序列，先做归一化（NFKC 等），再免预分词（whitespace 用特殊元符号 `_` 表示）地训练 BPE 或 Unigram 模型。它对语言无关，天然适合多语混合语料，被 mT5、LLaMA 系列等广泛采用。
2. **字节级 BPE（BBPE）**：以 UTF-8 字节（256 个基础符号）为最小单位，从根本上消除 OOV——任何字符都能用字节拼出。代价是序列更长、信息密度更低。
3. **Unigram LM**：基于概率语言模型择优保留子词，比 BPE 更易于控制词表并支持多语均衡采样。

多语词表通常通过「从合并所有语言语料训练得到的共享词表」实现跨语共享子词，使英语中的片段可在小语种被复用，是跨语言迁移的底层支撑。

## 三、形式化与数学基础

设语料由语言集合 L 组成，语言 l 的语料占比为 p_l，分词器得到子词序列 x。对句子 s_l（语言 l），其压缩比（token 数 / 字符数）可度量语言效率：

$$
r_l = \frac{|Tokenizer(s_l)|}{|s_l|_{\text{char}}}
$$

理想多语分词应满足「公平性约束」：信息量相当的文本，不同语言的 r_l 不应差得太悬殊。实际中英语 r_en 远低于泰语 r_th，导致单位信息成本：

$$
\text{cost}(l) \propto \frac{1}{r_l}
$$

即小语种单位信息成本更高。BPE / Unigram 的训练目标等价于在词表大小 |V| 约束下最小化训练语料的总 token 数：

$$
\min_{V} \sum_{s \in Corpus} |Tokenizer_V(s)| \quad \text{s.t.}\ |V| \le K
$$

由于语料以高资源语言为主，该目标天然偏向高资源语言，需在采样或词表分配上做纠偏（如过采样低资源语言、限制单语最大占比）。

## 四、代码实现

```python
# 以 SentencePiece 训练一个多语模型（参数以官方文档为准）
import sentencepiece as spm

spm.SentencePieceTrainer.train(
    input="multi_corpus.txt",      # 多语混合语料，按行混排
    model_prefix="multi",
    vocab_size=32000,              # 词表大小需按语言数权衡
    character_coverage=0.9995,     # 覆盖绝大多数字符，降低 OOV
    model_type="unigram",          # 或 "bpe"
    user_defined_symbols=["<lang:en>", "<lang:zh>"],  # 可注入语言标记
)

sp = spm.SentencePieceProcessor()
sp.load("multi.model")
# 编码：SPM 用 ▁ 表示原空格
ids = sp.encode("こんにちは world", out_type=int)
print(ids, sp.decode(ids))
```

```python
# 用 HuggingFace Tokenizers 对比多语 token 膨胀
from transformers import AutoTokenizer
tok = AutoTokenizer.from_pretrained("google/mt5-base")  # 多语 SentencePiece
en = tok("Hello world", add_special_tokens=False)["input_ids"]
th = tok("สวัสดีชาวโลก", add_special_tokens=False)["input_ids"]
print(len(en), len(th))  # 通常泰文 token 数明显更多
```

## 五、与其他技术对比

- **WordPiece（BERT 系）**：偏英文、依赖预分词与空格，多语友好度不如 SPM；如今多被更通用的 SPM / BBPE 取代。
- **字节级 BPE**：彻底无 OOV，但序列更长、训练更慢；GPT 系列采用以兼容任意 Unicode。
- **基于词的切分**：词表爆炸、OOV 严重，不适合多语大模型。
- **字符级**：序列过长、建模难，仅用于少数脚本特殊场景。

## 六、常见误区

- **误区一：同一模型对所有语言等价**——实际 token 数差异可达数倍，直接造成成本与性能不公平。
- **误区二：词表越大越好**——过大词表增加 embedding 参数与 softmax 计算，需在覆盖度与效率间权衡。
- **误区三：翻译后再分词等同原生**——跨语分词分布不同，翻译文本不能替代原生多语训练。
- **误区四：加数据就能解决低资源**——若分词仍把它切得很碎，容量瓶颈仍在子词层。

## 九、演进与趋势

从单语 BPE，到语言无关的统一 SPM，再到字节级 BPE 彻底消除 OOV；近年研究关注「多语词表均衡采样」「按语言动态分配子词容量」，以及训练后通过「继续预训练 + 扩容词表」为新增语言补充分词能力。更语义化的切分方法仍在探索中，具体方案以官方最新论文与文档为准。

## 十、小结

多语分词决定了模型对每种语言的容量分配与单位信息成本。选用语言无关的 SPM 或字节级 BPE、保持词表多语均衡、并用量化指标监控跨语 token 膨胀，是构建公平高效多语大模型的基础工程。
