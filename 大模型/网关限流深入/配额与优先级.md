# 配额与优先级

> 对应 gRPC, *Quota & Priority in API Gateways*（配额管理）；与 网关限流深入 / 优先级调度深入 衔接。

## 一、背景与挑战

多租户共享服务，需按套餐分配配额并区分优先级，避免大用户挤占。

## 二、核心原理

给用户/租户分配周期配额（token/QPS），并设优先级 tier；限流时高优先级先放行，低优先级先拒。

## 三、数学形式

配额消耗 $Q_u(t)=\sum \text{cost}$；剩余 $R_u=C_u-Q_u$；优先放行满足 $R_u\ge 0$ 且 $\text{tier}$ 高者。

## 四、代码实现

```python
if user.tier == "premium":
    limiter = premium_lim       # 更宽松
else:
    limiter = free_lim
```

## 五、与其他对比

- 与 优先级调度深入（网关层优先级与后端调度一致）协同。
- 与 网关限流深入（配额是限流维度）组成。

## 六、常见误区

- 配额周期过长难即时约束突发。
- 优先级滥用致低层用户饿死。

## 八、面试题

- 配额与限流区别？答：配额是周期总量预算，限流是瞬时速率控制，二者互补。

## 九、演进

无配额 → 固定配额 → 分层配额+优先级。

## 十、小结

配额+优先级实现多租户公平与保障，是商业化的基础。
