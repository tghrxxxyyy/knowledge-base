# 网关限流总览

> 对应 Turner, *A Practical Review of the Token Bucket Algorithm*, 1997（限流经典）；与 网关限流深入 / 服务框架深入 衔接。

## 一、背景与挑战

LLM 服务资源昂贵，突发流量会拖垮后端、超预算、致雪崩，需在入口限流。

## 二、核心原理

API 网关在请求进入服务框架前按规则（QPS/token/并发）限流、配额分配与降级，保护后端稳定性。

## 三、数学形式

限流目标：到达率 $\lambda$ 受控使 $\lambda\le \mu_{serve}$，且单位时间花费 $\le \text{budget}$。

## 四、代码实现

```python
if not limiter.allow(key=user, cost=1, burst=10):
    raise HTTPException(429, "rate limited")
```

## 五、与其他对比

- 与 服务框架深入（限流在更前层）串联。
- 与 优先级调度深入（限流后调度）前后衔接。

## 六、常见误区

- 仅限 QPS 忽略 token 成本差异巨大。
- 限流过严误伤正常用户。

## 八、面试题

- 为何 LLM 网关要限流？答：保护昂贵后端防雪崩、控预算、保公平，避免单用户耗尽资源。

## 九、演进

无限制 → 简单计数 → 多维（QPS/token/并发）限流。

## 十、小结

网关限流是 LLM 服务稳定与成本可控的第一道防线。
