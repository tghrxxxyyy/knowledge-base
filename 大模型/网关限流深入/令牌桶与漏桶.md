# 令牌桶与漏桶算法

> 对应 Turner, *Token Bucket / Leaky Bucket*, 1997；与 网关限流深入 衔接。

## 一、背景与挑战

需要平滑且可突发允许的限流，纯固定窗口易临界倍冲。

## 二、核心原理

令牌桶：以速率 $r$ 发令牌、容量 $b$，请求消耗令牌，空则拒；漏桶：以恒定速率流出整形流量。

## 三、数学形式

令牌数 $T(t)= \min(b,\,T_0+r(t-t_0))$；允许当 $T\ge \text{cost}$。

## 四、代码实现

```python
def allow(self, cost, now):
    self.tokens = min(self.burst, self.tokens + self.rate*(now-self.ts))
    if self.tokens >= cost:
        self.tokens -= cost; return True
    return False
```

## 五、与其他对比

- 与 基于Token的限流（以 token 数为 cost）是直接应用。
- 与 分布式限流（桶状态需共享）相关。

## 六、常见误区

- burst 设过大失去限流意义。
- 时钟回拨致令牌计算异常。

## 八、面试题

- 令牌桶 vs 漏桶？答：令牌桶允许突发（攒令牌），漏桶强制恒定速率整形。

## 九、演进

固定窗口 → 令牌桶/漏桶 → 分层桶。

## 十、小结

令牌桶/漏桶是限流基石，令牌桶更适配 LLM 突发生成场景。
