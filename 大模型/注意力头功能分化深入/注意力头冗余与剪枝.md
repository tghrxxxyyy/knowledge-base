# 注意力头冗余与剪枝

> 对应 Michel et al., *Are Sixteen Heads Really Better than One?*, NeurIPS 2019；Voita et al., ACL 2019。

## 一、背景与挑战

若多数头冗余，则可在几乎不损性能的前提下剪掉大部分头，降低推理成本。问题是如何可靠估计头的重要性并控制剪枝风险。

## 二、核心原理

标准做法是给每个头引入门控变量，用损失对门控的梯度估计重要性，再迭代剪枝与微调恢复。

- 重要性排序：一阶泰勒近似给出低成本的重要性代理，无需逐头重训。
- 结构冗余：许多层可只保留单头而性能下降有限，说明多头主要在训练期提供优化冗余。

## 三、数学形式

给定门控 $\xi_h\in\{0,1\}$，头重要性定义为 $I_h=\mathbb{E}_{x}\left|\dfrac{\partial \mathcal{L}(x)}{\partial \xi_h}\right|$，即一阶泰勒展开的绝对贡献。

剪枝目标为 $\min_{S}\ \mathcal{L}\big(\theta;\ \xi_{h}=0,\ \forall h\in S\big)$ s.t. $|S|\ge k$，实践中用贪心按 $I_h$ 升序剪。

## 四、代码实现

```python
import torch
def head_importance(model, batch, n_heads):
    gates = torch.ones(n_heads, requires_grad=True)
    loss = model(**batch, head_gates=gates).loss
    loss.backward()
    return gates.grad.abs().detach()                # 一阶重要性代理
```

## 五、与其他对比

- 与量化对照：剪枝改结构、需微调恢复；量化改数值精度、常可免训练。
- 与 头消融与因果干预 衔接：剪枝关注性能代价，消融关注功能归因，指标不同。

## 六、常见误区

- 用单任务验证集排序后全局剪枝，导致其他任务能力显著退化。
- 只看平均指标，忽略长尾样本与安全相关行为对特定头的依赖。

## 八、面试题

- 头重要性怎么算？答：给头加门控，用损失对门控梯度的绝对期望作一阶重要性代理。
- 为什么多头训练有用但推理可剪？答：多头提供优化期冗余，收敛后功能集中于少数头。

## 九、演进

均匀多头 → 重要性排序剪枝 → 迭代剪枝加微调 → 与量化/蒸馏联合的压缩流水线。

## 十、小结

头冗余是可利用的工程红利，但剪枝必须多任务评测，避免剪掉长尾与安全关键功能。
