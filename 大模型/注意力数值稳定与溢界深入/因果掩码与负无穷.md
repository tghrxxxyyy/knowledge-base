# 因果掩码与负无穷处理

> 对应 Transformer 解码器掩码（Vaswani17）；高效注意力实现中的掩码数值。

## 一、背景与挑战

自回归注意力需屏蔽未来位置。常见做法在 softmax 前加 $-\infty$，但 $-\infty$ 参与运算会触发 NaN（如 exp(-inf)=0 后 0/0）。

混合精度下 $-\infty$ 与有限值加减也需谨慎。

## 二、核心原理

掩码实现：在 scores 上加很大的负数（如 -1e9 或 torch.finfo 的 -inf），softmax 前已减最大值，使被掩位置 exp 后为 0。

但需保证减最大值后掩码项仍足够负，且最终不出现 0/0（所有位置被掩时才会 NaN，正常情形不会）。

## 三、数学形式

$\tilde s_{ij}=s_{ij}+M_{ij},\,M_{ij}=-\infty\ (j>i)$；$\mathrm{softmax}(\tilde s)_{ij}=0$ 当被掩；其余不变。

## 四、代码实现

```python
scores = scores.masked_fill(mask == 0, float("-inf"))
attn = torch.softmax(scores, dim=-1)     # 被掩处概率 0
```

## 五、与其他对比

- 与 softmax溢界 衔接，掩码依赖稳定 softmax。
- 与 长序列与溢出 衔接，掩码形状随序列增长。
- 与 混合精度溢出检测深入 相关，-inf 与有限值混合需 FP32。

## 六、常见误区

- 用 0 而非 -inf 掩码，未来位置仍有微弱概率泄漏。
- 在 FP16 中传 -inf，与有限值加出现 NaN。
- 全掩一行（未来全不可见）致 softmax 0/0 NaN。

## 八、面试题

- 掩码为何用 -inf？答：保证被掩位置 softmax 概率为严格 0，不泄漏信息。
- -inf 为何要 FP32？答：FP16 中 -inf 与有限值运算易产生 NaN。

## 九、演进

加性大负数 → -inf + 稳定 softmax → 分块掩码（FlashAttention）。

## 十、小结

因果掩码以 -inf 屏蔽未来，但须配合稳定 softmax 与 FP32 防 NaN。
