# 预训练范式演变

> 对应 Vaswani et al. 2017 *Attention Is All You Need*、Devlin et al. 2018 *BERT*、Radford et al. 2018/2019 *GPT*、Raffel et al. 2019 *T5* 等。

## 一、背景与挑战

Transformer 提出后，研究者在「如何预训练、用哪种架构」上分化为三条路线：Encoder-only、Decoder-only、Encoder-Decoder。它们的此消彼长，背后是「理解 vs 生成」「训练目标 vs 推理便利」「规模化友好度」的多重权衡。理解这段演变，对选型与读懂当今大模型为何多为 decoder-only 至关重要。

## 二、核心原理

- **Encoder-only（BERT）**：双向自注意力，看到整句上下文，预训练用掩码语言建模（MLM）。擅长分类、检索、NLU，但无法直接生成。
- **Decoder-only（GPT）**：因果自注意力，只能看左侧，预训练用自回归语言建模（LM）。天生适合生成与对话。
- **Encoder-Decoder（T5/BART）**：编码器理解、解码器生成，预训练常用去噪/span 填充，适合翻译、摘要等序列变换。

当今对话大模型几乎均为 decoder-only：生成任务统一、易做 scaling、KV Cache 友好、推理高效。

## 三、形式化与数学基础

三种注意力掩码决定可见范围。因果掩码 $M$ 使位置 $i$ 只能 attend 到 $j\le i$：

$$\mathrm{Attention}(Q,K,V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}} + M\right)V$$

其中 $M_{ij} = 0\ (j\le i)$，否则 $-\infty$。预训练目标各异：

- MLM（BERT）：$\max_\theta \log P(x_{\mathrm{masked}} \mid x_{\mathrm{visible}})$
- LM（GPT）：$\max_\theta \sum_t \log P(x_t \mid x_{<t})$
- Denoising（T5）：$\max_\theta \log P(x_{\mathrm{clean}} \mid \mathrm{noise}(x))$

## 四、代码实现

示意因果掩码构造：

```python
import torch

def causal_mask(seq_len, device="cpu"):
    # 下三角为0，上三角为-inf
    mask = torch.triu(torch.full((seq_len, seq_len), float('-inf')), diagonal=1)
    return mask.to(device)

def attn(q, k, v, mask=None):
    d = q.size(-1) ** 0.5
    scores = q @ k.transpose(-2, -1) / d
    if mask is not None:
        scores = scores + mask
    return torch.softmax(scores, dim=-1) @ v
```

## 五、与其他技术对比

| 架构 | 注意力 | 代表 | 当前地位 | 典型任务 |
|------|--------|------|----------|----------|
| Encoder | 双向 | BERT | 理解任务 | 分类、检索 |
| Decoder | 因果 | GPT/LLaMA/Qwen | 绝对主流 | 对话、生成 |
| Enc-Dec | 交叉 | T5/BART | 特定任务 | 翻译、摘要 |

## 六、常见误区

- 误区一：BERT「更强」。它是理解专用，不等于通用生成能力。
- 误区二：Encoder-Decoder 最适合一切。它结构复杂、推理慢，生成场景不如 decoder-only 简洁。
- 误区三：架构决定上限。数据、规模、对齐往往比架构差异更关键。

## 八、面试题

- 为何 decoder-only 成为大模型主流而非 encoder-decoder？从注意力、KV Cache、scaling 角度说明。
- BERT 的 MLM 与 GPT 的 LM 目标，分别带来什么能力差异？
- Encoder-Decoder 为何在翻译/摘要上曾占优？现在为何被 decoder-only 挑战？

## 九、演进与趋势

(1) decoder-only 大一统：因生成通用性与规模化优势，几乎一统对话/agent 场景。(2) 但编码器仍在检索、分类、embedding（如 BGE、E5）不可或缺。(3) 混合架构探索：如 Mamba 等线性注意力挑战 Transformer。(4) MoE 在 decoder-only 内增参不增算力。(5) 原生多模态预训练让「架构之争」扩展到跨模态统一。

## 十、小结

预训练范式从「三足鼎立」走向「decoder-only 主导」，根因是其生成统一性、KV Cache 友好与规模化红利。Encoder 在理解与检索、Enc-Dec 在特定序列变换仍有价值。架构选择本质是任务分布与工程约束的折中，而非单纯的强弱之分。
