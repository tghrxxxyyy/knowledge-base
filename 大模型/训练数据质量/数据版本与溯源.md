# 数据版本与溯源

> 对应 Data Version Control (DVC)、HuggingFace `datasets` 版本与 Google 「Datasheets for Datasets」(Gebru et al. 2021)。

## 一、背景与挑战

大模型训练是一次「数据驱动」的实验：同一份代码、不同数据版本可能得到能力截然不同的模型。若不做数据版本与溯源（data provenance），当出现「某能力退化」或「合规审计」时，无法回答「这个模型用过哪些数据、各占多少、来自何处、经过什么处理」。这违背可复现性（reproducibility）与可信 AI 的基本要求。挑战在于：训练数据规模巨大、来源多（爬虫、授权语料、合成数据），且处理链路长（过滤→去重→配比→打包），任一环节变动都应被记录；此外合规（如 GDPR、版权）要求能说明某段内容是否来自某受保护来源。

## 二、核心原理

数据版本与溯源包含三层：
1. **数据集版本化**：对原始与处理后数据集计算内容哈希（如 SHA256 或模糊哈希），每次生成新版本即留痕，类似代码 Git。DVC、HuggingFace `datasets` 的 `revision` 提供此类能力。
2. **处理链路记录**：用配置/清单记录过滤规则、去重参数、配比权重、打包长度，保证「同输入+同配置=同输出」可复现。
3. **来源快照与溯源**：保留每条样本的来源 URL、采集时间、许可证；合成数据标注生成模型与 prompt，支持向上追溯与向下归因（某能力来自哪批数据）。

核心实践是把「数据版本」与「模型 checkpoint 版本」绑定，形成可审计映射。

在合成数据盛行的当下，溯源还要覆盖「生成链路」：记录用于合成的基座模型、prompt 模板与采样参数，才能在发现偏见时反向回收。对合规而言，溯源粒度应到单条样本而非仅到数据集级——监管常要求说明某段内容是否源于特定受保护来源，粗粒度记录无法满足审计。数据指纹还应与训练超参、随机种子一并归档，方能完整复现一次实验。

## 三、形式化与数学基础

设数据集由域集合 $\mathcal{D}=\{D_1,\dots,D_m\}$ 构成，配比向量 $w=(w_1,\dots,w_m)$，$\sum w_i=1$。一次训练的数据指纹：

$$ \Phi = \text{hash}\Big(\big\{\text{hash}(D_i)\big\}_{i=1}^m,\, w,\, \theta_{\text{proc}}\Big) $$

其中 $\theta_{\text{proc}}$ 为处理超参。模型能力归因可用消融：移除域 $D_j$ 后能力变化 $\Delta_j = B(\Phi) - B(\Phi_{-j})$ 衡量 $D_j$ 的贡献。溯源即建立样本 $x$ 到来源 $s(x)$ 的映射 $x\mapsto (\text{url},\text{license},\text{time})$。

## 四、代码实现

```python
# 用 DVC 跟踪处理后的数据集版本（命令示意，非执行）
# dvc add data/train_processed
# dvc repro pipeline.yaml   # 配置驱动、可复现

import hashlib, json
def fingerprint(shards, weights, proc_cfg):
    h = hashlib.sha256()
    for s, w in zip(shards, weights):
        h.update(open(s, "rb").read()[:1<<20])   # 采样哈希
        h.update(str(w).encode())
    h.update(json.dumps(proc_cfg, sort_keys=True).encode())
    return h.hexdigest()

# 来源记录（每条样本附元数据）
record = {"text": "...", "source": "https://...",
          "license": "CC-BY-4.0", "generated_by": None}
```

## 五、与代码版本控制对比

| 维度 | 代码 Git | 数据版本 |
|------|----------|----------|
| 对象 | 文本 diff | 大文件/哈希 |
| 工具 | git | DVC/LakeFS/HF datasets |
| 成本 | 低 | 高（存储大） |
| 收益 | 可复现代码 | 可复现实验 |

二者配合：代码 + 数据指纹共同锁定一次训练。

## 六、常见误区

- **只存模型不存数据版本**：出问题时无法区分是数据还是代码变了。
- **用文件名而非内容哈希**：文件改名/覆盖会丢失真实版本信号。
- **溯源只记域不记样本**：合规审计需到单条来源，粗粒度不够。
- **合成数据不标生成模型**：后续无法评估某模型产出的偏见传导。
- **只记版本不记处理链**：缺过滤/去重参数，仍无法复现中间产物。
- **指纹不含随机种子**：同数据同配置因种子不同结果仍可异，复现不彻底。

## 七、与开源书·权威来源对应

## 九、演进与趋势

- **数据血缘图谱**：自动追踪样本从来源到模型的全程。
- **数据集卡片标准化**：`dataset card` 写明来源、偏见、许可。
- **可审计合成数据**：生成链全程留痕，支持监管。
- **差分隐私溯源**：在隐私合规下仍能定位来源。

## 十、小结

数据版本与溯源是可信、可复现训练的基石：用内容哈希锁版本、用清单锁处理链路、用元数据锁来源，并把数据指纹与模型 checkpoint 绑定。它既是工程需要，也是合规（版权、隐私）的前提。
