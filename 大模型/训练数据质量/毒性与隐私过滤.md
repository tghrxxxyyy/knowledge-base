# 毒性与隐私过滤

> 对应 Perspective API / Detoxify 毒性分类、Google「CISR」PII 实践与 OpenAI 预处理指南。

## 一、背景与挑战

预训练语料来自开放网络，天然混入两类高风险内容：**毒性内容**（暴力、色情、仇恨、自残等）与**个人可识别信息（PII）**（邮箱、电话、身份证、住址等）。若不前置过滤，模型会记忆并可能复现这些内容，既违反安全准则，也触碰版权与隐私法规（GDPR、CCPA、个人信息保护法）。过滤必须在训练前完成——一旦毒性/隐私进入参数，后续难以「洗掉」。挑战在于：毒性有文化相对性（多语言需本地化分类器），PII 形态多样（结构化如身份证、非结构化如闲聊中泄露的电话），且过滤过严会误杀正常文本（含邮箱的技术文档）、过松则留下风险，需精细权衡。

## 二、核心原理

两类过滤 pipeline：
1. **毒性过滤**：用分类器对文本打毒性分（toxicity score），高于阈值则剔除或降级。可用通用模型（Perspective API、Detoxify 基于 BERT）或自建。多语言需本地化模型，因同一词在不同语言毒性不同。
2. **PII 过滤/脱敏**：
   - **正则/模式匹配**：识别邮箱、手机号、身份证号、信用卡号等结构化 PII。
   - **NER/序列标注**：用命名实体识别模型找姓名、地址、组织等非结构化 PII。
   - **脱敏（anonymization）**：将识别到的 PII 替换为占位符（如 `[EMAIL]`），保留文本结构用于训练，而非整段删除。
   - **语义级检测**：大模型辅助识别隐式泄露（如「我住在北京朝阳区某某小区」）。

两者常组合：先 PII 脱敏保留文本，再毒性过滤剔除高危段。

过滤强度应「分域分级」：儿童向或客服场景阈值更严，科研/代码场景可放宽以免误杀含联系方式的正常文档。脱敏时优先保留文本结构（替换为占位符）而非整段删除，既能合规又能保住训练信号。对合成或翻译后重新流入的数据，需在管线末端做闭环复检，防止 PII 被重新引入。

## 三、形式化与数学基础

设文本 $x$ 的毒性分 $p_t(x)\in[0,1]$，PII 检测输出实体集合 $\mathcal{E}(x)=\{(e_i, \text{type}_i)\}$。过滤决策：

$$ \text{keep}(x) = \mathbf{1}[p_t(x)<\tau_t]\ \land\ \big(|\mathcal{E}(x)|=0\ \text{或已脱敏}\big) $$

脱敏映射 $x \mapsto x'$ 满足 $x'$ 中已无原始 PII，且分布 $P(x')\approx P(x)$（结构保留）。阈值 $\tau_t$ 由误杀率与漏放率权衡决定：

$$ \tau_t^* = \arg\min_{\tau} \big(\text{FN}(\tau)\cdot c_{\text{risk}} + \text{FP}(\tau)\cdot c_{\text{loss}}\big) $$

## 四、代码实现

```python
import re
from detoxify import Detoxify

tox = Detoxify("original")
EMAIL = re.compile(r"[\w.+-]+@[\w-]+\.[\w.-]+")
PHONE = re.compile(r"(?<!\d)\d{3}-\d{3,4}-\d{4}(?!\d)")

def clean(text, tau=0.5):
    scores = tox.predict(text)
    if scores["toxicity"] >= tau:          # 毒性过滤
        return None
    text = EMAIL.sub("[EMAIL]", text)      # PII 脱敏
    text = PHONE.sub("[PHONE]", text)
    return text

# 批量：先脱敏保留结构，再按毒性分筛
kept = [c for t in corpus if (c := clean(t)) is not None]
```

## 五、毒性 vs 隐私过滤对比

| 维度 | 毒性过滤 | PII 过滤 |
|------|----------|----------|
| 方法 | 分类器打分 | 正则+NER+脱敏 |
| 误杀代价 | 丢正常文本 | 丢含联系方式的文档 |
| 文化依赖 | 强（多语言） | 弱（格式较通用） |
| 处理方式 | 多剔除 | 多脱敏保留 |

## 六、常见误区

- **只删不脱敏**：整段删除损失大量有用文本，脱敏可保结构。
- **单语言分类器管全球**：中文毒性词需本地模型，英文模型误判高。
- **正则覆盖不全**：身份证/护照格式多样，漏掉即合规风险。
- **过滤后不复检**：合成或翻译数据可能重新引入 PII，需闭环。

## 七、与开源书·权威来源对应

- Perspective API、Detoxify 提供毒性打分；HuggingFace 上有多语言毒性分类器。
- Google「CISR」与 OpenAI 预处理指南描述 PII 检测与脱敏流程。
- spaCy / GLiNER 提供 NER 用于非结构化 PII 识别。
- 法规：GDPR 第 17 条（被遗忘权）、个人信息保护法要求去标识化。

## 九、演进与趋势

- **大模型辅助脱敏**：用 LLM 识别隐式 PII 与上下文毒性。
- **差分隐私训练**：在算法层进一步降低记忆风险。
- **合成数据替代**：用生成文本替换含 PII 的的真实段。
- **合规自动化**：把法规条款转成可执行过滤策略。
- **大模型辅助隐式 PII 检测**：识别上下文泄露（如闲聊中暴露住址）。
- **可解释拒答**：输出拒答理由，提升透明度与用户可接受度。

## 十、小结

毒性与隐私过滤是合规训练的前置闸门：毒性用分类器按阈值剔除，PII 用正则+NER 识别并优先脱敏而非删除，多语言需本地化。阈值是误杀与漏放的权衡，且需在合成/翻译数据上闭环复检。
