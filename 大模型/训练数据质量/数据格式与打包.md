# 数据格式与打包

> 对应 HuggingFace `datasets` (lhoestq et al.)、WebDataset (WebDataset 文档) 与 EfficientNet 训练数据实践。

## 一、背景与挑战

大模型预训练常在数 TB 乃至数十 TB 语料上运行，数据格式直接决定 I/O 效率与训练稳定性。朴素用 JSONL 逐行读取虽可读，但在分布式、高并发、流式训练下会成为瓶颈：海量小文件导致元数据开销大、随机读慢、难以跨节点流式。工业界因而转向列式（Parquet）与分片流式（WebDataset/TFRecord）格式。另一工程痛点是「padding 浪费」：固定长度序列若直接拼样本，短样本用大量 pad 补齐，浪费算力与显存。打包（packing）把多条样本无 padding 地拼接成定长序列，是提升吞吐的关键手段。挑战在于：打包需正确插入样本边界掩码，否则跨样本注意力会泄漏信息；格式选择需兼顾可读性与吞吐。

## 二、核心原理

主流格式对比：
1. **JSONL**：每行一个 JSON，人类可读、易调试，但小文件多、顺序读慢，适合中小规模或中间产物。
2. **Parquet**：列式存储，支持谓词下推与列裁剪，压缩率高，适合需按字段过滤/抽样的大规模数据集（HuggingFace `datasets` 默认后端之一）。
3. **WebDataset**：以 `.tar` 分片存储，每片含若干样本文件，天然适配对象存储与流式读取，避免海量小文件元数据开销。
4. **TFRecord / MDS**：TF 生态与 Mosaic 格式，强调顺序高吞吐。

打包：把 $k$ 条样本拼接为长度 $L$ 的序列，段间用特殊分隔符或 `sequence_id` 掩码隔离，注意力仅在同一段内计算。

## 三、形式化与数学基础

设样本长度 $l_1,\dots,l_k$，定长 $L$。静态（不打包）下每序列有效利用率：

$$ u = \frac{\sum_i l_i}{k\cdot L} \ll 1 \quad (\text{大量 pad}) $$

打包后把多条样本填入同一 $L$ 且不补 pad，利用率趋近：

$$ u_{\text{pack}} \approx \frac{\sum_i l_i}{L} \rightarrow 1 $$

代价是需构造块对角注意力掩码 $M$，其中 $M_{a,b}=0$ 当 token $a,b$ 属于不同样本。即：

$$ \text{attn}_{ab} = \frac{q_a k_b^\top}{\sqrt{d}} + M_{ab},\quad M_{ab}=-\infty\ \text{若跨样本} $$

## 四、代码实现

```python
from datasets import load_dataset
from tokenizers import Tokenizer

# 用 HuggingFace datasets 流式读取 Parquet（避免全量载入）
ds = load_dataset("json", data_files="shards/*.jsonl", streaming=True)
tok = Tokenizer.from_file("tokenizer.json")

# packing：按长度分桶后拼接（示意）
def pack(samples, L=2048, sep_id=2):
    buf, out = [], []
    for s in samples:
        ids = tok.encode(s["text"]).ids + [sep_id]
        buf += ids
        while len(buf) >= L:
            out.append(buf[:L]); buf = buf[L:]
    return out
```

## 五、格式对比

| 格式 | 读模式 | 吞吐 | 可读性 | 适用 |
|------|--------|------|--------|------|
| JSONL | 随机/顺序 | 低 | 高 | 调试/小数据 |
| Parquet | 列裁剪 | 高 | 中 | 大规模过滤 |
| WebDataset | 流式分片 | 最高 | 低 | 分布式训练 |
| TFRecord | 顺序 | 高 | 低 | TF 生态 |

## 六、常见误区

- **大规模还用 JSONL**：海量小文件拖垮文件系统元数据，训练空等 I/O。
- **打包忘加掩码**：跨样本注意力泄漏会让模型「偷看」下一条，评估失真。
- **pack 长度不设上限**：超长样本撑爆 batch，需先截断或分桶。
- **只追求吞吐忽略可读**：中间产物保留 JSONL 便于排查数据问题。

## 九、演进与趋势

- **确定性流式 shuffle**：跨 epoch 可复现且无需全量加载。
- **自适应 pack 长度**：按样本长度分布动态定 $L$ 最大化利用率。
- **远程存储原生**：直接读对象存储分片，省去本地拷贝。
- **样本级索引**：支持按 id 精确去重与抽样。

## 十、小结

数据格式与打包是训练工程的「看不见的杠杆」：流式分片格式（WebDataset/Parquet）解决 I/O 瓶颈，packing 用边界掩码消除 padding 浪费。选型按阶段权衡可读性与吞吐，并务必正确处理跨样本注意力隔离。
