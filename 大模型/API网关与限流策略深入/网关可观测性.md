# 网关可观测性

> 对应 OpenTelemetry/分布式追踪；LLM 网关观测。

## 一、背景与挑战

请求经网关→限流→服务多层，问题难定位，需全链路观测。

## 二、核心原理

网关打 trace/span、记请求数/延迟/token/错误；导出 Prometheus，看板 Grafana。

## 三、数学形式

错误率 $e = \frac{N_{err}}{N}$；P99 延迟为第 99 百分位；RED 指标（Rate/Errors/Duration）。

## 四、代码实现

```python
with tracer.start_as_current_span("gateway"):
    span.set_attribute("tokens", n); proxy(req)
```

## 五、与其他对比

- 与 大模型监控与告警深入（下游监控）衔接。
- 与 API网关总览深入 互补。

## 六、常见误区

- 只记网关层忽略下游耗时占比。
- 高基数标签（如每用户）爆炸指标。

## 七、与开源书对应

## 八、面试题

- 网关该记哪些指标？答：RPM/TPM、延迟、错误率、token，支撑限流与告警。

## 九、演进

日志 → 指标 → 分布式追踪。

## 十、小结

网关可观测性以 trace+RED 指标支撑限流与排障。
