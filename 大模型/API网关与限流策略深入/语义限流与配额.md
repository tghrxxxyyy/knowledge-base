# 语义限流与配额

> 对应 LLM 按 token/租户配额；语义级限流实践。

## 一、背景与挑战

按请求数限流忽略长短差异；应按 token 消耗与租户配额管理。

## 二、核心原理

限流维度：RPM（请求/分）、TPM（token/分）；按租户/key 配额；超额排队或拒（429）。

## 三、数学形式

配额约束 $\sum_i \text{tokens}_i \le Q_{tenant}$；TPM 限流 $\frac{\sum tok}{60}\le T$。

## 四、代码实现

```python
if tenant.tokens_this_min + est > quota: raise HTTP429()
tenant.tokens_this_min += est
```

## 五、与其他对比

- 与 成本优化与资源调度深入（配额即成本）衔接。
- 与 API网关总览深入 互补。

## 六、常见误区

- 只限 RPM 忽略长请求吃资源。
- 估 token 不准致配额漂移（用 tokenizer 估）。

## 八、面试题

- 为何按 token 限流？答：请求成本差异巨大，token 更贴资源消耗。

## 九、演进

RPM → TPM → 租户分级配额 → 语义预算。

## 十、小结

语义限流按 token/租户配额，更贴 LLM 实际成本。
