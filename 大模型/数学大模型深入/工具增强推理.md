# 工具增强推理

> 对应 Gao et al., *PAL: Program-Aided Language Models* (2022)；Chen et al., *ToRA: Tool-Integrated Reasoning* (2023)。

## 一、背景与挑战

大模型的心算与符号操作并不可靠：长数字相乘、微积分、矩阵运算常出现「看似合理却错误」的结果。根本原因不在于「不会」，而在于自回归生成无法保证数值精确。然而，模型擅长「理解问题、拆解步骤、写出求解程序」，这正是把计算外包给确定性工具的机会。纯语言推理的误差会沿链条累积，最后一步的差错让整题归零。

## 二、核心原理

工具增强推理（Tool-Augmented Reasoning）让模型在推理过程中输出可执行的代码（如 Python 表达式、SymPy 调用），由外部解释器运行并把结果回填，模型再据结果继续推理。代表工作 PAL（Program-Aided）用代码替代自然语言计算，ToRA 则联合训练「自然语言推理 + 工具调用」，使模型学会何时该写代码、何时该直接推。价值在于：计算误差趋近零、过程可追溯、且能处理超大数/高精度场景。

## 三、形式化与数学基础

设模型生成程序 $p$ 求解子问题 $q$，解释器 $\mathcal{E}$ 给出确定结果 $v=\mathcal{E}(p)$。整条推理轨迹为：

$$\tau = (s_1, \text{code}_1, v_1, s_2, \text{code}_2, v_2, \dots, y)$$

其中 $s_i$ 为自然语言步骤，$v_i$ 为工具返回。相比纯语言推理的误差累积：

$$\epsilon_{\text{lang}} = \sum_i \delta_i \quad\text{vs.}\quad \epsilon_{\text{tool}} \approx 0$$

因为 $\mathcal{E}$ 是确定性函数，单步数值误差 $\delta_i \to 0$，仅在「模型写错程序」时出错（属逻辑而非算术错），从而把误差来源从数值变为逻辑，更可控。

## 四、代码实现

```python
import sympy

# PAL 风格：模型写代码，解释器执行
def pal_solve(problem, llm):
    code = llm.generate_code(problem)   # 例如 "print(1/2 + 1/3)"
    try:
        result = eval_in_sandbox(code)   # 沙箱内执行
    except Exception as e:
        return f"code error: {e}"
    return result

# 用 SymPy 做符号计算（示意）
def symbolic(expr):
    return sympy.simplify(sympy.sympify(expr))

# 回填结果继续推理
def tool_augmented(problem, llm, max_rounds=5):
    ctx = problem
    for _ in range(max_rounds):
        step = llm.next_step(ctx)
        if step.needs_code:
            ctx += f"结果={eval_in_sandbox(step.code)}\n"
        else:
            ctx += step.text
    return ctx
```

## 六、常见误区

误区一：工具调用太慢不值得——准确率提升通常远胜延迟成本。误区二：模型写完代码就正确——程序逻辑错仍会导致错答，需校验。误区三：直接在生产环境执行模型生成的代码——必须有沙箱与权限隔离。误区四：所有计算都外包——简单整数加减反而增加开销。

## 九、演进与趋势

从单一 Python 执行，到多工具编排（计算器、检索、知识库、形式化验证器）；从「模型被动调用」到「训练时联合优化工具使用策略」；与 Agent 框架深度融合，形成「思考—调用—回填」的循环。

### 实践速查

- 触发：当问题含数值计算、方程、统计时优先走代码工具路径。
- 沙箱：模型生成代码必须在隔离、限资源、限权限环境中执行。
- 回填：执行结果以文本回填上下文，让模型据结果继续推理。
- 校验：代码异常需捕获并提示模型换思路，而非直接失败。
- 组合：PAL（纯代码）与 CoT（纯语言）可按题型混合使用。
- 边界：简单整数加减不必调用工具，避免无谓开销。

### 常见问题

- 问：代码执行结果错怎么办？答：多为模型写错程序逻辑，需回退重写。
- 问：工具调用安全吗？答：仅当严格沙箱化且禁网络/文件系统才安全。

## 十、小结

工具增强把不可靠的心算交给确定性执行器，让数学推理「可计算、可验证、可追溯」，但须以沙箱与校验为前提。
