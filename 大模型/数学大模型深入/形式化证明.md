# 形式化证明

> 对应 Polu & Sutskever, *Generative Language Modeling for Automated Theorem Proving* (GPT-f, 2020)；Lean 证明助手（leanprover/lean4）。

## 一、背景与挑战

自然语言的数学证明虽然对人类可读，却难以保证绝对严谨：隐含假设、跳步、措辞歧义都可能导致「看似正确实则有误」。对大模型而言，生成自然语言证明后缺乏可靠的判定器，无法确认其真伪。金融、安全等关键领域尤其无法接受「概率正确」的证明。更麻烦的是，自然语言证明难以被机器自动检验，模型可能给出「流畅但无效」的论证。

## 二、核心原理

形式化证明让 LLM 生成严格的形式语言（如 Lean、Isabelle、Coq）语句，由对应的证明助手（proof assistant）做机器验证。核心范式是「人机协作」：模型提出证明策略（tactic）与中间引理，证明助手负责类型检查与逻辑推演，一旦目标集清空即证明通过。这把「正确性判定」从不可靠的语言模型，移交给确定性的验证器。典型流程含三步：非正式陈述→形式化陈述（把自然语言转写为形式语言）、证明搜索（模型生成 tactic 序列）、验证闭环（失败则反馈重搜）。

## 三、形式化与数学基础

在 Lean 中，一个待证命题是一个类型 $\tau$，证明即构造该类型的项 $t : \tau$。证明搜索等价于在项空间中寻找 $t$：

$$\text{prove}(\tau) = \text{find } t \text{ s.t. } \vdash t : \tau$$

模型以策略语言生成步骤序列 $a_1,\dots,a_n$，每步将目标上下文 $\Gamma$ 变换：

$$\Gamma \xrightarrow{a_1} \Gamma_1 \xrightarrow{a_2} \cdots \xrightarrow{a_n} \emptyset$$

当目标集为空，证明完成。GPT-f 进一步用形式化证明作为奖励信号训练生成器，形成「证明即强化信号」的闭环，使模型在证明成功率上持续提升。

## 四、代码实现

```lean
-- Lean 4 示例：自然数加法交换律的形式化证明
theorem add_comm (a b : Nat) : a + b = b + a := by
  induction a with
  | zero => simp
  | succ a' ih => simp [Nat.add_succ, ih]

-- 模型可生成上述 tactic 序列，Lean 负责验证类型与逻辑
```

```python
# 神经证明搜索的极简循环（示意）
def search_lean(problem, model, timeout=30):
    ctx = init_context(problem)
    for _ in range(timeout):
        tactic = model.suggest(ctx)        # 模型建议下一步策略
        ctx, ok = lean_step(ctx, tactic)   # 证明助手执行并校验
        if ctx.is_empty():
            return "proved"
        if not ok:
            ctx = backtrack(ctx)           # 失败则回溯
    return "unknown"
```

## 五、与其他技术对比

## 六、常见误区

误区一：模型能写出证明文本就等于证明正确——必须经证明助手验证。误区二：形式化可完全自动化——当前仍需大量人工把陈述形式化，且证明搜索成本高。误区三：忽视训练数据稀缺——形式化语料远少于自然语言，易过拟合到少数库。误区四：认为所有数学都能轻易形式化——部分领域（如分析中的复杂估计）形式化极难。

## 九、演进与趋势

方向包括：更大规模的形式化语料建设、非正式到形式的自动翻译（autoformalization）、与过程奖励结合的选择性搜索，以及在数学奥林匹克级题目上的端到端尝试。形式化验证正从纯数学扩展到程序正确性证明。

### 实践速查

- 工作流：自然语言陈述 → autoformalization → tactic 搜索 → Lean 验证闭环。
- 数据：优先用已有形式化库（mathlib 等）作训练与验证来源。
- 搜索：结合人类书写的引理提示，能显著降低证明搜索宽度。
- 验证即奖励：证明成功即正例，可用于强化或重排序。
- 边界：非形式化领域（如复杂分析估计）形式化代价极高，需权衡。
- 工具链：lean4 + 证明搜索脚本 + 模型生成器是常见组合。

### 常见问题

- 问：模型写出的证明可信吗？答：必须经过 Lean 类型检查，文本本身不可信。
- 问：如何缓解数据稀缺？答：用强模型生成并自动验证，沉淀为可复用训练集。

## 十、小结

形式化证明把数学严谨性交给确定性验证器，是让大模型产出「可机器证」结论的根本路径，代价是数据稀缺与生成门槛高。
