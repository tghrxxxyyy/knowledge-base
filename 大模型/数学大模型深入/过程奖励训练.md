# 过程奖励训练

> 对应 Lightman et al., *Let's Verify Step by Step* (OpenAI, 2023)；Uesato et al., *Solving Math Word Problems with Process- and Outcome-based Feedback* (2022)。

## 一、背景与挑战

对数学题而言，仅用「最终答案对错」作为监督信号（结果奖励，ORM）存在致命缺陷：两条推理路径可能都得出错误答案，但其中一条的逻辑更接近正确；ORM 无法区分「优雅正确的中间步」与「侥幸蒙对的混乱推导」。更糟的是，强化学习若只看结果，容易奖励「碰巧答对」的捷径，而非可迁移的推理能力，导致过拟合到特定题型的表层模式。

## 二、核心原理

过程奖励模型（Process Reward Model, PRM）对推理链中的每一步独立打分，判断该步是否正确、是否有助于解题。训练时，PRM 的分数可作为强化学习（如 PPO）的稠密奖励，或在推理阶段做 best-of-n、beam search、蒙特卡洛树搜索的引导信号。Lightman 等人的实证显示，PRM 在 MATH 等竞赛题上显著优于 ORM，且与大模型自举标注结合后效果更好。关键洞见是：逐步信号能及时纠正错误方向，而不仅是事后奖惩。

## 三、形式化与数学基础

设推理链 $z=(z_1,\dots,z_m)$，步骤 $z_k$ 的隐式正确性为 $c_k\in\{0,1\}$。PRM 输出逐步概率：

$$r_k = P_{\theta}(c_k=1 \mid x, z_{\le k})$$

ORM 仅对整链打分：$R = P_{\phi}(y_{\text{final}} \text{ 正确} \mid x, z)$。

在以 PRM 为奖励的强化目标中，策略 $\pi$ 的期望回报可写为：

$$\mathcal{J}(\pi)=\mathbb{E}_{z\sim\pi}\Big[\sum_{k=1}^{m}\lambda^{m-k}\, r_k\Big]$$

其中 $\lambda$ 为折扣因子，越靠后的正确步骤权重越低（因其依赖前序）；该目标引导策略在每一步都朝高过程分方向优化，而非仅追求末端正确。

## 四、代码实现

```python
# 用 PRM 对单步打分并做回溯搜索（示意）
def prm_guided_search(problem, prm, generator, max_steps=8):
    best = None
    stack = [("", 0.0)]  # (已生成前缀, 累积过程得分)
    for _ in range(max_steps):
        prefix, score = stack.pop()
        step = generator(problem + prefix)
        step_score = prm.score(problem, prefix, step)
        if step_score < 0.5:
            continue  # 低分步骤剪枝
        new_prefix = prefix + step
        if is_final(new_prefix):
            return new_prefix  # 命中终态
        stack.append((new_prefix, score + step_score))
    return best
```

## 六、常见误区

误区一：PRM 标注一定准确——人工或模型标注的步骤级标签本身可能错，错误标签会系统性误导搜索。误区二：PRM 越强越好而忽略成本——逐步标注与推理时打分都昂贵，需权衡。误区三：把 PRM 当真理——它只是近似，对分布外推理仍会误判。误区四：直接用 PRM 做监督微调标签而忽视多样性。

## 九、演进与趋势

从人工逐步标注，走向模型自举标注（模型标模型）、自动形式化验证作金标（Lean 证明即标签），以及与 LLM-as-judge、树搜索深度融合。多模态与工具调用场景下的过程奖励也在探索中，目标是把「过程正确」变成可规模化获取的奖励。

### 实践速查

- 标注策略：先人工标少量高质量 PRM 数据，再让强模型自举扩充，最后用 PRM 过滤。
- 推理用法：best-of-n、beam search、MCTS 皆可，搜索宽度受 PRM 打分预算约束。
- 训练用法：作 PPO 稠密奖励，或作拒绝采样微调（RFT）的筛选器。
- 防御：定期用形式化验证或交叉 PRM 抽查标签质量，防止错误标签累积。
- 成本权衡：PRM 推理时打分较慢，可只在候选链末段启用以省算力。
- 常见失败：步骤切分粒度不一致会导致 PRM 打分漂移，需统一切分规则。

### 常见问题

- 问：PRM 能否完全替代 ORM？答：实践中常两者并用，ORM 作最终门禁、PRM 作过程引导。
- 问：步骤级标签从哪来？答：人工、模型自举、或形式化验证作金标。

### 关键记忆点

- PRM 解决「答案对≠会做」，把监督细化到每一步。
- 标注贵，但模型自举能大幅摊薄成本。

## 十、小结

过程奖励把「答案对错」细化为「每一步对错」，是提升数学推理可监督性与抗捷径能力的关键信号，但需正视其标注成本与近似误差。
