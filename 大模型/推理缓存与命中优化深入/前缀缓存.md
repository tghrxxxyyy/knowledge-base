# 前缀缓存

> 对应 Prompt/Prefix Caching（vLLM/Anthropic 支持）。

## 一、背景与挑战

系统提示、Few-shot、工具定义等长且复用，每请求重算 prefill 浪费。

## 二、核心原理

把相同前缀的 KV 缓存于显存，新请求匹配前缀直接复用，仅算差异部分。

## 三、数学形式

省算 $\Delta = \text{FLOPs}_{prefix} \times h_{prefix}$；命中时 prefill 仅差异 token。

## 四、代码实现

```python
# vLLM automatic prefix caching
llm = LLM(model=..., enable_prefix_caching=True)
```

## 五、与其他对比

- 与 推理缓存与命中优化深入 总览衔接（精确缓存）。
- 与 PagedAttention深入（KV 块共享）机制同源。

## 六、常见误区

- 前缀少许不同（如时间戳）致不命中。
- 缓存无淘汰致显存涨。

## 八、面试题

- 前缀缓存省在哪？答：复用系统提示等 KV，免重复 prefill 计算。

## 九、演进

无复用 → 手动 → 自动前缀缓存（哈希匹配）。

## 十、小结

前缀缓存复用稳定前缀 KV，是低成本高收益优化。
