# 缓存与一致性

> 对应缓存失效/一致性；LLM 答案时效。

## 一、背景与挑战

知识更新或模型切换后，旧缓存答案过时甚至错误，需失效策略。

## 二、核心原理

按 TTL 过期、按版本（模型/知识库）命名空间隔离、显式失效（知识变更清相关）、写时校验。

## 三、数学形式

新鲜度 $f = \frac{|\text{fresh}|}{|\text{cache}|}$；过期项占比高则 $f$ 低。

## 四、代码实现

```python
cache = VersionedCache(ns=f"m{v}:kb{k}")   # 模型/库版本隔离
cache.invalidate(prefix=doc_id)
```

## 五、与其他对比

- 与 语义缓存深入（命中逻辑）互补（本节管失效）。
- 与 大模型监控与告警深入（命中率监控）衔接。

## 六、常见误区

- 全局清缓存致命中率瞬崩。
- 忽略模型版本致新旧答案混。

## 七、与开源书对应

## 八、面试题

- 如何保缓存一致？答：版本命名空间+ TTL + 知识变更显式失效。

## 九、演进

不过期 → TTL → 版本隔离+显式失效。

## 十、小结

缓存一致靠版本与失效策略，防过时答案。
