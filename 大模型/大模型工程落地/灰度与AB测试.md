# 灰度与 A/B 测试

> 对应 llm-course (mlabonne) 与工业界 LLM 生产化实践（以官方最新文档为准）。

## 一、背景与挑战

大模型应用的质量很难用传统单测覆盖：提示词或模型的一次微调，可能让某些问题变好、另一些变差，且这种波动在离线小样本上不易暴露。
直接全量发布等于把不确定性直接暴露给全部用户。
灰度（渐进发布）与 A/B 测试提供了一条「用小流量验证、用数据决策」的安全路径，把发布风险控制在可承受范围内。

## 二、核心原理

核心流程是：先给新 prompt / 新模型分配小比例流量（如 1%–5%），与线上对照组同台对比，观察业务指标后再决定是否扩量。
关键约定：

- **流量随机且对齐**：实验组与对照组需来自同一用户分布，避免样本偏差。
- **统一埋点**：两组必须记录相同的指标口径（满意度、成本、时延、转化率）。
- **明确决策阈值**：事先定义显著性水平与最小样本量，避免「看了再改标准」。
- **可回滚**：一旦指标劣化，立即切回基线。

## 三、形式化与数学基础

对指标 $Y$，设对照组均值 $\bar{Y}_c$、实验组 $\bar{Y}_e$，样本方差 $s^2$、样本量 $n$，两比例 $z$ 检验统计量为：

$$
z = \frac{\bar{Y}_e - \bar{Y}_c}{\sqrt{2 s^2 / n}}
$$

当 $|z| > z_{1-\alpha/2}$（如 1.96）时认为差异显著。
所需最小样本量随效应量 $\delta$ 缩小而平方级增长：

$$
n \propto \left(\frac{z_{1-\alpha/2} + z_{1-\beta}}{\delta}\right)^2
$$

LLM 指标噪声大，往往需要更大样本或更长观测窗口；同时应监控多个指标（质量、成本、时延）做权衡，而非单一指标决策。

## 四、代码实现

以按用户 id 哈希分流为例，保证同一用户稳定落组：

```python
import hashlib

def assign_bucket(user_id: str, exp_ratio: float = 0.05) -> str:
    h = int(hashlib.md5(user_id.encode()).hexdigest(), 16)
    bucket = (h % 100) / 100.0
    return "experiment" if bucket < exp_ratio else "control"

# 记录指标时带上 bucket，便于后续对比
bucket = assign_bucket(user_id)
log_metric(bucket, latency_ms, cost_tokens, satisfaction)
```

## 五、与其他技术对比

| 方式 | 风险 | 反馈速度 | 适用 |
|------|------|----------|------|
| 直接全量 | 高 | 慢（已影响全体） | 极稳定变更 |
| 灰度 | 低 | 中 | 常规 prompt/模型迭代 |
| A/B 测试 | 低 | 慢（需统计显著） | 质量/成本权衡决策 |
| 离线评测 | 无 | 快 | 初步筛选 |

## 六、常见误区

- 只盯单点指标（某次满意度），忽略长期与分布变化。
- 实验组/对照组流量非随机，导致结论不可信。
- 中途篡改决策标准，把不显著的结果「解释」成成功。
- 忽视成本指标：质量略升但成本翻倍未必划算。

## 九、演进与趋势

从简单 A/B 走向「多臂老虎机（MAB）」与上下文 Bandit，自动分配流量给更优变体；结合在线评测与护栏，实现「安全探索」；并把 prompt 版本作为实验的第一公民纳入治理。
工程上常在正式 A/B 之前引入「影子模式（shadow mode）」：新 prompt/模型并行运行但不向用户返回结果，仅把生成内容与线上基线做离线对比，用于提前发现明显退化。

除了离线分析，建议把「自动回滚」纳入发布流程：当实验组在核心指标上相较基线劣化超过预设阈值（如满意度下降 > 1% 且持续 10 分钟），系统自动把流量切回基线，避免依赖人工盯盘。
这类「指标驱动发布（metric-driven release）」把灰度从「人工决策」升级为「闭环自动化」，是大规模 LLM 服务上线的标准做法。

## 十、小结

实验设计上还有两个易错点：一是「新奇效应」，新模型刚上线时用户因新鲜感给出更高满意度，需在指标中剔除或拉长观测窗口；二是「辛普森悖论」，整体指标改善可能掩盖某细分人群（如长 query 用户）的退化，因此应按用户分群分别看指标。
落地时建议把 prompt/模型版本、分流比例、各群指标写入统一看板，使「是否扩量」成为可复盘的数据决策，而非依赖直觉。
灰度与 A/B 测试把「发布」从一次性冒险变成持续的数据驱动决策：小流量验证、统一埋点、显著性决策、可回滚，是对抗 LLM 输出不确定性的工程护栏。
