# 缓存策略

> 对应 vLLM / HuggingFace TGI 文档与 llm-course (mlabonne)。

## 一、背景与挑战

LLM 推理中相当一部分请求是重复的或可预测的：相同问题反复出现、相似问题语义等价、同一系统提示被每请求复用。
缓存既能直接降本（省去一次推理），又能降时延（毫秒级返回）。
但缓存引入「陈旧性」与「误命中」两类风险，需要针对场景选择不同缓存形态并配套失效策略。

## 二、核心原理

常见缓存层级：

- **精确缓存（Exact Cache）**：query 完全一致才命中，最安全，适合固定问答。
- **语义缓存（Semantic Cache）**：用嵌入相似度命中「近似」问题，覆盖同义改写，需阈值防误命中。
- **前缀缓存（Prefix Cache / KV Cache 复用）**：系统提示等长前缀的 KV 在多次请求间复用，减少 prefill 计算，属推理引擎层优化。
- **结果缓存（Result Cache）**：对确定性任务（如固定模板抽取）缓存最终答案。

## 三、形式化与数学基础

语义缓存以余弦相似度判定命中：对查询嵌入 $\mathbf{q}$ 与缓存项嵌入 $\mathbf{k}$，当

$$
\text{sim}(\mathbf{q}, \mathbf{k}) = \frac{\mathbf{q}\cdot\mathbf{k}}{\|\mathbf{q}\|\,\|\mathbf{k}\|} \ge \tau
$$

时视为命中，$\tau$ 为相似度阈值。
命中率 $h$ 与误命中率 $f$ 共同决定收益与风险：过高 $\tau$ 降收益，过低 $\tau$ 升 $f$。
前缀缓存节省的 prefill 计算约为复用前缀长度 $L_p$ 对应的注意力开销，即跳过对前 $L_p$ 个 token 的 $QK^\top$ 重算。

## 四、代码实现

语义缓存的写入与查询骨架：

```python
import numpy as np

class SemanticCache:
    def __init__(self, threshold=0.92):
        self.items = []          # {"emb": np.ndarray, "answer": str}
        self.threshold = threshold

    def get(self, q_emb: np.ndarray) -> str | None:
        for it in self.items:
            sim = np.dot(q_emb, it["emb"]) / (
                np.linalg.norm(q_emb) * np.linalg.norm(it["emb"]))
            if sim >= self.threshold:
                return it["answer"]
        return None

    def put(self, q_emb: np.ndarray, answer: str):
        self.items.append({"emb": q_emb, "answer": answer})
```

## 五、与其他技术对比

| 缓存类型 | 命中条件 | 收益 | 风险 |
|----------|----------|------|------|
| 精确缓存 | 完全一致 | 高、安全 | 命中率低 |
| 语义缓存 | 相似度≥τ | 中高 | 误命中 |
| 前缀 KV 缓存 | 前缀相同 | 降 prefill | 需引擎支持 |
| 结果缓存 | 任务确定 | 高 | 陈旧 |

## 六、常见误区

- 语义缓存阈值设得过低，把「相似但答案不同」的问题错误复用。
- 忽略缓存陈旧（stale）：知识更新后旧答案仍在返回，需 TTL 或失效钩子。
- 把前缀缓存当成应用层功能，其实应由推理引擎（如 vLLM 的自动前缀缓存）承担。
- 不区分读写场景，对易变内容也长缓存。

## 九、演进与趋势

语义缓存与向量库深度融合、命中判定结合置信度与任务类型；前缀缓存走向跨请求、跨会话的 KV 共享；并出现「语义 + 精确」混合分层缓存以兼顾收益与安全。
部分推理引擎还支持基于对话前缀的自动复用，进一步降低多轮对话成本。
生产系统常采用「分层混合缓存」：先查精确缓存（命中即返），未命中再查语义缓存（相似度≥阈值），最后才进入推理并回填。

## 十、小结

在评测缓存效果时，应同时监控命中率、误命中率与「命中带来的时延/成本节约」三项，避免只看命中率而忽略误命中对质量的伤害。
一个实用经验是：对高确定性、低变化的内容（如产品规格、政策条款）可设较长 TTL；对易变的实时信息（如股价、库存）应缩短或禁用缓存。
缓存是 LLM 降本提效的关键杠杆，但需按场景选型：精确保安全、语义扩覆盖、前缀降计算、结果缓存确定任务，配套阈值与失效策略，才能避免误命中与陈旧。
