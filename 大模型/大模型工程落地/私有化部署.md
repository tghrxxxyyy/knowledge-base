# 私有化部署

> 对应 vLLM / Megatron-LM / DeepSpeed 官方文档。

## 一、背景与挑战

当数据合规、隐私保护或长期成本成为硬约束时，调用公有云 API 不可行：数据必须不出域，且 API 的持续按 token 计费在高频场景下可能超过自建成本。
私有化部署把开源权重（如 LLaMA、Qwen、GLM 系列）部署到内网 GPU 集群，配合高效推理引擎提供服务。
代价是一次性硬件投入与持续的运维责任，以及模型权重许可的合规审查。

## 二、核心原理

私有化链路通常包括：模型权重获取与许可校验 → 量化/切分以适配显存 → 推理引擎（vLLM / TensorRT-LLM / TGI）部署 → 网关鉴权与限流 → 监控与扩缩。
核心权衡：

- **数据不出域**：满足合规，但需自建全套可观测与审计。
- **可定制**：可微调、可换模型、可离线运行。
- **成本结构**：前期 CAPEX（硬件）+ 运维 OPEX，长期高频场景单位成本低于 API。
- **门槛**：需 GPU、需工程能力，模型权重许可需合规（部分模型限制商用）。

## 三、形式化与数学基础

显存占用可粗估为权重、KV Cache 与激活三部分：

$$
\text{VRAM} \approx \underbrace{P \times b}_{\text{权重}} + \underbrace{B \times L \times 2\,n\,d}_{\text{KV}} + \underbrace{A}_{\text{激活}}
$$

其中 $P$ 为参数量，$b$ 为每参数字节数（FP16 为 2，4-bit 为 0.5），$B$ 为批大小、$L$ 为层数、$n$ 为序列长、$d$ 为隐维。
量化通过降低 $b$ 直接把 7B–13B 模型压进单卡；张量并行则把 $P$ 沿层切到多卡，使单卡显存需求降至 $P\cdot b / T$（$T$ 为卡数）。

## 四、代码实现

以 vLLM 启动一个量化模型并限制并发为例（命令行示意，参数以官方最新文档为准）：

```bash
# 4-bit 量化权重（如 AWQ/GPTQ）由对应工具离线产出
python -m vllm.entrypoints.openai.api_server \
    --model Qwen/Qwen2.5-7B-Instruct \
    --quantization awq \
    --tensor-parallel-size 1 \
    --max-num-seqs 32
```

Python 侧调用本地 OpenAI 兼容端点：

```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")
resp = client.chat.completions.create(
    model="Qwen/Qwen2.5-7B-Instruct",
    messages=[{"role": "user", "content": "你好"}],
)
print(resp.choices[0].message.content)
```

## 五、与其他技术对比

| 方式 | 数据合规 | 长期成本 | 运维负担 | 灵活性 |
|------|----------|----------|----------|--------|
| 公有云 API | 弱（出域） | 随用量线性 | 低 | 低（不可控） |
| 私有化部署 | 强 | 高频更优 | 高 | 高 |
| 混合（敏感本地/其余云） | 中 | 中 | 中 | 中 |

## 六、常见误区

- 忽视模型权重许可，商用踩合规红线。
- 只看「能否跑起来」，不做并发与显存压测。
- 用训练框架（如原生 PyTorch）直接当推理服务，吞吐与并发远不及专用引擎。
- 低估运维：驱动、引擎升级、监控告警都需专人。

## 九、演进与趋势

方向是更小更强的开源模型（3B–14B 接近旧代大模型）、统一推理引擎、边缘/端侧部署（手机、PC NPU），以及「模型即服务」的内部平台化。
量化从 GPTQ 演进到 AWQ、乃至 FP8 推理，使单卡承载更大模型成为常态。
在模型选型上，私有化并不等于「越大越好」：许多企业场景用 7B–14B 的指令微调模型即可覆盖大部分工单/问答，配合检索增强能达到 70B 级闭源模型的可用效果，而硬件成本仅为其零头。

## 十、小结

常见的落地路径是「小模型打底 + 大模型兜底」——高频简单请求走本地小模型，复杂/高风险请求才路由到更大的本地或云模型。
这种混合部署在合规与成本之间取得了务实的平衡。
私有化部署用工程与硬件换取数据主权与长期成本可控：成功关键在于合规校验权重、量化适配显存、专用引擎保吞吐、完善监控与回滚。
