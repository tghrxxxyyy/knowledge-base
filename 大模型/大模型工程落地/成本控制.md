# 成本控制

> 对应 Kaplan et al. 2020 Scaling Laws 与 llm-course (mlabonne)。

## 一、背景与挑战

对大多数应用方而言，成本由**推理**而非训练主导。LLM 采用基于 token 的计费：长上下文、多轮对话、工具调用会成倍放大 token 消耗。商业可行性取决于「每个有价值产出的成本」，而非「能否跑通」。若不对成本施加工程约束，一个看似正确的功能也可能因单位经济不可持续而无法上线。

## 二、核心原理

成本的根本公式是：

$$
C = n_{in}\,p_{in} + n_{out}\,p_{out}
$$

其中 $n_{in}/n_{out}$ 为输入/输出 token 数，$p_{in}/p_{out}$ 为对应单价。常见降本杠杆：

- **精简上下文**：压缩 system prompt、裁剪检索片段，降低 $n_{in}$。
- **缓存**：精确缓存、语义缓存、前缀 KV 缓存，避免重复计算输入。
- **模型路由**：简单问题用小模型，复杂问题才上大模型。
- **量化部署**：用 4-bit / 8-bit 降低单位推理硬件成本。
- **批处理 / 连续批处理**：提高 GPU 利用率，摊薄固定开销。
- **预处理分类**：用轻量模型先做路由或过滤。

## 三、形式化与数学基础

设路由器把比例 $\alpha$ 的流量导向小模型（单位成本 $c_s$），其余流向大模型（$c_l$），则平均单位成本：

$$
\bar{c} = \alpha c_s + (1-\alpha) c_l
$$

相对「全量大模型」的节省比为：

$$
1 - \frac{\bar{c}}{c_l} = \alpha\left(1 - \frac{c_s}{c_l}\right)
$$

若缓存命中率为 $h$，则等效输入成本为 $(1-h)\,n_{in}\,p_{in}$。可见提升命中率 $h$ 与路由比例 $\alpha$ 是两条最直接的降本路径。

## 四、代码实现

语义缓存根据嵌入相似度复用历史答案：

```python
import numpy as np

def cached_answer(query_emb, cache, threshold=0.92):
    best, best_sim = None, -1.0
    for item in cache:
        sim = np.dot(query_emb, item["emb"]) / (
            np.linalg.norm(query_emb) * np.linalg.norm(item["emb"]))
        if sim > best_sim:
            best, best_sim = item, sim
    if best_sim >= threshold:
        return best["answer"], "cache_hit"
    return None, "miss"
```

## 五、与其他技术对比

| 杠杆 | 主要收益 | 潜在风险 |
|------|----------|----------|
| 模型路由 | 大幅降本 | 路由错误致质量下降 |
| 语义缓存 | 省重复输入 | 阈值过低致误命中 |
| 量化 | 降单位推理价 | 精度/质量回归 |
| 精简 prompt | 降输入 token | 信息缺失 |
| 批处理 | 提 GPU 利用率 | 尾延迟上升 |

## 六、常见误区

- 只优化输出 token，忽视输入（system prompt + 检索上下文往往占大头）。
- 语义缓存阈值设得过低，相似但不同的问题被错误复用。
- 量化后不测量质量回归，上线才发现效果掉点。

## 八、面试题

- 模型路由如何在不显著降质下降本？阈值如何确定？
- 为何输入 token 成本常被低估？
- 量化会如何影响单位推理成本与质量？

## 九、演进与趋势

方向是「小专用模型 + 路由器」协同、投机解码（speculative decoding）、KV 缓存共享、长上下文模型减少 RAG 检索开销，以及按请求预算（token budget）的精细化管控。

## 十、小结

成本控制是一组跨「提示词—缓存—路由—部署」的杠杆组合，目标是「每个质量产出对应的成本」最小化，而非单纯压低 token 数。用数据（命中率、路由比例、质量分）驱动取舍，才能兼顾体验与商业可行。
