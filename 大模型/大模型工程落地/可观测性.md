# 大模型可观测性

> 对应 LangSmith / Phoenix 官方文档与 llm-course (mlabonne)。

## 一、背景与挑战

传统监控只关心 HTTP 状态码与接口时延，但 LLM 应用的「逻辑」藏在自然语言提示与模型推理中，失败往往是「软失败」——答非所问、幻觉、越界，而非进程崩溃。一旦叠加 RAG 与 Agent，一次用户请求会展开为多步检索、重排、工具调用与子提示，任意节点出错都会污染最终结果，却难以归因。生产团队必须能回答：是哪一步产生了错误答案？实际发给模型的提示是什么？这次请求花了多少 token、多少成本？prompt 改动后质量是否在回归？可观测性正是把黑盒变成可调试系统的前提。

## 二、核心原理

可观测性在 LLM 场景下沿用「三支柱」并补齐质量信号：

- **日志（Logs）**：完整记录请求/响应、最终提示与补全、所用模型与采样参数、token 计数、时延，便于事后归因。
- **追踪（Traces）**：把一次请求拆成 span 树，覆盖「检索 → 重排 → 生成 → 工具调用」各节点及其父子耗时。
- **指标（Metrics）**：token 成本、时延分位数（p50/p95/p99）、错误率、缓存命中率，以及随时间的评测分数。
- **评测信号（Evals）**：离线与在线评测结果作为「质量指标」并入观测，弥补日志指标看不到的语义退化。

实践中还需关注**记录粒度与隐私**：全量记录 prompt/response 利于归因，但可能包含用户 PII，应在落盘前做脱敏或采样；高敏感场景可只存元数据与哈希。同时，把 prompt 版本号、模型版本号写入 trace 上下文，才能在指标波动时快速归因到具体变更。

## 三、形式化与数学基础

一次追踪可建模为 span 树。设 span $s_1,\dots,s_m$ 持续时间为 $d_i$，则关键路径时延为：

$$
T = \sum_{i \in \text{critical path}} d_i
$$

单次追踪的 token 成本为：

$$
C = n_{in}\,p_{in} + n_{out}\,p_{out}
$$

窗口内平均成本 $\bar{C} = \frac{1}{N}\sum_k C_k$；缓存命中率 $h = \frac{\#\text{hits}}{\#\text{requests}}$ 可直接折算为输入成本节约 $(1-h)\,n_{in}\,p_{in}$。

## 四、代码实现

以 OpenLLMetry 风格的自动埋点为例，函数调用会被自动记录为 span：

```python
from langsmith import traceable
from openai import OpenAI

client = OpenAI()

@traceable(name="generate")
def generate(prompt: str) -> str:
    resp = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
    )
    return resp.choices[0].message.content

# 调用后可在 LangSmith / Phoenix 中看到完整 trace 树
print(generate("用一句话解释注意力机制"))
```

## 五、与其他技术对比

| 维度 | 传统 APM（Prometheus/Jaeger） | LLM 可观测性（LangSmith/Phoenix） |
|------|------------------------------|-----------------------------------|
| 关注对象 | 接口、服务、容器 | 提示、补全、检索、工具调用 |
| 关键字段 | 状态码、耗时 | token 数、成本、评测分 |
| 失败定义 | 异常/超时 | 语义错误、幻觉 |
| 质量闭环 | 告警 | 评测 + 灰度 |

## 六、常见误区

- 只记录最终答案，不记录中间提示与工具调用，导致无法定位根因。
- 把一切异常当成 HTTP 错误，忽略「软质量退化」（答案变差但未报错）。
- 不对提示词做版本管理，指标波动时无法关联到具体变更。

## 九、演进与趋势

行业正推动 OpenTelemetry 的 GenAI 语义约定标准化；离线评测与在线监控趋于融合，把「评测分数」作为一等指标；同时出现提示词版本化、PII 脱敏后再落盘日志等隐私友好实践。

行业正推动 OpenTelemetry 的 GenAI 语义约定标准化，使 trace 中的 token、模型、工具调用等字段具备跨工具可比性，便于在 LangSmith、Phoenix、自研平台间迁移。

需要强调的是，可观测性的终点不是「堆图表」，而是「可行动」：当某次评测分数下跌时，应能下钻到具体 span、具体 prompt 版本，定位是检索质量下降还是模型退化。因此建议把评测集、prompt 版本、trace 三者打通，形成「改动 → 观测 → 回归/改善」的闭环，这正是评测驱动开发（EDD）的落地形态。

## 十、小结

可观测性把黑盒变成可调试系统：捕获完整 trace、监控 token 成本与时延分位数，并把质量信号回馈到迭代。它是 LLM 应用安全上线的必备前提，而非上线后的可选项。
