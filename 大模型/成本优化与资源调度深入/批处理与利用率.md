# 批处理与利用率

> 对应 GPU 利用率与批处理（连续批）；vLLM 实证。

## 一、背景与挑战

GPU 算力强但易空转；小批致利用率低，单位 token 成本高。

## 二、核心原理

连续批处理填满计算；调批大小/并发使 MFU（模型算力利用率）高；监控 sm 占用。

## 三、数学形式

$MFU = \frac{\text{achieved FLOPs}}{\text{peak FLOPs}}$；目标 >40%。

## 四、代码实现

```python
util = torch.cuda.utilization()
if util < 40: scale_concurrency(up)
```

## 五、与其他对比

- 与 连续批处理深入（机制）衔接（本节算账）。
- 与 模型服务负载均衡深入 共享。

## 六、常见误区

- 批过大超显存致 OOM。
- 只看 util 忽略 ITL 升。

## 七、与开源书对应

- rasbt/LLMs-from-scratch：https://github.com/rasbt/LLMs-from-scratch

## 八、面试题

- 为何利用率关键？答：GPU 按时间计费，空转也收费，利用率低单位成本高。

## 九、演进

无批 → 静态批 → 连续批提 MFU。

## 十、小结

利用率是成本核心，连续批把 MFU 做高。
