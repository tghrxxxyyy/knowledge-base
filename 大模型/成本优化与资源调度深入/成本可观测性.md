# 成本可观测性

> 对应 LLM 成本追踪（token 计价/FinOps）；成本面板。

## 一、背景与挑战

成本分散在算力/缓存/模型调用，需按租户/场景归因才能优化。

## 二、核心原理

埋点记录每请求 token（in/out）、模型、命中（缓存省）、时长；聚合成单位成本与趋势；归因到租户/功能。

## 三、数学形式

单位成本 $u = \frac{C_{period}}{N_{req}}$；归因 $c_{tenant}=\sum req_i$。

## 四、代码实现

```python
log_cost(tenant, model, in_tok, out_tok, cached=hit)
dashboard.group_by("tenant").sum("cost")
```

## 五、与其他对比

- 与 大模型监控与告警深入（质量/延迟）互补（本节成本）。
- 与 推理缓存与命中优化深入（省多少）衔接。

## 六、常见误区

- 不归因致不知哪贵。
- 只看总量忽略单请求分布。

## 八、面试题

- 为何要成本归因？答：定位高成本租户/场景，定向优化（缓存/小模型）。

## 九、演进

总账单 → 按模型 → 按租户/场景归因。

## 十、小结

成本可观测性靠 token 埋点与归因，驱动优化。
