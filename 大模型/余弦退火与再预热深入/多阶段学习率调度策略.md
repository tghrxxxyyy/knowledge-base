# 多阶段学习率调度策略

> 对应 microsoft/DeepSpeed 学习率调度配置；karpathy/nanoGPT 迭代式 LR 设计；大模型分阶段训练（预训练/继续预训练/指令微调）实践。

## 一、背景与挑战

现代大模型很少「一次训完」：它经历预训练、继续预训练、领域适配、指令微调等多个阶段，每阶段的数据分布、目标与规模都不同。若用单一全局 LR 轮廓，要么早期数据学习不足，要么后期阶段因 LR 过低而学得极慢。需要对各阶段独立塑形，否则会出现「新阶段几乎不学」或「旧能力被冲掉」的尴尬。

## 二、核心原理

多阶段调度为每一阶段单独设定 warmup、峰值 LR、衰减形状与步数；阶段切换时可重置优化器动量或继承状态。常见做法：继续预训练时重新 warmup 到一个比原始峰值更低的 LR（因数据分布变化、且已具备基础表征）；指令微调阶段用更小峰值与更短周期。阶段间 LR 可「断崖式」重设，也可「继承式」平滑过渡。核心思想是「不同阶段用不同学习节奏」。

## 三、形式化与数学基础

第 $k$ 阶段的 LR 由该阶段专属函数给出：

$$\eta^{(k)}_t = f_k\!\big(t;\, \eta^{(k)}_{\max},\, \eta^{(k)}_{\min},\, T_k\big)$$

其中 $f_k$ 可为余弦或线性，$T_k$ 为该阶段步数。跨阶段不连续切换：在阶段边界 $t=t_k$，

$$\eta^{(k)}_{T_k} \neq \eta^{(k+1)}_{0}$$

若采用「再预热」，则 $\eta^{(k+1)}_{0}$ 先升后降；若继承优化器状态，动量 $m$、二阶矩 $v$ 跨阶段保留以延续收敛轨迹。这种分段函数使整体 LR 成为阶段相关的分段曲线。

## 四、代码实现

```python
# DeepSpeed 风格多阶段配置（示意，来自官方 scheduler 参数）
sched_config = {
    "scheduler": {
        "type": "WarmupCosineDecay",
        "params": {
            "warmup_min_lr": 0,
            "warmup_max_lr": 3e-4,
            "warmup_num_steps": 2000,
            "total_num_steps": 100000,
        }
    }
}

# 多阶段手工拼接（示意）
def multi_stage_lr(step, stages):
    # stages: [(warmup, total, lr_max, lr_min), ...] 顺序拼接
    for (wu, tot, mx, mn) in stages:
        if step < tot:
            return get_lr(step, wu, tot, mx, mn)
        step -= tot
    return stages[-1][-1]   # 末段最低 LR
```

## 六、常见误区

误区一：阶段切换时未重置 warmup——新数据上 LR 过低、学习缓慢。误区二：所有阶段用同峰值——继续预训练用原峰值易破坏已有表征。误区三：忽略优化器状态继承/重置——不当继承会导致动量错位。误区四：阶段数过多导致工程复杂、难以调试。

## 九、演进与趋势

根据验证指标动态切换阶段的自适应调度正在探索；与数据课程、课程式难度联动，使 LR 轮廓与数据调度 jointly 优化；「阶段感知」的优化器（如分阶段调整 β、权重衰减）也在研究中。

### 实践速查

- 分段：每阶段独立设 warmup/峰值/衰减，阶段间可重设或继承状态。
- 再预热：继续预训练用更低峰值重新 warmup，保护已有表征。
- 状态：阶段切换可重置优化器动量，或继承以延续收敛轨迹。
- 配置：DeepSpeed 等支持 WarmupCosineDecay，按阶段填参即可。
- 监控：切换阶段后观察 loss 是否陡降（学习不足）或崩坏（峰值过高）。
- 简化：阶段过多增加工程复杂度，按需合并相邻同质阶段。

### 常见问题

- 问：继续预训练为何重预热且低峰值？答：数据分布变，需重新稳定轨迹。
- 问：优化器状态继承还是重置？答：看是否同分布延续，异构常重置。
- 问：阶段数过多有何问题？答：调度碎片化，调试与复现都更困难。

## 十、小结

多阶段调度让大模型在不同训练目标间平滑过渡，是连接预训练、继续预训练与微调的关键工程手段，核心是「每阶段独立塑形、切换审慎」。
