# 线性衰减与余弦衰减对比

> 对应 Loshchilov & Hutter, *SGDR* (2017) 中余弦调度设计；d2l-ai/d2l-zh 学习率调度对比；huggingface/transformers 调度器实现。

## 一、背景与挑战

选择 LR 衰减形状，会在「实现复杂度」「收敛速度」「最终精度」之间权衡。不同曲线在训练前期与末期的下降速度差异，会直接影响参数落入的盆地特性，进而左右泛化表现。实践中常见争论是「是否值得为了一点精度而换用更复杂的余弦」——答案取决于训练长度与目标精度。

## 二、核心原理

线性衰减（Linear Decay）以恒定速率把 LR 从峰值降到最低，全程斜率一致。余弦衰减（Cosine Decay）形如半周期余弦：两端变化慢、中间变化快，末期最平滑地趋近 $\eta_{\min}$。实践中余弦因「末期足够低且平滑」常略优于线性，尤其利于大模型长周期训练的精细收敛。其核心优势在于「不浪费前期学习容量、不粗暴砍断末期更新」。

## 三、形式化与数学基础

线性衰减：

$$\eta_t = \eta_{\max} - (\eta_{\max}-\eta_{\min})\cdot \frac{t}{T}$$

余弦衰减：

$$\eta_t = \eta_{\min} + \tfrac{1}{2}(\eta_{\max}-\eta_{\min})\Big(1+\cos\big(\pi\cdot\tfrac{t}{T}\big)\Big)$$

二者导数对比：线性斜率恒定；余弦在 $t=0$ 与 $t=T$ 处导数为 0，故起步温和、收尾平缓。末段余弦的瞬时变化率更小，参数更新更精细，更易停在平坦盆地而非越过最优解。

## 四、代码实现

```python
import math

def linear_lr(t, T, lr_max, lr_min=0.0):
    return lr_max - (lr_max - lr_min) * t / T

def cosine_lr(t, T, lr_max, lr_min=0.0):
    return lr_min + 0.5 * (lr_max - lr_min) * (1 + math.cos(math.pi * t / T))

# 对比同峰值、同总步数下的曲线形态
T = 1000
for t in [0, T // 4, T // 2, 3 * T // 4, T]:
    print(t, round(linear_lr(t, T, 3e-4), 6), round(cosine_lr(t, T, 3e-4), 6))
```

## 六、常见误区

误区一：认为形状差异无足轻重——在长周期大模型训练中，末期曲线形状对最终 loss 有可测影响。误区二：盲目选线性图省事——短训练影响小，长训练余弦更稳。误区三：把周期 $T$ 当成 epoch 数而非优化步数，导致曲线节奏错位。误区四：把余弦衰减等同于带重启的 SGDR——前者无重启。

## 九、演进与趋势

衰减形状正与数据课程、阶段权重联合设计；出现余弦+线性尾（cosine with linear tail）等混合形态以兼顾平滑与最低 LR；也出现根据验证曲线自适应切换衰减形状的策略。

### 实践速查

- 默认：长周期大模型训练用余弦，短训练线性也可接受。
- 末值：无论哪种，务必给非零 $\eta_{\min}$ 让末期仍有微调。
- 周期：把 $T$ 设为优化步数而非 epoch 数，避免与 batch 错位。
- 对照：同配置下同时跑线性/余弦做消融，确认收益真实。
- 混合： cosine-with-linear-tail 兼顾平滑与极低末 LR。
- 监控：对比末期 val_loss 曲线，余弦通常更平滑收敛。

### 常见问题

- 问：余弦一定优于线性吗？答：长训练通常略优，短训练差异小。
- 问：阶梯衰减还用吗？答：仍用于需手动里程碑的场景，但偏粗糙。
- 问：T 用 epoch 有何坑？答：batch 不同则实际步数不同，曲线节奏错。

### 关键记忆点

- 余弦末期最平滑，利于精细收敛；线性匀速，适合短训练。
- 周期 $T$ 用优化步数而非 epoch，避免与 batch 错位。
- 非零 $\eta_{\min}$ 是两条曲线的共同底线，不能降到绝对零。

## 十、小结

余弦衰减因平滑特性成为大模型主流，线性适合轻量/短训练；选型应结合训练长度与目标精度，而非盲目追新。
