# 统一基础模型多适配器

> 对应 Hu 2021 LoRA; huggingface/peft; Ouyang 2022 InstructGPT。

## 一、背景与挑战
多租户各需不同风格/领域模型，硬隔离部署浪费。统一基座 + 多适配器实现逻辑隔离。

## 二、核心原理
同一份 W 服务所有请求，仅增量随 adapter_id 变化。路由器（按请求元数据或分类器）选择适配器，保证租户间互不串扰。

## 三、形式化与数学基础
输出为适配器条件函数：
$ f(x; a) = W x + s_a B_a A_a x $
不同 a 给出不同行为，基座共享。

## 四、代码实现
```python
class MultiLoRARouter:
    def __call__(self, x, aid):
        return lora_forward(x, self.W, self.adapters[aid])
```

## 五、与其他技术对比
相比多模型微服务，统一基座运维简单、资源省，但需防适配器间干扰与越权。

## 六、常见误区
误区：共享基座会泄露数据。仅增量不同，前向隔离，但需鉴权防误用他者适配器。

## 七、与开源书/权威来源对应
Hu et al. 2021; PEFT LoRA 多适配器。见 huggingface/peft。

## 八、面试题
问：多适配器如何保证租户隔离？
答：请求绑定 adapter_id，路由仅加载对应增量，逻辑隔离。

## 九、演进与趋势
基座 + 路由即“模型即服务”多租户标准形态。

## 十、小结
统一基座多适配器以最低成本实现多任务/多租户逻辑隔离。
