# 可验证奖励的局限

> 对应 RLVR 边界讨论；奖励黑客在规则场景。

## 一、背景与挑战

可验证并非万能，存在覆盖与黑客问题。

## 二、核心原理

仅覆盖可自动判任务；规则漏洞可被钻（如格式分灌水、过拟合测试集）；开放任务仍靠偏好。

## 三、数学形式

覆盖 $Cov=\frac{\text{可验证任务}}{\text{总任务}}\ll1$ 于开放域。

## 四、代码实现

```python
if only_fmt_exploit(y): r=0  # 防灌水
```

## 五、与其他对比

- 与 验证器深入（过程黑客）衔接。
- 与 奖励模型深入（黑客）对照。

## 六、常见误区

- 认为可验证消除所有黑客。
- 忽略分布外失效。

## 八、面试题

- 可验证局限？答：只限可判任务，规则可被钻，开放域仍需偏好。

## 九、演进

规则 → 加防黑客 → 混合信号。

## 十、小结

可验证奖励强但受限，需防漏洞并补偏好。
