# 查询改写与查询扩展

> 对应 Lewis et al. 2020《RAG》与 dair-ai/Prompt-Engineering-Guide 及 run-llama/llama_index。

## 一、背景与挑战
用户查询常简短、口语化、缺上下文，直接检索召回差。查询改写用 LLM 把原查询重写为更利于检索的形式。

## 二、核心原理
常见策略：查询扩展（加同义/相关词）、查询分解（拆子问题）、假设性改写（生成理想问法）。改写可一次性或生成多份变体再融合（见多查询章）。

## 三、形式化与数学基础
设原查询 $q$，改写模型产生 $q' = \text{Rewrite}(q, c)$，其中 c 为对话/上下文。目标是使检索相关性提升：
$\max_{q'} \text{Rel}(q', D) \quad \text{s.t.} \quad q' \approx \text{意图}(q)$
可用强化学习以最终答案质量为奖励来优化重写器。

## 四、代码实现
```python
def rewrite_query(llm, q, history=""):
    prompt = f"把用户问题改写为适合向量检索的规范问法，只输出改写：\n{history}\n原问题：{q}"
    return llm.complete(prompt).strip()
```

## 五、与其他技术对比
相比直接检索，改写显著提升难查询召回；相比重排，它作用于召回侧、从源头改善。代价是增加一次 LLM 调用延迟。

## 六、常见误区
误区一：改写越复杂越好，过度改写会偏离原意。误区二：忽略上下文，多轮对话中不改写会导致指代歧义。

## 九、演进与趋势
用小模型专门微调重写器以降本；并结合检索反馈做迭代改写（改写-检索-再改写）。

## 十、小结
查询改写是低成本的召回增强手段，把「问得好」变成「检得准」。
