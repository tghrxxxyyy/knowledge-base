# 稀疏检索 BM25 原理

> 对应 Lewis et al. 2020《RAG》检索组件思路与 facebookresearch/faiss 稀疏索引及 run-llama/llama_index。

## 一、背景与挑战
稠密向量检索擅长语义，但对精确关键词、专有名词、ID 类查询往往不及词面匹配。稀疏检索以词频统计为基础，零训练、可解释。

## 二、核心原理
BM25 是词面相似度排序函数，基于查询词在文档中的词频（TF）、逆文档频率（IDF）与文档长度归一化。它不对语义建模，但对关键词召回稳健。

## 三、形式化与数学基础
对查询词项集合 Q，文档 d 得分：
$\text{BM25}(d,Q) = \sum_{t \in Q} \text{IDF}(t)\, \frac{f(t,d)(k_1+1)}{f(t,d)+k_1(1-b+b\,|d|/avgdl)}$
其中 $f(t,d)$ 为词频，$k_1,b$ 为超参，$\text{IDF}(t)=\ln\frac{N-n_t+0.5}{n_t+0.5}$。

## 四、代码实现
```python
import math
def bm25_score(q_terms, tf, idf, dl, avgdl, k1=1.5, b=0.75):
    s = 0.0
    for t in q_terms:
        ft = tf.get(t, 0)
        s += idf[t] * (ft*(k1+1)) / (ft + k1*(1-b+b*dl/avgdl))
    return s
```

## 五、与其他技术对比
相比向量检索，BM25 不依赖embedding、可冷启动、对关键词精确；缺点是缺乏语义泛化。因此常与稠密检索混合。

## 六、常见误区
误区一：BM25 已过时，实际上它仍是强基准且低成本。误区二：k1/b 随意设，实际需按语料微调。

## 七、与开源书/权威来源对应
- Lewis et al. 2020 将检索作为 RAG 基础模块。
- facebookresearch/faiss 提供稀疏表示支持。
- run-llama/llama_index 内置 BM25 检索器。

## 九、演进与趋势
BM25 与神经稀疏（如 SPLADE）结合，使词面匹配获得语义扩展，形成可学习的稀疏向量。

## 十、小结
BM25 是检索系统的稳定基石，理解它才能设计合理的混合检索。
