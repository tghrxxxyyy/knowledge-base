# 稠密检索与双塔模型

> 对应 Lewis et al. 2020《RAG》(DPR) 与 huggingface/transformers 及 stanford-futuredata/ColBERT。

## 一、背景与挑战
词面检索无法捕捉同义改写。稠密检索用神经网络把查询与文档映射到同一向量空间，按近邻召回语义相关文档。

## 二、核心原理
双塔编码器分别产出查询/文档向量，用对比学习对齐。训练用（查询，正文档，负文档）三元组，难负例（同批次或硬负）提升判别力。

## 三、形式化与数学基础
对比损失（InfoNCE）：
$\mathcal{L} = -\log \frac{\exp(E_q(q)^\top E_d(d^+))}{\sum_{d'\in\{d^+\}\cup N} \exp(E_q(q)^\top E_d(d'))}$
其中 N 为负样本集合，温度 $\tau$ 常隐含于缩放中。

## 四、代码实现
```python
import torch.nn as nn
def contrastive_loss(q, pos, negs, enc):
    eq, ep = enc(q), enc(pos)
    en = torch.stack([enc(n) for n in negs])
    scores = torch.cat([eq@ep, eq@en.T], 0)
    return nn.CrossEntropyLoss()(scores.view(1,-1), torch.zeros(1, dtype=torch.long))
```

## 五、与其他技术对比
相比 BM25，稠密检索语义强但需训练与索引，且对关键词可能漏召；因此常与稀疏混合。相比交叉编码器，可离线索引、适合召回。

## 六、常见误区
误区一：负样本随便取，其实难负例对质量至关重要。误区二：认为向量维度越大越好，过大会过拟合且占存储。

## 七、与开源书/权威来源对应
- Lewis et al. 2020 的 DPR 是稠密检索代表。
- huggingface/transformers 提供编码器实现。
- stanford-futuredata/ColBERT 为延迟交互变体。
