# 全栈微调实战（SFT / LoRA / 对齐）

> 板块：大模型 / 训练与部署 　|　 返回：[README](README.md)

## 一、什么时候需要微调

预训练模型（base）是「通才」，指令模型（chat/instruct）已做过 SFT + RLHF。你的业务要不要微调，看这几点：

- 领域术语多（医疗/法律/金融），通用模型总说外行话。
- 有固定输出格式（JSON Schema、工单模板），prompt 约束不稳。
- 私有知识频繁更新，RAG 检索成本高于直接内化。
- 风格/人设强约束（客服口吻、品牌语气）。

> 经验法则：先用 prompt + RAG 解决 80%，剩下 20% 成本高或格式不稳的再微调。微调不是银弹，是最后 20% 的优化。

## 二、微调方法谱系

| 方法 | 改动范围 | 显存 | 数据量 | 适用 |
|------|----------|------|--------|------|
| 全参微调 FFT | 全部权重 | 极高 | 大 | 领域大改 |
| LoRA | 低秩适配矩阵 | 低 | 中 | 最常见 |
| QLoRA | LoRA + 4bit 量化基模 | 极低 | 中 | 单卡可行 |
| Prefix/Tuning | 软提示前缀 | 低 | 小 | 轻量适配 |
| Adapter | 插入小网络 | 低 | 中 | 多任务 |

- **LoRA**：冻结原权重，训练低秩矩阵 A×B 近似增量 ΔW，推理时合并或旁路。参数量可降至 0.1%~1%。
- **QLoRA**：把基模量化到 NF4，配合 LoRA，单张 24G 卡可微调 7B~13B。

## 三、SFT 数据构造

SFT（监督微调）数据 = (instruction, input, output) 三元组，质量 >> 数量。

```json
{
  "instruction": "把用户问题分类到意图",
  "input": "帮我查一下昨天的订单",
  "output": "{"intent": "order_query", "time": "yesterday"}"
}
```

- **来源**：人工标注、强模型蒸馏（用 GPT-4 造）、已有业务日志清洗。
- **去重**：相似样本过多会过拟合风格。
- **难度分层**：简单/中等/困难混合，避免只学简单模式。
- **格式统一**：所有样本遵循同一 schema，便于损失稳定。

## 四、QLoRA 实战（伪代码）

```python
from peft import LoraConfig, get_peft_model
from transformers import AutoModelForCausalLM, BitsAndBytesConfig

bnb = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4")
model = AutoModelForCausalLM.from_pretrained("base-7b", quantization_config=bnb)
lora = LoraConfig(r=16, lora_alpha=32, target_modules=["q_proj","v_proj"], lora_dropout=0.05)
model = get_peft_model(model, lora)   # 只训练 LoRA 参数

# 训练：用 Trainer / accelerate，学习率 1e-4~2e-4，epoch 2~3
trainer.train()
model.save_pretrained("./lora-adapter")   # 仅存 adapter，几百 MB
```

## 五、训练超参要点

- **学习率**：LoRA 用 1e-4 ~ 3e-4；FFT 用 1e-5 ~ 5e-5。
- **epoch**：2~4，过犹不及（风格漂移、遗忘通用能力）。
- **batch / grad accum**：小卡用梯度累积模拟大 batch。
- **warmup**：前 3%~10% step 线性升温。
- **loss**：因果语言模型（next-token），只对 answer 部分算 loss（mask 掉 prompt）。

## 六、灾难性遗忘与缓解

- **现象**：微调后领域变强，但通用对话/代码崩了。
- **缓解**：
  - 用 LoRA（原权重冻结，遗忘少）。
  - 混合通用数据（10%~20%）一起训。
  - 控制 epoch 与学习率。
  - 用 ORPO/DPO 等偏好方法替代重 RLHF。

## 七、偏好对齐（DPO / RLHF）

- **RLHF**：奖励模型（RM）打分 → PPO 强化学习，流程复杂、易不稳定。
- **DPO（直接偏好优化）**：不需要显式 RM，直接用偏好对 (chosen, rejected) 优化，简单稳定，已成主流。

```python
# DPO 数据示例
{"prompt": "写一句标语", "chosen": "简洁有力的一句", "rejected": "啰嗦的十句"}
# 训练：DPOTrainer，beta 控制偏离基模程度
```

## 八、评测微调效果

- 在业务评测集上对比 base / chat / 微调后。
- 指标：格式准确率、任务通过率、人工满意度。
- 警惕「训练集高分、线上低分」→ 过拟合或分布偏移。

## 九、部署与合并

- **旁路加载**：基模 + LoRA adapter，推理时动态加载（多 adapter 切换）。
- **权重合并**：把 LoRA 合并进原权重，得到独立模型，部署简单但失去灵活性。
- 量化部署见 [推理优化](../推理与思考模型/03-推理优化与量化部署.md)。

## 十、数据合规与隐私

- 训练数据脱敏：PII（姓名/电话/身份证）必须清洗。
- 版权：商用模型权重许可（如 Llama 社区许可、Qwen 许可）。
- 审计：保留训练数据快照与版本，便于回溯。

## 十一、常见坑

1. 数据量少却全参微调 → 严重过拟合。
2. 只学业务样本忘混通用 → 通用能力崩。
3. LoRA rank 设太大（64+）→ 接近全参、显存涨、收益有限。
4. 不 mask prompt loss → 模型学会「复述问题」而非「回答」。
5. 训练集与线上分布不一致 → 离线好线上差。
6. 忽略数据去重 → 风格被少数模板绑架。

## 十二、落地清单

1. 确认微调必要性（先试 prompt+RAG）。
2. 造高质量 SFT 数据（≥1000 条起步，难例分层）。
3. QLoRA + LoRA 起步，单卡可跑。
4. 混通用数据防遗忘，控 epoch。
5. 业务评测集回归。
6. adapter 旁路部署 + 量化。
