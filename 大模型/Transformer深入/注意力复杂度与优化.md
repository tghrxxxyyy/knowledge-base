# 注意力复杂度与优化

> 对应 Dao et al. 2022 FlashAttention 与 Tay et al. 2022 Efficient Transformers 综述。

## 一、背景与挑战

标准自注意力需要计算所有位置对之间的相似度。
时间与显存复杂度均为 $O(n^2 d)$，其中 $n$ 为序列长度，$d$ 为隐维。
当 $n$ 从千级迈向百万级——长文档、高分辨率图像、基因组——计算与显存同时爆炸。
这成为 Transformer 扩展的最大瓶颈。
数十年来大量研究围绕「降低注意力的平方复杂度」展开，可归为三条路线：稀疏化、低秩/核近似、以及不改变数学结果的 IO 感知优化。

## 二、核心原理

按思路分类，主要变体如下。

- **稀疏注意力**（Longformer、BigBird）：每个 token 只关注局部窗口加少量全局 token，复杂度降为 $O(n\cdot w)$，但会损失部分长程依赖。
- **低秩/投影**（Linformer）：把键/值沿序列维投影到 $k$ 列，复杂度 $O(n\cdot k)$，以压缩换速度。
- **核近似线性注意力**（Performer）：用随机特征近似 softmax 核，实现 $O(n d^2)$ 的线性扩展，本质是用近似换复杂度。
- **IO 感知优化**（FlashAttention）：不改变数学结果，仅用分块（tiling）与重计算减少 HBM 读写，显著提速并降显存，是当前训练/推理的事实标准。

以显存与适用场景为例：全注意力需存储 $n\times n$ 分数矩阵，显存 $O(n^2)$。
稀疏注意力把每个 token 的可见范围限制为窗口 $w$ 加少量全局 token，显存降为 $O(n w)$，适合长文档但牺牲全局依赖。
线性注意力通过核技巧把 $\text{softmax}(QK^\top)V$ 改写为 $\phi(Q)(\phi(K)^\top V)$，先聚合出 $d\times d$ 的紧凑统计量，复杂度 $O(n d^2)$，代价是特征映射带来的近似误差。
实际选型应先看序列长度与精度要求，而非盲目追「线性」。

近似方法并非免费午餐：稀疏会丢长程信息，线性/低秩会引入近似误差。
在精度敏感任务（如检索、推理）上可能掉点，因此需配合评测决定是否采用。

## 三、形式化与数学基础

标准注意力定义为：

$$
\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right)V
$$

softmax 分母需先算全 $n\times n$ 分数矩阵 $S=QK^\top/\sqrt d$，再归一化。
传统实现把 $S$ 与 $P=\text{softmax}(S)$ 都写回显存，IO 成为瓶颈。
FlashAttention 把 $Q,K,V$ 分块装入 SRAM，在片上完成「分数→softmax→乘 V」的融合计算，仅输出最终 $O(n d)$ 结果。
它避免 $O(n^2)$ 中间矩阵的显存往返，把显存占用从 $O(n^2)$ 降回 $O(n)$。

## 四、代码实现

FlashAttention 已由框架内置，通常仅需开启标志（参数名以官方最新文档为准）：

```python
import torch.nn as nn

# PyTorch 2.x 的 scaled_dot_product_attention 即融合实现
from torch.nn.functional import scaled_dot_product_attention

def flash_attn(q, k, v, mask=None):
    # 内部自动选择内存高效内核（类似 FlashAttention）
    return scaled_dot_product_attention(q, k, v, attn_mask=mask)
```

## 五、与其他技术对比

| 方法 | 复杂度 | 是否精确 | 思路 |
|------|--------|----------|------|
| 全注意力 | $O(n^2 d)$ | 是 | 精确 |
| 稀疏(Longformer) | $O(n w)$ | 近似 | 局部窗口+全局 |
| 线性(Performer) | $O(n d^2)$ | 近似 | 核近似 |
| 低秩(Linformer) | $O(n k)$ | 近似 | 投影降列数 |
| FlashAttention | $O(n^2 d)$ IO 优化 | 是 | 减少 HBM 读写 |

## 六、常见误区

- 以为 FlashAttention「近似」了注意力；它结果与标准实现逐位一致，只是 IO 更优。
- 盲目追求「线性注意力」却在精度敏感任务上掉点；近似方法并非总是免费午餐。
- 只盯着计算 FLOPs，忽视显存带宽——长序列下 IO 常是真正瓶颈。

## 九、演进与趋势

FlashAttention 演进到 v2/v3，更好利用 GPU 特性与异步流水；并与分页 KV Cache（PagedAttention）结合服务长上下文。
同时稀疏与线性注意力在特定超长序列场景仍有价值。
在真实 GPU 上，attention 的瓶颈常是 HBM 带宽而非浮点算力：v2 重排循环、减少线程同步进一步提速，v3 利用 Hopper 的异步 warp 专用化与 TMA 把生产者/消费者重叠。

## 十、显存视角与小结

在工程落地时，通常无需手写内核——PyTorch 的 `scaled_dot_product_attention`、xFormers、以及 vLLM/TGI 等推理引擎均已内置融合实现，开启 `flash_attention_2` 标志即可生效。
验证收益的标准做法是固定序列长度对比吞吐与峰值显存：在 FP16、8k 以上长序列下，常见可观察到数倍加速与显存大幅下降。

回到变体选型：稀疏/线性/低秩适合「长度极大但精度容忍」的场景（如超长文档粗筛、近似检索），而对话、推理、代码等精度敏感任务应优先精确注意力。
实用经验是「先以 FlashAttention 跑通并测出真实瓶颈，再决定是否引入近似」，避免过早优化带来质量损失。

需要注意，注意力优化与 KV Cache 管理（如 PagedAttention）是互补的两层：前者压低单层计算与 IO，后者压低跨请求显存，二者共同决定长上下文服务的上限。
在 MoE 等稀疏模型中，注意力往往成为显存与延迟的主要来源，优化收益更显著。

注意力优化的两条主轴：一是近似（稀疏/线性/低秩）以换复杂度，二是精确但 IO 感知（FlashAttention）以换效率。
现代训练与推理的事实标准是 FlashAttention——它提醒我们：瓶颈常在显存带宽，而非算力本身。
