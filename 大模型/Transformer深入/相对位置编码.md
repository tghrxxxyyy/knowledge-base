# 相对位置编码 Relative Position

> 对应 Shaw et al. 2018 与 Dai et al. 2019 Transformer-XL / Raffel et al. 2020 T5。

## 一、背景与挑战

绝对位置编码把位置当作「位置 id」（第 1、第 2……），但语言理解往往更依赖相对距离——「A 前面隔两个词是 B」这类关系。
绝对编码在长度外推、句法泛化上有限；相对位置编码则把偏移 $i-j$ 直接注入注意力分数，让模型对「相距多远」更敏感。
并能更好泛化到训练时未见过的序列长度。
直觉上，语言中的句法关系（主谓、动宾）多由相对距离刻画，而非绝对位置；例如「吃」与其宾语的相对间距往往比「第几个词」更关键，这正是相对编码更符合语言先验的原因。

## 二、核心原理

代表性方案如下。

- **Shaw et al. (2018)**：在 $\text{score}(q_i,k_j)$ 中加入可学习相对位置表示 $a_{i-j}$，按偏移查表。
- **Transformer-XL / XLNet**：用正弦相对编码 $R_{i-j}$，并引入内容偏置 $u$ 与位置偏置 $v$，把「内容贡献」与「位置贡献」显式拆开，支持段循环（segment recurrence）。
- **T5 Bias**：把相对距离分桶（bucket），远距离压缩到同一桶，以有限参数覆盖任意长度。
- **RoPE**（现代主流）：把位置编码化为旋转操作，使内积仅依赖相对位置（详见位置编码章节），因实现简洁且与因果注意力天然契合，已成为 LLaMA/Qwen 等默认选择。

## 三、形式化与数学基础

Transformer-XL 风格下，注意力分数拆分为内容与位置两部分：

$$
\text{score}(i,j) = (q_i + u)^\top k_j + (q_i + v)^\top R_{i-j}
$$

其中 $u,v$ 分别为内容/位置偏置（可学习），$R_{i-j}$ 为依赖偏移 $i-j$ 的相对位置正弦向量。
第一项是纯内容匹配，第二项刻画「相距 $i-j$ 的位置关系」，使模型学到「相隔固定距离」的语义模式。
RoPE 则进一步把该思想解析化：对 $q_i,k_j$ 做依赖位置的旋转，使内积 $\langle q'_i,k'_j\rangle$ 只含相对项 $i-j$。

## 四、代码实现

以 Shaw 式可学习相对偏置的简化示意：

```python
import torch
import torch.nn as nn

class RelativePositionBias(nn.Module):
    def __init__(self, max_rel, d_head):
        super().__init__()
        self.rel_emb = nn.Embedding(2 * max_rel + 1, d_head)
    def forward(self, i, j):
        # 偏移 -> 查表索引
        rel = (i - j) + self.rel_emb.num_embeddings // 2
        return self.rel_emb(rel)  # 用于加到 score 上
```

## 五、与其他技术对比

| 方法 | 注入点 | 特点 |
|------|--------|------|
| Shaw | 加性偏置 | 简单、可学习 |
| Transformer-XL | 拆分内容/位置 | 支持段循环、长程 |
| T5 | 相对桶 | 长程压缩、参数省 |
| RoPE | 旋转 Q/K | 内积即相对、主流 |

## 六、常见误区

- 以为相对编码只是「绝对编码的另一种写法」；其关键价值在于让分数显式依赖 $i-j$，提升长度泛化。
- 忽视 T5 的桶机制：超长距离被压缩到同一桶，牺牲部分精度换参数与长度覆盖。
- 把 RoPE 与 Shaw 式偏置混为一谈；RoPE 通过旋转使内积天然只含相对项，实现更优雅。

## 九、演进与趋势

从可学习偏置（Shaw）到段循环（XL）到分桶（T5），再到旋转式 RoPE 成为 decoder-only 主流。
后续围绕「长上下文外推」发展 NTK-aware scaling、位置插值（PI）、YaRN 等方法：其核心是在推理时「压缩」位置索引，使训练长度之外的相对距离仍落在模型已见过的范围内。
相对编码因此从「训练技巧」演变为「长上下文能力的支柱」。

关于 RoPE 的外推机制，一个关键直觉是：NTK-aware scaling 通过按维度抬高旋转基频 $\theta_i$，使高频维度（对应小周期）在扩展后仍能保持原分布，仅让低频维度承担「压缩」，从而对短上下文几乎无损。
这也是为何同一份 4k 训练权重经适当 rope_scaling 后能稳定服务 32k 乃至 128k 上下文，而纯位置插值（直接缩小位置索引）往往伴随更明显的短上下文退化。

## 十、小结

在工程实践中，相对/旋转位置编码几乎已成默认：HuggingFace 主流模型（LLaMA、Qwen、GLM）均使用 RoPE，并通过 `rope_theta` 与 `rope_scaling` 暴露外推配置。
当需把训练长度从 4k 扩展到 32k/128k 时，常用 NTK-aware scaling（按频率维调整基频）或位置插值 PI/YaRN（压缩位置索引）来保持相对距离分布稳定。
从实现角度，RoPE 把旋转矩阵写为对角块形式，对 query/key 的奇偶维配对做二维旋转；由于旋转保内积，任意两位置的注意力只与其相对旋转差有关，从而天然编码相对位置。

需要警惕的是：外推会改变训练时学到的位置分布，扩展后务必在长上下文评测集（如长文档抽取、大海捞针 needle-in-haystack）上验证，而非只看困惑度。
若扩展过度（远超训练长度数倍），即使 RoPE 也会退化，此时更稳妥的做法是继续微调而非纯推理期外推。
相对编码与因果掩码需协同：前者叠加位置几何，后者保证只看左侧，二者缺一不可。
