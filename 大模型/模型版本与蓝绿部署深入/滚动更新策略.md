# 滚动更新策略（Rolling Update）

> 对应 K8s RollingUpdate maxSurge/maxUnavailable。K8s 文档定义滚动更新参数。

## 一、背景与挑战

无双份预算时，需逐实例替换版本，兼顾可用与资源。

## 二、核心原理

按批次下线旧实例、起新实例，期间新旧共存；控制最大不可用与最大 surge 保容量。

## 三、数学形式

并发度：$unavailable \le U$，$surge \le S$；$n$ 实例分 $\lceil n/S\rceil$ 批。

## 四、代码实现

```python
deploy.strategy(rolling=True, max_unavailable=1, max_surge=1)
deploy.rollout("v2")
```

## 五、与其他对比

- 与 蓝绿部署实践（双环境）对照，滚动省资源。
- 与 模型版本与蓝绿部署深入 同主题。

## 六、常见误区

- surge 过大瞬时资源吃紧。
- 旧实例长连接被强断致请求失败。

## 七、与开源书对应

- mlabonne/llm-course：https://github.com/mlabonne/llm-course
- d2l-zh：https://github.com/d2l-ai/d2l-zh

## 八、面试题

- 滚动 vs 蓝绿？答：滚动逐批替换省资源但切换慢、回退慢；蓝绿瞬时但双份成本。

## 九、演进

全量 → 滚动 → 滚动加就绪探针。

## 十、小结

滚动更新在成本与可用间折中，是默认更新策略。
