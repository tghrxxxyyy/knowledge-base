# 模型注册表实践

> 对应 MLflow / Hugging Face Hub / Triton model repository。Triton 用模型仓库管理版本。

## 一、背景与挑战

权重散落难管理，需统一仓储与阶段（staging、production）流转。

## 二、核心原理

注册表存权重、配置、指标与 lineage；支持别名（@prod）与阶段流转，服务按别名拉取。

## 三、数学形式

别名解析：$W_{prod}=resolve("@production")$；切换 alias 即换版本，原子操作。

## 四、代码实现

```python
client.set_alias("llm", alias="@prod", version="v12")
```

## 五、与其他对比

- 与 版本管理总览（注册概念）衔接。
- 与 蓝绿部署实践（按别名路由）共享。

## 六、常见误区

- 直接删版本致引用断裂。
- 阶段流转无审批致误上线。

## 七、与开源书对应

- mlabonne/llm-course：https://github.com/mlabonne/llm-course
- rasbt/LLMs-from-scratch：https://github.com/rasbt/LLMs-from-scratch

## 八、面试题

- 别名 vs 版本号？答：别名（@prod）稳定引用，版本号具体；切 alias 实现原子切换。

## 九、演进

路径引用 → 版本号 → 别名与阶段。

## 十、小结

注册表以别名与阶段把版本流转标准化、可审计。
