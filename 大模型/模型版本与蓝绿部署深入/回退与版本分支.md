# 回退与版本分支

> 对应 git 式模型 lineage；回退到上一稳定版本。MLflow 记录模型 lineage。

## 一、背景与挑战

新版本出问题时需快速回到已知好版本，并保留分支实验能力。

## 二、核心原理

注册表保留历史版本与 lineage；回退即把 alias 指回旧版；实验分支并行不干扰 prod。

## 三、数学形式

回退：$v_{prod}^{t+1} = v_{prev\ stable}$；分支 $v_{exp}$ 独立 lineage 不进 prod。

## 四、代码实现

```python
client.set_alias("llm", "@prod", prev_stable)
client.set_alias("llm", "@exp-a", "v13-rc")   # 实验分支
```

## 五、与其他对比

- 与 自动回滚机制（执行）共享回退。
- 与 版本管理总览（lineage）衔接。

## 六、常见误区

- 回退后未保留现场诊断。
- 实验分支权重污染生产存储。

## 八、面试题

- 回退与分支关系？答：回退复用历史稳定版本，分支并行实验互不影响生产。

## 九、演进

手工备份 → 注册表回退 → 分支化实验。

## 十、小结

回退与分支让版本演进安全可逆、实验可并行。
