# 版本兼容性保障

> 对应模型、分词器、客户端兼容；推理 API schema 演进。语义化版本规范指导兼容。

## 一、背景与挑战

换版本可能改 tokenizer、输出 schema，致老客户端报错或语义漂移。

## 二、核心原理

用配套 config 锁定 tokenizer 与生成参数；API 向后兼容（加字段不减字段）；做影子比对。

## 三、数学形式

兼容度 $comp = \frac{1}{N}\sum \mathbb I(output_{v2} \approx output_{v1})$，阈值判定。

## 四、代码实现

```python
assert tok_v2.vocab == tok_v1.vocab   # 分词一致
compat = output_equal(v1, v2, sample)
```

## 五、与其他对比

- 与 影子流量验证（比对）衔接。
- 与 灰度评估指标（质量）共享。

## 六、常见误区

- 只换权重忽略配套 config。
- 破坏性 schema 变更未加版本号。

## 七、与开源书对应

- mlabonne/llm-course：https://github.com/mlabonne/llm-course
- datawhalechina/llm-universe：https://github.com/datawhalechina/llm-universe

## 八、面试题

- 版本兼容看什么？答：分词器、生成配置、输出 schema 一致，并做输出比对验证。

## 九、演进

无约束 → 配套 config → schema 版本化。

## 十、小结

版本兼容防止能加载但语义变的隐性故障。
