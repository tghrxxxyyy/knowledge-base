# 提示词工程体系与模板实战

> 提示词工程（Prompt Engineering）是与模型协作的基本功。从零样本到思维链、到结构化输出与 Few-shot，系统化的提示词体系能显著提升稳定性与可维护性。

## 1. 基础范式

| 范式 | 做法 | 适用 |
| --- | --- | --- |
| Zero-shot | 直接给指令 | 简单、通用任务 |
| Few-shot | 给 2~5 个示例 | 格式固定、需对齐风格 |
| Chain-of-Thought | "一步步思考" | 推理、数学、逻辑 |
| Self-Consistency | 多次采样取多数 | 高准确推理 |
| ReAct | 推理+行动交替 | Agent 工具调用 |

## 2. 结构化提示模板

用占位符 + 变量渲染，避免拼接字符串：

```python
from string import Template
TPL = Template("""你是$role。
任务：$task
约束：
$constraints
输出格式（严格 JSON）：
$schema
用户输入：$input""")

prompt = TPL.substitute(role="资深客服",
    task="判断用户意图并给出分类",
    constraints="- 只输出 JSON\n- 不确定标 unknown",
    schema='{"intent": "...", "confidence": 0.0}',
    input=user_text)
```

## 3. 思维链与推理

```text
问题：一个班有 30 人，男生是女生的 2 倍，男生几人？
请一步步思考：
设女生 x 人，则男生 2x 人。
x + 2x = 30 → 3x = 30 → x = 10。
男生 = 2x = 20 人。
答案：20
```

CoT 让模型显式展开中间步骤，显著降低复杂推理错误率。

## 4. 角色与上下文锚定

- **系统提示**：固定角色、规则、禁忌、输出格式，放在最前。
- **少样本示例**：选代表性强、覆盖边界的示例。
- **负面约束**：明确"不要做什么"比只说"要做什么"更有效。

## 5. 输出结构化

- 要求 JSON / XML / Markdown 表格，并给出 schema。
- 用「函数调用/JSON mode」强制结构化，比纯文本解析稳。
- 复杂输出先做 schema 校验，失败则重试或降级。

## 6. 提示词版本管理

- 提示词当作代码：纳入 Git、走评审。
- 每个版本对应评测集结果，变更可回归。
- A/B 对比不同提示词效果。

## 7. 常见坑

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 指令模糊 | 输出漂移 | 明确角色+格式+约束 |
| 示例偏置 | 只学示例风格 | 多样示例 |
| 过长无结构 | 关键点被忽略 | 分节+强调 |
| 无输出校验 | 解析失败 | schema 校验+重试 |
| 硬编码拼接 | 注入风险 | 模板+转义 |

## 8. 进阶技巧

- **提示链（Prompt Chaining）**：把复杂任务拆成多步，每步独立提示，前步输出喂后步。
- **元提示（Meta-prompt）**：用模型生成/优化提示词。
- **检索增强提示**：动态注入相关知识片段。
