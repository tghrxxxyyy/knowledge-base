# 灰度发布总览

> 对应渐进式交付（Argo Rollouts 文档，2021；Istio 流量治理）。KServe 与 Argo Rollouts 支持 canary 分析。

## 一、背景与挑战

大模型服务上线风险高：权重大、启动慢、质量波动明显。全量切换一旦异常即影响全部用户，因此需以小流量先行验证再逐步放量。

## 二、核心原理

灰度发布先把新版本（canary）接入一小部分流量，依据监控指标决定是否继续放量；若异常则自动回滚到稳定版本（stable）。

## 三、数学形式

放量比例 $w_t$ 随时间递增：$w_{t+1}=w_t+\Delta$，约束 $\sum_i w_i=1$；回滚触发条件为 $risk(w_t)>\tau$。

## 四、代码实现

```python
route = set_weight("v2", pct=5)      # 先放 5% 流量
if analyzer.ok("v2"):
    route.set_weight(50)
else:
    rollback("v1")
```

## 五、与其他对比

- 与 模型版本与蓝绿部署深入 互补：蓝绿瞬时切换，灰度渐进放量。
- 与 自动回滚机制 衔接，本篇偏总览。

## 六、常见误区

- 灰度比例过小难暴露长尾问题，过大则风险集中。
- 忽略新实例冷启动期指标失真（warmup 未完）。

## 八、面试题

- 灰度与蓝绿区别？答：灰度渐进放量并按指标调节，蓝绿两套环境瞬时切换、无中间态。

## 九、演进

全量切换 → 蓝绿 → 金丝雀 → 自动渐进式（Argo Rollouts）。

## 十、小结

灰度发布以可控小流量验证新模型，是上线质量与风险平衡的核心手段。
