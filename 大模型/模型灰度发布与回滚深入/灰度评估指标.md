# 灰度评估指标

> 对应 ML 上线评估（延迟、质量、成本）；Prometheus + 业务埋点。Google SRE 强调 SLI/SLO。

## 一、背景与挑战

灰度放量的决策依赖可量化指标，且须兼顾技术侧与业务侧，单一指标容易误判。

## 二、核心原理

技术侧看 p99 延迟、错误率、吞吐；业务侧看答案准确率与满意度；成本侧看单请求 GPU 秒。多维加权做综合分。

## 三、数学形式

综合分 $S = \alpha\cdot Q + \beta\cdot(1-E) + \gamma\cdot(1-\frac{L}{L_{max}})$，权重和 $\alpha+\beta+\gamma=1$。

## 四、代码实现

```python
score = 0.5 * quality + 0.3 * (1 - err) + 0.2 * (1 - lat / 2.0)
promote_if(score >= baseline_score)
```

## 五、与其他对比

- 与 推理可观测与追踪深入（指标来源）衔接。
- 与 金丝雀分析与自动判定（用指标判定）共享。

## 六、常见误区

- 只看技术指标忽略答案质量劣化。
- 权重拍脑袋未经校准。

## 八、面试题

- 灰度看哪些指标？答：技术（延迟、错误、吞吐）+ 业务（质量、满意度）+ 成本，多维加权决策。

## 九、演进

单指标 → 多维 → 自动加权与门槛。

## 十、小结

灰度评估须技术与业务指标并重，否则放量决策失真。
