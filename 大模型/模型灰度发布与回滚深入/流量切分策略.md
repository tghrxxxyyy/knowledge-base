# 流量切分策略

> 对应 Istio VirtualService 权重路由；KServe canary 入口。Istio 通过权重实现按比例路由。

## 一、背景与挑战

如何把流量按比例、按特征分给 canary，是灰度落地的关键环节，直接影响验证的代表性。

## 二、核心原理

基于权重的随机切分最常用；也可按主体（用户 ID 哈希、租户、地域）做粘性或定向灰度，便于问题定位。

## 三、数学形式

按权重采样：$P(\text{route}=c)=\frac{w_c}{\sum w}$；按哈希 $h(u)\bmod 100< w_c$ 做定向切分。

## 四、代码实现

```python
def route(uid, w_canary):
    return "v2" if (hash(uid) % 100) < w_canary else "v1"
```

## 五、与其他对比

- 与 多租户隔离与配额深入（按租户切分）可结合。
- 与 影子流量验证（复制而非切分）对照。

## 六、常见误区

- 随机切分导致同一用户命中不同版本、体验跳变。
- 权重配置与网关缓存不一致造成切分偏差。

## 八、面试题

- 定向灰度为何用哈希？答：同一主体稳定落入同版本，保证体验一致且便于归因。

## 九、演进

随机权重 → 主体哈希 → 特征与模型路由（litellm）。

## 十、小结

流量切分决定灰度的粒度与可控性，常按主体哈希做稳定定向。
