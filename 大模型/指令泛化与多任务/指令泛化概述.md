# 指令泛化概述

> 对应 FLAN（Wei et al., 2021）、InstructGPT（Ouyang et al., 2022）与 Self-Instruct（Wang et al., 2022）。指令微调让模型从「续写」变成「听懂并照做」。

## 一、背景与挑战

预训练语言模型的目标是续写文本，不等于「理解指令并执行」。给一个零样本问题，它可能续写成更多问题而非回答。指令微调（Instruction Tuning）通过在大量「指令-回答」对上微调，让模型学会遵循人类意图。核心挑战：如何低成本获得高质量、多样、覆盖广的指令数据；如何让模型泛化到**没见过**的任务（真正的泛化，而非记住训练任务）；以及如何避免微调后通用能力退化。

## 二、核心原理

基本流程：

1. **构造指令数据**：把已有 NLP 数据集用模板转成指令形式（FLAN），或用强模型自举生成（Self-Instruct）。
2. **监督微调（SFT）**：在「指令 + 输入 → 输出」上做标准语言建模损失，只算输出部分的 token。
3. **多样性优先**：研究表明任务数量与多样性比单任务样本量更关键。

FLAN 的关键发现：在多任务上做指令微调，能显著提升**未见任务**的零样本性能；且模型规模越大，泛化增益越明显。

## 三、形式化与数学基础

SFT 目标（只对齐输出 token）：

$$\mathcal{L}=-\sum_{t\in \text{output}}\log P_\theta(y_t\mid x, y_{<t})$$

多任务混合（$K$ 个任务、权重 $\alpha_k$）：

$$\mathcal{L}=\sum_{k=1}^{K}\alpha_k\,\mathcal{L}_k$$

泛化差距（衡量未见过任务的表现）：

$$\Delta = \text{score}_{\text{unseen}} - \text{score}_{\text{base}}$$

## 五、与其他技术对比

| 手段 | 数据需求 | 泛化 | 成本 |
|------|---------|------|------|
| 预训练续写 | 海量文本 | 弱（不问自答） | 极高 |
| 指令微调 SFT | 万级指令对 | 强 | 低 |
| RLHF/DPO | 偏好对 | 强（对齐偏好） | 中 |
| 提示工程 | 无 | 中 | 极低 |

## 六、常见误区

- 认为指令数据越多越好：质量与多样性优先，噪声数据反有害。
- 只对输出算损失却忘了屏蔽提示：会训练模型去生成指令本身。
- 过度微调导致灾难性遗忘：应控制 epoch 与学习率，或混入通用语料。
- 用训练任务做评测：必须留出未见任务才能真正衡量泛化。

## 九、演进与趋势

从「人工写指令」到「模型自举 + 人工筛选」；从 SFT 走向 SFT + 偏好优化（DPO/RLHF）组合；指令数据开始覆盖多轮、工具调用与安全边界；更小模型配合高质量指令也能达到可用水平。

## 十、小结

指令泛化 = 用多样、高质量的指令数据做 SFT，让模型把「续写能力」转化为「遵循意图」。关键在于数据多样性、只对输出算损失，以及用未见任务评测泛化。
