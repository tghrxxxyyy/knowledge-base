# 零样本与涌现

> 对应 GPT-3（Brown et al., 2020）与 Emergent Abilities（Wei et al., 2022）。规模上去后，能力会「突然出现」。

## 一、背景与挑战

**零样本（Zero-shot）**指不给任何示例、直接下指令让模型完成任务；**少样本（Few-shot）**则在上下文里给少量示例。GPT-3 证明大规模模型具备可观的少样本能力。更引人注目的是**涌现能力**：某些能力在小模型上几乎为零，超过某个规模后突然出现。争议在于：部分「涌现」可能是评测指标不连续（如精确匹配）造成的假象，换成连续指标后曲线可能是平滑的。

## 二、核心原理

上下文学习（In-Context Learning）的直觉：模型把示例当作「条件」，在预训练学到的先验上做隐式推断：

$$P(y\mid x) = M\big(y \mid (x_1,y_1),\dots,(x_k,y_k), x\big)$$

注意：**没有梯度更新**，模型权重不变，示例只是上下文。这与微调本质不同。

涌现的可能解释：
1. **指标效应**：精确匹配类指标在小模型上是「全错」，大模型「偶尔对」，曲线看似突变。
2. **复合能力**：某任务需要多个子能力同时达到一定水平，乘积效应导致阈值式跃升。

## 三、形式化与数学基础

少样本下的后验（把上下文 $C$ 视为条件）：

$$P(y\mid x, C)=\frac{P(y, x, C)}{P(x,C)}$$

若把 ICL 看作隐式贝叶斯推断，示例帮助模型锁定「任务」这一隐变量 $z$：

$$P(y\mid x,C)=\sum_z P(y\mid x,z)\,P(z\mid C)$$

规模律（交叉熵随规模幂律下降）：

$$L(N) = L_\infty + \Big(\frac{N_c}{N}\Big)^{\alpha}$$

## 四、代码实现

少样本提示的构造（注意示例顺序与格式一致）：

```python
def few_shot(examples, query):
    # examples: [(x, y), ...]
    ctx = "\n\n".join(f"输入：{x}\n输出：{y}" for x, y in examples)
    return f"{ctx}\n\n输入：{query}\n输出："
```

实践中示例顺序会显著影响结果，应固定或做排列稳定性测试。

## 五、与其他技术对比

| 方式 | 是否更新权重 | 数据需求 | 适用 |
|------|------------|---------|------|
| 零样本 | 否 | 0 | 通用指令 |
| 少样本 ICL | 否 | 少量 | 格式/风格对齐 |
| 微调 SFT | 是 | 千–万级 | 稳定领域表现 |
| 提示优化 | 否 | 验证集 | 自动搜索好提示 |

## 六、常见误区

- 认为 ICL 是「临时训练」：它没有梯度更新，只是条件作用。
- 把涌现当成必然规律：部分能力是指标假象，需换连续指标复核。
- 示例越多越好：过多示例会挤占上下文且可能引入偏置。
- 忽略示例顺序敏感：同内容不同顺序结果可能差很多。

## 九、演进与趋势

长上下文让更多示例成为可能；思维链（CoT）把「直接答」变成「先推理再答」，显著提升复杂任务；自动提示优化逐步替代手工示例设计。

## 十、小结

零样本/少样本靠上下文条件作用而非梯度更新；涌现现象需谨慎解读，先排除指标假象。工程上，示例质量、顺序与格式一致性比数量更重要。
