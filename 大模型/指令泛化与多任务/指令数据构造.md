# 指令数据构造

> 对应 Self-Instruct（Wang et al., 2022）、Alpaca（Taori et al., 2023）与 WizardLM（Xu et al., 2023）。数据质量决定指令微调的上限。

## 一、背景与挑战

指令微调的效果高度依赖数据，而人工撰写成本高、覆盖窄。自动构造成为主流：用强模型自举生成指令与回答，再过滤。主要挑战：

1. **多样性不足**：模型反复生成相似指令。
2. **正确性无法保证**：自举的回答可能错误，会固化幻觉。
3. **分布偏斜**：偏向模型「擅长」的简单任务。
4. **长度/难度单一**：缺少复杂多步指令。

## 二、核心原理

典型流水线（Self-Instruct 思路）：

1. **种子**：少量人工撰写的种子指令。
2. **生成**：从种子里抽样，让模型生成新指令，再生成回答。
3. **过滤**：去重（如 ROUGE 相似度阈值）、去无效（过短/过长/含占位符）、去低质。
4. **回灌**：把通过过滤的指令加入种子池，继续迭代，扩大多样性。

WizardLM 的 Evol-Instruct 则通过「深度演化」（加约束、加推理步骤、具体化）与「广度演化」（换话题）主动提升指令难度与覆盖。

## 三、形式化与数学基础

去重相似度（以 n-gram ROUGE-L 为例）：

$$\text{sim}(a,b)=\frac{\text{LCS}(a,b)}{\max(|a|,|b|)}$$

保留条件 $\text{sim}(a,b) < \tau$（$\tau$ 常取 0.7）。

难度演化可视为对指令 $x$ 施加变换算子 $\phi$：

$$x' = \phi(x),\quad \phi\in\{\text{加约束},\ \text{具体化},\ \text{增加推理步}\}$$

数据配比（多来源混合）：

$$\mathcal{D} = \bigcup_s w_s \mathcal{D}_s,\qquad \sum_s w_s=1$$

## 四、代码实现

去重与基础过滤：

```python
def dedup(items, tau=0.7):
    keep = []
    for it in items:
        if all(rouge_l(it["instruction"], k["instruction"]) < tau for k in keep):
            keep.append(it)
    return keep

def valid(it):
    ins, out = it["instruction"], it["output"]
    return (10 < len(ins) < 1000 and len(out) > 5
            and "http" not in ins and not ins.startswith(("作为", "抱歉")))
```

## 六、常见误区

- 只做数量不做去重：重复指令会让模型过拟合几句套话。
- 完全信任自举答案：应抽样人工核查或引入验证器。
- 忽视难度分布：全是简单指令会让复杂任务表现差。
- 忘记留验证集：应保留人工撰写的高质量集做评测。

## 九、演进与趋势

从「生成更多」转向「生成更难、更准」；引入外部工具/执行反馈验证回答正确性；用小模型做质量打分批量过滤；合成数据逐步取代部分人工标注。

## 十、小结

指令数据构造的核心工艺是「种子 → 生成 → 过滤去重 → 迭代回灌」，并用演化手段提升难度与多样性。质量与多样性远比数量重要。
