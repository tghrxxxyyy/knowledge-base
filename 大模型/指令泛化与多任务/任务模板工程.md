# 任务模板工程

> 对应 FLAN 的模板化构造（Wei et al., 2021）与 Prompt Source 实践。把数据集变成指令数据，模板是核心工艺。

## 一、背景与挑战

指令微调需要大量「指令-回答」数据，而现成的有标注 NLP 数据集（分类、抽取、摘要）天然可转换。**任务模板**就是把这个转换标准化的工具：同一数据集配上多个模板，既能增广多样性，又能衡量模型对表述的鲁棒性。挑战：模板措辞会显著影响效果（表述敏感性）；模板质量参差会引入噪声；以及模板泄露（评测用了与训练相同的模板会高估泛化）。

## 二、核心原理

一个任务模板包含：

1. **指令部分**：描述任务（「判断下列评论的情感倾向」）。
2. **输入部分**：注入原始数据字段。
3. **输出部分**：目标标签或文本。

工程要点：

- **多模板增广**：同一任务写 5–10 个表述不同的模板，提升鲁棒性。
- **选项枚举**：分类任务在模板里列出候选标签，避免模型自由发挥。
- **反向模板**：同时构造「输入→输出」与「输出→输入」，增强双向理解。
- **留出模板**：评测必须用**未见过的模板**，否则测的是记忆而非泛化。

## 三、形式化与数学基础

数据集 $\mathcal{D}=\{(x_i,y_i)\}$，模板集 $\mathcal{T}=\{T_1,\dots,T_m\}$，则增广后：

$$\mathcal{D}'=\bigcup_{i}\bigcup_{j}\{(T_j(x_i),\, y_i)\}$$

鲁棒性可用模板间方差衡量：

$$\text{Var}_T = \frac{1}{m}\sum_{j}\big(s_j - \bar s\big)^2,\qquad \bar s=\frac{1}{m}\sum_j s_j$$

方差大说明模型对表述敏感，需增广或改写模板。

## 四、代码实现

把分类数据集转成指令样本：

```python
TEMPLATES = [
    "判断下面评论的情感倾向（正面/负面/中性）：\n{text}\n答案：",
    "这条评论是正面、负面还是中性？\n评论：{text}\n回答：",
    "对以下句子做情感分类。\n句子：{text}\n标签：",
]
def build(text, label, tpl_id=0):
    return {"prompt": TEMPLATES[tpl_id].format(text=text),
            "completion": label}
```

评测时换用一组**未参与训练**的模板，才能得到真实泛化水平。

## 五、与其他技术对比

| 数据构造方式 | 多样性 | 成本 | 噪声 |
|------------|--------|------|------|
| 单一手写模板 | 低 | 极低 | 低 |
| 多模板增广 | 中 | 低 | 低 |
| 模型自举（Self-Instruct） | 高 | 中 | 中 |
| 人工众包 | 高 | 高 | 低 |

## 六、常见误区

- 训练与评测用同一批模板：泛化指标虚高。
- 模板措辞随意：含歧义或超出标签空间的模板会误导训练。
- 不做选项枚举：分类任务应显式给出候选集。
- 只用一个模板：模型会对该表述过拟合。

## 九、演进与趋势

模板从人工撰写走向「模型生成 + 过滤」；模板库（如 Natural Instructions）成为公共资产；评测强调跨模板、跨任务的零样本泛化。

## 十、小结

任务模板工程 = 多模板增广 + 选项枚举 + 留出模板评测。它是把存量数据集转化为高质量指令数据的最低门槛路径。
