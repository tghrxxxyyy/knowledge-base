# 可观测性与动作空间

> 对应 Deng et al., *Mind2Web*, NeurIPS 2023；Zhou et al., *WebArena*, ICLR 2024（网页可观测与动作设计）。

## 一、背景与挑战

网页与桌面环境的原始观测极其冗长，元素定位歧义多，而动作若表达为坐标点击则脆弱且不可复现。
可观测性与动作空间的设计直接决定智能体的错误率与轨迹长度。

## 二、核心原理

- 观测压缩：抽取可交互元素（角色、可见文本、可用性）形成带唯一 ID 的无障碍树，剔除样式与不可见节点。
- 动作抽象：使用语义动作（click(id)、type(id, text)、select(id, option)）而非像素坐标，保证可回放与稳定。
- 可用动作枚举：每步给出当前合法动作集合，把选择问题限制在有限集内，显著降低幻觉动作。

## 三、数学形式

若原始观测 token 数为 $L$、抽取后为 $L'$，注意力成本按 $O(L^2)$ 计，压缩带来的相对加速约 $(L/L')^2$。

动作空间从连续坐标 $\mathbb R^2$ 变为离散集合 $\mathcal A(s)$ 后，随机命中概率从近零提升到 $1/|\mathcal A(s)|$，可学习性显著变好。

## 四、代码实现

```python
def observe(page, max_items=60):
    items = []
    for el in page.accessibility_tree():
        if el.visible and el.role in ("button", "link", "textbox", "combobox"):
            items.append({"id": len(items), "role": el.role,
                          "text": el.name[:60], "enabled": el.enabled})
    return items[:max_items]

def legal_actions(items):
    return [f"click({i['id']})" if i["role"] != "textbox" else f"type({i['id']}, ...)"
            for i in items if i["enabled"]]
```

## 五、与其他对比

- 与视觉多模态方案：截图输入更贴近人类操作、跨平台通用，但定位精度与 token 成本是难点；结构化树更省更稳但依赖可访问性信息。
- 与 API 直连：能用 API 就别用界面，界面自动化是无 API 时的兜底方案。

## 六、常见误区

- 把全量 DOM 塞入上下文，既贵又淹没关键元素。
- 元素 ID 每步重新编号但提示未说明，模型引用上一轮 ID 造成错点。
- 不返回动作失败原因（元素不可见、被遮挡），模型只能盲目重试。

## 八、面试题

- 为什么用语义动作而非坐标点击？答：语义动作稳定、可回放、可校验，坐标随分辨率与布局变化失效且无法审计。
- 如何控制观测长度？答：按可交互性与可见性过滤、截断文本、必要时分页浏览，并保留唯一稳定 ID。

## 九、演进

原始 HTML 输入 → 无障碍树抽取 → 语义动作与合法动作枚举 → 视觉加结构混合观测 → 面向任务的自适应观测粒度。

## 十、小结

可观测性与动作空间是环境交互的信息瓶颈：结构化压缩加语义离散动作是当前最稳的组合。
