# 交互轨迹与行为学习

> 对应 Chen et al., *FireAct: Toward Language Agent Fine-tuning*, 2023；Zeng et al., *AgentTuning*, ACL 2024（轨迹微调）。

## 一、背景与挑战

提示工程能让强模型充当智能体，但成本高且行为不稳定；把成功轨迹变成训练数据可以让小模型稳定胜任特定环境。
难点是轨迹质量参差、失败轨迹如何利用、以及避免把提示中的偶发格式固化成脆弱模式。

## 二、核心原理

- 轨迹收集：用强模型或人工在环境中产生 思考—动作—观测 轨迹，按最终成功与过程合规性筛选。
- 行为克隆：对动作 token 做监督微调，观测 token 通常不计损失（它们由环境给出而非模型该学的输出）。
- 失败利用：失败轨迹可用于偏好学习（成功对失败）或作为反例做对比学习，不宜直接做行为克隆。

## 三、数学形式

行为克隆目标为 $\max_\theta\sum_{t}\log\pi_\theta(a_t\mid x,\tau_{<t})$，仅在动作片段上计算损失，即对观测位置做掩码。

偏好式利用可用成对目标 $-\log\sigma\big(\beta[\log\frac{\pi_\theta(\tau^+)}{\pi_{\text{ref}}(\tau^+)}-\log\frac{\pi_\theta(\tau^-)}{\pi_{\text{ref}}(\tau^-)}]\big)$，把成功与失败轨迹配对。

## 四、代码实现

```python
def build_sft_sample(traj):
    ids, labels = [], []
    for seg in traj:                        # seg.kind in {prompt, thought, action, obs}
        t = tokenize(seg.text)
        ids += t
        labels += t if seg.kind in ("thought", "action") else [-100] * len(t)
    return {"input_ids": ids, "labels": labels}   # 观测位置不计损失
```

## 五、与其他对比

- 与纯提示智能体：微调后小模型延迟与成本更低、格式更稳，但泛化到新环境需重新收集轨迹。
- 与在线强化学习：轨迹微调是离线模仿，无需环境交互训练循环，样本效率高但受演示上限约束。

## 六、常见误区

- 对观测 token 也计损失，模型学着「幻想观测」，上线后自己编造环境返回。
- 只用成功轨迹且数量少，导致过拟合到特定任务模板，换措辞即失效。
- 轨迹中含环境特有 ID 与时间戳未做泛化处理，模型记住了无意义细节。

## 八、面试题

- 为什么观测片段要做损失掩码？答：观测由环境提供，让模型学习生成观测会诱发编造环境返回的行为。
- 失败轨迹怎么用？答：用于偏好对比或反例分析，而不是直接行为克隆，否则会把错误行为一起学会。

## 九、演进

纯提示智能体 → 强模型蒸馏轨迹 → 轨迹行为克隆（FireAct、AgentTuning）→ 成功失败配对偏好优化 → 在线交互强化。

## 十、小结

轨迹学习把提示期的能力固化进权重，关键工程细节是筛选质量、掩码观测与合理利用失败样本。
