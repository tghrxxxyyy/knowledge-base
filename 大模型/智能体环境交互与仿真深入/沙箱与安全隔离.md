# 沙箱与安全隔离

> 对应 Ruan et al., *ToolEmu: Identifying the Risks of LM Agents with a LM-Emulated Sandbox*, ICLR 2024；OWASP 对 LLM 应用风险的公开梳理。

## 一、背景与挑战

智能体一旦获得写权限（文件、shell、支付、邮件），一次错误动作就可能造成不可逆损失。
更棘手的是间接提示注入：环境内容（网页、文件、工具返回）可能携带指令，劫持智能体去执行攻击者意图。

## 二、核心原理

- 最小权限与分级授权：默认只读，写操作按风险分级，高风险动作要求人工确认或二次校验。
- 隔离执行：容器或虚拟机内运行，限制网络出口、文件系统范围、资源配额与执行时长。
- 不信任环境输入：把工具返回与网页内容视为数据而非指令，用分隔与来源标注降低注入成功率，并对敏感动作做独立确认通道。

## 三、数学形式

风险可用期望损失量化：$\text{Risk}=\sum_i p_i\cdot L_i$，其中 $p_i$ 为该类误动作概率、$L_i$ 为损失。

分级授权把高 $L_i$ 项的 $p_i$ 乘上人工确认的漏检率 $\eta\ll 1$，从而在不牺牲多数流程效率的前提下压低总风险。

## 四、代码实现

```python
RISK = {"read_file": 0, "http_get": 0, "write_file": 1, "shell": 2, "pay": 2}

def guarded_exec(tool, args, user_confirm):
    level = RISK.get(tool.name, 2)
    if level >= 2 and not user_confirm(tool.name, args):
        return "已拒绝: 需人工确认"
    with sandbox(net="deny", fs=WORKDIR, timeout=30, mem="512m"):
        return tool.run(**args)
```

## 五、与其他对比

- 与真实环境直连：沙箱牺牲部分能力换取可控与可回放，是迭代期的必要基础设施。
- 与模型侧对齐：对齐降低有意作恶概率，但无法覆盖注入与误操作，系统层隔离不可替代。

## 六、常见误区

- 认为「提示里写了不要执行危险操作」就够了：提示不是权限边界。
- 沙箱只限文件不限网络，注入后仍可外传数据。
- 把人工确认做成默认同意的弹窗，形式化确认等于没有确认。

## 八、面试题

- 什么是间接提示注入，为什么危险？答：环境数据中嵌入指令被模型当作命令执行，攻击面来自不可控的第三方内容，且绕过了用户意图。
- 如何设计权限分级？答：按动作不可逆性与损失规模分级，高风险要求人工确认加沙箱限制，并对全部动作留审计日志。

## 九、演进

无限制执行 → 容器隔离 → 权限分级与人工确认 → 模拟沙箱做风险评测（ToolEmu）→ 数据与指令分离的系统化防注入。

## 十、小结

智能体安全靠系统边界而非提示措辞：最小权限、隔离执行、人工确认与完整审计。
