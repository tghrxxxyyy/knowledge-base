# 稀疏注意力效率分析

> 对应 Tay et al., *Efficient Transformers: A Survey*, 2020 对稀疏/线性注意力的系统对比。

## 一、背景与挑战

稀疏模式理论复杂度低，但实际加速依赖硬件与实现；需理解何时真省、何时反噬。

## 二、核心原理

稀疏把 $O(n^2)$ 的 FLOPs 降为 $O(nw)$ 等，但不规则访存可能削弱 GPU 利用率，需与分块/核融合配合。

## 三、数学形式

全注意力 FLOPs $\approx 2n^2d$；滑窗 $\approx 2nwd$；加速比随 $n/w$ 增大而显著。

## 四、代码实现

```python
flops_dense = 2 * n * n * d
flops_sparse = 2 * n * w * d
speedup = flops_dense / flops_sparse
```

## 五、与其他对比

- 稀疏省 FLOPs 但需规整掩码；线性注意力省到 $O(n)$ 但改了近似形式。
- 与 FlashAttention 互补：前者减计算量，后者减显存带宽。

## 六、常见误区

- 只看理论复杂度忽略访存，实际未加速。
- 把稀疏注意力当万能，短序列下反慢于稠密。

## 八、面试题

- 为何稀疏注意力有时没加速？答：不规则掩码致 GPU 利用率低，需分块/融合才见效。

## 九、演进

理论稀疏 → 与 IO 优化（FlashAttention）结合 → 实际可用长序列。

## 十、小结

稀疏注意力效率需软硬件协同，理论降复杂度不等于实际加速。
