# 推理服务总览

> 对应 Kwon et al., *vLLM*, 2023（SOSP）；在线推理服务综述。

## 一、背景与挑战

LLM 推理自回归、长上下文、显存峰值高，朴素逐请求串行吞吐极低。

## 二、核心原理

服务栈：网关→调度器→推理引擎（vLLM/TGI/TRT-LLM）；核心优化是连续批处理与 PagedAttention。

## 三、数学形式

吞吐 $=\frac{\text{total tokens}}{\text{gpu-hours}}$；受限于 KV 显存与算力的短板。

## 四、代码实现

```python
from vllm import LLM, SamplingParams
llm = LLM(model="meta-llama/Llama-3-8B", tensor_parallel_size=2)
```

## 五、与其他对比

- 与 API网关与限流策略深入（入口）衔接。
- 与 成本优化与资源调度深入 共享显存观。

## 六、常见误区

- 以为加副本即线性扩容（KV/通信开销）。
- 忽视长尾请求占满 KV 致排队。

## 七、与开源书对应

- mlabonne/llm-course：https://github.com/mlabonne/llm-course
- rasbt/LLMs-from-scratch：https://github.com/rasbt/LLMs-from-scratch

## 八、面试题

- LLM 服务难点？答：自回归+长 KV 显存峰值，需批处理与显存管理提吞吐。

## 九、演进

串行 → 静态批 → 连续批（vLLM）→ 分布式。

## 十、小结

LLM 服务靠批处理+显存管理把吞吐做高，是部署核心。
