# 连续批处理

> 对应 Kwon et al., *vLLM / Orca*, 2023/2022（迭代级调度）。

## 一、背景与挑战

静态批处理须等长补齐、等最慢请求完成才释放，GPU 空转严重。

## 二、核心原理

迭代级调度：每解码一步动态组批，完成的请求立即退出、新请求随时加入，最大化占用。

## 三、数学形式

利用率 $u = \frac{\sum_i \text{tokens}_i}{B\cdot T}$；连续批使 $u$ 接近 1 而非被最长请求拖低。

## 四、代码实现

```python
# 伪：每步动态组批
batch = scheduler.step()        # 加入新/剔除完成
out = model.forward(batch)
```

## 五、与其他对比

- 与 PagedAttention深入 配合（按 slot 管理 KV）。
- 与 模型服务负载均衡深入 总览衔接。

## 六、常见误区

- 静态批仍用于简单场景，误以为都需连续批。
- 调度步过长致延迟抖动。

## 八、面试题

- 连续批为何比静态批好？答：逐 token 调度，完成即释放、新请求即入，消除补齐空转。

## 九、演进

无批 → 静态批 → 连续（迭代级）批。

## 十、小结

连续批处理是吞吐跃升关键，按步动态调度。
