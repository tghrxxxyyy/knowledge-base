# 序列建模取舍

> 对应 d2l-zh 与状态空间模型综述（Gu et al., S4, 2021；序列建模深入 对照）。

## 一、背景与挑战

不同序列任务在长度、实时性、数据量上差异大，需权衡 RNN/Transformer/SSM 选型。

## 二、核心原理

- RNN：推理 $O(1)$ 步长、适合流式，但训练慢且长程弱。
- Transformer：训练并行、长程强，但推理 $O(n^2)$ 且 KV 缓存随长度增长。
- SSM：线性复杂度、可并行训练、长序列友好，但离散化与选择性仍需调。

## 三、数学形式

复杂度对比：RNN 训练 $O(n)$ 顺序、推理 $O(1)$；Attention 训练/推理均 $O(n^2)$；SSM 训练 $O(n)$ 并行、推理 $O(1)$。

## 四、代码实现

```python
# 推理时 RNN/SSM 仅维护定长状态
state = step(x_t, state)   # O(1) per token
```

## 五、与其他对比

- 离线批处理长文档：Transformer 质量高但算力贵；SSM 更省。
- 在线流式：RNN/SSM 优势明显。

## 六、常见误区

- 盲目追大模型 Transformer 忽视推理成本；生产常需蒸馏/SSM 折中。
- 以为 SSM 完全取代注意力，实际混合架构常见。

## 七、与开源书对应

- d2l-zh 序列建模章：https://github.com/d2l-ai/d2l-zh
- 序列建模深入 提供 SSM 细节。

## 八、面试题

- 流式场景为何倾向 RNN/SSM？答：定长状态、每步 $O(1)$，避免 KV 缓存膨胀。

## 九、演进

RNN → Transformer → 高效注意力 → SSM → 混合架构。

## 十、小结

序列建模无单一最优，按长度、延迟、数据量在 RNN/注意力/SSM 间取舍。
