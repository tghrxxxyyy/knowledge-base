# 序列并行通信模式

> 对应 Megatron-LM 通信分析；Korthikanti et al., 2022。

## 一、背景与挑战

SP 在权重相关 GEMM 与序列相关算子间需转换分片布局。

## 二、核心原理

列并行 GEMM 输出是序列完整、TP 分片；接序列并行需 reduce-scatter 转成序列分片；反向时用 all-gather；通信量正比 $b s h$。

## 三、数学形式

转换通信 $C_{sp}\approx 2 b s h$（一次 reduce-scatter + 一次 all-gather）。

## 四、代码实现

```python
# GEMM 后由 TP 分片转 SP 序列分片
out = linear_col(x)              # TP 分片、序列完整
out = reduce_scatter(out, sp_group)   # 转序列分片
```

## 五、与其他对比

- 与 张量并行深入 通信叠加但各自量小。
- 与 通信压缩深入 难压缩（激活非梯度）。

## 六、常见误区

- 频繁 layout 转换增通信。
- 跨节点 SP 带宽不足。

## 八、面试题

- SP 与 TP 如何衔接布局？答：GEMM 后用 reduce-scatter 在序列维重分片。

## 九、演进

手动转换 →  fused 算子 → 自动布局。

## 十、小结

序列并行通信在 TP/SP 布局转换处，量正比序列长度。
