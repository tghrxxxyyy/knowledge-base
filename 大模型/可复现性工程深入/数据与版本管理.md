# 数据与版本管理

> 见「可复现性工程深入/可复现性总览」与「数据治理血缘深入」；DVC/lakeFS。

## 一、背景与挑战

数据变了，结果就变，但数据常无版本。

## 二、核心原理

用 DVC（对接对象存储）或 lakeFS 对数据集做版本化（类似 git 但面向大文件），记录数据 commit 哈希；每次实验绑定数据版本+代码版本+配置，形成可复现单元。

## 三、关键要点

- 数据哈希防篡改。
- 数据与代码同版本关联。

## 四、代码实现

```bash
dvc add data/; git add data.dvc
dvc checkout exp-branch
```

## 五、与其他对比

- git 管代码；DVC 管数据。

## 六、常见误区

- 只存路径——内容变了不知。

## 七、与开源书对应
