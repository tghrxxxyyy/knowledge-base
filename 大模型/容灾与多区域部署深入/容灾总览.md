# 容灾与多区域部署总览

> 对应灾难恢复（DR）与多区域（multi-region）；Kubernetes 跨区部署。云厂商提供多可用区。

## 一、背景与挑战

单区域故障（断电、网络、自然灾害）会导致全服务不可用，需容灾与多区域冗余。

## 二、核心原理

在多个区域部署副本，通过全局负载均衡与数据复制实现故障转移；按 RTO 与 RPO 定级别。

## 三、数学形式

可用性 $A = 1 - \prod_i (1 - A_i)$；多区域降低全断概率。

## 四、代码实现

```python
lb.add_backend("region-a", weight=50)
lb.add_backend("region-b", weight=50)
```

## 五、与其他对比

- 与 故障转移与Failover（执行）衔接。
- 与 双活与多活（模式）分述。

## 六、常见误区

- 只部署不演练，故障真发生时切不过去。
- 跨区域数据不一致致脑裂。

## 八、面试题

- 容灾为何多区域？答：消除单区域单点，按 RTO、RPO 做冗余与故障转移。

## 九、演进

单区 → 主备 → 多区域双活。

## 十、小结

容灾以多区域冗余换可用性，是服务连续性的底线。
