# 查询监控限流

> 对应 OWASP LLM Top 10（模型抽取与过量资源消耗风险面）、API 限流与风控实践，与 mlabonne/llm-course 安全章。

## 一、背景与挑战

模型抽取的「前兆」往往不是某一次异常请求，而是**长期、高频、模式化的探测**：攻击者用脚本批量提交相似输入，试图以最低成本覆盖原模型的决策边界。一旦这种规模化查询不被察觉，后续的克隆只是时间问题。

核心难点在于：正常业务也有高峰、也有批量调用。如果限流只按「每分钟请求数」粗暴封顶，要么误伤真实用户，要么被攻击者用低速、分布式策略绕过。监控限流的目标是**区分「正常流量」与「抽取型流量」**，在误伤与漏防之间取得平衡，把防御前移到攻击成形之前。

## 二、核心原理

监控层从多个维度刻画一次调用：身份（IP/API Key/账号）、语义相似度（与历史查询的近邻距离）、体积（输入输出长度）、时间分布（是否机械匀速）。当某身份在窗口内出现**高相似度 + 高重复率 + 异常匀速**的组合特征时，判定为疑似抽取。

处置不是一刀切封禁，而是分级响应：轻度异常降采样（返回缓存/扰动变体），中度异常触发挑战（验证码、 proof-of-work），重度异常限速或临时冻结密钥。这种「识别-分级-响应」的闭环，是限流从「保稳定」升级为「防抽取」的关键。

## 三、形式化与数学基础（含 LaTeX）

设窗口内身份 $u$ 的查询集合为 $\{x_1,\dots,x_n\}$，定义平均两两语义相似度

$$
\bar s(u)=\frac{1}{n^2}\sum_{i,j}\mathrm{sim}(x_i,x_j)
$$

以及相似查询速率 $r_s(u)$ 与匀速度（请求间隔方差的倒数）$c(u)$。综合风险评分

$$
\mathrm{Risk}(u)=\sigma\!\big(w_1\bar s(u)+w_2 r_s(u)+w_3 c(u)\big)
$$

当 $\mathrm{Risk}(u)>K$ 触发挑战；当持续超阈值则限速。阈值 $K$ 需在误伤率（false positive）与漏防率间权衡确定，通常以离线标注的探测样本调参。

## 四、代码实现（围栏配平）

```python
def risk_score(user, queries, sim_fn):
    n = len(queries)
    if n == 0:
        return 0.0
    s = sum(sim_fn(queries[i], queries[j])
            for i in range(n) for j in range(n)) / (n * n)
    rate = len(queries) / window_seconds(user)
    uniform = 1.0 / max(jitter(user), 1e-6)     # 间隔越均匀越大
    return sigmoid(0.5 * s + 0.3 * rate + 0.2 * uniform)

def on_request(user, x):
    if risk_score(user, recent(user)) > K:
        return challenge(user)                  # 验证码 / PoW
    return model.serve(x)
```

## 五、与其他技术对比

- 与普通稳定性限流相比：后者只看 QPS，前者看语义与行为模式，针对性更强。
- 与输出扰动相比：限流治「量」，扰动治「质」，互补。
- 与水印相比：限流在前端拦截，水印在后端举证。

## 六、常见误区

- 「设个 QPS 上限就够」——低速分布式攻击可绕过固定阈值。
- 「相似度检测太贵」——可用 MinHash/嵌入近邻近似，代价可控。
- 「误伤无所谓」——过度限流会赶走真实用户，需分级而非硬封。
- 「命中即封禁」——直接封禁易被误伤，应先挑战再限速。

## 八、面试题

- 问：如何识别抽取型查询？答：综合身份、语义相似度、重复率与匀速度，单看 QPS 不够，需行为模式识别。
- 问：为何要分级响应？答：避免误伤正常批量用户，轻度降采样、中度挑战、重度限速。
- 问：相似度检测成本高怎么办？答：用嵌入近邻、MinHash 等近似方法在可控开销下完成。
- 问：如何平衡误伤与漏防？答：用离线标注的探测样本调阈值 $K$，并以挑战而非硬封作为首选处置。

## 九、演进与趋势

从规则阈值走向**在线异常检测模型**（序列建模识别探测脚本），并与用户信誉、设备指纹、联邦风控联动；边缘侧实时限速也逐步普及。未来趋势是把监控、限流、扰动、水印编排成统一防御编排层。

### 关键要点速查

- 监控限流是第一道防线，目标是区分「正常流量」与「抽取型流量」而非只看 QPS。
- 风险评分应综合相似度、重复率、匀速度三维，单维极易被绕过。
- 处置必须分级：轻度降采样、中度挑战、重度限速，避免误伤真实用户。
- 相似度检测可用嵌入近邻或 MinHash 近似，成本可控，不必全量精算。
- 挑战机制（验证码/PoW）比直接封禁更友好，也能拖慢自动化脚本。
- 阈值 $K$ 需用离线标注的探测样本调参，在误伤与漏防间取平衡。
- 与扰动、水印编排成统一防御层，限流负责前端拦截、其余负责降质与举证。
- 监控数据本身含敏感信息，需做好访问审计，避免防御系统成为新攻击面。

## 十、小结

查询监控限流是模型抽取的第一道防线：用多维度行为识别替代单一 QPS 阈值，配合分级响应，在保体验的同时阻断规模化抽取，并为下游水印与法律追责争取时间。
