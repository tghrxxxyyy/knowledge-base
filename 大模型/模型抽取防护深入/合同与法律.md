# 合同与法律

> 对应 OWASP LLM Top 10（模型抽取风险面）、各平台服务条款（ToS）实践，与 mlabonne/llm-course 安全章。

## 一、背景与挑战

技术防护只能降低抽取的发生概率，却无法在事后「证明对方抄袭了你的模型」。当替代模型已经上线、甚至商业化，原模型方需要的是**可追溯、可举证、可追责**的手段。没有契约与法律层面的安排，技术团队往往拿不出「对方违反了什么」的依据。

一个典型场景是：某创业公司花费数月与算力训练出专用模型，以 API 收费。竞争者用脚本批量调用，几周内训出行为相近的免费替代模型并开源，原公司收入骤降却难以制止。此时限流与扰动只能降低速度，真正能叫停的是合同与法律的后手。

核心矛盾在于：API 的开放本质鼓励调用，而调用产生的数据又可能被用于再训练。若不在契约层面明确边界，一旦发生纠纷，技术防御就成了「防君子不防小人」。因此合同与法律不是技术的替代品，而是**与技术防御互补的事后威慑与追责机制**——它把「不该做」写进条款，把「做了」变成可追责的违约或侵权。

## 二、核心原理

法律防护围绕三条主线展开。其一，**服务条款（ToS）/ 使用协议**明示禁止：不得用返回结果训练替代模型、不得大规模抓取、不得逆向工程。这是最直接的事前约束，用户在调用前即被告知边界，也为后续追责奠定合同基础。

其二，**取证与存证**：对异常调用、可疑训练行为留存日志与样本，必要时引入水印/指纹作为权属证据。法务与技术在此交汇——没有技术侧的取证，法律条款就是空文，无法在纠纷中落地。

其三，**违约与侵权追责**：当证据链完整，可依据合同违约、不正当竞争或知识产权保护主张权利。法律上能走多远，取决于当地对「模型权重/输出」权属与「文本与数据挖掘例外」的规定，具体适用以司法辖区最新法规为准，本文不给出确定结论。

值得补充的是，条款本身也分层次：免费层可禁止任何再训练，商业层可允许有限微调但禁止竞品蒸馏。分层条款让防护与商业模式对齐，而非一刀切，避免把善意用户也挡在门外。

## 三、形式化与数学基础（含 LaTeX）

可将法律风险建模为威慑博弈。设守方维权成本为 $C_l$，攻击者期望收益为 $B_a$，被发现概率为 $p$，惩罚为 $F$。攻击者净期望收益

$$
U_a = (1-p)\,B_a - p\,F
$$

当且仅当 $U_a<0$（即 $p\,F > (1-p)B_a$）时，理性攻击者被威慑。可见提升**被发现概率 $p$**（靠监控+水印取证）与**惩罚强度 $F$**（靠清晰 ToS 与法律路径）同等重要。守方的治理投入应使 $p$ 与 $F$ 的乘积稳定超过攻击收益，而非只押注单一手段。若取证能力弱（$p$ 低），则需更高的合同惩罚 $F$ 补足，否则威慑不成立。

### 条款范本要点（参考）

下面是一段可在 ToS 中落地、且具备可操作性的禁止性条款骨架（措辞以法务审定为准）：

```text
禁止行为：
  1. 使用本服务输出（含文本、嵌入、logits）训练、微调或蒸馏任何竞争模型；
  2. 以自动化手段对接口进行大规模抓取、探测或重建决策边界；
  3. 对本服务进行逆向工程以推断架构、参数或训练数据成员。
违约后果：
  - 立即终止 API 密钥并保留追责权利；
  - 已产生的调用日志与输出样本可作为权属与违约证据。
```

该骨架的关键在于「行为可枚举 + 后果可执行 + 取证有授权」三点同时成立，否则条款难以落地。

## 五、与其他技术对比

- 与限流/扰动相比：技术防「发生」，法律备「追责」，前者降低概率，后者提高代价，二者正交互补。
- 与纯技术水印相比：水印提供证据素材，法律提供处置通道，二者缺一不可。
- 与开源协议相比：开源权重本就允许再训练，合同主要适用于闭源 API 模式，边界设定逻辑不同。
- 与访问控制相比：访问控制决定「谁能调」，合同决定「调了能做什么」，两者正交互补。

## 六、常见误区

- 「ToS 万能」——条款若无明确禁止训练、无取证支撑，纠纷时难以执行，威慑流于纸面。
- 「技术能完全防住」——再强的限流也有绕过空间，法律后手不可或缺。
- 「所有辖区规则相同」——模型权属与数据挖掘例外因法域而异，需以官方最新文档为准。
- 「取证可事后补」——行为日志若不实时留存，关键证据易随 TTL 过期丢失，应在架构层默认开启。
- 「开源就不需要合同」——开源仍需许可证约定衍生使用边界，否则商业蒸馏无制约。

## 七、与开源书·权威来源对应

- OWASP LLM Top 10 将模型抽取/过度依赖列为关键风险，并建议结合使用限制与监控。
- mlabonne/llm-course 安全章节强调 API 调用的契约与防护并重。
- 各主流模型服务商（如 OpenAI、Anthropic、Google 等）ToS 均设有「禁止用输出训练竞争模型」条款，可作范本参考。
- 关于模型权属与 TDM（文本与数据挖掘）例外，请以各司法辖区最新立法与官方解释为准。

## 八、面试题

- 问：法律如何补充技术防抽取？答：技术降概率，合同明边界，取证留证据，追责提代价，形成「威慑+追责」闭环。
- 问：ToS 里最该写清什么？答：明确禁止训练替代模型、大规模抓取与逆向工程，并约定违约后果与取证授权。
- 问：为什么取证要与技术结合？答：法律需要可采证据，水印与调用日志是权属与违约的关键素材，缺技术则条款空转。
- 问：合同能否完全阻止抽取？答：不能阻止发生，但能显著提高攻击者的法律与商业代价，改变其成本收益权衡。
- 问：分层条款有何好处？答：让防护强度与商业模式对齐，免费层严控、商业层灵活，避免一刀切伤生态。

## 九、演进与趋势

随着模型即服务普及，**契约正在标准化**：使用分级（研究/商业）、输出用途白名单、以及与水印绑定的「合规调用凭证」。监管侧也在讨论训练数据权属与模型保护的立法框架，具体走向以官方最新文档为准。企业侧则出现「法务+安全+算法」三方协同的治理流程，把条款落地为可执行的检测与处置，并在合同中嵌入自动化审计授权，使违约可被快速识别与取证。

## 十、小结

合同与法律是模型抽取防护的「后盾」：用清晰的 ToS 设定边界、用技术取证夯实证据、用追责机制提高攻击代价，与技术防御共同构成完整防线。它不追求「不发生」，而追求「发生即可被追责」，并以分层条款匹配不同商业模式，在防护与生态之间取得平衡。
