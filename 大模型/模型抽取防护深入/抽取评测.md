# 抽取评测

> 对应 Krishna et al. 2020《Model Extraction and Adversarial Attacks on Model Extraction》、mlabonne/llm-course 安全章，与 lm-evaluation-harness 评测实践。

## 一、背景与挑战

部署了限流、扰动、水印等防御后，团队常面临一个尴尬问题：**我们并不知道这些防御到底有没有用**。防御强度过高损害体验，过低则形同虚设。没有量化评测，防护就成了「凭感觉调参」，一旦被绕过也无从察觉。

抽取评测（extraction evaluation）的目标，就是**以攻击者的视角，度量替代模型在受防护后与原模型的差距**。差距越大，说明防御越有效；差距接近零，则说明防护被绕过。它把「安全」从定性口号变成可比较、可回归的指标，是安全发布前的必经关卡。

## 二、核心原理

评测遵循「红队即服务」思路：构造一个模拟攻击者，在给定查询预算（budget）下不断调用受防护的 API，收集「输入-输出」对，用这些数据训练一个替代模型（clone）。随后在多个任务上比较替代模型与原模型的表现差异。

关键维度有三：其一，**功能 fidelity**（保真度）——替代模型在目标任务上的准确率与原模型的差距；其二，**分布一致性**——替代模型输出分布与原模型 KL 散度的大小；其三，**攻击成本**——达成某保真度所需的最小查询量与算力。防御有效意味着在合理预算内，替代模型保真度显著低于原模型，且攻击者需要远超正常用户成本的投入。

## 三、形式化与数学基础（含 LaTeX）

设原模型为 $f$，替代模型为 $\hat f$，评测任务集合为 $\mathcal{T}$，样本分布为 $\mathcal{D}$。定义保真度

$$
\mathrm{Fidelity}(\hat f, f)=\mathbb{E}_{t\sim\mathcal{T},(x,y)\sim\mathcal{D}}\big[\,\mathbb{I}(\hat f_t(x)=f_t(x))\,\big]
$$

以及分布距离

$$
\mathrm{Div}(\hat f,f)=\mathbb{E}_{x\sim\mathcal{D}}\big[\,\mathrm{KL}\big(f(\cdot\mid x)\,\|\,\hat f(\cdot\mid x)\big)\big]
$$

给定攻击预算 $B$（总查询数），定义有效防护为：当 $n\le B$ 时，$\mathrm{Fidelity}$ 与 $1$ 的差距始终大于阈值 $\tau$。评测即绘制 $\mathrm{Fidelity}(n)$ 随 $n$ 的曲线，观察其收敛到 $1$ 的拐点是否远超出 $B$；若拐点 $\le B$，则防御被突破。

## 四、代码实现（围栏配平）

```python
def evaluate_extraction(target, defender, budget, tasks):
    probe_set = sample_queries(budget)         # 攻击者查询预算
    pairs = [(x, defender(target, x)) for x in probe_set]
    clone = train_surrogate(pairs)             # 用收集对训练替代模型
    gaps = []
    for t in tasks:
        g = task_gap(clone, target, t)         # 与原模型在任务 t 上的差距
        gaps.append(g)
    return {"mean_gap": mean(gaps), "budget": budget}

def is_defended(curve, budget, tau):
    # 在预算内保真度差距是否始终大于阈值
    return all(curve[n] < 1 - tau for n in range(1, budget + 1))
```

## 五、与其他技术对比

- 与「能力自评」相比：自评估只看模型自身好坏，抽取评测专门衡量抗克隆能力。
- 与「安全扫描」相比：扫描查已知漏洞，抽取评测是针对性的红队攻防演练。
- 与离线基准相比：它引入攻击者预算这一动态变量，更贴近真实威胁演化。

## 六、常见误区

- 「没有攻击就是安全」——攻击者可能只是预算未到，评测需覆盖多预算档位。
- 「只看准确率差距」——分布层面已被泄露而任务准确率未降，同样危险。
- 「跑一次即可」——防御参数变更后需重测，否则回归无感。
- 「克隆失败=完全安全」——可能只是查询策略低效，应尝试多种探测策略。

## 七、与开源书·权威来源对应

- Krishna et al. 2020 系统定义了模型抽取攻击与度量（含 fidelity、攻击查询量）。
- mlabonne/llm-course 将此类红队评测纳入模型安全实战。
- lm-evaluation-harness 可用于在标准化任务上量化替代模型的保真度衰减。
- OWASP LLM Top 10 亦建议以对抗性评估验证防护有效性。

## 八、面试题

- 问：如何评测防抽取效果？答：模拟攻击者用固定预算收集数据训替代模型，比较其与原始模型在任务保真度与分布距离上的差距，差距大即有效。
- 问：为何要引入预算？答：防御只在「合理预算内」有效才有意义，否则无限查询终将克隆成功。
- 问：只比准确率够吗？答：不够，还需看输出分布是否被复刻，分布泄露同样致命。
- 问：评测曲线怎么读？答：看保真度随查询量的收敛拐点，拐点超过攻击预算即视为有效防护。

## 九、演进与趋势

从单次模拟走向**自动化、持续化的抽取红队流水线**，与 CI 集成，防御参数变更即触发回归；并引入更细的「能力面」拆解（代码、推理、知识），分别评估各能力的可抽取性。黑盒攻防基准也在逐步标准化，使不同防御方案可横向对比。

### 关键要点速查

- 评测必须先于防御上线，并作为持续回归项，而非一次性动作。
- 攻击预算 $B$ 应取业务可承受的查询上限，而非理论无穷，否则结论无意义。
- 同时观测保真度与分布距离，只看准确率会漏掉「分布已泄露但任务未降」的情况。
- 攻击策略应多样（随机/自适应/对抗），单一策略易误判为安全。
- 替代模型架构应与原模型可比，规模差异过大会扭曲保真度度量。
- 监控、扰动、水印任一改动后都应重跑评测，防止回归无感。
- 评测本身消耗调用量，应在隔离环境进行，避免污染线上监控数据。
- 把「预算-保真度」曲线纳入发布门槛，低于阈值不得上线。

## 十、小结

抽取评测把防护效果量化为「预算-保真度」曲线，是验证限流、扰动、水印等手段是否有效的唯一可靠方式，应作为安全发布的必经关卡与持续回归项。
