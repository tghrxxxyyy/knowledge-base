# 水印防克隆

> 对应 Kirchenbauer et al. 2023《A Watermark for Large Language Models》(KGW)、模型水印与溯源研究，与 mlabonne/llm-course 安全章。

## 一、背景与挑战

限流、扰动、去重都是「事前」降低可抽取性的手段，但它们无法回答一个事后问题：**如果模型还是被克隆了，我怎么证明「那个模型偷了我的」？** 没有权属证据，法律追责就无从谈起，技术防御也失去了闭环。

水印（watermark）提供了一条不同路径：它不阻止攻击发生，而是在输出中嵌入**人类不可见、机器可检测**的信号。一旦克隆模型从受保护模型「学走了」生成分布，水印会作为「指纹」被继承，从而把克隆行为与原始模型关联起来，实现事后溯源举证。

## 二、核心原理

以经典的 KGW（Kirchenbauer et al. 2023）为例：在生成时，用一个固定于词表上的伪随机「绿名单」（green list）对 token 施加轻微偏好——被选中的 token 获得额外的 logit 加成，使生成文本在统计上偏向绿名单词。由于这种偏好是隐蔽且可复现的，检测方只需统计一段文本中绿名单词的比例，即可用假设检验判断其是否带水印。

当攻击者用受保护模型的输出训练替代模型时，替代模型会继承「偏向绿名单」的分布特征；即便攻击者做轻微微调，统计信号往往仍可被检出。这就把水印从「单条文本溯源」延伸为「模型级克隆举证」，是技术防御与法律追责之间的关键桥梁。

## 三、形式化与数学基础（含 LaTeX）

设词表 $\mathcal{V}$ 按密钥 $k$ 与上下文 $h$ 划分为绿名单 $G(h)$ 与红名单 $R(h)$。生成时对绿名单加偏置 $\delta>0$：

$$
\log p'(w\mid h)=\log p(w\mid h)+\delta\cdot\mathbb{I}[w\in G(h)]
$$

对一段长度为 $n$ 的文本，定义绿名单命中数 $m=\sum_{i=1}^n \mathbb{I}[w_i\in G(h_i)]$。在零假设（无水印、随机命中率 $\gamma=|G|/|\mathcal{V}|$）下，$m\sim\mathrm{Binomial}(n,\gamma)$。检验统计量 $z=\frac{m-n\gamma}{\sqrt{n\gamma(1-\gamma)}}$，当 $z$ 远超阈值即拒绝零假设，判定含水印。克隆模型因分布继承，其输出的 $z$ 值显著偏高，从而可被归因。

## 四、代码实现（围栏配平）

```python
import hashlib, random

def green_list(prefix, vocab_size, gamma=0.5, seed_key="secret"):
    h = hashlib.md5((seed_key + prefix).encode()).hexdigest()
    rng = random.Random(h)
    ids = list(range(vocab_size))
    rng.shuffle(ids)
    return set(ids[:int(vocab_size * gamma)])   # 绿名单

def score_watermark(tokens, green_sets, gamma):
    m = sum(1 for t, g in zip(tokens, green_sets) if t in g)
    n = len(tokens)
    z = (m - n * gamma) / (n * gamma * (1 - gamma)) ** 0.5
    return z                                     # z 越大越可能带水印
```

## 五、与其他技术对比

- 与限流相比：限流防「发生」，水印备「溯源」，职责不同，可叠加。
- 与输出扰动相比：扰动降可利用性，水印提供证据，二者互补。
- 与合同相比：合同给追责依据，水印给技术证据，互补成立。

## 六、常见误区

- 「水印能杜绝克隆」——不能，它只提供事后举证能力，不阻止发生。
- 「水印不可去除」——强改写、翻译、 paraphrasing 会削弱信号，需配合鲁棒水印研究。
- 「所有水印都安全」——密钥泄露或算法公开后，伪造水印成为可能，需密钥管理。
- 「检出即确权」——统计证据需结合其他线索，司法采信以当地规则为准。

## 七、与开源书·权威来源对应

- Kirchenbauer et al. 2023 提出可检测的绿名单 logit 偏置水印，是文本水印的奠基性工作。
- 后续研究（如 Scott et al. 2024 关于鲁棒性、公开-检测权衡）拓展了抗改写能力。
- mlabonne/llm-course 安全章将水印列入模型溯源工具箱。
- 模型水印与溯源专题讨论了其在克隆举证中的角色。

## 八、面试题

- 问：水印如何辅助防模型克隆？答：克隆模型继承受保护模型的生成分布偏好，水印统计信号随之被复制，可在模型层面举证抄袭。
- 问：KGW 的核心机制？答：按密钥把词表分为绿/红名单，对绿名单加 logit 偏置，检测端用假设检验识别。
- 问：水印的局限？答：可被改写攻击削弱，且依赖密钥保密与统计显著性，不能单独确权。
- 问：为何说它是桥梁？答：它把技术分布特征转化为可采证据，使合同追责具备事实基础。

## 九、演进与趋势

方向包括：更强的**抗改写/抗翻译鲁棒水印**、**语义级水印**（不依赖固定词表）、以及把水印与「证明模型所有权」的密码学方案结合，形成可司法采信的证据链。部分方案还探索在训练阶段注入不可磨灭的权重级指纹。

### 关键要点速查

- 水印是溯源层，不阻止抽取发生，价值在事后举证与威慑。
- KGW 的核心是绿/红名单 + logit 偏置，检测用假设检验的 $z$ 分数。
- 密钥管理是安全前提：密钥泄露则任何人可伪造水印，证据失效。
- 改写、翻译、 paraphrasing 会削弱统计信号，需配合鲁棒水印研究。
- 克隆模型继承分布偏好，故水印能从「单条文本」升级到「模型级」举证。
- 水印强度（偏置 $\delta$、绿名单比例 $\gamma$）需权衡可检测性与文本质量。
- 水印应与监控日志、合同追责串联，形成「技术证据 + 法律通道」闭环。
- 司法是否采信以当地规则为准，技术信号是必要条件而非充分条件。
- 绿名单比例 $\gamma$ 过大会拖慢检测所需文本长度，过小则信号弱，需权衡。
- 检测应在服务端批量进行，避免把密钥或算法暴露给客户端。
- 对高价值模型建议启用多密钥轮换，降低单密钥泄露影响。
- 水印与输出扰动可叠加：扰动降可利用性，水印备溯源，职责互补。

- 对生成式水印建议定期审计检出率，防止密钥或算法被反向分析。

## 十、小结

水印防克隆的本质是「指纹举证」：它不阻止抽取，却让克隆无处遁形，是技术防御与法律追责之间的关键桥梁，应作为多层防御中的溯源层。
