# 模型抽取风险

> 对应 Krishna et al. 2020《Model Extraction and Adversarial Attacks on Model Extraction》、OWASP LLM Top 10，与 mlabonne/llm-course 安全章。

## 一、背景与挑战

训练一个强模型需要海量数据、算力与工程投入，这些构成了模型方的核心资产。然而当模型以 API 形式对外服务时，它的「能力」本身就暴露在了查询接口之后——任何能调用接口的人，理论上都能通过足够多的查询**把能力「读」出来**。

这就是模型抽取（model extraction）风险：攻击者不需要拿到权重，只需用低成本查询收集大量「输入-输出」对，再据此训练一个行为相近的替代模型（extraction attack / model stealing）。对闭源商业模型而言，这等于用极小代价完成了一次「能力盗版」，直接侵蚀其商业壁垒与知识产权。

## 二、核心原理

抽取攻击的本质是**用黑盒查询近似一个函数的输入-输出映射**。攻击者构造查询分布 $\mathcal{D}_{query}$（覆盖原模型决策边界），获得标注 $(x, f(x))$，再用监督学习训练替代模型 $\hat f$。当 $\hat f$ 在目标任务上与 $f$ 足够接近，攻击成功。

两类典型目标：其一是**功能克隆**，复刻整体能力（尤其小模型易被高仿，因容量刚好够学映射）；其二是**元信息窃取**，通过查询推断架构、训练数据成员、甚至参数（如通过精心构造的输入反推决策边界曲率）。后者危害更隐蔽。此外，输出分布的风格、格式、偏好也会泄露，成为溯源线索。

## 三、形式化与数学基础（含 LaTeX）

设原模型 $f:\mathcal{X}\to\mathcal{Y}$，攻击者用查询集 $\mathcal{S}=\{(x_i,f(x_i))\}_{i=1}^n$ 训练 $\hat f_\theta$。经验风险

$$
\mathcal{L}(\theta)=\frac{1}{n}\sum_{i=1}^n \ell\big(\hat f_\theta(x_i),\,f(x_i)\big)
$$

其泛化误差受 $n$ 与查询覆盖度支配：查询越接近真实数据分布、样本越多，$\hat f$ 保真度越高。攻击成本 $C_{attack}\approx n\cdot c_{query}+C_{train}$，通常远小于原模型训练成本 $C_{train}^{orig}$，这正是抽取「划算」的根源。

对参数窃取，设原模型在输入 $x$ 处输出对参数的梯度 $\nabla_\theta f$，攻击者可借多查询差分近似——这类攻击需要远多于功能克隆的查询，但理论可行，凸显开放接口的信息泄漏面。

## 四、代码实现（围栏配平）

```python
def extraction_attack(target_fn, query_gen, budget):
    pairs = []
    for _ in range(budget):                     # 攻击者查询预算
        x = query_gen.sample()                  # 覆盖决策边界
        y = target_fn(x)                        # 黑盒获取输出
        pairs.append((x, y))
    surrogate = train_model(pairs)              # 训练替代模型
    return surrogate

def is_suspect(ip, volume, limit):
    # 简单前置防御：异常高查询量即限速
    return volume(ip) > limit
```

## 五、与其他技术对比

- 与「数据泄露」相比：数据泄露暴露训练内容，抽取暴露模型能力，前者是隐私问题、后者是产权问题。
- 与「模型逆向」相比：逆向试图恢复权重，抽取只需复刻行为，门槛更低、更常见。
- 与「提示注入」相比：注入劫持单次行为，抽取复制整体能力，纵深不同。

## 六、常见误区

- 「闭源即安全」——API 仍可被查询盗用，闭源只提高门槛不消除风险。
- 「小模型不会被抽」——小模型反而更易被高保真克隆（容量匹配）。
- 「只要不公开权重就无虞」——行为克隆完全不需要权重。
- 「抽取只发生在 NLP」——视觉、表格、推荐等任何提供预测 API 的模型皆可被害。

## 七、与开源书·权威来源对应

- Krishna et al. 2020 系统定义模型抽取攻击、度量（保真度、查询量）与初步防御。
- OWASP LLM Top 10 将模型抽取列为重点风险面，建议监控、限流与输出控制。
- mlabonne/llm-course 安全章节把「防范能力被 API 盗取」列为部署必做项。
- 各主流服务商的 ToS 普遍设有禁止训练竞争模型的条款。

## 八、面试题

- 问：模型抽取如何发生？答：攻击者用黑盒查询收集大量输入-输出对，监督训练替代模型复刻原模型行为，无需接触权重。
- 问：为何小模型更易被高仿？答：替代模型容量与原模型匹配时，行为映射更容易被学准。
- 问：抽取与数据泄露区别？答：抽取复制能力、泄露的是行为，数据泄露暴露的是训练内容。
- 问：元信息窃取是什么？答：通过探测推断架构、训练数据成员或参数，比功能克隆更隐蔽危害更大。

## 九、演进与趋势

攻击从「功能克隆」演进到「元信息窃取 + 抗防御绕过」，防御则从单一限流走向「监控+扰动+水印+法律」多层体系。自动化抽取红队（见「抽取评测」）正成为安全发布标准环节，并把防护从被动拦截转为主动度量。

### 关键要点速查

- 模型抽取用黑盒查询复刻行为，不需要权重，闭源只提高门槛不消除风险。
- 小模型反而更易被高保真克隆，因替代模型容量与原模型匹配。
- 除功能克隆外，还需警惕元信息窃取（架构/数据成员/参数推断）。
- 输出分布的风格与格式也会泄露，成为后续溯源线索。
- 攻击成本远低于原模型训练成本，这是抽取「划算」的根本原因。
- 任何提供预测 API 的模型（NLP/视觉/表格/推荐）皆可成为目标。
- 防御需「监控+扰动+水印+法律」多层，单一手段均非银弹。
- 抽取红队评测应纳入安全发布门槛，持续度量防护有效性。
- 防御强度应与模型商业价值成正比，高价值模型才值得重防御投入。
- 公开 demo/免费层往往是攻击入口，需与付费层采用不同风控策略。
- 模型能力越独特、越难替代，被抽取的经济动机越强，风险越高。
- 建立「异常查询告警 + 取证留存 + 法律通道」的三段式响应机制。

- 把抽取风险纳入威胁建模，与安全、法务同步评估，而非仅作技术议题。

## 十、小结

模型抽取是能力的「盗版」：它用低成本查询复制高价值模型的行为，对闭源商业模型尤其致命，必须以多层防御与持续评测应对，并把技术防护与法律追责串联成闭环。
