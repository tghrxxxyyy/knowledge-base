# CUDA图与动态形状约束

> 对应图对形状/地址固定的要求（CUDA Graphs 限制文档）。

## 一、背景与挑战

LLM decode 步形状随 batch、序列长度变化；图要求节点形状与地址在捕获期固定，否则需多图或重捕获。

## 二、核心原理

常见做法：对若干 (batch, seq) 组合预捕获多个图（cuda graph pool）；或用 padding 到固定形状复用单图。地址须为 graph-registered 张量。

## 三、数学形式

图集合 $G=\{g(b,s): b\in B, s\in S\}$；请求映射到最近 $(b,s)$，否则回退 eager。

## 四、代码实现

```python
key = (batch, seq_len)
g = graph_pool.get(key, fallback_eager)
```

## 五、与其他对比

- 与 分页注意力与PagedAttention深入：分页 KV 地址变化，需 registered 块池配合图。
- 与 迭代级批处理调度深入：批变化触发图选择。

## 六、常见误区

- 形状组合爆炸致图内存爆炸。
- 重捕获频繁抵消收益。

## 八、面试题

- 图如何处理变长？答：预捕获多形状图或 padding 到固定形状复用。

## 九、演进

单图 → 图池 → 形状无关图（实验中）。

## 十、小结

图对形状敏感，工程上用图池/padding 折中动态性与开销。
