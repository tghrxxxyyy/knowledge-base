# CUDA图在推理引擎应用

> 对应 TensorRT-LLM、vLLM、Triton 的 graph 使用。

## 一、背景与挑战

生产引擎需在易变负载下稳定用图获益。

## 二、核心原理

vLLM 对 decode 步可用 `torch.cuda.graph` 封装前向；TensorRT-LLM 在 builder 内将网络编译为可重放执行；Triton 经 backend 配置启用 graph。

## 三、数学形式

启用图后单步 $L\approx o_{replay}+\sum t_{k}$；未用则含 $\sum o_{launch}$，差随算子数放大。

## 四、代码实现

```python
model = torch.compile(model, dynamic=False)  # 间接用图
```

## 五、与其他对比

- 与 张量核心与混合精度推理深入：图与 Tensor Core 叠加收益。
- 与 投机解码验证开销深入：验证步亦可用图封装。

## 六、常见误区

- 盲目对所有阶段用图（prefill 形状多变不宜）。
- 忽略图内存占用（多形状副本）。

## 八、面试题

- prefill 为何少用图？答：形状随 prompt 长度剧烈变化，多图成本高、回退频繁。

## 九、演进

手动图 → 编译封装 → 自适应阶段选择。

## 十、小结

图在 decode 稳态步收益最大，prefill 因形状多变需谨慎。
