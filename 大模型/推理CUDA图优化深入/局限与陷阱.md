# CUDA图局限与陷阱

> 对应 CUDA Graphs 已知限制与踩坑经验。

## 一、背景与挑战

图并非银弹，误用会致错或内存爆炸。

## 二、核心原理

限制：捕获期不能有条件分支/动态形状/同步；重放时仅更新 registered 输入；多图占显存；错误重放致静默错。

## 三、数学形式

图内存 $M_G=\sum_{g\in G}\sum_{k\in g}\text{workspace}(k)$；随形状组合线性增长。

## 四、代码实现

```python
# 反例：捕获中含 if -> 报错
with graph.capture():
    y = a if cond else b   # 非法动态控制流
```

## 五、与其他对比

- 与 推理延迟剖析与火焰图深入：图可消除启动峰，需火焰图验证。
- 与 迭代级批处理调度深入：调度触发图选择逻辑。

## 六、常见误区

- 认为图能处理动态控制流。
- 忽略图内存峰值致 OOM。

## 八、面试题

- CUDA Graph 主要限制？答：形状/地址固定、无动态分支，多图耗显存。

## 九、演进

全图 → 关键步图 → 混合 eager/graph。

## 十、小结

图收益明确但有约束，宜仅用于形状固定的稳态 decode 步。
