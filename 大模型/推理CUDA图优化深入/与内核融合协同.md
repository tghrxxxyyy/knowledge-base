# CUDA图与内核融合协同

> 对应 kernel fusion 与 graph 减少启动的叠加效应。

## 一、背景与挑战

即便融合后算子仍可能多，启动开销累计；图进一步消除下发。

## 二、核心原理

先通过融合把多个 elementwise/reduce 合成更少 kernel，再用图把剩余 kernel 录制重放，双重降低 CPU 端比例。

## 三、数学形式

未优化启动开销 $n\cdot o$；融合后 $m\cdot o\ (m<n)$；再图化后 $\approx o_{replay}$。

## 四、代码实现

```python
fused = fuse([layernorm, add, gelu])   # 少 kernel
graph.capture(fused)
```

## 五、与其他对比

- 与 Triton内核自动调优深入：Triton 易写融合内核，再用图封装。
- 与 张量核心与混合精度推理深入：融合提升算术密度。

## 六、常见误区

- 只融合不忘图，启动开销仍在。
- 过度融合致寄存器溢出反慢。

## 八、面试题

- 图与融合关系？答：融合减 kernel 数，图减启动次数，二者叠加降本。

## 九、演进

独立 kernel → 融合 → 图封装。

## 十、小结

图与融合是降低 CPU 启动占比的两把刀，常配合使用。
