# 消息与广播机制

> 对应 消息传递（message passing）与黑板（blackboard）架构。

## 一、背景与挑战

消息格式不统一会导致解析失败；路由不当会造成信息孤岛或冗余。

## 二、核心原理

消息建议为结构化对象（含 id、sender、receiver、type、payload、timestamp）。路由三模式：点对点（精确）、发布订阅（主题）、共享黑板（所有 agent 读同一状态）。黑板适合弱耦合协作。

## 三、数学形式

广播负载随 agent 数增长：

$$L_{broadcast} = O(N \cdot M_{size})$$

$N$ 为订阅者数，需限流或按主题过滤。

## 四、代码实现

```python
class Msg:
    def __init__(self, sender, recv, type, payload): ...
bus.publish(Msg(a, None, "plan", p), topic="design")
```

## 五、与其他对比

- 与 分层记忆架构 的“共享黑板”可类比。
- 与 智能体推理成本建模深入 共担广播通信成本。

## 六、常见误区

- 消息用自然语言无结构，下游难可靠解析。
- 无消息去重，同信息反复处理。

## 八、面试题

- 黑板与点对点各适用？答：弱耦合、共享状态用黑板；强契约、定向协作用点对点。

## 九、演进

自然语言 → 半结构化 → 强类型消息总线。

## 十、小结

统一消息结构与合理路由，是通信可靠与可观测的基础。
