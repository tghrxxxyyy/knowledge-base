# 协议握手与协商

> 对应 多 agent 协商（negotiation）与任务分配协议。

## 一、背景与挑战

当任务需多体联合完成，谁认领、如何交接、冲突如何仲裁，需要握手与协商机制。

## 二、核心原理

引入轻量协议：任务广播 → 各 agent 自报能力/成本 → 协调者按效用分配 → 执行中周期性同步进度。协商可用“提议- counter 提议”收敛到一致方案。

## 三、数学形式

分配使总效用最大：

$$A^* = \arg\max_{A} \sum_{i} u_i(a_i),\quad a_i\cap a_j=\emptyset$$

保证任务不重叠分配。

## 四、代码实现

```python
bids = {a: a.bid(task) for a in agents}
owner = min(bids, key=bids.get)
```

## 五、与其他对比

- 与 智能体推理成本建模深入 用成本做竞价。
- 与 降级与兜底 衔接任务无人认领时升级。

## 六、常见误区

- 协商无终止，反复 counter 提议。
- 忽略 agent 自报能力的可信度（可能虚报）。

## 八、面试题

- 如何防止任务重复认领？答：协调者集中分配并保证子集不相交。

## 九、演进

人工指定 → 竞价分配 → 可信协商。

## 十、小结

握手与协商把“谁做什么”自动化，避免冲突与真空。
