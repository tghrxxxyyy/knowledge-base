# 角色与协作拓扑

> 对应 Li et al., *CAMEL*, 2023 角色扮演；AutoGen 多 agent 编排。

## 一、背景与挑战

没有角色分工，多智能体易重复劳动或互相矛盾。需明确职责边界与协作结构。

## 二、核心原理

为 agent 设定系统提示定义专业角色（如规划者、执行者、批评者、检索员）。拓扑决定信息流：流水线（串行）、星型（中心协调）、网状（自由协商）。拓扑影响延迟与一致性。

## 三、数学形式

星型协调开销低于网状：

$$C_{mesh}=O(N^2),\quad C_{star}=O(N)$$

$N$ 为 agent 数，大规模宜用星型或分层。

## 四、代码实现

```python
roles = {"planner": ..., "executor": ..., "critic": ...}
flow = pipeline([roles["planner"], roles["executor"], roles["critic"]])
```

## 五、与其他对比

- 与 智能体轨迹自我进化深入 的角色专业化一致。
- 与 人机协作与人在环深入 把人设为协调者。

## 六、常见误区

- 角色提示过泛，实际退化成同质 agent。
- 网状拓扑 agent 数稍多即成本爆炸。

## 八、面试题

- 为何大规模宜星型？答：网状通信复杂度平方级，星型线性更易扩展。

## 九、演进

无角色 → 固定角色 → 动态角色再分配。

## 十、小结

角色与拓扑把“多人协作”结构化，是规模化的关键设计。
