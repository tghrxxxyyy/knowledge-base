# 调度与抢占

> 对应 vLLM 中基于块占用的抢占（Kwon et al., 2023）。

## 一、背景与挑战

显存有限，突发大量长序列会耗尽 KV 块；需策略决定谁继续、谁让路。

## 二、核心原理

两种抢占：①交换（swap）把被抢占序列 KV 换到 CPU 内存，恢复时换回；②重算（recompute）丢弃 KV 重新生成。选 swap 还是 recompute 取决于带宽与长度。

## 三、数学形式

交换代价 $\approx \frac{\text{kv\_bytes}}{\text{pcie\_bw}}$；重算代价 $\approx \ell\cdot t_{step}$；取较小者。

## 四、代码实现

```python
if no_free_block():
    victim = pick_preemptable()
    swap_out(victim) if bw_ok else recompute(victim)
```

## 五、与其他对比

- 与 权重内存分页与卸载深入 的交换机制同源（CPU↔GPU）。
- 与 分页注意力与PagedAttention深入 共用块表。

## 六、常见误区

- 频繁抢占致长尾延迟飙升。
- 误选重算（长序列时远贵于交换）。

## 八、面试题

- 何时选交换而非重算？答：序列长、重算 token 多时，交换由带宽决定更便宜。

## 九、演进

无抢占 → 交换 → 重算/交换自适应。

## 十、小结

抢占在显存压力下保证公平与可达性，swap/recompute 取舍靠代价模型。
