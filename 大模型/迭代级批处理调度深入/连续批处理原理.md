# 连续批处理原理

> 对应 Orca 迭代级调度与 vLLM 连续批处理实现。

## 一、背景与挑战

请求到达异步、长度随机，需在不重起 kernel 的前提下持续喂满 GPU。

## 二、核心原理

调度器维护运行中序列集合；每步选可达序列组成 batch 做单步 decode，更新 KV（配合分页追加块），完成则回收；新请求插入空闲槽。

## 三、数学形式

第 $t$ 步 batch 大小 $b_t=|\{s:\text{running}_t\}|$；平均利用率 $\bar u=\frac1T\sum_t b_t/B_{max}$。

## 四、代码实现

```python
running = scheduler.poll()
logits = model.step(running.tokens, running.kv)
```

## 五、与其他对比

- 与 分页注意力与PagedAttention深入：连续批依赖分页追加 KV。
- 与 投机解码验证开销深入 可叠加（批内各序列投机）。

## 六、常见误区

- 每步重组 batch 有调度开销，过小 batch 不划算。
- 忽略不同序列长度对步延迟的拉齐效应。

## 八、面试题

- 连续批与静态批差异？答：前者每步动态组批、完成即走，后者等最慢。

## 九、演进

请求级批 → 步级连续批 → 优先级抢占批。

## 十、小结

连续批处理把批的粒度下放到单步，是提升吞吐又不损延迟的核心手段。
