# 调度吞吐量模型

> 对应推理服务容量建模（与排队论相关）。

## 一、背景与挑战

需预估某硬件上能扛多少并发与 QPS，指导扩容与定价。

## 二、核心原理

把每请求视作消耗若干 decode step 的任务；系统容量受显存（并发上限）与算力（step 吞吐）双重约束，取较小瓶颈。

## 三、数学形式

算力上限 $C=\frac{\text{FLOPs}_{GPU}}{f_{step}}$（step 数/秒）；显存上限 $M_{max}/kv_{per\_seq}$；可达吞吐取 $\min$。

## 四、代码实现

```python
cap = min(gpu_flops/flops_per_step, mem_budget/kv_per_seq)
```

## 五、与其他对比

- 与 权重内存分页与卸载深入 中带宽模型耦合。
- 与 推理延迟剖析与火焰图深入 互验。

## 六、常见误区

- 仅按算力估算忽略显存并发上限。
- 忽略前缀缓存命中改变有效负载。
