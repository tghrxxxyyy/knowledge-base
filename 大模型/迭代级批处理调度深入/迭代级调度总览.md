# 迭代级调度总览

> 对应 Yu et al., *Orca: A Distributed Serving System for Transformer-Based Generative Models*, OSDI 2022（iteration-level scheduling）。

## 一、背景与挑战

LLM 生成逐 token，序列长短与完成时刻各异；以整批结束为单位的静态批处理使快序列空等慢序列，GPU 利用率低。

## 二、核心原理

迭代级调度在每个解码步（iteration）动态组批：完成的序列立即退出，新序列随时加入，使每步 batch 尽量满，故称 continuous/iteration-level batching。

## 三、数学形式

吞吐近似 $T\approx \frac{N_{tok}}{\sum_t \text{batch}_t\cdot t_{step}}$；动态组批使分母中 $\text{batch}_t$ 更平稳。

## 四、代码实现

```python
while pending:
    batch = scheduler.next_batch()
    step(batch)
```

## 五、与其他对比

- 与 分页注意力与PagedAttention深入 互补：分页管显存，调度管生命周期。
- 相对静态批处理显著提升设备利用率。

## 六、常见误区

- 误以为批越大越好（受显存/长度约束）。
- 忽视新序列加入对正在生成序列的干扰（需公平）。

## 八、面试题

- 迭代级批处理为何提效？答：完成即出、新请求即入，消除整批等待，GPU 更饱满。

## 九、演进

静态批 → 迭代级批 → 抢占式调度。

## 十、小结

迭代级调度以逐 token 动态组批最大化 GPU 利用率，是现代推理引擎基石。
