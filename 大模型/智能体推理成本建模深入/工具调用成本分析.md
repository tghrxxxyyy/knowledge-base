# 工具调用成本分析

> 对应 工具生态计费（API/数据库/检索）与 agent 成本拆解。

## 一、背景与挑战

工具的单价差异巨大：本地函数近乎免费，远程 API 按次或按量计费，检索按向量数计费。混合使用时成本结构复杂。

## 二、核心原理

把每个工具抽象为 (单价, 延迟, 可靠性) 三元组，在规划阶段预估“调用该工具的期望花费”，用成本感知的策略选择工具而非只选最优质量。

## 三、数学形式

工具 $a$ 的期望成本：

$$E[c(a)] = p_{fail}(a)\cdot c_{retry}(a) + c_{call}(a)$$

高失败率工具即使单价低，期望成本也可能更高。

## 四、代码实现

```python
def exp_cost(tool):
    return tool.price + tool.p_fail * tool.price * tool.max_retry
```

## 五、与其他对比

- 与 工具调用错误恢复深入 共享失败率与重试成本。
- 与 多智能体通信协议深入 共担跨进程调用开销。

## 六、常见误区

- 低估远程工具网络与排队延迟的隐性成本。
- 忽略批量/缓存可摊薄的单次费用。

## 八、面试题

- 为何高失败率工具期望成本更高？答：重试放大单价，需计入失败概率。

## 九、演进

忽略 → 单价计费 → 期望成本感知规划。

## 十、小结

工具成本需以期望视角评估，失败率与重试是隐藏的大头。
