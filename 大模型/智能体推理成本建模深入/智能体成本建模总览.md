# 智能体推理成本建模总览

> 对应 LLM 服务成本结构（token/调用/延迟）与 agent 经济分析。

## 一、背景与挑战

智能体一次任务可能触发数十次 LLM 调用、工具往返与反思循环，成本与延迟远超单次问答。不建模成本就无从优化。

## 二、核心原理

成本由三类叠加：生成 token 费用、工具调用费用、等待延迟的机会成本。需建立“每任务成本 = Σ(调用成本 + 工具成本)”的核算框架，并区分固定（prompt）与可变（生成）部分。

## 三、数学形式

单任务期望成本：

$$C = \sum_{i=1}^{N}\big(c_{llm}(o_i) + c_{tool}(a_i)\big) + \lambda\cdot T_{wait}$$

$N$ 为步数，$\lambda$ 为延迟折算系数。

## 四、代码实现

```python
def task_cost(trace):
    return sum(c_llm(step.out) + c_tool(step.act) for step in trace)
```

## 五、与其他对比

- 与 智能体轨迹自我进化深入 共担“步数 N”这一关键变量。
- 与 智能体可靠性与失败模式深入 共担失败重试的额外成本。

## 六、常见误区

- 只看生成 token 忽略系统 prompt 与往返工具费。
- 用平均成本掩盖长尾昂贵任务。

## 八、面试题

- 智能体成本为何高于普通问答？答：多步循环、反思、工具往返使调用次数与 token 量成倍放大。

## 九、演进

不计成本 → 单调用计费 → 全轨迹成本核算。

## 十、小结

成本建模是智能体规模化的财务前提，必须先可度量再谈优化。
