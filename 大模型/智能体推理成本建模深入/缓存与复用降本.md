# 缓存与复用降本

> 对应 LLM 缓存（语义缓存/前缀缓存）与 prompt 复用。

## 一、背景与挑战

智能体常重复问相似子问题（如“当前日期”“格式说明”）。每次都付推理费是巨大的浪费。

## 二、核心原理

对确定性/高相似查询启用语义缓存；对共享系统前缀启用前缀缓存（prefix cache）避免重复 prefill；对可复用子计划做模板化。命中缓存将成本降为近乎零。

## 三、数学形式

含缓存的期望成本：

$$C_{cache} = C - h\cdot C_{hit},\quad h = P(\text{cache hit})$$

$h$ 越高，节省越多，但需维护缓存一致性。

## 四、代码实现

```python
if (key := sem_cache.get(query)):
    return key
out = llm(query); sem_cache.set(query, out)
```

## 五、与其他对比

- 与 长程任务记忆压缩深入 共享“避免重复计算”动机。
- 与 智能体推理成本建模深入 总览互补。

## 六、常见误区

- 缓存未设 TTL 致返回过期答案。
- 语义缓存阈值过松，返回错误近似。

## 八、面试题

- 前缀缓存为什么能降本？答：复用已计算的 KV 前缀，省去重复 prefill 算力。

## 九、演进

无缓存 → 精确缓存 → 语义缓存+前缀缓存。

## 十、小结

缓存把“重复推理”变成“查表”，是性价比最高的降本手段。
