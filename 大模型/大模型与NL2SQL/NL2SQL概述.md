# NL2SQL 概述（大模型视角）

> 对应 text-to-SQL 研究与用户 NL-to-SQL 智能问数工作。本文聚焦大模型如何把自然语言转 SQL。

## 一、背景与挑战

业务用户用自然语言问数据，需精准转 SQL 查询。难点：多表 join、嵌套子查询、相对时间(最近几天/上个月/去年)、领域术语、权限与安全。

## 二、核心原理

大模型 + 数据库 schema 上下文 → 生成 SQL。关键链路：自然语言理解 → schema 检索 → SQL 生成 → 执行校验 → 结果返回。

## 三、关键要点

| 难点 | 解法 |
|------|------|
| schema 多表 | 检索相关表 |
| 相对时间 | 时间标准化 |
| 语法正确 | 执行校验 |

## 四、常见误区

- 直接把整库 schema 塞进 prompt(超长且噪声)。
- 忽略执行报错导致的生成 SQL 不可运行。

## 五、与开源书对应

- 经典数据集 Spider; 综述: Yu et al., *Spider*, 2018; 大模型方法 DIN-SQL, C3-SQL。
- 见本知识库「场景设计/NL2SQL」相关章节。

## 六、面试题

- 为何 NL2SQL 必须给模型 schema 上下文？

## 七、演进

规则/模板 → 微调(seq2seq) → 大模型 + RAG(schema 检索) + 自校验。

## 八、小结

NL2SQL 是大模型落地数据分析的核心场景，schema 检索与执行校验是关键。
