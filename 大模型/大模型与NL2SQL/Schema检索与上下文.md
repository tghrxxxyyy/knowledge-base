# Schema 检索与上下文构建

> NL2SQL 的工程核心。

## 一、背景与挑战

表多字段多，全量 schema 超长且干扰。需检索与问题相关的表/字段。

## 二、核心原理

用向量检索(字段注释/示例查询)召回相关表与字段，拼成精简 schema 上下文；对关系表/字典表做特别映射。

## 三、关键要点

- 字段注释质量决定召回。
- 字典表需映射为可查询条件。

## 四、常见误区

- 关系表/关联表未映射到 SQL 关键词，模型无从下手。

## 五、面试题

- 为何 NL2SQL 要先检索相关表而非用全库 schema？

## 六、小结

精简准确 schema 上下文是生成正确 SQL 的前提。
