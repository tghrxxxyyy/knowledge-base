# 07 部署与上线运维

> Agent 上线只是开始。本章讲容器化部署、私有化 GPU、灰度策略、SLA 保障、故障演练、合规审计、On-call。目标是：**稳定、可回滚、可扩展、合规、有人兜底**。

## 一、部署形态

### 1.1 容器化（K8s）

- Agent 服务、工具层、RAG 服务、网关全部容器化，统一编排。
- **无状态 vs 有状态**：Agent 编排服务尽量无状态（状态外置 DB/工作流引擎）；若用 LangGraph 持久化，状态在外部存储。
- **配置与密钥分离**：ConfigMap + Secret（Vault 注入），不进镜像。

### 1.2 私有化 GPU 部署

- **推理引擎**：vLLM / SGLang / TRT-LLM（高吞吐、连续批处理）。
- **编排**：K8s + 推理 Operator（KServe / Ray Serve / 自研），GPU 资源池化。
- **弹性**：流量的波峰（白天）用 HPA + GPU 共享（MIG/MPS）；闲时缩容省钱。
- **多模型共存**：一个 GPU 节点跑多个小模型，大模型独占，按 QPS 调度。

### 1.3 混合部署

```mermaid
flowchart LR
    EDGE[用户/内网] --> ING[入口网关]
    ING --> AGENT[Agent 服务 Pod(无状态)]
    AGENT --> GW[模型网关]
    GW --> PUB[公有云模型 API]
    GW --> PRI[私有化 vLLM(内网GPU)]
    AGENT --> RAG[RAG 服务]
    RAG --> VEC[(向量库)]
```

- 合规数据走私有化路径；非敏感走公有云，平衡成本与合规。

## 二、灰度与发布策略

| 策略 | 说明 | 适用 |
|------|------|------|
| 金丝雀 | 1–5% 流量先上新版，观测无异常再全量 | 模型/prompt 变更 |
| 影子 | 新旧并行跑，新版本只记录不生效 | 评估新模型效果 |
| 按租户灰度 | 先放内部/友好租户 | 多租户系统 |
| 蓝绿 | 两套环境切流，回滚快 | 大版本 |

> **Prompt/模型变更也要灰度**：模型会漂移，直接全量可能一夜之间质量崩塌。

---

## 三、SLA 与弹性

- **延迟 SLA**：对话类 p95 < 数秒；批量类放宽。超阈值告警。
- **可用性**：多副本 + 健康检查 + 自动重启；网关降级（模型不可用时返回友好提示而非 500）。
- **限流**：入口 + 模型网关双层限流，防单用户打爆。
- **背压**：下游慢（DB/业务系统）时 Agent 排队而非雪崩。

---

## 四、故障演练与韧性

- **混沌测试**：故意杀掉 Agent Pod / 模型网关超时 / 向量库宕机，验证降级与恢复。
- **循环/卡死演练**：注入坏输入让 Agent 循环，验证熔断。
- **数据恢复**：状态外置，演练从 checkpoint 恢复长任务。
- **回滚预案**：prompt/模型/代码任一层出问题，5 分钟内回滚。

---

## 五、监控与告警

- **业务指标**：任务成功率、用户满意度、转人工率。
- **技术指标**：p95 延迟、错误率、GPU 利用率、队列深度。
- **成本指标**：日/周成本、单任务成本、超预算告警。
- **安全指标**：越权尝试、注入拦截、异常工具调用。

---

## 六、合规与审计

- **数据驻留**：合规数据不出域（私有化 + 脱敏，见 04 篇）。
- **审计留痕**：所有运行可回放（见 05 篇 Run Record）。
- **模型备案**：国内生成式 AI 服务按规定备案/登记。
- **定期安全审计**：红队复测、依赖漏洞扫描（OWASP LLM01-10）、权限复核。

---

## 七、On-call 与运维手册

- **On-call 轮值**：Agent 故障有人接（模型供应商宕机、私有 GPU 故障、向量库慢）。
- **Runbook**：常见问题排查（延迟高→看哪层；答非所问→检索还是生成问题；成本突增→哪个租户）。
- **知识沉淀**：每次事故写复盘，更新 eval 用例防止复现。

- [ ] 评估集跑通、 baseline 达标（成功率/延迟）
- [ ] tracing/eval/护栏已埋

- [ ] HITL 高危操作审批流可用
- [ ] 成本看板 + 预算告警
- [ ] 灰度策略 + 回滚预案
- [ ] 故障演练（杀 Pod/超时/循环）通过
- [ ] 合规（数据出境/备案/审计）通过
- [ ] On-call + Runbook 就位
