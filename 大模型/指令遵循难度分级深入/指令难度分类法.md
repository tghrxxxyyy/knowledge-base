# 指令难度分类法

> 对应 dair-ai/Prompt-Engineering-Guide 与指令微调难度相关研究。

## 一、背景与挑战

指令数据质量参差，难度差异巨大。对指令分级可支撑课程式 SFT、数据配比与评测设计，但缺乏统一 taxonomy。

## 二、核心原理

按维度分解难度：(1) 任务复杂度(单步vs多步)；(2) 约束数量(格式/长度/风格)；(3) 领域专业度；(4) 推理深度。综合打分得到难度等级。

## 三、数学形式

设指令 $x$ 在 $M$ 个维度得分为 $s_m\in[0,1]$，难度：

$$
D(x) = \frac{1}{M}\sum_{m=1}^{M} w_m s_m
$$

权重 $w_m$ 可由下游表现回归得到，突出关键维度。

## 四、代码实现

```python
def difficulty(scores, weights):
    import torch
    return (torch.tensor(scores) * torch.tensor(weights)).sum() / sum(weights)
```

## 五、与其他对比

相比单一困惑度，多维分类更贴合“遵循难度”，能解释为何某些指令难。

## 六、常见误区

误区：难度=长度。长指令可能只是简单罗列，短指令可能含强约束。

## 八、面试题

- Q：指令难度由什么决定？答：任务复杂度、约束数、领域深度、推理步数。
- Q：为何多维而非长度？答：长度与遵循难度弱相关。
