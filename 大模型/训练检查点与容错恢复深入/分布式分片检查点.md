# 分布式分片检查点

> 对应 Rajbhandari 2020 ZeRO、Zhao 2023 FSDP 与 pytorch/pytorch torch.distributed.checkpoint。

## 一、背景与挑战
大模型的完整 `state_dict` 远超单卡显存，集中式保存需要先把所有分片聚合到一处，再统一写盘，过程慢且占内存。
聚合写盘还会形成带宽瓶颈：所有 rank 的数据都要经过少数节点，写入带宽被单点限制，保存时间随模型增大而线性上升。
核心矛盾是「并行训练、串行保存」：训练本身已是多卡并行，检查点却退回集中式，成为扩展性的短板。
分片检查点（sharded checkpoint）的思路是让每个 rank 直接写自己的分片文件，天然并行，避免全局聚合。
核心挑战在于：分片布局必须可描述、可恢复，加载时要让各 rank 只读自身分片即可续训，且要保证保存过程的一致性（避免写入中途的残损）。

## 二、核心原理
分片检查点按 FSDP/ZeRO 的既有分片方式落盘：每个 rank 把自己持有的参数分片与优化器状态分片写入独立文件，或按统一命名写入同一目录。
保存时不需要 `summon_full_params`，因此没有全参聚合的显存峰值，内存占用与单卡分片大小相关。
加载时各 rank 读取自身分片，直接恢复到训练态，无需全局广播或聚合，恢复时间大幅缩短。
分片布局由元数据描述：记录每个张量被切成多少片、每片归属哪个 rank、位于文件的哪个偏移，这一描述让分片可被重新组装。
为保证一致性，保存前需要同步（barrier），确保所有 rank 到达同一训练步；保存完成后写入完成标记，避免读到半成品。

## 三、形式化与数学基础
设模型参数总量为 $\Psi$，数据并行度为 $N$，优化器状态占 $K\Psi$（含梯度、动量、方差等），则分摊到单个 rank 的检查点大小约为：

$$ C_{rank} = \frac{(K+1)\Psi}{N} + \frac{\Psi}{N} = \frac{(K+2)\Psi}{N} $$

集中式保存要求单点承担 $\Psi$ 量级的聚合与写入，带宽瓶颈为单点带宽：

$$ T_{central} \approx \frac{(K+2)\Psi}{B_{single}} $$

分片保存把写入分散到 $N$ 个 rank，理想情况下耗时降为：

$$ T_{sharded} \approx \frac{(K+2)\Psi}{N \cdot B_{single}} $$

即并行度带来近似 $N$ 倍的写入加速。加载同理，各 rank 只读 $1/N$ 的数据。分片元数据 $\mathcal{M}$ 描述映射：

$$ \mathcal{M} = \{\, (\,tensor\_name,\; shard\_id,\; owner\_rank,\; offset,\; length\,) \,\} $$

## 四、代码实现
```python
import torch
import torch.distributed as dist
from torch.distributed.checkpoint import (
    FileSystemWriter,
    FileSystemReader,
    save_state_dict,
    load_state_dict,
)

# 训练中保存分片检查点：各 rank 并行写自身分片
state = {"model": model.state_dict(), "optim": optim.state_dict()}
dist.barrier()                       # 同步，确保处于同一步
save_state_dict(state, FileSystemWriter("ckpt_sharded"))

# 恢复：各 rank 只读自身分片
dist.barrier()
load_state_dict(state, FileSystemReader("ckpt_sharded"))
model.load_state_dict(state["model"])
optim.load_state_dict(state["optim"])

# 若需迁移到单卡推理，可先聚合为完整权重
# 或使用 DeepSpeed 的 zero_to_fp32 离线脚本
```

## 五、与其他技术对比
| 方式 | 写入并行度 | 显存峰值 | 恢复速度 | 跨框架兼容 |
|---|---|---|---|---|
| 集中式 `torch.save` | 1（聚合点） | 高 | 慢 | 高（标准格式） |
| FSDP/ZeRO 分片 | N | 低 | 快 | 低（格式特定） |
| DCP 分布式检查点 | N | 低 | 快 | 中（有规范） |
| safetensors 分片 | N | 低 | 快 | 高 |
| DeepSpeed 离线重组 | 1（离线） | 中 | 慢 | 高（产物标准） |

## 六、常见误区
- 认为分片检查点可直接推理：需重组或用框架的分片读取 API，标准加载器无法直接消费。
- 认为分片格式跨框架通用：FSDP、DeepSpeed 的分片布局不互认，迁移需先重组。
- 保存不加 barrier：可能写入处于不同训练步的状态，导致恢复后不一致或残损。
- 忽视元数据：分片若无清晰描述，后续无法正确重组，等同于数据损坏。
- 认为分片必然更快：若存储本身是瓶颈或 rank 数很少，收益有限，需实测。

## 八、面试题
1. 问：分片检查点的优势是什么？
   答：各 rank 并行写自身分片，避免聚合瓶颈，显存占用低、恢复快。
2. 问：如何把分片检查点迁移到单卡？
   答：重组为标准 state_dict，或用 DeepSpeed 的 `zero_to_fp32.py` 离线转换。
3. 问：为什么保存前要 barrier？
   答：确保所有 rank 处于同一步，避免写入不一致或残损的检查点。
4. 问：分片布局靠什么描述？
   答：元数据记录张量的分片数、归属 rank、偏移与长度，据此可重组。
5. 问：分片检查点能否跨框架直接使用？
   答：不能，FSDP 与 DeepSpeed 的分片格式不互认，需先重组为标准格式。

- 具体实现与能力以官方最新文档为准。

## 十、小结
分片检查点是大规模训练的存储基石：它用并行写入替代集中聚合，把写入带宽瓶颈分散到各 rank，并让恢复只需读取本地分片。其代价是格式特定、需要重组才能用于推理，且依赖 barrier 与元数据保证一致性。
