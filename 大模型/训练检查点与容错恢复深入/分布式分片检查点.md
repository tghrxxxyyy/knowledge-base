# 分布式分片检查点

> 对应 pytorch/pytorch torch.distributed.checkpoint 与 Zhao 2023 FSDP。

## 一、背景与挑战
大模型单卡放不下完整 state_dict，集中保存需聚合且带宽瓶颈。分片检查点让每 rank 直接写本地分片。

## 二、核心原理
按 FSDP/ZeRO 的分片方式，各 rank 将其参数/优化器分片写入独立文件(或同目录分片)。加载时各 rank 仅读自身分片，无需全局聚合。

## 三、形式化与数学基础
单 rank 检查点大小：
$ C_{\\mathrm{rank}} = (K+1)\\Psi/N + \\Psi/N $，
总写入带宽需求降为 $1/N$ 单点，聚合保存则为 $\\Psi$ 单点瓶颈。

## 四、代码实现
```python
import torch
from torch.distributed.checkpoint import (
    FileSystemWriter, FileSystemReader, save_state_dict, load_state_dict)
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP

state = {"model": model, "optim": opt}
torch.distributed.barrier()
save_state_dict(state, FileSystemWriter("ckpt_sharded"))
```

## 五、与其他技术对比
集中式 `torch.save(state_dict)` 需 `summon_full_params` 聚合，慢且占显存；分片式并行 IO 省时。DeepSpeed 用 `zero_to_fp32.py` 离线重组。

## 六、常见误区
误区一：分片检查点可直接推理——需重组或框架读取分片。误区二：分片格式跨框架通用——FSDP/DeepSpeed 不互认。误区三：保存不需 barrier，实际需同步避免残损。

## 七、与开源书/权威来源对应
pytorch/pytorch `torch.distributed.checkpoint`；Zhao 2023 FSDP 分片保存。

## 八、面试题
问：分片检查点优势？答：并行 IO、无需聚合、省显存。问：如何迁移到单卡？答：重组 state_dict 或用 `zero_to_fp32.py`。

## 九、演进与趋势
异步分片保存、与对象存储直连；DTensor 统一分片描述。

## 十、小结
分片检查点是大规模训练的存储基石，避免聚合瓶颈并兼容弹性恢复。
