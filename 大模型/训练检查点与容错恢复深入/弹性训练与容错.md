# 弹性训练与容错

> 对应 pytorch/pytorch Elastic (torchelastic) 与 microsoft/DeepSpeed 容错。

## 一、背景与挑战
千卡训练跨度长，节点故障、抢占难免。弹性训练允许成员动态增减并从检查点恢复，而非整体重跑。

## 二、核心原理
用 etcd/rendezvous 管理成员集合，worker 失效后其余继续或等待替换；恢复时各 rank 载入最近分片检查点，优化器状态与数据采样位置复位。

## 三、形式化与数学基础
容错恢复点：
$ t_{\\mathrm{recover}} = t_{\\mathrm{checkpoint}} + t_{\\mathrm{load}} $，
期望浪费步数 $E = f \\cdot \\Delta t_{\\mathrm{ckpt}}$，其中 $f$ 故障率、$\\Delta t$ 检查点间隔，需权衡频率。

## 五、与其他技术对比
静态训练故障即全停；Kubernetes 重调度配合弹性 rendezvous 实现自动恢复。DeepSpeed 亦支持弹性 ZeRO。

## 六、常见误区
误区一：弹性无需检查点——无检查点无法恢复状态。误区二：任意成员变动安全——数据并行 rank 数变需重分片。误区三：恢复零丢失，实际丢失间隔内步数。

## 七、与开源书/权威来源对应
pytorch/pytorch torchelastic；microsoft/DeepSpeed elastic；facebookresearch/llama 容错实践。

## 八、面试题
问：弹性训练关键？答：rendezvous + 分片检查点。问：恢复代价？答：检查点间隔内的步数损失。

## 九、演进与趋势
与抢占式实例结合降成本；优雅退避与快速重连。

## 十、小结
弹性训练把"故障=重跑"变为"故障=局部恢复"，是长周期大规模训练必需。
