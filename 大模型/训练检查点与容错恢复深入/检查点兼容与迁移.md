# 检查点兼容与迁移

> 对应 huggingface/transformers 格式 与 pytorch/pytorch 版本兼容。

## 一、背景与挑战
框架/版本升级、并行策略变更会使旧检查点无法直接加载，需处理 key 映射、张量形状与 dtype 差异。

## 二、核心原理
加载时做 key 对齐(如 `module.` 前缀)、形状重映射(分片↔完整)、dtype 转换(fp16↔fp32)。跨框架需先重组为标准 state_dict 再映射。

## 三、形式化与数学基础
映射函数：
$ W_{\\mathrm{new}} = \\phi_{\\mathrm{key}}\\big(\\psi_{\\mathrm{shape}}(W_{\\mathrm{old}})\\big) $，
若参数量变化(如扩隐维)则需切片或初始化扩展部分，无法自动保证语义。

## 四、代码实现
```python
sd_new, sd_old = model.state_dict(), torch.load("old.bin")
missing = set(sd_new) - set(sd_old)
for k in sd_new:
    if k in sd_old and sd_new[k].shape == sd_old[k].shape:
        sd_new[k].copy_(sd_old[k].to(sd_new[k].dtype))
model.load_state_dict(sd_new, strict=False)
```

## 五、与其他技术对比
safetensors 提供元数据加速校验；DeepSpeed/FSDP 分片需先重组再迁移。transformers 用 `config` 约束结构。

## 六、常见误区
误区一：strict=True 万能——结构微差即报错，应查 missing/unexpected。误区二：dtype 不影响——fp16 累加误差需注意。误区三：分片可直接映射，需重组。

## 七、与开源书/权威来源对应
huggingface/transformers `load_state_dict`；pytorch/pytorch 版本迁移指南。

## 八、面试题
问：加载报 shape 不符？答：检查分片/完整差异或结构变更。问：如何跨框架？答：重组为标准 state_dict 再映射 key。

## 九、演进与趋势
结构化检查点格式自带 schema 校验；自动迁移工具。

## 十、小结
检查点兼容靠 key/shape/dtype 三层映射，标准化格式能显著降低迁移成本。
