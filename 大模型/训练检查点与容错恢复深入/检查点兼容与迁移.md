# 检查点兼容与迁移

> 对应 huggingface/transformers 权重加载、pytorch/pytorch 版本迁移指南与 safetensors 格式规范。

## 一、背景与挑战
训练框架、版本、并行策略会不断演进。旧检查点在新环境加载时，常因 key 命名、张量形状、数据类型不同而失败或静默错位。
最常见的差异有三类：命名差异（如多出 `module.` 前缀、层命名规则变化）、形状差异（分片与完整、隐藏维扩展）、dtype 差异（fp16 与 fp32 混用）。
跨框架迁移更复杂：FSDP、DeepSpeed 的分片布局互不认可，通常需要先重组为标准的、与框架无关的 `state_dict`。
核心挑战是：许多不匹配不会报错而是静默复制错位，导致模型「能加载但效果异常」，排查成本极高。
因此兼容与迁移需要显式校验：对比 key 集合、检查形状与 dtype、抽样验证数值，而不是盲目 `strict=True`。

## 二、核心原理
兼容迁移的核心是三层映射：key → shape → dtype。key 映射解决命名差异，shape 映射解决布局与结构差异，dtype 映射解决精度差异。
key 映射常用规则化处理：去除或添加前缀、替换命名片段、按配置重建名称。也可以在加载时用 `strict=False` 暴露 missing 与 unexpected 键，再逐项处理。
shape 映射处理分片与完整的转换，以及结构调整（如隐藏维扩展）。扩展部分无法从旧权重推导，需要显式初始化并接受语义损失。
dtype 映射处理 fp16/bf16/fp32 互转，注意累加误差与溢出风险，尤其在低精度下做大范围转置或重排时要小心。
跨框架迁移的标准路径是：旧格式 → 标准 state_dict → 目标框架。标准化中间态是可复用、可验证的关键。

## 三、形式化与数学基础
设旧权重为 $W_{old}$、新权重为 $W_{new}$，映射可分解为 key 与 shape 两个算子：

$$ W_{new} = \phi_{key}\big( \psi_{shape}(W_{old}) \big) $$

当形状不一致时，形状算子是带裁剪的投影。设旧形状为 $s_{old}$、新形状为 $s_{new}$，取交集切片：

$$ \psi_{shape}(W) = W[\,0:\min(s_{old}^{(i)}, s_{new}^{(i)}) \text{ 逐维} \,] $$

未覆盖的新增区域 $W_{new} \setminus \psi_{shape}(W_{old})$ 需初始化（随机或零），其语义无法从旧检查点恢复。dtype 转换带来的量化误差可粗略表示为：

$$ \epsilon_{quant} \le \frac{\Delta}{2},\qquad \Delta = \frac{2^{e_{\max}}}{2^{m}} $$

$m$ 为尾数位、$e_{\max}$ 为指数范围，说明低精度尾数少、精度损失不可避免，需在迁移时评估是否可接受。

## 四、代码实现
```python
import torch

def migrate_weights(model, old_path, prefix_map=None):
    sd_new = model.state_dict()
    sd_old = torch.load(old_path, map_location="cpu")
    prefix_map = prefix_map or {"module.": "", "model.": ""}

    # key 映射：按规则重命名旧权重
    renamed = {}
    for k, v in sd_old.items():
        nk = k
        for old, new in prefix_map.items():
            if nk.startswith(old):
                nk = new + nk[len(old):]
        renamed[nk] = v

    loaded, skipped = 0, []
    for k, target in sd_new.items():
        src = renamed.get(k)
        if src is None:
            skipped.append(k)          # 新结构，保持初始化
            continue
        if src.shape == target.shape:
            target.copy_(src.to(target.dtype))
            loaded += 1
        else:
            # 形状不同：按交集切片，剩余部分保持初始化
            slices = tuple(slice(0, min(a, b))
                           for a, b in zip(src.shape, target.shape))
            target[slices].copy_(src[slices].to(target.dtype))
            skipped.append(k)

    missing, unexpected = model.load_state_dict(sd_new, strict=False)
    return loaded, skipped, missing, unexpected
```

## 五、与其他技术对比
| 格式/机制 | key 对齐 | shape 灵活性 | dtype | 适用场景 |
|---|---|---|---|---|
| PyTorch `.bin` | 名称匹配 | 分片需重组 | 支持转换 | 通用 |
| safetensors | 名称匹配 | 分片友好 | 支持转换 | 高效、安全加载 |
| FSDP 分片 | 需 DTensor 描述 | 支持重分片 | 支持 | 同框架续训 |
| DeepSpeed ZeRO | 需离线重组 | 需重组 | 支持 | 同框架续训 |
| transformers | 依 config 映射 | 有转换逻辑 | 支持 | 跨实现迁移 |

## 六、常见误区
- 认为 `strict=True` 万能：结构微差即报错，应先用 `strict=False` 查 missing/unexpected。
- 认为 dtype 不影响结果：fp16 累加误差在长序列或大张量上不可忽略，需评估精度损失。
- 认为分片可直接映射：分片布局与标准 state_dict 不同，必须先重组。
- 忽视前缀差异：`module.`、`model.` 等前缀不一致是最常见的加载失败原因。
- 静默容忍形状不匹配：若不显式检查，可能只加载了部分权重却毫无提示。

## 八、面试题
1. 问：加载报 shape 不符怎么办？
   答：检查是分片与完整之差还是结构变更，按交集切片并初始化新增部分。
2. 问：如何跨框架迁移检查点？
   答：先重组为标准 state_dict，再做 key/shape/dtype 三层映射。
3. 问：`strict=False` 的风险是什么？
   答：会静默跳过不匹配的键，必须显式检查 missing 与 unexpected 列表。
4. 问：dtype 转换有何注意点？
   答：低精度尾数少、可能溢出，转换后应抽样验证数值与下游指标。
5. 问：前缀差异为何常见？
   答：DDP/FSDP 包装会加 `module.` 前缀，不同实现的层命名规则也可能不同。

## 十、小结
检查点兼容靠 key、shape、dtype 三层映射：key 解决命名、shape 解决布局与结构、dtype 解决精度。跨框架迁移应先重组为标准中间态。核心原则是显式校验而非盲目 `strict`，并通过抽样数值与下游指标验证迁移正确性，因为最危险的情况是「加载成功但权重错位」。
