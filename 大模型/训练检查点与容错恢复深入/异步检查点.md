# 异步检查点

> 对应 pytorch/pytorch 异步保存 与 facebookresearch/llama 训练经验。

## 一、背景与挑战
同步保存大模型检查点会冻结训练数十分钟，影响吞吐与迭代效率。异步检查点将序列化与写盘移出训练流。

## 二、核心原理
在训练步末尾复制当前分片状态到临时缓冲(或利用 CUDA 拷贝引擎)，立即继续训练；后台线程/进程完成序列化与落盘，必要时加 barrier 确保一致性。

## 三、形式化与数学基础
同步保存墙钟 $T_{\\mathrm{sync}} = C/R_{\\mathrm{io}}$ 完全阻塞；异步仅阻塞拷贝 $T_{\\mathrm{copy}}\\ll T_{\\mathrm{sync}}$，额外显存 $+\\Psi/N$ 缓冲：
$ \\Delta M \\approx \\Psi/N $。

## 四、代码实现
```python
import torch
# 概念：拷贝后异步写
snapshot = {k: v.detach().clone() for k, v in model.state_dict().items()}
# 后台线程写盘，训练继续
background_writer.enqueue(snapshot)
```

## 五、与其他技术对比
同步保存简单但拖慢；异步需额外缓冲与一致性保障。DeepSpeed/FSDP 均支持后台保存。

## 六、常见误区
误区一：异步零成本——需额外显存与 CPU 线程。误区二：可随时读——落盘未完成时文件不完整。误区三：无需 barrier，实际需确认写完再标记 latest。

## 七、与开源书/权威来源对应
pytorch/pytorch `torch.distributed.checkpoint` 异步接口；facebookresearch/llama 训练说明。

## 八、面试题
问：异步检查点代价？答：额外缓冲显存与后台 IO。问：一致性如何保？答：拷贝后标记完成，barrier 同步。

## 九、演进与趋势
与 NVMe 直写、增量检查点结合，进一步降阻塞。

## 十、小结
异步检查点以少量缓冲换取训练连续性，是长任务工程的标配。
