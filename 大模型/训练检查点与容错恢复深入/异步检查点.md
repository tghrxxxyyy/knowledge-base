# 异步检查点

> 对应 pytorch/pytorch torch.distributed.checkpoint 异步接口、Eisenman 2022 Check-N-Run 与 facebookresearch/llama 训练经验。

## 一、背景与挑战
大模型检查点体积巨大，同步保存会把训练完全冻结：序列化与写盘期间 GPU 空闲，保存耗时可达数分钟甚至数十分钟。
在长时间训练中，检查点频率不低，累计阻塞时间可观，直接拖低有效吞吐与迭代速度。
核心矛盾是「状态一致」与「训练连续」不可兼得：要保证检查点反映某一步的一致状态，就需在那一刻冻结；要训练不停，就必须在后台完成写盘。
异步检查点（asynchronous checkpointing）的思路正是把耗时部分移出训练主流程：训练步末尾快速快照，后续序列化与落盘交给后台。
挑战在于：快照本身需要复制状态（占额外显存），后台写盘与后续训练存在资源争用，且必须保证「未写完的检查点不可被视为有效」。

## 二、核心原理
异步检查点的基本流程分三步：快照、入队、后台落盘。在需要保存的训练步末尾，把当前分片状态复制到临时缓冲，随后立即继续训练。
复制可利用 GPU 到 CPU 的拷贝引擎或设备内拷贝，时间远小于完整序列化与写盘，因此主流程阻塞被大幅缩短。
后台线程或进程负责把缓冲序列化并写入存储；写完后写入完成标记，只有带完成标记的检查点才允许被恢复使用。
一致性由「快照时刻」保证：快照在 barrier 后执行，确保所有 rank 处于同步状态；之后的训练更新不影响已快照的缓冲。
资源争用需要管理：后台写盘会消耗 CPU、内存带宽与存储带宽，可能轻微拖慢训练，需限制并发或错峰。

## 三、形式化与数学基础
同步保存的墙钟时间由状态大小 $C$ 与写入速率 $R_{io}$ 决定，这段时间训练完全阻塞：

$$ T_{sync} = \frac{C}{R_{io}} $$

异步保存只阻塞快照拷贝，拷贝速率远高于落盘速率，因此：

$$ T_{block}^{async} = \frac{C}{R_{copy}} \ll \frac{C}{R_{io}} = T_{sync} $$

代价是额外显存/内存缓冲，大小约等于单 rank 分片：

$$ \Delta M \approx \frac{(K+1)\Psi}{N} $$

若后台写盘与训练并行，但共享存储带宽，则训练实际可用带宽下降，可用争用系数 $\alpha \in (0,1)$ 描述：

$$ T_{train}^{eff} = T_{train} \cdot \left(1 + \alpha \cdot \mathbb{1}[\text{writing}]\right) $$

稳态下，异步相比同步的净收益为正的条件是阻塞节省大于争用损失：

$$ \left(T_{sync} - T_{block}^{async}\right) > \alpha \cdot T_{train} \cdot p_{write} $$

其中 $p_{write}$ 为写盘时间占比。

## 四、代码实现
```python
import threading

class AsyncCheckpointer:
    # 以少量缓冲换取训练连续性
    def __init__(self, writer):
        self.writer, self.queue = writer, []
        self.lock = threading.Lock()
        threading.Thread(target=self._loop, daemon=True).start()

    def enqueue(self, model, optim, step):
        # 快照：设备到主机拷贝，随后训练可继续
        snap = {"model": {k: v.detach().to("cpu", copy=True)
                          for k, v in model.state_dict().items()},
                "optim": {k: v.detach().to("cpu", copy=True)
                          for k, v in optim.state_dict().items()},
                "step": step}
        with self.lock:
            self.queue.append(snap)

    def _loop(self):
        while True:
            with self.lock:
                item = self.queue.pop(0) if self.queue else None
            if item is not None:
                self.writer.save(item)                   # 后台落盘
                self.writer.mark_complete(item["step"])  # 写完成标记

# 训练循环：快照后立即继续，不等待落盘
ckpt = AsyncCheckpointer(writer)
for step, batch in enumerate(loader):
    if step % ckpt_interval == 0:
        ckpt.enqueue(model, optim, step)
    train_step(model, optim, batch)
```

## 五、与其他技术对比
| 方式 | 训练阻塞 | 额外内存 | 一致性风险 | 适用 |
|---|---|---|---|---|
| 同步保存 | 高（全量写盘） | 无 | 低 | 小模型、低频 |
| 异步保存 | 低（仅拷贝） | 一份分片 | 需完成标记 | 大模型、高频 |
| 增量检查点 | 低（只写差异） | 中 | 需基线与日志 | 变化缓慢参数 |
| 分片+异步 | 低 | 一份分片 | 需 barrier | 大规模训练 |
| 存储直写 | 低 | 低 | 依赖硬件 | 高性能存储 |

## 六、常见误区
- 认为异步零成本：需要额外显存与后台线程，且可能与训练争用资源。
- 认为随时可读：落盘未完成时文件不完整，必须等完成标记。
- 忽略 barrier：快照前不同步会导致各 rank 状态不一致，检查点不可用。
- 忽视缓冲生命周期：快照缓冲若过早释放或被覆盖，会导致写到错误状态。
- 不限制并发写盘：多个后台写任务同时进行会挤占带宽，反而拖慢训练。

## 八、面试题
1. 问：异步检查点的代价是什么？
   答：额外一份分片的缓冲内存与后台 IO 线程，以及潜在的资源争用。
2. 问：一致性如何保证？
   答：快照前 barrier 同步，快照后写完成标记，只有完整检查点可被使用。
3. 问：为什么快照要拷贝而不是直接引用？
   答：后续训练会原地更新参数，直接引用会导致写到被改动的状态。
4. 问：什么时候异步收益最大？
   答：模型大、保存频繁、存储写盘慢时，阻塞节省远超争用损失。
5. 问：如何降低争用？
   答：限制后台并发、错峰写盘、使用独立存储通道或更高带宽介质。

## 十、小结
异步检查点以少量缓冲换取训练连续性：训练步末尾快速快照、后台序列化落盘、完成标记保证一致性。其收益来自「拷贝远快于写盘」，代价是额外内存与资源争用。正确处理 barrier、缓冲生命周期与并发控制，是异步检查点可靠工作的前提。
