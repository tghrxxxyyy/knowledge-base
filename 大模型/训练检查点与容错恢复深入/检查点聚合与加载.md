# 检查点聚合与加载

> 对应 microsoft/DeepSpeed zero_to_fp32 与 pytorch/pytorch state_dict。

## 一、背景与挑战
分片检查点利于保存但不便推理/微调。需将其重组为完整权重(通常 fp16)供 `from_pretrained` 使用。

## 二、核心原理
加载所有分片，按参数名还原全局张量布局，拼接成完整 state_dict。DeepSpeed 提供 `zero_to_fp32.py`，FSDP 用 `summon_full_params` 或 `load_sharded_state_dict` 读取。

## 三、形式化与数学基础
重组：
$ W = \\mathrm{concat}(\\{W^{(r)}\\}_{r=1}^{N}, \\mathrm{axis}=\\mathrm{shard}) $，
优化器状态可丢弃，仅留 fp16/fp32 参数用于推理，体积由 $13\\Psi$ 降至 $2\\Psi$。

## 四、代码实现
```python
# DeepSpeed 重组示例
from deepspeed.utils.zero_to_fp32 import convert_zero_checkpoint_to_fp32_state_dict
convert_zero_checkpoint_to_fp32_state_dict(
    "ckpt_z3", "pytorch_model.bin", tag="latest")
# 之后可用 transformers 直接加载
```

## 五、与其他技术对比
FSDP 用 `summon_full_params` 在线聚合；DeepSpeed 离线脚本更灵活。两者产物均为标准 state_dict。

## 六、常见误区
误区一：重组保留优化器状态——推理不需要，通常只取参数。误区二：分片可直接 `load_state_dict`——需先重组或读分片 API。误区三：名称对齐随意，实际 key 必须匹配。

## 七、与开源书/权威来源对应
microsoft/DeepSpeed `zero_to_fp32.py`；pytorch/pytorch `FSDP.summon_full_params`。

## 八、面试题
问：如何得推理权重？答：重组分片为 fp16 state_dict。问：优化器状态去哪？答：丢弃，仅留参数。

## 九、演进与趋势
格式标准化(如 safetensors)加速加载；分片直读避免重组步骤。

## 十、小结
聚合检查点是分片保存与单卡使用间的桥梁，工具链成熟但须注意格式兼容。
