# 故障检测与重启策略

> 对应 pytorch/pytorch 健康检查 与 facebookresearch/llama 工程经验。

## 一、背景与挑战
硬件静默错误(如 GPU ECC、NCCL 超时报错)需被快速检测并触发可控重启，否则浪费大量计算。

## 二、核心原理
心跳/集合超时监控：某 rank 在 all-reduce 超时即判定故障，协调器中断作业、释放资源并重启成员，从最近检查点恢复。分级重启(同节点换卡 vs 跨节点)降低代价。

## 三、形式化与数学基础
检测延迟 $t_d$ 与恢复 $t_r$ 决定浪费：
$ W = t_d + t_r + \\Delta_{\\mathrm{ckpt}} $，
目标最小化 $W$ 同时避免误杀(偶发超时)。阈值需高于正常抖动。

## 四、代码实现
```python
import datetime, torch.distributed as dist
try:
    dist.all_reduce(tensor, timeout=datetime.timedelta(seconds=300))
except dist.DistTimeoutError:
    trigger_restart()   # 通知协调器重启
```

## 五、与其他技术对比
应用层心跳轻量但晚；NCCL 看门狗直接捕获通信挂死。云调度器负责节点级重启。

## 六、常见误区
误区一：超时即永久故障——可能是瞬时网络抖动，需重试。误区二：检测越灵敏越好——易误杀。误区三：重启无需清状态，实际须释放 NCCL 资源。

## 七、与开源书/权威来源对应
pytorch/pytorch 集合超时；facebookresearch/llama 长训练容错；microsoft/DeepSpeed。

## 八、面试题
问：如何检测挂死？答：集合通信超时 + 看门狗。问：重启策略？答：分级重启 + 最近检查点。

## 九、演进与趋势
预测性维护(提前迁移任务)；自愈调度器自动换卡。

## 十、小结
故障检测与重启策略决定大规模训练的可用性，须在灵敏与稳健间平衡。
