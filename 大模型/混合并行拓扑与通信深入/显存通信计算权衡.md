# 显存通信计算权衡

> 对应 Hoffmann 2022 (Chinchilla) 与 Narayanan 2021 资源建模。

## 一、背景与挑战
并行策略本质是在显存上限、通信带宽、算力三者间寻优。不同维度对三者敏感度不同，需联合建模。

## 二、核心原理
TP 增通信降显存但几乎不降算力利用率；PP 降通信增气泡损算力；ZeRO/DP 降显存增跨节点通信。目标是在给定集群下最大化 MFU(模型算力利用率)。

## 三、形式化与数学基础
MFU 近似：
$ \\mathrm{MFU} = \\frac{6\\Psi B / T}{P_{\\mathrm{peak}} \\cdot N} $，
其中 $B$ 令牌数、$T$ 墙钟、$P$ 单卡算力。通信与气泡通过 $T$ 进入，显存通过可训练最大 $\\Psi$ 约束。

## 四、代码实现
```python
# 概念：对比两种并行配置 MFU
def mfu(psi, B, T_sec, P_peak, N):
    return 6 * psi * B / T_sec / (P_peak * N)
# 选使 MFU 高且显存可行的 (t,p,d)
```

## 五、与其他技术对比
Chinchilla 给定计算预算下最优参数量与数据量，约束 $\\Psi$ 反过来决定所需并行度。通信拓扑决定达到该 $\\Psi$ 的代价。

## 六、常见误区
误区一：并行度越高越快——通信/气泡使 MFU 下降。误区二：只看显存——忽视通信成新瓶颈。误区三：Chinchilla 只管规模，实际与并行拓扑联动。

## 七、与开源书/权威来源对应
Hoffmann 2022 Chinchilla；Kaplan 2020 scaling laws；Narayanan 2021 资源模型。

## 八、面试题
问：MFU 受何影响？答：通信、气泡、显存限制的最大批。问：三权衡核心？答：显存-通信-算力三角。

## 十、小结
混合并行是资源约束下的多目标优化，建模显存/通信/算力才能选对拓扑。
