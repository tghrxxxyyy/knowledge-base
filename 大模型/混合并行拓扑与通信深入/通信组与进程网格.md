# 通信组与进程网格

> 对应 pytorch/pytorch ProcessGroup 与 microsoft/DeepSpeed 通信组。

## 一、背景与挑战
3D 并行需多种独立集合通信(TP 组内 all-reduce、PP 段间 p2p、DP 组 reduce-scatter)。必须用进程组隔离避免串扰。

## 二、核心原理
按设备编号构造不相交的通信组：TP 组含同节点连续 $t$ 卡，PP 组含跨节点同列 $p$ 卡，DP 组含剩余维 $d$ 卡。每个算子绑定对应组。

## 三、形式化与数学基础
进程编号分解：
$ r = r_{dp}\\cdot (t\\cdot p) + r_{pp}\\cdot t + r_{tp} $，
各维组大小分别为 $d,p,t$，满足 $\\sum$ 划分且组间无重叠，保证集合通信互不干扰。

## 四、代码实现
```python
import torch.distributed as dist
tp_group = dist.new_group(ranks_in_tp)
pp_group = dist.new_group(ranks_in_pp)
dp_group = dist.new_group(ranks_in_dp)
# TP 通信
dist.all_reduce(buf, group=tp_group)
# DP 通信
dist.reduce_scatter(buf, group=dp_group)
```

## 五、与其他技术对比
Megatron 用类似网格但通信在框架内隐式管理；DeepSpeed 通过配置自动建组。手动建组适合自定义调度。

## 六、常见误区
误区一：共享默认组做所有通信——会打乱跨组语义。误区二：组大小随意——须整除且覆盖全 rank。误区三：组创建无序，实际需所有 rank 同步创建。

## 七、与开源书/权威来源对应
pytorch/pytorch `new_group` 文档；Narayanan 2021 进程网格描述。

## 八、面试题
问：为何需多通信组？答：隔离不同并行维的集合通信。问：编号如何映射？答：按 dp/pp/tp 三维分解 rank。

## 九、演进与趋势
DTensor 以 `DeviceMesh` 声明式描述网格，自动派发通信组。

## 十、小结
进程网格与通信组是混合并行正确性的基础，错误分组会导致静默数值错误。
