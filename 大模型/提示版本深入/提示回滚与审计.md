# 提示回滚与审计

> 对应变更管理与合规；与 提示版本管理 衔接。

## 一、背景与挑战

坏提示上线致事故，需秒级回滚与完整审计链。

## 二、核心原理

保留历史不可变版本；出问题切别名回指旧版；记录每次变更的谁/何时/为何与评测结论。

## 三、数学形式

回滚成本 $C_{rb}=\text{switch\_alias}(v_{good})$；接近零（不改代码）。

## 四、代码实现

```python
registry.set_alias("prod", version="v6")  # 立即回滚
```

## 五、与其他对比

- 与 提示版本评估（回滚触发条件）互补。
- 与 模型安全与对齐（事故）共享审计。

## 六、常见误区

- 旧版本已被清理无法回滚。
- 审计只记代码不记评测与原因。

## 七、与开源书对应

- datawhalechina/llm-universe：https://github.com/datawhalechina/llm-universe
- dair-ai/Prompt-Engineering-Guide：https://github.com/dair-ai/Prompt-Engineering-Guide

## 八、面试题

- 回滚为何要保留旧版？答：事故时切别名即恢复，零部署成本，须不可变留存。

## 九、演进

无回滚 → 手动恢复 → 别名秒回滚+审计。

## 十、小结

提示回滚与审计是稳定性与合规底线，靠不可变版本与别名。
