# 提示版本管理

> 对应提示仓库（Prompt Registry）实践；与 提示版本总览 衔接。

## 一、背景与挑战

多团队协作下提示冲突、覆盖、丢失。

## 二、核心原理

用专用仓库（或 Git + 元数据）管理提示；每次变更生成不可变版本，支持标签、别名（prod/staging）与环境绑定。

## 三、数学形式

环境映射 $env \to v^*$；线上用别名解析：$v=alias(env)$ 保证可预期。

## 四、代码实现

```python
cfg = registry.resolve("system_prompt", env="prod")  # 返回 v7
```

## 五、与其他对比

- 与 提示回滚与审计（回滚机制）互补。
- 与 提示版本评估（决定是否发布）衔接。

## 六、常见误区

- 直接改 prod 别名指向未评测版本。
- 元数据缺失（谁改的、为何改）致不可审计。

## 八、面试题

- 别名（prod/staging）作用？答：解耦版本号与环境，安全灰度、快速回滚。

## 九、演进

Git 文本 → 专用仓库 → 环境别名治理。

## 十、小结

提示版本管理靠不可变版本+别名，支撑协作与安全发布。
