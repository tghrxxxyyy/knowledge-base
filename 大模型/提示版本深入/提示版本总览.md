# 提示版本总览

> 对应提示工程 MLOps；Bach et al., *PromptSource*, 2022（提示数据集版本化）。

## 一、背景与挑战

提示随迭代多版并存，需可追溯、可回滚、可对比，否则线上行为不可控。

## 二、核心原理

把每个提示当作带版本号、作者、评测结果的工件；与模型权重类似纳入版本管理。

## 三、数学形式

提示工件 $P_v=(template_v, meta_v, eval_v)$；版本序 $v_1\prec v_2\prec\cdots$。

## 四、代码实现

```python
prompts = {
  "v1": "你是助手。",
  "v2": "你是严谨中文助手，只输出JSON。",
}
```

## 五、与其他对比

- 与 系统提示深入（版本对象）衔接。
- 与 提示搜索深入（版本即可检索资产）互补。

## 六、常见误区

- 提示散落代码无版本，出事无法回滚。
- 版本号随意，难对应线上表现。

## 七、与开源书对应

- datawhalechina/llm-universe：https://github.com/datawhalechina/llm-universe
- dair-ai/Prompt-Engineering-Guide：https://github.com/dair-ai/Prompt-Engineering-Guide

## 八、面试题

- 为何提示要版本化？答：提示即模型行为代码，需可追溯、回滚与对比。

## 九、演进

硬编码 → 配置化 → 版本仓库+评测。

## 十、小结

提示版本化是提示工程 MLOps 基础，使行为可管可控。
