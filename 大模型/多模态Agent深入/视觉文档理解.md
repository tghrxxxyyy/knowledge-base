# 视觉文档理解 Agent

> 对应 LlamaIndex / LangChain 文档加载与多模态 RAG 文档、DeepSeek-VL、Qwen-VL 等 VLM 技术报告，以及 RAG 深度实践。

## 一、背景与挑战

企业知识大量沉淀在扫描 PDF、含图表/表格/版式的文档中。传统管线是「OCR → 版面解析 → 文本切块 → 向量检索 → 生成」，但 OCR 对复杂版式（多栏、嵌套表格、手写批注、图文混排）易出错，解析丢失空间结构。视觉文档理解 Agent 直接用 VLM「看图说话」，结合 RAG 检索相关页面再作答，更适合版式复杂、含图表的真实文档。

## 二、核心原理

流程分两步：

1. **页面级理解**：把 PDF 每页渲染为图像，VLM 直接读取，输出页面语义、表格内容、图表结论，作为可检索单元。
2. **检索增强生成**：用户提问时，先检索相关页面（文本摘要或页面图像），再把命中页面连同问题交给 VLM 生成答案，并标注出处。

相比「OCR+解析」，VLM 路线免去了脆弱的版式解析步骤，但成本更高、速度更慢，因此常混合：能用文本解析的用文本，复杂页用 VLM。

## 三、形式化与数学基础

把文档视为页面集合 $\mathcal{P}=\{p_1,\dots,p_n\}$，每页可表示为图像 $x_i$ 或其文本提取 $t_i$。检索阶段计算查询 $q$ 与页面表示的相关性：

$$r_i = \mathrm{sim}(E(q), E(p_i)), \qquad \mathcal{P}^* = \mathrm{TopK}_i\, r_i$$

生成阶段以检索页为条件：

$$y = \arg\max \log P(y \mid q, \{p_i\}_{i\in\mathcal{P}^*})$$

当 $p_i$ 为图像时，$E$ 与 $P$ 由 VLM 统一处理；为降成本，可先用轻量 OCR 得 $t_i$ 做初筛，再对 top 页用 VLM 精读。

## 四、代码实现

示意「OCR 初筛 + VLM 精读」混合检索：

```python
def answer(doc_pages, question, ocr, vlm, vector_db):
    texts = [ocr(page) for page in doc_pages]      # 轻量初筛
    hits = vector_db.search(question, texts, k=3)
    pages = [doc_pages[i] for i in hits]           # 命中页图像
    context = "\n".join(vlm.caption(p) for p in pages)
    return vlm.generate(f"据下文档回答问题:\n{context}\n问:{question}")
```

## 五、与其他技术对比

| 方案 | 版式鲁棒性 | 成本 | 准确性 | 适用 |
|------|------------|------|--------|------|
| OCR+解析+RAG | 弱（复杂版式崩） | 低 | 中 | 规整文档 |
| 纯 VLM 阅读 | 强 | 高 | 高 | 图表/扫描件 |
| 混合（OCR 筛+VLM 读） | 强 | 中 | 高 | 通用 |

## 六、常见误区

- 误区一：VLM 万能。超大图需切分/缩放，否则超出分辨率或丢细节。
- 误区二：全部页都喂 VLM。无关页浪费 token，应先检索再精读。
- 误区三：忽略出处。文档问答须可溯源，避免 VLM 幻觉。

## 九、演进与趋势

(1) 高分辨率 VLM 原生支持长图/大图，减少切分。(2) 文档专用模型（如版式感知 VLM）提升表格/图表抽取。(3) 与 Agent 结合：自动翻页、跨页推理、引用定位。(4) 多模态 RAG 标准化：页面图像与文本统一索引。(5) 端到端可溯源，答案直接链接原页面坐标。

## 十、小结

视觉文档理解 Agent 用 VLM 直接读取页面图像，绕过脆弱的 OCR/版式解析，结合 RAG 检索相关页再生成，特别适合含图表、扫描件、复杂版式的真实文档。实践中以「OCR 初筛 + VLM 精读」混合方案在成本与准确性间取得平衡，并须保证答案可溯源。
