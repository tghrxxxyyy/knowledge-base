# 连续批处理生产实践

> 对应 vLLM/TensorRT-LLM 部署；与 推理服务化与模型部署实战 衔接。

## 一、背景与挑战

把连续批落地到生产需配合引擎、监控、限流。

## 二、核心原理

选用支持连续批的引擎，配置最大 batch/KV 上限，监控 p99 与 GPU 利用率。

## 三、数学形式

配置参数：max_num_seqs、max_num_batched_tokens，决定并发与显存。

## 四、代码实现

```python
engine = vLLM(model, max_num_seqs=256, max_model_len=8192)
```

## 五、与其他对比

- 与 推理引擎深入（vLLM/TensorRT）强相关。
- 与 模型监控漂移深入 衔接（服务监控）。

## 六、常见误区

- 参数过大致 OOM；过小浪费。
- 忽视与投机解码的兼容。

## 七、与开源书对应

- llm-course：https://github.com/mlabonne/llm-course

## 八、面试题

- 部署连续批关键参数？答：最大并发序列数与最大批 token 数，受显存约束。

## 九、演进

单引擎 → 多副本+网关 → 自适应调度。

## 十、小结

连续批生产落地靠引擎支持与参数调优，配合监控保障 SLO。
