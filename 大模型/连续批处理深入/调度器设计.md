# 连续批处理调度器设计

> 对应调度策略与抢占。

## 一、背景与挑战

需决定每步哪些请求参与、何时接纳新请求、超长请求如何处置。

## 二、核心原理

调度器维护运行/等待队列，按步组装 batch，支持抢占（按优先级/显存）与弹性扩缩。

## 三、数学形式

每步 batch 大小受 KV 显存上限 $C$ 约束：$\sum_i L_i \le C$。

## 四、代码实现

```python
while running:
    batch = pick(running, max_tokens=C)
    step(batch)
    recycle_finished()
```

## 五、与其他对比

- 与 推理调度深入 互补（调度器是连续批的执行层）。
- 与 KV缓存优化深入 共享显存约束。

## 六、常见误区

- 无抢占致长请求饿死短请求。
- 忽略显存上限致 OOM。

## 七、与开源书对应

## 八、面试题

- 调度器如何防饿死？答：优先级/公平队列+抢占，保证短请求及时完成。

## 九、演进

FCFS → 优先级抢占 → 自适应。

## 十、小结

调度器是连续批处理大脑，需平衡吞吐、公平与显存。
