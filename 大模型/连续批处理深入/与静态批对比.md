# 连续批与静态批对比

> 对应吞吐/延迟分析。

## 一、背景与挑战

选型需看负载：突发、变长、长尾。

## 二、核心原理

静态批：固定一组请求到全部完成；连续批：每步重组。连续批在变长/高并发下吞吐高数倍。

## 三、数学形式

静态 GPU 利用率受最长序列支配；连续批逼近理论峰值（每步满 batch）。

## 四、代码实现

```python
# 静态
out = model.generate(fixed_batch)     # 等长等待
# 连续
loop: out = model.step(dynamic_batch)
```

## 五、与其他对比

- 与 推理经济成本深入 衔接（省算力=降成本）。
- 与 推理服务深入 共享。

## 六、常见误区

- 小流量下二者差异小，误以为无需连续批。
- 忽视连续批的代码复杂度。

## 七、与开源书对应

- llm-course：https://github.com/mlabonne/llm-course

## 八、面试题

- 何时静态批足够？答：请求同质、等长、低并发时可简化。

## 九、演进

静态 → 连续 → 与投机/分页一体。

## 十、小结

连续批在真实变长负载下显著优于静态，是生产标配。
