# 连续批处理总览

> 对应 Yu et al., *Orca: Continuous Batching*, 2022；vLLM/ TensorRT-LLM 实践。

## 一、背景与挑战

静态批处理需等整批最慢序列完成，GPU 空转严重；连续批处理按 token 步调度。

## 二、核心原理

每个解码步动态组合不同进度的请求（有完成的即补新），最大化 GPU 利用率。

## 三、数学形式

吞吐 $\approx$ 受制于每步 token 数而非最慢序列；等待时间从 $O(B\cdot T)$ 降到近似 $O(T)$。

## 四、代码实现

```python
# 每步从就绪队列取请求
batch = scheduler.step()       # 动态拼批
out = model.generate_step(batch)
```

## 五、与其他对比

- 与 KV缓存优化深入（分页）协同（vLLM 二者并用）。
- 与 推理服务深入 衔接。

## 六、常见误区

- 误以为静态大批次够用；长尾序列拖垮利用率。
- 忽视调度公平性/优先级。

## 八、面试题

- 连续批处理为何高效？答：按步动态拼批，避免等长等待，提 GPU 利用率。

## 九、演进

静态批 → 连续批（Orca）→ 与分页/投机融合。

## 十、小结

连续批处理是 LLM 服务吞吐关键，按 token 步灵活调度。
