# 损失突刺（Loss Spike）诊断

> 对应 大模型训练经验（如 GPT/LLaMA 训练日志中的 spike）；warmup 与数据相关。

## 一、背景与挑战

长训中 loss 偶发短暂飙升（spike）后回落，多由个别脏数据或学习率/数值瞬态引起；但持续飙升即发散。

区分“自愈尖刺”与“真发散”是关键。

## 二、核心原理

尖刺常因单批异常样本（重复/损坏/极端长度）或某步数值瞬态。监控滑动平均 loss，若偏离均值超 $k\sigma$ 即标记。

若尖刺后不回落，需回退到最近检查点并降 LR/跳过该批。

## 三、数学形式

$z_t=(L_t-\mu_L)/\sigma_L$；$z_t>k$（如 5）判为异常 spike；连续异常则判发散。

## 四、代码实现

```python
ema = 0.99 * ema + 0.01 * loss.item()
if loss.item() > ema + 5 * std:
    print("loss spike detected")
```

## 五、与其他对比

- 与 学习率与数值 衔接，LR 瞬态致 spike。
- 与 梯度范数监控 互补，spike 常伴梯度范数跳涨。
- 与 训练发散诊断与恢复深入 总览呼应。

## 六、常见误区

- 一遇 spike 就停训，浪费已训进度（可自愈）。
- 忽视脏数据批次，反复 spike。
- 把 spike 当噪声忽略，错过早期发散。

## 八、面试题

- 如何区分 spike 与发散？答：spike 后回落为瞬态，持续飙升且伴随 NaN 才是真发散。
- spike 常见原因？答：脏数据批次、LR 瞬态、数值溢出。

## 九、演进

人工看曲线 → 自动 z-score 标记 → 自动回退。

## 十、小结

损失突刺多为瞬态，靠统计阈值区分自愈与真发散，再决定回退。
