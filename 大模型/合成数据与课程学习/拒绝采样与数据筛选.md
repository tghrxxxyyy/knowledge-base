# 拒绝采样与数据筛选

> 对应对齐数据生产关键技术（Rejection Sampling Fine-Tuning, RFT；亦见 OpenAI 拒绝采样用于 RLHF 数据构造）。

## 一、背景与挑战

监督微调（SFT）数据中最怕混入错误、低质或格式不符的样本，尤其在数学、代码、科学推理等「答案可验证」任务上，一条错误解答会直接教坏模型。但强模型一次性直答的准确率有限，且批量生成难以保证每条都正确。

拒绝采样（Rejection Sampling）的思路是「广种薄收」：让模型对同一条题面采样多条候选，再用可验证信号（单元测试、符号求解、强模型判别）只保留正确/高分样本进入训练集。它能在不增加标注成本的前提下，大幅提升数据信噪比，是高质量推理数据生产的事实标准做法。

## 二、核心原理

拒绝采样源自概率采样：从提议分布 $q$ 采样，按接受概率 $\alpha$ 决定是否保留，使保留样本服从目标分布 $p$。在 LLM 数据生产中，它被工程化为「多次生成 + 自动校验 + 择优入库」：

1. **广生成**：对每条 prompt 采样 $N$ 个候选回答。
2. **校验**：对每个候选跑可执行/可判定验证器。
3. **接受**：仅保留通过验证的样本（可带奖励分数排序）。
4. **入库**：合格样本构成高质量 SFT 集。

当原始正确率为 $p_0$、采样 $N$ 条时，至少命中一条正确的概率为 $1-(1-p_0)^N$，随 $N$ 增长快速趋近 1。

## 三、形式化与数学基础

设验证器给出二元正确标记 $c(x,y)\in\{0,1\}$。接受率为：

$$
\alpha(x,y) = \frac{p_{target}(y\mid x)}{M\, q(y\mid x)} \approx c(x,y)
$$

在 SFT 数据构造中目标分布即「正确解答分布」，故：

$$
D_{clean} = \left\{ (x, y_i) \;\middle|\; y_i \sim \pi_\theta(\cdot\mid x),\; c(x,y_i)=1 \right\}
$$

奖励加权变体（ReSTEM）按奖励 $r$ 重采，迭代优化：

$$
\pi_{k+1} \propto \pi_k(y\mid x)\cdot \mathbb{1}[r(x,y) > \tau_k]
$$

## 四、代码实现

数学/代码数据筛选的精简实现：

```python
def reject_sample(model, prompts, verifier, n=8):
    clean = []
    for x in prompts:
        cands = model.generate(x, n_samples=n)   # 一次采样多条
        for y in cands:
            if verifier.check(x, y):             # 单元测试/求解器
                clean.append({"input": x, "output": y})
                break                            # 命中即收
    return clean
```

注意 `verifier` 必须独立于生成模型，否则验证形同虚设。

## 五、与其他技术对比

| 方法 | 是否需要验证器 | 信噪比 | 成本 | 适用 |
|------|----------------|--------|------|------|
| 单次直答 | 否 | 低-中 | 低 | 开放生成 |
| 拒绝采样 | 是（可验证） | 高 | 中 | 数学/代码 |
| 奖励模型筛选 | 是（RM） | 中-高 | 中 | 开放式 |
| 人工校验 | 是（人） | 最高 | 极高 | 黄金集 |

## 六、常见误区

- **「采样越多越好」**：边际收益随 $N$ 递减，且高 $N$ 算力成本陡增，需权衡。
- **「验证器可有可无」**：没有独立验证，拒绝采样退化为普通采样，信噪比无提升。
- **「只保留唯一正确解」**：多解任务应保留多样性，避免训练分布过窄。
- **混淆训练与推理**：拒绝采样是数据生产手段，不是推理期的采样策略。

## 九、演进与趋势

从静态拒绝采样演进到奖励加权的 ReSTEM 迭代重采，再到与课程学习结合（先易后难）、与自博弈结合（生成-判别互搏）。在推理阶段，拒绝采样思想也被用于 Best-of-N 解码与 STaR 式自我训练，形成「训练-推理」一体的采样哲学。

## 十、小结

拒绝采样是「用算力换质量」的典范：通过多采+验证+择优，把弱模型的正确率上限抬升，是数学、代码等可验证任务高质量数据生产不可替代的环节。落地要害在验证器的独立性与成本-收益平衡。
