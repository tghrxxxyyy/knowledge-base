# 多语言数据合成

> 对应多语言预训练与「模型自生成数据」研究（NLLB、BLOOM 多语语料、回译与跨语言蒸馏实践）；亦见「预训练/多语言」。

## 一、背景与挑战

大模型的多语言能力高度依赖训练语料的语种覆盖，但真实世界中高资源语言（英、中、法等）语料充裕，低资源语言（如多数非洲、原住民语言）的高质量文本极其稀缺，导致模型在后者上能力断崖。直接训练往往连基本语法与常识都学不稳。

多语言数据合成的核心挑战有三：其一，简单机器翻译会引入「翻译腔」，句法结构被源语绑架；其二，翻译错误与幻觉在低资源方向（如英→低资源）尤为严重，错误随回流被放大；其三，各语言脚本、形态与语序差异大，统一处理易损失语言特性。

## 二、核心原理

多语言合成主要走两条路线：

1. **翻译回流（Translate-Train）**：用强翻译模型把高资源指令/语料译为低资源语言，再混入训练，快速补齐覆盖。
2. **跨语言生成（Cross-lingual Generation）**：直接让多语模型用目标语言生成指令、问答与推理，配合母语者式提示（「以斯瓦希里语回答」）减少翻译腔。
3. **回译（Back-Translation）**：把目标语句子译回高资源语再译回，增强流畅度与多样性。

为防错误传播，需对生成结果做语言识别、困惑度过滤与母语 LLM 打分。

## 三、形式化与数学基础

设源语言 $s$、目标语言 $t$，翻译模型为 $M_{s\to t}$。回流样本构造为：

$$
x_t = M_{s\to t}(x_s), \quad y_t = M_{s\to t}(y_s)
$$

回译增强可写为两次映射：

$$
\tilde{x}_s = M_{t\to s}(x_t), \quad \tilde{x}_t = M_{s\to t}(\tilde{x}_s)
$$

质量过滤常用目标语语言模型困惑度 $PPL_t$ 作阈值：

$$
\text{keep}(x_t) = \mathbb{1}\left[ PPL_t(x_t) < \gamma \right]
$$

## 四、代码实现

一个翻译回流加过滤的精简流程：

```python
def synth_multilingual(pairs, translator, lm_target, ppl_thr=50.0):
    out = []
    for xs, ys in pairs:                      # 高资源种子
        xt = translator.translate(xs, tgt="sw")
        yt = translator.translate(ys, tgt="sw")
        if lm_target.ppl(xt) < ppl_thr:       # 困惑度过滤翻译腔
            out.append({"input": xt, "output": yt})
    return out
```

生产环境还需语言识别兜底，避免脚本错配。

| 方法 | 流畅度 | 保真度 | 成本 | 适用 |

| 直接翻译回流 | 中 | 低-中 | 低 | 冷启动 |
| 跨语言生成 | 高 | 中 | 中 | 有强多语模型 |
| 回译增强 | 高 | 中 | 中 | 提升多样性 |
| 母语人工 | 高 | 高 | 极高 | 黄金集 |

## 六、常见误区

- **「翻译即可用」**：翻译腔与语序错位会污染低资源表示，必须母语困惑度过滤。
- **「低资源方向质量无关」**：英→低资源翻译错误率最高，回流前务必验证。
- **「越多低资源数据越好」**：比例过高会挤占高资源信号，需与数据配比调度配合。
- **忽视脚本与形态**：黏着语、形态丰富语言需专门分词与模板。

## 九、演进与趋势

趋势是从「翻译为主」转向「原生多语生成」：用强多语基座直接产出目标语指令，配合母语 LLM 作为评判与过滤。统一 token 空间与多语均衡采样（见「数据配比调度」）进一步缓解语种失衡。未来低资源语言将更多依赖跨语言知识迁移而非单纯翻译。

## 十、小结

多语言数据合成是补齐低资源语言能力的务实路径，翻译回流与跨语言生成是两大抓手。成败关键在于过滤翻译腔与错误传播——合成不是终点，质量验证才是。
