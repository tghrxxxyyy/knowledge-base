# 指令数据质量

> 对应 Zhou et al. (2023) LIMA: Less Is More for Alignment；亦见指令微调 SFT 实践与 mlabonne llm-course。

## 一、背景与挑战

早期指令微调普遍迷信「数据量 = 能力」，不断堆大指令集。但工程实践中频繁出现「海量杂牌数据反而拉低效果」的现象：模型学会套模板、答非所问、风格漂移。问题不在数量，而在质量——单条样本的指令清晰性、回答准确性、格式一致性与难度分布，决定了 SFT 的上限。

核心矛盾是：高质量数据获取难、标注贵，而低质数据会「稀释」好样本、把模型带偏。如何在有限预算下最大化指令数据的对齐收益，是后训练工程的首要问题。

## 二、核心原理

高质量指令数据应具备四个特征：

1. **任务多样**：覆盖问答、写作、推理、代码、抽取等多类任务，避免单一模板。
2. **回答准确**：事实正确、逻辑自洽，错误样本需经拒绝采样剔除。
3. **格式一致**：统一输入输出结构，降低模型解析成本。
4. **难例充分**：包含一定比例的复杂、长链推理样本，防止「只学简单题」。

LIMA 的著名发现是：仅用约 1000 条经人工精心打磨的示范（「整洁示范」），就能让 65B LLaMA 表现出极强的指令遵循与风格对齐，效果媲美用海量数据训练的模型，证明「少而精」可胜「多而杂」。

需要指出，LIMA 的结论在「基座已具备足够世界知识」前提下成立：65B LLaMA 已内化了大量能力，SFT 只是「激活与对齐风格」，故少量示范足够。对能力尚弱的基座，仍需足量数据补足能力本身，质量筛选应叠加在「够用的量」之上，而非用质量完全替代数量。

## 三、形式化与数学基础

设训练集 $D$ 由高质量子集 $D_h$ 与噪声子集 $D_n$ 组成，SFT 损失为：

$$
\mathcal{L} = -\sum_{(x,y)\in D_h} \log \pi(y\mid x) - \sum_{(x,y)\in D_n} \log \pi(y\mid x)
$$

噪声样本以权重 $\lambda = |D_n|/|D_h|$ 干扰梯度方向。当 $\lambda$ 过大时，梯度被噪声主导，有效信号被稀释：

$$
\nabla \mathcal{L} \approx \frac{1}{1+\lambda}\nabla_h + \frac{\lambda}{1+\lambda}\nabla_n
$$

LIMA 主张直接压低 $\lambda$（精选 $D_h$），以极小 $|D_h|$ 获得强对齐。

## 四、代码实现

一个基于奖励模型的质量筛选示例：

```python
def filter_sft(data, reward_model, thr=7.0):
    kept = []
    for item in data:
        score = reward_model.score(item["instruction"], item["output"])
        if score >= thr:                      # 仅保留高奖励
            kept.append(item)
    return kept
```

配合去重与难度分层，可进一步均衡训练分布。

## 六、常见误区

- **「数据越多越稳」**：噪声随量线性累积，反而稀释好样本。
- **「格式不重要」**：不一致格式增加模型解析负担，降低遵循率。
- **「只堆简单题」**：缺难例会让模型遇到复杂指令即退化。
- **「质量=正确」**：多样性与风格一致性同样是质量维度，缺一不可。

## 九、演进与趋势

从 LIMA 的「人工精选少量」走向「自举生成+自动筛选」：用强模型生成、奖励模型/LLM-as-Judge 打分、拒绝采样保真，再用难度分层与去重均衡。质量评估正从单点打分演进为多维度 rubric（正确性、有用性、安全性、风格），并与数据配比调度联动。

## 十、小结

指令数据质量决定 SFT 天花板。LIMA 用 1K 条整洁示范证明「精选 > 堆量」；工程落地应把质量筛选（奖励打分、拒绝采样、难例均衡）作为标配，而非事后补救。
