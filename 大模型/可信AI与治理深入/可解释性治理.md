# 可解释性治理

> 对应 OECD AI 原则 1.2 透明可解释 与 NIST AI RMF 1.0；相关章节见「大模型可解释性」。

## 一、背景与挑战

大模型是典型黑盒，一个信贷拒批或诊断建议若无法解释原因，既无法让用户信服，也无法在出错时追责。可解释性治理要求把「可解释」从研究诉求变成治理机制：在合适场景提供可验证的解释，作为审批、审计与问责的依据。监管（OECD AI 原则强调透明可解释、EU AI Act 对高风险系统规定透明度义务）把可解释纳入强制范围。治理上需区分「可解释性」与「可理解性」：技术上有归因不等于业务方能读懂，后者才是治理落点；若解释停留在研究人员桌面，监管与用户仍无法消费。

## 二、核心原理

可解释性方法分两类：（1）局部解释——特征归因（如 integrated gradients、LIME）、注意力分析、contrastive explanation，回答「这次为何如此」；（2）全局/机制解释——探针（probing）、稀疏自编码器、circuits 等机制可解释性，理解模型内部概念与计算通路。治理上要求：解释可验证（不止是描述性）、全局+局部结合、高风险场景强制人类可理解的解释，并与「可信AI与治理深入/责任与问责」的留痕打通。落地建议：高风险决策提供「人类可读 + 机器可验证」双层解释，避免技术归因无法被业务方消费，并建立解释质量的验收门槛而非仅「有解释即可」。

## 三、形式化与数学基础

特征归因衡量输入维度 $i$ 对输出的贡献，integrated gradients 定义为从基线 $x'$ 到 $x$ 的路径积分：

$$
\mathrm{IG}_i(x)=\big(x_i-x'_i\big)\int_0^1\frac{\partial F(x'+\alpha(x-x'))}{\partial x_i}\,d\alpha
$$

归因满足完整性（completeness）：

$$
\sum_i \mathrm{IG}_i(x)=F(x)-F(x')
$$

机制可解释用稀疏自编码器把激活 $h$ 分解为可解释特征方向 $f_k$：

$$
h\approx\sum_k c_k\, f_k
$$

治理可要求解释满意度 $V(\text{exp},y)\ge v_0$ 作为审批阈值，把「可解释」从定性变为可验收的定量门禁，与评分卡（见「可信AI与治理深入/可信AI维度」）联动。

## 四、代码实现

```python
import torch

def integrated_gradients(model, inp, baseline, steps=50):
    # 沿基线到输入的路径累积梯度, 返回各维度归因
    alphas = torch.linspace(0, 1, steps)
    grads = []
    for a in alphas:
        x = baseline + a * (inp - baseline)
        x = x.requires_grad_(True)
        g = torch.autograd.grad(model(x).sum(), x)[0]
        grads.append(g)
    ig = (inp - baseline) * torch.stack(grads).mean(0)
    return ig

def explain_report(ig, top_k=5):
    # 取贡献最大的维度, 生成人类可读解释
    vals, idx = ig.abs().sort(descending=True)
    return [(int(idx[i]), float(vals[i])) for i in range(top_k)]

def accept(expl, v0=0.6):
    # 解释质量门禁: 仅当可解释性达标才通过审批
    return expl["satisfaction"] >= v0
```

## 六、常见误区

- 认为「注意力即解释」：注意力权重只是线索，未必对应因果贡献。
- 解释不可验证：描述性文字无法支撑治理问责。
- 只做全局忽视局部：高风险决策需针对具体 case 的局部解释。
- 把不可读归因当解释：技术归因未转译则业务方无法消费。
- 有解释无门禁：不验收解释质量，等于形式合规。

## 九、演进与趋势

从「注意力可视化」到「归因方法」，再到「机制可解释（circuits、稀疏特征）」。趋势是用自动化探针与可解释特征库支撑规模化治理，并把解释纳入审批与持续监控。监管推动「可理解性」成为高风险系统的交付义务，解释质量从「有无」走向「好坏可量化」。

## 十、小结

可解释性让黑盒决策可问责：通过局部归因与机制理解提供可验证解释，并接入治理与留痕机制，支撑高风险场景的透明与信任。解释须从技术归因转译为业务/监管可消费的语言，并以质量门禁保证其真实有效，才算真正落地。
