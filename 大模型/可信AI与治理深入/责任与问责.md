# 责任与问责

> 对应 EU AI Act 责任/可追溯条款 与 OECD AI 原则（2019）问责原则。

## 一、背景与挑战

当 AI 系统给出错误医疗建议、错误拒贷或生成违规内容，关键问题是「谁负责」。AI 本身不是责任主体，真正承担法律与道义责任的是开发者、部署者或使用者。若责任边界模糊、决策无留痕，事故后既无法定责也无法改进，公众信任将崩塌。监管（如 EU AI Act 对高风险系统的可追溯与责任规定、OECD AI 原则中的问责原则）要求建立清晰的人机责任边界与证据链。值得注意：随自主 Agent 兴起，责任链更复杂——规划 Agent、工具调用、模型生成多层叠加，须把问责设计到系统边界而非事后补救，否则一环出错便全盘推诿。

## 二、核心原理

责任与问责机制包含：（1）责任边界——以合同/政策明确开发者、部署者、使用者各自义务；（2）决策留痕——记录输入、模型版本、参数、输出、人工干预，形成可审计证据链；（3）事故复盘——建立上报、定责、补偿、修复流程；（4）可追溯性——把上述链路与「可信AI与治理深入/可解释性治理」打通，使每个输出可回溯到原因。问责是信任的终点：可信不止于不出错，更在于出错后能查清、能担责、能改进。落地时建议「谁调用谁兜底」为默认原则，再按合同细分，并把留痕接入复盘闭环而非只做摆设，使日志真正驱动责任认定与系统迭代。

## 三、形式化与数学基础

把一次决策建模为五元组事件：

$$
e=(a, x, \theta, y, h)
$$

其中 $a$ 为行动主体（人或 Agent），$x$ 为输入，$\theta$ 为模型版本，$y$ 为输出，$h$ 为人工是否干预。责任归属函数：

$$
\mathrm{liable}(e)=\begin{cases}
\text{deployer}, & h=\text{none}\\
\text{human}, & h=\text{override}\\
\text{developer}, & \text{bug in }\theta
\end{cases}
$$

对 Agent 链路可扩展为事件序列 $\{e_t\}$，逐跳记录工具调用与模型决策，使多跳责任可逐层回溯到最初触发方。

## 四、代码实现

```python
def log_decision(role, action, out, model_version, human_override=False):
    # 记录决策五元组, 供事后定责与审计
    incident_log.append({
        "role": role,
        "action": action,
        "out": out,
        "model": model_version,
        "human_override": human_override,
    })
    return len(incident_log) - 1  # 返回事件 id, 串联多跳责任链

def trace_chain(event_id):
    # 按事件 id 回溯因果链, 支撑逐层定责
    return incident_log[event_id]

def assign_liability(event):
    # 依据五元组自动建议责任主体
    if event["human_override"]:
        return "human"
    if event["model_bug"]:
        return "developer"
    return "deployer"
```

## 六、常见误区

- 认为「AI 担责」：责任主体是人或组织，AI 只是工具。
- 只留最终结果不留过程：缺输入/版本/干预记录则无法定责。
- 边界靠默契不靠合同：事故后易推诿，须书面明定。
- 把日志当摆设：不接入复盘流程则留痕无问责意义。
- 忽略 Agent 多跳：只记最后一步，前序工具调用责任无人认领。

## 七、与开源书·权威来源对应

- EU AI Act（Reg. 2024/1689）：高风险系统自动记录（logging）、可追溯与责任条款。
- OECD AI 原则（2019）：稳健、安全、透明、负责任。

## 九、演进与趋势

从「无留痕」到「事件日志」，再到「端到端可追溯 + 自动定责建议」。方向包括：把日志接入防篡改存证、用模型卡（model card）/数据卡实现供应链问责、以及监管驱动的强制记录标准。Agent 时代推动「责任边界即架构边界」，在系统设计期就固化责任链。

## 十、小结

责任与问责让可信落到人：清晰的责任边界、完整的决策留痕与事故复盘流程，使 AI 出错后能够查清原因、明确主体并加以改进。留痕只有接入复盘与补偿机制才构成真正的问责，对 Agent 系统还需沿多跳链路逐层定责。
