# 持续监控治理

> 对应 EU AI Act（Reg. 2024/1689）第 72 条上市后监测 与 NIST AI RMF 1.0（2023）Manage 阶段。

## 一、背景与挑战

大语言模型上线后并非一劳永逸：训练数据分布会随时间漂移，用户行为、外部世界知识不断演化，模型在部署环境里暴露出训练时未出现的风险（如越狱成功率上升、幻觉率抬升、群体公平性劣化）。一次性评测只能刻画发布瞬间的能力，无法反映长期可信度。监管侧也提出了明确要求——例如 EU AI Act 对高风险系统规定「上市后监测」（post-market monitoring）义务，NIST AI RMF 把 Monitor 列为贯穿生命周期的职能。因此可信 AI 必须由「发布即终」转向「持续治理」的运营闭环。实践中有三类典型漂移需要警惕：数据漂移（输入分布变化）、概念漂移（输入到输出的映射变化）、以及对抗漂移（攻击者主动演化绕过防线）。

## 二、核心原理

持续监控治理是在模型上线后，对性能、安全、公平、隐私、漂移等多类指标进行常态化采集与评估，并在触发阈值时自动或人工介入的闭环体系。核心环节包括：（1）指标定义——为每个可信维度设定可量化指标与基线；（2）数据采集——在线埋点、离线评测集、红队回灌三线并行；（3）漂移检测——统计检验或分布距离度量判断输入/输出分布偏移；（4）再评估与再训练——定期对留存/新标注集复跑评测；（5）治理动作——告警、回滚、补训、人工复核、下线；（6）反馈学习——把治理结论回流到数据治理与模型迭代。整个闭环需与「可信AI与治理深入/AI治理框架」中的审批与责任机制对接，形成「监测—研判—处置—复盘」的运营节奏。值得注意的是，监控本身不是目的，能否触发并闭环治理动作才是价值所在。

## 三、形式化与数学基础

以群体公平性漂移为例，设群体 G 在时刻 t 的公平率为 P_t(fair|G)，监测告警可由群体均差超阈触发：

$$
\Delta_{G_1,G_2}(t)=\big|P_t(\text{fair}\mid G_1)-P_t(\text{fair}\mid G_2)\big|
$$

输入分布漂移常用最大均值差异（MMD）或 KL 散度度量：

$$
\mathrm{MMD}^2(\mathcal{P}_t,\mathcal{P}_0)=\big\|\mathbb{E}_{x\sim\mathcal{P}_t}[\phi(x)]-\mathbb{E}_{x\sim\mathcal{P}_0}[\phi(x)]\big\|^2
$$

$$
\mathrm{KL}(\mathcal{P}_t\parallel\mathcal{P}_0)=\mathbb{E}_{x\sim\mathcal{P}_t}\big[\log\tfrac{\mathcal{P}_t(x)}{\mathcal{P}_0(x)}\big]
$$

当 $\Delta>\varepsilon$ 或 $\mathrm{MMD}^2>\delta$ 或 $\mathrm{KL}>\kappa$ 时触发治理动作。

## 四、代码实现

```python
import numpy as np

def fairness_gap(scores_a, scores_b, eps=0.05):
    # scores_* 为各群体判定为「公平」的 0/1 序列
    p_a = np.mean(scores_a)
    p_b = np.mean(scores_b)
    return abs(p_a - p_b), (abs(p_a - p_b) > eps)

def monitor(model, drift_fn, fair_fn, epsilon=0.05, delta=1e-2):
    # 周期调用: 返回是否需要治理介入
    d = drift_fn(model)
    gap, fired = fair_fn(epsilon)
    if d > delta or fired:
        # 触发后再评估与可能的回滚
        return {"action": "reevaluate", "drift": d, "gap": gap}
    return {"action": "ok"}

def schedule_reeval(period_days=7):
    # 定期复评节奏, 避免只靠阈值
    return f"reeval every {period_days}d"
```

## 六、常见误区

- 认为「上线即终」：忽略分布漂移与对抗演化，导致风险在数月后集中爆发。
- 只盯准确率：公平、安全、隐私指标同样会退化，单看能力会漏掉关键退化。
- 阈值静态不变：业务与用户群体变化后，固定 $\varepsilon$ 会失效，需定期校准。
- 监控与治理脱节：有告警无动作，等于没有监控。
- 忽视概念漂移：输入分布没变但映射变了，纯输入侧检测会漏报。

## 九、演进与趋势

从「发布即终」到「定期复评」，再到「实时持续治理」。未来方向包括：自动化评测回灌、在线学习与概念漂移自适应、把监控信号直接接入再训练与回滚流水线，以及用 LLM 自评作为低成本的持续信号源。监管侧（EU AI Act）正把上市后监测写入强制义务，并配套事件上报机制。

## 十、小结

持续监控治理把可信从「发布时快照」变成「生命周期闭环」：通过指标定义、采集、漂移检测、再评估与治理动作的循环，配合监管与责任机制，保障模型长期可信。监测只是手段，真正价值在于触发并闭环治理动作。
