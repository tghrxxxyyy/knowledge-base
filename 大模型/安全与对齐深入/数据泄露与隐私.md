# 数据泄露与隐私

> 对应 llm-course mlabonne「Privacy」章节、Carlini et al.「Extracting Training Data from Large Language Models」(2021) 与 GDPR/HIPAA 等合规要求。

## 一、背景与挑战

大模型在海量语料上训练，可能「记忆」并逐字复述训练数据中的敏感片段，包括个人身份信息（PII）、机密文档、代码与对话。隐私风险贯穿全生命周期：训练阶段的数据投毒与记忆、推理阶段的提示泄露与日志留存、以及模型权重本身可能成为敏感数据的载体。随着法规趋严（GDPR、HIPAA、《个人信息保护法》），数据不出域、可遗忘、可审计成为硬性要求，而 LLM 的「记忆」特性与「黑箱」特性使合规章外困难。

## 二、核心原理

隐私威胁主要有三类：（1）训练数据提取攻击——如 Carlini 等证明，通过构造特定前缀可诱导模型逐字吐出记忆的姓名、地址、代码；（2）成员推断攻击——判断某条样本是否出现在训练集中；（3）推理侧泄露——在多轮对话或共享上下文中，用户隐私被后续请求或第三方插件获取。防护手段包括：训练前 PII 检测与脱敏、差分隐私训练（DP-SGD）、机器遗忘（machine unlearning）、推理侧数据隔离与「用户数据不留存」策略、以及私有化/本地化部署。

## 三、形式化与数学基础

差分隐私通过向梯度加噪保障：对任意相邻数据集 $D, D'$（仅差一条记录），机制 $\mathcal{M}$ 满足 $(\epsilon,\delta)$-DP 若：

$$
\Pr[\mathcal{M}(D) \in S] \le e^\epsilon \Pr[\mathcal{M}(D') \in S] + \delta, \quad \forall S
$$

DP-SGD 在每步裁剪梯度范数至 $C$ 并加噪声 $\mathcal{N}(0, \sigma^2 C^2 I)$，使单条样本对更新的影响受控。记忆风险随训练步数与过拟合上升，可用「逐字提取率」$E = \frac{1}{N}\sum \mathbb{1}[\text{extracted}_i]$ 量化。

import re

PII_PATTERNS = {
    "phone": r"\b1[3-9]\d{9}\b",
    "email": r"\b[\w.]+@[\w.]+\.\w+\b",
    "id_card": r"\b\d{17}[\dX]\b",
}

def redact(text: str) -> str:
    for name, pat in PII_PATTERNS.items():
        text = re.sub(pat, f"[{name}]", text)
    return text

## 六、常见误区

- 误区一：模型不会「记住」具体数据。实证研究表明大模型可逐字复述训练片段。
- 误区二：脱敏后数据就绝对安全。重识别攻击仍可能从准标识符反推个体。
- 误区三：推理日志无关紧要。对话日志常成为最大泄露点，应默认不留存。
- 误区四：私有化部署即合规。还需访问控制、审计与算法备案等配套。

## 九、演进与趋势

从「事后脱敏」走向「训练期差分隐私 + 推理期数据隔离 + 可遗忘权」的全链路隐私工程；联邦学习、合成数据增强、以及基于密码学的推理（如安全多方计算）也在探索中。监管侧推动「AI 生成内容标识」与「训练数据确权」双向并行。

除技术防御外，组织层数据治理同样关键：训练语料需来源审计与授权链路，推理服务应默认关闭对话留存与「用于改进」开关。开源模型权重本身可被视为数据载体，发布前需做记忆审计与机器遗忘以规避泄露。监管侧正推动训练数据透明化与被遗忘权落地，使隐私从工程实践上升为法律义务。

- 来源审计：训练数据保留授权证明与链路。
- 默认不留存：推理对话不上训练、不落日志。
- 权重审计：发布前做提取攻击红队测试。
- 联邦训练：原始数据不出本地即可联合建模。
- 法律义务：被遗忘权与透明化逐步强制。

## 十、小结

大模型因记忆特性而成为隐私高危载体，风险覆盖训练、推理与部署全链路。有效的隐私防护需脱敏、差分隐私、机器遗忘与私有化部署组合，并以「默认不留存」的工程纪律守住推理侧底线。
