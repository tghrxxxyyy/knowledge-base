# 内容安全与审核

> 对应 llm-course mlabonne「Security」章节、OpenAI Moderation API 与 OWASP Top 10 for LLM Applications（LLM02 不安全输出处理）。

## 一、背景与挑战

大模型生成内容的能力越强，被滥用于产出违规内容（仇恨言论、色情、自残诱导、暴力、欺诈、政治敏感信息等）的风险越高。与传统的基于规则的论坛审核不同，LLM 的输出是开放式的、长文本、可多语言、可多模态，且攻击者会主动试探绕过，这给内容安全带来三方面挑战：一是覆盖面广，违规类型随地区和法规动态变化；二是误杀与漏杀的权衡，过于严格的审核会损害正常用户体验（可用性下降），过松则放行有害内容；三是多模态与跨语言，攻击常以隐晦隐喻、代码、图片藏字等方式逃避单层过滤。因此内容安全通常作为「输出侧防护」的最后一道闸，与输入过滤、对齐训练构成纵深防御。

## 二、核心原理

内容审核在生成前（输入预过滤）与生成后（输出后审核）两个环节介入。输出侧审核的典型流水线为：模型生成候选文本 → 安全分类器打分 → 命中高危类别则拦截/改写/降级 → 记录审计日志 → 可疑样本进入人工复核闭环。分类器可分为：基于关键词/正则的硬规则（快速但易被绕）、基于 fine-tuned 分类模型（如基于 BERT/RoBERTa 的 toxic 分类器，OpenAI Moderation、Perspective API 属于此类 API 化服务）、以及大模型自审（让一个强模型判断另一模型输出是否违规，即 LLM-as-a-judge）。多语言场景需本地化词表与本地化标注数据，避免文化差异导致的误判。

## 三、形式化与数学基础

设输出文本 token 序列为 $x = (x_1, \dots, x_n)$，安全分类器给出 $K$ 个风险类别的概率分布：

$$
p(c \mid x) = \text{Softmax}(W \cdot h_{\text{cls}}), \quad c \in \{1,\dots,K\}
$$

其中 $h_{\text{cls}}$ 为文本编码器得到的句向量。采用阈值 $\tau_c$ 判定违规：若 $\max_c p(c\mid x) > \tau_c$ 则拦截。误杀率与漏杀率分别为：

$$
\text{FPR} = \mathbb{E}[\mathbb{1}_{\hat{y}=1, y=0}], \qquad \text{FNR} = \mathbb{E}[\mathbb{1}_{\hat{y}=0, y=1}]
$$

运营上以代价加权目标 $\min\, w_f \cdot \text{FNR} + w_s \cdot \text{FPR}$ 调节阈值，其中漏杀代价 $w_f$ 通常远大于误杀代价 $w_s$（安全优先）。

## 四、代码实现

```python
from openai import OpenAI

client = OpenAI()

def moderate(text: str) -> dict:
    resp = client.moderations.create(input=text)
    r = resp.results[0]
    flagged = r.flagged
    scores = {k: round(v, 3) for k, v in r.category_scores.model_dump().items()}
    return {"flagged": flagged, "scores": scores}

def safe_generate(user_prompt: str) -> str:
    out = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": user_prompt}],
    ).choices[0].message.content
    if moderate(out)["flagged"]:
        return "⚠️ 该内容触发安全策略，已拦截。"
    return out
```

## 五、与其他技术对比

| 审核方式 | 速度 | 可解释 | 抗绕过 | 成本 |
|----------|------|--------|--------|------|
| 关键词/正则 | 极快 | 高 | 低 | 低 |
| 分类模型 API | 快 | 中 | 中 | 中 |
| LLM 自审 | 慢 | 高 | 高 | 高 |
| 人工复核 | 慢 | 高 | 高 | 很高 |

实践中常采用「关键词快筛 + 分类模型主筛 + LLM/人工抽检」的分级架构，在成本与覆盖率间取得平衡。

## 六、常见误区

- 误区一：有了安全分类器就能一劳永逸。攻击者会持续试探新绕过方式（同形字、拆分、翻译），需持续更新规则与数据。
- 误区二：把误杀率当作唯一指标。漏杀（放行违规）的代价往往远高于误杀，阈值应安全优先并根据场景调整。
- 误区三：翻译即清洗。将违规内容翻译成小语种并不能绕过多语言分类器，反而增加识别难度但非不可能。
- 误区四：输出拦截就够了。应与输入过滤、对齐训练、用户举报闭环协同，单点防御必然被突破。

## 九、演进与趋势

早期以关键词黑名单为主；随后引入统计分类模型（toxic/BERT）；当前走向「分类器 + LLM 自审 + 多模态审核 + 实时反馈闭环」的融合方案。趋势包括：可解释审核（给出命中依据）、隐私保护下的本地化审核（数据不出域）、以及针对 Agent 工具调用结果的细粒度动作级审核。

运营侧应建立安全可观测大盘：实时跟踪命中率、误杀投诉率与绕过样本聚类，并以周级节奏回流到规则与分类器。面向儿童的场景默认最严阈值并扩大类别覆盖；代码类场景需额外防范恶意利用（如生成攻击脚本）。审核策略须可配置、可灰度发布，新规则先小流量验证再全量。

- 灰度过载：新规则先 1% 流量验证误杀率，避免全量翻车。
- 样本回流：人工复核命中样本进入训练与评测集，形成闭环。
- 多模态：图片与音频需独立审核通道，不能只筛文本。
- 可解释：拦截应返回命中依据，便于申诉与纠错。
- 合规对齐：类别清单随地区法规动态更新。

## 十、小结

内容安全与审核是生成式 AI 落地的合规底线，作为输出侧防护与输入过滤、对齐训练共同构成纵深防御。工程上应以分级架构平衡误杀/漏杀与成本，并持续运营更新以应对不断演化的绕过手段。
