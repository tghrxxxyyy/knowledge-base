# 防御策略综述

> 对应 OWASP Top 10 for LLM Applications 与 llm-course mlabonne「Security」章节，安全工程纵深防御思想。

## 一、背景与挑战

单点安全手段（仅靠系统提示、仅靠输出分类器）在面对持续演化的攻击时必然被突破。大模型系统的攻击面横跨训练、推理、工具调用与数据流转，因此安全不能依赖某一层，而需「纵深防御（defense in depth）」——在多个环节设置相互独立又相互补充的防线，使任一层失效都不导致整体失守。

## 二、核心原理

纵深防御把安全能力拆解为多层：（1）训练期对齐——在 RLHF/DPO 偏好数据中融入安全样本，从分布层面降低有害输出概率；（2）输入过滤——对用户输入与检索内容进行意图分类与注入扫描；（3）输出审核——生成后用分类器/自审拦截违规；（4）工具最小权限——Agent 仅授予完成任务所必需的工具，危险动作需人工确认；（5）行为审计与日志——记录关键决策用于追责与复盘；（6）用户反馈闭环——举报与误判回流改进。各层独立失效时，其余层仍可兜底。

## 三、形式化与数学基础

设系统由 $L$ 层独立防御组成，第 $l$ 层被突破的概率为 $p_l$。整体被攻破的概率为各层串联失效：

$$
P_{\text{breach}} = \prod_{l=1}^{L} p_l
$$

可见增加一层即便不完美的防御，也会以乘法方式降低整体风险（当 $p_l<1$）。若各层相关性强（如都依赖同一分类器），则联合概率退化，故强调「独立性」。以代价函数表示：

$$
\min \sum_l c_l \quad \text{s.t.} \quad \prod_l p_l \le P_{\text{budget}}
$$

即在安全预算内分配各层成本，使整体突破概率最低。

## 四、代码实现

```python
def secure_pipeline(prompt, tools):
    # 1. 输入过滤
    if input_scan(prompt)["risk"] > 0.8:
        return refuse(prompt)
    # 2. 对齐模型生成
    draft = aligned_model.generate(prompt)
    # 3. 输出审核
    if output_moderate(draft)["flagged"]:
        return refuse_with_reason(draft)
    # 4. 工具最小权限 + 确认
    for call in planned_tool_calls(draft):
        if call.risk == "high" and not human_confirm(call):
            return "工具调用未授权。"
    # 5. 行为审计
    audit_log(prompt, draft, call)
    return draft
```

## 五、与其他技术对比

| 防御层 | 位置 | 防护对象 | 局限 |
|--------|------|----------|------|
| 对齐训练 | 训练期 | 分布级有害 | 被越狱绕过 |
| 输入过滤 | 推理前 | 注入/越狱 | 编码绕过 |
| 输出审核 | 推理后 | 违规输出 | 延迟/误杀 |
| 工具管控 | 执行前 | 危险动作 | 需设计权限 |

## 六、常见误区

- 误区一：系统提示写死规则即可。提示易被注入/越狱覆盖，非可靠防线。
- 误区二：有一层强防御足矣。单层必然被针对性突破，须多层互补。
- 误区三：只防输出不管工具。Agent 的工具调用危害远大于文本输出。
- 误区四：安全与体验对立。合理分层可在可接受体验下显著提升安全。

## 九、演进与趋势

从「补丁式单点防御」走向「训练—推理—执行—审计」全链路标准化；从规则到自适应、可解释的护栏；从企业自建到 OWASP/NIST 等框架指导下的合规化安全治理。未来重点是可验证安全（formal guarantee）与实时对抗防御。

落地需权衡成本与延迟：每层防御都引入算力与延迟，应在风险等级驱动下分级启用（高风险全开、低风险轻量）。审计与反馈闭环最易被忽视却最关键——没有闭环，防御会随时间退化。可观测安全指标（突破率、误杀率、拦截时延）应纳入线上监控大盘。

- 分级启用：按风险调度防御层强度。
- 闭环运营：发现即回流改进策略。
- 可观测：安全指标进监控大盘。
- 成本控制：低风险场景用轻量防线。
- 独立假设：各层尽量解耦避免共因失效。

## 十、小结

大模型安全无法依赖单点防御，纵深防御通过训练对齐、输入过滤、输出审核、工具管控、审计与反馈多层互补，以乘法方式降低整体突破概率。工程落地应坚持多层独立、场景化阈值与持续红队。
