# 红队测试 Red Teaming

> 对应 Ouyang et al. 2022「InstructGPT/RLHF」中红队章节、OpenAI Red Teaming Network 与 llm-course mlabonne「Security」。

## 一、背景与挑战

即便经过 RLHF 对齐，模型仍可能暴露偏见、有害输出、越狱漏洞与敏感信息泄露。常规评测（如 MMLU、基准准确率）只能衡量「能力上限」，无法发现「最坏情况行为」。红队测试（red teaming）以对抗性、攻击者视角系统性探测模型漏洞，是安全上线前不可或缺的环节，目标是主动发现而非证明安全。

## 二、核心原理

红队方法分为三类：（1）人工对抗——由训练有素的红队人员设计刁钻提示，覆盖多语言、多文化、边缘群体；（2）自动攻击——利用模板、越狱语料库、强化学习（如通过奖励模型自动搜索可越狱提示）批量生成攻击；（3）多轮诱导——通过渐进式对话绕过单次防御。发现的问题被转化为安全偏好数据（用于进一步对齐）与安全评测集（用于回归测试），形成「发现—修复—评测」闭环。

## 三、形式化与数学基础

可将红队建模为对抗搜索：红队者寻找提示 $x^*$ 使模型输出 $y$ 落入有害集合 $\mathcal{H}$：

$$
x^* = \arg\max_{x \in \mathcal{X}} \, \mathbb{1}[\pi_\theta(\cdot \mid x) \cap \mathcal{H} \neq \varnothing]
$$

自动化红队常用奖励模型 $r_\phi$ 作为可微代理，通过梯度上升（或遗传/强化学习）优化提示嵌入或离散 token，使 $r_\phi(\pi_\theta(x), x)$ 最大化有害性得分。防御侧则最小化该得分，构成 min-max 博弈：

$$
\min_\theta \max_x \, \mathbb{E}_{y\sim\pi_\theta(\cdot\mid x)}[r_\phi(y, x)]
$$

## 四、代码实现

```python
def red_team_round(model, attacker, topic, n_turns=3):
    conv = [{"role": "system", "content": "你是有害请求助手。"}]
    for _ in range(n_turns):
        probe = attacker.generate(conv, topic)
        conv.append({"role": "user", "content": probe})
        resp = model.generate(conv)
        conv.append({"role": "assistant", "content": resp})
        if safety_classifier(resp)["flagged"]:
            log_vuln(topic, probe, resp)   # 记录漏洞进训练/评测集
            break
    return conv
```

## 六、常见误区

- 误区一：红队=常规测试。红队追求「最坏情况」，常规测试追求「平均表现」，目标相反。
- 误区二：一次红队终身安全。攻击手法持续演化，需常态化、可回归。
- 误区三：只测英文。多语言、方言、文化特定攻击常被遗漏。
- 误区四：发现问题不沉淀。漏洞须回流到训练与评测集，否则修复不可持续。

## 九、演进与趋势

从纯人工走向「人工+自动+多模态」协同；从单轮提示走向长程对话与工具调用链路攻击；从发现漏洞走向「红队即服务」与持续回归。未来将更强调可量化风险评分与跨学科（心理、法律、安全）红队。

红队组织形态在演进：从临时抽调专家，走向常设团队 + 众包漏洞赏金 + 自动化平台组合。评测维度从能否越狱扩展到越狱成本、多语言覆盖与长期稳定性，并形成量化红队评分卡。红队样本具双重价值——既是修复对齐的训练燃料，也是回归测试的固定集，应纳入版本发布强制关卡。自动化红队可与 RLHF 形成闭环：用产出持续扩充偏好数据，使模型迭代中逐步加固。

- 常设化：红队纳入研发常态而非一次性活动。
- 闭环化：漏洞回流训练与评测集。
- 量化：以评分卡跟踪风险趋势与回归。
- 众包：漏洞赏金扩大攻击覆盖面。
- 多模态：覆盖图像与音频攻击面。
- 强制关卡：红队集作为发布准入条件。

## 十、小结

红队测试以攻击者视角主动暴露模型最坏情况行为，是安全对齐的必要补充。有效的红队需人工与自动化结合、覆盖多语言多模态，并将发现沉淀进训练与评测闭环，而非一次性活动。
