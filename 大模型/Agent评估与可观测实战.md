# Agent 评估与可观测实战

> 板块：大模型 　|　 返回：[README](README.md)
> 适用：多步推理、工具调用、自主 Agent 的质量度量与线上监控。

Agent（能调用工具、多步决策的系统）比单次问答复杂得多：失败可能发生在规划、工具调用、观察、反思任一环。没有评估与可观测，Agent 上线就是"黑盒裸奔"。

## 一、Agent 的失败模式

| 环节 | 失败表现 |
|------|----------|
| 规划 | 目标拆解错、步骤冗余/缺失 |
| 工具调用 | 选错工具、参数错、调用失败 |
| 观察 | 误解工具返回、忽略关键信息 |
| 反思 | 不纠错、死循环 |
| 终止 | 不停止/过早停止 |

## 二、评估维度

| 维度 | 度量 |
|------|------|
| 任务成功率 | 最终是否达成目标 |
| 步骤效率 | 平均步数、是否冗余 |
| 工具准确率 | 工具选择与参数正确率 |
| 容错 | 中途出错能否恢复 |
| 成本 | token/工具调用次数 |
| 安全 | 越权/注入抵御 |

## 三、评估方法

### 3.1 离线基准（Benchmark）

- 构建任务集（含预期轨迹/答案），批量跑 Agent，统计成功率。
- 轨迹级评估：不只看结果，还看中间步骤是否合理。
- 工具：LangSmith、自研 eval 框架、公开基准（如 AgentBench、WebArena）。

### 3.2 LLM-as-Judge

- 用强模型对 Agent 输出/轨迹打分（相关性、正确性、安全性）。
- 注意：裁判模型也有偏差，需校准 + 人工抽检。

### 3.3 在线 A/B 与采样

- 小流量灰度，对比新旧版本任务成功率与用户满意度。
- 人工标注抽样，校准自动指标。

## 四、可观测架构

```
Agent 运行 → 全链路 Tracing(每步/工具调用) → 日志/指标/轨迹存储
                                    ↓
                            Dashboard + 告警 + 回放
```

- **轨迹记录（Trace）**：每步的 prompt、工具调用、返回、反思，可回放。
- **指标**：步数、工具失败率、重试率、成功率、token 成本、P95 延迟。
- **告警**：成功率跌、工具失败激增、成本异常、注入拦截。

## 五、轨迹回放与调试

- 每条对话存完整 trace，出问题可逐帧回放。
- 对比"好轨迹 vs 坏轨迹"，定位系统性问题（如某工具常失败）。
- 沉淀为回归用例，防退化。

## 六、成本与质量平衡

- Agent 多步 + 反思会放大 token 消耗，需设步数上限、早停。
- 用更小模型做规划/简单步骤，大模型做关键推理，分层降本。

## 七、常见坑

1. **只看最终答案** → 漏掉步骤错误；轨迹级评估。
2. **无线上监控** → 退化不知；全链路 trace + 告警。
3. **步数无上限** → 死循环烧钱；max_steps + 早停。
4. **工具失败不重试/不报错** → 任务静默失败；失败处理 + 告警。
5. **Eval 与线上脱节** → 离线好线上差；在线采样校准。
6. **忽略安全评估** → 注入/越权；安全红队 + 拦截指标。
