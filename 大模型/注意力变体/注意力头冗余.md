# 注意力头冗余与剪枝

> 对应 Michel et al., *Are Sixteen Heads Really Better than One?* (NeurIPS 2019)、Voita et al., *Analyzing Multi-Head Self-Attention: Specialized Heads Do the Rest, Most Heads Can Be Pruned* (ACL 2019)、Desefouz et al. BERT 剪枝实践，以及「模型压缩/结构化剪枝」「注意力变体/FlashAttention原理」的互补视角。深入头重要性评估与部署加速落地。

## 一、背景与挑战

现代 Transformer 几乎都堆叠多头注意力（MHA）：$h=12\sim128$ 个头并行算不同子空间的注意力。直觉上「更多头 = 更强表达」，但大量实证发现：

- **统计冗余**：许多头的注意力分布高度相似（同一头内熵极低或与其他头相关系数极高）；
- **功能分工不均**：少数头专司位置、语法依赖、定冠词跟随、稀有词定位（Voita 称 special heads），大量头对下游损失贡献接近 0；
- **剪枝敏感度差异**：按头重要性剪掉 20%～40% 的头，下游困惑度/准确率几乎不动，个别层甚至提升；
- **工程收益明确**：头数直接影响 QKV 投影与注意力核的计算量、KV Cache 体积——**推理侧砍头 = 直接降显存与延迟**，比非结构化剪枝更容易落到硬件。

挑战在于：头不是独立可丢的「零件」。剪错头会破坏 residual 流中的信息通路；层间依赖强（末层头往往更可丢，但浅层关键头不可动）；剪后若不微调，长尾任务可能崩。因此需要**可复现的重要性度量 + 温和的剪枝-恢复流程**，而不是拍脑袋删。

## 二、核心原理

### 2.1 头重要性怎么打分

常见指标（可组合）：

1. **基于梯度的灵敏度**（Michel）：对验证集损失 $L$，头 $j$ 的重要性  
   $$ I_j = \mathbb{E}\big[\,|A_j \odot \partial L/\partial A_j|\,\big] $$  
   即注意力输出对损失的贡献量级；$I_j$ 小的头可先剪。
2. **注意力熵 / 模式**：熵极低（只盯一个位置）或与其他头 JS 散度极小 → 冗余或已由别的头覆盖。
3. **消融验证**：直接把头置零，测 $\Delta \text{PPL}$ 或 $\Delta \text{Acc}$；最准但要跑 $O(h)$ 次评估。
4. **结构相似度**：头间 $A_j A_k^\top$ 相关，聚类后每簇只保留代表头（头合并/蒸馏思路）。

### 2.2 剪枝策略

- **一次性（one-shot）**：全局按 $I_j$ 排序，从低到高剪到目标比例，再微调恢复。
- **迭代（iterative）**：每轮剪 5%～10% → 恢复训练 → 重新评估，更稳但成本高。
- **逐层配额**：实验上**深层头更冗余**，可给末层更高剪枝率、浅层/嵌入层附近更低配额。
- **与 MHA→MQA/GQA 关系**：剪头是「减 Q/K/V 头」；GQA 是「多个 Q 头共享 K/V」——两者常叠加：先剪冗余头，再对剩余头做 GQA 分组，KV Cache 进一步降。

### 2.3 为何「剪了还有救」

Residual 连接保证主通路不断；LayerNorm 重新定标；微调让剩余头**重新分工**，把被剪头的功能吸收。这是结构化剪枝可恢复的机制基础，也解释了「必须跟少量恢复训练」——不微调等于只做消融不修复。

## 三、形式化与数学基础

设第 $l$ 层有 $h$ 头，头输出拼接后线性变换：

$$ \text{MHA}(X)=\sum_{j=1}^{h} W_O^{(j)}\,\text{Attn}\big(XW_Q^{(j)},XW_K^{(j)},XW_V^{(j)}\big) $$

剪枝集合 $\mathcal{P}\subset\{1..h\}$ 后模型变为 $\text{MHA}'$ 只对 $j\notin\mathcal{P}$ 求和。目标是在约束下最小化任务损失：

$$ \min_{\mathcal{P}} \; \mathbb{E}[L(\theta,\mathcal{P})] \quad \text{s.t.}\quad |\mathcal{P}|\le k \;(\text{或 FLOPs/延迟预算}) $$

Michel 用一阶泰勒近似给出丢头的损失增量：

$$ \Delta L \approx \sum_{j\in\mathcal{P}} \bigg| \frac{\partial L}{\partial A_j}\cdot A_j \bigg| $$

即按「敏感度质量」从小到大剪。推理期，头数减半近似使 QKV GEMM 与 attention 核计算量减半（在 head 维可分的实现上），KV Cache 体积：

$$ \text{KV} = 2 \cdot B \cdot L \cdot h \cdot d_{\text{head}} \cdot \text{bytes} $$

$h$ 与 $d_{\text{head}}$ 同时影响 Cache——这也是「剪头 + GQA」能显著降服务成本的公式来源。

## 四、代码实现

```python
# 示意：按灵敏度对多头注意力做头级 mask（训练中可学习 / 评估后冻结）
import torch
import torch.nn as nn
import torch.nn.functional as F

class MultiHeadAttnPrune(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__()
        self.n_heads, self.d_head = n_heads, d_model // n_heads
        self.qkv = nn.Linear(d_model, 3 * d_model)
        self.o = nn.Linear(d_model, d_model)
        # 可解释为 0..1 的门控，训练后二值化为剪枝掩码
        self.head_gate = nn.Parameter(torch.ones(n_heads))

    def forward(self, x, prune_mask=None):
        B, L, D = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)
        def split(t):  # (B,L,H*dh) -> (B,H,L,dh)
            return t.view(B, L, self.n_heads, self.d_head).transpose(1, 2)
        q, k, v = split(q), split(k), split(v)
        gate = self.head_gate
        if prune_mask is not None:
            gate = gate * prune_mask          # 被剪头输出置零
        att = F.scaled_dot_product_attention(q, k, v)
        att = att * gate.view(1, -1, 1, 1)    # 头维门控
        y = att.transpose(1, 2).reshape(B, L, D)
        return self.o(y)
```

工业流程：**校准集上算重要性 → 生成 0/1 头掩码 → 1%～10% 数据恢复训练 → 测 PPL/任务指标与真实延迟 → 导出时物理删除被剪头的权重切片**（不是运行时 mask，否则算力不省）。

## 五、与其他技术对比

| 维度 | 头剪枝 | 非结构化权重量化/剪枝 | GQA/MQA | 层剪枝/蒸馏 |
| --- | --- | --- | --- | --- |
| 粒度 | 头 | 单个权重 | KV 头分组 | 整层/师生 |
| 硬件友好 | **高（维变小）** | 低（需稀疏 kernel） | 高 | 高 |
| 推理延迟 | 直接降 | 依赖实现 | 降 KV 与部分算力 | 降深度 |
| 恢复成本 | 低～中 | 中 | 改预训练/微调 | 高 |
| 与 FA 交互 | head_dim/头数变则 kernel 分块变 | 无关 | FA+GQA 成熟 | 无关 |

常见组合拳：**头剪枝 → GQA → 量化（fp8/int8）→ FlashAttention**，服务端延迟与显存叠加受益。与**层剪枝**正交：一个减宽度（头），一个减深度。

## 六、常见误区

1. **所有头同等重要，均匀随机剪**——远差于按灵敏度剪；特殊头（位置、语法）必须保留。
2. **剪完不微调也能稳**——评估集平均可能不掉，长尾与鲁棒性常掉；至少轻量恢复训练。
3. **运行时 mask 头就算加速**——权重与计算若不物理收缩，FLOPs 不降；导出需重写形状。
4. **末层头全可剪**——经验偏向「深层更冗余」，但仍有个别深头负责长程依赖，要按数据定。
5. **头剪枝等于蒸馏**——蒸馏是换更小模型+软标签；头剪枝是在原架构上删通道，二者可叠加但机制不同。
6. **对已量化模型再剪头会线性叠加收益**——数值范围与 kernel 变化可能交互，需整体基准测试。

## 八、面试题

**1. 为何可安全剪掉部分注意力头？**  
要点：多头功能冗余、部分头对损失梯度贡献极小；residual + 微调让剩余头吸收功能。有灵敏度/消融证据支持，而非任意删。

**2. 头重要性常用哪些指标？**  
要点：梯度加权输出（一阶泰勒）、注意力熵与头间相似度、直接消融 $\Delta$L；实践中校准集 + 迭代剪枝最稳。

**3. 剪头如何影响推理显存与延迟？**  
要点：QKV/O 投影与 attention 计算随头数近似线性降；KV Cache 与 $h\cdot d_{\text{head}}$ 成正比。物理删头才省算力，mask 不省。

**4. 头剪枝和 GQA 有什么关系？**  
要点：都是减少 K/V 冗余。头剪枝删「不要的头」，GQA 让多个 Q 头共享 K/V；常先剪再分组，进一步压 Cache。

**5. 为什么浅层头更「金贵」？**  
要点：浅层常负责局部位置、词法等基础模式，是深层特征的输入；深层表示更可替代，消融曲线通常显示深层剪枝更平坦。

## 九、演进与趋势

- **训练时即瘦身**：动态头、可学习门控（straight-through），预训练阶段就控制头数，而非事后剪。
- **与 GQA/MQA/MLA 合流**：现代开源模型（Llama3、Qwen、DeepSeek 等）在设计期就砍 KV 头，事后头剪枝更多用于微调适配与边缘部署。
- **注意力结构可解释**：头聚类、稀疏字典（SAE）用更细粒度解释「哪些头在编码什么」，反过来指导剪枝与编辑。
- **端侧约束**：手机/NPU 对动态形状不友好，**静态头数 + 固定 head_dim** 的剪枝导出比运行时自适应更受青赖。
- **安全视角**：某些头承载「抗拒性/事实回溯」等行为，剪错可能改变安全对齐表现，需行为评测而不只是 PPL。

## 十、小结

注意力头冗余是「多头是否真的多头有效」的实证回答：**多数头可剪，少数头是骨干**。正确姿势是：用梯度/消融打分 → 按层配额剪枝 → 短程恢复训练 → 物理导出测延迟。它与 GQA、量化、FlashAttention 同属「把 Transformer 的冗余变成服务成本优势」的工具箱；面试与落地都要同时讲清**数学上的可删性**与**工程上的可加速性**——缺一，都只是论文里的消融表。
