# 高效注意力综述

> 对应 Efficient Transformers 综述（Tay et al., 2022）与 FlashAttention（Dao et al., 2022）。核心矛盾是 $O(n^2)$ 的复杂度。

## 一、背景与挑战

标准自注意力的时间与空间复杂度都是 $O(n^2)$（$n$ 为序列长度），长序列下成为瓶颈：8K 上下文就要存 $64\times$ 于 1K 的注意力矩阵。挑战是既要降低复杂度，又不能显著掉点，还要在 GPU 上真的跑得快（理论 FLOPs 低不等于实测快，访存往往才是瓶颈）。

## 二、核心原理

主要流派：

1. **稀疏/局部注意力**（Longformer、BigBird）：每个 token 只关注局部窗口 + 少量全局 token，复杂度降到 $O(n)$ 或 $O(n\log n)$。
2. **低秩/线性注意力**（Linformer、Performer、线性注意力）：用核技巧或投影近似 softmax，把复杂度降到 $O(n)$。
3. **IO 感知精确注意力**（FlashAttention）：不近似，通过分块（tiling）与重计算把 HBM 访存从 $O(n^2)$ 降到 $O(n)$，实测更快更省显存。
4. **硬件/系统优化**：多查询 MQA、分组查询 GQA 减少 KV Cache。

关键洞察：**很多场景下瓶颈是显存带宽而非算力**，所以 IO 感知的精确算法（FlashAttention）往往优于近似算法。

## 三、形式化与数学基础

标准注意力：

$$\text{Attn}(Q,K,V)=\text{softmax}\!\left(\frac{QK^\top}{\sqrt d}\right)V$$

复杂度 $O(n^2 d)$。线性注意力用特征映射 $\phi$：

$$\text{Attn}_{\text{lin}} = \phi(Q)\big(\phi(K)^\top V\big),\qquad O(nd^2)$$

FlashAttention 的分块 softmax（在线归一化，避免物化 $n\times n$ 矩阵）：

$$m^{\text{new}}=\max(m^{\text{old}},\tilde m),\quad \ell^{\text{new}}=e^{m^{\text{old}}-m^{\text{new}}}\ell^{\text{old}}+e^{\tilde m-m^{\text{new}}}\tilde\ell$$

## 四、代码实现

优先用框架内置的高性能实现（以版本为准）：

```python
import torch.nn.functional as F
# PyTorch scaled_dot_product_attention 会自动选择 Flash / mem-efficient 内核
out = F.scaled_dot_product_attention(q, k, v, is_causal=True)
```

自定义掩码时仍然可用，但要避免物化完整掩码矩阵，否则省下的显存又会被吃掉。

## 五、与其他技术对比

| 方法 | 复杂度 | 是否精确 | 长序列实测 |
|------|--------|---------|-----------|
| 标准注意力 | O(n²) | 是 | 慢 |
| 稀疏/局部 | O(n)–O(n log n) | 否 | 快 |
| 线性/核方法 | O(n) | 否 | 快，可能掉点 |
| FlashAttention | O(n²) FLOPs / O(n) 显存 | 是 | 很快 |
| MQA/GQA | 减 KV | 是 | 推理省显存 |

## 六、常见误区

- 认为线性注意力一定更快：小序列下开销反而更大。
- 忽略 IO 瓶颈：理论 FLOPs 低不等于实测快。
- 用了 Flash 又物化完整 mask：显存优势被抵消。
- 认为稀疏注意力无损失：长程依赖可能被切断，需保留全局 token。

## 九、演进与趋势

FlashAttention 系列成为事实标准；推理侧靠 GQA + Paged KV 降低显存；训练侧探索长上下文的序列并行（Ring/Context Parallel）；新一代硬件进一步抬高 IO 效率上限。

## 十、小结

高效注意力的选择顺序：先用 IO 感知的精确实现（FlashAttention），再考虑减少 KV（GQA/MQA），最后才用有损近似（稀疏/线性）并做充分评测。
