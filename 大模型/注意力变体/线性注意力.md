# 线性注意力 Linear Attention

> 对应 Katharopoulos et al., *Transformers are RNNs: Fast Autoregressive Transformers with Linear Attention* (ICML 2020)；Choromanski et al., *Rethinking Attention with Performers* (ICLR 2021)；Zhai et al. GLA、Gu et al. RetNet、Mamba 相关线性 SSM 讨论；与「注意力变体/FlashAttention原理」形成「精确 IO 优化 vs 改变复杂度」对照。长序列时代的复杂度换精度方案。

## 一、背景与挑战

标准自注意力：

$$ \text{Attn}(Q,K,V)=\text{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right)V $$

计算与存储都含 $n\times n$ 项：训练 FLOPs $\mathcal{O}(n^2 d)$，注意力矩阵显存 $\mathcal{O}(n^2)$（Flash 可避免物化但仍 $\mathcal{O}(n^2)$ 计算）。当 $n$ 到 32k～1M（文档库、视频、Agent 长轨迹），平方项成为墙。

线性注意力的主张：若能把 softmax 相似度写成**核函数** $\phi(q)\phi(k)^\top$，利用结合律先算 $\phi(K)^\top V$（$d\times d$，与 $n$ 无关），再乘 $\phi(Q)$，复杂度降到 $\mathcal{O}(n d^2)$——在 $d\ll n$ 时**对序列长度线性**。

挑战：(1) softmax 不可分，核近似会损精度；(2) 因果 mask 下的在线递推实现要稳；(3) 许多任务上长程检索/精确匹配掉点明显；(4) 与 MHA 多头、KV Cache 服务生态的兼容。因此「线性注意力」是一族方法与权衡，而不是单一替换开关。

## 二、核心原理

### 2.1 核技巧与结合律

若 $k(x,y)=\phi(x)^\top\phi(y)$，则

$$ \text{Attn}_k(Q,K,V)_i=\frac{\sum_j k(q_i,k_j)\,v_j}{\sum_j k(q_i,k_j)}
=\frac{\phi(q_i)^\top \big(\sum_j \phi(k_j) v_j^\top\big)}{\phi(q_i)^\top \big(\sum_j \phi(k_j)\big)} $$

矩阵形式：

$$ \text{LinearAttn}=\phi(Q)\big(\phi(K)^\top V\big)\big(\phi(Q)\phi(K)^\top \mathbf{1}\big)^{-1} $$

先聚合 $S=\phi(K)^\top V\in\mathbb{R}^{d\times d}$，推理时可像 RNN 一样递推：

$$ S_t=S_{t-1}+\phi(k_t)v_t^\top,\quad o_t=\frac{\phi(q_t)^\top S_t}{\phi(q_t)^\top z_t},\quad z_t=z_{t-1}+\phi(k_t) $$

这正是「Transformers are RNNs」的标题含义：训练并行（像 Transformer），推理常数状态递推（像 RNN）。

### 2.2 代表性核与变体

| 方法 | $\phi$ / 结构 | 特点 |
| --- | --- | --- |
| Linear Attention (KA) | elu+1 等 | 最早工程化之一 |
| Performer FAVOR+ | 随机特征近似 softmax | 无偏/有偏可控估计 |
| RetNet | 指数衰减 + 保留头 | 训练并行 + 推理线性状态 |
| GLA | 门控线性注意力 | 数据驱动衰减 |
| Mamba/SSM | 连续状态空间离散化 | 非严格「核注意力」但同属线性扫描 |

### 2.3 精度为何会掉

softmax 的尖峰选择性（接近 one-hot 匹配）对**精确复制、检索、强局部**有利；平滑核往往「弥散」相关度，长程 needle-in-haystack 变差。改进方向：局部窗口 + 全局线性头混合、可学习衰减、输出门控、与卷积/SSM 交错堆叠。

## 三、形式化与数学基础

标准注意力的行 softmax 归一化：

$$ y_i=\frac{\sum_j e^{q_i^\top k_j/\sqrt{d}}\,v_j}{\sum_j e^{q_i^\top k_j/\sqrt{d}}} $$

若 $e^{x}\approx \phi(x)$ 且 $\phi(x)=\tilde\phi(x)^\top$（有限维特征），则上式化为核注意力。FAVOR+ 用正随机特征：

$$ e^{q^\top k}\approx \mathbb{E}_{\omega}[\varphi(q;\omega)\varphi(k;\omega)],\quad \varphi(x;\omega)=e^{\omega^\top x/2-\|x\|^2/4}\cdot\text{basis} $$

复杂度对比（单头，忽略常数）：

$$ C_{\text{std}}=\mathcal{O}(n^2 d),\quad C_{\text{lin}}=\mathcal{O}(n d^2 + n d\, d_{\text{inner}}) $$

当 $n\gg d$ 时线性占优；短序列上常数因子与 kernel 效率反而不如高度优化的 FlashAttention。记忆化状态 $S_t\in\mathbb{R}^{d\times d}$ 的显存与 $d^2$ 有关，与 $n$ 无关——服务端长对话状态可控，但**可逆性/精确重放**弱于存完整 KV。

## 四、代码实现

```python
# 因果线性注意力（elU+1 特征），训练并行示意
import torch
import torch.nn.functional as F

def elu_feature(x):
    return F.elu(x) + 1.0

def linear_attn_parallel(q, k, v):
    # q,k,v: (B, n, d)
    phi_q, phi_k = elu_feature(q), elu_feature(k)
    # KV 聚合: (B, d, d)
    kv = torch.einsum("bnd,bne->bde", phi_k, v)
    z  = phi_k.sum(dim=1)                     # (B, d)
    num = torch.einsum("bnd,bde->bne", phi_q, kv)
    den = torch.einsum("bnd,bd->bne", phi_q, z).clamp_min(1e-6)
    return num / den

# 推理递推状态（常数内存）
class LinearKVCache:
    def __init__(self, d, device, dtype=torch.float32):
        self.S = torch.zeros(d, d, device=device, dtype=dtype)
        self.z = torch.zeros(d, device=device, dtype=dtype)
    def step(self, q_t, k_t, v_t):
        phi_k = elu_feature(k_t); phi_q = elu_feature(q_t)
        self.S = self.S + torch.outer(phi_k, v_t)
        self.z = self.z + phi_k
        return (phi_q @ self.S) / (phi_q @ self.z).clamp_min(1e-6)
```

落地时注意：数值上 $S$ 长程累积可能溢出/漂移，需要归一化或门控；多头分别维护 $S_h$；与 RoPE 的相容性要专门设计（部分方法用衰减替代位置编码）。

## 五、与其他技术对比

| 维度 | Softmax + Flash | 线性注意力 | 稀疏注意力 | SSM/Mamba |
| --- | --- | --- | --- | --- |
| 序列复杂度 | $\mathcal{O}(n^2)$ 计算 | **线性** | 近线性（依赖模式） | 线性 |
| 精度（长程检索） | 强 | 弱～中 | 中 | 中～强 |
| 推理状态 | KV Cache $\mathcal{O}(n)$ | $\mathcal{O}(d^2)$ | 窗口+地标 | $\mathcal{O}(dN)$ |
| 训练并行 | 是 | 是 | 是 | 是 |
| 生态成熟度 | **最高** | 上升中 | 中 | 上升中 |

与 **FlashAttention**：FA 不改数学，只改 IO；线性注意力**改数学**以换复杂度。两者可分别回答「同样的 softmax 注意力怎样更快」与「要不要还用 softmax 注意力」。

## 六、常见误区

1. **线性注意力是无损加速**——错，是近似/换族，任务相关掉点可能显著。
2. **所有长上下文都该上线性头**——检索/代码复现类负载慎用；混合架构更常见。
3. **推理状态 $\mathcal{O}(d^2)$ 一定比 KV 便宜**——$d$ 很大或量化策略不当时不一定；且状态压缩不可精确回滚。
4. **有 RoPE 就能随便换线性核**——位置与衰减耦合是设计难题，很多线性方法重做位置机制。
5. **Mamba 就是线性注意力**——同属「线性时序模型」家族，数学形式与门控不同，不完全等同。

## 八、面试题

**1. 线性注意力为何能把复杂度降到线性？**  
要点：用可分解核 $\phi(q)^\top\phi(k)$，结合律先做 $K^\top V$ 的 $d\times d$ 聚合再乘 $Q$，消除 $n^2$ 中间矩阵。

**2. 推理时为何像 RNN？**  
要点：维护状态 $S_t=\sum_{j\le t}\phi(k_j)v_j^\top$，每步 $O(d^2)$ 更新，状态与 $n$ 无关。

**3. 精度瓶颈在哪？**  
要点：核近似削弱 softmax 的尖峰选择性，长程精确匹配与检索易掉点；需门控、衰减、混合窗口等补偿。

**4. 和 FlashAttention 的本质区别？**  
要点：FA 精确等价、只优化 IO；线性注意力改变计算图与数学，以近似换线性复杂度。

**5. 何时选线性/SSM 而非标准注意力？**  
要点：极长序列、状态内存敏感、可接受少量任务损失时；重要子任务仍保留局部 softmax 窗口。

## 九、演进与趋势

- **门控与衰减**：GLA、RWKV、RetNet 让「线性状态」可数据驱动遗忘，改善语言建模。
- **混合栈**：每隔数层插全局 softmax/窗口注意力，兼顾局部分辨率与全局可达。
- **与 MoE/量化结合**：线性状态更适合常驻内存与整型核探索。
- **基准修正**：needle 任务之外增加多跳推理与代码补全基准，避免「长文假阳性」。
- **服务协议**：常数状态利于多轮 Agent 记忆压缩，但 checkpoint/回放语义需产品层定义。

## 十、小结

线性注意力用核分解把 $\mathcal{O}(n^2)$ 换成 $\mathcal{O}(n d^2)$，并得到 RNN 式常数推理状态，是长上下文军备竞赛中的重要一条技术线。它**不是免费午餐**：数学被改写、精确检索变难、生态仍在追标准 MHA。正确姿势是：短中序列继续 Flash 精确注意力，超长或状态受限场景评估线性/混合架构，并用真实业务指标而非单一 needle 分数做决策。
