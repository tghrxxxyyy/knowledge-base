# 交叉注意力

> 对应 Transformer（Vaswani et al., 2017）的编码器-解码器注意力与 Perceiver（Jaegle et al., 2021）。交叉注意力是两个序列之间的桥。

## 一、背景与挑战

自注意力处理「序列内部」的关系，而很多任务需要「两个序列之间」的对齐：机器翻译中源句到目标句、多模态中文本到图像、问答中问题到文档、以及 Perceiver 式用少量 latent 去查询大量输入。挑战：两个序列长度差异大时计算浪费；对齐质量决定任务上限；以及交叉注意力的 KV 在每个解码步都要重新读取，是推理显存与带宽的常驻开销。

## 二、核心原理

交叉注意力中，Query 来自目标序列 $Y$，Key/Value 来自源序列 $X$：

$$Q = YW_Q,\quad K = XW_K,\quad V = XW_V$$

$$\text{CrossAttn}(Y,X)=\text{softmax}\!\left(\frac{QK^\top}{\sqrt d}\right)V$$

与自注意力的区别仅在于 $Q$ 与 $K,V$ 来源不同。复杂度为 $O(n_y n_x d)$。

关键性质：
- **不对称**：$X$ 提供被查询的内容，$Y$ 决定查什么。
- **KV 可缓存**：编码器输出固定后，$K,V$ 只需算一次，解码每步复用。
- **可作为压缩器**（Perceiver）：用 $m\ll n$ 个 latent query 把 $n$ 个输入压缩到 $m$。

## 三、形式化与数学基础

注意力权重矩阵 $A\in\mathbb{R}^{n_y\times n_x}$：

$$A_{ij}=\frac{\exp(q_i^\top k_j/\sqrt d)}{\sum_{j'}\exp(q_i^\top k_{j'}/\sqrt d)}$$

输出 $O = AV$。若用 $m$ 个 latent（Perceiver）：

$$Z = \text{CrossAttn}(Z_{\text{latent}}, X)\in\mathbb{R}^{m\times d},\quad m\ll n_x$$

复杂度从 $O(n_y n_x)$ 降到 $O(m n_x)$。

## 四、代码实现

编码器-解码器交叉注意力（概念实现）：

```python
import torch.nn.functional as F
def cross_attn(q, kv, W_q, W_k, W_v):
    # q:  [B, n_y, d]  目标序列
    # kv: [B, n_x, d]  源序列（编码器输出）
    Q, K, V = q @ W_q, kv @ W_k, kv @ W_v
    return F.scaled_dot_product_attention(Q, K, V)
```

推理时把 `K, V` 缓存下来，解码每步只重算 `Q`。

## 五、与其他技术对比

| 机制 | Q 来源 | KV 来源 | 典型用途 |
|------|--------|---------|---------|
| 自注意力 | 同序列 | 同序列 | 上下文建模 |
| 交叉注意力 | 目标序列 | 源序列 | 翻译/多模态/检索 |
| 因果自注意力 | 同序列（掩码） | 同序列 | 自回归生成 |
| 交叉 + latent | 可学习 latent | 大输入 | 输入压缩 |

## 六、常见误区

- 认为交叉注意力必须双向：它是单向的（Y 查 X）。
- 忽略 KV 缓存：编码器固定后应复用，否则每步重算。
- 源序列过长不做压缩：复杂度随 $n_x$ 线性增长。
- 与自注意力混用时忘记位置编码：两序列应有各自的位置信息。

## 九、演进与趋势

在纯解码器架构中，交叉注意力部分被「把外部内容拼进上下文」取代；但在多模态（Q-Former）、检索增强（FiD）、编码器-解码器翻译中仍是核心；Perceiver 式 latent 压缩在长输入场景重新受到重视。

## 十、小结

交叉注意力是连接两个序列的标准机制，Q 来自查询方、KV 来自被查询方。工程要点是 KV 缓存复用与在 $n_x$ 很大时用 latent 压缩。
