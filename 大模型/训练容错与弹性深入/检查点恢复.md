# 检查点恢复机制

> 对应 一致性检查点与恢复（与 早停与检查点选择深入 共用）；与 训练容错与弹性深入 衔接。

## 一、背景与挑战

恢复不仅要还原权重，还需还原随机状态、数据迭代位置、学习率调度，否则训练轨迹偏离或不收敛。

## 二、核心原理

检查点保存模型、优化器状态、随机种子、step/dataloader 偏移、调度器状态；恢复时整体载入并跳过已训样本。

## 三、数学形式

恢复状态 $S=\{W, M, V, rng, step, lr\_sched, data\_offset\}$；载入后从 $step+1$ 续训且数据不重复。

## 四、代码实现

```python
ck = torch.load("ckpt.pt")
model.load_state_dict(ck["model"]); opt.load_state_dict(ck["opt"])
train_loader.load_state_dict(ck["data"])   # 恢复迭代位置
```

## 五、与其他对比

- 与 早停与检查点选择深入（存什么）一致。
- 与 分布式优化器深入（分片状态需聚合保存）配合。

## 六、常见误区

- 漏存 dataloader 偏移致样本重复（过拟合风险）。
- 漏存 RNG 致数据增强不可复现。

## 八、面试题

- 检查点需存哪些才算可恢复？答：权重、优化器状态、步数、数据偏移、RNG、调度器，缺一则轨迹偏离。

## 九、演进

仅权重 → 含优化器 → 全轨迹（数据/RNG）恢复。

## 十、小结

完整检查点恢复保障训练连续性，缺失任一状态都会破坏轨迹。
