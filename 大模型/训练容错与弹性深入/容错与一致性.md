# 容错与一致性保障

> 对应 分布式一致性（all-reduce 原子性、幂等恢复）；与 分布式优化器深入 衔接。

## 一、背景与挑战

故障常发生在梯度同步中途，若部分 worker 已更新、部分未，状态会不一致致结果错误。

## 二、核心原理

同步原语（AllReduce/Rendezvous）需保证屏障式完成；恢复时回滚到检查点再统一重跑该步，确保全局步一致、无部分提交。

## 三、数学形式

一致性要求 $\forall i,j:\ \text{step}_i=\text{step}_j$ 或整体回滚到 $t_{ckpt}$；禁止 "半步" 状态持久化。

## 四、代码实现

```python
try:
    dist.all_reduce(grad)
except dist.DistError:
    rollback_to_ckpt()        # 全 worker 一致回滚
```

## 五、与其他对比

- 与 异步优化器深入（异步易不一致）形成对照，容错偏好同步屏障。
- 与 训练容错与弹性深入 总览共构保障。

## 六、常见误区

- 部分 worker 跳过该步致梯度尺度不一致。
- 恢复后未重新 barrier 致后续步错位。

## 八、面试题

- 故障中同步如何保一致？答：屏障式原语保证整步原子，失败则全体回滚到检查点重跑该步。

## 九、演进

无屏障 → 同步屏障 → 原子回滚恢复。

## 十、小结

容错以原子同步与回滚保证全局一致，杜绝半步污染。
