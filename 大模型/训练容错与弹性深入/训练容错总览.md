# 训练容错总览（Fault Tolerance）

> 对应 大规模训练稳定性实践（如 OPT/Megatron 经验）；与 训练容错与弹性深入 各节衔接。

## 一、背景与挑战

千卡级训练动辄数天，单点硬件/网络故障会中断；需容错机制保障长任务可恢复、不重来。

## 二、核心原理

通过周期性持久化检查点、进程组健康探测、故障隔离与重启，使任务在节点失效后能回滚到最近一致状态继续训练。

## 三、数学形式

可恢复性目标：恢复后全局步数 $t\ge t_{last\_ckpt}$，数据加载偏移需对齐，避免重复/遗漏样本。

## 四、代码实现

```python
if rank == 0 and step % 500 == 0:
    torch.save({"step": step, "model": model.state_dict()}, f"ckpt_{step}.pt")
```

## 五、与其他对比

- 与 早停与检查点选择深入（检查点机制）是同一基础设施。
- 与 分布式优化器深入（状态分片）需协同保存分片状态。

## 六、常见误区

- 只存模型不存优化器/步数致恢复后发散。
- 检查点过稀致故障后丢失大量进度。

## 八、面试题

- 为何训练需容错？答：长任务单点故障普遍，容错避免重训、保障可恢复与成本可控。

## 九、演进

无容错 → 周期检查点 → 弹性可恢复训练。

## 十、小结

训练容错以检查点+健康探测支撑长任务，是大模型训练的刚需。
