# 沙箱隔离执行

> 对应 容器/微虚拟机沙箱（container/microVM sandbox）运行不可信代码。

## 一、背景与挑战

智能体可能生成并执行代码（如数据分析），代码不可信，必须在隔离环境受限运行。

## 二、核心原理

用容器或 microVM 提供独立文件系统、网络策略与资源配额（CPU/内存/时长）。禁止或审计外网出口，挂载只读数据卷，执行后销毁环境，保证宿主机不受影响。

## 三、数学形式

资源约束保证有界影响：

$$\forall r\in\{cpu,mem,time\},\ r_{used}\le r_{cap}$$

越界即杀进程，防止 Fork 炸弹等。

## 四、代码实现

```python
with Sandbox(net="none", mem_mb=256, timeout=30) as sb:
    out = sb.exec(untrusted_code)
```

## 五、与其他对比

- 与 权限最小化 叠加：沙箱是执行层、权限是授权层。
- 与 智能体可靠性与失败模式深入 共担执行崩溃隔离。

## 六、常见误区

- 仅限算力不限网络，数据仍可能被外传。
- 共享宿主机卷致逃逸风险。

## 八、面试题

- 沙箱为何要禁网络？答：防止不可信代码外泄数据或下载恶意载荷。

## 九、演进

无隔离 → 容器 → microVM+网络策略+资源配额。

## 十、小结

沙箱把“执行不可信代码”关进隔离盒，是运行自生成代码的安全底线。
