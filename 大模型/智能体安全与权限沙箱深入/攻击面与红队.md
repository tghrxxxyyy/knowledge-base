# 攻击面与红队测试

> 对应 提示注入（prompt injection）与 agent 红队（red-teaming）。

## 一、背景与挑战

智能体读取外部内容（网页、邮件、文件），这些内容可嵌入恶意指令诱导其越权。需主动发现漏洞。

## 二、核心原理

红队构造对抗样本（注入指令、伪装工具返回、诱导泄露凭证），在仿真环境规模化探测失败模式。重点防护：不可信输入与指令严格隔离、输出做敏感信息过滤、工具调用二次校验。

## 三、数学形式

攻击成功率：

$$ASR = \frac{N_{successful\_attack}}{N_{total}}$$

红队目标是在上线前把 ASR 压到可接受阈值下。

## 四、代码实现

```python
for attack in redteam_suite:
    ok = simulate(agent, inject(attack))
    log(asr=ok)
```

## 五、与其他对比

- 与 智能体可靠性与失败模式深入 共担失败分类。
- 与 ToolEmu 风险评测同源。

## 六、常见误区

- 只防显式“忽略上文”而忽略间接注入。
- 红队只在安全环境，未覆盖真实工具副作用。

## 八、面试题

- 提示注入为何对 agent 尤其危险？答：agent 会据“被注入指令”真的调用工具，危害被放大。

## 九、演进

单轮防护 → 注入分类 → 红队规模化+输出过滤。

## 十、小结

红队把“未知漏洞”变成“已知清单”，是安全闭环的必要一环。
