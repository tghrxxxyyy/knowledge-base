# 权限最小化设计

> 对应 最小权限原则（Principle of Least Privilege）在 agent 工具上的应用。

## 一、背景与挑战

给智能体一把“万能钥匙”极其危险。需要按任务动态授予恰好够用的权限。

## 二、核心原理

工具声明所需 scope（读/写、对象、时间窗）。运行时按任务上下文签发短期、细粒度凭证（capability token）。任务结束即回收。避免长期全域凭证驻留。

## 三、数学形式

权限集合满足最小化：

$$|scope_{granted}| = \min\{|S|: \text{task feasible under } S\}$$

且有效期 $t_{exp}$ 短。

## 四、代码实现

```python
token = issuer.mint(scope=["file:read:/tmp"], ttl=300)
tool.exec(args, auth=token)
```

## 五、与其他对比

- 与 校验与回滚 互补：权限前置、校验后置。
- 与 智能体安全总览 同属纵深一层。

## 六、常见误区

- 凭证长期有效，泄露后持续可用。
- scope 过于宽泛（如 file:write:*）。

## 八、面试题

- 为何用短期凭证？答：降低泄露后的可用窗口，配合任务结束回收。

## 九、演进

静态全权限 → 角色权限 → 短期细粒度凭证。

## 十、小结

最小化权限把“能做”收敛到“只需做”，显著压缩风险面。
