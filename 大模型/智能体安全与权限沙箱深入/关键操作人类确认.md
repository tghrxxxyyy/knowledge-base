# 关键操作人类确认

> 对应 Human-in-the-loop 在危险动作上的强制确认。

## 一、背景与挑战

即便有沙箱，部分操作（真实付款、对外群发、删除生产数据）后果不可撤销，需人把关。

## 二、核心原理

对风险等级高的工具调用插入确认闸门：把“将要执行的动作+影响范围”呈现给人类，获显式批准才放行。确认信息应具体（而非笼统“是否继续”）。

## 三、数学形式

放行条件：

$$execute = \mathbb{1}[risk(a) \ge \tau_{human}] \cdot approve(human, a)$$

未达阈值或人拒则转降级/放弃。

## 四、代码实现

```python
if risk(action) >= HIGH:
    if not human.confirm(f"将执行:{action} 影响:{impact}"):
        return abort()
```

## 五、与其他对比

- 与 人机协作与人在环深入 共享确认节点设计。
- 与 降级与兜底 衔接“人拒后如何收场”。

## 六、常见误区

- 确认提示过于模糊，人习惯性点同意。
- 高频低风险也弹确认，人疲劳后懈怠。

## 八、面试题

- 确认提示为何要具体？答：让人真正评估影响，避免默认同意形同虚设。

## 九、演进

无确认 → 笼统确认 → 风险分级+具体影响确认。

## 十、小结

人类确认是高风险动作的最后闸门，设计好坏决定其是否真有效。
