# 编码器与解码器对比

> 对应 Vaswani et al., *Attention Is All You Need*, 2017；以及「预训练范式演变」相关综述。

## 一、背景与挑战

Transformer 提出后衍生出三种主流形态：encoder-only、decoder-only、encoder-decoder。选型常让人困惑：为什么 BERT 类用于理解、GPT 类用于生成？为什么今天大模型几乎全是 decoder-only？理解编码器与解码器在「注意力类型、信息流、任务适配」上的根本差异，是模型选型的理论基础。

## 二、核心原理

同一 Transformer 块由自注意力 + 前馈组成，三者区别在于注意力掩码与堆叠方式：

- **编码器（Encoder）**：双向自注意力，每个 token 可见全序列左右文，产出「上下文化表示」。
- **解码器（Decoder）**：因果自注意力（causal mask），第 $t$ 个 token 只能看 $\le t$ 的位置，逐词自回归生成。
- **编码器-解码器（Encoder-Decoder）**：编码器双向编码源，解码器通过**交叉注意力（cross-attention）** 查询编码器输出，适合「源→目标」映射（翻译、摘要）。

编码器解决「表示」，解码器解决「生成」。

## 三、形式化与数学基础

编码器自注意力无掩码，注意力权重 $A_{ij}\propto q_i^\top k_j$（全 $j$）。解码器加因果掩码 $\mathcal{M}$：

$$
A_{ij} = \frac{q_i^\top k_j}{\sqrt{d}}\quad \text{若 } j\le i,\; \text{否则 } -\infty
$$

encoder-decoder 交叉注意力中，解码器 query 来自自身、key/value 来自编码器输出：

$$
\text{CrossAttn}(Q_d, K_e, V_e) = \text{softmax}\!\left(\frac{Q_d K_e^\top}{\sqrt{d}}\right) V_e
$$

信息流：encoder 双向汇聚 $\rightarrow$ decoder 单向生成 $\rightarrow$ cross-attn 注入源信息。

## 四、代码实现

PyTorch 中因果掩码构造示意：

```python
import torch, torch.nn.functional as F

def causal_mask(seq_len):
    # 下三角为 1，上三角为 0（后续转 -inf）
    return torch.tril(torch.ones(seq_len, seq_len)).bool()

def attn(q, k, v, mask=None):
    scores = q @ k.transpose(-2, -1) / (q.size(-1) ** 0.5)
    if mask is not None:
        scores = scores.masked_fill(~mask, float("-inf"))
    return F.softmax(scores, dim=-1) @ v

# 编码器用 mask=None（双向），解码器用 causal_mask
```

## 五、与其他技术对比

| 形态 | 注意力 | 代表 | 擅长 | 不擅长 |
|------|--------|------|------|--------|
| encoder-only | 双向 | BERT | 理解/NLU、检索 | 生成 |
| decoder-only | 因果 | GPT/LLaMA | 生成、通用 LLM | 需要源对齐的映射 |
| encoder-decoder | 双向+交叉 | T5/BART | 翻译、摘要 | 部署复杂 |

## 六、常见误区

- 「解码器不能做理解」：decoder-only 通过双向预训练（如纯 CLM）也能理解，只是表示不显式分离。
- 「encoder-decoder 总比 decoder-only 好」：翻译/摘要上常占优，但通用能力与部署效率上 decoder-only 更胜。
- 「交叉注意力可被自注意力替代」：在长源场景下交叉注意力更聚焦，难以简单替代。
- 「现代 LLM 不用编码器」：RAG 中检索器常是编码器，二者常配合而非互斥。

## 九、演进与趋势

decoder-only 凭借规模化与通用性成为 LLM 主流；encoder-decoder 在翻译、摘要、多模态（如图文对齐）仍有价值；编码器则退居「表示/检索」专家（RAG 检索器、句向量）。混合架构（如 decoder + 检索编码器）正成为兼顾生成与事实性的主流方案。

## 十、小结

编码器（双向、表示）、解码器（因果、生成）、编码器-解码器（双向+交叉、映射）因注意力类型不同适配不同任务。现代 LLM 以 decoder-only 为主，但编码器在检索/RAG 中仍是关键组件。具体选型以任务与部署约束为准。
