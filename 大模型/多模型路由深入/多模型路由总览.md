# 多模型路由总览

> 对应 Shnitzer et al., *Routing Multiple Large Language Models with Partial Runtime Prediction*, 2023（arXiv:2308.03762）；与 多模型路由深入 / 服务框架深入 衔接。

## 一、背景与挑战

同时部署多个 LLM（强/弱、贵/廉），如何把请求派给合适的模型以省成本保质量。

## 二、核心原理

路由器依据请求特征/难度预测，把简单请求发小模型、难题发大模型，或以置信度触发升级（cascade）。

## 三、数学形式

路由目标 $\min \mathbb E[\text{cost}] + \lambda\cdot(1-\text{quality})$；约束 $\text{quality}\ge Q_{min}$。

## 四、代码实现

```python
model = router.select(req)            # 轻量分类器
if confidence(model(req)) < thr:
    model = strong_model              # 升级
```

## 五、与其他对比

- 与 服务框架深入（路由后由框架执行）上下游。
- 与 优先级调度深入（路由+调度协同）相关。

## 六、常见误区

- 路由模型本身开销吃掉节省。
- 难度估计不准致质量下滑。

## 八、面试题

- 多模型路由意义？答：按难度/成本把请求分给合适模型，在质量约束下最大化性价比。

## 九、演进

单模型 → 固定分流 → 学习式路由 + 级联。

## 十、小结

多模型路由用“合适模型做合适事”提升性价比，是成本控制核心。
