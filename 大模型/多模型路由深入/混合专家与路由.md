# 混合专家与路由

> 对应 Fedus et al., *Switch Transformers: Scaling to Trillion Parameter Models*, JMLR 2021（MoE 路由）；与 多模型路由深入 衔接。

## 一、背景与挑战

MoE 在模型内部用多个专家 + 门控路由，类比系统级多模型路由。

## 二、核心原理

每 token 经门控 $G$ 选 top-k 专家计算，稀疏激活在参数量增大同时控制计算量。

## 三、数学形式

$y=\sum_{i\in \text{topk}(G(x))} G(x)_i E_i(x)$；路由熵约束防专家坍塌。

## 四、代码实现

```python
weights, idx = gate(x).topk(k=2)
y = (weights * experts[idx](x)).sum(-1)
```

## 五、与其他对比

- 与 多模型路由深入（系统级路由）是微观对应。
- 与 优先级调度深入（负载均衡）共享均衡思想。

## 六、常见误区

- 门控失衡致少数专家过热，需辅助负载损失。
- top-k 路由引入通信开销。

## 八、面试题

- MoE 路由作用？答：每 token 选少量专家稀疏激活，扩参数而不线性增算力，需防负载失衡。

## 九、演进

稠密 → top-1 MoE → top-k + 负载均衡。

## 十、小结

MoE 把路由嵌入模型，是参数规模化与计算高效的统一范式。
