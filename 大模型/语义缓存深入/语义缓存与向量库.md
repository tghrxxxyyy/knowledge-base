# 语义缓存与向量库

> 对应向量数据库选型；向量数据库选型与调优实战 衔接。

## 一、背景与挑战

缓存规模增长需稳定向量存储与低延迟检索。

## 二、核心原理

用向量库（FAISS/Milvus/Redis）存查询嵌入与答案映射；支持增删与持久化，配合 TTL 淘汰。

## 三、数学形式

存储开销 $O(N\cdot d)$ 嵌入 + $O(N)$ 答案；检索 $O(\log N)$（图索引）。

## 四、代码实现

```python
milvus.insert([emb], [answer])   # 回填
hits = milvus.search(emb, top_k=1, radius=tau)
```

## 五、与其他对比

- 与 向量数据库选型与调优实战 共享选型。
- 与 提示缓存深入（KV）存储形态不同。

## 六、常见误区

- 缓存无限增长致检索变慢、成本升。
- 未做持久化重启丢缓存。

## 八、面试题

- 语义缓存如何存？答：向量库存查询嵌入与答案映射，支持增删、TTL 与持久化。

## 九、演进

内存字典 → 向量库 → 分布式向量缓存。

## 十、小结

语义缓存依赖向量库做规模化管理，需淘汰与持久化。
