# 数据库与缓存选型实战

> 板块：技术选型 　|　 返回：[README](README.md)

## 一、选型第一原则

先问三个问题：数据规模、一致性要求、读写比。别一上来就追新，先用熟、够用、能运维的方案。

## 二、关系型数据库选型

| 数据库 | 优势 | 适用 |
|--------|------|------|
| MySQL | 生态全、8.0 强、易运维 | 通用 OLTP |
| PostgreSQL | 功能强、扩展多、JSONB | 复杂查询/地理 |
| TiDB | 兼容 MySQL、水平扩展 | 海量且需 SQL |
| Oracle | 企业级强一致 | 大型政企/金融 |

- 单表 < 5000 万行、QPS < 1 万：单库足够，别上分库分表。
- 需要强事务（账务）：关系型 + 本地事务。

## 三、KV / 缓存选型

- **Redis**：内存 KV + 多种结构（String/Hash/ZSet/Stream），缓存/排行榜/分布式锁首选。
- **Memcached**：纯 KV、简单高性能，但功能少。
- **RocksDB**：嵌入式 LSM KV，本地持久化，适合做存储引擎底层。

## 四、文档 / 搜索

- **MongoDB**：Schema 灵活，迭代快，但事务弱、分析弱。
- **Elasticsearch**：全文检索 + 聚合分析，近实时。
- **ClickHouse**：列存 OLAP，亿级聚合秒级。

## 五、消息队列选型

| MQ | 特点 | 适用 |
|----|------|------|
| Kafka | 高吞吐、持久、流处理 | 日志/事件流 |
| RocketMQ | 事务消息、低延迟 | 电商交易 |
| Pulsar | 存算分离、多租户 | 云原生 |
| RabbitMQ | 易用、灵活路由 | 中小业务 |

## 六、缓存选型与场景

- 热点读：Redis 单机/集群。
- 本地缓存：Caffeine（进程内，抗读热点）。
- 多级：本地 → Redis → DB。

## 七、OLAP 选型

- 实时分析：ClickHouse / Doris。
- 离线数仓：Hive / Spark。
- 即席查询：Presto/Trino。

## 八、时序数据库

- **InfluxDB / VictoriaMetrics / Prometheus TSDB**：监控指标存储。

## 九、图数据库

- **Neo4j / Nebula**：关系网络、风控、推荐。

## 十、选型 checklist

1. 数据量 + 增长曲线。
2. 一致性强度（强/最终）。
3. 读写比（读多→缓存、写多→分区）。
4. 团队熟悉度与运维能力。
5. 成本（自建 vs 云托管）。

## 十一、常见误区

1. 小项目上分库分表 → 过度设计。
2. 用 Redis 当源数据 → 丢数据风险。
3. 选 MQ 只看吞吐不看可靠性。
4. 忽视运维成本（自建 ES/Kafka 集群很重）。
