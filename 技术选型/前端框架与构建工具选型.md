# 前端框架与构建工具选型

> 板块：技术选型 　|　 返回：[README](README.md)
> 适用：Web 应用、中后台、移动 H5、跨端、可视化。

前端选型已从"框架之争"演进为"框架 + 渲染模式 + 构建工具 + 跨端"的组合决策。核心是匹配**团队熟悉度、应用类型、性能与体验要求**。

## 一、主流框架对比

| 框架 | 特点 | 适用 |
|------|------|------|
| React | 生态最大、灵活、函数组件+Hooks | 大型 SPA、复杂交互 |
| Vue | 上手快、渐进式、中文友好 | 中后台、快速开发 |
| Angular | 全家桶、强约束、企业级 | 大型企业应用 |
| Svelte | 编译时、体积小、性能好 | 性能敏感/轻量 |
| Solid | 细粒度响应式、高性能 | 性能极致场景 |

> 框架差异在缩小，团队熟悉度往往比特性更重要。

## 二、渲染模式

| 模式 | 说明 | 优缺点 |
|------|------|--------|
| CSR（客户端渲染） | 浏览器渲染 | 简单，首屏慢/SEO 差 |
| SSR（服务端渲染） | 服务端出 HTML | 首屏快、SEO 好，需 Node 服务 |
| SSG（静态生成） | 构建时生成 | 极快，适合内容站 |
| ISR（增量静态） | SSG + 定时/按需重生成 | 兼顾动态与性能 |

- Next.js（React）、Nuxt（Vue）是 SSR/SSG 主流方案。
- 选型：内容/营销站用 SSG/ISR；强交互后台用 CSR/SSR。

## 三、状态管理

| 方案 | 特点 |
|------|------|
| Redux/Zustand（React） | 可预测/轻量 |
| Pinia（Vue） | 官方推荐、简洁 |
| 内置（Signal/Context） | 轻场景够用 |

> 避免过度设计：中小应用内置/轻量方案即可。

## 四、构建工具

| 工具 | 特点 | 趋势 |
|------|------|------|
| Webpack | 成熟、插件多、慢 | 存量项目 |
| Vite | 基于 ESM、极速冷启、HMR | 新项目主流 |
| esbuild/SWC | Go/Rust 编译，极快 | 底层加速 |
| Turbopack/Rspack | 增量/兼容 Webpack | 大型项目提速 |

> Vite 已成为新项目默认；Webpack 存量仍大量存在。

## 五、跨端与多端

| 方案 | 说明 |
|------|------|
| React Native / Flutter | 原生跨端 App |
| Taro/uni-app | 小程序多端 |
| Electron/Tauri | 桌面应用 |
| Web + PWA | 轻量跨端 |

## 六、组件库与 UI

- 中后台：Ant Design（React）、Element Plus（Vue）、Arco。
- 移动端：Ant Design Mobile、Vant。
- 设计系统：自研 Design Token + 组件库，保证一致性。

## 七、工程化要素

- **TypeScript**：类型安全，大型项目标配。
- **Monorepo**：pnpm workspace / Turborepo / Nx，多包复用。
- **质量**：ESLint + Prettier + 单测（Vitest/Jest）+ CI。
- **性能**：代码分割、懒加载、CDN、骨架屏。

## 八、选型决策框架

1. 应用类型：内容站/后台/互动应用/跨端？
2. 团队栈：熟悉 React 还是 Vue？
3. 性能与 SEO：要 SSR 吗？
4. 长期维护：生态与人才供给。
5. 构建速度：大仓需 Turbopack/Rspack。

## 九、常见坑

1. **盲目追新框架** → 团队不熟返工；选熟悉栈。
2. **SSR 无 Node 运维** → 部署复杂；评估运维能力。
3. **状态管理过度** → 简单页用 Redux 冗余；按需。
4. **构建配置混乱** → 慢且难维护；Vite + 标准化。
5. **忽视性能** → 首屏慢；代码分割 + 懒加载。
6. **多端重复开发** → 成本高；跨端框架统一。
