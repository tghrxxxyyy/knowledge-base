# 编排调度与工作流选型实战

> 从定时任务到复杂 DAG 工作流，编排调度是数据管道与自动化的大脑。本文对比 Airflow、Dagster、Prefect、K8s CronJob、Temporal 等，给出选型指南。

## 1. 编排需求分层

| 需求 | 工具 |
| --- | --- |
| 简单定时 | Cron / K8s CronJob |
| 数据管道 DAG | Airflow / Dagster |
| 现代 Python 工作流 | Prefect |
| 长流程/状态机 | Temporal |
| 微服务编排 | 工作流引擎（如 Cadence） |

## 2. 主流对比

| 工具 | 模型 | 优点 | 注意 |
| --- | --- | --- | --- |
| Airflow | DAG + Python | 生态最大、成熟 | 调度重、实时弱 |
| Dagster | 资产/类型 | 数据资产观、可测 | 较新 |
| Prefect | 流式 API | 易用、混合执行 | 生态成长中 |
| Temporal | 持久工作流 | 长流程/恢复强 | 概念重 |
| K8s CronJob | 容器定时 | 轻量、K8s 原生 | 无 DAG 依赖 |

## 3. Airflow 核心

```python
from airflow import DAG
from airflow.operators.python import PythonOperator
with DAG("etl", schedule="@daily") as dag:
    t1 = PythonOperator(task_id="extract", python_callable=extract)
    t2 = PythonOperator(task_id="load", python_callable=load)
    t1 >> t2
```

- DAG 定义依赖，调度器按时触发。
- 任务失败重试、告警、回填（backfill）。
- 适合批处理数据管道。

## 4. Temporal 长流程

- 把业务流程写成"持久工作流"，可运行数天、自动恢复。
- 状态由引擎持久化，进程崩了也能续。
- 适合订单履约、审批流等需长时一致性的场景。

## 5. 选型要点

- **批 vs 流**：批管道选 Airflow 系；实时流选 Flink/Spark Streaming。
- **DAG 复杂度**：简单依赖用 CronJob；复杂依赖用 Airflow。
- **长流程状态**：需持久恢复选 Temporal。
- **团队栈**：已在 K8s 上，CronJob/Argo Workflows 更顺。

## 6. 可靠性设计

- 任务幂等，支持重试不重复副作用。
- 失败告警 + 死信处理。
- 调度高可用：避免单点调度器。
- 执行环境隔离（容器化）。

## 7. 与数据质量

- 管道中嵌入数据校验（Great Expectations / dbt tests）。
- 失败阻断下游，防脏数据扩散。

## 8. 落地坑点

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 任务非幂等 | 重跑出错 | 幂等设计 |
| 调度单点 | 全停 | HA 部署 |
| DAG 失控 | 依赖环 | 静态检查 |
| 资源争抢 | 卡顿 | 资源配额 |

## 10. 小结

编排调度选型 = 复杂度 × 长流程诉求 × 团队栈。简单定时用 CronJob，数据 DAG 用 Airflow 系，长时一致流程用 Temporal，关键是任务幂等与高可用。
