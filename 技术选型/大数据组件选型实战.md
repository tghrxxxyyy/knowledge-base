# 大数据组件选型实战

> 板块：技术选型 　|　 返回：[README](README.md)
> 适用：离线数仓、实时流处理、日志分析、数据湖、OLAP 查询。

大数据选型本质是**按"数据规模/时延/查询模式"匹配组件**。没有一个组件通吃批、流、交互式分析，通常用"组合拳"。

## 一、需求维度

| 维度 | 问题 |
|------|------|
| 数据量 | GB / TB / PB？ |
| 时延 | 批（T+1）/ 近实时（秒）/ 实时（毫秒）？ |
| 查询 | 即席交互（ad-hoc）/ 固定报表 / 全文检索？ |
| 写入 | 批量导入 / 流式写入 / 高并发点写？ |
| 生态 | 是否已有 Hadoop/K8s 体系？ |

## 二、批处理

| 组件 | 特点 | 适用 |
|------|------|------|
| Spark | 内存计算、生态全、SQL/ML | 通用批处理、ETL |
| Hive/MR | 稳定、慢、SQL on Hadoop | 传统数仓 |
| Flink Batch | 流批一体 | 已有 Flink 栈 |
| Dagster/Airflow | 编排调度 | 工作流编排 |

## 三、流处理

| 组件 | 特点 | 适用 |
|------|------|------|
| Flink | 精确一次、状态管理、低延迟 | 实时计算、CEP |
| Kafka Streams | 轻量、与 Kafka 紧耦合 | 简单流处理 |
| Spark Streaming | 微批、易上手 | 准实时 |
| Storm | 老牌、低延迟 | 遗留 |

## 四、消息/数据总线

- **Kafka**：高吞吐、持久、流处理基石，几乎标配。
- **Pulsar**：存算分离、多租户、分层存储。
- 选型：Kafka 生态成熟优先；需多租户/分层存储看 Pulsar。

## 五、存储与数据湖

| 组件 | 特点 | 适用 |
|------|------|------|
| HDFS | 海量文件存储 | 传统 Hadoop |
| S3/对象存储 | 云原生、便宜 | 数据湖底座 |
| Hudi/Iceberg/Delta | 表格式、ACID、时间旅行 | 数据湖仓（Lakehouse） |
| Parquet/ORC | 列式存储 | 分析友好 |

> Lakehouse（湖仓一体）：对象存储 + 表格式（Iceberg/Hudi）+ 计算引擎（Spark/Trino），兼顾灵活与性能。

## 六、OLAP / 即席查询

| 组件 | 特点 | 适用 |
|------|------|------|
| ClickHouse | 列存、极速聚合、单表强 | 实时分析、日志 |
| Doris/StarRocks | MPP、高并发、MySQL 协议 | 报表/即席 |
| Druid | 时序预聚合 | 监控/事件 |
| Trino/Presto | 跨源联邦查询 | 数据湖即席 |
| Elasticsearch | 全文+聚合 | 搜索/日志 |

## 七、日志与检索

- **ELK（Elasticsearch+Logstash+Kibana）**：日志集中检索与可视化。
- **Loki**：轻量、标签索引、成本友好。
- **ClickHouse 存日志**：超大量日志低成本分析。

## 八、编排与治理

- **调度**：Airflow/DolphinScheduler（DAG 编排）。
- **元数据/血缘**：Atlas/DataHub（数据资产、血缘）。
- **质量**：Great Expectations/自研（数据校验）。
- **权限**：Ranger/自研（行列级）。

## 九、典型组合方案

| 场景 | 组合 |
|------|------|
| 实时数仓 | Kafka + Flink + Iceberg + Doris |
| 日志分析 | 采集 + Kafka + ES/Loki |
| 离线数仓 | HDFS/S3 + Hive/Spark + 调度 |
| 湖仓一体 | S3 + Iceberg + Trino/Spark + Doris 加速 |

## 十、常见坑

1. **组件堆砌** → 运维灾难；按需求最小集。
2. **流批两套代码** → 维护双倍；流批一体（Flink）。
3. **小数据上重型 Hadoop** → 过度工程；小量用单机/轻量。
4. **数据湖无治理** → 成数据沼泽；元数据+质量+权限。
5. **OLAP 选错** → 查询慢；按查询模式（聚合 vs 即席 vs 全文）选型。
6. **Kafka 无分区规划** → 热点/扩容难；合理 partition + key。
