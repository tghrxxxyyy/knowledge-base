# 结构型设计模式实战

> 结构型模式关注"类与对象如何组合成更大结构"，在不改原有代码的前提下扩展功能或简化接口。本文覆盖适配器、装饰器、代理、桥接、组合、外观、享元七种。

## 1. 适配器（Adapter）

把一个接口转成客户端期望的另一种接口。

```java
// 旧接口
class LegacyUserService { String getNameOld(){ return "老用户"; } }
// 目标接口
interface UserService { String getUserName(); }
// 适配器
class UserServiceAdapter implements UserService {
    LegacyUserService legacy;
    public String getUserName(){ return legacy.getNameOld(); }
}
```

适用：集成第三方/遗留系统，避免改调用方。

## 2. 装饰器（Decorator）

动态给对象加职责，比继承灵活。

```python
class Coffee:
    def cost(self): return 10
class Milk(Coffee):
    def __init__(self, c): self.c = c
    def cost(self): return self.c.cost() + 3
# 使用
c = Milk(Coffee())  # 加奶咖啡 13
```

- 层层包裹，开闭友好。
- Java IO（`BufferedInputStream(InputStream)`）是经典例子。
- 坑：装饰链过长难调试。

## 3. 代理（Proxy）

为对象提供替身以控制访问。

```java
interface Subject { void request(); }
class RealSubject implements Subject { public void request(){ /* 真实 */ } }
class Proxy implements Subject {
    RealSubject real;
    public void request(){
        if (real == null) real = new RealSubject(); // 懒加载
        // 可加鉴权/日志/缓存
        real.request();
    }
}
```

- 静态代理：手写；动态代理：JDK/ CGLIB 运行时生成。
- 适用：远程代理、虚拟代理、保护代理。

## 4. 桥接（Bridge）

分离抽象与实现，让两者独立变化。

```java
interface Renderer { void render(String s); }
class VectorRenderer implements Renderer { public void render(String s){ /*矢量*/ } }
abstract class Shape {
    Renderer r;
    Shape(Renderer r){ this.r = r; }
    abstract void draw();
}
```

- 避免"类爆炸"（每组合一个子类）。
- 适用：抽象与实现多维度变化。

## 5. 组合（Composite）

树形结构，叶子与容器统一处理。

```java
interface Node { void show(); }
class File implements Node { public void show(){ /* 文件 */ } }
class Dir implements Node {
    List<Node> children;
    public void show(){ for(Node n: children) n.show(); }
}
```

适用：菜单、文件系统、组织架构。

## 6. 外观（Facade）

为复杂子系统提供统一入口。

```java
class HomeTheaterFacade {
    void watchMovie(){ amp.on(); dvd.play(); light.dim(); }
}
```

- 降低调用方复杂度。
- 坑：外观变"上帝类"，应只封装常用组合。

## 7. 享元（Flyweight）

共享细粒度对象，节省内存。

```java
// 字符/连接池等大量重复对象场景
Map<String, Character> pool = new HashMap<>();
Character get(char c){ return pool.computeIfAbsent(String.valueOf(c), Character::new); }
```

适用：大量相似对象（如文本编辑字符、线程池）。

## 8. 选型对比

| 模式 | 关键 | 场景 |
| --- | --- | --- |
| 适配器 | 接口转换 | 兼容遗留 |
| 装饰器 | 动态加功能 | 功能叠加 |
| 代理 | 访问控制 | 懒加载/鉴权 |
| 桥接 | 抽象/实现分离 | 多维变化 |
| 组合 | 树形统一 | 层级结构 |
| 外观 | 统一入口 | 降复杂度 |
| 享元 | 对象共享 | 大量重复 |

## 10. 小结

结构型模式用组合而非继承扩展能力：装饰器加功能、代理控访问、桥接解耦维度、组合处理层级、享元省内存。识别"对象如何组织"比死记结构更重要。
