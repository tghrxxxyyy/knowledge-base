# 创建型设计模式实战

> 创建型模式关注"对象如何被创建"，目标是解耦创建逻辑与使用逻辑，提升灵活性。本文覆盖单例、工厂方法、抽象工厂、建造者、原型五种，含代码示例与选型。

## 1. 单例（Singleton）

保证一个类只有一个实例，并提供全局访问点。

```java
public class Singleton {
    private static volatile Singleton instance;
    private Singleton() {}
    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

- 双重检查锁需 `volatile` 防指令重排。
- 推荐用枚举单例（天然防反射/序列化破坏）或容器托管（Spring 默认单例）。
- 坑：多线程安全、反射破坏、测试困难（全局状态）。

## 2. 工厂方法（Factory Method）

父类定义创建接口，子类决定具体类型。

```java
interface Transport { void deliver(); }
class Truck implements Transport { public void deliver(){ System.out.println("陆运"); } }
class Ship implements Transport { public void deliver(){ System.out.println("海运"); } }

abstract class Logistics {
    abstract Transport createTransport();
    void plan() { createTransport().deliver(); }
}
class RoadLogistics extends Logistics {
    Transport createTransport() { return new Truck(); }
}
```

适用：创建逻辑随子类变化，避免 `new` 散落。

## 3. 抽象工厂（Abstract Factory）

创建一组相关对象（产品族）。

```java
interface GUIFactory {
    Button createButton();
    Checkbox createCheckbox();
}
class WinFactory implements GUIFactory {
    public Button createButton(){ return new WinButton(); }
    public Checkbox createCheckbox(){ return new WinCheckbox(); }
}
```

适用：需要保证一组对象风格一致（如跨平台 UI）。代价：新增产品需改接口，违反开闭。

## 4. 建造者（Builder）

分步构造复杂对象，避免巨型构造函数。

```java
User u = User.builder()
    .name("张三").age(30).email("a@b.com").build();
```

- 链式调用清晰，支持可选参数。
- Lombok `@Builder`、Effective Java 手写皆可。
- 坑：build() 前对象不完整，注意校验。

## 5. 原型（Prototype）

通过克隆创建对象，避免昂贵初始化。

```java
class Sheep implements Cloneable {
    String name;
    public Sheep clone() throws CloneNotSupportedException {
        return (Sheep) super.clone();  // 浅克隆
    }
}
```

- 注意浅克隆 vs 深克隆（引用字段需递归克隆）。
- 适用：对象创建成本高、结构相似。

## 6. 选型对比

| 模式 | 解决 | 典型场景 |
| --- | --- | --- |
| 单例 | 唯一实例 | 配置/连接池 |
| 工厂方法 | 子类决定类型 | 插件式创建 |
| 抽象工厂 | 产品族一致 | 跨平台 |
| 建造者 | 复杂对象 | 多参数对象 |
| 原型 | 克隆创建 | 高成本初始化 |

## 7. 常见坑

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 单例不线程安全 | 多实例 | 双重检查/枚举 |
| 工厂爆炸 | 类过多 | 配合配置化 |
| 建造者漏校验 | 非法对象 | build 中校验 |
| 原型浅克隆 | 共享引用 | 深克隆 |

## 9. 小结

创建型模式把"new"封装起来：单例控唯一、工厂控类型、建造者控复杂构造、原型控克隆。选对模式可显著降低耦合，但勿为用而用（YAGNI）。
