# 函数式与响应式设计模式实战

> 函数式与响应式并非"另一种语言特性"，而是一组可落地的设计模式：不可变、纯函数、管道、流式、背压。它们让并发更安全、逻辑更可组合、系统更能应对高吞吐与异步。与经典 GoF 模式互补，而非对立。

## 1. 函数式核心

```mermaid
flowchart LR
    A[输入] --> F1[纯函数f]
    F1 --> F2[纯函数g]
    F2 --> B[输出]
```

- **纯函数**：同输入同输出、无副作用，易测试易并行。
- **不可变**：数据不修改，返回新值，避免共享可变状态。
- **高阶函数**：函数作参数/返回，组合行为（map/filter/reduce）。

```python
# 管道：数据 → 清洗 → 转换 → 聚合
result = (data
    | where(lambda x: x.amount > 0)
    | select(lambda x: x.user_id)
    | group_by(count))
```

## 2. 响应式核心

| 概念 | 说明 |
| --- | --- |
| 流（Stream） | 随时间发出的数据序列 |
| 背压 | 下游慢时上游限产 |
| 操作符 | map/filter/flatMap/merge |
| 调度 | 线程/事件循环切换 |

## 3. 典型模式

- **管道（Pipeline）**：把处理拆成可组合阶段。
- **观察者（与响应式结合）**：事件驱动、自动传播。
- **策略即函数**：行为以函数注入，替代类爆炸。
- **惰性计算**：按需求值，省资源。

## 4. 适用与取舍

- **适用**：数据转换、流式处理、并发编排、UI 状态。
- **代价**：调试栈深、心智负担、学习曲线。
- **注意**：不是所有场景都适合，过度函数式反而难懂。

## 5. 常见坑

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 副作用泄漏 | 难测 | 纯函数隔离 |
| 栈过深 | 难调试 | 分步 + 日志 |
| 背压缺失 | OOM | 限流/缓冲 |
| 过度抽象 | 难懂 | 适度组合 |
| 阻塞混用 | 性能差 | 异步一致 |

## 7. 小结

函数式 + 响应式 = 纯函数组合 + 流式处理 + 背压控制。核心是用"不变与组合"换并发安全与可维护性，但需避免抽象过度。
