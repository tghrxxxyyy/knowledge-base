# 并发与多线程设计模式实战

> 并发场景下，一些经典模式能有效组织线程协作。本文覆盖线程池、生产者-消费者、读写锁、Future、ThreadLocal、Actor、不变性七种并发模式，含示例与坑点。

## 1. 线程池（Thread Pool）

复用线程，避免频繁创建销毁。

```java
ExecutorService pool = Executors.newFixedThreadPool(10);
pool.submit(() -> doWork());
```

- 核心参数：核心线程、最大线程、队列、拒绝策略。
- 坑：`newFixedThreadPool` 无界队列可能 OOM；IO 密集与 CPU 密集线程数不同。
- 推荐用 `ThreadPoolExecutor` 显式构造，配合理拒绝策略。

## 2. 生产者-消费者

解耦生产与消费速度，用阻塞队列。

```java
BlockingQueue<Task> q = new LinkedBlockingQueue<>();
// 生产者 q.put(task); 消费者 Task t = q.take();
```

- 天然削峰：生产快时任务堆积在队列。
- 坑：队列无界 OOM；消费慢导致积压。

## 3. 读写锁（ReadWriteLock）

读多写少场景提升并发。

```java
ReentrantReadWriteLock rw = new ReentrantReadWriteLock();
rw.readLock().lock();  // 多读可并发
rw.writeLock().lock(); // 写独占
```

- 读锁共享、写锁排他。
- 坑：写饥饿（读一直占）；可用 `StampedLock` 乐观读优化。

## 4. Future / CompletableFuture

异步获取结果，避免阻塞。

```java
CompletableFuture.supplyAsync(() -> fetch())
    .thenApply(this::parse)
    .thenAccept(System.out::println);
```

- 链式编排，异常用 `exceptionally` 处理。
- 坑：线程池用 `ForkJoinPool.commonPool` 默认可能不够。

## 5. ThreadLocal

线程内独享变量（如 traceId、数据库连接）。

```java
static ThreadLocal<String> trace = new ThreadLocal<>();
trace.set("abc"); String t = trace.get();
```

- 坑：线程池复用导致脏数据，必须 `remove()`；否则内存泄漏（线程常驻）。

## 6. 不变性（Immutability）

对象创建后不可变，天然线程安全。

```java
final class Point { final int x, y; Point(int x,int y){this.x=x;this.y=y;} }
```

- 配合 `final`、不可变集合（List.of）。
- 推荐：优先不可变，减少锁。

## 7. Actor 模型

消息驱动，每个 Actor 串行处理自己的 mailbox，无共享状态。

- Akka（JVM）、Erlang 原生。
- 避免锁，靠消息传递。
- 适用：高并发状态机、分布式。

```mermaid
flowchart LR
    A[Actor1] -->|消息| B[Actor2 mailbox]
    B -->|串行处理| C[状态变更]
```

## 8. 选型对比

| 模式 | 场景 |
| --- | --- |
| 线程池 | 通用异步任务 |
| 生产者-消费者 | 解耦/削峰 |
| 读写锁 | 读多写少 |
| Future | 异步编排 |
| ThreadLocal | 线程内上下文 |
| 不变性 | 共享只读 |
| Actor | 高并发无锁 |

## 9. 常见坑

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 线程池 OOM | 无界队列 | 有界+拒绝 |
| ThreadLocal 泄漏 | 脏数据 | remove |
| 死锁 | 互等锁 | 锁顺序 |
| 写饥饿 | 读一直占 | StampedLock |
| 共享可变 | 并发错 | 不变性 |

## 11. 小结

并发模式围绕"减少共享、解耦速度、安全通信"：线程池复用、队列削峰、锁分读写、不变性免锁、Actor 消息化。理解每种模式解决的具体并发痛点是关键。
