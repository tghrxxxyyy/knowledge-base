# 类型推导

> 对应 Hindley-Milner 与 Pierce。

## 一、背景与挑战
类型推导让程序员少写注解而仍获静态安全。挑战：算法完备性（HM 可判定）、与多态/重载的交互、报错定位。

## 二、核心原理
Hindley-Milner (Algorithm W) 用"类型变量 + 合一 (unification)"推导最通用类型 (principal type)。`let` 多态允许同一函数多处以不同实例使用。

## 三、形式化 / 数学基础
合一：求替换 $\sigma$ 使两类型相等。规则 `let` 多态：
$\dfrac{\Gamma\vdash e_1:\tau_1\quad \Gamma,\text{gen}(\Gamma,\tau_1)\vdash e_2:\tau_2}{\Gamma\vdash \mathtt{let}\ x=e_1\ \mathtt{in}\ e_2:\tau_2}$
其中 $\text{gen}$ 把 $\tau_1$ 中自由类型变量泛化。

## 四、代码实现
```python
def unify(a, b):
    if isinstance(a, Var):
        return {a.name: b}
    if isinstance(b, Var):
        return {b.name: a}
    if type(a) == type(b) and a.name == b.name:
        return {}
    raise TypeError("cannot unify %s %s" % (a, b))
```

## 五、与其他技术对比
- HM（ML/Haskell 旧版）：可判定、let 多态。
- 局部推导（Go/C++ auto）：仅表达式级，无 let 多态。
- 双向类型检查（Bidirectional）：分 synth/check 模式，更易扩展依赖类型。

## 六、常见误区
1. 以为 `let` 多态对嵌套函数都生效（值限制 value restriction）。
2. 合一顺序影响报错但不影响结果正确性（最通用性）。
3. 把重载当多态（重载需特化，非推导）。

## 十、小结
类型推导核心是合一与泛化：`let` 多态让 HM 兼具简洁与安全，是 ML 系语言的基石。
