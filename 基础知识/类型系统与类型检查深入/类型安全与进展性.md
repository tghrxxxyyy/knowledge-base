# 类型安全与进展性

> 对应 Pierce 第 8-9 章（Soundness）。

## 一、背景与挑战
类型安全 = 不会在运行期发生"未定义操作"（如整数上调用方法）。进展性 (progress) 与保持性 (preservation) 是证明的两半。挑战：实际语言因 `null`/强制转换难获完全 sound。

## 二、核心原理
Progress：良类型项要么已是值，要么能继续求值。Preservation：求值保持类型。二者归纳证明即得 Soundness：良类型程序不会"卡住(stuck)"。

## 三、形式化 / 数学基础
$\text{Soundness}=\text{Progress}\land\text{Preservation}$。
形式：$\text{if }\emptyset\vdash e:\tau\text{ then } e\text{ val }\lor\ \exists e'.\ e\to e'$，且每一步保持类型。
"Stuck" = 非值且无可应用求值规则（类型错误）。

## 四、代码实现
```python
# 小步语义：仅当类型匹配才有规则
def step(e):
    if isinstance(e, Add) and isinstance(e.l, Int) and isinstance(e.r, Int):
        return Int(e.l.v + e.r.v)   # 进展性保证此处类型已满足
    raise Stuck  # sound 语言永不在此
```

## 五、与其他技术对比
- 强 sound（Rust/Haskell）：编译期证无未定义行为。
- 弱/部分（Java/TS）：cast/`any` 引入运行期可能错误。
- 动态语言：运行期标签检查替代静态证明。

## 六、常见误区
1. 把"类型安全"等同于"无 bug"。
2. 以为有类型系统就 sound（需证明且无逃逸洞）。
3. 用 `unsafe`/cast 破坏 sound 而不自知。

## 九、演进与趋势
Rust 用借用检查在 unsafe 外保证 sound；逐步类型趋向默认 sound（strict 模式）。

## 十、小结
类型安全靠 progress 与 preservation 两引理证得；工程语言常用 `unsafe`/cast 换取表达力，代价是 sound 边界需人工守护。
