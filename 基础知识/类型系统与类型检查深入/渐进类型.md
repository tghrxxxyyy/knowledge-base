# 渐进类型

> 对应 Siek et al. 渐进类型 (Gradual Typing) 与 TypeScript。

## 一、背景与挑战
渐进类型让静态/动态混合：未注解处用 `Any`（或称 `dynamic`）桥接。挑战：保证"静态部分 sound"、运行时契约检查、与 `Any` 交互的边界错误。

## 二、核心原理
一致性 (consistency) 弱于子类型：`Any` 与任何类型一致。`Any` 处插入运行期守卫 (cast/blame)。类型从动态流向静态时强制检查；从静态流向动态时擦除。

## 三、形式化 / 数学基础
一致性 $\sim$：自反、对称（非传递的"弱"等价）。
$\tau\sim\mathtt{Any}$ 对任意 $\tau$；若 $\tau_1\sim\tau_2$ 则二者可互替换。
强制 $G:\tau\rightsquigarrow\tau'$ 在运行期投影/注入保证契约。

## 四、代码实现
```typescript
function len(xs: unknown): number {
    if (Array.isArray(xs)) return xs.length;  // 守卫收窄
    throw new Error("not array");
}
const a: any = "hi";
len(a); // 运行期才知是 string，运行时检查/报错
```

## 五、与其他技术对比
- TypeScript：结构类型 + `any`，默认非严格 sound（strict 模式更接近）。
- Python + Pyright：可选注解、`Any` 兜底。
- 完全静态（Rust）：无 `Any`，编译期全证。

## 六、常见误区
1. 以为 `any` 处编译期安全（运行期才查）。
2. 把一致性当子类型（不一致传递）。
3. 把 `unknown` 当 `any`（`unknown` 需收窄）。

## 九、演进与趋势
可选严格模式默认开启、基于类型的迁移工具（先用 `any` 后逐步收窄）、以及边界优化的瞬态/暂态运行时。

## 十、小结
渐进类型用 `Any` 与一致性桥接静态动态；理解运行期契约与 sound 边界，是在大型 JS/Python 代码库引入类型的实用路径。
