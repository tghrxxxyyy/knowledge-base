# 静态与动态类型

> 对应 Pierce《Types and Programming Languages》与 CS-Notes。

## 一、背景与挑战
静态类型在编译期检查类型，动态类型在运行期。挑战：表达力 vs 安全/性能； gradual typing 试图兼顾二者。

## 二、核心原理
静态：每个表达式有可推导类型 $\Gamma\vdash e:\tau$。动态：值带运行时类型标签，操作前检查。Soundness：若程序通过静态检查则运行期不会类型错误（progress + preservation）。

## 三、形式化 / 数学基础
类型规则（简单）：
$\dfrac{\Gamma\vdash e_1:\mathtt{int}\quad \Gamma\vdash e_2:\mathtt{int}}{\Gamma\vdash e_1+e_2:\mathtt{int}}$
Progress：若 $\emptyset\vdash e:\tau$ 则 $e$ 是值或存在 $e'$ 使 $e\to e'$。
Preservation：若 $e\to e'$ 且 $\vdash e:\tau$ 则 $\vdash e':\tau$。

## 四、代码实现
```python
def check(env, e):
    if isinstance(e, Int): return IntT
    if isinstance(e, Add):
        if check(env, e.l) == IntT and check(env, e.r) == IntT:
            return IntT
        raise TypeError("add needs ints")
```

## 五、与其他技术对比
- 静态（Java/Go/Rust）：早错、优化好、需标注或推导。
- 动态（Python/JS）：灵活、原型快、运行期开销与错误延迟。
- 渐进（TypeScript/Pyright）：部分注解、any 桥接。

## 六、常见误区
1. 认为静态类型能防所有 bug——只防类型错误。
2. 把"强类型"与"静态类型"混用（正交概念）。
3. 以为动态类型无类型——只是检查推迟到运行期。

## 十、小结
静态类型用编译期证明换取安全与性能，动态类型用灵活换取迭代速度；二者由 progress/preservation 形式化保证安全。
