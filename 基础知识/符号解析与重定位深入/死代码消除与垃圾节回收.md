# 死代码消除与垃圾节回收

> 对应 Levine《Linkers and Loaders》第 4 章；Aho、Sethi & Ullman《Compilers: Principles, Techniques, and Tools》（龙书）第 9 章（死代码消除）；并参考 GNU ld 手册 `--gc-sections` 与 `--icf` 选项。

## 一、背景与挑战

模板库、第三方头文件引入大量从未被调用的函数与节。若不裁剪，最终镜像膨胀、加载变慢、攻击面扩大，且静态初始化的无用对象仍会被构造。

需要在保留语义前提下剔除无用部分，这要求链接器知道「哪些代码/数据真的可达」。

难点在于：通过函数指针间接调用的回调、被 `init_array` 注册的构造函数、被异常处理表引用的代码，都不能简单判死。

## 二、核心原理

编译期 `-ffunction-sections -fdata-sections` 把每个函数/变量放独立节（`.text.foo`、`.data.bar`）。

链接器 `--gc-sections` 从入口（`_start`、被 `KEEP` 的 `init_array`、导出符号）出发，沿重定位边做图可达性遍历，未达节直接丢弃。

与编译期 DCE 互补：IR 层删无副作用语句，链接期删整个函数/数据节，粒度更粗但能跨 TU。

`--icf=safe`（Identical Code Folding）进一步合并字节相同的函数体，配合 GC 把模板膨胀压到极低。

## 三、形式化与数学基础

可达节集合是图的不动点：

$$Reach = fixpoint(\{entry\} \cup \bigcup_{s\in Reach} targets(reloc(s)))$$

垃圾节：

$$Garbage = All \setminus Reach$$

单函数/数据节是图的细粒度节点；重定位项 `R` 是有向边。

当 $Garbage \neq \emptyset$ 时，镜像体积下降 $\propto |Garbage|$。

## 四、代码实现

```bash
# 把每个函数/数据放独立节，链接时回收不可达节
gcc -ffunction-sections -fdata-sections -O2 -c a.c
gcc -ffunction-sections -fdata-sections -O2 -c b.c
gcc -Wl,--gc-sections -Wl,--icf=safe a.o b.o -o app

# 保护被函数指针/构造函数间接引用的节，避免误删
# 在链接脚本或代码中用 KEEP(*(.init_array*)) 保留初始化数组
```

`objcopy --strip-unused` 也可在对象层丢弃，但链接期 GC 更精确，因为它掌握跨 TU 的完整引用图。

## 五、与其他技术对比

| 阶段 | 粒度 | 能力 | 局限 |
| --- | --- | --- | --- |
| 编译期 DCE | 语句/表达式 | 删无副作用代码 | 跨 TU 不可知 |
| 链接期 GC-sections | 节 | 删整个未用函数 | 需 function-sections |
| ICF | 函数体 | 合并相同代码 | 可能影响栈回溯/地址敏感逻辑 |

编译期 DCE 在 IR 层删无副作用语句；链接期 GC-sections 在节粒度删整个函数，二者互补。

## 六、常见误区

1. 未加 `-ffunction-sections`，GC 无独立节点可删：所有函数挤在 `.text`，整体可达无法剔除。
2. 注册回调经函数指针，若非显式保留会被误删：用 `KEEP` 保护 `init_array`/`fini_array` 与特定节。
3. 误删导致运行时缺符号：需 `KEEP` 关键节（如异常表 `.eh_frame`、TLS 模板）。
4. 误以为 ICF 总安全：`--icf=safe` 仅合并「地址无关」函数，取函数地址比较的元数据会受影响。
5. 误以为 GC 不影响调试：被删节不再可调试，需保留 `.debug_*` 并理解映射失效。
6. 误以为 GC 只在链接期：LTO 先在 IR 层删函数，链接期 GC 再回收节，二者阶段不同。

## 七、与开源书·权威来源对应

- Levine《Linkers and Loaders》第 4 章讲节合并与回收（garbage collection of sections）。
- 龙书第 9 章讲编译期死代码消除（DCE）与可达定义分析。
- GNU ld 手册 `--gc-sections`/`--icf` 描述入口集、`KEEP` 与折叠安全约束。
- LLVM/LLD 文档说明 `lld` 默认更激进的 GC 与 ICF 策略。
- `KEEP` 语义见 binutils 链接脚本语言（`ld` 的 `INSERT`/`EXCLUDE_FILE` 与之配合）。

## 八、面试题

1. `--gc-sections` 如何工作？要点：从入口沿重定位做可达性遍历，丢弃不可达节。
2. 为何需 `-ffunction-sections`？要点：把函数拆成独立节，GC 才有可删的细粒度节点。
3. `KEEP` 用途？要点：保护被间接引用（函数指针、构造数组）的节不被误删。
4. ICF 是什么、风险？要点：合并相同函数体瘦身，但地址敏感逻辑需 `--icf=safe`。

## 九、演进与趋势

- ICF（相同代码折叠）进一步合并等价函数体，配合 GC 把 C++ 模板膨胀压到极低。
- 链接器引入「分区/分组」（`--sections` 分组）让 GC 在更大单元上工作。
- 与 LTO 结合：IR 层先删死函数，链接期再 GC 节，双重瘦身。

## 十、小结

垃圾节回收是链接期可达性裁剪，把细粒度节作为图节点实现精准瘦身。

它依赖 `-ffunction-sections` 提供节点、`KEEP` 保护间接引用，是削减镜像体积与攻击面的标准手段。
