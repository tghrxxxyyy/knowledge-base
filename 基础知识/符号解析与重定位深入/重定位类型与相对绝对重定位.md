# 重定位类型与相对绝对重定位

> 对应 Levine《Linkers and Loaders》第 7 章；CSAPP 第 7.6 节；并参考 x86-64 psABI（System V Application Binary Interface）关于 `R_X86_64_*` 重定位类型的规范与 ELF gABI 的 `REL`/`RELA`。

## 一、背景与挑战

不同指令对操作数寻址有不同要求：调用用相对偏移，数据指针用绝对地址，GOT 项又需绝对加载。单一重定位公式无法覆盖，链接器必须按类型分支。

此外，动态链接与 ASLR/PIE 要求「同一份代码可在任意基址运行」，这决定了重定位类型能否用相对/基址相关形式。

若某类型用错（如本应相对却用绝对），镜像在非零基址加载时会崩溃或无法地址无关。

## 二、核心原理

x86-64 关键类型：`R_X86_64_PC32`（相对 32 位，作用于 `call`/`lea` 等）、`R_X86_64_PLT32`（调用桩相对，链接期可能转 PLT）、`R_X86_64_64`（绝对 64 位）、`R_X86_64_GLOB_DAT`（填 GOT 绝对，动态链接）、`R_X86_64_JUMP_SLOT`（PLT 重定位）、`R_X86_64_RELATIVE`（基址加常数，用于 PIE 数据指针）、`R_X86_64_IRELATIVE`（IFUNC 解析后调用）。

静态链接用 PC32/RELATIVE 即可；动态链接额外用 GLOB_DAT/JUMP_SLOT 延后到 `ld.so` 加载时填。

加载器（`ld.so`）据类型选择加或减 `P`（place）或 `B`（基址）。

## 三、形式化与数学基础

重定位值公式（节基址为 `S`，加数 `A`，位置 `P`，基址 `B`）：

$$val = \begin{cases} S + A - P & \text{PC32/PLT32（相对）} \\ S + A & \text{64/GLOB_DAT（绝对）} \\ B + A & \text{RELATIVE（基址相关）} \end{cases}$$

其中 $B$ 为镜像加载基址。PIE 仅用相对与 RELATIVE 类型，故 $B$ 任意也不影响指令；绝对类型则要求 $B$ 固定，否则须运行时改写。

## 四、代码实现

```c
// 动态链接器应用重定位的简化逻辑
void apply_reloc(Elf64_Rela *r, void *base) {
    uint64_t S = sym_value(r->r_info);   // 符号运行地址
    uint64_t B = (uint64_t)base;          // 镜像基址
    uint64_t P = (uint64_t)base + r->r_offset;
    uint64_t A = r->r_addend;
    uint64_t *loc = (uint64_t*)P;
    switch (ELF64_R_TYPE(r->r_info)) {
    case R_X86_64_PC32:    *loc = S + A - P; break;
    case R_X86_64_64:      *loc = S + A;     break;
    case R_X86_64_RELATIVE:*loc = B + A;     break;
    }
}
```

`readelf -r` 可查看待应用重定位项；`ld.so` 在 `dlopen`/程序启动阶段遍历 `.rela.dyn`/`.rela.plt` 应用上述公式。

## 五、与其他技术对比

| 类型 | 是否依赖基址 | ASLR/PIE 友好 | 典型用途 |
| --- | --- | --- | --- |
| PC32/PLT32 | 否（相对） | 是 | 调用、取地址 |
| 64/GLOB_DAT | 是（绝对） | 否 | 数据指针、GOT |
| RELATIVE | 仅基址加常数 | 是 | PIE 静态数据 |
| IRELATIVE | 解析后调用 | 是 | IFUNC |

相对重定位与基址无关，支持 ASLR 与共享；绝对重定位简单但固定地址，一旦加载基址偏移即崩。

## 六、常见误区

1. 忽略 PLT32 与 PC32 在链接期差异：后者可能直连符号，前者经 PLT 桩支持惰性绑定。
2. 32 位相对调用跨 2 GiB 距离溢出：只在超大镜像（或模块远离）出现，需用 `R_X86_64_PC64`/PLT。
3. RELATIVE 不查符号，仅基址加偏移：常由静态 PIE 使用，速度最快。
4. 误以为所有重定位在静态链接完成：动态符号（GLOB_DAT/JUMP_SLOT）由 `ld.so` 在加载/首次调用时填。
5. 误以为 IRELATIVE 普通：它需在 `ld.so` 早期以解析后的 IFUNC 地址填充，参与 RELRO 保护。
6. 误以为 RELA 加数可有可无：x86-64 用 RELA 携带 `r_addend`，静态 PIE 的 RELATIVE 重定位靠加数修正偏移。
7. 误以为 GOT 一定需重定位：若符号在本模块且 hidden，编译器可直连，根本不产生 GOT 项。

## 七、与开源书·权威来源对应

- x86-64 psABI 定义全部 `R_X86_64_*` 类型与加数/符号语义，是权威清单。
- CSAPP 7.6 用 `readelf -r` 演示可重定位目标中的重定位项。
- Levine《Linkers and Loaders》第 7 章讲重定位算法与基址无关代码（PIC）。
- ELF gABI 区分 `REL`（无加数）与 `RELA`（带加数），x86-64 用 RELA。
- musl/glibc 的 `relocate` 循环对 RELATIVE 批量处理，显著加快 PIE 启动。

## 八、面试题

1. PC32 与 64 绝对何时用？要点：调用/取地址用相对，数据指针用绝对。
2. RELATIVE 为何无需符号？要点：仅基址加常数，符号地址在链接期已确定偏移。
3. PIE 依赖哪些类型？要点：PC32/PLT32 与 RELATIVE，使镜像可浮动。
4. GLOB_DAT 与 JUMP_SLOT 区别？要点：前者填数据 GOT，后者填 PLT 函数入口。
5. RELRO 与重定位类型关系？要点：FULL RELRO 在应用 GLOB_DAT/JUMP_SLOT 后把 GOT 设为只读，依赖这些类型已被正确填写。

## 九、演进与趋势

- RISC-V 用更少类型（PC 相对 + GOT）简化加载器；x86 增加 `R_X86_64_IRELATIVE` 支持 IFUNC 与 CPU 特性分发。
- `RELRO`/`FULL RELRO` 把重定位后的 GOT 设为只读，防止 GOT 覆写攻击。
- `BIND_NOW` 让全部重定位在加载期完成，牺牲惰性绑定换安全性。
- `DT_RELR`（relative reloc 压缩）以紧凑编码存储 RELATIVE 重定位，缩小 PIE 的重定位段。

## 十、小结

重定位类型把地址修正公式编码进每条记录：相对与绝对之分决定镜像能否浮动，RELATIVE 支撑 PIE/ASLR，而动态类型（GLOB_DAT/JUMP_SLOT/IRELATIVE）把剩余修正推迟到 `ld.so`，是静态与动态链接会合的关键机制。
