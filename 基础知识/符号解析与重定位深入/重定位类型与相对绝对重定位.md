# 重定位类型与相对绝对重定位

> 对应 Levine《Linkers and Loaders》第 7 章；CSAPP 第 7.6 节。

## 一、背景与挑战
不同指令对操作数寻址有不同要求：调用用相对偏移，数据指针用绝对地址，GOT 项又需绝对。单一重定位公式无法覆盖，必须按类型分支。

## 二、核心原理
x86-64 关键类型：R_X86_64_PC32（相对 32 位）、R_X86_64_PLT32（调用桩相对）、R_X86_64_64（绝对 64 位）、R_X86_64_GLOB_DAT（填 GOT 绝对）、R_X86_64_RELATIVE（基址加常数）。加载器据类型选择加或减 P。

## 三、形式化与数学基础
$$val = \begin{cases} S + A - P & \text{PC32/PLT32} \\ S + A & \text{64/GLOB_DAT} \\ B + A & \text{RELATIVE} \end{cases}$$
其中 $B$ 为镜像加载基址。PIE 仅用相对与 RELATIVE 类型，故 $B$ 任意。

## 四、代码实现
```c
switch (type) {
case R_X86_64_PC32:    *(int32_t*)P = S + A - P; break;
case R_X86_64_64:      *(uint64_t*)P = S + A;   break;
case R_X86_64_RELATIVE:*(uint64_t*)P = B + A;   break;
}
```

## 五、与其他技术对比
相对重定位与基址无关，支持 ASLR 与共享；绝对重定位简单但固定地址，一旦加载基址偏移即崩。

## 六、常见误区
1. 忽略 PLT32 与 PC32 在链接期差异——后者可能直连符号。
2. 32 位相对调用跨 2GiB 距离溢出，只在超大镜像出现。
3. RELATIVE 不查符号，仅基址加偏移，常由静态 PIE 使用。

## 七、与开源书/权威来源对应
ELF/x86-64 psABI 定义全部类型；CSAPP 7.6 演示 readelf -r；Levine ch7。

## 八、面试题
问：PC32 与 64 绝对何时用？RELATIVE 为何无需符号？PIE 依赖哪些类型？

## 九、演进与趋势
RISC-V 用更少类型（PC 相对 + GOT）简化加载器；x86 增加 IRELATIVE 支持 IFUNC。

## 十、小结
重定位类型把地址修正公式编码进每条记录，相对与绝对之分决定镜像能否浮动。
