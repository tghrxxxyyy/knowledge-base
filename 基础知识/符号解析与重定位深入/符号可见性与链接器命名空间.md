# 符号可见性与链接器命名空间

> 对应 Levine《Linkers and Loaders》第 6 章；CSAPP 第 7 章。

## 一、背景与挑战
大型程序由众多库组成，全局符号平面命名易冲突（如多个库都定义 log）。需要控制哪些符号对外可见、哪些仅模块内部使用。

## 二、核心原理
ELF 符号绑定字段区分 STB_LOCAL / STB_GLOBAL / STB_WEAK。配合 visibility（default/hidden/protected）可隐藏符号，减少动态符号表体积并启用更快调用。链接器命名空间（如 dlmopen）把一组库隔离在独立符号域，互不干扰。

## 三、形式化与数学基础
导出符号集 $E = \{ s \mid bind(s)\neq LOCAL \land vis(s)=default \}$。隐藏后调用开销：
$$\text{call}_{hidden} < \text{call}_{global}$$
因为省去 GOT/PLT 间接与符号查找。

## 四、代码实现
```c
// 隐藏符号，仅本 DSO 可见
__attribute__((visibility("hidden"))) int internal_counter;
// 默认导出
__attribute__((visibility("default"))) void api();
```

## 五、与其他技术对比
全局默认可见便于插件扩展但膨胀 dynsym、增加冲突面；hidden 默认（fvisibility=hidden）更安全紧凑，需显式导出 API。

## 六、常见误区
1. static 仅文件内可见，仍需配合 visibility 才能避免进 dynsym。
2. 以为 hidden 符号绝对不可外部调用——仍可由地址直接调用，只是不在符号表。
3. 命名空间隔离不隔离内存，仅隔离符号查找。

## 七、与开源书/权威来源对应
Levine ch6 讲符号作用域；glibc dlmopen 手册；CSAPP 7 章铺垫。

## 八、面试题
问：static 与 hidden visibility 区别？为何要隐藏符号？命名空间隔离用途？

## 九、演进与趋势
符号版本脚本（version script）配合 hidden 默认，成为库 ABI 稳定的标准做法。

## 十、小结
可见性控制把全局平面名空间收敛为受控导出面，是库工程化的基石。
