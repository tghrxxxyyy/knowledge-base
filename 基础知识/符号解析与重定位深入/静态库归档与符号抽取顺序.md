# 静态库归档与符号抽取顺序

> 对应 Bryant & O'Hallaron《CSAPP》第 7.6 节；Levine《Linkers and Loaders》第 4 章；并参考 GNU binutils `ar`/`ld` 手册关于归档符号表与 `--start-group`。

## 一、背景与挑战

静态库（`.a`）是若干 `.o` 的归档（archive），本身不含合并后的镜像，只是「对象文件的集合」。

链接器只为解析当前未决符号而按需抽取成员。命令行顺序直接决定哪些成员被纳入：顺序错则 `undefined reference`。

这与「直接给 `.o`」不同——`.o` 总是全量纳入，而 `.a` 成员是惰性抽取的。

理解单遍扫描算法是排查链接错误（尤其交叉依赖、循环依赖）的关键。

## 二、核心原理

链接器从左到右扫描输入。维护未决符号集 U、已定义 D、已归档 A。

遇 `.o` 立即加入并把其定义移入 D、引用加入 U。

遇 `.a` 仅在成员能解析 U 中至少一个符号时才抽取该成员，抽取后刷新 U/D；不能解析任何未决符号的成员被整体跳过。

扫描一遍后若 U 非空即报错 `undefined reference`。

循环依赖（`a` 用 `b`、`b` 用 `a`）需把库重复列两次：`-la -lb -la`，或用 `--start-group`/`--end-group` 包围让其循环解析。

## 三、形式化与数学基础

成员选取函数（单次前向扫描）：

$$M_{used} = \{ m \in A \mid def(m) \cap U_{before}(m) \neq \emptyset \}$$

链接器只向前看，故依赖环需重复列举：

$$command:\ \dots -la -lb -la$$

`--start-group A --end-group` 则对组内成员反复扫描直到 U 不再变化（不动点），代价是多次遍历。

## 四、代码实现

```bash
# 错误：库在依赖对象之前，其成员因 U 空被全忽略
gcc main.o -lm          # 若 main 用 math 且 -lm 在前可能 undefined
# 正确：被依赖者置后
gcc main.o -L. -lcalc -lm
# 循环依赖：重复列举
gcc main.o -la -lb -la
# 或用 group 包围（代价：多次扫描）
gcc main.o -Wl,--start-group -la -lb -Wl,--end-group
```

`ar rcs libx.a a.o b.o` 生成归档并写入符号表（`ranlib` 等价）；`nm libx.a` 可查看各成员导出的符号。

## 五、与其他技术对比

| 策略 | 扫描遍数 | 顺序敏感 | 适用 |
| --- | --- | --- | --- |
| 单遍左到右 | 1 | 是 | 常规链接 |
| `--start-group` | 多（不动点） | 否 | 循环依赖 |
| 全量 `.o` | 1 | 否 | 小项目 |
| LTO 归档 | 1（IR 合并） | 弱化 | 需全局优化 |

单遍左到右扫描省内存但敏感于顺序；`--start-group` 可循环解析，代价是多次扫描、链接变慢。

## 六、常见误区

1. 把库放命令行最前：其成员因 U 为空被全忽略，后续 `.o` 引用时再无库可抽 → `undefined reference`。
2. 以为链接器会全局搜索所有库：默认仅单遍前向，后面出现的库不能回头解析前面的未决符号。
3. 用 group 包围大库显著拖慢链接：组内反复扫描，应对「确有循环依赖」的少量库才用。
4. 误以为 `.a` 与 `.o` 等价：`.a` 惰性抽取，未被引用的成员不进镜像；`.o` 全量进。
5. 误以为 LTO 归档也受顺序困扰：bitcode 在链接期整体参与优化，顺序问题大幅弱化。

## 七、与开源书·权威来源对应

- CSAPP 7.6 用 `ar` 与链接顺序演示 `undefined reference` 与正确排布。
- Levine《Linkers and Loaders》第 4 章讲归档格式、符号表（`ranlib`）与单遍扫描算法。
- GNU ld 手册 `--start-group`/`--end-group` 说明循环依赖的解析与性能代价。
- binutils `ar` 文档描述 thin archive（`ar rcsT`，仅存路径）对大型构建的加速。

## 八、面试题

1. 为何出现 `undefined reference`？要点：库顺序错/未被抽取，或真缺定义；调顺序或用 group。
2. 循环依赖怎么解？要点：重复列库 `-la -lb -la`，或 `--start-group` 包围。
3. `--start-group` 代价？要点：组内反复扫描至不动点，链接时间上升。
4. `.a` 与 `.o` 在链接上区别？要点：`.a` 惰性按符号抽取成员，`.o` 全量纳入。

## 九、演进与趋势

- `lld`（LLVM ld）默认更宽松、解析更快，对顺序敏感度低于传统 GNU ld。
- LTO 归档以 bitcode 形式存储，链接期整体参与优化，弱化顺序问题。
- 增量链接与 `lld` 的并行归档处理进一步降低大静态库链接耗时。

## 十、小结

静态库抽取是带状态的单遍前向扫描：命令行顺序是链接成败的隐形开关。循环依赖用重复列举或 `--start-group` 化解，而现代链接器与 LTO 正在弱化这一历史约束。
