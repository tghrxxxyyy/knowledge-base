# 检查点机制与恢复起点

> 对应 Mohan et al. 1992（ARIES 模糊检查点），以及 Silberschatz《Database System Concepts》第 17 章。

## 一、背景与挑战
若每次恢复都从日志头重放，耗时随运行时间线性增长。检查点周期性记录系统状态，使恢复只需从最近检查点之后开始，显著缩短 MTTR。

## 二、核心原理
- 静态检查点：暂停所有写，落盘脏页并记录事务/脏页表，简单但阻塞。
- 模糊检查点（ARIES）：不阻塞写，记录检查点开始时的 TT 与 DPT 及 LSN；恢复从检查点 LSN 起，配合 redo 保证正确。
- 增量检查点：持续把脏页刷盘并推进检查点 LSN，避免一次性抖动。

## 三、形式化与数学基础
恢复起点：
$$ LSN_{start} = \max(LSN_{checkpoint}, \min DPT\ LSN) $$
恢复时间上界近似：
$$ MTTR \le O(\text{logs since checkpoint}) $$
模糊检查点不变量：
$$ \text{所有 } LSN < cp\_lsn \text{ 的修改已可重放} $$

## 四、代码实现
```python
# 模糊检查点（仅示意）
def fuzzy_checkpoint(tt, dpt):
    cp_lsn = log_write(CHECKPOINT_BEGIN)
    persist(tt, dpt, cp_lsn)          # 记录活跃事务与脏页
    log_write(CHECKPOINT_END, cp_lsn)
    return cp_lsn
```

## 五、与其他技术对比
静态检查点实现易但停顿；模糊/增量检查点无停顿但实现复杂。PostgreSQL 用 REDO 指针 + 后台刷脏实现近似增量检查点。

## 六、常见误区
1) 认为检查点后日志可全删——仍有未刷脏页对应日志。
2) 频繁检查点拖性能——IO 抖动。
3) 误以为模糊检查点需停止写——其正是为不停写设计。

## 九、演进与趋势
增量检查点、基于 LSN 水位自动触发、检查点与备份快照协同。

## 十、小结
检查点把恢复起点前移、缩短 MTTR；模糊/增量化让其在高吞吐下几无感知。
