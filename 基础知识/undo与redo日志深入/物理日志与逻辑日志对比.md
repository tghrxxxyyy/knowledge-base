# 物理日志与逻辑日志对比

> 对应 Garcia-Molina《Database Systems: The Complete Book》第 17 章（physical vs logical logging），以及 cmu-db/15445-course。

## 一、背景与挑战
日志记录“改了什么”有两种粒度：物理日志记页/字节级前后像，逻辑日志记录高层操作（如“给账户 +100”）。二者在恢复速度、日志量、跨版本兼容上各有取舍。

## 二、核心原理
- 物理日志：记录页 ID + 偏移 + 前后像，恢复简单、幂等、与存储结构紧耦合。
- 逻辑日志：记录操作语义（SQL/算子），日志量小、可跨存储结构，但重放依赖操作可重复且副作用可控（需避免自增 ID 等不可重放项）。
- 物理逻辑日志（如 PostgreSQL）：逻辑操作 + 物理页信息折中。

## 三、形式化与数学基础
日志量近似：
$$ |L_{phys}| \propto \text{changed bytes},\quad |L_{logic}| \propto \text{operation arity} $$
恢复确定性：物理日志重放与存储布局强相关，逻辑日志要求操作确定性：
$$ \text{replay}(op, state) = state' \ \text{确定可重复} $$

## 四、代码实现
```c
// 物理日志记录（仅示意）
typedef struct { lsn_t lsn; page_id p; off_t off; byte before[8]; byte after[8]; } phys_log;
// 逻辑日志记录（仅示意）
typedef struct { lsn_t lsn; txn_t t; op_kind op; int64_t acct; int64_t delta; } logic_log;
```

## 五、与其他技术对比
物理日志恢复快但体积大、版本绑定；逻辑日志紧凑但需幂等操作、难以处理索引等副作用；折中方案最常用。

## 六、常见误区
1) 认为逻辑日志一定更小——复杂操作未必。
2) 误以为逻辑日志可随意重放——需确定性。
3) 把 binlog（逻辑）与 redo（物理）等同。

## 九、演进与趋势
行级逻辑日志（CDC）、压缩物理日志、WAL 与 binlog 协同复制。

## 十、小结
物理与逻辑日志是“恢复成本 vs 日志体积/灵活性”的权衡；现实系统多以混合形态落地。
