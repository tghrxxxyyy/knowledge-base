# 覆盖索引

> 对应 Kleppmann《DDIA》索引章，以及 MySQL InnoDB 覆盖索引（Using index）。

## 一、背景与挑战
非聚簇索引查到主键后还需回表取其他列，回表是随机 I/O。若索引本身包含查询所需全部列，则可避免回表，显著提升性能。

## 二、核心原理
覆盖索引（covering index）的叶子结点已含 SELECT 所有列（通过复合索引前导列 + INCLUDE/附加列）。执行计划显示 `Using index` 表示未回表。

## 三、形式化 / 数学基础
回表代价消除：原 $C = h_{idx} + k \cdot h_{clu}$，覆盖后 $C = h_{idx}$（$k=0$）。性能提升约与命中行数 $k$ 成正比。

## 四、代码实现
```sql
CREATE INDEX idx_cover ON orders (user_id) INCLUDE (total, status);
-- 查询无需回表
SELECT total, status FROM orders WHERE user_id = 42;
-- EXPLAIN 显示 Using index
```

## 五、与其他技术对比
| 方式 | 回表 | 随机 I/O |
|------|------|----------|
| 普通二级索引 | 是 | 有 |
| 覆盖索引 | 否 | 无 |

## 六、常见误区
1. 建了索引就快——未覆盖仍要回表。
2. SELECT * 能覆盖——需所有列都在索引。
3. 覆盖索引无代价——更宽索引增加写与空间。

## 九、演进与趋势
Included columns（SQL Server、PostgreSQL 11+）把非键列附加到索引，便于覆盖而不影响排序键。

## 十、小结
覆盖索引通过把查询列纳入索引叶子避免回表，是读优化最有效的手段之一。
