# 索引选择性

> 对应 Silberschatz《Database System Concepts》11.2 与统计章，以及 Database Tuning 选择性估计。

## 一、背景与挑战
并非所有列都适合建索引。低基数列（如性别）过滤后剩大量行，走索引反而可能不如全表扫描。选择性衡量索引过滤能力。

## 二、核心原理
选择性（selectivity）= 匹配行数 / 总行数，越低越好（过滤越强）。基数（cardinality/NDV）越高选择性越好。优化器据此判断是否用索引及估计结果集大小。

## 三、形式化 / 数学基础
选择率 $s = 1/NDV$（等值、均匀假设）。索引区分度常用 $ratio = NDV / N$（接近 1 为优）。MySQL 用 `SHOW INDEX` 的 `Cardinality` 列估 NDV。

## 四、代码实现
```sql
SHOW INDEX FROM users;          -- 看 Cardinality
-- 或
SELECT COUNT(DISTINCT city)/COUNT(*) AS sel FROM users;
```

## 五、与其他技术对比
| 列 | NDV | 是否适合 B+ 索引 |
|----|-----|------------------|
| id | 高 | 是 |
| status | 低 | 谨慎/位图 |

## 六、常见误区
1. 所有列都建索引——低选择性列收益低、写代价高。
2. Cardinality 精确——多为采样估计。
3. 选择性只看单值——组合列的选择性需联合估。

## 九、演进与趋势
多列统计（依赖直方图、ndistinct 组合）提升相关列选择性估计；AI 索引顾问自动评估。

## 十、小结
选择性由列基数决定，高选择性列才适合 B+ 树索引；低基数列考虑位图或组合索引。
