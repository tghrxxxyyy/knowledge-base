# 单列与复合索引

> 对应 Silberschatz《Database System Concepts》11.2 索引类型，以及 MySQL 复合索引文档。

## 一、背景与挑战
单列索引简单但多列查询常需回表或多次索引。复合索引把多列编码进同一 B+ 树，能服务多列过滤，但顺序至关重要。

## 二、核心原理
单列索引只按一列排序；复合索引按键顺序 (a,b,c) 字典序排序，叶子按 (a,b,c) 排列。最左前缀原则：只有查询用到索引最左连续列时才能有效利用该索引。

## 三、形式化 / 数学基础
复合索引可服务的谓词集合为前缀闭包：$\{(a), (a,b), (a,b,c)\}$。查询 `WHERE b=?` 不命中（跳过 a），除非有独立单列索引或索引跳跃扫描。

## 四、代码实现
```sql
CREATE INDEX idx ON t (a, b, c);
-- 命中: WHERE a=1 AND b=2
-- 部分命中: WHERE a=1 (仅用 a)
-- 不命中前缀: WHERE b=2
```

## 五、与其他技术对比
| 索引 | 覆盖查询 | 顺序敏感 |
|------|----------|----------|
| 单列 | 单列的 | 否 |
| 复合 | 前缀组合 | 是 |

## 六、常见误区
1. (a,b) 索引能服务 (b) 查询——不能（除非跳跃扫描）。
2. 列顺序无所谓——应把高选择性/等值列放前。
3. 复合索引可任意排列——范围列后应停止利用。

## 九、演进与趋势
索引跳跃扫描（Oracle/MySQL 8）放宽最左前缀限制；包含列（INCLUDE）让复合索引更偏向覆盖。

## 十、小结
复合索引以字典序编码多列，最左前缀是设计与优化必须遵循的铁律。
