# 函数索引

> 对应 PostgreSQL 表达式索引文档，以及 MySQL 8 函数索引（Functional Key Parts）。

## 一、背景与挑战
查询常按表达式过滤，如 `WHERE lower(email)=?` 或 `WHERE DATE(created)=?`。普通列索引无法服务表达式，导致全表扫描。函数索引（表达式索引）对表达式结果建索引。

## 二、核心原理
函数索引对 `f(col)` 的计算结果建 B+ 树，查询需使用相同表达式才能命中。索引值按表达式结果排序存储，因此 `WHERE f(col)=c` 可走索引。

## 三、形式化 / 数学基础
索引键为 $k = f(c_1,\dots,c_n)$，查询谓词须等价匹配 $f$。注意表达式必须确定（无 `now()` 等非确定性函数）否则结果不稳定。

## 四、代码实现
```sql
-- PostgreSQL 表达式索引
CREATE INDEX idx_lower_email ON users (lower(email));
SELECT * FROM users WHERE lower(email) = 'a@b.com';

-- MySQL 8 函数索引
CREATE INDEX idx_date ON orders ((DATE(created)));
```

## 五、与其他技术对比
| 索引 | 服务谓词 | 注意 |
|------|----------|------|
| 列索引 | col = ? | 原值 |
| 函数索引 | f(col) = ? | 表达式一致 |

## 六、常见误区
1. 普通索引能服务 `lower(col)`——不能，需函数索引。
2. 任意函数都可索引——非确定性函数不行。
3. 函数索引自动维护——写时重算表达式有代价。

## 九、演进与趋势
部分索引（partial index，带 WHERE）与函数索引组合，进一步缩小索引体积，如只对活跃用户建索引。

## 十、小结
函数索引把表达式结果纳入索引，使表达式谓词也能走索引；前提是表达式确定且查询写法一致。
