# 一维前缀和

> 对应 youngyangyang04/leetcode-master 前缀和章节（区域和检索）、CLRS《Introduction to Algorithms》前缀和/扫描（scan）思想，以及 CyC2018/CS-Notes 前缀和题解。

## 一、背景与挑战

在算法题与工程系统中，"求一段连续区间的总和"是出现频率极高的基础操作：月活指标要按任意时间窗汇总、日志系统要统计某个时间段内的请求数、图像处理要用积分图快速得到矩形亮度和、数据库分析函数里的 `SUM() OVER (ROWS UNBOUNDED PRECEDING)` 本质上也是同一套思想。最朴素的做法是对每次询问直接遍历区间累加，单次 $O(r-l+1)$，最坏 $O(n)$；若有 $q$ 次询问，总代价 $O(qn)$。当 $n, q$ 同时达到 $10^5$ 量级时，$10^{10}$ 次运算在任何评测机或线上服务上都不可接受。

前缀和的动机非常直接：与其每次重新累加，不如一次性把"从开头到每个位置的累计和"存下来，之后任意区间和都能用两次查表和一次减法得到。预处理 $O(n)$，单次查询 $O(1)$，总代价 $O(n+q)$。这是一类典型的"离线预处理 + 在线查询"设计，在面试中几乎是一线大厂算法轮的送分题，也是后面更复杂技巧（子数组计数、二维积分图、差分）的公共底座。

需要注意的是，前缀和只解决"静态数组"场景：数组一旦被修改，预处理结果就失效了。若需要动态修改 + 区间查询，就要换成树状数组或线段树。理解这条能力边界，比背下公式更重要——面试官常常追问"如果中间插入一个数怎么办"，就是在探测你是否清楚这个限制。

## 二、核心原理

一维前缀和的核心是一个不变量：定义 $S[i]$ 为"前 $i$ 个元素之和"（采用 1-based 编号，$a_1 \dots a_n$），则

$$S[i] = a_1 + a_2 + \cdots + a_i$$

并且约定 $S[0] = 0$。这个空区间约定极其关键：它让"从第 1 个元素开始的区间"也能套用统一公式，而不需要特判。

有了 $S$，任意闭区间 $[l, r]$（$1 \le l \le r \le n$）的和可以这样得到：

$$\sum_{k=l}^{r} a_k = S[r] - S[l-1]$$

正确性一目了然：$S[r]$ 包含 $a_1 \dots a_r$，$S[l-1]$ 包含 $a_1 \dots a_{l-1}$，相减后恰好剩下 $a_l \dots a_r$，公共前缀被完全抵消。这就是"前缀"二字的含义——两段共享同一前缀，做差即得中间一段。

边界条件有三个必须守住：
1. $S[0]=0$ 必须显式初始化，否则查询 $[1, r]$ 时下标越界或需要写分支；
2. 若原数组是 0-based（Python 常见），查询函数的下标约定必须写清楚，最好在注释里标明是 0-based 还是 1-based；
3. 区间是闭区间 $[l,r]$ 还是半开区间 $[l,r)$ 必须在 API 命名和注释中固定下来，团队代码里混用是 bug 重灾区。

另一个容易被忽略的正确性要点：前缀和对负数完全成立。和的定义是线性累加，$a_i$ 为负并不破坏 $S[r]-S[l-1]$ 的恒等式，只是 $S$ 不再单调。因此"前缀和数组一定递增"是错误直觉，在带负权的数组上，任何依赖 $S$ 单调性的二分都必须先确认元素非负。

## 三、形式化与数学基础

递推式（离散形式的"积分"）：

$$S[0] = 0, \quad S[i] = S[i-1] + a_i \quad (1 \le i \le n)$$

区间查询：

$$\mathrm{sum}(l, r) = S[r] - S[l-1]$$

用求和号直接验证：

$$S[r] - S[l-1] = \sum_{k=1}^{r} a_k - \sum_{k=1}^{l-1} a_k = \sum_{k=l}^{r} a_k$$

从"离散微积分"的角度看，差分算子 $\Delta a_i = a_i - a_{i-1}$ 与前缀和互为逆运算（详见本专题《差分与前缀和的逆运算》）。前缀和相当于对序列做不定积分并固定 $S[0]=0$ 这个"积分常数"，区间和则是定积分 $S[r]-S[l-1]$。这个视角能解释为什么区间加法在差分上只动两个端点——那正是"求导"把局部变化集中到端点的效应。

复杂度证明：预处理对 $i=1..n$ 各做一次加法，时间 $\Theta(n)$，额外空间 $\Theta(n)$；每次查询恰好一次减法，$\Theta(1)$。总代价 $\Theta(n+q)$。对比朴素的 $\Theta(\sum_i |I_i|)$，当询问区间平均长度为 $\Theta(n)$ 时，加速比为 $\Theta(qn / (n+q)) \approx \Theta(n)$（$q$ 大时）。

再形式化一下不变量：对任意 $i$，$S[i]$ 始终等于 $a[1..i]$ 的真实和。维护该不变量的初始化在 $i=0$ 成立（空和为 0），归纳步：若 $S[i-1]$ 正确，则 $S[i] = S[i-1]+a_i$ 恰为 $a[1..i-1]$ 与 $a_i$ 之和，仍正确。查询公式的正确性如上，不依赖元素符号。

## 四、代码实现

标准 1-based 写法（把下标映射藏进长度 $n+1$ 的数组）：

```python
def build_prefix(a):
    """a: 0-based 原数组；返回 1-based 前缀和 s，s[i]=a[0]+...+a[i-1]"""
    n = len(a)
    s = [0] * (n + 1)
    for i in range(1, n + 1):
        s[i] = s[i - 1] + a[i - 1]
    return s


def range_sum(s, l, r):
    # 区间 [l, r]，1-based 闭区间，要求 1 <= l <= r <= n
    return s[r] - s[l - 1]


if __name__ == "__main__":
    a = [2, 4, 6, 8, 10]
    s = build_prefix(a)
    assert range_sum(s, 1, 3) == 12   # 2+4+6
    assert range_sum(s, 2, 2) == 4
    assert range_sum(s, 1, 5) == 30
```

0-based 变体（区间 $[l, r)$ 半开，和 Python 切片一致）：

```python
def build_prefix0(a):
    s = [0] * (len(a) + 1)
    for i, v in enumerate(a):
        s[i + 1] = s[i] + v
    return s

def range_sum_half(s, l, r):
    """半开区间 [l, r) 的和，0-based"""
    return s[r] - s[l]
```

关键变体——"前缀和 + 二分"求最小满足条件的窗口（要求 $a_i \ge 0$）：

```python
import bisect

def shortest_subarray_at_least(a, target):
    # a 非负，求和 >= target 的最短连续子数组长度
    n = len(a)
    s = build_prefix0(a)
    best = n + 1
    for r in range(1, n + 1):
        # 找最大的 l 使 s[r] - s[l] >= target，即 s[l] <= s[r] - target
        need = s[r] - target
        l = bisect.bisect_right(s, need, 0, r) - 1
        if l >= 0:
            best = min(best, r - l)
    return best if best <= n else 0
```

## 五、与其他技术对比

| 技术 | 预处理 | 单次区间和 | 支持单点修改 | 空间 | 适用场景 |
|------|--------|------------|--------------|------|----------|
| 朴素累加 | $O(1)$ | $O(n)$ | $O(1)$ | $O(1)$ | 查询极少 |
| 一维前缀和 | $O(n)$ | $O(1)$ | 不支持（需重建 $O(n)$） | $O(n)$ | 静态数组、海量查询 |
| 树状数组 | $O(n)$ | $O(\log n)$ | $O(\log n)$ | $O(n)$ | 动态单点改 + 区间和 |
| 线段树 | $O(n)$ | $O(\log n)$ | $O(\log n)$ | $O(n)$ | 动态改 + 区间和/最值/自定义信息 |
| 稀疏表 ST | $O(n\log n)$ | $O(1)$ | 不支持 | $O(n\log n)$ | 静态区间最值（幂等算子） |

取舍很清楚：只读查询用前缀和，常数最小、代码最短；有更新就上树状数组/线段树；区间最值这类没有逆元的聚合不能用前缀和"相减"，要换 ST 表或线段树。面试里能主动说出这条边界，比多写十行代码更加分。

## 六、常见误区

1. **下标体系混用**。原数组 0-based、前缀数组 1-based 时，`s[r]-s[l]` 与 `s[r]-s[l-1]` 只差一位，却会让所有含左端点 $l>1$ 的查询出错。后果是样例过了、边界全挂。对策：统一 1-based 并写进注释，或用半开区间 API 与 Python 切片对齐。
2. **忘记 `S[0]=0`**。不初始化哨兵，查询 $[1,r]$ 会越界或被迫写 `if l==0` 分支，分支一旦写漏就是局部错。哨兵不是可选优化，是公式成立的前提。
3. **误以为前缀和数组一定单调递增**。只有元素全非负才成立。在带负数数组上对 $S$ 二分求"第一个和达到 target 的位置"会得到错误答案，必须先确认非负，或改用二分答案 + 检查。
4. **区间定义（闭/半开）写反**。`r+1` 多减一个元素、左闭右开写成闭区间，会让"恰好 k 个元素"类问题差一。后果：差 1 的答案极难调试。对策：函数名带 `inclusive` / `half_open`，测试覆盖单元素区间。
5. **整数溢出**。C++/Java 中 $n \times \max|a_i|$ 可能超过 32 位；Python 无此问题，但若把结果传给其他系统仍要注意。后果是静默回绕，出现负和。对策：64 位累加或在语言层声明 `long`。

## 八、面试题

**1. LeetCode 303：数组不可变，多次区间求和。**
参考答案：构造 `s[i]=sum(a[:i])`（`s[0]=0`），`sum(l,r)=s[r+1]-s[l]`（0-based 半开）。预处理 $O(n)$、查询 $O(1)$、空间 $O(n)$。要点是说清哨兵与下标约定。

**2. 数组会被单点修改时，前缀和还合适吗？**
参考答案：不合适。单点改会使整个后缀 $S[i\ (i\ge pos)]$ 全部失效，重建 $O(n)$。改用树状数组（$O(\log n)$ 改 + 查）或线段树；若修改极少而查询极多，也可"攒一批修改再重建"做根号分治。

**3. 如何在 $O(1)$ 内回答"区间和是否等于 0"？**
参考答案：仍用前缀和，判断 `s[r]-s[l-1]==0`。追问"区间内是否存在和为 0 的子数组"才是前缀和 + 哈希（见本专题该篇）。

**4. 前缀和与积分图（integral image）什么关系？**
参考答案：一维积分图就是一维前缀和；二维积分图是二维前缀和，用于 CV 里矩形区域特征的常数时间求和（Viola-Jones 人脸检测的 Haar 特征即典型应用）。

## 九、演进与趋势

- **并行/向量化前缀和（scan）**：GPU 与 SIMD 中的 inclusive/exclusive scan 是基础原语（Thrust、CUB、SYCL），分治两趟（上行归约、下行传播）可把工作量保持 $O(n)$，深度降到 $O(\log n)$。这是"前缀和 = 离散积分"在现代硬件上的工程化。
- **高维与代数化推广**：二维前缀和、前缀异或、前缀 GCD、前缀模意义计数都是同一骨架；只要算子有合适的代数结构就能前缀化（见《前缀最值与其他前缀变换》）。
- **与哈希表结合**：`S[j]-S[i]=k` 的计数问题把前缀和从"查询工具"升级为"配对工具"，是中等难度题的主力（见本专题下一篇）。
- **在线系统中的窗口聚合**：时序库（Prometheus `rate`/`increase`）与流计算（Flink 滑动窗口）内部仍大量使用增量式前缀/累加结构，只是窗口边界随时间推进。

## 十、小结

一维前缀和用一次 $O(n)$ 预处理把区间和压成 $O(1)$ 的两次查表，是"空间换时间"最干净的例子：记住 $S[0]=0$ 哨兵、统一 1-based（或统一半开区间）、明确静态数组的前提，再按是否需要修改选择树状数组/线段树。它是差分、二维积分图、前缀哈希等一整族技巧的公共底座。
