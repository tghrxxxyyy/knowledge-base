# 差分在区间更新中的应用

> 对应 youngyangyang04/leetcode-master 差分应用（LeetCode 1109 航班预订、1094 拼车）与 CyC2018/CS-Notes；扫描线对照见《Concrete Mathematics》差分演算与竞赛几何资料。

## 一、背景与挑战

差分理论本身只有两行，真正拉开差距的是**应用场景识别**：什么时候该把问题转成"区间加 + 最后还原"。典型题：

- **航班预订（LeetCode 1109）**：$q$ 条预订记录 `first, last, seats`，表示区间内每个航班加 `seats` 个座位，问最终每个航班的总预订数。
- **拼车（LeetCode 1094）**：若干行程 `num, from, to`（上车点到下车点），车容量固定，问是否所有行程同时满足不超载。
- **日程/会议室**：多个区间预约，问某时刻最大重叠数。
- **涂色与覆盖**：若干区间刷漆，问最终每点颜色或覆盖次数。

朴素做法是每条记录真正改数组区间，$O(qn)$；当 $n$ 与 $q$ 同阶达 $10^3 \sim 10^5$，会立刻超时。更隐蔽的陷阱是：有人用"排序 + 双指针"硬做，代码长且边界多；有人用线段树，又重又慢。而这些问题的共同结构是——**离线、只关心最终（或扫描过程中的）前缀状态、操作是区间同增减**——正是差分的标准主场。

工程中同样常见：账务批量调账、监控规则对时间窗批量打标、游戏里对地图区间加 buff、发布系统对版本区间加灰度权重。识别出"区间加 + 静态收尾"模式，就能用差分把复杂度从平方级压到线性。

本篇重点不在"差分怎么写"（见上一篇），而在**如何建模**：边界语义（含/不含右端）、是否需要完全还原、如何边还原边判断、以及与扫描线的取舍。

## 二、核心原理

**通用建模三步**：

1. **把每条影响映射为区间加**：`[l, r)` 或 `[l, r]` 加 $v$。先确认题面语义：拼车的 `to` 是下车点，该点乘客已不在车上，故是半开区间 `[from, to)`，应在 `to` 处减；航班预订 `last` 是最后一个受影响航班，闭区间 `[first, last]`，应在 `last+1` 处减。**边界差一几乎全部出在这一步。**
2. **差分压缩**：`d[l] += v; d[r+1] -= v`（闭区间）或 `d[from] += n; d[to] -= n`（半开）。
3. **前缀还原并回答**：扫描一遍，`cur += d[i]` 即当前点的真实值。若问"每点最终值"，收集 `cur`；若问"是否始终不超过容量"，边扫边判；若问"最大重叠"，边扫边取 `max`。

**不变量**：扫描到位置 $i$ 时，`cur` 等于位置 $i$ 上所有区间的叠加值。因为 $d$ 已把每条区间的影响编码为端点事件，前缀和恰好按位置顺序摊开这些事件。

**为什么不需要线段树**：所有更新可离线预知，查询点按坐标递增扫描，差分的一次性前缀和即完成全部查询。线段树只在"更新与查询交错、且要随机查历史状态"时才必要。

**判断类问题甚至可以不显式还原数组**：拼车只关心扫描中 `cur` 是否超过 `capacity`，于是 $O(1)$ 空间（除 $d$ 外）即可，不必保存最终数组。

**稀疏坐标的处理**：若坐标范围远大于事件数（如 $10^9$），不能开 $10^9$ 的 $d$ 数组。对策是离散化坐标（排序去重后映射到下标）或改用扫描线（事件点排序后直接扫）。差分离散化后区间加要小心：离散化会把区间压成"块"，若要块内逐点值需在块内再处理；只问块端点/最大值时，扫描事件更简单。

## 三、形式化与数学基础

设坐标域 $[1..n]$，初始全 0。对每条操作 $t = (l_t, r_t, v_t)$，最终数组为

$$a[i] = \sum_{t: l_t \le i \le r_t} v_t$$

定义差分 $d[1..n+1]$，对每条操作执行

$$d[l_t] \mathrel{+}= v_t, \quad d[r_t+1] \mathrel{-}= v_t$$

则

$$a[i] = \sum_{k=1}^{i} d[k] = \sum_{t} v_t \big(\mathbf{1}[l_t \le i] - \mathbf{1}[r_t+1 \le i]\big) = \sum_{t: l_t \le i \le r_t} v_t$$

与定义一致。复杂度：建差分 $O(q)$，还原 $O(n)$，总计 $O(n+q)$；空间 $O(n)$。

拼车约束的形式化：行程 $t$ 占用区间 $[from_t, to_t)$，需求

$$\forall i,\ \sum_{t: from_t \le i < to_t} num_t \le capacity$$

用差分：`d[from_t] += num_t; d[to_t] -= num_t`，扫描时 `cur = Σ d[..]`，检查 `cur <= capacity`。注意 $i$ 是"站点编号"，$to$ 处已下车，故减法放在 $to$。

最大重叠问题：所有 $v_t = 1$，答案为 $\max_i a[i]$，扫描时取最大。若要"哪些点达到最大"，记录达到最大的坐标集合。

与扫描线的关系：差分 = 扫描线的"坐标连续化"版本。扫描线把事件按坐标排序后处理，不依赖坐标稠密；差分用下标直接定位，要求坐标可映射到 $O(n)$ 数组。两者复杂度在排序后同阶，差分常数更小、代码更短。

线性性保证多条操作可叠加后再一次还原，这是差分可批量、可并行（事件分别处理、最后合并 $d$）的依据。

## 四、代码实现

拼车（LeetCode 1094，半开区间语义）：

```python
def car_pooling(trips, capacity):
    """
    trips: list of [num_passengers, start, end]
    乘客在 start 上车，end 下车（end 处不再占用）
    """
    d = [0] * 1001            # 题目约束：0 <= location <= 1000
    for num, start, end in trips:
        d[start] += num
        d[end] -= num         # 半开区间：end 处释放
    cur = 0
    for v in d:
        cur += v
        if cur > capacity:
            return False
    return True


if __name__ == "__main__":
    assert car_pooling([[2, 1, 5], [3, 3, 7]], 4) is False
    assert car_pooling([[2, 1, 5], [3, 3, 7]], 5) is True
    assert car_pooling([[2, 1, 5], [3, 5, 7]], 3) is True
```

航班预订（LeetCode 1109，闭区间语义）：

```python
def corp_flight_bookings(bookings, n):
    d = [0] * (n + 2)
    for first, last, seats in bookings:
        d[first] += seats
        d[last + 1] -= seats   # 闭区间：last 仍占座
    res = []
    cur = 0
    for i in range(1, n + 1):
        cur += d[i]
        res.append(cur)
    return res


assert corp_flight_bookings([[1, 2, 10], [2, 3, 20], [2, 5, 25]], 5) == [10, 55, 45, 25, 25]
```

最大重叠数（离散坐标用事件排序 = 扫描线）：

```python
def max_overlap(intervals):
    events = []
    for l, r in intervals:   # 闭区间 [l, r]
        events.append((l, 1))
        events.append((r + 1, -1))
    events.sort()
    cur = best = 0
    for _, delta in events:
        cur += delta
        best = max(best, cur)
    return best
```

## 五、与其他技术对比

| 方法 | 时间 | 空间 | 边界处理 | 适合 |
|------|------|------|----------|------|
| 朴素逐点加 | $O(qn)$ | $O(n)$ | 简单 | 极小数据 |
| 差分 | $O(n+q)$ | $O(n)$ | 需分清开闭 | 坐标稠密、离线 |
| 扫描线（事件） | $O(q\log q)$ | $O(q)$ | 事件点明确 | 坐标稀疏/只需极值 |
| 线段树（懒标记） | $O(q\log n)$ | $O(n)$ | 灵活 | 动态改查交错 |
| 树状数组 | $O(q\log n)$ | $O(n)$ | 灵活 | 区间加 + 区间和在线 |

取舍：能离线就用差分；坐标大而稀疏用扫描线或离散化差分；需要中途任意查询上线段树/BIT。面试里先问清"是否只在最后查询"，再选结构，是成熟表现。

## 六、常见误区

1. **开闭区间语义搞错**。拼车应在 `end` 处减（乘客已下车），航班预订应在 `last+1` 处减（last 仍有效）。后果：要么多载一人、要么少订一座，边界点答案错误。对策：把语义写成注释 `// [start, end) 半开`，并用"单点区间"用例测试。
2. **坐标范围未预留导致越界**。`d[r+1]` 超出数组长度。后果：崩溃或负下标污染。对策：`d` 开 `n+2`，或条件判断。
3. **忘记最终还要前缀和**。把差分数组当答案输出。后果：答案是一堆正负事件。对策：变量名 `diff` vs `result`，还原后再返回。
4. **中途要查询却用差分**。若每次操作后都查询，差分退化为 $O(n)$ 每查。后果：TLE。对策：识别在线需求，改 BIT/线段树。
5. **稀疏坐标直接开大数组**。坐标到 $10^9$ 时开数组浪费内存甚至失败。后果：MLE。对策：离散化或扫描线；Python 里可用 `dict` 当稀疏差分，最后排序键扫描。

## 八、面试题

**1. 拼车问题为何只需判前缀和是否超容量？**
参考答案：任意时刻车上人数 = 该坐标上所有未完成行程的人数和 = 差分前缀和 `cur`。若扫描全程 `cur <= capacity`，则一切时刻满足；一旦超过即可提前返回 False。无需还原完整数组，也不需要记录每点。

**2. 区间更新与区间查询分别适合什么结构？**
参考答案：只更新最后查一次 → 差分；更新查询交错 → 树状数组（区间和）或线段树（区间和/最值/自定义）；区间加 + 单点查也可用 BIT 差分技巧；区间加 + 区间和在线用两棵树状数组或懒标记线段树。

**3. 航班预订与拼车的边界处理有何不同？**
参考答案：前者闭区间 `[first, last]`，反向修改在 `last+1`；后者半开 `[from, to)`，反向修改在 `to`。差别来自"右端点是否仍占用"，建模时必须先写清语义。

**4. 坐标稀疏（$10^9$）怎么办？**
参考答案：坐标离散化后在小数组上差分（注意区间被压成块），或用事件扫描线排序后处理；Python 可用 `defaultdict` 做稀疏差分，最后按坐标有序扫描。

## 九、演进与趋势

- **二维矩形批量更新**：矩形加用二维差分四角更新，最后二维前缀和还原，与一维完全同构（见《二维前缀和》）。
- **树上差分**：路径加、子树加，把端点标记放到 LCA 上，最后一次 DFS 还原，是图论题标配。
- **与线段树懒标记的统一**：懒标记本质上是"延迟的区间差分/加法标记的下推"，理解差分有助于理解 lazy propagation 的正确性。
- **流式/增量管道**：Flink/Spark 窗口增量聚合、时序库的 counter reset 处理，都可看作"事件差分 + 前缀恢复"的工程变体。
- **并行事件合并**：多线程分别累加差分、最后原子合并 $d$ 并还原，是并行前缀思想在更新侧的应用。

## 十、小结

差分把"批量区间加"压成端点两次 $O(1)$ 操作，一次前缀和还原即可回答最终值、峰值、是否超限等问题。应用时先抠清区间开闭语义，再选差分/扫描线/线段树；识别"离线、区间同增减、静态收尾"这一模式，就能用 $O(n+q)$ 干掉平方级暴力。
