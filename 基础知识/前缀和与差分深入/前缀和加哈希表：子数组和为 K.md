# 前缀和 + 哈希表（子数组和为 K）

> 对应 youngyangyang04/leetcode-master「和为 K 的子数组」与 CyC2018/CS-Notes 前缀和哈希；同类思想见 CLRS 中 pair-counting 与哈希表章节。

## 一、背景与挑战

"统计和为 $k$ 的连续子数组个数"（LeetCode 560）是一道标志性中等题。朴素做法是枚举左右端点 $i \le j$，对每个区间累加求和，$O(n^2)$ 次枚举、每次 $O(n)$ 最坏共 $O(n^3)$，即便用前缀和优化到 $O(n^2)$，在 $n = 10^5$ 时仍然不可行。更麻烦的是，这类问题往往还有变体：最长子数组、是否存在、子数组个数模 $p$ 为 0、子数组异或为 $k$……如果只会暴力，每个变体都要重写一遍双重循环。

问题的结构性障碍在于：子数组由两个端点决定，直接枚举是二元的；而"和"这个条件一旦写成前缀和之差，就退化为**一元约束**：$S[j] - S[i] = k$。于是问题从"枚举区间"变成"对每个右端点 $j$，找有多少个历史前缀 $S[i]$ 恰好等于 $S[j]-k$"。后者正是哈希表（计数映射）的主场——$O(1)$ 期望查询/更新，一次扫描即可。

在面试与工程中的位置：这是"前缀和 + 哈希"范式的入门题，后面接 523（模意义）、974（被 K 整除）、325（最长和为 k）、437（路径总和 III，树上变体）等一串题；工程上，流式统计"窗口内累计增量是否达到阈值"、账单里找对冲子段、监控里找累计偏差归零的时段，本质都是同一模型。它要求候选人同时掌握前缀和、哈希计数、以及**更新顺序**（先查后改）这一关键细节。

## 二、核心原理

设前缀和 $S[i] = a_1 + \cdots + a_i$（1-based，$S[0]=0$）。子数组 $a_{i+1..j}$ 的和为

$$S[j] - S[i]$$

要求 $S[j] - S[i] = k$，等价于

$$S[i] = S[j] - k$$

因此：从左到右扫描 $j = 1..n$，维护一个哈希表 `count`，其中 `count[x]` 表示"已经出现过的前缀和 $x$ 的个数"。每到一个 $j$，先查询 `count[S[j]-k]`，把答案累加这么多；再把当前 $S[j]$ 放入表中，供之后的右端点使用。

三个细节决定正确性：

1. **初值 `count[0] = 1`**。空前缀 $S[0]=0$ 必须在扫描开始前就存在于表中。否则当某个子数组恰好从下标 1 开始（即 $S[j]=k$）时，匹配不到 $S[i]=0$，漏计。
2. **先查询、后更新**。若先把自己 $S[j]$ 加进表再查 `S[j]-k`，当 $k=0$ 时会把"空区间"或自身配对误算；正确顺序保证配对的 $(i, j)$ 满足 $i < j$，即子数组非空且右端严格在左端之后。
3. **负数元素完全合法**。与"双指针只能处理正数"不同，哈希计数法不要求元素非负，因为它是纯代数等价变换，不依赖单调性。

为什么正确（不变量）：扫描到 $j$ 时，`count` 恰好包含 $\{S[0], S[1], \ldots, S[j-1]\}$ 的频次。于是 `count[S[j]-k]` 等于满足 $0 \le i < j$ 且 $S[i] = S[j]-k$ 的 $i$ 个数，也就是以 $j$ 为右端、和为 $k$ 的子数组个数。把 $j$ 从 1 到 $n$ 的贡献求和，每个合法区间 $[i+1, j]$ 恰被计数一次，无重复无遗漏。

## 三、形式化与数学基础

目标量：

$$\#\{(i,j) : 0 \le i < j \le n,\ S[j] - S[i] = k\}$$

等价改写：

$$\#\{(i,j) : i < j,\ S[i] = S[j] - k\} = \sum_{j=1}^{n} \#\{i < j : S[i] = S[j] - k\}$$

定义计数函数 $C_j(x) = \#\{i < j : S[i] = x\}$，则

$$\mathrm{ans} = \sum_{j=1}^{n} C_j(S[j] - k)$$

增量维护：$C_{j+1} = C_j + \delta_{S[j]}$（在 $S[j]$ 处加一），故可用一张哈希表从左到右推进，每步查询与更新均摊 $O(1)$，总时间 $O(n)$，空间 $O(n)$（不同前缀和至多 $n+1$ 个）。

$k=0$ 时验证：此时 $S[i]=S[j]$，答案是"相等前缀和的对数" $\sum_x \binom{c_x}{2}$，其中 $c_x$ 为 $x$ 的总出现次数。这与扫描算法一致，且说明"先查后改"恰好统计了无序对中的 $i<j$ 方向。

最长子数组版本的目标函数不同，是

$$\max\{j - i : S[j] - S[i] = k\} = \max\{j - i : S[i] = S[j] - k\}$$

对每个 $j$ 只需要最早出现的 $S[j]-k$，因此哈希表存**首次出现下标**而非频次：`first[x] = min index with prefix sum x`。两种目标（计数 vs 最长）对应两种哈希表值类型，不能混用。

模意义变体（523 / 974）：若要求 $S[j] - S[i] \equiv 0 \pmod p$，则改为查 $S[i] \equiv S[j] \pmod p$；注意负数取模在 Python 中 `%` 已给出非负余数，在 C++/Java 需要 `(x % p + p) % p` 归一化，否则哈希键不一致。

## 四、代码实现

计数版本（LeetCode 560）：

```python
def subarray_sum_k(nums, k):
    """返回和为 k 的连续子数组个数，元素可为负"""
    count = {0: 1}          # 空前缀 S[0]=0
    pref = 0
    ans = 0
    for x in nums:
        pref += x
        ans += count.get(pref - k, 0)   # 先查：找历史前缀
        count[pref] = count.get(pref, 0) + 1  # 后改：放入自己
    return ans


if __name__ == "__main__":
    assert subarray_sum_k([1, 1, 1], 2) == 2
    assert subarray_sum_k([1, 2, 3], 3) == 2      # [1,2], [3]
    assert subarray_sum_k([1, -1, 0], 0) == 3     # [1,-1], [0], [1,-1,0]
    assert subarray_sum_k([], 0) == 0
```

最长版本（LeetCode 325）：

```python
def longest_subarray_sum_k(nums, k):
    first = {0: -1}         # 前缀和 0 出现在虚拟下标 -1 之前
    pref = 0
    best = 0
    for j, x in enumerate(nums):
        pref += x
        if pref - k in first:
            best = max(best, j - first[pref - k])
        if pref not in first:   # 只记最早出现
            first[pref] = j
    return best
```

被 K 整除的子数组个数（LeetCode 974）：

```python
def subarrays_div_by_k(nums, k):
    count = {0: 1}
    pref = 0
    ans = 0
    for x in nums:
        pref += x
        rem = pref % k          # Python % 对负数返回非负余数
        ans += count.get(rem, 0)
        count[rem] = count.get(rem, 0) + 1
    return ans
```

## 五、与其他技术对比

| 方法 | 时间 | 空间 | 限制 | 适用 |
|------|------|------|------|------|
| 双重循环 + 前缀和 | $O(n^2)$ | $O(1)$ | 无 | $n \le 10^3$ |
| 前缀和 + 哈希计数 | $O(n)$ | $O(n)$ | 无（可负） | 计数/最长、任意符号 |
| 双指针滑动窗口 | $O(n)$ | $O(1)$ | **元素非负**（或单调） | 最长/最短、正数数组 |
| 暴力枚举起点 + 累加 | $O(n^2)$ | $O(1)$ | 无 | 教学 |

取舍：只要元素可负，就必须用哈希计数；若保证正数且问"最短/最长"，双指针更省空间。两者可对照记忆：**单调性换空间，哈希换通用性**。和"两数之和"对比也很有启发——那是数组上找 $a[i]+a[j]=k$，用值到下标的哈希；这里是前缀上找 $S[i]+(k)=S[j]$，用值到次数的哈希，同构。

## 六、常见误区

1. **忘记 `count[0] = 1`**。后果：所有"从开头起"的合法子数组被漏掉，例如 `[1,2,3], k=3` 只数到 `[3]` 而漏掉 `[1,2]`（若用错误顺序甚至更糟）。对策：把空前缀当作第 0 个历史前缀写进初始化。
2. **先更新再查询**。后果：$k=0$ 时把空子数组或自身算进去，计数偏大；也可能把 $i=j$ 的退化区间计入。对策：代码注释写明"先查后改，保证 $i<j$"，并用 `k=0` 的用例测试。
3. **用 `set` 而不是计数 `dict`**。后果：$S$ 重复出现多次时只算一次，计数偏小，例如全 0 数组、$k=0$。对策：值类型必须是出现次数（计数版）或最早下标（最长版）。
4. **模运算负余数**。Java/C++ 中 `-3 % 5 == -3`，与 `2` 不同键。后果：被 K 整除类问题答案错误。对策：`((pref % k) + k) % k`。
5. **把本模板套到"要求正数"的最短窗口**。哈希计数能求个数/最长，但"最短且和为 k"在可负时其实更难（无法二分/双指针）；正数时才可用滑动窗口。后果：方法与约束不匹配。对策：先确认元素符号与所求目标（计数/最长/最短）。

## 八、面试题

**1. 为什么 `count` 初值要是 `{0: 1}`？**
参考答案：代表空前缀 $S[0]=0$。当 $S[j]=k$ 时，子数组 $a_{1..j}$ 合法，需要匹配 $S[i]=0, i=0$。没有它会漏掉所有左端点为 1 的解。

**2. 如何改为"最长的和为 k 的子数组"？**
参考答案：哈希表存每个前缀和**第一次出现的下标**；对每个 $j$ 查 `first[S[j]-k]`，更新 `best = max(best, j - first[...])`。仍是 $O(n)$。

**3. 数组元素有负数，还能用滑动窗口吗？**
参考答案：不能。滑动窗口依赖"右扩使和增大、左缩使和减小"的单调性，负数破坏它，左指针需要回退，最坏退回 $O(n^2)$。此时用前缀和 + 哈希。

**4. 扩展：树上路径和为 k（LeetCode 437）怎么做？**
参考答案：DFS 维护根到当前节点的前缀和 `pref`，沿路径查 `count[pref-k]`，进入节点前 `count[pref]+=1`，退出时回溯减一。与数组版同构，只是扫描顺序变成 DFS。

## 九、演进与趋势

- **模意义与整除类**：523、974 把等式换成同余，成为"前缀哈希"的固定变形；竞赛里"子数组和模 $2^w$"配合位运算常见。
- **前缀异或**：`X[j] ^ X[i] = k` 即 `X[i] = X[j] ^ k`，异或是自身逆元，模板几乎照搬（见《前缀最值与其他前缀变换》）。
- **二维扩展**：子矩阵和为 k，固定上下边界降维成一维前缀数组后再用本模板，$O(n^2 m)$。
- **流式/在线统计**：监控与账务系统里"累计偏差等于阈值的时段数"可在线性扫描中实时维护，是本算法的工程投影；窗口版（只看最近 T 时间）则要配合滑动窗口与双端队列。
- **与随机化/多项式哈希结合**：字符串子串匹配、模式出现次数等问题中，前缀哈希（rolling hash）是另一条"前缀 + 哈希"路线，注意哈希冲突与模数选择。

## 十、小结

把区间和条件改写成前缀之差 $S[j]-S[i]=k$，再用哈希表统计"历史前缀 $S[j]-k$ 的出现次数"，即可 $O(n)$ 完成计数或求最长。三要点：`count[0]=1` 的空前提、先查后改保证 $i<j$、负数可用但模运算需归一化。这一模板是前缀和从查询工具升级为配对工具的关键一步。
