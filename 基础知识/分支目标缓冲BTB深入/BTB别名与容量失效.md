# BTB别名与容量失效

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》第3章。

## 一、背景与挑战
BTB 容量有限，采用哈希索引时会把不同分支指令映射到同一槽位，产生别名（alias）；工作集超过容量则产生容量失效（capacity miss），频繁换入换出。

## 二、核心原理
BTB 通常按 $(pc\;\text{hash})\bmod \text{sets}$ 索引，每 set 多路（associative）。别名指两个不同分支共享 tag 比较失败的冲突；容量失效则是总条目不足。二者都表现为 BTB 命中率下降。

## 三、形式化与数学基础
设索引位宽 $s$，相联度 $a$，总容量 $C=2^s\cdot a$。对任意 PC 集合 $W$，若 $|W|>C$ 则必存在容量失效；若两地址哈希同槽且替换策略驱逐，则产生别名冲突。

## 四、代码实现
```c
// 简单的直接映射 BTB，易别名
#define SETS 1024
Entry btb[SETS];
int idx(uint64_t pc){ return (pc >> 2) & (SETS-1); }
```

## 五、与其他技术对比
直接映射 BTB 硬件简单但别名严重；组相联减少别名但以面积和功耗为代价；软件可通过布局让热分支分散地址。

## 六、常见误区
误以为加大 BTB 总能提升性能。若工作集不大，额外容量只是浪费；且多端口访问会拖慢取指关键路径。

## 七、与开源书/权威来源对应
Hennessy & Patterson 在 cache/BTB 部分讨论了容量与冲突失效的通用原理，可类比到 BTB。

## 八、面试题
问：如何区分 BTB 的别名失效与容量失效？答：别名是不同分支争同一 set，容量是整体条目不足；前者靠相联度/哈希缓解，后者靠增大容量。

## 九、演进与趋势
现代采用分层 BTB（小快 L0 + 大慢 L1/L2）和上下文相关哈希，兼顾延迟与容量。

## 十、小结
BTB 失效与 cache 失效同构：容量与冲突两类，优化手段也类似，理解其一即理解其二。
