# 间接分支预测与置信度

> 对应 Intel SDM 卷3 分支预测相关章节与 Hennessy & Patterson 第3章。

## 一、背景与挑战
间接分支（如 switch、虚函数调用、跳转表）目标从寄存器读取，可能指向多个地址。普通 BTB 只能存一个目标，对多目标间接分支预测差。

## 二、核心原理
间接分支预测器为每个分支维护多候选目标（或用全局历史哈希选择）。置信度（confidence）位标记该预测是否可靠：低置信时硬件可能采取保守策略或结合 IT-TAGE 等机制。

## 三、形式化与数学基础
设候选目标集 $\{t_1,\dots,t_m\}$，预测函数：
$$P(pc,GHR)=\arg\max_k \text{count}(pc,GHR \to t_k)$$
置信度 $c = \frac{\max_k \text{count}_k}{\sum_j \text{count}_j}$。

## 四、代码实现
```c
//  Indirect BTB 候选数组示意
typedef struct { uint64_t target; int cnt; } ITarget;
ITarget ibtb[SETS][WAYS];
// 取计数最高且超过阈值的候选
```

## 五、与其他技术对比
条件分支预测「方向」，间接分支预测「选哪个目标」。二者共用 BTB 框架但后者需多目标存储，硬件更重。

## 六、常见误区
误以为间接分支无法预测。现代 IT-TAGE / indirect BTB 能很好处理多态调用，只是代价高于条件分支。

## 七、与开源书/权威来源对应
Intel SDM 描述间接分支在推测执行中的处理；Spectre v2 正是利用间接分支预测进行训练与泄露。

## 八、面试题
问：Spectre v2 利用了什么？答：攻击者训练间接分支（如间接调用）的 BTB 指向恶意 gadget，使受害者误推测执行。

## 九、演进与趋势
为缓解侧信道，硬件引入 IBRS、eIBRS 与推测限制，并在上下文切换时选择性刷新间接预测状态。

## 十、小结
间接分支预测是多目标选择问题，置信度帮助硬件在不确定时保守行事，也是安全攻防的焦点。
