# 间接分支预测与置信度

> 对应 Intel SDM 卷3（分支与推测执行）；Hennessy & Patterson《Computer Architecture: A Quantitative Approach》第3章；Spectre v2（CVE-2017-5715）相关分析。

## 一、背景与挑战

间接分支（indirect branch）的目标地址来自寄存器或内存，例如 C 的 `switch`/跳转表、C++ 的虚函数调用、函数指针回调、动态语言的分派。与条件分支「只需预测跳/不跳」不同，间接分支要「从多个可能目标中选一个」，且一个间接分支可能合法地指向几十甚至上百个目标（多态调用）。普通 BTB 每个条目通常只存一个最近目标，对多目标间接分支预测准确率很低。更棘手的是：间接分支预测错误不仅是性能问题，还是 Spectre v2 侧信道的入口——攻击者可训练间接分支预测器指向恶意 gadget，诱使受害者推测执行泄露数据。

## 二、核心原理

现代间接分支预测器（indirect BTB / ITB）为每个分支维护「多候选目标」或「按全局历史选择」的机制：

- 多候选存储：每个 set 内保存若干（target, count）对，用最近出现频率最高的候选作为预测；计数器记录各候选热度。
- 历史选择：用全局历史（GHR）或路径历史哈希选择目标，使同一间接分支在不同调用上下文下指向不同目标。
- 置信度（confidence）：为每个预测附一个置信位/计数器，标记该预测是否可靠。低置信时硬件可保守处理（如回退顺序取指、或结合更慢但更准的机制），降低误预测代价。

置信度的本质是对「预测器自身不确定度」的建模，使前端在「快但可能错」与「慢但稳」之间按把握程度取舍。

## 三、形式化与数学基础

设间接分支 $pc$ 在全局历史上下文 $G$ 下的候选目标集 $\{t_1,\dots,t_m\}$，预测函数为「取最高计数的候选」：

$$ P(pc, G) = \arg\max_k\ \text{count}(pc, G \to t_k) $$

置信度定义为最高候选计数占总计数的比例：

$$ c = \frac{\max_k \text{count}_k}{\sum_{j} \text{count}_j} \in [0,1] $$

当 $c$ 高于阈值 $\theta$ 时采用该预测；低于 $\theta$ 时进入保守路径（如顺序取指或查更大的间接预测结构）。对 $m$ 很大的多态调用，$c$ 天然偏低，预测器应如实降低置信而非强行选一个。

由此可得一个下界结论：在「各目标服从均匀分布」的理想多态场景下，任何「只看历史计数」的预测器准确率都不超过 $1/m$——除非引入额外信息（如目标地址的部分位、调用者身份），否则无论表多大都无法突破。这解释了为什么高度多态的代码（如大型 `switch` 或动态分派）始终是预测器的难点。

## 四、代码实现

下面给出间接 BTB 多候选结构的简化建模（示意）：

```c
// 简化的间接 BTB：每个 set 多路候选
#define SETS  1024
#define WAYS  4
typedef struct { uint64_t target; int cnt; int tag; } ITarget;

ITarget ibtb[SETS][WAYS];

// 选计数最高且超阈值的候选
uint64_t predict(uint64_t pc, uint64_t ghr) {
    int i = (pc ^ ghr) & (SETS - 1);
    int best = -1, maxc = 0;
    for (int w = 0; w < WAYS; w++) {
        if (ibtb[i][w].tag == pc && ibtb[i][w].cnt > maxc) {
            maxc = ibtb[i][w].cnt; best = w;
        }
    }
    if (best < 0) return pc + 4;          // 未命中：顺序取指
    return ibtb[i][best].target;
}
```

```c
// 置信度：最高候选占比低于阈值时降级为保守预测
double confidence(ITarget set[WAYS], int total) {
    int maxc = 0;
    for (int w = 0; w < WAYS; w++) if (set[w].cnt > maxc) maxc = set[w].cnt;
    return total ? (double)maxc / total : 0.0;   // 占比即置信度
}

uint64_t predict_with_conf(uint64_t pc, uint64_t ghr, double theta) {
    ITarget *set = &ibtb[(pc ^ ghr) & (SETS - 1)][0];
    int total = sum_counts(set, WAYS);
    if (confidence(set, total) < theta)
        return pc + 4;                 // 低置信：保守顺序取指，避免高代价误预测
    return predict(pc, ghr);
}
```

低置信时选择「保守顺序取指」是一种「主动放弃预测」的策略：它牺牲了潜在的性能收益，换取避免「跳到错误目标后深冲刷」的高代价，在预测器本身不可靠时是合理取舍。

## 五、与其他技术对比

| 预测对象 | 需预测什么 | 存储代价 | 典型机制 |
| --- | --- | --- | --- |
| 条件分支 | 跳/不跳（方向） | 小 | 2-bit 饱和计数器 |
| 间接分支 | 选哪个目标 | 大（多候选） | 多候选 ITB / IT-TAGE |
| 返回分支 | 返回地址 | 极小 | RAS |
| 数据相关分支 | 由寄存器值决定的方向 | 中 | 感知机/混合预测器 |

间接分支预测是「多目标选择」问题，共用 BTB 框架但需多目标存储，硬件远比条件分支预测重；其置信度机制是条件分支预测通常不需要的额外维度。

## 六、常见误区

误区一：间接分支无法预测。错——现代 IT-TAGE / indirect BTB 能很好处理多态调用，只是代价高于条件分支，且对「目标数极多且均匀」的场景仍困难。

误区二：置信度越高越准。错——置信度是「历史一致性」的统计，并不代表绝对正确；攻击者也可把某目标训练到高置信。

## 七、与开源书·权威来源对应

- Intel SDM 卷3 描述间接分支（JMP/CALL reg）在推测执行中的处理，以及 IBRS、eIBRS 等缓解措施。
- Hennessy & Patterson 第3章讨论间接分支预测的结构性难点（多目标）。
- Spectre v2（CVE-2017-5715）公开分析揭示：攻击者训练间接 BTB 指向恶意 gadget，使受害者误推测执行，是安全与微架构交叉的经典案例。
- Phoronix / 微架构评测常给出不同 CPU 的间接预测器规模差异。

## 八、面试题

1. 间接分支与条件分支预测的核心区别？要点：前者「选哪个目标」（多目标），后者「是否跳」（方向）；前者存储代价高。
2. Spectre v2 利用了什么？要点：训练间接分支（如间接调用）的 BTB 指向恶意 gadget，使受害者误推测执行后通过缓存侧信道泄露数据。
3. 置信度的作用？要点：标记预测可靠度，低置信时硬件保守处理以降低误预测/侧信道代价。
4. 为什么均匀多态的间接分支难以预测？要点：无额外信息时准确率上界仅为 $1/m$，表再大也无法突破。
5. 为什么把历史混入索引有帮助？要点：同一间接分支的目标常由调用路径决定，按上下文分表可让不同调用各记各的目标。
6. 间接预测器为何是安全议题？要点：预测状态跨特权级/进程复用会成为投毒入口，因此需要 IBRS/eIBRS 与切换时刷新等隔离手段。

## 九、演进与趋势

为缓解侧信道，硬件引入 IBRS、eIBRS 与推测限制（如限制跨特权级复用间接预测状态），并在上下文切换时选择性刷新间接预测器。间接预测器本身向 IT-TAGE、ITEAGE（加入循环与统计校正）演进，同时操作系统的 RETPOLINE（用返回序列替代间接分支）作为软件缓解仍广泛部署。

另一方向是「把分派信息显式暴露给硬件」：部分 ISA 扩展与编译器提示（如间接分支的类型/目标提示）尝试减少纯运行期猜测，把静态可知的信息传给预测器。这类协同能让多态分派在编译期就获得更好预测，是「软硬协同提升间接预测」的可行路径。

## 十、小结

间接分支预测是「多目标选择」问题，多候选存储与全局历史选择构成其核心，置信度帮助硬件在不确定时保守行事。它既是性能瓶颈点，也是 Spectre v2 等侧信道的攻击面，是微架构安全与性能的交汇处；而「均匀多态下的 $1/m$ 上界」提醒我们，这一问题的改进空间既受硬件限制，也受程序语义信息的限制。
