# 分支历史表与两位饱和计数器

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》第3章（分支预测）；Bryant & O'Hallaron《Computer Systems: A Programmer's Perspective》第4章。

## 一、背景与挑战

预测「分支是否跳转（方向）」最朴素的方法是记录上一次的结果（1-bit 计数器）：上一次 taken 就预测这次 taken。但它对「交替分支」（如循环末次不跳转、奇偶交替）极不友好——每次结果翻转都必然误预测，交替模式下误预测率高达 50%。根本问题是 1-bit 没有「迟滞」（hysteresis）：一次偶发的异常翻转就被当成趋势。两位饱和计数器（2-bit saturating counter）用「需要连续两次相反结果才翻转预测」引入迟滞，显著降低此类抖动带来的误预测，是现代方向预测最基础的构件。

误预测的代价不是「一次判断错」，而是「已取入的错误路径全部作废 + 重新取指」，代价随流水线深度与取指带宽放大。因此即便把误预测率从 5% 降到 3%，在深流水线超核上也可能带来两位数百分比的性能差异，这正是业界持续投入预测器研究的原因。

## 二、核心原理

每个分支条目维护一个 2-bit 状态机，四个状态分别为：强不跳（SN, 00）、弱不跳（WN, 01）、弱跳（WT, 10）、强跳（ST, 11）。预测位取最高位（bit1）：状态 $\ge$ WT（即 10/11）预测 taken，否则预测 not taken。

更新规则：taken 时状态加 1（饱和于 11），not taken 时减 1（饱和于 00）。关键在于——从「强」状态翻转到「预测方向相反」需要连续两次相反结果：例如当前 ST（11），先 not taken → WT（10，预测仍 taken），再 not taken → WN（01，预测才翻为 not taken）。这「两次才翻」的迟滞，使偶发异常（如循环末次不跳转）不会立刻破坏「整体倾向于 taken」的预测。

工程上，所有分支的 2-bit 状态被组织成「模式历史表（PHT）」：以分支地址（或与全局历史哈希后的索引）定位表项，每项 2 bit。表越大覆盖的分支越多、别名越少，但取指关键路径上的读取与更新延迟也越高，因此实际 CPU 会在容量与延迟间取折中（常见数十 K 项规模）。值得注意的是，2-bit 计数器本身不记录「历史」，只记录「该分支自身近期倾向」，这正是它处理不了跨分支相关性的根本原因，需要 GShare/TAGE 补足。

## 三、形式化与数学基础

设状态 $S_t \in \{0,1,2,3\}$（SN=0,WN=1,WT=2,ST=3），每周期接收结果 $r_t \in \{+1\text{(taken)}, -1\text{(not taken)}\}$，饱和更新：

$$ S_{t+1} = \text{clip}(S_t + r_t,\ 0,\ 3), \quad \text{clip}(x,l,u)=\min(\max(x,l),u) $$

预测位：

$$ P_t = \lfloor S_t / 2 \rfloor \in \{0,1\} $$

误预测率分析：对一个基础概率 $p$ taken 的分支，2-bit 计数器把状态收敛到与 $p$ 对应的稳态分布，只有当「连续两次相反」发生时才误预测，相比 1-bit 在 $p$ 接近 0 或 1 时误预测率近似减半（仅偶发翻转触发）。

若分支的实际序列按 Markov 链建模，转移概率为 $\Pr[taken \to not\ taken]$，则误预测率正比于「跨越预测阈值的转移概率」，即连续两次反方向转移的联合概率。这给出了一个直观结论：2-bit 相比 1-bit 的收益，恰好来自「把单次噪声翻转移除出预测」，收益大小与该噪声出现频率成正比。

## 四、代码实现

下面给出 2-bit 计数器的最简实现（用枚举与饱和加法）：

```c
typedef enum { SN = 0, WN = 1, WT = 2, ST = 3 } State;

int predict(State s) {
    return s >= WT;          // 高位为 1 则预测 taken
}

State update(State s, int taken) {
    if (taken && s < ST)  return (State)(s + 1);
    if (!taken && s > SN) return (State)(s - 1);
    return s;                // 饱和，保持
}
```

实际硬件会把所有分支的 2-bit 状态组织成「模式历史表（PHT）」，用分支地址（或地址与全局历史的哈希）索引。

```c
// 索引与更新：位运算实现，避免取模与分支
#define PHT_SIZE (1u << 16)
static uint8_t pht[PHT_SIZE];                // 每项 2 bit（此处用 1 字节示意）

static inline unsigned idx(uint64_t pc, uint64_t ghr) {
    return (unsigned)((pc ^ ghr) & (PHT_SIZE - 1));   // 低位哈希
}

void train(uint64_t pc, uint64_t ghr, int taken) {
    uint8_t *e = &pht[idx(pc, ghr)];
    *e = taken ? (*e | (*e >> 1)) : (*e & ~(*e >> 1));  // 饱和更新示意
}
```

位运算实现的意义在于「预测必须在取指当拍完成」，任何分支或取模都会落在关键路径上，因此硬件与高性能模拟器都用掩码与移位而非除法。

## 五、与其他技术对比

| 预测器 | 交替模式误预测 | 硬件 | 备注 |
| --- | --- | --- | --- |
| 1-bit | ~50% | 最小 | 无迟滞，抖动敏感 |
| 2-bit 饱和 | 低 | 小 | 工业标准 |
| 全局历史+局部（GShare） | 更低 | 中 | 利用相关性 |
| TAGE | 最低 | 高 | 多长度历史 |
| 感知机预测器 | 低（特定负载） | 高（权重存储） | 长历史线性组合 |

1-bit 在交替模式上半数误判；2-bit 已覆盖绝大多数收益。更宽计数器（3-bit/4-bit）边际收益极低，却占用更多位，故工业界普遍采用 2-bit。

## 六、常见误区

误区一：计数器越宽越好。错——实验表明 2-bit 已捕获绝大部分迟滞收益，更宽状态机边际收益低、且占用更多 BTB/PHT 位与功耗。

误区二：2-bit 能消除所有误预测。错——它只缓解「偶发翻转」，对「真正均匀分布（50%/50%）」的分支仍约 50% 误预测，这类需靠全局历史相关性（GShare/TAGE）处理。

误区三：预测位是最低位。错——预测位取最高位（bit1），迟滞体现在需要连续两次才翻越中间阈值。

误区四：PHT 越大越好。错——容量增大会拉长索引与访问延迟，且超出实际分支工作集后收益迅速饱和。

误区五：2-bit 与「bimodal」是两种不同结构。错——仅有两个稳定预测方向的 2-bit 计数器常被直接称为 bimodal 预测器，术语同源。

## 七、与开源书·权威来源对应

- Hennessy & Patterson 第3章给出 1-bit 与 2-bit 预测器在 SPEC 基准上的误预测率对比，证明 2-bit 的迟滞价值。
- CSAPP（Bryant & O'Hallaron）第4章以有限状态机描述 2-bit 计数器，并与程序控制流关联。
- 现代微架构资料（如 Agner Fog 手册）列出各 CPU 实际采用的饱和计数器位数与 PHT 规模。
- Seznec 的 TAGE 论文把 2-bit 计数器作为每个表项的基础组件，佐证其「最简可用构件」的地位。

## 八、面试题

1. 为什么 2-bit 比 1-bit 好？要点：迟滞——需连续两次相反才翻转，避免偶发异常（如循环末次不跳转）造成误预测；对 $p$ 接近 0/1 的分支误预测近似减半。
2. 两位计数器的四个状态如何映射为预测？要点：SN/WN 预测 not taken，WT/ST 预测 taken；从强态翻面需两次相反。
3. 误预测率能达到 0 吗？要点：不能，均匀分布分支仍约 50%，需更复杂的相关性预测器。
4. 为什么不用 3-bit？要点：边际收益极低而面积、功耗与更新逻辑成本上升，性价比低于把资源投入历史相关性结构。
5. 2-bit 计数器为什么处理不了跨分支相关？要点：它只记录该分支自身的近期倾向，不含其他分支的信息，需与全局历史哈希组合。
6. 为什么预测要放在取指当拍？要点：预测结果决定下一取指地址，晚一拍就意味着前端停顿，因此实现必须避免除法/分支等长延迟操作。

## 九、演进与趋势

从 2-bit 局部计数器出发，方向预测演化出：全局历史移位寄存器（GHR）把近期分支结果连成历史串；GShare 用「分支地址 XOR 全局历史」索引 PHT 以利用分支间相关性；再到 TAGE 用多个不同长度的几何历史组件覆盖长程模式。2-bit 饱和计数器始终是这些高阶预测器中每个表项的「基础计数器」。

「双模态（bimodal）」与 2-bit 同源：很多教材把 2-bit 称为 bimodal 预测器，因为它在两个「稳定态」之间摆动；而现代混合预测器（如 TAGE 的 base predictor）仍内部使用 bimodal 表作兜底。2-bit 的「迟滞」思想也被推广到感知机预测器的阈值更新，本质都是「用历史一致性抵抗噪声」，只是从离散状态机变成了连续权重。

## 十、小结

两位饱和计数器以极小硬件代价（每分支 2 bit）引入迟滞，把「偶发翻转」与「趋势反转」区分开，是现代方向预测精度跃升的基础构件。它解决的是「抖动」问题，更复杂的跨分支相关性则交给 GShare/TAGE；而其在面积、延迟与收益上的性价比，正是它至今仍是工业标准的原因。
