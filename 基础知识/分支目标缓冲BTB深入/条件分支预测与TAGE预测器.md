# 条件分支预测与TAGE预测器

> 对应 André Seznec 的 TAGE 预测器系列论文（Micro 2006 等）；Hennessy & Patterson《Computer Architecture: A Quantitative Approach》第3章；Bryant & O'Hallaron《Computer Systems: A Programmer's Perspective》第4章。

## 一、背景与挑战

条件分支只需预测「跳/不跳」，但真实程序中分支方向常依赖「长程、上下文相关」的模式，而非只看本分支自身历史。例如嵌套循环「外层循环第 $k$ 次时内层某分支才不跳」、或某分支的方向取决于几千条指令前另一分支的结果。简单的局部 2-bit 计数器无法捕捉这种跨分支相关性；单一全局历史的 GShare 也只用一个固定长度的历史，短历史抓不住长程模式、长历史又因条目稀释而别名严重。TAGE（TAgged GEometric history length）通过「多个几何递增长度的全局历史组件」同时覆盖短程与长程模式，把条件分支预测精度推到 SPEC 误预测率的理论下限附近。

TAGE 的收益不是来自某个单点技巧，而是来自「系统性消解别名」：用 tag 确认命中、用几何长度覆盖多尺度、用 useful 位控制替换，三者共同把有限容量的利用率提高。因此理解 TAGE 应当把它看成一个「容量管理策略」而非「更长的历史」。

## 二、核心原理

TAGE 维护一组「组件」（component / bank），编号 $i=1\dots n$，每个组件关联一个不同长度的全局历史 $L_i$。$L_i$ 按几何级数递增（如 4, 8, 16, 32, 64, 128…），使短历史与超长历史都被覆盖。每个组件用「分支地址 XOR 该长度的历史片段」做索引，并额外存一个 tag 验证「这条目确实由当前分支+当前历史写入」，以抵御别名。

预测时：从最长历史组件向最短扫描，选第一个「tag 匹配」的组件作为权威预测（它对应最具体的历史上下文，最可信）；若全不匹配，则回退到基础预测器（base predictor，通常是 bimodal 2-bit 表）。更新时只在被采用的组件（以及更长历史中 tag 冲突的）上调整计数器；若全程未命中，则在最短组件里按容量分配新条目。

实际实现还需维护每个条目的「useful 位（u-bit）」：它标记该条目近期是否被采用并命中，用于老化淘汰——当某组件满且需新分配时，优先替换 useful=0 的条目，避免覆盖仍在生效的预测。预测器的全局计数器也分「方向计数器」与「useful 计数器」两套，二者独立饱和，这使得 TAGE 既能纠正方向、又能判断「这个长历史条目是否真的有用」，是它相比朴素多表结构显著降低别名损失的关键细节。

## 三、形式化与数学基础

设历史长度集合 $L = \{l_1 < l_2 < \dots < l_n\}$，几何递增 $l_i \approx \alpha \cdot l_{i-1}$（典型 $\alpha=2$ 或 1.5）。组件 $i$ 的索引：

$$ idx_i = (pc \oplus GHR[l_i:0]) \bmod |T_i| $$

其中 $GHR[l_i:0]$ 是全局历史移位寄存器的低 $l_i$ 位。tag 存于该条目，预测取满足 $tag_i == \text{compute\_tag}(pc, i)$ 的最大 $i$。若最长匹配组件计数器指示 taken，则预测 taken。

几何分布的意义：覆盖从 $l_1$ 到 $l_n$ 的全部「相关长度」的同时，使每个组件条目数可控、别名概率平衡——等长铺满会要么太短抓不住长程、要么太长稀释条目。

别名概率可粗略估计：若组件 $i$ 有 $|T_i|$ 个条目、索引位宽 $b_i = \log_2 |T_i|$，则随机条件下「两个不同 (pc, 历史) 组合碰巧同索引」的概率约 $1/|T_i|$，而 tag 把「误用」概率进一步降到 $1/|T_i| \cdot 2^{-t_i}$（$t_i$ 为 tag 位宽）。因此在总容量受限时，用「较短 tag + 更多组件」往往优于「单个超长历史表」。

## 四、代码实现

下面给出 TAGE「选择最长匹配组件」的简化逻辑：

```c
// TAGE 选择最长匹配组件（示意）
#define N 6
int SIZES[N] = {1024, 2048, 4096, 8192, 16384, 32768};

int predict(uint64_t pc, uint64_t ghr) {
    for (int i = N - 1; i >= 0; i--) {          // 从最长历史开始
        int idx = (pc ^ (ghr & mask(i))) & (SIZES[i] - 1);
        if (tage[i][idx].tag == compute_tag(pc, i)) {
            return tage[i][idx].ctr >> 1;        // 计数器高位即预测位
        }
    }
    return base[pc & BASE_MASK] >> 1;            // 回退基础预测器
}
```

实际实现还需处理「useful 位」（条目有用性）、新条目分配（在最短组件或替代者中挑选）与计数器饱和。

```c
// 更新：被采用的组件调整计数器；未命中则在最短组件分配新条目
void update(uint64_t pc, uint64_t ghr, int taken, int provider) {
    if (provider >= 0) {
        ctr_update(&tage[provider][idx(provider, pc, ghr)].ctr, taken);
    } else {
        // 全程未命中：按 useful 位在最短组件里挑受害者
        int v = victim_by_useful(0, pc, ghr);     // useful=0 者优先被替换
        alloc_entry(&tage[0][v], pc, ghr);        // 新条目初始化为弱态
    }
    ghr = (ghr << 1) | taken;                     // 更新全局历史
}
```

注意 `ghr` 的更新必须在预测之后、且对所有分支统一进行，否则历史含义会在不同调用点之间漂移，导致索引与 tag 计算不一致。

## 五、与其他技术对比

| 预测器 | 相关性来源 | 长程模式 | 硬件代价 |
| --- | --- | --- | --- |
| 2-bit 局部 | 无（仅本分支） | 不能 | 最低 |
| GShare | 单一固定长度全局历史 | 受限 | 低 |
| TAGE | 多几何长度全局历史 + tag | 强 | 高 |
| TAGE-SC-L | TAGE + 统计校正 + 循环预测 | 最强 | 最高 |

相比 2-bit 计数器或单一 GShare，TAGE 用多长度历史覆盖短程与长程模式，误预测率显著更低，代价是面积、功耗与更新逻辑的复杂度。TAGE 已成为现代高性能 CPU（Intel、AMD、ARM 大核）方向预测器的主流底座。

## 六、常见误区

误区一：历史越长越好。错——过长的单一历史会稀释条目、增加别名，TAGE 的几何分布正是为平衡「覆盖长程」与「避免别名」。

误区二：tag 是可有可无的优化。错——不同历史长度可能索引到同一位置，tag 用于确认该条目确实由当前分支写入，避免别名误用，是 TAGE 正确性的关键。

误区三：TAGE 完全取代基础预测器。错——基础预测器（bimodal）是所有组件均未命中时的兜底，且为短历史、冷分支提供初始预测。

误区四：组件越多越好。错——每个组件都要并行走索引与比较，组件数增加会拉长预测延迟，且总存储有限时组件越多每个越小、别名反而上升。

误区五：TAGE 能预测数据相关分支。错——它的输入只有 pc 与历史，方向取决于寄存器值的分支（数据相关分支）仍属其覆盖不到的区域。

## 七、与开源书·权威来源对应

- Seznec 的 TAGE 系列论文（2006 起）是现代高性能分支预测器的事实标准，给出几何历史长度、tag 验证与最长优先的完备方案。
- Hennessy & Patterson 第3章概述全局历史（GHR）与局部分支历史思想，是理解 TAGE 的前置知识。
- CSAPP 第4章从程序控制流角度说明分支相关性的来源。
- 各代 Championship Branch Prediction（CBP）竞赛基准验证了 TAGE 类结构的领先性。

## 八、面试题

1. TAGE 为什么用 tag？要点：不同历史长度可能索引到同一位置，tag 确认条目是否由当前分支写入，避免别名误用。
2. 为什么用几何递增的历史长度？要点：同时覆盖短程与长程相关性，且平衡条目稀释与别名。
3. 预测时为何「最长匹配优先」？要点：最长历史对应最具体的上下文，预测最可信，故优先采用。
4. useful 位的用途？要点：标记条目是否真的被采用并命中，用于老化淘汰，避免覆盖仍在生效的预测。
5. 为什么 TAGE 仍需 bimodal 兜底？要点：冷启动与无长历史信息时需一个基础预测，且短程模式本身也需要覆盖。
6. TAGE 的天花板在哪里？要点：数据相关分支（方向取决于寄存器值而非控制流历史）与极嘈杂的工作负载，是其仍难覆盖的区域。

## 九、演进与趋势

TAGE 的后续变种持续逼近 SPEC 误预测下限：TAGE-SC-L 加入统计校正器（Statistical Corrector）修正组件的一致偏差；ITEAGE/Loop 预测器专门捕捉规则循环（直接预测「第几次才不跳」）；还有把感知机（perceptron）预测与 TAGE 融合的混合结构。总体而言，方向预测精度已非常接近理论上限，进一步收益来自更智能的循环与数据相关分支处理。

TAGE 的「几何历史长度 + tag」范式已被工业界广泛采纳：Intel 的分支预测器、ARM 的 Fetch 前端、以及各类开源 RTL（如 BOOM、Chromite）均以 TAGE 或其变体为骨干。Championship Branch Prediction（CBP）系列竞赛的历年冠军几乎都是 TAGE 类结构，这从实证上证明了「多长度历史 + 标签验证」相对于单一历史长度的压倒性优势。未来方向更多在「数据相关分支」（方向依赖于寄存器值而非控制流历史）上，那是当前 TAGE 仍难覆盖的最后疆域。

## 十、小结

TAGE 通过「多几何长度历史 + tag 验证 + 最长优先」把条件分支预测精度推到极高水平，是现代高性能 CPU 方向预测器的标配。其核心洞见是：用一组覆盖不同相关长度的组件，既抓住长程模式又避免别名，比任何单一历史长度都更优；而 useful 位与兜底基础预测器，则解决了「容量有限下如何优雅降级」的工程问题。
