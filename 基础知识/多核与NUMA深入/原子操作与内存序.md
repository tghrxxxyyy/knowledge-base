# 原子操作与内存序

> 对应 CSAPP 中文笔记 https://github.com/Hansimov/csapp 第12章；C11/C++ 内存模型（标准定性）；Hennessy & Patterson 附录 C。

## 一、背景与挑战

多线程计数/标志需原子性，且编译与 CPU 重排会破坏跨线程可见顺序，需内存序约束。

## 二、核心原理

原子操作(atomic)保证读-改-写不被中断(如 CAS、fetch_add)。内存序：relaxed 仅原子性、acquire/release 建立同步(锁/发布)、seq_cst 全序(默认最严)。x86 强内存模型(TSO)多数操作天然带序，弱模型(ARM)需显式屏障。

## 三、形式化 / 数学基础

happens-before：$A$ release 某原子，$B$ acquire 同原子且读到该值，则 $A$ 之前写对 $B$ 之后可见：

$$A \xrightarrow{release/acquire} B \Rightarrow write(A) \prec read(B)$$

seq_cst 要求所有原子操作有单一全序 $S$。

## 四、代码实现

```c
#include <stdatomic.h>
atomic_int flag = 0;
// 线程A
atomic_store_explicit(&flag, 1, memory_order_release);
// 线程B
while (!atomic_load_explicit(&flag, memory_order_acquire));
```

## 五、与其他技术对比

- mutex 易用但重；原子+正确序更轻。
- seq_cst 安全但限制重排，acq/rel 更松更快。

## 六、常见误区

- 误以为原子即顺序一致：relaxed 不保可见序。
- 在弱模型上漏屏障致难复现 bug。

## 八、面试题

- acquire/release 作用？答：建立同步，保证发布前写可见。
- x86 为何少需屏障？答：TSO 较强，多数访存已有序。

## 九、演进与趋势

C++20 加更强的原子与无锁结构支持。

## 十、小结

原子保证操作不可分割，内存序约束跨线程可见性，二者配合方正确。
