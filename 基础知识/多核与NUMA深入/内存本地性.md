# 内存本地性

> 对应 CSAPP 中文笔记 https://github.com/Hansimov/csapp 第6章；OSTEP https://github.com/remzi-arpacidusse/ostep-code 。

## 一、背景与挑战

在 NUMA 上，内存分配位置决定访问延迟。首次触碰分配(first-touch)使页归访问线程所在节点，错配则长期远程访问。

## 二、核心原理

调度策略：绑线程到节点，让线程自己 touch 分配的内存，页落到本地。或用 `numactl --membind` 预置。`migrate_pages` 可迁移已分配页到本地。

## 三、形式化 / 数学基础

设访问比例为 $f$ 远程，平均延迟：

$$AvgLat = (1-f)L_{local} + f(L_{local}+D)$$

降低 $f$（本地化）直接降延迟。

## 四、代码实现

```c
// 先绑定 CPU，再初始化 -> 内存落本地(first-touch)
void *p = malloc(N * sizeof(double));
#pragma omp parallel for
for (int i = 0; i < N; i++) p[i] = 0;  // 谁写谁本地
```

## 五、与其他技术对比

- first-touch 简单但依赖线程布局；显式 membind 更可控。
- 与 CPU 亲和性(下篇)互为表里。

## 六、常见误区

- 误以为 malloc 在本地：实际按策略可能远程。
- 忽视线程迁移导致 locality 丢失。

## 八、面试题

- first-touch 是什么？答：哪线程先访问，页分配其节点。
- 如何保证本地性？答：绑核+本地分配/迁移。

## 九、演进与趋势

自动 NUMA 平衡(migrate on fault)由内核尝试优化。

## 十、小结

内存本地性是 NUMA 性能核心，靠绑定与 first-touch 实现。
