# 多核缓存一致性

> 对应 CSAPP 中文笔记 https://github.com/Hansimov/csapp 第6章；Hennessy & Patterson 附录 C。

## 一、背景与挑战

多核同封装，每核私有缓存，跨核共享内存须一致（见 SUB2）。本篇聚焦多核场景下一致性的性能影响。

## 二、核心原理

同插槽内多核经最后一级缓存(LLC)与片内互连共享数据，一致性流量在环/网格上流动。跨插槽(见 NUMA)一致性经 QPI/UPI 等片间链路，延迟更高。

## 三、形式化 / 数学基础

远程核取数延迟：

$$Lat_{remote} = Lat_{local} + Hop \times Link\_delay$$

一致性使某行在 M 态迁移，跨片时 $Link\_delay$ 显著。

## 四、代码实现

```c
// 两线程频繁改同一行 -> 跨核一致性颠簸
#pragma omp parallel for
for (int i = 0; i < n; i++)
    shared_counter++;   // 非原子，且引发缓存行迁移
```

## 五、与其他技术对比

- 同片一致性快；跨片一致性受片间带宽限制。
- 与伪共享(SUB2)同源，根因是行粒度。

## 六、常见误区

- 误以为多核自动快：共享写冲突抵消并行。
- 忽视跨片一致性代价。

## 八、面试题

- 跨片一致性为何慢？答：片间链路延迟与带宽限制。
- 多核一致性与单核无关成本？答：行迁移与无效广播。

## 九、演进与趋势

片内网格 + 目录协议承载增长的一致性流量。

## 十、小结

多核一致性是正确前提，性能受拓扑与行粒度制约，需配 NUMA 意识。
