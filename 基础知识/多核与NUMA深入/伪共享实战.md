# 伪共享实战

> 对应 CSAPP 中文笔记 https://github.com/Hansimov/csapp 第6章；perf c2c 工具（Linux 文档定性）。

## 一、背景与挑战

多核每个线程改独立计数器，却因同缓存行频繁无效，吞吐不升反降。实战需定位与修复。

## 二、核心原理

用 `perf c2c` 检测缓存行在核间反复迁移(HITM)；用对齐/填充把每个变量放独立行。也可把每线程计数本地累计、最后汇总，减少跨核写。

## 三、形式化 / 数学基础

设 T 线程各写独立变量同行，每写触发行迁移：

$$Slowdown \approx T \times CoherenceTraffic / UsefulWork$$

隔离后该部分消失。

## 四、代码实现

```c
#include <stdalign.h>
struct padded { alignas(64) unsigned long c; char pad[64-sizeof(long)]; };
struct padded cnts[16];   // 每线程独立行
// 线程 t 只写 cnts[t].c
```

## 五、与其他技术对比

- 填充简单但费内存；线程本地+汇总更省带宽。
- 与锁方案无关，锁不解决行迁移。

## 六、常见误区

- 误以为加锁解决：锁只串行化，不消除迁移。
- 填充不足(未按 64 对齐)无效。

## 八、面试题

- 如何定位伪共享？答：perf c2c 看 HITM 行与涉核。
- 修复手段？答：行对齐填充或线程本地累计。

## 九、演进与趋势

编译器/运行时提供对齐标注与争用分析器普及。

## 十、小结

伪共享实战靠检测工具 + 行隔离/本地累计消除行迁移，是多核调优常项。
