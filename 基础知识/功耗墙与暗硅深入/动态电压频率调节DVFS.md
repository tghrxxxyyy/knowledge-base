# 动态电压频率调节 DVFS

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》功耗与热管理章；ARM Big.LITTLE 与大小核调度文档；Linux `cpufreq` 子系统文档。

## 一、背景与挑战

固定高频会让轻载时大量能量被浪费在「空转与漏电流」上；固定低频又会让重负载拖慢甚至错过截止期。处理器负载随时间剧烈波动，理想方案是**依负载实时调电压与频率**，在性能与能耗之间折中。DVFS（Dynamic Voltage and Frequency Scaling）因此成为几乎所有现代 SoC 与服务器的标配功耗管理技术。挑战在于：调速滞后、电压不能无限降、频率与电压必须协同（否则时序违例），且需避免频繁抖动。

「不能无限降」还体现在一个反直觉的边界上：当频率足够低时，漏电功耗不再随频率下降，反而由于任务执行时间被拉长而累积更多漏电能，使得总能量不降反升。因此 DVFS 存在一个「最优工作点」而非单调最优方向——这正是它与近阈值计算研究交汇的地方。

## 二、核心原理

数字电路的可用频率 $f$ 由关键路径延迟决定，而延迟随供电电压 $V$ 降低而上升，故有近似 $f \propto (V - V_{th})$（$V_{th}$ 为阈值电压）。降低频率即可降低所需电压，而动态功耗 $P_{dyn} \propto C V^2 f$，因此**同时降频降压**能超线性地省电。操作系统调度器或硬件 governor（如 ondemand、conservative、schedutil）周期性采样 CPU 利用率，据此选择电压-频率对（来自芯片的 OPP，Operating Performance Point 表）。注意电压调整比频率慢得多（微秒级 vs 纳秒级），故调度需预判而非瞬时响应。DVFS 与 P-state（性能状态）绑定，而 C-state（空闲态）则进一步在闲置时关时钟/断电，二者层次不同。

governor 的选择本质上是对「响应速度 vs 稳定性」的取舍：`ondemand` 反应快但易抖动，`conservative` 步进小更平滑但响应慢，`schedutil` 直接利用调度器的负载信号从而避免采样误差并减少滞后。现代实现更倾向于把调速决策与调度器耦合，使「选核」与「选频」成为同一个联合决策问题。

## 三、形式化与数学基础

单次任务能量-延迟积近似：

$$
E \cdot T = (P_{dyn} \cdot T) \cdot T = \alpha C V^2 \cdot (f T^2) = \alpha C V^2 \cdot \frac{W^2}{f^2}
$$

其中 $W$ 为工作量。降 $V, f$ 省能但增延迟。在截止期约束下的最优工作点：

$$
\min_{V,f} Energy \quad s.t.\quad T = \frac{W}{f} \le T_{deadline}
$$

可见：若任务有硬截止期，并非越低频越好——频过低会违约。漏电流 $I_{leak} \propto e^{V_{th}/(nV_T)}$ 随 $V$ 降低仍存，构成最低能耗点（与近阈值计算相通）。

把漏电加入模型即可看出最优点的存在：总能耗 $E(V,f) = (\alpha C V^2 f + P_{leak}(V)) \cdot W/f$。降 $V$ 使第一项按 $V^2$ 下降，但 $W/f$ 因 $f$ 下降而增大，使漏电项 $P_{leak} \cdot W / f$ 上升。二者方向相反，故 $E$ 关于 $V$ 的曲线存在极小值——在该点左侧漏电主导、右侧动态功耗主导。工程上这个点通常落在中等频率区间，也是 OPP 表中「能效点」的由来。此外，由于 $P_{dyn} \propto V^2$ 而 $f \propto V$，故 $P_{dyn} \propto V^3$（在 $V$ 主导延迟的区间内），这是「降压比降频收益大三倍幂次」的根源。

## 四、代码实现

```c
/* 简化 governor：利用率高则升频，低则降频（示意） */
void dvfs_tick(int util_pct) {
    if (util_pct > 80 && cur_freq < FMAX) {
        set_freq(cur_freq + STEP);          /* 升频以满足突发负载 */
    } else if (util_pct < 20 && cur_freq > FMIN) {
        set_freq(cur_freq - STEP);          /* 降频省电 */
    }
    set_voltage(volt_for_freq(cur_freq));   /* 频率改变时同步调整电压（查 OPP 表） */
}
```

```c
/* OPP 表示意：频率与电压必须成对（否则时序违例） */
const opp_t opp_table[] = {
    { .freq = 800_MHz,  .volt = 0.75f },   /* 最低能效点附近 */
    { .freq = 1600_MHz, .volt = 0.90f },
    { .freq = 2400_MHz, .volt = 1.05f },   /* 最高性能点 */
};
```

```c
/* 带滞回的 governor：加高低阈值间隙，避免在边界反复抖动 */
void dvfs_tick_hysteresis(int util_pct) {
    static int level = 1;                   /* 当前 OPP 档位 */
    if (util_pct > 90 && level < OPP_MAX) level++;      /* 上穿才升档 */
    else if (util_pct < 15 && level > 0)  level--;      /* 下穿才降档 */
    apply_opp(&opp_table[level]);           /* 中间区间保持不动，抑制振荡 */
}
```

第三段的滞回（hysteresis）设计是工程必需：若升降阈值相同（都是 50%），利用率在阈值附近波动会导致频率持续抖动，既增加稳压器负担又消耗额外能量。拉开阈值间隙后，稳态负载会稳定停在某一档，仅在负载显著变化时才调整。

## 五、与其他技术对比

| 维度 | DVFS | 时钟门控 | 电源门控 | 异构大小核 |
|------|------|----------|----------|------------|
| 作用层次 | 全局 V/f | 局部关时钟 | 关电压域 | 换核类型 |
| 省电幅度 | 中 | 小（动态） | 大（静态） | 大 |
| 延迟代价 | 中（电压慢） | 极小 | 大（恢复慢） | 中（迁移） |
| 适用场景 | 负载波动 | 单元闲置 | 整块关断 | 任务异构 |
| 调整粒度 | 域/簇/核 | 单元级 | 域级 | 核级 |

DVFS 与三者互补：DVFS 调「工作点」，时钟/电源门控消除「闲置能耗」，异构让不同负载落到最合适核。四者常同时存在：一个现代 SoC 会用 DVFS 调当前活跃簇的频率，用时钟门控关掉空闲执行单元，用电源门控关闭整个闲置簇，并靠异构调度把轻任务放到小核上。

## 六、常见误区

1. 误以为降频一定省总能量：若任务有固定截止期，拖长执行可能使漏电能耗累积，**总能耗反升或持平**。
2. 误以为电压可任意降：有最低 $V_{min}$，低于它电路无法在目标频率下正确翻转（时序违例）。
3. 忽略电压调整比频率**慢得多**，盲目高频抖动会引入额外稳定开销。
4. 误以为 DVFS 能解决所有功耗问题：它管「工作点」，管不了「闲置泄漏」与「空间热点」。
5. 混淆 P-state 与 C-state：前者调运行时的电压频率，后者是闲置时的关断深度。
6. 忽略 governor 采样间隔的影响：采样过疏会错过突发负载，过密则增加开销且易抖动。
7. 认为降压只影响动态功耗：漏电也随电压变化，且低温/高温下漏电特性不同，需按温区校准 OPP。
8. 忽视多域耦合：调整某核频率会改变共享稳压器与封装热环境，可能影响同封装其他核的可用频率。

## 八、面试题

1. 为何频率与电压需联动？答：维持时序正确需 $V$ 随 $f$ 升降，且动态功耗强依赖 $V^2$，单独降频不降压省电有限。
2. 有无截止期时 DVFS 策略差异？答：无截止期可尽量低压低频省能；有硬截止期须保证 $f \ge W/T_{dl}$，只能在该下限之上取舍。
3. 为什么电压调整比频率慢？答：片外/片内稳压器与电荷泵响应慢，而频率仅靠 PLL 分频可快速切换。
4. DVFS 与电源门控如何配合？答：运行时用 DVFS 调工作点，闲置时用电源门控彻底断电，覆盖动态与静态两类功耗。
5. 为什么低频低压时总能耗可能反升？答：漏电功耗不随频率下降，执行时间被拉长后漏电能累积更多，超过动态功耗的节省。
6. governor 为什么要设滞回阈值？答：避免利用率在单一阈值附近波动时频率反复抖动，减少稳压器负担与额外能耗。

## 九、演进与趋势

从每芯片单一 V/f 域，演进到**每核/每簇/每域**细粒度 DVFS（如 Intel 的 per-core turbo、ARM 的 DSU）；并引入机器学习预测负载以提前调速、降低滞后。与电源/时钟门控、异构调度深度协同，构成现代功耗管理的主线。

另一条趋势是把功耗管理下沉到软件栈的更多层：编译器在生成代码时标注功耗敏感区，运行时根据热预算动态调整并行度（如限制同时活跃的核数以防过热降频）。这种「性能换可持续性」的策略在数据中心尤为常见，其目标从「单次跑得最快」转为「长期吞吐最高」。

## 十、小结

DVFS 是应对功耗墙最成熟、最通用的技术，用「按需供能」在性能与能耗间换得 Pareto 最优。它的本质是把电压-频率这一连续旋钮交给调度器，使每焦耳能量都花在「真正需要的工作」上。

三条实践要点：电压必须随频率联动（否则违例或无收益）、有截止期时存在频率下限（不能一味求省）、滞回与预测共同抑制抖动与滞后（稳态才有效益）。
