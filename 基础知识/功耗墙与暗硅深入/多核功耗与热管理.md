# 多核功耗与热管理

> 对应 Hennessy & Patterson 量化方法热与功耗章与 Intel 热电偶/电源管理文档。

## 一、背景与挑战
局部高功耗产生热密度热点，超过结温会触发降频（thermal throttling）甚至损坏。多核需在温度、功耗、性能间联合管理（thermal-aware scheduling）。

## 二、核心原理
热阻模型：温升 $\Delta T = P \cdot R_{th}$。DVFS、时钟门控、任务迁移把热负载摊匀。电源管理控制器（如 Intel RAPL）按功耗/热预算实时调节。

## 三、形式化与数学基础
稳态温度：
$$T_{j} = T_{amb} + P \cdot R_{th}$$
热时间常数：
$$\tau = R_{th} C_{th},\quad T(t) = T_{ss}(1 - e^{-t/\tau})$$
调度目标：
$$\min \max_i T_i \quad s.t.\quad \sum P_i \le P_{budget}$$

## 四、代码实现
```c
// 温度感知调度: 把任务从热核迁到冷核
void thermal_balance(int temp[4], int load[4]) {
    int hot = argmax(temp), cold = argmin(temp);
    if (temp[hot] - temp[cold] > THRESH) {
        move_task(hot, cold, load[hot]/2); // 迁移一半负载
    }
}
```

## 五、与其他技术对比
仅 DVFS 控全局功率但不管空间热点；热感知调度管空间分布；二者协同（RAPL + scheduler）最佳。

## 六、常见误区
误以为降频只因功耗：常为温度。误以为平均温度安全即可：局部热点仍触发。

## 七、与开源书/权威来源对应
量化方法热管理；Intel RAPL/电源管理手册；Linux thermal framework。

## 八、面试题
问：为何热管理需空间均衡？答：局部热点触顶降频，整体性能受损。

## 九、演进与趋势
芯片内温度传感器阵列 + AI 预测热模型，精细调控。

## 十、小结
热管理是把"功耗预算"空间化的工程，决定了多核可持续性能。
