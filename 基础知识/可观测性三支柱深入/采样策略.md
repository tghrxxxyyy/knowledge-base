# 采样策略

> 对应可观测性数据的采样（sampling）以平衡成本与覆盖。

## 一、背景与挑战
全量采集在高流量下成本不可承受。采样在可控成本下保留足够信号，但需避免采样掉关键错误/长尾。

## 二、核心原理
- 头采样（head-based）：在请求入口决定采不采，简单但可能漏掉慢请求。
- 尾采样（tail-based）：等请求结束按结果（错误/慢）决策，保留有价值的。
- 概率采样：固定比例；自适应采样：按负载动态调。
- 分层采样：错误/慢请求 100%，正常流量降采样。

## 三、形式化 / 数学基础
- 采样率 $s$：保留比例，估计量需 $\hat x = x_{obs}/s$ 修正。
- 错误捕获概率：头采样下 $P(capture)=s$，低 s 易漏错误。
- 尾采样决策函数 $D(req)=\mathbf{1}[status\ge500 \lor latency>p99]$。
- 成本 $C(s) \approx s \cdot \lambda \cdot \text{cost\_per\_span}$。

## 四、代码实现
```yaml
# OTel Collector 尾采样示例（错误与慢请求全留）
processors:
  tail_sampling:
    policies:
      - name: errors
        type: status_code
        status_code: { status_codes: [ERROR] }
      - name: slow
        type: latency
        latency: { threshold_ms: 500 }
```

## 五、与其他技术对比
- 头采样：低延迟决策、可能漏尾；尾采样：更准但需缓冲与状态。
- 全量：最准最贵；降采样：省但偏。
- 客户端采样 vs 服务端收集器采样：开销与一致性权衡。

## 六、常见误区
- 低比例头采样漏掉罕见错误。
- 尾采样缓冲过久增加内存与延迟。
- 采样后未做分母修正导致指标失真。

## 十、小结
采样策略用头/尾/分层组合在成本与覆盖间取平衡，关键错误与长尾须优先保留。
