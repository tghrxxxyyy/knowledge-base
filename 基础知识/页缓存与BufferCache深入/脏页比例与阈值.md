> 对应 Linux 内核 Documentation（admin-guide/sysctl/vm.rst）与 Kleppmann《DDIA》。

## 一、背景与挑战
脏页比例过高意味着崩溃时丢失多、恢复慢；过低则写聚合不足、吞吐下降。挑战是给出一组可调阈值，在「IO 聚合度」与「丢失窗口/内存占用」间取得平衡，并按可用内存自适应。

## 二、核心原理
内核提供两类阈值（比例或绝对值）：dirty_background_ratio/bytes 控制「何时开始后台回写」；dirty_ratio/bytes 控制「何时阻塞写者」。另有 dirty_expire_centisecs（脏页最长存活）、dirty_writeback_centisecs（回写周期）。容器场景还有 memcg 级 dirty 限制。

## 三、形式化与数学基础
设可写内存 M。阈值线：
```
Wb = background_ratio * M     // 触发后台回写
Wt = dirty_ratio * M          // 触发写者阻塞
```
约束通常 Wb < Wt。回写节奏：
```
每 dirty_writeback_centisecs 唤醒一次，
过期脏页（age > dirty_expire_centisecs）被刷。
```
稳态要求磁盘带宽匹配写速率，否则 d 持续逼近 Wt。

## 四、代码实现
```c
// 阈值读取（sysctl，简化概念）
// /proc/sys/vm/dirty_background_ratio  (默认 10)
// /proc/sys/vm/dirty_ratio             (默认 20)
// /proc/sys/vm/dirty_expire_centisecs  (默认 3000 = 30s)
// /proc/sys/vm/dirty_writeback_centisecs (默认 500 = 5s)
// 内核判定（节选自 balance_dirty_pages）
if (global_node_page_state(NR_DIRTY) > dirty_background_bytes)
    wakeup_flusher_threads(bdi, WB_REASON_BACKGROUND);
```

## 五、与其他技术对比
- 纯内存写缓冲：快但崩溃丢失大。
- 直写：零丢失窗口但慢。
- 比例阈值回写：自适应内存规模，平衡聚合与安全。

## 六、常见误区
- 误区：dirty_ratio 限制的是磁盘占用。它限制的是「脏页占可写内存」比例。
- 误区：设 0 比例就直写。可能为 0 表示「使用默认值/无限制」语义，需看具体版本。

## 九、演进与趋势
引入 memcg 脏页限制，使容器级脏页可控；与 cgroup v2 的 io.max/writeback 协作，避免单容器拖慢整机回写。

## 十、小结
脏页比例阈值是写回缓存的安全阀：background 触发后台回写、ratio 触发写者节流，二者共同限定丢失窗口与聚合度。
