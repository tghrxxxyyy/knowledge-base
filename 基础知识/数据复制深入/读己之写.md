# 读己之写

> 对应 Kleppmann《DDIA》第 5 章“Reading Your Own Writes”。

## 一、背景与挑战
用户提交数据后立即刷新页面，却看不到自己刚写的内容——因读请求被路由到尚未同步的从库。读己之写(会话保证)要求“自己总能看到自己的写入”。

## 二、核心原理
实现思路：
- 跟踪写入版本/时间戳：客户端记录最近一次写入位点(如 LSN/版本号)。
- 读时等待：对该用户的后续读，路由到已追上该位点的副本，或读主。
- 短时窗口：仅在写入后一小段时间强制读主，之后可回到从库。
- 跨设备：若多端共享，需服务端记录该用户最近写入时间，所有端据此等待。

## 三、形式化 / 数学基础
设用户 u 写入 w 产生版本 v_u。读请求 r 满足读己之写 iff applied_version(r.replica) >= v_u。
实现：replica 暴露 last_applied 位点；读前检查位点 >= v_u，否则等待或路由其他副本。

## 四、代码实现
```python
def user_read(user, key):
    target_ver = user.last_write_version
    for replica in prefer_local_replicas():
        if replica.applied_version(key) >= target_ver:
            return replica.get(key)
    return leader.get(key)  # 兜底读主
```

## 五、与其他技术对比
- 读己之写是弱于线性一致、强于最终一致的用户级保证。
- 单调读常与之搭配使用。

## 六、常见误区
- 误区：异步复制下默认就能看到自己写。不一定。
- 误区：所有读都读主即可。丧失扩展且未解决跨从库单调读。

## 十、小结
读己之写是一种务实的用户级一致性保证，通过会话位点跟踪让“自己看到自己的写”，无需全局强一致。
