# 无主复制

> 对应 DeCandia et al.《Dynamo》(SOSP 2007) 与 Amazon DynamoDB 设计。

## 一、背景与挑战
传统主从有 Leader 瓶颈与故障切换复杂度。无主(leaderless)复制(如 Dynamo)让任意节点都可处理读写，通过“读多写多(quorum)”与版本协调达到高可用与可调一致。

## 二、核心原理
- 每个数据项按 key 哈希到 N 个副本节点(如 N=3)。
- 写：客户端向 W 个副本写成功即返回(W 可配)。
- 读：向 R 个副本读，取最新版本(带版本/向量时钟)，若有旧版本则在后台做反熵修复(read repair)。
- 可调一致：要求 W + R > N 即可保证读到的副本中至少有一个含最新写(强一致可调)。
- 版本冲突：并发写产生多个版本(siblings)，由客户端合并(或 CRDT)。

## 三、形式化 / 数学基础
Quorum 一致：若 W + R > N，则读集合与写集合必相交，保证读到最新。
反熵(anti-entropy)：副本间用 Merkle 树比对差异并修复。
版本协调：每个写附 (context, vector)，读返回所有不支配版本，客户端合并后回写。

## 四、代码实现
```python
def put(nodes, key, val, W, N):
    targets = hash_ring(key, N)
    ok = sum(n.write(key, val, version_inc()) for n in targets)
    return ok >= W
def get(nodes, key, R, N):
    vals = [n.read(key) for n in hash_ring(key, N)]
    latest = resolve_latest(vals)   # 按向量时钟取最新/合并
    if len(vals) >= R: return latest
```

## 五、与其他技术对比
- 相比单主：无切换故障点，写可用更高；但读需协调多副本。
- 相比多主：无显式 Leader，拓扑更扁平。

## 六、常见误区
- 误区：W+R>N 永远强一致。仅在无并发写且 quorum 正确时成立；sloppy quorum 下不一定。
- 误区：无主=无冲突。并发写仍有版本冲突需解决。

## 十、小结
无主复制以 quorum 读写与版本协调实现高可用与可调一致，代价是读路径的协调与冲突处理。
