# 故障检测与租约

> 对应 Gray & Lamport 相关租约工作与 DDIA 第8章（租约或锁）。

## 一、背景与挑战
FD 只给「怀疑」，若据此直接切主可能与「假死旧主」并存造成脑裂。租约（lease）把「谁是主」变成带期限的授权：旧主租约到期前新主不得上位，从而安全交接。

## 二、核心原理
主定期向协调者或副本续租。FD 怀疑某节点到不立即行动，等其租约自然到期再选新主。租约长度须大于 FD 检测时间，且小于业务可接受的主空窗。续租失败即释放权限。

## 三、形式化与数学基础
设租约时长 \\(L\\)，FD 检测时间 \\(D\\)（从崩溃到被怀疑），安全条件 \\(D < L < T_{split}\\)，其中 \\(T_{split}\\) 为允许的主空窗。任意时刻至多一个有效租约，保证单主。

## 四、代码实现
```python
def renew_lease(lease, now, duration):
    if now > lease.expiry - GRACE:
        lease.expiry = now + duration   # 续租
    return lease.expiry > now

def is_primary(lease, now):
    return lease.expiry > now
```

## 五、与其他技术对比
纯 FD 切主易脑裂；租约把「怀疑」延后到确定边界，代价是主空窗小于等于 L；ZooKeeper 临时节点即租约实现。

## 六、常见误区
1. 租约过长：故障切换慢。
2. 租约过短：网络抖动即丢主，频繁选举。
3. FD 怀疑立即抢租：须等旧租约过期，否则双主。

## 七、与开源书/权威来源对应
租约由 Gray 等人提出用于缓存一致性，后广泛用于主选举；ZooKeeper 用会话超时即租约；DDIA 第8章讨论时钟与租约。

## 八、面试题
问：租约如何防脑裂？
答：新主必须等旧主租约过期后才能生效，保证任意时刻至多一个有效主。

## 九、演进与趋势
将租约与 Raft 任期（term）结合，任期即逻辑租约，避免物理时钟依赖。

## 十、小结
租约把「软怀疑」转换为「硬边界」，是 FD 之上实现安全主切换的标准机制。
