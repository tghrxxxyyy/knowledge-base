# 故障检测器定义与属性

> 对应 Chandra & Toueg 1996（Unreliable Failure Detectors）与 DDIA 第8章。

## 一、背景与挑战
分布式系统需判断「某节点是否挂了」以触发切主、重分配。但网络分区下，无法区分「节点死」与「网络不可达」。故障检测器（FD）以「不可靠但有用」的方式给出怀疑列表，其属性决定系统能达成的一致性。

## 二、核心原理
FD 输出每个节点的「可信或怀疑」状态。两个关键属性：完备性（最终每个故障节点都被怀疑）与准确性（非故障节点最终不再被怀疑）。二者不可同时强保证（网络异步时），故分等级：完美、最终完美、弱等。

## 三、形式化与数学基础
- 强完备：每个崩溃的进程最终被所有正常进程永久怀疑。
- 弱完备：每个崩溃进程最终被某正常进程怀疑。
- 强准确：无正确进程被怀疑。
- 最终强准确：最终无正确进程被怀疑。

Chandra-Toueg 证明：最终弱完备加最终强准确的 FD 足以实现共识（即使异步）。

## 四、代码实现
```python
class Detector:
    def __init__(self): self.suspected = set(); self.last = {}
    def heartbeat(self, node, t): self.last[node] = t
    def check(self, now, timeout):
        for n, t in list(self.last.items()):
            if now - t > timeout:
                self.suspected.add(n)
            else:
                self.suspected.discard(n)
```

## 五、与其他技术对比
超时 FD 简单但不准（误判或漏判）；Phi 累积 FD 用统计降低误判；租约（lease）把「怀疑」变成「授权」，更确定。

## 六、常见误区
1. 认为 FD 能确定判死：异步下只能「怀疑」。
2. 把怀疑当事实立即切主：需配合共识或租约避免脑裂。
3. 固定超时不调：网络抖动致频繁误判。

## 七、与开源书/权威来源对应
Chandra & Toueg 1996 是 FD 理论基石；DDIA 第8章讲不可靠的网络与超时；6.824 用 FD 触发 Raft 选举。

## 八、面试题
问：为何 FD 不能既完备又准确？
答：异步网络下无法区分崩溃与分区，强准确会与强完备冲突（FLP 相关）。

## 九、演进与趋势
把 FD 与租约、共识结合，形成「软怀疑加硬授权」双层防护。

## 十、小结
FD 以概率性怀疑替代确定性判死，其属性等级决定系统可达成的一致性与可用性。
