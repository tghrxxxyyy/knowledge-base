# 心跳机制与超时

> 对应 Chandra & Toueg 1996 与 DDIA 第8章。

## 一、背景与挑战
心跳是最朴素的存活信号。但若超时设太短，网络瞬时抖动即误判；太长，真死发现慢、恢复慢。如何设超时、如何重传，是 FD 工程落地的关键。

## 二、核心原理
节点周期性发心跳，接收方维护「最后到达时间」。超时 = 期望间隔加容错余量。更优做法是用滑动窗口估计间隔分布（见 Phi），或采用指数退避重传避免风暴。

## 三、形式化与数学基础
设心跳间隔 \\(I\\)，网络延迟抖动 \\(\Delta\\)，安全超时
\\[
T = I + k\cdot\sigma + \Delta_{max}
\\]
其中 \\(k\\) 为置信系数。过小的 \\(T\\) 使误判率 \\(\approx P(抖动>T-I)\\) 升高。

## 四、代码实现

import time
def monitor(last_seen, interval, slack, now):
    return (now - last_seen) > (interval + slack)

## 五、与其他技术对比
固定心跳简单但僵化；携带负载的心跳（含健康指标）更丰富；gossip 传播心跳避免中心瓶颈；Phi 检测器在心跳之上做统计判定。

## 六、常见误区
1. 全局统一超时：跨地域延迟差异大，应分域。
2. 心跳携重负载：占带宽，应轻量。
3. 忽略时钟漂移：用单调时钟计超时。

## 七、与开源书/权威来源对应

## 八、面试题
问：超时如何设才合理？
答：基于实测心跳间隔的均值与方差，取间隔加若干倍标准差与最大延迟余量。

## 九、演进与趋势
eBPF 或内核级心跳降低开销；服务网格侧车统一健康探测。

## 十、小结
心跳是 FD 的数据源，合理超时需基于实测分布而非拍脑袋，方能在灵敏与稳定间平衡。
