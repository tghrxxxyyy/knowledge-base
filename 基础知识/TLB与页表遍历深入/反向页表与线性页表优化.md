# 反向页表与线性页表优化

> 对应 Tanenbaum《Computer Organization and Design》反向页表章（IBM Power 架构）。

## 一、背景与挑战
传统多级页表以 VA 为索引，"每进程一份"，在 64 位大地址空间下虽稀疏但仍随进程数线性增长。反向页表改为以物理页框为索引，全局唯一。

## 二、核心原理
反向页表（inverted page table）表项数 = 物理页数，每项记录"哪个 VA 映射到此框"。查表需由 VA 反查，常配合哈希表（hashed page table）加速。将稀疏 VA 空间哈希到有限表项，冲突链解决别名。

## 三、形式化与数学基础
表大小：
$$|IPT| = N_{phys\_pages}$$
与进程数无关，远小于多进程扁平页表之和。查表期望：
$$Lookup \approx 1 + \frac{LoadFactor}{ChainLen}$$
冲突随负载因子上升。

## 四、代码实现
```c
// 哈希反向页表
struct ipt_e { unsigned long va_tag; int pid; unsigned long pfn; int used; };
struct ipt_e ipt[MAX_PFN];
unsigned hash(unsigned long va, int pid){ return (va ^ (pid<<8)) % MAX_PFN; }
int invert_lookup(unsigned long va, int pid){
    unsigned h = hash(va, pid);
    while (ipt[h].used){ if(ipt[h].va_tag==va && ipt[h].pid==pid) return h; h=(h+1)%MAX_PFN; }
    return -1; // 不在内存
}
```

## 五、与其他技术对比
正向多级页表查表快（直接索引）但空间随进程增长；反向表省空间但查表需哈希/遍历。实际 x86 仍用正向，IBM Power 用反向。

## 六、常见误区
误以为反向表能直接由 VA 得 PA：需哈希反查且解决冲突。误以为它替代 TLB：二者互补。

## 七、与开源书/权威来源对应
Tanenbaum 计算机组成；OSTEP 虚拟内存对比。

## 八、面试题
问：反向页表为何在 64 位系统更省内存？答：按物理页数而非虚拟空间定大小。

## 九、演进与趋势
结合大页、嵌套页表（EPT）在虚拟化中分层使用。

## 十、小结
反向页表以"物理为索引"翻转了映射视角，适合物理内存受限、进程众多的场景。
