# 多级页表与 x86-64 四级页表

> 对应 Bryant & O'Hallaron《Computer Systems: A Programmer's Perspective》（CSAPP）第9章虚拟内存。

## 一、背景与挑战
32/64 位地址空间若用单一页表将占用海量内存（如 64 位下不可行）。多级页表以稀疏树结构仅分配实际使用的页目录，节省空间。

## 二、核心原理
x86-64 采用 4 级页表（PGD→PUD→PMD→PTE），48 位虚拟地址拆分为 4 个 9 位索引加 12 位页内偏移。每级表项指向下一级基址，末级 PTE 含物理页框号与权限位。

## 三、形式化与数学基础
地址分解（4 KB 页）：
$$VA = [\cancel{16}][PGD_9][PUD_9][PMD_9][PTE_9][offset_{12}]$$
页表总开销仅覆盖实际映射区域，比扁平表节省指数级。单级表项 8 字节，一级表 $2^9\times 8=4$ KB。

## 四、代码实现
```c
// 四级页表软件遍历(简化)
unsigned long walk(unsigned long *pgd, unsigned long va) {
    int idx[4];
    idx[0]=(va>>39)&0x1FF; idx[1]=(va>>30)&0x1FF;
    idx[2]=(va>>21)&0x1FF; idx[3]=(va>>12)&0x1FF;
    unsigned long *t = pgd;
    for (int i=0;i<3;i++){ t=(unsigned long*)(t[idx[i]]&~0xFFF); }
    return (t[idx[3]] & ~0xFFF) | (va & 0xFFF);
}
```

## 五、与其他技术对比
扁平页表省遍历但空间爆炸；多级以多次访存换空间。大页（2 MB/1 GB）合并末级，减少级数。

## 六、常见误区
误以为 64 位地址全用：x86-64 仅 48 位可寻址（规范地址）。误以为每级都需存在：稀疏处可缺页。

## 七、与开源书/权威来源对应
CSAPP 第9章；OSTEP（remzi-arpacidusse/ostep-code）虚拟内存章；Intel SDM 卷3。

## 八、面试题
问：48 位地址为何拆成 4×9+12？答：4 KB 页 12 位偏移，余 36 位分 4 级各 9 位。

## 九、演进与趋势
5 级页表（LA57）扩展至 57 位以支持超大地址空间（如 Intel 新硬件）。

## 十、小结
多级页表以时间换空间，是 64 位系统虚拟内存可行性的基石。
