# 页表遍历硬件与缺页

> 对应 remzi-arpacidusse/ostep-code 虚拟内存章与 CSAPP 第9章。

## 一、背景与挑战
TLB 未命中时，硬件 MMU 自动逐级查页表。若发现权限不符或页不在内存，则触发缺页异常，交由 OS 处理——这是虚拟内存按需调页的核心。

## 二、核心原理
页游走单元（page walk cache/硬件 walker）按 VA 索引走 4 级；遇 PTE 的 present 位为 0 即缺页，CPU 陷入内核，OS 分配物理页、读盘（按需调页）、更新 PTE、刷新 TLB 后返回。

## 三、形式化与数学基础
有效访存时间含缺页：
$$EAT = HitTLB + (1-HitTLB)\times Walk + PageFaultRate \times FaultTime$$
典型 $FaultTime \gg Walk \gg HitTime$，故降低缺页率是关键。

## 四、代码实现
```c
// 缺页处理伪代码(内核态)
void page_fault(unsigned long va, int write) {
    pte_t *e = walk_pte(current->pgd, va);
    if (!e->present) {
        unsigned long pfn = alloc_page();
        if (is_filebacked(va)) read_from_disk(pfn, va);
        e->pfn = pfn; e->present = 1;
        e->writable = write ? 1 : e->writable;
    }
    tlb_invalidate(va);
    return_to_user();
}
```

## 五、与其他技术对比
硬件遍历（x86）对 OS 透明且快；软件管理（MIPS）需 OS 填 TLB 但更灵活。缺页异常是二者共同出口。

## 六、常见误区
误以为缺页总是磁盘 IO：可能只是权限升级（写时复制 COW）。误以为遍历可见给用户态：由 MMU 硬件完成。

## 七、与开源书/权威来源对应
OSTEP 第15-18章；CSAPP 9.7-9.8；Intel SDM 页错误码。

## 八、面试题
问：写时复制为何先缺页再置写位？答：共享只读页，首次写触发复制。

## 九、演进与趋势
页表遍历缓存（PWCache）、以及页错误批处理、用户态缺页（userfaultfd）提升灵活性。

## 十、小结
页表遍历与缺页构成了"TLB 失效→硬件走表→OS 介入"的完整异常处理链。
