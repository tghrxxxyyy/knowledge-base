# 页表遍历硬件与缺页

> 对应 Bryant & O'Hallaron《CSAPP》9.7 节；Arpaci-Dusseau《Operating Systems: Three Easy Pieces》虚拟内存章；Intel SDM Vol.3 页错误码。

## 一、背景与挑战

TLB 未命中时，必须有东西去查页表。x86 由 MMU 里的**页表遍历器（page-table walker）**自动完成，软件完全不可见；MIPS 等则触发异常由 OS 软件填 TLB。

真正的复杂性来自"查表失败"的语义：present 位为 0、权限不符、保留位被置位、写只读页……这些都需要 CPU 陷入内核，由缺页处理程序决定是分配物理页、做写时复制、还是杀死进程。缺页处理是虚拟内存"按需调页、延迟分配、共享内存"全部能力的落点。

## 二、核心原理

遍历过程：以 CR3 的 PML4 基址为起点，逐级读取表项，检查 present 与权限，直到取得 PTE 中的物理页框号，与页内偏移拼接得到物理地址。硬件通常会把中间级结果缓存到 **页表遍历缓存（paging-structure caches）** 中，避免每次都从 PML4 重新走。

失败时产生的 **#PF 异常** 会向栈上压入出错地址（CR2）与错误码，错误码包含：P（present，1 表示由保护违规引起）、W/R（写触发）、U/S（用户态触发）、RSVD（保留位被置位）、I/D（取指触发）、PK、SGX。OS 依据这些位区分场景：

- P=0：页不在内存——可能是首次访问（按需调页）、被换出、或合法的零页/COW 共享页；
- P=1 且 W/R=1：写保护违规——典型的写时复制（COW）；
- U/S=1：用户态越权，通常直接 SIGSEGV。

## 三、形式化与数学基础

包含 TLB 与缺页的有效访存时间：

$$EAT = t_{hit} + (1-h_{TLB})\Big(t_{walk} + (1-h_{PWC}) \cdot k \cdot t_{mem}\Big) + f \cdot t_{fault}$$

其中 $h_{TLB}$ 为 TLB 命中率，$h_{PWC}$ 为页表遍历缓存命中率，$k$ 为未命中时仍需访问的内存级数（1–4），$f$ 为缺页率。典型量级为 $t_{fault} \gg t_{walk} \gg t_{hit}$（缺页可达数十万到数百万周期），因此降低缺页率永远优先于优化遍历。

若把缺页按类型分解（首次访问 $f_a$、COW $f_w$、换入 $f_s$），则

$$EAT = t_{hit} + (1-h_{TLB})t_{walk} + f_a t_{alloc} + f_w t_{cow} + f_s t_{swap}$$

后三项处理代价差异巨大，实践中的优化几乎都在减少 $f_s$（避免换出）与 $f_w$（减少 fork 后的 COW 抖动）。

## 四、代码实现

```c
/* x86-64 缺页处理骨架（伪代码，位名示意） */
void do_page_fault(struct pt_regs *regs, unsigned long err, unsigned long cr2) {
    unsigned long va = cr2;
    pte_t *pte = walk(current->mm->pgd, va);
    if (!err_present(err)) {                 /* 页不在内存 */
        if (is_anon_vma(va) && was_swapped(pte)) {
            swapin(va, pte);                 /* 从交换区读回 */
        } else if (is_cow_pte(pte)) {
            copy_page_and_remap(pte);        /* 写时复制：复制后置写位 */
        } else {
            alloc_and_zero(pte);             /* 匿名零页 / 首次访问 */
        }
    } else if (err_write(err)) {
        if (is_cow_pte(pte)) copy_page_and_remap(pte);
        else if (err_user(err)) send_signal(SIGSEGV);
        else handle_kernel_wp(va);           /* 内核只读页，如 gup 场景 */
    } else {
        send_signal(err_user(err) ? SIGSEGV : SIGBUS);
    }
    flush_tlb_page(va);                      /* 失效旧映射 */
}
```

关键在于：处理完成后必须失效对应 TLB 项，否则下次访存仍命中旧映射（旧映射往往仍指向只读的共享页）。

## 五、与其他技术对比

| 维度 | 硬件遍历（x86） | 软件管理 TLB（MIPS/早期 SPARC） | 页表遍历缓存 |
| --- | --- | --- | --- |
| 谁来走表 | MMU 硬件 | OS 异常处理程序 | 硬件辅助 |
| OS 可见性 | 透明（除缺页） | 显式填 TLB | 透明 |
| 灵活性 | 低（表格式固定） | 高（可自定义结构） | 中 |
| 遍历开销 | 硬件流水化，较快 | 陷入 + 软件查找，较慢 | 显著降低多级遍历 |
| 大页/多级扩展 | 依赖硬件定义 | 由软件自由设计 | 同样受益 |

## 六、常见误区

1. **以为缺页一定伴随磁盘 IO**：COW、零页、首次匿名映射都只涉及内存操作。
2. **以为缺页处理完 TLB 会自动更新**：必须显式失效旧项，否则仍走旧映射。
3. **忽略错误码的 P 位**：不看 P 位就会把保护违规误判为"页不在内存"，导致错误的分配逻辑。
4. **认为页表遍历用户态可见**：常态下完全由硬件完成，只有缺页才陷入内核。
5. **忘记大页也会缺页**：2 MB/1 GB 页的分配与拆分同样是缺页路径，代价更高。

## 八、面试题

1. **写时复制为什么要先缺页再置写位？** 要点：fork 后父子共享只读物理页，首次写触发保护违规缺页，此时才复制并授予写权限。
2. **#PF 错误码的 P 位有什么用？** 要点：区分"页不存在"与"权限不允许"两类语义，决定分配页还是报信号。
3. **页表遍历缓存解决了什么？** 要点：多级遍历重复读取上层目录，缓存中间结果可把 4 次访存降到 1 次量级。
4. **为什么缺页处理完必须失效 TLB？** 要点：旧项仍映射到只读共享页，不失效会导致再次缺页或权限错误。
5. **用户态如何自定义缺页处理？** 要点：`userfaultfd` 把缺页事件交给用户态进程处理，用于热迁移、按需加载、增量快照等。

## 九、演进与趋势

硬件侧持续优化遍历：页表遍历缓存分层、并行遍历、以及 5 级分页下的遍历加速。软件侧出现页错误批处理、`MAP_POPULATE` 预fault、THP 的 `khugepaged` 折叠、`userfaultfd` 用户态缺页处理，以及虚拟化中的 EPT violation 与 #VE 嵌套处理。近年还有基于 MMU 的地址空间隔离与内存标记（MTE）等把"保护检查"下沉到硬件。

## 十、小结

页表遍历与缺页构成"TLB 未命中 → 硬件走表 → 失败陷入 → OS 介入 → 失效重试"的完整链条。理解错误码语义、COW 的两阶段权限变化、以及遍历缓存的层次，是定位内存性能与正确性问题的关键。
