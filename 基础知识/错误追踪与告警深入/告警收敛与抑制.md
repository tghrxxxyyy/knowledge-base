# 告警收敛与抑制

> 对应 OpenTelemetry (observability standard)。

## 一、背景与挑战
一个根因（如数据库宕机）会触发下游数十个服务的级联告警，重复通知淹没真正的源头。

## 二、核心原理
通过依赖拓扑做抑制：当上游已告警，抑制其下游的同源告警；同一问题在窗口内合并为一条，并指向根因。

## 三、形式化与数学基础
设依赖图 G，若节点 u 已告警且 (u,v) in E，则对 v 的同源告警执行 suppress(v)。窗口 W 内同指纹事件合并为 1 条。

## 四、代码实现
```yaml
# Alertmanager 抑制规则
inhibit_rules:
  - source_match: { alert: "DBDown" }
    target_match: { alert: "HighLatency" }
    equal: ["datacenter"]   # 同机房则抑制下游
```

## 五、与其他技术对比
相比独立告警，收敛突出根因；但拓扑不准确会误抑制，需持续校准。

## 六、常见误区
- 抑制规则过宽，把独立问题也压掉。
- 依赖图陈旧，实际拓扑已变。

## 七、与开源书/权威来源对应
OpenTelemetry 与告警生态强调关联与去重。

## 八、面试题
收敛与降噪的区别？抑制规则错误会有什么后果？

## 九、演进与趋势
结合服务拓扑自动推导抑制关系，减少人工维护。

## 十、小结
收敛与抑制把级联噪音折叠到根因，是告警有效性的关键一环。
