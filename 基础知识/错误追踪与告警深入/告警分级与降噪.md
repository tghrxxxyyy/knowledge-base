# 告警分级与降噪

> 对应 Kim et al. 2016 (Accelerate / The DevOps Handbook)。

## 一、背景与挑战
无效告警（抖动、低优先级）过多会让 on-call 疲劳，真正严重的告警被忽略，即"狼来了"效应。

## 二、核心原理
按严重程度分级（如 P0-P3），仅对高级别触发通知；用持续时间、次数阈值过滤瞬时抖动，减少噪音。

## 三、形式化与数学基础
告警 a 触发条件：severity(a) >= THRESHOLD 且 duration(a) >= D_min。降噪即过滤掉 severity 低或持续时间短的瞬时异常。

## 四、代码实现
```yaml
alert: HighErrorRate
expr: rate(errors[5m]) / rate(requests[5m]) > 0.05
for: 10m          # 持续 10 分钟才告警，过滤抖动
labels: { severity: P1 }
```

## 五、与其他技术对比
相比"有异常就通知"，分级降噪保护 on-call 注意力；但分级过粗会漏报，需结合业务影响。

## 六、常见误区
- 把所有告警都标 P0，等于没有分级。
- 仅用瞬时阈值，网络抖动即触发。

## 七、与开源书/权威来源对应
Accelerate 把可恢复性与有效告警作为稳定性工程的核心能力。

## 八、面试题
如何定义告警分级？为什么需要 for 持续时间？

## 九、演进与趋势
告警智能降噪（自动聚类、根因归并）减少重复通知。

## 十、小结
告警分级与降噪的目标是"该响才响"，用 severity 与持续时间守住 on-call 注意力。
