# 错误聚合与指纹算法

> 对应 Sentry 官方分组（Grouping）文档与 OpenTelemetry 的 Exception 语义约定。

## 一、背景与挑战

线上系统每秒可能产生成千上万条异常堆栈。同一段代码抛出的同一个异常，会因请求参数、调用链、行号微调而产生海量变体。若把原始异常逐条展示，工程师会被噪声淹没，无法回答一个最基本的问题：「现在到底有几类真正的问题？」

错误聚合（error grouping）要解决的就是这个问题：把语义相同或高度相似的异常归并为一个「问题组（issue）」，用有限的组数替代海量原始条目，让运维者按影响面排序处理。

## 二、核心原理

聚合的核心是**指纹（fingerprint）**：对每条原始异常提取一组稳定的特征，计算哈希作为分组键。特征通常包括：

- 异常类型/类名（如 `TimeoutError`、`NullPointerException`）；
- 堆栈中关键帧的函数名与模块名（常取顶部 N 帧或去除噪声后的帧）；
- 错误消息的模板化结果（把数字、ID、地址等变量替换为占位符）；
- 可选的服务名、事务名、错误码等业务维度。

指纹相同即归为一组，组内记录首次/最近出现时间与计数。工程上还需处理**归一化**与**版本/环境隔离**：过度归一化会把本应区分的问题合并，归一化不足又会碎片化。

## 三、形式化与数学基础

设原始错误 $e = (\text{type}, \text{stack}, \text{msg}, \text{env})$，指纹函数定义为：

$$
f(e) = H\big(\text{norm}(\text{type}),\ \text{frames}(\text{stack}, k),\ \text{tmpl}(\text{msg})\big)
$$

其中 $H$ 为稳定哈希，$\text{frames}(\cdot, k)$ 取顶部 $k$ 帧，$\text{tmpl}(\cdot)$ 将变量替换为占位符。聚合后的问题组数：

$$
G = |\{\, f(e) \mid e \in E \,\}| \ll |E|
$$

信噪比可用「组数压缩比」衡量：

$$
\text{CR} = 1 - \frac{G}{|E|}
$$

归一化的取舍体现在：若 $k$ 太小、模板化太激进，则不同根因被合并（漏报）；若 $k$ 太大、含行号，则每次代码变动都产生新组（碎片化）。因此常见做法是固定「异常类型 + 关键帧」，并显式剔除行号与易变参数。

## 四、代码实现

```python
# 稳定指纹：异常类型 + 顶部关键帧（去掉行号与内存地址）
import hashlib, re

HEX = re.compile(r"0x[0-9a-fA-F]+")
NUM = re.compile(r"\d+")

def normalize_msg(msg):
    msg = HEX.sub("<addr>", msg)
    msg = NUM.sub("<n>", msg)
    return msg.strip()

def fingerprint(exc, top_k=3):
    frames = [f"{f.module}.{f.func}" for f in exc.frames[-top_k:]]
    raw = "|".join([
        exc.type,
        "|".join(frames),
        normalize_msg(exc.message),
    ])
    return hashlib.sha1(raw.encode("utf-8")).hexdigest()

# 聚合：以指纹为键累计计数
def aggregate(errors):
    groups = {}
    for e in errors:
        key = fingerprint(e)
        g = groups.setdefault(key, {"count": 0, "sample": e})
        g["count"] += 1
    return groups
```

## 五、与其他技术对比

| 方案 | 分组依据 | 抗漂移能力 | 维护成本 | 主要风险 |
| --- | --- | --- | --- | --- |
| 整条堆栈哈希 | 全栈字符串 | 低，行号变即新组 | 无 | 严重碎片化 |
| 异常类型 + 顶部帧 | 类型与关键帧 | 中高 | 低 | 同类型不同根因可能合并 |
| 类型 + 模板化消息 | 语义模板 | 中 | 中 | 模板规则需持续维护 |
| 规则/手写分组 | 人工规则优先 | 高 | 高 | 规则覆盖不全 |
| 语义向量聚类 | 堆栈 embedding 相似度 | 高 | 中高 | 阈值难调、可解释性差 |

## 六、常见误区

- **用整条堆栈做指纹**：任何行号或路径变化都会拆出新组，噪音极大。
- **忽略版本差异**：把不同版本、不同分支的异常混为一谈，掩盖回归。
- **模板化过度**：把「超时 1s」与「超时 60s」都归一为「超时」，丢失严重程度信息。
- **不含业务维度**：同一异常在不同租户/接口下影响面不同，应保留可筛选维度。
- **只看计数不看趋势**：突发少量新组往往比大量旧组更值得关注。

## 七、与开源书·权威来源对应

Sentry 官方文档描述了其默认分组算法与自定义指纹（fingerprint）规则，是错误聚合最成熟的工程参考；OpenTelemetry 的 Exception 语义约定规定了异常类型、消息与堆栈的标准字段，为跨系统聚合提供一致输入。具体分组细节与新增特性以各平台官方最新文档为准。

## 八、面试题

- **问：指纹为什么取顶部帧而非全栈？** 答：顶部帧最接近出错点，且比全栈稳定，能抵抗调用链变化引起的抖动。
- **问：过度聚合会有什么问题？** 答：把不同根因合并成一组，导致严重问题被平均值掩盖，定位与派发失真。
- **问：如何处理「同类异常不同原因」？** 答：在指纹中加入区分维度（如错误码、关键参数模板），或引入人工分组规则。
- **问：如何衡量聚合质量？** 答：看组数压缩比、组内是否同源、以及新组出现的稳定性。

## 九、演进与趋势

聚合正从「规则哈希」走向「语义聚类」：用堆栈向量化与相似度聚类自动归组相似错误，并对历史人工合并结果做学习以校准阈值。另一方向是与根因分析联动——同一 Trace 下的异常自动归并到同一问题，减少跨系统重复。

## 十、小结

错误聚合用指纹把海量异常收敛为少量问题组，其质量取决于指纹设计：既要稳定（抗行号/参数漂移），又要可分（不合并异源故障）。理解压缩比与归一化取舍，是构建高信噪比错误平台的关键。
