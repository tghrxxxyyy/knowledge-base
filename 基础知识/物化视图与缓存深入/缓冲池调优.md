# 缓冲池调优

> 对应 MySQL InnoDB Buffer Pool 调优文档，以及 Silberschatz 缓冲管理章。

## 一、背景与挑战
缓冲池大小直接影响命中率与吞吐。配置过小频繁落盘，过大则恢复慢且挤占内存。还需考虑分区、刷脏策略与预热。

## 二、核心原理
核心指标：缓冲池命中率（应 > 99%）、脏页比例、刷脏速率。调优项：池大小（innodb_buffer_pool_size）、实例数（多实例降锁竞争）、刷脏线程数、LRU 老年代比例（innodb_old_blocks_pct）。

## 三、形式化 / 数学基础
命中率 $h = 1 - \frac{disk\_reads}{logical\_reads}$。经验：工作集 $W$ 装入内存时 $h \approx 1$；池大小 $S < W$ 时 $h \approx S/W$（近似）。脏页比 $d = dirty/BP_{size}$ 需低于阈值避免检查点风暴。

## 四、代码实现
```ini
# my.cnf
innodb_buffer_pool_size = 12G
innodb_buffer_pool_instances = 8
innodb_old_blocks_pct = 37
innodb_max_dirty_pages_pct = 75
```

## 五、与其他技术对比
| 参数 | 过小 | 过大 |
|------|------|------|
| 池大小 | 命中低 | 恢复慢 |
| 实例数 | 锁竞争 | 管理开销 |
| 脏页阈值 | 频繁刷 | 检查点尖峰 |

## 六、常见误区
1. 池越大越好——超工作集边际递减且恢复慢。
2. 命中率 100% 正常——接近但非绝对。
3. 只看命中率——还需看脏页与刷脏。

## 十、小结
缓冲池调优围绕命中率、脏页与并发，目标是让工作集驻留内存且刷脏平滑，是 OLTP 性能第一旋钮。
