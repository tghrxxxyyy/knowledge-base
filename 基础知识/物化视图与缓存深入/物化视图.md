# 物化视图

> 对应 Silberschatz《Database System Concepts》第 4 章 视图与物化，以及 PostgreSQL 物化视图文档。

## 一、背景与挑战
复杂聚合查询（如每日销售额）每次重算代价高。物化视图把查询结果物理存储，读时直接取，但需要维护其与基表的一致性。

## 二、核心原理
物化视图 = 预计算并存储的查询结果。两种刷新：按需（REFRESH，全量或增量）与自动（基表变更时维护）。代价是存储与更新开销，收益是查询极快。

## 三、形式化 / 数学基础
视图 $V = Q(B)$。增量维护（维护代数）：对插入 $\Delta B$，
$\Delta V = Q(B \cup \Delta B) - Q(B)$。如 `COUNT(*)` 视图：$\Delta V = |\Delta B|$（插入为正，删除为负）。

## 四、代码实现
```sql
CREATE MATERIALIZED VIEW daily_sales AS
  SELECT date(ts), sum(amt) FROM orders GROUP BY date(ts);
-- 刷新
REFRESH MATERIALIZED VIEW daily_sales;          -- 全量
REFRESH MATERIALIZED VIEW CONCURRENTLY daily_sales; -- 增量(需唯一索引)
```

## 五、与其他技术对比
| 方式 | 读 | 写 | 新鲜度 |
|------|----|----|--------|
| 普通视图 | 慢(现算) | 无 | 实时 |
| 物化视图 | 快 | 有维护 | 可能滞后 |

## 六、常见误区
1. 物化视图自动实时——需显式刷新/维护。
2. 物化视图零成本——存储+更新开销。
3. 所有查询都能物化——含非确定性/易变函数不行。

## 九、演进与趋势
自动物化视图推荐与即时（real-time）维护（如 Oracle、云数仓）降低滞后；物化视图在湖仓一体中用于加速。

## 十、小结
物化视图以空间与维护换读取速度，增量维护与刷新策略决定其新鲜度与成本。
