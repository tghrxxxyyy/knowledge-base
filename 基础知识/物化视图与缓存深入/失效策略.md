# 失效策略

> 对应缓存经典文献（如过期与失效模式），以及 DDIA 中文缓存章。

## 一、背景与挑战
缓存数据会随源库变更而过时。何时、如何令缓存失效，直接决定数据正确性与系统开销。策略失当会导致脏读或缓存抖动。

## 二、核心原理
主要策略：TTL（生存时间，简单但有滞后窗口）、主动失效（写时删除/更新）、写穿（Write-Through，同步写缓存）、写回（Write-Behind，异步）。主动失效需保证"先更新 DB 再删缓存"或"先删缓存再更新 DB"的一致性顺序。

## 三、形式化 / 数学基础
一致性窗口 $W = t_{db\_commit} \to t_{cache\_invalid}$。TTL 下最大滞后 $= TTL$。Cache-Aside 顺序风险：若 删缓存 → 读回填旧值 → 更新DB，会产生脏缓存，故推荐 更新DB → 删缓存 并配合短暂延迟双删。

## 四、代码实现
```python
def update(uid, data):
    db.update(uid, data)
    redis.delete(f"u:{uid}")          # 主动失效
    # 双删防并发回填
    sleep(0.05); redis.delete(f"u:{uid}")
```

## 五、与其他技术对比
| 策略 | 一致性 | 复杂度 | 写开销 |
|------|--------|--------|--------|
| TTL | 弱 | 低 | 无 |
| 主动删 | 中 | 中 | 低 |
| Write-Through | 强 | 高 | 高 |

## 六、常见误区
1. TTL 足够——窗口内仍是旧数据。
2. 删缓存无并发问题——有回填竞态。
3. 双写缓存与库——顺序不当会脏。

## 九、演进与趋势

## 十、小结
失效策略在一致性与开销间权衡；主动失效 + 顺序约束 + CDC 是现代缓存一致的主流方案。
