# 隧道基本原理与封装开销

> 对应 网络隧道通用原理 与 RFC 2003 (IP-in-IP) 背景。

## 一、背景与挑战
隧道将一种协议报文封装进另一种协议载荷，以跨越不原生支持的网络或构建 overlay。代价是额外头部带来字节开销与 MTU 问题，处理不当会引发分片与性能下降。

## 二、核心原理
封装设备将原始 IP 包作为载荷，外加新的 IP 头（及可能的 UDP/专用头），在隧道端点解封装还原。典型如 IP-in-IP、GRE、VXLAN、IPsec。封装使内层路由域与外层传输域解耦，实现跨异构网络连通。

## 三、形式化与数学基础
封装后长度：
$$ L_{encap} = L_{orig} + H_{outer} + H_{tunnel} $$
有效吞吐因开销降低：
$$ \eta = \frac{L_{orig}}{L_{orig} + H_{overhead}} $$
MTU 需满足：
$$ MTU_{tunnel} \le MTU_{phys} - H_{overhead} $$
否则触发分片或 PMTU 发现。

## 四、代码实现
Linux 创建 GRE/IP 隧道：
```bash
ip tunnel add tun0 mode gre remote 198.51.100.1 local 192.0.2.1 ttl 255
ip link set tun0 up
ip addr add 10.0.0.1/30 dev tun0
```
查看开销：
```bash
ip link show tun0
```

## 五、与其他技术对比
直接路由无封装开销但受底层拓扑约束；MPLS 标签开销小但需标签分发；UDP 基隧道（VXLAN/Geneve）可穿越 NAT 但头部更大。

## 六、常见误区
误区一是隧道「免费」，实际有 CPU 封装/解封装与带宽开销。误区二是忽略 MTU，导致大包被丢弃且难排查（需 PMTU 或调小 MSS）。

## 七、与开源书/权威来源对应
RFC 2003 定义 IP-in-IP；RFC 2784 定义 GRE；Tanenbaum 第5章简述隧道；xiaolincoder 提及 overlay 与 MTU。

## 八、面试题
问：为什么隧道要调小 MTU/MSS？答：外层头增加长度使原 1500 包超过物理 MTU，需减小内层 MSS 或开启 PMTU 以避免分片与丢包。

## 九、演进与趋势
硬件 offload（如 NIC 的 VXLAN 解封装）降低 CPU 开销；Geneve 用可变长头更灵活；QUIC 在 UDP 上隧道化减少队头阻塞。

## 十、小结
隧道通过封装解耦内外层网络，代价是头部开销与 MTU 处理。合理规划 MTU/MSS 与 offload 是隧道性能的关键。
