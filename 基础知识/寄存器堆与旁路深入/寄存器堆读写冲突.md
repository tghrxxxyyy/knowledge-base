# 寄存器堆读写冲突

> 对应 Hennessy & Patterson《Computer Architecture》。

## 一、背景与挑战
同一周期内多指令同时读/写同一或不同物理寄存器，且写端口有限，会产生结构冲突与多端口争用，需仲裁或拆分。

## 二、核心原理
当某周期写端口数少于待写指令数，需将部分写延后或合并；读同一寄存器多端口并行无冲突，但写后读（同周期）需旁路而非堆内转发。

## 三、形式化与数学基础
端口需求下界：

    writes_per_cycle <= W_ports
    reads_per_cycle  <= R_ports

超额则需 stalls 或拆分周期。

## 四、代码实现
```verilog
// 写端口仲裁
always_comb begin
    we = 0;
    if (rob_commit_valid && wport_free) begin we = 1; waddr = commit_dst; end
end
```

## 五、与其他技术对比
分布式 PRF（按类型分整数/FPU）降低单堆端口压力；集中式简化但端口瓶颈明显。

## 六、常见误区
误以为读不会冲突；同周期多读需多读端口。误以为写可无限并行。

## 七、与开源书/权威来源对应
Hennessy & Patterson 讨论寄存器堆端口冲突与分布式设计。

## 八、面试题
1. 写端口不足如何处理？答：延后提交或增加堆/拆分。
2. 同周期读写同一寄存器靠什么？

## 九、演进与趋势
物理寄存器文件配合数据捕获减少写冲突与端口数。

## 十、小结
寄存器堆读写冲突源于有限端口，需仲裁、分布式堆或旁路来化解，是时序关键路径。
