# 寄存器重命名原理

> 对应 Hennessy & Patterson《Computer Architecture》。

## 一、背景与挑战
程序复用少量架构寄存器导致伪相关（WAR/WAW），限制乱序并行。重命名将架构寄存器动态映射到更大的物理寄存器堆，消除伪相关。

## 二、核心原理
每条写指令获得新物理寄存器，读指令引用最新映射。旧的「上一写者」在确认无读者且提交后回收。重命名表（RAT）是映射核心。

## 三、形式化与数学基础
逻辑到物理映射：

    RAT: ArchReg -> PhysReg
    写入: new_p = alloc(); RAT[dst] = new_p; link old_p to free-on-commit.

## 四、代码实现
```c
int RAT[32];
int free_stack[PHYS], sp = PHYS - 1;
int alloc() { return free_stack[sp--]; }
void rename_write(int rd) {
    int p = alloc();
    pending_free[RAT[rd]] = 1; // 旧物理寄存器待提交释放
    RAT[rd] = p;
}
```

## 五、与其他技术对比
无重命名则依赖停顿解决伪相关；重命名彻底解耦，但需管理物理寄存器生命周期与恢复。

## 六、常见误区
误以为重命名改变程序语义；仅改实现映射。误以为物理寄存器无限。

## 七、与开源书/权威来源对应
Hennessy & Patterson 详述 RAT 与物理寄存器分配。

## 八、面试题
1. 旧物理寄存器何时释放？答：确认无后续读者且提交后。
2. 重命名如何消除 WAW？

## 九、演进与趋势
检查点 RAT 加速恢复；混合架构/物理寄存器文件优化面积。

## 十、小结
寄存器重命名经动态映射消除伪相关，是乱序执行释放 ILP 的关键机制。
