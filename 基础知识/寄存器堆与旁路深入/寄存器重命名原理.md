# 寄存器重命名原理

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》（Tomasulo、记分牌、重命名）与 Patterson & Hennessy《Computer Organization and Design》，另参见 Herlihy & Shavit《The Art of Multiprocessor Programming》关于寄存器分配的类比。

## 一、背景与挑战

ISA 只暴露少量架构寄存器（RISC-V 32 个，ARM 31 个），而程序会反复复用它们。当指令序列里出现「写同一寄存器」或「读同一寄存器」却没有真实数据流关系时，就产生了伪相关：写后写（WAW）与写后读（WAR）。这些相关性并非程序语义要求，只是寄存器名字不够用导致的人为串行化。若不做处理，乱序执行会被迫遵守原程序顺序，大量并行性被浪费。寄存器重命名的任务就是：在硬件层面把少量架构寄存器动态映射到更多的物理寄存器，让每个「新写入的值」拥有独立存放位置，从而消除伪相关。

## 二、核心原理

重命名的核心洞察是：可以给每个逻辑值一个独立的名字（物理寄存器），于是 WAW/WAR 自然消失，只剩真实的数据流相关（RAW）。具体机制分三步。分配：每条写指令（destination）从空闲列表中取一个新的物理寄存器 $p_{new}$，作为该指令结果的新家。映射：重命名表（Register Alias Table, RAT 或 Map Table）把架构寄存器号更新为 $p_{new}$，于是后续读该架构寄存器的指令会拿到最新的物理名；同时该指令的源操作数需要被翻译成「当前 RAT 中记录的物理名」，这一步把逻辑读变成物理读。回收：被替换掉的旧物理寄存器 $p_{old}$ 不能立刻释放，因为可能仍有在途指令（已进入流水但尚未读到它）需要它；只有当确认没有读者且写入它的指令提交（retire/commit）之后，才能归还空闲列表。

分配与回收的顺序是正确性的关键。若采用「先分配后释放」且释放只在对提交时发生，则任何时刻在途指令引用的物理寄存器都不会被提前覆盖，这就是 Tomasulo 与后续乱序核的通行做法。若采用「重命名时立即释放」，则必须证明没有更老的未提交读者，代价是额外追踪结构。

RAT 通常分为前端 RAT（架构寄存器到最新物理名，供译码/重命名使用）与提交 RAT（架构状态，供精确异常恢复使用）。两者不一致的差距正好反映了在途投机的深度。

## 三、形式化与数学基础

记架构寄存器集合为 $A$，物理寄存器集合为 $P$，$|P| \gg |A|$。重命名是一个动态映射：

$$ \rho_t : A \to P $$

在时刻 $t$（按程序顺序推进）。对一条写架构寄存器 $a$ 的指令，定义为：

$$ p_{new} = \text{alloc}() ,\qquad \rho_{t+1}(a) = p_{new} $$

同时旧映射 $p_{old} = \rho_t(a)$ 被标记为待释放。对一条读架构寄存器 $a$ 的指令，其物理源为 $\rho_t(a)$。

并发的正确性条件可表述为：任何两条指令若在原程序中存在真实依赖 $i \to j$（$i$ 写、$j$ 读同一架构寄存器，且中间无第三方写），则重命名后 $j$ 的物理源等于 $i$ 的物理目的：

$$ \text{dep}(i,j) \implies src(j) = dst(i) $$

而伪相关的指令组在重命名后物理名互不相同：

$$ \text{WAW/WAR}(i,j) \implies dst(i) \neq dst(j) \ \text{或} \ src(i) \neq dst(j) $$

这就把「名字冲突」从执行约束中彻底移除。空闲物理寄存器的数量决定了可同时在途的指令数上界，因此 $|P| - |A|$ 约等于可投机的重命名槽位容量，是乱序窗口的硬件上限之一。

## 四、代码实现

下面用一个极简模型演示 RAT、空闲栈与待释放集合的协同（写指令重命名 + 提交回收）：

```c
#define NARCH 32
#define NPHYS 128

int RAT[NARCH];              // 架构 -> 物理
int phys_busy[NPHYS];        // 物理寄存器是否在用
int free_stack[NPHYS];       // 空闲物理栈
int free_top = NPHYS - 1;    // RISC-V 架构寄存器 0 号映射到固定物理项

int alloc_phys(void) {
    return free_stack[free_top--];   // 栈空即停顿：重命名槽位耗尽
}

void release_phys(int p) {
    free_stack[++free_top] = p;
    phys_busy[p] = 0;
}

// 重命名一条写 rd 的指令：返回其新分配的物理目的
int rename_write(int rd) {
    if (rd == 0) return 0;           // 零寄存器不分配、不追踪
    int p_new = alloc_phys();
    int p_old = RAT[rd];             // 旧名字：不能立刻释放
    RAT[rd] = p_new;
    pending_old_dst[--pending_top] = p_old;  // 提交时由 ROB 释放
    return p_new;
}

// 翻译源操作数：读取当前映射
int rename_read_src(int rs) {
    return RAT[rs];
}

// 提交阶段：指令退休时回收它替换掉的旧物理寄存器
void retire(int rob_entry) {
    if (rob_entry.old_dst != 0 && rob_entry.old_dst != rob_entry.new_dst)
        release_phys(rob_entry.old_dst);
}
```

关键边界：零寄存器（x0）永不分配也永不释放，否则会污染空闲列表；`free_top` 下溢时必须停顿重命名级，这是「重命名停顿」（rename stall）的来源，也是乱序窗口的真实限制。

## 五、与其他技术对比

| 机制 | 消除 WAW | 消除 WAR | 消除 RAW | 恢复方式 | 硬件成本 |
| --- | --- | --- | --- | --- | --- |
| 顺序发射 + 停顿 | 靠顺序 | 靠顺序 | 前递/停顿 | 无需 | 极低 |
| 记分牌（Scoreboard） | 部分 | 部分 | 靠等待 | 顺序提交 | 低 |
| Tomasulo（CDB + 保留站） | 是 | 是 | 靠 CDB 广播 | 顺序提交 | 中高 |
| 显式重命名 + ROB | 是 | 是 | 靠唤醒/旁路 | 精确异常、检查点 | 高 |
| 编译器静态重命名（软件流水） | 是 | 是 | 靠调度 | 无需硬件 | 编译器复杂 |

与「扩大架构寄存器数量」相比，重命名不改变 ISA、不破坏二进制兼容，却把可用名字数量从 32 提升到上百，这是它被所有现代高性能核采用的根本原因。

## 六、常见误区

1. 认为重命名会改变程序语义。它只改变值的存放位置，架构可见状态在提交时与顺序执行完全一致。
2. 认为物理寄存器可以无限增多。端口数、面积与访问延迟限制其规模，且空闲槽位决定乱序窗口上界。
3. 认为旧物理寄存器在重命名当拍即可释放。存在尚未读取该旧值的在途消费者时提前释放会造成静默数据损坏。
4. 忽略零寄存器的特殊映射，导致空闲列表被污染或出现悬空物理名。
5. 混淆重命名与旁路。重命名解决「名字冲突」，旁路解决「真实依赖的延迟」，二者分工不同且必须同时存在。
6. 忘记检查点（checkpoint）机制。分支误预测后若不能快速回滚 RAT 与空闲列表，恢复代价会吞掉投机收益。

## 八、面试题

1. 重命名为什么能消除 WAW 和 WAR？
   要点：WAW/WAR 源于复用同名寄存器；为每次写分配独立物理名后，两条指令的物理目的或源不再重合，顺序约束不再必要。

2. 旧物理寄存器什么时候才能真正释放？
   要点：当所有可能读到该旧值的更老指令都已进入流水（读过）且写它的指令已提交；工程上用 ROB 在提交时统一回收最安全。

3. 重命名如何影响乱序窗口大小？
   要点：空闲物理寄存器数量给出在途投机指令数的硬上限；槽位耗尽时重命名级停顿，窗口无法继续扩大。

4. 分支误预测后如何恢复映射状态？
   要点：提交 RAT 保持不变，回滚只需恢复前端 RAT 与空闲列表；用检查点快照或走 ROB 回滚均可行，检查点更快。

5. 重命名与寄存器分配（编译器）有何异同？
   要点：都把有限名字映射到更多存储；编译器在编译期消除伪相关以生成更好代码，硬件在运行期动态消除以适配任意二进制。

## 九、演进与趋势

早期 Tomasulo 用保留站加公共数据总线隐式完成重命名；现代核心用显式 PRF + RAT + ROB，把重命名与调度解耦，便于支持宽发射与深窗口。演进方向包括：检查点 RAT 加速分支恢复；破坏性重命名与交换技术（如 move elimination 让寄存器搬移只需换名不占执行单元）；以及「零延迟重命名」通过与与门消除不必要的物理寄存器分配以省面积。在向量与矩阵扩展中，重命名对象从标量寄存器扩展到向量寄存器片段，映射表规模与端口压力显著上升。

## 十、小结

寄存器重命名通过动态映射把有限架构寄存器扩展到充裕物理寄存器，一举消除 WAW/WAR 伪相关，让乱序执行能够真正按数据流调度。它的正确性依赖三条纪律：新写必先分配、旧值必须等确认无读者且提交后才回收、零寄存器永不参与分配。理解这三条，就掌握了乱序核心最核心的机制。
