# 物理寄存器文件与RAT

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》乱序执行章节、Patterson & Hennessy《Computer Organization and Design》，以及 Intel SDM 与 ARM ARM 中架构状态与微架构资源的区分说明。

## 一、背景与挑战

寄存器重命名需要一个大得多的实际寄存器堆来存放同一架构寄存器的多个版本，这个结构就是物理寄存器文件（Physical Register File, PRF），而把架构寄存器映射到物理项的结构就是重命名表（Register Alias Table, RAT）。二者协同，才能让乱序执行在不破坏架构语义的前提下自由调度：PRF 提供容量以容纳投机值，RAT 提供映射以定位当前值。核心挑战有三个：PRF 的端口与面积如何随容量增长而可控；RAT 如何在分支误预测后快速回滚；以及空闲物理寄存器的生命周期管理如何既不泄漏也不提前回收。

## 二、核心原理

PRF 与架构寄存器堆（ARF）的本质区别在语义：ARF 只有一份「官方」值，任何时刻读到的都是确定的提交状态；PRF 同时保存已提交值与投机值，且同一个架构寄存器可能对应多个物理项，其中只有 RAT 指向的那个才是「当前版本」。指令读操作数时，先查 RAT 把架构号翻译成物理号，再去 PRF 读该物理项；指令写结果时，结果写入它被分配到的物理项（而非架构号）。架构可见状态只在提交时通过更新提交 RAT 而「显式化」，PRF 中的投机项不改变架构语义。

分支恢复依赖检查点：在可能误预测的分支处保存 RAT 快照（以及空闲列表的边界），一旦确认误预测，就用快照在若干周期内重建前端 RAT 与空闲列表。若没有快照，就必须逐条回滚 ROB 中所有更年轻的指令，恢复时间与投机深度成正比，高频宽核心难以承受。检查点数量是面积与恢复速度的权衡：备份越多，可同时投机多个分支，但每份都是 31×7 位以上的存储与端口。

空闲物理寄存器的生命周期遵循三步：分配（重命名时从空闲列表取）、使用（写结果、被消费者读取）、回收（替换它的那条指令提交时，旧的物理项才归还）。回收时机是正确性关键：若在重命名时立即回收旧项，仍在途的更老消费者可能读到已被新值覆盖的内容。因此几乎所有实现都把实际回收推迟到提交。

## 三、形式化与数学基础

设架构寄存器数 $|A|=32$，物理寄存器数 $|P|$，空闲列表初始大小为 $|P| - |A| - 1$（扣除零寄存器对应的固定物理项）。任何时刻在途未提交且已分配物理目的的最大指令数不超过空闲槽位数，因此：

$$ W_{window} \le |P| - |A| - 1 + (\text{可复用项}) $$

这条不等式说明：想在乱序窗口里容纳 $W$ 条指令，PRF 至少要有 $|A| + W$ 个物理项。分支恢复代价可建模为：若在深度 $d$ 处误预测，走 ROB 逐条回滚的代价为 $O(d)$；使用检查点则近似为常数 $O(1)$（受检查点个数限制，取最近的一个）。

PRF 面积与延迟随容量增长的一阶模型为：

$$ A_{PRF} \approx |P| \cdot W_{bits} \cdot A_{cell}(r,w), \qquad T_{PRF} \approx T_{decode} + T_{bl}(|P|) + T_{sense} $$

这解释了为何 PRF 通常按数据类型拆分（整数、浮点、向量），并采用 bank 化以控制位线长度。下表总结关键数量关系：

| 量 | 符号 | 典型约束 |
| --- | --- | --- |
| 架构寄存器数 | $|A|$ | 由 ISA 固定（32） |
| 物理寄存器数 | $|P|$ | 由面积与窗口需求决定 |
| 可投机槽位 | $|P|-|A|-1$ | 决定乱序窗口上界 |
| 检查点数量 | $C$ | 面积与恢复延迟折中 |

## 四、代码实现

下面演示 PRF、RAT、检查点与空闲列表的协同模型，重点看恢复路径：

```c
#define NARCH 32
#define NPHYS 192
#define NCP   8

typedef struct {
    uint64_t val;
    int      ready;      // 结果是否已算出（供唤醒使用）
} phys_entry;

phys_entry PRF[NPHYS];
int RAT[NARCH];                 // 前端重命名表：架构 -> 物理
int RAT_commit[NARCH];          // 提交表：架构可见映射
int ckpt_rat[NCP][NARCH];       // 检查点快照
int ckpt_free_top[NCP];         // 检查点处的空闲栈顶，用于回滚分配
int free_stack[NPHYS];
int free_top;
int ckpt_id;

// 分配前先打检查点：记录当前自由栈边界与 RAT
void take_checkpoint(void) {
    int c = ckpt_id++ % NCP;
    for (int i = 0; i < NARCH; i++) ckpt_rat[c][i] = RAT[i];
    ckpt_free_top[c] = free_top;
}

// 分支误预测：用最近检查点一次性回滚 RAT 与空闲列表
void recover_from_checkpoint(int c) {
    for (int i = 0; i < NARCH; i++) RAT[i] = ckpt_rat[c][i];
    free_top = ckpt_free_top[c];   // 之前投机分配出去的物理项全部作废并归还
}

// 提交：把前端映射的对应项固化为架构状态，并回收它替换掉的旧项
void commit_entry(int arch_rd, int new_phys, int old_phys) {
    if (arch_rd == 0) return;
    RAT_commit[arch_rd] = new_phys;          // 架构可见值更新
    if (old_phys != 0 && old_phys != new_phys)
        free_stack[++free_top] = old_phys;   // 旧物理项归还空闲列表
}
```

边界注意：`free_top` 必须能跨检查点回滚，否则投机分配出去的物理项会永久泄漏，最终导致重命名停顿；检查点环形复用时，只有在对应分支已解决后才能被覆盖。

## 五、与其他技术对比

| 结构 | 存放内容 | 版本数 | 恢复方式 | 端口压力 | 典型实现 |
| --- | --- | --- | --- | --- | --- |
| 架构寄存器堆 ARF | 仅提交值 | 1 | 无需回滚 | 多读多写 | 顺序核 |
| PRF + RAT | 提交值 + 投机值 | 多版本 | 检查点或 ROB 回滚 | 多读少写 | 现代乱序核 |
| 保留站 + CDB（Tomasulo） | 操作数暂存于站内 | 隐式 | 顺序清空 | CDB 广播瓶颈 | 早期乱序核 |
| 影子寄存器（shadow） | 复制提交状态 | 2 份 | 交换 | 面积翻倍 | 部分嵌入式核 |

与 Tomasulo 的隐式重命名相比，显式 PRF + RAT 的优势是把「值存放」与「值广播」解耦：结果先写 PRF，唤醒信号单独传播，避免了 CDB 单点广播的带宽瓶颈，代价是需要更大的 PRF 与更复杂的检查点管理。

## 六、常见误区

1. 认为 PRF 越大越好。容量增长抬高位线延迟与面积，且端口数是更硬的约束；超出窗口需求的容量纯属浪费。
2. 认为 RAT 不需要检查点。没有快速回滚能力，分支误预测的恢复代价会随投机深度线性上升，抵消乱序收益。
3. 认为空闲物理项可以在重命名当拍释放。在途的老消费者可能仍引用旧物理名，提前释放导致静默数据损坏。
4. 混淆前端 RAT 与提交 RAT。前者推进到投机前沿，后者只在提交时更新；异常与恢复全部依赖这一区分。
5. 忽略零寄存器的物理映射，导致空闲列表泄漏或出现永不回收的物理项。
6. 认为数据捕获可以完全省掉 PRF 写端口。捕获只减少部分写压力，架构状态的更新与检查点回滚仍需 PRF 保存。

## 八、面试题

1. 检查点 RAT 用来解决什么问题？
   要点：分支误预测后快速回滚前端映射与空闲列表；用快照把恢复从 $O(d)$ 降到近似 $O(1)$，代价是每份快照的存储与端口。

2. 物理寄存器在什么条件下才真正空闲？
   要点：当替换它的那条指令提交，且所有更老的潜在读者都已读过它之后；工程上由提交阶段统一回收最安全。

3. PRF 与架构寄存器堆在语义上的根本区别是什么？
   要点：ARF 只存提交值、每寄存器一份；PRF 存提交值与投机值、同架构号可有多份，哪一份「当前」由 RAT 决定。

4. 为什么现代核心倾向「多读少写」的 PRF 端口配置？
   要点：读操作数需求远多于写结果（宽发射下 2:1 甚至更高）；配合数据捕获与旁路可进一步压低写端口。

5. 空闲列表泄漏会导致什么现象？
   要点：可用物理项逐渐减少直至耗尽，重命名级停顿、发射宽度利用不足、性能随运行时间缓慢下降，且难以定位。

## 九、演进与趋势

演进方向包括：数据捕获（capture）让结果直接经旁路送消费者，减少 PRF 写端口压力；分布式 PRF 按执行簇拆分并对齐唤醒延迟，降低交叉读写；检查点数量动态可配以适配不同分支密度；以及在向量与矩阵扩展中用分段 PRF 支持超大寄存器宽度。另一个趋势是「零值优化」与 move elimination，通过与门和名字交换减少不必要的物理项分配，从而在相同面积下换取更大的有效窗口。

## 十、小结

PRF 与 RAT 构成重命名的物理基础：PRF 提供多版本容量，RAT 提供当前映射，检查点提供快速恢复，空闲列表管理版本生命周期。四者缺一不可，任何一环的时机错误都会导致静默数据损坏或性能慢性衰减。理解 $W_{window} \le |P|-|A|-1$ 这条不等式，就理解了乱序窗口为何受物理寄存器规模硬约束。
