# 旁路转发与数据冒险

> 对应 Hennessy & Patterson《Computer Architecture》与 Bryant & O'Hallaron《CSAPP》。

## 一、背景与挑战
流水线中后一条指令可能依赖前一条尚未写回的结果（RAW 数据冒险），若停顿等待会浪费周期。旁路（forwarding/bypass）将中间结果直接前递给后续级。

## 二、核心原理
当 EX 或 MEM 段产生结果时，经旁路网络送至需要它的指令的 EX 输入，避免写回后再读。仍需一拍解决不了的 load-use 冒险（load 结果晚一拍）则插入气泡。

## 三、形式化与数学基础
RAW 冒险本需停顿 k 周期；旁路后：

    stall_cycles = max(0, produce_stage - consume_stage)

load-use 典型仍需 1 气泡。

## 四、代码实现
```verilog
// 旁路选择
always_comb begin
    if (ex_reg_wb && ex_rd == id_rs1) operand1 = ex_result;
    else if (mem_reg_wb && mem_rd == id_rs1) operand1 = mem_result;
    else operand1 = rf_rdata1;
end
```

## 五、与其他技术对比
停顿（插入气泡）简单但慢；旁路消除多数 RAW 停顿，是流水线标准优化。

## 六、常见误区
误以为旁路解决所有冒险；控制冒险与部分 load-use 仍需停顿/预测。误以为旁路改变语义。
