# 旁路转发与数据冒险

> 对应 Bryant & O'Hallaron《CSAPP》第 4 章（处理器体系结构）、Hennessy & Patterson《Computer Architecture: A Quantitative Approach》，以及 Patterson & Hennessy《Computer Organization and Design》冒险处理章节。

## 一、背景与挑战

流水线让多条指令重叠执行，但指令之间存在依赖关系。依赖分三类：结构冒险（硬件资源冲突，如同时争用同一存储器端口）、控制冒险（分支改变取指方向）、数据冒险（后一条指令需要前一条尚未产生的结果）。其中数据冒险又可细分为 RAW（读后写，真实依赖）、WAR（写后读，反依赖）和 WAW（写后写，输出依赖）。在顺序发射的五级流水线中，WAR/WAW 天然由顺序保证，因此主要矛盾是 RAW：前一条指令的结果要到 WB 段才写回寄存器堆，而后一条指令在 EX 段开头就需要它，若纯粹等待就要停顿 2~3 拍。

## 二、核心原理

旁路（forwarding，又称 bypassing）的核心思想是：结果不必等到写回寄存器堆，只要它在流水线的某个中间级已经算出，就可以通过额外的数据通路直接送到需要它的指令输入端，把原本「必须先落堆再读堆」的串行链条改成并行直连。

具体到五级流水线，结果在三个位置可用：EX 段末的 ALU 输出、MEM 段末的加载数据、WB 段末准备写堆的值。前两者可以直接前递给下游指令的 EX 输入，因此绝大多数 ALU-ALU 依赖无需停顿。旁路网络就是一组比较器加多路选择器：比较在途指令的目的寄存器号与当前指令的源寄存器号，命中则选中间结果。

优先级是关键：越靠近 EX 段的结果越新。若 EX/MEM 与 MEM/WB 都命中同一源寄存器，必须选 EX/MEM 那条（更年轻）的结果，否则会读到被覆盖前的旧值。这个错误不会导致崩溃，只会导致错误结果，且只在特定指令序列下出现，属于最危险的静默错误类型。

然而 load 指令有本质限制：数据在 MEM 段末才从存储器取出。紧随其后的消费者在 EX 段开头就需要它，前后只差一个周期，即便有旁路也来不及，因为数据在时间上尚不存在。这就是 load-use 冒险，必须插入一个气泡（bubble）。另一种解法是让 load 在地址计算完成后就尽早取数（提前发射或缩短存储器延迟），或在乱序核中由调度器把无关指令插进来填补，这就是为什么乱序核可以做到零停顿。

## 三、形式化与数学基础

把指令 $i$ 的结果产生段记为 $P(i)$，消费者 $j$ 需要该结果的段记为 $C(j)$，以周期为单位，需要插入的气泡数为：

$$ \text{stall}(i,j) = \max\left(0,\; P(i) - C(j)\right) $$

对 ALU 结果：$P=3$（EX 末），消费者 $C=3$（EX 开头），故 $\text{stall}=0$。对 load 结果：$P=4$（MEM 末），消费者 $C=3$，故 $\text{stall}=1$。

整体 CPI 可写为：

$$ \text{CPI} = 1 + \frac{N_{loaduse} + N_{branch} + N_{struct}}{N_{instr}} $$

在加入多档旁路后，$N_{loaduse}$ 只剩连续 load-消费者对；控制冒险由分支预测处理；结构冒险由端口复制处理。若想进一步压缩，需要乱序调度把气泡填满：

$$ \text{IPC} \le \min(\text{issue width},\ \text{ports/cycle},\ \text{1/(1 - N_{bubble}/N_{instr})}) $$

此外还需注意「同拍写后读」：若消费者与生产者恰好相隔一个流水级，则旁路必须在同一周期内既完成写堆又完成前递，此时堆内读到的是旧值，正确性完全依赖旁路选择，这也解释了为何 RTL 中读端口常写成组合读。

## 四、代码实现

先看前递数据的来源选择，按「越年轻越优先」排列：

```verilog
// 为 EX 段生成两个操作数：EX/MEM 优先，其次 MEM/WB，最后寄存器堆
always_comb begin
    src_a = rf_rdata_a;
    src_b = rf_rdata_b;

    if (exmem_regwrite && exmem_rd != 5'd0 && exmem_rd == idex_rs1)
        src_a = exmem_result;                 // 最年轻的结果
    else if (memwb_regwrite && memwb_rd != 5'd0 && memwb_rd == idex_rs1)
        src_a = memwb_result;

    if (exmem_regwrite && exmem_rd != 5'd0 && exmem_rd == idex_rs2)
        src_b = exmem_result;
    else if (memwb_regwrite && memwb_rd != 5'd0 && memwb_rd == idex_rs2)
        src_b = memwb_result;
end
```

再看 load-use 侦测与停顿插入，注意停顿要冻结 PC 与 IF/ID，同时给 EX 注入气泡：

```verilog
// 上一条是 load，且其结果被本条立即使用：必须停顿一拍
assign load_use = idex_memread && (idex_rd != 5'd0) &&
                  ((idex_rd == ifid_rs1) || (idex_rd == ifid_rs2));

always_ff @(posedge clk) begin
    if (load_use) begin
        pc    <= pc;            // 冻结取指
        ifid  <= ifid;          // 冻结译码
        idex  <= BUBBLE;        // EX 注入气泡
        exmem <= idex;          // 后续正常推进
    end
end
```

store 指令需要特别注意：它的数据依赖走的是 MEM 段（写存储器）而非 EX 段，因此对 store 数据的旁路要检查 MEM 段目的寄存器，时序窗口与 ALU 消费者不同，是教科书之外的常见真实工程细节。

## 五、与其他技术对比

| 方案 | RAW 停顿 | load-use 处理 | 控制冒险 | 硬件成本 | 适用场景 |
| --- | --- | --- | --- | --- | --- |
| 纯停顿（插气泡） | 每条 1~3 拍 | 停顿 1 拍 | 停顿 | 极低 | 教学、极简核 |
| 单档旁路（仅 EX/MEM） | 部分消除 | 停顿 1 拍 | 停顿 | 低 | 早期流水线 |
| 全档旁路（EX/MEM/WB） | 基本为 0 | 停顿 1 拍 | 预测 | 中 | 通用五级流水 |
| 旁路 + 分支预测 | 接近 0 | 停顿 1 拍 | 大幅降低 | 中高 | 现代顺序核 |
| 乱序 + 唤醒网络 | 0 | 由调度填满 | 预测 + 检查点 | 很高 | 高性能核 |

旁路与前递名称在文献中常互换；严格说 forwarding 强调「把结果送到消费者」，bypassing 强调「绕开寄存器堆这条路径」，二者在工程语境里指同一机制。旁路与寄存器重命名的分工也要分清：旁路解决真实依赖的延迟，重命名解决伪依赖的顺序约束。

## 六、常见误区

1. 认为旁路能解决所有数据冒险。load-use 因结果产生太晚，时间上不可达，必须插气泡或靠乱序填补。
2. 认为旁路也解决控制冒险。控制冒险需要分支预测或冲刷，与数据通路前递无关。
3. 认为旁路不改变任何语义。旁路改变了「值从哪个来源读出」，若优先级写错，语义就被悄悄破坏，产生静默错误。
4. 忘记比较「是否真的要写寄存器」。若不检查 regwrite 有效且目的非零，会把无关指令的结果错误前递。
5. 忽略同拍写后读的陷阱：读端口是组合读时，同拍命中的写不会反映在堆输出上，必须由旁路兜底。
6. 忽视 store 数据的旁路时点。store 数据在 MEM 段使用，若只按 EX 段消费者设计旁路逻辑会漏掉这一类依赖。

## 八、面试题

1. 为什么 load-use 冒险即使有前递也仍需气泡？
   要点：load 结果在 MEM 段末才可用，消费者在 EX 段开头就需要，时间上不可达，只能插气泡或由乱序调度填满。

2. 旁路与寄存器重命名的区别是什么？
   要点：旁路消除真实依赖（RAW）造成的等待，靠数据通路直连；重命名消除伪依赖（WAR/WAW）造成的顺序约束，靠名字扩展。二者互补。

3. 为什么前递必须比较目的寄存器号，而不是只判断指令类型？
   要点：只有真正写该寄存器的在途指令才携带所需值；不比较寄存器号会把无关结果错误前递。

4. 同时命中两档前递时如何选择？
   要点：选更年轻的结果（EX/MEM 优先于 MEM/WB），否则会读到被覆盖前的旧值，形成静默错误。

5. 为什么旁路无法把 CPI 压到 1 以下？
   要点：旁路只消除停顿，不能增加每周期发射的指令数；CPI 下界由发射宽度与资源端口决定，旁路只负责不让冒险把 CPI 抬高。

## 九、演进与趋势

简单前递在多发射乱序核中演进为唤醒网络（wakeup）+ 旁路网络（bypass）的双网络结构：唤醒负责通知发射队列中哪些指令的操作数已就绪，旁路负责把结果物理送到执行单元。随着发射宽度增加，旁路多路选择器的扇入急剧膨胀，成为时序瓶颈，因此出现分段旁路、按簇（cluster）分组前递、以及数据捕获等去长线手段。另一个趋势是把部分前递职责下移到编译器（软件流水、静态调度），或在 VLIW 中以显式延迟槽替代硬件旁路，用编译器复杂度换硬件面积。

## 十、小结

旁路转发通过把尚未写回的结果直接前递给消费者，消除了绝大多数 RAW 停顿，是流水线性能的基础机制。它的实现由比较器加多路选择器构成，成败取决于三条纪律：必须比较目的寄存器号、必须按「越年轻越优先」的优先级选择、必须准确识别 load-use 并插入气泡。理解这三条，才能既拿到性能又避免静默错误。
