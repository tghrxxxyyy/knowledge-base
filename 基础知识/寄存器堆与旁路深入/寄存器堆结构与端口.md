# 寄存器堆结构与端口

> 对应 Hennessy & Patterson《Computer Architecture》与 ARMv8 手册。

## 一、背景与挑战
寄存器堆是 CPU 最频繁访问的存储，需在单周期内支持多读多写（多发射）。端口数与面积、时序（字线/位线延迟）直接冲突。

## 二、核心原理
寄存器堆由二维存储单元阵列构成，配置独立读端口（提供地址→读出数据）与写端口（使能+数据写入）。每多一个端口增加位线与多路选择，面积和访问时间近似平方增长。

## 三、形式化与数学基础
访问时间随端口数 r、w 增长：

    T_access ~ O((r + w) * log2(N))  (N 为寄存器数)

多端口代价高昂，常靠复制或旁路折中。

## 四、代码实现
```verilog
// 双读一写寄存器堆
always_ff @(posedge clk) begin
    if (we) rf[waddr] <= wdata;
end
assign rdata1 = rf[raddr1];
assign rdata2 = rf[raddr2];
```

## 五、与其他技术对比
纯多端口 SRAM 快但面积大；用时间复用或 bank 拆分降低端口数，但增加延迟。

## 六、常见误区
误以为端口数可无限堆；物理与时序限制明显。误以为寄存器堆等同缓存。

## 七、与开源书/权威来源对应

## 九、演进与趋势
物理寄存器堆（PRF）与 RAT 取代小架构堆，支持重命名与多端口。

## 十、小结
寄存器堆以多端口支撑多发射，端口数与时序/面积是核心矛盾，需结构设计折中。
