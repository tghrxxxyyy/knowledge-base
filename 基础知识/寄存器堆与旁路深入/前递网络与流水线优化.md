# 前递网络与流水线优化

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》、Bryant & O'Hallaron《CSAPP》第 4 章（处理器体系结构），以及 Patterson & Hennessy《Computer Organization and Design》流水线章节。

## 一、背景与挑战

经典五级流水线（IF/ID/EX/MEM/WB）让指令重叠执行以逼近每周期一条指令（CPI≈1）。但指令之间存在真实数据依赖（RAW）：后一条指令的源操作数是前一条尚未写回的结果。如果只靠停顿等待写回，回写发生在 WB 段而使用发生在 EX 段，两条指令相差 3 个周期，会产生大量气泡，把 CPI 从 1 抬高到接近 2。前递（forwarding，又称 bypassing）网络的作用是：把中间级已经算出的结果不经寄存器堆直接送到需要它的指令输入端，从而把大部分 RAW 停顿压缩为零。

## 二、核心原理

流水线各级都会产生「结果」：EX 段的 ALU 输出、MEM 段的加载数据、WB 段准备写堆的值。前递网络本质是一组按目的寄存器号比较驱动的多路选择器：当某条后续指令的源寄存器号等于某个在途指令的目的寄存器号，且该在途指令确实要写寄存器（reg_write 有效、目标非零寄存器），就把它的中间结果选入本条指令的 ALU 输入，而不是用寄存器堆读出的旧值。

优先级必须严格：越接近 EX 段的结果越新。典型顺序是 EX/MEM 流水寄存器优先于 MEM/WB 流水寄存器，最后才是寄存器堆原值。若两条在途指令都写同一寄存器，必须选更年轻的那条（EX/MEM），否则会把旧值当成新值，产生静默错误。

前递能覆盖 ALU-ALU 依赖、ALU-store 数据依赖、甚至 store 数据到 store 地址的依赖，但无法覆盖 load-use：load 的数据在 MEM 段末才从存储器取出，而下一条指令需要在 EX 段开头就拿到，前后只差一个周期，时间上不可达，必须插入一个气泡。此外前递不能解决控制冒险，那需要分支预测或冲刷。

## 三、形式化与数学基础

把指令 $i$ 的结果产生段记为 $P(i)$，消费者需要该结果的段记为 $C(i)$，则以周期为单位的原始停顿为：

$$ \text{stall} = \max\left(0,\; P(i) - C(i)\right) $$

五级流水线中 ALU 结果在 EX 段末可用（$P=3$），消费者在 EX 段开头需要（$C=3$），故 $\text{stall}=0$，加旁路后无停顿。load 结果在 MEM 段末可用（$P=4$），消费者 $C=3$，故 $\text{stall}=1$，即典型的一拍 load-use 气泡。

整体性能可用 CPI 表示：

$$ \text{CPI} = 1 + \frac{N_{loaduse} + N_{branch} + N_{struct}}{N_{instr}} $$

前递消除了几乎所有 ALU RAW 项，剩下的主要是 load-use、控制冒险与结构冒险。若进一步配合分支预测与更深的旁路级（把 MEM 结果也纳入 EX 输入），可把上式分子压到很低，使实际 IPC 接近发射宽度上限。

## 四、代码实现

下面用 Verilog 展示一个 EX 段入口的旁路选择逻辑，注意优先级从新到旧：

```verilog
// ex_forward: 为 EX 段两个源操作数选择数据来源
always_comb begin
    // 默认取自寄存器堆
    op_a = rf_rdata_a;
    op_b = rf_rdata_b;

    // 第一优先级：EX/MEM 流水寄存器（最年轻的结果）
    if (exmem_regwrite && exmem_rd != 5'd0 && exmem_rd == id_ex_rs1)
        op_a = exmem_alu_result;
    if (exmem_regwrite && exmem_rd != 5'd0 && exmem_rd == id_ex_rs2)
        op_b = exmem_alu_result;

    // 第二优先级：MEM/WB 流水寄存器（较旧，仅在未命中上一档时生效）
    if (memwb_regwrite && memwb_rd != 5'd0 && memwb_rd == id_ex_rs1
        && !(exmem_regwrite && exmem_rd == id_ex_rs1))
        op_a = memwb_write_data;
    if (memwb_regwrite && memwb_rd != 5'd0 && memwb_rd == id_ex_rs2
        && !(exmem_regwrite && exmem_rd == id_ex_rs2))
        op_b = memwb_write_data;
end
```

与旁路配套的 load-use 侦测与停顿插入：

```verilog
// 若上一条是 load 且其结果被本条立即使用，则冻结 PC 与 IF/ID，插入气泡
wire load_use = idex_memread && idex_rd != 5'd0 &&
                (idex_rd == ifid_rs1 || idex_rd == ifid_rs2);

always_ff @(posedge clk) begin
    if (load_use) begin
        pc       <= pc;          // 保持
        ifid     <= ifid;        // 保持
        idex     <= bubble();    // 注入气泡
        exmem    <= idex_old;    // 正常推进
    end
end
```

## 五、与其他技术对比

| 方案 | 硬件成本 | RAW 停顿 | 对 load-use | 对控制冒险 | 综合适用性 |
| --- | --- | --- | --- | --- | --- |
| 纯停顿（插气泡） | 极低 | 每条 RAW 停 1~3 拍 | 需停顿 | 需停顿 | 教学与极简核 |
| 全前递（EX/MEM/WB 三档） | 中等 | 基本为 0 | 仍需 1 拍 | 无帮助 | 通用五级流水 |
| 前递 + 分支预测 | 中高 | 接近 0 | 仍需 1 拍 | 大幅降低 | 现代顺序核 |
| 重命名 + 乱序发射 | 高 | 0 | 靠调度隐藏 | 靠预测 + 检查点 | 高性能核心 |
| 唤醒网络（issue queue） | 很高 | 0 | 靠动态调度 | 靠预测 | 宽发射乱序核 |

核心权衡是：前递用组合逻辑的复杂度换周期数；乱序用更大的窗口与调度逻辑换更高的并行度。前递是基础，乱序是它的自然延伸。

## 六、常见误区

1. 认为前递能消除所有数据冒险。load-use 因结果产生太晚，仍需至少一个气泡，这是时间上的硬约束而非实现缺陷。
2. 认为前递与控制冒险无关却可以顺手解决。控制冒险需要预测或冲刷，前递只处理数据通路上的读写依赖。
3. 忘记比较「是否真的要写寄存器」。若在途指令不写寄存器或目的为零寄存器，误判为依赖会引入错误的前递。
4. 忽略优先级顺序。EX/MEM 必须优先于 MEM/WB，否则在连续两条指令写同一寄存器时读到旧值，形成极难复现的静默错误。
5. 忽视 store 的两种依赖。store 的地址来自 EX、数据可能来自另一条在途指令，二者都要前递，且时序要求不同。

## 八、面试题

1. 为什么 load-use 冒险即使有前递也仍需停顿一拍？
   要点：load 数据在 MEM 段末才可用，紧随其后的指令在 EX 段开头就需要，时间上不可达，只能插气泡或靠乱序调度填补。

2. 前递网络为什么必须比较目的寄存器号，而不能只比较是否是 ALU 指令？
   要点：只有真正写该寄存器且在途的指令才携带所需值；不比较寄存器号会把无关指令的结果错误前递。

3. 连续两条指令写同一寄存器时，前递的优先级为什么重要？
   要点：EX/MEM 中的结果比 MEM/WB 更新；若不按「越年轻越优先」选择，消费者会读到被覆盖前的旧值。

4. 前递与寄存器重命名是什么关系？
   要点：前递解决真实依赖的延迟问题（相同逻辑寄存器的读写），重命名解决伪依赖（WAR/WAW）造成的顺序约束，二者互补。

## 九、演进与趋势

前递网络在现代核心中与乱序调度深度融合：简单旁路演进为唤醒网络（wakeup network），发射队列在被唤醒的条目上做选择性发射；结果可以经「数据捕获」直接送给消费者而不写回堆，进一步缩短关键路径。同时，深流水与超宽发射让旁路多路选择器的扇入急剧膨胀，成为时序收敛的瓶颈，因此出现了分段旁路、按 bank 分组前递、以及用寄存器缓存中间结果以减少长线互连等工程手段。

## 十、小结

前递网络是流水线优化的基石：它用一组按寄存器号比较驱动的多路选择器，把大多数 RAW 依赖的等待从 2~3 拍压缩到 0，仅对 load-use 与控制冒险保留必要开销。理解其优先级规则、与停顿的配合边界，以及在大规模乱序核中的演进形态，是评估流水线性能的关键。
