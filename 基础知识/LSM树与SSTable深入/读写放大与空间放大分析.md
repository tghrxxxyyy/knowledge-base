# 读写放大与空间放大分析

> 对应 Chang et al. 2006（SSTable/Bigtable 中的放大问题），以及 cmu-db/15445-course 关于 LSM 代价模型的 lecture。

## 一、背景与挑战
LSM 引入三种相互制约的代价：写放大（WA）、读放大（RA）、空间放大（SA）。调优本质是三者在硬件约束下的权衡，任一指标的改善常以增加另一指标为代价。

## 二、核心原理
- 写放大：一次逻辑写触发多次物理写（compaction 重写同一数据）。
- 读放大：一次读需访问多个 SSTable 与层。
- 空间放大：同一 key 的多版本/墓碑占位导致磁盘占用高于逻辑数据量，直到 compaction 回收。

## 三、形式化与数学基础
Leveled 写放大约为 $WA \approx L \cdot T$（$L$ 层、$T$ 为 fanout）。Tiered 写放大接近 $T$。空间放大：
$$ SA = \frac{Size_{on\_disk}}{Size_{logical}} \ge 1 $$
在仅 Leveled 且未及时 compaction 时 $SA$ 可接近 $L$。读放大经验式：
$$ RA \approx L + \text{miss\_per\_level} $$

## 四、代码实现
```c
// 估算一次 flush 的写放大（仅示意）
double estimate_wa(int levels, int fanout, int tiered) {
    if (tiered) return (double)fanout;            // tiered 写放大低
    return (double)levels * fanout;               // leveled 写放大高
}
// SA 监控：比较 logical_size 与 sst_total_bytes
double space_amp(uint64_t sst_total, uint64_t logical) {
    return (double)sst_total / (logical ? logical : 1);
}
```

## 五、与其他技术对比
B+ 树 WA≈1（原地更新），但随机写慢；LSM Tiered WA 低、SA 高；Leveled SA 低、WA 高。WiscKey 通过 KV 分离把大 value 移出 LSM，显著降低 WA 与 SA。

## 六、常见误区
1) 只盯着 WA 调小——可能让 SA/RA 爆炸。
2) 误以为更多层一定更好——层多 WA、RA 同增。
3) 忽视墓碑积累导致 SA 长期偏高。

## 九、演进与趋势
自适应 compaction（按负载切换 Leveled/Tiered）、机器学习预测写模式、ZNS SSD 上 LSM 写放大近 1、KV 分离成为主流优化。

## 十、小结
三放大是 LSM 的统一代价视角；工程上应先定 SLA 再反推层级、fanout 与 compaction 策略。
