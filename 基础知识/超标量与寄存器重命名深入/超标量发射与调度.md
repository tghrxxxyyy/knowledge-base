# 超标量发射与调度

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》超标量与指令级并行章（第 3 章）与 CSAPP 第 4 章。

## 一、背景与挑战
经典流水线每周期取指、发射、完成一条指令，IPC 上限为 1。超标量（superscalar）每周期取指并「发射」多条指令到多个功能单元，以提升指令级并行（ILP）。核心难题是：在依赖图约束与资源限制下，「每周期选哪些就绪指令并行发射」，既要填满分功能单元，又不能违反数据/结构相关。

ILP 受多种因素限制：真相关数据（RAW）、控制相关（分支）、资源相关（FU/端口）、前端供给（取指/译码带宽）。超标量的艺术在于用动态调度最大化可并行发射的指令数，同时不破坏程序语义。

「超标量」与「超长指令字（VLIW）」常被混淆：前者由硬件在运行时决定并行发射哪几条，二进制兼容性好；后者由编译器在静态把并行指令打包成「长指令」，硬件只负责发射，硬件简单但需重新编译且难处理运行时不确定性（如 cache miss）。两种路线在历史上都出现过，最终主流选择了超标量 + 动态调度。

## 二、核心原理
取指后指令经译码、寄存器重命名、分发（dispatch）到发射队列/保留站，由调度器每周期选多条就绪指令发射到不同功能单元。按调度时机分：顺序发射（in-order issue，按程序序取，但可乱序完成）与乱序完成（out-of-order completion，经 Tomasulo/ROB）。现代处理器普遍「顺序取指、乱序执行、顺序提交」。发射宽度（每周期可发射数）、重命名宽度、提交宽度三者可不同，分别受前端、重命名、ROB 约束。

注意「发射」与「完成」分离：指令可按序发射、乱序完成，但最终提交（retire）仍按程序序，从而保证精确异常。宽发射若前端供不上指令（如 bad 分支预测导致取指空泡），IPC 仍上不去。

三个宽度的实际约束来源值得展开：取指宽度受 I-cache 行大小与分支预测的重定向能力限制；重命名宽度受映射表读写端口数（每周期需读取多条指令的源、写入多个目标映射）限制；提交宽度受 ROB 读端口与 ARF 写端口限制。设计时通常让三者相等（如 6 宽），但也可以不等（如取指 8、重命名 6、提交 6），此时瓶颈在最窄的一环。

## 三、形式化与数学基础
理想 IPC 受数据相关、资源与前端供给共同约束：
$$IPC \le \min\left(W,\; \frac{ILP_{avail}}{1 + DepStall},\; FrontendWidth\right)$$
其中 $W$ 为发射宽度，$ILP_{avail}$ 为平均指令级并行度，$DepStall$ 为相关停顿。关键路径长度决定延迟下界；宽发射若无足够 ILP 或前端供给不足，IPC 仍上不去。Amdahl 式瓶颈：最窄段决定整体。更精细的模型把控制相关（分支误预测率 × 流水线深度）也计入 DepStall。

把控制相关显式写进模型：设分支占比为 $f_b$、误预测率为 $m$、惩罚为 $P$ 个周期，则平均每指令的停顿为 $f_b \cdot m \cdot P$，于是

$$IPC \le \frac{1}{1 + DepStall_{data} + f_b \cdot m \cdot P}$$

这解释了为何「分支预测精度」在现代宽发射处理器中如此关键：当 $W = 6$、$P = 20$、$f_b = 0.2$ 时，把 $m$ 从 2% 降到 1%，可显著改变 IPC 上界。

## 四、代码实现
```c
// 每周期从就绪队列选最多 W 条发射
int schedule(inst_t queue[], int n, int W, int used_fu[], int NFU) {
    int issued = 0;
    for (int i = 0; i < n && issued < W; i++) {
        if (queue[i].ready && !used_fu[queue[i].fu]) {
            dispatch(queue[i]);
            used_fu[queue[i].fu] = 1;   // 占用 FU 端口
            issued++;
        }
    }
    return issued;   // 本周期实际发射数
}
// 顺序提交（retire）与乱序执行解耦，保证精确异常
void retire(rob_t rob[], int *head) {
    while (rob[*head].done && !rob[*head].exc) {
        commit(rob[*head].dst, rob[*head].phys);
        (*head)++;
    }
}
```

发射宽度与 FU 数量、端口数的联动：

```c
/* 每周期发射数受三者共同限制：发射宽度 W、FU 总数 NFU、每 FU 发射槽数 */
int effective_width(int W, int NFU, int slots_per_fu) {
    int alu_capacity = NFU * slots_per_fu;    // 结构相关的硬上限
    return (W < alu_capacity) ? W : alu_capacity;
}
```

## 五、与其他技术对比
| 维度 | 顺序发射 | 乱序调度(Tomasulo) | VLIW | SMT |
| --- | --- | --- | --- | --- |
| 调度者 | 硬件 | 硬件 | 编译器 | 硬件+线程 |
| 长延迟阻塞 | 易阻塞后续 | 可越过 | 需编译器填充 | 切换线程填 |
| 硬件复杂度 | 低 | 高 | 低 | 高 |
| 兼容性 | 好 | 好 | 绑定 ISA | 好 |
| 应对运行时不确定 | 差 | 好 | 差（依赖静态假设） | 好 |
| 资源利用率来源 | 指令窗口 | 指令窗口 | 编译器排布 | 多线程填充 |

SMT 与超标量的关系是「互补」：超标量从单线程中挖掘 ILP，若该线程本身 ILP 不足（如大量 cache miss），宽度再大也填不满；SMT 用另一线程的指令填补这些空隙，使功能单元利用率提升，代价是共享资源的竞争（ROB、IQ、cache）。

## 六、常见误区
1. 误以为宽发射直接高 IPC。受 ILP 与前端供给限制，宽发射若无并行指令则空转。
2. 误以为乱序=无序执行。仍按数据依赖图有序推进，仅完成顺序与程序序不同。
3. 混淆发射宽度/重命名宽度/提交宽度。三者受不同结构约束，可不相等。
4. 以为超标量能解决所有并行。内存级并行（MLP）、线程级并行（TLP）需另寻手段（cache/多核）。
5. 以为 VLIW 与超标量等价。VLIW 把调度责任交给编译器，对运行时变化（cache miss、分支）适应力差。
6. 忽略前端带宽。取指与分支预测能力不足时，后端再宽也无指令可发。
7. 以为加宽一定提升每瓦性能。功耗与面积随宽度超线性增长，收益递减，是「每瓦性能」的核心权衡。

## 八、面试题
1. 发射宽度 vs 重命名宽度 vs 提交宽度差异？
   要点：分别受取指/重命名/ROB 约束，可不同，瓶颈在最窄者。
2. 为何乱序执行仍需顺序提交？
   要点：保证精确异常与内存语义，仅「执行」乱序、「提交」按序。
3. ILP 受哪些限制？
   要点：真相关数据、控制相关（分支）、资源相关、前端供给。
4. 为什么单核宽发射有上限？
   要点：ILP 有限、内存延迟主导，继续加宽收益递减，转向多核/SMT。
5. SMT 与超标量解决的是同一个问题吗？
   要点：不是，超标量挖掘单线程 ILP，SMT 用多线程填充 ILP 空隙，二者互补。
6. 为什么分支预测精度对宽发射尤其重要？
   要点：误预测惩罚乘以宽度，宽度越大每次误预测丢弃的指令越多。

## 九、演进与趋势
宽发射（4–8 宽）配合 SMT、大 ROB、深流水线；受功耗/面积约束转向「每瓦性能」；前端分支预测精度成为 IPC 关键；多核取代无限宽发射成为主要并行手段。现代 CPU 在「宽发射 + 深乱序窗口 + 大 ROB」三方面协同提升单线程性能。

近年的一个新方向是「异构宽度」：把发射资源按指令类型差异化配置（如更多的访存端口、较少的除法单元），以匹配真实负载的混合比例，避免「均匀加宽」带来的浪费。

## 十、小结
发射与调度是超标量发挥 ILP 的核心：乱序调度通过动态相关性解析，在依赖与资源约束下尽量填满功能单元。IPC 受最窄瓶颈限制，宽发射需配合充足 ILP 与前端供给才有效，且与顺序提交共同保证正确性。理解「三个宽度、四个限制、一个最窄瓶颈」这一框架，就能系统地分析任何一条流水线的性能天花板。
