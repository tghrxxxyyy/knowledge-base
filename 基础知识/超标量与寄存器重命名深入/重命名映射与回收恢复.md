# 重命名映射与回收恢复

> 对应 Hennessy & Patterson 量化方法推测恢复章。

## 一、背景与挑战
分支误预测或异常时需撤销推测执行，恢复寄存器映射与 FreeList。若恢复慢，误预测惩罚增大；若映射表被错误覆盖，将导致数据损坏。

## 二、核心原理
常用三种恢复：1）检查点（分支时快照映射表）；2）未来文件（按序提交时逐步建立可恢复态）；3）回收（提交时把旧物理寄存器归还 FreeList）。误预测时以最近检查点恢复 map 与 free list。

## 三、形式化与数学基础
恢复延迟由检查点深度决定。设分支在 ROB 位置 $k$，检查点每 $c$ 条建一个，最坏恢复：
$$RecoverDelay \le c \times IssueWidth$$
FreeList 必须包含"未提交指令占用的物理寄存器"以外全部空闲项。

## 四、代码实现
```c
// 分支时打检查点
void checkpoint() {
    save_map[cp_idx] = copy_map(map);     // 映射表快照
    save_free[cp_idx] = copy_free(free_list);
    cp_idx = (cp_idx+1) % NCP;
}
void recover(int cp) {
    map = save_map[cp];                    // 恢复映射
    free_list = save_free[cp]; fp = ...;   // 恢复自由表
    // FreeList 包含所有推测分配的物理寄存器
}
```

## 五、与其他技术对比
检查点恢复快但占存储（多份映射）；未来文件省存储但恢复慢；现代多用检查点 + 提交回收混合。

## 六、常见误区
误以为提交才回收物理寄存器：是，但误预测需整体回退。误以为 FreeList 含已分配项：仅空闲项在内。

## 七、与开源书/权威来源对应
量化方法寄存器重命名恢复；CSAPP 控制流恢复类比。

## 八、面试题
问：为何误预测要同时恢复 map 和 FreeList？答：二者须一致，否则物理寄存器泄漏或误用。

## 九、演进与趋势
影子映射、混合检查点（如仅关键分支）减少存储。

## 十、小结
映射与回收是推测执行的"撤销机制"，其效率直接影响误预测惩罚，是乱序处理器鲁棒性的核心。
