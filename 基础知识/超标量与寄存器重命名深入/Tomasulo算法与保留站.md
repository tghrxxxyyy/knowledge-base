# Tomasulo算法与保留站

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》Tomasulo 算法章（源自 IBM 360/91）与 CSAPP 第 4 章。

## 一、背景与挑战
经典顺序流水线中，一条长延迟指令（如浮点除法）会阻塞后续无关指令，吞吐骤降。Tomasulo 算法（1967 年用于 IBM 360/91）通过「保留站（Reservation Station, RS）+ 公共数据总线（CDB）结果广播」实现动态调度：操作数一旦就绪就能越过阻塞指令执行，且隐式完成寄存器重命名，消除 WAW/WAR 伪相关。它是现代乱序执行的原型。

在 360/91 上，浮点单元远慢于定点，若顺序执行，浮点长延迟会拖垮整条流水线。Tomasulo 的核心洞察是：让后续无关指令「提前走」，只等它们真正需要的操作数，而不必等前面的慢指令整体完成——这就是「数据流驱动」的执行。

与传统记分牌（Scoreboarding）相比，Tomasulo 的另一大贡献是「分布式控制」：每个功能单元只需观察 CDB 上的标签，无需中央控制器统一裁决所有相关，缓解了集中式控制的复杂度与延迟。这一「广播-捕获」范式至今仍是乱序处理器唤醒机制的基础。

## 二、核心原理
每个功能单元配一组保留站。指令译码后落入 RS，若源操作数已就绪则存值，否则记录「该操作数将来自哪个 RS/物理寄存器（标签 tag）」。结果算完经 CDB 广播，所有等待该 tag 的 RS 项捕获值并标记就绪。这样：
- 长延迟指令不阻塞后续无关指令（它们绑定标签继续等）。
- 多条写同一架构寄存器的指令写到不同 RS，天然重命名。
当 RS 项所有源就绪且功能单元空闲，即可发射执行。CDB 是结果传播的枢纽，每周期广播一个结果，所有等待者同时被唤醒。

需要强调「寄存器状态的记录」：Tomasulo 为每个架构寄存器保存一个 tag（Qi），表示「哪个 RS 将产生它的最新值」；若 tag 为空则表示寄存器文件中的值有效。当指令发射时，它读取寄存器的 tag；结果广播时清空对应 tag 并写入值。这套「寄存器 + tag」的记录方式正是重命名映射表（RAT）的雏形。

RS 中的「操作数捕获」有两种风格：早期捕获（在广播时把值搬进 RS 项）与后期捕获（只记 tag，执行前再从寄存器文件读）。前者缩短关键路径但需要更多存储，后者省面积但增加发射前的读延迟。现代实现通常在两者间取舍。

## 三、形式化与数学基础
设指令 $i$ 依赖 $j$，当 $j$ 经 CDB 产生结果 $R_j$、标签为 $tag(j)$ 时：
$$tag(i, src) == tag(j) \implies val_{i,src} \leftarrow R_j,\; ready_i \leftarrow ready_i \lor true$$
发射条件：所有源操作数 ready（已捕获值）或已绑定将到来的标签。CDB 每周期仅能广播一个结果，故「CDB 带宽」成为唤醒上限——多结果需多 CDB 或分拍。RS 容量限制可同时驻留的推测指令数。隐式重命名的正确性：每条写指令的 tag 唯一，等待者只认自己依赖的 tag，因此 WAW/WAR 被天然消解（旧值被新 tag 覆盖，读旧值的指令早已绑定旧 tag）。

CDB 带宽的形式化影响：设每周期可广播 $b$ 个结果、平均每周期完成 $c$ 条指令，则必须 $b \ge c$ 才能保证唤醒不成为瓶颈。若功能单元能每周期完成 4 条指令但 CDB 只能广播 1 个结果，则实际完成速率被压到 1 条/周期。这正是早期 Tomasulo 实现对多 CDB 的强烈需求的来源。

RS 容量与可发掘 ILP 的关系：RS 项数 $R$ 决定了「多少条已译码但未执行的指令可以驻留」，因此可发掘的并行度上限受 $R$ 与 ROB 窗口的共同约束（在无 ROB 的原始 Tomasulo 中则由 RS 与寄存器 tag 唯一性约束）。

## 四、代码实现
```c
// 保留站条目与 CDB 广播唤醒
struct rs { int op; int tag1, tag2; int val1, val2; int rdy1, rdy2; int dst; };
struct rs RS[NR];

void cdb_broadcast(int tag, int result) {
    for (int i = 0; i < NR; i++) {          // 唤醒所有等待者
        if (!RS[i].rdy1 && RS[i].tag1 == tag) { RS[i].val1 = result; RS[i].rdy1 = 1; }
        if (!RS[i].rdy2 && RS[i].tag2 == tag) { RS[i].val2 = result; RS[i].rdy2 = 1; }
    }
}
int issue_ready(int i) {
    return RS[i].rdy1 && RS[i].rdy2;        // 两源就绪即可发射
}
```

配套的寄存器 tag 记录（记录「谁将写这个架构寄存器」）：

```c
int Qi[NARCH];    // 架构寄存器 -> 将写它的 RS 编号，0 表示寄存器文件值有效

void issue(int rs_idx, int dst_arch, int src1_arch, int src2_arch) {
    struct rs *r = &RS[rs_idx];
    r->tag1 = Qi[src1_arch];                    // 源操作数要么来自寄存器文件
    r->rdy1 = (r->tag1 == 0);                   // 要么等某个 RS 的 tag
    r->tag2 = Qi[src2_arch];
    r->rdy2 = (r->tag2 == 0);
    Qi[dst_arch] = rs_idx + 1;                  // 登记：本 RS 将产生该寄存器新值
    r->dst = dst_arch;
}
```

## 五、与其他技术对比
| 维度 | Scoreboarding | Tomasulo | 现代 PRF 调度 | 顺序流水线 |
| --- | --- | --- | --- | --- |
| 隐式重命名 | 否 | 是 | 是 | 否 |
| WAW/WAR | 仍阻塞 | 消除 | 消除 | 阻塞 |
| 操作数存储 | 寄存器/RS | RS 内嵌 | 集中 PRF | 寄存器 |
| 唤醒 | 集中 | CDB 广播 | CDB/唤醒网络 | 无 |
| 控制方式 | 集中式 | 分布式 | 分布式 | 集中式 |
| 推测支持 | 无 | 有限（需扩展） | 完整（ROB） | 无 |

Scoreboarding（CDC 6600）不重命名，存在 WAW/WAR 假相关；Tomasulo 用 RS 标签隐式重命名消除之。现代把 RS 与 PRF 结合演化为统一调度器。

需要指出 Tomasulo 的两点局限：一是原始算法没有 ROB，因此无法做精确异常与推测执行（分支预测后无法干净回滚）；二是结果必须经 CDB 广播，带宽受限。现代处理器用「ROB + PRF + 统一发射队列」补齐这两点，同时保留标签广播唤醒的思想。

## 六、常见误区
1. 误以为 Tomasulo 等于乱序提交。它只保证乱序执行与乱序完成，提交仍按序（经 ROB）才对外可见。
2. 误以为 RS 无限。容量限制每周期可驻留/发射的指令数，满则 stall 分发。
3. 忽略 CDB 瓶颈。每周期仅广播一个结果，多结果需多 CDB，否则唤醒受限。
4. 以为 Tomasulo 已过时。其思想（标签 + 广播唤醒）仍是现代乱序核心，只是实现从 RS 内嵌变为 PRF + 统一队列。
5. 以为 Tomasulo 自带分支预测与精确异常。原始算法没有，需额外的 ROB 与检查点机制。
6. 误以为「发射」等于「执行完成」。发射只表示派发到功能单元，完成时间取决于功能单元延迟。
7. 以为 RS 越多越好。RS 增大使广播比较逻辑功耗近似平方增长，且唤醒延迟上升（需更长的比较链）。

## 八、面试题
1. CDB 为何是瓶颈？如何缓解？
   要点：每周期仅广播一个结果；多用 CDB/分拍、增加唤醒带宽。
2. Tomasulo 如何隐式重命名？
   要点：写同一架构寄存器的指令分配到不同 RS，靠标签区分，消除 WAW/WAR。
3. 为何 Tomasulo 不等于乱序提交？
   要点：它只乱序执行/完成，提交顺序由 ROB 保证按序。
4. Tomasulo 与 Scoreboarding 的根本区别？
   要点：Tomasulo 隐式重命名（标签），Scoreboarding 不重命名，故 WAW/WAR 仍阻塞。
5. 原始 Tomasulo 缺少什么才能支持精确异常？
   要点：缺少按序提交结构（ROB）；结果直接写寄存器/内存会破坏精确异常所需的「异常点前后一致」。
6. 寄存器 tag（Qi）在算法中起什么作用？
   要点：记录「哪个 RS 将写该架构寄存器」，使后续指令能正确绑定待捕获的标签。

## 九、演进与趋势
物理寄存器堆 + 统一调度队列（Intel P6 之后）取代分离保留站，降低唤醒延迟与面积；非阻塞 wakeup、数据捕获（data capture）减少广播；Tomasulo 思想沉淀为现代乱序核心的调度基础。今天的处理器虽不再用「分离 RS + 内嵌操作数」，但标签广播唤醒仍是核心机制。

进一步的方向包括：把唤醒网络做成「推测唤醒」（speculative wakeup，提前一拍唤醒以缩短关键路径，若预测失败则重放）、按功能单元聚类以降低广播范围，以及用机器学习预测关键性以改进选择策略。

## 十、小结
Tomasulo 用保留站与标签广播实现动态调度，让无关指令越过阻塞继续执行，并隐式完成寄存器重命名，是乱序执行与寄存器重命名的理论原型。现代处理器在其思想上演化为 PRF + 统一调度队列的高效实现，CDB 唤醒机制沿用到今。理解「标签广播 + 操作数捕获」这一对机制，就理解了乱序执行调度的核心。
