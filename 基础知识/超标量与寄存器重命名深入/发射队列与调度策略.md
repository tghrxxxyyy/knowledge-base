# 发射队列与调度策略

> 对应 Hennessy & Patterson 量化方法调度器实现章。

## 一、背景与挑战
保留站/发射队列（Issue Queue, IQ）存放已重命名、待发射指令。调度策略决定"每周期选哪些就绪指令"，直接影响关键路径延迟与功能单元利用率。

## 二、核心原理
集中式 IQ 统一存放所有类型指令，醒来（wakeup）后参与选择；分布式按功能单元分区。选择算法分年龄优先（oldest-first，保公平/低延迟）与关键性优先（criticality）。

## 三、形式化与数学基础
年龄优先让最老就绪指令先发射，偏向降低尾部延迟；设指令年龄 $a_i$，选择：
$$\arg\min_i a_i \quad \text{s.t. } ready_i,\; FU_i \text{ free}$$
每周期选至多 $W$ 条，平局随机或按 PC。

## 四、代码实现
```c
// 年龄优先选择 W 条就绪指令
int select_issue(inst_t iq[], int n, int W, int *used_fu, int NFU) {
    int cnt=0;
    // 按入队序号(age)升序遍历
    for (int age=0; age<n && cnt<W; age++) {
        int i = order_by_age[age];
        if (iq[i].ready && !used_fu[iq[i].fu]) {
            dispatch(iq[i]); used_fu[iq[i].fu]=1; cnt++;
        }
    }
    return cnt;
}
```

## 五、与其他技术对比
集中 IQ 唤醒逻辑复杂但调度灵活；分布 IQ 低功耗但可能负载不均。年龄优先简单，关键性优先更优但需预测。

## 六、常见误区
误以为发射队列越大越好：唤醒功耗平方增长。误以为就绪即可立即发射：受 FU 与端口限制。

## 七、与开源书/权威来源对应
量化方法调度器结构；各厂商微架构分析（AnandTech/厂商手册）。

## 八、面试题
问：wakeup 与 select 为何分两阶段？答：先广播结果唤醒，再按策略选择发射。

## 九、演进与趋势
分区/聚类 IQ 降低功耗，非阻塞 wakeup 缩短关键路径。

## 十、小结
发射队列是乱序执行的"调度中枢"，其结构与策略在功耗、面积与 ILP 间精细平衡。
