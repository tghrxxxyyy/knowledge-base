# 发射队列与调度策略

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》超标量与乱序执行调度器章（第 3 章）与 Intel/ARM 微架构手册。

## 一、背景与挑战
发射队列（Issue Queue, IQ，亦称保留站/调度器）存放已译码、已重命名、等待操作数就绪的指令。每周期「选哪些就绪指令发射到功能单元」由调度策略决定，直接决定关键路径延迟与功能单元利用率。调度过保守会浪费 ILP，过激进会引发唤醒风暴与功耗爆炸。现代宽发射（4–8 宽）处理器的 IQ 结构与策略在面积、功耗与性能间精细权衡。

IQ 是乱序执行流水线的「调度中枢」：它位于重命名之后、功能单元之前，既要记录每条指令的源操作数状态（就绪/等待哪个标签），又要在每周期从众多就绪指令中选出最能提升吞吐的一组发射。其设计好坏直接反映在 IPC 上。

IQ 与 ROB 是两个不同职责的结构：ROB 管「提交顺序与异常精确」，IQ 管「执行时机与资源分配」。一条指令在 IQ 中等待就绪、发射、执行完成后写回 ROB；提交由 ROB 决定。二者分离使「乱序执行」与「按序提交」互不干扰。

## 二、核心原理
IQ 分两类：集中式（unified）统一存放所有类型指令，唤醒后统一选择；分布式（clustered）按功能单元类型分多个小队列，唤醒/选择局部化、低功耗但可能负载不均。调度时机分两阶段：wakeup（结果算完经旁路/CDB 广播，标记依赖者就绪）与 select（按策略选出最多 W 条发往空闲功能单元）。选择策略分年龄优先（oldest-first，降低尾部延迟、保公平）与关键性优先（criticality-aware，优先关键路径指令）。

集中式 IQ 唤醒逻辑复杂（每结果广播需比对所有项），但调度最灵活；分布式 IQ 每队列只比对自己类型，功耗低但某个类型突发时其他队列空闲也用不上，需跨队列迁移或接受不均。

「推测唤醒（speculative wakeup）」是现代 IQ 的常见优化：为缩短关键路径，调度器在结果尚未产生时就提前一拍唤醒依赖者（基于「多数指令会按时完成」的假设）；若假设落空，则需重放（replay）这些被错误唤醒的指令。它以少量重放代价换取了关键路径缩短，是「面积/功耗换性能」的典型。

## 三、形式化与数学基础
年龄优先：设指令年龄 $a_i$（入队序越小越老），每周期选至多 $W$ 条满足就绪且功能单元空闲的指令：
$$\arg\min_{i} a_i \quad \text{s.t. } ready_i=1,\; FU_i \text{ free},\; \text{count} < W$$
关键性优先则最大化「对关键路径延迟的削减」：
$$\max_i \text{criticality}(i) \quad \text{受同样约束}$$
年龄优先偏向公平与低尾延迟，关键性优先理论上 IPC 更高但需在线预测关键性，硬件复杂。一个折中是「年龄+关键性混合」：在年龄窗口内优先关键指令，兼顾公平。调度的影响可用 IPC 模型刻画：$IPC \le \min(W, ILP_{avail}/(1+DepStall))$。

IQ 的功耗模型是其容量的决定性约束：唤醒阶段每条结果需与 IQ 中所有项比较标签，比较次数约 $N_{result} \times N_{IQ}$，功耗随 IQ 容量近似线性增长（若同时增加结果数则近平方）。因此「IQ 越大越好」在功耗上是错误的，现代设计普遍控制在几十项量级，并用分区来限制广播范围。

选择逻辑（select）的关键路径也是设计难点：从 $N$ 项中选出最老的 $W$ 条，若用朴素的优先级编码器，延迟随 $N$ 增长。常见优化是把 IQ 分成若干 bank，每 bank 独立选出候选再合并，用并行度换延迟。

## 四、代码实现
```c
// 年龄优先选择：每周期最多 W 条就绪指令
int select_issue(inst_t iq[], int n, int W, int used_fu[], int NFU) {
    int cnt = 0;
    for (int age = 0; age < n && cnt < W; age++) {
        int i = order_by_age[age];           // 按入队序升序
        if (iq[i].ready && !used_fu[iq[i].fu]) {
            dispatch(iq[i]);
            used_fu[iq[i].fu] = 1;           // 占用该 FU 端口
            cnt++;
        }
    }
    return cnt;
}
// 唤醒阶段：结果广播后标记依赖者就绪（伪代码）
void wakeup(int tag, int result) {
    for (int i = 0; i < n; i++)
        if (iq[i].wait_tag == tag) { iq[i].val = result; iq[i].ready = 1; }
}
```

分区（clustered）IQ 的跨队列分发策略：

```c
/* 按 FU 类型分派到不同 IQ，降低唤醒广播范围 */
void dispatch_to_iq(inst_t *ins) {
    switch (ins->fu_type) {
    case FU_ALU:  iq_alu_insert(ins);  break;   // 算术队列
    case FU_MEM:  iq_mem_insert(ins);  break;   // 访存队列
    case FU_FPU:  iq_fpu_insert(ins);  break;   // 浮点队列
    default:      iq_unified_insert(ins); break;
    }
}
```

## 六、常见误区
1. 以为 IQ 越大越好。IQ 容量增大，唤醒比较逻辑（每结果广播需比对所有项）功耗近似平方增长，且唤醒延迟上升。
2. 以为就绪即能立即发射。还受功能单元端口数（每周期每 FU 有限发射槽）与总线竞争约束。
3. 混淆 wakeup 与 select。二者分两阶段：先广播结果唤醒依赖者，再按策略选择发射。
4. 以为关键性优先总是赢。错误的关键性预测会适得其反，且硬件成本不低。
5. 以为推测唤醒是免费的。它需要重放机制兜底，重放率过高时会反噬性能。
6. 以为 IQ 与 ROB 是同一个结构。二者职责不同：IQ 管执行时机，ROB 管提交顺序。
7. 忽略「选择逻辑本身」的关键路径。select 若延迟过长，会直接限制每周期可发射数。

## 八、面试题
1. wakeup 与 select 为何分两阶段？
   要点：先广播结果唤醒所有依赖者并标记就绪，再按策略选择发射，解耦「数据就绪」与「资源分配」。
2. 集中式与分布式 IQ 的取舍？
   要点：集中式灵活但唤醒功耗高；分布式低功耗但负载可能不均。
3. 年龄优先为何降低尾延迟？
   要点：最老就绪指令优先，避免老指令被新指令饿死，降低长尾。
4. 关键性优先的难点？
   要点：需在线、低开销地预测每条指令对关键路径的贡献，预测错则收益归零甚至变负。
5. 为什么 IQ 容量不能无限增大？
   要点：唤醒比较与功耗随容量增长，且唤醒延迟上升会拖慢关键路径。
6. 推测唤醒的代价是什么？
   要点：若预测失败需重放指令，重放率过高时收益被抵消。

## 九、演进与趋势
分区/聚类 IQ 降低功耗；非阻塞 wakeup 缩短关键路径；物理寄存器堆 + 统一调度队列取代分离保留站；数据预唤醒（data capture）减少唤醒延迟；机器学习预测关键性正在研究中。新一代 CPU（如 Apple M 系列、Intel Golden Cove）采用大 IQ + 混合关键性调度。

近年的另一方向是「IQ 与 ROB 的协同设计」：把发射与提交的元数据部分共享，减少冗余存储；以及「按负载动态分区」——根据指令流的类型分布动态调整各分区大小，以缓解静态分区导致的负载不均。

## 十、小结
发射队列是乱序执行的「调度中枢」：wakeup 标记数据就绪、select 按策略分配功能单元。其结构（集中/分布）与策略（年龄/关键性）在功耗、面积与 ILP 之间精细平衡，是宽发射处理器性能的核心，也是微架构差异的主要来源。理解「两阶段、两类结构、两类策略、一个功耗约束」，就能系统地评估任何一款乱序处理器的调度能力。
