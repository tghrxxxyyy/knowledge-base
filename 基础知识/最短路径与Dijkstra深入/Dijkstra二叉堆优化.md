# Dijkstra二叉堆优化

> 对应 Cormen 等《CLRS》第 24.3 节（Dijkstra 的二叉堆实现）与 Sedgewick《Algorithms》。

## 一、背景与挑战
朴素 Dijkstra 用线性扫描选最小，复杂度 $O(V^2)$，在稀疏图（$E \ll V^2$）下浪费大量时间。用最小堆（优先队列）把「取最小 dist」从 $O(V)$ 降到 $O(\log V)$，整体复杂度变为 $O((V+E)\log V)$，是工程中的标准实现。关键工程细节是「懒删除」处理距离更新，避免二叉堆上低效的 decrease-key。

稀疏图在现实中最常见（社交网络、路网、依赖图），所以堆优化版才是「日常版本」。理解它不仅要会写，还要理解「为何懒删除正确」「为何弹出要比较」这些易错点。

另一个工程视角是常数因素：二叉堆的 `log V` 虽小，但每次操作都有数组比较与交换，实际常数远大于理论。因此在 $V$ 只有几百的稠密图上，$O(V^2)$ 的线性扫描反而更快——「复杂度更优」不等于「跑得更快」，这在小规模数据上是必须实测的经验。

## 二、核心原理
堆中存放 $(dist[u], u)$。每轮弹出 dist 最小的顶点：若弹出的 dist 大于当前已知 dist[u]，说明是过期副本，跳过；否则处理它并松弛邻居。松弛成功（找到更短路径）就把 $(new\_dist, v)$ 压入堆，而非修改旧项。如此每个更优距离各生成一个堆项，过期项无害保留直到被弹出跳过。

这套机制与朴素版等价：朴素版「选最小未确定点」对应堆版「弹最小且非过期」，二者都保证每次处理的是当前全局最优未确定点。

需要注意「确定」的语义在堆版中不再依赖显式的 `done` 数组：一个顶点可能被弹出多次，但只有第一次（dist 最小且未被跳过）的处理是「确定」的，后续弹出都会因 `d > dist[u]` 被跳过。因此若需要 `done` 语义（例如输出最短路树），应以「首次成功弹出」为准，而不需要额外数组。

## 三、形式化与数学基础
每点最多入堆「出度」次，每次堆操作 $O(\log V)$：
$$T = O((V+E)\log V) = O(E\log V)\quad (\text{稀疏图 } E \ge V)$$
相比朴素 $O(V^2)$，当 $E = o(V^2/\log V)$ 时堆优化更优。斐波那契堆理论界 $O(V\log V + E)$，但常数大、工程少用。正确性依赖「堆顶即当前全局最小未确定 dist」，与朴素版选最小等价。懒删除引入的过期项占用堆空间，但弹出时被跳过，不影响结果。

堆规模的精确界：每个顶点最多在其每条入边被成功松弛时入堆一次，故堆中元素总数不超过 $E + 1$（源点初始入堆 + 每条边最多一次）。因此空间复杂度 $O(E)$，而不是某些直觉认为的 $O(V^2)$。这也解释了为什么懒删除在工程上完全可接受。

更准确的时间界应写为 $O((V + E)\log E)$：堆操作次数为 $O(E)$，每次 $O(\log E)$。由于 $E \le V^2$，有 $\log E \le 2\log V$，故与 $O(E\log V)$ 同阶。在「优先队列」文档中给出更细的推导。

## 四、代码实现
```python
import heapq
# 二叉堆优化 Dijkstra，O((V+E) log V)
def dijkstra_heap(graph, src):
    n = len(graph)
    dist = [float("inf")] * n
    dist[src] = 0
    pq = [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue                  # 跳过过期副本
        for v, w in graph[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                heapq.heappush(pq, (dist[v], v))
    return dist
```

若需要输出路径，只需额外维护前驱数组并在成功松弛时更新：

```python
def dijkstra_with_path(graph, src, dst):
    n = len(graph)
    dist = [float("inf")] * n
    prev = [-1] * n
    dist[src] = 0
    pq = [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue
        for v, w in graph[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                prev[v] = u           # 记录前驱，用于回溯路径
                heapq.heappush(pq, (dist[v], v))
    path, cur = [], dst
    while cur != -1:
        path.append(cur)
        cur = prev[cur]
    return dist[dst], path[::-1]
```

## 五、与其他技术对比
| 维度 | 朴素 $O(V^2)$ | 堆优化 $O(E\log V)$ | SPFA | Dial 桶 |
| --- | --- | --- | --- | --- |
| 适合图 | 稠密 | 稀疏 | 稀疏（无负权） | 整数权 |
| 稳定性 | 确定 | 确定 | 最坏 $O(VE)$ | 确定 $O(V+E)$ |
| 负权 | 否 | 否 | 否（需非负） | 否 |
| 额外空间 | $O(V)$ | $O(E)$（堆） | $O(V)$ 队列 | $O(W + V)$ |
| 是否需 decrease-key | 否 | 否（懒删除） | 否 | 否 |

Dial 桶队列利用「整数权 + 距离有界」把堆换成环形桶数组，达到 $O(V+E)$，是理论最优的实践版本；它的前提是最大边权 $W$ 与图规模相比不大，否则桶数过多反而浪费空间。

## 六、常见误区
1. 未用 `d > dist[u]` 跳过过期项。重复处理同一顶点，结果可能错、效率下降。
2. 负权图用 Dijkstra。负权破坏「弹出即确定」，堆优化同样失效。
3. 误以为堆越大越慢不可接受。懒删除使堆至多 $O(E)$ 项，仍在 $O(E\log V)$ 界内。
4. 在稠密图上用堆优化反而更慢。当 $E \approx V^2$ 时 $O(V^2\log V) > O(V^2)$，应退回朴素版。
5. 以为提前 break 一定安全。只有在「单目标」且「dist 非负」时，首次弹出目标才能 break；若要求全源结果则不行。
6. 以为 `(dist, node)` 元组的比较在任意语言中都可直接使用。在 Python 中若 dist 相同会比较 node，必须是可比较类型，否则报错。
7. 混淆「入堆次数」与「入堆顶点数」。同一顶点可入堆多次，这是懒删除的正常现象而非 bug。

## 八、面试题
1. 写出堆优化 Dijkstra；为何需要懒删除？
   要点：二叉堆无高效 decrease-key，压新副本 + 弹出跳过过期项更简。
2. 堆优化的复杂度？何时优于朴素？
   要点：$O((V+E)\log V)$；稀疏图 $E \ll V^2$ 时更优。
3. 为什么弹出时要比较 d 与 dist[u]？
   要点：堆中可能有多份同一顶点的旧副本，仅最新者有效。
4. 稠密图用堆优化会怎样？
   要点：$O(V^2\log V)$ 反劣于朴素 $O(V^2)$，应退回线性扫描。
5. 堆中最多有多少元素？
   要点：$O(E)$，因为每条边最多导致一次成功松弛入堆。
6. 单目标时能否提前结束？
   要点：可以，首次弹出目标且跳过过期项后即可 break，此时 dist 已最优（依赖非负权）。

## 九、演进与趋势
Dial 桶队列（整数权）达 $O(V+E)$；配对堆在路网表现佳；双向 Dijkstra 与 A* 结合启发进一步加速；Δ-stepping 实现并行化；这些都在「堆优化」基础上针对特定负载优化，堆优化是它们的共同起点。

工程上的另一趋势是「按需组合」：在路网这类地理图上用 A* + 地标（ALT）裁剪搜索空间，在通用图上退回堆优化 Dijkstra，在整数权图上用 Dial 桶，形成「同一算法族的多实现自动选择」策略。

## 十、小结
堆优化 Dijkstra 用最小堆取最近点、以懒删除处理距离更新，稀疏图复杂度 $O((V+E)\log V)$，是标准最短路实现。它把朴素算法的瓶颈从「选最小」转移到「堆操作」，并保持了非负权下的正确性；稠密图则应回退到朴素版。记住「堆大小是 $O(E)$ 而非 $O(V^2)$」「弹出必须比较」，就掌握了这个实现的全部要害。
