# A星A*与Dijkstra关系

> 对应 Hart, Nilsson & Raphael 1968（A* 算法原始论文）与 CLRS 第 24 章（最短路径）及 Pearl《Heuristics》。

## 一、背景与挑战
Dijkstra 求单源到所有点的最短路，会盲目扩展大量远离目标的无关节点。但在「单源到单目标」场景下，我们并不需要全图最短路。A*（A-Star）在 Dijkstra 的优先队列键中加入启发函数 $h(n)$，把搜索引向目标方向，显著减少扩展节点数——它是可采纳（admissible）启发下的「最优且有向」搜索，是 Dijkstra 的目标导向推广。

典型场景是游戏寻路、地图导航、机器人规划：目标明确，全图最短路是浪费。A* 通过「向目标启发」把扩展节点数从 $O(E)$ 降到与最短路长度相关的量级，是这类问题的事实标准。

A* 的收益完全取决于启发函数的质量：$h$ 越接近真实剩余代价 $h^*$，扩展的节点越少、搜索越「直」。极端情况下若 $h = h^*$（完美启发），A* 只扩展最短路上的节点，复杂度退化为线性；若 $h = 0$，则完全没有方向信息，退化为 Dijkstra。因此「设计好的 $h$」是使用 A* 的核心技能，而非附属细节。

## 二、核心原理
A* 把每个待扩展节点的键值设为 $f(n) = g(n) + h(n)$：
- $g(n)$：从源到 n 的实际最短距离（由松弛维护）。
- $h(n)$：从 n 到目标的估计代价（启发）。
优先扩展 $f$ 最小的节点。取 $h(n) \equiv 0$ 时，$f=g$，A* 完全退化为 Dijkstra。若 $h$ 可采纳（对任意 n 有 $h(n) \le h^*(n)$，即不高估真实代价）且一致（consistent，满足三角不等式 $h(n) \le w(n,n') + h(n')$），则 A* 首次弹出目标时即得到最优路径。

关键区别：Dijkstra 用「已知代价 g」排序，A* 用「已知 + 估计」（g+h）排序。启发让搜索偏向目标，但前提是 $h$ 不能高估，否则会剪掉真正最优路径。

「一致」这一条件还带来一个实用性质：节点一旦被弹出（closed）就无需再重新打开，因为不可能有更短的路径被发现。这把「可能重访」的复杂性消除，使实现只需一个 closed 集合。若启发仅可采纳但不一致，A* 仍能求出最优解，但必须允许「重新打开」已关闭节点，实现更复杂、效率更低。

## 三、形式化与数学基础
Dijkstra 扩展所有满足 $f=g$ 的节点；A* 在一致启发下只扩展「必要」节点，扩展数不超过 Dijkstra：
$$\text{expand}(A^*) \le \text{expand}(\text{Dijkstra})$$
一致性的等价形式（边权非负）：
$$h(n) \le c(n,n') + h(n')$$
它保证首次从优先队列弹出某节点时其 $g$ 已是最优（无需重访），从而使 A* 兼具最优性与效率。若 $h$ 可采纳但非一致，A* 仍最优但可能需重访节点（需用 closed set 去重）；若 $h$ 不可采纳（被高估），最优性丧失但搜索更快（类似贪心最佳优先）。启发强度 $h$ 越接近 $h^*$，扩展越少。

一致性 ⇒ 可采纳性的证明思路：假设 $h$ 一致，沿最短路从 $n$ 到目标的每一步应用三角不等式链式相加，可得 $h(n) \le h^*(n)$。反之不成立——存在可采纳但不一致的启发（例如在某些非欧几里得图上人为构造）。

「最优效率」的刻画：在「只使用 $h$ 信息」的所有可采纳算法中，A* 扩展的节点数最少（Hart 等 1968 的定理）。这是 A* 被称为「最优算法」的另一层含义——不仅是结果最优，在给定启发下也是搜索效率最优。

## 四、代码实现
```python
import heapq
# A*：h 为启发函数，需可采纳且一致以保最优
def astar(graph, src, dst, h):
    pq = [(h(src), 0, src)]
    g = {src: 0}
    closed = set()
    while pq:
        f, cost, u = heapq.heappop(pq)
        if u == dst:
            return cost
        if u in closed:
            continue
        closed.add(u)
        for v, w in graph[u]:
            ng = cost + w
            if ng < g.get(v, float("inf")):
                g[v] = ng
                heapq.heappush(pq, (ng + h(v), ng, v))
    return float("inf")
```

## 五、与其他技术对比
| 维度 | Dijkstra | A* | 贪心最佳优先 | 双向 Dijkstra |
| --- | --- | --- | --- | --- |
| 键值 | $g$ | $g+h$ | $h$ | 双向 $g$ |
| 最优性 | 是 | 可采纳+一致时 | 否 | 是 |
| 扩展方向 | 盲目（全图） | 导向目标 | 强导向 | 双向导向 |
| 适用 | 单源全图 | 单源单目标 | 仅求快 | 单源单目标 |
| 最坏退化 | — | $h=0$ 时退化为 Dijkstra | 可能极差 | 仍为双向全图 |
| 内存 | $O(V)$ | $O(V)$（含 closed） | $O(V)$ | $O(V)$ |

贪心最佳优先只按 $h$ 排序，速度极快但可能给出很差的路径；A* 的 $g+h$ 兼顾已付代价与剩余估计，是「速度与最优」的折中。实践中常先跑「加权 A*」快速给出可行解，再按需精化。

## 六、常见误区
1. 用不可采纳的 $h$（高估）仍期望最优。高估会剪掉真正最优路径，最优性丢失。
2. 启发与移动模型不匹配。如四连通网格用欧氏距离会低估、八连通用曼哈顿会高估，需按模型选取。
3. 忽视 $h$ 的一致性。仅可采纳不足以保证不重访；一致性能保证首次弹出即最优、无需重算。
4. 以为 A* 比 Dijkstra 总是更快。最坏（h 恒为 0 或全图扩展）时 A* 退化为 Dijkstra，甚至因 closed set 略慢。
5. 忽略 closed set 的正确性前提。若 $h$ 非一致，关闭节点后可能错过更短路径，必须允许重开。
6. 混淆「最优解」与「最优效率」。A* 在给定可采纳启发下扩展节点最少，这是独立于结果最优性的另一个保证。
7. 忽略启发计算本身的代价。$h$ 若计算昂贵（如查表或复杂几何运算），可能抵消搜索节点减少带来的收益。

## 八、面试题
1. A* 何时保证最优？h=0 为什么等价于 Dijkstra？
   要点：h 可采纳且一致；h=0 时 f=g，退化为 Dijkstra。
2. 一致性（consistent）与可采纳（admissible）关系？
   要点：一致 ⇒ 可采纳；一致还能保证不重访、首次弹出即最优。
3. 为什么 A* 比 Dijkstra 扩展更少？
   要点：启发把扩展优先引向目标，远离目标的节点不被展开。
4. h 高估会怎样？
   要点：剪掉真正最优路径，丧失最优性，但搜索更快（退化为贪心）。
5. 为什么四连通网格不能用欧氏距离之外的高估启发？
   要点：欧氏距离是四连通最短距离的下界（可采纳），而曼哈顿距离在八连通下会高估代价。
6. 加权 A* 牺牲了什么、换来什么？
   要点：牺牲严格最优性，换来「解代价不超过最优的 $\varepsilon$ 倍」的有界次优与显著加速。

## 九、演进与趋势
双向 A*、ALT（landmarks + 三角不等式）在路网寻路大幅加速；D* / D* Lite 处理动态变权图（机器人重规划）；加权 A*（Weighted A*）用 $\varepsilon$ 放大 $h$ 换取「有界次优」的极速搜索；IDA* 用迭代加深节省内存，适合内存受限场景。

在工程实践中，「分层 + 地标」是路网寻路的主流组合：先用粗粒度层次图快速确定大致走廊，再在小范围内用 A* 精化；同时用少量地标预计算的距离作为启发上/下界，使启发更紧、扩展更少。

## 十、小结
A* 是带启发 $h$ 的 Dijkstra，$h=0$ 时完全等价；在可采纳且一致的启发下保证最优且扩展更少。它以「目标导向」把 Dijkstra 的盲目扩展变为有向搜索，是单目标最短路与寻路的核心算法，启发质量直接决定效率。理解「可采纳保结果最优、一致保实现高效」这对条件的区别，是正确使用 A* 的关键。
