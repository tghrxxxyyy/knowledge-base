# 代码审计静态与动态

> 对应 OWASP Source Code Review / CyC2018/CS-Notes / remzi-arpacidusse 安全代码。

## 一、背景与挑战
漏洞根源多在代码逻辑(越权、注入、整数溢出)。SAST 不运行即查模式，DAST/IAST 运行期观测，二者互补。

## 二、核心原理
SAST 解析 AST/数据流，匹配危险模式(拼接 SQL、未校验输入)；IAST 在运行时插桩采集真实调用链，降误报。人工审计聚焦鉴权、密码学使用、边界。

## 三、形式化与数学基础
污点分析：
$$ sink(reachable) \Leftarrow source \xrightarrow{no sanitize} sink $$
若污点从 source(用户输入)经无净化路径达 sink(SQL/命令)，则存在注入。

## 四、代码实现
```python
# 危险: 字符串拼接 SQL (SAST 会标记)
def get(uid):
    return db.query("SELECT * FROM u WHERE id=" + uid)  # 注入
# 安全: 参数化
def get_safe(uid):
    return db.execute("SELECT * FROM u WHERE id=?", (uid,))
```

## 五、与其他技术对比
SAST 早但误报多；DAST 真实但晚；IAST 结合二者。人工审计补逻辑(越权)漏洞。

## 六、常见误区
只依赖 SAST 工具忽略上下文误报。以为参数化万能(仍可能逻辑越权)。忽视依赖代码审计。
