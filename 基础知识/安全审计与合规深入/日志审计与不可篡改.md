# 日志审计与不可篡改

> 对应 OWASP Logging Cheat Sheet / Swiecki syzkaller fuzzing (github.com/google/syzkaller)。

## 一、背景与挑战
安全事件靠日志回溯，但攻击者常清日志掩盖踪迹。审计日志需完整、时序正确且防篡改，才能用于取证与合规。

## 二、核心原理
记录认证、授权、敏感操作等关键事件；用只追加(append-only)存储与哈希链(每条指向前条哈希)确保不可篡改；集中化(SIEM)便于关联与留存。

## 三、形式化与数学基础
哈希链：
$$ h_i = H(h_{i-1} \| entry_i) $$
篡改任一条 $e_k$ 会使 $h_k$ 及之后全部失配，检测概率≈100%。

## 四、代码实现
```python
# 简易哈希链日志追加
import hashlib
chain = [b"GENESIS"]
def append(entry: bytes):
    prev = chain[-1]
    h = hashlib.sha256(prev + b"|" + entry).digest()
    chain.append(h)
    return h   # 存储时一并保存 entry 与 h
```

## 五、与其他技术对比
本地日志易删；WORM 存储/区块链式链提供强保证。集中 SIEM 利于实时告警但需传输安全。

## 六、常见误区
记敏感明文(口令/令牌)违反合规。只记成功不记失败漏掉攻击。时钟不同步致时序错乱。

## 七、与开源书/权威来源对应
OWASP Logging Cheat Sheet；syzkaller 崩溃日志用于内核漏洞审计；常见合规要求留存。

## 八、面试题
哈希链为何防篡改？哪些事件必须记？为何不能记口令？

## 九、演进与趋势
eBPF 无侵入审计；机密日志(密文+可验证)；隐私保护审计。

## 十、小结
审计日志需覆盖关键事件、集中留存并以哈希链保证不可篡改，是合规与取证基础。
