# 事件响应与取证

> 对应 NIST SP 800-61（计算机安全事件处理指南）；RFC 3227（证据收集与归档指南）；ISO/IEC 27037；OWASP 事件响应指引。

## 一、背景与挑战
入侵一旦发生，响应速度与处置顺序直接决定损失规模：慢一步可能让攻击者完成横向移动与数据外带，错一步（例如直接在受感染主机上操作）会破坏证据、毁掉后续归因与追责的可能。安全事件响应的核心矛盾是**「尽快恢复」与「保全证据」之间的张力**——恢复常常意味着重启、重装、隔离，而这一切都会改变现场。

具体挑战包括：其一，**证据的易逝性**——内存中的进程、网络连接、临时密钥一旦断电即消失，必须按「易失性顺序」采集；其二，**证据链（chain of custody）**——从采集到分析每一步都要可追溯、可证明未被篡改，否则在法务或合规场景下不被采信；其三，**时间线重建**——多台主机、多个时区、多种时钟源，需要做时间同步校正才能还原真实因果；其四，**预案缺失**——没有预置的联系人、权限与工具，事发时只能临时救火。

## 二、核心原理
**NIST SP 800-61** 给出的生命周期是：准备（Preparation）→ 检测与分析（Detection & Analysis）→ 遏制、根除与恢复（Containment, Eradication & Recovery）→ 事后活动（Post-Incident Activity）。准备阶段决定上限：预置日志留存、端点检测能力、离线取证工具包、演练过的联络树与授权流程。检测与分析阶段要确认范围（哪些主机、哪些账号、哪些数据）并建立假设。

**取证的核心是「先保全、后分析、只在副本上作业」**。采集顺序遵循易失性从高到低：CPU 寄存器与缓存 → 内存 → 网络连接与路由表 → 运行进程 → 磁盘 → 备份与归档介质。每份证据在采集后立即计算哈希（如 SHA-256）并记录采集时间、采集人、工具版本与设备序列号，形成证据链条目。分析阶段常用时间线（timeline）方法，把文件系统 MAC 时间、日志事件、网络流记录统一到一条时间轴上，寻找「首次入侵点 → 提权 → 横向移动 → 数据外带」的链条。遏制策略则分短遏制（隔离主机、封禁 IP）与长遏制（分段网络、改凭据），需权衡「阻断攻击」与「暴露攻击者行为以收集情报」。**RFC 3227** 正是对「采什么、按什么顺序采、怎么记录」的规范建议。

## 三、形式化与数学基础
证据完整性的形式化要求：采集副本与原始介质在哈希下一致，
$$ H(\mathrm{evidence}_{acquired}) = H(\mathrm{original}) $$
一旦不成立，则该证据不可信（或被证明为采集过程引入的偏差）。证据链可建模为带签名的追加日志：第 $i$ 条记录 $e_i$ 的完整性由
$$ h_i = H(h_{i-1} \| e_i),\qquad h_0 = \mathrm{GENESIS} $$
保证，任一条被修改都会导致后续哈希全部失配。响应效率常用 MTTR 与 MTTD 度量：
$$ \mathrm{MTTR} = \frac{1}{n}\sum_{i=1}^{n}\big(t_{resolve}^{(i)} - t_{detect}^{(i)}\big),\qquad \mathrm{MTTD} = \frac{1}{n}\sum_{i=1}^{n}\big(t_{detect}^{(i)} - t_{occur}^{(i)}\big) $$
时间线重建需处理时钟漂移。设主机 $k$ 相对参考源的偏移为 $\delta_k$，则校正后的真实时间
$$ t_{true} = t_{local}^{(k)} - \delta_k $$
$\delta_k$ 可由 NTP 日志、相邻事件锚点或文件系统序列号推断。攻击者的「停留时间（dwell time）」可写成
$$ T_{dwell} = t_{containment} - t_{initial\_access} $$
缩短 $T_{dwell}$ 是响应能力的核心目标，而它直接受 MTTD 制约——看不见就遏制不了。

## 四、代码实现
按易失性顺序采集并保全证据（示意，实际应使用经校验的取证工具）：
```bash
# 1) 记录现场元信息，先固化「谁在何时对什么做了什么」
date -u; hostname; uname -a; whoami > acquisition_meta.txt
# 2) 采集易失数据：网络连接、路由、进程、登录会话
ss -antp > net_conn.txt; ip route > route.txt; ps auxww > ps.txt; last -F > last.txt
# 3) 内存镜像（工具与参数以官方文档为准），完成后立即哈希
#    dump 完成后：
sha256sum mem.dump > mem.dump.sha256
# 4) 磁盘镜像：只读挂载或块级镜像，绝不在原盘上分析
dd if=/dev/sdX of=disk.img bs=4M conv=noerror,sync status=progress
sha256sum disk.img > disk.img.sha256
# 5) 全程记录证据链：时间、操作人、命令、哈希
```

证据链记录与校验（示意）：
```python
import hashlib, json, time

def add_evidence(chain, path, operator, note):
    h = hashlib.sha256(open(path, "rb").read()).hexdigest()
    prev = chain[-1]["hash"] if chain else "GENESIS"
    entry = {"seq": len(chain) + 1, "path": path, "sha256": h,
             "prev": prev, "operator": operator, "note": note,
             "ts": time.strftime("%Y-%m-%dT%H:%M:%SZ", time.gmtime())}
    entry["hash"] = hashlib.sha256(json.dumps(entry, sort_keys=True).encode()).hexdigest()
    chain.append(entry)
    return entry
```

时间线合并（示意）：
```python
# 把多源事件归一化到 UTC 后按时间排序，输出可读的因果链
def timeline(events, offsets):
    norm = []
    for e in events:
        t = e["ts"] - offsets.get(e["host"], 0)     # 校正时钟漂移
        norm.append((t, e["host"], e["source"], e["summary"]))
    return sorted(norm)
```

事件响应与取证在遏制阶段交叉：遏制动作（重启、隔离）必须先完成关键证据采集，否则归因能力永久丧失。

## 六、常见误区
1. **「直接在受影响主机上排查」**——错。会覆盖内存与临时文件、更新访问时间；应先采集易失数据，再在副本上分析。
2. **「采集完不哈希」**——错。没有哈希与证据链，任何结论在法务与合规层面都难以采信。
3. **「先恢复业务，证据以后再说」**——需权衡。至少要在恢复前完成易失数据采集与关键镜像，否则证据不可再生。
4. **「没有预案也能应对」**——错。缺少联络人、权限与工具包会让首次响应时间成倍增长，MTTD/MTTR 直接恶化。
5. **「遏制就是拔网线」**——不一定。全面断网会打草惊蛇、破坏对手行为可观测性；分段遏制与定向封禁常更优。

## 八、面试题
1. **NIST 响应生命周期的阶段？** 要点：准备 → 检测与分析 → 遏制/根除/恢复 → 事后活动；准备阶段决定上限。
2. **为什么采集后要立刻哈希？** 要点：证明证据未被篡改，构成证据链的核心；任何偏差都会使该证据不可信。
3. **MTTD 与 MTTR 的含义与关系？** 要点：MTTD 是发现延迟、MTTR 是恢复耗时；MTTD 高会直接拖长攻击者停留时间与损失规模。
4. **易失性顺序为什么重要？** 要点：内存、连接等数据断电即失、不可再生；必须优先采集才能保住最有价值的入侵线索。
5. **遏制的两类策略如何取舍？** 要点：短遏制快但可能暴露动作，长遏制利于情报收集但风险更高；需按事件性质与业务影响选择。

## 九、演进与趋势
端点侧，EDR/XDR 把进程树、命令行与网络行为持续采集，使「事后取证」部分前移为「事中可观测」，大幅缩短 MTTD。自动化侧，SOAR 把剧本（playbook）固化为可编排动作，实现封禁、隔离、取证包生成的自动执行与审计。云原生侧，容器与不可变基础设施让传统磁盘取证失效，取证转向镜像层、CI/CD 记录与云审计日志。威胁情报与 ATT&CK 映射让响应从「单事件处置」走向「对手技术覆盖度评估」。需注意隐私与合规约束（员工监控、跨境数据），具体工具能力与法律边界**以官方最新文档与法规为准**。

## 十、小结
事件响应以「准备—检测分析—遏制根除恢复—事后复盘」的流程快速止损并学习，取证以哈希保全与证据链保证结论可采信。二者的交接点是遏制动作：在改动现场之前完成易失数据采集与关键镜像，是保住归因能力的唯一机会。缩短 MTTD/MTTR 与攻击者停留时间，靠的是预置能力、可观测性与自动化——应急能力不是事发时临场发挥出来的，而是平时练出来的。
