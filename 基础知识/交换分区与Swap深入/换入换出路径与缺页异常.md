> 对应 Linux 内核 Documentation（mm/）与 remzi-arpacidusse/ostep-code「paging」章节。

## 一、背景与挑战
访问一个已换出的页会触发缺页异常（page fault），内核必须透明地把数据从磁盘读回、修复 PTE，再让指令重试。挑战是路径要可睡眠（涉及 IO）、要处理并发（多 CPU 同时缺页同一页），且不能死锁。

## 二、核心原理
访问 swapped 页 → MMU 产生 page fault → do_swap_page 解析 PTE 得到 swap entry → 从 swap 区域读取页到新分配帧 → 更新 PTE 为 present 并指向该帧 → 若支持，把 swap 槽位释放。换出方向相反：回收选中 → 写页到 swap 槽位 → 把 PTE 改写为 swapped entry。两路径都持有相关锁（如页表锁、swap 锁）保证原子。

## 三、形式化与数学基础
缺页处理延迟近似：
```
T_fault = T_trap + T_lookup + T_io + T_fixup
```
其中 T_io 主导（旋转盘 ~10ms 级，NVMe ~100μs 级）。若页正被其他 CPU 换入（处于 swap cache），本 CPU 等待而非重复读：
```
if (page_in_swap_cache(entry))
    wait_on_page_locked(page)   // 复用他人 IO
```

## 四、代码实现
```c
// mm/memory.c（简化）
vm_fault_t do_swap_page(struct vm_fault *vmf)
{
    swp_entry_t entry = pte_to_swp_entry(vmf->orig_pte);
    page = lookup_swap_cache(entry, vma, vmf->address);
    if (!page) {
        page = swapin_readahead(entry, GFP_HIGHUSER_MOVABLE, vmf);
        // 从 swap 区域读入
    }
    lock_page(page);
    vmf->page = page;
    ret = finish_fault(vmf);              // 建立 present PTE
    if (PageSwapCache(page))
        free_swap_slot(entry);            // 不再需要磁盘副本
    return ret;
}
```

## 五、与其他技术对比
- 纯按需换入：简单，但无预读会放大随机 IO。
- swapin_readahead：按局部性预取相邻槽位，降低后续缺页率。
- swap cache：让并发缺页同一页只发生一次真实 IO。

## 六、常见误区
- 误区：每次缺页都从磁盘读。swap cache 命中或正在换入时复用。
- 误区：换出一定先写盘。若是干净文件页的「换出」其实是丢弃（可从文件重读）。

## 九、演进与趋势
从单页换入到 swapin_readahead 聚类，再到 THP swap 的整簇换入；swap cache 与页缓存逐渐统一到 address_space 抽象之下。

## 十、小结
换入换出路径以缺页异常为入口，用 swap entry 定位磁盘、用 swap cache 去重并发 IO，实现「换出透明、换入无感」的虚拟内存语义。
