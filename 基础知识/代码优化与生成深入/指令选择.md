# 指令选择

> 对应 龙书 14.2 节（树覆盖）与 Appel 第 12 章。

## 一、背景与挑战
指令选择把 IR 表达式树映射到目标指令，常多条 IR 对应一条复杂指令（如 x86 `lea`、ARM 带移位的 add）。挑战：最优覆盖、寻址模式、成本模型。

## 二、核心原理
把 IR 树划分为可被单条指令覆盖的子树；用动态规划 (BURG) 选最小成本覆盖。复杂寻址模式（基址+变址+偏移）整体匹配省指令。

## 三、形式化 / 数学基础
对树节点 $n$，成本 $C(n)=\min_t\{\mathrm{cost}(t)+\sum C(\text{child covered by }t)\}$，其中 $t$ 是能覆盖 $n$ 及其子树的模板。动态规划自底向上求全局最优。

## 四、代码实现
```python
# 简化: 用模式表覆盖 IR 节点
def cover(node):
    best = min((rule.cost + sum(cover(c) for c in rule.children(node))
                for rule in rules if rule.match(node)), key=lambda x: x[0])
    return best
```

## 五、与其他技术对比
- BURG/动态规划：最优、生成器驱动。
- 手工树重写：直观但次优。
- DAG 覆盖：DAG 上共享降低重复。

## 六、常见误区
1. 强制逐节点 1:1 映射漏掉复合指令（如 `add r, [r+4]`）。
2. 成本模型不准致偏慢覆盖。
3. 覆盖破坏 SSA 名一致性。

## 九、演进与趋势
基于 ML 的覆盖、DAG 上全局选择、以及可重定目标 DSL（TableGen）。

## 十、小结
指令选择以树/DAG 覆盖把 IR 映射到最少/最快指令；动态规划保证最优，复合寻址模式是关键收益来源。
