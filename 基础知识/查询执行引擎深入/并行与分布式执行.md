# 并行与分布式执行

> 对应 mit-pdos/6.824（分布式系统执行与容错），以及 cmu-db/15445-course（parallel query execution lecture）。

## 一、背景与挑战
单机吞吐受限，需把查询并行化（多核/多节点）。难点在任务划分、数据交换（shuffle）、负载均衡与故障恢复。

## 二、核心原理
- 并行：把算子分解为并行管道/分区间并行（intra-operator）或流水线并行（inter-operator）。
- 分布式：数据按分区（hash/range）分布，Join/Agg 通过 shuffle 重分区，Exchange 算子负责数据搬运。
- 容错：任务失败重算（如 Spark lineage）或副本接管。

## 三、形式化与数学基础
理想加速（Amdahl）：
$$ S(N) = \frac{1}{(1-p) + p/N} $$
其中 $p$ 为可并行比例。Shuffle 网络量：
$$ Data_{shuffle} = O(|R| + |S|) $$
均衡分区的方差越小，倾斜越小。

## 四、代码实现
```python
# 按 hash 分区的 shuffle（仅示意）
def partition(rows, n_parts, key_fn):
    buckets = [[] for _ in range(n_parts)]
    for r in rows:
        buckets[hash(key_fn(r)) % n_parts].append(r)  # 重分区
    return buckets
```

## 五、与其他技术对比
MPP（如 Greenplum）共享无状态、靠网络 shuffle；Spark 用 lineage 容错但易 shuffle 昂贵；shared-nothing 与 shared-disk 在一致性与扩展上取舍不同。

## 六、常见误区
1) 认为加节点必线性加速——Amdahl 限制与倾斜。
2) 忽略数据倾斜导致长尾。
3) 误以为 shuffle 无成本。
