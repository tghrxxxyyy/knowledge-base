# 指令提交与顺序提交

> 对应 Hennessy & Patterson《Computer Architecture》。

## 一、背景与挑战
乱序执行中，靠后的指令可能先于靠前指令完成。但对外（架构状态、内存）必须表现为按程序顺序生效，否则破坏正确性与异常语义。

## 二、核心原理
提交阶段每周期从 ROB 头部提交若干条。只有头部指令完成且无误，才允许其写架构寄存器/提交 store；遇异常则停止提交并从该指令恢复。

## 三、形式化与数学基础
提交宽度 C 限制每周期提交数：

    committed_per_cycle <= C
    且需 head 连续 done 为真。

## 四、代码实现
```c
void commit_stage() {
    int n = 0;
    while (n < COMMIT_W && rob[head].done && !rob[head].exc) {
        retire(rob[head]); head = (head+1)&M; n++;
    }
    if (rob[head].exc) trap(rob[head]);
}
```

## 五、与其他技术对比
顺序提交保证正确性但可能受慢指令阻塞（head 未完则其后即使完成也等）；这是乱序核心的「提交墙」。

## 六、常见误区
误以为完成即可对外生效；未提交的结果对架构不可见。误以为提交宽度等于执行宽度。

## 九、演进与趋势
store 提交与内存顺序（memory model）交互，需 store 队列配合。

## 十、小结
顺序提交是乱序执行的 correctness 保证，所有架构态变更必须经 ROB 头部按序生效。
