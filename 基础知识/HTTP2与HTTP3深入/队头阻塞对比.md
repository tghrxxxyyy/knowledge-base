# 队头阻塞对比

> 对应 RFC 9113（HTTP/2）；RFC 9000（QUIC）；RFC 9114。

## 一、背景与挑战
“队头阻塞”（Head-of-Line blocking, HOL）指队首的堵塞拖慢整队。HTTP 与传输层都存在 HOL，但层级不同、解法不同，常混淆。

## 二、核心原理
HTTP/1.1 应用层 HOL：单连接内请求必须按序响应，慢响应阻塞后续。HTTP/2 多路复用消除应用层 HOL，但所有流共享一条 TCP，任一丢包阻塞全部流（TCP 层 HOL）。HTTP/3/QUIC 每流独立可靠，丢包只影响该流，消除传输层 HOL。

## 三、形式化 / 数学基础
设连接含 n 个流，丢包概率 p。HTTP/2 下该连接整体停顿概率约 $1-(1-p)^k$（k 为在途段数）；HTTP/3 单流停顿概率 p，其余 n-1 流不受影响。
TCP 重排等待：$恢复时延 \approx RTO$（整连接）。QUIC 流级：$恢复时延 \approx RTO$（单流），其余流继续。

## 四、代码实现
```text
HTTP/1.1: [req1==resp1][req2==resp2]   <- resp1 慢则 req2 等
HTTP/2 : 流1▢ 流2▢ 流3▢  (单TCP, 丢包→全停)
HTTP/3 : QUIC流1▢ 流2▢ 流3▢ (各自可靠, 丢包仅停对应流)
```

## 五、与其他技术对比
应用层 HOL（HTTP/1.1）vs 传输层 HOL（HTTP/2 over TCP）vs 流级隔离（HTTP/3）。WebSocket 在单 TCP 上也受 TCP HOL 影响。

## 六、常见误区
误区一：HTTP/2 多路复用解决了一切 HOL。错，TCP 层仍在。误区二：TCP 不会 HOL。错，丢包重传会阻塞整连接字节流。误区三：HTTP/3 完全无 HOL。错，单流内有序仍有 HOL。

## 九、演进与趋势
多路径 QUIC 进一步在多条网络路径间分担，降低单路径丢包影响。

## 十、小结
队头阻塞分应用层与传输层：HTTP/2 解前者、HTTP/3/QUIC 再解后者，是 Web 性能演进主线。
