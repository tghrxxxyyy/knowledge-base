# 无分支编程与条件传送

> 对应 Bryant & O'Hallaron《CSAPP》第3章 条件传送 / Hennessy & Patterson。

## 一、背景与挑战
对不可预测的小分支，预测失败代价可能高于计算本身。编译器与手写可用条件传送(CMOV)或无分支技巧消除控制依赖，转为数据依赖。

## 二、核心原理
条件传送指令(如 x86 `CMOVcc`)按标志位选值而不跳转，无预测、无冲刷。无分支技巧用位运算/算术表达选择，彻底去掉分支。

## 三、形式化与数学基础
无分支 max 用掩码：
$$ mask = (a < b) ? 0xFFF...F : 0 $$
$$ r = (a \& \sim mask) | (b \& mask) $$
等价于 `r = (a<b) ? b : a`，但无跳转。

## 四、代码实现
```c
// 无分支取最大值
#include <stdio.h>
int max_nb(int a, int b) {
    int mask = (a - b) >> 31;   // 负则全 1
    return (a & ~mask) | (b & mask);
}
// 编译器可能生成的 CMOV 版本
int max_cmov(int a, int b) {
    return (a > b) ? a : b;   // gcc -O2 常转 CMOV
}
```

## 五、与其他技术对比
CMOV 对可预测分支未必更快(仍算两路)；对随机分支更稳。与 SIMD 结合可整向量无分支，避免逐元素预测。

## 六、常见误区
盲目无分支：当分支高度可预测，额外计算可能更慢。无分支掩盖真实依赖导致乱序窗口压力。

## 七、与开源书/权威来源对应
《CSAPP》3.6.4 条件传送；编译器优化章节说明何时用 CMOV。

## 八、面试题
何时 CMOV 优于分支？无分支 max 的掩码原理？什么情况无分支变慢？

## 九、演进与趋势
SIMD 无分支(select/mask)、GPU 的谓词执行、以及编译器基于 PGO 自动选择分支/CMOV。

## 十、小结
无分支把控制依赖变为数据依赖，消除预测风险，但仅在分支不可预测且计算廉价时划算。
