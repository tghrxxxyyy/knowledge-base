# 虚函数与间接分支预测

> 对应 Bryant & O'Hallaron《CSAPP》第3章 过程调用 / Hennessy & Patterson 间接跳转章节。

## 一、背景与挑战
虚函数、函数指针、switch 跳转表产生间接分支，目标在运行时由 vtable/指针决定。普通条件预测器无法工作，需间接分支预测器(IBP)。

## 二、核心原理
间接预测器记录 (源地址, 最近目标) 历史，用类似 GShare 的全局历史索引目标缓存。若调用站点(call site)稳定映射到同一目标，命中率高；多态热点站点目标多变则下降。

## 三、形式化与数学基础
设调用站点 $s$ 的目标分布为 $P(t)$，预测熵：
$$ H(s) = -\sum_t P(t)\log_2 P(t) $$
熵越高越难预测。命中率 $p_s$ 与该站点目标数成反比。

## 四、代码实现
```c
// 多态调用：间接分支目标随对象类型变化
#include <cstdio>
struct Shape { virtual double area() = 0; };
struct Rect : Shape { double w,h; double area(){return w*h;} };
struct Circ : Shape { double r;   double area(){return 3.14*r*r;} };
double total(Shape **s, int n) {
    double t=0; for(int i=0;i<n;i++) t += s[i]->area();  // 间接调用
    return t;
}
```

## 五、与其他技术对比
去虚化(devirtualization, 已知类型)改直接调用；内联彻底消除调用。与条件分支预测相比，间接分支目标是多值而非二值。

## 六、常见误区
认为所有虚调用都慢：单目标热点虚调用被 IBP 很好预测。频繁变化的类型分布才是瓶颈。

## 七、与开源书/权威来源对应
《CSAPP》描述 vtable 机制；Hennessy & Patterson 讨论间接分支预测器结构。

## 八、面试题
间接分支为何难预测？去虚化如何帮助？IBP 用什么历史？

## 九、演进与趋势
Retpoline 缓解 Spectre v2 间接分支注入；CFG(Control Flow Guard)约束目标同时提供预测提示。

## 十、小结
间接分支目标多值，需专用 IBP；稳定调用站点无碍，类型抖动才致命，去虚化/内联是根治手段。
