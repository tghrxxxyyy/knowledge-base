# 虚函数与间接分支预测

> 对应 Bryant & O'Hallaron《CSAPP》第 3 章（机器级程序表示与过程调用）/ Hennessy & Patterson《Computer Architecture》间接跳转章节 / Driesen & Hölzle 1996 "The Direct Cost of Virtual Function Calls in C++"（OOPSLA）。

## 一、背景与挑战

虚函数、函数指针、`switch` 跳转表以及 JIT/解释器的 opcode 分派，都会编译出**间接分支**：目标地址在运行时由内存中的 vtable 指针或表项决定，编译期不可知。条件分支预测器输出的是「跳/不跳」二值，而间接分支要预测的是「跳到哪」，因此需要专用的间接分支预测器（Indirect Branch Predictor, IBP）。

挑战有两层。第一层是**目标多值**：同一条间接跳转在一段时间内可能有多个合法目标，预测器必须从历史里猜出下一个。第二层是**表项冲突**：不同程序位置的间接跳转共享同一 BTB 表项时发生别名，会互相污染历史。

工程上这直接映射到语言运行时设计：C++ 的虚调用、Java/C# 的虚方法与接口调用、JavaScript 的多态内联缓存，都在这条线上做取舍。

## 二、核心原理

IBP 的通用结构是「以分支指令 PC（或其哈希）索引一张目标缓存，表项存放最近一次或几次的目标地址」：

- **单目标式**：每项存一个目标。目标稳定的调用站点命中率极高，在 2~3 个目标间跳变的站点则频繁出错。
- **带历史式**：把全局分支历史 GHR 与 PC 异或后索引，或为每个 PC 维护一个小型目标集合（2~4 路），等价于对「在该历史上下文下目标是谁」做条件预测。
- **多尺度式（ITTAGE 类）**：把目标地址按几何级数增长的历史长度做多表预测，长历史可捕捉「每 N 次循环切换一次目标」这类模式。

vtable 机制本身也影响可预测性：`obj->vptr->method` 需要两次串行加载（先读对象头拿 vptr，再读 vtable 第 k 项），这条依赖链会推迟「目标地址可用」的时刻，使误预测的代价更高。

关键观察：**调用站点的目标分布是否稳定，比它是不是虚调用重要得多**。单态（monomorphic）热点是友好的，双态/多态乃至巨态（megamorphic）才是杀手。

## 三、形式化与数学基础

设某调用站点 $s$ 的目标分布为 $P_s(t)$，则预测的**条件熵**为

$$
H(s) = -\sum_{t} P_s(t)\log_2 P_s(t)
$$

$H(s)=0$ 表示单态（理论上可完美预测），$H(s)=\log_2 k$ 表示在 $k$ 个目标上均匀分布（最难）。任何预测器的错率下界为

$$
P_{miss}(s) \ge 1 - \max_t P_s(t)
$$

若目标分布高度依赖最近一次目标（一阶马尔可夫），带历史的 IBP 可把错率降到转移概率矩阵的对角优势附近：

$$
P_{miss} \approx 1 - \mathbb{E}_t\left[\max_{t'} P(t' \mid t)\right]
$$

这解释了为什么「在同一站点反复交替两个类型」比「随机在两个类型间切换」更易预测——前者的转移矩阵近乎确定。实践中常以**抽象目标个数**作为可预测性的粗代理：$k$ 越大、分布越平，误预测率越高。

## 四、代码实现

```cpp
// 多态调用：同一条间接分支，目标随动态类型变化
#include <cstdio>

struct Shape {
    virtual ~Shape() = default;
    virtual double area() const = 0;      // vtable 槽位固定
};
struct Rect : Shape { double w, h; double area() const override { return w * h; } };
struct Circ : Shape { double r;    double area() const override { return 3.14159265358979 * r * r; } };

// 循环体内的调用指令是间接分支，目标 = 各对象 vptr 指向的 vtable[slot]
double total(Shape *const *s, int n) {
    double t = 0.0;
    for (int i = 0; i < n; ++i)
        t += s[i]->area();
    return t;
}

// 去虚化(devirtualization)：类型唯一可证时退化为直接调用，可内联、可向量化
double total_rects(const Rect *const *r, int n) {
    double t = 0.0;
    for (int i = 0; i < n; ++i)
        t += r[i]->w * r[i]->h;           // 无间接分支
    return t;
}
```

编译器能做的：当类型在作用域内不可变（局部对象、`final` 类、LTO 可见唯一派生）时直接去虚化；否则做「守卫 + 直接调用」的推测式去虚化——先比较 vptr，命中后走上内联后的直接路径。运行时可做的：内联缓存（单态缓存 = 一次比较 + 直接调用；多态缓存 = 小型目标表），把不可预测的间接跳转换成等级化条件分支。

## 五、与其他技术对比

| 维度 | 直接调用 | 虚调用（IBP） | 内联缓存 | 跳转表 switch |
| --- | --- | --- | --- | --- |
| 目标确定性 | 编译期确定 | 运行期多值 | 运行期，带上下文 | 运行期多值（下标） |
| 预测依赖 | 无需预测 | BTB/IBP 历史 | 类型检查分支 | IBP + 下标可预测性 |
| 误预测代价 | 0 | 高（含 vptr 加载） | 中（可退化为分支） | 高 |
| 可否内联 | 可 | 仅去虚化后 | 单态路径可 | 否 |
| 典型手段 | —— | 去虚化、`final`、LTO | 单态/多态 IC | 密集化 + 边界检查 |

与条件分支预测相比：条件分支只有两个出口且局部性强，2-bit 计数器加全局历史就能做好；间接分支目标多值且依赖数据流，必须靠目标缓存或目标集合。

## 六、常见误区

- 「虚调用一定慢」：单态热点站点的虚调用几乎与直接调用同速，瓶颈在多态/巨态站点。
- 「`-O2` 会自动去虚化」：只有编译器能证明类型唯一时才做，通常还需 LTO 或显式开启推测式去虚化的开关。
- 「用 `switch` 代替虚函数就快」：跳转表仍是间接分支，只是把 vtable 依赖换成下标计算，多态性并未消失。
- 「误预测只损失跳转本身」：目标地址需先加载 vptr 再加载表项，整条串行链的延迟都计入代价。
- 「CFI 只影响安全」：CET 一类机制给出合法目标类型提示（`endbr`/`bti`），硬件可用它缩小预测目标集合，安全与性能并非纯对立。

## 八、面试题

1. **间接分支为何比条件分支难预测？** 要点：条件分支输出二值，间接分支输出地址空间上的多值，需要目标缓存/目标集合而非 2-bit 计数器。
2. **去虚化在什么条件下可行？** 要点：类型唯一可证（`final`、局部对象、LTO 全程序可见唯一派生），或类型剖面稳定（推测式去虚化 + vptr 守卫）。
3. **内联缓存如何帮助预测？** 要点：把一条多值间接跳转变成「比较 + 直接调用」的等级化分支，单态站点命中率极高，多态时退化为小型目标表。
4. **为什么 vtable 调用有额外延迟？** 要点：需先加载 vptr 再加载 vtable 表项，两条串行加载位于关键路径上。
5. **Spectre v2 与间接分支预测器是什么关系？** 要点：BTB 用低位地址索引且跨上下文共享，攻击者可污染预测目标；Retpoline 用 RAS 预测替代 BTB 预测，IBPB 在上下文切换时刷新预测状态。

## 九、演进与趋势

硬件侧向「按历史长度分层」的通用预测器发展（同时预测条件与间接分支的 TAGE 家族），并引入安全隔离（IBRS/IBPB、预测器按上下文打标签）。语言与运行时侧的推动更明显：JIT 用类型反馈 + 内联缓存 + 去虚化，AOT 编译器用 LTO + PGO 获得类型剖面；CET/BTI 这类强制目标校验给硬件提供了「合法目标集合」这一额外信息，反过来可收紧预测。语言特性层面，`final`/`sealed` 约定与接口去虚化也在从源头减少多态站点。

## 十、小结

虚调用的成本不在「多一次跳转」，而在目标地址的多值性与 vptr 加载的串行延迟。判断一个站点是否值得优化，看的是**目标分布的熵**而非它是否为虚调用。可控手段是去虚化、内联缓存与类型反馈；硬件侧则是更聪明的 IBP 与合法目标提示。
