# 分支误判代价与流水线冲刷

> 对应 Bryant & O'Hallaron《CSAPP》第4章 / Hennessy & Patterson《Computer Architecture》。

## 一、背景与挑战
一旦预测错误，流水线中已投机执行的后续指令必须作废(flush/rollback)，恢复状态并重取正确路径。深度流水线使误判代价随级数线性增长。

## 二、核心原理
投机执行在分支未决时沿预测路径推进，并缓存写于重排序缓冲(ROB)。误判信号到达后，ROB 中该分支之后的微操作被清空，流水线前端重新取指，浪费数十周期。

## 三、形式化与数学基础
误判代价近似：
$$ C_{mispred} \approx D_{pipeline} + B_{redispatch} $$
总周期受分支频率与误判率影响：
$$ CPI_{eff} = CPI_{base} + f_{br} \times (1-p) \times C_{mispred} $$
其中 $f_{br}$ 每指令分支数，$p$ 准确率。

## 四、代码实现
```c
// 误判代价可观测：插入大概率分支观察抖动
#include <stdio.h>
int hot(int *a, int n, int key) {
    int c = 0;
    for (int i = 0; i < n; i++)
        if (a[i] > key) c++;   // 数据分布决定可预测性
    return c;
}
```

## 五、与其他技术对比
流水线冲刷类似异常/中断的现场恢复，但更频繁且硬件自动。与缓存缺失不同，它是取指/解码阶段结构性停顿。

## 六、常见误区
以为深流水线一定快：误判代价随深度放大。把不可预测分支当热点优化反而浪费预算。

## 七、与开源书/权威来源对应
《CSAPP》4.5.3 用实验展示误判使性能腰斩；Hennessy & Patterson 给出 CPI 与误判率关系。

## 八、面试题
误判代价为何与流水线深度相关？投机执行如何回滚？如何降低误判率？

## 九、演进与趋势
更大 BTB、更准 TAGE、以及前端解耦( Decoupled Frontend)让取指不受误判阻塞。

## 十、小结
误判代价等于被冲刷的流水线级数，是深流水线时代的性能杠杆；减少热点不可预测分支收益最高。
