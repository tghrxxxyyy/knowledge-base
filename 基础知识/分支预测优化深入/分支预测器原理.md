# 分支预测器原理

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》分支预测章节 / Bryant & O'Hallaron《CSAPP》第 4 章 / McFarling 1993 "Combining Branch Predictors" / Seznec & Michaud 2006 "TAGE"。

## 一、背景与挑战

现代流水线前端深达十余级：取指必须在本周期就知道下一条指令的地址，而条件分支的方向要到执行阶段才算得出。不做预测就要停顿到方向解析，停顿深度等于「解析级 − 取指级」，前端吞吐直接腰斩。预测器的作用就是**在解码前猜出方向与目标**，猜对则分支近乎零代价。

难点的本质是信息不足：方向由运行时数据决定，编译器不知道，硬件只能从**历史**里推断。而历史资源是有限的——表项容量有限导致别名，观察窗口有限导致长周期模式看不到，索引方式有限导致不同分支互相干扰。

## 二、核心原理

预测器由三个部件构成，各自回答不同问题：

1. **方向预测**：「跳还是不跳」。演进路径是 1-bit（记上次结果）→ 2-bit 饱和计数器（抗单次噪声）→ 两级自适应（PHT 由分支历史索引）→ 全局/局部历史混合（Tournament）→ 多尺度几何历史（TAGE）→ 感知机预测。
2. **目标预测（BTB）**：缓存「这个 PC 上次跳到哪」，避免等到方向确定才算目标地址。BTB 多为组相联、用 PC 低位索引；容量不足时产生别名，取到错误目标。
3. **返回地址栈（RAS）**：函数返回目标由调用点决定且严格嵌套，用硬件栈（通常十几到几十项）预测远优于任何历史表；溢出/下溢时退化为 BTB。

此外还有循环预测器（识别固定次数的短循环，直接预测退出时机），以及把取指与预测解耦的前端设计。

## 三、形式化与数学基础

2-bit 饱和计数器的状态转移：

$$
C_{t+1} = \operatorname{sat}\!\left(C_t + \delta\right), \quad
\delta = \begin{cases} +1, & \text{taken} \\ -1, & \text{not taken} \end{cases}, \quad C_t \in \{0,1,2,3\}
$$

预测规则为 $\hat{y} = [C_t \ge 2]$。它等价于 $\alpha \approx 0.5$ 的指数加权移动平均：抗单次噪声，但**无法捕捉长相关**——若分支结果取决于 5 次之前的另一个分支，2-bit 计数器必然学不会。

两级自适应预测器把 PC 与历史组合成索引，即 GShare：

$$
idx = (pc \oplus GHR) \bmod |PHT|
$$

它用全局历史寄存器编码最近若干次结果，区分「同一分支在不同上下文下」的行为，代价是索引冲突：PC 低位分散不足时别名严重。

TAGE 用几何级数增长的多张表 $L_i \propto \alpha^{i-1}$ 同时覆盖短相关与长相关，每项带符号化的有用位计数，取命中历史最长的表为「提供者」。其依据是条件熵随历史增长而单调不增：

$$
H(Y \mid h_1) \ge H(Y \mid h_1, h_2) \ge \cdots \ge H(Y \mid h_1,\dots,h_k)
$$

长历史理论上更准，但样本稀疏、暖机慢，所以必须多尺度并行并配合置信度评估。感知机预测器则给每个历史位配权重，取点积符号：

$$
\hat{y} = \operatorname{sgn}\!\left(w_0 + \sum_{i=1}^{h} w_i g_i\right), \quad g_i \in \{-1,+1\}
$$

## 四、代码实现

```c
/* 2-bit 饱和计数器 + GShare 索引的简化模型 */
#include <stdio.h>
#include <stdint.h>

#define PHT_BITS 16
#define PHT_SIZE (1u << PHT_BITS)
#define HIST_BITS 12

static uint8_t  pht[PHT_SIZE];   /* 0 强不跳, 1 弱不跳, 2 弱跳, 3 强跳 */
static uint32_t ghr;             /* 全局历史寄存器 */

static inline uint32_t index_of(uint32_t pc) {
    uint32_t pc_bits = (pc >> 2) & (PHT_SIZE - 1);
    uint32_t hist    = ghr & ((1u << HIST_BITS) - 1);
    return (pc_bits ^ (hist << (PHT_BITS - HIST_BITS))) & (PHT_SIZE - 1);
}

static inline int  predict(uint32_t pc) { return pht[index_of(pc)] >= 2; }

static inline void update(uint32_t pc, int taken) {
    uint32_t i = index_of(pc);
    if (taken  && pht[i] < 3) pht[i]++;      /* 饱和加，抗单次噪声 */
    if (!taken && pht[i] > 0) pht[i]--;
    ghr = (ghr << 1) | (uint32_t)taken;      /* 真实硬件需预测 GHR 本身 */
}
```

一个 20 次迭代的循环，2-bit 计数器只在退出时错一次，误预测率约 5%；换成每次方向随机的分支，准确率退化到 50%。真实预测器还要处理**时序**问题：索引需要的历史位必须在取指周期就可用，而分支结果要到执行阶段才产生，因此需要用推测式历史（speculative GHR）并在误预测时回滚。

## 五、与其他技术对比

| 方案 | 训练成本 | 可捕捉的模式 | 面积/功耗 | 准确率定位 |
| --- | --- | --- | --- | --- |
| 静态（向回跳则 taken） | 无 | 循环结构 | 极低 | 弱，但无训练延迟 |
| 1-bit | 快 | 无噪声规律 | 低 | 差（交替模式全错） |
| 2-bit 饱和 | 快 | 单分支的偏向 | 低 | 中，抗单次噪声 |
| GShare / 两级 | 需暖机 | 分支间全局相关 | 中 | 较好，受别名限制 |
| Tournament | 需暖机 | 全局 + 局部的选择 | 较高 | 好 |
| TAGE-SC-L | 需暖机 | 多尺度长历史 | 高 | 当前主流最优之一 |
| 感知机/神经 | 暖机较长 | 线性可分的复杂相关 | 高（乘法器） | 特定负载更优 |

与 RAS 对比：RAS 不学习而是精确复现调用栈语义，对递归与深层调用远比历史表可靠。

## 六、常见误区

- 「所有分支都同样好预测」：数据依赖的随机分支（哈希校验、随机输入比较）准确率趋近 1/2。
- 「表越大越好」：容量上升带来索引延迟与功耗，索引函数设计不佳时增大表只增加别名。
- 「只看方向，忽略 BTB」：BTB 别名会取到错误目标，代价与误预测相当，但可能不体现在 `branch-misses` 里。
- 「历史越长越准」：长历史样本稀疏、暖机慢，短模式负载上反而更差。
- 「误预测计数低就没问题」：还需结合分支密度、BTB 命中率、RAS 溢出与 uop cache 命中率整体判断。

## 八、面试题

1. **为什么用 2-bit 而不是 1-bit？** 要点：需连续两次反向偏移才翻转，等价于带迟滞的 EWMA，可抵抗循环退出这类单次噪声。
2. **GShare 如何缓解别名？** 要点：把全局历史异或进索引，使同一 PC 在不同上下文落入不同表项；PC 低位分散不足时仍会冲突。
3. **BTB 的作用？** 要点：缓存目标地址让前端提前取指；缺失或别名造成与误预测同量级的前端气泡。
4. **TAGE 为什么用几何级数历史？** 要点：不同分支的相关长度不同，多尺度并行覆盖，取命中历史最长的提供者表，兼顾快适应与高精度。
5. **RAS 为什么必须存在？** 要点：返回目标由调用点决定且严格栈序，历史表无法泛化，RAS 用硬件栈精确复现。

## 九、演进与趋势

方向预测已接近实测上限，提升转向辅助信息：统计校正器（SC）修正长历史表偏差，侧预测器处理别名冲突。结构上 BTB 容量与延迟成为新瓶颈，出现多级 BTB、uop cache 与解耦取指。安全约束带来反向影响：预测器需按特权级/上下文打标签（IBRS/IBPB/STIBP），并出现「更安全但略慢」的预测模式。研究前沿包括神经网络预测器与可形式化验证的预测器设计。

## 十、小结

分支预测器用有限历史硬件赌方向与目标，其准确率直接决定前端吞吐。三大构件分别是方向表（2-bit → 两级 → TAGE 的演进）、BTB（目标）与 RAS（返回）；理解别名、暖机与不可预测分支这三类失效模式，才能正确解释性能数据。
