# 分支预测器原理

> 对应 Hennessy & Patterson《Computer Architecture》分支预测章节 / Bryant & O'Hallaron《CSAPP》第4章。

## 一、背景与挑战
现代流水线深达十余级，遇到条件分支须等条件算出才能取指。若停顿整条流水线，IPC 大幅下跌。分支预测器在解码前猜测方向，赌对则零代价。

## 二、核心原理
1-bit 预测器遇重复模式会错；2-bit 饱和计数器(双模)用强/弱状态抗噪。全局历史(GShare)把最近分支结果哈希进 PHT 索引，捕捉相关模式。BTB 缓存目标地址，避免取指等待。

## 三、形式化与数学基础
2-bit 饱和计数器状态转移：
$$ C_{t+1} = \text{sat}(C_t + \delta), \quad \delta = \begin{cases}+1 & \text{命中}\\ -1 & \text{未命中}\end{cases} $$
预测准确率：
$$ p = \frac{\text{correct}}{\text{total}} $$
GShare 索引：
$$ idx = (pc \oplus GHR) \bmod |PHT| $$

## 四、代码实现
```c
// 简化的 2-bit 饱和计数器表
#define N 1024
int pht[N] = {0};   // 0,1 弱/强不跳; 2,3 弱/强跳
int predict(int idx) { return pht[idx] >= 2; }
void update(int idx, int taken) {
    if (taken && pht[idx] < 3) pht[idx]++;
    if (!taken && pht[idx] > 0) pht[idx]--;
}
```

## 五、与其他技术对比
静态预测(向后跳 likely taken)简单但弱；动态 2-bit 抗噪；TAGE 用多尺度几何历史更长相关。相比返回地址栈(RAS)专治函数返回。

## 六、常见误区
认为预测器对所有分支一样好：高度随机分支(如哈希校验)不可预测。忽视 BTB 容量不足导致别名。

## 七、与开源书/权威来源对应
Hennessy & Patterson 详述 1/2-bit、GShare、Tournament；CSAPP 4.5.3 描述预测对性能影响。

## 八、面试题
为何用 2-bit 而非 1-bit？GShare 如何抗别名？BTB 作用？

## 九、演进与趋势
TAGE-SC-L 预测器、神经分支预测(perceptron)、Intel 的 IBT/IBPB 兼顾安全与性能。

## 十、小结
分支预测以历史统计赌方向，2-bit 饱和计数器与全局历史是核心，准确率直接决定 IPC。
