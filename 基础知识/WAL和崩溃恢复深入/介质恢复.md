# 介质恢复

> 对应 Silberschatz《Database System Concepts》17.7 Media Recovery，以及备份与归档日志实践。

## 一、背景与挑战
磁盘损坏、机房故障等介质失效无法靠 WAL 单库恢复，需从备份 + 归档日志重建。介质恢复（media recovery）保证即使整盘丢失也能恢复到某个时间点。

## 二、核心原理
策略：定期全量/增量备份，连续归档 WAL（archive log）。恢复时先还原最近备份，再重放归档日志到目标时间点（PITR，Point-In-Time Recovery）。可前滚到任意 LSN。

## 三、形式化 / 数学基础
恢复点 $R = Backup(T_b) \oplus Redo(Archive[T_b, T_r])$。RPO（恢复点目标）= $T_r - T_b$ 上限，由备份频率与归档延迟决定。

## 四、代码实现
```bash
# PostgreSQL PITR 示例
restore_command = 'cp /archive/%f %p'
recovery_target_time = '2026-01-01 12:00:00'
# 启动后自动重放归档日志至目标时间
```

## 五、与其他技术对比
| 恢复类型 | 数据源 | 范围 |
|----------|--------|------|
| 崩溃恢复 | 在线 WAL | 单实例 |
| 介质恢复 | 备份+归档 | 整盘/机房 |
| 副本恢复 | 同步副本 | 单节点 |

## 六、常见误区
1. 有备份就安全——无归档日志则只能回到备份点。
2. 归档日志可不连续——断档即无法前滚。
3. 介质恢复很快——依赖备份大小与日志量。

## 九、演进与趋势
云原生把备份/归档下沉到对象存储（如 S3），结合持续归档实现秒级 RPO 与跨区容灾。

## 十、小结
介质恢复依赖备份 + 连续归档日志，实现跨介质故障的时间点恢复，是 RPO/RTO 目标的核心保障。
