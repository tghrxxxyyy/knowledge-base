# 一致性哈希与虚拟节点

> 对应 Karger 1997（Consistent Hashing）与 DeCandia 2007（Dynamo）。

## 一、背景与挑战
传统哈希取模在节点数变化时会使几乎所有 key 重新映射，引发大规模数据迁移与缓存击穿。一致性哈希把节点与 key 都映射到圆环，只影响邻近区间，将迁移量降到最低。虚拟节点进一步均衡负载。

## 二、核心原理
将哈希空间 \\[0, 2^{32})\\] 首尾相连成环，节点按其 id 哈希落在环上，key 哈希后顺时针找首个节点即归属。节点加入或退出只重分配其相邻区间。虚拟节点（vnode）让每个物理节点在环上占多个点，平滑负载不均。

## 三、形式化与数学基础
设物理节点数 \\(N\\)，虚拟节点数 \\(V\\)，则每物理节点平均负责 \\(V/N\\) 个区间。当一节点失效，其 \\(V/N\\) 个区间均匀分散到其余节点，避免单点雪崩。迁移量由 O(K)（K 为总 key 数，取模法）降为 O(K/N)。

## 四、代码实现
```python
import hashlib
def h(s): return int(hashlib.md5(s.encode()).hexdigest(), 16) % (2**32)

ring = {}   # vnode_hash -> node
for node in nodes:
    for i in range(VNODES):
        ring[h(node + "#" + str(i))] = node

def locate(key):
    k = h(key)
    for vh in sorted(ring):
        if vh >= k:
            return ring[vh]
    return ring[min(ring)]   # 回绕
```

## 五、与其他技术对比
取模法简单但不支持扩缩容；范围分区负载可控但需手动分裂；一致性哈希自动最小化迁移，适合动态成员。Dynamo 用其做数据放置。

## 六、常见误区
1. 不用虚拟节点：物理节点少时负载高度不均。
2. 认为一致性哈希绝对均衡：仅虚拟节点足够时才近似。
3. 环上节点用不同哈希函数：key 与节点必须同空间同函数。

## 七、与开源书/权威来源对应
Karger 1997 提出一致性哈希；DeCandia 2007 在 Dynamo 中应用；DDIA 第6章详述分区。

## 八、面试题
问：一致性哈希为何减少迁移？
答：节点变动只改变环上邻近区间映射，其余 key 位置不变，迁移量约与 1/N 成正比。

## 九、演进与趋势
带权虚拟节点支持异构硬件；结合复制因子做多副本放置。

## 十、小结
一致性哈希以环结构最小化扩缩容迁移，虚拟节点解决负载均衡，是动态分区的基石。
