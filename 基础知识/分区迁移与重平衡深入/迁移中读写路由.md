# 迁移中读写路由

> 对应 DeCandia 2007（Dynamo）与 DDIA 第6章。

## 一、背景与挑战
分区迁移是持续过程，期间客户端请求如何路由才能既看到最新数据又不报错？路由层必须知道「哪些分区在迁移、源与目标分别是谁」。

## 二、核心原理
维护一张「分区到位置」路由表，标 Migration 状态。读请求可发源或目标（取版本较新者）；写请求在迁移期需双写或带条件，保证两副本最终一致。完成后路由表原子更新指向目标。

## 三、形式化与数学基础
路由函数 \\(R: P \to 2^{Nodes}\\)。正常 \\(|R(p)|=1\\)（或副本数）；迁移中 \\(|R(p)|=2\\)。读合并：\\(read(p)=\text{merge}(get(src),get(dst))\\)，用版本时钟选最新。

## 四、代码实现
```python
def route_read(partition):
    locs = routing[partition]
    vals = [node.get(partition) for node in locs]
    return merge_versions(vals)   # 版本合并

def route_write(partition, val):
    locs = routing[partition]
    for node in locs:             # 双写保不丢
        node.put(partition, val)
```

## 五、与其他技术对比
静态路由（无迁移感知）在迁移期会读旧或写丢；Dynamo 的协调者加多版本合并保证可用；Raft 分片用共识保证切换原子，路由更简单。

## 六、常见误区
1. 迁移中只读源：可能漏最新写（若已切部分流量）。
2. 写只写目标：源旧数据未同步导致回滚。
3. 路由表非原子更新：出现脑裂路由。

## 七、与开源书/权威来源对应
Dynamo 用版本时钟与协调者处理迁移期读写；DDIA 第6章讨论再均衡时的可用性与一致性。

## 八、面试题
问：迁移期写为何双写？
答：保证源与目标都不丢更新，待 catch-up 后切换路由，避免数据回退。

## 九、演进与趋势
将路由表存入共识（如 etcd），使其强一致、原子切换。

## 十、小结
迁移中读写路由靠「状态感知加双写或合并」保证不丢不乱，完成后原子切换。
