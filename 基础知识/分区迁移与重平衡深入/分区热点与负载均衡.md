# 分区热点与负载均衡

> 对应 DeCandia 2007（Dynamo）与 DDIA 第6章（分区与倾斜）。

## 一、背景与挑战
即使哈希均衡，业务上某些 key（如热点用户、大对象）仍会造成分区热点，单节点被打满。哈希分区的「无差别均衡」无法应对「非均匀负载」，需要针对性手段。

## 二、核心原理
手段：① 热点 key 拆分（复合 key 加后缀分桶，如 user:123#0..#N）；② 动态再平衡把热点分区迁移到空闲节点；③ 读副本或缓存分担读热点；④ 一致性哈希虚拟节点增加灵活性。

## 三、形式化与数学基础
设 key 访问分布 \\(P(k)\\)，物理节点数 \\(N\\)，理想均衡使每节点负载 \\(\approx \sum_k P(k)/N\\)。热点 key 的 \\(P(k)\gg 1/N\\) 破坏均衡，拆分成 \\(m\\) 个子 key 使每子 \\(P/m\\)，逼近均值。

## 四、代码实现
```python
def write_hot_key(base, value, shards=10):
    i = pick_less_loaded_shard(base)   # 或 round-robin
    store.put(f"{base}#{i}", value)

def read_hot_key(base, shards=10):
    return [store.get(f"{base}#{i}") for i in range(shards)]
```

## 五、与其他技术对比
纯哈希分区对热点无能为力；范围分区可手动把热点段挪走但运维重；动态再平衡自动但滞后。组合「拆分加再平衡」最实用。

## 六、常见误区
1. 认为哈希一定均衡：仅对 key 数均衡，不对访问量均衡。
2. 热点拆分后读聚合无上限：应限 shard 数并缓存。
3. 仅靠加节点：热点 key 仍在单分区，加节点无效。

## 八、面试题
问：哈希分区仍有热点怎么办？
答：对热点 key 加随机或顺序后缀拆分到多分区，或动态迁移热点分区到空闲节点。

## 九、演进与趋势
基于实时指标的自愈式再平衡，自动识别并拆分热点。

## 十、小结
分区均衡是「分布均衡」而非「负载均衡」，热点需拆分与动态迁移综合治理。
