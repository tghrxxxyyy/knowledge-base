# 分区迁移触发与流程

> 对应 DeCandia 2007（Dynamo）与 DDIA 第6章（分区再均衡）。

## 一、背景与挑战
节点上线、下线、负载倾斜都会触发分区迁移。迁移过程不能停服，且需保证迁移中读写正确、不丢数据、最终收敛。触发策略与流程设计决定系统可用性。

## 二、核心原理
触发来源：成员变更（扩缩容或故障）、负载均衡器检测倾斜、管理员命令。流程通常：① 标记源分区为「迁移中」；② 拷贝数据到目标；③ 切换路由并同步增量；④ 删除源数据。期间用版本或向量时钟避免覆盖。

## 三、形式化与数学基础
设迁移分区 \\(P\\)，迁移期间路由函数变为多映射 \\(route(P)=\{src, dst\}\\)，读写同时可见两副本，待 `catch-up` 完成后收敛为单目标。正确性要求迁移期间不丢写（写两副本或带租约）。

## 四、代码实现
```python
def migrate(partition, src, dst):
    snapshot = src.snapshot(partition)
    dst.load(snapshot)
    # 增量同步阶段
    while not caught_up(src, dst, partition):
        dst.apply(src.delta(partition))
    routing.set(partition, dst)   # 切换
    src.delete(partition)
```

## 五、与其他技术对比
停服迁移最简单但不可用；Dynamo 风格渐进迁移保可用但复杂；Raft 集群用成员变更（joint consensus）做「日志分区」迁移，语义更清晰。

## 六、常见误区
1. 先删源再迁：失败即丢数据，应迁完确认再删。
2. 迁移中不双写：增量丢失。
3. 路由切换瞬间不原子：读到部分旧部分新。

## 七、与开源书/权威来源对应
Dynamo 用向量时钟协调迁移中的并发写；DDIA 第6章讲再均衡与一致性风险。

## 八、面试题
问：迁移中如何保证不丢写？
答：迁移期对源与目标双写或挂增量日志，待完全 catch-up 再切路由。

## 九、演进与趋势
将迁移纳入共识（如 Raft 成员变更），使迁移本身成为一致操作。

## 十、小结
分区迁移需「拷贝-增量-切换-清理」四步并保证双写，方能在不掉线前提下安全再均衡。
