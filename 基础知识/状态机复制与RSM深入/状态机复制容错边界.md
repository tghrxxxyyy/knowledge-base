# 状态机复制容错边界

> 对应 Lamport 1998（Paxos）与 Gilbert & Lynch 2002（CAP）。

## 一、背景与挑战
RSM 能容忍多少故障？何时系统不可用？容错边界由「副本数」与「故障模型」（崩溃-恢复 vs 拜占庭）决定。理解边界才能正确规划集群规模与可用性。

## 二、核心原理
崩溃故障模型下，RSM 可容忍 \\(f\\) 个故障需至少 \\(2f+1\\) 副本（多数派 \\(f+1\\)）。拜占庭故障需 \\(3f+1\\)。可用性与「能否凑齐多数派」绑定：失去多数派则停止写入（CP 行为）。

## 三、形式化与数学基础
设总副本数 \\(N\\)，容错 \\(f\\)，则写入需 \\(\lceil N/2\rceil+1\\) 应答。令 \\(N=2f+1\\)，故障 \\(f\\) 个仍可应答 \\(f+1\\) 形成多数；故障 \\(f+1\\) 则写停顿。

## 四、代码实现
```python
def majority(n): return n // 2 + 1
assert majority(3) == 2   # 容忍1
assert majority(5) == 3   # 容忍2
```

## 五、与其他技术对比
异步复制（主从）主挂即可能丢未同步数据，容错弱于 RSM；RSM 以多数派换取不丢已提交。PACELC 进一步刻画延迟-一致权衡。

## 六、常见误区
1. 认为 2 副本可容 1 故障：2 副本任一挂都无多数，写停顿。
2. 忽视脑裂：无多数派机制会双主，RSM 用共识避免。
3. 拜占庭场景用 2f+1：不够，需 3f+1。

## 七、与开源书/权威来源对应
Lamport 1998 给出容错下界；Gilbert & Lynch 2002 关联 CAP；Raft 论文讨论成员变更与容错。

## 八、面试题
问：为何 2f+1 能容忍 f 崩溃？
答：故障 f 个后剩 f+1 个仍能形成多数派（大于 N/2），可继续决策。

## 九、演进与趋势
动态成员变更（Raft joint consensus）让容错边界在线调整。

## 十、小结
RSM 容错边界由多数派决定：崩溃故障需 2f+1，拜占庭需 3f+1，失去多数派即停写。
