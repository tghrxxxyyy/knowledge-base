# Karn 算法与重传二义性

> 对应 Karn & Partridge 1987《Improving Round-Trip Time Estimates》与 RFC 6298 对重传样本的处理。

## 一、背景与挑战
当一段被重传后收到 ACK，发送方无法判断该 ACK 是针对原始段还是重传段，因此用其计算 RTT 会严重偏差（二义性）。错误更新会让 RTO 忽大忽小，引发连锁重传。

## 二、核心原理
Karn 算法规定：一旦发生重传，对应的 RTT 样本不再用于更新 SRTT/RTTVAR（即「重传的样本丢弃」）。同时，每次重传将 RTO 指数退避（RTO = RTO * 2），直到收到一个「非重传段」的干净 ACK 才恢复常规更新。

## 三、形式化与数学基础
设第 k 次重传 RTO_k = RTO_0 · 2^k（退避上限常 60s）。二义性样本被排除：若段是重传的，则 skip 更新。退避在连续重传下增长，避免对持续丢包链路的激进重传。

## 四、代码实现
```python
if retransmitted:
    rto *= 2                  # 指数退避
    # 不更新 srtt/rttvar（Karn：丢弃二义样本）
else:
    update_rto(sample, rto)  # 干净样本才更新
```

## 五、与其他技术对比
RFC 6298 在 Karn 基础上细化：仅当该段「从未被重传且未被重传副本确认」时才更新；并规定重传后 RTO 退避、收到新数据 ACK 后不清零退避（除非进入持续计时器逻辑）。时间戳选项（TSOPT）可从根本缓解二义性。

## 六、常见误区
误区一：重传 ACK 必是重传段的——无法区分，故必须丢弃。误区二：退避无限增长——有上限（通常 60s）。误区三：开了时间戳就不需要 Karn——时间戳解决测量，Karn 仍是重传后的保守策略。

## 七、与开源书/权威来源对应
Karn & Partridge 1987 提出并命名；RFC 6298 第 3 节吸收其精神；xiaolincoder/hello-http 解释二义性；Kurose & Ross 提到 RTT 测量难题。

## 八、面试题
什么是重传二义性？Karn 如何避免？为何重传后要退避？时间戳如何缓解？

## 九、演进与趋势
TCP 时间戳选项（TSval/TSecr）使发送方能量化「ACK 延迟」，从而安全使用重传段的样本，部分弱化 Karn 的丢弃策略，但退避仍保留。

## 十、小结
Karn 算法通过「丢弃重传样本 + 指数退避」规避 RTT 二义性导致的估计失真，是 TCP 稳健重传的关键保守机制。
