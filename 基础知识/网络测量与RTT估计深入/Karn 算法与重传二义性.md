# Karn 算法与重传二义性

> 对应 Karn & Partridge 1987《Improving Round-Trip Time Estimates in Reliable Transport Protocols》与 RFC 6298 对重传样本的处理规则。

## 一、背景与挑战
TCP 通过测量往返时间（RTT）来设定重传超时（RTO）。问题出在重传场景：当一个报文段被重传后收到了 ACK，发送方无法判断这个 ACK 确认的是「原始段」还是「重传段」。若误判，RTT 样本会产生严重偏差——把重传段的 ACK 当作原始段的确认，会算出远大于真实值的 RTT；反之则可能严重低估。

这种不确定性称为「重传二义性」（retransmission ambiguity）。它的危害是连锁性的：RTT 样本失真导致 RTO 忽大忽小，RTO 过小会触发不必要的重传，重传又制造更多二义样本，形成恶性循环，浪费带宽并加剧拥塞。在丢包率较高的链路上，这个问题尤为突出。

## 二、核心原理
Karn 算法给出两条简洁而稳健的规则：

- 丢弃二义样本：一旦某个段发生了重传，其对应的 RTT 样本不用于更新 SRTT 与 RTTVAR。即「只信任从未被重传的段的 ACK」。
- 指数退避：每次重传后，将 RTO 加倍（$RTO \leftarrow 2 \cdot RTO$），直到收到一个干净（未被重传）的确认才恢复常规更新。

这两条规则分别应对「不要被污染」与「在持续丢包时不要急躁」。Karn 算法的哲学是保守：宁可暂时不更新估计，也不要引入错误样本；宁可拉长等待，也不要盲目重传。

## 三、形式化与数学基础
设第 $k$ 次重传后的超时值为 $RTO_k$，基准超时为 $RTO_0$，则退避关系为：

$$ RTO_k = RTO_0 \cdot 2^{k} $$

实际实现通常对退避设置上限（常见为 60 秒，具体以各实现与 RFC 为准），避免无限增长导致连接长时间卡死。

二义样本的排除可形式化为一个更新门控。设 $r$ 表示该段是否被重传过，则更新规则为：

$$ \text{update} = \begin{cases} \text{skip}, & r = \text{true} \\ \text{apply}, & r = \text{false} \end{cases} $$

即仅当 $r = \text{false}$ 时才把样本送入 SRTT/RTTVAR 的 EWMA 更新。退避在连续重传时以指数方式增长，使重传间隔迅速拉大，这是对「链路可能长时间不可用」的合理假设。

## 四、代码实现
```python
# Karn 算法核心：重传样本丢弃 + 指数退避
def on_ack(sample, retransmitted, srtt, rttvar, rto):
    if retransmitted:
        rto = min(60.0, rto * 2)      # 退避，且设置上限
        # 不更新 srtt/rttvar：丢弃二义样本
        return srtt, rttvar, rto
    # 干净样本才更新（alpha=1/8, beta=1/4，见 RFC 6298）
    rttvar = 0.75 * rttvar + 0.25 * abs(sample - srtt)
    srtt = 0.875 * srtt + 0.125 * sample
    rto = max(1.0, srtt + 4 * rttvar)
    return srtt, rttvar, rto
```

```text
# 关键不变量
- 任何进入了重传的段，其 ACK 不得用于 RTT 估计
- 退避在连续重传时单调递增，且有上限
- 收到干净 ACK 后恢复常规更新（退避的取消策略依实现）
```

## 五、与其他技术对比
RFC 6298 在 Karn 的基础上细化了更新条件：仅当「该段从未被重传，且其 ACK 也不是由重传副本触发」时才更新估计；同时规定重传后的退避行为与恢复规则。时间戳选项（TSOPT，RFC 7323）则从根源上缓解二义性：因为 ACK 会回显被确认数据最初发送时的时间戳，发送方可以直接计算出该确认真正对应的发送时刻，从而安全地使用重传场景下的样本。三者关系是：Karn 提供保守兜底，RFC 6298 规范化数值与条件，TSOPT 在可用时消解二义。

| 方案 | 二义处理 | 是否可用重传样本 | 额外开销 |
| --- | --- | --- | --- |
| Karn 算法 | 直接丢弃 | 否 | 无 |
| RFC 6298 细则 | 细化门控条件 | 否 | 无 |
| 时间戳选项 | 回显消歧 | 是 | 每段约 10 字节 |
| 发送方专用选项 | 每段刷新 | 是 | 每段 12 字节 |

## 六、常见误区
误区一：「收到重传后的 ACK 必然确认重传段」。错，无法区分，故必须丢弃该样本。误区二：「退避会无限增长」。错，实现通常设有上限，避免连接长期停滞。误区三：「启用时间戳后就不再需要 Karn」。错，时间戳解决测量，Karn 仍是重传后的保守策略，退避依然保留。误区四：「丢弃样本等于停止估计」。错，只是跳过受污染的样本，干净样本仍持续更新。误区五：「二义性只影响精度，不影响正确性」。错，失真的 RTO 会导致错误重传，影响吞吐与拥塞行为。

## 九、演进与趋势
时间戳选项使发送方能量化确认真实对应的发送时刻，从而在重传场景下也能安全使用 RTT 样本，部分弱化了 Karn 的「一律丢弃」策略。但退避机制作为对链路不可用的保守假设被保留下来，并被 QUIC 等新协议继承与发展。趋势是「测量能力增强 + 保守策略保留」：精度提升不改变对持续丢包保持谨慎的基本原则。

工程实现中的关键细节：

- 退避上限：避免 RTO 无限增长导致连接长时间停滞。
- 恢复策略：不同实现对「何时取消退避」处理不同，需依规范与实现确认。
- 快速重传：重复 ACK 触发的快速重传不走超时退避路径。
- 时间戳可用性：启用后可放宽重传样本的使用限制。
- 可观测性：记录重传次数、退避状态与 RTO 变化，便于定位异常。
- 初始估计：首个样本的初始化方式会影响早期 RTO 的激进度。

需要区分两种重传触发：超时重传走 RTO 退避，重复 ACK 触发的快速重传依赖拥塞控制逻辑。Karn 主要约束前者，两者共同构成 TCP 的丢包恢复机制。

## 十、小结
Karn 算法用「丢弃重传样本 + 指数退避」两条规则，规避了重传二义性导致的 RTT 估计失真，是 TCP 稳健重传的关键保守机制。它的价值在于承认不确定性并选择安全的默认行为，而非试图强行分辨不可分辨的 ACK。理解它与 RFC 6298、时间戳选项的分工，才能真正掌握 TCP 计时器的设计哲学。
