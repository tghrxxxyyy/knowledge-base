# 时间戳选项与 RTTM

> 对应 RFC 7323（TCP Extensions for High Performance，含时间戳选项与 PAWS，原 RFC 1323）与 RFC 6298 中的 RTTM 说明。

## 一、背景与挑战
Karn 算法因重传二义性必须丢弃受污染的 RTT 样本，代价是在丢包与重传期间，发送方对 RTT 的估计进入「失明」状态——只能退避与等待，无法精确测量。在丢包率较高或路径 RTT 波动较大的链路上，这会显著拖慢恢复速度。

要解决这一困境，需要一种能明确告知「这个 ACK 对应哪次发送」的机制。TCP 时间戳选项（Timestamp Option, TSOPT）正是为此设计：它在报文段中携带发送时刻，接收方在 ACK 中回显该时刻，使发送方能够精确算出该确认真正对应的往返时间，从而在重传场景下也能安全测量。

## 二、核心原理
TSOPT 在连接建立时通过 SYN 协商启用。启用后，每个 TCP 报文段携带两个时间戳字段：

- TSval：发送方当前时钟的值（单调递增）。
- TSecr：接收方在 ACK 中回显「最近一次收到的 TSval」，即触发该 ACK 的那个数据段的时间戳。

发送方收到 ACK 时，用当前时钟减去 TSecr，即可得到「从被确认数据发出到确认收到」的时间，这就是 RTT 样本。由于 TSval 标识的是发送时刻而非「第几次发送」，即便中间发生过重传，只要 ACK 回显的是原始发送时刻，该样本依然有效——重传二义性被消解。这就是 RFC 6298 所称的 RTTM（Round-Trip Time Measurement）。

## 三、形式化与数学基础
RTT 样本计算：

$$ S = T_{\text{now}} - \text{TSecr} $$

其中 $\text{TSecr}$ 是 ACK 所确认数据最初发送时的 TSval。关键在于 TSval 与「发送时刻」绑定，而非与「具体报文实例」绑定，因此重传不会污染测量。

时间戳的单调性要求：仅需单调递增，不需要全局时钟同步，因为计算的是差值而非绝对时刻。时钟粒度需足够细（RFC 建议毫秒级量级），否则内核对 RTT 的分辨率不足。

除测量外，时间戳还支撑 PAWS（Protection Against Wrapped Sequences）：接收方维护「最近见过的最大 TSval」，丢弃时间戳过旧的报文段，防止序号在高速链路上回绕造成的数据混淆。这要求 TSval 在连接生命周期内保持递增且不被回绕。

## 四、代码实现
```c
/* 发送侧：在报文段中写入当前时间戳 */
tcp_hdr->tsval = tcp_clock_now();
tcp_hdr->tsecr = last_received_tsval;

/* 接收侧：回显最近收到的 TSval */
tcp_hdr->tsecr = recent_tsval;

/* 收到 ACK：用回显计算样本，即使曾重传也可用 */
if (opt.tsecr != 0) {
    uint32_t sample = tcp_clock_now() - opt.tsecr;
    rtt_update(sample);          /* 不受 Karn 二义性限制 */
}
```

## 五、与其他技术对比
| 维度 | 无 TSOPT | 有 TSOPT |
| --- | --- | --- |
| 重传期 RTT 估计 | 失明（Karn 丢弃样本） | 可精确测量 |
| 二义性 | 存在 | 消解 |
| 是否防序号回绕 | 否 | 是（PAWS） |
| 开销 | 无 | 每段约 10 字节 |
| 时钟要求 | 无 | 单调即可，无需同步 |

无 TSOPT 时只能依赖 Karn 丢弃重传样本，估计在丢包期变盲；TSOPT 提供端到端时钟回显，思路类似 QUIC 的 ACK 帧携带 ack delay。代价是每段固定选项开销，在选项空间紧张时可能与 SACK 等同时启用产生压力。

## 六、常见误区
误区一：「时间戳选项用于加密」。错，它服务于测量与 PAWS，不涉及安全。误区二：「开着时间戳就不需要 Karn」。错，退避仍保留，Karn 的保守策略在极端情形下依然生效。误区三：「时间戳需要全局时钟同步」。错，只需单调递增，因为用的是差值。误区四：「时间戳会增加握手开销所以应关闭」。错，长肥管道上其收益远超每段 10 字节的开销。误区五：「TSecr 是接收方自己的时钟」。错，它回显的是对方的 TSval。

## 九、演进与趋势
在高速长肥管道（LFN）中，TSOPT 与窗口缩放、SACK 一同启用，支撑高带宽延迟积下的可靠传输；其测量能力也被 BBR 等模型化拥塞控制用于刷新 min_rtt。QUIC 则在设计之初就把 ack delay 显式建模进 RTT 估计，可视为对 TSOPT 思路的现代化继承。总体趋势是「把测量信息内建进协议」，减少对启发式补偿的依赖。

实现层面的要点：

- 时钟粒度：需足够细（毫秒级量级），否则测量分辨率不足。
- 单调性：TSval 必须严格单调递增，不能用会回拨的系统时钟。
- PAWS 阈值：以时间戳判断报文新旧，需处理回绕与初始化。
- 选项协商：仅在双方 SYN 均携带时启用，中途不可单方开启。
- 空间权衡：与 SACK、窗口缩放等共用有限选项空间，需综合取舍。
- 兼容性：对端不支持时应优雅降级，回退到 Karn 策略。

TSOPT 的工程价值在于「一次启用，长期受益」：它同时改善 RTT 测量的准确性、支持 PAWS 防回绕，并为高速链路提供更稳健的计时基础。

## 十、小结
TCP 时间戳选项通过 TSval/TSecr 的回显实现精确的往返时间测量（RTTM），弥补了 Karn 算法在重传期间的测量盲区。它的精妙之处在于把「测量锚点」从报文实例转移到「发送时刻」，从而让二义性自然消失；同时顺带提供了 PAWS 防序号回绕能力。理解 TSOPT 与 Karn、RFC 6298 三者的分工，是完整掌握 TCP 计时器体系的关键一环。
