# 乱序执行原理

> 对应 Hennessy & Patterson 第3章；CSAPP 中文笔记 https://github.com/Hansimov/csapp 第4章。

## 一、背景与挑战

顺序发射时，前条指令因 Cache 缺失或长延迟阻塞，后续无关指令本可先执行却被卡住。乱序执行(OoO)让无依赖指令越过阻塞者先行，提高利用率。

## 二、核心原理

现代流水线：前端(取指/译码)顺序，调度器(Reservation Station)缓存已就绪 uop，执行单元乱序完成，重排序缓冲(ROB)按原序提交(retire)以保证精确异常。核心：把“执行顺序”与“提交顺序”解耦。

## 三、形式化 / 数学基础

设指令 $i$ 阻塞 $D$ 拍，后续有 $k$ 条独立指令各需 $c$ 拍，顺序需 $D+\sum c$，乱序可并行：

$$Gain \approx D - \max_j sched(j)$$

窗口越大，能跨越的阻塞越长，IPC 越高。

## 四、代码实现

```c
// 独立计算可越过阻塞的 load
int x = arr[a];      // 若 cache 缺失阻塞
int y = b + c;       // 与之无关，乱序引擎可先算 y
int z = x * y;       // 等 x 就绪
```

## 五、与其他技术对比

- 乱序靠硬件动态调度；VLIW 靠编译器静态。
- 乱序需寄存器重命名消除 WAR/WAW 才能充分。

## 六、常见误区

- 误以为乱序改变程序语义：提交顺序仍保序，仅执行乱序。
- 误以为越大越好：窗口增带来功耗与面积平方代价。

## 八、面试题

- 为何需要 ROB？答：乱序执行但按序提交，保证异常精确与内存顺序可见。
- 乱序能越过真依赖吗？答：不能，RAW 必须等源就绪。

## 九、演进与趋势

调度窗口从几十扩大到数百 uop，配合大 ROB 与多端口。

## 十、小结

乱序执行用硬件动态调度隐藏延迟，是宽发射高性能核心的支柱。
