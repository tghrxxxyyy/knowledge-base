# 寄存器重命名

> 对应 Hennessy & Patterson 第3章；CSAPP 中文笔记 https://github.com/Hansimov/csapp 。

## 一、背景与挑战

程序寄存器少（如 16/32 个），但指令间常无真依赖却因使用同寄存器产生伪依赖(WAR/WAW)，限制并行。重命名把架构寄存器映射到大量物理寄存器。

## 二、核心原理

重命名表(RAT)把每个架构寄存器(ar)映射到物理寄存器(pr)。发射时分配新 pr 给目的，源查 RAT 得当前 pr。完成后旧 pr 在确认无读者后回收。两种组织：全局物理寄存器堆(PRF) 或 重排缓冲+架构寄存器堆(ROB+RRF)。

## 三、形式化 / 数学基础

物理寄存器数 $P \gg A$（架构数）。消除 WAW 链：

$$WAW(r):\; pr_{new} = free(),\; RAT[r] = pr_{new}$$

映射时需维护“上一条写 r 的 pr”与“free list”以支持精确回退。

## 四、代码实现

```c
# 伪代码：重命名
def rename(instr):
    s1 = RAT[instr.rs1]; s2 = RAT[instr.rs2]
    d  = free_list.pop()
    RAT[instr.rd] = d
    return (s1, s2, d)
```

## 五、与其他技术对比

- 重命名消除伪依赖，使乱序窗口能填满；不做则 ILP 受限。
- PRF 读端口多但提交简单；RRF 省寄存器但回退复杂。

## 六、常见误区

- 误以为重命名改变语义：只改存储位置，不改数据流。
- 误以为架构寄存器数=物理寄存器数。

## 八、面试题

- 为何能消除 WAR/WAW？答：目的分配新物理寄存器，源指向旧值。
- free list 耗尽怎么办？答：停顿发射直到提交回收。

## 九、演进与趋势

物理寄存器堆超大（数百），支持更大窗口与推测。

## 十、小结

寄存器重命名是释放 ILP 的关键，让“写同一名字”不再串行。
