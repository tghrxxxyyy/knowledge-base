# 预测误恢复机制

> 对应 Hennessy & Patterson 第3章；CSAPP 中文笔记 https://github.com/Hansimov/csapp 。

## 一、背景与挑战

投机执行一旦分支误判，已乱序完成的指令结果必须作废，状态回退到误分支点，且不能泄漏副作用。

## 二、核心原理

机制：气泡清空后续流水；ROB 中误分支之后的指令标记作废不提交；恢复 RAT 到误分支处快照(检查点)；清空/回退相关保留站。较新设计用“懒惰恢复”或影子映射减少停顿。

## 三、形式化 / 数学基础

误罚拍数约：

$$Penalty \approx pipeline\_depth + in\_flight\_ops$$

若每 N 指令一次误判，平均：

$$CPI_{eff} = CPI_{ideal} + MispredictRate \times Penalty$$

## 四、代码实现

```c
# 伪代码：分支提交时发现误预测
if commit_is_branch and wrong_target:
    flush_after(rob_pos)        # 作废后续
    restore_rat(checkpoint[pos])# 恢复重命名表
    pc = correct_target
```

## 五、与其他技术对比

- 急切恢复：停顿清空；懒惰恢复：保留旧映射，新映射覆盖，省停顿。
- 检查点数量有限，深度误恢复需多级。

## 六、常见误区

- 误以为误预测会留副作用：未提交指令不退休，状态不可见。
- 误以为恢复零代价：清空本身有延迟。

## 八、面试题

- 误预测后为何安全？答：ROB 未提交，回退 RAT 即可，无架构可见副作用。
- 检查点作用？答：快速恢复重命名表到分支点。

## 九、演进与趋势

大 ROB + 多层检查点减少恢复停顿，配合快速前端重定向。

## 十、小结

误恢复保证投机执行安全，代价是误罚，故预测准确率为先。
