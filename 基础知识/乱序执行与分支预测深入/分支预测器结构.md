# 分支预测器结构

> 对应 Hennessy & Patterson 第2章；CSAPP 中文笔记 https://github.com/Hansimov/csapp 。

## 一、背景与挑战

预测器要在极小面积/功耗下给出高准确率，并尽快提供目标地址，避免取指空泡。

## 二、核心原理

组成：方向预测（是否跳）+ 目标预测(BTB)。方向常用局部分支历史、全局历史(GHR)、路径历史，组合为 Gshare/TAGE。返回地址栈(RAS)预测函数返回。现代用多层：小型快速预测 + 大型慢速 TAGE。

## 三、形式化 / 数学基础

Gshare 索引 $i = GHR \oplus PC_k$；TAGE 用多张不同长度历史 $h_j$ 的表，命中较长历史者优先：

$$Predictor = \arg\max_j \{ table_j[GHR_{h_j} \oplus PC] \neq weak \}$$

置信表优先提供高置信预测，降低误罚。

## 四、代码实现

```c
# 伪代码：Gshare 更新
def predict(pc, ghr):
    idx = (ghr ^ (pc & mask)) & sz
    return pht[idx] >= 2     # 2位计数器 >=2 表预测跳
```

## 五、与其他技术对比

- 局部分支历史对独特模式好；全局捕捉跨分支相关。
- TAGE 用多历史长度兼顾两者。

## 六、常见误区

- 误以为大表必准：别名冲突可能降效。
- 忽视 RAS 对递归/虚函数的重要性。

## 八、面试题

- RAS 作用？答：预测函数返回地址，避免返回分支误判。
- Gshare 为何异或？答：混合全局与局部历史，降低别名。

## 九、演进与趋势

TAGE-SC-L、神经预测器(Perceptron)达极高准确率。

## 十、小结

预测器结构在表大小、历史长度与功耗间平衡，是前端吞吐命门。
