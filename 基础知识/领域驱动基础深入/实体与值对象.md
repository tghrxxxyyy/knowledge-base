# 实体与值对象

> 对应 Evans《Domain-Driven Design》第5章。

## 一、背景与挑战
领域建模时混淆"有身份"与"有属性"的对象，导致用值比较却依赖 ID，或用 ID 比较却只需属性相等，引发正确性与性能问题。

## 二、核心原理
实体（Entity）由身份（ID）定义，生命周期内属性可变但身份不变，相等性按 ID。值对象（Value Object）由属性定义，不可变、无身份，相等性按属性值，可自由替换。

## 三、形式化 / 数学基础
实体相等：$e_1=e_2 \iff id(e_1)=id(e_2)$。值对象相等：$v_1=v_2 \iff \bigwedge_{a\in attrs} a(v_1)=a(v_2)$。值对象满足不可变：$v.a$ 一经构造不可改。

## 四、代码实现
```python
@dataclass(frozen=True)
class Money:           # 值对象
    amount: int
    currency: str

class Order:           # 实体
    def __init__(self, order_id): self.id = order_id
    def __eq__(self, o): return isinstance(o, Order) and o.id == self.id
```

## 五、与其他技术对比
与"所有对象皆 Entity + ORM 行"相比，值对象减少身份管理负担、天然线程安全。与 DTO 不同，值对象是领域概念而非传输结构。

## 六、常见误区
误区：把本应是值对象的金额/地址建模成实体。误区：值对象里放可变字段破坏语义。

## 九、演进与趋势
语言层不可变类型（record、dataclass frozen、value class）让值对象建模更自然。

## 十、小结
以身份 vs 属性区分实体与值对象，多用值对象降低复杂度。
