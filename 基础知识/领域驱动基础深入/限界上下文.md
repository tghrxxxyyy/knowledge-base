# 限界上下文

> 对应 Evans《Domain-Driven Design》第 2 章、第 14 章 Bounded Context 与 Context Map。

## 一、背景与挑战

同一词汇在不同部门含义不同：「客户」在销售上下文含信用等级与商机，在物流上下文只关心收货地址与配送偏好。若强行共享一个大模型，概念会冲突、耦合一团，改一处牵全身。

挑战：(1) 概念语义随语境漂移；(2) 团队间模型互相污染；(3) 统一企业数据模型代价高且常常失败；(4) 边界划错导致大泥球。

## 二、核心原理

限界上下文（Bounded Context）是领域模型的显式边界，边界内术语有唯一、无歧义的定义（通用语言 Ubiquitous Language）。每个上下文拥有自己的模型、自己的「客户」含义。

上下文之间不共享模型，而是通过上下文映射（Context Map）的交互模式连接，常用防腐层（ACL, Anti-Corruption Layer）把外部模型翻译为本上下文的领域对象，避免污染。限界上下文与微服务边界高度吻合：一个上下文常对应一个服务。

上下文映射（Context Map）记录各上下文的关系，常见模式包括：合作关系（Partnership，同进退）、客户-供应商（Customer-Supplier，上游承诺接口）、遵奉者（Conformist，下游照搬上游模型）、防腐层（ACL，下游自建翻译隔离）、共享内核（Shared Kernel，谨慎共享一小部分）、分离方式（Separate Ways，彻底不连）。选错模式会导致不必要的耦合或重复。限界上下文与团队边界（康威定律）常重合：一个上下文由一个团队拥有，模型语义由该团队与领域专家共同维护的「通用语言」界定。当组织扩张，原单一上下文裂变为多个时，应同步重划模型边界，而不是强行在一个大模型里用包名区分——那只是伪装的解耦。实践中，事件风暴（Event Storming）工作坊是划定上下文的高效方法：贴出领域事件、命令、聚合，自然涌现出的聚类即候选上下文，再以「沟通成本与变更频率」微调边界。需要警惕的是，上下文不是越细越好：过多小上下文会带来大量 ACL 与集成成本，应在「语义清晰」与「集成开销」间折中。

上下文映射（Context Map）记录各上下文的关系，常见模式包括多种。
合作关系（Partnership）指两上下文同进退，共享成功与失败；客户-供应商（Customer-Supplier）中上游承诺接口契约。

## 三、形式化与数学基础

设上下文 $C_i$ 含模型 $M_i$ 与术语集 $T_i$。在 $C_i$ 内，术语到概念的映射唯一：

$$meaning: C_i \times T_i \to concept_i \quad \text{为单射（无歧义）}$$

跨上下文转换由 ACL 提供翻译函数：

$$translate: M_j \to M_i$$

保证外部模型进入本上下文时被规约为本上下文的概念，内部模型不被外部结构侵蚀。

## 四、代码实现

```python
# 销售上下文的 Customer 与物流上下文的 Customer 各自独立建模
class SalesCustomer:
    id: str
    credit_level: str
    opportunities: list

class ShipCustomer:
    id: str
    delivery_address: str

# 防腐层：把外部模型翻译为本上下文对象，隔离差异
class ShippingACL:
    def to_shipping_customer(self, c: SalesCustomer) -> ShipCustomer:
        return ShipCustomer(id=c.id, delivery_address=c.delivery_address)
```

注意：ACL 是单向适配器，下游上下文不直接依赖上游内部结构，仅消费翻译后的本上下文对象。

## 五、与其他技术对比

| 思路 | 模型数量 | 语义 | 耦合 |
|------|----------|------|------|
| 统一企业模型 | 1 | 常冲突 | 高 |
| 限界上下文 | 多 | 各自清晰 | 低（经映射） |
| 微服务 | 多 | 清晰 | 低 |

## 六、常见误区

- 强行统一全公司「一词一义」：违背语境差异，最终模型崩坏。
- 上下文过大：重蹈大泥球，失去边界意义。
- 上游模型直接进下游：无 ACL，下游被污染。
- 把限界上下文等同于团队组织而忽略模型语义：应以模型边界为准。

## 九、演进与趋势

领域故事讲述（Domain Storytelling）、事件风暴（Event Storming）成为划定上下文的协作方法；组织与上下文的对应（康威定律）被广泛用于服务拆分。具体以官方最新实践为准。

## 十、小结

以显式边界隔离模型语义，用上下文映射（尤其防腐层）连接彼此。限界上下文让「一词多义」成为受控事实，是大型领域建模的基石。
