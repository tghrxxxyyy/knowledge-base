# 聚合根

> 对应 Evans《Domain-Driven Design》第6章、Vernon《Implementing DDD》。

## 一、背景与挑战
领域对象互相引用形成网状图，事务边界与一致性边界不清，导致并发修改冲突与级联更新失控。

## 二、核心原理
聚合（Aggregate）是一组相关对象的边界，聚合根（Aggregate Root）是外部唯一可引用的入口。对聚合的修改通过根进行，保证内部 invariants 一致；一个事务只改一个聚合。

## 三、形式化 / 数学基础
聚合 $A=(root, \{child\})$。一致性规则：对 $A$ 的任何操作 $op$，结束后 $invariant(A)=true$。跨聚合一致性通过最终一致事件达成，不在单事务内强一致。

## 四、代码实现
```python
class Order:                      # 聚合根
    def __init__(self): self.items = []
    def add_item(self, p, qty):
        if self.total_qty() + qty > MAX:
            raise BusinessError("超限")
        self.items.append(Line(p, qty))
```

## 五、与其他技术对比
与"一个表一个事务"相比，聚合明确一致性边界；与实体不同，聚合根额外承担边界守卫职责。

## 六、常见误区
误区：聚合设计过大（近乎全表）导致锁竞争。误区：让外部直接引用聚合内子实体。

## 十、小结
聚合根是一致性边界入口，事务只跨一个聚合。
