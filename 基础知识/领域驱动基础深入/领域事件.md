# 领域事件

> 对应 Evans《Domain-Driven Design》"Domain Events"、Vernon 补充。

## 一、背景与挑战
领域中的重要事实（订单已支付、库存已扣减）需要通知其他上下文，但直接在领域对象里调用其他服务会破坏纯净与耦合。

## 二、核心原理
领域事件是对"已经发生的事实"的命名表达，过去时（OrderPaid）。领域层只发布事件，由应用层或订阅方响应，解耦跨聚合/跨上下文协作。

## 三、形式化 / 数学基础
事件 $e=(type, occurredAt, payload, aggregateId)$。订阅处理满足最终一致：$handle(e)$ 在有限延迟后使下游状态收敛，不影响事件发布方事务。

## 四、代码实现
```python
@dataclass
class OrderPaid:
    order_id: str
    amount: int

class Order:
    def pay(self):
        self.status = "PAID"
        self.events.append(OrderPaid(self.id, self.total))
# 应用层：publish(order.events)
```

## 五、与其他技术对比
与领域命令（Command，意图）相对：事件表"已发生"。与消息队列解耦但事件更偏业务语义。

## 六、常见误区
误区：把事件当命令（命名用将来时、含意图）。误区：在事件发布前就调用外部副作用。

## 九、演进与趋势

## 十、小结
用过去时事件解耦上下文，发布与处理最终一致。
