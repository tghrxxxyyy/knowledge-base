# 写时复制与页表权限

> 对应 Bovet & Cesati《Understanding the Linux Kernel》第 9 章与 Bryant & O'Hallaron《CSAPP》第 9 章。

## 一、背景与挑战
COW 如何在不修改应用的前提下"拦截"写入并复制？答案是利用 MMU 的页表权限位：把共享页设为只读，硬件在写时抛异常，内核接管完成复制。

## 二、核心原理
PTE 的 R/W 位为 0 且带 COW 标志时，CPU 写操作触发 `#PF`，错误码表明"写访问只读页"。内核查 `vm_area` 的 `VM_MAYWRITE` 与 COW 标记，分配新页、`copy_page`、更新写者 PTE 为可写、减原页 `refcount`，返回重试写指令。

## 三、形式化与数学基础
设页 $i$ 被 $k$ 个映射共享，写者 $w$ 触发：
$$k>1 \Rightarrow new = alloc();\ copy(new, i);\ PTE_w \leftarrow new,W=1;\ k \mathrel{-}= 1$$
$$k=1 \Rightarrow PTE_w.W = 1$$（仅去掉只读，无需复制）。故仅首写复制，后续写直接进行。

## 四、代码实现
```c
// 内核 do_wp_page 伪逻辑
if (page_count(old) > 1) {
    new = alloc_page();
    copy_page(new, old);          // 物理复制一页
    pte = mk_pte(new, vma->vm_page_prot | WRITE);
} else {
    pte = pte_mkwrite(pte);       // 仅提升权限
}
```

## 五、与其他技术对比
COW 用只读+异常实现惰性复制，相较显式深拷贝需语言支持；相较 vfork 共享，COW 保留独立语义且硬件强制。

## 六、常见误区
误以为 COW 由库实现：是内核+MMU 硬件机制。误以为只读映射能 COW 写：无 VM_MAYWRITE 会 SIGSEGV。误以为大页 COW 只复制改动部分：通常整大页复制。

## 七、与开源书/权威来源对应
Bovet & Cesati 第 9 章 do_page_fault/do_wp_page；CSAPP 9.6 缺页与保护。

## 八、面试题
问：COW 怎么知道该复制而不是报错？答：PTE 的 COW 标记 + vma 可写权限。问：refcount 作用？

## 九、演进与趋势
THP 下 COW 需先把大页拆小页再复制；userfaultfd 的 UFFDIO_COPY 把 COW 交用户态。

## 十、小结
COW 借页表只读位与缺页异常把"复制"推迟到真正写入，是惰性资源管理的典范。
