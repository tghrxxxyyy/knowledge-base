# 写时复制与页表权限

> 对应 Bovet & Cesati《Understanding the Linux Kernel》第 9 章（`do_page_fault`/写保护页处理）与 Bryant & O'Hallaron《CSAPP》第 9 章。

## 一、背景与挑战

COW 要在**不修改应用程序**的前提下「拦截写入并复制」。内核的做法是利用 MMU 的页表权限位：把共享页设为只读，硬件在写入时自动抛异常，内核接管完成复制。做不到这一点，COW 就得依赖语言或库的显式支持（如引用计数式 API 约束）。

这条路径要求三件事同时成立：PTE 的写权限位可被内核翻转；缺页异常能区分「写只读页」与「真非法访问」；内核有足够信息（引用计数、VMA 权限）判断该页是否属于 COW。任一条不成立，就退化为 `SIGSEGV` 或错误复制。

## 二、核心原理

COW 的判定与处理流程（以 Linux 为例）：

1. fork 时 `copy_page_range` 逐级复制页表，对每个**私有且可写**的 PTE 清掉写位并标记为 COW，同时把页的 `_refcount` 加一。
2. 写者执行写指令，MMU 检查 PTE：`W=0` 而访问是写，抛出 `#PF`。
3. `do_page_fault` 解析错误码，识别出「present + write + user」组合，进入写保护缺页路径。
4. 内核判断该 VMA 是否允许写（`VM_WRITE`）以及该页是否为 COW 页：
   - 匿名 COW 页且 `refcount > 1`：分配新页、`copy_page` 复制内容、写者 PTE 指向新页并置 `W=1`、原页计数减一；
   - COW 页但 `refcount == 1`：只需打开写权限，无需复制；
   - `MAP_PRIVATE` 的文件映射：从页缓存复制一份匿名私有副本，后续写不回写文件；
   - VMA 不可写或页不是 COW：投递 `SIGSEGV`。
5. 返回用户态重试那条写指令，此时 PTE 已可写，后续写不再触发缺页。

关键细节：**是 VMA 的权限而非 PTE 的权限决定访问是否合法**。PTE 上的只读只是实现 COW 的手段，内核把它与 `VM_WRITE` 区分开，这正是不能简单地把只读页映射成可写的原因。

## 三、形式化与数学基础

设页 $p$ 被 $k = refcount(p)$ 个映射共享，写者 $w$ 触发缺页后：

$$k > 1 \;\Rightarrow\; p' = alloc();\ copy(p',p);\ PTE_w \leftarrow (p', W{=}1);\ k' = k-1$$

$$k = 1 \;\Rightarrow\; PTE_w.W \leftarrow 1 \quad(\text{仅提升权限，不复制})$$

由此得到两条推论：**首写复制、续写直通**（复制只发生一次，后续写不再缺页）；**总复制量有上界**（$n$ 个写者各自首次写一页，最多复制 $n$ 页）。缺页成本可写作

$$C_{COW} = C_{fault} + [\,k > 1\,]\cdot C_{copy}$$

$C_{copy}$ 与页大小成正比，因此 2 MiB 透明大页上的一次 COW 复制代价是 4 KiB 页的 512 倍——这解释了 THP 为何放大 COW 开销。

## 四、代码实现

```c
/* 内核写保护缺页处理的主干（伪代码，贴近 Linux 结构） */
static int do_wp_page(struct vm_fault *vmf) {
    struct page *old = vmf->page;
    struct vm_area_struct *vma = vmf->vma;

    if (unlikely(!(vma->vm_flags & VM_WRITE)))
        return VM_FAULT_SIGSEGV;                 /* 真的不许写 */

    if (page_count(old) == 1) {
        /* 独占页：只打开写权限，避免无谓复制 */
        pte_t entry = pte_mkwrite(pte_mkdirty(vmf->orig_pte));
        set_pte_at(vma->vm_mm, vmf->address, vmf->pte, entry);
        update_mmu_cache(vma, vmf->address, vmf->pte);
        return 0;
    }

    /* 共享页：分配新帧并复制整页 */
    struct page *new = alloc_page(GFP_HIGHUSER_MOVABLE);
    copy_user_highpage(new, old, vmf->address, vma);
    pte_t entry = pte_mkwrite(pte_mkdirty(mk_pte(new, vma->vm_page_prot)));
    set_pte_at(vma->vm_mm, vmf->address, vmf->pte, entry);
    page_remove_rmap(old, false);                /* 解除旧映射 */
    put_page(old);                               /* 计数减一，可能释放 */
    return 0;
}
```

`MAP_PRIVATE` 的文件映射走另一条路：从页缓存复制出一份匿名页，之后写不落盘——这正是「写时复制」在文件映射上的体现。

## 五、与其他技术对比

| 维度 | 页表 COW | 引用计数式用户态 COW | 显式深拷贝 | vfork 共享地址空间 |
| --- | --- | --- | --- | --- |
| 触发方式 | MMU 缺页异常 | 库代码检查计数 | 调用方显式复制 | 无（直接共享） |
| 应用是否需改代码 | 不需要 | 需要（用其类型/API） | 需改调用 | 需要（禁止写） |
| 复制粒度 | 页（4 KiB / 2 MiB） | 对象/缓冲 | 对象 | 无 |
| 能否拦截任意写 | 是（硬件强制） | 否（绕过 API 即失效） | 否 | 否 |
| 并发正确性 | 内核保证 | 需原子计数 | 由调用方保证 | 不适用 |
| 主要开销 | 缺页 + 页复制 | 原子操作 | $O(n)$ 复制 | 无（语义受限） |

## 六、常见误区

- **「COW 是库实现的」**：在内核语境下它是内核加 MMU 的硬件机制，无需应用配合。
- **「只读映射也能 COW 写」**：若 VMA 不含 `VM_WRITE`（代码段、只读文件映射），写会直接 `SIGSEGV`，不复制。
- **「大页 COW 只复制改动的字节」**：页是复制的最小粒度，THP 上通常整页复制（部分实现会先拆分）。
- **「`refcount > 1` 就必须复制」**：还要看页是否被标记为 COW 以及 VMA 权限；只读共享页不参与 COW。
- **「缺页处理完就再也不缺页」**：之后的 `mprotect`、`mremap`、换出换入、再次 fork 都可能重新引入写保护缺页。

## 八、面试题

**Q1：内核怎么知道该复制而不是报错？**
要点：结合 VMA 的 `VM_WRITE`/`VM_MAYWRITE` 与页是否为 COW 页；权限允许写且是 COW 页就复制，否则 `SIGSEGV`。

**Q2：页的 `refcount` 在 COW 中起什么作用？**
要点：>1 说明有他人共享，必须复制；==1 表示独占，只需打开写权限。

**Q3：为什么 COW 的复制只发生一次？**
要点：复制后写者持有独占页且 PTE 已可写，后续写不再触发缺页。

**Q4：THP 为什么让 COW 变贵？**
要点：复制粒度从 4 KiB 变成 2 MiB，一次首写要复制整页，还可能触发大页拆分。

**Q5：`MAP_PRIVATE` 的文件映射写入会改文件吗？**
要点：不会。写触发缺页后从页缓存复制出匿名私有页，改动不回写文件。

## 九、演进与趋势

- **THP 下的优化**：拆分大页再复制、对小范围写优先拆页，降低单次复制量；`MADV_NOHUGEPAGE` 可让特定区间回避大页。
- **userfaultfd**：把缺页处理交给用户态，可实现自定义 COW（进程迁移、检查点、内存去重）。
- **多映射与共享内存**：`memfd`、`shmem` 与 KSM 都建立在「只读共享 + 写时拆分」之上，KSM 还会主动合并内容相同的匿名页。
- **安全加固**：`MADV_WIPEONFORK` 让敏感页在 fork 后于子进程中变为零页，避免密钥被继承。
- **硬件辅助**：部分平台在 PTE 上提供更丰富的软件位与原子更新原语，减少 COW 路径上的锁与 TLB 冲刷。

## 十、小结

COW 依靠页表只读位与缺页异常把复制推迟到真正写入：应用无需改代码，硬件负责拦截，内核负责判定与复制。它的三个判断要素是 VMA 权限、COW 标记与引用计数；三个成本来源是缺页、页复制与 TLB 影响。理解这些才能解释 `SIGSEGV` 与 COW 的边界，以及大页为何显著放大 COW 开销。
