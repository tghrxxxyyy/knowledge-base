# 轮询与一致性哈希

> 对应负载均衡调度算法；一致性哈希（Karger 1997）。

## 一、背景与挑战
如何把请求均匀且稳定地分到后端？简单轮询忽略后端异构；普通哈希在节点增减时会使几乎全部映射失效，导致大面积缓存击穿。

## 二、核心原理
轮询（Round-Robin）与加权轮询（WRR）按序或权重分配。一致性哈希（Consistent Hashing）把节点与 key 映射到同一哈希环，key 顺时针找最近节点；节点增减仅影响环上相邻区间，迁移最小化。虚拟节点（vnode）平摊负载不均。

## 三、形式化 / 数学基础
普通哈希节点变更影响比例：$\approx 1 - 1/N$（N 为节点数），几乎全部 key 重映射。
一致性哈希：新增 1 节点仅迁移 $1/(N+1)$ 的 key。
虚拟节点：节点 i 复制 $v$ 个 vnode，key 数方差随 v 增大而降低。

## 四、代码实现
```python
import hashlib
def node_for(key, nodes, vnodes=100):
    ring = {}
    for n in nodes:
        for v in range(vnodes):
            h = int(hashlib.md5(f"{n}#{v}".encode()).hexdigest(), 16)
            ring[h] = n
    hk = int(hashlib.md5(key.encode()).hexdigest(), 16)
    for h in sorted(ring):
        if hk <= h:
            return ring[h]
    return ring[min(ring)]   # 环回绕
```

## 五、与其他技术对比
轮询简单但无状态亲和；一致性哈希提供“最小迁移 + 可预测亲和”，适合缓存/有状态服务。对比最少连接（LC）按实时负载调度。

## 六、常见误区
误区一：一致性哈希节点变更多全量重映射。错，只动相邻区间。误区二：不用虚拟节点也均匀。错，节点少时分布偏斜大。误区三：哈希环解决负载。错，仅决定归属，需 vnode 平衡。

## 十、小结
轮询追求均匀、一致性哈希追求稳定最小迁移，虚拟节点补齐均衡，是有状态调度的核心算法。
