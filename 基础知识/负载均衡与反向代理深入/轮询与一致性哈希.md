# 轮询与一致性哈希

> 对应 Karger et al. 1997 *Consistent Hashing and Random Trees*（STOC）、Mitzenmacher 2001 *The Power of Two Choices in Randomized Load Balancing*（IEEE TPDS）与 Eisenbud et al. 2016 *Maglev*（NSDI）。

## 一、背景与挑战

「把请求均匀且稳定地分到后端」包含两个互相冲突的目标：**均匀**（负载贴合权重）与**稳定**（节点变化时尽量少迁移）。简单轮询只满足前者且忽略后端异构；简单取模两者都不满足——节点数从 $N$ 变成 $N+1$ 会让几乎全部键重新映射，在有状态服务或缓存集群上引发大面积击穿。

一致性哈希用哈希环同时逼近两个目标：节点与键映射到同一环，键归其顺时针最近节点所有，节点增减只影响环上相邻区间。它不解决「后端实时过载」的问题，那是自适应调度的事。

## 二、核心原理

**静态调度算法**（不看实时负载）：轮询（RR）按序分配，简单但要求后端同构；加权轮询（WRR）按权重分配，平滑实现可避免短时间连续命中同一节点；哈希按五元组或业务键映射，天然具备亲和性。

**动态调度算法**（看实时状态）：最少连接（LC）与加权最少连接（WLC）把新请求给并发连接最少者，能自然吸收慢节点；最短响应时间以延迟为反馈，对抖动敏感；**两随机取优**随机取两个节点选负载较低者，只用极少信息就把最大负载显著压低。

**一致性哈希的实现要点**：

- 环上节点用哈希值定位，键顺时针找第一个节点；
- **虚拟节点（vnode）**：每个物理节点注册 $v$ 个环上位置，把粒度从「按节点」细化到「按分片」，显著降低负载方差；
- **有界负载一致性哈希**：查找时跳过超过平均负载常数倍的节点，兼顾稳定与均衡；
- **Maglev 哈希**：预计算固定大小的查找表，查找 $O(1)$ 且节点变化时尽量少改槽位，实现极低延迟与最小扰动。

## 三、形式化与数学基础

**取模的迁移比例**：节点数 $N \to N+1$ 时，键保持原归属的比例为 $1/(N+1)$，需迁移的比例为

$$P_{migrate} = 1 - \frac{1}{N+1} \approx 1 \quad (N \gg 1)$$

**一致性哈希**：新增 1 个节点时，只有原属该节点在环上前驱区间的键需要迁移，比例为

$$P_{migrate}^{ch} = \frac{1}{N+1}$$

**虚拟节点的方差**：不设 vnode 时环上区间长度方差大、负载标准差与节点数同阶；设每节点 $v$ 个 vnode 后，负载比例的偏差约按 $\sigma_{load} \propto 1/\sqrt{v}$ 下降，但内存与查找成本随之上升、边际收益递减。**有界负载**：设平均负载为 $\bar{L}$、上界系数为 $c$，查找时跳过负载超过 $c\bar{L}$ 的节点；$c \to 1$ 最均衡但易连锁溢出，$c \to \infty$ 退化为普通一致性哈希。

## 四、代码实现

```python
import bisect
import hashlib

def _h(key: str) -> int:
    # 取 64 位哈希作为环上坐标
    return int(hashlib.blake2b(key.encode(), digest_size=8).hexdigest(), 16)

class Ring:
    def __init__(self, nodes, vnodes=128):
        self.vnodes, self.ring, self.keys = vnodes, {}, []
        for n in nodes:
            self.add(n)

    def add(self, node):
        for v in range(self.vnodes):
            pos = _h(f"{node}#{v}")
            self.ring[pos] = node
            bisect.insort(self.keys, pos)

    def remove(self, node):
        for v in range(self.vnodes):
            pos = _h(f"{node}#{v}")
            self.ring.pop(pos, None)                 # 摘除时同步删除环上位置
            i = bisect.bisect_left(self.keys, pos)
            if i < len(self.keys) and self.keys[i] == pos:
                self.keys.pop(i)

    def locate(self, key):
        i = bisect.bisect_left(self.keys, _h(key))
        if i == len(self.keys):     # 环回绕：命中最小哈希值的 vnode
            i = 0
        return self.ring[self.keys[i]]

def pick_two(pool, load, rng):
    # 两随机取优：只多一次采样即可显著压低峰值负载
    a, b = rng.randrange(len(pool)), rng.randrange(len(pool))
    return pool[a] if load(pool[a]) <= load(pool[b]) else pool[b]
```

## 六、常见误区

- **「一致性哈希节点变更是全量重映射」**：只有环上相邻区间受影响，迁移比例为 $1/(N+1)$。
- **「不用虚拟节点也很均匀」**：节点数少时环上区间方差很大，个别节点可能承担数倍平均负载。
- **「哈希环能解决负载不均」**：环只决定归属、不感知实时负载；热点键必须靠 vnode、有界负载或两级路由解决。
- **「轮询就够用了」**：后端异构或存在慢节点时，轮询会持续把请求压给坏节点，应改用加权或最少连接。
- **「有了哈希就不需要健康检查」**：节点不健康时必须主动摘除并触发重新映射，否则请求持续失败。

## 七、与开源书·权威来源对应

- **Karger et al. 1997（STOC）**：一致性哈希原始论文，给出虚拟节点与最小迁移的分析。
- **Mitzenmacher 2001（IEEE TPDS）**：两随机取优，证明极少量信息即可大幅降低最大负载。
- **Eisenbud et al. 2016（NSDI）**：Maglev 的查表式一致性哈希与工程可靠性设计。
- **Thaler & Ravishankar 1998（IEEE/ACM ToN）**：最高随机权重（rendezvous/HRW）哈希，无需环结构即可实现最小扰动映射。
- **Kurose & Ross《Computer Networking: A Top-Down Approach》**：应用层与 CDN 章节对调度与重定向的讨论。
- **Nginx / Envoy / HAProxy 官方文档**：`hash ... consistent`、`ring_hash`、`maglev` 等策略的语义与限制，以官方最新文档为准。

## 八、面试题

**Q1：一致性哈希解决什么问题？**
要点：在节点动态变化时最小化键的重映射，同时保持较好的负载分布，用于缓存、分片与有状态服务的路由。

**Q2：为什么需要虚拟节点？**
要点：不设 vnode 时环上区间长度方差大、节点少时严重偏斜；vnode 细化粒度，偏差约按 $1/\sqrt{v}$ 缩小。

**Q3：取模哈希为什么在扩容时是灾难？**
要点：$N \to N+1$ 时约 $N/(N+1)$ 的键改变归属，缓存全部失效，后端要承受同步的缓存重建压力。

**Q4：轮询与最少连接如何选择？一致性哈希能保证不超载吗？**
要点：后端同构且请求代价相近时用轮询（开销最小），后端异构或存在长连接、慢查询时用最少连接或加权算法；一致性哈希只决定归属，热点键仍会压垮单节点，需配合有界负载一致性哈希、vnode 或两级路由。

## 九、演进与趋势

- **有界负载一致性哈希与查表式哈希**：前者以平均负载的常数倍为上限兼顾均衡与稳定，后者（Maglev）用预计算表换取 $O(1)$ 查找与最小扰动，适配软件负载均衡器的高包速率要求。
- **去中心化选择与实时反馈**：Rendezvous（HRW）哈希无需维护环即可实现最小扰动；同时把实时延迟、队列深度引入调度，应对热点与慢节点。
- **与 eBPF 结合**：在内核态完成哈希与转发，配合控制面下发的表结构，兼顾性能与灵活性。

## 十、小结

轮询追求均匀、一致性哈希追求稳定最小迁移，二者解决不同问题；虚拟节点补齐了一致性哈希的均衡短板。工程上通常组合使用：先按业务键做一致性哈希确定候选集合，再在候选内用两随机取优或最少连接处理实时负载，最后由健康检查剔除坏节点。任何哈希算法都不能替代负载感知与故障摘除。
