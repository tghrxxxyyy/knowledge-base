# 四层与七层负载均衡

> 对应 L4（传输层）/ L7（应用层）负载均衡实践；RFC 3232（端口概念）。

## 一、背景与挑战
流量需要分发到多后端。四层只看 IP/端口，转发快但无法理解内容；七层能解析 HTTP 等协议做智能路由，但开销更大。

## 二、核心原理
L4（DSR / NAT / Tunnel 模式）基于 IP + TCP/UDP 端口做转发，不解析 payload，性能极高。L7 终止（或透传）应用协议，按 Host、URL、Header、Cookie 路由，支持重写、压缩、WAF。

## 三、形式化 / 数学基础
L4 决策元组：$(srcIP, srcPort, dstIP, dstPort, proto)$。
L7 路由规则：$route = f(HTTP.method, HTTP.host, HTTP.path, headers)$。
NAT 模式后端回包需经 LB（全程代理）；DSR（Direct Server Return）后端直回客户端，LB 仅改 MAC。

## 四、代码实现
```nginx
# 七层：按 Host 分流
upstream api { server 10.0.1.10; server 10.0.1.11; }
server {
    location /api/ { proxy_pass http://api; }
}
# 四层：stream 模块按端口转发
stream { server { listen 3306; proxy_pass mysql_backend; } }
```

## 五、与其他技术对比
L4 快但“盲”；L7 智能但多解析成本。云厂商常 L4 做集群入口、L7 做业务路由。对比 DNS LB（更外层、更粗）。

## 六、常见误区
误区一：L7 一定慢到不能用。错，现代 LB（Envoy、Nginx）可线速。误区二：L4 不能做会话保持。错，可基于源 IP/连接做。误区三：反向代理等于负载均衡。错，反代侧重“代表后端”，LB 侧重“分发”。

## 九、演进与趋势
eBPF/XDP 实现内核态 L4 高速转发；服务网格（sidecar）把 L7 能力下沉到数据面。

## 十、小结
L4 按元组转发、极致性能；L7 解析应用协议、智能路由，二者按场景组合。
