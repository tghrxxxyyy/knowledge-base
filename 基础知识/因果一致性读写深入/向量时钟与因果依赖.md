# 向量时钟与因果依赖

> 对应 Lamport 1978「Time, Clocks, and the Ordering of Events in a Distributed System」；Mattern 1988 关于向量时钟的刻画；Shapiro et al. 2011「Conflict-free Replicated Data Types」。

## 一、背景与挑战

要判断两个事件是否因果相关，单计数器（Lamport 时钟）不够：它只能保证 $a \to b \Rightarrow C(a) < C(b)$，反之不成立，因而无法区分「因果」与「并发」。向量时钟为每个节点维护一个逻辑时间数组，精确编码因果偏序：既能判定 $a$ 是否因果先于 $b$，也能判定二者并发。代价是元数据随节点数 $N$ 线性增长，且节点动态加入/退出时需要解决分量映射问题。核心挑战是在「判定精度」与「元数据开销」之间取舍。

## 二、核心原理

每个节点 $i$ 维护向量 $V_i$：本地事件使 $V_i[i] \mathrel{+}= 1$；发送消息时把当前向量随消息带出；接收消息时先 $V_i[i] \mathrel{+}= 1$，再对每个分量取 $\max(V_i[j], V_{msg}[j])$。对两个向量 $V, W$：若 $V \le W$ 且 $V \ne W$，则 $V$ 因果先于 $W$；若 $V \ge W$，则相反；否则二者并发。实现上「记录依赖」与「合并依赖」是同一算子 $\max$，因此向量时钟天然适合做因果依赖的元数据载体，也是 CRDT 与因果一致存储的基础设施。

## 三、形式化与数学基础

定义逐分量偏序：

$$ V \le W \iff \forall j,\; V[j] \le W[j] $$

强序（因果先于）与并发：

$$ V < W \iff V \le W \land V \ne W \qquad V \parallel W \iff \neg(V \le W) \land \neg(W \le V) $$

合并算子为逐分量取大：$(V \sqcup W)[j] = \max(V[j], W[j])$，它满足交换律、结合律、幂等律，故 $(\mathbb{N}^N, \sqcup)$ 构成 join 半格。维数 $N$ 对应参与节点数，空间与消息开销均为 $O(N)$。经典定理：向量时钟完整刻画 happens-before，即 $V(a) < V(b) \iff a \to b$；这比 Lamport 时钟的单向蕴含更强。

## 四、代码实现

```python
# 向量时钟：本地事件、收发消息、因果比较
class VectorClock:
    def __init__(self, nid, n):
        self.nid, self.v = nid, [0] * n

    def tick(self):                    # 本地事件 / 发送前
        self.v[self.nid] += 1
        return list(self.v)

    def send(self):
        self.tick()
        return {"from": self.nid, "vc": list(self.v)}

    def recv(self, msg):               # 接收：逐分量取 max 后本地自增
        for j, x in enumerate(msg["vc"]):
            if x > self.v[j]:
                self.v[j] = x
        self.tick()

    def merge(self, other):            # 依赖合并，也是半格 join
        self.v = [max(x, y) for x, y in zip(self.v, other)]

# 判定：先于 / 并发
def lt(a, b):
    return all(x <= y for x, y in zip(a, b)) and a != b

def concurrent(a, b):
    return not lt(a, b) and not lt(b, a)
```

注意 `tick` 与 `recv` 的顺序：接收时先合并再自增，才能保证消息事件严格晚于其发送事件。

## 六、常见误区

1. 认为向量时钟可无限扩展：节点数增大时空间与带宽开销显著，需要压缩或分片。
2. 忽略节点增删的映射：必须用稳定 id 加版本号管理分量，否则旧向量无法比较。
3. 用向量时钟做精确全序：它给出的是偏序，并发事件之间没有顺序。
4. 收发处理顺序颠倒：接收时必须先合并再自增，否则因果判定出现漏判。
5. 把向量时钟当物理时钟用：它是逻辑量，不能用于时间间隔或超时判断。

## 七、与开源书·权威来源对应

- Lamport 1978 提出 happens-before 偏序与逻辑时钟，是本章的理论起点。
- Mattern 1988 给出向量时钟对因果关系的完整刻画，明确「完整」含义。
- Shapiro et al. 2011 用向量时钟定义 CRDT 中的并发关系。
- Kleppmann《Designing Data-Intensive Applications》第9章讲解向量时钟与因果。
- 具体实现的元数据压缩方案，以各系统官方最新文档为准。

## 八、面试题

1. 如何判断两个事件并发？——两者向量互不 $\le$，即 $\neg(V \le W) \land \neg(W \le V)$。
2. 向量时钟为何能完整判定因果，而 Lamport 时钟不能？——前者记录每个节点的独立分量，后者只保留一个上界。
3. 接收消息时的正确操作顺序？——先逐分量取 max 合并，再本地自增。
4. 向量时钟的主要成本是什么？——空间与消息均为 $O(N)$，N 为节点数。
5. 为什么 $(\mathbb{N}^N, \sqcup)$ 是半格？——逐分量 max 满足交换、结合、幂等三律。

## 九、演进与趋势

为降低 $O(N)$ 开销，出现紧凑向量时钟（interval tree clock）、点式版本向量（dotted version vector）、以及仅需追踪「活跃因果边界」的方案。混合逻辑时钟把物理时间与逻辑分量结合，在保留单向因果判定的同时把元数据降到 $O(1)$。具体取舍以官方最新文档为准。

## 十、小结

向量时钟以 $O(N)$ 代价精确编码因果偏序，是因果一致存储与 CRDT 的基石；理解它的半格结构与收发顺序约束，是正确实现因果系统的前提。
