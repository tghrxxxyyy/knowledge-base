# 因果一致性与最终一致性边界

> 对应 Gilbert & Lynch 2002（CAP）与 Vogels 2009。

## 一、背景与挑战
最终一致只承诺「无新写后副本收敛」，不保证任何顺序，用户体验上可能读到「逻辑矛盾」状态。因果一致性是最终一致的一个强化子集，边界在于「是否尊重因果」。厘清边界有助于选模型。

## 二、核心原理
最终一致 ⊆ 因果一致 ⊆ 顺序一致 ⊆ 线性一致（强度递增）。因果一致在分区（P）存在时仍可保可用（AP 系统可达成），而线性一致在分区下需牺牲可用性（CP）。

## 三、形式化与数学基础
一致性层级构成偏序：
\\[
\text{Linearizable} \Rightarrow \text{Sequential} \Rightarrow \text{Causal} \Rightarrow \text{Eventual}
\\]
CAP 定理表明：网络分区下，一致性（C）与可用性（A）不可兼得；因果一致属「弱化 C」以保 A 的可行路径。

## 四、代码实现
```python
# 仅最终一致：写后立即可读任意副本，可能旧
def eventual_read(): return random_replica().get(k)
# 因果一致：需依赖检查（见前文 can_serve）
```

## 五、与其他技术对比
Dynamo 风格纯最终一致易出因果违例；引入向量时钟或依赖即升到因果一致；再引入共识即升到更强模型。

## 六、常见误区
1. 认为最终一致包含因果：反了，因果是最终一致的强化。
2. 认为分区下能保线性一致加可用：违反 CAP。
3. 把「收敛」当「合理」：收敛但逻辑矛盾仍不可用。

## 七、与开源书/权威来源对应
Gilbert & Lynch 2002 证明 CAP；Vogels 2009 列出最终一致变体；DDIA 第9章图示层级。

## 八、面试题
问：因果一致为何能在分区下保持可用？
答：它不要求全局单一序，只保因果闭包，可用 AP 复制达成。

## 九、演进与趋势
「因果加 CRDT」成为边缘或离线优先应用的事实标准。

## 十、小结
因果一致是最终一致到强一致的合理中间层，在 CAP 约束下最大化可用性同时保证逻辑合理。
