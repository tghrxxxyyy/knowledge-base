# 总线仲裁集中式与分布式

> 对应 Tanenbaum《Computer Organization and Design》与 ARM AMBA AXI 规范。

## 一、背景与挑战
多主设备（CPU、DMA、GPU）争用共享总线时，需仲裁器决定谁先获得总线，避免冲突并保证公平与带宽。

## 二、核心原理
集中式仲裁由单一仲裁器收集请求并按策略（固定优先级、轮转、加权）授权。分布式仲裁（如 AXI 的 QoS/仲裁）由各主设备协商或基于令牌，避免单点瓶颈。

## 三、形式化与数学基础
公平轮转保证每主设备平均延迟有界：

    W_i = \sum_{j} (R_j / \sum_k R_k) * L_j

其中 R 为请求率、L 为传输长度，仲裁影响等待分布。

## 四、代码实现
```verilog
// 简化: 轮转仲裁器
always_ff @(posedge clk) begin
    if (grant)
        ptr <= ptr + 1;  // 轮到下一个主
    req_reg <= req;
end
assign grant = req_reg[ptr];
```

## 五、与其他技术对比
集中式实现简单、确定性强，但可能成瓶颈；分布式扩展性更好，适合多核/多主 SoC。

## 六、常见误区
误以为高优先级永远先得总线会导致饿死；需加入老化或轮转机制。误以为仲裁只影响延迟不影响正确性。

## 七、与开源书/权威来源对应
AXI 规范描述互联仲裁与 QoS；Tanenbaum 讨论总线集中/分布式仲裁。

## 八、面试题
1. 固定优先级仲裁的缺陷？答：低优先级可能饿死。
2. 如何兼顾公平与实时性？

## 九、演进与趋势
片上网络（NoC）取代共享总线，仲裁变为路由与流控；QoS 精细化。

## 十、小结
总线仲裁在冲突中分配带宽，集中式简单、分布式可扩展，公平与优先级策略决定系统响应。
