# 预算与配额

> 对应资源配额（quota）、预算（budget）与成本治理。

## 一、背景与挑战
多团队共享集群时，缺乏配额会导致某业务吃满资源拖垮其他。预算/配额保障公平与成本可控。

## 二、核心原理
- 配额（quota）：对 CPU/内存/实例数/连接数设上限，防单租户膨胀。
- 预算（budget）：财务/资源月度上限，驱动效率优化。
- 限流（rate limit）：对请求速率设阈值保护下游。
- 优先级与抢占：关键业务优先，低优先可被回收。

## 三、形式化 / 数学基础
- 配额约束：$\sum_i r_{i,k} \le Q_k$（资源 $k$ 总量）。
- 利用率效率 $\eta = \frac{\text{used}}{\text{quota}}$，过低说明超买。
- 限流令牌桶：令牌生成率 $g$，桶容 $B$，瞬时最大突发 $B$。
- 成本 $C = \sum_i (r_{i,cpu}\cdot price_{cpu} + r_{i,mem}\cdot price_{mem})$。

## 四、代码实现
```yaml
# K8s ResourceQuota 示例
apiVersion: v1
kind: ResourceQuota
metadata: {name: team-a}
spec:
  hard:
    requests.cpu: "20"
    requests.memory: 40Gi
    pods: "30"
```

## 五、与其他技术对比
- 配额（硬上限）vs 预算（软目标）：前者防滥用，后者促效率。
- 限流 vs 配额：限流控请求速率，配额控资源占用。
- 无治理：灵活但风险高；强治理：安全但流程重。

## 六、常见误区
- 配额设太大失去意义，太小阻碍业务。
- 只看申请不看实际使用（超买浪费）。
- 限流阈值与系统真实容量脱节。
