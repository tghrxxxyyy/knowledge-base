# 拐点识别

> 对应在压测/监控中识别系统容量拐点（knee point）。

## 一、背景与挑战
系统吞吐随负载上升，但在某点后延迟骤增或错误率飙升，即拐点。准确识别拐点才能设定安全容量与告警阈值。

## 二、核心原理
- 拐点（knee）：吞吐-负载曲线中边际收益骤降、延迟开始非线性上升处。
- 信号：p99 延迟陡升、错误率上升、队列长度增长、CPU 饱和。
- 可用二阶导数/曲率或分段拟合定位。
- 区别于绝对上限（彻底崩溃点）。

## 三、形式化 / 数学基础
- 吞吐曲线 $R(\lambda)$；拐点为 $R''(\lambda)$ 最大负值处（曲率最大）。
- 延迟 $L(\lambda)$ 在 $\rho\to1$ 按 $L \approx \frac{1}{\mu-\lambda}$ 发散。
- 曲率 $\kappa = \frac{|R''|}{(1+R'^2)^{3/2}}$，取峰值定位 knee。
- 安全容量设为拐点 $\lambda^*$ 的某比例（如 70%）。

## 四、代码实现
```python
import numpy as np
def knee(loads, latencies):
    # 用延迟曲线的曲率峰值找拐点
    d1 = np.gradient(latencies, loads)
    d2 = np.gradient(d1, loads)
    curv = np.abs(d2) / (1 + d1**2)**1.5
    return loads[int(np.argmax(curv))]
```

## 五、与其他技术对比
- 固定阈值：简单但不随系统变；拐点动态识别：贴合实际。
- 平均延迟：平滑掩盖；曲率分析：捕捉突变。
- 容量模型预估 vs 实测拐点：应以实测为准。

## 六、常见误区
- 把崩溃点当成安全容量（应留余量）。
- 只看吞吐忽略延迟拐点。
- 单次压测噪声误判拐点（需重复）。

- 队列论 M/M/1 在 $\rho\to1$ 的发散特性。

## 九、演进与趋势
实时拐点检测用于自动限流/扩容；ML 拟合非线性容量曲线。

## 十、小结
拐点识别用曲率/延迟突变定位系统从健康到退化的转折，是设定安全容量与自动防护的依据。
