# 容量模型

> 对应容量规划的数学模型：从需求到资源映射。

## 一、背景与挑战
容量规划回答"需要多大资源支撑目标流量"。错误估计要么浪费成本，要么在峰值宕机。需结合模型与实测。

## 二、核心原理
- 资源维度：CPU、内存、I/O、网络带宽、连接数。
- 线性/次线性扩展假设：先测单实例能力，再按目标乘算。
- 考虑冗余与故障域：N+1、N+2 容错。
- 队列理论估算在利用率高时的延迟膨胀。

## 三、形式化 / 数学基础
- 所需实例数 $N = \lceil \frac{\lambda \cdot D}{C_{per\_inst} \cdot (1 - H)} \rceil$，$D$ 为每请求资源，$H$ 为目标利用率上限。
- M/M/1 平均驻留 $W = \frac{1}{\mu - \lambda}$；利用率 $\rho=\lambda/\mu$。
- 当 $\rho \to 1$，延迟发散，故设 $H<1$（如 0.7）。
- 冗余：$N_{final} = N + R$，$R$ 为容错实例数。

## 四、代码实现
```python
def plan_capacity(qps, per_inst_qps, target_util=0.7,冗余=1):
    need = qps / (per_inst_qps * target_util)
    return ceil(need) + 冗余
# 实测单实例 2000 qps，目标 10000 qps -> ceil(10000/(2000*0.7))+1 = 8
```

## 五、与其他技术对比
- 经验拍脑袋：快但易错；模型+实测：可靠但需数据。
- 静态规划 vs 弹性（见弹性容量）。
- 峰值规划 vs 平均规划：前者贵但安全。

## 六、常见误区
- 用平均流量规划忽略峰值（需按峰值+增长）。
- 假定线性扩展到极高利用率（延迟发散）。
- 忽略非 CPU 瓶颈（连接数、带宽）。
