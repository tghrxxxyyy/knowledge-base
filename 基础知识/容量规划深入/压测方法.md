# 压测方法

> 对应性能压测（load/soak/stress/spike testing）方法论。

## 一、背景与挑战
容量模型需实测验证。压测模拟流量暴露瓶颈、验证 SLA、找出拐点。方法不当会得到虚假"系统很强"。

## 二、核心原理
- 负载测试（load）：预期峰值下验证 SLA。
- 压力测试（stress）：超过预期找上限/拐点。
- 浸泡测试（soak）：长时间运行查内存泄漏/退化。
-  spike 测试：突发流量验证弹性。
- 分布式压测：多机产生足够压力，避免压测机成瓶颈。

## 三、形式化 / 数学基础
- 目标到达率 $\lambda_{target}$；逐步加压 $\lambda_i = \lambda_0 \cdot r^i$。
- 拐点检测：当 $R(\lambda)$ 增长放缓或错误率 $e(\lambda)$ 上升处即拐点 $\lambda^*$。
- SLA 违约：$e > e_{max} \lor p99 > L_{max}$ 判失败。
- 置信：重复 $k$ 次取稳定区间，排除偶发。

## 四、代码实现
```bash
# 用 vegeta 阶梯加压并看延迟/错误
echo "GET http://svc/" | vegeta attack -rate=1000 -duration=30s | vegeta report
# 阶梯：循环提升 rate 直到错误率上升
for r in 500 1000 2000 4000; do
  vegeta attack -rate=$r -duration=1m | vegeta report
done
```

## 五、与其他技术对比
- 基准测试：单组件；压测：端到端系统。
- 单机枪测：易成瓶颈；分布式压测：真实压力。
- 回放（replay）真实流量：最真实但难构造。

## 六、常见误区
- 压测机 CPU 跑满导致测的是压测机而非系统。
- 未用生产近似数据/缓存命中率失真。
- 只看平均忽略错误率与长尾。

## 七、与开源书 / 权威来源对应

- 工具：vegeta、wrk、k6、JMeter 文档。

## 九、演进与趋势
生产流量回放与影子（shadow）压测；基于 SLO 自动停启压测。

## 十、小结
压测用多种形态逼近真实负载，核心是阶梯加压找拐点、长时浸泡查泄漏，并以 SLA 为判据。
