# 写时复制文件系统

> 对应 btrfs 与 ZFS 的 CoW 设计，以及 OSTEP 崩溃一致性讨论。

## 一、背景与挑战
传统原地更新（in-place）易在崩溃时留下半写状态。写时复制（Copy-on-Write）改为“新写新位置、原子切换指针”，天然提供一致性、快照与去重。

## 二、核心原理
- 修改数据块时，分配新块写入，旧块保留至事务提交。
- 树结构（B-tree）根指针原子更新：新根指向新节点链，旧根仍一致。
- 快照 = 保留旧根不回收；克隆/去重共享未改块。

## 三、形式化 / 数学基础
事务提交：新根指针 $R' = f(R, \\Delta)$。提交即“原子写 $R'$”。若崩溃在写 $R'$ 前，旧 $R$ 仍有效（回退到上一事务）；写后则新状态完整。

## 四、代码实现
CoW 提交（示意）：

```c
void cow_commit(tree *old, tree *new) {
    write_nodes(new);            /* 写新节点(不覆盖旧) */
    fsync(new);
    atomic_store(&super->root, new);  /* 原子切根 */
    /* 旧节点在下次回收前保留, 可作快照 */
}
```

## 五、与其他技术对比
日志文件系统先写日志再回写原地；CoW 永不原地改，用指针切换实现原子性，快照近乎零成本，但需垃圾回收（旧块回收）与写放大控制。

## 六、常见误区
- 认为 CoW 不写旧块就无写放大：元数据与碎片化会增加写量。
- 忽略需定期 `balance`/`scrub` 回收。
- 混淆快照与备份：快照不抵御介质损坏（需副本/校验）。

## 九、演进与趋势
btrfs/ZFS 引入校验和树、压缩、去重与发送/接收（send/receive），CoW 成为现代文件系统主流范式。

## 十、小结
写时复制以“新写新块 + 原子切根”替代原地更新，天然一致且快照廉价，代价是写放大与回收复杂度。
