# 空闲空间管理

> 对应 Silberschatz《Operating System Concepts》文件系统章与 OSTEP。

## 一、背景与挑战
文件系统必须快速找到空闲块供新文件使用，并在删除后回收，同时避免碎片与位图不一致。

## 二、核心原理
- 位图（bitmap）：每块 1 bit，0 空闲 1 占用，简单紧凑。
- 空闲链表：把空闲块串成链，或成组链接（UNIX 成组链接法）。
- 日志/树结构（ext4/btrfs）用区间管理连续空闲。

## 三、形式化 / 数学基础
位图大小 $= \\frac{total\\_blocks}{8}$ 字节。分配寻找首个 0 bit 可用 `ffs` 指令；连续分配偏好相邻位以降低碎片。

## 四、代码实现
位图分配首个空闲块：

```c
int alloc_block(uint8_t *bm, int nblocks) {
    for (int i = 0; i < nblocks / 8; i++)
        if (bm[i] != 0xFF) {
            int b = ffs(~bm[i]) - 1;   /* 首个0位 */
            bm[i] |= (1 << b);
            return i * 8 + b;
        }
    return -1;
}
```

## 五、与其他技术对比
位图易持久化、扫描快但大文件系统位图本身不小；成组链接减少元数据但实现复杂；extent 直接记录连续区间。

## 六、常见误区
- 认为空闲块数 = 容量差：还需减去元数据（inode 表、位图自身）。
- 忽略位图与真实分配的一致性需日志保护。
- 把“删除文件”当立即擦除：仅置位图与 unlink。

## 九、演进与趋势
ext4 用区间（extent）描述空闲/已用，btrfs/zfs 用 B-tree 统一管理空间，减少扫描。

## 十、小结
空闲空间管理在“查找速度、元数据开销、碎片”间权衡；位图最常用，extent/树结构适配大容量。
