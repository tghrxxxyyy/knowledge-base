# 目录与路径解析

> 对应 Linux VFS `fs/namei.c` 与 Tanenbaum《Modern Operating Systems》。

## 一、背景与挑战
路径 `/a/b/c` 需逐段在目录中查找下一级 inode。解析要处理“.”“..”、挂载点、符号链接与权限，且需高效缓存。

## 二、核心原理
- 目录本质是“名字→inode 号”的映射表（ext 用线性项，ext4 用哈希树 htree）。
- 路径解析逐级 `lookup`；dentry cache 缓存近期结果。
- 符号链接需循环检测（link count / 解析深度限制）。

## 三、形式化 / 数学基础
路径解析是有限状态机：状态 = 当前目录 inode，读入分量 $c$，查表得 $inode(c)$，遇 `..` 取父。最大解析深度限制（如 40）防止符号链接环。

## 四、代码实现
递归查目录项（示意）：

```c
inode *path_resolve(inode *dir, char *parts[], int n) {
    for (int i = 0; i < n; i++) {
        if (!strcmp(parts[i], "..")) dir = dir->parent;
        else dir = dir_lookup(dir, parts[i]);
        if (!dir) return NULL;
    }
    return dir;
}
```

## 五、与其他技术对比
线性目录查找 O(n) 慢，ext4 htree 把目录做成类 B-tree 达 O(log n)；VFS 用 dentry cache 把常见路径降到近似 O(1)。

## 六、常见误区
- 认为“cd ..”是字符串操作：实际读父目录 inode。
- 忽略挂载点使“..”跨越文件系统边界。
- 符号链接无限循环防护依赖深度计数。

## 九、演进与趋势
VFS 持续强化 RCU 化 dentry 查找以降低锁争用；io_uring 提供异步 path 操作。

## 十、小结
目录是名字到 inode 的映射；路径解析逐级 lookup 并辅以 dentry cache 与链接环检测，把人类路径翻译为 inode。
