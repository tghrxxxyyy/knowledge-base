# 资源有序化

> 对应死锁预防中的“循环等待破坏”与内核锁获取顺序规范。

## 一、背景与挑战
循环等待是死锁四条件中最易在工程上消除的一条：只要所有线程按全局固定顺序获取资源，就不可能形成等待环。

## 二、核心原理
- 给每类资源赋予全局唯一序号。
- 任何线程必须按序号单调递增获取锁；已持高序锁时不得再申请低序锁。
- 该约束在编译期（lockdep）或运行期可被校验。

## 三、形式化 / 数学基础
设资源序函数 $ord:R\\to\\mathbb{N}$。线程持锁序列 $L_1<L_2<\\dots$ 必单调，则等待边只从高序指向尚未持有的更高序，不可能回到低序，故无环、无循环等待。

## 四、代码实现
按序加锁（两锁情形）：

```c
void lock_both(lock *a, lock *b) {
    lock *f = (a->id < b->id) ? a : b;
    lock *s = (a->id < b->id) ? b : a;
    lock(f); lock(s);     /* 总是先小后大 */
}
void unlock_both(lock *a, lock *b) {
    unlock(a); unlock(b);
}
```

## 五、与其他技术对比
相比银行家（需 Max、开销大）与检测（需恢复），有序化在编码期约定、零运行时死锁可能，但要求全局次序且可能降低并发度（粗序锁）。

## 六、常见误区
- 认为“只要加锁就安全”：顺序不一致恰是死锁根源。
- 忽略释放顺序虽不影响死锁，但影响清晰度。
- 在动态资源（如哈希表桶）上需把“地址序”作为稳定序。

## 九、演进与趋势
Linux lockdep 在运行期记录锁依赖图并静态检测“曾出现/可能出现”的逆向边，提前暴露序违规。

## 十、小结
资源有序化通过全局单调获取顺序破坏循环等待，是工程上最常用、零运行时死锁可能的预防手段。
