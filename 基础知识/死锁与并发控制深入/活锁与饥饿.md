# 活锁与饥饿

> 对应并发理论中的 liveness 性质与 Tanenbaum《Modern Operating Systems》。

## 一、背景与挑战
系统未死锁（无环），进程却永远无法前进：饥饿是长期分不到资源；活锁是持续重试却总在错误时机让步，双方都在“忙”却无进展。

## 二、核心原理
- 饥饿（Starvation）：调度/锁策略偏向某些线程，某线程无限等待。
- 活锁（Livelock）：两个线程互相检测冲突并各自退让，循环往复无进展（如走廊互相让路）。
- 二者都违反“必然终将推进”的活性（liveness）。

## 三、形式化 / 数学基础
定义进展谓词 $P(t)$：存在步骤使某请求最终被满足。饥饿 = $\\forall t,\\exists$ 请求在 $[t,\\infty)$ 永不满足；活锁 = 系统状态不断变但目标状态永不达。

## 四、代码实现
退避避免活锁（指数退避示意）：

```c
for (int attempt = 0; ; attempt++) {
    if (try_lock(&l)) break;
    int backoff = rand() % (1 << min(attempt, 10));
    usleep(backoff);     /* 随机退避, 打破对称 */
}
```

## 五、与其他技术对比
死锁完全阻塞；饥饿可运行但饿；活锁在运行却无效。解决：公平队列（FIFO 锁）、优先级老化、随机退避。

## 六、常见误区
- 认为“不死锁就正常”：活锁/饥饿同样无进展。
- 把活锁当死锁调试：CPU 在烧却无产出。
- 忽略优先级反转可引发饥饿。

## 九、演进与趋势
无锁数据结构、自适应互斥与排队锁（MCS/CLH）从机制上降低饥饿与活锁概率。

## 十、小结
活性问题涵盖死锁之外的“饿”与“假忙”：用公平排队、老化与随机退避保证最终进展。
