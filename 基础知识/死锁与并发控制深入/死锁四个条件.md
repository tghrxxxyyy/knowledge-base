# 死锁四个条件

> 对应 Silberschatz《Operating System Concepts》第 7 章死锁与 Tanenbaum《Modern Operating Systems》。

## 一、背景与挑战
多个进程循环等待彼此持有的资源时，系统陷入永久阻塞。Coffman 等人归纳出死锁产生的四个必要条件，缺一不可。

## 二、核心原理
四个条件（Coffman）：
1. 互斥（Mutual exclusion）：资源不可共享。
2. 占有并等待（Hold and wait）：持资时可再申请。
3. 不可抢占（No preemption）：资源只能自愿释放。
4. 循环等待（Circular wait）：存在进程等待环。

## 三、形式化 / 数学基础
用资源分配图 $G=(V,E)$，$V=P\\cup R$。边 $P_i\\to R_j$ 表示请求/分配。死锁 $\\iff$ 图中存在涉及进程的环且每资源实例数为 1（多实例需结合可用量判断）。

## 四、代码实现
检测请求是否可能成环（资源图简化，示意）：

```c
int deadlock_cycle(process *P, int n) {
    /* 反复移除“有未占用资源可满足”的进程, 剩者即死锁 */
    int *alive = calloc(n, sizeof(int));
    for (int chg = 1; chg; ) {
        chg = 0;
        for (int i = 0; i < n; i++)
            if (!alive[i] && has_satisfiable_request(P[i])) {
                alive[i] = 1; chg = 1; release(P[i]);
            }
    }
    for (int i = 0; i < n; i++) if (!alive[i]) return 1;
    return 0;
}
```

## 五、与其他技术对比
破坏任一条件即可防死锁：互斥难破（资源本质），常破“占有等待”（一次性申请）或“循环等待”（资源有序化）。检测+恢复则允许发生再回滚。

## 六、常见误区
- 认为“有环=死锁”：仅单实例资源时成立，多实例需看可用量。
- 混淆死锁与饥饿：饥饿是可运行但长期分不到资源。
- 以为加锁多就安全：顺序不当反而制造循环等待。

## 九、演进与趋势
现代系统多倾向“避免+检测”：数据库用等待图检测，内核锁遵循获取顺序规范以防循环等待。

## 十、小结
死锁须四个条件同时成立；工程上常通过资源有序化（破循环等待）或一次性申请（破占有等待）来预防。
