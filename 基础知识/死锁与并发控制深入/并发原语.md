# 并发原语

> 对应 OSTEP 第 26-31 章“锁与同步”与 Linux `include/linux/mutex.h`。

## 一、背景与挑战
多核并发访问共享数据需原子性、可见性与有序性保证。从原子指令到自旋锁、互斥、信号量、条件变量，构成并发编程的基石原语。

## 二、核心原理
- 原子指令：CAS、原子加（LL/SC 或 x86 LOCK 前缀）。
- 自旋锁：短临界区忙等；互斥（mutex）：长临界区睡眠。
- 信号量：计数资源；条件变量：等待某谓词成立。

## 三、形式化 / 数学基础
临界区互斥可建模为 Peterson 算法（两线程）：
$$flag[i]=1; turn=j; \text{while}(flag[j]\\land turn==j);$$
其正确性依赖原子存储与顺序一致性（或显式内存屏障）保证可见性。

## 四、代码实现
CAS 自旋锁（x86 示意）：

```c
void spin_lock(int *l) {
    while (__sync_val_compare_and_swap(l, 0, 1)) cpu_relax();
}
void spin_unlock(int *l) { __atomic_store_n(l, 0, __ATOMIC_RELEASE); }
```

## 五、与其他技术对比
自旋锁不睡眠、适合极短临界区与不可睡眠上下文；互斥可睡眠、适合长临界区但不可用在中断上下文；RCU 读侧无锁适合读多写少。

## 六、常见误区
- 在中断上下文用可睡眠 mutex：导致调度违例。
- 认为 CAS 一定无锁安全：需正确处理 ABA 与内存序。
- 忽略编译/CPU 重排而漏写屏障/atomic。

## 九、演进与趋势
RCU、seqlock、无锁队列广泛应用；C11/C++11 与 Linux `atomic_t` 提供标准化内存序模型。

## 十、小结
并发原语从原子指令向上构建：自旋锁/互斥管互斥，信号量/条件变量管协作，RCU/原子类型在正确内存序下实现高效无锁读。
