# 缺页异常与按需分页

> 对应 Bryant & O'Hallaron《CSAPP》第 9 章与 Bovet & Cesati《Understanding the Linux Kernel》内存管理章节。

## 一、背景与挑战

如果进程一启动就为整个地址空间分配并填实物理页，内存会被大量零值与从未使用的页浪费，启动也变得极慢。程序实际访问的地址往往只占其声明空间的一小部分（局部性原理），因此理想策略是「用多少、给多少」。

按需分页（demand paging）正是这一思想：虚拟页在首次访问时才为其分配物理帧并建立页表项。驱动这一过程的硬件机制就是缺页异常（page fault）。

## 二、核心原理

访问一个虚拟地址时，MMU 先查 PTE：

1. PTE 不存在（present 位为 0）或权限不符，MMU 触发 `#PF`；
2. CPU 陷入内核，执行 `do_page_fault`；
3. 内核按 VMA 判断访问是否合法，并据原因处理：

   - 匿名页：映射到全局零页，写时再 COW 分配真实帧；
   - 文件映射页：从页缓存取页，未命中则从磁盘读入；
   - COW 页：复制共享页为私有副本；
   - 非法访问（不在任何 VMA 或权限违规）：向进程发送 SIGSEGV。

4. 处理完成后刷新 TLB，重新执行触发异常的指令。

因此「缺页」不等于「错误」——绝大多数缺页是正常的按需分配。

## 三、形式化与数学基础

有效访问时间（Effective Access Time）：

$$ EAT = (1-p)\,T_{hit} + p\,T_{fault} $$

其中 $p$ 为缺页率，$T_{fault} = T_{disk\_read} + T_{map}$ 为一次缺页的总代价（磁盘延迟通常比内存访问慢数个数量级）。

若 $p$ 过高，大量时间耗在换页上，系统吞吐急剧下降，称为**抖动（thrashing）**。工作集模型给出必要条件：

$$ \sum_{i} W_i > M_{total} \Rightarrow \text{thrashing} $$

即所有进程工作集之和超过可用物理内存时，抖动不可避免。局部性原理保证正常工作下 $p$ 很小。

顺序访问时，内核用预读（readahead）把相邻页一并读入，把 $k$ 次缺页合并为约 $k/\text{窗口}$ 次：

$$ p_{seq} \approx \frac{1}{\text{readahead 窗口}} $$

## 四、代码实现

```c
#include <sys/mman.h>
#include <string.h>
#include <stdio.h>

int main(void) {
    size_t n = 1 << 20;   /* 1 MiB */

    /* 映射后尚无物理页，仅登记 VMA */
    char *p = mmap(NULL, n, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (p == MAP_FAILED) return 1;

    /* 首次读：映射到只读零页，不占物理内存 */
    printf("read before write: %d\n", p[0]);

    /* 首次写：触发缺页 -> COW 分配真实帧 -> 写 -> 重试指令 */
    p[0] = 42;

    /* 未触及的页始终不占物理帧 */
    memset(p + 4096, 1, 4096);

    munmap(p, n);
    return 0;
}
```

可用 `/usr/bin/time -v` 观察 `Minor`/`Major page faults` 计数来验证按需分配行为。

## 五、与其他技术对比

| 策略 | 分配时机 | 内存利用 | 延迟特征 | 适用场景 |
| --- | --- | --- | --- | --- |
| 按需分页 | 首次访问 | 高 | 首次访问有缺页延迟 | 通用默认 |
| 预分页/prefetch | 提前批量 | 中 | 降低顺序缺页延迟 | 顺序流 |
| readahead | 内核自预读 | 高 | 平滑顺序缺页 | 文件顺序读 |
| 全量预分配 | 启动时 | 低 | 无缺页但启动慢 | 实时性要求极高 |
| 大页 | 按需但粒度大 | 中 | 缺页次数减少 | 大数据结构 |

## 六、常见误区

- 认为缺页都是错误：正常按需分配也会走缺页路径。
- 认为 SIGSEGV 都是 bug：可能是访问合法 mmap 区之外，属于程序逻辑问题而非内核错误。
- 认为缺页一定读盘：匿名页只是映射零页或分配清零帧，无磁盘 IO。
- 混淆 minor 与 major fault：前者只需内存操作，后者涉及磁盘读入。
- 认为 `malloc` 后内存立即可用且已占物理内存：写之前只是虚拟地址。

## 八、面试题

- 问：首次读匿名映射为何可能共享零页？答：内核先把匿名页映射到只读全局零页，写时才 COW 分配。
- 问：thrashing 是什么？答：工作集超过物理内存导致频繁换页，CPU 大部分时间耗在 IO 上。
- 问：minor fault 与 major fault 的区别？答：是否需要从磁盘读入页。
- 问：readahead 的作用？答：把顺序访问的多次缺页合并，降低有效缺页率。

## 九、演进与趋势

大页与透明大页（THP）减少缺页次数与 TLB 压力；`userfaultfd` 把缺页处理交给用户态，用于虚拟机迁移、内存压缩与快照；内存分层（如 CXL）引入新的缺页代价模型。具体支持以官方最新文档为准。

## 十、小结

缺页异常是「访问触发分配」的机制，让内存按真实使用量增长，是虚拟内存高效的根本。关键在于区分正常缺页与非法访问，并用局部性与预读把有效缺页率压到很低。
