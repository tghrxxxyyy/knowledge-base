# 内存映射与内存保护

> 对应 Bryant & O'Hallaron《CSAPP》第 9 章与 Kerrisk《The Linux Programming Interface》第 49 章。

## 一、背景与挑战
不同内存区域需要不同权限：代码只读可执行、数据可读写、栈不可执行。mmap 的 `PROT_*` 与 `mprotect` 在页表级强制这些保护，错误访问由硬件触发 SIGSEGV。

## 二、核心原理
每 VMA 带 `vm_flags`（如 VM_READ/WRITE/EXEC），映射时写入 PTE 的 R/W/X 位。CPU 取指/读写时 MMU 检查权限，违规则 `#PF` 转内核判为非法，向进程发 SIGSEGV。GRO 数据段常 `PROT_READ|PROT_WRITE` 无 EXEC 防代码注入。

## 三、形式化与数学基础
访问判定：
$$allow(v, op) = vm\_flags(v) \;\&\; perm(op) \ne 0$$
其中 $perm(read)=R, perm(write)=W, perm(exec)=X$。一旦违反：
$$do\_page\_fault \to SIGSEGV$$
且 PTE 的 NX（不可执行）位由硬件强制。

## 四、代码实现
```c
// 分配可执行内存（如 JIT），需显式 PROT_EXEC
void *x = mmap(NULL, N, PROT_READ|PROT_WRITE|PROT_EXEC,
               MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
mprotect(x, N, PROT_READ|PROT_EXEC);  // 写后改为不可写
```

## 五、与其他技术对比
分段（x86 段限长）早期做保护，页式更细粒度统一；W^X（可写或可执不可兼）是安全基线。相较用户态检查，硬件页保护不可绕过。

## 六、常见误区
误以为 PROT_WRITE 必 PROT_READ：某些架构写隐含读，但应显式声明。误以为 mprotect 立刻生效全局：需 TLB 刷新。误以为 NX 防所有注入：还需 ASLR/栈保护。

## 七、与开源书/权威来源对应
CSAPP 9.7 地址翻译与安全（NX/ASLR）；Kerrisk 第 49 章 mprotect。

## 八、面试题
问：写只读映射为何 SIGSEGV？答：PTE 无 W 位，MMU 拒绝。问：W^X 原则？

## 九、演进与趋势
PXN/PAN（内核不可执行/访问用户）防提权；影子栈（CET）保护返回地址；guards 页防栈溢出。

## 十、小结
mmap 权限与 PTE 硬件位把内存保护落到页粒度，是进程隔离与安全执行的基础。
