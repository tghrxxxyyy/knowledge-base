# 内存映射与内存保护

> 对应 Bryant & O'Hallaron《CSAPP》第 9 章虚拟内存与 Kerrisk《The Linux Programming Interface》第 49 章。

## 一、背景与挑战

一个进程的地址空间里同时存在权限迥异的区域：代码段只读可执行、数据段可读写、栈可读写但通常不可执行、只读常量段不可写。若没有硬件级的权限强制，任意一次越界写或错误取指都可能破坏其他区域，甚至被利用来注入代码。

操作系统用「虚拟内存 + 页表权限位」解决这个问题：每个页表项（PTE）携带读/写/执行权限，MMU 在每次访问时检查，违规则触发缺页异常并最终转为 SIGSEGV。mmap 的 `PROT_*` 与 `mprotect` 则是用户态设置这些权限的接口。

## 二、核心原理

每个映射对应一个 VMA（`vm_area_struct`），其中 `vm_flags` 记录 `VM_READ`/`VM_WRITE`/`VM_EXEC` 等标志。建立映射时，这些标志被翻译进 PTE 的 R/W/X 位（在 x86-64 上通过 PTE 的写位与 NX 位表达）。

访问发生时的判定链：

1. MMU 按 PTE 权限检查本次访问类型；
2. 若不满足，产生 `#PF`（page fault）；
3. 内核 `do_page_fault` 判断是「合法的按需填充」还是「真正的权限违规」；
4. 违规则向进程发送 SIGSEGV，默认终止进程。

现代系统遵循 **W^X** 原则：一段内存可写或可执行，但不可同时具备，以阻断「写入 shellcode 再跳转执行」的攻击链。此原则由硬件 NX 位配合内核强制。

## 三、形式化与数学基础

设某 VMA 的标志集合为 $F$，访问操作需要权限 $p$。允许访问的条件为：

$$ \mathrm{allow}(v, p) = \left( F(v) \;\&\; \mathrm{perm}(p) \right) \ne 0 $$

其中 $\mathrm{perm}(\text{read}) = R$、$\mathrm{perm}(\text{write}) = W$、$\mathrm{perm}(\text{exec}) = X$。

违规路径：

$$ \text{access} \to \#PF \to \texttt{do\_page\_fault} \to \text{SIGSEGV} $$

权限变更需刷新 TLB，否则旧权限可能仍被缓存：

$$ \texttt{mprotect}(v, n, \text{new}) \Rightarrow \mathrm{invlpg}/(\text{TLB flush}) $$

W^X 约束可写为：

$$ \neg\left( W \in F(v) \;\wedge\; X \in F(v) \right) $$

## 四、代码实现

```c
#include <sys/mman.h>
#include <stdio.h>

int main(void) {
    size_t n = 4096;

    /* JIT 风格：先可读写填内容，再去掉写权限，保留执行 */
    void *p = mmap(NULL, n, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (p == MAP_FAILED) return 1;

    /* 写入机器码或数据 ... */

    /* 变为只读可执行，满足 W^X */
    if (mprotect(p, n, PROT_READ | PROT_EXEC) != 0) return 2;

    /* 再写会触发 SIGSEGV */
    /* ((char *)p)[0] = 0; */

    munmap(p, n);
    return 0;
}
```

只读数据的保护则相反：`mmap(..., PROT_READ, MAP_PRIVATE, fd, 0)` 后任何写都触发 SIGSEGV。

## 五、与其他技术对比

| 保护机制 | 粒度 | 生效方式 | 能否被用户态绕过 | 典型用途 |
| --- | --- | --- | --- | --- |
| x86 段限长 | 段 | 硬件 | 否 | 早期保护，现基本废弃 |
| 页表权限位 | 页（4 KiB 起） | 硬件 MMU | 否 | 通用内存保护 |
| `mprotect` | 页 | 内核改 PTE | 否 | 动态调整权限 |
| 用户态检查 | 视实现 | 软件 | 是 | 应用层校验 |
| W^X + NX | 页 | 硬件 + 内核 | 否 | 防代码注入基线 |

## 六、常见误区

- 认为 `PROT_WRITE` 必然隐含 `PROT_READ`：部分架构写隐含读，但应显式声明以免移植问题。
- 认为 `mprotect` 立即对所有 CPU 全局生效：需 TLB 刷新，多核下由内核协调。
- 认为有了 NX 就足够安全：还需 ASLR、栈保护、CFI 等多层防御。
- 忘记映射长度按页对齐：`mprotect` 的地址必须页对齐，长度会被向上取整。
- 认为 SIGSEGV 一定来自越界：也可能是合法的权限违规或栈溢出触及保护页。

## 八、面试题

- 问：写只读映射为何 SIGSEGV？答：对应 PTE 无写权限位，MMU 拒绝访问并触发异常。
- 问：W^X 原则是什么？答：同一页不可同时可写与可执行，用于阻断代码注入。
- 问：`mprotect` 后为何要刷 TLB？答：避免旧权限仍被缓存导致检查失效。
- 问：如何实现可执行的匿名内存？答：映射时带 `PROT_EXEC`，写完成后用 `mprotect` 去掉写权限。

## 九、演进与趋势

PXN/PAN 限制内核访问用户页或执行用户代码，防提权；硬件影子栈（如 CET）保护返回地址；保护页（guard page）检测栈溢出；内存标记（如 MTE）提供细粒度标签检查。具体支持以官方最新文档为准。

## 十、小结

mmap 权限与 PTE 硬件位把内存保护落到页粒度，形成进程隔离与安全执行的基础。核心记忆点是三条：权限由硬件强制、变更需刷 TLB、W^X 是防注入的基线。
