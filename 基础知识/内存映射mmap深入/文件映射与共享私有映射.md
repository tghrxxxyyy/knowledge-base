# 文件映射与共享私有映射

> 对应 Kerrisk《The Linux Programming Interface》第 49 章 mmap 标志语义与 Love《Linux Kernel Development》第 15 章。

## 一、背景与挑战

`mmap` 的两个核心标志 `MAP_SHARED` 与 `MAP_PRIVATE` 决定了写操作是否对其他映射者可见、是否最终落盘。它们几乎影响所有上层语义：进程间共享内存、写时复制（COW）、可执行文件的加载、数据库的内存映射文件，都建立在这个开关之上。

误用后果具体而严重：以为改了会落盘却发现文件未变；以为私有映射互不影响却观察到数据竞争；以为共享映射自动持久却丢数据。理解二者的底层差别是正确使用 mmap 的前提。

## 二、核心原理

**MAP_SHARED**：映射页与文件（以及同文件的其他共享映射）是同一份物理页。任一映射者的写都会立即对其他映射者可见；在适当时候（`msync` 或回写）这些改动会写回文件。

**MAP_PRIVATE**：写采用写时复制。首次写某页时，内核复制该页为进程私有副本，修改只对本进程可见，原文件与其它映射者不受影响。只读访问时则与共享映射一样复用同一份页缓存，因而省内存。

这解释了两个典型用法：加载可执行文件与共享库用私有映射（多进程共享只读代码，写时各自隔离，避免污染文件）；进程间共享数据用共享映射（改动互见）。

## 三、形式化与数学基础

私有写触发 COW。对页 $v$ 的首次写：

$$ \text{page}_{priv} = \mathrm{copy}(\text{page}_{shared}), \qquad PTE(v).W \leftarrow 1,\quad \text{COW}(v) \leftarrow 0 $$

共享写则原地修改共享页：

$$ \text{page}_{shared} \leftarrow \text{page}_{shared} \oplus \Delta, \qquad \forall m \in \mathrm{map}(file): m \text{ 可见} $$

回写条件（共享映射）：

$$ \text{file} \mathrel{+}= \Delta \quad \text{当 } msync(\text{MS\_SYNC}) \text{ 或进程/映射退出时} $$

页缓存共享带来的内存节省：若 $k$ 个进程映射同一只读文件区域，物理页占用约为 $O(\text{区域大小})$ 而非 $O(k \times \text{区域大小})$。

## 四、代码实现

```c
#include <sys/mman.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>

int demo_shared(int fd, size_t n) {
    /* 共享映射：两个进程都会看到彼此写入 */
    char *s = mmap(NULL, n, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (s == MAP_FAILED) return -1;
    s[0] = 'A';
    msync(s, n, MS_SYNC);        /* 主动落盘 */
    munmap(s, n);
    return 0;
}

int demo_private(int fd, size_t n) {
    /* 私有映射：写只影响本进程，文件不变 */
    char *p = mmap(NULL, n, PROT_READ | PROT_WRITE, MAP_PRIVATE, fd, 0);
    if (p == MAP_FAILED) return -1;
    p[0] = 'B';                  /* 触发 COW，文件保持原值 */
    munmap(p, n);                /* 不会写回 */
    return 0;
}
```

注意：`MAP_PRIVATE` 下的修改即使不 `munmap` 也不会落盘，这正是「私有」的语义。

## 五、与其他技术对比

| 机制 | 写可见性 | 是否落盘 | 内存共享 | 典型用途 |
| --- | --- | --- | --- | --- |
| `MAP_SHARED` 文件映射 | 所有映射者 | 是（msync/退出） | 是 | IPC、数据库映射文件 |
| `MAP_PRIVATE` 文件映射 | 仅本进程 | 否 | 只读时共享 | 加载可执行文件/库 |
| `MAP_SHARED\|MAP_ANONYMOUS` | 相关进程 | 否 | 是 | 现代共享内存 IPC |
| `shmget`/`shmat` | 相关进程 | 否 | 是 | 传统 System V 共享内存 |
| 管道/消息队列 | 读走即消失 | 否 | 否 | 流式通信 |

## 六、常见误区

- 认为 `MAP_PRIVATE` 的写会落盘：不会，除非使用 `MAP_SHARED`。
- 认为共享映射自动持久化：需要 `msync(MS_SYNC)` 或依赖退出时回写，崩溃可能丢数据。
- 认为私有映射一定省内存：首次写仍会 COW 复制，只是未被写的页共享。
- 在私有映射上做大范围写后期待文件更新：改动只在本进程内。
- 忽略 `MAP_SHARED` 的并发语义：多进程无同步地写同一页会产生数据竞争。

## 八、面试题

- 问：为什么加载 `.so` 用 `MAP_PRIVATE`？答：多进程共享只读代码页，写时各自 COW，互不污染且不改文件。
- 问：如何让 mmap 修改持久？答：用 `MAP_SHARED` 并调用 `msync(MS_SYNC)` 或在退出前确保回写。
- 问：`MAP_PRIVATE` 首次写发生了什么？答：触发缺页，内核复制共享页为私有副本并置写位。
- 问：共享映射与共享内存 IPC 的关系？答：共享文件映射或共享匿名映射都可实现进程间内存共享。

## 九、演进与趋势

`MAP_SYNC` 配合 DAX 使持久内存映射的写直接对存储介质可见；`memfd_create` 提供匿名可共享的文件描述符，便于在进程间传递映射；大页映射降低 TLB 压力。具体支持以官方最新文档为准。

## 十、小结

共享与私有决定写可见性与 COW 行为，是 mmap 语义正确性的关键开关。记住一句话：**共享映射改动互见且可落盘，私有映射改动仅本进程且不落盘**。
