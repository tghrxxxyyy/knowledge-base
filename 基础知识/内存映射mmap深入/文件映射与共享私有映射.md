# 文件映射与共享私有映射

> 对应 Kerrisk《The Linux Programming Interface》第 49 章 mmap 标志语义与 Love《Linux Kernel Development》第 15 章。

## 一、背景与挑战
mmap 的 `MAP_SHARED` 与 `MAP_PRIVATE` 决定写操作是否对其他映射者/磁盘可见，直接关系进程间共享、写时复制与数据持久化语义，易被误用。

## 二、核心原理
`MAP_SHARED`：映射页与文件（及同文件其他共享映射）共享，写回写盘（除非未 msync）。`MAP_PRIVATE`：写触发 COW，产生进程私有副本，原文件不变，常用于加载可执行文件与只读共享库，避免污染。

## 三、形式化与数学基础
私有写触发 COW：首次写页 $v$ 时
$$page_{private} = copy(page_{shared});\quad PTE(v).W=1,\; PTE(v).COW=0$$
共享写：$page_{shared}$ 原地修改，对所有映射者可见，$\Delta file = page_{shared}$。

## 四、代码实现
```c
// 共享映射：两进程可见彼此写入
void *s = mmap(NULL, N, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);
// 私有映射：写不改文件、不影响他人
void *p = mmap(NULL, N, PROT_READ|PROT_WRITE, MAP_PRIVATE, fd, 0);
p[0] = 1;   // 仅本进程可见，文件不变
```

## 五、与其他技术对比
共享映射近似共享内存 IPC，优于管道/消息的拷贝；私有映射用于安全加载代码段。相较 shmget，MAP_SHARED 匿名映射更现代灵活。

## 六、常见误区
误以为 MAP_PRIVATE 写会落盘：不会，除非 MAP_SHARED。误以为共享映射自动持久：需 msync/进程退出回写。误以为私有映射省内存：写时仍 COW 复制。

## 七、与开源书/权威来源对应
Kerrisk 第 49 章详述标志与同步；OSTEP 讲 COW 与私有映射加载可执行文件。

## 八、面试题
问：为什么加载 .so 用 MAP_PRIVATE？答：多进程共享只读代码又互不污染，写时各自 COW。问：如何让 mmap 改动持久？

## 九、演进与趋势
`MAP_SYNC`（DAX）使持久内存映射的写直接对存储介质可见；memfd 提供匿名可共享 fd。

## 十、小结
共享 vs 私有决定写可见性与 COW 行为，是 mmap 语义正确性的关键开关。
