# 跳表的插入与删除

> 对应 Pugh 1990 论文第 3 节插入与删除算法，TheAlgorithms/Python 的 skip list 实现，以及 Redis `zslInsert`/`zslDelete` 源码。

## 一、背景与挑战

查找是只读的，结构不变；插入和删除则必须改写多层指针，同时保住跳表的两条命根子不变量：**同一层关键字严格递增**、**高层链表是低层链表的子序列**（结点出现在第 $l$ 层就一定出现在 $0..l-1$ 层）。只要有一处指针挂错，查找就会漏元素或死循环。

与平衡树相比，跳表插入删除「看起来」简单——不旋转、不染色——但陷阱不少：新结点的层数是随机的，可能高于当前最大层，这时要扩展头结点指针数组并更新 `update`；删除时目标结点未必出现在所有层，必须逐层确认「这一层的后继确实是目标」再解链，否则会把别的结点错摘下来；删除后最高层可能变空，不收缩会让后续查找在空层里空转。

工程场景里，插入删除是写路径的核心：Redis `ZADD/ZREM`、LevelDB `Put/Delete`、Java `ConcurrentSkipListMap.put/remove` 全部落在这里。写并发下的插入删除还牵出「逻辑删除标记」等更深问题（另文讨论），但单线程版本是所有变体的地基。面试常考手写插入删除，以及「update 数组为什么必须在下降时填充」这类细节。

## 二、核心原理

**插入**分四步：

1. **定位并记录前驱**：从最高层向低层查找，在第 $i$ 层走到「最后一个关键字 $<$ 新 key」的结点，记入 `update[i]`。下降到第 0 层后，`update[0]` 就是底层插入点的前驱。
2. **决定新结点层数**：独立抛硬币，得 `lvl`（0-based）。若 `lvl > 当前最大层`，把更高层的 `update[i]` 都设为 `head`，并抬高最大层——因为新结点将成为新的「高层脊梁」。
3. **逐层挂接**：对 $i = 0..lvl$，令 `node.forward[i] = update[i].forward[i]; update[i].forward[i] = node`。这是标准的单链表插入，只是做了多层。
4. **可选**：若 key 已存在，实现策略不同——跳表通常允许重复 key（按插入序或后继序），符号表实现则选择覆盖 value 不增加结点。

**删除**同样先构造 `update[]`，然后：

1. 令 `target = update[0].forward[0]`，若为空或 key 不等，则元素不存在，直接返回。
2. 对 $i = 0..{\rm 当前最大层}$：只有当 `update[i].forward[i] is target` 时才执行 `update[i].forward[i] = target.forward[i]`。因为 target 的高度只有 `target.level`，高层上的「后继」其实是别的结点，不能乱摘。
3. 若删除后 `head.forward[最高层]` 为空，把最高层降下来，保持 `level` 与实际一致。

**为什么 `update[]` 必须在下降过程中填充？** 因为跳表查找路径在第 $i$ 层停留的最后一个结点，就是第 $i$ 层插入/删除操作的前驱。若只记第 0 层前驱再向上找，会丢失高层前驱信息，且可能因结点高度不一而找错。`update[i]` 的含义是不变量式的关键：「在第 $i$ 层，`update[i]` 之后的所有结点关键字都 $\ge$ 目标」且 `update[i].key < 目标`（对插入而言）。

**重复 key 与删除边界**：删除只删第一个匹配（或按实现删全部）；对带 value 的符号表，插入时先查是否存在，存在则替换。对 Redis zset，score 相同再比 member 字典序，保证全序，避免比较函数不严格弱序导致结构错乱。

## 三、形式化与数学基础

单层指针改写是 $O(1)$。新结点高度 $L$ 的期望是

$$E[L] = \sum_{l \ge 1} P(L \ge l) = \sum_{l \ge 1} p^l = \frac{p}{1-p}.$$

插入要改写 $L+1$ 层指针，期望改写次数 $O\!\left(\frac{1}{1-p}\right)$，与 $n$ 无关。但定位 `update[]` 的查找本身是期望 $O(\log n)$，故

$$T_{\text{insert}} = T_{\text{delete}} = O(\log n)\ \text{（期望）}.$$

空间上每次插入增加 $\frac{1}{1-p}$ 个指针期望；$p = 1/2$ 时约 2 个。

删除后的层高收缩不改变渐进复杂度：最高层以高概率只需降 $O(1)$ 层。更形式化地，删除后最大高度的期望仍是 $\log_{1/p} n + O(1)$，因为 $n$ 减 1 对期望影响极小。

均摊角度看，插入删除是「无再平衡」的：不存在红黑树那种一次旋转链，也没有 B 树的页分裂均摊。单次操作的代价波动只来自随机层高，且层高有截断上界，所以**最坏层高**下，一次插入的指针操作数 $\le L_{max} + 1$，确定性有界；慢的是定位查找那一段，期望对数、最坏线性（概率极小）。

对并发版本，插入删除还要付 CAS 重试的代价。若每层挂接一次 CAS，成功概率高时总期望仍是 $O(\log n)$；高冲突下需帮助（helping）或退避，这超出了本文范围但建立在单线程指针操作的清晰语义之上。

## 四、代码实现

完整可运行的插入、删除、查找，含层扩展与收缩、重复 key 覆盖策略。

```python
import random


class Node:
    __slots__ = ("key", "value", "forward")
    def __init__(self, key, value, level):
        self.key = key
        self.value = value
        self.forward = [None] * (level + 1)


class SkipList:
    def __init__(self, p=0.5, max_level=16):
        self.p = p
        self.max_level = max_level
        self.head = Node(None, None, max_level)
        self.level = 0
        self.size = 0

    def _random_level(self):
        lvl = 0
        while random.random() < self.p and lvl < self.max_level:
            lvl += 1
        return lvl

    def _find_update(self, key):
        """返回 (update[], 候选结点)。update[i] 是第 i 层 key 的前驱。"""
        update = [self.head] * (self.max_level + 1)
        cur = self.head
        for i in range(self.level, -1, -1):
            while cur.forward[i] and cur.forward[i].key < key:
                cur = cur.forward[i]
            update[i] = cur
        return update, cur.forward[0]

    def insert(self, key, value):
        update, nxt = self._find_update(key)
        if nxt and nxt.key == key:
            nxt.value = value  # 覆盖，不增加结点
            return
        lvl = self._random_level()
        if lvl > self.level:
            # 新层出现，前驱只能是 head
            for i in range(self.level + 1, lvl + 1):
                update[i] = self.head
            self.level = lvl
        node = Node(key, value, lvl)
        for i in range(lvl + 1):
            node.forward[i] = update[i].forward[i]
            update[i].forward[i] = node
        self.size += 1

    def delete(self, key):
        update, target = self._find_update(key)
        if not target or target.key != key:
            return False
        for i in range(self.level + 1):
            if update[i].forward[i] is not target:
                # 目标未达到该层，或该层后继不是目标
                break
            update[i].forward[i] = target.forward[i]
        while self.level > 0 and self.head.forward[self.level] is None:
            self.level -= 1
        self.size -= 1
        return True

    def to_list(self):
        out = []
        cur = self.head.forward[0]
        while cur:
            out.append((cur.key, cur.value))
            cur = cur.forward[0]
        return out


if __name__ == "__main__":
    sl = SkipList()
    data = [(5, "e"), (1, "a"), (3, "c"), (2, "b"), (4, "d"), (6, "f")]
    for k, v in data:
        sl.insert(k, v)
    assert sl.to_list() == [(1, "a"), (2, "b"), (3, "c"), (4, "d"), (5, "e"), (6, "f")]

    sl.insert(3, "C")  # 覆盖
    assert sl.to_list()[2] == (3, "C")
    assert sl.size == 6

    assert sl.delete(1) is True
    assert sl.delete(6) is True
    assert sl.delete(100) is False
    assert sl.to_list() == [(2, "b"), (3, "C"), (4, "d"), (5, "e")]

    # 乱序插入大量元素，验证有序性
    sl2 = SkipList()
    keys = list(range(200))
    random.shuffle(keys)
    for k in keys:
        sl2.insert(k, k * 10)
    assert [k for k, _ in sl2.to_list()] == list(range(200))
    for k in keys:
        assert sl2.delete(k) is True
    assert sl2.size == 0
    print("insert/delete ok")
```

实现细节：`_find_update` 在下降过程中把每层前驱写入 `update[i]`，高层未访问到的槽位保持 `head`（因从 `self.level` 降到 0，更高层本就无结点或刚扩展）；删除循环用 `is not target` 就地 break，天然处理「目标高度小于当前层」的情况。

## 五、与其他技术对比

| 维度 | 跳表插入/删除 | 红黑树 | AVL | 有序数组 | B+ 树 |
|------|---------------|--------|-----|----------|-------|
| 指针/元素移动 | 期望 $O(1)$ 次指针改写 | 最多 3 次旋转 | 最多 $O(\log n)$ 旋转 | $O(n)$ 移动 | 页分裂合并 |
| 代码行数 | 约 30 行 | 数百行 | 约百行 | 几行 | 数百行 |
| 局部性 | 指针跳 | 指针跳 | 指针跳 | 极好 | 页内好 |
| 并发改写 | 逐层 CAS，易 | 极难 | 难 | 难 | 页锁 |
| 最坏单次 | 定位可能慢 | 确定 $O(\log n)$ | 确定 $O(\log n)$ | $O(n)$ | 确定 $O(\log_B n)$ |

关键取舍：跳表把「再平衡」成本摊进了随机层数生成——插入删除本身几乎是纯指针挂接，这是它在并发场景胜出的结构原因。红黑树胜在确定性与标准库成熟；B+ 树胜在磁盘页与范围扫描。

## 六、常见误区

**误区一：扩展新层时忘记把 `update[i]` 设为 head。** 新层只有头结点一个「前驱」，若 `update[i]` 是 `None` 或残留旧值，挂接直接崩溃或破坏结构。

**误区二：删除时对所有层无条件 `update[i].forward[i] = target.forward[i]`。** 目标结点高度不够时，高层 `update[i].forward[i]` 是别的结点，这会把无辜结点从高层摘掉，查找立刻漏元素。必须逐层判断是否真是 target。

**误区三：删除后不收缩最高层。** 空层不会导致错误，但每次查找都要白白下降若干空层，常数变差；某些实现的 `level` 语义是「当前最高非空层」，不维护会越界访问 `forward[level]`。

**误区四：插入重复 key 时再挂一个结点，却按「符号表」语义查找。** 若上层以为 key 唯一，会出现查找返回哪个不确定、删除只删一个等问题。要么明确允许重复（按序插入），要么插入前先查并覆盖。

**误区五：比较函数对「相等」处理不一致。** 比如 Redis zset 必须 `score` 相同再比 `member`，否则两个不同 member 同 score 会被当成相等，插入删除语义错乱。

## 八、面试题

**Q1：手写跳表插入，为什么需要 `update` 数组？**
A：插入要在每一层把新结点挂到前驱之后，而各层前驱不同。查找下降时顺手记下每层前驱，才能 $O(L)$ 完成挂接；否则每层重新找前驱会把总代价抬到 $O(L \log n)$ 或写错结构。

**Q2：删除一个只有 0 层的结点，要注意什么？**
A：只应解链第 0 层；若对高层也执行 `update[i].forward[i] = target.forward[i]`，会错误摘掉高层的其它结点。正确写法是判断 `update[i].forward[i] is target`。

**Q3：如何支持重复 key？**
A：两种策略：(1) 允许重复，比较时严格小于才右移，相同 key 按插入顺序形成有序段；(2) 不允许重复，插入前查找命中则覆盖 value。删除时明确删第一个或全部。

**Q4：插入导致新最高层时，时间复杂度变了吗？**
A：没有。扩展 head 指针数组是 $O(L_{max})$ 一次性或均摊 $O(1)$；总期望仍是 $O(\log n)$。但要注意 `update` 数组大小要按 `max_level` 开，而不是按当前 `level`。

## 九、演进与趋势

**无锁插入删除**：Java `ConcurrentSkipListMap` 用 CAS 挂接 + 标记删除，删除先打标记再物理摘除，插入若发现标记结点则帮助删除。**持久化跳表**：LevelDB 在跳表结点上分配 arena，插入即追加、删除靠版本链/墓碑，避免原地改指针带来的崩溃恢复难题。**带 rank 的插入**：Redis 在挂接时同步维护每层 `span`，插入删除同时更新跨度，使 `ZRank` 可用。**批量插入**：先排序再建完全平衡索引，比逐个随机插入常数更好，用于 bulk load。**内存分配友好**：结点池/ slab 分配降低碎片，对写密集的 zset 很关键。

## 十、小结

跳表插入与删除的核心是「下降时记录每层前驱 `update[]`，再按新结点高度逐层挂接/解链」。期望代价 $O(\log n)$，指针改写期望 $O(1/(1-p))$ 次，无旋转。难点全在细节：新层扩展、删除时逐层确认目标、层高收缩、重复 key 语义。把这些边界做对，才配得上「比红黑树简单」的名声；也正是这些细节，决定了 Redis、LevelDB 里那几十行代码的成色。
