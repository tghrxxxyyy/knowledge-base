# 跳表基本结构与查找

> 对应 Sedgewick《Algorithms》。

## 一、背景与挑战
有序链表查找是 $O(n)$。跳表（Skip List）用「多层索引」对有序链表做概率加速，以简单实现获得近似平衡树的性能，被 Redis、LevelDB 采用。

## 二、核心原理
每个节点带若干层 forward 指针。查找时从最高层向右，遇到更大键则下降一层，直到底层定位。层数由随机硬币决定。

## 三、形式化与数学基础
设最大层数 $L=\lceil\log_{1/p} n\rceil$。期望每层节点数减半，查找期望步数：
$E=O(\log n)$，与平衡树同级，但实现仅需随机数。

## 四、代码实现
```python
import random
class Node:
    def __init__(self, key, level):
        self.key = key
        self.forward = [None] * (level + 1)
def search(head, key):
    cur = head
    for i in range(len(head.forward) - 1, -1, -1):
        while cur.forward[i] and cur.forward[i].key < key:
            cur = cur.forward[i]
    cur = cur.forward[0]
    return cur if cur and cur.key == key else None
```

## 五、与其他技术对比
相比红黑树/AVL，跳表代码简单、并发友好（可无锁分段）；相比平衡树，常数略高但更稳定易维护。

## 六、常见误区
误以为层数是固定值：应由概率生成，否则退化为链表。另一误区是查找时未从最高层开始导致漏节点。

## 七、与开源书/权威来源对应
Sedgewick《Algorithms》讨论概率性平衡；Pugh 1990 原始论文《Skip Lists》。

## 八、面试题
跳表查找复杂度为什么是 $O(\log n)$？最大层数如何选？

## 九、演进与趋势
无锁并发跳表（如 Java ConcurrentSkipListMap）、持久化跳表用于 LSM 存储。

## 十、小结
跳表以多层随机索引把有序链表查找降到期望 $O(\log n)$，实现远比平衡树简单。
