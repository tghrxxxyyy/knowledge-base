# 跳表基本结构与查找

> 对应 Pugh 1990 年论文《Skip Lists: A Probabilistic Alternative to Balanced Trees》、Sedgewick《Algorithms》第 4 版，以及 Redis / LevelDB 中的工程实现。

## 一、背景与挑战

在有序数据上做查找，最朴素的结构是有序数组或有序链表。有序数组支持 $O(\log n)$ 二分查找，但插入与删除需要搬移元素，代价 $O(n)$；有序链表插入删除只需改指针，但查找必须逐个比较，最坏 $O(n)$。工程里大量场景既要「按关键字有序」，又要频繁插入删除，还要支持范围扫描——比如内存数据库的有序索引、消息队列的时间线索引、限流器的滑动窗口计数。这些场景下，数组和链表都力不从心。

为了解决「查找快 + 改动便宜」的矛盾，经典做法是给链表加多层索引，演进到极致就是平衡树：AVL、红黑树、B 树都能在 $O(\log n)$ 内完成查找、插入、删除。但平衡树的代价是实现复杂——旋转、再平衡、各种情形分类（红黑树插入有 5 种情形、删除有 6 种），写对难、写并发更难。面试中手写红黑树几乎不现实，而跳表（Skip List）用「随机层数 + 多层前向指针」达到了同样的期望复杂度，核心查找/插入逻辑通常只有几十行。

跳表因此成为「工程友好型有序结构」的代表：Redis 的 zset 用跳表做主干，LevelDB/RocksDB 的 memtable 用跳表做内存表，Java 的 `ConcurrentSkipListMap` 用跳表实现并发有序映射。理解跳表的基本结构与查找路径，是掌握这一切的起点，也是面试中「为什么 Redis 不用红黑树」这类问题的知识根基。

## 二、核心原理

跳表可以看成「把有序链表按概率抽出多级稀疏索引」。每个结点包含一个关键字 `key`，以及一个前向指针数组 `forward[0..level]`：`forward[i]` 指向第 $i$ 层链表中它的后继。最底层（第 0 层）包含全部结点，就是原始有序链表；第 1 层大致包含一半结点；第 2 层大致包含四分之一……以此类推。另有一个不存数据的头结点 `head`，它的 `forward` 数组长度等于当前最大层数。

查找过程是「尽量在高层向右走，走不动就下降一层」：

1. 从头结点的最高层出发，设当前结点为 `cur = head`。
2. 在第 $i$ 层，反复向右：只要 `cur.forward[i]` 存在且其关键字小于目标 `key`，就令 `cur = cur.forward[i]`。
3. 第 $i$ 层走不动时，降到第 $i-1$ 层，重复步骤 2。
4. 降到第 0 层后，`cur.forward[0]` 就是第一个关键字 $\ge$ 目标的结点；若它等于 `key` 则查找成功，否则不存在。

不变量很关键：在任意层 $i$，沿 `forward[i]` 走出的序列关键字严格递增，且第 $i$ 层链表是第 $i-1$ 层链表的子序列（高层结点一定也出现在低层）。这个「子序列」不变量保证了从高层下降时不会跳过目标结点——当你在高层走到第一个关键字 $\ge$ 目标的位置之前，目标若存在，必然落在你当前位置与该后继之间的低层区间内。

边界条件要小心：头结点的关键字设为 $-\infty$ 或不参与比较；查找目标小于所有元素时，最终停在 head，`forward[0]` 是最小元素；查找目标大于所有元素时，底层走到最右结点，`forward[0]` 为 `None`。空表时 head 的所有 `forward` 都是 `None`。

正确性可以这样理解：每一层都是上一层的「快捷通道」。若把结点出现在第 $l$ 层看作抛硬币成功 $l$ 次，则第 $l$ 层的结点间距期望是 $2^l$。查找一次大约在每层向右走常数步，层数期望 $O(\log n)$，总步数期望 $O(\log n)$。这正是第三节要形式化的结论。

## 三、形式化与数学基础

设插入时每个结点独立地以概率 $p$ 晋升到更高一层（$0 < p < 1$，工程常取 $p = 1/2$），则结点高度 $L$ 服从几何分布：

$$P(L \ge l) = p^l, \quad l = 0, 1, 2, \ldots$$

$n$ 个结点中，期望有 $np^l$ 个出现在第 $l$ 层。当 $np^l = 1$ 时，该层大约只剩一个结点，因此跳表的期望最大层高约为

$$H \approx \log_{1/p} n.$$

对 $p = 1/2$，$H \approx \log_2 n$。下面估算查找代价。从第 $H$ 层开始，每向下一步可以看成从「当前层结点密度」跨越到目标位置。经典分析（Pugh 1990）给出期望向右移动次数的递推：设 $C(l)$ 为在第 $l$ 层还需要向右走的期望步数，则

$$C(l) = \frac{1}{1-p}\,C(l-1) + O(1),$$

其中 $\frac{1}{1-p}$ 是每层平均要尝试的指针数（几何分布的成功前失败次数）。展开得 $C(H) = O\!\left(\frac{1}{1-p} \cdot H\right) = O(\log_{1/p} n)$。当 $p = 1/2$ 时 $\frac{1}{1-p} = 2$，常数很小。

更直观的启发式：查找路径在每一层期望向右走 $1/p$ 步左右，一共下降约 $\log_{1/p} n$ 层，故

$$E[\text{search cost}] = O\!\left(\frac{1}{1-p} \cdot \log_{1/p} n\right) = O(\log n).$$

注意这是**期望**界而非最坏界。最坏情况是所有结点都只有 0 层（随机退化），查找退化为 $O(n)$，概率为 $(1-p)^n$，对 $p = 1/2$ 是指数小量。工程上再加一个 `MAX_LEVEL` 上限，把最坏层高钉死，空间上界也从期望变成确定值。

空间方面，每个结点的期望指针数是 $\sum_{l\ge 0} p^l = \frac{1}{1-p}$。当 $p = 1/2$ 时期望 2 个指针，总空间约 $2n$ 个指针，即 $O(n)$。

## 四、代码实现

下面给出一个可直接运行的跳表，包含查找、插入、删除与范围查询，并附经典用例。

```python
import random

class Node:
    __slots__ = ("key", "value", "forward")
    def __init__(self, key, value, level):
        self.key = key
        self.value = value
        self.forward = [None] * (level + 1)


class SkipList:
    def __init__(self, p=0.5, max_level=16):
        self.p = p
        self.max_level = max_level
        self.head = Node(None, None, max_level)
        self.level = 0  # 当前最高层（从 0 计）
        self.size = 0

    def _random_level(self):
        lvl = 0
        while random.random() < self.p and lvl < self.max_level:
            lvl += 1
        return lvl

    def search(self, key):
        cur = self.head
        for i in range(self.level, -1, -1):
            while cur.forward[i] and cur.forward[i].key < key:
                cur = cur.forward[i]
        nxt = cur.forward[0]
        return nxt.value if nxt and nxt.key == key else None

    def insert(self, key, value):
        update = [None] * (self.max_level + 1)
        cur = self.head
        for i in range(self.level, -1, -1):
            while cur.forward[i] and cur.forward[i].key < key:
                cur = cur.forward[i]
            update[i] = cur
        nxt = cur.forward[0]
        if nxt and nxt.key == key:
            nxt.value = value
            return
        lvl = self._random_level()
        if lvl > self.level:
            for i in range(self.level + 1, lvl + 1):
                update[i] = self.head
            self.level = lvl
        node = Node(key, value, lvl)
        for i in range(lvl + 1):
            node.forward[i] = update[i].forward[i]
            update[i].forward[i] = node
        self.size += 1

    def delete(self, key):
        update = [None] * (self.max_level + 1)
        cur = self.head
        for i in range(self.level, -1, -1):
            while cur.forward[i] and cur.forward[i].key < key:
                cur = cur.forward[i]
            update[i] = cur
        target = cur.forward[0]
        if not target or target.key != key:
            return False
        for i in range(self.level + 1):
            if update[i].forward[i] is not target:
                break
            update[i].forward[i] = target.forward[i]
        while self.level > 0 and self.head.forward[self.level] is None:
            self.level -= 1
        self.size -= 1
        return True

    def range_query(self, lo, hi):
        res = []
        cur = self.head
        for i in range(self.level, -1, -1):
            while cur.forward[i] and cur.forward[i].key < lo:
                cur = cur.forward[i]
        cur = cur.forward[0]
        while cur and cur.key <= hi:
            res.append((cur.key, cur.value))
            cur = cur.forward[0]
        return res


if __name__ == "__main__":
    sl = SkipList()
    for k, v in [(3, "c"), (1, "a"), (5, "e"), (2, "b"), (4, "d")]:
        sl.insert(k, v)
    assert sl.search(3) == "c"
    assert sl.search(10) is None
    assert sl.range_query(2, 4) == [(2, "b"), (3, "c"), (4, "d")]
    assert sl.delete(3) is True
    assert sl.search(3) is None
    assert sl.delete(3) is False
    print("skiplist ok, size =", sl.size)
```

代码要点：`update[i]` 记录第 $i$ 层「最后一个关键字小于 key」的结点，插入时在各层把它和后继之间断开挂上新结点；删除时只有当 `update[i].forward[i] is target` 才断链，因为目标结点未必达到所有层；删除后若顶层变空，把 `self.level` 降下来，避免空层拖慢查找。

## 五、与其他技术对比

| 维度 | 跳表 | 红黑树 | AVL 树 | 有序数组 + 二分 | B+ 树 |
|------|------|--------|--------|-----------------|-------|
| 查找 | 期望 $O(\log n)$ | 最坏 $O(\log n)$ | 最坏 $O(\log n)$ | $O(\log n)$ | $O(\log_B n)$ |
| 插入/删除 | 期望 $O(\log n)$，只改指针 | $O(\log n)$，需旋转 | $O(\log n)$，旋转更频繁 | $O(n)$ 搬移 | 分裂/合并 |
| 范围扫描 | 底层链表，极自然 | 中序后继，缓存不友好 | 同左 | 连续内存，优秀 | 叶子链表，优秀 |
| 实现复杂度 | 低（约几十行） | 高 | 中高 | 低 | 高 |
| 并发 | 易做 CAS 无锁 | 极难 | 难 | 难（写锁） | 锁粒度粗 |
| 最坏保证 | 需 `max_level` 兜底 | 确定性 | 确定性 | 确定性 | 确定性 |
| 空间 | 约 $2n$ 指针（$p=1/2$） | $3n$ 指针 | $3n$ 指针 | 紧凑 | 页内填充 |

取舍很清楚：要确定性最坏界、写标准库，选红黑树（C++ `std::map`、Java `TreeMap`）；要极致范围扫描与磁盘友好，选 B+ 树；要实现简单、并发友好、内存索引，选跳表。跳表的常数并不小——每层都有指针跳转，缓存局部性弱于数组——但它的代码可读性和可并发性在工程上往往更值钱。

## 六、常见误区

**误区一：以为层数可以固定或按 $\log n$ 均分。** 若人为把结点均匀放到各层（比如第 $i$ 层每隔 $2^i$ 个取一个），插入删除时需要大规模调整索引，回到平衡树的老路。跳表的精髓正是「随机决定、期望平衡」，不需要全局再平衡。

**误区二：查找时不从当前最高层开始，或下降顺序搞反。** 必须严格从高层向低层，每层尽量向右。若从底层往上找，会退化成多条链表的并查，失去加速意义。

**误区三：忽略「高层是低层子序列」的不变量。** 有人插入时只在第 0 层挂接、高层随意跳过，导致某结点出现在第 2 层却不在第 1 层，查找下降时会漏掉它。正确做法是新结点出现在 $0..lvl$ 的每一层。

**误区四：把期望 $O(\log n)$ 当成最坏 $O(\log n)$。** 跳表单次操作最坏可以是 $O(n)$（极端随机）。对延迟敏感系统必须设 `max_level`，或在关键路径用平衡树/跳表+兜底。

**误区五：头结点层数与 `level` 字段不同步。** 扩展新层时要同时初始化 `update[i] = head`，删除后要收缩 `level`，否则查找会在空层里白走。

## 八、面试题

**Q1：跳表查找为什么是 $O(\log n)$？请口述推导。**
A：结点以概率 $p$ 晋升，期望有 $np^l$ 个结点在第 $l$ 层，最大层高期望 $\log_{1/p} n$。查找每下降一层期望向右走 $O(1/(1-p))$ 步，故总期望步数 $O(\log_{1/p} n)$，当 $p = 1/2$ 即 $O(\log n)$。

**Q2：跳表和哈希表都能快速查找，为什么还要跳表？**
A：哈希表无序，不支持范围查询、排名、前驱后继；跳表底层是有序链表，天然支持 `range`、`floor/ceiling`、按排名取值。zset、限流、时间线索引都需要有序性。

**Q3：`max_level` 应该设多大？**
A：一般取 $\lceil \log_{1/p} N_{\max} \rceil$，$N_{\max}$ 是预期最大元素数。Redis 取 32 层（$p = 0.25$，可覆盖约 $2^{32}$ 级别的元素）。太小限制容量，太大浪费指针与比较。

**Q4：跳表能否退化？如何避免？**
A：随机数质量差或攻击者预测随机序列时可能退化。避免办法：加密级随机数、设层上限、必要时改用确定性跳表或平衡树。

## 九、演进与趋势

跳表在现代系统里演化出多个方向。**并发跳表**：Java `ConcurrentSkipListMap` 用 CAS + 标记删除实现无锁有序映射，成为 JVM 高并发有序容器的事实标准。**持久化/LSM**：LevelDB、RocksDB 的 memtable 就是跳表，顺序扫描友好、写入无旋转，flush 到 SSTable 时天然有序。**带 rank/span 的跳表**：Redis 在 `forward` 之外给每层存 `span`，使 `ZRank` 达到 $O(\log n)$。**确定性跳表**（Munro 等）用层间比例约束替代随机，给最坏界。**硬件友好变体**：把高层指针塞进缓存行、SIMD 多路比较，在现代 CPU 上进一步压常数。

面试与工程结合点：手写跳表是「结构思维 + 随机化 + 指针操作」的综合题；读懂 Redis/LevelDB 源码中的跳表，则是从「会算法」到「懂系统」的跨越。

## 十、小结

跳表用「随机高度 + 多层前向指针」给有序链表装上概率索引：查找从高层尽量向右、走不动再下降，期望 $O(\log n)$；插入删除只需维护每层前驱指针，无旋转。它牺牲确定性最坏界（可用层上限兜底），换来了极简实现、范围扫描天然、并发友好三大工程优势，是 Redis zset、LevelDB memtable 等系统的基石结构。
