# 控制冒险与分支延迟槽

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》第 3 章；Bryant & O'Hallaron《CSAPP》第 4 章（分支预测与冲刷）。

## 一、背景与挑战

控制冒险（control hazard，又称分支冒险）来自分支、跳转、异常改变了 PC 流向。在分支方向被解析之前，后续指令的取指方向未知：若按错误路径取指，就会取错指令、浪费周期。深流水线放大的代价是——分支之后已发射的指令级数越多，误预测冲刷的代价越大，CPI 随之显著上升。控制冒险因此是深流水线性能的关键瓶颈之一。

与数据冒险不同，控制冒险不依赖寄存器值，而依赖「程序执行路径」这个在取指时尚未确定的量，因此缓解手段从「转发值」转向「预测方向」或「延迟执行」。

第三个难点是「分支密度」：现代程序中平均每 5～6 条指令就有一条分支，若每条都停顿数拍，流水线收益会被完全抵消。这解释了为什么工业界投入大量晶体管去做多级预测器（BTB、方向历史、返回地址栈），而非仅靠编译器调度。

## 二、核心原理

早期 RISC（如 MIPS）采用分支延迟槽（branch delay slot）：紧跟分支指令的那条指令总是执行，与分支预测结果无关，是 ISA 层的契约。编译器负责把一条「有用」的指令（如不影响正确性的计算、或分支目标与落空路径都安全执行的指令）填进槽内，从而把这一个周期的停顿「藏」起来。现代核心则依赖分支预测器（BPB/BTB/返回地址栈）在取指阶段就猜测方向，避免延迟槽的语义负担与调度难题。

预测器的三件套值得区分：方向预测器（BPB/两级自适应/TAGE）回答「跳不跳」；目标缓冲（BTB）回答「跳到哪」；返回地址栈（RAS）专管函数返回（`ret` 的目标由调用时压栈得到）。三者配合才能在取指阶段就确定下一个 PC，这是现代前端吞吐的基础。

## 三、形式化与数学基础

设分支指令在周期 $t$ 进入 EX，方向在 $t+1$ 解析。若采用预测，需在 $t$ 即选定目标 $T_{pred}$。误预测惩罚 $P$（需冲刷的指令数）：

$$P = k + 1$$

其中 $k$ 为分支之后已发射但需作废的指令级数。延迟槽把 $k$ 减 1（槽内指令总执行），但深流水线时仍需预测，且槽数需随级数增长才能完全隐藏代价。误预测率 $\alpha$ 下，平均每条分支的代价为 $\alpha \cdot (k+1)$ 周期。

若把分支占比记为 $f_b$、误预测率为 $\alpha$，则流水线 CPI 的下界可写为：

$$CPI \ge CPI_{ideal} + f_b \cdot \alpha \cdot (k+1)$$

这一式说明：当 $k$ 随流水深度增长时，即使 $\alpha$ 很小，代价也可能可观——这正是「深流水线 + 高分支密度」组合下必须把预测准确率做到 95% 以上的原因。

## 四、代码实现

```assembly
# MIPS 风格分支延迟槽：把不依赖分支结果的更新放进槽
        beq  $t0, $zero, done
        add  $s1, $s1, $t1     # 延迟槽内总是执行，与跳转与否无关
done:
        nop
# 现代替代：分支预测 + BTB
#   predict: 若 hit BTB 且 taken → 取 target；否则顺序取指
#   误预测 → flush 流水线、回滚到分支处重取
```

```c
// 误预测冲刷控制：作废已取指的错误路径指令
void flush_pipeline() {
    if_id_valid = 0;   // 清空取指/译码边界
    ex_valid    = 0;   // 作废执行级
    pc = correct_target;  // 跳到正确目标重取
}
```

```c
// 分支代价估算：用于指导代码布局优化（把大概率分支放直线路径）
double branch_cost(long n_branches, double alpha, int k) {
    return n_branches * alpha * (k + 1);   // 期望冲刷周期数
}
// 优化手段：把热分支排成「不跳转即继续」，让预测器与取指缓冲都受益
```

## 五、与其他技术对比

| 维度 | 分支延迟槽 | 分支预测 |
| --- | --- | --- |
| 决策方 | 编译器（静态） | 硬件（动态学习） |
| 适应度 | 固定，依赖调度质量 | 随历史自适应 |
| 深流水线 | 槽数需随级数增长 | 预测准确率决定代价 |
| ISA 负担 | 契约语义（软件可见） | 对软件透明 |

延迟槽把停顿转移给编译器，对深流水线不友好（槽数需随级数增长）；分支预测则把赌注交给硬件，随历史学习，适应性更强。

| 预测组件 | 回答的问题 | 典型结构 |
| --- | --- | --- |
| 方向预测器 | 跳还是不跳 | 两级自适应、TAGE |
| BTB | 目标地址是哪 | 缓存式目标表 |
| RAS | 返回到哪 | 调用深度栈 |
| 取指单元 | 下一 PC 组合 | 与三者联动 |

## 六、常见误区

误区一：延迟槽指令「可能不执行」。错，延迟槽指令无论分支是否跳转都执行，这是 ISA 契约而非优化提示，软件必须遵守。误区二：延迟槽能消除所有控制冒险。错，它只隐藏一个周期，深流水线仍需预测。误区三：x86 有延迟槽。错，x86 依赖动态预测，且变长指令使延迟槽语义复杂，故未采用。误区四：分支预测准确率可到 100%。错，不可预测的分支（如随机输入决定的分支）预测率注定很低。

误区五：误预测只损失一条指令。错，损失的是 $k+1$ 级已发射指令的工作，且会浪费取指带宽与译码资源。误区六：延迟槽填 `nop` 无害。错，`nop` 会白白占用一个发射槽，等于每次分支都付出一次停顿。

## 七、与开源书·权威来源对应

- Hennessy & Patterson 第 3 章对分支延迟槽与误预测惩罚 $P=k+1$ 的量化分析是标准参考。
- CSAPP 第 4 章给出分支预测错误时流水线冲刷的时序示意，并说明延迟槽在流水线中的处理。
- 二者都把「减少需冲刷的级数」作为降低控制冒险代价的统一目标。
- Patterson & Ditzel 1980「The Case for the Reduced Instruction Set Computer」是延迟槽由来的经典背景。

## 八、面试题

1. 为什么现代 x86 没有分支延迟槽而 MIPS 有？要点：MIPS 早期为简化硬件采用静态延迟槽；x86 起步即依赖动态预测，且 CISC 变长指令使延迟槽语义复杂。
2. 误预测惩罚由什么决定？要点：分支解析时机与已发射/执行的后续指令级数 $k$，即 $P=k+1$。
3. 延迟槽为什么对新 ISA 不再友好？要点：深流水线需要多个槽，编译器难填满，且语义负担转移给软件。
4. BTB 与方向预测器分工？要点：前者预测目标地址，后者预测是否跳转；两者都命中才能无误地连续取指。
5. `ret` 为什么需要 RAS？要点：返回目标由调用点决定，方向预测器无从得知，必须用调用时压栈的地址栈。
6. 为何要把大概率分支排成「不跳转」？要点：不跳转时顺序取指无需依赖 BTB，命中率与取指效率都更高。

## 九、演进与趋势

深流水线使固定延迟槽失效，取而代之的是两级以上分支预测、BTB、返回地址栈（RAS）与感知能力的 TAGE 预测器；延迟槽在新 ISA（如 RISC-V）中已成可选甚至弃用特性，部分场景保留单槽仅为兼容旧软件。预测器还结合 IBT/IBPB 等安全机制，在性能与隔离间平衡。

安全侧的影响尤为深刻：Spectre-BTB/Spectre-RSB 等漏洞正是通过污染 BTB 与 RAS 让受害者在错误路径上执行 gadget；对应的缓解手段（IBRS/STIBP、retpoline、`lfence` 屏障、IBPB 刷洗）都在牺牲部分预测自由以换取隔离。换言之，控制冒险的缓解手段已成为「性能与安全」共同设计的前沿阵地。

## 十、小结

控制冒险的代价取决于分支解析时机：延迟槽是静态化解法（把停顿转移给编译器），预测器是动态化解法（把赌注交给硬件），二者目标都是减少冲刷气泡、提升 IPC。现代处理器几乎全面转向预测器，延迟槽仅作为历史兼容残留。理解 $P=k+1$ 与 $CPI = CPI_{ideal} + f_b\alpha(k+1)$ 两个式子，就能定量解释「为什么深流水线离不开高准确率预测器」。
