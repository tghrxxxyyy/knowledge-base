# 超标量下的冒险扩展

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》第4章。

## 一、背景与挑战
超标量每周期发射多条指令，使同名寄存器、同资源、同控制流上的竞争被放大，单一转发路径与单一停顿判定不再够用。

## 二、核心原理
超标量采用寄存器重命名消除 WAW/WAR，用保留站（reservation station）缓存操作数，用公共数据总线（CDB）广播结果实现「多发前递」。发射阶段做相关性检查，执行阶段做实际计算。

## 三、形式化与数学基础
设发射宽度 $w$，每周期最多解析 $w$ 条相关。理想加速比受限于指令级并行度（ILP）：
$$Speedup \le \frac{1}{(1-p)+\frac{p}{w}}$$
其中 $p$ 为可并行部分比例。冒险降低有效 $p$。

## 四、代码实现
```python
# 保留站条目结构示意
class RS:
    def __init__(self):
        self.busy = False
        self.op = None
        self.vj = None  # 操作数值
        self.vk = None
        self.qj = None  # 仍在等待的源
        self.qk = None
```

## 五、与其他技术对比
标量前递是「点对点连线」，超标量是「总线广播 + 重命名 + 调度」，复杂度由 $O(1)$ 跳转发升到 $O(n)$ 唤醒网络。

## 六、常见误区
误以为发射宽度越大越好。实际上受限于 ILP、分支误预测率与内存延迟，宽发射常处于饥饿状态。

## 七、与开源书/权威来源对应
Hennessy & Patterson 第4章 Tomasulo 算法详述了保留站与 CDB 的唤醒机制；ostep-code 虽侧重操作系统，但其并发思想可类比。

## 八、面试题
问：Tomasulo 如何同时消除 WAR 与 WAW？答：通过寄存器重命名把逻辑寄存器映射到物理保留站，写回按物理号排序，避免名称相关。

## 九、演进与趋势
从集中式保留站走向物理寄存器文件 + 分布式调度器（如 Intel P6 / Sandy Bridge 架构），减少单点广播瓶颈。

## 十、小结
超标量把冒险处理从「局部转发」升级为「全局依赖跟踪 + 唤醒网络」，是前递思想在宽度维度的自然扩展。
