# 前递数据通路的硬件实现

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》第 4 章（数据通路与转发）；Bryant & O'Hallaron《CSAPP》第 4 章（HCL 控制逻辑）。

## 一、背景与挑战

前递（forwarding，又称旁路 bypass）不是软件概念，而是数据通路中一组多路选择器（mux）与控制信号的物理实现。其硬件难点在于三点：（1）何时该转发（检测匹配）；（2）选哪个阶段的结果（EX/MEM、MEM/WB，还是 ALU 自身的 1-cycle 旁路）；（3）如何与停顿控制协调，避免转发与停顿逻辑相互打架。实现不当会导致取到陈旧值或插入不必要的停顿，既错又慢。

在真实数据通路里，结果可能同时出现在多个段寄存器中（EX/MEM 刚算完、MEM/WB 已写回前），转发逻辑必须按「最近优先」原则选择正确的源，并保证与 HDU 的 stall 信号不冲突。

第三类风险来自「旁路与写回的时序竞争」：若 `RegWrite` 与寄存器堆写入在同一拍的前后半段，必须确认读端口是否在同一拍就能读到新值；若不能，则必须在转发逻辑里显式覆盖，而不能依赖寄存器堆本身。这一细节是很多自制流水线「偶发取到旧值」的根因。

## 二、核心原理

典型五级流水有三类转发源：EX/MEM 段寄存器（刚算完）、MEM/WB 段寄存器（已写回前），以及 ALU 自身的「1-cycle 旁路」（同一拍内后半段结果送前半段）。转发单元比较 ID/EX 中的源寄存器编号（rs1/rs2）与下游段寄存器的目标寄存器编号（rd），若匹配且写回有效（RegWrite=1、rd≠0），则生成 forwardA/forwardB 选择信号，把对应结果_mux 到 ALU 输入端。多级匹配时更近一级优先，防止旧值覆盖新值。

`rd≠0` 这一条不可省：零寄存器恒为 0 且不可写，若把「rd=0」也视为匹配，会把某个「以 x0 为目标」的指令结果错误转发出去。同理 `RegWrite=1` 也不可省，否则 store、branch 等不写寄存器的指令会污染转发源。

## 三、形式化与数学基础

定义段寄存器目标 $\text{RD}_{EX},\text{RD}_{MEM},\text{RD}_{WB}$ 与写回有效位。对 ALU 源 $\text{RS}$：

$$\text{src} = \begin{cases} ALUout_{MEM} & \text{if } RegW_{MEM}\land RD_{MEM}=RS \\ ALUout_{WB} & \text{if } RegW_{WB}\land RD_{WB}=RS \\ RF[RS] & \text{otherwise} \end{cases}$$

多级匹配时优先级：更近的（MEM）覆盖更远的（WB），确保写入顺序语义被正确反映，避免新旧值冲突。若同时匹配 MEM 与 WB，必须选 MEM 的值，否则会读回已被覆盖的旧数据。

| 匹配级 | 数据来源 | 就绪时机 |
| --- | --- | --- |
| EX/MEM | 上一拍的 ALU 结果 | 本拍即可用 |
| MEM/WB | 上上拍的结果 | 本拍即可用（已有转发，故无需等 WB） |
| 寄存器堆 | 已提交值 | 读端口输出 |

## 四、代码实现

```verilog
// 转发选择信号（forwardB）组合逻辑
assign forwardB =
    (MEM_WB_RegWrite  && MEM_WB_rd  != 5'd0 && MEM_WB_rd  == ID_EX_rs2) ? 2'b01 :
    (EX_MEM_RegWrite  && EX_MEM_rd  != 5'd0 && EX_MEM_rd  == ID_EX_rs2) ? 2'b10 :
                                                                          2'b00;

// ALU 第二操作数据此选择
always @(*) begin
    case (forwardB)
        2'b00: alu_b = RF[ID_EX_rs2];
        2'b01: alu_b = wb_data;
        2'b10: alu_b = mem_aluout;
    endcase
end
```

```verilog
// ALU 自身 1-cycle 旁路：同一拍内后半段结果回送前半段
assign alu_bypass = (alu_now_rd == ID_EX_rs2) ? alu_out : alu_b;
```

注意优先级写法：`EX_MEM`（更近）的匹配必须写在 `MEM_WB` 之前，Verilog 条件表达式的「短路」语义恰好实现「更近优先」。

## 五、与其他技术对比

| 维度 | 前递（旁路） | 寄存器重命名 | 编译器调度 |
| --- | --- | --- | --- |
| 作用层 | 数据通路硬件 | 寄存器分配 | 指令序列 |
| 消除 RAW | 部分（除 load-use） | 全部 | 掩盖 |
| 代价 | 少量 mux + 比较器 | 物理寄存器堆 + RAT | 无硬件代价 |

前递只解决值可用性问题，对 load-use 仍需停顿；而乱序执行用寄存器重命名 + 发射队列从更高层面消除相关，前递仍是其中基础的数据供给机制。

| 方案 | 是否需 HDU | 额外停顿 | 适用范围 |
| --- | --- | --- | --- |
| 转发 + 单点停顿 | 是（仅 load-use） | 1 拍 | 顺序五级流水 |
| 结果广播（CDB） | 是（保留站控制） | 动态 | 乱序超标量 |
| 编译器调度 | 否 | 无（但代码膨胀） | 简单流水线 |

## 六、常见误区

误区一：forwarding 单元可替代 Hazard Detection Unit。错，load-use 仍需 HDU 产生 stall，二者协作。误区二：转发能消除所有 RAW。错，load 结果在 MEM 末才可用，下一条在 EX 就要，差一拍仍需停顿。误区三：转发发生在 WB 之后。错，转发正是「绕过 WB、直接从段寄存器取值」。误区四：forward 信号越多越好。错，优先级与默认路径必须正确，否则选错源比停顿更危险。

误区五：忘记排除 `rd=0`。错，零寄存器恒为 0，误转发会把 0 当成有效结果。误区六：忘记检查 `RegWrite`。错，store/branch 等不写回指令若被当成转发源，会引入错误数据。

## 七、与开源书·权威来源对应

- Hennessy & Patterson 图 4.x 附近的转发多路选择与控制信号表是经典教材内容，明确 forwardA/forwardB 的优先级。
- CSAPP 的 HCL 控制逻辑描述同样的匹配与选择，并在 PIPE 实现中给出完整信号。
- 二者一致认为转发是「把后向数据依赖转为连线而非停顿」。
- 配套实验（如 CSAPP `archlab`）要求实现完整转发与停滞控制，可直接验证优先级细节。

## 八、面试题

1. forwarding 能否消除所有 RAW？要点：不能，load-use 因结果晚一拍仍需一次停顿；异常与特殊指令也需保守处理。
2. 为什么 MEM 级转发优先级高于 WB？要点：更近的写应先被看到，否则旧值覆盖新值致错。
3. 转发与停顿如何协调？要点：先算转发源，若仍不可得（load-use）再令 HDU 插入 stall。
4. 为什么必须排除 `rd=0` 与 `RegWrite=0`？要点：零寄存器不可写、store/branch 不写回，误判会引入错误转发源。
5. Verilog 条件表达式如何实现「更近优先」？要点：把更近一级写在前面的三元条件分支，短路求值天然给出优先级。
6. 三源（EX/MEM、MEM/WB、ALU 旁路）为何都需要？要点：分别覆盖「差一拍结果」「差两拍结果」与「同一拍内后段结果」三类可用时机。

## 九、演进与趋势

在超标量/乱序核心中，单点对点转发演变为「多条结果总线 + 公共数据总线（CDB）广播网络」：任一写回单元把结果带标签（tag=物理寄存器号）广播，所有等待该 tag 的保留站被唤醒（wakeup）并选中操作数。这种「全局前递」不再依赖固定段寄存器位置，而是基于数据就绪事件动态供给。

随之带来的新问题是「唤醒与选择的时序环」：候选指令被唤醒后需经选择逻辑（select）才能发射，两者在同一周期内形成组合环，限制主频。工业界的应对包括「预测性唤醒（speculative wakeup）」「选择后置（select-then-wakeup）」等流水化改造，把唤醒与选择拆成两拍以换取更高频率——这是前递机制从「连线问题」演化为「时序与调度问题」的典型例证。

## 十、小结

前递硬件的本质是「基于寄存器编号匹配的多路选择」：它把尚未写回的结果直接送回 ALU 输入端，将后向数据依赖转化为连线延迟而非停顿周期，是流水线中成本最低、收益最高的冒险缓解。理解其源优先级与 HDU 的协作，是看懂现代数据通路的关键。设计时要牢记两条守卫条件——排除零寄存器与无写回指令——它们决定转发是「救命」还是「致错」。
