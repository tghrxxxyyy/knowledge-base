# 交换与回收

> 对应 OSTEP 第 21-22 章“交换空间”与 Linux `mm/vmscan.c`。

## 一、背景与挑战
物理内存不足时，需把不常用页换出到磁盘（swap），并在需要时换入；同时回收文件缓存、匿名页以腾出空间，避免 OOM。

## 二、核心原理
- 页类型：文件页（page cache，可丢弃/回写）、匿名页（需 swap）。
- 回收按 LRU 近似（active/inactive 双链）选 victim。
- 交换：匿名页写入 swap 设备，页表项标记为不存在并指向 swap 槽。

## 三、形式化 / 数学基础
工作集模型：进程在窗口 $\\Delta$ 内引用页集 $W(\\Delta)$。若 $|W| > \\text{物理页}$，则需换入换出，产生颠簸（thrashing）。扫描优先级 $\\text{SI} = \\frac{R}{S}$（referenced/age）用于 selection。

## 四、代码实现
收缩 LRU 链表（简化）：

```c
struct page *shrink_list(struct lruvec *l, int n) {
    struct page *victim = NULL;
    for (int i = 0; i < n; i++) {
        victim = lru_tail(&l->inactive);
        if (page_referenced(victim))   /* 近期访问过，保活 */
            move_to_active(victim);
        else
            reclaim_or_swap(victim);    /* 回收或换出 */
    }
    return victim;
}
```

## 五、与其他技术对比
纯分页无 swap 时内存耗尽即 OOM 杀进程；有 swap 可平滑但引入换入延迟。zswap/zram 用压缩内存代替磁盘，降低延迟。

## 六、常见误区
- 以为“开了 swap 就慢”：仅在真正压力下换出，空闲时不用。
- 混淆 page cache 回收与匿名页 swap：前者常无 IO。
- 忽略 swappiness 调参对交互的影响。

## 九、演进与趋势
zswap（压缩交换缓存）、MGLRU（多代 LRU）改善回收决策；内存分级（CXL 内存）引入新的回收层级。

## 十、小结
交换与回收在内存压力下按 LRU 近似回收文件页、换出匿名页，以 IO 延迟换取地址空间延续，是避免 OOM 的缓冲层。
