# 伙伴系统

> 对应 Linux `mm/page_alloc.c` 的伙伴分配器与 Wolf《Linux Kernel Programming》。

## 一、背景与挑战
内核需分配 2 的幂大小的连续物理页块，且释放后能高效合并以减少外部碎片。伙伴系统在“合并”上做了结构化设计。

## 二、核心原理
- 空闲块按 2 的幂阶（order 0..MAX_ORDER）组织成链表。
- 分配：找 >= 所需 order 的最小块，必要时从大块不断二分（halve），另一半作为“伙伴”挂入低阶空闲链。
- 释放：若其伙伴也空闲则合并，递归上推。

## 三、形式化 / 数学基础
块大小 $S = 2^{order} \\times page\\_size$。伙伴地址：$buddy = block \\oplus (S)$（按块大小异或可得配对伙伴）。合并条件：伙伴空闲且未被分配、同阶。

## 四、代码实现
伙伴释放合并（简化）：

```c
struct page *__free_one(struct zone *z, struct page *p, int order) {
    while (order < MAX_ORDER - 1) {
        struct page *b = p ^ (1 << (order + PAGE_SHIFT));
        if (!page_is_buddy(b, order)) break;
        list_del(&b->lru); p = min(p, b); order++;
    }
    list_add(&p->lru, &z->free_area[order]);
    return p;
}
```

## 五、与其他技术对比
伙伴系统避免任意大小导致的碎片，但有内部碎片（只能分配 2 的幂）；slab 在其上按对象大小再切分，降低小对象浪费。

## 六、常见误区
- 认为伙伴系统无碎片：仅消除“不可合并”碎片，仍有 2 的幂内部浪费。
- 忽略 MAX_ORDER 上限（通常 11，约 4 MiB 上限单块）。
- 误用伙伴分配小对象（应走 slab）。

## 九、演进与趋势
引入 per-CPU 页缓存（pcplist）降低锁争用；CMA 与内存规整（compaction）配合缓解大块连续分配困难。

## 十、小结
伙伴系统以 2 的幂块 + 异或伙伴 + 递归合并，在连续物理页分配中兼顾速度与低碎片，是内核页分配基石。
