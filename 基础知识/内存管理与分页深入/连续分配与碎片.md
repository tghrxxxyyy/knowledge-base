# 连续分配与碎片

> 对应 Silberschatz《Operating System Concepts》内存管理章与 Tanenbaum《Modern Operating Systems》。

## 一、背景与挑战
早期内存管理把进程装入连续物理区间。随着分配/释放交错，空闲区被切得零散，产生外部碎片；固定分区则造成内部碎片。

## 二、核心原理
- 首次适应（first-fit）、最佳适应（best-fit）、最差适应（worst-fit）等分配策略。
- 内部碎片：分配单元大于需求（如页内浪费）。
- 外部碎片：总空闲足够但无单块连续满足请求。

## 三、形式化 / 数学基础
外部碎片率 $F = 1 - \\frac{\\text{最大可分配连续块}}{\\text{总空闲}}$。紧凑（compaction）可合并碎片，但需重定位支持（基址/界限或页表）。

## 四、代码实现
首次适应分配器（按地址有序空闲链表）：

```c
chunk *first_fit(chunk *head, size_t need) {
    for (chunk *c = head; c; c = c->next)
        if (c->free && c->size >= need) return c;
    return NULL;
}
```

## 五、与其他技术对比
连续分配简单但直接受碎片限制；分页把物理内存切成固定页框，进程地址空间离散映射，基本消除外部碎片（仅留内部碎片）。

## 六、常见误区
- 认为“总空闲足够就能分配”：连续分配下外部碎片可致失败。
- 混淆内外碎片：内部是块内浪费，外部是块间零散。
- 忽略紧凑的代价（需暂停、重定位）。

## 九、演进与趋势
连续分配被分页/分段取代；现代系统中仅少量场景（DMA 缓冲、固件）仍需连续物理内存（通过 CMA 保留）。

## 十、小结
连续分配简洁但受外部碎片约束；分页以固定页框离散映射，根本性消除外部碎片，仅保留页内内部碎片。
