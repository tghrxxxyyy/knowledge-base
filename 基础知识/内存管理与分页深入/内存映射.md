# 内存映射

> 对应 CSAPP 第 9 章“虚拟内存”与 Linux `mm/mmap.c`。

## 一、背景与挑战
进程需要把文件、共享库或匿名内存映射到地址空间，避免显式 read/write 拷贝。mmap 建立虚拟页到文件/设备的映射。

## 二、核心原理
- `mmap` 在进程页表建映射，缺页时再按需读入（demand paging）。
- 私有映射（MAP_PRIVATE）写时复制；共享映射（MAP_SHARED）多进程可见。
- 文件映射页可被 page cache 复用，多个进程共享同一物理页。

## 三、形式化 / 数学基础
映射区 $[v_{start}, v_{end})$ 对应文件偏移 $[o, o+(v_{end}-v_{start}))$。缺页时 $PPN = \\text{pagecache}(file, o + VPN\\cdot size)$；写私有页触发 COW 复制新页框。

## 四、代码实现
建立文件私有映射：

```c
int fd = open("data.bin", O_RDONLY);
void *p = mmap(NULL, len, PROT_READ, MAP_PRIVATE, fd, 0);
/* 访问 p[i] 触发缺页，内核读入对应页 */
munmap(p, len);
```

## 五、与其他技术对比
相比 `read` 需内核→用户缓冲拷贝，mmap 让 CPU 直接访问 page cache 页，少一次拷贝；但小文件或随机访问可能 TLB/缺页开销不划算。

## 六、常见误区
- 认为 mmap 一定更快：大文件顺序读常优于 read，小随机可能更慢。
- 忽略 MAP_SHARED 写会回写文件（除非 MAP_PRIVATE+COW）。
- 忘 `munmap` 导致地址空间泄漏。

## 九、演进与趋势
`MAP_POPULATE` 预 fault、`madvise(MADV_WILLNEED)` 预取、以及用户态页表（如 io_uring 固定缓冲）降低映射开销。

## 十、小结
mmap 把文件/匿名内存直接映射进页表，按需缺页装入，用缺页+page cache 取代显式拷贝，是零拷贝与共享内存基础。
