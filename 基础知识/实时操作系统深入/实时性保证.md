# 实时性保证

> 对应 Tanenbaum《Modern Operating Systems》实时章与 Linux PREEMPT_RT。

## 一、背景与挑战
实时系统要求事件在可证明的截止时间内被响应与处理。仅有“快”不够，必须提供有界的最坏响应时间（WCRT）保证。

## 二、核心原理
- 可调度性分析：在部署前证明所有任务在截止前完成（如 RMS/EDF，见实时调度篇）。
- 抢占与低延迟：最小化关中断/关抢占临界区，降低调度延迟。
- 确定性：避免不可界定的行为（如随意 GC、无限循环）。

## 三、形式化 / 数学基础
任务最坏响应时间 $R_i = C_i + \\sum_{j\\in hp(i)} \\lceil R_i/T_j\\rceil C_j + L_{pre}$，其中 $hp(i)$ 为高优先级任务集，$L_{pre}$ 为抢占/中断延迟上界。调度可行需 $\\forall i: R_i \\le D_i$。

## 四、代码实现
计算最坏响应时间（响应时间分析，示意）：

```c
int wcrt(task *ts, int n, int i) {
    int R = ts[i].C;
    do {
        int newR = ts[i].C;
        for (int j = 0; j < n; j++)
            if (ts[j].prio > ts[i].prio)
                newR += div_ceil(R, ts[j].T) * ts[j].C;
        if (newR == R) break;
        R = newR;
    } while (R <= ts[i].D);
    return R;
}
```

## 五、与其他技术对比
通用 OS 优化平均吞吐、延迟无界；硬实时 OS（如 VxWorks、QNX）牺牲部分吞吐换确定性；Linux PREEMPT_RT 通过可抢占内核逼近软/硬实时。

## 六、常见误区
- 认为“足够快的处理器=实时”：无界延迟仍可能错过截止。
- 忽略中断延迟也是 WCRT 一部分。
- 混淆软实时（偶尔超时可接受）与硬实时（超时即失效）。

## 九、演进与趋势
Linux PREEMPT_RT 主线化、SCHED_DEADLINE 与 EDF 带宽隔离使通用内核也能承载硬实时负载。

## 十、小结
实时性保证靠“可调度性分析 + 有界抢占/中断延迟 + 确定性”，最坏响应时间上界是判定能否满足截止的核心指标。
