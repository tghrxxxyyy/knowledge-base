# 确定性

> 对应实时与嵌入式系统的确定性要求，及 Tanenbaum《Modern Operating Systems》。

## 一、背景与挑战
确定性指“相同输入与状态下，系统行为（尤其时序）可重复预测”。通用系统为吞吐优化引入大量不可预测因素，与实时/安全关键需求冲突。

## 二、核心原理
- 可预测调度：固定优先级/RMS、EDF 等行为确定。
- 消除不可界因素：禁用动态内存分配（避免碎片与回收抖动）、避免 GC、限定中断延迟。
- 时间触发（time-triggered）：按预排程表在固定时刻执行。

## 三、形式化 / 数学基础
确定性调度保证事件响应时间集合有界且可枚举：$RT \\subset [L_{min}, L_{max}]$，且 $L_{max}$ 由静态分析得出。时间触发下执行函数在时刻 $t_k$ 激活，抖动 $j = |t_{actual}-t_k|\\approx 0$。

## 四、代码实现
时间触发调度表（示意）：

```c
void timetrigger(tick t) {
    static const action *plan[] = {a1, a2, a3, NULL};  /* 固定槽位 */
    action *act = plan[t % SLOT];
    if (act) act();               /* 每个 tick 执行预定动作, 无动态决策 */
}
```

## 五、与其他技术对比
事件触发（event-triggered）灵活但时序可变；时间触发确定性高但资源利用率低。确定性 RTOS 常牺牲平均利用率换取可认证的可预测性。

## 六、常见误区
- 认为“快”等于“确定”：快但抖动大仍不可预测。
- 忽略动态分配/GC 的不可预测延迟。
- 混淆确定性（可重复）与正确性。

## 九、演进与趋势
混合关键级系统（MCS）、可认证 RTOS（如 seL4 微内核形式化验证）在时间触发与事件触发间按需组合。

## 十、小结
确定性要求时序可重复预测：通过固定调度、去除不可界延迟与时间触发执行，把系统行为收敛到可枚举、可认证的范围。
