# 速率单调调度

> 对应 Liu & Layland (1973) RMS 理论与 Tanenbaum《Modern Operating Systems》。

## 一、背景与挑战
周期性实时任务需静态优先级分配策略。速率单调调度（RMS）以“周期越短优先级越高”的简洁规则，在独立周期任务中是最优的静态优先级算法。

## 二、核心原理
- 任务 $i$：周期 $T_i$、计算时间 $C_i$、截止 = 周期。
- 优先级：$\\frac{1}{T_i}$ 越大（周期越短）优先级越高。
- 可调度判据：利用率 $\\le n(2^{1/n}-1)$（充分，非必要）；精确用响应时间分析（见实时性保证篇）。

## 三、形式化 / 数学基础
利用率上限 $U_{lub}(n)=n(2^{1/n}-1)$：
- $n=1:\\ 1.0$
- $n=2:\\ 0.828$
- $n=\\infty:\\ \\ln 2\\approx 0.693$
若 $\\sum C_i/T_i \\le U_{lub}$ 则可调度（sufficiency）。

## 四、代码实现
RMS 调度器选程（按周期排序的就绪表）：

```c
struct rt_task *rms_pick(struct rt_task *q, int n) {
    struct rt_task *best = NULL;
    for (int i = 0; i < n; i++)
        if (q[i].ready && (!best || q[i].T < best->T))
            best = &q[i];
    return best;
}
```

## 五、与其他技术对比
RMS 静态、易实现、可静态分析，但利用率上限约 69%；EDF 动态、利用率达 100% 但对过载敏感（见实时调度篇）。RMS 是静态类最优。

## 六、常见误区
- 认为“利用率<100%就一定可调度”：RMS 下需 < 上限值。
- 把 RMS 当万能：非周期/有资源互斥时需配合协议。
- 忽略判据是充分条件非必要（可达标却被判不可调度）。

## 九、演进与趋势
RMS 与 EDF 常被组合或用于多核分区调度；SCHED_DEADLINE 在 Linux 上提供 EDF 补充，RMS 仍用于静态安全关键系统。

## 十、小结
速率单调调度以“周期短者优先”的静态规则成为周期实时任务的最优静态算法，可调度性由利用率上限或响应时间分析判定。
