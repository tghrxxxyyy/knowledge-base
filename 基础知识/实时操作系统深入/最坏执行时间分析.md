# 最坏执行时间分析

> 对应实时系统 WCET 分析与 Tanenbaum《Modern Operating Systems》实时章。

## 一、背景与挑战
实时可调度性依赖任务最坏执行时间（WCET）。低估 WCET 会导致错过截止；高估则浪费资源。精确分析需考虑流水线、缓存、分支预测等硬件细节，极难。

## 二、核心原理
- 静态分析：对控制流图建模，结合硬件时序（cache 命中/失效、流水线）上界求和。
- 测量法：在目标硬件跑大量测试取最大值（悲观化）。
- 常用抽象：忽略/简化缓存，用流水线阻塞上界。

## 三、形式化 / 数学基础
对基本块 $b$ 的执行时间 $e_b$，路径最坏耗时 $WCET = \\max_{path}\\sum_{b\\in path} e_b$，受缓存/流水线修正为 $e_b = base + cache\\_miss\\_penalty\\cdot h_b$。整体受循环界 $L$ 约束：$\\sum L_i\\cdot e_{loop,i}$。

## 四、代码实现
基于 CFG 的简单 WCET 上界（示意）：

```c
int wcet(cfg_node *n, int *visited) {
    if (!n) return 0;
    int best = n->cost;
    for (edge *e = n->succ; e; e = e->next)
        best = max(best, n->cost + wcet(e->to, visited));
    return best;   /* 忽略循环界时为不安全上界, 需乘迭代次数 */
}
```

## 五、与其他技术对比
静态分析不依赖输入、给出有保证上界但偏保守；测量法贴近实际但可能漏未测路径（不安全）。工业常二者结合并加安全裕度。

## 六、常见误区
- 认为“实测最大值=WCET”：未测路径可能更慢。
- 忽略缓存/流水线使 WCET 难以精确。
- 混淆平均执行时间与最坏执行时间。

## 九、演进与趋势
时间可预测体系结构（如无缓存/可预测缓存）、WCET 自动化工具（aiT、Bound-T）与形式化验证提升分析精度与可信度。

## 十、小结
最坏执行时间是实时可调度性的输入基石：静态分析给保证上界、测量法给贴近值，二者结合并留裕度方能在安全关键系统使用。
