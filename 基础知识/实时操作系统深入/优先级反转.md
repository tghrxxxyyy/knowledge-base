# 优先级反转

> 对应 Tanenbaum《Modern Operating Systems》与著名的 Mars Pathfinder 案例。

## 一、背景与挑战
高优先级任务因等待低优先级任务持有的锁而阻塞，而中优先级任务又抢占低优先级任务运行，导致高优先级被“间接”长时间推迟——优先级出现反转。

## 二、核心原理
- 场景：H（高）等 L（低）持有的锁；M（中）抢占 L 运行；H 因此等 M 完成，优先级实际上低于 M。
- 危害：实时截止被打破，甚至系统失效（如火星探路者）。
- 解决：优先级继承（持有锁时临时升到等待者最高优先级）、优先级天花板。

## 三、形式化 / 数学基础
优先级继承协议：任务 $t$ 持锁时其有效优先级 $\\pi(t) = \\max(\\pi_{base}(t), \\max_{w\\in waiters(t)}\\pi_{base}(w))$。天花板协议：锁 $L$ 的天花板 $= \\max$ 所有可能取 $L$ 的任务优先级，取锁即升到天花板。

## 四、代码实现
优先级继承上扬（示意）：

```c
void lock_pi(mutex *m) {
    raw_lock(&m->raw);
    m->owner = current;
    current->eff_prio = max(current->eff_prio, m->ceil); /* 升到天花板 */
    if (current->eff_prio > current->prio) boost(current);
}
```

## 五、与其他技术对比
不处理反转：实时性无保障；优先级继承只在有等待者时上扬（更紧）；优先级天花板在取锁瞬间即升到天花板（更简单但有对小上界）。

## 六、常见误区
- 认为“高优先级总能先跑”：持锁低优任务可使其久等。
- 忽略中优先级任务的“插队”放大反转。
- 混淆优先级反转与死锁：反转不形成环。

## 九、演进与趋势
实时 Linux（PREEMPT_RT）的 rt_mutex 实现完整的优先级继承；用户态 futex 也支持 PI 以服务实时线程。

## 十、小结
优先级反转是高优任务被低优持锁者间接阻塞的现象；优先级继承/天花板协议通过临时抬升持锁者优先级消除反转。
