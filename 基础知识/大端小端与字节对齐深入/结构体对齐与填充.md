# 结构体对齐与填充

> 对应 Bryant & O'Hallaron《CSAPP》第3章（机器级表示）与 ABI 规范。

## 一、背景与挑战
为让 CPU 高效（或合法）访问，编译器按类型对齐要求插入填充（padding），使结构体实际大小常大于成员之和，跨平台布局也可能不同。

## 二、核心原理
对齐规则：成员偏移为其对齐值的整数倍（通常等于类型大小，如 int 4、double 8）；结构体整体大小为其最大成员对齐的整数倍。编译器据此在成员间/末尾填充。

## 三、形式化与数学基础
设成员序列类型 $T_i$，对齐 $a_i=\min(\text{sizeof}(T_i), \text{max\_align})$。偏移递推：
$$off_0=0,\quad off_{i+1} = \lceil (off_i+\text{sizeof}(T_i))/a_{i+1}\rceil \cdot a_{i+1}$$
总大小 $S = \lceil off_n / a_{max}\rceil \cdot a_{max}$。

## 四、代码实现
```c
#include <stdio.h>
struct S { char c; int i; double d; };
// 典型布局: c(1) + pad(3) + i(4) + d(8) = 16 字节
int main(){ printf("%zu\n", sizeof(struct S)); return 0; }
```

## 五、与其他技术对比
紧凑布局（pragma pack）省内存但可能降低访问速度甚至在某些架构上非法；默认对齐省事且快，但占用更多空间。

## 六、常见误区
误认为 struct 大小等于成员大小之和。填充使二者常不等；序列化到磁盘/网络时必须显式布局而非 memcpy 整个结构体。

## 七、与开源书/权威来源对应
CSAPP 第3章演示结构体对齐与 sizeof；System V AMD64 ABI 规定具体对齐规则。

## 八、面试题
问：如何减少结构体填充？答：按成员大小降序排列（大类型在前）通常减少填充，或用显式 packed 属性权衡性能。

## 九、演进与趋势
Rust/C++ 提供 repr(align/packed) 精确控制；跨语言 FFI 需手动对齐以免踩坑。

## 十、小结
结构体对齐是性能与正确性的隐含约束，理解填充规则才能正确计算大小与做序列化。
