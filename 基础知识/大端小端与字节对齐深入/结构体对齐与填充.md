# 结构体对齐与填充

> 对应 Bryant & O'Hallaron《CSAPP》第 3 章（机器级表示）与 System V AMD64 ABI。

## 一、背景与挑战

`sizeof(struct)` 常常大于各成员大小之和，这个「多出来的字节」就是填充（padding）。填充不是编译器随意浪费，而是为了满足各类型的对齐要求——让 CPU 能够用单条指令（或合法的多字节访问）读取成员。

这带来两类风险：一是**空间与性能的权衡**被忽视，结构体因填充而体积翻倍；二是**跨边界序列化**出错，把含填充的结构体直接写入文件或网络，接收方看到的是未初始化的垃圾字节，且布局随平台变化。理解填充规则，才能正确计算大小、设计布局并做序列化。

## 二、核心原理

对齐的两条基本规则：

1. **成员偏移必须是对齐值的整数倍**。对齐值通常是成员类型的大小（如 `int` 为 4、`double` 为 8），但受平台最大对齐上限约束；
2. **结构体总大小必须是其最大成员对齐值的整数倍**，以便数组中相邻元素都保持对齐。

编译器据此在成员之间插入填充，并在结构体末尾补足到整体对齐的倍数。此外还有 `_Alignas`/`alignas` 显式提高对齐、`#pragma pack` 或 `__attribute__((packed))` 取消填充——后者能省空间，但在某些架构上会引发未对齐访问异常或性能下降。

减少填充的经典技巧是**按成员大小降序排列**：大类型在前，小类型填充在尾部，通常能得到更紧凑的布局。

## 三、形式化与数学基础

设成员类型序列为 $T_1, \dots, T_n$，其对齐值为 $a_i = \min(\text{sizeof}(T_i),\ a_{\max})$，其中 $a_{\max}$ 为平台最大对齐。偏移量递推为：

$$
\text{off}_0 = 0,\qquad
\text{off}_{i+1} = \left\lceil \frac{\text{off}_i + \text{sizeof}(T_i)}{a_{i+1}} \right\rceil \cdot a_{i+1}
$$

结构体总大小为：

$$
S = \left\lceil \frac{\text{off}_n + \text{sizeof}(T_n)}{a_{\max}} \right\rceil \cdot a_{\max}
$$

填充总量即二者之差：

$$
\text{pad} = S - \sum_{i=1}^{n} \text{sizeof}(T_i)
$$

以 `struct S { char c; int i; double d; }` 为例（$a = 1,4,8$，$a_{\max}=8$）：偏移依次为 `c@0`、`i@4`（补 3 字节）、`d@8`，总大小 $S = 16$，而成员和仅 $1+4+8=13$，填充 3 字节。

## 四、代码实现

```c
#include <stdio.h>
#include <stddef.h>

struct S { char c; int i; double d; };
struct Sorted { double d; int i; char c; };   // 按大小降序，填充更少
struct Packed { char c; int i; double d; } __attribute__((packed));

int main(void) {
    printf("S           size=%zu align=%zu\n",
           sizeof(struct S), _Alignof(struct S));
    printf("Sorted      size=%zu\n", sizeof(struct Sorted));
    printf("Packed      size=%zu\n", sizeof(struct Packed));

    // 用 offsetof 验证各成员偏移
    printf("offsets: c=%zu i=%zu d=%zu\n",
           offsetof(struct S, c), offsetof(struct S, i),
           offsetof(struct S, d));
    return 0;
}
```

序列化时应逐字段显式编码（或使用固定布局的结构 + 字节序转换），而不是整体写出结构体。

## 五、与其他技术对比

| 方案 | 空间效率 | 访问速度 | 可移植性 | 适用场景 |
| --- | --- | --- | --- | --- |
| 默认对齐 | 中 | 快 | 高（同平台内） | 通用内存结构 |
| 重排成员（大在前） | 高 | 快 | 高 | 减少填充的常规手段 |
| `packed` 紧凑布局 | 最高 | 可能变慢或异常 | 中（字段偏移变） | 硬件寄存器映射、协议 |
| `alignas` 显式提高对齐 | 降低 | 快（利于 SIMD） | 高 | 向量化、缓存行对齐 |
| 逐字段序列化 | 不适用 | 慢 | 最高 | 网络/磁盘持久化 |

## 六、常见误区

- **认为 `sizeof` 等于成员之和**：填充使二者常不相等，必须逐成员计算或用 `offsetof` 验证。
- **整体 `memcpy` 结构体做序列化**：把填充中的垃圾字节和平台相关布局一并写出，跨机必错。
- **盲目使用 `packed`**：省了空间，却在部分架构上把普通访问变成未对齐访问，可能异常或更慢。
- **忽略数组元素间的对齐**：编译器补齐整体大小时已考虑数组场景，手工改布局需保持该性质。
- **忘记嵌套结构体**：内层结构体的对齐值参与外层布局，嵌套会放大填充。
- **跨语言 FFI 不做约定**：不同语言默认对齐可能不同，须显式声明布局（如 `repr(C)`）。

## 七、与开源书·权威来源对应

Bryant & O'Hallaron《CSAPP》第 3 章以实例演示结构体对齐、填充与 `sizeof` 的计算；System V AMD64 ABI 规定 x86-64 下各类型的具体对齐规则；各编译器手册说明 `packed`、`alignas` 的语义与限制。具体对齐值以目标平台 ABI 官方最新文档为准。

## 八、面试题

- **问：如何减少结构体填充？** 答：按成员大小降序排列通常能显著减少填充，或在确有需要时用 `packed` 并承担性能风险。
- **问：为什么结构体大小要对齐补齐？** 答：保证结构体数组中每个元素的成员都满足对齐要求。
- **问：`packed` 的代价是什么？** 答：可能产生未对齐访问，在严格对齐架构上触发异常或由硬件多次访存导致变慢。
- **问：如何确认实际布局？** 答：用 `offsetof` 打印各成员偏移，或用调试器查看内存。

## 九、演进与趋势

现代语言把布局控制显式化：Rust 用 `#[repr(C)]`、`#[repr(packed)]`、`#[repr(align(N))]` 精确声明；C++ 提供 `alignas`/`alignof`。跨语言 FFI 与二进制协议工具链则倾向于用 schema 描述布局，由代码生成器保证两端一致，把「对齐填充」从人工经验转为工具保证。

## 十、小结

结构体对齐是性能与正确性的隐含约束：偏移递推与末尾补齐共同决定了实际大小。理解填充规则，才能正确计算 `sizeof`、通过重排减少浪费，并在序列化时避开「整体写出结构体」这一经典陷阱。
