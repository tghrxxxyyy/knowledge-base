# 位域与对齐陷阱

> 对应 C 标准中位域（bit-field）规定与 CSAPP 第2章数据表示。

## 一、背景与挑战
位域用于紧凑存储（如标志位），但其内存布局由编译器与 ABI 决定，跨平台、跨编译器甚至跨大小端都可能不同，直接序列化极危险。

## 二、核心原理
C 标准不规定位域相邻位的排列、是否跨字节打包、由高位还是低位开始。因此位域仅适合进程内使用，跨边界通信须用显式移位/掩码。

## 三、形式化与数学基础
位域等价于对整数某段做掩码与移位。提取第 $p$ 位起长 $w$ 的字段：
$$field = (raw \gg p)\;\&\;((1\ll w)-1)$$
写入：
$$raw = (raw \;\&\; \sim(((1\ll w)-1)\ll p))\;|\;(val\ll p)$$
此方式完全可移植。

## 四、代码实现
```c
// 可移植字段提取，替代位域
#define GETF(x,p,w) (((x) >> (p)) & ((1u << (w)) - 1))
#define SETF(x,p,w,v) (x = ((x) & ~(((1u<<(w))-1)<<(p))) | ((v)<<(p)))
```

## 五、与其他技术对比
位域书写简洁但不可移植；显式位运算冗长但确定。网络/磁盘格式必须用后者。

## 六、常见误区
误认为位域布局可预测。即便同编译器，大小端也会改变位序，直接 memcpy 跨机必然出错。

## 七、与开源书/权威来源对应
CSAPP 第2章讲解移位/掩码表示位字段；C 标准（ISO/IEC 9899）明确位域布局是实现定义的。

## 八、面试题
问：为何位域不能用于协议？答：其布局由编译器/ABI/字节序决定，不可移植，必须用显式移位保证一致。

## 九、演进与趋势
Rust 的 bitflags、C++ std::bit 等提供可移植位操作抽象，减少手写出错。

## 十、小结
位域是进程内紧凑工具，跨边界须用确定性的移位/掩码，切忌把实现定义布局当标准。
