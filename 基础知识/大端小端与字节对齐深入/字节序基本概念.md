# 字节序基本概念

> 对应 Tanenbaum《Computer Networks》与 Bryant & O'Hallaron《CSAPP》第2章。

## 一、背景与挑战
多字节整数在内存中按字节存放顺序有两种约定：小端（little-endian，低字节在低地址）与大端（big-endian，高字节在低地址）。跨架构/网络传输时混用会导致数据解释错误。

## 二、核心原理
小端：地址递增方向对应字节权值递增（Intel x86、ARM 默认）。大端：地址递增对应权值递减（传统网络、部分 RISC、Power）。同一 32 位值 0x01020304 在两种序下字节排列相反。

## 三、形式化与数学基础
设整数 $V=\sum_{i=0}^{n-1} b_i 256^{i}$，$b_0$ 为最低字节。在地址基 $A$ 处：
$$mem[A+i] = \begin{cases} b_i & \text{little-endian}\\ b_{n-1-i} & \text{big-endian} \end{cases}$$

## 四、代码实现
```c
#include <stdio.h>
int main(){
    int v = 0x01020304;
    unsigned char* p = (unsigned char*)&v;
    printf("%02x %02x %02x %02x\n", p[0],p[1],p[2],p[3]);
    // 小端机器输出: 04 03 02 01
    return 0;
}
```

## 五、与其他技术对比
小端利于低位运算与类型扩展（地址不变）；大端利于人类阅读与网络协议自然顺序。二者无绝对优劣，关键是协议约定一致。

## 六、常见误区
误认为字节序影响位序。字节序只决定「字节」存放顺序，不影响字节内位顺序；此外它仅针对多字节类型，单字节不受影响。

## 七、与开源书/权威来源对应
CSAPP 第2章「表示与编码」用图示对比大小端；Tanenbaum 在网络层解释为何需要统一网络字节序。

## 八、面试题
问：如何判断本机字节序？答：放一个多字节常量，读其首字节：等于最低字节即小端，等于最高字节即大端。

## 九、演进与趋势
ARM 等支持两种序（BE8/LE），但软件层仍以 LE 为主；跨序问题更多由序列化协议（如 protobuf）规避。

## 十、小结
字节序是「字节在内存中的排列约定」，理解它可避免跨平台与网络数据错读。
