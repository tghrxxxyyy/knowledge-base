# 对齐与原子性保证

> 对应 C11/C++11 内存模型对原子对象对齐的要求与 Intel SDM 对齐与原子性。

## 一、背景与挑战
C/C++ 标准要求原子类型自然对齐；未对齐的原子访问是未定义行为。硬件原子指令通常也只保证对齐地址的原子性，未对齐会被拆成多步。

## 二、核心原理
对齐的 N 字节原子操作落在单一缓存行内，可由缓存锁/MESI 串行化保证不可分割；未对齐可能跨两行，无法整体加锁，故不被支持（或退化为非原子/异常）。

## 三、形式化与数学基础
对齐条件：地址 $a$ 满足 $a\bmod N = 0$，且访问完全位于单个缓存行 $C$（大小 64）：
$$a \ge C_{base} \land a+N \le C_{base}+64 \Rightarrow \text{可缓存锁原子}$$
否则原子性无法由硬件保证。

## 四、代码实现
```c
#include <stdatomic.h>
_Alignas(8) atomic_uint_least64_t a; // 必须 8 字节对齐
// 未对齐的 atomic 指针解引用 -> 未定义行为
```

## 五、与其他技术对比
对齐原子：硬件支持、不可分割。未对齐「原子」：标准未定义、实现可能崩溃或撕裂，必须避免。

## 六、常见误区
误认为加 atomic 关键字就能对任意地址原子。对象必须对齐，且编译器/运行时保证对齐布局，动态未对齐指针仍非法。

## 七、与开源书/权威来源对应
C11/C++11 标准规定原子对象「应对齐到其大小」；Intel SDM 说明 LOCK 对未对齐/跨行退化为总线锁或非法。

## 八、面试题
问：为何原子要求对齐？答：硬件原子依赖单缓存行锁定，未对齐跨行无法整体加锁，标准因而要求对齐。

## 九、演进与趋势
std::atomic_ref 要求被引用对象已正确对齐；sanitizer 可捕获未对齐原子使用。

## 十、小结
原子性与对齐紧密相关：只有自然对齐的对象才能由硬件保证不可分割，未对齐原子是未定义行为。
