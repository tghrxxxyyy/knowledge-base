# 对齐与原子性保证

> 对应 ISO/IEC 9899:2011（C11）与 ISO/IEC 14882:2011（C++11）内存模型，以及 Intel SDM 关于原子操作的说明。

## 一、背景与挑战

开发者常以为「加上 `atomic` 关键字就能对任意地址做原子操作」，事实并非如此。C11/C++11 标准要求原子对象**自然对齐**（对齐到其大小），对未对齐地址的原子访问是未定义行为。硬件层面同样如此：主流 CPU 的原子指令通常只保证对齐地址的原子性。

问题在动态内存、packed 结构体与手工指针运算中尤为隐蔽：编译能通过，运行时却可能崩溃、撕裂或产生难以复现的错误结果。理解「对齐是原子性的前提」，是写出正确并发代码的基础。

## 二、核心原理

现代 CPU 通过缓存一致性协议（如 MESI）实现原子性：对齐且不跨缓存行的访问可以由缓存的独占状态（或锁前缀）串行化，从而对其它核表现为不可分割。其要点有二：

1. **对齐**：地址必须是访问大小的整数倍，保证访问不被拆分；
2. **不跨缓存行**：访问范围完全落在单个缓存行内，缓存协议才能整体加锁。

若二者之一不满足，硬件可能把访问拆成多次操作，此时无法由硬件整体原子化——要么退化为总线锁（性能极差），要么直接不被支持（未定义行为/异常）。因此标准选择「要求对齐」这一保守但明确的约束。

此外，`volatile` 不等于原子：它只禁止编译器优化掉访问，不提供任何跨线程的原子性或顺序保证。原子性必须依赖 `_Atomic`/`std::atomic` 或显式锁。

## 三、形式化与数学基础

设原子对象大小为 $N$、地址为 $a$、所在缓存行大小为 $L$、行基址为：

$$
C_{\text{base}} = \left\lfloor \frac{a}{L} \right\rfloor \cdot L
$$

硬件可保证原子性的条件为：

$$
a \bmod N = 0 \quad \land \quad a \ge C_{\text{base}} \quad \land \quad a + N \le C_{\text{base}} + L
$$

即「自然对齐」且「不跨缓存行」。当 $N \le L$ 且对齐时，第二个条件自动满足（对齐访问必然落在单行内）。反之，若 $a \bmod N \neq 0$：

$$
\exists\, a:\ a \bmod N \neq 0 \Rightarrow \text{行为未定义（标准）/ 可能异常（硬件）}
$$

编译器的对齐保证体现为：静态对象与 `malloc` 返回的指针满足最大对齐，但**手工偏移后的指针不保证**：

$$
\text{aligned}(p + \Delta) \not\Rightarrow \text{aligned}(p)\quad (\Delta \text{ 任意})
$$

## 四、代码实现

```c
#include <stdatomic.h>
#include <stdio.h>
#include <stdlib.h>

// 正确：显式对齐到 8 字节，满足 atomic_uint_least64_t 的对齐要求
_Alignas(8) atomic_uint_least64_t counter;

// 正确：动态分配保证最大对齐，可直接承载原子对象
atomic_int *make_counter(void) {
    atomic_int *p = malloc(sizeof(atomic_int));   // malloc 满足最大对齐
    atomic_init(p, 0);
    return p;
}

int main(void) {
    atomic_store(&counter, 1);
    atomic_fetch_add(&counter, 1);                // 对齐对象的原子操作
    printf("counter = %llu\n",
           (unsigned long long)atomic_load(&counter));

    atomic_int *c = make_counter();
    atomic_fetch_add(c, 42);
    printf("heap counter = %d\n", atomic_load(c));
    free(c);
    return 0;
}
```

## 五、与其他技术对比

| 机制 | 是否保证原子性 | 是否要求对齐 | 主要用途 |
| --- | --- | --- | --- |
| `_Atomic`/`std::atomic` | 是 | 是（否则 UB） | 无锁同步 |
| 互斥锁（mutex） | 是（临界区） | 否 | 通用同步 |
| `volatile` | 否 | 否 | 硬件寄存器、信号处理 |
| `memcpy` 到对齐缓冲 | 不适用（非同步） | 目标需对齐才快 | 安全读取未对齐数据 |
| `atomic_ref`（C++20） | 是 | 被引用对象须对齐 | 对既有对象做原子视图 |

## 六、常见误区

- **认为加 `atomic` 就能对任意地址原子**：对象必须对齐，动态未对齐指针仍非法。
- **把 `volatile` 当原子**：`volatile` 不提供原子性与内存顺序，多线程下依然会撕裂。
- **在 packed 结构体里放原子成员**：packed 破坏了对齐，原子的使用变成未定义行为。
- **只关注对齐忽略缓存行**：对齐但仍跨行的宽访问（如未对齐的 16 字节）仍可能不被原子化。
- **假设 `malloc` 一定满足所有对齐**：它满足最大基本对齐，但 `aligned_alloc` 才支持指定更大对齐。
- **用普通指针强转做原子**：绕过类型系统的对齐假设，是编译器优化的雷区。

## 七、与开源书·权威来源对应

ISO/IEC 9899:2011（C11）与 ISO/IEC 14882:2011（C++11）内存模型规定原子对象应「对齐到其大小」，并定义原子操作的顺序语义；Intel SDM 说明 `LOCK` 前缀在未对齐或跨缓存行时可能退化为总线锁或行为受限；Bryant & O'Hallaron《CSAPP》对缓存一致性与 MESI 协议有系统讲解。具体实现行为以各标准与架构官方最新文档为准。

## 八、面试题

- **问：为什么原子要求对齐？** 答：硬件原子依赖单缓存行锁定与对齐访问，未对齐跨行无法整体加锁，标准因此要求对齐。
- **问：`volatile` 能替代原子吗？** 答：不能。它只防止编译器优化，不提供原子性与内存序。
- **问：malloc 返回的指针对齐如何？** 答：满足最大基本对齐，足以承载常见原子类型；更大对齐需 `aligned_alloc` 等接口。
- **问：如何检测未对齐原子使用？** 答：借助 UBSan/ASan 的对齐检查，或在代码审查中避免手工偏移指针。

## 九、演进与趋势

C++20 的 `std::atomic_ref` 允许对已存在的对象施加原子视图，但明确要求被引用对象已正确对齐，把「对齐前提」写进了类型契约。硬件侧，宽原子（如 16 字节原子的双宽 CAS）在部分平台要求 16 字节对齐，未满足则退化或报错。趋势是把对齐约束前移到语言与工具链，减少运行时的不可预测行为。

## 十、小结

原子性与对齐紧密相关：只有自然对齐、且不跨缓存行的访问，才可能由硬件保证不可分割。标准因此规定未对齐原子为未定义行为，`volatile` 也绝不能替代原子。正确做法是使用 `_Atomic`/`std::atomic`、保证对象对齐（静态或 `aligned_alloc`），并避免手工偏移指针。
