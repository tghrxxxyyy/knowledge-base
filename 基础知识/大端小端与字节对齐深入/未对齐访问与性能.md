# 未对齐访问与性能

> 对应 ARMv8 手册对齐要求与 Intel SDM 对齐行为章节。

## 一、背景与挑战
访问未对齐地址（如以奇地址读 4 字节）在某些架构上非法（触发异常），在另一些上可用但更慢（拆成多次访存）。

## 二、核心原理
x86 支持大多数未对齐访问（除特定指令），但可能需要多个总线周期或跨越缓存行，带来性能与原子性代价。ARM 传统上对齐要求更严，未对齐访问可能 UNDEF 或模拟，虽 ARMv8 放宽但对原子/多字节仍有约束。

## 三、形式化与数学基础
设访问地址 $a$，大小 $s$，对齐要求 $k$。未对齐度：
$$u = a \bmod k,\quad \text{if } u\neq 0 \text{ 则未对齐}$$
跨缓存行访问数 $\ge \lceil (a\bmod 64 + s)/64\rceil$，未对齐常使该值由 1 变 2。

## 四、代码实现
```c
// 未对齐读取（手动拼装，避免架构异常）
uint32_t rd_unaligned(unsigned char* p){
    return (uint32_t)p[0] | ((uint32_t)p[1]<<8) |
           ((uint32_t)p[2]<<16) | ((uint32_t)p[3]<<24);
}
```

## 五、与其他技术对比
对齐访问单指令完成、可原子；未对齐可能多指令、不可原子、易被并发撕裂，需额外同步。

## 六、常见误区
误认为 x86 上未对齐完全无害。虽不报错，但性能下降、失去原子性，且在某些 SIMD/原子指令上仍非法。

## 七、与开源书/权威来源对应
Intel SDM 描述未对齐访问对原子性与性能的影响；ARMv8 手册规定对齐要求；CSAPP 第3章提及对齐访问效率。

## 八、面试题
问：为何多线程下未对齐读危险？答：可能被并发写撕裂为两次访存，读到新旧混合值，且原子指令对未对齐地址不可用。

## 九、演进与趋势
现代编译器与 sanitizer（如 UBSan）能检测未对齐访问；SIMD 仍严格要求对齐以获得最佳性能。

## 十、小结
未对齐访问是「可移植性与性能陷阱」，理解各架构行为才能写出安全高效代码。
