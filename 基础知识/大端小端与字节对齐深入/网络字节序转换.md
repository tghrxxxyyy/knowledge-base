# 网络字节序转换

> 对应 RFC 791（IP）与 RFC 793（TCP）中网络字节序规定。

## 一、背景与挑战
网络协议规定使用大端（网络字节序，network byte order）。主机可能是小端，收发数据必须转换，否则 16/32 位字段全部颠倒。

## 二、核心原理
标准函数 htons/htonl（主机到网络）、ntohs/ntohl（网络到主机）完成 16/32 位转换。在大端主机上这些函数常为 no-op，在小端主机上做字节翻转。

## 三、形式化与数学基础
对 16 位值 $V=b_1 256 + b_0$，转换：
$$V_{net} = b_1 + b_0\cdot 256 = ((V\&0xFF)<<8) | ((V>>8)\&0xFF)$$
32 位同理按 4 字节逆序。

## 四、代码实现
```c
#include <arpa/inet.h>
uint32_t ip = htonl(0x0A000001); // 10.0.0.1 以网络序存放
uint16_t port = htons(8080);
```

## 五、与其他技术对比
手工移位可替代库函数但易错；使用标准化函数保证可移植。对于字符串形式的 IP，应用 inet_pton/inet_ntop 而非手转。

## 六、常见误区
误认为字符串 IP 需要字节序转换。「10.0.0.1」是文本，转二进制才涉及字节序；inet_pton 已正确处理。

## 七、与开源书/权威来源对应
RFC 791/793 规定网络字节序为大端；Stevens《UNIX 网络编程》详述转换函数；xiaolincoder/hello-http 也讲解。

## 八、面试题
问：为何网络用大端？答：历史约定与可读性，且早期网络主机多是大端，沿用成标准，所有实现据此转换即可。

## 九、演进与趋势
现代序列化（JSON、protobuf、cap'n proto）多采用 TLV/明确编码，绕开裸字节序问题；但底层协议字段仍遵循网络序。

## 十、小结
网络字节序统一为大端，主机序转换由标准函数处理，是网络编程正确性的基础细节。
