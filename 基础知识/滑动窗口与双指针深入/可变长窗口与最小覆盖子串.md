# 可变长窗口与最小覆盖子串

> 对应 youngyangyang04/leetcode-master 滑动窗口（LeetCode 76 最小覆盖子串）与 CyC2018/CS-Notes；框架表述亦见 labuladong 算法笔记滑动窗口章节。

## 一、背景与挑战

可变长滑动窗口的核心题型是：在 $s$ 中找满足某约束的连续子串/子数组，求最长、最短或计数，而窗口长度不固定。代表题就是**最小覆盖子串**（LeetCode 76）：给定 $s$ 与 $t$，求 $s$ 中包含 $t$ 所有字符及其数量的最短子串。暴力枚举所有子串并检查是否覆盖 $t$，$O(|s|^2 \cdot |t|)$；即使优化检查，$O(|s|^2)$ 也过不了 $|s| = 10^5$ 级数据。

难点在于：约束是"多种字符、且有数量下限"，不能像"和不超过 k"那样用一个数值表达；窗口合法性也不是简单阈值，而是"每种所需字符都够用"。若没有一套清晰的状态机（右扩直到合法 → 记录 → 左缩找更短 → 重复），代码很容易写成双重循环的变体，或者把 `valid` 计数更新错位，导致漏解、超时或返回错误子串。

面试中这是滑动窗口的"毕业题"：它逼你同时维护**需求表** `need`、**窗口表** `window`、以及**已满足的种类数** `valid`，并精确把握扩缩时机。工程上的投影包括：在日志流里找覆盖全部关键事件的最短时段、在文本里找包含全部关键词的最小片段、排课/会议室的最小时间覆盖等。掌握它，等于掌握了一整类"多重约束最短窗口"的解法骨架。

## 二、核心原理

最小覆盖子串的三张表设计是关键：

1. **`need`**：目标串 $t$ 的字符需求计数，只含 $t$ 中出现过的字符。例如 $t=\texttt{"AABC"}$，`need = {A:2, B:1, C:1}`。
2. **`window`**：当前窗口 $s[L..R]$ 中字符的实际计数（可只维护 `need` 中的字符，减少干扰）。
3. **`valid`**：已满足需求的**字符种类数**，即满足 `window[c] >= need[c]` 的 $c$ 的个数。当 `valid == len(need)` 时，窗口合法（覆盖 $t$）。

注意：判断合法不能用"窗口字符集 ⊇ $t$ 字符集"，必须满足**数量**；也不能用 `window == need` 整体相等（窗口可以有多余字符），正确的条件是"每个需要的字符数量都够"，用 `valid` 计数器增量维护，避免每步扫描整个表。

算法流程：

1. 右指针 $R$ 扫描 $s$，将 `s[R]` 计入 `window`；若该字符在 `need` 中且数量刚好达标（`window[c] == need[c]`），`valid += 1`。
2. 当 `valid == len(need)`：窗口已合法，用 $R-L+1$ 刷新最短答案；然后**尝试收缩**：`L` 右移，撤销 `s[L]`；若撤销导致某字符跌破需求（撤销前恰好等于 `need`），`valid -= 1`。收缩直到不合法为止，过程中每一步都可刷新答案。
3. 继续右扩，重复至 $R$ 走完。

**不变量**：
- `window` 始终是 $s[L..R]$ 的真实计数（扩缩对称更新）；
- `valid` 始终等于"当前满足 `window[c] >= need[c]` 的 $c$ 个数"，只在跨越阈值 $\pm 1$ 时变化；
- 每次 `valid == len(need)` 时的 $[L,R]$ 都是合法候选；收缩阶段保留每次合法瞬间的长度，最终得到全局最短。

**边界条件**：
- $t$ 可能含重复字符，必须计数而非集合；
- $t$ 含 $s$ 中不存在的字符时无解，返回空串；
- 收缩时必须**先判断是否跌破需求，再减计数**（顺序反了会误减 `valid`）；
- 记录答案时用 `start` 与 `min_len` 或切片，注意 Python 切片右开。

这套 need/window/valid 的设计可以原样迁移到其他"多重覆盖"问题：例如"找到包含全部关键词的最短日志片段""最少会议室覆盖全部会议时段"（后者的合法性是覆盖种类数）。关键是把需求写成**带下限的计数向量**，把合法性写成**已达标种类数是否等于需求种类数**，于是判断从 $O(|\Sigma|)$ 降到 $O(1)$，整个算法才能维持线性。

另一个容易被忽略的实现策略：`window` 只记录 `need` 中出现过的字符。这样窗口里无关字符不会污染表，`len(window)` 等统计量也不会被干扰字符影响。在字符集很大（Unicode）而 $t$ 很短时，这能显著降低空间与哈希操作成本。

## 三、形式化与数学基础

设字符集 $\Sigma$，需求向量 $n \in \mathbb{N}^{\Sigma}$（$t$ 的频率），窗口频率 $w(L,R) \in \mathbb{N}^{\Sigma}$。合法性：

$$P(L,R) \iff \forall c,\ w_c(L,R) \ge n_c$$

等价地，令 $m = |\{c : n_c > 0\}|$，

$$\mathrm{valid}(L,R) = \big|\{c : n_c > 0 \land w_c(L,R) \ge n_c\}\big| = m \iff P(L,R)$$

目标：

$$\min\{R - L + 1 : P(L,R)\}$$

增量：$w_c(L,R+1) = w_c(L,R) + [s_{R+1}=c]$，$w_c(L+1,R) = w_c(L,R) - [s_L=c]$。

`valid` 的更新只发生在阈值处：若 $s_{R}=c$ 且 $n_c>0$，当 $w_c$ 从 $n_c-1$ 变为 $n_c$ 时 `valid += 1`；撤销时当 $w_c$ 从 $n_c$ 变为 $n_c-1$ 时 `valid -= 1`。其余情况 `valid` 不变，这样避免了每次扫描 $\Sigma$。

单调性：对固定 $R$，若 $P(L,R)$ 成立，则对 $L' > L$ 可能不成立；若 $P(L,R)$ 不成立，则对 $L' < L$ 可能成立。扫描时 $L$ 只右移，每次 $R$ 对应的最小合法左端 $L^*(R)$ 不减，故总移动 $O(|s|)$，时间 $O(|s| + |t|)$，空间 $O(|\Sigma|)$ 或 $O(|t|)$。

对比"二分答案 + 判定"：二分长度 $\ell$，检查是否存在长度 $\ell$ 的合法窗口，$O(|s|\log|s|)$，常数更大且实现更繁；滑动窗口单趟更优。

## 四、代码实现

标准最小覆盖子串（LeetCode 76）：

```python
from collections import Counter

def min_window(s, t):
    if not s or not t or len(s) < len(t):
        return ""
    need = Counter(t)
    window = {}
    valid = 0
    L = 0
    start = 0
    min_len = float("inf")

    for R, ch in enumerate(s):
        # 右扩
        if ch in need:
            window[ch] = window.get(ch, 0) + 1
            if window[ch] == need[ch]:
                valid += 1

        # 合法则收缩找更短
        while valid == len(need):
            if R - L + 1 < min_len:
                min_len = R - L + 1
                start = L
            out = s[L]
            if out in need:
                # 先判断是否跌破，再减计数
                if window[out] == need[out]:
                    valid -= 1
                window[out] -= 1
            L += 1

    return "" if min_len == float("inf") else s[start:start + min_len]


if __name__ == "__main__":
    assert min_window("ADOBECODEBANC", "ABC") == "BANC"
    assert min_window("a", "a") == "a"
    assert min_window("a", "aa") == ""
    assert min_window("aaflslflsldkalskaaa", "aaa") == "aaa"
```

变体：最小窗口包含 $t$ 的所有字符（数量都 ≥，同上）；若改为"恰好等于"则要换判定。

变体：最长子串至多含 $k$ 个不同字符（LeetCode 340，可变长 + 频率）：

```python
def longest_k_distinct(s, k):
    from collections import defaultdict
    freq = defaultdict(int)
    L = 0
    best = 0
    for R, ch in enumerate(s):
        freq[ch] += 1
        while len(freq) > k:
            out = s[L]
            freq[out] -= 1
            if freq[out] == 0:
                del freq[out]
            L += 1
        best = max(best, R - L + 1)
    return best
```

## 五、与其他技术对比

| 方法 | 时间 | 空间 | 特点 |
|------|------|------|------|
| 暴力枚举子串 + 检查 | $O(|s|^2|t|)$ | $O(1)$ | 仅教学 |
| 滑动窗口（need/window/valid） | $O(|s|+|t|)$ | $O(|\Sigma|)$ | 最短覆盖标准解 |
| 二分答案 + 滑窗检查 | $O(|s|\log|s|)$ | $O(|\Sigma|)$ | 常数大，少用 |
| AC 自动机 / 多模式 | $O(|s|+|t|+\sum|p_i|)$ | 较大 | 多模式串覆盖 |

取舍：单模式多重计数约束 → 本文模板；"至多/最多"类最长问题 → 同框架改判定；多模式、正则匹配 → 自动机。面试里把 need/window/valid 三个名词讲清楚，基本就过关了。

## 六、常见误区

1. **只判断字符出现、不判断数量**。用 `set` 记 $t$ 的字符，$t=\texttt{"aa"}$ 时窗口里只有一个 `a` 也算合法。后果：返回偏长或错误子串。对策：`need` 用 Counter，合法条件是数量达标。
2. **`valid` 更新顺序反了**。收缩时先 `window[out] -= 1` 再判断 `window[out] == need[out]`，此时已跌破，误减或漏减。后果：`valid` 漂移，提前退出或永不收缩。对策：**先比对阈值，再减计数**（扩的时候是先加后比对）。
3. **把 `window == need` 当合法**。窗口可以含多余字符，整体相等太强。后果：漏掉合法解。对策：用 `valid == len(need)`，允许多余字符。
4. **忘记先扩后缩的层次**。把收缩写进 `if` 而非 `while`，一次只缩一格；或在不合法时也去刷新最短。后果：答案不是最短，或复杂度错误。对策：合法才进 while，while 内每次都可刷新答案。
5. **无解返回值不对**。`min_len` 保持 `inf` 时返回了切片或空切片语义混乱。后果：判题失败。对策：显式 `return ""` 或 0，哨兵与返回值写清楚。

## 八、面试题

**1. 如何判断窗口已经覆盖目标串？**
参考答案：`valid` 计数已满足需求的字符种类数，`valid == len(need)` 即合法。比每次遍历 `need` 快，且支持数量约束。

**2. 收缩窗口时为何先减计数再移 L（或先判断再减）？**
参考答案：要看是否刚好跌破需求。正确顺序：若 `window[out] == need[out]`，说明移走后不再满足，`valid -= 1`；然后 `window[out] -= 1`、`L += 1`。顺序反了会让 `valid` 与真实状态不一致。

**3. 若 $t$ 含重复字符，算法要改吗？**
参考答案：不用改结构，`need` 用计数即可；合法条件从"字符集覆盖"变为"每种数量够"。这是 `valid` 要按种类而非字符个数的原因。

**4. 如何扩展到"包含 t 中所有字符的最长子串"？**
参考答案：目标变为最长，收缩条件改为"不再合法就停"，合法时 `max` 长度；注意最长可能无上界（若要求恰好覆盖则有限）。多数变体是"至多/至少 k 个不同字符"，改判定即可。

## 九、演进与趋势

- **多模式最小覆盖**：多个模式串都要出现，可用 AC 自动机维护匹配状态，窗口内记录各模式是否命中；或位掩码压缩。
- **最小窗口子序列**（LeetCode 727）：子序列而非子串，双指针 + 回退，或 DP，比子串覆盖更难。
- **流式最小覆盖**：日志/事件流里找覆盖全部关键事件的最短时间窗，用同样三表结构在线维护；工程上要处理乱序与迟到。
- **与正则/自动机结合**：复杂约束用状态机表达合法性，滑窗维护自动机状态的进出增量。
- **并行分块预处理**：大文本分块统计频率再合并候选窗口，用于超长语料检索。

## 十、小结

最小覆盖子串是可变长滑动窗口的标杆题：`need` 定量需求、`window` 现状、`valid` 统计"已达标种类数"；右扩至合法、记录、左缩找更短，先判阈值再减计数。时间 $O(|s|+|t|)$，把暴力平方级压成线性，也是面试里区分度很高的滑窗考题。
