# 滑动窗口基本框架

> 对应 youngyangyang04/leetcode-master 滑动窗口章节（右扩左缩模板）、CyC2018/CS-Notes 双指针/滑动窗口题解，以及 Sedgewick《Algorithms》中 two-pointer 子数组扫描思想。

## 一、背景与挑战

数组/字符串上有一大类问题：找"满足某条件的连续子段"，求最长、最短或计数。例如"和不超过 target 的最长子数组""包含所有目标字符的最短子串""无重复字符的最长子串"。朴素做法枚举左右端点再验证，$O(n^2)$ 甚至 $O(n^3)$；$n = 10^5$ 时直接超时。更糟的是，很多候选人写出的"滑动窗口"只是把双重循环改写成 `while`，左指针乱回退，复杂度悄悄退化回平方级，自己却以为是线性。

滑动窗口（sliding window）是双指针的一种特化：维护区间 $[L, R]$，只向右扩、按需左缩，使每个元素最多进出窗口各一次，从而把平方枚举压成线性扫描。它在面试中的位置极其重要——字符串/数组中等题的主力模板，也是网络协议（TCP 接收窗口、流量控制）、流处理（时间窗聚合）、限流（令牌桶窗口）等工程概念的算法投影。面试官往往通过追问"为什么是 $O(n)$""什么条件下不能用"，来判断你是背模板还是真懂单调性。

本篇先立起通用框架：不变量、扩缩时机、复杂度来源；后续几篇分别展开定长、可变长、哈希结合、单调收缩与双指针变体。

## 二、核心原理

维护左右指针 $L, R$（通常 $R$ 用 for 循环推进，$L$ 在内层 while 中推进）：

1. **右扩**：`R` 每次向右一格，把 `arr[R]` 纳入窗口，更新聚合状态（和、计数、最值等）。
2. **判断合法性**：若窗口不满足条件，则**左缩**：`L` 右移并撤销 `arr[L]` 的贡献，直到重新合法（或收缩到空）。
3. **记录答案**：在窗口处于合法状态的恰当时机更新 `best`（求最长在扩后/缩后；求最短在合法刚达成时）。

**核心不变量**：
- 窗口状态始终等于 $[L, R]$ 内元素的真实聚合（扩缩时增量维护，不重算）；
- 对"最长"类问题，收缩结束后窗口是"以 $R$ 结尾的最长合法窗口"（或合法窗口的某个前缀边界）；
- 对"最短"类问题，每次合法时用当前 $R-L+1$ 刷新答案，并继续收缩以尝试更短。

**为什么是 $O(n)$**：$R$ 单调右移 $n$ 次；$L$ 也只右移、不回退，最多 $n$ 次。每个元素进出窗口各一次，总移动 $2n$，聚合更新若为 $O(1)$，整体 $\Theta(n)$。这依赖**单调性**：右扩使条件更难满足（或不变），左缩使条件更易满足，于是 $L$ 不需要回退去"救"更早的位置。

**边界条件**：
- 初始 `L = 0`，窗口可为空；
- 收缩用 `while` 而非 `if`（可能需要连缩多格）；
- 更新答案的时机与题意（最长/最短/是否存在）严格对应；
- 求"最短"时若始终不合法，要返回 0 或空串，注意哨兵初值。

## 三、形式化与数学基础

设窗口为区间 $[L, R]$，合法性谓词 $P(L, R) \in \{\mathrm{true}, \mathrm{false}\}$，聚合量 $A(L,R)$ 可增量维护：

$$A(L, R+1) = A(L, R) \oplus a_{R+1}, \quad A(L+1, R) = A(L, R) \ominus a_L$$

其中 $\oplus$ 为"纳入"操作，$\ominus$ 为"撤销"操作（和是 $+/-$，计数是 $+1/-1$，乘积是 $\times/\div$）。

单调性假设（最长型）：

$$P(L,R) \Rightarrow P(L', R) \text{ 对 } L' \ge L \text{（左缩保持合法）}$$

$$P(L,R) \Rightarrow \neg P(L, R') \text{ 可能对 } R' > R \text{（右扩可能破坏）}$$

在此假设下，对每个 $R$，存在最左边界 $L^*(R) = \min\{L : P(L,R)\}$，且 $L^*(R)$ 关于 $R$ 单调不减。算法维护的 $L$ 恰好追随 $L^*$，故总移动量 $O(n)$。

复杂度证明：外层 $R: 0 \to n-1$ 共 $n$ 步；内层 $L$ 累计最多 $n$ 步（$L$ 单调）。若每次扩缩的聚合更新代价 $O(1)$，总时间 $\Theta(n)$，额外空间取决于聚合（和 $O(1)$，频率表 $O(\sigma)$，$\sigma$ 为字符集大小）。

最长型答案：

$$\mathrm{ans} = \max_{R} \big(R - L^*(R) + 1\big)$$

最短型则要在 $P$ 刚变真时记录 $R-L+1$ 并继续压 $L$，求

$$\min\{R - L + 1 : P(L,R)\}$$

若条件非单调（如"子数组中位数不超过 k"），$L^*$ 不单调，框架失效，需平衡树/对顶堆等结构（见《单调性与窗口收缩策略》）。

## 四、代码实现

通用骨架（最长合法窗口，和不超过 `max_sum`，元素非负）：

```python
def longest_valid_window(arr, max_sum):
    L = 0
    cur = 0
    best = 0
    for R in range(len(arr)):
        cur += arr[R]                 # 右扩：纳入 arr[R]
        while cur > max_sum:          # 不合法则左缩
            cur -= arr[L]
            L += 1
        best = max(best, R - L + 1)   # 合法时更新最长
    return best


if __name__ == "__main__":
    # [1,2,3,1,1,1]，和不超过 5：最长合法窗口是 [3,1,1] 或 [1,1,1]，长度 3
    assert longest_valid_window([1, 2, 3, 1, 1, 1], 5) == 3
    assert longest_valid_window([2, 2, 2], 5) == 2
```

最短合法窗口骨架（和至少为 `target`，元素非负）：

```python
def shortest_subarray_at_least(arr, target):
    L = 0
    cur = 0
    best = float('inf')
    for R in range(len(arr)):
        cur += arr[R]
        while cur >= target:          # 合法时尝试压 L 求更短
            best = min(best, R - L + 1)
            cur -= arr[L]
            L += 1
    return best if best != float('inf') else 0
```

模板注释版（便于面试手写）：

```python
def sliding_window_template(s):
    from collections import defaultdict
    window = defaultdict(int)
    L = 0
    best = 0
    for R, ch in enumerate(s):
        # 1) 右扩：更新 window
        window[ch] += 1
        # 2) 收缩：当窗口不满足条件
        while not valid(window):
            window[s[L]] -= 1
            if window[s[L]] == 0:
                del window[s[L]]
            L += 1
        # 3) 更新答案（按最长/最短调整位置）
        best = max(best, R - L + 1)
    return best
```

## 五、与其他技术对比

| 方法 | 时间 | 空间 | 适用 |
|------|------|------|------|
| 暴力枚举两端 | $O(n^2)$~$O(n^3)$ | $O(1)$ | 极小数据 |
| 滑动窗口 | $O(n)$ | $O(1)$~$O(\sigma)$ | 条件单调、连续子段 |
| 前缀和 + 二分 | $O(n\log n)$ | $O(n)$ | 元素非负、和类条件 |
| 前缀和 + 哈希 | $O(n)$ | $O(n)$ | 和等于 k（可负） |
| 二分答案 + 检查 | $O(n\log V)$ | $O(1)$ | 最短/最长可判定性单调 |

取舍：连续子段 + 单调条件 → 滑动窗口；和等于定值且可负 → 前缀哈希；区间最值 → 单调队列；非单调约束（中位数、绝对值中位数等）→ 平衡树/对顶堆。滑动窗口的优势是常数小、代码短、在线单趟扫描；劣势是适用面窄，必须先验证单调性。

## 六、常见误区

1. **收缩条件写反**。在"合法"时收缩、"非法"时扩张，或把 `while` 写成 `if`（一次只缩一格）。后果：窗口不满足不变量，答案错或复杂度退化。对策：口头复述"非法才缩，合法就记录"。
2. **更新答案的时机错**。最短题在收缩**之后**更新（窗口已不是最短候选）；最长题在未合法时就取长度。后果：差一或取到非法窗口。对策：把 `best` 更新写在 while 外（最长）或 while 内、撤销之前（最短）。
3. **左指针回退**。为了"再看看"把 `L` 往左移。后果：破坏 $O(n)$ 保证，且状态难维护。对策：$L$ 只许右移；若感觉要回退，说明条件不单调，换算法。
4. **聚合更新不同步**。扩时加了频率、缩时忘减。后果：窗口状态与真实区间不符，后续全错。对策：扩缩操作必须成对，用 `del` 掉 0 计数避免无效键膨胀。
5. **忽略元素符号**。把"和不超过 k 的最长子数组"模板套到含负数数组。后果：负数让"缩到头"仍可能合法，$L^*$ 不单调，答案错。对策：先确认非负，否则换前缀和/哈希或分治。

## 八、面试题

**1. 滑动窗口为什么是 $O(n)$ 而不是 $O(n^2)$？**
参考答案：$R$ 右移 $n$ 次，$L$ 单调右移最多 $n$ 次，每个元素进出各一次；前提是合法性对 $L$ 单调，$L$ 不回退。若条件非单调则不成立。

**2. 哪些条件下滑动窗口不适用？**
参考答案：合法性不随边界单调变化的，如"中位数不超过 k""区间异或和等于 k"（后者用前缀哈希）。此时 $L$ 需要回退或无法增量维护，改用哈希、平衡树、分治。

**3. 最长与最短模板的差别在哪？**
参考答案：最长——不合法时缩、合法时 `max` 长度；最短——合法时先 `min` 再缩。更新 `best` 的位置不同，哨兵初值也不同（最短用 `inf`，注意无解返回 0）。

**4. 窗口聚合如何做到增量更新？**
参考答案：扩时应用 $\oplus$，缩时应用 $\ominus$，要求操作可逆（和、计数）或可单调撤销（乘积用除法需防 0）。聚合不可逆（如 gcd 可降不可升）时需另想办法。

## 九、演进与趋势

- **与单调队列结合**：窗口最值（LeetCode 239）用双端队列维护候选下标，均摊 $O(1)$。
- **与哈希表结合**：种类/次数约束用频率表 + `valid` 计数，见本专题专篇。
- **流式与协议窗口**：TCP 接收窗口、滑动限流、Flink 滚动/滑动窗口都共享"边界推进 + 增量聚合"模型。
- **可撤销/回滚窗口**：莫队算法把"窗口可回退"版本用于离线区间查询，是滑窗思想的离线推广。
- **并行分块**：大数据下分块预聚合再合并，类似前缀和的并行 scan。

## 十、小结

滑动窗口 = 右扩左缩 + 单调性 + 增量聚合：$L$ 不回退保证 $O(n)$，扩缩成对保证状态正确，答案更新时机区分最长/最短。先判断条件是否单调，再套模板；这是数组/字符串中等题最省力的线性武器。
