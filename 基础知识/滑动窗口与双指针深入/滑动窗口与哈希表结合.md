# 滑动窗口与哈希表结合

> 对应 youngyangyang04/leetcode-master 滑动窗口（含哈希）与 CyC2018/CS-Notes；频率表技巧亦见 Sedgewick《Algorithms》符号表应用。

## 一、背景与挑战

当窗口条件涉及"种类数""某字符最多出现 $k$ 次""频率恰好为 ..."时，单一数值（和、积）无法表达合法性，必须维护窗口内元素的**频率表**。典型题：无重复字符的最长子串（LeetCode 3）、至多含 $k$ 个不同字符的最长子串（LeetCode 340）、替换 $k$ 次后的最长重复字符子串（LeetCode 424）、最长重复子数组/全异或等。朴素做法枚举子串再建频率检查，$O(n^2)$ 甚至 $O(n^3)$，$n=10^5$ 时不可行。

滑动窗口 + 哈希表的组合是中等题主力：用 `dict`/`Counter` 维护 `freq`，配合 `valid` 或"条件计数器"判断合法性，左右指针移动时 $O(1)$ 增量更新。它的难点不在哈希本身，而在**如何把约束翻译成可增量维护的量**——比如"无重复"只需维护"出现次数是否超过 1"；"至多 k 种"维护不同键个数；"最多重复 k 次"维护"出现次数超过 k 的字符个数"。翻译对了，代码就是几十行线性扫描；翻译错了，就会陷入每次全表扫描或逻辑分叉。

工程中同样常见：滑动窗口限流统计去重 IP、风控里最近 N 秒内异常用户种类、流式去重计数、字符集约束校验。面试里它常与"最长/最短子串"绑定出现，是候选人最容易因边界条件翻车的地方。

## 二、核心原理

核心结构：

1. **`freq`（窗口频率表）**：键是元素/字符，值是当前窗口内出现次数。扩时 `freq[x] += 1`，缩时 `freq[y] -= 1`，减到 0 要删除，避免 `len(freq)` 虚高。
2. **条件计数器**：把合法性写成可增量的标量。
   - 无重复：维护"重复字符个数" `over`（`freq[x] > 1` 的键数），或直接用 `while freq[s[R]] > 1` 收缩。
   - 至多 k 种：合法性就是 `len(freq) <= k`。
   - 每个字符最多 k 次：维护"超过 k 的字符种数" `over`，合法 ⇔ `over == 0`。
   - 频率恰好/至少：维护 `valid`（达到阈值的键数），见《可变长窗口与最小覆盖子串》。
3. **扩缩骨架**：右扩更新 `freq` 与计数器；若不合法则左缩（while）；合法时更新答案。

**不变量**：`freq` 始终是 $[L,R]$ 的真实频率；计数器始终等于"当前窗口中满足/违反约束的键数"。因此合法性判断是 $O(1)$，不需要扫描整个表。

**正确性要点**：
- 对"最长"类问题，收缩到刚好合法的边界，此时以 $R$ 结尾的窗口最长；
- 对"最短"类问题，合法时记录并继续收缩；
- 计数器只在跨越阈值时 $\pm 1$，避免误更新。

**复杂度**：每个元素进出各一次，哈希表期望 $O(1)$，总期望 $O(n)$；空间 $O(\min(n, \sigma))$，$\sigma$ 为字符集大小。最坏 $O(n^2)$ 仅在哈希严重冲突时（可换计数数组把 $\sigma$ 固定，如 26 字母用 `int[26]`，严格 $O(n)$）。

**与前缀和 + 哈希的区别**：前缀和哈希处理"和等于 k"这种端点差约束，不要求连续窗口单调；滑动窗口哈希处理"窗口内部构成"约束，要求单调性以便 $L$ 不回退。两者都是"哈希 + 计数"，但适用模式不同。

把约束翻译成计数器，是这一类题的真正门槛。常见翻译如下：约束"无重复"翻译成"出现次数超过 1 的键数 $o=0$"；约束"至多 k 种"翻译成"$|\mathrm{dom}(f)| \le k$"，其中 $\mathrm{dom}(f)$ 是频率表的键集；约束"每个字符最多出现 k 次"翻译成"超过 k 的键数 $o=0$"；约束"至少每种都出现一次"翻译成"达标键数 $valid = |\mathrm{need}|$"。只要合法性是这些标量的布尔组合，就能 $O(1)$ 判断，滑窗才成立；否则要么每次扫描整张表（退化成 $O(n^2)$），要么换更强的数据结构。

频率表还有一个实现上的小技巧：在字符集很小（比如 26 个小写字母）时，用长度 26 的整型数组代替哈希表，既避免哈希冲突的最坏情形，也让 `len(freq)` 之类的操作变成显式的 `distinct` 计数，意图更清晰。这在热点代码与面试手写里都很实用。

## 三、形式化与数学基础

设窗口 $[L,R]$，频率向量 $f \in \mathbb{N}^{\Sigma}$：

$$f_c(L,R) = \#\{i \in [L,R] : a_i = c\}$$

增量：

$$f_c(L,R+1) = f_c(L,R) + [a_{R+1}=c], \quad f_c(L+1,R) = f_c(L,R) - [a_L=c]$$

不同字符数 $d(L,R) = |\{c : f_c > 0\}|$，增量时减到 0 则 $d \mathrel{-}= 1$，从 0 到 1 则 $d \mathrel{+}= 1$。

以"无重复字符的最长子串"为例，合法性 $P(L,R) \iff \forall c,\ f_c(L,R) \le 1$。定义

$$o(L,R) = |\{c : f_c(L,R) > 1\}|$$

则 $P \iff o = 0$。右扩 $a_{R+1}=c$ 时，若 $f_c$ 由 1 变 2，则 $o \mathrel{+}= 1$；左缩 $a_L=c$ 时，若 $f_c$ 由 2 变 1，则 $o \mathrel{-}= 1$。合法性 $O(1)$ 可判。

目标：

$$\max\{R - L + 1 : o(L,R) = 0\}$$

由 $o$ 对 $L$ 的单调性（左缩不会让 $o$ 变大），$L$ 不回退，总移动 $O(n)$。

对"至多 k 种"：$P(L,R) \iff d(L,R) \le k$，同样单调。

对"至多 k 次"：$P \iff \forall c,\ f_c \le k$，用 $o = |\{c : f_c > k\}|$。

哈希表实现的期望复杂度依赖均匀散列；固定字符集用数组计数可去掉期望，得到严格界。

## 四、代码实现

最长无重复子串（LeetCode 3）：

```python
def length_of_longest_substring(s):
    freq = {}
    L = 0
    best = 0
    for R, ch in enumerate(s):
        freq[ch] = freq.get(ch, 0) + 1
        while freq[ch] > 1:            # 出现重复则收缩
            out = s[L]
            freq[out] -= 1
            L += 1
        best = max(best, R - L + 1)
    return best


if __name__ == "__main__":
    assert length_of_longest_substring("abcabcbb") == 3
    assert length_of_longest_substring("bbbbb") == 1
    assert length_of_longest_substring("pwwkew") == 3
    assert length_of_longest_substring("") == 0
```

至多 k 个不同字符的最长子串（LeetCode 340）：

```python
def longest_k_distinct(s, k):
    if k <= 0:
        return 0
    freq = {}
    L = 0
    best = 0
    for R, ch in enumerate(s):
        freq[ch] = freq.get(ch, 0) + 1
        while len(freq) > k:
            out = s[L]
            freq[out] -= 1
            if freq[out] == 0:
                del freq[out]
            L += 1
        best = max(best, R - L + 1)
    return best
```

替换 k 次后的最长重复字符（LeetCode 424，维护窗口最大频率）：

```python
def character_replacement(s, k):
    freq = {}
    L = 0
    max_f = 0   # 窗口内单字符最大频率
    best = 0
    for R, ch in enumerate(s):
        freq[ch] = freq.get(ch, 0) + 1
        max_f = max(max_f, freq[ch])
        # 需要替换的次数 = 窗口长 - max_f
        while (R - L + 1) - max_f > k:
            out = s[L]
            freq[out] -= 1
            L += 1
        best = max(best, R - L + 1)
    return best
```

（424 中 `max_f` 可以不严格回退也正确，因为答案只会在更大窗口时更新；若面试官追问正确性，说明"历史上更大的 max_f 只会让窗口允许更长，不会让非法窗口被计入，最终 best 仍正确"。）

## 五、与其他技术对比

| 方法 | 时间 | 空间 | 适用 |
|------|------|------|------|
| 暴力枚举 + 每次建表 | $O(n^2)$~$O(n^3)$ | $O(\sigma)$ | 教学 |
| 滑窗 + 哈希频率 | 期望 $O(n)$ | $O(\sigma)$ | 种类/次数约束 |
| 滑窗 + 数组计数 | $O(n)$ | $O(\sigma)$ 固定 | 小字符集（a-z） |
| 前缀和 + 哈希 | $O(n)$ | $O(n)$ | 和/异或等于 k（可负） |
| 平衡树/有序统计 | $O(n\log\sigma)$ | $O(\sigma)$ | 中位数、秩约束 |

取舍：种类/次数类约束用滑窗哈希；和类端点约束用前缀哈希；固定小字符集用数组更稳；含秩/中位数用平衡树。面试中主动把 26 字母题写成 `int[26]`，会比 `dict` 更显工程感。

## 六、常见误区

1. **缩窗时只移 L 不更新 freq**。后果：频率失真，后续判断全错，且 `len(freq)` 永不下降。对策：扩缩对称，减到 0 要 `del`。
2. **用 `set` 而不是计数**。`set` 只能表达"是否出现"，无法处理"最多 k 次""恰好 2 次"。后果：约束被弱化，答案偏长。对策：值域用整数计数，另维护阈值计数器。
3. **`len(freq)` 当"不同字符数"却忘了删零键**。后果：种类数偏大，`> k` 判断过严，窗口偏短。对策：删除零键，或单独维护 `distinct`。
4. **收缩条件写成 `if`**。一次只缩一格，某些用例需要连缩多格。后果：答案错误或复杂度退化。对策：while。
5. **在含负数/非单调条件上硬套滑窗**。哈希频率解决的是"构成"约束，若约束是"和等于 k"且含负数，应用前缀哈希；若条件非单调（如中位数），滑窗失效。后果：算法错误。对策：先判断单调性与约束类型。

## 八、面试题

**1. 最长无重复子串的收缩条件是什么？**
参考答案：当新加入字符使 `freq[ch] > 1` 时收缩，直到该字符频率回到 1。合法性是"无重复"，用 while 处理连缩。

**2. 如何改为"至多含 k 个不同字符"？**
参考答案：合法性改为 `len(freq) <= k`，收缩到满足为止；记得减到 0 删除键。$O(n)$。

**3. LeetCode 424 为何可以不回退 max_f？**
参考答案：`max_f` 只增不减，对应的历史最大频率会放宽"允许窗口长度"，但最终答案只在真实合法窗口处更新；窗口收缩保证当前合法，且更大的 max_f 不会使非法窗口被计入。严格证明可说明最优窗口出现时 max_f 一定等于该窗口内真实最大频率。

**4. 哈希表与数组计数如何选择？**
参考答案：字符集小且连续（a-z、0-9）用数组，常数小、无哈希冲突；字符集大或动态（Unicode）用哈希表，空间随实际出现键数增长。

## 九、演进与趋势

- **固定字符集数组化**：把 `dict` 换成 `int[26]`/`int[128]`，常数更小，适合热点路径。
- **与计数树/有序统计结合**：需要动态秩（第 k 小、小于 x 的个数）时，频率表升级为 Fenwick/平衡树，滑窗均摊 $O(\log\sigma)$。
- **流式去重与限流**：最近窗口内独立用户数、去重 IP，用哈希 + 滑窗或 HyperLogLog 近似。
- **与前缀哈希合流**：子数组异或为 k、子矩阵计数等问题里，前缀哈希与滑窗频率分别处理端点约束与构成约束。
- **多维/多约束**：多种资源同时约束（CPU、内存、种类），维护多个计数器，合法条件取交集，是资源窗口调度的算法影子。

## 十、小结

滑动窗口与哈希表的结合，用频率表把"种类/次数"约束变成可增量维护的合法性；扩缩对称更新、减到 0 删键、阈值计数器只在跨越时增减，即可在期望 $O(n)$ 内解决无重复最长、至多 k 种、最多替换 k 次等中等题。先判断约束类型与单调性，再选哈希滑窗或前缀哈希。
