# 双指针：对撞指针与快慢指针

> 对应 youngyangyang04/leetcode-master 双指针章节与 Sedgewick《Algorithms》two-pointer 范式；环检测见 Floyd《Non-Deterministic Algorithms》(1967) 的判环思想。

## 一、背景与挑战

双指针是比滑动窗口更基础的范式：用两个下标/引用协同移动，把"嵌套枚举"压成单趟或近单趟扫描。两大经典形态：

- **对撞指针**：在有序序列上，左端 $i$ 与右端 $j$ 相向而行，每次淘汰一端不可能的解。典型：有序两数之和、盛最多水的容器、三数之和、接雨水（左右最大值）。
- **快慢指针**：同向、速度不同。典型：链表环判定与环入口、链表中点、删除倒数第 $k$ 个节点、归并排序的分割。

朴素做法往往 $O(n^2)$（两数之和双重循环）或需要 $O(n)$ 额外空间（哈希表）；快慢指针则能用 $O(1)$ 空间完成链表环检测，这是面试中"空间优化"的标准答案。工程上的投影包括：归并排序分割链表、检测循环引用、滑动窗口的同向双指针、以及"龟兔赛跑"式的进度检测（心跳/迭代检测）。

面试里双指针几乎必考：它考察排序性利用、边界收束、链表指针操作与不变量。常见翻车点：无序数组硬用对撞、比较节点时用值相等而非身份、环入口推导记错、边界 `i < j` 写成 `i <= j` 导致自配对。

## 二、核心原理

**对撞指针**：序列**有序**（如升序）时，维护 $i < j$。
- 若 $a[i] + a[j] < \mathrm{target}$：$i$ 增大（因为 $j$ 再减只会更小，$i$ 不增无解）；
- 若 $a[i] + a[j] > \mathrm{target}$：$j$ 减小；
- 相等则找到解（或按题意继续找全部解）。

不变量：每次移动都淘汰一端的全部候选。例如和太小，固定 $j$ 时所有更小的 $i$ 都无用；和太大同理。因此 $i, j$ 各自只单向移动，总步数 $\le n$，$O(n)$ 时间、$O(1)$ 空间。

**快慢指针**：
- **判环**：`slow` 每次 1 步，`fast` 每次 2 步；若存在环，二者必在环内相遇；若 `fast` 到 `null` 则无环。
- **中点**：`fast` 到尾时 `slow` 在中点（奇偶长度需约定）。
- **环入口**：相遇后，一指针回起点、两针同速 1 步，再相遇即入口（Floyd 判环的数学推导）。
- **倒数第 k**：`fast` 先走 $k$ 步，再同速，`fast` 到尾时 `slow` 在倒数第 $k$。

不变量：`fast` 与 `slow` 的相对速度差为 1（或固定值），相遇条件与环长相关；同速移位后相遇点满足入口距离等式。

**边界条件**：
- 对撞：必须有序；`i < j` 防止同一元素用两次；找全部解时相等也要移动指针去重。
- 快慢：`fast` 与 `fast.next` 判空防崩溃；比较节点用 `is`（Python）/引用相等，而非值相等；空链表、单节点、自环要特测。

两种形态的统一视角：都是"维护两个游标、利用结构信息减少枚举"。对撞利用**有序性**做单向淘汰；快慢利用**速度差**提取环与中点这类整体性质。滑动窗口则是同向双指针的特化（左指针只在违规时右移）。面试里若能一句话点出"三个都是双指针家族，只是约束不同"，会给面试官留下系统性印象。

对撞指针还有一个常被忽略的细节：找**全部**解时，相等分支里两个指针都要移动，并跳过重复值，否则会输出重复二元组；找**任意**解则可直接返回。三数之和里，固定第一个数后，内层就是有序两数之和，去重发生在枚举层与双指针层两处，漏掉任何一处都会输出重复三元组。

## 三、形式化与数学基础

**对撞正确性**：设 $a_1 \le a_2 \le \cdots \le a_n$，目标 $T$。若 $a_i + a_j < T$，则 $\forall i' < i,\ a_{i'} + a_j \le a_i + a_j < T$，故 $i'$ 全部不可能，$i$ 增；对称地，和过大则 $j$ 减。每次指针移动至少永久排除一个位置，总比较 $O(n)$。

**快慢指针判环**：设链表为"尾巴 + 环"，环长 $C$，入口距起点 $a$，入口距相遇点 $x$。慢针入环时快针已在环内某处；相对速度 1，故每步相对距离 $\pm 1$，在环上必相遇。相遇时设慢针共走 $f$ 步，则快针走 $2f$，差 $f$ 是环长整数倍：$f = a + x + kC$。两针同速从起点与相遇点出发，再走 $a$ 步同时到入口（推导：相遇点回退 $x$ 到入口，与起点走 $a$ 等价于 $a + x = kC$ 的倍数关系，经典结论是"同速后相遇于入口"）。

**中点**：fast 速度 2、slow 速度 1，fast 走完 $n$ 步时 slow 走 $\lfloor n/2 \rfloor$。

**倒数第 k**：fast 先行 $k$，则两者距离 $k$，同速到尾时 slow 恰距尾 $k$。

复杂度：对撞 $O(n)$ 时间 $O(1)$ 空间；快慢 $O(n)$ 时间 $O(1)$ 空间。对比哈希两数之和 $O(n)$ 时间 $O(n)$ 空间，对撞用有序性省空间。

## 四、代码实现

有序两数之和（LeetCode 167，对撞）：

```python
def two_sum_sorted(numbers, target):
    i, j = 0, len(numbers) - 1
    while i < j:
        s = numbers[i] + numbers[j]
        if s == target:
            return i + 1, j + 1      # 题目要求 1-based
        if s < target:
            i += 1
        else:
            j -= 1
    return None


if __name__ == "__main__":
    assert two_sum_sorted([2, 7, 11, 15], 9) == (1, 2)
    assert two_sum_sorted([2, 3, 4], 6) == (1, 3)
```

盛最多水的容器（LeetCode 11，对撞 + 面积）：

```python
def max_area(height):
    i, j = 0, len(height) - 1
    best = 0
    while i < j:
        area = (j - i) * min(height[i], height[j])
        best = max(best, area)
        if height[i] < height[j]:
            i += 1
        else:
            j -= 1
    return best
```

链表判环与环入口（Floyd）：

```python
class ListNode:
    def __init__(self, x):
        self.val = x
        self.next = None

def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:          # 节点身份比较
            return True
    return False

def detect_cycle_start(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            p = head
            while p is not slow:
                p = p.next
                slow = slow.next
            return p
    return None
```

删除倒数第 k 个节点（LeetCode 19，快慢 + 哑结点）：

```python
def remove_nth_from_end(head, k):
    dummy = ListNode(0)
    dummy.next = head
    fast = slow = dummy
    for _ in range(k):
        fast = fast.next
    while fast.next:
        fast = fast.next
        slow = slow.next
    slow.next = slow.next.next
    return dummy.next
```

## 五、与其他技术对比

| 问题 | 哈希法 | 对撞/快慢 | 取舍 |
|------|--------|-----------|------|
| 两数之和（无序） | $O(n)$ 时间 $O(n)$ 空间 | 需先排序 $O(n\log n)$ | 无序用哈希，有序用对撞 |
| 两数之和（有序） | $O(n)$ 空间 | $O(n)$ 时间 $O(1)$ 空间 | 对撞更省空间 |
| 链表环判定 | 哈希存访问 $O(n)$ 空间 | 快慢 $O(1)$ 空间 | 快慢是标准解 |
| 链表中点 | 遍历计数两次 | 快慢一趟 | 快慢 |
| 滑动窗口 | — | 同向双指针 | 见滑窗专题 |

取舍：有序/链表结构信息被利用时，双指针省空间且常数小；无序随机查找用哈希。面试中能说明"排序后可用对撞省掉哈希表"，是加分项。

## 六、常见误区

1. **无序数组用对撞指针**。未排序就相向移动，和的大小关系不成立，会漏解。后果：错误答案。对策：先排序（若需要原下标则存 (值, 下标) 对），或改哈希。
2. **比较值而非节点身份**。`slow.val == fast.val` 在有重复值的链表上会误判相遇。后果：假环或漏环。对策：`slow is fast` / `slow == fast`（Java 引用）。
3. **环入口推导记错**。相遇后不回起点，或同速时指针设置错。后果：入口返回错误。对策：记"相遇后，一头回起点、两针同步 1 步，再遇即入口"。
4. **边界 `i < j` 与 `i <= j` 混淆**。两数之和若 `i <= j` 会把同一元素用两次；接雨水则要 `i < j`。后果：自配对或漏掉边界。对策：按题意写清，测试 $n=2$。
5. **空指针未防护**。`fast.next.next` 在短链表上崩溃。后果：运行时错误。对策：while 条件写 `fast and fast.next`，用哑结点简化删头。

## 八、面试题

**1. 有序数组两数之和为何对撞正确？**
参考答案：有序保证和随 $i$ 增而增、随 $j$ 减而减；和太小时固定 $j$ 的更小 $i$ 全部无效，可整段淘汰。指针单向移动，$O(n)$。

**2. 快慢指针如何找环入口？**
参考答案：先相遇；设起点到入口 $a$、入口到相遇 $b$、环长 $C$，由 $2(a+b) = a+b+kC$ 得 $a = kC - b$。故一针回起点后同速，再走 $a$ 步相遇于入口。

**3. 快慢指针如何找链表中点？**
参考答案：slow 1 步、fast 2 步，fast 到尾时 slow 在中点；偶数长度返回第一个或第二个中点，按题意（有时先走一步调整）。

**4. 何时两数之和用哈希、何时用对撞？**
参考答案：无序且要 $O(n)$ 用哈希；有序（或可排序）且在意空间用对撞；若要三数之和，排序 + 对撞枚举第一个数是标准做法。

## 九、演进与趋势

- **三数之和/四数之和**：排序 + 枚举 + 对撞，去重靠跳过相同值；$O(n^2)$ / $O(n^3)$。
- **接雨水/柱状图最大矩形**：对撞配合左右最大值，或单调栈；是双指针与单调结构的交汇。
- **快慢指针的工程化**：循环引用检测、迭代收敛检测、龟兔进度对比（检测算法是否停滞）。
- **与滑动窗口统一视角**：同向双指针 = 滑动窗口；对撞 = 有序收缩；快慢 = 速度差，三者都可视为"维护两个边界/游标"的策略族。
- **并行/分布式双指针**：外部排序归并、双流对齐（diff/merge），是双指针在 IO 流上的延伸。

## 十、小结

对撞指针利用有序性把两端候选逐步淘汰，快慢指针利用速度差解决链表环、中点与倒数第 k；两者都是 $O(n)$ 时间、$O(1)$ 空间的经典范式。记住有序前提、节点身份比较、环入口推导与 `i < j` 边界，双指针就是面试里性价比最高的武器之一。
