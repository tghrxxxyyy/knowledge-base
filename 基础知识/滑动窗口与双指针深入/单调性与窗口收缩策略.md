# 单调性与窗口收缩策略

> 对应 youngyangyang04/leetcode-master 滑动窗口进阶（乘积小于 K 的子数组）与单调队列/单调栈专题；单调性论证亦见 CLRS 贪心与双指针相关讨论。

## 一、背景与挑战

滑动窗口能跑成 $O(n)$，靠的不是模板本身，而是**单调性**：左指针一旦右移就不用回头。很多候选人背了"右扩左缩"，却在"子数组乘积小于 k"（LeetCode 713）、"绝对差不超过 limit 的最长连续子数组"（LeetCode 1438）、"最长湍流子数组"这类题上写出平方算法，根因是没先判断合法性谓词是否随边界单调。

更一般地，窗口条件有两类：
- **单调条件**：右扩使条件更难满足、左缩使更易满足（如和超过上限、种类超上限、乘积超过上限）。此时 $L$ 只进不退，可用标准滑窗。
- **非单调条件**：扩大窗口可能让条件变好也可能变坏（如"和等于 k"含负数、"中位数不超过 x"、"最大最小值差超过 limit"在某些定义下）。此时 $L$ 需要回退或换结构，标准滑窗失效。

工程中同样要先判断"阈值型/覆盖型/频次型"约束是否可单调维护：限流窗口的"请求数 ≤ N"是单调的；"错误率 ≤ p%"在分母变化时就未必单调，需要更仔细的建模。面试里"为什么是 O(n)"与"什么情况不适用"几乎是必问，答不上来就露馅。

本篇专门讲：如何形式化判断单调性、乘积类问题为何要取对数或注意整数除法、收缩策略何时写成 while、以及非单调时的替代结构。

## 二、核心原理

**单调性定义（实用版）**：设合法性 $P(L,R)$。
- 若 $P(L,R)$ 蕴含 $P(L',R)$ 对所有 $L' \ge L$（左移左端点只会更合法或不变），且
- 存在方向使右扩通常"更不合法"（如和增大、乘积增大、种类增多），

则对每个 $R$，最左合法边界 $L^*(R)$ 单调不减，$L$ 可追随它而不回退。

**收缩策略**：
- 求**最长**合法窗口：不合法时 while 收缩到合法，然后用 $R-L+1$ 刷新。
- 求**最短**合法窗口：合法时先刷新答案，再 while 尝试收缩，直到不合法。
- 求**计数**（如乘积小于 k 的子数组个数）：合法时，以 $R$ 结尾的合法子数组恰有 $R-L+1$ 个，累加后继续。

**乘积类细节**（LeetCode 713）：元素为正整数时，乘积随右扩增大、随左缩减小，具备单调性。但实现上要注意：
- `k <= 1` 时答案恒 0（正整数乘积至少为 1）；
- 用整数除法收缩时，必须保证能除尽（乘积确实含该因子），用 `prod //= nums[L]` 在正整数下成立；
- 大数乘积会溢出（C++/Java），可转对数求和，或在 Python 直接用整数（任意大）；
- 严格/非严格不等式（`< k` vs `<= k`）决定 while 条件，差一常见。

**非单调例子**：
- 子数组和等于 k 且含负数：右扩和可增可减，$L$ 需回退 → 前缀和 + 哈希。
- 中位数约束：增删元素对中位数影响非单调 → 对顶堆/平衡树。
- "最大值-最小值 ≤ limit"：窗口内极差随扩缩变化复杂，但其实仍可单调（LeetCode 1438 用双单调队列），关键在于"违规时收缩一定正确"。

**收缩到空**：若单个元素就违规，$L$ 会越过 $R$，窗口为空；计数题要小心空窗口不要误加。

判断单调性的实用清单：先问自己"右扩时，合法性会变好还是变坏？左缩呢？"若答案是"右扩只会更难合法、左缩只会更容易合法"，就是标准滑窗。若"右扩可能让原本不合法的窗口又变合法"，说明左端点可能要回头，必须换方法。这个判断不需要严格证明，几组小样例手动试一下通常就能看出来——比如给数组里塞进一个负数，看"和"是否还会单调增长。

还有一个常见变体值得单独说：当问题问"最长"且合法性是"至多"型（至多 k 个 0、至多 k 种字符），收缩条件永远是"违规才缩"，答案在合法窗口上取 max；当问题问"最短"且合法性是"至少"型（至少和为 target、覆盖全部字符），答案在"合法刚达成"的那些瞬间取 min，然后立刻尝试收缩。两种时机的差别，比模板本身更值得在面试里讲清楚。

## 三、形式化与数学基础

谓词视角：$P(L,R)$ 表示窗口 $[L,R]$ 合法。若

$$\forall L' \ge L,\ P(L,R) \Rightarrow P(L', R) \tag{左单调}$$

$$\forall R' > R,\ P(L,R) \Leftarrow P(L,R') \text{ 不必成立（右扩可能破坏）}$$

则 $L^*(R) = \min\{L : P(L,R)\}$ 关于 $R$ 单调不减。算法维护 $L = L^*(R)$ 的下界近似，移动量 $\sum \Delta L \le n$。

乘积约束（正数）：$P(L,R) \iff \prod_{i=L}^{R} a_i < k$。取对数：

$$\sum_{i=L}^{R} \ln a_i < \ln k$$

转为"和"约束，单调性同"和不超过 k"。计数：

$$\mathrm{ans} = \sum_{R} \big(R - L^*(R) + 1\big)$$

（每个 $R$ 对应以 $R$ 结尾的最长合法左界之内的全部左端）。

复杂度：$R$ 步 $n$，$L$ 总移动 $O(n)$，每步 $O(1)$，故 $O(n)$。若用对数浮点，注意精度；正整数直接乘除在 Python 安全。

对于"极差 ≤ limit"：维护窗口最大/最小的单调队列，违规时收缩。设 $M(L,R), m(L,R)$ 为最值，$P \iff M - m \le \text{limit}$。右扩时最值可能变大，左缩时最值可能变小，因此违规只可能在扩后出现，收缩到合法即可，$L$ 不回退，仍 $O(n)$。

对于非单调（如和等于 k 含负）：$L^*$ 不单调，总移动可能 $O(n^2)$，必须换前缀哈希。

## 四、代码实现

乘积小于 k 的子数组个数（LeetCode 713）：

```python
def num_subarray_product_less_than_k(nums, k):
    if k <= 1:
        return 0
    L = 0
    prod = 1
    count = 0
    for R in range(len(nums)):
        prod *= nums[R]
        while prod >= k:          # 乘积超限则收缩
            prod //= nums[L]
            L += 1
        count += R - L + 1        # 以 R 结尾的合法窗口数
    return count


if __name__ == "__main__":
    assert num_subarray_product_less_than_k([10, 5, 2, 6], 100) == 8
    assert num_subarray_product_less_than_k([1, 2, 3], 0) == 0
    assert num_subarray_product_less_than_k([1, 1, 1], 1) == 0
```

最长连续 1 的个数，最多替换 k 个 0（LeetCode 1004，单调收缩）：

```python
def longest_ones(nums, k):
    L = 0
    zeros = 0
    best = 0
    for R, v in enumerate(nums):
        if v == 0:
            zeros += 1
        while zeros > k:          # 0 超额则收缩
            if nums[L] == 0:
                zeros -= 1
            L += 1
        best = max(best, R - L + 1)
    return best
```

极差不超过 limit 的最长子数组（LeetCode 1438，双单调队列）：

```python
from collections import deque

def longest_subarray_abs_diff_at_most(nums, limit):
    maxq, minq = deque(), deque()  # 存下标，maxq 递减、minq 递增
    L = 0
    best = 0
    for R, v in enumerate(nums):
        while maxq and nums[maxq[-1]] <= v:
            maxq.pop()
        maxq.append(R)
        while minq and nums[minq[-1]] >= v:
            minq.pop()
        minq.append(R)
        while nums[maxq[0]] - nums[minq[0]] > limit:
            if maxq[0] == L:
                maxq.popleft()
            if minq[0] == L:
                minq.popleft()
            L += 1
        best = max(best, R - L + 1)
    return best
```

## 五、与其他技术对比

| 条件类型 | 单调？ | 方法 | 时间 |
|----------|--------|------|------|
| 和 ≤ k（非负） | 是 | 滑窗 | $O(n)$ |
| 乘积 < k（正数） | 是 | 滑窗 / 取对数 | $O(n)$ |
| 种类 ≤ k | 是 | 滑窗 + 频率 | $O(n)$ |
| 极差 ≤ limit | 是（配合单调队列） | 滑窗 + 双单调队列 | $O(n)$ |
| 和 = k（可负） | 否 | 前缀和 + 哈希 | $O(n)$ |
| 中位数约束 | 否 | 对顶堆 / 平衡树 | $O(n\log n)$ |
| 窗口最值 | — | 单调队列 | $O(n)$ |

取舍：先判断单调方向，再决定是否滑窗；乘积转对数可复用"和"模板但注意精度；非单调条件要么换哈希/堆，要么改二分答案。面试里先说"我确认一下单调性"，比直接默写模板更稳。

## 六、常见误区

1. **把乘积当和一样处理却忽略 k≤1 或溢出**。`k <= 1` 时正整数乘积永远 ≥1，答案 0；C++ 乘积溢出变负会误判。后果：边界用例挂、大数出错。对策：先特判 `k<=1`，大数用对数或 Python 任意精度/逐步收缩避免长积。
2. **整数除法误差**。用浮点 `prod /= nums[L]` 再比大小，浮点误差可能导致 `prod` 略大于/小于真实值。后果：偶发错误计数。对策：正整数用 `//=`，或对数求和。
3. **while 条件写成 `>` 与 `>=` 混淆**。题目要 `< k`，则 `while prod >= k` 收缩；若写 `> k`，会留下 `prod == k` 的非法窗口。后果：多计或少计。对策：把不等式抄进注释，单测含恰好等于 k 的用例。
4. **以为所有"最长子数组"都能滑窗**。含负数和、异或等于 k、中位数等非单调条件，$L$ 回退导致平方。后果：超时或错误。对策：先问元素符号与约束形式。
5. **计数题忘记"以 R 结尾的个数是 R-L+1"**。暴力枚举左端。后果：$O(n^2)$。对策：合法时一次加 `R-L+1`，这是等差计数的固定套路。

## 八、面试题

**1. 何时滑动窗口的 L 必须回退？**
参考答案：合法性谓词不满足左单调时，例如和等于 k 且元素可负（右扩可能让和变小，之前跳过的左端又变合法）。此时改前缀哈希或分治。

**2. 乘积类窗口为何建议取对数转成和？**
参考答案：避免大数溢出与精度/整除问题，且可直接复用"和不超过 k"模板；代价是浮点精度，需注意比较容差，或只在元素较小时用整数乘除。

**3. "以 R 结尾的合法子数组个数"为什么是 R-L+1？**
参考答案：收缩后 $L$ 是最左合法边界，于是 $[L,R], [L+1,R], \ldots, [R,R]$ 全都合法（左缩只会更合法），共 $R-L+1$ 个。

**4. 极差约束怎么维护最值？**
参考答案：双单调队列（deque）维护窗口最大/最小候选下标，扩时弹尾、缩时弹过期队首；违规时收缩。均摊 $O(1)$。

## 九、演进与趋势

- **单调队列/栈**：窗口最值、下一个更大元素，是滑窗与单调结构的合体，见专题文档。
- **二分答案 + 判定**：当最值问题本身可二分长度时，单调性转移到判定函数，常用于"最小化最大"类。
- **对顶堆/平衡树**：动态中位数、秩约束，把滑窗扩展到 $O(\log n)$ 更新。
- **莫队与回滚**：离线区间问题允许 $L$ 回退，用分块+回滚把非单调约束也做到近线性。
- **流式限流与窗口聚合**：工程里"最近窗口是否超阈值"是单调收缩的直接应用；分片计数与平滑窗口是其近似实现。

## 十、小结

滑动窗口的复杂度来自单调性：先判断合法性随边界的方向，再定"非法收缩、合法记录"的时机；乘积类注意 k 边界与溢出，计数类用 R-L+1 等差累加；非单调条件不要硬套模板，改前缀哈希、单调队列或平衡树。会判断单调，才是真会滑窗。
