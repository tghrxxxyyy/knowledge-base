# 攻击树与威胁枚举

> 对应 Bruce Schneier 的《Attack Trees》(Dr. Dobb's Journal, 1999)、Shostack《Threat Modeling: Designing for Security》中的攻击树与攻击图章节、NIST SP 800-30 风险评估指南，以及 Saltzer & Schroeder 1975 的保护设计原则。

## 一、背景与挑战
STRIDE 按数据流元素横向枚举，产出「每个元素可能出什么问题」；但它不回答「攻击者按什么顺序、用什么组合打进来」。真实攻击往往是多步链条：先获取低权限凭证，再横向移动，最后提权。攻击树的作用就是把这种依赖结构显式化，让「组合路径」与「单点漏洞」都能被评估。

## 二、核心原理
攻击树是一棵有向与或树：根节点是攻击者目标（如「读取他人数据」），中间节点是子目标（如「获得有效会话」「绕过授权检查」），叶子是可执行的原子攻击步骤。节点类型决定分解语义：
- **OR 节点**：任一子节点达成即可实现父目标。
- **AND 节点**：所有子节点都需达成。

四个关键实践要点：
- **成本与概率是叶子的一等属性**。没有量化属性的攻击树只是逻辑图，无法支持优先级决策。
- **最便宜路径与最可能路径不同**：攻击者常选成本最低，因此需同时计算两类指标。
- **缓解措施的作用位置**：对 AND 节点，阻断任一子节点即可阻断整条路径（边际收益高）；对 OR 节点，必须覆盖所有子节点才能阻断父目标（覆盖成本高）。这是攻防资源分配的核心洞察。
- **与 STRIDE 配合**：用 STRIDE 保证横向完备，用攻击树表达纵向路径与依赖，叶子可回标 STRIDE 类别形成闭环。

## 三、形式化与数学基础
设叶子 $i$ 的独立成功概率 $p_i \in [0,1]$：

$$P_{or} = 1 - \prod_{i=1}^{k} (1 - p_i),\qquad P_{and} = \prod_{i=1}^{k} p_i$$

成本维度同理，攻击者最少花费为：

$$C_{or} = \min_i c_i,\qquad C_{and} = \sum_{i=1}^{k} c_i$$

美元成本与概率的联合指标用期望成本，即「平均需重复多少次才能成功一次」：

$$\mathrm{EC} = C_{path} \cdot \frac{1}{P_{path}}$$

若攻击者受预算 $B$ 与时间 $T$ 限制，可行路径集合为：

$$\Pi_{feasible} = \{\, \pi \mid C(\pi) \le B,\ T(\pi) \le T \,\},\qquad R_{tree} = \max_{\pi \in \Pi_{feasible}} P(\pi)$$

缓解的边际收益：对某叶子施加有效性 $e$ 的缓解后 $p_i \to p_i(1-e)$。在 AND 节点上父节点概率按因子 $(1-e)$ 缩放；在 OR 节点上衰减因子仅为 $(1 - e\,p_i)$，当 $p_i$ 很小时收益极小。这从数学上解释了「AND 路径上做缓解性价比高」。

规模控制：设平均分支因子 $b$、深度 $d$，节点数为 $O(b^d)$，故实践中需设定「展开到可行动原子步骤即停」的终止准则。

## 四、代码实现
```python
import math

# 攻击树求值：同时得到成功率、最小成本与最便宜路径
def evaluate(node):
    t = node["type"]
    if t == "LEAF":
        return {"p": node["p"], "cost": node["cost"], "path": [node["name"]]}
    kids = [evaluate(c) for c in node["children"]]
    if t == "OR":
        p = 1 - math.prod(1 - k["p"] for k in kids)
        best = min(kids, key=lambda k: k["cost"])
        return {"p": p, "cost": best["cost"], "path": best["path"]}
    if t == "AND":
        return {"p": math.prod(k["p"] for k in kids),
                "cost": sum(k["cost"] for k in kids),
                "path": [n for k in kids for n in k["path"]]}
    raise ValueError(f"unknown node type {t}")

tree = {
    "type": "OR", "name": "读取他人数据",
    "children": [
        {"type": "AND", "name": "伪造会话", "children": [
            {"type": "LEAF", "name": "窃取令牌",     "p": 0.15, "cost": 2000},
            {"type": "LEAF", "name": "绕过签名校验", "p": 0.40, "cost": 8000},
        ]},
        {"type": "LEAF", "name": "注入读取接口", "p": 0.30, "cost": 5000},
    ],
}
res = evaluate(tree)
print("成功概率:", round(res["p"], 4), "| 最便宜路径成本:", res["cost"])
print("路径:", " -> ".join(res["path"]))

# 缓解的边际收益：AND 上阻断一个子节点的降幅通常远大于 OR 上覆盖一个子节点
def p_or(ps):  return 1 - math.prod(1 - p for p in ps)
def p_and(ps): return math.prod(ps)
print("AND 降幅:", round(p_and([0.15, 0.40]) - p_and([0.015, 0.40]), 4))
```

## 五、与其他技术对比

|---|---|---|---|---|
| 视角 | 攻击者目标分解 | 资产/数据流分类 | 真实战术技术 | 多目标状态转移 |
| 结构 | AND/OR 树 | 六类清单 | 战术×技术表 | 有向图，可含环 |
| 是否含路径 | 是，含依赖关系 | 否 | 部分 | 是 |
| 是否可量化 | 是，概率与成本 | 否 | 弱，偏经验 | 是 |
| 主要用途 | 优先级与缓解选点 | 横向完备枚举 | 检测与响应对齐 | 复杂系统路径分析 |
| 主要局限 | 主观概率、易无限展开 | 只枚举不排序 | 偏已知 TTP | 建模与计算成本高 |

## 六、常见误区
误区一：概率主观导致结论失真。若 $p$ 凭感觉填写，整棵树的排序就不可信；应标注置信度并做敏感性分析。
误区二：忽略外部依赖节点。供应链、第三方 API、云服务商的控制权也是攻击面，漏掉会低估整体风险。
误区三：建树过细陷入无限分解。需设定终止准则，否则维护成本超过收益。
误区四：在 OR 节点上只做单点缓解。OR 语义要求覆盖全部子节点才能阻断父目标，做一半只能等比降概率。
误区五：把攻击树当一次性产物。攻击技术、暴露面与依赖都在变，需与威胁情报联动迭代。

## 七、与开源书·权威来源对应
- Bruce Schneier《Attack Trees》(1999)：攻击树概念的原始论文，给出 AND/OR 语义与成本属性用法。
- Shostack《Threat Modeling: Designing for Security》：把攻击树与 DFD、STRIDE 组合使用的工程方法，含图与树的取舍讨论。
- NIST SP 800-30《Guide for Conducting Risk Assessments》：风险要素（威胁源、脆弱性、影响、可能性）的标准划分。
- Saltzer & Schroeder 1975（CACM）：最小权限、机制经济性等原则，为缓解措施的选点提供设计依据。

## 八、面试题
1. OR 与 AND 节点的区别是什么？
   要点：OR 是任一子节点成功即可，AND 需全部成功；这决定缓解策略的覆盖面与边际收益。
2. 如何求最危险的攻击路径？
   要点：对每个可行路径算成功概率与期望成本，取概率最高或期望成本最低者；两者常不同。
3. 在 AND 与 OR 节点上做缓解，收益为何不同？
   要点：AND 只需阻断任一子节点即阻断整条路径；OR 必须覆盖全部子节点，单点缓解只等比降概率。
4. 攻击树的局限有哪些？
   要点：概率主观、易无限展开、难以表达含环与多目标关联的复杂攻击。
5. 攻击树与 STRIDE 如何配合？
   要点：STRIDE 保证横向枚举完备，攻击树补足纵向路径与依赖，叶子可回标 STRIDE 类别做闭环。

## 九、演进与趋势
攻击图把树扩展为多目标、可含环的状态转移图，更适合表达「攻陷 A 后可选多条后续路径」的真实场景，常见于云环境与零信任评估。自动化方向包括从 IaC 与配置中提取可达关系生成攻击图、把漏洞扫描结果映射到图的边上、再用图算法计算最短攻击路径。攻击树也越来越多地与 ATT&CK 技术编号对齐，使建模结论能映射到检测规则与响应预案。具体方法与工具能力以官方最新文档为准。

## 十、小结
攻击树的价值在于把「目标—子目标—原子步骤」的依赖结构显式化，并让每个叶子带上概率与成本，从而支持两类决策：排优先级（哪条路径最可能或最便宜）与选缓解点（AND 路径上阻断一个子节点的收益远高于 OR 上的单点覆盖）。它补充的是 STRIDE 缺失的纵向视角，但必须接受概率主观与规模爆炸这两个固有局限。
