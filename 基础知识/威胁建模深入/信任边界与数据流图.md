# 信任边界与数据流图

> 对应 Howard & LeBlanc STRIDE / OWASP Threat Modeling (DFD)。

## 一、背景与挑战
威胁发生在信任边界跨越处——数据从不可信区进入可信区。画出 DFD 并标出边界，才能精准落 STRIDE。

## 二、核心原理
DFD 元素：外部实体、进程、数据存储、数据流。信任边界是权限/信任级别变化的线(如互联网↔DMZ↔内网)。跨边界的数据流是篡改/泄露高发点。

## 三、形式化与数学基础
设边界切分集合为 $B$，跨边界流 $F_B = \{f : f \text{ crosses } b \in B\}$。威胁暴露面：
$$ E = |F_B| $$
优先对 $f \in F_B$ 施加认证/加密/校验。

## 四、代码实现
```python
# 标记跨信任边界的数据流
trust_zones = {"internet","dmz","internal"}
flows = [("internet","dmz","https"),("dmz","internal","rpc")]
for src,dst,proto in flows:
    if src != dst:
        print(f"边界流 {src}->{dst} 需STRIDE: 认证/加密/完整性")
```

## 五、与其他技术对比
DFD 描述结构与边界；攻击树描述如何突破；STRIDE 描述突破类型。三者构成完整威胁建模。

## 六、常见误区
漏画隐式边界(如同一进程内不同权限线程)。把内网默认当可信而忽略横向移动。

## 七、与开源书/权威来源对应
OWASP Threat Modeling；Microsoft Threat Modeling Tool 基于 DFD+STRIDE。

## 八、面试题

## 九、演进与趋势
自动化 DFD 从 IaC/代码提取；零信任架构模糊网络边界、强调身份边界。

## 十、小结
信任边界是威胁建模的"前线"，DFD 把它可视化，跨边界流即优先加固对象。
