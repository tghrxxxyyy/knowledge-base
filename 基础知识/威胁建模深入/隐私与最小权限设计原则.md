# 隐私与最小权限设计原则

> 对应 Saltzer & Schroeder 1975 年 CACM 论文《The Protection of Information in Computer Systems》中的八条设计原则、OWASP 安全设计原则、NIST SP 800-207 零信任架构，以及 GDPR 第 25 条「数据保护 by design」。

## 一、背景与挑战
系统在功能迭代中不断叠加权限与数据收集：为排查问题记全量日志、为方便调试开宽泛角色、为满足某个需求让服务持有他人数据副本。久而久之，系统持有远超功能所需的权限与数据，既扩大攻击面（一旦被攻陷，横向移动范围大），也带来合规风险。原则的价值在于提供一套「设计时就否决这类退化」的判据。

## 二、核心原理
Saltzer & Schroeder 的八条设计原则：
1. **机制经济性**：保护机制应尽可能简单小巧，越复杂越容易被绕过与出错。
2. **故障安全默认**：默认拒绝，仅在明确授权时放行；决策依赖缺失时结论是「否」。
3. **完全仲裁**：每次对每个对象的访问都要检查权限，不允许「首次检查后长期信任」的缓存式放行。
4. **开放设计**：安全性不依赖实现细节保密，而依赖密钥与凭证保密。
5. **权限分离**：需多重条件同时满足才能获得权限，避免单点决策被攻陷即全盘失守。
6. **最小权限**：每个主体只获得完成任务所必需的最小权限，且时限尽可能短。
7. **最小共用机制**：多个用户共用的机制应尽量少，共享通道是信息泄露与相互影响的来源。
8. **心理可接受性**：机制不应让用户觉得难以使用，否则会被绕过或误用。

隐私语境的扩展：目的限定（只用于声明目的）、数据最小化（只收集与目的直接相关的数据）、存储限定（设置保留期限并到期删除或匿名化）、透明度与控制、完整性与机密性。

落地手段：RBAC 表达角色到权限的映射，ABAC 用属性表达细粒度条件，ReBAC 表达关系；默认拒绝网关与策略引擎执行完全仲裁；短期凭证与令牌降权实现最小权限的时间维度。

## 三、形式化与数学基础
设主体集合 $S$、权限集合 $P$，主体 $s$ 持有 $P_s$、所需最小集 $P_{need}(s)$，则

$$P_{need}(s) \subseteq P_s,\qquad \text{最优 } P_s = P_{need}(s)$$

基数与加权两种过量权限度量：

$$\mathrm{Excess}(s) = |P_s \setminus P_{need}(s)|,\qquad \mathrm{Excess}_\omega(S) = \sum_{s \in S} \sum_{p \in P_s \setminus P_{need}(s)} \omega(p)$$

完全仲裁的形式化：对每次访问请求都要求

$$\mathrm{dec}(s, o, p) = \text{allow} \iff (s, o, p) \in \mathrm{Policy}$$

且不允许「凭历史判定结果跳过检查」的路径。故障安全默认即策略无法判定时返回拒绝：

$$\mathrm{dec}(\cdot) = \text{deny} \quad \text{当 Policy 不可判定}$$

权限分离为合取条件，需 $k \ge 2$ 个独立条件同时满足：

$$\mathrm{allow} \iff \bigwedge_{i=1}^{k} c_i$$

隐私侧的量化对应是 $k$-匿名：对每个准标识符组合 $v$，

$$k\text{-anonymity}: \quad \forall\, v,\ |\{r \in D : r.\mathrm{QI} = v\}| \ge k$$

即每条记录至少与 $k-1$ 条记录在准标识符上不可区分。

## 四、代码实现
```python
import time

# 完全仲裁 + 故障安全默认：每次访问都判定，无法判定即拒绝
def decide(subject, obj, perm, policy):
    try:
        rules = policy.rules_for(obj, perm)
    except LookupError:
        return False                        # 依赖缺失 -> 默认拒绝
    return any(rule.matches(subject, obj) for rule in rules)

def access(subject, obj, perm, policy):
    if not decide(subject, obj, perm, policy):   # 不使用任何放行缓存
        raise PermissionError(f"deny {subject.sid} {perm} on {obj}")
    return obj.read() if perm == "read" else obj.write()

# 最小权限授予：只授必需权限，且带到期时间，权限不累积
def grant(subject, needed, ttl_seconds):
    subject.perms |= set(needed)
    return {"perms": set(needed), "expires_at": time.time() + ttl_seconds}

def revoke_expired(subject, rec):
    if time.time() >= rec["expires_at"]:
        subject.perms -= rec["perms"]        # 到期回收
    return subject.perms
```

## 五、与其他技术对比

| 维度 | 最小权限 | 故障安全默认 | 完全仲裁 | 权限分离 |
|---|---|---|---|---|
| 核心主张 | 只授必需且时限短 | 无法判定即拒绝 | 每次访问都检查 | 多条件同时满足 |
| 落地载体 | RBAC/ABAC、短期令牌 | 默认拒绝网关、白名单 | 策略引擎拦截点 | 双人审批、多签名、分片密钥 |
| 失效模式 | 权限膨胀、长期凭证 | 默认放行、异常吞掉 | 首次检查后缓存放行 | 同一人持有多重凭证 |
| 度量指标 | 加权过量权限 | 未授权请求放行率 | 绕过检查路径数 | 单点可独自完成比例 |
| 性能影响 | 低 | 低 | 中，每次访问都判定 | 中高，需协调 |

## 六、常见误区
误区一：默认允许（故障开放）。配置缺失、策略解析失败、下游不可用时「先放行」是最危险的退化路径。
误区二：权限只增不减。人员调岗、服务下线后旧权限残留，累积成巨大过量权限面，需定期回收与到期机制。
误区三：把开放设计误解为不加密。开放设计说的是算法公开不影响安全，前提是密钥保密；自研保密算法通常更脆弱。
误区四：把「一次登录鉴权」当完全仲裁。登录态只证明身份，每次资源访问仍需授权判定。
误区五：认为 RBAC 就是最小权限。若角色设计宽泛，最小权限并未实现，需配合权限审计与更细粒度。

## 七、与开源书·权威来源对应
- Saltzer & Schroeder 1975（CACM）：八条设计原则的原始出处，最小权限与故障安全默认的经典表述。
- OWASP 安全设计原则与 OWASP Threat Modeling Cheat Sheet：把这些原则映射为应用层可执行的检查项。
- NIST SP 800-207《Zero Trust Architecture》：「永不信任、始终验证」与最小权限在网络架构层面的延伸。
- NIST SP 800-162《ABAC 指南》：属性基访问控制在策略表达上的工程规范。
- GDPR 第 25 条（Data Protection by Design and by Default）：目的限定、数据最小化与存储限定的法规要求。

## 八、面试题
1. Saltzer & Schroeder 的八条原则有哪些？
   要点：机制经济性、故障安全默认、完全仲裁、开放设计、权限分离、最小权限、最小共用机制、心理可接受性。
2. 故障安全默认与故障开放的区别，为什么前者重要？
   要点：前者无法判定时拒绝，后者异常时放行；放行型失效会让配置错误直接变成未授权访问。
3. 最小权限如何在工程上落地？
   要点：按任务授予、使用短期凭证、定期权限审计与回收、用属性策略取代宽泛角色。
4. 完全仲裁的性能代价怎么缓解？
   要点：把判定点靠近资源、缓存策略判定结果而非跳过判定、把判定下沉到统一入口。
5. 零信任与最小权限的关系？
   要点：零信任是最小权限在网络层的体现——信任依据从网络位置换为身份与上下文，每次访问都要验证与授权。

## 九、演进与趋势
零信任把「永不信任、始终验证」变成默认架构，配合短期凭证、设备态势与持续授权，使最小权限从静态配置走向动态判定。隐私 by design 已进入法规，推动数据最小化、目的限定与保留期限成为设计评审必查项。技术手段上，策略即代码、机密计算与差分隐私正在扩散。具体规范与合规要求以官方最新文档为准。

## 十、小结
Saltzer & Schroeder 的原则半个世纪后仍有效，是因为它们描述的是结构性必然规律：机制越简单越难出错，默认拒绝才能收敛配置风险，每次检查才能对抗状态变化，权限越少损失越小。最小权限与故障安全默认是其中影响面最大的两条，工程上通过属性策略、短期凭证、到期回收与统一判定点落地，并在隐私语境下扩展为数据最小化、目的限定与存储限定。
