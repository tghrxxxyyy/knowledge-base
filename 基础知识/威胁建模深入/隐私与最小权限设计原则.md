# 隐私与最小权限设计原则

> 对应 Saltzer & Schroeder 1975 "Protection and Authorization" (CACM)。

## 一、背景与挑战
系统常在功能叠加中累积过量权限与数据收集，既增攻击面又触合规风险。Saltzer & Schroeder 提出八条设计原则至今有效。

## 二、核心原理
核心原则：最小权限(每主体仅得必要权)、机制经济性(小而简)、完全仲裁(每次访问都检查)、开放设计(不靠隐匿)、权限分离、最小共用机制、心理可接受、故障安全默认(默认拒绝)。

## 三、形式化与数学基础
设主体 $s$ 权限集 $P_s$，所需最小集 $P_{need}$：
$$ P_s \supseteq P_{need},\ \text{最优时 } P_s = P_{need} $$
过量权限熵：
$$ Excess = |P_s \setminus P_{need}| $$

## 四、代码实现
```python
# 默认拒绝的访问控制检查
def check(subject_perms, required):
    # 故障安全: 缺省拒绝
    return required in subject_perms  # 完全仲裁每次都查
def grant(user, perm, need_only):
    if perm in need_only:
        user.perms.add(perm)   # 最小权限授予
```

## 五、与其他技术对比
这些是设计哲学，落地为 RBAC/ABAC 与默认拒绝网关。相比具体技术，原则更持久普适。

## 六、常见误区
默认允许(故障开放)违背安全默认。权限只增不减累积。把开放设计误解为不加密。

## 七、与开源书/权威来源对应
Saltzer & Schroeder 1975 原文八原则；OWASP 安全设计原则；CSAPP 提及保护机制。

## 九、演进与趋势
零信任(永不信任，始终验证)是最小权限在网络层的延伸；隐私 by design 入法规。

## 十、小结
Saltzer & Schroeder 原则构成安全设计基石，最小权限与故障安全默认尤其关键。
