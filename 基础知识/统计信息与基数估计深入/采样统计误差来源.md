# 采样统计误差来源

> 对应 PostgreSQL 文档 sampling（`default_statistics_target`）与学术上采样估计偏差分析，参考 Garcia-Molina 第12章。

## 一、背景与挑战
为降低 ANALYZE 开销，统计通常基于随机抽样而非全表扫描。采样带来估计方差，小表或倾斜数据上误差尤大，直接传导到计划质量。

## 二、核心原理
采样率由 `default_statistics_target`（PostgreSQL，控制直方图桶数与采样页数）或类似参数决定。误差来自：采样行数不足、倾斜值被漏采、数据分布随时间漂移、并发写入使采样瞬间不一致。

## 三、形式化与数学基础
对比例 $p$ 的二项估计，标准误：
$$ SE = \sqrt{\frac{p(1-p)}{n}} $$
$n$ 为采样行数。可见稀有值（小 $p$）或采样不足（小 $n$）时误差显著。桶数 $k$ 增大可降低直方图量化误差但提高采样需求。

## 四、代码实现
```sql
-- PostgreSQL 提高采样精度
ALTER TABLE orders ALTER COLUMN amount SET STATISTICS 500;
-- 增大默认目标
SET default_statistics_target = 1000;
```

## 五、与其他技术对比
MySQL 的 `innodb_stats_sample_pages`（旧）与基于持久统计的 `innodb_stats_persistent_sample_pages` 控制采样页，思路类似。列式存储常在写入时维护区块级精确统计，弱化采样误差。

## 六、常见误区
认为统计一定准——采样天然有误差。认为调高目标零成本——更慢的 ANALYZE 与更大统计存储。

## 七、与开源书/权威来源对应
PostgreSQL 文档「Default Statistics Target」；Garcia-Molina 12 章采样估计。

## 八、面试题
问：小表统计反而不准怎么解？答：提高 statistics target 或强制全采样（如 PostgreSQL 表足够小则自动近似全扫）。

## 九、演进与趋势
自适应采样、增量统计随写入追加更新，减少全表 ANALYZE 频率与误差。

## 十、小结
采样统计是开销与精度的权衡，理解误差来源才能正确调参与解读计划。
