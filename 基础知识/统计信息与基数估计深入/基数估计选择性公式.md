# 基数估计选择性公式

> 对应 Garcia-Molina《Database Systems: The Complete Book》第12章与 Silberschatz《OSC》第14章 selectivity estimation。

## 一、背景与挑战

优化器的核心任务，是把一条 SQL 的谓词、连接、分组翻译成「每一步预计返回多少行」（基数，cardinality）。错误的选择性（selectivity）估计会直接选错连接顺序与扫描方式，是坏执行计划的首要根因。

基数估计建立在「选择性公式」之上，而公式的可靠性又完全取决于统计信息的质量。可以说，优化器聪明与否，一半取决于代价模型，一半取决于这些基础公式的输入准不准，二者缺一不可。

## 二、核心原理

**选择性**是谓词过滤后保留的行数占比，取值 $[0,1]$。常用谓词的选择性经验公式：

- 等值谓词：$sel = 1/D$，$D$ 为该列 distinct 值数（假设均匀）。
- 范围谓词：$sel \approx (range / domain) / buckets$，结合直方图更准。
- 多谓词（独立假设）：各选择性相乘。
- 等值连接 $R \bowtie S$：包含假设 $sel = 1 / \max(D_R, D_S)$。

优化器把各表基数与连接选择性连乘，得到中间结果与最终结果的估计大小，再用代价模型比较不同计划。注意，公式输出是「估计」而非「真实」，真实值只能靠执行后统计；偏差会在多层连接中被连乘放大。

## 三、形式化与数学基础

对表 $R$ 行数 $N_R$，多谓词下基数：

$$ card(R) = N_R \cdot \prod_i sel(pred_i) $$

等值连接 $R \bowtie S$ 的基数（包含假设，即连接键在对方都存在）：

$$ card(R \bowtie S) = \frac{N_R \cdot N_S}{\max(D_R, D_S)} $$

范围谓词用直方图桶估计：

$$ sel(a \le x < b) \approx \sum_{bucket \cap [a,b]} \frac{overlap}{bucket\_range} \cdot \frac{bucket\_rows}{N} $$

多列相关时，独立乘积被依赖系数修正（见「多列统计与相关性」）。代价模型通常为：

$$ Cost = \sum_{step} (IO + CPU \cdot card_{step}) $$

基数误差会被后续连接放大，首层估计最关键。设每层误差 $\epsilon$，经 $L$ 层连接后相对误差约 $(1+\epsilon)^L$，呈指数增长。

## 四、代码实现

```sql
-- 观察优化器的基数估计（rows 列）
EXPLAIN SELECT * FROM users WHERE city = 'BJ' AND age > 30;
-- 叠加多谓词时对比独立相乘与真实
EXPLAIN ANALYZE SELECT * FROM users WHERE city = 'BJ';
EXPLAIN ANALYZE SELECT * FROM users WHERE age > 30;
-- 二者真实基数可能与独立相乘估计偏差很大（列相关时）

-- 查看某列统计以核验公式输入
SELECT attname, n_distinct, most_common_vals
FROM pg_stats WHERE tablename = 'users';
```

## 五、与其他技术对比

| 系统 | 估计手段 | 特点 |
| --- | --- | --- |
| PostgreSQL | 直方图 + MCV + 多变量统计 | 组合较完整 |
| MySQL | 索引统计 + 直方图 | 单列为主 |
| 商业库 | 动态采样 + 自适应 | 首执后修正 |
| Learned | 模型预测基数 | 前沿，抗相关 |

商业库引入动态采样与运行时修正（adaptive query）缓解估计偏差；learned cardinality 用模型直接预测，弱化对公式与静态统计的依赖，适合强相关、倾斜严重的分析负载。

## 六、常见误区

- 把 `rows` 当真实行数：它只是估计，与实际常有出入。
- 认为多谓词一定相乘：列相关时独立相乘失效，需多列统计修正。
- 认为 distinct 数即均匀：倾斜列下 $1/D$ 假设严重失真，需 MCV / 直方图。
- 认为连接基数公式总是准：包含假设忽略连接键缺失值，外连接与 NULL 会显著偏离。

## 八、面试题

- 等值连接基数怎么估？答：两表行数乘积除以较大 distinct 数（包含假设）。
- 为什么估计会差？答：统计缺失、列相关、数据倾斜、采样误差。
- 范围谓词为何用直方图？答：均匀假设在倾斜列失真，直方图按桶刻画分布更准。
- 基数误差为何在连接中放大？答：每层基数连乘，误差随连接层数指数级累积。

## 九、演进与趋势

Learned cardinality（用回归 / 神经模型预测基数）、动态重优化在首执后校正，以及多列统计自动发现，是提升估计精度的前沿方向；将估计误差反馈进统计刷新，形成闭环自校正，从「一次性估计」走向「边执行边学习」。

应用这些公式时，要时刻记住它们的隐含前提：等值 $1/D$ 假设了均匀与无 NULL；$1/\max(D_R,D_S)$ 假设了连接键在对方都存在（即无孤儿值）；独立相乘假设了列间无关。任一前提不成立，公式就偏离真实，且偏差会沿连接链放大。

因此调试坏计划的有效起点，是「倒推公式输入」：看优化器用的 $D$、直方图、MCV 分别来自哪列统计，再与实际数据比对，往往能定位是哪一列统计失真导致整条计划崩坏。

在复杂查询里，手动估算一遍基数（纸面算）是极有价值的训练：它能让你预判优化器会怎么想，进而判断该调统计、加提示还是改写法。很多「玄学慢查询」在纸面估算后都会现出原形。

最后，公式只是工具，真正的决策由代价模型完成；选择性估计越准，代价模型才越可信。把「基数估计」当作优化器链条的第一环来重视，是成为合格 DBA / 性能工程师的分水岭。

## 十、小结

基数估计是优化器决策的数学基础：选择性公式把谓词转成行数，统计质量与相关性处理共同决定计划好坏；理解公式是读懂 `EXPLAIN` 的第一步，也是定位计划退化的核心工具，更是 DBA 调优的底层语言。
