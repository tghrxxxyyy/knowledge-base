# 直方图类型与构建

> 对应 PostgreSQL 官方文档「Histogram」与 MySQL 8.0 直方图特性，参考 Garcia-Molina《Database Systems》第12章。

## 一、背景与挑战

单列统计若只有「distinct 值数」与「平均宽度」，无法刻画值的分布形状。当数据倾斜（如少数用户产生绝大多数订单）时，范围谓词 `amount > 1000` 的基数估计会严重失真。直方图把列值范围分成若干桶（bucket）并记录每桶频次，使优化器对范围与倾斜值的估计更准，是基数估计的关键补充。

没有直方图，优化器对范围查询只能靠均匀假设，倾斜数据下计划极易选错——要么高估而走不必要的索引，要么低估而误判全表扫描代价。

## 二、核心原理

- **等宽直方图（equi-width）**：每桶覆盖相同值域 $[b_{i-1}, b_i)$。实现简单，但在密集区域精度差（一桶塞入大量行），稀疏区域又浪费。
- **等高直方图（equi-height / SERIAL）**：每桶含相同行数。更抗倾斜，能均匀刻画长尾，但桶内分布不可见。
- **Singleton（MySQL 8.0）**：对低频值逐一记录其精确频次，适合 distinct 多但单值频次低的列。
- **Equi-height（MySQL 8.0）**：等价于等高直方图。

PostgreSQL 用等高直方图配合 `most_common_values`（MCV）处理长尾：MCV 单独记录高频值，其余值进直方图，避免高频值被「平均」掉造成估计偏差。

## 三、形式化与数学基础

等高直方图桶边界 $b_0 < b_1 < \dots < b_k$ 满足每桶行数近似相等：

$$ count(b_{i-1} \le x < b_i) \approx \frac{N}{k} $$

对某桶内值 $v$ 的选择性估计：

$$ sel(v) \approx \frac{bucket\_rows}{distinct\_in\_bucket \cdot total\_rows} $$

等宽直方图则按值域比例：

$$ sel(v) \approx \frac{range\_in\_bucket}{total\_range} \cdot \frac{bucket\_rows}{total\_rows} $$

等高在倾斜数据下误差更小，因为每桶行数可控；等宽在均匀数据下更直观。桶数 $k$ 越大，量化误差越小，但存储与 `ANALYZE` 成本上升。

## 四、代码实现

```sql
-- MySQL 8.0 建直方图
ANALYZE TABLE orders UPDATE HISTOGRAM ON amount WITH 32 BUCKETS;
SELECT * FROM information_schema.COLUMN_STATISTICS;  -- 查看桶

-- PostgreSQL 的等高直方图由 ANALYZE 自动构建
ALTER TABLE orders ALTER COLUMN amount SET STATISTICS 100;
ANALYZE orders;
-- 查看：SELECT histogram_bounds, most_common_vals FROM pg_stats WHERE attname='amount';
```

## 五、与其他技术对比

| 类型 | 抗倾斜 | 存储 | 适用 |
| --- | --- | --- | --- |
| 等宽 | 差 | 低 | 分布均匀 |
| 等高 | 好 | 中 | 通用默认 |
| Singleton | 好（低频） | 高 | 多 distinct 低频列 |

PostgreSQL 直方图 + MCV 协同；MySQL 8.0 直方图对无法建索引的列（表达式、文本前缀）特别有用，弥补索引选择性信息缺失，但单列假设仍无法处理相关性。

## 六、常见误区

- 认为直方图替代索引：它只辅助估计选择性，不改变访问路径本身。
- 认为桶越多越好：过多桶增加存储与分析开销，且更新成本上升，边际收益递减。
- 认为等高直方图桶内均匀：桶内分布未知，仅用均匀假设估计，极端聚集仍会偏差。
- 认为直方图能估连接选择性：单列的直方图不能直接估两列连接，需多列统计。

## 八、面试题

- 等高与等宽区别？答：等高每桶行数相等抗倾斜，等宽每桶值域相等实现简单但密集区失真。
- PostgreSQL 为何还要 MCV？答：高频值进 MCV 精确记录，避免被直方图均匀化抹平。
- 直方图能估连接选择性吗？答：不能直接，需配合多列统计 / 相关性。
- Singleton 适合什么列？答：distinct 很多但单值频次低的列，逐一记录更准。

排障时有个快速判断：若 `EXPLAIN` 对范围谓词的估计明显偏离实际，先看该列有无直方图（`histogram_bounds` 是否为空）；为空说明从未构建，建之即可。若已有但仍偏差，多半是桶数太少或数据刚漂移，需提高目标或刷新。

值得一提的是，直方图与 MCV 是互补而非替代：直方图管「连续范围」，MCV 管「离散高频」。二者都健全，范围与等值谓词估计才同时可靠，缺一则另一类查询仍会退化。

## 九、演进与趋势

多维直方图（2D 直方图、基于采样的近似直方图）、以及 learned distribution（用模型拟合列分布）处理列间相关性，是提升基数估计的研究热点；自动直方图构建（如 Oracle）减少人工干预，并按列重要度差异化桶数。

选用直方图类型时有个简单判据：若数据分布大致均匀，等宽足够且更省存储；若高度倾斜或含少数极端高频值，等高 + MCV 是更稳的组合，因为等宽会把「长尾」全压进一两个桶里失真。

桶数并非越多越准：桶数超过 distinct 值数后收益归零，且每个桶都占统计存储、每次 ANALYZE 都更慢。经验上 100 桶已基本覆盖大多数列的刻画需求，再高多是浪费。

运维上，直方图只在 `ANALYZE` 时重建，因此它也会过期（见「统计信息过期与计划退化」）。对频繁大批量更新的表，应在更新后主动 `ANALYZE` 相关列，否则直方图仍停留在旧分布，范围查询计划同样会退化。

值得补充的是，直方图本身不解决「多列相关」：它描述单列分布，两列联合分布仍需多列统计。把直方图与函数依赖统计结合，才是完整刻画真实数据形状的手段。

## 十、小结

直方图通过刻画值分布弥补单列均值统计不足，是倾斜数据下计划准确的关键；等高 + MCV 是工程上最稳妥的组合，但桶数需在精度与开销间权衡，且直方图只解决单列分布，相关性需多列统计。
