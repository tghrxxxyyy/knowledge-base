# 策略模式与开闭原则

> 对应 Gamma, Helm, Johnson & Vlissides 1994 (GoF《Design Patterns》)。

## 一、背景与挑战
同一行为的多种算法（如折扣计算、压缩方式）若用 if/else 分支实现，新增算法须修改原代码，违反开闭原则。

## 二、核心原理
将每个算法封装为独立策略类，实现统一接口；上下文持有一个策略引用，运行时可切换，从而使系统对扩展开放、对修改关闭。

## 三、形式化与数学基础
策略接口 S 定义 algorithm()。上下文 C 含字段 s: S。运行时 C.s = Si 即切换行为。新增策略 = 新增类，原 C 与已有 Si 不变。

## 四、代码实现
```python
class Discount:
    def price(self, p): raise NotImplementedError
class Vip(Discount):
    def price(self, p): return p * 0.8
class Normal(Discount):
    def price(self, p): return p
class Cart:
    def __init__(self, d): self.d = d
    def total(self, p): return self.d.price(p)  # 行为可插拔
```

## 五、与其他技术对比
相比状态模式，策略不持有状态转移；相比模板方法，策略把整个算法外置而非只留出钩子。

## 六、常见误区
- 策略类过多导致类膨胀，可结合函数式（传 lambda）简化。
- 把本应属于领域规则的简单分支过度抽象。

## 七、与开源书/权威来源对应
GoF 将策略列为行为型模式；Martin《Clean Code》强调用多态替代switch/if分支。

## 八、面试题
策略模式与状态模式的区别？如何用 lambda 简化策略？何时不该使用策略模式？

## 九、演进与趋势
函数式语言直接用高阶函数表达策略；DI 容器可按配置注入不同策略实现 A/B 测试。

## 十、小结
策略模式是开闭原则的经典落地，用组合替代分支，代价是对象数量增加。
