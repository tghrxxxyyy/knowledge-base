# 装饰器模式与责任链

> 对应 Gamma, Helm, Johnson & Vlissides 1994 (GoF《Design Patterns》)。

## 一、背景与挑战
希望在不修改原有类的前提下动态叠加功能（日志、缓存、鉴权），继承会导致子类组合爆炸。

## 二、核心原理
装饰器实现与被装饰对象相同的接口，内部持有一个同类型引用，在委托前后添加增强逻辑。责任链则让多个处理器依次处理请求，或中断传递。

## 三、形式化与数学基础
装饰器：D wraps C，调用 d.op() = enhance(op())。责任链：处理器 H1->H2->...，每个可处理并决定是否 next()。

## 四、代码实现
```python
class Handler:
    def handle(self, req): raise NotImplementedError
class Auth(Handler):
    def __init__(self, n): self.n = n
    def handle(self, req):
        if not req.get("token"): return "denied"
        return self.n.handle(req) if self.n else None
class Biz(Handler):
    def handle(self, req): return "ok"
```

## 五、与其他技术对比
装饰器强调透明增强，责任链强调顺序流转与短路；二者皆可替代多层继承。

## 六、常见误区
- 装饰顺序影响结果（如先缓存后日志与反之不同），需显式约定。
- 责任链过长导致调试困难，需保证可观测。

## 七、与开源书/权威来源对应
GoF 同时收录装饰器与责任链；Web 框架中间件即二者结合的典型实现。

## 八、面试题
装饰器与代理的区别？责任链如何避免请求无人处理？如何调试长链？

## 九、演进与趋势
AOP 将装饰逻辑以切面声明，运行时织入，进一步减少样板代码。

## 十、小结
装饰器与责任链都用组合实现灵活增强，是避免继承膨胀的常用手段。
