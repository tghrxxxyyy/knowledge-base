# 单例模式的线程安全实现

> 对应 Gamma, Helm, Johnson & Vlissides 1994 (GoF《Design Patterns》)。

## 一、背景与挑战
在进程内需要唯一实例的场景（配置中心、连接池、注册表）中，重复创建会浪费资源并引发状态不一致。难点在于多线程并发首次访问时可能构造出多个实例。

## 二、核心原理
- 私有化构造器，对外提供静态访问点。
- 用类级锁或双重检查锁定（DCL）保证初始化的原子性。
- 饿汉式在类加载时创建，天然线程安全但可能提前占用资源；懒汉式延迟创建但需处理并发。

## 三、形式化与数学基础
设线程集合 T，实例引用 i。要求最终满足：
forall t in T: read(i) 后 i != null，且只存在一个对象 o 使得 created(o) == true。
DCL 的正确性依赖内存屏障：写 i 与写对象字段之间需 happens-before 关系。

## 四、代码实现
```java
public class Singleton {
    // volatile 防止指令重排导致的半初始化对象
    private static volatile Singleton instance;
    private Singleton() {}
    public static Singleton get() {
        if (instance == null) {            // 第一次检查，避免每次加锁
            synchronized (Singleton.class) {
                if (instance == null) {    // 第二次检查，保证唯一
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

## 五、与其他技术对比
相比全局变量，单例提供受控访问与延迟初始化；相比依赖注入容器，单例更轻量但难以替换与测试。DCL 比每次加锁的懒汉式性能更好。

## 六、常见误区
- 漏写 volatile，JDK 1.5 之前可能因重排返回未初始化完成的对象。
- 在分布式环境中误以为进程内单例等于全局唯一，实际需借助分布式锁或专用协调服务。

## 九、演进与趋势
现代更推荐通过依赖注入框架（如 Spring 的单例作用域、Guice）管理生命周期，避免手写并发单例样板代码。

## 十、小结
单例的核心是受控唯一性，线程安全靠锁加内存可见性保障，实践中优先交给容器管理。
