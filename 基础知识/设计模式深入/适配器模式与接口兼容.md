# 适配器模式与接口兼容

> 对应 Gamma, Helm, Johnson & Vlissides 1994 (GoF《Design Patterns》)。

## 一、背景与挑战
复用的第三方库或遗留系统接口与目标接口不一致，直接修改其代码不可行，需要在不改动双方的前提下让它们协同工作。

## 二、核心原理
适配器实现目标接口，内部持有被适配者引用，在方法调用时做参数映射与转换，使不兼容接口无缝对接。

## 三、形式化与数学基础
目标接口 T 定义方法 m(a)。被适配者 A 有方法 n(b)。适配器 f: a -> b 满足 T.m(a) = A.n(f(a))，从而屏蔽差异。

## 四、代码实现
```java
interface Target { void request(String s); }
class Legacy { void oldRequest(int id) { /* ... */ } }
class Adapter implements Target {
    private Legacy legacy = new Legacy();
    public void request(String s) {
        int id = Integer.parseInt(s);  // 转换接口差异
        legacy.oldRequest(id);
    }
}
```

## 五、与其他技术对比
相比外观模式（为子系统提供简化入口），适配器聚焦单一接口转换；相比桥接，适配器处理的是既有不兼容而非预先设计的二维变化。

## 六、常见误区
- 适配器里塞入业务逻辑，应只做适配与转换。
- 双向适配器隐藏了耦合，慎用。

## 七、与开源书/权威来源对应
GoF 将适配器列为结构型模式；CyC2018/CS-Notes 有适配器与桥接的对比示例。

## 八、面试题
适配器与桥接模式如何区分？类适配器与对象适配器的优劣？何时该重构而非适配？

## 九、演进与趋势
在微服务中，API Gateway 与 BFF 层承担了类似适配与聚合的职责，把协议转换前移到边界。

## 十、小结
适配器是集成遗留与第三方系统的关键模式，原则是把转换收敛在一处。
