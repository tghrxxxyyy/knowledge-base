# 原子操作与内存屏障

> 对应 Bryant & O'Hallaron《CSAPP》第 12 章并发；Love《Linux Kernel Development》第 9 章原子与屏障。

## 一、背景与挑战

多核下 `counter++` 并非原子：它展开为「读-改-写」三条指令，期间可被其他核插入，导致丢失更新。需要 CPU 提供的原子指令（LOCK 前缀 / LL-SC）以及内存屏障来约束编译与 CPU 重排，才能保证并发正确性。原子操作是一切锁与无锁结构的基础砖块。

实践中的难点在于「原子性」与「顺序性」常被混为一谈：原子只保证单个操作不可分割，却不保证多个原子操作之间的顺序，也不保证非原子数据随之可见。ABA 问题、内存回收（如无锁栈的节点释放）与「原子变量与非原子数据混用」是三类典型陷阱，其根因都在于过度信任「原子即安全」。

## 二、核心原理

`atomic_add` 用 `LOCK XADD` 在总线上锁住对应缓存行完成读改写；x86 上 `LOCK` 前缀使后续指令原子执行（锁定缓存行而非真的锁总线，MESI 下为缓存锁）。ARM 用 LL-SC（Load-Link/Store-Conditional）：先 `LDXR` 读并标记，再 `STXR` 条件存储，若期间被他人改则存储失败需重试。内存屏障（`smp_mb`/`mb`）禁止编译器与 CPU 重排特定访存，避免「发布未初始化数据」等坑——写数据后写标志，二者间需写屏障。

LL-SC 的关键性质是「独占监视（exclusive monitor）」：它只监视被标记地址所在的一致性粒度（通常是一个缓存行）。因此存在两个边界情况：其一，对同一缓存行内其他地址的写也可能导致 STXR 失败（虚假失败），需在重试循环中容忍；其二，监视会因中断、上下文切换、缓存行被驱逐而失效，故 LL-SC 循环必须足够短且不能包含可能睡眠的操作。

## 三、形式化与数学基础

原子 RMW 满足：所有实例的操作构成全序，且其间无中间态对外可见：

$$\forall i,\ op_i\ \text{全序},\ \text{无中间态可见}$$

顺序一致性要求：`smp_mb()` 在其两侧访存间建立 happens-before。经典 Dekker 标志测试（无屏障）失效，因为两线程的「写标志」可互相重排到「读对方标志」之后：

$$init\ then\ flag=1 \not\Rightarrow other\ sees\ init$$

加屏障后该序被强制保留。

| 内存序意图 | x86 实现 | ARMv8 实现 |
| --- | --- | --- |
| 全屏障（mb） | `mfence` 或 `lock` 前缀 | `dmb ish` |
| 写写（wmb） | 通常为空（TSO 保证） | `dmb ishst` |
| 读读（rmb） | 通常为空 | `dmb ishld` |
| acquire | 编译器屏障（无指令） | `dmb ishld` / `ldar` |
| release | 通常为空 | `dmb ishst` / `stlr` |

## 四、代码实现

```c
// 原子自增（x86 LOCK XADD）
static inline void atomic_inc(atomic_t *v) {
    asm volatile("lock xaddl %0, %1"
        : "+r"(one), "+m"(v->counter)
        : : "memory");        // "memory" 阻止编译器重排
}
// 发布数据：写数据后写标志，二者间加写屏障
data = 42;
smp_wmb();                     // 写写屏障，保证 data 先于 ready 可见
ready = 1;
```

ARM 上 `smp_wmb` 展开为 `dmb ishst`，x86 因 TSO 多为空（store→store 本就不重排）。

```c
// LL-SC 重试循环（ARM 风格）：必须容忍虚假失败
int atomic_cas_llsc(int *p, int expect, int desired) {
    int cur, ok;
    do {
        cur = __ldxr(p);                  // 加载链接：标记本行
        if (cur != expect) { __clrex(); return cur; }  // 清除监视标记
        ok = __stxr(desired, p);          // 条件存储：被改则失败
    } while (ok != 0);                    // 失败则重试（含虚假失败）
    return expect;
}
```

## 五、与其他技术对比

| 工具 | 作用 | 代价 | 适用 |
| --- | --- | --- | --- |
| 原子指令 | 单变量 RMW | 低（缓存锁） | 计数/标志 |
| 内存屏障 | 约束重排 | 中（拖慢流水） | 发布点 |
| 锁 | 临界区 | 高（可能睡眠） | 多变量复杂不变式 |
| RCU | 读零开销 | 写复杂、需宽限期 | 读多写少 |

原子指令 vs 锁：原子无阻塞适合单变量；锁适合临界区。acquire/release 比全屏障更轻且语义足够；相较 RCU，屏障用于单一发布点。

## 六、常见误区

1. 误以为单条 C 语句原子——`i++` 是三条指令，非原子。
2. 误以为 `volatile` 保证原子/有序——仅禁编译器缓存该变量，不提供 RMW 原子、不阻止 CPU 重排。
3. 误以为加锁就无需屏障——锁内已有屏障，但「锁外发布数据」仍需显式屏障。
4. 误以为 LL-SC 失败一定因真实冲突——同缓存行其他地址的活动也会导致虚假失败，重试循环须容忍。
5. 误以为原子操作等于「读最新值」——原子保证单一变量全序与不可分割，不保证实时读到「刚写的值」。
6. 误以为原子 CAS 就能解决 ABA——需配合版本计数/标签指针，否则指针自增后 A→B→A 会骗过 CAS。

## 八、面试题

1. 为什么 `i++` 线程不安全？答：非原子 RMW，多核交错导致丢失更新。
2. `smp_mb` 作用？答：在全序中保证其两侧访存不被重排，建立跨线程 happens-before。
3. LL-SC 与 LOCK XADD 区别？答：x86 用锁缓存行做原子 RMW；ARM 用「加载链接+条件存储」重试，遇冲突则 STXR 失败重来。
4. 何谓 LL-SC 的虚假失败？答：即使目标地址未被改，同缓存行的其他活动或监视失效也会令 STXR 失败，需重试。
5. 原子操作能替代锁吗？答：单变量可以；多变量复杂不变式仍需锁，原子只保证单点不可分割。
6. ABA 问题如何解决？答：给指针附带版本号或使用「标签指针/双字 CAS」，使 A→B→A 不满足 CAS 的期望值。

## 九、演进与趋势

C11 `_Atomic`/C++ `std::atomic` 标准化原子语义；ARMv8.1 LSE 扩展提供原生原子指令（如 `CAS`、`SWP`）降低 LL-SC 重试开销；TSX 事务内存曾作为实验性替代，但因安全/禁用趋于边缘。

另两条主线值得关注：一是「降低原子代价」——x86 的 `lock` 前缀在单核或未共享缓存行时的成本差异显著，软件通过缓存行填充（避免 false sharing）与「每线程本地计数 + 汇总量」把原子从热路径移除；二是「内存回收」——无锁结构普遍依赖安全回收（epoch、hazard pointer、RCU、GC）来避免「读线程仍持有旧节点时被写线程释放」，原子操作本身不解决这一问题。

## 十、小结

原子指令消除读改写竞态，内存屏障约束重排，二者是构建一切锁与无锁结构的基础砖块。理解「原子只保单变量、屏障才保顺序」是避免并发 bug 的根本。进一步应牢记「原子不解决回收与 ABA」：任何无锁结构在设计时必须显式回答「节点何时能被安全释放」「CAS 的期望值是否会被旧状态骗过」这两个问题。
