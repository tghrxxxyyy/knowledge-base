# 原子操作与内存屏障

> 对应 Bryant & O'Hallaron《CSAPP》第 12 章并发与 Love《Linux Kernel Development》第 9 章。

## 一、背景与挑战
多核下 `counter++` 并非原子：读-改-写之间可被其他核插入，导致丢失更新。需要 CPU 提供的原子指令（LOCK 前缀 / LL-SC）以及内存屏障来约束编译与 CPU 重排，保证并发正确性。

## 二、核心原理
`atomic_add` 用 `LOCK XADD` 在总线上锁住缓存行完成读改写；LL-SC（ARM）用"加载链接+条件存储"重试。内存屏障（`mb()`/`smp_mb()`）禁止编译器与 CPU 重排特定访存，避免发布未初始化数据等坑。

## 三、形式化与数学基础
原子 RMW 满足：
$$\forall i,\; op_i\; 全序,\; 无中间态可见$$
顺序一致性要求：`smp_mb()` 在两边访存间建 happened-before。Decker 标志（无屏障）失效因写可重排：
$$init\; then\; flag=1 \not\Rightarrow other\; sees\; init$$

## 四、代码实现
```c
// 原子自增（x86 LOCK XADD）
static inline void atomic_inc(atomic_t *v) {
    asm volatile("lock xaddl %0, %1"
        : "+r"(one), "+m"(v->counter) :: "memory");
}
// 发布数据：写数据后写标志，二者间加写屏障
data = 42; smp_wmb(); ready = 1;
```

## 五、与其他技术对比
原子指令 vs 锁：原子无阻塞适合单变量；锁适合临界区。acquire/release 比全屏障更轻且语义足够。相较 RCU，屏障用于单一发布点。

## 六、常见误区
误以为单条 C 语句原子：`i++` 是三条指令。误以为 volatile 保证原子/有序：仅禁编译器缓存。误以为加锁就无需屏障：锁内已有，但锁外发布仍需。

## 八、面试题
问：为什么 i++ 线程不安全？答：非原子 RMW，交错丢失更新。问：smp_mb 作用？

## 九、演进与趋势
C11 `_Atomic`/atomics 标准化；ARMv8 LSE 扩展提供原生原子；TSX 事务内存实验性。

## 十、小结
原子指令消除读改写竞态，内存屏障约束重排，是构建一切锁与无锁结构的基础砖块。
