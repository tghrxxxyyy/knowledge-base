# 条件变量与生产者消费者

> 对应 Bryant & O'Hallaron《CSAPP》第 12 章与 Kerrisk《The Linux Programming Interface》第 30 章。

## 一、背景与挑战
仅用互斥无法表达"条件不满足就等待"——忙等浪费 CPU。条件变量（condvar）配合互斥让线程在谓词不满足时睡眠、被唤醒后重新检查，是生产者消费者、线程池的核心。

## 二、核心原理
`pthread_cond_wait` 原子地释放互斥并睡眠；`pthread_cond_signal/broadcast` 唤醒。`while` 循环重查谓词防虚假唤醒与多消费者惊群。谓词保护靠同一互斥：改谓词持锁，等释放锁睡眠。

## 三、形式化与数学基础
不变量（管程）：
$$hold(mutex) \land pred \text{ 检查在锁内}$$
唤醒协议：
$$producer: lock;\ buf.push(x);\ signal;\ unlock$$
$$consumer: lock;\ while(empty) wait;\ x=buf.pop();\ unlock$$
`while` 而非 `if` 抵御虚假唤醒。

## 四、代码实现
```c
pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t c = PTHREAD_COND_INITIALIZER;
while (1) {
    pthread_mutex_lock(&m);
    while (queue_empty(&q)) pthread_cond_wait(&c, &m);  // 原子释锁并睡
    int x = queue_pop(&q);
    pthread_mutex_unlock(&m);
    consume(x);
}
```

## 五、与其他技术对比
条件变量需配互斥与谓词；信号量可替代但易漏唤醒。相较自旋等待，condvar 睡眠省 CPU。相较 RCU，condvar 用于通用同步而非读多写少。

## 六、常见误区
误以为 `if` 判断够：虚假唤醒致错。误以为 `signal` 前需持锁：应在锁内改谓词并 signal。误以为 condvar 自带状态：无，须自己维护谓词。

## 七、与开源书/权威来源对应
CSAPP 12.5 生产者消费者与 condvar；Kerrisk 第 30 章 pthread 条件变量；OSTEP 同步。

## 八、面试题
问：为什么 cond_wait 要用 while 而非 if？答：防虚假唤醒、多消费者抢空。问：signal 何时调用？

## 九、演进与趋势
`pthread_cond_clockwait` 支持超时时钟；futex 基元使 condvar 快路径更省；C++ `std::condition_variable` 标准封装。

## 十、小结
条件变量以"锁内谓词 + 等待/唤醒"实现高效阻塞同步，是生产者消费者模型的标准解法。
