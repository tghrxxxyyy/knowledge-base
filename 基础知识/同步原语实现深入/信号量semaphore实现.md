# 信号量semaphore实现

> 对应 Bryant & O'Hallaron《CSAPP》第 12 章与 Love《Linux Kernel Development》第 10 章。

## 一、背景与挑战
互斥只保护单一临界区，而需限制并发访问数量（如连接池上限、生产者消费者缓冲）或跨进程同步时，需信号量：一个计数值 + P/V 原子操作。

## 二、核心原理
`sem_wait`（P）：原子减计数，若 <0 则睡眠入等待队列；`sem_post`（V）：原子加计数，若有等待者则唤醒一个。计数初值即许可数，可用于限流（N 个资源）或事件通知（0/1 二值）。

## 三、形式化与数学基础
不变量：
$$0 \le permits \le N,\quad 临界并发数 \le N$$
P/V：
$$P: s = s-1;\ if\; s<0\; sleep$$
$$V: s = s+1;\ if\; s\le 0\; wake$$
正确加锁保证无丢失唤醒（V 在释放等待队列锁内）。

## 四、代码实现
```c
sem_t sem; sem_init(&sem, 0, 4);   // 最多 4 个并发
void worker(void) {
    sem_wait(&sem);                 // P
    use_resource();
    sem_post(&sem);                 // V
}
```

## 五、与其他技术对比
信号量可计数、可跨进程（命名 sem）；互斥锁不可计数、通常同进程。相较条件变量，信号量自带计数不需额外谓词。易误用（忘记 V 永久阻塞）。

## 六、常见误区
误以为信号量等于互斥锁：信号量可计数、可跨进程。误以为 P 一定睡：计数>0 时直接过。误以为 sem_post 在信号上下文安全：取决于实现。

## 七、与开源书/权威来源对应
CSAPP 12.3 生产者消费者与信号量；Kerrisk 第 53 章 POSIX 信号量；OSTEP 同步章。

## 八、面试题
问：用信号量如何实现互斥？答：初值 1 的二值信号量即互斥。问：P/V 为何必须原子？

## 九、演进与趋势
`sem_wait` 结合 futex 优化；读优先/写优先信号量用于读写场景；内核 `struct semaphore` 用于不可自旋处。

## 十、小结
信号量以计数 + 原子 P/V 提供限流与同步原语，是经典并发控制工具。
