# 逻辑时钟

> 对应 Lamport《Time, Clocks, and the Ordering of Events in a Distributed System》(1978)。

## 一、背景与挑战
物理时钟不可靠且难同步。Lamport 提出用“逻辑计数器”捕捉事件的因果关系(happens-before)，在不依赖真实时间的前提下为分布式事件提供偏序。

## 二、核心原理
每个进程维护计数器 C。规则：
1. 进程内事件前 C = C + 1。
2. 发送消息时带 C；接收方更新 C = max(本地 C, 消息 C) + 1。
由此定义 happens-before：a -> b 若 a 在 b 前发生于同进程，或 a 是发送、b 是对应的接收，或传递闭包。
Lamport 时钟给出了全序(再按进程 ID 打破平局)，但仅保持因果偏序，不反映实时。

## 三、形式化 / 数学基础
happens-before 关系 (->) 是严格的偏序(非自反、反对称、传递)。
性质：若 a -> b 则 C(a) < C(b)。
反例：并发事件 a ∥ b 满足 C(a) 与 C(b) 不可比(可任意大小)，故 C 仅保证因果方向，不能判定并发。

## 四、代码实现
```python
class LamportClock:
    def __init__(self): self.t = 0
    def tick(self): self.t += 1; return self.t
    def update(self, recv): self.t = max(self.t, recv) + 1; return self.t
# 发送: tick(); 携带 t; 接收: update(msg.t)
```

## 五、与其他技术对比
- 逻辑时钟只捕捉因果偏序，不能判定全局实时序。
- 向量时钟在其基础上可判定“并发”。
- 物理时钟反映真实时间但不可靠。

## 六、常见误区
- 误区：C(a) < C(b) 推出 a -> b。反方向不成立(并发也可能 C 小)。
- 误区：逻辑时钟能全序因果。它给出的是因果序+任意打破平局的全序，非实时。

## 九、演进与趋势
向量时钟、混合逻辑时钟(HLC)、TrueTime 都是对其思想的扩展。

## 十、小结
Lamport 逻辑时钟以纯计数器捕捉因果关系，奠定了分布式序研究的基础，但仅能表达因果偏序。
