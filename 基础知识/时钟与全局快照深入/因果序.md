# 因果序

> 对应 Birman, Schiper, Stephenson《Lightweight Causal and Atomic Group Multicast》(1991) 与 Lamport 因果序。

## 一、背景与挑战
在组播/广播中，有时不需要全局全序，只需保证“有因果关系的消息按序到达”，无因果的消息可乱序。因果序比全序更弱、可扩展性更好。

## 二、核心原理
因果序(Causal Order)交付：若发送 m1 后某进程才发送 m2，则所有交付 m2 的进程必须先交付 m1。
实现：用向量时钟标记每条消息的因果依赖；接收方缓存无法判定因果前序的消息，待依赖齐备再按因果序交付。
结合全序可得到“因果+全序广播”(强于单独因果序)。

## 三、形式化 / 数学基础
消息 m 带向量 V_m(发送者在其发送前的向量)。
因果前序：m1 -> m2 当且仅当 V_{m1} < V_{m2}。
交付规则：仅当所有满足 m' -> m 的消息已交付，才可交付 m。
并发消息(向量不可比)可任意顺序交付。

## 四、代码实现
```python
def can_deliver(msg_vec, delivered_max):
    # delivered_max: 本节点已交付的因果前沿(向量)
    return all(msg_vec[k] <= delivered_max[k] for k in range(len(msg_vec))) \
       and any(msg_vec[k] > delivered_max[k] for k in range(len(msg_vec)))
```

## 五、与其他技术对比
- 因果序 < 全序广播(全序更强)。
- 因果序 > 可靠广播(仅保证到达)。
- 常用于 CRDT 复制、无冲突协作编辑。

## 六、常见误区
- 误区：因果序需要全局定序。不需要，只需维护依赖。
- 误区：因果序能保证并发消息顺序。并发消息顺序无关紧要。

## 九、演进与趋势
因果序是 CRDT、本地优先(local-first)软件的理论基础，在协作场景中持续流行。

## 十、小结
因果序只约束有因果关系的消息顺序，比全序更轻量且更易扩展，是协作与最终一致系统的核心序模型。
