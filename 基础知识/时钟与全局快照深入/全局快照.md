# 全局快照

> 对应 Chandy & Lamport《Distributed Snapshots: Determining Global States of a Distributed System》(1985)。

## 一、背景与挑战
如何在不停机的异步系统中，获得一份“逻辑上同时”的全局状态(用于检查点、死锁检测、分布式 GC)？直接同时采样各进程会有时间差导致不一致。

## 二、核心原理
Chandy-Lamport 算法(基于 Marker)：
1. 发起者记录自身状态，向所有出边发 Marker 消息，并开始记录后续入边消息。
2. 进程收到首个 Marker(在某通道)时：记录自身状态，标记该通道“记录中”，向其他出边转发 Marker，记录该通道后续消息直到收齐所有入边 Marker。
3. 进程收齐所有入边 Marker 后，停止对应通道记录。
最终全局快照 = 各进程状态 + 各通道在记录期间缓存的消息(通道状态)。
关键性质：快照反映某个“cut”，其上的因果一致(无进程在快照后状态被误纳入前状态)。

## 三、形式化 / 数学基础
设全局状态 S = (s_1, s_2, ..., s_n, c_1, ..., c_m)，c_k 为通道缓冲。
一致切(consistent cut)：若事件 e 在快照中，则所有 f -> e 也在快照中。
算法保证所得切是一致切：Marker 的传播使“先发生”的因果被完整捕获。

## 四、代码实现
```python
class Snapshot:
    def __init__(self, pid, peers):
        self.state = None; self.channel_rec = {p: False for p in peers}
        self.buffer = {p: [] for p in peers}
        self.done = False
    def on_marker(self, from_p):
        if not self.started:

        self.channel_rec[from_p] = True
        if all(self.channel_rec.values()):
            self.done = True  # 快照完成
```

## 五、与其他技术对比
- 相比停系统再快照：CL 算法在线、无全局停顿。
- 相比应用层定时采样：保证因果一致，不会看到“未来影响过去”。

## 六、常见误区
- 误区：快照是某物理时刻的瞬间。其实是一个一致切，含通道中飞行消息。
- 误区：需要全局时钟。CL 算法完全不依赖时间同步。

## 九、演进与趋势
快照用于流式系统的状态备份(如 Apache Flink 的分布式快照/Chandy-Lamport 变体)。

## 十、小结
Chandy-Lamport 通过 Marker 消息在异步系统中构造一致切，在不停机下获得因果一致的全局快照。
