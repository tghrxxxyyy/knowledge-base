# 全序广播

> 对应 Kleppmann《DDIA》第 9 章 Total Order Broadcast 与 Lamport 逻辑时钟应用。

## 一、背景与挑战
许多系统要求所有节点以相同顺序收到并应用同一批消息(如状态机复制、数据库复制)。全序广播(原子广播)正是提供“可靠 + 全序”交付的抽象。

## 二、核心原理
全序广播满足：
- 可靠交付：消息最终被所有正常节点交付。
- 全序：所有节点以相同顺序交付消息。
- 因果交付(可选增强)：若发送 m1 后才发 m2，则所有节点先交付 m1 再 m2。
实现方式：常由共识算法(如 Raft/Paxos)充当“单一领导者决定顺序”的引擎；ZooKeeper 的 Zab 即全序广播协议。

## 三、形式化 / 数学基础
设消息序列 M，节点 i 的交付序列 D_i。全序广播要求 ∀i,j: D_i 与 D_j 是 M 的相同排列。
等价性：全序广播 与 共识(consensus) 在计算上等价 —— 能实现其一即可实现另一。
因果+全序广播 等价于 线性一致(在状态机复制语境)。

## 四、代码实现
```python
# 用单一 Leader 决定顺序(简化)
def broadcast(leader, msg, followers):
    seq = leader.assign_seq(msg)        # 全局单调递增序号
    for f in followers:
        f.deliver(seq, msg)             # 按序交付
    return seq
```

## 五、与其他技术对比
- 相比 FIFO/因果广播：全序广播更强，要求全局一致序。
- 与共识等价：Raft 的日志复制本质就是全序广播。

## 六、常见误区
- 误区：全序广播=先到先得。到达顺序因网络而变，必须 Leader/共识定序。
- 误区：全序广播等于线性一致。还需“读最新”语义才算线性一致。

## 九、演进与趋势
跨地域全序广播(Paxos/Raft 跨区域)是全球化系统的核心难题，催生 EPaxos 等无序提交优化。

## 十、小结
全序广播以“可靠 + 全局一致序”为状态机复制提供基础，且与共识计算等价，是强一致系统的中枢抽象。
