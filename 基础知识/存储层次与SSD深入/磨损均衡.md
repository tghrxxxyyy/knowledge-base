# 磨损均衡

> 对应 Remzi Arpaci-Dusseau《OSTEP》Flash/SSD 章节；Micron/SK hynix NAND 耐久性白皮书（公开定性）；OpenSSD / LightNVM 文档中的 FTL 磨损均衡设计。

## 一、背景与挑战

NAND 闪存的每个擦除块都有有限的编程/擦除（P/E）次数：SLC 约 $10^5$ 量级，TLC 常见 $10^3$，QLC 更低。超过阈值后氧化层退化，数据保持变差、错误率升高，块进入坏块。若写入总是集中在少数「热点」物理块（例如日志区、映射表区、频繁覆盖的目录项），这些块会先坏，整块 SSD 提前报废——即使其它大量冷块几乎没被擦过。

朴素做法是「哪里有空就往哪写」或「固定几个开放块轮换」：前者会让新写总是落在擦除次数低的块上，看似公平，但冷数据长期占着低磨损块却不参与轮换；后者会让日志型负载把固定区域写穿。工程上必须系统地摊匀所有块的擦除次数，这就是磨损均衡（Wear Leveling, WL）。

对 SSD 供应商与系统工程师，WL 直接决定标称 DWPD/TBW 是否兑现；对面试，常问「动态 vs 静态磨损均衡」「为什么冷数据也要搬」「WL 与 GC 的关系」，考察对寿命模型和 FTL 内部权衡的理解。

## 二、核心原理

**目标**：让所有块的擦除次数 $e_i$ 尽量接近，最大化「最早坏块」出现时间，从而最大化整盘寿命。

**动态磨损均衡（Dynamic WL）**：新写入分配时，优先选择擦除次数较低的空闲/可回收块，避免总是用同一批块。只处理「活跃数据」，对冷数据无力——冷数据占据的块擦除次数低，但永远不参与写轮换，热区却已磨穿。

**静态磨损均衡（Static WL）**：周期性或阈值触发地把冷数据从低擦除块搬到高擦除块（或反之），让原本「停着不动」的块也进入轮换。例如：把只读备份从 $e=100$ 的块搬到 $e=5000$ 的块，腾出低磨损块给热写。搬迁本身有写放大代价，因此要控制频率与阈值。

**实现要素**：
- 每块维护擦除计数器 $e_b$，随 GC/擦除递增，并持久化保存。
- 分配器在空闲块中按策略选：最小 $e_b$（贪心）、或轮转（round-robin）、或按 WL 目标加权。
- 冷热分离：识别冷块（长期不变）与热块（高频更新），分别路由到不同物理区（partitioning），再做区间内均衡与区间间迁移。
- 预留空间（OP）提供更多可轮换块，降低单位块擦除频率。
- 触发条件：周期性巡检、或当 $e_{max}-e_{min}$ 超过阈值时启动搬迁；搬迁限速以免影响前台 IO。

**工程细节**：磨损均衡与 GC 常共享块元数据与搬迁通道，因此要限流与优先级调度；搬迁本身也是写，需要计入 WAF。冷数据识别可用采样（读热度计数）、日志（文件系统冷热标记）或主机提示（TRIM/Discard 时机、ZNS 分区语义）。对于长期只读的归档数据，静态 WL 会周期性「翻动」，必要时结合数据保持刷新（scrub）一并做。

**不变量**：
1. 任何有效数据在搬迁过程中必须保持可读（通常先写到新位置再更新映射，最后擦旧块）。
2. 擦除计数单调不减，且持久化（掉电后可恢复），否则均衡状态丢失。
3. WL 不能与数据保持（retention）冲突：长期不动的数据也会因电荷泄漏出错，需定期刷新（read-scrub）。

## 三、形式化与数学基础

设块 $i$ 的擦除次数 $e_i$，均衡目标是极差受控：

$$\max_i e_i - \min_i e_i \le \epsilon$$

其中 $\epsilon$ 是允许的不均衡度。若完全均衡，每块擦除次数约等于总擦除次数除以块数：

$$\bar{e} = \frac{\sum_i e_i}{N}$$

**寿命估算**：设块擦除上限 $N_{pe}$，块数 $N$，块容量 $B_{block}$，主机写入速率 $W_{host}$（字节/天），写放大 $WA$，则：

$$Endurance_{days} \approx \frac{N \cdot B_{block} \cdot N_{pe}}{WA \cdot W_{host}}$$

若不均衡，有效寿命由 $\max_i e_i$ 决定：

$$Life \approx \frac{N_{pe}}{\max_i \dot{e}_i}$$

其中 $\dot{e}_i$ 是块 $i$ 的擦除速率。最坏情况（无 WL、热区占 1/10 块）寿命缩短近 10 倍。

**静态 WL 搬迁代价**：设冷区大小 $C$，触发阈值 $\Delta = e_{max}-e_{min} > \theta$，每次搬迁 $M$ 字节，则 WL 附加写放大 $WA_{WL} = M / H$（$H$ 为主机写）。需要 $\theta$ 平衡「搬迁频率」与「不均衡度」：阈值太小搬迁太勤，太大则不均衡恶化。

**概率模型（动态 WL 选块）**：若从 $F$ 个空闲块中均匀随机选，期望最大最小差约 $O(\sqrt{\ln F} \cdot \sigma)$；贪心最小 $e_b$ 可把极差压到近 1–2 次擦除，但需要维护优先队列（堆）。

## 四、代码实现

下面模拟「无 WL（总是用同一开放块区）」「动态 WL（选擦除最少的空闲块）」「静态 WL（冷数据搬迁）」三种策略，统计擦除计数极差与搬迁写放大。

```python
"""磨损均衡模拟：动态/静态 WL 对比"""


class WearLeveler:
    def __init__(self, n_blocks: int, strategy: str = "dynamic"):
        self.n = n_blocks
        self.strategy = strategy  # "none" | "dynamic" | "static"
        self.erase = [0] * n_blocks
        self.hot = set(range(n_blocks // 2))       # 热区：前半
        self.cold = set(range(n_blocks // 2, n_blocks))
        self.free = list(range(n_blocks))
        self.write_bytes = 0
        self.gc_bytes = 0
        self.wl_migrate_bytes = 0

    def _pick_block(self):
        if self.strategy in ("dynamic", "static"):
            # 选擦除次数最少的空闲块
            if self.free:
                return min(self.free, key=lambda b: self.erase[b])
            # 无空闲则擦一个热区块（模拟 GC）
            b = min(self.hot, key=lambda x: self.erase[x])
            self.erase[b] += 1
            self.gc_bytes += 4096 * 16  # 搬有效页
            return b
        # 无 WL：总用同一个块，模拟固定写穿热点
        return 0

    def write_hot(self, n_pages: int):
        for _ in range(n_pages):
            b = self._pick_block()
            if b in self.free:
                self.free.remove(b)
            self.write_bytes += 4096
            # 简化：每写一页即满块擦除归还，使擦除计数可见
            self.erase[b] += 1
            self.free.append(b)

    def static_migrate(self):
        """把冷数据从低磨损块搬到高磨损块，腾出低磨损块给热写"""
        if self.strategy != "static":
            return
        cold_low = min(self.cold, key=lambda x: self.erase[x])
        hot_high = max(self.hot, key=lambda x: self.erase[x])
        self.wl_migrate_bytes += 4096 * 8
        self.erase[cold_low] += 1
        self.erase[hot_high] += 1  # 目标块被写入
        self.cold.remove(cold_low)
        self.hot.remove(hot_high)
        self.cold.add(hot_high)
        self.hot.add(cold_low)

    def stats(self):
        return {
            "strategy": self.strategy,
            "erase_max": max(self.erase),
            "erase_min": min(self.erase),
            "spread": max(self.erase) - min(self.erase),
            "host_bytes": self.write_bytes,
            "wl_migrate": self.wl_migrate_bytes,
            "gc_bytes": self.gc_bytes,
        }


def run(strategy, n_blocks=16, pages=200):
    wl = WearLeveler(n_blocks, strategy)
    for _ in range(pages // 10):
        wl.write_hot(10)
        if strategy == "static":
            wl.static_migrate()
    print(wl.stats())


if __name__ == "__main__":
    run("none")
    run("dynamic")
    run("static")
```

预期结果：`none` 策略擦除极差大（热块被反复用）；`dynamic` 显著缩小极差；`static` 在动态基础上进一步均衡冷热，并产生一定的 `wl_migrate` 写放大。这展示了 WL 的核心取舍：用额外搬迁写换寿命均衡。

## 五、与其他技术对比

| 策略 | 均衡对象 | 附加写放大 | 实现复杂度 | 适用 |
|------|---------|-----------|-----------|------|
| 无 WL | — | 0 | 最低 | 仅演示 |
| 动态 WL | 活跃写块 | 低 | 低–中 | 一般消费/企业 |
| 静态 WL | 冷+热全部块 | 中（搬迁） | 高 | 企业级、高耐久 |
| 主机侧分区（ZNS） | 主机分区管理 | 可很低 | 接口约束 | LSM、对象存储 |

与 GC 协同：GC 选牺牲块时优先擦除「有效页少且擦除次数可控」的块；WL 选新块时看擦除计数。两者目标不同（GC 回收空间，WL 均衡寿命），常共用块元数据。与 TRIM 协同：提前失效无效页，降低 GC 与 WL 的无效工作。

## 六、常见误区

1. **「磨损均衡没有代价」**——错。静态 WL 要搬迁冷数据，增加写放大与延迟；阈值与频率必须权衡，否则「为了寿命更短命」。
2. **「动态 WL 就够了」**——错。冷数据占着低磨损块时，热区照样磨穿；需要静态 WL 或主机侧冷热分层。
3. **「擦除计数不用持久化」**——掉电后计数丢失会导致均衡判断错误，企业盘会把擦除计数存入 NAND 或 PLP 保护的 DRAM。
4. **「数据只读就不会影响寿命」**——只读数据本身不擦除，但占着块，迫使其它块被反复用；WL 必须搬冷数据。另外长期不刷新也会因电荷泄漏出错。
5. **「预留空间 OP 与寿命无关」**——OP 提供更多可轮换块与 GC 空间，直接降低单位块擦除速率，是 WL 的「缓冲区」。

## 八、面试题

**1. 磨损均衡的目的是什么？**
答：把擦除次数摊匀到所有块，避免热区先坏，最大化整盘寿命。理想状态是 $\max e_i - \min e_i$ 受控。

**2. 静态与动态磨损均衡有什么区别？**
答：动态只在写新数据时选擦除次数少的块，处理热数据；静态还会把冷数据从低磨损块搬到高磨损块，让冷块也参与轮换，更彻底但搬迁有写放大。

**3. 磨损均衡会引入写放大吗？**
答：会，尤其是静态 WL 搬迁冷数据时。需用阈值控制触发频率，把 $WA_{WL}$ 限制在可接受范围，与寿命收益权衡。

**4. 如何观察 SSD 磨损状态？**
答：读 NVMe SMART：`percentage_used`、`media_errors`、`data_units_written` 等；结合写入量与标称 TBW/DWPD 估算剩余寿命。厂商工具（如 nvme-cli smart-log）可查。

## 九、演进与趋势

3D TLC/QLC/PLC 使单块 P/E 下降，WL 与 GC 变得更重要：更强的 LDPC 纠错、读重试、以及「磨损+错误率」联合调度。ZNS/FDP 把冷热分区交给主机，天然降低不均衡，减少盘内搬迁。智能预测（学习式冷热识别）提前搬冷数据，降低被动 GC/WL。存储级内存（SCM）与 CXL 闪存分层中，WL 跨介质调度成为新课题。可观测性方面，NVMe 2.0 与云厂商监控 WAF/磨损分布，做主动替换预测（predictive failure）。开源 OpenSSD 与 SPDK 均提供了可运行的 WL 策略实验平台。

## 十、小结

磨损均衡用动态选块与静态冷数据搬迁，把 NAND 有限的 P/E 预算摊匀到所有块，避免热区提前失效。它与 GC、TRIM、OP 协同，代价是可控的搬迁写放大。理解 $e_i$ 极差、寿命公式与冷热分层，是 SSD 耐久性设计与运维预测的基础。
