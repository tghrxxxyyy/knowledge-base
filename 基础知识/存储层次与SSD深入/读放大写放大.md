# 读放大写放大

> 对应 Remzi Arpaci-Dusseau《OSTEP》Flash/SSD 章节；Yang, Ren 等《Distilling the Real Cost of Production Storage Systems》（FAST 相关研究）；SNIA SSD 性能与耐久度术语定义。

## 一、背景与挑战

SSD 内部为提升寿命与性能做了大量「额外工作」：写一个 4KB 逻辑块，物理上可能要写 16KB 页、再搬几个有效页做 GC、最后还擦写整块。这些额外读写会吃掉带宽、增加延迟、消耗闪存寿命。用三个放大系数量化：读放大（Read Amplification, RA）、写放大（Write Amplification, WA/WAF）、空间放大（Space Amplification, SA）。三者合称「三大放大」，是评价存储引擎与 SSD 内部效率的核心指标，数据库、云盘、对象存储在容量规划与 SLA 上必须逐项核对。

朴素观察只看主机侧 IOPS/带宽会误判：主机写 1MB/s，内部 NAND 可能在写 3–5MB/s，寿命与功耗都被悄悄吃掉；主机读 4KB，介质可能读出 16KB 甚至更多，带宽与读干扰（read disturb）一并上升。更隐蔽的是空间放大：逻辑有效数据 1TB，物理却占了 1.3TB，容量账面与实际可售容量对不上。若不做量化，就会出现「标称写寿命提前耗尽」「尾延迟抖动」「云盘成本算不准」等问题。

在工程与面试中，写放大是 SSD 专题最高频的题目：GC 放大、映射放大、TRIM 作用、顺序写为何 WA≈1、ZNS 为何降 WA。面试官通常追问 WAF 的定义与降 WA 的手段，而不是只要名词。回答时要能区分「主机写量」「NAND 编程量」「有效数据量」三个口径，并把 GC 有效页比例、页粒度、OP 与写入模式串起来。

## 二、核心原理

**写放大（WA / WAF）**：
$$WAF = \frac{\text{NAND 实际编程字节}}{\text{主机写入字节}}$$
来源：
1. **GC 放大**：异地更新后无效页散落，GC 从牺牲块搬有效页到新块，搬运即额外编程。这是最主要、最可控的来源，也是「顺序写 vs 随机写」差异的根源。
2. **映射表/元数据放大**：FTL 映射持久化、日志、条带化冗余（内部 RAID、ECC 校验页、奇偶校验）也占写，通常约占百分之几到十几。
3. **磨损均衡搬迁**：冷数据搬家产生的写。静态 WL 为了寿命必须做，但要控制触发阈值。
4. **页内局部写**：主机写 4KB，闪存页 16KB 时可能触发 RMW（读-改-写）或整页编程；小随机写难以凑满整页。
5. **写合并与缓冲刷回**：小写凑页依赖写缓冲合并度；随机写会半满页写入，后续 GC 时这半页常被判定为有效页继续搬运。

**读放大（RA）**：
$$RA = \frac{\text{NAND 读出字节}}{\text{主机请求字节}}$$
来源：小请求读整页（页粒度）、GC 过程为判断有效页而扫描读、ECC/LDPC 纠错重试与读干扰重读、预读（prefetch）超出请求范围、映射表查找导致的额外元数据读。随机 4KB 读若物理页 16KB，RA 可达 4×（实测因缓存与映射会低一些）。顺序大块读因预取与页对齐，RA 可接近 1。

**空间放大（SA）**：
$$SA = \frac{\text{物理占用}}{\text{逻辑有效数据}}$$
来源：预留空间（OP, over-provisioning）、内部日志、无效页未回收前占用、GC 期间牺牲块与新块的临时双副本。SA 换 WA 与写性能：OP 越大，GC 越轻松，WA 越低，但用户可用容量越小；这是存储产品定价与耐久设计的核心折中。

**TRIM/DISCARD**：文件系统释放块后通知 SSD，FTL 提前标无效页，降低 GC 有效页比例 $v$，从而降低 WA、加速 GC、改善稳态性能。没有 TRIM 时，已删除文件的页仍被当作有效页搬运，等于「白搬」。

**不变量**：$WAF \ge 1$（内部不能少于主机写）；顺序大块写时 $v$ 低、页合并好，$WAF \approx 1$；随机小写 $WAF$ 可 >5 甚至更高。RA 同理不小于 1（忽略压缩收益时）。SA 在开启压缩/去重后可能 <1，但那是逻辑层收益，物理层 SA 仍 $\ge 1$。

## 三、形式化与数学基础

**GC 引起的写放大推导**：设牺牲块大小 $B$（页数 $n_p$），其中有效页数 $n_v$，无效页数 $n_i = n_p - n_v$。一次 GC：读有效页 $n_v$、编程到新块 $n_v$、擦除 1 块。为了给主机提供 $n_i$ 个空闲页，GC 写入 $n_v$ 页，故每主机写一页的 GC 放大：

$$WA_{GC} = \frac{n_v + n_i}{n_i} = \frac{n_p}{n_i} = \frac{1}{1 - v}, \quad v = \frac{n_v}{n_p}$$

与 FTL 文档一致：$v$ 越高放大越大。总写放大还要加映射与内部日志因子 $1 + \alpha$：

$$WAF \approx \frac{1}{1-v} \cdot (1 + \alpha)$$

**读放大**：设主机请求大小 $r$，物理读粒度 $P$（页），则粗略：

$$RA \approx \frac{P}{r} \quad (r < P)$$

若请求被缓存命中率 $h_c$，实测 $RA \approx (1-h_c)\frac{P}{r} + h_c$。对 4KB 请求、16KB 页、$h_c=0.5$，$RA \approx 0.5\times 4 + 0.5 = 2.5$。

**寿命与 DWPD**：设盘容量 $C$，P/E 次数 $N_{pe}$，每天主机写 $D$ 倍容量（DWPD），则理论寿命（天）：

$$Life \approx \frac{C \cdot N_{pe}}{WAF \cdot D \cdot C} = \frac{N_{pe}}{WAF \cdot D}$$

WAF 从 1 升到 4，寿命降为 1/4。这是数据中心必须测 WAF 的原因。

**空间放大与 OP**：设预留比例 $p = OP/C_{raw}$，则稳态 GC 有效页比例上限约 $v \le \frac{1}{1+p}$（启发式），代入得 $WAF \le 1 + 1/p$。OP=25% 时 WAF 理论上限约 5，实际常 1.5–3。反过来，若要求 WAF $\le w$，需要 $p \ge \frac{1}{w-1}$：要把 WAF 压到 2 以下，OP 至少约 100%（不现实），所以工程上靠「降低 $v$」（TRIM、顺序写）比单纯堆 OP 更有效。

**综合权衡**：三大放大互相牵制。降 WA 往往要付 SA（更大 OP）或软件复杂度（ZNS 分区）；降 RA 要付缓存容量或预取带宽；降 SA 要接受更高 WA 与 GC 压力。存储引擎（LSM-tree vs B-tree）与介质放置策略（冷热分层）本质上是在这三者之间选一个工作点。

## 四、代码实现

下面计算 WAF/RA/SA，并基于有效页比例与 OP 推导寿命。

```python
"""读放大、写放大、空间放大与寿命估算"""


def write_amplification(host_bytes: int, nand_bytes: int) -> float:
    if host_bytes <= 0:
        raise ValueError("host_bytes must be > 0")
    return nand_bytes / host_bytes


def gc_waf(valid_ratio: float) -> float:
    """GC 稳态近似 WAF = 1/(1-v)"""
    if not 0 <= valid_ratio < 1:
        raise ValueError("valid_ratio in [0, 1)")
    return 1.0 / (1.0 - valid_ratio)


def read_amplification(host_read: int, nand_read: int) -> float:
    return nand_read / host_read


def space_amplification(physical_used: int, logical_valid: int) -> float:
    return physical_used / logical_valid


def life_days(capacity_tb: float, pe_cycles: int, waf: float, dwpd: float) -> float:
    """寿命（天）≈ PE次数 / (WAF * DWPD)"""
    if waf <= 0 or dwpd <= 0:
        raise ValueError("waf and dwpd must be > 0")
    return pe_cycles / (waf * dwpd)


def page_ra(request: int, page_size: int, hit_cache: float = 0.0) -> float:
    """读放大近似：未命中读整页，命中走缓存"""
    return (1 - hit_cache) * (page_size / request) + hit_cache


if __name__ == "__main__":
    # 场景1：顺序写 4GB，NAND 实际写 4.2GB（映射/日志）
    wa1 = write_amplification(4 * 1024**3, int(4.2 * 1024**3))
    print(f"顺序写 WAF≈{wa1:.3f}")   # ≈1.05

    # 场景2：随机小写，GC 有效页比例 v=0.5 -> WAF≈2
    wa2 = gc_waf(0.5)
    print(f"v=0.5 GC WAF≈{wa2:.3f}")

    # 场景3：4KB 读、16KB 页、缓存命中 50%
    ra = page_ra(4096, 16384, 0.5)
    print(f"4KB 随机读 RA≈{ra:.3f}")

    # 场景4：寿命：TLC PE=3000, DWPD=1
    for waf in (1.0, 2.0, 4.0):
        life = life_days(1.0, 3000, waf, 1.0)
        print(f"WAF={waf}: 寿命≈{life:.0f} 天 ({life/365:.2f} 年)")

    # 场景5：空间放大
    sa = space_amplification(1000, 750)
    print(f"SA≈{sa:.3f}（物理1000，逻辑750）")

    # 断言经典关系
    assert abs(gc_waf(0.0) - 1.0) < 1e-9
    assert abs(gc_waf(0.5) - 2.0) < 1e-9
    assert write_amplification(100, 250) == 2.5
```

输出示例：顺序写 WAF≈1.05；v=0.5 时 GC WAF=2；4KB 读 RA≈2.5；WAF=4 时寿命只有 WAF=1 的 1/4。这串数字说明「看主机写入量远远不够，必须测 WAF」。

## 五、与其他技术对比

| 维度 | 顺序大块写 | 随机小写 | ZNS 顺序分区 | 带 PLP 的企业盘 |
|------|-----------|---------|--------------|----------------|
| WAF | ≈1–1.2 | 2–8+ | ≈1 | 1.5–3（可预测） |
| RA | 低 | 中–高 | 低 | 中 |
| SA | 可控 | 无效页堆积 | 低 | OP 更大 |
| 尾延迟 | 稳定 | GC 抖动 | 更稳 | PLP+GC 调度稳 |
| 适用 | 日志、备份 | 数据库 OLTP | LSM-tree、对象 | 企业 SLA |

降 WA 的工程手段：TRIM、更大 OP、顺序写（日志结构）、写合并、压缩（可变相降低主机写）、按热冷分层、ZNS。降 RA：大请求、预取对齐、避免超小随机读、缓存热数据。

## 六、常见误区

1. **「写放大只是主机写多了」**——错。主机写量不变，GC/映射/均衡仍会造成 NAND 多写；WAF 是内部/主机之比，不是主机 IOPS。
2. **「WAF 等于 1 就最好」**——理论最优，但实际盘为了寿命、恢复与均衡会有 >1 的合理放大；关键是可预测、可控，而不是盲目压到 1。
3. **「读放大不重要，只看 IOPS」**——小随机读会被页粒度放大，带宽与 NAND 读寿命（read disturb）都受影响；读缓存命中率、页大小与请求大小要一起看。
4. **「OP 越大越好」**——OP 降 WA、稳尾延迟，但牺牲可售容量与成本；企业盘常 7%–28% OP，需按工作负载权衡。
5. **「TRIM 一定立刻降低 WA」**——TRIM 生效依赖 GC 调度时机；若主机不周期性 TRIM（如云盘稀疏分配），GC 仍会搬「以为有效」的数据。

## 八、面试题

**1. 什么是写放大？主要来源是什么？**
答：NAND 实际编程量与主机写入量之比 $WAF = NAND\_write / Host\_write \ge 1$。主要来自异地更新后的 GC 搬有效页、映射表持久化、磨损均衡搬迁、页内局部写触发 RMW/整页编程。

**2. 顺序写为什么 WAF 低？**
答：顺序写让块内页连续有效/失效成片，GC 时有效页比例低甚至块可直接擦；页合并好，几乎无半页写。随机小写使有效页散布，GC 放大 $1/(1-v)$ 恶化。

**3. 如何降低 WAF？**
答：TRIM、预留空间、顺序/日志结构写、写合并与压缩、冷热分层、使用 ZNS/Open-Channel 把 GC 交给主机、避免超小随机写。

**4. DWPD 与 WAF 什么关系？**
答：DWPD 是每天可写盘容量倍数的标称耐久；实际寿命 $Life \approx N_{pe}/(WAF \cdot DWPD)$。WAF 越高，同样 DWPD 下寿命越短，所以选盘要看厂商 WAF 条件与自身工作负载。

## 九、演进与趋势

ZNS、FDP（Flexible Data Placement，NVMe 2.0）让主机控制数据放置，WAF 可降到接近 1，已在数据库 LSM（RocksDB ZenFS）、对象存储、云盘后端落地。硬件侧，3D QLC/PLC 容量大但 PE 低，更依赖大 OP、强 ECC 与主机写整形；计算存储把压缩、去重下推，变相降低主机写与 WAF。可观测性上，NVMe SMART 暴露 WAF、介质磨损、错误计数；云厂商按 WAF 收费或调 DWPD，并用 WAF 预警发现异常写模式（如日志风暴、GC 抖动）。

存储引擎侧，LSM-tree 天然顺序写、WAF 友好，但读放大与空间放大（多版本、压实）需要压实调度与布隆过滤器来压制；B-tree 随机原地写 WAF 与写停顿更差，但读放大低。选型时要按工作负载读写比、更新热点分布来平衡三大放大。研究热点包括学习式 GC、按访问频率的分层放置、以及「持久内存+SSD」混合写路径的放大控制；对云上多租户，还要考虑邻居噪声导致的放大波动与隔离。

## 十、小结

读放大、写放大、空间放大刻画 SSD 内部额外 I/O 与容量代价，其中 WAF 直接决定寿命与稳态性能。GC 有效页比例 $v$、页粒度、OP、TRIM 与写入模式共同决定这些系数。工程上用顺序写、TRIM、ZNS 与合理 OP 把放大压到可预测范围，是存储系统调优的核心。
