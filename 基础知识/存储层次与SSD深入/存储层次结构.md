# 存储层次结构

> 对应 Bryant & O'Hallaron《Computer Systems: A Programmer's Perspective》第 6 章；Remzi Arpaci-Dusseau《Operating Systems: Three Easy Pieces》（OSTEP）虚拟化与持久化章节；Tanenbaum《Modern Operating Systems》。

## 一、背景与挑战

计算机存储介质在物理上呈现近乎单调的权衡：越快的越贵、越小、越耗电。寄存器与 SRAM 缓存以亚纳秒级延迟换取极小容量，DRAM 以几十纳秒换取 GB 级容量，SSD/HDD 以微秒到毫秒换取 TB 级容量，磁带/对象存储则以更慢换取近乎无限的归档容量。程序的工作集却往往「热的小、冷的大」——只有一小部分数据在任意时刻被频繁访问。

朴素做法同样有两个极端。一是「全部用最快介质」：成本与功耗不可行，现代服务器内存若全用 SRAM 价格会高几个数量级。二是「全部用最慢介质」：每次 load/store 都打到 SSD/磁盘，性能差 4～6 个数量级。层次结构（memory/storage hierarchy）的核心思想是：用局部性（temporal/spatial locality）把「小而热」的层放在快介质上，让绝大多数访问命中快层，从而以接近快介质的速度、接近慢介质的成本运行。

在工程与面试里，存储层次是贯穿硬件缓存、OS 页面缓存、数据库缓冲池、CDN/多级存储的统一抽象。AMAT（平均访存时间）、命中率、写策略、一致性与持久化边界，都是这里的必考内容。

## 二、核心原理

**金字塔结构**（自上而下，容量递增、延迟递增、每字节成本递减）：

寄存器 → L1 → L2 → L3（共享）→ 主存 DRAM → 本地 SSD/NVMe → 网络存储/HDD → 磁带/对象存储。

**局部性原理**：
- 时间局部性：刚访问的数据很可能再次访问（循环变量、热点索引）。
- 空间局部性：地址相邻的数据可能一起被访问（数组遍历、代码顺序执行）。

**每层作为上层的缓存**：硬件缓存对 CPU 透明，由控制器按行管理；主存作为虚拟内存页的「缓存」，页错误时从磁盘调入；SSD 上的文件系统页缓存（page cache）缓存热点文件块；数据库缓冲池缓存热点页。层次越高，命中延迟越低，缺失代价越大。

**命中/缺失机制**：访问先查最快层，命中则返回；缺失则向更慢层取一块（block/page）回填，可能替换旧块。替换策略（LRU、LFU、RRIP）、写策略（写直达/写回）、预取与非临时绕过决定实际效率。多级缓存之间还存在包含性（inclusive）、排他性（exclusive）与非包含（non-inclusive）关系，影响缺失时的行为与一致性流量。

**边界条件**：
- 多级缓存包含性（inclusive/exclusive/non-inclusive）影响替换与一致性。
- 持久性边界：DRAM 易失，SSD/NVM 持久；CPU 缓存与 store buffer 中的数据在掉电时可丢，需要刷回/屏障。
- 带宽平衡：上层每周期可发多次请求，下层可能成为瓶颈，出现排队与反压。
- 成本模型：每字节成本差常达 $10^3$–$10^5$ 倍，层次是经济必然。
- 一致性与共享：多核共享缓存层（如 L3）还要承担缓存一致性协议的职责。

**为什么正确/有效**：层次结构把「快而贵」与「慢而廉」解耦，只要局部性成立，访问大多命中快层，平均延迟接近快层、单位成本接近慢层。AMAT 公式是这一点的定量表达。若局部性不成立（纯随机大工作集），层次会退化为「每层都 miss」，性能跌回慢层，这时需要改算法、预取或扩容。

## 三、形式化与数学基础

两层模型下，设命中率 $h$、快层命中时间 $T_L$、慢层访问时间 $T_S$，缺失时需先查快层再访问慢层（或并行），则：

$$AMAT = h \cdot T_L + (1-h) \cdot (T_L + T_S) = T_L + (1-h) \cdot T_S$$

若慢层访问与快层查找重叠（并行），更接近 $h T_L + (1-h) T_S$。多级（L1/L2/L3/内存）时递归：

$$AMAT = T_{L1} + m_{L1}(T_{L2} + m_{L2}(T_{L3} + m_{L3} T_{mem}))$$

其中 $m_{Li}$ 为该级缺失率。例：$T_{L1}=1$ns，$m_{L1}=2\%$，$T_{L2}=5$ns，$m_{L2}=20\%$，$T_{mem}=80$ns，则：

$$AMAT \approx 1 + 0.02(5 + 0.2 \times 80) = 1 + 0.02 \times 21 = 1.42\text{ns}$$

可见即使缺失代价高，只要顶层命中率高，平均时间仍接近 L1。这就是层次结构的威力。

成本约束：设预算 $C$、容量-成本线性近似 $Cost = \sum_i p_i S_i$，在命中率约束下求最优容量分配，可归约为「把边际命中率提升最大的预算加到该层」。工程经验是：L1 追求延迟（小、快），L2/L3 追求命中率与共享，内存追求容量，SSD 追求每 GB 价格与寿命。

## 四、代码实现

下面用 Python 模拟三层存储（L1 缓存 → 主存 → 磁盘）的 AMAT，并对比顺序访问与随机大步长访问的命中率差异，验证局部性。

```python
"""三层存储层次 AMAT 与局部性演示"""
from collections import OrderedDict


class CacheLevel:
    def __init__(self, name, n_lines, hit_time_ns):
        self.name = name
        self.n_lines = n_lines
        self.hit_time = hit_time_ns
        self.lines = OrderedDict()
        self.hits = 0
        self.misses = 0

    def access(self, block_id):
        if block_id in self.lines:
            self.hits += 1
            self.lines.move_to_end(block_id)
            return True
        self.misses += 1
        if len(self.lines) >= self.n_lines:
            self.lines.popitem(last=False)
        self.lines[block_id] = True
        return False


class Hierarchy:
    def __init__(self):
        self.l1 = CacheLevel("L1", n_lines=16, hit_time_ns=1)
        self.l2 = CacheLevel("L2", n_lines=64, hit_time_ns=5)
        self.mem_time = 80.0
        self.disk_time = 10_000_000.0  # 10ms 磁盘
        self.l1_acc = self.l2_acc = self.mem_acc = self.disk_acc = 0

    def read(self, block_id, use_disk=False):
        self.l1_acc += 1
        if self.l1.access(block_id):
            return
        self.l2_acc += 1
        if self.l2.access(block_id):
            return
        self.mem_acc += 1
        if use_disk:
            self.disk_acc += 1

    def amat(self):
        n = self.l1_acc or 1
        m1 = self.l1.misses / n
        m2 = self.l2.misses / max(self.l2_acc, 1)
        t = (self.l1.hit_time
             + m1 * (self.l2.hit_time
                     + m2 * (self.mem_time
                             + (self.disk_acc / max(self.mem_acc, 1)) * self.disk_time)))
        return t


def run_pattern(name, blocks, use_disk=False):
    h = Hierarchy()
    for b in blocks:
        h.read(b, use_disk=use_disk)
    m1 = h.l1.misses / h.l1_acc
    print(f"{name}: L1命中率={1-m1:.2%} AMAT≈{h.amat():.2f}ns "
          f"L1miss={h.l1.misses} L2miss={h.l2.misses}")


if __name__ == "__main__":
    N = 256
    run_pattern("顺序遍历(空间局部性)", list(range(N)))
    # 随机大步长：每次跳 97 块，破坏空间局部性
    run_pattern("随机大步长", [(i * 97) % (N * 16) for i in range(N)])
```

预期结果：顺序遍历 L1 命中率高（块被连续复用），AMAT 接近 1ns；随机大步长缺失率显著上升，AMAT 靠近 L2/内存代价。这正是「层次 + 局部性」的定量体现。

## 五、与其他技术对比

| 层级 | 介质 | 延迟量级 | 容量 | 管理者 | 持久性 |
|------|------|----------|------|--------|--------|
| 寄存器 | SRAM | <1ns | KB | 编译器/ISA | 易失 |
| L1/L2/L3 | SRAM | 1–20ns | MB | 硬件 | 易失 |
| 主存 | DRAM | 50–100ns | GB–TB | OS/硬件 | 易失 |
| NVDIMM/持久内存 | DRAM+闪存 | ~100ns | GB | OS/应用 | 持久 |
| NVMe SSD | NAND | 10–100µs | TB | FTL/块层 | 持久 |
| HDD | 磁盘 | 1–10ms | TB–PB | 文件系统 | 持久 |
| 磁带/对象 | 磁带/云 | 秒–分钟 | PB+ | 归档系统 | 持久 |

取舍：层次越高追求延迟与确定性，越低追求容量、成本与持久性。缓存对程序透明；虚拟内存与页缓存由 OS 管理；数据库缓冲池在应用层再做一层。NVM 插入「内存-SSD」之间后，层次边界变模糊，需要新的数据放置（tiering）策略。

## 六、常见误区

1. **「层次结构完全透明、没有代价」**——错。缺失惩罚、替换抖动、写放大、TLB 未命中、预取失效都是真实代价；工作集超过快层时会 thrashing。
2. **「命中率越高越好，容量越大越好」**——大缓存查找更慢、功耗更高；层次设计是延迟、命中率、面积的折中，不是单纯堆容量。
3. **「写策略与层次无关」**——错。写直达/写回、写分配/非临时绕过决定写流量与崩溃一致性，是层次性能的核心维度。
4. **「DRAM 掉电不丢数据」**——错。DRAM 是易失的；持久化必须落到 SSD/NVM，并考虑缓存与 write buffer 中未提交的数据。
5. **「SSD 比 HDD 快就总该用 SSD」**——冷数据、顺序大容量归档用 HDD/磁带更经济；层次结构的价值正在「按热度分层」。

## 八、面试题

**1. 为什么计算机要把存储分层次？**
答：因为速度、容量、成本无法同时最优。局部性使热数据留在快层，从而以接近快介质的速度、慢介质的成本服务绝大多数访问。这是工程与经济共同作用的结果。

**2. AMAT 公式是什么？**
答：两层时 $AMAT = T_L + (1-h) T_S$（命中时间 + 缺失率 × 缺失代价）。多级则逐级加入缺失率与慢层时间。

**3. 顺序访问为什么比随机访问快？**
答：顺序访问利用空间局部性，预取与缓存行填充让一次缺失取回多字，后续访问命中；随机大步长破坏局部性，缺失率高，且可能引发写放大与排队。

**4. 如何判断系统瓶颈在层次的哪一层？**
答：用性能计数器（LLC 缺失率、内存带宽、TLB miss、IOPS/延迟）与工具（perf、iostat、pcm）。若 LLC miss 高且内存带宽饱和，瓶颈在内存层；若 I/O 延迟主导，看 page cache 命中与设备队列深度。

## 九、演进与趋势

持久内存（NVDIMM、CXL Type-3）把「持久」插入内存层，形成异构内存分层（DRAM + PMem + SSD），需要热数据放置、页迁移与字节可寻址持久化。CXL 内存池化让层次跨越机器；智能网卡/DPU 在近存储处做缓存与压缩。软件上，Linux 的多代 LRU、tiered memory（memfd/migrate_pages）、数据库的缓冲池扩展到 PMem、对象存储的冷热分层（S3 Glacier）都是层次思想的延伸。硬件缓存也在变化：大 L3/victim cache、chiplet 多级互连、3D 堆叠 SRAM。可计算存储（computational storage）与近数据处理进一步把「计算放层次底部」，降低数据搬运。

## 十、小结

存储层次用局部性把快而贵、慢而廉的介质组织成金字塔，使平均访问时间接近顶层、单位成本接近底层。AMAT 与命中率是基本度量，写策略、一致性、持久化边界决定正确性与性能。无论是 CPU 缓存、页缓存还是 SSD 内 FTL，层次结构都是系统设计的第一性原理。
