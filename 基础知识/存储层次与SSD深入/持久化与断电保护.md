# 持久化与断电保护

> 对应 OSTEP https://github.com/remzi-arpacidusse/ostep-code ；数据库持久化与 UPS/电容公开资料定性。

## 一、背景与挑战

写缓存提升性能但掉电会丢数据。需保证已确认写入真正落盘，且崩溃后可恢复。

## 二、核心原理

手段：写穿/刷盘(fsync)、掉电保护电容(PLP)让 SSD 把电容能量用于写完 DRAM 缓存、日志/预写日志(WAL)保证原子与有序、断电检测。fsync 强制刷到持久介质。

## 三、形式化 / 数学基础

WAL：提交前先写日志 $L$ 落盘，再改数据：

$$Commit \Rightarrow Persist(L) \land durable(L)$$

恢复时重放 $L$ 至一致点。持久性需 $fsync$ 返回后介质已写。

## 四、代码实现

```c
fd = open("db.log", O_WRONLY|O_SYNC);
write(fd, record, n);    // O_SYNC / fsync 强制落盘
fsync(fd);               // 确保返回后已持久
```

## 五、与其他技术对比

- fsync 安全但慢；带 PLP 的写缓存可既快又安全。
- WAL 以顺序写换随机写安全。

## 六、常见误区

- 误以为 write 返回即落盘：仅入页缓存。
- 忽视 SSD 自带 DRAM 缓存掉电丢。

## 八、面试题

- 为何要 fsync？答：把页缓存刷到持久介质，保崩溃可恢复。
- PLP 作用？答：掉电时电容供电写完缓存。

## 九、演进与趋势

原子写指令、无电容持久内存改变持久化范式。

## 十、小结

持久化靠刷盘与日志，断电保护依赖 fsync 与硬件 PLP，权衡性能与安全。
