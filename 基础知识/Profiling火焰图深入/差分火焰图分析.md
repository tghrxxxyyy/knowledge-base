# 差分火焰图分析

> 对应 Brendan Gregg 的 Differential Flame Graphs（brendangregg.com）与 github.com/brendangregg/FlameGraph 中的 difffolded.pl。

## 一、背景与挑战
性能优化与版本迭代都要回答同一个问题：这次改动让程序变快了还是变慢了，慢在哪里、快在哪里？

如果只把优化前后的两张火焰图并排看，人眼很难量化差异：两张图形状可能非常相似，只有个别子树有细微变化；而不同总样本数还会让绝对宽度不可比。肉眼比对既慢又不可靠。

差分火焰图（differential flame graph）正是为解决「对比」而生：它把两份采样按栈对齐，直接以颜色与宽度呈现增减，让回归与收益一目了然。它是性能门禁与优化验证的关键工具。

## 二、核心原理
差分火焰图的构造分两步。

- 对齐：以「折叠栈」的栈字符串为键，把 before 与 after 两份数据合并到同一棵树上，保证同名栈可比。
- 求差：对每个栈计算采样数之差，正值表示变热（耗时增加），负值表示变冷（耗时减少）。

呈现规则通常为：红色表示 after 比 before 更热（回归或新增开销），蓝色表示更冷（优化生效），灰色或近白表示基本无变化。

要保证可比性，两次采样必须在相同条件下进行：相同的采样频率、时长、目标进程与负载。否则差异中会混入采样噪声与条件偏差，结论不可信。difffolded.pl 负责合并与求差，flamegraph.pl 配合 --negate 与 --colors=redblue 渲染。

## 三、形式化与数学基础
设对同一个栈 $i$，优化前后采样计数分别为 $C_{before,i}$ 与 $C_{after,i}$，则绝对差为：

$$ \Delta_i = C_{after,i} - C_{before,i} $$

为消除总样本数不同的影响，应做归一化。以 before 总量为基准的相对变化为：

$$ \delta_i = \frac{\Delta_i}{\sum_j C_{before,j}} $$

若两次总样本数差异较大，更稳健的做法是各自归一化为占比再相减：

$$ \delta_i = \frac{C_{after,i}}{\sum_j C_{after,j}} - \frac{C_{before,i}}{\sum_j C_{before,j}} $$

显著路径由 $|\delta_i|$ 较大者给出，阈值需结合采样噪声设定。设单次采样计数近似服从泊松分布，则差值的标准差约为：

$$ \sigma(\Delta_i) \approx \sqrt{C_{before,i} + C_{after,i}} $$

只有当 $|\Delta_i|$ 明显大于该量级时，才可认为变化是真实的而非随机波动。这一判据是「避免把噪声当回归」的关键。

## 四、代码实现
生成差分火焰图的标准流程。

```bash
# 1) 优化前采集（相同频率与时长）
perf record -F 99 -g -p "$(pidof app)" -- sleep 30
perf script | ./stackcollapse-perf.pl > before.folded

# 2) 优化后采集（条件保持一致）
perf record -F 99 -g -p "$(pidof app)" -- sleep 30
perf script | ./stackcollapse-perf.pl > after.folded

# 3) 求差并渲染：红=变热，蓝=变冷
./difffolded.pl before.folded after.folded > diff.folded
./flamegraph.pl --negate --colors=redblue diff.folded > diff.svg
```

在脚本中做一次简化版的求差，便于理解其本质。

```python
# 读入两个折叠文件，按栈对齐求相对变化
def load(path):
    m = {}
    for line in open(path):
        line = line.strip()
        if not line:
            continue
        stack, cnt = line.rsplit(" ", 1)   # 栈与计数
        m[stack] = m.get(stack, 0) + int(cnt)
    return m

before, after = load("before.folded"), load("after.folded")
tb = sum(before.values()) or 1
ta = sum(after.values()) or 1
for stack in set(before) | set(after):
    delta = after.get(stack, 0) / ta - before.get(stack, 0) / tb
    if abs(delta) > 0.001:                 # 过滤噪声
        print(f"{delta:+.4f} {stack}")
```

注意两次采集的 `-F`、时长与进程必须一致，否则差异没有意义。

## 五、与其他技术对比

| 维度 | 差分火焰图 | 普通火焰图 | 微基准（microbench） |
| --- | --- | --- | --- |
| 展示内容 | 变化的量与位置 | 绝对占用 | 特定片段耗时 |
| 是否需两份数据 | 是，且需同条件 | 否 | 否 |
| 端到端影响 | 可观察 | 可观察 | 常不可观察 |
| 噪声敏感度 | 高，需阈值过滤 | 中 | 低 |
| 典型用途 | 回归检测、优化验证 | 找热点 | 算法级对比 |

差分图回答「变了多少」，普通图回答「本来是多少」，微基准回答「这个函数本身多快」；三者角色不同，不能互相替代。

## 六、常见误区
- 不同采样时长或频率直接差分：总样本数不同，绝对差值毫无意义。
- 栈聚合键不一致：一份含地址、一份已符号化，导致同名栈无法对齐。
- 忽略噪声：把小于 $\sqrt{C_1 + C_2}$ 量级的差异当作真实回归。
- 只看向上的红、不看向下的蓝：优化可能把开销转移到别处，需同时关注新增热点。

## 九、演进与趋势
- 连续差分：每次发布自动采集并生成差分图，形成性能回归门禁。
- CI 集成：把差分结果作为流水线质量门槛，超标则阻断合并。
- 持续剖析平台的「按时间对比」视图，使差分成为日常而非一次性动作。

## 十、小结
差分火焰图把优化与回归的影响量化呈现：对同一批栈求采样差、做归一化、按阈值过滤噪声，再用红蓝配色标出变热与变冷。它把「凭感觉比对两张图」升级为「可度量的差异检测」，是性能回归检测与优化验证的有效手段。前提是两次采样条件严格一致。
