# 状态压缩与网格铺砖

> 对应 L. L. Luby & A. P. 铺砖问题的经典轮廓线 DP 表述、李煜东《算法竞赛进阶指南》网格 DP 章节，以及 AtCoder/Codeforces 诸多 "domino tiling" 题解传统。

## 一、背景与挑战

网格铺砖是状压 DP 最能发挥的场景之一：给定 $n \times m$ 的棋盘（通常 $n,m$ 一个小、一个可达 $10^3$ 以上），用 $1 \times 2$ 的骨牌不重叠地覆盖整个棋盘，求方案数或最优价值。若 $n=m=10$，直接回溯搜索的状态空间大到不可行；而棋盘又天然带"局部相邻"结构，使得我们只关心**当前轮廓线**上哪些格子已被覆盖——这就把二维铺砖压成了一维的位掩码。

朴素做法为什么不行？回溯/DFS 逐格放骨牌，最坏 $O(2^{nm})$；生成函数与匹配多项式只适合规则小棋盘，一旦加上"某些格子是障碍""骨牌带权"就失效。更关键的是，铺砖的局部性意味着：决定当前格子怎么放时，只需要知道轮廓线上"已伸出的骨牌尾巴"，不需要整张棋盘的完整信息——若不把这条信息压成 `mask`，就既无法合并子问题，也无法设计 DP。

在面试与竞赛里，"网格铺砖/轮廓线 DP"是区分"会背 TSP"与"真懂状态压缩"的分水岭。工程上，它对应版面排布、地砖铺设方案、FPGA 布线中的可布性估算、DNA 芯片探针排布等；本质都是"带局部约束的二维匹配计数/优化"。

## 二、核心原理

**逐格递推与轮廓线。** 设棋盘按行优先顺序编号为 $(0,0), (0,1), \dots$。处理到某个格子时，已经决策完"轮廓线左上方"的所有格子，未决策的是右下方。**轮廓线**就是这两部分的分界线，长度为 $m+1$，跨越列边界。每个边界位置记录"是否有一块已放置骨牌的尾巴伸进当前行/下一格"。

**状态编码。** 用一个 $m$ 位掩码 `profile` 表示当前行从左到右 $m$ 个位置的"占用情况"：第 $j$ 位为 1，表示轮廓线在该列的上方（或左侧）有一块骨牌的尾巴伸出来，覆盖了当前格。处理到格子 $(i, j)$ 时，`profile` 的第 $j$ 位决定了当前格是否已被占据。

**转移（以 $1\times 2$ 骨牌为例）。** 处理格子 $(i,j)$ 时：

1. 若 `profile` 的第 $j$ 位为 1：当前格已被之前的骨牌覆盖，直接跳到 $(i, j+1)$，并把 `profile` 的第 $j$ 位清 0（尾巴已消化）。
2. 若为 0：当前格必须由新骨牌覆盖，有两种选择：
   - **横放**：覆盖 $(i,j)$ 与 $(i,j+1)$，则 `profile` 的第 $j+1$ 位置 1（尾巴伸向右），再递推。
   - **竖放**：覆盖 $(i,j)$ 与 $(i+1,j)$，则 `profile` 的第 $j$ 位置 1（尾巴伸向下），再递推。

换行时，`profile` 的最右位必须为 0（没有越界尾巴），且整个 `profile` 作为下一行的初始占用状态左移/循环使用——这就是"轮廓线滚动"。

**为什么正确。** 不变量：`profile` 恰好记录了"已放置骨牌中，尚未与第二个格子配对的那些尾巴的位置"。每一步决策要么消化一个尾巴，要么产生一个新尾巴，要么把新格子配对完毕。骨牌互不重叠且最终无尾巴，当且仅当覆盖合法。递推覆盖了所有合法铺法的决策序列，故计数正确。

**边界条件。** 最后一行只能横放或消化，不能向下伸出尾巴（否则越界）；最后一列不能横放。$n$ 与 $m$ 中把小的那个当作"状态位数"（$2^{\min(n,m)}$），大的那个用来逐行/逐列递推。

**障碍格变体。** 若某些格子不可放，则当前格若被轮廓尾巴覆盖且该格是障碍，此状态非法；若当前格是障碍且未被覆盖，则只能"跳过"。

## 三、形式化与数学基础

**状态空间。** 设 $w = \min(n, m)$，则 profile 是 $w$ 位整数，状态数 $2^w$。若 DP 递推按"格点"进行，总状态数 $O(nm \cdot 2^w)$，每个状态常数或 $O(1)$ 种转移，故

$$
T = O(nm \cdot 2^{w}), \quad S = O(2^{w}).
$$

对 $n=3, m=1000$，$2^3=8$，轻松通过；对 $n=m=15$，$2^{15}\approx 3\times 10^4$，$nm=225$，仍可接受；对 $n=m=20$，$2^{20}$ 与 $400$ 相乘达 $4\times 10^8$，吃紧。

**方案数递推式。** 设 $f[i][j][mask]$ 为处理到 $(i,j)$、轮廓线状态为 $mask$ 的方案数，则按上述四类转移写成

$$
f[i][j+1][mask'] \mathrel{+}= f[i][j][mask],
$$

并把 $j=m$ 的状态在换行时与 $f[i+1][0][mask]$ 合并（清掉最右位/检查合法性）。最终答案是 $f[n-1][m-1][0]$（无尾巴残留）。

**与匹配计数的联系。** $n\times m$ 棋盘的 $1\times 2$ 骨牌铺法数等于该网格图完美匹配数。对 $2\times n$ 棋盘，它退化为斐波那契数 $F_{n+1}$；这是检验代码的经典用例。轮廓线 DP 是求完美匹配的"转移矩阵/DP"通用版，比永久积和（pfaffian）更易处理障碍与变体。

**复杂度对比。** 回溯剪枝常数再好也是指数 $2^{\Omega(nm)}$；轮廓线 DP 把指数压缩到 $2^{\min(n,m)}$，是"维数规约"的教科书案例。

**空间滚动。** 因为 $f$ 只依赖"上一列/上一行"，可以只保留两个数组滚动，空间降为 $O(2^w)$。

## 四、代码实现

完整可运行的轮廓线 DP：求 $n\times m$ 棋盘 $1\times 2$ 骨牌铺法数，并支持障碍。

```python
# 轮廓线 DP：网格 1x2 骨牌铺法数
# 处理顺序：按行优先，逐格推进，profile 长度 = m，bit j 表示当前行第 j 列是否被
# "来自上方的竖放尾巴"占住。


def count_tilings(n, m, blocked=None):
    """
    n 行 m 列棋盘，用 1x2 骨牌铺满（不重叠、不越界）。
    blocked: 可选，False/0 表示可放，True/1 表示障碍；形状 n×m。
    返回方案数（整数）。
    """
    if n < m:
        # 交换行列，让状态位数最小
        return count_tilings(m, n, None if blocked is None
                             else [[blocked[i][j] for i in range(n)] for j in range(m)])
    blocked = blocked or [[False] * m for _ in range(n)]
    # 若面积为奇数，无法铺满
    if (n * m - sum(sum(row) for row in blocked)) % 2 == 1:
        return 0

    from collections import defaultdict
    # dp[mask]：当前格之前的轮廓线状态
    dp = defaultdict(int)
    dp[0] = 1

    for i in range(n):
        for j in range(m):
            ndp = defaultdict(int)
            for mask, ways in dp.items():
                cur = (mask >> j) & 1  # 当前格是否已被竖放尾巴占住
                if blocked[i][j]:
                    if cur:
                        continue          # 障碍格却被占，非法
                    # 障碍格必须空着
                    nm = mask & ~(1 << j)
                    ndp[nm] += ways
                    continue
                if cur:
                    # 当前格已被覆盖，消化尾巴
                    nm = mask & ~(1 << j)
                    ndp[nm] += ways
                    continue
                # 当前格空着，必须放骨牌
                # (1) 横放：占用 (i,j) 与 (i,j+1)
                if j + 1 < m and not blocked[i][j + 1] and not ((mask >> (j + 1)) & 1):
                    nm = mask | (1 << (j + 1))
                    ndp[nm] += ways
                # (2) 竖放：占用 (i,j) 与 (i+1,j)
                if i + 1 < n and not blocked[i + 1][j]:
                    nm = mask | (1 << j)
                    ndp[nm] += ways
            dp = ndp
    return dp[0]


if __name__ == '__main__':
    # 2×n 铺法数应为斐波那契 F_{n+1}
    assert count_tilings(2, 2) == 2
    assert count_tilings(2, 3) == 3
    assert count_tilings(2, 4) == 5
    assert count_tilings(2, 5) == 8
    # 3×4 全铺经典值 11
    assert count_tilings(3, 4) == 11
    print('tiling ok', count_tilings(3, 10))
```

实现说明：`cur` 位被清掉表示尾巴已被消化；横放时把右邻位置 1（对称地，竖放把下方位置 1，等价于"下一行初始 mask 的 j 位为 1"）。这是最简洁的"竖尾巴占当前行 bit"编码，等价于经典轮廓线，但状态转移更短。

## 五、与其他技术对比

| 方法 | 时间 | 空间 | 可处理障碍 | 可加权 | 备注 |
|------|------|------|------------|--------|------|
| 轮廓线状压 DP | $O(nm 2^{\min(n,m)})$ | $O(2^{\min})$ | 是 | 是 | 首选 |
| 逐行状压（兼容矩阵） | $O(m \cdot 3^{w})$ 级 | $O(2^w)$ | 是 | 是 | 列举两行兼容对 |
| 回溯/DFS + 剪枝 | 指数 | 小 | 是 | 是 | 仅超小棋盘 |
| Pfaffian / 永久积和 | $O((nm)^3)$ | 大 | 困难 | 困难 | 理论完美匹配数 |
| 递推/斐波那契 | $O(n)$ | $O(1)$ | 否 | 否 | 仅 $2\times n$ 特例 |

取舍：$\min(n,m)\le 15$ 且有障碍/权值，必用轮廓线；规则 $2\times n$ 直接斐波那契；$n=m=20$ 以上需折半或别的代数方法。

## 六、常见误区

1. **状态位的语义搞混。** 一会儿"1 表示已覆盖"，一会儿"1 表示有尾巴"，转移时 `|` 与 `& ~` 用反，方案数立刻错。必须在代码开头写清注释并全程贯彻。
2. **换行时忘记检查越界尾巴。** 例如最后一列仍允许横放，或行末没有把最右位清干净，导致非法状态流入下一行，答案偏大。
3. **忘记面积奇偶性预判。** 可铺满的必要条件是"可放格数为偶数"，不判断会把大量明显无解的算例跑成 0 以外的错值（或浪费时间）。
4. **交换行列后障碍矩阵没有同步转置。** 当 `n < m` 时为了压状态常把棋盘转置，若 `blocked` 没跟着转，障碍位置全错。
5. **用 `int` 溢出。** 计数类方案数增长极快（$3\times 10$ 的铺法数已上亿，$10\times 10$ 天文数字），Python 无此问题，但 C++ 需 `long long` 或高精度；面试要用 Python 时说明整数无限精度。

## 八、面试题

**1. $n\times m$ 棋盘 $1\times 2$ 骨牌铺法数，$n=3, m=1000$，怎么算？**
参考答案：把状态位数取 $\min(n,m)=3$，轮廓线 DP $O(nm \cdot 2^3)=O(3000)$，轻松通过。状态位表示竖放尾巴是否占住当前列。

**2. 请解释轮廓线状态每一位的含义，以及竖放/横放如何更新。**
参考答案：bit $j$ 表示"当前行第 $j$ 列是否有一块骨牌从上方（或前一列横放）伸下来的尾巴"。横放：把 $j+1$ 位置 1；竖放：把 $j$ 位置 1（等价于下一行被占）；若当前格已被占，清 $j$ 位并跳过。

**3. 若棋盘上有障碍格怎么办？**
参考答案：障碍格不能被骨牌覆盖。转移时若当前格是障碍但被尾巴占住则非法；若当前格是障碍且空，直接跳过。预判：剩余可放格数必须为偶数。

**4. 为什么不能直接对整张棋盘做 $2^{nm}$ 枚举？**
参考答案：$nm=40$ 时 $2^{40}\approx 10^{12}$，完全不可行。轮廓线 DP 利用局部性把状态压到 $2^{\min(n,m)}$，是这类问题的本质优化。

## 九、演进与趋势

铺砖状压之后的演进包括：**多米诺 / 三格骨牌（tromino）混合**，状态位需要记录更细的"尾巴长度/类型"；**带权铺砖**（每块骨牌有收益），转移改 max；**计数取模**（如 $\bmod 10^9+7$）防溢出；**连通性铺砖**（要求骨牌连成一块），要叠加括号表示法，升级为插头 DP；**大棋盘计数** 转向转移矩阵快速幂（把轮廓线 DP 写成矩阵自乘）或 Pfaffian。工程上，版面排布与芯片布线用同一思想做可行性与方案计数；游戏关卡生成也会用铺砖 DP 做连通性校验。面试趋势稳定在"3×n / 有障碍 / 解释状态位"三件套。

## 十、小结

网格铺砖把"二维覆盖"压成轮廓线上的一维位掩码，利用局部性在 $O(nm\cdot 2^{\min(n,m)})$ 内精确计数或优化；关键在于说清每一位的尾巴语义、处理换行边界与障碍合法性，它是状压 DP 从一维集合走向二维几何的标志性入口。
