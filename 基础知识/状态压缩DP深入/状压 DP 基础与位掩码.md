# 状压 DP 基础与位掩码

> 对应 Bellman 1962（动态规划最优化原理）、Cormen et al.《算法导论》第 15 章动态规划，以及 youngyangyang04/leetcode-master 状态压缩 DP 章节。

## 一、背景与挑战

在组合优化与棋盘类问题中，DP 的某一维状态常常不是"某个连续数值"，而是"某个集合的取舍"：哪些物品已经装进背包、哪些城市已经访问过、棋盘上哪些格子已经被覆盖。这类状态如果用 `set`、布尔数组甚至字符串去表示，不仅转移时哈希代价高昂，状态空间也无法被紧凑地索引成 DP 表的下标，滚动数组、记忆化搜索、状态去重都会变得极其笨拙。

朴素做法的失败是系统性的。以"从起点出发，访问完 n 个点"为例，若用 `list` 记录访问顺序，状态数是 $n!$，而实际上"走过哪些点"比"以什么顺序走过"信息更粗，前者只有 $2^n$ 种。不把集合压进下标，就既写不出正确的转移，也做不了任何剪枝。另一方面，当 $n$ 超过 20 之后，$2^n$ 本身也会爆炸，所以状压 DP 不是万能钥匙，它是一把**为小规模集合维度打造的精确钥匙**：$n \le 20$ 左右时，位掩码把状态压成一个机器字，转移只需几次位运算，快到可以放进最内层循环。

在工程与面试语境里，状压 DP 是"集合 DP"的标准写法。面试官考察的往往不是能否背出某道题，而是：能否识别出"状态其实是集合"、能否用位运算安全地增删查、能否估算出 $2^n$ 的空间与时间边界、能否在必要时配合子集枚举把 $O(2^n \cdot n)$ 的朴素转移降下来。它是后续 TSP、铺砖、连通性插头 DP 等一系列高级技巧的公共底座。

## 二、核心原理

核心思想一句话：**用一个 $n$ 位整数 `mask` 的二进制位表示 $n$ 个元素的归属**，通常约定第 $i$ 位（从 $0$ 开始）为 1 表示元素 $i$ "已选/已覆盖/已访问"。于是整个集合状态就是一个整数，DP 表可以写成一维 `dp[mask]`，或加上附加维度写成 `dp[mask][i]`（表示已选集合为 `mask`、且当前停在元素 $i$）。

围绕 `mask` 的基本操作只有四类，都必须写对：

- **判断**：`(mask >> i) & 1` 或 `mask & (1 << i)`，非 0 表示 $i$ 在集合中。
- **加入**：`mask | (1 << i)`，幂等，重复加同一元素不改变集合。
- **删除**：`mask & ~(1 << i)`。
- **枚举补集元素**：遍历 `i`，跳过已在 `mask` 中的，用 `nxt = mask | (1 << i)` 转移。

为什么这样写是正确的？关键在于位运算与集合运算的同构：`|` 对应并集，`&` 对应对称/交集，`~` 对应补集，整数相等当且仅当对应集合相等。因此 `dp[mask]` 可以被唯一索引，同集合的不同写法不会产生重复状态——这正是 `set` 哈希方案最脆弱的地方。

边界条件要单独设计。起点通常是"只含出发元素"的单点集合，例如 TSP 从城市 0 出发时初始化 `dp[1 << 0] = 0`，其余为 $+\infty$。目标状态是全集 `(1 << n) - 1`。转移时**必须**检查 $i \notin mask$，否则会把已经在集合里的元素再加一次，虽然集合值不变，但语义上是错误的转移（例如"再访问一次城市 i"），在计数类 DP 中会把方案数算爆。

不动量（invariant）可以概括为：`dp[mask]` 的定义域恰好覆盖"mask 恰好表示该集合"的所有方案最优值；每条转移把某个 $i \notin mask$ 并入集合，因此所有转移构成一张无环 DAG（集合大小单调递增），按 `mask` 从小到大枚举即可完成 DP，无需拓扑排序。

## 三、形式化与数学基础

**状态空间。** $n$ 个元素的子集共 $2^n$ 个，故 `dp` 数组长度为 $2^n$。若附加"当前所在元素"维度，则状态数为 $n \cdot 2^n$。

**单点转移。** 对最简单的"逐个加入元素"型 DP：

$$
dp[mask \cup \{i\}] = \min\bigl(dp[mask] + w(mask, i)\bigr), \quad i \notin mask
$$

其中 $w$ 是加入元素 $i$ 的代价。按 $mask = 0,1,\dots,2^n-1$ 升序枚举时，$mask \cup \{i\} > mask$ 恒成立，故不会出现"用未来更新过去"的顺序错误。

**时间复杂度。** 每个 $mask$ 尝试至多 $n$ 个 $i$，故朴素转移总代价

$$
T(n) = \sum_{mask=0}^{2^n-1} O(n) = O(n \cdot 2^n).
$$

空间为 $O(2^n)$（若只与前继有关，可用滚动或按 `popcount` 分层，但状压表通常直接开满）。

**与排列枚举的对比。** 若把访问序列本身当状态，状态数 $n!$；而"已访问集合 + 当前位置"只有 $n\cdot 2^n$ 个，这是因为同一集合的不同到达顺序在最优子结构下可以合并。比值

$$
\frac{n!}{n \cdot 2^n} = \frac{(n-1)!}{2^n}
$$

在 $n=10$ 时约为 $362880/1024 \approx 354$，$n=16$ 时已超过 $10^7$，这就是状压的价值所在。

**位运算正确性引理。** 对任意 $0 \le i < n$：

1. `mask | (1<<i)` 的第 $i$ 位为 1，其余位与 `mask` 相同；
2. `((mask | (1<<i)) >> i) & 1 == 1`；
3. 若 `(mask >> i) & 1 == 1`，则 `mask | (1<<i) == mask`。

因此"加入"操作保持集合单调不减，且在 $i \notin mask$ 时严格扩大集合（作为整数严格增大），保证 DAG 性质。

**适用规模。** 以 $O(n\cdot 2^n)$、常数约 $10^8$/秒估算，$n=20$ 约 $2\times 10^7$ 次转移可过，$n=22$ 起吃紧；若转移再套子集枚举 $O(3^n)$，则 $n$ 需压到 15 左右。这是面试中必须主动说出的边界判断。

## 四、代码实现

下面给出一份完整可运行的模板：用位掩码做"集合 + 当前位置"型 DP（即 TSP 的 Held-Karp 骨架），并附带位运算工具函数。对经典用例 $n=4$ 的完全图验证。

```python
# 状压 DP 模板：集合 + 当前位置（TSP 骨架）
INF = float('inf')


def popcount(x: int) -> int:
    return bin(x).count('1')


def held_karp(dist):
    """dist[i][j] 为完全图距离矩阵，返回从 0 出发、回到 0 的最短 TSP 路径长。"""
    n = len(dist)
    size = 1 << n
    dp = [[INF] * n for _ in range(size)]
    parent = [[-1] * n for _ in range(size)]
    dp[1 << 0][0] = 0  # 只访问过城市 0，当前停在 0

    for mask in range(size):
        if not (mask & 1):      # 必须包含起点 0
            continue
        for u in range(n):
            if not (mask >> u) & 1 or dp[mask][u] == INF:
                continue
            for v in range(n):
                if (mask >> v) & 1:   # v 已访问，跳过
                    continue
                nxt = mask | (1 << v)
                cand = dp[mask][u] + dist[u][v]
                if cand < dp[nxt][v]:
                    dp[nxt][v] = cand
                    parent[nxt][v] = u

    full = size - 1
    ans = INF
    last = -1
    for u in range(1, n):
        cand = dp[full][u] + dist[u][0]
        if cand < ans:
            ans = cand
            last = u

    # 回溯路径（可选）
    path = []
    mask, cur = full, last
    while cur != -1:
        path.append(cur)
        prev = parent[mask][cur]
        if prev == -1:
            break
        mask ^= (1 << cur)
        cur = prev
    path.reverse()          # [0, ..., last]
    route = path + [0]      # 闭合回路
    return ans, route


if __name__ == '__main__':
    # 4 城市经典用例：最短圈 0->1->3->2->0 = 1+2+3+4 = 10？ 用对称距离矩阵
    d = [
        [0, 10, 15, 20],
        [10, 0, 35, 25],
        [15, 35, 0, 30],
        [20, 25, 30, 0],
    ]
    ans, path = held_karp(d)
    print(ans, path)   # 期望 80, 路径 0-1-3-2-0 或 0-2-3-1-0
```

位运算工具函数（面试可直接默写）：

```python
def has(mask, i):   return (mask >> i) & 1
def add(mask, i):   return mask | (1 << i)
def remove(mask, i): return mask & ~(1 << i)
def lowbit(mask):   return mask & -mask
def submasks(mask):
    """枚举 mask 的所有子集（含 0 与自身），总复杂度 O(3^n) 摊还。"""
    sub = mask
    while True:
        yield sub
        if sub == 0:
            break
        sub = (sub - 1) & mask
```

代码要点：`parent` 用于回溯最优路径；`mask` 从小到大枚举保证转移无后效；循环中先跳过不含起点的 `mask`，可省掉约一半无用状态。

## 五、与其他技术对比

| 技术 | 状态表示 | 时间 | 适用场景 | 局限 |
|------|----------|------|----------|------|
| 状压 DP（位掩码） | 整数 `mask` | $O(n 2^n)$ | $n\le 20$ 的集合维度 | $n$ 稍大即爆炸 |
| 记忆化搜索 + `frozenset` | 哈希集合 | 常数大 | 教学/小数据 | 无法滚动、缓存不友好 |
| 分支限界 / 回溯 | 隐式树 | 最坏指数 | 可剪枝的问题 | 最坏劣于状压 |
| 插头/轮廓线 DP | 轮廓线编码 | $O(nm\cdot S)$ | 网格连通性、铺砖 | 状态设计复杂 |
| 整数线性规划/求解器 | 显式约束 | 依赖求解器 | 工程落地 | 竞赛不现实 |

取舍很清晰：集合维度小（$n\le 20$）且转移只依赖"集合本身"时，位掩码是首选；集合元素是网格上的"轮廓"而非抽象编号时，应升级为轮廓线 DP；需要精确解且可并行时，才考虑求解器。

## 六、常见误区

1. **忘记检查 $i \notin mask$ 就转移。** 后果：TSP 类问题会重复访问城市；计数 DP 的方案数会翻倍甚至溢出。正确写法是 `if (mask >> i) & 1: continue`。
2. **把 $n=25$ 还硬套 $O(n 2^n)$。** $2^{25}\approx 3\times 10^7$，再乘 $n$ 就到 $10^9$，必然超时。正确做法是压到 20 以内，或改用折半枚举（meet-in-the-middle）、启发式。
3. **初始化漏掉起点或边界。** 例如 `dp[0][0] = 0`（空集却停在 0）语义错误；应写 `dp[1<<0][0] = 0`。边界错会导致答案偏小或全是 INF。
4. **位序约定前后不一致。** 一会儿"第 i 位表示第 i 个物品"，一会儿改成 1-based，导致 `1 << i` 错位。团队代码中应在开头用常量固定 `BIT(i) = 1 << i` 并注释约定。
5. **用 `mask / 2`、`mask % 2` 去做位判断。** 这在语义上是取整除而不是取第 $i$ 位；当 $i>1$ 时完全错误。应始终用 `>>` 与 `&`。

## 八、面试题

**1. 为什么状压 DP 的状态数是 $2^n$ 而不是 $n!$？**
参考答案：状态定义的是"哪些元素已被选"，而不是"以什么顺序被选"。最优子结构保证同一集合的不同到达顺序可以合并为一个最优值，故子集数 $2^n$ 足够；$n!$ 是路径级枚举，浪费了可合并性。

**2. 位掩码加入元素为什么用 `|` 而不是 `+`？**
参考答案：`|` 是幂等的集合并，重复加入不改变集合；`+ (1<<i)` 在第 $i$ 位已是 1 时会进位，破坏其他位，导致状态非法。删除用 `& ~(1<<i)` 而不是 `- (1<<i)`，理由同理。

**3. 给定 $n\le 20$ 的 TSP 距离矩阵，说出复杂度并判断能否过 $n=22$。**
参考答案：Held-Karp 是 $O(n^2 2^n)$ 时间、$O(n 2^n)$ 空间。$n=20$ 时约 $4\times 10^8$ 次内层更新，C++ 卡常可过；Python 必须 $n\le 16$ 左右。$n=22$ 时 $2^{22}$ 行数组本身就要几百 MB，通常需要滚动数组 + 迭代内层剪枝，或改用分支限界。

**4. 如何枚举一个 mask 的所有子集？总复杂度是多少？**
参考答案：`sub = mask; while True: ...; sub = (sub - 1) & mask`，直到 `sub == 0` 后再处理 0 并退出。所有 mask 的子集枚举总次数为 $\sum_{mask} 2^{popcount(mask)} = 3^n$，这是 $(1+2)^n$ 的二项式展开，比 $2^n \cdot 2^n = 4^n$ 小得多。

## 九、演进与趋势

基础位掩码之后，常见演进路径有四条。其一是**子集枚举优化**：当转移是"从 mask 的某个子集 sub 合并而来"时，用 `sub = (sub-1) & mask` 枚举，把均摊做到 $O(3^n)$。其二是**高维状态拆分**：两个独立的小集合维度可分别状压再张量积，或用折半枚举把 $2^{40}$ 拆成两个 $2^{20}$。其三是**与轮廓线/插头 DP 结合**：网格问题中"轮廓线"本质是带连通性编码的位掩码，括号表示法把插头状态压进 $O(3^m)$ 或 $O(4^m)$ 的小集合。其四是**工程落地**：编译器寄存器分配、硬件测试向量生成、子集和/背包类配置问题中，位集合 + DP 的组合仍是基准解法；现代求解器对小规模集合问题也常内嵌 BDD/位并行加速。趋势上，状压本身没有"变大"的魔法，但与折半、Meet-in-the-middle、剪枝搜索的组合不断把可解规模往前推。

## 十、小结

状压 DP 用一个整数位掩码把"集合取舍"压进 DP 下标，使状态可索引、转移可用位运算、复杂度可控在 $O(n\cdot 2^n)$；它正确性建立在位运算与集合运算同构、转移构成 DAG 之上，适用前提是元素数 $n$ 大约不超过 20。掌握 `mask` 的增删查、边界初始化与规模估算，就拿到了 TSP、子集枚举、铺砖与插头 DP 全家桶的通行证。
