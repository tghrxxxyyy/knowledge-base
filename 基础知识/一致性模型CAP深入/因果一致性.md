# 因果一致性

> 对应 Lamport《Time, Clocks, and the Ordering of Events in a Distributed System》(1978) 与 causal consistency 相关工作(Aiyer et al. 2005)。

## 一、背景与挑战
线性一致代价高。很多场景只需保证“有因果关系的事件不乱序”(如评论必须在原帖之后)，无因果关系的并发写可自由收敛。因果一致性在强一致与最终一致间取得平衡。

## 二、核心原理
定义 happens-before 关系 (->)：
1. 同进程内程序序 ->。
2. 进程读 x 后写 y，则读 -> 写。
3. 传递闭包。
因果一致性要求：对任意 a -> b，所有进程必须看到 a 在 b 之前。并发(不可比)的写可乱序，最终收敛。

## 三、形式化 / 数学基础
- 向量时钟 V：V[i] 表示进程 i 已知事件数。
- 事件 e 因果先于 f 当且仅当 V_e < V_f（逐分量 <= 且至少一分量 <）。
- 收敛条件：副本最终对所有并发写应用相同的一组更新(交换律/合并函数需满足结合律、交换律，如 OR-Set、CRDT)。
CRDT 收敛性依赖：merge(a, merge(b,c)) = merge(merge(a,b), c) 且 merge(a,b)=merge(b,a)。

## 四、代码实现
```python
# 向量时钟因果比较
def happens_before(va, vb):
    le = all(va[i] <= vb[i] for i in range(len(va)))
    lt = any(va[i] < vb[i] for i in range(len(va)))
    return le and lt

# 因果一致读：维护本进程见过的最大向量时钟
def read_causal(store, ctx_vec):
    for item in store.items:
        if not happens_before(item.vec, ctx_vec):
            continue  # 跳过尚未因果可见的
```

## 五、与其他技术对比
- 弱于线性一致(不保证实时)，强于最终一致(保证因果序)。
- COPS、Bolt-on Causal Consistency 等系统可在最终一致存储上叠加因果层。

## 六、常见误区
- 误区：因果一致能防止所有冲突。并发写仍可能冲突，需冲突解决。
- 误区：向量时钟可完全排序。只能判定因果/并发，不能全序。

## 九、演进与趋势
CRDT(无冲突复制数据类型)成为因果/最终一致的事实标准，用于本地优先(local-first)软件。

## 十、小结
因果一致性只约束有因果关联的事件的顺序，允许并发自由收敛，是性能与正确性的务实折中。
