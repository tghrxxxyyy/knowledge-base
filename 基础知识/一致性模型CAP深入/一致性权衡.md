# 一致性权衡

> 对应 PACELC 模型(Abadi, 2010) 与 DDIA 第 9 章。

## 一、背景与挑战
CAP 把取舍描述为分区时的二选一，忽略了无分区时系统同样在延迟与一致间权衡。PACELC 更完整地刻画了真实系统的设计空间。

## 二、核心原理
PACELC：
- 若发生分区(P)：选 A 或 C。
- 否则(E, else)：选 L(低延迟) 或 C(强一致)。
因此 CP 系统在 E 时也可能选 L(如同步复制=高一致但高延迟)。真实设计是在 P/A/C/L 四维中按业务定位。

## 三、形式化 / 数学基础
一致性延迟代价可建模：写延迟 T_w = f(quorum, RTT)。
- 强一致需 W + R > N(多数派读)，W 越大延迟越高。
- 可调一致：一致性级别 k ∈ {ONE, LOCAL_QUORUM, QUORUM, ALL} 直接映射 W,R 与延迟/一致性强度。

## 四、代码实现
```python
# 可调一致性：根据级别选择读写副本数
def quorum(level, n):
    if level == "ONE":   return 1, 1
    if level == "QUORUM":return (n//2)+1, (n//2)+1
    if level == "ALL":   return n, n
# 强一致需 w + r > n
```

## 五、与其他技术对比
- 纯 CAP：只谈 P 下 C/A。
- PACELC：补充无分区下的 L/C 取舍，更贴近工程。

## 六、常见误区
- 误区：选了 CP 就一定低延迟。CP 在 E 时仍可因同步复制而慢。
- 误区：一致与可用是固定属性。实际可运行时动态调节。

## 九、演进与趋势
“一致性即服务”：同一系统暴露多种一致性级别，由每次请求按需选择。

## 十、小结
一致性权衡不是二选一，而是 P/A 与 L/C 的多维连续谱；PACELC 提供了更工程化的分析框架。
