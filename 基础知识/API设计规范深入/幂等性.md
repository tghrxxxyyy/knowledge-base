# 幂等性

> 对应 HTTP 规范 RFC 7231、REST 与支付系统设计实践。

## 一、背景与挑战
网络重试、客户端重复提交会让同一操作执行多次，造成重复扣款、重复下单等严重后果。

## 二、核心原理
幂等操作：执行一次与执行多次效果相同。GET/PUT/DELETE 语义幂等；POST 不幂等。通过幂等键（Idempotency-Key）使非幂等写可安全重试。

## 三、形式化 / 数学基础
$f$ 幂等当且仅当 $\forall x,\ f(f(x))=f(x)$。服务端记录 $key \to result$，收到相同 $key$ 时返回首次结果而非重复执行。

## 四、代码实现
```http
POST /payments
Idempotency-Key: 9f1c-4a2b
```
```python
if store.get(key): return store.get(key)   # 已处理，直接返回
result = do_pay(); store.put(key, result); return result
```

## 五、与其他技术对比
客户端去重只能防手抖；服务端幂等键才能抗网络重试与网关重发。与事务配合防止并发双写。

## 六、常见误区
误区：仅在客户端禁用按钮。误区：幂等键未设 TTL 导致存储无限增长。

## 七、与开源书 / 权威来源对应
RFC 7231 Section 4.2.2 (Idempotent Methods)；Stripe API "Idempotent Requests"；CS-Notes: https://github.com/CyC2018/CS-Notes

## 八、面试题

## 九、演进与趋势
网关层统一幂等中间件、结合分布式锁与去重表成为标准实践。

## 十、小结
用幂等键把非幂等写变为可重试安全操作。
