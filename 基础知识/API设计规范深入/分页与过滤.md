# 分页与过滤

> 对应 Google API Design Guide「Pagination」章节与 JSON:API 规范，结合 Keyset 分页实践。

## 一、背景与挑战

列表接口若返回全量数据，会拖垮服务、撑爆网络并放大客户端内存压力。客户端需要可控的翻页、稳定的排序与字段过滤。但最常见也最易错的「偏移分页（offset）」在数据频繁变动时会出现重复或漏读，深分页更是性能黑洞。选择合适的分页与过滤策略直接影响 API 的可扩展性与正确性。

从治理视角，分页与过滤还是「资源成本控制」手段：不限页的列表接口会被滥用于全量抓取，既压垮服务端又泄露数据规模。合理的默认分页上限（如 max 100）与稳定排序是 API 安全与公平的一部分。

## 二、核心原理

偏移分页（`offset/limit`）实现简单，但依赖「中间无插入删除」，高并发写入下会漂移。游标分页（cursor）基于有序键取「大于上一游标的前 N 条」，结果稳定且性能与偏移量无关。过滤用 `filter` 表达条件，排序用 `sort`，字段投影用 `fields` 减少带宽。生产环境长列表几乎都应首选游标/Keyset 分页。

从工程视角，游标应是「不透明（opaque）」的：服务端把排序键（甚至租户上下文）编码进 cursor 并返回给客户端，客户端只透传、不解析，避免暴露内部主键与越权遍历。

关键要点：

- 偏移分页依赖「中间无插入删除」，高并发写入下会漂移。
- 游标分页基于有序键取「大于上一游标的前 N 条」，结果稳定。
- 游标应是不透明的（opaque），由服务端编码排序键与租户上下文。
- 深分页用大 offset 会触发全表扫描，应改用 Keyset + 索引。
- 过滤/排序/投影分别由 filter/sort/fields 表达，减少带宽与越权。
- 默认分页上限（如 max 100）是资源成本控制与防爬的重要手段。

## 三、形式化与数学基础

偏移分页：第 $p$ 页取记录区间：

$$
[(p-1)\cdot s,\ p\cdot s)
$$

游标分页：以有序键 $k$ 取：

$$
\{r \mid k(r) > \text{cursor} \land \text{filter}(r)\}\ \text{limit}\ s
$$

深分页代价：offset 法需扫描并丢弃前 $O(\text{offset})$ 行；Keyset 法借助 $(k)$ 上的索引直接定位，复杂度 $O(s)$，与偏移无关。投影节省带宽：

$$
\text{bytes} \approx s \cdot \sum_{f\in\text{fields}} \text{size}(f)
$$

## 四、代码实现

```http
GET /orders?limit=20&cursor=eyJpZCI6MTIzfQ==   # 游标（base64 编码上一页末键）
GET /orders?offset=40&limit=20                  # 偏移（仅适合静态数据）
GET /orders?sort=-created_at&fields=id,status&filter=status:paid
```
```sql
-- Keyset 分页：用索引 (created_at, id) 直接定位
SELECT id, status FROM orders
WHERE (created_at, id) < (:last_ct, :last_id)
  AND status = 'paid'
ORDER BY created_at DESC, id DESC
LIMIT 20;
```

## 五、与其他技术对比

| 分页方式 | 稳定性 | 深分页性能 | 随机跳页 | 实现难度 |
|----------|--------|------------|----------|----------|
| Offset | 低（会漂移） | 差（全表扫描） | 易 | 低 |
| Cursor/Keyset | 高 | 优（索引定位） | 难 | 中 |
| Seek (token) | 高 | 优 | 难 | 中 |
| 游标+加密 | 高 | 优 | 难 | 高 |

## 六、常见误区

误区一：深分页用大 offset（如 offset=1000000）——触发全表扫描与超时。

误区二：未对排序键建索引——任何分页都退化为全扫，Keyset 也失效。

误区三：游标暴露内部主键——应加密或签名避免信息泄漏与越权遍历。

误区四：把过滤逻辑放客户端——增加带宽与越权风险，应在服务端执行。

误区五：排序键不唯一——同值多行会跨页重复或漏读，需追加唯一键（如 id）作 tie-breaker。

## 七、与开源书·权威来源对应

Google Cloud API Design Guide「Pagination」推荐 cursor/next_page_token；JSON:API Specification 定义 pagination 链接；use-the-index-luke 详述 Keyset 分页与索引；CS-Notes 汇总分页陷阱；电商平台常用 encrypted cursor 防泄漏。GraphQL 用 Relay Cursor Connection 统一游标语义，把分页抽象为 edges/pageInfo。

## 九、演进与趋势

GraphQL 用 Relay Cursor Connection 规范统一游标语义；gRPC/Connect 用 token 分页；服务端常返回 `next_cursor` 与 `has_more` 让客户端无感翻页；物化视图支撑稳定快照分页。无游标（stateless cursor）向「有状态快照游标」演进，以应对强一致分页需求。

## 十、小结

优先游标/Keyset 分页配合索引排序与字段投影，避免深分页性能黑洞；用加密游标兼顾稳定与安全，并以默认上限控制资源成本，是列表接口的最佳实践。
