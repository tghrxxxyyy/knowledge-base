# 输入校验

> 对应安全编码中的输入校验（Input Validation）与白名单原则。

## 一、背景与挑战
多数注入/越权源于未校验或错误校验不可信输入。校验应在信任边界进行，采用白名单与强类型，而非黑名单。

## 二、核心原理
- 白名单优于黑名单：只允许已知合法值/格式。
- 校验位置：服务端为必须，客户端仅体验层（不可信）。
- 类型与范围：数字范围、字符串长度、枚举值。
- 规范化（canonicalization）后再校验，防编码绕过（如 `%2e%2e`）。

## 三、形式化 / 数学基础
- 合法集 $V$ 为有限或可描述集合；校验谓词 $valid(x)= (x\in V)$。
- 黑名单 $B$ 满足 $valid_{black}(x)= (x\notin B)$，但 $B$ 难穷举 → 不安全。
- 正则锚定：必须 `^...$` 全串匹配，否则部分匹配绕过。
- 规范化：先 $x' = canonical(x)$ 再校验，消除等价编码。

## 四、代码实现
```python
import re
def validate_username(u: str) -> bool:
    # 白名单：仅字母数字下划线，3-20 长度，全串锚定
    return bool(re.fullmatch(r"[A-Za-z0-9_]{3,20}", u))
def validate_age(a: str) -> bool:
    try:
        n = int(a); return 0 <= n <= 150
    except ValueError:
        return False
```

## 五、与其他技术对比
- 白名单 vs 黑名单：白名单完备安全；黑名单常被绕过。
- 服务端 vs 客户端校验：客户端可绕过，服务端必做。
- 校验 vs 转义：校验拒绝非法，转义处理合法但特殊字符。

## 六、常见误区
- 正则未锚定 `^$` 致部分匹配绕过。
- 仅前端校验（后端未校验）。
- 校验前未规范化被编码绕过。
