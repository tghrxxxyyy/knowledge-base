# 日志脱敏

> 对应日志中的敏感信息脱敏（Data Masking in Logs）。

## 一、背景与挑战
日志常无意记录密码、token、身份证、手机号等 PII/凭据，既合规风险又成攻击目标。需在写入前对敏感字段脱敏。

## 二、核心原理
- 识别敏感字段：凭据、PII、支付信息、内部拓扑。
- 脱敏策略：掩码（mask）、哈希（加盐）、截断、完全不记。
- 集中处理：在日志库/序列化层统一脱敏，避免散落遗漏。
- 合规：遵循最小记录原则与数据保护法规（如 GDPR/PIPL）。

## 三、形式化 / 数学基础
- 脱敏函数 $M: V \to V'$，要求不可逆且保持可用（如保留后四位）。
- 掩码：$M(v)=prefix \mathbin\| \text{'*'}^k$，隐藏中间。
- 加盐哈希：$M(v)=H(salt\mathbin\|v)$，可关联但不可还原。
- 记录必要性：仅当 $need(v)=true$ 才记，否则丢弃。

## 四、代码实现
```python
import re, hashlib
def mask_phone(p: str) -> str:
    return re.sub(r"(\d{3})\d{4}(\d{4})", r"\1****\2", p)
def hash_token(t: str) -> str:
    return hashlib.sha256(("salt:"+t).encode()).hexdigest()[:16]
```

## 五、与其他技术对比
- 脱敏 vs 加密：脱敏不可逆、面向展示；加密可还原需密钥。
- 掩码 vs 哈希：掩码保留部分可读；哈希用于关联不可还原。
- 不记 vs 脱敏：最敏感信息应完全不记。

## 六、常见误区
- 仅脱敏密码却忘记 token/身份证/银行卡。
- 脱敏规则在多处重复易遗漏（应集中）。
- 把脱敏后的哈希当唯一 ID 泄露关联风险。

## 十、小结
