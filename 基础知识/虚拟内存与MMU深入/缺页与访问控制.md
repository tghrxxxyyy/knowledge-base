# 缺页与访问控制

> 对应 CSAPP 中文笔记 https://github.com/Hansimov/csapp 第9章；OSTEP https://github.com/remzi-arpacidusse/ostep-code ；Tanenbaum《Modern Operating Systems》；Intel SDM 异常向量 14（Page Fault）。

## 一、背景与挑战

页表把映射做成「按需」：进程声明了很大地址空间，却不必一开始就占用物理内存。真正访问时，若页表项不存在或权限不符，CPU 触发缺页异常（page fault），陷入内核由软件决定下一步——分配物理页、从磁盘换入、复制共享页，还是判定非法访问。这一机制把按需调页、保护、共享、写时复制（COW）统一在一个入口，是虚拟内存灵活性的来源。

但缺页也是正确性与性能的雷区。把「合法的懒分配缺页」与「非法的段错误」混为一谈会写出脆弱代码；不理解 COW 就解释不了 `fork` 为何几乎瞬间完成、子进程写一页后为何内存翻倍；忽略权限位（R/W/X/U/S/NX）会引入可写可执行的注入漏洞。面试与系统编程中，能否正确分类缺页、说明 PTE 权限语义、解释 mmap 私有/共享映射差异，是基本功。

朴素做法要么在启动时把所有页装入（浪费且慢），要么用一个「是否有效」位做粗粒度保护（无法表达只读、写时复制、只执行）。现代方案在 PTE 中编码细粒度权限与状态，由缺页处理程序根据错误码（CR2 与错误码位）精确分流。

这套机制还支撑着大量「看不见」的系统能力：动态链接库的按需映射、`fork` 的写时复制、垃圾回收器的读屏障、数据库的 mmap 缓冲池、甚至安全沙箱的 W^X 页保护。理解缺页，就理解了操作系统如何把有限物理内存伪装成无限、可保护、可共享的地址空间。面试里让你画缺页处理流程、分类 minor/major/非法、解释 COW，本质上是在问你是否真正读懂了虚存的「异常即控制流」。

## 二、核心原理

**触发条件**（任一即触发 #PF）：

1. 存在位 `P=0`：页不在内存（未映射、已换出、或尚未分配）。
2. 权限不符：只读页被写、用户态访问内核页（U/S）、数据段尝试执行（NX）、写了只执行页。
3. 其他：页表配置错误、保护键（PKU）违反、指令取指保护等。

**缺页分类（软件视角）**：

- **minor（软缺页）**：页已在物理内存，只是当前进程页表未映射。典型：匿名页首次触碰（zero page）、COW 复制、共享库已被他人载入。代价仅是建表，微秒级。
- **major（硬缺页）**：需从后备存储（磁盘/交换分区/文件）读入，毫秒级甚至更慢，涉及 I/O 调度与等待队列。
- **非法（invalid）**：无任何合法理由，内核发送 `SIGSEGV`/`SIGBUS` 终止或让进程自行处理。

**写时复制（COW）**：`fork` 时父子页表都指向同一物理页，权限设为只读并标记 COW。任一方写入触发缺页，内核复制该页、更新写方 PTE 为可写；若只剩一方引用，可直接提升权限。不变量：任意时刻写者独占可写页，读者可共享只读页。这把「复制全部地址空间」的 $O(M)$ 成本摊到实际写入的页面上。

**访问控制位**：PTE 含 R/W、U/S、NX（执行禁用）、A（访问）、D（脏）、G（全局）。内核在每次 walk 时检查，硬件保证无法绕过（除非内核自身配置错误）。`mprotect` 修改权限后必须同步刷新 TLB。

**边界条件**：缺页处理必须可重入、可并发（多核同页同时缺页要加锁）；处理程序中不能再触发同类缺页（需使用预留内存）；信号处理函数中访问未映射页同样会嵌套缺页。文件映射还涉及与 page cache 的一致性。

**权限位的组合语义**：`mprotect` 可以把页设为只读、只执行、可读写，但「可写可执行」（W+X）是安全大忌，现代 OS 与硬件（NX/XD）默认禁止或强烈不建议。栈通常是 RW 不可执行，堆也是；JIT 编译器要执行时得显式切 W→X，避免同时可写可执行。PKU/PKEY 则进一步允许在不改 PTE 权限位的前提下快速切换访问域，适合影子栈与隔离运行时。

## 三、形式化与数学基础

缺页处理决策可形式化为：

$$
trap(vaddr) \to reason \to
\begin{cases}
COW: & page' = copy(page),\ remap(RW) \\
swap/file: & load(page),\ remap(P) \\
zero-fill: & alloc(),\ remap(RW) \\
invalid: & signal(SIGSEGV)
\end{cases}
$$

权限检查为布尔谓词：

$$allow = P \land (write \Rightarrow R/W) \land (user \Rightarrow U/S) \land (exec \Rightarrow \lnot NX \lor \text{exec-allowed})$$

任一子句失败即触发异常并保留错误码。

COW 的期望代价：设 $F$ 为 fork 后实际写入页比例，地址空间页数 $N$，则复制工作量 $O(F\cdot N)$，相对立即复制的 $O(N)$ 节省 $(1-F)$。对「fork 后 exec」的 shell 模型 $F \approx 0$，接近零成本。

major 缺页延迟模型：$T_{major} = T_{queue} + T_{io} + T_{map}$，其中 $T_{io}$ 主导；因此减少 working set、用大页、避免 swap 风暴是关键。

安全视角：W^X（不可写且可执行）、ASLR、DEP 依赖权限位组合；若把栈设为可执行或可写可执行，会显著扩大攻击面。

## 四、代码实现

用 Python 模拟 PTE 权限与三类缺页分流，并演示 COW 引用计数：

```python
PROT_R, PROT_W, PROT_X = 1, 2, 4


class PTE:
    def __init__(self, pfn=None, prot=0, cow=False):
        self.pfn = pfn
        self.prot = prot
        self.cow = cow
        self.present = pfn is not None

    def allow(self, need: int) -> bool:
        return self.present and (self.prot & need) == need


class VM:
    def __init__(self):
        self.pt = {}
        self.page_ref = {}   # pfn -> refcount
        self.next_pfn = 0x100

    def alloc(self, vpn, prot=PROT_R | PROT_W, cow=False):
        pfn = self.next_pfn
        self.next_pfn += 1
        self.page_ref[pfn] = 1
        self.pt[vpn] = PTE(pfn, prot, cow)

    def access(self, vpn, need: int, is_write=False):
        pte = self.pt.get(vpn)
        if pte is None or not pte.present:
            # 首次访问：懒分配 zero page（minor）
            self.alloc(vpn, prot=PROT_R | PROT_W)
            return f"minor fault: zero-fill vpn={vpn:#x}"
        if is_write and pte.cow:
            # COW：引用>1 则复制，否则提升权限
            old = pte.pfn
            if self.page_ref[old] > 1:
                self.alloc(vpn, prot=PROT_R | PROT_W)
                self.page_ref[old] -= 1
                return f"cow copy: vpn={vpn:#x} old_pfn={old:#x}"
            pte.cow = False
            pte.prot |= PROT_W
            return f"cow promote: vpn={vpn:#x}"
        if not pte.allow(need):
            return f"invalid access -> SIGSEGV vpn={vpn:#x} need={need}"
        return f"ok: pfn={pte.pfn:#x}"

    def fork_copy(self, child: "VM"):
        for vpn, pte in self.pt.items():
            pte.cow = True
            pte.prot &= ~PROT_W
            self.page_ref[pte.pfn] += 1
            child.pt[vpn] = PTE(pte.pfn, pte.prot, cow=True)


# 经典用例
if __name__ == "__main__":
    parent, child = VM(), VM()
    parent.alloc(0x4000, prot=PROT_R | PROT_W)
    parent.fork_copy(child)
    print(parent.access(0x4000, PROT_W, is_write=True))   # cow copy
    print(child.access(0x4000, PROT_R, is_write=False))  # ok，仍是共享页
    print(parent.access(0x5000, PROT_R, is_write=False)) # minor zero-fill
    parent.pt[0x4000].prot = PROT_R                       # 变只读
    print(parent.access(0x4000, PROT_W, is_write=True))  # SIGSEGV
```

预期输出依次为 `cow copy`、`ok`、`minor fault`、`invalid access -> SIGSEGV`。这覆盖了 COW、懒分配与权限拒绝三条主路径。

## 五、与其他技术对比

| 机制 | 作用 | 成本 |
|------|------|------|
| minor 缺页 | 建映射/COW | 低，无 I/O |
| major 缺页 | 换入页 | 高，磁盘 I/O |
| COW | 延迟复制，共享 fork | 写时复制抖动 |
| mprotect | 动态改权限 | 需 TLB shootdown |
| userfaultfd | 用户态处理缺页 | 复杂度高 |
| mmap MAP_SHARED | 多进程共享写回 | 一致性协议 |

与「显式 malloc 复制」对比：COW 把复制成本与实际写入对齐；与「页锁/写屏障」对比，COW 由硬件权限触发，无需改写每条 store。与「直接 SIGSEGV 处理」对比：内核缺页路径是受控的、带锁的、可分派到 swap/file/zero 逻辑；用户态信号处理只是最后一层兜底。

性能上，minor 缺页只需改 PTE，微秒级；major 缺页要等磁盘，毫秒级甚至更久，是延迟毛刺的主要来源。监控 `pgfault`/`pgmajfault`、换入换出速率，以及 mmap 文件的 major 比例，是数据库与缓存服务排障的第一步。

## 六、常见误区

1. **「缺页一定是性能灾难」**——minor 缺页很便宜；只有 major I/O 与 swap 风暴才致命。监控指标应区分 minor/major。
2. **「mmap 写入就立即写磁盘」**——`MAP_PRIVATE` 是 COW 私有副本，不会写回；`MAP_SHARED` 才与 page cache 一致并可能刷盘。
3. **「fork 会完整复制进程内存」**——实现上是 COW，页表复制但物理页共享；真正复制发生在写入时。
4. **「段错误一定是数组越界」**——也可能是权限（写只读数据、执行栈）、未映射地址、栈溢出；需看 CR2 与错误码。
5. **「改了权限立即全局生效」**——需刷新 TLB（shootdown），否则其他核心仍可能用旧权限继续访问。

## 八、面试题

1. **minor、major、invalid 三类缺页有何区别？**  
   参考答案：minor 页已在内存只需建映射/COW，快；major 需从磁盘/交换读入，慢；invalid 无合法解释，触发 SIGSEGV。

2. **COW 如何让 fork 变快？写入时做什么？**  
   参考答案：父子共享只读物理页并增加引用；写触发缺页后复制该页（或引用为 1 时直接提升可写），把全量复制摊到实际写页。

3. **PTE 权限位有哪些？W^X 是什么意思？**  
   参考答案：R/W、U/S、NX、A、D 等。W^X 表示页不可同时可写可执行，防止注入代码，依赖 NX 与权限分离。

4. **为什么 mprotect 后程序行为可能延迟生效或被多核看到不一致？**  
   参考答案：存在 TLB 缓存旧映射，必须 shootdown；内核保证一致性，但用户态若自己改页表（特殊场景）必须手动失效。

## 九、演进与趋势

演进包括：`userfaultfd` 把缺页交给用户态（用于热迁移、内存去重、垃圾回收）；KSM 内核合并相同内容匿名页；内存保护键（PKU/PKEY）实现无 TLB shootdown 的快速权限切换；`madvise` 系列（`DONTNEED`、`WILLNEED`、`HUGEPAGE`）精细控制缺页与大页；实时系统用 `mlock` 避免 major 缺页；虚拟化中缺页与 EPT violation 组合成嵌套故障处理。安全上，CFI、影子栈（shadow stack）扩展了「访问控制」的语义。趋势是让缺页从「异常」变成可编程、可观测的系统调优点，而不是只能忍受的黑盒。

## 十、小结

缺页与访问控制把按需分配、保护、共享和 COW 统一在一次异常入口：PTE 权限决定能否访问，错误码与页状态决定分流路径。理解 minor/major/invalid、COW 引用计数与 TLB 一致性，才能写出高效而安全的系统程序，并在性能分析中正确区分「懒分配的免费缺页」与「真正昂贵的换页」。
