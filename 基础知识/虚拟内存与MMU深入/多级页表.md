# 多级页表

> 对应 CSAPP 中文笔记 https://github.com/Hansimov/csapp 第9章；OSTEP https://github.com/remzi-arpacidusse/ostep-code ；Intel SDM Vol. 3《Paging》。

## 一、背景与挑战

平坦（flat）单级页表在宽地址空间面前会立刻爆炸。以 x86-64 用户可见的 48 位虚拟地址、4KB 页为例，虚拟页号有 36 位，页表需要 $2^{36}$ 个表项；每项 8 字节，仅一张页表就占 $2^{39}$ 字节（512 GiB），而且其中绝大多数项为空——进程实际映射的代码、数据、栈、堆加起来往往只有几十到几百 MB。为每个进程都维护这样一张巨大而稀疏的表，内存与管理成本都不可接受。

更糟的是，若采用「按需分配非空表项」的哈希表方案，硬件查找会变慢且复杂，失去用简单索引完成转换的硬件友好性。问题的本质是：如何在保持「硬件一次索引得 PFN」这种结构化访问方式的同时，只为地址空间中真正被使用的部分付出存储？

多级页表（multi-level page table）给出的答案是「分层索引 + 按需分配上层」：把 VPN 再拆成若干段，每段索引一级表；只有当上一级表项表明下一级存在时，才为下一级分配页框。这样，稀疏地址空间只占用实际触及的那几条路径，空间复杂度从 $O(2^{n-p})$ 降到与映射页数近似线性相关。它是现代虚存的骨架结构，也是面试中考察「用时间换空间」思想的经典载体。

## 二、核心原理

x86-64 经典 4 级页表把 48 位虚拟地址拆成：

$$vaddr = [\,\underbrace{PML4}_{9}\;|\;\underbrace{PDPT}_{9}\;|\;\underbrace{PD}_{9}\;|\;\underbrace{PT}_{9}\;|\;\underbrace{offset}_{12}\,]$$

转换过程是一条指针链：

1. 用 `CR3`（物理根地址）定位 PML4 表，取 `bits[47:39]` 索引得到 PML4E；
2. 若 PML4E 的存在位 `P=0`，触发缺页异常，由内核决定是否建立映射；否则 `PML4E.PFN` 指向 PDPT；
3. 用 `bits[38:30]` 索引 PDPT 得 PDPTE；同理得 PD；
4. 用 `bits[29:21]` 索引 PD 得 PDE，用 `bits[20:12]` 索引 PT 得 PTE；
5. PTE 的 PFN 与 12 位 offset 拼接成物理地址。

**不变量**：每一级表项都必须 `P=1` 才能继续向下；任一级 `P=0` 就停止并触发缺页。权限位（R/W、U/S、NX）在路径上是「与」关系——上层只读、下层可写，最终仍只读。这保证了保护不会被下层表绕过。

**大页融合**：若在 PDPT 级遇到 `PS=1`（page size），该表项直接给出 1GB 页框；PD 级 `PS=1` 给出 2MB 页。此时提前终止遍历，剩余低位全部是页内偏移。这是多级结构向大页扩展的自然方式。

**边界条件**：每级表本身占一页（4KB / 512 项）。创建映射时若中间表不存在，内核必须分配并清零新表，再把 PFN 填入上级——这是 `mmap` 真正「建立」映射时的隐藏成本。删除映射时还要逐级回收空表，避免泄漏。

## 三、形式化与数学基础

设虚拟地址 $n=48$ 位，页偏移 $p=12$，级数 $L=4$，每级索引位数 $s=9$，满足

$$n = L\cdot s + p = 4\times 9 + 12 = 48$$

令 $i_k$ 为第 $k$ 级索引（$k=1..L$，从最高级开始），则

$$i_k = \left\lfloor \frac{vaddr}{2^{p + s\cdot(L-k)}} \right\rfloor \bmod 2^{s}$$

物理地址合成：

$$PA = \big(PFN_{L} \ll p\big) + (vaddr \bmod 2^{p})$$

其中 $PFN_L$ 是最终叶子表项中的物理页框号。

空间代价：设进程实际映射 $m$ 个页，且虚拟地址分布随机。叶子页表至少需要 $\lceil m/512\rceil$ 个页框；上层表数量取决于映射的「稀疏程度」，最坏接近 $m$ 条独立路径时，上层表也达到 $O(m)$ 级别，但常数远小于单级全表 $2^{36}$。典型进程映射数十 MB 时，总页表内存只有几十到几百 KB，对比单级的 512 GiB 节省了 5–6 个数量级。

访问代价：无 TLB 时一次转换最多 $L+1$ 次访存（$L$ 次读表 + 1 次读数据）；四次访存对性能是灾难，故必须依赖 TLB 把「转换」变成「查缓存」。多级页表用空间换来的额外时间，被 TLB 这一层缓存抵消——这是层次化设计的教科书案例。

## 四、代码实现

下面完整模拟 x86-64 四级页表的地址拆分、表构建与逐级查找：

```python
PAGE_SHIFT = 12
LEVEL_BITS = 9
LEVELS = 4  # PML4, PDPT, PD, PT
PAGE_SIZE = 1 << PAGE_SHIFT
ENTRIES = 1 << LEVEL_BITS


def split_indices(vaddr: int):
    """返回 [pml4, pdpt, pd, pt, offset]。"""
    offset = vaddr & (PAGE_SIZE - 1)
    vpn = vaddr >> PAGE_SHIFT
    idx = []
    for k in range(LEVELS - 1, -1, -1):
        idx.append((vpn >> (LEVEL_BITS * k)) & (ENTRIES - 1))
    return idx + [offset]


class PageTable:
    """多级页表：table 是 512 槽数组，槽为 None / 叶子 dict / 下级 PageTable。"""

    def __init__(self, level=0):
        self.level = level
        self.entries = [None] * ENTRIES

    def map_page(self, vaddr: int, pfn: int, flags="RW"):
        *idx, _ = split_indices(vaddr)
        node = self
        for i in idx[:-1]:
            if not isinstance(node.entries[i], PageTable):
                node.entries[i] = PageTable(node.level + 1)
            node = node.entries[i]
        node.entries[idx[-1]] = {"pfn": pfn, "flags": flags, "P": 1}

    def walk(self, vaddr: int):
        """逐级索引；返回 (pfn, flags, 访问次数)。缺失抛 KeyError。"""
        *idx, offset = split_indices(vaddr)
        node = self
        walks = 0
        for i in idx:
            walks += 1
            e = node.entries[i]
            if e is None:
                raise KeyError(f"page fault at level {node.level}, idx={i}")
            if isinstance(e, dict):          # 大页提前终止（此处简化为叶子）
                return e["pfn"], e["flags"], walks, offset
            node = e
        raise KeyError("not a leaf")


# 经典用例
if __name__ == "__main__":
    pt = PageTable()
    # 映射两个相距甚远的页，体现稀疏性
    va1, va2 = 0x0000_7F00_0000_0000, 0x0000_0040_0000_0000
    pt.map_page(va1, pfn=0xABC00, flags="RX")
    pt.map_page(va2, pfn=0xDEF00, flags="RW")

    for va in (va1 + 0x123, va2 + 0x7FF):
        pfn, flags, walks, off = pt.walk(va)
        pa = (pfn << PAGE_SHIFT) | off
        print(f"VA=0x{va:x} -> PA=0x{pa:x} flags={flags} walks={walks}")

    print("split 0x7f0000000123 =", [hex(x) for x in split_indices(va1 + 0x123)])
    try:
        pt.walk(0x0000_1234_0000_0000)
    except KeyError as e:
        print("caught:", e)
```

预期输出包含两条转换（walks 最多 4）、索引拆分结果，以及一次缺页捕获。代码用字典树显式展示「上级不存在则不分配下级」的按需特性。

## 五、与其他技术对比

| 方案 | 空间 | 转换延迟 | 硬件复杂度 | 适用 |
|------|------|----------|------------|------|
| 单级页表 | $O(2^{n-p})$，巨大 | 1 次查表 | 最简单 | 32 位小地址、嵌入式 |
| 多级页表 | 与映射规模相关，小 | 最多 L+1 次 | 中等（需多次索引） | 现代通用 OS |
| 哈希/倒排页表 | 与页框数成正比 | 1 次哈希，冲突变慢 | 较高 | 大物理内存、64 位稀有系统 |
| 段页式 | 段表+多级页表 | 多一级 | 高 | 教学、历史 x86 |

多级页表的取舍非常清晰：多付出几次「仅在 TLB 缺失时」才发生的访存，换取数量级的空间节省，并且保持了「定长索引」的硬件友好。倒排页表在物理页远少于虚拟页时省空间，但失去按进程直接索引的便利，需要附加散列与 ASID，实际采用较少。

## 六、常见误区

1. **「多级页表让每次访存都变慢四倍」**——错。TLB 命中时根本不会走页表；只有 TLB 缺失才触发遍历。把「缺失代价」与「平均代价」混为一谈是常见概念错误。
2. **「多级页表本身不占内存」**——错。每一级表都要真实页框；进程映射很多且分散时，上层表也会变多。`fork` 后大量 COW 或 mmap 碎片会放大页表内存。
3. **「页表项就是 PFN」**——PTE 还有存在位、权限位、脏位、访问位、NX 位、全局位、PAT 等；软件必须正确维护这些位，否则保护与统计会出错。
4. **「地址拆分是均等的」**——9-9-9-9-12 是 4 级 + 4KB 页的特例；5 级（LA57）是 9×5+12=57，大页则在中途 `PS` 位终止并扩大 offset。
5. **「创建 mmap 立即写满所有下级表」**——Linux 通常只建立 VMA，首次访问才缺页分配页框与中间表；这叫按需分页（demand paging）。

## 八、面试题

1. **x86-64 四级页表如何拆分虚拟地址？**  
   参考答案：48 位地址 = 9+9+9+9+12。从高到低依次为 PML4、PDPT、PD、PT 索引，低 12 位为页内偏移。CR3 指向 PML4 物理基址。

2. **多级页表相对单级页表省的是什么、多付的是什么？**  
   参考答案：省空间——只为被使用的地址区间分配下级表；多付时间——TLB 缺失时最多 L 次额外访存。用 TLB 缓解时间代价。

3. **上级页表项 P=0 时硬件做什么？**  
   参考答案：立即触发缺页（page fault），不继续遍历。内核决定是分配页（demand paging）、从磁盘换入，还是发送 SIGSEGV。

4. **什么是 LA57？**  
   参考答案：5 级页表扩展，57 位虚拟地址（9×5+12），支持更大地址空间，用于服务器级场景；需要 CPU、内核、glibc 一并支持。

## 九、演进与趋势

演进方向有三条线。其一，地址空间变宽：Intel/AMD 的 LA57 与 ARM 的 52 位 VA，页表层级从 4 级变 5 级。其二，降低遍历成本：页表本身被缓存进 CPU 的 PWC（page-walk cache），大页直接跳过若干级；PCID/ASID 保留不同进程的 TLB 项，避免切换刷新。其三，扩展语义：SVM/VT-x 的嵌套页表（NPT/EPT）给虚拟机再套一层「客户机物理 → 宿主物理」的多级页表；IOMMU 给设备做同样的转换；CXL 与持久内存继续复用页表做地址映射。软件侧，Linux 的 THP、页表自适应合并（split_huge_page）与页表锁优化（per-VMA lock）都是在多级结构上的增量打磨。理解多级页表的「按需索引」本质，才能看懂这些演进为何成立。

## 十、小结

多级页表把一次巨大的稀疏查找拆成若干定长索引，只为触及的路径付费，用最多 $L$ 次额外访存换取数量级的空间节省；再用 TLB 把这条路径从热路径上摘掉。它是「时间换空间 + 缓存掩盖延迟」的经典设计，也是理解大页、IOMMU、虚拟化嵌套页表的共同起点。
