# 地址转换性能

> 对应 CSAPP 中文笔记 https://github.com/Hansimov/csapp 第9章；OSTEP https://github.com/remzi-arpacidusse/ostep-code 。

## 一、背景与挑战

每次访存都隐含地址转换，转换开销直接叠加到所有内存操作，需整体评估。

## 二、核心原理

转换路径：TLB 命中→直接；缺失→页表遍历(多级)→可能缺页。优化：TLB 大且多级、PCID/ASID 减刷新、大页减级数、页表缓存在 L1/L2。CR3 存根地址。

## 三、形式化 / 数学基础

总访存延迟含转换：

$$MemLat = TLB\_chk + (1-h)\times Walk + data\_access$$

页行走访 4 次内存时 $Walk \approx 4 \times DRAM$。PCID 避免切换时 $O(TLB)$ 刷新。

## 四、代码实现

```c
// 测 TLB 缺失：随机大步长遍历 -> 强制 TLB miss
for (int i = 0; i < N; i += stride)
    sum += arr[i * 64];   // stride 跨页，TLB 抖动
```

## 五、与其他技术对比

- 硬件遍历(x86)快但固定；软件遍历(RISC)灵活但陷内核。
- 大页同时降本与级。

## 六、常见误区

- 误以为转换免费：TLB 缺失代价高。
- 忽视进程切换刷 TLB(无 PCID 时)。

## 八、面试题

- 为何进程切换慢？答：TLB 失效需重建(无 PCID)。
- 降转换开销手段？答：TLB/大页/PCID。

## 九、演进与趋势

PCID、大页、TLB 预取持续提升转换效率。

## 十、小结

地址转换性能由 TLB 主导，需综合大页、ASID 与缓存协同优化。
