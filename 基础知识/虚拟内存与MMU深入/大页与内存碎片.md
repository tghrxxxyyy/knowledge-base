# 大页与内存碎片

> 对应 CSAPP 中文笔记 https://github.com/Hansimov/csapp 第9章；OSTEP https://github.com/remzi-arpacidusse/ostep-code 。

## 一、背景与挑战

4KB 页在大内存工作集下 TLB 缺失频繁；但大页(2MB/1GB)带来内部碎片与分配难。

## 二、核心原理

大页减少 PTE 数与 TLB 项需求，提升覆盖；但分配需连续物理框，易失败，且页内浪费(内部碎片)。透明大页(THP)由内核自动合并但可能引发延迟抖动。

## 三、形式化 / 数学基础

TLB 覆盖：

$$Coverage = TLB\_entries \times PageSize$$

大页使同等项数覆盖更多内存，降低缺失率。碎片：

$$InternalFrag \le PageSize - used$$

## 四、代码实现

```bash
# 查看/启用大页
grep Huge /proc/meminfo
echo 2048 > /proc/sys/vm/nr_hugepages   # 预留 2MB*2048
```

## 五、与其他技术对比

- 标准页：灵活、无碎片；TLB 覆盖小。
- 大页：TLB 友好；分配与碎片成本。

## 六、常见误区

- 误以为大页总更快：小工作集无益，反增碎片。
- THP 可能致 compaction 停顿。

## 八、面试题

- 大页收益？答：减 PTE 与 TLB 缺失，提升覆盖。
- 代价？答：内部碎片与连续分配难。

## 九、演进与趋势

透明大页与显式大页并存，1GB 页用于大内存数据库。

## 十、小结

大页在 TLB 效率与碎片间权衡，适合大工作集场景。
