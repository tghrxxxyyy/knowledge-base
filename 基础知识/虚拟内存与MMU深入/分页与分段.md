# 分页与分段

> 对应 CSAPP 中文笔记 https://github.com/Hansimov/csapp 第9章；OSTEP https://github.com/remzi-arpacidusse/ostep-code ；Tanenbaum《Modern Operating Systems》第3章。

## 一、背景与挑战

多道程序设计要求每个进程拥有独立、连续、受保护的地址空间，而物理内存在进程运行期间不断被切碎、换出、复用，呈高度碎片化的动态状态。若让进程直接使用物理地址，就必须在装载时把整个程序放进连续内存，一旦进程增长或被换出再换回，几乎必然搬家，正确性与性能都难保证。操作系统必须提供一层抽象，使「进程看到的连续地址」与「物理内存的真实布局」解耦。

早期方案是分段：按程序的逻辑结构划分代码段、数据段、栈段、堆段，每段有基址与界限。它符合程序员心智模型，共享与保护也很自然——把只读代码段映射给多个进程即可共享。但段长可变，内存分配退化为动态分区问题，外部碎片随运行时间累积，压缩与紧凑代价高昂；段过大时还难以换出。工程界于是转向定长单元：把地址空间切成固定大小的页，物理内存切成同样大小的页框，任意页可放入任意框，外部碎片被彻底消除。

分页与分段的取舍是操作系统课程与面试的高频考点：不是谁取代谁的简单叙事，而是「逻辑结构」与「物理管理」两种抽象的分工。现代通用 OS（Linux、Windows、macOS）以分页为绝对主体，x86 虽保留段寄存器，但在 64 位模式下基址强制为 0，分段实质退化为兼容遗迹；而段页式（先分段、段内再分页）曾在 x86 保护模式中使用，今天主要活在考试题与部分嵌入式/教学系统中。

## 二、核心原理

**分段**把虚拟地址解释为 `(段号, 段内偏移)`。段表（segment table）为每段维护 `(base, limit, 权限)`。地址转换时先取段号查表，检查 `offset < limit`，再计算 `PA = base + offset`。不变量是：任何成功转换必满足偏移在界内，权限位与访问类型匹配。变长段的优点是共享粒度与保护粒度贴合逻辑单位（例如整个函数库只读共享）；致命缺点是外部碎片——空闲内存总量足够却找不到连续的 `limit` 大小区域，必须紧凑（compact）或拒绝分配。

**分页**把虚拟地址固定拆成 `(VPN, offset)`，页大小 $2^p$（常见 4KB，$p=12$）。物理内存被切成等长页框（frame），页表记录 `VPN → PFN` 的映射。转换为：

$$PA = (PFN \ll p) \;|\; (vaddr \bmod 2^p)$$

页框任意挑选，因此没有外部碎片；程序最后一部分用不满一页时浪费不超过一页，产生内部碎片，期望约为半页。权限（R/W/X/U/S）与状态位（存在位 P、访问位 A、脏位 D）放在 PTE 中，使保护与映射统一在一张表里。

**边界条件**：页大小是精度与开销的折中——页越小，内部碎片越少、换入换出粒度越细，但页表项数量与 TLB 压力越大。4KB 是数十年工程平衡的结果。段页式则把地址写成 `(段号, 页号, 偏移)`，先查段表得页表基址，再查页表得 PFN，保护仍按段，物理分配仍按页，代价是多一级查表。

## 三、形式化与数学基础

设虚拟地址位宽 $n$，页大小 $2^p$，则

$$VPN = \lfloor vaddr / 2^p \rfloor,\quad offset = vaddr \bmod 2^p,\quad PFN = PT[VPN]$$

$$PA = PFN \cdot 2^p + offset$$

单级页表项数为 $2^{n-p}$。以 x86-64 的 48 位用户地址、4KB 页为例，项数达 $2^{36}$，每项 8 字节则整表 $2^{39}$ 字节（512 GiB），显然不可行——这正是多级页表的动机（见《多级页表》）。

内部碎片的期望浪费：若文件/数据长度 $L$ 在页内均匀分布，则平均浪费 $E[W]=(2^p-1)/2$。外部碎片在变长分配下可用「首次适应/最佳适应」建模，但无法根除；定长页使任意空闲框可立即复用，分配复杂度为 $O(1)$。

分段的转换约束为 $0 \le offset < limit$，否则产生越界异常；这比纯分页的「仅查权限位」多了一次动态界限比较，但换来了可变粒度保护。

## 四、代码实现

下面用 Python 模拟地址拆分、单级页表转换，并统计页内内部碎片：

```python
PAGE_SHIFT = 12          # 4 KiB
PAGE_SIZE = 1 << PAGE_SHIFT
ADDR_BITS = 48           # 用户态虚拟地址位宽（x86-64 规范）


def split_vaddr(vaddr: int):
    """把虚拟地址拆成 (VPN, offset)。"""
    if vaddr < 0 or vaddr >= (1 << ADDR_BITS):
        raise ValueError("vaddr out of range")
    offset = vaddr & (PAGE_SIZE - 1)
    vpn = vaddr >> PAGE_SHIFT
    return vpn, offset


def build_page_table(mappings: dict):
    """mappings: {vpn: (pfn, flags)}，flags 为 'R','W','X','U' 字符串集合。"""
    return dict(mappings)


def translate(vaddr: int, pt: dict, mode="R"):
    vpn, offset = split_vaddr(vaddr)
    if vpn not in pt:
        raise MemoryError(f"page fault: VPN={vpn:#x} not present")
    pfn, flags = pt[vpn]
    need = {"R": "R", "W": "W", "X": "X"}[mode]
    if need not in flags:
        raise PermissionError(f"permission denied: need {need}, have {flags}")
    pa = (pfn << PAGE_SHIFT) | offset
    return pa, vpn, offset, pfn


def internal_frag(payload_len: int, page_size: int = PAGE_SIZE) -> int:
    """给定有效载荷长度，计算内部碎片（末页浪费字节数）。"""
    if payload_len <= 0:
        return 0
    used_in_last = ((payload_len - 1) % page_size) + 1
    return page_size - used_in_last


# 经典用例
if __name__ == "__main__":
    # 进程有两段逻辑区域：代码只读执行，数据可读写
    # VPN = VA >> 12，故 VA 0x10000000 的 VPN 是 0x10000
    pt = build_page_table({
        0x10000: (0x20000, {"R", "X"}),   # 代码页，VA 0x10000000-0x10000fff
        0x10001: (0x20001, {"R", "X"}),
        0x30000: (0x40000, {"R", "W"}),   # 数据页，VA 0x30000000-0x30000fff
    })
    pa, vpn, off, pfn = translate(0x1000_00C8, pt, mode="X")
    print(f"VA=0x{0x100000C8:x} -> PA=0x{pa:x} (VPN=0x{vpn:x}, off=0x{off:x})")
    assert pa == (0x20000 << 12) | 0xC8

    try:
        translate(0x3000_0000, pt, mode="X")   # 数据页不可执行
    except PermissionError as e:
        print("caught:", e)

    try:
        translate(0x9999_0000, pt)             # 未映射页
    except MemoryError as e:
        print("caught:", e)

    print("internal frag for 1 byte:", internal_frag(1))          # 4095
    print("internal frag for 4096 bytes:", internal_frag(4096))   # 0
    print("internal frag for 4097 bytes:", internal_frag(4097))   # 4095
```

运行结果应包含：`VA=0x100000c8 -> PA=0x200000c8`，两次 `caught`，以及 4095 / 0 / 4095 的碎片统计。这段代码清晰体现了 `(VPN, offset)` 拆分、PTE 权限检查与末页浪费三件事。

## 五、与其他技术对比

| 维度 | 分段 | 分页 | 段页式 |
|------|------|------|--------|
| 单元大小 | 变长（逻辑单位） | 定长（如 4KB） | 段变长、页定长 |
| 外部碎片 | 严重 | 无 | 无（页级） |
| 内部碎片 | 无 | 有（末页） | 有 |
| 共享/保护粒度 | 段级，贴合逻辑 | 页级，偏机械 | 段级保护 + 页级分配 |
| 地址转换 | 一次查段表 | 一次查页表 | 段表 + 页表 |
| 典型应用 | 早年 x86 保护模式、嵌入式 | 现代通用 OS | 教学、部分内核结构 |

取舍本质：分段优化「表达语义」，分页优化「物理管理」。通用 OS 选择分页，是因为内存分配效率与换页粒度是第一瓶颈；而 ELF/Mach-O 在文件层仍保留 section/segment 语义，只是进入内存后统一按页管理。

## 六、常见误区

1. **「分页没有碎片」**——错。分页消除的是外部碎片，内部碎片始终存在，平均约半页。对海量小文件或大量短生命周期对象，若按页分配且不做 slab/对象缓存，浪费可观。
2. **「分段已经彻底消失」**——x86-64 用户代码几乎感觉不到段，但 GDT/LDT、`FS`/`GS`（TLS）仍依赖段机制；内核在进入时仍配置段描述符。说「退化」而非「消失」更准确。
3. **「页越大越好」**——大页减少 TLB 缺失，却增大内部碎片、提高分配连续物理内存的难度，还可能放大拷贝与换出代价。4KB 与 2MB 必须按工作集选择。
4. **「虚拟地址等于物理地址加个偏移」**——在纯分段下接近，但在分页（尤其多级页表）下映射是离散的、可换出的，同一 PFN 可被多个 VPN 映射（共享库、COW）。
5. **「段页式只是考试产物」**——它在概念上解释了「逻辑单位保护 + 物理定长管理」如何兼得，理解它有助于看懂 x86 保护模式与某些 RTOS 的地址翻译。

## 八、面试题

1. **分页与分段的核心区别是什么？各自碎片情况如何？**  
   参考答案：分段按逻辑单位变长划分，无内部碎片但有外部碎片；分页按定长页划分，无外部碎片但有内部碎片。分段保护/共享自然，分页分配简单、支持离散映射与换页。

2. **4KB 页时页内偏移多少位？若页大小改为 64KB 呢？**  
   参考答案：$p = \log_2(PageSize)$。4KB → 12 位；64KB → 16 位。地址低位是 offset，高位是 VPN。

3. **为什么现代通用 OS 几乎只用分页？**  
   参考答案：内存分配与回收要高效、支持稀疏地址空间、按需调页和共享页框；定长页把分配简化为位图/空闲链表管理，且与磁盘交换块、大页、NUMA 迁移等机制同构。分段的外部碎片与变长管理成本过高。

4. **虚拟地址 0x00007F12_3456_7890，页 4KB，VPN 和 offset 各是多少（按 48 位）？**  
   参考答案：offset 取低 12 位 = 0x890；VPN = 地址右移 12 位。可用代码中 `split_vaddr` 直接算出并校验。

## 九、演进与趋势

现代系统的演进主线是「分页为底座，叠加多层优化」：多级/五级页表支撑 48/57 位地址空间；大页（2MB/1GB）与透明大页（THP）缓解 TLB 压力；反向映射（rmap）解决「物理页被谁映射」的扫描成本；KSM 把内容相同的匿名页合并；设备内存（GPU、CXL）继续沿用页表语义做 IOMMU 映射。分段的思想则以「区域（VMA）」形式活在操作系统中——Linux 用 `vm_area_struct` 描述连续、同权限的虚拟区间，实现按需装载、COW 与保护，某种意义上是「逻辑分段 + 物理分页」的工程融合。面试与工程中，理解这一融合比死记「分段被淘汰」更有价值。

## 十、小结

分段以变长逻辑单位换取自然的共享与保护，却受困于外部碎片；分页以定长映射消除外部碎片、把分配变成框的复用，代价是内部碎片与更机械的保护粒度。现代系统用页表实现高效离散映射，用 VMA 等结构保留逻辑分区，最终在性能与语义之间取得平衡——理解这两种抽象的不变量与代价，是掌握虚拟内存一切后续机制的起点。
