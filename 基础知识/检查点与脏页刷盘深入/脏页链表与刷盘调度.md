# 脏页链表与刷盘调度

> 对应 MySQL InnoDB 官方文档「Buffer Pool」与「Dirty Page Flushing」，参考 DDIA 第3章 B-Trees 与缓冲管理。

## 一、背景与挑战

缓冲池（buffer pool）中被修改但尚未写回磁盘的页称为脏页。脏页必须定时刷回磁盘，以满足两点：持久性（崩溃后可由 WAL Redo 重建，但 Redo 量不应过大）与检查点推进（检查点要求 `redo_lsn` 前脏页已刷盘）。刷盘过快占用 IO、与前台争抢；过慢则在崩溃时 Redo 量过大，或在内存压力下被迫同步刷盘造成抖动（foreground flush stall）。

挑战在于：刷盘调度是反馈控制问题——要随脏页比例、IO 带宽、写负载峰谷动态调整速率，既不能尖峰也不能欠账。

## 二、核心原理

InnoDB 维护脏页链表（flush list），按页最早修改的 LSN（oldest_modification_lsn）有序排列，这样刷盘时天然从「最老脏页」开始，持续推进 `redo_lsn`。后台有 page cleaner 线程周期性刷盘，刷盘速率受脏页比例上限（`innodb_max_dirty_pages_pct`）、低水位（`_lwm`）与目标 LSN 推进速度控制。为减少随机 IO，采用「邻居写」（flush neighbors）：刷某脏页时顺带刷其相邻页，把随机写聚成顺序写。

调度核心是反馈环：脏页比例 $p$ 超过目标则加快刷盘，低于则放松，使 $p$ 稳定在目标附近。

反馈环的核心是「脏页比例驱动速率」：比例超目标则加快刷盘、低于则放松，使比例稳定在目标附近。邻居写在 HDD 上收益明显（随机→顺序），但在 SSD 上可能徒增写入、收益有限，需按介质权衡 innodb_flush_neighbors。多 page cleaner 并行与 NUMA 感知的分区，是缓冲池扩展性的关键。

## 三、形式化与数学基础

设脏页比例 $p = D / B$（$D$ 为脏页数、$B$ 为缓冲页数）。反馈式平滑刷盘速率 $r$ 与 $(p - p_{\mathrm{target}})$ 成正比：

$$ r = r_{\mathrm{base}} + k \cdot \max(0, p - p_{\mathrm{target}}) $$

当 $p > p_{\max}$ 触发积极刷盘（甚至前台等待 `Innodb_buffer_pool_wait_free`）。`redo_lsn` 推进速度需匹配写负载 $W$，否则脏页堆积：

$$ \frac{d\,\mathrm{LSN}_{\mathrm{redo}}}{dt} \ge W - r $$

即刷盘速率 $r$ 至少要跟上写入，才能使 `redo_lsn` 持续前移、恢复区间不膨胀。

## 五、与其他技术对比

| 引擎 | 刷脏机制 | 特点 |
|------|----------|------|
| InnoDB | flush list + page cleaner | 脏页 LSN 有序、邻居写 |
| PostgreSQL | bgwriter + checkpoint | 参数体系不同（`bgwriter_lru_maxpages`） |
| LSM-tree | 无原地脏页 | 顺序写 SSTable，规避随机刷盘 |
| RocksDB | 后台 compaction | 类 LSM，合并即「刷盘」 |

PostgreSQL 的 bgwriter 与 checkpoint 配合刷脏，机制类似但参数不同。LSM-tree（O'Neil 1996）无原地更新脏页概念，改为顺序写不可变 SSTable，从根本上规避随机刷盘抖动。

## 六、常见误区

误区一：脏页不刷就丢失——有 WAL 保证，崩溃后可 Redo 重建，故脏页可缓刷，只是影响恢复长度。误区二：SSD 下刷盘调度不重要——仍影响写放大与寿命，且 `wait_free` 毛刺在 SSD 上也存在。误区三：刷得越勤越安全——过度刷盘抢占前台 IO，且增加写放大。误区四：邻居写总有益——随机写盘（HDD）受益，顺序介质（SSD）下邻居写可能徒增写入。

## 八、面试题

1. 脏页为什么不立即刷盘？聚合随机写为顺序、利用缓冲提升读命中，且 WAL 保证崩溃可恢复。
2. 脏页比例过高后果？检查点推进慢、崩溃恢复长、内存压力下前台同步刷盘（wait_free）抖动。
3. flush list 为何按 LSN 排序？保证从最老脏页刷起，持续推进 redo_lsn，使恢复区间最短。
4. 邻居写作用与局限？把随机写聚成顺序写（HDD 受益），SSD 下收益有限甚至增写。

多 page cleaner 与 NUMA 感知分区提升大缓冲池扩展性；写整形（write shaping）按存储特性调整刷盘节奏，降低 SSD 写放大与寿命损耗。机器学习预测脏页产生模式，在空闲带宽预刷、高峰避让。可观测上，wait_free 与刷盘吞吐是判断调度是否健康的核心指标。

## 十、小结

脏页刷盘是吞吐与恢复成本的平衡艺术：靠脏页链表（LSN 有序）+ 反馈式调度（比例驱动）+ 邻居写（聚合 IO）平滑进行。理解 `redo_lsn` 推进与脏页比例反馈环，是调优缓冲池的关键。
