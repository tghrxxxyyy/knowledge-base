# 模糊检查点与精确检查点

> 对应 Mohan 1992 ARIES 论文中的 Fuzzy Checkpointing 与 Gray 1978 系统恢复理论，参考 Silberschatz 第17章 Recovery。

## 一、背景与挑战
检查点（checkpoint）记录「某一时刻数据库的一致状态」，用于缩短崩溃恢复时需要重放的日志长度。精确检查点要求暂停所有写入以保证一致性快照，代价高；模糊检查点允许在写活动进行时记录，成为主流选择。

## 二、核心原理
模糊检查点不要求数据库静止，它记录检查点开始时的活跃事务列表与脏页信息，恢复时结合日志 Redo 到检查点之后即可。精确检查点则需等待所有脏页刷盘且此刻无进行中事务，恢复可直接从检查点状态开始。

## 三、形式化与数学基础
恢复需重放日志量近似：
$$ L_{redo} = L_{total} - L_{before\_ckpt} $$
模糊检查点使 $L_{before\_ckpt}$ 接近最近一次稳定点，从而 $L_{redo}$ 显著降低，且不引入停写窗口。

## 四、代码实现
```c
// 伪代码：模糊检查点
begin_checkpoint();
write_checkpoint_record(active_txns, dirty_pages);
// 不阻塞新事务，继续处理
end_checkpoint();
```

## 五、与其他技术对比
早期系统常用 quiescent（静止）检查点，简单但造成停顿。模糊检查点将「记录」与「刷脏」解耦，是现代引擎标配。PostgreSQL 的 checkpoint 属此类，配合 REDO 日志。

## 六、常见误区
认为检查点就是把所有数据刷盘。实际上模糊检查点只是记录现场信息，真正刷脏由后台刷盘线程异步完成。认为检查点越频繁恢复越快——但频繁检查点增加 IO 负担。

## 七、与开源书/权威来源对应
Mohan 等 1992 的 ARIES 论文 Section 4 详述 fuzzy checkpointing；Silberschatz《Database System Concepts》17.5 节。

## 八、面试题
问：为什么用模糊检查点？答：避免停写、降低恢复时间同时不阻塞业务。问：恢复时模糊检查点怎么用？答：从检查点记录的事务表与脏页表出发，先 Redo 再 Undo 未提交事务。

## 九、演进与趋势
增量检查点（如增量记录脏页位图）进一步平摊检查点开销，避免单次大量刷盘造成的 IO 尖峰。

## 十、小结
模糊检查点通过记录现场而非强制静止，兼顾恢复速度与可用性，是 WAL 体系的关键一环。
