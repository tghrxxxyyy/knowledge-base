# 发射队列与唤醒选择

> 对应 Hennessy & Patterson《Computer Architecture》。

## 一、背景与挑战
乱序核心需一个结构来暂存已译码但未发射的指令，并在其操作数就绪时「唤醒」并选择送入功能单元，平衡宽度与延迟。

## 二、核心原理
发射队列（Issue Queue / Reservation Station）保存指令源标签与就绪位。结果在 CDB 广播时唤醒匹配的等待项（置就绪）；每周期按优先级（年龄/类型）从就绪项中选若干发射。

## 三、形式化与数学基础
唤醒条件：

    for each entry e: if e.src_tag == broadcast_tag then e.ready = 1

选择：从 {e | e.ready} 中取优先级最高且功能单元空闲者。

## 四、代码实现
```c
void wakeup(int tag, uint64_t val) {
    for (int i = 0; i < IQ; i++)
        if (iq[i].src1 == tag) { iq[i].v1 = val; iq[i].r1 = 1; }
        if (iq[i].src2 == tag) { iq[i].v2 = val; iq[i].r2 = 1; }
}
int select() {
    for (int i = 0; i < IQ; i++)
        if (iq[i].r1 && iq[i].r2 && fu_ok(iq[i].op)) return i;
    return -1;
}
```

## 五、与其他技术对比
集中式发射队列调度灵活但功耗大；分布式（按功能单元分区）降低开销，调度局部性不同。

## 六、常见误区
误以为唤醒即发射；需就绪且被选。误以为队列越大越好，越大延迟越高。

## 九、演进与趋势
指令窗口与发射队列容量扩大以隐藏长延迟，受功耗限制。

## 十、小结
发射队列通过唤醒与选择将就绪指令派发到功能单元，是乱序调度的中枢。
