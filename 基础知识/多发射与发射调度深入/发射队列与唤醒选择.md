# 发射队列与唤醒选择

> 对应 Hennessy & Patterson《Computer Architecture》动态调度章节 / Palacharla et al. 1997 "Complexity-Effective Superscalar Processors"（ISCA）/ Intel 优化手册中关于调度延迟与发射带宽的描述。

## 一、背景与挑战

乱序核心需要一个结构暂存「已译码、已重命名、但操作数未就绪」的指令，并在操作数到齐时把它们送到功能单元。这个结构就是发射队列（Issue Queue, IQ），也叫保留站（Reservation Station, RS）或调度窗口。

它要同时满足三个互相冲突的诉求：**容量**（决定能跨越多少延迟而不停顿）、**延迟**（每周期要完成「唤醒—选择—读寄存器—发射」，这条链在时序关键路径上，容量越大越慢）、以及**带宽**（每周期要能唤醒并发射足够多指令喂饱多个功能单元）。

难点在于「唤醒」与「选择」在**同一周期内串行依赖**：只有先知道哪些项就绪，才能选择发射哪些；而唤醒又依赖本周期其他功能单元广播的结果，那些结果又依赖本周期发射的指令。这条环绕决定了主频上限。

## 二、核心原理

发射队列的每项通常保存 `{valid, 操作码, 目的标签, 源1{标签|值, 就绪位}, 源2{标签|值, 就绪位}, 年龄}`，工作流程分三步：

1. **唤醒（wakeup）**：功能单元完成后把结果标签放到广播网络（CDB 或其等价物）上，队列中所有等待该标签的项被逐个比较（CAM 语义）并置就绪位，同时把值写入该项的源值字段。
2. **选择（select）**：从所有就绪项中挑出本周期可发射的那些，约束是功能单元空闲、端口可用、不超过发射宽度。优先级通常按**年龄**（越老越优先，避免饥饿）。
3. **发射（dispatch）**：把选中项送到功能单元，标记该项可回收。

三个决定成败的实现细节：**推测唤醒**——为缩短回路，直接在发射时假定「本周期发射的指令下周期必产出结果」，提前唤醒消费者，若假设失效（如加载发生缓存缺失）必须**撤销唤醒**把就绪位清回，这是乱序核心功耗与复杂度的重要来源；**数据捕捉 vs 压缩**——前者把值随唤醒写入队列项（省一次 PRF 读），后者让值留在 PRF、发射时再读（面积与时序更友好）；**队列压实**——条目发射后留下的空洞需要折叠，否则有效容量下降，而压实本身也是时序负担。

## 三、形式化与数学基础

设唤醒—选择—发射链路延迟为 $L_{ws}$，最理想的要求是 $L_{ws} \le 1$。大容量队列上这通常不成立，于是引入**流水化简化的唤醒**与多周期标签匹配，代价是生产者—消费者之间的最小距离 $d$ 增加，等效削弱了跨越延迟的能力。

容量的收益可用 Little 定律描述：若要隐藏延迟为 $M$ 周期的访存，而平均每 $k$ 条指令有一条访存，则所需窗口大小近似为

$$
Q \gtrsim \frac{M}{k}
$$

这解释了为什么窗口必须随内存延迟增长——窗口不足时长延迟无法被掩盖，性能直接被 L2/L3 延迟支配。选择逻辑则是一个带资源约束的优先集合：

$$
S = \operatorname*{arg\,top}_{|S| \le W}\ \left\{ e : r_e = 1,\ \textstyle\sum_{e' \in S}[f_{e'} = f_e] \le C_f \right\}
$$

其中 $r_e$ 是就绪标志，$f_e$ 是所需功能单元，$C_f$ 是该单元端口数。等价的高效实现是**年龄矩阵**：每对项之间维护一个优先级位，选走一项后翻转相应行/列，避免每周期做全局排序。

## 四、代码实现

```c
/* 发射队列：唤醒（标签匹配） + 选择（年龄优先 + 功能单元约束） */
#include <stdint.h>
#define IQ_SIZE 64
#define N_FU    8

typedef struct {
    uint8_t  valid, op, r1, r2;   /* r1/r2：源就绪位 */
    int16_t  t1, t2;              /* 源标签；-1 表示已有值 */
    uint16_t age;                 /* 越小越老 */
} iq_entry;

static iq_entry iq[IQ_SIZE];
static int      fu_ports[N_FU];

void wakeup(int16_t tag) {        /* 广播结果：匹配标签者置就绪 */
    for (int i = 0; i < IQ_SIZE; i++) {
        if (!iq[i].valid) continue;
        if (iq[i].t1 == tag) { iq[i].r1 = 1; iq[i].t1 = -1; }
        if (iq[i].t2 == tag) { iq[i].r2 = 1; iq[i].t2 = -1; }
    }
}

int select_and_issue(int width) { /* 年龄最小者优先，受端口数约束 */
    int issued = 0;
    for (int w = 0; w < width; w++) {
        int best = -1;
        for (int i = 0; i < IQ_SIZE; i++) {
            if (!iq[i].valid || !iq[i].r1 || !iq[i].r2) continue;
            int fu = iq[i].op & (N_FU - 1);
            if (fu_ports[fu] <= 0) continue;              /* 结构相关 */
            if (best < 0 || iq[i].age < iq[best].age) best = i;
        }
        if (best < 0) break;                              /* 无更多可发射项 */
        fu_ports[iq[best].op & (N_FU - 1)]--;
        iq[best].valid = 0;
        issued++;
    }
    return issued;
}
```

真实实现里 CAM 匹配是面积与功耗热点：比较器数量随「项数 × 广播总线数」增长，因此出现**分布式队列**（按功能单元分区，只比较本区）与**非选择队列**（跳过显式选择、就绪即发射，牺牲调度质量换频率）。撤销推测唤醒还需记录「该项由哪个标签唤醒」，否则无法精确清回就绪位。

## 五、与其他技术对比

| 结构 | 调度质量 | 时序/功耗 | 容量扩展性 | 典型代价 |
| --- | --- | --- | --- | --- |
| 集中式 IQ | 最优（全局可见） | 差（大 CAM + 大选择树） | 差 | 唤醒延迟高，主频受限 |
| 分布式 IQ（按 FU 分区） | 局部最优 | 好 | 好 | 跨区指令无法互相调度 |
| 非选择队列（就绪即发射） | 一般 | 很好 | 好 | 无法按年龄消解端口冲突 |
| 纯按序队列 | 无乱序调度 | 极好 | 极好 | 无法跨越长延迟 |
| 带数据捕捉的 IQ | 同集中式 | 面积大、省 PRF 端口 | 中 | 唤醒网络写带宽压力 |

与 ROB 的关系：ROB 管**提交顺序与精确异常**，IQ 管**执行顺序与资源分配**；两者常被混淆，但规模约束完全不同。

## 六、常见误区

- 「被唤醒就等于被发射」：唤醒只置就绪位，还需通过选择（功能单元空闲、发射宽度、年龄优先）才能发射。
- 「队列越大越好」：容量上升使唤醒—选择链路变长、功耗上升，可能降低主频并增加推测唤醒撤销次数。
- 「唤醒是单周期的」：大容量队列通常需要流水化唤醒，等效增加生产者—消费者最小距离。
- 「分布式队列没有代价」：跨区依赖必须靠额外转发或条目复制解决，否则损失可观的 ILP。
- 「年龄优先是唯一正确策略」：某些负载下按类型或关键路径优先更优，但会带来饥饿与实现复杂度。

## 八、面试题

1. **唤醒与选择为什么分两步？** 要点：唤醒解决「数据是否到齐」（标签匹配），选择解决「本周期能否发射」（功能单元、端口、宽度、优先级）；两者约束不同却串联在关键路径上。
2. **推测唤醒是什么，为何需要撤销？** 要点：为缩短回路，发射时假定结果下周期可用；若实际延迟更长（缓存缺失）就必须撤销激活状态，等待真正广播。
3. **集中式与分布式队列如何取舍？** 要点：集中式调度更优但 CAM 与选择树随容量恶化；分布式改善时序与功耗，代价是跨区调度受限。
4. **为什么窗口要随内存延迟增长？** 要点：由 Little 定律，隐藏延迟 $M$ 需要足够的在途指令数，窗口不足则停顿直接暴露 L2/L3 延迟。
5. **数据捕捉与压缩的区别？** 要点：前者把值随唤醒写入队列（省 PRF 读端口，但面积与唤醒带宽压力大），后者值留在 PRF、发射时读取。

## 九、演进与趋势

演进围绕「在不牺牲调度质量的前提下缩短唤醒—选择回路」：分布式与层次化队列、流水化唤醒加依赖链补偿、非选择队列与推测唤醒的组合、按关键路径加权的选择策略。功耗成为主要瓶颈后，出现按需唤醒、门控与队列分区技术。研究层面，可扩展的大窗口调度与「窗口 vs 主频」的权衡仍是热点；安全约束则要求推测唤醒的撤销与状态恢复彻底，避免残留状态被侧信道利用。

## 十、小结

发射队列是乱序调度的中枢：唤醒回答「数据是否就绪」，选择回答「本周期发给谁」，发射完成资源分配。它与 ROB、重命名、功能单元端口紧密耦合，核心矛盾是**容量、延迟与功耗的三方权衡**；理解推测唤醒与撤销机制，是看懂现代核心主频受限原因的关键。
