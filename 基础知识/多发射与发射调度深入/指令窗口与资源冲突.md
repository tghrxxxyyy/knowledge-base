# 指令窗口与资源冲突

> 对应 Hennessy & Patterson《Computer Architecture》。

## 一、背景与挑战
指令窗口保存所有已发射未完成的指令，其大小限制可暴露的 ILP。窗口内指令争用有限功能单元、总线与缓存端口即资源冲突。

## 二、核心原理
窗口越大，可跨越的长延迟越多、ILP 越高，但唤醒/选择逻辑延迟与功耗上升。资源冲突发生在多条就绪指令争同一功能单元或同一周期多条访存。

## 三、形式化与数学基础
完成时间近似受窗口 W 与功能单元数 F 约束：

    throughput <= min( W / miss_latency, F / op_latency )

## 四、代码实现
```c
int fu_busy[N_FU];
int try_issue(int op) {
    int fu = fu_for(op);
    if (fu_busy[fu]) return 0;  // 资源冲突
    fu_busy[fu] = 1; return 1;
}
```

## 五、与其他技术对比
大窗口提升 ILP 但延迟/功耗非线性增长；SMT 用多上下文填窗口，提高功能单元利用率。

## 六、常见误区
误以为窗口无限大性能无限；端口与电源成瓶颈。误以为资源冲突仅指 RAW。

## 九、演进与趋势
大窗口需更聪明预取与分支预测配合；功耗成主要约束。

## 十、小结
指令窗口大小与资源冲突共同决定可挖掘的 ILP，是性能与功耗的折中焦点。
