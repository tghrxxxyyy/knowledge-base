# 静态调度与记分牌

> 对应 Hennessy & Patterson《Computer Architecture》。

## 一、背景与挑战
动态相关（RAW/WAR/WAW）会阻塞流水。记分牌（Scoreboard）是一种较早期的动态调度机制，允许不相关的指令越过阻塞指令继续执行。

## 二、核心原理
记分牌维护每张功能单元与每个目标寄存器的状态（busy/目标单元）。指令在满足源就绪且目标单元空闲且目标寄存器无其他写时才发射；执行完写回并清除状态。

## 三、形式化与数学基础
三类相关检测：

    RAW: 源寄存器 busy 且目标==本源 -> 等待
    WAR: 目标寄存器将被本指令写, 但另一指令读它且未读 -> 等待
    WAW: 目标寄存器 busy -> 等待

## 四、代码实现
```c
struct sb { int busy; int fu; int dst; } scoreboard[NR_REG];
int can_issue(int s1, int s2, int d, int fu) {
    return !scoreboard[d].busy && fu_free(fu)
        && !reg_pending_write(s1) /*RAW*/ && !reg_pending_write(s2);
}
```

## 五、与其他技术对比
记分牌仅解决结构相关与部分 WAR/WAW，不重命名；Tomasulo 用寄存器重命名更彻底消除 WAW/WAR。

## 六、常见误区
误以为记分牌能完全避免 WAW 停顿；它靠等待而非重命名。误以为它等价于乱序提交。

## 七、与开源书/权威来源对应
Hennessy & Patterson 以 CDC 6600 记分牌为例讲解动态调度。

## 九、演进与趋势
记分牌被 Tomasulo 与 ROB 取代，但作为动态调度思想奠基。

## 十、小结
记分牌用状态表实现指令级乱序执行越过阻塞，是动态调度的早期经典方案。
