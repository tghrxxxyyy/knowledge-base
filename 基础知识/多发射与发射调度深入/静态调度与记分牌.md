# 静态调度与记分牌

> 对应 Hennessy & Patterson《Computer Architecture》动态调度章节（CDC 6600 记分牌）/ Thornton 1964 "Parallel Operation in the Control Data 6600" / Muchnick《Advanced Compiler Design and Implementation》/ Cooper & Torczon《Engineering a Compiler》。

## 一、背景与挑战

流水线里的三类相关会阻塞执行：RAW（真数据依赖）、WAR、WAW。若完全由硬件按序处理，一条长延迟指令就会堵住后面所有指令。解决思路有两条硬软分工：

- **硬件动态调度**：让硬件在运行期判断「哪些指令现在就能执行」。记分牌（Scoreboard）是这一路线的早期经典——CDC 6600 用它让不相关的指令越过正在等待的指令继续执行。
- **软件静态调度**：让编译器在编译期重排指令，把有用的指令填进延迟空隙。这要求编译器知道精确的延迟表，并接受「二进制与具体微架构绑定」的代价。

两者的核心差异在于**谁知道运行时信息**：缓存缺失、存储地址冲突只有在运行期才知道，因此纯静态调度无法处理动态延迟；而记分牌不重命名，只能靠等待解决名字相关。

## 二、核心原理

### 记分牌

记分牌维护三张状态表：**指令状态表**（每条已发射指令处于 issue / read operands / execute / write result 四阶段中的哪一阶段）、**功能单元状态表**（每个单元是否忙、操作码、目的寄存器、源寄存器）、**寄存器结果状态表**（哪个功能单元将写这个寄存器）。

发射条件：功能单元空闲、目标寄存器没有其他未完成写（避免 WAW）。读操作数条件：所有源寄存器都不再被其他未完成指令写（避免 RAW）；这一阶段同时确保 WAR 安全——只有在源被读走之后，后来的写才允许写回结果。

三类相关在记分牌下的处理：**RAW** 使指令停顿在 read operands 阶段；**WAW** 使指令停顿在 issue 阶段；**WAR** 通过「按序写回」保证不冲突，代价是写结果阶段可能排队。关键局限是**不重命名**，且不提供数据前递——结果必须经寄存器堆，额外增加延迟。

### 静态调度

编译器侧的主流方法是**表调度（list scheduling）**：以基本块为单位，按关键路径最长的优先级把指令排入可用槽位，并用延迟表判断何时可发射。跨基本块需要更激进的技术：**迹调度（trace scheduling）**沿高频路径做全局重排并插入补偿代码，**软件流水**把循环不同迭代的指令交错以填满延迟空隙。VLIW/EPIC 把并行性完全交给编译器，硬件只负责按槽位发射。

## 三、形式化与数学基础

表调度可形式化为带资源约束的调度问题。设有向无环图 $G=(V,E)$，边 $(u,v)$ 的延迟 $d_{uv}$（$u$ 的结果需等多少周期才能被 $v$ 使用），指令 $v$ 占用周期 $p_v$，功能单元 $f$ 的资源上限为 $R_f$。求发射时刻指派 $t: V \to \mathbb{N}$，使总长度 $\max_v (t_v + p_v)$ 最小，且满足

$$
t_v \ge t_u + p_u + d_{uv}\ \ \forall (u,v) \in E, \qquad
\left|\{v : f_v = f,\ t_v \le \tau < t_v + p_v\}\right| \le R_f
$$

即使忽略资源约束，最短长度也不小于**关键路径长度** $T_{\min} \ge \max_{\text{path } P} \sum_{v \in P}(p_v + d_{v,\text{next}})$，这是调度的下界。

记分牌的效果可用 CPI 分解刻画：若名字相关造成的停顿为 $S_{name}$、结构相关为 $S_{struct}$、真相关为 $S_{raw}$，则

$$
CPI = CPI_{ideal} + S_{raw} + S_{name} + S_{struct}
$$

重命名能消掉 $S_{name}$，这正是 Tomasulo 相对记分牌的核心改进。静态调度的收益则受「编译器可见延迟」限制：若编译期假设 L1 命中延迟为 4 周期而运行期为 200（缺失），填充的指令全部作废，因此静态调度对固定延迟有效，对访存需配合软件预取与分块。

## 四、代码实现

```c
/* 记分牌：发射与读操作数阶段的判定（简化，不含写回排队） */
#include <stdint.h>
#define N_FU  5
#define N_REG 32
#define NO_FU (-1)

typedef struct { uint8_t busy, fu; int8_t dst; } sb_reg_t;
typedef struct { uint8_t busy, op; int8_t dst, s1, s2; } sb_fu_t;

static sb_reg_t reg_stat[N_REG];   /* 寄存器 -> 将写它的功能单元 */
static sb_fu_t  fu_stat[N_FU];

/* 发射：目标寄存器无未完成写（WAW），功能单元空闲（结构相关） */
int can_issue(int s1, int s2, int dst, int fu) {
    if (fu_stat[fu].busy) return 0;
    if (dst >= 0 && reg_stat[dst].busy) return 0;            /* WAW */
    if (s1 >= 0 && s1 == s2 && reg_stat[s1].busy) return 0;  /* 同一源只算一次 */
    return 1;
}

/* 读操作数：所有源寄存器都不再被未完成指令写（RAW） */
int can_read_operands(int s1, int s2) {
    if (s1 >= 0 && reg_stat[s1].busy) return 0;   /* 等生产者写回 */
    if (s2 >= 0 && reg_stat[s2].busy) return 0;
    return 1;                                     /* 读走后按序写回即满足 WAR */
}

/* 表调度的核心循环（伪代码形态）：每拍从「前驱已全部完成」的指令中
   按关键路径优先级取至多 width 条填入槽位，直到无就绪项或全部排完。
   node_t 需包含 pred_count、关键路径优先级 prio、延迟 lat 与目标单元 fu。 */
```

工程提示：记分牌的 `can_read_operands` 必须在「读走源操作数」的当拍原子完成，否则 WAR 语义被破坏；静态调度的延迟表要与目标微架构一致，跨代复用会显著损失收益。

## 六、常见误区

- 「记分牌能完全避免 WAW 停顿」：它靠等待而非重命名，WAW 仍需串行。
- 「记分牌等价于乱序提交」：CDC 6600 的提交仍按序，乱序只发生在执行阶段。
- 「静态调度在乱序核上没意义」：编译器调度仍能减少发射队列压力，但收益远小于在按序核上。
- 「VLIW 不需要硬件复杂度」：它把调度复杂度转给编译器，代价是二进制与微架构强绑定、代码膨胀。
- 「关键路径优先总是最优」：资源紧张时，兼顾功能单元类型的均衡启发式常更优。

## 八、面试题

1. **记分牌为何仍需 WAW 等待？** 要点：没有重命名，目标寄存器只有一个物理位置，两个写必须串行，因此发射阶段就要检查目标是否被占用。
2. **记分牌与 Tomasulo 的关键差异？** 要点：标签机制消除 WAR/WAW 并支持 CDB 前递；记分牌靠等待与「按序写回」保证正确性。
3. **静态调度在什么条件下收益最大？** 要点：延迟固定可预测（算术流水、无缺失访存）、基本块内依赖稀疏、且硬件按序发射时。
4. **为什么静态调度处理不了缓存缺失？** 要点：缺失延迟运行期才知道，编译期填充的指令会全部作废，需靠预取、分块与乱序硬件兜底。
5. **VLIW 的主要风险是什么？** 要点：二进制与具体微架构绑定，换机器需重编译；代码膨胀、调度失败时性能崩塌。

## 九、演进与趋势

记分牌作为动态调度的奠基思想被 Tomasulo 与 ROB 取代，但它揭示的结构相关与名相关分类至今通用。静态调度在大窗口乱序核上角色转变：从「主角」变成「减负」——编译器减少乱序压力、PGO 驱动关键路径优先、二进制级重排改善布局。VLIW/EPIC 在通用计算中不占主流，但在 DSP、网络处理器与 AI 加速器（显式数据流、脉动阵列）中依然常见，因为那里的延迟固定、编译期可完全掌握。

## 十、小结

记分牌用状态表让不相关指令越过阻塞指令，是动态调度的早期经典；它的天花板是「不重命名」与「不经前递」。静态调度把决策移到编译期，对固定延迟有效但对动态延迟无能为力。两者在今天的定位是：硬件负责动态决策，编译器负责减少需要动态决策的机会。
