# 数据去中心化

> 对应 Newman《Building Microservices》第5章 "Data"。

## 一、背景与挑战
共享数据库是微服务最大反模式：一个服务改表结构会破坏其他服务，违背独立部署。

## 二、核心原理
每个服务私有数据库（Database per Service），通过 API 或事件同步所需数据；避免跨服务事务，采用最终一致性。

## 三、形式化 / 数学基础
一致性模型：强一致要求 $Linearizable$，代价高；最终一致满足 $\forall op$ 经过有限时间后所有副本收敛。用版本向量 $VV$ 检测因果顺序。

## 四、代码实现
```sql
-- 每个服务独立 schema，互不可见
-- order-service.order_db / payment-service.pay_db
-- 跨域数据通过事件异步复制
```

## 五、与其他技术对比
与共享数据库相比独立性高但需处理冗余与一致性；与 CQRS 配合用只读副本服务查询。

## 六、常见误区
误区：用同一数据库不同 schema 假装去中心化。误区：在跨服务直接 JOIN。

## 七、与开源书 / 权威来源对应

## 八、面试题
"为什么共享数据库是反模式？如何处理跨服务数据？"

## 九、演进与趋势
数据网格（Data Mesh）把领域数据当作产品，进一步去中心化治理。

## 十、小结
数据库私有化 + 异步同步，换取部署独立。
