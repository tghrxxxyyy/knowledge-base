# 弹性设计

> 对应 Newman《Building Microservices》、Microsoft "Designing Resilient Systems"。

## 一、背景与挑战
分布式系统中故障常态存在：下游超时、依赖雪崩、瞬时网络抖动会拖垮整个系统。

## 二、核心原理
弹性模式：超时（Timeout）、重试（Retry with backoff）、熔断（Circuit Breaker）、舱壁隔离（Bulkhead）、限流（Rate Limit）、降级（Fallback）。

## 三、形式化 / 数学基础
熔断器三态：Closed/Open/Half-Open。以滑动窗口失败率 $f=\frac{fail}{total}$，当 $f>threshold$ 且样本足够则 Open，冷却 $t_{cool}$ 后转 Half-Open 试探。

## 四、代码实现
```python
# 简单熔断装饰器逻辑
if breaker.open:
    return fallback()
try:
    r = call()
    breaker.record(success=True)
except:
    breaker.record(success=False); raise
```

## 五、与其他技术对比
重试解决瞬时故障但加剧拥塞，需配退避与 jitter；舱壁隔离限制爆炸半径，优于全局共享连接池。

## 六、常见误区
误区：无退避地盲目重试导致重试风暴。误区：把超时设得过长，线程被占满。

## 九、演进与趋势
混沌工程（Chaos Engineering）主动验证弹性；自适应限流（如 TCP Vegas 思路）兴起。

## 十、小结
用超时、重试、熔断、隔离组合抵御故障传播。
