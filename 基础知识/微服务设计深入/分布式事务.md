# 分布式事务

> 对应 Newman《Building Microservices》、Pat Helland "Life beyond Distributed Transactions"。

## 一、背景与挑战
跨多个服务的写操作无法用单机数据库事务保证 ACID，两阶段提交（2PC）在微服务中可用性差、锁资源久。

## 二、核心原理
采用最终一致性方案：Saga 模式（一组本地事务 + 补偿事务）、TCC（Try-Confirm-Cancel）、基于消息队列的事件驱动。核心思想是"接受暂时不一致，保证可恢复"。

## 三、形式化 / 数学基础
Saga 为事务序列 $T_1,T_2,\dots,T_n$，每 $T_i$ 有补偿 $C_i$。失败时逆序执行 $C_n,\dots,C_{k+1}$ 回滚已完成步骤。满足 $T$ 全成功或 $\sum C$ 抵消。

## 四、代码实现
```python
# 编排式 Saga：本地事务成功则发事件，失败则发补偿
def create_order():
    reserve_inventory();  # T1
    charge_payment();     # T2
    # 若 T2 失败 -> release_inventory() 补偿
```

## 五、与其他技术对比
2PC 强一致但阻塞、可用性低；Saga 高可用但仅最终一致且需补偿逻辑；TCC 更细但侵入强。

## 六、常见误区
误区：在微服务强求 2PC。误区：补偿事务未考虑幂等，导致重复回滚出错。

## 九、演进与趋势
事务消息（如 RocketMQ half-message）、Outbox 模式保证本地事务与事件原子性。

## 十、小结
用 Saga/消息驱动换取可用性，以补偿保证最终一致。
