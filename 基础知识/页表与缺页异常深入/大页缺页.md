# 大页缺页

> 对应 Linux 透明大页（THP）与 hugetlbfs，及 CSAPP 第 9 章大页机制。

## 一、背景与挑战
4 KiB 页在大数据集下导致页表项海量、TLB 命中率低、缺页频繁。大页（2 MiB/1 GiB）减少页表级数、提升 TLB 覆盖，但缺页与内存管理更复杂。

## 二、核心原理
- 标准页 4 KiB，PMD 级大页 2 MiB，PUD 级 1 GiB。
- 透明大页（THP）在内核按需把连续 4 KiB 页合并为大页，对应用透明。
- 大页缺页需分配连续物理块（伙伴系统高阶块），失败则降级普通页。

## 三、形式化 / 数学基础
TLB 覆盖 $= \\text{条目数} \\times \\text{页大小}$。同样 64 条目，4 KiB 覆盖 256 KiB，2 MiB 覆盖 128 MiB。页表层数：4 KiB 需 4 级，2 MiB 只需到 PMD（少一级查表）。

## 四、代码实现
透明大页分配（示意）：

```c
struct page *alloc_transhuge_page(struct vm_area *vma, unsigned long addr) {
    struct page *p = alloc_pages(THP_ORDER);   /* 高阶连续块 */
    if (!p) return alloc_normal_page();          /* 降级 */
    prep_compound_page(p, THP_ORDER);
    return p;
}
```

## 五、与其他技术对比
hugetlbfs 需预留、管理显式；THP 自动但可能因碎片需整理（compaction），偶发延迟尖峰；标准 4 KiB 灵活但 TLB 压力大。

## 六、常见误区
- 认为大页总是更快：碎片化整理可能引入延迟抖动。
- 忽略大页内部碎片（小对象占用 2 MiB）。
- 混淆 hugetlb 与 THP 的预留方式。

## 九、演进与趋势

## 十、小结
大页以更大映射单位减少页表层级与缺页频率、扩大 TLB 覆盖，代价是连续内存需求与碎片整理的潜在延迟。
