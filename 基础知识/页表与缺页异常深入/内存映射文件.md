# 内存映射文件

> 对应 CSAPP 第 9 章“内存映射”与 Linux `mm/mmap.c`，详见 SUB 内存管理与分页深入 的《内存映射》篇。

## 一、背景与挑战
把文件当作内存数组直接访问可避免 read/write 的拷贝与系统调用负担。内存映射文件让文件页通过页表直接出现在进程地址空间。

## 二、核心原理
- `mmap` 建 VMA，PTE 初始无效。
- 访问触发缺页，内核从 page cache 读入文件页并建立映射（major fault 首次，之后可共享）。
- 私有映射写时 COW；共享映射写回文件（由 writeback 刷盘）。

## 三、形式化 / 数学基础
映射窗口 $[v_{start},v_{end})$ 对应文件 $[off, off+len)$。缺页偏移 $k = \\lfloor(addr-v_{start})/B\\rfloor$，装入页 $pagecache(file, off + k\\cdot B)$。共享映射的多进程指向同一物理页（引用计数 >1）。

## 四、代码实现
映射并修改文件（私有 vs 共享）：

```c
int fd = open("f", O_RDWR);
char *p = mmap(NULL, sz, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);
p[0] = 'X';          /* 共享映射: 改动最终写回文件 */
munmap(p, sz);
```

## 五、与其他技术对比
`read`/`write` 需内核缓冲到用户缓冲拷贝；mmap 直接映射页缓存，少一次拷贝，但小文件或随机访问可能 fault 开销不划算（见《内存映射》篇详述）。

## 六、常见误区
- 认为 mmap 一定快于 read：取决于访问模式。
- 私有映射写会改文件：不会，COW 保护原文件。
- 忘 `msync` 保证共享映射改动落盘时机。

## 九、演进与趋势
`MAP_POPULATE` 预 fault、`madvise` 提示与 DAX（持久内存直接映射免 page cache）扩展映射语义。

## 十、小结
内存映射文件把文件页经页缓存直接映射进地址空间，用缺页驱动装入、COW/写回控制可见性，是零拷贝与共享内存的基础技术。
