# 写时复制

> 对应 CSAPP 第 9 章“写时复制”与 OSTEP 第 4-5 章 fork。

## 一、背景与挑战
`fork()` 需复制父进程地址空间，但往往子进程马上 `exec`，复制纯属浪费。写时复制（Copy-on-Write）让父子先共享页，仅在写入时才真正复制。

## 二、核心原理
- `fork` 后父子 PTE 均标记为只读，且指向同一物理页。
- 任一方写该页触发页错误，内核复制该页为新页框，PTE 改为可写。
- 未写的页始终共享，零拷贝。

## 三、形式化 / 数学基础
设进程写集合 $W$ 占比 $p$，COW 复制页数 $\\approx p\\cdot N$（$N$ 为映射页数），远小于全量 $N$。`fork` 成本从 $O(N)$ 降到 $O(\\text{页表复制})$。

## 四、代码实现
写保护触发 COW（示意）：

```c
vm_fault_t do_wp_page(struct vm_area *vma, unsigned long addr) {
    struct page *old = pte_page(*pte);
    struct page *new = alloc_page();
    copy_page(new, old);             /* 仅复制被写的这一页 */
    set_pte(pte, mk_pte(new, vma->vm_page_prot | WRITE));
    return VM_FAULT_MINOR;
}
```

## 五、与其他技术对比
深复制（eager copy）简单但慢且浪费；COW 惰性、按需复制，是 fork+exec 高效的根因；`vfork` 更进一步共享地址空间直至 exec。

## 六、常见误区
- 认为 fork 立刻复制全部内存：实际靠 COW 共享。
- 忽略 COW 页错误开销（写密集时仍会复制很多页）。
- 混淆 COW 与 mmap MAP_PRIVATE（机制相同）。

## 九、演进与趋势
`vfork`/`clone` 提供轻量进程变体；userfaultfd 与 `MAP_PRIVATE` 文件映射让用户态实现自定义 COW 语义。

## 十、小结
写时复制以“只读共享 + 写时复制单页”把 fork 成本降到页表级别，是 Unix 进程创建高效的关键机制。
