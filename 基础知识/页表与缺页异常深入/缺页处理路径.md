# 缺页处理路径

> 对应 Linux `handle_mm_fault` 与 `do_fault`/`do_anonymous_page`，及 CSAPP 第 9 章。

## 一、背景与挑战
从 CPU 触发页错误到返回用户态恢复执行，内核要完成“查 VMA → 判类型 → 建映射/读盘/杀进程”的一连串操作，且必须高效正确。

## 二、核心原理
路径：异常入口 → 保存现场 → `find_vma` 定位区间 → 区分匿名/文件/swap/COW → 分配页或读入 → 更新 PTE → 返回重试指令。若地址不落任何 VMA 或权限错 → SIGSEGV。

## 三、形式化 / 数学基础
缺页延迟 $L_{fault} = L_{vma} + L_{alloc} + (L_{disk} \\text{ if major})$。关键不变量：处理完 PTE 存在位与权限必须与访问一致，否则同地址会无限重入（double fault）。

## 四、代码实现
缺页主流程（示意）：

```c
vm_fault_t handle_mm_fault(struct vm_area *vma, unsigned long addr, unsigned int flags) {
    if (addr < vma->vm_start || addr >= vma->vm_end)
        return VM_FAULT_SIGSEGV;          /* 不在任何区间 */
    if (vma->vm_flags & VM_ANONYMOUS)
        return do_anonymous_page(vma, addr, flags);
    return do_fault(vma, addr, flags);    /* 文件/swap/COW */
}
```

## 五、与其他技术对比
匿名缺页最轻（取零页）；文件缺页需 page cache 与可能磁盘读；swap 缺页需换入；COW 需复制。路径复杂度递增，但都复用同一 `handle_mm_fault` 框架。

## 六、常见误区
- 忽略 double fault 风险：建映射前必须使 PTE 一致。
- 认为缺页只发生在用户态：内核态访问非法映射同样 fault（更危险）。
- 混淆 fault 与异常入口成本。

## 九、演进与趋势
per-VMA 锁与 RCU VMA 查找降低缺页路径锁争用；userfaultfd 让用户态接管特定缺页处理。

## 十、小结
缺页处理路径经 VMA 定位、类型分发与 PTE 修正完成“按需内存”，核心是正确建立一致的页表项以保证指令可重试。
