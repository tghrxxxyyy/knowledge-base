# 请求调页

> 对应 OSTEP 第 20 章“分页：请求调页”与 CSAPP 第 9 章。

## 一、背景与挑战
若进程启动就把全部地址空间装入内存，启动慢且浪费（很多代码/数据永不访问）。请求调页（demand paging）只在首次访问时才装入对应页。

## 二、核心原理
- PTE 初始有效位为 0，访问触发 minor/major fault。
- 若为匿名页：分配零页并建立映射（minor）。
- 若为文件映射：从 page cache 读入（major，磁盘 IO）。
- 空闲页不足时先回收/换出再装入。

## 三、形式化 / 数学基础
设工作集为 $W$，物理页为 $P$。若 $|W| \\le P$，几乎无 major fault；否则持续换入换出产生颠簸。有效访问时间 $EAT = (1-p)\\cdot t_{mem} + p\\cdot t_{page\\_fault}$。

## 四、代码实现
匿名页首次访问（示意）：

```c
vm_fault_t do_anonymous_page(struct vm_area *vma, unsigned long addr) {
    struct page *p = alloc_zeroed_page();   /* 取零页 */
    set_pte(pte, mk_pte(p, vma->vm_page_prot)); /* 建映射 */
    return VM_FAULT_MINOR;
}
```

## 五、与其他技术对比
纯交换（启动时全装入）启动慢、内存占用高；请求调页启动快、按需占用，但需要缺页机制与换出配合；预取（prefetch）可在 fault 前主动装入。

## 六、常见误区
- 认为 mmap 后数据已在内存：仅建区间，访问才 fault。
- 忽略工作集超过物理内存时的颠簸。
- 把 minor fault 当 IO 成本。

## 九、演进与趋势
内核预读、working set 感知的回收与 `madvise` 提示让请求调页更智能；压缩交换（zswap）降低 major fault 成本。

## 十、小结
请求调页把“装入时机”推迟到首次访问，用缺页机制按需取页，以少量 fault 代价换启动速度与内存节约。
