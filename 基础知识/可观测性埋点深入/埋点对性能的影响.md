# 埋点对性能的影响

> 对应 Vonng/ddia (Designing Data-Intensive Applications)。

## 一、背景与挑战
埋点若在主流程同步执行（序列化、网络发送），会直接增加延迟与 CPU，甚至在高并发下反压业务。

## 二、核心原理
通过异步、批处理、采样与无锁队列把埋点开销移出关键路径；指标累加优先用原子操作而非锁。

## 三、形式化与数学基础
同步埋点使请求延迟 T = T_biz + T_instr；异步批处理后 T ≈ T_biz，仅增加后台 CPU 与内存缓冲 B，需在 B 上限内背压。

## 四、代码实现
```python
# 非阻塞：入队即返回，后台线程批量上报
q.put(record)            # 主线程几乎零等待
# 后台
batch = q.get_bulk(timeout=1.0)
exporter.export(batch)
```

## 五、与其他技术对比
相比同步上报，异步批处理大幅降低毛刺；相比不埋点，仍有内存与少量 CPU 成本需监控。

## 六、常见误区
- 埋点异常未隔离，导致业务请求因采集失败而报错。
- 在高 QPS 路径打超大属性，内存被打满。

## 七、与开源书/权威来源对应
ddia 在批处理与流处理章节讨论吞吐与开销的权衡。

## 八、面试题
如何把埋点开销控制在 1% 以内？埋点故障为何不能影响主流程？

## 九、演进与趋势
eBPF 与语言运行时内建埋点在更低成本下提供可观测性。

## 十、小结
埋点必须异步化与隔离，把开销关在后台，才能既可见又不拖慢业务。
