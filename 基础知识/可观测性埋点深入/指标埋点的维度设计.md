# 指标埋点的维度设计

> 对应 OpenTelemetry (observability standard)。

## 一、背景与挑战
只上报一个总数无法定位问题，埋点需要带维度（标签）才能按服务、接口、地域切片分析，否则可观测性沦为黑盒。

## 二、核心原理
指标由名称、数值与一组标签（key=value）组成。设计时应选择低基数、稳定且有诊断价值的维度，避免维度爆炸。

## 三、形式化与数学基础
指标 m = (name, value, {k1:v1, ..., kn:vn})。时间序列数 = 标签取值组合的乘积，需控制基数以免存储与查询爆炸。

## 四、代码实现
```python
from opentelemetry import metrics
meter = metrics.get_meter("checkout")
counter = meter.create_counter("orders_total")
counter.add(1, {"status": "success", "region": "cn"})  # 带维度
```

## 五、与其他技术对比
相比纯日志，指标存储成本低、聚合快；维度过多则退化为高基数问题，需用日志/追踪补充细节。

## 六、常见误区
- 把 user_id 当用户维度打标，导致基数爆炸拖垮时序库。
- 维度命名不统一，跨服务无法关联。

## 七、与开源书/权威来源对应
OpenTelemetry 规范定义了 Metric 的语义约定与基数控制建议。

## 八、面试题
为什么不能用高基数维度打标？RED/USE 方法分别关注哪些指标？

## 九、演进与趋势
从手工埋点走向自动 instrumentation，框架层透明采集标准指标。

## 十、小结
埋点维度决定可观测的下钻能力，低基数、语义一致是设计铁律。
