# 日志结构化与采样

> 对应 OpenTelemetry (observability standard)。

## 一、背景与挑战
非结构化文本日志难以检索，高流量下全量日志成本极高，且大量重复日志淹没关键信息。

## 二、核心原理
以 JSON 等结构化格式输出（含时间戳、级别、trace_id、字段），并配合采样（按级别、速率或错误优先）控制体积。

## 三、形式化与数学基础
设日志流 L，采样函数 s(l) 以概率 p 保留。目标：retained = {l in L | s(l)} 满足错误日志 p=1，正常日志 p<<1，在成本与可排查间折中。

## 四、代码实现
```python
import json, logging
logging.info(json.dumps({"event": "pay", "order": oid, "ms": 12}))  # 结构化
# 采样：仅保留 10% 的健康请求日志
if level == "ERROR" or random() < 0.1:
    emit(log)
```

## 五、与其他技术对比
相比纯文本，结构化便于机器解析；相比全量，采样降本但可能漏掉偶发细节，需保证错误全采。

## 六、常见误区
- 在日志里拼装大对象，拖慢主流程。
- 采样把关键上下文一并丢掉，应保留 trace 关联。

## 七、与开源书/权威来源对应
OpenTelemetry 定义了 Logs 数据模型与上下文关联（trace_id/span_id）。

## 八、面试题
如何做到降本又不丢关键日志？结构化日志对告警有什么帮助？

## 九、演进与趋势
日志与追踪统一上下文，告警可直接跳转到对应 trace 与日志。

## 十、小结
结构化与采样让日志既可被机器消费又可控成本，错误优先是采样底线。
