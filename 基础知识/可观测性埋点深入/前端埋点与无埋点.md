# 前端埋点与无埋点

> 对应 OpenTelemetry (observability standard)。

## 一、背景与挑战
业务希望了解用户真实交互（点击、停留、转化），但手动埋点覆盖不全且随改版易失效。

## 二、核心原理
- 代码埋点：显式在事件中上报，精准但维护重。
- 无埋点/全埋点：自动采集所有交互，按规则筛选，覆盖广但数据量大。
- 可视化埋点：在界面圈选元素生成采集规则，折中两者。

## 三、形式化与数学基础
设页面元素集合 E，无埋点采集函数 c: E -> event 全量触发；可视化埋点定义子集 R ⊂ E 仅采集命中规则的元素。

## 四、代码实现
```javascript
// 代码埋点：精准
btn.addEventListener("click", () => track("pay_click", {amt}));
// 无埋点：代理全局点击，后台按需过滤
document.addEventListener("click", e => autoTrack(e.target));
```

## 五、与其他技术对比
相比代码埋点，无埋点覆盖全但噪音大、隐私风险高；可视化埋点平衡灵活与成本。

## 六、常见误区
- 无埋点全量上报导致隐私合规与流量成本问题。
- 圈选的元素选择器随改版失效。

## 七、与开源书/权威来源对应
OpenTelemetry Web 规范定义了浏览器端的 Trace/Metric 采集语义。

## 八、面试题
代码埋点与无埋点如何取舍？前端埋点的隐私合规要点？

## 九、演进与趋势
前端埋点与后端追踪打通，形成全链路用户旅程视图。

## 十、小结
前端埋点需在选择性与成本间权衡，合规与稳定性是不可逾越的底线。
