# 硬件异常与缺页处理

> 对应 Bryant & O'Hallaron《Computer Systems: A Programmer's Perspective》第 8 章「异常」，以及 Bovet & Cesati《Understanding the Linux Kernel》第 4 章（中断与异常）与第 9 章（进程地址空间）。

## 一、背景与挑战
CPU 执行指令时可能遇到除零、非法操作码、访问未映射页、页权限违例、对齐错误等情况。这类事件由**当前指令**引起，与指令流严格同步，称为「异常」（exception），区别于由外部设备异步拉起的「中断」（interrupt）。若没有硬件级的异常机制，虚拟内存、按需分页、写时复制、调试断点、系统调用都无从实现。

挑战在于：异常发生在最底层的指令边界上，处理器必须在**不破坏用户可见状态**的前提下把控制权交给内核，同时把「为什么出错」这一信息（异常号、出错地址、错误码）完整传递过去，以便内核决定是修补后重试、向进程投递信号，还是直接崩溃。

## 二、核心原理
x86 通过中断描述符表（IDT）分发异常。异常号是架构固定的，例如 `#DE`(0) 除零、`#DB`(1) 调试、`#BP`(3) 断点、`#UD`(6) 非法操作码、`#GP`(13) 通用保护、`#PF`(14) 缺页、`#AC`(17) 对齐检查、`#MC`(18) 机器检查。处理器把异常号、错误码压栈，切换到内核栈（由 `TSS.RSP0` 决定），跳转到 IDT 中登记的入口。

按语义分三类：
- **故障（fault）**：返回地址指向**引发异常的那条指令**，内核修复后可重试。`#PF` 是典型。
- **陷阱（trap）**：返回地址指向**下一条指令**；`int3`、`#OF`、以及 `syscall`/`int 0x80` 的软件路径都属此类。
- **终止（abort）**：不保证可返回，如双重故障 `#DF`、机器检查 `#MC`。

缺页是异常机制的旗舰应用。`#PF` 发生时 CR2 保存触发故障的线性地址，错误码给出失败原因；内核 `do_page_fault` 据此决定分支：
1. 地址是否落在当前进程的某个 VMA 内？不在则 `SIGSEGV`。
2. 保护位是否满足访问类型？不满足则 `SIGSEGV`（`SEGV_ACCERR`），或对私有可写映射触发写时复制。
3. 页表项为空（present=0）：匿名页 `do_anonymous_page` 分配零页；文件页 `do_fault` 走 `address_space`（页缓存／readahead）；换出页 `do_swap_page` 换入。
4. 页表项存在但权限不足：`do_wp_page` 执行 COW，复制页并让两方各自持有私有副本。
5. NUMA 节点不均匀时 `do_numa_page` 触发页迁移。

## 三、形式化与数学基础
异常语义可写成对返回地址的映射：

$$ type = \begin{cases} fault & PC \leftarrow addr(\text{引发异常的指令}) \\ trap & PC \leftarrow addr(\text{下一条指令}) \\ abort & \text{不保证可返回} \end{cases} $$

x86-64 缺页错误码 $\mathrm{EC}$ 的位编码（自低位起）：

$$ \mathrm{EC} = P + 2\cdot W + 4\cdot U + 8\cdot RSVD + 16\cdot ID + 32\cdot PK $$

其中 $P$ 表示页表项存在（$P=1$ 时的故障通常是权限问题，$P=0$ 是真正的缺页），$W$ 表示访问是写，$U$ 表示发生在用户态，$ID$ 区分指令取指与数据访问，$PK$ 表示保护键违例。据此可判定：$P=1, W=1$ 且映射为 PFN_WRITE_PROTECT 私有 → COW；$U=1, P=0$ 且无 VMA 覆盖 → 非法访问。

缺页的代价可用摊还模型描述。设缺页服务时间为 $T_{pf}$（主缺页含磁盘 I/O 约 $10^6$–$10^7$ ns，次缺页仅分配页约 $10^2$–$10^3$ ns），每 $n$ 次访问发生一次缺页，则平均访问时间：

$$ T_{avg} = T_{tlb} + \frac{T_{pf}}{n} $$

## 四、代码实现
```c
#include <signal.h>
#include <stdio.h>

int main(void) {
    int *p = NULL;
    *p = 1;          /* 用户态写地址 0 -> #PF，EC 含 U 位 -> SIGSEGV */
    return 0;
}
```

```c
/* 除零：x86 的 #DE 映射为 SIGFPE；注意有符号溢出的 INT_MIN / -1 在
 * x86 上同样触发除法异常，而 C 标准视其为未定义行为。 */
int x = 1 / 0;

/* 对 mmap 只读区域写：页表项 present，W=1，U=1 -> COW 或 SIGSEGV */
char *ro = mmap(NULL, 4096, PROT_READ, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
ro[0] = 'x';         /* 匿名私有页可写保护时走 do_wp_page，成功 */
```

内核在**用户态之外**访问用户地址时必须用异常表修正，而不是直接 oops：

```c
/* 概念性伪码：copy_from_user 通过 _ASM_EXTABLE 登记修正地址，
 * 若访问期间发生 #PF，内核跳转到修正点并返回未拷贝字节数。 */
unsigned long not_copied = _copy_from_user(dst, src, n);
if (not_copied) return -EFAULT;   /* 不 panic，而是向上返回错误 */
```

内核态缺页若无法修复（如访问不属于任何内核映射的地址），内核打印 oops 并终止当前任务；若发生在中断上下文或持有关键锁，则升级为 panic。

## 五、与其他技术对比
| 维度 | 硬件异常 | 硬件中断 | 用户态信号 | 系统调用 |
| --- | --- | --- | --- | --- |
| 时序关系 | 与当前指令同步 | 与指令流异步 | 多为异步（同步信号除外） | 由指令显式触发 |
| 入口 | IDT（异常门） | IDT（中断门） | 由异常/中断路径构造 | `syscall` 指令 |
| 是否可屏蔽 | 一般不可（`NMI` 更不可） | 可（`cli`/`IF`） | 可（除 `SIGKILL`/`SIGSTOP`） | 不适用 |
| 传递信息 | 异常号 + 错误码 + CR2 | 中断向量 | `siginfo_t`（含 `si_addr`） | 寄存器参数 |
| 内核处置 | 修复重试／投递信号／panic | 驱动处理或唤醒 | 执行处理函数或默认动作 | 执行系统调用体 |

`#PF` 与 `SIGSEGV` 的关系是「硬件首跳 → 内核裁决 → 软件通知」：前者是机制，后者是策略。理解这层映射是调试段错误的关键——`si_addr` 往往直接等于出错的虚拟地址，`si_code` 区分 `SEGV_MAPERR`（地址无映射）与 `SEGV_ACCERR`（有映射但权限不符）。

## 六、常见误区
- **以为 `SIGSEGV` 只来自空指针**：任何越权地址都可触发，包括野指针、栈溢出踩到 guard page、对只读映射写入、以及内核 `SMAP` 保护的越界访问。
- **以为所有故障都能重试返回**：`abort` 类异常（`#DF`、`#MC`）不会返回；`#GP` 在处理不当后同样演变为终止。
- **以为用户态能捕获一切**：内核态违例通常直接 oops/panic；`SIGKILL`、`SIGSTOP` 类的终止也不经用户处理。
- **以为缺页一定要读磁盘**：匿名页首次触碰、COW 复制都属「次缺页」（minor fault），`/proc/<pid>/stat` 中的 `maj_flt` 与 `min_flt` 分别计数两者，性能分析必须区分。
- **以为 `#PF` 发生时栈一定可用**：内核栈溢出或栈上破坏会导致二次缺页并最终 `#DF` 后三重故障（triple fault），表现为机器复位——这也是为何需要独立的内核栈与 `IST`（中断栈表）。

## 八、面试题
1. **fault 与 trap 的区别？**
   要点：fault 的返回地址指向引发异常的指令，修复后可重试（`#PF`）；trap 返回地址指向下一条指令（`int3` 断点、`#OF`）。
2. **`#PF` 错误码如何解读？**
   要点：`P` 判定是否存在页表项；`W` 判定读写；`U` 判定特权级；`RSVD`/`ID`/`PK` 为扩展位。`U=1, P=0` 且无 VMA 覆盖基本等同于非法地址。
3. **一次完整的匿名页首次写入经历哪些步骤？**
   要点：TLB miss → 页表遍历 → P=0 → `#PF` → `do_page_fault` 校验 VMA 与权限 → `do_anonymous_page` 分配零页并写页表 → 返回用户态重试指令 → TLB 填充。
4. **为什么内核访问用户指针需要异常表？**
   要点：用户可能传入非法地址，若无修正机制，缺页会走内核 oops 路径导致进程甚至系统崩溃；异常表把 `#PF` 转为返回 `-EFAULT`。
5. **什么是 `userfaultfd`，它改变了什么？**
   要点：把缺页事件导出到用户态处理（用于 GC、检查点、迁移），使内核缺页路径的一部分策略可由用户实现，代价是必须处理死锁、递归缺页与对非 VMA 地址的限制。

## 九、演进与趋势
硬件侧，机器检查架构（MCA）与 `#MC` 强化了内存/缓存错误的隔离与上报，配合 `EDAC` 子系统实现可纠正错误的计数与不可纠正错误的隔离；虚拟化侧，EPT/NPT 使二级页表缺页成为常态，云计算因此引入大页、`KSM`、以及缺页统计的可观测性工具。内核侧，`userfaultfd` 把缺页策略部分下放到用户态，成为 JVM/Go/CRIU 等运行时的基础设施；`folio` 改造统一了页缓存与匿名页的处理路径，使缺页逻辑不再需要区分尾页。此外，`madvise`/`MADV_POPULATE`、`MAP_POPULATE` 允许应用主动预缺页以规避抖动。所有这些都建立在同一套硬件异常机制上，其语义边界（fault/trap/abort）自保护模式以来基本稳定。

## 十、小结
硬件异常是同步的「指令级中断」：IDT 负责分派，错误码与 CR2 负责携带原因，内核负责分类处置。缺页处理把这一机制转化为按需分页、写时复制、换页与 NUMA 迁移的统一入口，是保护模式与虚拟内存的硬件基石。掌握 fault/trap/abort 的差别、`#PF` 错误码语义与主/次缺页的区分，是读懂崩溃现场与做内存性能分析的前提。
