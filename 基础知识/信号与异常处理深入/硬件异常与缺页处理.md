# 硬件异常与缺页处理

> 对应 Bryant & O'Hallaron《CSAPP》第 8 章异常与 Bovet & Cesati《Understanding the Linux Kernel》第 4/9 章。

## 一、背景与挑战
CPU 执行遇除零、非法指令、页保护违例等会触发"异常"——同步、由当前指令引起，区别于异步中断。内核异常分发器据异常号处理，错误或致命异常向进程发信号。

## 二、核心原理
x86 异常分故障（fault，可重试如 #PF）、陷阱（trap，如 int3 调试）、终止（abort，如硬件错）。#PF 是典型故障：保存现场、查原因，缺页则分配页重试；若访问非法地址则向进程发 SIGSEGV 终止。

## 三、形式化与数学基础
异常分类：
$$type = \begin{cases} fault & \text{返回并重试原指令（#PF）}\\ trap & \text{返回下一条（断点）}\\ abort & \text{不返回（致命）}\end{cases}$$
页故障错误码 $EC$ 编码：P（存在位）、W/R、U/S，决定是否 COW 或非法。

## 四、代码实现
```c
// 访问未映射地址触发 #PF -> 内核发 SIGSEGV
int *p = NULL;
*p = 1;            // 同步异常，进程收到 SIGSEGV 默认 core dump
// 除以零
int x = 1/0;       // SIGFPE
```

## 五、与其他技术对比
异常同步于指令流、中断异步于它；二者都经 IDT 进入内核。相较信号（软件层），异常是硬件层首跳，内核再转信号。

## 六、常见误区
误以为 SIGSEGV 都是空指针：任意越权地址均可。误以为异常可 `return` 重试所有：abort 不可恢复。误以为用户能捕获所有异常：特权级错误直接 panic。

## 七、与开源书/权威来源对应
CSAPP 8.1 异常分类；Bovet & Cesati 第 4 章异常与 9 章缺页。

## 八、面试题
问：fault 与 trap 区别？答：fault 重试原指令（缺页），trap 执行下一条（断点）。问：#PF 错误码含义？

## 九、演进与趋势
Machine Check 架构强化硬件错误隔离；用户态 #PF 经 userfaultfd 可定制（GC、迁移）。

## 十、小结
硬件异常是同步的"指令级中断"，内核据类型处理或转信号，是保护模式与虚拟内存的硬件基础。
