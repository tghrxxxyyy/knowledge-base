# 信号机制与信号处理函数

> 对应 Kerrisk《The Linux Programming Interface》第 20–21 章「信号」，以及 Bryant & O'Hallaron《Computer Systems: A Programmer's Perspective》第 8 章异常控制流。

## 一、背景与挑战
信号是内核或进程向进程投递的**异步软件中断**：`Ctrl-C` 产生 `SIGINT`，子进程退出产生 `SIGCHLD`，管道写端关闭产生 `SIGPIPE`，非法指令产生 `SIGILL`。它是 Unix 最早的进程间通信手段，也是唯一不依赖文件描述符的通知机制。
难点在于它同时是事件通知、异常上报通道与控制流劫持手段。处理函数在任意指令边界插入执行，破坏了顺序执行假设：它与被中断代码共享全局状态，却不能阻塞，也不能假定 `errno`、`malloc` 内部状态或 `stdio` 缓冲区处于一致状态。

## 二、核心原理
每个线程有两组信号状态：**阻塞集**（blocked，被屏蔽的信号不递送，只停留未决）与**未决集**（pending，已产生未递送）。生产者调用 `kill`/`raise`/`tgkill`/`pthread_kill`/`sigqueue`，内核路径为 `__send_sig_info` → `prepare_signal` → `__send_signal_locked`：标准信号只在 pending 位图置位（重复发送合并），实时信号分配 `sigqueue` 节点入队。
递送时机是**从内核态返回用户态之前**：调度器经 `exit_to_user_mode` 检查 `signal_pending`，若有未阻塞的未决信号，就在用户栈（或 `SA_ONSTACK` 指定的备用栈）上写入 `rt_sigframe`（含 `ucontext` 与 `siginfo_t`），并把 PC 指向处理函数入口；处理函数返回时跳到蹦床执行 `rt_sigreturn` 恢复上下文。这解释了信号栈帧为何不可无限嵌套，以及栈溢出场景为什么必须配 `sigaltstack`。
投递目标也是语义的一部分：`kill(pid, sig)` 是进程级信号，内核挑一个未阻塞该信号的线程递送；`tgkill`/`pthread_kill` 是线程级信号，只投给指定线程；同步信号（`SIGSEGV` 等）总是投给触发的那个线程。

## 三、形式化与数学基础
递送条件：

$$ deliver(s) \iff s \in pending \;\land\; s \notin blocked $$

标准信号的 pending 是位图，因此合并语义为

$$ \left|pending_s\right| \le 1 \;\;(s \in [1,31]), \qquad \left|pending_s\right| \ge 0 \;\;(s \in \text{SIGRT}) $$

处理期间的临时屏蔽集为

$$ blocked_{eff}(s) = blocked \cup \{s\} \cup sa\_mask(s) $$

其中 $\{s\}$ 自动加入以防递归重入（除非 `SA_NODEFER`）。处理函数还必须满足 $errno_{after} = errno_{before}$，否则会污染被中断代码的错误判断。

## 四、代码实现
```c
#include <errno.h>
#include <signal.h>
#include <string.h>
#include <unistd.h>

static volatile sig_atomic_t got_sigint = 0;

static void handler(int sig) {
    int saved_errno = errno;            /* 必须保存，否则污染被中断代码 */
    (void)sig;
    got_sigint = 1;                     /* volatile sig_atomic_t，异步信号安全 */
    const char msg[] = "got SIGINT\n";
    ssize_t n = write(STDOUT_FILENO, msg, sizeof(msg) - 1);
    (void)n;                            /* 禁 printf/malloc，它们非异步信号安全 */
    errno = saved_errno;
}

int main(void) {
    struct sigaction sa;
    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;                    /* 不加 SA_RESTART，让 read 可被中断 */
    if (sigaction(SIGINT, &sa, NULL) == -1) return 1;

    for (;;) {
        char buf[128];
        ssize_t n = read(STDIN_FILENO, buf, sizeof(buf));
        if (n == -1 && errno == EINTR) {
            if (got_sigint) return 0;   /* 用标志位，不在处理器里做事 */
            continue;
        }
        if (n <= 0) break;
    }
    return 0;
}
```

自管道技巧把信号转成可被 `poll`/`epoll` 统一等待的字节流，是事件循环程序的标准做法：

```c
static int sigpipe[2];                          /* 预先 pipe() 并设为非阻塞 */
static void handler_pipe(int sig) {
    int saved = errno;
    unsigned char b = (unsigned char)sig;
    ssize_t n = write(sigpipe[1], &b, 1);        /* 唯一允许的 async-safe 动作 */
    (void)n;
    errno = saved;
}
```

| 维度 | 信号 | 管道/FIFO | 共享内存 | `eventfd` | `signalfd` |

与硬件中断相比，信号运行在进程上下文、可被屏蔽、处理函数是普通用户代码；与异常相比，信号多为异步，只有 `SIGSEGV`/`SIGFPE`/`SIGILL`/`SIGBUS`/`SIGTRAP` 属同步信号。信号的根本局限是**带宽极低且不保证排队**，只适合做通知，不适合传数据。

## 六、常见误区
- **以为处理函数里可以调用任意 libc 函数**：只有 POSIX 列出的 async-signal-safe 函数可用（`write`、`read`、`_exit`、`sigaction`、`kill` 等）；`printf`、`malloc`、`syslog` 都可能因内部锁被中断代码持有而死锁。
- **以为标准信号会排队**：不会。连发 10 个 `SIGUSR1` 只递送 1 次；需要计数语义必须用实时信号或自管道/`eventfd`。
- **以为 `signal()` 可移植**：其语义随实现变化（BSD 自动重启且不重置，System V 只生效一次），必须使用 `sigaction`。
- **忽略 `EINTR`**：未设置 `SA_RESTART` 时慢速系统调用以 `EINTR` 返回，忽略它会导致数据丢失或忙循环。
- **以为 `SIGKILL`/`SIGSTOP` 可以捕获或阻塞**：内核特判，不可捕获、不可忽略、不可阻塞。

## 八、面试题
1. **信号处理函数为什么不能用 `printf`？**
   要点：`printf` 走 `stdio` 缓冲与锁，非异步信号安全；若中断点正在 `printf` 内部持锁，重入会死锁或破坏缓冲区。应改用 `write`。
2. **`SIGKILL` 能捕获吗？为什么？**
   要点：不能。内核在 `prepare_signal` 阶段对 `SIGKILL`/`SIGSTOP` 特判，忽略用户注册与屏蔽，保证进程必然可被终止。
3. **同一标准信号连发 5 次，处理函数执行几次？**
   要点：通常 1 次——pending 是位图，合并为一次；若处理过程中又有到达则可能再执行一次，但绝不等价于 5 次。
4. **如何让信号与 `epoll` 事件循环共存？**
   要点：自管道或 `signalfd`/`eventfd` 把信号转成 fd 可读事件；处理器中只做 `write` 与置标志这类异步安全操作。
5. **`fork` 与 `exec` 后信号状态如何变化？**
   要点：`fork` 后子进程继承阻塞集与处理函数（pending 清空）；`exec` 后处理函数重置为默认动作，`SIG_IGN` 设置与阻塞集被保留。

## 九、演进与趋势
信号的处理复杂度推动了替代方案：`signalfd` 让事件循环用 `read` 同步收取信号，`eventfd`/`timerfd` 把事件与定时器统一成 fd，`pidfd_open`/`pidfd_send_signal` 用 fd 而非 pid 定位进程，消除了 pid 复用带来的 TOCTOU 竞态。语言运行时层面，Go 运行时接管全部信号（把 `SIGSEGV` 用于自身栈检查与抢占），Rust 生态倾向用 `signal_hook` 转成 channel。但「处理函数只做最小动作」与「只用异步信号安全函数」这两条纪律始终不变。

## 十、小结
信号是内核提供的异步软件中断：`pending` 与 `blocked` 决定递送时机，返回用户态前的检查与信号帧构造决定执行语义，`siginfo_t` 决定携带信息。四条最常踩的坑是：标准信号不排队、处理器只能调 async-signal-safe 函数、`errno` 必须保存恢复、`EINTR` 必须处理。掌握这些边界，是写出健壮 Unix 服务与理解 `signalfd`/`epoll` 事件模型的前提。
