# 同步信号与致命信号

> 对应 Bryant & O'Hallaron《CSAPP》第 8 章与 Kerrisk《The Linux Programming Interface》第 20 章。

## 一、背景与挑战
并非所有信号都异步：SIGSEGV、SIGFPE、SIGILL、SIGBUS 由进程自身某条指令同步触发，称为"同步信号"。它们默认终止并 core dump，理解其来源对调试崩溃至关重要。

## 二、核心原理
同步信号由 CPU 异常直接产生，递送给引发异常的线程（不可跨线程）。内核在异常路径构造 `siginfo` 含故障地址（si_addr）、错误码。若进程未捕获则执行默认动作（Core/ Term）。core 文件供 gdb 回溯。

## 三、形式化与数学基础
同步信号递送唯一目标：
$$target = current\_thread;\quad siginfo.si\_addr = fault\_va$$
默认动作集合 $A(s) \in \{Term, Core, Stop, Ign, Cont\}$。SIGSEGV/SIGBUS/SIGFPE/SIGILL 默认 $Core$。

## 四、代码实现
```c
// 注册处理可捕获同步信号以记录现场（但须谨慎恢复）
struct sigaction sa;
sa.sa_sigaction = segv_handler;
sa.sa_flags = SA_SIGINFO;
sigaction(SIGSEGV, &sa, NULL);
// 触发：访问只读映射 -> SIGSEGV si_addr 即该地址
```

## 五、与其他技术对比
同步信号不可阻塞忽略（SIGKILL/SIGSTOP 也不可），异步信号可屏蔽排队。相较普通 IPC，同步信号携带故障地址。相较 try/catch，信号无栈展开、处理难恢复。

## 六、常见误区
误以为 SIGSEGV 可安全恢复继续：除非修复映射，否则重试仍崩。误以为捕获就能忽略：部分硬件状态不可恢复。误以为 core 总生成：受 ulimit -c 与 setrlimit 限制。

## 七、与开源书/权威来源对应
CSAPP 8.5 异常→信号映射；Kerrisk 第 20 章默认动作表与 siginfo。

## 八、面试题
问：为什么 SIGSEGV 叫同步信号？答：由当前线程某指令触发，非外部异步。问：core 文件如何产生？

## 九、演进与趋势
`SIGSYS` 配合 seccomp 让用户态过滤系统调用；core 模式（pipe）支持即时上传分析。

## 十、小结
同步信号把硬件异常暴露为进程级通知，携带精确故障地址，是崩溃诊断的关键信息源。
