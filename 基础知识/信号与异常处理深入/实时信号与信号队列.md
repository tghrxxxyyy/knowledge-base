# 实时信号与信号队列

> 对应 Kerrisk《The Linux Programming Interface》第 22 章实时信号与 Bryant & O'Hallaron《CSAPP》第 8 章。

## 一、背景与挑战
标准信号（1-31）不排队、易丢失、无优先级，难以可靠传递带数据的事件。实时信号（SIGRTMIN..SIGRTMAX）提供可靠排队、有序递送与附带数据（sigval），适合高可靠通知。

## 二、核心原理
实时信号若被阻塞，多个实例进入内核队列（per-signal 排队），解除阻塞后按发送顺序逐个递送，同优先级内 FIFO。用 `sigqueue` 发送可附带 `sigval`（整型或指针）。`SA_SIGINFO` 处理函数通过 `siginfo_t->si_value` 取数据。

## 三、形式化与数学基础
排队深度受 `RLIMIT_SIGPENDING` 限制 $Q$。递送顺序：
$$priority(SIGRT_a) < priority(SIGRT_b) \Rightarrow a\;先$$
同优先级 FIFO。标准信号 $pending_s \in \{0,1\}$（无队列），实时信号可 $>1$。

## 四、代码实现
```c
union sigval v; v.sival_int = 42;
sigqueue(pid, SIGRTMIN+1, v);     // 可靠发送带数据
// 接收
sa.sa_sigaction = rt_handler; sa.sa_flags = SA_SIGINFO;
sigaction(SIGRTMIN+1, &sa, NULL);
// rt_handler 中 info->si_value.sival_int == 42
```

## 五、与其他技术对比
实时信号 vs 标准信号：可靠排队+数据；vs 管道/socketpair：信号更轻量但带宽低。相较 `eventfd`，实时信号携数据但开销大。

## 六、常见误区
误以为所有信号都排队：仅实时信号。误以为实时信号无限排队：受 RLIMIT_SIGPENDING。误以为 si_value 指针跨进程安全：需共享内存。

## 七、与开源书/权威来源对应
Kerrisk 第 22 章 sigqueue/SA_SIGINFO/排队语义；POSIX 实时扩展。

## 八、面试题
问：标准信号为何可能丢事件？答：不排队，多次发送仅置一位。问：实时信号如何带数据？

## 九、演进与趋势
`signalfd` 把实时信号事件化，配合 epoll 避免信号处理复杂；但高频场景实时信号仍适用。

## 十、小结
实时信号以可靠排队、有序与附数据弥补标准信号缺陷，是 POSIX 实时编程的可靠通知机制。
