# 缓存友好

> 对应 CPU 缓存层级（L1/L2/L3）与局部性原理。

## 一、背景与挑战
现代 CPU 与内存速度差距达百倍，缓存未命中会阻塞流水线。算法复杂度相同，缓存友好度不同可差数倍。

## 二、核心原理
- 时间局部性：刚访问的数据很可能再访问。
- 空间局部性：相邻数据很可能一起访问。
- 缓存行（cache line）通常 64 字节，一次加载一整行。
- 伪共享（false sharing）：多核修改同一缓存行不同字段导致反复失效。

## 三、形式化 / 数学基础
- 缓存命中率 $h = \frac{H}{H+M}$，$M$ 为未命中数。
- 平均访问时间 $AMAT = h\cdot t_{hit} + (1-h)\cdot t_{miss}$。
- 缓存映射：组相联度 $k$，每组 $k$ 行。
- 伪共享：两变量地址满足 $\lfloor a/64\rfloor = \lfloor b/64\rfloor$ 且被不同核写。

## 四、代码实现
```c
// 行优先遍历（缓存友好）vs 列优先（缓存不友好），NxN 矩阵
#define N 1024
int m[N][N];
long sum_row() {            // 顺序访问，友好
    long s=0;
    for(int i=0;i<N;i++) for(int j=0;j<N;j++) s+=m[i][j];
    return s;
}
// 解决伪共享：按缓存行对齐
struct alignas(64) Counter { long v; };
```

## 五、与其他技术对比
- 链表：缓存不友好（指针跳跃）；数组：连续友好。
- 哈希开放寻址：局部性好于链式（缓存）。
- 预取（prefetch）：软件提示缓解未命中但增加带宽压力。

## 六、常见误区
- 只看算法大 O 忽略常数（缓存常数巨大）。
- 忽视结构体字段顺序导致填充/伪共享。
- 过度预取反而挤占带宽。

## 九、演进与趋势
非一致内存（NUMA）与缓存协同；硬件预取增强；数据布局优化（DLO）自动化。

## 十、小结
缓存友好的核心是提升局部性、避免伪共享，常比微优化算法带来更大收益。
