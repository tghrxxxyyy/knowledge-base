# 内存对齐

> 对应数据对齐（alignment）与 ABI/硬件访问约束。

## 一、背景与挑战
CPU 通常要求特定类型按其对齐边界访问（如 8 字节类型在 8 倍数地址）。未对齐访问在某些架构会触发总线错误，或跨缓存行降低性能。

## 二、核心原理
- 对齐规则：类型大小 $s$ 的对象地址须为 $\text{align}(t) = s$（基本类型）的倍数。
- 结构体对齐：每个字段按自身对齐，整体大小向上取到最大字段对齐的倍数（含尾部填充）。
- 缓存行对齐（64B）用于消除伪共享。
- 重排字段（大→小）可减少填充浪费。

## 三、形式化 / 数学基础
- 地址约束：$addr \equiv 0 \pmod{\text{align}(t)}$。
- 结构体大小 $S = \text{round\_up}(\sum \text{size}_i + \text{pad}_i,\ \max_k \text{align}_k)$。
- 填充量 $P = S - \sum \text{size}_i$。
- 伪共享规避：字段地址模 64 不同。

## 四、代码实现
```c
#include <stdalign.h>
struct Bad  { char c; int i; double d; }; // 有填充
struct Good { double d; int i; char c; }; // 重排减填充
_Alignas(64) int hot[16];                 // 缓存行对齐
// 用 offsetof(struct Bad, i) 观察填充
```

## 五、与其他技术对比
- 压缩结构体（#pragma pack）：省内存但可能更慢/不合法于某些架构。
- 序列化字节流：跨平台需显式布局，避免依赖对齐。
- 对齐分配（aligned_alloc）：为 SIMD/大页准备。

## 六、常见误区
- 以为 sizeof 等于字段和（忽略填充）。
- 把结构体直接 memcpy 跨架构（对齐/端序差异）。
- 过度对齐浪费内存。

## 九、演进与趋势
Rust `#[repr(align)]`/packed 显式控制；zero-copy 解析依赖对齐假设。

## 十、小结
内存对齐影响正确性（总线错误）与性能（跨行/伪共享），结构体布局需刻意设计。
