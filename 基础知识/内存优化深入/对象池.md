# 对象池

> 对应对象池（object pool）模式与分配开销优化。

## 一、背景与挑战
高频分配/释放小对象会带来堆锁竞争、碎片与 GC 压力。对象池预先分配一批可复用对象，降低分配频率。

## 二、核心原理
- 预分配：启动时或低峰期批量 new 一批对象入空闲链表。
- 借还模式：acquire 取一个，release 归还而非 free。
- 线程本地池（TLS）减少跨线程锁。
- 上限控制：防止池无限膨胀（软上限 + 必要时真正释放）。

## 三、形式化 / 数学基础
- 分配速率 $\lambda_a$；池命中率 $h = 1 - \frac{\text{real\_alloc}}{N_{acquire}}$。
- 期望堆分配次数降到 $\approx \frac{N_{acquire}}{pool\_size}$（周转周期）。
- 内存上限 $M \le C_{pool} \times \text{obj\_size}$。
- 复用周转：$T_{turn} = \frac{\text{pool\_size}}{\lambda_a}$，需 $T_{turn} \ll$ 对象生命周期。

## 四、代码实现
```go
type Pool struct{ free chan *Buf }
func NewPool(n int) *Pool {
    p := &Pool{free: make(chan *Buf, n)}
    for i := 0; i < n; i++ { p.free <- &Buf{Data: make([]byte, 4096)} }
    return p
}
func (p *Pool) Get() *Buf { return <-p.free }
func (p *Pool) Put(b *Buf) { p.free <- b } // 复用而非 GC
```

## 五、与其他技术对比
- 直接 new/GC：简单但有压力；池：低延迟但需正确归还防泄漏。
- slab 分配器：内核级对象池，按类型定长。
- 线程栈分配：零开销但生命周期受限。

## 六、常见误区
- 忘记归还导致"池泄漏"（对象只借不还可观测量增长）。
- 池过大浪费内存；过小退化为频繁真实分配。
- 跨线程共享池引入锁反而更慢。
