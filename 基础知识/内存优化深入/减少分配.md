# 减少分配

> 对应降低堆分配频率的优化技术集合。

## 一、背景与挑战
分配器本身有锁与元数据开销；GC 语言分配越多回收越频繁。减少分配能直接降低延迟毛刺与 CPU 占用。

## 二、核心原理
- 栈分配优先：短生命周期对象放栈，自动回收零成本。
- 复用缓冲区：读写用固定 buf 而非每次 new。
- 批量处理：一次分配批量元素（slice reserve）。
- 零拷贝：视图/切片替代复制（string view、slice）。
- 逃逸分析：编译器把可证明的堆对象降到栈。

## 三、形式化 / 数学基础
- 分配次数 $A$；优化目标 $\min A$ 且 $\frac{A_{heap}}{A_{total}} \to 0$。
- GC 工作量与存活集 $L$ 及分配速率相关：回收成本 $\propto \frac{\lambda_a}{\text{throughput}}$。
- 逃逸分析条件：对象地址不逃出函数作用域。
-  amortized 分配：$C = \frac{\text{alloc\_cost}}{N}$ 随批量 $N$ 下降。

## 四、代码实现
```go
// 预分配容量，避免 append 反复增长分配
func build(n int) []int {
    out := make([]int, 0, n)   // reserve
    for i := 0; i < n; i++ { out = append(out, i) }
    return out
}
// 复用 buffer
var buf [4096]byte
n, _ := io.ReadFull(r, buf[:])
```

## 五、与其他技术对比
- 对象池：复用同类对象；减少分配：从设计上少创建。
- 值类型 vs 引用类型：C#/Go 值类型减少堆压力。
- 写时复制容器：共享底层减少复制分配。

## 六、常见误区
- 过早 reserve 大容量浪费内存。
- 把长生命周期对象误放栈（返回局部地址）。
- 忽视接口装箱（interface{}）带来的隐式分配。

## 九、演进与趋势
编译器逃逸分析增强；Arena 分配器（Rust bumpalo、C++ 标准提案）批量回收。

## 十、小结
减少分配靠栈分配、复用、批量与零拷贝，从设计上削减分配器与 GC 负担。
