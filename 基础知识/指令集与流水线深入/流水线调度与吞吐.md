# 流水线调度与吞吐

> 对应 Hennessy & Patterson 第3章；CSAPP 中文笔记 https://github.com/Hansimov/csapp 。

## 一、背景与挑战

即便有转发，RAW 尤其 load-use 冒险仍插入气泡；调度（静态/动态）重新排列指令以填满空泡、提升吞吐。

## 二、核心原理

静态调度（编译器）：指令重排、填充无关指令、循环展开。动态调度：记分牌(Scoreboard)与 Tomasulo 让无依赖指令越过阻塞指令执行（乱序），见 SUB3。

## 三、形式化 / 数学基础

考虑 $m$ 拍延迟操作，间隔 $k$ 拍再发同类型：

$$Stall = \max(0, m - k)$$

平均 IPC 受限于关键路径长度与资源数：

$$IPC \le \frac{Depth_{pipeline}}{CriticalPathCycles}$$

## 四、代码实现

```c
// 编译器调度前：load 后立即用，1 拍停顿
r1 = mem[0]; r2 = r1 + 1;
// 调度后插入无关指令隐藏延迟
r1 = mem[0]; r3 = r4 * r5; r2 = r1 + 1;
```

## 五、与其他技术对比

- 静态调度不增加硬件但依赖编译器智能；动态调度硬件复杂但通用。
- 乱序执行本质是动态调度，需配合寄存器重命名。

## 六、常见误区

- 误以为调度可突破数据依赖：真依赖(RAW)无法消除，只能隐藏。
- 把吞吐提升等同于延迟下降。

## 八、面试题

- 调度能消除哪类依赖？答：只能重排隐藏 WAR/WAW，RAW 需靠转发/提前计算。
- 吞吐与延迟关系？答：调度提吞吐，单指令延迟不变。

## 九、演进与趋势

从编译器静态调度到硬件乱序窗口持续扩大，调度粒度细化到微操作。

## 十、小结

调度用并行填充气泡，是连接流水与乱序执行的桥梁。
