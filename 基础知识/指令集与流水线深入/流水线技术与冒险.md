# 流水线技术与冒险

> 对应 CSAPP 中文笔记 https://github.com/Hansimov/csapp 第4章；Hennessy & Patterson 附录 A。

## 一、背景与挑战

单条指令串行执行吞吐低。把执行拆为取指(IF)、译码(ID)、执行(EX)、访存(MEM)、写回(WB)多级，可让多条指令重叠，提升吞吐；但指令间依赖会引发停顿。

## 二、核心原理

经典 5 级流水：IF→ID→EX→MEM→WB。理想加速比约等于级数，受限于最慢段与冒险。冒险分三类：结构冒险（资源冲突）、数据冒险（读写同一寄存器）、控制冒险（分支改 PC）。

## 三、形式化 / 数学基础

吞吐：

$$Throughput = \frac{Instructions}{Time} \approx \frac{1}{CPI \times ClockCycleTime}$$

数据冒险可用转发（forwarding）消除部分停顿。RAW 依赖需检测：当 `ID` 段指令源寄存器等于前一条 `EX/MEM` 目的寄存器时转发。

## 四、代码实现

```c
// 数据冒险示例：下一条立刻用上一条结果
int a = load();   // EX 段算地址，MEM 取数
int b = a + 1;    // 若无转发，此处需停顿等待 a 写回
```

## 五、与其他技术对比

- 流水提升吞吐但不降低单条延迟；超标量才提高 ILP。
- 转发解决 RAW，但 load-use 冒险仍需 1 拍停顿。

## 六、常见误区

- 误以为流水一定加速：冒险频繁时气泡(bubble)抵消收益。
- 把控制冒险当成数据冒险处理。

## 八、面试题

- 五段流水三类冒险？答：结构/数据/控制；数据冒险用转发或停顿解决。
- 转发为什么不能消除所有冒险？答：load-use 数据尚未在 EX 末就绪。

## 九、演进与趋势

更深流水（10+ 级）提升频率但放大分支误罚；现代转向宽发射与乱序而非单纯加深。

## 十、小结

流水是吞吐优化的基础，冒险处理（转发、预测、调度）决定实际收益。
