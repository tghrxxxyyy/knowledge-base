# 指令级并行

> 对应 Hennessy & Patterson 第3章；CSAPP 中文笔记 https://github.com/Hansimov/csapp 。

## 一、背景与挑战

ILP 指程序内在可被同时执行的指令数。受限于真数据依赖、控制依赖与资源，硬件需尽量逼近理论 ILP。

## 二、核心原理

ILP 来源：循环内独立迭代、基本块内无依赖指令。限制因素：真依赖链长度、分支频率、Cache 缺失、窗口/端口数。Software 流水线、踪迹调度、推测执行都用尽 ILP。

## 三、形式化 / 数学基础

Amdahl 式限制：若可并行部分比例 $p$，最大加速：

$$S_{max} = \frac{1}{(1-p) + p/W}$$

$W$ 为可并行宽度。窗口大小 $R$ 决定能跨越多长依赖链挖掘并行：

$$ILP_{exploited} \le f(R, BranchAccuracy)$$

## 四、代码实现

```c
// 向量累加：迭代间独立，ILP 高
double s = 0;
for (int i = 0; i < N; i++)
    s += w[i] * x[i];   // 可被多端口 FMA 并行/流水线
```

## 五、与其他技术对比

- ILP 在通用代码常受限；线程级并行(TLP)与数据级并行(DLP/SIMD)互补。
- 乱序窗口越大，越能跨分支挖并行但功耗上升。

## 六、常见误区

- 误以为加宽发射就能线性提升：受限于依赖链与分支。
- 忽视 store/load 队列容量限制实际窗口。

## 八、面试题

- 限制 ILP 的因素？答：真依赖、控制依赖、Cache 缺失、结构资源。
- ILP 与 TLP 区别？答：指令级 vs 线程级并行。

## 九、演进与趋势

ILP 收益递减，算力增长更多来自 SIMD 与多核。

## 十、小结

ILP 是性能上限的理论量，微架构目标是在功耗预算内逼近它。
