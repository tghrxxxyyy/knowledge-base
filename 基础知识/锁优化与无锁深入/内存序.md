# 内存序

> 对应内存模型与内存序（memory ordering / happens-before）。

## 一、背景与挑战
编译器和 CPU 会重排指令以提升性能，多线程下可能导致一个线程的写入在另一线程看来乱序可见。内存序规定了原子/同步操作的可见性与顺序保证。

## 二、核心原理
- happens-before：若 A happens-before B，则 A 的效果对观察到 B 的线程可见。
- 顺序一致性（SC）：所有操作全局单一顺序（最强但最慢）。
- 松弛模型：relaxed/acquire/release/acq_rel/seq_cst 逐级加强。
- acquire（读）与 release（写）配对建立同步：release 前的写入对后续 acquire 可见。
- x86 为 TSO（强），ARM/POWER 为弱序，需显式屏障。

## 三、形式化 / 数学基础
- release 写 $W^{rel}$ 与 acquire 读 $R^{acq}$：若 $R^{acq}$ 读到 $W^{rel}$ 的值，则 $W^{rel}$ 之前的所有写对 $R^{acq}$ 之后可见（synchronizes-with）。
- relaxed：仅保证原子性，不保证顺序/可见性顺序。
- seq_cst：在所有线程间有单一全序，最贵。
- 数据竞争定义：两个未同步的并发访问其一为写 → 未定义行为。

## 四、代码实现
```cpp
#include <atomic>
std::atomic<bool> ready{false};
int data = 0;
// 写线程
data = 42;
ready.store(true, std::memory_order_release); // 释放
// 读线程
while (!ready.load(std::memory_order_acquire)); // 获取
// 此处 data==42 必然可见
```

## 五、与其他技术对比
- mutex：隐式获得 acquire/release 与全序，简单正确；原子+内存序：精细但易错。
- volatile（Java/C#）：Java volatile 有 happens-before 语义；C/C++ volatile 无线程同步语义（仅防编译器优化）。
- seq_cst vs acquire/release：性能差异在弱序架构显著。

## 六、常见误区
- 用 C/C++ volatile 做线程同步（错误）。
- 在弱序架构省略 acquire/release 导致读到旧值。
- 认为原子操作天然全局有序。

## 十、小结
