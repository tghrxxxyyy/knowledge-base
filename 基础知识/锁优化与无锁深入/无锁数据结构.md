# 无锁数据结构

> 对应 lock-free 数据结构（基于原子操作的并发结构）。

## 一、背景与挑战
锁带来竞争、优先级反转与死锁风险。无锁（lock-free）结构保证系统级进展，避免单个线程阻塞整体，适合高并发低延迟。

## 二、核心原理
- Lock-free：无限执行中至少有一线程持续前进（无死锁/活锁全局停顿）。
- Wait-free：每个线程在有限步内完成（更强）。
- 常用原语：CAS、 FAA（fetch-and-add）、DCAS。
- 技巧：copy-on-write、CAS 循环重试、 hazard pointer（安全回收）。

## 三、形式化 / 数学基础
- CAS 语义：$\text{CAS}(addr, exp, new) = (mem==exp\ ?\ (mem\leftarrow new, true)\ :\ false)$。
- 进展性层级：blocking > lock-free > wait-free（每级更强保证）。
- ABA 风险：值由 A→B→A，CAS 误判未变（见 CAS与ABA问题）。
- 无锁队列常用 Michael-Scott 算法（头尾指针 + CAS）。

## 四、代码实现
```java
// 无锁栈（Treiber stack）片段
AtomicReference<Node> head = new AtomicReference<>();
void push(int v) {
    Node n = new Node(v);
    Node h;
    do { h = head.get(); n.next = h; }
    while (!head.compareAndSet(h, n));
}
```

## 五、与其他技术对比
- 互斥结构：易证明正确但竞争受限；无锁：高并发但难验证。
- 读写锁 + 不可变快照：有时比无锁更简单达成无阻塞读。
- 事务内存：以语言/硬件抽象替代手写无锁。

## 六、常见误区
- 误以为无锁等于无等待（lock-free 不保证单线程有界步数）。
- 忽略内存回收导致 use-after-free（需 hazard pointer/epoch）。
- 忽视 ABA 破坏正确性。

## 九、演进与趋势
硬件事务内存补充无锁；语言级原子类型与 epoch GC 简化实现。

## 十、小结
无锁结构用 CAS 循环取得系统级进展，但需处理 ABA 与内存回收，正确性验证成本高。
