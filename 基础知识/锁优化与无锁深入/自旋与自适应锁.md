# 自旋与自适应锁

> 对应自旋锁（spinlock）与自适应自旋（adaptive spinning）。

## 一、背景与挑战
线程获取不到锁时，若临界区极短，直接挂起（上下文切换）成本可能高于短暂忙等。自旋在锁很快释放时更划算。

## 二、核心原理
- 自旋锁：循环 CAS 忙等，不睡眠，适合UP核短临界区/中断上下文。
- 代价：空转浪费 CPU，长临界区下灾难。
- 自适应自旋：根据历史（该锁上一次等待者是否很快获释）动态决定是否自旋及自旋时长。
- 用户态常结合 futex：先自旋若干次，失败再内核等待。

## 三、形式化 / 数学基础
- 自旋期望成本 $C_{spin} = T_{crit\_avg} \times \text{cycles}$ 当 $T_{crit} \ll T_{switch}$。
- 上下文切换成本 $C_{switch} \approx 1\sim 10\ \mu s$（数万周期）。
- 自适应决策：若 $P(\text{release soon}) > \frac{C_{switch}}{C_{spin\_budget}}$ 则自旋。
- 退避：指数退避 $t_k = \min(t_{max}, t_0 \cdot 2^k)$。

## 四、代码实现
```c
// 简单自旋锁（x86）
void spin_lock(volatile int *l) {
    while (__sync_lock_test_and_set(l, 1)) {
        while (*l) cpu_relax();   // 让出流水线
    }
}
// 自适应：失败一定次数后 futex_wait
if (!atomic_cas(&l, 0, 1)) {
    for (int i=0;i<SPIN_LIMIT && l;i++) cpu_relax();
    if (l) futex_wait(&l, 1);
}
```

## 五、与其他技术对比
- 互斥锁（睡眠）：适合长临界区；自旋：短临界区。
- 自旋 + futex：兼顾两者，生产常用。
- ticket lock vs MCS lock：公平性与缓存友好度差异（MCS 减少伪共享）。

## 六、常见误区
- 单核 CPU 自旋等于死等（应让出）。
- 长临界区用自旋浪费 CPU。
- 忽视 NUMA 下远程原子操作的跨节点代价。

## 九、演进与趋势
MCS/CLH 排队锁降低多核伪共享；硬件 monitor/mwait 优化忙等。

## 十、小结
自旋在短临界区比睡眠划算，自适应与 futex 结合使其在生产中兼顾延迟与 CPU 占用。
