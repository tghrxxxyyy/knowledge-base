# 锁竞争

> 对应互斥锁竞争（lock contention）与临界区优化。

## 一、背景与挑战
多线程共享可变状态时需加锁保证原子性与可见性。竞争激烈的锁成为吞吐瓶颈，表现为线程在锁上自旋/阻塞、CPU 空转或上下文切换。

## 二、核心原理
- 临界区越短越好，把 I/O、计算移出锁外。
- 缩小锁粒度：分段锁（striping）、读写锁分离读写。
- 锁粗化/细化权衡：过细增加开销，过粗增加竞争。
- 无锁化：用原子操作替代互斥（见无锁数据结构）。

## 三、形式化 / 数学基础
- 临界区占用比 $c = \frac{T_{crit}}{T_{total}}$。
- 理想并行加速受锁限制（类似阿姆达尔）：$S \le \frac{1}{c + (1-c)/n}$。
- 等待队列长度 $Q$ 在竞争均衡时正比于到达率 $\lambda$ 与持锁时间。
- 吞吐近似 $R \approx \frac{1}{T_{crit} + T_{wait}}$。

## 四、代码实现
```java
// 锁粒度细化：用分段锁替代全局锁
class StripedCounter {
    private final AtomicLong[] parts = new AtomicLong[16];
    long get(int key) { return parts[key & 15].incrementAndGet(); }
}
// 把耗时操作移出 synchronized
synchronized(lock) { id = next++; }
doExpensiveWork(id);   // 锁外执行
```

## 五、与其他技术对比
- 粗粒度锁：简单但竞争大；细粒度：高并发但易死锁/复杂。
- 互斥锁 vs 原子：原子适合小操作，锁适合复杂不变式。
- 乐观锁（CAS 重试）vs 悲观锁。

## 六、常见误区
- 在锁内做 I/O 或系统调用。
- 用大锁保护本可无锁的只读数据。
- 误以为加锁一定慢（短临界区开销极小）。

## 十、小结
锁竞争优化的核心是缩短临界区、细化粒度、移出重操作，必要时转向原子/无锁。
