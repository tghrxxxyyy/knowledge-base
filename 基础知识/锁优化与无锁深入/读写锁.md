# 读写锁

> 对应读写锁（ReadWriteLock / RWMutex）的读者共享与写者独占。

## 一、背景与挑战
读多写少场景用互斥锁会让并发读互相阻塞。读写锁允许多读者同时进入，仅写者独占，提升读吞吐。

## 二、核心原理
- 读者加读锁（共享），写者加写锁（独占）。
- 写优先 vs 读优先：防写饥饿需写优先/公平策略。
- 升级/降级：持有读锁时获取写锁（升级有死锁风险，常需先释放）。
- 适用：缓存、配置、元数据等读多写少。

## 三、形式化 / 数学基础
- 读者数 $R$、写者数 $W$，不变式：$R>0 \Rightarrow W=0$ 且 $W>0 \Rightarrow R=0$。
- 吞吐量（读主导）：$R_{read} \approx \frac{R_{calls}}{T_{read}}$ 并发放大。
- 写等待时间随读者持续占用而增长（饥饿）。
- 锁状态可用单整数编码：写标志位 + 读者计数。

## 四、代码实现
```go
var mu sync.RWMutex
var cache = map[string]string{}

func Get(k string) string {
    mu.RLock(); defer mu.RUnlock()   // 共享读
    return cache[k]
}
func Set(k, v string) {
    mu.Lock(); defer mu.Unlock()     // 独占写
    cache[k] = v
}
```

## 五、与其他技术对比
- 互斥锁：任何访问都独占，简单但读吞吐低。
- 读写锁：读并发高，但写可能饥饿、实现更复杂。
- 原子指针 + 不可变快照：无锁读（见无锁数据结构）。

## 六、常见误区
- 写少但每次持有长，导致读被长期排除。
- 读锁内尝试升级写锁导致死锁。
- 以为读写锁总比互斥快（写频繁时更慢）。

## 九、演进与趋势
StampedLock（乐观读）、seqlock（无锁读+写独占）进一步优化读路径。

## 十、小结
读写锁在读多写少时显著提升并发，但需防范写饥饿并谨慎处理锁升级。
