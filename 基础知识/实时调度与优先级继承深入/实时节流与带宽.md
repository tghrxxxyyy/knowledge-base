> 对应 Linux 内核 Documentation（scheduler/sched-rt.rst 的 rt_bandwidth）与 Silberschatz《Operating System Concepts》。

## 一、背景与挑战
若实时任务（尤其 FIFO）占满 CPU，CFS 与普通任务会被饿死，甚至看门狗/ shell 无法运行，系统失去可管理性。挑战是在保留实时能力的同时，对实时带宽设上限，留出口给非实时任务。

## 二、核心原理
RT 带宽控制（rt_bandwidth）为每个 CPU 的实时运行设配额：rt_runtime（如默认 0.95s）每 rt_period（如 1s）内允许实时任务占用的 CPU 时间。超限时实时任务被 throttle（停跑），把 CPU 让给非实时。全局由 /proc/sys/kernel/sched_rt_runtime_us 与 sched_rt_period_us 控制；cgroup 内也可单独设。

## 三、形式化与数学基础
设周期 P = rt_period_us，配额 R = rt_runtime_us。实时带宽占比：
```
B = R / P      (默认 0.95)
```
约束：B < 1，保证至少 (1-B) 的 CPU 留给非实时。运行统计：
```
if (rt_rq->rt_time > R)  throttle(rt_rq);     // 本周期超限
on period boundary:      rt_rq->rt_time = 0;  // 重置
```
throttle 期间实时任务不可运行，直到下一周期或手动 unthrottle。

## 四、代码实现
```c
// kernel/sched/rt.c（简化）
static void update_curr_rt(struct rq *rq)
{
    rt_rq->rt_time += delta_exec;
    if (sched_rt_runtime_exceeded(rt_rq)) {
        rt_rq->throttled = 1;
        resched_curr(rq);          // 切走实时任务
    }
}
static void do_sched_rt_period_timer(struct rt_bandwidth *rt_b)
{
    for_each_cpu(cpu) {
        rt_rq->rt_time = 0;        // 周期重置
        if (rt_rq->throttled)
            unthrottle_rt_rq(rt_rq);
    }
}
```

## 五、与其他技术对比
- 无节流：实时任务可 100% 占 CPU，饿死其他。
- RT 带宽节流：留出口，牺牲少量实时占用来保系统可管理。
- CFS 配额（cpu.max）：针对普通任务的另一种带宽限制。

## 六、常见误区
- 误区：实时任务永远不被限流。RT 带宽默认留 5% 给非实时，可配置。
- 误区：throttle 等于杀死任务。只是暂停到下一周期，任务仍在运行队列。

## 九、演进与趋势
与 cgroup v2 的 cpu.max.rt 结合，支持容器级实时带宽隔离；在 PREEMPT_RT 下与 deadline 调度协同，避免 RT 饿死 DL。

## 十、小结
RT 带宽节流以「每周期配额」给实时任务设上限，在保留实时能力的同时保障系统不被实时任务完全饿死。
