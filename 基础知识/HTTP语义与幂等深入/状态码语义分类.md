# 状态码语义分类

> 对应 RFC 9110《HTTP Semantics》第 15 节状态码定义与 Kurose & Ross《Computer Networking》应用层章节。

## 一、背景与挑战

HTTP 状态码以三位数字传达响应类别。错误排查、重试策略、缓存行为都依赖对状态码语义的准确理解。误用状态码会带来连锁问题：客户端对本不该重试的 4xx 疯狂重试，或把临时错误缓存成永久结果。

因此需要一套清晰的分类视角：首位数字决定类别，类别决定客户端的默认决策。

## 二、核心原理

按首位数字分五类：

- **1xx 信息**：如 `100 Continue`、`103 Early Hints`，请求已收到，继续处理。
- **2xx 成功**：`200 OK`、`201 Created`、`204 No Content`、`206 Partial Content`。
- **3xx 重定向**：`301` 永久、`308` 永久且保持方法；`302`、`307` 临时，其中 `307`/`308` 严格保持原方法，`301`/`302` 历史上可能被改为 GET。
- **4xx 客户端错误**：`400`、`401`、`403`、`404`、`409`、`410`、`429`。
- **5xx 服务器错误**：`500`、`502`、`503`、`504`。

只有幂等方法在 5xx 与 `408`/`429` 上才可安全重试。

## 三、形式化与数学基础

设状态码 $c$，类别由首位数字 $d = \lfloor c/100 \rfloor$ 决定。客户端决策可建模为「可重试性函数」：

$$R(c, m) = \big[(d = 5)\big] \lor \big[(c \in \{408, 429\}) \land (m \in Idempotent)\big]$$

其中 $m$ 为请求方法，$Idempotent = \{GET, HEAD, PUT, DELETE, OPTIONS, TRACE\}$。重定向的方法保持性可表示为：

$$preserve(m, c) = \begin{cases} \text{true} & c \in \{307, 308\} \\ \text{maybe} & c \in \{301, 302\} \end{cases}$$

缓存性则与类别及头部共同决定，3xx 与 5xx 在特定条件下可被缓存（见 Cache-Control）。

## 四、代码实现

一个按状态码与方法决定是否重试的客户端策略。

```python
IDEMPOTENT = {"GET", "HEAD", "PUT", "DELETE", "OPTIONS", "TRACE"}

def should_retry(code: int, method: str) -> bool:
    d = code // 100
    if d == 5:                       # 服务端错误：默认可重试（幂等方法更安全）
        return True
    if code in (408, 429):           # 请求超时 / 限流：需退避后重试
        return method in IDEMPOTENT
    return False

def backoff_delay(attempt: int, base: float = 0.1, cap: float = 10.0) -> float:
    # 指数退避，配合抖动避免重试风暴
    import random
    return min(cap, base * (2 ** attempt)) * (0.5 + random.random())
```

对 `429`，应优先读取 `Retry-After` 头；对 `503` 同样常带该头，指示何时再试。

## 六、常见误区

- 误区一：302 与 307 等价。302 历史上可能把方法改为 GET，307/308 严格保持原方法。
- 误区二：4xx 都不重试。408 与 429 属于「暂时性」客户端错误，应退避重试。
- 误区三：500 一定是本服务 bug。可能是上游 502 透传或依赖故障。
- 误区四：502 与 504 相同。502 是网关收到无效响应，504 是网关等待上游超时。
- 误区五：301 一定永久且安全。永久重定向会被缓存，配置错误难以撤销，需谨慎使用。

## 八、面试题

1. 301 与 308 的区别？答：308 是永久重定向且严格保持方法与请求体，301 历史上可能改方法。
2. 哪些状态码可重试？答：5xx 一般可重试，408/429 在幂等方法下可退避重试。
3. 429 的含义与应对？答：请求过多（限流），应读取 Retry-After 并退避。
4. 502 与 504 的区别？答：502 是上游返回无效响应，504 是等待上游响应超时。

## 九、演进与趋势

RFC 9110 统一了早期分散的 723x 系列，语义总体稳定。`103 Early Hints` 等新码用于优化加载；`428 Precondition Required`、`451`（法律原因不可用）等用于特定场景。错误语义的演进趋于稳定与规范化。

## 十、小结

状态码首位即类别，类别决定客户端的默认决策。掌握 3xx 的方法保持差异、4xx/5xx 的可重试边界，以及 502/504 的网关语义，是正确实现客户端容错的前提。
