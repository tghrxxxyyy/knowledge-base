# 状态码语义分类

> 对应 RFC 9110 第 15 节状态码定义与 xiaolincoder/hello-http 的状态码速查。

## 一、背景与挑战
HTTP 状态码以三位数字传达响应类别。错误排查、重试策略、缓存行为都依赖对状态码语义的准确理解，误用状态码会导致客户端错误重试或缓存污染。

## 二、核心原理
1xx 信息（如 100 Continue）；2xx 成功（200/201/204/206）；3xx 重定向（301 永久、302/307/308 临时，308 保持方法）；4xx 客户端错误（400/401/403/404/409/410/429）；5xx 服务器错误（500/502/503/504）。其中 301/308 可被缓存与永久重定向，302/307 为临时。

## 三、形式化与数学基础
状态码首位 d ∈ {1..5} 决定类别，客户端据此决策：d=2 提交成功；d=3 需跟随 Location；d=4 通常不可重试（除 408/429 可退避重试）；d=5 可安全重试（幂等方法）。可重试性函数 R(code, method) = (d==5) or (code in {408,429} and method idempotent)。

## 四、代码实现
```python
def should_retry(code, method):
    if 500 <= code < 600: return True
    if code in (408, 429): return method in IDEMPOTENT
    return False
```

## 五、与其他技术对比
gRPC 用独立的状态码（如 UNAVAILABLE、NOT_FOUND）且常带错误详情；WebSocket 关闭帧用 1000/1001 等应用码，与 HTTP 状态码体系不同但概念相似。

## 六、常见误区
误区一：302 与 307 等价——302 历史上可能改方法为 GET，307/308 严格保持原方法。误区二：4xx 都不重试——429/408 应退避重试。误区三：500 一定是服务端 bug——可能是上游 502 透传。

## 七、与开源书/权威来源对应
RFC 9110 第 15 节权威定义；xiaolincoder/hello-http 提供分类表；Kurose & Ross 介绍 HTTP 事务与响应。

## 八、面试题
301 与 308 区别？哪些状态码可重试？429 含义？502 与 504 区别？

## 九、演进与趋势
RFC 9110 统一了早期分散的 723x 系列；一些新状态码（如 103 Early Hints）被引入以优化加载，错误语义总体稳定。

## 十、小结
状态码首位即类别，理解 3xx 方法保持差异与 4xx/5xx 的可重试边界，是正确实现客户端容错的前提。
