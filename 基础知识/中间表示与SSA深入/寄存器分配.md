# 寄存器分配

> 对应 龙书 第 13 章 与 Appel 第 11 章（图着色）。

## 一、背景与挑战
把无限 SSA 名/临时变量映射到有限物理寄存器，溢出 (spill) 到栈。挑战：冲突图构建、着色近似、溢出代价最小化。

## 二、核心原理
干涉图 (interference graph)：两变量生命期重叠则连边，相邻不可同寄存器。图着色：相邻不同色。Chaitin 法：删低度节点、递归着色、度 > K 则 spill。

## 三、形式化 / 数学基础
若 $live(a)\cap live(b)\neq\varnothing$ 则 $a,b$ 干涉（边）。
着色数 $\le K$（物理寄存器数）。溢出代价 $\approx \text{use+def}$ 次数 / 生命期长度，优先 spill 低代价者。

## 四、代码实现
```python
def color(g, K, spill_cost):
    stack = []
    while g.nodes:
        n = min(g.nodes, key=lambda x: (len(g.adj[x]), -spill_cost[x]))
        if len(g.adj[n]) < K:
            stack.append(n); g.remove(n)
        else:
            spill(n)  # 溢出到内存
    for n in reversed(stack):
        g.assign_free_color(n, K)
```

## 五、与其他技术对比
- 图着色（Chaitin）：质量高、复杂。
- 线性扫描 (Linear Scan)：快、JIT 友好。
- 全局 vs 局部分配：JIT 常用局部/线性扫描换编译速度。

## 六、常见误区
1. 忽略 $\phi$ 相关变量必须同寄存器（coalescing 合并）。
2. 溢出代价估计错致抖动。
3. 调用约定寄存器未预着色致破坏。

## 十、小结
寄存器分配是图着色问题：干涉边不能同色，溢出是唯一退路；JIT 场景用线性扫描以编译速度为先。
