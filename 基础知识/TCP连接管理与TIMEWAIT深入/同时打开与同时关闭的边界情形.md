# 同时打开与同时关闭的边界情形

> 对应 RFC 793 (TCP) 第3.4节 simultaneous open / close。

## 一、背景与挑战
标准三次握手假设一端先发起。但两个对等端可能在同一时刻互相发送 SYN，或在已建立连接上几乎同时发起关闭。这些对称场景打破了「客户端/服务端」的假设，需要 TCP 状态机特殊处理，否则会建立两条半连接或丢失数据。

## 二、核心原理
同时打开时，双方都处于 SYN_SENT 并收到对方的 SYN（而非 SYN+ACK）。状态机迁移到 SYN_RCVD 再互发 ACK，最终建立单条连接，共消耗 4 个报文段（比普通握手多一个）。同时关闭时，双方都处于 ESTABLISHED 并发送 FIN，进入 FIN_WAIT_1，收到对方 FIN 后进入 CLOSING，待各自 ACK 到达后进入 TIME_WAIT。

## 三、形式化与数学基础
普通建连报文段数为 3，同时打开为 4：
$$ N_{seg}^{simopen} = 4 $$
同时关闭的状态迁移需双方各发送一个 FIN 与一个 ACK，且都需经历 TIME_WAIT 以保证迟到报文消散。

## 四、代码实现
同时打开在 Linux 中由 `tcp_rcv_synsent_state_process` 识别 SYN 而非 SYN+ACK 分支处理。示意判断：
```c
if (th->syn && !th->ack) {
    // 对端也是主动打开，进入 SYN_RCVD 并回 SYN+ACK
}
```

## 五、与其他技术对比
UDP 无连接自然无此概念；SCTP 通过四路握手与 cookie 原生支持双方同时发起关联，对同时打开更健壮。

## 六、常见误区
误区一是以为同时打开会建立两条连接，实际只建立一条，额外消耗一个报文段。误区二是以为同时关闭会跳过 TIME_WAIT，双方仍各自进入 TIME_WAIT。

## 七、与开源书/权威来源对应
RFC 793 图6与第3.4节给出同时打开/关闭的迁移；Kurose & Ross 习题中讨论该边界情形。

## 八、面试题
问：同时打开需要几次报文段？答：4 次，比标准三次握手多一次，因为双方各自发送一个 SYN 且互不以 SYN+ACK 回应。

## 九、演进与趋势
现代 P2P 与 NAT 穿透场景下同时打开更常见，TCP 同时打开结合 `SO_REUSEADDR` 可支持对等连接，但防火墙常拦截入向 SYN，实践中更多借助 UDP 打洞。

## 十、小结
同时打开与同时关闭是 TCP 状态机对称分支，分别用 4 段握手和双方 TIME_WAIT 保证正确性，理解它们有助于分析非常规连接建立失败。
