# 向量时钟冲突检测

> 对应 DeCandia et al. 2007（Dynamo 冲突检测）与 Parker et al. 1983（Detecting Conservation Violations，版本向量起源）。

## 一、背景与挑战
在并发复制（multi-master / leaderless）场景中，同一逻辑对象会被多个副本独立更新。系统需要知道：两个版本是「因果有序」（一方可安全取代另一方），还是「并发冲突」（二者都该保留并合并）。若把并发版本误判为有序而覆盖，就会静默丢写；若把有序版本误判为冲突，则制造无谓的合并负担。向量时钟把这一判定转化为偏序比较，是冲突检测的数学基础。

这个问题在「无主存储 + 客户端合并」架构里尤其关键：协调者没有全局视图，只能依赖版本附带的向量时钟在读取时「事后」判定。判定错了，要么丢写（覆盖并发），要么读放大（把本可合并的版本当冲突）。因此冲突检测的精确性直接决定数据正确性与性能，是复制系统的核心正确性保证。

另一种更彻底的思路是「让冲突不可能存在」：用 CRDT 的数据类型使并发更新天然可交换、可合并，从而无需在应用层检测冲突。但 CRDT 只适用于特定数据类型，对「任意对象」仍需向量时钟这类机制。二者是互补而非替代。

## 二、核心原理
冲突检测依赖支配（dominates）关系：
- $V_a$ dominates $V_b$：$\forall j: V_a[j] \ge V_b[j]$ 且至少一维严格大于。表示 a 因果包含 b，b 可被丢弃。
- $V_a$ 与 $V_b$ 互不 dominates：各自包含对方没有的更新，即并发冲突，应都被保留。
「互不 dominates」等价于「存在维度 i、j 使 $V_a[i]>V_b[i]$ 且 $V_b[j]>V_a[j]$」。实践中常先算「是否被支配」，再取反得到并发。多个版本时，需两两比较、保留极大元（不被任何其它版本支配者），被支配者一律丢弃。注意一个常见坑：不能只挑「最大分量」的版本，因为并发版本没有单一最大者。

「极大元集合」的求法可优化：先按「分量和」降序排序，再逐个与已保留的极大元比较，只保留不被支配者。这利用了一个事实：若某版本被支配，则支配它的版本分量和必然不小于它，因此排序后支配者先被处理，后续比较可尽早剪枝。

版本数量也需要控制：Dynamo 等系统会限制每个键保留的兄弟版本数（如最多 10 个），超出时按策略合并或丢弃最旧者。这避免了「冲突长期累积导致读放大」的工程问题。

## 三、形式化与数学基础
并发的判定式：
$$\text{concurrent}(A,B) \iff \neg(A \le B) \land \neg(B \le A)$$
其中 $A \le B \iff \forall j: A_j \le B_j$。当 concurrent 为真时，两版本不可比较，合并函数 $merge$ 必须同时考虑二者。等价地，向量时钟的可比性完整刻画了版本间的 happened-before，因此冲突检测的正确性等价于偏序比较的正确性。对 k 个版本，$O(k^2)$ 两两比较即可保留极大元集合；也可借助「已支配者不必再比」的剪枝加速，但正确性依赖于偏序的传递性。

偏序的三个性质在此都用到：自反性（$A \le A$ 恒成立）、反对称性（$A\le B \land B \le A \Rightarrow A = B$）、传递性（$A \le B \land B \le C \Rightarrow A \le C$）。传递性保证「若 $C$ 支配 $A$、$A$ 支配 $B$，则 $C$ 支配 $B$」，因此「只与极大元比较」不会漏掉被间接支配的版本。

极大元集合的性质：任意有限偏序集都有非空的极大元集合，且其中任意两个元素互不可比（否则有一个会被支配）。这保证了「保留极大元」的语义是清晰的——它们恰好是「互不冲突的最多可能并存版本」。

## 四、代码实现
```python
# 冲突检测：返回两版本是否并发
def concurrent(a, b):
    le_ab = all(a[j] <= b[j] for j in range(len(a)))
    le_ba = all(b[j] <= a[j] for j in range(len(a)))
    return not (le_ab or le_ba)

# 返回不被任何版本支配的极大元集合
def maximal_versions(versions):
    result = []
    for i, (vc, _) in enumerate(versions):
        dominated = any(dominates(versions[j][0], vc)
                        for j in range(len(versions)) if j != i)
        if not dominated:
            result.append(versions[i])
    return result

def dominates(a, b):
    return all(a[j] >= b[j] for j in range(len(a))) and \
           any(a[j] > b[j] for j in range(len(a)))
```

维度不足时按 0 补齐（保证不同长度的时钟可比）：

```python
def pad(vc, n):
    # 缺失维度视为 0：未参与过的进程计数为 0
    return list(vc) + [0] * (n - len(vc))

def concurrent_padded(a, b):
    n = max(len(a), len(b))
    return concurrent(pad(a, n), pad(b, n))
```

## 五、与其他技术对比
| 维度 | 向量时钟 | 单版本号 | 内容哈希 |
| --- | --- | --- | --- |
| 区分覆盖/并发 | 是 | 否 | 否 |
| 判定因果序 | 是 | 单向 | 否 |
| 合并依据 | 偏序 | 时间先后 | 是否相同 |
| 元数据大小 | $O(N)$ | $O(1)$ | $O(1)$ |
| 是否需应用合并 | 需要 | 不需要（会丢写） | 不需要（会丢写） |

哈希只能判断「是否相同」，版本号只能判断「谁新」，都无法区分「新的是因为覆盖还是因为并发」。

还需区分「向量时钟」与「版本向量」：二者结构相同，但语义侧重不同——向量时钟用于为事件打时间戳（判定 happened-before），版本向量用于为对象版本打分（检测并发写）。工程文档中二者常混用，理解其共同本质即可。

## 六、常见误区
1. 用单一递增版本号判冲突。单版本号丢失了「谁先谁后」的结构，并发更新会被误判为顺序更新而丢写。
2. 维度固定导致扩容受限。增删节点若不改变维度约定，新旧时钟不可比较。
3. 把「值相同」当「无冲突」。并发编辑可能恰好产生相同值，但因果上仍是冲突，需保留合并历史。
4. 只保留「最新单个版本」。并发时正确做法是保留多个极大元，而非挑一个「最大」的。
5. 以为并发判定可忽略传递性。偏序传递性保证极大元算法正确，破坏它表示则剪枝会漏掉冲突。
6. 忽略维度映射的一致性。不同节点对「第几维对应哪个进程」必须有相同约定，否则比较结果无意义。
7. 忽略兄弟版本数量控制。长期累积不合并会让读放大持续恶化，需设定上限并强制合并策略。

## 八、面试题
1. 如何用向量时钟判定两版本冲突？写出充分必要条件。
   要点：互不 dominates，即存在维度 i、j 各自严格大。
2. dominates 与 concurrent 的关系？为什么检测并发先判 dominates？
   要点：concurrent = 非（a dominates b）且非（b dominates a）；判 dominates 更直接。
3. 维度不一时如何比较？如何安全增删节点？
   要点：缺省维度按 0 处理；增删需全局一致地维护映射或采用 ITC。
4. k 个版本如何高效找出冲突集合？
   要点：两两比较保留极大元（不被任何版本支配者），被支配者丢弃。
5. 为什么不能只挑「分量最大」的版本？
   要点：并发版本无单一最大者，会丢失另一分支的更新。
6. 向量时钟与版本向量有何区别？
   要点：结构相同、用途不同——前者给事件打时间戳判 happened-before，后者给对象版本打分检并发写。

## 九、演进与趋势
冲突检测从「显式版本向量」走向「CRDT 自动合并」：冲突不再需要应用层手工 merge，数据类型本身保证收敛（Shapiro 2011）。Dotted Version Vectors 进一步把冲突元数据压缩，使大规模并发复制可行；生产系统中常与「后台 read repair」配合，读取时暴露冲突、写入时收敛。未来方向是「检测即合并」的统一数据类型。

另一方向是「冲突的可观测性」：把冲突率、兄弟版本数等指标暴露给运维，让应用层能判断「当前合并策略是否合理」，从「静默丢写」或「读放大」两种隐蔽故障中解放出来。

## 十、小结
向量时钟把「是否冲突」变成可计算的偏序比较：一方 dominates 另一方则有序可覆盖，否则并发须合并。它是并发复制系统中冲突检测的核心，也是版本向量、CRDT 的理论起点，其精确性直接关系到无主存储是否会静默丢写，是保障复制正确性的第一道防线。掌握「极大元集合」与「缺失维度按 0 补齐」两条实现要点，就能正确落地冲突检测。
