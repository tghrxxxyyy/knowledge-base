# 因果序与因果一致性

> 对应 Lamport 1978（happened-before 与因果）与 Shapiro 2011（CRDTs，因果一致复制）以及 Kleppmann DDIA 第5章。

## 一、背景与挑战
强一致代价高，最终一致可能读到“违反因果”的状态（如先看到回复再看到原帖）。因果一致性保证有因果关系的操作顺序被所有副本尊重。

## 二、核心原理
- 因果序：若操作 a 影响 b（b 读取 a 的结果或在其后），则所有副本必须先应用 a 再应用 b。
- 并发操作可任意排序。
- 向量时钟用于检测并维护因果依赖。

## 三、形式化与数学基础
对操作 op，其因果历史用版本向量 $V_{op}$ 表示。副本应用 op 前需满足 $\forall j: V_{dep}[j] \le local[j]$（依赖已就位）。并发 op 之间无此约束。

## 四、代码实现
# 因果就绪检查
def ready(op, local):
    return all(op.deps[j] <= local[j] for j in range(len(local)))

## 五、与其他技术对比
- 对比线性一致：因果一致更弱但更易实现高可用。
- 对比最终一致：因果一致多了“不违反因果”约束。

## 六、常见误区
1. 以为最终一致一定违反因果——可用因果一致型最终一致。
2. 把因果一致当成读己之写。
