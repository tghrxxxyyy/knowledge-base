# 页与缓冲池

> 对应 Silberschatz《Database System Concepts》第 10 章 Storage and File Structure，以及 CMU 15-445 Lecture 9-10 Buffer Pool。

## 一、背景与挑战
磁盘按页（page，常见 4KB/8KB/16KB）读写，随机 I/O 比顺序 I/O 慢约两个数量级。数据库用缓冲池（buffer pool）缓存页，将频繁访问的数据留在内存，减少磁盘访问。挑战在于有限内存下的替换策略与脏页刷盘时机。

## 二、核心原理
缓冲池由若干页帧（frame）组成，通过页表映射 `(表空间ID, 页号) -> 帧`。读页时先查缓冲池，未命中则从磁盘读入并可能触发替换。被修改的页标记为脏（dirty），需写回磁盘后帧才能复用。

## 三、形式化 / 数学基础
设命中率 $h$，平均访问代价
$$T_{avg} = h \cdot T_{mem} + (1-h) \cdot T_{disk}$$
LRU 用近似时间戳：每帧记录 last_used，淘汰最小者；Clock 用单比特 ref 位近似。

## 四、代码实现
```c
// 简化 Clock 扫描淘汰
int evict(Pool *p) {
    while (1) {
        Frame *f = &p->frames[p->clock];
        p->clock = (p->clock + 1) % p->n;
        if (!f->pinned && f->ref == 0) {
            if (f->dirty) flush(f);
            return f->id;
        }
        f->ref = 0;
    }
}
```

## 五、与其他技术对比
| 策略 | 优点 | 缺点 |
|------|------|------|
| LRU | 简单、贴合局部性 | 全表扫描易污染 |
| Clock | 近似 LRU、开销低 | 精度略差 |
| LRU-K | 抗扫描 | 实现与内存开销大 |

## 六、常见误区
1. 缓冲池越大越好——超过工作集后收益递减且大池恢复慢。
2. 混淆 page 与 extent：page 是读写单位，extent 是分配单位。
3. 以为脏页立即写盘——实际依赖刷脏线程批量写。

## 九、演进与趋势
现代引擎（PostgreSQL ring buffer、MySQL 多 buffer pool instances、RocksDB block cache）通过分区、预取与压缩页缓存降低锁竞争与碎片。

## 十、小结
缓冲池是连接 CPU 与磁盘的桥梁，替换策略与脏页管理直接决定 OLTP 吞吐；理解页式存储是学习 B+ 树与索引的基础。
