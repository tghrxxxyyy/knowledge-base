# 空间管理

> 对应 Silberschatz《Database System Concepts》第 10 章 Physical Storage，以及 MySQL InnoDB 表空间管理。

## 一、背景与挑战
随着增删改，文件会产生碎片与空闲空洞。如何分配、回收、合并空间，既减少碎片又避免频繁系统调用，是存储层必须解决的问题。

## 二、核心原理
数据库以区段（extent，含若干连续页）为单位向 OS 申请，以页为单位使用。空闲空间用位图（bitmap）或空闲链表（free list）跟踪；删除产生的空闲页进入空闲列表供复用。

## 三、形式化 / 数学基础
碎片率 $F = 1 - \frac{\text{已用有效页}}{\text{已分配页}}$。区段分配策略：当表小用碎片页（fragment），增长后改整 extent 分配，降低管理开销。

## 四、代码实现
```c
// 位图分配一个空闲页
int alloc_page(Space *s) {
    for (int i = 0; i < s->nbytes; i++) {
        if (s->bitmap[i] != 0xFF) {
            int b = ffs(~s->bitmap[i]) - 1;
            s->bitmap[i] |= (1 << b);
            return i * 8 + b;
        }
    }
    return -1; // 需新 extent
}
```

## 五、与其他技术对比
| 方式 | 优点 | 缺点 |
|------|------|------|
| 位图 | 紧凑、查块快 | 大空间扫描慢 |
| 空闲链表 | 分配 O(1) | 易外部碎片 |
| 区段组 | 减少碎片 | 小表浪费 |

## 六、常见误区
1. DELETE 立即释放空间给 OS——通常只标记空闲供复用。
2. 碎片不影响性能——随机访问空洞会增加 I/O。
3. 自动回收——常需 OPTIMIZE/重建。

## 九、演进与趋势
存储计算分离（如 Aurora）把空间管理下沉到分布式存储层，引擎只发 redo 日志；本地 SSD 缓存层做页级预热。

## 十、小结
空间管理用 extent/页两级 + 位图/链表平衡分配效率与碎片，是缓冲池与索引的底层支撑。
