# 向量化执行

> 对应 Boncz et al. MonetDB/X100 向量化论文（2005），以及 ClickHouse/DuckDB 执行模型。

## 一、背景与挑战
传统火山模型逐行（tuple-at-a-time）调用算子，函数调用与解释开销大，且无法利用 CPU 流水线与 SIMD。向量化一次处理一批（vector/batch）数据。

## 二、核心原理
算子以列批量（如 1024 行）为单位传递，内部用紧凑数组 + 循环处理，利于编译器向量化（SIMD）与缓存局部性。惰性物化（late materialization）延迟拼装整行。

## 三、形式化 / 数学基础
传统逐行：每元组 $O(1)$ 调用但常数开销 $c$ 主导，$T \approx N \cdot c$。向量化：批处理摊薄调用开销，循环可被 SIMD 并行，$T \approx N \cdot (c/b + k)$，$b$ 为批量、$k$ 为每元素计算。

## 四、代码实现
```c
// 向量化过滤：批量比较
void filter_gt(double *col, double *out, int n, double thr, int *cnt) {
    for (int i = 0; i < n; i++)        // 编译器可 SIMD 化
        if (col[i] > thr) out[(*cnt)++] = col[i];
}
```

## 五、与其他技术对比
| 模型 | 单位 | CPU 友好 | 开销 |
|------|------|----------|------|
| 火山逐行 | 1 行 | 否 | 高 |
| 向量化 | 批 | 是 | 低 |
| 编译执行 | 整段 | 最优 | 最低 |

## 六、常见误区
1. 向量化=多线程——它是 SIMD/批处理，与并行正交。
2. 批量越大越好——受缓存大小限制。
3. 向量化总能赢——解释型小查询可能更慢。

## 九、演进与趋势

## 十、小结
向量化以批处理 + SIMD 摊薄调用开销、提升缓存命中，是现代分析引擎的执行核心。
