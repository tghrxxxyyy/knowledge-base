# 行存对比

> 对应 Silberschatz《Database System Concepts》第 12 章 物理存储，以及 C-Store 行列对比。

## 一、背景与挑战
存储格式决定 I/O 模式：OLTP 多单行点查/更新，OLAP 多扫描少数列。行存与列存各有取舍，理解对比有助于选型。

## 二、核心原理
行存把整行连续存放，单行读写只需一次 I/O，适合事务；列存把同列连续存放，少数列扫描 I/O 最小且易压缩，适合分析。现代系统用混合（PAX：行组内按列）折中。

## 三、形式化 / 数学基础
读 $c$ 列 $N$ 行：行存 I/O $\approx N \cdot W_{row}$；列存 $\approx c \cdot N \cdot W_{col}$（$W_{col} \ll W_{row}/C_{total}$）。写单条：行存 $O(1)$ 定位，列存需写多列文件。

## 四、代码实现
```sql
-- 行存 OLTP 表
CREATE TABLE txns (id BIGINT, uid BIGINT, amt NUMERIC, ts TIMESTAMP);
-- 列存分析表（ClickHouse）
CREATE TABLE events (uid UInt64, amt Float64, ts DateTime)
ENGINE = MergeTree ORDER BY (ts);
```

## 五、与其他技术对比
| 维度 | 行存 | 列存 |
|------|------|------|
| 点查 | 优 | 差 |
| 扫描少数列 | 差 | 优 |
| 单行更新 | 优 | 差 |
| 压缩 | 弱 | 强 |

## 六、常见误区
1. 一种格式通吃——HTAP 才需混合。
2. 列存不能更新——可借 delta/版本。
3. 行存无法分析——能，只是 I/O 不经济。

## 九、演进与趋势
HTAP 系统（TiDB、PolarDB）用行存服务事务、列存副本服务分析，行转列异步同步。

## 十、小结
行存优事务、列存优分析，混合存储与 HTAP 是兼顾两者的现代方案。
