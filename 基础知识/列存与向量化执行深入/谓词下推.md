# 谓词下推

> 对应 Garcia-Molina《Database Systems》第 16 章查询优化（下推），以及 Parquet/ORC 谓词下推（谓词裁剪）。

## 一、背景与挑战
查询 `SELECT ... WHERE col > 10` 若先读全部数据再过滤，浪费大量 I/O 与计算。把过滤尽量推到数据读取前/读取时执行，可大幅减少处理量。

## 二、核心原理
谓词下推（predicate pushdown）将过滤条件下推到扫描层：行存下推到存储引擎，列存下推到列块（结合统计信息/列块最小最大值跳过不满足的块，即 min-max/zone map）。

## 三、形式化 / 数学基础
无下推代价 $C = read(all) + filter(all)$；下推后 $C = read(matched\_blocks) + filter(matched)$。块跳过基于 $skip \iff max(block) < 10$（对 `>10`）。

## 四、代码实现
```sql
-- Spark / Parquet 自动谓词下推
spark.read.parquet("/data/t")
     .filter(col("ts") > "2026-01-01")
     .select("uid")
-- 引擎用每文件/每块的统计(min,max)跳过不相关块
```

## 五、与其他技术对比
| 方式 | 读取量 | 计算量 |
|------|--------|--------|
| 先读后滤 | 全量 | 全量 |
| 谓词下推 | 子集 | 子集 |

## 六、常见误区
1. 谓词下推总是自动——复杂表达式可能无法下推。
2. 下推能消除所有 I/O——只能跳过整块。
3. 视图/函数列可下推——常不行。

## 九、演进与趋势
Bloom filter 索引、稀疏索引与下推结合，进一步缩小扫描范围；下推到存储层（如数据湖）成为趋势。

## 十、小结
谓词下推把过滤尽量靠近数据源，用块统计跳过无关数据，是分析查询 I/O 优化的关键手段。
