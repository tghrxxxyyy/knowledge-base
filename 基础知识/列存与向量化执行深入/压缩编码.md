# 压缩编码

> 对应 Abadi et al. 列存压缩技术，以及 Parquet/ORC 编码文档。

## 一、背景与挑战
列存数据同构、局部性强，是压缩的沃土。合适编码既省空间又常能"边解压边计算"（late materialization + 编码下推谓词）。

## 二、核心原理
常用编码：字典编码（低基数列）、游程编码（RLE，连续重复）、位打包（bit-packing，小整数）、Delta 编码（有序差）、LZ 族（通用）。谓词可下推到编码层（如字典映射后只比编码值）。

## 三、形式化 / 数学基础
字典编码：原值 $v \to code \in [0, NDV)$，存储 $\approx \log_2 NDV$ 位/值。RLE：序列 $a^m b^n \dots$ 压缩为 $(a,m),(b,n)$。压缩比 $r = size_{comp}/size_{orig}$。

## 四、代码实现
```python
def dict_encode(col):
    uniq = {v: i for i, v in enumerate(sorted(set(col)))}
    return [uniq[v] for v in col], list(uniq.keys())
# 谓词下推：只在字典里找匹配 code 再扫描 code 数组
```

## 五、与其他技术对比
| 编码 | 适合 | 随机访问 |
|------|------|----------|
| 字典 | 低基数 | 需映射 |
| RLE | 连续重复 | 差 |
| Bit-pack | 小整数 | 好 |

## 六、常见误区
1. 压缩一定慢——编码常可被查询直接消费。
2. 一种编码通吃——需按列特征选。
3. 压缩只省空间——也省 I/O 与带宽。

## 九、演进与趋势
轻量压缩（Frame-of-Reference、FOR）、Patas/ALP 等针对浮点；编码与向量化执行深度协同。

## 十、小结
压缩编码利用列存的同构性大幅减体，并支持编码级谓词下推，是列存性能倍增器。
