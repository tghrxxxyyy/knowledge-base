# 边界与接缝

> 对应 Feathers《Working Effectively with Legacy Code》"Seams"、测试边界理论。

## 一、背景与挑战
不可测代码常在边界处（时间、随机数、网络、文件系统）与不可控依赖纠缠，找不到可注入点。

## 二、核心原理
接缝（Seam）是"程序中点，其旁行为可不修改该点代码而被替换"。在 I/O 与领域逻辑间留缝，测试时注入假实现。边界指系统与外界（DB、网络、时钟）交界，应薄且可替。

## 三、形式化 / 数学基础
接缝点 $s$ 使 $behavior(s)$ 由外部提供：$run(s, impl_{real})$ 生产运行，$run(s, impl_{fake})$ 测试运行，二者共享 $s$ 之上逻辑。

## 四、代码实现
```python
def process(now_provider, data):
    return summarize(data, now=now_provider())
# 测试传入 lambda: lambda: datetime(2020,1,1)
```

## 五、与其他技术对比
与 DI 相关但更通用：接缝可通过继承、函数参数、编译开关实现，不限于构造注入。

## 六、常见误区
误区：把边界逻辑写进领域核心，无法替换。误区：为缝而缝，过度抽象。

## 九、演进与趋势
面向接口设计与纯函数式核心（functional core, imperative shell）把边界推到最外层。

## 十、小结
在边界留缝，使不可控依赖可被替换与测试。
