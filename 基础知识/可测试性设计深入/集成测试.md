# 集成测试

> 对应 Mike Cohn 测试金字塔理论（《Succeeding with Agile》）；Fowler 关于测试分层的相关论述。

## 一、背景与挑战

单元测试全绿，但组件联调仍失败：数据库映射写错、事务边界不一致、序列化格式对不上、消息顺序错乱。这类「模块各自正确、协作即错」的问题，单测无法暴露，必须用集成测试验证多组件协作与基础设施交互。遗憾的是，很多团队要么过度依赖单测（覆盖面窄），要么滥用端到端（慢且脆），都源于对集成测试定位不清。

## 二、核心原理

集成测试验证模块间接口与基础设施（DB、消息队列、HTTP 服务）的真实协作。原则是「少而真」：用测试容器（Testcontainers）启动与生产同版本的真实依赖，避免用内存替身掩盖接口差异；同时遵守测试金字塔——多单元、少集成、更少端到端，使信号成本比最优。集成测试还应可独立运行、可清理，防止相互污染。关键在于验证「接线正确」，而非重复单测已覆盖的业务逻辑。

## 三、形式化与数学基础

测试金字塔建议数量比例约为：单元测试 : 集成 : 端到端 $\approx 70:20:10$。设第 $i$ 层测试数为 $n_i$、单条成本为 $c_i$、缺陷定位价值为 $v_i$，总投入：

$$\text{Cost}=\sum_i n_i c_i,\quad \text{Value}=\sum_i n_i v_i$$

因 $c_{\text{int}}>c_{\text{unit}}$ 且 $v_{\text{e2e}}$ 高但脆弱，需在 $n_{\text{int}}$ 上取平衡，使 $\text{Value}/\text{Cost}$ 最大。经验上，集成测试数量约为单测的 1/3，端到端再减半。

## 四、代码实现

```python
# 使用真实数据库的集成测试（pytest + Testcontainers 思路）
def test_order_persist(db_container):
    repo = SqlOrderRepo(db_container.get_connection())
    repo.save(Order("o1", total=99))
    found = repo.find_by_id("o1")
    assert found is not None
    assert found.total == 99           # 验证真实持久化与映射

# 关键：测试间隔离，每条用例自清理
def test_order_rollback(db_container):
    with pytest.raises(IntegrityError):
        repo.save(Order(None))         # 非法字段应回滚
    # 验证失败后数据库未残留脏数据
    assert repo.find_by_id(None) is None
```

## 五、与其他技术对比

| 测试类型 | 隔离度 | 速度 | 暴露的问题 | 定位难度 | 维护成本 |
| --- | --- | --- | --- | --- | --- |
| 单元测试 | 高 | 快 | 内部逻辑 | 低 | 低 |
| 集成测试 | 中 | 中 | 接口/契约/基础设施 | 中 | 中 |
| 端到端 | 低 | 慢 | 全链路 | 高 | 高 |

## 六、常见误区

误区一：用集成测试覆盖本该单测的逻辑——慢且难定位。误区二：共享脏数据不清理——导致用例顺序相关、偶发失败。误区三：用内存替身代替真实 DB——掩盖类型/方言差异，上线才爆。误区四：把集成测试当单测那样高频运行——拖慢反馈循环，应放入独立 CI 阶段。

## 九、演进与趋势

Testcontainers 让集成测试用生产级依赖本地可跑；影子数据库/影子流量降低环境差异；服务虚拟化使外部依赖可控可重放；「集成测试即代码」与 ephemeral 环境结合，使每次 PR 都能跑真实依赖集成。

### 实践速查

- 比例：遵循金字塔，集成测试约为单测的 1/3，端到端再减半。
- 真实依赖：用 Testcontainers 启动生产同版本 DB/中间件，避免内存替身。
- 隔离：每条用例自清理，或用事务回滚、临时 schema 保证可重复。
- 范围：只验证「接线正确」，业务逻辑已由单测覆盖，不重复。
- 分层：把集成测试放独立 CI 阶段，避免拖慢单测快速反馈。
- 数据：用工厂函数构造测试数据，避免手写明文 SQL 散落各处。

### 常见问题

- 问：集成测试变慢怎么办？答：减数量、用并行、仅对关键路径保留。
- 问：内存库能代替真实 DB 吗？答：不能，会掩盖类型与方言差异。
- 问：用例偶发失败？答：多为数据污染或未清理，加隔离与清理钩子。

### 关键记忆点

- 集成测试验证「接线正确」，数量约为单测的 1/3，端到端再减半。
- 用 Testcontainers 跑真实依赖，避免内存替身掩盖接口差异。
- 每条用例自清理，防数据污染导致的偶发失败。
- 只覆盖跨组件协作，业务逻辑交给单测，不重复造轮子。
- 放独立 CI 阶段，避免拖慢单测的快速反馈。
- 用工厂函数构造测试数据，减少散落明文 SQL。

## 十、小结

集成测试验证组件协作，少而真，置于金字塔中层，是连接单测与端到端、捕捉接线错误的关键一环。
