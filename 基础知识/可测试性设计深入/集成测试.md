# 集成测试

> 对应 Fowler《Refactoring》、测试金字塔（Mike Cohn）理论。

## 一、背景与挑战
单元测试通过但组件联调失败：数据库映射错、事务边界错、序列化不一致。需要验证多组件协作。

## 二、核心原理
集成测试验证模块间接口与基础设施（DB、消息、HTTP）协作；应少而精，用测试容器（Testcontainers）保证环境真实。保持金字塔：多单元、少集成、更少端到端。

## 三、形式化 / 数学基础
测试金字塔比例建议：单元测试 : 集成 : E2E $\approx 70:20:10$。集成测试成本 $C_{int}$ 高于单元，故数量受控以平衡 $信号/成本$。

## 四、代码实现
```python
def test_order_persist(db):
    repo = SqlOrderRepo(db)
    repo.save(Order("o1"))
    assert repo.find_by_id("o1").id == "o1"  # 真数据库
```

## 五、与其他技术对比
与单元测试（隔离）相比，集成测试暴露接口契约错误但更慢更脆；与 E2E 相比成本低、定位快。

## 六、常见误区
误区：用集成测试覆盖本该单元测的逻辑（慢）。误区：集成测试共享脏数据不清理。

## 九、演进与趋势
Testcontainers 让集成测试用生产级依赖；影子数据库降低环境差异。

## 十、小结
集成测试验证协作，少而真，置于金字塔中层。
