# 可测性指标

> 对应 ISO/IEC 25010（可维护性之子特性「可测试性」）；Feathers《Working Effectively with Legacy Code》。

## 一、背景与挑战

代码难测往往不是测试本身的问题，而是设计问题：隐藏依赖、静态全局调用、把业务逻辑与 I/O 混写，使单元测试无法隔离被测对象。当团队抱怨「这个模块没法写单测」时，本质上是在说它的可测性低。可测性应作为架构质量属性，在设计阶段就被度量与守护，而不是事后补测试时才发现。否则技术债会随代码膨胀而指数级增长。

## 二、核心原理

可测性（Testability）可从三个维度衡量：可控制性（能否方便地设定输入与前置状态）、可观测性（能否观察输出与内部状态变化）、可隔离性（能否用替身替换外部依赖）。高可测性代码通常具备显式依赖、纯函数核心、薄边界。可测性低会导致测试脆弱、速度慢、覆盖假的「绿」。这三者彼此促进：依赖显式化后更容易注入替身（可隔离），替身使状态可控（可控制），纯函数使输出确定（可观测）。

## 三、形式化与数学基础

可测性近似正比于控制性与可观测性的乘积、反比于隔离成本：

$$T \propto \frac{C_{\text{control}} \times O_{\text{observe}}}{I_{\text{cost}}}$$

圈复杂度（Cyclomatic Complexity）越高、全局可变状态越多，可测性越低。设模块有 $e$ 条边、$n$ 个节点、$p$ 个连通分量，则：

$$CC = e - n + 2p$$

纯函数比例上升（减少副作用）会提升 $C_{\text{control}}$ 与 $O_{\text{observe}}$，从而拉高 $T$。反之，全局可变状态会同时压低三项。

## 四、代码实现

```python
# 难测：隐藏依赖 + 全局时钟 + 副作用
def greet_bad():
    now = datetime.now()          # 不可控
    return "hi " + now.strftime("%H")

# 易测：依赖显式传入，逻辑可观测
def greet_good(now_provider, formatter):
    return "hi " + formatter(now_provider())

# 测试时注入确定性依赖
def test_greet():
    assert greet_good(lambda: datetime(2020, 1, 1),
                      lambda d: d.strftime("%H")) == "hi 00"
    # 可控制性：now 由测试决定；可观测性：输出确定；可隔离性：无外部依赖
```

## 五、与其他技术对比

| 指标 | 关注点 | 是否前置 | 与测试关系 |
| --- | --- | --- | --- |
| 可测性 | 设计可否被测试 | 应前置 | 因 |
| 代码覆盖率 | 是否被执行 | 事后 | 果 |
| 圈复杂度 | 路径数量 | 事后 | 相关 |
| 可维护性 | 是否易改 | 应前置 | 相关 |

可测性是因、覆盖率是果：高可测性让写测试变容易，从而自然提升覆盖率与质量。

## 六、常见误区

误区一：用覆盖率高证明设计好——高覆盖可能靠大量桩硬凑，代码依旧僵化。误区二：为测暴露私有字段——破坏封装换来的可测性是伪可测。误区三：把可测性等同于「能跑测试」——能跑不代表易维护、易改。误区四：忽视全局状态的隐性破坏——单测间共享可变全局状态会导致偶发失败。

## 九、演进与趋势

静态分析工具直接给出可测性评分（如不可测分支比例、全局状态引用数）；架构适应度函数（Architecture Fitness Functions）在 CI 中把可测性作为硬性门禁；契约测试与可测性指标联动，把跨服务边界也纳入可测性评估。

### 实践速查

- 度量：在 CI 中统计圈复杂度、全局可变状态引用数、依赖入参数。
- 门禁：把可测性评分纳入架构适应度函数，低于阈值则阻断合并。
- 改造：对难测模块先找接缝（见「边界与接缝」），再引入 DI。
- 观测：优先把副作用推到边界，使核心逻辑成为纯函数。
- 反模式：隐藏时钟、隐藏随机源、静态全局调用都会拉低可测性。
- 平衡：不要为测而暴露私有字段，改用包级可见性或接缝替代。

### 常见问题

- 问：高覆盖率为何不代表易测？答：可能靠大量桩硬凑，设计依旧僵化。
- 问：如何快速估模块可测性？答：看能否不启动基础设施就跑通单测。

### 关键记忆点

- 可测性三性：可控、可观测、可隔离，控制与观测乘积除以隔离成本。
- 它是覆盖率与可维护性的前置因，应设计阶段就守护。
- 全局可变状态是头号杀手，应尽早隔离到边界。

## 十、小结

控制、观察、隔离三性决定可测性，应作为设计质量属性前置考量，而非事后补测试；它是覆盖率、可维护性的前置因。
