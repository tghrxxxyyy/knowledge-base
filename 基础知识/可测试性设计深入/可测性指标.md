# 可测性指标

> 对应 "Software Testability" (ISO/IEC 25010 可维护性子特性)、Feathers 可测性观。

## 一、背景与挑战
代码难测往往不是测试的问题，而是设计问题：隐藏依赖、静态调用、混用逻辑与 I/O，使单元测试无法隔离。

## 二、核心原理
可测性（Testability）可从可控制性（能否设定输入/状态）、可观测性（能否观察输出/内部）、可隔离性（能否替换依赖）衡量。高可测性设计即高可测代码。

## 三、形式化 / 数学基础
可测性近似 $T \propto \frac{可控性 \times 可观测性}{隔离成本}$。圈复杂度 $CC$ 越高、全局状态越多，可测性越低。纯函数比例上升则 $T$ 上升。

## 四、代码实现
```python
# 难测：隐藏依赖 + 全局时钟
def greet(): return "hi " + datetime.now().strftime("%H")
# 易测：依赖显式传入
def greet(now): return "hi " + now.strftime("%H")
```

## 五、与其他技术对比
与代码覆盖率互补：覆盖率高不代表易测（可能靠大量桩硬凑）。可测性是因，覆盖率是果。

## 六、常见误区
误区：用覆盖率高证明设计好。误区：为测而暴露私有字段破坏封装。

## 九、演进与趋势

## 十、小结
控制、观察、隔离三性决定可测性，应前置到设计。
