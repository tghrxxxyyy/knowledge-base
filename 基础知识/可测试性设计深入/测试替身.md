# 测试替身

> 对应 Meszaros《xUnit Test Patterns》"Test Double"、Fowler 文章。

## 一、背景与挑战
真实依赖（数据库、第三方、时钟）慢、不稳定、难构造异常场景，直接依赖它们使测试脆弱。

## 二、核心原理
测试替身（Test Double）分五类：Dummy（占位）、Stub（返回预设值）、Spy（记录调用）、Mock（预设期望并验证）、Fake（轻量可用实现，如内存库）。

## 三、形式化 / 数学基础
替身替换真实依赖 $D$ 为 $D'$，满足对某些输入返回受控输出：$stub(x_{test})=y_{preset}$。Mock 额外断言 $called(D', method, args)$。

## 四、代码实现
```python
from unittest.mock import Mock
repo = Mock()
repo.find_by_id.return_value = Order("o1")   # stub
svc = OrderService(repo)
svc.ship("o1")
repo.find_by_id.assert_called_once_with("o1")  # mock 验证
```

## 五、与其他技术对比
Stub 只提供数据，Mock 验证行为；Fake 是可投产的简化实现；过度使用 Mock 会耦合测试与实现细节。

## 六、常见误区
误区：Mock 一切导致测试脆弱（实现细节一变就红）。误区：Spy 与 Mock 混淆。

## 七、与开源书 / 权威来源对应
Meszaros, G.《xUnit Test Patterns》"Test Double"；Fowler 相关文章；CS-Notes: https://github.com/CyC2018/CS-Notes

## 八、面试题
"Mock 与 Stub 的区别？什么时候不该用 Mock？"

## 九、演进与趋势
契约测试部分替代 Mock 微服务间交互；快照测试减少手写桩。

## 十、小结
按需选替身：Stub 给数据、Mock 验行为、Fake 做实替。
