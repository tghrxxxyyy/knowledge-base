# 加权投票 Weighted Voting

> 对应 Gifford 1979《Weighted Voting for Replicated Data》（MIT）；Coulouris《Distributed Systems: Concepts and Design》投票章；Kleppmann《Designing Data-Intensive Applications》第 8 章。

## 一、背景与挑战

普通 quorum 给每个副本一票，但现实中副本往往是**异构**的：有的磁盘大、I/O 快、在网络中心，有的只是边缘弱节点。给边缘弱节点与核心强节点同等投票权既浪费强节点能力，又让弱节点拖慢法定达成。加权投票让关键副本拥有更高权重，更贴近真实容错与性能需求，同时也带来权重分配与动态调整的新问题——权重配错反而制造隐性单点。

## 二、核心原理

- 每个副本 $i$ 有投票权重 $v_i$，总权重 $V = \sum_i v_i$。
- 写需获得权重和 $\ge W$ 的确认。
- 读需读取权重和 $\ge R$ 的副本。
- 约束 **$W + R > V$** 保证读集合与写集合在权重意义上相交。
- 某副本故障仅损失其权重，不必达到「数量多数」；可把高权重集中在少数强节点，使读写更易达成法定（延迟更低），同时用低权重边缘节点兜底容错。

实例推演（权重 $(5,3,2),\ V=10,\ W=R=6$）：
- 写向三节点广播，核心 A(5)+B(3)=8 即达 $W=6$，无需等边缘 C(2)，延迟更低。
- 读比较权重和 $\ge 6$ 的副本，A+B 已满足，同样快。
- 若边缘 C(2) 宕机，剩 8 仍可写可读；若核心 A(5) 宕机，剩 5 < 6，则短暂不可写——说明权重分配直接决定容错边界。
- 若误把 A 权重设为 6（>V/2=5），则 A 单节点即可单独达成法定，退化为隐性主。

## 三、形式化与数学基础

设总权重 $V$，阈值满足：

$$
W + R > V
$$

典型取 $W = R = \lceil V/2 \rceil + 1$。某次写成功当且仅当 $\sum_{ack} v_i \ge W$。容错能力：系统可容忍任意权重和 $< W$ 的副本集合故障。例如三节点权重 $(5,3,2),\ V=10,\ W=R=6$：失重 2 的边缘节点后剩 8 仍可写；失重 5 的节点后剩 5 < 6 则不可写。

## 四、代码实现

```python
# 加权法定判定（示意）
def has_quorum(acks_weights, threshold):
    return sum(acks_weights) >= threshold

# 权重分配示例：强节点高权重
replicas = [("core-A", 5), ("core-B", 3), ("edge-C", 2)]
V = sum(w for _, w in replicas)          # 10
W = R = V // 2 + 1                       # 6
print(has_quorum([5, 3], W))            # True: 核心两节点已达成
print(has_quorum([2], W))               # False: 仅边缘节点不足
```

```python
# 扩缩容时重算阈值（示意）
def recompute(V):
    return V // 2 + 1                   # W = R
```

## 五、与其他技术对比

| 维度 | 等权 quorum | 加权投票 | 主从复制 | 容错单位 |
|------|-------------|----------|----------|----------|
| 节点权重 | 平等 | 按能力分配 | 主唯一 | — |
| 容错粒度 | 数量多数 | 权重多数 | 主故障切换 | 权重和 |
| 适用 | 同构集群 | 异构集群 | 简单读写 | — |
| 延迟 | 中等 | 可由强节点快速达成 | 仅主 | — |

加权投票仍是去中心投票，优于「硬主从」，且比等权更贴合异构现实。

## 六、常见误区

1. 权重分配不当导致单点权重大：若某节点权重 $> V/2$，它实际成为隐性主，破坏去中心性。
2. 忽略权重总和变化：扩缩容时需重算 $W,R$，否则阈值失效。
3. 误以为权重高=更可靠：权重反映「能力/重要性」，不等于故障率，需综合。
4. 把权重当成副本数：判定用权重和而非节点数，计数方式不同。
5. 以为加权可突破 CAP：分区下仍需在 C/A 间取舍，加权只改变法定构成。
6. 静态权重不适应负载：热点节点若权重固定，故障切换时法定达成变得更难。
7. 以为权重越高越好：过高集中权重会降低整体容错（单点失则法定破）。

## 八、面试题

1. 加权投票如何修改 quorum 不等式？答：把副本数 $N$ 换成总权重 $V$，约束变为 $W+R>V$，判定用权重和。
2. 权重如何反映节点异构？答：强/近中心节点给高权重，使法定更易由少量强节点达成，降低延迟。
3. 权重分配要注意什么？答：避免单节点权重超 $V/2$ 形成隐性主；扩缩容重算阈值。
4. 加权投票容错由什么决定？答：由可丢失的权重和上限（<W）决定，而非节点个数。
5. 为何单节点权重不可超 V/2？答：否则它单独即可达成法定，系统退化为该节点的隐性主。

## 九、演进与趋势

动态调整权重随负载/健康度变化（如节点过热降权）；与 CRDT、灵活 quorum（flexible quorum）结合，在异构云环境中优化成本与可用。具体以官方最新文档为准。

## 十、小结

加权投票把「票数」换成「权重」，使 quorum 适应异构与分级容错。它在保持去中心投票优点的同时，更精细地刻画了节点的真实能力与重要性。
