# 二维树状数组

> 对应 Fenwick 1989 原始论文多维扩展、Sedgewick《Algorithms》第 14 章、CLRS《算法导论》第 10.3 节（多维前缀背景）。

## 一、背景与挑战
矩阵上的「单点加 + 矩形区域求和」是图像处理、二维计数、棋盘统计中的常见操作。朴素做法是每次遍历矩形 $O(nm)$，在高频更新下不可接受。一维树状数组只解决单行，二维树状数组（2D BIT）把每一维都用 lowbit 分解，将矩形统计压到 $O(\log n \cdot \log m)$，且常数极小。

它本质上是「一维 BIT 再套一维 BIT」：外层 BIT 的每个节点本身又是一行 BIT，从而形成二维矩形块的管理结构。

真正的挑战在于两个维度不能被简单解耦：矩形区域由行区间与列区间共同限定，因此凡是「跨两维」的操作（矩形加、矩形和、二维偏序）都必须同时处理两层的 lowbit 路径。误以为「先按行做一次 BIT、再按列做一次」就能拼出矩形和，是初学者最常见的构图错误——前缀和不能这样张量化。

## 二、核心原理
把一维 BIT 的「一维区间」替换为「二维矩形块」：`bit[x][y]` 管理以 $(x,y)$ 为右上角、由 lowbit 决定的矩形区域之和。更新时对外层 $x$ 沿 `x += lowbit(x)` 循环，对内层 $y$ 沿 `y += lowbit(y)` 循环，把每个覆盖到的矩形块加上 delta。

查询矩形 $(1,1)$ 到 $(x,y)$ 的前缀和时，两层都沿 lowbit 递减累加。任意矩形 $[x1,x2]\times[y1,y2]$ 的和用四角容斥得到。注意两维都必须 1-indexed，否则内层或外层循环会死循环。

低层实现上有一个重要选择：内层用「数组 of 数组」还是「一维数组 + 行偏移」。前者可读性好，缓存局部性一般；后者把 $bit[i][j]$ 展平为 $bit[i \cdot (m+1) + j]$，可减少一次指针跳转，在大矩阵上更快但可读性下降。此外，若矩阵稀疏，可把每行替换为「按需创建的 BIT」，或改用哈希表 + 离散化，把空间从 $O(nm)$ 降到 $O(k\log)$（$k$ 为非零元素数）。

## 三、形式化与数学基础
设矩阵 $A[1..n][1..m]$，二维 BIT 节点：

$$ bit[x][y] = \sum_{i=x-lowbit(x)+1}^{x}\;\sum_{j=y-lowbit(y)+1}^{y} A[i][j] $$

单点加与二维前缀查询各含两层循环，每层 $O(\log)$：

$$ T_{add} = T_{query} = O(\log n \cdot \log m),\quad \text{空间 } O(nm) $$

矩形和（四角容斥）：

$$ S = Q(x2,y2) - Q(x1-1,y2) - Q(x2,y1-1) + Q(x1-1,y1-1) $$

四角容斥可视为二维的容斥原理 $|A \cup B| = |A| + |B| - |A \cap B|$ 的直接应用：矩形 $[x1,x2]\times[y1,y2]$ 是「$x\le x2$」与「$y\le y2$」两个前缀区域的交集，减去两个「超出边界」的条带后，交叠部分被减了两次，故需加回。当 $n = m = 10^3$ 时 $O(\log n \log m) \approx 100$，而朴素遍历需 $10^6$ 次，差距达四个数量级。若改为「矩形加 + 矩形和」，则需引入二维差分：用四棵树分别维护差分系数，使 $O(\log^2)$ 仍成立，但常数与空间乘四。

## 四、代码实现
```python
class Fenwick2D:
    def __init__(self, n, m):
        self.n, self.m = n, m
        self.bit = [[0] * (m + 1) for _ in range(n + 1)]   # 两维均 1-indexed
    def add(self, x, y, delta):
        i = x
        while i <= self.n:              # 外层：行方向沿 lowbit 上溯
            j = y
            while j <= self.m:          # 内层：列方向沿 lowbit 上溯
                self.bit[i][j] += delta
                j += j & (-j)
            i += i & (-i)
    def query(self, x, y):
        s, i = 0, x
        while i > 0:                    # 外层：行方向沿 lowbit 下降
            j = y
            while j > 0:                # 内层：列方向沿 lowbit 下降
                s += self.bit[i][j]
                j -= j & (-j)
            i -= i & (-i)
        return s
    def rect_sum(self, x1, y1, x2, y2):
        # 四角容斥：注意参数四组均需 -1 处理左下边界
        return (self.query(x2, y2) - self.query(x1 - 1, y2)
                - self.query(x2, y1 - 1) + self.query(x1 - 1, y1 - 1))

# 变体：矩形加 + 矩形和（差分 + 四棵树，思路示意）
# 对矩形 (x1,y1)-(x2,y2) 加 v，等价于在差分网格四点做修正，
# 再维护 T1..T4 四棵 2D BIT 以支持带权前缀和；常数与空间均为单棵的 4 倍
```

`rect_sum` 中的四组 `-1` 是最易错处：若写成 `query(x2,y2) - query(x1,y2) - query(x2,y1) + query(x1,y1)`，得到的是「开区间」矩形，边界行/列会被漏掉。工程上建议为该方法写单元测试，覆盖「单格」「单行」「整矩阵」三种退化情况。

## 五、与其他技术对比
| 维度 | 朴素遍历 | 二维 BIT | 二维线段树 | 差分 + 双 BIT |
| --- | --- | --- | --- | --- |
| 单点加 | $O(1)$ | $O(\log n\log m)$ | $O(\log n\log m)$ | 不支持 |
| 矩形加 | $O(nm)$ | 需四棵树 | 支持但实现繁 | $O(\log n\log m)$ |
| 矩形和 | $O(nm)$ | $O(\log n\log m)$ | $O(\log n\log m)$ | $O(\log n\log m)$ |
| 代码/常数 | 极小 | 小 | 大 | 中 |

二维 BIT 代码短、常数小，但同样只支持前缀/单点类操作；二维线段树更通用但冗长且易出 bug（需维护 $4\times$ 子区间）。若需求是「矩形加 + 矩形和」，纯 2D BIT 不够，必须叠加差分技巧；若还需「区间最值」等不可逆合并操作，则只能改用线段树或二维稀疏表。

## 六、常见误区
误区一：只把一维当 x 维、忘记 y 维也需 1-indexed，导致内层循环死循环。误区二：矩形求和直接用 `Q(x2,y2)-Q(x1,y1)` 漏掉容斥，正确需四角。误区三：以为二维 BIT 能直接做「矩形区域加」——单 2D BIT 只擅长单点加，矩形加需差分 + 双 BIT 技巧。

误区四：在稀疏大矩阵上开满 $O(nm)$ 数组爆内存，应先离散化或压缩坐标。误区五：误判空间为 $O(n+m)$——实际是 $O(nm)$。误区六：把坐标 0 或负数直接当下标，未做偏移映射。误区七：认为四角容斥的顺序可以任意交换——表达式正确但若中间量用无符号整型相减可能下溢。

## 八、面试题
1. 用 2D BIT 做矩阵点加与矩形和，复杂度？答：点加与查询均 $O(\log n\log m)$。
2. 四角容斥公式？答：$Q(x2,y2)-Q(x1-1,y2)-Q(x2,y1-1)+Q(x1-1,y1-1)$。
3. 稀疏大矩阵怎么办？答：对行/列离散化后用压缩下标建 BIT，或转 CDQ 分治。
4. 二维 BIT 能直接矩形加吗？答：不能，需差分数组 + 四个 2D BIT，把矩形加化归为四点更新。
5. 为什么两维都必须 1-indexed？答：`j & (-j)` 在 $j=0$ 时为 0，内层循环永不前进而死循环；这也是 BIT 结构的硬前提。
6. 能否只对一维做 BIT、另一维暴力？答：可以，复杂度降为 $O(\log n \cdot m)$，在 $m$ 很小而 $n$ 很大时反而更划算，属于常见工程折中。

## 九、演进与趋势
二维 BIT 与差分结合可支持「矩形区域加 + 矩形查询」（四棵树或差分技巧）；对超大稀疏矩阵可配合坐标离散化与动态开点。可持久化 2D BIT 支持历史快照查询，但空间代价显著（每层复制受影响节点）。

在图像处理与计算几何中，2D BIT 常用于二维偏序计数（如「左下角有多少点」），是离线扫描线算法的在线替代。当维度继续升高（三维偏序）时，嵌套 BIT 的常数会迅速恶化，此时 CDQ 分治或整体二分往往是更实用的选择。具体取舍需按数据规模实测确定。

## 十、小结
二维树状数组把两维各用 lowbit 分解，矩形统计降到 $O(\log n\log m)$，是二维前缀求和最实用的轻量结构，核心在于两重 lowbit 循环与四角容斥。

记忆要点三条：两维都要 1-indexed；求和必用四角容斥（四个 `-1` 不能丢）；矩形加须叠差分技巧而非直接使用。掌握这三点，2D BIT 的绝大多数误用都能避免。
