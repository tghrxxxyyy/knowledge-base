# 树状数组lowbit原理

> 对应 Fenwick 1989《A New Data Structure for Cumulative Frequency Tables》、Kozen《The Design and Analysis of Algorithms》、Sedgewick《Algorithms》第 14 章。

## 一、背景与挑战
频繁求前缀和并做单点加时，朴素数组查询 $O(n)$、前缀和数组更新 $O(n)$，二者无法同时高效。需要一种结构把「前缀和」与「单点更新」都降到对数级，同时保持常数极小、代码极短。树状数组（Fenwick Tree，也称 Binary Indexed Tree）用 `lowbit` 把前缀和分解为 $O(\log n)$ 个不重叠的区间段，是这一权衡的典范。

lowbit 是整个结构的数学基石：它决定了每个节点「管理多长一段」以及更新/查询时「如何跳跃」。理解 lowbit 等于理解了 BIT 的全部。

从更抽象的视角看，BIT 是「用二进制表示做区间分解」的产物：任意正整数 $i$ 都能唯一分解为若干个「以某个 2 的幂为长度、以某处为右端点」的区间之和，而这些区间恰好对应二进制中每一个为 1 的位。lowbit 只是这一分解在代码层面的实现方式。

## 二、核心原理
`lowbit(x) = x & -x` 取 $x$ 二进制表示中「最低位的 1 及其后的所有 0」构成的数值，即 $x$ 能被 $2$ 整除的最大次幂：$lowbit(x) = 2^{\nu_2(x)}$。索引 $i$ 管理的区间长度为 $lowbit(i)$，覆盖 $(i - lowbit(i),\; i]$。

更新时从 $i$ 沿 `i += lowbit(i)` 向上爬，把每条覆盖 $i$ 的区间加上 delta；查询前缀时从 $i$ 沿 `i -= lowbit(i)` 向下跳，累加每条区间的和。两条路径互为反向，步数等于 $i$ 二进制中 1 的个数。

`x & -x` 之所以有效，依赖于补码表示：$-x$ 等于 `~x + 1`，把 $x$ 最低位的 1 变成 1、其后变成 0、其前全部取反，再与 $x$ 按位与，就只剩最低位那个 1 及其后的 0。这是补码设计带来的「免费礼物」，也是 BIT 实现如此简短的原因。

「向上爬」与「向下跳」的对称性可这样理解：向上爬时每次把「当前最低位的 1」进位到更高位，从而经过所有「右端点为某祖先、且区间包含 $i$」的节点；向下跳时每次去掉「当前最低位的 1」，从而把前缀 $[1,i]$ 恰好切成不重叠的若干段。二者是同一分解的两个方向。

## 三、形式化与数学基础
设 $x$ 的二进制为 $b_k b_{k-1}\dots b_0$，则：

$$ lowbit(x) = x \;\&\; (\sim x + 1) = 2^{\min\{j \mid b_j = 1\}} $$

`bit[i]` 维护区间和：

$$ bit[i] = \sum_{t = i - lowbit(i) + 1}^{i} a[t] $$

前缀查询的跳数等于 $i$ 的二进制中 1 的个数 $popcount(i)$，故：

$$ T_{add} = T_{prefix} = O(\log n),\quad \text{空间 } O(n) $$

期望跳数为 $\frac{1}{2}\log_2 n$（每 bit 为 1 的概率约 1/2），常数极小。

「不重叠覆盖」的严格表述：设 $i = \sum_{k \in S} 2^k$（$S$ 为置位集合），则前缀 $[1,i]$ 被分解为 $\{|S|\}$ 个区间 $[i - 2^{k_1} + 1, i]$、$[i - 2^{k_1} - 2^{k_2} + 1, i - 2^{k_1}]$、……，每个区间的长度恰为某个 $2^k$，且右端点恰是某个访问到的 `bit` 下标。这一分解唯一且不重叠，因此前缀和查询既不重复也不遗漏。

## 四、代码实现
```python
class Fenwick:
    def __init__(self, n):
        self.bit = [0] * (n + 1)          # 1-indexed
    def add(self, i, delta):
        while i < len(self.bit):
            self.bit[i] += delta
            i += i & (-i)                  # 向上覆盖
    def prefix(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & (-i)                  # 向下拆分
        return s
```

`x & -x` 依赖补码表示，Python 任意精度整数同样适用，无需担心符号位。`lowbit(0)=0` 是必须避开 0 下标的根本原因。

手动计算 lowbit 的等价写法（便于理解位运算语义）：

```python
def lowbit_bitwise(x):
    # 等价于 x & -x：不断清除更低位，直到找到最低置位
    return x & (~x + 1)        # 补码语义下与 x & -x 完全相同

def lowbit_loop(x):
    if x == 0:
        return 0                # lowbit(0) = 0，正是必须 1-indexed 的原因
    step = 1
    while (x & step) == 0:      # 找出最低置位
        step <<= 1
    return step
```

## 五、与其他技术对比
| 维度 | 前缀和数组 | 树状数组 | 线段树 |
| --- | --- | --- | --- |
| 单点加 | $O(n)$ | $O(\log n)$ | $O(\log n)$ |
| 前缀/区间和 | $O(1)$ | $O(\log n)$ | $O(\log n)$ |
| 常量与代码 | 极小 | 极小 | 较大 |
| 任意区间最值 | 不支持 | 不支持 | 支持 |
| 空间 | $O(n)$ | $O(n)$ | 约 $4n$ |
| 递归 | 无 | 无 | 通常有 |

树状数组代码更短、常数更小，但只擅长前缀/单点类操作；线段树通用但冗长。lowbit 的二进制跳跃是其对线段树「树高 = log n」的等价替代。

## 六、常见误区
误区一：树状数组下标从 0 开始——传入 0 会使 `i -= i & -i` 永不变化而陷入死循环，必须 1-indexed。误区二：以为 `lowbit` 是某种魔法哈希——它只是「最低置位位对应的权值」，与补码取负等价。

误区三：以为任意区间最值也能用 BIT——最值不满足可减性，单 BIT 不行。误区四：忽略 Python 中 `i & -i` 对负数也正确（补码语义）。误区五：把 `bit` 长度设为 $n$ 而非 $n+1$，导致最大下标 `n` 的更新越界。

误区六：以为 `lowbit` 只用于 BIT。它同样用于处理「最低置位」的位运算题（如统计置位数、模拟进位），是通用技巧。误区七：以为跳数是固定 $O(\log n)$ 的「实际常数也小」。期望跳数约为 $\frac{1}{2}\log_2 n$，在最坏（全 1 的二进制）时才是 $\log_2 n + 1$。

## 八、面试题
1. 解释 `lowbit(x) = x & -x` 的作用？答：取到 $x$ 最低位的 1 对应权值，决定 `bit[i]` 管理的区间长度与爬升步长。
2. 为什么树状数组必须 1-indexed？答：lowbit(0)=0 会导致循环不前进；1-indexed 使每个下标都有正 lowbit，路径正常终止。
3. 单 BIT 的时间复杂度与空间？答：更新/查询均 $O(\log n)$，空间 $O(n)$。
4. 为什么期望跳数是 $\frac{1}{2}\log_2 n$？答：每个二进制位为 1 的概率约 1/2，跳数等于置位位数。
5. 为什么 `x & -x` 能取到最低置位？答：补码下 $-x = \sim x + 1$，与 $x$ 相与后只剩最低置位及其后的 0。
6. 前缀分解为什么不重不漏？答：按二进制置位逐位切分，每段长度恰为对应 $2^k$，右端点互为前一段的左边界减一。

## 九、演进与趋势
树状数组可扩展到「区间加/区间求和」（两个 BIT）、二维 BIT（矩形统计）、可持久化 BIT（历史版本查询）。在竞赛与系统代码中，BIT 常以「差分数组 + BIT」组合实现在线区间修改，取代线段树以降低常数。

硬件层面，单点加的对数步数对缓存友好（访问地址局部聚集在 lowbit 链上），这使其在实际跑分中常优于递归线段树。近年还出现「分块 BIT」以进一步改善缓存局部性，用轻微的空间换显著的实际速度。

## 十、小结
树状数组用 lowbit 把前缀和拆成 $O(\log n)$ 个区间段，以极小常数与代码量实现单点加与前缀查询的对数复杂度，是前缀统计最简洁高效的结构。lowbit 是连接「位运算」与「区间分解」的桥梁。掌握「向上爬覆盖、向下跳拆分」这一对称性，以及「1-indexed 的必然性」，就掌握了 BIT 的全部要点。
