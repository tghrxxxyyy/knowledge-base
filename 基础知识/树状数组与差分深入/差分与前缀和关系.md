# 差分与前缀和关系

> 对应 Sedgewick《Algorithms》第 14 章、CLRS《算法导论》第 10.3 节（前缀和）、Fenwick 1989（差分数组与 BIT 关系）。

## 一、背景与挑战
对数组做「多次区间统一加值、最后查询整体结果」是批量修改场景（如充值流水、区间染色、日程覆盖）的常见需求。朴素地每次遍历区间 $O(n)$ 在 $m$ 次修改下为 $O(nm)$。差分数组（difference array）把每次区间加降到 $O(1)$，最后整体前缀和一次性还原，把修改与查询解耦；而前缀和是差分的逆运算，二者构成一对对偶变换。

理解这对对偶关系，是掌握「区间修改类」问题的钥匙：几乎所有「区间加 + 单点/区间查询」都能用差分或其 BIT 升级版解决。

对偶关系有一个直观的解释：前缀和是「求和的逆运算」（由 $a$ 得 $S$），差分是「求差的逆运算」（由 $a$ 得 $d$）；施加「差分」再施加「前缀和」得到原数组，施加「前缀和」再施加「差分」同样得到原数组（在合适的边界约定下）。正是这种可逆性，使「区间操作」能在差分域中变成「端点操作」，再变换回原域即得结果。

## 二、核心原理
差分 $d[i] = a[i] - a[i-1]$（约定 $a[0]=0$，即 $d[1]=a[1]$）。对原数组区间 $[l,r]$ 加 $v$，只需在差分数组上做两点修改：`d[l] += v`（从此处开始整体抬升）与 `d[r+1] -= v`（在右界之后抵消抬升）。最后对 $d$ 求前缀和即得修改后的 $a$。

若把差分本身用树状数组维护，则还能在线的单点/前缀查询，不必等全部修改完再还原。差分的本质是「把区间操作压成端点操作」，这是它能从 $O(n)$ 降到 $O(1)$ 的根本原因。

这一「端点化」思想的普适性值得强调：二维的矩形加可以化为四个角点修改（二维差分），区间异或可以化为两个端点异或（异或差分），区间乘（元素非零时）可以化为端点乘法。凡是「可交换、可逆」的区间操作，都能套用差分框架。

需要考虑的边界情况：当 $r = n$ 时，`d[r+1]` 越界，正确做法是「不写」而非写零——把差分数组开成 $n+2$ 长度并允许写 `d[n+1]`（其值不参与还原）是更省心的做法。

## 三、形式化与数学基础
设原数组 $a[1..n]$，差分 $d[1..n]$，$d[i]=a[i]-a[i-1]$（令 $a[0]=0$）。区间加 $[l,r]$ 加 $v$：

$$ d[l] \leftarrow d[l] + v,\qquad d[r+1] \leftarrow d[r+1] - v $$

还原（前缀和）：

$$ a[i] = \sum_{k=1}^{i} d[k] $$

单批区间加 $O(1)$，整体还原 $O(n)$；配合 BIT 维护差分后，单点/前缀查询也可 $O(\log n)$：

$$ T_{add} = O(1),\quad T_{query} = O(\log n) $$

从线性代数视角看，前缀和是一个上三角矩阵 $P$（$P_{ij} = 1$ 当 $i \ge j$），差分是它的逆矩阵 $D = P^{-1}$（$D_{ii}=1$、$D_{i,i-1}=-1$，其余为 0）。区间加在原域是「向量的稀疏相加」$a + v \cdot \mathbf{1}_{[l,r]}$，在差分域则变成 $d + v \cdot (\mathbf{e}_l - \mathbf{e}_{r+1})$——两个基向量的线性组合。这正是「区间操作变端点操作」的代数本质。

「在线区间加 + 区间求和」可用双 BIT 实现：维护 $B_1[i] = d[i]$ 与 $B_2[i] = i \cdot d[i]$，则前缀和 $\sum_{k=1}^{x} a[k] = (x+1)\sum_{k\le x} B_1[k] - \sum_{k \le x} B_2[k]$。

## 四、代码实现
```python
def range_add_diff(d, l, r, v):
    # d 长度 n+2，1-indexed，a[0]=0
    d[l] += v
    if r + 1 < len(d):
        d[r + 1] -= v          # 右界外抵消

def reconstruct(a, d):
    cur = 0
    for i in range(1, len(a) + 1):
        cur += d[i]            # 前缀和还原
        a[i - 1] = cur
```

若在线查询某点，可用 BIT 维护 $d$，`prefix(i)` 即 $a[i]$。区间加则变为 `add(l, v)` 与 `add(r+1, -v)` 两点更新。

二维差分（矩形加 $[x_1,x_2]\times[y_1,y_2]$ 加 $v$）用四角容斥：

```python
def rect_add_2d(d, x1, y1, x2, y2, v):
    # d 为 (n+2) x (m+2) 的二维差分数组，1-indexed
    d[x1][y1]         += v
    d[x1][y2 + 1]     -= v
    d[x2 + 1][y1]     -= v
    d[x2 + 1][y2 + 1] += v    # 右下角补回（容斥）
# 还原：对 d 做二维前缀和，即得每个位置的实际值
```

## 五、与其他技术对比
| 维度 | 直接遍历区间 | 差分数组 | 线段树 | BIT+差分 |
| --- | --- | --- | --- | --- |
| 区间加 | $O(n)$ | $O(1)$ | $O(\log n)$ | $O(\log n)$ |
| 离线还原 | — | $O(n)$ | — | $O(\log n)$ 查询 |
| 递归/常数 | 无 | 极小 | 有 | 小 |
| 支持在线查询 | 是 | 否 | 是 | 是 |
| 支持区间最值 | 否 | 否 | 是 | 否 |
| 二维扩展 | 困难 | 四角容斥 | 需二维线段树 | 二维 BIT |

差分把批量加与查询解耦，常数极小但适合「离线统一还原」；线段树支持在线区间加但更重；BIT+差分兼得在线与轻量。若还要求区间最值，则只能上线段树（最值不可减，无法用差分表示）。

## 六、常见误区
误区一：忘记 `d[r+1] -= v`，导致 $r$ 之后的元素也跟着抬升，区间越界错误。误区二：忽略 `r+1` 越界判断，当 $r=n$ 时写入 `d[n+1]` 越界。

误区三：把差分与前缀和当成同一操作——差分是「相邻差」，前缀和是「相邻和」，互为逆运算。误区四：以为差分能直接在线回答任意点值而不还原——需先整体前缀和或用 BIT 维护差分。误区五：在 $l>r$ 时未校验，导致端点颠倒。

误区六：以为差分适用于任何区间操作。它依赖操作的「可逆 + 可交换」，最值这类不可减的操作不适用。误区七：混淆「差分数组用于离线批量修改」与「BIT 维护差分实现在线修改」两种不同用法，前者 $O(1)$ 改、$O(n)$ 还原，后者两者都是 $O(\log n)$。

## 八、面试题
1. 用差分实现多次区间加后求最终数组？答：每次 `d[l]+=v, d[r+1]-=v`，最后对 $d$ 做前缀和。
2. 如何在线查询某点？答：用 BIT 维护差分数组，`prefix(i)` 即该点当前值，区间加变为两点 BIT 更新。
3. 差分与前缀和的关系？答：互为逆运算，一个是「相邻差」一个是「相邻和」。
4. 二维差分怎么做？答：用四角容斥的二维差分数组，矩形加 $[x1,x2]\times[y1,y2]$ 加 $v$ 化为四点修改。
5. 为什么差分不能处理区间最值？答：最值不可减（无法由前缀信息推出区间信息），不满足差分所需的可逆性。
6. 如何用两个 BIT 实现区间加 + 区间和？答：维护 $B_1[i]=d[i]$ 与 $B_2[i]=i\cdot d[i]$，区间和化为两前缀的线性组合。

## 九、演进与趋势
差分与 BIT 结合可实现「在线区间加 + 区间求和」（双 BIT 法）；与二维差分结合可支持矩形区域加（四角容斥）。在算法竞赛中，差分是处理覆盖类、区间染色类问题的基础技巧，常与扫描线、贪心配合。

工程上，差分的「端点记录」思想也出现在时序数据库的 delta-of-delta 编码、列式存储的增量压缩中——用「相邻差值」而非绝对值存储，能显著提升压缩率，本质上与差分数组同源。

## 十、小结
差分数组把区间加降为 $O(1)$，与前缀和互为逆运算，是批量修改的利器；配合 BIT 可进一步获得在线查询能力，是线段树的轻量替代。理解「差分 = 前缀和的逆矩阵」这一代数视角，可以从容地把该技巧推广到二维、异或差分等变体，并在遇到「操作不可逆」时立刻意识到它不适用。
