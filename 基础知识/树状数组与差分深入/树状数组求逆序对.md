# 树状数组求逆序对

> 对应 Fenwick 1989 原始论文、CLRS《算法导论》第 2.4 节（逆序对）、Sedgewick《Algorithms》第 14 章。

## 一、背景与挑战
逆序对计数（数组中有多少对 $(i,j)$ 满足 $i<j$ 且 $a[i]>a[j]$）是排序、距离度量与统计中的经典问题。朴素双重循环 $O(n^2)$ 在 $n$ 达 $10^5$ 时不可行。借助树状数组配合离散化，可把复杂度降到 $O(n\log n)$，且相比归并排序更易扩展为「带权逆序对」「每个位置的逆序数」等变体。

逆序对还与「数组距离插入排序运行时间」「偏序计数」紧密相关，是许多算法题的底层子问题。

工程上还有两点常被忽视：其一，答案可能非常大，$n=10^5$ 时逆序对数最多约 $5\times10^9$，超出 32 位有符号整型上界，必须用 64 位；其二，BIT 的更新与查询必须严格配对（每次插入一次更新、每次统计一次查询），漏掉或多算一次都会产生系统性偏差，且这种偏差在小样本上不易暴露。

## 二、核心原理
核心思想是从右向左扫描数组，对每个值查询「已经扫描过（即位于其右侧）且比它小的元素个数」，该值即它贡献的逆序对数，再把当前值插入 BIT。等价地，也可从左向右扫描，查询「已出现且比它大的元素个数」。

由于原值可能很大或离散，需先离散化（排序去重映射到排名），使 BIT 下标落在 $[1,n]$ 范围。注意 BIT 下标必须 1-indexed，故排名从 1 开始。相等元素不计入逆序，离散化用 `set` 去重后逻辑自然成立。

为什么两种扫描方向等价？从右向左时，每个当前位置只需统计「右侧且更小」的个数；从左向右时，改为统计「左侧且更大」的个数；二者对每一对逆序对恰好各计一次，故总和相同。实践中从右向左更常见，因为它天然对应「计算每位置右侧更小元素个数」这一常见输出需求。BIT 之所以适用，是因为它支持两类操作——前缀和查询与单点更新——而「统计满足值域条件的已见个数」恰好是前缀和查询，插入恰好是单点更新，二者都是 $O(\log n)$，因而总复杂度为 $O(n\log n)$。

## 三、形式化与数学基础
设离散化后排名为 $r(x)$。从右向左扫描，逆序总数：

$$ Inv = \sum_{k=1}^{n} \big(\text{已见且小于 } a[k] \text{ 的元素数}\big)
      = \sum_{k=1}^{n} P(r(a[k]) - 1) $$

其中 $P(t)$ 为 BIT 前缀查询。离散化 $O(n\log n)$，扫描 $n$ 次各 $O(\log n)$：

$$ T = O(n\log n),\quad \text{空间 } O(n) $$

特别地，每个位置 $k$ 的逆序数即其被扫描时的 $P(r(a[k])-1)$。

可从「逆序对数 = 插入排序需要交换的次数」得到另一种推导：插入排序把元素 $a[k]$ 插入已排序前缀时，需要跨越的元素数恰为其逆序数，故总和等于总交换次数，这也是 CLRS 用逆序对给出插入排序下界的原因。BIT 的复杂度来自它的位运算结构：`i & (-i)` 取最低有效位（lowbit），使更新路径与查询路径各含 $O(\log n)$ 个节点，二者互为逆序路径。当 $n=10^5$ 时 $\log_2 n \approx 17$，故循环体执行约百万次量级，远快于 $O(n^2)$ 的百亿次。

## 四、代码实现
```python
def count_inversions(arr):
    # 离散化：把原值映射到 1..m 的排名（去重后按升序编号）
    sorted_vals = sorted(set(arr))
    rank = {v: i + 1 for i, v in enumerate(sorted_vals)}
    bit = [0] * (len(sorted_vals) + 1)
    inv = 0
    def add(i, d):
        # 沿 lowbit 向上更新所有覆盖点 i 的节点
        while i < len(bit):
            bit[i] += d
            i += i & (-i)
    def prefix(i):
        # 沿 lowbit 向下累加，得到 [1..i] 的计数和
        s = 0
        while i > 0:
            s += bit[i]
            i -= i & (-i)
        return s
    for x in reversed(arr):          # 从右向左
        r = rank[x]
        inv += prefix(r - 1)          # 已见且严格小于 x 的个数
        add(r, 1)                     # 把 x 计入已见集合
    return inv

# 变体：同时返回每个位置的逆序数（右侧更小元素个数）
def count_inversions_per_pos(arr):
    sorted_vals = sorted(set(arr))
    rank = {v: i + 1 for i, v in enumerate(sorted_vals)}
    bit = [0] * (len(sorted_vals) + 1)
    res = [0] * len(arr)
    def add(i):
        while i < len(bit):
            bit[i] += 1
            i += i & (-i)
    def prefix(i):
        s = 0
        while i > 0:
            s += bit[i]
            i -= i & (-i)
        return s
    for k in range(len(arr) - 1, -1, -1):
        r = rank[arr[k]]
        res[k] = prefix(r - 1)        # 记录而非仅累加
        add(r)
    return res
```

注意 `prefix(r - 1)` 中的 `-1` 是「严格小于」的实现：若写成 `prefix(r)`，则已出现的相等元素也被计入，而相等不构成逆序。若数组保证元素互不相同，这一差别不受影响；但一旦存在重复值就会多算，这是最高频的实现错误。

## 五、与其他技术对比
| 方法 | 复杂度 | 是否需要离散化 | 可扩展性 | 常数 | 是否在线 |
| --- | --- | --- | --- | --- | --- |
| 朴素双重循环 | $O(n^2)$ | 否 | 差 | 极小 | 是 |
| 归并排序 | $O(n\log n)$ | 否 | 中（易求总数） | 中 | 否（离线） |
| 树状数组 | $O(n\log n)$ | 是 | 高（易求每位置） | 小 | 是 |
| 线段树 | $O(n\log n)$ | 是 | 最高（可带复杂合并） | 较大 | 是 |
| 平衡 BST / 有序容器 | $O(n\log n)$ | 否 | 中 | 大 | 是 |

BIT 写法更直观且易扩展为带权统计；归并排序不需离散化但扩展每位置逆序数略麻烦（需在合并时计数）。线段树与 BIT 同阶但更通用，代价是常数更大；有序容器（如平衡树）免去离散化但当常数与内存开销明显。

## 六、常见误区
误区一：未离散化就用大值域作 BIT 下标，导致数组开到值域大小而爆内存——必须先排序去重映射。误区二：`prefix(r-1)` 写成 `prefix(r)`，会把「等于自身」的已见元素算入逆序，而相等不算逆序。

误区三：扫描方向和查询方向弄反，导致把左侧元素也算进去。误区四：忽略重复值——离散化用 `set` 去重后，相等元素应计为 0 逆序，逻辑自然成立。误区五：以为 BIT 求逆序对比归并排序「更快」——同阶，区别在可扩展性与实现直观度。误区六：BIT 下标从 0 开始，导致 `i & (-i)` 在 $i=0$ 时恒为 0 而死循环——必须 1-indexed。误区七：用 32 位整型存答案，结果在大规模数据上静默溢出。

## 八、面试题
1. 用 BIT 求逆序对，复杂度与离散化原因？答：$O(n\log n)$；离散化把值域压到排名空间，避免开超大数组。
2. 能否同时求每个位置的逆序数？答：能，扫描时把 `prefix(r-1)` 作为该位置的逆序数记录即可。
3. 与归并排序相比优劣？答：BIT 需离散化但易扩展；归并无需离散化，求每位置略繁。
4. 如何求「带权逆序对」（如 $\sum (a[i]-a[j])$）？答：维护两个 BIT 分别计数量与元素和，按排名区间查询后组合。
5. 为什么 BIT 下标必须从 1 开始？答：`i & (-i)` 依赖最低有效位，$i=0$ 时 lowbit 为 0 会使更新陷入死循环，1-indexed 是该结构的前提而非习惯。
6. 逆序对数会不会溢出？答：会，最大约为 $n(n-1)/2$，$n=10^5$ 时已超 32 位，须用 64 位整型；BIT 下标也必须从 1 开始，否则 `i & (-i)` 恒为 0 而死循环。

## 九、演进与趋势
二维逆序对、带权逆序对可用多维 BIT 或 CDQ 分治（离线处理三维偏序）；「动态逆序对」（边删边查）可用 BIT + 树套树或可持久化结构。BIT 求逆序对也是许多计数题（如出列顺序、逆序距离）的子步骤。在数据库系统中，逆序对计数近似衡量「乱序程度」，可用于判断是否需要重排（如 LSM-tree 的 compaction 触发）。更一般地，「统计满足值域条件的历史元素」是一类通用模式，逆序对只是它最简单的特例；掌握该模式后，诸如「区间内小于阈值的个数」等问题都能用同一套「离线 + BIT」框架解决。

## 十、小结
树状数组从右向左统计「已见且小于当前值」的元素数，以 $O(n\log n)$ 求逆序对；离散化是落地前提，BIT 的在线可扩展性优于归并排序。

三条落地要点：离散化（把值域压到排名）、严格小于（查询 `prefix(r-1)`）、1-indexed（否则死循环）。掌握这三点即可稳定写出正确且高效的实现。
