# 树状数组区间求和

> 对应 Fenwick 1989《A New Data Structure for Cumulative Frequency Tables》、Sedgewick《Algorithms》第 14 章、CLRS《算法导论》第 10.3 节（前缀和背景）。

## 一、背景与挑战
区间 $[l,r]$ 求和是最常见的离线/在线查询之一。朴素地对数组每次遍历是 $O(n)$，在高频查询下不可接受。前缀和数组能在 $O(1)$ 回答区间和，但单点更新需 $O(n)$ 重写前缀。当「点更新」与「区间查询」交替出现（如实时计数、频率统计、滑动窗口聚合）时，需要一种既支持快速更新又支持快速区间求和的结构，树状数组（Fenwick Tree）正是为此而生。

它与线段树都能做到两点 $O(\log n)$，但代码量与常数显著更小，是竞赛与系统代码中的首选。代价是只擅长「前缀/单点」类操作，任意区间最值需另寻结构。

从抽象层面看，树状数组解决的是「可减半群」上的动态前缀查询问题：只要操作满足结合律且存在逆元（如加法、异或），就能用 BIT 维护；若不存在逆元（如最值、最大公约数），则 BIT 无法直接支持区间查询，必须改用线段树一类「保留中间结果」的结构。这一判据是选型时最该先问的问题。

## 二、核心原理
基于「单点加 + 前缀和」的维护，任意区间和可由两个前缀和相减得到：`range(l, r) = prefix(r) - prefix(l-1)`。树状数组用 lowbit 把前缀和维护拆成 $O(\log n)$ 段，使得单点加与前缀查询均为 $O(\log n)$。

关键点在于：下标必须从 1 开始（便于 `i & -i` 的二进制分解），`prefix(0)` 约定为 0，因此查询 `l=1` 时 `prefix(0)` 自然返回 0，无需特判。区间求和本身不修改数组，只是查询，所以可视为「两次前缀查询的差」。

「两次前缀之差」这一恒等式是 BIT 区间求和的全部内容，也是最容易出错的地方：左端点必须用 `l-1`，否则会「少减一项」而多算 $a[l]$。这个 off-by-one 是 BIT 相关题目最高频的错误来源。

## 三、形式化与数学基础
设原数组为 $a[1..n]$，树状数组 `bit[i]` 维护区间 $(i - \text{lowbit}(i),\; i]$ 的和。前缀和：

$$ P(i) = \sum_{k=1}^{i} a[k] = \bigoplus_{j} bit[j],\quad j \text{ 由 } i \text{ 反复减 lowbit 得到} $$

区间和：

$$ \text{range}(l,r) = P(r) - P(l-1) $$

每次操作跳数等于 $i$ 的二进制中 1 的个数，期望 $O(\log n)$，最坏 $\lfloor\log_2 n\rfloor+1$。故单次区间求和 $O(\log n)$，$m$ 次查询 $O(m\log n)$。

「可减半群」条件的形式化：区间查询要求能由「前缀信息」推出区间信息，即存在逆运算使 $\text{range}(l,r) = f(P(r), P(l-1))$。加法满足（$f$ 为减法），异或满足（$f$ 为异或），但最值不满足（无法由「前缀最大值」推出「区间最大值」——因为最大值可能来自被减去的部分）。

若还要求「区间加 + 区间和」，可用双 BIT：维护 $B_1[i] = d[i]$、$B_2[i] = i \cdot d[i]$（$d$ 为差分），则

$$ \sum_{k=1}^{x} a[k] = (x+1)\sum_{k \le x} B_1[k] - \sum_{k \le x} B_2[k] $$

## 四、代码实现
```python
class Fenwick:
    def __init__(self, n):
        self.bit = [0] * (n + 1)          # 1-indexed
    def add(self, i, delta):
        while i < len(self.bit):
            self.bit[i] += delta
            i += i & (-i)
    def prefix(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & (-i)
        return s
    def range_sum(self, l, r):
        # 左闭右闭 [l, r]
        return self.prefix(r) - self.prefix(l - 1)
```

若只需查询，可一次性把 `bit` 建好（用 `add` 逐个插入，或用「前缀和优化建树」在 $O(n)$ 完成），避免每次从零构造。

$O(n)$ 建树与双 BIT 区间加/区间和：

```python
    def build(self, a):
        n = len(a)
        self.bit = [0] * (n + 1)
        for i in range(1, n + 1):
            self.bit[i] += a[i - 1]
            j = i + (i & -i)              # 向上贡献给父节点，O(n) 建树
            if j <= n:
                self.bit[j] += self.bit[i]

class RangeAddRangeSum:                    # 双 BIT：区间加 + 区间和
    def __init__(self, n):
        self.b1, self.b2 = Fenwick(n), Fenwick(n)
    def range_add(self, l, r, v):          # [l, r] 整体加 v
        self.b1.add(l, v);     self.b1.add(r + 1, -v)
        self.b2.add(l, v * l); self.b2.add(r + 1, -v * (r + 1))
    def prefix_sum(self, x):               # 前 x 项之和
        return (x + 1) * self.b1.prefix(x) - self.b2.prefix(x)
```

## 五、与其他技术对比
| 维度 | 朴素数组 | 前缀和数组 | 树状数组 | 线段树 |
| --- | --- | --- | --- | --- |
| 单点加 | $O(1)$ | $O(n)$ | $O(\log n)$ | $O(\log n)$ |
| 区间和 | $O(n)$ | $O(1)$ | $O(\log n)$ | $O(\log n)$ |
| 代码量 | 极小 | 小 | 小 | 较大 |
| 区间加/最值 | 不支持 | 不支持 | 需改造 | 原生支持 |
| 空间 | $O(n)$ | $O(n)$ | $O(n)$ | 约 $4n$ |
| 常数 | 最小 | 最小 | 小 | 较大 |

树状数组在区间求和上比线段树更短更快，但任意区间最值与区间修改需额外改造（双 BIT 或差分）。选型的判据是「操作是否可减」：可减（和、异或、乘积）优先 BIT；不可减（最值、GCD）只能用线段树。

## 六、常见误区
误区一：左端点用 `l` 而非 `l-1` 相减，会少算元素 $a[l]$。误区二：下标从 0 开始传入导致 `i -= i & -i` 死循环——树状数组必须 1-indexed。误区三：以为树状数组能直接做区间加——单 BIT 只擅长单点加/区间和，区间加需双 BIT 或差分技巧。

误区四：忽略 `prefix(0)=0` 约定，手动特判反而出错。误区五：把区间和当「可直接维护」而非「两前缀之差」，导致在更新语义上混乱。

误区六：以为 BIT 能求区间最值。最值不可减，单 BIT 无法支持，需线段树或稀疏表（静态）。误区七：忽略整数溢出。若元素与 $n$ 都很大，前缀和可能溢出 32 位，需用 64 位整型。

## 八、面试题
1. 用 BIT 实现区间和，时间复杂度？答：`prefix` 两次各 $O(\log n)$，合计 $O(\log n)$，空间 $O(n)$。
2. 如何用两个 BIT 支持区间加+区间和？答：用 $B[i]=a[i]$ 与 $B2[i]=i\cdot a[i]$ 两个树状数组，区间加 $[l,r]$ 加 $v$ 等价于在两点更新，区间和公式化为前缀差。
3. 树状数组能求区间最值吗？答：单 BIT 不行（最值不满足可减性），需线段树或特定 RMQ 结构。
4. 为什么 BIT 比线段树更适合本场景？答：区间求和满足可减性，BIT 用 lowbit 以极小常数实现，省去递归与左右子节点维护。
5. 忘记 `l-1` 会发生什么？答：区间和会多算 $a[l]$，是最常见的 off-by-one 错误。
6. 什么操作不能用 BIT 做区间查询？答：不可减的操作，如最值、最大公约数，因为它们无法由两个前缀结果相减得到。

## 九、演进与趋势
Fenwick 与差分数组结合可支持「区间修改 + 区间查询」；与离线前缀和、莫队算法组合可解更复杂的区间统计。可持久化 BIT（用线段树套用持久化思路）支持历史版本查询；二维 BIT 把矩形区域求和降到 $O(\log n\log m)$。

在数据库与流处理中，BIT 常用于实时指标聚合（如 PV/UV 的区间累计），替代代价更高的全量扫描。工程实现上还常用「分段 BIT」：把大数组切成若干块，每块一个小 BIT，以改善缓存局部性并支持并行更新。

## 十、小结
树状数组区间求和即「两前缀和之差」，单次 $O(\log n)$，是前缀统计最简洁高效的结构。它用 lowbit 把更新与查询都压到对数级，是介于朴素数组与线段树之间的最佳折中。掌握「可减才可用 BIT」这一判据，以及「左端点必须减一」这一细节，就能在正确性与效率上同时做对。
