# 树状数组单点更新

> 对应 Fenwick 1989《A New Data Structure for Cumulative Frequency Tables》、Sedgewick《Algorithms》第 14 章、CLRS《算法导论》第 10.3 节。

## 一、背景与挑战
单点更新（给某个下标加/减值）是树状数组最基本的写操作。若每次更新都重建前缀和数组需 $O(n)$，在高频更新下不可行。树状数组要求：更新某个下标后，所有覆盖该下标的前缀区间都必须同步修改，且保持后续任意前缀查询一致。

如何用最少的操作覆盖所有相关区间，是 BIT 更新设计的核心。答案正是 lowbit 链：它恰好枚举了「以该下标为右端点的所有管理区间」。

这一需求的本质是「局部修改如何影响全局聚合」。在普通数组里，改一个元素只影响它自己；在前缀和数组里，改一个元素影响其后所有前缀；在树状数组中，改一个元素只影响 $O(\log n)$ 个节点——BIT 正是通过「把每个前缀分解为对数个节点」，把修改的传播范围从 $O(n)$ 压缩到 $O(\log n)$。

## 二、核心原理
从下标 $i$ 出发，沿 `i += lowbit(i)` 不断向上爬，把路径上每一个 `bit[j]`（即管理区间包含 $i$ 的节点）加上 delta。由于 `bit[j]` 管理的区间恰为 $(j-lowbit(j), j]$，任何包含 $i$ 的前缀区间其对应 BIT 节点必在 $i$ 的 lowbit 链上，因此这条路径恰好覆盖所有受影响节点，且每个节点被更新恰好一次。

查询前缀时反向沿 `i -= lowbit(i)` 累加，二者对称。这一对称性是 BIT 正确性的核心保证：更新与查询走同一条「区间分解」路径的正反向。

「每个节点被更新恰好一次」这一点值得验证：假设 lowbit 链上出现重复节点 $j$，则从 $i$ 出发有两条不同路径到达 $j$，但每次跳转都是确定的（$j \leftarrow j + lowbit(j)$），故路径唯一，不存在重复。同时链上节点的管理区间都包含 $i$（可归纳证明），故也不遗漏。

初始建树也有 $O(n)$ 的优化写法：对每个 $i$，把 $a[i]$ 加到 `bit[i]`，再把 `bit[i]` 累加到 `bit[i + lowbit(i)]`。这比逐点 `add` 的 $O(n\log n)$ 快一倍。

## 三、形式化与数学基础
设 `bit` 节点 $j$ 覆盖 $(j-lowbit(j), j]$。更新 $a[i] \mathrel{+}= \delta$ 时，受影响节点集合为：

$$ \{j \mid i \le j < i+lowbit(i),\; j \text{ 由 } i \text{ 反复加 lowbit 得到}\} $$

路径长度等于 $i$ 的二进制中 1 的个数 $popcount(i)$：

$$ T_{update} = O(\log n),\quad T_{prefix} = O(\log n) $$

所有受影响的 BIT 节点被恰好更新一次，无重复无遗漏，保证前缀查询一致性。最坏路径长为 $\lfloor\log_2 n\rfloor+1$。

更精确的路径长度刻画：从 $i$ 出发，每次加 lowbit 至少把「最低的 1」进位到更高位，因此最高位只会前进、不会后退，路径长度不超过二进制位数。链的终点是「大于 $n$ 或不大于 $n$ 的最大二次幂」——若 $n$ 是 2 的幂，则 $i=n$ 的 lowbit 为 $n$，下一跳为 $2n$ 越界，路径立即终止。

空间复杂度 $O(n)$：只需一个长度为 $n+1$ 的数组。这是 BIT 相对线段树（需 $4n$ 数组）的显著优势，对大 $n$ 场景意义重大。

## 四、代码实现
```python
class Fenwick:
    def __init__(self, n):
        self.bit = [0] * (n + 1)     # 1-indexed
    def point_add(self, i, delta):
        while i < len(self.bit):
            self.bit[i] += delta
            i += i & (-i)             # 沿 lowbit 链向上
    def prefix(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & (-i)             # 沿 lowbit 链向下
        return s
```

`delta` 可正可负：减某值即传入负 delta，无需单独实现。若 `bit[i]` 用 `atomic` 类型，单点更新可做到无锁并发（但查询需可见性保证）。

$O(n)$ 建树（比逐个 `point_add` 快一倍）：

```python
    def build(self, a):
        n = len(a)
        self.bit = [0] * (n + 1)
        for i in range(1, n + 1):
            self.bit[i] += a[i - 1]                 # 先放入自身元素
            j = i + (i & -i)                        # 再向上贡献给父节点
            if j <= n:
                self.bit[j] += self.bit[i]
```

## 五、与其他技术对比
| 维度 | 重建前缀和数组 | 树状数组单点更新 | 线段树单点更新 |
| --- | --- | --- | --- |
| 更新 | $O(n)$ | $O(\log n)$ | $O(\log n)$ |
| 前缀查询 | $O(1)$ | $O(\log n)$ | $O(\log n)$ |
| 代码量 | 极小 | 小 | 较大 |
| 空间 | $O(n)$ | $O(n)$ | 约 $4n$ |
| 缓存友好度 | 高 | 高（地址聚集） | 较低（递归/跳转） |
| 可扩展能力 | 无 | 二维/可持久化 | 区间加/最值等更通用 |

相比重建前缀和（$O(n)$），BIT 单点更新仅 $O(\log n)$；相比线段树同样对数但代码更短、常数更小、缓存更友好。代价是 BIT 的通用性弱：区间最值、区间赋值等操作它难以支持。

## 六、常见误区
误区一：更新循环条件写成 `i <= n` 而 `bit` 长度若恰为 $n$ 会越界，安全写法是 `i < len(self.bit)`（即 `i <= n`）。误区二：以为 delta 只能为正——减即传负。

误区三：把 `i += i & -i` 写成 `i += 1`，会破坏 lowbit 链导致部分前缀区间未更新、查询结果错误。误区四：下标从 0 开始传入导致死循环。误区五：误以为更新只影响 `bit[i]` 一个节点——实际影响整条 lowbit 链上的所有祖先节点。

误区六：以为并发更新无需同步。多线程同时更新同一 BIT 会相互覆盖，除非按 bit 节点分片或用原子操作并保证查询可见性。误区七：以为建树必须 $O(n\log n)$。可用 $O(n)$ 的「向上贡献」建树法显著加速。

## 八、面试题
1. 写一个支持单点加与前缀查的 BIT？答：见上文 `point_add` / `prefix`，各 $O(\log n)$。
2. 单点更新为何是 $O(\log n)$？答：路径长度等于二进制中 1 的个数，最坏 $\lfloor\log_2 n\rfloor+1$。
3. 如何扩展为区间加？答：维护差分数组的两个 BIT，区间 $[l,r]$ 加 $v$ 变为 `add(l,v)` 与 `add(r+1,-v)` 两点更新。
4. 为什么 BIT 节点被更新恰好一次？答：lowbit 链上的节点集合恰好是所有管理区间包含 $i$ 的节点，且互不重叠覆盖，无重复。
5. 如何 $O(n)$ 建树？答：对每个 $i$ 先把 $a[i]$ 放入 `bit[i]`，再把 `bit[i]` 累加到 `bit[i+lowbit(i)]`。
6. BIT 相比线段树的空间优势？答：BIT 只需 $O(n)$ 数组，线段树通常需约 $4n$。

## 九、演进与趋势
单点更新是 BIT 一切扩展的基石：区间加/区间和、二维 BIT、可持久化 BIT 都建立在单点加之上。现代实现中，BIT 常以「差分数组 + BIT」组合实现在线区间修改，取代线段树以降低常数。

硬件层面，lowbit 链的访问地址局部聚集，对 CPU 缓存预取友好，使 BIT 在实测中常优于递归线段树；在 NUMA 上需注意节点跨核访问的额外延迟。

## 十、小结
树状数组单点更新沿 lowbit 链 $O(\log n)$ 修改所有覆盖区间，保持前缀一致；它是 BIT 所有高级用法的底层原语，代码短、常数小、易实现。掌握「更新向上爬、查询向下跳」的双向对称，以及「路径唯一且覆盖完整」的证明思路，就掌握了 BIT 正确性的全部要点。
