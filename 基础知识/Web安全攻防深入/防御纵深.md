# 防御纵深

> 对应纵深防御（Defense in Depth）安全架构原则。

## 一、背景与挑战
单一防线失效即全盘崩溃。纵深防御以多层、异构控制降低单点失守影响，是 Web 安全体系的核心设计哲学。

## 二、核心原理
- 多层：边界防火墙、WAF、认证、授权、输入校验、输出编码、监控层层设防。
- 异构：不同层用不同机制，避免同类漏洞同时击穿。
- 失败安全（fail-safe）：组件失效时默认拒绝而非放行。
- 最小权限与隔离：即使一层被突破也限制横向移动。

## 三、形式化 / 数学基础
- 若各层独立失效概率 $p_i$，纵深后综合突破概率 $P_{break} \approx \prod p_i$（远小于单层）。
- 纵深收益随层数 $k$ 指数下降：$P \propto p^k$。
- 失败安全：$deny$ 为默认决策 $d_0$，仅当全部层通过才 $allow$。
- 隔离度：横向移动成本随网段/身份域数量上升。

## 四、代码实现
```python
def handle(req):
    if not waf_pass(req):        return 403   # 第一层
    if not authenticate(req):    return 401   # 第二层
    if not authorize(req.user):  return 403   # 第三层
    data = validate(escape(req.body))          # 第四层 输入校验+输出编码
    return render(data)
# 默认拒绝：任何未显式允许皆拒绝
```

## 五、与其他技术对比
- 单点强防护 vs 纵深：前者失效即崩；纵深降级运行。
- 预防 vs 检测响应：纵深包含检测层（见告警/可观测性）。
- 网络隔离 vs 应用控制：互补。

## 六、常见误区
- 有了 WAF 就忽略参数化（WAF 可被绕过）。
- 各层用同一机制（同源漏洞）。
- 失败默认放行（应默认拒绝）。
