# 伙伴系统分配合并原理

> 对应 Silberschatz《Operating System Concepts》与 Tanenbaum《Modern Operating Systems》。

## 一、背景与挑战
连续物理页分配若随意切分会产生外部碎片，使大块请求无法满足。伙伴系统以 2 的幂大小与「成对合并」策略，在高效分配的同时限制碎片。

## 二、核心原理
空闲页按阶（order，块含 $2^{order}$ 页）组织在链表中。分配时取满足需求的最小阶块，若更高阶空闲则 recursively 拆分一半给伙伴；释放时若伙伴也空闲则合并为高一阶，重复直到伙伴忙或达上限。

## 三、形式化与数学基础
块地址对齐到其大小，伙伴计算：

$$ \text{buddy}(addr, order) = addr \oplus (1 \ll (order + PAGE\_SHIFT)) $$

合并条件：伙伴块空闲且属于同一阶。

$$ \text{merge if } \text{free}(buddy) \land \text{order}(buddy)=order $$

该结构保证任何空闲块都可被唯一拆分/合并，外部碎片可控。

## 四、代码实现
伙伴分配核心（概念）：

```c
struct page *alloc_pages(unsigned order) {
    for (int o = order; o < MAX_ORDER; o++) {
        if (!list_empty(&free_area[o])) {
            struct page *p = pop(&free_area[o]);
            while (o > order) {        // 拆分
                o--;
                list_add(&buddy(p, o), &free_area[o]);
            }
            return p;
        }
    }
    return NULL;                        // 内存不足
}
```

## 五、与其他技术对比
首次适配等算法碎片更不可控；伙伴系统以 2 幂约束换取 O(1) 合并；slab 在其上切小对象；与段式分配不同，伙伴系统是页级连续分配。

## 六、常见误区
认为伙伴系统无碎片，内部（块大于需求）与外部（高阶难凑）碎片都存在；认为伙伴地址就是 addr+size，实际用异或算；忽略阶上限。

## 七、与开源书/权威来源对应
Silberschatz 第 8 章伙伴系统；Tanenbaum《Modern Operating Systems》；Linux mm/page_alloc.c 是工业级实现。

## 八、面试题
伙伴地址如何计算；为何能快速合并；碎片来源；与 slab 关系。

## 九、演进与趋势
防碎片迁移类型（movable/unmovable）把碎片隔离；大页与 CMA 在伙伴系统之上管理连续内存。

## 十、小结
伙伴系统以 2 的幂块与异或伙伴计算，在连续物理页分配中实现高效的拆分与合并，是内核页分配器的核心算法。
