# 页面迁移类型与碎片避免

> 对应 Linux 内核 Documentation/vm/ 与 Silberschatz《Operating System Concepts》。

## 一、背景与挑战
长期运行后，不可移动页散布在空闲区之间，会把连续空闲页切碎，使大块（如大页、DMA）分配失败。按「可移动性」分类页面可从根源减少碎片。

## 二、核心原理
伙伴系统把页按迁移类型分桶：不可移动（内核永久结构）、可回收（如页缓存，可丢弃）、可移动（用户匿名页，可迁移）。分配尽量在同类型内满足；当某类型不足时按优先级借用，并在回收/迁移时把可移动页挪走，腾出连续空闲区。

## 三、形式化与数学基础
迁移类型集合 $M = \{\text{unmovable}, \text{reclaimable}, \text{movable}, \dots\}$。空闲块按类型分入 $F_{o,m}$。分配优先：

$$ \text{alloc}(o, m): \text{try } F_{o,m} \to \text{fallback } F_{o,m'} $$

碎片指数（内核 /proc/buddyinfo 概念）：

$$ \text{fragmentation} \uparrow \iff \text{unmovable 散落} $$

迁移可移动页使连续块重组。

## 四、代码实现
fallback 顺序（内核定义）：

```c
// 简化：分配失败时的回退类型顺序
const int fallback[MIGRATE_TYPES] = {
    [MIGRATE_UNMOVABLE]   = MIGRATE_RECLAIMABLE,
    [MIGRATE_RECLAIMABLE] = MIGRATE_MOVABLE,
    [MIGRATE_MOVABLE]     = MIGRATE_RECLAIMABLE,
};
```

分配时先本类型，再按 fallback 借。

## 五、与其他技术对比
不分类型的伙伴系统允许任意混合导致碎片；迁移类型通过「隔离」不同寿命页面降低碎片；CMA（连续内存分配器）进一步预留可移动区域供大块使用。

## 六、常见误区
认为可移动页真的随意搬，需页表更新与冻结；认为不可移动页可迁移，内核永久结构不行；忽略 fallback 会污染目标类型。

## 七、与开源书/权威来源对应
Linux Documentation/vm/page_migration.rst 与 伙伴系统代码；Silberschatz 讨论碎片；OSTEP 涉及内存压缩。

## 八、面试题
迁移类型有哪些；为何减少碎片；fallback 作用；CMA 用途。

## 九、演进与趋势
内存压缩（compaction）配合迁移类型回收连续块；大页透明化依赖低碎片环境。

## 十、小结
按可移动性对页面分类并隔离，使伙伴系统能在运行时维持连续空闲区，是避免外部碎片、支持大页与 DMA 的核心机制。
