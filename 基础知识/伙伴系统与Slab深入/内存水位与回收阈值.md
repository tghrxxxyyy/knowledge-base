# 内存水位与回收阈值

> 对应 Linux 内核 Documentation/vm/ 与 Silberschatz《Operating System Concepts》。

## 一、背景与挑战
系统需在内存耗尽前主动回收，否则突发的分配失败会卡住关键路径。通过水位线（WMARK）设定空闲内存阈值，触发异步与同步回收。

## 二、核心原理
每个 zone 设三个水位：min、low、high。空闲低于 low 触发 kswapd 异步回收；低于 min 则分配者自己同步回收（direct reclaim）；高于 high 时 kswapd 停止。水位按 zone 总内存比例计算，避免过早或过晚回收。

## 三、形式化与数学基础
设空闲页数 $F$。行为：

$$ F < min \implies \text{direct reclaim（分配者自己回收）} $$
$$ low \le F < high \implies \text{kswapd 回收中} $$
$$ F \ge high \implies \text{kswapd 休眠} $$

watermark 计算（简化）：

$$ min = \text{total} \times \frac{1}{2^{order+2}} \times \text{调节因子} $$

low 与 high 在 min 上加回补区。

## 四、代码实现
水位检查（概念）：

```c
int zone_watermark_ok(struct zone *z, unsigned order, int alloc_flags) {
    long free = zone_page_state(z, NR_FREE_PAGES);
    long min = z->watermark[WMARK_MIN] + (1 << order);
    if (free <= min) return 0;
    if (free >= z->watermark[WMARK_LOW])
        wake_kswapd(z, order);   // 触发异步回收
    return 1;
}
```

## 五、与其他技术对比
无水位则分配直到 OOM；固定阈值难适配不同内存大小，比例水位更通用；与 memcg 的层级限额正交，分别控制全局与容器级。

## 六、常见误区
认为 kswapd 总能及时，内存暴涨会触及 min 引发直接回收卡顿；认为水位越高越好，过高浪费可用内存；忽略 NUMA 下各 zone 独立水位。

## 七、与开源书/权威来源对应
Linux Documentation/vm/balance.rst 与 watermark 代码；Silberschatz 讨论页回收；Hennessy & Patterson 论存储层次。

## 八、面试题
三个水位含义；kswapd 何时启动；直接回收为何慢；水位如何计算。

## 九、演进与趋势
PSI（Pressure Stall Information）提供更细的内存压力信号；内存多代回收（MGLRU）改进回收效率。

## 十、小结
内存水位以 min/low/high 三级阈值把回收从「被动 OOM」变为「主动平滑」，是内核平衡性能与可用性的关键控制环。
