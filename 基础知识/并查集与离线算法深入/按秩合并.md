# 按秩合并

> 对应 Tarjan 1975 并查集论文、CLRS《Introduction to Algorithms》第 21 章「不相交集合」，以及 Union by Rank / Union by Size 的标准分析。

## 一、背景与挑战

并查集若在 `union` 时随手把一棵树的根挂到另一棵下面，最坏会退化：反复把「深度大的树」挂到「深度小的树」上，或总是把元素 $n$ 挂到元素 $1$ 上，形成深度 $O(n)$ 的链。此时单次 `find` 就要爬 $n$ 层，$m$ 次操作 $O(mn)$，$10^5$ 规模直接超时。

路径压缩能事后补救，但它是「均摊」意义上的优化：在压缩生效之前，某些 `find` 已经很慢；而且若分析只靠路径压缩、合并方向仍任意，证明也更绕。**按秩合并（union by rank）**从源头控制形状：合并时永远把「矮的树」挂到「高的树」下面，两棵树高度相同时才让高度加一。这样树高被钉在 $O(\log n)$，无需压缩也不退化。

与路径压缩结合后，得到教科书级结论：$m$ 次操作总代价 $O(m\,\alpha(n))$，$\alpha$ 为反阿克曼函数。工程上按秩（或按大小 `size`）合并几乎是标配——Kruskal、连通块、账户合并等实现都会带上，因为「树高可控」让递归 `find` 不爆栈、也让最坏情况可解释。

面试里常考「证明按秩合并树高 $O(\log n)$」「rank 和 size 用哪个、更新时机」「为什么 rank 在路径压缩后不更新也没关系」。这些问题都要求把不变量说清楚。

## 二、核心原理

### 2.1 秩（rank）的定义

每个根结点维护一个 `rank[x]`，表示「以 $x$ 为根的树高上界」。注意是上界，不是精确高度——路径压缩会让实际高度小于 rank，rank 只用于决定合并方向，这并不破坏正确性。

叶子初始 `rank = 0`。合并两棵树时：

- 若 `rank[ra] < rank[rb]`，把 `ra` 挂到 `rb` 下，`rank[rb]` 不变；
- 若 `rank[ra] > rank[rb]`，把 `rb` 挂到 `ra` 下，`rank[ra]` 不变；
- 若相等，任选一边挂接（通常 `rb` 挂到 `ra`），然后 `rank[ra] += 1`。

### 2.2 不变量

1. **划分不变量**：`parent` 森林始终表示当前的集合划分；压缩与合并不跨集合改边。
2. **秩不变量**：对任意根 $x$，若 `rank[x] = k`，则以 $x$ 为根的树高 $\le k$，且至少有 $2^k$ 个结点。
3. **合并单调**：挂接后，新根的 rank 不小于旧的两个 rank，至多加 1。

### 2.3 按大小（size）合并

另一种等价启发式：维护子树大小，把**小树挂到大树**下。它同样保证树高 $O(\log n)$（更直观：每向上一层，子树至少翻倍），而且 size 在「按排名取元素」「启发式合并字符串」里可直接复用。区别是：

- rank 合并：高度上界，相等才 +1；
- size 合并：`size[ra] += size[rb]`，常数更直观。

二者渐进相同。带权并查集常用 size 方向以减少遍历；纯连通性二者皆可。

### 2.4 与路径压缩的关系

按秩合并单独就把树高限制在 $\log_2 n$；路径压缩单独（任意合并）也能均摊到对数级。二者**叠加**才有 $\alpha(n)$。注意：路径压缩不更新 rank（也不需要），因为 rank 只是「上界启发式」；若强行用实际高度做 rank，压缩后高度变化，维护成本高且没必要。

## 三、形式化与数学基础

**树高界**。对根 $x$，记 $S(x)$ 为子树大小。归纳：`rank[x] = 0` 时 $S = 1 = 2^0$。合并时：

- 秩不同时，矮树挂到高树下，新树高不变，$S$ 增大，界仍成立；
- 秩相同为 $k$ 时挂接，新 rank $k+1$，新子树大小 $\ge 2^k + 2^k = 2^{k+1}$。

故 $\text{rank}[x] = k \Rightarrow S(x) \ge 2^k$，从而

$$\text{rank}[x] \le \log_2 n, \quad \text{树高} \le \log_2 n.$$

于是**仅按秩合并**时，单次 `find` 最坏 $O(\log n)$，$m$ 次操作 $O(m \log n)$。

**叠加路径压缩**。Tarjan 1975 的逆阿克曼分析给出 $O(m\,\alpha(n))$。直觉：rank 把结点分成「量级」$0,1,2,\ldots$；压缩把路径上结点提到根，使大量结点的「到根秩差」变为 0。势能函数可取

$$\Phi = \sum_{x \text{ 非根}} \text{rank 相关的等级},$$

每次 find 的均摊代价正比于势能下降，总势能与 $n\alpha(n)$ 同阶。

**反阿克曼函数** $\alpha(n)$：设 Ackermann $A(1,j)=2^j$，$A(i,1)=A(i-1,2)$，$A(i,j)=A(i-1,A(i,j-1))$，则 $\alpha(n)=\min\{k:A(k,4)\ge n\}$（定义细节随教材微调）。它增长比任何 $\log^{*}$ 更慢，对现实 $n$ 是 4 以内的常数。

## 四、代码实现

按秩合并 + 路径压缩完整实现，含按大小变体与经典用例（连通块计数、Kruskal MST）。

```python
class DSURank:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n
        self.count = n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]  # 隔代压缩
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1
        self.count -= 1
        return True

    def connected(self, a, b):
        return self.find(a) == self.find(b)


class DSUSize:
    """按大小合并，size 可用于启发式合并。"""

    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        return True


# ---------- Kruskal 最小生成树 ----------
def kruskal(n, edges):
    """edges: (w, u, v)，返回 (总权重, 选中的边列表)。"""
    edges = sorted(edges)
    dsu = DSURank(n)
    total, mst = 0, []
    for w, u, v in edges:
        if dsu.union(u, v):
            total += w
            mst.append((u, v, w))
            if len(mst) == n - 1:
                break
    return total, mst


# ---------- 连通块计数 ----------
def count_components(n, edges):
    dsu = DSURank(n)
    for u, v in edges:
        dsu.union(u, v)
    return dsu.count


if __name__ == "__main__":
    # 秩增长与树高
    d = DSURank(8)
    # 合并 0-1, 2-3, 0-2, 4-5, 6-7, 4-6, 0-4
    for a, b in [(0, 1), (2, 3), (0, 2), (4, 5), (6, 7), (4, 6), (0, 4)]:
        d.union(a, b)
    root = d.find(0)
    assert all(d.find(i) == root for i in range(8))
    assert d.count == 1
    assert d.rank[root] <= 3  # 树高上界

    # Kruskal
    edges = [(1, 0, 1), (2, 0, 2), (3, 1, 2), (4, 1, 3), (5, 2, 3)]
    w, mst = kruskal(4, edges)
    assert w == 1 + 2 + 4  # 0-1,0-2,1-3
    assert len(mst) == 3

    # 连通块
    assert count_components(5, [(0, 1), (1, 2), (3, 4)]) == 2

    # 按大小
    s = DSUSize(6)
    s.union(0, 1)
    s.union(2, 3)
    s.union(0, 2)
    r = s.find(0)
    assert s.size[r] == 4
    print("union by rank ok")
```

要点：`union` 永远「小秩挂大秩」；秩相等才 `rank += 1`。`DSUSize` 的 `size` 只在 `union` 更新。Kruskal 排序后贪心加边，`union` 返回假即成环跳过。

## 五、与其他技术对比

| 维度 | 按秩合并 | 按大小合并 | 任意方向 | 随机合并 |
|------|----------|------------|----------|----------|
| 树高 | $O(\log n)$ | $O(\log n)$ | 最坏 $O(n)$ | 期望 $O(\log n)$ |
| 额外字段 | rank | size | 无 | 无 |
| 与路径压缩叠加 | $O(\alpha(n))$ | $O(\alpha(n))$ | 均摊 $O(\log n)$ | 均摊 $O(\alpha(n))$ |
| 适用 | 通用、证明方便 | 需要子树大小 | 仅原型 | 不想维护字段 |
| 实现 | 极简 | 极简 | 最简 | 简单 |

**取舍**：需要「连通块大小」「启发式合并集合」时用 size；只需连通性、想要标准证明用 rank；随机合并省一个数组，但期望分析更绕。生产代码几乎总是 rank 或 size 二选一。

## 六、常见误区

**误区一：rank 与 size 混用更新规则。** rank 只在「相等合并」时 +1；size 是加和。把 rank 当 size 加会破坏上界语义，树高分析失效。

**误区二：路径压缩后修改 rank。** 压缩只改 parent，不应改 rank；rank 是合并用的上界，不是实时高度。改它反而增加复杂度且无必要。

**误区三：合并方向写反（大挂小）。** 等于没有按秩，树可退化成链，递归 `find` 爆栈、复杂度回退到 $O(n)$ 每次。

**误区四：以为按秩合并就不用路径压缩。** 只按秩是 $O(\log n)$ 均摊级；叠加压缩才近常数。面试要说清二者关系。

**误区五：递归 `find` + 不按秩。** 深链递归 Python 爆栈。要么迭代压缩，要么合并时保秩。

## 八、面试题

**Q1：证明按秩合并树高 $O(\log n)$。**
A：`rank[x] = k` 时子树大小 $\ge 2^k$。合并同秩时高度才加一且大小至少翻倍，故 $k \le \log_2 n$，树高有界。

**Q2：rank 和 size 怎么选？**
A：只要连通性用 rank，证明经典；要集合大小或启发式合并用 size。两者渐进相同。

**Q3：为什么路径压缩不更新 rank？**
A：rank 只是合并启发式的上界，不是精确高度；压缩后实际高度下降，但更新 rank 成本高且不影响正确性与 $\alpha(n)$ 界。

**Q4：带权并查集合并时权重怎么维护？**
A：挂在小秩/小树下时，要调整挂接根的「到新父的权」，保证路径上的权值语义（距离、异或、种类）不变；方向由秩/大小决定。

## 九、演进与趋势

**按秩 + 带权**是竞赛标配（食物链、银河英雄传说）。**启发式合并**（小表并进大表）在字符串、bitset、图邻接表合并中广泛应用，思想同源。**可持久化并查集**常按秩控制树高，降低主席树深度。**并行并查集**（多线程 union）需要原子挂接与仍能证明的启发式。面试趋势是把「$\alpha(n)$ 直觉 + 秩不变量 + 工程选型」一起考，而不是默写代码。

## 十、小结

按秩合并通过「小秩挂大秩、同秩才增高」把树高钉在 $O(\log n)$，消除任意合并的退化风险；与路径压缩叠加得到 $O(\alpha(n))$ 反阿克曼均摊，是并查集「几乎常数」神话的另一半。rank 与 size 各有场景，更新规则不可混用。掌握秩不变量，才能在 Kruskal、连通块、带权并查集里写对、讲清、答稳。
