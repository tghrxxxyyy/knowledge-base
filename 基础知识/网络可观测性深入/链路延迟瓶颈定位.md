# 链路延迟瓶颈定位

> 对应 Brendan Gregg 性能分析与 Google SRE 延迟管理；参考 Vonng/ddia。

## 一、背景与挑战
端到端延迟由多段组成（DNS、TCP 握手、TLS、处理、排队）。定位瓶颈需分层拆解。

## 二、核心原理
用延迟分解法：在各阶段打点（connect、TLS handshake、first byte、processing），结合 trace 与 RED，找出最大贡献段。

## 三、形式化与数学基础
端到端延迟分解：
  T_total = T_dns + T_tcp + T_tls + T_server + T_queue + T_network
关键路径上的最大项即瓶颈：
  bottleneck = argmax_i T_i
各段可用直方图（p50/p95/p99）观察长尾。

## 四、代码实现
// Go 分阶段计时
t0 := time.Now()
conn, _ := net.Dial("tcp", addr)        // T_tcp
tls.Client(conn, cfg).Handshake()       // T_tls
req.Write(conn)                          // T_network
resp.Read()                              // T_server + T_queue
log latencyBreakdown(t0, phases)

## 五、与其他技术对比
黑盒监控只能看总和，白盒打点+trace 才能定位具体阶段。

## 六、常见误区
1. 只看平均延迟忽略 p99 长尾。
2. 把网络 RTT 当服务端处理时间。
