# 可观测性三大支柱

> 对应 Google SRE Book（Monitoring Distributed Systems）与 OpenTelemetry 文档；参考 Vonng/ddia。

## 一、背景与挑战
分布式系统中，仅"能否工作"不够，还需理解"为何这样"。Metrics、Logs、Traces 三支柱互补，构成可观测性。

## 二、核心原理
- Metrics：聚合数值（QPS、延迟、错误率），适合告警与趋势。
- Logs：离散事件记录，适合事后排错。
- Traces：单次请求跨服务调用链，适合定位瓶颈。

## 三、形式化与数学基础
RED 指标（请求服务）：
  Rate = requests/sec
  Errors = error_rate
  Duration = p50/p95/p99 latency
USE 指标（资源）：
  Utilization, Saturation, Errors
三者关联：trace 定位 -> metric 量化 -> log 取证。

## 四、代码实现
# Prometheus 指标示例（Python）
from prometheus_client import Counter, Histogram
REQ = Counter("http_requests_total", "total", ["method"])
LAT = Histogram("http_latency_seconds", "lat")
@LAT.time()
def handle(req):
    REQ.labels(req.method).inc()
    return do(req)

## 五、与其他技术对比
传统监控偏指标，可观测性强调从输出推断内部状态，依赖高基数 trace/context。

## 六、常见误区
1. 只采集 metrics 自称可观测——缺 trace 难定位跨服务问题。
2. 日志打印敏感信息或过度导致成本爆炸。
