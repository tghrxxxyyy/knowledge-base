# 死锁与优先级反转

> 对应 Tanenbaum《Modern Operating Systems》死锁章节 / remzi-arpacidusse/ostep-code。

## 一、背景与挑战
多线程按不同顺序获取多把锁易形成循环等待(死锁)。优先级反转中，高优先级线程被持锁的低优先级线程阻塞，且被中优先级线程抢占，导致"高优先级等低优先级"。

## 二、核心原理
死锁四条件：互斥、持有并等待、不可抢占、循环等待。打破任一即可。优先级反转在 Mars Pathfinder 曾导致重启，靠优先级继承(PI)解决。

## 三、形式化与数学基础
资源分配图含环是死锁必要(在单实例资源为充分)条件。Banker 算法基于安全序列：
$$ \exists \text{序列} \langle P_1..P_n\rangle : Need_i \le Work $$
保持 $Work$ 单调增长则安全，否则可能死锁。

## 四、代码实现
```c
// 固定锁顺序避免循环等待
void transfer(Account* a, Account* b, int amt) {
    Account* first  = (a->id < b->id) ? a : b;   // 全局序
    Account* second = (a->id < b->id) ? b : a;
    lock(first); lock(second);
    // ... 转账 ...
    unlock(second); unlock(first);
}
```

## 五、与其他技术对比
死锁是永久停滞，活锁是反复退让不前进，饥饿是长期得不到资源。优先级反转介于其间，靠协议而非算法消除。

## 六、常见误区
认为加超时即可——超时仅缓解非根治。忽视嵌套锁顺序。优先级继承配置缺失导致反转重现。
