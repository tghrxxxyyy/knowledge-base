# 自旋锁与阻塞锁权衡

> 对应 remzi-arpacidusse/ostep-code (GitHub) / Tanenbaum《Modern Operating Systems》同步章节。

## 一、背景与挑战
临界区极短时，线程挂起/唤醒的上下文切换开销(数微秒)远超过锁持有时间。选错锁类型会浪费大量 CPU 或引入不必要调度。

## 二、核心原理
自旋锁在无法获取时忙等(busy-wait)，不切换上下文，适合多核短临界区。阻塞锁(互斥量)在获取失败时让出 CPU 进入睡眠，适合长临界区或单核。混合自旋-阻塞(adaptive mutex)先自旋再阻塞。

## 三、形式化与数学基础
设临界区时间 $C$，上下文切换开销 $S$，自旋锁总等待期望：
$$ T_{spin} = \sum_{i=1}^{k} (C + C_i) $$
阻塞锁额外成本：
$$ T_{block} = S + C + S_{wake} $$
当 $C \ll S$ 时自旋更优。

## 四、代码实现
```c
// 极简 TAS 自旋锁
#include <stdatomic.h>
atomic_int lock = 0;
void acquire() {
    while (atomic_exchange(&lock, 1))   // 测试并设置
        ;                               // 忙等
}
void release() { atomic_store(&lock, 0); }
```

## 五、与其他技术对比
自旋锁零切换但占 CPU；互斥量让出 CPU 但延迟高。读写锁在只读场景更优；无锁结构彻底避免锁。

## 六、常见误区
单核系统自旋锁永远空转浪费(除非抢占关闭)。自旋过久等于 DoS 自身。未设内存屏障导致可见性乱序。

## 九、演进与趋势
qspinlock(排队自旋)、MCS 锁减少缓存一致性流量；futex 把阻塞下沉到内核。

## 十、小结
锁的选择取决于临界区长度与核数：短小多核选自旋，长久单核选阻塞，混合最常用。
