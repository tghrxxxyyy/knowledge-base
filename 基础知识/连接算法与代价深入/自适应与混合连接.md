# 自适应与混合连接

> 对应 cmu-db/15445-course（adaptive query processing / hybrid join lecture），以及 Vonng/ddia 第 3 章（执行相关）。

## 一、背景与挑战
静态选连接算法在统计不准或数据倾斜时易选错。自适应/混合连接在运行时根据观测（如基数、倾斜、内存）切换或融合算法，提升鲁棒性。

## 二、核心原理
- 混合 Hash/Merge：依内存与排序状态动态选。
- Adaptive Hash Join：先按是否内存充足决定 build 或转 grace。
- 运行时重优化（如 Eddy）：元组在算子间动态路由。
- 倾斜感知：检测到热点键转为广播或特殊处理。

## 三、形式化与数学基础
自适应期望代价：
$$ E[Cost] = \sum_i p_i \cdot cost_i $$
其中 $p_i$ 为运行时观测到的情形概率（如内存充足与否）。目标最小化：
$$ \min_{policy} E[Cost] $$
倾斜键比例 $\alpha$ 高时触发特殊处理分支。

## 四、代码实现
```python
# 自适应选择 hash/grace（仅示意）
def adaptive_hash(R, S, mem_budget):
    if R.size < mem_budget:
        return in_memory_hash(R, S)     # 内存够：直接建
    else:
        return grace_hash(R, S)         # 不够：分区后连接
```

## 五、与其他技术对比
静态优化依赖预估，易错；自适应增加一点运行时开销换取稳健。代价是执行器更复杂、可预测性降低。

## 六、常见误区
1) 认为自适应总能救错估——切换本身有成本。
2) 忽视观测开销。
3) 误以为混合连接无副作用——可能重复处理。
