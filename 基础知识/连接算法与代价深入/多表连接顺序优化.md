# 多表连接顺序优化

> 对应 Garcia-Molina《Database Systems: The Complete Book》第 16 章（join order / dynamic programming），以及 cmu-db/15445-course（join ordering lecture）。

## 一、背景与挑战
多表连接（如 10 张表）有阶乘级的连接顺序。顺序极大影响中间结果大小与总代价，需在可行时间内找到近优顺序。

## 二、核心原理
- 动态规划：按“子查询子集”递推最小代价，System R 风格，适合表数较少（如 ≤ 10~12）。
- 左深树（left-deep）限制搜索空间以提速。
- 贪心/遗传/随机化用于超多表场景。
- 利用连接图（非连通分量可独立）剪枝。

## 三、形式化与数学基础
可能的二叉树连接顺序数（Catalan 相关）：
$$ \#order \approx \frac{(2n-2)!}{(n-1)!(n-1)!} $$
DP 状态：
$$ dp[subset] = \min_{split} (dp[subset_1] + dp[subset_2] + join\_cost) $$
左深树将搜索从指数降为更可控规模。

## 四、代码实现
```python
# 动态规划连接顺序（仅示意）
def best_order(tables):
    dp = {frozenset([t]): (0, t) for t in tables}
    for size in range(2, len(tables)+1):
        for subset in combinations(tables, size):
            best = INF
            for left in proper_subsets(subset):
                right = subset - left
                c = dp[left][0] + dp[right][0] + join_cost(left, right)
                if c < best: best, dp[subset] = c, (c, (left, right))
    return dp[frozenset(tables)]
```

## 五、与其他技术对比
DP 精确但随表数爆炸；左深限制牺牲部分最优换速度；贪心快但不保证最优。商业优化器常组合（DP + 启发式）。

## 六、常见误区
1) 认为连接顺序无所谓——中间结果膨胀致命。
2) 忽略 DP 状态爆炸。
3) 误以为任何顺序结果相同——结果相同但代价差巨大。
