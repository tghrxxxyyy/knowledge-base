# 流量控制

> 对应 RFC 9293；Kurose & Ross 第 3 章（流控与拥塞控制之别）。

## 一、背景与挑战
发送方可能以远超接收方处理能力（或接收缓冲）的速率发包，导致接收方丢包。流量控制（flow control）保证发送方不淹没接收方，解决“端到端速率匹配”。

## 二、核心原理
接收方在每個 ACK 中通告接收窗口 `rwnd`（剩余可用缓冲区），发送窗口受 `min(cwnd, rwnd)` 约束。`rwnd=0` 时发送方停止发数据，仅允许发 1 字节探测段以打破死锁。

## 三、形式化 / 数学基础
$rwnd_t = R_{buf} - (R_{recv} - R_{acked})$，即缓冲区减去已收未读字节。
发送窗口：$W_{send} = \min(cwnd, rwnd)$。
零窗口探测：每 $RTO$ 或约 1 分钟发 1 字节，迫使接收方回含新 rwnd 的 ACK。

## 四、代码实现
```java
// 接收方更新通告窗口
int free = recvBuffer.capacity() - recvBuffer.occupied();
int rwnd = Math.max(0, free);
tcpHeader.setWindow(rwnd); // 携带在每一个 ACK
```

## 五、与其他技术对比
流量控制针对“接收方缓冲”，是端到端的；拥塞控制针对“网络中间链路”，是多点的。二者通过 `min(cwnd, rwnd)` 共同决定实际发送窗口。

## 六、常见误区
误区一：流量控制防止网络拥塞。错，那是拥塞控制的职责。误区二：rwnd=0 后连接永久挂起。错，有零窗口探测保活。误区三：Silly Window Syndrome 只在发送方。错，接收方也可能（Clark 算法解决）。

## 九、演进与趋势
自动缓冲区调优（autotuning）动态调整 socket 缓冲区与 rwnd；接收端 offload（如 TCP 接收 offload）减轻 CPU。

## 十、小结
流量控制用 rwnd 通告让发送方不超过接收能力，是 `min(cwnd, rwnd)` 中的 rwnd 分量。
