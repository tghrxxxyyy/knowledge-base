# 滑动窗口

> 对应 Tanenbaum《Computer Networks》第 6 章；RFC 9293。

## 一、背景与挑战
停-等协议（stop-and-wait）每发一帧等一个 ACK，信道利用率仅 $1/(1+2a)$（$a=RTT/(L/R)$），在高 BDP 链路上极低。滑动窗口让发送方在未被确认前连续发送多个段，从而“填满管道”。

## 二、核心原理
发送窗口上界由接收方通告的接收窗口 `rwnd` 与拥塞窗口 `cwnd` 共同决定：`发送窗口 = min(cwnd, rwnd)`。窗口内的字节分为“已发送已确认 / 已发送未确认 / 可发送未发送 / 不可发送”四段，随 ACK 到达向右滑动。

## 三、形式化 / 数学基础
可用窗口（usable window）：$W_{use} = \min(cwnd, rwnd) - (S_{last\_ack} - S_{unacked})$。
管道容量（BDP）：$BDP = B \cdot RTT$，理想窗口至少为 BDP 才能跑满带宽。
窗口缩放选项（RFC 7323）：$rwnd_{advertised} = rwnd_{field} \cdot 2^{scale},\ scale\in[0,14]$。

## 四、代码实现
```go
type Sender struct {
    base     uint32 // 最早未确认序号
    next     uint32 // 下一个待发序号
    win      uint32 // 发送窗口 = min(cwnd,rwnd)
}
func (s *Sender) canSend(n uint32) bool {
    return s.next < s.base + s.win
}
```

## 五、与其他技术对比
滑动窗口是“字节流”层面的流控/拥塞窗口抽象；与之相对的是数据链路层的 Go-Back-N 与 Selective Repeat，二者以“帧号”为窗口单位，且通常无拥塞窗口概念。

## 六、常见误区
误区一：窗口单位是“报文段个数”。错，TCP 窗口按字节计。误区二：rwnd 越大越好。错，过大会加剧 bufferbloat。误区三：窗口不滑动直到超时。错，每收到 ACK 即滑动。

## 八、面试题
1. 发送窗口是谁决定的？答：min(cwnd, rwnd)。2. 窗口缩放解决什么问题？答：16 位 rwnd 最大 65535 字节不足以匹配高 BDP 链路。

## 九、演进与趋势
自动调优（autotuning）让 socket 缓冲区随measured BDP 自适应；MPTCP 维护每子流窗口并做耦合拥塞控制。

## 十、小结
滑动窗口用 `min(cwnd, rwnd)` 同时实现流控与拥塞控制，配合窗口缩放才能在现代高带宽链路跑满吞吐。
