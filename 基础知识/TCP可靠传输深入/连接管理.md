# 连接管理

> 对应 RFC 9293（TCP 状态机）；RFC 6528（SYN Cookie）。

## 一、背景与挑战
TCP 面向连接，通信前需建立端到端状态，结束后需优雅释放并防止旧报文干扰新连接。连接管理定义了建立、释放与异常处理的完整状态机。

## 二、核心原理
三次握手建立连接：SYN（seq=ISN_A）→ SYN+ACK（seq=ISN_B, ack=ISN_A+1）→ ACK（ack=ISN_B+1）。
四次挥手释放：FIN → ACK → FIN → ACK；主动关闭方进入 TIME_WAIT 等待 2MSL。

## 三、形式化 / 数学基础
状态转移关键：
$CLOSED \xrightarrow{SYN} SYN\_SENT \xrightarrow{SYN,ACK} ESTABLISHED$。
$TIME\_WAIT$ 持续时间 $= 2\cdot MSL$（MSL 常见 30s–2min，Linux 默认 60s）。
同时打开（simultaneous open）与同时关闭有独立转移路径。

## 四、代码实现
```c
// 典型阻塞服务端
int s = socket(AF_INET, SOCK_STREAM, 0);
bind(s, ...); listen(s, 128);
int c = accept(s, ...);          // 完成三次握手
// ... 读写 ...
close(c);                        // 触发四次挥手
```

## 五、与其他技术对比
UDP 无连接管理，无握手/挥手、无 TIME_WAIT；QUIC 在 UDP 之上自建连接（含 0-RTT），但语义类似“建立/释放”。

## 六、常见误区
误区一：两次握手即可。错，无法确认客户端的接收能力，且易遭旧 SYN 误导。误区二：TIME_WAIT 是 bug。错，它保证最后 ACK 可达并让旧报文消亡。误区三：服务器不会进 TIME_WAIT。错，谁主动关闭谁进。

## 九、演进与趋势
TCP Fast Open（TFO，RFC 7413）在 SYN 携带数据以削减一次 RTT；SYN Cookie 缓解 SYN 洪泛已成为标准实践。

## 十、小结
三次握手建立、四次挥手释放、TIME_WAIT 保安全，是 TCP 面向连接语义的落地。
