# 超时重传

> 对应 RFC 6298（RTO 计算）；RFC 9293。

## 一、背景与挑战
报文可能丢失、乱序或延迟。发送方必须判定“多久没收到 ACK 就算丢”，过短会误重传浪费带宽，过长则恢复慢。超时重传是可靠性的最后兜底机制。

## 二、核心原理
发送方为每个未确认段维护重传定时器；超时则重传并指数退避（binary exponential backoff）。RTO 必须随网络 RTT 动态变化，不能取固定值。

## 三、形式化 / 数学基础
RFC 6298 算法：
$R_{i}$ 为第 i 个采样 RTT，$M$ 为其测量值。
首样本：$SRTT = M,\ RTTVAR = M/2$。
后续：$RTTVAR = (1-\beta)RTTVAR + \beta|SRTT-M|$（$\beta=1/4$）；$SRTT = (1-\alpha)SRTT + \alpha M$（$\alpha=1/8$）。
$RTO = SRTT + 4\cdot RTTVAR$，并钳制 $RTO \ge 1\,\text{s}$。
重传后定时器翻倍：下一个 $RTO' = 2\cdot RTO$（指数退避）。

## 四、代码实现
```python
SRTT = RTTVAR = None
def on_sample(m):
    global SRTT, RTTVAR
    if SRTT is None:
        SRTT, RTTVAR = m, m / 2.0
    else:
        RTTVAR = 0.75 * RTTVAR + 0.25 * abs(SRTT - m)
        SRTT = 0.875 * SRTT + 0.125 * m
    return max(1.0, SRTT + 4 * RTTVAR)
```

## 五、与其他技术对比
超时重传是“消极”的兜底（要等很久才触发）；快速重传依靠重复 ACK 主动探测丢包，恢复快得多。二者互补：没有超时，长期丢 ACK 会卡死；没有快重传，恢复太慢。

## 六、常见误区
误区一：每次重传都重新采样 RTT。错，Karn 算法规定重传的段不参与 RTT 采样（避免二义性）。误区二：RTO 等于平均 RTT。错，还要加 4 倍抖动。

## 八、面试题
1. 为什么 RTO 要加 4×RTTVAR 而非等于 SRTT？答：吸收抖动，避免频繁误重传。2. Karn 算法解决了什么？答：重传段 RTT 采样的二义性。

## 九、演进与趋势
Tail Loss Probe（TLP，RFC 8985）在 RTO 前发送探测段，用 1 个丢包快速恢复，降低尾延迟。

## 十、小结
超时重传靠 RFC 6298 的 SRTT/RTTVAR 估算动态 RTO 并指数退避，是可靠性兜底；Karn 算法与 TLP 是其 refine。
