# RISC-V后端代码生成

> 对应 Appel《Modern Compiler Implementation》第 8-9 章；RISC-V Unprivileged ISA Spec；Waterman & Asanović《The RISC-V Reader》。

## 一、背景与挑战

RISC-V 是规整的加载-存储（load-store）架构：仅基址+12 位符号立即寻址，指令格式少（R/I/S/B/U/J），通用整数寄存器 32 个（x0 恒零）。后端需把 IR 映射到其少量指令与寄存器约定，是学习 RISC 后端设计的典型样本。挑战集中在：大立即/大偏移拆分、调用约定的正确实现、零寄存器 x0 的特殊处理，以及栈帧对齐。这些约束看似简单，却是「教科书 RISC 后端」与「能跑的 RISC 后端」之间的全部距离。

RISC-V 的模块化设计进一步影响了后端结构：基础整数指令集（RV32I/RV64I）之外，M（乘除）、A（原子）、F/D（浮点）、C（压缩）、V（向量）等扩展是可选的。后端必须能按目标配置「启用/禁用」对应指令与寄存器，这要求寄存器分配器与指令选择器都能参数化，而不能把寄存器集合写死。

## 二、核心原理

RISC-V 不支持内存源操作数，复杂表达式须先算地址（`addi`/移位）再 `load/store`。函数调用约定：`a0-a7` 传参（多过 8 个走栈）、`ra` 存返回地址、`sp` 管理栈帧、`s0-s11` 为被调用者保存、`t0-t6` 为调用者保存。后端依次做指令选择（DAG/全局）、寄存器分配（区分 caller/callee 类）、指令调度、发射。所有内存访问偏移受 12 位符号立即限制，超界需经临时寄存器合成。浮点用 `fa0-fa7`/`ft0-ft11` 与 `fs0-fs11`，规则类似。

寄存器分类对分配算法的影响非常直接：调用者保存寄存器（t 类）在调用点不必保存，但跨调用不保活；被调用者保存寄存器（s 类）必须在函数入口保存、出口恢复。寄存器分配器需要在「给活跃变量分配 s 类以跨调用保活」与「避免过多 callee-saved 保存/恢复开销」之间权衡，通常用「优先给跨调用的活跃区间分配 s 类」的启发式。

x0 的处理需要特别小心：写 x0 的指令（如 `addi x0, x0, 5`）在语义上是空操作，可被后端用作「占位/对齐」；读 x0 恒为 0，可用于生成常量 0（`add rd, x0, x0`）或无条件跳转（`jalr x0, ra, 0` 即 `ret`）。把 x0 纳入通用寄存器分配会浪费一个寄存器位，故通常直接排除在可分配集合之外。

## 三、形式化与数学基础

32 位常量拆分（大立即须两段拼装）：

$$imm_{32} = ((imm \gg 12) \ll 12) + (imm \& 0xFFF)$$

用 `lui rd, hi20` 设高 20 位后 `addi rd, rd, lo12` 补低 12 位；因 `addi` 符号扩展，若 `lo12` 为负需把 `hi20` 进位 +1 修正。栈帧偏移同理受 12 位限制，深栈帧需经临时寄存器（`t` 类）间接访问。

$$sp\_offset = (hi20 \ll 12) + sign\_ext(lo12)$$

拆分的进位修正必须精确处理：设目标常量为 $C$，令 $lo = C \& 0xFFF$（12 位无符号），若 $lo \ge 0x800$（即符号扩展后为负），则取 $hi = ((C + 0x1000) \gg 12)$，$lo' = lo - 0x1000$；否则 $hi = C \gg 12$，$lo' = lo$。这样 $hi \ll 12 + lo'$ 恰好等于 $C$。忽略这一修正会让 $C$ 的值为 $C - 0x1000$，产生难以定位的错误。

栈帧布局的约束：RISC-V ABI 要求 `sp` 在函数调用点保持 16 字节对齐（因为 `sd/ld` 双字访问与扩展指令可能要求更宽对齐）。因此栈帧大小必须向上取整到 16 的倍数，即使实际只需要 4 字节。

## 四、代码实现

```asm
# 函数调用约定示例（调用 foo(a0=5) 并保存返回地址）
addi sp, sp, -16        # 开栈帧（16 字节对齐）
sd   ra, 8(sp)           # 保存返回地址（callee-saved 视角由调用者负责 ra）
li   a0, 5               # 参数放入 a0
call foo                 # 跳转并写 ra
ld   ra, 8(sp)           # 恢复 ra
addi sp, sp, 16          # 收栈帧
ret                      # 等价于 jalr zero, ra, 0

# 大立即加载（设 x5 = 0x12345678）
lui  x5, 0x12345         # 高 20 位
addi x5, x5, 0x678       # 低 12 位（符号扩展，若负需进位修正）
```

含进位修正的大立即加载（正确写法）：

```asm
# x6 = 0x12345FFF（低 12 位 0xFFF 为负，需 hi +1 修正）
lui  x6, 0x12346         # 注意：高 20 位已进位 +1
addi x6, x6, -1          # 低 12 位取 0xFFF 的符号值 -1，拼接结果正确
```

## 五、与其他技术对比

| 维度 | RISC-V | x86-64 | ARM-64 |
| --- | --- | --- | --- |
| 寻址 | 基址+12 位立即 | 复杂多模式 | 基址+偏移/前变址 |
| 编码 | 定长 32 位（C 扩展 16） | 变长 | 定长 32 位 |
| 教学性 | 高，规则少 | 低 | 中 |
| 大常量加载 | lui+addi 两条 | 单条 movabs | movz/movk 多条 |
| 条件执行 | 需分支指令 | 需分支（有 cmov） | 多数指令可条件化 |
| 寄存器约定 | ABI 明确 8 参 | 6 寄存器传参 | 8 寄存器传参 |

RISC-V 比 x86 编码简单、易于教学与形式化验证；缺少复杂寻址需更多指令，但解码器与流水线更省面积。它的模块化扩展（M/A/F/D/C/V）让后端可逐步支持，而不破坏基础编码。

## 六、常见误区

1. 大立即未拆分致 `lui`+`addi` 溢出符号位需修正：负 `lo12` 必须向高 20 位进位。
2. 忘记 `ra` 是 caller 视角的返回地址需保存：跨调用不保存会丢失返回点。
3. 误用零寄存器 `x0` 作目标致丢弃结果：`x0` 恒零、写无效，仅适合用于清零/占位。
4. 栈帧未 16 字节对齐：RISC-V ABI 要求 `sp` 在调用点保持对齐，否则 `call` 后访问浮点可能出错。
5. 把 `t` 寄存器当 callee-saved：调用者保存类在调用后值不保，跨调用用 `s` 类才安全。
6. 忽略「调用点」与「函数入口」的对齐要求不同：`sp` 须在调用点对齐，函数内部临时使用可不对齐但恢复时必须还原。
7. 以为浮点寄存器也是 32 个。F/D 扩展下浮点寄存器独立编号，且 `fs0-fs11` 才是被调用者保存类。

## 七、与开源书·权威来源对应

- Appel《Modern Compiler Implementation》第 8-9 章给出 RISC 后端（含寄存器分配与调用约定）流程，可作为 RISC-V 后端的蓝本。

## 八、面试题

1. 问：RISC-V 如何传参？大立即怎么拼？
   答：`a0-a7` 传前 8 个参数，多余走栈；大立即用 `lui` 设高 20 位 + `addi` 补低 12 位（注意符号扩展进位）。
2. 问：为何 RISC-V 无复杂寻址模式？
   答：保持 ISA 规整、定长编码、易流水线化与形式化验证；复杂地址由编译器用 ALU 指令合成，把复杂度从硬件移到软件。
3. 问：`x0` 的作用？
   答：恒零寄存器，用于 `mv rd, x0`（清零）、比较占位（`bne rs, x0, lbl`），写它无效，简化指令集设计。
4. 问：为什么栈要 16 字节对齐？
   答：ABI 要求保证 `sp` 在调用边界对齐，使 `sd`/`ld` 双字访问与 SIMD（若扩展）不跨缓存行错位。
5. 问：大立即拆分时为何要进位修正？
   答：`addi` 的 12 位立即是符号扩展的，低 12 位为负时需要把高 20 位加 1 才能拼出正确常量。
6. 问：callee-saved 与 caller-saved 在使用上如何区分？
   答：跨函数调用需要保活的值必须用 `s` 类（被调用者保存）或自行压栈；只在单次调用内使用的临时值用 `t` 类即可。

## 九、演进与趋势

RISC-V 向量扩展（V）与压缩扩展（C）扩展后端表达能力；B 扩展增位操作、F/D 扩展处理浮点；LLVM 持续完善寄存器分配与指令选择，支持更多扩展组合。形式化验证（如用 ISA 形式语义证明后端正确性）在 RISC-V 上尤为活跃。

工程上，编译器后端的另一趋势是「用声明式 ISA 描述驱动代码生成」：把指令编码、寄存器类、调用约定写成机器可读的描述（如 TableGen），由工具自动生成选择器与编码器，从而在扩展不断增加时仍能保持可维护性。

## 十、小结

RISC-V 后端以规整指令与清晰调用约定展示了 RISC 代码生成的典型流程与权衡。其难度不在单条指令，而在「用最少指令拼出大立即/大偏移、守住建制约定」——这恰是后端工程把高级语义落地为物理机器码的地基。RISC-V 的价值正在于：它把这套后端流程简化到「可以用一节课讲清楚」，却又不失真实工业后端的所有关键约束。
