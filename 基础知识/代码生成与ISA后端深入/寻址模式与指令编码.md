# 寻址模式与指令编码

> 对应 Aho, Sethi & Ullman《Compilers》第 8 章；Appel《Modern Compiler Implementation》第 8 章；Intel/AMD 与 RISC-V 手册。

## 一、背景与挑战

不同 ISA 支持的寻址模式（立即、寄存器、基址+位移、缩放索引、PC 相对）差异巨大，直接决定可生成的指令形态与二进制编码密度。后端必须把抽象的「内存访问」lower 为具体寻址模式，再由编码器填成严格位域的机器码。例如 `a[i]`（i 为 int 下标、元素 4 字节）在 x86 可一条 `mov` 完成，在 RISC-V 则需先算 `base + i*4` 再 load。理解寻址模式与编码约束，才能生成既正确又紧凑的目标代码。

这一环节的复杂度集中体现在「编码器必须精确无误」：与算法层面的错误不同（结果错但能跑），编码错误往往直接导致非法指令或错误访存，且难以通过阅读源码发现。因此工业级后端通常用「声明式描述 + 自动生成」的方式构建编码器，并配套反汇编器做交叉验证。

## 二、核心原理

后端把 IR 中的 `mem[base+idx*scale+disp]` 形式的抽象访问 lowering 为具体寻址模式。x86 允许 `[base+index*scale+disp]`（经 ModRM + SIB 字节描述），RISC-V 仅支持「基址 + 12 位符号立即数」。编码器据操作数类型与寄存器编号将指令模板填为机器码，处理 REX 前缀、ModRM、SIB、重定位与位移宽度（8/32 位）。无法用单条指令表达的复杂地址需先用 ALU 指令合成地址。编码阶段还须处理重定位项（如函数调用目标的链接时填充）。

x86 的编码结构可分层理解：前缀（legacy/REX/VEX）、opcode、ModRM（mod/reg/rm 三段）、SIB（scale/index/base）、displacement、immediate。其中 ModRM 的 mod 与 rm 共同决定「操作数在寄存器还是在内存、以及用哪种寻址」，而 SIB 仅在需要「base+index」时才出现。理解这一层次结构，是从零实现编码器的前提。

RISC-V 的编码则统一得多：所有指令 32 位定长，opcode 在低 7 位，接着是 rd、funct3、rs1、rs2、funct7 等固定字段（具体位置随格式类型 I/S/B/U/J 不同）。这种规整性使解码器可以用「同一套字段提取逻辑」处理绝大多数指令，是 RISC 通过规整性换取解码效率的典型。

## 三、形式化与数学基础

有效地址计算：

$$EA = base + index \times scale + displacement,\quad scale \in \{1,2,4,8\}$$

编码位域（以简化模型示意）：

$$inst = (opcode \ll 32) | (modrm \ll 24) | (reg \ll 21) | (rm \ll 18) | imm$$

具体位宽与位置随 ISA 严格定义；x86 还需 REX 前缀扩展寄存器号与 64 位操作数。RISC-V 的 I 型立即按 `imm[11:0]` 符号扩展，故大偏移需 `lui`+`addi` 拆分，且拆分时若低 12 位为负需向高 20 位进位修正。

从信息论角度可估算「编码密度」的差异：x86 因支持内存源操作数与复杂寻址，完成 `dst += mem[base+idx*scale+disp]` 只需 1 条指令（约 4–8 字节）；RISC-V 需要「算地址（可能 2 条）+ load + add」共约 4 条指令（约 16 字节）。这是 CISC 在代码密度上的天然优势，也是嵌入式场景仍需 CISC 类 ISA 的原因之一。

但密度优势有代价：变长指令使预解码复杂，指令边界需逐字节扫描，因此 x86 需要额外的 uop cache 来避开重复解码的开销。这是「密度 vs 解码复杂度」的经典权衡。

## 四、代码实现

```c
// 编码 add rax, [rbx+8] （x86-64）
void emit_load_add(void) {
    emit(0x48);                 // REX.W：64 位操作数
    emit(0x03);                 // ADD r/m64, r64
    emit(0x43);                 // ModRM: mod=01 reg=000(rax) rm=011(rbx), +disp8
    emit(0x08);                 // disp8 = 8
}
// RISC-V: 加载 mem[sp+16] 到 t0
//  lw t0, 16(sp) -> imm=0x010, rs1=0x02, funct3=0x02, rd=0x05, opcode=0x03
// 大偏移拆分：
//  lui t0, %hi(sym); addi t0, t0, %lo(sym)
```

x86 使用 SIB 字节的两寄存器+缩放寻址（`mov eax, [rbx+rcx*4+16]`）：

```c
void emit_sib_addressing(void) {
    emit(0x8B);                 // MOV r32, r/m32
    emit(0x44);                 // ModRM: mod=01, reg=000(eax), rm=100(需 SIB)
    emit(0x8B);                 // SIB: scale=2(×4), index=001(rcx), base=011(rbx)
    emit(0x10);                 // disp8 = 16
}
```

## 五、与其他技术对比

| 维度 | CISC (x86) | RISC (RISC-V/ARM) |
| --- | --- | --- |
| 寻址模式 | 丰富（多操作数/内存源） | 规整（基址+立即） |
| 编码 | 变长、复杂解码 | 定长/少格式、易流水线 |
| 指令数 | 少 | 多（需先算地址） |
| 代码密度 | 高 | 较低（C 扩展可缓解） |
| 解码开销 | 高（需 uop cache 缓解） | 低 |
| 编译器负担 | 低（硬件做地址计算） | 高（编译器合成地址） |

CISC 丰富寻址减少指令数但解码复杂；RISC 规整编码利于流水线但需多指令合成复杂地址。ARM 介于二者之间：支持前变址/后变址寻址，但仍是定长 32 位（AArch32 有 Thumb 变长）。

## 六、常见误区

1. 误用 32 位寻址模式访问 64 位地址：缺 REX.W 会截断地址宽度，导致错误取指/访存。
2. 位移溢出：x86 仅支持 8/32 位 disp，RISC-V 仅 12 位，超界需重 materialization 到临时寄存器。
3. 忘记 REX 前缀：扩展寄存器（r8–r15）或 64 位操作数必须加 REX，否则编码非法或语义错。
4. 混用符号/零扩展：RISC-V 的 load 立即为符号扩展，`addi` 立即亦符号扩展，大立即拆分须修正高 20 位进位。
5. 忽略重定位：跳转/调用目标在链接前未知，须生成重定位项而非立即数硬编码。
6. 忽略 SIB 的出现条件。只有「base+index」型寻址才需要 SIB，多余添加会使指令长度与语义都出错。
7. 以为编码长度固定。x86 指令长度在 1–15 字节之间变化，位移宽度选择会直接改变指令长度与解码路径。

## 七、与开源书·权威来源对应

## 八、面试题

1. 问：x86 与 RISC-V 寻址差异？REX 前缀作用？ModRM 含义？
   答：x86 支持内存源操作数与复杂寻址，RISC-V 仅基址+12 位立即；REX 扩展寄存器号与 64 位宽度；ModRM 描述操作数来自寄存器还是内存及寻址形式。
2. 问：RISC-V 大立即怎么加载？
   答：`lui rd, hi20` 设高 20 位，`addi rd, rd, lo12` 补低 12 位（符号扩展需修正 hi 进位）。
3. 问：为何 CISC 解码器更贵？
   答：变长指令与多寻址模式需复杂预解码逻辑，占用流水前端面积与功耗，故 x86 引入 uop cache 缓解。
4. 问：为什么位移宽度受限？
   答：编码空间有限，大位移用额外指令（如基址寄存器预加）表达，是 ISA 在「密度 vs 规整」间的取舍。
5. 问：什么时候需要 SIB 字节？
   答：当寻址形如「base + index × scale」时；仅 base 或仅 disp 的情况不需要 SIB。
6. 问：为什么必须生成重定位项？
   答：符号地址在编译期未知，需留给链接器填充；若硬编码会得到错误地址。

## 九、演进与趋势

x86 可变长编码持续加压解码器（引入 uop cache 缓解）；RISC-V 压缩指令（C 扩展）提升密度，B 扩展增位操作；ARM 的 scaled addressing 介于二者之间。新趋势是后端用声明式 ISA 描述（如 TableGen）自动生成编码器与反编码器。

另一趋势是「编译器与 ISA 协同设计」：ISA 设计者会参考编译器的常见模式（如频繁的数组索引、结构体字段访问）来设计寻址模式，从而在硬件复杂度可控的前提下最大化代码质量。这种「面向编译器」的 ISA 设计理念在 RISC-V 的扩展讨论中尤为明显。

## 十、小结

寻址模式决定指令表达力，编码器把抽象内存访问固化为严格位域机器码。后端开发的真正难点往往不在「算对地址」，而在「用最少指令、最少前缀、不溢出位移位宽」地把它编出来——这是 ISA 约束与编译器智慧的交汇点。一个字节编错，整条指令就成非法；编码器的正确性直接决定生成代码能否运行。
