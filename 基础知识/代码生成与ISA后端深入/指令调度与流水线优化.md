# 指令调度与流水线优化

> 对应 Aho 等《Compilers》第 8 章；Appel《Modern Compiler Implementation》第 13 章。

## 一、背景与挑战
现代 CPU 多发射、深流水线，简单按序发射会因数据/结构冒险停顿。指令调度重排不相关指令填补延迟槽，提升 ILP。

## 二、核心原理
基于 DAG 的列表调度：节点为指令，边为数据/资源依赖。每周期从就绪列表选指令发射，满足延迟（如 load 到使用需 3 周期）与功能单元占用。启发式（关键路径优先）最大化吞吐。

## 三、形式化与数学基础
调度长度下界由关键路径决定：
$$len \ge \max_{path} \sum_{i\in path} delay(i)$$
就绪时间 $rdy(n)=\max_{p\in pred(n)} (rdy(p)+latency(p\to n))$，优先发射 $rdy$ 早且处关键路径者。

## 四、代码实现
```python
while not done:
    ready = [n for n in nodes if all(p.sched for p in preds(n))]
    n = max(ready, key=lambda x: critical_len(x))
    schedule(n, cycle); cycle += 1
```

## 五、与其他技术对比
局部（基本块内）调度简单但受限；全局（跨块、trace/超块）调度收益大但需保证语义与异常安全；软件流水用于循环。

## 六、常见误区
1. 调度违反控制依赖致结果错误（需谓词或守卫）。
2. 忽略 RAW/WAW 后需重排寄存器避免伪依赖。
3. 过度依赖静态调度，乱序执行 CPU 可部分吸收。

## 九、演进与趋势
机器学习调度器（如 Google ML 调度）据真实硬件反馈调序，超越手写启发式。

## 十、小结
指令调度用依赖 DAG 与延迟约束重排指令，把流水线空隙压到最小。
