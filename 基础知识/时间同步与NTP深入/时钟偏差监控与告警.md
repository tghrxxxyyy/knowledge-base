# 时钟偏差监控与告警

> 对应 DDIA 第8章「依赖时钟的危险」与 Vogels 2009。

## 一、背景与挑战
即便部署了 NTP，节点仍可能因配置错误、网络隔离或与错误源同步而悄悄偏离。若不监控偏差，故障会在「租约过期」「日志乱序」时才暴露，定位困难。监控的核心是把「时间不确定性」变成可观测指标。

## 二、核心原理
监控项包括：根延迟（root delay）、根离散（root dispersion）、与参考源偏移、stratum 跳变、本地时钟频率漂移率。告警阈值应基于业务可容忍的偏差，而非固定值。chronyd 的 `tracking` 与 `sources` 命令即提供这些量。

## 三、形式化与数学基础
设允许误差界 \\(\epsilon\\)，当前根离散 \\(D\\)，偏移 \\(\theta\\)，则健康条件为
\\[
|\theta| + D \le \epsilon
\\]
一旦越界即告警。漂移率 \\(r\\) 长期超规格预示硬件老化。

## 四、代码实现
```python
import subprocess, re
out = subprocess.check_output(["chronyc", "tracking"]).decode()
m = re.search(r"Last offset\s*:\s*([-\d.e]+)", out)
offset = float(m.group(1))
if abs(offset) > 0.05:   # 50ms 告警
    alert("clock drift too large")
```

## 五、与其他技术对比
逻辑时钟（HLC）把物理偏差收敛到 bounded 范围，监控转为「HLC 物理部分超出阈值」；TrueTime 直接暴露误差界，应用层可读 `epsilon`。

## 六、常见误区
1. 只在出故障后查时间：应持续采集偏移时间序列。
2. 用单一阈值：不同业务（交易、日志）容忍度不同。
3. 忽略 stratum 突变：可能意味着同步源失效。

## 七、与开源书/权威来源对应
DDIA 用案例说明未监控的时钟偏差造成过分布式数据库数据损坏；Vogels 2009 指出时钟不确定性需被显式处理。

## 八、面试题
问：监控 NTP 健康应看哪些指标？
答：root delay、root dispersion、offset、stratum 与漂移率。

## 九、演进与趋势
可观测性平台把时钟偏差作为一等指标，与 trace 或 metric 关联定位「时间相关」故障。

## 十、小结
时钟监控把隐性偏差显性化，是时间敏感系统的必备防护层。
