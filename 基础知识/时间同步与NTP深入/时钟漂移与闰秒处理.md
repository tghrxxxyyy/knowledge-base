# 时钟漂移与闰秒处理

> 对应 Vogels 2009（Eventually Consistent）与 DDIA 第8章「时钟问题」。

## 一、背景与挑战
任何物理时钟都有频率偏差，称为漂移率（drift rate），单位通常是 ppm（百万分之一）。即使 100 ppm 的高稳钟，每天也会偏差约 8.64 秒。更棘手的是「闰秒」——为校正地球自转变慢，UTC 会插入（或罕有删除）一秒，使当天出现 23:59:60。这让依赖「时间单调递增」「一天等于 86400 秒」假设的软件大规模出错。

## 二、核心原理
操作系统维护两类时钟：墙上时钟（wall-clock，可被 NTP 步进或闰秒跳变）与单调时钟（monotonic clock，只增不减，不受 NTP 步进影响）。正确做法是：测量时间间隔用单调时钟；记录事件发生时刻用墙上时钟并容忍误差。闰秒通过「 leap smear 」在数小时内线性分摊，而非瞬间跳变。

## 三、形式化与数学基础
设晶体标称频率 \\(f_0\\)，实测频率 \\(f=f_0(1+\epsilon)\\)，则 \\(T\\) 秒后累积误差约 \\(\Delta t = \epsilon T\\)。漂移率 \\(\epsilon\sim 10^{-4}\\)（100 ppm）时，\\(T=86400\\) 得 \\(\Delta t\approx 8.6\\) 秒。闰秒使墙上时钟在插入点出现重复或跳变，单调性被破坏。

## 四、代码实现
```python
import time

# 正确：用单调时钟测时长
start = time.monotonic()
do_work()
elapsed = time.monotonic() - start

# 错误：用墙上时钟测时长，闰秒会给出负值或异常
start_wall = time.time()
```
Google 的 leap smear 由 NTP 服务端在 24h 内把 1s 平摊到每次回复的偏移中。

## 五、与其他技术对比
GPS 或原子钟系统（如 TrueTime）由硬件保证无闰秒跳变；普通 NTP 客户端需依赖服务商做 smear。逻辑时钟（Lamport/HLC）完全不受闰秒影响，因为它们不依赖物理时间。

## 六、常见误区
1. 认为 `time.time()` 单调递增：墙上时钟会被 NTP 回拨或闰秒重复。
2. 认为一天固定 86400 秒：闰秒日有 86401 秒。
3. 在分布式事务里用本地墙上时钟做版本号：漂移加闰秒导致版本乱序。

## 七、与开源书/权威来源对应
DDIA 明确区分「墙上时钟」与「单调时钟」，并指出闰秒曾导致多家公司大规模故障；Vogels 2009 强调时钟不确定性对最终一致性的影响。

## 八、面试题
问：为什么测时间间隔要用单调时钟？
答：墙上时钟可能被 NTP 步进或闰秒改变，导致间隔为负或异常，单调时钟保证只增不减。

## 九、演进与趋势
业界逐步弃用「跳秒」方案，转向 smear 或改用 TAI（无闰秒原子时）再换算；逻辑时钟的流行也降低了对物理闰秒的依赖。

## 十、小结
时钟漂移是物理必然，闰秒是人为校正；健壮性来自「区分两类时钟 + 接受误差界」，而非假设时间精确。
