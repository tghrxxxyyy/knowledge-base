# 租约与故障检测

> 对应 Chen, Gupta & Welch 2002（Failure Detection in a Nutshell, IEEE TDSC）与 Gray & Lamport 2006（The Byzantine Generals in the lease）。

## 一、背景与挑战

故障检测要「快」又要「准」：太敏感会在网络抖动时误杀健康节点（false positive），引发不必要的主从切换与数据搬运；太迟钝则延长不可用时长（false negative），客户端长时间连着死节点。租约把「检测超时」转化为「权利释放」——二者必须联合设计，否则要么提前释放（误杀），要么延迟释放（双主窗口过长）。如何量化灵敏度并在时延与误报间取得平衡，是分布式系统的基本功，也是共识协议（Raft/Paxos）可用性边界的来源。检测与授权解耦但必须联动。

## 二、核心原理

故障检测器输出「可疑/存活」判断，常见模型是「最终可靠且快」的 $\langle\mathcal{P},\mathcal{S}\rangle$（如 Chandra-Toueg）。租约时长 $T$ 应大于「能在多大概率下判定原持有方失联」所需的探测时间上界，保证租约到期前检测已能确认其失联。实践中用连续 $k$ 轮无应答即判定失败，配合自适应超时（基于观测的 RTT 分位数）抑制抖动误报。二者配合实现「失联即释放」：检测一旦判定失败，等待租约自然到期即回收权利，无需强杀——这既保证安全（不提前释放给新者）又保证最终可用（到期必释放）。关键是：检测决定「何时怀疑」，租约决定「何时权利真正失效」，二者时间点不同。

## 三、形式化与数学基础

设单轮「假死」（本应存活却未应答）概率为 $p$，要求整体误报率 $<\alpha$，需连续 $k$ 轮失败才判定。独立假设下：

$$ (1-p)^k \ge 1-\alpha \quad\Rightarrow\quad k \ge \frac{\ln\alpha}{\ln(1-p)} $$

设每轮探测周期 $T_{probe}$，则判定失败的期望时间在 $k\cdot T_{probe}$ 量级。安全条件要求租约时长覆盖该上界：

$$ T \ge k\cdot T_{probe} + d_{max} + \epsilon $$

其中 $d_{max}$ 为最大网络延迟、$\epsilon$ 为处理时间。这样租约到期时检测早已能确认失联，避免「未确认就释放」或「已释放却仍被认为活着」。注意 $k$ 越大越保守（误报越低）但检测越慢，需在 $\alpha$ 与时延间折中。自适应超时令 $T_{probe}$ 随观测 RTT 调整，避免固定值在大长尾下误杀。

## 四、代码实现

```python
# 基于连续失败的租约撤销决策
def maybe_revoke(fail_count, threshold, now, lease):
    # 检测层已判定失败（连续 threshold 轮无应答）
    if fail_count >= threshold:
        # 不强行杀，等租约自然到期再回收，保证安全窗口
        if now >= lease.expire:
            lease.owner = None
            return True
    return False

# 自适应超时：基于滑动窗口 RTT 分位数
def next_timeout(rtts, quantile=0.99, slack=3):
    return slack * percentile(rtts, quantile)
```

## 五、与其他技术对比

| 机制 | 误报控制 | 与租约关系 |
| --- | --- | --- |
| 固定超时 | 弱（不适应抖动） | 易提前/延迟释放 |
| 自适应超时 | 强 | 联合调优更安全 |
| SWIM（怀疑机制） | 强（间接探测+怀疑） | 互补，可喂给租约 |

对比 SWIM：SWIM 用间接探测与「怀疑」列表降低误报，与租约的超时释放互补；对比静态超时，自适应更鲁棒。Raft 的选举超时即「检测 + 租约」耦合的实例：election timeout 必须远大于心跳间隔，否则易误触发重选。检测与授权是同一枚硬币的两面。

## 六、常见误区

1. 固定超时不适应云环境抖动——网络 RTT 长尾大，固定值要么误杀要么迟钝。
2. 检测与租约解耦导致提前释放——若 $T$ 小于检测上界，可能检测未确认就释放，违反安全。
3. 以为「快速检测」即好——过快的灵敏度抬高误报率 $\alpha$，触发雪崩式切换。
4. 混淆「进程 alive」与「服务健康」——存活不代表能正常服务，需应用层健康检查。
5. 以为检测判失败即权利失效——权利失效永远由租约到期定，检测只决定「何时怀疑」。
6. 忽略误报成本——误杀引发的主从切换可能比短暂不可用代价更高（数据搬运、客户端重连）。

## 七、与开源书·权威来源对应

- Chen, Gupta & Welch 2002：系统综述故障检测的概率模型与灵敏度/误报权衡，给出 $\langle\mathcal{P},\mathcal{S}\rangle$ 框架。
- Chandra & Toueg 1996：不可靠故障检测器与共识的关系，奠定「检测+租约/超时」的理论基础。
- Gray & Lamport 2006：把检测超时与租约安全窗口联合建模。
- Das et al. 2002（SWIM）：可扩展的故障检测协议，含怀疑机制。
- Hunt et al. 2010（ZooKeeper）：会话超时近似租约的工程实践。

## 八、面试题

1. 如何平衡故障检测的灵敏度？
   要点：用连续多轮失败+自适应超时抑制抖动；在误报率 $\alpha$ 与时延间取折中，避免雪崩。
2. 租约时长与检测超时如何联动？
   要点：$T$ 必须 $\ge$ 判定失败所需探测时间上界 + 网络/处理延迟，保证到期前已能确认失联。
3. 误杀（false positive）的后果？
   要点：触发不必要的主从切换，数据搬运与短暂不可用；严重时会话中断。
4. 为什么 Raft 选举超时要远大于心跳间隔？
   要点：否则网络抖动会频繁误判 leader 失联，引发无意义重选与任期震荡。
5. 检测判失败为何不直接剥夺权利？
   要点：直接剥夺可能在旧持有者仍合法时造成双主；等租约到期才释放是安全边界。

## 九、演进与趋势

基于 gossip 的故障检测（如 SWIM）在大规模集群中以对数消息量达成高准确，正逐步替代中心式心跳。把检测置信度而非二元判断喂给租约，可实现渐进释放。

- eBPF 可在内核观测真实存活指标，辅助更精确的应用层检测与超时估计。
- Serverless 平台的弹性实例要求检测与租约随实例生命周期动态调整，避免僵尸租约。
- 把故障检测从「进程级」细化到「服务级」，只对真正影响可用的故障触发租约释放。

用机器学习做自适应超时与租约时长预测（基于历史 RTT/失败模式）；把故障检测从「二元可疑」升级为「置信度」，与租约的渐进释放结合，进一步压低误报与不可用窗口。在 Serverless/弹性实例场景，故障检测需适配实例启停，租约时长随生命周期动态调整。基于 gossip 的检测（如 SWIM）与租约结合，在大规模集群中既准又省。

## 十、小结

故障检测为租约释放提供依据，二者需在「时延与误报」间联合调优。核心不等式 $T\ge k\cdot T_{probe}+d_{max}+\epsilon$ 把检测灵敏度直接转换为安全窗口——脱离检测谈租约时长，必然埋下双主或误杀的隐患。记住：检测决定「何时怀疑」，租约决定「何时权利真正失效」，这是两个必须区分的时间点。
