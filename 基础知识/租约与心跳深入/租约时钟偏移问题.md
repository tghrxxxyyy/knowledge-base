# 租约时钟偏移问题

> 对应 Gray & Lamport 2006（lease 安全性依赖时钟上界）与 Lamport 1978（逻辑时钟与物理时钟讨论）。

## 一、背景与挑战
租约安全性建立在“客户端时钟不会超前服务端太多”的假设上。若客户端时钟被调快，它可能认为自己仍持有租约而继续写，造成双写。

## 二、核心原理
- 租约有效期由授予方时间定义，但持有方用本地时钟判断。
- 时钟漂移/人为 step 会使持有方误判有效性。
- 缓解：用单调时钟（monotonic）、限制最大漂移、引入 fencing token。

## 三、形式化与数学基础
设双方时钟偏差上界 δ，则最坏情况下持有方比授予方早认为租约还有效的时间为 δ。安全条件变为：
$T_{lease} > \delta + d_{max} + \varepsilon$
其中 d_max 为最大网络延迟。

## 四、代码实现
# 用单调时钟避免被调快
import time
start = time.monotonic()
def still_valid(elapsed, ttl):
    return (time.monotonic() - start) < ttl

## 五、与其他技术对比
- 对比逻辑时钟：逻辑时钟不测真实时间，无法直接表达“超时”。
- 对比 NTP 同步：NTP 仍可能有 step，需配合 fencing。

## 六、常见误区
1. 用 wall-clock 判断租约，被 ntpdate 跳变击穿。
2. 认为 fencing token 可完全替代租约时长设计。
