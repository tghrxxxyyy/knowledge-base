# 租约机制原理

> 对应 Gray & Lamport 2006（The Byzantine Generals in the lease: breaking the tie with time）与 Burrows 2006（Chubby 论文）。

## 一、背景与挑战
在分布式系统中，资源常被多个客户端并发访问。如何让某客户端在一段时间内独占地访问资源，又不依赖全局时钟？租约（lease）用“带超时的授权”解决这一问题。

## 二、核心原理
- 服务端授予客户端一段有效期 [t, t+T] 的租约，期间客户端独占。
- 客户端在到期前续租；若到期未续，服务端可把资源授权他人。
- 租约本质是把“谁有权”问题转化为本地超时判断。

## 三、形式化与数学基础
设时钟漂移率 ρ，网络最大延迟 d，授予租约时长 T。安全条件要求：
$T > \frac{d}{1 - \rho} + \text{processing}$
否则可能出现双主。服务端通常设置比客户端超时节律更保守的边界。

## 四、代码实现
# 简化租约管理
class Lease:
    def __init__(self, ttl):
        self.ttl = ttl
        self.owner = None
        self.expire = 0

    def grant(self, who, now):
        if now < self.expire:
            return False
        self.owner = who
        self.expire = now + self.ttl
        return True

## 五、与其他技术对比
- 对比锁：租约不怕客户端崩溃后死锁，超时自动释放。
- 对比心跳：租约显式授权且可缓存，心跳仅表达存活。

## 六、常见误区
1. 认为租约永不丢失——时钟漂移可造成双主。
2. 把租约时长设得过短导致频繁续租风暴。
