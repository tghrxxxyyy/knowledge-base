# B树与磁盘IO优化

> 对应 CLRS。

## 一、背景与挑战
内存访问纳秒级、磁盘/SSD 毫秒或百微秒级。数据结构若树高过大、节点不填满一页，会放大随机 I/O，成为性能瓶颈。

## 二、核心原理
让一个 B 树节点恰好对应一个磁盘页（如 4KB/16KB）。增大分支因子 $t$ 直接降低树高，使查找只需少数几次页读。预读与缓存进一步摊还 I/O。

## 三、形式化与数学基础
页大小 $P$、关键字大小 $e$，则 $t\approx P/(2e)$。树高 $h=O(\log_t n)$，I/O 次数正比于 $h$。例如 $t=100$ 时十亿记录仅约 4-5 层。

## 四、代码实现
```python
PAGE_SIZE = 4096
KEY_SIZE = 16
def branching_factor(page=PAGE_SIZE, key=KEY_SIZE):
    # 约每页容纳的指针/关键字数
    return max(2, page // (key + 8))
def io_cost(n, t):
    import math
    return math.log(n + 1, t)  # 近似页读次数
```

## 五、与其他技术对比
二叉搜索树每节点一关键字，树高 $O(\log_2 n)$ 远大于 B 树 $O(\log_t n)$；哈希索引虽 $O(1)$ 但不支持范围。

## 六、常见误区
把 B 树当纯内存结构优化：忽略页对齐会让 I/O 数翻倍。设过小 $t$ 等于退化成二叉树。

## 七、与开源书/权威来源对应
CLRS 第 18 章开头讨论外存与 I/O 模型；Cormen 等给出 I/O 界。

## 八、面试题
给定页大小与记录数，估算 B+ 树层数；为何分支因子大 I/O 少？

## 九、演进与趋势
针对 SSD 的随机读特性，出现更少层、更大页的变体；缓冲池与预取仍是关键。

## 十、小结
B 树节点对齐磁盘页、扩大分支因子，将查找 I/O 降到 $O(\log_t n)$，是外存索引性能核心。
