# B树在数据库索引中的应用

> 对应 CyC2018/CS-Notes。

## 一、背景与挑战
数据库需要二级索引支持点查、范围查、排序，并在高并发写入下保持高效。聚簇与非聚簇索引的存储布局差异影响性能。

## 二、核心原理
InnoDB 聚簇索引的 B+ 树叶子直接存整行（按主键排序）；二级索引叶子存主键值，需回表。MVCC 通过 undo 日志与事务快照实现多版本并发，使读不加锁。

## 三、形式化与数学基础
点查沿 B+ 树 $O(\log_t n)$ 落到叶子；回表再 $O(\log_t n)$。缓冲池命中率决定实际 I/O。写入经 redo/undo 日志保证持久性与原子性。

## 四、代码实现
```python
# 简化：二级索引查找后回表
def lookup_via_secondary(idx_root, cluster_root, key):
    pk = btree_search(idx_root, key)  # 得到主键
    return btree_search(cluster_root, pk)  # 回表取整行
```

## 五、与其他技术对比
聚簇索引按主键连续存储、范围扫描快；二级索引需回表（除非覆盖索引）。相较 LSM 树，B+ 树点查稳定、写放大可控。

## 六、常见误区
误以为二级索引叶子存整行（实际存主键）；忽视回表代价在大结果集下显著。把 MVCC 当成无锁读也属误解。

## 七、与开源书/权威来源对应
CyC2018/CS-Notes 的 MySQL 索引章节；数据库实现教材详述聚簇与 B+ 树。

## 八、面试题
聚簇与非聚簇区别？为什么推荐自增主键？覆盖索引是什么？

## 九、演进与趋势
列式存储、LSM 树（RocksDB）在写多场景替代部分 B+ 树；但 B+ 树仍是读主导 OLTP 主流。

## 十、小结
B+ 树聚簇索引把行按主键存叶子，二级索引经回表访问，配合 MVCC 实现高并发一致读。
