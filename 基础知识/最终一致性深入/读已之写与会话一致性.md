# 读已之写与会话一致性

> 对应 Vogels 2009（Eventually Consistent，client-centric guarantees）与 Kleppmann DDIA 第5章（client-centric consistency）。

## 一、背景与挑战
纯最终一致可能让用户“刚提交却读不到自己写的内容”，体验糟糕。客户端中心一致性（client-centric）在最终一致之上提供若干实用保证。

## 二、核心原理
- 读己之写（Read-Your-Writes）：用户总能读到自己之前的写。
- 会话一致（Session）：同一会话内保证读己之写。
- 单调读（Monotonic Read）：不会读到比之前更旧的值。
- 单调写（Monotonic Write）：写按序生效。

## 三、形式化与数学基础
用版本向量/时间戳：客户端携带上一次写版本 $V_w$。读请求带 $V_w$，副本返回 $\ge V_w$ 的版本，从而满足读己之写。单调读要求后续读版本不减。

## 四、代码实现
# 读己之写：带上下文读
def read(ctx, key, last_write_v):
    for rep in replicas:
        v = rep.get_version(key)
        if v >= last_write_v:
            return rep.get(key)
    return None

## 五、与其他技术对比
- 对比线性一致：client-centric 更弱但易实现。
- 对比纯最终一致：多了对用户体验友好的保证。

## 六、常见误区
1. 以为读己之写是全局强一致。
2. 跨设备/跨会话无法保证。
