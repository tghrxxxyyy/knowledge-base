# 拓扑排序与依赖解析

> 对应 youngyangyang04/leetcode-master 拓扑排序（依赖/编译顺序）与 Sedgewick《Algorithms》。

## 一、背景与挑战
包管理器、构建系统需按依赖顺序安装/编译模块。循环依赖必须被检测并报告。

## 二、核心原理
把模块当节点、依赖当边，拓扑排序给出合法构建顺序；若检测到环，则提示循环依赖并中断。

## 三、形式化与数学基础
依赖图 $G=(M,E)$。合法序列存在 ⟺ $G$ 无环。构建顺序即任一拓扑序；环对应无法解析的依赖簇。

## 四、代码实现
```python
def build_order(modules, deps):
    # deps: (mod, needs) 表示 mod 依赖 needs
    adj = {m: [] for m in modules}
    indeg = {m: 0 for m in modules}
    for mod, need in deps:
        adj[need].append(mod)
        indeg[mod] += 1
    from collections import deque
    q = deque(m for m in modules if indeg[m] == 0)
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    if len(order) != len(modules):
        raise ValueError('circular dependency detected')
    return order
```

## 五、与其他技术对比
拓扑排序是依赖解析核心；当依赖带版本约束时需 SAT/约束求解，超出纯拓扑范畴。

## 六、常见误区
- 依赖方向颠倒（被依赖者应先构建）。
- 多个独立连通分量未分别处理（应全部入队）。
