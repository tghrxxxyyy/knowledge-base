# 拓扑排序在编译与任务调度

> 对应 Tarjan 1972（强连通分量）与 CLRS 22.4；工程实践见 Sedgewick《Algorithms》。

## 一、背景与挑战
编译器按依赖顺序处理翻译单元；分布式系统按依赖并行调度任务。拓扑排序提供顺序与并行层。

## 二、核心原理
拓扑序给出串行顺序；按"同一轮入度变 0"的分层则可并行执行（层内无依赖）。环需先缩点（Tarjan SCC）再调度。

## 三、形式化与数学基础
分层：$L_0=\{v\mid indeg(v)=0\}$，迭代移除得 $L_1,L_2,\dots$。并行度由最大层大小决定；环经 SCC 缩为单点。

## 四、代码实现
```python
def schedule_levels(n, edges):
    indeg = [0] * n
    adj = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v)
        indeg[v] += 1
    from collections import deque
    level = []
    q = deque(i for i in range(n) if indeg[i] == 0)
    while q:
        level.append(list(q))
        nxt = deque()
        for u in q:
            for v in adj[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    nxt.append(v)
        q = nxt
    return level
```

## 五、与其他技术对比
单纯拓扑给出顺序；分层拓扑给出并行机会，更贴近真实调度器。

## 六、常见误区
- 把层内节点当作有依赖（实际层内独立可并行）。
- 含环图直接分层会遗漏节点。

## 七、与开源书/权威来源对应

- Tarjan 1972 SCC 用于环压缩。

## 九、演进与趋势
现代构建系统（Bazel 等）用增量 + 缓存 + 分层拓扑实现大规模并行编译。

## 十、小结
拓扑排序既是编译顺序基础，也能分层以支持并行任务调度。
