# 拓扑排序在编译与任务调度

> 对应 Tarjan 1972（强连通分量）与 CLRS 第 22.4 节；工程实践见 GNU Make、Bazel 与 Sedgewick《Algorithms》并行调度讨论，及 PERT/CPM 项目调度。

## 一、背景与挑战

编译器与调度器面对的是同一类对象：一堆**带依赖的任务**，要决定"先做什么、什么可以同时做"。编译一个 C++ 工程，头文件与源文件形成依赖图；链接目标有前后关系；微服务部署时 A 要等 B 就绪；CI 里 lint、test、deploy 有先后。朴素串行执行按任意顺序做，要么违反依赖直接失败，要么把本可并行的任务排成串行，机器利用率极低。

挑战有三层。第一，**顺序合法性**：必须先满足所有前置（拓扑序）。第二，并行机会**：同一时刻可执行的任务集合是"当前入度 0"的集合，不是任意子集；把它们错开就是浪费。第三，**环与异常**：循环依赖要识别；任务失败、动态加边（增量构建）时图要能更新。只用"列表 sort"式比较器无法表达偏序；只用单线程队列又丢掉并行度。

在工程与面试里，这一主题考查"拓扑序 vs 拓扑分层"的区别：拓扑序是串行线性扩展，分层（level/antichain 批次）才对应并行调度。Bazel、Ninja、Make `-j`、Airflow、Kubernetes Job、Terraform 都是"依赖图 + 并行执行器"的结构。面试常问：如何最大化并行度、层数与关键路径的关系、含环怎么办、失败如何传播。

## 二、核心原理

**串行顺序**：任一拓扑序保证每个任务在其前置完成后开始。

**并行分层**：令 $L_0 = \{ v \mid indeg(v) = 0 \}$。执行完 $L_0$ 并删边后，新入度 0 的点构成 $L_1$，依此类推。同层内任意两点之间无依赖路径（否则不能同层），故可同时执行。层数 $T$ 称为**深度**（各任务权为 1 时即最长链长度）。

**不变量**：任务 $v$ 进入 $L_k$ 当且仅当其全部前驱已在更早层完成；因此 $k$ 是"最早可开始时间"（单位耗时下）。最大并行宽度 $W = \max_k |L_k|$。

**关键路径关系**：单位耗时时，$T$ 等于最长链；带权时 $T$ 等于关键路径长度（见另篇"关键路径"）。调度目标常是 makespan 最小，即 $T$。

**环的处理**：含环图无法直接分层。先用 Tarjan 求强连通分量，把每个 SCC 缩成点，得到 condensation DAG；簇内任务要么按约定顺序串行，要么视为必须一起调度的"原子块"。构建系统对环通常直接报错，但插件/模块系统可用缩点容忍。

**失败传播**：任务失败时，其全部后继不可执行（反向 BFS 标记 blocked）。增量场景：某任务输入变化，反向传播 dirty，只重跑受影响子图（内容哈希 + 缓存命中则跳过）。

**资源约束**：真正调度器还要限制并行度（CPU、内存）。此时不能简单"整层同步"，而是用"就绪堆 + 资源配额"：从就绪集取任务直到资源耗尽，完成一个释放资源再取。这会偏离理想分层，但 makespan 接近关键路径下界。

**边界条件**：孤立任务自成一层可立即执行；失败任务不能计入完成；动态加边可能引入环，要重新检测；优先级不同的任务在层内应按优先级排序（稳定调度）。

## 三、形式化与数学基础

**分层定义**：
$$L_0 = \{ v : indeg(v) = 0 \}, \quad L_{k} = \{ v : \text{所有前驱在} \bigcup_{i<k} L_i,\ \exists \text{前驱在} L_{k-1} \}$$
等价于 Kahn 按批出队。

**深度 = 最长链**：对单位权 DAG，$T = \max_{k} \{k : L_k \neq \varnothing\} + 1$ 等于最长路径点数减一（边数）。证明：归纳可知 $v \in L_k$ 当且仅当从任一源点到 $v$ 的最长路径恰为 $k$（单位权）；故最深任务所在层即最长路径。

**带权最早开始**：设任务耗时 $d(v)$，
$$est(v) = \max_{u \in pred(v)} \big(est(u) + d(u)\big), \quad est(v)=0 \text{ 若无前驱}$$
$$\text{makespan} = \max_v (est(v) + d(v))$$
该递推在拓扑序上线性求出，是最小 makespan 的下界（无资源约束时可达）。

**并行度下界与上界**：设 $W$ 为最大层宽，$T$ 为深度。理想执行时间满足
$$\max\Big( T,\ \frac{n}{P} \Big) \le \text{makespan} \le T + \frac{n}{P} \quad (\text{粗糙界})$$
$P$ 为处理器数。更精确用工作量 $W_{\text{work}} = \sum d(v)$ 与跨度 $T_\infty = T$（Brent 定理）：
$$T_P \ge \max\left( \frac{W_{\text{work}}}{P},\ T_\infty \right), \quad T_P \le \frac{W_{\text{work}}}{P} + T_\infty$$

**SCC 缩点**：Tarjan 在 $O(V+E)$ 内求 SCC；缩点图无环；簇大小影响串行代价。循环依赖簇内任务数 $s$ 至少贡献 $s$ 的串行链。

## 四、代码实现

```python
from collections import deque


def schedule_levels(n, edges):
    """单位任务的拓扑分层：层内可并行。返回层列表；有环返回 None。"""
    adj = [[] for _ in range(n)]
    indeg = [0] * n
    for u, v in edges:
        adj[u].append(v)
        indeg[v] += 1

    q = deque(i for i in range(n) if indeg[i] == 0)
    levels = []
    seen = 0
    while q:
        level = list(q)
        levels.append(level)
        seen += len(level)
        nxt = deque()
        for u in level:
            for v in adj[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    nxt.append(v)
        q = nxt
    return levels if seen == n else None


def earliest_times(n, durations, edges):
    """带权任务的最早开始/完成与关键路径长度"""
    adj = [[] for _ in range(n)]
    indeg = [0] * n
    for u, v in edges:
        adj[u].append(v)
        indeg[v] += 1

    q = deque(i for i in range(n) if indeg[i] == 0)
    est = [0] * n
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in adj[u]:
            est[v] = max(est[v], est[u] + durations[u])
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)
    if len(order) != n:
        raise ValueError("cycle in task graph")
    eft = [est[i] + durations[i] for i in range(n)]
    makespan = max(eft)
    return est, eft, makespan


def run_with_resources(n, edges, durations, P):
    """简化模拟: P 台机器，就绪堆按(最早开始, id)取，贪心调度。
    返回 makespan 估计与每个任务的开始时间。"""
    adj = [[] for _ in range(n)]
    rev = [[] for _ in range(n)]
    indeg = [0] * n
    for u, v in edges:
        adj[u].append(v)
        rev[v].append(u)
        indeg[v] += 1

    # 预计算 est 作为优先级
    _, _, _ = earliest_times(n, durations, edges)
    from heapq import heappush, heappop
    ready = []
    for i in range(n):
        if indeg[i] == 0:
            heappush(ready, (0, i))  # (est, id)

    start = [None] * n
    running = []  # (finish, id)
    t = 0
    done = 0
    while ready or running:
        # 启动
        while ready and len(running) < P:
            est_u, u = heappop(ready)
            st = max(t, est_u)
            start[u] = st
            heappush(running, (st + durations[u], u))
        if not running:
            break
        t, u = heappop(running)
        done += 1
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                est_v = max(start[u] + durations[u],
                            max((start[x] + durations[x] for x in rev[v] if start[x] is not None), default=0))
                heappush(ready, (est_v, v))
    return t, start


if __name__ == "__main__":
    edges = [(0, 1), (0, 2), (1, 3), (2, 3)]
    levels = schedule_levels(4, edges)
    assert levels == [[0], [1, 2], [3]]

    durations = [2, 3, 3, 1]
    est, eft, ms = earliest_times(4, durations, edges)
    assert ms == 6  # 0(2) -> 1(3) -> 3(1) = 6

    assert schedule_levels(3, [(0, 1), (1, 2), (2, 0)]) is None

    t, start = run_with_resources(4, edges, durations, P=2)
    assert t == 6
    print("all tests passed")
```

## 五、与其他技术对比

| 维度 | 拓扑分层 | 纯拓扑序（串行） | 资源受限启发式 | 一般 RCPSP 精确解 |
|---|---|---|---|---|
| 并行机会 | 层内并行 | 无 | 有，受配额 | 最优但慢 |
| 复杂度 | $O(V+E)$ | $O(V+E)$ | 模拟/堆 | NP-hard |
| 关键路径 | 直接得深度 | 隐含 | 近似 | 精确 |
| 环处理 | 缩点后分层 | 缩点 | 缩点 | 缩点 |
| 适用 | 构建、CI、批处理 | 简单顺序 | 云调度、集群 | 小规模精确 |

取舍：**求工期/并行度用分层**；**只要一个顺序用拓扑序**；**有 CPU/内存配额用就绪堆启发式**；理论最优要 ILP/分支定界。Brent 定理告诉我们：只要跨度小、工作量能摊开，$P$ 台机器的 makespan 接近 $\max(W/P, T_\infty)$。

## 六、常见误区

1. **把层内节点当成有依赖**：层内是反链（antichain），可完全并行；若实现里层内再串行，就丢掉并行度。后果：构建时间成倍变长。
2. **整层 barrier 同步过度**：真实调度器允许"完成一个立刻解锁后继"，不必等整层结束；写成 layer-barrier 会拖长尾延迟。应使用就绪队列。
3. **含环图直接分层漏节点**：环上点永远不入度 0，层列表不含它们却当成功。必须 `seen == n` 或先 SCC。
4. **忽略资源约束算理想工期**：按分层宣称"3 步完成"，但只有 1 台机器时实际要 $\sum d_i$。向业务汇报 makespan 必须区分跨度与工作量。
5. **失败传播没做反向 BFS**：一个任务失败，下游仍被调度，浪费资源或产出脏结果。应立刻标记后继 blocked。

## 八、面试题

**1. 如何用拓扑排序最大化任务并行度？**  
按入度归零分层，层内全部同时执行；层数是最长链（跨度），最大层宽是峰值并行度。资源无限时 makespan = 层数；资源有限时用就绪堆 + 配额，目标逼近 $\max(W/P, T_\infty)$。

**2. 含环依赖图如何先处理再调度？**  
Tarjan 求 SCC，缩点成 DAG，簇内按约定串行或报错拒绝。缩点后再分层调度。构建系统通常对环直接失败并打印链路。

**3. 带权任务的最短总工期怎么算？**  
拓扑序上 DP：$est(v)=\max_{u\in pred(v)}(est(u)+d(u))$，makespan $=\max_v(est(v)+d(v))$。这就是关键路径长度；无资源约束时可达该下界。

**4. 一个任务失败后如何调整调度？**  
把该任务标记 failed，对其全部后继（反向 BFS）标记 blocked 并取消排队；就绪集中只保留前置全成功的任务。增量构建场景还要清缓存、传播 dirty。

## 九、演进与趋势

现代构建与调度系统把拓扑分层做成"图 + 执行器 + 缓存"三件套：**Bazel/Ninja/Turborepo** 用增量 action graph 与内容寻址缓存；**Kubernetes/Airflow/Argo** 把 DAG 作业托管到集群，自动重试与资源配额；**数据流水线（Spark、Flink、Beam）** 用拓扑序生成 stage 与流水线并行；**CPU 核心/NUMA/功耗感知**调度在层内再做优先级与绑核。理论方向包括动态图的在线拓扑、近似 makespan、学习型调度（用 ML 预测任务耗时做优先级）。可以说，只要系统里有"依赖 + 并行"，内核就是拓扑排序与关键路径。

## 十、小结

拓扑排序在编译与调度中给出合法顺序，分层给出并行机会，关键路径给出工期下界；SCC 缩点处理环，反向传播处理失败与增量。分清"跨度、工作量、资源配额"三件事，才能把图算法正确落到构建系统与任务调度器里。
