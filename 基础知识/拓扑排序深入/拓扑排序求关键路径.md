# 拓扑排序求关键路径

> 对应 CLRS 第 24 章（DAG 上的最长/最短路径）与经典项目管理方法 PERT/CPM；亦见 youngyangyang04/leetcode-master 拓扑排序进阶与 AOE 网（Activity On Edge）教学材料。

## 一、背景与挑战

项目由一组**带耗时的任务**与**依赖关系**组成，要求两件事：完成整个项目的最短总工期，以及哪些任务**一天都不能拖**（拖了就拖累整个项目）。这就是关键路径（Critical Path）问题。计算机里对应：编译流水线的最短完成时间、数据流水线的 stage 工期、硬件电路的最长延迟路径（静态时序分析的 setup path）。

为什么不能用最短路直觉？依赖图是 DAG，任务耗时非负，但"总工期"由**最慢的那条链**决定，不是最快——它是 **DAG 上的最长路径**。一般图最长路径是 NP-hard，但 DAG 因无环可在拓扑序上做线性 DP。朴素做法"枚举所有路径取最大"是指数的；用 Bellman-Ford 对边权取负又容易在实现上翻车（负环语义、初始化）。

工程/面试中的位置：关键路径是"拓扑 DP"的代表题，也是 AOE 网（边表示活动、点表示事件）的标准算法。面试常问：最早/最迟发生时间怎么算、松弛时间（slack）是什么、如何还原路径、为什么一般图不能这么算。PERT/CPM 项目管理、CPU 关键路径分析、CI 流水线优化，全用同一套公式。

## 二、核心原理

AOE 网（Activity On Edge）用**事件**做顶点、**活动**做有向边：边 $u \to v$ 上的权 $w$ 是活动耗时，事件 $v$ 表示"其入边活动全部完成的时刻"。源点 $s$ 是项目开始，汇点 $t$ 是项目结束。

**两个时间戳**：
- **事件最早发生时间** $ve(v)$：从源点到 $v$ 的最长路径权和。$v$ 的所有入活动都完成才能发生，故取 max。
- **事件最迟发生时间** $vl(v)$：在不影响总工期 $ve(t)$ 的前提下，$v$ 最迟何时发生。从汇点倒推，取 min。

**活动** $a = (u,v)$ 的时间：
- 最早开始 $e(a) = ve(u)$；
- 最迟开始 $l(a) = vl(v) - w(a)$；
- **松弛时间（slack）** $d(a) = l(a) - e(a)$。

$d(a) = 0$ 的活动在**关键路径**上——没有任何缓冲，延一天项目就延一天。关键路径是使最长路径取到 $ve(t)$ 的任意一条路径，可能不唯一。

**算法骨架**：拓扑序正向求 $ve$；逆拓扑序（或反图拓扑）求 $vl$；再扫边算 $e, l, d$。总复杂度 $O(V+E)$。

**边界**：AOE 通常有唯一源/唯一汇；多源多汇可虚拟超级源/汇（0 耗时边）。若图不连通，项目可能有多个独立工期，取 max 或分项目处理。耗时必须非负（否则"最长"语义与调度都会乱）。拓扑失败（有环）则项目无解。

**与 AOV 的区别**：AOV 用点表示活动、边表示先后（如课程表），求的是顺序；AOE 用边表示活动、点表示事件，求的是工期与关键活动。两者都靠拓扑序。

**还原关键路径**：记录每个点在 $ve$ 递推中取到 max 的前驱边，从 $t$ 沿"关键前驱"回溯到 $s$。若有多条，任取或全部枚举（DFS 回溯所有 $d=0$ 边）。

## 三、形式化与数学基础

**最早时间**（正向，拓扑序）：
$$ve(s) = 0, \quad ve(v) = \max_{(u,v) \in E} \big( ve(u) + w(u,v) \big)$$
总工期 $T = ve(t)$（$t$ 为汇点）。该式是最优子结构：到 $v$ 的最长路取决于各前驱的最长路加边权，取 max 正确因为 $v$ 要等**所有**入活动。

**最迟时间**（逆向）：
$$vl(t) = T, \quad vl(u) = \min_{(u,v) \in E} \big( vl(v) - w(u,v) \big)$$
含义：$u$ 不能晚于"任一后继的最迟时间减去该活动耗时"，否则某后继会拖期；取 min 保证不误期。

**活动松弛**：
$$e(a) = ve(u), \quad l(a) = vl(v) - w(u,v), \quad d(a) = l(a) - e(a) \ge 0$$
$d(a)=0 \iff$ 活动 $a$ 在某条最长路径上（可证：若 $d(a)=0$，则 $ve(u)+w=vl(v)$，前后缀可拼成 $T$）。

**正确性（$ve$ 为最长路）**：归纳拓扑序。$ve(v)$ 等于从源到 $v$ 的最长路径权。因无环，路径可按拓扑递推；max 覆盖所有入边情形。

**复杂度**：正向、逆向各一次拓扑扫描，$O(V+E)$；空间 $O(V+E)$。

**DAG 最长路径与一般图**：一般有向图最长简单路径 NP-hard（可归约自哈密顿路径）；DAG 无环，DP 无后效性。若误用 Dijkstra（min-heap）求最长，因"非负权最短路"贪心不适用于 max 目标，会错；正确是拓扑序 DP。

**与 CPM 的关系**：CPM 用 $ve, vl, slack$ 识别关键活动；PERT 再考虑工期的随机性（三点估计 $\frac{a+4m+b}{6}$），做概率工期。

## 四、代码实现

```python
from collections import deque


def critical_path_aoe(n, edges):
    """
    AOE 网: edges: [(u, v, w)] 表示活动 u->v 耗时 w。
    假设 0 为源、n-1 为汇（可多源多汇时自行加虚拟点）。
    返回 dict: ve, vl, activities(list of (u,v,w,e,l,d)), critical_edges, makespan
    """
    adj = [[] for _ in range(n)]
    radj = [[] for _ in range(n)]
    indeg = [0] * n
    for u, v, w in edges:
        adj[u].append((v, w))
        radj[v].append((u, w))
        indeg[v] += 1

    # 拓扑序
    q = deque(i for i in range(n) if indeg[i] == 0)
    topo = []
    indeg_work = indeg[:]
    while q:
        u = q.popleft()
        topo.append(u)
        for v, w in adj[u]:
            indeg_work[v] -= 1
            if indeg_work[v] == 0:
                q.append(v)
    if len(topo) != n:
        raise ValueError("AOE net has a cycle")

    # 最早发生时间
    ve = [0] * n
    for u in topo:
        for v, w in adj[u]:
            if ve[u] + w > ve[v]:
                ve[v] = ve[u] + w

    makespan = max(ve)

    # 最迟发生时间（从 makespan 出发；若汇点唯一可用 ve[n-1]）
    vl = [makespan] * n
    for u in reversed(topo):
        for v, w in adj[u]:
            if vl[v] - w < vl[u]:
                vl[u] = vl[v] - w

    # 活动的 e, l, d
    activities = []
    critical_edges = []
    for u, v, w in edges:
        e = ve[u]
        l = vl[v] - w
        d = l - e
        activities.append((u, v, w, e, l, d))
        if d == 0:
            critical_edges.append((u, v, w))

    return {
        "ve": ve,
        "vl": vl,
        "activities": activities,
        "critical_edges": critical_edges,
        "makespan": makespan,
    }


def reconstruct_critical_path(n, edges, result):
    """从汇点回溯一条关键路径（点序列）"""
    # 以 makespan 对应的汇点为终点
    ve, critical = result["ve"], result["critical_edges"]
    sink = max(range(n), key=lambda i: ve[i])
    crit_adj = {}
    for u, v, w in critical:
        crit_adj.setdefault(u, []).append(v)

    path = [sink]
    cur = sink
    visited = set()
    while cur in crit_adj and cur not in visited:
        visited.add(cur)
        # 任取一条关键出边；也可全部枚举
        nxt = crit_adj[cur][0]
        path.append(nxt)
        cur = nxt
    path.reverse()
    return path


if __name__ == "__main__":
    # 经典 AOE: 0 -> 1(6) -> 3(1) -> 5
    #            0 -> 2(4) -> 3(1) -> 5
    #            0 -> 2(4) -> 4(5) -> 5
    edges = [
        (0, 1, 6),
        (0, 2, 4),
        (1, 3, 1),
        (2, 3, 1),
        (2, 4, 5),
        (3, 5, 2),
        (4, 5, 3),
    ]
    res = critical_path_aoe(6, edges)
    assert res["makespan"] == 12  # 0-2-4-5: 4+5+3=12
    assert (2, 4, 5) in res["critical_edges"] and (4, 5, 3) in res["critical_edges"]
    # 松弛时间非负
    assert all(d >= 0 for *_, d in res["activities"])
    path = reconstruct_critical_path(6, edges, res)
    assert path[0] == 0 and path[-1] == 5
    print("all tests passed")
```

## 五、与其他技术对比

| 维度 | 关键路径（AOE + 拓扑 DP） | Dijkstra（最短路） | Bellman-Ford（负权） | 暴力枚举路径 |
|---|---|---|---|---|
| 目标 | DAG 最长（工期） | 非负最短 | 含负权最短 | 最长 |
| 复杂度 | $O(V+E)$ | $O((V+E)\log V)$ | $O(VE)$ | 指数 |
| 一般图 | 仅 DAG | 非负 | 可负（无负环） | NP-hard |
| 输出 | 里程碑、松弛、关键边 | 距离 | 距离 | 路径 |
| 用途 | 项目/流水线/时序 | 导航、网络 | 套汇、差分约束 | 玩具 |

取舍：**工期/关键活动用 AOE**；**最短导航用 Dijkstra**；**含负权用 Bellman-Ford/SPFA**。把最长转最短（边权取负）再跑 Dijkstra 是错的（非负前提破坏）；即使跑 Bellman-Ford 也得不到"松弛时间"这套里程碑结构。

## 六、常见误区

1. **用 Dijkstra/BFS 求最长路径**：贪心"当前最小"不适用于 max 目标，且非负前提下也得不到最长。后果：工期算短，排期乐观到必崩。
2. **$ve$ 递推取 min 或漏 max**：事件要等所有入活动，必须 max；若写成 sum 或 min，关键路径完全错。
3. **$vl$ 初值不当**：应从汇点 $T$ 逆推 min；若初始化成 0 或 inf 处理不当，松弛时间全错。
4. **忘记活动耗时归属**：$e(a)=ve(u)$，$l(a)=vl(v)-w(a)$；把 $w$ 加到错误一端（写成 $vl(v)$ 或 $ve(v)$）会偏一天。
5. **只算 makespan 不输出关键活动**：业务上"哪些任务不能拖"才是决策依据；只给总工期无法指导资源倾斜。

## 八、面试题

**1. 为何 DAG 最长路径可在线性时间求？**  
无环则可拓扑排序，DP 无后效性：$ve(v)=\max_{u\in pred(v)}(ve(u)+w(u,v))$ 在拓扑序上一次算完，$O(V+E)$。一般图最长简单路径 NP-hard。

**2. 如何还原关键路径而不只是长度？**  
正向求 $ve$ 时记录取到 max 的前驱边；或算完 $e,l$ 后取 $d=0$ 的边组成子图，从汇点沿这些边回溯到源点。多条关键路径时 DFS 全枚举。

**3. 松弛时间（slack）是什么？有何用？**  
$d(a)=l(a)-e(a)$ 表示活动可推迟而不影响工期的余量。$d=0$ 是关键活动，资源应优先保障；$d>0$ 可调度到非高峰。项目经理据此做资源平衡。

**4. 为什么不能把边权取负再跑最短路求最长？**  
取负后目标变为"最短"，但 Dijkstra 要求非负权；即便用 Bellman-Ford，得到的是负权最短，再取反才是最长——可行但没必要，且得不到 $ve/vl/slack$ 的完整结构；在存在正环时更无意义（AOE 无环）。

## 九、演进与趋势

关键路径方法持续演进：**PERT** 引入三点估计与工期分布，做概率完成时间；**资源平衡/资源约束**（RCPS）在关键路径上加人力/机器限制，转化为 RCPSP（NP-hard，启发式）；**动态关键路径**用于 CI/数据流水线，改一个任务自动重算 slack；**硬件静态时序分析（STA）** 用同一套最长路径算法算 setup 检查，是芯片签核的核心；**学习型调度**预测任务耗时并重排优先级。现代构建系统（Bazel、Airflow）把关键路径高亮成"优化热点"，工程上优先优化关键活动的收益远高于非关键活动。

## 十、小结

关键路径 = AOE 网上的拓扑 DP：正向求事件最早时间得总工期，逆向求最迟时间得松弛时间，$d=0$ 的活动串成关键路径。它把"最长路径"这一难问题在 DAG 上降到 $O(V+E)$，是项目管理、编译流水线与芯片时序的共同基础。
