# 单点登录基础

> 对应 RFC 6749 (OAuth 2.0) 背景 / OWASP / CyC2018/CS-Notes (GitHub)。

## 一、背景与挑战
多系统各自登录既差体验又难统一注销与审计。SSO 让用户一次认证即可访问多个信任应用，但需可信的令牌交换与集中身份提供方(IdP)。

## 二、核心原理
用户向 IdP 认证，IdP 签发断言/令牌，各应用(SP)信任该断言而免登。SAML 用 XML 断言，OIDC 用 JWT ID Token，CAS 用票据。核心是联合身份与单点注销。

## 三、形式化与数学基础
SSO 信任链：
$$ User \xrightarrow{auth} IdP \xrightarrow{assertion} SP $$
断言不可伪造需签名验证：
$$ Valid = Verify(sig_{IdP}, assertion, cert_{IdP}) $$

## 四、代码实现
```python
# 校验 IdP 签名的 JWT ID Token(需 PyJWT + JWKS)
import jwt
id_token = "..."  # 来自 OIDC 回调
claims = jwt.decode(id_token, options={"verify_signature": True},
                    audience="my_client", issuer="https://idp.example.com")
# 验证通过即信任该用户身份
```

## 五、与其他技术对比
SAML 企业级、重；OIDC 基于 OAuth 轻量、移动友好；CAS 简单。SSO 提升体验但 IdP 成单点故障/高价值目标。

## 六、常见误区
把 OAuth 当认证协议(它本是授权)；IdP 被攻破全盘崩。忽略单点注销使会话残留。

## 七、与开源书/权威来源对应
RFC 6749 背景；OIDC 规范；CyC2018/CS-Notes 单点登录章节。

## 九、演进与趋势
Passkey + FedCM 标准化身份联合；去中心化身份(DID)。

## 十、小结
SSO 通过可信 IdP 断言实现一次登录多系统访问，OIDC/JWT 是主流实现，但 IdP 安全至关重要。
