# 最小权限与认证授权边界

> 对应 Saltzer & Schroeder 1975 "Protection and Authorization" / OWASP。

## 一、背景与挑战
认证(AuthN: 你是谁)与授权(AuthZ: 你能做什么)常被混用。边界不清导致越权(如改他人资源)。最小权限要求二者严格分离并默认拒绝。

## 二、核心原理
AuthN 产出身份声明；AuthZ 基于身份+策略决定访问。每次请求都应重新仲裁(完全仲裁)，不因"已登录"而跳过对象级检查。对象级授权防 IDOR(不安全直接对象引用)。

## 三、形式化与数学基础
请求 $(u, obj, act)$ 允许当且仅当：
$$ AuthN(u) \land Policy(u, obj, act) = Permit $$
IDOR 漏洞即缺 $Policy(u, obj, \cdot)$，任意 $obj$ 可被访问。

## 四、代码实现
```python
# 对象级授权检查(防 IDOR)
def delete_doc(user, doc_id):
    doc = db.get(doc_id)
    if not doc:
        return 403
    if doc.owner_id != user.id:   # 对象级授权
        return 403
    db.delete(doc)
    return 200
```

## 五、与其他技术对比
AuthN 只确认身份，AuthZ 决定范围；RBAC/ABAC 是 AuthZ 实现。二者是纵深防御的不同层。

## 六、常见误区
登录即信任所有操作(缺对象级检查)导致越权。把前端隐藏按钮当授权(后端必须查)。

## 七、与开源书/权威来源对应
Saltzer & Schroeder 1975；OWASP Broken Access Control( Top 10 A01)；CS-Notes 安全章节。

## 八、面试题
AuthN 与 AuthZ 区别？什么是 IDOR？为何需对象级授权？

## 九、演进与趋势
策略即代码(OPA)、细粒度属性授权、零信任每次请求重判。

## 十、小结
认证与授权必须分离且每次请求仲裁，对象级检查防越权，最小权限贯穿始终。
