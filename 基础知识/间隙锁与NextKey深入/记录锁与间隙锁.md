# 记录锁与间隙锁

> 对应 MySQL InnoDB 官方文档「InnoDB Locking」与 Gray 等锁理论，参考 cmu-db/15445-course 并发控制。

## 一、背景与挑战
InnoDB 在可重复读（RR）下不仅要锁住已存在的行，还要锁住「行之间的空隙」，以防止其他事务插入导致幻读。记录锁与间隙锁是这一机制的两块基石。

## 二、核心原理
记录锁（Record Lock）锁住索引上某条具体记录。间隙锁（Gap Lock）锁住两条索引记录之间的区间，阻止在该区间插入新记录。间隙锁之间兼容（都只是「防插入」），但会阻塞插入意向锁。二者共同实现 RR 下的幻读防护。

## 三、形式化与数学基础
设索引键有序集合 $K = \{k_1 < k_2 < \dots\}$，插入目标 $v$ 落在间隙 $(k_i, k_{i+1})$。若间隙被锁：
$$ lock(k_i, k_{i+1}) \Rightarrow insert(v),\, k_i < v < k_{i+1} \text{ 被阻塞} $$
记录锁则仅对具体 $k_j$ 生效。

## 四、代码实现
```sql
-- 触发间隙锁（RR 下）
SELECT * FROM t WHERE id BETWEEN 10 AND 20 FOR UPDATE;
-- 锁住 [10,20] 记录及两端间隙，阻止插入 11~19 间新值
```

## 五、与其他技术对比
PostgreSQL 默认用 MVCC + 快照实现可重复读，无间隙锁概念（靠 SIREAD 跟踪防幻读，串行化用谓词锁/SerialSnapshot）。InnoDB 以锁实现，开销与阻塞特征不同。Oracle 类似用多版本。

## 六、常见误区
认为间隙锁锁住的是某行——它锁的是区间。认为读不加锁——`FOR UPDATE`/`FOR SHARE` 或当前读会加锁，普通快照读不加。

## 八、面试题
问：间隙锁解决什么？答：防止幻读（并发插入使同一查询返回不同行集）。问：间隙锁之间会互斥吗？答：不会，多个间隙锁可共存，只阻塞插入。

## 九、演进与趋势
部分引擎用谓词锁/区间树更精确表达锁范围，降低间隙锁的过度封锁。

## 十、小结
记录锁锁行、间隙锁锁区间，二者配合在 RR 下杜绝幻读。
