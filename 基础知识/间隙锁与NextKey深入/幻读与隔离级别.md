# 幻读与隔离级别

> 对应 ANSI SQL 隔离级别标准与 Berenson 等「Critique of ANSI SQL Isolation」论文，参考 Silberschatz 第15章。

## 一、背景与挑战
幻读指同一事务内两次相同范围查询返回不同行集（因并发插入）。不同隔离级别对幻读、不可重复读、脏读的定义与防护差异，是并发正确性的核心。

## 二、核心原理
ANSI 四级：读未提交（可能脏读）、读已提交（防脏读，允许不可重复读与幻读）、可重复读（防不可重复读；InnoDB RR 额外用 Next-Key 防幻读）、串行化（完全隔离）。需区分「快照读」（MVCC 一致性视图，天然防幻读）与「当前读」（`FOR UPDATE` 等，需锁防幻读）。

## 三、形式化与数学基础
幻读发生条件（当前读、无间隙锁时）：
$$ \exists insert\; T_2\; between\; read_1(T_1)\; and\; read_2(T_1) $$
InnoDB RR 以 Next-Key Lock 使该插入被阻塞，破坏条件。

## 四、代码实现
```sql
SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ;
BEGIN;
SELECT * FROM t WHERE k BETWEEN 1 AND 10;  -- 快照读
SELECT * FROM t WHERE k BETWEEN 1 AND 10 FOR UPDATE;  -- 当前读+Next-Key锁
COMMIT;
```

## 五、与其他技术对比
PostgreSQL 的 RR 用 MVCC 快照防不可重复读与幻读（快照读天然一致），但并发写冲突靠 SI 检测。InnoDB 靠锁 + MVCC 双机制。SQL Server 串行化用键范围锁。

## 六、常见误区
认为 RR 一定防幻读——纯快照读场景靠 MVCC 可防，但当前读若无间隙锁则不行；InnoDB RR 因 Next-Key 实际防住。认为隔离级别越高越好——串行化并发最低。

## 七、与开源书/权威来源对应
Berenson 1995「A Critique of ANSI SQL Isolation Levels」；Silberschatz 15.5「Levels of Consistency」。

## 八、面试题
问：RR 与串行化区别？答：RR 允许写偏斜等异常，串行化完全等价串行执行。问：InnoDB RR 为何防幻读？答：快照读靠 MVCC，当前读靠 Next-Key Lock。

## 九、演进与趋势
可串行化快照隔离（SSI，PostgreSQL 实现）以更低代价提供串行化，是隔离级别研究的重要进展。

## 十、小结
幻读防护依赖隔离级别与实现的结合，InnoDB 的 RR 通过 MVCC + Next-Key 双管齐下实现防幻读。
