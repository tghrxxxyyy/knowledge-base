# 慢启动与拥塞避免

> 对应 RFC 5681；Kurose & Ross 第 3 章。

## 一、背景与挑战
网络核心是“尽力而为”的，多个发送方共享瓶颈链路时若盲目提速会致丢包、重传风暴与吞吐量崩溃（拥塞崩溃，Jacobson 1988）。需在网络“恰好不拥塞”处稳定运行。

## 二、核心原理
慢启动（slow start）：连接初期 cwnd 从 1 SMSS 起，每收到一个 ACK 则 cwnd 加 1 SMSS，呈指数增长，快速探测容量。当 cwnd ≥ ssthresh 转入拥塞避免，改为每个 RTT 加 1 SMSS（线性增长）。

## 三、形式化 / 数学基础
慢启动：每 RTT $cwnd \leftarrow 2\cdot cwnd$（指数）。
拥塞避免：每 RTT $cwnd \leftarrow cwnd + 1$ SMSS（线性），等价于每收到 ACK 加 $SMSS^2/cwnd$。
阈值切换：当 $cwnd \ge ssthresh$ 离开慢启动。

## 四、代码实现
```c
void on_ack() {
    if (cwnd < ssthresh)            // 慢启动
        cwnd += SMSS;
    else                            // 拥塞避免
        cwnd += (SMSS * SMSS) / cwnd;
}
```

## 五、与其他技术对比
慢启动“指数探顶”、拥塞避免“线性逼近”，二者合称 TCP Reno 的基础。对比 BBR 基于模型（BtlBw×RTTprop）主动控制，而非依赖丢包信号。

## 六、常见误区
误区一：慢启动“慢”是因为速率低。错，它增长极快（指数），只是起点低。误区二：cwnd 永远不超过 ssthresh 才安全。错，拥塞避免阶段 cwnd 会持续超过 ssthresh。误区三：ssthresh 固定。错，每次丢包后重设。

## 八、面试题
1. 慢启动每个 RTT 增长几倍？答：约 2 倍。2. ssthresh 作用？答：慢启动与拥塞避免的分界。

## 九、演进与趋势
HyStart（RFC 9406）在慢启动末期用延迟信号提前退出，减少丢包；Initial Window 已提升到 10 MSS（RFC 6928）。

## 十、小结
慢启动指数探、拥塞避免线性守，是 Reno 类算法“先快后稳”的拥塞控制骨架。
