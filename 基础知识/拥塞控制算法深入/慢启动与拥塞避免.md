# 慢启动与拥塞避免

> 对应 RFC 5681（TCP Congestion Control）；Stevens《TCP/IP Illustrated》卷1 第21章；Kurose & Ross《Computer Networking》第3章。

## 一、背景与挑战

互联网核心是「尽力而为」（best-effort）的存储转发网络，没有预留带宽的机制。当多个发送方共享同一瓶颈链路时，若每个发送方都按自己最大速率发送，瓶颈队列会迅速填满并溢出，引发大规模丢包、超时与重传风暴，整体吞吐量不升反降——这就是 Jacobson 在 1988 年提出的「拥塞崩溃」（congestion collapse）。设计拥塞控制的目标，是在「网络恰好不拥塞」的临界点附近稳定运行，同时尽可能把瓶颈带宽用满。慢启动与拥塞避免正是 TCP Reno 类算法实现这一平衡的两个阶段：前者在连接初期快速探测可用容量，后者在逼近容量后谨慎逼近以避免冲垮网络。

## 二、核心原理

慢启动（slow start）在连接建立后启动，拥塞窗口 `cwnd` 从 1 个 SMSS（Sender Maximum Segment Size）开始，每收到一个对「新数据」的 ACK，`cwnd` 就增加 1 个 SMSS。由于一个 RTT 内会收到约 `cwnd` 个 ACK，因此每个 RTT `cwnd` 大致翻倍，呈指数增长。当 `cwnd` 增长到不小于慢启动阈值 `ssthresh` 时，进入拥塞避免阶段：此后每个 RTT 仅增加 1 个 SMSS（即每个 ACK 增加 `SMSS²/cwnd`），呈线性增长，避免再次指数冲击瓶颈。

三个关键变量需厘清：`cwnd` 是发送方自行维护、受网络拥塞约束的窗口；`rwnd` 是接收方通告的窗口；真正允许发送的字节上限是 `min(cwnd, rwnd)`。`ssthresh` 初始可设成很大（如 `rwnd`），但每次发生丢包（超时或 3-dup-ACK）后会被重设为当前 `cwnd` 的一半左右，从而永久改变慢启动与拥塞避免的切换点。

## 三、形式化与数学基础

慢启动阶段每 RTT 的窗口演化近似为：

$$ cwnd_{t+1} \approx 2 \cdot cwnd_t $$

从 $cwnd_0$ 增长到 $ssthresh$ 所需的 RTT 数约为 $\lceil \log_2(ssthresh/cwnd_0) \rceil$。

拥塞避免阶段每 RTT 线性增加 1 个 SMSS，等效于每收到一个 ACK 增加：

$$ \Delta cwnd = \frac{SMSS^2}{cwnd} $$

阈值切换条件为：

$$ cwnd \ge ssthresh \quad \Rightarrow \quad \text{离开慢启动} $$

丢包事件后 `ssthresh` 的更新（以 Reno 为例）为：

$$ ssthresh \leftarrow \max\!\left(\frac{cwnd}{2},\ 2\cdot SMSS\right) $$

之后 `cwnd` 重置为 1 个 SMSS 重新慢启动（超时情形），或重置为 `ssthresh` 后进入快速恢复（3-dup-ACK 情形）。

## 四、代码实现

下面给出一个简化的每 ACK 更新逻辑，展示两个阶段的分界与窗口增长：

```c
// 简化的 Reno 每 ACK 处理（忽略快速重传/恢复细节）
void on_ack_received(uint32_t acked_bytes) {
    if (cwnd < ssthresh) {
        // 慢启动：每到一个 ACK，cwnd 增加 1 个 SMSS
        cwnd += SMSS;
    } else {
        // 拥塞避免：每 ACK 增加 SMSS^2 / cwnd（按字节累计）
        cwnd += (SMSS * SMSS) / cwnd;
    }
}

void on_timeout_or_triple_dupack(void) {
    ssthresh = max(cwnd / 2, 2 * SMSS);  // 乘性减阈值
    cwnd = SMSS;                          // 超时则回到慢启动起点
    // 若是 3-dup-ACK，cwnd 通常设为 ssthresh 并进入快速恢复
}
```

实际 Linux 内核（`net/ipv4/tcp_cong.c` 的 `tcp_slow_start`）以「每 ACK 增发 `ack/2` 段」的近似实现慢启动，避免逐段加 1 的高开销。

## 五、与其他技术对比

| 维度 | 慢启动 | 拥塞避免 | BBR（模型式） |
| --- | --- | --- | --- |
| 增长方式 | 指数（每 RTT ×2） | 线性（每 RTT +1 MSS） | 按 BtlBw 主动 pacing |
| 控制依据 | RTT 计 ACK 数 | RTT 计 ACK 数 | 测量的 BtlBw×RTTprop |
| 触发信号 | 阶段切换由 ssthresh | 丢包触发降速 | 带宽/延迟探测 |
| 适用阶段 | 连接初期/恢复后 | 接近容量时 | 全程 |

二者合称 Reno 的「先快后稳」骨架；而 BBR 不依赖丢包信号，直接对瓶颈带宽与最小 RTT 建模，从设计哲学上绕开了慢启动的指数探顶风险。

## 六、常见误区

误区一：慢启动「慢」是因为发送速率低。错——它每 RTT 翻倍，增长速度极快，只是起点（1 个 SMSS）低，因此命名强调的是「起步谨慎」而非「全程慢」。

误区二：`cwnd` 永远不能超过 `ssthresh`。错——`ssthresh` 只是慢启动与拥塞避免的切换点，进入拥塞避免后 `cwnd` 会持续、线性地超过它。

误区三：`ssthresh` 是固定常量。错——每次丢包后 `ssthresh` 都按当时 `cwnd` 的一半重设，它是动态学习的「上次安全水位」。

误区四：慢启动从 1 起步效率太低。实际上 RFC 6928 已将初始窗口（IW）提升到 10 个 MSS，连接初期不再从 1 缓慢爬升。

## 七、与开源书·权威来源对应

- RFC 5681 第3节明确定义了慢启动与拥塞避免的窗口演化与 `ssthresh` 更新规则。
- Stevens《TCP/IP Illustrated》卷1 第21章用大量报文序列图展示慢启动的指数爬坡过程。
- Kurose & Ross《Computer Networking》第3章以「加法增/乘法减」框架统一讲解这两个阶段。
- Hennessy & Patterson 虽偏体系结构，但其对「反馈控制闭环」的讨论可类比拥塞窗口的动态调整。

## 八、面试题

1. 慢启动每个 RTT 窗口增长几倍？要点：约 2 倍（指数），但按 ACK 计数实现；现代 IW=10 MSS。
2. `ssthresh` 的作用与何时更新？要点：慢启动/拥塞避免分界；每次丢包后设为 `cwnd/2`。
3. 为什么拥塞避免阶段每 ACK 加 `SMSS²/cwnd` 等效于每 RTT 加 1 MSS？要点：一个 RTT 内有 `cwnd/SMSS` 个段、约同样多 ACK，累加得 1 MSS。
4. 超时与 3-dup-ACK 对 `cwnd` 的处理有何不同？要点：超时回到 1 MSS 重新慢启动；3-dup-ACK 进入快速恢复、`cwnd` 置为 `ssthresh`。

## 九、演进与趋势

慢启动的「盲目指数探顶」在长肥管道（LFN）上仍可能冲垮浅队列。HyStart（RFC 9406）在慢启动末期监测 RTT 的上升趋势，一旦延迟明显抬升就提前退出慢启动、转入拥塞避免，从而减少进入拥塞避免前的那次丢包。此外，初始窗口从 1 提升到 10 MSS（RFC 6928）缩短了短连接的握手开销。BBR 等模型式算法则进一步弱化了对慢启动的依赖。

## 十、小结

慢启动以指数增长快速探测可用容量，拥塞避免以线性增长谨慎逼近瓶颈，二者由动态 `ssthresh` 衔接，构成 Reno 类算法「先快后稳」的拥塞控制骨架。理解 `cwnd`、`ssthresh`、`rwnd` 三者的关系与丢包后的重置逻辑，是掌握整个 TCP 拥塞控制的前提。
