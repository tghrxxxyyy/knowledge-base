# 现代变体

> 对应 RFC 9438（CUBIC）；RFC 9413（TCP 演进综述）。

## 一、背景与挑战
标准 Reno 在大 BDP 链路下因“每个 RTT 才加 1 MSS”而收敛极慢、利用率低；不同场景（数据中心、卫星、无线）需要差异化算法。

## 二、核心原理
现代变体在 Reno 框架上改进：CUBIC 用时钟而非 RTT 驱动、按凹函数逼近上次 ssthresh；BIC 二分搜索；Vegas 基于 RTT 预测；Westwood 用带宽估计设 ssthresh；RACK 用时间重传。各变体针对特定链路特征优化。

## 三、形式化 / 数学基础
CUBIC 拥塞窗口：$cwnd(t) = C\cdot (t - K)^3 + W_{last}$ 其中 $K = \sqrt[3]{W_{last}\cdot(1-\beta)/C}$，$W_{last}$ 为上次丢包前 cwnd，$\beta=0.7$（乘性减因子）。Linux 默认 CC 即 CUBIC。

## 四、代码实现
```c
// CUBIC 简化
long long t = now_ms - epoch_start_ms;
long long k = cbrt(w_last * (1 - beta) / C);
cwnd = C * (t - k) * (t - k) * (t - k) + w_last;
```

## 五、与其他技术对比
Reno 适合小 BDP；CUBIC/BBR 适合大 BDP 与长肥管道；Vegas 适合低丢包但易在混合场景饿死；数据中心多用 DCTCP/BBR 降尾延迟。

## 六、常见误区
误区一：新算法一定全面优于 Reno。错，取决于 RTT/BDP/丢包率。误区二：CUBIC 是 Reno 的线性增。错，是三次函数。误区三：BBR 属于 Reno 家族。错，BBR 是模型式、非 AIMD。

## 九、演进与趋势
BBR v2、L4S、基于机器学习的拥塞控制（如 Aurora）是活跃研究方向。

## 十、小结
现代变体（CUBIC/BBR/Vegas 等）针对大 BDP 与异构网络优化 Reno，是拥塞控制的工程演进。
