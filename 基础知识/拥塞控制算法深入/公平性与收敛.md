# 公平性与收敛

> 对应 Chiu & Jain 公平性论文；RFC 5681。

## 一、背景与挑战
多条 TCP 流共享同一瓶颈链路时，协议应让带宽被“公平”分配，且系统状态能从任意初值收敛到均衡点，否则会出现饿死或震荡。

## 二、核心原理
用公平性与收敛性两个维度评价拥塞算法。Jain 公平性指数 $f = (\sum x_i)^2 / (n \sum x_i^2)$ 衡量分配均衡度（1 为完全公平）。AIMD 被证明在“效用函数”下能收敛到比例公平（proportionally fair）。

## 三、形式化 / 数学基础
Jain 指数：$f = \dfrac{(\sum_{i=1}^{n} x_i)^2}{n\sum_{i=1}^{n} x_i^2} \in (0,1]$。
AIMD 二人收敛：设容量 C，流 x、y 满足 $x+y=C$，AIMD 使 $x-y$ 每次迭代按 $1/2$ 衰减，长期趋于 0。
比例公平：最大化 $\sum \log x_i$ 的解即等分（在等 RTT 下）。

## 四、代码实现
```python
def jain(xs):
    s = sum(xs)
    return s * s / (len(xs) * sum(x*x for x in xs))
```

## 五、与其他技术对比
AIMD 收敛到公平但 RTT 小的流占优（RTT 不公平）；BBR 在大 BDP 下对 Reno 不公平（抢占）；MFQ/近似公平排队在网络层用调度而非端点实现公平。

## 六、常见误区
误区一：TCP 天生完全公平。错，存在 RTT 与启动时间导致的偏置。误区二：公平就是每流绝对等分。错，比例公平考虑权重。误区三：Jain=1 一定最优。错，还要看利用率。

## 九、演进与趋势
网络层公平（FQ-CoDel、pacing）与端点算法协同；BBR v2 显式考虑与 Reno 的公平性。

## 十、小结
公平性用 Jain 指数量化、AIMD 保证收敛到比例公平，但现实存在 RTT 与算法间的不公平。
