# 拥塞信号

> 对应 RFC 3168（ECN）；RFC 5681（丢包信号）。

## 一、背景与挑战
拥塞控制需要“信号”判断网络是否过载。传统仅靠丢包（隐含信号），但丢包代价高且滞后；显式拥塞通知（ECN）提供早期、无损的信号。

## 二、核心原理
端点用两类信号：(1) 丢包/3-dup-ACK —— 强信号，触发乘性减；(2) ECN —— IP 头 ECT/CE 标记、TCP 头 ECE/CWR 协商与回传，指示“轻微拥塞”，可在不丢包下降速。

## 三、形式化 / 数学基础
ECN 字段（IP ToS 低 2 位）：00=Non-ECT，10=ECT(0)，01=ECT(1)，11=CE（拥塞经历）。
TCP 标志：ECE（Echo Congestion Experienced）、CWR（Congestion Window Reduced）。
处理：收到 CE 的段，ACK 置 ECE；发送方见 ECE 后减半 cwnd 并置 CWR 通知接收方停止回声。

## 四、代码实现
```c
if (ip_header->ecn == 0b11) {        // CE
    tcp_header->flags |= ECE;         // 回声拥塞
}
if (tcp_header->flags & ECE) {
    cwnd = max(cwnd / 2, 2);          // 降速
    tcp_header->flags |= CWR;          // 通知对端
}
```

## 五、与其他技术对比
丢包信号是“硬”、滞后、有损的；ECN 是“软”、提前、无损的。Delay-based 信号（如 Vegas 用 RTT 上升）则更前瞻但易与基于丢包的流不公平。

## 六、常见误区
误区一：ECN 标记会丢包。错，ECN 的意义正是用标记代替丢弃。误区二：ECN 关闭时无法拥塞控制。错，丢包仍是兜底。误区三：只有路由器能设 CE。对，仅支持 ECN 的转发设备标记。

## 九、演进与趋势
L4S（RFC 9330/9331）扩展 ECN 为低时延可扩展拥塞信号，配合 BBR/DCTCP 进一步降排队。

## 十、小结
拥塞信号从“丢包”扩展到“ECN 标记”，让控制更及时无损，是现代拥塞控制的重要组成。
