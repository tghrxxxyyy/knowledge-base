# 等价约束与谓词选择

> 对应 Selinger 1979 System R 优化器、PostgreSQL「Constraint Exclusion / Equivalence Class」与 Garcia-Molina《Database Systems: The Complete Book》查询优化章节。

## 一、背景与挑战
SQL 查询里同一个列往往出现在多个位置：既是连接条件，又被 WHERE 过滤，还可能参与派生表。这些条件表面分散，实际互相蕴含。
如果优化器逐条孤立处理谓词，就会错失推导机会：明明可以在扫描表 $a$ 前就用 `a.x = 5` 过滤，却等到连接后才过滤，中间结果被无谓放大。
等价类（equivalence class）正是把分散等值条件汇成推导力的结构。它让优化器从「已知相等」推「新相等」，从而提前过滤、剪枝分区、改进选择性估计。
与之配套的是约束排除（constraint exclusion）：利用表或分区的 CHECK 约束，在计划阶段直接跳过不可能含数据的分区。
核心挑战在于推导的正确性与收益平衡：推导过多会增加规划开销，函数包裹列与 OR 条件下的推导更复杂，部分优化器只支持有限形式。

## 二、核心原理
优化器在预处理阶段收集所有形如 $c_i = c_j$ 的等值条件（来自 JOIN 的 ON 与 WHERE），并查并集，把互相相等的列归入同一等价类。
在同一等价类中，任意两列被视为等价，于是可以生成派生谓词：若类中某列已知等于常量 $v$，则类中所有列都等于 $v$。
派生谓词可以下推到基表，使过滤尽早发生，减小中间结果规模，也让每张表的基数估计更准。
等价类还用于连接顺序与连接算法选择：同一类内的连接条件可用等值哈希或归并连接，且可共享排序性质。
约束排除则检查查询谓词与分区约束是否矛盾。若某分区的 CHECK 约束与谓词无交集，该分区在计划中直接剔除，扫描量随之下降。

## 三、形式化与数学基础
等价类 $E = \{c_1, c_2, \dots, c_m\}$ 表示类中任意两列等价：

$$ \forall c_i, c_j \in E,\quad c_i \equiv c_j $$

若查询中存在常量等值 $c_k = v$ 且 $c_k \in E$，则派生谓词集合为：

$$ \{\, c_i = v \mid c_i \in E \,\} $$

由此选择率可下推到每个基表，减少中间结果：

$$ card_{\text{after}} = N \cdot \prod_{p \in \text{derived\_pred}} \mathrm{sel}(p) $$

约束排除的判定条件：设分区约束为 $C_{\text{part}}$、查询谓词为 $P$，若二者可满足性无交集则剪枝：

$$ C_{\text{part}} \wedge P \equiv \text{false} \;\Rightarrow\; \text{skip partition} $$

对范围与包含约束，可推广为区间推理：若谓词区间 $[l_p, h_p]$ 与分区区间 $[l_c, h_c]$ 不相交，则分区可跳过。

## 四、代码实现
```sql
-- 等价类推导：b.y = 5 可推 a.x = 5，a 表可提前过滤
EXPLAIN
SELECT * FROM a JOIN b ON a.x = b.y WHERE b.y = 5;

-- 分区表约束排除：只扫描匹配分区
-- 表按 partition_key 范围分区，且各分区有 CHECK 约束
EXPLAIN
SELECT * FROM logs WHERE partition_key >= '2024-03-01'
                      AND partition_key <  '2024-04-01';

-- PostgreSQL 查看等价类与谓词下推效果（以计划中的 Filter/Index Cond 为准）
EXPLAIN (VERBOSE, COSTS OFF)
SELECT * FROM a JOIN b ON a.x = b.y WHERE a.x = 5;

-- 函数包裹列会阻断下推与剪枝
EXPLAIN SELECT * FROM logs WHERE date_trunc('month', ts) = '2024-03-01';
```

## 五、与其他技术对比
| 机制 | 依据 | 收益 | 限制 |
|---|---|---|---|
| 等价类推导 | 等值传递性 | 提前过滤、改善估计 | 主要覆盖等值，OR 支持有限 |
| 约束排除 | 分区/表约束 | 跳过整分区 | 依赖分区键与谓词形式 |
| 分区裁剪 | 分区键谓词 | 减少扫描 | 需静态常量或可求值表达式 |
| 谓词下推 | 关系代数变换 | 减小中间结果 | 子查询/窗口函数有限制 |
| 函数索引 | 表达式索引 | 让函数谓词可索引 | 需显式创建，维护成本高 |

## 六、常见误区
- 认为 JOIN 条件只在连接时起作用：等值条件经传递性可变成单表过滤，提前执行。
- 认为函数包裹列不影响下推：`WHERE YEAR(d) = 2024` 常无法利用索引，也难做分区裁剪。
- 忽视 OR 条件：`a.x = 5 OR b.y = 5` 无法简单推导等价，优化器支持有限。
- 假设约束排除总是生效：需要分区约束与谓词形式匹配，动态参数或函数会阻断。
- 把推导与改写混为一谈：推导生成新谓词，改写改变算子结构，二者都属逻辑优化但机制不同。

## 八、面试题
1. 问：等价类对优化有什么作用？
   答：派生新谓词、提前过滤、分区剪枝、改善选择性估计与连接选择。
2. 问：为什么 `WHERE YEAR(d)=2024` 难以优化？
   答：函数包裹列破坏了等价推导与索引/分区匹配，通常需要函数索引或改写谓词。
3. 问：约束排除与分区裁剪有何区别？
   答：前者基于表/分区 CHECK 约束做逻辑排除，后者基于分区键谓词直接定位分区。
4. 问：等价推导会带来什么风险？
   答：推导过多增加规划时间，且若常量选择率不准，推导会放大估计误差。
5. 问：OR 条件为何更难优化？
   答：OR 不满足等值传递，需展开为并集或做更复杂的约束推理，支持有限。

## 九、演进与趋势
- 更通用的约束推理（范围、包含、否定约束）与更智能的分区裁剪。
- 机器学习辅助谓词推导与选择率估计，尝试缓解相关性带来的误差。
- 在分布式与湖仓场景中，等价约束驱动的谓词下推直接影响跨节点数据搬运量。
- 具体能力以各数据库官方最新文档为准。

## 十、小结
等价约束把分散的等值条件汇成推导力，是谓词下推与分区剪枝的基础；约束排除则把表/分区约束转成计划期的剪枝决策。二者共同减少扫描与中间结果，但都受谓词形式限制——函数包裹、OR 条件与动态参数常使优化机会丧失。
