# 代价模型局限性

> 对应 Kleppmann《Designing Data-Intensive Applications》第 3 章、Ioannidis 优化器误差综述与 Garcia-Molina《Database Systems: The Complete Book》查询优化章节。

## 一、背景与挑战
代价模型是真实执行成本的简化近似，它的每一处简化都会在复杂查询上累积成偏差，最终表现为「理论上最优、实际很慢」。
典型的简化包括：假设列间独立、用有限桶近似分布、忽略缓存与并发、把 CPU 与 IO 权重粗糙线性化、以及统计本身的采样误差。
这些简化单独看都合理，叠加起来却能让基数估计偏离真实值数十倍，进而误导 $\arg\min$ 的计划选择。
核心挑战是：优化器只能基于「它知道的信息」决策，而信息既不完备也不总是新鲜；越是复杂查询，误差越容易放大。
理解局限不是为了否定代价模型，而是为了在计划异常时知道该查什么、改什么、以及何时该人工干预。

## 二、核心原理
第一类局限来自独立性假设。优化器常把复合谓词的选择率相乘，忽略列相关；一旦列强相关，乘积会严重低估或高估。
第二类来自分布近似。直方图与 MCV 只能覆盖有限形态，长尾、多峰、偏斜分布很难被刻画，桶内均匀假设进一步引入误差。
第三类来自执行模型简化。代价模型往往不含缓存命中、并发争用、NUMA、磁盘队列深度等效应，而这些在真实系统中影响巨大。
第四类来自搜索受限。连接顺序搜索空间随表数指数增长，优化器设置深度上限后退化为启发式，可能错过更优计划。
第四类与前三类不同：它不来自估计错误，而来自搜索预算不足，属于「知道但没找到」。

## 三、形式化与数学基础
估计基数 $\hat{C}$ 与真实基数 $C$ 的误差常近似为乘法关系，各项误差 $\epsilon_i$ 相乘：

$$ \hat{C} = C \cdot \prod_{i=1}^{k} \epsilon_i $$

当多项 $\epsilon_i > 1$（或 $< 1$）同向累积时，误差呈指数增长：

$$ \log \hat{C} - \log C = \sum_{i=1}^{k} \log \epsilon_i $$

由于计划选择依赖估计代价 $\hat{C}(\pi)$，估计偏差会翻转最优计划：

$$ \pi_{\text{true}}^{*} = \arg\min_\pi C(\pi) \neq \arg\min_\pi \hat{C}(\pi) = \hat{\pi}^{*} $$

相邻算子的误差还会级联：连接树底层的行数偏差会被上层放大。这解释了为什么「一个统计错误」能导致整条计划崩坏。搜索受限则可用下界描述：优化器只探索 $\Pi_{\text{search}} \subset \Pi$，若最优计划不在其中，则无论代价模型多准都无法选中。

## 四、代码实现
```sql
-- 用 EXPLAIN ANALYZE 暴露估计与实际的偏差
EXPLAIN (ANALYZE, BUFFERS, VERBOSE)
SELECT c.name, sum(o.amount)
FROM customers c JOIN orders o ON o.cust_id = c.id
WHERE c.region = 'APAC' AND o.status = 'paid'
GROUP BY c.name;

-- 对比 estimated rows 与 actual rows，偏差大处即局限所在
-- 关注：
--   rows=X (estimated)  vs  actual rows=Y
--   loops 导致的实际放大
--   是否出现 Nested Loop 配大表（典型估计过低信号）

-- 检查统计新鲜度与相关性
SELECT attname, n_distinct, correlation, last_analyze
FROM pg_stats WHERE tablename IN ('customers', 'orders');

-- 列相关时创建扩展统计
CREATE STATISTICS st_cust_region_status (dependencies)
ON region, status FROM customers;
ANALYZE customers;
```

## 五、与其他技术对比
| 方案 | 机制 | 能缓解的局限 | 代价 |
|---|---|---|---|
| 更好的统计 | 多列/表达式统计 | 独立性、分布近似 | 维护成本、规划开销 |
| 自适应查询处理 | 运行时调整并行度/计划 | 估计误差 | 实现复杂 |
| 反馈优化/重优化 | 用实际行数重优化 | 估计误差级联 | 重复规划、不稳定 |
| Learned Optimizer | 模型预测基数/代价 | 多项局限 | 训练数据、泛化风险 |
| 计划提示/CTE 物化 | 人工约束 | 搜索受限 | 需专家、易过拟合 |

## 六、常见误区
- 盲信优化器选的计划：它基于简化模型，偏差大时选择未必优。
- 认为调一处参数能根治：需综合统计、硬件参数、SQL 写法多管齐下。
- 只看总耗时不看估计偏差：偏差才是根因，耗时只是表征。
- 认为统计越新越好：高频 ANALYZE 有开销，应按变更率触发并关注相关性。
- 忽视搜索受限：有时最优计划根本没被枚举，调统计也无用，需改写查询或加提示。

## 八、面试题
1. 问：为什么优化器会选错计划？
   答：统计不准、列相关、代价参数失真、搜索受限等多重局限叠加。
2. 问：误差为何呈乘法累积？
   答：复合选择率相乘、连接行数逐层放大，各因子误差同向时指数增长。
3. 问：搜索受限与估计误差有何不同？
   答：前者是没找到最优计划，后者是评价标准偏离真实，二者需不同手段处理。
4. 问：如何快速定位局限？
   答：用 `EXPLAIN ANALYZE` 对比估计与实际行数，偏差最大的节点即根因线索。
5. 问：何时应人工干预计划？
   答：统计与参数都已合理、估计仍偏差大且查询关键时，才考虑改写或提示。

## 九、演进与趋势

- 云数据库把统计管理与自动调参做成托管能力，减少人工干预。

## 十、小结
代价模型是有用但粗略的指南：独立性假设、分布近似、执行模型简化与搜索受限共同造成偏差，且误差常呈乘法累积并翻转计划选择。正视局限，才能用 `EXPLAIN ANALYZE`、统计更新、参数校准与必要的人工干预正确诊断与修复。
