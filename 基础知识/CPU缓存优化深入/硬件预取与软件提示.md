# 硬件预取与软件提示

> 对应 Hennessy & Patterson《Computer Architecture》预取章节 / 《CSAPP》第5章。

## 一、背景与挑战
即使顺序访问，首访仍 miss。预取在访问前将数据搬入缓存，隐藏延迟。但过度预取会污染缓存、挤占带宽，反而降低性能。

## 二、核心原理
硬件预取器监测访问流(如步长、流缓冲)，自动发起预取。软件预取通过 intrinsic(如 x86 `PREFETCHT0`)显式提示。预取目标应在被使用前足够早到达，又不至于过早被驱逐。

## 三、形式化与数学基础
设预取提前量需覆盖缺失延迟 $L$ 与产生间隔 $\tau$：
$$ \text{lookahead} \ge \lceil L / \tau \rceil $$
若预取触发到可用时间 $t_{pref} < L$ 则无收益；若提前超过驻留时间则被替换。有效预取率：
$$ \eta = \frac{\text{useful prefetches}}{\text{total prefetches}} $$

## 四、代码实现
```c
// x86 软件预取：提前取后续元素
#include <xmmintrin.h>
void process(int *a, int n) {
    for (int i = 0; i < n; i++) {
        if (i + 16 < n)
            _mm_prefetch((const char*)&a[i+16], _MM_HINT_T0);
        a[i] = a[i] * 2;   // 当前元素已被预取
    }
}
```

## 五、与其他技术对比
硬件预取透明但保守(仅规则模式)；软件预取精确但需手写且绑定微架构。预取与分块互补：分块减少工作集，预取隐藏剩余缺失。

## 六、常见误区
认为预取越多越好，无效预取占用带宽与 MSHR 条目。在随机访问模式预取无效。预取不能替代算法局部性。

## 七、与开源书/权威来源对应
Hennessy & Patterson 详述流缓冲与步长预取器；Intel SDM 描述 PREFETCH 指令语义。

## 八、面试题
硬件预取如何识别流？软件预取何时无效？预取污染是什么？

## 九、演进与趋势
机器学习驱动的预取器、跨页/跨步长预测、SMS(大步幅流)预取器；硬件与编译器协作更紧密。

## 十、小结
预取以带宽换延迟，关键在于时机与精度。规则流依赖硬件，不规则模式需软件提示或重构访问。
