# 写策略与写合并

> 对应 《CSAPP》第6章 / Hennessy & Patterson《Computer Architecture》写缓冲章节。

## 一、背景与挑战
写操作若每次直达内存，延迟高且占用总线。写策略决定何时、如何把脏数据写回。对显存/设备内存，未合并的散写尤其昂贵。

## 二、核心原理
写回(write-back)仅更新缓存，脏位置位，逐出时写回；写直达(write-through)同时写缓存与下一级。写分配/非写分配决定缺失时是否载入。写合并(write-combining, WC)把相邻写聚合成突发事务。

## 三、形式化与数学基础
写直达流量：
$$ \text{BusWr} = W $$ (每次写都上总线)
写回流量：
$$ \text{BusWr} = W \times \text{miss\_rate} / \text{line\_size} $$
写回大幅减少总线写，但需脏位与一致性开销。

## 四、代码实现
```c
// 顺序填充帧缓冲以触发写合并(64B 突发)
#include <stdint.h>
volatile uint32_t *fb = (uint32_t*)0xC0000000;
void draw_line(uint32_t color) {
    for (int i = 0; i < 4096; i++)
        fb[i] = color;   // 连续写被合并为缓存行突发
}
```

## 五、与其他技术对比
写回省带宽但一致性复杂；写直达简单但慢。WC 内存适合 GPU/显存，WB 适合普通 RAM。与读预取互补。

## 六、常见误区
把映射为 WT 的设备内存当 WB 用，导致写丢失。误认为写合并会重排语义——WC 不保证顺序，需屏障。

## 七、与开源书/权威来源对应
《CSAPP》6.4.3 写回与写分配；Hennessy & Patterson 写缓冲与写合并；x86 内存类型(UC/WC/WB)在 Intel SDM。

## 八、面试题
写回 vs 写直达优劣？写合并加快什么场景？为何设备内存用 WC？

## 九、演进与趋势
非临时写(non-temporal store, `MOVNTI`)绕过缓存直写；缓存划分(CAT)按核控制 WB/WC 配额。

## 十、小结
写策略在一致性与带宽间权衡；写合并与 NT store 是绕过缓存、压低延迟的关键手段。
