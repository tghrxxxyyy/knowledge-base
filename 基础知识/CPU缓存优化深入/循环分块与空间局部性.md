# 循环分块与空间局部性

> 对应 Bryant & O'Hallaron《CSAPP》第6章 / Hansimov/csapp (GitHub)。

## 一、背景与挑战
矩阵乘法 `C = A*B` 朴素三层循环对 B 按列访问，步长为 N 的跨距访问破坏空间局部性，缓存缺失率极高，性能远未达到硬件峰值。

## 二、核心原理
循环分块(loop tiling / blocking)将大矩阵切成可放入缓存的块，使块内数据在 evict 前被多次复用。分块后时间局部性提升，cold miss 与 capacity miss 同时下降。

## 三、形式化与数学基础
设块大小 $b$，三层循环分块后内层仅访问 $3b^2$ 字，若 $3b^2 \times 8 \le C_{L2}$ 则工作集驻留 L2。朴素算法每元素缺失约 $2N$ 次，分块后约 $2N/b$ 次，加速比近似 $b$ 倍。

## 四、代码实现
```c
// ijk 顺序 + ikj 分块，B 连续访问
#define N 512
#define B 32
double A[N][N], B[N][N], C[N][N];
void matmul_block() {
    for (int i = 0; i < N; i += B)
        for (int k = 0; k < N; k += B)
            for (int j = 0; j < N; j += B)
                for (int ii = i; ii < i+B; ii++)
                    for (int kk = k; kk < k+B; kk++)
                        for (int jj = j; jj < j+B; jj++)
                            C[ii][jj] += A[ii][kk]*B[kk][jj];
}
```

## 五、与其他技术对比
循环展开减少分支但不解决局部性；分块与向量化(SIMD)正交可叠加；NUMA 分块需结合内存亲和性。

## 六、常见误区
块过大超出缓存反而更慢；块过小增加循环开销。误以为交换循环顺序等于分块，仅改顺序未限制工作集仍可能溢出。

## 七、与开源书/权威来源对应
《CSAPP》6.6 矩阵乘法优化案例；Hansimov/csapp 的 cache lab 要求手工分块；cmu-db/15445 也涉及缓存友好算子。

## 八、面试题
为何 ikj 优于 ijk？如何选块大小？容量缺失与分块关系？

## 九、演进与趋势
编译器自动分块(auto-tuning, e.g. ATLAS/OpenBLAS)、polyhedral 编译自动生成分块；硬件 prefetcher 部分缓解但分块仍必要。

## 十、小结
循环分块通过限制工作集于缓存提升复用，是数值计算优化的基石，块大小需匹配缓存容量。
