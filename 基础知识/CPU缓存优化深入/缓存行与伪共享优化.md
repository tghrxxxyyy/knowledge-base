# 缓存行与伪共享优化

> 对应 Bryant & O'Hallaron《CSAPP》第6章 / remzi-arpacidusse/ostep-code (GitHub)。

## 一、背景与挑战
多核并发时，两个线程修改不同变量若落在同一 64 字节缓存行，会导致该行在核间反复失效(Invalidate)，即使逻辑无共享也产生竞争，称为伪共享(false sharing)，可让并行程序退化成串行性能。

## 二、核心原理
MESI 协议下，某核写缓存行会使其他核该行的副本变为 Invalid。下次其他核写入需重新获取所有权(RFO, Read For Ownership)，引发环上广播与内存事务。伪共享使缓存一致性流量剧增。

## 三、形式化与数学基础
缓存行宽度 $B=64$ 字节。设两个变量地址差 $\Delta a$，当 $\lfloor a_1 / 64 \rfloor = \lfloor a_2 / 64 \rfloor$ 时同处一行即可能伪共享。填充使：
$$ \Delta a \ge 64 - \text{sizeof(type)} $$
典型用 64 字节对齐或填充到独立缓存行。

## 四、代码实现
```c
// 每线程独立计数器，填充到独占缓存行避免伪共享
#include <stdio.h>
#define CACHELINE 64
typedef struct {
    long count;
    char pad[CACHELINE - sizeof(long)];
} padded_t;
padded_t counters[8];   // 每个核一个独立缓存行
void inc(int id) { counters[id].count++; }  // 无 RFO 竞争
```

## 五、与其他技术对比
加锁也能串行化但引入阻塞开销；伪共享优化是无锁的、通过布局而非同步解决。与真实数据共享不同，伪共享是布局假象。

## 六、常见误区
认为 volatile 能解决伪共享：volatile 保证可见性但不改变缓存行布局。填充过大浪费内存与缓存容量。仅并发写才触发，并发只读不伪共享。

## 九、演进与趋势
C11 `_Alignas(64)`、C++17 `std::hardware_destructive_interference_size`、Linux `____cacheline_aligned` 宏成为标准手段；硬件也引入方向预测减少 RFO。

## 十、小结
伪共享是并发性能隐形杀手，根因是缓存行粒度的误失效。通过缓存行对齐隔离热写变量即可消除。
