# 启动阶段的内存与栈初始化

> 对应 Silberschatz《Operating System Concepts》与 Intel SDM 卷3。

## 一、背景与挑战
早期启动没有可用的动态内存分配器，也没有进程概念，需要先用静态预留的栈与最简页表把处理器带到能运行 C 代码的状态，并建立起物理内存映射与早期堆。

## 二、核心原理
固件先用 CAR（Cache As RAM）把 L2/L3 缓存当临时栈，使 PEI 阶段能跑 C 代码；进入内核后，早期汇编用静态定义的栈指针与临时页表（恒等映射加内核高位映射）跳到 C 入口；随后建立页表、探测 e820/内存映射，初始化伙伴系统之前的启动分配器（memblock）。

## 三、形式化与数学基础
页表把虚拟页号映射到物理帧号，恒等映射满足：

$$ \forall v \in V_{ident},\; \text{PA}(v) = v $$

内核直接映射区（直接映射物理内存）满足：

$$ \text{VA} = \text{phys\_base} + \text{PA} $$

## 四、代码实现
早期栈与入口（x86-64 简化）：

```asm
.global _start
_start:
    movq    initial_stack(%rip), %rsp
    call    x86_64_start_kernel
    hlt

.section .bss
.align 16
initial_stack:
    .skip 16384
```

```c
void x86_64_start_kernel(void) {
    early_page_table_init();
    memblock_reserve(text, size);
    start_kernel();
}
```

## 五、与其他技术对比
UEFI 有 Boot Services 提供 AllocatePages，内核接管后丢弃；BIOS 阶段几乎没有标准内存服务。memblock 是内核早期的分配器，之后被伙伴系统与 slab 取代，概念类似但生命周期更短。

## 六、常见误区
认为启动阶段可以用 kmalloc，此时分配器尚未初始化；认为栈地址随意，早期栈必须在已映射且非易失内存；忽略 cache-as-RAM 在永久内存就绪前的必要性。

## 七、与开源书/权威来源对应
Silberschatz《Operating System Concepts》第 8 章概述内存管理初始化；Intel SDM 卷3 描述分页与 CR 寄存器；Linux 内核 Documentation/mm/ 描述 memblock 与页分配。

## 八、面试题
为什么启动早期需要 cache-as-RAM；memblock 与伙伴系统的关系；早期页表与最终页表的区别；栈指针从哪来。

## 九、演进与趋势
KASLR 让内核加载地址随机化以抵抗攻击；5 级页表支持更大地址空间；启动内存 sanitizer 帮助发现早期内存错误。

## 十、小结
启动阶段在缺乏正式分配器时，用预留栈、临时页表与启动分配器把处理器推进到能运行完整 C 内核的状态，是后续一切内存管理的基础。
