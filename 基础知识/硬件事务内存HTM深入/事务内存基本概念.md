# 事务内存基本概念

> 对应 Herlihy & Moss《Transactional Memory: Architectural Support for Lock-Free Data Structures》(1993)。

## 一、背景与挑战
锁带来死锁、优先级反转、低并发。事务内存（Transactional Memory, TM）借鉴数据库事务：一段代码作为「事务」原子、隔离地执行，冲突时中止重试。

## 二、核心原理
事务对内存的读写被记录。提交时若无冲突则整体生效（原子性）；若另一事务改了它读过的地址（读集冲突）或它改了别人读/写的地址（写集冲突），则中止（abort）回滚。

## 三、形式化与数学基础
事务 $T$ 有读集 $R_T$、写集 $W_T$。两事务 $T_i,T_j$ 冲突当：
$$Conflict \iff (R_i\cap W_j)\cup(W_i\cap R_j)\cup(W_i\cap W_j)\neq \emptyset$$
无冲突事务可并发提交。

## 四、代码实现
```c
// 软件事务内存（STM）伪代码
atomic {
    x = x + 1;
    y = f(x);
}
// 硬件或运行时保证冲突时整体回滚重试
```

## 五、与其他技术对比
TM 以「乐观并发」替代锁的「悲观互斥」，高冲突下频繁中止反而更慢；低中冲突下并发度显著更高。

## 六、常见误区
误认为事务永远比锁好。高争用场景中止风暴使吞吐崩塌，且事务有容量与系统调用限制。

## 七、与开源书/权威来源对应
Herlihy & Moss 1993 提出 HTM 硬件支持；Shavit & Touitou 1997 提出 STM；ostep 等操作系统教材讨论并发抽象。

## 八、面试题
问：事务内存与数据库事务异同？答：都讲 ACID 中的 A/I，但内存事务无持久化（D），且中止代价低、用于短临界区。

## 九、演进与趋势
HTM 与 STM 混合（HyTM）结合二者优点；语言层（如 C++ 事务性内存 TS）探索语法支持。

## 十、小结
事务内存用「乐观、冲突回滚」取代锁，简化了并发编程，但依赖低冲突假设与硬件支持。
