# HTM的局限与淘汰

> 对应 Intel 各代 erratum 与 2019 年后 TSX 禁用公告。

## 一、背景与挑战
HTM 理论优美，但落地受容量、中止、安全漏洞与实现复杂度困扰。Intel 多次因 erratum 与侧信道禁用 TSX，工业界采用谨慎。

## 二、核心原理
HTM 的根本局限：事务容量受缓存限制（写集/读集溢出即中止）；与虚拟内存、中断、系统调用交互复杂；推测执行状态可能成为侧信道（如 TSX 被用于计时）。当微码修复成本高，厂商选择禁用。

## 三、形式化与数学基础
中止概率近似随冲突率 $c$ 与事务大小 $s$ 增长：
$$P(abort) \approx 1 - (1-c)^{s}$$
大事务、高冲突时迅速逼近 1，使 HTM 退化为频繁回退。

## 四、代码实现
```c
// 检测 TSX 可用性（IA32_ARCH_CAPABILITIES / MSR）
if (!(cpuid_tsx_enabled() && !tsx_disabled_by_ucode()))
    use_lock_only(); // 直接走锁路径
```

## 五、与其他技术对比
相比无锁（CAS/LL-SC）与成熟锁，HTM 在多数通用场景收益不稳定，且可移植性差，逐渐被更可控的方案取代。

## 六、常见误区
误认为 HTM 是未来主流。现实中其部署受安全与正确性顾虑限制，很多服务器 CPU 已默认关闭。

## 七、与开源书/权威来源对应
Intel 安全公告与微码更新说明 TSX 禁用原因；研究论文（如「TSX Aborts」分析）总结局限。

## 八、面试题
问：为何 TSX 被禁用？答：微码/硬件 erratum 与侧信道风险使厂商选择关闭 RTM/HLE，避免错误与安全暴露。

## 九、演进与趋势
研究转向更受限但可靠的「受控事务」与语言级 STM；x86 上 HTM 作为可选优化而非依赖特性。

## 十、小结
HTM 展示了事务内存的可行性，但容量、中止、安全三重局限使其未能成为主流，回退到锁/无锁仍是稳健选择。
