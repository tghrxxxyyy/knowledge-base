# 中止原因与回退路径

> 对应 Intel SDM 卷3 TSX 中止原因编码与 ARM TME 规范。

## 一、背景与挑战
事务中止来源多样：容量超限、数据冲突、页表/TLB 事件、中断、系统调用、I/O 等。健壮的 HTM 代码必须为每种中止提供回退（fallback）。

## 二、核心原理
中止时硬件丢弃事务的所有写（回滚到 XBEGIN 前状态），并返回中止原因（如位图）。软件据此选择重试、降级到锁、或调整事务粒度。常见模式是「事务优先 + 锁兜底」。

## 三、形式化与数学基础
中止原因集合 $\mathcal{A}=\{cap, conflict, interrupt, syscall, \dots\}$。回退策略：
$$Policy(a) = \begin{cases} retry & a=conflict \land tries<T\\ lock\_path & \text{otherwise} \end{cases}$$

## 四、代码实现
```c
for (int t=0; t<MAX_RETRY; t++){
    unsigned status = _xbegin();
    if (status == _XBEGIN_STARTED){ critical(); _xend(); return; }
    if (!(status & CONFLICT)) break; // 非冲突原因直接降级
}
lock_critical(); // 回退路径
```

## 五、与其他技术对比
「乐观重试」适合冲突稀疏；「立即锁兜底」适合高冲突。混合策略平衡二者，但代码复杂度上升。

## 六、常见误区
误认为无限重试最优。重试遇持续性冲突会死循环，必须限制次数并降级。

## 七、与开源书/权威来源对应
Intel SDM 列出 EAX 中止原因位；ARM TME 的 TSTART 返回错误码用于类似回退。

## 八、面试题
问：为何系统调用会让事务中止？答：系统调用可能切换地址空间、访问不可缓存资源，破坏事务隔离假设，硬件只能中止。

## 九、演进与趋势
运行时自适应（统计中止率决定走事务还是锁）成为最佳实践；TSX 在部分 CPU 被禁用削弱其可用性。

## 十、小结
HTM 的实用性取决于健壮的回退路径：识别中止原因、限次重试、最终降级到锁。
