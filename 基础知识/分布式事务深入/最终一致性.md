# 最终一致性

> 对应 Terry et al. 1992 最终一致性，以及 Kleppmann《DDIA》第 9 章。

## 一、背景与挑战
强一致在多副本/分区下代价高、可用性受限（CAP）。许多场景可接受副本短暂不一致，只要经过无新写入后最终收敛——这就是最终一致性。

## 二、核心原理
在无新更新的前提下，经过足够时间所有副本达到相同状态。常用机制：异步复制、读修复（read repair）、写时传播（anti-entropy）、向量时钟/版本号解决冲突。

## 三、形式化 / 数学基础
设副本状态 $R_i(t)$，若自 $t_0$ 后无写，则 $\exists t_1, \forall i,j: R_i(t)=R_j(t), \forall t>t_1$。一致收敛性。冲突解决常用 last-writer-wins（LWW）或 CRDT 自动合并。

## 四、代码实现
```python
def read_repair(key):
    vals = {r: r.get(key) for r in replicas}
    if len(set(vals.values())) > 1:
        winner = max(vals, key=lambda r: vals[r].version)
        for r in replicas:
            if r != winner: r.put(key, vals[winner])
    return vals[winner]
```

## 五、与其他技术对比
| 模型 | 延迟 | 可用 | 读一致性 |
|------|------|------|----------|
| 强一致 | 高 | 低 | 始终 |
| 最终一致 | 低 | 高 | 延迟后 |

## 六、常见误区
1. 最终一致=不一致——只是过渡态。
2. 不需要冲突处理——并发写必有冲突。
3. 最终时间可预期——无上界保证（除非加约束）。

## 九、演进与趋势
CRDT（无冲突复制数据类型）与因果一致性（如 COPS）在最终一致框架内提供更强的收敛与语义保证。

## 十、小结
最终一致性以暂时不一致换取高可用与低延迟，靠复制、冲突解决与修复机制保证收敛。
