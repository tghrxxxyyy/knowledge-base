# 三阶段提交

> 对应 Skeen 1981 三阶段提交论文，以及分布式系统教材。

## 一、背景与挑战
2PC 在协调者崩溃且参与者处于不确定态时会无限阻塞。3PC 试图通过引入超时与预查询阶段降低阻塞概率，但无法在异步网络下完全保证。

## 二、核心原理
3PC 在 2PC 基础上增加 CanCommit 阶段（先问能否提交而不锁资源），其后 PreCommit（类似 2PC 的准备，进入可超时退出状态），最后 DoCommit。参与者在 PreCommit 超时后默认提交，从而避免不确定态无限等待。

## 三、形式化 / 数学基础
状态机增加 `PRECOMMIT`；参与者在 PRECOMMIT 超时 $\to$ commit（假设网络分区下多数已同意）。这依赖于同步假设（有界延迟），在纯异步模型中 FLP 定理表明无法彻底解决。

## 四、代码实现
```python
# 参与者状态机（简化）
if msg == CAN_COMMIT: send(AGREE if ready else ABORT)
elif msg == PRECOMMIT: persist(); start_timer()
elif timeout(PRECOMMIT): commit()   # 3PC 关键：超时默认提交
elif msg == DOCOMMIT: commit()
```

## 五、与其他技术对比
| 协议 | 阶段 | 阻塞 | 假设 |
|------|------|------|------|
| 2PC | 2 | 可能 | 无 |
| 3PC | 3 | 减少 | 有界延迟 |

## 六、常见误区
1. 3PC 彻底解决阻塞——仅在同步网络假设下。
2. 3PC 比 2PC 安全——异步下可能双提交。
3. 工业界多用 3PC——实际应用很少。

## 九、演进与趋势
现代系统放弃 3PC，改用 Paxos/Raft 共识 + 日志复制实现更稳健的原子提交。

## 十、小结
3PC 通过预查询与超时默认提交降低阻塞，但依赖同步假设，工业界多转向共识协议。
