# 时钟与协调

> 对应 Lamport 1978 逻辑时钟，以及 Spanner TrueTime / Google 时钟同步实践。

## 一、背景与挑战
分布式下无全局物理时钟，事件先后顺序难以判断，导致事务冲突、一致性判断困难。需要时钟模型与协调协议来排序与达成一致。

## 二、核心原理
Lamport 逻辑时钟给事件递增编号，保证因果顺序 $a \to b \Rightarrow C(a) < C(b)$。向量时钟能检测并发。物理时钟靠 NTP/PTP 同步但有误差；Spanner 用 TrueTime（GPS+原子钟）给出时间区间 $[t_{earliest}, t_{latest}]$ 实现外部一致事务。

## 三、形式化 / 数学基础
Lamport 规则：发送前 $C \leftarrow C+1$；收到消息 $C \leftarrow \max(C, C_{msg})+1$。TrueTime 保证 $|t_{now} - t_{true}| < \epsilon$，提交等待 $2\epsilon$ 实现线性izable 快照。

## 四、代码实现
```python
def lamport_on_send(clk): return clk + 1
def lamport_on_recv(clk, ts): return max(clk, ts) + 1
# Spanner: 提交前等 uncertainty
def commit():
    s, e = truetime()
    sleep(2 * (e - s))   # 等误差窗口过去
    write_commit_ts(e)
```

## 五、与其他技术对比
| 时钟 | 精度 | 全局序 | 用途 |
|------|------|--------|------|
| 物理 | 有误差 | 否 | 一般 |
| Lamport | 因果 | 部分 | 排序 |
| TrueTime | 区间 | 是 | 外部一致 |

## 六、常见误区
1. NTP 时钟精确——毫秒级误差且可跳变。
2. 逻辑时钟=物理时间——只保因果不保真实时间。
3. 向量时钟可扩展——O(N) 存储。

## 九、演进与趋势
混合逻辑时钟（HLC）结合物理与逻辑时钟；TSO（时间戳预言机，如 TiDB）集中分配单调时间戳。

## 十、小结
时钟与协调是分布式一致的基础：逻辑时钟保因果、TrueTime/TSO 提供全局可排序的时间，支撑外部一致事务。
