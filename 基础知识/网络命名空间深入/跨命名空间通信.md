# 跨命名空间通信

> 对应 Linux man veth(4)/ip-netns(8)；参考 Docker/容器网络文档。

## 一、背景与挑战
两个 netns 默认完全隔离，需要显式通道才能互通：要么二层桥接，要么三层路由，要么借助宿主中转。

## 二、核心原理
- veth pair + bridge：两 ns 各持一端，桥接同二层，直接 L2 通信。
- 路由 + 转发：配置静态路由，经宿主转发（需 ip_forward）。
- 隧道（veth+GRE/VXLAN）：跨主机 ns 互通。

## 三、形式化与数学基础
二层可达条件：
  same_bridge AND ip_same_subnet
三层可达：
  route(dst) exists AND ip_forward=1
VXLAN 封装：
  inner_L2 -> UDP(4789) -> outer_IP  (跨主机 ns 互通)

## 四、代码实现
# 让 ns1 与 ns2 经 bridge 互通
ip link add v1 type veth peer name v1p
ip link add v2 type veth peer name v2p
ip link set v1p master br0; ip link set v2p master br0
ip link set v1 netns ns1; ip link set v2 netns ns2
ip netns exec ns1 ip addr add 10.0.0.1/24 dev v1
ip netns exec ns2 ip addr add 10.0.0.2/24 dev v2

## 五、与其他技术对比
bridge 适合同主机；VXLAN 适合跨主机大二层；纯路由适合三层隔离。

## 六、常见误区
1. 两端 IP 不同子网却挂同一 bridge 不通——需同子网或加路由。
2. 忘记关防火墙导致 FORWARD 被丢。
