# 跨命名空间通信

> 对应 Linux man veth(4) / ip-netns(8) / ip-link(8)；Stevens《TCP/IP Illustrated》卷一（路由与转发）。

## 一、背景与挑战

netns 之间的隔离是默认状态，而不是可选状态。任何互通都必须**显式接线**：可能是一根二层虚拟线缆，可能是一条静态路由，也可能是一条跨主机的隧道。运行时与运维工具的错误，大多出在"以为接上了其实没接上"——配置分散在两个命名空间里，任一侧缺失都表现同样的"不通"。

因此需要把可选路径梳理清楚，并明确每条路径的前提条件（同子网？需转发？需封装？）。

## 二、核心原理

三条基本路径：

- **二层桥接（veth pair + bridge）**：两个 netns 各持 veth 一端，宿主侧两端接入同一网桥。两端处于同一二层域，只要 IP 在同一子网即可直接 ARP 与通信，无需三层转发。
- **三层路由**：veth 一端接宿主、一端在容器，宿主开启 `ip_forward` 并按目标网段配置路由。跨网段通信必须走此路，且 FORWARD 链需放行。
- **隧道（VXLAN/Geneve/GRE）**：跨主机时把内层二层帧封装到外层 UDP/IP 中传输，实现"大二层"；宿主机之间需可达且放行封装端口。

此外还有**直接点对点**：一对 veth 两端分置两个 netns，不给网桥，两端配同子网地址即成一条 /31 式的点对点链路——这是最轻量的跨 ns 通信方式，常用于测试与沙箱。

## 三、形式化与数学基础

二层可达条件：

$$reach_{L2} = same\_bridge \;\land\; ip \in same\_subnet$$

三层可达条件：

$$reach_{L3} = \exists route(dst) \;\land\; ip\_forward = 1 \;\land\; FORWARD_{policy} = ACCEPT$$

跨主机 VXLAN 封装可写成：

$$inner_{L2} \to UDP_{(4789)} \to outer_{IP} \to underlay$$

（4789 为 IANA 分配的 VXLAN 默认端口，部分实现历史上使用其他端口，部署时需两端一致。）

可达性的判定需要注意非对称性——**去程与回程可以走不同机制**：常见拓扑是去程走桥（同子网）而回程因源地址不同走 NAT（跨网段），此时必须两边都配置正确才能通过。用形式化语言说，可达要求正向路径与反向路径同时成立：

$$reachable(a,b) = reach_{a \to b} \;\land\; reach_{b \to a}$$

## 四、代码实现

```bash
# 场景一：两个 netns 经网桥互通（同子网，二层直通）
ip netns add ns1; ip netns add ns2
ip link add br0 type bridge; ip link set br0 up
ip addr add 10.0.0.254/24 dev br0

ip link add v1 type veth peer name v1p
ip link add v2 type veth peer name v2p
ip link set v1 netns ns1; ip link set v2 netns ns2
ip link set v1p master br0; ip link set v2p master br0
ip link set v1p up; ip link set v2p up

ip netns exec ns1 ip addr add 10.0.0.1/24 dev v1
ip netns exec ns2 ip addr add 10.0.0.2/24 dev v2
ip netns exec ns1 ip link set v1 up; ip netns exec ns1 ip link set lo up
ip netns exec ns2 ip link set v2 up; ip netns exec ns2 ip link set lo up
ip netns exec ns1 ping -c1 10.0.0.2

# 场景二：跨主机用 VXLAN 打通两个 ns 所在的大二层
ip link add vx0 type vxlan id 42 dstport 4789 \
    remote 192.168.1.20 local 192.168.1.10 dev eth0
ip link set vx0 master br0; ip link set vx0 up
```

## 五、与其他技术对比

| 维度 | 桥接（同主机） | 三层路由 | VXLAN 隧道 | macvlan/ipvlan |
| --- | --- | --- | --- | --- |
| 适用范围 | 单主机 | 单主机或经路由器 | 跨主机大二层 | 单主机直连物理网 |
| 是否需要转发 | 否（二层） | 是 | 是 | 否 |
| 是否需隧道封装 | 否 | 否 | 是 | 否 |
| MTU 影响 | 无 | 无 | 需下调内层 MTU | 无 |
| 与 netfilter 交互 | 默认不经（需 br_netfilter） | 经 FORWARD | 经 FORWARD | 受限 |

## 六、常见误区

1. **同桥但两端 IP 不同子网**：二层能通、三层不通，必须改子网或加路由。
2. **忘记开转发**：`ip_forward=0` 时跨网段报文在 FORWARD 处被丢。
3. **防火墙默认拒绝**：宿主 FORWARD 策略为 DROP 时会静默丢包，表现为 ping 不通但接口计数正常。
4. **MTU 未随封装下调**：VXLAN 路径上大包被丢弃，出现"能 ping 不能传大文件"。
5. **只配单向路由**：回程路由缺失时连接建立失败。
6. **忘记 loopback**：新 netns 中 lo 默认 down，会影响依赖本地回环的应用与健康检查。

## 八、面试题

1. **两个 netns 如何互通？** 要点：veth pair 加网桥（同子网二层）或经宿主三层路由转发，跨主机再加隧道。
2. **bridge 与路由方式的区别？** 要点：桥不修改 IP、在同一二层域内转发，无需转发开关；路由需 ip_forward 且要经 FORWARD 链策略。
3. **VXLAN 的用途？** 要点：在主机可达的三层网络上构造大二层域，使跨主机容器像在同一交换机下。
4. **为什么打通了却传不了大文件？** 要点：封装导致有效 MTU 下降，未下调内层 MTU 时大包被静默丢弃。
5. **如何快速判断故障在二层还是三层？** 要点：看 ARP/邻居表是否解析成功（二层）、路由与 FORWARD 计数是否增长（三层）。

## 九、演进与趋势

跨主机容器网络的实现路线持续分化：VXLAN/Geneve 覆盖网络（易用、开销固定），纯三层 BGP 方案（无封装、与物理网络对齐），以及 eBPF 侧的直接转发（绕过 iptables 与部分桥接路径）。Cilium 等实现可在同一节点内以 socket 层或 tc/XDP 旁路完成跨 ns 转发，显著降低延迟；硬件侧，DPU 与可编程网卡承担封装与策略，把部分开销从主机 CPU 卸载出去。

## 十、小结

跨 netns 通信不是单一机制，而是"桥接、路由、隧道"三条路径按场景组合的选择题。判断故障时，先分清二层还是三层、去程还是回程、同主机还是跨主机，再逐项核对前提条件，才能稳定定位问题。
