# 命名空间与容器网络

> 对应 OCI 运行时规范与 runc 实现（opencontainers/runc）；参考 Vonng/ddia。

## 一、背景与挑战
容器并非虚拟机，而是用 namespace + cgroup 隔离的进程。网络隔离正是靠 netns 实现"每个容器一套网络栈"。

## 二、核心原理
runc 启动容器时调用 clone(CLONE_NEWNET) 创建新 netns，再通过 veth 接入宿主 bridge，配合 iptables MASQUERADE 实现 NAT 出网。

## 三、形式化与数学基础
容器出网 NAT：
  src: 10.0.0.2:1234 -> POSTROUTING MASQUERADE -> host_ip:random
回包按 conntrack 映射回 10.0.0.2:1234。
隔离保证：容器 A 的端口 80 与容器 B 的端口 80 在不同 netns 互不冲突。

## 四、代码实现
// runc 简化：创建带 netns 的容器
pid_t pid = clone(child_fn, stack,
    CLONE_NEWNET | CLONE_NEWPID | CLONE_NEWUTS | SIGCHLD, arg);
// 父进程将 veth 一端移入子 netns
ip link set veth1 netns <child_pid>
ip netns exec <ns> ip addr add 10.0.0.2/24 dev veth1

## 五、与其他技术对比
host 网络模式共享宿主 netns（无隔离、高性能）；bridge 模式隔离但需 NAT。

## 六、常见误区
1. 容器网络慢就怪 netns——多数开销在 NAT/conntrack。
2. 误以为容器有独立内核——共享宿主内核。

## 十、小结
