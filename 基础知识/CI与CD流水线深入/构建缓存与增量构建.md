# 构建缓存与增量构建

> 对应 Humble & Farley 2010 (Continuous Delivery)。

## 一、背景与挑战
大型仓库全量构建耗时长，重复编译未变更模块浪费算力，拖慢 CI 反馈，降低提交频率。

## 二、核心原理
通过内容寻址缓存（对源文件与依赖计算哈希）复用已有产物；增量构建只重新编译受影响的编译单元及其下游。

## 三、形式化与数学基础
设模块依赖图 G=(V,E)。变更集合 C，需重建 V' = C ∪ {v | 存在 u in C, path u->v}。缓存命中即跳过编译，仅当哈希变化才重建。

## 四、代码实现
```bash
# Bazel 风格：输入哈希命中则复用缓存
bazel build //service:all --remote_cache=grpc://cache:9090
# 本地依赖缓存
npm ci --prefer-offline
```

## 五、与其他技术对比
相比全量构建，增量构建省时但需正确推导依赖；相比分布式缓存，本地缓存更快但无法跨机器共享。

## 六、常见误区
- 缓存键未包含环境变量，导致"相同源码不同结果"的脏缓存。
- 把时间戳写入产物，破坏内容寻址。

## 七、与开源书/权威来源对应
Humble & Farley 2010 强调"只构建一次"并全程复用同一产物，避免构建不一致。

## 八、面试题
如何设计缓存键以保证正确性？增量构建如何处理宏/配置变更？

## 九、演进与趋势
远程构建缓存 + 构建网格（Build Farm）让 CI 节点共享结果，接近本地体验。

## 十、小结
缓存与增量构建用哈希与依赖图消除重复工作，是规模化 CI 的必备优化。
