# 部署流水线编排

> 对应 Kim et al. 2016 (The DevOps Handbook / Accelerate)。

## 一、背景与挑战
从代码到多环境（测试、预发、生产）的推进涉及多步操作，人工串联易出错且不可重复。

## 二、核心原理
把部署建模为可声明、可重试的流水线：环境晋级（promote）基于制品与门禁，每一步产出可被后续复用，失败可定位到具体阶段。

## 三、形式化与数学基础
流水线是有向无环图 D=(Stages, Edges)。晋级条件 promote(s) = gate(s.output) && approval(s)。整体成功当且仅当到达终态且路径连通。

## 四、代码实现
```yaml
deploy-staging:
  stage: deploy
  environment: staging
  script: ["./deploy.sh staging"]
deploy-prod:
  stage: deploy
  environment: production
  when: manual            # 人工批准晋级
  needs: ["deploy-staging"]
  script: ["./deploy.sh prod"]
```

## 五、与其他技术对比
相比脚本拼凑，编排提供可视化、审计与回退点；相比纯 CI，它覆盖了"部署到环境"的连续过程。

## 六、常见误区
- 把环境变量硬编码进脚本，不同环境行为不一致。
- 缺少幂等设计，重复执行产生副作用。

## 七、与开源书/权威来源对应
The DevOps Handbook 用"部署流水线"统一价值流；Accelerate 将部署频率列为四大关键指标之一。

## 八、面试题
部署流水线为什么需要幂等？人工卡点放在哪一层最合适？

## 九、演进与趋势
GitOps 把流水线状态声明在 Git 中，由控制器持续对齐实际与目标状态。

## 十、小结
部署编排把多环境推进标准化、可视化，是高频可靠交付的工程骨架。
