# 蓝绿部署在CD中的应用

> 对应 Humble & Farley 2010 (Continuous Delivery)。

## 一、背景与挑战
原地升级常导致服务短暂不可用，且一旦新版本异常回退成本高。需要近乎零停机的切换能力。

## 二、核心原理
维护两套环境：蓝（当前生产）与绿（新版本）。绿环境验证通过后，通过路由/负载均衡一次性把流量切到绿；异常时切回蓝，实现快速回滚。

## 三、形式化与数学基础
设流量分配 w_blue, w_green 且 w_blue + w_green = 1。蓝绿切换即令 w_green=1 的原子操作；回滚即重置为 w_blue=1。

## 四、代码实现
```bash
# 切换入口流量到 green 池
kubectl patch svc/app -p '{"spec":{"selector":{"version":"green"}}}'
# 异常时回退
kubectl patch svc/app -p '{"spec":{"selector":{"version":"blue"}}}'
```

## 五、与其他技术对比
相比滚动更新，蓝绿切换更彻底、回滚更快，但需要双倍资源；相比金丝雀，它不做小流量灰度。

## 六、常见误区
- 忽略数据库兼容性，蓝绿两版对 schema 假设不同导致切换失败。
- 未先对绿环境做充分冒烟就切流。

## 七、与开源书/权威来源对应
Humble & Farley 2010 把蓝绿部署作为零停机发布的基础模式之一。

## 八、面试题
蓝绿与金丝雀如何选择？蓝绿对数据库迁移有什么要求？

## 九、演进与趋势
与服务网格结合，蓝绿可做到按请求元数据精准切换，进一步降低风险。

## 十、小结
蓝绿部署用冗余环境换取切换与回滚的确定性，是零停机发布的经典方案。
