# 自旋锁基本原语与原子操作

> 对应 Intel SDM 卷3 与 Hennessy & Patterson《Computer Architecture》。

## 一、背景与挑战
多处理器下共享数据需互斥。当临界区极短且持锁期间不可睡眠时，自旋锁比睡眠锁更高效，因为它避免上下文切换。正确性依赖原子读-改-写原语。

## 二、核心原理
自旋锁核心是原子地测试并设置某标志，失败则循环（自旋）直到成功。x86 用 LOCK 前缀的 XCHG 或 CMPXCHG 实现原子交换/比较交换，内存顺序上提供全序（total order）保证。

## 三、形式化与数学基础
用互斥不变量描述：

$$ \forall t_1 \neq t_2,\; \neg(\text{holder}(t_1) \land \text{holder}(t_2)) $$

获取操作由原子指令定义：

$$ \text{acquire} \iff \text{CAS}(\text{lock}, 0, 1) = \text{true} $$

自旋即循环：

$$ \text{while } \neg \text{acquire()} \text{ do spin} $$

## 四、代码实现
基于原子交换的自旋锁：

```c
typedef struct { volatile int v; } spinlock_t;

void spin_lock(spinlock_t *l) {
    while (__sync_lock_test_and_set(&l->v, 1)) {
        while (l->v) cpu_relax();  // 让出流水线
    }
}
void spin_unlock(spinlock_t *l) {
    __sync_lock_release(&l->v);
}
```

x86 上 `__sync_lock_test_and_set` 编译为带 LOCK 的 XCHG。

## 五、与其他技术对比
自旋锁适合短临界区与不可睡眠上下文；信号量/互斥量适合长临界区且可睡眠；RCU 适合读多写少且读侧无锁。自旋锁在单核非抢占内核中常退化为仅禁用抢占。

## 六、常见误区
认为自旋锁可任意长时间持有，长临界区会饿死其他核；在单核上自旋无意义（应禁抢占）；在可睡眠上下文用自旋锁可能死锁。

## 七、与开源书/权威来源对应
Intel SDM 卷3 第 8 章描述 LOCK 与原子指令；Hennessy & Patterson《Computer Architecture》讨论同步原语；Linux 内核 Documentation/memory-barriers.txt 说明顺序语义。

## 八、面试题
自旋锁适用场景；LOCK 前缀作用；为何单核上自旋锁退化为禁抢占；自旋与睡眠锁如何选择。

## 九、演进与趋势
排队锁（ticket/MCS）降低不公平；qspinlock 在大小核架构上优化；硬件事务内存曾尝试但最终受限。

## 十、小结
自旋锁以原子指令在短临界区实现低开销互斥，依赖 LOCK 前缀保证多核原子性，是操作系统并发原语的地基。
