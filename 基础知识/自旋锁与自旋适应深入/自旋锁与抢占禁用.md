# 自旋锁与抢占禁用

> 对应 Linux 内核 Documentation/memory-barriers.txt 与 Intel SDM 卷3。

## 一、背景与挑战
单核内核若允许在持锁时抢占，等价线程可在另一上下文拿到同一逻辑「锁」，造成伪并发死锁或数据破坏。自旋锁因此常与抢占禁用绑定。

## 二、核心原理
在可抢占内核中，spin_lock 既获取原子锁又禁用本地抢占，确保持锁期间不会被同核其他线程打断而再次进入临界区。释放时恢复抢占。PREEMPT 模型下这是必须的；非抢占内核只需原子锁本身。

## 三、形式化与数学基础
设 $P$ 为本地抢占状态，临界区安全条件：

$$ \text{safe} \iff (\text{locked} \land \neg P) $$

即持锁且本地不可抢占。释放后：

$$ \text{unlock}: \text{locked} \gets \text{false},\; P \gets \text{allowed} $$

## 四、代码实现
内核风格（概念）：

```c
void spin_lock_bh(spinlock_t *l) {
    local_bh_disable();     // 禁软中断
    preempt_disable();      // 禁抢占
    arch_spin_lock(&l->raw);
}
void spin_unlock_bh(spinlock_t *l) {
    arch_spin_unlock(&l->raw);
    preempt_enable();
    local_bh_enable();
}
```

## 五、与其他技术对比
spin_lock 禁用抢占与（视变体）软中断；mutex 允许抢占与睡眠但不可在中断上下文用。disabled 抢占的代价小于睡眠，但长于必要会损害实时性。

## 六、常见误区
认为禁用抢占等于禁用中断，实际中断仍可发生，只是不会切到别的线程；认为 preempt_disable 能防 SMP 并发，它只防同核；混淆 spin_lock 与 spin_lock_irq。

## 七、与开源书/权威来源对应
Linux 内核 Documentation/preempt-locking.txt 与 memory-barriers.txt；Intel SDM 卷3；Silberschatz《Operating System Concepts》讨论临界区。

## 八、面试题
为何单核也要禁抢占；spin_lock 与 spin_lock_irq 区别；preempt_disable 防什么；何时用 _bh 变体。

## 九、演进与趋势
实时内核（PREEMPT_RT）把许多自旋锁改为可睡眠的 rt_mutex，减少关抢占区间；优先级继承避免优先级反转。

## 十、小结
自旋锁与抢占禁用协同保证临界区在单核与多核下都安全，禁用抢占防止同核伪并发，是内核同步正确性的基础约定。
