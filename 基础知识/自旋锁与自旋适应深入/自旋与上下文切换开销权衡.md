# 自旋与上下文切换开销权衡

> 对应 Tanenbaum《Modern Operating Systems》与 Silberschatz《Operating System Concepts》。

## 一、背景与挑战
选择自旋还是睡眠本质上是在两种开销间权衡：自旋浪费 CPU 周期，睡眠付出上下文切换与调度延迟。临界区长度、持锁者是否可抢占、是否处于中断上下文决定了最优选择。

## 二、核心原理
经验法则：临界区小于两次上下文切换开销时自旋更优；持锁者可能睡眠时不该自旋；中断上下文不可睡眠必须自旋（或用可睡眠锁的禁用中断变体）。系统负载与 CPU 数也影响——核多则自旋更可能干扰他人。

## 三、形式化与数学基础
设临界区期望时长 $E[T_c]$，上下文切换成本 $C_{cs}$，自旋到释放的等待 $E[W]$。策略期望成本：

$$ C_{spin} = E[W] \times \text{CPU\_cost} $$
$$ C_{sleep} = C_{cs} + \text{sched\_latency} $$

选较小者。更精细地考虑持锁者运行概率 $p$：

$$ C_{adaptive} = p\,C_{spin} + (1-p)\,C_{sleep} $$

## 四、代码实现
阈值判断示例：

```c
#define CTX_SWITCH_COST_CYCLES 5000
// 粗略：若临界区远小于切换成本则自旋
if (estimated_critical_cycles < CTX_SWITCH_COST_CYCLES)
    spin_lock(&l);
else
    mutex_lock(&m);
```

## 五、与其他技术对比
自旋零切换延迟但占 CPU；睡眠不占 CPU 但延迟高；RCU 在读多写少时彻底避免二者；无锁结构用原子指令替换锁。选择是多维度的工程权衡。

## 六、常见误区
认为多核下自旋永远优于睡眠，高负载时自旋浪费严重；认为睡眠一定安全，中断上下文睡眠会崩溃；忽略中断禁用时间对实时性的影响。

## 七、与开源书/权威来源对应
Tanenbaum《Modern Operating Systems》第 2 与 6 章讨论互斥与调度；Silberschatz 论临界区；OSTEP 的锁章节给出切换成本直觉。

## 八、面试题
如何决定自旋还是睡眠；中断上下文为何必须自旋；临界区长度如何估计；RCU 何时取代锁。

## 九、演进与趋势
混合锁（先自旋若干次再睡眠）成为用户态与内核态常见模式；硬件提示（如 x86 PAUSE）降低自旋功耗。

## 十、小结
自旋与睡眠的权衡取决于临界区时长、持锁者状态与上下文类型，理解这三种维度才能在具体场景选对同步原语。
