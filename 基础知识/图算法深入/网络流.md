# 网络流

> 对应 CLRS《Introduction to Algorithms》第 26 章 Maximum Flow、Ford & Fulkerson (1956)、Dinic (1970) 以及最大流最小割定理。

## 一、背景与挑战

最大流问题：给定有向网络 $G=(V,E,c)$，每条边有容量 $c(e)$，源点 $s$ 与汇点 $t$，求 $s\to t$ 能推送的最大流量。它是组合优化的基石之一，能统一建模大量看似无关的问题：二分图最大匹配、任务分配、项目选择（最小割）、图像分割、网络带宽分配、棒球淘汰赛判定、供需调度。

难点在于建模远比跑算法更难。把实际问题正确转成「源、汇、容量、边」需要技巧：拆点（点容量）、反向边（表示撤销流量）、多重边、超级源汇、二分图的左源右汇。算法层面，纯 DFS 增广（Ford-Fulkerson）在整数容量下正确但可能极慢（找到绕远的增广路）；Edmonds-Karp 用 BFS 找最短增广路保证 $O(VE^2)$；Dinic 用分层图 + 阻塞流进一步降到 $O(V^2 E)$，二分图上 $O(\sqrt V E)$，是工程与竞赛的首选。

面试中网络流属高阶内容，常见考法是「建图转化」（如「灌溉花园」「飞行员配对」「最小体力」「最多路径」）和「最大流最小割定理」的理解。错误往往不在循环，而在反向边忘建、容量方向搞反、源汇选错。

## 二、核心原理

**残量网络（Residual Network）**：流量 $f$ 之后，边 $(u,v)$ 的剩余容量 $c_f(u,v)=c(u,v)-f(u,v)$，同时反向边 $(v,u)$ 的残量容量等于已推流量 $f(u,v)$（允许「退流」）。增广路是残量网络中 $s\to t$ 的路径；沿路径推送 $\Delta = \min$ 残量，更新正反向边。

**Ford-Fulkerson (FF)**：反复在残量网络找 $s\to t$ 路径并增广，直到无增广路。若容量为整数，每次增广至少 +1，最多 $|f^*|$ 次，终止且正确。若容量实数，可能不终止或收敛到非最大流。

**Edmonds-Karp (EK)**：FF 的具体化——每次用 **BFS 找最短增广路**。最短增广路长度随增广单调不减，总增广次数 $O(VE)$，每次 BFS $O(E)$，总 $O(VE^2)$。保证多项式时间。

**Dinic**：两阶段循环：
1. **BFS 建分层图** `level[]`：只走残量为正的边，记录 $s$ 到各点的最短距离（层数）；
2. **DFS 多路增广（阻塞流）**：只在 `level[v] == level[u]+1` 的边推进，用 `it[]` 当前弧优化避免重复扫描，直到该层无增广。

当 BFS 无法到达 $t$ 时结束。分层保证每次 DFS 走最短路；阻塞流把「该长度的增广路」一次性榨干。复杂度 $O(V^2 E)$；单位容量（二分匹配）$O(\sqrt V E)$。

**最大流最小割定理**：$s\-$t 最大流值 = 最小 $s$-$t$ 割容量。割 $(S,T)$（$s\in S,t\in T$）的容量为 $c(S,T)=\sum_{u\in S,v\in T}c(u,v)$。FF 终止时残量网络中 $t$ 不再可达，$S$ = 残量网络从 $s$ 可达的点集，即最小割。

**正确性不变量**：流量守恒（除 $s,t$ 外入流=出流）；容量约束 $0\le f(e)\le c(e)$；残量网络始终合法。每步增广不破坏守恒，最终无增广路即最大。

## 三、形式化与数学基础

**流与割**。流 $f: V\times V \to \mathbb R^+$ 满足：
1. 容量约束：$0\le f(u,v)\le c(u,v)$；
2. 守恒：对 $v\notin\{s,t\}$，$\sum_u f(u,v)=\sum_w f(v,w)$。
流量值 $|f|=\sum_v f(s,v)-\sum_v f(v,s)$。

**弱对偶**：任意流 $|f|\le c(S,T)$（任意割）。因为流从 $S$ 到 $T$ 的净流出不超过割容量。

**强对偶（最大流最小割）**：存在流 $f^*$ 与割 $(S^*,T^*)$ 使 $|f^*|=c(S^*,T^*)$。
证明构造：FF 终止时令 $S^*$ 为残量网络 $s$ 可达集。此时 $S^*$ 到 $T^*$ 的边已饱和（残量 0），反向边流量 0，故 $|f|=c(S^*,T^*)$。由弱对偶 $|f|$ 为最大、$c(S^*)$ 为最小割。

**EK 复杂度证明思路**：增广后最短增广路长度不减；对每条边，被「关键边」（满流截断）的次数 $O(V)$，共 $O(VE)$ 次关键事件，每次 BFS $O(E)$。

**Dinic 复杂度**：$O(V^2 E)$ 由 $O(V)$ 个不同 BFS 层次 × 每层次阻塞流 $O(VE)$ 得出。二分图单位容量时层数 $O(\sqrt V)$，总 $O(\sqrt V E)$。

**整数容量引理**：若 $c$ 全整数，则 FF 始在有限步终止，且最大流为整数。这是 FF 实用的前提。

## 四、代码实现

Edmonds-Karp 与 Dinic（含当前弧优化、最小割还原），可直接运行。

```python
from collections import deque
from typing import List, Tuple

INF = float('inf')


def edmonds_karp(cap: List[List[int]], s: int, t: int) -> int:
    """
    Edmonds-Karp 最大流。cap[u][v] 为容量，图稠密邻接矩阵。
    返回最大流值。
    """
    n = len(cap)
    flow = [[0] * n for _ in range(n)]
    max_flow = 0

    while True:
        # BFS 找最短增广路
        parent = [-1] * n
        parent[s] = s
        q = deque([s])
        while q and parent[t] == -1:
            u = q.popleft()
            for v in range(n):
                if parent[v] == -1 and cap[u][v] - flow[u][v] > 0:
                    parent[v] = u
                    q.append(v)
        if parent[t] == -1:
            break
        # 计算瓶颈并增广
        path_flow = INF
        v = t
        while v != s:
            u = parent[v]
            path_flow = min(path_flow, cap[u][v] - flow[u][v])
            v = u
        v = t
        while v != s:
            u = parent[v]
            flow[u][v] += path_flow
            flow[v][u] -= path_flow
            v = u
        max_flow += path_flow
    return max_flow


class Dinic:
    """Dinic 最大流，邻接表 + 当前弧优化。"""

    def __init__(self, n: int):
        self.n = n
        self.graph: List[List[List[int]]] = [[] for _ in range(n)]
        # 每条边: [to, cap, rev_index]

    def add_edge(self, u: int, v: int, c: int) -> None:
        self.graph[u].append([v, c, len(self.graph[v])])
        self.graph[v].append([u, 0, len(self.graph[u]) - 1])

    def bfs(self, s: int, t: int, level: List[int]) -> bool:
        for i in range(self.n):
            level[i] = -1
        level[s] = 0
        q = deque([s])
        while q:
            u = q.popleft()
            for v, c, _ in self.graph[u]:
                if c > 0 and level[v] < 0:
                    level[v] = level[u] + 1
                    q.append(v)
        return level[t] >= 0

    def dfs(self, u: int, t: int, f: int, level: List[int], it: List[int]) -> int:
        if u == t:
            return f
        while it[u] < len(self.graph[u]):
            v, c, rev = self.graph[u][it[u]]
            if c > 0 and level[v] == level[u] + 1:
                d = self.dfs(v, t, min(f, c), level, it)
                if d > 0:
                    self.graph[u][it[u]][1] -= d
                    self.graph[v][rev][1] += d
                    return d
            it[u] += 1
        return 0

    def max_flow(self, s: int, t: int) -> int:
        flow = 0
        level = [-1] * self.n
        while self.bfs(s, t, level):
            it = [0] * self.n
            while True:
                f = self.dfs(s, t, INF, level, it)
                if f == 0:
                    break
                flow += f
        return flow

    def min_cut(self, s: int) -> List[bool]:
        """最大流后求最小割的 S 集（s 可达集）。"""
        vis = [False] * self.n
        q = deque([s])
        vis[s] = True
        while q:
            u = q.popleft()
            for v, c, _ in self.graph[u]:
                if c > 0 and not vis[v]:
                    vis[v] = True
                    q.append(v)
        return vis


def bipartite_max_matching(adj: List[List[int]], n: int, m: int) -> int:
    """
    用 Dinic 解二分匹配。左 0..n-1，右 0..m-1。
    源点 n，汇点 n+1。
    """
    dinic = Dinic(n + m + 2)
    s, t = n, n + 1
    for u in range(n):
        dinic.add_edge(s, u, 1)
    for v in range(m):
        dinic.add_edge(n + v, t, 1)
    for u in range(n):
        for v in adj[u]:
            dinic.add_edge(u, n + v, 1)
    return dinic.max_flow(s, t)


if __name__ == "__main__":
    # 经典网络
    # 0->1(3), 0->2(2), 1->2(1), 1->3(2), 2->3(4)
    cap = [
        [0, 3, 2, 0],
        [0, 0, 1, 2],
        [0, 0, 0, 4],
        [0, 0, 0, 0],
    ]
    assert edmonds_karp(cap, 0, 3) == 5

    d = Dinic(4)
    d.add_edge(0, 1, 3)
    d.add_edge(0, 2, 2)
    d.add_edge(1, 2, 1)
    d.add_edge(1, 3, 2)
    d.add_edge(2, 3, 4)
    assert d.max_flow(0, 3) == 5
    s_set = d.min_cut(0)
    assert s_set[0] and not s_set[3]

    # 二分匹配：0-0,0-1,1-1,2-2 -> 3
    adj = [[0, 1], [1], [2]]
    assert bipartite_max_matching(adj, 3, 3) == 3
    print("max flow ok")
```

## 五、与其他技术对比

| 算法 | 思路 | 复杂度 | 适用 |
| --- | --- | --- | --- |
| Ford-Fulkerson | 任意 DFS 增广 | $O(E\cdot \|f^*\|)$，实数不保证 | 教学、整数小流量 |
| Edmonds-Karp | BFS 最短增广 | $O(VE^2)$ | 稳妥、易写 |
| Dinic | 分层 + 阻塞流 | $O(V^2 E)$，二分 $O(\sqrt V E)$ | 竞赛与工程首选 |
| ISAP / 预流推进 | 高度标签、溢出流 | $O(V^2 E)$ 或更好 | 常数更优、实现复杂 |
| 费用流 SSP | 每次最短路 + 最小费用增广 | 视实现 | 带权匹配、运输 |

匹配 vs 流：纯二分匹配用匈牙利/霍普克罗夫特更快更短；一旦有容量、多源多汇、边权，转网络流。最小割应用（项目选择、图像分割）是流模型的独特优势。

## 六、常见误区

1. **忘记建反向边**。残量网络依赖反向边表示退流；漏建会导致「无法撤销错误流量」，结果非最大或不正确。反向边初始容量 0，增广时 `cap[u][v] -= d; cap[v][u] += d`。
2. **DFS 不记录当前弧（无 `it`）**。Dinic 若每次从头扫邻接表，会重复扫描已确定不可增广的边，复杂度退化。必须 `it[u]` 游标。
3. **BFS 分层后仍走非 `level[v]==level[u]+1` 的边**。破坏最短路性质，Dinic 正确性与复杂度都受影响。
4. **建图漏源汇或方向反**。如二分匹配忘记「源连左、右连汇」，或容量写在反向。建图错会让最大流为 0 或偏小，且很难从算法端排查。
5. **实数容量用 FF 可能不终止**。非整数容量时增广可能无限细分。实数场景用 EK/Dinic 或带 eps 的实现。

## 八、面试题

**1. 最大流最小割定理是什么？如何找最小割？**

参考答案：最大流值 = 最小割容量。求最大流后，在残量网络中从 $s$ 做 BFS，可达点集为 $S$，$(S, V\setminus S)$ 即最小割。常用于「哪些边是瓶颈」「项目选择最大化收益」等题。

**2. 为什么 FF 用 BFS 找最短增广路就变成多项式时间？**

参考答案：BFS 保证增广路长度单调不减，每条边被「关键边」次数 $O(V)$，总增广 $O(VE)$，乘 BFS 的 $O(E)$ 得 $O(VE^2)$。任意 DFS 增广可能选绕远路，导致流量分细，整数容量下仍终止但可能指数慢。

**3. 网络流如何建模二分图最大匹配？**

参考答案：源点连左部容量 1，左部连右部（有边则容量 1），右部连汇点容量 1。最大流值 = 最大匹配数。也可从匹配反向理解为单位容量网络。

**4. 项目选择问题（选哪些项目，有依赖与收益）如何用最小割？**

参考答案：正收益项目连源点（容量=收益），负收益连汇点（容量=|代价|），依赖关系 $a$ 需要 $b$ 则建 $a\to b$ 容量 $\infty$。最大流最小割的补集即最优选择，总收益 = 正收益和 - 最小割。

## 九、演进与趋势

网络流的工程化高度成熟：**最小费用最大流**（SSP、Capacity Scaling）用于运输、匹配、指派；**多商品流**、**动态流**、**增量最大流**是研究热点；**预流推进**（Push-Relabel）与 **Link-Cut Tree 优化 Dinic**（$O(VE\log V)$）提升大规模性能。图像分割（Graph Cut）、立体匹配、医学分割经典用最小割求能量最小化。

工程侧，云网络带宽分配、SDN 路由优化、数据中心流量工程都以流模型为内核。编译器寄存器分配、VLSI 布线也用流与割。机器学习中，能量模型推断、图匹配（Graph Matching Networks）与流理论结合。理解残量网络与增广路，是理解一切流与割问题的钥匙。

## 十、小结

网络流的核心是残量网络 + 增广路：FF 反复增广至无路，EK 用 BFS 最短增广 $O(VE^2)$，Dinic 用分层阻塞流 $O(V^2 E)$（二分图 $O(\sqrt V E)$）。最大流最小割定理把流量与割对偶，是建模与验证的利器。实现三要素：反向边、当前弧、分层判断。建模能力（拆点、超级源汇、容量设计）比模板更重要——把任务分配、项目选择、图像分割正确转成流，才算真正掌握。
