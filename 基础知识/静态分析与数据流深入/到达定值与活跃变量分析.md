# 到达定值与活跃变量分析

> 对应 Aho, Lam, Sethi & Ullman《Compilers: Principles, Techniques, and Tools》第 9 章；Appel《Modern Compiler Implementation》数据流分析章节；Kildall 1973《A Unified Approach to Global Program Optimization》。

## 一、背景与挑战
两个最常被使用的数据流分析方向恰好相反。常量传播需要知道「在程序点 $p$，变量 $x$ 的值来自哪一次赋值」——这是沿执行方向向前累积的信息；寄存器分配需要知道「在程序点 $p$ 之后，变量 $x$ 是否还会被读取」——这是沿执行方向反推的信息。

把它们放在一起看，才理解编译器优化的基础：没有到达定值就无法安全地把「已知是常量的定值」替换掉使用点；没有活跃信息就无法判断寄存器内容是否还需保留，也无法构造冲突图（interference graph）做图着色分配。

挑战在于控制流带来的分支与循环：一条路径上的定值在另一条路径上可能不存在，循环又让信息反复回流。分析必须保守——宁可不优化，也不能优化错。

## 二、核心原理
**到达定值（reaching definitions，前向 may 分析）**：对每个程序点求「可能到达该点的所有定值」集合。每个基本块 $B$ 有两组信息：$gen_B$ 是块内产生且未被块内后续定值杀死的定值，$kill_B$ 是块内被重新赋值的变量对应的所有旧定值（含其它块中的）。信息沿 CFG 前向传递，入口汇合用并集（某条路径上到达即可，因此是 may 分析）。

**活跃变量（liveness，后向 may 分析）**：对每个程序点求「在此点之后会被读取（在被重新定义之前）」的变量集合。块级 $use_B$ 是块内被读取且读取前未被本块定义的变量，$def_B$ 是块内被定义的变量。信息沿 CFG 后向传递，出口汇合用并集。变量在某定值之后活跃，说明该定值有下游使用，是死代码消除与寄存器分配的判据。

两者用途互补：到达定值支撑常量传播、复制传播与未初始化变量检测；活跃变量支撑死代码消除、寄存器分配与冲突图构造。

## 三、形式化与数学基础
到达定值的块级方程（$IN$ 为块入口信息，$OUT$ 为块出口信息）：
$$OUT[B] = gen_B \cup (IN[B] - kill_B), \qquad IN[B] = \bigcup_{P \in pred(B)} OUT[P]$$
活跃变量的块级方程（方向反转，以出口为起点）：
$$IN[B] = use_B \cup (OUT[B] - def_B), \qquad OUT[B] = \bigcup_{S \in succ(B)} IN[S]$$
格结构：两者都是集合的幂集格。对 may 分析，偏序为包含，上确界为并集，底为 $\varnothing$、顶为全集：
$$x \sqsubseteq y \iff x \subseteq y, \qquad x \sqcup y = x \cup y, \qquad \bot = \varnothing$$
迭代从 $\bot$ 出发单调上升。迁移函数 $f_B(X) = gen_B \cup (X - kill_B)$ 对 $\cup$ 单调，且格高度有限（不超过定值总数），故在有限步内收敛到最小不动点。

一个常用推论：若某使用点 $u$ 的 $IN[u]$ 恰为单元素集 $\{d\}$，则所有执行路径都经 $d$，$u$ 处必然读到 $d$ 写的值，可安全做常量/复制传播；若有两个定值同时到达，则来源不唯一，不能传播。

## 四、代码实现
用位向量实现两个分析，关键是跑工作队列直到不动点。
```python
from collections import deque

def reaching_defs(blocks, preds, succs):
    gen = {b: blocks[b].gen_mask for b in blocks}
    kill = {b: blocks[b].kill_mask for b in blocks}
    IN  = {b: 0 for b in blocks}
    OUT = {b: gen[b] for b in blocks}          # may 分析：从空集向上升
    work = deque(blocks)
    while work:
        b = work.popleft()
        new_in = 0
        for p in preds[b]:
            new_in |= OUT[p]
        if new_in != IN[b]:
            IN[b] = new_in
            new_out = gen[b] | (IN[b] & ~kill[b])
            if new_out != OUT[b]:
                OUT[b] = new_out
                for s in succs[b]:             # 只有变化才传播
                    work.append(s)
    return IN, OUT

def liveness(blocks, preds, succs):
    use = {b: blocks[b].use_mask for b in blocks}
    dfn = {b: blocks[b].def_mask for b in blocks}
    IN  = {b: 0 for b in blocks}
    OUT = {b: 0 for b in blocks}               # may 分析：出口从空集开始
    work = deque(blocks)
    while work:
        b = work.popleft()
        new_out = 0
        for s in succs[b]:
            new_out |= IN[s]
        if new_out != OUT[b]:
            OUT[b] = new_out
            new_in = use[b] | (OUT[b] & ~dfn[b])
            if new_in != IN[b]:
                IN[b] = new_in
                for p in preds[b]:             # 后向：往祖先传播
                    work.append(p)
    return IN, OUT
```
冲突图的构造方式说明了活跃信息的用法：按块内语句**逆序**扫描，遇到定义就把该变量与当前活跃集内所有变量连边（定义者与被活跃者冲突），然后把它从活跃集中移除；遇到使用则加入活跃集。

## 五、与其他技术对比
| 分析 | 方向 | 格汇合 | 典型问题 | 主要用途 |
| --- | --- | --- | --- | --- |
| 到达定值 | 前向 | $\cup$（may） | 哪次赋值可能到达 | 常量/复制传播、未初始化检测 |
| 活跃变量 | 后向 | $\cup$（may） | 值之后是否被读 | 死代码消除、寄存器分配 |
| 可用表达式 | 前向 | $\cap$（must） | 是否所有路径都算过 | 公共子表达式消除 |
| 非常忙表达式 | 后向 | $\cap$（must） | 之后是否必然被算 | 提升计算、循环不变式 |
| 符号分析 | 前向 | 抽象格（非位集） | 变量的符号 | 优化与诊断 |

## 六、常见误区
- 认为活跃变量可以前向计算。它必须从出口反推，因为「之后是否被使用」是未来的性质。
- 忽略块内语句顺序。块内必须先按顺序处理：先定义后使用的变量不增加 $IN$（不进入 $use_B$）。
- 忘记函数调用会影响寄存器。调用可能杀掉调用者保存寄存器，需按调用约定建模，否则活跃集被低估、分配出错。
- 混淆「变量未被使用」与「定值已死」。只有该定值之后再无该变量使用（且不再被重定义）时才是死定值。
- 用 $\cap$ 做 may 分析。方向与汇合算子不匹配会破坏保守性，导致优化不安全。
- 忽略不可达块。不可达块的信息不应参与可达部分的汇合，初始化不当会引入伪事实。

- Aho/Lam/Sethi/Ullman《Compilers》第 9 章：给出到达定值、活跃变量、可用表达式等分析的定义、方程与迭代算法，是本节结论的标准出处。

## 八、面试题
1. 活跃变量为什么必须后向分析？要点：判断「之后是否被使用」，信息从使用点向定义点反推，出口初始化后沿逆边传播。
2. 到达定值与活跃变量如何配合用于优化？要点：前者确定使用的来源以做常量/复制传播；后者判断定值是否死、并构造冲突图。
3. 两者都是 may 分析却方向相反，说明什么？要点：信息内容都是「可能的集合」故汇合用并集，差别只在传播方向。
4. 死代码消除的判据是什么？要点：定值 $d$ 定义的变量在 $d$ 的所有后继点都不活跃，即结果永远不会被读取。
5. 函数调用对活跃分析有什么影响？要点：调用点可能读取实参、写回返回值、破坏调用者保存寄存器，必须按调用约定建模。

## 九、演进与趋势
SSA 形式让到达定值变得隐式：每个变量每次定义恰有一个名字，「到达」退化为「使用哪个版本」，分析从集合运算简化为图上传播。活跃分析随之转为 SSA 的 liveness，用于构造 SSA 销毁（de-SSA）的合并与寄存器分配。工程上，稀疏化（只在定义与使用点之间传播）与基于支配树的求解显著降低了分析成本；语言层面，所有权与借用检查把一部分「值是否还会被使用」的判断提前到类型系统完成。具体实现以官方最新文档为准。

## 十、小结
到达定值与活跃变量是数据流家族的一对镜像：前者前向、回答「值从哪来」，后者后向、回答「值还要不要」。二者都是 may 分析、都用并集汇合，却因方向不同服务于完全不同的优化；把它们放在同一格框架下理解，是掌握后续所有数据流分析的关键一步。
