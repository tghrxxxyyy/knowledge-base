# 到达定值与活跃变量分析

> 对应 Aho 等《Compilers》第 9 章；Appel《Modern Compiler Implementation》第 17 章。

## 一、背景与挑战
常量传播需知道某点能见到哪个赋值；寄存器分配需知道某点之后变量是否还被用（活跃）。两者方向相反，却同属数据流家族。

## 二、核心原理
到达定值（前向 may）：gen 为块内新定值，kill 为同变量旧定值，$OUT=gen\cup(IN-kill)$。活跃变量（后向 may）：变量在块后使用则活跃，$IN=use\cup(OUT-def)$。活跃分析驱动寄存器分配，到达定值驱动常量传播。

## 三、形式化与数学基础
到达定值：
$$OUT[B] = gen_B \cup (IN[B] - kill_B)$$
活跃变量：
$$IN[B] = use_B \cup (OUT[B] - def_B)$$
其中 use/def 为块内上行/下行引用集。

## 四、代码实现
```python
def live_in(b):
    return uses(b) | (live_out(b) - defs(b))
def reaching_out(b):
    return gens(b) | (reaching_in(b) - kills(b))
```

## 五、与其他技术对比
到达定值是 may（可能到达，高估安全）；活跃变量是 may 但后向；二者组合可算"某定值是否唯一到达且仍活跃"，支撑复制传播。

## 六、常见误区
1. 活跃变量前向算——实际必须后向。
2. 把 def 当 use——块内先定义后使用不增加 IN。
3. 忽略过程调用杀掉调用者保存寄存器全部活跃集。

## 九、演进与趋势
SSA 让到达定值隐式表达（每个定值唯一），活跃分析转为 SSA 上的 liveness。

## 十、小结
到达定值与活跃变量是数据流的两面，分别以前向/后向 may 分析支撑常量与寄存器优化。
