# 实时调度

> 对应 Tanenbaum《Modern Operating Systems》实时调度章与 Liu & Layland 经典论文。

## 一、背景与挑战
硬实时任务必须在截止时间（deadline）前完成，否则造成系统失效。通用分时调度（CFS）不提供截止保证，需要 RMS/EDF 等可证明调度算法。

## 二、核心原理
- 速率单调调度 RMS（静态优先级）：周期越短优先级越高，可调度判据 $\\sum \\frac{C_i}{T_i} \\le n(2^{1/n}-1)$。
- 最早截止优先 EDF（动态优先级）：总是运行绝对截止时间最早者，利用率上限为 100%。

## 三、形式化 / 数学基础
RMS 利用率界限（Liu-Layland）：$U_{lub}(n)=n(2^{1/n}-1)$，随 $n\\to\\infty$ 趋近 $\\ln 2\\approx0.693$。单任务临界：$C_1/T_1 + C_2/T_2 \\le 0.828$ 方可调度。

EDF 充分必要：对所有任务 $\\sum \\frac{C_i}{T_i} \\le 1$（独立周期任务、无资源互斥）。

## 四、代码实现
EDF 选程（按绝对截止时间排序的就绪队列头）：

```c
struct rt_task *edf_pick(struct list_head *q) {
    struct rt_task *best = NULL, *t;
    list_for_each_entry(t, q, link)
        if (!best || t->abs_deadline < best->abs_deadline)
            best = t;
    return best;
}
```

## 五、与其他技术对比
RMS 实现简单、可静态分析，但利用率上限仅 ~69%；EDF 利用率达 100% 但需动态排序、对过载更敏感（多米诺效应）。通用 CFS 不保证截止。

## 六、常见误区
- 认为“优先级高=实时保证”：无调度性分析时仍可能错过 deadline。
- 混淆硬实时与软实时：硬实时错过即失效。
- 忽略资源互斥导致的优先级反转会破坏调度性。

## 九、演进与趋势
Linux 通过 SCHED_FIFO/SCHED_RR 与 SCHED_DEADLINE（EDF + 带宽隔离）提供实时支持；多核下引入全局/分区调度与缓存隔离研究。

## 十、小结
实时调度的核心是“可证明的截止保证”：RMS 用静态优先级、EDF 用动态截止，二者以不同利用率代价换取确定性。
