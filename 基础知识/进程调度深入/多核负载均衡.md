# 多核负载均衡

> 对应 Linux 内核 `kernel/sched/fair.c` 的 `load_balance` 与 `idle_balance`，以及 Love《Linux Kernel Development》。

## 一、背景与挑战
多核下每个 CPU 维护自己的运行队列，若不均，会出现“一核忙死、一核闲死”。负载均衡在保持缓存亲和性的同时，将任务从忙队列迁移到闲队列。

## 二、核心原理
- 调度域（sched domain）层级：SMT → MC（核） → NUMA，逐层均衡。
- 周期性 `tick` 与 `idle` 入口触发 `load_balance`；仅在“不平衡超过阈值”时迁移。
- 用 `cpu_load` 与 `nr_running` 衡量，迁移代价与缓存失效权衡。

## 三、形式化 / 数学基础
均衡目标是使各 CPU 的加权负载尽量相等。定义失衡度 $I = \\max_i load_i - \\min_i load_i$；当 $I > imbalance\\_threshold$ 且存在可迁移任务时，迁移量 $m = \\lfloor I/2 \\rfloor$ 以“拉平”而非过度抖动。

## 四、代码实现
`load_balance` 关键片段（简化）：

```c
int load_balance(int cpu, struct rq *busiest) {
    if (busiest->load - this_rq->load < imbalance)
        return 0;                 /* 足够均衡，不动 */
    p = detach_one_task(busiest); /* 从最忙队列取一个 */
    if (p) attach_one_task(this_rq, p);
    return p ? 1 : 0;
}
```

## 五、与其他技术对比
全局队列（所有核共享一个 runqueue）天然均衡但锁争用大；每核私有队列（Linux）扩展性好，但需显式均衡逻辑。NUMA 还要考虑内存就近。

## 六、常见误区
- 认为“越频繁均衡越好”：频繁迁移破坏缓存亲和、增加开销。
- 忽略 NUMA：跨节点迁移会显著增加内存访问延迟。
- 把负载均衡等同“平均分配核数”，实际按权重与容量。

## 九、演进与趋势
EAS（Energy Aware Scheduling）把能耗模型纳入均衡；异构 big.LITTLE 下按算力容量（capacity）而非仅负载分配。

## 十、小结
多核均衡是“亲和性 vs 公平性”的折中：以调度域层级、阈值触发、选择性迁移，在扩展性前提下尽量拉平负载。
