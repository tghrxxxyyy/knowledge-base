# 调度目标与度量

> 对应 OSTEP 第 7-10 章“CPU 调度”与 Silberschatz《Operating System Concepts》第 5-6 章。

## 一、背景与挑战
单 CPU（或单核）上可运行线程数远超硬件并行度，必须在就绪队列中做出“下一个运行谁、运行多久”的决策。调度器需要同时满足吞吐、响应、公平等多目标，而这些目标常常相互冲突（如 throughput 与 response time）。

## 二、核心原理
调度目标通常量化为下列指标：
- CPU 利用率（Utilization）：$U = \\frac{\\text{busy}}{\\text{total}}$
- 吞吐量（Throughput）：$X = \\frac{\\text{完成的进程数}}{\\text{时间}}$
- 周转时间（Turnaround）：$T = \\text{完成时间} - \\text{到达时间}$
- 等待时间（Waiting）：$W = T - \\text{运行时间} - \\text{IO时间}$
- 响应时间（Response）：$R = \\text{首次获得CPU时间} - \\text{到达时间}$

Little 定律将平均驻留数 $N$、吞吐 $X$ 与平均停留时间 $T$ 关联：$N = X \\cdot T$。

## 三、形式化 / 数学基础
对 $n$ 个作业，平均周转时间 $\\overline{T} = \\frac{1}{n}\\sum T_i$。FCFS 下短作业可能被长作业“护航”（convoy effect）。SJF 在“所有作业同时到达且已知运行时间”时使 $\\overline{T}$ 最小（交换论证可证）。

## 四、代码实现
用 Python 模拟 FCFS 与 SJF 的周转时间计算：

```python
def avg_turnaround(jobs):
    # jobs: list of (arrival, burst)
    jobs = sorted(jobs)
    t, total = 0, 0.0
    for arr, burst in jobs:
        t = max(t, arr) + burst
        total += t - arr
    return total / len(jobs)

fcfs = [(0, 8), (1, 4), (2, 9), (3, 5)]
sjf  = sorted(fcfs, key=lambda x: x[1])
print(avg_turnaround(fcfs), avg_turnaround(sjf))
```

## 五、与其他技术对比
FCFS 简单但无抢占、易被长作业拖慢；SJF 最优平均周转但需预知 burst 且可能饿死长作业；RR 以时间片换取公平响应；多级队列/多级反馈队列结合优先级与老化。

## 六、常见误区
- 误以为“吞吐量高”等于“响应快”：二者常此消彼长。
- 误用 SJF 于真实系统：运行时间不可预知，只能预估（如 exponential averaging）。
- 忽略 IO 密集型与 CPU 密集型混合时对响应时间的影响。

## 九、演进与趋势
从单队列 O(1) 调度到 CFS 的虚拟时钟模型，再到 Energy-Aware 与 Heterogeneous（big.LITTLE）感知调度，调度器持续在公平、延迟、能耗间权衡。

## 十、小结
调度本质是“多目标优化”；指标定义清晰是分析与比较算法的第一步，SJF 在已知长度下最小化平均周转，RR 以时间片保交互。
