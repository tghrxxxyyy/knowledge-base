# 顺序一致性与松弛模型

> 对应 Lamport《How to Make a Multiprocessor Computer That Correctly Executes Multiprocess Programs》（1979，SC 原始定义）与 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》内存一致性章节。

## 一、背景与挑战

多线程程序的正确性依赖于一个根本问题：一个核的写入何时、以什么顺序对其他核可见？如果给一个最强答案——任何时刻所有核都看到完全相同的、符合各自程序序的全局执行序列——那就是顺序一致性（Sequential Consistency, SC）。SC 易于推理，但几乎禁止所有提升性能的硬件优化：不能有写缓冲、不能乱序访存、每次写都要等到全局可见。

于是硬件厂商走向松弛（relaxed）模型：保留 SC 的语义骨架，允许特定组合的重排，并要求程序员在真正需要顺序的地方插入栅栏。这形成了一组谱系：TSO（x86）只放松 StoreLoad，PSO 额外放松 StoreStore，弱内存（ARM/POWER/RISC-V RVWMO）几乎不保证任何跨地址顺序。挑战在于：模型越弱，硬件越快，程序员越容易写出「在某个平台上碰巧正确」的代码。

## 二、核心原理

Lamport 的 SC 定义包含两条要求：其一，所有处理器发出的内存操作存在一个全局总顺序；其二，每个处理器自身的操作在该总序中保持其程序序。注意 SC 并不要求「实时」——它不要求操作按墙上时钟顺序生效，只要求存在一个与程序序兼容的全局序。这一点常被混淆，也是 SC 弱于线性一致性（linearizability）的地方。

松弛的方向可以按「重排哪两类访问」来分类：

- 写后读（StoreLoad）：最先被放松的，因为它直接对应写缓冲带来的收益。TSO 放松此项。
- 写后写（StoreStore）：放松后允许写合并与乱序写完成。PSO 放松此项。
- 读后读（LoadLoad）与读后写（LoadStore）：放松后允许乱序执行与投机读。
- 读—读、读—写、写—写、写—读全部放松：弱内存模型，仅靠同步操作建立顺序。

硬件实现这些放松的机制：写缓冲（store buffer）解耦写完成与写可见；失效队列（invalidate queue）解耦失效接收与失效生效；非阻塞缓存与 MSHR 允许缺失期间继续服务其他访问；投机执行允许读先于更早的写。所有这些都提升吞吐，但都把顺序责任转移给了软件。

实际系统的做法是「按需付费」：acquire/release 只约束必要方向，seq_cst 提供全局总序。此外还有一条重要性质——DRF-SC：若程序不存在数据竞争，则在 SC 语义下执行的结果与真实硬件一致，因此程序员只要消除数据竞争，就能用 SC 的直觉推理。这是所有松弛模型能够被工程接受的前提。

## 三、形式化与数学基础

SC 要求：对执行 $E$，存在所有访存操作的全序 $\prec$，使得

$$\forall i:\ \prec_{po(i)} \subseteq \prec \qquad \text{（程序序被全序保持）}$$

且每个读返回该地址在 $\prec$ 中最近一次写所写之值：

$$\forall r:\ val(r) = val\!\left(\max_{\prec}\{w \mid w \xrightarrow{addr} r,\ w \prec r\}\right)$$

松弛模型的形式化方式是「公理 + 顺序对」。定义若干顺序对（如 $\prec_{po}$ 程序序、$\prec_{rf}$ 读写序、$\prec_{mo}$ 修改序、$\prec_{fr}$ 读—读序），然后限定哪些组合必须被禁止。以 TSO 为例，只需保证除「store→load」之外的程序序对都进入全局序：

$$a \prec_{po} b \wedge \neg(store(a) \wedge load(b)) \;\Rightarrow\; a \prec_m b$$

以释放一致性为例，只需保证同步点两侧：

$$W \prec_{po} release \Rightarrow W \prec_m release, \qquad acquire \prec_{po} R \Rightarrow acquire \prec_m R$$

经典 litmus 测试用于区分这些模型。「Store Buffering」（SB）：核 1 执行 `x=1; r1=y`，核 2 执行 `y=1; r2=x`。SC 禁止 $r_1 = r_2 = 0$，TSO 允许，加 MFENCE 后禁止。「Message Passing」：SC 与 RC 都禁止「看到旗标未见数据」，而纯 relaxed 允许。

SC 的性能代价可用「每次写的全局确认往返」刻画。设缓存一致性往返延迟为 $L$，则 SC 下单次写的有效成本约为：

$$Cost_{SC}(store) \approx L \quad \text{（可能需等待全局可见）}$$

而 TSO/RC 下普通写只需进入本地写缓冲：

$$Cost_{TSO}(store) \approx 1 \text{ 周期（缓冲写入）} + \text{异步完成}$$

这就是松弛模型能带来数倍吞吐提升的量化原因，也是「SC 税」（SC tax）这一说法的来源。

## 四、代码实现

```c
/* 顺序一致性下的自旋锁：SEQ_CST 提供全局单一顺序，易于推理但代价最高 */
#include <stdatomic.h>

static atomic_int g_lock = 0;

static void sc_lock(void) {
    while (atomic_flag_test_and_set_explicit(&g_lock, memory_order_seq_cst)) {
        /* 忙等；生产代码应插入 pause / yield */
    }
}

static void sc_unlock(void) {
    atomic_flag_clear_explicit(&g_lock, memory_order_seq_cst);
}

/* 同样的锁，用 acquire/release 实现：正确性不变，代价更低 */
static void rc_lock(void) {
    int expected = 0;
    while (!atomic_compare_exchange_weak_explicit(&g_lock, &expected, 1,
                                                  memory_order_acquire,
                                                  memory_order_relaxed)) {
        expected = 0;                       /* CAS 失败后必须重置期望值 */
    }
}

static void rc_unlock(void) {
    atomic_store_explicit(&g_lock, 0, memory_order_release);
}
```

```c
/* SB（store buffering）litmus：在 TSO 上可能观察到 r1==r2==0，
   加入全屏障后该结果被禁止 */
static int x, y, r1, r2;

void thread1(void) { x = 1; __atomic_thread_fence(__ATOMIC_SEQ_CST); r1 = y; }
void thread2(void) { y = 1; __atomic_thread_fence(__ATOMIC_SEQ_CST); r2 = x; }

/* 若去掉两个 fence，则 (r1, r2) == (0, 0) 在 TSO/弱内存上均可能出现；
   在 SC 语义下不可能出现。 */
```

实现要点：CAS 循环中的 `expected` 必须每次重试前重置（或依赖 `compare_exchange` 在失败时回写当前值这一约定）；自旋等待需要退避策略（pause、指数退避、yield）以免浪费执行资源与一致性带宽；把「读—改—写」+「全屏障」合并成一条指令（x86 的 LOCK 前缀，ARM 的 LDAXR/STLXR 循环）通常比「普通 CAS + 单独 MFENCE」更经济。

## 五、与其他技术对比

| 模型 | LoadLoad | LoadStore | StoreStore | StoreLoad | 代表平台 | 推理难度 |
| --- | --- | --- | --- | --- | --- | --- |
| SC | 保序 | 保序 | 保序 | 保序 | 无主流硬件 | 最低 |
| TSO | 保序 | 保序 | 保序 | **可重排** | x86 | 低 |
| PSO | 保序 | 保序 | **可重排** | **可重排** | 部分历史架构 | 中 |
| RCsc/RCpc | 可重排 | 可重排 | 可重排 | 可重排 | ARM、POWER | 高 |
| 纯弱序 | 可重排 | 可重排 | 可重排 | 可重排 | 早期 Alpha | 最高 |

补充维度：线性一致性（linearizability, Herlihy & Wing 1990）比 SC 更强——它额外要求操作的生效顺序尊重实时（真实时间）顺序，因此是分布式与并发数据结构的正确性标准；SC 只要求存在某个与程序序兼容的总序，不约束实时性。

## 六、常见误区

1. 认为 x86 是 SC：它是 TSO，允许 StoreLoad 重排，需要 MFENCE 或 LOCK 才能获得 SC 语义。
2. 认为顺序一致的 C 代码天然线程安全：SC 只约束「有定义的」执行，数据竞争使程序行为未定义，与模型强弱无关。
3. 混淆 SC 与线性一致性：SC 不要求实时顺序，线性一致性要求；前者是硬件模型，后者是无锁数据结构的正确性判据。
4. 认为屏障可以「加速」可见性：屏障只约束顺序，不缩短一致性协议的传播延迟。
5. 认为松弛模型一定「不可移植」：用语言级原子操作并按需选择内存序，可以在所有平台上正确且高效。
6. 认为 scoped/域限定一致性等同于弱化正确性：作用域只是限定同步的可见范围（如线程内、设备内、全系统），并不放弃正确性，只是要求程序员正确选择范围。

## 八、面试题

1. 问：SC 与 TSO 的关键区别？答：TSO 允许较晚的读越过较早的写（StoreLoad 重排），SC 不允许任何重排；其余三类重排在 TSO 中仍被禁止。
2. 问：SC 与线性一致性有何不同？答：SC 只要求存在与程序序兼容的全局总序，不要求尊重实时顺序；线性一致性额外要求操作按真实时间生效，是并发对象的正确性条件。
3. 问：DRF-SC 保证的意义是什么？答：若程序无数据竞争，则所有提供 SC-for-DRF 的模型下的执行结果都与 SC 一致，程序员可用 SC 直觉推理，无需关心底层重排。
4. 问：为什么 StoreLoad 最先被放松？答：它直接对应写缓冲带来的吞吐收益；放松后普通写无需等待全局确认，代价是需要显式屏障才能获得「写后读」的顺序。
5. 问：弱内存下如何写出既正确又高效的代码？答：先消除数据竞争（锁或原子），再按需选择内存序（优先 acquire/release），只在真正的双向顺序需求处使用 seq_cst 或全屏障。

## 九、演进与趋势

- 语言级模型统一硬件差异：C++11/Java/Rust 把 SC、acquire/release、relaxed 作为标准词汇，取代平台相关的屏障指令。
- SC-for-DRF 成为最低公共标准：所有主流模型都保证无竞争程序的可推理性，这让「先消除竞争，再谈性能」成为工程共识。
- 域限定一致性：以作用域（线程/设备/系统）弱化同步范围，降低跨域同步成本。
- 形式化与验证：litmus 测试、模型检查与编译器测试成为发布前验证内存模型实现的常规手段。
- 硬件弱化与软件抽象分离：硬件继续弱化以省功耗，软件层（语言、运行时、库）承担把语义补回来的责任。

## 十、小结

顺序一致性是并发正确性的黄金标准：它给出「存在一个全局总序并尊重程序序」这一清晰语义，但代价是禁止写缓冲与乱序，性能代价高昂。松弛模型用可推理的栅栏换性能——TSO 只放松 StoreLoad，弱内存几乎全部放松，而 acquire/release 与 seq_cst 让程序员按需付费。掌握 SC 的定义、各模型的放松点、以及 DRF-SC 这条安全底线，就掌握了现代多核编程中「正确性与性能如何分账」的全部要点。
