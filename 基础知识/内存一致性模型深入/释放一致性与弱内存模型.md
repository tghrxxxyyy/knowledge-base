# 释放一致性与弱内存模型

> 对应 Hennessy & Patterson 量化方法弱内存章与 ARM 厂商手册。

## 一、背景与挑战
释放一致性（RC）将同步与数据共享分离：普通访问可任意重排，仅 acquire/release 同步点需保序。ARM/POWER 等弱内存模型进一步松弛，性能高但正确性依赖显式标注。

## 二、核心原理
RC 区分普通读写与同步操作：acquire（进入临界区）之后的普通访问不得在它之前执行；release（离开）之前的访问不得在其后。硬件只需在同步点插入必要屏障，普通访问自由重排。

## 三、形式化与数学基础
RC 约束：
$$W_{before\_release} \xrightarrow{prog} release \Rightarrow W_{before} \text{全局先于 release}$$
$$acquire \xrightarrow{prog} R_{after} \Rightarrow acquire \text{全局先于 } R_{after}$$
普通读写间无跨线程顺序保证。

## 四、代码实现
```c
#include <stdatomic.h>
atomic_int lock = 0;
void critical(void) {
    // acquire: 之前的普通访问不能移到锁内
    while (atomic_exchange_explicit(&lock, 1, memory_order_acquire)) {}
    data = compute();      // 临界区
    // release: 区内写须在释放前全局可见
    atomic_store_explicit(&lock, 0, memory_order_release);
}
```

## 五、与其他技术对比
相比 SC 全保序，RC 只保同步点，普通访问可深度流水线化；相比无模型，RC 给出可证明的同步语义，便于推理。

## 六、常见误区
误以为 release 后写立即可见：仅保证"之前写已完成"。误以为普通变量跨线程安全：仍需原子/同步。

## 七、与开源书/权威来源对应
量化方法 RC；C++11 标准；ARM Barrier Litmus Tests。

## 八、面试题
问：acquire/release 相比 SC 少了什么保证？答：普通访问间的跨线程顺序。

## 九、演进与趋势
Rust/C++ 原子类型将 RC 语义语言化，硬件提供轻量屏障。

## 十、小结
释放一致性把"必须保序"收窄到同步点，是弱内存模型下兼顾性能与可推理性的核心抽象。
