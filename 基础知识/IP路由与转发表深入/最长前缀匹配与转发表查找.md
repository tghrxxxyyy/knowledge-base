# 最长前缀匹配与转发表查找

> 对应 RFC 4632 (CIDR) 与 Tanenbaum《Computer Networks》第5章。

## 一、背景与挑战
IP 转发时目的地址可能匹配路由表中多条前缀，需选择最精确（最长掩码）的匹配项，否则会错误路由。高效的最长前缀匹配 LPM 算法直接影响路由器吞吐。

## 二、核心原理
路由表以 (prefix, mask) 组织，转发时对目的 IP 依次按各前缀掩码取位比较，取匹配位数最多的条目。默认路由 0.0.0.0/0 作为兜底。LPM 保证更具体路由优先于聚合路由。

## 三、形式化与数学基础
设候选前缀集 $P$，目的地址 $d$，匹配判定：
$$ m(p) = \text{最长公共前缀长度}(p, d) $$
选择：
$$ p^* = \arg\max_{p \in P,\, p \text{ matches } d} |p| $$
其中 $|p|$ 为前缀长度（掩码位数）。

## 四、代码实现
Linux 查看路由与匹配：
```bash
ip route show
ip route get 8.8.8.8
```
简单 LPM 实现示意：
```python
def lpm(routes, dst):
    best = None
    for prefix, masklen in routes:
        if (dst & mask(masklen)) == prefix:
            if best is None or masklen > best[1]:
                best = (prefix, masklen)
    return best
```

## 五、与其他技术对比
精确匹配（如 MAC 表）用哈希即可，LPM 需 trie/位图等结构。硬件转发用 TCAM 并行比较所有表项实现单周期 LPM。

## 六、常见误区
误区一是认为路由表按顺序匹配首条命中，实际按最长前缀而非书写顺序。误区二是默认路由优先级高，实为最后兜底。

## 七、与开源书/权威来源对应
RFC 4632 描述 CIDR 与聚合；Tanenbaum 第5章解释 LPM；xiaolincoder 图解 IP 转发查表。

## 八、面试题
问：目的地址同时匹配 /24 和 /16，选哪个？答：选 /24（更长前缀更具体），这就是最长前缀匹配原则。

## 九、演进与趋势
随着路由表超百万条，LPM 结构从简单 trie 演进到多比特 trie、二叉检索等；SRv6 将转发语义扩展到段路由。

## 十、小结
最长前缀匹配是 IP 转发的核心查表规则，保证最具体路由优先。理解 LPM 与默认路由关系对排查路由选择至关重要。
