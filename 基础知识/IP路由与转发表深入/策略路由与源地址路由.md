# 策略路由与源地址路由

> 对应 Linux 策略路由（RPDB）与 RFC 1102 (Policy Routing) 背景。

## 一、背景与挑战
普通路由只按目的地址查表，无法根据源地址、入接口、TOS 等条件选择不同路径。多宿主主机、按业务分流、VPN 分流等场景需要策略路由。

## 二、核心原理
Linux 策略路由由规则库 RPDB 组成，每条规则按匹配条件（源地址、入接口、fwmark、TOS 等）选择路由表。内核先遍历规则，命中后到对应 FIB 查目的路由。典型用途：来自某源走 VPN 表，其余走主表。

## 三、形式化与数学基础
RPDB 是优先级有序规则集 $R = \{r_1 \prec r_2 \prec \dots\}$，每条 $r_i$ 含选择器 $S_i$ 与表 $T_i$：
$$ \text{lookup}(pkt) = \text{FIB}_{T_k}.\text{lookup}(dst),\quad k = \min\{i \mid S_i(pkt)\} $$
即取首个匹配规则指向的表。

## 四、代码实现
Linux 配置源策略路由：
```bash
ip rule add from 192.168.10.0/24 table 100
ip route add default via 10.0.0.1 dev tun0 table 100
ip route flush cache
```
按 fwmark 策略：
```bash
ip rule add fwmark 0x1 table 200
```

## 五、与其他技术对比
普通目的路由简单但僵化；策略路由灵活但规则多时增加查表层级开销。SDN 把策略上收到控制器集中编排。

## 六、常见误区
误区一是认为 `ip rule` 本身就转发，它只选表，实际转发仍在对应路由表。误区二是配置后不刷新缓存导致不生效（旧内核需 flush）。

## 七、与开源书/权威来源对应
Linux `ip-rule`/`ip-route` 文档描述 RPDB；RFC 1102 讨论策略路由概念；运维实践中常用于多出口分流。

## 八、面试题
问：如何让来自内网 A 的流量走电信、内网 B 走联通？答：用 `ip rule` 按源地址分别指向两张路由表，各表配不同默认网关。

## 九、演进与趋势
eBPF 可在 TC/XDP 层实现更灵活的策略路由与负载，逐步补充传统 RPDB；云厂商用 VPC 路由表实现租户级策略。

## 十、小结
策略路由以规则库按多维度条件选择路由表，突破仅按目的地址的限制，是实现多宿主、业务分流的关键手段。
