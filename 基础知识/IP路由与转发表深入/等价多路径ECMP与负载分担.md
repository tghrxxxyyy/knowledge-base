# 等价多路径ECMP与负载分担

> 对应 RFC 2992（Analysis of an Equal-Cost Multi-Path Algorithm）、RFC 791（Internet Protocol）、Hopps 2000 的 ECMP 哈希分析，以及 Kurose & Ross《Computer Networking: A Top-Down Approach》转发与路由章节。

## 一、背景与挑战

当路由表针对同一目的前缀存在多条度量完全相同（前缀长度、管理距离、IGP cost 均相等）的路径时，单路径转发的弊端立刻显现：一条链路被打满而其余闲置，带宽被浪费；一旦这条链路故障，流量只能整体切换而无法平滑分担。ECMP（Equal-Cost Multi-Path）让流量在多条等价路径之间分担，既提升吞吐又提供天然的冗余。但随之而来的是一个严格的约束：同一 TCP 流的所有报文必须走同一条路径，否则到达顺序错乱会触发大量重传与拥塞控制回退，性能反而崩溃。因此 ECMP 的设计核心不是「怎么分得匀」，而是「怎么在保序的前提下分得匀」。

## 二、核心原理

ECMP 在 FIB 中为同一目的前缀维护一个下一跳集合（nexthop group）。转发时对报文头部字段做哈希，用哈希值对集合大小取模选出其中一个下一跳。哈希输入通常是五元组：源 IP、目的 IP、源端口、目的端口、协议号（TCP/UDP）。这五个字段在同一连接的生命周期内保持不变，因此同一流稳定映射到同一条路径，实现保序；不同流因四元组不同而散布到不同路径，实现负载分担。

五元组中若端口号数量少、或大量流来自同一对主机（如数据中心存储流量、视频转码集群），哈希分布会严重偏斜。更隐蔽的问题是「哈希极化」：在多级 Clos/Fat-tree 拓扑中，若每级都用同一个哈希函数与同样的输入，则所有级的选路结果完全相关，等价路径退化为单一物理路径，带宽收益归零。工程上通过每级改变哈希种子（seeds）、加入路由器标识、或使用不同的哈希字段组合来打破相关性。

集合大小变化会引发流颠簸：链路故障时下一跳集合从 $k$ 变为 $k-1$，取模结果整体改变，几乎所有流都会重新映射，导致全表会话出现瞬时乱序。一致性哈希（consistent hashing）或加权一致性哈希把扰动限制在失效路径对应的那些流上，是缓解手段。

## 三、形式化与数学基础

设等价下一跳集合 $N = \{n_1, \dots, n_k\}$，哈希函数 $h$ 输出到 $[0, M)$，路径选择为：

$$ i = h(\text{srcIP}, \text{dstIP}, \text{srcPort}, \text{dstPort}, \text{proto}) \bmod k $$

选择 $n_i$。理想均匀性要求每条路径被选中的概率相同：

$$ P(\text{path} = n_j) = \frac{1}{k}, \quad \forall j $$

现实哈希函数不可能完美均匀，偏差用极化因子衡量。RFC 2992 提出用扰动表（perturbation table）打散低位相关性，其对哈希值 $h$ 的扰动为：

$$ h' = h \oplus p\!\left[\, (h \gg 8) \wedge 15 \,\right] \gg s $$

其中 $p$ 是预生成的伪随机表，$s$ 为位移量。目的是把高位信息混入低位，避免取模时低位规律导致偏斜。

一致性哈希的扰动界可表述为：当集合从 $k$ 变为 $k-1$ 时，期望重新映射的流比例为

$$ \mathbb{E}\!\left[\frac{\text{remapped}}{\text{total}}\right] \approx \frac{1}{k} $$

远优于朴素取模下的接近 $1$ 的比例。

## 四、代码实现

Linux 配置两条等价路径（权重相同即等价）：

```bash
ip route add 10.0.0.0/8 \
  nexthop via 192.168.1.1 dev eth0 weight 1 \
  nexthop via 192.168.2.1 dev eth1 weight 1
ip route get 10.0.0.5
```

内核侧的 ECMP 哈希选择（概念简化版，实际实现见 `net/ipv4/route.c` 与 `fib_multipath_hash`）：

```c
// 计算五元组哈希并选择等价下一跳（概念示意）
static unsigned int ecmp_hash(const struct flow_key *k, unsigned int seed)
{
    unsigned int h = seed;
    h ^= k->saddr;  h *= 0x9E3779B1u;  h ^= h >> 15;
    h ^= k->daddr;  h *= 0x85EBCA77u;  h ^= h >> 13;
    h ^= k->sport;  h *= 0xC2B2AE3Du;  h ^= h >> 16;
    h ^= k->dport;  h *= 0x27D4EB2Fu;  h ^= h >> 15;
    h ^= k->proto;  h *= 0x165667B1u;  h ^= h >> 13;
    return h;
}

static struct nexthop *ecmp_select(struct nexthop_group *g,
                                   const struct flow_key *k,
                                   unsigned int seed)
{
    unsigned int idx = ecmp_hash(k, seed) % g->count;
    return &g->hops[idx];
}
```

运维侧常用 `ip route show` 与 `ip route get` 验证选路，用 `traceroute` 或每流探测确认不同五元组确实走了不同路径。

## 五、与其他技术对比

| 方案 | 保序性 | 分布均匀性 | 故障切换扰动 | 控调度 | 典型场景 |
| --- | --- | --- | --- | --- | --- |
| 逐包轮询（round-robin） | 差（易乱序） | 最优 | 中等 | 无 | 无状态 UDP、实验室 |
| 五元组哈希 ECMP | 好（流内一致） | 受流特征影响 | 大（重映射） | 无 | 数据中心、运营商骨干 |
| 加权 ECMP | 好 | 可调 | 大 | 弱 | 不等带宽链路 |
| 一致性哈希 ECMP | 好 | 中 | 小 | 无 | 大规模无状态后端 |
| MPLS/SR 流量工程 | 好 | 可精调 | 小 | 强 | 运营商、跨域 TE |

关键权衡：逐包负载均衡分布最均匀但有乱序风险，仅适用于无连接或能容忍乱序的流量；基于流的哈希保序但均匀性取决于哈希函数质量与流特征；显式流量工程最可控但需要信令与状态维护，扩展性与运维复杂度更高。

## 六、常见误区

1. 认为 ECMP 能均分每条连接的带宽。实际是按流哈希，单条大象流只能走一条路径，其速率上限仍受该路径瓶颈限制。
2. 认为换个哈希函数就能解决所有偏斜。根因可能是流特征单一（端口集中、地址对固定），此时改变哈希只能缓解而无法根治。
3. 忽略哈希极化。多级拓扑中若各级使用相同哈希输入，等价路径会被相关性绑定成单一路径，ECMP 形同虚设。
4. 认为链路增减不会影响现有流。取模方案的流颠簸会导致大面积重映射与瞬时乱序，需要一致性哈希或可重配置方案缓解。
5. 在需要严格有序的存储或 RPC 流量上盲目开启逐包分担，导致重传风暴。
6. 忘记对称性需求。某些中间盒与防火墙要求双向流走同一条路径，ECMP 必须保证正反向哈希一致，否则会话被丢弃。

## 八、面试题

1. ECMP 为什么用五元组哈希而不是轮询？
   要点：轮询会让同一 TCP 流的报文走不同路径，造成乱序、重传与拥塞窗口回退；哈希保证流内路径一致，兼顾保序与分担。

2. 什么是哈希极化，如何缓解？
   要点：多级拓扑中各级使用相同哈希输入导致选路结果完全相关；通过对每级使用不同种子、加入设备标识或改变字段组合来打破相关性。

3. 链路故障时 ECMP 会怎样？
   要点：下一跳集合变小，朴素取模会导致大量流重映射并瞬时乱序；一致性哈希或可重配置 ECMP 可把扰动限制在失效路径对应的流上。

4. ECMP 能保证单条流的带宽提升吗？
   要点：不能。单流仍走单路径，受该路径可用带宽限制；只有多流并发时才能聚合多条路径的带宽。

5. 为什么某些环境要求 ECMP 保持正反向对称？
   要点：状态化中间盒（防火墙、NAT、连接跟踪）以五元组识别会话，若两个方向走不同路径，回程报文可能被丢弃或状态不同步。

## 九、演进与趋势

ECMP 的演进围绕三件事：更均匀的分布、更小的故障扰动、更细的控调度。具体包括一致性哈希与加权一致性哈希（减少重映射）、动态加权（按链路利用率调整权重）、可重配置 ECMP（链路变化时保持大部分流不变）、以及结合 SRv6 段路由实现细粒度流量工程。在数据中心，ECMP 与自适应路由（adaptive routing，按拥塞实时选路）结合，进一步逼近理论吞吐；在运营商网络中，ECMP 常与 MPLS TE 并存，由 TE 承担精细调度而 ECMP 承担弹性分担。此外，硬件可编程交换机（P4/RMT）让哈希字段与权重可按业务在线调整，是近年最实用的进展方向。

## 十、小结

ECMP 通过哈希把流分布到等价下一跳，在保序前提下实现负载分担与冗余。三个关键工程点决定其成败：用五元组哈希保证流内一致、用扰动表与多级去相关缓解偏斜与极化、用一致性哈希控制链路变化时的流颠簸。它不提升单流带宽，只在多流并发时聚合容量，这一边界必须在容量规划时明确。
