# 等价多路径ECMP与负载分担

> 对应 RFC 2992 (ECMP) 与 RFC 791 (IP) 转发背景。

## 一、背景与挑战
当路由表存在多条等长（相同前缀长度与度量）的下一跳时，单路径转发会浪费带宽且无法弹性。ECMP 让流量在多条等价路径间分担，提升吞吐与冗余，但需保证同一流不乱序。

## 二、核心原理
ECMP 在 FIB 中对同一目的维护下一跳集合，按哈希（通常基于五元组源/目的 IP、端口、协议）将流映射到某条路径。哈希保证同一流始终走同一条，避免乱序；不同流分布到不同路径实现负载分担。

## 三、形式化与数学基础
设等价下一跳集合 $N = \{n_1,\dots,n_k\}$，哈希函数 $h$ 输出桶索引：
$$ i = h(srcIP, dstIP, srcPort, dstPort, proto) \bmod k $$
选择 $n_i$。为保证均匀，常用扰动（如 RFC 2992 的扰动表）缓解哈希偏斜。

## 四、代码实现
Linux 配置多路径路由：
```bash
ip route add 10.0.0.0/8 \
  nexthop via 192.168.1.1 dev eth0 weight 1 \
  nexthop via 192.168.2.1 dev eth1 weight 1
```
查看：
```bash
ip route get 10.0.0.5
```

## 五、与其他技术对比
逐包负载分担可更均匀但易乱序被多数 TCP 场景拒绝；基于流的 ECMP 保序但可能分布不均。MPLS 流量工程可显式选路比 ECMP 更可控。

## 六、常见误区
误区一是 ECMP 能均分每条连接带宽，实际按流哈希，单大象流仍占单路径。误区二是改哈希能解决所有偏斜，根因可能是流特征单一。

## 七、与开源书/权威来源对应
RFC 2992 给出 ECMP 哈希与扰动分析；数据中心网络（如 Fat-tree）广泛用 ECMP；Kurose & Ross 提及负载均衡转发。

## 八、面试题
问：ECMP 为什么用五元组哈希而非轮询？答：轮询会导致同一 TCP 流报文走不同路径造成乱序与重传，哈希保证流内一致。

## 九、演进与趋势
一致性哈希与可重配置 ECMP（如 RPS/RFS）结合，减少链路变更时的流颠簸；SRv6 提供更细粒度流量工程。

## 十、小结
ECMP 通过哈希将流分布到等价下一跳实现负载分担与冗余，关键在于以流为单位保序、以扰动缓解偏斜。
