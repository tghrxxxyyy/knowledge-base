# 静态路由与动态路由取舍

> 对应 Kurose & Ross《Computer Networking》第4章 与 RFC 4271 背景。

## 一、背景与挑战
网络连通可手工配置静态路由，也可用动态路由协议自动学习。选择取决于规模、变更频率、故障恢复需求与运维复杂度，错误取舍会导致黑洞或收敛缓慢。

## 二、核心原理
静态路由由管理员显式指定下一跳，无协议开销、确定性强，但拓扑变化需人工干预，扩展性差。动态路由（IGP 如 OSPF/IS-IS、EGP 如 BGP）通过邻居通告自动计算路径并快速收敛，代价是协议复杂度与计算/带宽开销。

## 三、形式化与数学基础
管理距离决定优先级（数值越小越优先）：
$$ \text{preference}: \text{static} < \text{OSPF} < \text{RIP} < \text{eBGP (typical)} $$
路由度量用于同协议内选优，如 OSPF cost 与链路带宽相关：
$$ cost = \frac{100\,\text{Mbps}}{bandwidth} $$

## 四、代码实现
Linux 添加静态路由：
```bash
ip route add 10.20.0.0/16 via 192.168.1.1 dev eth0
ip route add default via 192.168.1.1
```
动态路由由守护进程（bird/quagga/frr）配置，例如 OSPF 接口启用。

## 五、与其他技术对比
静态路由适合边界默认、小网络与稳定拓扑；动态路由适合中大型、多路径、需自动故障切换的场景。二者常结合：动态学内部、静态指默认。

## 六、常见误区
误区一是认为动态一定优于静态，实际在简单稳定环境静态更简单可靠。误区二是默认路由随意指向，可能形成路由环路或黑洞。

## 七、与开源书/权威来源对应
Kurose & Ross 第4章对比静态/动态；RFC 2328 (OSPF) 与 RFC 4271 (BGP) 定义动态协议；CyC2018/CS-Notes 网络小结提及。

## 八、面试题
问：什么时候用静态路由？答：拓扑稳定、网络小、或对路径有严格可控需求（如默认路由、黑洞路由）时，避免动态协议开销。

## 九、演进与趋势
SDN 用集中控制替代部分动态协议，云网络用 overlay 路由降低对底层 IGP 的依赖；但 BGP 在跨域仍不可替代。

## 十、小结
静态路由确定低开销但难扩展，动态路由自动收敛但复杂。实际网络多以静态处理边界、动态处理内部，按规模与稳定性取舍。
