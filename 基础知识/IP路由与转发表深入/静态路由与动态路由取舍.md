# 静态路由与动态路由取舍

> 对应 Kurose & Ross《Computer Networking: A Top-Down Approach》第 5 章（控制平面）、RFC 4271（BGP-4）、RFC 2328（OSPFv2）、RFC 2453（RIPv2）与 RFC 1058（RIP）。

## 一、背景与挑战

让两个网络互相可达，有两条根本不同的路径：由管理员手工写死下一跳（静态路由），或由路由协议在邻居间交换信息自动计算（动态路由）。选择不是「谁更先进」的问题，而是对规模、变更频率、故障恢复时间、运维复杂度与可控性的综合权衡。选错的代价很直接：在应该用静态的边界上用动态协议，会引入不必要的复杂度和收敛风险；在应该用动态的大规模网络上用静态，会出现配置漂移、黑洞路由与人工恢复缓慢。核心挑战在于：如何在同一张路由表里协调这两种来源，使转发既确定又能自愈。

## 二、核心原理

静态路由由管理员显式指定目的前缀与下一跳（或出接口），其特征是零协议开销、行为完全确定、不受邻居扰动影响，但拓扑变化必须人工介入，扩展性差且容易出现遗留配置。它适合三类场景：末梢网络的默认路由、边界出口的默认指向、以及刻意构造的黑洞/丢弃路由与备份路由。

动态路由由协议进程自动学习。按作用域分两类：IGP（内部网关协议，如 OSPF、IS-IS、RIP）负责域内可达性，追求快速收敛与拓扑自适应；EGP（外部网关协议，事实标准为 BGP）负责域间可达性，追求策略表达与大规模稳定性而非最快收敛。IGP 通常是链路状态（OSPF/IS-IS，每台路由器掌握全网拓扑并各自跑最短路径）或距离矢量（RIP，邻居间传递距离与下一跳）两类；BGP 是路径矢量，传递的是到达某前缀的 AS 路径，用路径属性表达策略偏好。

两者协同的典型模式是：内部用 IGP 学习细粒度路由，边界用静态默认路由兜底，二者通过管理距离决定优先级；也可以配置浮动静态路由（floating static），即静态路由的管理距离被调高，仅在动态路由消失时才生效，充当备份路径。

## 三、形式化与数学基础

管理距离（administrative distance, AD）决定不同来源路由的优先级，数值越小越优先。典型取值关系为：

$$ \text{AD}(\text{connected}) < \text{AD}(\text{static}) < \text{AD}(\text{eBGP}) < \text{AD}(\text{OSPF}) < \text{AD}(\text{RIP}) $$

同协议内的多条候选路径由度量（metric）比较。OSPF 的接口代价与带宽成反比：

$$ cost = \frac{\text{reference bandwidth}}{\text{interface bandwidth}} $$

域内最短路径用 Dijkstra 算法求解：

$$ d(v) = \min_{u \in N(v)} \left( d(u) + w(u,v) \right) $$

RIP 用跳数作为度量，最大 15 跳，16 视为不可达，这直接限制其可扩展性。BGP 不用单一标量度量，而是按属性顺序决策：先比 local preference（越大越优），再比 AS_PATH 长度（越短越优），再比 origin，再比 MED（越小越优），最后比 eBGP 优于 iBGP、以及 router ID 破平。

收敛时间可粗略分解为：

$$ T_{converge} \approx T_{detect} + T_{flood} + T_{compute} + T_{install} $$

静态路由的 $T_{converge}$ 实际上由人工介入时间决定，是数量级差异的来源。

## 四、代码实现

Linux 添加静态路由与默认路由：

```bash
# 指向具体前缀，指定下一跳与出接口
ip route add 10.20.0.0/16 via 192.168.1.1 dev eth0

# 默认路由
ip route add default via 192.168.1.1

# 浮动静态路由：管理距离 200，高于动态路由，仅在动态路由消失时生效
ip route add 10.20.0.0/16 via 192.168.1.1 dev eth0 metric 200

# 黑洞路由：丢弃该前缀流量
ip route add 10.99.0.0/16 blackhole

# 查看与验证
ip route show
ip route get 10.20.0.5
```

FRR（FRRouting）中启用 OSPF 的最小配置（动态路由侧）：

```text
router ospf
  network 10.0.0.0/8 area 0.0.0.0
  passive-interface eth2
!
interface eth0
  ip ospf cost 10
  ip ospf hello-interval 10
  ip ospf dead-interval 40
```

注意 `passive-interface` 的作用：让该接口参与宣告但不建立邻居，避免在面向终端网段上发送协议报文。

## 五、与其他技术对比

| 维度 | 静态路由 | IGP（OSPF/IS-IS） | EGP（BGP） | SDN 集中控制 |
| --- | --- | --- | --- | --- |
| 配置方式 | 手工 | 协议自动 | 协议 + 策略 | 控制器下发 |
| 收敛速度 | 人工（很慢） | 秒级 | 秒到分钟级 | 取决于控制器与通道 |
| 协议开销 | 无 | 洪泛/邻居报文 | 会话与更新报文 | 控制通道开销 |
| 扩展性 | 差 | 中（域内） | 高（域间） | 取决于控制器规模 |
| 策略能力 | 无 | 弱（cost/区域） | 强（路径属性） | 强 |
| 故障自愈 | 无 | 有 | 有 | 有（依赖控制器可用性） |
| 典型用途 | 默认路由、黑洞、末梢 | 企业/园区骨干 | 跨域互联 | 云网络、数据中心 |

权衡的主线是「确定性与自适应性的对立」。静态路由确定性最强、故障自适应为零；动态路由自适应强、但引入了协议复杂度、收敛窗口与潜在环路；集中控制把策略能力推到最强，代价是对控制器可达性的依赖。

## 六、常见误区

1. 认为动态路由一定优于静态路由。在拓扑稳定的小网络或末梢链路上，静态更简单、更可预测、更少受协议缺陷影响。
2. 默认路由随意指向，形成黑洞或环路。默认路由必须与上游可达性一致，否则流量被吸入无返回路径。
3. 忽略管理距离的作用。同目的前缀的多来源路由靠 AD 决胜，若静态与动态 AD 配置不当，会出现「配了不生效」或「备份路由抢主」。
4. 忘记双向可达性。只配去程静态路由而没有回程，会产生单向通断的经典故障，且表现为「ping 不通但抓包有请求」。
5. 在需要策略的域间场景用 IGP 硬撑。IGP 不表达策略偏好，跨域路由策略必须靠 BGP 属性。
6. 忽视收敛期间的瞬时环路与黑洞。距离矢量协议在收敛窗口内可能出现计数到无穷，需要水平分割、毒性逆转等机制。

## 七、与开源书·权威来源对应

- Kurose & Ross《Computer Networking: A Top-Down Approach》第 5 章：控制平面、路由算法（链路状态与距离矢量）与自治系统概念。
- Tanenbaum & Wetherall《Computer Networks》：路由算法分类与收敛性讨论。
- RFC 2328：OSPFv2 的链路状态数据库、区域划分与 SPF 计算。
- RFC 4271：BGP-4 的会话状态机、路径属性与决策过程。
- RFC 2453 / RFC 1058：RIPv2 / RIP 的距离矢量机制与 15 跳限制。
- RFC 1195：IS-IS 集成化以支持 IP。
- `ip-route(8)` 与 FRR 用户手册：静态路由与动态协议的实际配置语义。

## 八、面试题

1. 什么时候应该用静态路由？
   要点：拓扑稳定、网络规模小、需要严格可控路径（默认路由、黑洞路由、末梢网络）或作为浮动备份；避免不必要的协议开销与收敛风险。

2. 管理距离与度量有什么区别？
   要点：管理距离用于比较不同来源（静态/OSPF/BGP）的信任度，只在来源之间决胜；度量用于同一协议内部比较路径优劣。

3. 为什么 BGP 不用单一度量而用属性序列？
   要点：域间路由的核心诉求是策略表达（商业关系、流量引导）而非最短路径；属性序列允许按 local preference、AS_PATH、MED 等分层次表达偏好。

4. 浮动静态路由的原理是什么？
   要点：给静态路由配置高于动态路由的管理距离，使其平时不参与转发，仅在动态学习到的路由消失时接管，实现无协议依赖的备份路径。

5. RIP 的 15 跳限制带来什么后果？
   要点：网络直径被硬性限制，超限前缀不可达；也延长了计数到无穷的收敛过程，这是距离矢量在大网中不适合的根本原因。

## 九、演进与趋势

趋势之一是解耦：控制平面与数据平面分离（SDN），把路由计算上收到控制器，网络设备只保留转发，用集中视角获得更好的全局优化与策略一致性；但在跨域互联场景，BGP 因其策略表达能力与既成生态仍不可替代。趋势之二是 Overlay 化：云网络用 VXLAN/Geneve 等隧道在物理 IGP 之上构建虚拟拓扑，降低对底层协议的依赖，把租户隔离与策略放在 overlay 层实现。趋势之三是可编程数据平面：P4/RMT 让转发行为可按业务定制，配合控制器实现更细粒度的路由与分流。整体上，静态路由的适用边界被压缩到「默认、黑洞、末梢」，而策略能力持续向集中控制与可编程方向集中。

## 十、小结

静态路由确定、低开销但难以扩展；动态路由自动收敛、适应变化但引入复杂度、收敛窗口与环路风险。实际网络的标准做法是分层协同：内部用 IGP 学习细粒度可达性，边界用静态默认路由兜底，跨域用 BGP 表达策略，用管理距离与度量统一裁决。理解管理距离与度量的分工，是避免「配了不生效」这类经典故障的关键。
