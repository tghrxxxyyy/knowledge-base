# 基于规则与基于代价

> 对应 Garcia-Molina《Database Systems: The Complete Book》第 16 章 Optimizer 架构，以及 CMU 15-445 Query Optimization。

## 一、背景与挑战
优化器如何把 SQL 变成计划？两条路线：RBO（基于规则，确定性重写）与 CBO（基于代价，枚举+估分）。现代系统多用 CBO，RBO 作预处理。

## 二、核心原理
RBO 应用等价变换规则（如谓词下推、列裁剪、常量折叠、视图展开）得到逻辑等价计划，按固定优先级执行，不估代价。CBO 在逻辑计划基础上枚举物理计划并用代价模型选优。

## 三、形式化 / 数学基础
RBO 规则即代数恒等式，如 $\sigma_{p_1 \land p_2}(R) \equiv \sigma_{p_1}(\sigma_{p_2}(R))$。CBO 目标 $\arg\min_{p \in Plans} cost(p)$。

## 四、代码实现
```python
# 谓词下推（RBO 示例）
def push_predicate(sel, join):
    return Join(Sel(sel.cond_left, join.left),
                Sel(sel.cond_right, join.right))
```

## 五、与其他技术对比
| 方式 | 确定性 | 自适应性 | 复杂度 |
|------|--------|----------|--------|
| RBO | 强 | 无 | 低 |
| CBO | 弱 | 强 | 高 |
| 混合 | 中 | 中 | 中 |

## 六、常见误区
1. RBO 总能给出好计划——无代价感，可能错过更优。
2. CBO 一定最优——受统计信息质量限制。
3. 二者互斥——实际 RBO 预处理 + CBO 选物理计划。

## 十、小结
