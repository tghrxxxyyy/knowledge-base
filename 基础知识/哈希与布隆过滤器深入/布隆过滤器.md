# 布隆过滤器

> 对应 Bloom, B. H.《Space/Time Trade-offs in Hash Coding with Allowable Errors》(Communications of the ACM, 1970)，以及 Broder & Mitzenmacher 关于网络应用的综述。

## 一、背景与挑战

在缓存、爬虫、数据库、网络转发里，经常要回答：「这个元素是否**可能**在集合里？」若集合有上亿元素，用 HashSet 精确存储会占用数 GB 甚至上百 GB 内存——很多场景只做一次前置拦截（例如判断 URL 是否抓过、判断 key 是否可能在后端），并不需要精确答案，也不需要取出元素本身。此时用十亿级别的内存换「可能在/必不在」是不划算的。

布隆过滤器（Bloom Filter）用一个 $m$ 位的比特数组与 $k$ 个独立哈希函数，把空间压到每个元素约 1~2 字节，查询仍是 $O(k)$。它的不对称性是价值核心：**没有假阴性**（报告「不在」就一定不在），**允许假阳性**（报告「在」可能是误判）。用这一个不对称，可以把大量后端查询、磁盘 IO、数据库主键回表直接挡在门外：先查布隆，必不在就立刻返回；可能在才走昂贵路径。

朴素做法为什么不行？(1) 精确哈希集合空间是元素的几十倍（含装箱、指针、负载因子），上亿元素就上 GB；(2) 只存一个「全体元素的哈希表的哈希」仍会碰撞误判且无法量化；(3) 把整表塞进磁盘又带来 IO 瓶颈，违背了「前置拦截省 IO」的初衷。布隆过滤器把「空间、误判率、哈希个数」三者用明确公式绑定，可按业务容忍度调参，这是它经久不衰的原因。

在工程与面试中，布隆过滤器是「缓存穿透」的标准答案，也是 Redis（`redisbloom` / RedisBloom 模块）、HBase、Cassandra、Chrome/Safe Browsing、比特币 SPV、CDN 节点判重的底层组件。面试官通常希望你能推导误判率公式、给定 $n$ 与目标误判率 $p$ 算出 $m$ 与 $k$，并说清「可否删除」。

## 二、核心原理

**结构**。一个长度为 $m$ 的比特数组 $B[0..m-1]$，初始全 0。准备 $k$ 个哈希函数 $h_1, \ldots, h_k$，每个把元素映到 $[0, m)$。

**插入** $add(x)$：对 $i = 1..k$，置
$$
B[h_i(x) \bmod m] \leftarrow 1.
$$

**查询** $contains(x)$：检查 $B[h_1(x)] \cdots B[h_k(x)]$ 是否**全为 1**。任一位为 0，则 $x$ 必不在（假阴性不可能）；全为 1，则**可能**在（假阳性可能）。

**为什么没有假阴性**。若 $x$ 曾被插入，则它的 $k$ 位在插入时已全部置 1；此后只会置 1、不会清 0（标准布隆不支持删除），故查询必然全 1。假阳性来自「其他元素恰好把这 $k$ 位都置成了 1」。

**双哈希技巧**。独立 $k$ 个哈希成本高。实践中用两个强哈希 $h_1, h_2$ 构造
$$
g_i(x) = h_1(x) + i \cdot h_2(x) \pmod m, \quad i = 0..k-1,
$$
在经验上足够独立，只需两次哈希计算。要求 $h_2(x) \neq 0$（或加常数），否则所有 $g_i$ 相同，等价只有一个哈希。

**不变量**。(1) 比特只置 1 不清 0（除非是计数布隆）；(2) 查询的 $k$ 位必须全部计算，不能提前返回；(3) $m$、$k$、期望元素数 $n$ 必须在创建时确定，事后扩展会改变误判率语义。

**边界条件**。空过滤器上查询必为假；$n$ 远超设计容量时误判率急剧上升，应触发重建或分层；$k$ 过大查询变慢且 $m$ 过小会过度置位。

## 三、形式化与数学基础

**误判率推导**。设已插入 $n$ 个元素，哈希均匀独立。考虑某一位仍为 0 的概率。一次插入把某特定位保持 0 的概率是 $1 - \frac{1}{m}$；$k$ 次哈希都未碰它则为 $\left(1 - \frac{1}{m}\right)^k$。插入 $n$ 个元素后该位仍为 0 的概率：
$$
P_0 = \left(1 - \frac{1}{m}\right)^{kn} \approx e^{-kn/m}.
$$
查询一个**不存在**的元素时，它的 $k$ 个位置全为 1 才误判。各位置近似独立（理想独立哈希），故
$$
p \approx \left(1 - P_0\right)^k \approx \left(1 - e^{-kn/m}\right)^k.
$$

**最优 $k$ 的推导**。固定 $m, n$，把 $p$ 看作 $k$ 的函数。令 $\lambda = \frac{kn}{m}$，则
$$
p(k) = \left(1 - e^{-kn/m}\right)^k.
$$
取对数求导：
$$
\ln p = k \ln(1 - e^{-kn/m}).
$$
对 $k$ 求导并令为 0，经典结果是最优
$$
k^* = \frac{m}{n} \ln 2 \approx 0.693 \cdot \frac{m}{n}.
$$
此时
$$
p_{\min} = \left(\frac{1}{2}\right)^{k^*} = e^{-k^* \ln 2} = 2^{-k^*}.
$$
或写成
$$
p_{\min} = \left(1 - 2^{-k^*}\right)^{k^*} \approx (0.6185)^{m/n}.
$$
更常用的是反解 $m$：给定 $n$ 与目标 $p$，
$$
m = -\frac{n \ln p}{(\ln 2)^2} \approx 1.44\, n \ln \frac{1}{p}.
$$
例如 $n = 10^7$、$p = 1\%$，则 $m \approx 1.44 \times 10^7 \times \ln 100 \approx 1.33 \times 10^8$ 位 $\approx 16$ MB，$k^* \approx 0.693 \times 13.3 \approx 9$。每个元素约 1.44 字节，远低于 HashSet。

**$k$ 的敏感性**。$k$ 偏离 $k^*$ 时误判率上升。$k$ 太小则置位少、假阳性高；$k$ 太大则置位过密、几乎所有位变 1，同样升高。对固定的 $m/n$，$p(k)$ 是单峰的，峰点在 $k^*$。

**计数期望**。查询不存在元素时期望命中 1 的位数是 $k \cdot (1 - e^{-kn/m})$；全 1 概率即上式 $p$。布隆过滤器不可删除的原因也可从这里看出：清掉某元素的 $k$ 位会误伤同时共享这些位的其它元素。

## 四、代码实现

不依赖第三方库的布隆过滤器，用 `hashlib` 与双哈希派生 $k$ 个索引，带误判率估算与自动参数选择。

```python
"""布隆过滤器：双哈希派生、误判率估算、按目标误判率定参。"""
from __future__ import annotations

import hashlib
import math
from typing import Iterable


class BloomFilter:
    def __init__(self, m: int, k: int):
        if m <= 0 or k <= 0:
            raise ValueError("m and k must be positive")
        self.m = m
        self.k = k
        self.bits = bytearray((m + 7) // 8)
        self.count = 0

    # ---------- 工具 ----------
    def _hashes(self, item) -> tuple[int, int]:
        if not isinstance(item, (bytes, bytearray)):
            item = str(item).encode("utf-8")
        digest = hashlib.md5(item).digest()
        h1 = int.from_bytes(digest[:8], "big")
        h2 = int.from_bytes(digest[8:16], "big") | 1  # 强制奇数，避免步长为 0
        return h1, h2

    def _indexes(self, item) -> Iterable[int]:
        h1, h2 = self._hashes(item)
        for i in range(self.k):
            yield (h1 + i * h2) % self.m

    def _set(self, idx: int) -> None:
        self.bits[idx >> 3] |= 1 << (idx & 7)

    def _get(self, idx: int) -> int:
        return (self.bits[idx >> 3] >> (idx & 7)) & 1

    # ---------- 对外 ----------
    def add(self, item) -> None:
        for idx in self._indexes(item):
            self._set(idx)
        self.count += 1

    def might_contain(self, item) -> bool:
        return all(self._get(idx) for idx in self._indexes(item))

    # 误判率上界估计
    def estimated_fpr(self) -> float:
        if self.m == 0:
            return 1.0
        return (1 - math.exp(-self.k * self.count / self.m)) ** self.k


def optimal_params(n: int, p: float) -> tuple[int, int]:
    """给定期望元素数 n 与目标假阳性率 p，返回 (m, k)。"""
    if not (0 < p < 1):
        raise ValueError("p must be in (0,1)")
    m = math.ceil(-n * math.log(p) / (math.log(2) ** 2))
    k = max(1, round(m / n * math.log(2)))
    return m, k


if __name__ == "__main__":
    n, target_p = 100_000, 0.01
    m, k = optimal_params(n, target_p)
    print(f"n={n} p={target_p} -> m={m} bits (~{m/8/1024:.1f} KB), k={k}")

    bf = BloomFilter(m, k)
    for i in range(n):
        bf.add(f"user:{i}")

    # 不在集合中的元素应大多返回 False，实测误判率接近目标
    fp = sum(1 for i in range(n, n + 100_000) if bf.might_contain(f"user:{i}"))
    print(f"empirical fpr over 1e5 negatives: {fp/100_000:.4f}")
    print(f"estimated fpr: {bf.estimated_fpr():.4f}")
    assert bf.might_contain("user:0")
    assert not bf.might_contain("user:not_exist") or True  # 允许假阳性
    print("ok")
```

实测假阳性率通常落在 0.8%~1.2%，与理论值吻合。`optimal_params` 可直接用于容量规划。

## 五、与其他技术对比

| 维度 | HashSet | Bloom Filter | Cuckoo Filter | 布隆 + 后端回表 |
|------|---------|--------------|---------------|-----------------|
| 空间 | 大（装箱、指针） | 极小（1~2 B/元素） | 小（约 2~4 B） | 极小 |
| 假阳性 | 无 | 有（可调 $p$） | 有（略优） | 有 |
| 假阴性 | 无 | **无** | 无 | 无 |
| 删除 | 支持 | 不支持 | 支持 | 不支持 |
| 查询代价 | $O(1)$ 期望 | $O(k)$ 次哈希 | $O(1)$ | $O(k)$ + 回表 |
| 典型场景 | 精确去重 | 缓存穿透、海量判存在 | 需删除的近似集合 | 省 IO 的前置过滤 |

与 Cuckoo Filter 相比：布隆更省空间、实现简单；Cuckoo 支持删除且查询一次内存访问，常数更优。与精确集合相比：布隆用「可调的假阳性」换数量级的空间节省；只要业务能容忍误判（误判导致一次多余回表，而不是错误接受），就非常划算。

## 六、常见误区

**误以为可删除**。清掉某元素的 $k$ 位会把其它元素共享的位也清 0，造成假阴性——这是布隆过滤器的设计红线。需要删除请用计数布隆或 Cuckoo Filter。

**$m$、$k$ 事后乱调**。先按小 $n$ 建、后来塞进十倍元素，误判率按指数恶化。应在创建时按峰值 $n$ 与目标 $p$ 用 $m \approx 1.44 n \ln(1/p)$ 预留，或用可扩展布隆（Scalable Bloom）自动加层。

**哈希相关导致聚集**。用 `hash(x) % m` 与 `hash(x) + 1` 当两个哈希，几乎完全相关，等价于 $k=1$，误判率远高于理论。必须用独立哈希或双哈希构造，并强制 $h_2 \neq 0$。

**把「假阳性」当成「大概率存在」**。当 $n$ 接近设计容量、$p$ 又调得高时，大量查询都会假阳性，布隆失去拦截价值，后端被打满。监控假阳性率并在超阈值时重建。

**$k$ 与 $m$ 不匹配**。$k$ 过大（比如 50）会把表迅速填满，反而提高假阳性；$k$ 过小又置位不足。用 $k^* = (m/n)\ln 2$，通常落在 4~12。

## 八、面试题

**1. 如何用布隆过滤器防缓存穿透？**
参考答案：穿透指查询不存在的 key 打穿缓存打到 DB。把「肯定不存在」用布隆过滤器挡在前面：查布隆，报告不在直接返回空；可能在才查缓存/DB。误判只会导致一次多余 DB 查询，不会脏读。注意布隆需随数据插入维护，且不可删除（或用计数布隆）。

**2. 已知要存 1 亿个 URL、假阳性率 < 0.1%，估算空间与 $k$。**
参考答案：$m = -n\ln p / (\ln 2)^2 = 10^8 \times \ln 1000 / 0.480 \approx 1.44\times 10^9$ 位 $\approx 172$ MB，$k \approx 0.693 \times 14.4 \approx 10$。远小于 HashSet 的数 GB。

**3. 为什么布隆过滤器不能删除？标准变体怎么支持删除？**
参考答案：删除清位会误伤共享位的元素，引入假阴性。计数布隆把每一位换成计数器，删除减 1；Cuckoo Filter 用指纹桶直接支持删除。二者都会增加空间。

**4. $k$ 取多少合适？过大过小会怎样？**
参考答案：$k^* = (m/n)\ln 2$ 最小化假阳性。过小置位少、假阳性高；过大置位过密、几乎全 1，同样升高。固定 $m/n$ 时 $p(k)$ 单峰，峰在 $k^*$。

## 九、演进与趋势

**可扩展布隆（Scalable Bloom Filter）**。每层按几何级数分配容量与误判率（如 $p_i = p / 2^i$），填满自动加层，支持未知规模写入。

**计数布隆与删除**。见「计数布隆过滤器」篇：用 4 位计数器换删除能力，空间约 4 倍。

**Cuckoo Filter / Ribbon Filter**。支持删除、查询一次内存访问；Ribbon（RocksDB 使用）在低假阳性率下空间优于布隆。

**分区布隆与热点优化**。把大布隆切成多段、按 key 前缀路由，提升缓存局部性；对热点 key 预热。

**硬件与持久化**。布隆位图可放 DRAM 或持久内存；SSD 上可做「页级布隆」减少读放大。RedisBloom、RocksDB、LevelDB、Cassandra 都内置相关组件。

## 十、小结

布隆过滤器以 $m$ 位数组与 $k$ 个哈希实现亚线性空间的存在性查询，核心不对称性是「无假阴性、允许假阳性」。误判率 $p \approx (1-e^{-kn/m})^k$，最优 $k = (m/n)\ln 2$，给定 $n, p$ 时 $m \approx 1.44 n \ln(1/p)$。它用可调的误判率换来了数量级的空间节省，是缓存穿透、海量去重、网络去重的标准前置结构；代价是不可删除、需按峰值容量规划。理解公式与调参，就能在工程中把它当「便宜的大概率过滤器」而不是「精确集合」来用。
