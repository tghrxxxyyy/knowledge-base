# 三阶段提交

> 对应 Skeen《Nonblocking Commit Protocols》(1981) 提出的 3PC。

## 一、背景与挑战
为缓解 2PC 的阻塞，3PC 引入“预提交(canCommit/preCommit/doCommit)”三阶段，并依靠超时自动推进，试图在“同步网络+有界延迟+无网络分区”假设下实现非阻塞。

## 二、核心原理
三阶段：
1. CanCommit：协调者询问，参与者若可提交回 yes(不锁资源)。
2. PreCommit：协调者收齐 yes 后发 preCommit；参与者锁定资源、写日志、回 ack。此时若协调者崩溃，参与者超时后默认提交(因已确认全员 yes)。
3. DoCommit：协调者收齐 ack 后发 doCommit；参与者提交释放锁。
关键差异：PreCommit 后参与者具备“超时即提交”的依据(因为 canCommit 已确认全员可提交)，从而可在协调者失联时自行推进，减少阻塞。

## 三、形式化 / 数学基础
非阻塞条件：要求网络同步(消息有界延迟)、节点不出现网络分区(仅崩溃)。在此假设下，PreCommit 后的超时提交是安全的——因所有参与者都已同意，且无分区使部分已提交部分未知。
局限：真实异步网络不满足该假设，故 3PC 在实践中仍可能不一致，工业界很少直接用。

## 四、代码实现
```python
# 参与者：preCommit 后若超时且收到过全部 yes，则自行提交
def on_timeout_after_precommit(agreed_all_yes):
    if agreed_all_yes:
        commit_locally()   # 安全推进
```

## 五、与其他技术对比
- 相比 2PC：多一个 canCommit 阶段，且 PreCommit 后可超时提交，减少阻塞。
- 代价：多一轮往返，且依赖同步网络假设，实用性受限。

## 六、常见误区
- 误区：3PC 在真实分布式环境完全非阻塞。同步/无分区假设不成立时仍可能不一致。
- 误区：3PC 取代 2PC。工业多用 2PC + 共识/补偿，而非裸 3PC。

## 九、演进与趋势
共识协议(Raft/Paxos)用于原子提交成为更可靠的“非阻塞”路径；3PC 主要停留在理论与教学。

## 十、小结
3PC 通过预提交与超时推进缓解了 2PC 阻塞，但其严格的同步假设在真实网络中难以满足，故更多作为理论参考。
