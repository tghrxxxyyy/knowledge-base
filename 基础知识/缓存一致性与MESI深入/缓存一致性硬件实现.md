# 缓存一致性硬件实现

> 对应 Hennessy & Patterson 附录 C；CSAPP 中文笔记 https://github.com/Hansimov/csapp 。

## 一、背景与挑战

协议需硬件在监听/目录间维护状态、处理请求与应答，且尽量不阻塞处理器。

## 二、核心原理

监听实现：所有缓存控制器监听共享总线/环上事务，收到 BusRd/BusInv 更新本行状态并应答。目录实现：内存侧目录记录每行的共享者位图，仅向相关核发消息。

## 三、形式化 / 数学基础

监听带宽随核数 $P$ 增长约为 $O(P)$ 广播；目录为点对点 $O(1)$ 目标集：

$$Traffic_{snoop} \sim P \times ReqRate,\quad Traffic_{dir} \sim |Sharers| \times ReqRate$$

目录项开销约 $O(P \times Lines)$ 位。

## 四、代码实现

```c
// 目录控制器伪代码
def handle_read(addr, req_core):
    sharers = dir[addr]
    send_data_to(req_core, addr)
    dir[addr] = sharers | {req_core}   # 加入共享者
```

## 五、与其他技术对比

- 监听：简单、低延迟，扩展性差。
- 目录：可扩展，但目录内存与目录缺失代价。

## 六、常见误区

- 误以为一致性全由软件维护：主流由硬件协议。
- 忽视目录缺失需访内存的额外延迟。

## 八、面试题

- 监听与目录扩展差异？答：监听广播 O(P)，目录点对点 O(1) 共享者。
- 目录位图开销？答：每行约 P 位记录共享核。

## 九、演进与趋势

大核数芯片用分布式目录 + 片内互连（网格/环）承载一致性流量。

## 十、小结

硬件协议以监听(小系统)或目录(大系统)落地一致性，是性能与可扩展性的核心权衡。
