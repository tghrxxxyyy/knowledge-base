# 伪共享与缓存行对齐

> 对应 CSAPP 中文笔记 https://github.com/Hansimov/csapp 第6章；Intel 优化手册（公开定性）。

## 一、背景与挑战

缓存以行（通常 64 字节）为一致性单位。两核各改同一行中不同变量，虽逻辑无关，却因行在 M/E 间颠簸而频繁无效，性能骤降——伪共享。

## 二、核心原理

解决：让频繁独立写的变量落在不同缓存行，即按 64 字节对齐并填充。Linux 提供 `____cacheline_aligned` 宏；C11 有 `_Alignas(64)`。

## 三、形式化 / 数学基础

设两变量同处一行，核 A/B 交替写，每次写触发行在 M 态于两核间迁移：

$$Cost \approx N \times (Invalidate + CoherenceTraffic)$$

隔离到不同行后 $Cost \to 0$（无共享行）。

## 四、代码实现

```c
#include <stdalign.h>
struct counter {
    alignas(64) unsigned long a;   // 独占一行
    alignas(64) unsigned long b;   // 独占另一行，避免伪共享
};
```

## 五、与其他技术对比

- 伪共享 vs 真共享：前者无关变量同行，后者真依赖。
- 填充增大内存占用，需权衡。

## 六、常见误区

- 误以为加锁解决伪共享：锁不消除行迁移，只是串行化。
- 填充过度浪费缓存容量。

## 八、面试题

- 什么是伪共享？答：无关变量同缓存行被多核改，致行一致性颠簸。
- 如何定位？答：perf c2c / 硬件计数器（如 LLC-miss 异常）。

## 九、演进与趋势

语言与运行时提供原生对齐标注；分析工具（perf c2c）普及。

## 十、小结

伪共享是隐性的多核性能杀手，靠行对齐与填充解决，代价是空间。
