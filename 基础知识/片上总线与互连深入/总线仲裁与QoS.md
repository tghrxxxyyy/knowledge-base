# 总线仲裁与 QoS

> 对应 ARM AMBA 规范 QoS 扩展与 Hennessy & Patterson 互连章。

## 一、背景与挑战
多主设备竞争总线时，若公平轮询，实时/高优流量可能被低优流量饿死或抖动。仲裁器与 QoS 机制决定带宽分配与延迟上限。

## 二、核心原理
常见仲裁：固定优先级、轮询（RR）、加权轮询（WRR）、信用制（credit-based）。QoS 信号（如 AXI QoS 4 bit）让高优先级事务优先获得总线，同时用带宽限制防止霸占总线。

## 三、形式化与数学基础
加权轮询下主 $i$ 获得带宽比例：
$$BW_i = \frac{w_i}{\sum_j w_j} \times TotalBW$$
信用制中每主有令牌 $c_i$，事务消耗令牌，重填速率控制长期带宽：
$$\frac{dc_i}{dt} = refill_i - use_i$$

## 四、代码实现
```c
// 加权轮询仲裁
int w[4] = {4,2,1,1};
int credit[4] = {4,2,1,1};
int arbiter() {
    for (int i=0;i<4;i++)
        if (credit[i] > 0) { credit[i]--; return i; } // 选有信用者
    for (int i=0;i<4;i++) credit[i] = w[i];           // 重置
    return 0;
}
```

## 五、与其他技术对比
固定优先级简单但可能饿死低优；RR 公平但无带宽保证；WRR/信用制兼顾公平与保障，适合混合实时负载。

## 六、常见误区
误以为公平即最优：实时流量需延迟上限而非平均公平。误以为 QoS 自动生效：需端点正确标注。

## 七、与开源书/权威来源对应
ARM AMBA QoS 扩展；量化方法互连仲裁；Linux 设备树 QoS。

## 八、面试题
问：信用制如何防饥饿又限带宽？答：令牌耗尽即停，重填速率定长期配额。

## 九、演进与趋势
硬件 QoS 监控 + 软件调度协同，支持 DVFS 与带宽隔离。

## 十、小结
仲裁与 QoS 把"谁先用总线"从无序竞争变为可预测的资源分配。
