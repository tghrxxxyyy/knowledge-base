# 环形与网格拓扑

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》互连网络与拓扑章节，以及 Dally & Towles《Principles and Practices of Interconnection Networks》。

## 一、背景与挑战

多核与多插槽系统的互连拓扑直接决定三件事：访问延迟、聚合带宽与可扩展性上界。环形（ring）把节点串成一个闭环，链路数少、布线规则、单跳延迟低，但共享链路的聚合带宽随节点数受限；网格（mesh）把节点排成二维阵列，链路数随节点数线性增长，可扩展到数百节点，代价是平均跳数随 $\sqrt{N}$ 增长。

选择拓扑的本质是在三个维度之间做权衡：延迟（由直径与平均跳数决定）、带宽（由二分带宽与链路数决定）、以及物理实现成本（面积、布线拥塞、功耗、时钟与电源分布）。此外拓扑还与一致性协议强耦合——ring 天然提供全局有序的环停止（ring stop）转发，便于实现嗅探式一致性；mesh 则通常配合目录与 home 节点分散布局。

## 二、核心原理

环形拓扑：每个节点有两个邻居（左、右），事务沿最短方向绕行。节点以「环停止」（ring stop）方式接入：请求在环上单向流动，目的节点在环上截取并注入响应。经典优化是双环（正反两个方向各一环）以缩短平均跳数，或分段环（segmented ring）让不同事务在不同段并行占位。ring 的固有弱点是聚合带宽不随节点数增长——所有流量共享同样的链路资源，节点越多越容易饱和。

网格拓扑：节点按 $(x,y)$ 排列，每个路由器连接四个邻居与本地节点。Dally 在其经典工作中指出，在均匀随机流量下 mesh 的每节点可持续带宽趋于常数（不随 $N$ 衰减），这正是 mesh 可扩展性的来源。为提升效率，实务中常引入「集中」（concentration）：一个路由器服务多个本地节点（如 4 个核共享一个路由器），减少路由器数量与面积。

环形与网格在真实产品中都有应用：环形常见于中小规模多核与一致性互连；网格常见于大规模多核、GPU 与多插槽系统的核心互连。二者也都可通过加入垂直链路（3D 堆叠）或跨环捷径（如带旁路的分段环）降低平均跳数。

## 三、形式化与数学基础

环形（$N$ 节点，双向最短路径）：

$$D_{ring} = \left\lfloor \frac{N}{2} \right\rfloor, \qquad \bar{H}_{ring} \approx \frac{N}{4}$$

$k \times k$ 网格（$N = k^2$）：

$$D_{mesh} = 2(\sqrt{N} - 1), \qquad \bar{H}_{mesh} \approx \frac{2\sqrt{N}}{3}$$

环形（含环回）与 torus 的区别在于是否把首尾相接：torus 的直径为 $k/2$（每维），平均跳数约为 $k/2$ 的常数倍，但需要更长的绕行链路。

二分带宽是区分二者可扩展性的关键。切分 $N$ 节点环需要切断 2 条链路：

$$BW_{bisect}^{ring} = 2 B_{link}$$

而 $k \times k$ 网格的切面为 $k$ 条链路：

$$BW_{bisect}^{mesh} = k B_{link} = \sqrt{N} B_{link}$$

因此环的聚合带宽是 $O(1)$，网格是 $O(\sqrt{N})$。若考虑一致性流量（每写一次需要失效所有共享者），ring 上的广播式失效会迅速吃满链路，这也是大核数系统放弃 ring 而转向 mesh + 目录的原因。

## 四、代码实现

```c
/* 环形：选择最短绕行方向，并计算跳数 */
int ring_dir(int cur, int dst, int N, int *hops) {
    int cw  = (dst - cur + N) % N;     /* 顺时针跳数 */
    int ccw = (cur - dst + N) % N;     /* 逆时针跳数 */
    if (cw <= ccw) { *hops = cw;  return +1; }
    else           { *hops = ccw; return -1; }
}

/* 网格：XY 维序路由 + 曼哈顿跳数（无拥塞时的最短路径长度） */
typedef struct { int x, y; } pt_t;
int mesh_hops(pt_t a, pt_t b) {
    int dx = a.x > b.x ? a.x - b.x : b.x - a.x;
    int dy = a.y > b.y ? a.y - b.y : b.y - a.y;
    return dx + dy;                     /* 曼哈顿距离即最小跳数 */
}

void mesh_next(pt_t cur, pt_t dst, pt_t *nxt) {
    *nxt = cur;
    if (cur.x != dst.x) nxt->x += (cur.x < dst.x) ? +1 : -1;  /* 先走 X */
    else if (cur.y != dst.y) nxt->y += (cur.y < dst.y) ? +1 : -1;
}

/* 环形仲裁中的「环停止」占位：同一 slot 只能被一个请求占用，
   因此环本身充当分布式仲裁器，天然提供事务的全序。 */
int ring_slot_acquire(int node, int slot) {
    return ring_owner[slot] == -1 && (ring_owner[slot] = node) >= 0;
}
```

环形的「环停止 + 单向流动」有一个重要副产品：同一 slot 上的事务获得全局一致的先后顺序，这天然满足缓存一致性协议对写串行化的要求，因此早期多核用 ring 实现嗅探式一致性几乎没有额外排序逻辑。

## 五、与其他技术对比

| 维度 | 环形 Ring | 2D 网格 Mesh | Torus | 全交叉开关 |
| --- | --- | --- | --- | --- |
| 直径 | $\lfloor N/2 \rfloor$ | $2(\sqrt{N}-1)$ | $\sim k/2$（每维） | $1$ |
| 二分带宽 | $O(1)$ | $O(\sqrt{N})$ | $O(\sqrt{N})$ | $O(N)$ |
| 链路数/面积 | $O(N)$，布线规则 | $O(N)$ | $O(N)$，需长绕线 | $O(N^2)$ |
| 可扩展核数 | 约 ≤ 20 | 数百 | 数百（需绕线预算） | ≤ 约 16–32 |
| 一致性适配 | 嗅探（全序天然） | 目录 + home 分散 | 目录 | 嗅探/目录均可 |
| 主要瓶颈 | 共享链路饱和 | 跳数与拥塞 | 长链路延迟与布线 | 面积、功耗、线延迟 |

## 六、常见误区

1. 认为 ring 带宽无限：所有节点共享同样的链路资源，节点增加只会加剧争用而不会提升聚合带宽。
2. 认为 mesh 总是更快：小规模系统里 ring 的跳数更少、布线更省，实际延迟往往更低。
3. 忽略集中（concentration）的影响：多个核共享一个路由器虽省面积，但会在路由器入口形成新的争用点。
4. 把跳数等同于延迟：拥塞、虚通道分配与交叉开关排队往往才是主导项，尤其在接近饱和时。
5. 认为拓扑与协议可独立设计：ring 的全序特性、mesh 的分散 home 布局都深度影响一致性协议的实现方式。
6. 忽略物理约束：mesh 的角节点到中心的内存控制器距离不均，会造成延迟非均匀（NUCA 问题）。

## 八、面试题

1. 问：ring 与 mesh 何时各自更优？答：小规模（约十余节点以内）ring 的跳数少、布线省、延迟低；规模增大后 mesh 的二分带宽随 $\sqrt{N}$ 增长，可扩展性胜出。
2. 问：为什么 ring 上容易实现一致性？答：单向环上同一 slot 的占用天然提供全局定序，写请求获得全序即可满足写串行化，无需额外排序硬件。
3. 问：mesh 的均匀随机流量下每节点带宽为何趋于常数？答：切面链路数随 $\sqrt{N}$ 增长，而节点数随 $N$ 增长，二者相除后每节点可用带宽趋于定值。
4. 问：集中（concentration）的取舍是什么？答：省路由器数量与面积，但多核共享同一路由器端口会引入入口争用与更高的排队延迟。
5. 问：torus 相比 mesh 的代价？答：直径更小、平均跳数更低，但需要首尾相接的长绕线以及可能更长的链路延迟，布线预算紧张时不划算。

## 九、演进与趋势

- 混合拓扑：局部 ring（簇内）+ 全局 mesh（簇间），兼顾低延迟与可扩展性。
- 3D 堆叠与硅中介层：垂直链路把平均跳数从 $O(\sqrt{N})$ 降到 $O(\sqrt[3]{N})$ 量级。
- 动态/可重构拓扑：按流量模式动态改变绕行或旁路路径，工程上多见于分段环与旁路设计。
- 与内存层次协同：把 L2 切片与内存控制器沿拓扑分散（NUCA/S-NUCA），让热数据靠近使用它的核。
- 拓扑感知的软件调度：操作系统与运行时的线程/数据放置策略主动利用拓扑局部性。

## 十、小结

拓扑是互连的骨架：ring 用最少的链路换来最低的单跳延迟与天然全序，适合中小规模；mesh 用线性增长的链路换来随 $\sqrt{N}$ 增长的二分带宽，适合大规模。选择的判据不是「哪个更快」，而是「在给定规模、流量模式与物理预算下，延迟、带宽、面积三者如何取舍」；并且这个选择必须与一致性协议的实现方式联合考量。
