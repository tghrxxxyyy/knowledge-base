# 缓存一致性与互连协议

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》缓存一致性与互连章节（snooping 与 directory），目录协议思想溯源自 Censier & Feautrier 1978 与 Tang 1976。

## 一、背景与挑战

多核共享物理内存时，同一地址可能同时存在于多个私有缓存中。硬件必须保证三项基本性质：单写多读（SWMR）不变式、数据值不变式（写传播）、以及写操作的全局串行化。这一层由缓存一致性协议负责，而协议消息必须「搭车」在互连上传输，因此一致性与互连本质上是协同设计（co-design）。

规模是第一驱动力。嗅探（snooping）要求每个请求广播到所有缓存，消息量随核数 $N$ 线性增长；当 $N$ 达到数十甚至上百核，广播占用的链路带宽、探针端口（snoop port）的面积与功耗都不可接受。目录（directory）协议把「谁持有副本」这一信息集中或分布式记录下来，将广播转为点对点消息，是当前大规模多核与多插槽系统的默认选择。

互连还带来额外的非理想因素：消息乱序、链路往返延迟（构成目录间接访问的三跳成本）、跨 die/跨 socket 的带宽墙，以及探针过滤器（snoop filter）容量有限导致的伪共享抖动。协议必须在这些条件下保持可证明的正确性：无死锁、无活锁、状态不变量不被破坏。

## 二、核心原理

嗅探协议：所有缓存控制器监听共享总线（或环上的有序通道）。写请求触发广播 Invalidate，读请求可能触发数据转发（cache-to-cache transfer）或写回。经典三类组织：

- 写一次（write-once）：首次写穿透到内存再取得独占，减少后续失效确认。
- MSI/MESI/MOESI：写失效（write-invalidate），以状态位编码减少总线流量，是主流方案。
- Dragon：写更新（write-update），适合生产者—消费者连续写的场景，但持续占用总线带宽。

目录协议：每个缓存行有一个「宿主节点」（home node，可与内存控制器合一），目录项记录该行状态与持有者。常见组织：

1. 全映射位图（full-map）：$N$ 位 sharers 加脏位，精确但存储 $O(N)$。
2. 粗粒度向量：每 $k$ 个节点共享一位，会引发超集失效（superset invalidation）。
3. 链式目录（chained）：目录项只存一个指针，持有者按序串成链，失效沿链传播。
4. 有限指针（limited pointers）：只存若干指针，溢出时退化为广播，兼顾平均成本与最坏情形。

目录消息分三类：Read Miss、Write Miss（获取独占）、Invalidate/Ack。关键优化是请求转发（forwarding）：home 收到读缺失时，若某缓存处于 M 态，则令该缓存直接把数据发给请求者，把「写回 home 再发送」的三跳压缩为两跳，同时 home 进入 pending 状态等待写回。

## 三、形式化与数学基础

设核数为 $N$，嗅探协议每次写广播的流量：

$$Traffic_{snoop} = N \cdot S_{msg} \quad \text{（每行每次写）}$$

目录协议的定向开销：

$$Traffic_{dir} = |Sharers| \cdot S_{msg} + N \cdot S_{ptr}$$

目录位图存储为每行 $N$ 位（脏位另计）。设行大小为 $B$ 字节，则目录相对缓存的数据开销：

$$\frac{M_{dir}}{M_{cache}} = \frac{N/8}{B}$$

例如 $N=64$、$B=64\,\text{B}$ 时比例约为 $12.5\%$，这正是全映射目录在片上难以承受的直接原因。

链式目录的失效延迟为 $O(L)$（$L$ 为链长）。设某行被任一节点持有的概率为 $p$，则链长期望 $E[L] \approx N \cdot p$。有限 $k$ 指针方案的溢出概率可用二项分布近似：

$$P_{ovf} = \sum_{i>k} \binom{N}{i} p^{i}(1-p)^{N-i}$$

一致性要求可形式化表述为：对任意地址 $a$，任意时刻不存在两个处于可写状态（M/E）的副本；且对任意两个持有副本的核，它们观察到的该地址写序列相同。前者即 SWMR，后者即写串行化。

## 四、代码实现

```c
/* 目录 home 节点：读/写缺失处理（含 pending 缓冲，简化模型） */
enum { DIR_I, DIR_S, DIR_M, DIR_PENDING } dstate[MAX_LINE];
int      owner[MAX_LINE];
uint64_t sharers[MAX_LINE];                /* 位图，最多 64 核 */

void dir_read_miss(int line, int req) {
    if (dstate[line] == DIR_M) {           /* 存在脏副本，用转发取数 */
        send_fwd(owner[line], req, FWD_DATA);  /* cache-to-cache */
        pending[line] = req;                   /* 等写回，避免丢失 */
        dstate[line]  = DIR_PENDING;
    } else {                               /* I 或 S：直接给共享副本 */
        sharers[line] |= (1ull << req);
        dstate[line]   = DIR_S;
        send_data(req, line);
    }
}

void dir_write_miss(int line, int req) {
    for (int i = 0; i < N; i++)            /* 只发给已知共享者，无广播 */
        if (sharers[line] & (1ull << i)) send_inv(i, line);
    if (dstate[line] == DIR_M) send_inv(owner[line], line);
    sharers[line] = 0;
    owner[line]   = req;
    dstate[line]  = DIR_M;                 /* 待收齐 Ack 才算完成 */
}

void dir_writeback(int line, int from) {   /* 写回释放独占 */
    if (dstate[line] == DIR_PENDING) {     /* 转发给挂起的等待者 */
        sharers[line] = (1ull << pending[line]);
        dstate[line]  = DIR_S;
        send_data(pending[line], line);
    } else {
        owner[line] = -1;
        dstate[line] = DIR_I;
    }
}
```

实现要点：home 必须处理「转发未完成又来新请求」的竞态，通常引入 transient 状态（如 DIR_PENDING）与按行的请求队列，把同一行的请求 FIFO 化，避免 A-B-A 型丢失效应。若 home 只是转发数据而不同时更新状态，必须在收到写回后重放挂起请求。

## 五、与其他技术对比

| 维度 | 嗅探（Snooping） | 全映射目录 | 链式/有限指针目录 |
| --- | --- | --- | --- |
| 扩展性 | 差，$O(N)$ 广播 | 好，点对点 | 好，但失效沿链串行 |
| 缺失延迟 | 低（一跳广播） | 高（home 间接 2–3 跳） | 中（多跳转发） |
| 存储开销 | 无 | $N$ 位/行 | $O(1)$ 指针/行 |
| 链路带宽 | 随核数线性上升 | 与共享者数成正比 | 与链长成正比 |
| 实现复杂度 | 低（总线天然定序） | 中（home 仲裁 + pending） | 高（链维护、容错） |
| 典型场景 | ≤ 8–16 核 SoC | 多插槽服务器 | 大规模 CC-NUMA |

## 六、常见误区

1. 把一致性协议与内存一致性模型混为一谈：前者管「单地址多副本」，后者管「多地址访问顺序」，二者正交。
2. 认为目录一定比嗅探快：home 的间接访问引入额外跳数与排队延迟，小规模下嗅探反而更优。
3. 忽略 transient 状态：真实实现中的多数 bug 出在转发/pending 竞态，而非稳态状态机。
4. 认为「失效完成」就等于「对端立刻看到新值」：还需写回或数据转发完成，才满足数据值不变式。
5. 低估探针过滤器（snoop filter）的作用：多插槽系统常用它把广播压成目录式，本质是「目录化的嗅探」。
6. 认为共享即无代价：伪共享（false sharing）会让不同变量的写互相失效，需要按缓存行对齐数据结构。

- Censier & Feautrier 1978、Tang 1976：目录协议的原始思想与全映射位图组织。

- ARM AMBA CHI 规范：现代一致性互连的消息分类（ReadShared/ReadUnique/MakeUnique 等）。
- Coulouris《Distributed Systems》：把一致性视为复制协议的分布式视角（quorum 与失效）。

## 八、面试题

1. 问：目录协议如何避免广播？答：home 节点维护 sharers 位图，只向已知持有者发 Invalidate；未持有者无需打扰。代价是目录存储与每行一次间接访问。
2. 问：为什么大核数下嗅探不可行？答：每个请求要到达所有缓存，探针端口与链路带宽随 $N$ 线性增长，广播风暴会挤占数据带宽。
3. 问：写缺失在 MESI 与目录下分别如何实现？答：MESI 广播 BusRdX 并等待所有 Invalidate 应答；目录只向 sharers 定向发送，收齐 Ack 后授予独占。
4. 问：转发（forwarding）为什么能降低延迟？答：让 M 态持有者直接向请求者发数据，省去「写回 home 再发送」的一跳；代价是 home 需要 pending 缓冲与超时重试。
5. 问：链式目录如何容忍节点失效？答：需要断链检测与链重建，或退化为广播；位图目录则依赖 home 的持久化与请求重放。

## 九、演进与趋势

- 分层/簇化一致性：簇内嗅探、簇间目录（hierarchical coherence），在延迟与扩展性之间取平衡。
- 协议与互连融合：ARM CHI 把一致性消息作为互连层的一等公民定义；CXL.cache 把一致性域延伸到设备。
- 域限定一致性（scoped coherence）：如 HSA 的 agent/workgroup/system 作用域，弱化不必要的全局排序。
- 异构与加速器一致性：GPU/NPU 通过 ACE/CHI 端口参与一致性，减少显式拷贝。
- 形式化验证：用 litmus test 与模型检查（如 murphi 类工具）验证协议，已是现代 SoC 的必备流程。

## 十、小结

缓存一致性协议与互连拓扑深度耦合：小规模共享总线天然提供排序，嗅探实现简单、延迟低；大规模系统必须靠目录把广播换成定向消息，代价是存储、间接延迟与 transient 状态复杂度。抓住「谁有副本、如何失效、数据何时可见、home 如何缓冲竞态」这四件事，就抓住了从 MESI 到 CHI 到 CXL 的全部共同骨架。
