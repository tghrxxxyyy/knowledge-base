# 保守式 GC Boehm-Demers-Weiser

> 对应 Boehm & Weiser 1988《Garbage Collection in an Uncooperative Environment》；Jones, Hosking & Moss《The Garbage Collection Handbook》保守式回收章。

## 一、背景与挑战

C/C++ 没有运行时类型信息，指针可以任意做算术、可以存在 `union` 里、可以只保留中间值；编译器还可能把指针放进寄存器、拆成两半或优化掉。要在这样的语言上做精确 GC，就必须改造编译器与 ABI。

Boehm-Demers-Weiser（BDW）GC 走另一条路：不要求编译器配合，把每个字都当作"**可能**是指针"来处理。这就是"conservative（保守）"的含义——宁可保留可疑对象，也绝不回收可能仍被引用的对象。

这个选择还有一个容易被忽视的副作用：由于不能改变对象地址，分配器无法通过压缩来整理碎片，长期运行的进程会出现堆利用率下降，必须靠分配器的空闲块合并来缓解。

## 二、核心原理

判活规则：若某内存字的值（按对齐过滤后）落在某个已分配堆对象的地址区间 $[base(o), end(o))$ 内，就认为 $o$ 可达。扫描范围覆盖：

- 线程栈（按栈顶到底部的**保守**范围，需知道栈边界，可通过寄存器与平台特定接口获得）；
- 寄存器集合（把寄存器刷到栈上再扫）；
- 静态/全局数据段；
- 堆内的所有字（已分配块本身）。

因为无法知道哪些字是真指针，**对象不能移动**——移动会让未知的"似指针"失效。所以 BDW 只能用 Mark-Sweep 系策略，配合空闲链表分配。

为提升精度，实现上通常会：跳过明显非法的地址、用黑名单/哨兵值剔除常见误判、把栈扫描与静态数据段分段登记（`GC_register_*`），以及对"已知不含指针"的对象用 `GC_malloc_atomic` 声明以**不做**内部扫描。

## 三、形式化与数学基础

保守可达集：

$$Reach_{cons} = \{\, o \mid \exists w \in Words,\ value(w) \in [base(o),\, end(o)) \,\}$$

安全性（不误回收）可写成：

$$\neg Reach_{cons} \;\Rightarrow\; o \text{ 确实不可达}$$

即保守式只可能**漏回收**（保留垃圾），绝不**误回收**（回收活对象）。误留率取决于"随机整数恰好落入对象区间"的概率：设对象总覆盖字节为 $M$、字宽 $w$，则单个随机字被误判的概率量级为 $q \approx M/2^{w}$。指针密度高的栈会显著抬高该概率，这也是"float garbage"的来源。

## 四、代码实现

```c
/* 保守扫描一个候选字（简化） */
static void scan_word(void *w) {
    word v = *(word *)w;
    if (v & (sizeof(word) - 1)) return;        /* 未对齐，必非指针 */
    obj *o = find_object_containing(v);        /* 区间查找 */
    if (o && !o->marked) push_gray(o);         /* 标记并继续深入 */
}
/* 使用：替换 malloc/新对象分配 */
void *p = GC_MALLOC(n);        /* 含指针的对象，内部字会被扫描 */
char *b = GC_MALLOC_ATOMIC(n); /* 纯字节缓冲，内部不扫描，省时且避免误留 */
GC_gcollect();                 /* 必要时手动触发 */
```

栈扫描需要知道栈边界，实践中常在初始化时记录栈基址，并在每次进入 GC 时用当前栈指针界定有效区间；线程栈与协程栈需要显式注册。

## 六、常见误区

1. **以为整数不会误判**：恰好等于某对象地址的整数（哈希值、时间戳、ID）会被当指针，导致对象长期无法回收。
2. **以为可做压缩**：任何移动都会让未登记的旧指针失效，因此保守 GC 不能压缩。
3. **混用自定义分配器**：用 `mmap`/`sbrk` 自管内存会让 GC 看不到这些块，破坏堆元数据或漏标。
4. **忘记 `GC_MALLOC_ATOMIC`**：纯数据缓冲若用普通分配会被逐字扫描，既有性能损失又提高误留概率。
5. **忽略线程注册**：多线程下未注册的线程栈不会被扫描，可能误回收其持有的对象。

## 八、面试题

1. **什么是保守式 GC？** 要点：把每个字都当作可能指针，只要值落在某对象区间内就保守判活。
2. **为什么不能移动对象？** 要点：无法枚举全部真指针，搬迁会让未更新的旧值悬空。
3. **哪些情况会造成误留？** 要点：整数恰为地址、栈上残留的陈旧指针、未声明为 atomic 的数据缓冲。
4. **如何降低保守扫描成本？** 要点：atomic 标记无指针块、分代/增量模式、按页登记与黑名单过滤。
5. **保守式适合什么场景？** 要点：无法改造编译器的 C/C++ 库、脚本引擎嵌入宿主语言、需要零侵入接入的遗留系统。

## 九、演进与趋势

实践中常用**混合模式**：栈与静态区精确扫描（借助编译器插件或显式 API），堆内保守扫描；或反过来对已知类型对象精确扫描、对未知块保守扫描。语言层面，C++ 的智能指针与 RAII 在相当大程度上替代了自动回收需求，Rust 的所有权模型则从类型系统侧消解了同一问题。BDW 仍是许多脚本引擎与编译器前端的宿主内存管理器。

## 十、小结

Boehm GC 以"宁可误留，不可误收"的保守策略，在不改编译器的前提下为 C/C++ 提供自动回收。它以不可移动与可能的假活为代价，换取零侵入的兼容性——这是一次典型的工程折中而非理论最优解。
