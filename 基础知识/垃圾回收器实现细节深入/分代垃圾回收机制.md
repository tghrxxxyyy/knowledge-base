# 分代垃圾回收机制

> 对应 Jones, Hosking & Moss《The Garbage Collection Handbook》第 9 章（Generational Collection）；Wilson 1992《Uniprocessor Garbage Collection Techniques》。

## 一、背景与挑战

标记-清除与标记-压缩的代价是 $O(|Heap|)$，与存活对象数无关；而实测程序中绝大多数对象在分配后极短时间内死去。若每次都扫描整个堆，绝大部分工作都花在反复确认"这些垃圾确实是垃圾"。

核心矛盾在于：把回收范围缩小到"新分配区"之后，就再也不能假设能从根出发走遍所有指针——老年代里可能存在指向年轻代的引用，而这次回收并不扫描老年代。

次要矛盾是提示成本：如果为了知道跨代引用而给每次引用赋值加检查，就可能把省下的扫描时间又以屏障的形式还给程序。分代 GC 的工程难点正是把这个检查做得足够便宜。

第三个约束是**晋升策略**：把对象何时移入老年代这件事做成固定的阈值还是自适应的启发式，直接决定老年代的填满速度与 Major GC 频率。

## 二、核心原理

堆划分为年轻代与老年代。年轻代通常由 Eden 加两块 Survivor（S0/S1）构成，用复制式（Cheney）回收：存活对象在两块 Survivor 间来回拷贝，达到晋升阈值（tenuring threshold）后提升到老年代。

跨代引用由**记忆集（remembered set）**记录。最常用的实现是**卡表（card table）**：把堆按固定粒度（如 512 字节）切成卡，写屏障在"老指向新"的写操作上把对应卡置脏。

Minor GC 的根集 = 线程栈/寄存器/全局变量 + 脏卡中扫出的老年代对象。为避免每次引用赋值都判断代际，实现上常用"无条件置脏"与"卡已脏则跳过"两种屏障形态；后者需要保证卡表初值与年轻代边界对齐。

晋升还分"复制晋升"与"直接晋升"：大对象、以及 Survivor 放不下的对象通常直接进老年代，避免一次无谓拷贝。TLAB（线程本地分配缓冲）则把 Eden 的 bump 分配去同步化，是分代 GC 高频分配能跑快的前提。

## 三、形式化与数学基础

弱分代假说（weak generational hypothesis）写成条件生存概率：

$$P(\text{alive at } a+1 \mid \text{alive at } a) \ll 1$$

设年轻代大小 $Y$、堆大小 $H$、晋升率 $\pi$，则 Minor GC 的复制量为 $O(|Reach_{young}|)$ 而非 $O(H)$；每次 Minor 晋升到老年代的字节数期望为 $\pi \cdot Y$。老年代回收频率由晋升速度决定：

$$f_{major} \approx \frac{\pi \cdot Y \cdot f_{minor}}{|Old|}$$

卡表空间开销约为 $|Heap|/512$ 字节。脏卡还引入"保守根"：脏卡里已死的年轻对象也会被当作根存活一轮，形成浮动垃圾；脏卡比例越高，Minor GC 的实际成本越接近扫描整张卡所覆盖的区域。

## 四、代码实现

```c
/* 经典卡表 + 写屏障：老->新 引用时置脏卡 */
static uint8_t *card_table;          /* 每 512B 一字节 */
static inline uint8_t *card_of(void *p) {
    return &card_table[((uintptr_t)p) >> 9];
}
void store_ref(obj *parent, obj **field, obj *child) {
    *field = child;                              /* 先写值 */
    if (in_old_gen(parent) && in_young_gen(child))
        *card_of(parent) = DIRTY;                /* 再置脏卡 */
}
/* Minor GC 根集 = 脏卡扫出的年轻对象 + 栈/寄存器/静态区 */
```

屏障必须与赋值在**同一条抽象指令**内完成，否则编译器或 CPU 重排会造成漏记；因此屏障后通常需要编译器屏障，并发场景还需内存屏障指令。

## 五、与其他技术对比

| 维度 | 分代 | 非分代 Mark-Sweep | 非分代 Mark-Compact |
| --- | --- | --- | --- |
| 单次暂停 | 多数为 Minor，短 | 与堆大小成正比 | 与堆大小成正比 |
| 吞吐 | 高（幸存者少） | 中 | 中低（移动开销） |
| 空间开销 | 卡表 + Survivor 预留 | 标记位 | 标记位 + 空闲块 |
| 碎片 | 老年代需另处理 | 有外部碎片 | 无外部碎片 |
| 写操作成本 | 加屏障 | 无 | 无 |
| 实现复杂度 | 高（屏障、晋升、记忆集） | 低 | 中高 |

## 六、常见误区

1. 认为分代"免费"：写屏障插入每一条引用赋值，写密集负载吞吐会明显下降。
2. 过早晋升：Survivor 过小或阈值过低会把短命对象直接送进老年代，引发老年代碎片与频繁 Major GC。
3. 忽略卡粒度权衡：卡太粗会引入大量无关根使 Minor 退化；太细则卡表内存占用上升。
4. 认为分代能消除碎片：老年代若不移动仍会碎片化，需要 Mark-Compact 或 region 化整理。
5. 把 Minor GC 暂停小等同于"没有暂停问题"：晋升风暴时 Major GC 仍可能出现长尾停顿。
6. 误以为 Survivor 越大越好：Survivor 过大挤压 Eden，Minor GC 频率上升，总吞吐未必改善。

## 八、面试题

1. **为什么需要写屏障？** 要点：回收只扫年轻代时无法发现老年代中的跨代指针；屏障在写时把老->新引用记入记忆集，补全根集。
2. **Minor GC 与 Major GC 的根集差别？** 要点：Minor 仅需"栈/寄存器/静态 + 脏卡引用的老年代对象"，Major 需遍历整堆。
3. **晋升阈值如何影响性能？** 要点：过低使老年代快速填满、Major 频率上升；过高使长命对象反复拷贝并长期占用 Survivor。
4. **分代假说不成立时会怎样？** 要点：缓存/大数组负载下每次 Minor 后老年代即被填满，退化为接近全堆回收。
5. **为什么大对象常直接进老年代？** 要点：拷贝成本与 Survivor 空间压力都过大，直接分配可避免反复搬迁。

## 九、演进与趋势

G1 把堆切成 region 并为每个 region 维护 RSet，用可预测停顿模型做"垃圾优先"收集；ZGC/Shenandoah 通过染色指针与读屏障把压缩也并发化，使暂停与堆大小无关。记忆集本身也在演进：从"每卡一字节"向 per-region 位图、乃至免记忆集的彩色指针方案发展，年轻代与老年代的边界也变得动态（region 可被重新归类）。

## 十、小结

分代 GC 把弱分代假说转化为工程结构：年轻代用复制、老年代用低频重回收，跨代正确性由写屏障与卡表/记忆集保证。收益来自"少扫"，代价落在每次引用赋值的屏障与晋升策略调优上——它的成败几乎完全取决于对真实负载对象年龄分布的判断是否成立。
