# 并发与增量式垃圾回收

> 对应 Dijkstra 等 1978《On-the-Fly Garbage Collection》；Yuasa 1990（SATB）；Bacon 等 2004《A Unified Theory of Garbage Collection》。

## 一、背景与挑战

Stop-The-World 回收在大堆上可产生数百毫秒乃至数秒的暂停，直接违反低延迟服务的尾延迟预算。目标是把回收工作与 mutator（业务线程）交错或并行执行，让**单次停顿**与堆大小解耦。

难点在于所有"暂停期间天然成立"的前提在并发下全部失效：对象图在回收过程中被 mutator 持续修改，标记结果随时可能变旧。

还有一个隐蔽的难点是**根集**：线程栈与寄存器随时在变，无法在不挂起线程的情况下可靠读取。因此几乎所有并发收集器都要保留一次（或几次）短暂的 STW 来完成根扫描与差异收敛。

## 二、核心原理

**增量式**把标记切成小步，与 mutator 交替执行，靠写屏障捕获修改；**并发式**让回收线程与 mutator 真正同时运行，除写屏障外还需内存屏障保证跨核可见性。

理论基元是**三色标记**：白（未访问，假定垃圾）、灰（已发现待扫描）、黑（已扫描完成）。回收结束的条件是"无灰对象"。并发修改会破坏不变式，因此需要：

- **增量更新（incremental update）**：黑对象新增白引用时，把白对象置灰（Dijkstra 屏障）。
- **快照即开始（snapshot-at-the-beginning, SATB）**：黑对象删除对白的引用时，把被删除的白对象记录为存活（Yuasa 屏障）。

无论哪种，结束前都需要一次短暂的 STW 重新标记（remark）来收敛由栈扫描与屏障队列残留造成的差异。

## 三、形式化与数学基础

强三色不变式要求不存在从黑到白的直接边：

$$\forall e=(a,b):\quad color(a)\neq black \;\lor\; color(b)\neq white$$

弱不变式只要求"黑可达的白最终会被发现"。写屏障的作用就是维持其中之一。最大暂停时间满足

$$P_{max} = P_{remark} + P_{root\text{-}scan} \ll T_{full}$$

其中 $P_{root\text{-}scan}$ 可用根分区/批量扫描进一步摊薄。SATB 下浮动垃圾上界约为本次标记周期内新分配的数据量：

$$G_{float} \le \sum_{\text{cycle}} alloc$$

增量式还可给出"标记速率必须快于分配速率"的可行性条件：设标记速率 $R_{mark}$（字节/秒）、分配速率 $R_{alloc}$，则要求 $R_{mark} > R_{alloc}$，否则回收永远追不上。

## 四、代码实现

```c
/* Dijkstra 增量更新写屏障：防止黑->白丢标 */
void store_ref(obj *a, obj **field, obj *b) {
    *field = b;                          /* 实际写值 */
    if (color(a) == BLACK && color(b) == WHITE)
        shade(b);                        /* 把 b 置灰并推入标记队列 */
}

/* Yuasa SATB 屏障：记录被覆盖的旧值 */
void store_ref_satb(obj *a, obj **field, obj *b) {
    obj *old = *field;
    if (color(a) == BLACK && color(old) == WHITE)
        satb_queue_push(old);            /* 旧值快照为活 */
    *field = b;
    *(volatile obj **)field = b;         /* 保证顺序可见 */
}
```

并发标记的典型阶段：初始标记（STW，扫描根）→ 并发标记（mutator 同时跑，屏障工作）→ 重新标记（STW，处理屏障队列与 SATB 缓冲）→ 并发清理/转移。

## 五、与其他技术对比

| 维度 | Stop-The-World | 增量式 | 并发式 |
| --- | --- | --- | --- |
| 最大暂停 | 与堆成正比 | 与步长成正比 | 与根集/remark 成正比 |
| 吞吐 | 最高 | 略降（交替开销） | 降（屏障 + 线程竞争） |
| 实现难度 | 低 | 中高 | 高（内存模型、屏障） |
| 是否需要屏障 | 否 | 是 | 是（写和/或读） |
| 浮动垃圾 | 无 | 少量 | 有（尤其 SATB） |
| 典型场景 | 批处理 | 早期交互式系统 | 服务端低延迟 |

## 六、常见误区

1. **漏写屏障导致漏标**：漏标会让活对象被回收（崩溃），远比浮动垃圾严重；浮动垃圾只影响内存占用。
2. **以为并发就没有暂停**：初始标记、重新标记、根扫描通常仍需 STW，只是被压到很短。
3. **写屏障过重**：每次引用赋值都插入检查，写密集负载吞吐会下降，故常做快速路径过滤。
4. **忽略内存序**：标记位与指针的写顺序若无屏障，其他核可能看到"一半更新"的状态。
5. **把浮动垃圾当作泄漏**：SATB 下本轮新增的对象会整体存活一轮，属于设计预期而非 bug。

## 七、与开源书·权威来源对应

- Dijkstra 等 1978 的 on-the-fly 标记与增量更新屏障；Steele 1975 的并发标记思想。

## 八、面试题

1. **三色标记中"灰"的意义？** 要点：灰 = 已发现但其引用尚未扫描，是工作队列的边界；无灰对象即标记完成。
2. **增量更新与 SATB 的区别？** 要点：前者在新增引用时保护新对象；后者在删除引用时保护旧对象，天然产生浮动垃圾。
3. **为什么并发 GC 仍需 STW？** 要点：根集（栈/寄存器）无法安全并发扫描，且屏障队列需要收敛，故有极短的初始标记与重新标记。
4. **读屏障与写屏障的取舍？** 要点：写屏障影响所有写操作；读屏障影响所有读但可支持对象移动（自愈式指针），ZGC/Shenandoah 因此选择后者。
5. **如何判断并发回收是否跟得上？** 要点：标记速率必须大于分配速率，否则并发周期无法收敛，会退化为强制 STW 回收。

## 九、演进与趋势

ZGC 与 Shenandoah 用染色指针（colored pointer）加读屏障实现并发压缩，暂停时间与堆大小、存活量都几乎无关；G1 用 SATB 加预测模型做增量式混合回收。工程趋势是把"暂停"进一步转移到根扫描（并发栈扫描、handshake）与屏障快速路径优化上，并借助硬件特性（如 ARM 的 MTE）辅助标记。

## 十、小结

并发/增量 GC 以颜色不变式与屏障把回收拆进业务执行流，用吞吐与实现复杂度换取可预测的低延迟；其中"漏标致命、浮动垃圾可容忍"是最重要的工程直觉。
