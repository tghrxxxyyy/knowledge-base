# 并发与增量式垃圾回收

> 对应 Bacon 2004（GC 算法统一理论）；Wilson 1992（GC 综述）。

## 一、背景与挑战
 Stop-The-World GC 在大型堆上暂停可达数百毫秒，无法满足低延迟服务。需把回收与 mutator 并发或分步进行。

## 二、核心原理
增量式把标记拆成小步与 mutator 交替，用写屏障捕获 mutator 的修改（如三色不变式：黑不指向白）。并发式让回收线程与业务线程同跑，需内存屏障保证可见性与一致性。最终仍需短暂 STW 做收尾（重新标记）。

## 三、形式化与数学基础
三色不变式（强）：
$$\forall e=(a,b),\ color(a)\neq black \lor color(b)\neq white$$
写屏障在 mutator 把白对象接入黑对象时将其置灰（或黑），保持不变量。最大暂停 $P_{max} \ll T_{full}$。

## 四、代码实现
```c
// Dijkstra 写屏障（增量更新）
void write(obj *a, obj *b) {
    *field(a) = b;
    if (color(a) == BLACK && color(b) == WHITE)
        mark_gray(b);   // 防漏标
}
```

## 五、与其他技术对比
STW 实现简单但长暂停；增量降低单次停顿但总吞吐略降；并发最大化响应但需屏障与 CPU 资源竞争。

## 六、常见误区
1. 漏写屏障致并发标记漏标（浮动垃圾尚可，漏标致命）。
2. 以为并发无暂停——仍有 brief STW。
3. 屏障过重拖累 mutator 吞吐。

## 七、与开源书/权威来源对应
Bacon 2004（统一 GC 理论）；Wilson 1992；Jones & Lins 并发章。

## 八、面试题
问：三色标记是什么？写屏障为何必需？并发 GC 还有暂停吗？

## 九、演进与趋势
ZGC/Shenandoah 用读屏障+染色指针实现亚毫秒暂停；Region 化并发压缩成主流。

## 十、小结
并发/增量 GC 以颜色不变式与写屏障把回收拆入业务流，换取可预测低延迟。
