# DDoS分类

> 对应 RFC 4732（Internet Denial-of-Service Considerations）与 Mirkovic & Reiher 2004《A Taxonomy of DDoS Attack and DDoS Defense Mechanisms》。

## 一、背景与挑战
分布式拒绝服务（Distributed Denial of Service, DDoS）通过控制大量分布主机，向目标同时倾泻流量或请求，耗尽带宽、连接表、CPU 或后端数据库资源，使合法用户无法获得服务。与单机 DoS 相比，其显著特征是「分布式」——攻击源地理分散、协议多样、动机复杂，单点封禁 IP 无法奏效。

分类之所以重要，是因为不同类别的攻击消耗的资源不同，对应的检测信号与缓解手段也截然不同：用防火墙规则去挡带宽洪泛是徒劳，用大带宽清洗中心去挡 Slowloris 也属于高射炮打蚊子。工程师必须先判断「正在被哪一类攻击」，才能选择正确的对策。

现实挑战还包括：攻击者常混合使用多层手段（L3 洪泛打底、L7 慢速请求干扰），使单一分类判据失效；云环境中弹性扩缩容会把「可用性攻击」转化为「成本攻击」，账单本身成为破坏目标。此外，攻击工具即服务（DDoS-for-hire）大幅降低了发动门槛。

## 二、核心原理
主流分类有两个正交维度：按协议层次、按攻击来源与动机。

按协议层次：
- L3/L4 容量型（volumetric）：UDP 洪泛、ICMP 洪泛、DNS/NTP/Memcached 反射放大，目标是占满链路带宽。
- L4 协议型：SYN 洪泛、ACK 洪泛、连接耗尽，目标是耗尽服务器连接状态表或内核资源。
- L7 应用层：HTTP GET/POST 洪泛、Slowloris、慢速 POST，目标是以小流量耗尽应用线程、连接或数据库连接池。

按来源与手法：直接攻击（攻击者直接发包）、反射放大（借第三方服务器放大）、僵尸网络（botnet 集中调度）。按动机：竞技炫耀、勒索敲诈、政治表达、商业竞争。分类不是学术洁癖，而是「检测信号 → 处置动作」的映射表。

## 三、形式化与数学基础
把目标的服务能力抽象为容量 $C$，合法请求到达率 $\lambda_{legit}$，攻击速率 $\lambda_{attack}$。服务可用的必要条件为：

$$ \lambda_{legit} + \lambda_{attack} \le C $$

攻击者只需使 $\lambda_{attack} > C - \lambda_{legit}$ 即可造成拒绝服务。防御者资源并非无限，因此真正目标是让到达目标的流量满足：

$$ \lambda_{to\_target} = \lambda_{legit} + \lambda_{attack}(1 - d) < C $$

其中 $d$ 为过滤与清洗的综合丢弃率。攻击强度常用两种量纲表示：带宽型以 bit/s 计，$I_{bps}=\sum_i rate_i^{bps}$；包速率型以 packet/s 计，$I_{pps}=\sum_i rate_i^{pps}$。后者的破坏性常被低估——小包洪泛能以极低带宽打满路由器的 pps 处理能力。

## 四、代码实现
```bash
# 观察单位时间 pps 异常（示意，非完整检测逻辑）
sar -n DEV 1 5 | awk '$5 > 200000 { print "疑似洪泛", $0 }'

# 统计单个源 IP 的半连接数，识别连接耗尽型
ss -tan state syn-recv | awk '{ print $5 }' | cut -d: -f1 | sort | uniq -c | sort -rn | head

# 应用层：按 IP 统计最近请求数（需配合日志管道）
awk '{ print $1 }' access.log | sort | uniq -c | sort -rn | head -20
```

上面的命令仅用于离线排查思路演示，生产检测应基于流采样（NetFlow/sFlow）、eBPF 或专用防护设备的基线模型。分类判定通常综合三个信号：峰值带宽是否饱和、新连接速率是否异常、应用层错误率（超时、5xx）是否突升。

## 五、与其他技术对比
| 维度 | 容量型（Volumetric） | 协议型（Protocol） | 应用层（L7） |
| --- | --- | --- | --- |
| 主要消耗 | 链路带宽 | 连接表/内核资源 | CPU/线程/DB 连接 |
| 典型代表 | UDP、放大攻击 | SYN 洪泛 | HTTP 洪泛、Slowloris |
| 流量特征 | 高 bps/pps，易识别 | 半连接堆积 | 请求合法、行为异常 |
| 主要对策 | 运营商清洗、任播分散 | SYN Cookie、连接限速 | WAF、行为分析、挑战 |
| 检测难点 | 区分攻击与突发业务 | 源 IP 常被伪造 | 与正常爬虫难区分 |

三类并非互斥，真实攻击常跨层叠加，防护需多层联动而非依赖单一设备。

工程上可按「攻击面」把判据与响应动作绑定，形成一张可执行的决策表：

- 链路利用率接近饱和、丢包集中在边界 → 容量型：联系上游清洗、启用任播分散。
- 新连接失败、syn-recv 堆积 → 协议型：开启 SYN Cookie、收紧连接速率。
- 带宽平稳但 P99 延迟与 5xx 上升 → 应用层：启用 WAF 规则、挑战与限流。
- 流量来源集中于少数 ASN/国家 → 反射放大：引入信誉与地理策略。
- 单 IP 请求速率远超人类操作 → L7 洪泛：按 IP 与会话限速并加验证挑战。
- 应用指标先动、带宽后动 → 慢速攻击：优先行为分析而非带宽清洗。

三类攻击的可观测性差异值得注意：容量型在带宽与 pps 上立即可见，协议型在连接状态统计中显现，应用层攻击往往只能通过业务指标（超时率、错误率、后端连接池占用）间接发现，检测时延更长，因而更依赖基线建模而非静态阈值。

预算有限时，防御投入的优先级通常是先保底、再增强、后精细：

- 保底：SYN Cookie、基础限流、上游应急通道。
- 增强：WAF、行为分析与挑战机制。
- 精细：信誉评分、自动编排与近源清洗。

## 六、常见误区
误区一：「DDoS 就是大流量」。错，L7 慢速攻击带宽可能只有几 Mbps，却能拖垮线程池。误区二：「加带宽就能扛」。错，带宽成本随攻击规模线性上升，且打的是 pps 或连接数时加带宽无用。误区三：「防火墙能挡所有 DDoS」。错，防火墙本身可能就是被洪泛打瘫的环节，需要上游运营商级清洗。误区四：「分类只是学术」。错，分类直接决定你该在哪个环节、用哪类设备处置。

## 八、面试题
1. DDoS 按协议层次分为哪几类？每类消耗的核心资源是什么？
2. 为什么应用层 DDoS 用「加带宽」无法解决？
3. 反射放大攻击属于哪一类？它为什么能绕开「攻击者自身带宽有限」的约束？
4. 收到线上服务超时告警，如何快速判断是容量型、协议型还是应用层攻击？
5. 混合攻击场景下，分层缓解的优先级应如何设计？

## 九、演进与趋势
IoT 僵尸网络把攻击规模推向 Tbps 级；云原生环境催生「成本型 DDoS」——攻击者迫使弹性扩容，账单成为武器。检测侧从静态阈值走向基于基线建模与机器学习的自适应识别，缓解侧向边缘任播与近源清洗演进。同时，攻击工具即服务降低了门槛，使中小站点也频繁遭受勒索型攻击。防御思路正从「堆带宽」转向「可观测性 + 自动化编排」。

## 十、小结
DDoS 分类的本质是回答「攻击在消耗什么资源」。按层次分为容量型、协议型与应用层，是工程上最有解释力的切分：它直接映射到检测信号与缓解手段。理解分类后，才能设计出「上游清洗 + 协议层加固 + 应用层挑战」的多层防御，而不是寄望于某一件银弹设备。
