# 流量清洗与限速

> 对应流量清洗（scrubbing）与限速实践；RFC 2827（BCP38）。

## 一、背景与挑战
攻击流量混杂正常流量，需区分并剥离恶意部分，同时限制异常速率以保护后端。清洗中心与限速是落地的两件套。

## 二、核心原理
流量清洗：把疑似攻击流量引流（BGP 引流/策略路由）到清洗中心，用指纹（特征）、行为分析、ACL 过滤掉攻击，干净流量回注。限速（policing）：在边界用令牌桶丢弃超阈值流量，保护下游。

## 三、形式化 / 数学基础
清洗后残余：$\lambda_{clean} = \lambda_{legit} + \lambda_{attack}(1 - d_{detect})$，$d_{detect}$ 为检测丢弃率。
限速（srTCM，RFC 2697）：承诺速率 $CIR$、突发 $CBS$，超标流量标记/丢弃。

## 四、代码实现
```bash
# 边界限速（令牌桶管制）
tc qdisc add dev eth0 root tbf rate 1gbit burst 32kbit latency 10ms
# 引流清洗（伪）：BGP 把受害者前缀通告到 scrubbing 中心
```

## 五、与其他技术对比
清洗（识别并剥离，保留合法）vs 黑洞（全丢，误杀合法）；限速（丢超规）vs 整形（缓存平滑）。清洗保可用、黑洞保网络。

## 六、常见误区
误区一：清洗能 100% 区分。错，总有漏杀/误杀需调优。误区二：限速等于清洗。错，限速简单粗暴、无内容识别。误区三：限速不影响正常用户。错，配置过严会误伤。

## 十、小结
流量清洗识别剥离攻击、限速约束异常速率，二者结合在保可用与保网络间取舍。
