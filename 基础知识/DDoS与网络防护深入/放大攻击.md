# 放大攻击

> 对应 RFC 5358（DNS 放大考量）；CERT 放大攻击告警。

## 一、背景与挑战
某些协议请求小、响应大，且可伪造源 IP（无状态 UDP）。攻击者用伪造的受害者 IP 发请求，让大量服务器把大响应“放大”打向受害者，形成反射放大。

## 二、核心原理
放大因子 = 响应大小 / 请求大小。典型：DNS（ANY 查询）、NTP（monlist，因子~500x）、SSDP、Memcached（因子极大）、SNMP。防御：禁用开放解析器/monlist、做源验证（BCP38）、限速响应。

## 三、形式化 / 数学基础
放大因子：$A = \dfrac{size(response)}{size(request)}$。
攻击总带宽：$\lambda = N_{reflectors} \cdot rate_{resp}$，受害收到 $\lambda$ 而攻击者只发 $N \cdot rate_{req} = \lambda/A$。
BCP38（RFC 2827）：在边缘过滤伪造源地址，使反射无法定向到真实受害者。

## 四、代码实现
```bash
# 关闭 DNS 开放递归（named.conf）
options { recursion no; allow-query { internal; }; };
# 关闭 NTP monlist
ntpdc -c "restrict default nomodify notrap nopeer noquery"
```

## 五、与其他技术对比
放大攻击（反射、无需控制大量主机，借公共服务器）vs 直接僵尸网络洪泛（需控制肉鸡）；前者“借力打力”、隐蔽且高效。

## 六、常见误区
误区一：TCP 易被放大。错，TCP 需握手、难伪造源、无放大。误区二：关了 DNS 递归就没事。错，NTP/Memcached/SSDP 同样危险。误区三：放大攻击需要肉鸡。错，借公共服务器即可。

## 九、演进与趋势
Memcached 放大曾达 1.7 Tbps；行业推动默认关闭可放大服务、部署响应限速。

## 十、小结
放大攻击借无状态 UDP 协议的小请求大响应进行反射，BCP38 与关闭开放服务是根本防护。
