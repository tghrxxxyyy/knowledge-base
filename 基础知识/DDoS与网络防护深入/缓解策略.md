# 缓解策略

> 对应 DDoS 缓解分层实践；RFC 4732。

## 一、背景与挑战
面对大规模 DDoS，单点防御不够，需要从边缘到应用的多层缓解体系，在尽量不误伤合法用户的前提下过滤攻击流量。

## 二、核心原理
分层缓解：网络层 ACL/黑洞、运营商清洗中心（scrubbing）、任播（anycast）分散、速率限制、WAF/七层挑战（CAPTCHA、JS 挑战）、CDN 吸收静态流量、地理/AS 封锁。关键原则：尽可能在靠近源侧、在带宽充足处清洗。

## 三、形式化 / 数学基础
多层过滤：设各层丢弃率 $d_i$，残余攻击 $\lambda' = \lambda \prod (1-d_i)$。
任播：将目标 IP 宣告到 $N$ 个节点，攻击流量按路由分散到各点，单点压力 $\approx \lambda/N$。
速率限制（令牌桶，见 SUB7）：每源 $r$、容量 $b$。

## 四、代码实现
```nginx
# 七层限流（每 IP 每秒 10 请求）
limit_req_zone $binary_remote_addr zone=perip:10m rate=10r/s;
server { location / { limit_req zone=perip burst=20 nodelay; ... } }
```

## 五、与其他技术对比
边缘清洗（运营商级、大带宽）vs 主机防火墙（有限）；被动丢弃 vs 主动挑战（对应用层 bot）。各层互为补充，没有“银弹”。

## 六、常见误区
误区一：装 WAF 就免疫 DDoS。错，WAF 主要防应用漏洞，对 volumetric 无力。误区二：限流能挡放大攻击。错，需上游带宽清洗。误区三：误杀不可避免就不管。错，需精细白名单/挑战降误杀。

## 十、小结
DDoS 缓解靠网络/运营商/应用多层联动、任播分散与限流挑战，原则是近端大带宽处清洗。
