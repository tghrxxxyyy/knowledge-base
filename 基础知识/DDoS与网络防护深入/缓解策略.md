# 缓解策略

> 对应 RFC 4732（Internet Denial-of-Service Considerations）与 BCP38 / RFC 2827（Network Ingress Filtering）。

## 一、背景与挑战
面对大规模 DDoS，任何单点防御都不够：主机防火墙挡不住链路洪泛，清洗中心无法识别慢速应用层攻击，WAF 对容量型攻击无能为力。真正的缓解是一套从边缘到应用、从网络层到内容层的协同体系，目标是在尽量不误伤合法用户的前提下，把攻击流量在到达关键资源之前层层削减。

难点在于「效果」与「误伤」的权衡：过滤越激进，攻击被挡得越彻底，但正常用户被误拦的概率也越高。缓解策略的设计，本质是沿着攻击链在不同位置部署能力互补的防线。

## 二、核心原理
分层缓解的关键原则是：尽可能靠近攻击源侧、在带宽充裕处完成清洗。典型层次包括：

- 网络层：上游运营商 ACL、黑洞路由、源地址过滤（BCP38）。
- 基础设施层：清洗中心（scrubbing）、任播（anycast）分散、CDN 吸收静态流量。
- 传输层：SYN Cookie、连接数限速、半连接参数调优。
- 应用层：WAF、七层速率限制、行为分析与挑战（JS 挑战、验证码）。
- 访问控制：地理/AS 封锁、黑白名单、信誉评分。

任播把同一个服务地址宣告到多个地理分散的节点，攻击流量按 BGP 路由就近被多个节点分摊，单点压力大幅下降；清洗中心则用大带宽与专业设备承接被引流的流量。

## 三、形式化与数学基础
设各层对攻击流量的独立丢弃率为 $d_1, d_2, \dots, d_n$，则到达最内层关键资源的残余攻击约为：

$$ \lambda' = \lambda_{attack} \prod_{i=1}^{n} (1 - d_i) $$

多层叠加能显著压低残余，但也意味着各层都需付出成本与误杀代价。

任播的分散效果可粗略建模为：把目标地址宣告到 $N$ 个节点后，若流量按路由均匀分摊，则单节点承受：

$$ \lambda_{node} \approx \frac{\lambda_{total}}{N} $$

实际分摊取决于 BGP 路径与地域分布，并非严格均分，但趋势成立。

速率限制沿用令牌桶模型：每源速率上限 $r$、突发容量 $b$，超限部分被丢弃或降级。

## 四、代码实现
```nginx
# 七层限流：每 IP 每秒 10 个请求，允许 20 个突发
limit_req_zone $binary_remote_addr zone=perip:10m rate=10r/s;

server {
  location /api/ {
    limit_req zone=perip burst=20 nodelay;
    limit_conn perip_conn 20;
    proxy_pass http://backend;
  }
}
```

```bash
# 内核侧：开启 SYN Cookie 与连接跟踪调优
sysctl -w net.ipv4.tcp_syncookies=1
sysctl -w net.netfilter.nf_conntrack_max=1048576
```

```yaml
# 编排：检测到攻击超阈值时自动触发清洗引流（示意）
on_attack_threshold:
  - action: divert_to_scrubbing   # BGP 引流到清洗中心
  - action: enable_js_challenge   # 应用层挑战
  - action: notify_oncall
```

上述配置为示意，参数需结合业务基线设定，具体语法以各组件官方文档为准。

## 五、与其他技术对比
| 防护层 | 代表手段 | 擅长攻击类型 | 局限性 |
| --- | --- | --- | --- |
| 网络/运营商 | ACL、黑洞、BCP38 | 容量型、伪造源 | 粗粒度，可能误伤整段 |
| 基础设施 | 清洗中心、任播、CDN | 容量型、分散攻击 | 成本高，需引流协同 |
| 传输层 | SYN Cookie、连接限速 | 协议型 | 对应用层无效 |
| 应用层 | WAF、限流、挑战 | 应用层、Bot | 对带宽洪泛无力 |
| 访问控制 | 地理/AS 封锁、信誉 | 已知恶意来源 | 误伤与绕过风险 |

各层互为补充，没有单一银弹。合理的架构是让攻击流量按「容量型交给运营商与任播、协议型交给传输层、应用层交给 WAF 与挑战」的路径被逐层削减。

## 六、常见误区
误区一：「装了 WAF 就免疫 DDoS」。错，WAF 主要防应用漏洞与部分应用层攻击，对容量型洪泛无能为力。误区二：「限流能挡住放大攻击」。错，放大攻击占满的是链路带宽，必须在更上游清洗。误区三：「误杀不可避免就放任不管」。错，应通过白名单、渐进挑战与阈值调优尽量降低误杀。误区四：「一层做到极致就够了」。错，攻击常跨层叠加，缺一环即成为短板。

## 九、演进与趋势
云原生 DDoS 防护（如各大云厂商的 Shield 类服务与 CDN 边缘防护）把任播、大带宽清洗与机器学习实时识别整合为托管能力，中小团队无需自建即可获得运营商级防护。趋势上，防护点持续前移到边缘，检测从阈值走向行为基线，处置从人工走向自动编排；同时，攻击的「成本型」变体要求缓解策略兼顾弹性扩缩容的经济性。

## 十、小结
DDoS 缓解的精髓是「分层协同、近源清洗」：用运营商与任播承接容量、用传输层机制抵御协议攻击、用应用层挑战与限流拦截 Bot，并以访问控制做最后收敛。任何一层都不是银弹，只有把它们编排成有梯度的防线，并持续监控误杀与残余流量，才能在大规模攻击下守住可用性。
