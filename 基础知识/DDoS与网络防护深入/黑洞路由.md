# 黑洞路由

> 对应 BGP 黑洞路由（Blackhole Routing）；RFC 3882（BGP 社区黑洞）。

## 一、背景与挑战
当攻击规模超过清洗能力或来源极分散，继续让流量抵达目标会拖垮整个网段。最后手段是把去往受害 IP 的流量“丢弃到虚空”，牺牲该 IP 可用性以保全网络。

## 二、核心原理
黑洞路由：将受害者前缀指向 null0/丢弃接口（静态黑洞），或通过 BGP 把前缀带黑洞社区（如 RFC 3882 的 BLACKHOLE 社区）通告给上游，使上游也丢弃该流量。代价是该 IP 完全不可达（牺牲可用性换网络稳定）。

## 三、形式化 / 数学基础
路由决策：目的 IP ∈ 黑洞前缀 → 下一跳 null0 → 丢包，合法与攻击流量一同丢弃。
BGP 社区通告：$prefix\ +\ COMMUNITY(blackhole)$ 使上游 AS 对该前缀做丢弃，范围可控（通常限特定 ASN/粒度）。

## 四、代码实现
```bash
# 本地静态黑洞
ip route add 192.0.2.0/24 blackhole
# BGP 通告黑洞社区（伪配置）
route 192.0.2.0/24 community BLACKHOLE -> 上游丢弃
```

## 五、与其他技术对比
黑洞（全丢、保网络、牺牲 IP）vs 清洗（保 IP、需能力）；vs 限速（部分保）。黑洞是“断尾”最后手段，针对超大规模或无法区分时。

## 六、常见误区
误区一：黑洞能缓解攻击又不掉线。错，被黑洞 IP 完全不可达。误区二：黑洞只丢攻击。错，合法流量一起丢。误区三：黑洞是首选。错，应作为最后兜底。

## 九、演进与趋势
精细化黑洞（只丢特定五元组/源 ASN）、与清洗自动切换（攻击超阈值自动黑洞）是运营实践。

## 十、小结
黑洞路由以牺牲目标 IP 可用性为代价丢弃全部流量，是超大规模 DDoS 下的最后兜底手段。
