# 解释与编译权衡

> 对应 Crafting Interpreters 与 Kennedy & Allen（JIT 章）。

## 一、背景与挑战
解释启动快、可移植、省编译时间；编译（AOT/JIT）执行快但启动慢、需优化成本。权衡点决定语言运行时策略。

## 二、核心原理
解释：每条指令循环解码执行，启动即跑。编译：先转机器码（可能优化）再直接执行，启动有延迟但稳态快。JIT 取其中：运行期把热点编成机器码。

## 三、形式化 / 数学基础
设解释每条成本 $c_i$，编译启动 $C_c$ 边际每条 $c_m$（$c_m\ll c_i$）。执行 $n$ 次总成本：解释 $n c_i$，编译 $C_c + n c_m$。临界 $n^* = C_c/(c_i-c_m)$：超过即编译更值。

## 四、代码实现
```python
def execute(code):
    if hot(code):                 # 热点
        return run_native(jit(code))   # 编译后跑
    return interpret_loop(code)        # 否则解释
```

## 五、与其他技术对比
- 纯解释（CPython 旧）：启动快、慢。
- AOT（C/Rust）：快、启动快、失可移植。
- JIT（JVM/V8）：平衡、需运行时编译线程。

## 六、常见误区
1. 以为 JIT 总比解释快（冷路径反而慢）。
2. 忽略编译本身的开销与暂停。
3. 把可移植与性能对立（JIT 兼得可移植+快）。
