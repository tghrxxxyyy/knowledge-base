# 去优化

> 对应 Kennedy & Allen 与 CS-Notes（V8 deopt）。

## 一、背景与挑战
JIT 基于假设（类型、分支）生成快代码；假设失效必须安全回退到解释器/未优化码。挑战：状态重建、性能抖动、正确性。

## 二、核心原理
编译时记录"去优化元数据"：每守卫对应解释器/基线位置的变量映射。守卫失败触发 deopt，重建帧并跳转；被去优化的代码通常标记不再用。

## 三、形式化 / 数学基础
守卫 $g$ 关联不变式 $I$。若运行期 $\neg I$ 则 deopt：从机器态按元数据映射回字节码/解释态 $(pc, locals)$，保证语义等价。

## 四、代码实现
```python
def guard_int(x, deopt_meta):
    if not isinstance(x, int):
        deoptimize(deopt_meta)   # 重建解释器帧并跳回
    return x
```

## 五、与其他技术对比
- 去优化（V8）：保正确、代价为停顿。
- 无去优化（AOT 保守）：不快但稳。
- 重编译：去优化后按新轮廓再编译（分层）。

## 六、常见误区
1. 以为去优化是 bug（其实是正常安全机制）。
2. 频繁去优化致"性能悬崖"。
3. 去优化元数据不全致状态错。

## 九、演进与趋势
去优化成本降低（惰性重建）、分层重编译、以及基于轮廓的稳定化。

## 十、小结
去优化是 JIT 投机优化的安全网：假设失效即回退解释态，保正确；频繁去优化是性能信号而非错误。
