# 热点探测

> 对应 Kennedy & Allen 与 CS-Notes（JVM 热点）。

## 一、背景与挑战
JIT 只在"热点"代码上花编译成本才划算。挑战：准确识别热点、开销低、及时编译、避免抖动 (thrashing)。

## 二、核心原理
方法计数：每次调用/回边 (back-edge) 计数器 +1，超阈值触发编译。分层：先轻量编译，再对更热者重编译优化更强。

## 三、形式化 / 数学基础
计数器 $c_m$（方法入口）、$c_b$（循环回边）。当 $c_m>T_m$ 或 $c_b>T_b$ 触发编译。衰减：计数周期性减半防旧热点长期霸占。

## 四、代码实现
```python
def on_back_edge(method):
    method.loop_count += 1
    if method.loop_count == THRESHOLD:
        enqueue_compile(method, level=1)
```

## 五、与其他技术对比
- 计数法（HotSpot）：简单、主流。
- 采样法：低开销、可能漏。
- 轨迹法（见轨迹 JIT）：按执行路径而非方法。

## 六、常见误区
1. 计数不衰减致已冷代码仍被编译。
2. 阈值过低致抖动（反复编译）。
3. 只数方法忽略循环（热点常在循环）。

## 十、小结
热点探测是 JIT 的"节流阀"：方法+回边计数超阈触发编译，衰减防止误判；准确探测决定 JIT 收益上限。
