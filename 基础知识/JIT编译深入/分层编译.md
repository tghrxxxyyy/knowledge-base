# 分层编译

> 对应 CS-Notes（HotSpot Tiered Compilation）与 Kennedy & Allen。

## 一、背景与挑战
单层 JIT 难兼顾启动与峰值：重优化拖慢启动，轻优化限峰值。分层编译用多级（解释→C1→C2）渐进优化。挑战：层级切换、代码替换 (OSR)、资源。

## 二、核心原理
Level 0 解释；Level 1/2 轻量编译（快、带剖析）；Level 3/4 重优化（向量化等）。热点先快速编轻量，更热再编重量。运行时可 OSR 替换正在跑的方法。

## 三、形式化 / 数学基础
编译级别 $L\in\{0,1,2,3,4\}$，优化强度递增、编译成本递增。切换：$hot(m)$ 提升 $L$；OSR 把解释/低层栈帧迁到高层入口并重建状态。

## 四、代码实现
```python
def maybe_compile(m, level):
    if m.calls > T[level]:
        new = compile(m, level + 1)   # 升层
        install(m, new)               # 替换入口; 运行中可 OSR
```

## 五、与其他技术对比
- 单层 JIT：简单但权衡差。
- 分层（HotSpot）：启动快 + 峰值高。
- AOT+分层（Graal）：再降启动。

## 六、常见误区
1. 以为分层只省时间（也提升峰值可达性）。
2. OSR 状态重建错致语义变。
3. 层级过多致编译线程拥挤。
