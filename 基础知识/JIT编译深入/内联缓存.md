# 内联缓存

> 对应 CS-Notes（V8/JS 内联缓存）与 Crafting Interpreters。

## 一、背景与挑战
动态语言每次属性/方法访问都查表很慢。内联缓存 (IC) 把"上次结果"缓存在调用点，命中即快。挑战：状态（单/多/巨态）管理、正确性、失效。

## 二、核心原理
在访问点存 (隐藏类/形状, 偏移或地址)。同类对象命中直接取偏移；类变则更新或退化为多态/查表。类型反馈于此收集。

## 三、形式化 / 数学基础
IC 状态机：monomorphic $(C,a)$ → 命中直接用 $a$；新类 $C'$ → polymorphic $\{(C,a),(C',a')\}$；超多类 → megamorphic 查表。
命中代价 $O(1)$，巨态回退 $O(\log n)$ 哈希。

## 四、代码实现
```c
// 访问点缓存: 存 shape 与偏移
if (obj->shape == ic.shape) {
    return obj->props[ic.offset];   // 单态命中
} else {
    ic = lookup_and_update(obj, name);  // 更新/退化
}
```

## 五、与其他技术对比
- 单态 IC：最快（近直接访问）。
- 多态 IC：仍较快。
- 巨态：等同查表，应尽量避免。
- 与 vtable 关系：静态语言用 vtable，动态语言用 IC。

## 六、常见误区
1. 混用多种 shape 致巨态变慢。
2. 以为 IC 只在方法调用（属性访问也用）。
3. 隐藏类频繁变化破坏 IC。

## 九、演进与趋势
多态 IC 容量增大、基于 IC 的类型反馈驱动编译、以及形状稳定化分析。

## 十、小结
内联缓存是动态语言性能核心：在访问点缓存 shape→偏移，单态时近原生；保持形状稳定是高速关键。
