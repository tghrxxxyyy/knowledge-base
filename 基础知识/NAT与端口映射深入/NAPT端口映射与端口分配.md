# NAPT端口映射与端口分配

> 对应 RFC 3022（Traditional IP NAPT）、RFC 4787（UDP 的 NAT 行为要求）、RFC 5382（TCP 的 NAT 行为要求）、RFC 5508（ICMP 要求），以及 RFC 6056（传输层端口随机化建议）。

## 一、背景与挑战
NAPT 的复用能力完全建立在「为一堆内部会话分配不冲突的外部端口」这件事上。端口分配策略决定三件事：**并发能力**（端口池多大、能否及时回收，决定能同时承载多少会话）；**穿透成功率**（外部端口是否与目标相关、是否可预测，决定 P2P 打洞能否成功）；**安全性与可溯源性**（端口是否可预测影响离线攻击难度，CGNAT 下端口分配是否可记录决定能否溯源到用户）。
不同实现（Linux conntrack、家用路由器、CGNAT、云网关）在这三点上差异巨大，导致同一套 P2P/VoIP 代码在不同网络下表现完全不同。RFC 4787/5382 系列正是为此建立「可判定的行为要求」。

## 二、核心原理
**分配时机与流程**：出站首包到达时 conntrack 创建表项，NAT 层执行端口分配——先看映射是否已存在（同一内网端点访问同一目标的表项，存在则复用）；再尝试**端口保持（port preservation）**，即内网端口在外部端口池可用且符合策略时优先使用同一端口号（这使协议内的端口假设更容易成立，也减少应用层不兼容）；否则从端口池按策略选取空闲端口；随后建立映射、改写源地址与端口并重算校验和；表项携带超时与状态，由 conntrack 定时器回收。
**映射独立性与过滤独立性**是描述 NAT 行为的两个正交维度。映射维度：**EIM**（端点无关映射，同一内网端点访问任意目标都使用同一外部端口，是锥形的定义性特征）、**ADM**（地址相关映射，外部端口依赖目标地址）、**APDM**（地址与端口相关映射，即对称 NAT）。过滤维度：**EIF**（任何外部源都能入站到已存在的映射）、**ADF**（只允许曾作为出站目的地址的外部源入站）、**APDF**（只允许曾作为出站目的 IP 与端口的外部端点入站）。
**端口保持与奇偶性/连续性**：RFC 4787 要求 NAT 在可能时保持端口奇偶性并尽量保持连续性，因为某些协议（RTP/RTCP 约定奇数/偶数端口对）依赖这一性质。无法保持时，应用需要有能力从信令中获知实际端口——这正是 STUN/ICE 存在的价值。
**超时参数**决定映射寿命：TCP `ESTABLISHED` 极长（数量级为天，因为有明确连接状态）、TCP `SYN_SENT`/`FIN_WAIT`/`TIME_WAIT`/`CLOSE` 较短以加快回收、UDP 无连接状态只有空闲超时（默认数量级为几十秒，另有识别到连续 UDP 流后的更长变体）、ICMP 独立短超时。具体默认值随内核版本与发行版配置变化，以官方文档与实际系统为准。
**超时与保活的相互作用**是生产环境最常见的故障源：应用依赖 TCP 长连接，但链路中间 NAT 的空闲超时可能远短于 TCP keepalive 间隔，于是「连接在 NAT 上被静默删除」而两端仍以为连接存在，表现为「空闲一段时间后首次请求超时或失败」。判据是 $T_{keepalive} > T_{idle} \Rightarrow$ 映射必然被提前回收。正确做法是应用层心跳（典型 15–30 秒）或启用 TCP keepalive 并调短间隔。
**端口随机化**：RFC 6056 建议对客户端源端口做随机化而非顺序递增，以抵御「离线攻击者预测端口加猜测序列号」的注入攻击。这与 NAT 的分配策略相互影响——若 NAT 顺序可预测地分配端口，会削弱整体抗预测性，因此现代实现需要在「保持兼容性」与「引入随机性」之间显式权衡。
**CGNAT 与日志**：运营商级 NAT 让大量用户共享同一公网 IP 的端口区间，必须记录「时间戳 + 公网 IP + 端口区间 + 内网标识」以满足法律与运维溯源要求（RFC 6888 有专门章节）。端口分配的粒度直接影响日志体量：**端口块分配**把每用户分配一段连续端口并定期轮换，大幅降低日志量，是 CGNAT 的常用折中。

## 三、形式化与数学基础
设端口池大小 $P$、已用映射数 $U$（每协议独立计数），则一次新分配成功的概率为

$$ \Pr(\text{成功}) = \frac{P - U}{P} $$

若采用端口保持策略，还需满足内网端口 $p_{priv}$ 未被占用且符合策略：

$$ \Pr(\text{保持成功}) = \frac{1}{P} \cdot \left[ p_{priv} \notin used \right] \cdot \left[ r \le \rho \right] $$

其中 $\rho$ 为策略允许的保持概率上限（引入随机性时不会 100% 保持）。映射寿命为

$$ L = \begin{cases} \min(T_{idle},\; T_{keepalive} + \epsilon) & \text{有保活流量} \\ T_{idle} & \text{无流量} \end{cases} $$

端口块分配下的日志压缩率可量化：若每用户分配端口块并每周期 $T_{rot}$ 轮换一次，则单位时间日志条数为 $R_{log} = N_{users} / T_{rot}$，相比「每会话一条」的 $R_{log}' = \lambda_{sessions} \cdot N_{users}$，通常可压缩三到四个数量级。

## 四、代码实现
```bash
# 关键超时参数：决定映射寿命（默认值随版本/发行版变化，以实际系统为准）
sysctl net.netfilter.nf_conntrack_udp_timeout          # UDP 基础空闲超时
sysctl net.netfilter.nf_conntrack_udp_timeout_stream   # 识别为流后的 UDP 超时
sysctl net.netfilter.nf_conntrack_tcp_timeout_established
sysctl net.netfilter.nf_conntrack_tcp_timeout_time_wait
sysctl net.netfilter.nf_conntrack_max                  # 表容量（常先于端口耗尽）
```

```bash
# 限制 NAT 使用的源端口范围，便于与防火墙策略/日志对齐
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE --to-ports 20000-32000

conntrack -L 2>/dev/null | head           # 一张表就是 NAT 的映射表
conntrack -L --orig-src 192.168.1.10 2>/dev/null
conntrack -E -p udp 2>/dev/null           # 实时追踪映射创建与销毁
cat /proc/net/stat/nf_conntrack           # 端口/表项耗尽相关的丢弃计数
```

```c
/* 概念性伪码：conntrack 中的端口分配尝试顺序 */
static int alloc_external_port(struct nf_conn *ct, u16 *sport) {
    /* 1. 端口保持：内网端口未被占用且策略允许时直接复用 */
    if (policy_allows_preservation() && port_free(ct->orig_port))
        return use_port(ct, ct->orig_port);

    /* 2. 依据 RFC 6056 思想在范围内随机选取，避免可预测分配 */
    for (int i = 0; i < MAX_PROBES; i++) {
        u16 cand = random_in_range(port_min, port_max);
        if (port_free(cand))
            return use_port(ct, cand);
    }
    return -ENOMEM;        /* 端口耗尽：表现为新建连接失败或被丢弃 */
}

/* 表项超时：由状态与流量共同刷新 */
static void refresh_timeout(struct nf_conn *ct) {
    if (ct->proto.tcp.state == TCP_CONNTRACK_ESTABLISHED)
        mod_timer(&ct->timeout, jiffies + tcp_established_timeout);
    else
        mod_timer(&ct->timeout, jiffies + udp_timeout);   /* UDP 仅靠空闲计时 */
}
```

应用侧的对策是把保活间隔压到 NAT 空闲超时以下（留足余量并加抖动）：典型做法是每 15–30 秒发送一次最小心跳，既刷新两端 NAT 的映射，也刷新过滤许可集合。

## 五、与其他技术对比
| 维度 | 动态 NAPT | 静态端口转发 | UPnP/PCP 映射 | CGNAT | IPv6 直连 |
| --- | --- | --- | --- | --- | --- |
| 分配时机 | 出站首包自动分配 | 管理面预配置 | 主机主动申请 | 出站首包，多级 | 无需分配 |
| 外部端口稳定性 | 随超时变化，可能保持 | 固定 | 申请期内固定 | 更易变化 | 地址本身稳定 |
| 入站主动可达 | 需已有映射 | 是 | 是（需续约） | 极难（多层 NAT） | 是（无状态过滤下） |
| 并发上限 | 端口池与表容量 | 由配置条数决定 | 由网关端口池 | 受日志与端口块约束 | 不受此限 |
| 打洞友好度 | 取决于映射独立性（EIM 友好） | 不适用 | 友好 | 常为 APDM，困难 | 不适用 |

与静态转发相比，NAPT 的优势是「零配置、自动回收」，缺点是不可预测（端口会变、会超时）。与 UPnP/PCP 相比，NAPT 不依赖网关额外能力但无法保证入站可达。与 CGNAT 相比，单级 NAPT 至少还有可推理空间，而 CGNAT 叠加第二层转换，使地址相关映射与端口块轮换成为常态。

## 六、常见误区
- **误区一：以为外部端口等于内部端口。** NAT 通常重新分配以避免冲突；端口保持只是「尽量」。协议若假设端口不变，必须通过 STUN 或信令交换获知实际端口。
- **误区二：认为映射永久有效。** 空闲超时后会被回收，UDP 尤其短，表现为「空闲一段时间后连接失效」或「NAT 类型看起来变了」。
- **误区三：用 TCP keepalive 默认值做保活。** 默认间隔（小时量级）远大于 NAT 空闲超时（分钟量级），无法阻止映射回收，必须显式调短或使用应用层心跳。
- **误区四：忽略端口耗尽。** 并发会话足够多（或端口范围被限制得很窄）时新分配会失败；排查应同时看 `nf_conntrack_max` 与端口范围约束，而不只看带宽。
- **误区五：以为分配策略与安全无关。** 顺序可预测的端口分配会削弱序列号随机化的效果，使离线注入攻击更可行（RFC 6056 明确建议随机化）。
- **误区六：在 CGNAT 场景假设行为可控。** CGNAT 常为地址端口相关映射且带端口块轮换，P2P 方案必须把「打洞失败即用中继」作为一等路径。

## 七、与开源书·权威来源对应
- RFC 3022 描述端口重写与校验和处理，是 NAPT 映射机制的原始定义。
- RFC 4787 规定 UDP 的 NAT 行为要求，给出 EIM/ADM/APDM 与 EIF/ADF/APDF 术语、端口保持与映射复用判定方法。
- RFC 5382 给出 TCP 的 NAT 行为要求，含超时建议与连接跟踪语义；RFC 5508 补充 ICMP 要求。
- RFC 6056 建议传输层源端口随机化算法，是理解「NAT 端口分配为何要随机」的权威依据。
- RFC 6888 要求 CGNAT 记录端口分配以满足溯源，并讨论端口块分配的日志压缩思路；Stevens《TCP/IP Illustrated》关于 TCP 状态机与 `TIME_WAIT` 的章节解释了 TCP 与 UDP 超时差异的根源。

## 八、面试题
1. **为什么 UDP 的映射超时比 TCP 短得多？**
   要点：UDP 无连接状态，NAT 无法感知会话结束，只能靠空闲超时回收；TCP 有明确状态机，可准确判断并及时回收，同时把仍在传输的长连接保留很久。
2. **端口保持（port preservation）的利弊？**
   要点：利在于兼容依赖端口号的协议（RTP 奇偶对、部分 P2P 与游戏协议）并减少应用不兼容；弊在于降低随机性、可能暴露内网端口使用模式，且端口冲突时不可用。
3. **映射独立性与过滤独立性各指什么？如何影响打洞？**
   要点：映射独立性决定同一内网端点在访问不同目标时是否复用同一外部端口（EIM 复用、APDM 不复用）；过滤独立性决定哪些外部源可入站（EIF 全部、APDF 仅曾通信的对端）。EIM 是打洞前提。
4. **端口耗尽的典型征兆与排查路径？**
   要点：现象是新建连接偶发失败、表项被丢弃、日志出现分配失败；应同时检查端口范围限制（`--to-ports`）、`nf_conntrack_max`、超时是否过长以及是否存在连接泄漏。
5. **CGNAT 为什么必须记录端口分配日志？**
   要点：多用户共享公网 IP，只有「时间 + 公网 IP + 端口（区间）+ 内网标识」四要素齐全才能把某条外网观测到的连接唯一映射到个人；端口块分配与轮换可把日志量压缩几个数量级。

## 九、演进与趋势
NAPT 端口分配的演进围绕「可预测性」「可观测性」「可溯源性」三条线展开。行为标准化方面，RFC 4787/5382/5508 把「NAT 应该怎么做」从经验变成要求；ICE 则干脆不再依赖分类，而是枚举候选并实测连通性，把不可预测性转化为运行时测量。分配策略方面，RFC 6056 的随机化思想同时影响客户端源端口与 NAT 分配端口，而端口保持被保留以兼容旧协议——这是被明确承认的折中。CGNAT 方面，端口块分配与结构化日志成为运营商标配。观测能力上，`conntrack -E` 事件流与 `/proc/net/stat/nf_conntrack` 计数器让映射生命周期可被真实测量，取代了「猜测路由器行为」。长期看，IPv6 的端到端可达性会削弱「端口分配」这一瓶颈的存在意义。

## 十、小结
NAPT 的端口分配是会话复用的核心：出站首包触发分配，优先尝试端口保持，否则从池中（宜随机）选取，并受端口池大小、`conntrack_max` 与超时参数共同约束；映射寿命由空闲超时决定，因此保活间隔必须显著小于 UDP 空闲超时。映射独立性（EIM/ADM/APDM）与过滤独立性（EIF/ADF/APDF）是描述 NAT 行为的两个正交维度，前者决定打洞能否成功，后者决定入站许可范围。掌握这组术语与超时、端口两个量化约束，就能诊断「空闲后连接失效」「新建连接偶发失败」「打洞在某些网络下必然失败」这三类最常见问题。
