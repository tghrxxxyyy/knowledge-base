# 锥形NAT与对称NAT差异

> 对应 RFC 3489 (STUN, 旧分类) 与 RFC 5389 更新术语。

## 一、背景与挑战
NAT 行为差异直接影响穿透难度。按「相同内网地址端口访问不同外部目标时，外部端口是否变化」可区分锥形与对称型，这决定了 P2P 打洞是否可行。

## 二、核心原理
锥形 NAT（Cone）对同一个内网 (IP, port) 不论访问哪个外部目标，都复用同一外部 (IP, port)，并按入站过滤规则细分完全锥型、受限锥型、端口受限锥型。对称 NAT 则为每个不同外部目标分配不同外部端口，使反射地址不可预测，打洞几乎必然失败需 TURN 中继。

## 三、形式化与数学基础
设内部端点 $i$，目标 $d_1, d_2$：
- 锥形：$\text{ext}(i, d_1) = \text{ext}(i, d_2)$
- 对称：$\text{ext}(i, d_1) \ne \text{ext}(i, d_2)$ 当 $d_1 \ne d_2$

入站过滤（以受限锥型为例）要求：仅允许曾收到过报文的内部映射对应的外部源地址入站。

## 四、代码实现
通过 STUN 两次请求不同服务器判断类型：
```python
_, e1, p1 = stun.get_ip_info(stun_server_a)
_, e2, p2 = stun.get_ip_info(stun_server_b)
if p1 != p2:
    print('对称型 NAT')
else:
    print('锥形 NAT')
```

## 五、与其他技术对比
完全锥型最易穿透（任意外部可入站），端口受限锥型需先出站；对称型最难，需中继。UPnP 映射可绕过差异但依赖路由器支持。

## 六、常见误区
误区一是把「锥形」理解为更安全，实际完全锥型允许任意入站更危险。误区二是以为所有家用路由器都是锥形，不少 CGNAT 是对称的。

## 七、与开源书/权威来源对应
RFC 3489 早期分类 NAT 类型；RFC 5389 更新并弱化类型术语，强调行为；WebRTC/ICE 实践中按行为处理。

## 八、面试题
问：为什么对称 NAT 难以打洞？答：相同内网端点访问不同目标的外部端口不同，对端无法预知应发包到的外部端口，连通性检查难以命中。

## 九、演进与趋势
现代 ICE 实现不再强依赖 NAT 类型，而是枚举候选并实测连通性；IPv6 普及后端到端直连免去类型困扰。

## 十、小结
锥形与对称 NAT 的核心区别在于是否按目标复用外部端口，对称型因地址不可预测使打洞困难，往往需要 TURN 中继兜底。
