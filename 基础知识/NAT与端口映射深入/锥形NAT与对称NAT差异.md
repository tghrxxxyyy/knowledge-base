# 锥形NAT与对称NAT差异

> 对应 RFC 3489（STUN 早期的 NAT 类型分类）、RFC 5389 / RFC 8489（STUN 更新版本对分类算法的修订）、RFC 4787（EIM/ADM/APDM 与 EIF/ADF/APDF 术语），以及 RFC 8445（ICE）。

## 一、背景与挑战
「这个 NAT 能不能打洞」是 P2P 与实时通信中最常见的判断需求，而答案取决于一条极简的判据：**同一个内网端点访问不同的外部目标时，NAT 分配的外部端口是否保持不变？**
保持不变则对端只要能猜到或从信令中获知这个稳定端口，就能把包打进来，打洞可行；每次都变则对端无法预知该往哪个端口发包，打洞基本失败，只能靠中继。这一差异把 NAT 分成「锥形」（Cone）与「对称」（Symmetric）两大类，并按**入站过滤规则**进一步细分为四种经典类型。需要注意：RFC 3489 的分类算法在 RFC 5389 之后**已被弱化甚至移除**（因其在多 IP 服务器、多网卡与地址相关映射的现实中不可靠），现代实践改用 RFC 4787 的两个维度描述行为，并由 ICE 通过实测连通性替代静态分类。

## 二、核心原理
**映射维度**决定打洞可行性：**EIM**（端点无关映射，对外部目标无关，同一内网端点始终使用同一外部端口，是锥形的定义性特征）、**ADM**（外部端口依赖目标 IP）、**APDM**（外部端口同时依赖目标 IP 与端口，即典型对称 NAT）。
**过滤维度**决定谁能打进来：**EIF**（任何外部源都能向已存在的映射发包）、**ADF**（只允许曾作为出站目的地址的外部 IP 发包）、**APDF**（只允许曾作为出站目的 IP 与端口的外部端点发包）。
**四种经典类型**由两者组合而成：完全锥形（EIM + EIF，知道映射端点即可打入）、受限锥形（EIM + ADF，仅该 IP 曾被访问过才可打入）、端口受限锥形（EIM + APDF，仅该 IP:port 曾被访问过才可打入）、对称（APDM 或 ADM，通常配 APDF，需预知端口，一般不能打入）。
**打洞的时序要求**：本质是让**双方 NAT 同时**存在「出站映射到对端」与「入站许可来自对端」。锥形 NAT 是 EIM，一旦任意一方曾向对端发过包，其对端映射端点就固定且可复用；对称 NAT 下每次向新目标发包都分配新端口，于是：A 为对称、B 为锥形时，B 只能打到 A 的「B 见过的那个」端口，需要极精确的同步与运气；双方都为对称时打洞几乎必然失败。**UPnP/PCP 是绕过类型差异的另一条路**：直接向网关申请固定映射，把「对称」变成可预测状态，前提是网关支持且未被策略禁用。
**RFC 5389 之后的处理方式变化**值得一提：早期（RFC 3489）STUN 内置了「跑多个测试判定四种类型」的算法；后来发现它给出的结论不一致甚至错误，因此 RFC 5389 明确表示不应依赖该算法做分类，转而强调「测出映射与过滤行为」这一更本质的目标。ICE 则彻底放弃分类：直接枚举候选并实测连通性，对任何 NAT 类型都无需先验假设。

## 三、形式化与数学基础
设内部端点 $i$，外部目标 $d_1 \ne d_2$，映射函数为 $\mathrm{ext}(i, d)$：

$$ \text{锥形（EIM）}:\quad \mathrm{ext}(i, d_1) = \mathrm{ext}(i, d_2) $$
$$ \text{对称（ADM/APDM）}:\quad \mathrm{ext}(i, d_1) \ne \mathrm{ext}(i, d_2) $$

过滤规则可写成入站许可集合：

$$ allow(i) = \begin{cases} \mathbb{U} & \text{EIF（任意外部源）} \\ \left\{ a \;\middle|\; i\ \text{曾向 } a \text{ 发包}\right\} & \text{ADF（仅地址）} \\ \left\{ (a, p) \;\middle|\; i\ \text{曾向 } (a,p) \text{ 发包}\right\} & \text{APDF（地址 + 端口）} \end{cases} $$

打洞成功的必要条件可表述为存在时间窗口 $[t, t+\Delta]$ 使得 $\mathrm{ext}(i_A, i_B)$ 在 A 侧已建表、$\mathrm{ext}(i_B, i_A)$ 在 B 侧已建表，且 $i_B \in allow_A$、$i_A \in allow_B$。锥形下 $\mathrm{ext}(i_A, i_B)$ 与目标无关，条件一旦成立即长期保持；对称下每次尝试目标变化都会改变 $\mathrm{ext}$，满足区间极窄。
**端口预测攻击**的量化：若对端外部端口在 $N$ 个候选值上近似均匀随机，己方从 $k$ 个源端口向对端 $m$ 个候选端口探测，命中概率约为

$$ \Pr(\text{hit}) \approx 1 - \left(1 - \frac{1}{N}\right)^{k \cdot m} \approx \frac{k \cdot m}{N} \quad (k \cdot m \ll N) $$

当 $N \approx 2^{16}$ 时即使 $k = m = 256$ 命中概率也仅约 1；要达到较高命中率需上万次探测，代价与误报都不可接受。此外若实现顺序递增分配端口，$N$ 的有效熵远小于 $2^{16}$，预测难度骤降——RFC 6056 的随机化建议正是为此。

## 四、代码实现
```python
# 经典判据：向两个「不同公网地址」的 STUN 服务器发 Binding 请求，比较回填的映射端口。
# 端口相同 -> 端点无关映射（锥形）；不同 -> 地址相关映射（对称）。
import stun

def probe(server):
    return stun.get_ip_info(stun_server=server)   # (nat_type_guess, ip, port)

def mapping_is_independent(a="stun.a.example:3478", b="stun.b.example:3478"):
    _, ip_a, port_a = probe(a)
    _, ip_b, port_b = probe(b)
    if port_a is None or port_b is None or ip_a != ip_b:
        return None                  # 探测失败或多出口：结论不可比，不能下判断
    return port_a == port_b          # True: EIM；False: ADM/APDM
    # 过滤行为需第三方配合：从「未通信过的 IP:port」向你刚建立的映射发包
    #   收到 -> EIF；仅换地址可收 -> ADF；换端口即被丢 -> APDF
```

```python
# 打洞：双方几乎同时向对方的映射端点发包，互相成全彼此的映射与过滤许可
import socket
import time

def punch(sock, peer, rounds=12, interval=0.25):
    got = []
    sock.setblocking(False)
    for _ in range(rounds):
        try:
            sock.sendto(b"PUNCH", peer)      # 本端 NAT 因此建立"向对端"的映射
        except OSError:
            pass
        try:
            while True:
                data, addr = sock.recvfrom(2048)
                got.append((addr, data))     # 收到即表示对端的打洞同时命中
        except OSError:
            pass
        time.sleep(interval)
    return got
    # 对称 NAT 下常见结果：双方都发出去了，但都没收到 -> 需 TURN 兜底
```

## 五、与其他技术对比
| 维度 | 完全锥形 | 受限锥形 | 端口受限锥形 | 对称 NAT | UPnP/PCP 映射 |
| --- | --- | --- | --- | --- | --- |
| 映射独立性 | EIM | EIM | EIM | ADM / APDM | 显式固定（等效 EIM） |
| 过滤独立性 | EIF | ADF | APDF | 通常 APDF | 由映射决定 |
| 任意外部源可入站 | 是（知端点即可） | 否（需曾通信） | 否（需曾通信到端口） | 否 | 由申请范围决定 |
| 打洞难度 | 低 | 中（需同步发包） | 中（需同步发包） | 高（基本失败） | 低（依赖网关支持） |
| 安全含义 | 最弱（易被直接接入） | 中 | 较强 | 较强 | 取决于实现的认证 |
| 常见场景 | 部分家用路由器 | 部分家用路由器 | 常见家用路由器 | CGNAT、企业防火墙 | 家用路由器（若开启） |

常见的误解是把「锥形」等同于「更好或更安全」。恰恰相反：**完全锥形**允许任何知道映射端点的外部主机直接接入，攻击面最大；对称 NAT 因端口不可预测，反倒更难被外部利用。技术上的「好」取决于目标——对 P2P 而言锥形友好，对安全而言对称更严。

## 六、常见误区
- **误区一：把「锥形」理解为更安全。** 完全锥形（EIM + EIF）意味着任何外部源都可向已知映射发包，是最易被利用的一类；对称 NAT 的端口不可预测性反而更难被外部利用。
- **误区二：以为所有家用路由器都是锥形。** 大量家用路由器与几乎所有 CGNAT 会表现为地址相关映射，行为还随固件版本变化。
- **误区三：依赖 RFC 3489 的四类型算法做判定。** 它在多 IP 服务器、多网卡、地址相关映射的现实下会给出不一致结论，RFC 5389 之后已不建议依赖。
- **误区四：用两个不同端口的 STUN 服务器做「对称判定」。** 判据必须比较「不同目标地址」下的映射端点；若两台服务器共享同一 IP 则无法区分 EIM 与 APDM，且必须确认两次出口地址一致。
- **误区五：以为打洞失败就是代码 bug。** 在对称 NAT 或严格企业防火墙下打洞失败是**规范允许的正常结果**，应准备 relay 候选并让 ICE 自动降级，而非反复重试。
- **误区六：忽略映射端点的有效期。** UDP 空闲超时后映射会被回收，后续发包会新建映射并可能换端口；打洞或直连方案必须包含保活。

## 七、与开源书·权威来源对应
- RFC 3489 给出 STUN 早期的 NAT 四类型分类与对应探测算法，是「锥形/对称」术语的历史来源。
- RFC 5389（及其继任 RFC 8489）修订 STUN，弱化类型术语、强调映射与过滤行为的测量，并指出原分类算法不可靠。
- RFC 4787 定义 **EIM/ADM/APDM** 与 **EIF/ADF/APDF** 六个术语，是描述 NAT 行为最严谨的框架（RFC 5382 给出 TCP 侧对应要求）。
- RFC 8445 定义 ICE 的候选收集、连通性检查与 nomination，说明现代实现为何用「实测」替代「分类」。
- Stevens《TCP/IP Illustrated》关于 UDP/TCP 与过滤的讨论可解释过滤许可集合的底层行为；Ross《Computer Networking: A Top-Down Approach》对 NAT 与 P2P 的讲解提供直觉模型。

## 八、面试题
1. **为什么对称 NAT 难以打洞？**
   要点：同一内网端点访问不同目标会得到不同外部端口（APDM），对端无法预知应发包到的端口；双方需要精确同步的时序与端口猜测，成功率极低。
2. **完全锥形与端口受限锥形的区别是什么？**
   要点：两者映射相同（EIM，外部端口稳定），差别在过滤规则——完全锥形允许任何外部源入站，端口受限锥形只允许曾与该内网端点通信过的「IP:port」入站。
3. **为什么 RFC 5389 之后不再推荐用 STUN 判定 NAT 类型？**
   要点：该算法假设服务器地址不同即代表目标不同且 NAT 单一出口，实际存在多 IP 服务器、多网卡、地址相关映射等情形，结论不可靠。
4. **如何判断某 NAT 是否为端点无关映射？**
   要点：从同一内网端点向两个**不同 IP 的 STUN 服务器**各发一次 Binding 请求，比较回填的映射端口；相同为 EIM，不同为 ADM/APDM。必须确认两次出口公网地址一致，否则结论无效。
5. **面对对称 NAT，工程上有哪些可行策略？**
   要点：优先 TURN 中继兜底；尝试 UPnP/PCP 申请固定映射；在受控网络中配置静态端口转发；以及在协议层用连接 ID 与路径验证承受地址变化（如 QUIC）。

## 九、演进与趋势
趋势是从「静态分类」走向「动态测量」：RFC 3489 的四类型分类因判定不可靠被弱化，RFC 4787 的独立性框架提供可测维度，ICE 则把问题转化为「枚举候选 + 实测连通性 + 失败即降级」，因此新出现的 NAT 行为（如 CGNAT 的端口块轮换）不会破坏已有穿透逻辑。另一条趋势是「让网关配合」：PCP 提供带认证的显式映射，把不可预测的自动分配替换为契约式映射。长期看，IPv6 端到端可达性回归会削弱「类型」这一概念的重要性，但在 CGNAT 与双栈长期共存的环境下，映射与过滤行为仍将是穿透设计的第一手事实依据。

## 十、小结
锥形与对称 NAT 的核心判据只有一条：同一内网端点访问不同外部目标时，外部端口是否复用。锥形（EIM）下端口稳定，配合不同过滤规则（EIF/ADF/APDF）形成完全锥形、受限锥形与端口受限锥形；对称 NAT（ADM/APDM）下端口随目标变化，使打洞基本不可行。工程上应放弃「判定类型」的思路，转而测量映射与过滤行为、让 ICE 通过实测连通性自动决策，并把 TURN 中继作为一等公民；网关可配合时用 UPnP/PCP 取得确定性映射。最后要纠正一个直觉错误：锥形并非「更安全」，完全锥形反而是最容易被外部接入的一类。
