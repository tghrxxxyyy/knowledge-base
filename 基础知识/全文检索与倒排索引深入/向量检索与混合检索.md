# 向量检索与混合检索

> 对应 Kleppmann《Designing Data-Intensive Applications》第 3 章（检索演进背景），以及 Vonng/ddia 第 3 章。

## 一、背景与挑战
语义检索（如“意思相近”）靠关键词倒排难以覆盖。向量检索把文本/图像编码为稠密向量，按近邻搜索（ANN）找语义相似项；混合检索结合稀疏（BM25）与稠密（向量）以兼顾召回与精度。

## 二、核心原理
用嵌入模型把文档/查询映射为向量，索引用 ANN（HNSW、IVF-PQ 等）近似最近邻搜索。混合检索对 BM25 与向量分数分别召回再融合（如 RRF 倒数排名融合），取长补短。

## 三、形式化与数学基础
余弦相似：
$$ sim(a,b) = \frac{a \cdot b}{\|a\|\|b\|} $$
HNSW 查询复杂度近似：
$$ O(\log N) $$
RRF 融合：
$$ score(d) = \sum_{r \in runs} \frac{1}{k + rank_r(d)} $$
（$k$ 为常数，常 60）

## 四、代码实现
```python
# RRF 倒数排名融合（仅示意）
def rrf(runs, k=60):
    s = {}
    for run in runs:                    # runs: 各检索返回的列表
        for rank, doc in enumerate(run):
            s[doc] = s.get(doc, 0) + 1.0 / (k + rank + 1)
    return sorted(s, key=s.get, reverse=True)
```

## 五、与其他技术对比
BM25 精准匹配词但无语义；向量检索语义好但可能漏精确词、且需嵌入质量。混合检索在 RAG/搜索中成为主流。

## 六、常见误区
1) 认为向量检索取代关键词——常需混合。
2) 忽略嵌入模型领域适配。
3) 误以为 ANN 结果是精确最近邻——是近似。

## 十、小结
