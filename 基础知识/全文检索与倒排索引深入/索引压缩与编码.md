# 索引压缩与编码

> 对应 Chang et al. 2006（SSTable 压缩相关），以及 Vonng/ddia 第 3 章（存储压缩讨论）。

## 一、背景与挑战
倒排索引常比原文本还大（尤其包含位置与词频）。压缩倒排列表与词典可显著降低内存/磁盘占用并提升 IO 效率，且现代 CPU 解压快于读未压缩数据。

## 二、核心原理
- 差值编码（delta）：docId 有序，存相邻差值而非绝对值。
- 可变字节（VByte）/ Simple-8b / PForDelta：用小字节数编码小差值。
- 词典压缩：前端编码（front coding）共享前缀、FST（有限状态转换器）紧凑存储。

## 三、形式化与数学基础
有序 docId 序列 $d_1 < d_2 < \dots$，差值：
$$ \Delta_i = d_i - d_{i-1} $$
平均码长由熵决定，VByte 编码 $x$ 需：
$$ \lceil \frac{\lfloor \log_2 x \rfloor + 1}{7} \rceil \text{ bytes} $$
压缩后 IO 减少比：
$$ r = \frac{Size_{raw}}{Size_{compressed}} $$

## 四、代码实现
```python
# 差值编码（仅示意）
def delta_encode(ids):
    out = []
    prev = 0
    for i in ids:
        out.append(i - prev)   # 存差值
        prev = i
    return out

def vbyte_write(n, buf):
    while True:
        b = n & 0x7f
        n >>= 7
        buf.append(b | (0x80 if n else 0))  # 高位为续位
        if not n: break
```

## 五、与其他技术对比
无损通用压缩（gzip）对已结构化差值序列收益有限；专用整数编码（PForDelta）更快更紧凑。列式存储同理用字典+RLE。

## 六、常见误区
1) 认为压缩一定拖慢——解压常快于 IO。
2) 忽略差值后再压缩才有效。
3) 误以为词典压缩不重要——它占大量内存。

## 十、小结
倒排索引压缩以“差值 + 可变长编码 + 词典共享”大幅降占用、提 IO，是检索系统可扩展的关键。
