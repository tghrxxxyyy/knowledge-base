# 倒排索引结构

> 对应 Vonng/ddia 第 3 章（全文检索与倒排索引讨论），以及 Kleppmann《Designing Data-Intensive Applications》第 3 章。

## 一、背景与挑战
关系索引适合等值/范围，但“包含某词的所有文档”需要扫描全表。倒排索引（Inverted Index）以词项为键、文档列表为值，把全文检索变为查表 + 合并，是搜索引擎的基石。

## 二、核心原理
索引由词典（term dictionary）与倒排列表（postings）组成：每个词项指向出现它的文档 ID 列表（含词频、位置以支撑短语与 proximity 查询）。检索时把查询词对应的 posting 列表取交集/并集并排序。

## 三、形式化与数学基础
布尔查询 AND 代价：
$$ Cost = \sum_t |postings(t)| $$
用 skip pointer 在有序 docId 列表跳进，交集复杂度：
$$ O(|A| + |B|) \ (\text{有序合并}) $$
文档频率 $df(t)$ 与词项频率 $tf(t,d)$ 用于后续打分。

## 四、代码实现
```python
# 倒排列表有序合并（AND 查询，仅示意）
def intersect(a, b):
    i = j = 0
    out = []
    while i < len(a) and j < len(b):
        if a[i] == b[j]:
            out.append(a[i]); i += 1; j += 1
        elif a[i] < b[j]: i += 1
        else: j += 1
    return out
```

## 五、与其他技术对比
正排索引（doc→terms）利于取文档内容；倒排（term→docs）利于检索。B+ 树可做等值但无法高效“包含词”查询；倒排专为全文。

## 六、常见误区
1) 认为倒排只存 docId——位置信息支撑短语。
2) 忽略词典内存占用。
3) 误以为倒排能直接排序——需打分层。

## 十、小结
