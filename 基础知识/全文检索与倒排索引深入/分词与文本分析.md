# 分词与文本分析

> 对应 Kleppmann《Designing Data-Intensive Applications》第 3 章（全文检索预处理），以及 Vonng/ddia 第 3 章。

## 一、背景与挑战
原始文本需切分为词项并归一化，才能建立一致的倒排索引。分析（analysis）的质量直接决定召回与精度：同一词的不同形态、大小写、停用词如何处理。

## 二、核心原理
分析管线：字符过滤 → 分词（tokenizer，如按空白/ICU 边界）→ 词项过滤（小写化、去停用词、词干提取 stemmer、同义词扩展）。中英文差异大：英文按空格、中文需分词器（jieba 等）。同一 analyzer 须用于索引与查询以保持一致。

## 三、形式化与数学基础
词项集合映射：
$$ analyze(doc) = \{ t_1, t_2, \dots \} $$
词干化函数 $stem: \Sigma^* \to \Sigma^*$ 使：
$$ stem("running") = stem("runs") = "run" $$
倒排构建为多重集到 docId 列表的映射。

## 四、代码实现
```python
# 简单分词+小写+去停用词（仅示意）
STOP = {"the","a","is"}
def analyze(text):
    toks = []
    for w in text.lower().split():        # 小写化 + 分词
        w = w.strip(".,")
        if w and w not in STOP:
            toks.append(w)
    return toks
```

## 五、与其他技术对比
按字符 n-gram（如 bigram）对中文友好但索引大；按词分词更紧凑但依赖词典。大小写/词干处理影响召回；过度归一化会损精度。

## 六、常见误区
1) 索引与查询用不同 analyzer——召回错位。
2) 过度去停用词丢失语义。
3) 中文直接按字切——词项爆炸。
