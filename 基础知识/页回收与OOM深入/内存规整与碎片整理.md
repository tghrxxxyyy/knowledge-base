> 对应 Linux 内核 Documentation（admin-guide/mm/transhuge.rst）与 Tanenbaum《Modern Operating Systems》。

## 一、背景与挑战
长期运行后，空闲页虽总量充足，却分散为零散小片，无法满足大块连续分配（如巨页 hugepage、DMA 缓冲）。挑战是在不丢弃用户数据的前提下，把已用页「迁移」以拼出连续空闲区，且不能长时间阻塞。

## 二、核心原理
内存规整（compaction）把可移动页从「空闲区边界」向一端迁移，使空闲页在向另一端聚集，从而合成连续大块。它识别页的可移动性：文件页、匿名页（借助 migration entry）大多可迁移，而内核钉住页（kmalloc、pinned）不可迁移。kcompactd 内核线程与直接规整路径协同工作，类似 kswapd 的水线机制。

## 三、形式化与数学基础
设内存被划分为可移动（M）与不可移动（U）两类。规整目标是最大化最大连续空闲块长度 L_max。迁移成本近似：
```
cost ≈ Σ_{p ∈ moved} (copy_page(p) + fixup_pte(p))
```
其中 fixup_pte 包含更新页表与 rmap 的开销。最优不可行，内核用「从两端扫描、相遇时停止」的贪心策略逼近。

## 四、代码实现
```c
// mm/compaction.c（简化）
static int compact_zone(struct zone *zone, struct compact_control *cc)
{
    while ((free_pfn = isolate_freepages(zone, cc)) &&     // 从高端扫空闲
           (migrate_pfn = isolate_migratepages(zone, cc))) { // 从低端扫可移
        migrate_pages(&cc->migratepages, alloc_misplaced,
                      NULL, cc->mode, MR_COMPACTION, NULL);
        if (cc->free_pfn <= cc->migrate_pfn)  // 两指针相遇
            break;
    }
    return COMPACT_SUCCESS;
}
```

## 五、与其他技术对比
- 丢弃回收：释放冷页，但不能保证连续。
- 伙伴系统防碎片：按可移动性分组（migrate types）从源头减少外部碎片。
- 规整：事后治理，把零散变连续，成本高于预防。

## 六、常见误区
- 误区：compaction 会把所有页都搬走。实际只迁移「可移动」页，钉住页原地不动。
- 误区：碎片只影响性能不影响功能。对巨页分配，碎片可造成分配永久失败。

## 十、小结
内存规整通过迁移可移动页把零散空闲拼成连续大块，是支持巨页与设备 DMA 的必要事后治理手段。
