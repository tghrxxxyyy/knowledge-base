# 中断处理

> 对应 OSTEP 第 24 章“中断”与 Linux `kernel/irq`。

## 一、背景与挑战
外设（网卡、磁盘、时钟）需异步通知 CPU 有事件发生。中断打断当前执行流，转入处理程序，要求快进快出、不丢事件。

## 二、核心原理
- 硬件置中断请求线（IRQ），CPU 在完成当前指令后查中断向量表跳转 ISR。
- 上半部（top half）只做最紧急处理（应答、取数据），下半部（bottom half）做耗时工作。
- 中断控制器（如 APIC）做优先级与分发。

## 三、形式化 / 数学基础
中断延迟 $L_{int} = L_{hw} + L_{vect} + L_{mask}$，其中 $L_{mask}$ 为当前关中断最长临界区。吞吐量受最大可承受 IRQ 率约束：$R_{max} < 1 / L_{isr}$。

## 四、代码实现
注册与应答中断（Linux 风格示意）：

```c
irqreturn_t my_isr(int irq, void *dev) {
    u32 status = readl(REG_STATUS);
    if (!(status & INT_PENDING)) return IRQ_NONE;
    writel(INT_ACK, REG_STATUS);     /* 立即应答, 清pending */
    schedule_bottom_half();          /* 其余延后 */
    return IRQ_HANDLED;
}
```

## 五、与其他技术对比
轮询（polling）确定性好但浪费 CPU；中断事件驱动高效但带来延迟抖动与栈压力；现代多用“中断+NAPI 轮询”混合（见网络栈）。

## 六、常见误区
- 在 ISR 里做睡眠/长耗时：上半部不可睡眠。
- 忽略中断嵌套与重入保护。
- 认为中断总能立即响应：受关中断临界区限制。

## 九、演进与趋势
 threaded IRQ 把下半部线程化，PREEMPT_RT 进一步把中断处理转为可抢占线程，降低延迟抖动。

## 十、小结
中断是外设异步通知机制：硬件触发、向量跳转、上半部快答、下半部延后，核心是平衡响应及时性与系统开销。
