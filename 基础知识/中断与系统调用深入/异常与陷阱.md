# 异常与陷阱

> 对应 CSAPP 第 8 章“异常控制流”与 Tanenbaum《Modern Operating Systems》。

## 一、背景与挑战
CPU 执行中遇到非预期或需内核介入的事件： fault（页错误）、trap（有意陷入，如系统调用）、abort（致命）。需区分同步（由指令引起）与异步（中断）。

## 二、核心原理
- 异常分类：中断（异步）、fault（可恢复，如缺页）、trap（有意，如 `int 0x80`/`syscall`）、abort（不可恢复）。
- 异常号索引 IDT/中断描述符表，进入内核态执行 handler，返回可能重试或跳过。

## 三、形式化 / 数学基础
异常向量表 $V[e]$ 给出 handler 入口；fault 返回地址 = 触发指令（重试），trap 返回地址 = 下一条（不重试）。同步性：$\\text{异常由当前指令流引起}$，可精确定位 PC。

## 四、代码实现
x86-64 系统调用入口（trap 示意）：

```asm
syscall:                 # 用户态执行 syscall 指令
    swapgs              # 切换内核 GS
    mov %rsp, %gs:0     # 保存用户栈
    mov %gs:8, %rsp     # 切到内核栈
    call do_syscall     # 按 rax 分派
    iretq               # 返回用户态
```

## 五、与其他技术对比
中断异步于指令流；fault/trap/abort 同步。trap 是进入内核的“故意门”，区别于错误类 fault。

## 六、常见误区
- 混淆中断与异常：前者异步外部，后者同步内部。
- 认为缺页都是错误：多数是正常的按需调页 fault。
- 忽略 fault 返回地址语义（重试 vs 跳过）。

## 九、演进与趋势
x86 由 `int 0x80` 转向 `syscall`/`sysenter` 快速陷阱；向量化处理与用户态陷阱（如 FRED）降低开销。

## 十、小结
异常是同步的控制流变更：fault 可恢复重试、trap 故意陷入、abort 致命，内核借异常向量表统一处理。
