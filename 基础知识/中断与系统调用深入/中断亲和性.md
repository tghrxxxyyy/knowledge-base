# 中断亲和性

> 对应 Linux `irqbalance` 与 `smp_affinity`，以及 Love《Linux Kernel Development》。

## 一、背景与挑战
多核下中断可分发到任意 CPU，但随意分发会破坏缓存局部性、与进程争用同一核。中断亲和性把特定 IRQ 绑定到指定 CPU。

## 二、核心原理
- `/proc/irq/N/smp_affinity` 位掩码决定哪些 CPU 可处理该 IRQ。
- 将网络中断绑到处理该队列的 CPU，使软中断与数据处理同核，提升缓存命中。
- `irqbalance` 自动分散中断以均衡负载。

## 三、形式化 / 数学基础
设 CPU 集合 $C$，亲和掩码 $A_i \\subseteq C$。期望目标：最小化 $\\sum_i \\text{cache\\_miss}(i)$ 同时使负载 $\\max_{c}\\sum_{i:c\\in A_i} rate_i$ 均衡。

## 四、代码实现
设置亲和掩码（用户态示意）：

```c
cpu_set_t m; CPU_ZERO(&m); CPU_SET(2, &m);
sched_setaffinity(0, sizeof(m), &m);     /* 进程 */
/* 或写 /proc/irq/<n>/smp_affinity 十六进制掩码 */
```

## 五、与其他技术对比
默认 IRQ 可漂移到空闲核（均衡但破坏局部性）；手动亲和性保局部性但需人工调优；NUMA 还需考虑设备与内存就近。

## 六、常见误区
- 认为“绑死一个核”总是最好：高 IRQ 率会饿死该核其他任务。
- 忽略 NUMA：跨节点内存访问拖慢处理。
- 混淆进程亲和与中断亲和。

## 九、演进与趋势
XPS（发送侧缩放）、RPS/RFS（接收侧软中断 steering）与 NUMA 感知共同把数据流与 CPU 核对齐。

## 十、小结
中断亲和性通过把 IRQ 绑定到合适 CPU，在缓存局部性与负载均衡间取舍，是高吞吐网络栈的关键调优手段。
