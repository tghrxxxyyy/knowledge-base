# 上下文切换

> 对应 OSTEP 第 6 章“上下文切换”与 Linux `kernel/sched/core.c`。

## 一、背景与挑战
多任务靠在进程/线程间切换 CPU 实现并发。切换需保存/恢复寄存器、切换地址空间与内核栈，是调度开销的主要来源。

## 二、核心原理
- 保存当前寄存器到 `task_struct.thread` / 内核栈。
- 若切换地址空间，刷新页表基址（CR3/ASID）并可能刷 TLB。
- 恢复目标寄存器，返回用户态继续执行。

## 三、形式化 / 数学基础
切换成本 $C_{ctx} = C_{reg} + C_{tlb} + C_{cache}$。跨进程（$mm$ 不同）需切换页表带来 TLB 失效；同进程线程切换免去页表切换，仅 $C_{reg}$。

## 四、代码实现
`__switch_to` 关键（x86 示意）：

```asm
    mov %rsp, TASK_RSP(%rsi)    # 保存旧栈
    mov TASK_RSP(%rdi), %rsp    # 载入新栈
    mov %rbx, TASK_RBX(%rsi)    # 保存 callee 寄存器
    ...
    ret                         # 返回到新任务
```

## 五、与其他技术对比
线程切换（同地址空间）轻于进程切换；用户态协程切换仅保存少量寄存器、无特权切换，最轻；硬件线程（SMT）切换近乎零但共享执行单元。

## 六、常见误区
- 认为切换只花“几条指令”：TLB/缓存冷启动代价常被低估。
- 混淆进程与线程切换成本差异（页表）。
- 忽略切换频率对 cache 命中率的隐性影响。

## 九、演进与趋势
PCID/ASID 减少 TLB 刷新；用户态调度（如 goroutine、io_uring 轮询）减少内核切换；run-to-completion 模型降低切换频率。

## 十、小结
上下文切换保存寄存器、切换页表与栈；代价含寄存器、TLB 与缓存冷启动，是并发的基本开销度量。
