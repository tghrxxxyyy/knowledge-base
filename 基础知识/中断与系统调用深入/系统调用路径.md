# 系统调用路径

> 对应 CSAPP 第 8 章与 Linux `arch/x86/entry`。

## 一、背景与挑战
用户程序需请求内核服务（IO、进程、内存）。系统调用是受控的内核入口，必须完成特权级切换、参数校验与上下文保存，且安全返回。

## 二、核心原理
- 用户态置系统调用号（rax）与参数寄存器，执行 `syscall`。
- 内核验证参数（指针属用户空间、长度合法）、执行服务、返回值经 rax 回传。
- 返回前可能 `schedule`（若需重调度）或处理信号。

## 三、形式化 / 数学基础
调用开销模型：$C_{sc} = C_{mode} + C_{save} + C_{check} + C_{svc}$。其中 $C_{mode}$ 为特权级切换与栈切换固定成本，通常数百 ns 级。

## 四、代码实现
glibc 封装（示意）：

```c
long syscall(int n, ...) {
    register long a0 __asm__("rdi") = arg0;
    register long n0  __asm__("rax") = n;
    __asm__ volatile("syscall" : "+r"(n0) : "r"(a0) : "rcx","r11","memory");
    return n0;   /* 返回码, 负值为 -errno */
}
```

## 五、与其他技术对比
`syscall` 指令比旧 `int 0x80` 快（无特权级栈切换开销）；`vDSO` 把部分调用（gettimeofday）留在用户态免去陷入；io_uring 用共享环进一步减少陷入次数。

## 六、常见误区
- 认为系统调用“免费”：每次都有模式切换与校验成本。
- 忽略参数需内核拷贝/校验（不能信任用户指针）。
- 混淆 errno 与返回值：负返回码取负即 errno。

## 九、演进与趋势
io_uring 用 SQ/CQ 环形缓冲批量提交，减少系统调用次数；eBPF 在内核内处理部分逻辑避免往返。

## 十、小结
系统调用是受控的内核门：经 `syscall` 完成模式切换、参数校验与执行，是用户态获得特权的唯一正规通道。
