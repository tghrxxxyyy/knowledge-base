# 字符串哈希

> 对应 Cormen et al.《算法导论》哈希表章节的滚动哈希思想，以及 Rabin–Karp 算法（Rabin & Karp, 1987）与多项式哈希（polynomial rolling hash）。

## 一、背景与挑战

许多字符串问题并不需要"逐字符比对"，而是反复询问**两个子串是否相等**：判断回文、找重复子串、最长公共子串、文本查重、判断一个串是否为另一个的循环移位……如果每次都用 $O(L)$ 时间比较长度为 $L$ 的子串，整体很容易退化到 $O(n^2)$ 甚至更高。我们需要一种能把任意子串"压成"可 $O(1)$ 比较的摘要（fingerprint）的手段。

哈希正是这样的摘要函数。但朴素地对每个子串重新计算哈希是 $O(L)$ 的，省不掉比较开销。**滚动哈希**（rolling hash）的突破在于：选一个可增量更新的哈希族，使得子串 $T[l..r]$ 的哈希能在 $O(1)$ 时间内由 $T[l+1..r]$ 或前缀哈希算出。最经典的是**多项式哈希**：

$$
H(T) = \bigl(t_0 b^{m-1} + t_1 b^{m-2} + \cdots + t_{m-1} b^0 \bigr) \bmod M,
$$

其中 $b$ 是基数（base），$t_i$ 是字符编码，$M$ 是大模数。它把字符串看成 $b$ 进制大整数，天然支持"去头加尾"的滚动。

在工程与面试中，字符串哈希是"偷懒神器"也是"被卡常客"。竞赛里它可以几乎替换掉 KMP 的很多用法（求任意子串相等、找重复子串），但在 Codeforces 等平台上，若用单模数 $2^{64}$（自然溢出）又不注意基数选择，可能被构造数据故意制造碰撞而 Wrong Answer。因此理解冲突概率、知道如何用双哈希加固，是进阶选手与普通选手的分水岭。Java 的 `String.hashCode`、Git 的内容寻址、Rabin–Karp 多模式匹配，都是同一思想的工程化身。

## 二、核心原理

多项式哈希把字符串 $S = s_0 s_1 \cdots s_{m-1}$ 映射为 $b$ 进制数值模 $M$。它有两条关键性质：

1. **可递推**：已知 $H(S)$，右端加字符 $c$ 得到 $H(S+c) = (H(S)\cdot b + c) \bmod M$；左端去字符时需要"减掉最高位"，并除以 $b$（模意义下乘 $b$ 的逆元，或用前缀哈希规避除法）。
2. **前缀哈希支持 $O(1)$ 子串查询**：预处理
   $$
   h[i+1] = (h[i]\cdot b + t_i) \bmod M,\quad i=0..n-1
   $$
   其中 $h[0]=0$。则子串 $T[l..r]$（长度 $L=r-l+1$）的哈希为
   $$
   H(l,r) = \bigl(h[r+1] - h[l]\cdot b^{L}\bigr) \bmod M.
   $$
   这正是"高进制减去前缀贡献"的标准写法；实现时注意 Python 负数取模、C++ 里 `(x % M + M) % M`。

**不变量**：$h[i]$ 始终等于前缀 $T[0..i-1]$ 的多项式值模 $M$。子串公式是把 $T[l..r]$ 对齐到最低位：先用 $h[r+1]$ 得到 $T[0..r]$ 的值，减去 $T[0..l-1]$ 贡献的高位部分 $h[l]\cdot b^L$。

**为什么正确**：多项式在整数环上是单射的（不同串对应不同 $b$ 进制数），取模后若 $M$ 足够大且两串不等，碰撞概率取决于哈希值的分布均匀性。注意哈希相等是子串相等的**必要条件**而非充分条件——这正是它快且危险的原因。

**工程要点**：
- **基数 $b$** 应大于字符集大小，常取质数如 $131, 13331, 91138233$；避免 $b$ 与 $M$ 有特殊代数关系。
- **模数 $M$** 常用 $10^9+7$、$10^9+9$，或直接用 `uint64` 自然溢出（等价 $M=2^{64}$，利用无符号溢出特性，速度极快）。
- **双哈希**：用两个不同 $(b, M)$ 生成两个哈希值，比较时两者都相等才算匹配，把碰撞概率从约 $1/M$ 压到约 $1/M_1M_2$。
- **冲突不是 bug 而是特性**：哈希只能加速，不能替代证明。重要判题/安全场景要么双哈希，要么在可疑时回退真实比较。

## 三、形式化与数学基础

**前缀递推与子串公式。** 令 $h[0]=0$，$h[i+1] = (h[i] b + t_i) \bmod M$。展开可得

$$
h[k] = \Bigl(\sum_{i=0}^{k-1} t_i b^{k-1-i}\Bigr) \bmod M.
$$

于是

$$
h[r+1] - h[l] b^{L} \equiv \sum_{i=l}^{r} t_i b^{r-i} \pmod M,
$$

即子串 $T[l..r]$ 的多项式值。预先算出 $powb[i]=b^i \bmod M$，查询为 $O(1)$。

**冲突概率。** 若把哈希值近似均匀分布在 $[0, M)$，对 $q$ 次比较，至少一次假阳性的概率约为

$$
1 - \Bigl(1 - \frac{1}{M}\Bigr)^q \approx \frac{q}{M} \quad (q \ll M).
$$

例如 $M \approx 10^9$、$q=10^6$ 时约为 $10^{-3}$，不可忽略；双哈希后约为 $10^{-6}$ 量级再平方级下降。用 $2^{64}$ 自然溢出时形式概率极低，但若对手知道你的 $b$ 与模数，可构造人为碰撞（存在性可由生日攻击或模数代数结构论证），故竞赛建议双模或随机 $b$。

**Rabin–Karp 的期望复杂度。** 用滚动哈希匹配长度 $m$ 的模式，扫描 $n-m+1$ 个窗口，每次 $O(1)$ 更新；假阳性时才做 $O(m)$ 真实比较。若每次比较假阳性概率约 $1/M$，期望总时间

$$
O(n + m) + O\bigl((n-m+1)\cdot \tfrac{m}{M}\bigr) = O(n + m)
\quad (M \text{ 足够大时}).
$$

最坏（每次全冲突）是 $O(nm)$，这是与 KMP 的本质差别：KMP 最坏线性，哈希期望线性。

**取模与逆元。** 若用"去头加尾"式滚动（维护窗口哈希 $h$，左移时 $h = h - t_{\text{left}} b^{m-1}$，再 $h = h\cdot b + t_{\text{new}}$），完全不需除法，更安全；前缀哈希方案也不需逆元。只有在维护"可任意切片的双端队列哈希"时才可能要模逆。

## 四、代码实现

```python
class StringHash:
    """多项式滚动哈希，前缀预处理，O(1) 子串哈希。支持双哈希防碰撞。"""

    def __init__(self, s: str, bases=(131, 13331), mods=(10**9 + 7, 10**9 + 9)):
        self.n = len(s)
        self.bases = bases
        self.mods = mods
        self.h = []
        self.pb = []
        for b, m in zip(bases, mods):
            h = [0] * (self.n + 1)
            pb = [1] * (self.n + 1)
            for i, ch in enumerate(s):
                h[i + 1] = (h[i] * b + ord(ch)) % m
                pb[i + 1] = (pb[i] * b) % m
            self.h.append(h)
            self.pb.append(pb)

    def get(self, l: int, r: int) -> tuple:
        """返回子串 s[l..r] 的双哈希元组。"""
        res = []
        for k in range(len(self.bases)):
            m = self.mods[k]
            v = (self.h[k][r + 1] - self.h[k][l] * self.pb[k][r - l + 1]) % m
            res.append(v)
        return tuple(res)


def longest_duplicate_substring(s: str) -> str:
    """用哈希 + 二分找最长重复子串（允许重叠）。"""
    n = len(s)
    lo, hi, ans = 1, n, ""
    while lo <= hi:
        mid = (lo + hi) // 2
        sh = StringHash(s)
        seen = {}
        found = None
        for i in range(n - mid + 1):
            key = sh.get(i, i + mid - 1)
            if key in seen:
                found = i
                break
            seen[key] = i
        if found is not None:
            ans = s[found:found + mid]
            lo = mid + 1
        else:
            hi = mid - 1
    return ans


if __name__ == "__main__":
    sh2 = StringHash("abracadabra")
    assert sh2.get(0, 3) == sh2.get(7, 10)  # "abra" == "abra"
    assert sh2.get(0, 2) != sh2.get(3, 5)   # "abc" != "aca"
    assert sh2.get(0, 0) == sh2.get(3, 3)   # "a" == "a"
    assert longest_duplicate_substring("banana") == "ana"
    assert longest_duplicate_substring("abcd") == ""
    print("Hash ok")
```

## 五、与其他技术对比

| 方案 | 预处理 | 单次查询 | 最坏正确性 | 空间 | 典型用途 |
|------|--------|----------|------------|------|----------|
| 朴素比较 | $O(1)$ | $O(L)$ | 确定 | $O(1)$ | 短串、一次性比较 |
| 字符串哈希 | $O(n)$ | $O(1)$ | 有碰撞风险 | $O(n)$ | 大量子串相等、二分长度类问题 |
| KMP/Z-algorithm | $O(n)$ | 可给出所有 border/Z 值 | 确定 | $O(n)$ | 精确匹配、周期、border |
| 后缀数组 + LCP | $O(n)$ 或 $O(n\log n)$ | $O(1)$ LCP | 确定 | $O(n)$ | 子串排序、不同子串计数、严格求解 |
| 后缀自动机 | $O(n)$ | 子串存在性 $O(m)$ | 确定 | $O(n)$ | 子串计数、最长重复、在线构造 |

**取舍**：哈希胜在实现短、常数小、任意区间 $O(1)$；输在"期望正确"。需要严格正确时用后缀数组/SA-IS 或在哈希冲突时回退字符比较。双哈希在竞赛中通常够用，金融/安全路径上不要单哈希做唯一判断。

## 六、常见误区

1. **用 `hash` 内置函数或 Java `String.hashCode` 做子串比较。** 它们不是滚动哈希，无法 $O(1)$ 得到子串值；且实现细节可能被碰撞攻击。必须自己维护多项式前缀。
2. **只用单模数且基数固定公开。** 竞赛恶意数据可构造碰撞导致 WA。对策：双哈希、随机基数、或 `uint64` 自然溢出 + 大基数。
3. **忘记负数取模。** $h[r+1]-h[l]b^L$ 可能为负，C++ 中直接 `% M` 得到负值导致比较失败；Python 自动处理但仍建议显式 `% M` 保持风格统一。
4. **比较不同长度的哈希值当作相等。** 哈希包含了长度信息（高位个数），不同长度几乎必然不同；但有人用"前缀哈希"误当成"内容哈希"去比。应始终明确区间长度一致，或把长度编入键。
5. **认为哈希相等就是子串相等。** 这只是高概率事件。正确姿势是把哈希当索引/过滤器，关键路径加真实比较或双模确认。

## 八、面试题

1. **如何 $O(1)$ 判断 $S[l_1..r_1]$ 与 $S[l_2..r_2]$ 是否相等？**  
   参考答案：预处理多项式前缀哈希与 $b$ 幂，子串哈希 $H(l,r)=(h[r+1]-h[l]b^{r-l+1}) \bmod M$，比较两个哈希值（建议双哈希）；如需 100% 正确可再做一次字符级验证。

2. **给定字符串，求最长重复子串（可重叠）。**  
   参考答案：二分答案长度 $L$，用滚动哈希检查是否存在两个相同长度为 $L$ 的子串。可行性单调：若长度 $L$ 可行则 $L-1$ 可行。总复杂度 $O(n \log n)$。

3. **为什么用 $2^{64}$ 自然溢出常被卡？怎么防？**  
   参考答案：模数固定且基数公开时，攻击者可构造碰撞；另外部分语言/编译器无符号溢出语义要小心。防护：双模（$10^9+7$ 与 $10^9+9$）、随机基数、或在命中哈希后二次校验。

4. **Rabin–Karp 与 KMP 如何选择？**  
   参考答案：需要最坏线性、在线、多模板共享前缀时选 KMP（或 AC 自动机）；需要任意区间相等、多询问、二分长度类问题时哈希更灵活。RK 最坏可被卡到 $O(nm)$，KMP 不会。

## 九、演进与趋势

字符串哈希的演进集中在**更强的抗碰撞**与**更丰富的可合并结构**。一是把哈希做成可结合的 monoid（区间拼接哈希 $H(xy)=H(x)b^{|y|}+H(y)$），从而进入线段树/树状数组，支持单点修改后的子串比较，这在动态字符串题与编辑器撤销栈里很实用。二是**几何哈希与 SimHash/MinHash** 家族用于近重复检测、网页去重、推荐系统，把"精确相等"放宽到"相似度"。三是生物信息学中的 **k-mer 哈希**（如 minimizer、FracMinHash）把滚动哈希与抽样结合，在基因组比对中把海量短串索引压到可放进内存。四是安全领域提醒：不可把非加密哈希（poly hash、Murmur）用于完整性校验；对抗场景请用 BLAKE3/SHA-3 或 HMAC。工程上，Git 的对象寻址、CDN 缓存键、API 幂等键都可以看作"把内容映射为指纹"这一思想的延伸，而多项式滚动哈希是其中最古老、最轻量的一员。

## 十、小结

字符串哈希把子串相等判定从 $O(L)$ 降到期望 $O(1)$，核心是多项式递推 $h[i+1]=h[i]b+t_i$ 与子串公式 $H(l,r)=(h[r+1]-h[l]b^L)\bmod M$。它极其好用，但必须清醒认识到碰撞风险：选好基数与模数、关键处双哈希、重要路径回退真实比较。理解它与 KMP、后缀结构的分工，是把"能过样例"提升到"能过数据"的关键一步。
