# 并发编程深入实战（AQS / CompletableFuture / ForkJoinPool / 并发调试）

> Java 并发编程 =「**线程模型 + 同步机制 + 并发工具 + 调试排障**」。本篇从「概览」升级为「深入实战」：AQS 源码核心、CompletableFuture 异步编排、ForkJoinPool 分治框架、并发调试工具链、线程池调优实战、并发 Bug 复现与修复。

---

## 一、线程基础回顾

### 1.1 线程状态

```
NEW → RUNNABLE → BLOCKED / WAITING / TIMED_WAITING → TERMINATED

RUNNABLE 包含 Ready 和 Running（JVM 不区分）
BLOCKED：等待获取 synchronized 锁
WAITING：wait()/join()/park()
TIMED_WAITING：sleep()/wait(timeout)/park(timeout)
```

### 1.2 synchronized 锁升级

```
无锁 → 偏向锁 → 轻量级锁（CAS + Mark Word）→ 重量级锁（Monitor）

偏向锁：单线程反复进入同步块（无竞争）
轻量级锁：CAS 竞争（短等待）
重量级锁：OS 互斥量（长等待）
自旋锁：轻量级锁失败后自旋一定次数再升级
```

## 二、AQS 深入（AbstractQueuedSynchronizer）

### 2.1 核心结构

```
AQS = volatile int state + CLH 双向队列

state = 同步状态（0/1/重入次数/许可数量）
CLH 队列 = 等待获取锁的线程链表（FIFO）

获取锁：
  1. tryAcquire(arg)：CAS 修改 state
  2. 成功 → 返回
  3. 失败 → 封装为 Node 加入 CLH 队列尾部
  4. 队列中的线程自旋/阻塞等待

释放锁：
  1. tryRelease(arg)：修改 state
  2. 唤醒队列头部的下一个线程
```

### 2.2 基于 AQS 的实现

| 组件 | state 含义 | 模式 |
|------|-----------|------|
| ReentrantLock | 重入次数（0/1/N） | 独占 |
| Semaphore | 许可数量 | 共享 |
| CountDownLatch | 计数器 | 共享 |
| ReentrantReadWriteLock | 高16位=读锁计数，低16位=写锁计数 | 独占+共享 |
| StampedLock | 版本号 + 模式标记 | 乐观读/悲观读写 |

### 2.3 AQS 源码关键路径

```
以 ReentrantLock不公平锁为例：

获取锁：
  lock() → NonfairSync.lock()
    → tryLock(): CAS(0→1) 成功则持有锁
    → 失败: acquire(1)
      → tryAcquire(1): 检查 state
        → 0: CAS(0→1) 抢锁
        → >0: 检查是否重入（exclusiveOwnerThread == current）
      → 失败: acquireQueued(addWaiter(EXCLUSIVE), arg)
        → 将当前线程封装为 Node 加入 CLH 队列尾部
        → for(;;) { parkAndCheckInterrupt() }  // 阻塞等待
        → 前驱节点释放后 unpark 唤醒

释放锁：
  unlock() → release(1)
    → tryRelease(1): state -= 1
    → state == 0: 完全释放
    → unparkSuccessor(head): 唤醒队列中下一个等待线程
```

## 三、CompletableFuture 异步编排

### 3.1 核心 API

```java
// 创建异步任务
CompletableFuture<String> cf = CompletableFuture.supplyAsync(() -> {
    return queryUser(userId);
}, executor);

// 链式编排
cf.thenApply(user -> user.getName())        // 同步转换
  .thenApplyAsync(name -> lookup(name), pool) // 异步转换
  .thenAccept(name -> log.info(name))        // 消费结果
  .exceptionally(ex -> "default")            // 异常处理
  .whenComplete((result, ex) -> {            // 完成回调
      if (ex != null) log.error("failed", ex);
      else log.info("done: {}", result);
  });

// 组合多个异步任务
CompletableFuture.allOf(cf1, cf2, cf3)  // 全部完成
    .thenRun(() -> log.info("all done"));

CompletableFuture.anyOf(cf1, cf2, cf3)  // 任一完成

// 手动完成
cf.complete("result");     // 手动完成
cf.completeExceptionally(ex); // 手动失败
```

### 3.2 常见模式

```java
// 模式一：超时控制
CompletableFuture.supplyAsync(() -> slowQuery())
    .orTimeout(3, TimeUnit.SECONDS)  // 超时（Java 9+）
    .exceptionally(ex -> "timeout fallback");

// 模式二：依赖链（串行）
getUser(userId)
    .thenCompose(user -> getOrders(user.getId()))  // flatMap
    .thenApply(orders -> filterActive(orders));

// 模式三：并行聚合
CompletableFuture<UserInfo> userFuture = getUserAsync(id);
CompletableFuture<Orders> ordersFuture = getOrdersAsync(id);
userFuture.thenCombine(ordersFuture, (user, orders) -> {
    return new UserInfo(user, orders);
});

// 模式四：异常恢复
queryFromDB()
    .exceptionally(ex -> queryFromCache())  // 降级
    .thenApply(data -> transform(data));
```

## 四、ForkJoinPool 分治框架

### 4.1 核心思想

```
ForkJoinPool = 工作窃取（Work-Stealing）线程池

每个线程有自己的双端队列（Deque）
  → 空闲线程从其他线程队列尾部「偷取」任务
  → 减少竞争，提高并行度

适用于：递归分治任务（排序/搜索/遍历）
```

### 4.2 使用示例

```java
// 并行归并排序
class MergeSort extends RecursiveTask<int[]> {
    int[] arr; int left, right;
    
    @Override
    protected int[] compute() {
        if (right - left <= 16) {
            return sequentialSort(arr, left, right);  // 小数组直接排序
        }
        int mid = (left + right) / 2;
        MergeSort leftTask = new MergeSort(arr, left, mid);
        MergeSort rightTask = new MergeSort(arr, mid, right);
        leftTask.fork();  // 异步执行左半部分
        int[] right = rightTask.compute();  // 当前线程执行右半部分
        int[] left = leftTask.join();       // 等待左半部分
        return merge(left, right);
    }
}

// 提交到 ForkJoinPool
ForkJoinPool pool = new ForkJoinPool();  // 默认并行度 = CPU核数
pool.invoke(new MergeSort(arr, 0, arr.length));
```

### 4.3 关键参数

| 参数 | 说明 | 默认值 |
|------|------|--------|
| parallelism | 最大并行度 | CPU 核数 |
| asyncMode | 异步模式（true=先进先出） | false |
| keepAliveTime | 空闲线程存活时间 | 1 分钟 |

**注意**：`commonPool()`（ForkJoinPool.commonPool()）默认并行度 = CPU 核数-1，多个 ForkJoinTask 共享。CPU 密集任务不要用 commonPool。

## 五、并发调试工具链

### 5.1 jstack（线程快照）

```bash
# 导出线程快照
jstack <pid> > thread_dump.txt

# 查看死锁
jstack <pid> | grep -A 20 "deadlock"

# 查看 BLOCKED 线程
jstack <pid> | grep -B 5 "BLOCKED"
```

### 5.2 Arthas（在线诊断）

```bash
# 查看线程状态
thread          # 所有线程
thread -n 3     # 最忙的3个线程
thread -b       # 查看阻塞线程
thread --state BLOCKED  # 所有 BLOCKED 线程

# 查看线程堆栈
thread <id>     # 指定线程堆栈

# 监控方法耗时
trace com.example.Service query  # 实时方法耗时
watch com.example.Service query returnObj  # 观察返回值
```

### 5.3 JMH 基准测试

```java
@BenchmarkMode(Mode.AverageTime)
@OutputTimeUnit(TimeUnit.NANOSECONDS)
@Warmup(iterations = 5, time = 1)
@Measurement(iterations = 10, time = 1)
@Fork(2)
public class MyBenchmark {
    @Benchmark
    public void testSynchronized() { /* ... */ }
    
    @Benchmark
    public void testReentrantLock() { /* ... */ }
}
```

## 六、线程池调优实战

### 6.1 参数设置

```java
ThreadPoolExecutor pool = new ThreadPoolExecutor(
    corePoolSize,      // 核心线程数（常驻）
    maximumPoolSize,   // 最大线程数
    keepAliveTime,     // 空闲线程存活时间
    TimeUnit.SECONDS,
    workQueue,         // 任务队列
    threadFactory,     // 线程工厂
    rejectionHandler   // 拒绝策略
);
```

### 6.2 线程数计算

| 场景 | 公式 | 说明 |
|------|------|------|
| CPU 密集 | N + 1（N = CPU 核数） | 减少上下文切换 |
| IO 密集 | N × (1 + W/C)（W=等待时间，C=计算时间） | 利用等待时间 |
| 混合型 | 2N ~ 4N | 按压测调整 |

### 6.3 常见坑

| 问题 | 原因 | 解决 |
|------|------|------|
| 任务堆积 | corePoolSize 太小 + 队列太大 | 增大 corePoolSize 或用 SynchronousQueue |
| OOM | 无界队列（LinkedBlockingQueue） | 用有界队列 + 合理拒绝策略 |
| 线程饿死 | CPU 密集任务用无界队列 | 用 SynchronousQueue 或 CallerRunsPolicy |
| 线程泄漏 | 自定义线程池没 shutdown | JVM 关闭时 shutdown |
| 上下文切换 | 线程数过多 | 按公式设置 + 压测验证 |

## 七、并发 Bug 复现与修复

### 7.1 常见并发 Bug

| Bug | 表现 | 原因 |
|-----|------|------|
| 数据竞争 | 结果不确定 | 多线程无同步访问共享变量 |
| 活锁 | 任务永远执行 | 线程互相让步（如 CAS 重试失败） |
| 死锁 | 任务卡死 | 两个线程互相持有对方需要的锁 |
| 线程饥饿 | 某线程永远得不到执行 | 公平锁未设置 / 线程优先级 |

### 7.2 复现技巧

```bash
# 1. 压力测试（增大并发概率）
ab -n 10000 -c 200 http://localhost:8080/api

# 2. 随机延迟（暴露竞态条件）
Thread.sleep(new Random().nextInt(10));

# 3. Arthas 实时监控
watch com.example.Service update returnObj -x 2

# 4. jstack 快照（发现死锁）
jstack <pid> | grep -A 20 "deadlock"
```
