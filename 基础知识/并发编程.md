# Java 并发编程

## 〇、本体介绍

**并发编程是什么**：让多个计算「同时推进」（单核时间片切、多核真并行），提升吞吐与响应。Java 通过 **线程（Thread）** 作为最小调度单位，提供从 `synchronized` 到 `java.util.concurrent`（JUC）的一整套工具。

**解决什么痛点**：多核时代不并发就浪费 CPU；但共享内存带来**竞态、可见性、有序性**三大问题，处理不好就是数据错乱、死锁、诡异 bug。

**核心主线**：① 线程基础与状态；② 可见性/有序性（volatile、内存模型 JMM）；③ 原子性与锁（synchronized 锁升级、Lock/AQS）；④ 线程池；⑤ JUC 工具类；⑥ 并发容器与原子类；⑦ 伪共享与无锁（Disruptor/CAS）。

**适用场景**：高并发服务端、异步任务、并行计算。
**不适用场景**：纯单线程脚本（并发引入复杂度）。

---

## 一、线程与线程状态

- 创建方式：`Thread` / `Runnable` / `Callable`(有返回值) / 线程池（推荐）。
- 状态（6 种）：`NEW → RUNNABLE → BLOCKED / WAITING / TIMED_WAITING → TERMINATED`。
- `BLOCKED`：等 synchronized 监视器锁；`WAITING`：等 `wait()/join()/LockSupport.park()`（无超时）；`TIMED_WAITING`：带超时的等待。

---

## 二、JMM 与三大问题

- **可见性**：一个线程改了变量，另一个线程未必立刻看到（CPU 缓存）。`volatile` 保证可见性（写立即刷主存、读从主存取）且**禁止指令重排**（有序性），但**不保证复合操作原子性**。
- **有序性**：编译/CPU 可能重排，单线程看不出，多线程出事。`volatile` / `synchronized` / `final` 提供 happens-before 保障。
- **原子性**：`i++` 非原子（读-改-写）。用 `synchronized`、`Lock` 或 `AtomicInteger`(CAS) 保原子。
- **happens-before**：JMM 的偏序规则——`volatile 写→读`、`锁释放→获取`、`线程 start/ join` 等，保证「前面的操作对后面可见」。

---

## 三、synchronized 与锁升级

- **原理**：基于对象头的 **Monitor（监视器锁）**，底层依赖 OS 互斥量（早期重量级锁，开销大）。
- **锁升级（JDK 6+）**：**无锁 → 偏向锁 → 轻量级锁（CAS 自旋）→ 重量级锁**。
  - 偏向锁：单线程反复进入，记线程 ID，几乎零开销。
  - 轻量级锁：多线程交替，CAS 自旋避免阻塞。
  - 重量级锁：竞争激烈，线程阻塞挂起（OS mutex），开销大。
- 锁消除/锁粗化（JIT 优化）：无竞争锁被消除、连续加锁合并。

---

## 四、Lock 与 AQS

- **AQS（AbstractQueuedSynchronizer）**：JUC 的基石。用一个 **volatile int state** + **CLH 等待队列** 实现同步。
  - 独占（ReentrantLock）：`tryAcquire/tryRelease`，公平/非公平（非公平可插队，吞吐高）。
  - 共享（Semaphore/CountDownLatch/CyclicBarrier 等）：`tryAcquireShared`。
- **ReentrantLock**：可中断、可超时、公平可选、绑定多 Condition（比 `synchronized` + `wait/notify` 灵活）。
- **synchronized vs ReentrantLock**：后者功能更全（公平、可中断、多条件），前者自动释放、简洁、JIT 优化好；无绝对优劣，按需选。

---

## 五、线程池（重点）

- **核心参数**：`corePoolSize`(核心)、`maximumPoolSize`(最大)、`keepAliveTime`(非核心线程空闲回收)、`workQueue`(任务队列)、`threadFactory`、`RejectedExecutionHandler`(拒绝策略)。
- **执行流程**：任务来 → 核心线程满？→ 入队列 → 队列满？→ 开非核心线程到最大 → 还满？→ 拒绝策略。
- **拒绝策略**：`AbortPolicy`(抛异常，默认)、`CallerRunsPolicy`(调用者线程执行)、`DiscardPolicy`(静默丢)、`DiscardOldestPolicy`(丢最旧)。
- **Executors 的坑**：`newFixedThreadPool`/`newSingleThread` 用**无界队列**易 OOM；`newCachedThreadPool` 最大线程无界也易 OOM。生产**手动 `new ThreadPoolExecutor`** 并设合理队列与拒绝策略。
- **常见池**：`IO 密集` 线程数可大（如 2×核数）；`CPU 密集` 约核数；混合型权衡。

---

## 六、JUC 工具类

- **CountDownLatch**：倒计数，await 等 countDown 到 0（一次性）。
- **CyclicBarrier**：循环屏障，等 N 个线程到齐再一起继续（可重置）。
- **Semaphore**：信号量，限流（控制并发数）。
- **Phaser**：更灵活的阶段同步（JDK7+）。
- **Exchanger**：两个线程交换数据。

---

## 七、并发容器与原子类

- **ConcurrentHashMap**：分段锁 → JDK8 **CAS + synchronized 锁桶头节点**（更细粒度），读无锁。
- **CopyOnWriteArrayList**：写时复制，读无锁、写加锁复制，适合**读多写少**（如监听器列表）。
- **BlockingQueue**：`ArrayBlockingQueue`(有界)、`LinkedBlockingQueue`(默认无界)、`SynchronousQueue`(直接交接)、`DelayQueue`(延迟)。线程池与生产者消费者基石。
- **原子类**：`AtomicInteger/Long/Reference`、`AtomicStampedReference`(解决 ABA)、`LongAdder`(分段计数，高并发更优)。

---

## 八、CAS 与 ABA / 自旋

- **CAS（Compare-And-Swap）**：`compareAndSet(expected, new)`，无锁原子更新，自旋重试。AQS、原子类底层。
- **ABA 问题**：值 A→B→A，CAS 误以为没变。解决：`AtomicStampedReference`（版本号）/ `AtomicMarkableReference`。
- **自旋开销**：高竞争下 CAS 空转耗 CPU；`LongAdder` 用分段降低竞争。

---

## 九、死锁与诊断

- **四个必要条件**：互斥、占有且等待、不可剥夺、循环等待。
- **预防**：按固定顺序加锁、一次性申请全部锁、超时释放（`tryLock`）、银行家算法。
- **诊断**：`jstack <pid>` 看 `BLOCKED`/`deadlock`；` arthas`/`async-profiler` 定位。

---

## 十、伪共享（False Sharing）

- 多个变量在同一 **缓存行（64B）**，多核各改其一导致整行失效互踢，性能骤降。
- **解决**：`@Contended`（JDK8+，需 `-XX:-RestrictContended`）或手动 `padding` 填充到 64B。`LongAdder` 的 Cell 即用此思想。
- 无锁框架 **Disruptor** 用环形缓冲 + 消除伪共享实现极高吞吐。

## 十二、速查表

| 场景 | 选型 |
|------|------|
| 简单互斥 | `synchronized` |
| 需公平/可中断/多条件 | `ReentrantLock` |
| 原子计数 | `AtomicInteger` / `LongAdder` |
| 高并发计数 | `LongAdder` |
| 等待一组完成 | `CountDownLatch` |
| 多阶段栅栏 | `CyclicBarrier` |
| 限流 | `Semaphore` |
| 读多写少列表 | `CopyOnWriteArrayList` |
| 并发 Map | `ConcurrentHashMap` |

## 面试高频问题（20+ 条）

1. **线程有哪些状态？** NEW/RUNNABLE/BLOCKED/WAITING/TIMED_WAITING/TERMINATED。
2. **BLOCKED 和 WAITING 区别？** 前者等 synchronized 锁；后者等 wait/join/park（无锁竞争）。
3. **并发三大问题？** 可见性、原子性、有序性。
4. **volatile 保证什么？** 可见性 + 有序性（禁止重排），不保证复合操作原子性。
5. **volatile 能替代锁吗？** 不能，i++ 等多步操作仍需锁/CAS。
6. **happens-before 是什么？** JMM 偏序规则，保证前操作对后可见（volatile、锁、start/join 等）。
7. **synchronized 锁升级？** 无锁→偏向→轻量(CAS)→重量(阻塞)，竞争升级。
8. **偏向锁/轻量锁/重量锁区别？** 偏向单线程零开销；轻量多线程交替 CAS 自旋；重量竞争阻塞（OS mutex）。
9. **synchronized vs ReentrantLock？** 后者可中断/超时/公平/多 Condition；前者自动释放、JIT 优化。
10. **AQS 原理？** volatile state + CLH 队列，独占/共享模式实现同步。
11. **ReentrantLock 公平与非公平？** 非公平可插队吞吐高；公平按队列顺序。
12. **线程池核心参数？** 核心数、最大数、空闲回收、队列、工厂、拒绝策略。
13. **线程池执行流程？** 核心满→入队→队满→开非核心→还满→拒绝。
14. **为什么不建议 Executors 创建池？** 无界队列/无界线程数易 OOM；应手动 new ThreadPoolExecutor。
15. **拒绝策略有哪些？** Abort(抛异常)/CallerRuns(调用者跑)/Discard(丢)/DiscardOldest(丢最旧)。
16. **CPU/IO 密集线程数？** CPU 密集≈核数；IO 密集可更大（如 2×核或更多）。
17. **CountDownLatch vs CyclicBarrier？** 前者一次性倒数等待；后者可重置循环栅栏。
18. **Semaphore 用途？** 信号量限流，控并发数。
19. **ConcurrentHashMap 怎么保证并发？** JDK8 CAS + synchronized 锁桶头（更细粒度），读无锁。
20. **CopyOnWriteArrayList 适用？** 读多写少（写时复制），不适合写频繁。
21. **CAS 是什么、ABA 怎么办？** 无锁比较交换；ABA 用版本号（AtomicStampedReference）。
22. **什么是伪共享、怎么解决？** 同缓存行多变量互踢；@Contended/padding 填充；LongAdder 用此优化。
23. **死锁四个条件？** 互斥、占有等待、不可剥夺、循环等待；破坏其一即可预防。
24. **如何排查死锁？** jstack 看 deadlock/BLOCKED；arthas 诊断。
25. **ThreadLocal 内存泄漏？** Entry 用弱引用 key，value 强引用需手动 remove，否则线程池复用下泄漏。
