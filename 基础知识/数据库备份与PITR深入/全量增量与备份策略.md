# 全量增量与备份策略

> 对应 Vonng/ddia（备份策略运维），以及 Kleppmann《Designing Data-Intensive Applications》第 5 章（容错与复制）。

## 一、背景与挑战
纯全量备份在大数据下窗口长、存储贵。需结合全量 + 增量/差异备份，在恢复成本与备份成本间平衡，并满足 RPO/RTO 目标。

## 二、核心原理
- 全量：完整拷贝基线。
- 增量：仅自上次备份（任意级）以来的变化（依赖链长、恢复慢）。
- 差异：自上次全量以来的变化（恢复只需全量+最新差异）。
- 合成全量：由全量+增量在备份服务端合成，减少源端压力。

## 三、形式化与数学基础
恢复所需备份数：
$$ N_{inc} = 1 + k \quad (\text{全量 + k 个增量}) $$
$$ N_{diff} = 2 \quad (\text{全量 + 1 差异}) $$
存储增长：
$$ Storage \approx Size_{full} + \sum \Delta_i $$

## 四、代码实现
```python
# 选择备份方式（仅示意）
def plan_backup(days_since_full, daily_delta, rto_budget):
    if days_since_full >= 7 or daily_delta > rto_budget:
        return "full"          # 周全量或变化大
    return "incremental"      # 否则增量
```

## 五、与其他技术对比
增量省空间但恢复链长；差异恢复快但占空间；合成全量兼顾。策略取决于 RPO/RTO 与存储预算。

## 六、常见误区
1) 增量链过长导致恢复脆弱——单环损坏全毁。
2) 只看备份成功不看恢复演练。
3) 忽视备份加密与权限。
