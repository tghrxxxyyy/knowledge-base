# 备份一致性与快照

> 对应 Rosenblum & Ousterhout 1992, *The Design and Implementation of a Log-Structured File System*（快照/写时复制思想），以及 Vonng/ddia（快照备份）。

## 一、背景与挑战
运行中的数据库文件在写入，直接拷贝会得到“撕裂”的不一致备份。需借助文件系统/卷快照或写时复制（CoW），在某一原子时刻获得一致视图。

## 二、核心原理
- 写时复制快照：对数据块做指针级快照，初始零拷贝，后续修改才复制旧块，从而得到“某一时刻”的不可变镜像。
- 与 WAL 配合：快照后记录快照对应的 WAL 位点，恢复时先还原快照再重放此后 WAL 达一致。
- 冻结（fsfreeze）可瞬时暂停写入保证应用一致性。

## 三、形式化与数学基础
快照一致性：
$$ \forall block\ b,\ Snapshot(b) = state\_at(t_{snap}) $$
CoW 写开销：
$$ Cost_{write} = O(1) + copy\_old\_block \ (\text{首次修改}) $$
配合 WAL 位点 $LSN_{snap}$，恢复一致性：
$$ Consistent \iff WAL\ replayed\ from\ LSN_{snap} $$

## 四、代码实现
```bash
# 仅示意：冻结 + 快照（Linux LVM 思路）
fsfreeze --freeze /data        # 暂停写入
lvcreate --snapshot --name snap /dev/vg/data
fsfreeze --unfreeze /data      # 恢复写入
```

## 五、与其他技术对比
热拷贝（无快照）需锁表或依赖 WAL 补偿；CoW 快照几乎零停顿、一致性好；但快照本身不是完整备份，仍需归档。

## 六、常见误区
1) 认为快照等于备份——快照多在同存储，需导出归档。
2) 忽略快照后 WAL 位点。
3) 长时间保留大量快照拖累性能。

## 九、演进与趋势
云卷快照 + WAL 归档一体化、应用一致快照、跨区快照复制。

## 十、小结
一致性备份靠快照（CoW）或冻结 + WAL 位点；快照是手段而非终点，须归档方可容灾。
