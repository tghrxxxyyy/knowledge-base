# 物理备份与逻辑备份

> 对应 Vonng/ddia 中文翻译（数据库运维与备份讨论），以及 Kleppmann《Designing Data-Intensive Applications》第 5 章（复制与持久性背景）。

## 一、背景与挑战
备份是灾难恢复的最后防线。物理备份复制数据文件（快、一致依赖机制），逻辑备份导出 SQL/数据（可跨版本/跨平台但慢）。二者互补。

## 二、核心原理
- 物理备份：直接拷贝数据目录/页（如文件系统快照、pg_basebackup），恢复快但要求同版本/同平台。
- 逻辑备份：导出表结构与数据（如 pg_dump、mysqldump），恢复慢但灵活、可选择性恢复单表。
- 一致物理备份需配合 WAL/快照以保证“某一时点一致”。

## 三、形式化与数学基础
备份窗口与恢复点：
$$ RPO = t_{fail} - t_{last\_backup} $$
物理备份时间：
$$ T_{phys} \approx \frac{Size_{data}}{IO_{copy}} $$
逻辑备份因重建索引/约束更慢：
$$ T_{logic} \gg T_{phys} $$

## 四、代码实现
```bash
# 仅示意命令行（非 Python 逻辑，展示两种备份）
# 物理：基于页拷贝
pg_basebackup -D /backup/data -Ft -P
# 逻辑：导出 SQL
pg_dump -Fp mydb > mydb.sql
```

## 五、与其他技术对比
物理备份快但耦合环境；逻辑备份慢但可移植、可过滤。生产常“物理全量 + 逻辑单表救援”组合。

## 六、常见误区
1) 认为逻辑备份能保证时间点一致——需事务/快照配合。
2) 忽略物理备份的版本绑定。
3) 只备不演练恢复——备份无用。
