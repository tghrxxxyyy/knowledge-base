# 全局历史与局部历史预测器

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》分支预测相关章节。

## 一、背景与挑战
分支间存在相关性：例如某个外层循环分支的结果依赖于内层分支历史。选择用"所有分支的全局历史"还是"单个分支自身的局部历史"索引 PHT，直接决定能否捕捉跨分支相关。

## 二、核心原理
全局历史（GHR）记录最近若干次所有分支的跳转结果；局部历史（LHR）为每个分支维护独立历史。gshare 用 GHR 与 PC 异或索引 PHT，gselect 用拼接。局部方案对"仅依赖自身模式"的分支更优，全局方案对跨分支相关更优。

## 三、形式化与数学基础
别名函数：gshare 索引 $I = (GHR \oplus PC_{tag}) \bmod 2^n$。若两个不同 PC 经异或映射到同一项称别名冲突。期望别名数随表大小 $N$ 减小而上升，故增大 $N$ 降低冲突：
$$Alias \approx \frac{P}{N}$$
其中 $P$ 为活跃分支数。

## 四、代码实现
```c
// 局部历史：每分支一个历史寄存器
unsigned short lhr[1024];   // 1024个分支, 10位历史
unsigned char lpht[1024][1024]; // 局部PHT

int predict_local(unsigned int pc_idx) {
    return lpht[pc_idx][lhr[pc_idx]] >= 2;
}
void update_local(unsigned int pc_idx, int taken) {
    int s = lhr[pc_idx];
    if (taken) { if (lpht[pc_idx][s] < 3) lpht[pc_idx][s]++; }
    else       { if (lpht[pc_idx][s] > 0) lpht[pc_idx][s]--; }
    lhr[pc_idx] = ((lhr[pc_idx] << 1) | (taken & 1)) & 0x3FF;
}
```

## 五、与其他技术对比
全局历史状态少、覆盖跨分支相关；局部历史状态大（每个分支一张表）但无跨分支相关。混合预测器（McFarling 1993）用选择器动态挑两者之一。

## 六、常见误区
误以为全局一定优于局部。在 SPECint 中二者互补，混合预测器常胜出。误以为 GHR 越长越好：过长会稀释 PHT 条目、增加冷启动错误。

## 七、与开源书/权威来源对应
量化方法对比 gshare/gselect；CMU 体系结构课程讲义有实验数据；CS-Notes 给出直观对比图。

## 八、面试题
问：gshare 与 gselect 索引方式差异及别名特性？答：gshare 异或、抗 PC 别名更强；gselect 拼接、表更大。问：何时局部历史优于全局？

## 九、演进与趋势
现代预测器采用多分量（TAGE）同时维护不同长度全局/局部分量，由提供预测的最长匹配分量胜出。

## 十、小结
全局与局部历史是捕捉分支相关性的两种正交视角，理解其冲突本质是设计混合/分量预测器的基础。
