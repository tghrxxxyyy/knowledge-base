# 分支预测准确率与误预测代价分析

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》性能量化章节。

## 一、背景与挑战
评估预测器不能只看准确率，还要看"误预测代价"。深层流水线下，一次误测可能损失 15-20 周期，因此降低误测率 1% 可能换来数百分比 IPC 提升。

## 二、核心原理
性能损失由误预测率 $MP$ 与每次误测惩罚 $P$ 共同决定。通过剖析（如 perf 的 branch-misses 事件）量化。分析时区分"可预测"（规则循环）与"难预测"（随机间接跳转）分支。

## 三、形式化与数学基础
理想 CPI 受分支影响：
$$CPI_{actual} = CPI_{base} + MP \times P$$
其中 $MP$ 为每指令误预测数。若 $IPC=1/ CPI$，则吞吐下降因子近似 $1/(1+MP\cdot P)$。

## 四、代码实现
```python
# 由perf样式的计数器估算代价
def ipc_loss(mispred_per_insn, penalty):
    # mispred_per_insn: 每指令误预测数, penalty: 周期
    added_cpi = mispred_per_insn * penalty
    return added_cpi

mp = 0.02   # 2% 指令误预测
print("额外CPI:", ipc_loss(mp, 15))
```

## 五、与其他技术对比
相比单纯比较准确率，考虑代价的"每千条指令误测数（MPKI）"更贴近实际。不同工作负载敏感度差异大：浮点密集负载对误测不敏感，整数/脚本语言 Dispatch 极敏感。

## 六、常见误区
误以为准确率 99% 已足够好：若代价 20 周期仍显著拖累。误把训练集准确率外推到所有负载。

## 七、与开源书/权威来源对应
量化方法以 SPEC CPU 为例给出 MPKI 分析；Linux perf 文档提供 branch-misses 计数。

## 八、面试题
问：为什么深层流水线放大误预测代价？答：FlushDelay 随级数上升。

## 九、演进与趋势
结合硬件采样（如 Intel LBR）在线分析难预测分支，指导编译器加 hint 或重排。

## 十、小结
预测器评估必须同时看准确率与代价，MPKI × 惩罚是更真实的性能指标。
