# 返回地址栈与间接分支预测

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》函数调用与返回章节。

## 一、背景与挑战
过程返回（ret）总是跳转到最近一次 call 的下一条指令；虚函数/函数指针等间接跳转目标多变。普通条件分支预测器对这两者效率低，需专门结构。

## 二、核心原理
返回地址栈（RAS）是一个小栈：执行 call 时把返回地址压栈，执行 ret 时弹出作为预测目标。RAS 与全局历史预测正交，对递归与嵌套调用几乎零误测。间接分支预测器则维护（PC → 目标）的缓存（BTB/ITTAGE），记录最近若干目标。

## 三、形式化与数学基础
RAS 深度为 $D$，栈顶指针 $sp$。压栈：$sp \leftarrow \min(sp+1, D)$， $S[sp] \leftarrow retAddr$。弹出：$target = S[sp]$， $sp \leftarrow \max(sp-1, 0)$。命中率随深度满足：
$$Hit \approx 1 - \left(\frac{overflow}{D}\right)$$
过浅 RAS 在深度递归时溢出导致误测。

## 四、代码实现
```c
// 返回地址栈模拟
unsigned long ras[16];
int rsp = 0;
void ras_call(unsigned long ret_addr) {
    if (rsp < 15) ras[++rsp] = ret_addr;
}
unsigned long ras_ret(void) {
    if (rsp > 0) return ras[rsp--];
    return 0; // 栈空, 需BTB预测
}
```

## 五、与其他技术对比
RAS 对返回类分支近乎完美，但无法处理间接跳转；间接目标预测器（ITTAGE）捕捉目标多变性。二者互补，现代前端同时部署。

## 六、常见误区
误以为 RAS 可替代 BTB。RAS 只处理返回，call 目标与间接跳转仍依赖 BTB。误以为 RAS 深度无关紧要，深度递归易溢出。

## 七、与开源书/权威来源对应
量化方法"分支目标缓冲与 RAS"；CSAPP 第3章函数调用栈与返回地址。

## 八、面试题
问：RAS 溢出会发生什么？答：返回目标预测退化为 BTB，可能误测。问：为什么递归不靠 BTB 而靠 RAS？

## 九、演进与趋势
RAS 引入推测压栈/恢复以支持乱序提交，间接预测器与 ITTAGE/微操作缓存结合。

## 十、小结
RAS 与间接预测器分别解决了"返回"和"多变目标"两类特殊控制流，是高精度前端不可或缺的部分。
