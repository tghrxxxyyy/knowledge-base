# 分支预测器硬件流水实现

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》指令流水线章节。

## 一、背景与挑战
分支预测器必须嵌入取指（Fetch）级，在指令 Cache 访问的同时给出下一 PC。预测错误时，已发射的后续指令必须被抹除并回滚，因此预测器与流水线深度、恢复机制强耦合。

## 二、核心原理
前端每周期从取指地址生成 PC，预测器产出"是否跳转"与"目标 PC"，二者送入 BTB 与目标缓冲。预测在取指级完成，误预测在后续级（如执行级确认方向）被发现，通过检查点恢复 GHR/RAS/计数器等全局状态。

## 三、形式化与数学基础
取指带宽受预测路径约束：每周期可取指 $W$ 条，但遇到预测为跳转则下一周起从目标取指。有效取指吞吐：
$$IPC_{fetch} \le \frac{W}{1 + MispredRate \times FlushDelay}$$
其中 $FlushDelay$ 为流水线清空周期数。

## 四、代码实现
```c
// 取指级预测流水线片段
struct fetch_state { unsigned pc; unsigned pred_pc; int pred_taken; };
void fetch_stage(unsigned *pc) {
    int taken = predict(*pc);
    unsigned tgt = btac_lookup(*pc);
    if (taken) *pc = tgt;
    else       *pc = *pc + 4;
}
```

## 五、与其他技术对比
无预测顺序取指每遇分支停顿；预测取指需额外 BTB/恢复逻辑。与乱序执行相比，预测器错误惩罚由流水线深度决定而非发射宽度。

## 六、常见误区
误以为预测只在取指级。方向在执行级确认，但目标已在取指级需要。误以为更深流水线总是更快：误预测惩罚随之增大。

## 七、与开源书/权威来源对应
量化方法流水线性能模型；CSAPP 第4章 Y86 流水线含分支处理。

## 八、面试题
问：误预测在哪一极被发现、恢复哪些状态？答：执行级确认，恢复 GHR/RAS/计数器等检查点。

## 九、演进与趋势
分支预测与指令预取、微操作缓存（uop cache）、循环流检测器（LSD）协同，减少取指级对预测器的依赖。

## 十、小结
预测器硬件实现的核心是与流水线深度匹配的低延迟查询与快速状态恢复，决定了实际前端吞吐。
