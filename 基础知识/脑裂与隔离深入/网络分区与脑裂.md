# 网络分区与脑裂

> 对应 Gilbert & Lynch 2002（CAP 定理证明，网络分区下的一致/可用取舍）与 Brewer 2000（CAP 猜想）。

## 一、背景与挑战
网络分区（network partition）是脑裂的诱因。根据 CAP，分区发生时系统必须在一致性（C）与可用性（A）间抉择，这直接决定脑裂期间的写策略。

## 二、核心原理
- CP 系统：分区时拒绝少数派写，保一致但牺牲可用。
- AP 系统：分区时两侧都可读写，保可用但产生分歧，需事后合并。
- 脑裂是 AP 系统分区时的必然现象，需靠冲突解决而非阻止。

## 三、形式化与数学基础
CAP 证明：异步网络下，若发生分区（P），则一致性（C）与可用性（A）不可兼得。选择 C 意味着少数派请求失败（防脑裂）；选择 A 意味着允许脑裂。

## 四、代码实现
# 分区下策略选择
def on_partition(side_size, N, mode):
    if mode == "CP":
        return side_size > N / 2   # 仅多数派可写
    return True                     # AP 两侧均可写

## 五、与其他技术对比
- 对比 CA 系统：单数据中心无 P 假设，但非真实分布式。
- 对比 quorum：quorum 是实现 CP 的具体手段。

## 六、常见误区
1. 以为“CAP 三选二”可静态固定——实则是分区时的取舍。
2. 忽略 AP 系统脑裂后的合并成本。

## 九、演进与趋势
用可调一致性（tunable consistency）在请求级决定 C 或 A。

## 十、小结
脑裂是 AP 系统在分区时的必然结果，设计重点从“防”转向“解”。
