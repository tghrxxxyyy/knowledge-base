# 脑裂问题概述

> 对应 Kleppmann DDIA 第8章（分布式系统中的脑裂）与 Gilbert & Lynch 2002（CAP 定理，网络分区下的行为）。

## 一、背景与挑战
脑裂（split-brain）指网络分区后，原本单一集群被割裂成多个子集，各自都认为自己是“主”，从而并行写入造成数据分歧甚至丢失。

## 二、核心原理
- 分区使节点间心跳/租约中断。
- 若缺乏仲裁，两侧都可能提升自己为主。
- 两侧独立写入后，分区恢复时无法自动合并冲突。

## 三、形式化与数学基础
设集群分两半规模 a 与 b（a+b=n）。若写入只需多数确认，则任何一侧要获得多数需 size > n/2。当 n 为奇数且一侧 < n/2 时无法达成写入，从而阻止双主。

## 四、代码实现
# 是否获得多数
def has_majority(members, live):
    return len([m for m in members if m in live]) > len(members) / 2

## 五、与其他技术对比
- 对比单主强一致：单主依赖选主防脑裂。
- 对比无主最终一致：Dynamo 风格用版本化解冲突而非防脑裂。

## 六、常见误区
1. 认为“主从”架构天然不会脑裂——异步复制仍可双主。
2. 以为心跳恢复即自动一致。

## 十、小结
脑裂源于分区下缺乏仲裁，核心是“谁能写”的全局判定。
