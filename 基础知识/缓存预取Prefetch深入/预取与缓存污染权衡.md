# 预取与缓存污染权衡

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》存储器层次设计章节；Drepper《What Every Programmer Should Know About Memory》；Chen & Baer 1995《Effective Hardware-Based Data Prefetching for High-Performance Processors》。

## 一、背景与挑战
预取把「未来可能使用的数据」提前放进容量固定的缓存。容量是零和的：任何一条预取行被插入，都可能对应一条有用行被驱逐。若预取行在被使用前就被换出，或者根本不会被使用，那么这次预取只贡献了带宽消耗和空间压力，这就是缓存污染（cache pollution）。

污染的隐蔽之处在于它不体现在预取自身的命中率上。预取可以「命中」得很好——数据显示预取行确实被拉进来了，但同一时间需求缺失率上升、IPC 下降，因为被挤掉的是别的数据。因此评价预取必须看整体指标，而不是预取子系统内部的计数。

## 二、核心原理
权衡由两个正交的指标刻画：准确率（accuracy，预取的行中有多少最终被使用）与覆盖度（coverage，全部本可预取的缺失中有多少被成功提前取到）。再叠加时效性（timeliness）：过早取到的行可能在使用前被驱逐，过晚则延迟没有覆盖。

工程上的常用手段有四类：
- 限制深度与距离：只取紧邻的少数行，剩下的交给需求访问自然带出。
- 降低目标层级：预取只到 L2/L3，避免直接占用紧张的 L1；L1 由需求访问或 L2 命中填充。
- 使用旁路策略：对一次性数据使用非临时预取，绕过缓存层次。
- 反馈限流：跟踪预取行是否在被驱逐前被使用，动态调整深度，或在 MSHR/带宽压力高时关闭预取。

另一个关键细节是插入位置。若预取行按最近使用（MRU）位置插入，会立刻成为被驱逐的候选；部分设计改为插入到 LRU 位置或专门的预取缓冲区，让它有机会被「提升」为需求命中，同时不挤掉热点数据——这正是 Jouppi 提出预取缓冲区的动机。

## 三、形式化与数学基础
设预取总数为 $P$，其中最终被使用 $U$，被驱逐的有用行数为 $E$，内存延迟为 $L_{mem}$，单次预取事务成本 $c_{pf}$：
$$Accuracy = \frac{U}{P}, \qquad Coverage = \frac{|\,prefetched \cap demanded\,|}{|\,demanded\,|}, \qquad Pollution = \frac{E}{P}$$
净收益判据可以写成
$$\Delta T = \alpha_{cov}\cdot N_{miss}\cdot L_{mem} - P\cdot c_{pf} - E\cdot c_{evict}$$
只有当第一项大于后两项之和时，预取才值得开启。若采用 AMAT 视角：
$$AMAT = t_{hit} + MR \cdot L_{mem}, \qquad MR = MR_{demand} + f(N_{pf}, \; cap_{eff})$$
预取降低 $MR_{demand}$，但占用容量后使有效容量 $cap_{eff}$ 下降，从而抬高其它访问的 $MR$。因此存在一个最优深度：
$$D^{*} = \arg\max_{D} \; \big[\,\alpha(D)\cdot L_{mem} - (1-\alpha(D))\cdot c_{evict} - c_{pf}\,\big]$$
其中 $\alpha(D)$ 通常随 $D$ 递减（越远越可能无用），而覆盖度随 $D$ 递增，两者共同决定极值点。这也是为什么固定深度不如自适应深度。

## 四、代码实现
带反馈的自适应深度控制器：跟踪「预取行是否在被驱逐前被使用」，据此调节深度，并在队列压力高时暂停。
```c
#define MAXD 8
typedef struct { int depth; int issued; int used; int throttled; } pf_ctrl_t;

void on_prefetch(void *line, pf_ctrl_t *c) { c->issued++; mark_pending(line); }
void on_use(void *line, pf_ctrl_t *c)       { if (unmark_pending(line)) c->used++; }

void periodic_tune(pf_ctrl_t *c, uint64_t inflight, uint64_t limit) {
    if (c->issued < 32) return;                 /* 样本不足不调整 */
    int acc = c->used * 100 / c->issued;
    if (inflight > limit * 3 / 4) {             /* 队列压力高：激进收缩 */
        c->depth = 1; c->throttled = 1;
    } else if (acc > 60 && c->depth < MAXD) {
        c->depth++; c->throttled = 0;
    } else if (acc < 20 && c->depth > 1) {
        c->depth--;                             /* 准确率低：保守收缩 */
    }
    c->issued = c->used = 0;
}
```
用模拟器度量污染时需要区分两类归因：由预取行插入直接驱逐的行数，以及因有效容量下降而增加的缺失。下面的计数器示意后者：
```python
def classify_misses(cache, trace):
    demand_miss = pf_miss = pf_useful = 0
    for tag, is_prefetch in trace:
        hit = cache.access(tag)
        if not hit:
            evicted = cache.insert(tag, is_prefetch)
            if is_prefetch:
                pf_miss += 1
            else:
                demand_miss += 1
            if evicted is not None and evicted.was_prefetched and not evicted.used:
                evicted_useful_after = True        # 被预取行挤掉、且自身未被使用
    return demand_miss, pf_miss, pf_useful
```

## 五、与其他技术对比
| 策略 | 准确率需求 | 污染风险 | 覆盖延迟 | 适用场景 |
| --- | --- | --- | --- | --- |
| 预取到 L1 | 高 | 最高 | 最好 | 短循环、数据量远小于 L1 |
| 预取到 L2 | 中 | 中 | 需一次 L2 命中延迟 | 一般数组遍历、通用工作负载 |
| 预取到 L3 | 低 | 低 | 延时较明显 | 大数据集、共享数据 |
| 非临时预取（旁路） | 低 | 极低 | 仅覆盖带宽等待 | 一次性流式数据 |
| 预取缓冲区（专用） | 中 | 低 | 需提升步骤 | 想避免挤占主缓存 |
| 不预取 | — | 无 | 无 | 容量极度紧张、随机访问 |

## 六、常见误区
- 认为预取不影响命中率。错误预取会显著降低有效命中率，尤其在缓存紧张的工作负载中。
- 只看预取自身的准确率，不看整体 IPC 与需求缺失率。准确率 90% 但在容量瓶颈下仍可能是净负收益。
- 认为「无用行会被立刻淘汰所以无所谓」。LRU 下被污染的行会在缓存中驻留完整一轮，期间一直在挤占空间。
- 忽视共享缓存的多租户效应。一个核的预取污染会影响同物理核或同 L3 切片的其它线程。
- 把深度调大当作调优手段。深度是收益与污染的权衡参数，不是单调指标。
- 忽略写入场景。写入引发的独占预取不仅占容量，还会无效化其它核的副本，污染与一致性成本叠加。

## 七、与开源书·权威来源对应
- Hennessy & Patterson：讨论预取收益随缓存大小、带宽与工作集的变化，指出预取存在最优强度而非单调收益。
- Jouppi 1990：提出用小型全相联预取缓冲区暂存预取行，让预取不直接挤占主缓存，是「减少污染」的经典设计。
- Drepper《What Every Programmer Should Know About Memory》：从程序员视角给出预取与局部性的实测与建议，强调过早/过量预取的危害。
- Chen & Baer 1995：建立准确率与覆盖度的分析框架，是评估预取污染的标准工具。
- Bryant & O'Hallaron《Computer Systems: A Programmer's Perspective》第 6 章：说明固定容量下局部性与冲突/容量缺失的取舍。

## 八、面试题
1. 如何衡量预取好坏？要点：看准确率、覆盖度，以及对整体命中率、带宽占用与 IPC 的净影响，而非预取条数或预取命中率。
2. 为什么把预取行插到 LRU 位置更有利？要点：避免立刻驱逐热点行，同时保留被提升为需求命中的机会。
3. 预取深度为什么存在最优值？要点：覆盖度随深度递增但准确率递减，收益是两者之差再扣成本，因此存在极值点。
4. 多核场景下污染有何不同？要点：污染作用在共享缓存上，会影响其它线程与其它租户，且与一致性流量叠加。
5. 什么情况下应该关闭预取？要点：工作集接近或超过缓存容量、访问模式随机、准确率持续偏低且带宽紧张时。

## 九、演进与趋势
硬度方向包括：反馈驱动的深度与开关控制（准确率/压力双反馈）、对有害预取的在线识别与黑名单、按缓存状态感知的插入策略。研究方向上，学习型预取器尝试更精准地选择候选行以减少污染；同时，可编程缓存管理与 CXL 等新内存层次让「预取到哪一层」成为新的权衡维度。具体能力以官方最新文档为准。

## 十、小结
预取不是免费午餐：它用有限容量和带宽换取延迟隐藏。真正的设计目标是让预取行在被驱逐前刚好被使用，判断标准必须落在整机的命中率与 IPC 上，而不是预取子系统自报的漂亮数字。
