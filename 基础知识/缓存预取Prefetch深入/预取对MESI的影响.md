# 预取对MESI的影响

> 对应 Intel SDM 卷3 与 MESI 缓存一致性协议相关章节。

## 一、背景与挑战
在多核系统中，预取不仅影响本地缓存，还会通过一致性协议（如 MESI）在其它核产生探测（snoop）流量，可能把远端缓存行变无效或触发写回。

## 二、核心原理
预取发出的读请求会使对应缓存行在本地进入 S（共享）或 E（独占）态，并触发其它核相应行降级（如 M→I 或 E→S）。过度预取放大一致性流量，反而拖累整体。

## 三、形式化与数学基础
MESI 状态转移：收到 Read(Exclusive) 时，持有者若处于 M 则写回并转 I。设预取使总线事务数增加 $\Delta B$，则一致性带宽占用：
$$BW_{coh} \propto B_{base} + \Delta B_{prefetch}$$
当 $\Delta B_{prefetch}$ 过大，内存与互联成为瓶颈。

## 四、代码实现
```c
// 多核下预取引发的伪共享示意
struct { int a; int b; } pad;
// 核0预取 a，核1预取 b，同缓存行 -> 反复 MESI 颠簸
```

## 五、与其他技术对比
单核预取只关乎本地命中；多核预取额外付出一致性代价，需更克制，常配合硬件抑制跨核无效预取。

## 六、常见误区
误以为预取对多核无副作用。实际上预取会制造虚假共享与探测风暴，恶化可扩展性。

## 七、与开源书/权威来源对应
Intel SDM 描述预取对一致性的影响；Hennessy & Patterson 第5章 / 多核章节讨论一致性流量与伪共享。

## 八、面试题
问：预取如何导致伪共享？答：预取相邻变量可能把同缓存行的另一核数据拉入并触发无效，引发无谓颠簸。

## 九、演进与趋势
硬件区分「本地需求预取」与「一致性安全」，对可能跨核的预取施加抑制，并引入目录协议降低广播。

## 十、小结
预取在单核是性能优化，在多核还需考虑一致性开销，盲目预取会放大 MESI 流量、损害扩展性。
