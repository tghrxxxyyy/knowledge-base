# 硬件流预取器原理

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》第5章。

## 一、背景与挑战
顺序访存（如数组遍历）存在强空间局部性，但 CPU 取指/取数总滞后于需求。流预取器（stream prefetcher）主动把后续缓存行提前载入，隐藏内存延迟。

## 二、核心原理
硬件监测缓存缺失的地址序列，当检测到连续的行访问流（stride=1 或固定步长）时，自动发出后续行的预取请求。预取器维护若干「流」，每个流记录起始地址、方向、步长与已预取深度。

## 三、形式化与数学基础
设访问序列 $a_k = a_0 + k\cdot s$，$s$ 为缓存行大小的倍数。预取触发条件：连续 $n$ 次访问满足
$$|a_{k+1}-a_k - s| < \epsilon$$
则对流 $i$ 预取 $a_{k+1+j},\; j=1..D$，$D$ 为预取深度。

## 四、代码实现
```c
// 流预取器检测示意
void on_miss(uint64_t addr){
    int line = addr / LINESIZE;
    if (last_line + 1 == line && stream_active){
        for (int j=1;j<=DEPTH;j++)
            prefetch_line((line+j)*LINESIZE);
    } else {
        last_line = line; stream_active = 1;
    }
}
```

## 五、与其他技术对比
硬件流预取无需软件改动，但只能捕捉规则流；软件预取可针对不规则但已知模式，代价是额外指令与调优负担。

## 六、常见误区
误以为预取越多越好。过度预取会挤占内存带宽、污染缓存并驱逐有用数据。

## 七、与开源书/权威来源对应
Hennessy & Patterson 第5章讨论多级缓存与预取对缺失率的影响；CSAPP 第6章以矩阵遍历展示空间局部性收益。

## 八、面试题
问：预取为何可能降低性能？答：占用带宽、污染有限缓存行、预取无用数据导致后续有用数据被驱逐。

## 九、演进与趋势
从单一 L2 流预取向 L1/L2 多级、结合访问历史学习（如 Sandbox 预取）的方向发展。

## 十、小结
流预取以「识别规则访存流并提前取数」为核心，是隐藏内存延迟最简单有效的硬件手段。
