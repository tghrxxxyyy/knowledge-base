# stride与上下文切换开销

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》第5章。

## 一、背景与挑战
步长预取器的内部状态（上次地址、步长）在进程上下文切换后可能失效或污染，导致新进程得到错误预取流，甚至泄露跨进程信息。

## 二、核心原理
上下文切换使地址空间改变，预取器需重置或按 ASID/PC 上下文隔离流状态。若不分上下文，旧进程学到的步长会误用于新进程，造成无谓带宽浪费。

## 三、形式化与数学基础
设切换前后进程 $P_A,P_B$ 的访问步长分别为 $s_A,s_B$。若不隔离，流状态 $S$ 在切换后延续，导致预取地址偏差：
$$\hat a = a_{last,A} + s_A \neq a_0 + s_B$$
产生无效预取，污染率上升。

## 四、代码实现
```c
// 上下文切换时清空/切换预取状态
void context_switch(pid_t new){
    for (int i=0;i<N;i++){ sdt[i].state = 0; sdt[i].last = 0; }
    current_asid = new;
}
```

## 五、与其他技术对比
按 ASID 分区的预取器避免污染但占用更多存储；全清零简单但冷启动代价高。这是面积与正确性的权衡。

## 六、常见误区
误认为预取器状态可在进程间共享。共享会跨进程污染，且现代安全模型要求切换时清理推测状态。

## 七、与开源书/权威来源对应
Hennessy & Patterson 讨论多道程序下缓存与预取器的上下文影响；Spectre/Meltdown 披露后，厂商文档强调切换时刷新推测结构。

## 八、面试题
问：为何上下文切换要清预取状态？答：避免跨进程污染与侧信道泄露，同时防止错误步长产生无效预取。

## 九、演进与趋势
硬件引入按上下文标记的预取表与切换时选择性刷新（如只刷受影响集合），平衡安全与冷启动。

## 十、小结
步长预取状态是有状态的，上下文切换必须妥善隔离或重置，否则既损性能又生安全隐患。
