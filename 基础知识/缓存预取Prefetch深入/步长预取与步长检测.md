# 步长预取与步长检测

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》第5章。

## 一、背景与挑战
许多访问模式并非单位步长（如遍历每第 k 个元素、结构体数组按字段偏移），需要检测任意步长 $s$ 才能有效预取。

## 二、核心原理
步长预取器为每个活跃流维护「上一次地址」与「当前推断步长」。当新缺失地址与上次之差等于已学步长，则按该步长继续预取；否则重新学习。常用多寄存器表（stride detection table）缓存最近地址与步长。

## 三、形式化与数学基础
设第 $k$ 次访问 $a_k$。步长状态机：
$$s_{k+1}= \begin{cases} a_{k+1}-a_k & \text{if } \text{state}=\text{init}\\ s_k & \text{if } a_{k+1}-a_k=s_k\\ \text{learn}(a_{k+1}-a_k) & \text{otherwise} \end{cases}$$
预取地址 $p = a_k + m\cdot s_k,\; m=1..D$。

## 四、代码实现
```c
// 步长检测表项
typedef struct { uint64_t last; int64_t stride; int state; } SD;
SD tbl[N];
void access(uint64_t a, int id){
    if (tbl[id].state==1 && a-tbl[id].last==tbl[id].stride)
        prefetch(a + tbl[id].stride * DEPTH);
    else { tbl[id].stride = a - tbl[id].last; tbl[id].state = 1; }
    tbl[id].last = a;
}
```

## 五、与其他技术对比
单位流预取是步长预取 $s=1$ 的特例。步长预取更通用，但需存储与比较步长，硬件更复杂。

## 六、常见误区
误认为步长预取能处理随机访问。随机模式无稳定步长，预取器会频繁重置，反而无效。

## 七、与开源书/权威来源对应
Hennessy & Patterson 在预取章节区分了顺序与步长模式；CSAPP 第6章矩阵访问顺序（行优先 vs 列优先）正是步长差异的实例。

## 八、面试题
问：为何列优先遍历大矩阵慢？答：步长等于行宽，跨越缓存行多、空间局部性差，步长预取收益低且易失效。

## 九、演进与趋势
结合上下文（如 PC 关联）区分同地址不同步长流，减少别名，提升检测准确率。

## 十、小结
步长预取通过「学习并复用访问间距」覆盖非单位规则模式，是对流预取的必要泛化。
