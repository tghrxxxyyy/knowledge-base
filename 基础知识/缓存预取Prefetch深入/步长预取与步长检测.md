# 步长预取与步长检测

> 对应 Chen & Baer 1995《Effective Hardware-Based Data Prefetching for High-Performance Processors》；Baer & Chen 1991《An Effective On-Chip Preloading Scheme to Reduce Data Access Penalty》；Hennessy & Patterson《Computer Architecture: A Quantitative Approach》存储器层次章节。

## 一、背景与挑战
许多访问模式并非单位步长：遍历结构体数组时按字段偏移跳步、矩阵按列访问时步长等于行宽、图像处理按行跨距取样、FFT 的蝶形访问、稀疏矩阵按固定 stride 取对角线。单位步长的流预取器对这些模式完全失效——因为相邻缺失地址之差不是 1。

步长预取器要解决的问题变成：在没有编译器信息的情况下，从缺失地址序列中「在线学习」出步长，并据此预测后续地址。挑战包括学习延迟（要看到几次相同差值才能确认）、别名（不同流映射到同一表项）、以及步长为负或多流交替时的正确性。

## 二、核心原理
步长预取器为每个活跃流维护一组状态：上次访问地址、当前推断步长、置信度计数（通常 2 位）。当新的缺失地址与上次地址之差等于已学步长时，置信度上升；达到阈值后开始按步长发出预取。差值改变时，用新差值替换旧步长并把置信度清零，形成「重新学习」。

工程实现常称为步长检测表（stride detection table，SDT）或引用预测表（reference prediction table，RPT），表项索引来自 PC、地址或两者的散列。几个关键设计选择：
- 用几次确认：典型是连续 2～3 次相同差值才认流，避免把随机访问误判为规则流。
- 索引方式：用触发缺失的 PC 参与索引可以区分「同一页内不同循环的不同步长」，减少别名；只用地址则更省硬件但别名更多。
- 预取深度与步长倍数：预取地址为 $a_k + m\cdot s$，通常 $m$ 从 1 递增到 $D$；步长大时同一深度覆盖的地址空间更远（可能跨越更多页）。
- 负步长支持：需要带符号比较与方向位，向下遍历数组时同样有效。

## 三、形式化与数学基础
设第 $k$ 次缺失地址为 $a_k$，差值 $\delta_k = a_k - a_{k-1}$。步长状态机的更新规则：
$$s_{k} = \begin{cases} \delta_k & \text{首次或 } \delta_k \neq s_{k-1}\ (\text{重置置信度}) \\ s_{k-1} & \delta_k = s_{k-1}\ (\text{置信度} +1) \end{cases}$$
只有当置信度达到阈值 $\theta$（对应 $\theta+1$ 次一致差值）时才发出预取：
$$p_m = a_k + m \cdot s_k, \qquad m = 1..D$$
以缓存行为单位（步长 $s$ 折算为行数 $s/L_{line}$）时，预取应跳过已取到的部分：
$$p_m = a_k + m\cdot s_k, \quad m = 1..D \quad\text{且} \quad \frac{p_m - a_k}{L_{line}} > D_{already}$$
把有效预取比例记为 $\alpha$，流被误检（随机访问凑巧满足差值）的概率随阈值 $\theta$ 指数下降：若单次差值偶然相等的概率为 $\pi$，则误检概率约
$$P_{false} \approx \pi^{\theta}$$
而学习延迟（错过多少次必要预取）为 $\theta$ 次缺失，因此阈值选择是「误检率」与「学习代价」的权衡，实际系统中通常取 $\theta \in \{1,2\}$。

## 四、代码实现
带置信度与负步长支持的最小 SDT：
```c
#include <stdint.h>
#include <stdbool.h>

#define SDT_N   64          /* 表项数（2 的幂） */
#define THRESH  2           /* 2 位置信度：连续 3 次一致才预取 */
#define DEPTH   4

typedef struct { uint64_t last; int64_t stride; uint8_t conf; bool valid; } sdt_t;
static sdt_t sdt[SDT_N];

void on_miss(uint64_t addr, uint64_t pc) {
    /* 索引：地址低位与 PC 低位混合，降低不同流的别名概率 */
    unsigned idx = (unsigned)(((addr >> 6) ^ (pc >> 4)) & (SDT_N - 1));
    sdt_t *e = &sdt[idx];
    int64_t delta = e->valid ? (int64_t)addr - (int64_t)e->last : 0;

    if (e->valid && delta == e->stride) {
        if (e->conf < THRESH + 1) e->conf++;
        if (e->conf > THRESH) {                       /* 置信度足够：发预取 */
            for (int m = 1; m <= DEPTH; m++) {
                int64_t a = (int64_t)addr + m * e->stride;
                if (a > 0) issue_prefetch((uint64_t)a);   /* 边界检查 */
            }
        }
    } else {
        e->stride = delta; e->conf = 0; e->valid = true;   /* 重新学习 */
    }
    e->last = addr;
}
```
用一段脚本量化「随机访问下的误检率」可以验证阈值选择：
```python
import random
def false_rate(theta, n=200000, span=1 << 20):
    prev, stride, conf, total = None, None, 0, 0
    for _ in range(n):
        cur = random.randrange(span)
        if prev is not None:
            d = cur - prev
            if stride is not None and d == stride:
                conf += 1
                if conf > theta:
                    total += 1               # 误判为流并发出预取
            else:
                stride, conf = d, 0
        prev = cur
    return total / n
print([ (t, round(false_rate(t), 6)) for t in (0, 1, 2, 3) ])
```

## 五、与其他技术对比
| 机制 | 可处理的步长 | 硬件状态 | 学习代价 | 主要弱点 |
| --- | --- | --- | --- | --- |
| 顺序流预取 | 仅 $s = L_{line}$ | 极少 | 极低 | 非单位步长全失效 |
| 步长预取（SDT/RPT） | 任意固定 $s$ | 每项含步长与置信度 | $\theta$ 次缺失 | 别名、多流交替、变步长 |
| GHB + 差值相关 | 变化的差值序列 | 历史表较大 | 需历史匹配 | 冷启动慢、表容量压力 |
| 空间化预取 | 同页内多点模式 | 页级标记 | 需训练位图 | 页内局部性差时无效 |
| 软件预取 | 编译器可静态判断 | 无 | 无（编译期） | 需人工/编译器支持 |

## 六、常见误区
- 认为步长预取能处理随机访问。随机序列没有稳定步长，表项不断被重置，预取要么不发要么发错。
- 认为只有步长 1 才算「流」。结构体数组按字段遍历、矩阵按列访问都是固定步长，是最典型的受益场景。
- 忽略负步长。向后遍历数组（如从尾部扫描）需要带符号步长与方向判断。
- 忽视别名。地址散列索引会让不同流落到同一表项，互相覆盖导致两条流都学不出来。
- 认为阈值越低越好。阈值低则学习快但误检率高，会把随机访问当作流，产生大量污染。
- 混淆「步长检测」与「地址预测」。检测出步长只是第一步，预取时刻、深度与层级同样决定成败。

## 七、与开源书·权威来源对应
- Chen & Baer 1995：给出步长预取器的结构与准确率/覆盖率评估，是步长检测算法的经典文献。
- Baer & Chen 1991：更早提出片上预取方案，讨论预取深度与缓存容量的关系。
- Hennessy & Patterson：在预取讨论中区分顺序模式与大步长模式，并说明预取收益依赖于访问规律性。
- Bryant & O'Hallaron《Computer Systems: A Programmer's Perspective》第 6 章：行优先与列优先遍历大矩阵的性能差异，正是步长效应在程序层面的体现。
- Drepper《What Every Programmer Should Know About Memory》：以逐元素跨步访问为例说明步长对缓存与 TLB 的双重压力。

## 八、面试题
1. 为什么列优先遍历大矩阵慢？要点：步长等于行宽，每次访问跨越整行，缓存行利用率低、TLB 覆盖页数多，步长预取的收益也被摊薄。
2. 步长检测为什么需要置信度计数？要点：避免随机差值被误判为规律，用连续一致次数把误检概率压到 $\pi^{\theta}$ 量级。
3. 表项别名会带来什么后果？要点：不同流互相覆盖状态，导致反复重新学习、预取时有时无，表现为性能抖动。
4. 负步长需要哪些额外硬件？要点：带符号比较与方向位，且预取地址计算要支持减法与下界检查。
5. 步长预取与顺序流预取是什么关系？要点：顺序流是步长等于缓存行大小的特例，步长预取是其泛化，代价是更多状态与比较逻辑。

## 九、演进与趋势
演进方向包括：把 PC 或上下文信息纳入索引以降低别名；支持「多流并发」的表组织（同一 PC 对应多条流）；用差值相关或历史表处理变步长序列；跨页步长预取与 TLB 协同以覆盖大步长场景。此外，学习型方法尝试用更长的历史窗口预测复杂但不完全规则的地址序列，其工程可行性仍在验证中，具体以官方最新文档为准。

## 十、小结
步长预取通过「学习并复用访问间距」把顺序流预取推广到任意固定步长，代价是状态、比较逻辑与学习延迟。它的核心工程问题不是算法本身，而是别名控制与阈值选择：学得太慢错过收益，学得太快引入污染。
