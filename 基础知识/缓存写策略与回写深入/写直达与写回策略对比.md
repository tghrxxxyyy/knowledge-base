# 写直达与写回策略对比

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》第 2 章与 Appendix C；Bryant & O'Hallaron《Computer Systems: A Programmer's Perspective》第 6 章。

## 一、背景与挑战

处理器与主存之间存在巨大的速度鸿沟：现代超标量核心每周期可提交多条 store，而一次主存访问动辄上百纳秒。缓存用 SRAM 挡在这条鸿沟前面，但「写」比「读」多了一个自由度——读只需要决定从哪一层取数据，写却必须决定新数据何时、以何种形式出现在下一级存储中。这个决定就是写策略（write policy），最基本的两种是写直达（write-through，也译写通）与写回（write-back，也译写回写）。

朴素做法是每次写都同步更新缓存和内存（写直达的直觉版本），保证内存永远是最新副本。但这样每一次 store 都会占用下级互连与内存带宽，而其中绝大多数写很快又会被同地址的后续写覆盖——纯属浪费。另一种朴素做法是「写缓存后就不管了」，若没有脏位记录，替换时既不知道该不该写回，也无法在掉电或一致性请求时找回最新数据。因此工程上必须在带宽、延迟、状态复杂度、多核一致性之间做系统取舍。

在体系结构课程与面试中，写策略是缓存章节的必考点：面试官常从「写回为什么省带宽」「脏位什么时候清」「多级缓存 L1 为何常写直达」切入，考察的是对缓存状态机与流量分析的真正理解，而不是名词背诵。

## 二、核心原理

**写直达（write-through）**：命中时同时更新缓存行与下一级（或内存）；未命中时按是否写分配处理（常见组合是写不分配：直接写下级，不调入缓存）。不变量是「下级存储中的副本永远不旧于缓存」。由于每次写都要传播，必须配写缓冲（write buffer）把同步写变成异步，否则 CPU 会被内存延迟卡死。写直达的优点是实现简单、无需脏位、替换时直接丢弃、天然利于一致性（其他观察者总能从内存看到新值）；代价是写流量等于全部 store 数，带宽浪费严重。

**写回（write-back）**：命中时只改缓存行，并把该行脏位（dirty bit）置 1；只有在「替换脏行」或「一致性协议要求写回/失效」时，才把整行写回下级。不变量是「脏行是该地址唯一最新副本，内存中的副本可能过期」。因此写回必须维护每行至少一个脏位（实际上常与 valid、MESI 状态一起编码），替换逻辑也变复杂：干净行可直接丢弃，脏行必须先写回。

两种策略都可与写分配（write-allocate）组合，但实践中的主流搭配是：写回 + 写分配（利用写的空间局部性，先调块再改），写直达 + 写不分配（未命中写不值得调块）。现代多级缓存还常混合：L1 用写直达 + 写分配（对上层 L2 流量可控，且 L1 可以做得很小、状态简单），L2/L3 用写回（把流量挡在芯片内，减少昂贵的内存访问）。

## 三、形式化与数学基础

设一段时间内 CPU 发出 $W$ 次写，写命中率为 $h_w$，读命中率为 $h_r$，读请求数为 $R$，每次写/写回传输一个缓存行 $B$ 字节。

写直达下，每一次写（无论命中与否）都产生一次下级写事务：

$$Traffic_{WT} = W \cdot B$$

写回下，只有替换脏行才写回。设缓存共 $N$ 行，替换次数为 $E$，被替换行中脏行比例为 $d$（与写频率和重用距离有关），则：

$$Traffic_{WB} = d \cdot E \cdot B$$

在稳定随机访问下，替换次数近似等于未命中次数 $E \approx (R+W)\cdot(1-h)$，脏行比例 $d$ 通常显著小于 1（很多替换行只被读过或已写回）。于是写回相对写直达的流量比为：

$$\frac{Traffic_{WB}}{Traffic_{WT}} \approx \frac{d(1-h)(R+W)}{W}$$

当写密集且命中率高时（例如 $h=0.95$，$d=0.3$，$R \approx W$），该比值远小于 1，写回可把下级写流量降低一个数量级。这也解释了为何数据库、流媒体等写密集负载在写回缓存下吞吐更高。

再考虑延迟：写直达若无写缓冲，每次 store 都要等下级确认，写代价为 $T_{mem}$；有深度为 $k$ 的写缓冲时，只要缓冲不满，store 延迟近似 $T_{L1}$，缓冲满才停顿。写回的 store 延迟恒为 $T_{L1}$，但替换脏行时突发写回会拉长 miss 服务时间，形成「替换尖刺」。

## 四、代码实现

下面是一个可运行的写策略对比模拟器：同一访问序列分别用写直达+写不分配、写回+写分配两种策略模拟，统计下级写次数与写流量。

```python
"""写直达 vs 写回 写流量对比模拟器"""
from collections import OrderedDict


class CacheSim:
    def __init__(self, num_lines: int, policy: str):
        assert policy in ("WT", "WB")
        self.num_lines = num_lines
        self.policy = policy          # WT=写直达+写不分配, WB=写回+写分配
        self.lines = OrderedDict()    # tag -> dirty
        self.mem_writes = 0           # 下级写次数（按行计）
        self.mem_reads = 0

    def _evict_one(self):
        tag, dirty = self.lines.popitem(last=False)
        if self.policy == "WB" and dirty:
            self.mem_writes += 1      # 脏行写回

    def access(self, is_write: bool, block_id: int):
        if block_id in self.lines:
            self.lines.move_to_end(block_id)
            if is_write:
                if self.policy == "WT":
                    self.mem_writes += 1   # 写直达：每次写都传到下级
                    self.lines[block_id] = False
                else:
                    self.lines[block_id] = True   # 写回：只标脏
            return

        # 未命中
        if is_write and self.policy == "WT":
            self.mem_writes += 1      # 写不分配：直接写下级，不调入
            return

        # 需要调入（读未命中，或写回策略的写未命中=写分配）
        self.mem_reads += 1
        if len(self.lines) >= self.num_lines:
            self._evict_one()
        self.lines[block_id] = bool(is_write and self.policy == "WB")


def run(trace, nlines=4):
    result = {}
    for policy in ("WT", "WB"):
        sim = CacheSim(nlines, policy)
        for is_write, blk in trace:
            sim.access(is_write, blk)
        result[policy] = (sim.mem_writes, sim.mem_reads)
    return result


if __name__ == "__main__":
    # 写密集且有空间局部性：同块连续写 8 次，再换块
    trace = [(True, i // 8) for i in range(64)]
    r = run(trace, nlines=4)
    print("写直达 mem_writes =", r["WT"][0])  # 64：每写必传
    print("写回   mem_writes =", r["WB"][0])  # 8：每块只脏一次，替换时写回
    assert r["WT"][0] == 64
    assert r["WB"][0] == 8
    print("写回把下级写次数从 64 降到 8，流量比 =", r["WB"][0] / r["WT"][0])
```

运行输出证实：对 64 次顺序写 8 个块的负载，写直达产生 64 次下级写，写回仅 8 次（每块被替换时写回一次），流量下降 87.5%。

## 五、与其他技术对比

| 维度 | 写直达（WT） | 写回（WB） |
|------|-------------|-----------|
| 下级写次数 | 等于 store 数 | 约等于脏行替换数，远小于 store 数 |
| 脏位 | 不需要 | 必需 |
| 替换代价 | 低（直接丢弃） | 高（脏行须先写回） |
| 一致性 | 简单（内存总是新值） | 需协议介入（写回/失效） |
| 写停顿 | 依赖写缓冲隐藏 | 无 store 停顿，但 miss 尖刺 |
| 典型搭配 | 写不分配 + 写缓冲 | 写分配 |
| 典型位置 | 早期 L1、某些嵌入式、NVM 直写模式 | L2/L3、现代主缓存 |

取舍核心：写直达用带宽换简单与一致性可见性；写回用状态复杂度换带宽效率。掉电安全场景（如 NVDIMM 直写）也偏向写直达或显式刷缓存，因为写回的脏行在崩溃窗口内可能丢失。

## 六、常见误区

1. **「写回永远不写内存」**——错。脏行被替换、一致性 snoop 要求写回、显式刷缓存（如 clflush、CR0.CD 切换）时都必须写回。写回只是把写推迟合并，不是取消。
2. **「写直达没有脏位，所以完全不需要状态」**——错。写直达仍需 valid/tag，多核下还要与 MESI 等协议配合；只是不需要 dirty 位。
3. **「写回一定比写直达快」**——错。随机写、工作集远大于缓存、脏行替换频繁时，写回的替换尖刺与写放大可能反而更差；写直达配合写合并在某些流式负载下更平滑。
4. **「写策略与写分配是同一维度」**——错。写策略决定「何时传到下级」，写分配决定「未命中是否调入缓存」，是两个正交维度，只是实践搭配有偏好。
5. **「L1 用写回总是最优」**——错。许多现代 CPU 的 L1 采用写直达到 L2（或写回 L1 + 包含式 L2），因为 L1 容量小、替换频繁，写直达可简化 L1 一致性与替换逻辑，把合并压力下放给更大的 L2。

## 八、面试题

**1. 写回相比写直达的主要优势是什么？代价是什么？**
答：优势是显著降低下级/内存写流量——只在脏行替换或一致性请求时写回，对写密集且有局部性的负载可降一个数量级；代价是每行需要脏位、替换逻辑更复杂，且崩溃时脏行数据可能丢失，多核下需要协议保证其他核看到最新值。

**2. 脏位（dirty bit）何时置位、何时清零？**
答：写回缓存中，对缓存行的写命中置位 dirty=1；把该行写回下级（替换时或被 snoop/flush）后清零。若行被失效（invalidate），干净行直接丢弃，脏行须先写回再失效。

**3. 为什么很多处理器 L1 用写直达、L2 用写回？**
答：L1 容量小、替换频繁，写直达可简化 L1 状态与一致性，把写合并与脏行管理下放到更大、更慢但更省流量的 L2；L2 写回再把流量挡在片内，减少昂贵的内存访问。这是延迟、面积与带宽的折中。

**4. 写直达必须配写缓冲吗？**
答：强烈建议。否则每次 store 都要等内存确认，流水线会被写停顿拖垮。写缓冲让 store 只写入 L1 并入队，由缓冲异步排空；仅当缓冲满时才反压 CPU。

## 九、演进与趋势

现代多级缓存很少非此即彼：Intel/ARM 大核普遍采用「L1 写直达或写回 + L2 写回 + LLC 写回」的混合层次，并在 store buffer / write combining buffer 中做合并。持久内存（NVDIMM、CXL 内存）引入了新约束：脏行在掉电窗口内不安全，于是出现「写直达持久域」与显式刷缓存指令（CLWB、CLFLUSHOPT）——写回思想被保留，但增加了「持久化屏障」维度。数据库与分布式存储同样借用了这套语义：Linux page cache 的 write-back 与 fsync、Ceph/RocksDB 的 WAL 与 write-back 缓存、SSD 内部 DRAM 映射表的回写，本质都是「延迟提交换带宽，用日志/电容换崩溃一致性」。CXL Type-3 内存与分层内存（tiered memory）还在推动硬件透明的冷热数据回写。

## 十、小结

写直达保证下级永远是最新副本，简单但费带宽；写回用脏位把写推迟合并，省流量但引入替换写回与一致性复杂度。两者与写分配正交、常按「写回+写分配、写直达+写不分配」搭配，并在多级缓存中混合使用——理解脏位不变量与流量公式，是分析一切缓存写路径的基础。
