# 写分配与写不分配

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》Appendix C；Bryant & O'Hallaron《CSAPP》第 6 章。

## 一、背景与挑战

写未命中（write miss）发生时，硬件面临一个比读未命中更微妙的决策：是要不要先把包含目标地址的那个缓存行从下级取进缓存，再在缓存里完成这次写？还是干脆跳过缓存、直接把数据写到下级存储？前者叫写分配（write-allocate / fetch-on-write），后者叫写不分配（no-write-allocate / write-around）。这个决策直接决定缓存污染程度、后续命中率与未命中代价。

朴素的直觉有两个极端。一是「凡写必调块」：实现最统一（写未命中就复用读未命中路径），但如果访问是纯流式的（如 `memset`、顺序写大数组，写完再也不读），调进来的块用一次就被替换，白白占用缓存空间并挤掉热点数据，还多付一次下级读。二是「凡写必绕过」：省下调块流量，但对有空间局部性的写（同一行内连续多字写）会反复未命中、反复写穿下级，错过合并机会。两种极端在各自不利的负载上都会明显掉速。

在工程与面试里，写分配常与写回绑定讨论，写不分配常与写直达绑定讨论——但它们是两个正交维度。面试题往往从「写未命中为什么常用写分配」「流式写怎样避免污染」切入，考察的是对局部性、缓存污染与流量的综合判断。

## 二、核心原理

**写分配（write-allocate）**：写未命中时，先执行一次块读（等价于读未命中：分配行、填入数据），然后在缓存行上完成写。若配写回策略，则把该行标脏。其正确性依赖一个假设：该地址附近即将被再次访问（时间或空间局部性）。一旦成立，这次「先付一次块读」的投资会在后续命中中赚回来；若不成立，就是纯浪费——付出块读流量 + 污染缓存 + 迟早还要写回（若配写回）。

**写不分配（no-write-allocate）**：写未命中时直接写向下级（通常经写缓冲），不调入缓存。缓存内容不变，自然也无污染。若配写直达，则命中时也是缓存与下级同写。适合「写一次就走」的流式数据。需要注意：写不分配并不等于「永不读块」——同一地址若被读，仍会走读未命中路径调入。

**边界条件与不变量**：
- 写分配命中后，行的状态由写策略决定（写回置脏；写直达则下级同步更新）。
- 写不分配时，若该块恰已在缓存中（这次是「未命中」的定义要小心：若块在缓存则是命中写），一般仍按命中路径处理；写不分配主要作用于未命中。
- 与写缓冲交互：写不分配产生的下级写进入写缓冲合并；写分配产生的块读可能与缓冲中的同地址写发生 RAW 冲突，需要「写缓冲读穿透」（read forwarding / write drain）保证读到新值。

现代缓存更常见的组合是「写回 + 写分配」：写回让缓存行成为唯一最新副本，写分配保证「改之前先把最新内容拿进来」——否则只改一个字节却不知道行内其他字节，会写坏整行。这也是写分配几乎总与写回同现的根本原因（写直达不分配也合法，但局部性差时更亏）。

## 三、形式化与数学基础

设一段访存轨迹中写操作 $W$ 次，目标块互不相同的写块数为 $U$（$U \le W$），同一块上连续写次数均值为 $\bar{k} = W/U$。设缓存行大小 $B$，下级读代价 $T_r$，下级写代价 $T_w$。

写分配的代价模型（配写回）：对每个新块，一次块读 $B$ 字节；之后该块内写全为命中；块被替换时若脏则一次写回。

$$Cost_{WA} = U \cdot T_r + D \cdot T_w$$

其中 $D$ 为被替换脏行数（$D \le U$）。有效「摊还到每次写」的代价为：

$$\frac{Cost_{WA}}{W} = \frac{T_r}{\bar{k}} + \frac{D}{W} T_w$$

写不分配的代价模型（配写直达）：每次未命中写都是一次下级写，命中写也写下级：

$$Cost_{NWA} = W \cdot T_w$$

（若进一步计入命中写也写穿，则更准确是全部 $W$ 次写都产生下级写事务。）

比较两者：当 $\bar{k}$ 大（空间局部性好）且 $T_r \approx T_w$ 时，$\frac{T_r}{\bar{k}} \ll T_w$，写分配明显占优；当 $\bar{k} \to 1$（纯流式、写一次就走）时，写分配要付 $T_r$ 且污染缓存，可能不如写不分配。再考虑缓存污染代价：设被调入的流式块驱逐了有用块，引起额外读缺失次数 $M$，其代价 $M \cdot T_r$ 必须计入写分配一侧：

$$Cost_{WA}' = Cost_{WA} + M \cdot T_r$$

在大流式写负载下 $M$ 可能接近 $U$，此时写分配几乎总是更差——这就是非临时写（non-temporal store）存在的定量理由。

## 四、代码实现

下面的模拟器在固定缓存容量下，对比「写分配+写回」与「写不分配+写直达」在两种负载（流式写、块内重复写）下的下级读写次数。

```python
"""写分配 vs 写不分配 对比模拟器"""
from collections import OrderedDict


class WritePolicyCache:
    def __init__(self, n_lines: int, write_allocate: bool):
        self.n_lines = n_lines
        self.wa = write_allocate           # True=写分配+写回, False=写不分配+写直达
        self.lines = OrderedDict()         # tag -> dirty
        self.mem_writes = 0
        self.mem_reads = 0
        self.hits = 0
        self.misses = 0

    def _evict(self):
        _, dirty = self.lines.popitem(last=False)
        if dirty:  # 写回策略才会有脏行
            self.mem_writes += 1

    def write(self, block: int):
        if block in self.lines:
            self.hits += 1
            self.lines.move_to_end(block)
            self.lines[block] = True if self.wa else self.lines[block]
            if not self.wa:
                self.mem_writes += 1      # 写不分配配写直达：命中也写穿
            return
        self.misses += 1
        if not self.wa:
            self.mem_writes += 1          # 未命中直接写下级，不调入
            return
        # 写分配：先读入块，再标脏
        self.mem_reads += 1
        if len(self.lines) >= self.n_lines:
            self._evict()
        self.lines[block] = True

    def read(self, block: int):
        if block in self.lines:
            self.hits += 1
            self.lines.move_to_end(block)
            return
        self.misses += 1
        self.mem_reads += 1
        if len(self.lines) >= self.n_lines:
            self._evict()
        self.lines[block] = False


def experiment(name, ops, n_lines=8):
    print(f"--- {name} ---")
    for label, wa in (("写分配+写回", True), ("写不分配+写直达", False)):
        c = WritePolicyCache(n_lines, wa)
        for kind, blk in ops:
            c.write(blk) if kind == "W" else c.read(blk)
        print(f"{label}: hits={c.hits} misses={c.misses} "
              f"mem_reads={c.mem_reads} mem_writes={c.mem_writes}")


if __name__ == "__main__":
    # 负载1：纯流式写 64 个不同块（写一次就走）
    stream = [("W", i) for i in range(64)]
    experiment("流式写（无局部性）", stream, n_lines=8)

    # 负载2：4 个块每块连续写 16 次（空间/时间局部性好）
    repeat = [("W", i // 16) for i in range(64)]
    experiment("块内重复写（局部性好）", repeat, n_lines=8)
```

预期结果：流式写时写分配产生 64 次下级读 + 若干写回，写不分配产生 64 次下级写且不污染缓存；重复写时写分配仅 4 次下级读 + 最多 4 次写回，远优于写不分配的 64 次下级写。可见两种策略没有绝对优劣，关键在局部性。

## 五、与其他技术对比

| 维度 | 写分配 + 写回 | 写不分配 + 写直达 | 非临时写（绕过缓存） |
|------|--------------|------------------|---------------------|
| 未命中处理 | 读入块再写 | 直接写下级 | 直接写合并缓冲→内存 |
| 局部性利用 | 好（后续同块命中） | 差 | 无（有意绕过） |
| 缓存污染 | 流式写时严重 | 无 | 无 |
| 下级流量 | 少（合并写回） | 多 | 中（写合并后） |
| 典型场景 | 通用负载、随机写 | 流式写、只写一次 | memset、大块拷贝、DMA 填充 |
| 代表机制 | 现代 L2/L3 | 早期写直达缓存 | MOVNTI、_mm_stream_* |

取舍：局部性好选写分配，流式选写不分配/非临时写。现代 CPU 的非临时指令本质上是「软件显式选择写不分配并强制走写合并缓冲」。

## 六、常见误区

1. **「写分配只能配写回」**——错，这是常见但不必然的搭配。写分配也可配写直达（调入后每次写都写穿），只是性价比通常不高；写不分配也可出现在写回缓存的未命中路径（少见但合法）。两者是正交维度。
2. **「写不分配就是永不缓存该数据」**——错。写不分配只影响写未命中路径；若之后对该块有读，仍会正常调入缓存。
3. **「写分配总是更好，因为缓存命中率高」**——错。对流式写（如 `memset` 大数组），写分配会用无用块冲掉热点数据，命中率反而下降，还多付块读流量。
4. **「写未命中调块后就安全了，不需处理写缓冲」**——错。若写缓冲里还有该地址未提交的旧写，块读可能读到过期数据，必须写穿透/转发，否则破坏正确性。
5. **「与 MESI 无关」**——错。写分配调入块时往往以 Shared/Exclusive 状态进入，真正写之前要升级为 Modified，会引发总线事务；写不分配的写穿在多核下也要保证其他核看到新值。

## 八、面试题

**1. 写分配为什么常与写回一起使用？**
答：写回使缓存行成为唯一最新副本，改之前必须保证行内其他字节正确——所以未命中写要先调入整块（写分配）再改。写分配还利用空间局部性，把后续同块写变成命中。若写直达，下级总是最新的，调块收益下降，写不分配更常见。

**2. 什么负载下写不分配（或非临时写）更优？**
答：只写一次不再读的流式负载（memset、顺序写大数组、输出缓冲）。写分配会污染缓存并多付块读，写不分配/非临时写绕过缓存并借助写合并减少事务数。

**3. 写分配的写未命中，和读未命中有什么异同？**
答：同：都要从下级取回整块并分配缓存行。异：写分配取回后立即改字节并置脏（配写回），读未命中保持干净；写分配还要防写缓冲旧值，处理可能的 RMW 语义。

**4. 如何用性能计数器验证缓存被流式写污染？**
答：观察 L1D/L2 缺失率在写大数组时升高、命中率下降，且 miss 与写次数同量级；对比开非临时 store 后缺失率下降、内存带宽上升。Linux perf 可看 L1-dcache-load-misses、LLC-load-misses 等事件。

## 九、演进与趋势

现代处理器在硬件里做自适应：Intel 的 write-allocate 优化、ARM 的 non-temporal hint、以及自适应替换策略（如 DIP）都会动态权衡是否调入。ISA 层面，非临时提示（`MOVNT*`、`PRFM PSTL*`、RISC-V 的 cache hint）把「写不分配」变成软件可控选项，被 glibc 的 `memcpy`、BLAS、ML 推理框架广泛使用。系统层，Linux 的 write-around（某些块设备直写）与 FUSE/io_uring 的缓冲策略、数据库批量加载（bulk load）都体现同一思想：识别「不复用」的数据并绕过缓存。CXL 分层内存与智能网卡（DPU）也在用类似的冷热判断决定是否分配到稀缺的 DRAM 层。

## 十、小结

写分配用一次块读投资换取后续命中，适合有局部性的通用写；写不分配让流式写绕过缓存、避免污染。两者与写回/写直达正交，实践中多为「写分配+写回」与「写不分配+写直达/非临时写」。正确选择取决于局部性、缓存容量与流量预算，是缓存调优的基本功。
