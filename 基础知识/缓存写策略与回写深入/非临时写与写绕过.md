# 非临时写与写绕过

> 对应 Intel SDM Vol. 1（Streaming/Non-Temporal Stores）；Bryant & O'Hallaron《CSAPP》第 6 章；McCalpin《Memory Bandwidth and Machine Balance》。

## 一、背景与挑战

大量科学计算、多媒体、数据库批量加载的代码形状是「顺序写一大块内存，写完就再也不读」。典型如 `memset`、图像帧缓冲填充、模型参数初始化、日志顺序落盘缓冲、张量输出写回。这些数据一旦写入就离开热点工作集，若仍按普通写路径进缓存，会用「一次性数据」把真正有用的行挤出去——这就是缓存污染（cache pollution）。

朴素做法的问题在两层。第一层是流量：普通写回缓存会把这些行标脏，最终还要整行写回，等于「先占缓存、再写内存」，两头吃亏。第二层是局部性反噬：流式写的工作集远大于 L1/L2，会把后续真正要读的热数据驱逐，缺失率飙升，整体性能可能比「不用缓存」还差。Bryant 教授在 CSAPP 中用「颠簸（thrashing）」描述这种自伤。

硬件与 ISA 的对策是写绕过（write-around）与非临时写（non-temporal store）：软件用显式提示告诉硬件「这块数据不需要缓存」，直接走写合并缓冲落到内存。这在高性能内存拷贝、ML 推理、流媒体编码中是标准优化。面试常问「非临时写为什么快/什么时候更慢」「为什么还要 sfence」「和 write-allocate 的关系」，考察对缓存污染与存储序的理解。

## 二、核心原理

**非临时写（non-temporal store）**：ISA 提供的 store 变体，语义是「数据短暂使用（non-temporal），不必保留于缓存」。x86 有 `MOVNTI`、`MOVNTDQ`、`MOVNTPS/PD` 及内在函数 `_mm_stream_si32/si64`、`_mm_stream_pd` 等；ARM 有 non-temporal load/store hint（如 `PRFM PSTL1STRM`）；RISC-V 以 cache hint/非临时提示标准化。

**路径差异**：
- 普通写（配写分配）：store → L1 命中改行/未命中调块置脏 → 替换时写回内存。
- 非临时写：store → 写合并（WC）缓冲 → 合并到整行 → 一次突发写内存；不分配 L1/L2 行（或允许短暂分配后快速驱逐，视实现）。

**写绕过（write-around / write-combining store）**：广义上指「未命中不调入缓存、直接写下级」，非临时写是它的 ISA 显式形式。与写不分配同类，但硬件通常保证合并与可流式化。

**不变量与边界**：
1. 非临时写仍要维护存储一致性：多核下其他核最终要看到新值；故需要 `sfence`/`mfence` 或非临时 store 围栏保证缓冲排空与顺序。
2. 非临时提示是「提示」，不是绝对禁止缓存；实现可忽略，但正确性不能依赖「不进缓存」。
3. 对即将读回的数据，非临时写会让后续读变成未命中（数据在内存而非缓存），反而更慢——所以只适合「写一次不再读」。
4. 部分实现允许短暂分配再驱逐（transient allocation），以简化与一致性的交互。

**与预取配合**：流式读用非临时预取（`_mm_prefetch` T0/T1/NTT），流式写用 NT store，双向都绕过或低优先级占用缓存，才能避免「读也污染、写也污染」。

## 三、形式化与数学基础

设大数组大小 $S$，缓存容量 $C$（有效可分配容量约 $\beta C$，$\beta$ 为组相联与冲突折损），$S \gg C$。

普通写路径（写回+写分配）：
- 写阶段：$S/B_{line}$ 次行调入与后续脏行写回，下级流量约 $2S$（读入 $S$ + 写回 $S$）。
- 若随后还有读阶段，工作集已被冲掉，再读又是 $S$ 流量。
- 额外代价：热数据被驱逐，设引起额外缺失开销 $M \cdot T_{miss}$。

非临时写路径：
- 写阶段：仅 $S$ 字节顺序写出（合并后接近峰值带宽），下级流量约 $S$。
- 缓存保持干净，热数据命中率不受影响。

写流量比：

$$\frac{Traffic_{NT}}{Traffic_{WB}} \approx \frac{S}{2S} = \frac{1}{2}$$

若再计入污染导致的额外缺失，优势更大。时间模型上，设内存带宽 $B_{mem}$，峰值合并效率 $\eta$：

$$T_{NT} \approx \frac{S}{\eta B_{mem}}, \qquad T_{WB} \approx \frac{2S}{\eta B_{mem}} + T_{thrash}$$

当 $S/C > 4$ 时 $T_{thrash}$ 主导，非临时写可快数倍。反之若 $S \ll C$ 且数据会被重用，非临时写让后续读全 miss：

$$T_{NT}' = T_{NT} + \frac{S}{B_{mem}} + T_{miss} > T_{WB}$$

因此决策阈值大致是「数据是否在缓存内会被再次使用」：会用则普通写+写回，不会用则非临时写。

## 四、代码实现

下面用 Python 模拟「普通写分配写回」与「非临时写绕过」两种路径，统计缓存污染（热行被驱逐次数）与下级流量，并给出可对照的 C 语义伪代码等价物。

```python
"""非临时写 vs 普通写：污染与流量模拟"""
from collections import OrderedDict


class TinyCache:
    def __init__(self, n_lines):
        self.n_lines = n_lines
        self.lines = OrderedDict()   # tag -> dirty
        self.mem_traffic = 0         # 以行为单位的下级流量
        self.evicted_hot = 0         # 被驱逐的热行数

    def touch(self, tag, is_hot=False):
        if tag in self.lines:
            self.lines.move_to_end(tag)
            return
        if len(self.lines) >= self.n_lines:
            old, dirty = self.lines.popitem(last=False)
            if is_hot:
                self.evicted_hot += 1
            self.mem_traffic += 1 + (1 if dirty else 0)  # 调入(1) + 脏写回
        self.lines[tag] = False

    def write_normal(self, tag):
        """普通写：写分配，调入并标脏"""
        self.touch(tag)
        self.lines[tag] = True

    def write_nontemporal(self, tag):
        """非临时写：不分配缓存，直接写下级（合并后一次行写）"""
        self.mem_traffic += 1


def workload(n_stream, n_hot, cache_lines):
    # 阶段1：热数据填满缓存
    # 阶段2：流式写 n_stream 个新块
    # 阶段3：再读热数据
    hot_tags = list(range(1000, 1000 + n_hot))

    def run(nt: bool):
        c = TinyCache(cache_lines)
        for t in hot_tags:
            c.touch(t, is_hot=False)   # 预热
        for i in range(n_stream):
            if nt:
                c.write_nontemporal(5000 + i)
            else:
                c.write_normal(5000 + i)
        hot_miss = 0
        for t in hot_tags:
            if t not in c.lines:
                hot_miss += 1
                c.touch(t, is_hot=True)
        return c, hot_miss

    for label, nt in (("普通写分配", False), ("非临时写", True)):
        c, miss = run(nt)
        print(f"{label}: mem_traffic={c.mem_traffic} hot_miss_after_stream={miss}")


if __name__ == "__main__":
    workload(n_stream=64, n_hot=8, cache_lines=16)
```

预期输出：普通写分配会把 8 个热行全部冲掉（hot_miss=8）且流量约 2× 流式块数；非临时写 hot_miss=0，流量约等于流式块数。这直观验证了非临时写在「写一次」负载上既省流量又保热数据。

对应的 x86 C 内在函数写法（可对照编译）：

```c
#include <immintrin.h>
#include <string.h>

/* 流式拷贝：读可用普通 load（配合预取），写用非临时 */
void stream_copy(double *dst, const double *src, size_t n) {
    for (size_t i = 0; i + 3 < n; i += 4) {
        __m256d v = _mm256_load_pd(src + i);
        _mm256_stream_pd(dst + i, v);
    }
    _mm_sfence();  /* 保证 NT 写缓冲有序排空、对其他核/设备可见 */
}

/* 只写初始化，如 memset 大数组 */
void nt_fill(int *p, size_t n, int val) {
    __m128i v = _mm_set1_epi32(val);
    for (size_t i = 0; i + 3 < n; i += 4)
        _mm_stream_si128((__m128i *)(p + i), v);
    _mm_sfence();
}
```

`_mm_sfence` 的作用是：对非临时写建立顺序、保证在后续依赖该数据的操作前已排空写合并缓冲——没有它，别的核或设备可能读到旧值。

## 五、与其他技术对比

| 维度 | 普通写（写回+写分配） | 非临时写 / 写绕过 | 写直达+写缓冲 |
|------|----------------------|-------------------|---------------|
| 是否分配缓存 | 是 | 否（或瞬态） | 是/否 |
| 缓存污染 | 流式时严重 | 无 | 有 |
| 下级流量 | 读入+写回≈2S | ≈S | ≈S |
| 后续读 | 命中快 | 全 miss | 取决于是否分配 |
| 顺序保证 | 缓存序+协议 | 需 sfence | 写缓冲序 |
| 适用 | 通用、会重用 | 只写一次大块 | 写穿路径 |

取舍：重用数据用普通写；一次性流式用非临时；需要强序时补 fence。混合负载可按阈值（如数组大小 > L2 容量）选择，glibc 的 `memcpy`/`memset` 就按大小切换策略。

## 六、常见误区

1. **「非临时写一定更快」**——错。只对「写后不复用」的大块数据更快；小数据或随后要读的数据用非临时写会损失缓存收益，反而更慢。
2. **「非临时写不需要 fence」**——错。NT store 进入写合并缓冲后异步落地，必须用 `sfence`/`mfence`（或语言级原子/屏障）保证顺序与可见性，否则多核/设备可见性不完整。
3. **「非临时写等于禁止缓存硬件分配」**——提示语义上是「避免长期占用」，实现可瞬态分配；正确性不能依赖绝对不缓存。
4. **「写绕过和写不分配完全一样」**——概念同源（未命中不调入），但写不分配是缓存策略选择，非临时写是 ISA 提示+专用 WC 路径，常带合并与弱序语义。
5. **「只要用 NT store，带宽就到峰值」**——还受合并度、对齐、线程数、内存通道、行激活与刷新影响；需要 64B 对齐、顺序地址流、足够并发才能压满带宽（如 STREAM 测试）。

## 八、面试题

**1. 非临时写为什么能避免缓存污染？**
答：它走写合并缓冲直接写内存，不把目标行长期分配进缓存，因此不会驱逐热数据；同时整行合并写出，下级流量接近 1× 数据量。

**2. 为什么非临时写之后必须 `sfence`？**
答：NT store 是弱序、异步排空到内存的。`sfence` 保证在此之前的 NT 写已按序对全局可见，避免后续核/设备读到旧值，也满足持久化前的顺序要求。

**3. 什么时候不该用非临时写？**
答：数据会被再次读取、工作集能放进缓存、小块随机写、需要低延迟而非高吞吐的路径。这些情况下普通写+写回更好。

**4. 如何判断一个 memcpy 实现该不该用 NT store？**
答：看拷贝大小相对 LLC/缓存容量与复用模式。glibc 经验阈值通常是「超过 L2/LLC 的显著比例且目的端不会被立刻读」；也可用 perf 对比 L2/LLC 缺失与带宽。

## 九、演进与趋势

非临时性（non-temporality）从 store 扩展到 prefetch（`prefetchnta`）、内存类型（WC）与分配策略（DIP、RRIP 的低优先级插入）。ML 框架（TensorRT、ONNX Runtime）与向量化库（oneDNN、FFTW）用 NT store 落地大激活/梯度；数据库批量导入与日志刷盘走类似路径。持久内存（PMem）把 NT 与 `clwb`/`sfence` 结合成「流式持久写」。CXL 与分层内存中，冷数据写到慢层也用非临时/低优先级策略。RISC-V Zicbop、ARM MTE/HINT 体系都在标准化可移植的提示，让编译器与运行时自动选择绕过策略。

## 十、小结

非临时写/写绕过用「不分配缓存+写合并直写内存」解决流式写的污染与双倍流量问题，是高性能内存拷贝与 ML 负载的关键武器。它只适合写一次不再读的数据，并以 `sfence` 保证顺序。把局部性判断和 fence 语义想清楚，才能用对这把双刃剑。
