# 缓存行状态与脏位

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》Appendix C；Bryant & O'Hallaron《CSAPP》第 6 章；Intel SDM Vol. 3A 缓存控制章节。

## 一、背景与挑战

缓存的每一行并不是「随便放数据的槽位」，而是一个带元数据的小状态机。硬件必须随时知道三件事：这行现在是不是有效数据（valid）？它是不是比下级存储更新（dirty）？它属于哪个地址（tag）？缺任何一项，替换、写回、一致性都无法正确进行。

朴素做法是「缓存里有数据就算数」，这在复位后、失效后、部分写后立刻出错：刚上电时行里是随机噪声，若被当成有效数据返回，程序立刻崩溃；另一极端是「任何写都同步写穿」，则永不需要脏位，但下级带宽被浪费。于是工程上必须给每行配控制位，并定义清楚每条指令、每个总线事务如何更新这些位。

脏位（dirty bit）是写回缓存的正确性基石：它记录「内存副本已过期」。面试里高频问题「脏位何时置 1/清 0」「替换脏行怎么做」「valid 和 dirty 谁先看」，考的都是这套元数据状态机是否真正想清楚。

## 二、核心原理

**典型行元数据**（直接映射/组相联每行一份）：
- `valid`：行内数据是否代表某地址的有效内容。复位或失效后为 0。
- `tag`：地址高位，用于比较「这行是不是要找的块」。
- `dirty`：写回策略下，本行是否比下级新。写直达缓存通常不需要 dirty。
- 可选：MESI/MOESI 状态、LRU/PLRU 替换伪位、ECC 校验位、prefetch 位等。

**访问状态机（写回 + 写分配）**：
1. 读命中：valid=1 且 tag 匹配 → 返回数据，状态不变。
2. 读未命中：分配（或替换）一行 → 若替换的是脏行，先写回；取下级块填入；valid=1, dirty=0。
3. 写命中：改数据字节，dirty=1（不变量：脏行的下级副本过期）。
4. 写未命中：按写分配读入块再写并置脏；或按写不分配直接写下级。

**替换不变量**：只有 dirty=0 的行可以直接丢弃；dirty=1 的行必须先写回再丢弃或覆盖。清 dirty 的时机只有两个——写回完成之后，或把行失效（若协议保证下级已是最新，例如写直达）。

**边界条件**：
- 部分写（store 小于行宽）只改行内字节，dirty 仍整行置 1；写回以整行为单位。
- 复位后全部 valid=0，dirty=0。
- 多核一致性下，写回缓存的 dirty 往往与 MESI 的 M 状态合并编码：M 即 dirty，S/E 即 clean。
- 持久内存（NVDIMM）语义下，dirty 还表示「未持久」，需要 clwb/fence 落到持久域。
- ECC 与 dirty 交互：写回时通常整行重算校验位；若 ECC 存在，行状态机还要处理纠正后的写回时机。
- 预取行可能 valid=1 但「非预期」，有些实现用额外位区分，替换时优先丢弃预取行。

**为什么正确**：dirty 位维护了一个简单的不变量——「dirty=1 当且仅当本行内容比下级新」。写命中把行变新就置 1，写回让下级追平就清 0。替换逻辑只需读 dirty 决定写回或丢弃，无需猜测；这使写回缓存在硬件上可验证、可形式化（可用状态机模型检查）。若没有 dirty 位，硬件要么永远写回（浪费带宽），要么永远丢弃（丢更新），没有第三种既省带宽又正确的方式。

## 三、形式化与数学基础

设缓存有 $N$ 行，访问轨迹中写次数 $W$，被替换行集合 $E$，其中脏行数 $D$，写回代价 $T_{wb}$，无效丢弃代价近似 0。则替换阶段的写回总代价：

$$Cost_{replace} = D \cdot T_{wb}, \quad D \le |E| \le N_{miss}$$

若无 dirty 位而「一律写回」，代价变成 $|E| \cdot T_{wb}$，浪费 $(|E|-D) \cdot T_{wb}$；若无 dirty 位而「一律丢弃」，则丢更新，正确性被破坏。因此 dirty 位以 1 bit / 行的成本，把写回流量压缩为 $D/|E|$ 比例。

再看脏位密度：设每次写命中以概率 $p$ 置脏且随后被替换前未再写回，写次数为 $W$、替换数为 $E$，则期望脏替换数：

$$\mathbb{E}[D] \approx E \cdot \frac{W_{hit}}{W_{hit} + R_{hit}} \cdot \frac{1}{\bar{k}}$$

其中 $\bar{k}$ 是同一行被重复写的平均次数（重复写摊薄脏替换）。在写密集局部性好时 $\bar{k}$ 大，$D \ll W$，写回收益最大。

元数据存储开销：每行 dirty 1 bit + valid 1 bit，行宽 $B=64$B 时元数据占比约 $2/(512) \approx 0.4\%$，却能节省大量写流量——性价比极高。

## 四、代码实现

下面实现一个带 valid/dirty/tag 的直接映射写回缓存，跟踪每次替换时的写回决策，并统计「因 dirty 而写回」与「直接丢弃」的次数。

```python
"""缓存行 valid/dirty 状态机模拟（直接映射写回缓存）"""


class Line:
    __slots__ = ("tag", "valid", "dirty", "data")

    def __init__(self):
        self.tag = None
        self.valid = False
        self.dirty = False
        self.data = None  # 用 block_id 代替真实字节


class WriteBackCache:
    def __init__(self, n_sets: int):
        self.n_sets = n_sets
        self.lines = [Line() for _ in range(n_sets)]
        self.write_backs = 0   # 因 dirty 而写回
        self.discards = 0      # clean 行直接丢弃
        self.mem_writes = 0
        self.mem_reads = 0

    def _index_tag(self, addr_block: int):
        return addr_block % self.n_sets, addr_block // self.n_sets

    def _evict(self, line: Line):
        if not line.valid:
            return
        if line.dirty:
            self.mem_writes += 1
            self.write_backs += 1
            line.dirty = False
        else:
            self.discards += 1
        line.valid = False

    def write(self, block: int, value):
        idx, tag = self._index_tag(block)
        line = self.lines[idx]
        if line.valid and line.tag == tag:
            line.data = value
            line.dirty = True          # 写命中：置脏
            return
        self._evict(line)              # 未命中：先处理旧行
        self.mem_reads += 1            # 写分配：读入整块
        line.valid, line.tag = True, tag
        line.data = value
        line.dirty = True

    def read(self, block: int):
        idx, tag = self._index_tag(block)
        line = self.lines[idx]
        if line.valid and line.tag == tag:
            return line.data
        self._evict(line)
        self.mem_reads += 1
        line.valid, line.tag, line.dirty = True, tag, False
        line.data = f"mem[{block}]"
        return line.data

    def flush_all(self):
        """显式刷回所有脏行（如关机 / clflush）"""
        for line in self.lines:
            if line.valid and line.dirty:
                self.mem_writes += 1
                self.write_backs += 1
                line.dirty = False


if __name__ == "__main__":
    c = WriteBackCache(n_sets=4)
    # 写 0、1、2、3 各一次（4 行刚好放下，均脏）
    for b in range(4):
        c.write(b, f"v{b}")
    # 读 0 -> 命中；再写 5 -> 与 0 同 set，替换脏行 0
    c.read(0)
    c.write(5, "v5")
    print("write_backs =", c.write_backs)  # 1：替换脏行 0
    print("discards   =", c.discards)      # 0
    print("mem_writes =", c.mem_writes)    # 1
    # 读 1 若不在… 实际 1 还在，验证 dirty 仍为 True
    c.flush_all()
    print("after flush mem_writes =", c.mem_writes)  # 4（剩余脏行 1,2,3,5）
    assert c.write_backs == 5
```

代码体现了核心不变量：写命中置 dirty；替换 dirty 行时先 `mem_writes += 1` 再丢弃；flush 清空所有脏行。任何遗漏 `if line.dirty` 的实现都会要么丢数据、要么浪费带宽。

## 五、与其他技术对比

| 维度 | 有 dirty 的写回 | 无 dirty 的写直达 | MESI 行状态 |
|------|----------------|-------------------|-------------|
| 行元数据 | valid+tag+dirty | valid+tag | valid 合并为 M/E/S/I |
| 替换行为 | 脏写回，净丢弃 | 直接丢弃 | M 写回，S/E/I 按协议 |
| 一致性 | 需协议取最新 | 内存总是新 | 由协议保证 |
| 元数据成本 | +1 bit/行 | 最低 | 2 bit/行 状态编码 |
| 崩溃安全 | 脏行可丢 | 较安全 | M 态可丢 |

MESI 可看作 dirty 位的推广：M=dirty 且独占，E=clean 独占，S=clean 共享，I=无效。MOESI 再加 Owned，让共享脏数据不必立即写回内存。

## 六、常见误区

1. **「dirty=0 就什么都不用做」**——错。多核下替换/失效 clean 行仍可能要发总线事务（如让其他核或目录更新共享状态）；持久化场景 clean 只表示与下级一致，不一定已到持久介质。
2. **「dirty 表示与磁盘/SSD 一致」**——错。脏位描述的是缓存与紧邻下一级（通常是下一级缓存或主存）的关系，与持久设备无关；页面回写、文件系统刷盘是 OS 层的另一套 dirty（page dirty）。
3. **「写直达缓存完全没有状态位」**——错。仍需 valid 与 tag；多核写直达也可能参与一致性协议，只是没有 dirty。
4. **「部分写只 dirty 一个字节」**——错。缓存行是最小一致/写回粒度，任意字节写都把整行标脏，写回也是整行传输。
5. **「valid 和 tag 比较顺序无所谓」**——实现上常先比 tag 再确认 valid，但逻辑上必须 valid=1 才可能命中；复位后若忽略 valid，会把垃圾当数据返回。

## 八、面试题

**1. dirty 位为 1 的行被替换时如何处理？**
答：必须先把整行写回下一级存储（或触发一致性协议的写回事务），完成后才能覆盖或失效该行。若直接丢弃，内存中仍是旧值，等于丢更新。

**2. valid 位的作用是什么？为什么复位后要清零？**
答：valid 表示行内数据是否代表某地址的有效内容。复位后行内是随机值，若 valid=1 会被误命中返回垃圾，所以硬件复位或失效后必须把 valid 清 0。

**3. 写直达缓存需要 dirty 位吗？**
答：通常不需要。写直达每次写都更新下级，缓存行与下级一致，替换可直接丢弃。但仍需要 valid/tag；若参与多核一致性，还有协议状态位。

**4. 如何用 2 个 bit 编码 MESI 并映射 dirty 语义？**
答：00=Invalid，01=Shared（干净共享），10=Exclusive（干净独占），11=Modified（脏独占）。M 等价于 dirty=1 且独占；E/S 表示 clean；I 无有效数据。有的实现把 dirty 与状态分开存，语义等价。

## 九、演进与趋势

行元数据越来越「厚」：替换伪位（PLRU/RRIP）、预取位、签名、ECC、缓存着色、分区（CAT）位都挂在行或组上。一致性协议把 dirty 融进状态机（MESI/MOESI/MESIF），目录协议再在分布式目录里复制类似状态。持久内存时代出现「持久 dirty」概念：行可能已写但未持久，需要 `clwb` + fence 才算 durable，这把「脏」扩展为 volatile-dirty 与 persistent-dirty 两层。安全侧还有缓存行填充（cache line padding）与「脏行侧信道」研究（如 Flush+Reload 的变体），说明行状态本身也是微架构安全边界。开源模拟器 gem5、ChampSim 中的 cache 模块是理解这些状态机的好材料。

## 十、小结

valid 决定「这行算不算数」，dirty 决定「替换时写回还是丢弃」。这两个比特配合 tag 比较，构成写回缓存的最小正确状态机；它们又被一致性协议推广为 MESI 等多状态编码。理解行状态的不变量与转换时机，是排查缓存一致性 bug 与分析写流量的前提。
