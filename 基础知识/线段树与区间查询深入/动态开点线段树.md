# 动态开点线段树

> 对应 OI Wiki「线段树」动态开点条目、李煜东《算法竞赛进阶指南》权值线段树章节，以及可持久化线段树（主席树）中的节点共享思想（本系列下一篇展开）。

## 一、背景与挑战

静态线段树要求值域/下标范围事先知道，并用 $4n$ 数组一次性分配节点。两种情形会让它失效：

1. **值域巨大**：要维护"值在 $[1, 10^9]$ 内的出现次数/最值"，$4\times 10^9$ 个节点不可能开出来。哪怕实际只插入 $10^5$ 个点，静态线段树也必须覆盖整个值域。
2. **多版本 / 多次加点**：权值线段树合并、可持久化、或"在线插入且下标稀疏"时，预先开满既浪费又不现实。

动态开点（Dynamic Node / Pointer-based Segment Tree）的思路是：**不预先建树，只在真正用到某个区间时创建节点**。初始只有一个根（或空树），每次更新/查询递归时，若某个孩子不存在就现场 `new` 一个。由于每次操作只会创建 $O(\log U)$ 个节点（$U$ 为值域大小），总空间与操作数同阶，而不是与值域同阶。

在面试里，动态开点常作为"值域线段树 / 权值线段树 / 主席树"的前置问题出现：面试官想知道你是否理解"节点是按需分配的"，以及递归写法怎么在缺孩子时补节点。在工程中，它对应稀疏索引（只给出现过的 key 建节点）、时序数据的时间轴压缩、以及"值域很大但实际用到的点很少"的统计问题。

## 二、核心原理

**节点结构。** 每个节点是一个对象/字典，至少包含：`l, r`（左右孩子指针，可为空）、`val`（聚合值，如计数/区间和）。递归函数签名带着当前节点管理的值域 `[L, R]`。

**按需创建。** 从根进入要更新的值 `x` 时：

- 若当前节点为 `None`，先创建一个空节点（`val = 0`）。
- 若 $L = R$，写入叶子。
- 否则取 `mid`，若 `x` 落在左半，递归并把左孩子指针挂上；回溯 pushup。

查询同理：孩子为 `None` 直接按"空贡献"返回（0 / $-\infty$），不需要补节点——查询只读，不制造空间。

**为什么空间够用。** 单次插入在树高 $O(\log U)$ 层上各创建至多 1 个节点，故 $q$ 次插入总节点数 $O(q \log U)$。对比静态线段树的 $O(U)$，这是稀疏性的胜利。

**不变量。** 每个存在的节点 $p$：`p.val` 等于其管理区间内已插入信息的聚合；缺失的子树等价于全 0（或单位元）。

**边界条件。** 空树查询返回单位元；创建节点时 `val` 初始化为单位元（求和 0，max $-\infty$）；`mid` 划分与静态版一致（$[L,mid]$ 与 $[mid+1,R]$）。

**与懒标记结合。** 动态开点也能打懒标记，但下传前必须保证儿子存在——不存在则创建空儿子再下传，否则标记会丢。

## 三、形式化与数学基础

**值域与树高。** 值域 $[1, U]$ 的线段树高 $h = \lceil \log_2 U \rceil$。若 $U = 10^9$，$h \approx 30$。

**节点数上界。** 定理：$q$ 次单点插入后，动态开点线段树节点数不超过 $q \cdot h + 1 = O(q \log U)$。

**证明。** 每次插入从根走到某个叶子，路径长 $h$；路径上每个"尚未存在"的节点被创建一次，已存在的不重复创建。故每次插入至多创建 $h$ 个节点，总和 $q h$。 $\square$

**空间对比。**

$$
\text{静态：} O(U), \quad \text{动态：} O(q \log U).
$$

当 $q = 10^5, U = 10^9$ 时，静态 $10^9$ 不可行，动态约 $3\times 10^6$ 个节点，可行。

**时间复杂度。** 插入与查询都是 $O(\log U)$，与静态相同（多一次指针判空，常数略大）。

**权值线段树（统计 $k$ 小）。** 把"值"当作下标，节点存出现次数。插入 $x$：沿值域走到叶子 `cnt++`，回溯 pushup。查询"第 $k$ 小"：看左子树计数 $c$，若 $k \le c$ 走左，否则走右并 $k \leftarrow k - c$。这是动态开点最经典的应用。

## 四、代码实现

完整可运行的动态开点线段树（权值计数 + 第 $k$ 小 + 区间计数查询）。

```python
# 动态开点线段树（权值线段树）：插入、删除、查询第 k 小、区间计数
class Node:
    __slots__ = ('l', 'r', 'cnt')

    def __init__(self):
        self.l = None
        self.r = None
        self.cnt = 0


class DynamicSegTree:
    """值域 [lo, hi] 上的计数线段树，节点按需创建。"""

    def __init__(self, lo, hi):
        self.lo = lo
        self.hi = hi
        self.root = Node()

    def insert(self, x, delta=1):
        """把 x 的计数增加 delta（delta=1 插入，-1 删除）。"""
        self.root = self._update(self.root, self.lo, self.hi, x, delta)

    def _update(self, p, L, R, x, delta):
        if p is None:
            p = Node()
        p.cnt += delta
        if L == R:
            return p
        mid = (L + R) // 2
        if x <= mid:
            p.l = self._update(p.l, L, mid, x, delta)
        else:
            p.r = self._update(p.r, mid + 1, R, x, delta)
        return p

    def count(self, Lq, Rq):
        """值在 [Lq, Rq] 内的元素个数。"""
        return self._count(self.root, self.lo, self.hi, Lq, Rq)

    def _count(self, p, L, R, Lq, Rq):
        if p is None or Rq < L or R < Lq:
            return 0
        if Lq <= L and R <= Rq:
            return p.cnt
        mid = (L + R) // 2
        return self._count(p.l, L, mid, Lq, Rq) + self._count(p.r, mid + 1, R, Lq, Rq)

    def kth(self, k):
        """返回第 k 小的元素（k 从 1 开始）。不存在则抛错。"""
        if k <= 0 or k > (self.root.cnt if self.root else 0):
            raise ValueError('k out of range')
        return self._kth(self.root, self.lo, self.hi, k)

    def _kth(self, p, L, R, k):
        if L == R:
            return L
        mid = (L + R) // 2
        left_cnt = p.l.cnt if p.l else 0
        if k <= left_cnt:
            return self._kth(p.l, L, mid, k)
        return self._kth(p.r, mid + 1, R, k - left_cnt)


if __name__ == '__main__':
    st = DynamicSegTree(1, 10 ** 9)
    for v in [5, 1, 9, 3, 7]:
        st.insert(v)
    assert st.count(1, 10 ** 9) == 5
    assert st.count(3, 7) == 3          # 3,5,7
    assert st.kth(1) == 1
    assert st.kth(3) == 5
    assert st.kth(5) == 9
    st.insert(5, -1)                    # 删除一个 5
    assert st.count(1, 10 ** 9) == 4
    assert st.kth(3) == 7
    # 大值域稀疏插入
    for v in [10 ** 9, 1, 5 * 10 ** 8]:
        st.insert(v)
    assert st.count(1, 10 ** 9) == 7
    print('dynamic seg ok', st.kth(1), st.kth(7))
```

实现细节：`_update` 每次都可能新建节点并返回指针，调用方把返回值挂回父指针；`_count` 遇到 `None` 直接返回 0，不创建节点；`kth` 依赖左子树计数。值域取 $[1, 10^9]$ 时树高约 30，插入 7 个点仅创建约 $7\times 30$ 个节点。

## 五、与其他技术对比

| 方法 | 空间 | 插入 | 查询 | 适用 |
|------|------|------|------|------|
| 静态线段树 | $O(U)$ | $O(\log U)$ | $O(\log U)$ | 值域小且已知 |
| 动态开点 | $O(q\log U)$ | $O(\log U)$ | $O(\log U)$ | 值域大、插入稀疏 |
| 树状数组 + 离散化 | $O(n)$ | $O(\log n)$ | $O(\log n)$ | 只需可离散的序 |
| 平衡树（权值） | $O(n)$ | $O(\log n)$ | $O(\log n)$ | 要分裂合并 |
| 哈希表 | $O(n)$ | $O(1)$ | $O(1)$ 均摊 | 不需序统计 |

取舍：能离散化就离散化 + 树状数组（常数最小）；不能离散（在线、值域极大）或要支持"值域区间计数 + 第 k 小"，用动态开点权值线段树；要区间排名/前驱后继再叠加可持久化。

## 六、常见误区

1. **查询时也顺手创建节点。** 查询应是只读的，遇到 `None` 返回单位元即可；否则多次查询会把空间撑到 $O(q\log U)$ 以上且毫无必要。
2. **删除不减计数或允许负计数。** `insert(x, -1)` 前应确认存在；若允许负计数，`kth` 与 `count` 语义会被破坏。
3. **`mid` 计算与递归边界写错。** $[L,mid]$ 与 $[mid+1,R]$ 必须与创建路径一致；`L > R` 或 `L==R` 处理不当会导致无限递归。
4. **忘记 pushup。** 只改叶子 `cnt` 不回溯更新祖先，`count` 与 `kth` 全错。每次 `_update` 返回前必须更新 `p.cnt`（本实现用 `p.cnt += delta` 在进入时累加，需保证每个节点只在路径上被加一次）。
5. **值域边界用负数/0 时划分失衡。** 若值可为负，把 `lo` 设为最小值或整体平移，避免 `mid` 偏斜导致树高退化。

## 八、面试题

**1. 值域 $10^9$、最多 $10^5$ 次插入，如何维护区间计数与第 $k$ 小？**
参考答案：动态开点权值线段树。空间 $O(q\log U)\approx 3\times 10^6$，插入/查询 $O(\log U)$。

**2. 动态开点为什么空间是 $O(q\log U)$？**
参考答案：每次插入路径长 $O(\log U)$，每层至多新建 1 个节点；$q$ 次插入共 $O(q\log U)$ 个节点。缺失子树隐含为空，不占空间。

**3. 查询需要创建节点吗？**
参考答案：不需要。查询只读，`None` 子树返回单位元即可。只有更新才创建。

**4. 与离散化 + 树状数组比，动态开点的优势是什么？**
参考答案：支持在线、值域极大且不要求离线全知；还天然支持"值域区间"查询与第 $k$ 小；离散化在需要"真实值域距离/区间覆盖"时会失真。

## 九、演进与趋势

动态开点是通往更高级结构的台阶：**可持久化（主席树）** 在每次插入时新建 $O(\log U)$ 个节点并共享旧节点，得到版本序列；**线段树合并**把两棵权值线段树按需合并，总复杂度 $O(n\log U)$；**李超树**动态开点维护线段凸壳；**树套树**（线段树套平衡树）用动态开点压值域。工程上，稀疏索引、时序数据库的倒排段、游戏排行榜的分数段统计都用它。面试趋势是把它作为"权值线段树 / 主席树"的必经前置。

## 十、小结

动态开点线段树按需创建节点，把空间从 $O(U)$ 压到 $O(q\log U)$，时间仍是 $O(\log U)$；它维护"缺失子树 = 单位元"的不变量，是权值统计、区间第 $k$ 小、主席树与线段树合并的共同底座。
