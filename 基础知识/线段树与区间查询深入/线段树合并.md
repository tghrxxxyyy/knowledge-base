# 线段树合并

> 对应 李煜东《算法竞赛进阶指南》权值线段树合并、OI Wiki「线段树合并」条目，以及 Codeforces 关于 "Segment Tree Merge" 的经典技巧总结。

## 一、背景与挑战

当问题需要"对每个集合维护一棵权值线段树，并支持集合合并"时，逐元素插入是 $O(n\log U)$ 每次，总复杂度会退化成 $O(n^2\log U)$。典型场景：树上每个节点维护其子树内的权值分布，自底向上合并；或者 DSU 启发式合并时把小集合元素插入大集合。线段树合并（Segment Tree Merge）直接把两棵树**结构上合并**：同步遍历两棵动态开点线段树，两棵都有的节点合并计数，只有一棵有的节点直接挂到结果上——总复杂度是两棵树节点数的较小者级别的 $O(\text{节点数})$，在均摊意义下是 $O(n\log U)$。

朴素做法为什么不行？对每个合并都把小集合的每个元素插入大集合，若合并链退化成链式（小的总是被插入），最坏 $O(n^2\log U)$。线段树合并的均摊分析表明：**每个节点最多被"合并掉"一次**，一旦它被合并进结果树并释放，就不会再参与后续合并，故总代价是所有树的节点总量级。

在竞赛中，"线段树合并求树上第 $k$ 小""子树众数""区间合并后的全局统计"是省选高频题。在面试里，它是"DSU / 启发式合并 / 权值结构"的组合考法；在工程上，它对应多副本倒排索引合并、时间序列分片合并、多玩家状态的聚合。

## 二、核心原理

**合并操作。** 给定两棵动态开点权值线段树 $A, B$，返回一棵新树（或直接在 $A$ 上改），节点信息按"计数相加 / 最值取 max"合并。递归规则：

1. 若 $A$ 为空，返回 $B$；若 $B$ 为空，返回 $A$。
2. 若都是叶子：`val = merge(A.val, B.val)`，返回其一。
3. 否则：`A.l = merge(A.l, B.l)`，`A.r = merge(A.r, B.r)`，pushup 后返回 $A$。

**为什么这样省。** 只有"两棵都非空"的节点才需要双方都走一遍；单侧为空时直接挂接指针，$O(1)$。两棵树节点数分别为 $|A|, |B|$，合并访问的节点数不超过 $O(\min(|A|,|B|) \log U)$？更精确的均摊是 $O(|A| + |B|)$ 仅当树稀疏时；经典结论：**把 $k$ 棵总节点数 $N$ 的树合并成一棵，总复杂度 $O(N \log U)$ 或更紧 $O(N)$**（视实现与是否销毁）。

**均摊分析（关键）。** 每次递归中，若左右孩子都存在则双方节点都被访问；若一侧不存在则直接挂接。可以证明每个节点被"深度访问"的次数不超过它所在树高，但若合并后释放原节点（指针复用/删除），每个节点只被消耗一次，故

$$
T_{\text{merge}} = O(\text{两树共有路径}) = O(\min(|A|,|B|)\cdot \text{branch})，\ \text{总均摊 } O(N\log U).
$$

竞赛中常用"小树合入大树"的启发式保证退化可控。

**删除/清空。** 合并后若允许销毁 $B$，把 $B$ 的节点直接挂到 $A$ 并把 $B$ 置空，可以进一步省空间；Python 中靠引用计数回收即可。

**边界条件。** 空树合并返回另一方；叶子合并要处理"计数相加"还是"取 max"；值域两端递归终止（$L==R$）。

**与 DSU 启发式合并对照。** DSU 按大小合并是 $O(n\log n)$；线段树合并在权值维度上把每个元素的贡献折成 $O(\log U)$ 节点，合并代价与节点数线性相关。

## 三、形式化与数学基础

**总节点数。** $n$ 次单点插入建立 $n$ 棵单点树或一棵大树时，动态开点节点数 $O(n\log U)$。

**合并复杂度定理。** 将 $m$ 棵线段树合并成一棵，设总节点数为 $N$，则总时间 $O(N \log U)$；若采用"把小树节点直接挂接到大树"的写法且共享子树，则更紧的界是 $O(N \alpha)$ 或实践中的 $O(N)$。

**证明草图。** 递归 `merge(a, b)` 只在 `a` 与 `b` 都非空时下降两侧；每对"被同时访问的节点"最多被合并一次并在之后释放。对每个元素，它贡献的节点在合并森林中最多沿"被合并路径"走 $O(\log U)$ 次，故总和 $O(N\log U)$。 $\square$

**启发式（小合大）。** 每次把节点数少的树并入多的，单次代价 $O(\min(|A|,|B|)\log U)$，总 $O(N\log^2 U)$ 或更好；配合"链式合并"时最坏可控。

**空间。** 合并若复用节点则总空间保持 $O(N)$；若新建节点则 $O(N\log U)$。竞赛常复用节点并删除源树。

**与线段树分裂对照。** 分裂是合并的逆操作：把一棵树按值域/条件拆成两棵，同样 $O(\text{节点数})$。两者常配合做"可重集操作"。

## 四、代码实现

完整可运行：动态开点权值线段树的合并，用于"合并多个可重集后查第 $k$ 小/区间计数"。

```python
# 线段树合并：动态开点权值线段树
class Node:
    __slots__ = ('l', 'r', 'cnt')

    def __init__(self):
        self.l = None
        self.r = None
        self.cnt = 0


def update(p, L, R, x, delta):
    if p is None:
        p = Node()
    p.cnt += delta
    if L == R:
        return p
    mid = (L + R) // 2
    if x <= mid:
        p.l = update(p.l, L, mid, x, delta)
    else:
        p.r = update(p.r, mid + 1, R, x, delta)
    return p


def merge(a, b, L, R):
    """把两棵权值线段树合并，返回新根（复用节点）。计数相加。"""
    if a is None:
        return b
    if b is None:
        return a
    if L == R:
        a.cnt += b.cnt
        return a
    mid = (L + R) // 2
    a.l = merge(a.l, b.l, L, mid)
    a.r = merge(a.r, b.r, mid + 1, R)
    a.cnt = (a.l.cnt if a.l else 0) + (a.r.cnt if a.r else 0)
    return a


def count(p, L, R, Lq, Rq):
    if p is None or Rq < L or R < Lq:
        return 0
    if Lq <= L and R <= Rq:
        return p.cnt
    mid = (L + R) // 2
    return count(p.l, L, mid, Lq, Rq) + count(p.r, mid + 1, R, Lq, Rq)


def kth(p, L, R, k):
    if L == R:
        return L
    mid = (L + R) // 2
    left = p.l.cnt if p.l else 0
    if k <= left:
        return kth(p.l, L, mid, k)
    return kth(p.r, mid + 1, R, k - left)


if __name__ == '__main__':
    LO, HI = 1, 20
    # 三个可重集
    sets = [[1, 2, 3], [4, 5], [2, 2, 9]]
    roots = []
    for s in sets:
        root = None
        for x in s:
            root = update(root, LO, HI, x, 1)
        roots.append(root)
    merged = None
    for r in roots:
        merged = merge(merged, r, LO, HI)
    # 全集 {1,2,3,4,5,2,2,9} = 8 个元素
    assert count(merged, LO, HI, 1, 20) == 8
    assert count(merged, LO, HI, 2, 2) == 3
    assert kth(merged, LO, HI, 1) == 1
    assert kth(merged, LO, HI, 4) == 2
    assert kth(merged, LO, HI, 8) == 9
    # 合并后再插入
    merged = update(merged, LO, HI, 10, 1)
    assert count(merged, LO, HI, 9, 20) == 2   # 9 与 10
    print('seg-merge ok', count(merged, LO, HI, 1, 20))
```

实现细节：`merge` 复用 `a` 的节点，把 `b` 的信息并入；叶子直接 `cnt` 相加；非叶递归后 pushup。查询 `count`/`kth` 与动态开点版一致。若要"取 max"合并，把 `cnt` 换成 `mx` 并用 `max` 合并即可。

## 五、与其他技术对比

| 方法 | 合并代价 | 空间 | 备注 |
|------|----------|------|------|
| 逐元素插入 | $O(|S|\log U)$ | $O(N)$ | 朴素 |
| 启发式 + 平衡树 | $O(|S|\log N)$ | $O(N)$ | 常数大 |
| 线段树合并 | $O(\min(|A|,|B|)\log U)$ 均摊 | $O(N)$ | 权值统计首选 |
| DSU 启发式 | $O(N\log N)$ | $O(N)$ | 不维护权值分布 |
| 离线整体二分 | $O(N\log^2 N)$ | $O(N)$ | 可避在线合并 |

取舍：需要"集合合并 + 权值查询"用线段树合并；只要连通用 DSU；离线可整体二分/分治。

## 六、常见误区

1. **合并后忘记 pushup。** 子树挂接好了但父节点 `cnt` 没更新，后续 `count`/`kth` 全错。
2. **把空节点当零节点参与递归。** `None` 应在递归入口立即返回另一方；若下钻到 `None.l` 会异常。
3. **合并时两边都新建节点。** 浪费一倍空间且容易漏挂指针；应复用其中一棵的节点。
4. **不区分"计数相加"与"最值取 max"。** 两种合并的 pushup 公式不同，混用直接错。
5. **销毁源树后仍引用旧指针。** Python 中把 `b` 置 `None` 即可；手写指针语言要防止悬垂指针。

## 八、面试题

**1. 如何合并两棵权值线段树？复杂度？**
参考答案：递归 `merge(a,b)`：空则返回另一方，叶子合并计数，非叶递归左右后 pushup。均摊 $O(\min(|A|,|B|)\log U)$，总 $O(N\log U)$。

**2. 为什么均摊能到 $O(N\log U)$ 而不是每次 $O(|A|+|B|)$ 累加？**
参考答案：节点在被合并后即"消耗"，每个节点只在有限次合并中被深度访问；总访问量不超过节点总量乘树高。

**3. 树上每个节点维护子树权值分布，怎么做？**
参考答案：自底向上把孩子线段树合并到父节点，再插入自身；复杂度 $O(N\log U)$。可再叠加树上前缀查询。

**4. 合并与分裂的关系？**
参考答案：分裂是把一棵树按条件拆成两棵，合并是把两棵并成一棵；两者都是 $O(\text{节点数})$ 级结构操作，常配合做可重集的持久化与回滚。

## 九、演进与趋势

线段树合并的后续演进：**线段树分裂/合并**成套支持可重集；**主席树 + 合并**做带版本的区间第 $k$ 小；**树上启发式合并 + 权值线段树**求子树众数；**李超树合并**维护凸壳。工程上，多副本索引合并、分片统计聚合、多人状态合成都用同一骨架。面试趋势是"合并均摊分析 + 与 DSU 启发式对比"。

## 十、小结

线段树合并把两棵动态开点权值线段树按节点递归并在一起，空侧直接挂接、双侧递归后 pushup，均摊总代价 $O(N\log U)$；它与分裂、启发式合并一起，构成"集合合并 + 权值统计"问题的高效工具箱。
