# 浮点加法的对齐与规格化流程

> 对应 Hennessy & Patterson《Computer Architecture》。

## 一、背景与挑战
两个浮点数阶码不同，尾数无法直接相加。硬件需先对齐阶码、再相加、最后规格化与舍入，流程决定了浮点加法器的延迟与精度。

## 二、核心原理
标准步骤：比较阶码 → 右移较小阶码的尾数使其阶码相等（对齐）→ 符号感知的尾数加减 → 规格化左移/右移 → 舍入 → 处理溢出与异常。

## 三、形式化与数学基础
设 a = m_a × 2^{e_a}，b = m_b × 2^{e_b} 且 e_a ≥ e_b。对齐后：

    b' = (m_b >> (e_a - e_b)) * 2^{e_a}
    result = (m_a ± b') * 2^{e_a}

规格化：若尾数最高位非 1 则左移并降阶，若溢出则右移并升阶。

## 四、代码实现
```verilog
// 简化: 对齐阶段
always_comb begin
    if (ea >= eb) begin
        shamt = ea - eb;
        mb_aligned = mb >> shamt;
        e_res = ea;
    end else begin
        shamt = eb - ea;
        ma_aligned = ma >> shamt;
        e_res = eb;
    end
end
```

## 五、与其他技术对比
乘法无需对齐但需尾数乘与阶码加；加法瓶颈在对齐移位与规格化，延迟高于整数加法。

## 六、常见误区
认为对齐一定右移小数阶码；当结果规格化需要左移时若降阶到 0 可能下溢为次正规。

## 九、演进与趋势
FMA 将乘加合并为单舍入；硬件前导零预测降低规格化延迟。

## 十、小结
浮点加法以对齐、加减、规格化、舍入四步为核心，理解其顺序依赖是解释非结合性的关键。
