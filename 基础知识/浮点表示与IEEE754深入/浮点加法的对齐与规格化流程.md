# 浮点加法的对齐与规格化流程

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》第 3 章；IEEE 754-2019 加减语义；CSAPP 第 2 章。

## 一、背景与挑战

两个浮点数 $a = m_a \times 2^{e_a}$ 与 $b = m_b \times 2^{e_b}$ 的尾数不能直接相加，除非阶码相同。若 $e_a = e_b + 10$，$m_b$ 必须右移 10 位才能与 $m_a$ 对齐到同一权重；这一步是浮点加法器与整数加法器的本质差异。对齐时移出的位不能简单丢掉，需要「保护位、舍入位、粘滞位」（guard/round/sticky）记住被移出部分，否则舍入会错。

更复杂的是相加可能改变有效位的量级：`1.0 + (-0.999...)` 的结果会变成很小的数，需要左移规格化并降低阶码；而 `0.111... + 0.000...1` 可能进位溢出，需要右移升阶。整数加法的进位只影响符号扩展，浮点加法的进位/借位会改变指数字段，流程更长。

工程师要解释清楚：为什么浮点加法不满足结合律？为什么减法（消去、cancellation）特别危险？如何用 FMA、Kahan 求和改进？这些都依赖对「对齐 → 尾数加减 → 规格化 → 舍入」流水线的精确理解。矩阵乘库、物理引擎、编译器后端优化都建立在这套语义之上：编译器不能随意重结合表达式，除非用户显式放宽数值契约。

从性能角度，浮点加法器比整数加法器长得多：比较阶码、移位对齐、加减、前导零计数、再规格化、舍入，每一步都有延迟。CPU 用前导零预测与流水化把它压到 3–5 周期，但乱序窗口仍可能被长依赖链卡住。理解这条流水线，才能明白 SIMD 向量加法为何吞吐高而延迟固定，也才能解释并行归约里「顺序不同结果不同」的根源。面试中常让手写流程或判断误差来源，而不是只背结论。

## 二、核心原理

标准浮点加法五步：

1. **比较阶码**：取 $e_s = \max(e_a, e_b)$，计算位移量 $\Delta = |e_a - e_b|$。
2. **对齐**：较小数的尾数右移 $\Delta$ 位。为了不丢信息，保留 guard（1 bit）、round（1 bit）与 sticky（此后所有被移出位的或）。若 $\Delta$ 很大（超过尾数宽度+保护位），小数对大数几乎无贡献，可简化为「粘滞为 1」的近似。
3. **尾数加减**：按符号做加或减；减法可能产生前导零，需要计数。
4. **规格化**：若结果为 0，特殊处理；若产生进位（上溢出），尾数右移 1 位、阶码加 1；若出现前导零，左移并降低阶码，直至最高位为 1（或下溢到次正规）。
5. **舍入与溢出检查**：用 GRS 位按舍入模式舍入；阶码上溢得 Inf，下溢得 0 或次正规；输出符号。

**不变量**：输出的 $(e, m)$ 必须是该结果的规范表示（或次正规/零/Inf/NaN 特例）；舍入只发生一次（在最终规格化后）。

**边界条件**：

- 两数符号相反且量级接近 → 消去（cancellation），相对误差可能被放大，尽管绝对误差仍小。
- $\Delta$ 很大时，对齐后小数全移出，结果近似大数；sticky 保证向最近偶数在「略大/略小」上正确。
- 次正规：阶码降到最小后仍需左移时，不再增加有效指数，进入次正规处理。
- NaN/Inf 传播：任一操作数为 NaN 结果为 NaN；Inf+(-Inf)=NaN；Inf+有限=Inf。
- 结果为精确零时，符号位规定为 $+0$（默认 RNE），除非两个操作数都是 $-0$。
- 超过尾数宽度的对齐移位不能真移几十位，硬件常用 sticky 归约，软件模拟也应避免 $O(\Delta)$ 的逐位循环。

**消去为何危险**：设 $a=1.234567$，$b=-1.234566$，二者本身各有约 $10^{-7}$ 的表示误差，相减后结果 $10^{-6}$ 量级，相对误差可能到百分几。算法设计上应尽量避免「相近数相减」，改用等价变形（如 $\sqrt{x+1}-\sqrt{x} = 1/(\sqrt{x+1}+\sqrt{x})$）。

## 三、形式化与数学基础

设 $e_a \ge e_b$，对齐后：

$$b' = m_b \cdot 2^{-(e_a - e_b)}$$

$$s = (m_a \pm b') \cdot 2^{e_a}$$

若 $s$ 的规格化尾数为 $m_r$、阶码 $e_r$，则最终结果：

$$r = \mathrm{round}(m_r \times 2^{e_r})$$

对齐右移的位流记为 $g\,r\,s$：$g$ 为第 1 个被移出位，$r$ 为第 2 位，$s = \bigvee_{i\ge 2} bit_i$。舍入到最近偶数时用这三比特决定是否加 1 ulp。

误差界（一次舍入）：

$$|fl(a+b) - (a+b)| \le \frac{1}{2} ulp(r)$$

但相对误差在消去时会变大。设 $a = 1.000\ldots\times 2^{0}$，$b = -0.111\ldots\times 2^{0}$，结果只有很少有效位，相对误差可达 $O(2^{-p'})$，其中 $p' \ll p$。这就是为什么减法要谨慎。

结合律失效的机制：$fl(fl(a+b)+c)$ 与 $fl(a+fl(b+c))$ 在不同顺序下对齐量与舍入点不同，得到不同 $r$。求和 $n$ 项的误差可随顺序累积到 $O(nu)$（朴素）或 $O(\sqrt{n}u)$（随机顺序）或 $O(u)$（Kahan/补偿求和）。

浮点加法延迟：比较 → 领先零计数（LZA）→ 移位 → 加法 → 再规格化 → 舍入。现代 CPU 用前导零预测与流水化把延迟压到 3–5 周期，但仍高于整数加。

## 四、代码实现

用 Python 模拟 FP32 对齐、加减、规格化与 RNE 舍入（含 GRS 简化版）：

```python
import struct


def f32_bits(x):
    return struct.unpack(">I", struct.pack(">f", x))[0]


def f32_from_bits(u):
    return struct.unpack(">f", struct.pack(">I", u))[0]


def decompose_f32(x):
    u = f32_bits(x)
    s = (u >> 31) & 1
    e = (u >> 23) & 0xFF
    f = u & 0x7FFFFF
    if e == 0:
        # 0 或次正规：有效数 0.f，真实阶码 -126
        mant = f
        exp = -126
        implicit = 0
    else:
        mant = f | (1 << 23)   # 24-bit
        exp = e - 127
        implicit = 1
    return s, exp, mant, implicit, e, f


def round_rne(mant, sticky, width=24):
    """把 (mant, sticky) 舍入到 width 位有效（RNE）。返回新的 mant。"""
    # 假设 mant 已经是「有效部分左对齐到 width+1 以上」的整数
    # 简化：认为需要舍入的是最低位之后的值
    shift = mant.bit_length() - width
    if shift <= 0:
        return mant << (-shift)
    truncated = mant >> shift
    rem = mant & ((1 << shift) - 1)
    half = 1 << (shift - 1)
    guard = rem >= half
    tie = rem == half
    lsb = truncated & 1
    if guard and (not tie or lsb == 1 or sticky):
        truncated += 1
    return truncated


def add_f32_simulated(a, b):
    """返回 (result_float, dict 过程信息)。不处理 NaN/Inf 全套，专注主路径。"""
    sa, ea, ma, ia, Ea, Fa = decompose_f32(a)
    sb, eb, mb, ib, Eb, Fb = decompose_f32(b)
    info = {"a": (sa, ea, ma), "b": (sb, eb, mb)}
    # 选择较大阶码为结果基
    if (ea, sa) > (eb, sb) or (ea == eb and ma >= mb):
        s1, e1, m1, s2, e2, m2 = sa, ea, ma, sb, eb, mb
    else:
        s1, e1, m1, s2, e2, m2 = sb, eb, mb, sa, ea, ma
    delta = e1 - e2
    info["delta"] = delta
    # 对齐：小数右移，sticky 为移出位的或
    sticky = 0
    if delta > 0:
        if delta >= 48:
            sticky = 1 if m2 else 0
            m2_shifted = 0
        else:
            mask = (1 << delta) - 1
            sticky = 1 if (m2 & mask) else 0
            m2_shifted = m2 >> delta
    else:
        m2_shifted = m2
    info["sticky"] = sticky
    # 同号加、异号减
    if s1 == s2:
        sgn, res = s1, m1 + m2_shifted
    else:
        if m1 >= m2_shifted:
            sgn, res = s1, m1 - m2_shifted
        else:
            sgn, res = s2, m2_shifted - m1
    info["res_before_norm"] = res
    if res == 0:
        return 0.0, info
    # 规格化到 24 位左右
    exp = e1
    while res < (1 << 23):
        res <<= 1
        exp -= 1
    while res >= (1 << 24):
        sticky |= res & 1
        res >>= 1
        exp += 1
    # 舍入
    res = round_rne(res, sticky, width=24)
    if res >= (1 << 24):
        res >>= 1
        exp += 1
    # 编码
    frac = res & 0x7FFFFF
    E = exp + 127
    if E <= 0 or E >= 255:
        # 简化处理溢出/下溢
        val = 0.0 if E <= 0 else float("inf")
    else:
        val = f32_from_bits((sgn << 31) | (E << 23) | frac)
    info["result_bits"] = hex(f32_bits(val)) if val == val else None
    return val, info


# 经典用例
if __name__ == "__main__":
    cases = [(1.0, 1.0), (1.0, -0.9999999), (0.1, 0.2),
             (1e20, 1.0), (3.14159, 2.71828)]
    for a, b in cases:
        got, info = add_f32_simulated(a, b)
        want = f32_from_bits(f32_bits(a + b))  # 仍受 Python double 影响，仅供对照
        print(f"{a} + {b} -> sim={got}  info_delta={info.get('delta')} sticky={info.get('sticky')}")
    # 验证对齐：1.0 + 2^-30
    got, info = add_f32_simulated(1.0, 2.0 ** -30)
    print("1 + 2^-30 =", got, "delta=", info["delta"])
```

预期：`1.0+1.0=2.0`；`1.0 + 2^{-30}` 的 `delta=30` 且 sticky 可能为 1，结果回滚为 1.0（24 位有效位装不下）；消去例出现前导零规格化。这是理解 GRS 与非结合性的最小完整实验。

## 五、与其他技术对比

| 运算 | 对齐需求 | 主要误差 | 优化 |
|------|----------|----------|------|
| 浮点加减 | 需要，右移+GRS | 消去、舍入 | LZA、前导零预测 |
| 浮点乘 | 不需要对齐 | 两次舍入（若无 FMA） | 部分积树 |
| 定点加 | 无需 | 仅溢出 | 简单 ALU |
| Kahan 求和 | 逻辑补偿 | 极小 | 补偿变量 |
| FMA | 乘加一体 | 单次舍入 | 避免中间舍入 |

与整数加法对比：整数对齐固定（同位宽），浮点要动态移位并跟踪尾部比特。与乘法对齐对比：乘法阶码相加，没有跨权重移位，但有效位乘积为 $2p$ 位，仍需舍入。与 FMA 对比：融合乘加把对齐后的乘积与加数一次性处理，避免中间舍入，是更精确也更常用的基本单元。

硬件成本上，浮点加法需要宽移位器、前导零计数器、舍入逻辑，面积与功耗都高于整数加；向量单元通过 SIMD 把多个 lane 并排摊薄成本。GPU 则用大量小浮点单元换吞吐，牺牲单线程延迟。理解加法流水线，有助于在算法层减少关键路径（例如用 Horner、FMA、补偿求和），而不只是依赖硬件提速。

## 六、常见误区

1. **「对齐总是右移小阶码」**——多数如此；但若较大阶码其实是负数且需要规格化左移，流程中还有反向规格化。关键仍是「先统一阶码，再加减，最后规格化」。
2. **「移出位直接丢掉」**——丢掉会使 RNE 在边界上出错；必须有 sticky（或等价物）知道「是否非零」。
3. **「浮点加法满足结合律」**——对齐量与舍入点依赖顺序，$(a+b)+c \ne a+(b+c)$。
4. **「减法的绝对误差很小所以没危险」**——消去使相对误差放大，迭代算法（求逆、求根）可能因此发散。
5. **「结果规格化总保持相同阶码」**——进位或前导零都会改阶码；次正规时还会出现「指数钉在最小值」的特殊路径。

## 八、面试题

1. **浮点加法为什么不满足结合律？**  
   参考答案：对齐移位与舍入依赖加法顺序，不同顺序产生不同的中间舍入，最终结果可能差数个 ulp。

2. **GRS 三位（guard/round/sticky）分别起什么作用？**  
   参考答案：保护对齐时被移出的高 2 位与其余位的或；舍入时用于判断是否进位、是否恰在中点，保证 RNE/截断等模式正确。

3. **前导零计数/预测为什么重要？**  
   参考答案：消去后结果可能有很多前导零，需要左移规格化；LZA 可与加法并行预测移位量，降低延迟。

4. **如何降低大规模求和误差？**  
   参考答案：Kahan 补偿求和、按幅值排序、使用更高精度累加器（FP64 累加 FP32）、或 FMA；避免朴素顺序累加。

## 九、演进与趋势

现代 CPU 将对齐、LZA、规格化、舍入流水化，并提供 SIMD 打包浮点加（AVX/SVE）与 FMA 单指令单舍入。GPU Tensor Core 在矩阵乘中用 FP32 累加 BF16/FP16 乘积，本质是「对齐后的更高精度累加」。软硬协同方面，编译器默认禁止不安全重结合（除非 `-ffast-math`）；数值库提供补偿求和与 reproducibility 模式（如 `math.fsum`）。学术上研究确定性并行归约（tree shape 固定）、误差自动微分工具。理解对齐与规格化，才能看懂这些优化在误差与性能之间如何取舍。

## 十、小结

浮点加法的核心是「统一步调（对齐）、加减、恢复规范（规格化）、一次舍入」；GRS 位与前导零处理保证了正确性与精度，消去现象解释了结合律失效与相对误差放大。掌握这条流水线，就掌握了浮点误差分析与数值算法调优的钥匙。
