# 浮点舍入模式与舍入到最近偶数

> 对应 IEEE Std 754-2019（第 4 章舍入方向）；Bryant & O'Hallaron《CSAPP》2.4；David Goldberg 1991 经典论文。

## 一、背景与挑战

实数轴是连续的，浮点可表示集合 $F$ 是离散格点，几乎所有运算的真实结果 $x$ 都落在两个可表示数之间，必须「投影」回 $F$。这个投影规则就是舍入模式。选错了规则，轻则统计偏差、重则数值算法发散：例如「总是向上舍入」会让长序列求和持续偏大；「截断/向零」在积分、概率计算里引入系统性负偏（对正数）。

十进制的「四舍五入」习惯并不完全适用于二进制：当 $x$ 恰好落在两个浮点数中点时，四舍五入会无条件进一，导致平均结果向上漂移。科学计算需要无系统偏差的默认策略，这就是「舍入到最近偶数」（round-to-nearest-even，RNE，也叫银行家舍入/banker's rounding）被 IEEE 754 选为默认的原因。

工程与面试要求：能说出四种舍入方向、能解释 ties-to-even 的判定、能手写 RNE、知道舍入误差界 $|fl(x)-x|\le\frac12 ulp(x)$。很多 bug 来自「以为 float 是精确小数」或「以为每个语言默认舍入都一样」。Python 的 `round`、C 的 `printf("%f")`、Java 的 `Math.round` 对 0.5 的处理并不完全一致，跨系统对账时会冒出一分钱差异。

更深层的问题是误差传播：单次舍入很小，但经过成千上万次运算后可能放大。数值线性代数用条件数刻画放大倍数，金融计价要求最后一步才舍入到分，蒙特卡洛模拟要求可复现的随机数与舍入。舍入模式不是实现细节，而是算法语义的一部分。理解 RNE 与误差界，才能跨平台解释结果差异，这也是可复现科学计算的基石。

## 二、核心原理

IEEE 754 定义四种定向舍入与默认的最近舍入：

1. **roundTiesToEven（RNE，默认）**：就近舍入；恰在中点时选尾数最低位（LSB）为 0 的那个「偶数」。
2. **roundTiesToAway**：中点时远离零。
3. **roundTowardPositive**：向 $+\infty$。
4. **roundTowardNegative**：向 $-\infty$。
5. **roundTowardZero**：向 0（截断 magnitude）。

**为什么是偶数**：中点时进或舍的概率各半的话，LSB=0 目标使最低位统计上保持平衡，大量运算后误差不累积成系统性漂移。这与十进制「银行家舍入」（0.5 情况下取偶）同理。

**实现要点**：浮点内部有 guard/round/sticky 三比特。若被舍去部分 $< 0.5 ulp$，截断；$> 0.5 ulp$，进位；$= 0.5 ulp$，看当前 LSB：LSB=1 则进位（变偶数进到偶），LSB=0 则保持（已是偶）。

**边界条件**：

- 负数：RNE 对 $-x$ 是对称的（$round(-x) = -round(x)$）。
- 次正规区：ulp 固定为最小间隔，舍入仍按同样规则。
- 舍入后可能进位跨越阶码边界（例如 $1.11\ldots\times 2^e + 0.5 ulp \to 1.00\ldots\times 2^{e+1}$）。
- 硬件状态字（如 x86 MXCSR、ARM FPCR）可切换模式；数值库常临时改模式再恢复，需注意线程局部性。
- 中点判定依赖「被舍去部分恰好等于半个 ulp」，这要求保留足够的低位信息（GRS 位），仅看最后一位会错。

**为什么需要定向舍入**：区间算术用向 $+\infty$ 与向 $-\infty$ 分别算上下界，保证真实值落在区间内；嵌入式安全计算、编译器优化（重结合）也常用定向舍入给出保守估计。默认 RNE 追求「单点最准」，定向舍入追加「最坏误差可控」，二者互补。

## 三、形式化与数学基础

设 $x$ 的两侧可表示数为 $y_- = \max\{y\in F : y \le x\}$，$y_+ = \min\{y\in F : y \ge x\}$。RNE：

$$
\mathrm{RNE}(x)=
\begin{cases}
y_- & |x-y_-| < |y_+-x| \\
y_+ & |x-y_-| > |y_+-x| \\
\text{even}(y_-, y_+) & |x-y_-| = |y_+-x|
\end{cases}
$$

其中 $\text{even}$ 取尾数最低位为 0 者。

**误差界**：设 $x$ 落在 $[2^e, 2^{e+1})$，$ulp = 2^{e-t}$（$t$ 为尾数位），则

$$|RNE(x) - x| \le \frac{1}{2} ulp(x)$$

相对误差 $|RNE(x)-x|/|x| \le 2^{-p-1}\cdot 2 = 2^{-p} = u$ 对最坏区成立，通常更小。机器精度 $u=2^{-p}$ 就是这个相对误差量级。

**单步运算的误差模型**：对四则运算（非溢出）：

$$fl(op(a,b)) = (a \; op \; b)(1 + \delta),\quad |\delta| \le u$$

这是数值分析中 backward error 分析的基石。若每次运算都有 $|\delta|\le u$，则 $n$ 步朴素计算误差可累积到 $O(nu)$；算法稳定性就是控制这个累积。

**银行家舍入的偏差**：截断对正数期望偏差 $-0.5 ulp$；RNE 期望偏差近似 0（中点进舍对称），因此随机舍入等效。

## 四、代码实现

完整实现二进制 RNE，并对照 Python 的 `round` 与 IEEE 语义：

```python
def rne_int(x: float, exp_shift: int) -> float:
    """
    把 x 量化到步长 2^{-exp_shift} 的格点上，使用 ties-to-even。
    例如 exp_shift=0 量化到整数，exp_shift=3 量化到 1/8。
    """
    scale = 2.0 ** exp_shift
    y = x * scale
    floor = int(y // 1)
    frac = y - floor
    if frac > 0.5:
        return (floor + 1) / scale
    if frac < 0.5:
        return floor / scale
    # 恰在中点：取偶数
    return (floor if floor % 2 == 0 else floor + 1) / scale


def ties_to_even_demo():
    # 量化到整数
    for v in [2.5, 3.5, 4.5, -2.5, -3.5]:
        print(v, "->", rne_int(v, 0))
    # 量化到 1/8（3 位小数）
    for v in [0.0625, 0.1875, 0.3125]:
        print(v, "->", rne_int(v, 3))


def ulp_error(x: float, p: int = 24) -> float:
    """近似 ulp(x) 对 binary 浮点。"""
    import math
    if x == 0:
        return 2 ** (-p)
    e = math.floor(math.log2(abs(x)))
    return 2 ** (e - (p - 1))


# 经典用例
if __name__ == "__main__":
    print("== RNE ==")
    ties_to_even_demo()
    # Python round 对 .5 也是 bankers（但二进制下 2.5 精确可表示）
    print("python round(2.5), round(3.5):", round(2.5), round(3.5))
    # 误差界检查：对 1/3 在 FP32 的相对误差
    x32 = float(__import__("struct").unpack("f", __import__("struct").pack("f", 1/3))[0])
    print("1/3 -> FP32 rel err:", abs(x32 - 1/3) / (1/3))
    print("u(24) =", 2.0 ** -24)
```

预期输出：`2.5->2.0, 3.5->4.0, 4.5->4.0`（偶数），负数对称；`round(2.5)=2`，`round(3.5)=4`。相对误差小于 $u=2^{-24}$。这演示了 ties-to-even 与误差界。

## 五、与其他技术对比

| 模式 | 中点行为 | 偏差 | 用途 |
|------|----------|------|------|
| RNE | 取偶 | 统计无偏 | 默认、科学计算 |
| 截断/向零 | 总是向下幅值 | 负偏（正数） | 快速、某些硬件 |
| 向 +∞ | 总进 | 正偏 | 区间算术上界 |
| 向 -∞ | 总舍 | 负偏 | 区间算术下界 |
| ties-away | 中点进位 | 正偏 | 商业四舍五入 |

与「十进制四舍五入」对比：四舍五入 0.5 进 1，长期有正偏；银行家舍入消除该漂移。与「随机舍入」对比：随机舍入也无偏但不可复现；RNE 确定性更好。

区间算术：用 `roundUp` 与 `roundDown` 分别算上下界，得到包含真实结果的区间，误差可证明。

与「随机舍入」对比：随机舍入期望无偏、但不可复现，适合某些蒙特卡洛与低精度训练；RNE 确定性强，便于调试与对账。与「截断」对比：硬件截断实现最简单，却引入固定方向偏差，长期统计不可接受。选择哪一种，取决于你要「最准」、「无偏」、「可复现」还是「可证明最坏界」。

## 六、常见误区

1. **「四舍五入就是 IEEE 默认」**——错。默认是 RNE，中点取偶；四舍五入对应 ties-away 或语言级不同规则。
2. **「向零舍入只是慢一点」**——它引入系统偏差，统计型/积分型算法会偏，且与 RNE 结果不可比。
3. **「浮点运算误差总可忽略」**——相对误差 $u$ 很小，但运算次数巨大或条件数差（消去）时误差会被放大，必须分析条件数。
4. **「任意语言/平台结果一致」**——除非严格 IEEE 并锁定舍入模式；`-ffast-math`、FMA 融合、向量归约顺序都会改变结果。
5. **「比较浮点用 ==」**——舍入导致几乎每个计算值都有微小误差，应使用容差比较；这与舍入模式同属「不要假设精确」的误区家族。

## 八、面试题

1. **为什么默认舍入选「最近偶数」而不是总是进位？**  
   参考答案：中点时总是进位会让结果长期向上漂移；ties-to-even 使进舍统计对称，消除系统偏差，适合大规模科学计算。

2. **2.5、3.5、4.5 在 RNE 下量化到整数分别是？**  
   参考答案：2.5→2、3.5→4、4.5→4（目标都是偶数）。Python `round` 对这些恰好可表示的 .5 值也按此规则。

3. **相对误差界与 u 的关系？**  
   参考答案：RNE 单次运算 $|fl(op)-op| \le 0.5 ulp$，相对误差约 $u=2^{-p}$；这是数值稳定性分析的起点。

4. **什么时候必须切换舍入模式？**  
   参考答案：区间算术、严格误差界证明、某些仿真要求确定性；要用 `fesetround`/硬件控制字，并注意线程局部状态。

## 九、演进与趋势

高精度库（MPFR）、区间算术、可复现科学计算（气候、蒙特卡洛）推动「显式控制舍入」成为一等公民；IEEE 754-2019 引入属性与准静态舍入域，便于并发一致。AI 低精度格式（BF16/FP8）也必须定义舍入：训练框架常用 RNE 或随机舍入（stochastic rounding）帮助低精度收敛。硬件方面，FMA 单次舍入、向量运算的归约顺序确定性是 GPU 可复现性研究热点。语言层面，Rust/C++ 提供更清晰的浮点语义与 `round_ties_even` 函数。理解 RNE 与误差界，才能在这些新旧格式之间做出可证明的数值选择。

## 十、小结

舍入模式定义了连续实数如何投影到离散浮点格点；IEEE 754 默认 RNE 通过「中点取偶」消除系统偏差，并给出 $\frac12 ulp$ 的误差界。理解 ties-to-even、GRS 位与 $fl(x)=x(1+\delta)$ 模型，是数值算法稳定、跨平台可复现与正确比较浮点的前提。
