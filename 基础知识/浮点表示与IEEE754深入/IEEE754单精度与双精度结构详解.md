# IEEE754单精度与双精度结构详解

> 对应 IEEE Std 754-2019；Hennessy & Patterson《Computer Architecture: A Quantitative Approach》；Bryant & O'Hallaron《CSAPP》第 2 章。

## 一、背景与挑战

1970–80 年代，不同厂商用互不兼容的浮点格式：有的把阶码放高位、有的放低位，偏置不同，舍入规则各行其是。结果是同一段科学计算代码在 IBM、DEC、Intel 机器上得到不同结果，甚至出现「改个编译器选项数值就变了」的困境。数值软件无法移植，物理仿真与金融计算的可复现性难以保证。IEEE 754-1985 应运而生，统一了二进制浮点的位布局、特殊值、舍入与异常语义；此后 2008、2019 修订不断扩展格式（含十进制浮点、半精度等）。

对今天的程序员，问题并未消失：你必须精确知道 FP32/FP64 的位划分，才能解释 `0.1+0.2!=0.3`、才能手写位级转换、才能设计与硬件兼容的序列化协议（很多深度学习 checkpoint 直接按 IEEE 位模式存储）。朴素做法是把 float 当「小数」用，忽视二进制表示误差与动态范围限制，导致精度灾难或溢出为 Inf/NaN。

单精度与双精度是使用最广的两种格式。它们的差异不是「精度高一点」，而是尾数位、阶码位、偏置、可表示范围与误差界的全面不同。工程上选型要在这四个维度上权衡：存储带宽 vs 精度 vs 范围 vs 速度。序列化协议（Parquet、HDF5、SafeTensors）直接按 IEEE 位模式存数，位布局理解错误会静默毁掉整个数据集。

今天的程序员仍必须精确知道 FP32/FP64 的位划分，才能解释 `0.1+0.2!=0.3`、手写位级转换、设计与硬件兼容的文件格式。朴素做法是把 float 当「小数」用，忽视二进制表示误差与动态范围限制，导致精度灾难或溢出为 Inf/NaN。面试中，能手写位分解、算出最小正规数与 ulp，是区分「会用」和「懂」的标志；这也是理解后续舍入、特殊值、低精度格式的共同基础。

## 二、核心原理

IEEE 754 二进制浮点由三段组成：符号位 $S$、偏置阶码 $E$、尾数（小数）$F$。规格化数的值为：

$$(-1)^S \times 2^{E - bias} \times (1.F)$$

隐含前导 1 使有效位多出 1 位精度，不必存储。

**单精度（binary32）**：32 位 = 1 + 8 + 23。$bias = 127$。阶码字段全 0 与全 1 有特殊含义：全 0 表示零或次正规数，全 1 表示 Inf 或 NaN。规格化数实际阶码范围 $e = E-bias \in [-126, +127]$。

**双精度（binary64）**：64 位 = 1 + 11 + 52。$bias = 1023$。规格化阶码 $e \in [-1022, +1023]$。

**次正规数**：阶码字段为 0 时，隐含位改为 0，用于平滑下溢，避免从最小正规数跳到 0 出现「吸收洞」（absorption gap）。

**不变量**：同一个数学值的表示唯一（除 ±0 有两种编码），这保证了二进制可复现；零有 `+0` 与 `-0`，比较时相等但 $1/+0 = +\infty$，$1/-0 = -\infty$。

**边界条件**：FP32 大约 7 位有效十进制数字，FP64 约 15–16 位；超过尾数范围的加减会丢精度，超过阶码范围会 Inf/NaN。序列化时必须注意字节序与对齐，很多文件格式直接存 `uint32`/`uint64` 位模式。

**编码唯一性**：规格化数的编码一一对应，避免了「同一值多种位模式」带来的比较与哈希混乱；但 $\pm 0$ 仍有两种编码，`memcmp` 比较浮点时会把 $+0$ 与 $-0$ 判为不同，这是序列化与哈希的经典坑。跨语言传输时建议统一转换为 canonical 位模式，或用数值比较而非字节比较。

**与整数的关系**：对正浮点数，位模式作为无符号整数时的大小顺序与数值顺序一致（偏置阶码 + 隐含前导 1 的结果）。因此可以安全地把 float 位模式转 `int32`/`int64` 做排序，前提是排除 NaN 与负零的特殊情况。很多游戏引擎与物理引擎的 `FloatFlip` 排序技巧正建立在这一点上。

## 三、形式化与数学基础

设尾数字段宽度 $t$（FP32: 23，FP64: 52），则有效精度为 $p = t+1$ 位（含隐含 1）。单位舍入间隔（unit in the last place）在规格化区间 $[2^e, 2^{e+1})$ 为：

$$ulp(x) = 2^{e - t} = 2^{e - (p-1)}$$

相对误差界（舍入到最近偶数）：

$$|fl(x) - x| \le \frac{1}{2} ulp(x) = 2^{-p-1}\cdot 2^{e+1}$$

机器精度（machine epsilon）定义为 $u = 2^{-p}$：FP64 的 $p=53$，$u = 2^{-53} \approx 1.11\times 10^{-16}$；FP32 的 $p=24$，$u = 2^{-24} \approx 5.96\times 10^{-8}$。

最大规格化值：

$$x_{max} = (2 - 2^{-t}) \times 2^{bias}$$

- FP32：$(2-2^{-23})\times 2^{127} \approx 3.4028235\times 10^{38}$
- FP64：$(2-2^{-52})\times 2^{1023} \approx 1.7976931348623157\times 10^{308}$

最小正规数：
- FP32：$2^{-126} \approx 1.17549435\times 10^{-38}$
- FP64：$2^{-1022} \approx 2.2250738585072014\times 10^{-308}$

偏置的意义：把有符号真实阶码 $e$ 映射为无符号字段 $E = e + bias$，便于硬件用无符号比较做数的大小排序（正数位模式越大数值越大）。

## 四、代码实现

用 Python `struct` 与位运算完整解析/构造 FP32，并验证经典数值：

```python
import struct


def bits_of(x: float) -> int:
    return struct.unpack(">I", struct.pack(">f", x))[0]


def float_of_bits(u: int) -> float:
    return struct.unpack(">f", struct.pack(">I", u))[0]


def decode_f32(x: float):
    u = bits_of(x)
    s = (u >> 31) & 1
    e = (u >> 23) & 0xFF
    f = u & 0x7FFFFF
    if e == 0:
        kind = "zero" if f == 0 else "subnormal"
        val = (-1) ** s * (f / (2 ** 23)) * 2 ** (-126)
    elif e == 0xFF:
        kind = "inf" if f == 0 else "nan"
        val = float("inf") if f == 0 else float("nan")
    else:
        kind = "normal"
        val = (-1) ** s * (1 + f / (2 ** 23)) * 2 ** (e - 127)
    return {"sign": s, "exp_field": e, "frac": f, "kind": kind, "value": val}


def min_normal_f32() -> float:
    return float_of_bits(1 << 23)          # exp=1, frac=0 -> 2^-126


def eps_f32() -> float:
    return 2.0 ** -24


# 经典用例
if __name__ == "__main__":
    d = decode_f32(0.1)
    print("0.1 ->", d)
    assert d["kind"] == "normal"
    assert d["exp_field"] == 123           # 2^-4 附近

    print("0.1+0.2 == 0.3 ?", (0.1 + 0.2) == 0.3)  # False
    print("min normal FP32:", min_normal_f32())
    print("eps FP32:", eps_f32())
    print("max FP32:", float_of_bits(0x7F7FFFFF))

    # 重建
    u = bits_of(1.0)   # 0x3F800000
    print("1.0 bits:", hex(u))
    assert float_of_bits(u) == 1.0
```

预期：`0.1` 的位模式为 `0x3DCCCCCD`，`0.1+0.2==0.3` 为 False，最小正规约 `1.175494e-38`。代码展示了位分解、类型判定与往返转换。

## 五、与其他技术对比

| 格式 | 位宽 | 符号/阶码/尾数 | 精度 | 范围 | 典型用途 |
|------|------|----------------|------|------|----------|
| FP32 | 32 | 1/8/23 | ~7 位十进制 | $10^{\pm38}$ | 图形、通用科学计算 |
| FP64 | 64 | 1/11/52 | ~16 位十进制 | $10^{\pm308}$ | 科学仿真、金融 |
| FP16 | 16 | 1/5/10 | ~3 位 | $10^{\pm5}$ | 图形、部分推理 |
| BF16 | 16 | 1/8/7 | ~2–3 位 | 同 FP32 | 深度学习训练 |
| TF32 | 19 | 1/8/10 | 介于 | 同 FP32 | Tensor Core 内部 |
| 定点 | 可变 | — | 精确 | 有限 | DSP、货币 |

与定点相比：浮点动态范围大，适合科学计算，但有舍入误差；定点无舍入、可精确，适合信号处理与十进制金额。与 x87 80 位扩展精度相比：FP64 更可移植、更易向量化。与 bfloat16/FP16 对比：FP32 在带宽与精度间平衡最好，是默认工作格式；FP64 用于误差敏感或范围需求大的场景；低精度格式服务 AI 与图形。

成本视角：FP64 占用是 FP32 的两倍带宽，向量宽度减半，吞吐常为 FP32 的 1/2 到 1/64（消费级 GPU 可能故意削弱 FP64）。因此数值仿真库会提供精度可选的模板，HPC 集群调度也按「是否需要 FP64」区分队列。理解格式差异不仅是正确性问题，也是性能与成本问题。

## 六、常见误区

1. **「浮点满足结合律」**——$(a+b)+c \ne a+(b+c)$ 是常态。排序求和、并行归约都可能改变结果。
2. **「用 == 比较两个 float」**——应比较绝对/相对误差，或对计算结果用 `math.isclose`。`0.1+0.2==0.3` 是经典反例。
3. **「所有十进制小数都能精确表示」**——只有分母为 2 的幂的分数可精确；`0.1` 在二进制下是无限循环，必须舍入。
4. **「双精度只是单精度加长」**——阶码位数也不同（8 vs 11），动态范围与精度同时变化；转换格式时先看范围是否会溢出。
5. **「隐含前导 1 总是存在」**——仅规格化数如此；零与次正规数没有隐含 1，NaN/Inf 的阶码字段为全 1。

## 八、面试题

1. **为什么 0.1 + 0.2 不等于 0.3？**  
   参考答案：0.1 与 0.2 在二进制下都是无限循环小数，各自舍入后与 0.3 的真实表示存在 ulp 级差异，求和后误差仍残留，`==` 比较失败。

2. **FP64 的机器精度 u 是多少？怎么推？**  
   参考答案：尾数有效 53 位，$u=2^{-53}\approx 1.11\times 10^{-16}$。它给出相对舍入误差上界量级。

3. **单精度能表示的最小正规数与最大数？**  
   参考答案：最小正规 $2^{-126}\approx 1.18\times 10^{-38}$；最大 $(2-2^{-23})\times 2^{127}\approx 3.40\times 10^{38}$。

4. **偏置阶码有什么好处？**  
   参考答案：把真实有符号阶码变成无符号字段，正浮点数的位模式比较与数值比较一致，便于排序、最大值、硬件比较器实现。

## 九、演进与趋势

从 x87 80 位扩展精度、SSE/AVX 打包浮点，到 AVX-512 与 ARM SVE 的向量 FP，位布局始终兼容 IEEE 754。AI 浪潮带来 BF16/TF32/FP8 等窄格式，但语义仍沿用「符号+阶码+尾数」骨架。可复现计算要求严格的舍入模式与禁用重结合（`-ffast-math` 慎用）；IEEE 754-2019 引入补充属性、准静态舍入域，方便多线程一致设置。序列化方面，NumPy、PyTorch、Arrow 都直接约定 IEEE 位模式。未来 FP64 在 HPC 仍不可替代，而低精度格式在 AI 中扩大使用，选型关键仍是：误差是否可接受、范围是否覆盖、硬件是否有加速。

## 十、小结

IEEE 754 用符号位、偏置阶码与隐含前导 1 统一了浮点表示，FP32 与 FP64 在精度、范围、带宽上给出两档标准选择。理解位分解、ulp 与 $u=2^{-p}$，才能正确解释舍入误差、特殊值与跨语言可复现性，这是数值软件可靠性的根基。
