# N 皇后问题

> 对应 Bell & Stevens, "A Backtracking Algorithm for the N-Queens Problem"、Skiena《The Algorithm Design Manual》第 7 章例题，以及 youngyangyang04/leetcode-master 回溯章节（N 皇后）。

## 一、背景与挑战

N 皇后要求在 $N\times N$ 棋盘上放置 $N$ 个皇后，使它们互不攻击：任意两个皇后不能同行、同列、同对角线。它是回溯算法的「Hello World」，也是衡量剪枝与状态设计能力的经典标尺。1848 年由 Max Bezzel 提出，Gauss 曾研究过 $N=8$ 的解，此后成为算法教科书的保留节目。

问题的难点在于约束的耦合性。行可以用「逐行放」这一决策顺序天然消掉（每行恰好一个皇后），但列和两条对角线是全局共享资源：在第 $r$ 行第 $c$ 列放皇后，会同时占用第 $c$ 列、主对角线 $r-c$、副对角线 $r+c$。若每次判断冲突都扫一遍已放皇后，单次检查 $O(r)$，总代价 $O(N\cdot N! \cdot N)$，在 $N=13$ 时已不可接受。必须把冲突判断降到 $O(1)$，并尽早剪掉注定失败的分支。

更深层的挑战是解的规模。N 皇后解的个数 $Q(N)$ 增长不规则：$Q(8)=92, Q(10)=724, Q(12)=14200, Q(15)=2279184$，而 $Q(27)$ 已超过两亿。若只求「一个解」，启发式与对称性剪枝可以非常快；若求「全部解」或「计数」，则必须依赖高度压缩的状态表示与剪枝。工程上，N 皇后变体出现在测试用例生成、约束求解基准、CPU 分支预测压力测试中；面试中它几乎是「回溯 + 位运算优化」的代名词。

## 二、核心原理

标准解法采用**逐行放置**：在第 $r$ 行尝试每一列 $c$，若 $(r,c)$ 不与已放皇后冲突，则放置并递归到 $r+1$；回溯时撤销。逐行保证了「每行恰好一个皇后」，行约束被决策顺序消掉，剩下的只有列约束与对角线约束。

**冲突的 $O(1)$ 检测**是核心。三个布尔数组（或位集）即可：

- `cols[c]`：第 $c$ 列是否被占用；
- `diag1[r - c + N]`：主对角线（西北-东南方向）是否被占用。同一条主对角线上 $r-c$ 恒定；
- `diag2[r + c]`：副对角线（东北-西南方向）是否被占用。同一条副对角线上 $r+c$ 恒定。

放置 $(r,c)$ 的合法性为 `not cols[c] and not diag1[r-c+N] and not diag2[r+c]`。注意 $r-c$ 取值范围是 $-(N-1)..(N-1)$，数组下标需 $+N$ 偏移；$r+c$ 范围是 $0..2N-2$，数组开 $2N$ 即可。

**位运算压缩**把三个数组压成三个整数。设 `col`、`d1`、`d2` 为位掩码，第 $c$ 位为 1 表示该列/对角线被占用，则候选列集合为

```text
available = (~(col | d1 | d2)) & ((1 << N) - 1)
while available:
    bit = available & -available        # 取最低位的 1
    available -= bit
    c = bit.bit_length() - 1            # 位号即列号
    # 放置 (r, c)，递归时：
    #   col  | bit
    #   (d1 | bit) << 1     # 主对角线编号随行号 +1
    #   (d2 | bit) >> 1     # 副对角线编号随行号 -1
```

位运算版的好处是：冲突检测与「枚举所有可用列」合并为一次位运算，常数极小；并且 `(d1 | bit) << 1`、`(d2 | bit) >> 1` 的位移正好对应 $r\to r+1$ 时对角线编号的变化——$r-c$ 不变但列号变化的效果被编码进移位。这是 N 皇后能压到极快的关键。

**正确性**依赖两个不变量：进入第 $r$ 行时，前 $r$ 行已放的皇后互不攻击（剪枝保证）；`cols/diag` 与棋盘状态严格一致（撤销保证）。只要逐行尝试所有列且冲突检测完备，就能枚举全部解。对称性剪枝（如首行只放前 $N/2$ 列，再利用左右镜像翻倍）可在计数时再减一半，但会增加实现复杂度，面试中一般不作要求。

## 三、形式化与数学基础

设第 $r$ 行放置的列号为 $x_r$，则一个解是 $\{0,1,\ldots,N-1\}$ 的一个排列 $x$，满足对任意 $i \ne j$：

$$
x_i \ne x_j,\qquad |i - j| \ne |x_i - x_j|.
$$

第一式即列互异，第二式即对角线互异（$r-c$ 与 $r+c$ 分别恒定等价于 $|i-j| = |x_i-x_j|$）。

无剪枝时搜索树为 $N$ 层满 $N$ 叉树，节点数

$$
\sum_{r=0}^{N} N^{r} = \frac{N^{N+1}-1}{N-1} = \Theta(N^{N}),
$$

比 $N!$ 还大（因为未强制列互异）。加列约束后剪成 $N!$ 的排列树；再加对角线约束，实际访问节点远小于 $N!$。对 $N=8$，纯排列枚举是 $40320$ 个叶子，而实际回溯只访问约两万节点；$N=12$ 时比例更悬殊。

位运算版单节点工作量为 $O(1)$（位运算 + 常数次操作），总时间 $O(\text{访问节点数})$，空间 $O(N)$（递归栈）。计数问题的时间复杂度同上，解数 $Q(N)$ 无闭式，OEIS A000170 给出序列；渐近上 $Q(N) \sim N! / e^{2}$ 的猜想并不准确，已知 $\frac{Q(N)}{N!}$ 随 $N$ 缓慢衰减，界估计是活跃研究方向。

正确性归纳证明：设前 $r$ 行为合法放置。在 $r$ 行枚举所有列，冲突检测恰过滤掉与已放皇后同列/同对角线的位置，因此递归进入的仍是合法部分解。$r=N$ 时得到合法完整解。由归纳，所有合法解都被枚举；又因剪枝只删非法位置，不漏解。

## 四、代码实现

先给布尔数组版（好读），再给位运算版（极快）。均返回全部解。

```python
from typing import List


def solve_n_queens(n: int) -> List[List[int]]:
    """布尔数组版：返回全部解，每个解是列号列表。"""
    cols = [False] * n
    d1 = [False] * (2 * n)   # 下标 r - c + n
    d2 = [False] * (2 * n)   # 下标 r + c
    ans: List[List[int]] = []
    path: List[int] = []

    def dfs(r: int) -> None:
        if r == n:
            ans.append(list(path))
            return
        for c in range(n):
            k1, k2 = r - c + n, r + c
            if cols[c] or d1[k1] or d2[k2]:
                continue
            cols[c] = d1[k1] = d2[k2] = True
            path.append(c)
            dfs(r + 1)
            path.pop()
            cols[c] = d1[k1] = d2[k2] = False

    dfs(0)
    return ans


def solve_n_queens_bit(n: int) -> List[List[int]]:
    """位运算压缩版：col/d1/d2 用整数位掩码表示占用。"""
    ans: List[List[int]] = []
    path: List[int] = []

    def dfs(r: int, col: int, d1: int, d2: int) -> None:
        if r == n:
            ans.append(list(path))
            return
        # 可用列：未被列/两对角线占用的位
        available = (~(col | d1 | d2)) & ((1 << n) - 1)
        while available:
            bit = available & -available          # 最低位的 1
            available -= bit
            c = bit.bit_length() - 1
            path.append(c)
            # 主对角线编号随行号 +1 -> 左移；副对角线随行号 -1 -> 右移
            dfs(r + 1, col | bit, (d1 | bit) << 1, (d2 | bit) >> 1)
            path.pop()

    dfs(0, 0, 0, 0)
    return ans


def total_n_queens(n: int) -> int:
    """只计数，不存解。"""
    count = 0

    def dfs(r: int, col: int, d1: int, d2: int) -> None:
        nonlocal count
        if r == n:
            count += 1
            return
        available = (~(col | d1 | d2)) & ((1 << n) - 1)
        while available:
            bit = available & -available
            available -= bit
            dfs(r + 1, col | bit, (d1 | bit) << 1, (d2 | bit) >> 1)

    dfs(0, 0, 0, 0)
    return count


def to_board(cols: List[int]) -> List[str]:
    n = len(cols)
    return [''.join('Q' if c == cols[r] else '.' for c in range(n)) for r in range(n)]


if __name__ == "__main__":
    assert total_n_queens(8) == 92
    assert total_n_queens(4) == 2
    assert sorted(solve_n_queens(4)) == sorted(solve_n_queens_bit(4))
    for sol in solve_n_queens_bit(4):
        print(to_board(sol))
    print("N=8 count:", total_n_queens(8))
```

## 五、与其他技术对比

| 方法 | 冲突检测 | 思路 | 速度 | 适用 |
| --- | --- | --- | --- | --- |
| 暴力全排列 + 校验 | $O(N)$ 扫描 | 枚举排列再验对角线 | 极慢 | 仅教学 |
| 布尔数组回溯 | $O(1)$ | 三数组记录占用 | 快，易读 | 面试首选 |
| 位运算回溯 | $O(1)$，常数更小 | 三掩码 + 移位 | 极快 | 计数/大规模 N |
| 迭代加深 + 启发式 | $O(1)$ | 先找一解，启发式定行序 | 找一解快 | 只需一个解 |
| DLX 精确覆盖 | 建模为精确覆盖 | Dancing Links | 通用但重 | 数独/通用 CSP |

与数独的关系：N 皇后是「逐行放 + 三类全局约束」的特例；数独是「每格一个变量 + 行列宫约束」，约束传播更复杂。与位运算专题的关系：`(bit & -bit)` 取最低位、`~(mask)` 取补、移位更新对角线掩码，都是位运算压缩状态的典范写法。

## 六、常见误区

1. **对角线编号未偏移导致数组越界**。$r-c$ 为负数，直接当下标会用 Python 负下标取到末尾元素，产生隐式错误。必须用 $r-c+N$，或改用字典/位掩码。
2. **忘记撤销标记**。`cols[c] = False` 若漏掉或与递归配对错位，状态被污染，后续分支误判冲突，结果偏少且极难排查。
3. **位运算版移位方向搞反**。主对角线 $r-c$：行号增加时，为保持编号差，掩码应左移；副对角线 $r+c$：行号增加时右移。写反会导致漏解或重复。
4. **用递归存解时存了引用**。`ans.append(path)` 而非 `list(path)`，所有解会变成最后一个叶子。
5. **`bit.bit_length() - 1` 与列号对应错误**。`bit_length` 返回最高位下标+1，对单比特正好是列号+1；若掩码含多位则完全错误。必须保证传入的是单比特。

## 八、面试题

**1. 为什么主对角线用 $r-c$ 标识、副对角线用 $r+c$？**

参考答案：同一主对角线上的格子行列差恒定（西北-东南），同一副对角线上的格子行列和恒定（东北-西南）。用这两个量做键，可把「是否同对角线」化为 $O(1)$ 查表。注意 $r-c$ 有负数需偏移。

**2. 如何用位运算加速 N 皇后？复杂度变化？**

参考答案：用三个整数位掩码表示列与两对角线的占用，`available = ~(col|d1|d2) & mask` 一次得到所有合法列，`bit & -bit` 逐个取出。递归时 `(d1|bit)<<1`、`(d2|bit)>>1` 编码对角线随行号的漂移。渐近复杂度不变（仍受解数支配），但常数大幅下降，计数 $N=15$ 可在毫秒级完成。

**3. N 皇后与全排列枚举的关系？**

参考答案：每个解可看作列号的一个排列（每行不同列）。纯排列枚举再校验对角线是 $O(N\cdot N!)$；回溯在放置时就检查对角线，等价于对排列树做可行性剪枝，访问节点少得多。

**4. 如何只判断 $N$ 皇后是否有解？**

参考答案：回溯找到第一个解即返回；可加对称性（首行只试前 $\lceil N/2 \rceil$ 列）或已知结论：$N \ge 4$ 时均有解（$N=2,3$ 无解）。数学上这是经典存在性结果，无需搜索。

## 九、演进与趋势

N 皇后解的计数与枚举是组合数学长期课题：$Q(N)$ 的渐近界、对称解、互不攻击的超级皇后（同时控制骑士步）等变体持续被研究。大额 $N$（如 $N=27$ 以上）的完全枚举依赖分布式搜索、位并行 SIMD、对称性削减与分支定界，曾有多篇论文报告用集群完成 $N=27$ 的全枚举。

工程上，N 皇后是约束求解器的标准基准：Gecode、OR-Tools、MiniZinc 等 CSP/CP 工具用它对比变量序启发式（MRV、度启发式）与传播算法的性能。测试领域用它生成高冲突配置以压测分支预测与缓存。掌握 N 皇后，等于掌握了一把衡量约束搜索效率的标尺。

## 十、小结

N 皇后是「回溯 + $O(1)$ 冲突检测」的范本：逐行放消掉行约束，列与两条对角线用三组标记 $O(1)$ 判断；位运算把标记压成整数并用移位编码对角线漂移，常数极小。对角线编号 $r-c$（需偏移）与 $r+c$ 是全部状态设计的核心。把布尔版与位运算版都写熟，面试中的 N 皇后、数独、解数独类题目都能快速落地。
