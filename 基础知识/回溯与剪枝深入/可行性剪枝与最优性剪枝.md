# 可行性剪枝与最优性剪枝

> 对应 Skiena《The Algorithm Design Manual》第 7 章分支定界、Horowitz & Sahni《Fundamentals of Computer Algorithms》分支定界章节，以及 youngyangyang04/leetcode-master 回溯剪枝专题。

## 一、背景与挑战

裸回溯枚举整棵状态空间树，最坏复杂度是指数级甚至阶乘级。剪枝（Pruning）是让回溯「能用」的唯一系统性手段：在搜索过程中提前判断某些分支不可能产生合法解（可行性剪枝），或不可能优于当前已知最优解（最优性剪枝），从而整棵子树跳过。没有剪枝的回溯只是换了写法的暴力；有了剪枝，同一套框架能在毫秒内解决 $N$ 皇后、旅行商、0-1 背包等看似爆炸的问题。

难点在于剪枝的**正确性**与**强度**往往互相牵制。剪枝条件写得太松，子树只砍掉一点点，照样超时；写得太紧，可能误剪含有合法解（甚至最优解）的分支，答案静默出错。更隐蔽的是边界：最优性剪枝常用 `cost >= best`，但当要求「所有最优解」时必须写 `cost > best`，否则会漏掉并列最优。再比如下界估计若高估了剩余代价（non-admissible），同样会误剪。

工程与面试中，剪枝意识是区分「会写回溯」与「写得出能过的回溯」的分水岭。LeetCode 困难回溯题（N 皇后 II、解数独、划分为 k 个等和子集、旅行商状压 DP 前的回溯基线）都在考察：能否发现约束、能否设计下界、能否在正确的地方用正确的不等号。工业界的分支定界求解器（整数规划、调度优化）本质上就是「系统化 + 带启发式的最优性剪枝」。

## 二、核心原理

**可行性剪枝（Feasibility Pruning）**：当前部分解已违反某条约束，任何扩展都不可能合法，立即返回。例子：组合总和中 `当前和 > target`（全为正数时）；N 皇后中列/对角线冲突；数独某格候选集为空；排列中元素重复且未去重。可行性剪枝的判断越早越好——在「做出选择之前」过滤，而不是递归进来才发现。

**最优性剪枝（Optimality Pruning / Bound Pruning）**：当前代价已不可能比已知最优解更好，停止深入。设 $g$ 为当前部分解已花费代价，$h$ 为剩余部分的**下界估计**（至少还要花多少），$best$ 为当前最优。若

$$
g + h \ge best
$$

则剪枝（求最小值问题）。这正是分支定界（Branch and Bound）的核心。$h=0$ 时退化为 `g >= best` 的朴素版本；$h$ 越紧，剪得越多。

**正确性条件**：可行性剪枝必须只删「不可扩展为合法解」的分支；最优性剪枝的 $h$ 必须是 **admissible**（可采纳）：不高估真实剩余代价，即 $h \le h^*$（$h^*$ 为真实最小剩余代价）。满足可采纳性时，$g+h \ge best$ 蕴含该分支最终代价 $\ge best$，剪掉不丢最优解。若只求任意最优解，等号可剪；若求全部最优解，需 $g+h > best$。

**剪枝的叠加**：多种剪枝可以同时使用，取条件的交集（任一满足即剪）。常见组合是「可行性 + 下界 + 对称性剪枝」。对称性剪枝（如子集枚举中强制升序、TSP 固定起点）砍掉的是「本质相同」的分支，正确性来自解的等价类划分。

**边界条件**：`best` 的初始化必须是严格上界（如 $+\infty$，或先用贪心求一个可行解）。若 `best` 初始化为 0，最优性剪枝会立刻剪光所有分支，得到空解——这是常见事故。

## 三、形式化与数学基础

设状态空间树 $T$，每个节点 $v$ 对应部分解，$g(v)$ 为已花代价，$h(v)$ 为剩余下界，$f(v)=g(v)+h(v)$。求最小值时的剪枝规则：

$$
\text{若 } f(v) \ge best \text{，则 } v \text{ 的子树中不含更优解。}
$$

证明：设 $v$ 的某个子孙叶子 $\ell$ 的总代价为 $g(\ell)$。由于 $h$ 是剩余代价的下界，$g(\ell) \ge g(v) + h(v) = f(v) \ge best$，故 $\ell$ 不优于当前最优，剪枝安全。

分支定界的完整框架：维护优先队列按 $f$ 值展开最有希望的节点（最佳优先）或按 DFS 展开；每找到一个完整解就更新 $best$；展开时对每个孩子做 $f$ 测试。设最优解代价为 $C^*$，可采纳启发式 $h \le h^*$，则算法终止时 $best = C^*$。

搜索树规模分析：令 $T'$ 为剪枝后保留的节点集。可行性剪枝删除所有「前缀已违反约束」的子树；最优性剪枝删除所有 $f \ge best$ 的子树。于是

$$
|T'| = \#\{v \in T : v \text{ 前缀可行且 } f(v) < best\}.
$$

$h$ 越紧（越接近 $h^*$），$f$ 越大，剪掉越多。极端情况 $h=h^*$ 时，算法直接沿最优路径搜索，只展开 $O(\text{深度})$ 节点——这就是 A* 的理想行为。

可行性剪枝可视为 $h = +\infty$ 的特例：违反约束即「无穷代价」，$f=+\infty \ge best$ 恒成立。这给出了两种剪枝的统一视角。

## 四、代码实现

以「0-1 背包求最小代价 / 组合最优化」为载体，展示可行性剪枝 + 最优性剪枝 + 贪心初始上界。附带一个可运行的「划分等和子集」示例（LeetCode 416 同类）。

```python
from typing import List


def knapsack_min_cost(values: List[int], costs: List[int], capacity: int) -> float:
    """
    在总花费不超过 capacity 的前提下，最大化 values 之和。
    这里用「最小化 -value」的视角展示最优性剪枝；
    同时用可行性剪枝砍掉超容量分支。
    """
    n = len(values)
    best = 0  # 最大价值，初始 0（贪心可改进）

    # 贪心初始上界：按性价比排，能装就装（用于收紧 best，可选）
    order = sorted(range(n), key=lambda i: -values[i] / costs[i] if costs[i] else 1e9)
    g_cap, g_val = 0, 0
    for i in order:
        if g_cap + costs[i] <= capacity:
            g_cap += costs[i]
            g_val += values[i]
    best = g_val

    # 剩余价值后缀上界（用于最优性剪枝）：从 i 到末尾的最大可能追加
    # 这里用「排序后剩余全拿」的松弛上界
    sorted_vals_desc = sorted(values, reverse=True)
    suffix_bound = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suffix_bound[i] = suffix_bound[i + 1] + sorted_vals_desc[i]

    def dfs(i: int, cap: int, val: int) -> None:
        nonlocal best
        if i == n:
            best = max(best, val)
            return
        # 最优性剪枝：即使后面全拿（上界）也超不过 best
        # 注意 suffix_bound 是「任意顺序剩余全拿」的上界，admissible
        if val + suffix_bound[n - i] <= best:
            return
        # 不选
        dfs(i + 1, cap, val)
        # 选（可行性剪枝：超容量则不进）
        if cap - costs[i] >= 0:
            dfs(i + 1, cap - costs[i], val + values[i])

    dfs(0, capacity, 0)
    return best


def can_partition(nums: List[int]) -> bool:
    """LeetCode 416：能否分成两个和相等的子集。
    可行性剪枝：当前和超过目标即停；最优性式剪枝：排序后从大到小试。
    """
    total = sum(nums)
    if total % 2:
        return False
    target = total // 2
    nums.sort(reverse=True)  # 大数优先，尽早逼近/超界，剪枝更强

    def dfs(i: int, remain: int) -> bool:
        if remain == 0:
            return True
        if i == len(nums) or remain < 0:
            return False
        # 可行性剪枝已在 remain < 0 处理
        # 选 nums[i]
        if dfs(i + 1, remain - nums[i]):
            return True
        # 不选
        return dfs(i + 1, remain)

    return dfs(0, target)


def tsp_branch_and_bound(dist: List[List[int]]) -> float:
    """
    小规模 TSP 的分支定界：g = 已走路径长度，h = 未访问点的最小出边和（下界）。
    展示最优性剪枝 g + h >= best 即剪。
    """
    n = len(dist)
    best = float('inf')
    # 每个点的最小出边，作为剩余代价下界（admissible）
    min_out = [min(dist[i][j] for j in range(n) if j != i) for i in range(n)]

    def dfs(u: int, visited: int, count: int, cost: int) -> None:
        nonlocal best
        # 下界：剩余 n-count 个点至少还要 (n-count) 条最小出边 + 回起点
        rest = n - count
        if rest > 0:
            h = sum(min_out[i] for i in range(n) if not (visited >> i) & 1)
            h += min(dist[u][i] for i in range(n) if not (visited >> i) & 1)  # 至少一条出边
        else:
            h = dist[u][0]  # 回到起点
        if cost + h >= best:
            return  # 最优性剪枝
        if count == n:
            total = cost + dist[u][0]
            if total < best:
                best = total
            return
        for v in range(n):
            if (visited >> v) & 1:
                continue
            dfs(v, visited | (1 << v), count + 1, cost + dist[u][v])

    dfs(0, 1, 1, 0.0)
    return best


if __name__ == "__main__":
    assert can_partition([1, 5, 11, 5])
    assert not can_partition([1, 2, 3, 5])
    # 4 点 TSP 对称距离矩阵
    d = [
        [0, 10, 15, 20],
        [10, 0, 35, 25],
        [15, 35, 0, 30],
        [20, 25, 30, 0],
    ]
    assert tsp_branch_and_bound(d) == 80.0
    print("pruning demos ok")
```

## 五、与其他技术对比

| 技术 | 核心思想 | 剪枝依据 | 适用 |
| --- | --- | --- | --- |
| 纯回溯 | 全枚举 | 无 | 只能出小数据 |
| 可行性剪枝 | 违约束即停 | 硬约束 | 一切 CSP |
| 最优性剪枝 / 分支定界 | $g+h\ge best$ 剪 | 下界 $h$ | 组合优化 |
| IDA* | 迭代加深 + $f=g+h$ | $f$ 超阈值即停 | 内存受限、深度未知 |
| A* / Dijkstra | 最优先展开 $f$ 小的点 | 启发式排序 | 图最短路、寻路 |
| 记忆化 / DP | 缓存等价子问题 | 最优子结构 | 状态可压缩时 |
| 动态规划 + 状压 | 把搜索改成 DP | 重叠子问题 | TSP、背包、小 $n$ |

剪枝与分支定界的关系：B&B 是剪枝的系统化框架，把「下界剪枝 + 优先队列 + 可行解更新」工程化。IDA* 把 $f=g+h$ 的剪枝用于迭代加深 DFS，内存 $O(\text{深度})$，适合 15 拼图等场景。与 DP 相比：若子问题高度重叠且可表征，DP 远快于搜索；若状态空间不规则、约束复杂，剪枝回溯更灵活。

## 六、常见误区

1. **下界 $h$ 高估（non-admissible）导致误剪最优解**。例如 TSP 中用「剩余点最小出边和」是合法下界；若改用「剩余点两两最小边」可能高估（当两点间必经中间点时），会把最优解剪掉，结果偏大且难以察觉。
2. **`best` 初始化错误**。若用 `best = 0` 做最小化，或最大化时用 `best = float('inf')` 而不改，剪枝会把整棵树剪光，返回无意义结果。最小化应初始化 $+\infty$ 或先用贪心赋值；最大化初始化 $0$ 或负无穷。
3. **不等号边界错误**。求「所有最优解」时用 `>=` 会漏掉并列最优；求「任意最优解」时用 `>` 会多搜索等于最优的分支（慢但正确）。必须根据需求选 `>=` 还是 `>`。
4. **可行性剪枝写得太早**。例如在「选或不选」之前就用 `if cost >= best: return`，但此时 `cost` 可能还没算完整，导致漏掉「选了更优物品后变好」的路径。最优性剪枝要在 `cost`/`h` 都是当前节点的确切值时再判断。
5. **忽视可行性剪枝与最优性剪枝的顺序**。通常先做便宜的可行性判断（$O(1)$ 比较），再算 $h$（可能 $O(n)$）。反过来在热路径上算 $h$ 会拖慢整体，即使剪枝率不变。

## 八、面试题

**1. 如何设计 admissible 下界用于最优性剪枝？**

参考答案：下界必须不高估剩余真实代价。常用构造：松弛问题的最优值（如 TSP 去掉「回到起点」约束后的最小出边和；背包中剩余物品按单位价值的分数上界）；或忽略部分约束后的易解问题。验证方法是问「是否存在某种走法比这个估计更省？」若存在，则估计非 admissible。

**2. 可行性剪枝与最优性剪枝能否同时用？**

参考答案：可以，且通常必须同时用。可行性剪枝剔除非法分支，最优性剪枝剔除「合法但无望更优」的分支，二者交集才是搜索空间。实践上先判可行（便宜），再算下界（可能贵）。二者都不影响正确性，只要各自的正确性条件成立。

**3. 为什么求所有最优解时剪枝条件不能带等号？**

参考答案：当 $g+h = best$ 时，该分支可能产生另一个代价等于 $best$ 的解。若用 $\ge$ 剪掉，就会漏掉并列最优解。求「任意最优」时可以剪；求「全部最优」时必须用 $>$，或在剪枝判断前先接受完整解。

**4. 分支定界与回溯的区别？**

参考答案：回溯主用于枚举/判定，剪枝以可行性为主；分支定界主用于优化，维护 `best` 与下界 $h$，用 $g+h\ge best$ 剪枝，并常结合优先队列最佳优先展开。两者共享状态空间树与撤销机制，B&B 是回溯在优化问题上的强化版。

## 九、演进与趋势

剪枝技术与现代求解器深度结合。整数规划求解器（CPLEX、Gurobi、SCIP）用线性规划松弛作下界、结合割平面与分支定界，能解百万变量的调度与物流问题。SAT/CDCL 求解器用冲突学习代替盲剪，效果远超朴素回溯。机器学习侧，学习式启发式（learning to branch）用 GNN 预测分支变量，已在若干基准上超过手工启发式。

工程应用里，剪枝思想无处不在：数据库查询优化的分支限界搜索、编译器指令调度的搜索剪枝、机器人路径规划的 A*/IDA*、游戏 AI 的 alpha-beta 剪枝（本质是最优性剪枝在对抗搜索中的特例）。理解可采纳性与剪枝边界，是理解所有这些系统的共同基础。

## 十、小结

剪枝分两种：可行性剪枝（违约束即停）与最优性剪枝（$g+h\ge best$ 即停），后者即分支定界的灵魂。正确性来自「只删无解/无望子树」，强度来自下界 $h$ 的紧致程度（可采纳且越接近真实代价越好）。`best` 初始化、不等号边界、剪枝时机是三大事故点。把剪枝与 MRV、对称性削减、贪心初始解叠加，才能让回溯从「能写」变成「能过」。
