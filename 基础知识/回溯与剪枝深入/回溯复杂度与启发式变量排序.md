# 回溯复杂度与启发式变量排序

> 对应 Russell & Norvig《Artificial Intelligence: A Modern Approach》第 6 章 CSP、Skiena《The Algorithm Design Manual》第 7 章，以及 Rossi, van Beek & Walsh《Handbook of Constraint Programming》变量序与值序章节。

## 一、背景与挑战

回溯的最坏复杂度是指数级——这是理论事实，无法用任何启发式改变。但实践中，同样规模的实例，有无启发式、启发式好坏，运行时间可以差几个数量级，甚至「无解/无解」的判定从超时变成瞬间。这说明：**变量与值的选择顺序决定了实际访问的搜索树规模**，是回溯工程化的核心杠杆。

为什么要专门讨论变量序？因为在约束满足问题（CSP）里，变量赋值顺序并非无关紧要。先赋一个候选很多、约束很少的变量，几乎不减少后续分支；先赋一个候选很少的变量，能立刻传播约束、把失败暴露在浅层。同理，值序影响「多快碰到好解」：求一个解时先试最有希望的值，能大幅缩短搜索；求全部解时值序影响不大，但仍影响常数。

挑战在于：启发式本身有开销（每次选变量都要扫一遍域、算冲突数），选不好可能得不偿失；启发式只改变常数与实际规模，不改变最坏界，面试官常追问「理论复杂度变了吗」；此外，变量序与值序、剪枝、传播强度是耦合的，单点优化未必带来整体加速。工程上，CSP 求解器（Gecode、OR-Tools）把 MRV、度启发式、最少约束值做成标准配置，调度、编译、验证问题的实际性能很大程度取决于这些启发式。

## 二、核心原理

**变量序（Variable Ordering）** 决定「下一个赋值谁」：

1. **MRV（Minimum Remaining Values，最小剩余值）**：选择当前候选集最小的变量。直觉是「失败优先」（fail-first）——最有约束的变量先处理，要么立刻确定，要么立刻暴露矛盾，避免把失败拖到深层才发现。
2. **度启发式（Degree Heuristic）**：与最多未赋值变量相连的变量优先。用于打破 MRV 的平局：约束最多的变量对后续影响最大，先赋值收益高。
3. **动态组合**：MRV 做主键、度做次键，即 `min(unassigned, key=lambda v: (len(dom[v]), -degree(v)))`。

**值序（Value Ordering）** 决定「先试哪个值」：

1. **最少冲突值（Least-Constraining Value, LCV）**：选择从邻居域中删掉值最少的取值，给后续变量留最多选择。适用于求一个解：「先试最容易成功的」。
2. **学习/统计序**：用历史成功率、随机动态重启等学习出的顺序，工业求解器常用。
3. **求全部解时**：LCV 意义不大（所有值都要试），但好的值序能让「有用解」先出现，便于交互式求解。

**传播与剪枝的协同**：MRV 的收益依赖候选集维护（前向检验或更强传播）。若每次重算候选，MRV 开销大；若维护增量域削减，MRV 几乎免费。弧相容（AC-3）每次赋值后把约束推到邻居域上，与 MRV 天然配套：域削减后 MRV 的选择更准，剪枝更早。

**正确性**：变量序与值序只改变访问顺序，不改变解集。只要最终枚举完整（无剪枝错误），任何序都是完备的。启发式是性能优化，不是正确性来源。

## 三、形式化与数学基础

设搜索树深度为 $n$，第 $k$ 层分支因子为 $b_k$。树中节点数

$$
|T| = \prod_{k=1}^{n} b_k,\qquad
\log |T| = \sum_{k=1}^{n} \log b_k.
$$

MRV 的作用是压低早期的 $b_k$：令 $b_k = |D_k|$ 为被选变量的候选数。由于 $\log$ 是凹函数、总节点数是连乘，早期 $b_k$ 的下降带来乘法级收益。极端情形：若每步都能选到 $|D_k|=1$ 的变量（约束传播充分），则 $|T| = 1$，无需回溯。

更精细的分析引入「失败深度」。设平均失败深度为 $d_f$，则无启发式时大量节点在 $d_f \approx n$ 处被剪；MRV 让失败提前到 $d_f \ll n$，剪掉的子树规模从 $b^{n-d_f}$ 量级变为 $b^{n-d_f'}$，收益呈指数。

LCV 的价值可从「首次成功率」看：设每个值扩展成功的概率为 $p_i$，LCV 倾向选 $p_i$ 大的值，期望搜索节点数与 $\sum_i (1-p_1)(1-p_2)\cdots$ 相关，先试高 $p$ 能减少大量无效分支。

复杂度结论要分清两层：**最坏复杂度不变**，仍为 $O(b^n)$（组合搜索固有指数）；**实际/平均复杂度**可从「不可解」降到「毫秒」。面试中应答：启发式不改变渐近界，但决定实用性；与剪枝、传播叠加时，实际节点数可近多项式。

信息论视角：每赋一个变量，搜索空间被切分；好的变量序是「每单位信息量最大化削减搜索空间」，MRV/LCV 是对这一目标的贪心近似。

## 四、代码实现

一个带 MRV + 度启发式 + LCV 的通用 CSP 求解器骨架，以及在 N 皇后上的对照实验。

```python
from typing import Any, Callable, Dict, List, Optional, Set, Tuple


class CSP:
    """简单 CSP：变量名 -> 值域集合；约束为二元谓词 constraints[(x,y)](xv,yv)。"""

    def __init__(self, variables: List[Any], domains: Dict[Any, List[Any]]):
        self.variables = variables
        self.domains = {v: list(domains[v]) for v in variables}
        self.neighbors: Dict[Any, List[Any]] = {v: [] for v in variables}
        self.constraints: Dict[Tuple[Any, Any], Callable[[Any, Any], bool]] = {}

    def add_constraint(self, x: Any, y: Any, pred: Callable[[Any, Any], bool]) -> None:
        self.constraints[(x, y)] = pred
        self.constraints[(y, x)] = lambda a, b: pred(b, a)
        self.neighbors[x].append(y)
        self.neighbors[y].append(x)

    def select_variable(self, assigned: Set[Any]) -> Any:
        """MRV：候选最少；平局用度启发式（约束多的优先）。"""
        unassigned = [v for v in self.variables if v not in assigned]

        def key(v: Any) -> Tuple[int, int]:
            return (len(self.domains[v]), -len(self.neighbors[v]))

        return min(unassigned, key=key)

    def order_values(self, var: Any) -> List[Any]:
        """LCV：选择对邻居约束最少的值。"""
        def conflict_count(val: Any) -> int:
            cnt = 0
            for nb in self.neighbors[var]:
                pred = self.constraints.get((var, nb))
                if pred is None:
                    continue
                # 邻居还有多少值与 val 相容（越少说明 val 越具约束性）
                ok = sum(1 for nv in self.domains[nb] if pred(val, nv))
                cnt += (len(self.domains[nb]) - ok)
            return cnt

        return sorted(self.domains[var], key=conflict_count)

    def is_consistent(self, var: Any, val: Any, assigned: Dict[Any, Any]) -> bool:
        for nb, nv in assigned.items():
            pred = self.constraints.get((var, nb))
            if pred is not None and not pred(val, nv):
                return False
        return True

    def backtrack(self, assigned: Optional[Dict[Any, Any]] = None) -> Optional[Dict[Any, Any]]:
        assigned = {} if assigned is None else assigned
        if len(assigned) == len(self.variables):
            return dict(assigned)
        var = self.select_variable(set(assigned))
        for val in self.order_values(var):
            if not self.is_consistent(var, val, assigned):
                continue  # 可行性剪枝
            assigned[var] = val
            res = self.backtrack(assigned)
            if res is not None:
                return res
            del assigned[var]  # 撤销
        return None


def nqueens_csp(n: int) -> Optional[Dict[int, int]]:
    """把 N 皇后建成 CSP 并用 MRV+LCV 求一解，对照实验用。"""
    variables = list(range(n))
    domains = {r: list(range(n)) for r in variables}
    csp = CSP(variables, domains)
    for i in range(n):
        for j in range(i + 1, n):
            def pred(a: int, b: int, _i=i, _j=j) -> bool:
                return a != b and abs(_i - _j) != abs(a - b)
            csp.add_constraint(i, j, pred)
    return csp.backtrack()


if __name__ == "__main__":
    sol = nqueens_csp(8)
    assert sol is not None
    assert len(sol) == 8
    # 校验互不攻击
    items = sorted(sol.items())
    for i in range(len(items)):
        for j in range(i + 1, len(items)):
            r1, c1 = items[i]
            r2, c2 = items[j]
            assert c1 != c2 and abs(r1 - r2) != abs(c1 - c2)
    print("8-queens via CSP+MRV+LCV:", [sol[r] for r in range(8)])
```

对照实验（概念）：把 `select_variable` 改成固定顺序 `next(v for v in self.variables if v not in assigned)`，`order_values` 改成原始 `self.domains[var]`，在 $n=10$ 以上的皇后或中等规模图着色上，节点数会多一个数量级以上。

## 五、与其他技术对比

| 策略 | 规则 | 效果 | 适用 |
| --- | --- | --- | --- |
| 固定顺序 | 按变量下标 / 输入序 | 实现最简，易卡死 | 教学、极小实例 |
| MRV | 选候选最少变量 | 失败提前，指数级削减 | 通用 CSP 首选 |
| 度启发式 | 选约束最多变量 | 打破平局、局部影响大 | 与 MRV 组合 |
| LCV | 试约束最少的值 | 求一解时成功率高 | 找任意解 |
| 随机/学习序 | 动态重启、学习分支 | 工业求解器标配 | 大规模实例 |
| 约束传播 + MRV | 域削减后再选变量 | 效果翻倍 | AC-3/前向检验配套 |

与剪枝的关系：剪枝删子树，变量序让好子树先被探。二者叠加才实用。与 DP 的关系：若状态可压缩（如 N 皇后用位掩码状态 DP），DP 优于搜索；变量序是「无法 DP 时」的主武器。与 SAT 求解的关系：DPLL 中的变量序（VSIDS、分支启发式）是 MRV 思想的学习版，冲突多的变量优先，是 CDCL 高效的关键。

## 六、常见误区

1. **以为启发式改变了最坏复杂度**。MRV 只改善实际表现，最坏仍是 $O(b^n)$。面试答「变成多项式」是错的；应说「最坏不变，实际节点数可降数量级」。
2. **MRV 开销大于收益**。若每次 `select_variable` 都重算所有域大小 $O(n \cdot |D|)$，在小问题上比固定顺序还慢。应维护域大小增量更新，或只在中等规模问题上启用。
3. **LCV 用在求全部解**。LCV 服务于「尽快找到第一个解」；求全部解时每个值都要试，LCV 只增加排序开销，应直接按原始顺序或字典序。
4. **只调变量序、不维护候选**。MRV 的前提是域信息准确；若不做前向检验，域大小不反映传播后的实际情况，MRV 可能选错变量。传播与 MRV 是一对。
5. **值序写反**。「最少约束值」是给后续留余地（选约束少的）；写成「最多约束值」会让分支迅速失败，效果相反。同样，求一解时先试 LCV，求反例/证伪时也许先试最可能失败的值，视目标而定。

## 八、面试题

**1. MRV 为何叫「失败优先」（fail-first）？**

参考答案：MRV 选择候选最少的变量，即「最接近失败」的变量。这样要么很快确定赋值，要么很快暴露矛盾并回溯，避免把不协调拖到深层才被发现。失败越早，剪掉的子树越大，搜索越快。相对的 LCV 是「成功优先」（succeed-first）。

**2. 变量排序对回溯最坏复杂度有影响吗？**

参考答案：没有。最坏情况仍是指数级 $O(b^n)$，因为任意序都可能落在最坏实例上。启发式改善的是实际访问节点数与常数，是工程性能问题，不是复杂度类问题。但在平均意义和结构化实例上，差别可达数量级。

**3. MRV 与度启发式如何配合？**

参考答案：MRV 作主排序键（候选数升序），度启发式作次排序键（约束数降序），即 `key = (len(domain), -degree)`。MRV 减少分支因子，度启发式在平局时优先影响大的变量，二者互补。

**4. 什么时候不该用启发式？**

参考答案：问题极小（$n \le 6$ 之类）、变量序开销占比高、或已用强传播/DP 把搜索压到线性时。另外，若需求是「按字典序输出全部解」，任意序会打乱输出顺序，需固定变量序。

## 九、演进与趋势

现代 CSP/SAT 求解器已从手工启发式走向**学习式启发式**。CDCL 中的 VSIDS 依据冲突频率动态调权；SCIP 等分支定界用 ML 预测分支变量（learning to branch）；AlphaCode、神经符号系统用网络引导搜索顺序。随机重启（Luby 序列）、相变现象（phase transition）研究揭示：接近可满足边界的实例最难，启发式与随机化收益最大。

工程侧，OR-Tools 的 CP-SAT 把 SAT 与线性规划、传播、重启、学习结合，在调度排班竞赛中碾压纯回溯。芯片验证、形式化方法用 SMT 求解器处理位向量与数组理论，变量序与理论传播的协同是性能关键。理解 MRV/LCV 这对基础启发式，是读懂这些工业系统的必要起点。

## 十、小结

回溯最坏仍是指数级，但变量序与值序决定实际规模：MRV（失败优先）压低分支因子、度启发式打破平局、LCV（成功优先）提高首次命中率。它们不改变正确性、不改变最坏界，却能把「超时」变成「毫秒」。与候选集维护、前向检验、剪枝叠加后，才是工程可用的约束搜索。记住：启发式是性能杠杆，剪枝与传播才是正确性与规模的根基。
