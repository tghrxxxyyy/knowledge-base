# 归档与流复制基础

> 对应 PostgreSQL 官方文档「Continuous Archiving and Point-in-Time Recovery」与「Streaming Replication」，参考 DDIA 第3章。

## 一、背景与挑战
单机崩溃恢复不够，还需跨节点复制与按时间点恢复（PITR）。日志归档与流复制是这两大能力的基石。

## 二、核心原理
归档（archive）把 WAL/redo 段持续拷贝到外部存储，配合基础备份可做 PITR：恢复到某个时间前。流复制（streaming replication）让从库通过日志流实时追主库，基于日志位点（LSN）保持同步，支持同步/异步模式。

## 三、形式化与数学基础
PITR 恢复需满足：
$$ backup\_start \le target\_time \le last\_archive\_lsn $$
复制延迟：
$$ lag = LSN_{primary} - LSN_{replica} $$
同步复制要求 $LSN_{replica} \ge LSN_{commit}$ 才算提交成功。

## 四、代码实现
```sql
-- PostgreSQL 归档配置
archive_mode = on
archive_command = 'cp %p /archive/%f'
-- 流复制从库 recovery.conf / standby.signal
primary_conninfo = 'host=primary port=5432'
```

## 五、与其他技术对比
MySQL 用 binlog 做复制与增量备份，binlog + 全量备份实现 PITR；其组提交与半同步见 SUBDIR 7。PostgreSQL 物理流复制基于 WAL 段 shipping。

## 六、常见误区
认为有副本就万无一失——异步副本有延迟窗口可能丢最近事务。认为归档可随意删——PITR 窗口依赖最早归档段。

## 七、与开源书/权威来源对应
PostgreSQL 文档「Continuous Archiving」「Streaming Replication」；DDIA 第3章复制章节。

## 八、面试题
问：PITR 需要什么？答：基础备份 + 连续归档日志，恢复到目标 LSN/时间。问：同步 vs 异步复制？答：同步不丢已提交但延迟高，异步反之。

## 九、演进与趋势
日志即服务、跨地域多副本共识（如 Raft/Paxos 之上做复制）成为云数据库标准。

## 十、小结
归档与流复制把单机日志能力延伸到备份与高可用，是生产数据库的必备。
