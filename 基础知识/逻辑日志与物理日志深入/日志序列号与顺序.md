# 日志序列号与顺序

> 对应 Mohan 1992 ARIES 的 LSN 设计与 InnoDB 实现，参考 Silberschatz 第17章。

## 一、背景与挑战
所有日志与页修改必须有一个全局有序的标尺，才能正确重放、避免重复或遗漏。LSN（Log Sequence Number）就是这个标尺。

## 二、核心原理
LSN 单调递增，通常实现为 (文件号, 偏移) 或单一递增整数。每次写日志追加 LSN。页头部记录 `page_lsn` 标识该页最后被哪个 LSN 修改。事务有 `last_lsn` 链表指向其所有日志。检查点记录 `redo_lsn`（最早脏页 LSN）。

## 三、形式化与数学基础
全序关系：
$$ LSN_1 < LSN_2 < \dots < LSN_n $$
恢复时对任意页 $p$：重放条件为 $LSN_{record} > page\_lsn(p)$。事务回滚沿 `last_lsn` 逆序，每条 Undo 产生 CLR（compensation record）带新 LSN 以防止重做时重复撤销。

## 四、代码实现
```sql
-- InnoDB 暴露 LSN 相关状态
SHOW STATUS LIKE 'Innodb_os_log_written';
SHOW ENGINE INNODB STATUS;   -- 含 Log sequence number
```

## 五、与其他技术对比
PostgreSQL 的 LSN 为 8 字节 (time, seg, offset) 格式，用于流复制位点。分布式系统常用混合逻辑时钟（HLC）替代单点 LSN 以支持跨节点顺序。

## 六、常见误区
认为 LSN 是时间戳——它是日志位置而非墙上时间。认为新 LSN 一定对应新事务——同一事务产生多个 LSN。

## 七、与开源书/权威来源对应
Mohan 1992 ARIES 的 LSN 与日志结构；InnoDB「Redo Log」文档；PostgreSQL「Streaming Replication」LSN。

## 八、面试题
问：如何用 LSN 避免重复重放？答：比较记录 LSN 与页 page_lsn，仅应用更新的。问：CLR 作用？答：标记已撤销，防止恢复时重复 Undo。

## 九、演进与趋势
逻辑 LSN（如全局事务序号）在分布式事务与一致性快照中取代物理 LSN。

## 十、小结
LSN 提供日志全序，是重放、回滚、复制位点的统一坐标。
