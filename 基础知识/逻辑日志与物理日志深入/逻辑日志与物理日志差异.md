# 逻辑日志与物理日志差异

> 对应 Mohan 1992 ARIES 的物理/生理日志与 DeCandia 2007 Dynamo、MySQL binlog 逻辑日志对比，参考 Silberschatz 第17章。

## 一、背景与挑战
日志可记录「改了哪个页的哪个字节」（物理/生理）或「执行了哪条 SQL / 哪行前后像」（逻辑）。二者在恢复粒度、复制友好性、存储开销上差异巨大。

## 二、核心原理
物理日志（ARIES 的 physiological logging）记录页号 + 偏移 + 前后像，恢复精准且与高层语义无关，适合单机崩溃恢复。逻辑日志记录操作语义（如 `UPDATE t SET x=1 WHERE id=2`），跨节点复制可读、可过滤、可在不同存储结构上重放，但需保证幂等与确定性。

## 三、形式化与数学基础
物理日志量约：
$$ L_{phys} = \sum changes (page\_id, offset, before, after) $$
逻辑日志量约：
$$ L_{logical} = \sum operations (stmt, old\_row, new\_row) $$
批量更新（如 `UPDATE` 全表）逻辑日志远小于逐行物理日志。

## 四、代码实现
```sql
-- MySQL binlog 逻辑格式
SHOW VARIABLES LIKE 'binlog_format';  -- ROW / STATEMENT / MIXED
-- ROW 格式记录行前后像，STATEMENT 记录 SQL
```

## 五、与其他技术对比
PostgreSQL WAL 主要是物理（含少量逻辑信息），逻辑复制靠单独的逻辑解码输出。MySQL 的 redo 是物理、binlog 是逻辑，二者配合完成崩溃恢复与复制。

## 六、常见误区
认为逻辑日志能替代物理日志做崩溃恢复——逻辑重放依赖表结构且慢，通常仍需物理 redo。认为 ROW 格式日志一定大——相比 STATEMENT 它更安全和确定，常是默认首选。

## 七、与开源书/权威来源对应
Mohan 1992 ARIES（physiological logging）；Silberschatz 17.3；MySQL 官方 binlog 文档。

## 八、面试题
问：物理与逻辑日志各自用途？答：物理用于崩溃恢复精准快速，逻辑用于复制与审计。问：binlog_format=STATEMENT 风险？答：含 `NOW()`/`UUID()` 等非确定函数会导致从库不一致。

## 九、演进与趋势
逻辑解码（logical decoding）、CDC（change data capture）让逻辑日志成为数据管道核心，物理日志向并行恢复演进。

## 十、小结
物理日志保恢复、逻辑日志保复制，现代系统常二者并存各司其职。
