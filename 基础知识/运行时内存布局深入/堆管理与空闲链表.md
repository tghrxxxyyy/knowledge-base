# 堆管理与空闲链表

> 对应 Arpaci-Dusseau《OSTEP》第 16-17 章（malloc）；Silberschatz《Operating System Concepts》。

## 一、背景与挑战
用户态堆需从内核批量要内存（brk/mmap）后自行切分复用，既要快又要低碎片。如何组织空闲块是分配器性能核心。

## 二、核心原理
经典隐式空闲链表：每个块含头部（大小+分配位），通过大小穿越相邻块。分配策略：首次适配（first fit）、最佳适配（best fit）。释放时合并（coalesce）相邻空闲块防外部碎片。边界标记加速合并。

## 三、形式化与数学基础
碎片率：
$$external\ frag = \frac{free\_bytes - max\_contiguous}{total\_heap}$$
合并逻辑：若 $next.block.alloc=0$ 则 $size += next.size$；前块类似，需脚部标记。

## 四、代码实现
```c
// 隐式链表分配（简化）
void* malloc(size_t sz) {
    sz = align(sz + HDR);
    for (b = heap_start; b->size; b = next(b))
        if (!b->alloc && b->size >= sz) {
            split(b, sz); return payload(b);
        }
    return sbrk(sz);  // 向内核要
}
```

## 五、与其他技术对比
显式空闲链表（双向链表）查找快但多空间；分离空闲表（segregated）按大小分桶近似常数时间；tcmalloc 按线程分池减锁。

## 六、常见误区
1. 忘记对齐导致总线错误。
2. 释放后未合并致外部碎片累积。
3. 边界写入覆盖头部破坏整个堆（经典 heap overflow）。

## 七、与开源书/权威来源对应
OSTEP ch16-17 malloc 实现；Silberschatz；remzi-arpacidusse/ostep-code 示例代码。

## 八、面试题
问：first fit 与 best fit？coalesce 为何重要？内部/外部碎片区别？

## 九、演进与趋势
jemalloc/tcmalloc 以线程本地缓存与大小分级支撑高并发；安全分配器加防护头防溢出。

## 十、小结
堆分配器用空闲链表与合并策略在速度与碎片间权衡，是用户态内存基石。
