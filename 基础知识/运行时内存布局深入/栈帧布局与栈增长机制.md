# 栈帧布局与栈增长机制

> 对应 Bryant & O'Hallaron《Computer Systems: A Programmer's Perspective》第 3.7 节过程调用、System V AMD64 ABI 调用约定、Silberschatz《Operating System Concepts》内存管理章，以及 Love《Linux Kernel Development》进程地址空间与栈扩展部分。

## 一、背景与挑战
函数调用需保存返回地址、参数、局部变量与调用者保存的寄存器，并保证返回后精确恢复调用者状态。若无统一约定，就无法跨编译器与动态库协作。栈帧就是这套约定的载体；而「栈按需增长」要解决一个矛盾：启动时无法预知需要多少栈空间，但越界又是安全漏洞。

## 二、核心原理
x86-64 的调用序列（System V AMD64 ABI）：
1. 调用者把前六个整型／指针参数放 `rdi, rsi, rdx, rcx, r8, r9`，前八个浮点参数放 `xmm0`–`xmm7`，超出部分按逆序压栈。
2. `call` 压入返回地址并令 `rsp -= 8`。
3. 被调者 `push rbp` 保存调用者帧指针，`mov rbp, rsp` 建立新帧，`sub rsp, N` 开辟局部空间。
4. 返回时恢复 `rsp` 并 `ret` 弹出返回地址。

帧内从高地址到低地址依次是：参数溢出区、返回地址、保存的 `rbp`、局部变量与临时数组。`rsp` 向下生长，`rbp` 在帧内保持稳定，便于调试器回溯。

栈的增长机制（Linux）：
- 栈顶附近留有一个未映射的**保护页**。
- 访问栈顶以下地址触发缺页异常，内核检查该地址是否落在可向下扩展的栈区间内、且与 `rsp` 距离合理。
- 合理则把栈的 VMA 向下扩展并建立映射；距离过大则判定为栈溢出并发送 SIGSEGV。
- 因此栈增长是**由缺页异常驱动的按需扩展**，而非显式的系统调用。
- 内核还会校验访问地址与 `rsp` 的邻近性，以抵御「跳过大段地址触碰栈」的栈钳制类攻击。
- 编译器在分配超过一页的局部空间时会插入**栈探测**循环，逐页触碰，确保每页都触发缺页并被正确记账。

## 三、形式化与数学基础
帧内偏移约定：

$$a_i = [rbp + 16 + 8i]\ \text{（溢出参数）},\qquad l_j = [rbp - 8 - 8j]\ \text{（局部变量）}$$

栈指针演化与不越界约束：

$$rsp_{after} = rsp_{before} - \mathrm{framesize} \ge \mathrm{stack\_limit}$$

其中 $\mathrm{stack\_limit} = stack\_top - RLIMIT\_STACK$。违反即栈溢出。ABI 还要求 `call` 执行前满足 16 字节对齐：

$$rsp \bmod 16 = 0 \quad \text{（call 之前）}$$

于是函数入口处 $rsp \bmod 16 = 8$（返回地址占 8 字节），编译器据此决定是否插入对齐填充。违反该约束会在使用对齐访存指令时崩溃。

递归深度上限：设单帧大小 $F$、栈上限 $L$：

$$d_{max} \approx \left\lfloor \frac{L}{F} \right\rfloor,\qquad \text{overflow} \iff rsp - F < stack\_limit$$

这是「递归改迭代」最直接的量化依据：$F$ 稍大，安全深度就成比例下降。

## 四、代码实现
```asm
# x86-64 典型函数序言与尾声（AT&T 语法）
foo:
    pushq   %rbp              # 保存调用者帧指针
    movq    %rsp, %rbp        # 建立当前帧
    subq    $32, %rsp         # 开辟 32 字节局部空间
    movl    %edi, -4(%rbp)    # 第一个整型参数落到局部槽
    # ... 函数体 ...
    leave                     # 等价于 movq %rbp, %rsp; popq %rbp
    ret
```

```c
#include <stdio.h>

/* 用局部变量地址观察栈向下生长；大帧须逐页触碰以触发缺页记账 */
static void depth(int level) {
    char pad[64];
    pad[0] = (char)level;
    printf("level=%2d frame@%p\n", level, (void *)pad);
    if (level < 4) depth(level + 1);
}

/* 危险示例：返回已销毁帧上的指针 */
static char *bad(void) {
    char local[16] = "hello";
    return local;              /* 悬空指针，未定义行为 */
}

/* 正确做法：让调用者提供缓冲区 */
static void good(char *out, size_t cap) { snprintf(out, cap, "%s", "hello"); }
```

## 五、与其他技术对比

| 维度 | 栈分配（自动变量） | 堆分配（malloc） | 静态/全局区 | 线程栈 |
|---|---|---|---|---|
| 生命周期 | 随函数返回自动回收 | 手动管理 | 进程全程 | 随线程存在 |
| 分配成本 | 近似常数，仅调整 rsp | 需分配器逻辑 | 加载时确定 | 创建线程时确定 |
| 大小上限 | RLIMIT_STACK，默认数 MiB | 受地址空间与物理内存 | 链接期确定 | 创建时指定 |
| 碎片问题 | 无（严格 LIFO） | 外部与内部碎片 | 无 | 无 |
| 增长方式 | 缺页驱动向下扩展 | brk/mmap 扩展 | 不增长 | 创建即固定 |

## 六、常见误区
误区一：返回局部变量的地址。帧销毁后那块内存随时被覆盖，栈保护无法挽救。
误区二：在栈上开巨型数组。默认栈上限通常只有数 MiB，应立即崩溃或触发保护，应改为堆分配。
误区三：忽略 16 字节对齐要求。ABI 强制对齐，编译器依赖它使用对齐指令，不满足会崩溃。
误区四：认为内核会无限制扩展栈。扩展受 `RLIMIT_STACK` 与地址合理性约束，越界即 SIGSEGV。
误区五：以为 `sub rsp, N` 就完成大帧的安全分配。跨多页时必须逐页触碰，否则可能跳过保护页。

## 八、面试题
1. 栈帧包含哪些内容？
   要点：溢出参数、返回地址、保存的 rbp、局部变量与临时空间，以及被调用者保存的寄存器。
2. 栈为什么向下生长？有什么实际影响？
   要点：约定使帧地址随调用递减，便于用固定负偏移寻址；影响保护页位置与栈溢出检测方式。
3. 返回局部变量指针为什么危险？
   要点：帧随函数返回销毁，该内存进入未定义状态，可能被后续调用覆盖。
4. 16 字节栈对齐要求从何而来？
   要点：ABI 规定，配合 SSE/AVX 对齐访存；函数入口因返回地址占 8 字节而呈 8 字节对齐。
5. 大局部数组为什么要逐页触碰？
   要点：跨越保护页的写入可能跳过内核的栈扩展判定，stack probing 保证每页都触发缺页并被记账。

## 九、演进与趋势
影子栈把返回地址复制到受保护的独立区域，返回时比对，直接阻断 ROP 类返回地址劫持，是硬件辅助控制流完整性的核心机制。栈钳制防护要求内核校验缺页地址与 `rsp` 的邻近性，防止用大偏移探测绕过保护页。编译器的栈金丝雀、安全展开与自动栈探测已成为常见默认选项。具体开关与行为以各工具链与内核官方最新文档为准。

## 十、小结
栈帧是调用约定的物理形态：`rsp` 向下生长、`rbp` 稳固帧基、偏移由 ABI 固化。栈增长靠缺页异常驱动，由内核判定地址合理性并扩展 VMA，这也决定了它的边界行为（溢出即 SIGSEGV、大帧需逐页触碰、需要栈钳制防护）。工程上牢记三条约束：不返回局部指针、不放大数组、不破坏 16 字节对齐。
