# 缓存一致性与伪共享问题

> 对应 Tanenbaum《Modern Operating Systems》第 8 章（多处理与缓存）；Silberschatz《Operating System Concepts》。

## 一、背景与挑战
多核各自缓存同一内存，需协议保证看到一致值。当两核频繁写同一缓存行不同字段，缓存行在核间反复无效，性能骤降，即伪共享。

## 二、核心原理
MESI 协议维护缓存行状态（Modified/Exclusive/Shared/Invalid）。写共享行需获取独占并广播无效。伪共享：两变量同缓存行（通常 64 字节），各自线程写导致整行来回迁移，吞吐断崖。

## 三、形式化与数学基础
设缓存行大小 $L=64B$，变量 $a,b$ 同处一行。两核各写：
$$bandwidth \propto \frac{1}{2 \times t_{invalidate}}$$
填充至不同行后 $t_{invalidate}\to 0$，吞吐恢复。所需填充：
$$pad \ge L - (addr(b)\ \%\ L) + (L - addr(a)\ \%\ L)$$

## 四、代码实现
```c
struct alignas(64) Counter {  // 每核独占一行
    uint64_t val;
};
Counter per_core[NUM_CPUS];   // 无伪共享
```

## 五、与其他技术对比
伪共享靠布局（对齐/填充）消除；真共享需锁或原子；缓存行隔离增加内存占用，是空间换时间。

## 六、常见误区
1. 以为不同变量无关——同缓存行仍相互无效。
2. 只在单核测试发现不了伪共享。
3. 过度填充浪费缓存容量。

## 七、与开源书/权威来源对应

## 八、面试题
问：伪共享是什么？MESI 如何工作？如何消除伪共享？

## 九、演进与趋势
硬件提示（NT store）、编译器 __attribute__((aligned)) 与 perf c2c 工具定位伪共享。

## 十、小结
伪共享是缓存一致性协议的隐性代价，靠缓存行对齐把无关写隔离即可消除。
