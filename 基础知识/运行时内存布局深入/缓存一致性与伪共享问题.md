# 缓存一致性与伪共享问题

> 对应 Tanenbaum《Modern Operating Systems》多处理器与缓存一致性章、Hennessy & Patterson《Computer Architecture》缓存与存储层次章、Drepper《What Every Programmer Should Know About Memory》，以及 Herlihy & Shavit《The Art of Multiprocessor Programming》共享内存模型部分。

## 一、背景与挑战
多核各自持有私有缓存以减少访存延迟，于是同一内存地址的多个副本需要协议维持一致。协议本身是对的，但代价在于：当两个核频繁写**同一缓存行中的不同字段**时，硬件会把整行在核间反复迁移与失效，尽管逻辑上两个变量毫不相关。这就是伪共享（false sharing）——一个由布局而非算法引起的性能问题，单核测试完全无法发现。

## 二、核心原理
缓存行：现代处理器以缓存行为单位搬运数据，常见行大小 64 字节。行是**一致性的粒度**，也是伪共享的根源。

MESI 协议用四态描述每行的状态：Modified（本核独占且已修改，需负责回写）、Exclusive（本核独占且与内存一致）、Shared（多核共享且都与内存一致）、Invalid（本行无效）。状态转换要点：读取未命中且其他核无副本则加载为 E，其他核有 S 副本则加载为 S；写入必须在 M 或 E 状态下进行，若为 S 须先广播失效并取得所有权（RFO），把其他核降为 I；独占脏行被其他核读取时须先回写或直接转发。

伪共享的发生：变量 $a$ 与 $b$ 同行，核 1 只写 $a$、核 2 只写 $b$，每次写都让对方副本失效，对方下次访问需重新取行并再失效回来，行在核间「乒乓」，有效带宽塌陷。注意这与「真共享」不同：真共享是同一变量被多核访问，需要锁或原子操作保证正确性；伪共享是不同变量被访问，正确性无问题但性能受损。

消除手段：填充／对齐使每个被独立写的变量独占一行；每核持有本地副本并在最后统一规约；把同核访问的字段放一起、不同核写的字段分开放；用性能分析工具定位跨核缓存行竞争。

## 三、形式化与数学基础
设行大小 $L = 64$ B，两核以频率 $f$ 交替写同行变量，则无效化次数约为

$$N_{inv} \approx 2 f \Delta t$$

有伪共享时的可用吞吐与所有权转移延迟成反比，消除后不再有跨核失效：

$$\mathrm{BW}_{false} \propto \frac{1}{t_{inv}},\qquad t_{inv} \to 0 \Rightarrow \mathrm{BW} \to \mathrm{BW}_{ideal}$$

所需填充量估计：若两变量紧邻，至少需让后者的起始落到下一行：

$$pad \ge L - (addr(a) \bmod L)$$

空间代价用放大因子衡量，其中 $s$ 为实际数据字节数，$s$ 越小放大越严重：

$$\mathrm{Amplification} = \frac{L}{s}$$

$s = 8$ 字节计数器时放大 8 倍，这是典型的空间换时间取舍，需用性能收益验证。更精细的判据考虑只读字段——只读副本可同时处于 S 状态，不产生无效化，因此

$$\text{false sharing} \iff \text{同行} \wedge \text{至少一核写} \wedge \text{多核持有副本}$$

结论：真正需要分离的是**被不同核写的**字段；把只读配置与可写计数放一起通常无害。

## 四、代码实现
```c
#include <stdint.h>

#define CACHE_LINE 64
#define NCPU 4

/* 反例：两个计数器同行，多线程写会互相无效化 */
struct bad_counters { volatile long a; volatile long b; };

/* 正例：每个槽位独占一行，写操作不再产生跨核失效 */
struct align_slot {
    _Alignas(CACHE_LINE) volatile long v;
    char pad[CACHE_LINE - sizeof(long)];
};
struct good_counters { struct align_slot slots[NCPU]; };

/* 三种等价的对齐写法 */
struct explicit_pad { long v; char pad[56]; };              /* 手动填充 */
struct attr_aligned { long v; } __attribute__((aligned(64)));
struct c11_aligned  { _Alignas(64) long v; };

/* 替代思路：每核本地累加，避免任何跨核写 */
static long local_sums[NCPU];
static void reduce(long *out) {
    long total = 0;
    for (int i = 0; i < NCPU; i++) total += local_sums[i];
    *out = total;                   /* 只在结束时读取一次 */
}
```

## 五、与其他技术对比

| 维度 | 伪共享 | 真共享（竞争同一变量） | 缓存行填充 | 无共享（本地副本） |
|---|---|---|---|---|
| 根因 | 不同变量同处一行 | 同一变量被多核访问 | 布局人为隔离 | 数据被复制 |
| 正确性影响 | 无，仅性能 | 需同步原语保证正确 | 无 | 需最后规约 |
| 典型症状 | 随核数增加而吞吐下降 | 锁争用、原子操作热点 | 内存占用上升 | 规约阶段有开销 |
| 解决手段 | 对齐与填充 | 锁、原子、分片 | 即解决手段本身 | 规约合并 |
| 空间代价 | 无 | 无 | 放大因子 $L/s$ | 核数倍副本 |
| 检测方式 | 跨核缓存行缺失计数 | 锁竞争剖析 | 不适用 | 不适用 |

## 六、常见误区
误区一：以为「不同变量互不影响」。硬件按行管理一致性，同行的不同变量仍相互无效化。
误区二：只在单核上测试。单核下没有跨核无效化，伪共享完全不显现。
误区三：认为填充越多越好。过度填充会降低缓存有效容量、增加内存占用与预取压力。
误区四：把所有字段都拉到独占行。同核访问的字段挤在一行反而更好，只需分离被不同核写的字段。

## 八、面试题
1. 什么是伪共享，与真共享有何区别？
   要点：伪共享是不同变量处于同一缓存行导致的无效化风暴，仅性能受损；真共享是同一变量被多核访问，需同步保证正确性。
2. MESI 协议如何工作？
   要点：行有 M/E/S/I 四态，写需独占并向其他核广播失效，独占脏行被读时需先回写或转发。
3. 如何消除伪共享？
   要点：对齐填充使被独立写的变量独占行、每核本地副本加最终规约、调整布局分离写热点。
4. 为什么单核测试发现不了伪共享？
   要点：没有跨核缓存行迁移与失效，同一核写不会产生所有权转移开销。

## 九、演进与趋势
缓存行大小在多个架构上长期稳定，部分处理器提供便于隔离的填充指令与非临时存储，以减少写分配与缓存污染。性能分析工具链已能定位跨核缓存行竞争（如按缓存行聚合的采样），使伪共享从「靠猜」变成「可测量」。语言与运行时层面，对齐属性与专门的填充类型让消除伪共享变得可移植。具体常数与语义以各标准与实现官方最新文档为准。

## 十、小结
伪共享是一致性协议在设计上的隐性代价：一致性粒度是缓存行，而程序关注的是变量，两者的错配导致无关写互相无效化。判据可归纳为「同一行 + 至少一核写 + 多核持有副本」；解法可归纳为「把被不同核写的字段分到不同行，把同核访问的字段放在一起」。它不是正确性问题，因此不会报错，只会在多核上悄悄吃掉吞吐——这正是它需要被主动测量与预防的原因。
