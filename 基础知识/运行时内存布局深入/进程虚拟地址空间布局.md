# 进程虚拟地址空间布局

> 对应 Silberschatz《Operating System Concepts》第 8 章；Arpaci-Dusseau《Operating Systems: Three Easy Pieces》（OSTEP）。

## 一、背景与挑战
每个进程拥有独立虚拟地址空间，内核须把代码、数据、堆、栈、共享库、内核区合理排布，既要隔离又要高效映射物理内存。

## 二、核心原理
典型 Linux 布局（低到高）：程序代码、只读数据、已初始化数据、BSS、堆（向上增长）、内存映射区、栈（向下增长）、内核空间（高地址）。ASLR 随机化栈/堆/库基址以抗攻击。

## 三、形式化与数学基础
地址空间为函数 $M: VA \to PA \cup \{\bot\}$，页对齐：
$$VA = VPN \times P + offset,\quad VPN = \lfloor VA / P \rfloor$$
有效空间 $[0, 2^{bits}-1]$，高 $K$ 位保留给内核（如 48 位地址高 16 位符号扩展）。

## 四、代码实现
```c
// 探查布局
printf("code %p\n", (void*)main);
printf("heap %p\n", malloc(1));
int x; printf("stack %p\n", (void*)&x);
// /proc/self/maps 列出所有映射
```

## 五、与其他技术对比
固定布局易受猜测攻击；ASLR 打乱基址增加利用难度但需 PIE 配合；32 位地址空间紧张，64 位缓解碎片。

## 六、常见误区
1. 以为栈在低地址——Linux 栈在高地址向下生长。
2. 混淆虚拟与物理地址，二者经页表映射。
3. 忽略内核占用高地址，用户态不可用。

## 七、与开源书/权威来源对应
OSTEP 地址空间章；Silberschatz ch8；CSAPP 7.9/9 章。

## 八、面试题
问：栈向哪生长？堆呢？ASLR 作用？内核区在哪？

## 九、演进与趋势
5 级页表支持更大地址；大页（2MiB/1GiB）减少 TLB 压力；mremap 动态调堆映射。

## 十、小结
虚拟地址空间把各内存区域规整排布，页表与 ASLR 共同保障隔离与安全。
