# 进程虚拟地址空间布局

> 对应 Silberschatz《Operating System Concepts》第 8 章内存管理、Arpaci-Dusseau《OSTEP》地址空间与内存 API 章节、Bryant & O'Hallaron《Computer Systems: A Programmer's Perspective》第 9 章虚拟内存，以及 Love《Linux Kernel Development》进程地址空间部分。

## 一、背景与挑战
每个进程都以为自己独占整个地址空间：代码在低地址、栈在高地址、堆在中间。这层「幻觉」靠页表与内核的地址空间描述结构维持。理解布局要回答三个问题：各区域为何放在这个位置（历史与效率约束）、区域边界如何动态变化（堆向上、栈向下、映射区填充）、内核如何在不破坏兼容性的前提下提供隔离与随机化。

## 二、核心原理
64 位 Linux 用户进程的典型布局（低地址到高地址）：
1. 代码段（text）：可执行指令，通常只读可执行。
2. 只读数据段（rodata）：常量与字符串字面量。
3. 已初始化数据段（data）：有初值的全局与静态变量。
4. 未初始化数据段（bss）：零初始化变量，不占可执行文件空间，加载时映射为零页并按需分配。
5. 堆（heap）：`brk`/`sbrk` 从低位向上扩展；`malloc` 的较大请求走 `mmap` 落到映射区。
6. 内存映射区：共享库、文件映射、匿名映射，随时间向低地址「生长」。
7. 栈（stack）：从高地址向下生长，内核以缺页异常驱动按需扩展。
8. 内核空间：高地址保留，用户态不可访问；划分依平台与地址位宽而定。

内核描述结构：每个进程有一组 VMA（虚拟内存区域），记录起始、结束、权限与后端对象。`/proc/<pid>/maps` 与 `smaps` 就是这些 VMA 的文本视图，是排障的第一手资料。

地址随机化（ASLR）：栈、堆、映射区基址在进程启动时随机偏移，使攻击者无法依赖固定地址。ASLR 需要可执行文件编译为位置无关（PIE）才能随机化代码段；共享库天然位置无关，随机化收益明显。

区域边界的三个关键性质：
- 堆与映射区相向生长，中间空隙是二者共享的剩余空间；二者相遇则分配失败。
- 栈顶有保护页，越界访问会先命中它并触发 SIGSEGV。
- 映射区的 VMA 数量有上限（`vm.max_map_count`），大量小映射（线程栈、JIT 代码页）容易触顶。

## 三、形式化与数学基础
地址空间建模为部分函数，把虚拟地址映射到物理地址或「不存在」：

$$M: VA \to PA \cup \{\bot\}$$

页对齐关系（页大小 $P = 2^p$）：

$$VA = VPN \times P + offset,\quad VPN = \lfloor VA/P \rfloor,\quad offset = VA \bmod P$$

堆与映射区不许相遇的约束：

$$heap\_brk < mmap\_base - \varepsilon$$

不等式被打破时 `brk` 或 `mmap` 失败（典型 ENOMEM）。这解释了 32 位空间里「大堆 + 大量共享库」组合为何容易失败。

ASLR 强度用熵刻画。设随机化范围 $R$ 字节，则可能位置数与攻击者尝试 $k$ 次至少命中一次的概率为：

$$N_{pos} = \frac{R}{P},\qquad P_{hit}(k) = 1 - \left(1 - \frac{1}{N_{pos}}\right)^{k} \approx \frac{k}{N_{pos}}$$

$N_{pos}$ 很大时单点猜测几乎不可能，但一旦存在信息泄露（打印指针、越界读），熵即被大幅削弱——这正是 ASLR 必须与避免信息泄露配合的原因。两条容量约束：VMA 数量与新映射失败的判据，以及栈可用空间：

$$n \ge N_{max} \Rightarrow \text{ENOMEM},\qquad S_{avail} = stack\_top - L_s - rsp$$

## 四、代码实现
```c
#include <stdio.h>
#include <stdlib.h>

int g_init = 42;               /* data 段 */
int g_zero;                    /* bss 段 */
static const char *msg = "ro"; /* 只读数据 */

int main(void) {
    int local = 1;                     /* 栈 */
    int *heap = malloc(1024 * 1024);   /* 大块通常走 mmap */

    printf("text   main   = %p\n", (void *)main);
    printf("rodata msg    = %p\n", (void *)msg);
    printf("data   g_init = %p\n", (void *)&g_init);
    printf("bss    g_zero = %p\n", (void *)&g_zero);
    printf("heap   heap   = %p\n", (void *)heap);
    printf("stack  local  = %p\n", (void *)&local);

    /* 真实布局以 /proc/self/maps 为准，排障时优先看它 */
    free(heap);
    return 0;
}
```

## 五、与其他技术对比

| 维度 | 单一连续地址空间 | 分页式虚拟地址空间 | 分段式 | 段页式 |
|---|---|---|---|---|
| 隔离粒度 | 无隔离 | 页级，细 | 段级，粗 | 段 + 页 |
| 外部碎片 | 严重 | 无 | 严重 | 无 |
| 稀疏支持 | 差 | 好（按需建页表） | 一般 | 好 |
| 共享能力 | 无 | 页级共享 | 段级共享 | 灵活 |
| 保护检查点 | 无 | 每次访问（页表项权限） | 每次访问（段限长） | 两者兼有 |
| 现代地位 | 否 | 主流（x86-64 主要靠分页） | 历史形态 | 有兼容性残留 |

## 六、常见误区
误区一：以为栈在低地址。Linux 上栈位于用户空间高地址并向下生长，堆在低地址向上生长。
误区二：混淆虚拟地址与物理地址。打印出的指针都是虚拟地址，需经页表映射才对应物理帧。
误区三：忽略内核占用高地址空间。用户态不能访问那段地址，且用户地址位宽小于指针类型宽度。
误区四：认为打开 ASLR 就绝对安全。ASLR 提供概率性防护，一旦有信息泄露，熵被显著削弱。
误区五：忽视 VMA 数量上限。线程栈、JIT 代码页与大量小映射会耗尽 `vm.max_map_count`，表现为看似有内存却映射失败。

## 八、面试题
1. 栈向哪个方向生长，堆呢？
   要点：栈从高地址向下，堆从低地址向上；二者相向生长且不能相遇。
2. ASLR 的作用与局限？
   要点：随机化栈、堆、映射区基址提高利用门槛；局限是熵有限，信息泄露会让防护失效。
3. 内核空间在地址空间的什么位置？
   要点：用户空间高地址一侧保留，用户态不可访问；划分依平台与地址位宽而定。
4. 为什么需要 PIE 才能让 ASLR 随机化代码段？
   要点：非位置无关的可执行文件含绝对地址，无法整体搬移到随机基址。

## 九、演进与趋势
地址位宽扩展带来更深的多级页表与更大的用户可用空间，同时要求应用正确处理「指针高位为规范形式」的约束。大页通过提高 TLB 覆盖率改善大内存负载性能，但也带来内存碎片与分配失败率问题。容器与沙箱让每个进程的地址空间叠加更多映射层（命名空间、加载器、JIT），VMA 管理与随机化的组合变得更复杂。具体参数与默认值以目标平台官方最新文档为准。

## 十、小结
进程虚拟地址空间是一张「有序排布 + 动态生长 + 随机化」的地图：低地址放代码与数据，堆向上、栈向下、映射区填充中间并向下扩展，高地址留给内核。这套布局由 VMA 描述，由页表实现隔离与保护，由 ASLR 与保护页提供安全边界。工程上三条实用线索是：用 `/proc/self/maps` 观察真实布局、警惕堆与映射区相遇及 VMA 触顶这两类失败、并理解 ASLR 是概率防护而非绝对屏障。
