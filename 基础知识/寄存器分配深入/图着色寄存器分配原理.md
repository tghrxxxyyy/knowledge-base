# 图着色寄存器分配原理

> 对应 Chaitin et al. 1982（Register Allocation via Graph Coloring, PLDI）与 Appel 1989（Graph-Coloring Register Allocation, PLDI）。

## 一、背景与挑战

程序中的虚拟寄存器数往往远超物理寄存器数 $K$（典型 $K=16$ 或 $32$）。当两个变量在某一时刻同时活跃（live），它们不能映射到同一物理寄存器，否则值会互相覆盖。寄存器分配的核心问题即：把无限虚拟寄存器映射到有限物理寄存器，使冲突变量异色，并最小化 spill。图着色把该问题建模为经典的图 $K$-着色，是工业级编译器的主流框架。其难点在于：图着色是 NP 完全问题，且 spill 决策与着色顺序相互纠缠，需要启发式逼近最优。

## 二、核心原理

构建干涉图（interference graph）：节点为变量，边连接「任意程序点同时活跃」的变量对。寄存器分配等价于用 $K$ 种颜色（物理寄存器）给节点上色，使相邻节点异色。Chaitin 的迭代算法分两步：(1) 简化（simplify）——反复移走度数 $<K$ 的节点压栈，因为「一个度数低于 $K$ 的节点总能等邻居上色后再选一个未用色」；(2) 回涂（select）——逆序弹出节点，从其邻居已用色集之外选一个颜色。若简化阶段出现所有节点度数 $\ge K$（无可简化节点），则选一个 spill 代价最小的节点「潜在溢出」（potential spill）并暂时移走，继续简化；回涂后再处理真正需要 spill 的节点。预着色节点（ABI 固定寄存器）作为已有颜色约束必须保留，并参与度数计算（它们相当于不可移动的已染色节点）。

## 三、形式化与数学基础

干涉图 $G=(V,E)$，着色函数 $c:V\to\{1..K\}$ 满足：

$$ \forall\,(u,v)\in E:\ c(u)\neq c(v) $$

图可 $K$-着色当且仅当色数 $\chi(G)\le K$。简化可行性依据：若 $degree(v)<K$，则移除 $v$ 后其子图若可着色，$v$ 必可着色（邻居至多 $K-1$ 色，留至少一色可用）。Chaitin 的 spill 启发式选低成本节点：

$$ spill\ \arg\min_v \frac{uses(v)+defs(v)}{degree(v)+1} $$

即「使用少、冲突多」的变量优先 spill（但需结合 spill 代价模型修正，见溢出调度篇）。回涂时的可用色集为邻居已用色的补集：

$$ c(v)\in \{1..K\}\setminus \{c(u)\mid u\in adj(v)\} $$

只要补集非空即可着色，否则该节点需 spill。

## 四、代码实现

```c
// Chaitin 迭代着色（简化 -> 回涂）
void color(graph *G, int K) {
    stack stk;
    while (!G->nodes.empty()) {
        node *v = pick_degree_lt_K(G, K);     // 可简化节点
        if (v) { stk.push(v); G->remove(v); continue; }
        // 无可简化：选 spill 代价最小者暂移
        node *s = pick_spill(G);
        G->remove(s); stk.push(s);            // 标记为 potential spill
    }
    while (!stk.empty()) {
        node *v = stk.pop();
        int used = neighbor_colors(G, v);     // 邻居已用色集合
        if (v->potential_spill && all_colors_used(used))
            insert_spill_code(v);             // 真正 spill，插 load/store
        else
            v->color = pick_free_color(used, K);
    }
}
```

## 五、与其他技术对比

| 方案 | 质量 | 复杂度 | 适合 |
| --- | --- | --- | --- |
| 图着色（Chaitin） | 最优近似 | 高（含 spill 迭代） | 静态编译 |
| 线性扫描 | 略低 | 近线性 | JIT |
| 优先级着色（SSA） | 高 | 中高 | 现代编译器 |
| 贪心（本地） | 低 | 低 | 快速/受限 |

图着色质量最高但 NP 难，靠启发式与 spill 迭代逼近；常与线性扫描组合（热路径着色、冷路径扫描）。优先级着色在简化前按 spill 代价排序，避免把高代价变量过早移走，质量优于朴素 Chaitin。

## 六、常见误区

1. 以为 $K$-着色总有解——变量冲突过密必 spill，需 potential spill 机制。
2. 溢出选「高代价」节点，导致大量 load/store 拖累性能；应按代价模型选最小增量。
3. 忽略预着色（ABI 固定寄存器）作为已染色约束——与其冲突的变量不能同色。
4. 认为简化顺序无关——简化/回涂顺序直接决定最终着色质量与 spill 数。
5. 以为图着色产出全局最优——它是 NP 难的近似，启发式可能非最优。
6. 忽略 coalescing 与着色的耦合——先合并后着色，合并影响图结构与度数。

## 七、与开源书·权威来源对应

- Chaitin et al. 1982（PLDI）：图着色分配奠基，提出干涉图、简化/回涂与 spill 启发式。
- Appel 1989（PLDI）：完善优先级着色与 SSA 结合，提升并行性与质量。
- Appel《Modern Compiler Implementation》ch11：教科书级完整实现。
- Aho《Compilers》（龙书）ch8：把活跃分析与冲突图构建纳入编译原理主线。
- Muchnick《Advanced Compiler Design》：从高级优化角度讨论着色与 spill。
- Briggs 1992：改进溢出模型（频率感知），与着色迭代衔接。

## 八、面试题

1. 干涉图如何构建？
   要点：反向数据流算每个程序点的 live 集，任意点同时活跃的两变量连边。
2. 为什么图着色是 NP 难？spill 选谁？
   要点：$K$-着色判定为 NP 完全；按 spill 代价（频次加权）选最小增量节点。
3. simplify 为何只移走度数 $<K$ 的节点？
   要点：这类节点总能等邻居上色后选到空闲色，保证回涂可解。
4. 预着色节点如何参与着色？
   要点：作为已染色约束，计入邻居度数，相关变量须避开其颜色。
5. 优先级着色相比朴素 Chaitin 好在哪？
   要点：简化前按 spill 代价排序，避免高代价变量过早被移走导致多余 spill。

## 九、演进与趋势

Briggs 1992 改进溢出模型（频率感知）；现代分配器普遍基于 SSA 构建更稀疏冲突图、结合优先级着色与合并（coalescing），质量逼近最优且更快。过程间/跨函数着色把范围从单函数扩展到调用图。寄存器分配与指令调度协同（unified allocation+scheduling）是前沿方向，进一步压低 spill 与停顿。

## 十、小结

图着色把寄存器分配化为图论着色：干涉边刻画冲突、spill 代价指导溢出、预着色约束守住 ABI。理解简化/回涂与 spill 迭代，就掌握了工业级寄存器分配器的理论内核——它是「冲突即异色、溢出即权衡」这一思想最优雅的工程表达。
