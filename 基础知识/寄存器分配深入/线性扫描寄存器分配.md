# 线性扫描寄存器分配

> 对应 Poletto & Sarkar 1999（Linear Scan Register Allocation, TOPLAS）与 Appel《Modern Compiler Implementation》第 11 章。

## 一、背景与挑战

图着色分配质量高，但简化/回涂的复杂度与全局干涉图规模随函数变大而显著上升，对 JIT、即时编译、运行时代码生成不友好——这些场景要求毫秒乃至亚毫秒级的分配。线性扫描（linear scan）以接近线性的时间给出「接近图着色质量」的分配：它放弃全局着色，改在存活区间（live interval）上做区间调度贪心，是运行时编译的事实标准策略。当函数巨大或编译预算极低时，图着色的高成本不可接受，线性扫描的性价比优势凸显。

## 二、核心原理

把每个虚拟寄存器的存活区间 $I_v=[start(v), end(v)]$ 按起始点排序，沿「程序计数器时间轴」扫描。维护一个「当前活跃区间」集合。每当遇到某区间起点，先释放所有已经结束（$end\le$ 当前点）的区间所占的寄存器；若仍有空闲寄存器则分配给新区间，否则 spill 当前活跃区间中「最晚结束」者（因为它占用时间最长、spill 它影响最小）。本质是区间调度贪心——优先让短区间复用寄存器，长区间让位。实践中还引入优先级（热区间优先）、区间合并（相邻同变量区间合并为一个）以弥补质量。对 SSA 形式的 IR，φ 节点的区间合并进一步减少碎片。线性扫描不保证全局最优，但实践中与图着色质量差距很小。

## 三、形式化与数学基础

区间 $I_v=[start(v),end(v)]$。扫描点 $t$ 时同时活跃的区间数：

$$ A(t)=\bigl|\{\,I\mid start(I)\le t < end(I)\,\}\bigr| $$

若 $A(t)\le K$（物理寄存器数）则不 spill；否则需在活跃集中选一个 spill。最优贪心选择使后续冲突最小者，即结束最晚者：

$$ spill\ \arg\max_{I\in active} end(I) $$

目标是在不超出 $K$ 个寄存器的前提下最小化 spill 总代价。带优先级时，先按权重降序处理热区间，冷区间后填、易 spill。复杂度主要来自排序：

$$ T_{alloc}=O(n\log n)\ (\text{排序})\ +\ O(n\log K)\ (\text{堆维护活跃集}) $$

远快于图着色的多次简化/回涂迭代。

## 四、代码实现

```python
def linear_scan(intervals, K):
    intervals.sort(key=lambda i: i.start)     # 按起始点排序
    active, free = [], list(range(K))         # 空闲寄存器栈
    for iv in intervals:
        # 释放已结束的区间，回收其寄存器
        still = []
        for a in active:
            if a.end <= iv.start:
                free.append(a.reg)
            else:
                still.append(a)
        active = still
        if free:
            iv.reg = free.pop()                # 有空闲则分配
            active.append(iv)
        else:
            victim = max(active, key=lambda a: a.end)  # 最晚结束者 spill
            spill(victim)
            active.remove(victim)
            iv.reg = victim.reg
            free.append(iv.reg)
            active.append(iv)
    return active
```

## 五、与其他技术对比

| 方案 | 时间复杂度 | 质量 | 适合 |
| --- | --- | --- | --- |
| 图着色 | 高（含 spill 迭代） | 最优近似 | 静态编译 |
| 线性扫描 | 近线性 $O(n\log n)$ | 略低 | JIT/运行时 |
| 优先线性扫描 | 近线性 | 接近 | 带 profile |
| 混合（热着色/冷扫描） | 中 | 高 | 生产 JIT |

线性扫描快但可能错过全局最优；用「热区间优先 + 区间合并」弥补质量差距。混合策略对热路径图着色、冷路径线性扫描，兼顾速度与质量。

## 六、常见误区

1. 以为线性扫描永远比图着色差——对大函数、热路径差距很小，却快一个数量级。
2. 不按执行频次排序（spill 冷区间优先），导致热区间被 spill、冷区间占着寄存器。
3. 忽略区间合并（相邻同变量区间应并为一个整体），造成无谓的碎片与边界 spill。
4. 把「区间」误当作「基本块」——区间跨越整个存活期，含控制流汇合。
5. 以为扫描一遍即可——优先级/合并需预处理，spill 后可能需二次扫描。
6. 忽略调用边杀掉 caller-saved——跨调用活跃变量须用 callee-saved 或 spill。

## 八、面试题

1. 线性扫描与图着色的核心区别与取舍？
   要点：前者区间贪心近线性时间、质量略低；后者全局着色质量高、慢。JIT 优先选线性扫描。
2. 为什么选「最晚结束」的区间 spill？
   要点：它占用时间最长，spill 它对后续区间冲突影响最小。
3. 热区间优先如何提升质量？
   要点：先分配高频路径，冷区间后填且易 spill，把有限寄存器留给热点。
4. 线性扫描的复杂度为何近线性？
   要点：排序 $O(n\log n)$ + 堆维护活跃集，无图着色的多次迭代简化。
5. 何时混合策略优于纯线性扫描？
   要点：热路径对质量敏感时，热着色/冷扫描兼顾速度与峰值性能。

## 九、演进与趋势

优先线性扫描（按 profile 权重）成为主流 JIT 标配；「热路径图着色 + 冷路径线性扫描」的混合策略兼顾质量与速度；SSA 上的线性扫描进一步利用 φ 节点减少拆分。硬件加速（寄存器分配专用电路）也在研究之中。带修正的线性扫描（linear scan with buddy）把溢出区间与其伙伴配对，降低 spill 抖动。

## 十、小结

线性扫描用「存活区间贪心调度」把分配降到近线性时间，是运行时编译的实用之选。理解其「释放—分配—spill 最晚结束者」的循环与优先级补偿，就能在速度与质量间取得工程平衡——对 JIT 与即时编译，它是质量与延迟之间的最优折中。
