# 线性扫描寄存器分配

> 对应 Appel《Modern Compiler Implementation》第 11 章；Briggs 等线性扫描实践。

## 一、背景与挑战
图着色质量高但慢，JIT 编译要求秒级乃至毫秒级分配。线性扫描以线性时间给出接近质量的分配，适合运行时编译。

## 二、核心原理
把每个虚拟寄存器的存活区间（live interval）按起始点排序，沿时间轴扫描。维护活跃区间集合，区间结束释放寄存器；新区间若无空闲寄存器则 spill 最晚结束者。本质是区间调度贪心。

## 三、形式化与数学基础
区间 $I_v = [start(v), end(v)]$。扫描点 $t$ 时占用寄存器数：
$$| \{ I \mid start(I) \le t < end(I) \} | \le k$$
溢出策略选择使 $\max end(I)$ 最大的活跃区间，最小化后续冲突。

## 四、代码实现
```python
intervals.sort(key=lambda i: i.start)
active = []
for iv in intervals:
    expire(iv.end)            # 释放结束的
    if len(active) < K:
        assign(iv, free_reg())
    else:
        spill(max(active, key=end))  # 最晚结束
    active.append(iv)
```

## 五、与其他技术对比
线性扫描 O(n log n) 远快于图着色，但可能错过全局最优；常用优先级（热区间优先）弥补质量。

## 六、常见误区
1. 以为线性扫描永远更差——对大函数差距很小。
2. 不按频次排序导致冷区间抢热寄存器。
3. 忽略区间合并（相邻区间同变量）致碎片。

## 七、与开源书/权威来源对应
Appel ch11 线性扫描；Briggs 等 JIT 实践；LLVM 曾用线性扫描变体。

## 八、面试题
问：线性扫描 vs 图着色？为何适合 JIT？spill 谁？

## 九、演进与趋势
基于存活区间的优先线性扫描、与图着色混合（热路径着色、冷路径线性）成主流。

## 十、小结
线性扫描用区间贪心把分配降到近线性时间，是运行时编译的实用之选。
