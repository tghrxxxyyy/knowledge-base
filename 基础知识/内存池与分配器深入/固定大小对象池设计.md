# 固定大小对象池设计

> 对应 Hennessy & Patterson《Computer Architecture》与 Silberschatz《Operating System Concepts》。

## 一、背景与挑战
频繁分配释放大量同尺寸对象会带来碎片化与外部碎片，且通用分配器开销大。固定大小对象池以「批量预分配 + 自由链表」消除碎片并提速。

## 二、核心原理
对象池预先向底层申请一大块内存，切成等尺寸槽位，用自由链表串起空闲槽。分配即从表头取一个，释放即归还到表头。因尺寸固定，无外部碎片，分配为常数时间。

## 三、形式化与数学基础
设块含 $N$ 个槽，槽尺寸 $s$，自由链表长度 $F$。分配：

$$ \text{alloc}: F>0 \implies \text{pop head},\ F \gets F-1 $$

释放：

$$ \text{free}: \text{push head},\ F \gets F+1 $$

内存利用率：

$$ U = \frac{\text{已用槽}}{N} $$

无外部碎片，仅可能有内部碎片（对象小于 $s$）。

## 四、代码实现
自由链表对象池：

```c
typedef struct node { struct node *next; } node_t;
node_t *free_list;

void *pool_alloc(void) {
    node_t *n = free_list;
    if (!n) return NULL;          // 池空
    free_list = n->next;
    return n;
}
void pool_free(void *p) {
    node_t *n = p;
    n->next = free_list;
    free_list = n;
}
```

## 五、与其他技术对比
通用 malloc 需查找合适块、易碎片；对象池零碎片、O(1) 但只支持单一尺寸；slab 是对象池在内核的系统化实现，增加了着色与每 CPU 缓存。

## 六、常见误区
认为对象池解决所有碎片，内部碎片仍在；认为池越大越好，未用槽浪费内存；忽略线程安全需额外锁或每线程池。

## 七、与开源书/权威来源对应
Hennessy & Patterson 讨论缓存与对齐；Silberschatz 论分区分配；Linux slab 是对象池的工程化。

## 八、面试题
对象池为何无外部碎片；与 malloc 区别；内部碎片来源；如何线程安全。

## 九、演进与趋势
每线程对象池减少锁竞争；与 NUMA 结合把池放在本地节点；用户态 tcmalloc/jemalloc 吸收该思想。

## 十、小结
固定大小对象池以自由链表提供 O(1)、零外部碎片的分配，是高频同尺寸对象分配的高效基础结构。
