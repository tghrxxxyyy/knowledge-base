# 可执行文件加载与进程镜像建立

> 对应 Silberschatz《Operating System Concepts》第 8 章；Bryant & O'Hallaron《CSAPP》第 7.9 节。

## 一、背景与挑战

内核不能把磁盘上的字节直接当指令执行，必须按 ELF 程序头（program header）把文件段映射到虚拟地址空间，并建立初始栈、堆、寄存器与入口状态。还要处理 BSS 清零、动态链接器加载、ASLR 基址随机化等。这一步是 `execve` 的核心，决定了进程「起跑」时的内存图景。若映射出错（如权限位给错、基址冲突），要么段错误，要么给攻击者留下可写可执行页——故加载器同时承担安全边界职责。

还需注意 `execve` 的「原子替换」语义：它不创建新进程，而是用新映像覆盖当前进程的地址空间、寄存器与文件描述符表（除标记 `CLOEXEC` 者），失败时进程不受影响。这一「要么全换、要么不动」的性质，使 shell 的 fork+exec 模型得以可靠工作。

## 二、核心原理

ELF 的 `PT_LOAD` 段描述「哪段文件内容映射到哪段虚拟地址及权限（r/w/x）」。加载器遍历程序头，对每个 `PT_LOAD` 调用 `mmap` 建立文件到虚址的映射，并把 `p_memsz > p_filesz` 的部分（BSS，未初始化数据）清零。设置入口地址 `e_entry`、初始栈（压入 argc/argv/envp/auxv）。动态可执行先加载 `PT_INTERP` 指定的 `ld.so` 作为解释器，由它完成后续动态绑定。加载器还会处理 `PT_TLS`（线程局部存储）、`PT_GNU_STACK`（是否可执行栈）等扩展段。

对动态可执行，内核只做「映射 ld.so + 映射主程序 + 建立初始栈」，真正的重定位与符号解析交给 ld.so 在用户态完成——这也解释了为何 `LD_DEBUG` 能看到大量用户态解析日志，而内核侧只留下一次 `execve`。

## 三、形式化与数学基础

虚拟地址到文件偏移映射：对段 $[v_{start}, v_{end}]$ 对应文件 $[f_{start}, f_{end}]$，有：

$$v-v_{start}=f-f_{start},\quad pgoff=\lfloor f_{start}/PAGE\rfloor$$

页面边界对齐到 `PAGE`（通常 4KiB）。文件内偏移与虚拟地址仅在「页内」相等，跨页因对齐而不同，这是混淆二者的常见根源。BSS 大小 $=p_{memsz}-p_{filesz}$，占内存但不占文件。ASLR 引入随机 load-bias $B$，使实际虚址变为 $v+B$，但段内相对偏移不变。

| 情形 | 关系 |
| --- | --- |
| 段内偏移 | $f-f_{start}=v-v_{start}$ |
| 页对齐 | $p_{offset}\equiv p_{vaddr}\ (\text{mod } PAGE)$ |
| 页内偏移 | $f\bmod PAGE = v\bmod PAGE$ |
| BSS 大小 | $p_{memsz}-p_{filesz}$ |

## 四、代码实现

```c
// 内核 execve 加载循环（简化）
Elf64_Phdr *ph = phdr;
for (int i = 0; i < n_ph; i++, ph++) {
    if (ph->p_type != PT_LOAD) continue;
    vm_mmap(file, ph->p_vaddr, ph->p_filesz,
            ph->p_flags, ph->p_offset);              // 映射文件内容
    if (ph->p_memsz > ph->p_filesz)
        memset((void*)(ph->p_vaddr + ph->p_filesz), 0,
               ph->p_memsz - ph->p_filesz);          // 清零 BSS
}
regs->rip = ehdr.e_entry;        // 设置入口
setup_initial_stack(argc, argv, envp);  // 初始栈
```

现代内核用 `vm_file`/`vm_area_struct` 把映射组织成 VMA 红黑树，缺页时按 VMA 回填物理页。

## 五、与其他技术对比

| 加载策略 | 启动速度 | 内存 | 说明 |
| --- | --- | --- | --- |
| 静态一次性映射 | 慢（全载入） | 高 | 旧式 |
| 按需分页（demand paging） | 快 | 低 | 首次访问才调入物理页 |
| 预读/readahead | 更快 | 中 | 顺序访问模式优化 |

现代系统都用按需分页：映射建立页表项但物理页延迟到缺页时才分配，启动更快、内存更省。

| 加固机制 | 作用 | 相关程序头 |
| --- | --- | --- |
| ASLR | 随机化基址，抗 ROP | load-bias |
| W^X / NX | 页不可同时可写可执行 | `PT_GNU_STACK` |
| RELRO | 重定位后数据段只读 | `PT_GNU_RELRO` |
| 栈保护 | 检测栈溢出 | `PT_GNU_PROPERTY`（CET） |

## 六、常见误区

1. 文件大小等于内存大小——BSS 不占文件空间却占内存，且可能被 `mmap` 零页匿名映射。
2. 以为加载即执行——还需动态链接、TLS 初始化、`.init`/`.fini` 数组运行，才能真正进入 `main`。
3. 混淆虚拟地址与文件偏移——二者仅页内相等，跨页因 `p_vaddr` 与 `p_offset` 独立对齐而不同。
4. 误以为基址固定——ASLR 下实际基址随机，相对偏移才恒定。
5. 误以为 `execve` 会克隆进程——它替换当前进程映像，无新 PID，仅失败时原进程继续。
6. 误以为 `PT_LOAD` 段一定与节一一对应——段是加载粒度、节是链接/调试粒度，多个节可合成一个段。

## 八、面试题

1. `execve` 做了什么？答：解析 ELF 程序头、映射 `PT_LOAD` 段、清零 BSS、设入口与初始栈，必要时加载 ld.so，最后跳入口。
2. BSS 为何不在文件里？答：BSS 是未初始化数据，全零无需存盘，加载时由加载器清零，省文件空间。
3. `PT_LOAD` 与 `PT_DYNAMIC` 区别？答：`PT_LOAD` 描述可映射的代码/数据段；`PT_DYNAMIC` 描述动态链接元数据区，供 ld.so 解析。
4. 为何现代加载用按需分页？答：避免一次性把全文件读入内存，启动更快、内存按需占用。
5. `auxv` 里有哪些与安全相关的项？答：`AT_RANDOM`（栈保护 canary 与指针异或种子）、`AT_PHDR`/`AT_ENTRY`（供 ld.so 定位自身）。
6. 为何 `execve` 失败不影响原进程？答：内核在替换地址空间前先完成全部校验与映射准备，任一步失败即回滚并返回错误码。

## 九、演进与趋势

load-bias 随机化（ASLR）打乱基址以抗 ROP；大页（2MiB/1GiB）映射减少 TLB 压力；`PT_GNU_RELRO` 配合 full RELRO 把数据段在加载后设为只读，抵御 GOT 篡改。内核还用 `vm_flags` 强制 W^X（不可同时写与执行）以堵住 shellcode 注入。

新方向有三：其一，延迟映射与 `userfaultfd` 支持更细粒度的按需加载（如 lazy-pull 容器镜像）；其二，`memfd`/`execveat` 支持从内存或文件描述符直接执行，简化无盘与强隔离场景；其三，CET/影子栈（`PT_GNU_PROPERTY`）在加载期建立控制流保护前提，把加载器变成安全能力的启用点。可见「加载」已从纯搬运演化为安全策略的执行入口。

## 十、小结

加载是文件段到虚拟空间的受控映射，BSS 清零、入口设置与初始栈是建立进程态的最后拼图，而按需分页与 ASLR 是现代加载器的默认加固。读懂 `readelf -l` 的输出（每个 `PT_LOAD` 的 `Offset/VirtAddr/FileSiz/MemSiz/Flags`）即可预测进程初期的整个内存布局，这是排查启动崩溃、段错误与权限问题的基本功。
