# 重定位表与ELF重定位项

> 对应 Levine《Linkers and Loaders》第 7 章；CSAPP 第 7.6 节。

## 一、背景与挑战
编译器生成代码时未知外部符号地址，只能在指令操作数处填 0 并留下重定位记录，由链接器/加载器事后补值。

## 二、核心原理
ELF 每个须重定位的节附一张 .rela.text（带加数）或 .rel.text。每项含：偏移 offset（节内位置）、信息 info（符号索引 + 类型）、加数 addend。常见类型 R_X86_64_PC32（相对）、R_X86_64_64（绝对）、R_X86_64_GLOB_DAT（GOT 项）。

## 三、形式化与数学基础
对 R_X86_64_PC32，最终写入值：
$$value = S + A - P$$
其中 $S$ 为符号运行时地址，$A$ 为加数（常量偏移），$P$ 为重定位位置自身地址。相对跳转因此与加载基址无关。

## 四、代码实现
```c
// 应用一条重定位
void apply(Elf64_Rela *r, uint64_t S) {
    uint64_t P = base + r->r_offset;
    int64_t v = (int64_t)(S + r->r_addend - P);
    *(int32_t *)P = (int32_t)v;   // 32 位相对
}
```

## 五、与其他技术对比
绝对重定位 R_X86_64_64 直接写 $S+A$，依赖固定加载基址；PC 相对重定位使代码可加载到任意地址，是 PIE 的基础。

## 六、常见误区
1. 把 addend 当成 0——PC 相对调用常带 -4 修正指令长度。
2. 误以为重定位只在链接期——加载动态库时也要重做。
3. 32 位相对溢出（距离超过 2G）只在大型可执行文件才暴露。

## 七、与开源书/权威来源对应
ELF 规范定义重定位类型；CSAPP 7.6 用 readelf 演示；Levine ch7 讲重定位算法。

## 八、面试题
问：S+A-P 各含义？PC32 与 64 绝对区别？为何 PIE 必须相对重定位？

## 九、演进与趋势
RELA 取代 REL（加数独立字段），RISC-V 引入 PC 相对与 GOT 混合类型，提升可重定位性。

## 十、小结
重定位项是位置修正的元数据，PC 相对公式 S+A-P 是地址无关的根基。
