# 静态链接与符号合并机制

> 对应 Bryant & O'Hallaron《CSAPP》第 7 章；Levine《Linkers and Loaders》第 4 章。

## 一、背景与挑战
多个可重定位目标文件（.o）各自拥有独立的符号表、代码段与数据段，链接器必须把它们合并成单一可执行镜像。核心难点是：相同名字的符号来自不同翻译单元、强弱语义不同、地址在链接前未知，必须在合并后统一重排。

## 二、核心原理
链接器按输入顺序读取 .o，将同名的 .text/.data/.bss 节拼接成连续区域，构建全局符号表。对全局符号，链接器进行决议（resolution）：从所有定义中选一个，未定义引用被解析为最终地址。强弱符号规则：强符号（函数、已初始化全局）只能有一个定义；弱符号（未初始化全局）允许多个，链接器任选其一。

## 三、形式化与数学基础
合并后符号表规模满足：
$$|\Sigma| = \sum_{i} |sym_i| - |\text{重复弱符号}|$$
其中 $\Sigma$ 为最终符号集合。节在镜像中的偏移由累加布局决定：$off_k = \sum_{j<k} size_j$。

## 四、代码实现
```c
// 伪代码：节拼接布局
unsigned off = 0;
for (Section *s = secs; s; s = s->next) {
    s->addr = base + off;   // 分配虚拟地址
    off += align_up(s->size, s->align);
}
```

## 五、与其他技术对比
静态链接把所有代码固化为单一镜像，启动快、部署简单，但体积大、库更新需重链；动态链接把共享库延迟到加载期绑定，节省内存但引入 GOT/PLT 开销与版本耦合。

## 六、常见误区
1. 认为未初始化全局变量是强符号——实际是弱符号，落入 COMMON。
2. 以为链接顺序无关——静态库按命令行顺序抽取，符号在前未用到则后续不再回头。
3. 重复定义强符号却期望链接器报错位置明确，实际仅报 multiple definition。

## 八、面试题

## 九、演进与趋势
现代链接器（lld、gold）采用并行节合并与增量链接，LTO 在链接期重做整个程序优化，模糊了编译与链接边界。

## 十、小结
静态链接的本质是符号决议加节布局，强弱符号与顺序语义是工程正确性的关键。
