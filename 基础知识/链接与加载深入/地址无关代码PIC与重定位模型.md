# 地址无关代码PIC与重定位模型

> 对应 Levine《Linkers and Loaders》第 11 章；CSAPP 第 7.12 节。

## 一、背景与挑战
共享库要能被多个进程映射到不同虚拟地址仍正确运行，不能依赖固定地址，否则每个进程需一份私有副本，失去共享意义。

## 二、核心原理
地址无关代码（PIC）通过两级间接访问全局数据：先取当前指令地址（IP 相对），加 GOT 偏移得到 GOT 项，再经 GOT 读真实地址。函数调用走 PLT+GOT。模块内数据可用 IP 相对直接访问，跨模块必须经 GOT。

## 三、形式化与数学基础
访问全局变量 $g$ 的地址：
$$addr(g) = GOT + idx \times 8$$
而 $GOT$ 自身可经 $ RIP + disp $ 取得，因 GOT 与代码段相对距离在链接期固定。故不依赖绝对基址。

## 四、代码实现
```c
// 取 GOT 基址（x86-64，AT&T 语法）
get_got:
    lea .GOTPCREL(%rip), %rax   // rax = GOT 基址
    movq idx*8(%rax), %rax       // 解引用 GOT 项
    ret
```

## 五、与其他技术对比
PIC 牺牲一条额外间接寻址换取可共享；非 PIC 代码段直接绝对寻址，更快但每进程需重定位私有副本（TEXTREL）。

## 六、常见误区
1. 以为 PIC 只影响代码——全局数据的 GOT 间接同样必要。
2. 把 -fPIC 与 -fpie 混用——前者用于库，后者用于可执行文件 PIE。
3. 误以为 PIC 无需重定位——GOT 项本身仍需加载期填充。

## 九、演进与趋势
x86-64 原生 RIP 相对寻址让 PIC 几乎零成本；RISC-V 用 gp 寄存器缓存 GOT 基址加速。

## 十、小结
PIC 用相对地址加 GOT 间接把绝对依赖压缩到少量数据项，实现代码段共享。
