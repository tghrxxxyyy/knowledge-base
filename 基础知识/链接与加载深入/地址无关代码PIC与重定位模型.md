# 地址无关代码PIC与重定位模型

> 对应 Levine《Linkers and Loaders》第 11 章；Bryant & O'Hallaron《CSAPP》第 7.12 节。

## 一、背景与挑战

共享库要能被多个进程映射到不同虚拟地址仍正确运行。若代码段直接绝对寻址全局变量/函数，则每个进程需一份私有副本（因为地址不同），彻底失去「共享物理页」的意义。地址无关代码（PIC，Position-Independent Code）通过相对寻址 + GOT 间接，使同一份代码段可被所有进程共享，无论加载基址如何。反过来，若不用 PIC 而用 `-no-pie` 编译的库，加载器必须在加载期对所有绝对引用重定位，迫使代码段变成私有（TEXTREL），内存与启动成本陡增。

代价也是真实的：GOT 间接让每次跨模块数据访问多一次访存，热点循环中可能可观测；GOT 项本身必须在加载期填充，因此在 `-z now` 全绑定之外还存在「必须在首次访问前完成」的约束。PIC 本质上是在「可共享性」与「少量间接访存」之间的取舍，而现代 ISA 的寻址模式设计（如 x86-64 的 RIP 相对）已把这一代价压到接近于零。

## 二、核心原理

PIC 对全局数据采用两级间接：先取当前指令地址（IP 相对），加 GOT 偏移得到 GOT 项地址，再经 GOT 解引用得到真实数据地址。函数调用走 PLT+GOT。模块内数据可用 RIP 相对直接访问（同模块内偏移固定），跨模块全局数据/函数必须经 GOT。由此，需要重定位的「绝对依赖」被压缩到少量 GOT 项，代码段本身纯相对、可共享。对「模块内函数调用」也可 RIP 相对直接跳，无需 GOT，仅跨模块调用才走 PLT。

还需区分三种符号可见性对访问方式的影响：`static`（局部）符号在汇编期即可解析偏移，完全无需 GOT；`hidden`/`protected` 可见性使其在定义模块内可用直接寻址、跨模块不可见，是「既想导出又想省间接」的关键手段；只有默认可见性（default）的外部符号才必须走 GOT/PLT。理解这一点即可解释「为何 `-fvisibility=hidden` 能显著减少动态重定位」。

## 三、形式化与数学基础

访问全局变量 $g$ 的地址：

$$addr(g)=GOT+idx\times 8$$

而 $GOT$ 自身可经 $RIP+disp$ 取得，因为 GOT 与代码段的相对距离在链接期固定。故访问 $g$ 完全不依赖绝对基址，只依赖「代码到 GOT 的固定偏移 + GOT 项在加载期被填充」。PIE（Position-Independent Executable）把同一思想用于可执行文件，配合 ASLR 实现地址随机化。设加载基址 $B$，则实际 $GOT_{run}=GOT_{link}+B$，而 $RIP$ 取址天然含 $B$，故相对关系恒成立。

对函数调用，PLT 桩的目标值满足：

$$GOT[2+i] = \begin{cases} PLT\_stub & \text{未绑定} \\ addr(f_i) & \text{已绑定} \end{cases}$$

即「解析与调用解耦」，PIC 的地址无关性因此同时覆盖数据与代码两个方向。

## 四、代码实现

```asm
; 取 GOT 基址并访问全局变量（x86-64 AT&T 语法）
get_got:
    lea .GOTPCREL(%rip), %rax     ; rax = GOT 基址（RIP 相对）
    movq idx*8(%rax), %rax        ; 解引用 GOT 项 -> 变量真实地址
    ret
; 模块内数据则可直接： mov var(%rip), %reg（无需 GOT）
```

RISC-V 用 `gp` 寄存器缓存 GOT 基址，加速跨模块访问；但 `gp` 需在函数入口重设，故需 `-fno-pic` 之外的约定管理。

```c
// 三种可见性对访问方式的影响（对比示意）
int global_default;              // 默认：跨模块访问需经 GOT
__attribute__((visibility("hidden"))) int global_hidden;  // 模块内直访，不导出
static int global_static;        // 纯局部：汇编期定偏移，零重定位
```

## 五、与其他技术对比

| 方式 | 代码段共享 | 访问开销 | 用途 |
| --- | --- | --- | --- |
| PIC（库） | 可 | 多一次间接 | 共享库 |
| PIE（可执行） | 可（自身） | 多一次间接 | 地址随机化可执行 |
| 非 PIC | 不可（需私有副本） | 直接 | 老式/内核 |
| hidden 符号 | 可 | 无额外间接 | 库内私有 API |

PIC 牺牲一条额外间接寻址换取可共享；非 PIC 代码段直接绝对寻址更快但每进程需重定位私有副本（TEXTREL）。hidden 可见性则兼得两者：既保持代码段可共享，又避免 GOT 间接。

## 六、常见误区

1. 以为 PIC 只影响代码——全局数据的 GOT 间接同样必要，否则数据地址仍绝对。
2. 把 `-fPIC` 与 `-fpie` 混用——前者用于库、后者用于可执行文件 PIE，语义不同。
3. 误以为 PIC 无需重定位——GOT 项本身仍需在加载期填充（通过 `R_X86_64_GLOB_DAT`）。
4. 误以为所有访问都走 GOT——模块内数据/函数可用 RIP 相对直访，仅跨模块才需间接。
5. 误以为 `-fPIC` 一定比 `-fpic` 好——`-fpic` 使用更小的 GOT 偏移表（受 ISA 限制），大模块才需要 `-fPIC`。
6. 误以为 PIC 会让程序变慢很多——x86-64 的 RIP 相对寻址下，多数访问与绝对寻址指令长度相同，代价极小。

## 八、面试题

1. PIC 如何访问全局变量？答：RIP 相对取 GOT 基址 → 加索引取 GOT 项 → 解引用得真实地址，全程相对、可共享。
2. 为什么需要 GOT？答：把绝对地址依赖集中到可写数据项，代码段保持纯相对从而可被多进程共享。
3. PIE 与 PIC 关系？答：PIC 用于库（可加载任意地址），PIE 用于可执行文件（配合 ASLR 随机基址），机制相同。
4. 模块内访问为何可不用 GOT？答：同模块内代码与数据相对偏移固定，RIP 相对直访即可，跨模块才需 GOT 间接。
5. `hidden` 可见性为何能减少重定位？答：隐藏符号不参与跨模块解析，可被直接寻址并允许链接器移除其 GOT 项。
6. `-fpic` 与 `-fPIC` 的差别？答：`-fpic` 生成更紧凑的 GOT 偏移访问（受 ISA 位宽限制），超限时需 `-fPIC`。

## 九、演进与趋势

x86-64 原生 RIP 相对寻址让 PIC 几乎零额外成本；RISC-V 用 `gp` 缓存 GOT 基址加速；`R_X86_64_REX_GOTPCRELX` 让链接器把 GOT 访问直接优化为 RIP 相对加载，进一步减少间接。TLS（线程局部存储）的「初始可执行」模型也依赖 PIC 的 GOT 偏移定位。

安全侧的趋势是「尽可能消除可写重定位」：full RELRO 让 GOT 在重定位后只读，`-fvisibility=hidden` 与 `-Wl,-Bsymbolic` 减少运行时解析面，`-z now` 消除惰性绑定的可写窗口。这些手段本质上都在压缩「PIC 必须保留的可写间接层」，在保持可共享性的同时降低攻击面。

## 十、小结

PIC 用相对地址加 GOT 间接把绝对依赖压缩到少量数据项，实现代码段共享与地址随机化，是现代共享库与 PIE 的底层基石。理解「哪些访问可以免 GOT」——模块内直访、hidden 符号、链接器 GOT 优化——是写出高效且加固良好的库代码的关键。
