# 云上中间件体系总览（PaaS 托管全景）

> 云上中间件 = 云厂商把消息、缓存、数据库、数仓、调度等基础设施做成**托管服务（Managed/PaaS）**：免运维、高可用、弹性伸缩、按量付费。本篇给「自建中间件」与「云托管中间件」的全景对照，以及选型方法论。细分生态见：消息与集成 / 数据库与缓存 / 数仓与大数据三篇。

---

## 一、为什么用云上中间件（PaaS vs 自建）

| 维度 | 自建（自运维） | 云托管（PaaS） |
|------|---------------|----------------|
| 人力 | 部署/升级/扩缩容/故障自愈全自己干 | 全托管，只写业务代码 |
| 高可用 | 自己搭主从/集群/多可用区 | 厂商 SLA 承诺（99.9%~99.99%+） |
| 弹性 | 提前备机，扩缩容慢 | 秒~分钟级伸缩，按量计费 |
| 升级 | 停服风险自担 | 厂商滚动升级，通常无感 |
| 运维 | 监控/告警/备份/恢复自建 | 自带监控、自动备份、一键恢复 |
| 成本 | 闲时也付满配机器钱 | 按用量付费，闲时省钱 |
| 风险 | 完全可控 | 厂商锁定（Lock-in）、区域故障跟随厂商 |

> 适用判断：**人力贵、量波动大、要快速上线 → 云托管**；**强合规（数据不出域）、要极致成本或深度定制 → 自建或私有化**。绝大多数中小企业「云托管 + 少量自建」混合最划算。

## 二、云中间件与自建组件的一一对应

| 能力 | 自建开源 | AWS | Azure | GCP | 阿里云 | 腾讯云 |
|------|----------|-----|-------|-----|--------|--------|
| 对象存储 | MinIO | S3 | Blob Storage | Cloud Storage | OSS | COS |
| 关系库托管 | MySQL/PostgreSQL 自建 | RDS/Aurora | Azure SQL/Database for PostgreSQL | Cloud SQL/AlloyDB | RDS/PolarDB | 云数据库 CDB/TDSQL |
| 文档库 | MongoDB | DocumentDB | Cosmos DB (Mongo API) | Firestore/文档DB | 云 MongoDB | 云 MongoDB |
| KV/缓存 | Redis | ElastiCache/MemoryDB | Azure Cache for Redis | Memorystore | 云 Redis/Tair | 云 Redis |
| 分布式表 | TiDB | (Aurora/Serverless) | Cosmos DB | Spanner | PolarDB-X | TDSQL |
| 消息队列 | RocketMQ/Kafka | SQS/SNS | Service Bus/Event Grid | Pub/Sub | 云 RocketMQ/MNS | CMQ/TDMQ |
| 流处理 | Kafka/Flink | Kinesis/MSK | Event Hubs/Azure Stream Analytics | Pub/Sub/Flink(Dataflow) | 云 Kafka/Flink | CKafka/流计算 |
| 数仓 | ClickHouse/Doris | Redshift | Synapse | BigQuery | MaxCompute/AnalyticDB | 云数仓 |
| 搜索 | Elasticsearch | OpenSearch | AI Search/Cognitive Search | 无托管 ES（GKE 自建） | 云 ES | 云 ES |
| 调度 | XXL-JOB | Step Functions | Logic Apps | Workflows | 云工作流 | 云工作流 |
| 事件总线 | — | EventBridge | Event Grid | Eventarc | 云 EventBridge | EventBridge |
| 注册/配置 | Nacos | (无,靠 ECS/AppConfig) | (无) | (无) | 微服务引擎 MSE | 微服务平台 TSF |

> 核心认知：**云上中间件不是新组件，而是「开源组件的托管化 + 云生态整合」**——你学的原理全部通用，只是不用自己运维。AWS 尤其爱用新名字包装（如 DocumentDB=托管 MongoDB 兼容），认准「兼容什么开源协议/API」即可迁移知识。

## 三、托管中间件的共性特性（无论哪家）

1. **高可用内置**：多可用区（AZ）部署、自动故障转移，厂商承诺 SLA；
2. **弹性伸缩**：按吞吐/容量自动扩缩（serverless 档位甚至零运维）；
3. **安全默认**：VPC 隔离、加密（传输+静态）、IAM/密钥管理、审计日志；
4. **监控集成**：自带指标（CloudWatch/Azure Monitor/云监控）+ 告警 + 自动备份/恢复；
5. **生态打通**：与其他云服务原生联动（触发函数、进数仓、进湖），免自研胶水；
6. **计价模式**：按量（实例 + 存储 + 流量 + IO 请求），比自建更细粒度。

## 四、选型方法论（云中间件六问）

1. **问协议**：是否兼容我已用的开源协议（S3/MQTT/MySQL 协议/REDIS 协议）？兼容则迁移零改动。
2. **问 SLA**：99.9% vs 99.99% 差一个九，报价差多少？核心链路才值得高可用档。
3. **问锁定**：用了它的专属 API 后，迁回自建成本多高？（S3 协议是事实标准，放心；专属事件格式要谨慎）
4. **问弹性**：流量波峰/波谷比例多大？serverless 档 vs 预留实例怎么配省钱？
5. **问区域**：目标用户所在区域是否有该服务？跨区域访问延迟与成本？
6. **问预算**：用量 × 单价 vs 自建 TCO（机器+人力+升级）：用量稳定且大 → 自建更省；波动大 → 云托管。

## 五、多云与规避锁定

| 策略 | 做法 | 代价 |
|------|------|------|
| 协议抽象层 | 只依赖「开源标准协议」类服务（S3/Kafka/MySQL/Redis 协议） | 换云时 API 兼容 |
| 自建抽象层 | 上层封装统一接口（如统一 MQ 客户端） | 开发成本 |
| 数据层尽量可迁移 | 数据导出/备份机制必须成熟（厂商锁定主要在数据） | 验证导出 |
| 高可用双云 | 关键读路径双云冗余 | 成本翻倍，极少需要 |

> 现实结论：**「协议兼容优先」是防锁定的第一道防线**——选「兼容 S3/Kafka/Redis/MySQL」的托管服务，未来换云/迁回自建都是平滑的。

## 六、速查：什么时候用云上哪一类

| 场景 | 首选云服务 | 替代自建 |
|------|-----------|----------|
| 文件/图片/备份 | S3 / OSS / COS | MinIO |
| 业务解耦+削峰 | SQS / 云 RocketMQ | RabbitMQ/RocketMQ |
| 事件驱动（云内联动） | EventBridge / Event Grid | 自研事件总线 |
| 高吞吐日志管道 | Kinesis / MSK / CKafka | Kafka 集群 |
| 标准关系业务 | RDS / Cloud SQL / PolarDB | MySQL 主从 |
| 弹性+高并发关系库 | Aurora / PolarDB-X | TiDB 自建 |
| 会话/热点缓存 | ElastiCache / 云 Redis | Redis 自建 |
| 全量分析/BI | Redshift / BigQuery / MaxCompute | ClickHouse 自建 |
| 全文搜索 | OpenSearch / 云 ES | ES 集群 |
| 定时/编排任务 | Step Functions / 云工作流 | XXL-JOB |
