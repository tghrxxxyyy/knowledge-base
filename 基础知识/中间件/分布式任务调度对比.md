# 分布式任务调度对比（Quartz / XXL-JOB / Elastic-Job / PowerJob / SchedulerX / Sat）

> 分布式任务调度是定时任务/批处理作业的调度中心： cron 表达式触发、分片执行、失败重试、可视化管控。相比数据库轮询/Redis 键过期，专业调度器以「分片/弹性/治理」成为标配。本文横向对比 6 大调度器，每类按「解决的问题 → 原理 → 特性 → 选型关注点」拆解。

---

## 一、要解决的问题

| 痛点 | 说明 |
|------|------|
| 单点故障 | Quartz 单节点挂了任务不执行 |
| 单机瓶颈 | 任务量超单机处理能力 |
| 分片执行 | 大数据量任务需拆分到多节点并行 |
| 可视化 | 任务管理/执行日志/失败告警需 UI |
| 弹性扩缩 | 节点增减时任务自动重分配 |

> 核心认知：**分布式调度 = 调度器（选主/触发）+ 执行器（业务逻辑）分离**——调度器负责 cron 触发与路由，执行器负责业务。

---

## 二、六大调度器对比

### 2.1 Quartz（Java 调度基础库）

**定位**：Java 调度的事实标准库（无分布式能力）

**原理**：
- RAMJobStore（内存）或 JobStoreTX（数据库悲观锁）
- 集群模式：数据库行锁选举（`SELECT FOR UPDATE`）

| 特性 | 说明 |
|------|------|
| 优点 | 轻量、稳定、Spring 集成好 |
| 缺点 | 集群模式数据库压力大、无 UI、无分片、无失败告警 |

**选型关注点**：单机定时任务 → Quartz（足够）；分布式场景 → 选专业调度器。

### 2.2 XXL-JOB（轻量级分布式调度平台）

**定位**：大众点评开源，国内最流行

**原理**：
- 调度中心（Admin）：Web UI + 调度触发，支持集群部署（DB 行锁防重复触发，推荐 Nginx 负载均衡）
- 执行器（Embed）：业务方引入 SDK，自动注册
- 调度：cron 触发 → RPC 调用执行器 → 回调结果
- 分片：执行器集群分片（分片参数=实例索引/总数）

| 特性 | 说明 |
|------|------|
| 优点 | UI 友好、分片广播、失败重试、路由策略丰富 |
| 缺点 | 调度中心 HA 依赖 DB 行锁 + 集群部署；无工作流（DAG）；分片参数需手动传 |

**选型关注点**：国内 Java 业务 + 要 UI + 分片 → XXL-JOB。

### 2.3 Elastic-Job（Elastic-Job-Lite / Cloud）

**定位**：当当开源，ZK 协调的分布式调度

**原理**：
- ZooKeeper 协调：选主/分片/故障转移
- 弹性扩缩：分片自动感知节点变化重分配
- 作业类型：Simple/Dataflow/Script

| 特性 | 说明 |
|------|------|
| 优点 | 弹性扩缩、ZK 协调 HA、Dataflow 流式处理 |
| 缺点 | 依赖 ZK、学习曲线陡 |

**选型关注点**：需要弹性扩缩 + ZK 基础设施 → Elastic-Job。

### 2.4 PowerJob（分布式调度 + 计算）

**定位**：多语言、高弹性、支持 Map Reduce 计算

**原理**：
- Server（调度中心）+ Worker（执行器）
- 通信：Akka（高性能 Actor 模型）
- MapReduce：任务自动拆分 → 分发 → 汇总

| 特性 | 说明 |
|------|------|
| 优点 | 多语言支持、MapReduce、处理器链、工作流（DAG） |
| 缺点 | 相对年轻、社区较小 |

**选型关注点**：多语言/MapReduce/工作流 → PowerJob。

### 2.5 SchedulerX（阿里中间件）

**定位**：阿里商用调度平台

| 特性 | 说明 |
|------|------|
| 优点 | 与阿里云集成、高可用、精确一次 |
| 缺点 | 商业产品、阿里云绑定 |

### 2.6 Sat（国产轻量调度）

**定位**：轻量级分布式调度

| 特性 | 说明 |
|------|------|
| 优点 | 轻量、Nacos/Redis 协调、DAG 支持 |
| 缺点 | 相对年轻 |

## 三、横向对比表

| 维度 | Quartz | XXL-JOB | Elastic-Job | PowerJob | SchedulerX | Sat |
|------|--------|---------|-------------|----------|-------------|-----|
| 分布式 | 集群模式（弱） | 是 | 强（ZK） | 强（Akka） | 是 | 是 |
| 协调机制 | 数据库 | DB 行锁 | ZooKeeper | Akka | 内部 | Nacos/Redis |
| HA | 弱 | DB 锁集群 | ZK HA | Akka HA | 高可用 | 是 |
| 分片 | 无 | 分片广播 | 弹性分片 | MapReduce | 分片 | 分片 |
| 弹性扩缩 | 无 | 手动注册 | 自动感知 | 自动感知 | 自动 | 自动 |
| UI | 无 | 强 | 弱 | 强 | 强 | 有 |
| 失败重试 | 无 | 有 | 有 | 有 | 有 | 有 |
| 路由策略 | 无 | 丰富（第一个/最后一个/轮询/随机/一致性哈希/最经常使用/故障转移/忙碌转移/分片广播） | 分片 | 丰富 | 丰富 | 丰富 |
| 工作流（DAG） | 无 | 无 | 无 | 有 | 有 | 有 |
| 多语言 | Java | Java | Java | Java/Go/Python 等 | Java | Java |
| 社区 | 成熟 | 活跃（国内最流行） | 活跃 | 成长中 | 商业 | 年轻 |
| 开源 | 是 | 是 | 是 | 是 | 否 | 是 |
| 依赖 | 数据库 | MySQL | ZooKeeper | 无外部依赖 | 阿里云 | Nacos/Redis |

## 四、选型速查

| 场景 | 首选 | 备选 |
|------|------|------|
| 单机定时任务 | Quartz | — |
| 国内 Java 业务 + UI + 分片 | XXL-JOB | — |
| 需要弹性扩缩 + ZK | Elastic-Job | — |
| 多语言/MapReduce/工作流 | PowerJob | SchedulerX |
| 阿里云生态 | SchedulerX | XXL-JOB |
| 轻量级 + Nacos/Redis | Sat | XXL-JOB |
| 需要工作流（DAG） | PowerJob | SchedulerX |
| 商业支持 | SchedulerX | — |
