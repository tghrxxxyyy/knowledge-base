# 分布式 ID 生成器（雪花 / 号段 / UUID）

> 分布式 ID 生成是**分布式系统的地基设施**：全局唯一、趋势递增、高性能、高可用。主流方案：**雪花算法（Snowflake）**（时间+机器+序列，趋势有序）、**号段模式**（DB 批量取号，性能高）、**UUID**（无序/不可索引）、**Redis INCR**。相比自增主键（单机瓶颈）、时间戳（并发冲突），专业的分布式 ID 以「**唯一 + 有序 + 高性能（10万+/s）+ 可解析（内含时间/机器信息）**」成为订单/消息/日志场景标配。本篇按「解决的问题 → 原理 → 方案对比 → 选型关注点」拆解。

---

## 一、要解决的问题

| 痛点 | 说明 |
|------|------|
| 全局唯一 | 多实例/多库并发生成 ID 不能重复（合并分表关键） |
| 性能 | 订单/日志高频场景需要 10 万+/s 生成能力 |
| 趋势递增 | 数据库索引友好（B+Tree 顺序写） |
| 可排序 | 时间有序便于按时间维度分页/分区 |
| 可解析 | ID 能反解出生成时间/机器（排查/路由） |

> 核心认知：**分布式 ID 三要素 = 唯一性（全局）+ 有序性（趋势）+ 高性能（本地生成优先）**——「本地生成」是性能关键（不依赖网络）。

---

## 二、核心方案与原理

### 2.1 雪花算法（Snowflake，最流行）

```
 63位 long：0 | 41位时间戳(ms) | 10位机器ID | 12位序列号
              ↑               ↑           ↑
         自定义纪元起毫秒    数据中心5位+机器5位   同一毫秒内自增(4096个/ms)

每秒理论 409.6 万 ID；时钟回拨是最大风险
```

**变体**：
- **百度 UidGenerator**：时间 + 工作机（从 DB 分配）+ 序列（环形）；
- **美团 Leaf-snowflake**：机器 ID 从 ZK 获取 + 时钟回拨自动检测/熔断；
- **改进方向**：去掉机器位换业务位、时间右移压缩（如毫秒→秒）。

**时钟回拨处理**：检测到回拨 → 抛异常/等待追平/用扩展位（等回拨，回拨过大直接降级 DB 取号）。

### 2.2 号段模式（DB 批量取号，性能方案）

```
每次从 DB 取一段号：UPDATE `id_biz` SET max_id = max_id + step WHERE biz = 'order'
  → 内存持有 [max_id, max_id+step]，本地发完再取下一段
  → 支持多进程异步取段（美团的 Leaf-segment：双 buffer 预取）

优点：性能高（网络只在取段时）、趋势递增、DB 压力小
缺点：依赖 DB（取段失败降级）、号码非严格连续（可接受）
```

### 2.3 Redis INCR / Lua

```
INCR order_id（Redis 原子自增）
  → 简单高性能，但依赖 Redis 可用性，且可预测（安全风险：ID 泄露订单量）
```

### 2.4 UUID

```
UUID v4 随机 122 位 → 32 位十六进制
  → 全局唯一简单，但无序（索引碎片化）、体积大（36 字符）、不可排序
  → 改进：UUID v7（时间有序版，新趋势）
```

### 2.5 其他

| 方案 | 说明 |
|------|------|
| 数据库自增（多库步长） | 库1:奇 库2:偶（步长=库数），扩库要改步长 |
| 时间戳+随机 | 简单但冲突率随并发上升（不推荐生产） |
| ZK/etcd 原子 | 一致性高但性能低（仅低频场景） |

## 三、方案横向对比

| 维度 | 雪花 | 号段（Leaf-segment） | Redis INCR | UUID v4 | DB 步长自增 |
|------|------|---------------------|------------|---------|-------------|
| 唯一性 | 全局 | 全局 | 全局 | 全局 | 全局 |
| 有序性 | 趋势有序 | 趋势有序 | 严格递增 | 无序 | 递增 |
| 性能 | 极高（本地） | 高（本地发号） | 高（网络 IO） | 最高 | 低（DB 瓶颈） |
| 依赖 | 无（本地） | DB（低频） | Redis | 无 | DB |
| 体积 | 8B | 8B | 8B | 16B/36 字符 | 8B |
| 可解析 | 时间+机器 | 无 | 无 | 无 | 无 |
| 风险 | 时钟回拨 | DB 故障 | Redis 故障/可预测 | 索引碎片 | 扩容改步长 |
| 适用 | 订单/消息/日志 | 订单/流水 | 计数类 | 客户端 ID/纯唯一 | 单机小系统 |

**选型关注点**：
- 通用主键/订单/消息 → **雪花**（性能 + 有序 + 可解析，处理时钟回拨）；
- 严格递增/DB 已有 → **号段模式**（Leaf-segment，双 buffer 预取）；
- 无顺序要求/客户端生成 → **UUID v7**（时间有序，推荐替代 v4）；
- 计数/短 ID → **Redis INCR**。

## 四、生产实践（雪花）

### 4.1 关键实践

| 实践 | 说明 |
|------|------|
| 机器 ID | 从注册中心/配置文件分配，禁止硬编码（冲突=重复） |
| 时钟回拨 | 回拨 <5ms 等追平；>5ms 熔断降级（DB 取号） |
| 纪元 | 自定义纪元（不要从 1970 开始，延长可用年限） |
| 序列溢出 | 同一毫秒序列满 → 自旋等待下一毫秒 |
| 异常兜底 | 生成失败降级到号段/UUID（保证可用性） |
| 可解析 | 保留时间位解析能力（排查/热点分析） |

### 4.2 常见坑

- **机器 ID 冲突**：多环境/多机房共用 ID → 重复 ID（必须在位段规划时隔离）；
- **时钟回拨未处理**：NTP 校正导致 ID 回退 → 订单错乱；
- **分表路由依赖 ID 时间位**：雪花 ID 按时间位路由 → 冷热不均（用 hash 路由）；
- **前端精度丢失**：64 位 ID 传前端 JS 丢精度（Number.MAX_SAFE_INTEGER）→ 转字符串。

## 五、选型速查

| 场景 | 首选 | 备选 |
|------|------|------|
| 订单/消息主键 | 雪花 | 号段 |
| 严格递增流水号 | 号段（Leaf-segment） | Redis INCR |
| 客户端生成/无顺序 | UUID v7 | UUID v4 |
| 日志 ID | 雪花（时间解析） | UUID |
| 短 ID/邀请码 | Redis INCR + 混淆 | 号段 + 进制转换 |
| 低频全局唯一 | ZK/etcd 原子 | DB 自增 |
