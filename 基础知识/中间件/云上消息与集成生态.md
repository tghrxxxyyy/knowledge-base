# 云上消息与集成生态（队列 / 主题 / 事件 / 流）

> 云厂商把消息中间件做成托管服务，且按 IO 模型拆成**队列（Q）、主题（Topic/SNS）、事件总线（Event Bus）、流（Stream）**四类。本篇逐个拆解 AWS / Azure / GCP / 阿里云 / 腾讯云的对应服务，每条按「解决的问题 → 原理 → 特性 → 选型关注点」。

---

## 一、四类 IO 模型先分清（所有云通用）

| 模型 | 语义 | 典型场景 | 云服务代表 |
|------|------|----------|-----------|
| 队列 Queue | 点对点，一条消息只被一个消费者处理 | 任务解耦、削峰、异步 | SQS / 云 RocketMQ / CMQ |
| 主题 Topic | 发布订阅，一条消息被所有订阅者各收一份 | 事件通知、广播 | SNS / Pub/Sub / MNS |
| 事件总线 | 事件驱动编排，按规则路由到目标 | 云服务间联动、事件过滤 | EventBridge / Event Grid |
| 流 Stream | 有序可回放、高吞吐日志 | 日志管道、实时分析 | Kinesis / Event Hubs / CKafka |

> 最容易混淆：**Topic 是「广播」、Queue 是「竞争消费」**——和自建里 MQTT vs 消息队列的区别一模一样（见「[MQTT 与消息 Broker](./MQTT与消息broker.md)」）。

## 二、AWS：SQS / SNS / EventBridge / Kinesis

### 2.1 SQS（Simple Queue Service）——托管队列

**解决的问题**：不想自建 RabbitMQ/RocketMQ，要一个「开箱即用、无限伸缩、高可用」的队列来解耦与削峰。

**原理**：分布式队列，标准队列至少一次投递（可能重复），FIFO 队列严格有序 + 恰好一次（基于消息组）。

| 特性 | 说明 |
|------|------|
| 标准 vs FIFO | 标准高吞吐（默认乱序、至少一次）；FIFO 严格有序 + 去重，限 300 msg/s |
| 可见性超时 | 消费者拉走后消息对他人不可见，处理完删除；超时未删重复投递 |
| 死信队列 DLQ | 消费失败 N 次进 DLQ，人工/脚本处理 |
| 长轮询 | 减少空轮询流量（20s） |
| CloudWatch | 内置队列深度、条年龄监控 |

**选型关注点**：延迟敏感（FIFO 有吞吐上限）→ 换 Kinesis 或自建；需要延迟消息/事务消息 → 云 RocketMQ 更合适；SQS 是「极简可靠队列」，不是「企业消息平台」。

### 2.2 SNS（Simple Notification Service）——托管 Pub/Sub 主题

**解决的问题**：一个事件要发给多类接收方（短信/邮件/HTTP 回调/队列/函数），不想每家各接一个。

**原理**：主题 + 订阅者组，发布进主题 → SNS 扇出发往所有订阅者（fan-out）。

**特性**：主题过滤（按属性只推给感兴趣的订阅）、多协议订阅（HTTP/SMS/Email/Lambda/SQS）、与 SQS 组合做「扇出到 N 个队列」、地区多租户隔离。

**选型关注点**：需要持久化历史/回放 → SNS 不存历史，要接 SQS/Kinesis；需要消费端负载均衡 → 订阅到 SQS 而非直接 HTTP。

### 2.3 EventBridge —— 云内事件总线（无代码集成核心）

**解决的问题**：云上几十个服务的事件（EC2 状态、S3 上传、定时 cron？）要按规则自动触发下游，**不想写胶水代码**。

**原理**：事件总线接收事件（事件源），规则（pattern matching）路由到目标（Targets：Lambda/Step Functions/SQS/HTTP）。

**特性**：事件模式匹配（按 source/detail-type/字段）、调度器（cron 定时）、自定义事件源（自家应用也能对接）、跨账号/跨区域总线、归档与重放（Audit）。

**选型关注点**：这是「**云原生事件驱动架构**」的枢纽——凡是「A 云服务变化 → 触发 B」的编排都优先考虑；但它依赖厂商事件格式，跨云迁移成本高（防锁定重点）。

### 2.4 Kinesis —— 托管流（Apple-style 数据管道）

**解决的问题**：高吞吐、**有序、可回放**的实时数据流（点击流、日志、IoT）——即「托管版 Kafka」的核心能力。

**原理**：分片（Shard）模型 = Kafka 分区；每条记录带序列号；消费者按分片读游标，支持回放。

**特性**：Kinesis Data Streams（实时流）、Data Firehose（批量落 S3/Redshift）、Data Analytics（SQL 实时分析）；保留期默认 24h（可调）；时序无序风险低（按分片保序）。

**选型关注点**：需要多消费者组/复杂 Topic 路由 → MSK（托管 Kafka）语义更全；需要 >24h 回放 → 落 S3+Athena；**Kinesis 分片数封顶吞吐，扩缩容要手动调分片**。

## 三、Azure：Service Bus / Event Grid / Event Hubs

| 服务 | 定位 | 与 AWS 对应 | 关键点 |
|------|------|------------|--------|
| Service Bus | 企业级消息总线 | SQS+RabbitMQ | 队列+主题+事务+去重+会话，强一致，适合企业集成 |
| Event Grid | 事件路由（云内） | EventBridge | 子网事件分发，毫秒级，路由到函数/逻辑应用 |
| Event Hubs | 大规模事件流 | Kinesis | 高吞吐流、分区模型、捕获到 Blob |

**选型关注点**：企业系统对接（ERP/SAP 等）→ Service Bus（协议全、可靠）；云内事件编排 → Event Grid（快而轻）；海量遥测/日志 → Event Hubs（吞吐优先）。

## 四、GCP：Pub/Sub / Dataflow

**Pub/Sub** —— GCP 的托管消息（同时覆盖 Queue + Topic，即拉即推）。
- 原理：全局消息服务，订阅模型（pull 长轮询 / push 推送），At-least-once + 去重；
- 特性：按消息计费、自动伸缩、跨区域复制、与 Dataflow/BigQuery 原生打通；
- 选型关注点：没有「类 Kafka 的严格分区排序」语义（有序需 key 分组）；重紫山云内集成，跨云弱。

**Dataflow** —— 托管 Flink/Beam 流处理：写 Beam 代码跑在托管集群，自动扩缩容、Exactly-once，常与 Pub/Sub 组实时链路。

## 五、阿里云：MNS / 云 RocketMQ / EventBridge / 云 Kafka

| 服务 | 定位 | 关键点 |
|------|------|--------|
| MNS | 简单队列+主题 | 轻量，标准队列/FIFO，入门友好 |
| 云 RocketMQ | 开源 RocketMQ 托管 | 事务/延迟/顺序消息全兼容，迁移无痛（国内业务首选） |
| 云 Kafka | 开源 Kafka 托管 | 兼容 Kafka 协议，日志/管道/可回放 |
| 云 EventBridge | 事件总线 | 云内事件驱动 + 定时 + 规则路由，同 AWS EventBridge 心智 |
| 日志服务 SLS | 日志采集→消费 | 常作「日志→SLS→消费/告警」链路 |

**选型关注点**：国内业务、要事务消息 → **云 RocketMQ**（与自建开源 API 兼容，迁移成本最低）；要流式高吞吐 → 云 Kafka；事件驱动 → EventBridge。配套：消息轨迹、消息查询、延迟消息均开箱即用。

---

## 六、腾讯云：CMQ / CKafka / TDMQ / EventBridge

- **CMQ**：兼容 RabbitMQ/HTTP 协议的队列，可靠、可视化管理；
- **CKafka**：Kafka 托管，高吞吐、与 COS/Ckafka 生态联动；
- **TDMQ**：腾讯自研消息平台，兼容 Pulsar/RocketMQ/CMQ 多协议（一个平台多协议）——多协议统一是亮点；
- **EventBridge**：云内事件总线 + 定时任务 + 集成。

---

## 七、选型速查（按需求选，不按品牌选）

| 需求 | 首选 | 备选 |
|------|------|------|
| 简单解耦削峰 | SQS / MNS | 云 RocketMQ（要事务时） |
| 事务消息/延迟消息 | 云 RocketMQ（阿里） | TDMQ (RocketMQ 兼容) |
| 一个事件通知多接收方 | SNS / 云 MNS 主题 | Pub/Sub |
| 云内事件驱动编排 | EventBridge / Event Grid / Eventarc | 自研事件中心 |
| 高吞吐流+回放 | Kinesis / Event Hubs / 云 Kafka | MSK |
| 需要 Kafka 全语义 | MSK / CKafka / 云 Kafka | Kinesis（语义不全） |
| 跨云/多云 | 协议兼容层（Kafka/S3 类开源标准） | 厂商专属 API |
