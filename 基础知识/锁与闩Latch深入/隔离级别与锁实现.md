# 隔离级别与锁实现

> 对应 Berenson et al. 1995, *A Critique of ANSI SQL Isolation Levels*（隔离级别形式化），以及 Silberschatz《Database System Concepts》第 16 章。

## 一、背景与挑战
SQL 定义 Read Uncommitted/Serializable 等等级，但 ANSI 定义存在歧义（Berenson 指出其不足）。各引擎用锁 + MVCC 组合实现不同级别，需在性能与正确性间取舍。

## 二、核心原理
- 读未提交：可读未提交（常仍用 MVCC 避免脏读实际多靠近 RC）。
- 读已提交：语句级快照/短锁，防脏读。
- 可重复读：事务级快照或范围锁防幻读（实现各异）。
- 串行化：SSI 或 2PL+范围锁。
锁实现：读锁/写锁 + 间隙锁（防插入幻行）。

## 三、形式化与数学基础
ANSI 现象：P0 脏写、P1 脏读、P2 不可重复读、P3 幻读。各级别禁止集合：
$$ RC: \neg P0,\neg P1;\quad RR: \neg P0..P3;\quad SER: \text{conflict serializable} $$
间隙锁保护范围：
$$ gap\_lock(a,b) \text{ 阻止在 }(a,b) \text{ 插入} $$

## 四、代码实现
```c
// 间隙锁防止幻读（仅示意）
void rr_insert_protect(Txn* t, Index* ix, Key lo, Key hi) {
    ix->gap_lock(t, lo, hi);   // 锁定范围，阻止并发插入
}
```

## 五、与其他技术对比
基于锁实现易保证严格但并发低；基于 MVCC 实现高并发但需 SSI 才真正串行。MySQL 用 GAP 锁，PostgreSQL 用 SSI。

## 六、常见误区
1) 认为 RR 一定防幻读——依实现而异（ANSI 漏洞）。
2) 混淆 RC 与 RR 的快照粒度。
3) 误以为 SER 永远最慢——SSI 接近 SI 性能。

## 九、演进与趋势
SSI 普及、可证明隔离级别、硬件时钟辅助串行化。

## 十、小结
隔离级别是“正确性 vs 并发”的旋钮；理解其真实语义（尤其 RR 与幻读）是避免并发 bug 的关键。
