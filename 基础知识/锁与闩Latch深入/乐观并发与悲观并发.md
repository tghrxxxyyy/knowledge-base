# 乐观并发与悲观并发

> 对应 Kleppmann《Designing Data-Intensive Applications》第 7 章（并发控制对比），以及 Garcia-Molina《Database Systems: The Complete Book》第 18 章。

## 一、背景与挑战
并发控制分两派：悲观（先加锁防冲突）与乐观（先操作、提交再校验）。选择取决于冲突率：低冲突下乐观更优，高冲突下悲观更稳。

## 二、核心原理
- 悲观（2PL/Lock）：事务开始即对数据加锁，冲突时阻塞或终止。
- 乐观（OCC）：分读（记录读集）、写（本地缓冲）、校验（提交时检查读集是否被别的事务改）三阶段，冲突则重做。MVCC 常被视为乐观变体（快照+提交校验）。

## 三、形式化与数学基础
设冲突概率 $p$。悲观阻塞代价：
$$ E_{pess} \propto p \cdot wait $$
乐观重做代价：
$$ E_{opt} \propto p \cdot redo\_cost + (1-p)\cdot 0 $$
当 $p$ 小，$E_{opt} \ll E_{pess}$；当 $p$ 大相反。

## 四、代码实现
```python
# 乐观并发校验（仅示意）
def validate(txn):
    for item in txn.read_set:
        if item.version != txn.snapshot_version[item]:
            return ABORT          # 读集被改，冲突
    return COMMIT
```

## 五、与其他技术对比
悲观实现简单、适合高冲突（如库存扣减）；乐观高吞吐、低冲突（如只读分析）；MVCC 是“乐观读、悲观写”的混合。

## 六、常见误区
1) 认为乐观永远高吞吐——高冲突下频繁重做。
2) 误以为乐观不需锁——写写仍需某种冲突处理。
3) 忽略校验阶段的开销。
