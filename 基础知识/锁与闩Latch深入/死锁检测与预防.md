# 死锁检测与预防

> 对应 Gray 1978（死锁与超时），以及 Silberschatz《Database System Concepts》第 16 章（deadlock handling）。

## 一、背景与挑战
2PL 下多个事务循环等待锁会死锁。需检测（等待图找环）或预防（破坏必要条件）来恢复。

## 二、核心原理
- 预防：一次申请全部锁、按固定顺序加锁、抢占（超时/优先级剥夺），以牺牲并发换无死锁。
- 检测：维护等待图（WFG），定期检测环；发现死锁则选牺牲者（最小代价/最年轻）回滚。
- 超时：等待超过阈值即中止，简单但可能误伤。

## 三、形式化与数学基础
等待图 $G=(T, E)$，边 $T_i \to T_j$ 表示 $T_i$ 等 $T_j$ 的锁。死锁 ⇔ $G$ 含环。牺牲者选择最小化：
$$ victim = \arg\min_{T} (cost(T)) $$
其中 $cost$ 含已工作时间、持有锁数、重启代价。

## 四、代码实现
```python
# 等待图环检测（仅示意）
def detect_deadlock(wfg):
    visited = set()
    def dfs(u, path):
        if u in path: return path[path.index(u):]  # 发现环
        for v in wfg[u]:
            r = dfs(v, path + [u])
            if r: return r
        return None
    for t in wfg:
        cyc = dfs(t, [])
        if cyc: return cyc
    return None
```

## 五、与其他技术对比
预防实现简单但并发低；检测并发高但需周期扫描与选牺牲者；超时最轻量但可能误伤。工程多用检测+超时结合。

## 六、常见误区
1) 认为 2PL 防死锁——它不防。
2) 牺牲者选错导致饥饿/反复回滚。
3) 忽略热点的级联死锁。
