# 锁粒度与意向锁

> 对应 Garcia-Molina《Database Systems: The Complete Book》第 18 章（lock granularity / intention locks），以及 Silberschatz《Database System Concepts》第 16 章。

## 一、背景与挑战
锁粒度越细（行级）并发高但管理开销大；越粗（表级）开销小但并发低。意向锁（Intention Lock）在不遍历细粒度锁的前提下，快速表明“将在更细粒度加锁”的意图。

## 二、核心原理
意向锁加在粗粒度（如表/页）上，声明其子节点将加某种锁：IS（意向共享）、IX（意向排他）、SIX（共享+意向排他）。申请行级 S/X 前须先获表级 IS/IX。相容矩阵保证不冲突地共存。

## 三、形式化与数学基础
锁层级 $H$（库→表→页→行）。申请行锁 $L$ 前：
$$ must\_hold(parent, IX \text{ or } IS) $$
相容性（部分）：
$$ C(IX, IS)=1,\ C(IX, S)=0,\ C(SIX, IX)=0 $$
意向锁使表级快速冲突检测复杂度从 $O(children)$ 降为 $O(1)$。

## 四、代码实现
```c
// 意向锁：先表级 IX 再行级 X（仅示意）
void lock_row(Table* t, Row* r, Txn* tx) {
    lock_mgr->acquire(t, IX, tx);     // 表级意向排他
    lock_mgr->acquire(r, X, tx);      // 行级排他
}
```

## 五、与其他技术对比
无意向锁时粗粒度需枚举子锁，开销大；意向锁用“声明意图”以常数代价完成冲突预判。行锁并发高但内存多；页锁折中。

## 六、常见误区
1) 认为意向锁会阻塞普通读——它只与表级 S/X 冲突。
2) 混淆 IX 与 X——IX 不阻止行级 S。
3) 误以为粒度越细越好——锁管理开销上升。
