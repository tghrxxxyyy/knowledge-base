# Web 安全

## 〇、本体介绍

**Web 安全**：保护 Web 应用免受恶意利用，覆盖**注入、跨站、越权、数据泄露、身份伪造**等。与「认证授权 JWT/OAuth2」（见 中间件/认证授权JWT-OAuth2.md）互补——那篇讲「你是谁、能进」，本篇讲「进来了怎么防被攻击」。

**核心威胁模型**：一个 Web 系统要防——**输入不可信**（用户/第三方都是敌）、**输出要转义**、**权限要校验**、**密钥要管好**。

**常见大类（OWASP Top 10 脉络）**：注入、 Broken Access Control（越权）、XSS、CSRF、SSRF、敏感数据泄露、安全配置错误、身份伪造、日志监控不足、SSRF。

---

## 一、注入类（Injection）

- **SQL 注入**：把恶意 SQL 拼进查询。`' OR '1'='1` 绕过、联合查询拖库、堆叠注入。
  - **防御**：**预编译/参数化查询（PreparedStatement）** 是第一防线；加白名单校验、最小权限库账号、ORM 防拼接、WAF。
- **命令注入**：`Runtime.exec` / `os.system` 拼用户输入执行系统命令。防御：避免调 shell、白名单、转义。
- **XXE（XML 外部实体）**：解析不可信 XML 时外部实体读本地文件/SSRF。防御：禁用 DTD/外部实体。
- **表达式注入（SpEL/OGNL）**：模板/规则引擎拼接用户输入致 RCE。防御：不把用户输入当代码执行。

---

## 二、XSS（跨站脚本）

- **原理**：把恶意脚本注入页面，其他用户浏览时执行，盗 Cookie / 钓鱼 / 蠕虫。
- **三类**：
  - 存储型（存库，如评论）——危害最大。
  - 反射型（URL 参数反射到页面）。
  - DOM 型（前端 JS 操作 DOM 触发，不经过服务端）。
- **防御**：**输出编码/转义**（HTML/JS/URL 上下文不同转义不同）、**CSP（内容安全策略）** 限制脚本来源、HttpOnly Cookie（防 JS 读）、输入校验、`X-XSS-Protection`。

---

## 三、CSRF（跨站请求伪造）

- **原理**：受害者已登录，攻击者诱导其浏览器向目标站发**非本意请求**（如转账），借登录态执行。
- **与 XSS 区别**：XSS 利用信任用户、在站点内执行脚本；CSRF 利用信任的**浏览器会话**、发跨站请求。
- **防御**：**CSRF Token**（请求带服务端签发的一次性 token）、**SameSite Cookie**（Strict/Lax 限制跨站带 cookie）、校验 Referer/Origin、重要操作二次确认/验证码。

---

## 四、SSRF（服务端请求伪造）

- **原理**：服务端按用户输入的 URL 去请求内部资源，攻击者让其访问**内网/元数据**（如 `http://169.254.169.254` 云元数据拿临时凭证）。
- **防御**：**白名单协议+域名/IP**、禁止内网地址、不走用户提供的 URL 直连、用 URL 解析+DNS 重校验、网络层隔离。

---

## 五、越权（Broken Access Control）

- **水平越权**：A 用户访问 B 用户的数据（如改 URL 的 `id`）。防御：**服务端校验资源归属**（当前用户是否拥有该对象）。
- **垂直越权**：普通用户调管理员接口。防御：**基于角色的权限校验（RBAC）**，每个接口验权限。
- 口诀：**任何「我能不能看这个 id」都要服务端判，不能只靠前端隐藏按钮**。

---

## 六、认证与会话安全

- **密码存储**：**加盐哈希（bcrypt/scrypt/Argon2）**，绝不明文/弱哈希（MD5/SHA 直接存）。
- **会话**：HttpOnly + Secure + SameSite Cookie；JWT 设短过期 + 黑名单/轮换（见 JWT/OAuth2）。
- **暴力破解**：限流、验证码、锁定、MFA。
- **敏感数据**：传输 TLS、存储加密、日志脱敏。

---

## 七、其他高频

- **点击劫持（Clickjacking）**：透明 iframe 覆盖诱导点击。`X-Frame-Options` / CSP `frame-ancestors` 防。
- **CORS 配置错误**：`Access-Control-Allow-Origin: *` 配合凭据泄露；应显式白名单。
- **文件上传漏洞**：传 webshell、覆盖、XSS。防御：类型白名单、重命名、存非执行目录、杀毒。
- **依赖/供应链**：漏洞库（Log4j 等），用 SCA 扫描、及时升级。

---

## 八、安全开发生命周期（SDL）

- 威胁建模（STRIDE）→ 安全编码 → 静态/动态扫描（SAST/DAST）→ 依赖扫描 → 渗透测试 → 监控告警。
- 关联：CI/CD 的 DevSecOps（见 CI-CD/13）把安全左移进流水线。

---

## 九、与其他板块的关系

- **中间件 / 认证授权 JWT-OAuth2**：身份与令牌安全。
- **中间件 / API 网关**：网关层做统一鉴权、WAF、限流，是安全边界。
- **CI/CD / DevSecOps**：把安全扫描自动化进流水线。
- **场景设计 / 稳定性**：限流/防刷也是安全（防滥用）的一部分。

## 十、速查表（防御清单）

| 威胁 | 关键防御 |
|------|---------|
| SQL 注入 | 参数化查询、白名单、最小权限 |
| XSS | 输出转义、CSP、HttpOnly |
| CSRF | Token、SameSite、Referer |
| SSRF | 协议/域名白名单、禁内网 |
| 越权 | 服务端校验归属、RBAC |

## 面试高频问题（20+ 条）

1. **OWASP Top 10 有哪些？** 注入、越权、XSS、CSRF/SSRF、敏感泄露、配置错、身份伪造等。
2. **SQL 注入原理与防御？** 拼接恶意 SQL；用 PreparedStatement 参数化、白名单、最小权限。
3. **为什么参数化查询防注入？** 语句与数据分离，输入不会被当 SQL 执行。
4. **XSS 三类？** 存储/反射/DOM；危害最大是存储型。
5. **XSS 防御？** 上下文转义、CSP、HttpOnly、输入校验。
6. **CSP 是什么？** 内容安全策略，限制可加载脚本/资源来源，缓解 XSS。
7. **CSRF 原理？** 借受害者登录态发跨站非本意请求。
8. **CSRF 防御？** Token、SameSite Cookie、Referer/Origin 校验、二次确认。
9. **CSRF 和 XSS 区别？** XSS 在站点内执行脚本盗信息；CSRF 借会话发跨站请求。
10. **SameSite 的 Strict/Lax？** Strict 完全不带跨站 Cookie；Lax 允许安全方法跨站带（默认）。
11. **SSRF 是什么、危害？** 服务端代发请求打内网/元数据；可拿云凭证。
12. **SSRF 防御？** 协议域名白名单、禁内网 IP、DNS 重校验、网络隔离。
13. **水平 vs 垂直越权？** 水平：访问他人同权限数据；垂直：普通用户调管理员接口。
14. **怎么防越权？** 服务端校验资源归属（RBAC/ABAC），不只靠前端隐藏。
15. **密码怎么安全存储？** 加盐哈希 bcrypt/scrypt/Argon2，不存明文/弱哈希。
16. **MD5/SHA 直接存密码为什么不行？** 快、易被彩虹表/暴力破解；需慢哈希+盐。
17. **HttpOnly Cookie 作用？** 防 JS 读 Cookie，缓解 XSS 盗 Session。
18. **点击劫持怎么防？** X-Frame-Options / CSP frame-ancestors 禁止被 iframe。
19. **CORS 常见错误？** `*` 配凭据泄露；应显式白名单 origin。
20. **文件上传漏洞与防御？** 传 webshell；类型白名单、重命名、非执行目录。
21. **XXE 是什么？** 解析不可信 XML 外部实体读文件/SSRF；禁用 DTD 防。
22. **命令注入怎么防？** 避免 shell 调用、白名单、转义。
23. **什么是 SDL / 安全左移？** 在需求/编码/构建阶段就做安全，而非上线后。
24. **依赖漏洞（如 Log4j）怎么防？** SCA 扫描、及时升级、WAF 规则临时缓解。
25. **JWT 安全风险？** 算法混淆（none/RS→HS）、密钥弱、过期过长；见 JWT/OAuth2 文档。
