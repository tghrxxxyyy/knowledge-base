# 语法树构建

> 对应 Crafting Interpreters 与 Appel 抽象语法树 (AST) 章。

## 一、背景与挑战
解析产出 AST 而非具体语法树 (CST)：去掉冗余括号、分隔符，保留结构语义。挑战：节点类型设计、位置信息保留（用于错误）、与后续语义分析接口。

## 二、核心原理
每个语言构造对应节点类：`Bin(op,left,right)`、`Unary`、`Call(callee,args)`、`If(cond,then,els)` 等。解析时构造并返回节点，组合成树。

## 三、形式化 / 数学基础
AST 是 CST 的"去标点"商：把满足结合律/优先级的中间节点折叠；对应属性文法中对每个产生式附构造动作（语义动作）。

## 四、代码实现
```python
class Bin:
    def __init__(self, op, left, right):
        self.op, self.left, self.right = op, left, right
class Lit:
    def __init__(self, value): self.value = value
# 解析 expr 时返回 Bin("+", Lit(1), Lit(2)) 之类节点
```

## 五、与其他技术对比
- CST（语法树）：含所有 token，利于格式化/重排（IDE）。
- AST：语义结构，供类型检查/代码生成。
- 括号 AST：Crafting Interpreters 用 precedence 直接建 AST。

## 六、常见误区
1. 在 AST 里保留无语义的括号节点（应折叠）。
2. 丢失源码位置导致报错无行列。
3. 把语义检查提前塞进构造（应后置）。

## 九、演进与趋势
强类型 AST（Rust 枚举）、可序列化 AST（protobuf）、以及语法树到语义模型的自动派生。

## 十、小结
语法树是解析的目标产物：用节点层次表达结构、用类型表达语义，是后续所有编译阶段共享的数据结构。
