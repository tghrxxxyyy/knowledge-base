# 解析器生成器

> 对应 yacc/bison、ANTLR 与 龙书。

## 一、背景与挑战
解析器生成器从文法规格自动产出 parser。挑战：文法冲突报告、优先级/结合性声明、从 LALR 到 ALL(*) 的能力差异、与词法器协作。

## 二、核心原理
输入文法 → 构造项集/状态表 → 输出 `action`/`goto` 表（LR）或递归下降代码（ANTLR）。用户通过 `%left`/`%prec` 消解冲突。

## 三、形式化 / 数学基础
bison 默认 LALR(1)：以 LR(1) 项集合并相同核心的状态，省表空间但可能引入伪冲突。ANTLR 用 ALL(*) 自适应 LL(*)，避免左因子但支持语义谓词。

## 四、代码实现
```yacc
%left '+'
%left '*'
%%
expr: expr '+' expr
    | expr '*' expr
    | '(' expr ')'
    | ID
    ;
```

## 五、与其他技术对比
- yacc/bison：LALR，表小、成熟；冲突需处理。
- ANTLR：LL(*)/ALL(*)，好错误、好文法表达；生成 Java/Python/C#。
- 手写递归下降：最灵活但无自动冲突检测。

## 六、常见误区
1. 忽略生成器的冲突警告（shift/reduce 默认移进）。
2. 优先级声明顺序错导致结合性反了。
3. 词法器与解析器 token 编号不一致。

## 九、演进与趋势
语法与语义动作分离、增量生成、以及把 parser 生成并入构建系统的缓存化。

## 十、小结
解析器生成器把文法工程化：理解冲突、优先级与状态表，是高效构建稳健 parser 的关键。
