# 错误恢复

> 对应 龙书 4.3 / Appel 第 3 章错误恢复。

## 一、背景与挑战
真实编译器不应在首个语法错误处崩溃，而应报告并继续以发现更多错误。挑战：误报/漏报、不陷入无限循环、给出有用位置信息。

## 二、核心原理
- 恐慌模式 (panic mode)：丢弃 token 直到同步集（如语句结束符 `;`/`}`）再恢复。
- 短语层恢复：在文法嵌 `error` 产生式（yacc 的 `error`）。
- 错误产生式：显式列出常见错误形态。

## 三、形式化 / 数学基础
同步集 $S_A = FOLLOW(A)\cup\{\text{stmt-end}\}$。当 `peek() not in expected` 且不在同步集，跳 token 至 `peek() in sync_set` 再弹出状态栈到可接收该符。

## 四、代码实现
```python
def parse_stmt():
    try:
        return parse_real_stmt()
    except ParseError:
        sync_to({";","}"})
        return ErrorStmt(last_pos)
def sync_to(tokens):
    while peek().kind not in tokens:
        next()  # 恐慌模式丢弃
```

## 五、与其他技术对比
- 恐慌模式：实现简单、不会死循环，但跳过多。
- 短语层：恢复更精准，需手工标注。
- 错误产生式：最友好但文法膨胀。

## 六、常见误区
1. 恢复后状态栈未回退导致持续报错。
2. 恐慌模式丢弃不够致无限循环。
3. 一次性抛出中断整文件解析。

## 十、小结
错误恢复让编译器"批量报错"而非一错即崩；恐慌模式最简单稳健，短语层最精准，同步集是共同基石。
