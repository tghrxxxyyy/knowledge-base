# 上下文无关文法

> 对应 龙书 第 4 章 与 Appel《Modern Compiler Implementation》。

## 一、背景与挑战
正则语言不足以表达嵌套/递归结构（如括号配对、表达式）。上下文无关文法 (CFG) 用产生式描述递归结构，是编程语言的语法骨架。挑战：二义性、左递归、与 parser 实现方式的对应。

## 二、核心原理
CFG $G=(V,T,P,S)$，非终结符 $V$、终结符 $T$、产生式 $P: A\to\alpha$、开始符 $S$。推导 $A\Rightarrow\alpha$ 一步替换。语言 $L(G)=\{w\in T^*\mid S\overset{*}{\Rightarrow}w\}$。

## 三、形式化 / 数学基础
产生式示例（算术表达式）：
$E\to E+T\mid T$
$T\to T*F\mid F$
$F\to (E)\mid \mathtt{id}$
该文法无二义；若写成 $E\to E+E\mid E*E\mid (E)\mid \mathtt{id}$ 则有二义（优先级未定）。

## 四、代码实现
```python
grammar = {
    "E": [["E","+","T"], ["T"]],
    "T": [["T","*","F"], ["F"]],
    "F": [["(","E",")"], ["id"]],
}
# 非终结符到产生式列表的映射即 CFG 的数据结构
```

## 五、与其他技术对比
- 正则文法（RG）⊂ CFG：只能线性结构，无递归。
- CFG ⊂ CSG（上下文相关）：CFG 不能表达"声明先于使用"的语义约束（需语义分析）。
- PEG：有 Ordered Choice，天然无二义但非 CFG 等价。

## 六、常见误区
1. 认为 CFG 能检查变量声明（不能，需符号表）。
2. 左递归文法直接给递归下降会死循环。
3. 二义文法靠 parser 隐式消解优先级易错。

## 九、演进与趋势
算法化文法（Parsing Expression Grammar）、自适应文法、以及把语法直接嵌语言的 combinator 库（Parsec）。

## 十、小结
CFG 是编程语言语法的标准模型：产生式描述递归结构，parser 把 Token 流还原成这棵树；二义性与左递归是工程实现的两大坑。
