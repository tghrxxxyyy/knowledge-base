# 递归下降解析

> 对应 Crafting Interpreters 与 Appel 第 3 章。

## 一、背景与挑战
递归下降是手写 LL 解析器的常用技术：每个非终结符一个函数，函数调用对应产生式展开。挑战：只能处理 LL(1)（无左递归、无二义）；需消除左递归与提取左公因子。

## 二、核心原理
对 $A\to\alpha_1\mid\alpha_2\mid\dots$，函数 `parseA` 用向前看符 (lookahead) 选择分支；终结符用 `expect(tok)` 匹配并消费。

## 三、形式化 / 数学基础
LL(1) 判定：对每个非终结符 $A$ 的产生式 $i,j$，$FIRST(\alpha_i)\cap FIRST(\alpha_j)=\varnothing$，且若 $\alpha_i\Rightarrow^*\epsilon$ 则 $FIRST(\alpha_j)\cap FOLLOW(A)=\varnothing$。满足即 LL(1)。

## 四、代码实现
```python
def parse_expr():
    node = parse_term()
    while peek() in ("+","-"):
        op = next().kind
        node = Bin(op, node, parse_term())
    return node

def parse_term():
    node = parse_factor()
    while peek() in ("*","/"):
        op = next().kind
        node = Bin(op, node, parse_factor())
    return node
```

## 五、与其他技术对比
- 递归下降：手写直观、错误友好；但仅 LL(1) 且需文法改造。
- LL/LR 表驱动：自动、覆盖更广文法族。
- PEG 递归下降：带 Ordered Choice，左递归需包支持。

## 六、常见误区
1. 未消除左递归导致无限递归。
2. 用 `==` 比较 Token 而非类型。
3. 在回溯式实现中副作用（如声明）重复执行。

## 十、小结
递归下降把文法"翻译"为互相调用的函数；理解 FIRST/FOLLOW 与左递归消除是写正确 parser 的关键。
