# 中断异常进入内核路径

> 对应 Bovet & Cesati《Understanding the Linux Kernel》第 4 章 Exception Handling 与 Bryant & O'Hallaron《CSAPP》第 8 章 Exceptional Control Flow；并参考 Intel《SDM》Volume 3 第 6 章 Interrupt and Exception Handling 与内核文档 `Documentation/x86/entry_64.rst`。

## 一、背景与挑战

用户态程序运行在 CPL=3（Ring 3），一旦要执行特权操作、响应外部设备，或在执行指令时遇到非法状态，都必须把控制权移交给内核（CPL=0）。

x86 把这种「从低特权级陷入高特权级」的统一机制称为 gate（门）。门分为中断门、陷阱门与任务门。

系统调用、缺页、除零、设备 IRQ 都共用这套硬件入口，但三者在「是否关中断」「是否压错误码」「返回指令」上差异显著。

理解这条统一路径是理解整个控制权转移的基础：任何一处寄存器保存不完整，或栈切换错误，都会在返回用户态时崩溃。

任何一处安全检查遗漏，都可能成为权限提升漏洞。尤其要注意 #DF、#MC、NMI 这类不可嵌套异常对独立栈（IST）的硬性要求，处理不当会触发三重故障（triple fault）重启。

## 二、核心原理

x86-64 用 IDT（Interrupt Descriptor Table）保存 256 个门描述符，每个门含段选择子、偏移、DPL 与类型。

硬件响应时：先按向量号查 IDT；比较当前 CPL 与门 DPL（中断/陷阱门 DPL 通常为 0，但 `syscall`/`sysenter` 走 MSR 而非 IDT）。

若跨特权级，从 TSS 取出目标特权级的内核栈（或 IST 栈），硬件自动压入 `ss`、`rsp`、`rflags`、`cs`、`rip`（部分异常还会先压 `error_code`）。

清 IF（中断门）或保留 IF（陷阱门），再跳门偏移。

内核汇编桩（如 `entry_SYSCALL_64`、`asm_exc_page_fault`）随后 `swapgs` 切换 per-CPU 基址，把用户寄存器 `SAVE_ALL` 进 `pt_regs`，再调用 C 处理函数（`do_syscall_64`、`exc_page_fault`）。

异常按行为分三类：fault（可修复，返回原指令重执行，如 #PF）、trap（返回下一条，如 `#BP`）、abort（不可恢复，如 #MC）。

## 三、形式化与数学基础

进入保存的上下文集合：

$$R = \{rip,\ cs,\ rflags,\ rsp,\ ss,\ error\_code?\}\ \cup\ GP\_regs$$

特权级切换：

$$CPL_{user}=3 \rightarrow CPL_{kernel}=0$$

错误码仅对特定异常（#PF、#DF、#TS、#GP 等）存在，对中断与 `syscall` 不存在，因此返回前内核要保证栈对齐一致。

嵌套深度受内核栈与 IST 栈容量约束，若 $depth > S_{stack}/frame$ 即栈溢出并触发 #DF 二次异常。

对 NMI，硬件强制屏蔽后续 NMI 直到 `IRET` 执行，防止重入。

## 四、代码实现

```asm
# x86-64 系统调用快速入口（arch/x86/entry/entry_64.S 简化）
entry_SYSCALL_64:
    swapgs                      # 用 IA32_LSTAR 上下文切换 per-CPU 内核栈基址
    movq    %rsp, %gs:pcpu_old_rsp
    movq    %gs:pcpu_kernel_rsp, %rsp
    pushq   $__USER_DS         # 预留 ss 槽
    pushq   pcpu_old_rsp       # 用户 rsp
    SAVE_ALL                   # 保存通用寄存器进 pt_regs
    movq    %rsp, %rdi
    call    do_syscall_64      # C 处理函数，返回值在 rax
    jmp     restore_regs_and_return_to_usermode
```

对缺页这类带错误码的异常，硬件先压 `error_code`，桩据此跳到 `exc_page_fault` 并传入 `struct pt_regs *` 与错误码，错误码的比特位编码了访问类型（读/写/用户/写时复制等）。

异常向量经 `idtentry` 宏统一包裹，区分 `error_code` 有无。

## 五、与其他技术对比

| 维度 | 硬件中断 | CPU 异常 | 系统调用 |
| --- | --- | --- | --- |
| 触发来源 | 外部设备/APIC | 当前指令 | 主动 `syscall` |
| 同步性 | 异步 | 同步 | 同步 |
| 是否压错误码 | 否 | 部分 | 否 |
| 进入是否关 IF | 是（中断门） | 否（陷阱门） | 由 MSR 掩码定 |
| 典型处理 | `do_IRQ` | `exc_*` | `do_syscall_64` |

相较用户态回调，内核入口由硬件强制、不可伪造，且强制切换栈与特权级；任务门在现代 Linux 中已基本不用，统一走中断/陷阱门。

NMI 与 #MC 使用 IST 独立栈，与常规异常隔离。

## 六、常见误区

1. 误以为 `syscall` 与 `int $0x80` 路径相同：`syscall` 走 MSR_LSTAR 不查 IDT，无错误码，`sysret` 返回。
2. 误以为进入内核会保存全部状态：硬件只压 5 个机器字，通用寄存器由软件 `SAVE_ALL` 补齐。
3. 误以为用户可 `cli/sti`：这些是特权指令，用户态执行触发 #GP。
4. 误以为 IST 栈是性能优化：它是为 #DF、#MC、NMI 等不可嵌套异常准备的安全栈，避免栈耗尽导致三重故障。
5. 误以为所有异常都返回原指令：只有 fault 重执行原指令，trap 返回下一条，abort 不返回。
6. 误以为中断可随时被新中断打断：关中断窗口（IF 清）内不可被可屏蔽中断打断。

## 七、与开源书·权威来源对应

- Bovet & Cesati 第 4 章详述 IDT、门描述符、异常分类（fault/trap/abort）与 `entry_64` 流程。
- CSAPP 8.1 把中断/异常/系统调用统一归类为「异常控制流（exceptional control flow）」。
- Intel SDM Vol.3 §6 给出错误码语义、IST 与 TSS 切换的硬件精确描述，是寄存器级实现的权威依据。
- 内核 `entry_64.rst` 说明 `SWAPGS` 配对、硬件帧布局与 `idtentry` 宏的封装。

## 八、面试题

1. 中断、异常、系统调用进入内核的异同？要点：均跨特权级，但异步/同步/主动之分，栈、IF、错误码处理不同。
2. `swapgs` 的作用与配对要求？要点：建立内核 gs 基址，返回前必须再 `swapgs`，否则用户态能复用内核基址。
3. 为什么部分异常带错误码而中断不带？要点：错误码由当前执行上下文产生，外部中断无对应指令上下文。
4. #PF 是 fault 还是 trap？为何必须返回原指令？要点：fault，修正映射后需重执行触发指令。

## 九、演进与趋势

- KPTI（Meltdown 缓解）使进入/返回都需切换用户/内核页表，增加 `CR3` 写与 TLB 刷新开销。
- `syscall`/`sysret` 取代 `int $0x80` 与 `sysenter` 成为主路径；SPEC_CTL 在入口处写 IBRS 缓解预测执行侧信道。
- FRED（Flexible Return and Event Delivery）在新一代 Intel CPU 上统一异常/中断/系统调用的入口与返回框架，显著简化 `entry_64.S`。

## 十、小结

中断、异常、系统调用共享 x86 的 gate 硬件路径，但语义各异：异步通知、同步故障、主动请求。

理解 IDT、错误码、IST 与 `pt_regs` 的保存/恢复，是把握「控制权从用户移交内核再无痕返回」的统一基础，也是内核安全边界正确实现的基石。
