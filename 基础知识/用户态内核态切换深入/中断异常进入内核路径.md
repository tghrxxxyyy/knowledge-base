# 中断异常进入内核路径

> 对应 Bovet & Cesati《Understanding the Linux Kernel》第 4 章与 Bryant & O'Hallaron《CSAPP》第 8 章。

## 一、背景与挑战
硬件中断、CPU 异常、软件 syscall 都需进入内核执行处理程序。它们共用"陷入（trap）"机制但入口、权限与返回语义不同，理解统一路径有助于把握控制权转移。

## 二、核心原理
三者经 IDT 门描述符进入内核：中断门清 IF（关中断）并切换栈到内核栈；陷阱门（syscall/int3）不关中断；异常门用于故障。进入时硬件压错误码与返回地址，内核 `entry_SYSCALL_64` 等汇编桩保存寄存器、切换到内核栈、调用 C 处理。

## 三、形式化与数学基础
进入保存上下文集合 $R = \{rip, cs, rflags, rsp, ss\} \cup GP\_regs$。返回：
$$sysret/iret \Rightarrow restore(R)$$
中断额外 $IF$ 状态由门类型决定。优先级切换：$CPL_{user}=3 \to CPL_{kernel}=0$。

## 四、代码实现
```asm
// 内核 entry 简化：保存用户寄存器到 pt_regs
entry_SYSCALL_64:
    swapgs                  // 切换 per-cpu 内核栈
    mov %rsp, %gs:cpu_current
    push regs...
    call do_syscall_64
    iretq                  // 返回用户态
```

## 五、与其他技术对比
中断异步、异常同步、syscall 主动；三者入口不同但都走内核栈与 IDT。相较用户态回调，内核入口由硬件强制、不可伪造。

## 六、常见误区
误以为 syscall 与中断路径完全相同：权限/栈处理细节不同。误以为进入内核不保存全部寄存器：必须保存以正确返回。误以为 cli/sti 用户可用：特权指令。

## 七、与开源书/权威来源对应
Bovet & Cesati 第 4 章 IDT 与入口；CSAPP 8.1 异常/中断/系统调用分类。

## 八、面试题
问：中断、异常、系统调用进入内核的异同？答：均经 IDT，但异步/同步/主动，栈与 IF 处理不同。问：swapgs 作用？

## 九、演进与趋势
x86-64 用 `syscall`/`sysret` 精简路径；KPTI 缓解 Meltdown 需切换用户/内核页表，增加开销。

## 十、小结
中断/异常/syscall 共享陷入硬件路径但语义各异，是控制权从用户移交内核的统一基础。
