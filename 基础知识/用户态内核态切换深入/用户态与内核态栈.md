# 用户态与内核态栈

> 对应 Bovet & Cesati《Understanding the Linux Kernel》第 3 章与 Bryant & O'Hallaron《CSAPP》第 8 章。

## 一、背景与挑战
用户态与内核态各有独立栈：内核栈小（通常 8-16 KiB）且每线程独立，不能借用用户栈（用户内存不可信）。陷入时必须正确切换到内核栈并保存用户现场。

## 二、核心原理
进程 `task_struct` 含指向内核栈的指针，内核栈顶存 `thread_info`/栈结构。进入内核（syscall/中断）由硬件与 `swapgs`/`mov` 切到内核栈，用户寄存器存入 `pt_regs`。返回时恢复并切回用户栈。用户栈大且可增长，内核栈固定小防溢出。

## 三、形式化与数学基础
栈切换：
$$on\_enter: ksp = task.thread.sp;\; save(user\_regs);$$
$$on\_exit: restore(user\_regs);\ usp = pt\_regs.sp$$
内核栈容量 $S_k$（如 16 KiB）须容纳调用深度与中断嵌套，超出即栈溢出 panic。

## 四、代码实现
```asm
// x86-64 进入：把用户栈指针保存到内核 pt_regs，切到内核栈
swapgs
mov %rsp, %gs:kernel_stack  // 暂存用户 rsp
mov %gs:kernel_stack_top, %rsp
sub $PT_REGS_SIZE, %rsp
// ... 后续 C 函数使用内核栈
```

## 五、与其他技术对比
内核栈独立且小、不可增长；用户栈大、可 mmap 扩展。相较协程栈，内核栈由调度器严格管理。中断栈（部分架构独立）防止深度嵌套耗尽进程内核栈。

## 六、常见误区
误以为内核能用用户栈：用户内存不可信且可能被换出。误以为内核栈可无限大：固定小，深递归易溢出。误以为栈切换只发生在进程切换：陷入即切换。

## 七、与开源书/权威来源对应
Bovet & Cesati 第 3 章进程/内核栈；CSAPP 8.1 用户/内核上下文。

## 八、面试题
问：为什么内核不能共用用户栈？答：用户内存不可信、可能被恶意修改或换出。问：内核栈多大？

## 九、演进与趋势
独立中断栈、virtio 栈减少嵌套风险；THP/guard 页防栈溢出；KASAN 检测内核栈越界。

## 十、小结
用户/内核双栈隔离保证特权代码不依赖不可信用户内存，是特权级安全的根基。
