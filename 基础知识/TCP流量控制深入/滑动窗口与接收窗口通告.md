# 滑动窗口与接收窗口通告

> 对应 RFC 793 (TCP) 与 Kurose & Ross《Computer Networking》第3章。

## 一、背景与挑战
发送方若一次性灌满网络会造成接收方缓冲溢出与中间队列丢包。TCP 流量控制的目标正是让发送速率匹配接收方的处理能力，而非匹配网络带宽。其核心机制是接收窗口 rwnd 的通告与滑动。

## 二、核心原理
接收方在每个 ACK 中通过窗口字段通告当前可接收字节数 rwnd = 接收缓冲 - 已收未读。发送方维持发送窗口 $= \min(cwnd, rwnd)$，其中 rwnd 保证不压垮接收方。窗口随数据确认向右滑动，已确认部分释放，可发送前沿推进。

## 三、形式化与数学基础
发送窗口上界为：
$$ W = \min(cwnd, rwnd) $$
接收窗口计算：
$$ rwnd = RcvBuffer - (LastByteRcvd - LastByteRead) $$
当 $rwnd = 0$ 时发送方停止发送应用数据，仅可发探测段。

## 四、代码实现
Linux 计算通告窗口在 `tcp_select_window`：
```c
new_window = tcp_space(sk);  // 即接收缓冲剩余
tp->rcv_wnd = new_window;
```
发送时受窗口约束：
```c
int snd_wnd = tp->snd_wnd;  // 来自对端通告
```

## 五、与其他技术对比
流量控制针对接收方能力，拥塞控制针对网络能力，二者相乘取小。UDP 无内置流控，需应用自行实现；QUIC 同样以流级与连接级流量控制防止接收方过载。

## 六、常见误区
误区一是把 rwnd 与 cwnd 混为一谈，前者保护接收方，后者保护网络。误区二是以为窗口为 0 后连接就死了，实际上发送方启零窗口探测恢复。

## 七、与开源书/权威来源对应
RFC 793 定义窗口字段；Kurose & Ross 第3章给出滑动窗口与 rwnd 公式；xiaolincoder/hello-http 图解窗口滑动过程。

## 八、面试题
问：接收窗口为 0 时发送方怎么办？答：停止发数据，启动零窗口探测定时器周期发送 1 字节探测段，待对端窗口重新打开。

## 九、演进与趋势
早期 16 位窗口最大 65535 字节不足以匹配高带宽链路，RFC 7323 的窗口缩放选项将窗口扩大到 1GB 量级，是高吞吐传输的前提。

## 十、小结
滑动窗口通过接收方 rwnd 通告限制发送量，保护接收缓冲不被淹没。它与拥塞窗口 cwnd 取小决定实际发送窗口，是 TCP 可靠传输的基石之一。
