# 红黑树

> 对应 CLRS《Introduction to Algorithms》第 13 章 Red-Black Trees；Sedgewick《Algorithms》左倾红黑树；Guibas & Sedgewick《A Dichromatic Framework for Balanced Trees》(1978)。

## 一、背景与挑战

普通二叉搜索树在有序输入下退化为链表，查找从 $O(\log n)$ 恶化到 $O(n)$。AVL 树以严格高度差约束解决了退化问题，但插入/删除的旋转次数偏多，写密集场景常数不友好。工程界需要一种**近似平衡**、修复代价小、且在最坏情况下仍有对数上界的结构——这正是红黑树（Red-Black Tree）的定位。

红黑树由 Guibas 与 Sedgewick 于 1978 年提出，后经 CLRS 系统化成为教科书标准。它通过给结点着色（红/黑）约束路径上的黑结点数，保证树高不超过 $2\log_2(n+1)$。与 AVL 相比，红黑树插入最多两次旋转、删除最多三次旋转，修复更「局部」，综合常数更优。因此它成为工业界事实标准：C++ `std::map`/`std::set`、Java `TreeMap`/`HashMap`（链表转红黑树）、Linux 内核调度器与 `vm_area_struct` 管理、Epoll 红黑树定时器等都以红黑树为底层。

在面试中，红黑树的考察点通常不是完整手写删除（那过于冗长），而是：五条性质、黑高与高度上界证明、插入修复的三种情形、与 AVL/跳表的取舍。理解红黑树也有助于理解 B 树（2-3-4 树的等价视角）。

## 二、核心原理

**五条性质（必须同时成立）：**

1. 每个结点非红即黑。
2. 根结点是黑色。
3. 每个叶子（NIL 哨兵）是黑色。
4. 红结点的两个孩子都是黑色（不存在相邻红结点）。
5. 对任一结点，其到所有后代叶子的路径包含相同数目的黑结点（**黑高**相同）。

其中性质 5 是平衡性的真正来源：它保证没有一条路径能比另一条长出太多——因为相邻红结点被性质 4 禁止，长路径上红结点最多与黑结点一样多。

**黑高 $bh(x)$。** 定义为从结点 $x$（不含 $x$ 自身）到其后代 NIL 叶子路径上的黑结点数。性质 5 等价于：以 $x$ 为根的子树中，任意两条到 NIL 的路径黑高相等，记作 $bh(x)$。

**插入修复。** 新结点先着**红色**（不破坏性质 5），然后处理与父结点同为红的冲突（破坏性质 4）。设当前结点为 $z$，叔叔为 $u$，祖父为 $g$：

- **情形 1：叔叔是红。** 把父与叔染黑、祖父染红，问题上移到祖父，继续循环。
- **情形 2：叔叔是黑，且 $z$ 是内侧孩子（之字形）。** 通过一次旋转把情形转为情形 3。
- **情形 3：叔叔是黑，且 $z$ 是外侧孩子（直线形）。** 对祖父旋转一次，并交换父与祖父的颜色，完成修复。

最坏情形 1 可上移 $O(\log n)$ 次，但旋转至多两次。最后把根染黑（性质 2）。

**删除修复。** 删除黑色结点会破坏黑高，引入「双重黑」概念向上冒泡：视兄弟颜色、兄弟孩子颜色分四种情形（LL/LR/RL/RR 类似），通过旋转与染色把双重黑消掉或转移到能被染黑的红结点上。实现复杂，但分支清晰，总旋转 $O(1)$。

**边界条件。** NIL 哨兵统一为黑色、可共用一个哨兵对象；根必须最终为黑；插入情形 1 中祖父可能是根，染红后循环结束再染黑；`parent` 指针必须始终正确，否则旋转会断链。

## 三、形式化与数学基础

**高度上界证明。** 对含 $n$ 个内部结点的红黑树，先证以 $x$ 为根的子树至少有 $2^{bh(x)} - 1$ 个内部结点（对高度归纳：$x$ 为 NIL 时 $bh=0$ 成立；否则两子树黑高均为 $bh(x)-1$，故 $n_x \ge 2(2^{bh(x)-1}-1)+1 = 2^{bh(x)}-1$）。

对根 $r$，$n \ge 2^{bh(r)} - 1$，即 $bh(r) \le \log_2(n+1)$。另一方面，由性质 4，根到叶子的路径长度 $h$ 满足「黑结点数 $\ge \lceil h/2 \rceil$」（红黑交替时红最多占一半），而黑结点数至少为 $bh(r)$，故

$$bh(r) \ge \frac{h}{2} \implies h \le 2\,bh(r) \le 2\log_2(n+1).$$

因此查找/插入/删除均为 $O(\log n)$。常数 2 是红黑树比 AVL（约 1.44）更「高」的原因，但换来更少旋转。

**与 2-3-4 树的等价。** 将红结点与父结点合并可视为 3-结点或 4-结点，红黑树对应一棵 2-3-4 B 树。性质 4 禁止相邻红结点，等价于 B 树结点分裂规则；性质 5 对应 B 树所有叶子同层。借助这一视角，删除的复杂分支可以理解为 B 树的「下溢借位/合并」。

**旋转保持性质。** 旋转只改指针、不改颜色时，性质 1、3 保持；配合染色策略可恢复性质 2、4、5。插入情形 3 的「父染黑、祖父染红」本质是把黑高差沿旋转轴重新分配。

## 四、代码实现

完整可运行的红黑树插入（含左旋/右旋、三种修复情形、中序校验）。为篇幅聚焦核心，删除沿用「递归 BST 删除 + 重新插入」的教学简化仅在注释说明；生产实现应完整处理双重黑。

```python
class RBNode:
    __slots__ = ("key", "red", "left", "right", "parent")

    def __init__(self, key, red=True):
        self.key = key
        self.red = red
        self.left = None
        self.right = None
        self.parent = None


# 共用黑色 NIL 哨兵
NIL = RBNode(None, red=False)


class RBTree:
    def __init__(self):
        self.root = NIL

    def left_rotate(self, x):
        y = x.right
        x.right = y.left
        if y.left is not NIL:
            y.left.parent = x
        y.parent = x.parent
        if x.parent is None:
            self.root = y
        elif x is x.parent.left:
            x.parent.left = y
        else:
            x.parent.right = y
        y.left = x
        x.parent = y

    def right_rotate(self, x):
        y = x.left
        x.left = y.right
        if y.right is not NIL:
            y.right.parent = x
        y.parent = x.parent
        if x.parent is None:
            self.root = y
        elif x is x.parent.right:
            x.parent.right = y
        else:
            x.parent.left = y
        y.right = x
        x.parent = y

    def insert(self, key):
        z = RBNode(key, red=True)
        z.left = z.right = NIL
        y = None
        x = self.root
        while x is not NIL:
            y = x
            x = x.left if key < x.key else x.right
        z.parent = y
        if y is None:
            self.root = z
        elif key < y.key:
            y.left = z
        else:
            y.right = z
        self._insert_fixup(z)
        self.root.red = False

    def _insert_fixup(self, z):
        # 仅当父为红时才冲突（性质 4）
        while z.parent is not None and z.parent.red:
            if z.parent is z.parent.parent.left:
                y = z.parent.parent.right          # 叔叔
                if y.red:                           # 情形 1：叔红
                    z.parent.red = False
                    y.red = False
                    z.parent.parent.red = True
                    z = z.parent.parent
                else:
                    if z is z.parent.right:         # 情形 2：之字
                        z = z.parent
                        self.left_rotate(z)
                    # 情形 3：直线
                    z.parent.red = False
                    z.parent.parent.red = True
                    self.right_rotate(z.parent.parent)
            else:
                y = z.parent.parent.left
                if y.red:
                    z.parent.red = False
                    y.red = False
                    z.parent.parent.red = True
                    z = z.parent.parent
                else:
                    if z is z.parent.left:
                        z = z.parent
                        self.right_rotate(z)
                    z.parent.red = False
                    z.parent.parent.red = True
                    self.left_rotate(z.parent.parent)
        self.root.red = False

    def inorder(self, node=None, out=None):
        if out is None:
            out = []
            node = self.root
        if node is not NIL:
            self.inorder(node.left, out)
            out.append(node.key)
            self.inorder(node.right, out)
        return out


if __name__ == "__main__":
    t = RBTree()
    for k in [7, 3, 18, 10, 22, 8, 11, 26, 2, 6]:
        t.insert(k)
    print(t.inorder())
    assert t.inorder() == sorted([7, 3, 18, 10, 22, 8, 11, 26, 2, 6])
    print("root red?", t.root.red)  # False
```

## 五、与其他技术对比

| 维度 | 红黑树 | AVL | 跳表 | B+ 树 |
|------|--------|-----|------|-------|
| 平衡性 | 近似（$h\le 2\log n$） | 严格（$h\le 1.44\log n$） | 概率期望 | 多路，极矮 |
| 插入旋转 | 最多 2 次 | 至多 1 次但可能更多层 | 无旋转 | 分裂/合并（磁盘） |
| 删除修复 | 最多 3 次旋转 | 可能 $O(\log n)$ 次 | 简单删指针 | 借位/合并 |
| 实现复杂度 | 高（删除分支多） | 中 | 低 | 中高 |
| 并发 | 需加锁/RCU | 需加锁 | 天然易无锁 | 页锁/latch |
| 典型应用 | TreeMap、内核、epoll | 读多写少字典 | Redis zset | 数据库索引 |

结论：通用有序容器选红黑树；查找极致且写少选 AVL；追求实现与并发简单选跳表；数据落盘选 B+ 树。

## 六、常见误区

1. **只染色不旋转（或反之）。** 情形 1 只需染色上移；情形 2/3 必须旋转 + 染色。漏旋转会让相邻红结点残留，中序对但黑高错，后续插入直接破坏性质 5。
2. **忘记共用黑色 NIL。** 若每个空指针当 `None` 又不统一判黑，性质 3/5 的推理会崩。生产代码用哨兵对象，教学代码也至少统一 `is not None` 与颜色语义。
3. **以为红黑树是「严格平衡」。** 它只是近似平衡，最坏高度是 AVL 的约 1.4 倍；不能用「左右子树高度差 ≤1」当不变量。
4. **删除后根可能变红、双重黑未消。** 删除修复结束必须 `root.red = False`，否则性质 2 被破坏。
5. **认为 HashMap 转红黑树是为了加速所有查询。** Java 8+ 在链表长度 ≥8 且表容量 ≥64 时树化，主要防哈希碰撞导致的 $O(n)$ 退化；小表仍以扩容为主。红黑树在此是**退化保护**，不是常规路径。

## 八、面试题

**1. 请陈述红黑树五条性质，并证明高度 $h \le 2\log_2(n+1)$。**
参考答案：五条性质见上文。证明：子树至少 $2^{bh}-1$ 个内部结点，故 $bh(root)\le\log_2(n+1)$；又路径上红结点不相邻，$h \le 2bh(root)$，合并即得。

**2. 红黑树插入时为什么新结点着红色？**
参考答案：着红不增加任何路径的黑结点数，不破坏性质 5，只可能破坏性质 4（与父同红），修复只需局部旋转/染色。若着黑则直接破坏性质 5，修复更难。

**3. 插入修复中「叔叔为红」与「叔叔为黑」处理有何本质区别？**
参考答案：叔为红时子树黑高均匀，染色把冲突上移祖父即可；叔为黑时黑高已偏，必须旋转把红结点「换边」并重新染色，把黑高差抹平。前者零旋转，后者一到两次旋转。

**4. 为什么 Java HashMap 链表长度到 8 就转红黑树？**
参考答案：哈希碰撞使链表查询退化 $O(n)$；红黑树把最坏降到 $O(\log n)$。阈值 8 是碰撞概率与树化开销的工程折中；容量小时优先扩容而非树化。

## 九、演进与趋势

- **左倾红黑树（LLRB）**：强制红结点左倾，把插入/删除情形压到更少分支，适合教学与函数式实现（Sedgewick、部分语言库）。
- **B 树等价与缓存友好变体**：部分现代索引（如 Bw-Tree、Bε 树）用「多路 + 局部缓冲」在 SSD/NVM 上替代传统红黑树；内存侧也有「无指针、隐式完全二叉树」的 B 树风格容器。
- **并发红黑树**：Linux 用 RCU + 自旋锁保护 `rbtree`；Java `ConcurrentSkipListMap` 则直接改用跳表，说明高并发下概率结构更受欢迎。
- **工程现状**：标准库 map/set 仍以红黑树为主；新系统在「有序 + 高并发」时越来越多选择跳表或 B 树，红黑树更多作为通用默认与教学重点。

## 十、小结

红黑树用「红黑着色 + 五条性质」把高度压在 $2\log_2(n+1)$ 内，插入/删除只需常数次旋转，是通用有序表的工程标准。理解黑高证明、插入三种修复情形，以及它与 AVL/跳表的取舍，比死记删除分支更重要。
