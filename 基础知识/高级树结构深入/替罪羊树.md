# 替罪羊树

> 对应 Galperin & Rivest《Scapegoat Trees》(1993)；《算法竞赛进阶指南》/《竞赛数学》平衡树章节中常用的无旋平衡树方案。

## 一、背景与挑战

AVL 与红黑树都要在插入/删除时做旋转维护，实现细节多、容易写错；Treap 依赖随机优先级，虽然均摊正确但带随机性，某些确定性场景不受欢迎。竞赛与教学中常需要一种**确定性、无旋转、好写好调**的平衡二叉搜索树——替罪羊树（Scapegoat Tree）正是为此而生。

替罪羊树的核心思想非常直白：插入/删除时**完全不旋转**，只沿路径更新子树大小；一旦发现某棵子树「太不平衡」，就找到失衡的罪魁祸首（替罪羊结点），把该子树**整棵拍平再重建为完全平衡的 BST**。重建是 $O(k)$ 的（$k$ 为子树大小），但因为触发不频繁，均摊下来每次操作仍是 $O(\log n)$。名字来自「替罪羊」：整个子树替一个失衡结点受罚、被重建。

它在工程上的位置：实现成本低、行为确定、常数可预测，适合教学演示「重量平衡」思想、竞赛中的平衡树模板、以及对旋转逻辑要求不高但要求正确性的内部字典。它也是理解 Treap、FHQ Treap、伸展树等「均摊/惰性平衡」结构的对照组。

## 二、核心原理

**α 权重平衡不变量。** 取定参数 $\alpha \in (0.5, 1)$（常用 0.7）。对每个非空结点 $x$，要求其左右子树的规模满足

$$\max(|x.left|, |x.right|) \le \alpha \cdot |x|,$$

其中 $|x|$ 是以 $x$ 为根的子树结点数。若某结点违反该不等式，则称其为**替罪羊**，需要重建以它为根的子树。

为什么 $\alpha$ 必须大于 0.5？若 $\alpha \le 0.5$，则两边子树都要严格小于父的一半，只有空树满足，会永远触发重建。$\alpha$ 越接近 1，树越松（更高）但重建越少；$\alpha$ 越接近 0.5，树越紧（更矮）但重建越频繁。经验上 0.7 是平衡点。

**插入流程。**

1. 按 BST 规则下行插入叶子，沿途递增各结点 `size`。
2. 回溯（或第二次上行）时检查路径上每个结点是否违反 α 平衡。
3. 一旦找到替罪羊 $x$，中序遍历拍平 $x$ 子树为有序数组，再从中间递归建完全平衡 BST，替换原子树。**只需重建第一次（最深）或指定的一次**，不必继续向上——重建后子树规模不变，祖先的 α 条件由均摊分析保证。

实现上常见两种触发判定：

- **重量法（严格）**：$\max(|L|,|R|) > \alpha |x|$。
- **高度法**：用深度阈值 $\log_{1/\alpha} n$ 作为最大允许深度，插入深度超过阈值则向上找替罪羊重建。高度法实现更短，竞赛常用。

**删除流程。** 有两种风格：

1. **直接删**：像普通 BST 删除（后继替换），沿途减 `size`，可能触发重建。
2. **惰性删**：打删除标记，结点数记为 $n_{active}$；当标记结点占比过高时整树重建一次，顺便清掉标记。惰性删除实现更简单，适合删除为主的题目。

**为什么正确。** BST 中序性质在重建时被刻意保持（拍平数组有序，中点为根）；α 平衡保证深度 $O(\log_{1/\alpha} n)$；重建均摊成本由「上次重建后至少插入了足够多结点」摊销。

**边界条件。** $\alpha=0.7$ 时 $\log_{1/0.7} n \approx 2.8\log_2 n$，高度界比 AVL 松但仍有对数；重建时必须正确计算子树大小；空树/单结点不重建；α 过小会陷入「插入即重建」。

## 三、形式化与数学基础

**高度界。** 设根子树规模为 $n$，则任一结点 $x$ 的子树规模沿路径至少以因子 $\alpha$ 收缩（替罪羊性质的逆否）：若孩子 $y$ 满足 $|y| > \alpha |x|$，则 $x$ 会失衡——因此在**平衡态**（刚重建完）每个孩子的规模 $\le \alpha |parent|$。深度 $d$ 处结点的子树至少还需要

$$n \ge \frac{1}{1-\alpha}\left(\alpha^{-d} - 1\right) \cdot c$$

级别的规模支撑，从而

$$d \le \log_{1/\alpha} \frac{n}{1-\alpha} = O(\log n).$$

更常见的表述：以高度法看，允许的最大深度为 $\lfloor \log_{1/\alpha} n \rfloor$，超过则重建，故树高 $O(\log n)$。

**重建均摊分析。** 考察一次触发重建的插入：设重建子树大小为 $k$。重建后该子树完全平衡，至少能再承受 $k(1-\alpha)$ 量级的净插入才会再次在该深度失衡（经典证明用「势能」或「重建间隔」计数）。因此重建成本 $O(k)$ 摊到 $\Omega(k)$ 次操作上，均摊 $O(1)$；再叠加查找路径 $O(\log n)$，总均摊 $O(\log n)$。

Galperin & Rivest 的严格证明给出：任意操作序列的摊还成本为 $O(\log n)$，且常数随 $\alpha$ 选择可调。

**与 α 的关系。** 高度因子 $\log_{1/\alpha} n$：$\alpha=0.5$ 时约为 $1\cdot\log_2 n$ 但不可行；$\alpha=0.7$ 时约 $1.9\log_2 n$；$\alpha=0.9$ 时约 $6.6\log_2 n$。故 α 是「高度常数 vs 重建频率」的直接旋钮。

## 四、代码实现

完整可运行的替罪羊树插入（重量平衡 + 中序重建），含查找与中序验证：

```python
class Node:
    __slots__ = ("key", "size", "left", "right")

    def __init__(self, key):
        self.key = key
        self.size = 1
        self.left = None
        self.right = None


def _size(t):
    return t.size if t else 0


def _update(t):
    if t:
        t.size = 1 + _size(t.left) + _size(t.right)
    return t


def flatten(t, out):
    """中序拍平，保持有序。"""
    if t is None:
        return
    flatten(t.left, out)
    out.append(t.key)
    flatten(t.right, out)


def build(keys, lo, hi):
    """有序切片建完全平衡 BST。"""
    if lo > hi:
        return None
    mid = (lo + hi) // 2
    node = Node(keys[mid])
    node.left = build(keys, lo, mid - 1)
    node.right = build(keys, mid + 1, hi)
    return _update(node)


def rebuild(t):
    """整棵子树重建为完全平衡。"""
    keys = []
    flatten(t, keys)
    return build(keys, 0, len(keys) - 1)


ALPHA = 0.7


def _is_unbalanced(t):
    return max(_size(t.left), _size(t.right)) > ALPHA * _size(t)


def insert(t, key):
    if t is None:
        return Node(key)
    if key == t.key:
        return t
    if key < t.key:
        t.left = insert(t.left, key)
    else:
        t.right = insert(t.right, key)
    _update(t)
    if _is_unbalanced(t):
        t = rebuild(t)   # 替罪羊：整子树重建
    return t


def search(t, key):
    while t:
        if key == t.key:
            return True
        t = t.left if key < t.key else t.right
    return False


def inorder(t, out=None):
    if out is None:
        out = []
    if t:
        inorder(t.left, out)
        out.append(t.key)
        inorder(t.right, out)
    return out


if __name__ == "__main__":
    root = None
    for i in range(1, 31):          # 有序插入也不退化
        root = insert(root, i)
    assert inorder(root) == list(range(1, 31))
    assert search(root, 15) and not search(root, 99)
    print("size =", root.size, "ok")
```

## 五、与其他技术对比

| 结构 | 平衡策略 | 旋转 | 随机性 | 实现难度 | 典型场景 |
|------|----------|------|--------|----------|----------|
| 替罪羊树 | α 权重平衡 + 整树重建 | 无 | 无 | 低 | 竞赛、教学、实现成本敏感 |
| AVL | 高度差 $\le 1$ + 四种旋转 | 有 | 无 | 中 | 读多写少字典 |
| 红黑树 | 着色黑高约束 | 有 | 无 | 高 | 工程通用有序表 |
| Treap | 随机优先级堆 | 有 | 有 | 中 | 竞赛、期望平衡 |
| FHQ Treap | 分裂合并 | 无 | 有 | 中 | 竞赛序列维护 |
| 伸展树 | 访问时旋转到根 | 有 | 无 | 中 | 局部性强访问 |

取舍：若你想要「无旋转 + 确定性 + 好写」，选替罪羊树；若追求最优查询高度，AVL；若写工程通用库，红黑树；若做序列区间操作，FHQ Treap 更顺手。

## 六、常见误区

1. **α 取 0.5 或更小。** 会导致几乎每次插入都触发重建，复杂度退化到 $O(n)$ 级别。必须 $\alpha \in (0.5, 1)$，常用 0.7。
2. **α 取太大（如 0.95）。** 重建少了，但树高常数变成 $\log_{1/0.95} n \approx 14\log_2 n$，查找变慢，失去意义。
3. **重建后不返回新根 / 不更新父指针。** `rebuild` 返回的新根必须接回父亲或作为全局根，否则丢树。这是最常见的崩溃点。
4. **size 维护遗漏。** 插入、删除、重建后都要更新 `size`，否则 α 判定完全失真，树会静默退化。
5. **删除后忘记可能触发重建。** 删除使一侧变空，同样可能破坏 α 平衡；若只在插入后检查，树会在反复删除后倾斜。
6. **误以为重建是「旋转」的一种。** 重建是 $O(k)$ 的全量操作，均摊便宜但单次昂贵；实时性要求高的路径上要避免触发大重建（可用惰性删除摊平）。

## 八、面试题

**1. 什么是替罪羊树的 α 平衡条件？为什么 α 必须大于 0.5？**
参考答案：$\max(|L|,|R|) \le \alpha |x|$。若 $\alpha \le 0.5$，非空结点两子树必须都小于父的一半，只有空树满足，会永远失衡重建，失去意义。$\alpha \in (0.5,1)$ 在高度常数与重建频率间折中。

**2. 替罪羊树一次插入最多重建几次？均摊复杂度？**
参考答案：一次插入找到一个替罪羊重建即可（更深层重建后祖先满足均摊界），单次重建 $O(k)$，但可摊到 $\Omega(k)$ 次操作，均摊 $O(\log n)$。

**3. 手写替罪羊树插入与重建。**
参考答案：递归插入并更新 size → 回溯时若 `max(size(left),size(right)) > α*size` 则 flatten + build 重建子树并返回新根。注意 rebuild 的返回值必须接回。

**4. 替罪羊树 vs Treap：何时选谁？**
参考答案：替罪羊树确定性、无随机，适合可复现场景；Treap 期望高度略优、支持分裂合并等高级操作，竞赛中 FHQ Treap 更通用。实现简易性两者接近，但替罪羊删除可惰性化，Treap 删除要处理优先级旋转。

## 九、演进与趋势

- **惰性删除 + 批量重建**：删除打标记，比例超过阈值时整树重建，把删除均摊到 $O(\log n)$，是竞赛模板常见做法。
- **部分重建 / 局部替罪羊**：只重建最小失衡子树，减少单次重建代价；与「权值线段树」结合可做第 k 大等扩展。
- **与 Treap/FHQ Treap 融合**：部分模板把替罪羊的重量思想用于随机树的退化检测。
- **工程启发**：α 平衡是「重量平衡树」（WBT）的近亲；OCaml、Haskell 部分有序 map 用 WBT 而非红黑树，因为函数式持久化下旋转路径复制成本高、而重量条件更易局部验证。
- **教学价值**：替罪羊树让学生理解「均摊分析」与「惰性维护」——现代索引结构（如 LSM 树的合并）也是同一哲学。

## 十、小结

替罪羊树用「α 权重平衡 + 失衡时整树重建」取代旋转，确定性地把操作均摊到 $O(\log n)$。实现短、思路清晰，是无旋平衡树的代表；把握好 α 选取、size 维护与重建返回值，就能得到一个可靠又好写的动态字典。
