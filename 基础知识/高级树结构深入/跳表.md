# 跳表

> 对应 Pugh《Skip Lists: A Probabilistic Alternative to Balanced Trees》(1990)；Redis 设计与实现中 zset 的 skiplist 实现。

## 一、背景与挑战

平衡二叉树（AVL、红黑树）能保证 $O(\log n)$ 操作，但旋转、着色、递归修复的实现复杂度高，并发时还要小心指针更新顺序。工程界一直有一种渴望：能不能用**极简的代码**得到同样的对数级性能，而且天然适合范围查询和并发？跳表（Skip List）给出了肯定答案。

跳表由 William Pugh 于 1990 年提出。它本质是**多层有序链表**：底层包含所有元素，往上以概率 $p$（常取 $1/2$）晋升一层，形成「快捷通道」。查找时从最高层向右扫描，走不动就下沉一层，像坐地铁换乘——快线跳过大量站点，慢线保证精确落地。期望时间 $O(\log n)$，期望空间 $O(n)$，代码量往往只有红黑树的三分之一。

它的工程地位非常实在：**Redis 的有序集合（zset）默认用跳表 + 哈希表**实现；Java `ConcurrentSkipListMap`/`ConcurrentSkipListSet` 是标准库并发有序容器；LevelDB/RocksDB 的 memtable 可选 skip list；许多数据库的内存索引、任务调度的时间轴结构也用跳表。面试中「为什么 Redis zset 用跳表不用红黑树」是经典高频题。

## 二、核心原理

**结构。** 每个结点含一个键值和一个指针数组 `forward[0..level]`。第 0 层是完整的有序链表；第 $i$ 层是第 $i-1$ 层的随机子序列。另设一个表头结点，其最高层指向当前最大层高。

**查找。** 从表头最高层 $L$ 开始：

```
curr = head
for i = L downto 0:
    while curr.forward[i] exists and curr.forward[i].key < target:
        curr = curr.forward[i]
# 此时 curr 是 target 的前驱
```

若 `curr.forward[0].key == target` 则命中。高层负责「大跨步跳过」，低层负责「精确定位」。

**插入。** 先按查找路径记录每层前驱 `update[i]`；随机生成新结点层高 $level$（几何分布，$P(level \ge k) = p^k$）；把 `update[i].forward[i]` 指向新结点（$i \le level$）。不需要旋转，只改常数个指针。

**删除。** 同样记录前驱数组，把各层 `update[i].forward[i]` 跳过被删结点即可；若删掉最高层结点可顺便降低表的 `level`。

**层高分布。** 以 $p=1/2$ 为例：约 50% 结点只有 1 层，25% 有 2 层，12.5% 有 3 层……期望层高 $\sum_{k\ge1} p^{k-1} = \frac{1}{1-p} = 2$。为防极端情况，通常设置 `MAX_LEVEL`（如 32 或 64）并做截断。

**为什么正确。** 期望意义下，每向上一层结点密度减半，查找路径长度是几何级数 $1 + 2 + 4 + \cdots$ 直到 $n$，对数收敛。这不是最坏保证（最坏仍可能 $O(n)$），但实践中高度集中在 $O(\log n)$。

**边界条件。** 空表、重复键（更新而非插入）、全部删除后 `level` 回落、随机层高上限、`update` 数组必须记录**每一层**的前驱（漏一层就断链）。

## 三、形式化与数学基础

**查找代价。** 把查找逆序看成从目标结点向上爬到顶层。期望上升高度为 $\sum_{k\ge1} p^{k-1}(1-p) \cdot k = \frac{1}{1-p}$，对 $p=1/2$ 即 2。水平方向，第 $i$ 层被经过的期望结点数为 $O(1/p)$，共约 $\log_{1/p} n$ 层，故

$$E[\text{比较次数}] = O\left(\frac{1}{1-p}\log_{1/p} n\right) = O(\log n).$$

**空间代价。** 结点 $x$ 层数 $L_x$ 服从几何分布，$E[L_x] = \frac{1}{1-p}$，故总指针数期望 $\frac{n}{1-p}$，即 $p=1/2$ 时期望 $2n$ 个指针，空间 $O(n)$。

**层高上界。** 单个结点层高 $\ge k$ 的概率 $p^{k-1}$。取 $MAX\_LEVEL = \lceil \log_{1/p} n \rceil + c$ 可使越界概率低于 $n \cdot p^c$。

**与平衡树对比的概率界。** 跳表的期望是对所有随机种子成立的；固定种子后可重现。最坏情况（所有结点同层）退化为 $O(n)$，故关键基础设施有时用「确定性跳表变体」或直接选平衡树。方差分析表明 $p=1/2$ 在时间/空间上接近最优，$p=1/4$ 节省空间但稍慢。

**并发友好性。** 指针更新是单写多读可容忍的「先挂后摘」（插入先设新结点 forward，再改前驱）；配合 CAS 可实现无锁跳表（Herlihy 等的 Skip List 无锁算法），这是红黑树很难做到的。

## 四、代码实现

完整可运行的跳表（插入、查找、删除、范围查询）：

```python
import random


class Node:
    __slots__ = ("key", "val", "forward")

    def __init__(self, key, val, level):
        self.key = key
        self.val = val
        self.forward = [None] * (level + 1)  # forward[i] 是第 i 层后继


class SkipList:
    MAX_LEVEL = 16
    P = 0.5

    def __init__(self):
        self.head = Node(None, None, self.MAX_LEVEL)
        self.level = 0   # 当前最大层（0-based）
        self.n = 0

    def random_level(self):
        lv = 0
        while random.random() < self.P and lv < self.MAX_LEVEL:
            lv += 1
        return lv

    def _find_predecessors(self, key):
        update = [None] * (self.MAX_LEVEL + 1)
        curr = self.head
        for i in range(self.level, -1, -1):
            while curr.forward[i] and curr.forward[i].key < key:
                curr = curr.forward[i]
            update[i] = curr
        return update, curr.forward[0]

    def insert(self, key, val):
        update, found = self._find_predecessors(key)
        if found and found.key == key:
            found.val = val          # 重复键则更新
            return
        lv = self.random_level()
        if lv > self.level:
            for i in range(self.level + 1, lv + 1):
                update[i] = self.head
            self.level = lv
        node = Node(key, val, lv)
        for i in range(lv + 1):
            node.forward[i] = update[i].forward[i]
            update[i].forward[i] = node
        self.n += 1

    def search(self, key):
        _, node = self._find_predecessors(key)
        return node.val if node and node.key == key else None

    def delete(self, key):
        update, node = self._find_predecessors(key)
        if not node or node.key != key:
            return False
        for i in range(len(node.forward)):
            if update[i].forward[i] is node:
                update[i].forward[i] = node.forward[i]
        while self.level > 0 and self.head.forward[self.level] is None:
            self.level -= 1
        self.n -= 1
        return True

    def range_query(self, lo, hi):
        """返回 [lo, hi] 内的 (key, val) 列表。"""
        _, node = self._find_predecessors(lo)
        res = []
        while node and node.key <= hi:
            res.append((node.key, node.val))
            node = node.forward[0]
        return res


if __name__ == "__main__":
    sl = SkipList()
    for i in [3, 6, 7, 9, 12, 19, 17, 26, 21, 25]:
        sl.insert(i, i * 10)
    assert sl.search(19) == 190
    assert sl.delete(19) and sl.search(19) is None
    print(sl.range_query(6, 21))
    print("level =", sl.level, "n =", sl.n)
```

## 五、与其他技术对比

| 维度 | 跳表 | 红黑树 | AVL | B+ 树 | 哈希表 |
|------|------|--------|-----|-------|--------|
| 查找 | 期望 $O(\log n)$ | 最坏 $O(\log n)$ | 最坏 $O(\log n)$ | $O(\log_m n)$ | 期望 $O(1)$ |
| 范围查询 | 天然顺序扫描 | 需中序遍历 | 同左 | 叶子链最优 | 不支持 |
| 实现难度 | 低 | 高 | 中 | 中高 | 低 |
| 并发 | 易无锁 | 难 | 难 | 页锁 | 可分段锁 |
| 内存 | 指针较多（$2n$ 级） | 较省 | 较省 | 页对齐 | 负载因子敏感 |
| 典型 | Redis zset、并发 map | TreeMap、内核 | 读多字典 | 磁盘索引 | 通用 KV |

取舍：需要**有序 + 并发 + 实现简单**时跳表几乎无敌；需要**最坏保证**（如实时系统）选红黑树/AVL；磁盘场景选 B+ 树；只需等值查询选哈希。

## 六、常见误区

1. **层高不设上限。** 理论几何分布可无限增长，必须 `MAX_LEVEL` 截断，否则单结点占满内存、层数失控。
2. **插入时漏记某层前驱。** `update[]` 必须记录 0..level 每一层；漏高层会导致高层链断裂，查找「跳过」元素或空指针。
3. **认为跳表「一定」比红黑树快。** 跳表是期望性能，指针跳转缓存不友好，单线程纯查找红黑树常更稳；跳表赢在实现简单、范围查询与并发。
4. **删除后不收缩 level。** 表头高层空指针若不清理，后续查找多走空层，性能退化。
5. **重复键处理不当。** 语义上是 set 还是 map 要事先定好；Redis zset 是 score+member 唯一，插入重复 member 是更新 score。
6. **用伪随机种子导致可预测层高。** 安全敏感场景（防哈希碰撞攻击）需用密码学随机或确定性平衡树。

## 八、面试题

**1. Redis zset 为什么用跳表而不用红黑树？**
参考答案：一是实现简单、代码更短、bug 面小；二是范围查询（`ZRANGEBYSCORE`）在跳表上就是底层链表顺序扫，红黑树要中序迭代器；三是并发/持久化友好；四是跳表缓存局部性可通过调 p 改善。Redis 作者在邮件列表明确表示「不是因为快，是因为简单」。

**2. 跳表的期望时间与空间是多少？p 的影响？**
参考答案：时间期望 $O(\log_{1/p} n)$，空间期望 $O(n/(1-p))$。$p$ 大则层多、查找快、费空间；$p$ 小则省空间、稍慢。工程常用 $p=1/2$ 或 $1/4$。

**3. 手写跳表插入，说明 update 数组的作用。**
参考答案：查找时逐层记录前驱到 `update[i]`；插入随机层高 $lv$，对 $i\le lv$ 执行 `node.forward[i]=update[i].forward[i]; update[i].forward[i]=node`。update 保证各层不断链。

**4. 跳表如何支持范围查询和排名？**
参考答案：范围查询从 `lower_bound` 起沿 `forward[0]` 扫到上限；排名可在每层结点加 `span`（Redis 实现）累加前驱跨度，$O(\log n)$ 求 rank，或顺序扫描 $O(k)$。

## 九、演进与趋势

- **无锁并发跳表**：Herlihy 等基于 CAS 的 skip list 成为并发数据结构经典，Java `ConcurrentSkipListMap` 即类似实现。
- **带 span 的跳表**：Redis 在指针上附加跨度，支持 $O(\log n)$ 的 `ZRANK`/`ZCOUNT`，把跳表升级为顺序统计结构。
- **压缩/分层跳表**：结合 Trie 前缀思想做字符串字典；与 LSM-tree 配合做 memtable（RocksDB 可选 skip list 实现）。
- **确定性跳表变体与 Finger Skip List**：在保留简单性的同时收紧最坏界；学术上还有 Skip B-Tree、Skip Quadtree 等空间索引。
- **工程趋势**：新系统在「内存有序 + 并发」场景几乎默认跳表；红黑树退居「最坏保证 + 单线程」利基。NVM/持久内存时代，跳表的追加式指针更新也比旋转更易崩溃恢复。

## 十、小结

跳表用概率分层的多层有序链表，以 $O(n)$ 期望空间换来期望 $O(\log n)$ 的查找/插入/删除，并把范围查询做成天然的链表扫描。它实现极简、并发友好，是 Redis zset 与 Java 并发有序容器的支柱——在「够快、好写、能并发」的综合评分上，常胜过红黑树。
