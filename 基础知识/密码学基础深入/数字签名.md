# 数字签名

> 对应数字签名（RSA-PSS / ECDSA / EdDSA）与不可否认性。

## 一、背景与挑战
签名用私钥对消息摘要签名，任何持有公钥者均可验证，提供来源认证与不可否认。挑战在随机数安全（ECDSA k 重用灾难）与算法选择。

## 二、核心原理
- 流程：hash(message) → 私钥签名 → (r,s)；验证用公钥。
- RSA 签名：$s = H(m)^d \bmod n$，验证 $s^e \equiv H(m)$。
- ECDSA：基于椭圆曲线，签名依赖随机数 $k$；k 重用可解私钥。
- EdDSA（Ed25519）：确定性 nonce，抗弱随机数，现代推荐。

## 三、形式化 / 数学基础
- 不可伪造性（EUF-CMA）：存在性不可伪造抗选择消息攻击。
- ECDSA 签名：$r=(kG)_x \bmod n,\ s=k^{-1}(e+rd_A)\bmod n$。
- k 重用：两签名同 $k$ 可解 $d_A = \frac{s_1 e_2 - s_2 e_1}{r(s_2-s_1)} \bmod n$（私钥泄露）。
- 安全哈希绑定：先 hash 再签名，避免长度/扩展攻击。

## 四、代码实现
```python
from cryptography.hazmat.primitives.asymmetric import ed25519
from cryptography.hazmat.primitives import hashes, serialization
sk = ed25519.Ed25519PrivateKey.generate()
sig = sk.sign(b"doc")
sk.public_key().verify(sig, b"doc")   # 抛异常即验证失败
```

## 五、与其他技术对比
- 签名 vs MAC：签名可公开验证、不可否认；MAC 需共享密钥。
- ECDSA vs Ed25519：后者确定性 nonce 更安全、更快。
- RSA-PSS vs PKCS#1 v1.5：PSS 具可证明安全，推荐。

## 六、常见误区
- ECDSA 随机数 k 重用 → 私钥泄露（Sony PS3 事件）。
- 对原文而非哈希签名（性能/安全差）。
- 用同一密钥既加密又签名（隔离原则）。

## 九、演进与趋势
Ed25519 成主流；后量子签名（Dilithium）标准化；阈值签名用于多签。

## 十、小结
数字签名以私钥签名公钥验证提供认证与不可否认，须用安全 nonce 与 Ed25519/PSS，严禁 k 重用。
