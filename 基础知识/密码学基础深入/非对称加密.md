# 非对称加密

> 对应公钥加密（RSA / ECC / DH）与密钥交换。

## 一、背景与挑战
对称加密难解决密钥分发。非对称加密用公钥加密、私钥解密（或反之签名），但计算慢，通常用于交换对称密钥而非直接加密大量数据。

## 二、核心原理
- RSA：基于大数分解难题，加密 $c=m^e\bmod n$，解密 $m=c^d\bmod n$。
- DH/ECDH：双方各自私钥 + 对方公钥算出共享秘密，前向安全。
- ECC：同等安全下密钥更短（256bit ECC ≈ 3072bit RSA）。
- 混合加密：非对称交换密钥 + 对称加密数据（TLS 做法）。

## 三、形式化 / 数学基础
- RSA 正确性来自欧拉定理：若 $ed\equiv1\pmod{\varphi(n)}$，则 $(m^e)^d\equiv m$。
- 分解难度：$n=pq$，已知 $n$ 求 $p,q$ 为经典难题（Shor 算法可在量子下多项式解）。
- ECDH 共享：$S = d_A \cdot P_B = d_B \cdot P_A$（椭圆曲线点乘）。
- 离散对数难题支撑 DH/ECDH。

## 四、代码实现
```python
from cryptography.hazmat.primitives.asymmetric import ec
from cryptography.hazmat.primitives.kdf.hkdf import HKDF
from cryptography.hazmat.primitives import hashes
# ECDH 密钥交换
a = ec.generate_private_key(ec.SECP256R1())
b = ec.generate_private_key(ec.SECP256R1())
shared_a = a.exchange(ec.ECDH(), b.public_key())
key = HKDF(algorithm=hashes.SHA256(), length=32, salt=None, info=b"").derive(shared_a)
```

## 五、与其他技术对比
- RSA vs ECC：ECC 更快、密钥短；RSA 实现历史久。
- RSA 加密 vs DH 交换：RSA 直接传密文，DH 双方共算秘密。
- 非对称慢：仅用于密钥/小数据，大量数据用对称。

## 六、常见误区
- 用 RSA 直接加密大明文（慢且需填充防攻击）。
- 忽视前向安全（长期私钥泄密可解密历史会话）。
- ECDH 复用 nonce/私钥导致共享秘密泄露。

## 十、小结
非对称加密解决密钥分发，ECDH 提供前向安全密钥交换，实际与对称加密组合构成混合体系。
