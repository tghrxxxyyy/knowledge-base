# 密码协议

> 对应认证协议与密钥协商协议（TLS 握手、OPA 等）。

## 一、背景与挑战
单个原语安全不代表组合安全。协议需抵御中间人、重放、降级等。TLS 是最广泛使用的认证+密钥交换协议。

## 二、核心原理
- TLS 1.3 握手：ClientHello/ServerHello 协商密钥，ECDHE 提供前向安全，0-RTT/1-RTT。
- 认证：服务端用证书（CA 链）证明身份；可选客户端证书。
- 防重放：nonce/序列号；防降级：版本/密码套件协商固化。
- 记录层：用协商出的对称密钥 AEAD 加密应用数据。

## 三、形式化 / 数学基础
- ECDHE 共享秘密 $S = d_C \cdot P_S = d_S \cdot P_C$，双方推导出相同 $S$。
- 主密钥 $MK = \text{HKDF}(S, \text{transcript})$，绑定握手消息防篡改。
- 认证绑定：$\text{Verify}(cert_{server}, CA_{root})$ 且证书域名匹配。
- 前向安全：每次会话独立 ECDHE 临时密钥，长期私钥泄露不解密历史。

## 四、代码实现
```python
import ssl, socket
ctx = ssl.create_default_context()          # 默认 TLS1.3，验证 CA
ctx.minimum_version = ssl.TLSVersion.TLSv1_3
with socket.create_connection(("example.com", 443)) as s:
    with ctx.wrap_socket(s, server_hostname="example.com") as tls:
        print(tls.version(), tls.cipher())  # 已认证 + 加密
```

## 五、与其他技术对比
- TLS 1.2 vs 1.3：1.3 去除了不安全的静态 RSA 密钥交换、更快更安全。
- IPSec/WireGuard vs TLS：网络层 vs 应用/传输层。
- 自签证书 vs CA：自签需手动信任，易被中间人。

## 六、常见误区
- 关闭证书验证（`verify=False`）形同明文。
- 使用静态 RSA 密钥交换（无前向安全）。
- 忽略证书域名/过期校验。

## 九、演进与趋势
TLS 1.3 普及；后量子密钥交换（Hybrid）进入草案；mTLS 用于服务网格零信任。

## 十、小结
密码协议把原语组合成安全通信，TLS 1.3 以 ECDHE 前向安全、证书认证与 AEAD 记录层成为基石。
