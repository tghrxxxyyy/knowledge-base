# 对称加密

> 对应对称加密（块密码/流密码）与分组模式。

## 一、背景与挑战
对称加密用同一密钥加解密，效率高，适合加密大量数据。挑战在于密钥分发安全与正确选择模式/填充。

## 二、核心原理
- 块密码（AES）固定分组 128bit，密钥 128/192/256。
- 模式：ECB（不安全的独立分组）、CBC、CTR、GCM（带认证）。
- GCM 同时提供机密性与完整性（AEAD），现代首选。
- 密钥须随机且保密，IV/nonce 须唯一（尤其 CTR/GCM 重用 nonce 致命）。

## 三、形式化 / 数学基础
- AES 是轮函数 $R_k$ 的迭代：$E_k(p)=R_{k_{10}}\circ\cdots\circ R_{k_1}(p)$。
- CTR：$c_i = p_i \oplus E_k(nonce \mathbin\| i)$，变为流密码。
- GCM 认证标签 $T = \text{GHASH}_H(C \mathbin\| A) \oplus E_k(nonce\mathbin\|0^{31}1)$。
- 语义安全（IND-CPA）要求相同明文不同密文（靠随机 IV）。

## 四、代码实现
```python
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
import os
key = AESGCM.generate_key(bit_length=256)
aes = AESGCM(key)
nonce = os.urandom(12)                 # 必须唯一
ct = aes.encrypt(nonce, b"secret", b"aad")  # 带认证
pt = aes.decrypt(nonce, ct, b"aad")
```

## 五、与其他技术对比
- 对称 vs 非对称：对称快、需共享密钥；非对称慢、解决分发。
- ECB vs CBC/GCM：ECB 泄露模式，GCM 加认证。
- 流密码（ChaCha20）vs 块（AES）：ChaCha20 在无 AES 指令集设备上更快。

## 六、常见误区
- GCM nonce 重用 → 可恢复明文甚至伪造标签。
- 用 ECB 加密结构化数据泄露模式。
- 自己实现密码算法（极易出错）。

## 九、演进与趋势
AES-GCM 普及；ChaCha20-Poly1305 成 TLS 默认之一；AEAD 成标准要求。

## 十、小结
对称加密以 AES-GCM 等 AEAD 模式为现代标准，关键是安全密钥管理、唯一 nonce 与禁用 ECB。
