# 影子流量与流量镜像

> 对应 Kleppmann 2017《Designing Data-Intensive Applications》中关于请求复制、扇出与一致性影响的讨论，以及 Envoy 流量镜像实践。

## 一、背景与挑战

新版本在预发环境难以复现真实负载与数据分布：预发流量小、数据偏、链路不全，许多问题（性能拐点、脏数据、边界 case）只有上线后才暴露。需要在「不影响真实用户」的前提下用真实生产流量验证候选版本。

挑战：(1) 镜像会放大后端负载，候选服务可能拖垮自己或被限流；(2) 影子版若写入共享存储会污染生产数据；(3) 镜像必须异步，不能增加主路径延迟；(4) 镜像流量需脱敏与隔离。

## 二、核心原理

流量镜像（mirroring / shadowing）把生产请求复制一份（或按比例抽样）发给候选版本，原响应仍由稳定版返回给用户。候选版只记录结果用于比对，其异常、超时、错误都不影响线上。核心约束：镜像是「旁路只读验证」，用户无感。

典型实现：网关/Envoy 在转发主请求同时异步发一份到 shadow cluster，丢弃其响应或仅入库分析。候选版应接隔离的存储或只读副本，避免双向写入。

落地时还需处理三类工程细节。其一，请求脱敏：生产请求常含 PII（手机号、token），镜像前应在网关层剥离敏感字段或哈希，避免影子库违规存隐私。其二，下游隔离：候选版连接的数据库、缓存、第三方 API 必须指向影子或预发环境，绝不能复用生产写入路径，否则「只读验证」变「污染生产」。其三，采样与限流：mirror_percent 按候选容量设定，并在候选服务前置熔断，避免其慢吞拖垮镜像发送方。与回放（replay）的区别在于：影子流量用「实时生产请求」验证「当前候选版」，时效性强但受候选容量限制；回放用「历史录制流量」离线反复跑「多个候选版」，适合回归对比但数据可能过期。二者常组合：日常用影子流量保真，发版前用回放做全量回归。此外需对镜像请求打标（如加 X-Shadow 头），方便下游识别、限流与审计，也便于在链路追踪中把镜像流量从真实指标中剔除，避免污染 SLO 统计。

当候选版在镜像中暴露异常，应自动降比例并通知负责人，而非继续放大负载。

## 三、形式化与数学基础

设请求 $r$ 进入系统。主路径返回 $f_{\mathrm{stable}}(r)$；镜像路径异步执行 $f_{\mathrm{candidate}}(r)$ 仅记录结果，不参与响应：

$$\text{用户可见} = f_{\mathrm{stable}}(r), \quad T_{\mathrm{user}} = T(f_{\mathrm{stable}})$$

镜像开销独立核算，镜像占比 $p$（mirror_percent）：

$$\text{候选负载} = p \cdot \lambda_{\mathrm{prod}}, \quad \lambda_{\mathrm{prod}} \text{ 为生产 QPS}$$

比对指标：差异率 $\delta = \frac{1}{N}\sum_i \mathbb{1}[f_{\mathrm{candidate}}(r_i) \neq f_{\mathrm{stable}}(r_i)]$，超阈值报警。

## 四、代码实现

Envoy 流量镜像（概念配置）：

```yaml
route:
  cluster: stable-cluster
  request_mirror_policy:
    cluster: candidate-cluster
    mirror_percent: 100      # 镜像比例，0-100
    runtime_key: "mirror.candidate"
```

注意：mirror_percent 过高会成倍放大候选服务与下游存储压力，应按候选容量设定；候选版写操作必须路由到影子库，绝不能回写生产主库。

## 五、与其他技术对比

| 方式 | 用户风险 | 数据风险 | 负载 | 真实性 |
|------|----------|----------|------|--------|
| 金丝雀 | 有（少量） | 有 | 中 | 高 |
| 影子流量 | 无 | 需隔离 | 放大 | 高 |
| 回放(replay) | 无 | 隔离 | 离线 | 中 |
| 预发测试 | 无 | 无 | 低 | 低 |

## 六、常见误区

- 影子版写入了共享存储，污染生产数据：应只做只读或隔离写入（影子库/只读副本）。
- 镜像比例过高拖垮网络与候选服务：需按容量限流。
- 把镜像延迟算进主路径：镜像必须 fire-and-forget。
- 忽略脱敏：生产请求含 PII，镜像落地需合规处理。

## 九、演进与趋势

与流量回放（record & replay）结合，用历史流量做离线回归，进一步前置风险发现；与差分测试（diff testing）结合自动比对两版本响应差异。具体以官方最新文档为准。

镜像流量的价值在「零用户风险的高保真验证」，应作为发版前标准预检环节。

## 十、小结

流量镜像用真实请求做无风险验证，是发布前的高保真预检手段。其前提是异步、隔离写入与按容量限速，否则可能反噬生产。
