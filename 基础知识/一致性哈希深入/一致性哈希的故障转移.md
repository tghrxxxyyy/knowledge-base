# 一致性哈希的故障转移

> 对应 DeCandia et al. 2007（Dynamo hinted handoff 与故障转移）与 Kleppmann DDIA 第5章（复制）。

## 一、背景与挑战
当某节点宕机，其负责区间的 key 不可用。一致性哈希结合副本链与 hinted handoff，让下游节点临时接管，故障恢复后再归还数据。

## 二、核心原理
- 副本链（preference list）包含 R 个节点，宕机时顺延到下一个健康节点。
- Hinted handoff：临时接收方记下“本应属于谁”，恢复后回传。
- 反熵定期修复副本差异。

## 三、形式化与数学基础
设节点可用率 p，副本因子 R，则 key 不可用概率为 $(1-p)^R$。提高 R 以指数降低不可达概率。

## 四、代码实现
# 顺延到下一个健康节点
def get_node(ring, key, healthy, R):
    lst = preference_list(ring, key, R + 5)
    for n in lst:
        if n in healthy:
            return n
    return None

## 五、与其他技术对比
- 对比主备切换：一致性哈希无需显式主节点。
- 对比 Raft 故障转移：Raft 是强一致，这里是最弱可用。

## 六、常见误区
1. hinted handoff 积压导致接收方过载。
2. 网络分区时产生多份“临时owner”。

## 九、演进与趋势
用 CRDT 替代 hinted handoff 的临时副本，减少回传复杂度。

## 十、小结
一致性哈希配合副本链与 handoff，实现无主架构下的高可用故障转移。
