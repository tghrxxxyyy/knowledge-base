# 带权重的一致性哈希

> 对应 DeCandia et al. 2007（Dynamo 虚拟节点表达异构容量）与 Karger et al. 1997（一致性哈希可扩展至加权）。

## 一、背景与挑战

上一篇用虚拟节点压平了负载方差，默认前提是「所有物理节点长得一样」。现实集群几乎总在打脸：同一套 Cassandra 集群里可能混着 2018 年的 12 核 4TB 机械盘老机器和 2024 年的 64 核 16TB NVMe 新机器；缓存集群里有的实例独占整机，有的与其它服务混部只能用一半内存；云上还常按成本混用 Spot 机型。若每台机器分配相同数量的 vnode，新老机器收到相同期望的 key 数与流量——小机器磁盘先满、请求排队，大机器却长期半闲。这不是算法错误，而是**模型与现实的错配**：基础一致性哈希只表达「谁在环上」，不表达「谁该扛多少」。

加权一致性哈希（Weighted Consistent Hashing）就是给节点赋予容量权重，让强机器在环上「占得更多」，从而期望负载与权重成正比。它的工程价值非常直接：混部集群的平均利用率可以明显提高（不必按最小机器规格配置所有分片），扩容时可以把新大机器的权重逐步调高做「温迁移」，缩容时反向操作。面试中它通常作为「虚拟节点的延伸题」出现：如何用 vnode 表达权重、权重误差与什么有关、动态权重怎么做。

要解决的挑战有三层：一是**静态权重分配**——给定容量向量，算出每节点 vnode 数；二是**离散化误差**——vnode 必须是整数，小权重节点可能取整失真；三是**动态性**——机器负载会随业务波动，静态权重很快过期，需要反馈调整而不引起再平衡风暴。

## 二、核心原理

核心思路一句话：**用 vnode 数量作为权重的离散化载体**。为物理节点 $i$ 分配 $v_i$ 个虚拟节点，且
$$
v_i \propto w_i,
$$
其中 $w_i$ 是权重（可来自磁盘容量、CPU 核数、内存、压测吞吐的任意合成指标）。由于每个 vnode 在环上期望占有 $\frac{1}{\sum_j v_j}$ 的弧长，节点 $i$ 的期望负载占比就约为 $\frac{v_i}{\sum_j v_j} \approx \frac{w_i}{\sum_j w_j}$。

不变量与正确性要点：

1. **环上所有 vnode 仍是统一哈希、统一顺时针规则**。加权只改变「每个物理节点在环上点的数量」，不改变路由逻辑。这保证与无权版本的兼容性：客户端、查找结构完全一样。
2. **权重通过数量而非距离表达**。不要试图让 vnode 在环上的「间距」与权重成反比——那样会破坏均匀哈希，热点会聚集。正确的加权是「复制更多入口点」，每个入口点仍均匀随机。
3. **相对负载期望正确，绝对值可控制**。若希望节点 $i$ 的目标 key 数为 $C_i$，则令 $v_i = \alpha C_i$，总 vnode 数 $V = \sum v_i$ 越大，实现值越接近 $C_i$。

与「显式区间划分」的对比：显式划分（例如按权重切环弧长）可以精确，但增删节点时要重算所有边界，破坏局部性；vnode 加权保持「增删只影响局部弧」的性质，代价是权重精度受 $V$ 限制。工程上几乎总是选 vnode 加权。

还有一个重要设计点：**权重应当表达长期容量，而不是瞬时 QPS**。把实时 CPU 当权重会让 vnode 数频繁变化、触发大规模 rebalance。正确做法是「慢变量用 vnode、快变量用限流/负载均衡器」。

## 三、形式化与数学基础

设总 vnode 预算为 $V$（例如 $V = 1000$ 或 $V = 100 \cdot N$），节点集合权重 $w_1,\dots,w_N$，$\sum w_i = W$。

**vnode 分配**。最简单是
$$
v_i = \left\lfloor V \cdot \frac{w_i}{W} \right\rfloor,
$$
但这样 $\sum \lfloor \cdot \rfloor$ 可能小于 $V$，且小权重节点可能被取成 0。改进为**最大余数法（Hamilton / Largest Remainder）**：
1. 先给每个节点 $\lfloor V w_i / W \rfloor$ 个 vnode，并保证至少 1 个；
2. 计算余数 $r_i = V w_i / W - v_i$；
3. 把剩余 $V - \sum v_i$ 个 vnode 依次分给余数最大的节点。

这样 $\sum v_i = V$，且 $|v_i - V w_i / W| \le 1$。

**负载期望**。节点 $i$ 期望负载占比
$$
\mathbb{E}\left[\frac{\text{load}_i}{K}\right] = \frac{v_i}{V} \approx \frac{w_i}{W}.
$$

**离散化误差**。绝对误差
$$
\left|\frac{v_i}{V} - \frac{w_i}{W}\right| \le \frac{1}{V}.
$$
相对误差对权重最小的节点最严重：若 $w_i/W = 1\%$ 而 $V = 100$，则 $v_i \approx 1$，取整波动可达 100%。**规则：$V$ 必须远大于 $W / \min w_i$ 的倒数**，等价地每个最小权重节点至少分到 $10\sim 20$ 个 vnode。

**随机方差叠加**。在离散化误差之外，还有 $1/\sqrt{V}$ 的随机弧长波动。综合偏差量级为
$$
\text{相对偏差} \approx O\left(\frac{1}{V}\right) + O\left(\frac{1}{\sqrt{V}}\right) = O\left(\frac{1}{\sqrt{V}}\right),
$$
因此主要靠增大 $V$ 来收敛；权重取整是次要项但对小权重节点更尖锐。

**动态权重的收敛性**。若每隔周期 $T$ 按负载反馈把 $w_i$ 乘以因子 $\lambda_i \in [0.9, 1.1]$ 并重新分配 vnode，每次 vnode 数变动 $\Delta v_i$ 会触发迁移约 $\frac{|\Delta v_i|}{V} K$ 个 key。控制 $|\Delta v_i| \le \delta V$（例如 1%）可把单次迁移控制在 $O(\delta K)$，避免风暴。

## 四、代码实现

实现加权 vnode 环，用最大余数法分配 vnode，并验证负载与权重成正比。

```python
import hashlib
from bisect import bisect_left, insort
from collections import Counter


def md5_int(data) -> int:
    if not isinstance(data, bytes):
        data = str(data).encode()
    return int.from_bytes(hashlib.md5(data).digest()[:8], "big")


def allocate_vnodes(weights: dict, V: int) -> dict:
    """最大余数法：按权重分配 V 个 vnode，每个节点至少 1 个。"""
    W = sum(weights.values())
    if W <= 0:
        raise ValueError("weights must be positive")
    if V < len(weights):
        raise ValueError("V must be >= number of nodes")

    raw = {n: V * w / W for n, w in weights.items()}
    alloc = {n: max(1, int(v)) for n, v in raw.items()}
    # 修正下取整造成的差额
    while sum(alloc.values()) > V:
        # 理论上 max(1,..) 可能超出，优先从余数最小的节点减（不低于1）
        n = min(alloc, key=lambda x: raw[x] - alloc[x])
        if alloc[n] > 1:
            alloc[n] -= 1
        else:
            break
    remain = V - sum(alloc.values())
    if remain > 0:
        order = sorted(weights, key=lambda n: (raw[n] - alloc[n]), reverse=True)
        i = 0
        while remain > 0:
            n = order[i % len(order)]
            alloc[n] += 1
            remain -= 1
            i += 1
    return alloc


class WeightedRing:
    def __init__(self, weights: dict, V: int = 1000):
        self.alloc = allocate_vnodes(weights, V)
        self._pts, self._owner = [], {}
        for node, vi in self.alloc.items():
            for i in range(vi):
                p = md5_int(f"{node}#{i}")
                while p in self._owner:
                    p = md5_int(f"{node}#{i}#r{p}")
                insort(self._pts, p)
                self._owner[p] = node

    def get(self, key):
        h = md5_int(key)
        i = bisect_left(self._pts, h)
        if i == len(self._pts):
            i = 0
        return self._owner[self._pts[i]]


if __name__ == "__main__":
    # 三台机器：容量比 4 : 2 : 1
    weights = {"big": 4.0, "mid": 2.0, "small": 1.0}
    ring = WeightedRing(weights, V=700)
    print("vnode 分配:", ring.alloc)

    keys = [f"k{i}" for i in range(30000)]
    cnt = Counter(ring.get(k) for k in keys)
    total = sum(cnt.values())
    for n, w in weights.items():
        actual = cnt[n] / total
        expect = w / sum(weights.values())
        print(f"{n:6s} expect={expect:.2%}  actual={actual:.2%}")
```

输出会显示三台机器的实际负载约为 57% / 29% / 14%，贴近 4:2:1。把 $V$ 从 700 降到 21，观察 `small` 节点的偏差会明显变大——这直观展示了离散化误差。

## 五、与其他技术对比

| 方案 | 权重精度 | 迁移局部性 | 动态调整 | 实现复杂度 |
| --- | --- | --- | --- | --- |
| 等权 vnode | 无权重概念 | 好 | 改 vnode 数即可 | 低 |
| 加权 vnode | $O(1/V)$ 离散误差 | 好 | 改 $v_i$ 触发局部迁移 | 中 |
| 显式弧长划分 | 精确 | 差（边界全变） | 需全量重切 | 高 |
| 一致性哈希 + 权重复制（复制 key 多份） | 精确 | 中 | 灵活 | 中，语义复杂 |
| 客户端加权随机（不做环） | 精确 | 不适用 | 灵活 | 低，但无数据本地性 |

显式划分适合「静态、强 SLA、要求精确配额」的场景；加权 vnode 是弹性集群的主流。复制式加权会让同一 key 映射多个候选，常与读写策略绑定。

## 六、常见误区

1. **权重长期不更新**。扩容了 16TB 新机器却沿用旧 vnode 数，利用率仍不平衡；应当在节点属性变化时触发权重重算与限速迁移。
2. **$V$ 太小导致离散化误差爆炸**。小权重节点只分到 1 个 vnode 时，它的实际负载可能偏离目标一倍以上。应保证最小权重节点至少 10～20 个 vnode。
3. **把瞬时负载当权重**。QPS 抖动引起 vnode 数频繁变化，触发持续 rebalance，雪上加霜。权重只反映容量/慢变指标。
4. **用「间距」或「重复 key 副本」做加权却破坏了哈希均匀性**。例如按权重在环上等距插入，会让 vnode 聚集，局部热点。加权只能靠「点的数量」，不能靠「点的刻意排布」。
5. **忽略归一化与最小保障**。权重之和变化、出现权重为 0 的节点、或 $V < N$，都会让分配函数崩溃或让某些节点饿死。

## 八、面试题

**1. 如何用虚拟节点表达机器权重？**
按权重比例分配 vnode 数 $v_i \propto w_i$，期望负载占比即权重占比；用最大余数法控制取整误差。

**2. 权重误差与什么有关？**
与总 vnode 数 $V$ 成反比（离散误差 $\le 1/V$），与随机方差 $1/\sqrt{V}$ 叠加；最小权重节点相对误差最大。

**3. 新机器加进来后，如何避免一次性搬太多数据？**
把新机器 vnode 数分阶段提升（或权重线性爬坡），每阶段迁移 $\Delta v / V$ 的数据，限速执行。

**4. 权重应该用磁盘还是 CPU？**
用反映长期容量的合成指标（磁盘、内存、压测吞吐）；瞬时 CPU/QPS 不宜作权重，应交给限流与负载均衡。

## 九、演进与趋势

现代系统把加权一致性哈希做成了**闭环**：Cassandra、ScyllaDB 支持根据磁盘与 compaction 压力动态调整 token 分配；云原生存储（TiKV、Vitess）用「Range 分裂 + 按节点容量调度副本」实现更细粒度的加权；服务网格（Envoy ring hash、gRPC）提供 weight 字段直接参与环构建。研究方向包括「无 vnode 的加权跳跃哈希」、「基于在线学习的权重预测」、以及「多维资源（CPU/磁盘/网络）联合权重」的 Pareto 均衡。可以预期，随着混部与异构算力（ARM/x86/GPU 旁路）普及，带权重的一致性哈希会从「可选优化」变成「标配能力」。

## 十、小结

带权重的一致性哈希用 vnode 数量把连续权重离散到环上：$v_i \propto w_i$ 保持路由规则不变，却让期望负载与容量对齐；最大余数法与足够大的 $V$ 控制误差，动态权重需限速爬坡避免迁移风暴。它是异构集群提高利用率、平滑扩缩容的关键机制。
