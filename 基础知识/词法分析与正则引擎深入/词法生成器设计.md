# 词法生成器设计

> 对应 flex 与 Crafting Interpreters 扫描器章。

## 一、背景与挑战
词法生成器（如 lex/flex）从正则规格自动生成扫描器。挑战：处理多模式规则、最长匹配 (maximal munch)、规则优先级、以及把 DFA 编译为高效跳转表或代码。

## 二、核心原理
每条规则是一个正则 + 动作；所有正则用 `|` 合并为一个 NFA，子集构造得 DFA；匹配时走 DFA，记录最近遇到的接受态及其规则编号（最长匹配）。

## 三、形式化 / 数学基础
扫描器维持当前 DFA 状态 $s$ 与输入位置 $i$：
```
while s 有转移 on input[i]:
    s = move[s][input[i]]; i += 1
    if s in accepting: last = (rule[s], i)
回退到 last 的位置并触发对应动作
```

## 四、代码实现
```c
/* flex 生成骨架示意 */
int yylex() {
    int s = 0, last = -1, start = yypos;
    while (yytrans[s][INPUT(yypos)] >= 0) {
        s = yytrans[s][INPUT(yypos)]; yypos++;
        if (yyaccept[s]) last = yypos;
    }
    if (last < 0) error();
    return yyrule[ /* 由 last 反查 */ ];
}
```

## 五、与其他技术对比
- 表驱动：可移植、易改规格，跳转略慢。
- 直接编码转移（手写扫描器）：最快、可读性好，但无自动生成。
- 虚拟机式（如 RE2）：对正则统一执行引擎。

## 六、常见误区
1. 忽略最长匹配，导致 `=` 被 `==` 规则抢先匹配错。
2. 规则顺序混淆：相同长度时取"先定义"规则而非最长。
3. 在动作里修改输入缓冲破坏回退位置。

## 九、演进与趋势

## 十、小结
词法生成器把"正则集合 → NFA → DFA → 表/代码"流水线化；最长匹配与规则优先级是规格语义的核心。
