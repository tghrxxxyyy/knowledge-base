# 正则表达式理论

> 对应 Crafting Interpreters (munificent) 与 龙书 (Aho et al., 《Compilers: Principles, Techniques, and Tools》)。

## 一、背景与挑战
正则表达式用于描述"正则语言"，是词法分析的理论基础。挑战在于：正则语言只能表达有限状态可识别的模式，无法处理需要计数或嵌套的结构（如配对的括号 `((()))`）。实际中 PCRE 等扩展了反向引用，使其超出严格正则语言范畴，并可能带来指数级回溯代价。

## 二、核心原理
正则语言由字母表 $\Sigma$ 上的正则运算构造：空集 $\emptyset$、空串 $\epsilon$、单字符 $a\in\Sigma$，以及并 $R_1\mid R_2$、连接 $R_1R_2$、闭包 $R_1^*$。每个正则表达式是有限自动机的紧凑记法。

## 三、形式化 / 数学基础
正则表达式 $R$ 定义的语言 $L(R)$ 递归定义：
- $L(\emptyset)=\varnothing$
- $L(\epsilon)=\{\epsilon\}$
- $L(a)=\{a\}$
- $L(R_1\mid R_2)=L(R_1)\cup L(R_2)$
- $L(R_1R_2)=\{xy\mid x\in L(R_1), y\in L(R_2)\}$
- $L(R_1^*)=\bigcup_{i\ge 0}L(R_1)^i$

Kleene 定理：正则语言、正则表达式中、有限自动机三者等价。

## 四、代码实现
```python
import re
pat = re.compile(r"(?P<num>\d+)\.(?P<num>\d+)")  # 匹配小数
m = pat.match("3.14")
print(m.group("num"))  # 第一次捕获 3
```
注意 `re` 默认贪婪，量词后加 `?` 变为懒惰匹配。

## 五、与其他技术对比
- DFA：确定性、无回溯、线性时间，但构造可能状态爆炸。
- NFA：非确定性、可用子集构造转 DFA。
- 回溯引擎（PCRE）：支持反向引用，但最坏指数时间。
- 解析器（CFG）：可表达嵌套/计数，正则做不到。

## 六、常见误区
1. 认为正则能匹配任意嵌套结构——严格正则语言不能。
2. 给用户输入套用复杂回溯正则导致 ReDoS（灾难性回溯）。
3. 混淆 `*`（零次或多次）与 `+`（一次或多次）。

## 九、演进与趋势
RE2（Russ Cox）采用 Thompson NFA 保证线性时间；Rust 的 `regex` crate 也禁用回溯；Unicode 属性类（\p{...}）使正则更贴合真实文本。

## 十、小结
正则表达式是词法分析的数学根基，三等价（正则式/正则语言/有限自动机）是理解扫描器的钥匙；工程上需在表达力与匹配复杂度之间权衡。
