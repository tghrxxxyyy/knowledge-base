# 实用词法器实现

> 对应 Crafting Interpreters 手写扫描器（Lox）。

## 一、背景与挑战
手写扫描器常用于解释器/编译器前端。挑战：正确处理空白与注释跳过、行号列号跟踪、错误报告、关键字 vs 标识符区分、以及多字符符号（`<=`、`!=`）。

## 二、核心原理
维护 `start`、`current`、`line` 指针；`advance()` 取字符，`match()` 试探下一字符，返回 Token 流。关键字用哈希表从标识符查表得到。

## 三、形式化 / 数学基础
扫描器是 DFA 的显式实现：$s_0$ 为"起始"，每 `advance` 改变状态；当无转移且当前累加串在关键字表/标识符规则中即产出 Token 并回到 $s_0$。

## 四、代码实现
```python
KEYWORDS = {"if","else","while","return","print"}
def scan(src):
    toks, i, n = [], 0, len(src)
    while i < n:
        c = src[i]
        if c.isalpha():
            j = i
            while j < n and src[j].isalnum(): j += 1
            word = src[i:j]
            toks.append(("KW" if word in KEYWORDS else "ID", word))
            i = j
        elif c.isspace():
            i += 1
        else:
            toks.append(("PUNCT", c)); i += 1
    return toks
```

## 五、与其他技术对比
- 手写：可读、易调试、可定制宜错误处理；flex 生成：规格改动快、性能略好。
- 单遍 vs 两遍：多数解释器单遍产出 Token 流供解析器消费。

## 六、常见误区
1. 错误位置用"消费后"指针导致行列号偏 1。
2. 关键字当标识符：漏查关键字表。
3. 多字符符号只判单字符（`<` 漏 `<=`）。

## 十、小结
实用扫描器是 DFA 的可读实现：指针 + 关键字表 + 多字符符号处理即可支撑多数语言；手写在可维护性上往往优于生成器。
