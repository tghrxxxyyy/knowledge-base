# 最长匹配与贪心

> 对应 龙书 词法分析规则 与 正则匹配语义。

## 一、背景与挑战
"最长匹配" (maximal munch)：扫描器取能匹配的最长前缀；正则"贪婪"指量词尽量多吃输入。二者常被混淆，但分别作用于"词法规则选择"和"单条正则的重复次数"。

## 二、核心原理
词法层：若多条规则接受同一前缀，选匹配长度最大者；长度相同选规格中先出现的规则。正则层：量词 `*`/`+`/`?` 默认贪婪，尽量扩展匹配；加 `?` 变懒惰。

## 三、形式化 / 数学基础
设规则集 $R_k$ 在位置 $i$ 的匹配长度为 $\ell_k$。选择
$\arg\max_k \ell_k$，平局取 $\min k$（先定义者）。
正则贪心：$L(a^*)$ 取最长 $a$-串；懒惰 $a*?$ 取最短。

## 四、代码实现
```python
import re
print(re.match(r"<.*>", "<a> <b>").group())   # 贪婪: "<a> <b>"
print(re.match(r"<.*?>", "<a> <b>").group())  # 懒惰: "<a>"
```

## 五、与其他技术对比
- 最长匹配（词法）：保证 `==` 不被拆成两个 `=`。
- 贪婪（正则）：影响单规则内捕获范围。
- POSIX 语义：在所有最长匹配中再选"最左最长子表达式"，与 Perl 风格不同。

## 六、常见误区
1. 把正则贪婪当成词法最长匹配——层级不同。
2. 在 HTML/XML 用贪婪 `.*` 跨标签匹配出错。
3. 忘记 POSIX 与 PCRE 在歧义时的不同抉择。

## 九、演进与趋势
possessive 量词 `++`/`*+`（Java/PCRE）占有式匹配杜绝回溯；原子组 `(?>...)` 用于性能敏感扫描。

## 十、小结
最长匹配决定词素边界，贪婪决定正则内部重复范围；理解两者层次是写对扫描器与正则的前提。
