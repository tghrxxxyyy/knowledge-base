# 后缀树与后缀数组的等价性

> 对应 CLRS。

## 一、背景与挑战
后缀树与后缀数组看似两种结构，但本质上编码了同一信息。理解其等价性有助于在「树」与「数组」表示间自由转换。

## 二、核心原理
后缀树的叶子按字典序做先序遍历（DFS），得到的叶子顺序恰好是后缀数组。相邻两个叶子在树上的最近公共祖先深度，正好等于它们之间高度数组 $lcp$ 的值。

## 三、形式化与数学基础
设树中从根到叶子 $SA[i]$ 的路径长度为 $|s|-SA[i]$。两后缀 $SA[i],SA[j]$ 的 LCP 长度等于它们 LCA 的深度：
${\rm LCP}(i,j)={\rm depth}({\rm LCA}(SA[i],SA[j]))$。
由高度数组做笛卡尔树得到的正是后缀树的拓扑，故二者同构。

## 四、代码实现
```python
def sa_to_tree_topology(sa, lcp):
    # 笛卡尔树：以 lcp 为键值的最小堆，即后缀树拓扑
    n = len(lcp)
    parent = [-1] * n
    stack = []
    for i in range(n):
        last = -1
        while stack and lcp[stack[-1]] > lcp[i]:
            last = stack.pop()
        if stack:
            parent[i] = stack[-1]
        if last != -1:
            parent[last] = i
        stack.append(i)
    return parent
```

## 五、与其他技术对比
后缀树显式存边、便于遍历所有子串；后缀数组更省空间、可配合 RMQ 做任意 LCP 查询。等价性意味着二者可互相模拟。

## 六、常见误区
误以为后缀树节点数等于后缀数组长度：后缀树内部节点数 $O(n)$，而 SA/LCP 长度为 $n$。混淆 DFS 序与排名序也会导致取错。

## 七、与开源书/权威来源对应
CLRS 第 32 章讨论后缀树与后缀数组；Sedgewick《Algorithms》给出二者转换示例。

## 八、面试题
如何由后缀数组在 $O(n)$ 重建后缀树拓扑？反过来由后缀树如何得 SA？

## 九、演进与趋势
现代实现常只存后缀数组 + LCP（省内存），需要时按需构树或用后缀自动机替代。

## 十、小结
后缀树与后缀数组是同构的字符串索引：DFS 序给出 SA，LCA 深度给出 LCP，二者可线性互转。
