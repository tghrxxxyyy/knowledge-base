# 非聚簇索引叶子节点结构

> 对应 MySQL InnoDB 官方文档「Secondary Index Structure」与 Silberschatz 第11章 B+Tree。

## 一、背景与挑战
理解二级（非聚簇）索引叶子节点的精确内容，是设计索引、预估索引大小、解释回表行为的底层基础。

## 二、核心原理
InnoDB 二级索引的每一层节点按「索引列值」排序，叶子节点条目为 `(索引列值, 主键值)`。若索引列有重复值，则靠主键值进一步排序以保证唯一有序。非叶子节点存 `(索引列值, 子页号)`。

## 三、形式化与数学基础
二级索引叶子条目大小：
$$ entry\_size = \sum col_i\_size + pk\_size + rec\_overhead $$
索引总页数随行数 $N$ 与条目大小近似线性：
$$ Pages \approx \frac{N \cdot entry\_size}{page\_usable} $$

## 四、代码实现
```sql
-- 联合二级索引叶子按 (a,b,pk) 排序
CREATE INDEX idx_ab ON t(a, b);
-- 唯一约束索引额外保证 a 唯一，但叶子仍带 pk
```

## 五、与其他技术对比
MyISAM 非聚簇索引叶子存行文件偏移，不含主键概念（除非显式建主键索引）。InnoDB 因聚簇特性，所有二级索引都「指向主键」而非行地址。

## 六、常见误区
认为二级索引叶子存整行——只存索引列与主键。认为索引列 NULL 不被索引——InnoDB 索引包含 NULL 且视作最小值。

## 七、与开源书/权威来源对应
InnoDB 文档「Secondary Indexes」；Silberschatz 11.3。

## 八、面试题
问：二级索引为什么必须含主键？答：用于回表定位聚簇行，也保证叶子条目全局有序唯一。

## 九、演进与趋势
INCLUDE 非键列让叶子可额外存覆盖列而不参与排序键，平衡覆盖能力与排序宽度。

## 十、小结
二级索引叶子 = 索引列 + 主键，这一结构决定了回表机制与索引体积。
