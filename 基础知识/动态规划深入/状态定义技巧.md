# 状态定义技巧

> 对应 《算法竞赛进阶指南》（李煜东）动态规划状态设计章节，与 CP-Algorithms / LeetCode 状态机 DP 专题。

## 一、背景与挑战

同一道题，状态定义不同，复杂度与实现难度可以天差地别。最经典的例子是最长上升子序列：`dp[i]` 表示「以 $i$ 结尾的 LIS 长度」得 $O(n^2)$；换成 `tails[len]` 表示「长度为 $len$ 的 LIS 最小结尾」，二分替换后是 $O(n \log n)$。又如股票买卖：若状态只写 `dp[i]` 第 $i$ 天收益，根本无法转移；写成 `dp[i][k][0/1]` 表示第 $i$ 天、剩 $k$ 次交易、是否持有，才把约束完整编码进状态。

背景痛点是：**转移方程本身往往不难，难在「状态要表示什么」**。状态维度太多会 MLE/TLE；太少则信息丢失、转移写不出来；错把「过程量」当状态、或把可由其它维度推出的冗余维度塞进状态，都会让实现变成灾难。面试里，面试官常让你「先定义状态再写转移」，就是要考察你是否能把问题约束翻译成状态维度。

工程与竞赛语境中，状态设计是 DP 的灵魂技能。数位 DP 的 `pos/tight/lead/mask`、区间 DP 的 `f[i][j]`、背包的「容量」维、状态压缩的「集合掩码」，都是成熟套路。读完本篇，你应能对陌生问题快速给出「状态要区分哪些信息」的清单，并知道如何用维度守恒、滚动数组、状态压缩、状态机编码等技巧把状态塑造成可转移的形态。

## 二、核心原理

**维度守恒**。状态必须恰好区分「影响未来决策」的信息，不多不少。问自己：若两个历史轨迹在「状态」处合并，它们对未来的最优选择是否总是相同？若相同，可以合并（省维度）；若不同，必须再加一维区分（不丢信息）。

**把限制条件转化为状态**。「恰好选 $k$ 个」→ 加一维 `cnt`；「不能连续选」→ 加一维 `prev_selected` 或改写转移；「区间合并」→ 状态是区间端点 `f[i][j]`；「集合选择」→ 位掩码 `mask`。限制若只影响单步转移，可放进转移判断；若影响「后续可达性」，必须进状态。

**常用状态形状**。
1. **前缀/序列型**：`dp[i]` 做到第 $i$ 个，或 `dp[i][0/1]` 末尾选/不选。
2. **背包型**：`dp[c]` 容量为 $c$ 的最优，或 `dp[i][c]` 前 $i$ 件。
3. **区间型**：`dp[i][j]` 区间 $[i,j]$ 的最优，枚举断点 $k$。
4. **集合型**：`dp[mask][i]` 已选集合 $mask$、当前在 $i$。
5. **数位型**：`dp[pos][tight][lead][mask]` 枚举到第 $pos$ 位、是否贴上界、是否有前导零、已用数字集合。
6. **状态机型**：`dp[i][s]` 第 $i$ 步后处于状态 $s$（如股票 `s ∈ {hold, sold, cooldown}`）。
7. **树上型**：`dp[u][0/1]` 子树 $u$、根选/不选。

**边界与初始化**。`dp[0]`、空集、空区间、根节点的初值必须显式定义，否则边界泄漏。负无穷/正无穷的语义（不可达 vs 代价无穷）要统一。

**滚动数组**。若转移只依赖上一行/上一阶段，可把二维压成一维，空间 $O(\text{最后一维})$。注意背包倒序、区间 DP 的长度循环方向。

## 三、形式化与数学基础

**状态空间大小**。若第 $i$ 维取值 $n_i$，则总状态数
$$
S = \prod_{i=1}^{d} n_i, \qquad \text{时间} = O(S \cdot A), \quad A = \text{单状态转移数}.
$$
目标是让 $S \cdot A$ 落在时限内。多一维常让 $S$ 乘以 $n$，故「维度守恒」直接决定能否过。

**数位 DP 的状态**。$dp[pos][tight][lead][mask]$：
- $pos$：当前填到高位第几位；
- $tight$：是否仍贴着上界，决定下一位上限；
- $lead$：是否有前导零（影响 0 是否计入 mask）；
- $mask$：已出现数字的位集。
状态数约 $L \cdot 2 \cdot 2 \cdot 2^{10}$，$L \le 20$ 时完全可行。转移：
$$
dp[pos][t][l][m] = \sum_{d=0}^{up} dp[pos+1][t \wedge (d=up),\ l \wedge (d=0),\ m']}
$$
其中 $up = (tight ? s[pos] : 9)$，$m'$ 是更新后的 mask。

**股票买卖（$k$ 次交易）**。状态 $dp[i][j][0/1]$：第 $i$ 天结束、已完成 $j$ 次卖出、当前是否持有。转移：
$$
\begin{aligned}
dp[i][j][0] &= \max(dp[i-1][j][0],\ dp[i-1][j][1] + price_i), \\
dp[i][j][1] &= \max(dp[i-1][j][1],\ dp[i-1][j-1][0] - price_i).
\end{aligned}
$$
状态空间 $O(n \cdot k)$；$k \ge n/2$ 时退化为无限次交易（贪心累加正差）。维度「0/1 持有」是把「能否卖」编码进状态的典型。

**LIS 的两种状态**。
$$
dp[i] = 1 + \max_{j < i,\ a_j < a_i} dp[j] \quad (O(n^2)).
$$
优化：$tails[len] = \min$ 可能的结尾值，$len$ 递增，二分找第一个 $\ge a_i$ 的位置替换，长度即 LIS。状态从「位置」换成「长度」，把 $O(n)$ 枚举换成 $O(\log n)$，依赖 $tails$ 单调性。

**滚动背包**。二维 $dp[i][c] = \max(dp[i-1][c], dp[i-1][c-w_i]+v_i)$ 可压成一维，但循环顺序必须反映依赖：
- 0/1 背包：$c$ 从 $C$ 到 $w_i$ 倒序；
- 完全背包：$c$ 从 $w_i$ 到 $C$ 正序。
形式上，倒序等价于「使用 $dp[i-1][\cdot]$」，正序等价于「可复用 $dp[i][\cdot]$」。

## 四、代码实现

两个完整例子：数位 DP（统计 $[0,n]$ 中含至少一个某数字的数）与股票买卖含冷冻期的状态机 DP。

```python
"""状态定义技巧：数位 DP 与股票状态机 DP。"""
from __future__ import annotations

from functools import lru_cache


# ---------- 1. 数位 DP：统计 [0, n] 中数位集合非空的数（即 >0） ----------
def count_up_to(n: int) -> int:
    """返回 [0, n] 中正整数个数（用以演示数位状态；等于 n）。"""
    if n < 0:
        return 0
    s = str(n)

    @lru_cache(maxsize=None)
    def dfs(pos: int, tight: bool, lead: bool, mask: int) -> int:
        if pos == len(s):
            # 到末位：若不是纯前导零（mask>0），则构成一个数
            return 1 if mask > 0 else 0
        up = int(s[pos]) if tight else 9
        total = 0
        for d in range(up + 1):
            ntight = tight and (d == up)
            nlead = lead and (d == 0)
            nmask = mask
            if not nlead:
                nmask |= 1 << d
            total += dfs(pos + 1, ntight, nlead, nmask)
        return total

    return dfs(0, True, True, 0)


def count_with_digit(n: int, digit: int) -> int:
    """[0,n] 中十进制表示包含 digit 的正整数个数。"""
    if n < 0:
        return 0
    s = str(n)

    @lru_cache(maxsize=None)
    def dfs(pos: int, tight: bool, lead: bool, seen: bool) -> int:
        if pos == len(s):
            return 1 if (seen and not lead) else 0
        up = int(s[pos]) if tight else 9
        total = 0
        for d in range(up + 1):
            ntight = tight and (d == up)
            nlead = lead and (d == 0)
            nseen = seen or (d == digit and not nlead)
            total += dfs(pos + 1, ntight, nlead, nseen)
        return total

    return dfs(0, True, True, False)


# ---------- 2. 股票买卖含冷冻期（LeetCode 309） ----------
def max_profit_with_cooldown(prices: list[int]) -> int:
    """
    状态机：
      hold:   手上持有股票的最大收益
      sold:   今天刚卖出（之后有冷冻期）
      rest:   冷冻期结束/不持有，可买
    """
    if not prices:
        return 0
    hold = -prices[0]
    sold = float("-inf")
    rest = 0
    for p in prices[1:]:
        prev_hold, prev_sold, prev_rest = hold, sold, rest
        hold = max(prev_hold, prev_rest - p)          # 继续持有 或 今天买入
        sold = prev_hold + p                          # 今天卖出
        rest = max(prev_rest, prev_sold)              # 继续休息 或 冷冻结束
    return max(hold, sold, rest)


# ---------- 3. 股票买卖 k 次交易（LeetCode 188） ----------
def max_profit_k_transactions(prices: list[int], k: int) -> int:
    n = len(prices)
    if n == 0 or k == 0:
        return 0
    if k >= n // 2:
        return sum(max(0, prices[i + 1] - prices[i]) for i in range(n - 1))
    # dp[j] = 完成 j 次卖出且不持有；buy[j] = 完成 j 次卖出后持有
    dp = [0] * (k + 1)
    buy = [float("-inf")] * (k + 1)
    for p in prices:
        for j in range(1, k + 1):
            # 注意倒序更新，避免同一天买+卖
            dp[j] = max(dp[j], buy[j] + p)
            buy[j] = max(buy[j], dp[j - 1] - p)
    return dp[k]


if __name__ == "__main__":
    assert count_up_to(0) == 0
    assert count_up_to(9) == 9
    assert count_up_to(20) == 20
    print("count_up_to(100) =", count_up_to(100))
    print("count with digit 7 in [0,100]:", count_with_digit(100, 7))

    assert max_profit_with_cooldown([1, 2, 3, 0, 2]) == 3
    assert max_profit_k_transactions([2, 4, 1], 2) == 2
    assert max_profit_k_transactions([3, 2, 6, 5, 0, 3], 2) == 7
    print("all ok")
```

数位 DP 用 `tight/lead/seen` 三维编码「是否贴上界、前导零、是否已出现目标数字」，这正是维度守恒的体现：少了 `tight` 会重复计数，少了 `lead` 会把 0 误判为出现。

## 五、与其他技术对比

| 技巧 | 状态形状 | 时间 | 空间 | 典型场景 |
|------|----------|------|------|----------|
| 朴素二维 DP | `dp[i][j]` | $O(nC)$ | $O(nC)$ | 背包、编辑距离 |
| 滚动数组 | `dp[j]` | 同左 | $O(C)$ | 只依赖上一行 |
| 状态压缩 | `dp[mask][i]` | $O(2^n n)$ | $O(2^n n)$ | TSP、集合覆盖 |
| 状态机 DP | `dp[i][s]` | $O(n|S|)$ | $O(|S|)$ | 股票、打家劫舍 III |
| 数位 DP | `dp[pos][tight][lead][mask]` | $O(L \cdot 2 \cdot 2 \cdot 2^{10})$ | 同左 | 数字计数、数码统计 |
| 区间 DP | `dp[i][j]` | $O(n^3)$ | $O(n^2)$ | 矩阵链、石子合并 |
| 数据结构优化 | `dp[i] + query` | $O(n \log n)$ | $O(n)$ | 单调队列、线段树优化 |

与暴力搜索对比：状态压缩把「子集枚举」变成整数索引，天然去重；与 BFS 对比：DP 强调无后效性最优值累积，BFS 用于无权/等权最短路。与贪心对比：状态机 DP 允许比较所有分支，贪心只选局部最优。

## 六、常见误区

**状态维度过多导致 MLE/TLE**。把可推导的冗余量（如「已选元素和」若等于容量）也塞进状态，状态空间爆炸。后果是内存超限。应做维度守恒：可由其它维度算出的就不要单独存。

**忘记 `tight` 或 `lead`（数位 DP）**。不贴紧上界却按上界枚举会重复计数；不处理前导零会把 `007` 与 `7` 混淆。后果是计数结果偏大/偏小。用 `lru_cache` 时参数必须完整包含这些标志。

**状态机转移写错冷冻期/卖出后不可立即买**。把 `sold` 与 `rest` 混成一个状态，会在卖出当天又买入。后果是收益偏大（错误地允许违规交易）。必须把「刚卖出」独立成状态。

**滚动数组方向错**。0/1 背包正序遍历变成完全背包；区间 DP 的长度维递减导致依赖未就绪。后果是答案系统性偏差。依赖只来自上一阶段时倒序，依赖来自本阶段时正序。

**位运算优先级**。`mask & 1 << i` 在 Python 中是 `mask & (1 << i)`，但 C/C++ 中是 `(mask & 1) << i`。后果是掩码逻辑错乱。用括号明确写 `mask & (1 << i)`。

## 八、面试题

**1. 股票买卖 $k$ 次交易如何定义状态？**
参考答案：`dp[i][j][0/1]` 第 $i$ 天、已完成 $j$ 次卖出、是否持有。或滚动成 `dp[j]`、`buy[j]`。转移：今天卖 `dp[j] = max(dp[j], buy[j]+p)`，今天买 `buy[j] = max(buy[j], dp[j-1]-p)`。$k \ge n/2$ 退化为无限次贪心。

**2. 数位 DP 的状态为什么要 `tight` 与 `lead`？**
参考答案：`tight` 表示仍贴着上界，决定下一位上限，否则会枚举到大于 $n$ 的数；`lead` 区分前导零与真实数字 0，影响「是否出现过某数字」等统计。二者缺一都会计数错误。

**3. 状态定义多了维度会怎样？少了呢？**
参考答案：多维度状态空间乘积增大，MLE/TLE；少维度信息不足，转移无法表达（无法区分未来不同的历史）。目标是「恰好」：两个历史若未来决策总相同，应合并；否则必须区分。

**4. 什么时候用滚动数组？**
参考答案：转移只依赖上一阶段（上一行/上一件物品）时可压缩一维。0/1 背包倒序、完全背包正序。区间 DP 依赖 `len-1`，需按长度递增填。

## 九、演进与趋势

**自动状态机 + DP**。把转移写成自动机（AC 自动机、后缀自动机）上的 DP，处理「模式匹配计数」「带禁止子串」等约束，状态是自动机节点。

**$(\min, +)$ 卷积与半环 DP**。把转移统一成代数运算，批量优化（如 $O(n^{3/2})$ 的 min-plus 乘积），用于最短路、编辑距离、子序列匹配。

**数据结构优化 DP**。线段树/树状数组/平衡树维护区间最优，把 $O(n^2)$ 转移降到 $O(n \log n)$；单调队列、凸壳处理决策单调。

**外存与并行状态空间**。状态爆炸时分层、分块、meet-in-the-middle，或 GPU 并行填表。

**学习型状态压缩**。用嵌入/哈希把高维状态映到低维近似，或用神经网络学价值函数，在游戏、推荐、控制中做近似 DP。

## 十、小结

状态定义是 DP 的灵魂：用维度守恒精确编码「影响未来的信息」，把限制翻译进状态（`tight/lead/mask/0-1`），用滚动数组与状态压缩控空间，用状态机处理交易约束。状态形状决定复杂度上限，转移只是在形状上填表。少一维信息丢失、多一维空间爆炸——先想清「状态表示什么」，再写转移方程。
