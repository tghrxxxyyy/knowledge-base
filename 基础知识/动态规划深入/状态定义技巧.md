# 状态定义技巧

> 对应 《算法竞赛进阶指南》动态规划状态设计章节。

## 一、背景与挑战
同样的题，状态定义不同复杂度天差地别。常见维度包括：前缀/后缀、差值、余数、集合（二进制）、数位。

## 二、核心原理
「维度守恒」：需要区分的信息必须进入状态，冗余维度浪费空间。常用技巧：把限制条件转化为状态的一维。

## 三、形式化 / 数学基础
数位 DP 用 `dp[pos][tight][lead][mask]` 表示枚举到第 pos 位、是否贴紧上界、是否前导零、已出现数字集合。
集合维度用位掩码：$mask\in[0,2^n)$，第 k 位表示元素 k 是否已选。

## 四、代码实现
```python
def count_numbers_up_to(n):
    s = str(n)
    from functools import lru_cache
    @lru_cache(None)
    def dfs(pos, tight, lead, mask):
        if pos == len(s):
            return 1 if mask > 0 else 0
        up = int(s[pos]) if tight else 9
        res = 0
        for d in range(up + 1):
            nt = tight and d == up
            nl = lead and d == 0
            nm = mask
            if not nl:
                nm |= 1 << d
            res += dfs(pos + 1, nt, nl, nm)
        return res
    return dfs(0, True, True, 0)
```

## 五、与其他技术对比
与暴力枚举相比，状态压缩把集合信息压成整数，转移用位运算；与 BFS 最短路相比，DP 强调无后效性的最优值累积。

## 六、常见误区
状态维度过多导致 MLE/超时；忘记处理前导零或上界紧贴；位运算写错（遗漏或重复置位）。

## 九、演进与趋势

## 十、小结
状态定义是 DP 的灵魂：多一维可能爆空间，少一维则信息丢失，应使状态「恰好」区分必要信息。
