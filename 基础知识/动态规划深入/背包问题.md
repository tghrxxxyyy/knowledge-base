# 背包问题

> 对应 CLRS《Introduction to Algorithms》第 16 章与《背包九讲》（崔添翼），以及 Garey & Johnson《Computers and Intractability》中的 NP-hard 问题分类。

## 一、背景与挑战

背包问题是动态规划的入门范式，也是资源分配类问题的统一抽象：给定 $n$ 件物品（重量 $w_i$、价值 $v_i$）与容量 $C$，在不超过容量的前提下选若干件，使总价值最大。它的变体几乎覆盖了工程中的常见约束：**0/1 背包**（每件最多一次）、**完全背包**（每件无限次）、**多重背包**（每件限 $s_i$ 次）、**分组背包**（每组选一件）、**依赖背包**（选子节点必须选父节点）。零钱兑换、分割等和子集、任务调度、负载均衡、广告库存分配，都能翻译成某个背包变体。

朴素做法是指数级枚举：$2^n$ 种子集，$n=50$ 就跑不动。更糟的是很多人误用贪心——按性价比 $v_i/w_i$ 排序取前若干——这对**分数背包**（物品可拆）正确，对 0/1 背包会错：高性价比物品太重，装一件就把容量占满，反而不如两件稍低性价比的小件。这个反例是面试中的经典陷阱。

在工程与面试语境中，背包是「DP 入门必考」与「资源分配模板」。面试官常让你写 0/1 背包一维滚动、解释完全背包正序原因、或把「零钱兑换」「目标和」识别为背包计数。读完本篇，你应能对每个变体写出正确转移、说出复杂度、并知道多重背包二进制拆分与单调队列优化的适用边界。

## 二、核心原理

**状态定义**。$dp[i][c]$：考虑前 $i$ 件物品、剩余容量 $c$ 时的最大价值。转移：
$$
dp[i][c] = \max \big( dp[i-1][c],\ dp[i-1][c - w_i] + v_i \big),
$$
即「不选第 $i$ 件」与「选第 $i$ 件」的最优。边界 $dp[0][c] = 0$，答案 $dp[n][C]$。

**一维滚动**。转移只依赖上一行，可压成 `dp[c]`：
- **0/1 背包**：容量 $c$ 从 $C$ 到 $w_i$ **倒序**，保证 `dp[c-w_i]` 来自上一轮（每件最多一次）。
- **完全背包**：容量 $c$ 从 $w_i$ 到 $C$ **正序**，允许同一物品重复使用。

这是背包问题最易错、也最常考的细节：**遍历方向决定物品能否重复**。

**多重背包**。每件最多 $s_i$ 次。朴素是把每件拆成 $s_i$ 个 0/1 物品，$O(n s_i C)$。**二进制拆分**：把 $s_i$ 个拆成 $1, 2, 4, \ldots, 2^k, r$ 份，$O(\log s_i)$ 件 0/1 物品即可组合出任意次数，总复杂度 $O(n C \log s)$。**单调队列优化**把每件物品按容量模 $w_i$ 分组，组内用单调队列维护窗口最值，达到 $O(n C)$。

**分组背包**。每组至多选一件：$dp[c] = \max_{i \in \text{group}} (dp[c - w_i] + v_i)$，注意组内物品要用「上一阶段」的 `dp`，可倒序或用临时数组。

**可行性 / 计数 / 最值**。同一框架下转移算子不同：
- 最值：$\max$
- 计数方案数：$\sum$
- 可行性：$\mathrm{or}$
例如「分割等和子集」是可行性 0/1 背包，「零钱兑换 II」是完全背包计数。

**不变量**。一维滚动时，`dp[c]` 在处理第 $i$ 件前代表前 $i-1$ 件的最优；倒序保证不重复用本件，正序保证可重复。容量必须 $\ge w_i$ 才能选，循环下界是 `w[i]`。

## 三、形式化与数学基础

**递推与复杂度**。二维 $dp[i][c]$ 的状态数 $O(nC)$，单状态转移 $O(1)$，总时间 $O(nC)$、空间 $O(nC)$。滚动后空间 $O(C)$。这是**伪多项式时间**：$C$ 是数值大小，若 $C$ 以二进制输入、$C \sim 2^{60}$，则 $O(nC)$ 不可行。0/1 背包是 NP-hard，存在 $O(2^{n/2})$ 的 meet-in-the-middle 与 FPTAS。

**完全背包的收敛**。正序遍历时，`dp[c]` 允许物品 $i$ 被用任意次，等价于
$$
dp[c] = \max_{k \ge 0} \big( k \cdot v_i + dp_{\text{prev}}[c - k w_i] \big).
$$
这与「无界整数划分」的生成函数视角一致。

**二进制拆分的正确性**。任意整数 $s \le 2^{k+1}-1$ 可表示为 $\sum_{j=0}^{k} b_j 2^j + r$（$r < 2^{k+1}$）。拆成重量 $2^j w$、价值 $2^j v$ 的若干件，可组合出 $0..s$ 的任意次数，且不引入多于 $s$ 的使用。件数 $O(\log s)$，总复杂度从 $O(n s C)$ 降到 $O(n C \log s)$。

**多重背包单调队列优化**。对固定物品 $i$，$dp[c] = \max_{0 \le k \le s_i, k w_i \le c} (dp_{\text{prev}}[c - k w_i] + k v_i)$。令 $c = q w_i + r$，$q = \lfloor c/w_i \rfloor$，则
$$
dp[c] = \max_{k} \big( dp_{\text{prev}}[(q-k) w_i + r] + (q-k) v_i \big) + k' v_i,
$$
对每个剩余类 $r$，用单调队列在滑动窗口 $[q-s_i, q]$ 上维护最大值，总 $O(n C)$。

**分数背包的贪心**。按 $v_i/w_i$ 降序，装满为止，可证明最优（交换论证）。0/1 不行：反例 $w=[3,2,2], v=[5,2,2], C=4$，贪心取 3 的只得 5，取两个 2 的得 4？等下，[2,2] 是 4，[3] 是 5，贪心对了。经典反例：$w=[3,2,2], v=[6,2,2], C=4$，性价比 2 vs 1 vs 1，贪心取 3 得 6，取两个 2 得 4。仍是贪心对。真正的反例是性价比高但太重：$w=[10,9], v=[10,9], C=9$，贪心按性价比相同，任意；改 $w=[10,6], v=[10,6], C=12$，贪心装 10，另一方案 6+6 无。经典反例应为：$w=[3,2,2], v=[4,3,3], C=4$：性价比 4/3≈1.33, 1.5, 1.5，贪心装 $v=4$ 得 4，装两个 2 得 6。正确！

**可行性判定**。布尔背包 `dp[c] = dp[c] or dp[c-w_i]`，bitset 加速后复杂度 $O(nC/w)$（按字长 $w=64$），常数降 64 倍。

## 四、代码实现

完整背包模板：0/1、完全、多重（二进制拆分 + 单调队列）、分组、可行性、计数。可直接运行。

```python
"""背包问题：0/1、完全、多重（二进制拆分 / 单调队列）、分组、计数。"""
from __future__ import annotations

from collections import deque


def knapsack_01(weights: list[int], values: list[int], capacity: int) -> int:
    dp = [0] * (capacity + 1)
    for w, v in zip(weights, values):
        for c in range(capacity, w - 1, -1):
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[capacity]


def knapsack_complete(weights: list[int], values: list[int], capacity: int) -> int:
    dp = [0] * (capacity + 1)
    for w, v in zip(weights, values):
        for c in range(w, capacity + 1):   # 正序：物品可重复
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[capacity]


def knapsack_multiple_binary(weights, values, limits, capacity: int) -> int:
    """多重背包：二进制拆分成 0/1 物品。"""
    dp = [0] * (capacity + 1)
    for w, v, s in zip(weights, values, limits):
        k = 1
        while s > 0:
            take = min(k, s)
            s -= k
            k <<= 1
            ww, vv = w * take, v * take
            for c in range(capacity, ww - 1, -1):
                dp[c] = max(dp[c], dp[c - ww] + vv)
    return dp[capacity]


def knapsack_multiple_queue(weights, values, limits, capacity: int) -> int:
    """多重背包：按重量模 w 分组，单调队列维护窗口最大值，O(nC)。"""
    dp = [0] * (capacity + 1)
    for w, v, s in zip(weights, values, limits):
        if w == 0:
            continue
        new_dp = dp[:]
        for r in range(w):
            # 队列存候选下标 q，对应容量 c = q*w + r
            dq: deque[int] = deque()
            q = 0
            while True:
                c = q * w + r
                if c > capacity:
                    break
                # 候选值：dp_prev[c - k*w] + k*v  =  dp[c] + q*v  的线性形式
                # 维护 val(q) = dp[c] - q * v 的单调递减队列，窗口宽度 s
                val = dp[c] - q * v
                while dq and dp[dq[-1] * w + r] - dq[-1] * v <= val:
                    dq.pop()
                dq.append(q)
                while dq and dq[0] < q - s:
                    dq.popleft()
                best = dp[dq[0] * w + r] + (q - dq[0]) * v
                new_dp[c] = max(new_dp[c], best)
                q += 1
        dp = new_dp
    return dp[capacity]


def knapsack_group(groups: list[list[tuple[int, int]]], capacity: int) -> int:
    """分组背包：每组至多选一件。groups = [[(w,v), ...], ...]"""
    dp = [0] * (capacity + 1)
    for group in groups:
        new_dp = dp[:]
        for w, v in group:
            for c in range(capacity, w - 1, -1):
                new_dp[c] = max(new_dp[c], dp[c - w] + v)
        dp = new_dp
    return dp[capacity]


def subset_sum_possible(nums: list[int], target: int) -> bool:
    """可行性 0/1 背包：分割等和子集 / 目标和判定。"""
    dp = [False] * (target + 1)
    dp[0] = True
    for x in nums:
        for c in range(target, x - 1, -1):
            dp[c] = dp[c] or dp[c - x]
    return dp[target]


def coin_change_ways(coins: list[int], amount: int) -> int:
    """完全背包计数：凑成 amount 的组合数（顺序无关）。"""
    dp = [0] * (amount + 1)
    dp[0] = 1
    for coin in coins:
        for a in range(coin, amount + 1):
            dp[a] += dp[a - coin]
    return dp[amount]


if __name__ == "__main__":
    # 0/1 背包经典例
    w = [2, 3, 4, 5]
    v = [3, 4, 5, 6]
    assert knapsack_01(w, v, 8) == 10

    # 完全背包：物品可重复
    assert knapsack_complete(w, v, 8) == 12  # 4 个 2 → 12

    # 多重背包两种实现应一致
    mw = [1, 2, 3]
    mv = [1, 2, 3]
    ms = [3, 2, 1]
    a = knapsack_multiple_binary(mw, mv, ms, 6)
    b = knapsack_multiple_queue(mw, mv, ms, 6)
    assert a == b, (a, b)
    print("multiple:", a)

    # 分组背包
    groups = [[(2, 3), (3, 4)], [(1, 1), (4, 8)]]
    print("group:", knapsack_group(groups, 7))

    assert subset_sum_possible([1, 5, 11, 5], 11)
    assert not subset_sum_possible([1, 2, 3, 5], 20)

    assert coin_change_ways([1, 2, 5], 5) == 4
    print("all ok")
```

多重背包的单调队列实现对每个重量模类维护 `dp_prev[c] - q*v` 的单调队列，窗口宽度为限次 $s$，经典用例与二进制拆分结果一致。

## 五、与其他技术对比

| 变体 | 物品可用次数 | 遍历方向 | 复杂度 | 典型题 |
|------|--------------|----------|--------|--------|
| 0/1 背包 | 0 或 1 | 容量倒序 | $O(nC)$ | 分割等和子集、目标和 |
| 完全背包 | 无限 | 容量正序 | $O(nC)$ | 零钱兑换、完全平方数 |
| 多重背包 | $\le s_i$ | 二进制拆分/单调队列 | $O(nC\log s)$ / $O(nC)$ | 库存分配、买书 |
| 分组背包 | 每组 0 或 1 | 组间阶段化 | $O(nC)$ | 依赖选择、任务分组 |
| 分数背包 | 可拆 | 贪心 | $O(n\log n)$ | 资源比例分配 |
| 可行性/计数 | 视变体 | 布尔/加法 | $O(nC)$ | 子集和、组合数 |

与贪心对比：只有分数背包能贪心。与搜索对比：DP 用容量维换指数；状态爆炸时可用 meet-in-the-middle（$n \le 40$）。与位运算对比：可行性背包可用 bitset 加速到 $O(nC/64)$。

## 六、常见误区

**0/1 背包误用正序遍历**。正序让 `dp[c-w]` 已含本物品，等于完全背包。后果是答案偏大（每件可用多次）。必须倒序。完全背包才正序。

**容量循环边界写错**。`for c in range(C, 0, -1)` 忘记下界 `w[i]`，`dp[c-w]` 负索引串到数组尾部。后果是运行错误或静默错解。用 `range(C, w-1, -1)`。

**多重背包不拆分直接循环**。把 $s_i$ 次当成嵌套循环 $O(s_i)$，或拆分错误（二进制份数算错）导致次数上限被突破。后果是超时或价值虚高。用二进制拆分时严格 `take = min(k, s)`。

**用贪心做 0/1 背包**。按性价比排序取前若干，在反例（高性价比太重）上错解。后果是面试直接挂。分数背包才贪心。

**计数背包忘记 `dp[0]=1`**。零钱兑换方案数初始化为 0，则所有方案数都是 0。后果是计数全错。凑零钱、路径计数类必须 `dp[0]=1`。

## 八、面试题

**1. 零钱兑换（最少硬币数）是哪种背包？**
参考答案：完全背包最值（每种硬币无限次），`dp[a] = min(dp[a], dp[a-coin]+1)`，容量正序。若求组合数则是完全背包计数，`dp[a] += dp[a-coin]` 且 `dp[0]=1`，外层循环硬币保证顺序无关。

**2. 分割等和子集能否用贪心？**
参考答案：不能，它是 0/1 背包可行性。判 `sum` 为偶数后，求能否选出子集和 `sum/2`。一维布尔 DP，倒序遍历。贪心按值排序会在反例上错。

**3. 0/1 背包一维数组为何要倒序？**
参考答案：保证 `dp[c-w]` 是「上一轮、未放本件」的值，从而每件最多用一次。正序会用到本轮已更新的值，等于完全背包。

**4. 多重背包如何优化到 $O(nC)$？**
参考答案：二进制拆分到 $O(nC\log s)$；进一步按 $c \bmod w_i$ 分组，组内用单调队列维护 $dp_{prev}[c-k w]+k v$ 的滑动窗口最大值，得到 $O(nC)$。

## 九、演进与趋势

**单调队列 / 斜率优化**。见「单调优化」篇：多重背包 $O(nC)$，完全背包带凸代价时斜率优化 $O(n \log n)$。

**Bitset 加速可行性**。`std::bitset` 或 Python `int` 位运算批量移位或，常数降 64 倍，适合大 $C$ 的可行性判定。

**高维与依赖背包**。树形依赖背包（选子必选父）用树上分组背包；泛化物品、有依赖的代价图。

**近似与 FPTAS**。0/1 背包有完全多项式近似方案（缩放价值），用于超大 $C$ 的工程近似。

**混合整数与求解器**。工业界小规模精确背包用 ILP（Gurobi、OR-Tools），大规模用贪心/DP 混合或分层近似。

## 十、小结

背包是 DP 的范式：状态是「前 $i$ 件 + 剩余容量」，转移是「选或不选」，一维滚动靠遍历方向区分 0/1 与完全。多重背包用二进制拆分或单调队列压复杂度，分组背包阶段化，计数/可行性改算子即可。只有分数背包可贪心，0/1 必须 DP。掌握一维滚动与遍历方向，就能把绝大多数资源分配问题翻译成背包模板。
