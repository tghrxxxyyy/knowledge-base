# 文档测试与示例可执行化

> 对应 reStructuredText / Sphinx docs-as-code。

## 一、背景与挑战
文档里的代码示例随接口演进悄然失效，读者照抄却跑不通，信任度下降。

## 二、核心原理
把文档中的代码片段作为可测试单元：doctest 直接运行示例并比对输出；CI 在每次提交校验全部示例，保证"文档即真相"。

## 三、形式化与数学基础
设文档示例 e 有输入 i 与期望输出 o。doctest 执行 e 得 o'，断言 o' == o。CI 失败集合 F = {e | o' != o}，需为空。

## 四、代码实现
```python
def add(a, b):
    # >>> add(1, 2)
    # 3
    return a + b
# 运行：python -m doctest -v doc.py
```

## 五、与其他技术对比
相比纯描述，可执行示例自带验证；相比独立测试用例，它更贴近读者视角，但覆盖应限于示例级。

## 六、常见误区
- 示例依赖外部状态（时间、网络），结果不确定导致误失败。
- 只写不跑，失去执行化意义。

## 七、与开源书/权威来源对应
Python doctest 与 Sphinx doctest 扩展是文档可执行化的标准工具。

## 八、面试题
doctest 与单元测试如何分工？文档示例为何要进 CI？

## 九、演进与趋势
交互式 Notebook 与文档联动，示例可在页面直接运行。

## 十、小结
文档测试把示例变成活证据，是防止文档腐化的强力手段。
