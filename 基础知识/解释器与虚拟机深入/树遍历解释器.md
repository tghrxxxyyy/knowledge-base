# 树遍历解释器

> 对应 Crafting Interpreters（jlox 树遍历解释器）与 SICP。

## 一、背景与挑战
树遍历解释器直接遍历 AST 求值，无需编译。挑战：慢（重复遍历、无优化）、环境管理、尾调用/性能。

## 二、核心原理
对每个 AST 节点写 `evaluate`：字面量返回值、二元运算递归求值子节点后运算、调用建新环境绑定参数并执行函数体。

## 三、形式化 / 数学基础
求值函数 $E:(\text{Env},\text{Expr})\to\text{Value}$。
$\dfrac{E(\rho,e_1)=v_1\quad E(\rho,e_2)=v_2}{E(\rho,e_1\ \text{op}\ e_2)=v_1\ \text{op}\ v_2}$。
环境 $\rho: \text{Name}\rightharpoonup \text{Value}$ 链式作用域。

## 四、代码实现
```python
def eval(e, env):
    if isinstance(e, Lit): return e.value
    if isinstance(e, Bin):
        l = eval(e.l, env); r = eval(e.r, env)
        return apply(e.op, l, r)
    if isinstance(e, Var): return env.lookup(e.name)
```

## 五、与其他技术对比
- 树遍历：实现最快、无 IR、慢。
- 字节码 VM：先编译再执行，快、可优化。
- 直接 AST 缓存：部分缓存子结果。

## 六、常见误区
1. 环境未链式子作用域致变量遮蔽错。
2. 每次访问重复遍历同一子树（无缓存）。
3. 把副作用顺序搞错（先求值左再右）。

## 九、演进与趋势
部分求值、AST 解释器加 JIT 快速路径、以及惰性/记忆化求值。

## 十、小结
树遍历解释器是理解"求值=遍历+环境"的最小实现：简单但慢，是通往字节码 VM 的阶梯。
