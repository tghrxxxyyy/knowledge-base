# 字节码虚拟机

> 对应 Crafting Interpreters（clox 字节码 VM）与 CS-Notes。

## 一、背景与挑战
把 AST 编译成线性字节码，由 VM 执行，比树遍历快得多。挑战：编译器/VM 分工、栈/寄存器模型、调试信息、调用帧。

## 二、核心原理
前端编译 AST→字节码指令流（如 `CONST 1; CONST 2; ADD; PRINT`）；VM 取指-执行循环 (dispatch) 解释。指令紧凑、局部性好。

## 三、形式化 / 数学基础
VM 状态：$(pc, \text{operand stack}, \text{call frames})$。
步进：$\text{decode}(code[pc])\to$ 动作 + $pc\leftarrow pc+\text{len}$。栈式：`ADD` 弹两压一。

## 四、代码实现
```c
for (;;) {
    uint8_t op = *ip++;
    switch (op) {
        case OP_ADD: {
            double b = pop(); double a = pop();
            push(a + b); break;
        }
        case OP_CONST: push(constants[*ip++]); break;
    }
}
```

## 五、与其他技术对比
- 字节码栈式：实现简、可移植（JVM）。
- 寄存器式：少 dispatch/少压弹、密集（Lua）。
- 树遍历：无编译、最慢。

## 六、常见误区
1. 栈式 VM 弹栈顺序错（先右后左）。
2. 忘了维护调用帧链（回溯/异常）。
3. 指令编码与编译器不一致。

## 九、演进与趋势
computed-goto 分派（LLVM `__builtin_expect`）、字节码验证（JVM）、以及字节码 + JIT 混合。

## 十、小结
字节码 VM 把"编译"与"执行"分离：紧凑指令 + 取指循环换来对 AST 解释的数量级加速，是 JVM/Lua/Python 的共同内核。
