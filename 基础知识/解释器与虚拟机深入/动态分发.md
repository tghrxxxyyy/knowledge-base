# 动态分发

> 对应 CS-Notes（多态/JVM 虚方法）与 Crafting Interpreters。

## 一、背景与挑战
动态分发（虚方法/消息发送）依运行期实际类型选方法。挑战：查找成本、内联缓存、与静态单态/多态/巨态的关系。

## 二、核心原理
调用 `o.m()`：查 `o` 实际类的 vtable 得 `m` 槽位地址再跳。第一次缓存（内联缓存 IC）：记录 (类, 地址)，命中即直接跳，免去查表。

## 三、形式化 / 数学基础
vtable：类 $C$ 的方法地址数组 $VT_C[m]$。调用 `o.m()` 译 `call VT[o.klass][m]`。
IC 状态：monomorphic（1 类，命中快）、polymorphic（少数）、megamorphic（多，退回查表）。

## 四、代码实现
```c
void call_virtual(Obj* o, int m) {
    void (*fn)(Obj*) = o->klass->vtable[m];
    fn(o);   // 经 vtable 动态分发
}
```

## 五、与其他技术对比
- vtable：O(1) 查表、C++/Java 用。
- 字典/消息（Python/Smalltalk）：哈希、灵活、慢、靠 IC。
- 静态单态 + 去虚化 (devirtualize)：JIT 常见优化。

## 六、常见误区
1. 以为动态分发必须每次哈希（vtable 是 O(1)）。
2. 忽略 IC 巨态退化致慢。
3. 把接口调用当必然慢（单态时近直接调用）。

## 九、演进与趋势
PIC（多态 IC）分层、基于轮廓的去虚、以及接口分派的类型测缓存。

## 十、小结
动态分发靠 vtable 与内联缓存：单态时几近直接调用，巨态才回退查表；理解 IC 状态是性能调优关键。
