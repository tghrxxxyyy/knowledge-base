# 技术债务量化管理

> 对应 Steve McConnell《Code Complete / Managing Technical Debt》、技术债务隐喻（Cunningham）与 Wardley 量化思路。

## 一、背景与挑战

技术债常被模糊感知为「代码有点乱」，却无法排序、无法向业务解释偿还优先级，最终持续累积直至拖垮交付速度。典型困境：

- 只有定性抱怨，无量化，难以进入排期对话。
- 业务方看不到「还债」收益，优先级总被功能需求挤压。
- 债务混杂（缺测试、坏设计、重复代码），无法区分轻重。
- 只盯「本金」忽略「利息」，持续损耗被无视。

核心挑战是把债务变成可比较、可谈判、可管理的资产清单。

## 二、核心原理

把债务量化为「偿还成本 + 持续利息 + 风险敞口」三项：

1. 本金（cost）：修复所需人天。
2. 利息（interest）：不修复时每月/每迭代的损耗（如改一处连带回归、调试耗时）。
3. 风险（risk）：引发线上故障或安全问题的概率与影响。

建立债务清单，按「利息/本金」比（即投资回报 ROI）排序偿还，优先处理比值高者。关键是让技术债进入和 feature 同等的优先级讨论，用业务语言沟通。

（落地补充：）
- 用 churn 率、缺陷复发率、平均修复时长自动折算利息并刷新清单，减少人工主观偏差。

## 三、形式化与数学基础

单笔债务 $d_i$ 具三元组 $(c_i, i_i, r_i)$（本金、月利息、风险）。总负担：

$$ T = \sum_i c_i + \sum_i i_i \cdot t $$

偿还优先级按单位本金回报：

$$ \rho_i = \frac{i_i + \lambda r_i}{c_i} $$

$\lambda$ 为风险折算系数。优先偿还 $\rho$ 高者。这与投资组合按 ROI 排序一致：先还「小成本、高损耗」的债。

## 四、代码实现

```python
# 技术债务清单与按 ROI 排序偿还
debts = [
    {"name": "支付模块无测试", "cost": 10, "interest": 3, "risk": 5},
    {"name": "重复告警逻辑", "cost": 2, "interest": 1, "risk": 1},
]

def prioritize(debts, lam=0.5):
    for d in debts:
        # 单位本金回报：利息 + 风险折算，除以成本
        d["roi"] = (d["interest"] + lam * d["risk"]) / d["cost"]
    return sorted(debts, key=lambda d: d["roi"], reverse=True)

plan = prioritize(debts)
for d in plan:
    print(d["name"], "ROI=", round(d["roi"], 2))  # 先还 ROI 高者
```

## 五、与其他技术对比

| 维度 | 纯定性抱怨 | 量化债务管理 |
| --- | --- | --- |
| 可谈判 | 弱 | 强（业务语言） |
| 优先级 | 凭感觉 | 按 ROI |
| 关注 | 只看本金 | 本金 + 利息 + 风险 |
| 结果 | 持续累积 | 有计划偿还 |

## 六、常见误区

- 「只记本金不记利息」：忽略持续损耗的紧迫性，永远排不上。
- 「一切不完美都算债」：失去重点，清单失控。
- 「只打补丁（还利息）」：不降本金，损耗永续。
- 「还债=停工」：应与功能需求混合排期，渐进偿还。

## 九、演进与趋势

从「人工评估」到「静态分析 + 变更频率自动估算利息」；趋势是用代码复杂度、churn、缺陷密度自动生成债务利息，持续更新清单并接入迭代规划。

## 十、小结

技术债务量化后才有可管理的优先级。核心是算清利息、用 ROI 排序偿还，把它变成与功能需求同等可比的工程资产，避免无声累积拖垮交付。
