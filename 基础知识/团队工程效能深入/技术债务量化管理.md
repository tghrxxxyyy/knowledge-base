# 技术债务量化管理

> 对应 McConnell《Code Complete》。

## 一、背景与挑战
技术债常被模糊感知为"代码有点乱"，却无法排序、无法向业务解释偿还优先级，最终持续累积。

## 二、核心原理
把债务量化为"偿还成本"：修复所需人天、风险敞口、对交付速度的影响；建立债务清单并按利息（持续损耗）排序。

## 三、形式化与数学基础
单笔债务 d 具 (cost, interest, risk)。总负担 T = Σ cost_i + Σ interest_i。优先偿还 interest/cost 比高者，类似投资回报排序。

## 四、代码实现
```python
debts = [
    {"name": "无测试支付模块", "cost": 10, "interest": 3},  # 人天/月损耗
]
debts.sort(key=lambda d: d["interest"]/d["cost"], reverse=True)
```

## 五、与其他技术对比
相比纯定性抱怨，量化让债务可谈判；相比只还利息（打补丁），应有计划地降本金。

## 六、常见误区
- 只记本金不记利息，忽略了持续损耗的紧迫性。
- 把一切不完美都算债务，失去重点。

## 七、与开源书/权威来源对应
《Code Complete》讨论技术债的隐喻与可控管理。

## 八、面试题
如何向非技术管理者解释技术债？利息与本金哪个更该优先？

## 九、演进与趋势
用静态分析与变更频率自动估算债务利息，持续更新清单。

## 十、小结
技术债务量化后才有可管理的优先级，核心是算清利息并据 ROI 偿还。
