# 平台工程与内部开发者平台

> 对应 Kim et al. 2016 (Accelerate / The DevOps Handbook)。

## 一、背景与挑战
每个团队重复搭建构建、部署、观测能力，成本高且不一致；开发者被基础设施细节拖累，无法聚焦业务。

## 二、核心原理
平台工程以"内部开发者平台（IDP）"为产品，向研发提供自服务黄金路径（脚手架、流水线、环境、可观测），降低认知负荷。

## 三、形式化与数学基础
设团队数 N，重复能力集合 C。集中平台后边际成本 MC = C + k·N 远低于分散的 N·C；开发者认知负荷 L 随抽象提升而下降。

## 四、代码实现
```bash
# 开发者只需一条命令获得标准环境
devctl new service order --template std-python
devctl env up        # 拉起预置可观测+流水线的环境
# 平台背后封装了 K8s/CI/监控细节
```

## 五、与其他技术对比
相比让每个团队自建 DevOps，平台工程提供一致性与规模经济；但需避免平台成为新的瓶颈与强管控。

## 六、常见误区
- 平台强制唯一路径，扼杀必要灵活性。
- 平台团队脱离用户（研发）做"自嗨"功能。

## 七、与开源书/权威来源对应
Accelerate 指出能力（自动化、按需环境）是高绩效的驱动因素，平台工程是其组织落地。

## 八、面试题
平台工程与 DevOps 的关系？IDP 为什么要以产品思维运营？

## 九、演进与趋势
平台工程与 GitOps、Internal Developer Portal（如 Backstage）融合，形成自助式研发体验。

## 十、小结
平台工程通过内部平台把复杂基础设施封装为自服务能力，让团队把精力放回价值创造。
