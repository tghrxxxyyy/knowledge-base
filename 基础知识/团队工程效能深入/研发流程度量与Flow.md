# 研发流程度量与Flow

> 对应 Kim et al. 2016 (The DevOps Handbook / Accelerate)。

## 一、背景与挑战
关注"资源利用率"（人是否忙）会误导——局部繁忙常伴随大量在制品积压，端到端交付反而更慢。

## 二、核心原理
流动效率 = 活跃时间 / (活跃 + 等待时间)。优化方向是减少等待（队列、审批、环境），而非让人更忙；限制在制品（WIP）提升吞吐。

## 三、形式化与数学基础
流动效率 FE = T_active / (T_active + T_wait)。根据利特尔定律 L = λ W（在制品=到达率×周期），降 WIP 即降周期 W。

## 四、代码实现
```python
# 统计一个需求从开始到上线的等待占比
active = sum(dev_time)          # 真正写代码/测试
wait = sum(blocked_time)        # 等评审/等环境
fe = active / (active + wait)
```

## 五、与其他技术对比
相比资源利用率，流动效率暴露等待浪费；二者往往此消彼长，优化流动优先于填满工时。

## 六、常见误区
- 追求 100% 人员利用率，反而堆高在制品、拉长周期。
- 只优化单环节，无视跨环节等待。

## 七、与开源书/权威来源对应
The DevOps Handbook 用价值流图揭示等待是交付的最大敌人。

## 八、面试题
为什么高利用率不等于高产出？利特尔定律对 WIP 的启示？

## 九、演进与趋势
价值流管理平台自动绘制等待热点，指导减 WIP。

## 十、小结
流动效率把注意力从"人忙不忙"转到"价值流不流畅"，是效能提升的系统视角。
