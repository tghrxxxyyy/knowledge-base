# 里氏替换原则

> 对应 Barbara Liskov 1987 年替换原则、Martin《Clean Architecture》。

## 一、背景与挑战
子类覆写父类方法后，若调用方依赖父类契约却得到意外行为，系统会出现隐蔽缺陷（如 Square 继承 Rectangle 导致面积错误）。

## 二、核心原理
LSP（Liskov Substitution Principle）：子类型必须能够替换其基类型，且使用基类型的程序在替换后行为不被破坏。强调"行为兼容"而非仅"签名兼容"。

## 三、形式化 / 数学基础
对前置条件与后置条件：子类型方法的前置条件不能强于基类，后置条件不能弱于基类（按 Bertrand Meyer 契约式设计）：
$$\forall x:\ pre_{base}(x) \Rightarrow pre_{sub}(x)$$
$$post_{sub}(x) \Rightarrow post_{base}(x)$$
不变量在子类调用前后必须保持。

## 四、代码实现
```python
class Bird:
    def fly(self): ...
class Penguin(Bird):
    def fly(self):
        raise NotImplementedError  # 破坏 LSP：调用方假设所有 Bird 会飞
# 正例：抽象出可飞能力
class FlyingBird(Bird):
    def fly(self): ...
```

## 五、与其他技术对比
LSP 是 OCP 得以成立的前提：只有子类可替换，才能对扩展关闭。与"鸭子类型"互补但更强调契约。

## 六、常见误区
误区：仅保证编译通过即认为满足替换。真正要求的是行为契约（不变量、异常、性能语义）一致。

## 九、演进与趋势
现代语言以不可变类型、代数数据类型（ADT）降低 LSP 违例风险。

## 十、小结
替换性由行为契约定义，而非继承关系本身。
