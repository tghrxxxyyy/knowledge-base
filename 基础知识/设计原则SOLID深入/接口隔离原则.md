# 接口隔离原则

> 对应 Martin《Clean Architecture》、GoF 客户端特定接口思想。

## 一、背景与挑战
一个"胖接口"强制实现类提供其不需要的方法（抛出 UnsupportedOperationException），调用方也被迫依赖无关方法，增加耦合与变更影响面。

## 二、核心原理
ISP（Interface Segregation Principle）：客户端不应被迫依赖它不使用的方法。应为不同客户端定义小而专的接口，而非一个通用大接口。

## 三、形式化 / 数学基础
设接口 $I$ 的方法集 $M$，客户端 $C$ 仅使用 $M_C \subset M$。ISP 要求存在 $I_C$ 使 $M(I_C)=M_C$ 且 $C$ 仅依赖 $I_C$，从而耦合度 $Dep(C)=\sum |M_C|$ 最小化。

## 四、代码实现
```java
interface Printer { void print(); }
interface Scanner { void scan(); }
// 老旧一体机实现两者；纯打印机只实现 Printer
class SimplePrinter implements Printer {
    public void print() { ... }
}
```

## 五、与其他技术对比
与 SRP 相似（都反对"大而全"），SRP 针对实现变化原因，ISP 针对调用方依赖面。Role Interface（角色接口）是 ISP 的常用落地形态。

## 六、常见误区
误区：把 ISP 当成"接口越碎越好"，导致接口爆炸。应按真实客户端分组，而非每个方法一个接口。

## 七、与开源书 / 权威来源对应

## 八、面试题

## 九、演进与趋势
语言层面的默认方法（default method）与 trait 缓和了接口膨胀，但 ISP 的客户端视角依然有效。

## 十、小结
按客户端而非实现者来切分接口，缩小依赖面。
