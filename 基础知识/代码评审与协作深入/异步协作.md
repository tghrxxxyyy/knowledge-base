# 异步协作

> 对应 Git 工作流、Conventional Commits 规范、Google 工程实践，与 CS-Notes: https://github.com/CyC2018/CS-Notes。

## 一、背景与挑战

分布式、跨时区的团队无法像同地团队那样「凑一块评审」。当评审依赖同步会议，交付节奏会被最慢的时区拖垮；当沟通只靠评论区来回，语义误解与上下文缺失会放大。更常见的问题是：一个巨大的 PR 挂起数天无人敢审，因为没人愿意一次性理解上千行改动。

异步协作的目标，是**让评审不依赖「同时在场」也能高效、留痕、可追溯**。它依赖的不是工具本身，而是纪律——小 PR、清晰描述、响应 SLA、约定式提交。

## 二、核心原理

异步评审有几个可操作支柱：

- **小 PR（<400 行）**：把大改动拆成可独立评审的逻辑单元，降低单次的认知负荷，缩短等待。
- **清晰描述**：用「Context / Change / Risk / Test」结构说明为什么改、改了什么、风险与验证，让评审者无需反复追问。
- **响应 SLA**：约定评审者在 N 小时内响应，避免无限挂起。Draft PR 用于提前对齐设计，不进入正式评审。
- **约定式提交（Conventional Commits）**：`feat:`/`fix:`/`refactor:` 等前缀让变更性质自解释，便于自动生成变更日志与回溯。

这些纪律共同把「同步依赖」转成「结构化异步流」。

## 三、形式化与数学基础（含 LaTeX）

评审等待时间

$$
W = T_{review} - T_{open}
$$

实证上，缺陷密度 $\rho$ 与变更规模 $S$ 正相关，且评审有效性随 $S$ 增大而下降。近似有

$$
\rho(S)\approx \rho_0 + k\cdot S,\qquad \mathrm{Effectiveness}(S)\propto \frac{1}{S}
$$

故控制 $S<400$ 行可在可接受的 $W$ 内保持高有效性。SLA 把 $W$ 上限约束为 $W\le SLA$，防止挂起。

## 四、代码实现（围栏配平）

```text
# Conventional Commits 示例
feat(order): add idempotency key for retry        # 新能力
fix(pay): handle timeout on retry                 # 缺陷修复
refactor(cart): extract pricing calc              # 重构

# PR 描述模板（Context / Change / Risk / Test）
## Context：支付重试存在重复扣款
## Change：引入幂等键，去重重试请求
## Risk：低，仅新增中间件
## Test：新增单测覆盖超时重试场景
```

## 五、与其他技术对比

- 与**同步评审会议**相比：异步可扩展、留痕、不依赖同时在场；但需纪律（SLA、小 PR）防挂起。
- 与**大 PR 一次性评审**相比：小 PR 缩短等待、提升发现率，代价是更多次上下文切换。
- 与**口头对齐**相比：PR 描述是「写下来的意图」，比口头更可回溯。

## 六、常见误区

- 「一个 PR 改全功能」——规模过大无人愿审，缺陷漏出率上升。
- 「无 SLA 靠自觉」——跨时区下易无限等待，交付失速。
- 「提交信息随意」——`update`/`fix bug` 类信息丢失变更语义，难以回溯。

## 七、与开源书·权威来源对应

- Git 文档与各类 Git 工作流（feature branch / fork）是异步协作的基础。
- Conventional Commits 规范定义了 `type(scope): subject` 的提交信息约定。
- Google 工程实践强调小变更、清晰描述与快速评审节奏。
- CS-Notes 在 Git/协作板块整理了上述工作流要点。

## 八、面试题

- 问：如何优化异步代码评审？答：小 PR、清晰描述、设响应 SLA、用 Draft 提前对齐，并用约定式提交自解释变更。
- 问：为什么 PR 要小？答：小 PR 降低认知负荷、缩短等待、提升缺陷发现率。
- 问：SLA 有何作用？答：约束评审等待上限，防止跨时区下 PR 无限挂起。

## 九、演进与趋势

PR 自动分片（把大改动拆小）、AI 生成变更摘要与影响面分析，正加速异步评审；提交信息驱动的自动化发布也更易落地。

### 关键要点速查

- 异步评审靠纪律而非工具：小 PR、清晰描述、SLA、约定式提交。
- 单 PR 控制 <400 行，降低认知负荷、缩短等待、提升缺陷发现率。
- PR 描述用 Context/Change/Risk/Test，让评审者无需反复追问。
- 设响应 SLA 约束等待上限，防止跨时区下 PR 无限挂起。
- Draft PR 用于提前对齐设计，不进入正式评审，降低返工。
- Conventional Commits 让变更性质自解释，便于回溯与发布。
- 异步可扩展、留痕，但需纪律防止挂起，不能只靠自觉。
- PR 自动分片与 AI 变更摘要正加速异步评审，降低上下文切换。

## 十、小结

小 PR、清描述、设 SLA、约定式提交，让异步评审既高效又可追溯，是分布式团队的协作基石。
