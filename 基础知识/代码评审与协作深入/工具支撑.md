# 工具支撑

> 对应 GitHub/GitLab 评审、静态分析、CI 集成实践。

## 一、背景与挑战
纯人工评审漏掉格式、重复、安全等机械问题，且重复劳动消耗评审精力，使人忽略设计。

## 二、核心原理
用工具分层接管：Linter/Formatter 统一风格、SAST 查安全、覆盖率门禁、架构校验、CI 自动跑测试。人工专注设计、意图与边界。

## 三、形式化 / 数学基础
工具可自动化项占比 $A_{auto}$ 越高，人工评审聚焦于不可自动化的 $1-A_{auto}$。设机械问题率 $m$，工具拦截使人工所见缺陷降至 $(1-A_{auto})\cdot m$。

## 四、代码实现
```yaml
# PR 检查流水线
checks:
  - prettier / black
  - eslint / ruff
  - unit + coverage gate
  - secret-scan / semgrep
```

## 五、与其他技术对比
与全人工评审相比，工具处理机械项、释放人力；但工具不能替代设计判断。

## 六、常见误区
误区：工具报告当评审结论。误区：门禁过严致开发者绕过。

## 七、与开源书 / 权威来源对应
GitHub/GitLab Code Review 文档；Fowler 持续集成；CS-Notes: https://github.com/CyC2018/CS-Notes

## 八、面试题
"哪些评审工作应交由工具？人工应聚焦什么？"

## 九、演进与趋势
AI 评审 Bot 预读 PR，标注疑似问题供人确认。

## 十、小结
工具接管机械检查，人工聚焦设计与意图。
