# 流量整形

> 对应流量整形与管制（Shaping vs Policing）；RFC 3290（信令 QoS）。

## 一、背景与挑战
上游可能突发发送，超过下游处理能力或合约速率，造成丢包与抖动。流量整形（shaping）把突发“削峰填谷”，使发送速率平滑、符合合约。

## 二、核心原理
整形（Shaping）通过缓存 + 受控调度延迟发包，使输出速率不超过目标曲线（如令牌桶）。管制（Policing）则直接丢超规流量而非缓存。整形保平滑但引入时延，管制不缓存但可能丢包。

## 三、形式化 / 数学基础
漏桶（整形视角）：输出恒定速率 $r$，桶容量 $b$，超出溢出的若被缓存则排队、若被管制则丢弃。
令牌桶（见令牌桶与漏桶）：令牌以 $r$ 生成、容量 $b$；有令牌才发，从而限制平均速率 $\le r$、允许短时突发至 $b$。

## 四、代码实现
```bash
# Linux tc 用 tbf（令牌桶整形）限制为 10Mbit、突发 10KB
tc qdisc add dev eth0 root tbf rate 10mbit burst 10kbit latency 50ms
```

## 五、与其他技术对比
整形（缓存+延迟）vs 管制（直接丢）；令牌桶（允许突发）vs 漏桶（严格恒定）。整形常用于出口限速，管制常用于入口合约执行。

## 六、常见误区
误区一：整形和管制一回事。错，一个缓存一个丢。误区二：整形不会丢包。错，桶/队列满仍丢。误区三：整形能提升吞吐。错，只是平滑、可能降突发能力。

## 九、演进与趋势
AQM（CoDel）与整形结合改善缓冲区时延；云网络用 hierarchical token bucket 分层限速。

## 十、小结
流量整形用缓存+调度平滑速率、符合合约，与管制（丢）互补，核心在令牌桶/漏桶模型。
