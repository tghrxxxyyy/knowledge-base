# 网络测量

> 对应 RFC 7799（主动/被动/混合测量的术语与 Type-P 概念）；RFC 4656（OWAMP）；RFC 5357（TWAMP）；RFC 3550（RTP 抖动估计）；Kurose & Ross《Computer Networking: A Top-Down Approach》时延与丢包章节。

## 一、背景与挑战
运维、容量规划与故障定位都建立在量化之上：端到端时延是多少、丢包发生在哪一段、瓶颈带宽是否达到预期、抖动是否超出语音可用范围。但网络不像 CPU 那样可以插探针，只能从外部观测——这带来方法上的根本困难。

第一个困难是「测什么」。同一业务流量在网卡、内核协议栈、应用层看到的时间戳可能差出几十微秒到毫秒；微突发（microburst）在毫秒级采样下完全不可见。第二个困难是侵入性：主动探测包会与业务流量竞争队列，在自身就是瓶颈的链路上，观测行为会改变被观测对象。第三个困难是时钟：单向时延的测量精度完全受两端时钟同步误差支配。

## 二、核心原理
按 RFC 7799 的术语，测量可分三类。

**主动测量**：注入专门构造的探测包（Type-P），观察其到达情况。典型手段包括 ICMP 探测（往返时延）、逐跳探测（路径与逐跳时延）、以及标准化的 OWAMP/TWAMP（单向/双向时延，需网元配合）。优点是可控、可复现、可定位到路径段；缺点是引入额外流量，且探测包可能与业务流量的优先级或队列不同，得到的不是业务真实体验。

**被动测量**：在转发设备或端主机上观察真实流量。数据面导出（如 IPFIX、sFlow）提供流级统计，抓包与内核追踪提供包级细节。优点是不打扰业务；缺点是受采样率与聚合粒度限制，加密流量下可见性下降，并带来隐私与合规约束。

**混合测量**：用主动探测提供标定点、用被动观测提供覆盖与规模，两者互相校正。

核心指标与获取方式：往返时延（时间戳回显）、单向时延（需时钟同步）、丢包率（序列号配对）、抖动（相邻时延差的平滑统计）、瓶颈带宽（包对/包列的时间膨胀）、可达性与路径（逐跳探测）。

## 三、形式化与数学基础
往返时延（发送时间戳 $t_1$、收到回显 $t_2$）：
$$RTT = t_2 - t_1$$
单向时延在两端时钟存在偏移 $\theta$（以及频率偏差）时无法直接获得。设发送端时间为 $t_1$、接收端时间为 $t_2$，则
$$OWD = (t_2 - t_1) + \theta, \qquad D_{rtt} = OWD_{f} + OWD_{b}$$
即在只有 RTT 的情形下，单向时延的误差就是 $\theta$，因此必须依赖 NTP/PTP 类时钟同步。

丢包率（发送 $S$、收到 $R$，按序列号配对）：
$$p = \frac{S - R}{S}$$
抖动（RFC 3550 的 16 样本指数平滑估计，$D(i-1,i)$ 为相邻包时延差）：
$$J \leftarrow J + \frac{|D(i-1,i)| - J}{16}$$
瓶颈带宽估计（包对/包列串行化后到达间隔被拉伸，$L$ 为包长、$\Delta t_{arr}$ 为到达间隔）：
$$B \approx \frac{L}{\Delta t_{arr}}$$
该估计成立的前提是包对之间没有交叉流量干扰，否则结果系统性偏低。

## 四、代码实现
带时间戳的往返探测（比 ICMP 更贴近传输层路径，可用于区分设备对 ICMP 限速带来的偏差）：
```python
import socket, time

def tcp_rtt(host, port, samples=10):
    out = []
    for _ in range(samples):
        s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        s.settimeout(1.0)
        t1 = time.monotonic()
        try:
            s.connect((host, port))          # 用三次握手耗时近似一个 RTT
            out.append((time.monotonic() - t1) * 1000.0)
        except OSError:
            out.append(float("nan"))
        finally:
            s.close()
    return out

def stats(xs):
    v = sorted(x for x in xs if x == x)
    if not v:
        return None
    n = len(v)
    return {"n": n, "min": v[0], "med": v[n // 2], "max": v[-1],
            "p95": v[min(n - 1, int(0.95 * n))]}    # 长尾看 p95 而非均值
```
被动侧的关键是保留首末时间戳：只按五元组与时间桶累加计数能算出流量分布，但只有保留首个与最后一个包的时间戳，才能进一步得到流内到达间隔与突发形态。

## 五、与其他技术对比
| 维度 | 主动测量 | 被动测量 | 混合测量 |
| --- | --- | --- | --- |
| 侵入性 | 有（注入探测包） | 无 | 低（少量标定探测） |
| 覆盖范围 | 只覆盖被探测目标 | 覆盖全部真实流量 | 两者结合 |
| 业务代表性 | 可能不同队列/优先级 | 直接反映业务 | 可校准 |
| 依赖条件 | 对端响应、路径可达 | 采集点、采样率、权限 | 两者 |
| 时钟要求 | 单向时延需同步 | 流级统计通常不需 | 视指标而定 |
| 主要偏差来源 | 探测包自身影响、限速 | 采样偏差、聚合粒度 | 标定误差 |

| 指标 | 主动获取 | 被动获取 | 精度限制 |
| --- | --- | --- | --- |
| RTT | 直接 | 从 ACK 时序推断 | 受应用行为影响 |
| 单向时延 | 需两端配合 | 合成困难 | 时钟偏移主导 |
| 丢包率 | 序列号配对 | 序列号/流统计 | 采样与乱序干扰 |
| 抖动 | 连续探测 | 按流时序 | 采样率决定可观测尺度 |
| 瓶颈带宽 | 包对/包列 | 吞吐与到达间隔 | 交叉流量干扰 |

## 六、常见误区
- 认为 `ping` 测的是应用层时延。它是网络层往返，且常被设备限速或降优先级，不能代表业务路径。
- 认为单向时延可以轻易测得。没有两端时钟同步，单向时延的误差就是时钟偏移，量级常常大于所求时延本身。
- 认为丢包率为 0 就是链路健康。探测包可能被优先处理，或丢包发生在未被探测的方向与路径上。
- 忽略采样偏差。流级采样会系统性低估短流与小包的影响，聚合粒度会掩盖微突发。
- 把平均时延当作体验。业务体验更多由 p95/p99 与分布尾部决定，平均值会掩盖长尾。
- 忽视测量本身的成本。高精度包级采集在高速链路上产生巨大 CPU 与存储开销，甚至影响转发性能。

## 七、与开源书·权威来源对应
- RFC 7799：定义主动、被动、混合测量的术语，以及 Type-P 与「指标必须在特定包类型下才有意义」的原则。
- RFC 4656（OWAMP）与 RFC 5357（TWAMP）：单向/双向时延测量的协议规范，明确时钟与错误源的处理要求。
- RFC 3550：RTP 中抖动估计的指数平滑公式，是抖动度量的常用权威定义。
- RFC 7011（IPFIX）：流信息导出协议，是被动流级测量的标准框架。
- Kurose & Ross《Computer Networking: A Top-Down Approach》：时延组成（处理、排队、传输、传播）与丢包章节，是理解各指标物理含义的基础。
- Stevens《TCP/IP Illustrated》第 1 卷：TCP 时序与 RTT 估计（含 RTO 计算）的实现级描述，说明端侧如何自行推断路径质量。

## 八、面试题
1. 主动测量与被动测量的区别与各自偏差？要点：前者注入探测包、可控可定位但侵入且不代表业务队列；后者观测真实流量但受采样、聚合与可见性限制。
2. 单向时延为什么难测？要点：需要两端时钟同步，否则结果被时钟偏移污染；工程上常用 RTT 替代或依赖 PTP/NTP 标定。
3. 包对方法如何估计瓶颈带宽？要点：利用串行化导致的到达间隔膨胀，用包长除以间隔估计；交叉流量会造成低估。
4. 抖动怎么定义与估计？要点：相邻包时延差的统计量，常用 RFC 3550 的 16 样本指数平滑；采样率限制可观测的抖动尺度。
5. 为什么平均值不够？要点：时延与抖动都是长尾分布，业务体验由 p95/p99 与丢包事件分布决定。
6. 流级采样有什么系统性偏差？要点：按比例采样对短流不友好，会低估小流影响并掩盖突发。

## 九、演进与趋势
三个方向值得关注：其一是可编程数据面遥测，让包携带沿途设备状态，把逐跳信息从「多次探测」变成「一次携带」；其二是内核态细粒度采集，用 eBPF 类技术在不复制数据到用户态的前提下做聚合与直方图统计，降低采集成本；其三是硬件时间戳与精确时钟，让单向时延精度向微秒级推进。同时加密流量占比上升，被动测量越来越依赖元数据与端侧上报，隐私与合规成为设计硬约束。具体实现与协议以官方最新文档为准。

## 十、小结
网络测量没有银弹：主动测量换来可控性却牺牲业务代表性，被动测量换来真实性却受采样与可见性限制。可靠的做法是先明确要回答的问题（定位故障段还是评估业务体验），再选择能覆盖该问题的观测点与时钟方案，并用另一种方法交叉验证。
