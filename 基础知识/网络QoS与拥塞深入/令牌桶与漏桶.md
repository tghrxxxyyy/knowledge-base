# 令牌桶与漏桶

> 对应 RFC 2697（srTCM）/ RFC 2698（trTCM）；网络调速经典模型。

## 一、背景与挑战
需要一种算法既限制平均速率又允许合理突发，或严格平滑输出。令牌桶与漏桶是两种互补的经典方案。

## 二、核心原理
令牌桶：以恒定速率 r 向容量 b 的桶加令牌，包需取走令牌才发；桶空则等或丢（限流）/排队（整形）。平均速率 ≤ r，允许突发至 b。漏桶：输出以恒定速率 r 漏出，输入可突发入桶，溢出则丢；输出严格平滑。

## 三、形式化 / 数学基础
令牌桶：令 $T(t)$ 为 t 时刻令牌数，$0\le T\le b$，$dT/dt = r$（生成），发包减 $size$。允许突发量 $= b$。
漏桶（漏出速率 r，容量 b）：$Q(t)$ 队列长，$dQ/dt = in - r$（in>r 时累积，超 b 丢）。
trTCM：用 CBS（承诺突发）、PBS（峰值突发）双桶区分“承诺/超标”着色。

## 四、代码实现
```python
import time
class TokenBucket:
    def __init__(self, rate, cap):
        self.rate, self.cap, self.tok, self.ts = rate, cap, cap, time.time()
    def allow(self, n=1):
        now = time.time()
        self.tok = min(self.cap, self.tok + (now - self.ts) * self.rate)
        self.ts = now
        if self.tok >= n:
            self.tok -= n; return True
        return False
```

## 五、与其他技术对比
令牌桶“限平均、容突发”；漏桶“严格恒定输出”。令牌桶更适合限速+突发（如 API 限流），漏桶更适合平滑（如流量整形出口）。

## 六、常见误区
误区一：令牌桶不允许突发。错，桶容量即突发额度。误区二：漏桶能加速。错，只平滑不加速。误区三：二者完全等价。错，突发语义相反。

## 八、面试题
1. 令牌桶与漏桶核心区别？2. 限流常用哪种？答：令牌桶。

## 九、演进与趋势
Hierarchical Token Bucket（HTB）用于多级限速；RED/CoDel 等 AQM 与令牌桶协同。

## 十、小结
令牌桶限平均容突发、漏桶严格平滑，是限速与整形的两大基础算法。
