# 差分服务

> 对应 RFC 2474（DSCP）；RFC 2475（DiffServ 架构）；RFC 4594（PHB 指南）。

## 一、背景与挑战
IntServ 逐流状态无法扩展。DiffServ 退一步：在网络边界把包分类标记，核心只按少数“每跳行为”（PHB）处理，实现可扩展的差异化服务。

## 二、核心原理
用 IP 首部 ToS 字节的 DSCP（6 位，64 个值）标记类。标准 PHB：EF（加速转发，低时延低抖，给语音）、AF（确保转发，4 类各 3 丢弃优先级）、BE（默认尽力）。边界做分类/计量/标记，核心做调度与丢弃。

## 三、形式化 / 数学基础
DSCP 编码：$DSCP[5:0]$，如 EF=101110，AFxy：$101\ x\ y0$（x=类1-4，y=丢弃优先级0-2）。
PHB 语义：EF 近似 CBR 保证；AF 类 k 保证最小带宽，超出按 y 优先级丢。
调度：$min\text{-}guarantee(C_k) \le G_k$，超额部分按 $y$ 丢（先丢 y 大者）。

## 四、代码实现
```bash
# Linux 用 tc 标记与分类（DSCP EF）
tc qdisc add dev eth0 root handle 1: htb
tc filter add dev eth0 protocol ip parent 1:0 prio 1 \
  u32 match ip tos 0xb8 0xfc classid 1:10   # EF
```
```c
// 设置 DSCP（EF=0x2E 左移 2 位入 ToS）
iph->tos = 0x2E << 2;
```

## 五、与其他技术对比
DiffServ（类级、可扩展）vs IntServ（流级、强保证但不可扩展）；vs MPLS EXP/TC 位做类似分类。

## 六、常见误区
误区一：DSCP 保证端到端带宽。错，仅在本域有效，跨域常被重置。误区二：64 个 DSCP 都独立保障。错，标准只定义 EF/AF/BE 等少量 PHB。误区三：标记后一定优先。错，依赖设备实际调度策略。

## 九、演进与趋势
与 AQM（CoDel/FQ-CoDel）协同；IETF 研究更细的延迟保障（如 L4S 用 ECT(1)）。

## 十、小结
差分服务用 DSCP 标记 + PHB 类级调度，以可扩展方式提供差异化转发保障。
