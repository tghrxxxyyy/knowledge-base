# 差分服务

> 对应 RFC 2474（Definition of the Differentiated Services Field）；RFC 2475（DiffServ 架构）；RFC 2597（AF PHB）；RFC 3246（EF PHB）；RFC 4594（DiffServ 服务类配置指南）。

## 一、背景与挑战
IntServ 的逐流预留需要核心路由器维护每条流的状态并执行逐跳准入控制，状态量与流数成正比，在骨干网不可行。DiffServ 退一步：把「保证」从流粒度降到类粒度，把复杂度从核心推到边界。

代价随之而来。既然核心不区分单个流，同一类内的流就没有任何隔离，一个不守规矩的流会挤占同类其它流的额度；既然标记发生在边界，标记的信任模型就必须被设计，否则终端可以自行打上高优先级标记来抢占资源。

## 二、核心原理
DS 域（DS Field）占用 IPv4 ToS 字节 / IPv6 Traffic Class 字节，其中高 6 位是 DSCP（Differentiated Services Code Point），低 2 位留给 ECN。因此有 64 个可用编码点，但标准只定义了少量「每跳行为」（PHB）：

- **EF（Expedited Forwarding，加速转发）**：为低时延、低抖动、低丢包业务设计，典型是语音。实现上通常配合严格优先级调度与入口限速（整形/管制），确保 EF 流量不至于淹没其它队列。
- **AF（Assured Forwarding，确保转发）**：分 4 个类，每类内 3 个丢弃优先级，共 12 个编码点。类内保证最低带宽，超出部分按丢弃优先级丢弃，形成「保证 + 降级」的层次。
- **BE（Best Effort，默认）**：不提供保证的默认行为，此外还有 CS（Class Selector）编码点用于与 IP 优先级兼容。

边界设备承担四件事：分类（按五元组、应用识别或接口）、计量（令牌桶判定合规性）、标记（写入 DSCP，必要时降级重标记）、按需整形。核心设备只做两件事：按 DSCP 映射到队列，按 PHB 调度与丢弃。

## 三、形式化与数学基础
DSCP 是 6 位二进制，记作 $DSCP[5:0]$。关键编码：
$$DSCP_{EF} = 101110_2 = 46, \qquad DSCP_{BE} = 000000_2 = 0$$
AF 编码由类号 $x \in \{1,2,3,4\}$ 与丢弃优先级 $y \in \{1,2,3\}$ 组合而成：
$$DSCP_{AFxy} = (x \ll 3) \mid (y \ll 1)$$
例如 $AF11 = (1\ll3)\mid(1\ll1) = 001010_2 = 10$，$AF43 = (4\ll3)\mid(3\ll1) = 100110_2 = 38$：$x$ 占据高 3 位形成 `001`～`100`，$y$ 占据中间 2 位形成 `01`～`11`，最低位恒为 0。

PHB 的语义化表述：AF 类 $k$ 的保障与超额丢弃可写成
$$\text{guarantee}(C_k) \ge G_k, \qquad \text{超额部分按丢弃优先级 } y \text{ 递增（先丢 } y \text{ 大的）}$$
EF 的目标是「速率受限后的近似恒定服务」：
$$R_{EF}^{in} \le R_{EF}^{out} \quad\Longrightarrow\quad D_{EF} \approx \text{常量},\ f_{jitter} \to 0$$
这一保证依赖入口限速：若 EF 流量超过预留出口速率，队列必然堆积，时延保证随之失效。这就是 RFC 3246 强调 EF 必须配合策略（管制或整形）使用的原因。

## 四、代码实现
边界标记：按 DSCP 语义写入 DS 域，并保留 ECN 位。
```c
#include <netinet/ip.h>

/* DSCP 常量（6 位），写入时必须左移 2 位以对齐 DS 域 */
#define DSCP_EF   46
#define DSCP_AF21 18
#define DSCP_BE    0

void mark_dscp(struct iphdr *iph, uint8_t dscp) {
    uint8_t ecn = iph->tos & 0x03;                 /* 保留 ECN 位 */
    iph->tos = (uint8_t)((dscp << 2) | ecn);
    iph->check = 0;                                /* 由协议栈重算校验和 */
}
```
核心侧只按 DSCP 分类入队，并用类级调度保证最低份额：
```text
on_enqueue(pkt):
    cls = phb_map(pkt.dscp)          # EF / AF1..AF4 / BE -> 队列号
    if queue[cls].len == queue[cls].limit:
        drop(pkt, cls)               # AF 类按丢弃优先级选择受害者
        return
    queue[cls].push(pkt)

on_dequeue():
    for cls in priority_order:       # EF 最高，其余按权重轮询
        if not queue[cls].empty():
            return queue[cls].pop()  # EF 通常用严格优先级
```
用 `tc` 落地「EF 严格优先 + AF 加权轮询」的核心侧行为：
```bash
tc qdisc add dev eth0 root handle 1: htb default 30
tc class add dev eth0 parent 1:  classid 1:1  htb rate 1gbit
tc class add dev eth0 parent 1:1 classid 1:10 htb rate 100mbit prio 0   # EF
tc class add dev eth0 parent 1:1 classid 1:20 htb rate 200mbit prio 1   # AF2x
tc filter add dev eth0 protocol ip parent 1:0 prio 1 u32 \
  match ip tos 0xb8 0xfc flowid 1:10      # 0xb8 = EF(46) << 2
tc filter add dev eth0 protocol ip parent 1:0 prio 2 u32 \
  match ip tos 0x48 0xfc flowid 1:20      # 0x48 = AF21(18) << 2
```

## 五、与其他技术对比
| 维度 | DiffServ（DSCP + PHB） | IntServ（RSVP） | MPLS EXP / TC 位 | 802.1p / PCP（以太网） |
| --- | --- | --- | --- | --- |
| 作用层次 | IP 层 | IP 层 | MPLS 标签 | 以太网帧 |
| 状态量 | O(类数) | O(流数) | O(类数) | O(类数) |
| 保证强度 | 类级相对保证 | 流级硬保证 | 与 DiffServ 类似 | 每跳局部 |
| 跨域传递 | 需域间约定与重标记 | 需逐跳信令 | 随标签转发 | 出接口即失效 |

| 服务类 | 典型 DSCP | 保证目标 | 典型业务 |
| --- | --- | --- | --- |
| EF | 46 | 低时延/低抖动/低丢包 | 语音、交互式实时 |
| AF4x | 34/36/38 | 高优先带宽 + 三级丢弃 | 视频会议、多媒体流 |
| AF2x | 18/20/22 | 中优先带宽 | 事务型业务、交互应用 |
| AF1x | 10/12/14 | 低优先带宽 | 批量、后台同步 |
| BE | 0 | 无保证 | 默认流量 |

## 六、常见误区
- 认为 DSCP 能提供端到端带宽保证。它只在本 DS 域内有效，跨域常被重标记或清零；端到端保证需要域间 SLA 与一致的 PHB 配置。
- 认为 64 个 DSCP 都各有独立保障。标准只定义了 EF/AF/BE 等少量 PHB，其余编码点的行为由实现决定。
- 认为打了标记就一定会被优先处理。实际取决于沿途设备是否信任该标记、是否按 PHB 映射到独立队列、以及队列是否拥塞。
- 认为 AF 类内不需要隔离。同类内没有流隔离，不合规流量会挤压合规流量的额度，因此必须在边界做计量。
- 忽略 EF 与 AF 的参数陷阱。EF 不做入口限速时会挤占全部带宽；AF 若把 $y$ 的丢弃顺序配反，会让重要流量先被丢。
- 混淆 ToS 字节与 DSCP。写入 IPv4 首部时必须左移 2 位，且不要破坏低 2 位的 ECN 域。

## 七、与开源书·权威来源对应
- RFC 2474：定义 DS 域结构与 DSCP，明确如何在 IPv4/IPv6 中承载以及编码点的分配规则。
- RFC 2475：DiffServ 架构，定义 DS 域、边界/核心职责、分类器/计量器/标记器/整形器的组合。
- RFC 2597：AF PHB 的类与丢弃优先级定义，是 AF 编码与语义的权威来源。
- RFC 3246：EF PHB 定义，并强调必须配合入口限速/策略才能维持低时延低抖动。
- RFC 4594：服务类与编码点配置指南，给出业务到 DSCP 的推荐映射。
- Kurose & Ross《Computer Networking: A Top-Down Approach》：QoS 章节对比 IntServ 与 DiffServ 的保证粒度与可扩展性。

## 八、面试题
1. DSCP 是多少位、EF 与 AF 的编码规则是什么？要点：6 位；EF = `101110`（46）；AF 编码为 $(x\ll3)|(y\ll1)$，$x$ 为类、$y$ 为丢弃优先级。
2. EF 与 AF 的区别？要点：EF 面向低时延低抖动（需入口限速），AF 面向带宽保证并带三级丢弃优先级，类内无隔离。
3. 为什么 DiffServ 可扩展？要点：核心只需按 DSCP 映射队列，不维护逐流状态，状态量只与类数相关。
4. 为什么必须做边界重标记？要点：防止终端自行打高优先级标记抢占资源，确保信任模型成立。
5. 跨域时 DSCP 会发生什么？要点：可能被清零或重标记，端到端保证依赖域间约定（如隧道内层/外层 DSCP 处理策略）。
6. EF 为什么必须限速？要点：EF 通常使用严格优先级调度，若不限速会饿死其它队列，时延保证同时失效。

## 九、演进与趋势
演进集中在两点。一是与主动队列管理协同：仅靠类级带宽分配无法控制排队时延，需要在每类队列上引入 AQM 控制驻留时间。二是与低时延传输结合：L4S 使用 ECN 的 ECT(1) 与专用 AQM，把「低时延」从优先级语义转为端到端信号语义。此外，可编程数据面让 PHB 映射与计量更灵活，云与园区网也在推广「业务到 DSCP」的自动化策略下发，减少手工配置偏差。具体定义以官方最新文档为准。

## 十、小结
差分服务用 6 个比特把「保证」从流粒度压缩到类粒度，从而把复杂度从核心推到边界：核心只需一张 DSCP 到队列的映射表和类级调度器，边界则负责分类、计量、标记与整形。它的保证是相对的、域内的、类级的——理解这三条边界，才不会把它误当成逐流硬保证。
