# 显式拥塞通知

> 对应 RFC 3168（ECN）；RFC 9331（L4S / ECT(1)）。

## 一、背景与挑战
传统靠丢包通知拥塞，代价高且滞后，还会引发 bufferbloat（缓冲区堆积致高时延）。ECN 让路由器在将拥塞时“标记”而非“丢”，给端系统提前信号。

## 二、核心原理
IP ToS 低 2 位为 ECN 域：00 Non-ECT、10 ECT(0)、01 ECT(1)、11 CE。支持 ECN 的路由器在队列超阈值时把 ECT 包标记成 CE。TCP 在 ACK 中回 ECE，发送方减半 cwnd 并置 CWR。L4S（RFC 9331）用 ECT(1) 做低时延可扩展拥塞信号。

## 三、形式化 / 数学基础
ECN 编码：$ECT(0)=10_2,\ ECT(1)=01_2,\ CE=11_2$（二进制两位）。
处理：路由器见 ECT≠00 且拥塞 → 置 CE；否则不改。
TCP 标志：ECE（回声 CE）、CWR（窗口已减）。

## 四、代码实现
```c
if (queue_len > K) && (ecn == ECT0 || ecn == ECT1) {
    ip->ecn = CE;            // 标记而非丢弃
}
if (tcp->flags & ECE) {
    cwnd >>= 1; tcp->flags |= CWR;   // 降速并通知
}
```

## 五、与其他技术对比
ECN（无损、提前）vs 丢包（有损、滞后）；L4S 的 ECT(1) 配合更激进 AQM（如 DualPI2）实现低时延多流共享，区别于传统 ECT(0) 的 Reno 友好。

## 六、常见误区
误区一：ECN 会丢包。错，标记代替丢。误区二：开了 ECN 就无丢包。错，极端拥塞仍丢。误区三：所有应用都受益。错，对时延敏感流效益最大。

## 九、演进与趋势
L4S（RFC 9330/9331）将 ECN 扩展为可扩展低时延信号，与 BBR/DCTCP 配合降排队。

## 十、小结
ECN 让路由器以标记代替丢弃提前示警，减少丢包与排队，是现代 AQM 的关键信号。
