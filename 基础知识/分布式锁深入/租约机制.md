# 租约机制

> 对应 Gray & Cheriton《Leases: An Efficient Fault-Tolerant Mechanism for Distributed File Cache Consistency》(1989)。

## 一、背景与挑战
锁常需在“有限时间”内自动释放以防死锁。租约(lease)是一种带期限的授权：持有者在期限内拥有权利，过期自动失效，无需依赖释放消息。

## 二、核心原理
- 授予：服务端给客户端一个租约，含 TTL(如 10s)。
- 续租：客户端在到期前发 renew 延长(携带更高 epoch，防旧持有者)。
- 失效：到期未续则自动失效，资源可被他人获取。
- 时钟假设：要求 TTL >> 时钟漂移 δ，且服务端用自身时钟判定到期，避免依赖客户端时间。
租约广泛用于缓存一致性、分布式锁、Leader 权威。

## 三、形式化 / 数学基础
设授予时刻 t0，TTL = L。有效区间 [t0, t0+L]。
安全性：若两个租约区间不重叠，则不会双持(在 L > 最大时钟漂移且续租及时时成立)。
过期窗口风险：若持有者停顿 >= L，则他人已获租约，存在短暂双活窗口，需 fencing 兜底。

## 四、代码实现
```python
import time
class Lease:
    def __init__(self, ttl): self.ttl = ttl; self.expire = time.time() + ttl
    def valid(self): return time.time() < self.expire
    def renew(self, ttl): self.expire = time.time() + ttl
```

## 五、与其他技术对比
- 相比“永久锁 + 显式释放”：租约自愈，不怕持有者崩溃。
- 相比 fencing：租约管“何时失效”，fencing 管“过期后陈旧请求如何被拒”，常配合使用。

## 六、常见误区
- 误区：租约过期一定安全。停顿超 TTL 会出现双活，需 fencing。
- 误区：TTL 越短越安全。过短增加续租开销与抖动。

## 九、演进与趋势
租约成为共识系统 Leader 权威的基础(如 Raft 心跳即隐式租约)；与 fencing token 成标准组合。

## 十、小结
租约以带期限的授权实现故障自愈的互斥，是分布式锁与缓存一致性的核心机制；但需配合 fencing 消除过期窗口风险。
