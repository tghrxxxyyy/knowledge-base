# 慢启动与拥塞避免

> 对应 RFC 5681 §3 与 Jacobson 1988；参考 Kurose & Ross《Computer Networking》。

## 一、背景与挑战
连接起始不知网络容量，需先快速探测（慢启动），接近容量后转为谨慎线性增长（拥塞避免）以防过载。

## 二、核心原理
- 慢启动：cwnd 从 1 MSS 起，每收到 ACK 指数增长（+1 per ACK），直到达到 ssthresh。
- 拥塞避免：超过 ssthresh 后每 RTT 线性 +1 MSS（AI）。
丢包触发 ssthresh=cwnd/2，cwnd 降为 ssthresh（Reno），或 1（Tahoe）。

## 三、形式化与数学基础
慢启动：
  cwnd_{k+1} = cwnd_k + cwnd_k = 2*cwnd_k  (每 RTT 翻倍)
拥塞避免：
  cwnd += 1 MSS per RTT
探测到容量 C 的 RTT 数：
  slow_start = log2(C)

## 四、代码实现
// 慢启动到拥塞避免切换
void on_ack(cong *c) {
    if (c->cwnd < c->ssthresh) {
        c->cwnd += 1;                 // SS：指数（每 ACK +1）
    } else {
        c->cwnd += 1.0 / c->cwnd;     // CA：AI
    }
}

## 五、与其他技术对比
慢启动指数快但易过冲；拥塞避免线性稳但恢复慢（Reno 在长肥管道劣势）。

## 六、常见误区
1. 名字"慢"启动其实很快——指数增长。
2. 混淆 ssthresh 初始值（常 65535 或随实现）。

## 九、演进与趋势
HyStart 检测 RTT 抬升提前退出慢启动，减少过冲。

## 十、小结
慢启动快速探顶、拥塞避免稳健维持，是 TCP 吞吐爬升的双阶段机制。
