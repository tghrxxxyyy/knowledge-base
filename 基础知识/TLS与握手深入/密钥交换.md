# 密钥交换

> 对应 RFC 8446（TLS 1.3 Key Exchange）；DH / ECDHE。

## 一、背景与挑战
通信双方需在公开信道协商出只有彼此知道的共享密钥，且防窃听（前向安全）。早期 RSA 密钥传输把预主密钥用服务器公钥加密，但无前向安全。

## 二、核心原理
现代 TLS 用 (EC)DHE：双方各自生成临时公私钥，交换公钥，各自用自己私钥与对端公钥计算共享秘密 $S = g^{ab}$。TLS 1.3 仅保留 DHE/ECDHE（ ephemeral），彻底移除静态 RSA 密钥传输。

## 三、形式化 / 数学基础
Diffie-Hellman：$公钥 A = g^a \bmod p$，$B = g^b \bmod p$；$共享 S = B^a = A^b = g^{ab} \bmod p$。
椭圆曲线（ECDHE）：$A = aG$，$B = bG$，$S = abG$（群运算点乘）。
密钥派生：$master\_secret = HKDF(shared\_S,\ ...)$（TLS 1.3 用 HKDF，RFC 5869）。

## 四、代码实现
```python
from cryptography.hazmat.primitives.asymmetric import ec
priv = ec.generate_private_key(ec.SECP256R1())
pub  = priv.public_key()
shared = priv.exchange(ec.ECDH(), peer_pub)   # = abG
```

## 五、与其他技术对比
ECDHE（临时）vs 静态 DH/RSA：前者每连接换新密钥，具前向安全；后者长期密钥泄露可解密历史流量。RSA 密钥传输已弃用。

## 六、常见误区
误区一：密钥交换把密钥“传”给对方。错，双方各自计算，从不传输共享秘密。误区二：DHE 比 ECDHE 安全。错，等价安全下 ECDHE 密钥更短更快。误区三：前向安全由证书保证。错，由临时密钥（ephemeral）保证。

## 十、小结
密钥交换用 ECDHE 在公开信道协商共享秘密并借此获得前向安全，是 TLS 机密性的根基。
