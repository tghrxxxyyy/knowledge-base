# 前向安全

> 对应 RFC 8446（ephemeral 要求）；Whitfield Diffie 概念。

## 一、背景与挑战
若长期私钥（服务器 RSA 私钥或静态 DH 密钥）泄露，攻击者能否解密历史 recorded 流量？若可以，则无前向安全（Forward Secrecy, FS）。这对应“事后攻破”风险。

## 二、核心原理
前向安全要求每次会话使用一次性临时密钥（ephemeral, ECDHE），会话结束后丢弃。即使服务器长期私钥泄露，也无法还原当时的共享秘密，因为临时私钥已销毁、不出现在任何持久数据里。

## 三、形式化 / 数学基础
设长期密钥 $K_{long}$，会话临时密钥 $e_i$。FS 成立当：$解密(密文_i)\ 仅需\ e_i$，而 $e_i$ 在会话结束即删，与 $K_{long}$ 无关。
非 FS（RSA 传输）：预主密钥用 $K_{pub}$ 加密，握有 $K_{priv}$ 即可解密历史流量 → 无 FS。

## 四、代码实现
```python
# 每次连接新生成临时密钥，会话结束 del
ephemeral_priv = ec.generate_private_key(ec.SECP256R1())
# ... 握手使用 ephemeral_priv ...
del ephemeral_priv   # 会话结束即销毁，保证前向安全
```

## 五、与其他技术对比
ECDHE（FS）vs 静态 DH / RSA 密钥传输（无 FS）。PFS（Perfect Forward Secrecy）是 FS 的强形式。QUIC/TLS 1.3 强制 ephemeral。

## 六、常见误区
误区一：有加密就有前向安全。错，RSA 密钥传输加密但无 FS。误区二：证书私钥泄露不影响历史。错，若无 FS，RSA 传输的流量可被解密。误区三：FS 靠频繁换证书。错，靠临时会话密钥。

## 九、演进与趋势
TLS 1.3 强制 ephemeral；后量子算法（ML-KEM）亦设计为前向安全。

## 十、小结
前向安全依赖每次会话的临时密钥，使长期密钥泄露也无法解密历史流量，是 TLS 1.3 的硬性要求。
