# 握手流程

> 对应 RFC 8446（TLS 1.3 握手）；RFC 5246（TLS 1.2）。

## 一、背景与挑战
握手要在不安全的信道完成密码套件协商、密钥交换、身份认证与密钥确认，且尽量省 RTT。1.2 与 1.3 流程差异巨大。

## 二、核心原理
TLS 1.3 1-RTT 握手：ClientHello（含 key_share、supported_groups、supported_versions）→ ServerHello（key_share）+ EncryptedExtensions + Certificate + CertificateVerify + Finished；客户端回 Finished。之后应用数据即可。支持 0-RTT 携带 early data。

## 三、形式化 / 数学基础
密钥调度：$shared = ECDHE\ share$；$handshake\_secret = HKDF(shared,\ 0)$；$client\_handshake\_traffic\_secret = Derive(handshake\_secret,\ "c hs traffic")$；
$server$ 同理；最终 $master\_secret = HKDF(handshake\_secret,\ ...)$，$application\_traffic\_secret = Derive(master,\ "c ap traffic")$。
握手消息哈希用于 CertificateVerify 签名：$\text{TranscriptHash}$。

## 四、代码实现
```text
C -> S: ClientHello {versions, groups, key_share, cipher_suites}
S -> C: ServerHello {key_share}
      + EncryptedExtensions + Certificate + CertVerify + Finished
C -> S: Finished
// 此后 Application Data 双向加密
```

## 五、与其他技术对比
TLS 1.2 全握手 2 RTT（含 Certificate 在 ServerHello 后、需 ClientKeyExchange）；1.3 压缩到 1 RTT 且加密大部分握手。DTLS 握手面向 UDP，需重传与无状态 Cookie。

## 六、常见误区
误区一：TLS 握手一定 2 RTT。错，1.3 通常 1 RTT、可 0-RTT。误区二：Finished 只是确认。错，它用 MAC 绑定全部握手消息防篡改。误区三：ClientKeyExchange 在 1.3 仍有。错，1.3 移除之。

## 九、演进与趋势
0-RTT 与 PSK 恢复普及；后量子握手正在并入 1.3。

## 十、小结
TLS 1.3 握手用 ECDHE + HKDF 调度密钥，1-RTT 完成且加密大部分消息，是现代安全通信标准流程。
