# 偿还策略

> 对应 Martin "Tech Debt Quadrant"、重构节奏实践。

## 一、背景与挑战
债务无限累积会拖垮交付速度，但一次性还清又中断业务。需要成本收益驱动的偿还节奏。

## 二、核心原理
Martin 提出债务四象限（鲁莽/谨慎 × 有意/无意）。策略：在改动相关代码时顺手偿还（ Boy-Scout）、为高风险高利息债务排专门偿还、用"债务上限"约束新增。

## 三、形式化 / 数学基础
偿还决策：当预期利息节省 $\sum I(t)$ 超过偿还成本 $C_{pay}$ 且 $C_{pay}<budget$ 时执行。设置债务上限 $TDR \le T_{max}$。

## 四、代码实现
```text
# 每次触及模块时，预留 20% 工时还债
sprint_capacity = feature_hours + 0.2 * feature_hours  # 还债预算
```

## 五、与其他技术对比
与"重构 sprint"相比，持续小幅偿还更平滑；与完全不还很不同，需主动治理。

## 六、常见误区
误区：设 100% 偿还目标不现实。误区：只还看得见的不还架构债。

## 七、与开源书 / 权威来源对应
Martin, R. C. "A Mess is not a Technical Debt"（债务象限）；Fowler 技术债务文章；CS-Notes: https://github.com/CyC2018/CS-Notes

## 八、面试题
"如何制定还债计划？什么是技术债务象限？"

## 九、演进与趋势
把债务偿还写入 OKR/团队协议，设组织级债务预算。

## 十、小结
按利息率与预算持续偿还，设债务上限。
