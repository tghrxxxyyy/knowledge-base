# 偿还策略

> 对应 Martin 技术债务象限（Tech Debt Quadrant）、Fowler 技术债务文章与 Boy-Scout 重构节奏实践；参考 CS-Notes（CyC2018）。

## 一、背景与挑战

技术债务若无限累积，会线性乃至指数地拖垮交付速度（每次改动都因耦合、脆弱测试而变慢变险）。但另一方面，一次性「还清所有债务」的重构 sprint 会中断业务、耗尽信任，且不现实——探索期有意债务本就是合理的杠杆。挑战在于：如何在「持续交付」与「还债」之间找到成本收益驱动的节奏，既不陷入债务雪崩，也不因过度清洁而停滞。

关键认知是：债务有「利息率」差异，应优先偿还高利息、高风险的债务，而非平均用力。

## 二、核心原理

Martin 提出债务四象限：按「鲁莽/谨慎」与「有意/无意」组合。无意且鲁莽的债务最危险（不知情下的草率），应优先消除；有意且谨慎的债务是可管理杠杆。偿还策略据此：

1. Boy-Scout 规则：每次触及某模块时顺手改善一点（「离开时比来时干净」），把还债摊进日常，避免专项中断。
2. 风险/利息优先：对高利息、高失败率的债务排专门偿还（如关键路径上的脆弱模块）。
3. 债务上限约束：设 TDR 上限，超线即冻结新功能、划拨专项预算。
4. 变更驱动：优先在「即将改动」的区域还债，因为改动本身就要理解代码，边际成本最低。

## 三、形式化与数学基础（含 LaTeX）

偿还决策基于利息节省与成本比较：若预期累计利息节省超过偿还成本且在预算内，则执行：

$$
\sum_{t} I_t(\text{after}) - \sum_{t} I_t(\text{before}) > C_{\text{pay}},\quad C_{\text{pay}} < \text{budget}
$$

设债务上限：

$$
\text{TDR} \le T_{\max}
$$

对多候选按「利息率」$k$（每期多付维护成本占本金比）排序，优先高 $k$：

$$
\text{priority} \propto k \cdot P,\qquad P=\text{principal}
$$

即本金大且利息率高的债务最先还，等价于金融中的「高息债务优先偿还」原则。

## 四、代码实现

```text
# 每次触及模块时，预留还债工时（结构示意）
sprint_capacity = feature_hours + 0.2 * feature_hours   # 20% 还债预算
# Boy-Scout：本次改动模块时，顺手消除该模块的坏味道
```

```python
# 按利息率排还债优先级（结构示意）
def rank_debts(debts):
    # debts: [{principal, interest_rate, touched_soon}]
    scored = []
    for d in debts:
        s = d["interest_rate"] * d["principal"]
        if d.get("touched_soon"):
            s *= 1.5                        # 将改动区域加权
        scored.append((s, d))
    return [d for _, d in sorted(scored, reverse=True)]
```

## 五、与其他技术对比

- 与「重构 sprint（专项还清）」相比：持续小幅偿还（Boy-Scout）更平滑、对交付冲击小，但需纪律。
- 与「完全不还」相比：主动治理避免雪崩，代价是日常少量工时。
- 与「平均还债」相比：按利息率优先更符合经济学，避免在不重要处过度清洁。

## 六、常见误区

- 「设 100% 偿还目标」：不现实且浪费，探索债是合理杠杆。
- 「只还看得见的不还架构债」：架构债利息率最高却被忽视。
- 「一次性大重构 sprint」：中断业务、易失败，应常态化小额。
- 「不区分债务类型」：无意鲁莽债需紧急消除，有意谨慎债可接受。

## 九、演进与趋势

把债务偿还写入 OKR / 团队协议，设组织级「债务预算」像财务预算一样被审批；架构适应度函数在 CI 中自动校验约束，使偿还从「道德呼吁」转为「工程纪律」。结合度量可视化，偿还效果可被持续验证。

## 十、小结

偿还策略以 Martin 债务象限区分债务性质，按利息率与风险优先、用 Boy-Scout 节奏持续小额偿还，并以 TDR 上限兜底。其权威基础是 Martin 与 Fowler 的债务方法论，落地关键是把还债编入日常产能而非孤立 sprint。
