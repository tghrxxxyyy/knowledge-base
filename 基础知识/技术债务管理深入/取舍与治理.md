# 取舍与治理

> 对应 "Technical Debt Governance"、精益与权衡分析。

## 一、背景与挑战
还债与交付永远冲突，缺乏治理机制会让债务在隐形中失控，或在治理中僵化。

## 二、核心原理
治理 = 透明（可见）+ 决策（谁在何时承担债务）+ 上限（阈值告警）+ 复盘（债务如何产生）。业务与技术共同对"利息"负责，而非技术单方面背锅。

## 三、形式化 / 数学基础
用成本收益比 $R = \frac{NPV(节省)}{C_{pay}}$ 排序候选。设阈值 $R_{min}$，仅当 $R>R_{min}$ 才排期；超上限触发强制治理会议。

## 四、代码实现
```text
governance_policy:
  debt_ratio_limit: 0.05
  review_if_exceed: true
  owner: tech-lead + pm
```

## 五、与其他技术对比
与"技术独裁"相比，共治让业务理解代价；与"完全自由"相比，有上限防失控。

## 六、常见误区
误区：把债务治理推给工具自动解决。误区：只在事故后才治理（被动）。

## 七、与开源书 / 权威来源对应
McConnell, S.《Managing Technical Debt》；Martin 债务象限；CS-Notes: https://github.com/CyC2018/CS-Notes

## 八、面试题
"如何建立技术债务治理机制？业务应如何参与？"

## 九、演进与趋势
债务作为产品待办项（backlog item）与业务优先级统一排序。

## 十、小结
透明、共担、设限、复盘，把债务变成可治理决策。
