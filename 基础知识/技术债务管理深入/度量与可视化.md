# 度量与可视化

> 对应 SonarQube 技术债务指标与 McConnell《Managing Technical Debt》方法论；参考 CS-Notes（CyC2018）。

## 一、背景与挑战

「看不见的债务无法管理」——技术债务常被团队凭感觉争论（「代码有点乱」「再不重构不行了」），缺乏与业务对话的共同语言。度量缺失会导致两类问题：要么盲目相信「没有报错的代码就是好代码」，要么陷入主观扯皮、无法排优先级。可视化则是把度量转化为决策信号的关键：趋势图揭示债务是在累积还是被消化，热图定位热点模块。挑战在于指标本身会被「玩游戏」（goodhart 定律），单一数字易误导，需在指标体系与组织用法上同时下功夫。

## 二、核心原理

度量的核心是用可量化、可复现的信号刻画债务：

1. 代码级信号：重复率（duplicated lines）、圈复杂度（cyclomatic complexity）、方法/类规模、单元测试覆盖率。
2. 债务比率（TDR）：修复成本 / 开发成本，作为整体健康度的归一化指标。
3. 可靠性/可维护性评级：SonarQube 等工具以规则违例加权估算「理想修复天数」。
4. 趋势与分布：按模块/团队的债务热图、随时间的趋势线，识别累积方向与责任归属。

可视化把这些信号呈现在看板，使「还哪里的债、还到什么程度」成为可讨论、可承诺的议题。

## 三、形式化与数学基础（含 LaTeX）

技术债务比率定义为修复成本与开发成本之比：

$$
\text{TDR}=\frac{\text{RemediationCost}}{\text{DevelopmentCost}}
$$

SonarQube 以 $\text{TDR}<5\%$ 评为 A 级，并给出各规则类型权重 $w_k$ 与问题数 $n_k$，估算理想修复天数：

$$
\text{RemediationCost}=\sum_k w_k \cdot n_k \cdot t_k
$$

其中 $t_k$ 为单类问题的平均修复工时。圈复杂度 $v(G)$ 衡量单函数的独立路径数：

$$
v(G)=e-n+2p
$$

$e,n,p$ 分别为控制流图的边、节点、连通分量数，值越高越难测、越易藏 bug。

## 四、代码实现

```bash
# SonarScanner 输出债务指标（结构示意）
sonar-scanner -Dsonar.projectKey=demo -Dsonar.host.url=http://sonar
# 关注：technicalDebt、coverage、duplicated_lines_density、sqale_rating
```

```python
# 计算模块债务热（结构示意）
def module_debt(metrics):
    # metrics: {module: {complexity, coverage, dup}}
    scores = {}
    for m, v in metrics.items():
        # 复杂度高、覆盖低、重复高 => 债务重
        scores[m] = v["complexity"] * (1 - v["coverage"]) + v["dup"]
    return sorted(scores.items(), key=lambda x: -x[1])   # 热模块优先
```

## 五、与其他技术对比

- 与纯主观评估相比：度量提供基线、可复现、可对比，支撑跨团队横向比较。
- 与「只看行数/bug 数」相比：组合多指标 + 趋势更能反映真实健康度。
- 风险：单一指标（如覆盖率）易被刷分，应以指标组合与趋势为主，辅以人工评审。

## 六、常见误区

- 「只盯一个指标」：覆盖率 100% 仍可能架构混乱，需多维组合。
- 「把度量当 KPI 惩罚团队」：会引发刷分与隐瞒，应作为改进信号而非考核鞭子。
- 「忽视趋势只看病快照」：单日数值意义有限，趋势方向才说明治理是否有效。
- 「工具分高即无债」：静态分析覆盖不到设计债、文档债等软债务。

## 九、演进与趋势

代码健康分（Code Health）结合机器学习预测债务热点与 defect 概率；将度量嵌入 PR 检查，给出「本次变更引入的债务增量」；与 DORA 等交付效能指标联动，把债务利息翻译成业务可懂的交付速度损耗，使可视化成为经营决策入口。

关键是将度量转化为行动：当某 PR 的「债务增量」超阈值时自动评论并建议还债项，使可视化不止于看板，而是嵌入工作流。同时应定期对指标本身做校准，防止工具升级导致历史趋势断裂。

## 十、小结

度量与可视化以 TDR、复杂度、覆盖率、重复率等组合信号把隐形债务显性化，并通过趋势与热图支撑优先级决策。其权威基础是 McConnell 与 SonarQube 方法论，落地关键是多维组合、避免刷分、作为改进信号而非惩罚工具。
