# 度量与可视化

> 对应 SonarQube 指标、McConnell《Managing Technical Debt》方法论。

## 一、背景与挑战
债务"看不见"就无法管理，团队凭感觉争论，缺乏与业务对话的共同语言。

## 二、核心原理
用可量化信号：代码重复率、圈复杂度、覆盖率、债务比率（Technical Debt Ratio = 修复成本 / 开发成本）。通过趋势图、热图在看板可视化，让债务可见。

## 三、形式化 / 数学基础
技术债务比率 $TDR = \frac{RemediationCost}{DevelopmentCost}$，SonarQube 以 $TDR<5\%$ 为 A 级。修复成本按"理想天数"估算，每问题类型有权重。

## 四、代码实现
```bash
# SonarScanner 输出债务指标
sonar-scanner -Dsonar.projectKey=demo
# 关注 technicalDebt / coverage / duplicated_lines_density
```

## 五、与其他技术对比
与纯主观评估相比，度量提供基线；但单一数字（如行数）易误导，应组合多指标与趋势。

## 六、常见误区
误区：只盯一个指标（如覆盖率）造成假象。误区：把度量当 KPI 惩罚团队。

## 七、与开源书 / 权威来源对应

## 九、演进与趋势
代码健康分（Code Health）结合 ML 预测债务热点。

## 十、小结
组合度量 + 趋势可视化，使债务可被治理对话。
