# 债务分类

> 对应 Cunningham「Ward Explains Debt Metaphor」（1992）与软件债务分类研究；参考 Martin《Clean Code》、CS-Notes（CyC2018）。

## 一、背景与挑战

「技术债务」常被笼统指责为「代码不够好」，但不同债务的成因、利息率与偿还代价迥异。把「探索期有意借的杠杆」和「无意留下的草率缺陷」混为一谈，会导致资源误投：要么在不重要的债上过度清洁，要么对高危债视而不见。分类的意义，是为治理提供「先还哪类、怎么还」的决策依据，使债务从情绪化讨论转为可管理对象。

挑战在于：真实系统里债务常交叉（一个模块同时有代码债、测试债、架构债），且「本金」难以精确计量，多为相对估计，需要定性标签与定量信号结合。

## 二、核心原理

按性质（技术维度）分类：

1. 代码债务：坏味道（长函数、重复、魔法数），局部可修。
2. 设计债务：结构缺陷（不当继承、职责错位）。
3. 架构债务：边界/耦合问题（循环依赖、层违反），代价最高。
4. 文档债务：缺失/过时的设计、接口说明，增加理解成本。
5. 测试债务：覆盖不足或脆弱测试，回归风险高。
6. 基础设施债务：落后依赖、手工部署、无 IaC。

按意图（决策维度）分类（Martin 象限）：谨慎/鲁莽 × 有意/无意。无意且鲁莽者最危险，需紧急消除；有意且谨慎者是可管理杠杆。

## 三、形式化与数学基础（含 LaTeX）

债务可建模为本金 $P$ 与利息流 $I(t)$：每期因债务多付的维护/返工成本为

$$
I(t)=k\cdot P\cdot \gamma(t)
$$

$k$ 为利息率（依赖债务类型与意图），$k_{\text{reckless}}>k_{\text{prudent}}$；$\gamma(t)$ 为随系统演化的放大因子（如耦合度上升）。鲁莽债因 $k$ 高应优先偿还。多维分类可用标签向量：

$$
\mathbf{d}=(d_{\text{type}},\, d_{\text{intent}},\, P,\, k)
$$

治理时按 $k\cdot P$ 排序（见偿还策略）。注意「本金」$P$ 多为相对估计（理想人天），难以精确，故决策宜用排序而非绝对值。

## 四、代码实现

```python
# 债务分类标签与排序（结构示意）
def classify(debt):
    # debt: {type, intent, principal, interest_rate}
    debt["label"] = f"{debt['type']}/{debt['intent']}"
    return debt

def priority(debts):
    # 按利息率 * 本金排序；鲁莽无意为最高
    scored = sorted(
        debts,
        key=lambda d: d["interest_rate"] * d["principal"],
        reverse=True,
    )
    return scored
```

## 五、与其他技术对比

- 与金融债务不同：技术债利息不是线性可控，且「本金」难以精确计量，多为相对估计。
- 与单维「代码坏味道」相比：多维分类（性质+意图）更能指导治理优先级。
- 与「全量还清」相比：分类后可有意保留低息探索债，集中资源打高息债。

## 六、常见误区

- 「所有债务都要立刻还清」：过度偿还拖慢交付，忽略探索债的杠杆价值。
- 「把一切不完美都叫债务」：需区分「债务（有利息的取舍）」与「普通不完美」。
- 「只按类型不还按意图」：无意鲁莽债比有意谨慎债危险得多。
- 「本金可精确核算」：实际多为估计，应重排序轻绝对值。

## 九、演进与趋势

把债务作为可追踪资产纳入 issue 模板与架构决策记录（ADR），用标签向量驱动看板；结合 LLM 辅助从代码评审、事故复盘自动提取债务候选并建议分类，降低人工标注成本，使分类成为持续治理的入口。

## 十、小结

债务分类按「性质（代码/设计/架构/文档/测试/基础设施）× 意图（谨慎/鲁莽 × 有意/无意）」多维刻画，揭示了利息率差异与优先偿还依据。其源流是 Cunningham 的债务隐喻与 Martin 象限，落地需定性标签结合定量排序，而非笼统指责「代码不好」。
