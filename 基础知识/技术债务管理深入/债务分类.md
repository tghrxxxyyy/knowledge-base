# 债务分类

> 对应 Cunningham "Ward Explains Debt Metaphor"、软件债务分类研究。

## 一、背景与挑战
"技术债务"常被笼统指责，但不同债务成因与代价迥异，混合管理会误投资源。

## 二、核心原理
按性质分：代码债务（坏味道）、设计债务（结构缺陷）、架构债务（边界/耦合）、文档债务、测试债务、基础设施债务。按意图分：谨慎有计划的债务 vs 鲁莽无意的债务。

## 三、形式化 / 数学基础
债务可建模为本金 $P$ 与利息 $I(t)$：每期因债务多付的维护成本 $I = k\cdot P$。鲁莽债务利息率高 $k_{reckless}>k_{prudent}$，应优先偿还高 $k$。

## 四、代码实现

```text
# 简单分类标签（用于看板）
debt = { type: "design", intent: "reckless", principal: 5, interest_rate: 0.3 }
```

## 五、与其他技术对比
与金融债务不同，技术债利息不是线性可控，且"本金"难以精确计量，多为相对估计。

## 六、常见误区
误区：所有债务都要立刻还清（过度偿还拖慢交付）。误区：把一切不完美都叫债务。

## 七、与开源书 / 权威来源对应

## 八、面试题

## 九、演进与趋势
把债务作为可追踪资产纳入 issue 模板与架构决策记录（ADR）。

## 十、小结
先分类与度量利息率，再决定偿还优先级。
