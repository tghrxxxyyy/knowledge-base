# 命名与函数

> 对应 Martin《Clean Code》第2章 "Meaningful Names"、第3章 "Functions"。

## 一、背景与挑战
糟糕命名迫使读者反查上下文，长函数掩盖意图，参数列表混乱增加调用错误。

## 二、核心原理
命名应"揭示意图"而非描述实现；函数应短小（<20 行）、只做一件事、参数尽量少（<3）、无副作用。命令与查询分离。

## 三、形式化 / 数学基础
函数纯度可用副作用集合度量：$SideEffects(f) = \{s \mid f\ 修改\ s\}$。理想纯函数 $SideEffects=\emptyset$，便于推理与测试。

## 四、代码实现
```python
# 差
def get(d):  # 含义模糊，且修改了状态
    d['x'] += 1
    return d['x']
# 好
def increment_counter(counter: Counter) -> int:
    counter.value += 1
    return counter.value
```

## 五、与其他技术对比
与"匈牙利命名"等旧规不同，现代风格强调"可读优先"；与函数式编程共享"小而纯"理念。

## 六、常见误区
误区：用缩写节省字符。误区：用布尔参数切换行为（应拆两个函数）。

## 七、与开源书 / 权威来源对应
Martin, R. C.《Clean Code》第2、3章；CS-Notes: https://github.com/CyC2018/CS-Notes

## 八、面试题
"什么是命令查询分离？为什么函数参数不宜过多？"

## 九、演进与趋势
类型推导与静态类型（TypeScript、Rust）部分替代命名中对类型的暗示。

## 十、小结
好命名即好文档，小函数聚焦单一意图。
