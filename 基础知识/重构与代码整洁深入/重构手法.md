# 重构手法

> 对应 Fowler《Refactoring》目录中的 60+ 重构（Refactorings）。

## 一、背景与挑战
重构是在不改变外部行为的前提下改善内部结构。需要一套"小步、可验证"的手法组合，避免大爆炸式重写。

## 二、核心原理
每个重构是"名称 + 动机 + 做法 + 示例"的结构化操作，如 Extract Method、Rename、Move Method、Replace Conditional with Polymorphism、Introduce Parameter Object。

## 三、形式化 / 数学基础
重构保持行为等价：设变换 $T$，对全部输入 $x$，有 $f_{before}(x)=f_{after}(T(x))$。每一步后运行测试套件验证该等价性（回归保护）。

## 四、代码实现
```python
# Extract Method
def print_owing(invoice):
    outstanding = sum(i.amount for i in invoice.items)  # 提取为 calc_outstanding()
    print("name:", invoice.customer)
    print("amount:", outstanding)
```

## 五、与其他技术对比
重构区别于重写（rewrite，改变行为或技术栈）与性能优化（可能改变结构但不一定改善可读性）。

## 六、常见误区
误区：不写测试就重构。误区：一次做多个重构导致无法定位回归。
