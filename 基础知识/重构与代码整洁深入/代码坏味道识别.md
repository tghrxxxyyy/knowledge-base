# 代码坏味道识别

> 对应 Fowler《Refactoring》第3章 "Bad Smells in Code"。

## 一、背景与挑战
坏味道（code smell）是"代码中可能指示更深层次问题的表面征象"，并非错误，但提示重构机会。识别它们是重构第一步。

## 二、核心原理
Fowler 归纳了约 20 种坏味道，分为五类：膨胀（Bloaters，如 Long Method、Large Class）、面向对象滥用、变更障碍（Shotgun Surgery）、冗余（Duplicated Code）、耦合（Message Chains、Middle Man）。

## 三、形式化 / 数学基础
可用量化指标辅助：方法行数 $L_m$、圈复杂度 $CC = E - N + 2P$（E 边、N 节点、P 谓词），当 $CC>10$ 视为高风险；重复率 $Dup=\frac{重复代码行}{总代码行}$。

## 四、代码实现
```python
# Duplicated Code 坏味道
def invoice_us(order):
    return order.qty * order.price * 1.0
def invoice_eu(order):
    return order.qty * order.price * 1.2  # 税率逻辑重复
# 应提取 calc(order, rate)
```

## 五、与其他技术对比
坏味道是启发式，不是度量阈值；与静态分析工具（SonarQube）互补，工具给数字、人判断意图。

## 六、常见误区
误区：见到重复就抽方法，忽略语义差异。误区：把坏味道当 bug 直接修，应重构而非重写。

## 九、演进与趋势
IDE 实时高亮坏味道、AI 辅助识别重复，使识别成本下降。

## 十、小结
坏味道是可操作的重构信号，需结合意图判断。
