# 测试护盾

> 对应 Fowler《Refactoring》"Testing"、Beck《Test-Driven Development》。

## 一、背景与挑战
没有测试网，重构如同走钢丝。测试套件是允许安全重构的"护盾"，提供快速反馈。

## 二、核心原理
在重构前先有覆盖关键行为的测试；遵循测试金字塔（多单元测试、少端到端）。TDD 以"红-绿-重构"循环把测试变为设计工具。

## 三、形式化 / 数学基础
覆盖率指标：行覆盖 $C_{line}=\frac{被执行行}{总行}$，分支覆盖 $C_{branch}=\frac{覆盖分支}{总分支}$。护盾强度更取决于"突变测试"存活率 $M=\frac{未检测突变}{总突变}$，越低越好。

## 四、代码实现
```python
def test_calc_outstanding():
    inv = Invoice(items=[Item(10), Item(20)])
    assert calc_outstanding(inv) == 30  # 重构前后断言不变
```

## 五、与其他技术对比
与"调试驱动开发"相反，TDD 先写失败测试。与类型系统互补：类型防一类错误，测试防行为错误。

## 六、常见误区
误区：追求 100% 行覆盖而忽略断言质量。误区：重构后不跑全量测试。

## 八、面试题

## 九、演进与趋势
AI 生成测试、Property-Based Testing 提升护盾密度。

## 十、小结
测试套件是重构的安全网，质量优于覆盖率数字。
