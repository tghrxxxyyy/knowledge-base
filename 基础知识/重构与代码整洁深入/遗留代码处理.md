# 遗留代码处理

> 对应 Feathers《Working Effectively with Legacy Code》。

## 一、背景与挑战
遗留代码指"没有测试的代码"。直接改易碎，需先建立"接缝"（seam）才能安全注入测试。

## 二、核心原理
Feathers 提出"遗留代码改动算法"：先识别改动点，找测试点，打破依赖（如子类化、接口提取），写 characterization test 锁定当前行为，再重构。

## 三、形式化 / 数学基础
接缝：$seam$ 是程序中点，其旁行为可在不修改该点代码的前提下被替换。设依赖 $D$ 经接缝 $S$ 注入，则测试可传 $D_{fake}$：$call(S, D_{fake})$。

## 四、代码实现
```python
# 用子类覆盖受保护方法以隔离依赖
class MyService(LegacyService):
    def get_time(self):
        return FIXED_TIME  # 便于 characterization test
```

## 五、与其他技术对比
与绿地重构不同，遗留代码优先"锁行为"而非"改善结构"。与测试替身技术强相关。

## 六、常见误区
误区：先大改结构再加测试（顺序反了）。误区：凭印象假设旧行为。

## 七、与开源书 / 权威来源对应
Feathers, M.《Working Effectively with Legacy Code》；CS-Notes: https://github.com/CyC2018/CS-Notes

## 八、面试题
"如何处理没有测试的老代码？什么是 characterization test？"

## 九、演进与趋势
可观测性（tracing、影子流量）辅助推断旧行为，降低 characterization 成本。

## 十、小结
先缝测试、锁行为，再渐进重构。
