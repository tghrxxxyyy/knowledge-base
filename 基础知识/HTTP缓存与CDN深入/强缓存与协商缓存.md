# 强缓存与协商缓存

> 对应 RFC 7234 §4-§5；参考 xiaolincoder/hello-http（HTTP 缓存章节）。

## 一、背景与挑战
缓存分两级：强缓存（不发请求，直接本地取）与协商缓存（发请求，服务器判 304）。二者协同决定命中路径。

## 二、核心原理
- 强缓存：Cache-Control: max-age / Expires 满足时，浏览器直接使用，状态 200 (from cache)。
- 协商缓存：强缓存失效后，带 If-None-Match / If-Modified-Since 询问，304 表示未变。

## 三、形式化与数学基础
判定流程：
  if (now < freshness_time) -> 强缓存命中
  else if (validator matches) -> 304 协商命中
  else -> 200 新资源
新鲜度生命周期：
  heuristic = (Date - Last-Modified) * 0.10  (启发式，无 max-age 时)

## 四、代码实现
// 浏览器缓存判定伪代码
if (cache.maxAge > 0 && now - resp.time < cache.maxAge)
    return FROM_CACHE;
if (req.ETag == resp.ETag)
    return NOT_MODIFIED; // 304
return FETCH_NEW;

## 五、与其他技术对比
强缓存零网络往返，协商缓存至少 1 RTT（通常 304 体积小）。CDN 边缘同样遵循该模型。

## 六、常见误区
1. 认为 304 比强缓存快——强缓存根本不发请求。
2. 用 Last-Modified 秒级精度易碰撞，ETag 更稳。
