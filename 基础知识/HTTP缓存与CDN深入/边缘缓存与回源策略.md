# 边缘缓存与回源策略

> 对应 CDN 标准实践；参考 RFC 7234 与 xiaolincoder/hello-http（缓存与 CDN 章）。

## 一、背景与挑战
边缘节点如何决定缓存什么、何时回源、如何保持新鲜，直接影响成本与一致性。

## 二、核心原理
- 分层回源：边缘 -> 区域父层 -> 源站，减少跨区回源。
- 条件回源：仅当不可缓存或过期才回源；支持 stale-while-revalidate（后台刷新）。
- 主动推送/预热：内容发布时主动写入边缘。

## 三、形式化与数学基础
stale-while-revalidate 扩展新鲜度：
  可立即返回 stale，同时后台验证，期限 = max-age + stale_while_revalidate
回源带宽：
  B_origin = B_total * (1 - HR_edge) * (1 - HR_parent)

## 四、代码实现
# 伪代码：stale-while-revalidate
def get(url):
    obj = cache.get(url)
    if obj and obj.age < obj.max_age:
        return obj                       # 新鲜
    if obj and obj.age < obj.max_age + obj.swr:
        async_refresh(url)               # 后台回源
        return obj                       # 返回旧值
    return origin.fetch(url)

## 五、与其他技术对比
传统回源是同步阻塞，SWR 提升用户感知速度但可能短暂返回旧值，需业务容忍。

## 六、常见误区
1. 滥用 stale-while-revalidate 导致脏数据长时间可见。
2. 回源风暴：大量节点同一时刻回源，需加锁/合并。

## 九、演进与趋势
边缘 KV 与计算让回源策略更智能（按内容热度分层）。

## 十、小结
回源是缓存成本与新鲜度的平衡点，分层+SWR+合并是成熟方案。
