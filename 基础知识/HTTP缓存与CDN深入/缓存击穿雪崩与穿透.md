# 缓存击穿雪崩与穿透

> 对应通用分布式缓存工程实践（Redis 官方文档 / 美团技术博客模式）；参考 xiaolincoder/hello-http。

## 一、背景与挑战
高并发下缓存异常会导致数据库被瞬间打垮，常见三类问题：击穿、雪崩、穿透。

## 二、核心原理
- 击穿：热点 key 过期瞬间大量请求直达 DB。用互斥锁/单飞（singleflight）重建。
- 雪崩：大量 key 同时过期或缓存宕机，请求洪峰击垮 DB。用随机过期时间、多级缓存。
- 穿透：查询不存在的数据，缓存与 DB 都无，恶意刷库。用布隆过滤器/空值缓存。

## 三、形式化与数学基础
单飞：并发 N 请求合并为 1 次 DB 查询：
  DB_queries = 1 (而非 N)
布隆过滤器误判率：
  p ≈ (1 - e^{-kn/m})^k
其中 k=哈希函数数，m=位数组大小，n=元素数。

## 四、代码实现
# Go singleflight 防止击穿
import "golang.org/x/sync/singleflight"
var g singleflight.Group
func get(key string) (v Value, err error) {
    v, err, _ = g.Do(key, func() (interface{}, error) {
        return db.Load(key) // 仅一个协程回源
    })
    return
}

## 五、与其他技术对比
三者根因不同：击穿是单点热点、雪崩是集体失效、穿透是无效 key，解法各异。

## 六、常见误区
1. 用空值缓存穿透却不设短 TTL，浪费内存。
2. 随机过期时间方差太小仍可能雪崩。
