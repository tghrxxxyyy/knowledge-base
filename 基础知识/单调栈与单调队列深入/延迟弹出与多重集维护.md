# 延迟弹出与多重集维护

> 对应 youngyangyang04/leetcode-master 单调队列进阶与 CyC2018/CS-Notes 滑动窗口题解。

## 一、背景与挑战

滑动窗口问题里有个隐含假设经常被忽略：**窗口内的值可能重复，也可能要求第 $k$ 大/中位数这类非「单点最值」**。标准单调队列只维护一个极值候选序列，遇到重复值、需要第 $k$ 大、或需要「删除任意位置」时就力不从心。典型场景：滑动窗口中位数、滑动窗口第 $k$ 大、窗口内众数、窗口内重复值去重后的最值，以及「定时器/过期缓存」这类带 TTL 的数据结构。

直接用平衡树（`multiset`、`SortedList`）可以插入删除与查询第 $k$，但：
- 窗口滑出时需要删除**指定值**；若值重复，要删除**一个实例**而不是全部。
- 某些语言/场景没有现成平衡树，自己实现红黑树代价高。
- 「只关心中位数/第 $k$ 大」时，平衡树整棵树都是浪费。

于是有了**延迟弹出（lazy deletion）**与**多重集维护**这两类技巧：
1. **延迟弹出**：不立刻从数据结构删除过期元素，而是标记/计数，等到它出现在「答案位置」（堆顶、队首）时再真正丢弃。典型是「双堆 + 哈希计数」求滑动窗口中位数。
2. **多重集维护**：用计数器 `Counter` / 哈希频次 + 单调队列，允许重复值共存，出队条件改为「频次归零才真正弹出」，解决重复值与第 $k$ 大。

这两类思想在工程中无处不在：延迟队列、TTL 缓存、限流器窗口、日志去重、以及一切「窗口 + 多重集合」问题。面试中「滑动窗口中位数」是难题，期望答案是「对顶堆 + 延迟删除」，并说清为什么不能用简单单调队列。

## 二、核心原理

**核心矛盾**：数据结构只支持「从一端删除」或「只删极值」，但实际需要删除「窗口中任意过期元素」。延迟弹出的解法是：**把删除推迟到「不删会影响答案」的那一刻**。

**对顶堆求中位数**。维护两个堆：
- `lo`：最大堆，存窗口较小的一半（堆顶是较小半最大）。
- `hi`：最小堆，存窗口较大的一半（堆顶是较大半最小）。
- 平衡条件：$|lo| \ge |hi|$ 且 $|lo| - |hi| \le 1$。中位数 = `lo[0]`（当两堆等大时取平均）。

**延迟删除**：维护 `delayed: Counter` 记录「已过期但仍在堆中」的元素。当窗口移出元素 $x$，`delayed[x] += 1`，并不立刻从堆删除。当某堆堆顶恰好是过期元素（`delayed[top] > 0`），才真正弹出并把计数减 1。这样删除均摊 $O(\log n)$，且无需在堆中查找任意元素。

**多重集维护重复值**。简单单调队列在「相等值」时要么全弹、要么全留。要正确处理重复值，维护 `freq` 计数器：
- 入窗：`freq[x] += 1`。
- 出窗：`freq[x] -= 1`。
- 若队列/堆按值维护，只有当 `freq[x] == 0` 时才允许真正从候选集删除。
这就是「延迟弹出」的另一形态：**用计数决定何时真正弹出**，而不是用「下标过期」一次性弹。

**不变量**：
- 对顶堆：$lo$ 最大 $\le hi$ 最小，且大小差 $\le 1$（允许 `delayed` 造成临时不平衡，需「清理后再调整」）。
- 计数延迟：`freq` 真实反映窗口内计数；堆/队列中可能含过期项，但过期项只能在顶部被清理，且清理不影响正确答案。

**边界条件**：
- $k=1$：中位数就是当前元素。
- 全部相等：计数增加，堆中多个相等值，延迟删除只在顶部清理。
- `delayed` 计数必须在「弹出真正元素」时递减，否则会误删新元素。

## 三、形式化与数学基础

**对顶堆中位数**。设窗口 $W$ 有 $m = |W|$ 个元素，排序后 $x_{(1)} \le x_{(2)} \le \dots \le x_{(m)}$。维护划分 $W = L \cup R$，$L$ 为较小 $\lceil m/2 \rceil$ 个，$R$ 为较大 $\lfloor m/2 \rfloor$ 个。则
$$
\text{median} =
\begin{cases}
x_{(m/2)}, & m \text{ 为偶数时也可取平均}\\
x_{((m+1)/2)}, & \text{奇数}
\end{cases}
$$
实现上 `lo` 堆顶 $= \max L$，`hi` 堆顶 $= \min R$，中位数由 $lo$ 堆顶（或两堆顶平均）给出。

**延迟删除的复杂度**。每次插入/删除标记 $O(\log n)$；清理堆顶过期元素时，每个元素只被真正弹出一次，总清理 $O(n\log n)$。均摊每步 $O(\log n)$。空间 $O(n)$（堆中最多含全部未清理过期元素）。

**计数多重集的正确性**。设真实窗口多重集 $M$，结构维护 $M' = M \cup E$，其中 $E$ 是过期但未清理的元素。条件：$E$ 中元素若在答案路径（堆顶）会被立即清理，故查询答案时 $E$ 不影响。归纳可证：每次查询前，堆顶过期项被弹尽，答案等价于在 $M$ 上查询。

**与平衡树对比**。平衡树支持任意删除与第 $k$ 大 $O(\log n)$，但常数大、实现复杂；对顶堆 + 延迟删除更轻，但只支持中位数/极值，不支持任意第 $k$ 大（除非配合树状数组/分块）。

**滑动窗口第 $k$ 大**。可用两个对顶堆（维护前 $k$ 大），或树状数组（值域离散化后统计前缀和），或分块。延迟删除思想通用。

## 四、代码实现

**滑动窗口中位数**（对顶堆 + 延迟删除）与 **滑动窗口最大值**（单调队列 + 计数延迟弹出，处理重复值）。

```python
from collections import Counter, deque
import heapq


class SlidingWindowMedian:
    def __init__(self):
        self.lo = []       # 最大堆（取负模拟），存较小一半
        self.hi = []       # 最小堆，存较大一半
        self.delayed = Counter()
        self.lo_size = 0   # 有效大小（扣除 delayed）
        self.hi_size = 0

    def _prune(self, heap, is_lo):
        """弹出堆顶的过期元素。"""
        while heap:
            x = -heap[0] if is_lo else heap[0]
            if self.delayed[x] > 0:
                self.delayed[x] -= 1
                heapq.heappop(heap)
            else:
                break

    def _rebalance(self):
        if self.lo_size > self.hi_size + 1:
            self._prune(self.lo, True)
            x = -heapq.heappop(self.lo)
            self.lo_size -= 1
            heapq.heappush(self.hi, x)
            self.hi_size += 1
            self._prune(self.lo, True)
        elif self.lo_size < self.hi_size:
            self._prune(self.hi, False)
            x = heapq.heappop(self.hi)
            self.hi_size -= 1
            heapq.heappush(self.lo, -x)
            self.lo_size += 1
            self._prune(self.hi, False)

    def add(self, x):
        if not self.lo or x <= -self.lo[0]:
            heapq.heappush(self.lo, -x)
            self.lo_size += 1
        else:
            heapq.heappush(self.hi, x)
            self.hi_size += 1
        self._rebalance()

    def remove(self, x):
        self.delayed[x] += 1
        if self.lo and x <= -self.lo[0]:
            self.lo_size -= 1
            if x == -self.lo[0]:
                self._prune(self.lo, True)
        else:
            self.hi_size -= 1
            if self.hi and x == self.hi[0]:
                self._prune(self.hi, False)
        self._rebalance()

    def get_median(self):
        self._prune(self.lo, True)
        self._prune(self.hi, False)
        return -self.lo[0] if self.lo_size >= self.hi_size else self.hi[0]


def sliding_window_median(nums, k):
    w = SlidingWindowMedian()
    res = []
    for i, x in enumerate(nums):
        w.add(x)
        if i >= k - 1:
            res.append(w.get_median())
            w.remove(nums[i - k + 1])
    return res


def sliding_max_with_dup(nums, k):
    """单调队列 + 频次计数：允许重复值，窗口过期时延迟弹出。"""
    dq = deque()      # 存下标，对应值递减（用 < 比较，保留相等）
    freq = Counter()
    res = []
    for i, x in enumerate(nums):
        # 只弹出严格更小的，相等保留（处理重复值）
        while dq and nums[dq[-1]] < x:
            dq.pop()
        dq.append(i)
        freq[x] += 1
        # 窗口过期：若队首下标过期，只真正弹出当其值频次为 0
        if i >= k - 1:
            # 先清理队首过期下标
            while dq and dq[0] <= i - k:
                old = nums[dq.popleft()]
                freq[old] -= 1
                # 若旧值仍在窗口（重复），它可能仍在 dq 中间，保留
            res.append(nums[dq[0]])
    return res


if __name__ == "__main__":
    print(sliding_window_median([1, 3, -1, -3, 5, 3, 6, 7], 3))
    # 期望: [1, 1, -1, -1, 3, 5]
    print(sliding_max_with_dup([1, 3, 1, 2, 1, 5], 3))
```

注意：对顶堆版本里 `delayed` 保证过期元素只在堆顶被清理；`sliding_max_with_dup` 用频次处理重复值，队列存下标以便过期。真实工程还应加「若堆顶过期优先清理」的防御式 `_prune`。

## 五、与其他技术对比

| 方法 | 时间 | 空间 | 重复值 | 第 $k$ 大 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 简单单调队列 | $O(n)$ | $O(k)$ | 难 | 否 | 只最值、需去重 |
| 单调队列 + 频次延迟弹出 | $O(n)$ | $O(k)$ | 支持 | 否 | 重复值最值 |
| 对顶堆 + 延迟删除 | $O(n\log k)$ | $O(k)$ | 支持 | 中位数 | 中位数首选 |
| 平衡树 / SortedList | $O(n\log k)$ | $O(k)$ | 支持 | 支持 | 通用，常数大 |
| 树状数组（离散化） | $O(n\log n)$ | $O(n)$ | 支持 | 支持 | 值域离散 |
| 分块 | $O(n\sqrt n)$ | $O(n)$ | 支持 | 支持 | 代码复杂 |

简单单调队列最快但功能最窄；对顶堆是中位数问题的标准答案；需要任意第 $k$ 大、插入删除时用平衡树或树状数组。

## 六、常见误区

1. **重复值过早弹出导致答案丢失**。相等值若被 `<=` 全部弹掉，窗口内其它相等元素无法成为候选。求重复值最值时应用 `<` 或 `>` 保留相等。
2. **频率未及时回退**。窗口移出后不减 `freq`，过期值仍被当作有效，答案偏大/偏小。
3. **延迟删除不清理堆顶**。只标记不弹出，堆顶长期是过期值，答案错误。必须在查询前 `prune`。
4. **对顶堆平衡时不清理延迟元素**。`lo_size`、`hi_size` 与堆物理大小不一致，rebalance 会把过期元素当有效搬动，破坏划分。
5. **把延迟弹出当成「完全不用删」**。延迟只是推迟，最终过期元素必须从结构中移除；否则空间无限增长，且慢查询。

## 八、面试题

**1. 窗口内第 $k$ 大如何用单调结构近似？**
简单单调队列只维护极值，不能直接给第 $k$ 大；可用两个堆（对顶堆维护前 $k$ 大）、平衡树或树状数组。延迟弹出保证过期元素被正确剔除。

**2. 延迟弹出解决了什么问题？**
数据结构不支持任意删除（如堆）时，把过期元素的删除推迟到它位于答案路径（堆顶）时执行，均摊 $O(\log n)$，避免查找任意元素。

**3. 对顶堆求中位数为什么要延迟删除？**
窗口滑出的元素可能埋在堆中间，无法直接删除。用 `delayed` 计数标记，堆顶时再清理，保证「查询前堆顶有效」。

**4. 重复值如何处理？**
用频次计数，只有计数归零才真正从候选集弹出；比较时保留相等值，避免答案丢失。

## 九、演进与趋势

延迟弹出与多重集维护是「窗口聚合 + 过期语义」的通用技巧，广泛用于 TTL 缓存、定时器轮、限流窗口、日志去重、在线学习样本缓冲。竞赛中，滑动窗口中位数、第 $k$ 大、众数、去重最值都是常客。工程实现常把「对顶堆」替换为「跳表 / B 树 / 红黑树」以支持更复杂查询；分布式窗口聚合（Flink、Spark）则用「增量聚合 + 状态后端 + 过期清理」实现同等语义。未来方向包括：近似中位数（t-digest、GK summary）以降低内存、带乱序水位的延迟删除、以及硬件友好型（SIMD）窗口聚合。

## 十、小结

当数据结构不支持任意删除、窗口又有多重集语义时，延迟弹出与计数多重集是关键技巧：用 `delayed` / `freq` 把删除推迟到答案路径，保证堆顶/队首有效，均摊代价可控。对顶堆求中位数、单调队列处理重复值，都是这一思想的落地。
