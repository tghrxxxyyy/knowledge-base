# 单调队列与滑动窗口最大值

> 对应 youngyangyang04/leetcode-master 单调队列（滑动窗口最大值）与 CyC2018/CS-Notes。

## 一、背景与挑战

滑动窗口最值是流式数据处理的经典问题：数组每向右滑动一格，要求出当前长度为 $k$ 的窗口内最大（或最小）值。它在监控告警（最近 5 分钟峰值）、行情系统（滚动最高价）、限流器（窗口内计数峰值）、图像处理（最大池化 max-pooling）中无处不在。暴力做法是每个窗口重新扫描 $k$ 个元素，$O(nk)$；当 $n=10^6$、$k=10^4$ 时直接不可行。

一个自然优化是用堆（优先队列）：维护窗口内元素，取堆顶。但堆有个麻烦——窗口滑出时，元素「过期」了，却埋在堆中间，无法高效删除。常见做法是「懒删除」：堆顶若已过期就丢弃重取。这可以工作，但每次操作 $O(\log k)$，常数较大，且实现要小心过期标记。

单调队列给出更优雅的答案：维护一个**双端队列（deque）**，存放下标，对应值单调递减（求最大值）。入队时从队尾弹出所有更小值（它们永不可能成为后续最大），队首若下标过期则出队。这样**队首始终是当前窗口最大值**，每次操作均摊 $O(1)$。它同时解决了「最值」与「过期」两件事，而且无需堆、无需懒删除标记。

这一结构在面试中的出现频率很高：滑动窗口最大值、最小值、窗口第 k 大（进阶）、跳跃游戏 VI、子数组最小值之和、以及一切「窗口内单调候选」问题。期望答案不是背代码，而是说清「为什么队尾可以弹、为什么队首要过期、为什么均摊 $O(1)$」。

## 二、核心原理

维护一个双端队列 `dq`，存下标，满足 `nums[dq[0]] >= nums[dq[1]] >= ...`（递减，求最大）。

处理下标 $i$ 时三步：

1. **踢掉队尾无用候选**：当 `nums[dq[-1]] <= nums[i]`，弹出队尾。因为 $i$ 比它们大且更靠右，它们在任何包含 $i$ 的未来窗口里都不可能是最大值。
2. **入队**：把 $i$ 从队尾加入。
3. **过期出队**：若 `dq[0] <= i - k`，说明队首下标已滑出窗口左边界，从队首弹出。可能一次弹多个（连续过期），但每个下标只过期一次。
4. **取答案**：当 $i \ge k-1$，`nums[dq[0]]` 即窗口 $[i-k+1, i]$ 的最大值。

不变量：
- 队列下标对应值严格递减（或非严格，取决于是否保留相等）。
- 队列中的下标都在当前窗口内（或即将入窗）。
- 队首是当前窗口最大值；队列是「候选最大值」的单调列表。

为什么这样正确？窗口最大值一定是窗口内某个元素；对任意窗口元素 $x$，若它右边有更大元素，$x$ 永远不是最大。队尾弹出正是把这些「注定无用」的元素提前清掉，使队列保持「每个候选都可能在未来窗口成为最大」。队首只需检查是否过期。

边界条件：
- $k=1$：队列只含当前元素，答案就是 `nums[i]`。
- 全部相等：比较用 `<=` 会全部弹出只剩最后一个；用 `<` 会保留多个相等值。题目若要求「最左/最右」，需相应选择。
- $k > n$：应提前判定或按题意处理，一般约束 $1 \le k \le n$。
- 求最小值时：整体反转比较符号，维护递增队列。

## 三、形式化与数学基础

设窗口 $W_i = [i-k+1, i]$（当 $i \ge k-1$），定义
$$
M_i = \max_{j \in W_i} nums[j].
$$

单调队列维护候选集合 $C_i \subseteq W_i$，使得
$$
M_i = \max_{j \in C_i} nums[j],
$$
且 $C_i$ 中下标对应值递减。于是 $M_i = nums[dq[0]]$。

**正确性（归纳）**。$i=0$ 时队列含 0，显然。假设 $i$ 时不变量成立，处理 $i+1$：
- 队尾弹出的是所有 $\le nums[i+1]$ 的旧候选，它们在任何含 $i+1$ 的窗口都不再是最大（被 $i+1$ 支配），故可安全删除。
- 队首过期者不在 $W_{i+1}$ 中，必须删除。
- 剩余队列仍是 $W_{i+1}$ 内候选的递减序列，且最大者在队首。

**均摊复杂度**。每个下标入队 1 次、出队至多 1 次（从队尾或队首），故总操作 $O(n)$，均摊每步 $O(1)$。最坏单步可能连续弹出多个（例如递减序列后突然来个超大值），但总弹出次数被 $n$ 约束。

**与堆的对比公式**。堆每次 push/pop $O(\log k)$，总 $O(n \log k)$，常数较大，且懒删除需要额外哈希记录过期。单调队列 $O(n)$，且下标天然携带过期信息，无需额外结构。

**空间**。队列最多 $O(k)$ 个下标（递减序列），加上答案数组 $O(n-k+1)$。空间 $O(n)$ 输出，$O(k)$ 队列。

**滑动窗口最小值**同理，维护递增队列，比较符号反转。

## 四、代码实现

标准滑动窗口最大值，附带最小值与「用堆 + 懒删除」对照实现，方便理解取舍。

```python
from collections import deque
import heapq


def sliding_window_max(nums, k):
    """滑动窗口最大值。返回每个窗口最大值列表。"""
    if not nums or k == 0:
        return []
    dq = deque()          # 存下标，对应值递减
    res = []
    for i, x in enumerate(nums):
        # 队尾更小值永不可能是后续最大，弹出
        while dq and nums[dq[-1]] <= x:
            dq.pop()
        dq.append(i)
        # 队首过期：下标已滑出窗口左端
        if dq[0] <= i - k:
            dq.popleft()
        if i >= k - 1:
            res.append(nums[dq[0]])
    return res


def sliding_window_min(nums, k):
    """滑动窗口最小值：维护递增队列。"""
    dq = deque()
    res = []
    for i, x in enumerate(nums):
        while dq and nums[dq[-1]] >= x:
            dq.pop()
        dq.append(i)
        if dq[0] <= i - k:
            dq.popleft()
        if i >= k - 1:
            res.append(nums[dq[0]])
    return res


def sliding_window_max_by_heap(nums, k):
    """对照：最大堆 + 懒删除（过期元素不立即删，取堆顶时再判断）。"""
    res, heap = [], []
    for i, x in enumerate(nums):
        heapq.heappush(heap, (-x, i))
        while heap and heap[0][1] <= i - k:
            heapq.heappop(heap)          # 弹出过期
        if i >= k - 1:
            res.append(-heap[0][0])
    return res


if __name__ == "__main__":
    a = [1, 3, -1, -3, 5, 3, 6, 7]
    k = 3
    print(sliding_window_max(a, k))          # [3, 3, 5, 5, 6, 7]
    print(sliding_window_min(a, k))          # [-1, -3, -3, -3, 3, 3]
    print(sliding_window_max_by_heap(a, k))  # [3, 3, 5, 5, 6, 7]
```

要点：双端队列两端都要能删（队尾弹小、队首弹过期），故必须用 deque 而非普通栈/队列；下标而非值存入，才能判断过期；比较用 `<=` 还是 `<` 决定相等元素保留策略，需与题意一致。

## 五、与其他技术对比

| 方法 | 时间 | 空间 | 过期处理 | 备注 |
| --- | --- | --- | --- | --- |
| 暴力每窗扫描 | $O(nk)$ | $O(1)$ | 无需 | 仅小 $n,k$ |
| 单调队列 | $O(n)$ | $O(k)$ | 下标天然过期 | 最优，面试首选 |
| 最大堆 + 懒删除 | $O(n\log k)$ | $O(k)$ | 需标记/判断堆顶 | 动态插入删除更灵活 |
| 平衡树 / multiset | $O(n\log k)$ | $O(k)$ | 删除指定元素 | 可求第 $k$ 大 |
| 稀疏表 ST | $O(n\log n)$ 预处理，$O(1)$ 查询 | $O(n\log n)$ | 无滑动删除 | 静态区间最值 |

单调队列是「只滑动、只问最值」场景的最优解；堆与平衡树在需要插入/删除任意元素、或求第 $k$ 大时更合适；稀疏表适合静态、多次查询、无插入删除。

## 六、常见误区

1. **队列存值不存下标**。无法判断元素是否过期，必须用下标与 $i-k$ 比较。
2. **只用单端队列或栈**。队尾弹小、队首弹过期，两端都操作，必须是双端队列。
3. **比较符号不一致导致相等元素处理错**。`<=` 会弹出相等，窗口最大值取最右；`<` 保留相等。题目要求「最左最大值」时用 `<`，要求「最右」时用 `<=`。
4. **忘了队首过期检查**。队首可能长时间是最大值，但下标已出窗，直接取会错误返回旧值。
5. **把最坏单步当成均摊**。单次循环里 `while` 可弹出很多，但总弹出 $O(n)$；报告复杂度时说均摊 $O(1)$。

## 八、面试题

**1. 单调队列为何必须用双端队列？**
队尾要弹出「比新元素小」的无用候选，队首要弹出「已滑出窗口」的过期元素，两端都需 $O(1)$ 删除，故 deque。

**2. 它与单调栈的异同？**
都用单调性维护候选；单调栈只在一端进出，用于「下一个更大」；单调队列两端进出并处理窗口过期，用于「滑动窗口最值」。单调队列可看作「带过期的单调栈」。

**3. 窗口内第 k 大如何用单调结构？**
简单单调队列只维护最值，无法直接给第 $k$ 大；需要平衡树（如 sorted list）或「两个堆（对顶堆）」维护，见延迟弹出与多重集维护。

**4. 为什么均摊 $O(1)$？**
每个下标最多入队 1 次、出队至多 1 次，总操作 $O(n)$，故均摊每步 $O(1)$；最坏单步可 $O(k)$。

## 九、演进与趋势

单调队列是「滑动窗口聚合」的理论基础，广泛出现在流处理（Flink、Spark Streaming 的窗口聚合）、行情引擎（滚动极值）、图像卷积与 max-pooling、以及游戏服务器的限流统计。竞赛中常与动态规划结合（如跳跃游戏 VI、滑动窗口最值优化 DP），把 $O(nk)$ 优化到 $O(n)$。进阶方向包括：滑动窗口中位数（对顶堆/平衡树）、滑动窗口第 $k$ 大（多层单调或离线分块）、以及在线算法中的「单调队列 + 延迟删除」组合。在系统面试中，它常作为「大数据窗口聚合」的缩影，考察候选人对流式复杂度的敏感度。

## 十、小结

单调队列用「递减候选 + 下标过期」两个不变量，把滑动窗口最值做到均摊 $O(1)$：队尾弹出永远无用的小值，队首弹出已过期的旧值，队首即答案。它比堆更轻、比暴力更快，是窗口最值问题的标准答案。
