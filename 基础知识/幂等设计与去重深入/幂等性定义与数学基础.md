# 幂等性定义与数学基础

> 对应 Gray 1978（Notes on Data Base Operating Systems）与 DDIA 第11章（流处理与幂等）。

## 一、背景与挑战
网络不可靠导致客户端超时重试，同一请求可能被投递多次。若服务端操作非幂等（如「余额减 10」），重复执行会产生错误结果。幂等设计让「执行一次」与「执行多次」效果相同，是构建可靠系统的基石。

## 二、核心原理
数学上，操作 f 幂等当且仅当 \\(f(f(x)) = f(x)\\)。在分布式服务中，这意味着携带相同「幂等键」的重复请求，第二次及以后应被识别并跳过实际副作用，或重放相同结果。

## 三、形式化与数学基础
设状态转移函数 \\(S' = apply(S, req)\\)，对重复请求 \\(req\\)（同键）：
\\[
apply(apply(S, req), req) = apply(S, req)
\\]
即二次应用不改变结果。等价于该操作在状态空间上是幂等映射。

## 四、代码实现
```python
def transfer(req_id, from_, to_, amount, seen):
    if req_id in seen:          # 已处理
        return seen[req_id]     # 返回原结果
    result = do_transfer(from_, to_, amount)
    seen[req_id] = result
    return result
```

## 五、与其他技术对比
事务回滚处理「失败撤销」，幂等处理「重复执行」；at-most-once 靠不重试，at-least-once 必须配合幂等才能安全。

## 六、常见误区
1. 认为重试天然安全：非幂等操作重试会放大副作用。
2. 只在客户端去重：服务端仍需，因多客户端或重试路径不同。
3. 用请求内容而非稳定键判重：相同业务语义应有同一键。

## 七、与开源书/权威来源对应
Gray 1978 讨论「幂等事务」与可重启操作；DDIA 第11章强调流处理需幂等 sink。

## 八、面试题
问：HTTP 中哪些方法幂等？
答：GET、PUT、DELETE 语义上幂等；POST 默认不幂等。

## 九、演进与趋势
云厂商把「幂等键」作为 API 标准字段（如支付、订单创建），框架层自动去重。

## 十、小结
幂等是「重试安全」的数学保证，靠稳定键加状态记忆实现。
