# 幂等与分布式事务

> 对应 Gray 1978 与 DDIA 第9章、第12章（分布式事务与共识）。

## 一、背景与挑战
两阶段提交（2PC）等分布式事务保证原子性，但协调者故障会阻塞；Saga 等补偿式事务用「反向操作」回滚。幂等在二者中都很关键：重试子事务、重放日志都要求子操作可安全重复。

## 二、核心原理
在 Saga 中，每个本地事务与其补偿事务都应幂等，这样在故障恢复重放时不会重复扣款或重复补偿。2PC 的「prepare 或 commit」若需重试，也依赖参与者对重复 commit 的幂等响应。

## 三、形式化与数学基础
补偿应满足 \\(comp(comp(S)) = comp(S)\\)（补偿也幂等），且 \\(comp(apply(S,T)) = S\\)（语义回滚）。重试算子 \\(R\\) 满足 \\(R(R(x))=R(x)\\)。

## 四、代码实现
```python
def saga_step(tx_id, op):
    if done(tx_id, op):
        return result_of(tx_id, op)   # 幂等：已执行直接返回
    r = execute(op)
    mark_done(tx_id, op, r)
    return r

def compensate(tx_id, op):
    if compensated(tx_id, op):
        return
    undo(op); mark_compensated(tx_id, op)
```

## 五、与其他技术对比
2PC 强一致但可用性低、易阻塞；Saga 高可用但需幂等补偿；幂等是这两种方案下重试安全的共同前提。

## 六、常见误区
1. 认为 Saga 自动安全：补偿非幂等会导致重复反向操作。
2. 2PC 协调者重试 commit 不考虑幂等：参与者需容忍重复 commit。
3. 把「发送消息」当可回滚：应转「可取消或可确认」的 TCC 模式。

## 七、与开源书/权威来源对应
Gray 1978 讨论事务幂等与可重启；DDIA 第9、12章讲分布式事务与共识替代。

## 八、面试题
问：为何 Saga 补偿必须幂等？
答：故障恢复会重放补偿，非幂等补偿会重复撤销造成状态错误。

## 九、演进与趋势
TCC（Try-Confirm-Cancel）把幂等内置于三阶段，配合事务消息落地。

## 十、小结
无论 2PC 还是 Saga，子操作与补偿的幂等是故障重试安全的前提。
