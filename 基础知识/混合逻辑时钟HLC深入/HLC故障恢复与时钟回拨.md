# HLC故障恢复与时钟回拨

> 对应 HLC 论文（Kulkarni et al. 2014）与 DDIA 第8章。

## 一、背景与挑战
节点崩溃重启、时钟被 NTP 回拨、或者从快照恢复后，本地 HLC 可能落后真实时间或其他节点，导致分配的时间戳违反单调性或因果序。恢复协议必须保证 \\(l\\) 不会「倒流」到不合理位置。

## 二、核心原理
重启后，节点取 \\(l = \max(local\_pt, persisted\_l)\\)，并强制 \\(l \ge pt - \epsilon\\)。若发现自身 HLC 落后太多（超过阈值），通过心跳从对端拉取较新 HLC 并前移，必要时施加短暂「时钟跳跃保护」避免假历史。

## 三、形式化与数学基础
恢复后约束：
\\[
pt - \epsilon \le l_{new} \le \max(pt, l_{old}) + \delta
\\]
其中 \\(\delta\\) 为允许的前移量，保证 \\(l\\) 既不太旧也不无限膨胀。

## 四、代码实现
```python
def recover(local_l, local_c, pt, eps=50, delta=1000):
    l_new = max(pt - eps, local_l, pt)
    if l_new - local_l > delta:
        l_new = local_l + delta   # 限制前移
    return l_new, 0
```

## 五、与其他技术对比
TrueTime 靠硬件避免回拨；纯物理时钟重启易产生重复时间戳；HLC 通过 max 与持久化状态天然抗回拨。

## 六、常见误区
1. 重启直接用当前物理时间：可能丢弃崩溃前的因果进度。
2. 无限制前移 l：会被误判为「未来事件」触发重试风暴。
3. 忽略持久化：内存态丢失即回拨。

## 七、与开源书/权威来源对应
HLC 论文讨论持久化与重启正确性；DDIA 强调单调时钟对恢复的重要性。

## 八、面试题
问：HLC 重启为何要取 max 而非直接用物理时间？
答：避免时间戳回退破坏因果序与单调性，并保留崩溃前的进度下界。

## 九、演进与趋势
将 HLC 持久化进 WAL，使恢复与日志回放一致。

## 十、小结
HLC 通过 max 约束与有界前移，在故障恢复中维持单调与因果正确。
