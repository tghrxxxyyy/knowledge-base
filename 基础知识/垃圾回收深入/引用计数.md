# 引用计数

> 对应 Jones《GC Handbook》第 1 章 与 CS-Notes（Python GC）。

## 一、背景与挑战
引用计数 (RC) 为每个对象记引用数，归零即回收，可增量为局部、无全局暂停。挑战：循环引用、计数开销、原子计数成本（多线程）。

## 二、核心原理
`refcount(o)` 在引用建立 +1、销毁 -1；为 0 时回收并递归减其引用域。循环引用需配合 tracing GC 或弱引用/打破环。

## 三、形式化 / 数学基础
不变量：若 `o` 可达则 `rc(o) > 0`；若不可达则最终 `rc(o) = 0`（无环时）。
维护：`rc(o)+=1` on `p=o`；`rc(o)-=1` on `p` 失效；若变 0 则 free 并 `rc(field)-=1`。

## 四、代码实现
```python
def ref_down(o):
    o.rc -= 1
    if o.rc == 0:
        for f in o.refs:
            ref_down(f)   # 递归回收子对象
        free(o)
```

## 五、与其他技术对比
- RC：即时、局部、无大暂停；但有环泄漏、每引用开销。
- Tracing：处理环、批量但暂停。
- 混合（CPython）：RC 主体 + 周期性 tracing 收环。

## 六、常见误区
1. 以为 RC 能回收循环（不能，需 cycle collector）。
2. 忽略递归 `ref_down` 栈溢出（大环）。
3. 多线程未用原子计数致竞态。

## 十、小结
引用计数以每引用开销换即时局部回收，但循环引用是其阿喀琉斯之踵；实践中多以 tracing 兜底循环。
