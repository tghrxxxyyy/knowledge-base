# 分代回收

> 对应 Jones《GC Handbook》第 6 章 与 CS-Notes（JVM GC）。

## 一、背景与挑战
分代假说：多数对象朝生暮死。把堆分代（年轻/老年），只对年轻代频繁回收。挑战：跨代引用（卡片表/记忆集）、老年代晋升、full GC 代价。

## 二、核心原理
年轻代用复制 GC；存活多次的对象晋升 (promote) 到老年代。跨代指针用 write barrier 记录 （card table）避免全堆扫描根。

## 三、形式化 / 数学基础
弱分代假说：被回收时大多数对象年轻。晋升年龄 $age(o)$ 达到阈值 $\tau$ 则移入 old gen。
Write barrier：当 `old.obj = young` 时标记对应 card，使 minor GC 把该 card 当根。

## 四、代码实现
```python
def write_barrier(obj, field, val):
    obj[field] = val
    if in_old(obj) and in_young(val):
        card[card_index(obj)] = DIRTY   # 记录跨代引用
# minor GC 根 = roots + DIRTY cards
```

## 五、与其他技术对比
- 分代：常见、贴合假说、minor 快；需 write barrier。
- 不分代：实现简但全堆慢。
- 分区域 (G1/ZGC)：把堆分 region 平衡停顿。

## 六、常见误区
1. 漏 write barrier 致跨代引用丢失（误回收老年代指向）。
2. 误以为分代消除 full GC（老年满仍需）。
3. 晋升阈值不当致过早晋升/反复复制。

## 十、小结
分代回收基于"年轻对象多死"的实证：以 write barrier 维护跨代边界，使 minor GC 廉价；是 JVM/.NET 的默认基石。
