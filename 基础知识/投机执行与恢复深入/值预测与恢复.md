# 值预测与恢复

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》；参考 value prediction 与置信度门控（confidence gating）机制（Lipasti & Shen 等）。

## 一、背景与挑战

部分指令产生高度可预测的值：指针链遍历（load 的地址来自上一次 load 的结果）、计数循环、规整数组偏移、间接跳转目标等。值预测（value prediction）猜测某指令的输出，以提前解除 RAW 数据依赖，让后续指令投机使用预测值。一旦预测错误就必须回滚恢复。收益取决于准确率——错误恢复代价可能压垮并行收益，因此值预测必须配「置信度门控」才实用。

值预测面对的最大障碍是「收益正负号不确定」：分支预测的错误代价是固定的流水线冲刷，而值预测的错误代价随依赖链长度增长——预测错一条链首指令，可能要回滚其后数十条已经投机执行的指令。这使得值预测的可行性阈值远高于分支预测，也是它在通用处理器中迟迟未大规模落地的根本原因。

## 二、核心原理

值预测器用上下文信息预测输出：last-value（最近一次值）、stride（等差值，适合循环/指针遍历）、context-based（按 PC 与历史表索引）。预测值作为源供后续指令投机执行；当真实结果算出后与预测比对，错误则标记依赖链上指令为误推测并回滚。为避免低准确率拖累，通常加置信度门控：仅当预测器「足够确信」才采纳，否则走普通等待路径。间接跳转目标预测本质上也是「值预测」的一种（预测 PC 而非数据）。

三类预测器的适用边界各不相同：last-value 在「同一指令连续多次产生相同值」时最有效（如循环里不变的边界或重复地址）；stride 在「值按固定步长变化」时最有效（数组遍历、计数递增），但遇到分支导致步长变化就失效；context-based 用指令历史（如最近若干次结果）做索引，能捕捉更复杂模式，代价是表项更多、训练更慢，且首次遇到新模式必然失败。

## 三、形式化与数学基础

设预测准确率 $p$，单次正确收益 $g$（隐藏的依赖延迟），错误恢复代价 $c$（回滚+重取指）。期望收益：

$$E = p \cdot g - (1-p) \cdot c$$

仅当 $p > \frac{c}{g + c}$ 时净收益为正，故需高准确率或置信度门控。置信度 $conf$ 用于门控：仅当 $conf \ge \theta$ 才采纳预测，等效于只在高 $p$ 子集上投机。设采纳率 $q$（conf≥θ 的比例），实际收益为 $q\cdot(p_{sel}\cdot g - (1-p_{sel})\cdot c)$。

把阈值代入数值可直观感受门槛之高：若 $g = 5$ 周期、$c = 40$ 周期（依赖链较长时并不夸张），则要求 $p > 40/45 \approx 89\%$ 才有正收益；若 $c$ 因需冲刷整个投机窗口而升至 100 周期，阈值高达 $95\%$。这正是置信度门控的价值：把「全量猜测」变为「高置信子集猜测」，虽然损失了部分可猜时机（$q < 1$），但显著抬高了 $p_{sel}$，使乘积为正。极端情况下，若门控过严导致 $q \to 0$，收益也趋零，因此 $\theta$ 的选取本身是一个优化问题。

## 四、代码实现

```c
#define N 1024
#define MAX 7                          // 置信度饱和上限
#define THRESH 4                       // 门控阈值

uint64_t last_val[N];
int conf[N];                           // 置信度计数（0..MAX）

uint64_t predict_value(int id) {
    if (conf[id] < THRESH) return SENTINEL;   // 低置信不预测，走常规等待
    return last_val[id];
}

void verify(int id, uint64_t real) {
    if (real == last_val[id]) {
        conf[id] = (conf[id] < MAX) ? conf[id] + 1 : MAX;  // 命中升置信
    } else {
        rollback_chain(id);                    // 错误：回滚该指令及其全部消费者
        conf[id] = 0;                          // 置信清零，进入冷却期
    }
    last_val[id] = real;                       // 无论对错都更新最近值
}

// stride 预测器：记录上次值与步长，适合循环与指针遍历
typedef struct { uint64_t last; int64_t stride; int conf; } StrideEnt;
StrideEnt st[N];

uint64_t predict_stride(int id) {
    if (st[id].conf < THRESH) return SENTINEL;
    return (uint64_t)((int64_t)st[id].last + st[id].stride);
}

// 间接跳转目标预测：把 PC 也当作「值」预测，机制完全相同
uint64_t predict_target(int call_site) { return last_target[call_site]; }
```

`rollback_chain` 是整套机制的性能与正确性交汇点：它必须能精确识别「因该值而投机执行的全部指令」，通常借助 ROB 中的依赖标记位实现；若回滚范围过小会留下错误状态，过大则白费了本可保留的投机成果，二者都会削弱收益。

## 五、与其他技术对比

| 技术 | 解除的依赖 | 风险 | 恢复粒度 | 适用 |
| --- | --- | --- | --- | --- |
| 值预测 | RAW 数据依赖 | 错误恢复代价高 | 整条依赖链 | 指针链/循环 |
| 分支预测 | 控制依赖 | 误预测 flush | 整条路径 | 普遍 |
| 内存消歧 | load/store 冲突 | 冲突回滚 | 相关 load 链 | 别名稀疏 |
| 地址预测（load 地址） | 地址计算依赖 | 地址错致缓存/转发错 | 相关访存链 | 指针密集 |
| 寄存器重命名 | WAW/WAR 伪依赖 | 无（确定性） | 不需要 | 普遍 |

值预测可打破 RAW 依赖，但预测错误恢复代价高，需高准确率才划算；常用于特定模式（stride、间接跳转目标预测）。与分支预测不同，值预测错的恢复粒度是「整条依赖链」，代价往往更大。与寄存器重命名相比，后者是确定性优化、无需恢复，二者性质完全不同——不应把值预测与重命名混为一谈。

## 六、常见误区

1. 误以为值预测总有益：低准确率时恢复代价超过收益，须置信度门控。
2. 误以为可预测任意值：随机/不可预测的值预测准确率近 50%，徒增回滚。
3. 忽略恢复范围：错误预测需回滚其后整条依赖链，不止单条指令。
4. 把值预测当确定性优化：它是投机，必须配恢复路径，否则结果错误。
5. 混淆值与地址预测：预测数据值（值预测）与预测 load 地址（地址预测）是不同表、不同恢复条件。
6. 认为置信度只需命中即升：若更新策略过于激进，一次侥幸命中就会长期提升置信度，实际准确率被高估。
7. 忽略预测表索引冲突：不同指令映射到同一条目会互相污染，降低准确率，需合理哈希与容量规划。
8. 认为值预测可替代寄存器重命名或内存消歧：三者解除的是不同依赖，不能互相替代。

## 七、与开源书·权威来源对应

- Hennessy & Patterson《Computer Architecture》讨论值预测、stride/last-value 预测器与置信度门控对 IPC 的影响，并给出「仅在收益为正才启用」的分析。
- Lipasti & Shen 等早期工作提出值预测与置信度门控，证明在指针密集负载下可显著提升 ILP。
- Adve & Gharachorloo 1996 关于内存一致性与顺序的论述，可用于理解值预测与内存消歧在依赖建模上的分工。

## 八、面试题

1. 问：值预测为何要置信度？
   答：避免错误恢复代价压垮收益；仅在高准确率子集（conf ≥ θ）上采纳，等价于只对净收益为正的指令投机。
2. 问：常见于哪些模式？
   答：指针链遍历、计数/步长循环、规整数组偏移、间接跳转目标等强相关模式。
3. 问：与分支预测的恢复有何不同？
   答：分支预测错触发流水线 flush，值预测错需回滚其 RAW 依赖链，二者恢复粒度与代价不同，值预测往往更贵。
4. 问：为什么间接跳转目标预测也归类值预测？
   答：它预测的是「下一条指令地址」这个「值」，机制相同（last-target/上下文表 + 置信度 + 错误回滚）。
5. 问：准确率门槛如何计算？
   答：由 $p > c/(g+c)$ 给出；恢复代价越大，门槛越高，因此缩短依赖链比提升准确率更有效。
6. 问：为什么值预测在通用 CPU 中不普及？
   答：收益窗口窄（仅个别模式有效）、面积与功耗开销大、恢复代价高，综合性价比低于分支预测与预取。

## 九、演进与趋势

与神经网络预测器、负载特征结合提升准确率；但实用性受限（硬件面积与功耗、训练开销）。研究聚焦「只在收益确定场景启用」的细粒度门控，而非通用值预测。近年还探索用值预测加速内存依赖链（预测 load 结果以提前解 RAW）。

另一条相关路线是「软件侧值推测」：由编译器在语义允许时插入乐观假设并生成守卫代码，运行时验证失败则回退到保守路径。这本质上是把值预测从硬件搬到编译期，代价是代码膨胀，但在特定领域（如数值计算、序列化）效果显著。具体能力以各系统官方最新文档为准。

## 十、小结

值预测以高准确率打破数据依赖，但必须将错误恢复成本计入收益，是投机执行的进阶技术。它的成败不在「能不能猜」，而在「猜得够准才值」——置信度门控把这一经济学判断固化进硬件，使投机只在确定性正收益处发生。值预测与分支预测、内存消歧一起，构成了现代 CPU「三层投机」的完整图景。判据只有一条：$p > c/(g+c)$；围绕这条不等式，可以解释值预测的一切工程取舍——为什么需要置信度、为什么只对特定模式有效、为什么恢复机制的设计比预测器本身更关键。
