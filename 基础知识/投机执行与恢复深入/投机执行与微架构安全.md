# 投机执行与微架构安全

> 对应 Kocher 2019（Spectre）、Böhme 2018（Meltdown）与 Saltzer & Schroeder 1975。

## 一、背景与挑战
传统安全模型假设仅「架构可见」状态影响程序。投机执行证明微架构状态（缓存、TLB、分支历史）也能泄露信息，打破隔离假设。

## 二、核心原理
攻击分两步：诱导投机访问秘密（利用预测器/乱序），再借微架构侧信道（计时、端口争用）观测痕迹。防御须阻断「秘密→微架构状态→可测信道」链。

## 三、形式化与数学基础
信息泄漏量受信道容量约束：

    I(secret; observation) > 0 当且仅当存在可区分的微架构状态差异。

## 四、代码实现
```c
// 防御: 用屏障阻止跨域投机
void safe_access(size_t i, size_t len) {
    if (i >= len) return;        // 真实检查
    asm volatile("lfence" ::: "memory"); // 阻止后续投机越过
    use(data[i]);
}
```

## 五、与其他技术对比
纯架构层保护（权限位）不足；需微架构层缓解（lfence、retpoline、eIBRS、缓存分区）。

## 六、常见误区
误以为只禁用缓存可解；性能崩溃且侧信道不止缓存。误以为用户态无法影响内核投机。

## 七、与开源书/权威来源对应
Saltzer & Schroeder 1975 提出最小权限与完全中介；Spectre/Meltdown 揭示微架构侧信道。

## 九、演进与趋势
硬件提供推测限制（如 Arm FEAT_SPECRES、x86 IBPB/STIBP），软件结合数据清洗。

## 十、小结
投机执行的安全问题源于微架构残留可被侧信道观测，防御需架构与微架构协同。
