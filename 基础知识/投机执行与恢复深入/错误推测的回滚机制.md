# 错误推测的回滚机制

> 对应 Hennessy & Patterson《Computer Architecture》。

## 一、背景与挑战
投机执行一旦发生误预测或非法访问，必须保证架构状态不被污染，并尽快回到正确路径，回滚机制决定恢复延迟。

## 二、核心原理
恢复依赖 ROB 截断与映射快照（检查点）。误预测点之后的 ROB 项丢弃，RAT 与物理寄存器空闲表恢复到分支点，前端从正确 PC 重取。

## 三、形式化与数学基础
恢复代价：

    recovery_latency = flush_cycles + rename_reset + refill_frontend

检查点数量 n 影响可并行恢复的分支数。

## 四、代码实现
```c
void rollback(int branch_rob) {
    int chk = checkpoint[branch_rob];
    restore_rat(chk);
    restore_freelist(chk);
    rob_truncate_after(branch_rob);
    fetch_pc = correct_target;
}
```

## 五、与其他技术对比
无检查点需从 ROB 顺序重建映射，慢；检查点（影子 RAT）以少量存储换快速恢复。

## 六、常见误区
误以为回滚仅清空流水线；架构寄存器映射也须恢复。误以为微架构状态全清。

## 七、与开源书/权威来源对应
Hennessy & Patterson 讨论检查点与恢复延迟。

## 九、演进与趋势
多级检查点、按预测置信度提前部分恢复降低代价。

## 十、小结
错误推测回滚通过 ROB 截断与映射检查点快速恢复架构一致性，是投机执行的兜底保障。
