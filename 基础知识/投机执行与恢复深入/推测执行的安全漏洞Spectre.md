# 推测执行的安全漏洞Spectre

> 对应 Kocher 2019（Spectre）与 Böhme 2018（Meltdown）。

## 一、背景与挑战
投机执行会运行本不应执行的指令并留下微架构痕迹（缓存状态）。攻击者可训练分支预测，诱导受害者投机访问秘密，再用侧信道（cache timing）读出。

## 二、核心原理
Spectre 变种 1（边界检查绕过）：构造越界读 x = arr1[arr2[i]]，训练使分支预测「不会越界」，投机执行越界读并把 arr1 对应缓存行带入缓存，随后用计时测信道恢复秘密字节。

## 三、形式化与数学基础
侧信道观察：

    time_access(addr) 小 -> 该缓存行曾被投机加载
    通过扫描 arr1 某偏移的访问时间反推 arr2[i] 的值。

## 四、代码实现
```c
// 示意(不可用于攻击): 越界读训练分支
if (i < len) {            // 被误导为 taken
    unsigned char v = kernel_mem[i];
    dummy[v * 256] = 1;   // 把 v 映射到缓存行
}
// 攻击者测 dummy[k*256] 命中情况恢复 v
```

## 五、与其他技术对比
Meltdown 利用权限检查与异常的顺序漏洞；Spectre 利用分支预测，更难通过微码补丁根治，需软件屏障（lfence、retpoline）。

## 六、常见误区
误以为仅内核受影响；Spectre 跨进程/跨沙箱均可能。误以为禁用缓存即可，性能不可接受。

## 七、与开源书/权威来源对应
Kocher 2019 论文给出 Spectre 原理与缓解；Böhme 2018 描述 Meltdown。

## 九、演进与趋势
新型缓解：eIBRS、推测限制指令、硬件分区缓存；安全与性能权衡持续。

## 十、小结
Spectre 暴露投机执行的微架构副作用可被侧信道利用，是安全与体系结构交叉的重要课题。
