# 分支预测与投机执行

> 对应 Hennessy & Patterson《Computer Architecture》与 Kocher 2019（Spectre）。

## 一、背景与挑战
控制相关使流水线在分支结果未定时停顿。分支预测器猜测目标并沿该路径投机执行，结果正确则省去等待，错误则回滚。

## 二、核心原理
预测器（两位饱和计数器、全局历史 GShare、TAGE 等）依历史猜测方向；预测后沿目标取指执行。提交时核对实际方向，错误则 flush 投机部分并恢复。

## 三、形式化与数学基础
两位计数器状态机：

    strongly/weakly taken/not_taken, 在误预测时递减/递增,
    仅越过中点才改变预测方向。

预测准确率提升直接提升有效 IPC。

## 四、代码实现
```c
int bimodal[4096]; // 两位饱和计数器
int predict(uint32_t pc) {
    int i = (pc >> 2) & 0xFFF;
    return (bimodal[i] >> 1) & 1; // 最高位为方向
}
void update(int pc, int taken) {
    int i = (pc >> 2) & 0xFFF;
    bimodal[i] += taken ? 1 : -1;
    bimodal[i] &= 3;
}
```

## 五、与其他技术对比
静态预测（如 backward-taken）简单但准确低；动态预测随历史提升，但资源与功耗更高。

## 六、常见误区
误以为预测错误仅损失几条指令；现代深流水误预测代价可达数十周期。误以为投机无副作用。

## 七、与开源书/权威来源对应
Hennessy & Patterson 讲预测器；Spectre/Kocher 2019 揭示投机副作用。

## 九、演进与趋势
TAGE、感知机预测器持续提升；同时引入安全约束防止投机侧信道。

## 十、小结
分支预测驱动投机执行以提升 IPC，但误预测需 ROB 恢复，且其微架构残留构成安全挑战。
