# 贪心与动态规划：无后效性辨析

> 对应 Bellman《Dynamic Programming》1957/1962 最优化原理，CLRS 第 15 章（DP）与第 16 章（贪心）的系统对比，及 Kleinberg & Tardos《Algorithm Design》第 4、6 章。

## 一、背景与挑战

很多优化问题既能用贪心也能用 DP 写：背包、区间、调度、最短路、序列对齐。二者的代码都短，但**正确性边界完全不同**——贪心一旦策略错就是结构性错误，DP 只要状态定义对就必对（只是可能慢）。工程事故常常源于"看着像贪心"：0-1 背包按价值密度贪心、带权区间按结束时间贪心、打家劫舍里"隔一个抢一个"当万能钥匙，都在边界数据上翻车。

判断到底该用哪个，核心是**无后效性**与**最优子结构是否对"单步决策"成立**：
- 贪心：一步定死后，剩余问题与原问题同构，且**局部最优选择必然属于某个全局最优解**；
- DP：一步决策会影响多个后续子问题，必须**保留多种"前缀/状态"下的最优**，不能提前丢弃。

无后效性（马尔可夫性）指：当前状态一旦确定，之后的决策与如何到达当前状态无关。DP 的状态设计就是为了把"历史影响"压进状态；贪心则要求历史影响足够简单——最优剩余决策与历史无关且唯一确定。两者都不满足时，要退回搜索/分治/回溯。

面试中这是"设计题"：面试官给一个新模型，看你能否判断贪心/DP/搜索，并说出反例或证明思路。工程上，资源调度、推荐排序、压缩、路径规划都要在"快但需证明"与"慢但稳"之间取舍。

## 二、核心原理

**贪心的条件**：
1. **贪心选择性质**：存在最优解包含当前贪心选择（或交换论证可把最优解换成含该选择的）；
2. **最优子结构**：做出该选择后，剩余问题与原问题同构；
3. **无后效性的强化**：最优剩余策略不依赖选择的"方式/顺序"细节，只依赖剩余资源/位置。

**DP 的条件**：
1. **最优子结构**：最优解包含子问题最优解；
2. **重叠子问题**：同一状态被多次计算，用表/记忆化；
3. **无后效性**（状态定义后）：$f(s)$ 只与状态 $s$ 有关，与路径无关。若与路径有关，状态要把路径压进去。

**典型分野**：
- **分数背包**可贪心（按价值密度），因为物品可分割，局部密度最优可拼成全局；
- **0-1 背包**不可贪心，必须 DP（状态是容量 + 物品索引），因"选了重的低价值"可能堵死高价值组合；
- **活动选择（无权）**贪心（结束时间）；
- **加权区间** DP；
- **Huffman** 贪心（合并最小）；
- **矩阵链乘、编辑距离、LCS** 明确 DP；
- **Dijkstra** 在非负权下贪心，负权退化为 DP/迭代松弛（Bellman-Ford）。

**判断技巧（实用清单）**：
1. 能否给出交换论证（把最优解换成贪心解且不劣）？能 → 贪心候选；
2. 能否构造小反例推翻贪心？能 → DP/搜索；
3. 决策是否"可分割/可累加"？可分割常贪心，离散组合常 DP；
4. 状态空间是否多项式？指数 → 剪枝搜索/近似；
5. 目标是否 max-min、带耦合约束？耦合强则 DP 或 MIP。

**无后效性的形式**：设决策序列 $a_1,\dots,a_n$，状态转移 $s_{i+1} = T(s_i, a_i)$，代价 $c(s_i,a_i)$。若总代价可写成 $\sum c_i$ 且 $s$ 足够刻画"资源/位置"，则 DP 可行；若最优 $a_i$ 由 $s_i$ 唯一决定且与未来无关，贪心可行。

## 三、形式化与数学基础

**最优子结构**：$OPT(s) = \min_{a \in A(s)} \{ c(s,a) + OPT(T(s,a)) \}$。DP 直接求解该递推。

**贪心退化条件**：若存在选择函数 $g(s)$ 使
$$OPT(s) = c(s, g(s)) + OPT(T(s, g(s)))$$
对所有 $s$ 成立（即最优首步固定），则可用贪心：一直选 $g$。这等价于"贪心选择性质 + 子问题最优"。

**无后效性形式**：状态 $s$ 是充分统计量——
$$P(\text{未来最优} \mid s, \text{历史}) = P(\text{未来最优} \mid s)$$
若不成立（历史影响未来），必须扩充状态（如记录"是否用过某物品""上一个选择"），否则 DP 错；贪心更不可能。

**0-1 背包反例**：容量 50，物品 $(w,v) = (10,60), (20,100), (30,120)$。价值密度：6, 5, 4。贪心取 10+20=30 重量，价值 160，剩 20 不能装 30，总 160；最优取 20+30=50，价值 220。故贪心非最优。

**分数背包**：同上贪心取 10+20+ (20/30)*30 → 60+100+80=240，最优。

**交换论证在 DP 中的作用**：DP 不需要交换论证，靠枚举保留所有可能；贪心靠交换论证"压缩"枚举到一条路径。

**复杂度对比**：贪心常 $O(n\log n)$（排序 + 扫描）；DP 常 $O(n^2)$、$O(n^3)$ 或 $O(nC)$（背包）；搜索 $O(b^d)$。空间：贪心 $O(1)$~$O(n)$，DP 表常更大（可滚动优化）。

## 四、代码实现

```python
def knapsack_01(w, v, cap):
    """0-1 背包: 必须 DP。返回最大价值。"""
    n = len(w)
    dp = [0] * (cap + 1)
    for i in range(n):
        for c in range(cap, w[i] - 1, -1):
            if dp[c - w[i]] + v[i] > dp[c]:
                dp[c] = dp[c - w[i]] + v[i]
    return dp[cap]


def knapsack_01_with_choice(w, v, cap):
    """0-1 背包还原选择（布尔表）"""
    n = len(w)
    dp = [[0] * (cap + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        for c in range(cap + 1):
            dp[i][c] = dp[i - 1][c]
            if c >= w[i - 1]:
                dp[i][c] = max(dp[i][c], dp[i - 1][c - w[i - 1]] + v[i - 1])
    # 回溯
    chosen = []
    c = cap
    for i in range(n, 0, -1):
        if dp[i][c] != dp[i - 1][c]:
            chosen.append(i - 1)
            c -= w[i - 1]
    chosen.reverse()
    return dp[n][cap], chosen


def fractional_knapsack(items, cap):
    """分数背包: 可贪心。items: list of (w, v)"""
    items = sorted(items, key=lambda x: x[1] / x[0], reverse=True)
    gain = 0.0
    for w, v in items:
        if cap >= w:
            gain += v
            cap -= w
        else:
            gain += v * cap / w
            break
    return gain


def weighted_interval_dp(intervals, weights):
    """加权区间: DP（无权时才贪心）"""
    import bisect
    items = sorted(zip(intervals, weights), key=lambda x: x[0][1])
    n = len(items)
    ends = [it[0][1] for it in items]
    dp = [0] * (n + 1)
    for i in range(1, n + 1):
        (s, f), w = items[i - 1]
        j = bisect.bisect_right(ends, s, 0, i - 1)
        dp[i] = max(dp[i - 1], dp[j] + w)
    return dp[n]


def max_activities_greedy(intervals):
    """无权区间: 贪心正确"""
    items = sorted(intervals, key=lambda x: x[1])
    cnt, last = 0, float("-inf")
    for s, f in items:
        if s >= last:
            cnt += 1
            last = f
    return cnt


if __name__ == "__main__":
    w = [10, 20, 30]
    v = [60, 100, 120]
    assert knapsack_01(w, v, 50) == 220  # DP 最优
    # 贪心(价值密度)会得 160，确认 DP 更优
    assert fractional_knapsack(list(zip(w, v)), 50) == 240.0

    opt, chosen = knapsack_01_with_choice(w, v, 50)
    assert opt == 220 and set(chosen) == {1, 2}

    iv = [(1, 3), (2, 5), (4, 6)]
    assert max_activities_greedy(iv) == 2
    assert weighted_interval_dp(iv, [3, 2, 4]) == 7
    print("all tests passed")
```

## 五、与其他技术对比

| 维度 | 贪心 | 动态规划 | 记忆化搜索 | 回溯/暴力 |
|---|---|---|---|---|
| 决策 | 局部最优，一条路径 | 枚举子问题 | 同 DP | 枚举全部 |
| 正确性 | 需证明 | 状态对则对 | 同 DP | 完备 |
| 速度 | 快 $O(n\log n)$ | 中 $O(n^2)$ 等 | 中 | 慢指数 |
| 适用 | 调度、编码、MST | 背包、序列、区间加权 | 状态稀疏 | 小规模/约束复杂 |
| 失败模式 | 策略错结果差 | 状态错结果差 | 同左 | 超时 |

取舍：**先试交换论证，成则贪心；不成看状态能否多项式表达，能则 DP；再不行搜索+剪枝或近似**。工程上常"贪心初解 + 局部搜索/DP 精修"。

## 六、常见误区

1. **0-1 背包用价值密度贪心**：反例可得次优。必须 DP。分数背包才能贪心。
2. **把无权区间的贪心套到带权**：结束时间贪心只对计数正确；加权要 DP。
3. **状态没压入"历史影响"**：例如"是否已用过优惠券""上一个字符"，漏了就违反无后效性，DP 错。
4. **以为"都能 DP"所以不证贪心**：DP 可能超时（$n=10^5$ 时 $O(n^2)$ 不可接受）；能贪心时必须证，否则性能事故。
5. **贪心失败就以为只能 DP**：有时可"贪心 + 交换/局部搜索"或近似；有时状态空间太大只能启发式。

## 八、面试题

**1. 为什么 0-1 背包不能用贪心？**  
价值密度贪心会优先取"单位价值高但占用多"的物品，可能挤掉组合更优的物品。反例：容量 50，$(10,60),(20,100),(30,120)$，贪心 160，DP 最优 220。只有分数背包可贪心。

**2. 哪些迹象提示该用 DP 而非贪心？**  
存在"选择会互相牵制"的资源约束、需要比较多种组合、小规模反例能推翻贪心、状态可用"前缀 + 资源/位置"多项式描述。反之，交换论证能走通则贪心。

**3. 无后效性在两者的含义有何不同？**  
DP：状态设计要保证"未来只依赖当前状态"；若历史有影响，把影响压进状态。贪心：更强，要求最优下一步与历史无关且可贪心选择，局部最优即可全局。

**4. 贪心快但想稳怎么办？**  
可以先证贪心；证不出就 DP 或"贪心初解 + 局部搜索/线性规划松弛 rounding"。混合策略在调度、推荐里很常见。

## 九、演进与趋势

理论侧，**拟阵/拟阵交**刻画贪心正确类，**次模函数最大化**给出 $1-1/e$ 贪心保证；**在线算法**用竞争比分析"不可撤销的贪心"；**近似 DP（FPTAS）**把指数 DP 降到多项式近似。工程侧，ML 调度用学习权重 + 贪心/DP 混合，推荐系统用贪心召回 + DP 重排，压缩用 Huffman（贪心）+ 上下文建模（DP/算术），硬件布线用 MST/Steiner 贪心 + 精修。"贪心提供可解释的快解，DP 提供精确边界"仍是主流设计模式。

## 十、小结

贪心要求"局部最优可拼全局"，靠交换论证与最优子结构；DP 要求状态充分且无后效，靠枚举保留多种可能。分数背包可贪心、0-1 背包必须 DP、无权区间可贪心、加权区间必须 DP——能否贪心的关键是**局部最优是否必然属于某个全局最优**。不确定时优先 DP，能证则用贪心换效率。
