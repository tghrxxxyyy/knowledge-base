# 贪心算法的正确性证明与交换论证

> 对应 CLRS《Introduction to Algorithms》第 16 章（Greedy Algorithms）与 Kleinberg & Tardos《Algorithm Design》第 4 章（Greedy Algorithms）；拟阵理论见 Edmonds 1971 与 Papadimitriou & Steiglitz《Combinatorial Optimization》。

## 一、背景与挑战

贪心算法每一步都做"局部最优"选择，希望拼出全局最优。它跑得快、代码短，是活动选择、Huffman、Dijkstra、MST 的共同骨架。但**局部最优不等于全局最优**：0-1 背包按价值密度贪心会次优，最短路在负权下贪心会错，区间按开始时间贪心会错。工程里最大的坑是"看起来显然对"——随手写贪心、只测几组样例、上线后在边界数据翻车。

为什么必须证明？因为贪心一旦出错，不是差几个百分点，而是**结构性错误**：可能系统性地选错，损失可以任意大。相比之下 DP 若状态对了只是慢，结果总对。所以流程应该是：先猜贪心策略 → 严格证明（交换论证或贪心选择性质）→ 若证不出来退回 DP 或近似算法。面试里能默写模板只到及格线，能说清"为什么对、哪里会错"才是高分。

证明工具主要有三条路：**交换论证（Exchange Argument）**把任意最优解逐步替换成贪心解且不恶化目标；**贪心选择性质 + 最优子结构**先证存在含贪心首步的最优解再归纳；**拟阵（Matroid）**给出"贪心正确"的代数刻画。掌握前两条就能覆盖绝大多数面试与工程场景，第三条用于判断"这个策略是否必然对"。

## 二、核心原理

**交换论证的机制**：设贪心解为 $G = (g_1, g_2, \dots)$，任取一个最优解 $OPT$。我们构造一系列解 $OPT = OPT_0 \to OPT_1 \to \cdots \to OPT_k = G$，每次用贪心的选择去"替换" $OPT_i$ 中某个不同的选择，且目标值不恶化。因 $OPT$ 最优，所有替换实际保持最优（若能更优则与 $OPT$ 最优矛盾，故 $cost$ 不变）。最后 $OPT_k$ 与 $G$ 相同，故 $G$ 也最优。

**替换的两个关键点**：
1. **可行性**：把贪心元素换进去后，解仍然合法（不违反约束）；
2. **不劣化**：目标函数不变或变好（最小化问题里 $cost$ 不增）。

**贪心选择性质**：存在一个最优解包含贪心算法的**第一步选择**。这常与交换论证连用：先证首步可进最优解，再对剩余子问题归纳（最优子结构）。

**最优子结构**：做出贪心选择后，剩余问题仍是同构的子问题，且子问题的最优解拼上首步得到原问题最优解。

**拟阵视角（了解即可）**：若可行解集合是独立系统且满足交换公理（$|A|<|B|$ 则 $\exists x\in B\setminus A$ 使 $A\cup\{x\}$ 独立），则按权排序的贪心求最大权独立集是正确的。活动选择、拟阵交、某些调度问题落在拟阵里；0-1 背包不落在（约束含容量，不是拟阵），故贪心失败。

**常见的交换场景**：
- **邻项交换**（activity selection、Huffman）：把贪心元素与最优解中第一个"不同位置"交换；
- **决策范围收缩**（Dijkstra、MST）：证明"当前选的那个必然在某个最优解里"，再缩到子问题；
- **期限/序列交换**（区间、任务排序）：若最优解违反贪心顺序，交换相邻逆序对，目标不劣。

**边界**：目标函数可加、约束单调时交换好证；若目标是 max-min、有耦合约束（如全局容量），交换可能不可行，要退 DP。多目标/带随机性时贪心证明更难。

## 三、形式化与数学基础

**交换论证形式化**：设最小化问题，可行解集 $\mathcal{F}$，代价 $c$。贪心产生 $G$。若对任意 $OPT\in\arg\min_{\mathcal{F}} c$，存在映射 $\phi_1,\dots,\phi_k$ 使得
$$OPT_k = \phi_k(\cdots\phi_1(OPT)), \quad OPT_k = G, \quad c(\phi_i(OPT_{i-1})) \le c(OPT_{i-1})$$
且 $\phi_i$ 保持可行性，则
$$c(G) = c(OPT_k) \le c(OPT) \le c(G)$$
最后一个不等号因 $G$ 可行。故 $c(G)=c(OPT)$，贪心最优。

**活动选择的贪心选择性质**（CLRS 16.1）：设 $a_1$ 是结束时间最早的活动。设 $A$ 为最优解，$a_j = \min A$（结束最早）。若 $a_j \neq a_1$，令 $A' = (A \setminus \{a_j\}) \cup \{a_1\}$。因 $f(a_1) \le f(a_j)$，$a_1$ 与 $A$ 中其余活动仍相容，$|A'|=|A|$，故 $A'$ 也是最优且含 $a_1$。归纳得贪心最优。子问题 $S_k = \{a_i : s_i \ge f(a_1)\}$ 结构不变。

**Huffman 贪心的交换论证**（CLRS 16.3）：设最优前缀码对应二叉树 $T$，频率最小的两个字符是 $x, y$。可证存在一棵最优树使 $x,y$ 为最深兄弟：取 $T$ 中深度最深的兄弟 $a,b$ 与 $x,y$ 交换，加权路径长不增（因 $f(x),f(y)$ 最小，交换后 $\sum f_i d_i$ 不增）。合并 $x,y$ 为新节点 $z$（$f(z)=f(x)+f(y)$），递归。

**Dijkstra 的贪心正确性**：非负权下，当前 $dist$ 最小且未确定的点 $u$ 满足 $dist[u]=\delta(s,u)$。反证：若 $\delta < dist[u]$，最短路上必有未确定点 $x$ 使 $dist[x] \le \delta < dist[u]$，与 $u$ 是最小未确定点矛盾。

**复杂度常见结论**：排序 $O(n\log n)$ + 线性扫描 $O(n)$ = $O(n\log n)$；若用堆维护候选则 $O((V+E)\log V)$。证明复杂度时要算清比较次数与数据结构。

## 四、代码实现

```python
import heapq


def max_activities(intervals):
    """活动选择: 结束时间贪心。返回最大相容活动数与所选下标。
    证明: 先证结束最早者必可进最优解，再归纳子问题。"""
    items = sorted(enumerate(intervals), key=lambda x: (x[1][1], x[1][0]))
    chosen = []
    last_end = float("-inf")
    for idx, (s, f) in items:
        if s >= last_end:
            chosen.append(idx)
            last_end = f
    return len(chosen), chosen


def huffman_codes(freqs):
    """Huffman 编码: 返回 codes dict 与加权路径长 WPL。
    贪心: 每次合并频率最小的两个节点。"""
    # freqs: dict char -> freq
    heap = [(f, i, ch, None, None) for i, (ch, f) in enumerate(sorted(freqs.items()))]
    heapq.heapify(heap)
    uid = len(heap)
    while len(heap) > 1:
        f1, _, ch1, l1, r1 = heapq.heappop(heap)
        f2, _, ch2, l2, r2 = heapq.heappop(heap)
        heapq.heappush(heap, (f1 + f2, uid, None, (f1, ch1, l1, r1), (f2, ch2, l2, r2)))
        uid += 1

    root = heap[0]
    codes = {}

    def walk(node, prefix):
        f, _, ch, left, right = node
        if left is None and right is None:
            codes[ch] = prefix or "0"
            return
        walk(left, prefix + "0")
        walk(right, prefix + "1")

    walk(root, "")
    wpl = sum(freqs[c] * len(code) for c, code in codes.items())
    return codes, wpl


def dijkstra(n, edges, src):
    """非负权单源最短路: 贪心取当前最近点确定。"""
    adj = [[] for _ in range(n)]
    for u, v, w in edges:
        adj[u].append((v, w))
        adj[v].append((u, w))  # 无向则加这行

    dist = [float("inf")] * n
    dist[src] = 0
    pq = [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue
        for v, w in adj[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                heapq.heappush(pq, (dist[v], v))
    return dist


def exchange_argument_demo(intervals):
    """演示交换论证: 结束最早者必在最优解中。"""
    # 构造一个最优解（用 DP 求最大不重叠），再检查是否可换成含最早结束者
    # 这里用贪心结果作为对照，展示二者大小相等
    g_cnt, _ = max_activities(intervals)
    # 按下标 DP 求最优（区间数不大）
    items = sorted(intervals, key=lambda x: x[1])
    n = len(items)
    dp = [0] * (n + 1)
    for i in range(1, n + 1):
        # 二分找最后一个结束 <= start[i-1] 的
        s, f = items[i - 1]
        lo, hi = 0, i - 1
        while lo < hi:
            mid = (lo + hi + 1) // 2
            if items[mid - 1][1] <= s:
                lo = mid
            else:
                hi = mid - 1
        dp[i] = max(dp[i - 1], dp[lo] + 1)
    return g_cnt, dp[n]


if __name__ == "__main__":
    intervals = [(1, 4), (3, 5), (0, 6), (5, 7), (3, 9), (5, 9), (6, 10), (8, 11), (8, 12), (2, 14)]
    cnt, _ = max_activities(intervals)
    g, opt = exchange_argument_demo(intervals)
    assert g == opt == cnt

    codes, wpl = huffman_codes({"a": 5, "b": 9, "c": 12, "d": 13, "e": 16, "f": 45})
    assert wpl == 224  # 经典例子
    assert all(not codes[c].startswith(codes[d]) for c in codes for d in codes if c != d)

    dist = dijkstra(3, [(0, 1, 1), (1, 2, 2), (0, 2, 5)], 0)
    assert dist == [0, 1, 3]
    print("all tests passed")
```

## 五、与其他技术对比

| 维度 | 贪心 | 动态规划 | 分治 | 回溯/搜索 |
|---|---|---|---|---|
| 决策方式 | 局部最优，不回头 | 枚举子问题最优 | 分成独立子问题 | 枚举+剪枝 |
| 正确性 | 需证明（交换/拟阵） | 状态对则正确 | 结构对则正确 | 完备 |
| 典型复杂度 | $O(n\log n)$ | $O(n^2)$~$O(n^3)$ | $O(n\log n)$ | 指数 |
| 内存 | 低 | 常较高 | 低~中 | 栈/路径 |
| 适用 | 调度、编码、MST、最短路 | 背包、编辑距离、区间加权 | 排序、FFT | 组合枚举 |

取舍：**能证贪心选择性质就用贪心**（快且省内存）；**证不出但有最优子结构就 DP**；**子问题独立分治**；**要最优且约束复杂用搜索+剪枝或 ILP**。贪心还常作近似算法（集合覆盖 $\ln n$、最大割 $1/2$）与在线算法（势函数分析）。

## 六、常见误区

1. **凭直觉不证明**：0-1 背包按价值密度贪心、区间按开始时间贪心，都是"看起来对"的经典反例。后果：答案系统性偏差，边界数据必挂。
2. **交换时不保可行性**：例如带全局容量的多约束问题，把贪心元素换进去可能超容量，交换论证失效。此时不能硬套。
3. **忽略最优子结构**：贪心选完后子问题若不是原问题同构（约束变了），不能归纳，需换状态（DP）。
4. **把贪心当搜索用**：只取一条路径，无法回溯。若问题需要比较多种组合（如背包），贪心会漏最优。
5. **相等元素处理不一致**：结束时间相同按开始/下标稳定排序，否则不同实现结果不同，测试不稳。

## 八、面试题

**1. 如何用交换论证证明活动选择的贪心正确性？**  
设 $a_1$ 结束最早，$A$ 为最优解，$a_j$ 为 $A$ 中结束最早者。若 $a_j\ne a_1$，把 $a_j$ 换成 $a_1$，因 $f(a_1)\le f(a_j)$，$a_1$ 与 $A$ 其余活动仍相容，$|A|$ 不变，故存在含 $a_1$ 的最优解。对子问题 $S_k=\{a:s\ge f(a_1)\}$ 归纳即得贪心最优。

**2. 什么情况下贪心一定失败，需要改用 DP？**  
当问题不满足贪心选择性质（局部最优不必然属于某个全局最优）时，如 0-1 背包、加权区间调度、带耦合约束的组合优化。特征：交换论证做不下去、或能构造反例。此时用 DP 或搜索。

**3. 拟阵是什么？和贪心什么关系？**  
拟阵是满足独立性与交换公理的集合系统。在拟阵上按权降序贪心可得最大权独立集。它给出"贪心正确"的代数刻画；活动选择可嵌入拟阵，0-1 背包不能。

**4. 如何在面试中展示证明能力？**  
先说策略（结束时间/频率合并/当前最近点），再说两条：① 存在含该选择的最优解（交换论证）；② 剩余子问题同构（归纳）。最后给复杂度。三句话结构比长篇更清晰。

## 九、演进与趋势

贪心在现代算法里有三条延展线：**近似算法**（贪心给出 $\ln n$、$1/2$ 等近似比，配合 LP 松弛与 rounding）；**在线算法与竞争比**（滑雪租赁、页替换用势函数分析）；**学习型/自适应贪心**（用 ML 预测权重再贪心，在调度、广告、推荐里落地）。工程上，调度器、压缩、网络路由、最小生成树子系统都是贪心骨架；带约束的资源分配常是"贪心 + 局部搜索/模拟退火"混合。理论侧，拟阵交、次模最大化（贪心 $1-1/e$）仍是活跃方向。

## 十、小结

贪心不是拍脑袋，而是要靠**交换论证**或**贪心选择性质 + 最优子结构**撑起来的严谨方法：能证明则 $O(n\log n)$ 一击即中，证不出就退回 DP。掌握"换掉不同选择、保可行性、不劣化目标"这套动作，就能在活动选择、Huffman、Dijkstra、MST 等经典问题上游刃有余。
