# 贪心算法的正确性证明与交换论证

> 对应 CLRS《Introduction to Algorithms》第 16 章与 Kleinberg & Tardos《Algorithm Design》第 4 章（贪心算法）。

## 一、背景与挑战
贪心算法在每一步都做出局部最优选择，希望得到全局最优。但"局部最优"不等于"全局最优"，因此必须通过严格证明来确认正确性。工程上常有人凭直觉使用贪心，结果在边界数据上出错。

## 二、核心原理
两种主流证明方法：
1. 交换论证（Exchange Argument）：把任意最优解逐步替换成贪心解，且不恶化目标值。
2. 贪心选择性质 + 最优子结构：先证存在一个含贪心首步的最优解，再递归。

## 三、形式化与数学基础
设最优解集合为 $OPT$，贪心解为 $G$。交换论证要求对每一步 $i$，存在映射 $\phi$ 使：
$$cost(\phi(OPT)) \le cost(OPT) \quad \text{且} \quad \phi(OPT) = G$$
即经过有限次保优交换后可化为贪心解。

## 四、代码实现
```python
# 交换论证模板：用堆不断取局部最优，并证明可替换
import heapq

def greedy_exchange(items):
    # items: list of (weight, value)
    heap = [(-v / w, w, v) for w, v in items]
    heapq.heapify(heap)
    chosen = []
    while heap:
        _, w, v = heapq.heappop(heap)
        chosen.append((w, v))  # 局部最优选择
    return chosen
```

## 五、与其他技术对比
动态规划枚举所有子问题，保证最优但开销大；贪心只走一条路径，快但需证明。若问题满足"贪心选择性质"，贪心可将 $O(2^n)$ 降到 $O(n \log n)$。

## 六、常见误区
- 认为"看起来最优"就正确，缺少交换论证。
- 把贪心当搜索用，没验证最优子结构。
- 忽略相等元素的稳定处理，导致不同实现结果不一致。

## 九、演进与趋势
现代研究把贪心嵌入近似算法（如集合覆盖的 $\ln n$ 近似）与在线算法，理论保证来自势函数分析。

## 十、小结
贪心不是"拍脑袋"，而是需要交换论证或贪心选择性质支撑的严谨方法；能证明就用，不能证明应退回到 DP。
