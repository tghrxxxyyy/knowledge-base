# 区间调度与活动选择问题

> 对应 CLRS《Introduction to Algorithms》第 16.1 节（Activity-Selection Problem）与 Kleinberg & Tardos《Algorithm Design》第 4 章；亦见 youngyangyang04/leetcode-master 贪心区间专题。

## 一、背景与挑战

区间调度是一族问题的抽象：会议室安排、CPU 任务排程、广告位售卖、航班登机口分配、频谱分配……最经典的形式是**活动选择**：给定 $n$ 个活动 $[s_i, f_i)$，每个活动占用一台机器，求**互不重叠**的活动最大数量（或最大价值）。更一般的变体有：最多不重叠区间（LeetCode 435）、用最少箭引爆气球（452）、合并区间（56）、无重叠区间最少删除（435 反面）、区间划分/会议室数量（253）。

为什么朴素做法不行？枚举所有子集检查是否相容是 $O(2^n \cdot n)$；按开始时间排序后贪心"能选就选"会丢最优（反例：$[1,10], [2,3], [3,4]$，先选 $[1,10]$ 只得 1 个，最优是 2 个）；按最长持续时间、最早开始、最少冲突等启发式都可能错。区间调度的核心洞察是**按结束时间排序**，这是交换论证能撑住的少数几个"漂亮贪心"之一。

在面试里，区间专题出现频率极高，且变体多：计数、合并、覆盖、划分、加权。考官盯的是：能否分清"最大不重叠数"与"最少删除数"、排序键选对没有、端点开闭（$s \ge f$ vs $s > f$）是否一致。工程上，资源预订系统与排班系统把区间模型扩展到多机（并行机调度）与带权（加权区间调度用 DP），这时贪心不再充分。

## 二、核心原理

**核心贪心**：按结束时间升序排序，维护 `last_end`（已选区间中最后一个的结束时间）。若当前区间 $s_i \ge last_end$ 则选它并更新 `last_end = f_i`；否则跳过。

**直觉**：结束越早，留给后续的时间越多。这不是"尽量早开始"，而是"尽量早释放机器"。

**交换论证**：设 $a_1$ 是结束最早的活动。任取最优解 $A$，若 $a_1 \notin A$，把 $A$ 中结束最早的 $a_j$ 换成 $a_1$。因 $f_1 \le f_j$，$a_1$ 与 $A\setminus\{a_j\}$ 中所有活动仍相容，故 $A' = (A \setminus \{a_j\}) \cup \{a_1\}$ 也是最优且含 $a_1$。对剩余子问题 $S_k = \{a_i : s_i \ge f_1\}$ 归纳，贪心最优。

**最优子结构**：选完 $a_1$ 后，剩余问题是"在与 $a_1$ 不冲突的区间里求最大相容集"，与原问题同构。

**常见变体的贪心策略**：
- **最多不重叠**：按结束时间升序，能选就选（上面的）。
- **最少删除使不重叠**：$n - \text{最多不重叠数}$。
- **引爆气球（箭数）**：按结束坐标升序，若下一气球起点 > 当前箭位置（当前结束），则需要新箭；实际是"最大重叠段"计数，贪心同构。
- **合并区间**：按起点排序，扫一遍合并 $s_{i} \le cur\_end$ 的区间。
- **区间覆盖（选最少区间覆盖线段）**：按起点排序，每次在覆盖到当前点的区间里选**结束最远**的，能覆盖就推进；这是"最远贪心"，与活动选择的"最早结束"对偶。
- **会议室数量（最小资源）**：按开始时间扫，用堆维护进行中会议的结束时间；堆大小峰值即答案。这是"在线"视角，不是相容集计数。

**边界条件**：
- 端点开闭：$[s,f)$ 用 $s \ge last\_end$；闭区间 $[s,f]$ 用 $s > last\_end$。LeetCode 题面要读清。
- 结束时间相同：按开始时间或下标稳定排序，避免抖动。
- 空集合、单元素、完全嵌套（$[1,10],[2,3],[4,5]$）都要测。
- 负坐标或无序输入：先排序再扫。

**加权情形**：每个活动有权 $w_i$，求最大权相容集。此时"结束最早"贪心**不再最优**，要用 DP：按结束时间排序，$dp[i] = \max(dp[i-1], dp[p(i)] + w_i)$，其中 $p(i)$ 是最后一个与 $i$ 相容的活动。

## 三、形式化与数学基础

**问题定义**：活动 $a_i = (s_i, f_i)$，相容定义为 $f_i \le s_j$ 或 $f_j \le s_i$（半开）。求最大基数相容集：
$$\max |A| \quad \text{s.t.} \quad \forall i \ne j \in A,\ \text{compatible}(a_i, a_j)$$

**贪心选择性质**：设 $a_k = \arg\min_i f_i$。存在最优解含 $a_k$。证明如上交换论证。归纳得算法最优，即
$$|G| = |OPT| = \max\{|A| : A \text{ 相容}\}$$

**复杂度**：排序 $O(n\log n)$，扫描 $O(n)$，总 $O(n\log n)$。空间 $O(1)$（原地）或 $O(n)$（存下标）。

**加权 DP**：
$$dp[i] = \max\big(dp[i-1],\ dp[p(i)] + w_i\big), \quad p(i) = \max\{ j < i : f_j \le s_i \}$$
$dp[i]$ 表示考虑前 $i$ 个（按结束排序）的最优权。$p(i)$ 可二分，总 $O(n\log n)$。这是贪心失效后退回 DP 的标准形态。

**与拟阵**：不带权的区间相容性构成拟阵（独立集 = 相容活动集），故贪心正确；带权可看作加权拟阵，贪心按权排序**不对**，要 DP/拟阵交。这解释了"为何无权可以、加权不行"。

**反例（按开始时间贪心）**：$[1,10], [2,3], [3,4]$。按开始时间：选 $[1,10]$，只得 1；最优 2。按结束时间：$[2,3],[3,4]$，得 2。

**会议室数（在线下界）**：排序后扫描，用最小堆存结束时间；新会议开始 $\ge$ 堆顶结束则复用。堆峰值即最小房间数。证明：任意时刻重叠数下界为堆大小；堆算法恰好达到。

## 四、代码实现

```python
import bisect
import heapq


def max_activities(intervals):
    """最多不重叠区间数。intervals: list of (start, end)，半开区间。"""
    items = sorted(intervals, key=lambda x: x[1])
    count = 0
    last_end = float("-inf")
    for s, f in items:
        if s >= last_end:
            count += 1
            last_end = f
    return count


def max_activities_with_choice(intervals):
    """返回数量与所选区间（按结束时间贪心）"""
    items = sorted(intervals, key=lambda x: x[1])
    chosen = []
    last_end = float("-inf")
    for s, f in items:
        if s >= last_end:
            chosen.append((s, f))
            last_end = f
    return chosen


def erase_overlap_intervals(intervals):
    """最少删除使不重叠 = n - 最多不重叠"""
    n = len(intervals)
    return n - max_activities(intervals)


def merge_intervals(intervals):
    """合并重叠区间"""
    items = sorted(intervals)
    merged = []
    for s, f in items:
        if not merged or s > merged[-1][1]:
            merged.append([s, f])
        else:
            merged[-1][1] = max(merged[-1][1], f)
    return [tuple(x) for x in merged]


def min_arrows(points):
    """引爆气球: points = [(x1,x2), ...]，一支竖线箭可引爆 x 坐标在 [x1,x2] 的所有气球。
    按右端点排序，箭尽量靠右。"""
    items = sorted(points, key=lambda x: x[1])
    arrows = 0
    arrow_x = None
    for s, f in items:
        if arrow_x is None or s > arrow_x:
            arrows += 1
            arrow_x = f
    return arrows


def min_meeting_rooms(intervals):
    """最小会议室数: 在线扫描 + 最小堆"""
    items = sorted(intervals)
    heap = []  # 进行中会议的结束时间
    for s, f in items:
        if heap and heap[0] <= s:
            heapq.heappop(heap)
        heapq.heappush(heap, f)
    return len(heap)


def weighted_interval_scheduling(intervals, weights):
    """加权区间调度 DP: 返回最大权"""
    items = sorted(zip(intervals, weights), key=lambda x: x[0][1])
    n = len(items)
    ends = [it[0][1] for it in items]
    dp = [0] * (n + 1)
    for i in range(1, n + 1):
        (s, f), w = items[i - 1]
        j = bisect.bisect_right(ends, s, 0, i - 1)  # 最后一个 f <= s
        dp[i] = max(dp[i - 1], dp[j] + w)
    return dp[n]


if __name__ == "__main__":
    # 经典: 11 个活动取 4 个（CLRS 图 16.1 风格）
    acts = [(1, 4), (3, 5), (0, 6), (5, 7), (3, 9), (5, 9),
            (6, 10), (8, 11), (8, 12), (2, 14), (12, 16)]
    assert max_activities(acts) == 4
    assert erase_overlap_intervals(acts) == len(acts) - 4

    assert merge_intervals([(1, 3), (2, 6), (8, 10), (15, 18)]) == [(1, 6), (8, 10), (15, 18)]
    assert min_arrows([(10, 16), (2, 8), (1, 6), (7, 12)]) == 2
    assert min_meeting_rooms([(0, 30), (5, 10), (15, 20)]) == 2

    # 加权反例: 贪心会错, DP 对
    iv = [(1, 3), (2, 5), (4, 6)]
    w = [3, 2, 4]
    # 贪心按结束: 选(1,3)再(4,6)得 7; 最优也是 7
    assert weighted_interval_scheduling(iv, w) == 7
    print("all tests passed")
```

## 五、与其他技术对比

| 维度 | 结束时间贪心 | 开始时间贪心 | 加权 DP | 在线堆（会议室） |
|---|---|---|---|---|
| 目标 | 最大不重叠数 | 启发式 | 最大权 | 最小资源 |
| 正确性 | 最优 | 可能错 | 最优 | 最优 |
| 复杂度 | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ |
| 适用 | 无权计数 | 不推荐 | 带权/带价值 | 多机/多房间 |

取舍：**计数用结束时间贪心**；**加权退回 DP**；**最小房间用堆**；**区间合并用起点排序**。变体先问清目标是"数""权"还是"资源数"，再选策略。

## 六、常见误区

1. **按开始时间排序贪心**：反例 $[1,10],[2,3],[3,4]$ 只得 1。必须按结束时间。
2. **混淆"最多不重叠"与"最少删除"**：答案互补（$n - \text{ans}$），但面试表述要对应题意；LeetCode 435 是删除数。
3. **端点开闭处理不一致**：半开用 $s \ge last\_end$，闭区间用 $s > last\_end$。差一 bug 在边界炸掉。
4. **加权问题仍用结束时间贪心**：权重不均时会丢最优。必须 DP。
5. **会议室问题当成活动选择**：会议室求"最小资源"是在线堆，不是最大相容集；两者目标不同。

## 八、面试题

**1. 区间调度与加权区间调度的解法差异？**  
无权求最大个数：按结束时间升序贪心，$O(n\log n)$，交换论证保证最优。带权求最大价值：贪心失效，用 DP $dp[i]=\max(dp[i-1], dp[p(i)]+w_i)$，$p(i)$ 二分查找，同样 $O(n\log n)$。

**2. 若要求覆盖整段时间的最小区间集合，策略如何变化？**  
这是"区间覆盖"：按起点排序，每次在能覆盖当前点的区间中选**结束最远**的，推进当前点到该结束；若某段无区间覆盖则无解。与活动选择的"最早结束"对偶，也是贪心。

**3. 如何求最小会议室数量？**  
按开始时间扫描，最小堆维护进行中会议的结束时间。新会议开始 $\ge$ 堆顶则复用弹出，否则新开。堆大小峰值即答案，$O(n\log n)$。

**4. 端点重合算重叠吗？**  
看定义。半开 $[s,f)$ 时 $f_i = s_j$ 不算重叠，条件是 $s_j \ge f_i$；闭区间时算重叠，需 $s_j > f_i$。实现前先和面试官确认。

## 九、演进与趋势

区间调度扩展到**并行机**（$m$ 台机器，最大相容族，可看作区间图着色，贪心按开始时间用堆即最优着色）、**实时系统 EDF/LLF**（按期限/松弛度贪心，有可调度性分析）、**带权与多资源**（DP/MIP）、**在线与竞争比**（无法预知未来时的策略）。工程上，云资源编排、会议室预订、CDN 缓存替换、无线频谱分配都是区间模型；学习型调度用预测时长做加权，再跑 DP/贪心混合。区间图论（最大团、着色、支配）也与此深度相关。

## 十、小结

区间调度的黄金法则是**按结束时间排序、能选就选**，交换论证保证无权情形最优；加权要 DP，最小资源用堆。分清目标（计数/权/资源）、端点开闭与排序键，就能覆盖面试中的绝大多数区间变体。
