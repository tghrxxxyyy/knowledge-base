# 拉斯维加斯算法

> 对应 Babai 1979 "Monte-Carlo Algorithms in Graph Isomorphism Testing"（LV/MC 术语来源）/ Motwani & Raghavan《Randomized Algorithms》/ Hoare 1961 "Algorithm 65: FIND" / Blum et al. 1973（BFPRT 线性时间选择）。

## 一、背景与挑战

拉斯维加斯（Las Vegas）算法与蒙特卡洛互为对偶：**结果总是正确，运行时间随机**。它适合「正确性是硬要求、时间可以波动」的场景——排序、选择、组合搜索、以及任何不能容忍错误答案的工程代码。

它的价值在于回避最坏情况而不牺牲正确性。确定性算法要保证最坏情况界，往往需要额外机制（如 BFPRT 的中位数之中位数选枢纽）与额外常数开销；随机化版本靠随机枢纽把「对手构造的坏输入」变成概率极低的事件，实现对每个固定输入都以高概率快速完成。

与蒙特卡洛的对比要点是：MC 用「可能出错」换取「时间确定」，LV 用「时间随机」换取「必然正确」；工程上可以二者结合——用随机化快速构造候选，再用确定性步骤验证，从而兼具两者的优点。

## 二、核心原理

拉斯维加斯算法有三类典型形态：

1. **循环重试（Repeat-until-success）**：每轮独立尝试，成功的概率为 $p$，失败则重试。期望轮数 $1/p$。典型如随机构造一个解、检查是否满足约束。
2. **随机化消除最坏情况（Random pivot / Random walk）**：算法结构确定，仅把关键选择随机化，从而把「最坏输入」的概率压低。典型是随机化快速排序与随机化 quickselect（Hoare 的 FIND）。
3. **随机构造 + 确定性验证（Las Vegas 化蒙特卡洛）**：先用随机化方法找一个候选解（可能失败），再用确定性算法严格验证；验证通过即输出正确答案。这在数论与代数算法中很常见——随机找一个见证（witness），再确定性地检查它。

关键工程要点有三个：**随机源必须独立于输入**（否则对手可反推种子并构造最坏情况）；**重试之间必须独立**（否则「期望 $1/p$ 轮」的结论不成立）；以及**必须有终止兜底**（LV 算法的最坏运行时间无界，工程实现常设置迭代上限并降级到确定性算法）。

## 三、形式化与数学基础

设每次尝试独立的成功概率为 $p$，则所需尝试次数 $T$ 服从几何分布：

$$
\Pr[T = k] = (1-p)^{k-1} p, \qquad \mathbb{E}[T] = \frac{1}{p}, \qquad \operatorname{Var}(T) = \frac{1-p}{p^2}
$$

由马尔可夫不等式可得尾概率界：

$$
\Pr[T \ge k\,\mathbb{E}[T]] = \Pr\!\left[T \ge \frac{k}{p}\right] \le \frac{1}{k}
$$

即「超出期望 $k$ 倍」的概率不超过 $1/k$。若各轮代价有界，可进一步用切尔诺夫界得到指数级尾界：$r$ 轮全部失败的概率为 $(1-p)^r \le e^{-pr}$。

以随机化 quickselect 为例，设输入互异、每次均匀随机取枢纽。设第 $k$ 小元素为 $x$，可以证明 $x$ 所在子问题的规模以常数概率至少缩小到 $3/4$：

$$
\Pr[\text{规模缩小到} \le \tfrac{3}{4} n] \ge \frac{1}{2}
$$

因此期望递归深度为 $O(\log n)$，期望比较次数为 $O(n)$（常见分析给出 $\mathbb{E}[C] \le 4n$ 的简洁上界；文献中的精确常数约为 $3.4n$ 量级，随计数方式不同略有差异）。这与 BFPRT 的最坏情况 $O(n)$ 形成对照：随机版实现更简单，但**最坏情况仍为 $O(n^2)$**，只是概率极低。

## 四、代码实现

```c
/* 随机化 quickselect：原地分区，期望 O(n)，结果必然正确 */
#include <stdio.h>
#include <stdlib.h>

static void swap(int *a, int *b) { int t = *a; *a = *b; *b = t; }

/* 返回 x 的秩（左侧元素个数），同时完成一次三分区 */
static int partition3(int *a, int lo, int hi, int x) {
    int lt = lo, i = lo, gt = hi;
    while (i <= gt) {
        if (a[i] < x)      swap(&a[lt++], &a[i++]);
        else if (a[i] > x) swap(&a[i], &a[gt--]);
        else               i++;
    }
    return lt;                      /* [lo,lt) 小于 x，[lt,i) 等于 x */
}

/* 求第 k 小（0 基）：每轮随机取枢纽，只递归一侧 */
int quickselect(int *a, int lo, int hi, int k) {
    while (lo < hi) {
        int x = a[lo + rand() % (hi - lo + 1)];      /* 随机枢纽，打破最坏输入 */
        int mid = partition3(a, lo, hi, x);
        if (k < mid)      hi = mid - 1;              /* 目标在左侧 */
        else if (k == mid) return a[mid];            /* 命中分界点 */
        else              lo = mid + 1;              /* 目标在右侧 */
    }
    return a[lo];
}

int main(void) {
    int a[9] = {7, 1, 5, 3, 9, 2, 8, 4, 6};
    printf("median = %d\n", quickselect(a, 0, 8, 4));  /* 第 5 小 */
    return 0;
}
```

三分区（荷兰国旗式）在存在大量重复元素时把问题规模压得更快，是工业实现（如 C++ `nth_element` 一类）的常见做法。注意 `rand() % n` 的模偏差在小 $n$ 时影响可忽略，但应避免在安全敏感场景使用。

## 五、与其他技术对比

| 算法 | 结果 | 时间 | 最坏情况 | 实现复杂度 |
| --- | --- | --- | --- | --- |
| 随机化 quickselect | 必正确 | 期望 $O(n)$ | $O(n^2)$ 但概率极低 | 低 |
| BFPRT（中位数之中位数） | 必正确 | $O(n)$ 最坏 | $O(n)$ | 高（常数大） |
| 朴素确定性选择（排序后取） | 必正确 | $O(n\log n)$ | $O(n\log n)$ | 最低 |
| Miller–Rabin 素性测试 | 概率正确（MC） | 确定 | 确定 | 低 |
| 随机构造 + 确定性验证 | 必正确（LV） | 期望有界 | 可能有界差 | 中 |
| 随机快排 | 必正确 | 期望 $O(n\log n)$ | $O(n^2)$ 概率极低 | 低 |

与蒙特卡洛的核心差异：LV 的「随机」体现在**时间**上，MC 的「随机」体现在**正确性**上。二者可用「验证器」互转：为 MC 加上确定性验证即得 LV；把 LV 截断（超时给近似答案）即近似 MC。

## 六、常见误区

- 「把它当成近似算法」：拉斯维加斯算法输出的一定是最优/精确答案，与近似算法完全不同族。
- 「忽略期望时间分析」：只测平均耗时不等于给出期望界；需说明每轮成功概率与独立性前提。
- 「把随机快排当蒙特卡洛」：快排结果必然正确（只是时间随机），属拉斯维加斯。
- 「认为期望时间等于实际时间」：由马尔可夫界，超出期望 $k$ 倍的概率可达 $1/k$，长尾真实存在，实时系统需要超时兜底。

## 八、面试题

1. **举一个拉斯维加斯算法的例子并分析期望时间？** 要点：随机化 quickselect，每轮随机枢纽、只递归一侧；规模以常数概率缩到 $3/4$ 以下，期望比较 $O(n)$。
2. **随机化选择与 BFPRT 如何取舍？** 要点：随机版实现简单、期望常数小，但最坏 $O(n^2)$；BFPRT 最坏线性但常数大、实现复杂，实时性要求高时选后者。
3. **LV 与 MC 如何互相转化？** 要点：给 MC 加确定性验证器即得 LV；把 LV 加超时截断并输出当前最好解即近似 MC。
4. **为什么重试之间必须独立？** 要点：$\mathbb{E}[T] = 1/p$ 的推导依赖几何分布，若各轮相关或共享坏状态，成功概率可能不增，期望轮数结论失效。
5. **如何给出比期望更强的保证？** 要点：重试 $r$ 次全部失败的概率为 $(1-p)^r$，可用 $e^{-pr}$ 界定，从而得到指数级的高概率保证。

## 九、演进与趋势

拉斯维加斯思想在现代系统中随处可见：随机化一致性协议与路由（打破对称）、随机化负载均衡（如「两次随机选择」）、随机化图算法与线性代数（随机投影、随机化数值线性代数）、以及密码学中的零知识证明（证明者随机化，验证者确定性检查——本质是 LV 结构）。理论上，去随机化研究试图在保持效率的前提下消除随机性；工程上，趋势是把 LV 的随机性与 MC 的截断结合，形成「有时间预算的近似+可验证」的混合算法，尤其适合在线服务与实时系统。

## 十、小结

拉斯维加斯算法保证正确、时间随机，是「正确性优先、时间靠概率」的随机范式。它的分析基石是几何分布的期望 $1/p$ 与马尔可夫/切尔诺夫尾界；工程上必须保证随机源独立于输入、重试相互独立，并为无界最坏时间准备超时兜底或确定性降级路径。
