# 在线算法

> 对应 Borodin & El-Yaniv《Online Computation and Competitive Analysis》/ Sleator & Tarjan 1985 "Amortized Efficiency of List Update and Paging Rules"（CACM）/ Lykouris & Vassilvitskii 2018 "Competitive Caching with Machine Learned Advice"。

## 一、背景与挑战

在线算法面对的是「输入逐个到达、必须立刻决策、且不可反悔」的场景：缓存淘汰、股票买卖、服务器调度、电梯调度、内存分页、竞拍与定价。与离线算法的根本差别是**没有未来信息**——决策时不知道后续会有哪些请求。

衡量标准因此不能是「与最优解比较」这一朴素想法（离线最优可能利用了未来信息，在线算法永远追不上），而需要一个新的度量：**竞争比（competitive ratio）**，即在线算法的代价与最优离线算法代价之比的**最坏情况上界**。它把「不知道未来」的代价量化成一个可证明的倍数。

难点有三个：如何证明竞争比（需要构造性下界，即针对任意在线算法给出一个输入序列使其比值达到下界）、如何在随机化模型下定义对手（oblivious vs adaptive）、以及如何在实践中利用预测（机器学习给出的未来提示）而不失去理论保证。

## 二、核心原理

在线算法的核心是「策略 + 竞争比分析」。几个必知的结果：

1. **分页/缓存置换**：缓存容量 $k$。**LRU**（最近最少使用）与 **FIFO**（先进先出）都是 $k$-competitive；而 **LFU**（最不常使用）没有常数竞争比。**标记算法（marking algorithm）**给出了随机化分页的 $O(\log k)$ 竞争比，是最优美的随机化在线结果之一。
2. **滑雪租赁问题**：租一次 1 元、买一副 $B$ 元，不知道会滑多少次。策略是「先租 $B-1$ 天，之后买」，竞争比为 2，且这是确定性算法的下界（无法做得更好）。
3. **列表更新（list update / move-to-front）**：MTF 是 2-competitive，这是 Sleator–Tarjan 的经典结果。
4. **$k$-server 问题**：$k$ 台服务器服务请求流，最小化总移动距离。确定性竞争比的下界是 $k$，随机化下界为 $O(\log k)$，一般情形的最优随机化算法是否达到 $O(\log k)$ 曾长期是开放问题。

策略设计的通用直觉是**保守与激进之间的平衡**：过于保守（如永远不动缓存）会在模式变化时付出巨大代价；过于激进（如频繁切换）会在稳定阶段浪费。竞争比分析恰好量化了这个平衡点。

## 三、形式化与数学基础

在线算法 $\mathcal{A}$ 的竞争比为 $c$，若对**一切**输入序列 $I$ 有

$$
\text{cost}_{\mathcal{A}}(I) \le c \cdot \text{cost}_{\text{OPT}}(I) + \alpha
$$

其中 $\alpha$ 是与输入长度无关的常数（称为加性常数，允许「暖机阶段」的常数额外代价）。若 $\alpha = 0$ 则称为严格 $c$-竞争。LRU 在容量为 $k$ 的分页问题上是 $k$-竞争的，且该比在确定性算法中是最优的。

以滑雪租赁为例可以看清界的来源。设实际滑雪天数为 $d$。策略「先租 $B-1$ 次再买」的代价为

$$
\text{cost}_{\mathcal{A}} = \begin{cases}
d, & d < B \\
(B-1) + B = 2B - 1, & d \ge B
\end{cases}
$$

而最优离线策略的代价为 $\min(d, B)$。于是当 $d < B$ 时比值为 $d/d = 1$；当 $d \ge B$ 时比值 $\le (2B-1)/B < 2$。故竞争比不超过 2。下界方面：任何确定性策略在「第 $B$ 天前后」都会遇到对手构造的两难——若早买则对方让 $d$ 很小，若晚买则对方让 $d$ 很大，可证明比值至少为 2。

竞争比与近似比的关键区别在于：近似比比较的是**同一问题的离线解**与离线最优解，而竞争比比较的是在线算法的代价与**拥有完整未来信息的最优离线算法**的代价，天然包含「信息劣势」这一额外成本。

## 四、代码实现

```python
# LRU 缓存（k-competitive）与滑雪租赁的在线策略
from collections import OrderedDict

class LRU:
    def __init__(self, k):
        self.k = k
        self.cache = OrderedDict()      # 头部为最近使用，尾部为最久未使用
        self.misses = 0

    def access(self, x):
        if x in self.cache:
            self.cache.move_to_end(x)   # 命中：提升到最近使用端
            return True
        self.misses += 1
        if len(self.cache) >= self.k:
            self.cache.popitem(last=False)   # 淘汰最久未使用的项
        self.cache[x] = True
        return False

def ski_rental(days, buy_cost):
    # 先租 buy_cost-1 次，之后买断；代价达到 2*buy_cost-1 即为买断完成
    spent = 0
    for _ in range(days):
        spent += 1 if spent < buy_cost - 1 else buy_cost
        if spent >= 2 * buy_cost - 1:
            break                       # 已买断，后续天数不再产生代价
    return spent

if __name__ == "__main__":
    lru = LRU(3)
    for page in [1, 2, 3, 1, 4, 5, 1, 2, 3, 4]:
        lru.access(page)
    print("LRU misses:", lru.misses)
    for d in (1, 5, 20, 100):
        on, off = ski_rental(d, 10), min(d, 10)   # 后者是拥有未来信息的离线最优
        print(f"days={d:3d} online={on:3d} offline={off:3d} ratio={on/off:.2f}")
```

输出可直接验证竞争比：任取天数，`ratio` 都不超过 2，且在 $d$ 略小于买断价时接近 1、在 $d$ 很大时趋近 2。

## 五、与其他技术对比

| 算法/模型 | 竞争比 | 模型假设 | 特点 |
| --- | --- | --- | --- |
| LRU | $k$（最优确定性） | 分页、容量 $k$ | 实现简单，符合局部性时实测好 |
| LFU | 无常数比 | 同上 | 对频率分布敏感，可能被对抗 |
| 标记算法（随机化） | $O(\log k)$ | 随机化、oblivious 对手 | 理论上显著优于确定性 |
| 滑雪租赁策略 | 2（最优确定性） | 单次决策 | 与 $k$-server 同源 |
| ML 增强缓存（如 LHD） | 最优有界，较差预测下降级 | 带预测的在线 | 好预测时接近离线最优 |
| 离线最优（OPT/Belady） | 1（基准） | 拥有全部未来信息 | 不可实现，仅作对照 |

## 六、常见误区

- 「竞争比就是近似比」：竞争比的对照物是拥有未来信息的最优离线算法，包含信息劣势，因此数值通常更大。
- 「在线算法可以用离线最优评估」：离线最优需要未来信息，用它做基准会让在线算法永远「看起来很差」。
- 「LRU 总比 FIFO 好」：两者竞争比同为 $k$，特定负载下 FIFO 甚至更好；LRU 的优势来自局部性而非理论比值。
- 「随机化对手模型都一样」：oblivious 对手（预先固定输入）与 adaptive 对手（观察随机选择后构造输入）给出的下界完全不同，对比结果时必须说明模型。
- 「有了 ML 预测就不再需要理论保证」：预测可能错误，实用做法是「预测正确时接近最优，预测错误时退回竞争比保证」（一致性 + 鲁棒性）。

## 八、面试题

1. **LRU 的竞争比是多少，如何理解？** 要点：容量 $k$ 的分页问题中 LRU 是 $k$-competitive，且确定性算法无法更好；直觉是最坏情况下每 $k$ 次请求可能全部缺失，而离线最优全命中。
2. **滑雪租赁问题的最优在线策略与竞争比？** 要点：先租 $B-1$ 次再买断，竞争比不超过 2；且可证任何确定性策略的竞争比下界为 2。
3. **竞争比与近似比的区别？** 要点：近似比对照离线最优解（同一信息条件），竞争比对照拥有未来信息的最优离线算法，度量的是信息劣势的代价。
4. **随机化在线算法的对手模型有何影响？** 要点：oblivious 对手下随机化可显著改进（如分页 $O(\log k)$），adaptive 对手下往往退回确定性量级，结论必须标明模型。
5. **ML 预测如何融入在线算法？** 要点：用「一致性（预测准确时接近最优）+ 鲁棒性（预测差时仍有竞争比保证）」框架，通过置信度参数在预测与保守策略间切换。

## 九、演进与趋势

理论方向上，$k$-server 猜想与随机化竞争比的紧确界仍是核心开放问题；组合方法上出现了对「在线匹配、在线背包、在线拍卖」等新模型的系统研究。应用方向上最显著的变化是**学习增强在线算法**（learning-augmented online algorithms）：用机器学习给出对未来的预测（如下一个页面请求、下一笔作业时长），再用「一致性/鲁棒性」框架保证预测错误时不至于崩坏。这一思路已进入 CDN 缓存、数据库缓冲池、云调度与广告分配等系统。同时，在线算法与在线凸优化、bandit 问题的交叉也在加深。

## 十、小结

在线算法在未知未来下必须立即决策，竞争比提供了「相对最优离线算法」的可证明性能界。必记的结论是分页问题的 $k$-竞争下界、滑雪租赁的 2-竞争最优策略、以及随机化带来的 $O(\log k)$ 改进；实践中真正的进步来自把预测引入策略，同时保留竞争比兜底。
