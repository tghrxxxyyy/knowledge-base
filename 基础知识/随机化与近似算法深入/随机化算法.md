# 随机化算法

> 对应 Motwani & Raghavan《Randomized Algorithms》(1995) / CLRS 第 5 章（概率分析与随机化算法）/ Karger 1993 "Global Min-cuts in RNC" / Rabin 1980 "Probabilistic Algorithm for Testing Primality"。

## 一、背景与挑战

确定性算法必须对所有输入都表现良好，因此常被最坏情况绑住手脚：快速排序在对手精心构造的输入上退化为 $O(n^2)$，哈希表在对手选择冲突键时退化为线性查找，对称性强的结构（如图同构）会让任何固定策略失效。

随机化不是「碰运气」，而是一种**算法设计范式**：把随机选择引入算法内部，使对手无法预测执行路径，从而把「对所有输入都好」弱化为「对每一个固定输入，以高概率好」。代价是结果或时间变成随机变量，必须用概率语言描述其保证。它带来三类收益：更简单的实现（随机化最小割远比确定性算法简洁）、更好的期望性能（随机化快排的比较次数接近下界常数因子）、以及对抗输入的免疫。

## 二、核心原理

按「随机性影响什么」分为两大族，这是本领域最基本的分类：

- **蒙特卡洛（Monte Carlo）算法**：运行时间确定（或有确定上界），但结果可能出错，出错概率可控制。典型如 Miller–Rabin 素性测试、Freivalds 矩阵乘法验证。
- **拉斯维加斯（Las Vegas）算法**：结果**总是正确**，运行时间随机。典型如随机化快速排序、随机化 quickselect、随机重试式算法。

随机性在算法中有四种常见用途：

1. **打破对称与对抗**：随机选枢纽，使任何固定输入都等价于随机输入。
2. **采样估计**：用随机样本估计难以解析的量。
3. **指纹与校验**：用随机哈希把「相等性判断」压缩为廉价比较，如 Rabin–Karp 字符串匹配。
4. **随机化构造 + 确定性验证**：随机找一个候选解，再花确定性代价验证（把 MC 转成 LV 的常用手法）。

## 三、形式化与数学基础

以随机化快速排序为例。设输入为 $n$ 个互异元素，算法每次均匀随机挑选枢纽。定义指示变量 $X_{ij} = 1$ 表示元素 $i$ 与 $j$（按排序后次序）被比较过。可以证明

$$
\Pr[X_{ij} = 1] = \frac{2}{j - i + 1}
$$

因为 $i$ 与 $j$ 被比较当且仅当在区间 $[i, j]$ 中，$i$ 或 $j$ 是最先被选为枢纽的元素。于是总比较次数的期望为

$$
\mathbb{E}[C] = \sum_{i<j} \frac{2}{j-i+1} = 2\sum_{k=1}^{n-1}\frac{n-k}{k} < 2n\ln n
$$

即期望 $O(n\log n)$，常数因子接近下界 $\ln n$ 的量级——比确定性中位数版本更简单又更快。

把期望界转成高概率界需要尾部不等式。若 $X$ 是 $N$ 个独立同分布伯努利变量之和、均值 $\mu$，切尔诺夫界给出

$$
\Pr[X \ge (1+\delta)\mu] \le \exp\!\left(-\frac{\delta^2 \mu}{2+\delta}\right), \quad \delta \in (0,1]
$$

这是把「期望好」升级为「几乎必然好」的标准工具，只需独立性与有界性。而马尔可夫不等式 $\Pr[X \ge k\,\mathbb{E}[X]] \le 1/k$ 只能给出多项式级尾界，适用于「重试」型分析。

## 四、代码实现

```c
/* 随机化快速排序：原地 Lomuto 分区 + 随机枢纽 */
#include <stdio.h>
#include <stdlib.h>

static void swap(int *a, int *b) { int t = *a; *a = *b; *b = t; }

/* 均匀随机取枢纽并与末元素交换，从而打破对手构造的最坏输入 */
static int partition(int *a, int lo, int hi) {
    int r = lo + rand() % (hi - lo + 1);
    swap(&a[r], &a[hi]);
    int pivot = a[hi], i = lo - 1;
    for (int j = lo; j < hi; j++)
        if (a[j] < pivot) swap(&a[++i], &a[j]);
    swap(&a[i + 1], &a[hi]);
    return i + 1;
}

/* 小的子区间递归、大的用循环处理，控制栈深度 */
void qsort_rand(int *a, int lo, int hi) {
    while (lo < hi) {
        int p = partition(a, lo, hi);
        if (p - lo < hi - p) { qsort_rand(a, lo, p - 1); lo = p + 1; }
        else                 { qsort_rand(a, p + 1, hi); hi = p - 1; }
    }
}

int main(void) {
    int a[10] = {5, 2, 9, 1, 7, 3, 8, 0, 6, 4};
    qsort_rand(a, 0, 9);
    for (int i = 0; i < 10; i++) printf("%d ", a[i]);
    putchar('\n');
    return 0;
}
```

注意 `rand()` 的取值上限（`RAND_MAX`）在 `hi - lo + 1` 很大时会引入模偏差，生产代码应使用 `arc4random_uniform()` 一类无偏接口或拒绝采样。此外随机源必须独立于输入，否则对手可以反推种子。

## 五、与其他技术对比

| 类型 | 结果正确性 | 运行时间 | 保证形式 | 典型算法 |
| --- | --- | --- | --- | --- |
| 确定性算法 | 必正确 | 确定 | 最坏情况界 | 归并排序、BFPRT |
| 拉斯维加斯 | 必正确 | 随机 | 期望/高概率界 | 随机快排、随机 quickselect |
| 蒙特卡洛（单侧错） | 可能漏判 | 确定 | 错误概率有界 | Miller–Rabin |
| 蒙特卡洛（双侧错） | 可能误判 | 确定 | 错误概率有界 | Freivalds 矩阵验证 |

与确定性算法对比的要点：随机化消除了「对抗输入」这一最坏情况来源，但引入了「概率正确」的新成本，且结果默认不可复现（除非固定种子；而固定种子等于放弃抗对抗性）。

## 六、常见误区

- 「随机化算法结果一定对」：蒙特卡洛族可能给出错误答案，必须用重复执行降低错误率。
- 「混淆期望与最坏」：$O(n\log n)$ 期望并不排除 $O(n^2)$ 尾部，只是概率极低（需用尾界证明）。
- 「伪随机源随便用」：低质量线性同余在低位有强相关性，会破坏独立性假设，使误差界失效。
- 「多次重复一定独立」：每次用同一固定种子时重复毫无意义；算法内部状态有残留时重复也可能不独立。
- 「随机化可以掩盖错误的算法设计」：复杂度阶数由算法结构决定，随机化只改变常数与最坏情况风险。

## 八、面试题

1. **随机化快排为何期望 $O(n\log n)$？** 要点：用指示变量 $X_{ij}$ 表示两元素是否被比较，$\Pr[X_{ij}=1] = 2/(j-i+1)$，求和得 $2nH_n$ 量级。
2. **MC 与 LV 的本质区别？** 要点：MC 时间确定但可能错，LV 必正确但时间随机；二者可通过「随机构造 + 确定性验证」互相转化。
3. **如何把期望界升级为高概率界？** 要点：用切尔诺夫/霍夫丁界，依赖独立性与有界性；马尔可夫只能给多项式级尾界。
4. **随机化为什么能抗最坏输入？** 要点：对手无法预测随机选择，对任意固定输入，算法行为都等价于随机输入下的行为。
5. **如何消除随机性（去随机化）？** 要点：条件期望法（把随机选择替换为条件期望更优的确定性选择）、构造小型 $\epsilon$-独立采样空间，或用伪随机生成器模拟。

## 九、演进与趋势

随机化已成为许多领域的默认工具：随机哈希与跳表、流式算法（Count-Min Sketch、HyperLogLog）、分布式共识与路由（随机化消除对称）、机器学习（随机梯度、随机投影、Dropout）。理论方向的长期议题是**去随机化**——在哪些条件下随机性可被消除而不损失效率。另一条线是**随机源质量**：从硬件 RNG（RDRAND/RNDR）到可验证随机函数，随机性的可信度本身成为安全问题。

## 十、小结

随机化算法以概率换取简洁、鲁棒与抗对抗性，其正确理解依赖两个基石：按「结果是否可能错」划分的蒙特卡洛/拉斯维加斯分类，以及用指示变量与尾部不等式做的期望与高概率分析。它不改变复杂度阶数，但能把最坏情况的悬崖变成可量化的风险。
