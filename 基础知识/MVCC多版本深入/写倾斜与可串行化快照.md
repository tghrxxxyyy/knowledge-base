# 写倾斜与可串行化快照

> 对应 Berenson et al. 1995（write skew 在 SI 下的存在性），以及 Kleppmann《Designing Data-Intensive Applications》第 7 章（SSI）。

## 一、背景与挑战
快照隔离避免了脏读/不可重复读/幻读，却仍允许“写倾斜”：两个事务各自读对方将写的重叠数据，基于快照判断后都提交，结果等价于某种非串行交错，破坏业务不变量。

## 二、核心原理
写倾斜示例：医生值班表要求“至少一人值班”，两个事务各读“对方在值班”的快照，都把自己设为不在岗并提交，导致无人值班。可串行化快照隔离（SSI）在 SI 基础上跟踪事务间的读写依赖（rw-antidependency），提交时检测危险结构并中止其一。

## 三、形式化与数学基础
危险结构（SSI 检测）：存在事务 $T_1, T_2$ 形成环或读写依赖使序列化图含环：
$$ T_1 \xrightarrow{rw} T_2 \xrightarrow{ww} T_1 \implies \text{危险} $$
SSI 通过记录 in/out 冲突标志，在提交时若自身处于危险构型则中止：
$$ \text{abort if } flagged\_dangerous(T) $$

## 四、代码实现
```python
# 简化 SSI 危险标记（仅示意）
def on_commit(txn):
    if txn.in_conflict and txn.out_conflict:   # 既被读又写冲突
        return ABORT                           # 可能构成危险结构
    return COMMIT
```

## 五、与其他技术对比
SI 允许写倾斜；2PL 严格可串行但锁冲突高；SSI 在接近 SI 性能的前提下达到可串行化，被 PostgreSQL 9.1+ 实现。

## 六、常见误区
1) 认为 SI 已“够安全”——写倾斜会破坏不变量。
2) 误以为写倾斜只是更新同一行——跨行不变量也会触发。
3) 低估 SSI 的误中止率——依赖检测精度。

## 十、小结
写倾斜揭示 SI 的非串行化本质；SSI 用冲突图检测补齐正确性，是“性能与一致性”兼得的主流方案。
