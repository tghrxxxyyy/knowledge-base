# 快照的通道状态

> 对应 Chandy & Lamport 1985（channel state recording）与 mit-pdos/6.824 Lab 3 对通道状态的实现要求。

## 一、背景与挑战
全局快照不止进程状态，还包括“在途消息”。通道状态记录的是快照边界处仍在传输、尚未被接收方计入的消息集合。遗漏它会破坏一致性。

## 二、核心原理
- 进程开始记录后，到该通道 marker 到达前，所有收到的应用消息都记入该通道状态。
- marker 到达即关闭记录。
- 最终通道状态 = “快照前发出、快照后到达”的消息。

## 三、形式化与数学基础
对通道 C(p→q)，记 $M_{pre}$ 为 marker 前发出的消息，$M_{post}$ 为 marker 后发出的。通道状态 $S_C = \{ m \in M_{pre} \mid r_m \text{ 在快照之后} \}$。这保证全局状态因果闭合。

## 四、代码实现
# 通道状态记录
def on_msg(self, ch, msg, snap):
    if snap.recording and not snap.channel_closed[ch]:
        snap.channel[ch].append(msg)   # 记入在途
    else:
        self.deliver(msg)

## 五、与其他技术对比
- 对比仅记录进程状态：会丢失在途消息。
- 对比数据库 WAL：WAL 记录的是已落盘日志而非在途。

## 六、常见误区
1. 把 marker 当作普通消息处理。
2. 在 marker 到达后仍写入通道状态。
