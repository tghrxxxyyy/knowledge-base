# 可串行化

> 对应 Silberschatz《Database System Concepts》15.6 锁与可串行化，以及 Garcia-Molina《Database Systems: The Complete Book》16 章。

## 一、背景与挑战
可串行化（Serializability）要求并发调度效果等价于某串行调度。如何在高并发下既保证又高效，是并发控制核心难题。

## 二、核心原理
冲突可串行化：调度中相邻冲突操作（读写、写读、写写同一数据）不可交换，若其优先图（precedence graph）无环则可串行化。两段锁（2PL）保证冲突可串行化：加锁阶段后只有释放。

## 三、形式化 / 数学基础
优先图 $G=(T, E)$，$T_i \to T_j$ 当 $T_i$ 在 $T_j$ 前操作同一数据且至少一方为写。可串行化 $\iff G$ 无环。2PL 定理：遵守 2PL 的调度必冲突可串行化。

## 四、代码实现
```python
def two_phase_lock(op, locks, held):
    if op.kind in ('r','w'):
        acquire(locks[op.item], op.kind)
        held.add(op.item)        # 增长阶段
    # 一旦释放，禁止再加锁
```

## 五、与其他技术对比
| 方法 | 保证 | 死锁 | 并发 |
|------|------|------|------|
| 2PL | 冲突可串行化 | 可能 | 中 |
| SSI | 可串行化 | 无 | 高 |
| 时间戳 | 可串行化 | 无 | 中 |

## 六、常见误区
1. 可串行化=最优——可能过度限制并发（如 snapshot 已够用）。
2. 2PL 不会死锁——会，需超时/检测。
3. 视图可串行化易检测——实际是 NP 完全。

## 九、演进与趋势
SSI、乐观并发控制（OCC）、多版本 2PL 等在不牺牲正确性的前提下提升并发，云端多采 MVCC+SSI。

## 十、小结
可串行化是正确性的黄金标准；2PL 与 SSI 是两大实现路线，前者加锁后者检测冲突环。
