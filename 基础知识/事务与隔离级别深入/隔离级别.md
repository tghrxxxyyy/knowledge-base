# 隔离级别

> 对应 ANSI SQL-92 隔离级别，以及 Silberschatz《Database System Concepts》15.4。

## 一、背景与挑战
串行化执行最安全但吞吐低。SQL 标准定义四级隔离，在异常与性能间折中。但 ANSI 定义存在漏洞（如写倾斜未覆盖）。

## 二、核心原理
四级：Read Uncommitted、Read Committed、Repeatable Read、Serializable。级别升高逐步禁止脏读、不可重复读、幻读等异常。

## 三、形式化 / 数学基础
用禁止的异常表刻画：
| 级别 | 脏读 | 不可重复读 | 幻读 |
|------|------|------------|------|
| RU | 允许 | 允许 | 允许 |
| RC | 禁止 | 允许 | 允许 |
| RR | 禁止 | 禁止 | 允许* |
| S  | 禁止 | 禁止 | 禁止 |
（*Snapshot 隔离阻止幻读但非 ANSI 串行化）

## 四、代码实现
```sql
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
BEGIN;
SELECT * FROM orders WHERE user_id = 1;  -- 快照内一致
COMMIT;
```

## 五、与其他技术对比
| 级别 | 实现 | 性能 |
|------|------|------|
| RC | 语句级快照/锁 | 高 |
| RR | 事务级快照 | 中 |
| S  | 谓词锁/SSI | 低 |

## 六、常见误区
1. RR 一定能防幻读——基于锁的 RR 才防，快照 RR 不防写倾斜。
2. 级别越高越正确——Serializable 才等价于串行。
3. MySQL 默认 RR 等于标准 RR——InnoDB RR 额外防幻读（next-key lock）。

## 九、演进与趋势
Serializable Snapshot Isolation（SSI，如 PostgreSQL 9.1+）在不加锁下达到串行化，是近年主流进展。

## 十、小结
隔离级别是异常与性能的折中；理解每个级别禁止的异常比记名字更重要。
