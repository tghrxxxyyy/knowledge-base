# 快照隔离

> 对应 Berenson et al. 1995 A Critique of ANSI SQL Isolation Levels，以及 DDIA 中文第 7 章。

## 一、背景与挑战
加锁串行化吞吐低。快照隔离（SI）让每个事务看到一致性快照，读不阻塞写、写不阻塞读，但标准 ANSI 未涵盖，且存在写倾斜。

## 二、核心原理
事务开始时获取快照版本号（如 xmin）。读操作只看在快照前已提交且未被后续删除的版本；写操作在提交时检查写写冲突（first-committer-wins）。

## 三、形式化 / 数学基础
版本可见性规则：行版本 $v$ 对事务 $T$（快照 $s$）可见当且仅当 $v.xmin \le s < v.xmax$（或 $xmax$ 未提交）。提交时若 $\exists$ 已提交事务修改了 $T$ 读过/写过的相同键则中止（写倾斜检测的基础）。

## 四、代码实现
```sql
-- PostgreSQL 显式快照隔离（实际为可串行化 SSI 之前用 REPEATABLE READ 近似 SI）
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
BEGIN;
-- 整个事务看到同一快照
SELECT sum(bal) FROM accounts;
COMMIT;
```

## 五、与其他技术对比
| 方案 | 读阻塞写 | 写倾斜 | 性能 |
|------|----------|--------|------|
| 锁串行化 | 是 | 无 | 低 |
| SI | 否 | 有 | 高 |
| SSI | 否 | 无 | 中高 |

## 六、常见误区
1. SI 等同 Serializable——错，存在写倾斜。
2. 快照永远最新——快照是事务开始时的。
3. SI 无锁就无冲突——first-committer-wins 仍会中止。

## 九、演进与趋势
SSI 在 SI 之上加依赖图环检测，达到真正串行化且无锁，PostgreSQL 已落地。

## 十、小结
快照隔离以多版本换取高并发，但需警惕写倾斜；SSI 是其安全升级。
