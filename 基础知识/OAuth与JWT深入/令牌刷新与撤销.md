# 令牌刷新与撤销

> 对应 RFC 6749 刷新令牌 / RFC 7519 / OWASP。

## 一、背景与挑战
access_token 短命(防泄露窗口)但频繁过期影响体验。refresh_token 换发新 token，却引入被盗后长期可用的撤销难题。

## 二、核心原理
access_token 短时(如 15min)，refresh_token 长时(如 30天)且可轮换：每次用 refresh 换新 access 同时作废旧 refresh(rotation)，一旦检测到重用即吊销整族令牌。

## 三、形式化与数学基础
令牌生命周期：
$$ t_{access} \ll t_{refresh} $$
轮换安全：若 refresh $r_k$ 被用后 $r_k$ 再出现则判定泄露：
$$ reuse(r_k) \Rightarrow revoke(family(r_k)) $$

## 四、代码实现
```python
# 刷新并轮换(示意)
def refresh(rt):
    fam = store.get_family(rt)
    if rt != fam.current:          # 检测到重用/旧令牌
        fam.revoke_all(); return 403
    new_rt = fam.rotate()          # 轮换并作废旧
    new_at = issue_access(fam.user)
    return {"access_token": new_at, "refresh_token": new_rt}
```

## 五、与其他技术对比
短 access+刷新比长 access 安全；服务端黑名单 vs 轮换各有成本。JWT 无状态使吊销需额外机制(黑名单/版本号)。

## 六、常见误区
refresh_token 长期不变被拖库。前端存 refresh 于 localStorage 易 XSS 窃。忽略轮换导致一钥永逸。

## 七、与开源书/权威来源对应
RFC 6749 §1.5；OAuth Security BCP；OWASP 会话管理。

## 八、面试题
为何短 access+refresh？轮换如何detect泄露？JWT 如何吊销？

## 九、演进与趋势
DPoP 绑定、绑定 cookie 的刷新、续期令牌(bound token)。

## 十、小结
刷新令牌以轮换与短命 access 平衡体验与安全，轮换检测重用是吊销关键。
