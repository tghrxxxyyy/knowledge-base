# 写合并Write Combining

> 对应 Intel SDM 卷3 中 Write-Combining (WC) 内存类型与 MTRR/PAT 的规定。

## 一、背景与挑战

对显存、设备 MMIO 等不可缓存（UC/WC）区域，若逐字节或逐个 32 位字写入，会产生大量窄总线事务，设备与总线不堪重负。图形帧缓冲的填充就是典型：像素写入极其密集，但每个缓存行内可自然聚合。

写合并（write combining）把落在同一缓存行内的多个写累积起来，等行填满或缓冲超时/遇屏障时，再作为一次宽事务发往设备，显著降低事务数与开销。

## 二、核心原理

硬件维护若干写合并缓冲（WC buffer）：

1. 写进入 WC 缓冲，按缓存行地址归组，不立即发出。
2. 同一行的后续写继续累积；行填满则刷出。
3. 缓冲超时、遇到屏障或需要读同一区域时，强制刷出。
4. WC 区域**不做读转发、不缓存**，读操作直接走慢速总线。

因此 WC 只适合「连续、只写」的访问模式，如帧缓冲、DMA 描述符写入、设备命令队列。

## 三、形式化与数学基础

设对某缓存行 $L$ 共发生 $k$ 次写，每次 $b$ 字节。未合并时每次写是一次独立事务：

$$T_{unmerged} = k$$

理想合并后（行大小 64 字节）事务数约为：

$$T_{merged} \approx \left\lceil \frac{k \cdot b}{64} \right\rceil$$

当 $b=4,\ k=16$ 时，$T_{unmerged}=16$，$T_{merged}\approx 1$，事务数下降一个数量级。合并收益与写是否连续强相关：若写分散在不同行，缓冲会频繁刷出，收益消失。

## 四、代码实现

对 `mmap` 得到的 WC 映射区域顺序写，是最常见的用法。

```c
#include <stdint.h>
#include <string.h>

// fb 指向以 write-combining 类型映射的帧缓冲基址
void fill_row(volatile uint32_t *fb, const uint32_t *pixels, size_t n) {
    // 连续、按 16 字节粒度写，便于硬件合并为整行事务
    size_t i = 0;
    for (; i + 4 <= n; i += 4) {
        fb[i + 0] = pixels[i + 0];
        fb[i + 1] = pixels[i + 1];
        fb[i + 2] = pixels[i + 2];
        fb[i + 3] = pixels[i + 3];
    }
    for (; i < n; ++i) fb[i] = pixels[i];
    // 需要确保写已送达设备时，再插入屏障 / 读回
}
```

写合并缓冲通常有数量上限，同时活跃的行数过多会导致互相驱逐，因此应尽量让写「贴着同一行向前推进」。

## 五、与其他技术对比

| 维度 | 普通写缓冲（WB 区域） | 写合并（WC 区域） | 写穿透（WT） |
| --- | --- | --- | --- |
| 对象 | 可缓存内存 | 不可缓存/设备内存 | 设备/特殊区域 |
| 读转发 | 有 | 无 | 无 |
| 缓存后续读 | 是 | 否 | 视实现 |
| 目标 | 隐藏写延迟 | 减少事务数 | 立即写达 |
| 典型用法 | 通用写 | 帧缓冲、MMIO 流式写 | 寄存器写 |

## 六、常见误区

- 误区一：WC 区域可读回刚写的值。WC 不做读转发，读会走真实总线，既慢又可能破坏合并流。
- 误区二：WC 对所有写都有效。分散在不同缓存行的写会不断触发刷出，合并收益很低。
- 误区三：WC 与普通写缓冲是一回事。前者面向不可缓存区域且只写，后者面向可缓存写并支持转发。

## 八、面试题

1. 为什么 WC 区域不宜读？答：不缓存、不合并读，读直达慢速设备总线并打断合并流。
2. 写合并与写缓冲的区别？答：前者针对不可缓存区域的只写合并，后者针对可缓存写且支持转发。
3. 什么时候需要主动刷新 WC 缓冲？答：要把数据真正送达设备时，或以屏障/读回强制排序时。
4. 如何最大化合并收益？答：让写按缓存行连续推进，减少同时活跃的行数。

## 九、演进与趋势

GPU 与加速器暴露更丰富的内存类型（device、write-through、streaming 等），写合并仍是设备映射的标准优化。在异构计算与持久内存语境下，刷新与排序语义更受重视，具体语义以各厂商官方最新文档为准。

## 十、小结

写合并以「同缓存行写累积成单次宽事务」降低不可缓存区域的写开销，是设备映射性能的关键。用它的前提是访问连续且只写，并且要清楚它不含读转发、需要主动刷新才能保证送达。
