# 写合并Write Combining

> 对应 Intel SDM 卷3 中 Write-Combining (WC) 内存类型与写合并缓冲。

## 一、背景与挑战
对显存或设备内存等不可缓存（UC/WC）区域，逐字节写会产生大量总线事务。写合并（write combining）把同一缓存行的多个写聚合成一次更宽的事务，显著减少开销。

## 二、核心原理
硬件维护若干写合并缓冲（WC buffer），将落在同一缓存行内的连续/邻近写累积，直到行填满或超时/遇屏障，再一次性刷出。常用于图形帧缓冲与 DMA 描述符写入。

## 三、形式化与数学基础
设对缓存行 $L$ 共 $k$ 次写，每次 $b$ 字节。未合并需 $k$ 次事务，合并后约 $\lceil k\cdot b / 64\rceil$ 次：
$$T_{merged} \approx \left\lceil\frac{k\cdot b}{64}\right\rceil \ll k = T_{unmerged}$$

## 四、代码实现
```c
// 对 WC 映射区域连续写（如帧缓冲）
volatile uint32_t* fb = wc_mapping;
for (int i=0;i<N;i+=4) fb[i]=pixel[i]; // 合并为 16 字节写
```

## 五、与其他技术对比
写合并针对不可缓存区域且只写不读；普通写缓冲针对可缓存写。WC 不具缓存语义（不可读转发），用途不同。

## 六、常见误区
误以为 WC 区域可读回刚写的值。WC 不做读转发，读会走真实总线，性能极差，应避免对 WC 区读-改-写。

## 七、与开源书/权威来源对应
Intel SDM 卷3 的「Memory Type Range Registers」与 WC 类型规定写合并语义；显卡驱动广泛依赖此特性。

## 八、面试题
问：为何 WC 区不宜读？答：WC 不缓存、不合并读，读操作直接访问慢速设备总线，且破坏合并流。

## 九、演进与趋势
GPU 与加速器暴露更丰富的内存类型（如 write-through、device），写合并仍是设备映射的标准优化。

## 十、小结
写合并以「同缓存行写累积成单次事务」降低不可缓存区域的写开销，是设备映射性能的关键。
