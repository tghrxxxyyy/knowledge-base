# 写缓冲区基本结构

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》第 5 章与 Bryant & O'Hallaron《CSAPP》第 6 章。

## 一、背景与挑战

处理器核产生写操作的速度远高于内存子系统能接受的速度。若每条 store 都要阻塞到数据写入下级存储才算完成，流水线将被严重拖慢；而且写是「射后不理」的语义，本核并不需要等它落地。

写缓冲区（write buffer / store buffer）作为核与内存之间的 FIFO 缓冲层，解耦二者速率：store 入队即算完成，后台按内存可承受的速率逐个刷出。

## 二、核心原理

写缓冲的基本工作方式：

1. **入队即完成**：store 指令把地址与数据放入缓冲条目，流水线立即继续，不必等待内存。
2. **后台刷出**：缓冲控制器把条目按 FIFO 顺序写入下级缓存/内存，写完成时回收条目。
3. **读转发**：若后续 load 命中缓冲中尚未刷出的条目，需把最新值转发给 load（store-to-load forwarding），保证本核读到自己的写。
4. **满则停顿**：缓冲满且仍有 store 时，流水线必须停顿，直到有空位。

现代实现还会做写合并（write coalescing）：把同一缓存行的多个条目归并，减少下级事务数。

## 三、形式化与数学基础

设每周期产生 $w$ 条 store，下级内存的长期吸收速率为 $m$（通常 $m < w$）。有深度 $D$ 的写缓冲可吸收瞬时突发，只要累积未决量不超过 $D$：

$$\max_{t}\left(\sum_{\tau \le t} w_\tau - \sum_{\tau \le t} m_\tau\right) \le D$$

若长期 $\mathbb{E}[w] > m$，无论 $D$ 多大最终都会填满并停顿，因此写缓冲只解决「突发/短时」不匹配，长期吞吐仍由内存带宽决定。平均停顿周期可近似为：

$$Stall \approx \max\left(0,\; \mathbb{E}[w] - m\right) \cdot \frac{1}{\text{每条刷出耗时}}$$

## 四、代码实现

以下用 Verilog 片段示意写缓冲的核心结构（地址、数据、有效位与队头/队尾指针）。

```verilog
module store_buffer #(parameter DEPTH = 8) (
    input  wire        clk,
    input  wire        rst,
    input  wire        store_en,
    input  wire [63:0] store_addr,
    input  wire [63:0] store_data,
    output wire        full
);
    reg [63:0] addr  [0:DEPTH-1];
    reg [63:0] data  [0:DEPTH-1];
    reg        valid [0:DEPTH-1];
    reg [$clog2(DEPTH)-1:0] head, tail;
    reg [$clog2(DEPTH):0]   count;

    assign full = (count == DEPTH);

    always @(posedge clk) begin
        if (rst) begin
            head <= 0; tail <= 0; count <= 0;
        end else begin
            if (store_en && !full) begin   // 入队
                addr[tail]  <= store_addr;
                data[tail]  <= store_data;
                valid[tail] <= 1'b1;
                tail  <= (tail + 1) % DEPTH;
                count <= count + 1;
            end
            if (count != 0 && drain_ready) begin // 后台刷出
                valid[head] <= 1'b0;
                head  <= (head + 1) % DEPTH;
                count <= count - 1;
            end
        end
    end
endmodule
```

真实设计还需处理转发比较逻辑、对齐合并、与一致性协议（如 MESI）的交互。

## 五、与其他技术对比

| 结构 | 解决的问题 | 方向 | 是否需转发 |
| --- | --- | --- | --- |
| 写缓冲 | 写速率与内存不匹配 | 写 | 是（store-to-load） |
| 读缓冲 / MSHR | 读延迟与未命中 | 读 | 否（但对齐合并） |
| 预取器 | 隐藏读延迟 | 读 | 否 |
| 写合并缓冲（WC） | 不可缓存区域的事务数 | 写 | 否（不可读转发） |

## 六、常见误区

- 误区一：store 入缓冲即对其他核可见。入缓冲只对本核「完成」，全局可见性由一致性协议与刷出时机决定。
- 误区二：写缓冲能提升长期吞吐。它只吸收突发；长期带宽受内存限制。
- 误区三：写缓冲影响不到读。实际上读需与缓冲做地址比较以转发，比较逻辑是关键的时序路径之一。

## 七、与开源书·权威来源对应

- Hennessy & Patterson《Computer Architecture: A Quantitative Approach》第 5 章，把写缓冲作为「处理器-内存速度差」的标准解法。
- Bryant & O'Hallaron《CSAPP》第 6 章，写缓冲对写命中延迟的隐藏。
- Sorin, Hill & Wood《A Primer on Memory Consistency and Cache Coherence》，把 store buffer 纳入内存模型建模。

## 八、面试题

1. 写缓冲与读缓冲解决的是同一个问题吗？答：不是。写缓冲对齐写速率，读缓冲/预取隐藏读延迟。
2. store 后立即 load 同地址能否读到新值？答：能，通过 store-to-load 转发，但仅限本核。
3. 写缓冲填满会发生什么？答：流水线停顿，直到有条目刷出。
4. 写合并减少的是什么？答：对下级存储（缓存/内存/设备）的事务数与带宽压力。

## 九、演进与趋势

现代实现普遍采用合并写缓冲、按缓存行归并、与 miss status holding register 协同的访存队列。在乱序核中，store buffer 还与 load/store queue、内存消歧（memory disambiguation）深度耦合。不同厂商的缓冲深度与合并策略差异较大，具体以各自微架构官方资料为准。

## 十、小结

写缓冲以「先入队、后台刷」解耦写速率差异，是访存子系统的关键缓冲层。它同时带来三个必须理解的性质：入队即本核完成、读需转发、全局可见性另由一致性协议保证。
