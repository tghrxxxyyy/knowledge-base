# 写缓冲区基本结构

> 对应 Hennessy & Patterson《Computer Architecture: A Quantitative Approach》第5章。

## 一、背景与挑战
处理器核产生写操作的速度远高于内存子系统能接受的速度。若每条 store 都阻塞到写完成，流水线将严重停顿。写缓冲区（write buffer / store buffer）作为 FIFO 缓冲解耦二者。

## 二、核心原理
store 指令把地址与数据先放入写缓冲区即算「完成」，流水线继续；后台由缓冲控制器把条目逐个写向下级缓存/内存。读取时若地址命中缓冲中待写条目，需转发（store-to-load forwarding）最新值。

## 三、形式化与数学基础
设每周期产生 $w$ 条 store，内存吸收速率 $m$（$m<w$）。若无缓冲，停顿周期累积；有深度 $D$ 的写缓冲可吸收突发：
$$\text{可持续条件}: \sum_{t} w_t - m_t \le D$$

## 四、代码实现
```verilog
// 写缓冲条目
reg [63:0] wbuf_addr [0:DEPTH-1];
reg [63:0] wbuf_data [0:DEPTH-1];
reg        wbuf_valid[0:DEPTH-1];
// 入队
always @(posedge clk) if (store & !full) wbuf_valid[head] <= 1;
```

## 五、与其他技术对比
写缓冲解决「写速率不匹配」，读缓冲/预取解决「读延迟」，二者目标不同但都用于平滑访存。

## 六、常见误区
误以为 store 一旦入缓冲就对其他核可见。实际上它对其它核的可见性取决于一致性协议与写完成时机。

## 七、与开源书/权威来源对应
Hennessy & Patterson 第5章把写缓冲作为「处理器-内存速度差」的标准解法；CSAPP 第6章提及写缓冲对写命中延迟的隐藏。

## 八、面试题
问：写缓冲能否让 store 之后的 load 立刻看到值？答：能，通过 store-to-load 转发，但只对本地核；全局可见性另由一致性保证。

## 九、演进与趋势
现代采用合并写缓冲（write coalescing）与按缓存行归并，减少下级带宽压力。

## 十、小结
写缓冲用「先入队、后台刷」解耦写速率差异，是访存子系统的关键缓冲层。
