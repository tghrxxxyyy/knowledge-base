# Store Buffer与Spectre变体

> 对应 Kocher 2019（Spectre）与 Böhme 2018（Meltdown）相关披露。

## 一、背景与挑战
写缓冲本身不直接是 Spectre 主向量，但其「延迟可见」语义与乱序/推测执行结合，可被用于构造隐蔽信道或加剧侧信道。理解其边界对系统设计很重要。

## 二、核心原理
Spectre 主要利用分支预测与推测执行越权读；Meltdown 利用异常延迟（故障指令结果仍短暂驻留）越权读。写缓冲在其中的角色是：store 的可见时序可被微架构状态观察，从而辅助泄露或衡量推测窗口。

## 三、形式化与数学基础
设攻击者测量 store 刷出延迟 $\Delta t$。若存在隐藏状态 $S$（如推测标志），使得：
$$\Delta t = f(S)$$
则可通过计时推断 $S$，构成隐蔽信道：
$$Leak = H(\Delta t)$$

## 四、代码实现
```c
// 伪代码：用 store 完成时间作侧信道（示意，非可利用 exploit）
t0 = rdtsc();
shared[sensitive & 1] = 1; // 推测执行写
t1 = rdtsc();
// 测量 t1-t0 推断 sensitive 的一位
```

## 五、与其他技术对比
Spectre 借助预测器训练，Meltdown 借助异常延迟，写缓冲相关通道更偏「时序隐蔽信道」，三者属同一微架构侧信道家族。

## 六、常见误区
误认为打补丁后写缓冲不再相关。缓解措施（如屏障、序列化）会改变其时序特征，但底层延迟可见性仍是分析对象。

## 七、与开源书/权威来源对应
Kocher et al. 2019 的 Spectre 论文；Böhme et al. 2018 的 Meltdown 论文；Intel SDM 后续增订了推测执行限制。

## 八、面试题
问：写缓冲与 Meltdown 关系？答：Meltdown 主要借故障延迟而非写缓冲，但微架构中 store 时序可被用于构造与测量隐蔽信道。

## 九、演进与趋势
硬件引入推测限制、数据采样保护（如 Intel MDS 缓解），并在上下文切换时刷新推测状态，缩小此类通道。

## 十、小结
写缓冲的延迟可见性本身非漏洞，但与推测执行结合会扩大侧信道面，需在安全分析中纳入考量。
