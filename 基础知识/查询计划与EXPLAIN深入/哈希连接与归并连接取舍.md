# 哈希连接与归并连接取舍

> 对应 Garcia-Molina《Database Systems: The Complete Book》第13章 Join Algorithms 与 cmu-db/15445-course 讲义。

## 一、背景与挑战
等值连接是大表分析查询的瓶颈。哈希连接与归并连接均能避免嵌套循环的平方级代价，但适用前提不同，优化器需据数据特征取舍。

## 二、核心原理
哈希连接分两阶段：构建阶段把较小输入（build 表）按连接键哈希装入内存哈希表；探测阶段扫描较大输入（probe 表），对每行哈希后在表中找匹配。归并连接要求两输入在连接键上已排序，随后类似归并排序的两指针扫描合并匹配行，能优雅地处理两边各有序的情况。

## 三、形式化与数学基础
哈希连接期望代价（内存足够）：
$$ C = B_{build} + B_{probe} $$
即各扫描一遍。归并连接代价：
$$ C = B_R + B_S $$
但前提是已排序，否则需额外排序代价 $O(N \log N)$ 页级近似 $B \log B$。

## 四、代码实现
```sql
-- PostgreSQL 中可用 EXPLAIN 看到 Hash Join / Merge Join
EXPLAIN SELECT * FROM lineitem l JOIN orders o
ON l.order_id = o.id WHERE o.total > 1000;
```
MySQL 8.0 在等价连接中已引入哈希连接，EXPLAIN 显示 `Hash`。

## 五、与其他技术对比
哈希连接对内存敏感，build 表过大需分桶落盘（Grace Hash Join）。归并连接对倾斜数据更稳，且输出天然有序利于上层聚合。嵌套循环在大表无索引时最差。

## 六、常见误区
认为哈希连接总是最快。若两表都已按连接键排序，归并连接省去构建哈希与排序 overhead 反而更优。认为哈希连接不需要排序——内存不足时仍需部分落盘。

## 七、与开源书/权威来源对应
Garcia-Molina 第13章详述 Grace Hash Join 与 Sort-Merge Join；cmu-db/15445-course 第10讲对比三者 IO 复杂度。

## 八、面试题
问：归并连接的前提？答：两关系在连接属性上排序（或建有有序索引）。问：哈希连接内存不足怎么办？答：分桶写盘，分批构建探测（Grace Hash）。

## 九、演进与趋势
 Radix Hash Join 通过分区降低内存压力；并行哈希与向量化探测成为现代引擎标配（如 Vectorwise、ClickHouse）。

## 十、小结
哈希连接适合内存充足的大表等值连接，归并连接适合已排序输入，二者以 IO 与内存为取舍核心。
