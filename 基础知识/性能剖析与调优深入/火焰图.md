# 火焰图

> 对应 Brendan Gregg Flame Graphs 方法论（Folded Stacks）。

## 一、背景与挑战
采样剖析产生海量栈样本，文本/表格难以直觉呈现。火焰图把调用栈按宽度编码耗时，让热点一眼可见，并支持交互式下钻。

## 二、核心原理
- 折叠栈（Folded stacks）：每行 `funcA;funcB;funcC count`，分号分隔栈帧、空格后跟样本数。
- 绘图：栈底为根，向上展开子调用；x 轴宽度 = 样本占比（注意 x 轴无序、按字母/合并排序）。
- 颜色无语义（默认随机），高度 = 栈深度。
- 差分火焰图：两个 folded 文件相减，凸显回归。

## 三、形式化 / 数学基础
- 每个样本权重 $w_i$ 代表在栈帧上的停留时间。
- 函数 $f$ 总宽度比例 $p_f = \frac{\sum_{i: f \in stack_i} w_i}{\sum_i w_i}$。
- 递归会自折叠；相同栈合并计数。
- 差分：$d_f = p_f^{new} - p_f^{old}$，负值（收窄）常显示为蓝，正值（变宽）为红。

## 四、代码实现
```bash
# 典型生成流程（perf + FlameGraph 脚本）
perf record -F 99 -a -g -- sleep 30
perf script | ./stackcollapse-perf.pl > out.folded
./flamegraph.pl out.folded > cpu.svg
```

## 五、与其他技术对比
- gprof：插桩、侵入、仅用户态、无生产可用。
- 文本热点表：信息密度低，无法看调用上下文。
- 差分散点（scatter）：看波动，火焰图看结构。

## 六、常见误区
- 误认为 x 轴是时间顺序（实际无序，仅宽度有意义）。
- 用颜色判断"快慢"（颜色无语义）。
- 采样频率过低导致栈不完整（需 -g 展开）。

## 九、演进与趋势
差值火焰图、I/O 火焰图、off-CPU 火焰图、eBPF 实时火焰图使生产长期可观测。

## 十、小结
火焰图用折叠栈 + 宽度编码，把采样剖析转成可下钻的热点结构，是性能沟通的通用语言。
