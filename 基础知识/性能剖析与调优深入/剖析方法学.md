# 剖析方法学

> 对应 Brendan Gregg 性能方法论（USE 方法、方法论分层）。

## 一、背景与挑战
性能问题往往表现为延迟高、吞吐低、资源耗尽，但根因可能隐藏在 CPU、内存、I/O、锁或网络任一环节。缺乏方法论时容易"瞎调"，在错误方向浪费时间。剖析方法学的目标是建立可复用的定位框架，把"感觉慢"转化为可量化、可归因的指标。

## 二、核心原理
- USE 方法：对每个资源检查 Utilization（利用率）、Saturation（饱和度）、Errors（错误）。
- 延迟分解（Latency Decomposition）：把一次请求拆成各阶段耗时的火焰图/水线。
- 自上而下与自下而上结合：先业务指标，再系统资源，再微架构。
- 三大黄金信号：延迟、流量、错误率、饱和度（RED/USE 衍生）。

## 三、形式化 / 数学基础
- 利用率 $U = \frac{T_{busy}}{T_{total}} \in [0,1]$。
- Little 定律：$L = \lambda W$，其中 $L$ 为系统内平均请求数，$\lambda$ 为到达率，$W$ 为平均驻留时间。
- 饱和度可建模为排队长度 $Q = \max(0, \text{arrival} - \text{service})$。
- 阿姆达尔定律（并行加速比）：$S(n)=\frac{1}{(1-p)+p/n}$，$p$ 为可并行比例。

## 四、代码实现
```python
import time

def profile(fn, *args, repeat=1000):
    t0 = time.perf_counter()
    for _ in range(repeat):
        fn(*args)
    dt = time.perf_counter() - t0
    print(f"{fn.__name__}: {dt/repeat*1e6:.2f} us/call")
    return dt
```

## 五、与其他技术对比
- 日志埋点：侵入式、可控但开销大、覆盖有限；剖析：非侵入采样、覆盖全但需符号。
- 基准测试：回答"有多快"；剖析：回答"为什么慢"。两者互补。
- 单点 printf：快速但不成体系，无法发现偶发长尾。

## 六、常见误区
- 过早优化：在未定位瓶颈前改代码。
- 只看平均值：长尾 P99 才是用户体验。
- 在开发机结论外推到生产（数据量、并发、NUMA 差异）。

## 九、演进与趋势
eBPF 让内核级无侵入剖析成为常态；持续剖析（continuous profiling）把采样延伸到生产长期运行；火焰图标准化（Folded stacks）促进跨语言聚合。

## 十、小结
剖析方法学是用 USE + 延迟分解 + 黄金信号建立"先测量、后优化"的纪律，任何调优都应从可量化指标出发。
