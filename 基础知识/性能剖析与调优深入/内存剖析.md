# 内存剖析

> 对应 Brendan Gregg 内存分析法与 Valgrind/pprof 工具链。

## 一、背景与挑战
内存问题包括泄漏（持续增长）、碎片（分配失败但总量充足）、高常驻集（RSS）、以及 GC 压力。定位需区分堆、栈、匿名映射、文件缓存（page cache）。

## 二、核心原理
- 分配剖析：按调用栈统计分配字节/次数（heap profiling）。
- 泄漏检测：对比不同时间点的存活对象集合。
- RSS 拆解：匿名、文件映射、共享库。
- 工作集（working set）：实际被频繁访问的物理页集合。

## 三、形式化 / 数学基础
- 驻留集大小 $RSS = \sum \text{resident pages} \times 4\text{KB}$。
- 碎片率 $\phi = 1 - \frac{\text{largest free block}}{\text{total free}}$。
- 分配速率 $\lambda_a = \frac{\text{alloc\_bytes}}{T}$；GC 压力与 $\lambda_a$ 正相关。
- 工作集模型（Denning）：$\text{WS}(t,\tau)=\bigcup_{i=t-\tau}^{t} \text{referenced pages}_i$。

## 四、代码实现
```go
// Go 自带堆剖析：import _ "net/http/pprof"
// 运行后执行：go tool pprof http://localhost:6060/debug/pprof/heap
func leakDemo() {
    var hold [][]byte
    for i := 0; i < 1e6; i++ {
        hold = append(hold, make([]byte, 1024)) // 持续增长不释放
    }
}
```

## 五、与其他技术对比
- Valgrind massif：精确但极慢（10~50x），适合线下。
- pprof / jemalloc profile：低开销，适合生产采样。
- /proc/<pid>/smaps：瞬时快照，无历史趋势。

## 六、常见误区
- 把 page cache 增长当成泄漏（可被回收）。
- 只看 VIRT 不看 RSS。
- 误把 GC 语言"未达阈值未回收"当泄漏。

## 九、演进与趋势
eBPF 内存事件追踪（oomkill、malloc 栈）；硬件内存带宽剖析（Intel PCM）；NUMA 感知剖析。

## 十、小结
内存剖析靠分配采样与存活对比定位泄漏/碎片，并用 RSS 拆解区分匿名与缓存。
