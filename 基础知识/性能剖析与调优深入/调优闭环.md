# 调优闭环

> 对应性能工程的 PDCA（计划-执行-检查-处理）闭环。

## 一、背景与挑战
单次调优常因环境变化而失效。需要把"假设→改动→度量→验证"变成可重复闭环，避免凭直觉反复试错。

## 二、核心原理
- 假设驱动：基于剖析提出可证伪假设（"锁竞争是瓶颈"）。
- 单一变量：每次只改一个参数，保证因果可归因。
- 度量验证：用同一基准/剖析对比前后。
- 回归防护：把关键指标纳入监控与 CI。

## 三、形式化 / 数学基础
- 改进幅度 $\Delta = \frac{M_{after}-M_{before}}{M_{before}}$。
- 统计显著性：t 检验 $t = \frac{\bar x_1-\bar x_2}{s_p\sqrt{1/n_1+1/n_2}}$。
- 目标阈值：当 $|\Delta| < \epsilon$（噪声带）视为无效果。
- 多目标权衡：帕累托前沿上选满足 SLA 的最低成本点。

## 四、代码实现
```python
def tune_loop(params, budget=20):
    best = None
    for _ in range(budget):
        cfg = pick(params)            # 单变量扫描
        metric = run_benchmark(cfg)    # 同一基准
        if best is None or metric < best.metric:
            best = (cfg, metric)
        record(metric)                 # 写监控/日志
    return best
```

## 五、与其他技术对比
- 一次性调优：快但不可持续；闭环：可靠但需基建。
- A/B 实验：面向产品；调优闭环：面向系统指标。
- 自动调参（autotuning）：把闭环算法化（贝叶斯优化）。

## 六、常见误区
- 同时改多个参数无法归因。
- 只看峰值不看长尾与稳定性。
- 忽略改动带来的副作用（如增大缓存致 GC 变慢）。

## 十、小结
