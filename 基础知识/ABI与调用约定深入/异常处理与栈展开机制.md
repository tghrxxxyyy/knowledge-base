# 异常处理与栈展开机制

> 对应 System V AMD64 ABI（ unwind 规范）；Itanium C++ ABI 异常条款。

## 一、背景与挑战
抛出异常须沿调用链回退多帧，恢复每个函数的清理代码与寄存器状态。需要可调用的元数据描述每帧如何展开。

## 二、核心原理
编译器为每个函数生成 .eh_frame 描述符（基于 DWARF CFI），记录本帧如何在异常点恢复 caller 的 rsp/rbp/寄存器。libunwind 据此逐步 unwind：取返回地址、找对应 FDE、执行恢复指令、调用 landing pad。

## 三、形式化与数学基础
展开序列是一串状态转移：
$$state_{i+1} = unwind(CFI_i, state_i)$$
每步恢复 $\{rsp, rbp, rip\} \to caller$。匹配 catch 类型后停止并跳 landing pad，否则继续直至终止（std::terminate）。

## 四、代码实现
```c
// 走查展开（libunwind 风格）
unw_cursor_t c; unw_init_local(&c, &uc);
do {
    unw_step(&c);             // 退一帧
} while (!matches_handler(&c));
// 执行对应 landing pad
```

## 五、与其他技术对比
setjmp/longjmp 是手动、无类型的安全网；C++ 异常自动但需 unwind 表，零开销异常（Zero-cost）仅在抛时才付代价。

## 六、常见误区
1. 以为异常不耗性能——表占用空间、抛出慢。
2. 析构在栈展开中必调用，资源泄漏靠 RAII。
3. 剥离 unwind 信息致异常崩溃（strip --strip-unwind）。

## 七、与开源书/权威来源对应
System V AMD64 unwind 节；Itanium C++ ABI；libunwind 源码。

## 八、面试题
问：栈展开如何工作？eh_frame 作用？零开销异常含义？

## 九、演进与趋势
紧凑 unwind 格式（compact unwind）加速 macOS；Windows 用不同 UNWIND_INFO 体系。

## 十、小结
异常处理依赖 CFI 元数据做栈展开，把控制流安全回退到匹配的处理器。
