# 参数传递与寄存器传参细节

> 对应 Bryant & O'Hallaron《Computer Systems: A Programmer's Perspective》第 3.7 节；System V AMD64 ABI（x86-64 psABI）第 3.2.3 节「Passing of Arguments」；Intel SDM 卷 1 调用约定章节。

## 一、背景与挑战

函数参数不只是整数，还有浮点、结构体、向量、long double 等。ABI 必须为每一类规定使用哪些寄存器、按什么顺序、落在栈上何处，并定义内存对齐与「一个参数跨多个寄存器」时的拆分规则。若分类不一致，链接器不会报错，但运行时会取到错位数据——这是最隐蔽的 ABI bug 之一。参数传递因此是跨编译器、跨语言互调的精确契约，也是手写内联汇编与 JIT 代码生成器必须严格遵守的协议。

## 二、核心原理

System V AMD64 用一套**分类（classification）**算法给每个参数定类。对参数逐个独立地：INTEGER 类（整型、指针、枚举）依次用 rdi, rsi, rdx, rcx, r8, r9；SSE 类（float/double 及向量）依次用 xmm0..xmm7（新规范扩展至 xmm15）；MEMORY 类（如超过 16 字节且不能拆分的聚合、含 MEMORY 片的 union）则经栈传递——调用方分配空间，把指针放入整数寄存器序。聚合类型若可拆成两个 eightbyte 字段，就分别落入整数/SSE 寄存器；否则整体按 MEMORY 走栈。整数与 SSE 使用**两套独立计数游标**，互不占用对方名额。long double 属 X87 类，占用专用的 x87 浮点栈寄存器，且会触发后续对齐约束。

## 三、形式化与数学基础

分类函数 $class(arg)$ 的简化映射：

$$
class = \begin{cases}
INTEGER & \text{整型/指针/枚举} \\
SSE & \text{float / double / 向量} \\
MEMORY & \text{过大聚合或含数组/不可拆} \\
X87 & \text{long double（80 位，x87 栈）}
\end{cases}
$$

寄存器分配用两个游标 $i$（整数，初值 0）与 $j$（SSE，初值 0）推进，目标槽：

$$
slot(arg) = \begin{cases}
[rdi..r9][i],\ i\mathrel{+}=1 & class=INTEGER \land i<6 \\
[xmm0..xmm7][j],\ j\mathrel{+}=1 & class=SSE \land j<8 \\
stack[k],\ k\mathrel{+}=1 & \text{否则}
\end{cases}
$$

注意一个 long double 参数占用一整个 x87 寄存器槽；当一个参数被拆分为多个 eightbyte 时，多个寄存器被同时占用，分类必须递归到每个 eightbyte 再整体判定。

## 四、代码实现

```asm
# 混合参数 f(int, double, int)
mov  edi, a        # INTEGER -> rdi
movsd xmm0, b      # SSE      -> xmm0
mov  esi, c        # INTEGER -> rsi（整数游标独立推进到第二项）
call f
# 第 7 个及以后的整数参数才压栈，右到左
```

```c
/* 一个会被拆进 rdi + xmm0 的结构体参数 */
typedef struct { long a; double b; } Pair;
void g(int x, Pair p, int y);  /* x:rdi, p.a:rsi, p.b:xmm0, y:rdx */

/* 超过 16 字节的聚合则退化为指针传参 */
typedef struct { long a,b,c; } Triple;
void h(Triple t);              /* 实际传入指向 t 的隐式指针 */
```

## 五、与其他技术对比

| 维度 | 32 位 cdecl | x86-64 SysV | Microsoft x64 |
|------|-------------|-------------|----------------|
| 整数传参 | 全栈（右到左） | rdi..r9 后栈 | rcx,rdx,r8,r9 后栈 |
| 浮点传参 | 栈 | xmm0..xmm7（独立） | xmm0..xmm3 |
| 栈对齐 | 4 字节 | 16 字节（call 前 rsp%16==0） | 16 字节 + home space |
| 聚合拆分 | 逐字段压栈 | 按类拆入寄存器 | 大多经栈 |

## 六、常见误区

1. 以为浮点也占整数寄存器序——实际走**独立**的 xmm 计数，二者名额不共享。
2. 大结构体按值传参导致隐式拷贝与栈空间膨胀，甚至触发对齐问题。
3. 在可变参数场景下，浮点参数仍按 SSE 传递，但 `va_arg` 的类型必须显式声明为 `double`，否则取址错位。
4. 忽略 call 前 `rsp` 必须 16 字节对齐，否则 SSE 指令可能触发 #GP 异常。
5. 误以为参数顺序是全局连续编号——整数与 SSE 各自从 0 计数，中间穿插不会互相「填空」。

## 八、面试题

1. 浮点参数用什么寄存器？答：xmm0..xmm7，与整数 rdi..r9 使用相互独立的计数游标。
2. 大结构体如何传参？答：若分类含 MEMORY 类，则在栈上分配并用指针传入整数寄存器序；若可拆为 ≤2 个 eightbyte 则拆入寄存器。
3. 为何分类规则重要？答：它决定了二进制层面每个字节落在哪个寄存器/栈槽，是跨编译器、跨语言调用的唯一契约。
4. long double 与 double 传参有何不同？答：double 走 SSE（xmm），long double 走 X87 类（x87 栈寄存器），占用与推进规则不同。

## 九、演进与趋势

AVX/AVX-512 把 SSE 分类扩展为对 256/512 位向量（如 `__m256`）的多 eightbyte 拆分（SSEUP 连续填充）；Windows 的 vectorcall 等约定则进一步细化向量传参。ABI 工作组持续修订这些细节，但核心「分类 + 双游标」框架保持稳定，具体边界以官方最新 psABI 文档为准。

## 十、小结

参数传递是 ABI 的「门面契约」：它用分类算法把每一种类型映射到确定的寄存器或栈槽，并用整数/SSE 双游标保证互不干扰。理解这套机制，是读懂反汇编、排查跨语言调用错位、以及写出正确内联汇编的前提。
