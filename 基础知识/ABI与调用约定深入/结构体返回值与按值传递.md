# 结构体返回值与按值传递

> 对应 Bryant & O'Hallaron《Computer Systems: A Programmer's Perspective》第 3.7 节；System V AMD64 ABI（x86-64 psABI）第 3.2.3 节「Returning of Structures」；Intel SDM 卷 1 调用约定章节。

## 一、背景与挑战

C/C++ 允许结构体按值返回与按值传参，但这在二进制层面是个麻烦事：调用方渴望「拿到一个完整对象」，而通用寄存器只有 64 位宽，栈帧上的对象又该由谁分配、谁释放？如果 ABI 不给出精确规则，不同编译器生成的函数根本无法互相链接调用。核心矛盾是：既要让「按值语义」对程序员透明，又要在寄存器/内存之间做出唯一确定的布局约定，并明确返回对象的内存由谁负责、在何处构造。一旦规则错位，轻则链接失败，重则运行时取到错位字段——这类 bug 在反汇编里极难定位。

更具挑战性的是「部分走寄存器」的情形：一个结构体可能一半字段适合寄存器、一半必须走内存。ABI 必须给出一个可机械执行的判定算法，而不是留给人去判断，否则同一份源码在不同编译器下会生成互不兼容的接口。

## 二、核心原理

System V AMD64 ABI 用一个统一的「分类（classification）」算法处理所有聚合类型（struct/union/class/array）。算法把对象按 8 字节（eightbyte）切片，对每一片递归归类为 INTEGER / SSE / SSEUP / X87 / X87UP / COMPLEX_X87 / NO_CLASS / MEMORY 之一。对**返回值**的关键结论是：如果整个对象的分类结果里**含有 MEMORY 类**，或对象大到寄存器装不下，调用方就必须在自己的栈帧上分配返回缓冲区，并把该缓冲区地址作为**隐藏的第一个参数**经由 rdi 传入；被调函数把结果写到这里，最后把同一地址放回 rax 让调用方取回。若不含 MEMORY 类（通常是 ≤16 字节且可拆为整/浮字段的小对象），结果直接经 rax（必要时 rdx、xmm0、xmm1）返回。要注意的是，隐藏指针占用了 rdi，因此一个 `struct Big f(int a)` 实际是 `f(Big* hidden, int a)`——`a` 落在 rsi 而非 rdi。

分类算法中的几条合并规则决定了最终结果：若某个 eightbyte 的不同字段分别落入 INTEGER 与 SSE，合并结果为 INTEGER（整类优先）；若寄存器数量不足以容纳所有 eightbyte，多余部分转为 MEMORY；而一旦出现 MEMORY 类，整个对象就走隐藏指针（不做「部分寄存器 + 部分内存」的混合返回）。这最后一条规则极大简化了实现——要么全寄存器、要么全内存，回避了最复杂的混合场景。

## 三、形式化与数学基础

设聚合对象 $O$ 大小为 $|O|$，按 8 字节切片得 $n = \lceil |O|/8 \rceil$ 片，每片类别为 $c_i$。返回值位置由分类决定：

$$
ret\_loc(O) = \begin{cases}
\{rax, rdx, xmm0, xmm1\} & \text{若 } \forall i\le n,\ c_i \neq MEMORY \text{（最多 2 个 eightbyte 经寄存器）} \\[4pt]
hidden\_ptr\ (rdi) & \text{否则}
\end{cases}
$$

走隐藏指针路径时，调用方与被调满足：

$$
[rsp]=caller\_buffer,\quad rax = ptr = rdi,\quad *ptr = O_{result}
$$

分类是**按片**而非整体：一个 16 字节的 `struct {long a; double b;}` 被切成 INTEGER 片 + SSE 片，走寄存器返回（rax + xmm0）；而 `struct {long a; long b; long c;}` 共 24 字节、含 3 个 eightbyte，超出寄存器可承载数，整体走隐藏指针。包含数组、或任一 eightbyte 落入 MEMORY 的 union 同样走隐藏指针。

可以把判定条件再压缩成两句：其一，「eightbyte 数 ≤ 2 且无 MEMORY 类」⇒ 寄存器返回；其二，「其余情况」⇒ 隐藏指针。由于 x86-64 允许的返回寄存器组（rax、rdx、xmm0、xmm1）刚好能承载两个 eightbyte，尺寸上界与类别条件是耦合的。这也解释了一个常见现象：把结构体从 16 字节改为 17 字节，返回方式会突然从寄存器变成隐藏指针，性能随之出现台阶式变化——这不是编译器行为诡异，而是 ABI 规则的直接后果。

## 四、代码实现

```asm
# 大结构体（>16 字节）按值返回，调用方视角（x86-64）
sub   rsp, 40              ; 调用方在栈上分配返回缓冲
mov   rdi, rsp            ; 隐藏指针作为第 1 个参数
call  make_vec            ; 被调把结果写到 [rdi]
mov   rax, [rsp]          ; 此后 [rsp] 即返回的结构体，rax 也指向它
add   rsp, 40
```

```c
/* 走寄存器返回的小结构体示例 */
typedef struct { long a; double b; } Pair;     /* 16 字节：INTEGER + SSE */
Pair f(void) { return (Pair){.a=1, .b=2.0}; }  /* 返回在 rax + xmm0 */

/* 走隐藏指针的大结构体示例 */
typedef struct { long a, b, c; } Triple;       /* 24 字节 -> rdi 隐藏指针 */
Triple g(void);                                 /* 调用方分配，地址经 rdi 传入 */

/* 边界演示：仅差一个字节，返回方式即从寄存器切到隐藏指针 */
typedef struct { long a, b; }   S16;            /* 16 字节 -> rax + rdx */
typedef struct { long a, b; char c; } S17;      /* 24 字节（含填充）-> 隐藏指针 */
```

第三段是排查性能异常的实用工具：当某接口改动后调用开销突然上升，先检查「结构体尺寸是否越过了 16 字节门槛」，往往能立刻定位原因。同样的门槛也适用于按值传参：参数分类与返回值分类共用同一套算法，因此大结构体作参数同样会经由栈或指针传递。

## 五、与其他技术对比

| 维度 | 小结构体（寄存器返回） | 大结构体（隐藏指针） | C++ RVO / 复制消除 | Windows x64 规则 |
|------|------------------------|----------------------|---------------------|------------------|
| 拷贝次数 | 0（直接构造于寄存器） | 1（被调写回调用方缓冲） | 编译期消除，0 拷贝 | 依尺寸二分 |
| 调用方开销 | 无额外栈分配 | 需分配返回缓冲 | 无 | 同左 |
| ABI 负担 | 分类规则复杂 | 隐藏指针约定 | 约定不变，靠优化 | 规则更简单 |
| 跨语言互调 | 完全依赖 psABI | 需双方遵守同一约定 | 仅限同编译器 | 与 System V 不兼容 |

对照 Windows x64：聚合类型若 ≤8 字节（能塞进一个寄存器）则返回在 rax，否则一律走隐藏指针，规则与 System V 不同，进一步说明「按值返回」没有跨平台统一的实现。这意味着同一份头文件在两个平台上编译出的目标文件无法直接链接，跨平台库必须显式隔离此类接口。

## 六、常见误区

1. 以为「按值返回大结构体」真的零拷贝——编译器暗中插入了隐藏指针，发生一次写回。
2. 忽略返回对象的**对齐要求**：带 `alignas(16)` 的结构体即便 ≤16 字节也可能因对齐而走 MEMORY 类。
3. 跨 ABI 边界（System V 与 Microsoft x64）返回同一结构体，因分类规则不同导致二进制不兼容。
4. 误以为 rdx 总能跟着 rax 用：只有第二片确为 INTEGER/X87 类时才会用 rdx。
5. 忽略隐藏指针对参数寄存器序的「挤占」：一旦走隐藏指针，所有显式参数整体后移一个寄存器位。
6. 以为 16 字节是唯一门槛：对齐要求、union 的 MEMORY 片、含数组的成员都会额外触发隐藏指针。
7. 在返回语句中依赖「先构造再拷贝」的语义：RVO 虽在多数场景适用，但 ABI 层面仍可能发生写回，对性能敏感的代码应传指针而非按值返回。
8. 忽略 `sret` 属性在 LLVM IR 层的体现：它决定了函数签名与调用方栈帧布局，调试时若忽略会误读寄存器。

## 八、面试题

1. 什么情况下结构体按值返回会走隐藏指针？答：分类含 MEMORY 类或对象过大（超过寄存器可承载的 eightbyte 数）时，调用方分配缓冲并经 rdi 传隐藏指针。
2. `struct {int x; int y;}` 与 `struct {int x; double y;}` 返回方式有何不同？答：前者两片皆 INTEGER，走 rax+rdx；后者 INTEGER+SSE，走 rax+xmm0。
3. `struct {long a,b,c;}`（24 字节）如何返回？答：3 个 eightbyte 超出寄存器承载，整体走隐藏指针，调用方分配缓冲、地址经 rdi 传入。
4. C++ 的 RVO 是否改变了 ABI？答：不改变，RVO 是编译期把返回值直接构造到目标对象的优化，底层仍遵守同一套分类约定。
5. 隐藏指针如何影响显式参数的寄存器分配？答：它占用 rdi，使所有显式参数整体后移一位（首个参数落到 rsi）。
6. 为什么两个平台的同一结构体返回方式可能不同？答：System V 用「eightbyte 分类」，Windows x64 用「尺寸二分」，判定逻辑不同故结果不同。

## 九、演进与趋势

C++17 把复制消除从「允许」升级为「强制」（mandatory RVO），在一些场景彻底消除临时对象，降低了对隐藏指针路径的使用频率；但 ABI 本身的分类规则自 2000 年代确定后基本稳定。随着 AVX/AVX-512 引入，psABI 增加了对 256/512 位向量返回的分类（如 `AVX` / `AVX512` 类），规则持续细化但保持向后兼容。具体边界以官方最新 psABI 文档为准。

另一条演进方向是「按引用返回」逐渐成为高性能接口的默认选择：既然按值返回大对象必然带来一次写回，现代 C++ 与 Rust 代码更倾向于让调用方提供输出位置（`out` 参数或 `&mut`），把内存分配与生命周期控制显式化，从而绕开分类规则的性能不确定性。

## 十、小结

结构体按值返回的本质，是 ABI 用一套「按 8 字节切片分类」的算法，在寄存器直传与隐藏指针写入之间做出确定选择。程序员看到的「按值语义」背后，是一份精确到字段类别的内存安排契约。理解它有助于排查跨语言调用、结构体大小边界以及对齐相关的诡异 bug。

三条记忆要点：门槛是「两个 eightbyte 且无 MEMORY 类」（越界即走指针）、隐藏指针占用 rdi 从而挤占所有参数位、平台 ABI 不同则结果不同（不可混链）。
