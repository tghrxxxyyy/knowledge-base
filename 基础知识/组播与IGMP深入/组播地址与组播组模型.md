# 组播地址与组播组模型

> 对应 RFC 1112 (IGMPv1) 与 RFC 4607 (SSM) 背景。

## 一、背景与挑战
一对多、多对多通信（直播、视频会议）若用单播会重复占用带宽，广播又无法跨子网且打扰无关主机。IP 组播以「组」抽象让接收者按需加入，高效分发到多个接收者。

## 二、核心原理
IPv4 组播地址属 D 类（224.0.0.0/4），其中 224.0.0.0/24 为本地链路保留（如 224.0.0.1 全主机、224.0.0.2 全路由器）。接收主机通过 IGMP 加入某组，路由器据此建立组播转发状态；任意源发往组地址的报文按需复制转发。

## 三、形式化与数学基础
组播转发状态常以 (S, G) 或 (*, G) 表示：
$$ (*, G): \text{任意源到组 } G $$
$$ (S, G): \text{特定源 } S \text{ 到组 } G $$
组地址范围：
$$ 224.0.0.0 \le addr \le 239.255.255.255 $$
其中 239.0.0.0/8 为管理范围（私有）组播。

## 四、代码实现
Linux 加入组播组（Python）：
```python
import socket, struct
s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
mreq = struct.pack('4s4s', socket.inet_aton('224.0.0.251'), socket.inet_aton('0.0.0.0'))
s.setsockopt(socket.IPPROTO_IP, socket.IP_ADD_MEMBERSHIP, mreq)
```
查看组成员：
```bash
ip maddr show
```

## 五、与其他技术对比
广播（255.255.255.255）打扰所有主机且受限网段；单播重复发送浪费源带宽；组播仅发给加入者且网络内复制，效率最高但需路由协议支持。

## 六、常见误区
误区一是认为组播地址可当源地址，D 类仅作目的地址。误区二是组播能跨公网任意传播，实际需 PIM/MBGP 等维护且运营商常限。

## 七、与开源书/权威来源对应
RFC 1112 定义主机组播扩展与 IGMPv1；RFC 4607 定义 SSM；Tanenbaum 第5章介绍组播寻址。

## 八、面试题
问：224.0.0.1 与 224.0.0.2 区别？答：前者表示子网内所有主机，后者表示子网内所有路由器，常用于邻居发现类协议。

## 九、演进与趋势
SSM（RFC 4607）简化模型，只收指定源；IPv6 组播（FF00::/8）内建且地址结构更清晰；BIER 等新方案探索无状态组播转发。

## 十、小结
IP 组播以 D 类地址与组概念实现高效一对多分发，IGMP 管理主机成员关系，是流媒体与状态同步的基础技术。
