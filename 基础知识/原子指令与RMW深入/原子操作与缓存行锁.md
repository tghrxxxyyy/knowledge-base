# 原子操作与缓存行锁

> 对应 Intel SDM Vol.3A「Locked Atomic Operations / Bus Locking」与 Hennessy & Patterson《Computer Architecture》中一致性协议对原子性的支撑。

## 一、背景与挑战

原子 RMW 必须在物理层面阻止其它核同时修改同一数据。早期 x86 用 `LOCK#` 信号锁住整个前端总线，代价极高：所有处理器、所有内存事务都要停下来等。随着片上多核与缓存层次的出现，锁总线变成不可接受的开销。现代实现改为「锁缓存行」：只让包含目标数据的缓存行进入独占态，把竞争局部化到那一条 64 字节的行上。

问题随之而来：如果目标数据跨了两条缓存行、或者所在的物理内存根本不可缓存（MMIO、某些非对齐区域），缓存行锁就无法覆盖，此时硬件只能退回到总线锁。理解这条退化路径，是写出低开销原子代码的关键。

## 二、核心原理

`LOCK` 前缀使后续指令在执行期间取得目标缓存行的独占所有权。实现机制是：

1. 处理器发出「读-改-写」请求，一致性协议（MESI/MESIF/MOESI）先把该行在本核缓存中提升为 **M（Modified）** 或独占态；
2. 若该行在他核缓存中为 S（Shared）或 E，则先广播 Invalidate，等待确认；
3. 在持有独占态期间，本核**延迟响应**其它核对同一行的探测（snoop），直到 RMW 完成；
4. 写入以 M 态完成，天然满足原子性——因为整个系统的其他观察者在同一时刻都看不到该行。

关键点：**原子性来自「独占权 + 对探测的延迟响应」**，而不是来自「禁止一切内存访问」。因此锁缓存行只影响与该行相关的核，而非全系统。

当以下条件不满足「可用缓存行锁覆盖」时，处理器退化为总线锁（x86 上表现为 `LOCK#`/split-lock 检测）：

- 操作数跨越两条及以上缓存行（对齐的 8 字节访问通常安全，未对齐的则可能跨界）；
- 地址不可缓存（UC 类型内存，如 MMIO）；
- 访问跨页且在页表层面不连续。

## 三、形式化与数学基础

设原子操作作用于地址 $a$，其位于缓存行 $C(a)$。缓存行锁保证在任意时刻 $t$：

$$\forall t:\; \left|\{\,p \;:\; p \text{ 在 } t \text{ 时刻以独占态持有 } C(a)\,\}\right| \;\le\; 1$$

由此，对该行内任意字节的 RMW 序列在系统层面不可分。相比之下，总线锁施加的约束是全系统级的：

$$\forall t:\; \neg\exists\, \text{other bus transaction during } [t, t+\Delta]$$

它把所有无关流量一并阻塞。由于 $\Delta$ 与前端总线/互连的仲裁延迟同阶，总线锁的开销比缓存行锁高出若干数量级。

缓存行大小 $B$ 通常为 64 字节，故一次对齐的 8 字节 RMW 需要独占 $B$ 字节的全部权限，这就是「伪共享（false sharing）」的根源：逻辑上无关的两个变量若共用一行，仍会互相争用。

## 四、代码实现

```asm
; 缓存行内原子自增（结果被忽略）
        lock inc qword ptr [counter]     ; 优先走缓存行锁

; 跨缓存行的 RMW 会触发 split lock / 总线锁
        lock add qword ptr [misaligned], 1
```

```c
/* 伪共享：同一缓存行内的两个独立计数器互相拖累 */
struct { _Atomic long a; _Atomic long b; } shared;

/* 修复：把各自填充到独占缓存行 */
#define CACHELINE 64
struct padded {
    _Atomic long v;
    char pad[CACHELINE - sizeof(long)];
} __attribute__((aligned(CACHELINE)));
```

Linux 内核提供 `cache_line_size()` 与 `____cacheline_aligned`；用户态可用 `std::hardware_destructive_interference_size` 获取建议值（以工具链实现为准）。

## 五、与其他技术对比

| 维度 | 缓存行锁 | 总线锁 | 软件互斥量（futex） |
| --- | --- | --- | --- |
| 作用范围 | 单条缓存行 | 整个内存子系统/互连 | 临界区（任意大小） |
| 开销量级 | 数十周期 | 数百至上万周期 | 无争用时数次原子操作 |
| 是否阻塞无关流量 | 否 | 是 | 否 |
| 触发条件 | 大多数对齐 RMW | 跨行/非缓存内存/未对齐 | 调用方显式加锁 |
| 可表达语义 | 单指令 RMW | 单指令 RMW | 任意多指令临界区 |
| 公平性 | 无保证 | 无保证 | 取决于实现（可做到 FIFO） |

## 六、常见误区

- **「`LOCK` 一定锁总线」**：现代实现优先缓存行锁，总线锁仅在无法用缓存行覆盖时触发；某些平台还会对未对齐的 split lock 施加惩罚或抛异常。
- **「原子操作只影响目标变量」**：它独占整条缓存行，同行的其它变量也被牵连，这就是伪共享。
- **「加了 `alignas(8)` 就一定不 split」**：跨页边界的对齐访问仍可能 split，且透明大页合并会改变实际布局。
- **「缓存行锁不需要内存屏障」**：锁只保证原子性，不自动给出 acquire/release 语义，跨变量顺序仍需显式内存序。

## 八、面试题

**Q1：什么情况 `LOCK` 退化为总线锁？**
要点：操作数跨多条缓存行、访问不可缓存内存、或在需要硬件仲裁的平台上执行未对齐 split lock。

**Q2：为什么缓存行锁比总线锁便宜？**
要点：只阻塞与目标行相关的探测，不影响无关内存事务；总线锁冻结整个互连。

**Q3：什么是伪共享，如何消除？**
要点：逻辑独立的变量共处一行导致互相使无效；用填充加对齐让各变量独占缓存行。

**Q4：原子操作能替代内存屏障吗？**
要点：不能。`relaxed` 原子只保证原子性，跨变量可见性顺序需要 acquire/release 或 fence。

## 九、演进与趋势

- 硬件持续优化缓存锁粒度与延迟响应逻辑，并对「跨行原子」施加限制（x86 的 split lock 检测在部分平台可配置为抛 `#AC`）。
- **对齐要求被前移到语言/ABI**：C11 `_Atomic`、C++ `std::atomic` 要求实现保证合理对齐，运行库在可能时给出诊断。
- 互连层面出现更细粒度的原子单元与近存原子（in-memory atomics），以支撑高并发计数与图计算。
- 内核为减少 split lock 惩罚，会在用户态触发时发出警告甚至限流，推动程序修正数据布局。

## 十、小结

多核上的原子性靠「缓存行独占 + 延迟探测响应」实现，而非默认的总线锁；总线锁只是无法用缓存行覆盖时的兜底。理解这条路径，能解释伪共享为何昂贵、为何要对齐数据结构，也能解释为什么热点原子操作会成为扩展性瓶颈。
