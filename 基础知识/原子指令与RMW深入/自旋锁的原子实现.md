# 自旋锁的原子实现

> 对应 Bryant & O'Hallaron《Computer Systems》与 Herlihy《Art of Multiprocessor Programming》。

## 一、背景与挑战
自旋锁在临界区极短时比睡眠锁更高效（避免上下文切换）。其正确性依赖原子「测试并设置」操作在竞争下的互斥。

## 二、核心原理
典型实现用原子交换（TAS）或 CAS 尝试把锁变量 0→1；成功者进入临界区，失败者循环重试（可加退避）。释放时原子写 0。

## 三、形式化与数学基础
设锁状态 $L\in\{0,1\}$。acquire 用原子：
$$L_{new} = TAS(L): L\leftarrow 1,\; \text{return old}$$
仅当 old==0 者获得锁，保证互斥：
$$\forall \text{holders } h_1\neq h_2:\; \neg(h_1 \land h_2 \text{ hold simultaneously})$$

## 四、代码实现
```c
// TAS 自旋锁
void lock(int* l){
    while (__sync_lock_test_and_set(l, 1)) {
        while (*l) cpu_relax(); // 等待
    }
}
void unlock(int* l){ __sync_lock_release(l); }
```

## 五、与其他技术对比
自旋锁适合短临界区、低延迟；互斥量（睡眠锁）适合长临界区、避免空转。前者占 CPU，后者有切换成本。

## 六、常见误区
误认为自旋锁总是快。高竞争或长临界区下自旋空耗 CPU，反而更慢，还可能饿死。

## 七、与开源书/权威来源对应
CSAPP 第12章讨论信号量与自旋锁；Herlihy 分析锁的进展性与自旋开销。

## 八、面试题
问：为何释放用原子写而非普通写？答：确保释放对所有核可见且不被重排，普通写可能因缓冲延迟导致他人长时间自旋。

## 九、演进与趋势
排队自旋锁（MCS、ticket）缓解不公平与缓存颠簸；结合内存序（acquire/release）表达语义。

## 十、小结
自旋锁用原子 TAS 实现互斥，是短临界区同步的轻量手段，但需注意竞争与公平性。
