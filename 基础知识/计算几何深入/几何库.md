# 几何库

> 对应 CGAL（Computational Geometry Algorithms Library）、Boost.Geometry、GEOS/JTS，以及 Shewchuk (1997) 自适应精度几何谓词论文、《Computational Geometry: Algorithms and Applications》关于鲁棒性的讨论。

## 一、背景与挑战

计算几何的算法在纸面上往往只有几十行，工程落地却极易出错。根因是**浮点误差与退化输入**：本应共线的三点因舍入被判定为“微左转”，凸包多出毛刺；本应相交的线段被漏判；多边形布尔运算在边界重合处产生零面积碎片或自相交环。自己手写几何谓词，等于在沙地上盖楼——单元测试过不了随机退化数据，更过不了用户真实数据。

成熟几何库（CGAL、Boost.Geometry、GEOS、JTS）的价值不只是“提供凸包函数”，而是一整套**稳健几何基础设施**：

1. **精确谓词（exact predicates）**：`orientation`、`in_circle`、`do_intersect` 保证符号永远正确，即使坐标是浮点。
2. **精确构造（exact constructions）**：交点、中点、圆弧交点用有理数或代数数表示，后续运算不丢信息。
3. **退化处理与概念化设计**：点、线段、多边形、排列、三角剖分有统一概念模型，算法对维度和内核（kernel）泛型化。

在工程中，GIS（PostGIS 底层是 GEOS）、CAD（OpenCASCADE）、机器人（OMPL/FCL）、游戏物理（Bullet/Box2D 的部分模块）都依赖这些库。面试中虽然常手写算法，但“知道为何不能直接用裸浮点写生产级几何”是高级工程师的分水岭；系统设计里选型“用 CGAL 还是手写”也常被追问。

## 二、核心原理

### 1. 谓词与构造分离

Shewchuk 指出，几何算法正确性依赖的往往只是**符号**（谓词），而不是具体数值（构造）：

- **谓词**：orientation（三点转向）、incircle（点在圆内/外）、sidedness。只需符号，可用高精度或自适应方式精确计算。
- **构造**：交点坐标、偏移、圆弧求交。必须产生新坐标，需有理数/代数数内核。

CGAL 的架构把二者拆开：`Exact_predicates_inexact_constructions_kernel`（EPICK）用浮点存坐标、自适应算谓词，构造仍用 double——适用于凸包、三角剖分、Voronoi 拓扑正确即可的场景；`Exact_predicates_exact_constructions_kernel`（EPECK）用 Gmpq/代数数，连交点都精确，代价是慢一个数量级。

### 2. 自适应精度（adaptive precision）

`orient2d(a,b,c)` 流程：

1. 用双精度浮点快速算 $D = (b-a)\times(c-a)$。
2. 若 $|D|$ 大于误差界（由输入坐标的量级估计），直接返回符号。
3. 否则升级到精确算术（扩展精度浮点或整数运算），算出精确符号。

这样快路径覆盖绝大多数输入，慢路径只在“几乎共线”时触发，兼顾速度与 100% 正确。

### 3. 内核（kernel）与概念（concept）

CGAL 用模板参数化几何内核：算法只依赖 `Point_2`、`Vector_2`、`Orientation_2` 等概念，不绑定具体数类型。用户可换 `double`、`Gmpq`、`CORE::Expr` 而不改算法。Boost.Geometry 用标签分发（tag dispatching）和策略（strategy）模式达到类似效果。

### 4. 退化输入规范化

库通常要求或内部执行：去除重复点、统一绕向（逆时针外环、顺时针内环）、容差或精确比较。GEOS 的 `GeometryFixer`、CGAL 的 `Polygon_set_2` 都处理自相交与零面积环。

## 三、形式化与数学基础

**误差界。** 双精度浮点（IEEE-754 binary64，53 位有效位）运算满足 $fl(a\circ b) = (a\circ b)(1+\delta)$，$|\delta| \le u = 2^{-53}$。叉积

$$
D = (b_x-a_x)(c_y-a_y) - (b_y-a_y)(c_x-a_x)
$$

由两次乘法、一次减法组成，相对误差界可推出约 $O(u)$ 乘以量级因子 $\|(b-a)\|\|(c-a)\|$。当 $|D|$ 小于该界时，符号不可信，必须升级精确算术。

**精确 orientation。** 整数坐标 $|coord| \le B$ 时，叉积绝对值 $\le 2B^2$，用 $2B^2 < 2^{53}$ 即可无损；更大坐标用 `__int128`、GMP 或浮点扩展（double-double / quad-double）。Shewchuk 的实现用浮点滤波 + 整数精确回退。

**有理数构造。** 两直线交点

$$
x = \frac{d_1 c_2 - d_2 c_1}{a_1 b_2 - a_2 b_1}
$$

是有理数（若系数有理）。用 Gmpq 保存分子分母，可保证后续谓词仍精确。缺点是分子分母可能膨胀，需要周期性约分或使用代数数域。

**复杂度代价。** 浮点谓词 $O(1)$ 极快；自适应谓词期望 $O(1)$，最坏升精确；有理数构造 $O(\log B)$ 每次乘加（位运算）。CGAL 文档报告：EPICK 下凸包比手写浮点慢 2–5 倍，EPECK 可能慢 10–50 倍，但换来正确性。

**布尔运算。** 多边形并/交用排列（arrangement）+ 扫描线，精确内核保证边界一致；近似内核在重合边处会失败。

## 四、代码实现

```python
"""手写稳健谓词与最小几何库雏形：自适应 orientation + 多边形面积 + 点在多边形内。"""
from __future__ import annotations
from dataclasses import dataclass
from fractions import Fraction
from typing import List, Sequence


@dataclass(frozen=True)
class Pt:
    x: float
    y: float


def _orient2d_fast(a: Pt, b: Pt, c: Pt) -> float:
    return (b.x - a.x) * (c.y - a.y) - (b.y - a.y) * (c.x - a.x)


def orient2d(a: Pt, b: Pt, c: Pt) -> int:
    """自适应方向谓词：1 左转 / -1 右转 / 0 共线。
    浮点不确定时用 Fraction 精确回退（教学版；生产用 Shewchuk C 实现）。
    """
    d = _orient2d_fast(a, b, c)
    # 粗略误差界：若 |d| 相对量级很小，升级精确
    scale = (abs(b.x - a.x) + abs(b.y - a.y)) * (abs(c.x - a.x) + abs(c.y - a.y))
    if abs(d) > 1e-12 * max(scale, 1.0):
        return 1 if d > 0 else (-1 if d < 0 else 0)
    # 精确回退：有理数运算
    ax, ay = Fraction(a.x).limit_denominator(10**12), Fraction(a.y).limit_denominator(10**12)
    bx, by = Fraction(b.x).limit_denominator(10**12), Fraction(b.y).limit_denominator(10**12)
    cx, cy = Fraction(c.x).limit_denominator(10**12), Fraction(c.y).limit_denominator(10**12)
    exact = (bx - ax) * (cy - ay) - (by - ay) * (cx - ax)
    if exact > 0:
        return 1
    if exact < 0:
        return -1
    return 0


def polygon_area(poly: Sequence[Pt]) -> Fraction:
    """精确有向面积（用 Fraction 避免浮点误差）。"""
    s = Fraction(0)
    n = len(poly)
    for i in range(n):
        x1 = Fraction(poly[i].x).limit_denominator(10**12)
        y1 = Fraction(poly[i].y).limit_denominator(10**12)
        x2 = Fraction(poly[(i + 1) % n].x).limit_denominator(10**12)
        y2 = Fraction(poly[(i + 1) % n].y).limit_denominator(10**12)
        s += x1 * y2 - x2 * y1
    return s / 2


def point_in_polygon(p: Pt, poly: Sequence[Pt]) -> bool:
    """射线法，用 orient2d 稳健判交。"""
    n = len(poly)
    inside = False
    for i in range(n):
        a, b = poly[i], poly[(i + 1) % n]
        # 检查边与向右水平射线相交
        if (a.y > p.y) != (b.y > p.y):
            # 求交点 x（浮点足够，符号判定在上面）
            x_int = a.x + (p.y - a.y) * (b.x - a.x) / (b.y - a.y)
            if x_int > p.x:
                inside = not inside
    return inside


class SimpleGeometryLibrary:
    """演示：把稳健谓词封装成常用 API。"""

    @staticmethod
    def is_left_turn(a: Pt, b: Pt, c: Pt) -> bool:
        return orient2d(a, b, c) > 0

    @staticmethod
    def segments_intersect(p1: Pt, p2: Pt, p3: Pt, p4: Pt) -> bool:
        d1 = orient2d(p1, p2, p3)
        d2 = orient2d(p1, p2, p4)
        d3 = orient2d(p3, p4, p1)
        d4 = orient2d(p3, p4, p2)
        if d1 * d2 < 0 and d3 * d4 < 0:
            return True
        # 端点/共线退化（简化）
        return False

    @staticmethod
    def area(poly: Sequence[Pt]) -> float:
        return float(polygon_area(poly))


if __name__ == "__main__":
    # 浮点近共线：精确谓词应判共线
    a = Pt(0, 0)
    b = Pt(1e-8, 1e-8)
    c = Pt(2e-8, 2e-8)
    assert orient2d(a, b, c) == 0

    # 明显左转
    assert orient2d(Pt(0, 0), Pt(1, 0), Pt(1, 1)) == 1

    # 多边形面积精确为 1
    square = [Pt(0, 0), Pt(1, 0), Pt(1, 1), Pt(0, 1)]
    assert polygon_area(square) == Fraction(1, 1)

    # 点在多边形内
    assert point_in_polygon(Pt(0.5, 0.5), square)
    assert not point_in_polygon(Pt(1.5, 0.5), square)

    lib = SimpleGeometryLibrary()
    assert lib.is_left_turn(Pt(0, 0), Pt(1, 0), Pt(0, 1))
    assert lib.segments_intersect(Pt(0, 0), Pt(2, 2), Pt(0, 2), Pt(2, 0))
    assert abs(lib.area(square) - 1.0) < 1e-9

    # 共线线段不应报规范相交
    assert not lib.segments_intersect(Pt(0, 0), Pt(1, 0), Pt(2, 0), Pt(3, 0))
    print("几何库：全部用例通过")
```

## 五、与其他技术对比

| 方案 | 谓词正确性 | 构造精度 | 性能 | 适用 |
|------|------------|----------|------|------|
| 裸浮点手写 | 不保证 | 不保证 | 最快 | 原型、游戏非关键 |
| **自适应精确谓词（EPICK）** | 100% | 浮点 | 快 | 凸包、三角剖分、判断类 |
| 全精确有理（EPECK） | 100% | 100% | 慢 10–50× | 布尔运算、CAD、GIS |
| 有理数 `Fraction` | 100% | 100% | 慢 | 教学、小规模 |
| 近似/整数缩放 | 视范围 | 视范围 | 中 | 像素坐标、网格 |

取舍：**生产几何优先用成熟库**（CGAL/GEOS/JTS）。若必须手写，至少实现精确 orientation 与明确的共线约定。布尔运算、多边形叠置不要用裸浮点硬写。

## 六、常见误区

1. **用 `abs(d) < eps` 判共线，eps 全局固定。** 坐标量级变化一个数量级，eps 立刻失效。应用相对误差界或精确算术。
2. **谓词正确但构造仍用浮点。** 拓扑对了，交点坐标有漂移，后续再运算误差累积。布尔运算必须精确构造。
3. **多边形绕向不规范。** 外环顺时针、内环逆时针混用，面积符号、点在多边形内、布尔运算全错。入库前统一绕向。
4. **忽略重复点与零面积环。** 算法在退化环上死循环或除零。预处理清洗输入。
5. **把库的“近似内核”当精确内核用。** Boost.Geometry 默认 double 策略在重合边界会失败，文档写明的 exact 内核才用于关键路径。

## 八、面试题

**1. 为什么生产环境不建议裸浮点写几何判定？**
参考答案：浮点舍入会使符号错误，导致拓扑判定不一致（漏交点、凸包缺角）。应用精确谓词（自适应滤波 + 精确回退）或成熟库；构造问题还须有理数表示。

**2. CGAL 的 EPICK 与 EPECK 内核有何区别？**
参考答案：EPICK = exact predicates + inexact constructions，谓词精确、构造仍 double，快且够用于凸包/三角剖分；EPECK 谓词与构造都精确（Gmpq/代数数），适合布尔运算，慢但全对。

**3. 如何用有理数避免几何误差？**
参考答案：把坐标存为 $\frac{p}{q}$，交点等构造结果也是有理数，后续谓词精确。代价是数膨胀与性能，需约分或使用 GMP。

**4. 点在多边形内如何做才稳？**
参考答案：射线法 + 精确 orientation 处理边界。若只问内部/外部，可用 winding number。注意射线过顶点、水平边的退化约定。

## 九、演进与趋势

**鲁棒几何即服务**：GEOS 被 PostGIS、QGIS、Shapely 统一调用；Rust 生态有 `robust`、`geo` crate 植入 Shewchuk 谓词。**GPU 精确谓词**、SIMD 批量 orientation 用于实时碰撞与点云。

**代数数与曲线布置**：圆弧、样条的精确布尔运算用代数数域（CGAL `Arrangement_on_surface_2`），支撑 CAD/字体轮廓（FreeType/HarfBuzz 也涉及稳健求交）。**与形式化验证结合**：Coq/Isabelle 中验证几何算法正确性成为研究热点。

**工程趋势**：优先复用库而非重写；对性能敏感路径用“浮点滤波 + 精确回退”；在坐标范围可控时（像素、整数网格）用整数算术从源头消灭误差。

## 十、小结

几何库的核心资产不是某个算法，而是**稳健谓词、精确构造、退化处理与概念化架构**。理解谓词/构造分离与自适应精度，就理解了为何手写浮点几何总在边界翻车；在工程选型中“能用 CGAL/GEOS 就用，自写则必须精确谓词”应成为默认纪律。
