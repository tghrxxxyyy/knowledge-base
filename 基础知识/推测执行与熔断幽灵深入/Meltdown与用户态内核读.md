# Meltdown 与用户态内核读

> 对应 Lipp et al. 2018《Meltdown》(USENIX Security，真实作者年份)；Gruss et al. KAISER 论文。

## 一、背景与挑战

Meltdown 利用多数 x86 微架构的一个缺陷：在执行权限检查（页表 U/S 位）完成之前，CPU 就推测把内核地址的数据返回给后续指令使用。于是用户态程序可以「先读内核物理内存、再用它做点什么（留下缓存痕迹），最后才触发异常被捕获」——异常虽然发生，但泄漏已完成。这让普通用户程序越权读取任意内核内存，威胁所有未打补丁的系统。与 Spectre 不同，Meltdown 不需要构造 gadget，而是直接利用权限检查的时序缺陷。

其危害在于：内核中常驻大量跨进程共享的敏感数据（密钥、口令哈希、其他进程内存映射），一旦可被任意读取，所有进程隔离形同虚设。

还有一层放大器效应：Meltdown 可直接读取**物理内存映射区**，因此在虚拟化环境下还可能读到宿主或其他虚拟机内存；在启用了直接物理内存映射（如 `physmap`）的系统中，攻击者甚至不必知道目标虚拟地址，扫描映射区即可。这把「单机越权」升级为「跨隔离域泄漏」。

## 二、核心原理

访问内核地址时，CPU 先返回数据（供推测继续执行），稍后才因权限异常终止该指令。但被读取的内核数据已经用于索引一个用户态数组（如 `user_arr[data*4096]`），把 `data` 的某个比特「编码」进缓存状态。当异常处理返回后，攻击者用 Flush+Reload 测哪个偏移命中，即可逐比特/逐字节重建内核页内容。整个过程不需要任何特权，也不依赖构造 gadget，纯粹利用「权限异常晚于数据返回」的窗口。

旁路信号的选择很讲究：必须以「与数据相关的内存访问」作为编码手段，且该访问必须命中缓存而非被拒绝（用户态数组本身是合法映射，仅索引值来自推测读到的内核字节）。这就是经典「transient load + cache encode」两段式结构，也是所有瞬态执行攻击的公共骨架。

## 三、形式化与数学基础

推测窗口内：

$$data = Load(kernel\_addr)\quad \text{先于}\quad Exception(permission)$$

随后 `user_arr[data * 4096]` 命中缓存。设页大小 4KB，每次可编码 $\log_2(4096)=12$ 比特的偏移信息，重复即可恢复完整字节：

$$byte = \bigcup_{k} offset_k,\quad offset_k \in [0,256)$$

（实际每次泄漏一个字节，靠 256 个 4KB 页区分 256 种值）。攻击者逐字节、逐页扫描即可重建整个内核地址空间的可读内容。

| 要素 | 取值/说明 |
| --- | --- |
| 缓存行 | 通常 64B |
| 步长（页） | 4096B，确保不同值映射到不同缓存行 |
| 可区分值 | 256（一字节） |
| 每字节探测次数 | 需多次重复以对抗噪声 |
| 判定方法 | Flush+Reload / Evict+Reload 计时 |

## 四、代码实现

```c
// Meltdown 泄漏内核字节（示意，需越权映射/直读）
void leak(unsigned long kaddr, uint8_t *user_arr) {
    uint8_t val = *(volatile uint8_t *)kaddr;  // 触发异常（被捕获）
    user_arr[val * 4096]++;                    // 推测执行留下 cache 痕迹
}
// 攻击者: clflush 全部 256 页 → 调用 leak → 测哪页命中 → 得 val
// 缓解: KAISER/KPTI 不把内核页映射到用户页表，使 Load 直接页表缺失
```

```c
// 缓解后的语义：用户态访问内核地址立即页表缺失，无数据返回
if (access(kaddr) == PAGE_FAULT_BEFORE_DATA)
    return;   // 权限检查先于数据，推测窗口被关闭
```

```c
// 攻击者侧：用信号处理捕获异常，再用计时区分命中页
static void sigsegv(int sig) { siglongjmp(exploit_jmp, 1); }   // 跳过故障指令
uint8_t meltdown_read(uint64_t kaddr) {
    uint64_t offs[256]; uint8_t best = 0;
    for (int i = 0; i < 256; i++) _mm_clflush(&probe[i * 4096]);  // 清缓存
    if (!sigsetjmp(exploit_jmp, 1)) leak(kaddr, probe);          // 触发推测读
    for (int i = 0; i < 256; i++) offs[i] = time_load(&probe[i * 4096]);  // 计时
    // 命中页（时间最短）即泄漏字节，配合重复投票抗噪
    return pick_min_index(offs);
}
```

## 五、与其他技术对比

| 维度 | Meltdown | Spectre V1/V2 |
| --- | --- | --- |
| 利用根因 | 权限检查晚于数据返回 | 分支/间接分支误预测 |
| 是否需 gadget | 否（直接越权读） | 是（需构造 gadget） |
| 受影响范围 | 主要是 Intel 类乱序 CPU | 几乎所有带预测的处理器 |
| 主要缓解 | KPTI、权限检查前置 | retpoline、IBRS/STIBP |

Meltdown 是「权限隔离」层面的漏洞，Spectre 是「控制/数据预测」层面的漏洞，二者机理不同但都借缓存侧信道完成泄漏。

| 缓解手段 | 针对 | 代价 |
| --- | --- | --- |
| KPTI（页表隔离） | Meltdown | 每次系统调用切换 CR3，开销可观 |
| PCID | 降低 KPTI 的 TLB 冲刷开销 | 硬件支持成本 |
| 权限检查前置 | Meltdown（新微架构） | 设计成本 |
| 微码/清缓存（VERW） | 相关 MDS 类泄漏 | 执行开销 |

## 六、常见误区

误区一：异常会阻止泄漏。错，异常在推测之后才触发，缓存已留痕。误区二：所有 CPU 都中招。错，部分架构（如部分 ARM/AMD）权限检查更早或严格串行，不易中招。误区三：KPTI 防 Spectre。错，KPTI 主要防 Meltdown（隔离内核页表），Spectre 需 retpoline/eIBRS。误区四：用户态无法触达内核地址。错，地址空间布局上内核地址对用户态可见（只是权限位禁止），Meltdown 正是利用这点。

误区五：KPTI 没有代价。错，它使每次陷入内核都需切换页表，早期实测开销可达几个百分点，故用 PCID 减轻。误区六：打了补丁就完全安全。错，Meltdown 只是瞬态执行家族的一支，仍需叠加对 Spectre 系列与 MDS/L1TF 等的缓解。

## 七、与开源书·权威来源对应

- Lipp et al. 2018《Meltdown》（USENIX Security）给出完整 PoC 与「权限检查晚于数据使用」的机理。
- Gruss et al. KAISER 论文提出把内核/用户页表分离以阻断 Meltdown。
- Linux KPTI 补丁（KAISER 主线化）是工业界直接落地。
- Hennessy & Patterson 的权限/保护机制章节可作背景对照。

## 八、面试题

1. 为何 Meltdown 主要伤 Intel？要点：其权限异常晚于数据返回，留出推测窗口；AMD/部分 ARM 更早拦截。
2. KPTI 如何阻断 Meltdown？要点：用户态页表不映射内核页，Load 直接页表缺失，无数据返回。
3. 异常被捕获为何仍有泄漏？要点：泄漏发生在缓存侧信道，与异常是否抛出无关。
4. KPTI 的代价为何可用 PCID 降低？要点：PCID 给不同页表打标签，避免每次 CR3 切换都冲刷整个 TLB。
5. 为什么用「页粒度索引」而不直接编码整个值？要点：缓存行是固定小粒度，用 4096 步长可让 256 个值落在互不干扰的缓存行上。
6. 为什么需要重复探测？要点：计时含噪声与调度抖动，需多次投票或统计取中位数提高信噪比。

## 九、演进与趋势

KPTI 分离内核/用户页表；硬件增加自动清缓存指令（VERW/MD_CLEAR）、数据采样抑制（如 Intel 的 MDS 缓解）；新一代微架构把权限检查提前到流水线更前端，从根上缩小推测窗口，使 Meltdown 类攻击难以成立。同时，用户/内核页表隔离也成为默认安全配置，即便无漏洞也启用以防侧信道。

后续研究把这一思路扩展到更多状态与部件：L1TF/Foreshadow 针对 L1 数据缓存、MDS（RIDL/Fallout）针对填充缓冲与负载端口、ZombieLoad 针对行填充缓冲、Retbleed 针对返回指令预测。缓解策略也从「单点补丁」演进为「默认隔离 + 按需刷洗 + 硬件重构」的组合拳，并促使把「推测执行安全」纳入微架构设计的一等约束。

## 十、小结

Meltdown 暴露了「权限检查晚于数据使用」的设计缺陷：用户态借此越权读取内核内存并经由缓存侧信道泄漏。KPTI 以一定性能代价换取地址空间隔离，是软件层对硬件缺陷的快速止血，也推动了权限检查前置的硬件重构。理解它应把握两句话：泄漏靠缓存计时而非数据通路本身；隔离的本质是「让推测读从一开始就取不到数据」，而非「让它出错后再补救」。
