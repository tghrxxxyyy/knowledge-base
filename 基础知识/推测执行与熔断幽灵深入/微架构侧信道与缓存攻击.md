# 微架构侧信道与缓存攻击

> 对应 Kocher/Spectre 与经典缓存攻击文献（如 Bernstein 2005 缓存时序攻击，真实来源）。

## 一、背景与挑战
除熔断/幽灵外，缓存本身即是强大的侧信道：共享缓存使攻击者通过访问时延推断他人访问模式，进而恢复密钥或敏感数据（如 AES T-table 攻击）。

## 二、核心原理
基于时间的攻击测量某内存/数组访问耗时：命中缓存快、未命中慢。Flush+Reload 先 `clflush` 受害者行再测命中；Prime+Probe 填充缓存集再测驱逐。

## 三、形式化与数学基础
命中/未命中时延差 $\Delta = T_{miss} - T_{hit} \gg 0$。判决：
$$Bit = \begin{cases} 1 & T_{access} < T_{threshold} \\ 0 & \text{否则} \end{cases}$$
在 AES 中，不同 S-box 索引访问不同 T 表缓存行，反复测量可得密钥字节。

## 四、代码实现
```c
// Flush+Reload 探测受害者是否访问页偏移o
void clflush(volatile void *p){ __builtin_ia32_clflush(p); }
int probe(volatile char *p){
    uint64_t t=rdtsc(); (void)*p; t=rdtsc()-t;
    return t < HIT_THRESHOLD; // 1=命中(受害者曾访问)
}
// 受害者访问 shared[o] 后, probe(shared+o) 返回1
```

## 五、与其他技术对比
Flush+Reload 需共享内存、精度高；Prime+Probe 无需共享、按缓存集推断；二者都比熔断更"通用"。

## 六、常见误区
误以为常量时间代码可完全免疫：还需防缓存集冲突。误以为只在加密领域：任何数据依赖访问都可能泄漏。

## 七、与开源书/权威来源对应
Bernstein 2005 Cache-timing AES；Spectre/Meltdown 论文；CS-Notes 安全基础。

## 八、面试题
问：常量时间编程为何重要？答：使执行时间不依赖秘密，消除时序侧信道。

## 九、演进与趋势
缓存分区、模糊时间（fuzzy time）、以及软硬件协同隔离缓解侧信道。

## 十、小结
缓存侧信道是推测执行攻击之外的另一大片攻击面，安全编码（常量时间、隔离）是根本防线。
