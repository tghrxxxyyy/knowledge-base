# 域名空间与解析

> 对应 RFC 1034 / RFC 1035（DNS 规范）；RFC 9499（术语）。

## 一、背景与挑战
IP 地址难记且易变，需要层次化、可读的名字系统把“域名”映射为“IP”。DNS 是一棵以根（.）为顶的 inverted tree 命名空间。

## 二、核心原理
域名按标签（label）从右到左分层：www.example.com 中 com 是 TLD，example 是二级域，www 是主机。解析是从根到 TLD 到权威服务器的迭代/递归查询过程，最终取回 A/AAAA 记录。

## 三、形式化 / 数学基础
域名长度限制：单标签 ≤ 63 字节，全名（含点）≤ 255 字节。
消息头部：$ID(16)\ |\ Flags(16)\ |\ QDCOUNT\ |\ ANCOUNT\ |\ NSCOUNT\ |\ ARCOUNT$（各 16 位）。
资源记录（RR）：$NAME\ |\ TYPE\ |\ CLASS\ |\ TTL\ |\ RDLENGTH\ |\ RDATA$。

## 四、代码实现
```python
import socket
# 解析域名到 IP（底层走系统 resolver -> DNS）
ips = socket.getaddrinfo("www.example.com", 80)
for ip in ips:
    print(ip[4][0])   # IPv4/IPv6 地址
```

## 五、与其他技术对比
DNS 分布式层级 vs hosts 文件（集中、静态）；vs mDNS（局域网无权威）；vs DoH/DoT（加密传输但解析逻辑不变）。

## 六、常见误区
误区一：DNS 只返回 IP。错，还返回 MX、CNAME、TXT、NS 等。误区二：域名末尾点不重要。错，www.example.com. 的尾点表示根，绝对名。误区三：解析一次即全局。错，受 TTL 与缓存影响。

## 九、演进与趋势
DNS over HTTPS/TLS 普及；EDNS(0)（RFC 6891）扩展 UDP 有效载荷与选线。

## 十、小结
DNS 把层次域名解析为资源记录，是互联网的“电话簿”，结构是倒置树 + 分布式权威。
