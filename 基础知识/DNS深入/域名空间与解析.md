# 域名空间与解析

> 对应 RFC 1034 / RFC 1035（DNS 规范与报文格式）；RFC 9499（DNS 术语）；RFC 6891（EDNS(0)）。

## 一、背景与挑战
IP 地址既难记又易变，需要一套层次化、可读、可委派的名字系统把「域名」映射为「IP 及其它属性」。DNS 给出的答案是：一棵以根（`.`）为顶的倒置树（inverted tree），每个节点有一段标签（label），自顶向下逐级委派权威，任何组织只需维护自己那一段。

难点有四：其一，规模——名字空间无限增长而任何单机都存不下，必须靠委派与缓存分摊；其二，可用性——根与 TLD 是全球单点，必须 Anycast 冗余且极轻量；其三，互操作——报文是二进制线格式（wire format），字段宽度与压缩规则必须严格一致；其四，扩展——原始规范只覆盖少量记录类型，后续用 EDNS 与新的 RR 类型扩展而不能破坏旧实现。

## 二、核心原理
域名自右向左分层：`www.example.com.` 去掉末尾「」后，`com` 是 TLD，`example` 是二级域，`www` 是主机标签。末尾那个点代表根，写全即为**绝对名（FQDN）**；省略点则视为相对名，由解析器按 `search` 列表补全——这正是「同一域名在不同环境解析结果不同」的常见来源。

解析是「从根到 TLD 再到权威」的过程，最终取回 A/AAAA 等记录。委派通过 NS 记录实现：父区 NS 记录指向子区权威服务器名，而这些权威服务器名若与子区同名（in-bailiwick），父区必须额外提供 **glue 记录**（A/AAAA），否则形成循环依赖无法解析。此外，一个名字可以有 CNAME（别名，指向另一名字）、MX、TXT、SRV 等记录；CNAME 与其它类型共存会破坏语义，故规范禁止。

## 三、形式化与数学基础
长度约束：单个标签 $\le 63$ 字节，完整域名（含分隔点与根点）$\le 255$ 字节：
$$ |\mathrm{label}_i| \le 63,\qquad \sum_i (|\mathrm{label}_i|+1) + 1 \le 255 $$
报文头部固定 12 字节，字段为：
$$ ID(16)\ \|\ Flags(16)\ \|\ QDCOUNT \|\ ANCOUNT \|\ NSCOUNT \|\ ARCOUNT $$
每个计数为 16 位，因此单报文问题区通常限定为 1 条。资源记录（RR）统一格式：
$$ \mathrm{NAME} \|\ \mathrm{TYPE} \|\ \mathrm{CLASS} \|\ \mathrm{TTL} \|\ \mathrm{RDLENGTH} \|\ \mathrm{RDATA} $$
域名在报文中的压缩用指针实现：最高两位置 1 表示「接下来 14 位是偏移量」而非标签长度，即
$$ \mathrm{ptr} = \texttt{0xC0} \mid \mathrm{offset}(14) $$
压缩使重复后缀只存一次，但要求解析器防止指针成环（恶意报文可构造自指指针导致死循环，故实现必须限制跳转次数）。EDNS(0) 通过 OPT 伪记录把 UDP 载荷能力从 512 字节协商放大到更大值，并携带 DO 位、扩展 RCODE 等。

## 四、代码实现
最常见的应用层调用与直接查看报文：
```python
import socket
# 走系统 resolver 配置（/etc/resolv.conf 或 nsswitch），返回含 IPv4/IPv6
for family, _, _, _, addr in socket.getaddrinfo("www.example.com", 80):
    print(family, addr[0])
```

```bash
# 只看答案段：末列为 IP，倒数第二列为 TTL
dig +noall +answer www.example.com A
# 追踪完整委派链（从根开始逐级）
dig +trace www.example.com
```

手工解析报文头部与压缩指针（示意，省略边界检查）：
```python
def parse_name(buf, pos, depth=0):
    labels, jumps = [], 0
    while True:
        if depth > 128:                 # 防指针成环
            raise ValueError("compression loop")
        ln = buf[pos]
        if ln == 0:
            pos += 1
            break
        if ln & 0xC0 == 0xC0:           # 压缩指针
            if jumps == 0:
                end = pos + 2
            pos = ((ln & 0x3F) << 8) | buf[pos + 1]
            jumps += 1
            depth += 1
            continue
        labels.append(buf[pos + 1: pos + 1 + ln].decode())
        pos += 1 + ln
    return ".".join(labels) + ".", (end if jumps else pos)
```

## 五、与其他技术对比
| 维度 | DNS | hosts 文件 | mDNS / LLMNR | DoH / DoT |
| --- | --- | --- | --- | --- |
| 结构 | 分布式倒置树 + 委派 | 单机静态表 | 局域网组播即问即答 | 传输层封装，结构不变 |
| 权威来源 | 分层权威服务器 | 本机管理员 | 各主机自答 | 远端 HTTPS/TLS 解析器 |
| 可扩展性 | 全球级 | 仅本机 | 仅广播域 | 同 DNS |
| 支持记录类型 | 丰富（A/MX/TXT/...） | 仅地址映射 | 少量 | 同 DNS |
| 变更生效速度 | 受 TTL 制约 | 立即 | 立即 | 受 TTL 制约 |
| 隐私 | 明文（除非叠加加密） | 不涉及网络 | 广播可见 | 加密到解析器 |

## 六、常见误区
1. **「DNS 只返回 IP」**——错。还返回 MX、CNAME、TXT、NS、SOA、SRV 等；`getaddrinfo` 只是最窄的一层视图。
2. **「域名末尾的点不重要」**——错。`www.example.com.` 是绝对名；省略点会被 search 域拼接，导致解析到 `www.example.com.corp.local`。
3. **「解析一次即全局一致」**——错。结果受各级缓存与 TTL 影响，不同解析器可看到不同版本。
4. **「NS 记录写好就能用」**——错。若 NS 指向的名字在子区内，父区必须提供 glue，否则解析器拿不到权威地址。
5. **「CNAME 可以和其他记录并存」**——错。CNAME 所在名字不应再有其它类型记录（DNSSEC 相关类型除外），否则语义冲突。

## 七、与开源书·权威来源对应
- RFC 1034：域名概念、委派模型、解析算法（递归与迭代的规范定义）。
- RFC 1035：报文线格式、RR 编码、压缩指针与实现规则。
- RFC 9499：DNS 术语表，统一 label / zone / delegation 等易混概念。
- RFC 6891：EDNS(0)，扩展 UDP 载荷、DO 位与扩展 RCODE。
- Kurose & Ross《Computer Networking: A Top-Down Approach》第 2 章：把 DNS 作为应用层服务的经典讲解。
- Tanenbaum《Computer Networks》应用层与命名章节：分层命名的系统视角。
- 图解网络（hello-http）：DNS 报文与抓包的中文可视化补充材料。

## 八、面试题
1. **解析从哪开始？** 要点：本地缓存 → hosts → 本地递归解析器 → 根 → TLD → 权威；根只给 referral。
2. **单标签与全名长度限制？** 要点：标签 ≤ 63 字节，全名 ≤ 255 字节，超长即非法名。
3. **什么是 glue 记录，为何需要？** 要点：父区为 in-bailiwick 的 NS 名字提供 A/AAAA，打破「要查权威地址得先问权威」的循环。
4. **压缩指针有什么风险？** 要点：可构造指向自身或成环的指针，实现必须限制跳转次数与偏移范围。
5. **FQDN 与相对名差别？** 要点：尾点表示绝对名；无尾点则按 search 列表补全，是解析行为差异的常见根因。

## 九、演进与趋势
传输侧，DoH/DoT/DoQ 把 DNS 搬到加密通道，解析逻辑不变但隐私与可管控性重新平衡。协议侧，EDNS(0) 已是事实标配，QNAME minimization（RFC 7816）减少向根与 TLD 泄露的查询全名，DNS Cookies（RFC 7873）缓解伪造源地址的放大滥用。名字空间侧，国际化域名依赖 Punycode/IDNA 作映射，根区新增 TLD 与 DNSSEC 签名让「名字即信任边界」的意味更强。此外，服务发现（SRV、SVCB/HTTPS 记录）正在把「域名 → 地址」扩展为「域名 → 地址 + 协议参数」。

## 十、小结
DNS 用一棵可委派的倒置树把层次域名映射为多种资源记录，靠分布式权威与缓存实现全球规模。理解标签与 FQDN、报文线格式与压缩指针、glue 与委派的关系，是排查「解析不到 / 解析到错的地方」类问题的基本功；而 EDNS(0) 与加密传输则勾勒出 DNS 的现代演进方向。
