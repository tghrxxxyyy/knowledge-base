# 负载均衡

> 对应 RFC 1034（轮询 A 记录）；CDN/GSLB 实践。

## 一、背景与挑战
单台服务器无法承载高并发，需把流量分散到多台后端。DNS 是最外层、最廉价的负载均衡与就近调度手段。

## 二、核心原理
权威服务器对同一域名返回多个 A/AAAA 记录，解析器/客户端按序或随机选用，实现简单轮询（round-robin）。结合 EDNS Client Subnet（ECS）可按客户端地理位置返回不同 IP 集合，实现 GSLB（全局负载均衡）。

## 三、形式化 / 数学基础
轮询返回集合：$A = \{ip_1, ip_2, ..., ip_n\}$，客户端取第 $(k \bmod n)$ 个（k 为查询序号或随机）。
加权轮询：以权重 $w_i$ 比例分配流量，期望占比 $w_i / \sum w_j$。
健康检查摘除：某 $ip_j$ 不可达则从集合移除，直到恢复。

## 四、代码实现
```bash
# 权威返回多个 A 记录即轮询
dig +short www.example.com A
# 93.184.216.34
# 93.184.216.35
# 客户端随机/轮询选择其一
```

## 五、与其他技术对比
DNS 层 LB 粗粒度、受 TTL 制约、切换慢；L4/L7 负载均衡（见 SUB6）细粒度、实时。二者常组合：DNS 做 GSLB 选 region，内部 LB 做实例级分发。

## 六、常见误区
误区一：DNS 轮询保证均匀。错，受客户端缓存与 TTL 偏置。误区二：DNS LB 能感知后端实时负载。错，通常只能靠健康检查粗调。误区三：改 A 记录立即生效。错，TTL 限制。

## 十、小结
DNS 以多 A 记录轮询与 ECS 实现粗粒度全局负载均衡，是流量调度的第一道闸门。
