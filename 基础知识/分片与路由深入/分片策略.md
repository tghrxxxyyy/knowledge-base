# 分片策略

> 对应 Kleppmann《DDIA》第 6 章 Partitioning。

## 一、背景与挑战
单节点容量与吞吐有限。分片(Sharding/Partitioning)把数据按某种键切分到多节点，突破单机瓶颈；核心问题是“如何切、如何路由、如何再平衡”。

## 二、核心原理
分片维度：
- 按键范围(range)：连续区间映射到节点，范围查询友好，但易热点。
- 按哈希(hash)：key 哈希后取模/落到环，分布均匀，但范围查询需跨片。
- 按目录/lookup：显式映射表，灵活但需查表。
目标：数据均衡、路由高效、再平衡成本低、热点可控。
实际应用中常“哈希分片 + 二级索引局部/全局”组合。

## 三、形式化 / 数学基础
设分片数 k，映射 f: Key -> {0..k-1}。
均衡度衡量：各分片负载标准差 σ；理想 σ 小。
哈希分片：f(k) = hash(k) mod k。范围分片：f(k) = floor((k - min)/(max - min) * k) 类线性映射。

## 四、代码实现
```python
def shard_of(key, k):
    return hash(key) % k          # 哈希分片
def range_shard(key, boundaries):  # 范围分片
    for i, b in enumerate(boundaries):
        if key <= b: return i
    return len(boundaries)
```

## 五、与其他技术对比
- 哈希：均衡、无范围序；范围：有序、易热点。
- 目录式：最灵活但多一次查表，映射表本身需高可用。

## 六、常见误区
- 误区：分片数固定不变。增长后需再平衡扩容。
- 误区：哈希分片能优化范围查询。需要全局二级索引弥补。

## 九、演进与趋势
一致性哈希、动态再平衡、自动分片(如 Vitess、CockroachDB)让分片对应用透明。

## 十、小结
分片策略在均衡、有序、再平衡成本间权衡；哈希与范围是两种基础范式，常结合使用。
