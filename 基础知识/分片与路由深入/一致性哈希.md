# 一致性哈希

> 对应 Karger et al.《Consistent Hashing and Random Trees》(STOC 1997)。

## 一、背景与挑战
传统哈希取模在节点数 N 变化时，几乎全部 key 需重新映射，引发大规模数据迁移与缓存失效。一致性哈希让节点增减只影响邻近 key，极大降低再平衡成本。

## 二、核心原理
- 把节点与 key 都哈希到一个固定环(如 0..2^32-1)。
- key 顺时针找到第一个节点(或其虚拟节点)归属。
- 节点加入：只接管环上它与前驱之间的 key；退出：其 key 转移给后继。
- 虚拟节点(vnode)：每个物理节点映射多个环上位置，使负载更均衡。
优点：节点变化仅影响 1/N 的 key 范围，迁移局部化。

## 三、形式化 / 数学基础
环空间 C = [0, M)，M = 2^32。节点位置 P_i = hash(node_i)；key 位置 K = hash(key)。
归属：successor(K) = min{ P_j | P_j >= K }（环形回绕）。
节点增减：仅 (P_new, predecessor(P_new)] 区间的 key 迁移，占比约 1/N。
虚拟节点数 v：物理节点 i 占环上 v 段，均衡方差随 v 增大下降。

## 四、代码实现
```python
import bisect, hashlib
class ConsistentHash:
    def __init__(self, nodes, vnodes=100):
        self.ring = []
        self.node_of = {}
        for n in nodes:
            for i in range(vnodes):
                h = int(hashlib.md5(f"{n}#{i}".encode()).hexdigest(), 16)
                self.ring.append(h); self.node_of[h] = n
        self.ring.sort()
    def get(self, key):
        h = int(hashlib.md5(key.encode()).hexdigest(), 16)
        idx = bisect.bisect_right(self.ring, h) % len(self.ring)
        return self.node_of[self.ring[idx]]
```

## 五、与其他技术对比
- 相比取模哈希：再平衡迁移量从 O(全部) 降到 O(1/N)。
- 缺点：需维护环与虚拟节点；范围查询仍不便。

## 六、常见误区
- 误区：一致性哈希完全均衡。无虚拟节点时会倾斜，需 vnode。
- 误区：节点变化零迁移。仅“相邻区间”迁移，并非无迁移。

## 九、演进与趋势
虚拟节点 + 带权虚拟节点让一致性哈希在异构集群中均衡；被 Dynamo/Cassandra 广泛采用。

## 十、小结
一致性哈希通过环形空间与虚拟节点，把节点变化的再平衡成本从全量降到局部，是大规模缓存与存储分片的基石。
