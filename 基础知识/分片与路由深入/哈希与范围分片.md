# 哈希与范围分片

> 对应 Kleppmann《DDIA》第 6 章 Partitioning by Key Range 与 Partitioning by Hash。

## 一、背景与挑战
分片的两大基础方法：按 key 哈希(取模或散列)与按 key 范围。二者在“分布均衡性”与“范围查询效率”上各有取舍。

## 二、核心原理
哈希分片：
- f(k) = hash(k) mod N，数据均匀打散。
- 优点：负载均衡好，避免热点(对随机 key)。
- 缺点：范围查询需扫所有分片；热点 key(如某大 V)仍集中。
范围分片：
- 按 key 有序区间划分(如 [a-m]、[n-z])。
- 优点：范围/前缀查询只命中少数分片，顺序扫描高效。
- 缺点：若访问模式偏斜(如按时间递增)，最新区间成热点。

## 三、形式化 / 数学基础
哈希取模再平衡问题：N 变化时 hash(k) mod N 大多失效，需全量重分布(一致性哈希缓解)。
复合键：可对“分区键”哈希、对“排序键”范围，兼顾均衡与有序(如 DynamoDB 的 partition key + sort key)。

## 四、代码实现
```python
# 哈希分片(取模)：扩缩容会导致大量迁移
def shard_mod(key, n): return hash(key) % n

# 范围分片：按字典序边界
BOUNDS = ["m", "t", "z"]
def shard_range(key):
    for i, b in enumerate(BOUNDS):
        if key <= b: return i
    return len(BOUNDS)
```

## 五、与其他技术对比
- 哈希：均衡优先，牺牲范围查询。
- 范围：查询优先，牺牲均衡。
- 组合：分区键哈希 + 排序键范围，是工业常用折中。

## 六、常见误区
- 误区：哈希分片永不热点。倾斜的访问键(单个 key 巨热)仍热点。
- 误区：范围分片一定能均衡。取决于 key 分布与访问模式。

## 九、演进与趋势
一致性哈希解决取模迁移问题；组合键(分区键+排序键)成为云数据库标准。

## 十、小结
哈希与范围分片是两种互补范式，理解其均衡与查询的取舍是设计分片方案的基础。
