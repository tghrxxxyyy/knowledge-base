# 热点与数据倾斜

> 对应 Kleppmann《DDIA》第 6 章“Skewed Workloads and Mitigating Hot Spots”。

## 一、背景与挑战
即使哈希分片通常均衡，真实负载常有“少数 key 极热”或“某区间被集中访问”，造成单分片过载(热点/倾斜)，拖垮整体。

## 二、核心原理
热点来源：
- 单key热点：某超热用户/商品，所有请求打到同一分片。
- 区间热点：按时间递增写入时，最新分片成写入热点。
缓解：
- 热点 key 拆分：把单 key 加随机后缀分散到多分片，读时聚合(写扩散)。
- 应用层缓存：前置缓存吸收读热点。
- 动态再平衡：把过热分片拆分。
- 选对分区键：避免单调递增或高度偏斜的键。

## 三、形式化 / 数学基础
负载分布 Zipf 律：第 k 热门 key 的请求量 ∝ 1/k^s。极少数 key 占大部分流量。
热点 key 拆分：原 key k 拆为 k#0..k#(r-1)，使单分片负载降为 1/r，但读需 r 路聚合、一致性需合并最新。

## 四、代码实现
```python
import random
def write_hot(key, val, replicas=10):
    suffix = random.randint(0, replicas-1)   # 写分散
    shard_put(f"{key}#{suffix}", val)
def read_hot(key, replicas=10):
    return merge([shard_get(f"{key}#{i}") for i in range(replicas)])  # 读聚合
```

## 五、与其他技术对比
- 哈希均衡但挡不住单 key 热点；范围易区间热点。
- 拆分法增加读复杂度，是热点与读放大之间的权衡。

## 六、常见误区
- 误区：哈希分片就没有热点。单 key 极热照样打垮单分片。
- 误区：拆分热点 key 无代价。读需聚合，且并发写需合并。

## 九、演进与趋势
自适应分片(按实时负载自动分裂)、智能缓存与请求合并缓解热点。

## 十、小结
热点与倾斜是分片系统的现实威胁，需从分区键选择、热点拆分、缓存与动态再平衡多管齐下。
