# 路由层

> 对应 Kleppmann《DDIA》第 6 章“Request Routing”。

## 一、背景与挑战
客户端如何知道“某 key 该去哪个节点”？路由层负责把请求导向正确分片，并在再平衡时保持映射最新，且不成为瓶颈或单点。

## 二、核心原理
三种路由方式：
- 客户端感知：客户端持有路由表(分区->节点)，直连目标节点(如 Cassandra 的 token map)。
- 路由/代理层：专门代理节点维护路由表并转发(如 Proxy)。
- 节点自助：请求到任意节点，节点若非归属则转发/重定向(如 Redis Cluster 的 MOVED)。
路由表来源：zookeeper/etcd 等共识存储保存最新映射，节点变更时通知。

## 三、形式化 / 数学基础
路由表 R: partition_id -> node_address。一致性要求：所有客户端在再平衡后最终看到同一 R(经共识/版本号同步)。
重定向协议：节点返回 (target_node, new_R_version)，客户端缓存更新，降低后续跳数。

## 四、代码实现
```python
class Router:
    def __init__(self, registry): self.registry = registry  # 共识维护的路由表
    def route(self, key):
        pid = consistent_hash(key)
        return self.registry.node_of(pid)
# 客户端缓存路由表，监听变更事件刷新
```

## 五、与其他技术对比
- 客户端直连：低延迟，但路由表需推送到所有客户端。
- 代理层：集中易管理，但多一跳且需高可用。
- 节点重定向：去中心，但首次可能多跳。

## 六、常见误区
- 误区：路由层可单点。它必须高可用(多副本/共识)。
- 误区：路由表永远最新。再平衡期间存在短暂陈旧，需重定向兜底。

## 九、演进与趋势
服务网格与智能客户端把路由下沉，结合共识存储实现自动、低延迟路由。

## 十、小结
路由层把请求准确导向分片，是分片系统对客户端透明的关键；其高可用与一致性直接决定系统可用性。
