# 再平衡

> 对应 Kleppmann《DDIA》第 6 章 Rebalancing Partitions。

## 一、背景与挑战
数据量与流量增长，或节点故障/扩容，都需要把分片在节点间重新分配(再平衡)，目标是在迁移成本、均衡度与可用性之间取得平衡。

## 二、核心原理
再平衡策略：
- 固定数量分片 + 节点间移动：把逻辑分片(而非单个 key)作为迁移单位，扩缩容时整片迁移。
- 动态分片大小：分裂过热分片、合并过冷分片(如 HBase Region)。
- 一致性哈希再平衡：节点增减只迁移相邻区间。
原则：迁移期间数据仍可读写(通常先复制再切换路由)，避免停机；迁移要限流以免压垮系统。

## 三、形式化 / 数学基础
设分片集合 P，节点集合 N。再平衡是映射 g: P -> N 的更新，使负载均衡度量(如各节点数据量)标准差最小，同时迁移代价 Σ size(moved_p) 最小。
目标函数常取 min (α·不均衡度 + β·迁移量)，α,β 为策略权重。

## 四、代码实现
```python
# 简单再平衡：把分片按负载排序后均摊到节点
def rebalance(shards, nodes):
    buckets = {n: 0 for n in nodes}
    plan = {}
    for s in sorted(shards, key=lambda x: -x.size):
        n = min(buckets, key=buckets.get)
        plan[s.id] = n; buckets[n] += s.size
    return plan
```

## 五、与其他技术对比
- 逻辑分片迁移优于逐 key 迁移(减少元数据抖动)。
- 一致性哈希迁移量小但可能不均衡，需虚拟节点调和。

## 六、常见误区
- 误区：再平衡可瞬间完成。大分片迁移耗时，需渐进与限流。
- 误区：迁移中数据不可用。设计应保证双写/复制期间可读。

## 十、小结
再平衡在均衡度与迁移成本间权衡；以分片为粒度、渐进限流、保证可用是工程最佳实践。
