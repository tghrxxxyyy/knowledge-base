# 缓冲与缓存

> 对应 OSTEP 第 35-37 章“缓存与缓冲”与 Linux 页缓存。

## 一、背景与挑战
IO 设备比 CPU 慢几个数量级。缓冲（buffer）平滑生产/消费速率差，缓存（cache）利用局部性减少实际 IO 次数。

## 二、核心原理
- 页缓存（page cache）：文件读写先走内存页，写可延迟/合并（writeback）。
- 缓冲区缓存（buffer cache）：块设备层缓存；现代与页缓存统一。
- 预读（readahead）按顺序预测提前装入后续页。

## 三、形式化 / 数学基础
缓存命中率 $h$，平均访问时间 $T_{avg} = h\\cdot T_{hit} + (1-h)\\cdot (T_{hit}+T_{miss})$。命中率随工作集 $W$ 与缓存容量 $C$ 关系：$h\\approx \\min(1, C/|W|)$（理想全关联）。

## 四、代码实现
强制刷盘（绕过写缓冲）：

```c
fd = open("f", O_WRONLY|O_SYNC);   /* 每次写同步到设备 */
write(fd, buf, n);
/* 或普通写后: */
fsync(fd);                          /* 刷页缓存到磁盘 */
```

## 五、与其他技术对比
写穿透（write-through）每写落盘安全但慢；写回（write-back）合并延迟写更快但有丢数据窗口；直写缓存 vs 回写缓存是性能/持久性权衡。

## 六、常见误区
- 认为写返回即安全：写回缓存下需 fsync。
- 忽略缓存污染（大文件扫描冲掉热页）。
- 混淆 buffer 与 cache：前者为速率匹配，后者为加速访问。

## 九、演进与趋势
多队列块层（blk-mq）、io_uring 与 NVMe 低延迟设备重塑缓存层次；持久内存模糊内存与存储边界。

## 十、小结
缓冲匹配速率、缓存利用局部性；页缓存+写回+预读把慢速设备“提速”，代价是需 fsync 换持久性。
