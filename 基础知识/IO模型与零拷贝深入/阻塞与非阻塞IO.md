# 阻塞与非阻塞IO

> 对应 OSTEP 第 33-34 章“IO 与磁盘”与 CSAPP 第 10 章“系统级 IO”。

## 一、背景与挑战
进程发起 IO 时，数据可能尚未就绪。阻塞 IO 挂起等待；非阻塞 IO 立即返回，让线程去做别的事，但需要轮询或配合事件通知。

## 二、核心原理
- 阻塞：`read` 在数据未到前睡眠，就绪后被唤醒返回。
- 非阻塞：`fcntl(fd, O_NONBLOCK)`，`read` 若未就绪返回 `EAGAIN`，需重试。
- 二者区别在于“未就绪时是否让出 CPU 并睡眠”。

## 三、形式化 / 数学基础
阻塞模型线程数 $= $ 并发连接数 $N$（每连接一线程）；非阻塞 + 事件循环线程数 $\\ll N$。吞吐受“就绪通知机制”效率影响，而非阻塞本身不加速 IO，只提升并发结构。

## 四、代码实现
非阻塞读（示意）：

```c
fcntl(fd, F_SETFL, O_NONBLOCK);
for (;;) {
    ssize_t n = read(fd, buf, sz);
    if (n > 0) process(buf, n);
    else if (n == -1 && errno == EAGAIN) { /* 未就绪, 去做别的事 */ break; }
    else break; /* EOF 或错误 */
}
```

## 五、与其他技术对比
阻塞简单但线程随连接膨胀；非阻塞需状态机/事件循环；结合 IO 多路复用（下篇）才能在单线程服务海量连接。

## 六、常见误区
- 认为非阻塞比阻塞“更快”：单次 IO 延迟相同，差别在并发模型。
- 忘记处理 `EAGAIN`/`EINTR` 循环。
- 在非阻塞 fd 上直接阻塞调用。

## 九、演进与趋势
io_uring 用内核态提交/完成队列把阻塞与非阻塞统一为异步高效路径，减少系统调用开销。

## 十、小结
阻塞 IO 以睡眠换取简单；非阻塞以立即返回换取并发弹性，但必须配合事件通知才能有效服务多连接。
