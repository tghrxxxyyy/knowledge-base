# 零拷贝技术

> 对应 Linux `sendfile`/`splice`/`tee` 与 CSAPP 系统级 IO。

## 一、背景与挑战
把文件经网络发出（如 Web 服务器）若用 `read`+`write`，数据要在内核缓冲与用户缓冲间反复拷贝并多次系统调用。零拷贝消除不必要的拷贝与上下文切换。

## 二、核心原理
- `sendfile(out, in, ...)`：数据直接在内核页缓存与 socket 缓冲间传递，不进用户空间。
- `splice`：在任意两个 fd 间用管道缓冲搬数据，同样免用户拷贝。
- 现代网卡支持 DMA 从页缓存直接取数据（含 scatter-gather）。

## 三、形式化 / 数学基础
传统路径拷贝次数 $= 2$（内核→用户、用户→内核）+ 2 次上下文切换；`sendfile` 路径拷贝 $= 0$（仅 DMA）+ 1 次系统调用，CPU 占用与延迟显著下降。

## 四、代码实现
sendfile 转发文件到 socket：

```c
off_t off = 0;
/* 内核内把 in 的文件页直接送入 out(socket), 不进用户态 */
sendfile(out_fd, in_fd, &off, file_size);
```

## 五、与其他技术对比
`read`+`write` 最直观但有冗余拷贝；`mmap`+`write` 省一次拷贝（无用户缓冲拷贝）但仍需 write 路径；`sendfile`/`splice` 彻底零用户态拷贝。

## 六、常见误区
- 认为零拷贝=零开销：仍有 DMA 与页缓存管理。
- 误在 `sendfile` 目标用普通文件 fd（需 out 为 socket）。
- 忽略大文件时页缓存被占用。

## 九、演进与趋势
`MSG_ZEROCOPY`、io_uring 的 `SPLICE`/`send zc` 以及用户态网络栈进一步压缩拷贝与通知开销。

## 十、小结
零拷贝通过 `sendfile`/`splice` 让数据在内核内部（页缓存↔socket）流转，省去用户态往返拷贝与多余系统调用，是高性能转发的核心。
