# 编译器重排序与内存模型

> 对应 Lamport 1979 顺序一致性论文与 C11/C++ 内存模型规范。

## 一、背景与挑战
编译器为优化可对无数据依赖的访存重排、合并、消除。单线程下语义不变，但多线程下会破坏同步协议，使锁、标志发布失效。

## 二、核心原理
编译期重排受「as-if-serial」约束：单线程可观察行为不变。但跨线程，必须靠 volatile（阻止消除/合并）或更严格的原子与屏障（阻止重排）来约束。C++ 内存模型定义 happens-before 关系。

## 三、形式化与数学基础
happens-before 是程序次序（program order）与同步次序（synchronizes-with）的传递闭包：
$$a\;\text{hb}\;b \iff a\;\text{po}\;b \lor a\;\text{sw}\;b \lor \exists c: a\;\text{hb}\;c\;\text{hb}\;b$$

## 四、代码实现
```c
// 编译器可能重排普通写
int data = 0, flag = 0;
// 线程1
data = 42; flag = 1; // 普通变量可能被重排为 flag=1; data=42
// 应使用 atomic with release 防止
```

## 五、与其他技术对比
编译器重排发生在生成代码阶段，CPU 重排发生在执行阶段，二者独立但都受内存模型约束，需双重防护。

## 六、常见误区
误认为 volatile 提供原子性与顺序保证。它仅阻止编译器优化，且与 C++ 原子语义不同。

## 七、与开源书/权威来源对应
C++ 标准的内存模型章节；Lamport 的「How to Make a Multiprocessor Computer That Correctly Executes Multiprocess Programs」定义 SC。

## 八、面试题
问：volatile 能替代互斥吗？答：不能。它不保证原子、不阻止 CPU 重排、不建立跨线程 happens-before。

## 九、演进与趋势
语言级内存模型（C11/C++11、Rust、Java）把「顺序/松弛/获取/释放」抽象出来，减少直接写屏障。

## 十、小结
编译器重排是优化副产物，理解 as-if-serial 与 happens-before 才能写出正确的并发代码。
