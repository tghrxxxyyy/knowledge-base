# 顺序一致性模型

> 对应 Lamport 1979「How to Make a Multiprocessor Computer That Correctly Executes Multiprocess Programs」。

## 一、背景与挑战
顺序一致性（Sequential Consistency, SC）是最易理解的模型：所有处理器的操作似乎按某全局顺序执行，且每个处理器内部顺序保持。但它限制硬件优化，真实 CPU 不严格遵守。

## 二、核心原理
SC 要求：结果等价于所有处理器操作的交错（interleaving），且每个核的程序次序在交错中保持。实现 SC 需禁止所有重排并即时可见，代价高。

## 三、形式化与数学基础
存在全序 $\prec$ 满足：
1. 若 $a\;\text{po}\;b$（同核），则 $a\prec b$。
2. 每个处理器的读返回最近写入的值（按 $\prec$）。
则称执行满足 SC。

## 四、代码实现
```python
# SC 可执行性检查（概念）
def is_SC(execution):
    for interleaving in all_orders():
        if consistent_with_program_order(interleaving) and values_match(interleaving):
            return True
    return False
```

## 五、与其他技术对比
SC 是「黄金标准」但性能差；TSO 与弱模型放松限制换取性能。Dekker/Peterson 等算法依赖 SC 或需强屏障。

## 六、常见误区
误认为多核硬件默认提供 SC。多数架构为性能放弃 SC，需用屏障/原子重建所需保证。

## 七、与开源书/权威来源对应
Lamport 1979 原始论文定义 SC；Hennessy & Patterson 与操作系统教材（如 ostep）常以此作为讨论起点。

## 八、面试题
问：为何实际 CPU 不用 SC？答：SC 禁止重排与写缓冲，会严重限制流水线与写吞吐，性能损失大。

## 九、演进与趋势
现代做法是在弱模型上用语言级原子「模拟」SC 所需片段，而非全局强制 SC。

## 十、小结
顺序一致性是最强、最直观的模型，但成本使其无法在硬件层直接实现，理解它方能把握为何需要屏障。
