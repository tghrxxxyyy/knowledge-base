# 经典消息传递模式

> 对应 Boehm 内存模型论文与 Herlihy《The Art of Multiprocessor Programming》。

## 一、背景与挑战
两个线程通过「数据 + 标志」通信是最基本的并发模式。若缺少正确同步，接收方可能读到标志已置但数据未写，造成错误。

## 二、核心原理
生产者写数据后 release 置标志；消费者 acquire 读标志，若看到置位则数据必已可见。该模式是锁、队列、管道的基础。

## 三、形式化与数学基础
Dekker 风格的单标志协议依赖：
$$\text{load}(flag)\;\text{acquire}\;\text{then}\;\text{see}(data)\iff \text{store}(data)\;\text{before}\;\text{store}(flag)\;\text{release}$$
若违反（如缺少屏障），则二者可见性无序，断言可失败。

## 四、代码实现
```c
std::atomic<bool> ready{false};
int payload = 0;
// 生产者
payload = 100;
ready.store(true, std::memory_order_release);
// 消费者
while (!ready.load(std::memory_order_acquire)) {}
assert(payload == 100); // 安全
```

## 五、与其他技术对比
消息传递比共享锁更轻量，但适用范围限于「一写多读/发布」语义；复杂共享状态仍需互斥或事务。

## 六、常见误区
误认为 while(!ready) 轮询不需要屏障。轮询本身用 acquire 读才能建立 happens-before，否则编译/CPU 可能永久缓存旧值。

## 七、与开源书/权威来源对应
Herlihy & Shavit《The Art of Multiprocessor Programming》详述该模式；C++ 内存模型示例直接采用此模式。

## 八、面试题
问：若去掉 release/acquire 会怎样？答：在 ARM 上可能消费者看到 ready=true 却读到 payload 旧值，断言失败。

## 九、演进与趋势
无锁 SPSC 环形队列即该模式的工程化，配合内存序与缓存行对齐实现高性能通信。

## 十、小结
消息传递用「标志 + 内存序」把数据可见性显式同步，是构建一切高层并发原语的地基。
