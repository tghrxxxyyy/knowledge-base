## 一、背景与挑战
CFS 想让所有可运行实体「公平共享 CPU」，但必须保证调度延迟有界：一个任务不应等太久才被调度到。挑战是在「越多任务越细切」与「切换开销不可忽略」之间确定调度周期与每任务最小运行时间。

## 二、核心原理
CFS 定义目标调度延迟 sched_latency（如 sysctl_sched_latency），期望在此窗口内每个可运行实体至少跑一次。理想每任务时间片 = sched_latency / 可运行数。但任务过多时时间片过小、切换开销爆炸，于是引入最小运行时间 sched_min_granularity：单任务一次至少跑这么久。最终通过「周期按权重分配、且不低于 min_granularity」来平衡。

## 三、形式化与数学基础
设可运行数为 n，总权重 Σw，实体 i 权重 w_i。理论时间片：
```
slice_i = sched_latency * (w_i / Σw)
```
约束：
```
slice_i >= sysctl_sched_min_granularity
=> 若 n 过大，实际周期 = n * min_granularity（拉长延迟保住粒度）
```
当 n <= sched_latency / min_granularity 时用固定周期；超出则周期随 n 增长。

## 四、代码实现
```c
// kernel/sched/fair.c（简化）
static u64 sched_slice(struct cfs_rq *cfs_rq, struct sched_entity *se)
{
    u64 slice = __sched_period(cfs_rq->nr_running);   // 周期
    slice = slice * se->load.weight / cfs_rq->load.weight;
    return slice;
}
static u64 __sched_period(unsigned long nr_running)
{
    u64 period = sysctl_sched_latency;
    if (unlikely(nr_running > sched_nr_latency))
        period = nr_running * sysctl_sched_min_granularity;
    return period;
}
```

## 五、与其他技术对比
- 固定时间片 RR：实现简单，但不按权重。
- CFS 周期法：按权重分配且保最小粒度，兼顾公平与开销。
- 多级反馈：以优先级隐式控制时间片。

## 六、常见误区
- 误区：任务越多每个分到的真实时间不变。实际为保 min_granularity，周期会拉长、延迟增大。
- 误区：min_granularity 只影响低优先级。它约束所有实体的单次最小时长。

## 九、演进与趋势
引入 wakeup_granularity、以及 PELT 让周期计算更贴合实际负载；HRTICK 提供高精度抢占时限，使周期更精确。

## 十、小结
调度周期与最小运行时间在「公平细切」与「切换开销」间取平衡，是 CFS 把抽象公平落到可运行时间片的桥梁。
