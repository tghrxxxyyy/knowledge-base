> 对应 Linux 内核 Documentation（scheduler/）与 Tanenbaum《Modern Operating Systems》。

## 一、背景与挑战
调度对象不只是进程，还可能是线程、进程组、甚至 cgroup。不同场景需要不同策略（公平、实时、空闲）。挑战是抽象出统一的「可调度实体」并支持「多调度类按优先级链」的组织。

## 二、核心原理
CFS 调度对象是 sched_entity（可运行实体），其挂入 cfs_rq。调度器核心是「调度类（sched_class）」链表：stop > dl（deadline）> rt（实时）> fair（CFS）> idle。pick_next_task 从最高优先级类开始询问，某类无runnable实体则下沉到下一类。这样实时任务永远优先于普通 CFS 任务。

## 三、形式化与数学基础
设调度类集合 C 按优先级排序 C_1 > C_2 > ... > C_k。选取下一个任务：
```
for i = 1..k:
    t = C_i.pick_next();  if t != NULL: return t
return idle_task
```
每个类内部用各自结构（CFS 用 rb tree，RT 用优先级位图+队列，DL 用红黑树按 deadline）。

## 四、代码实现
```c
// kernel/sched/core.c（简化）
struct task_struct *pick_next_task(struct rq *rq, struct task_struct *prev)
{
    for_each_class(class) {            // stop, dl, rt, fair, idle
        p = class->pick_next_task(rq);
        if (p) return p;
    }
    return rq->idle;                   // 全空则跑 idle
}
// CFS 类的实现
const struct sched_class fair_sched_class = {
    .pick_next_task = pick_next_task_fair,
    .enqueue_task  = enqueue_task_fair,
    .dequeue_task  = dequeue_task_fair,
};
```

## 五、与其他技术对比
- 单调度器：简单但无法并存多种策略。
- 调度类链：清晰分层，实时优先于公平。
- 完全公平单树：难以表达组/实时混合。

## 六、常见误区
- 误区：所有任务都进 CFS 红黑树。实时与 deadline 走各自结构，且优先级更高。
- 误区：调度类越多越慢。pick_next 短路在第一个非空类，开销小。

## 九、演进与趋势
EAS（Energy Aware Scheduling）在 CFS 之上叠加能效考量； schedutil 调速器与调度类协作；组调度（见本子目录第 5 篇）把 sched_entity 嵌套成树。

## 十、小结
调度实体与调度类把「被调度对象」与「调度策略」解耦，以分层类链实现多策略共存与严格优先级。
