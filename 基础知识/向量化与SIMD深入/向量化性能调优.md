# 向量化性能调优

> 对应 CSAPP 中文笔记 https://github.com/Hansimov/csapp 第5章；Intel 优化手册（公开定性）。

## 一、背景与挑战

向量化后未必快：内存带宽、对齐、依赖、尾数处理常成瓶颈，需系统调优。

## 二、核心原理

要点：保证对齐与连续访问、避免跨步、展开循环、用 reduction 指令、减少掩码浪费、注意 AVX-512 降频、结合多线程与缓存分块。

## 三、形式化 / 数学基础

受内存带宽 $B$ 限制时：

$$Speedup \le \frac{B}{W \times elemSize \times computePerElem}$$

即计算强度低于 $B$ 则瓶颈在带宽，向量化无助。

## 四、代码实现

```c
// 分块使数据留在缓存，提升向量化收益
for (int j = 0; j < N; j += B)
    for (int i = 0; i < n; i++)
        for (int k = j; k < j+B; k++)
            c[i] += a[i][k] * b[k];   // 缓存友好 + 向量化
```

## 五、与其他技术对比

- 仅向量化不解决带宽瓶颈；需缓存分块配合。
- 多线程 + SIMD 常叠加收益。

## 六、常见误区

- 误以为越宽越好：AVX-512 可能降频。
- 忽略计算强度，瓶颈在内存。

## 八、面试题

- 向量化后仍慢原因？答：内存带宽/跨步/对齐/尾处理。
- 何时该用 AVX-512？答：计算密集且散热允许，否则权衡降频。

## 九、演进与趋势

编译器报告 + 性能分析(屋顶线模型)指导调优成主流。

## 十、小结

向量化收益取决于数据访问与计算强度，调优要结合带宽与缓存。
