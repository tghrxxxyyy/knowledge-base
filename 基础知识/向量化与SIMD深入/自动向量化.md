# 自动向量化

> 对应 CSAPP 中文笔记 https://github.com/Hansimov/csapp 第5章；编译器优化公开资料（GCC/LLVM 文档定性）。

## 一、背景与挑战

手写 intrinsic 难维护。编译器在 -O3/-O2 下可把标量循环自动转为 SIMD，但受循环形态约束。

## 二、核心原理

向量化需：循环无数据依赖(无跨迭代写读同一元素)、步长已知、无函数调用副作用、迭代次数可静态或运行时处理(余数循环)。常以 -ftree-vectorize 开启，用 `#pragma omp simd` 提示。

## 三、形式化 / 数学基础

设循环体每迭代独立，向量因子 $VF = L$。串行长度 $N$ 拆为：

$$N = k \times VF + r$$

主向量循环 $k$ 次，余数 $r$ 用标量，保证正确。

## 四、代码实现

```c
// 提示编译器可向量化
#pragma omp simd
for (int i = 0; i < n; i++)
    c[i] = a[i] * b[i] + 1.0f;   // 无依赖，步长1
```

## 五、与其他技术对比

- 自动向量化零改代码但保守；手写 intrinsic 可控但脆弱。
- -ffast-math 放宽浮点结合律以放宽向量化。

## 六、常见误区

- 误以为加 -O3 必向量化：别名/分支常阻断，需看优化报告。
- 忽视 -ffast-math 改变浮点结果。

## 八、面试题

- 哪些循环难向量化？答：含函数调用、指针别名、跨迭代依赖、变长步长。
- 余数循环作用？答：处理非整除尾段，保证正确。

## 九、演进与趋势

编译器识别归约(reduction)、掩码谓词，配合可伸缩向量。

## 十、小结

自动向量化把 DLP 交给编译器，但程序员需写“友好”循环并验证报告。
