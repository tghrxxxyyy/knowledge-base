# 数据布局与对齐

> 对应 CSAPP 中文笔记 https://github.com/Hansimov/csapp 第5章；CS-Notes https://github.com/CyC2018/CS-Notes 。

## 一、背景与挑战

SIMD 需连续对齐的数据才能高效加载。AoS(数组结构体)跨字段布局难向量化，SoA(结构体数组)按字段连续更易。

## 二、核心原理

SoA 把同类字段放连续数组，单通道操作无 stride；AoS 每元素含多字段，向量通道需跨距 gather。对齐到向量宽度(32/64 字节)避免 split-load 与对齐异常。

## 三、形式化 / 数学基础

AoS 跨距 $stride = sizeof(struct)$；向量加载需：

$$addr \equiv 0 \pmod{W/8}$$

未对齐或跨距非 1 触发 gather/多次加载，吞吐下降。

## 四、代码实现

```c
// AoS -> SoA 以便向量化
struct Particle { float x, y, z; };       // 跨距12，难对齐
float *px, *py, *pz;                      // SoA，连续且易对齐
```

## 五、与其他技术对比

- SoA 利于 SIMD 但改结构、访存局部性按字段；AoS 缓存友好于整体遍历。
- 对齐分配 `_mm_malloc` / `aligned_alloc` 提升加载效率。

## 六、常见误区

- 误以为 SoA 总更快：跨字段同时访问时 AoS 更省缓存。
- 忽视未对齐加载的额外代价。

## 八、面试题

- 为何 SoA 易向量化？答：同字段连续，单通道无跨距。
- 对齐为何重要？答：避免 split-load 与未对齐异常。

## 九、演进与趋势

可伸缩向量用掩码消除重排需求；编译器自动 AoS→SoA 重构研究中。

## 十、小结

数据布局决定向量化能否高效，SoA 与对齐是常规优化手段。
