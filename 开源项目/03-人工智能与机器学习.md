## 二、分类速览与选型建议

- **深度学习框架**：做科研 / 快速实验选 PyTorch（动态图、调试直观）；做工业级、跨端部署、已有 TF 生态的存量系统选 TensorFlow。两者都提供自动求导与 GPU 加速，PyTorch 赢在「易用」，TF 赢在「成熟与移动端（TFLite）」。
- **LLM/推理**：想本地一键跑模型选 Ollama；想极致压榨老硬件 / 纯 CPU 跑选 llama.cpp；想高并发对外提供服务选 vLLM（PagedAttention 省显存）；想系统学原理选 LLMs-from-scratch；想直接调现成模型选 Transformers。
- **Agent**：个人自动化与跨端助手看 openclaw / hermes-agent；可视化拼装与低代码看 langflow / dify；偏工程编排与 RAG 看 langchain；让 Agent 上网操作看 browser-use；早期自主 Agent 思潮看 AutoGPT。
- **AIGC**：新手入门 AI 绘画用 stable-diffusion-webui；想做复杂可控工作流、节点图编排用 ComfyUI。
- **AI 应用平台**：需要分布式训练 / 调参 / 超参搜索与在线推理一体化，选 Ray。

> 选型一句话：框架看 PyTorch、本地推理看 Ollama/llama.cpp、Agent 工程看 langchain/dify、绘画看 ComfyUI、平台看 Ray。

## 三、重点速读

### openclaw/openclaw —— Agent 化个人计算的集大成者

openclaw 以约 378k Star 稳居本篇榜首，是「把 AI Agent 装进个人电脑」这一思潮的代表作。它的定位不是某个垂直工具，而是一个**跨 OS/跨平台的个人 AI 助手运行时**：在桌面、移动端、命令行甚至浏览器里都能接管你的日常任务——写邮件、整理文件、调度本地脚本、跨应用搬运数据，本质上把操作系统变成了一个可被自然语言驱动的「智能中间件」。

其核心特性在于「Agent 化个人计算」：相比传统的一次性问答，openclaw 强调长任务的自主规划与执行、对本地文件与应用的读写权限管理、以及多步任务的容错重试。生态上它通常对接 Ollama 等本地推理后端（隐私数据不出本机），也能桥接云端大模型。它能火，是因为正好踩中了「端侧 AI + 个人自动化」的双重红利——用户既想要智能，又不想把隐私交给 SaaS。

> 口诀：个人计算 Agent 化，本地跑模型、跨端能调度，openclaw 把 OS 变成会听话的助手。

### pytorch/pytorch —— 研究界的事实标准动态图框架

PyTorch 以约 101k Star 成为深度学习研究的首选框架。相比 TensorFlow 早期的静态图，PyTorch 的**动态计算图（define-by-run）**让模型调试像写普通 Python 一样直观：断点、打印张量形状、条件分支都能实时生效，极大降低了科研试错成本。其 `torch.autograd` 自动求导、`torch.nn` 模块化 API 与 CUDA 深度集成，让 GPU 训练既高效又顺手。

生态方面，PyTorch 背靠 Meta 与庞大的学界社区，几乎所有新论文的官方实现都优先放出 PyTorch 版本；围绕它的 `torchvision`、`torchaudio`、`torchserve`、以及和 Hugging Face Transformers 的无缝衔接，构成了从实验到落地的完整链路。它能长期占据研究榜首，关键在于「易用性」与「生态广度」的正循环——用的人越多，模型与教程越丰富，反过来又吸引更多人用。

> 口诀：动态图、易调试，研究首选 PyTorch；论文复现先看它，GPU 加速靠 CUDA。

### huggingface/transformers —— 预训练模型的「应用商店」

Transformers 以约 162k Star 扮演了 AI 界的「模型中枢」角色。它把 BERT、GPT、Llama、Qwen、ViT、Whisper 等海量预训练模型统一封装成一致的 `pipeline` API：一行代码加载、一行代码推理，文本/视觉/音频/多模态全覆盖。它既支持快速推理（inference），也提供 `Trainer` 与 `PEFT` 做微调训练，把「调模型」的门槛降到了最低。

其爆发式流行源于「模型即服务」范式的普及：Hugging Face Hub 上托管了数百万个社区模型与数据集，开发者无需从零训练，直接下载、微调、部署。它和本库「大模型」板块天然呼应——transformers 是模型落地到代码的最后一公里，而 vLLM、llama.cpp 等则补足了高吞吐与本地轻量推理的场景。对工程师而言，先逛 Hub 再 `from_pretrained`，已成为标准动作。

> 口诀：模型万万千，transformers 一统 API；下载即推理，Hub 上逛一圈。

### ollama/ollama 与 ggml-org/llama.cpp —— 本地推理双子星

Ollama（约 170k Star）与 llama.cpp（约 120k Star）共同定义了「在笔记本上跑大模型」的体验。Ollama 负责「爽」：一条 `ollama run qwen2.5` 就能拉起模型、自动处理量化与运行环境，对 DeepSeek、Qwen、Llama 等主流权重开箱即用，是本地把玩的首选入口。llama.cpp 负责「广」：纯 C/C++ 实现、几乎零依赖，能在 CPU、Apple Silicon、树莓派乃至各种奇葩硬件上推理，2026-03 突破 10 万星，正是「端侧普惠」的注脚。

两者常配合使用——Ollama 底层本身就调用 llama.cpp 系的推理内核，上层提供更友好的 CLI/REST；而 open-webui、dify 等界面又把它们当作本地后端。它们之所以火，是因为把「大模型必须上云、必须大显存」的刻板印象彻底打破，让个人开发者以极低成本拥有私有、可离线、可定制的大脑。

> 口诀：Ollama 管方便、llama.cpp 管兼容，本地大模型双子星；笔记本也能跑，隐私不出行。

### 趋势观察（2026）

- **端侧与本地化**：Ollama、llama.cpp、openclaw 的走高，说明「模型跑在本地、数据不出机」正从极客需求变成主流偏好，尤其在隐私敏感行业。
- **Agent 从演示走向生产**：langchain/dify/langflow 把 Agent 工程化，browser-use 把操作面延伸到浏览器，hermes-agent 探索持久记忆与技能沉淀——自主 Agent 正从「能跑」迈向「可托管」。
- **推理引擎专业化**：vLLM 把「高吞吐省显存」做成独立层，与训练框架解耦，标志着 LLM 服务进入精细化运维阶段。
- **低代码普及**：langflow、dify 的流行表明，构建 RAG/Agent 应用正在下沉到非算法同学，可视化编排成为新入口。

> 一句话趋势：本地化 + Agent 化 + 推理专业化 + 低代码，是 2026 年 AI 开源最确定的四条主线。
