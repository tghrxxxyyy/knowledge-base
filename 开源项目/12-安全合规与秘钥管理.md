# 安全合规与秘钥管理（开源精选）

> 板块：开源项目 　|　 返回：[README](README.md)
> 覆盖：秘钥、策略、镜像扫描、代码安全、依赖治理。通行开源项目。

安全不是上线后救火，而是"安全左移（Shift Left）"——在开发期就做秘钥管理、依赖扫描、镜像扫描、策略校验。本文按安全生命周期梳理开源工具与工程实践。

## 一、一句话定位

安全是工程的一部分，不是附加项。把安全卡点嵌入开发流水线（CI），让不合规的代码/镜像"提交即拦"，远比上线后救火成本低。

## 二、秘钥与凭据管理

- **HashiCorp Vault**：集中管理秘钥/证书/动态凭据，支持自动轮换、加密即服务、审计日志。应用按需动态获取短期凭据，而非静态写死。
- **KMS（云厂商）**：信封加密，应用拿明文不出 KMS（数据用数据密钥加密，数据密钥用 KMS 主密钥加密）。
- **Sealed Secrets / External Secrets Operator**：K8s 中安全注入秘钥，避免明文进 Git（详见 [云原生/GitOps与持续交付](../云原生/GitOps与持续交付.md)）。
- **原则**：秘钥不入代码、不入镜像、不提交 Git；用环境变量或挂载注入；定期轮换。

## 三、策略与准入控制

- **OPA（Open Policy Agent）**：通用策略引擎，用 Rego 写策略，可做 K8s 准入、API 鉴权、CI 卡点。
- **Kyverno**：K8s 原生策略（YAML 写），准入/审计/生成。比 OPA 对 K8s 更友好（无需学 Rego）。
- **场景**：禁止特权容器、强制资源限制、镜像来源白名单、标签必填。

```rego
# OPA Rego 示例：禁止 latest 镜像
deny[msg] {
  input.request.kind.kind == "Pod"
  image := input.request.object.spec.containers[_].image
  endswith(image, ":latest")
  msg := "禁止使用 latest 镜像"
}
```

## 四、镜像与供应链安全

- **Trivy / Clair / Grype**：扫描镜像/文件系统/依赖的 CVE 漏洞。
- **cosign / Sigstore**：镜像签名与验证，保证来源可信（防篡改）。
- **SBOM（软件物料清单）**：生成 CycloneDX/SPDX，追踪组件与漏洞（合规与应急溯源）。
- **CI 卡点**：漏洞超阈值则阻断发布；基础镜像定期重建以吸收补丁。

## 五、代码安全（SAST/DAST）

- **SonarQube / Semgrep**：静态分析，查注入、硬编码秘钥、危险函数。Semgrep 用规则（YAML）快速定制，误报低。
- **Bandit（Python）/ FindSecBugs（Java）**：语言专用 SAST。
- **DAST**：运行时动态扫描（如 OWASP ZAP），模拟攻击发现运行时漏洞。
- **秘钥扫描**：GitLeaks / TruffleHog 扫历史提交防泄露（泄露后必须轮换，因为历史不可改）。

## 六、依赖与供应链治理

- **依赖漏洞**：Dependabot / Renovate 自动升级；SCA 工具（如 Trivy 的 SCA）查传递依赖。
- **锁文件**：package-lock / go.sum / Pipfile.lock 保证可复现、防意外升级。
- **供应链攻击**：校验包签名、最小权限安装、私有代理（npm/PyPI 镜像）降低投毒风险。
- **最小依赖**：不引入不必要的包，减少攻击面。

## 七、身份与访问（IAM）

- **OAuth2 / OIDC**：授权与单点登录（SSO）。
- **Keycloak**：开源身份提供者，支持 SSO/2FA/社交登录。
- **最小权限**：角色按需授予，定期回收（离职/转岗即回收）。

## 八、网络安全

- **mTLS**：服务间双向认证（服务网格默认，见 [云原生/ServiceMesh深入](../../云原生/ServiceMesh深入.md)）。
- **网络策略**：K8s NetworkPolicy 隔离命名空间/服务（默认全通，需显式限制）。
- **WAF**：防护常见 Web 攻击（SQL 注入、XSS）。

## 九、合规要点

- **数据脱敏**：PII（姓名/手机号/身份证）存储加密或脱敏；展示打码。
- **审计日志**：谁在何时做了什么，不可篡改（append-only）。
- **留存与删除**：按法规（如 GDPR/个保法）保留与销毁；用户注销即删除。
- **隐私**：最小化采集，明确告知与同意。

## 十、安全开发实践

1. 威胁建模（STRIDE）在设计阶段： spoofing/篡改/抵赖/信息泄露/拒绝服务/提权。
2. 输入校验与输出编码防注入（SQL/命令/XSS）。
3. 秘钥集中管理 + 自动轮换。
4. CI 集成 SAST + 依赖扫描 + 镜像扫描。
5. 默认拒绝 + 最小权限（默认无权限，按需授予）。
6. 红蓝对抗与定期审计。

## 十一、常见坑

- **秘钥硬编码进代码** → 泄露，必须扫描历史并轮换。
- **镜像用 latest** → 不可复现且无法校验，难回滚。
- **只扫不修** → 漏洞清单越积越多，扫描沦为摆设。
- **权限过度授予** → 一破全破（横向移动）。
- **合规当作文档而非工程** → 上线即违规，出事无证据。
