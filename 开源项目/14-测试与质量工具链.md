# 测试与质量工具链（开源精选）

> 板块：开源项目 　|　 返回：[README](README.md)
> 覆盖：单元/接口/性能/混沌/质量门禁。通行开源项目。

## 一、一句话定位

质量不是测试一个环节，而是「单元→接口→UI→性能→混沌→静态分析」的多层防护。工具链让质量可自动化、可度量。

## 二、单元测试

- **JUnit 5（Java）/ pytest（Python）/ Jest（JS）/ Go test**：各语言标配。
- **Mock**：Mockito（Java）、unittest.mock（Python）、jest.fn（JS）。
- **覆盖率**：JaCoCo / coverage.py / Istanbul，配合门禁。
- 详见 [测试与代码质量/单元测试与测试金字塔](../测试与代码质量/单元测试与测试金字塔.md)。

## 三、接口与契约测试

- **Postman / Apifox / Bruno**：接口调试与集合测试。
- **RestAssured（Java）/ requests+pytest**：API 自动化。
- **契约测试**：Pact（消费者驱动契约），防接口变更破坏调用方。

## 四、UI / E2E

- **Selenium**：老牌 Web 自动化。
- **Playwright / Cypress**：现代 E2E，快、稳、易调试。
- **Appium**：移动端自动化。
- 原则：只覆盖核心旅程，避免全量 E2E（慢且脆）。

## 五、性能与压测

- **JMeter**：功能全的压测工具，GUI/CLI。
- **k6**：代码化、云原生友好的压测（JS 脚本）。
- **Gatling**：Scala/DSL 高性能压测。
- **locust**：Python 写分布式压测。
- 指标：QPS、P99 延迟、错误率、资源占用。

## 六、模糊与混沌

- **模糊测试（Fuzzing）**：AFL / libFuzzer / go-fuzz 自动生成异常输入找崩溃。
- **混沌工程**：Chaos Mesh / Litmus 注入故障验证韧性。详见 [SRE/故障演练与稳定性保障](../SRE/故障演练与稳定性保障.md)。

## 七、静态分析与质量门禁

- **SonarQube / SpotBugs / PMD（Java）**、**ESLint / Prettier（JS）**、**ruff（Python）**：规范与坏味道检测。
- **质量门禁**：覆盖率/复杂度/漏洞不达标则阻断合并。
- 详见 [测试与代码质量/代码质量与静态分析](../测试与代码质量/代码质量与静态分析.md)。

## 八、CI 集成

```yaml
# 简化 CI 阶段
stages: [lint, unit-test, integration, build, deploy]
# 单测失败即阻断，质量门禁卡点
```

- pre-commit 钩子挡低级问题；CI 跑全量质量。

## 九、测试数据与环境

- **Testcontainers**：测试中起真实 DB/中间件容器，避免内存假实现行为偏差。
- **数据工厂**：builder/factory 造数据，隔离用例。
- **环境一致**：Docker Compose / 仿真环境贴近生产。

## 十、常见坑

- 只写 E2E 不写单测 → 慢且难定位。
- 测试依赖共享状态 → 互相污染、flaky。
- 覆盖率高但无断言 → 假绿。
- 压测用错模型（并发≠用户数）→ 结论失真。
- 混沌不控制爆炸半径 → 影响真实用户。
