## 重点速读

### golang/go —— 云原生的"母语"

Go 由 Google 于 2009 年发布，定位是"为大规模工程与多核服务器时代"设计的系统语言。它刻意砍掉了继承、泛型（早期）、异常等复杂特性，换来极快的编译速度与极低的学习成本。最核心的竞争力是 **goroutine + channel** 的 CSP 并发模型：轻量级协程让单机轻松支撑百万级并发，channel 提供"不要用共享内存来通信，要用通信来共享内存"的范式。

为什么这么火？因为 Kubernetes、Docker、Prometheus、etcd、Terraform 等一整代云原生基础设施都是 Go 写的，形成了"用 Go 写基础设施"的强网络效应。对后端工程师而言，Go 是写高并发服务、CLI 工具、Sidecar/Operator 的性价比之王。

> 口诀：**"协程轻、编译快、云原生里它最帅。"**

### rust-lang/rust —— 守住内存安全的高墙

Rust 用"所有权 + 借用检查 + 生命周期"在编译期消灭了数据竞争与悬垂指针，做到**无 GC 的内存安全**。这在过去是天然矛盾的：要么像 C/C++ 手写管理（易出 bug），要么像 Java/Go 上交 GC（有停顿与开销）。Rust 把安全验证前移到编译期，因此特别适合性能与正确性格外敏感的场景——操作系统、浏览器引擎(Firefox 的 Servo)、WASM、嵌入式固件，以及近两年的 AI 训练框架与数据库内核（如 TiKV、neon、vectordb）。

为什么这么火？一方面 Linux 内核已接纳 Rust 作为第二语言，另一方面 AI 算力时代对"零开销抽象 + 安全并行"的渴求，让 Rust 成为系统编程的新宠。学习曲线陡，但一次编译通过基本就跑得稳。

> 口诀：**"所有权、编译期把关，内存安全不用 GC 扛。"**

### astral-sh/uv + astral-sh/ruff —— Python 工具链的"Rust 革命"

Python 生态长期被"慢"诟病：pip 装包慢、虚拟环境创建慢、flake8/black/isort 一堆工具各跑各的。Astral 公司用 Rust 重写了整条工具链——**uv** 一个命令替代 pip/venv/poetry/pdw，环境创建从分钟级降到秒级；**ruff** 一条命令替代 flake8+black+isort+autoflake 等十余个 Linter/Formatter，速度提升 10~100 倍。二者共享同一套 Rust 内核，命令行体验极度统一。

为什么这么火？因为在 AI/数据科学时代，Python 是绝对主流，但工程化体验落后。Astral 把"现代开发者体验"带回 Python，且完全向后兼容既有生态，几乎零迁移成本就被社区疯抢。对日常写 Python 的工程师，这是近期最值得上车的两件神器。

> 口诀：**"uv 管环境、ruff 管格式，Rust 一跑快得真实。"**

## 选型决策（后端工程师视角）

```
写云原生基础设施/CLI/网关  → Go（生态成熟、编译快、协程并发）
写核心组件/性能敏感内核    → Rust（内存安全、零开销，学习成本高）
写前端/全栈/脚本工具      → TypeScript + Node（bun/deno 可作运行时替代）
写 AI/数据管道/快速原型   → Python（uv 管环境、ruff 管质量，体验已现代化）
JVM 系业务开发            → Kotlin（现代化语法）+ Java（生态深）
```

| 场景 | 首选 | 原因 |
|------|------|------|
| 容器编排/Operator | Go | K8s 生态母语，SDK 齐全 |
| 网关/API 代理 | Go | 高并发低延迟，部署单二进制 |
| 协议解析/序列化核心 | Rust | 安全+性能，WASM 可分发 |
| 数据引擎/向量库 | Rust/Go | 性能敏感、安全并行 |
| 前端全栈 | TS + Node | 类型安全、生态最大 |
| 快速迭代/ML | Python | 生态统治力，工具链已 Rust 化 |

## 深挖：运行时机制（面试必答）

### Go GMP 调度器（百万协程的秘密）

```
G(goroutine 协程) / M(线程) / P(本地运行队列的处理器)
G 在 M 上跑，M 需要绑定 P 才能调度；
阻塞(系统调用/GC)时 M 可解绑 P，让 P 换一个 M 继续执行 → 阻塞不饿调度
```

- **work-stealing**：P 本地队列空了就去别的 P 偷一半 G；
- 系统调用阻塞时，M 脱钩让路，回来再排队（handoff）；
- 工程启示：goroutine 开销仅 ~2KB 起步，**一个连接一个 goroutine 的模型**能撑百万连接——这是 Go 写网关/代理横扫云原生场的原因（对比 Java 线程 1MB 栈）。

### Node.js 事件循环（为什么 IO 密集它很强）

```
事件循环阶段(每轮): timers → pending → poll(核心) → check → close
- timers: setTimeout 到期回调
- poll: 等待并处理 IO 事件（多数回调在这）
- check: setImmediate
- 回调里做 CPU 重活 → 阻塞整个循环
```

- libuv 线程池兜底 fs/DNS 等阻塞调用（默认 4 线程）；
- 工程启示：**IO 密集用异步（事件循环），CPU 密集必须 worker_threads 或拆进程**——这是 Node 服务性能分水岭。

### Python GIL（为什么 CPU 密集它慢）

- GIL 保证同一时刻只有一个线程执行 Python 字节码 → 多线程无法并行吃满多核；
- IO 密集（等网络/磁盘）会释放 GIL，多线程依然有用；CPU 密集请用 `multiprocessing` 或多进程服务；
- 好消息：Python 3.13 引入**无 GIL 构建（free-threaded）**实验支持，生态迁移中；
- 工程启示：AI/数据服务常「Python 编排 + C/Rust 扩展（numpy/torch 底层）」就是这个原因。

### 语言选型的本质问题（三问）

1. **并发模型**：协程（Go/JS async）/ 线程（Java）/ 无 GC 所有权（Rust）——你的 IO 模型是什么？
2. **内存管理**：GC（Java/Go/JS，有停顿）/ 手动（C/C++）/ 编译期（Rust，零开销）——延迟敏感度？
3. **生态半径**：基础设施（Go/Rust）、业务（Java/Kotlin/TS）、AI/数据（Python）——周边库谁最全？
