## 一、一句话定位

大数据栈回答三件事：海量数据怎么存（湖/仓）、怎么算（批/流）、怎么按时跑（调度）。云原生时代，流批一体与湖仓一体是主线。

## 二、批处理

- **Apache Spark**：基于 RDD/DataFrame 的内存计算，SQL/Streaming/MLlib 一体。Shuffle 是性能关键。
- **Hadoop MapReduce**：早期批处理标准，磁盘型，已被 Spark 大幅替代。
- **Hive**：把 SQL 翻译成 MapReduce/Tez/Spark 执行，数据仓库查询。
- **核心概念**：分区（partition）、分桶（bucket）、列式存储（ORC/Parquet）减少 IO。

```python
# PySpark 读 Parquet 做聚合
from pyspark.sql import SparkSession
spark = SparkSession.builder.appName("etl").getOrCreate()
df = spark.read.parquet("s3a://bucket/events/")
df.groupBy("user_id").count().write.mode("overwrite").parquet("out/")
```

## 三、流计算

| 引擎 | 语义 | 特点 |
|------|------|------|
| Apache Flink | 精确一次、事件时间 | 真正的流原生，状态管理强 |
| Spark Streaming | 微批 | 复用 Spark 生态，易上手 |
| Kafka Streams | 库级 | 轻量，嵌入应用 |
| Storm | 至少一次 | 老牌，已式微 |

- **Flink 关键**：事件时间（event time）vs 处理时间；水位线（watermark）处理乱序；Checkpoint + 状态后端保证精确一次。
- **CDC 接入**：Flink CDC + Debezium 捕获数据库变更，实时入仓。详见 [技术选型/消息队列选型与对比](../技术选型/消息队列选型与对比.md)。

## 四、消息与缓冲（流的数据总线）

- **Kafka**：高吞吐日志总线，流计算的入口/出口。
- 详见 [技术选型/消息队列选型与对比](../技术选型/消息队列选型与对比.md) 与 [源码系列/消息中间件源码要点](../源码系列/消息中间件源码要点.md)。

## 五、湖仓一体（Lakehouse）

- **数据湖（Lake）**：对象存储上存原始数据（Parquet/ORC），Schema-on-read，便宜灵活。
- **数据仓库（Warehouse）**：结构化、Schema-on-write、强治理（如 ClickHouse/StarRocks）。
- **湖仓一体**：在湖上叠加事务与元数据层（ACID），代表：**Apache Iceberg / Delta Lake / Apache Hudi**。表格式提供快照、时间旅行、Schema 演化。

## 六、OLAP 与即席查询

- **ClickHouse / Apache Doris / StarRocks**：列存 MPP，亿级聚合秒级。
- **Presto/Trino**：跨数据源联邦查询。
- **DuckDB**：进程内 OLAP，轻量分析。

## 七、调度与编排

- **Airflow**：Python 定义 DAG，成熟生态，适合批调度。
- **DolphinScheduler**：可视化工作流，国内流行。
- **Dagster / Prefect**：新一代数据编排，强调资产（asset）与可观测。
- 关键：依赖、重试、告警、SLA。

## 八、数据质量与治理

- **Great Expectations / Soda / dbt tests**：数据校验与测试。
- **Apache Atlas / DataHub / Amundsen**：元数据与血缘。
- **权限**：Ranger / 平台级 ACL。

## 九、实时数仓典型链路

```
业务库 → CDC(Flink/Debezium) → Kafka → Flink 清洗聚合 → Iceberg/ClickHouse → 看板/服务
```

- 离线补算：T+1 用 Spark 重跑，与实时对齐口径。

## 十、选型经验

1. 离线为主、SQL 多 → Spark + Hive + Iceberg。
2. 实时优先、低延迟 → Flink + Kafka + ClickHouse。
3. 既要又要 → 湖仓一体（Iceberg 表格式）+ 两套引擎共用。
4. 中小团队 → 托管服务优先，自建集群运维重。

## 十一、常见坑

- 小文件过多 → 合并（compaction），否则元数据爆炸、查询慢。
- 流窗口乱序不处理 → 结果不准，必须配 watermark。
- 状态后端用内存 → 大状态 OOM，用 RocksDB。
- 离线实时口径不一致 → 重复对账，统一指标定义。
- 不治理元数据 → 数据沼泽（data swamp），没人敢用。

## 十二、学习路径

1. 学 SQL + 数据建模（维度建模）。
2. 跑通 Spark 批处理。
3. 学 Flink 流处理（事件时间/状态/Exactly-once）。
4. 接 Iceberg 湖仓，理解表格式。
5. 用 Airflow 编排，加数据质量校验。
